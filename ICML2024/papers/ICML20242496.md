## Problem

LLM agents rely on manually curated functions to solve downstream tasks, a process that is time-consuming and error-prone, while fine-tuning the underlying LLM to better use functions requires expensive compute and access to model weights that are often unavailable for proprietary APIs. This paper asks whether one can instead treat the agent's functions as learnable parameters and iteratively optimize them offline, without ever modifying the LLM itself.
![Teaser figure](../imgs/ICML20242496/cropped_page0_idx0.webp)

## Input / Output

The method takes a training set of task-question/ground-truth-answer pairs (limited by the LLM context window, e.g., 80 examples for MATH, 100 for TabMWP, 10 for GAIA) and an initial agent system (GPT-4+ or ReAct) with an empty or minimal function set. It produces an optimized set of Python functions—each specified by a name, natural-language description, JSON argument schema, required packages, and code implementation—that the agent can invoke at inference time to produce task answers. The entire process is black-box with respect to the LLM: no gradient access or weight modification is required.

## Method

The core mechanism is the AgentOptimizer, an LLM-based optimizer that replaces numeric optimizers (SGD/Adam) in a training loop over the function space. At each epoch, the agent is evaluated on the training set, and the resulting execution history (how functions were called, errors encountered, success/failure per problem) plus the current function set are fed to the AgentOptimizer, which performs one progressive action per step—add_function, revise_function, remove_function, or TERMINATE—rather than regenerating the entire function set. Two stabilization strategies prevent degradation: roll-back reverts the function set if training performance drops (and records the failed update as in-context negative examples for future steps), and early-stop halts training after C consecutive non-improving steps. The paper also provides a generalization bound via Hoeffding's inequality showing the expected test loss gap between the trained and optimal function set scales as O(1/√|D_train|).

## Results

On the MATH dataset, agent training improved test accuracy in 11 out of 14 agent-type/data-type combinations, with notable gains such as GPT-4+ agent on Number Theory (56.3% → 67.5%) and ReAct agent on Precalculus (53.8% → 62.5%). On the more complex GAIA and TabMWP benchmarks, agent training yielded average test improvements of 6% (GPT-4+ agent) and 8.5% (ReAct agent), with ReAct on TabMWP jumping from 59.0% to 70.0% and GPT-4+ on GAIA rising from 16.0% to 23.0%. The method is model-agnostic, also improving Code-Llama-34B (7.5% → 11.3%) and Mixtral-8x7B (23.8% → 28.8%) on MATH.

## Baselines & Comparisons

The paper compares against two tool-creation baselines: CREATOR (Qian et al., 2023), which creates tools exclusive to each query, and CRAFT (Yuan et al., 2024), which creates and retrieves specialized toolsets. On TabMWP test, both trained agents substantially outperform the baselines: ReAct with agent training reaches 70.0% vs. CRAFT's 38.5% and CREATOR's 30.0%, while GPT-4+ with agent training achieves 56.0% vs. 38.5% and 30.0%. On MATH test, ReAct with agent training (77.5%) edges out CREATOR (75.0%) and CRAFT (73.8%), but GPT-4+ with agent training (66.25%) underperforms both baselines. Overall, the agent training method wins 3 out of 4 head-to-head comparisons, with the largest margins on TabMWP where the iterative optimization over execution history provides a clear advantage over one-shot tool creation.

## Relation to Prior Work

This paper carves new ground by drawing an explicit analogy between traditional model training (SGD/Adam optimizing numeric weights) and agent training (an LLM-based AgentOptimizer iteratively updating a function set), a framing absent from prior tool-creation work like CREATOR and CRAFT, which generate tools in a single shot without iterative optimization. It also departs from the LLM-as-optimizer line (OPRO, hyperparameter optimization) by targeting the agent's operational functions rather than prompts or hyperparameters, and from LLM finetuning approaches (ToolLLM, AgentTune) by requiring no access to model weights. The progressive function update mechanism (add/revise/remove actions per step) and the roll-back/early-stop training loop are novel components not present in any single prior work.

## Why It Matters / Open Questions

The paradigm is practically valuable because it works with black-box LLMs (GPT-4, GPT-3.5) without finetuning, and the method is already integrated into the AutoGen library, lowering the barrier for practitioners. Key limitations include the training set being bounded by the LLM context window (batch training surprisingly degrades performance), observed overfitting on the MATH dataset, and theoretical guarantees that rely on strong i.i.d. and oracle-optimizer assumptions. Open questions include whether the approach scales to larger function spaces, whether the AgentOptimizer can be made more sample-efficient, and whether the learned functions transfer across agent architectures or task families beyond the tested domains.
