## Problem

Optimization modeling—converting real-world business problems into solvable (MI)LP formulations—still requires expert knowledge, preventing widespread adoption in sectors that cannot afford optimization specialists. While LLMs offer a path to automate this, they struggle with ambiguous terminology, long problem descriptions, large numerical data, and unreliable code generation, and existing benchmarks are too simple to capture these challenges.
![Teaser figure](../imgs/ICML20240024/cropped_page1_idx0.webp)

## Input / Output

The system takes a natural language problem description and a separate numerical data file as input, deliberately decoupling data from the description so that prompts remain short regardless of dataset size. It produces a LaTeX mathematical formulation for each constraint and objective, executable Python code calling Gurobi, and the optimal solution value. An instance counts as correctly solved only if the code runs without error and the returned optimal value matches the ground truth.

## Method

OptiMUS is a multi-agent LLM pipeline (Manager, Formulator, Programmer, Evaluator) that iteratively formulates, codes, and debugs an optimization model. A preprocessing step converts the natural language description into a structured state of parameters, clauses, and background context. The key architectural contribution is a tripartite connection graph over parameters, constraints, and variables that lets each agent retrieve only the relevant context for a given clause, keeping prompt length nearly constant even as problem complexity grows. The Manager coordinates an iterative loop in which the Formulator writes LaTeX formulations and defines new variables, the Programmer generates and debugs Gurobi Python code, and the Evaluator executes the code and reports errors back to the Manager for targeted fixes. This modular design, combined with the use of GPT-4 and solver-specific structure exploitation (SOS, indicator variables), enables OptiMUS to scale to long descriptions and large data files while outperforming single-prompt and prior multi-agent baselines by over 20-30%.

## Results

OptiMUS achieves 78.8% accuracy on NL4OPT, 66.7% on ComplexOR, and 72.0% on NLP4LP, where accuracy means the generated code runs successfully and produces the correct optimal value. This represents a relative improvement of over 20% on the easy NL4OPT dataset and over 30% on the harder ComplexOR and NLP4LP datasets compared to the prior state-of-the-art (Chain-of-Experts). The modular connection-graph design keeps average prompt length nearly constant (~2,838–3,241 tokens) across datasets of varying difficulty, whereas CoE's prompts grow from 2,003 to 3,825 tokens.

## Baselines & Comparisons

OptiMUS outperforms both baselines across all three datasets. Against Chain-of-Experts (CoE, Xiao et al. 2024), the prior state-of-the-art for natural-language optimization modeling, OptiMUS gains +14.6 pp on NL4OPT (78.8% vs 64.2%), +28.6 pp on ComplexOR (66.7% vs 38.1%), and +18.9 pp on NLP4LP (72.0% vs 53.1%). Against Reflexion (Shinn et al. 2023), a general-purpose self-reflection framework, the margins are even larger: +25.8 pp on NL4OPT, +47.6 pp on ComplexOR, and +25.7 pp on NLP4LP. The advantage is most pronounced on the harder datasets (ComplexOR, NLP4LP), where iterative multi-agent coordination and the connection graph's ability to isolate relevant context per constraint prove critical. Ablation results further show that removing the debugging loop drops accuracy by 6–14 pp, and replacing GPT-4 with GPT-3.5 or Mixtral-8x7B causes a dramatic collapse (e.g., 28.6% → 6.6% on NL4OPT), underscoring that the modular prompt structure demands strong reasoning capabilities.

## Relation to Prior Work

OptiMUS extends the multi-agent LLM framework (inspired by AutoGen) to the specific domain of optimization modeling, departing from prior end-to-end approaches like Chain-of-Experts (Xiao et al., 2024) and Reflexion (Shinn et al., 2023) by introducing a modular architecture centered on a connection graph that decouples constraints and keeps prompts short regardless of problem size. It also builds on the NL4OPT benchmark lineage (Ramamonjison et al., 2023) but explicitly addresses the limitation that existing datasets are too simple to test scalability, contributing the NLP4LP dataset of 67 long, complex problems. The system repurposes the manager-worker pattern from general-purpose agent frameworks but tailors it to the iterative formulate-code-evaluate-debug loop specific to optimization, and integrates solver-specific structures (SOS, indicator variables) that prior LLM-based approaches ignored.

## Why It Matters / Open Questions

By making optimization modeling accessible without expert-level OR training, OptiMUS addresses a real adoption barrier (81% of commercial solver users hold advanced degrees) and the modular connection-graph design offers a practical recipe for scaling LLM agents to long-context, data-heavy problems. Key open questions include whether smaller fine-tuned models can match GPT-4 on the novel modular prompt format, how to detect hidden formulation errors that don't produce runtime failures, and whether the manager's agent-selection policy can be improved via reinforcement learning. The NLP4LP dataset fills a gap in the benchmark landscape for long, complex optimization problems, though at 67 instances it remains small for statistical robustness.
