## Problem

Early-exit LLMs have only been demonstrated at small scales (≤13B parameters), while standard LLMs are routinely trained at 175B+ using 3D parallelism. No existing framework supports training early-exit models with pipeline parallelism, since the multi-exit loss objective is distributed across pipeline stages with only limited point-to-point communication. Additionally, naive early-exit inference is incompatible with KV caching, a standard technique for autoregressive generation, because tokens generated via early exits lack KV caches in deeper layers.

## Input / Output

The system takes a text prompt and produces a generated text sequence via autoregressive decoding, where each token is emitted at an adaptively selected exit depth (e.g., 1/4, 1/2, or full model depth) based on a per-token confidence threshold. The model architecture is a GPT Transformer backbone with minimalistic early-exit layers (output embedding matrices, optionally preceded by layer normalization or an MLP) inserted at user-specified depths, with the option to tie or untie input/output embedding matrices across exits. Training uses standard next-token prediction (negative log-likelihood) with a weighted sum of losses across all exits.

## Method

EE-LLM, built on Megatron-LM, introduces three key technical contributions. For training, it defines auxiliary losses inductively across pipeline stages (L_i^aux = L_i + <g_i, x_i>) so that each stage computes correct gradients for the multi-exit objective using only the standard P2P communication pattern, with no additional inter-stage communication. Performance optimizations exploit idle resources in the 1F1B schedule—implicit bubbles from load imbalance and idle memory in later stages—so that adding k early exits to middle stages increases training time by only k×(f_EE + b_EE) and leaves peak GPU memory unchanged. For inference, it proposes a novel pipeline-parallel decoding scheme where, upon early exit, the full-model forward pass of the current token continues in parallel on later stages while the next token's generation begins immediately on the first stage, achieving speedup without missing KV caches and without relying on GPU batching effects.

## Results

For training efficiency, with all proposed optimizations applied, a 1.3B early-exit model achieves 5.24 s/iteration and 19.85 GB peak memory, matching the standard model's 5.23 s and 19.85 GB; the 7B model reaches 17.79 s and 62.27 GB versus 17.75 s and 62.27 GB for the standard model. For inference, the pipeline-based early-exit method achieves 2× or higher speedup over full-model inference on HELM benchmarks (BoolQ, TruthfulQA, NaturalQuestions, XSUM, CNN/DailyMail) with comparable or even better evaluation scores at moderate confidence thresholds. The system scales training to 30B parameters on 64 A100 GPUs, an unprecedented scale for early-exit LLMs.

## Baselines & Comparisons

This is primarily a systems paper, so comparisons are against the standard (non-early-exit) training/inference pipeline rather than competing early-exit methods. On training efficiency, the naive early-exit implementation adds 1.5% time and 21% peak memory overhead for the 1.3B model (5.31 s / 24.05 GB vs. 5.23 s / 19.85 GB), but the proposed optimizations reduce this to a negligible 0.2% time overhead and zero memory overhead (5.24 s / 19.85 GB). On inference, the pipeline-based method outperforms KV recomputation with TP=1 for all confidence thresholds below 1.0, despite incurring point-to-point communication overhead; KV recomputation with TP=4 is faster but requires high-bandwidth interconnects (e.g., A100 NVLink) that are not universally available. In terms of output quality, the final-exit loss of early-exit models converges to values close to or slightly below those of standard models trained with identical hyperparameters, indicating that early-exit training does not degrade full-model performance. The paper does not directly compare against other early-exit inference frameworks (e.g., SkipDecode, synchronized parallel decoding) on a common benchmark, limiting direct head-to-head comparisons.

## Relation to Prior Work

This paper extends the early-exit LLM line of work (CALM, LITE, SkipDecode, synchronized parallel decoding) from small-scale, single-device settings to large-scale 3D parallelism built on Megatron-LM. The key departure is addressing the fundamental incompatibility between early-exit training objectives (multiple losses on different pipeline stages) and pipeline parallelism, which no prior framework supported. For inference, it departs from KV-recomputation and state-propagation approaches by proposing a novel pipeline-parallelism-based method that is natively compatible with KV caching, avoiding the high theoretical complexity of recomputation.

## Why It Matters / Open Questions

EE-LLM removes the primary infrastructure barrier to training early-exit LLMs at the same scale as standard LLMs, making early exiting a practical option for large-scale deployment. The finding that early-exit training incurs negligible overhead under pipeline parallelism (due to implicit load-imbalance bubbles) is a useful systems insight that could generalize to other multi-loss architectures. Limitations include the 30B experimental ceiling, reliance on greedy decoding with a simple confidence threshold, and the pipeline-based inference method's requirement for multiple devices. Open questions include whether early exiting yields proportionally larger speedups at 100B+ scales, and how more sophisticated exit conditions or architectures interact with the proposed training/inference infrastructure.
