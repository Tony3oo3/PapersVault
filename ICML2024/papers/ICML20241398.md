## Problem

Existing automated discovery systems either lacked sufficient computational power (Bacon), were restricted to narrow domains (AlphaFold), or required substantial human intervention for verification (CoScientist), leaving no practical path to end-to-end data-driven scientific discovery. This position paper argues that large generative models now make it feasible to automate both hypothesis search and verification from observational data, while simultaneously demonstrating that LGMs alone are insufficient without fail-proof tool integration and active user moderation.

## Input / Output

The system accepts a tabular dataset with its metadata as the primary input, optionally augmented by a natural language query specifying a high-level research objective or a specific hypothesis to test. It operates in two modes: fully autonomous (considering the full hypothesis space) and user-guided (narrowing search via the query). Outputs are structured as a multi-agent dialogue producing a decomposed research plan, executable Python code for statistical tests (e.g., OLS, GLM, t-tests, logistic regression), test results with interpretation, generated hypotheses with null/alternative formulations, and interdisciplinary analytical insights. User feedback can be injected at any point to redirect the discovery process.

## Method

DATAVOYAGER employs a role-based multi-agent architecture built on the AutoGen framework, powered by GPT-4, with five specialized agents: a Planner that interprets queries and decomposes objectives into executable sub-tasks, a Programmer that performs data transformations and generates or invokes code for statistical analyses, a Data Expert that interprets results and connects interdisciplinary knowledge, a Critic that evaluates analytical methods, and a User Proxy that facilitates on-demand human feedback. The system leverages GPT-4's function-calling capability to invoke pre-defined, fail-proof statistical functions (e.g., run_logistic_regression, t-test) alongside unconstrained code generation for custom analyses, combining structured tool use with free-form program synthesis. Agents communicate in arbitrary order via AutoGen's group chat mechanism, enabling dynamic orchestration where the Planner delegates sub-tasks, the Programmer executes them, and the Data Expert and Critic iteratively refine the analysis. The key design principle is that LGMs provide the knowledge, planning, and code-generation backbone, while external structured tools and user moderation address LGM limitations in hallucination, long-horizon reasoning, and domain-specific reliability.

## Results

This is a position paper with a qualitative proof-of-concept (DATAVOYAGER) rather than a quantitative benchmark study. DATAVOYAGER, built on GPT-4 with the AutoGen multi-agent framework, is demonstrated on National Longitudinal Survey of Youth (NLSY) data across three research questions (time preference vs. BMI, incarceration vs. wealth, social background vs. degree completion). The system qualitatively demonstrates capabilities in data understanding, hypothesis generation, multi-step planning, statistical verification (t-tests, OLS, GLM, logistic regression with interaction terms), interdisciplinary knowledge integration, and human feedback accommodation. No standard quantitative metrics (accuracy, F1, etc.) are reported; the paper instead argues for desiderata and identifies open research challenges.

## Baselines & Comparisons

This position paper does not conduct formal quantitative baseline comparisons; the `compares_to` set is empty. Instead, it provides a qualitative survey (Figure 3) of seven existing systems (MLAgentBench, CoScientist, Bacon, DataLume, ThoughtSpot, Google AutoML, WolframAlpha) across seven desiderata dimensions. The survey reveals that no single existing system covers all desired functionalities for end-to-end data-driven discovery: CoScientist requires wet-lab experiments (not fully autonomous), DataLume lacks hypothesis search for complex workflows, Bacon lacked computational power, and AutoML/ThoughtSpot/WolframAlpha do not support hypothesis generation or knowledge integration. The authors position DATAVOYAGER as a baseline that, for the first time, partially addresses multiple desiderata simultaneously (data understanding, hypothesis generation, planning, statistical verification, and knowledge integration) through LGM capabilities, while explicitly acknowledging gaps in scale, p-hacking resistance, and long-horizon planning that remain open research challenges.

## Relation to Prior Work

This position paper builds on the multi-agent LLM architecture lineage (AgentBench, Sotopia) and GPT-4's function-calling and code-generation capabilities to propose DATAVOYAGER, a proof-of-concept for end-to-end data-driven scientific discovery. It explicitly positions itself against prior discovery systems—Bacon (1981) lacked computational power, CoScientist (2023) required wet-lab verification, and DataLume (2023) handled only code generation without hypothesis search—arguing that LGMs now make the full hypothesis-search-and-verify loop practically tractable for the first time. The paper also draws on planning (ADAPT, Voyager), continual learning (CLIN, Reflexion), and Swanson Linking literature to frame the desiderata for an ideal system, while distinguishing its data-driven scope from AutoML and automated data-analysis tools that lack hypothesis generation and knowledge integration.

## Why It Matters / Open Questions

The paper identifies a concrete research gap: no existing system performs fully autonomous, end-to-end data-driven discovery (hypothesis search + verification) from observational data, and it provides a structured taxonomy of required capabilities (data understanding, hypothesis generation, multi-step planning, verification, continual learning, p-hacking prevention) that can guide future work. Its key caveat—that LGMs alone are insufficient and that fail-proof tool integration, scale, and active user moderation are essential—sets realistic expectations and opens specific research questions (long-horizon planning, inference-time tool adaptation, mixed-initiative interaction). Broader concerns around reproducibility, p-hacking at scale, policy misuse, and bias percolation from both data and models are flagged as unresolved challenges that any deployed system must address.
