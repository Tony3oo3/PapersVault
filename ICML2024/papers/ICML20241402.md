## Problem

Existing heterogeneous DPFL algorithms either require a trusted server or weight clients' updates by their reported privacy parameter ε_i, which is both suboptimal (the actual noise level also depends nonlinearly on batch size and dataset size) and vulnerable to clients falsifying their ε values to gain larger aggregation weights. This paper tackles the underexplored setting of local heterogeneous DPFL with an untrusted server where clients simultaneously have non-uniform privacy parameters, batch sizes, and dataset sizes.

## Input / Output

At each round the server receives a matrix M ∈ R^{p×|S^e|} of noisy model updates from participating clients, where p is the number of model parameters (up to ~21M for ResNet-34 on CIFAR-100). Crucially, the server does not need clients' true privacy parameters — it estimates each client's noise level directly from the geometric structure of M via RPCA, making the method immune to falsified ε reports. The output is a globally trained model satisfying per-client (ε_i, δ_i)-DP guarantees, with aggregation weights inversely proportional to estimated per-client noise variance.

## Method

The key insight is that the noise variance σ_i² in a client's model update depends nonlinearly on ε_i, batch size b_i, and dataset size N_i, so weighting by ε_i alone (as in PFA/WeiAvg) is suboptimal. Robust-HDP exploits the fact that under moderately heterogeneous data, the matrix of clients' updates decomposes into a low-rank signal component L and a sparse noise component S via Robust PCA (Principal Component Pursuit). The ℓ₂ norm of each column of S yields an estimate of that client's noise variance, and aggregation weights are set as w_i ∝ 1/σ̂_i², which is provably close to the optimal inverse-variance weighting. For scalability to large models, RPCA is applied to row sub-matrices of M (e.g., 200K rows at a time) and the resulting noise estimates are averaged. The paper proves per-client (ε_i, δ_i)-DP via parallel composition and establishes convergence under heterogeneous local steps, batch sizes, and varying aggregation weights.

## Results

On FMNIST (E=200), Robust-HDP achieves per-parameter noise variance in the aggregated model update nearly identical to the Oracle optimum (Eq. 8) across all nine privacy distributions: e.g., 0.27 vs. 0.27 (Dist1), 7.62 vs. 7.60 (Dist6), and 5.95 vs. 5.93 (Dist9). Baselines are orders of magnitude worse, with minimum ε reaching 1868.45 on Dist6 versus Robust-HDP's 7.62. On MNIST with heterogeneous data split (60 clients, max 8 labels/client), Robust-HDP achieves 84.84% average test accuracy (Dist1) and 73.82% (Dist9), outperforming WeiAvg (81.14%/72.07%), PFA (81.29%/72.97%), and DPFedAvg (82.61%/73.03%). Robust-HDP also converges faster and remains robust when a client sends a falsified privacy parameter to the server.

## Baselines & Comparisons

Robust-HDP outperforms all four baselines on both noise variance and test accuracy across all datasets and privacy distributions. Compared to WeiAvg and PFA (Liu et al., 2021a), which use w_i ∝ ε_i aggregation, Robust-HDP reduces noise variance by 3–250× (e.g., 0.27 vs. 1.02 on Dist1; 7.62 vs. 28.29 on Dist6) because it accounts for batch-size heterogeneity that ε-proportional weighting ignores. Against DPFedAvg (Noble et al., 2021), which weights by dataset size N_i, Robust-HDP is 4–94× better on noise variance (e.g., 0.27 vs. 1.27 on Dist1; 7.62 vs. 70.71 on Dist6). The minimum ε baseline (Liu et al., 2021a) is the worst, with noise variance up to 245× higher than Robust-HDP (1868.45 vs. 7.62 on Dist6), and it diverged in 1 of 3 trials on MNIST. Critically, Robust-HDP is immune to clients falsifying their ε values to the server, whereas WeiAvg and PFA degrade significantly under such attacks (Figure 5, right).

## Relation to Prior Work

This paper builds on two distinct lines of work: DPSGD (Abadi et al., 2016) as the local noise mechanism each client employs, and Robust PCA / Principal Component Pursuit (Candes et al., 2009) as the server-side tool for decomposing the aggregated update matrix into a low-rank signal and a sparse noise component. It departs from prior heterogeneous DPFL methods (PFA, WeiAvg, DPFedAvg) that either require a trusted server or rely on clients' self-reported privacy parameters ε for aggregation weighting. The key conceptual departure is recognizing that ε alone is an incomplete proxy for a client's actual noise level—batch size and dataset size introduce additional, non-linear variation—motivating a noise-aware aggregation strategy that is independent of any client-reported privacy values.

## Why It Matters / Open Questions

The finding that straightforward aggregation strategies (w_i ∝ ε_i) are suboptimal and vulnerable to falsified privacy parameters addresses a practical security gap in untrusted-server DPFL deployments. The RPCA-based noise estimation is elegant in its independence from client-reported values, but its effectiveness depends on the noise matrix being approximately sparse (requiring sufficient variation in ε and batch sizes across clients) and the underlying signal matrix being low-rank (constrained by data heterogeneity). Open questions include performance under highly heterogeneous data splits, scalability to very large models where RPCA precision degrades, and whether the sparse-noise assumption holds in realistic deployments with limited client diversity.
