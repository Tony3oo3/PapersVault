## Problem

Speculative decoding accelerates LLM inference by having a small draft model propose tokens that a large target model verifies in parallel, but its speedup is bottlenecked by the draft model's low token acceptance rate, especially under diverse query distributions and large capability gaps. Existing approaches treat the draft model as static after deployment, ignoring the fact that real serving workloads exhibit domain-specific and temporally shifting query distributions that a fixed model cannot track.

## Input / Output

The system consumes a streaming sequence of user text prompts alongside a frozen target LLM (e.g., Vicuna-7B or FLAN-T5-XL 3B) and one or more small draft models (e.g., LLaMA-160M or T5-Small 80M). For each prompt, the draft model proposes k=5 candidate tokens, the target model verifies them in a single parallel pass, and the accepted tokens (plus one bonus token) are appended to the output. Concurrently, the system records the error index and the target model's full logit distribution at each rejection point into a replay buffer, which is periodically consumed to update the draft model weights via a distillation loss. The update interval I (fixed at 8 requests in experiments) is dynamically adjustable based on system load.

## Method

OSD frames draft-model improvement as online knowledge distillation where the target LLM is the teacher and the draft model is the student. During each speculative decoding step, the target model's verification pass naturally exposes both the draft's erroneous proposals and the correct token distributions, which are stored in a replay buffer; every I requests, the draft model is fine-tuned by minimizing a generalized KL-based loss (forward KL, reverse KL, or JSD) between the target and draft distributions over the buffered (prompt, error_index, target_logits) tuples, using teacher-sampled, student-sampled, or mixed token sequences. To further narrow the effective query distribution, OSD supports multiple domain-specialized draft models (by language or topic) and routes each incoming query to the best-matching draft via lightweight metadata tags or a 67M BERT classifier, reducing per-model learning difficulty. The approach is orthogonal to how the initial draft model is constructed and can be layered on top of existing speculative decoding variants such as Medusa's multi-head decoding.

## Results

OSD achieves a token acceptance rate increase of 0.1 to 0.65 over the original draft model, translating to a 1.42×–2.17× end-to-end latency reduction across four datasets (Spider, Gsm8k, Code-search-Python, Alpaca-finance). With the (TinyLLaMA-1.1B, Vicuna-33B) pair, OSD reaches up to 2.17× speedup on Spider and 1.51× on Chatbot Arena; with the (LLaMA-160M, Vicuna-7B) pair, speedups range from 1.36× to 1.63×. At a token acceptance rate of 0.9, the theoretical maximum speedup reaches 2.63× (measured 2.55×) for the 160M/7B pair and 2.63× for the 1.1B/33B pair.

## Baselines & Comparisons

The paper's sole external baseline is Medusa (Cai et al., 2024), which uses additional linear decoding heads on the target model rather than a separate draft model. On Spider, OSD applied to a standard draft model (LLaMA-160M) achieves 2.17× speedup, outperforming both vanilla Medusa-7B (1.34×) and Medusa+OSD (2.01×) by 0.83× and 0.16× respectively. On Chatbot Arena, the picture reverses: Medusa+OSD (2.38×) beats both vanilla Medusa (2.03×) and draft-model+OSD (1.51×), because Medusa's heads were pre-trained on ShareGPT data that closely matches the Arena distribution. Overall, OSD consistently improves upon its host method by 0.35×–0.67×, but the relative advantage of a separate draft model versus Medusa's heads depends on how well the draft model's training distribution aligns with the serving workload.

## Relation to Prior Work

OSD builds directly on speculative decoding (Leviathan et al., 2023), where a small draft model proposes tokens that a large target model verifies in parallel, and on generalized knowledge distillation (Agarwal et al., 2023; Gu et al., 2023), which aligns a student's output distribution to a teacher's via KL-based objectives. The key departure is making the draft model dynamic: rather than treating it as a static artifact trained offline, OSD continuously fine-tunes it during serving using the verification signals already produced by speculative decoding, effectively turning the target model's corrections into free training data. The paper also introduces draft model routing across query domains (language, topic), which extends the single-draft-model assumption in prior speculative decoding work. Concurrent work DistillSpec (Zhou et al., 2023) applies KD to speculative decoding but is acknowledged as a specific subset of OSD's broader online framework.

## Why It Matters / Open Questions

The practical impact is significant for LLM serving: a 0.1–0.65 increase in token acceptance rate translates to 1.42×–2.17× latency reduction, and the FLOPs analysis shows the update cost is negligible relative to target model inference (and real clusters operate at <1% utilization). Open questions remain around the optimal number and size of domain-specific draft models, the best routing/classification strategy, replay buffer eviction policies, and whether the approach scales to much larger target models (≥70B) where the draft-to-target size ratio and memory constraints differ. The finding that the draft model retains prior knowledge when adapting to new distributions (no catastrophic forgetting) is encouraging but tested only on two small model pairs and a handful of datasets.
