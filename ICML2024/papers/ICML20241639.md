## Problem

Existing synthetic data generation (SDG) methods assume a trusted aggregator that receives raw data from all sources, but in practice data is distributed across organizations (hospitals, companies) that cannot legally or practically share it. No prior solution generates differentially private synthetic data from arbitrarily partitioned (horizontal, vertical, or mixed) distributed sources using marginal-based synthesizers without relying on a single trusted entity or specialized hardware.

## Input / Output

The framework takes N data holders' private tabular datasets (secret-shared to M MPC servers), a domain specification Ω defining attribute value spaces, a query workload Q of 1-way and 2-way marginals, and privacy parameters (ε, δ). Data holders perform local computations (LOCAL_COMPUTE) to pre-compute partial marginal answers, reducing MPC overhead. The output is a differentially private synthetic tabular dataset D̂ published by the initiating server S₁, with utility matching the centralized paradigm.

## Method

CaPS exploits the observation that in the select-measure-generate template, only the select and measure steps require access to private data, while generate is DP-safe post-processing. The framework applies 'DP-in-MPC': MPC servers run protocols π_COMP (aggregating secret-shared marginal answers, including a join for vertical partitions), π_SELECT (computing errors, normalizing, and applying the exponential mechanism entirely within MPC to pick the next query), and π_MEASURE (generating Gaussian noise via Irwin-Hall approximation or Box-Muller inside MPC and adding it to the true marginal). The noisy measurement is then revealed to S₁, which runs the generate step in the clear. The design is modular—protocols for select and measure can be swapped to adapt to any marginal-based SDG algorithm (demonstrated for MWEM+PGM and AIM)—and supports 2PC, 3PC, and 4PC settings with passive or active adversaries.

## Results

On COMPAS (7,214 samples), CaPS matches CDP within 0.01–0.02 on all ML metrics (e.g., AIM LR-AUC: CDP 0.67 vs. CaPS(H) 0.66 vs. CaPS(V) 0.68) and workload error (CDP 0.017 vs. CaPS 0.015–0.019). On Diabetes (768 samples), CaPS similarly matches CDP (e.g., MWEM+PGM LR-AUC: CDP 0.62 vs. CaPS(H) 0.64 vs. CaPS(V) 0.67; ERROR Δ: CDP 0.15 vs. CaPS 0.14). On the smaller Breast Cancer dataset (285 samples), results show higher variability but remain comparable (e.g., AIM ERROR Δ: CDP 0.30 vs. CaPS 0.23). Runtime overhead of CaPS over CDP ranges from ~1.1× (horizontal, small datasets) to ~5× (vertical, MWEM+PGM on COMPAS), with 3PC passive providing the lowest MPC cost.

## Baselines & Comparisons

The primary baseline is CDP (Central Differential Privacy), where all data is aggregated at a trusted central entity and DP noise is added in the clear. CaPS matches CDP utility on COMPAS and Diabetes across both AIM and MWEM+PGM, with differences typically ≤0.02 in AUC/F1 and ≤0.01 in workload error Δ. On the smaller Breast Cancer dataset (n=285), CaPS shows greater variance (e.g., AIM RF-AUC drops from 0.58 CDP to 0.45 CaPS(H)), which the authors attribute to the small sample size amplifying DP randomness. In terms of runtime, CaPS incurs 1.1×–5× overhead over CDP depending on data distribution and algorithm: horizontal setups add minimal overhead (~1.1×), while vertical setups with MWEM+PGM on COMPAS reach ~2.5× (152s vs. 61s). The paper does not directly benchmark against other distributed SDG methods (e.g., FL-based approaches) in the main tables, positioning CDP as the utility reference and emphasizing that CaPS is the first to achieve this utility level without a trusted aggregator or specialized hardware.

## Relation to Prior Work

This paper builds on the select-measure-generate template used by state-of-the-art marginal-based synthetic data generators (MWEM+PGM and AIM) and introduces a 'DP-in-MPC' paradigm that embeds differential privacy mechanisms within secure multi-party computation protocols. It departs from federated learning approaches (Xin et al., 2020; Behera et al., 2022) that handle only horizontal or vertical partitioning and rely on a single honest-but-curious aggregator, as well as from Ramesh et al. (2023) which requires specialized hardware (TEE). The framework generalizes the authors' prior workshop exploration of DP-in-MPC on an older SDG algorithm (Hardt & Rothblum, 2010) to modern marginal-based synthesizers and arbitrary data partitioning, while leveraging the modularity of MPC schemes (2PC, 3PC, 4PC) to support different threat models.

## Why It Matters / Open Questions

CaPS addresses a practical bottleneck in regulated domains (healthcare, finance) where data holders cannot share raw data with a central aggregator, enabling collaborative synthetic data generation with both input and output privacy guarantees. The modular design means new SDG algorithms can be adapted by simply designing MPC protocols for their select and measure steps, and the underlying MPC primitives can be swapped for more efficient future schemes. Key limitations include the MPC overhead in π_COMP for arbitrary (especially vertical) distributions, which scales with total sample count n, and the current evaluation on relatively small datasets (n ≤ 7,214). Open questions include scalability to millions of users, extension to other data modalities (images, text), and optimization of the join/marginal computation protocols for large-scale deployments.
