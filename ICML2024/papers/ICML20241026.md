## Problem

ML-based approaches for exact CO solvers (e.g., GNNs for branching) are black-box and cannot explain what structural patterns they exploit, hindering further algorithmic understanding and improvement. Prior symbolic discovery methods for CO rely on human-designed fixed-length features requiring extensive domain knowledge, and existing graph-based symbolic distillation (layer-by-layer from trained GNNs) suffers from cumulative error that leads to suboptimal policies. The paper asks: can we learn interpretable symbolic branching policies directly from the general bipartite graph representation of MILP problems, without handcrafted features or iterative distillation?
![Teaser figure](../imgs/ICML20241026/cropped_page1_idx0.webp)

## Input / Output

The method takes the variable-constraint bipartite graph of a MILP instance as input, where each constraint node carries 5 features (cosine similarity, bias, tight indicator, dual value, age), each variable node carries 19 features (type, coefficient, bounds, fractionality, basis, reduced cost, etc.), and each edge carries 1 feature (normalized coefficient). The output is a symbolic tree that, when evaluated on a graph state, produces a scalar score for every fractional branching variable; the variable with the highest score is selected for branching. The symbolic tree encodes up to two hops of neighborhood aggregation (via min/max/mean/sum operators as subtree roots) followed by a main scoring function, making it a compact, human-readable expression rather than a neural network.

## Method

GS4CO introduces a unified symbolic tree representation in which graph aggregation operators (min, max, mean, sum) serve as subtree roots, allowing a single tree to consistently encode both mathematical functions and multi-hop neighborhood aggregation over the bipartite graph. A decoder-only Transformer generates the tree token-by-token via depth-first traversal, augmented with four tree-structural encodings (positional, layer, active parent & sibling, and spatial) that capture the hierarchical structure of the expression tree. Training uses PPO with a risk-seeking objective, where the fitness is the imitation accuracy against full strong branching (FSB) expert demonstrations collected from 100 training instances. Six search-space constraints (three graph-specific: aggregation input requirements, main-function input restrictions, and a two-layer depth cap) prevent trivial policies and accelerate convergence. The key architectural insight is that end-to-end generation of the full symbolic tree avoids the cumulative approximation error inherent in iteratively distilling each GNN layer separately, yielding policies that are ~500× lighter and ~20× faster to infer than GNN baselines while outperforming them on CPU.

## Results

On the four standard CO benchmarks (Setcover, Cauctions, Facilities, Indset), GS4CO achieves the best end-to-end solving time and the most instances solved to optimality among all CPU-based methods. For example, on Indset-Easy, GS4CO solves 33/50 instances within 3000s (vs. GNN 11/50, Hybrid 4/50, RPB 2/50) in 53.18s; on Cauctions-Easy it solves 30/50 in 3.16s (vs. Hybrid 17/50 in 3.35s). The learned policies are also ~500× smaller (0.49 KB vs. 266 KB for GNN) and ~20× faster for CPU inference (1.84 ms vs. 33.88 ms). GS4CO generalizes well to larger (Hard) instances, e.g., on Indset-Hard it solves 24/37 instances in 2157s versus Hybrid's 8/33 in 2223s.

## Baselines & Comparisons

GS4CO outperforms the human-designed FSB and RPB policies (Achterberg, 2007) by a wide margin on all four benchmarks, e.g., reducing Indset-Easy time from 243.58s (FSB) to 53.18s while solving 33 vs. 0 instances to optimality. Against the interpretable Trees model (Alvarez et al., 2017), GS4CO achieves substantially higher imitation accuracy (44.13% vs. 40.43% on Setcover) and far better end-to-end performance. Compared to the GNN baseline (Gasse et al., 2019), GS4CO matches or exceeds CPU inference speed while being ~500× lighter; the GNN-GPU variant is faster but requires GPU hardware unavailable on typical solver servers. Versus the Hybrid model (Gupta et al., 2020), GS4CO wins on 3 of 4 benchmarks (Setcover, Cauctions, Indset) on Easy instances and clearly dominates on Hard instances (e.g., Facilities-Hard: 1018.70s/22 wins vs. 1219.91s/11 wins), though Hybrid retains a slight edge on Facilities-Easy. Against the prior symbolic approach Symb4CO (Kuang et al., 2024), GS4CO achieves slightly lower imitation accuracy (44.13% vs. 45.37% on Setcover) but comparable or better end-to-end solving time (13.29s vs. 13.45s for the C++ version), while requiring far less domain knowledge for feature design.

## Relation to Prior Work

This paper sits at the intersection of two research threads: (1) GNN-based branching for MILP solvers (Gasse et al., 2019; Gupta et al., 2020), which learns black-box policies from variable-constraint bipartite graphs, and (2) deep symbolic regression (Petersen, 2019; Landajuela et al., 2021), which generates interpretable mathematical expressions via PPO-trained sequential models. The key departure is from both: prior symbolic approaches for CO (Kuang et al., 2024) only handle handcrafted fixed-length feature vectors, while prior GNN distillation methods (Cranmer et al., 2020) fail on branching due to cumulative error across layers. GS4CO is the first to unify these by learning symbolic aggregation functions directly from graph inputs using a Transformer with tree-structural encodings, generating the full policy end-to-end rather than layer-by-layer.

## Why It Matters / Open Questions

The practical significance is that a 0.49 KB symbolic policy outperforms a 266 KB GNN in end-to-end CPU solving time across four benchmarks, demonstrating that interpretability need not come at a performance cost for deployment on CPU-only solver servers. The learned policies reveal that effective branching relies on surprisingly sparse structural information (only a few node features, no edge features, two-hop aggregation), which can guide both human and automated solver design. Key limitations include: the imitation accuracy is still lower than GNNs (44% vs 54% on Setcover), the approach is restricted to the variable-selection component of branching, and it still requires manually designed node features. Open questions include extending to other solver components (cut selection, primal heuristics, node selection), moving from pure mathematical expressions to richer program-level policies (e.g., RPB-like logic), and leveraging LLMs to reduce the combinatorial search space.
