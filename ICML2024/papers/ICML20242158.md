## Problem

Existing synthetic data generation methods for code instruction tuning (SELF-INSTRUCT, Evol-Instruct) rely on a narrow set of predefined seed tasks or heuristics, causing the generated data to inherit the system bias of the teacher LLM and fail to reflect the diversity of real-world programming. This limits the instruction-following capability of open-source code models, which remain substantially behind proprietary systems like ChatGPT on rigorous benchmarks.

## Input / Output

At the data generation stage, OSS-INSTRUCT consumes 1–15 consecutive lines of code randomly extracted from 80K documents in starcoderdata (a decontaminated subset of The Stack spanning Python, C++, Java, TypeScript, Shell, C#, Rust, PHP, and Swift) and produces a self-contained coding problem paired with a correct solution via a single teacher-LLM call. At inference time, the resulting Magicoder models take a natural-language task description (e.g., a docstring) or a partial code context as input and emit a complete source-code solution, evaluated with greedy decoding (pass@1) on benchmarks ranging from single-function Python tasks to multilingual completion and data-science pipelines.

## Method

OSS-INSTRUCT prompts a teacher LLM (GPT-3.5-turbo-1106) with a seed code snippet and a structured template that asks it to imagine a realistic, self-contained coding problem and write a correct solution, using the snippet purely as creative inspiration rather than as a template to fill in. This yields 75K diverse instruction pairs covering algorithmic challenges, library-based completion, whole-program development, and even whole-application construction, with the lowest TF-IDF cosine similarity to HumanEval among all compared generation methods, confirming distributional novelty. The base CODELLAMA-PYTHON-7B is fine-tuned for 2 epochs on this data (Adafactor, lr 5e-5, batch 512, seq length 1216) to produce Magicoder-CL; a second stage on 110K evol-codealpaca-v1 samples (orthogonal Evol-Instruct data) yields MagicoderS-CL. An ablation shows that directly fine-tuning on semantically matched comment–function pairs from the same corpus actually degrades performance, validating that the LLM-mediated transformation from raw snippets into coherent problem–solution pairs is essential for data factuality. The same pipeline applied to DeepSeek-Coder-Base-6.7B produces Magicoder-DS and MagicoderS-DS, with the latter reaching 76.8 pass@1 on HumanEval using 8× fewer fine-tuning tokens than DeepSeek-Coder-Instruct-6.7B.

## Results

On HumanEval+ (pass@1, greedy decoding), MagicoderS-CL (7B) achieves 66.5%, surpassing ChatGPT (65.9%) and all open-source models, while MagicoderS-DS (6.7B) reaches 70.7%. On MBPP+, MagicoderS-CL scores 56.6% and MagicoderS-DS scores 64.4%. On DS-1000 (completion), MagicoderS-CL achieves 37.5% overall, an 8.3-point absolute improvement over WizardCoder-SC-15B (29.2%). On MultiPL-E, MagicoderS-CL (7B) achieves 42.9/57.5/44.4/47.6/44.1/40.3 across Java/JavaScript/C++/PHP/Swift/Rust, approaching WizardCoder-CL-34B with only 7B parameters.

## Baselines & Comparisons

MagicoderS-CL (7B) surpasses ChatGPT (GPT-3.5 Turbo) on the more rigorous HumanEval+ (66.5 vs. 65.9) but trails on standard HumanEval (70.7 vs. 72.6); it remains well below GPT-4 Turbo (85.4). Against CODELLAMA-PYTHON-7B (the base model), Magicoder-CL improves HumanEval from 37.8 to 60.4 and HumanEval+ from 34.1 to 55.5. Magicoder-CL outperforms WizardCoder-CL-7B (60.4 vs. 48.2 on HumanEval) and WizardCoder-SC-15B (60.4 vs. 51.9), and MagicoderS-CL further extends the lead to 70.7. On DS-1000, Magicoder-CL (29.9) and MagicoderS-CL (37.5) outperform INCODER-6.7B (7.4), Code-Cushman-001 (18.1), and WizardCoder-SC-15B (29.2). Against DeepSeek-Coder-Instruct-6.7B, MagicoderS-DS achieves higher HumanEval+ (70.7 vs. 70.1) and MBPP+ (64.4 vs. 63.4) with 8× fewer finetuning tokens (240M vs. 2B). In the ablation using a weaker teacher, Magicoder-CL-Mixtral-7B (55.5 on HumanEval+) outperforms its teacher Mixtral-8x7B-Instruct-v0.1 (39.6), demonstrating that OSS-INSTRUCT activates the base model's own capabilities rather than merely distilling the teacher.

## Relation to Prior Work

This paper extends the synthetic-data instruction tuning paradigm for code LLMs established by SELF-INSTRUCT and Code Alpaca, and the heuristic-based evolution approach of Code Evol-Instruct (WizardCoder). Rather than relying on a fixed set of seed tasks or a small number of evolution heuristics, OSS-INSTRUCT repurposes random open-source code snippets as creative prompts for a teacher LLM to generate diverse, realistic coding problems. The method is explicitly orthogonal to Evol-Instruct, enabling a two-stage pipeline (OSS-INSTRUCT → Evol-Instruct) that the authors show yields further gains. Conceptually, it shifts the source of diversity from prompt engineering to the unbounded variety of real-world code, addressing the bias-inheritance concern raised by prior synthetic-data work.

## Why It Matters / Open Questions

OSS-INSTRUCT provides a practical, fully open-source recipe for generating high-quality code instruction data that substantially narrows the gap between small (≤7B) open models and proprietary systems like ChatGPT. The negative result showing that direct finetuning on semantically-matched comment-function pairs from the same corpus actually degrades performance (while the inspiration-based approach improves it by ~20 points) challenges the intuition that more topically relevant data is always better, pointing to data factuality over format as the critical factor. Open questions include whether the method scales to larger base models, whether self-training with weaker teachers is viable, and whether the gains hold on contamination-free benchmarks like LiveCodeBench.
