## Problem

SSL clustering methods that learn prototypes via gradient descent are notoriously prone to training collapse, requiring additional regularizers (centering, target sharpening, Sinkhorn-Knopp, ME-MAX) to force representations to spread evenly. Moreover, state-of-the-art ViT-based SSL methods (iBOT, DINOv2) optimize over the full transformer output ([CLS] + patch tokens) with MIM, drastically increasing computational cost and training time. The paper asks whether a memory-based, prototype-free formulation can achieve stable SSL training without extra regularizers while operating only on the [CLS] token.

## Input / Output

The method consumes multiple augmented views of an RGB image per iteration (2 global views at 224×224 and 10 local views at 96×96, using color jittering, Gaussian blur, solarization, and random crop) and produces a single 256-d unit-norm embedding vector from the [CLS] token only, projected from the ViT's 768-d output. Unlike iBOT or DINOv2, no patch-level representations are used for the training objective, which is the key architectural simplification that reduces memory and compute. The non-parametric memory (FIFO queue of K=65536 vectors) stores teacher-branch representations from prior iterations and is updated without gradient flow.

## Method

MaSSL augments a standard ViT teacher-student (EMA) architecture with a non-parametric working memory that stores encoded representations from previous training iterations. At each step, the memory is partitioned into B stochastic blocks of N_b randomly sampled representations, and each view's embedding is compared via cosine similarity against each block to produce a softmax-normalized view-memory similarity distribution. The loss is a cross-entropy between the student's and teacher's similarity distributions over each block, forcing views of the same image to activate consistent patterns of memory representations. The stochastic block sampling (rather than contiguous FIFO slices) is critical: it breaks the ordering bias introduced by the FIFO update rule and acts as an implicit regularizer that prevents collapse without any explicit entropy or uniformity penalty. Because the memory is non-parametric and the loss operates only on the [CLS] token, MaSSL avoids the 16M+ extra trainable parameters of DINO's prototype head and the patch-level MIM overhead of iBOT, achieving comparable or better transfer performance in ~9% less training time and 25.6% less GPU memory.

## Results

On transfer learning (k-NN, ViT-B/16, k=20), MaSSL achieves an average of 63.4% across 8 datasets, outperforming DINO (62.0%) and iBOT (60.7%) by +1.4 and +2.7 points respectively, with notable gains of +2.6 on Aircraft and +4.6 on GTSRB. On in-domain ImageNet-1M linear probing (ViT-B/16, 400 epochs), MaSSL reaches 79.6% top-1 accuracy and 77.2% k-NN, matching iBOT (79.5/77.1) and surpassing DINO (78.2/76.1). For image retrieval on Oxford-5k/Paris-6k (ViT-B/16), MaSSL achieves mAP of 39.3/14.1/65.8/38.1 (M/H/M/H), beating DINO in 3/4 scenarios and iBOT in 3/4. Training MaSSL for 800 epochs on ViT-S requires 177.3 hours and 15.1 GB memory, which is ~9% faster and 25.6% less memory than iBOT (193.4H, 19.5G) while achieving comparable or better performance.

## Baselines & Comparisons

Against DINO (Caron et al., ICCV 2021), MaSSL wins on transfer learning (avg +1.4 at k=20), in-domain linear probing (79.6% vs 78.2% on ViT-B), image retrieval (39.3 vs 37.4 mAP on Oxford-5k Medium), copy detection (87.6 vs 86.8 mAP), and low-shot classification (70.4% vs 66.2% at 1 image/class on ViT-B). Against iBOT (Zhou et al., ICLR 2022), MaSSL achieves comparable in-domain linear probing (79.6% vs 79.5%) but clearly wins on transfer learning (avg +2.7 at k=20), copy detection (87.6 vs 84.2 mAP, a +3.4 gap), and low-shot (70.4% vs 68.2% at 1 image/class). Against MoCo-v3 (Chen et al., ICCV 2021), MaSSL substantially outperforms across all benchmarks (e.g., 63.4 vs 54.5 avg k-NN transfer, 79.6 vs 76.7 linear probing). Against the supervised DEIT baseline (Touvron et al., ICML 2021), MaSSL is within 2.2% on ViT-B linear probing (79.6% vs 81.8%) while being fully self-supervised. Against the supervised retrieval method Revaud et al. (ICCV 2019), MaSSL remains below (39.3 vs 49.8 on Oxford-5k Medium) but narrows the gap significantly compared to other SSL methods.

## Relation to Prior Work

MaSSL builds directly on DINO's teacher-student EMA architecture with ViT backbones but replaces the learned prototype layer (65,536 centroids trained via gradient descent) with a non-parametric FIFO memory of past representations, eliminating the need for explicit anti-collapse regularizers (centering, sharpening, Sinkhorn-Knopp, ME-MAX). The stochastic memory block mechanism draws on the random partition pretext task from Silva & Ramirez Rivera (2023), repurposing it to break FIFO ordering bias and regularize training. Conceptually, the paper reframes SSL clustering as a memory-comparison problem: rather than learning fixed prototypes, the network formulates discriminative tasks by comparing current views against randomly sampled past experiences, positioning itself as a negative-free contrastive method distinct from MoCo/PIRL queue-based approaches that mine negatives.

## Why It Matters / Open Questions

The practical significance lies in demonstrating that training collapse in SSL can be avoided without any explicit regularizer, purely through stochastic memory block sampling, while operating only on the [CLS] token to achieve ~9% faster training and 25.6% less GPU memory than iBOT. However, the performance gains over DINO and iBOT are modest (typically 0.1–0.5 points on most benchmarks), and the method still requires careful tuning of memory size and block size. Open questions include whether the memory-based approach scales to larger datasets or multi-modal settings, whether the FIFO ordering bias issue generalizes to other queue-based methods, and whether the [CLS]-only limitation affects dense prediction tasks more severely than the sparse correspondence results suggest.
