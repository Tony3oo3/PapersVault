## Problem

WebAssembly's implicit stack machine, limited numeric types (i32, i64, f32, f64), and minified/obfuscated variable names make it extremely difficult for humans and LLMs to understand, yet effective decompilation is critical for security analysis and code review. Naive end-to-end sequence-to-sequence translation fails because of the scarcity of WebAssembly pretraining data and the complexity of tracking implicit data flow, and existing decompilers (wasm2c, Benali 2022) cannot produce compilable code on real-world benchmarks.

## Input / Output

The method takes WebAssembly text format (WAT) code—compiled from C++ via Emscripten and converted with WABT—as input, which is first annotated line-by-line with explicit virtual stack states by a static analysis tool (nearly doubling the code size). The annotated WAT is then fed to an LLM in a structured 4-step CoT prompt, producing as output: predicted C/C++ data types for parameters and return values, semantically named local variables, a natural-language function summary, and finally equivalent C++ source code enclosed in a code block.

## Method

StackSight is a three-stage neurosymbolic pipeline that decomposes WebAssembly decompilation into intermediate reasoning steps mirroring human reverse engineering. First, a static analysis algorithm simulates all 172 WebAssembly opcodes to annotate each WAT line with the precise virtual stack state, using symbolic execution to track divergent control-flow branches. Second, a chain-of-thought prompting strategy guides the LLM through four sequential steps: (1) predicting high-level data types from stack operations, (2) recovering semantic names for each local variable based on operation histories, (3) summarizing the function's purpose in natural language, and (4) generating equivalent C++ code. The approach uses 1-shot in-context learning with the annotated WAT, and the key insight is that explicit stack tracking plus structured intermediate reasoning steps significantly outperform direct translation, reducing hallucinations and improving functional correctness by up to 70% over ICL baselines.

## Results

StackSight achieves the highest functional correctness across all models and datasets. On HumanEval-X, GPT-4 with StackSight reaches 36.5% correct (passing all test cases) versus 19.7% for 1-shot ICL, while on MBXP it reaches 59.6% versus 42.4%. For Code Llama-7b, StackSight more than doubles the correct rate on HumanEval-X (24.6% vs. 13.5% for 1-shot) and improves MBXP from 10.3% to 15.4%. The paper reports an overall 70% increase in functionally correct decompiled code compared to the strongest ICL baseline.

## Baselines & Comparisons

The paper compares StackSight against in-context learning (ICL) baselines with 1-shot, 3-shot, 5-shot, and 10-shot examples across three LLMs (GPT-3.5-turbo, GPT-4, Code Llama-7b). StackSight consistently outperforms all ICL baselines on both compile rate and functional correctness across every model-dataset combination. The largest gains appear with GPT-4 on MBXP (+17.2 pp correct) and with Code Llama on HumanEval-X (+11.1 pp correct over the best ICL baseline), suggesting that the neurosymbolic pipeline is especially beneficial for smaller models and more complex code. Notably, increasing ICL shots from 1 to 10 does not monotonically improve results (e.g., GPT-3.5 on MBXP drops from 19.6% to 10.2% correct), whereas StackSight with just 1-shot example surpasses all multi-shot ICL variants. The authors also note that existing WebAssembly decompilers (wasm2c from WABT and the transformer-based decompiler of Benali 2022) fail to produce compilable code on these datasets and are therefore excluded from quantitative comparison.

## Relation to Prior Work

This paper extends the Chain-of-Thought prompting paradigm (Wei et al., 2022) into the reverse engineering domain, specifically for WebAssembly decompilation, where no prior work had applied multi-step LLM reasoning. It departs from earlier WebAssembly decompilation efforts (Benali 2022; Lehmann & Pradel 2022; Romano & Wang 2023) that relied on end-to-end sequence-to-sequence models or type-recovery classifiers, by introducing a neurosymbolic pipeline that couples a dedicated static analysis tool (virtual stack tracking across all 172 opcodes) with structured CoT prompting. The approach also differentiates itself from LLM-based decompilation of native x86/ARM binaries (Pearce et al. 2022; Xu et al. 2023; Wong et al. 2023) by targeting WebAssembly's unique implicit stack machine, which has no direct analogue in register-based architectures.

## Why It Matters / Open Questions

As WebAssembly adoption grows across browsers, IoT, and smart contracts, the inability to understand minified or third-party WASM modules poses real security risks (e.g., cryptojacking), making effective decompilation practically urgent. The paper demonstrates that LLMs alone are insufficient for WebAssembly due to data scarcity, and that explicit program analysis (stack visualization) is a necessary complement—a finding that could generalize to other low-resource, stack-based ISAs. Limitations include evaluation on relatively short, exercise-level functions (avg. ~10 lines of C++), testing on only three models, and the static analysis tool being tightly coupled to the WebAssembly specification, leaving open whether the neurosymbolic CoT strategy scales to large, multi-module WASM binaries or heavily obfuscated production code.
