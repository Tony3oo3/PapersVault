## Problem

LLM agents typically produce actions as JSON or text in pre-defined formats, which limits them to a constrained action space (only pre-defined tools) and restricted flexibility (inability to compose multiple tools or use control flow in a single action). The paper asks how to effectively expand LLM agents' action space to handle complex, multi-step real-world tasks that require coordination of multiple tools, dynamic adjustment based on observations, and access to existing software libraries.

## Input / Output

The agent receives natural language instructions from users, tool/API definitions, and environmental observations (code execution results, error messages, tracebacks) across multiple interaction turns. Its output is a full executable Python code block enclosed in <execute> tags that can contain multiple function calls, for-loops, if-statements, variable assignments, and package imports — not merely a single atomic tool invocation. The agent also produces natural language responses to users and a final answer in a specified format. A key structural constraint is that each turn's code is executed in a persistent Python interpreter, so variables and state persist across turns, enabling the agent to build on prior computations and self-debug based on error feedback.

## Method

CodeAct consolidates all agent-environment actions into executable Python code, integrated with a Python interpreter that returns execution results and error messages as observations for multi-turn interaction. The core insight is that LLMs already possess extensive programming knowledge from pre-training on code, making Python a natural and cost-effective action format that natively supports control flow (loops, conditionals) and data flow (variable storage, composition of multiple tool calls) without requiring hand-crafted task-specific tools. To improve open-source models, the authors construct CodeActInstruct (7,139 multi-turn trajectories) by repurposing five existing datasets (HotpotQA, MATH, APPS, WikiTableQuestion, ALFWorld) and selectively retaining trajectories where the model encounters errors and self-corrects, promoting self-debugging capability. CodeActAgent is then obtained via full-parameter supervised fine-tuning of LLaMA-2-7B and Mistral-7B on a mixture of CodeActInstruct and general conversation data (OpenOrca, ShareGPT, CapyBara), using a 4×A100 node with sequence lengths of 4,096 (Llama-2) or 16,384 (Mistral), 5 epochs, and cosine-decay learning rate scheduling.

## Results

On the new M³ ToolEval benchmark (82 complex multi-tool tasks), CodeAct achieves up to 20% absolute improvement in success rate over JSON and text actions, with gpt-4-1106-preview reaching 74.4% success rate (vs. 53.7% text, 52.4% JSON) while requiring 2.1 fewer interaction turns on average. On API-Bank atomic tool calls, CodeAct matches or exceeds baselines for 8 out of 17 LLMs overall. The fine-tuned CodeActAgent (Mistral-7B) achieves an overall average of 42.5 across agent and generic tasks, outperforming all open-source baselines (FireAct: 14.0, AgentLM: 24.8, Mistral Instruct: 25.6) and approaching gpt-3.5-turbo (54.0), while maintaining or improving general capabilities (e.g., 58.0% GSM8K vs. 43.3% for Mistral Instruct).

## Baselines & Comparisons

Against FireAct (Chen et al., 2023a), CodeActAgent (LLaMA-2) achieves a 119% relative improvement in overall average (30.7 vs. 14.0), with dramatic gains on MINT in-domain (51.3 vs. 0.0) and out-of-domain (20.4 vs. 0.3), while FireAct shows near-zero performance on all agent tasks. Against AgentLM/AgentTuning (Zeng et al., 2023), CodeActAgent (LLaMA-2) achieves a 24% relative improvement in overall average (30.7 vs. 24.8), with a 5.9× advantage on MINT in-domain (51.3 vs. 8.7) and a 2.9× advantage on SciWorld (17.6 vs. 13.7), though AgentLM retains a slight edge on MiniWob++ (28.9 vs. 25.5). The Mistral-based CodeActAgent further extends these margins, reaching 42.5 overall (vs. 25.6 for Mistral Instruct) and 46.2 on MiniWob++ (vs. 0.5 for Mistral Instruct), while also improving generic tasks like GSM8K (58.0 vs. 43.3) and HumanEval (34.7 vs. 29.3). Notably, CodeActAgent (LLaMA-2) matches AgentLM on MiniWob++ despite never being explicitly tuned for text actions, suggesting the CodeAct training transfers to other action formats.

## Relation to Prior Work

This paper builds on the MINT multi-turn interaction framework for evaluating LLM agents and extends the line of work on agent instruction tuning (AgentTuning/AgentLM, FireAct) by replacing text-based actions with executable Python code. It departs from prior code-generation-for-problem-solving work (Voyager, code-as-policy, PaL) by making code a multi-turn, dynamically adjustable action format rather than a single-turn static program, and from concurrent TaskWeaver by providing rigorous quantitative evaluation across 17 LLMs rather than qualitative demonstrations. The key conceptual departure is framing code as a unified action space that natively supports control flow, data flow, existing software packages, and automated error feedback—capabilities that require careful engineering in JSON or text action formats.

## Why It Matters / Open Questions

The code-as-action paradigm has become a widely adopted design pattern for LLM agents, and this paper provides the empirical justification (17-model comparison, new M³ ToolEval benchmark) and practical infrastructure (CodeActInstruct dataset, CodeActAgent model) that made it accessible to the open-source community. The finding that LLMs' pre-training exposure to code makes code a more natural action format than JSON or text is a practically important insight for model developers. Open questions remain around safety mechanisms for sandboxed code execution, closing the significant performance gap between open-source (13.4%) and closed-source (74.4%) models on complex multi-tool tasks, and whether the self-debugging capability demonstrated here scales to more complex, long-horizon environments.
