## Problem

Long-context LLM inference is bottlenecked by loading the entire KV cache during each decode step, which can exceed 16 GB for 32K-token contexts. Existing KV cache eviction methods (H2O, TOVA, StreamingLLM) make static or history-based pruning decisions, but the paper shows that token criticality is highly query-dependent: a token irrelevant to one query can be essential for the next, causing these methods to discard tokens needed for future generation and severely degrading accuracy on long-dependency tasks.

## Input / Output

During the decode stage, Quest consumes the current single-token Query vector Q and per-page metadata (channel-wise min and max Key values, stored incrementally as new tokens are appended to the KV cache). It outputs Top-K critical page indices (K is a preset token budget, e.g., 128–4096 tokens) and the resulting approximate attention output, which feeds the FFN for the next generated token. The KV cache is managed at page granularity (default 16 tokens/page), so the metadata footprint is only 2·M·L/S bytes versus the full 2·M·L bytes of the cache.

## Method

Quest exploits query-aware sparsity by estimating per-page criticality without loading full Key vectors. For each KV cache page, it stores the per-dimension minimum and maximum Key values as lightweight metadata. Given the current Query vector Q, Quest computes an upper-bound attention score per page by taking U_i = max(Q_i·m_i, Q_i·M_i) for each channel i and summing across dimensions, which is guaranteed to exceed any actual Q·K product within that page. The Top-K pages by this score are then loaded and subjected to standard self-attention, reducing memory movement from the full cache to metadata plus K pages (a 1/S + K·S/L fraction). The first two layers, which exhibit low sparsity (<10%), always use full attention. This design is compatible with PagedAttention and existing quantization schemes, and is implemented with dedicated CUDA kernels built on FlashInfer.

## Results

On the 10k passkey retrieval task, Quest achieves 99% accuracy with only 64 KV cache tokens (~0.6% of sequence length), while H2O, TOVA, and StreamingLLM score 0–5%. On the 100k passkey retrieval task, Quest reaches 100% accuracy with a 2048-token budget, versus 2–10% for all baselines. At 32K sequence length with a 2048-token budget, Quest delivers a 7.03× self-attention speedup and 2.23× end-to-end inference speedup (with 4-bit AWQ quantization) over FlashInfer. On LongBench, Quest with a 1K token budget matches full-KV-cache performance across all six datasets, whereas baselines require 5–14K tokens for comparable accuracy.

## Baselines & Comparisons

Quest dramatically outperforms all three KV cache eviction baselines (H2O, TOVA, StreamingLLM) on long-dependency tasks. On 10k passkey retrieval, Quest achieves 99% accuracy at a 64-token budget while H2O, TOVA, and StreamingLLM score 0–1%; on 100k passkey retrieval, Quest reaches 100% at 2048 tokens versus 2–10% for all baselines, because eviction methods permanently discard the passkey tokens before the question is posed. On LongBench, Quest with a 1K token budget matches full-cache performance on all six datasets, whereas TOVA requires 14K tokens for NarrativeQA (vs. Quest's 5K) and H2O/StreamingLLM show persistent gaps even at larger budgets. Against the FlashInfer attention kernel (the standard dense-attention baseline), Quest achieves 7.03× self-attention speedup at 32K sequence length and 2.23× end-to-end decode speedup with 4-bit AWQ quantization, with latency growing only marginally as sequence length increases. Under the same lossless-accuracy constraint on LongBench, Quest reduces self-attention latency by 3.82× (GovReport) and 4.54× (TriviaQA) compared to the best-performing baseline.

## Relation to Prior Work

Quest builds directly on PagedAttention's page-granularity KV cache management but departs fundamentally from prior KV cache eviction methods (H2O, TOVA, StreamingLLM) that permanently discard tokens based on historical attention scores or fixed windows. The key conceptual shift is from eviction to dynamic selection: Quest retains the full KV cache and instead uses per-page min/max Key metadata combined with the current Query vector to estimate which pages are critical for each decode step. This query-aware sparsity insight extends the earlier observation that attention is inherently sparse (Zhang et al., 2023b; Ge et al., 2024) by showing that the set of critical tokens is not static but shifts with each new query token.

## Why It Matters / Open Questions

The 7.03× self-attention speedup and 2.23× end-to-end latency reduction are practically significant for production long-context serving, and the technique is compatible with existing quantization (AWQ) and page-based memory management, making it easy to integrate into current inference stacks. A key limitation is that the first two layers still require full attention due to low sparsity, and evaluations are restricted to 7B models in single-batch settings; scaling to larger models and multi-batch serving remains open. The paper also does not address how Quest interacts with other emerging efficiency techniques like speculative decoding or multi-query attention, which could compound or conflict with its page-selection strategy.
