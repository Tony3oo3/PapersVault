## Problem

Existing fully quantized training (FQT) methods for transformers suffer from three key limitations: they use a quantize-compute-dequantize (QCD) scheme that keeps inter-operator data in FP16, missing memory-bandwidth savings on memory-bound layers like LayerNorm and GELU; per-token quantization fails to handle channel-wise activation outliers in transformers, causing significant accuracy degradation; and weight gradient computation is often left in full precision, limiting overall speedup. No prior method simultaneously achieves INT8 data flow, accurate quantization for transformers, and broad hardware portability.

## Input / Output

The method consumes standard transformer training inputs—text token sequences for NLP (WMT 14 En-De, OpenWebText) and RGB images for vision (ImageNet-1K)—and produces a fully trained transformer model with INT8-quantized activations, weights, and gradients. Internally, every tensor is stored as an INT8 matrix paired with a per-block FP16 scale factor matrix (block size B=32), while the master weight copy remains in FP32. The method runs on any GPU supporting INT8 tensor-core matrix multiplications (demonstrated on RTX 4090 and RTX 3090), unlike FP8 approaches that require Hopper architecture.

## Method

Jetfire introduces two complementary mechanisms. First, an INT8 data flow replaces the conventional QCD pipeline: all activations, weights, and gradients are stored and transferred between operators in INT8 format, halving memory access for both compute-bound linear layers and memory-bound non-linear operators (GELU, LayerNorm, Dropout, Add). Second, per-block quantization partitions each matrix into B×B blocks along both the token and channel axes, assigning one scale factor per block based on its maximum absolute value; this confines the impact of channel-wise or token-wise outliers to a single block while remaining compatible with tensor-core WMMA instructions (which require scaling only along outer axes). The linear layer is implemented in CUDA with a 3-level tiling hierarchy (CUDA block → quantization block → 16×16 WMMA), performing on-chip dequantization to FP32 accumulation and re-quantization to INT8 output. Non-linear operators are implemented in Triton with kernel fusion: INT8 data is loaded from global memory, dequantized to FP32 in shared memory for the element-wise computation, then quantized back to INT8 before writing to global memory, achieving up to 1.8× speedup over FP16 PyTorch implementations.

## Results

On WMT 14 En-De machine translation, Jetfire achieves 26.49 BLEU, matching the FP16 baseline exactly, while SwitchBack drops to 26.46 and per-tensor quantization falls to 26.04. On GPT-2 pretraining (OpenWebText), Jetfire achieves lower validation loss than the FP16 baseline across all sizes (e.g., 2.4696 vs. 2.5993 for GPT-2-large), while SwitchBack degrades by 0.3–0.45 in valid loss. On ImageNet-1K DeiT pretraining, Jetfire stays within 0.1% top-1 accuracy of FP16 (and even improves DeiT-base by 0.36%), whereas per-tensor quantization fails to converge. End-to-end, Jetfire delivers a 1.42× training speedup and 1.49× activation memory reduction for a standard transformer block on RTX 4090.

## Baselines & Comparisons

Against SwitchBack (per-token quantization, Wortsman et al. 2023), Jetfire wins on every task: it matches FP16 BLEU on WMT (26.49 vs. 26.46), stays within 0.1% top-1 on DeiT (vs. 0.5–0.6% degradation for SwitchBack), and reduces GPT-2 validation loss by 0.17–0.58 (e.g., 2.4696 vs. 3.0512 for GPT-2-large). On GLUE fine-tuning, Jetfire narrows the gap to FP16 from 4.27 points (SwitchBack on GPT-2-large) to just 0.07 points. Against per-tensor quantization (Banner et al. 2018), Jetfire is dramatically superior: per-tensor fails to converge on all DeiT models, incurs 0.28–0.62 higher valid loss on GPT-2, and drops GLUE scores by 2–7 points. The two CNN-specific INT8 training methods (GDA and DAQ) are only evaluated on DeiT in the appendix, where Jetfire outperforms them by 1.8–3.0% top-1 accuracy (e.g., 76.03 vs. 73.06 for GDA and 72.40 for DAQ on DeiT-base), confirming that CNN-oriented quantization strategies are insufficient for transformers.

## Relation to Prior Work

This paper extends the Fully Quantized Training (FQT) lineage, which has primarily targeted CNNs (Zhu et al., 2020; Zhao et al., 2021a) or, for transformers, used per-token quantization while leaving weight gradients in FP16 (SwitchBack, Wortsman et al., 2023). The key departure is the INT8 data flow: rather than the standard quantize-compute-dequantize (QCD) pattern that keeps activations in FP16 between operators, Jetfire stores and transfers all intermediate tensors in INT8, enabling acceleration of memory-bound non-linear operators (GELU, LayerNorm) that QCD cannot touch. The per-block quantization scheme is positioned as a hardware-aware compromise between per-channel (accurate but incompatible with tensor-core WMMA) and per-token (hardware-friendly but inaccurate for channel-wise outliers), and unlike FP8 methods (TransformerEngine, FP8-LM) it runs on any GPU with INT8 tensor core support rather than requiring Hopper architecture.

## Why It Matters / Open Questions

By reducing both compute and memory bandwidth simultaneously, Jetfire makes INT8 transformer pretraining practical on widely available GPUs (RTX 4090/3090) without the accuracy losses that plagued prior per-token approaches, which is meaningful for labs and practitioners without access to Hopper-class hardware. The 1.42× end-to-end speedup and 1.49× activation memory reduction are moderate but compound across large-scale training runs. Open questions include whether per-block quantization generalizes to architectures with different outlier structures (e.g., MoE, state-space models), whether the approach scales to 10B+ parameter models where communication overhead dominates, and whether the INT8 data flow can be extended to optimizer states and master weight copies for further memory savings.
