## Problem

Training neural operators for PDEs requires large-scale paired datasets, but generating them via traditional solvers (FDM/FEM + iterative linear solvers like GMRES) is the dominant computational bottleneck, often exceeding 95% of total pipeline time with O(m·n²) complexity per sample. Moreover, iterative solvers inevitably introduce truncation errors (typically 10⁻⁵ to 10⁻⁷) that degrade downstream model quality, and tightening the tolerance further increases cost. No prior method generates PDE training data at machine precision without solving linear systems.

## Input / Output

The method takes a small precomputed set of 10–50 basis solution functions (generated once via GMRES at 10⁻⁵ tolerance), the discretized PDE operator matrix A (sparse, size up to 62,500×62,500), and random Gaussian-distributed weights to produce arbitrarily large training datasets (1,000–20,000 instances). Each output sample is a triple (parameter function a, source function f, solution function u) on an N×N uniform grid, with f computed as b = Ax at machine precision (~10⁻¹⁶). The generation time is nearly independent of dataset size because the expensive basis-function step is amortized, and only the O(n²) matrix-vector multiplication scales with the number of samples.

## Method

DiffOAS inverts the standard data-generation pipeline: instead of generating the source term f and solving Ax = b for the solution u, it first constructs solution functions u by randomly combining a small set of physically-conformant basis functions with Gaussian weights (plus boundary-preserving noise), then computes the source term via a single matrix-vector multiplication b = Ax. This replaces the O(m·n²) iterative linear solve with an O(n²) multiplication, yielding a theoretical one-order (O(n)) speedup while eliminating all solver truncation error. The basis functions must be drawn from the correct physical distribution (e.g., GRF-solved Darcy solutions); ablation shows that substituting Fourier, Chebyshev, or raw GRF functions as bases produces datasets with >30% training error, confirming that physical conformity of the basis is essential. Theoretical analysis in Sobolev spaces formalizes the operator action as a bounded linear map L: U → F, and error analysis via the GMRES residual bound (|h_{j+1,j}|·‖y_j‖) demonstrates that DiffOAS achieves ~10⁻¹⁶ precision where GMRES is limited to the user-specified tolerance.

## Results

DiffOAS achieves a ~300× speedup over GMRES for generating 10,000 Darcy Flow data points (597 s vs. ~179,000 s at 1E-5 tolerance), with the operator-action step alone accelerating by up to 70,000× at matrix size 62,500. The generated data maintains machine precision (1E-16) compared to GMRES's typical 1E-5 truncation error. On model performance, DiffOAS-generated data yields FNO errors of 4.26e-3 (Darcy), 6.52e-4 (Wave), and 4.79e-3 (Diffusion) with 10,000 instances, matching or exceeding GMRES baselines, while DeepONet errors improve from 6.82e-2 to 5.62e-2 (Darcy) and 7.70e-2 to 6.04e-2 (Diffusion).

## Baselines & Comparisons

Against the primary GMRES baseline (scipy 1.11.4), DiffOAS wins decisively on generation time across all three PDE problems: ~33× faster on Darcy Flow (9.49 s vs. 299 s for 1,000 instances), ~20× on Wave (160 s vs. 3,270 s), and ~33× on Diffusion (603 s vs. 19,900 s), while matching or improving FNO/DeepONet prediction errors at 10,000 training instances. In the SPD-matrix comparison (Appendix C.1, matrix size 62,500, 1,000 data points), DiffOAS (0.39 s) outperforms MINRES (114.9 s) by ~295×, Conjugate Gradient (1,426 s) by ~3,650×, SKR/Krylov recycling (1,283 s) by ~3,290×, and GMRES (19,740 s) by ~50,700×. DiffOAS also surpasses GMRES on data precision, achieving machine-precision 1E-16 residuals versus GMRES's 1E-5 truncation error, and the ablation confirms that physically-motivated basis functions are essential—replacing them with GRF, Fourier, or Chebyshev bases degrades FNO error from 4.26% to 31–94%.

## Relation to Prior Work

This paper carves new ground in PDE dataset generation by inverting the standard pipeline: rather than generating source terms and solving large linear systems (via GMRES, MINRES, CG, or Krylov-subspace recycling) for solution functions, DiffOAS generates solution functions from physically-motivated basis functions and computes source terms via a single matrix-vector multiplication (operator action). Conceptually, it repurposes the discretized PDE operator matrix A from a system to be solved into a linear map to be applied, reducing the core operation from O(m·n²) to O(n²). The approach sits at the intersection of neural operator training (FNO, DeepONet) and classical numerical PDE discretization (FDM, FEM), but departs from all prior data-generation methods that treat the linear solve as an unavoidable bottleneck.

## Why It Matters / Open Questions

The 300× speedup for 10,000-instance datasets and the guarantee of machine-precision (10⁻¹⁶) data versus GMRES truncation errors (10⁻⁵–10⁻⁷) directly address the two most cited practical barriers to scaling neural operators: generation cost and label noise. However, the method is restricted to steady-state PDEs with homogeneous boundary conditions, and the basis-function generation step still requires solving a small number of PDEs with traditional solvers, so the speedup is bounded below by that cost. Open questions include extension to time-dependent PDEs, inhomogeneous or nonlinear boundary conditions, and whether the physically-motivated basis construction generalizes to 3D or higher-dimensional problems without combinatorial growth in basis count.
