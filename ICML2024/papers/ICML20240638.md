## Problem

Existing code generation benchmarks (HumanEval, MBPP) evaluate standalone function synthesis from natural language but ignore the more common practice of modifying and expanding existing code. The only prior FIM benchmark, HumanEval-Infilling, is limited to 164 short Python snippets with randomly masked lines rather than syntax-aware completions, and prior evaluations use narrow prompt selections that skew comparisons between FIM-trained and non-FIM-trained models. This paper addresses these gaps by introducing a large-scale, multilingual, syntax-aware FIM benchmark with fair evaluation protocols.

## Input / Output

Each example provides a code file (in Python, Java, C++, or C#) with a contiguous AST-identified segment masked, plus a natural language problem description. The masked segment is one of three types: an algorithmic code block (deepest innermost loop body), a control-flow expression (e.g., a while-loop condition or if-statement predicate), or an API function call. The model produces the filled-in segment, which is evaluated via execution-based unit tests (98.25% of examples) or syntactical matching for API calls. The benchmark contains 17,720 examples from 8,590 code files, with average code context of ~3,364 bytes and average completion of ~42 bytes, all sourced post-April 2022 to minimize data contamination.

## Method

SAFIM constructs FIM tasks by parsing code files into Abstract Syntax Trees and masking structurally meaningful segments: the deepest algorithmic block (validated by confirming no-op substitution breaks unit tests), critical control-flow expressions (validated by confirming substitution with true/false/empty changes test outcomes), or API function calls (curated with contextual hints). Five prompt designs—L2R, PSM, SPM, IPF, and One-Shot—are implemented to fairly accommodate FIM-pretrained, L2R-pretrained, and chat models, with the best-performing prompt selected per model. A novel syntax-aware truncation algorithm replaces regex-based heuristics by iteratively removing output lines until the result fits as a valid AST subtree and the surrounding code's AST structure matches the original, enabling fair evaluation of open-ended models like CodeGen that lack explicit end-of-sequence signals. The evaluation of 15+ LLMs reveals that FIM pretraining enhances both FIM and L2R performance, and that pretraining methodology and data quality (e.g., repo-level context, execution feedback) outweigh sheer model size in determining task-specific performance.

## Results

On the SAFIM benchmark (17,720 examples across algorithmic block, control-flow, and API function call completion), DeepSeekCoder-33B achieves the highest average Pass@1 of 69.0%, followed by DeepSeekCoder-6.7B (63.4%) and StarCoder-15.5B (55.5%). Notably, StarCoder (15.5B) matches or exceeds GPT-4 (>220B, 53.3% avg) despite being over 10× smaller, while CodeLLaMa-13B (52.8%) is comparable to GPT-4. The best open-source model (DeepSeekCoder-33B) outperforms the best proprietary model (GPT-4) by 15.7 points in average Pass@1.

## Baselines & Comparisons

DeepSeekCoder-33B dominates all three task categories, achieving 60.8% (Algo), 71.1% (Control), and 75.2% (API), outperforming GPT-4 by 18.7, 15.9, and 12.6 points respectively. StarCoder (15.5B) achieves 55.5% average, surpassing GPT-4 (53.3%) by 2.2 points despite being over 10× smaller, with its advantage driven primarily by API completion (68.1% vs. 62.6%) where repository-level pretraining context is critical. Within the CodeLLaMa family, the FIM+L2R pretrained 13B model (52.8% avg) outperforms the larger 34B model (49.7% avg) that lacks FIM pretraining, demonstrating that pretraining methodology outweighs model size. CodeGen-16B (31.0% avg) and InCoder-6B (33.8% avg) trail significantly behind FIM-pretrained models of similar or smaller size, with CodeLLaMa-13B exceeding them by over 20 points. For control-flow completion specifically, CodeLLaMa models benefit from execution-based feedback in their self-instruct training, while for API completion, StarCoder and DeepSeekCoder excel due to incorporating repository context (GitHub issues, commit messages, topological code ordering) into pretraining.

## Relation to Prior Work

This paper extends the Fill-in-the-Middle (FIM) evaluation paradigm established by InCoder (Fried et al., 2023) and the HumanEval-Infilling benchmark, departing from random line/character masking to syntax-aware, AST-structural masking of code blocks, control-flow expressions, and API calls. It also builds on the broader code LLM evaluation landscape (HumanEval, MBPP, APPS) by targeting the more realistic scenario of modifying existing code rather than generating standalone functions. The introduction of five distinct prompt designs (L2R, PSM, SPM, IPF, 1S) and a syntax-aware truncation algorithm represents a methodological departure from prior FIM evaluations that typically used a single prompt type and regex-based post-processing.

## Why It Matters / Open Questions

SAFIM fills a critical gap between small single-function L2R benchmarks and large repo-level benchmarks, providing a 17,720-example multilingual FIM benchmark with execution-based evaluation that is resistant to data contamination. The finding that FIM pretraining enhances (rather than harms) L2R performance, and that pretraining methodology can outweigh model size (StarCoder 15.5B ≈ GPT-4 >220B), challenges prevailing assumptions in code LLM development. However, the authors acknowledge these cross-family comparisons are not controlled experiments, leaving open the question of whether these effects hold when pretraining paradigms are varied within a single model architecture. The syntax-aware truncation technique is immediately applicable to real-world code completion systems.
