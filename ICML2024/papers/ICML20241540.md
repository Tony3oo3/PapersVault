## Problem

LLMs of code are trained on surface textual form and lack semantic understanding of how programs execute at runtime, making them poor at tasks requiring execution-aware reasoning such as program repair. A preliminary study shows that chain-of-thought prompting with execution traces actually degrades performance for many models (e.g., −7.8% on HUMANEVALFIX-PLUS), revealing that LLMs cannot effectively leverage execution information in natural language out-of-the-box.

## Input / Output

The model receives an NL task instruction, a buggy program, associated test cases, and execution traces formatted as compact inline code comments that show only changed variable states per executed line, indexed by execution order with loop iterations compressed (e.g., '# (3) n=1; (5) n=2; ...; (21) n=10'). The output is a two-part generation: a natural language rationale that identifies and explains the bug by reasoning over expected vs. actual variable values in the trace, followed by the corrected program enclosed in a code block. The trace representation is significantly more token-efficient than prior scratchpad-style unrolling, fitting 95.1% of MBPP-R examples within 2048 tokens versus 60.1% for Scratchpad.

## Method

NEXT (Naturalized Execution Tuning) is an iterative self-training procedure that bootstraps a synthetic dataset of execution-aware rationales without manual annotation. In each iteration, the model samples candidate (rationale, fix) pairs via temperature sampling (T=0.8, 32 samples) on a subset of hard problems (those with PASS@1 ≤ 10% under the base model); candidates are filtered by unit test execution as a binary reward, and the model is finetuned from its initial checkpoint on the surviving pairs to avoid overfitting to early-iteration noise. The key design choices are: (1) an inline trace representation that embeds variable states as pseudo-comments within the original code structure, preserving the LLM's learned code representations; (2) restricting sampling to hard problems to improve sample efficiency and push the model toward more challenging repairs; and (3) jointly modeling both the NL rationale and the code fix as latent variables, so that the rationale is shaped by the requirement to lead to a correct fix. Over 10 iterations, this yields a 26.1% absolute improvement in PASS@1 on MBPP-R and 10.3% on HUMANEVALFIX-PLUS, with the model also generalizing to test-time scenarios where traces are absent.

## Results

On MBPP-R, PaLM 2-L+NEXT achieves a PASS@1 fix rate of 49.3%, a 26.1% absolute improvement over the 3-shot PaLM 2-L baseline (23.2%), and outperforms GPT-3.5 (42.9%) on all PASS@k metrics. On HEFIX+ (generalization without additional finetuning), NEXT achieves 42.5% end-to-end fix rate, a 10.3% absolute gain over PaLM 2-L (32.2%). The model also improves proxy-based rationale quality by 6.3% on MBPP-R and 6.1% on HEFIX+, and generalizes to the trace-absent test setting with a 40.8% fix rate (21.8% above baseline).

## Baselines & Comparisons

PaLM 2-L+NEXT outperforms GPT-3.5 (42.9%) by 6.4 points on MBPP-R PASS@1 and leads on all PASS@k metrics, while GPT-4 (63.2%) remains substantially ahead. Against open-source code LLMs, NEXT surpasses the strongest (Mixtral-8x7B at 32.3% on HEFIX+ end-to-end) by a minimum of 29.4% on end-to-end and 11.1% on proxy-based PASS@1. On the generalization benchmark HEFIX+, PaLM 2-L+NEXT (42.5%) still trails GPT-3.5 (59.4%) and GPT-4 (77.6%) but improves over the base PaLM 2-L by 10.3% absolute. Ablations confirm that both execution traces and CoT rationales are critical: removing traces drops PASS@1 from 49.3% to 44.1%, and removing rationales reduces sample diversity (PASS@25 drops from 79.4% to 71.8%). The model also generalizes to the out-of-distribution trace-absent test setting, achieving 40.8% fix rate versus 19.0% for the 3-shot baseline.

## Relation to Prior Work

NEXT is an instantiation of the STaR rationale-bootstrapping framework (Zelikman et al., 2022) and chain-of-thought reasoning (Wei et al., 2022), adapted to the domain of program execution. It departs from Scratchpad (Nye et al., 2021) and Self-Debugging (Chen et al., 2023), which generate execution traces as model output, by instead consuming pre-existing runtime traces as input and learning to produce task-specific NL rationales grounded in them. Compared to SelfAPR (Ye et al., 2022), which performs self-training on code fixes alone, NEXT jointly learns rationales and fixes, and introduces a compact inline trace representation that is significantly more token-efficient than unrolled line-by-line formats.

## Why It Matters / Open Questions

NEXT demonstrates that LLMs can be taught to perform execution-aware debugging reasoning in natural language, improving both fix rates and interpretability for program repair. The finding that the model generalizes to trace-free test-time settings suggests the learned reasoning transfers beyond the training distribution. Key limitations include restriction to Python and function-level programs, inability to capture if-condition values in traces, and reliance on unit tests as the sole filtering signal (no process-level supervision). Open questions include extending to multi-language settings, complex objects (tensors, DataFrames), and whether iterative self-training can improve self-debugging ability without gold traces.
