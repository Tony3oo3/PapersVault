## Problem

In DREAMCODER's wake-sleep framework, the neural recognition model learns to reduce search breadth while the library (via chunking) reduces search depth, but these two knowledge sources operate independently: the recognition model's amortized knowledge has no direct influence on which functions are chunked. This disconnect means chunking decisions rely solely on compression of already-discovered solutions, overlooking functionality that the recognition model has learned to prefer but that is absent or underrepresented in current solutions—particularly problematic when few example solutions are available.

## Input / Output

The method consumes the recognition model's bigram distribution over well-typed programs (parameterized by φ_D), a set of candidate sub-expression functions F extracted from discovered solutions, and the beam of solved programs B_x per task. It produces a probabilistic score p(c|f; φ_D) for each candidate function, from which a threshold or top-k selection determines which functions are added to the library. The output library is then used to retrain a new recognition model in the next wake-sleep cycle, closing the loop.

## Method

The paper introduces 'dream decompiling': a mechanism that directly leverages the recognition model's amortized parameters to decide what to chunk, rather than relying on compression alone. The key variant (DDC-PC) defines a Bernoulli model p(c|f; φ_D) expressing uncertainty about whether chunking f will benefit the recognition model's future search guidance. This is computed via a 'caching benefit' measure C(q, ρ, f) = n_ρ^f log q(f) / log q(ρ), which quantifies the relative reduction in generation difficulty when f is no longer sampled. The final scoring criterion (Eq. 7) combines three factors: the recognition model's probability of generating f for a task, the caching benefit of f within solved programs, and the recognition model's probability of those programs—effectively asking whether chunking f would make the model's preferred solutions substantially easier to generate. A simpler variant (DDC-AVG) averages the recognition model's preference for each function across tasks. Both are integrated into DREAMCODER by replacing only the library-update step, preserving the rest of the wake-sleep architecture.

## Results

Across 6 program synthesis domains, DREAMDECOMPILER-PC (DDC-PC) outperforms DREAMCODER by 13.25% on average test task performance in list processing and by over 17% in the remaining deterministic domains (block towers, symbolic regression, LOGO graphics) at their respective peak cycles. This improvement is achieved despite solving only 2–10% more training tasks at the time of peak, indicating the gain comes from better chunking decisions rather than more data. Statistical significance is confirmed via Welch's t-test in cycle 3 (t=2.57, p=0.016), cycle 4 (t=2.1, p=0.045), and the final cycles. In text editing, all three systems (DDC-PC, DDC-AVG, DREAMCODER) achieve comparable performance, though DDC-PC still chunks more useful individual functions early on.

## Baselines & Comparisons

The sole baseline is DREAMCODER (Ellis et al., 2021), the original wake-sleep Bayesian program synthesis system that uses a compression objective for library learning. DDC-PC wins on 5 of 6 domains in peak test-task accuracy: +13.25% in list processing (cycle 5), and >17% in block towers (cycle 7), symbolic regression (cycle 4), and LOGO graphics (cycle 5). In text editing, DDC-PC ties with DREAMCODER on final test accuracy, though it still chunks functions that are more useful for eventual test-task solving. DDC-PC also consistently outperforms the simpler DDC-AVG variant across all deterministic domains, validating the probabilistic chunking criterion over naive averaging. The advantage is most pronounced in intermediate learning cycles (when fewer example solutions are available), and diminishes as all systems converge, suggesting dream decompiling is particularly beneficial under data scarcity.

## Relation to Prior Work

This paper extends DREAMCODER (Ellis et al., 2021), a Bayesian program learning system that jointly learns a library and a neural search policy via a wake-sleep procedure. The key departure is in library learning: DREAMCODER and related systems (BABBLE, STITCH, Wong et al.) select chunking candidates using compression objectives over discovered solutions, treating the recognition model and library as independently learned components. Here, the authors introduce 'dream decompiling,' which directly leverages the recognition model's amortized knowledge to decide what to chunk, creating a feedback loop where the search policy shapes the search space it subsequently guides. The probabilistic chunking criterion (DDC-PC) is grounded in information-theoretic caching benefit and decision theory, going beyond the simpler averaging approach (DDC-AVG).

## Why It Matters / Open Questions

The core insight—that the same amortized neural knowledge can simultaneously reduce search breadth and depth—provides a principled mechanism for stronger bootstrapping in program synthesis, particularly when few example solutions are available. This is practically relevant because real-world program induction often operates in low-data regimes where compression-based chunking overlooks functionality needed for future tasks. Open questions remain: how to determine the optimal number of functions to chunk, how to generate candidates for functionality absent from existing solutions, whether more sophisticated neural architectures would benefit more from this dual-use of amortized knowledge, and how to avoid catastrophic forgetting when the library (and thus the recognition model's sample space) changes between cycles.
