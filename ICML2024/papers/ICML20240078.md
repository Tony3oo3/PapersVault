## Problem

In single-context batch sampling (generating multiple completions from one prompt), incremental decoding becomes memory-I/O bound because the shared context KV cache is redundantly loaded for every batch index. At high batch sizes and long context lengths, this redundant I/O dominates latency, limiting practical batch sizes and making real-time multi-candidate generation (e.g., for code IDEs or reranking) infeasible with standard attention implementations.

## Input / Output

The method operates on a single text prompt whose KV cache is computed once during prefill, then broadcast across b batch indices during incremental decoding. The KV cache is internally split into a context portion K_c (identical across all batch indices, shape 1×h×m_c×k) and a decoding portion K_d (unique per batch index, shape b×h×m_d×k). The output is b independently sampled token sequences, each generated autoregressively from the shared context, with the constraint that the method applies only when all batch indices share the same prefill context.

## Method

Bifurcated attention decomposes the query-key and weight-value attention during incremental decoding into two separate GEMM operations: one against the shared context KV cache (einsum without the batch axis, so K_c is loaded once) and one against the per-sample decoding KV cache (einsum with the batch axis). The two results are concatenated (for logits) or summed (for the value-weighted output), yielding mathematically identical results to standard attention with the same FLOPs but reducing memory I/O from gk·b(m_c+m_d) to gk·(m_c+b·m_d), a gain approaching b-fold when m_c ≫ m_d. The technique is compatible with the entire generalized multi-query family (multi-head g=h, multi-query g=1, grouped-query 1<g<h) and requires only ~20 lines of PyTorch einsum code. The paper further establishes scaling-law results showing multi-query attention requires ~10% model size compensation to match multi-head capabilities, and demonstrates that bifurcated attention combined with multi-head can rival a larger multi-query model at moderate batch sizes while enabling far more extreme batch sizes (up to 2048) and context lengths (32k+) when combined with multi-query or GQA.

## Results

For CodeGen-16B (multi-head, 2k context), bifurcated attention enables increasing batch size from 5 to 128, raising pass@k from 59.0% to 84.6% and pass@top3 (mean log-prob ranking) from 55.2% to 58.1%. On a 7B model at 32k context length, bifurcated attention achieves 54.92 ms/token at batch size 16 where standard SDPA runs out of memory, and 30.66 ms/token with Torch Compile. At 8k context and batch size 128, bifurcated attention reaches 48.69 ms/token versus 1183.46 ms for FlashAttention-2 with non-contiguous memory (a ~24× speedup). The method also enables multi-head models to match or beat larger multi-query models in latency at moderate batch sizes (up to 64), removing the need to train a separate MQ model.

## Baselines & Comparisons

The primary baseline is FlashAttention-2 (Dao et al., 2022), a fused attention kernel that is highly efficient during prefill but not context-aware during incremental decoding. At batch size 1, Flash2 is slightly faster (e.g., 24.06 ms vs. 30.38 ms at 8k context), but the gap reverses sharply as batch size grows: at 8k/BS=16, bifurcated attention is 3.5× faster (31.70 vs. 109.64 ms), and at 8k/BS=128 it is 24× faster than Flash2 with non-contiguous memory (48.69 vs. 1183.46 ms). At 32k context, Flash2 and SDPA hit OOM at batch sizes as low as 4–8, while bifurcated attention continues to scale to BS=128 (101.18 ms). Compared to PyTorch's standard SDPA kernel, bifurcated attention shows a similar pattern: competitive at BS=1 but dramatically superior at higher batch sizes, with SDPA hitting OOM at 32k/BS=4 while bifurcated attention handles BS=128. The paper also compares against multi-query attention (Shazeer, 2019) as an alternative KV-compression strategy; with bifurcated attention, a multi-head model matches or beats a 10%-larger multi-query model in latency at moderate batch sizes (≤64), meaning practitioners can avoid retraining a separate MQ model for single-context batch sampling workloads.

## Relation to Prior Work

This paper introduces bifurcated attention, an inference-time optimization that operates on top of the generalized multi-query attention family (unifying multi-head, multi-query, and grouped-query attention). It builds directly on the KV-cache structure established by multi-head attention (Vaswani et al., 2017) and the compression framework of GQA (Ainslie et al., 2023), but departs from prior IO-reduction approaches like FlashAttention and paged attention by exploiting the shared-prefix structure specific to single-context batch sampling: the context KV cache is loaded once rather than once per batch index. The method is orthogonal to and composable with speculative decoding, quantization, and tensor parallelism, positioning it as a complementary layer in the inference optimization stack rather than a replacement for existing techniques.

## Why It Matters / Open Questions

Bifurcated attention enables a 25× increase in supported batch size for single-context sampling (e.g., CodeGen-16B from batch 5 to 128), directly translating into large pass@k gains (59%→84.6%) under fixed latency budgets, which is critical for code assistants, self-consistency, and tree-of-thought reasoning. A key practical finding is that multi-head + bifurcated attention rivals a larger multi-query model at moderate batch sizes, meaning existing MH checkpoints can benefit without retraining. Limitations include applicability only to single-context batch sampling (not general batch inference), potential overhead at very small workloads due to reduced GEMM parallelism, and the fact that the technique's gains depend on the context length being substantially larger than the number of generated tokens. Open questions include interaction with future attention quantization, integration with FlashAttention-style fused kernels, and whether the shared-prefix exploitation generalizes to multi-turn or retrieval-augmented settings.
