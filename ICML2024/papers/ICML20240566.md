## Problem

Retrieval-augmented code-to-text generation models are susceptible to being misled by irrelevant or semantically mismatched retrieved references, since existing methods do not assess how well a retrieved description actually matches the input code. Additionally, standard contrastive retrievers suffer from a training-inference gap: all non-ground-truth descriptions are treated as negatives during training, yet the truly relevant reference may not be the top-1 retrieval at inference time.
![Teaser figure](../imgs/ICML20240566/cropped_page0_idx0.webp)

## Input / Output

The model takes a code snippet (Python function or SQL query, truncated to 512 tokens) and a single top-1 retrieved reference description from a large code-summary database (up to ~1M entries), formatted as a RoBERTa-style cross-encoding sequence [CLS] code [SEP] [SEP] reference [SEP]. It autoregressively generates a natural language description (docstring or natural-language query, up to 80 tokens for code summarization, 32 for SQL-to-text) using beam search with beam size 4.

## Method

PinNet introduces a four-component pipeline (Retriever → Encoder → Discriminator → Decoder) with two key mechanisms. First, a Transformer-based discriminator (PinNet-Dis) is trained to classify the BLEU-score relevance of the retrieved reference into 6 ordinal bins; its final-layer hidden representations capture which parts of the reference are semantically aligned with the code versus misleading. Second, a novel PinAttention module injects these discriminative representations into the decoder's cross-attention by modulating both queries and keys through additional Multi-Head Attention layers with the reference representation as K and V, enabling the decoder to dynamically up-weight informative tokens and suppress misleading ones. The retriever (PinNet-Ret) is trained with a hierarchical triplet loss that enforces a three-way distance ordering—relevant descriptions closer to the code than random texts but farther than the ground truth—bridging the training-inference gap that standard contrastive objectives ignore.

## Results

On CodeXGLUE code summarization, PinNet achieves BLEU-4 of 21.83 (Python) and 23.48 (Java), outperforming the previous state-of-the-art REDCODER by 0.82 and 0.54 points respectively. On SQL-to-text generation, PinNet reaches BLEU 38.4 on WikiSQL and 21.9 on StackOverflow, surpassing the prior best PreQR2Seq by 6.3 and 0.8 points. Against large language models (up to 3B parameters) on CodeXGLUE-Java, PinNet (0.2B) achieves BLEU 23.5, ROUGE-L 40.6, and METEOR 16.1, exceeding all fine-tuned LLM baselines on lexical metrics.

## Baselines & Comparisons

PinNet outperforms all 24 baselines across both tasks. Against generative models (Seq2Seq, Transformer), PinNet gains over 5 BLEU points on Python. Among pre-trained language models, the strongest baseline CodeT5+ (20.47/20.83) is surpassed by 1.36/2.65 points. The closest competitor is REDCODER (21.01/22.94), which uses a stronger PLBART backbone and 10 retrieved references; PinNet wins by 0.82/0.54 points using only top-1 retrieval and a weaker GraphCodeBERT backbone. On SQL-to-text, PinNet beats PreQR2Seq (32.1/21.1) by 6.3/0.8 BLEU. Against LLMs on Java, PinNet (0.2B) exceeds fine-tuned StarCoder (3B) by 3.1 BLEU and 1.1 ROUGE-L, though StarCoder edges out PinNet on METEOR (14.7 vs 16.1) and SentenceBERT (61.9 vs 61.9, tied). The retrieval module PinNet-Ret also outperforms SCORE-R by 1.17/1.20 BLEU on Python/Java code-to-text retrieval.

## Relation to Prior Work

PinNet extends the retrieval-augmented code-to-text paradigm established by REDCODER (Parvez et al., 2021) and earlier work (Zhang et al., 2020; Wei et al., 2020), which retrieve reference descriptions to condition generation. The key departure is the introduction of a discriminator that explicitly scores the semantic relevance between the retrieved reference and the input code, coupled with PinAttention that uses the discriminator's hidden representations to modulate cross-attention weights in the decoder. Additionally, the hierarchical triplet retrieval loss (L_HR) departs from standard contrastive objectives by maintaining a three-way distance ranking (ground truth > relevant > random), addressing the train-inference gap where relevant-but-not-gold references are treated as negatives during training.

## Why It Matters / Open Questions

The paper identifies and addresses a practical failure mode in RAG systems—models being 'deluded' by irrelevant retrieved references—which is broadly relevant beyond code summarization to any retrieval-augmented generation pipeline. The discriminator-plus-attention-modification pattern is a lightweight, generalizable mechanism that could be applied to other RAG settings. However, limitations remain: PinNet uses only top-1 references (vs. 10 in REDCODER), incurs ~30% runtime overhead, and still fails when long-distance dependencies make even the best retrieval irrelevant. The comparison showing a 0.2B model outperforming 2–3B LLMs on code summarization is notable but partly attributable to style mismatch with ground-truth summaries rather than fundamental superiority.
