## Problem

Existing retrieval benchmarks (e.g., BEIR) do not require long-context reasoning—naive truncation or chunking baselines perform near-optimally because relevant information is concentrated in the first few hundred tokens. In real-world domains like law, medicine, and finance, documents span tens of thousands of tokens with key details dispersed throughout, yet no retrieval encoder can process such sequences efficiently, and standard contrastive fine-tuning (MNRL) demands batch sizes that exceed GPU memory for long inputs.

## Input / Output

The encoder takes a short query (typically 60–900 tokens) and a long document (up to 32,768 tokens) as separate inputs, each producing a single fixed-length dense embedding vector via a [CLS]-style pooling. Retrieval is performed by computing pairwise cosine similarity between query and document embeddings, and performance is measured as nDCG@10 over ranked document lists. A key design constraint is that the same 80M-parameter model must handle both the short query and the long document in a single forward pass without chunking or averaging sub-embeddings.

## Method

M2-BERT is an 80M-parameter encoder built on the Monarch Mixer (M2) state-space architecture, which replaces quadratic self-attention with Monarch matrix multiplications to achieve subquadratic scaling in both sequence length and model dimension, enabling 32K-token inputs. Pretraining uses a masked-language-modeling objective on a deliberate mixture of variable-length (short) and maximum-length (long) sequences from C4, Wikipedia, and BookCorpus; the 32K variant additionally requires warm-starting from a pretrained 8K checkpoint because random initialization fails to converge. For fine-tuning, the authors replace the standard MNRL contrastive loss—which requires large in-batch negative sets—with Orthogonal Projection Loss (OPL), which computes MSE between the cosine similarity of a single query-document pair and a binary target (1.0 for positives, 0.0 for negatives), enabling effective training at batch size 1 and thus fitting 32K-token documents within a single A100 GPU.

## Results

On the LoCoV1 long-context retrieval benchmark (12 tasks, nDCG@10), M2-BERT-32k achieves 95.2, outperforming the next-best baseline BM25 (81.5) by 13.7 points and the strongest Transformer-based model E5-Mistral (73.0) by 22.2 points, despite having only 80M parameters vs. 7.11B. On BEIR (short-context retrieval), M2-BERT-128 scores 38.7 nDCG@10, within 1.3 points of SentenceBERT (40.0) while using 27% fewer parameters. On MTEB, M2-BERT-128 matches SentenceBERT at 63.3 vs. 63.1 average score. In terms of efficiency, M2-BERT-32k embeds a 32K-token document 676× faster than E5-Mistral (0.0071s vs. 4.8s on A100).

## Baselines & Comparisons

M2-BERT-32k decisively outperforms all Transformer-based dense retrievers on LoCoV1: it beats E5-Mistral (7.11B) by 22.2 points, BGE-Large (335M) by 30.2 points, Jina Embeddings (137M) by 28.0 points, and ColBERTv2 (110M) by 40.9 points in average nDCG@10. Against the lexical baseline BM25, M2-BERT-32k leads by 13.7 points, confirming that dense long-context encoding captures cross-document reasoning that bag-of-words methods miss. On the short-context BEIR benchmark, M2-BERT-128 trails SentenceBERT by only 1.3 nDCG@10 points (38.7 vs. 40.0) while using 27% fewer parameters, and on MTEB it slightly edges out SentenceBERT (63.3 vs. 63.1). In the MLDR reranking setting, M2-BERT-32K used as a BM25 reranker achieves 80.9 nDCG@10, surpassing LongColBERT's 77.5. The key finding is that chunking strategies barely help (and sometimes hurt) existing models on LoCoV1, whereas M2-BERT's native long-context processing yields consistent gains as sequence length scales from 128 to 32K tokens (+35.5 points).

## Relation to Prior Work

This paper adapts the Monarch Mixer (M2) state-space architecture—previously studied only for short, uniform-length sequences (≤128 tokens)—into a retrieval encoder capable of processing up to 32K tokens, departing from the Transformer-based encoders (SentenceBERT, E5-Mistral, BGE-Large) that dominate the retrieval literature. For fine-tuning, it replaces the standard MNRL contrastive loss (which requires large batch sizes incompatible with long sequences) with Orthogonal Projection Loss, a batch-size-independent alternative. The paper also introduces LoCoV1, a 12-task benchmark that extends the retrieval evaluation setting to documents where relevant information is dispersed across tens of thousands of tokens, filling a gap left by BEIR and MTEB where truncation and chunking baselines perform near-optimally regardless of document length.

## Why It Matters / Open Questions

The LoCoV1 benchmark exposes a real evaluation blind spot: existing retrieval benchmarks do not require long-context reasoning, making it impossible to distinguish models that genuinely process long documents from those that merely truncate. The 80M-parameter M2-BERT outperforming 7.11B-parameter E5-Mistral by 22+ points while being 3–676× faster at embedding generation suggests state-space architectures could become the default for long-document retrieval pipelines. Open questions include the observed negative transfer when jointly fine-tuning on short- and long-context data, whether OPL is truly optimal versus other batch-independent losses, and how to close the remaining 18-point gap on short-context BEIR tasks where Transformer encoders still lead.
