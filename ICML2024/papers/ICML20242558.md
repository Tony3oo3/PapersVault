## Problem

When a pre-trained neural network underperforms, practitioners lack a systematic way to identify the root cause (e.g., batch size too large vs. too small, or model size vs. optimizer being the more severe issue) without access to training configurations, the original dataset, or the ability to retrain. Conventional validation-based metrics (training/validation error) can only roughly distinguish overfitting from underfitting and fail to provide fine-grained, actionable diagnosis of which specific hyperparameter or resource is responsible for the failure.

## Input / Output

The method takes a single pre-trained neural network (ResNet-18 or ViT-tiny on CIFAR-10) as input and extracts four loss landscape metrics from it: training error, mode connectivity (via a 3-bend Bézier curve between two seeds), Hessian trace (via Hutchinson's estimator), and CKA similarity between two seeds. It outputs a binary failure-source label for two canonical questions: Q1 (is the optimizer hyperparameter too large or too small relative to optimal?) and Q2 (is the more severe failure source model size or the optimizer?). In a downstream application, the diagnosis is converted into a one-step configuration change direction (increase/decrease batch size, or increase model size). The entire pipeline operates in a few-shot regime where only 12–160 labeled configurations calibrate the tree thresholds, and the resulting classifier transfers to unseen datasets, scales, and architectures.

## Method

MD tree is a fixed-hierarchy decision tree whose structure is dictated by the statistical physics of learning framework rather than learned via information gain. The tree partitions the hyperparameter space using a specific metric ordering: training error at the root (capturing the interpolation threshold), mode connectivity at the first internal level (capturing sharp regime transitions), and Hessian trace (sharpness) or CKA similarity at the leaf level. Only the scalar threshold at each internal node is optimized, using the bounded Brent method on a small few-shot training set to maximize classification accuracy. This design exploits the observation that loss landscape metrics produce piecewise-linearly separable regimes with sharp, transferable boundaries, whereas validation metrics yield complex nonlinear decision boundaries that degrade under distribution shift. The fixed hierarchy acts as an inductive bias that regularizes the classifier, yielding up to 12.71% higher accuracy than a standard decision tree using the same loss landscape features in the few-shot setting.

## Results

On the Q1 diagnosis task (determining whether batch size is too large or too small), MD tree achieves 87.7% accuracy with 96 training samples in the dataset transfer setting, outperforming the validation-based decision tree by 14.88%. In the scale transfer setting, MD tree trained on models with fewer than 0.01M parameters still reaches 82.56% accuracy on models up to 44.66M parameters. For Q2 (model size vs. optimizer), MD tree reaches 74.11% accuracy with 160 training samples, outperforming validation-based methods by 18.31%. In the one-step configuration change task, MD tree yields a 5.52% CIFAR-10 accuracy improvement (Q1) and 8.10% (Q2) with optimal step size, compared to 3.50% and 5.03% for random diagnosis respectively.

## Baselines & Comparisons

MD tree is compared against three families of baselines: (1) Validation + DT, which uses training/validation error and loss as features; (2) Hyperparameter + DT, which uses model size and data amount; and (3) Loss landscape + DT, which uses the same loss landscape metrics as MD tree but with a standard (unfixed-hierarchy) decision tree. On Q1 dataset transfer with 96 samples, MD tree (87.7%) outperforms Validation + DT by 14.88% and Hyperparameter + DT by a wider margin. With only 12 training samples, MD tree still reaches 76.64%, outperforming the standard DT with the same loss landscape features by 12.71%, demonstrating the benefit of the fixed tree hierarchy as an inductive bias. On Q2, MD tree (74.11%) beats the validation-based method by 18.31%. In the one-step configuration change task, MD tree consistently outperforms all baselines across fixed, random, and optimal step sizes, approaching the optimal-diagnosis upper bound (5.52% vs. 5.83% for Q1; 8.10% vs. 8.83% for Q2). A stronger combined baseline (Hyperparameter + Validation + DT) narrows the gap but MD tree still leads in both dataset and scale transfer scenarios.

## Relation to Prior Work

This paper builds directly on the loss landscape regime taxonomy of Yang et al. (2021) and the statistical physics framework of Martin & Mahoney (2017), repurposing metrics originally designed to characterize phase transitions in hyperparameter space (mode connectivity, Hessian trace, CKA similarity) as diagnostic features for a new classification task. It departs from conventional model diagnosis (training/validation error analysis à la Raschka, 2018) by arguing that validation metrics yield complex, non-transferable nonlinear boundaries, whereas loss landscape geometry provides piecewise-linear separability across regimes. The paper also positions itself as orthogonal to generalization-metric work (which predicts test performance) and neural scaling laws (which allocate resources pre-training), focusing instead on post-hoc, configuration-agnostic failure-source identification.

## Why It Matters / Open Questions

The practical value is clear: when a pre-trained model underperforms and retraining or config access is infeasible, MD tree offers an interpretable, low-cost diagnostic (sharpness measurement adds only 0.24% to training time). The transferability finding—that a tree trained on 0.01M-parameter models diagnoses 44.66M-parameter models at 82.56% accuracy—suggests the multi-regime loss landscape structure is scale-invariant, which could make the tool broadly applicable. Key limitations include restriction to CIFAR-10/ResNet-18, a single optimizer hyperparameter (batch size), and only four failure sources; open questions include whether the approach extends to learning rate, deeper architectures, or more complex failure taxonomies, and whether fine-tuning thresholds in the target domain closes the remaining accuracy gap (e.g., 79.56% max on Q2).
