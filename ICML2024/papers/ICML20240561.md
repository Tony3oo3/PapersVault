## Problem

Autoregressive LLM decoding is memory-bandwidth-bounded, generating only one token per step and severely underutilizing GPU parallel processing power. Existing acceleration methods like speculative decoding require a separate draft model that is nontrivial to train, does not generalize across base models or datasets, and can even slow down decoding when acceptance rates are low. The paper asks whether one can parallelize decoding using only the base model itself, without any auxiliary component, while exactly preserving the output distribution.

## Input / Output

The method takes a standard text prompt and the base LLM's weights (no draft model, no external data store) and produces a generated text sequence that is distributionally identical to autoregressive decoding. Internally, it maintains a fixed-sized 2D window of shape (N−1)×W over the Jacobi iteration trajectory and an n-gram pool C that caches historical n-grams; the three tunable parameters W (lookahead positions), N (n-gram length), and G (max parallel verifications, typically set to W) control the compute-per-step tradeoff. The attention mask is a custom non-causal pattern that keeps lookahead and verification branches mutually invisible, and the implementation is compatible with FlashAttention and supports greedy, top-K, and top-P sampling.

## Method

LOOKAHEAD DECODING reformulates autoregressive decoding as a non-linear fixed-point system solvable by Jacobi iteration, then exploits the fact that each Jacobi step can produce tokens at multiple positions simultaneously. A lookahead branch maintains a sliding 2D window over the Jacobi trajectory to generate W disjoint n-grams in parallel per step, and an n-gram pool caches these candidates across steps. A verification branch retrieves up to G promising n-grams (those whose first token matches the last generated token) and verifies them in parallel using a progressive prefix-matching scheme that accepts the longest matching prefix, preserving the exact output distribution without storing full probability vectors (greedy sampling at generation time reduces each n-gram to a one-hot token). The paper proves a scaling law: the number of decoding steps decreases linearly with log(FLOPs) per step, enabling a compute-for-latency tradeoff. Lookahead Parallelism (LP) distributes the disjoint lookahead branches and independent verification candidates across multiple GPUs with near-zero inter-device communication during the forward pass, achieving up to 4× speedup on 8 A100s for code completion.

## Results

LOOKAHEAD DECODING achieves 1.4x–2.3x end-to-end speedup over autoregressive greedy decoding across MT-Bench, HumanEval, MBPP, and GSM8K on a single A100 (Fig. 5). With FlashAttention integration, the 7B model reaches 1.8x speedup on MT-Bench, and with Lookahead Parallelism on 8 GPUs, it achieves up to 4x speedup on ClassEval code completion. The method preserves output distribution quality: ROUGE scores are within 0.01–0.05 of autoregressive baselines on XSum and CNN/Daily Mail while delivering 1.46x–1.60x speedups with sampling (Table 2). The step compression ratio S ranges from 1.45x to 2.05x depending on the (N, W, G) configuration.

## Baselines & Comparisons

Against the primary baseline (HuggingFace greedy search), LOOKAHEAD DECODING consistently wins with 1.4x–2.3x speedup, with larger gains on code tasks (2.3x on HumanEval) due to higher token repetitiveness. Compared to Medusa (Cai et al., 2024), LOOKAHEAD DECODING achieves lower speedups (1.6x–2.1x vs. 2.3x–2.6x), but Medusa requires training additional decoding heads while LOOKAHEAD DECODING needs no auxiliary model or training. Speculative decoding with TinyLlama-1B or Vicuna-7B as draft models actually causes slowdowns (0.7x–1.0x), confirming the paper's argument that obtaining a well-matched draft model is non-trivial. Parallel Jacobi decoding (PJ) from Santilli et al. (2023) shows severe slowdowns (0.3x–0.7x) due to high per-step cost, while its GS-Jacobi variant (PGJ) achieves only 1.1x–1.2x, well below LOOKAHEAD DECODING. Prompt lookup decoding (Saxena, 2023) achieves 1.44x speedup, which is outperformed by LOOKAHEAD DECODING's best configuration (1.88x with prompt-as-reference augmentation).

## Relation to Prior Work

This paper builds directly on Jacobi decoding (Santilli et al., 2023), which reformulates autoregressive decoding as solving a non-linear system via fixed-point iteration, and on the speculative decoding paradigm (Chen et al., 2023a; Leviathan et al., 2023) of guess-and-verify. The key departure is that LOOKAHEAD DECODING eliminates the need for a separate draft model by using the base model's own underutilized compute to generate n-grams along the Jacobi trajectory (lookahead branch) and then verify them against the n-gram pool. Unlike tree-based verification methods (SpecInfer, Medusa, Eagle), it verifies disjoint n-grams in parallel, and unlike Pipeline/Tensor Parallelism, its proposed Lookahead Parallelism distributes tokens rather than model parameters across GPUs, avoiding per-step communication on the critical path.

## Why It Matters / Open Questions

LOOKAHEAD DECODING provides a model-free, distribution-preserving acceleration method with a clean scaling law (linear reduction in decoding steps per log FLOPs), making it future-proof as hardware compute grows. Its main limitation is that it requires surplus FLOPs (the memory-bandwidth-bound regime), so it may slow down under large-batch serving or on compute-constrained hardware. Open questions include how the method interacts with continuous batching, whether the n-gram pool can be further optimized for longer contexts, and whether the log-linear scaling law holds across model architectures and sequence lengths beyond what was tested.
