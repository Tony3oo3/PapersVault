## Problem

ProtoPNet produces visually interpretable classifications by matching images to prototypical patches, but in practice it learns prototypes that focus on spurious features (e.g., backgrounds) and inconsistent concepts (e.g., different body parts across images of the same species). Prior debugging methods addressed these issues without explicitly quantifying human user preferences for prototype quality, leaving no principled, learnable metric to guide prototype improvement.

## Input / Output

The method operates on RGB images from fine-grained classification datasets (CUB-200-2011 with ~30 images per bird species, Stanford Cars with 196 car models) and outputs a class label along with per-prototype activation patterns overlaid on the input image. Beyond the standard image input, the framework requires a small set of human scalar ratings (1–5 scale) of prototype-image pairs collected via Amazon Mechanical Turk (6 raters per pair, 700 pairs total), which are used to train the reward model. The reward model itself takes an image and its associated activation pattern as a pair and outputs a scalar reward in (0,1) via a Bradley-Terry ranking.

## Method

R3-ProtoPNet is a three-step post-processing debugging framework applied to a pretrained ProtoPNet. First, a reward model is trained on pairwise comparisons synthetically generated from scalar human ratings using a Bradley-Terry cross-entropy loss. Second, the R2 update combines reward reweighing (a reward-weighted objective that pulls low-reward prototypes toward high-reward image patches via inverse-distance weighting) with prototype reselection (randomly sampling new patch candidates for prototypes below a reward threshold and accepting those exceeding an acceptance threshold). Third, the full model is retrained with the original ProtoPNet loss to realign the base CNN features and classifier layer with the updated prototypes, restoring and often improving predictive accuracy. The key distinction from RLHF is that no formal reinforcement learning algorithm is used; reward values serve directly as a supervisory signal for prototype search, making the procedure efficient and offline.

## Results

On CUB-200-2011, R3-ProtoPNet (ensemble of five base architectures) achieves 84.37% test accuracy, up from 82.92% for the original ProtoPNet ensemble. Across all architectures, R3-ProtoPNet increases average prototype reward by 27.66% (0.47 → 0.60) and activation precision by 18.59% (73.22 → 86.83). On Stanford Cars, the ensemble accuracy improves from 90.39% to 91.57%, with average reward rising from 0.72 to 0.86. The reward model trained on 500 human ratings achieves 90.09% test accuracy in ranking prototype quality.

## Baselines & Comparisons

Against the original ProtoPNet (Chen et al., 2019), R3-ProtoPNet wins on test accuracy for 5 of 6 individual architectures (e.g., DenseNet-121: 79.64% → 80.42%) and the ensemble (82.92% → 84.37%), while also substantially improving interpretability metrics (reward +27.66%, AP +18.59%). The one exception is DenseNet-161, where R3 slightly underperforms (79.75% → 79.48%). Against ProtoPFormer (Xue et al., 2022), R3 applied to its global and local prototypes improves test accuracy from 84.27% to 85.31% and raises average reward from 0.55/0.59 to 0.68/0.70. Against ProtoPNet with SDFA and SA modules (Huang et al., 2023), R3 improves test accuracy from 85.03% to 85.82% and activation precision from 89.21 to 92.88, confirming that the framework generalizes to already-improved prototype-based variants.

## Relation to Prior Work

This paper builds directly on ProtoPNet (Chen et al., 2019) as the base architecture and departs from prior ProtoPNet improvements (Bontempelli et al., 2023; Barnett et al., 2021; Huang et al., 2023) by introducing a learned reward model trained on scalar human ratings as a quantitative metric for prototype quality, rather than relying on binary feedback or architectural constraints. The reward model formulation draws on the Bradley-Terry pairwise comparison model (Bradley & Terry, 1952) and the cross-entropy loss from Christiano et al. (2017), while the update mechanism uses reward-weighted learning (Lee et al., 2023; Ziegler et al., 2019) rather than formal RLHF algorithms like PPO. The framework is positioned as a post-processing debugging step that is orthogonal to the base architecture, demonstrated by its application to both CNN-based ProtoPNet and transformer-based ProtoPFormer.

## Why It Matters / Open Questions

The R3 framework provides a practical, offline debugging procedure that requires only ~300–500 human ratings to train a reward model, making human-in-the-loop interpretability improvement feasible at scale. The finding that the temporary accuracy drop during prototype reselection is not merely recovered but exceeded after retraining challenges the common narrative of an inherent accuracy-interpretability trade-off, though this evidence is limited to two fine-grained datasets. Key open questions include whether the reward model captures cross-image consistency (not just single-image overlap), whether it inadvertently penalizes non-obvious but predictive features (e.g., texture), and whether the framework generalizes beyond prototype-based models to other interpretable architectures.
