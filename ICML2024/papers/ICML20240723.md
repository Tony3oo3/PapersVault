## Problem

Existing instruction tuning for large language models improves helpfulness and natural-language safety but largely ignores the security of generated code, leaving even state-of-the-art instruction-tuned LMs producing vulnerable code roughly 40% of the time. The core challenge is to enhance code security during instruction tuning without degrading utility on functional correctness, natural language understanding, and other human-preference tasks.

## Input / Output

The method takes a pretrained LM, a standard instruction tuning dataset (e.g., Evol-Instruct-66k for coding LMs or LMSYS-Chat-1M for general-purpose LMs), and a security dataset of triples (instruction, secure program, insecure program) where the two programs differ only in security-critical tokens (~9% of total tokens). The security dataset is constructed from GitHub commits via an automated pipeline that filters by CWE keywords and verifies fixes with CodeQL static analysis. The output is a single instruction-tuned LM that achieves ~90% secure code generation across 60 testing scenarios while maintaining comparable scores on HumanEval, MBPP, MMLU, and TruthfulQA.

## Method

SafeCoder performs a joint optimization in a single training run: at each iteration, a sample is drawn from either the standard instruction tuning set (optimized with standard negative log-likelihood) or the security set (optimized with two masked losses). For security samples, a masked NLL loss (L^sec) increases the probability of security-critical tokens in the secure program, while a masked unlikelihood loss (L^vul) decreases the probability of the corresponding insecure tokens. The masks are computed via token-level diff (using Python's difflib) between the secure and insecure programs, concentrating the learning signal exclusively on security-relevant tokens. The security dataset is collected through a two-step automated pipeline over 145M GitHub commits: lightweight heuristic filtering (CWE keyword matching, ≤40 changed lines, ≤2 files) followed by CodeQL verification that the pre-commit code has vulnerabilities and the post-commit code does not. Minority CWE-language classes are oversampled to a threshold k to balance training, and the combined dataset (1,268 samples across 25 CWEs and 6 languages) is mixed with the standard instruction tuning data without altering their relative proportions.

## Results

Across six state-of-the-art LMs (StarCoder-1B/3B, CodeLlama-7B, Phi-2-2.7B, Llama2-7B, Mistral-7B), SafeCoder raises secure code generation from ~60% (standard instruction tuning) to ~89–93%, a ~30 percentage-point improvement. Utility is preserved: HumanEval Pass@1, MBPP Pass@1, MMLU, and TruthfulQA scores remain within 1–3 points of the standard instruction-tuned baseline. For example, StarCoder-1B goes from 62.9% to 92.1% code security while maintaining HumanEval Pass@1 at 19.4 (vs. 20.4 without SafeCoder), and Mistral-7B reaches 89.6% security with HumanEval Pass@1 of 33.7 (vs. 35.2 without SafeCoder).

## Baselines & Comparisons

The primary external baseline is SVEN (He & Vechev, CCS 2023), which patches an insecure instruction-tuned LM via incremental security tuning with a KL-divergence regularizer. The paper demonstrates that SVEN exhibits an inherent trade-off: as the KL weight w^KL increases (preserving utility), security drops, and as it decreases (improving security), functional correctness degrades (Figure 3). SafeCoder, by contrast, achieves both high security (~90%) and high utility simultaneously because it jointly optimizes both objectives in a single training run rather than patching post-hoc. Against the standard instruction-tuning baseline (w/o SafeCoder), SafeCoder gains ~25–30 percentage points in code security across all six LMs while keeping utility metrics within 1–3 points. Ablations confirm that the collected security dataset contributes ~20% of the security gain, loss masking contributes ~10%, and the unlikelihood loss contributes 5–11% depending on the model.

## Relation to Prior Work

SafeCoder extends SVEN (He & Vechev, 2023), which performs security hardening for pretrained code completion models via masked contrastive losses, to the instruction-tuning setting for both coding and general-purpose LMs. The key methodological departure is replacing SVEN's contrastive loss (which requires a separate insecure reference LM) with a masked unlikelihood loss (Welleck et al., 2020) applied to the same model, and integrating security training jointly with standard instruction tuning rather than as a post-hoc incremental patch. The automated data collection pipeline also departs from SVEN's manual curation by leveraging heuristic filtering over GitHub commits followed by CodeQL static analysis verification.

## Why It Matters / Open Questions

The 'security-for-free' property—achieving ~30% security improvement with negligible utility loss—is practically significant because it can be trivially integrated into existing instruction tuning pipelines without architectural changes or additional training stages. However, SafeCoder does not generalize well to CWEs unseen during training, provides no formal security guarantees, and does not address already-instruction-tuned LMs that require post-hoc security patching. Extending the approach to reinforcement learning and improving cross-CWE generalization remain open directions.
