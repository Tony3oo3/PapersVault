## Problem

Existing LLM inference systems (vLLM, Orca, etc.) treat external tool calls or human-response waits as request terminations, discarding the KV cache and forcing full recomputation upon resumption. This recomputation accounts for 37–40% of total model forwarding time in augmented-LLM workloads, wasting GPU resources that could serve new requests. No prior system provides a principled mechanism to handle these mid-generation interceptions efficiently.

## Input / Output

The system ingests LLM text prompts interleaved with external tool responses (calculator outputs, Wikipedia QA snippets, virtual-environment state updates, human chat messages, Stable Diffusion image descriptions, and Bark TTS audio) that arrive at highly variable latencies ranging from sub-millisecond (math) to over 28 seconds (chatbot). The output is the continuation of autoregressive text generation after each interception completes. A key constraint is that the KV cache for a paused request must be retained in some form (GPU, CPU, or recomputed) across the interception, and context lengths vary widely (700–2200 tokens) across augmentation types.

## Method

INFERCEPT introduces a 'min-waste interception' principle that dynamically selects, per request and per iteration, among three strategies—preserve, chunked discard, and pipelined swap—to minimize GPU memory waste. For swap, it pipelines kernel launch, data movement, and model forwarding layer-by-layer, and chunks the swap across multiple iterations bounded by a per-iteration swap budget (tokens swappable within one forward-pass time), eliminating swap-induced waste entirely. For discard, it exploits the complementary resource profiles of decoding (memory-bound, few query tokens) and recomputation (compute-bound, many query tokens) by splitting the discarded context into chunks sized to the GPU saturation point minus the running batch, cutting recomputation waste roughly in half. At each iteration, the scheduler sorts intercepted requests by their computed memory waste (min of preserve-waste and chunked-discard-waste), assigns the swap budget to the highest-waste requests, and preserves or discards the remainder; resumed requests are scheduled FCFS from separate swap and waiting queues to maintain fairness.

## Results

INFERCEPT sustains 1.6×–2× higher request arrival rates than vLLM at the same normalized latency across GPT-J-6B (1 GPU), Vicuna-13B (1–2 GPUs), and Llama3-70B (4 GPUs), while achieving 1.3×–12× lower normalized latency at the same throughput. It completes over 2× more requests per second and reduces GPU memory waste to 0.69% (vs. 27% for Discard and 26% for Swap). On single-augment workloads, INFERCEPT improves normalized latency by up to 2.3× (QA) and 1.9× (Chatbot) over vLLM.

## Baselines & Comparisons

INFERCEPT outperforms all four baselines (vanilla vLLM/Discard, ImprovedDiscard, Preserve, and Swap) on every metric across all model sizes. Vanilla vLLM (Discard) wastes 27% of GPU resources and spends 37–40% of forwarding time on recomputation; ImprovedDiscard fixes the FCFS starvation but still incurs the same recomputation overhead, making it consistently worse than INFERCEPT. Preserve is the strongest baseline for small models (6B) because preserving short-context requests is cheaper than recomputing, yet INFERCEPT still wins on all metrics thanks to its dynamic min-waste scheduling. Swap wastes 26% of GPU resources and over 25% of workload time on synchronous data movement; INFERCEPT's swap pipelining and chunking eliminate 96% of that waste. The gap widens with model size and GPU count: on Llama3-70B (4 GPUs), INFERCEPT achieves up to 12× lower normalized latency vs. vLLM, while Preserve and Swap benefit from GQA's compressed KV but still trail INFERCEPT's per-request adaptive decisions.

## Relation to Prior Work

INFERCEPT builds directly on vLLM's PagedAttention for GPU memory management and Orca's iteration-level scheduling paradigm, but departs fundamentally by introducing the problem of LLM generation interception — pausing decoding for external tool calls, human responses, or environment interactions. While prior systems (vLLM, Orca, Sarathi, DistServe) optimize standalone LLM inference, none address the unique memory and scheduling challenges of temporarily paused requests whose KV caches must be preserved, swapped, or recomputed. The paper also repurposes Sarathi's chunked-prefill idea, applying chunking not to initial prompt processing but to recomputation and GPU-CPU swapping, and introduces swap pipelining to hide data-movement latency behind model forwarding.

## Why It Matters / Open Questions

As LLMs are increasingly augmented with tools, agents, and human-in-the-loop interactions (ChatGPT plugins, ReAct, virtual environments), the 37–40% recomputation waste identified here becomes a first-order cost in production serving. The min-waste interception principle and its concrete mechanisms (swap pipelining, chunked recomputation, adaptive per-request strategy selection) offer a practical path to near-zero waste that could be integrated into existing serving stacks. Open questions include how the approach scales to multi-turn agent workflows with deeply nested interceptions, whether the min-waste objective generalizes to other resource constraints (e.g., network bandwidth for distributed inference), and how scheduling-policy choices (beyond FCFS) interact with interception-aware scheduling.
