## Problem

Existing LLM-based tabular learning methods require an LLM inference call per sample at test time, often need fine-tuning access to the LLM (infeasible for API-only models like GPT-3.5), and degrade or fail when the serialized feature text exceeds prompt length limits. These constraints make LLM-based tabular prediction impractical for real-world deployment, especially on datasets with many features.
![Teaser figure](../imgs/ICML20240695/cropped_page2_idx0.webp)

## Input / Output

The method consumes a tabular dataset with natural-language feature names and definitions, a task description phrased as a question, and k few-shot labeled samples serialized into text. At training time, it produces a set of interpretable natural-language rules per class (10 rules per class by default), which are parsed into executable Python code to generate binary features. At inference time, only a lightweight linear model over these binary features is needed, yielding class probabilities via softmax over non-negative weighted dot products—no LLM calls are required.

## Method

FeatLLM assigns the LLM the role of feature engineer rather than predictor. A structured prompt guides the LLM through a two-step reasoning process: first inferring causal relationships between features and the task using prior knowledge (without seeing examples), then deriving specific threshold/membership rules for each class conditioned on few-shot demonstrations. The generated natural-language rules are parsed into executable Python code via a second LLM call, producing binary features indicating rule satisfaction per sample. A simple linear model with non-negative trainable weights (no bias) is then fitted on these binary features to estimate class probabilities, with cross-entropy loss optimized over the few-shot samples. The entire pipeline is repeated T=20 times with feature/sample bagging, shuffled example order, and temperature 0.5 to generate diverse rule sets, and final predictions average the class probabilities across all ensemble members—combining self-consistency with bagging to handle both noisy rules and prompt-size constraints.

## Results

FeatLLM achieves an average AUC of 77.86 (4-shot), 79.31 (8-shot), and 80.70 (16-shot) across 11 tabular datasets, outperforming the strongest LLM-based baseline TabLLM (70.26, 72.76, 76.22) by approximately 7–8 AUC points on average. On individual datasets, FeatLLM reaches 86.68 AUC on Adult (4-shot), 80.28 on Diabetes (4-shot), and 100.00 on Solution-mix (4-shot). The framework also handles high-dimensional datasets (Communities with 103 features, Myocardial with 111 features) where LLM-based baselines (TabPFN, In-context, TABLET, TabLLM) fail entirely due to prompt size limitations.

## Baselines & Comparisons

FeatLLM outperforms all 8 baselines on average AUC across all shot settings (4/8/16), with the largest margins over conventional methods: +12.4 AUC over LogReg, +27.9 over XGBoost, and +19.6 over SCARF at 4-shot. Among LLM-based baselines, FeatLLM beats TabLLM by +7.6 AUC (4-shot) and +4.5 AUC (16-shot), In-context learning by +9.4 AUC (4-shot), TABLET by +9.2 AUC (4-shot), and TabPFN by +14.9 AUC (4-shot). However, FeatLLM loses to TabLLM on Car (72.69 vs 85.82 at 4-shot) and NHANES (92.20 vs 99.49 at 4-shot), and to STUNT on Heart (75.66 vs 88.27 at 4-shot). A critical practical advantage is that FeatLLM is the only method that successfully handles high-dimensional datasets (Communities, Myocardial with >100 features) where TabPFN, In-context, TABLET, and TabLLM all fail due to prompt size constraints. Inference cost is also dramatically lower: FeatLLM requires only 0.006 ms per sample (comparable to LogReg) versus 335–523 ms for other LLM-based methods.

## Relation to Prior Work

This paper departs from the dominant paradigm of LLM-based tabular learning (TabLLM, TABLET, in-context learning) where the LLM performs end-to-end per-sample prediction, instead repurposing the LLM as a one-time feature engineer that extracts interpretable rules/conditions from prior knowledge and few-shot examples. Conceptually, it builds on chain-of-thought prompting (Wei et al., 2022b) to structure a two-step reasoning process (prior-knowledge inference followed by data-driven rule derivation) and on ensemble methods (Breiman, 2001) via feature bagging to handle prompt-size constraints and improve robustness. The downstream predictor is reduced to a simple non-negative linear model over binary rule features, a stark contrast to the complex LLM inference required by prior approaches.

## Why It Matters / Open Questions

The practical impact is significant: FeatLLM reduces inference from ~463ms (in-context LLM) to ~0.006ms (linear model), requires only API-level access without fine-tuning, and handles datasets with 100+ features where prior LLM-based methods fail entirely. However, the framework is explicitly scoped to the low-shot regime, and the automated parsing step still exhibits error rates up to 40% on datasets with many categorical features. Open questions include whether the approach scales to larger sample sizes, how societal biases embedded in LLM prior knowledge propagate into generated rules, and whether the rule-based feature space can be extended to richer functional forms beyond binary conditions.
