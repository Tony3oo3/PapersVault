## Problem

On-device DNN training at the edge faces three simultaneous constraints—scarce labelled user data (5–30 samples), severely limited memory (≤1 MB on MCUs), and constrained compute—that no prior method addresses jointly. Existing sparse-update approaches use static layer/channel selections determined by expensive offline searches, cannot adapt to new tasks, and still incur 1.5–3× the memory/compute of TinyTrain while losing 2.6–7.7% accuracy under data scarcity.
![Teaser figure](../imgs/ICML20241033/cropped_page1_idx0.webp)

## Input / Output

At deployment, TinyTrain consumes a small set of labelled user images (various-way-various-shot, 5–30 per class, 128×128×3 RGB), the meta-trained backbone weights, and explicit memory/compute budgets (e.g., ~1 MB backward-pass memory, ~15% of total MACs). It outputs sparsely updated model weights and class predictions via ProtoNet nearest-centroid classification, where class prototypes are computed from the support set and queries are assigned by cosine distance to the nearest prototype.

## Method

TinyTrain is a two-stage pipeline. Offline, it pre-trains a CNN backbone on ImageNet and then meta-trains it with ProtoNet on MiniImageNet in an episodic few-shot fashion (5–30 shots per class), producing a weight initialisation that is sample-efficient for unseen cross-domain tasks. Online, it performs task-adaptive sparse update: it computes Fisher information on activations for each layer using the few target samples, then ranks layers by a multi-objective score s_i = P_i / (‖W_i‖_norm × M_i_norm) that jointly captures channel importance, parameter count, and MAC cost. Layers are greedily selected under the memory and compute budgets, and within each selected layer the top-K channels by Fisher information are updated. This dynamic selection runs in 20–35 seconds on edge devices (vs. ~10 minutes for SparseUpdate's offline evolutionary search), enabling per-task adaptation without any pre-determined static policy.

## Results

TinyTrain achieves the highest average top-1 accuracy across three DNN architectures (MCUNet, MobileNetV2, ProxylessNASNet) on nine cross-domain few-shot datasets, reaching 69.3%, 65.6%, and 68.3% respectively — outperforming full fine-tuning (FullTrain) by 3.6–5.0 pp and the SOTA sparse-update method (SparseUpdate) by 2.6–7.7 pp. In terms of efficiency, TinyTrain reduces backward-pass memory by up to 1,098× and computation by up to 7.68× compared to FullTrain, while staying within a 0.78–1.06 MB memory envelope suitable for MCU-grade platforms. On Raspberry Pi Zero 2, TinyTrain completes end-to-end on-device training in ~10 minutes (vs. ~2 hours for FullTrain) with 1.20–1.31 kJ energy consumption.

## Baselines & Comparisons

TinyTrain outperforms all seven baselines on average accuracy across all three architectures. Against FullTrain (Pan & Yang, 2010), which fine-tunes the entire network, TinyTrain gains 3.6–5.0 pp while using up to 1,098× less memory and 7.68× less computation — demonstrating that full fine-tuning is both infeasible on edge hardware and not necessarily optimal under data scarcity. Against LastLayer (Ren et al., 2021; Lee & Nirjon, 2020), which updates only the classifier head, TinyTrain improves accuracy by 13.0–26.9 pp, confirming that last-layer-only adaptation is insufficient for cross-domain tasks. Against TinyTL (Cai et al., 2020), which adds lite-residual adapters to every block, TinyTrain gains 4.8–7.2 pp while requiring 606–692× less memory. Against SparseUpdate (Lin et al., 2022), the prior SOTA with static evolutionary-search-based layer/channel selection, TinyTrain improves accuracy by 2.6–7.7 pp while reducing memory by 1.59–2.23× and computation by 1.52–1.82×, and eliminates the need for a 10-minute offline GPU search. Against Transductive fine-tuning (Dhillon et al., 2020) and AdapterDrop variants (Rücklé et al., 2021), TinyTrain leads by 3.2–9.2 pp on average, with the gap widening as more adapter layers are dropped.

## Relation to Prior Work

TinyTrain builds on the ProtoNet meta-learning framework (Snell et al., 2017) for few-shot adaptation and the Fisher information criterion (Theis et al., 2018) for identifying important network components, but departs fundamentally from the static sparse-update paradigm of SparseUpdate (Lin et al., 2022) by making layer/channel selection dynamic and task-adaptive at deployment time. It also extends the insight from Hu et al. (2022) that standard transfer learning underperforms in the few-shot regime by incorporating FSL-based meta-training into the offline stage, rather than relying on conventional pre-train-then-fine-tune pipelines. The key conceptual departure is the joint multi-objective criterion that simultaneously accounts for channel importance, memory footprint, and compute cost, replacing the single-objective (accuracy-only) or memory-only optimisation of prior sparse-update methods.

## Why It Matters / Open Questions

TinyTrain is the first framework to jointly address the three practical bottlenecks of on-device training—data scarcity, memory, and compute—enabling training within the 1 MB memory envelope of MCU-grade platforms, which prior methods could not achieve. This opens the door to on-device personalisation on commodity IoT hardware (Raspberry Pi Zero 2, Jetson Nano) with 10-minute training times instead of hours. However, the evaluation is limited to CNN-based architectures on vision classification tasks, and the authors explicitly note that extending to Transformers, RNNs, segmentation, or mobile LLMs remains open. The practical impact is significant for the TinyML and edge-AI communities, though the method's reliance on Fisher information computed over a small support set may not generalise trivially to non-convolutional architectures.
