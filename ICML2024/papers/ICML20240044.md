## Problem

Existing code LLM benchmarks (HumanEval, MBPP, ARCADE, DS-1000) are manually curated, cover only narrow domains (introductory algorithms, a few data-science libraries), and are prohibitively expensive to expand to the full breadth of real-world software. This paper asks whether an unsupervised evaluation method can measure code LLM performance across diverse domains without any human-annotated test cases.

## Input / Output

For SYNTHESIS_RTC, the input is a contiguous code region (32–384 characters) sampled from a source file, along with ≤1024 characters of surrounding context and the project's existing unit tests; the forward model produces a ≤128-character natural language description, and the backward model produces code that is scored by unit-test pass rate. For EDITING_RTC, the input is an old→new code edit pair with surrounding context; the forward model produces an edit description and the backward model produces the new code, scored by exact match. The final outputs are an RTC score (fraction of forward×backward sample pairs that are semantically correct) and a forward lift score (RTC minus the score obtained when the forward description is replaced by an uninformative placeholder such as 'TODO: Implement.').

## Method

The core mechanism is round-trip correctness (RTC), adapted from property-based testing: a single LLM is prompted to perform a forward task (code→natural-language description, or edit→edit description) and then a backward task (description + context→code, or old code + description→new code), and the backward output is checked for semantic equivalence to the original input via unit tests or exact match. RTC is estimated by drawing N_f forward samples (temperature 0.8–1.0) and N_b backward samples (temperature 0.0–0.1) per input and averaging the similarity score. A forward lift is computed by subtracting the backward-only performance (using a generic placeholder instead of the model's description) from full RTC, isolating the information contributed by the forward model. The same model is used for both directions to avoid a 'communication chasm' between differently-worded descriptions and the backward model's expectations, and the 128-character cap on forward samples prevents verbose models from gaining an unfair advantage. The method requires no training or fine-tuning; it is a purely inference-time evaluation protocol applied to off-the-shelf instruction-tuned LLMs.

## Results

RTC_pass strongly correlates with the standard pass@1 metric on both HumanEval (Pearson r=0.96, Spearman ρ=0.90) and ARCADE (Pearson r=0.96, Spearman ρ=0.81), validating RTC as a reliable unsupervised proxy. On the diverse 58-project dataset, RTC_pass varies widely across domains (e.g., TheAlgorithms achieves very high scores while jedi, a static analysis library, has the lowest), revealing domain-specific weaknesses invisible to narrow benchmarks. For code editing (EDITINGRTC), Gemini Pro achieves 12.9% RTC_ExactMatch with a forward lift of 12.4%, compared to 5.2% and 4.8% for Gemini Nano 2, respectively.

## Baselines & Comparisons

Against the standard pass@1 metric from Chen et al. (2021), RTC_pass achieves near-perfect correlation (r=0.96) on both HumanEval and ARCADE, confirming RTC as a valid unsupervised alternative that requires no human-curated test cases. The absolute RTC_pass values are lower than pass@1 (e.g., 40.2% vs. 75.6% for DSC 33B-IT on HumanEval), which the authors attribute to the absence of input-output examples in the backward prompt and noise from the forward description step. Against the supervised CodeReviewer evaluation from Li et al. (2022b), RTC_ExactMatch proves more reliable: supervised BLEU scores for edit descriptions are extremely low (0.5–1.0) and uninformative, while supervised NL→Edit exact match (11.7–19.4%) can be misleading when PR comments are misaligned with the labeled code edit. In such noisy-label cases, RTC correctly identifies that the model's generated descriptions are consistent with the edit even when they do not lexically overlap with the noisy PR comment reference.

## Relation to Prior Work

This paper repurposes the software-testing concept of round-trip correctness (from property-based testing, Fink & Bishop 1997) as an unsupervised evaluation methodology for code LLMs, rather than building on a specific prior LLM evaluation method. Conceptually, the forward/backward sampling resembles back translation in machine translation (Sennrich et al., 2016), but the focus shifts from data augmentation to model evaluation. It also relates to self-consistency decoding (Wang et al., 2022) and IdentityChain (Min et al., 2023), but departs from both by requiring functional correctness (via unit tests or exact match) rather than mere sample consistency, and by not requiring a human-annotated reference corpus. The code synthesis and editing tasks themselves are well-established; the novelty lies entirely in the evaluation protocol.

## Why It Matters / Open Questions

RTC addresses a practical bottleneck in code LLM evaluation: the cost and narrowness of human-curated benchmarks like HumanEval and ARCADE. By showing r=0.96 correlation with pass@1 while enabling evaluation across 58 diverse open-source projects and the previously unbenchmarked code editing task, it offers a scalable complement to existing benchmarks. Key limitations include the coupling of forward and backward task quality (a poor forward model poisons the backward evaluation), dependence on the similarity function's quality, and the adversarial-gaming risk if models are trained directly against the RTC objective. Open questions include whether RTC can be extended to multi-file or repository-level tasks, whether different forward/backward model pairings can be made to work without the communication-chasm confounders the authors identify, and how RTC behaves as models and codebases evolve rapidly.
