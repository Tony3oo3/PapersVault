## Problem

Current open-source guardrail solutions for LLMs (Llama Guard, Nvidia NeMo, Guardrails AI) provide only basic rule-description infrastructure and loosely coupled neural-symbolic components, without a systematic process to handle multiple, potentially conflicting safety requirements across diverse application contexts. The paper argues that guardrail construction demands the same engineering rigor as safety-critical software (per ISO-26262, DO-178B/C), yet no such end-to-end methodology—from requirement specification through verification to deployment—currently exists in the LLM safety literature.

## Input / Output

Guardrails consume LLM input prompts and/or output text, but the consumption mechanism varies substantially across frameworks: Llama Guard concatenates input and output into a single sequence for a fine-tuned Llama2-7b classifier, NeMo embeds prompts via sentence-transformers (all-MiniLM-L6-v2) and retrieves the nearest canonical form via KNN/Annoy, while Guardrails AI parses RAIL XML specifications to validate output structure, types, and quality. Outputs range from binary safety classifications and enforcement actions (block, filter, redirect) to automatically generated corrective prompts that trigger LLM regeneration and re-checking, with the specific action determined by the application context and which requirement category (toxicity, fairness, privacy, hallucination) is triggered.

## Method

This position paper proposes a systematic design methodology for LLM guardrails structured around three pillars. First, a sociotechnical, multi-disciplinary process (drawing on whole-system approaches from healthcare) to precisely define and justify requirements for a specific application context, resolving conflicts between requirements such as safety vs. creativity or fairness vs. privacy. Second, more deeply coupled neural-symbolic architectures beyond the Type-1 systems used by current tools, where learning agents handle frequent cases and symbolic agents (e.g., knowledge graphs, pointer networks) handle rare corner cases with interpretability, enabling principled conflict resolution via logic and decision theory. Third, a rigorous verification and testing regime combining statistical certification (randomized smoothing, conformal prediction, certified robustness bounds) for individual requirements with Pareto front evaluation for managing trade-offs among multiple conflicting objectives, all structured within a V-model SDLC that links each development phase to its corresponding testing activity and culminates in a formal safety argument for stakeholder communication.

## Results

This is a position paper without quantitative benchmarks; its primary contribution is a qualitative comparison of three open-source guardrail frameworks (Llama Guard, Nvidia NeMo, Guardrails AI) and a systematic design methodology. The qualitative analysis (Table 2) reveals that no single framework supports all five evaluation dimensions: Llama Guard lacks enforcement rules, Nvidia NeMo lacks output checking and scalability, and Guardrails AI lacks multi-modal support. The paper further demonstrates via examples (Appendix B) that current guardrails still permit jailbreaking, biased responses, privacy leaks, and hallucinations in ChatGPT, while also showing that some previously known attacks (DAN, hypothetical-response framing) have been patched in newer model versions.

## Baselines & Comparisons

The paper qualitatively compares three guardrail frameworks rather than proposing a new method to benchmark against baselines. Llama Guard (Meta, Llama2-7b) is a Type-1 neural-symbolic classifier that monitors both input and output but cannot enforce corrective actions, making it the weakest on the enforcement dimension. Nvidia NeMo (NVIDIA) uses Colang for programmable dialogical constraints and KNN-based intent matching, supporting enforcement and multi-modality but lacking post-generation output validation and being limited to ChatGPT integration. Guardrails AI (Rajpal, 2023) is a Type-2 neural-symbolic system with RAIL XML specifications and automatic corrective-prompt regeneration, offering the best scalability across LLMs but restricted to text-only checks. The authors conclude that all three frameworks provide only basic infrastructure (rule-description languages, example workflows) without comprehensive studies on capability, generalization, or expressivity, and none implements the systematic, multi-requirement, verification-driven design process the paper advocates.

## Relation to Prior Work

This position paper surveys three existing LLM guardrail implementations (Llama Guard, Nvidia NeMo, Guardrails AI) and positions them as using only the simplest, loosely coupled neural-symbolic architectures (Type-1 and Type-2 per Lamb et al., 2021). It departs from the prevailing ad-hoc, tool-centric view of guardrails by importing the systematic engineering discipline of safety-critical software (ISO-26262, DO-178B/C, V-model, SDLC) into the LLM safety domain, arguing that guardrails require the same full development lifecycle rigor. The paper also draws on the broader LLM safety literature on jailbreaking, RLHF, differential privacy, and hallucination detection, but reframes these individual techniques as components within a unified, multi-requirement engineering process rather than standalone solutions.

## Why It Matters / Open Questions

The paper identifies a critical gap: existing guardrail tools provide infrastructure (rule languages, basic workflows) but lack a systematic methodology for specification, conflict resolution, verification, and certification across multiple, potentially conflicting requirements. Open questions include how to provide certified robustness guarantees for guardrails (beyond empirical testing), how to resolve tensions between safety and intelligence/creativity in a principled way, and whether more deeply coupled neural-symbolic architectures (Type-6) can handle the complexity that loosely coupled systems cannot. The socio-technical, multi-disciplinary framing is underexplored in the LLM safety literature and could reshape how guardrail requirements are elicited and validated in practice.
