## Problem

Autoregressive LLM inference is memory-bandwidth-bound for long sequences and large batches, because the full KV cache must be fetched from memory at every generation step. While tokens attend to only a small fraction of the sequence, existing inference-time methods either permanently evict cache entries (losing information), require architectural changes at pre-training, or can reduce transfers by at most 50% by skipping value fetches while still needing the full key cache to compute attention scores.

## Input / Output

SparQ Attention operates on a single attention head's inputs: a query vector q ∈ ℝ^{d_h}, the key cache K ∈ ℝ^{S×d_h}, the value cache V ∈ ℝ^{S×d_h}, and a running mean value vector v̄ ∈ ℝ^{d_h} maintained across generation steps. It produces the standard attention output y ∈ ℝ^{d_h}. Two hyperparameters control the compression ratio: r (number of query components used for score approximation, typically 8–64) and k (number of top positions whose full key-value pairs are fetched, typically 128). The method is applied at inference time to off-the-shelf models with no retraining or architectural modification.

## Method

SparQ Attention approximates the attention output in three steps. First, it identifies the r largest-magnitude components of the query vector and fetches only the corresponding r columns of K to compute approximate attention scores, using a softmax temperature τ = √(d_h · ‖q∘m_q‖₁/‖q‖₁) that corrects for the partial dot product. Second, it selects the top-k positions from these approximate scores and fetches only the full key-value pairs at those positions to compute a partial attention output. Third, it interpolates between this partial output and a running mean value vector v̄, weighted by the approximate score mass α assigned to the top-k positions, compensating for the un-fetched values. The approach exploits three observed properties of pretrained transformers: attention score sparsity (softmax mass concentrates on few positions), query vector heavy-tailedness (leptokurtic distributions mean a small subset of components dominates the dot product), and value auto-correlation along the sequence axis (justifying the mean-value correction). This yields up to 8× reduction in attention data transfers with minimal accuracy loss across Llama 2/3, Mistral, Gemma, and Pythia models.

## Results

SparQ Attention achieves up to 8× reduction in attention data transfers (1/8 compression) with minimal accuracy loss across five tasks and five model families. On SQuAD 1-shot with Llama 3 8B, SparQ maintains 78.3% exact-match accuracy at 1/8 compression versus 81.2% for the dense baseline (a 2.9-point drop), while on the Text Repetition task it preserves 213/213 characters of verbatim recall. On TriviaQA 0-shot, SparQ at 1/8 compression scores 82.8% versus 83.2% dense for Llama 3 8B, and on WikiText-103 BPC the increase is only 0.56→0.58. Microbenchmarks on A100 confirm a 3.02× wall-clock speedup for the attention kernel at batch size 64, S=4096, approaching the 6.4× theoretical bound.

## Baselines & Comparisons

SparQ Attention consistently outperforms both H2O and LM-Infinite across all five tasks and all five model families at 1/8 compression. Against H2O, the gap is most dramatic on SQuAD (e.g., 78.3% vs 61.7% for Llama 3 8B) and Text Repetition (213 vs 30 characters for Llama 3 8B), where H2O's eviction of low-attention tokens permanently loses information needed for retrieval. Against LM-Infinite, SparQ's advantage is even larger: on SQuAD at 1/8, SparQ scores 57.1–80.3% versus LM-∞'s 17.0–51.8%, and on Repetition SparQ retains 144–237 characters versus LM-∞'s 18–29. On TriviaQA and WikiText-103, where the information is more uniformly distributed, H2O narrows the gap (e.g., 82.5% vs 82.8% on TriviaQA for Llama 3 8B), but SparQ still matches or exceeds it. FlexGen (top-k sparse attention using exact scores) is included as a baseline in the appendix but is omitted from the main table because its compression ratio cannot go below 1/2; SparQ extends the achievable compression range to 1/8 while maintaining accuracy.

## Relation to Prior Work

SparQ Attention sits at the intersection of two lines of work: inference-time KV cache compression (H2O, Scissorhands, FastGen) and sparse/efficient attention (FlexGen, LM-Infinite, StreamingLLM). It departs from eviction-based methods by retaining the full KV cache and instead selectively fetching only relevant tokens at each generation step, avoiding the permanent information loss that limits eviction approaches on retrieval-heavy tasks. It also departs from methods like FlexGen that still require the full key cache to compute exact attention scores (capping compression at 50%) by exploiting the heavy-tailed structure of query vectors to approximate scores from a small subset of key dimensions. The mean value reallocation step, motivated by observed auto-correlation in value vectors, is a novel compensation mechanism not present in prior sparse attention or cache compression work.

## Why It Matters / Open Questions

This provides a drop-in, training-free inference optimization that can be applied to any existing LLM, with up to 8× reduction in attention data transfers and near-dense accuracy across five model families and five task types. The needle-in-a-haystack results (100% at 1/4 compression vs. 5.9% for H2O) highlight a practical advantage for retrieval-augmented generation and long-context applications where eviction methods silently lose critical information. Open questions include the 50% extra memory cost of storing K in two layouts, the modest GPU speedups at small batch sizes (1.28×–1.63× without full kernel fusion), and whether the technique composes well with 4-bit KV cache quantization or weight sparsity methods. The paper also notes that GQA models performed better without the mean value reallocation step, suggesting the optimal configuration may be model-dependent.
