## Problem

Designing effective reward functions for RL agents operating on image-based observations remains a significant bottleneck, as rewards are typically hand-crafted by domain experts and often sparse. While pre-trained VLMs can understand visual scenes and reason about task completion, directly querying them at every time step is computationally prohibitive, stochastic, and produces uninterpretable outputs. This paper asks whether VLMs can be leveraged in a one-shot manner to generate efficient, verifiable, and interpretable reward functions that accelerate RL training.

## Input / Output

The method takes only two images as input to the VLM: a single initial-state frame and a single goal-state frame from the environment (top-down RGB for MiniGrid/Pandas-Gym, or a 45-degree RGB-D camera view for CLIPort). The VLM outputs a set of standalone Python scripts that perform image processing (contour detection, color thresholding, vertex counting, convex hull approximation) to identify objects and check sub-task or goal completion. These scripts are then executed at every RL time step on the current observation frame, producing binary completion signals or continuous progress values (e.g., normalized Euclidean distance) that form a dense reward signal. No fine-tuning of the VLM is required; all interaction occurs through the GPT-4 web interface.

## Method

VLM-CaR is a three-stage pipeline that converts VLM visual reasoning into executable reward code. In the generation stage, the VLM is sequentially prompted to (i) identify the agent and relevant objects by color/shape/vertices, (ii) infer n sequential sub-tasks from the initial and goal images, and (iii) write a Python program for each sub-task's object identification and completion check. In the verification stage, the generated programs are executed on 2 expert trajectories (all sub-tasks must be completed) and 100 random trajectories (fewer than 10% may complete any sub-task); programs that fail are sent back to the VLM with a refinement prompt until they pass. In the training stage, the verified programs are assembled into a dense auxiliary reward (1/n per sub-task completion, plus a final goal reward) and fed into standard RL algorithms (PPO for discrete MiniGrid, TQC for continuous Pandas-Gym). The approach is conceptually grounded in the options framework, where the VLM generates initiation and termination conditions as code while the option policies are learned via RL, and it operates entirely zero-shot without any VLM fine-tuning.

## Results

The paper presents results primarily through learning curves (Figures 2–4) rather than a single numerical summary table. In MiniGrid, VLM-CaR dense rewards enable the agent to solve DoorKey8x8 (a task where sparse environment rewards yield no meaningful performance with PPO), and accelerate learning across all tested grid environments. In Pandas-Gym, VLM-CaR rewards improve both success rate and sample efficiency over sparse environment rewards using TQC. In CLIPort, the VLM-CaR generated reward function successfully separates four policies of varying skill (random, novice, sub-optimal, expert), with all policies clearly distinguishable in separating-piles and novice/random clearly separated from sub-optimal/expert in the other two tasks.

## Baselines & Comparisons

The primary baseline throughout the paper is the sparse environment-provided reward (i.e., standard RL training without VLM-CaR auxiliary rewards). VLM-CaR consistently outperforms this baseline across all three environment suites. In MiniGrid (PPO, 1M steps), VLM-CaR rewards produce significantly faster learning and, critically, enable task completion in DoorKey8x8 where the sparse-reward baseline fails entirely. In Pandas-Gym (TQC, 100K steps), VLM-CaR achieves higher success rates at equivalent training budgets and reaches target success rates with fewer samples. In CLIPort (imitation-learning checkpoints), the VLM-CaR reward function acts as a valid performance metric, correctly ordering policies by skill level (random < novice < sub-optimal < expert) across all three robotic tasks. The paper does not compare against other reward-design methods (e.g., CLIP-based cosine similarity rewards, Eureka, or MineCLIP); the sole comparison is VLM-CaR dense rewards versus the original sparse environment reward.

## Relation to Prior Work

This paper departs from the dominant VLM-as-reward-model paradigm (CLIP cosine similarity, fine-tuned Flamingo success detectors, MineCLIP) by instead using a VLM in a zero-shot, reasoning capacity to generate executable Python code that implements reward functions, rather than relying on embedding-space similarity. It also extends the 'code as policies' line of work (Liang et al., 2023) from generating control programs to generating reward programs, and frames the generated sub-task code within the options framework (Sutton et al., 1999), where the VLM produces initiation/termination conditions while RL learns the option policies. A key methodological addition over prior LLM reward-design work (Eureka, Kwon et al.) is the automated verification pipeline using expert and random trajectories to catch false-positive reward scripts before deployment.

## Why It Matters / Open Questions

Reward design remains a major practical bottleneck in deploying RL to real-world tasks, and this paper demonstrates that a $20/month GPT-4 subscription can produce interpretable, verifiable dense reward functions that meaningfully accelerate training in both discrete (MiniGrid) and continuous (Pandas-Gym, CLIPort) settings. However, the approach currently requires manual assembly of VLM-generated scripts into a callable reward class, relies heavily on color and shape identification (limiting applicability to environments with visually distinct objects), and has not been tested in fully automated end-to-end form. Open questions include whether the pipeline scales to environments with visually similar objects (e.g., MetaWorld), whether more advanced image-processing prompts or off-the-shelf detectors can broaden coverage, and whether the options framework can be fully exploited to eliminate the manual assembly step.
