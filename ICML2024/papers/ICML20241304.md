## Problem

Manual heuristic design for combinatorial optimization is labor-intensive and demands rich expert knowledge, while existing LLM-based automatic heuristic design methods like FunSearch evolve only code representations and require on the order of one million LLM queries to produce a competitive heuristic. No prior framework simultaneously evolves high-level linguistic ideas (thoughts) and their executable implementations (codes) in a coordinated evolutionary search, leaving a gap in both efficiency and the ability to reason over the conceptual space of heuristics.
![Teaser figure](../imgs/ICML20241304/cropped_page0_idx2.webp)

## Input / Output

EoH takes a problem description, a set of evaluation instances, and an LLM (GPT-3.5-turbo) as inputs, and produces for each heuristic a short natural-language thought (a few sentences capturing the key logic) paired with a Python function in a pre-defined format specifying the function name, input variables, and output variables so it can be seamlessly integrated into the evaluation harness. Unlike standard evolutionary algorithms that evaluate a single objective on one instance, each heuristic's fitness is computed by running the generated algorithm across a set of problem instances and aggregating the results (e.g., average gap to a lower bound or best-known solution).

## Method

EoH maintains a population of N heuristics, each represented as a triple of (natural-language thought, Python code, fitness value), and evolves both the thoughts and codes simultaneously using LLMs as genetic operators. Five curated prompt strategies drive the search: two exploration strategies (E1 generates heuristics maximally different from selected parents; E2 identifies common ideas among parents and introduces novel components) and three modification strategies (M1 modifies a parent's logic, M2 adjusts parameters, M3 removes redundant components). At each generation, all five strategies are invoked N times to produce up to 5N candidate heuristics, each of which the LLM first describes in natural language and then implements as code; feasible candidates are evaluated on problem instances and the N best are retained via rank-based selection with probability proportional to 1/(rank + N). This thought-code co-evolution with structured prompts achieves state-of-the-art AHD performance using only ~2,000 LLM queries—roughly 500× fewer than FunSearch—while demonstrating strong generalization to out-of-distribution instances.

## Results

On online bin packing, EoH achieves an average gap to the lower bound of 0.80% on 5k-C100 Weibull instances (matching FunSearch) and 0.78% on 5k-C500 (vs. FunSearch's 1.47%), using only ~2,000 LLM queries versus FunSearch's ~1 million. On TSP, the EoH-designed GLS heuristic finds the best-known solutions (0% gap) on 3 of 6 TSPLib instances (pr124, kroA150, u159) and achieves an average gap of 0.11% across all six, outperforming POMO (avg 1.29%) and LEHD (avg 1.34%). On flow shop scheduling, EoH achieves an average gap of 0.23% to Taillard upper bounds across 11 test sets, dramatically outperforming the next-best method PFSPNet_NEH (avg 2.48%) and hand-crafted NEH (avg 2.71%).

## Baselines & Comparisons

On online bin packing, EoH outperforms FunSearch on 5 of 6 instance sets (e.g., 2.13% vs. 6.75% on 1k_C500; 0.78% vs. 1.47% on 5k_C500) while using roughly 500× fewer LLM queries (~2,000 vs. ~1 million); FunSearch wins only on 10k_C100 (0.33% vs. 0.61%). Both hand-crafted First Fit and Best Fit are consistently outperformed by EoH across all six instance sets. On TSP, EoH's GLS heuristic dominates all neural solvers (AM, POMO, LEHD) and hand-crafted methods (NI, FI, Or-Tools) on all six TSPLib instances, finding optimal solutions where POMO achieves 0.60% and LEHD 1.11% on pr124. On flow shop scheduling, EoH achieves gaps of 0.10–0.61% across all Taillard test sets, outperforming the strongest baseline PFSPNet_NEH (1.72–5.05%) by a factor of 3–8×, and hand-crafted NEH/NEHFF (1.88–5.48%) by an even wider margin. The ablation study further confirms that evolving both thoughts and codes (vs. code-only EoC) and using all five prompt strategies (vs. E1-only) are both critical for achieving these results.

## Relation to Prior Work

EoH builds directly on FunSearch (Romera-Paredes et al., 2024), which established the paradigm of using LLMs within an evolutionary loop to search over code space for heuristic functions. The key departure is twofold: EoH introduces a dual representation where each heuristic carries both a natural-language 'thought' and executable code, and it employs five explicit prompt strategies (two exploration, three modification) that guide the LLM's reasoning over parent heuristics, rather than relying on code-only mutation/crossover. This positions EoH as a more structured and efficient instantiation of the LLM+EC framework for Automatic Heuristic Design, connecting to the broader hyper-heuristic and genetic programming literature while avoiding the need for hand-crafted primitives or domain model training.

## Why It Matters / Open Questions

The ~500× reduction in LLM queries (≈2,000 vs. ≈1 million for FunSearch) makes LLM-assisted heuristic design far more practical and accessible, potentially democratizing automatic algorithm design for practitioners without large compute budgets. The conceptual contribution of co-evolving thoughts and codes as complementary views of a heuristic opens a new axis of search that neither pure code evolution nor pure text evolution captures. Open questions include whether the approach scales to larger or more complex problem classes, whether domain-specific LLMs would further improve results, how to formally characterize the heuristic search space, and how to integrate human expert feedback into the evolutionary loop.
