## Problem

Code language models trained with fill-in-the-middle (FIM) objectives acquire infilling capabilities, yet most generation systems still rely on strictly left-to-right decoding, leaving this bidirectional context ability largely untapped at inference time. It remains unclear how the acquired infilling proficiency can be leveraged to improve complete code generation beyond narrow partial-completion tasks, and how to integrate it into a practical decoding pipeline without additional training.

## Input / Output

The method takes a standard code prompt (function signature plus docstring) and a short suffix prompt string (e.g., 'return' for Python functions, or a variable name for DS-1000) as input, and produces a complete generated function or program. Unlike conventional left-to-right decoding, the generation is non-monotonic: the model can interrupt mid-sequence, pivot to suffix generation, and then infill the skipped middle. During the looping phase, left-to-right outputs must be heuristically parsed back into the (prefix, middle, suffix_p, suffix_c) quadruple since sentinel tokens are absent in plain left-to-right decodes, with three splitting strategies (Vanilla, Extended, Half) explored for this segmentation.

## Method

The core insight is that FIM training inherently endows causal decoder-only models with a self-infilling capability: the model can generate a suffix conditioned only on the prefix (marginalizing over the middle), then infill the middle given both self-generated contexts. The paper builds two mechanisms on top of this. First, an interruption mechanism monitors next-token probability during left-to-right decoding; when the max probability drops below a threshold τ, decoding is suspended, a suffix is generated (constrained to begin with a suffix prompt token via logit override), and the middle is infilled — an easy-first strategy that defers uncertain tokens and scaffolds the output with a definitive suffix anchor. Second, a looping mechanism alternates between self-infilling and left-to-right decoding for N iterations, where each pass re-generates the suffix with the expanded context (now including the infilled middle) and re-infills the middle with the updated suffix, analogous to piece-wise Gibbs sampling over the four context segments. The entire framework is a pure inference-time decoding strategy requiring no additional training, applied to existing FIM-trained models such as StarCoder, Code Llama, and DeepSeek-Coder.

## Results

On HUMANEVAL (zero-shot), self-infilling with looping (N=2) improves pass@1 by 4.6–4.9 points over left-to-right decoding across all evaluated models: CODE LLAMA 7B (34.1→39.0%), CODE LLAMA 13B (35.4→40.8%), STARCODER 15.5B (35.4→38.4%), and STARCODERBASE 15.5B (31.7→36.0%). On MBPP (three-shot), gains are 1.0–2.8 points in pass@1 (e.g., CODE LLAMA 13B: 47.2→49.0%). The looping mechanism scales with iterations N, and at N=2 the method also reduces degenerate outputs (e.g., from ~13% to 2.4% for CODE LLAMA 7B at τ=0.25).

## Baselines & Comparisons

Self-infilling with looping (N=2) consistently outperforms the left-to-right baseline across all four model families on both HUMANEVAL and MBPP, with the largest gains on STARCODERBASE (+4.3 pass@1 on HUMANEVAL) and CODE LLAMA 7B (+4.9). Compared to external baselines, CODE LLAMA 7B with self-infilling (39.0%) surpasses CODE LLAMA-INSTRUCT 7B (34.8%) and CODE LLAMA-PYTHON 7B (38.4%) on HUMANEVAL pass@1, suggesting that decoding-time self-infilling can match or exceed the benefits of instruction tuning or domain-specific pre-training. CODE LLAMA 13B with self-infilling (40.8%) also exceeds CODE LLAMA-INSTRUCT 13B (42.7% is slightly higher, so it is a near-tie) and CODE LLAMA-PYTHON 13B (43.3% is higher). However, the method remains well below proprietary models: GPT-3.5 Turbo (72.6%) and GPT-4 Turbo (88.4%) lead by a wide margin on HUMANEVAL pass@1. On DS-1000, self-infilling narrows the gap between left-to-right completion and the insertion mode (which uses official suffixes), e.g., CODE LLAMA 13B improves from 30.3% to 33.1% overall, approaching the insertion baseline of 34.4%.

## Relation to Prior Work

This paper builds on the Fill-In-the-Middle (FIM) training objective (Bavarian et al., 2022) used in models like StarCoder and Code Llama, but departs from prior infilling work by identifying an overlooked inference-time property: FIM-trained models can autonomously generate a suffix from a prefix alone (self-infilling), not just fill a gap given both contexts. Rather than proposing a new training objective or architecture (as InCoder, GLM, or causal masking approaches do), the paper repurposes the existing FIM capability to construct a non-monotonic decoding process with interruption and looping mechanisms. It also contrasts with self-improvement frameworks (Self-Refine, Self-Debug) by operating purely through in-place context updates without external tools or verbal feedback.

## Why It Matters / Open Questions

The practical takeaway is that FIM-trained code models can be substantially improved at inference time without any retraining, simply by changing the decoding strategy. The interruption mechanism reduces degenerate outputs (e.g., from 13% to 2.4% for Code Llama 7B), and the looping mechanism scales with model size, yielding up to 9% absolute pass@1 gains on DeepSeek-Coder-33B. Key limitations include the computational overhead of repeated context processing, the restriction to single-span infilling, and the finding that the approach does not transfer well to instruction-tuned models. Open directions include multi-span/nested infilling, KV-cache optimization across loop iterations, and extending the framework to mathematical reasoning and grammar-constrained generation.
