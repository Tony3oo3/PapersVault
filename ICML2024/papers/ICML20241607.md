## Problem

Deploying multiple LLMs of varying sizes (e.g., for latency-adaptive serving or speculative decoding) incurs prohibitive memory overhead and requires training or distilling separate model versions. The prior any-precision DNN concept, which derives lower-bit models by truncating MSBs of a parent model, relies on quantization-aware training from scratch and uses bitpacking-based GPU kernels that cannot reduce memory bandwidth at lower bit-widths—making it impractical for memory-bound LLM inference.

## Input / Output

The method consumes a pre-trained LLM's FP16 weights and produces a single n-bit parent model stored in a bitplane layout (n separate bit-vectors per weight) plus small centroid tables for each supported bit-width (e.g., 3, 4, 8-bit). At inference, the engine accepts a runtime bit-width request and loads only the corresponding subset of bitplanes and centroid table, so the same memory footprint serves all supported precisions. The quantization process itself runs in under a minute on a 24-core CPU for 7B-scale models, requiring no training data or gradient updates.

## Method

The quantization method, called incremental upscaling, first generates a 3-bit seed model using SqueezeLLM's clustering-based non-uniform quantization, then adds one bit at a time by splitting each existing cluster into two sub-clusters via weighted K-means, preserving the any-precision property that lower-bit models are exact MSB prefixes of the parent. The specialized GPU kernel stores weights in a bitplane representation so that a k-bit request loads only k of the n bitplanes, directly reducing memory bandwidth proportionally. Three kernel optimizations address the resulting inefficiencies: a byte-permutation of bitplanes to restore coalesced activation access, a SIMD-style bit-transpose algorithm (40 bitwise ops vs. 76 for the standard 8×8 transpose), and centroid table lookup merging that halves table accesses at 3-bit by packing adjacent indices into a single 6-bit lookup.

## Results

The incremental upscaling approach (SqLLM+IU) achieves perplexity within 0.1 of independently quantized SqueezeLLM models across Llama-2-7B, Mistral-7B, and OPT models at 4–8 bits (e.g., Llama-2-7B 4-bit: 5.62 vs. 5.61 on WikiText2). Zero-shot accuracy drops are within 0.2% on average across five tasks. The specialized kernel achieves up to 3.84× speedup over cuBLAS FP16 at 3-bit on RTX 4090, matching SqueezeLLM's kernel on desktop GPUs and substantially outperforming it on Jetson AGX Orin (3.84× vs. 3.15× at 3-bit). Memory savings reach up to 3.56× when supporting all bit-widths from 3 to 8 for Llama-2-7B.

## Baselines & Comparisons

Against SqueezeLLM (the backbone quantization method), SqLLM+IU matches perplexity within 0.1 in nearly all cases and zero-shot accuracy within 0.2%, confirming that incremental upscaling preserves quality without retraining. Against the SqueezeLLM GPU kernel, the paper's bitplane-based kernel performs on par on RTX 4090 and RTX 4070 Laptop (e.g., 3.99× vs. 3.69× at 3-bit on 4096×4096) but achieves substantial improvements on Jetson AGX Orin (3.84× vs. 3.15× at 3-bit), where limited cache and compute make the optimizations more impactful. Against uniform quantization kernels (ExLlamaV2, LUT-GEMM, AWQ, TensorRT-LLM), the paper's kernel achieves the best or near-best latency in the majority of configurations across all three GPUs (Table 10), despite the added complexity of supporting non-uniform quantization and any-precision. The paper also demonstrates that incremental upscaling is fundamentally incompatible with uniform quantization methods: applying it to GPTQ causes perplexity to explode (e.g., 36.82 at 4-bit vs. 5.71 for vanilla GPTQ on Llama-2-7B), and AWQ+IU produces infinite perplexity at 4-bit, motivating the choice of clustering-based non-uniform quantization as the backbone.

## Relation to Prior Work

This paper extends the any-precision DNN concept from Yu et al. (2021), which relied on quantization-aware training for CNNs, to LLMs by replacing QAT with a post-training quantization (PTQ) pipeline built on SqueezeLLM's clustering-based non-uniform quantization. The key methodological departure is 'incremental upscaling'—starting from a low-bit seed model and adding bits one at a time via weighted K-means sub-clustering—rather than training from scratch. On the systems side, the paper departs from the bitpacking-based weight representations used by existing quantized GEMM kernels (ExLlamaV2, LUT-GEMM, AWQ, TensorRT-LLM) in favor of a bitplane-based layout that enables runtime bit-width selection without reloading the full parent model.

## Why It Matters / Open Questions

The paper addresses a practically important but underexplored deployment scenario: serving multiple LLM sizes on memory-constrained devices (desktops, mobile) without the cost of training or storing separate models, with up to 3.56× memory savings when supporting all bit-widths from 3 to 8. A notable limitation is that the kernel does not use tensor cores, making it slower than cuBLAS FP16 during the prefill phase for large batch sizes, which the authors mitigate with a dequantize-then-cuBLAS fallback. Open questions include whether the approach extends to activation quantization, whether it remains effective for much larger models (70B+), and whether the bitplane layout's overhead becomes prohibitive on next-generation hardware with wider memory buses.
