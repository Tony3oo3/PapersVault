## Problem

Existing code LM benchmarks like HumanEval and MBPP evaluate code generation from natural language specifications but do not measure a model's ability to understand and trace through code execution. This paper identifies that high HumanEval scores (e.g., WizardCoder, Phind, Phi distilled from GPT-4 data) do not translate to better code execution or reasoning, revealing a critical blind spot in how code LMs are evaluated.

## Input / Output

Each benchmark sample is a short Python function (3–13 lines, 75–300 characters) using only str, list, or dict standard library methods, paired with a concrete input-output pair. For output prediction (CRUXEval-O), the model receives the function and input and must produce the exact execution result; for input prediction (CRUXEval-I), it receives the function and output and must produce any valid preimage. Correctness is verified by execution via assert statements, and the functions are constrained to be deterministic, side-effect-free, and free of floating-point or complex arithmetic so that a human could solve them without extra memory.

## Method

The benchmark is constructed via a three-stage generate-and-filter pipeline: (1) Code Llama 34B is prompted with 69 standard library function names (47 str, 11 dict, 11 list) plus two few-shot examples to produce 102,000 candidate functions and 489,306 input-output pairs; (2) candidates are filtered for simplicity (no imports, no floating point, integer args ≤ 3, string/list args length ≤ 3, deterministic, runs in < 2 s); (3) 800 samples are selected using bootstrap noise analysis to ensure statistically reliable model comparisons. The paper then evaluates 20 models (Code Llama, StarCoder, WizardCoder, Phi, Phind, DeepSeek, Mistral, GPT-3.5, GPT-4) with pass@1 (T=0.2) and pass@5 (T=0.8), and investigates chain-of-thought prompting and fine-tuning on ~140K distilled assertions. A key finding is that CoT substantially boosts GPT-4 (to 75%/82% pass@1 on input/output prediction) but provides minimal gains for open-source models, and that fine-tuning plateaus well below 70% test accuracy even when trained on benchmark-identical programs.

## Results

GPT-4 with chain-of-thought (CoT) achieves the best performance on CRUXEval, reaching 74.8% pass@1 on input prediction and 81.9% pass@1 on output prediction. Without CoT, GPT-4 scores 67.1% and 63.4% respectively, while the best open-source model, Code Llama 34B, achieves only 46.5% and 41.1% pass@1. CoT provides the largest absolute boost for GPT-4 (+7.7% input, +18.5% output) compared to other models, where gains are modest (e.g., Code Llama 34B gains +3.9% input, +4.9% output). All models except GPT-4 have over 50% failure rate on at least one task.

## Baselines & Comparisons

GPT-4 dominates all baselines by a wide margin, achieving 67.1%/63.4% pass@1 (input/output) without CoT and 74.8%/81.9% with CoT, far exceeding the best open-source model. Among open-source models, DeepSeek Coder-Instruct 33B (47.4%/44.0%) and Phind v2 34B (47.9%/38.3%) slightly edge out Code Llama 34B (46.5%/41.1%) on input prediction, while DeepSeek Coder-Base 33B (43.6%) leads on output prediction. A striking finding is that distilled models WizardCoder 34B (42.8%/41.2%) and Phind v2 (47.9%/38.3%) score over 20% higher than Code Llama 34B on HumanEval yet show no corresponding improvement on CRUXEval, suggesting their gains are task-specific rather than reflecting general code reasoning. Phi-1 (13.9%/23.3%) performs among the worst despite high HumanEval scores, further confirming this disconnect. For base models (StarCoder, Code Llama, DeepSeek-Base, Mistral), a positive correlation between HumanEval and CRUXEval scores is observed, indicating that code generation and execution/understanding abilities are linked in non-distilled settings.

## Relation to Prior Work

This paper carves out a new evaluation dimension for code LMs by introducing CRUXEval, which tests code execution (output prediction) and code reasoning (input prediction) rather than the code generation from natural language specifications that dominates existing benchmarks like HumanEval and MBPP. While prior work (Austin et al. 2021, Scratchpad, CodeExecutor) has trained models on execution information, CRUXEval is positioned as the first publicly available benchmark specifically measuring these capabilities. The benchmark construction follows a generate-and-filter recipe using Code Llama 34B, drawing on the statistical noise analysis methodology to justify its 800-sample size. The paper also connects to the broader literature on LM reasoning failures and the 'reversal curse,' using code execution as a concrete testbed for understanding where and why models break down.

## Why It Matters / Open Questions

CRUXEval reveals a critical blind spot in current code LM evaluation: models distilled from GPT-4 data (WizardCoder, Phind, Phi) achieve impressive HumanEval scores but show no improvement in code execution or reasoning over their base models, challenging the assumption that distillation transfers general code understanding. The finding that even GPT-4 with CoT consistently fails on simple Python programs (e.g., miscounting string operations, failing basic comparisons) suggests that execution ability is a fundamentally different skill from code generation. Open questions include whether more sophisticated fine-tuning (process supervision, execution-state conditioning) can close the gap, whether improved execution ability transfers to better code generation, and whether the generate-and-filter recipe can be extended to longer, multi-language, or more complex programs.
