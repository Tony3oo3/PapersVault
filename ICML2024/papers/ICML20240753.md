## Problem

Despite strong performance on code completion benchmarks like HumanEval and MBPP, it remains unclear whether Large Code Models actually understand the logical constructs of the programs they manipulate. Task-driven evaluations measure end-to-end accuracy but cannot attribute failures to specific programming concepts such as control flow, data flow, or identifier naming, leaving practitioners without fine-grained diagnostic information about model limitations.

## Input / Output

CACP requires only hard-label black-box access to the model (no logits, no fine-tuning, no additional training data). It takes a partial program prefix and a natural-language instruction, generates a counterfactual pair by applying a predicate-specific mutation to the reference solution and cutting both at the same location, then queries the model on both inputs. The output is a per-program Mutation Effect (binary: whether unit-test correctness changed) and an aggregated Average Mutation Effect (AME) per PCP, where lower AME indicates better concept understanding.

## Method

CACP generates counterfactual programs through four minimal mutations, each targeting exactly one Programming Concept Predicate: If-Else Flip (negating the condition and swapping branches), Independent Swap (reordering data-flow-independent statement blocks), Def-Use Break (renaming a variable's second definition chain to a random string), and Variable-Name Invariance (renaming or shuffling variable names). Both the original and mutated reference solutions are cut at the same position (typically retaining the first 75% as prefix) to form a matched counterfactual input pair, and both mutated solutions are verified to pass the original test suite. The Mutation Effect for a single program is the absolute difference in unit-test pass/fail between the model's completions on the original and counterfactual inputs; the Average Mutation Effect across all valid programs quantifies the model's understanding of that PCP. This design ensures specificity (each mutation perturbs only one concept), correctness (counterfactuals remain solvable), and validity (perturbations are syntactically and semantically natural), enabling causal attribution of model failures to specific programming concepts without any model adaptation.

## Results

Across ten LLMs evaluated on HumanEval+MBPP and CodeContests, GPT-4 achieves the lowest AMEs, ranging from 1.57% (Independent-Swap) to 7.21% (Variable-Names Shuffle) on HumanEval+MBPP, and 5.05%–21.58% on CodeContests. In contrast, smaller general-purpose models like Llama 2 (7B) show AMEs as high as 34.07% (DefUse-Break on CodeContests) and 29.08% (Variable-Names Shuffle on HumanEval+MBPP). The Variable-Names and IfElse-Flip mutations produce the largest accuracy drops (up to 33% AME), while Independent-Swap is the most well-understood PCP (AME as low as 1.57% for GPT-4). Code-specific fine-tuning (Code Llama, PaLM 2-S*, StarCoder) consistently reduces AME for variable-name mutations compared to their base counterparts.

## Baselines & Comparisons

GPT-4 dominates on HumanEval+MBPP, achieving AMEs of 6.43%–7.21% for variable-name mutations and 5.95% for If-Else Flip, substantially outperforming the next-best models (Code Llama 34B at 12.55%–15.14% and PaLM 2-S* at 12.31%–19.74%). However, on CodeContests, GPT-4's advantage narrows: its DefUse-Break AME (21.58%) is comparable to Llama 2 70B (26.04%) and Code Llama 34B (26.60%), suggesting the harder contest-level problems stress even the strongest model. Code-specific fine-tuning consistently helps for variable-name invariance: Code Llama 34B (12.55%/15.14%) outperforms Llama 2 70B (14.37%/19.81%), and PaLM 2-S* 24B (12.31%/19.74%) outperforms PaLM 2 64B (23.75%/22.58%). Model size matters: within the Llama 2 family, AME for Variable-Names Shuffle drops from 29.08% (7B) to 19.81% (70B) on HumanEval+MBPP. StarCoder, despite being a 13B code-specific model, performs mid-pack, with AMEs of 16.86%–21.07% on HumanEval+MBPP, indicating that code pre-training alone does not guarantee strong PCP understanding without sufficient scale.

## Relation to Prior Work

This paper extends the counterfactual analysis framework from Abid et al. (2022) — originally designed for debugging NLP model mistakes — to the domain of code, introducing predicate-specific mutations grounded in classical program analysis (def-use chains, data-flow, control-flow). It departs from prior robustness studies of code models (Shirafuji et al., 2023; Henkel et al., 2022) by ensuring mutations are minimal and isolate a single programming concept, rather than applying arbitrary semantic-preserving transformations. Unlike Cito et al. (2022), which used counterfactuals for explaining individual predictions via syntactic perturbations, CACP targets concept-level understanding and works in a hard-label black-box setting without requiring token-level probability access (unlike Palacio et al., 2023a,b).

## Why It Matters / Open Questions

CACP provides the first systematic, fine-grained diagnostic for attributing code LLM failures to specific programming concepts rather than vague end-to-end accuracy drops, enabling practitioners to identify exactly which predicates a model struggles with. The finding that code-specific fine-tuning improves variable-name understanding but not control-flow or data-flow understanding suggests that current training data distributions do not adequately cover these concepts, pointing toward targeted data augmentation as a future direction. Limitations include the restriction to Python, reliance on test-based attribution (excluding datasets without unit tests), and the small number of valid DefUse-Break instances (22 on HumanEval+MBPP), which limits statistical confidence for that mutation.
