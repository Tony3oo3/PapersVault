## Problem

Real-world tabular datasets frequently contain missing values, and naively cleaning them before training is expensive and may be unnecessary if predictions are invariant to how missing cells are imputed. This paper asks whether, for Naive Bayes classifiers, one can efficiently certify that a test point's prediction is the same across all exponentially many possible worlds (completions) of an incomplete dataset, and conversely, how few cells an adversary must corrupt to NULL to break that robustness.

## Input / Output

The Decision Problem takes an incomplete tabular dataset D^□ (categorical features over a shared domain U containing NULL, with all points labeled) and one or more complete test points, and returns a boolean indicating whether every test point is certifiably robust. The Data Poisoning Problem takes a complete dataset D and k test points, and returns a poisoned dataset D† with the minimum number of cells set to NULL such that all k test points become certifiably non-robust. All continuous features are pre-discretized into 5 equal-width bins, and the closed-world semantics restrict imputation to values already observed in the dataset.

## Method

For the Decision Problem, the key insight is that for NBC the maximum (resp. minimum) support value of a test point for label l over all possible worlds is attained by imputing every NULL cell to agree with (resp. disagree with) the test point on that attribute, yielding closed-form expressions S↑(l|t) and S↓(l|t) computable in O(nd+md) time; robustness holds iff S↓(l|t) > max_{l'≠l} S↑(l'|t). An indexing structure over attribute-value frequencies extends this to k test points in O(nd+kmd). For single-point Data Poisoning, the problem reduces to AlterPrediction, solved by a provably optimal greedy algorithm that iteratively applies either operation A1 (increase Pr(t|l) by altering the least-frequent matching attribute) or A2 (decrease Pr(t|l*) by altering the least-frequent matching attribute), choosing whichever drives the support gap Δ negative in fewer steps, running in O(nmd). For multiple test points, the problem is NP-complete for d≥3 via a reduction from Vertex Cover on d-regular graphs, and a heuristic that unions the per-point optimal poisonings is provided.

## Results

For the Decision Problem, the proposed Iterate+Index algorithm is approximately 20× faster than the Iterate baseline (Ramoni & Sebastiani, 2001) when checking 16 test points, and its running time remains nearly constant as the number of test points increases (vs. linear growth for baselines). For the Data Poisoning Problem, the Greedy Search (GS) algorithm is provably optimal for a single test point, achieving the minimum poisoning rate across all datasets, and is significantly faster than Random Poisoning (RP) and marginally faster than Smarter Random Poisoning (SR). The Data Poisoning Problem is shown to be NP-complete for multiple test points on datasets with ≥3 features. Experiments span 10 real-world Kaggle datasets ranging from 918 rows (Heart) to 568,630 rows (Credit Card) with 8–96 features.

## Baselines & Comparisons

The primary baseline is the Iterative Algorithm from Ramoni & Sebastiani (2001), which computes min/max support values per test point without indexing. The paper's Iterate+Index method outperforms it by ~20× for 16 test points (Figure 2) and ~10× at 16 points (Figure 3), while maintaining near-constant running time as test points increase. The Approximate Decision (AD) baseline, which samples 100 random possible worlds, is much slower and provides no correctness guarantee (can return false positives). For the Data Poisoning Problem, GS (the paper's optimal greedy algorithm) dominates both RP (random cell selection) and SR (random A1/A2 operations) in both running time and poisoning rate across all 10 datasets. GS achieves the minimum number of poisoned cells for single test points by construction, while RP and SR always require more cells. For multiple test points, GS is applied iteratively per point (Algorithm 4) as a heuristic, since the problem is NP-complete; it still outperforms RP and SR in practice.

## Relation to Prior Work

This paper extends the min/max support value framework for Naive Bayes over incomplete data introduced by Ramoni & Sebastiani (2001) into a formal certifiable robustness setting, connecting the ML robustness literature (certified defenses for kNN, SVM, decision trees) with the database incomplete-data literature (possible worlds, closed-world semantics, consistent query answering). It departs from prior data poisoning work, which focuses on adversarial perturbations to model inputs or training labels, by instead studying poisoning via the insertion of missing values (NULL cells) into a clean dataset. The data cleaning literature (SampleClean, ActiveClean, BoostClean) provides the motivation: the paper asks whether cleaning can be skipped entirely when predictions are provably invariant to how missing values are imputed.

## Why It Matters / Open Questions

The practical implication is that for NBC-based pipelines, one can certify in O(md + nd) time—matching the cost of training itself—that a test point's prediction is invariant to all possible imputations of missing values, potentially saving expensive data cleaning. The NP-completeness result for multi-point poisoning (via a Vertex Cover reduction) cleanly delineates the boundary between tractable and intractable settings. However, the results are restricted to Naive Bayes, and the authors themselves identify extending to random forests, gradient-boosted trees, and general classifiers as the key open question. The experimental finding that poisoning rates are often non-trivial (requiring many cell modifications) suggests that certifiable robustness, while useful, does not eliminate the need for data cleaning in most practical scenarios.
