## Problem

Deploying LLMs across diverse hardware budgets typically requires training multiple model variants from scratch, which is prohibitively expensive in time, data, and compute. Existing elastic architectures like Matformer only support nested MLP layers, and Mixture-of-Experts networks are restricted to feedforward layers with fixed activation budgets, leaving no mechanism to jointly adapt both attention and MLP capacity per-layer based on a user-specified latency target and input difficulty.
![Teaser figure](../imgs/ICML20240206/cropped_page0_idx0.webp)

## Input / Output

The framework takes a fully pre-trained LLM (GPT-3-2B/8B or Llama-2-7B) and a scalar latency target T as input, and produces a single elastic model that at inference time routes each token through a per-layer sub-network (selecting a subset of attention heads and MLP channels) to generate text. The dynamic variant conditions routing on both the latency target and the current hidden state, so different tokens within the same sequence can traverse different sub-network widths. Latency is measured end-to-end via TensorRT-LLM on A100 GPUs with prompt length 8 and generation length 512.

## Method

FLEXTRON introduces a nested elastic structure for both MLP and MHA layers, where K candidates per layer share a single weight matrix and are instantiated by slicing the first d_j rows (MLP) or first d_j heads (MHA), with d_1 < d_2 < ... < d_K. Before continued-tuning, neurons and heads are permuted by activation-magnitude importance so that any prefix of the matrix retains the most critical channels. Elastic continued-tuning randomly samples k sub-networks from the K^N candidate pool at each step and optimizes them jointly with gradient accumulation, requiring only ~7.63% of original pretraining tokens. To train routers without suffering gradient vanishing, the paper introduces a Surrogate Model—a small two-layer MLP that predicts the full LLM's language loss from router logits alone; once its MSE falls below a threshold, routers are updated via SM gradients plus a latency-constraint loss (Eq. 8). The final system supports both static routing (latency-only) and input-adaptive routing (latency + hidden state), enabling per-token sub-network selection that allocates more compute to harder inputs.

## Results

On the Llama-2-7B backbone, FLEXTRON's input-adaptive (Dynamic) router at 0.7× latency achieves 63.1% average across six downstream benchmarks with only 4.1B non-embedding parameters, outperforming the full 6.5B model's 69.1% by retaining 91% of its performance at 30% less compute. On GPT-3-8B, the Dynamic-0.7× variant reaches 62.0% average with 4.3B parameters. The entire FLEXTRON conversion (elastic continued-tuning + router tuning) consumes only 7.63% of the original pretraining tokens (89.9B + 1.049B out of 1.1T for GPT-3).

## Baselines & Comparisons

FLEXTRON-Llama2-7B Dynamic-0.7× (4.1B params, 63.1% avg) outperforms OpenLLaMA-3Bv2 (3.2B, 60.3%) by 2.8 points and Sheared-LLaMA-2.7B (2.5B, 62.1%) by 1.0 point, while using fewer parameters than both. Against Pythia-6.9B (6.4B, 55.4%), FLEXTRON's 0.7× variant wins by 7.7 points with 2.3B fewer parameters. On the GPT-3-8B backbone, FLEXTRON Dynamic-0.7× (62.0%) exceeds OpenLLaMA-3Bv2 (60.3%) by 1.7 points. The full FLEXTRON models closely match their base LLMs (69.1% vs. 69.2% for Llama-2-7B; 66.8% vs. 68.0% for GPT-3-8B), confirming that elastic continued-tuning preserves full-model performance. In the Pareto scaling-law comparison (Figure 5), FLEXTRON dominates Matformer across all latency regimes, with the input-adaptive variant achieving the lowest validation loss at every parameter count, and even outperforming the end-to-end-trained GPT-3-843M model.

## Relation to Prior Work

FLEXTRON extends the nested elastic network paradigm from Matformer (which applies elasticity only to MLP layers) to both MLP and Multi-Head Attention layers, creating a richer candidate operation space. It draws on Matryoshka representation learning for the shared-weight slicing mechanism and on Mixture-of-Expert routing (Switch Transformers, Pathways) for input-adaptive sub-network selection, but departs from MoE by using heterogeneous nested experts with weight sharing rather than separate expert parameters. The post-training conversion framework—transforming an already-trained LLM into an elastic network via importance-based permutation and sample-efficient continued tuning—is a key departure from prior elastic networks (Once-for-All, SortedNet) that require costly from-scratch training of a supernet.

## Why It Matters / Open Questions

FLEXTRON offers a practical path to deploying a single LLM across heterogeneous hardware budgets without retraining, which is directly relevant to production systems serving diverse user devices. The 7.63% training token cost relative to full pretraining makes the approach accessible, and the fitted scaling-law parameters give practitioners a quantitative guideline for choosing sub-networks under joint latency/parameter/accuracy constraints. Open questions include whether the approach scales cleanly to 70B+ parameter models, how well the surrogate model generalizes across very different latency regimes, and whether the importance-based permutation strategy remains effective for architectures with more complex attention variants (e.g., grouped-query attention). The paper does not explore interaction with quantization or sparsity, which are orthogonal compression axes likely to be combined in practice.
