## Problem

Serving LLM inference in a single centralized datacenter with homogeneous high-performance GPUs is prohibitively expensive, yet deploying inference across heterogeneous, cross-datacenter GPU pools has not been fully explored. Existing inference frameworks (e.g., FlashAttention, HuggingFace Accelerate) assume homogeneous GPU clusters and enforce symmetric parallelism, making them unable to exploit diverse GPU compute capacities or navigate the exponentially larger space of allocation strategies introduced by heterogeneous inter-GPU connections.
![Teaser figure](../imgs/ICML20240881/cropped_page2_idx0.webp)

## Input / Output

The system consumes a text prompt (with specified input sequence length s_in and output sequence length s_out) along with a pool of heterogeneous GPUs characterized by per-device memory limits, memory bandwidth, tensor-core FLOPS, and a full pairwise latency/bandwidth communication matrix. It produces generated text tokens and an optimal GPU allocation layout specifying which subset of GPUs serves each pipeline stage, how many transformer layers each stage holds, and what tensor-parallelism degree each stage uses. The scheduling is formulated as a constrained optimization problem maximizing expected SLO attainment subject to per-device memory constraints.

## Method

HEXGEN introduces asymmetric parallel execution where each pipeline stage can independently be assigned a different number of transformer layers and a different tensor-parallelism degree, breaking the symmetry constraint of prior systems. The scheduling algorithm operates in two phases: a dynamic programming procedure (with a heuristic restricting TP groups to same-type GPUs on the same machine, reducing complexity from O(S_i·2^|d|) to O(S_i·∏#_k)) finds the optimal stage-to-GPU assignment for a given pipeline group, and a genetic algorithm with constrained mutations (merge, split, swap) searches over the global partition of the GPU pool into independent pipeline groups. The cost model decomposes inference time into memory-scan cost, matrix-multiplication FLOPS cost, TP AllReduce communication (modeled via the BSP superstep model), and PP point-to-point communication (modeled via the α-β model using the fastest inter-stage link), all subject to per-GPU memory footprint constraints.

## Results

Serving LLAMA-2 (70B) under the same cloud budget (~$65/hr), HEXGEN on a heterogeneous GPU pool achieves up to 2.3× lower latency deadlines and handles up to 4× higher peak request rates (2× on average) compared to FlashAttention on homogeneous A100 GPUs. At half the budget (~$29.6/hr), HEXGEN still matches the homogeneous baseline's SLO attainment. Against the decentralized Petals system, HEXGEN achieves up to 3.5× lower latency deadlines and tolerates up to 10× higher request rates. The asymmetric parallelism implementation alone contributes up to 1.8× lower latency and 2× higher peak traffic over a symmetric parallel baseline.

## Baselines & Comparisons

Against FlashAttention (Dao, 2023) on homogeneous A100 GPUs, HEXGEN on heterogeneous GPUs wins decisively: up to 2.3× lower latency deadlines and 4× higher peak request rate at the same budget, and at half the budget HEXGEN still matches the homogeneous SLO attainment. Against HuggingFace-TGI (the state-of-the-art homogeneous serving system), HEXGEN achieves up to 1.25× lower latency deadlines while handling the same request rates, though the paper acknowledges that HEXGEN's lack of advanced batching limits its full potential here. Against Petals (the state-of-the-art decentralized inference system), HEXGEN dominates with up to 3.5× lower latency deadlines and 10× higher request rates, attributed to Petals' reliance on dynamic swarm parallelism versus HEXGEN's static scheduling. The ablation removing asymmetric parallelism (keeping only the scheduling algorithm) shows a 1.8× latency gap and 2× peak-rate gap versus full HEXGEN, confirming both components are necessary.

## Relation to Prior Work

This paper extends FlashAttention's inference framework by introducing asymmetric tensor model parallelism and pipeline parallelism, departing from the homogeneous-GPU-cluster assumption that underpins systems like HuggingFace Accelerate, FasterTransformer, and AlpaServe. For scheduling, it formulates a constrained optimization problem combining dynamic programming (for per-pipeline stage layout) with a genetic algorithm (for global GPU partition), drawing on the alpha-beta and BSP communication cost models. It contrasts with Petals, the closest prior decentralized inference system, by replacing Petals' dynamic swarm-parallelism coordination with a static, pre-computed scheduling approach that exploits heterogeneous GPU capacities and network topologies.

## Why It Matters / Open Questions

The practical impact is significant: at the same cloud budget, HEXGEN achieves up to 2.3× lower latency or handles 4× more requests than a homogeneous A100 datacenter, and at half the budget it still matches homogeneous performance—strong evidence that heterogeneous, cross-datacenter deployment can democratize LLM inference. A key acknowledged limitation is the absence of continuous batching, which the authors note is non-trivial under heterogeneous pipeline groups with divergent execution times and memory limits. Open questions include whether the static scheduling approach generalizes to highly dynamic GPU pools (beyond the 4-GPU offline test), how the cost model holds under quantized or sparse model variants, and whether the genetic algorithm's convergence guarantees extend to much larger GPU pools with more GPU types.
