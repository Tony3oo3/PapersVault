## Problem

Large collections of specialized PEFT models (e.g., LoRA adapters) are widely available, but existing post-hoc routing methods either retrieve a single expert for the entire query or uniformly merge all experts, failing to exploit the possibility that different experts may be useful for different tokens at different layers. This paper asks whether adaptive per-token, per-module routing among specialized experts can improve zero-shot generalization without requiring simultaneous access to the datasets used to train each expert.
![Teaser figure](../imgs/ICML20241496/cropped_page0_idx0.webp)

## Input / Output

The method takes a standard text prompt as input and produces generated text as output, operating on LM-adapted T5.1.1 XL (3B parameters). During inference, routing decisions are made independently at every linear layer where PEFT modules are inserted and for every token position, with top-k=2 modules selected per activation. The base model's output is augmented by the weighted sum of the selected expert modules' contributions at each layer, so the output format is identical to the base model's text generation.

## Method

PHATG00SE introduces a post-hoc gating step: after a contributor trains a LoRA module on their task, they freeze all parameters and train a single sigmoid gate vector (v ∈ R^n) in front of each module for 100 steps using the same dataset and objective. At inference, the gate vectors from all experts are standardized, and for each token activation at each layer, cosine similarity scores are computed between the standardized activation and every expert's standardized gate vector. Top-k (k=2) routing selects the highest-scoring modules, whose outputs are scaled by softmax-normalized weights (with 1/√n temperature) and added to the base model's linear output. The key insight is that the gate vector, trained with the module frozen, learns to encode activation patterns characteristic of its task, enabling the router to compose capabilities from multiple specialized experts on a per-token, per-module basis rather than committing to a single expert for the entire input.

## Results

On the T0 Held-In setting (36 experts), PHATG00SE achieves 56.9 on T0HO, nearly matching the Oracle upper bound (57.2) and substantially outperforming the Multitask T0-3B baseline (51.6) by 5.3 points. On BIG-bench Hard and Lite, PHATG00SE scores 34.9 and 37.3 respectively, matching or exceeding T0-3B (34.9 and 36.6). In the larger FLAN setting (166 experts), PHATG00SE achieves 35.6 on BBH and 35.2 on BBL, outperforming all other post-hoc routing methods but falling short of the FLAN-T5-XL multitask reference (38.9 and 45.4).

## Baselines & Comparisons

PHATG00SE outperforms the Retrieval baseline (Jang et al., 2023) by 6.9 points on T0HO (56.9 vs 50.0) and by 4.2–6.0 points on BBH/BBL across both settings, confirming that per-token, per-module routing substantially beats single-expert retrieval. Against Arrow (Ostapenko et al., 2024), which constructs gates from LoRA SVD, PHATG00SE leads by 1.8 points on T0HO (56.9 vs 55.1) and by 5.0–5.6 points on BBH/BBL in the FLAN setting. PHATG00SE also surpasses Merged Experts (Ostapenko et al., 2023) by 11.5 points on T0HO (56.9 vs 45.4), though Merged Experts edges it out by 0.4 on BBH in the T0 setting. Most notably, PHATG00SE matches or exceeds the explicit Multitask T0-3B baseline (Sanh et al., 2021) on all three T0 Held-In benchmarks (56.9 vs 51.6 on T0HO; 34.9 vs 34.9 on BBH; 37.3 vs 36.6 on BBL) despite operating in a fully decentralized setting without simultaneous data access. In the FLAN setting, PHATG00SE outperforms all routing baselines but trails the FLAN-T5-XL multitask reference, which was trained on a different (non-public) dataset mixture and is not a fair comparison.

## Relation to Prior Work

This paper builds on the intersection of parameter-efficient fine-tuning (LoRA, Adapters) and sparsely-gated Mixture-of-Experts routing, but departs from prior post-hoc expert routing work (Jang et al., 2023; Belofsky, 2023; Durbin, 2024) that selects a single expert model per query via embedding similarity. The key conceptual shift is from model-level to per-token, per-module routing: rather than asking 'which expert should handle this input?', PHATG00SE asks 'which specific LoRA module at which layer should process this particular token?', drawing on the MoE top-k routing mechanism (Shazeer et al., 2016; Du et al., 2022). The post-hoc sigmoid gate training step is the novel mechanism that produces routing vectors without requiring simultaneous dataset access, distinguishing it from both retrieval-based methods and the contemporaneous Arrow approach (Ostapenko et al., 2024) that derives gates from LoRA singular vectors.

## Why It Matters / Open Questions

PHATG00SE offers a practical path toward decentralized development of generalist language models by recycling the growing ecosystem of shared PEFT modules (17,000+ on Hugging Face) without requiring centralized compute or simultaneous data access. The finding that a lightweight 100-step gate training step can produce routing that matches or exceeds explicit multitask training is practically significant for the PEFT community. However, a notable open question is the inconsistent scaling behavior: performance on knowledge-heavy tasks degrades as the expert pool grows from 36 to 166, suggesting that simply adding more experts is not a reliable path to improved generalization. Future work on decoder-only architectures, heterogeneous module types, and understanding why larger pools sometimes hurt remains important.
