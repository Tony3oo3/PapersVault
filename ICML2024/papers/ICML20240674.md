## Problem

Class-imbalanced node classification on graphs suffers from biased representations toward majority classes, and existing engineered loss functions (e.g., ReNode, TAM) rely heavily on human expert knowledge with limited adaptability to specific tasks. No prior work has applied automated loss function search to graph-structured data, and generic autoloss frameworks like Autoloss-Zero are not tailored to the unique challenges of imbalanced node classification.
![Teaser figure](../imgs/ICML20240674/cropped_page0_idx0.webp)

## Input / Output

AutoLINC takes an imbalanced graph (node features, edges, labels with a specified imbalance ratio ρ), a GNN architecture (GCN, GAT, or GraphSAGE), and an evaluation metric as input. It outputs a discovered loss function expressed as a mathematical formula over the model's logits ŷ, one-hot labels y, and class-specific node counts N, along with a fully trained GNN. The loss function is constrained to a parse tree of maximum depth 10 generated by a context-free grammar, and the final expression is averaged over all nodes to yield a scalar training objective.

## Method

AutoLINC frames loss function search as a nested optimization problem and employs Monte Carlo Tree Search (MCTS) with UCT selection to explore a context-free grammar-defined search space of loss function expressions. The search space uses input nodes (logits, labels, class counts N) and primitive operators (element-wise arithmetic, log, exp, tanh, square, sqrt, and a single mean aggregation), with the grammar ensuring every valid expression incorporates all three input types. A two-tier loss function check strategy accelerates the search: a Basic Check Strategy detects NaN values and caches equivalent expressions to avoid redundant evaluation, while an Early Rejection Strategy terminates proxy-task training early when a candidate shows non-monotonic accuracy improvement or lags significantly behind the current top-10 loss functions. A lightweight proxy task with curtailed training iterations provides fast reward signals (validation bACC) during MCTS, and the top-10 discovered loss functions are re-evaluated on the full task to select the final loss function.

## Results

On 15 GNN-dataset combinations (GCN/GAT/SAGE × Cora/CiteSeer/PubMed/Amazon-Computers/Amazon-Photo) with class imbalance ratio ρ=10, AutoLINC achieves the best balanced accuracy (bACC) in 13 out of 15 settings. The largest gains appear with GAT on Amazon-Photo (74.41% bACC vs. 65.88% for the strongest baseline Balanced Softmax+TAM, a +8.5 pp improvement) and on CiteSeer (58.48% vs. 54.14%, +4.3 pp). On GCN-Cora, AutoLINC reaches 70.21% bACC, surpassing the best baseline (Balanced Softmax+TAM at 69.17%) by ~1 pp. The discovered loss functions also transfer well to ρ=5 settings, retaining competitive performance without re-searching.

## Baselines & Comparisons

AutoLINC outperforms all six loss-function baselines (CE, RE-Weight, PC Softmax, Balanced Softmax, Balanced Softmax+TAM, ReNode) on 13 of 15 GNN-dataset combinations at ρ=10; the strongest baseline, Balanced Softmax+TAM, is beaten by 1–8.5 pp in bACC depending on the setting. Against non-loss-function-engineering methods (Table 7), AutoLINC alone is competitive with GraphSHA but slightly below it on some datasets; however, AutoLINC combined with GraphSHA (AutoLINC+GraphSHA) surpasses GraphSHA, GraphENS, and GraphSMOTE across all three GNNs and both imbalance ratios, e.g., reaching 76.88% bACC on Cora-GCN (ρ=5) vs. GraphSHA's 76.69%. In the direct comparison with Autoloss-Zero (Table 9, same 1-hour CPU budget), AutoLINC achieves substantially higher bACC—e.g., 70.60% vs. 62.64% (Autoloss-Zero-B) on Cora-GCN and 71.34% vs. 68.03% on Cora-GAT—attributed to AutoLINC's preference for structurally simpler loss expressions that generalize better in node classification. The only setting where AutoLINC does not clearly lead is PubMed-GCN at ρ=10, where the gain over Balanced Softmax+TAM is marginal (72.43 vs. 72.15 bACC), likely due to PubMed's high topology imbalance.

## Relation to Prior Work

This paper extends the automated loss function search paradigm (Autoloss-Zero, Li et al. 2022) from computer vision to graph-structured data, replacing Regularized Evolution with Monte Carlo Tree Search (Coulom, 2006) and designing a search space that explicitly incorporates class-specific node counts to address imbalance. It departs from hand-crafted loss functions for imbalanced node classification (ReNode, TAM) by automating the design process, and from prior automated loss search by tailoring the grammar, proxy tasks, and rejection strategies to the unique challenges of semi-supervised graph learning. The paper is, to the authors' knowledge, the first to apply automated loss function search to node classification on graphs.

## Why It Matters / Open Questions

The framework provides a practical, generalizable alternative to expert-designed loss functions for imbalanced node classification, with discovered loss functions showing transferability across GNN architectures and datasets of the same type (governed by homophily). Key limitations include reduced transferability across structurally different graph types (citation vs. co-purchase), high computational cost (~12 hours per search), and untested applicability to heterogeneous graphs. An open question is whether the MCTS-based search can be made more efficient or whether the discovered loss functions can be distilled into interpretable, closed-form expressions that practitioners can adopt without re-running the search.
