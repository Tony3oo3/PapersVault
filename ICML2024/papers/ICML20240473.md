## Problem

Serving multiple LLMs of varying sizes and popularities on a GPU cluster is costly because existing spatial partitioning wastes GPUs on unpopular models, while temporal multiplexing ignores the distinct computation characteristics of prefill versus decoding phases, leaving GPUs underutilized most of the time. No prior system combines spatial and temporal multiplexing while accounting for LLM popularity differences and the asymmetric resource demands of the two inference phases.

## Input / Output

MuxServe takes a GPU cluster topology, a set of LLMs (e.g., LLaMA models from 4B to 70B) with their workload characteristics (arrival rates, prompt/output lengths), and incoming text prompts as input, and produces served LLM responses as output. The system operates at the infrastructure level: it first determines a static placement of LLMs onto GPU mesh groups and a batching/scheduling strategy, then at runtime dispatches individual prefill and decoding jobs to dynamically partitioned SM resources. Evaluation metrics are aggregate weighted throughput and SLO attainment (percentage of requests meeting a latency target scaled relative to single-device execution time).

## Method

MuxServe's key insight is to colocate LLMs based on popularity (pairing high-traffic with low-traffic models) to multiplex memory, and to separate prefill and decoding into independent jobs that are flexibly colocated to multiplex computation. An enumeration-based greedy placement algorithm (Algorithm 1) searches over device mesh groups, prioritizing LLMs with large computation requirements, to find the optimal grouping of LLM units that maximizes total throughput. Within each unit, an Adaptive Batch Scheduling (ADBS) algorithm uses per-LLM token block quotas (normalized by request rate) to ensure fair KV cache sharing, prioritizes prefill jobs, and fills remaining SM capacity with round-robin decoding jobs, periodically reallocating quotas based on observed KV cache utilization. A unified resource manager implements this via CUDA MPS for dynamic SM partitioning and a head-wise unified KV cache that stores attention-head-level blocks in a shared memory space, enabling heterogeneous LLMs to share a single KV cache pool without per-model reservation.

## Results

On a 32-GPU cluster (4× A100 80GB nodes) serving 19 LLMs of varying sizes, MuxServe achieves up to 1.8× higher aggregated throughput and processes 2.9× more requests within 99% SLO attainment compared to both spatial partitioning (vLLM) and temporal multiplexing (AlpaServe-style) baselines on synthetic workloads. On real ChatLMSYS workloads (16 LLMs, 32 GPUs), MuxServe delivers 1.38× and 1.46× higher throughput versus spatial partitioning and temporal multiplexing respectively, while consistently achieving higher SLO attainment across all rate scales. The gains are most pronounced when LLM popularity is highly skewed (larger power-law exponent α), where colocating popular and unpopular LLMs yields the greatest resource multiplexing benefit.

## Baselines & Comparisons

MuxServe is compared against two baselines: (1) spatial partitioning, where each LLM is served independently on a dedicated GPU group using vLLM, and (2) temporal multiplexing, where LLMs share GPUs via time-sliced scheduling (similar to AlpaServe) with continuous batching. MuxServe outperforms both baselines on throughput in all evaluated scenarios, with the largest gap (up to 1.8×) on synthetic workloads with skewed popularity distributions. On real ChatLMSYS traces, MuxServe achieves 1.38× throughput over spatial partitioning and 1.46× over temporal multiplexing. For SLO attainment, MuxServe generally wins, though with small α (even popularity) and tight SLO targets, colocation interference causes a slight SLO penalty relative to spatial partitioning. Temporal multiplexing performs particularly poorly when medium-rate LLMs are co-located on large meshes, as it cannot efficiently interleave their prefill and decoding phases.

## Relation to Prior Work

MuxServe builds directly on vLLM's Paged Attention for single-LLM memory management and extends it to a cross-LLM unified KV cache via a head-wise granularity observation. It departs from AlpaServe's temporal multiplexing (which treats LLM inference as a monolithic job) by exploiting the distinct computation profiles of prefill and decoding phases to enable flexible spatial-temporal colocation across different LLMs. The CUDA MPS-based SM partitioning provides the spatial mechanism, while the adaptive batch scheduling (ADBS) and popularity-aware placement algorithm constitute the novel scheduling layer that prior multi-model serving systems lack.

## Why It Matters / Open Questions

For LLM endpoint providers serving dozens of models with highly uneven popularity, the 1.8× throughput and 2.9× SLO improvements translate directly into significant GPU cost reduction, making multi-model serving economically viable at scale. The head-wise unified KV cache and prefill-decoding disaggregation are practical techniques likely to be adopted in production serving stacks. Open questions include scalability of the O(MCD) placement algorithm to hundreds of LLMs, applicability to heterogeneous architectures with varying attention head sizes (which the head-wise cache assumes are similar), and how the fairness constraint (ε) should be tuned in production settings with SLA guarantees.
