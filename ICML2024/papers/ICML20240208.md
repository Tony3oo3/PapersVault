## Problem

Transformer-based LLMs require a KV cache that grows linearly with sequence length, quickly exhausting GPU memory during long-context inference and fine-tuning. Existing remedies—heuristic token eviction (H2O) and fixed-window attention sinks (StreamingLLM)—discard full-sequence information and fail to extrapolate beyond the training context window. No prior method provides a learnable, data-driven compression of the KV cache to a fixed size that preserves contextual fidelity while remaining a drop-in addition to pre-trained architectures.

## Input / Output

The method consumes long text sequences (up to 32K tokens) in fixed-size blocks of B tokens (default 512), projecting each block into Q, K, V matrices. The KV cache is maintained at a constant size M (128–512 slots) regardless of total sequence length, so peak memory is O(MB) rather than O(L²). During inference, the pre-filling stage processes the prompt in segments and compresses KVs to M slots; the generation stage then operates with B=1, attending only to the M compressed entries. The convolutional heads add only ~22M parameters for Llama-2-7B, and the pre-trained weights remain untouched, allowing users to revert to uncompressed mode by simply removing the heads.

## Method

LoCoCo replaces the simple concatenation of new KV pairs with cached ones by a learnable compression operator C implemented as a shallow 1D convolution (single conv layer, kernel size 21, ReLU activation). The convolution takes the stacked [K_n, K̃; V_n, Ṽ] matrix (2d input channels, M output channels) and produces an M×(M+B) weight matrix, which is row-normalized to yield blending coefficients w_{i,j} and w̃_{i,j} that fuse each cache slot as a weighted combination of incoming tokens and existing cache entries. This design satisfies three desiderata—negligible computational overhead (O(L log L) via FFT), learnability (end-to-end trained on a small calibration set), and stationarity (shift-invariant convolution avoids the discontinuities of heuristic token dropping). For long-context extension, the convolutional heads are combined with positional interpolation and LoRA adapters (rank 8) to fine-tune the pre-trained model from 4K to 32K context, while for post-hoc compression only the convolutional heads are tuned for 200 steps on 10⁸ tokens. The method can also be stacked on top of existing eviction policies (StreamingLLM, H2O) for further gains.

## Results

On Proof-Pile-2 perplexity with Llama-2-7B extended to 32K context, LoCoCo achieves 3.4408 PPL, approaching the full-sequence baseline (3.4012) while using only a fixed 512-token KV cache. On LongBench, LoCoCo scores 37.4%, outperforming H2O (36.9%) and LongLoRA (34.7%). During inference, LoCoCo compresses up to 3482 tokens into a 128-size KV cache with up to 0.2791 accuracy improvement over baselines at the same cache size. In terms of efficiency, LoCoCo uses 50 GB GPU memory (vs. OOM for full sequence) and achieves 33 tokens/s throughput at 16K pre-filling, surpassing H2O (32 tok/s) and LongLoRA (25 tok/s).

## Baselines & Comparisons

LoCoCo consistently outperforms all three baselines across every evaluated context length. Against H2O (heavy-hitter token eviction), LoCoCo achieves lower perplexity at every context length, with the gap widening as context grows: at 32K, LoCoCo scores 3.4408 vs. H2O's 3.5102 (a 0.07 PPL improvement), and on LongBench LoCoCo reaches 37.4% vs. H2O's 36.9%. Against LongLoRA (shifted sparse attention + LoRA), LoCoCo shows a larger margin, particularly at longer contexts: 3.4408 vs. 3.5916 PPL at 32K, and 37.4% vs. 34.7% on LongBench. Against StreamingLLM (attention sinks + local window), LoCoCo is substantially better, as StreamingLLM's perplexity remains flat (~4.03) regardless of context length, indicating it fails to leverage long-range information. On SCROLLS (Table 3), LoCoCo also leads all baselines on every subtask (e.g., GovReport: 0.3113 vs. H2O 0.2924, LongLoRA 0.2891). In terms of practical efficiency, LoCoCo matches H2O's memory usage (50 GB) and slightly exceeds its throughput (33 vs. 32 tok/s), while LongLoRA uses 1 GB less memory but is significantly slower (25 tok/s).

## Relation to Prior Work

LoCoCo builds on Transformer-XL's segment-level attention with cached KV pairs and LongLoRA's fine-tuning recipe (positional interpolation + LoRA + embedding/normalization updates), but departs fundamentally from heuristic-based token eviction methods like H2O and StreamingLLM by replacing rule-based dropping with a learnable 1D convolutional compression operator. The conceptual lineage draws from state-space models and convolutional language models (Poli et al., 2023; Massaroli et al., 2023), repurposing convolutions not as attention replacements but as lightweight, drop-in fusion kernels that compute per-slot mixing weights for the KV cache. Unlike LongLoRA, which requires architectural modifications, LoCoCo adds only shallow convolutional heads (22M parameters for Llama-2-7B) on top of frozen pre-trained weights, preserving the original model's behavior when the compressor is removed.

## Why It Matters / Open Questions

The drop-in design makes LoCoCo immediately applicable to any pre-trained LLM without retraining, lowering the barrier for practitioners on memory-constrained hardware (demonstrated on 48GB A6000 GPUs). However, the method still requires a short calibration phase (200 steps for inference, more for context extension), and the compression is inherently lossy—performance gaps versus full-sequence baselines, while small, persist at the highest compression ratios. Open questions include whether the approach scales gracefully beyond 32K contexts, how it interacts with emerging sparse-attention or retrieval-augmented architectures, and whether the convolutional heads can be absorbed into the base model via distillation to eliminate the extra inference overhead entirely.
