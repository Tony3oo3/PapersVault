## Problem

Training neural networks that interact with physics simulations requires differentiable simulators, but established ML libraries (PyTorch, TensorFlow, Jax) lack simulation-specific primitives like differential operators, boundary conditions, and differentiable linear solves, while existing differentiable physics frameworks are either highly specialized or use incompatible programming paradigms. This forces researchers to write low-level, framework-specific simulation code that is difficult to reuse, debug, and port across projects.

## Input / Output

PhiFlow consumes initial field states defined on staggered grids, centered grids, unstructured meshes, or point clouds, along with per-side boundary conditions and simulation parameters (viscosity, time step, etc.), and optionally neural network predictions that feed into the simulation loop. Outputs include the evolved field state with full gradient access (including gradients w.r.t. sparse matrix entries in implicit solves), single-call Matplotlib/Plotly visualizations, and optimized parameters from integrated SciPy solvers. A distinctive design choice is that the same simulation function runs in 1D, 2D, 3D, or higher dimensions without modification, and batch dimensions can be added to any input to vectorize the entire simulation for parallel experiments.

## Method

PhiFlow is a pure-Python toolkit built on the PhiML abstraction layer, which wraps tensor operations from PyTorch, TensorFlow, Jax, or NumPy so that all simulation code is backend-agnostic and inherits GPU/TPU acceleration, JIT compilation, and automatic differentiation. The core technical contributions are: (1) a library of differential operators (gradient, divergence, Laplacian, curl) on grids and meshes with user-selectable spatial order via on-the-fly stencil generation, coupled with boundary-condition-aware scheme selection; (2) fully differentiable preconditioned linear solvers (CG, BiCG, ILU) that support backpropagation through the sparse matrix A itself, not just the right-hand side; (3) automatic sparse matrix generation via function tracing, where a user-defined affine Python function is recorded and assembled into an explicit CSR matrix with cached sparsity patterns and jit-compiled dependency graphs; (4) dimensionality-agnostic code through tagged spatial axes; and (5) batch-dimension vectorization that propagates through all operations, eliminating the need for vmap while preserving debuggability. The fluid solver is assembled from composable building blocks (make_incompressible, diffuse, advect) rather than provided as a monolithic solver, enabling users to repurpose individual operations for heat transfer, wave propagation, or other PDEs.

## Results

PhiFlow achieves competitive wall-clock performance across all three supported backends (PyTorch, TensorFlow, JAX) on an NVIDIA RTX 3090, with per-step times ranging from 0.38 ms (2D waves, JAX) to 46 ms (PIV, JAX). The performance gap between backends is modest, with JAX typically fastest for random-access tasks and PyTorch best for easily parallelizable ones. In code-brevity comparisons against prior frameworks, PhiFlow requires dramatically fewer lines: 14 vs. 165 lines for wave propagation (Warp), 29+2 vs. 79+41 lines for billiards (DiffTaichi), and a compact 10-line implementation vs. 83 lines for sphere packing (JAX-MD).

## Baselines & Comparisons

The paper compares PhiFlow against three prior differentiable-physics frameworks by replicating their showcase experiments. Against DiffTaichi (Hu et al., 2019) on the billiards problem, PhiFlow uses 29 lines of computation plus 2 lines of plotting versus DiffTaichi's 79 + 41 lines, and ChatGPT's readability assessment finds the PhiFlow code more structured, higher-level, and more insightful. Against JAX-MD (Schoenholz & Cubuk, 2020) on sphere packing, the original requires 25 lines of imports, 25 for computation, and 33 for plotting, while PhiFlow's implementation is a single compact block; ChatGPT correctly identifies the PhiFlow library and explains the physics, whereas it misidentifies the JAX-MD code's purpose. Against Warp (Macklin, 2022) on 2D wave propagation, PhiFlow's 14-line implementation is roughly 12× shorter than Warp's 165 lines, and ChatGPT extracts all key parameters (resolution, domain size, boundary conditions) from the PhiFlow code but fails to do so for the Warp code. In all three comparisons, PhiFlow wins decisively on code brevity and readability, while performance remains competitive (no backend consistently outperforms the others by more than ~2×).

## Relation to Prior Work

PhiFlow positions itself as a unifying layer between the two historically separate ecosystems of differentiable simulation (DiffTaichi, JAX-MD, Warp, DOLFIN-adjoint, MuJoCo) and mainstream ML libraries (PyTorch, TensorFlow, JAX). It builds directly on the PhiML abstraction layer for cross-backend tensor operations and DLPack for zero-copy inter-library data transfer. The key conceptual departure from prior frameworks is the emphasis on Python-native, high-level abstractions—dimensionality-agnostic code, automatic matrix generation via function tracing, and batch-dimension vectorization—rather than requiring users to adopt a specialized DSL (Taichi, Julia) or low-level kernel programming (Warp). The fluid solver, differential operators, and boundary condition handling follow standard numerical methods (staggered grids, operator splitting, semi-Lagrangian advection) but are packaged as composable, differentiable building blocks rather than monolithic solvers.

## Why It Matters / Open Questions

PhiFlow addresses a practical bottleneck in scientific ML: the high barrier to entry when combining differentiable physics with neural network training, which has pushed many researchers toward supervised learning or custom low-level implementations. The dramatic code brevity demonstrated (e.g., 14 lines vs. 165 for wave propagation, 8 lines for the full thermal conductivity inverse problem) suggests the framework could accelerate research iteration cycles substantially. Open questions include whether the abstraction layer introduces measurable overhead at very large problem sizes, how the automatic matrix generation scales to highly nonlinear or time-varying operators, and whether the framework can handle the extreme parallelism demands of production-scale CFD. The ChatGPT-based readability assessment, while informal, highlights a genuine gap in reproducibility and code sharing in the differentiable simulation literature.
