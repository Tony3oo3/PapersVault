## Problem

Existing tabular ML methods can only learn from a single table, forcing practitioners to manually join and aggregate multiple relational tables into a flat feature matrix — a process that is slow, suboptimal, loses fine-grained signal, and risks temporal leakage. This paper introduces Relational Deep Learning (RDL), an end-to-end deep learning paradigm that eliminates manual feature engineering by learning representations directly from the multi-table relational structure.
![Teaser figure](../imgs/ICML20240544/cropped_page1_idx0.webp)

## Input / Output

The method consumes a full relational database (multiple tables linked by primary-foreign key relationships, with multi-modal row attributes spanning text, images, categorical, and numerical types, plus optional per-row timestamps) together with a training table that specifies entity IDs, ground-truth labels, and a seed timestamp per example. It outputs node-level or link-level predictions (classification or regression) via task-specific heads applied to GNN-computed node embeddings. A critical constraint is temporal consistency: for each training example with seed time t, the model may only access entities with timestamps ≤ t, enforced through temporal neighbor sampling during computation graph construction.

## Method

The core representation maps a relational database to a heterogeneous Relational Entity Graph where each row is a node, columns define node features, and primary-foreign key links define typed edges, with a schema graph providing the node and edge type taxonomy. The architecture comprises three end-to-end trainable stages: (1) pre-trained multi-modal column encoders produce initial node embeddings, (2) L layers of relational-temporal message passing propagate information across typed edges while filtering each neighborhood to include only neighbors with τ(w) ≤ t (the seed time), and (3) a task-specific head (MLP for node-level, bilinear for link-level) maps final embeddings to predictions. Training tables are auto-generated from historical data via time-conditioned SQL queries, and scalability to billion-row databases is achieved through temporal neighbor sampling that constructs bounded computation graphs per training example. The key differentiator from prior relational GNN work is the integration of time as a first-class citizen throughout the pipeline — from data splitting to message passing — which prevents temporal leakage without any manual feature engineering.

## Results

On the rel-amazon-ltv regression task (predicting user lifetime value over 2 years), the GNN-based RDL method achieves a test MAE of 3.12 and RMSE of 10.61, outperforming the single-table XGBoost baseline (MAE 3.49, RMSE 13.11) by approximately 10% on MAE and 19% on RMSE. The GNN also surpasses all naive baselines (global mean, entity mean, entity median). The paper notes these are preliminary proof-of-concept results across four tasks on two relational databases (rel-amazon and rel-stackex), with the GNN significantly outperforming XGBoost on all tasks.

## Baselines & Comparisons

The paper compares the proposed GNN-based RDL method against XGBoost applied to a single table (the entity table joined with the training table, with no SQL-based feature engineering) and several naive input-independent baselines (global zero/mean/median, entity mean/median, random, majority). On the rel-amazon-ltv regression task, the GNN achieves MAE 3.12 and RMSE 10.61, beating XGBoost (MAE 3.49, RMSE 13.11) by a substantial margin of ~10% on MAE and ~19% on RMSE. The GNN also outperforms all naive baselines, including entity-level statistics that leverage per-entity historical labels. The authors emphasize that the XGBoost baseline is deliberately kept minimal (single table, no feature engineering) to isolate the benefit of the relational graph structure, and that the significant gap demonstrates the value of end-to-end relational learning over manual flattening. The paper notes that in two binary classification cases, a naive majority-vote baseline achieves higher raw accuracy due to extreme label imbalance, but the GNN still wins on the more informative AP and ROC-AUC metrics.

## Relation to Prior Work

This paper positions Relational Deep Learning as the natural successor to statistical relational learning (SRL) and Markov logic networks, but grounded in modern deep learning rather than first-order logic and graphical models. Technically, it composes heterogeneous message passing (R-GCN, HGT) with temporal filtering (TGN) and neighbor sampling (GraphSAGE) into a unified pipeline over a relational entity graph, while explicitly departing from prior partial explorations (Schlichtkrull et al., 2018; Cvitkovic, 2019; Zahradnik et al., 2023) by adding the training-table formulation, temporal consistency as a first-class constraint, and a standardized benchmark. The paper draws a deliberate analogy to the pre-deep-learning era of computer vision, arguing that manual SQL feature engineering on relational data is the equivalent of hand-crafted Gabor filters, and that end-to-end GNN learning is the missing transition.

## Why It Matters / Open Questions

The paper identifies a genuine gap: the majority of enterprise and scientific data lives in multi-table relational databases, yet no standard ML paradigm can learn across tables without laborious manual feature engineering. By framing this as a graph representation learning problem with a concrete pipeline (schema graph → entity graph → time-consistent computation graph → GNN) and releasing RELBENCH, it provides a research program and shared benchmark that could catalyze a new subfield. Key open questions include scaling to sharded/distributed databases, designing GNN architectures that exploit the n-partite and regular edge-connectivity structure of relational graphs, multi-task learning across related predictive tasks, and whether foundation models can be pre-trained on relational data. The empirical evidence is preliminary (two databases, four tasks, no ablations), so the practical case for RDL over well-engineered feature pipelines remains to be established at scale.
