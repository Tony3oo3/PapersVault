## Problem

Existing text-to-3D methods either generate single objects or are restricted to narrow domains like indoor scenes, leaving open-domain scene composition with up to a hundred spatially related assets unsolved. Prior rule-based systems (WordsEye, SceneSere) require extensive human-authored templates for each new domain, and LLM-based agents like BlenderGPT lack the relational abstraction needed for complex spatial planning, achieving only 5.6/100 constraint satisfaction scores.

## Input / Output

The method takes a free-form natural language query (e.g., 'a girl hunter walking in a slum village with fantasy creatures') and produces a Blender-executable Python script that encodes per-asset layout matrices (position, scale, Euler-angle orientation) and renders a photorealistic scene image. Assets are retrieved from Turbosquid via a two-stage CLIP-based pipeline (text-to-text top-10, then text-to-image re-ranking), and the scene is decomposed into sub-scenes of roughly 10–20 assets each to keep the combinatorial layout problem tractable. The rendered image is fed back to a multimodal LLM for iterative critique, so the final output is a refined script plus its rendered image.

## Method

SceneCraft uses a dual-loop self-improving pipeline built on GPT-4V and Blender. In the inner loop, an LLM-Planner constructs a relational bipartite scene graph linking assets to spatial-relation nodes (proximity, alignment, parallelism, symmetry, etc.); an LLM-Coder then writes Python code that instantiates scoring functions for each relation and a constraint solver that maximizes the sum of relation scores over layout matrices; Blender renders the result, and a GPT-4V reviewer identifies unsatisfied constraints and revises the script, repeating for ~4 iterations. In the outer loop, after processing a batch of queries, a Library-Learner reviews the incremental modifications each query's inner loop made to constraint functions, detects consensus patterns, and merges them into a reusable non-parametric skill library of Python functions. This library learning requires no ground-truth scenes, no explicit reward, and no LLM weight updates—only the multimodal LLM's visual critique as the learning signal—enabling continuous self-improvement from as few as 20 synthetic examples.

## Results

On 20 unseen synthetic queries with ground-truth constraints, SceneCraft achieves a CLIP similarity score of 69.8 and a constraint satisfaction score of 88.9, compared to BlenderGPT's 24.7 and 5.6 respectively — a 45.1% improvement in CLIP score. On the Sintel movie evaluation, SceneCraft reaches 82.7 scene CLIP similarity and 69.3 layout matrix similarity versus BlenderGPT's 41.8 and 27.5. In human evaluation across 22 responses, SceneCraft is preferred 76.8% of the time overall (83.6% on composition/constraint agreement, 74.5% on aesthetics).

## Baselines & Comparisons

The only external baseline is BlenderGPT, an LLM assistant that generates basic Blender instructions (moving assets, changing textures) without relational constraint planning. SceneCraft decisively outperforms BlenderGPT on every metric: CLIP similarity improves from 24.7 to 69.8 (+45.1%) and constraint score from 5.6 to 88.9 on synthetic queries. On the Sintel movie, SceneCraft's scene CLIP score is 82.7 vs. BlenderGPT's 41.8 (+40.9%), and the scene-guided video generation achieves FVD of 317 vs. 574 for BlenderGPT-guided generation. Ablation results confirm that the relational scene graph is the most critical component (removing it drops constraint score to 3.2, near BlenderGPT level), followed by the inner-loop visual feedback (removing it drops to 26.1) and the learned skill library (removing it drops to 64.5). In head-to-head human evaluation, SceneCraft is preferred 76.8% of the time overall, with the largest margin on constraint agreement (83.6% vs. 11.4%).

## Relation to Prior Work

SceneCraft extends the text-to-3D scene synthesis lineage (WordsEye, SceneSere) by replacing hand-crafted rule-based spatial constraints with LLM-generated Blender code, and departs from the closest concurrent work 3D-GPT by directly interfacing with Blender and a large-scale asset pool rather than a procedural wrapper like Infinigen. Its dual-loop architecture draws on the LLM-agent self-refinement paradigm (Reflexion, Voyager) and the constraint-based scene graph optimization tradition (GraphDreamer, SceneWiz3D), but introduces a non-parametric library-learning outer loop that compiles per-scene constraint function updates into a reusable skill library without any gradient-based fine-tuning. The video generation component builds on VideoPoet, using generated 3D scene images as a conditioning signal for a fine-tuned autoregressive video model.

## Why It Matters / Open Questions

The paper demonstrates that complex spatial planning for open-domain 3D scenes can be handled by an LLM agent with iterative visual feedback and a growing non-parametric skill library, avoiding the cost and inaccessibility of LLM parameter tuning. However, the evaluation is limited to 40 synthetic queries and a single relatively weak baseline (BlenderGPT), the rendering setup uses fixed lighting and ground texture, and the video generation experiment assumes ground-truth assets are provided. Open questions include whether the library learning generalizes beyond the small set of spatial relations tested, how the system scales to scenes with hundreds of assets, and whether the generated scenes can serve as effective control signals for video generation in truly open-domain settings without curated assets.
