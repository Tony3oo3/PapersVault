## Problem

Existing web agent benchmarks (MiniWoB, WebArena, WebShop) focus on toy pages, e-commerce, or general consumer websites, leaving a critical gap: no benchmark evaluates agents on the complex, non-standard UIs of real enterprise software where knowledge workers spend their days. This paper asks how capable current LLM-based web agents are at performing common knowledge work tasks (filtering lists, filling forms, searching knowledge bases, ordering from service catalogs, reading dashboards) on the widely-deployed ServiceNow platform, which serves 85% of the Fortune 500.

## Input / Output

At each step, the agent receives a natural language task goal (delivered via a chat interface), the current page's HTML DOM snapshot and/or accessibility tree (ranging from 40K to 500K tokens after basic cleaning), an optional viewport screenshot, the currently focused element, and the previous action's error message. The agent outputs a single web action per step drawn from a customizable space: bid-based primitives (click, fill, hover, press), coordinate-based primitives (mouse_click, keyboard_type), or arbitrary Python code with full Playwright API access. For information-retrieval tasks, the agent additionally produces a chat response that is validated against a set of acceptable answers. A maximum of 15 steps per episode is enforced.

## Method

The paper introduces two coupled contributions: WorkArena, a benchmark of 33 tasks (19,912 unique instances) spanning six categories (lists, forms, knowledge bases, service catalogs, dashboards, menus) on live ServiceNow Personal Developer Instances, and BrowserGym, a POMDP-based OpenAI Gym environment built on Chromium/CDP/Playwright that provides multimodal observations (HTML, AXTree, screenshot), a flexible action space, chat-based user interaction, and native support for multi-page navigation and nested iFrames/shadow DOMs. The evaluated agent is a simple chain-of-thought LLM agent with configurable flags for observation features (focused element, error history, visible/clickable tags, coordinates), action space (bid-only vs. bid+coord, multi-action), and memory (action history, think history). An ablation study across GPT-4o, GPT-3.5, and Llama3-70B reveals that chain-of-thought is essential (10+ point drop without it), that adding too many features degrades weaker models due to prompt truncation, and that 2D coordinate actions help on MiniWoB but not on WorkArena. GPT-4o achieves 42.7% on WorkArena versus 6.1% for GPT-3.5 and 17.9% for Llama3, with list-filtering tasks at 0% for all models.

## Results

On the newly introduced WorkArena benchmark (33 tasks, 19,912 instances), GPT-4o achieves 42.7% success rate, substantially outperforming GPT-3.5 (6.1%) and Llama3-70B (17.9%). On MiniWoB, GPT-4o reaches 66.1% (82.9% on the WebGum subset), and on WebArena it achieves 23.5%, surpassing the original paper's GPT-4 score of 14.4%. Notably, all agents score 0% on the list-filter tasks, which require interacting with a non-standard HTML widget, highlighting a clear capability gap for current LLM-based web agents on enterprise software.

## Baselines & Comparisons

The paper compares four agent configurations (GPT-4o, GPT-4o-V with Set-of-Mark vision, GPT-3.5, and Llama3-70B) across three benchmarks. GPT-4o dominates all other models on every benchmark: on WorkArena it achieves 42.7% vs. 17.9% (Llama3) and 6.1% (GPT-3.5), a gap that is far more pronounced than on MiniWoB (66.1% vs. 62.6% vs. 38.9%), consistent with emergent capability scaling. On WebArena, the GPT-4o agent's 23.5% success rate substantially exceeds the 14.4% reported in the original WebArena paper (Zhou et al., 2023) using GPT-4, attributed to BrowserGym's richer observation and action spaces. On MiniWoB, GPT-4o's 82.9% on the WebGum subset surpasses prior zero-shot web agent results (Assouel et al., 2023; Zeng et al., 2023). The vision-augmented GPT-4o-V provides only marginal gains (e.g., 41.8% vs. 42.7% on WorkArena), suggesting current VLMs lack sufficient screen-related training data for meaningful multimodal improvement.

## Relation to Prior Work

This paper extends the web agent benchmarking line (MiniWoB, WebShop, WebArena) by targeting enterprise software, a domain the authors explicitly identify as unexplored. Rather than building on a specific prior agent architecture, it introduces BrowserGym as a unified environment that subsumes features from prior work (multimodal observations, code-based actions, accessibility trees) while adding chat-based interaction and multi-page navigation. The empirical agent is a straightforward chain-of-thought LLM agent, positioned as a baseline to characterize the benchmark's difficulty rather than as a methodological contribution.

## Why It Matters / Open Questions

WorkArena fills a critical gap by evaluating web agents on the complex, non-standard UIs of real enterprise software (ServiceNow), where 85% of Fortune 500 companies operate. The finding that all agents achieve 0% on list-filtering tasks—despite them being trivial for humans—highlights a concrete failure mode (non-standard HTML widgets) that current architectures cannot handle. Open questions include whether compositional multi-step workflows will be even harder, whether vision-language models can eventually close the multimodal gap, and how the significant open/closed-source LLM disparity (17.9% vs 42.7% for GPT-4o) will evolve as open models improve.
