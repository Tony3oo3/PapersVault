## Problem

Most code LLMs treat source code as flat sequences of subword tokens, ignoring its intrinsic hierarchical structure. Prior structure-aware approaches rely on computationally expensive program analyses (control-flow analysis, code execution) or architectural modifications, limiting scalability to real-world, multi-language codebases. AST-T5 addresses this gap by introducing a lightweight, structure-aware pretraining paradigm that requires only syntactic parsing.

## Input / Output

During pretraining, code files are parsed into ASTs via Tree-sitter, tokenized with a 100k byte-level BPE vocabulary, and segmented into 1024-token chunks. AST-aligned subtrees are replaced with unique sentinel tokens, and the decoder reconstructs the original spans. For downstream tasks, the model accepts natural language prompts (text-to-code), source code in one language (transpilation), or code snippets (classification), producing generated code, transpiled code, or categorical labels respectively. The model uses beam search for generation and rank classification for understanding tasks.

## Method

AST-T5 introduces two structure-aware pretraining techniques on top of a standard T5_BASE encoder-decoder architecture (277M parameters, 12-layer encoder/decoder, 768 hidden dim). First, AST-Aware Segmentation uses a dynamic programming algorithm with a monotonic queue (O(n²/max_len) complexity) to partition code files into chunks that minimize AST subtree breaks, replacing naive greedy splitting. Second, AST-Aware Subtree Corruption replaces random span masking with a recursive algorithm that selects masking spans aligned to AST subtrees, with a tunable threshold θ (uniformly sampled 5–100 per example) controlling granularity from individual tokens to entire function bodies. The pretraining objective remains standard span corruption with a 25% mask ratio, requiring no architectural changes or additional heads, making AST-T5 a drop-in replacement for any T5 variant. Pretrained on 524B tokens from The Stack Dedup across Python, Java, C, C++, C#, Markdown, and reStructuredText.

## Results

AST-T5 (277M params) achieves 14.0 Pass@1 on HumanEval, 22.9 EM on Concode, 23.8/16.1 EM on Bugs2Fix (Small/Medium), 68.9/72.3 EM on Java-C# transpilation, 98.6 F1 on Clone Detection, and 65.8 Acc on Defect Detection. On the more rigorous EvalPlus benchmark, AST-T5 scores 12.8 Pass@1 on HumanEval+ and 19.3 on MBPP+, surpassing InCoder-6.7B (12.2/15.9) and CodeGen2-1B (9.1/11.0) despite being 24x and 3.6x smaller respectively. On multi-lingual HumanEval, AST-T5 achieves 14.0 (Python) and 10.6 (Java), outperforming BLOOM-7.1B (7.9/8.1) and OPT-13B (0.6/0.6).

## Baselines & Comparisons

Against the closest same-size competitor CodeT5, AST-T5 wins on every comparable metric: Concode EM (22.9 vs 22.3), Bugs2Fix (23.8/16.1 vs 21.6/14.0, a +2.2/+2.1 gain), Java-C# transpilation (68.9/72.3 vs 65.9/66.9, a +3.0/+5.4 gain), and Clone Detection F1 (98.6 vs 97.2), while tying on Defect Detection (65.8 vs 65.8). Versus CodeT5+BASE, AST-T5 leads on HumanEval (14.0 vs 12.0) and Clone Detection (98.6 vs 95.2) but trails slightly on Defect Detection (65.8 vs 66.1). Against encoder-only models CodeBERT and GraphCodeBERT, AST-T5 dominates on transpilation (e.g., Java-C# 68.9/72.3 vs 59.0/58.8 for CodeBERT) and clone detection. On the EvalPlus benchmark, AST-T5 (277M) outperforms InCoder-6.7B on both HumanEval+ (12.8 vs 12.2) and MBPP+ (19.3 vs 15.9), and beats CodeGen2-1B by 3.7 and 8.3 points respectively. On multi-lingual code generation, AST-T5 surpasses BLOOM-7.1B and OPT-13B on all four sub-benchmarks (e.g., HumanEval Python 14.0 vs 7.9 for BLOOM), and exceeds CodeGen-multi-350M on every metric, demonstrating strong parameter efficiency.

## Relation to Prior Work

AST-T5 builds directly on the T5 encoder-decoder architecture and its span corruption pretraining objective, positioning itself as a drop-in replacement that requires no architectural changes or additional heads. It departs from prior structure-aware code models (GraphCodeBERT, StructCoder, AST-aware attention mechanisms) that necessitate expensive program analyses, control-flow graphs, or model modifications, by exploiting AST structure solely through pretraining-time segmentation and masking decisions. The approach is conceptually closest to CodeT5's identifier-aware pretraining and DOBF's deobfuscation objective, but replaces those heuristics with a principled dynamic-programming-based segmentation and a recursive subtree-corruption algorithm that targets semantically meaningful code spans.

## Why It Matters / Open Questions

The paper demonstrates that a 277M-parameter model with a single pretraining objective can match or exceed models 10–25× larger on code generation benchmarks, suggesting that structure-aware pretraining signals may be a more efficient path to code competence than brute-force scaling. The practical simplicity (no architecture change, one objective, Tree-sitter as the only external dependency) makes the technique broadly adoptable for any encoder-decoder code LM. Key limitations include the assumption of syntactically valid input code, potential degradation of natural-language generation quality, and the fact that all results are at a single model scale, leaving open whether the AST-aware advantage persists or diminishes at larger parameter counts.
