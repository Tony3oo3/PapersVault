## Problem

Conventional RL state representations capture general environmental information but omit task-specific details, causing value networks to produce non-smooth mappings from states to rewards and suffer from low sample efficiency. Existing remedies rely on extensive sample learning or expert knowledge injection, both of which are costly. The paper asks whether LLMs can autonomously generate task-related state representations that improve the Lipschitz continuity of value networks without requiring LLM access during training or testing.
![Teaser figure](../imgs/ICML20242106/cropped_page1_idx1.webp)

## Input / Output

The method takes a source state vector (e.g., joint positions, velocities, coordinates) along with a natural-language task description and per-dimension state details as input to GPT-4, which outputs two executable Python functions: a state representation function F(s)→s^r that computes task-specific features from the source state, and an intrinsic reward function G(s, s^r)→r^i. The augmented state s^c = (s, s^r) is concatenated and fed to the policy and value networks, while the total reward is r + w·r^i. LLM consultation occurs only at the start of each iteration; during both training and testing, the system runs entirely on the generated code with no LLM in the loop.

## Method

LESR prompts GPT-4 to generate K candidate pairs of state representation and intrinsic reward function codes, trains K parallel TD3 agents for a short N_small timesteps, and computes per-dimension Lipschitz constants between each state feature and the extrinsic reward as a feedback signal. This feedback, along with episode returns, is fed back to the LLM via a chain-of-thought analysis prompt to iteratively refine the generated code over I iterations. Theoretically, the paper proves (Theorems B.4, B.8) that reducing the Lipschitz constant of the reward function lowers the upper bound on Lip(V;S) and tightens the suboptimality gap of the greedy policy, providing a formal justification for why smoother state-to-reward mappings accelerate convergence. The resulting F_best and G_best are algorithm-agnostic and transfer directly to PPO and SAC without re-iteration, yielding average improvements of 29% (Mujoco) and 30% (Gym-Robotics) over SOTA baselines.

## Results

LESR achieves an average 29% relative performance improvement (RPI) over TD3 across 5 Mujoco tasks (e.g., Swimmer: 164.2 vs. 84.9, +93%; Ant: 4343.4 vs. 3532.6, +23%) and a 30% average success rate improvement over TD3 across 6 Gym-Robotics tasks (e.g., FetchPush: 0.91 vs. 0.07, +84%; AdroitHandDoor: 0.88 vs. 0.53, +34%). On the sample-efficiency evaluation at only 300k steps, LESR yields a 91% average RPI over TD3 (Hopper: 2705.0 vs. 921.9, +193%; Swimmer: 150.9 vs. 49.9, +203%). The generated state representation and intrinsic reward functions transfer directly to PPO (+34% avg.) and SAC (+20% avg.) without re-iteration.

## Baselines & Comparisons

LESR consistently outperforms TD3 (the base algorithm) across nearly all tasks: 4/5 Mujoco tasks and 5/6 Gym-Robotics tasks, with the largest gains on Swimmer (+93%) and FetchPush (+84%). Against EUREKA (the closest LLM-based reward-design baseline), LESR achieves a 29% vs. −2% average RPI on Mujoco and 30% vs. 8% average PI on Gym-Robotics, indicating that state-representation augmentation provides substantially more benefit than reward design alone. On the AntMaze tasks where TD3 completely fails (0% success), LESR still achieves 7–17% success rates, while EUREKA reaches only 0–13%. The generated functions also transfer to PPO and SAC without re-iteration, yielding +34% and +20% average improvements respectively, confirming algorithm-agnosticism. Notably, EUREKA actually degrades performance on Ant (−27% RPI) and Walker2d (−9% RPI) relative to TD3, whereas LESR improves on both.

## Relation to Prior Work

LESR departs from the dominant LLM+RL paradigm (Voyager, DEPS, LGTS) where LLMs remain tightly coupled to agents during inference, instead using LLM purely as an offline code generator consulted only at the start of each iteration. It extends the state-representation-learning line (Niv 2019, Ota et al. 2020, Merckling et al. 2022) by replacing data-driven representation learning with LLM-generated task-specific features, and differentiates from EUREKA (Ma et al. 2023) by treating the intrinsic reward as an auxiliary signal to anchor state-representation learning rather than as the primary reward design. The theoretical grounding draws on Lipschitz-regularized convergence results (Oberman & Calder 2018, Asadi et al. 2018) to formalize why smoother state-to-reward mappings accelerate value-network training.

## Why It Matters / Open Questions

The practical takeaway is that a single GPT-4 call can produce state-representation code that transfers algorithm-agnostically (TD3→PPO/SAC) and yields ~30% average gains across Mujoco and Gym-Robotics without any LLM involvement at test time, making it a low-overhead plug-in for existing RL pipelines. Key limitations include reliance on source-state features only (no external observations), dependence on LLM quality for generating physically meaningful representations, and evaluation restricted to continuous-control benchmarks. Open questions include whether the approach extends to partially observable or high-dimensional perceptual settings, and whether the Lipschitz-continuity argument generalizes beyond the deterministic-policy assumptions used in the proofs.
