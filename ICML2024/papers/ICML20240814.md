## Problem

Machine learning experimentation—iteratively designing, coding, running, and analyzing experiments to improve model performance—requires extensive domain knowledge and is a central bottleneck in ML research. While language models have shown promise as autonomous agents, no prior benchmark systematically evaluates whether LM-based agents can perform end-to-end ML experimentation across diverse tasks, modalities, and difficulty levels.
![Teaser figure](../imgs/ICML20240814/cropped_page1_idx0.webp)

## Input / Output

Each task provides a textual task description, starter files (baseline code in PyTorch/TensorFlow/JAX/Keras plus training and unlabeled test data), and an evaluator that scores a final submission file (e.g., submission.csv with per-class probabilities or regression predictions). The agent operates in a sandboxed workspace with file-system and Python-execution access, and its full interaction trace—including structured research plans, fact-check entries, and per-step observations—is recorded for qualitative evaluation. Success is defined as improving the baseline performance metric by at least 10%, and efficiency is measured in wall-clock time and total LM tokens consumed.

## Method

The paper introduces MLAgentBench, a 13-task benchmark spanning canonical datasets (CIFAR-10, IMDB, ogbn-arxiv), classic and recent Kaggle challenges, active research problems (CLRS, BabyLM), and code-optimization tasks, all instantiated in a unified task-agnostic environment with 12 primitive and compound actions. The proposed agent extends the ReAct framework by structuring each LM response into five ordered components: Reflection (verbal self-feedback inspired by Reflexion), Research Plan and Status (a persistent, interpretable high-level plan that tracks completed steps and confirmed results), Fact Check (explicitly verifying whether plan updates are grounded in observed outputs to counter hallucination), Thought (reasoning about the next action), and Action with JSON-formatted input. Compound actions like Edit Script and Understand File encapsulate multi-step file operations with auxiliary LM calls, reducing the burden on the main agent. The agent is evaluated across seven LMs (GPT-4, GPT-4-turbo, Claude v1.0/v2.1/v3 Opus, Gemini Pro, Mixtral) and compared against AutoGPT and LangChain-ReAct baselines, with Claude v3 Opus achieving the highest 37.5% average success rate.

## Results

The Claude v3 Opus agent achieves the best average success rate of 37.5% across 13 ML experimentation tasks, defined as improving the performance metric by ≥10% over the starter-code baseline. Success rates range from 100% on well-established tasks (house-price, spaceship-titanic) to 0% on recent Kaggle challenges (parkinsons-disease, fathomnet) and BabyLM. In terms of average percentage improvement over baseline, GPT-4 leads at 41.3%, followed by GPT-4-turbo (32.8%) and Claude v3 Opus (26.1%), indicating GPT-4 makes larger gains when it succeeds but less consistently. The proposed agent framework outperforms AutoGPT (2.9–13.5%) and LangChain/ReAct (1.0–33.7%) on average success rate when paired with the same LMs.

## Baselines & Comparisons

Claude v3 Opus (37.5% avg success) outperforms GPT-4-turbo (26.0%), GPT-4 (19.2%), Gemini Pro (18.3%), Claude v1.0 (16.3%), and Mixtral (3.8%) on success rate, with a clear generational progression within the Claude family (v1.0 → v2.1 → v3 Opus: 16.3% → 26.0% → 37.5%). However, GPT-4 achieves a higher average percentage improvement (41.3% vs. 26.1% for Claude v3 Opus), meaning it makes larger gains when it does succeed, though less consistently. Against agent frameworks, the proposed method (with its Research Plan, Fact Check, and Reflection components) substantially outperforms AutoGPT (2.9% with GPT-4-turbo, 13.5% with Claude v3 Opus) and LangChain/ReAct (1.0% and 33.7% respectively), though LangChain with Claude v3 Opus is competitive at 33.7%, partially because its simpler design avoids submission format errors. All agents fail completely (0% success) on parkinsons-disease, fathomnet, and BabyLM, suggesting these tasks exceed current LM agent capabilities regardless of framework.

## Relation to Prior Work

This paper builds directly on the ReAct framework (Yao et al., 2023) for the thought-action loop and on Reflexion (Shinn et al., 2023) for the self-reflective component, extending both with a structured Research Plan and Status tracker and a Fact Check mechanism to combat hallucination. Conceptually, it departs from AutoML and hyperparameter-tuning approaches (AutoML-GPT, MLcopilot) by granting the agent full open-ended code manipulation rather than constraining it to a predefined search space. It also distinguishes itself from general-purpose agent benchmarks (AgentBench, WebArena, ARA) by focusing specifically on the iterative, code-executing workflow of ML experimentation, and from autonomous agent projects (AutoGPT, Voyager) by providing a contained, automatically evaluable environment.

## Why It Matters / Open Questions

MLAgentBench is the first systematic benchmark for evaluating LLM agents on end-to-end ML experimentation, filling a critical gap between general agent benchmarks and AutoML evaluations. The stark performance gap between well-established tasks (100% success on house-price) and post-training Kaggle challenges (0% success) provides concrete evidence of data contamination and limited generalization, while the identification of hallucination (20% of runs) and long-horizon planning failures pinpoints specific architectural weaknesses. The practical cost analysis (~$231 expected cost per task at 26% success rate) highlights that reliability, not just capability, is the bottleneck for real-world deployment. Open questions include whether better planning/replanning strategies can close the gap on complex tasks, and how human-in-the-loop intervention might improve success rates.
