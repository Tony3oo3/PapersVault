## Problem

Existing LLM inference parallelization schemes (tensor and sequence parallelism) do not exploit the causal structure of attention, computing the full QK^T matrix and exchanging K,V via all-gather collectives, which incurs up to 2× overhead in both computation and communication relative to the ideal causal case. This is particularly costly for the prompt (prefill) phase where long user contexts make TTFT a compute-bound bottleneck critical for user experience in retrieval-augmented generation, in-context learning, and summarization.

## Input / Output

The method takes a user context of C text tokens and LLM model weights (any causal-attention decoder such as Llama or Falcon), and produces the first generated token with minimized TTFT followed by subsequent tokens in the extension phase. The context is unevenly partitioned across p processes (e.g., [0, 9728, 16384] for a 16k context on 2 GPUs), and the KV-cache serves as the intermediate artifact passed between processes. The method requires contiguous physical memory for KV-cache to avoid costly extra copies during point-to-point transfers.

## Method

KV-Runahead dual-purposes the existing KV-cache interface (already present for the extension phase) to parallelize the prompt phase: instead of all processes computing QK^T in parallel and exchanging K,V via all-gather, each process computes its local (Q,K,V) on an unevenly partitioned context and hands the accumulated KV-cache to the next process via asynchronous point-to-point send, forming a dependency chain that naturally restricts computation to the lower triangular (causal) portion. This reduces total QK^T dot-products and network traffic by up to 2× compared to tensor/sequence parallelism, and replaces global synchronization with point-to-point communication that is robust to bandwidth fluctuations. To handle the resulting asymmetric computation load, the paper proposes context-level load-balancing via a hierarchical grid search that finds the optimal uneven partitioning minimizing the maximum QK^T across processes, with results stored in a lookup table for fast interpolation at inference time. The theoretical lower bound TTFT*(p) = TTFT(1)/2 · (1/p + 1/p²) reveals super-linear scalability for causal LLMs, which KV-Runahead approaches closely in practice.

## Results

KV-Runahead (KVR-S) achieves up to 1.42× TTFT speedup over Tensor/Sequence Parallelization (TSP) on Llama 7B (16k context, 4 GPUs) and up to 1.63× on Falcon 7B (8k context, 8 GPUs), all on a 300 GB/s network. On a low-bandwidth 10 GB/s network, the speedup widens to 1.79× (Llama 7B, 8k, 4 GPUs). KVR-S also demonstrates superior robustness: under noisy network conditions, TSP degrades by up to 11.8% in TTFT while KVR-S degrades by at most 3.7%. Across all tested models (Llama 7B/13B/30B, Falcon 1B/7B) and context lengths (1k–16k), KVR-S consistently outperforms TSP on both 4-GPU and 8-GPU configurations.

## Baselines & Comparisons

The sole baseline is Tensor/Sequence Parallelization (TSP), which combines tensor parallelism (Shoeybi et al., 2020) and sequence parallelism (Li et al., 2023) with all-gather collectives for K/V exchange, as further characterized by SplitWise (Patel et al., 2023). KVR-S wins against TSP in every tested configuration: the speedup grows with context length (from ~1.1× at 1k to 1.42× at 16k for Llama 7B) and with GPU count (e.g., 1.30× → 1.36× for Llama 7B 8k going from 4 to 8 GPUs). The advantage is most pronounced on Falcon 7B (up to 1.63×) and on low-bandwidth networks (10 GB/s), where KVR-S reaches 1.79× because TSP's all-gather is more bandwidth-sensitive. Under noisy network conditions, TSP suffers up to 11.8% TTFT degradation while KVR-S degrades by at most 3.7%, confirming the benefit of point-to-point asynchronous communication over global synchronization. TSP also hits out-of-memory errors at 16k context on 2 GPUs, whereas KVR-S does not, indicating lower peak memory usage.

## Relation to Prior Work

KV-Runahead repurposes the KV-cache mechanism—originally designed solely for the autoregressive extension phase—into a parallelization primitive for the prompt/prefill phase, departing from the tensor and sequence parallelism (TSP) paradigm that shards computation symmetrically and relies on all-gather collectives. Conceptually, it is closest to pipeline parallelism in its dependency-chain structure, but the causal attention mask and the pre-existing KV-cache interface eliminate the need for custom layer partitioning or activation recomputation. The paper also draws on the theoretical observation that causal attention's lower-triangular structure permits super-linear speedup with more processes, a property that TSP's symmetric all-gather approach cannot exploit.

## Why It Matters / Open Questions

TTFT is the dominant latency bottleneck for long-context applications (RAG, in-context learning, summarization), and KV-Runahead offers a low-engineering-cost path to 1.4–1.6× speedup over the current SOTA parallelization (TSP) with minimal code changes to existing LLM serving stacks. The robustness to non-uniform network bandwidth (≤3.7% TTFT degradation vs. >10% for TSP) makes it attractive for heterogeneous or shared-cluster deployments. Open questions include how the technique composes with other inference optimizations (speculative decoding, quantization, PagedAttention's non-contiguous memory), whether the one-time lookup-table search overhead is acceptable for production systems with highly variable context-length distributions, and how it scales to models where KV-cache memory itself becomes the binding constraint.
