## Problem

Despite PPO powering production systems like ChatGPT and Claude, DPO frequently achieves superior results on academic RLHF benchmarks, raising the question of whether DPO is genuinely better or whether PPO's underperformance stems from suboptimal implementation. This paper investigates the fundamental algorithmic limitations of DPO and identifies the key practical factors that enable PPO to achieve state-of-the-art alignment performance.
![Teaser figure](../imgs/ICML20242263/cropped_page3_idx1.webp)

## Input / Output

The alignment pipeline takes a user instruction (text prompt) and produces a single-round text response optimized for human preferences. For dialogue tasks (HH-RLHF, SafeRLHF), preference pairs of the form (x, y_w, y_l) provide training signal, while for code generation tasks (APPS, CodeContest), ground-truth rewards from test-case verification serve as the feedback signal. The trained model outputs either natural language responses or executable Python code, evaluated via reward models, GPT-4 pairwise comparison, or pass@k metrics.

## Method

The paper provides a theoretical proof (Theorem 4.1) that the class of policies reachable by PPO is a proper subset of those reachable by DPO, showing DPO can exploit out-of-distribution responses that PPO's KL regularization against the reference model prevents. Empirically, the authors demonstrate that DPO's performance is highly sensitive to distribution shift between the base model's outputs and the preference dataset, and that iterative DPO with self-generated data mitigates but does not eliminate this issue. On the PPO side, ablation studies identify three critical techniques: advantage normalization for training stability, large batch sizes (512) for consistent gains especially on code tasks, and exponential moving average updates of the reference model to avoid over-regularization. With these techniques, PPO consistently outperforms DPO, DPO-Iter, RRHF, and PRO across all benchmarks, achieving state-of-the-art results on CodeContest (22.4% 10@1k with CodeLlama-34B, surpassing AlphaCode-41B's 16.4%).

## Results

On the CodeContest benchmark, PPO with CodeLlama-34B achieves 22.4% pass@10 (10@1k), surpassing the previous state-of-the-art AlphaCode-41B (16.4%) by 6 percentage points. On APPS, PPO with CodeLlama-34B reaches 44.4% / 18.0% / 9.1% pass@5 on Introductory / Interview / Competition levels, while DPO-Iter fails to improve over SFT at any model size. On HH-RLHF, PPO attains 0.718 OpenAssistant reward and a 57% GPT-4 win rate against chosen responses, compared to DPO's 0.611 and 55%. On SafeRLHF, PPO achieves 99.5% safety rate with +1.69 helpfulness, whereas DPO only reaches 55.4% safety with −4.19 helpfulness.

## Baselines & Comparisons

PPO decisively outperforms DPO (Rafailov et al., 2023) on every task: on CodeContest, DPO produces 0.0% pass rate (outputting meaningless code snippets after one epoch) versus PPO's 22.4%; on HH-RLHF, PPO scores 0.718 OpenAssistant reward versus DPO's 0.611; and on SafeRLHF, PPO reaches 99.5% safety with positive helpfulness while DPO only achieves 55.4% safety with negative helpfulness. DPO-Iter (Xiong et al., 2023) narrows the gap on SafeRLHF (99.9% safety) but still trails PPO on helpfulness (−2.96 vs +1.69) and collapses on code tasks (3.2% vs 22.4% on CodeContest). RRHF (Yuan et al., 2023) and PRO (Song et al., 2023) are both substantially outperformed by PPO on HH-RLHF (0.523 and 0.529 OpenAssistant reward respectively vs PPO's 0.718). On the code generation front, PPO with CodeLlama-34B surpasses AlphaCode-41B (Li et al., 2022) on CodeContest (22.4% vs 16.4% 10@1k) despite using only Python, whereas AlphaCode used both Python and C++. Against Beaver-v1 (Dai et al., 2023) on SafeRLHF, PPO achieves higher helpfulness (+0.66 vs −6.59) while maintaining a comparable safety rate (98.6% vs 89.6%).

## Relation to Prior Work

This paper builds directly on the RLHF framework (Ziegler et al., 2019; Ouyang et al., 2022) and the two dominant alignment paradigms: reward-based PPO (Schulman et al., 2017) and reward-free DPO (Rafailov et al., 2023). It extends the RL community's findings on PPO implementation details (Engstrom et al., 2020; Andrychowicz et al., 2021; Yu et al., 2022) to the LLM alignment setting, identifying three critical factors—advantage normalization, large batch size, and EMA reference model updates—that were previously underexplored in RLHF. The theoretical analysis (Theorem 4.1) departs from prior work by Li et al. (2023) on synthetic contextual bandits by providing a formal set-inclusion result (Π_PPO ⊂ Π_DPO) and connecting it to the practical issue of distribution shift between model outputs and preference data.

## Why It Matters / Open Questions

This paper challenges the prevailing narrative in academic benchmarks that DPO outperforms PPO, showing that DPO has a fundamental theoretical limitation (it can exploit out-of-distribution responses in ways PPO cannot) and that PPO, with proper tuning, consistently surpasses DPO across dialogue and code generation tasks. The practical tuning guidelines for PPO (advantage normalization, batch size 512, EMA reference) are immediately actionable and likely to shift implementation choices in the community. Open questions remain around reward model quality (acknowledged as a limitation), whether findings generalize to other actor-critic algorithms, and how to handle the increased computational cost of PPO relative to DPO's simpler training loop.
