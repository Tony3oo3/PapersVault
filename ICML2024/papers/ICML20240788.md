## Problem

No comprehensive benchmark exists for evaluating LLM-based agents on end-to-end data analysis tasks, which require planning, code writing, sandbox interaction, and self-debugging rather than simple code completion. Existing code benchmarks like DS-1000 only test snippet insertion, and data analysis questions are typically open-ended, making automatic evaluation without human supervision difficult.
![Teaser figure](../imgs/ICML20240788/cropped_page1_idx0.webp)

## Input / Output

The agent receives a CSV file (avg. 9,640 rows × 10.6 columns), a data analysis question, and explicit constraints specifying exact methods and statistical parameters. The output must follow a strict closed-form format of one or more @answer_name[answer] tokens (up to 8 subquestions per question), where each answer has a defined type and value range. Evaluation is performed via regular expression extraction and exact string matching against ground-truth labels obtained from OpenAI ADA with 3-consistency filtering.

## Method

The benchmark (DAEval) is constructed by crawling real CSV files from GitHub, generating open-ended questions with GPT-4 guided by seven expert-identified data analysis concepts (e.g., correlation analysis, outlier detection, feature engineering), then applying a format-prompting technique that appends detailed constraints and @answer_name[answer] format requirements to convert each question into a uniquely answerable closed-form problem. An agent framework implements the ReAct loop with a Docker-isolated Python sandbox, and a GPT-3.5 reformatting step ensures models' free-form responses conform to the required output format before regex-based scoring. For training, DAInstruct (5,131 ReAct trajectories over 631 CSV files) is collected by having GPT-4 solve generated questions through the same agent framework, then filtered by rule-based checks and GPT-4 quality criteria across five dimensions. DAAgent is produced by instruction-tuning CodeLlama (7B/13B/34B) on DAInstruct, with the 34B variant achieving 64.59% accuracy—3.9% above GPT-3.5—while also showing a 50% Self-Debug Success Rate comparable to GPT-3.5.

## Results

On the DAEval validation set (257 questions, 461 subquestions), GPT-4 achieves the highest accuracy at 78.99%, while the best open-source LLM, Qwen-72B-Chat, reaches 59.92%. The paper's DAAgent-34B, instruction-tuned from CodeLlama on DAInstruct, achieves 64.59% accuracy, surpassing GPT-3.5 (60.70%) by 3.9 percentage points despite having far fewer parameters. Self-debug success rate (SDSR) varies substantially: GPT-4 achieves 0.71, DAAgent-34B achieves 0.50, GPT-3.5 achieves 0.47, and Qwen-72B-Chat only 0.28.

## Baselines & Comparisons

DAAgent-34B (64.59%) outperforms GPT-3.5 (60.70%) by 3.9 points and Abab5.5 (61.48%) by 3.1 points, while remaining well below GPT-4 (78.99%) by 14.4 points. Among open-source models, Qwen-72B-Chat (59.92%) is the strongest general LLM, trailing GPT-3.5 by only 0.78 points and exceeding Gemini-Pro (56.42%) by 3.5 points. Instruction tuning on DAInstruct yields dramatic gains over the base CodeLlama models: DAAgent-34B improves from 31.13% to 64.59% (+33.5 points), DAAgent-13B from 26.67% to 55.86% (+29.2 points), and DAAgent-7B from 24.61% to 51.36% (+26.8 points). Among agent frameworks, AutoGen with GPT-4 (71.48%) substantially outperforms XAgent with GPT-4 (47.52%), suggesting multi-agent conversation is more effective than single-agent for data analysis. In self-debug, GPT-4 leads with SDSR 0.71, DAAgent-34B (0.50) slightly edges out GPT-3.5 (0.47), while Qwen-72B-Chat (0.28) shows the weakest self-debug capability among top models.

## Relation to Prior Work

This paper builds on the ReAct agent paradigm (Yao et al., 2022) for the reasoning-action loop and on CodeLlama (Rozière et al., 2023) as the base model for its instruction-tuned DAAgent. It departs from code-completion benchmarks (HumanEval, MBPP, DS-1000) that only require filling in code snippets, and from tool-use benchmarks (ToolBench, Gentopia) that focus on API calling, by framing data analysis as an end-to-end agent task requiring planning, code writing, sandbox execution, self-debugging, and answer extraction. The format-prompting technique for converting open-ended questions into closed-form, automatically evaluable ones is a methodological contribution that distinguishes it from prior LLM-as-judge approaches, which the paper shows achieve only 67% consistency with human experts on data analysis.

## Why It Matters / Open Questions

As the first dedicated benchmark for evaluating LLM-based agents on data analysis, InfiAgent-DABench fills a clear gap: prior code benchmarks don't test the full agent loop, and no prior work systematically measures planning, self-debugging, and sandbox interaction on realistic CSV files. The finding that even GPT-4 plateaus at ~79% and that self-debug ability (SDSR) varies dramatically across models (0.71 for GPT-4 vs. 0.28 for Qwen-72B) points to concrete, actionable weaknesses. Key limitations include the single-modal scope (no visualization), reliance on OpenAI ADA for ground-truth labels (potential circularity), and LLM-synthesized questions that may carry distributional biases despite human filtering. Open questions include extending to multimodal evaluation, improving self-debug as a targeted training objective, and whether the format-prompting approach generalizes beyond tabular data.
