## Problem

Modern ML workflows increasingly produce ecosystems of related models (fine-tuned variants, quantized edge models, federated learning derivatives), yet no existing system tracks the dependencies among them. Without automated lineage tracking, storing all model variants is redundant, debugging requires manual bisection to find whether a bug originates in a model or an upstream parent, updating a parent model does not propagate to children, and concurrent edits by multiple users lack a principled merge mechanism.

## Input / Output

MGit consumes ML model checkpoints (e.g., Hugging Face BERT/RoBERTa/T5 models, ResNet-50, Llama-2-7b) along with their torch.fx DAG representations and optional user-registered creation functions (Python callables specifying how a child model is derived from its parents). It produces a lineage graph where nodes carry metadata (model type, name, creation function) and edges are typed as provenance (derivation) or versioning (temporal succession); for storage, it emits delta-compressed parameter tensors with pointers to parent layers, and for collaboration it emits a merge conflict report (no-conflict, possible-conflict requiring tests, or hard conflict requiring manual resolution).

## Method

MGit's core abstraction is a lineage graph with two edge types: provenance edges (solid) recording how a model is derived from its parents via an optional creation function, and versioning edges (dashed) tracking successive versions of the same model. For storage, MGit applies content-based hashing (SHA-256 over tensor values and shapes) to deduplicate identical parameters across models, then computes quantized deltas between non-identical parent-child parameter pairs and losslessly compresses them with LZMA or RLE, accepting compression only if accuracy stays within a configurable threshold. Graph construction can be automated via a diff primitive that converts models to DAGs, runs a hash-table-based graph matching algorithm to compute structural and contextual divergence scores, and inserts each new model as a child of its most similar existing node. Higher-level operations—traversal-based testing, run_update_cascade (a modified BFS that re-invokes creation functions only after all parents are updated), and a merge primitive that checks for layer-level conflicts and inter-layer dependencies—build directly on this graph, enabling automated propagation of upstream fixes and structured collaboration.

## Results

MGit achieves up to 6.96× storage compression (G3, federated learning models) using LZMA delta compression with content-based hashing, compared to 2.29× for the Full baseline (LZMA on entire models). In a user study with 20 ML practitioners, MGit users completed a model updating task 3× faster (11.3 min vs. 35.7 min, p = 5.8×10⁻⁷) and found 5.3 out of 8 buggy models versus 0.5 for the control group (p = 3.6×10⁻⁵). For collocated inference of Llama-2-7b and Llama-2-7b-chat, MGit saves 39.3% GPU memory at 90% layer merging with up to 1.5× inference speedup, at the cost of up to 12.2% accuracy degradation on Pile.

## Baselines & Comparisons

The paper compares MGit's delta compression pipeline (quantization + LZMA on inter-model deltas + content-based hashing) against two baselines: 'Full' (LZMA applied to entire model checkpoints) and 'Full w/o quantization' (LZMA without the quantization step). MGit(LZMA+Hash) outperforms the Full baseline on compression ratio for 4 out of 6 graphs: 2.14× vs. 1.83× (G1), 5.35× vs. 1.85× (G2), 6.96× vs. 2.29× (G3), and 2.64× (G6, no Full baseline reported). The only tie is G4 (2.57× for both), where the Full baseline benefits from compressing root models that MGit skips. The Full w/o quantization baseline consistently underperforms, achieving compression ratios below 1.0 for G1 (0.87×), G2 (0.78×), and G3 (0.72×), indicating that quantization is essential for effective lossless compression of model parameters. MGit also outperforms the RLE-based variant (e.g., 6.96× vs. 3.11× on G3) at the cost of slightly longer compression time, and the content-based hashing alone provides 9.4–79.6% savings depending on parameter sharing across models.

## Relation to Prior Work

MGit extends the model versioning and management space (ModelHub, MLflow, DVC, Hugging Face Hub) by introducing a lineage graph as a first-class data structure that tracks provenance and versioning relationships between derived models, rather than treating each model as an independent artifact. Its delta compression pipeline directly builds on Delta-DNN (Hu et al., 2020), extending the quantization-plus-lossless-compression approach from intra-model to inter-model parameter deltas. Compared to Git-Theta, which focuses on parameter-level versioning of individual models, MGit broadens scope to managing a network of related models with automated update cascades, traversal-based testing, and a merge primitive for collaboration. The collocated inference component draws on tensor-sharing ideas from Tetris, Gemel, and PetS but adds the ability to merge near-identical layers across models.

## Why It Matters / Open Questions

MGit addresses a practical and growing pain point: as model ecosystems become increasingly derivative (fine-tuning, quantization, federated averaging, MTL), the lack of lineage tracking makes storage wasteful, debugging opaque, and updates error-prone. The 7× storage reduction and 3× speedup in model updating are meaningful for teams managing large model families, and the open-sourced implementation lowers the adoption barrier. Key limitations include the quadratic scaling of the auto-insertion algorithm, the absence of dataset provenance tracking, and the accuracy tradeoffs in collocated inference (up to 12.2% degradation at 90% layer merging). Open questions include whether the lineage graph abstraction generalizes to non-derivative model relationships (e.g., ensemble members) and how to integrate data-level provenance without exploding graph complexity.
