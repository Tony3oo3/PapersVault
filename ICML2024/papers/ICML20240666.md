## Problem

Evaluating Retrieval-Augmented Generation (RAG) systems on narrow, domain-specific tasks lacks a canonical, automated, and interpretable methodology. Existing benchmarks measure general LLM capabilities that do not transfer to task-specific factual accuracy, and human-in-the-loop evaluation is expensive and does not scale. The paper asks: can we automatically generate a task-specific exam from a document corpus and use it to both rank RAG pipelines and decompose performance into its constituent components?

## Input / Output

The method takes a task-specific document corpus (e.g., 1,249 AWS troubleshooting pages, 13,000 ArXiv abstracts, 977 StackExchange Q&A pairs, or 493 SEC filing sections) and a set of candidate RAG pipelines, each defined by an LLM (Mistral-7B, LlamaV2-13B, or LlamaV2-70B), a retrieval mechanism (Closed-Book, Oracle, BM25, MultiQA, SIAM, DPR, or DPRV2), and an in-context learning mode (0, 1, or 2 examples). It produces a 4-choice multiple-choice exam (275–515 questions per task after filtering), a pointwise accuracy score per pipeline, IRT ability scores decomposed additively into LLM, retrieval, and ICL components, per-question item parameters (difficulty, discrimination, guessing), and an aggregated Fisher information function quantifying exam informativeness across the ability spectrum.

## Method

The core contribution is a two-stage pipeline: (1) an LLM (LlamaV2-70B) generates candidate multiple-choice questions from each document, followed by NLP-based a-priori filters (Jaccard and embedding similarity thresholds) that remove degenerate discriminators and non-self-contained questions; and (2) a hierarchical IRT model that extends the standard 3-parameter logistic IRT by decomposing each pipeline's ability θ_m into an additive sum θ_llm + θ_ret + θ_icl, enabling independent estimation of each RAG component's contribution via joint maximum-likelihood fitting over all pipelines and questions simultaneously. The paper further introduces the Fisher information function I(θ|g_i, d_i, b_i) to quantify how well each question discriminates between models at a given ability level, and an iterative refinement loop (Algorithm 1) that alternately refits the IRT model and discards the least discriminative r-th quantile of questions to monotonically increase the exam's aggregated information. Bloom's taxonomy is applied programmatically to categorize questions by cognitive complexity, enabling granular, interpretable diagnostics of where RAG pipelines succeed or fail.

## Results

Across four tasks (DevOps, StackExchange, ArXiv, SEC Filings), the best non-Oracle RAG configuration (LlamaV2-70B + DPRV2) achieves 71.8% average accuracy, while the Oracle upper bound reaches 74.8%. The IRT hierarchical model decomposes ability into LLM, retrieval, and ICL components, revealing that retrieval method choice often yields larger ability gains than scaling model size (e.g., in t_sec, switching from SIAM to DPRV2 provides more ability gain than upgrading from Mistral-7B to LlamaV2-70B). Notably, poorly aligned retrievers (SIAM) can perform worse than no retrieval at all (ClosedB), and hybrid ensembles (DPRV2) offer the most robust cross-task performance.

## Baselines & Comparisons

The paper compares 45 RAG pipeline configurations (3 LLMs × 7 retrieval methods × 3 ICL modes) across four tasks. LlamaV2-70B + DPRV2 achieves the best average accuracy (71.8%), outperforming Mistral-7B + DPRV2 (64.6%) and LlamaV2-13B + DPRV2 (63.9%), confirming that model size helps but retrieval choice is equally critical. A key finding is that switching retrieval from SIAM to DPRV2 on LlamaV2-70B in t_sec yields a larger IRT ability gain (+1.61) than upgrading from Mistral-7B to LlamaV2-70B with the same retriever (+1.38). Sparse retrieval (BM25) outperforms dense retrieval (MultiQA, SIAM) on t_ops and t_arx, while dense retrieval wins on t_stk, showing no single retrieval paradigm dominates. Hybrid ensembles (DPR, DPRV2) consistently provide the most robust cross-task performance. The Oracle setting (74.8% avg) establishes an upper bound, with the gap to best non-Oracle (71.8%) indicating that retrieval quality remains the primary bottleneck.

## Relation to Prior Work

This paper adapts Item Response Theory (IRT), a psychometric framework originally developed for human exam analysis (Rasch 1960, Lord 1968, Embretson & Reise 2013), to the automated evaluation of RAG pipelines. While IRT has seen limited use in ML for interpretability (Yeung 2019, Martinez-Plumed 2019) and recommender systems (Liu 2023), this is the first work to leverage it for evaluating generative models, introducing a hierarchical IRT model that decomposes RAG ability into LLM, retrieval, and in-context learning components. The paper positions itself against existing RAG evaluation frameworks (RAGAs, RaLLe, ARES) by offering a fully automated, ground-truth-free, and component-level interpretable alternative, and against general LLM benchmarks by focusing on task-specific factual accuracy rather than broad capabilities.

## Why It Matters / Open Questions

The framework provides RAG practitioners with a scalable, cost-efficient evaluation loop that does not require human annotation, and the hierarchical IRT decomposition enables targeted component selection rather than black-box pipeline scoring. The key practical finding—that retrieval mechanism choice often yields larger gains than LLM scale—challenges the default assumption that bigger models are the primary lever, and the iterative exam improvement via Fisher information offers a principled path toward self-optimizing benchmarks. Open questions include extending the approach to multilingual settings, agent-based sequential tasks, and non-QA tasks like summarization, as well as understanding how corpus size and chunking interact with model ability in a quantitative way.
