## Problem

KV cache memory grows linearly with batch size and context length, becoming the dominant bottleneck in LLM inference speed and memory usage. While quantization is the most straightforward remedy, prior work has only applied uniform 4-bit per-token quantization without a systematic study of KV cache element distributions, leaving it unclear why key and value caches resist low-bit compression differently and what quantization granularity is optimal for each.
![Teaser figure](../imgs/ICML20241311/cropped_page1_idx0.webp)

## Input / Output

The method consumes KV cache tensors that arrive sequentially during autoregressive decoding (one new key/value vector per generated token) along with the current query vector. It produces a 2-bit (or 4-bit) quantized KV cache structured as a grouped quantized portion plus a small full-precision residual window of at most R tokens, and the final attention output. The grouped portion uses group size G=32 along the quantization dimension, and the residual window is the only part stored in FP16, making the memory overhead negligible for long sequences.

## Method

KIVI's core insight is an asymmetric quantization strategy: key cache is quantized per-channel (grouping elements along the channel dimension) because a few fixed channels exhibit persistent large-magnitude outliers, while value cache is quantized per-token because attention sparsity means the output is a weighted sum over only a few important tokens, so per-token quantization confines error to individual tokens. To handle the streaming nature of autoregressive decoding—where per-channel quantization spans multiple tokens and cannot be applied incrementally—KIVI splits each cache into a grouped part (quantized in blocks of G tokens) and a residual part (kept in full precision, at most R tokens). During decoding, new tokens are appended to the residual; once it reaches R tokens, it is quantized and concatenated into the grouped part, and the residual resets. Attention scores are computed via tiled matrix multiplication that fuses dequantization with the matmul, combining the quantized and full-precision portions seamlessly. This design requires no fine-tuning, is plug-and-play, and is fully compatible with weight-only quantization.

## Results

KIVI compresses KV cache to 2-bit with minimal accuracy loss: on Llama-2-7B, KIVI-2 achieves 63.05 CoQA (vs. 63.88 at 16-bit), 33.95 TruthfulQA (vs. 30.76), and 12.74 GSM8K (vs. 13.50). On LongBench, KIVI-2 maintains within ~1% of 16-bit average across Llama-2-7B (44.27 vs. 44.52), Llama-2-13B (44.69 vs. 44.85), and Mistral-7B (45.85 vs. 46.58). In system-level evaluation on a single A100, KIVI enables up to 4× larger batch size and delivers 2.35×–3.47× throughput improvement over the FP16 baseline, with 2.6× peak memory reduction including model weights.

## Baselines & Comparisons

The primary baseline is 4-bit per-token quantization (K-T, V-T), as used by FlexGen (Sheng et al., 2023), H2O (Zhang et al., 2023), and ATOM (Zhao et al., 2024). KIVI-2 at 2-bit matches or exceeds this 4-bit baseline on most tasks: on Llama-2-7B, KIVI-2 scores 63.05 CoQA vs. 64.82 for 4-bit (−1.8 pts) but 33.95 TruthfulQA vs. 29.85 (+4.1 pts) and 12.74 GSM8K vs. 12.28 (+0.5 pts); on Mistral-7B, KIVI-2 achieves 36.01 GSM8K vs. 36.85 for 4-bit (−0.8 pts). Against the fake 2-bit (K-C, V-T) quantization that quantizes all tokens without a full-precision residual window, KIVI-2 dramatically outperforms on hard reasoning tasks: GSM8K jumps from 5.76 to 12.74 on Llama-2-7B and from 26.46 to 36.01 on Mistral-7B, demonstrating the critical role of the full-precision sliding window. KIVI-4 essentially matches 16-bit performance across all models (e.g., 63.78 vs. 63.88 CoQA on Llama-2-7B), while KIVI-2 stays within ~2% on most tasks. On LongBench, KIVI-2's average score is within 0.3–0.7 points of 16-bit for Llama-2 models, confirming robustness in long-context settings.

## Relation to Prior Work

This paper departs from the prevailing approach in KV cache quantization, where prior work (FlexGen, H2O, ATOM) applied uniform per-token round-to-nearest quantization to both key and value caches due to the streaming nature of autoregressive inference. KIVI's core insight, grounded in a systematic empirical study of KV cache element distributions, is that key and value caches have fundamentally different outlier structures: key cache exhibits persistent channel-wise outliers (consistent with activation outlier findings in AWQ and SmoothQuant), while value cache has no such pattern. The method repurposes the grouped-quantization idea from weight quantization (GPTQ, AWQ) but applies it asymmetrically—per-channel for keys, per-token for values—and introduces a grouped-plus-residual split to reconcile per-channel quantization with the streaming constraint, a design not present in prior KV cache compression work.

## Why It Matters / Open Questions

KIVI's 2.6× peak memory reduction with near-zero accuracy loss is a practically significant efficiency win for LLM serving, enabling up to 4× larger batch sizes and 2.35–3.47× throughput on a single A100, which directly reduces per-request cost at scale. The tuning-free, plug-and-play nature makes it immediately deployable alongside existing weight quantization and system-level optimizations (vLLM, PagedAttention). Open questions include whether the full-precision sliding window can be further reduced or replaced, whether the approach extends to sub-2-bit regimes, and how to fuse the quantization/dequantization overhead into surrounding operations to close the remaining gap with pure FP16 latency. The Falcon-7B results (requiring 4-bit rather than 2-bit due to multi-query attention's single KV head) also suggest the method's effectiveness is architecture-dependent.
