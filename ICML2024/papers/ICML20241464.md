## Problem

Full-matrix preconditioners such as M-FAC and GGT store a sliding window of m past gradients (m=100–1000), each of dimension d, incurring Θ(md) memory that is intractable at scale—for example, M-FAC on BERT-base requires over 450 GB of GPU RAM. This memory bottleneck makes full-matrix preconditioning impractical on consumer hardware despite its demonstrated accuracy advantages over diagonal methods like Adam.

## Input / Output

The method consumes standard stochastic gradients g_t = ∇_θ L(θ_t) produced by backpropagation at each training step, along with the current model parameters θ_t. It outputs updated parameters θ_{t+1} via a preconditioned descent direction. Internally, the gradient history ring buffer G ∈ R^{m×d} is replaced by a compressed representation storing only k ≪ d entries per gradient (e.g., k = d/100 for 99% sparsity), plus a single d-dimensional error feedback vector ξ_t, reducing the optimizer state from O(md) to O(mk + d) memory.

## Method

EFCP applies an error feedback loop before gradients enter the preconditioner's sliding window: at each step, the previous compression error ξ_{t-1} is added to the current gradient to form an accumulator a_t, which is then compressed via block-wise Top-k sparsification (or low-rank power iteration) to produce c_t; the residual ξ_t = a_t − c_t is carried forward. The compressed c_t is fed into the existing M-FAC or GGT preconditioner, whose internal operations (scalar products and linear combinations of gradients) are reformulated to exploit the sparse/low-rank structure. A key technical contribution is a novel dynamic sparse ring-buffer data structure with custom CUDA kernels for sparse-matrix-vector multiplication and sparse linear combination, leveraging block-wise Top-k to ensure uniform sparsity patterns that enable shared-memory accumulation. Theoretically, the paper shows the approach achieves O(√(d/T)·√(d/k)) average regret for full-matrix Adagrad under Hessian-stability assumptions, and empirically demonstrates that 99% gradient sparsity recovers the accuracy of dense M-FAC on ImageNet/ResNet-18 and GLUE/BERT while reducing memory to within ~15% of SGD.

## Results

On ImageNet/ResNet-18, Sparse M-FAC (S-MFAC) at 1% gradient density achieves 70.01% Top-1 accuracy, matching Dense M-FAC (70.03%) while using only 14.3 GB of GPU memory versus 58.5 GB for Dense M-FAC and 12.8 GB for SGD. On BERT-BASE/GLUE-MNLI, S-MFAC reaches 84.86% accuracy where Dense M-FAC runs out of memory (417 GB required for the ring buffer alone), outperforming Adam (84.6%). On the ASDL benchmark (ViT-Tiny/CIFAR-10), S-MFAC achieves 98.0% test accuracy with only 1.15× memory overhead relative to SGD, matching Shampoo and outperforming K-FAC (97.4%) and SENG (97.7%).

## Baselines & Comparisons

Against Adam/AdamW, S-MFAC clearly wins on BERT fine-tuning: 71.06% vs 66.86% on BERT-TINY (+4.2 pp) and 76.40% vs 74.77% on BERT-MINI (+1.6 pp) on GLUE-MNLI, while matching Adam on BERT-BASE (84.86% vs 84.6%). Against K-FAC on the ASDL ViT-Tiny/CIFAR-10 benchmark, S-MFAC achieves 98.0% vs 97.4% with comparable time overhead (1.63× vs 1.12×) and slightly higher memory (1.15× vs 1.13×). Against Shampoo on ImageNet/ResNet-18, S-MFAC achieves 70.01% Top-1 in 4h 21m with 14.3 GB memory, while Shampoo reaches 70.24% (at lr=5) but requires 11h 21m and 12.66 GB; at the more standard lr=2.5, Shampoo drops to 69.62%, below S-MFAC. The key practical advantage over Dense M-FAC is memory: S-MFAC reduces the ring buffer from Θ(md) to O(mk) with k=d/100, enabling BERT-BASE training (14.8 GB) where D-MFAC requires 417 GB for the buffer alone and simply cannot run.

## Relation to Prior Work

This paper combines two previously separate lines of work: full-matrix preconditioning (M-FAC for natural gradient, GGT for adaptive regularization) and error-feedback-based gradient compression (Alistarh et al., 2018; Karimireddy et al., 2019). The key conceptual departure is applying error feedback not to the gradient used for parameter updates, but to the gradient history stored in the preconditioner's sliding-window ring buffer, thereby compressing the preconditioner itself rather than the update direction. The low-rank variant repurposes PowerSGD-style power iteration (Vogels et al., 2019) for the same purpose, and the theoretical analysis extends the diagonal adaptive compression results of Li et al. (2022) toward the full-matrix setting.

## Why It Matters / Open Questions

The practical impact is substantial: full-matrix preconditioners like M-FAC and GGT were previously infeasible at scale (BERT-base required 417 GB just for the gradient ring buffer), and EFCP reduces this to single-GPU memory (14.8 GB) while recovering dense-preconditioner accuracy. The main open question is theoretical: the full-matrix convergence guarantee requires a 'Hessian stability' assumption that is not yet rigorously established, and the authors acknowledge that further work is needed to fully explain the remarkable practical convergence. Broader implications include whether the approach extends to other second-order methods (K-FAC, Shampoo) and whether the sparse ring-buffer data structure can be generalized beyond M-FAC/GGT.
