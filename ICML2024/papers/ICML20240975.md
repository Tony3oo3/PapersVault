## Problem

Scaling Mixture-of-Experts models by adding more experts increases GPU memory requirements (for parameters, optimizer states, and dispatch masks) even though computational complexity remains constant, forcing researchers to provision ever-larger GPU arrays. Existing frameworks like FairSeq and Tutel hit out-of-memory errors at moderate expert counts (e.g., 16 experts for MoE-L), and token load imbalance across experts causes straggler GPUs and wasted computation from zero-padding.

## Input / Output

ES-MoE consumes text tokens (batched sequences from datasets such as WikiText-103, SST-2, MNLI, BoolQ) and MoE model parameters that reside in host CPU RAM or SSD rather than GPU memory. The gating network's per-token routing decisions dynamically determine which experts are uploaded to which GPU for each microbatch. The system produces updated model parameters (written back to host memory after CPU-based Adam optimization) and standard training loss, maintaining mathematical equivalence to the original training semantics.

## Method

ES-MoE offloads all expert parameters and optimizer states to host memory (or SSD for very large models), keeping only non-expert parameters, the currently active expert, and activations on the GPU. It pipelines expert processing at the expert granularity: the token permutation phase overlaps with the first expert upload, subsequent experts are uploaded concurrently with the previous expert's computation, and CPU-based Adam optimization for each expert begins immediately after that expert's backward pass completes, hiding optimization latency behind other layers' GPU work. A dynamic expert placement module (a greedy Graham 4/3-approximation scheduler running in <2.7 µs) assigns experts to GPUs per-batch based on token load, eliminating zero-padding and balancing GPU workloads. Instead of batched matrix multiplication, ES-MoE sequentially assigns tokens to experts, avoiding the large dispatch mask and freeing GPU memory for up to 8× larger microbatches. An adaptive offloading strategy selects among GPU-only, CPU-offload, and CPU+SSD-offload modes based on model size, with 25% of the most-used experts pinned to each GPU to reduce I/O overhead.

## Results

ES-MoE achieves training throughput of up to 117,150 words/s on MoE-S with 64 experts (3.70B params), a 17.5× improvement over Zero-Offload^E (6,702.8 words/s). On the largest configuration (MoE-L, 64 experts, 29.3B params), ES-MoE is the only framework that completes training at 1,240.8 words/s, while all baselines hit OOM. ES-MoE also fine-tunes a 15B-parameter MoE model on 4 GPUs in 6.5 hours, achieving 88% accuracy on SST-2, 78.2% on MNLI, and 68.5% on BoolQ. Overall, ES-MoE supports up to 67× more experts (with SSD) than GPU-only baselines while maintaining mathematical equivalence to standard training.

## Baselines & Comparisons

ES-MoE outperforms all three baselines on every configuration where they can run. Against Zero-Offload^E (a modified ZeRO-Offload extended for expert-wise offloading), ES-MoE achieves 3.5×–17.5× higher throughput, with the largest gap at 64 experts where the offloading overhead of Zero-Offload^E becomes most severe. Against FairSeq/Gshard (Lepikhin et al., 2020), ES-MoE delivers 4.4×–11.6× speedup, and FairSeq hits OOM at 16 experts for MoE-L and 32 experts for MoE-M. Against Tutel (Hwang et al., 2022), the state-of-the-art MoE-specialized framework, ES-MoE achieves up to 3.16× higher throughput (e.g., 148,673 vs. 76,776 words/s on MoE-S with 32 experts), and Tutel also OOMs at 16 experts for MoE-L. Critically, ES-MoE is the only method that successfully trains MoE-L with 64 experts (29.3B params) on 4 GPUs, where all baselines fail with OOM.

## Relation to Prior Work

ES-MoE builds on the standard expert parallelism paradigm (Fedus et al., 2022; Lepikhin et al., 2020) and CPU offloading techniques (Ren et al., 2021; Rajbhandari et al., 2020), but departs from both in critical ways. Unlike static expert assignment in expert parallelism, ES-MoE introduces dynamic expert placement using a greedy scheduling algorithm (Graham, 1969) to balance token loads per-batch. Unlike layer-wise offloading in ZeRO-Offload, ES-MoE operates at expert granularity with pipelined upload/compute/optimization, and it is implemented on top of FairSeq (Ott et al., 2019). The paper explicitly positions itself as the first work targeting the regime where MoE expert memory exceeds aggregate GPU capacity, distinguishing it from MegaBlocks (Gale et al., 2022) which requires all experts resident in GPU memory.

## Why It Matters / Open Questions

ES-MoE substantially lowers the hardware barrier for MoE training, enabling 15B-parameter fine-tuning on 4 A100s (vs. 64 GPUs previously) and 67× more experts via SSD offloading, which is directly relevant to academic and small-organization researchers. A key open question is how the approach scales to inference and to even larger models where CPU/SSD bandwidth becomes the bottleneck; the paper notes GPU utilization degrades as experts grow because per-expert token counts shrink. The reliance on CPU-based Adam (31× slower than GPU) means the pipelining overhead will grow with model depth, and the method's applicability to non-MoE architectures or to settings with heterogeneous GPU clusters remains unexplored.
