## Problem

Translating high-level semantic understanding from multimodal large language models into precise, generalizable robotic control remains an open challenge. Existing approaches either lack visual grounding (relying on text-only LLM planning) or depend on task-specific skill models that fail to generalize across novel objects, physical constraints, and robot platforms. The core gap is a unified framework that bridges conceptual scene understanding with low-level manipulation while maintaining cross-platform transferability.
![Teaser figure](../imgs/ICML20241482/cropped_page0_idx0.webp)

## Input / Output

The system ingests three RGBD views (left, right, top) from depth cameras fused into a unified TSDF representation, alongside a free-form human language instruction. It outputs structured executable Python code that calls a predefined set of ROS/MoveIt APIs for perception, grasping, and motion planning. The code is organized as a tree-of-thought decomposition into sequential object-centric units, each annotated with manipulation preferences (approach direction, preferred contact position), physical property predictions (joint axes, articulation type), and target pose proposals before the final trajectory is generated.

## Method

RoboCodeX adopts a BLIP-2-style architecture (ViT-G/14 + Q-Former + LLaMA-13B) augmented with a channel-wise attention vision adapter that aggregates class tokens from four hierarchical ViT stages to capture multi-scale object details. The core reasoning mechanism is a tree-of-thought decomposition: the global instruction is parsed into object-centric units, each expanded via external API calls (AnyGrasp for grasp pose candidates, GAMMA for articulated joint prediction, Open3D for plane detection) and a preference-based selection that uses visual reasoning to pick the optimal grasp from top-10 candidates. Trajectory generation employs zeroth-order optimization over sampled paths evaluated against control cost and occupancy-map collision constraints. Training proceeds in two stages: pre-training on a 147K-sample procedurally generated dataset (HM3D scenes + GPT-4-synthesized tasks and code) mixed 1:1 with general VQA data, followed by SFT on a 49K-sample curated dataset where only code achieving >50% execution success rate is retained, mixed 10:1 with general VQA data to prevent overfitting.

## Results

On five manipulation tasks (Pick&Place, Drawers, Doors, Put Object in Drawer, Multi-stage), RoboCodeX achieves average success rates of 0.80, 0.84, 0.74, 0.68, and 0.64 respectively, yielding an overall average of 74% — a ~17 percentage-point absolute improvement over GPT-4V (57.6% average). On embodied navigation (HM3D/HSSD), RoboCodeX reaches 40.0/40.3% Success and 24.2/22.0 SPL, outperforming L3MVN, Pixel-Nav, and ESC. On general VQA benchmarks, RoboCodeX-13B scores 71.5 on LLaVA-Bench (matching LLaVA-1.5-13B) and 31.0 on MM-Vet.

## Baselines & Comparisons

RoboCodeX outperforms all four LLM/MLLM baselines across every manipulation task. Against GPT-4V (the strongest baseline), RoboCodeX gains +17 pts on Pick&Place (0.80 vs 0.63), +16 pts on Doors (0.74 vs 0.52), +13 pts on Drawers (0.84 vs 0.68), +13 pts on Put Object in Drawer (0.68 vs 0.55), and +14 pts on Multi-stage (0.64 vs 0.50). GPT-4 (text-only) trails GPT-4V on most tasks, confirming the value of visual input, while GPT-3.5 is weakest overall (20% on Doors and Multi-stage) due to poor reasoning and syntax errors. On embodied navigation, RoboCodeX beats L3MVN(GPT-2) by +4.8 SR and +7.7 SPL on HM3D, and surpasses ESC(GPT-3.5) by +0.8 SR and +1.9 SPL. On general VQA, RoboCodeX-13B slightly exceeds LLaVA-1.5-13B on LLaVA-Bench (71.5 vs 70.7) but falls short on MM-Vet (31.0 vs 35.4), indicating its robotic specialization comes at a modest cost to complex multimodal reasoning.

## Relation to Prior Work

This paper extends the code-generation-for-robotics line (ProgPrompt, Code-as-Policies, RoboScript) by replacing purely linguistic inputs with multimodal visual grounding, so that physical preferences, joint constraints, and grasp poses are inferred directly from RGBD observations rather than from text descriptions. Architecturally, it adopts the BLIP-2 paradigm (ViT + Q-Former + LLaMA) and augments it with a tree-of-thought decomposition that partitions a high-level instruction into object-centric manipulation units, each expanded with affordance, physical property, and trajectory sub-predictions. For navigation, it builds on L3MVN's frontier-selection framework but replaces the text-only LLM decision with multimodal visual reasoning over candidate frontiers. The key conceptual departure from prior embodied-AI work is treating executable code as a symbolic bridge between MLLM cognition and low-level operational-space control, enabling cross-platform transfer by swapping configuration files rather than retraining policies.

## Why It Matters / Open Questions

By encoding manipulation preferences and physical constraints in generated code rather than in a fixed policy network, RoboCodeX demonstrates zero-shot cross-platform generalization (Franka → UR5) that is difficult to achieve with end-to-end learned policies, making the approach attractive for multi-robot deployments. The specialized multimodal reasoning dataset (147K pretraining + 49K SFT samples) and the iterative refining pipeline for SFT data address a genuine gap: standard VLM pretraining corpora underrepresent physical-world reasoning. However, the framework remains limited to quasi-structured manipulation (pick-and-place, articulated objects) and struggles with dexterous, force-sensitive, or unstructured tasks (wiping, sweeping), leaving open the question of whether code-based intermediate representations can scale to the full spectrum of embodied interaction.
