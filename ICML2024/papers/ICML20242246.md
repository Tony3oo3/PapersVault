## Problem

Existing planning benchmarks for LLM-powered agents focus on constrained settings with single-objective optimization and fixed ground truths, leaving open whether language agents can handle the multi-constraint, long-horizon, partially observable planning that characterizes real-world tasks. TravelPlanner addresses this gap by introducing a benchmark grounded in travel planning, where agents must simultaneously satisfy explicit user constraints (budget, cuisine, room rules), implicit commonsense constraints (no repeated attractions, reasonable city routes), and dynamic environment constraints (unavailable flights or attractions).

## Input / Output

The agent receives a natural language query specifying departure city, destination state, trip duration (3, 5, or 7 days), group size (1–8), budget, and up to three hard constraints (cuisine, room type, room rule, transportation preference). It interacts with a static sandbox of ~4 million records via six search tools (CitySearch, FlightSearch, DistanceMatrix, RestaurantSearch, AttractionSearch, AccommodationSearch) plus a NotebookWrite tool for working memory. The output is a structured day-by-day plan with fields for current city, transportation (flight number, departure/arrival times), three meals, attractions, and accommodation per day, which is parsed into JSON and checked against all constraints by automated scripts.

## Method

TravelPlanner constructs a closed sandbox environment with ~4 million data entries sourced from public datasets (Kaggle flight data, Google Distance Matrix API, Zomato restaurants, Google Places, Airbnb listings) and modified to prevent data contamination. The 1225 queries are organized into 9 groups (3 trip durations × 3 difficulty levels: Easy = budget only, Medium = budget + one constraint + variable group size, Hard = budget + three constraints), each validated by human annotators to guarantee at least one feasible plan. Evaluation operates in two modes: two-stage (agent collects information via ReAct-style tool use, then plans) and sole-planning (all information is pre-provided, isolating planning skill). Plans are scored on delivery rate, commonsense constraint pass rate (8 dimensions), hard constraint pass rate, and final pass rate, each computed in both micro (per-constraint) and macro (per-plan) aggregation. Five LLMs (GPT-4-Turbo, GPT-3.5-Turbo, Gemini Pro, Mixtral-8x7B-MoE, Mistral-7B-32K) are evaluated with four planning strategies (Direct, ZS-CoT, ReAct, Reflexion) in zero-shot setting, alongside a greedy-search baseline.

## Results

On the TravelPlanner test set (1000 queries), GPT-4-Turbo with ReAct in two-stage mode achieves the highest final pass rate of 0.6%, while all other LLMs (GPT-3.5-Turbo, Gemini Pro, Mixtral, Mistral) score 0%. In sole-planning mode (where information is pre-provided), Direct GPT-4-Turbo reaches 4.4% final pass rate, and Direct Gemini Pro reaches 2.1%. Even the best agent (Direct GPT-4-Turbo) achieves only 23.1% micro hard-constraint pass rate and 15.2% micro commonsense pass rate, far below the 100% delivery rate of greedy search, which itself scores 0% on final pass rate.

## Baselines & Comparisons

GPT-4-Turbo dominates all other LLMs in both modes: in two-stage mode it achieves 0.6% final pass rate versus 0% for GPT-3.5-Turbo, Gemini Pro, Mixtral, and Mistral, and in sole-planning mode Direct GPT-4-Turbo (4.4%) outperforms Direct Gemini Pro (2.1%) by more than 2×. Among planning strategies in sole-planning mode, Direct prompting with GPT-4-Turbo (4.4%) substantially outperforms ReAct (0.7%), Reflexion (0.6%), and CoT (0.4%) with GPT-3.5-Turbo, indicating that the LLM backbone matters far more than the planning strategy. Greedy search, despite achieving 100% delivery rate and 72% micro commonsense pass rate, scores 0% on final pass rate because it cannot satisfy hard constraints like budget. The gap between two-stage and sole-planning modes (e.g., GPT-4-Turbo: 0.6% vs. 4.4%) reveals that information collection via tools is a major bottleneck, with agents using tools less effectively than reference plans (Table 5). Overall, no method approaches human-level performance, as even the best agent satisfies fewer than 25% of hard constraints holistically.

## Relation to Prior Work

This paper carves new ground by introducing a planning benchmark that departs fundamentally from prior LLM agent evaluations. While existing planning benchmarks (Blocksworld, embodied agents, web navigation) focus on single-objective optimization with fixed ground truths, TravelPlanner deliberately generalizes to multi-constraint, long-horizon, partially observable planning where agents must simultaneously satisfy environment, commonsense, and hard user constraints while actively collecting information via tools. It repurposes the tool-use paradigm from ReAct and the reflective loop from Reflexion as evaluation scaffolding rather than as the contribution itself, positioning the benchmark as the primary artifact.

## Why It Matters / Open Questions

The near-total failure of state-of-the-art LLMs (GPT-4 at 0.6% final pass rate) on a task that humans complete in ~12 minutes provides a critical calibration point for the field, revealing that current agents cannot holistically track multiple constraints or sustain coherent long-horizon plans. The consistent gap between micro and macro pass rates across all models highlights a specific architectural limitation—auto-regressive generation cannot naturally perform the backtracking and forward-looking reasoning that multi-constraint planning demands. Open questions include whether more sophisticated search strategies (beyond ReAct/Reflexion), better working-memory mechanisms, or training with constraint-aware objectives could close this gap, and whether the benchmark's difficulty is appropriately calibrated or artificially inflated by its closed-sandbox design.
