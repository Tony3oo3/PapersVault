## Problem

Existing simulation data generation for robotics focuses on scene-level diversity (object poses, instances) rather than task-level diversity, because creating novel tasks requires substantial human effort to specify asset relationships, task progression, and verify achievability. This limits policies trained on simulation data to only tens or hundreds of tasks, hindering task-level generalization. The paper asks whether LLMs can automatically generate diverse, achievable simulation tasks to scale up policy training.
![Teaser figure](../imgs/ICLR20240192/cropped_page1_idx0.webp)

## Input / Output

The LLM task-creation pipeline takes a task name (goal-directed mode) or the current task library state (exploratory mode), a list of available URDF assets, and retrieved reference tasks from the task library, and produces a Python task class implementing scene setup, spatial goals, and language goals for PyBullet. The downstream policy takes top-down RGB-D images (downscaled to 320×160) and a language instruction, and outputs an affordance map that is converted into pick-and-place end-effector actions for a UR5e with a suction gripper. The task library stores validated task codes that serve dual purposes: retrieval context for future generation and training data for LLM finetuning.

## Method

GenSim is a three-component LLM framework: (1) a Task Creator that uses a two-stage prompt chain—first generating a natural-language task description, then generating the corresponding Python code—with few-shot examples retrieved from the task library (RAG); (2) a Task Library that caches validated tasks and employs an LLM critic to filter for novelty, correctness, and non-redundancy before acceptance; and (3) a multitask policy training stage that uses generated task code to produce expert demonstrations for behavior cloning with a CLIPort-style transporter network. The framework operates in two modes: goal-directed (top-down, decomposing a target task into a curriculum of simpler tasks) and exploratory (bottom-up, bootstrapping novel tasks from existing ones). The key insight is that LLM grounding and coding capabilities are distilled into low-level visuomotor policies through the intermediately synthesized simulation data, and that finetuning smaller models (GPT-3.5, Code-Llama with LoRA) on GPT4-generated tasks substantially improves their simulation coding performance.

## Results

On real-world transfer (12 tasks, 10 trials each), GenSim pretrained on 70 GPT4-generated simulation tasks achieves 62.5% average success rate, compared to 39.2% for CLIPort (original 10 human-curated tasks) and 27.5% for no pretraining — a 25% absolute improvement over the CLIPort baseline. In simulation, joint training with GPT4-generated tasks improves in-domain few-shot generalization by over 50% and yields approximately 40% zero-shot transfer to unseen tasks. Policy training success rates on GPT4-generated tasks (75.8% single-task, 74.1% multi-task) are comparable to human-curated CLIPort tasks (76.6% and 76.1%), confirming task achievability.

## Baselines & Comparisons

The primary baseline is CLIPort (Shridhar et al., 2022), the original 10-task human-curated Ravens benchmark used for simulation pretraining. GenSim(70 Tasks) outperforms CLIPort by 23.3 percentage points on average real-world success (62.5% vs. 39.2%), with the largest gains on long-horizon and compositionally novel tasks like build-wheel (3/10 vs. 0/10) and align-block-in-zone (6/10 vs. 2/10). GenSim(50 Tasks) also beats CLIPort (46.7% vs. 39.2%), showing a clear scaling trend with more generated tasks. In simulation, the paper further compares task generation quality across GPT-4, GPT-3.5, and Code-Llama-Instruct-13B (both prompted and LoRA-finetuned), finding that finetuned open-source models approach GPT-4's code generation success rates while GPT-4 remains strongest in goal-directed coding. The paper also ablates against no-pretraining (training from scratch on real data only, 27.5%) and no-adaptation (0%), confirming that both simulation pretraining and minimal real-world fine-tuning are necessary for strong transfer.

## Relation to Prior Work

This paper builds on the CLIPort/Ravens benchmark (Shridhar et al., 2022; Zeng et al., 2021) for the simulation environment, policy architecture (transporter network with affordance prediction), and initial 10 human-curated tasks, but departs from prior simulation data generation work that focused on scene-level diversity (domain randomization, procedural asset generation) by introducing task-level diversity through LLM program synthesis. It connects to the broader LLM-in-robotics literature (task planning, reward design, user interfaces) but occupies a distinct niche: using LLMs as code generators to produce entire simulation task implementations rather than high-level plans or rewards. The retrieval-augmented generation approach with a persistent task library and LLM critic for quality filtering is a novel application of RAG to robotic simulation task creation.

## Why It Matters / Open Questions

The paper demonstrates that LLM-generated simulation tasks can meaningfully improve task-level generalization (50% in-domain, 25% sim-to-real), suggesting a scalable path toward foundational manipulation policies without prohibitive real-world data collection. However, the scope is limited to tabletop pick-and-place with a suction gripper, the generated code still suffers from hallucinations and syntax errors requiring human verification (~10s per task), and the sim-to-real results are based on only 12 tasks with 10 trials each. Open questions include whether the approach scales to dexterous or contact-rich manipulation, whether self-improvement loops (using generated tasks to finetune the generator) can close the quality gap, and how task quality (e.g., misaligned language instructions) quantitatively affects downstream policy performance.
