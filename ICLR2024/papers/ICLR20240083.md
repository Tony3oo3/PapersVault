## Problem

Existing LLM-based neuro-symbolic visual reasoning models (VisProg, ViperGPT) exhaustively generate a full code snippet for every new query instance without reusing or growing modules, and they never verify the generated code against test cases. This contrasts sharply with human learning, where knowledge blocks are accumulated, tested, stored in a library, and reconfigured for new tasks. The paper addresses the absence of a mechanism to grow a reusable module library, validate modules before storage, and transfer learned modules across diverse visual reasoning tasks with only a handful of training examples.

## Input / Output

The system consumes RGB images paired with natural language instructions (or sets of images for Raven/MEWL) along with a small set of training examples (10 for Raven/MEWL, 100–300 for GQA/RefCOCO). During the learning phase, the output is Python code modules (class definitions with function signatures) that are stored in a growing library; during inference, the output is a high-level symbolic program (e.g., COMPARE_ATTRIBUTE(IMAGE, BOX0, BOX1, ATTR)) that is executed against the module library to yield a text answer, bounding box, edited image, tag label, or selected answer image. The module library persists across tasks, so modules learned on GQA can be directly invoked for image editing or knowledge tagging without retraining.

## Method

GENOME operates in three LLM-driven stages. In Module Initialization, the LLM is prompted with existing module signatures and a few training queries to determine whether new modules are needed; if so, it specifies their input/output signatures and decomposes the query into reasoning steps that serve as test cases. In Module Generation, the LLM implements the new module as a Python class, executes it against the test cases, and iteratively debugs (up to 5 rounds, feeding error messages back into the prompt) until the pass rate exceeds a threshold η; only verified modules are added to the library. In Module Execution, the LLM parses each test query into a sequence of symbolic operations over the module library (both pre-defined VisProg/ViperGPT modules and newly learned ones), which are then executed to produce the final answer. The key differentiator from prior work is the closed loop of module verification, library growth, and cross-task module reuse, enabling few-shot adaptation to entirely new reasoning tasks like Raven's Progressive Matrices.

## Results

On GQA (compositional VQA), GENOME achieves 45.6% accuracy with gpt-3.5-turbo-instruct, competitive with VisProg-Instruct (45.4%) and BLIP-2 (44.7%), though below ViperGPT-CodeX (48.1%). On RefCOCO (referring expression comprehension), GENOME scores 69.2%, surpassing ViperGPT-Instruct (62.4%) and KOSMOS-2 (57.4%) but trailing ViperGPT-CodeX (72.0%). On Raven's Progressive Matrices, GENOME reaches 80.1%/67.6%/69.1% (Center/L-R/U-D) using only 10 training examples, substantially outperforming fully-supervised ResNet+DRT (58.1%/65.8%/67.1%) and approaching ALANS-V (98.4%/97.3%/96.4%). On MEWL, GENOME achieves 43.7%/45.3%/41.0% (shape/color/material), beating Aloe (34.2%/33.2%/31.0%) but trailing Flamingo-1.1B on shape and material.

## Baselines & Comparisons

On the primary benchmarks, GENOME (45.6% GQA, 69.2% RefCOCO) is competitive but does not match ViperGPT-CodeX (48.1% GQA, 72.0% RefCOCO), which benefits from the stronger Codex model; however, GENOME clearly outperforms ViperGPT-Instruct (38.2% GQA, 62.4% RefCOCO) and KOSMOS-2 (57.4% RefCOCO) under the same instruct-level LLM. On Raven, GENOME (80.1/67.6/69.1) substantially beats fully-supervised ResNet+DRT (58.1/65.8/67.1) and, on the balanced I-RAVEN variant, surpasses SRAN (78.2/70.1/70.3), LEN (56.4/44.2/44.2), and CoPINet (54.4/51.9/52.5), though it remains well below ALANS-V (98.4/97.3/96.4) which is trained on massive in-domain data. On MEWL, GENOME (43.7/45.3/41.0) outperforms Aloe (34.2/33.2/31.0) across all three attributes but is slightly behind Flamingo-1.1B (49.3/35.3/48.5) on shape and material while leading on color. In transfer-learning settings (image editing and knowledge tagging), GENOME dramatically outperforms VisProg, achieving 55.3% editing accuracy versus VisProg's 16.7%, and 58.8% tagging F1 versus 19.9%, demonstrating the value of learned modules over a fixed pre-defined library.

## Relation to Prior Work

GENOME extends the LLM-based neuro-symbolic visual reasoning line initiated by VisProg (which maps language to a fixed set of handcrafted modules) and ViperGPT (which generates a full code snippet per instance). It departs from both by introducing a growing, reusable module library: new modules are synthesized by the LLM, verified against training examples, and stored for cross-task reuse, drawing an explicit analogy to human incremental skill acquisition. The framework also incorporates a debug-and-retry loop for generated code, a mechanism absent in prior LLM-program-synthesis approaches for vision.

## Why It Matters / Open Questions

The module-reuse and cross-task transfer capability (e.g., GQA-learned modules applied to image editing and knowledge tagging) offers a practical path toward a single neuro-symbolic system that handles diverse visual tasks without per-task retraining, while preserving interpretability through explicit Python programs. However, performance on standard benchmarks (GQA 45.6, RefCOCO 69.2) remains below the strongest baselines (ViperGPT-CodeX 48.1/72.0), and the few-shot Raven results, while competitive, trail fully-supervised methods like ALANS-V. Open questions include whether a universal prompt can replace task-specific ones, whether the approach extends to video/audio modalities, and how the module library scales as the number of tasks grows.
