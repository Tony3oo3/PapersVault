## Problem

Existing layout generation methods represent each element as a numerical tuple (category, x, y, w, h) and treat generation as a pure numerical optimization task, discarding the semantic relationships between elements and the meaning of each attribute. This limits the model's ability to capture complex layout structure and prevents leveraging the rich code and numerical knowledge already embedded in large language models.
![Teaser figure](../imgs/ICLR20241504/cropped_page0_idx0.webp)

## Input / Output

The method takes a partial layout where some element attributes (position, size, or both) are masked, along with a domain prompt (e.g., 'mobile UI') and a task instruction (e.g., 'remaining values'). Numerical values are first quantized via k-Means to one decimal place and embedded as string attributes within an HTML/SVG template using <rect> tags with absolute coordinates. The output is a complete HTML/SVG code string that is directly rendered into a visual layout without any coordinate conversion step, with regex-based format correction and boundary clipping applied to handle generation errors.

## Method

LayoutNUWA reframes layout generation as code completion over HTML/SVG templates using a Code Instruct Tuning (CIT) pipeline with three modules. The Code Initialization module quantizes element positions and sizes via k-Means, constructs a structured HTML template with <rect> tags and a domain/task prompt, and inserts LLM mask tokens for unknown values. The Code Completion module fine-tunes a 7B autoregressive LLM (LLaMA2 or CodeLLaMA) to fill in the masked portions, employing a self-consistency strategy that randomly permutes element order within a mini-batch (K=10 permutations) and a multi-task joint loss across three conditional tasks (T=3) to mitigate autoregressive order sensitivity. The Code Rendering module directly renders the completed code to a visual layout. The key insight is that representing layouts as code lets the model inherit LLMs' pre-trained knowledge of code syntax, numerical tokens, and structural conventions, enabling domain-agnostic training across RICO, PubLayNet, and Magazine simultaneously.

## Results

On the Magazine dataset, LayoutNUWA (CodeLLaMA, Domain-Agnostic) achieves FID scores of 8.791, 6.755, and 7.572 on the C→S+P, C+S→P, and Completion tasks respectively, surpassing the strongest baseline LayoutDM (19.206, 14.265, 15.804) by over 50% in FID. On RICO, LayoutNUWA reaches mIoU of 0.445 (C→S+P) and 0.564 (C+S→P), and on PubLayNet it attains mIoU of 0.385 and 0.483, consistently outperforming all numerical-tuple baselines. The model also achieves near-zero failure rates (0.0–0.3%) compared to 28–34% for GPT-4 zero-shot and 100% for LLaMA2/CodeLLaMA zero-shot.

## Baselines & Comparisons

LayoutNUWA outperforms all six numerical-tuple baselines (LayoutTrans, BLT, LayoutGAN++, MaskGIT, DiffusionLM, LayoutDM) on mIoU and FID across the vast majority of task–dataset combinations. The closest competitor is LayoutDM (Inoue et al., 2023), which LayoutNUWA surpasses by 54–58% in FID on Magazine (e.g., 8.791 vs. 19.206 on C→S+P) and by 18–24% in mIoU on RICO (e.g., 0.564 vs. 0.391 on C+S→P); however, LayoutDM retains a slight FID edge on RICO C+S→P (2.288 vs. 2.870). Against GPT-4 in a zero-shot setting, LayoutNUWA achieves higher mIoU on all three Magazine tasks (e.g., 0.418 vs. 0.362 on Completion) and reduces the generation failure rate from ~29% to 0.3%, confirming that code instruct tuning is essential even for frontier LLMs. The domain-agnostic training setting further amplifies gains over domain-specific baselines, as LayoutNUWA-CL-DA consistently outperforms its domain-specific counterpart (LayoutNUWA-CL-DS) by 3–10% in mIoU, demonstrating cross-domain complementarity that numerical methods cannot exploit.

## Relation to Prior Work

This paper departs from the dominant paradigm in layout generation that represents elements as numerical tuples (c, x, y, w, h) and optimizes them via autoregressive, GAN, or diffusion models (LayoutTransformer, BLT, LayoutDM, etc.). Instead, it repurposes the instruction-tuning paradigm from NLP by reframing layout generation as HTML/SVG code completion, leveraging LLMs' pre-trained structural knowledge of markup languages. The Code Instruct Tuning (CIT) approach is a novel adaptation of instruction tuning specifically designed for the numerical-semantic hybrid nature of layout data, combining k-Means quantization, dynamic HTML templates, and multi-task joint loss with element permutation for order invariance.

## Why It Matters / Open Questions

The reframing of layout generation as code generation opens a path to exploit the vast pre-trained knowledge in LLMs (HTML structure, spatial reasoning in code) that purely numerical models cannot access, and the domain-agnostic training capability is a practical advantage over prior domain-specific methods. Key limitations include the autoregressive bottleneck (slower generation, error propagation), domain confusion under the DA setting, and restriction to simple rectangular elements. Open questions include whether this code-based paradigm extends to more complex design elements (text, images, curves), whether non-autoregressive LLMs or smaller models could achieve comparable results, and how to mitigate the domain confusion issue in multi-domain training.
