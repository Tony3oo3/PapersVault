## Problem

Most code generation research focuses on increasing the quantity and functional correctness of training data while ignoring stylistic attributes like readability, variable naming, and program structure. This paper investigates whether making training code more structured and readable actually improves downstream code generation performance, and identifies which specific data-quality attributes matter.
![Teaser figure](../imgs/ICLR20240599/cropped_page1_idx0.webp)

## Input / Output

The data-cleaning pipeline takes existing (problem statement, Python solution) pairs from APPS and CODE-CONTESTS and produces parallel cleaned datasets where solutions are renamed, modularized into helper sub-functions, and annotated with natural-language plans. Functional equivalence between original and transformed programs is verified using the dataset's input-output test cases as an oracle checker. The downstream code generation task takes a natural language problem statement and produces a Python program, evaluated via strict PASS@K functional correctness.

## Method

The paper proposes a three-step LLM-based data-cleaning pipeline that transforms existing programs while preserving functional correctness: (1) renaming variables to be descriptive and contextually meaningful, (2) decomposing monolithic code into smaller helper sub-functions with a main() entry point, and (3) prepending a natural-language plan that summarizes each function top-down. Each step uses GPT-3.5-Turbo with zero-shot prompting and a simple instruction, with up to 5 retries if the oracle equivalence checker (test-case execution) fails. The key insight is leveraging the disparity in difficulty between generating a solution from scratch and editing an existing one, making the approach effective even when the model cannot independently solve the problem. Fine-tuning CodeLlama-7B on the modularized dataset yields up to 30% improvement over the original, and 15% of the cleaned data outperforms 100% of the original.

## Results

Fine-tuning CodeLlama-7B on the modularized dataset (D_modular) improves PASS@25 on CODE-CONTESTS from 6.4 to 8.3 (30% relative gain) and PASS@1 on APPS-INTRODUCTORY from 18.7 to 22.7 (23% relative gain) compared to fine-tuning on the original dataset. The modularized model also outperforms the larger ALPHACODE-9B and ALPHACODE-41B models on all CODE-CONTESTS metrics (e.g., PASS@100: 12.4 vs. 10.0). In terms of data efficiency, fine-tuning on just 15% of the cleaned D_modular dataset matches the performance of fine-tuning on the entire original dataset.

## Baselines & Comparisons

The proposed modularized CodeLlama-7B outperforms both ALPHACODE-9B and ALPHACODE-41B on all three CODE-CONTESTS metrics (PASS@10: 6.1 vs. 5.0, PASS@25: 8.3 vs. 7.0, PASS@100: 12.4 vs. 10.0), despite being a 7B model fine-tuned on a cleaned subset of the same training data. It also beats CODE-DAVINCI-002 on PASS@10 (6.1 vs. 3.0) and PASS@100 (12.4 vs. 7.5). However, the method still lags behind GPT-3.5-TURBO (PASS@100: 12.4 vs. 18.2) and GPT-3.5-TURBO + Brainstorm (PASS@100: 12.4 vs. 29.3), which are substantially larger closed-source models. On APPS-INTRODUCTORY, the modularized model (PASS@1 = 22.7) matches CODE-DAVINCI-002 (PASS@1 = 22.1) but falls short on PASS@10 (36.9 vs. 50.2) and PASS@25 (42.6 vs. 58.7). The paper also shows that a distillation baseline (D_distill, generated directly by GPT-3.5-TURBO) underperforms the transformation-based D_modular dataset, confirming that cleaning existing code is more effective than generating new solutions.

## Relation to Prior Work

This paper extends the data-quality-for-LLM-training line of work (Li et al. 2023d on textbook-quality pretraining data, Zhou et al. 2023 and Cao et al. 2023 on instruction data curation) into the code domain, but departs from the dominant synthetic-generation approach (Gunasekar et al. 2023, Haluptzok et al. 2023) by transforming existing programs rather than generating new ones from scratch. The three-step pipeline (renaming → modularization → planning annotations) draws on program decomposition literature (Zhou et al. 2022, Wang et al. 2023) and chain-of-thought prompting (Wei et al. 2022), repurposing them as data-cleaning operations validated by an oracle equivalence checker. The key conceptual departure is leveraging the asymmetry between generating a solution from scratch and editing an existing one, making the approach applicable even when the transformation model cannot solve the problem independently.

## Why It Matters / Open Questions

The finding that 15% of cleaned data outperforms 100% of original data has direct practical implications for training efficiency in code LLMs, and the modularization-as-data-quality insight generalizes beyond algorithmic code generation to broader software engineering tasks. The planning disentanglement experiment reveals a critical open problem: supervised learning on LLM-generated plans fails to improve planning because the plans themselves are imprecise, yet the model can follow gold plans accurately—suggesting the bottleneck is plan generation, not plan execution. A key limitation is reliance on proprietary models (GPT-3.5-Turbo/GPT-4-Turbo) for transformation, and the authors note that self-training with open models plus oracle checkers is a promising but unexplored direction.
