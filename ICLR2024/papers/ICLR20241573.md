## Problem

Existing approaches to augment LLMs with tools rely on general-purpose APIs or create unverified, non-reusable tools, limiting their ability to handle specialized tasks. Prior tool-creation methods (LATM, CREATOR) produce at most one tool per task or per test case, and retrieval from large toolsets depends on simplistic similarity matching that fails to pinpoint relevant tools. CRAFT addresses both gaps by building large, validated, reusable toolsets and retrieving from them via multi-view matching.

## Input / Output

At inference, the evaluated LLM (GPT-3.5-Turbo or GPT-4) receives a task-specific input—an image plus a text question for VQA, a table plus a natural-language question for tabular processing, or a text math problem—and first generates candidate function names and docstrings describing what it needs. These are used to retrieve up to three tool snippets from the pre-built toolset, which are then injected into the prompt. The LLM generates Python code that invokes the retrieved tool functions; the code is executed in an interpreter to produce a final text or numerical answer.

## Method

CRAFT is a training-free, plug-and-play framework with two offline/online components. Offline, a toolset is built via a four-step pipeline: (1) iterative min-max sampling of problems from a source dataset using SimCSE cosine similarity to ensure diversity, with GPT-4 generating executable Python solutions that are kept only if they produce correct outputs; (2) abstraction, where GPT-4 rewrites specific solutions into generic, reusable functions with placeholder arguments, descriptive names, and docstrings; (3) validation, where GPT-4 must solve the original problem using only the abstracted tool, discarding tools that fail; and (4) deduplication, where tools sharing the same function name and argument count are grouped and GPT-4 selects the most comprehensive one. Online, retrieval uses a multi-view matching strategy: the LLM generates a target function name f_t and docstring d_t for the query, and SimCSE similarity is computed independently against each tool's original problem q_i, function name f_i, and docstring d_i; the three ranked lists are merged by frequency and the top three tools (appearing in at least two views) are selected. The retrieved code snippets are appended to the prompt so the LLM can call them as APIs in its generated solution.

## Results

Using GPT-3.5-Turbo as the backbone, CRAFT achieves 45.4 SAcc / 48.8 F1 on GQA, 33.4 SAcc / 43.0 F1 on OK-VQA, and 30.8 SAcc / 40.6 F1 on A-OKVQA, representing an average 43.16% relative F1 improvement over the best baselines on vision-language tasks. On tabular processing (TabMWP), CRAFT reaches 88.4% accuracy, and on mathematical reasoning (MATH algebra), it achieves 68.1% accuracy. The paper also shows that scaling the backbone to GPT-4 further improves CRAFT (e.g., 55.6 SAcc on GQA vs. 51.4 for ViperGPT), and performance increases monotonically as the toolset grows from 0 to 525 tools.

## Baselines & Comparisons

CRAFT substantially outperforms the vanilla tool-using baselines (ViperGPT for VQA, Program-of-Thoughts for TabMWP/MATH) across all datasets, with the largest gains on OK-VQA (33.4 vs. 15.4 SAcc, +18.0) and A-OKVQA (30.8 vs. 15.6 SAcc, +15.2). Among prior tool-creation methods, LATM (Cai et al.) performs poorly on every dataset (e.g., 9.3% on TabMWP), while CREATOR (Qian et al.) is competitive on MATH (65.0 vs. 68.1) but still trails CRAFT on all other benchmarks. For retrieval baselines built on the same toolset, CRAFT's multi-view matching beats both SimCSE (Qin et al.) and BM25 (Patil et al.) on all VQA datasets and MATH, with the sole exception being TabMWP where BM25 edges out CRAFT by 0.8 points (89.2 vs. 88.4), which the authors attribute to the dataset's relatively simple patterns. External Python libraries (NumPy, SciPy, Pandas, SymPy) fail to improve over vanilla and sometimes hurt performance (e.g., 41.1 vs. 58.2 on MATH), underscoring the need for task-specific toolsets.

## Relation to Prior Work

CRAFT carves new ground at the intersection of tool learning and tool creation for LLMs. Prior tool-learning work (TALM, Toolformer, Gorilla, ToolLLM) relies on pre-existing general-purpose APIs, while the few tool-creation efforts (LATM creates one tool from three samples; CREATOR creates a per-query tool) produce limited, non-reusable, or unverified toolsets. CRAFT departs from both by constructing a large, validated, and deduplicated toolset through an iterative generation-abstraction-verification-deduplication pipeline, and by replacing single-view similarity retrieval with a multi-view matching function over problem text, function names, and docstrings. The framework is training-free and plug-and-play, positioning it as a practical middle ground between fine-tuning and ad-hoc tool use.

## Why It Matters / Open Questions

CRAFT offers a low-cost (~$2,500), training-free recipe for specializing off-the-shelf LLMs to new domains, and the released toolsets provide immediately reusable assets for downstream tasks. The demonstrated scalability—performance continues to rise as the toolset grows—suggests a path toward ever-larger, domain-specific tool libraries without retraining. Key limitations remain: the approach is restricted to tasks solvable via executable code, its effectiveness is tightly coupled to the backbone model's tool-manipulation ability (open-source models perform near-randomly), and the diminishing gains with stronger backbones (GPT-4 vs. GPT-3.5-Turbo) hint at a self-guidance ceiling. Open questions include extending beyond code-based tools (e.g., pseudocode or natural-language tool descriptions) and eliciting reliable tool-use in open-source LLMs.
