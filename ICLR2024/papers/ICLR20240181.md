## Problem

LLM-based agents face a critical challenge in navigating expansive action spaces (hundreds of candidate API functions per step): unidirectional methods (open-loop, greedy closed-loop) suffer from error propagation and limited exploration, while existing tree search methods (DFS, MCTS) require exhaustive traversal of nearly all potential actions, making them computationally prohibitive. The paper asks how to efficiently balance exploration and exploitation in large action spaces without exhaustive search.
![Teaser figure](../imgs/ICLR20240181/cropped_page1_idx0.webp)

## Input / Output

The method takes a natural language task description, a pool of m candidate API function definitions, and in-context demonstration examples as input. It produces an ordered sequence of API function calls (the solution plan) that, when executed sequentially, yields the final answer. For tool-use tasks, each node in the search tree is a specific API call with parameters; for math reasoning, nodes are intermediate reasoning steps in natural language. The search is bounded by a maximum step limit T (default 20) and samples k=10 i.i.d. actions per expansion via self-consistency.

## Method

ToolChain* formulates tool-use planning as an A* best-first search over a decision tree where each node represents a potential API call. The cost function f(n) = g(n) + h(n) combines a cumulative cost g(n) (geometric mean of a task-specific LCS-based heuristic against a long-term memory of successful plans and a self-consistency frequency score) with a future cost h(n) (geometric mean of a relative-position heuristic from long-term memory and an LLM imagination score measuring how many current steps appear in the LLM's imagined completion). Unlike MCTS, which requires multi-step rollouts to a terminal state, ToolChain* expands only the single next step per iteration, requiring just one LLM call per expansion. This design allows erroneous actions to be progressively de-prioritized through accumulating cost, enabling the search to abandon faulty branches and converge on globally optimal solutions within a manageable number of steps.

## Results

On ToolBench (4 tool-use environments), ToolChain* achieves 68.5% average success rate with GPT-3.5-turbo and 74.7% with GPT-4, surpassing the strongest baselines (MCTS at 64.8%/72.1%, AdaPlanner at 63.5%/72.1%) by 3.7% and 2.5% respectively. On GSM8K math reasoning, it reaches 77.0% (GPT-3.5-turbo) and 93.5% (GPT-4) accuracy, and on the harder ToolQA subset it achieves 52.0% and 84.0%. In terms of efficiency, ToolChain* requires 7.35× less time than MCTS on planning tasks and 2.31× less on reasoning tasks, while being 37.2% faster than the most efficient tree-search baseline (ToT-BFS).

## Baselines & Comparisons

ToolChain* consistently outperforms all eight baselines across both LLM backbones. Against the strongest closed-loop method AdaPlanner, it gains 5.0% (GPT-3.5) and 2.6% (GPT-4) average success rate on ToolBench, attributed to AdaPlanner's reliance on high-quality environmental feedback that is unavailable in larger action spaces. Against the strongest tree-search baseline MCTS, ToolChain* improves by 3.7% (GPT-3.5) and 2.6% (GPT-4) while being 415.84% faster, since A* search requires only one-step expansion versus MCTS's multi-step rollout. On GSM8K, ToolChain* beats Self-Consistency by 0.9% (GPT-3.5) and 1.1% (GPT-4), and on the harder ToolQA subset the gap widens to 5.0% and 6.0%, respectively, indicating superior handling of complex multi-step reasoning. On ScienceQA, ToolChain* (as a plug-and-play replacement for Chameleon's planner) improves accuracy by 0.8% over Chameleon (80.7% vs. 79.9%). The open-loop GPT baseline and greedy ReAct are the weakest, trailing ToolChain* by 9.3% and 9.2% on average (GPT-3.5), confirming that unidirectional exploration is insufficient for expansive action spaces.

## Relation to Prior Work

ToolChain* sits at the intersection of classical A* search and LLM-based agent planning, departing from the dominant MCTS-based approach (RAP/Hao et al.) by replacing expensive multi-step rollouts with single-step expansion guided by a composite cost function. It builds on the tree search framing introduced by Tree-of-Thoughts (Yao et al.) but replaces its heuristic DFS/BFS traversal with a principled best-first search using task-specific cumulative cost (long-term memory LCS scores + self-consistency frequency) and future cost (memory-based positional heuristics + LLM imagination). The method also draws on self-consistency (Wang et al.) for action sampling and DeBERTa-based NLI for semantic deduplication, integrating these into a unified cost function rather than using them as standalone decoding strategies.

## Why It Matters / Open Questions

The paper demonstrates that a well-designed A* cost function can match or exceed MCTS accuracy while being 7× faster, making tree search practically viable for LLM agents in real-world tool-use settings where latency matters. Its plug-and-play applicability across GPT-3.5, GPT-4, and LLaMA-2 (with fine-tuned StepLLaMA-2) broadens its relevance beyond closed-source APIs. Key limitations include remaining slower than open-loop systems, dependence on seed data for the long-term memory heuristic, and the trade-off between search depth and solution quality that constrains deployment in time-sensitive applications. Open questions include whether the cost function design generalizes to truly open-ended action spaces without any reference plans, and whether the tree structure can be pruned further for real-time use.
