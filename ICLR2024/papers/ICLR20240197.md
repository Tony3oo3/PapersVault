## Problem

Open-source LLMs lag far behind closed-source models like GPT-4 Code Interpreter on mathematical reasoning, scoring only 56.8% and 13.5% on GSM8K and MATH respectively, versus 97% and 69.7% for GPT-4 Code Interpreter. While code-augmented methods (PAL, PoT, CSV) show strong gains with closed-source models, no effective recipe exists to make open-source models replicate the GPT-4 Code Interpreter's ability to seamlessly interleave natural language reasoning, code generation, and execution-result feedback.

## Input / Output

The model takes a math problem as plain text input and produces an LCE (Language, Code, Execution) solution: a sequence of blocks delimited by special tokens (<|text|>, <|code|>, <|execution|>, <|endofblock|>) that alternate between natural language reasoning, Python code, and execution output. During inference, code blocks are executed in a persistent Jupyter Notebook session (preserving variables across blocks), and the resulting output is appended to the context before the model continues autoregressive generation, allowing up to 32 LCE blocks per solution. The final block contains the numerical answer.

## Method

MathCoder introduces the MathCodeInstruct dataset (80k problems) built in two stages: first, GPT-4 Code Interpreter-style LCE solutions are collected for GSM8K and MATH training sets to fine-tune CodeLlama-34B into MathCoder-Initial; second, a novel 'problem interpolation' prompt asks GPT-4 to generate intermediate-difficulty problems between a GSM8K and a MATH example, with solutions produced by MathCoder-Initial via self-distillation (n=3 self-consistency filtering). For training, special tokens delimit text, code, and execution components, and the cross-entropy loss is computed only on natural language and code tokens while execution-result tokens are zeroed out, so the model learns to reason and write code but not to hallucinate outputs. At inference, a Jupyter Notebook executes each detected code block in real time, appends the result to the context, and the model continues generating the next reasoning block—replicating the GPT-4 Code Interpreter loop within an open-source Llama-2 or CodeLlama backbone.

## Results

MathCoder achieves state-of-the-art results among open-source LLMs on all five evaluation datasets. The largest model, MathCoder-L-70B (Llama-2-70B base), scores 83.9% on GSM8K and 45.1% on MATH, with an average of 73.1% across all five benchmarks. The CodeLlama-based variant, MathCoder-CL-34B, achieves 81.7% on GSM8K and 45.2% on MATH (average 70.2%), surpassing WizardMath-70B by +24.0 points in average accuracy. Even the smallest model, MathCoder-L-7B, outperforms WizardMath-70B by +4.5 points in average score.

## Baselines & Comparisons

MathCoder decisively outperforms all open-source baselines. MathCoder-L-7B (50.7 avg) surpasses WizardMath-70B (46.2 avg) by +4.5 points, and MathCoder-CL-34B (70.2 avg) exceeds WizardMath-70B by +24.0 points, with the largest gap on MATH (+22.5) and Mathematics (+58.8). Against Llama-1 RFT-34B (27.9 avg), MathCoder-CL-34B leads by +42.3 points. Among closed-source models, MathCoder-CL-34B beats ChatGPT-3.5 (80.8 GSM8K, 34.1 MATH) and PaLM-2 (80.7 GSM8K, 34.3 MATH) on both GSM8K and MATH, and the paper reports it also outperforms GPT-4 (without code interpreter) on MATH. However, a substantial gap remains versus GPT-4 Code Interpreter (97.0 GSM8K, 69.7 MATH), which still leads by 15.3 and 24.5 points respectively. The CodeLlama-based variants consistently outperform their Llama-2 counterparts of the same size (e.g., +4.1 avg for 7B, +3.0 avg for 13B), attributed to CodeLlama's stronger code generation ability from additional code pre-training.

## Relation to Prior Work

This paper directly extends the GPT-4 Code Interpreter paradigm (Zhou et al., 2023a) — interleaved natural language, code, and execution results (LCE) — from a closed-source prompting setting to a supervised fine-tuning recipe for open-source LLMs. It departs from prior code-based math methods (PAL, PoT) that use code-only solutions and from prior math instruction-tuning efforts (WizardMath, RFT) that rely solely on natural-language Chain-of-Thought, by unifying both modalities in a single training corpus. The self-consistency filtering from Wang et al. (2023a) is adopted for data quality control, and the novel problem interpolation prompting strategy bridges the difficulty gap between GSM8K and MATH, a data-augmentation idea not present in either line of work.

## Why It Matters / Open Questions

MathCoder demonstrates that open-source models can be brought substantially closer to GPT-4 Code Interpreter performance through targeted instruction tuning on LCE-format data, with the 7B model already surpassing the 70B WizardMath — a practical recipe for resource-constrained settings. The released MathCodeInstruct dataset and models lower the barrier for reproducing code-augmented math reasoning. Key limitations remain: dependence on GPT-4 for seed data generation caps the ceiling, uni-modal architecture struggles with geometry, and the gap to GPT-4 Code Interpreter (69.7% vs. 45.2% on MATH) is still large. Open questions include whether the LCE format generalizes to other reasoning domains and whether the self-distillation loop can be iterated to close the remaining gap without additional GPT-4 calls.
