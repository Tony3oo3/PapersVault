## Problem

Activation memory for long-sequence inference grows exponentially with sequence length and can exceed parameter memory by orders of magnitude, yet existing solutions are either limited to specific modules (e.g., FlashAttention for attention), introduce numerical errors (quantization), or rely on manual chunk design that is suboptimal and impractical for diverse models and input lengths. No automated, general-purpose system existed to reduce activation memory across arbitrary computation graphs while controlling speed loss.

## Input / Output

AutoChunk consumes a model's computation graph in PyTorch FX intermediate representation together with a user-specified memory budget (peak activation memory cap). It produces a chunk execution plan specifying which node regions to chunk, along which tensor dimension, and at what chunk size, then code-generates a modified computation graph that is recompiled and invoked at runtime. The user-facing API is a single call `model = autochunk(model, memory_budget)`, and the output model processes the same long input sequences (1D text, 2D images, protein sequences) with reduced peak activation memory.

## Method

AutoChunk is a compiler system that iteratively applies three passes—estimation, chunk search, and chunk selection—until the memory budget is met. The chunk search pass uses a bottom-up breadth-first algorithm over the computation graph to enumerate all legal chunk regions, guided by four formal rules (basic chunkability, output alignment, flow traceability, and unique setting) that ensure chunked outputs equal original outputs. The chunk selection pass employs dynamic programming with beam search over a composite cost function combining macro terms (number of nodes and total FLOPs in the chunked region) and micro terms (computation density per node and stride of the chunked dimension), motivated by the observation that 70% of nodes consume less than 30% of peak activation memory. A graph optimization step prunes irrelevant chunk flows within a region to avoid redundant computation, and a two-stage search with a local window of size k reduces complexity from O(N³) to O(ζk²N). At runtime, PyTorch FX code generation automatically applies the selected chunk plans to the computation graph.

## Results

AutoChunk reduces over 80% of activation memory while keeping speed loss within 10%, and extends maximum inference sequence length by 3.2× (2D inputs: AlphaFold, ViT, UNet) to 11.7× (1D inputs: GPT). At 40–50% of the original activation memory budget, throughput loss is within 3%; at 20% memory, loss stays below 10%. Against the expert-designed chunk from OpenFold on AlphaFold, AutoChunk reduces minimum activation memory by 30.6–34.4% and achieves a 9.2–14.6% throughput speedup at matched memory budgets.

## Baselines & Comparisons

The paper compares AutoChunk against two baselines. First, against fused attention kernels (memory-efficient attention, Rabe & Staats 2022): even when the O(n²) attention memory is already eliminated by the fused kernel, AutoChunk further reduces total activation memory by over 70% at only 5% speed loss, showing that non-attention modules still dominate memory for long sequences. Second, against the expert-designed chunk strategy from OpenFold (Ahdritz et al. 2022) on AlphaFold: AutoChunk lowers the minimum achievable activation memory by 30.6–34.4% and delivers a 9.2–14.6% throughput speedup when both methods are constrained to the same memory budget. AutoChunk wins on both memory efficiency and speed in every reported comparison, with the largest gains appearing at longer sequence lengths where the expert chunk runs out of memory beyond 1024 tokens.

## Relation to Prior Work

AutoChunk generalizes the manual chunking technique introduced in AlphaFold, Swin Transformer, and Reformer—where experts hand-crafted chunk regions for specific modules like attention and feed-forward—into a fully automated compiler system. It departs from prior deep learning compilers (XLA, TVM, TorchInductor) that focus on operator fusion and loop tiling for speed, by targeting activation memory as the primary optimization objective through a dedicated chunk search and selection pipeline. Unlike checkpointing-based methods (Jain et al., 2020) that reduce activation memory during training, AutoChunk is specifically designed for inference and operates on the computation graph via PyTorch FX code generation.

## Why It Matters / Open Questions

By reducing activation memory by over 80% with less than 10% speed loss, AutoChunk makes long-sequence inference feasible on hardware with limited GPU memory, extending maximum sequence length by 3.2×–11.7× across 1D and 2D inputs. The finding that automated chunk selection outperforms expert-designed strategies in both memory and speed challenges the assumption that manual tuning is necessary for performance-critical inference configurations. Open questions include whether the approach extends to training (the authors mention this as future work), how it scales to even more complex architectures with irregular memory patterns, and whether the DP-based selection generalizes to multi-GPU or distributed settings.
