## Problem

ConvBN blocks in transfer learning face a dilemma: Eval mode is stable but stores the full convolutional output Y for backpropagation, nearly doubling memory; Deploy mode fuses parameters for efficiency but is theoretically unstable for training because the weight-scaling and gradient-scaling coefficients are inverses of each other. No existing mode simultaneously achieves Eval-level stability and Deploy-level efficiency for fine-tuning pre-trained models.

## Input / Output

The method takes a feature map tensor X of shape [N, C_in, H_in, W_in] and the pre-trained ConvBN parameters (convolution weight ω, bias b, tracked BN statistics μ̂/σ̂, and affine parameters γ/β) as input, and produces the same normalized output Z as Eval mode in both forward and backward passes. It is a drop-in replacement requiring no architectural modification—only a one-line configuration flag in PyTorch or MMCV/MMEngine—and works for any CNN containing consecutive Conv+BN or TransposedConv+BN or Linear+BN blocks, including architectures with skip connections and mixed precision.

## Method

The paper first proves that Deploy mode is unstable because the scaling coefficient γ/√(σ̂²+ε) applied to weights is the exact inverse of the coefficient applied to gradients, so channels with small or large scaling suffer amplified gradient updates. The proposed Tune mode resolves this by computing the fused parameters ω' = ω·γ/√(σ̂²+ε) and b' = (b−μ̂)·γ/√(σ̂²+ε)+β dynamically on-the-fly each iteration, then performing a single convolution Z = ω'⊛X + b' for the forward pass (matching Deploy efficiency). Crucially, the backward pass differentiates through the original parameters (ω, b, γ, β) rather than the fused ones, making gradients identical to Eval mode and preserving training stability. This reduces per-block memory from X+Y to X+ω' (since feature maps Y are orders of magnitude larger than kernel weights ω') and replaces an affine transform on the large feature map with one on the small weight tensor. The mode is automatically activated via PyTorch's torch.fx compiler, which identifies consecutive Conv+BN patterns without manual intervention.

## Results

On three fine-grained classification datasets (CUB-200, Aircrafts, Stanford Cars) with a ResNet-50 backbone, Tune mode matches or slightly exceeds Eval mode accuracy (e.g., 83.20% vs 82.62% on CUB-200) while reducing GPU memory by ~37% (12.32 GB vs 19.50 GB) and iteration time by ~8–9%. On COCO object detection across 9 detector-backbone configurations, mAP changes are within ±0.003 of Eval mode while memory is reduced by 20–43%. In adversarial example generation across 6 architectures, Tune mode achieves 5–8% speedup and 30–45% memory savings over Eval mode.

## Baselines & Comparisons

Against Inplace-ABN (Bulo et al., 2018), Tune mode is a clear winner on all three axes: it saves substantially more memory (38.3% reduction vs. 16.2%), is faster rather than slower (12.3% speedup vs. 9.1% slowdown), and preserves accuracy (83.20% vs. 74.80% on CUB-200; 85.90% vs. 78.23% on Aircrafts), because Inplace-ABN modifies the network architecture with invertible activations while Tune mode is a drop-in replacement. Against FrozenBatchNorm from Detectron2 (Wu et al., 2019), Tune mode maintains the baseline mAP (e.g., 0.3832 for Faster R-CNN ResNet-50) whereas FrozenBatchNorm drops to 0.3790, because freezing BN parameters limits the network's expressive power. The primary comparison is against Eval mode (the standard practice in transfer learning): Tune mode achieves functionally identical forward and backward propagation, so accuracy is preserved, while the on-the-fly weight fusion eliminates the need to store the intermediate feature map Y, yielding the 20–44% memory and 7–14% time reductions reported throughout the paper.

## Relation to Prior Work

This paper builds on the well-known ConvBN fusion technique used at deployment time (Markuš, 2018), where convolution, normalization, and affine transforms are collapsed into a single convolution with pre-computed parameters. It departs from this by computing the fused parameters on-the-fly during training rather than once-for-all, thereby preserving the gradient dynamics of Eval mode while achieving near-Deploy-mode efficiency. The work also contrasts with memory-reduction alternatives like Inplace-ABN (Bulo et al., 2018), which trades speed and accuracy for memory savings, and FrozenBatchNorm (Detectron2), which sacrifices trainable parameters. The theoretical analysis of Deploy-mode instability—showing that weight and gradient scaling coefficients are inverses—is a clean formalization of a phenomenon practitioners had observed empirically but not rigorously explained.

## Why It Matters / Open Questions

The practical impact is significant: Tune mode is integrated into PyTorch 2.2+ and MMCV/MMEngine as a one-line configuration, giving every CV practitioner doing transfer learning a free 20–44% GPU memory reduction and 5–14% speedup without modifying model architecture or hyperparameters. The main limitation is that Tune mode requires pre-trained running statistics, so it cannot be used for training from scratch (though Appendix K shows it can be activated in late pre-training stages). An open question is whether similar on-the-fly parameter fusion strategies can be extended to other normalization layers (GroupNorm, LayerNorm) or to transformer architectures where the memory bottleneck lies elsewhere (attention matrices rather than convolutional feature maps).
