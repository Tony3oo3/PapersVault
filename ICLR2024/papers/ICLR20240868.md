## Problem

Transformer-based code translation models like TransCoder-ST produce uninterpretable outputs—there is no way to trace which training snippet contributed to each generated token—and improving their accuracy requires expensive retraining with only marginal gains. This paper asks whether a lightweight, interpretable post-hoc correction layer can substantially boost translation accuracy without retraining the underlying Transformer.
![Teaser figure](../imgs/ICLR20240868/cropped_page2_idx0.webp)

## Input / Output

The method takes a wrong Python translation (one of beam_size=10 candidates from TransCoder-ST that failed unit tests) together with its corresponding unit test cases. Before retrieval, a unified name rule is applied to standardize all non-built-in identifiers (parameters → a₀, a₁, …; function → func; variables → b₀, b₁, …), and the (replacement, name) pairs are stored for optional name recovery. The output is a corrected Python function that passes the unit tests, accompanied by a per-token decision-making basis: for each generated token, the system returns the ⟨src_func, tgt_func_pref⟩ snippet from the datastore that justified that token, making the correction traceable.

## Method

The core mechanism is a kNN-retrieval-based error correction datastore (ECD) built from error correction language pairs—each pair consisting of the first failed and first successful Python translation of the same Java function. Keys are encoder representations of ⟨src_func, tgt_func_pref⟩ extracted from a pre-trained Transformer, and values are tokenizations of the ground-truth target token; at inference, the current wrong-translation prefix is encoded as a query, the k nearest keys are retrieved, and a temperature-scaled softmax over distances yields the corrected token distribution. The kNN-ECS_m variant splits the same dataset into m sub-datastores connected in series, so a wrong translation that still fails unit tests after one sub-datastore is re-fed into the next, enabling multi-round correction with diverse data flows that capture information in both high- and low-density regions of the datastore. The unified name rule further reduces retrieval noise by collapsing diverse rare identifiers into a homogeneous schema, shifting similarity matching toward code logic and structure rather than superficial naming differences.

## Results

On the Java-to-Python translation task, the proposed kNN-ECS₁₈ with the unified name rule achieves 89.9% functional equivalence (unit-test-passing rate), improving TransCoder-ST's baseline of 68.9% by 21.0 percentage points. The single-datastore variant kNN-ECD reaches 84.5%, while the distributed multi-datastore kNN-ECS_m variants range from 86.5% (m=3) to 89.9% (m=18). Applying the unified name rule consistently adds 1.7–6.5% over the no-rename variants (kNN-ECD*/kNN-ECS_m*), and the rule alone yields 5.1% preliminary corrections before any datastore retrieval.

## Baselines & Comparisons

The paper's primary comparison is against TransCoder-ST (68.9%), the state-of-the-art unsupervised code translation model that the error correction method is designed to augment; kNN-ECS₁₈ with the unified name rule outperforms it by 21.0 percentage points (89.9% vs. 68.9%). Against the earlier TransCoder (49.0%) and DOBF (52.7%) baselines, the improvement is even more pronounced (40.9 and 37.2 points respectively), though these are not direct competitors since they lack the unit-test-guided fine-tuning of TransCoder-ST. The j2py baseline (38.3%) represents a rule-based approach and is far outperformed. Within the proposed method family, the distributed kNN-ECS_m consistently outperforms the single-datastore kNN-ECD by 2.1–7.4 points (e.g., 89.9% vs. 84.5% at m=18), and the unified name rule adds a further 1.7–6.5% over the no-rename variants, confirming that reducing identifier noise is a meaningful contributor to correction quality.

## Relation to Prior Work

This paper repurposes the kNN-MT retrieval framework (Khandelwal et al., 2020), originally designed for natural language translation, into a non-parametric error correction mechanism for code translation. It builds directly on TransCoder-ST (Rozière et al., 2022) as the base translator whose beam-search outputs are repaired, and on TransCoder (Rozière et al., 2020) as the encoder/decoder used to generate datastore keys. The key conceptual departure from the dominant retraining paradigm in code translation (TransCoder, DOBF, TransCoder-IR) is the shift to a retrieval-based correction loop that avoids any model weight updates, while the distributed multi-datastore (ECS_m) structure and the unified name rule represent novel architectural and preprocessing contributions not present in prior kNN-MT or code anonymization work.

## Why It Matters / Open Questions

The paper demonstrates that a non-parametric, interpretable correction layer can close a large gap (68.9% → 89.9%) in code translation accuracy without the computational cost of retraining, offering a practical and auditable alternative for deployment settings where model transparency matters. However, the evaluation is confined to Java→Python and relies on a test set constructed from translations that already have a known correct counterpart, limiting generalizability claims. Open questions include whether the approach extends to other language pairs, whether it degrades gracefully when unit tests are unavailable, and how datastore size and retrieval latency scale to production-scale codebases.
