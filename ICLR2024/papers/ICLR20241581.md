## Problem

Open-source LLMs lag far behind closed-source models (GPT-4, PaLM-2) on mathematical reasoning benchmarks. Existing remedies are either computationally expensive continued pre-training on 100B+ tokens of math web data, or dataset-specific fine-tuning (e.g., WizardMath on GSM8K+MATH) that boosts in-domain accuracy but degrades out-of-domain performance by up to 10%. The paper asks whether a lightweight, generalizable instruction-tuning recipe can close this gap across diverse math fields and complexity levels without dataset-specific overfitting.

## Input / Output

The model receives a math problem as plain text (open-formed or multiple-choice) and, by default, generates a step-by-step natural-language CoT solution ending in a final answer. Appending the trigger phrase 'Let's write a program to solve the problem' switches the model to PoT mode, producing an executable Python program whose stdout is the answer. At inference time, the hybrid decoding strategy first attempts PoT; if the generated program is not executable, it falls back to CoT. Decoding is capped at 2048 tokens, and for multiple-choice questions a re-prompting step maps the generated answer to the nearest option if no explicit letter is produced.

## Method

The core contribution is MathInstruct, a 260K (instruction, response) dataset that hybridizes CoT and PoT rationales (72% CoT, 28% PoT) across 13 math sources spanning grade-school arithmetic through college-level abstract algebra and formal logic, with six subsets newly curated via GPT-4 prompting and validated by executing generated programs against ground-truth answers. Llama-2 and Code Llama base models (7B–70B) are fine-tuned on MathInstruct using standard supervised instruction tuning (Alpaca-style format, lr 2e-5/1e-5, batch 128, cosine schedule, 3 epochs, DeepSpeed ZeRO-3 for 34B/70B). The key design insight is complementary coverage: CoT rationales preserve language-based reasoning for abstract and commonsense problems where no Python API exists, while PoT rationales teach the model to offload precise computation (e.g., sympy for quadratic roots, numpy for eigenvalues) to an external interpreter. A simple hybrid decoding heuristic—attempt PoT first, fall back to CoT on execution failure—further lifts accuracy on every test set without additional training.

## Results

MAmmoTH-7B achieves 31.5% on MATH (competition-level), exceeding the previous open-source SoTA WizardMath-7B (10.7%) by 21 percentage points, and MAmmoTH-Coder-34B reaches 43.6% on MATH, surpassing GPT-4's CoT result (42.5%). Across all nine evaluation datasets, MAmmoTH models deliver an average accuracy gain of 16–32% over the best existing open-source baselines at each scale. Out-of-domain gains are even more pronounced: MAmmoTH-Coder-34B achieves 63.2% average OOD accuracy versus 31.7% for Platypus-34B, a 31.5-point improvement.

## Baselines & Comparisons

MAmmoTH decisively outperforms WizardMath (the prior open-source SoTA on MATH) at every scale: MAmmoTH-7B scores 31.5% vs. WizardMath-7B's 10.7% on MATH, and MAmmoTH-70B scores 41.8% vs. WizardMath-70B's 22.7%. On out-of-domain benchmarks, the gap widens further—MAmmoTH-7B achieves 48.1% average OOD accuracy versus WizardMath-7B's 28.6%, confirming that dataset-specific tuning (GSM8K+MATH only) harms generalization. MAmmoTH-Coder-34B (43.6% on MATH) surpasses GPT-4's CoT result (42.5%), and MAmmoTH-70B (41.8%) also exceeds GPT-4 on MATH, though GPT-4 Code Interpreter (69.7%) remains far ahead. Against Platypus (the main OOD competitor), MAmmoTH-Coder-34B leads by 31.5 points in average OOD accuracy (63.2% vs. 31.7%), while MAmmoTH-70B edges out Platypus-70B on MATH (41.8% vs. 15.6%) and MMLU-Math (56.7% vs. 52.5%). Base Llama-2 models and STEM-pretrained Galactica are substantially outperformed at all scales, with MAmmoTH-7B averaging 47.7% in-domain versus Llama-2-7B's 19.3%. Code-Llama as a base consistently outperforms Llama-2 (e.g., MAmmoTH-Coder-7B 51.6% vs. MAmmoTH-7B 47.7% in-domain average), and the 34B Coder model even surpasses the 70B non-Coder model on OOD tasks.

## Relation to Prior Work

This paper sits at the intersection of two established reasoning paradigms for LLMs: Chain-of-Thought (CoT) prompting (Wei et al., 2022) and Program-of-Thought (PoT) prompting (Chen et al., 2022), and departs from prior math instruction-tuning work (WizardMath, RFT) that relied exclusively on CoT rationales from a narrow set of datasets. The key conceptual departure is the deliberate hybridization of CoT and PoT rationales within a single instruction-tuning dataset (MathInstruct), combined with broad coverage across math fields and complexity levels, rather than dataset-specific fine-tuning. The data curation pipeline also draws on Self-Instruct (Wang et al., 2023) for generating college-level math problems and on GPT-4 for synthesizing and validating PoT rationales.

## Why It Matters / Open Questions

The paper provides a practical, low-cost recipe (260K samples, standard fine-tuning) for closing the open-source/closed-source gap in mathematical reasoning, with the 34B model matching GPT-4's CoT score on MATH. The finding that OOD generalization gains exceed in-domain gains, and that PoT-only training outperforms CoT-only training in the ablation, challenges the field's default assumption that natural-language step-by-step reasoning is the primary axis for math improvement. Limitations remain: the models are not trained on proof-type problems, complex analysis, or graph theory, and the hybrid decoding strategy (PoT-first with CoT fallback) is a simple heuristic rather than a principled routing mechanism. Open questions include whether the hybrid CoT/PoT paradigm transfers to other specialized domains and whether more sophisticated decoding strategies (beyond self-consistency) can further close the remaining gap to GPT-4 Code Interpreter.
