## Problem

Existing code auto-completion benchmarks (e.g., CodeXGLUE, PY150, GitHub Java Corpus) evaluate models only on single-file completion, leaving a significant assessment gap for the multi-file, cross-repository scenarios that dominate real-world development. This paper introduces RepoBench to fill that gap by benchmarking the full pipeline of a repository-level auto-completion system: retrieving relevant cross-file snippets, completing code with cross-file context, and combining both in an end-to-end pipeline.

## Input / Output

For code completion (RepoBench-C), the input prompt is constructed by concatenating cross-file context (file path + commented code snippet parsed from import statements) with in-file context (file path + import statements + up to 30 preceding lines), cropped to fit model token limits of 2,048 or 8,192 tokens. For the pipeline task (RepoBench-P), the model must first select top-k relevant snippets from a candidate pool (minimum 10 candidates) and then predict the next line, with a minimum prompt length of 12,000 tokens (Python) or 24,000 tokens (Java) and a mean of ~44k–139k tokens. The output is a single predicted next line of code (first non-comment line, up to 64 tokens) evaluated via Exact Match, Edit Similarity, and CodeBLEU, while the retrieval task outputs a ranked list of candidate snippets scored by Accuracy@k.

## Method

RepoBench constructs its dataset by using tree-sitter to parse import statements in Python and Java files, identifying cross-file module dependencies and the corresponding defining code snippets. Three task settings are defined: Cross-File-First (XF-F, masking the first usage of a cross-file module), Cross-File-Random (XF-R, masking a non-first occurrence), and In-File (IF, masking a line with no cross-file dependency). The retrieval task (RepoBench-R) frames snippet selection as a top-k ranking problem over candidate snippets using similarity functions (Jaccard, Edit, or semantic embeddings from CodeBERT/UniXcoder/InstructOR), while the pipeline task (RepoBench-P) chains retrieval into autoregressive next-line prediction. To prevent data leakage, training data is drawn from the github-code dataset (cutoff March 2022) and test data from newly crawled GitHub repositories (Feb–Aug 2023), with continuous updates (v1.1 uses Oct–Dec 2023 data and deduplication against Stack v2). The benchmark is maintained as a live, publicly available resource with optional fine-tuning data provided for smaller models.

## Results

On RepoBench-C (code completion), CodeLlama-34B achieves the best Python performance with 37.40% EM, 72.98% Edit Sim, and 47.04% CodeBLEU on the 2k subset, while Codex dominates Java with 42.47% EM, 80.01% Edit Sim, and 55.62% CodeBLEU. On the 8k subset, CodeLlama-34B leads Python (36.26% EM) and Codex leads Java (40.52% EM). For the end-to-end pipeline (RepoBench-P), using UniXcoder-L2H retrieval with Codex yields the best overall performance at 37.11% EM and 74.31% Edit Sim for Python, and 41.83% EM and 74.93% Edit Sim for Java, outperforming the no-retrieval baseline by ~4% EM.

## Baselines & Comparisons

For code completion (RepoBench-C), CodeLlama-34B outperforms Codex on Python by ~6% EM (37.40 vs. 31.31 on 2k), while Codex outperforms CodeLlama-34B on Java by ~3% EM (42.47 vs. 39.41), demonstrating language-specific strengths. StarCoder (15.5B) trails both CodeLlama-34B and Codex on Python but is competitive on Java (37.35% EM vs. 39.41%). CodeGen scales monotonically from 350M (20.71% EM Python) to 16.1B (33.41%), yet remains below CodeLlama-7B at the same parameter scale. For retrieval (RepoBench-R), InstructOR (1.5B) achieves the highest acc@1 (28.22% Python Easy), with UniXcoder (125M) close behind at 27.09%, both substantially outperforming lexical baselines (Jaccard: 21.97%) and random (15.66%). In the end-to-end pipeline (RepoBench-P), UniXcoder-L2H retrieval with Codex improves Python EM from 33.15% (no retrieval) to 37.11%, and even random retrieval (34.94%) beats the no-context baseline, confirming that any cross-file context helps. Gold-Filled strategies (which include the correct snippet) only marginally outperform UniXcoder-L2H, suggesting the retriever already captures most of the benefit.

## Relation to Prior Work

This paper extends the well-established single-file code completion task (evaluated by benchmarks like CodeXGLUE, PY150, and the GitHub Java Corpus) to the repository-level setting, where cross-file dependencies must be resolved. It departs from CoCoMIC (Ding et al., 2022), which introduced cross-file completion but only as a single prediction task, and from RepoEval (Zhang et al., 2023), which is limited to 16 Python repositories and was absorbed into StarCoder's training data. RepoBench's key conceptual contribution is the segmentation of the auto-completion workflow into three distinct sub-tasks—retrieval, completion, and end-to-end pipeline—enabling isolated diagnosis of where systems fail, rather than treating repository-level completion as a monolithic black box.

## Why It Matters / Open Questions

RepoBench fills a genuine evaluation gap: prior benchmarks could not distinguish whether a model's failure in multi-file completion stems from poor retrieval, poor generation, or both. As a live, continuously updated benchmark (v1.1 already released and adopted in the StarCoder 2 technical report), it mitigates the data-leakage problem that plagued earlier code benchmarks. Open questions remain around how to efficiently handle very long cross-file contexts (the pipeline task averages 44k–139k tokens), whether repository-level pre-training (as in StarCoder 2) is the right path versus better retrieval, and how findings generalize beyond Python and Java. The finding that even random cross-file context outperforms no context suggests current models underutilize repository structure, pointing to a clear direction for future work.
