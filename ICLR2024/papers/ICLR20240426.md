## Problem

Detecting data contamination in LLMs remains notoriously difficult because training corpora are private, string-matching produces false negatives under slight text variations, and canary strings rely on trainer compliance without enforcement. No prior work has exploited the longitudinal structure of benchmarks—problems released over years—combined with known training cutoff dates to create a natural experiment that partitions examples into likely-seen versus likely-unseen subsets for closed-source models.

## Input / Output

The method consumes problem descriptions from Codeforces (competitive programming, 2010–2023) and Project Euler (math puzzles, 2001–2023), along with a computed GitHub Presence score derived by counting substring matches of each problem's title/ID across all public GitHub repositories mentioning the dataset. For Codeforces, the LLM generates code evaluated against both public and private test cases; for Project Euler, it generates a single numeric answer. Beyond pass rate, the pipeline also probes memorization by asking the model to reproduce problem titles (given dataset name + ID) and Codeforces tags (given title + ID), scoring token-level recall via logistic regression.

## Method

The core contribution is a longitudinal regression framework that treats the LLM's training cutoff date as a natural experiment, partitioning each benchmark into pre-cutoff (probable training exposure) and post-cutoff (probable no exposure) subsets. The authors fit interaction models of the form DV ~ (Difficulty + GitHub Presence) · postCutoff, using binomial regression for pass rate (count of passed test cases out of n_p) and logistic regression for title/tag reproduction. The key diagnostic is whether the GitHub Presence coefficient is statistically significant before the cutoff but vanishes after: for GPT-4 on Codeforces, each unit increase in log GitHub Presence raises pass-rate odds by 4.5% pre-cutoff but the effect is null post-cutoff, with non-overlapping confidence intervals. The authors validate robustness through public-vs-private test case ablations and chi-squared tests confirming no significant covariate shift in tag or difficulty distributions across the cutoff boundary.

## Results

On Codeforces, GPT-4 shows a statistically significant positive association between GitHub Presence and pass rate before the training cutoff (odds ratio = 1.044, p<0.001) that disappears entirely after the cutoff (OR = 1.000, p=0.988). GPT-3.5-Turbo exhibits a similar pattern (OR = 1.023 before, OR = 1.014 after, p=0.081), and Code Bison shows OR = 1.031 before its February 2023 cutoff. Overall pass rates drop sharply post-cutoff: GPT-4 falls from 37% to 16%, and GPT-3.5-Turbo from 27% to 13% on Codeforces. On Project Euler, the pre-cutoff GitHub Presence effect is even stronger (GPT-4: OR = 1.478; GPT-3.5-Turbo: OR = 1.277), with zero problems solved post-cutoff.

## Baselines & Comparisons

The paper's central comparison is not model-vs-model in the traditional sense but rather each model's pre-cutoff vs. post-cutoff performance, using the training cutoff as a natural experiment. GPT-4 outperforms GPT-3.5-Turbo across all difficulty levels in both periods (higher pass rates and a stronger pre-cutoff GitHub Presence effect: OR 1.044 vs. 1.023), consistent with GPT-4's larger training corpus. Code Bison (cutoff Feb 2023) shows the same qualitative pattern—significant GitHub Presence association before cutoff, none after—but with a very wide post-cutoff confidence interval due to only ~4 months of new problems. Code-Llama-34b and Davinci-002 achieve less than 1% pass rate both before and after the cutoff, rendering them unsuitable for meaningful contamination analysis and effectively losing to both GPT models by a wide margin. The non-overlapping confidence intervals for GPT-4's GitHub Presence coefficient (before vs. after cutoff) provide the strongest statistical evidence of memorization, a distinction not as cleanly established for GPT-3.5-Turbo (p=0.081, marginal at α=0.1).

## Relation to Prior Work

This paper extends the contamination-detection methodology of Magar & Schwartz (2022) and Zhang et al. (2021), who compared model performance on seen vs. unseen training examples, by replacing controlled training experiments with the natural experiment of known training cutoff dates. It adapts the proxy-metric approach of Chang et al. (2023), who used public search results to estimate a book's presence in GPT-4's training data, to GitHub repository mentions as a proxy for a problem's exposure in LLM training corpora. The dataset construction builds on AlphaCode's (Li et al., 2022) Codeforces collection design, while the longitudinal framing departs from Golchin & Surdeanu (2023), who compared memorized completions with/without benchmark clues on static datasets rather than exploiting temporal partitioning.

## Why It Matters / Open Questions

The paper provides a practical, reproducible methodology for detecting contamination in closed-source LLMs where training data is inaccessible, which is the dominant case in industry. Its core implication—that even high-quality, hand-constructed benchmarks have ever-shortening shelf lives as successive model cutoffs sweep past them—challenges the field's reliance on static evaluation sets and motivates a shift toward continuous, staggered release cycles. Key limitations include the inability to rule out latent confounders, the restriction to longitudinal datasets (most popular benchmarks are released all at once), and small post-cutoff sample sizes that limit statistical power for some models. Open questions include whether the methodology generalizes to non-code domains and how to handle the case where fine-tuning data may extend past the stated pretraining cutoff.
