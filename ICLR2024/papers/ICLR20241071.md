## Problem

While instruction fine-tuning methods like Evol-Instruct have dramatically improved general-purpose LLMs, their application to Code LLMs remains largely unexplored. Existing open-source Code LLMs (StarCoder, CodeLlama) focus primarily on pre-training, leaving a significant performance gap versus closed-source models like GPT-4. The paper asks whether adapting Evol-Instruct with code-specific heuristics can close this gap through fine-grained instruction tuning alone.
![Teaser figure](../imgs/ICLR20241071/cropped_page1_idx0.webp)

## Input / Output

The model accepts a natural-language instruction describing a coding task (optionally with additional context or test examples) in a structured prompt format with 'Instruction' and 'Response' fields, and produces a complete code solution. For evaluation, the model generates code under greedy decoding (single attempt) or n=200 samples for pass@1 estimation, with temperature=0.2 and top_p=0.95. The training data evolves from ~20k Code Alpaca samples to ~78k samples across multiple evolution rounds, with sequence length capped at 2048 tokens.

## Method

Code Evol-Instruct iteratively evolves code instruction data using five code-specific heuristics: adding new constraints/requirements, replacing common requirements with less common ones, increasing reasoning steps, injecting erroneous code as adversarial misdirection, and imposing higher time/space complexity requirements. Starting from Code Alpaca (~20k samples), GPT-3.5 or GPT-4 evolves the data over multiple rounds; after each round, all evolved data is merged with the original set to fine-tune StarCoder-15B or CodeLlama-34B-Python (batch size 512, 200 steps, lr=2e-5, cosine schedule, fp16). An external dev set serves as an evolving stop control—evolution halts when performance degrades. The key insight is that instruction complexity, not merely data quantity or token count, drives the performance gain, as confirmed by controlled experiments matching sample and token counts across rounds.

## Results

WizardCoder 34B achieves 71.5% pass@1 on HumanEval and 61.2% on MBPP (n=200, temperature=0.2, top_p=0.95), surpassing all open-source Code LLMs and even GPT-4 (67.0%) on HumanEval. On HumanEval+ with greedy decoding, WizardCoder 34B scores 64.6%, outperforming GPT-3.5/ChatGPT (63.4%), while WizardCoder 15B (59.8%) beats Claude (53.0%) and Bard (44.5%). On MultiPL-E, WizardCoder 34B leads across all 8 programming languages (e.g., 55.3% on JavaScript, 47.2% on C++), and on DS-1000 insertion, WizardCoder 15B reaches 32.8% overall versus StarCoder's 25.4%.

## Baselines & Comparisons

WizardCoder 34B (71.5% HumanEval) decisively outperforms all open-source baselines: CodeLlama-Python (53.7%), CodeLlama (48.8%), OctoCoder (46.2%), StarCoder (33.6%), and CodeLlama-Instruct (41.5%), with margins of 17.8–37.9 points. It also surpasses strong closed-source models including GPT-3.5/ChatGPT (48.1%), Code-Davinci-002 (47.0%), PanguCoder2 (61.6%), and Unnatural-CodeLlama (62.2%), and even exceeds GPT-4 (67.0%) on HumanEval. On HumanEval+ (greedy decoding), WizardCoder 34B (64.6%) beats GPT-3.5 (63.4%), and WizardCoder 15B (59.8%) outperforms Claude (53.0%) and Bard (44.5%). On MultiPL-E, WizardCoder 34B leads CodeLlama-Instruct by 3.4–12.6 points across all 8 languages (e.g., 55.3% vs 45.9% on JavaScript). On DS-1000 insertion, WizardCoder 15B (32.8% overall) beats StarCoder (25.4%) by 7.4 points, with the largest gap on TensorFlow (37.8% vs 20.0%). The only model WizardCoder 34B does not surpass is GPT-4 on HumanEval+ (where GPT-4 is not reported in the paper's greedy-decoding comparison), though it does beat GPT-4 on the n=200 HumanEval setting.

## Relation to Prior Work

This paper adapts WizardLM's Evol-Instruct method—originally designed for general language instruction data—to the code domain, introducing coding-specific evolutionary heuristics (LeetCode-style constraint addition, adversarial erroneous code injection, and time/space complexity escalation) that have no direct analogue in the general-domain Evol-Instruct. It builds on StarCoder and CodeLlama as base models and Code Alpaca as the seed instruction dataset, positioning itself as the first instruction fine-tuning pipeline explicitly designed for Code LLMs. The work departs from prior code LLM efforts (CodeLlama-Instruct, OctoCoder, InstructCodeT5+) that relied on self-instruct or static instruction sets, by iteratively evolving instruction complexity as the primary mechanism for performance gains.

## Why It Matters / Open Questions

The paper demonstrates that instruction complexity—not merely data quantity or test-set similarity—is the pivotal driver of code generation performance, a finding that redirects attention in the code LLM community toward data quality over data volume. The practical impact is significant: a 15B open-source model surpassing Claude and Bard, and a 34B model matching GPT-3.5 on HumanEval+, narrows the open-source/closed-source gap substantially. However, the models still trail GPT-4 by a wide margin, and the method's reliance on a strong external LLM (GPT-3.5/4) for data evolution raises questions about scalability and whether the gains transfer when the evolution model is weaker. Open questions include whether further evolution rounds or alternative complexity axes (e.g., multi-file reasoning, debugging) can close the remaining gap to frontier models.
