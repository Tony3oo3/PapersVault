## Problem

Prior instruction-tuned code LLMs (WizardCoder, InstructCodeT5+, PanGu-Coder2) rely on OpenAI's closed-source API to generate synthetic training data, raising legal, reproducibility, and hallucination concerns. Additionally, existing code benchmarks like HumanEval only evaluate code synthesis, leaving code repair and code explanation unmeasured. This paper addresses both gaps by constructing a large permissively-licensed instruction dataset from Git commits and a multi-task, multi-language benchmark.

## Input / Output

The models handle three input-output scenarios: code synthesis (NL docstring → code), code repair (buggy function + failing unit tests → corrected function), and code explanation (correct function → NL description, which is then used to regenerate code for execution-based scoring). For the explanation task, the model's output is constrained to a character limit matching the original docstring length, and any substring of ≥20 characters overlapping the solution is stripped to prevent copying. Evaluation uses pass@1 with temperature 0.2, top_p=0.95, and n=20 samples per problem across 164 problems in 6 languages (Python, JavaScript, Java, Go, C++, Rust).

## Method

The core data contribution is COMMITPACK, a 4TB corpus of Git commits scraped from GitHub via BigQuery, filtered for permissive licenses, single-file changes, and quality criteria. A stricter 2GB subset, COMMITPACKFT, retains only commits whose messages begin with an imperative verb (e.g., 'Fix…', 'Add…'), contain multiple words, and lack external references, yielding 742K samples across 277 languages. The key insight is that commit messages naturally pair human instructions with code diffs, eliminating the need for closed-source model outputs. For instruction tuning, the authors mix 5,000 samples from COMMITPACKFT (covering 6 evaluation languages) with filtered OASST data to provide natural-language targets, then fine-tune StarCoder (16B) and CodeGeeX2 (6B). Ablations show COMMITPACKFT is essential for code repair (it contains ~20% bug-fix commits) while OASST is necessary for code explanation (providing NL output targets), and the combination yields a 23% absolute improvement over the base StarCoder model.

## Results

OCTOCODER (16B, instruction-tuned StarCoder) achieves the best average pass@1 among all permissive models across HUMANEVALPACK: 27.0% on HUMANEVALFIX, 24.5% on HUMANEVALEXPLAIN, and 35.5% on HUMANEVALSYNTHESIZE (46.2% on Python HumanEval specifically). The smaller 6B OCTOGEEX also outperforms all prior permissive Code LLMs, reaching 24.4%, 22.9%, and 30.9% respectively. GPT-4 remains the strongest overall model (47.8%, 52.1%, 78.3% average) but is closed-source. Instruction tuning on COMMITPACKFT+OASST yields a 23% absolute improvement over the base StarCoder model on average.

## Baselines & Comparisons

OCTOCODER outperforms all permissive baselines across all three HUMANEVALPACK tasks: it beats StarCoder (base) by +13.6, +24.5, and +7.9 points on FIX, EXPLAIN, and SYNTHESIZE respectively; beats CodeGeeX2 by +14.9, +24.5, and +7.4; and beats BLOOMZ (176B) by +14.5, +17.0, and +24.0. Among non-permissive models, OCTOCODER trails WizardCoder on HUMANEVALSYNTHESIZE (35.5% vs. 40.1%) and HUMANEVALEXPLAIN (24.5% vs. 27.5%) but leads on HUMANEVALFIX (27.0% vs. 25.7%), and substantially outperforms InstructCodeT5+ on every task. GPT-4 dominates all comparisons with large margins (e.g., 78.3% vs. 35.5% on SYNTHESIZE), confirming that closed-source models remain ahead. Notably, OCTOGEEX at only 6B parameters surpasses the 16B StarCoder and 176B BLOOMZ on all tasks, demonstrating the efficiency of the instruction tuning approach.

## Relation to Prior Work

This paper applies the instruction tuning paradigm (Wei et al., 2022; Ouyang et al., 2022) to code LLMs, departing from concurrent work (WizardCoder, PanGu-Coder2, InstructCodeT5+) that relies on OpenAI-generated synthetic data by instead exploiting the natural instruction-answer structure of Git commits (commit message as instruction, code diff as answer). It extends the HumanEval code synthesis benchmark (Chen et al., 2021) into HUMANEVALPACK, adding code repair and code explanation tasks across six languages, and builds on crosslingual generalization findings (Muennighoff et al., 2022b) to show that instruction tuning transfers to programming languages seen only during pretraining. The base models (StarCoder, CodeGeeX2) follow the large-scale permissively-licensed pretraining line of work, with the contribution being the instruction data source and evaluation framework rather than the architecture.

## Why It Matters / Open Questions

HUMANEVALPACK addresses a practical gap: HumanEval code synthesis is near saturation (GPT-4 at 86.6% pass@1 on Python), while the harder repair and explanation variants remain far from solved, giving the field a more discriminating evaluation target. The finding that permissively-licensed Git commit data (COMMITPACKFT) outperforms OpenAI-synthetic instruction data for code models challenges the assumption that more capable closed models are necessary for generating training data, with implications for reproducibility and commercial usability. Open questions include whether pretraining on the full 4TB COMMITPACK further improves performance, how to make models aware of output length constraints, and whether the benchmark generalizes beyond the six languages tested.
