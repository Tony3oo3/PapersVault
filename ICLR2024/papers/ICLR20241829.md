## Problem

Existing Shapley-based data importance methods compute importance only over the final preprocessed training set, treating the ML model in isolation. In practice, data errors originate in source datasets that pass through preprocessing pipelines (joins, augmentations, scalers, embeddings) before reaching the model, making it impossible to directly apply prior methods to identify which source tuples are most responsible for poor model quality. The paper asks how to efficiently compute Shapley values of source data examples while accounting for the interdependencies introduced by pipeline operators.

## Input / Output

The method consumes a source training dataset (which may be multi-modal, e.g., images joined with metadata tables), a data preprocessing pipeline expressed as a composition of operators (map, fork, join, reduce), a validation dataset, and a model quality metric (accuracy or fairness metrics like equalized odds difference). It outputs a Shapley importance score for every source data tuple, which is then used to rank and prioritize label repairs. A key structural requirement is that the pipeline must be expressible (or approximable) as one of three canonical forms—map, fork, or one-to-many join—so that provenance polynomials remain O(1) in size relative to the dataset.

## Method

The core mechanism is a data provenance framework that assigns a Boolean polynomial to each pipeline output tuple, encoding which source tuples must be present for that output to exist. For canonical pipelines (map, fork, one-to-many join), these polynomials have bounded size, enabling O(1) subset membership checks that eliminate the cost of re-running the pipeline for every sampled subset. To achieve PTIME Shapley computation, the paper further approximates the target model with a KNN classifier and assumes an additive quality metric, reducing the Shapley sum to a counting oracle over value assignments. This oracle is computed via Additive Decision Diagrams (ADDs): the pipeline structure is compiled into a polynomial-size ADD whose model counting operation exactly evaluates the exponential sum. For map, fork, and one-to-many join pipelines, the resulting ADDs have polynomial size, yielding Shapley computation in O(N²), O(M²N²), and O(N⁴) time respectively—orders of magnitude faster than Monte Carlo baselines while achieving comparable label-repair effectiveness.

## Results

Datascope KNN achieves comparable label-repair performance to TMC x100 (the strongest Monte Carlo baseline) across multiple pipelines and models (LogisticRegression, XGBoost, ResNet-18, MobileVIT, MinLM, ALBERT), while reducing computational cost by orders of magnitude. For the fairness metric (equalized odds difference), Datascope KNN Interactive — which recomputes Shapley values at each of 100 repair checkpoints — is the only method that successfully improves fairness, outperforming all static-importance baselines. In scalability experiments, runtime grows roughly linearly with both training set size (10k–1M) and validation set size (100–10k), with Shapley scores computable in minutes even for 1M training samples with 1k features.

## Baselines & Comparisons

The primary baseline is Truncated Monte Carlo (TMC) from Ghorbani & Zou (2019), evaluated at 10 and 100 iterations. Datascope TMC x10/x100 matches the label-repair accuracy of vanilla TMC x10/x100 while achieving significant runtime reductions by avoiding redundant pipeline re-evaluation via provenance-based subset membership checks (Figure 3). Datascope KNN, which replaces the black-box model with a KNN proxy and uses ADD-based model counting, matches TMC x100 performance on accuracy-driven label repair (Figure 4) at a fraction of the computational cost — orders of magnitude faster. On the fairness task (equalized odds difference, Figure 5), static-importance methods including TMC x100 and Datascope KNN (single computation) fail to improve fairness, while Datascope KNN Interactive (recomputing at each checkpoint) is the only method that achieves meaningful fairness gains, likely because the complex metric causes the optimal repair path to shift after each intervention. All Datascope variants substantially outperform the Random baseline across all settings.

## Relation to Prior Work

This paper extends the data valuation literature (Ghorbani & Zou, 2019; Jia et al., 2019a) by moving the Shapley computation from the preprocessed training set to the source data, accounting for the ML preprocessing pipeline in between. It draws on data provenance theory (Green et al., 2007; Cheney et al., 2009) to model how tuples flow through pipeline operators, and on knowledge compilation via Additive Decision Diagrams to turn the resulting subset-membership counting into a PTIME model-counting problem. The prior KNN-proxy Shapley algorithm (Jia et al., 2019a) is recovered as a special case for map pipelines, while fork and one-to-many join pipelines require the new ADD-based counting oracles.

## Why It Matters / Open Questions

The practical gap this paper addresses is significant: most real-world ML systems involve non-trivial preprocessing (scaling, augmentation, joins, embeddings), and existing Shapley-based debugging tools cannot be applied to the source data where errors actually originate. The canonical-pipeline approximation, validated on 500K Microsoft workflows, covers the vast majority of real pipelines, making the approach broadly applicable. Key limitations include the reliance on a KNN proxy model (which may diverge from the true model's sensitivity to individual examples), the assumption of additive quality metrics, and the approximation of estimator-transformer pipelines by freezing reduce statistics. Open questions include extending to non-additive metrics, multi-class settings, and more complex pipeline topologies (e.g., many-to-many joins).
