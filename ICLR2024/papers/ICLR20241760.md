## Problem

Neural program synthesizers are evaluated primarily on i.i.d. test sets, but it remains unclear whether they can compositionally generalize—combining subprograms in novel ways not seen during training, as human programmers do when decomposing complex tasks. This paper identifies five distinct forms of compositional generalization in program synthesis (length, concept mixing, concept reordering, new operation composition, and operation functionality extension) and shows that both Transformers and LLMs struggle significantly on these tasks compared to i.i.d. settings.

## Input / Output

The method takes a set of 3–4 I/O examples (input strings or integer lists paired with desired outputs) that implicitly specify a program in a domain-specific language (RobustFill for string manipulation or DeepCoder for list manipulation). The output is a sequence of subprograms (concatenated expressions in RobustFill, or assignment lines in DeepCoder) that correctly transform every input to its corresponding output. In the LLM experiments, DSL programs are rendered as Python functions calling a hypothetical `dsl` library, and the LLM produces code in that format via few-shot prompting.

## Method

ExeDec performs step-by-step synthesis in the execution space using two Transformer models: a SubgoalModel that predicts the desired intermediate output (subgoal) for each I/O example at the next step, and a SynthesizerModel that generates the subprogram achieving that subgoal from the current state. Both models use a Specification-Transformer architecture with double attention over the multi-example specification, and the SubgoalModel additionally employs Aligned Relative Attention (ARA) to handle its sequence-of-sequences output format. A modified beam search runs multiple partial rollouts in parallel, scoring candidates by combined log-probabilities of subgoals and subprograms plus validity checks (parseability, executability, and functional deduplication). The key insight is that by conditioning the SynthesizerModel only on the current subgoal rather than the full remaining specification, the model is shielded from spurious compositional patterns that cause overfitting. For LLMs, the same decomposition is realized through few-shot prompting where the model predicts execution subgoals before code at each step, with actual execution results (not predicted subgoals) fed back into the prompt history.

## Results

On RobustFill with beam size 10, ExeDec achieves 95.5% no-generalization accuracy and 87.0% average compositional generalization accuracy, compared to 90.9% and 42.4% for the Transformer baseline (+44% relative improvement in generalization). On DeepCoder, ExeDec reaches 61.2% no-generalization and 23.1% generalization accuracy versus 53.6% and 5.7% for the Transformer baseline (a 4.4× improvement in generalization). In LLM few-shot experiments with PaLM 2, the ExeDec-style prompting strategy achieves the best performance across nearly all settings, solving 40–75% more tasks than the next-best approach on DeepCoder-Pythonic.

## Baselines & Comparisons

ExeDec substantially outperforms Latent Programmer (Hong et al., ICML 2021) on every generalization task and in the i.i.d. setting: on RobustFill (beam 10), ExeDec achieves 87.0% GenAvg vs. 33.7% for Latent Programmer, and on DeepCoder 23.1% vs. 3.5%. Against the Transformer baseline (no decomposition), ExeDec gains +44% average compositional generalization on RobustFill and +18% (4.4×) on DeepCoder, while also improving i.i.d. accuracy. Compared to the no-subgoal ablation (step-by-step synthesis without explicit subgoal prediction), ExeDec achieves +7% on RobustFill (34% reduction in failures) and +5% (1.28×) on DeepCoder, confirming that predicting execution subgoals is more robust than directly predicting code. The no-subgoal ablation slightly edges out ExeDec on DeepCoder's i.i.d. setting (64.7% vs. 61.2%) and on Length-Generalization, suggesting some spurious-pattern interactions. In the LLM few-shot setting, the ExeDec-style prompting consistently outperforms both the baseline (single-shot) and ablation-style (step-by-step without subgoals) approaches across all three domain variants.

## Relation to Prior Work

ExeDec sits at the intersection of two established lines of work: execution-guided multi-step synthesis (Zohar & Wolf, 2018; Ellis et al., 2019; Chen et al., 2019) and planning-based synthesis that generates high-level plans before code (Nye et al., 2019; Hong et al., 2021). The key departure is that ExeDec performs decomposition in the *execution space*—predicting intermediate program states (subgoals) rather than code tokens or latent plans—making the subgoal model blind to compositional code patterns. For evaluation, the paper draws on compositional generalization taxonomies from NLP (SCAN, COGS, Keysers et al., 2020) but is the first to systematically instantiate such tasks for programming-by-example, where prior work (Balog et al., 2017; Ellis et al., 2019) only reported length generalization as a side result.

## Why It Matters / Open Questions

The 5-task meta-benchmark provides a reusable, principled framework for measuring compositional generalization in PBE that can be applied to new DSLs and datasets, filling a gap where prior evaluations only tested i.i.d. or length generalization. The finding that predicting execution subgoals (rather than code) is a more robust inductive bias for generalization has practical implications for designing future synthesizers and for structuring LLM prompts. Key open questions include whether the approach extends to natural hierarchical decompositions (beyond line-by-line), whether it generalizes to general-purpose languages with realistic code, and whether the SubgoalModel can be replaced by more abstract state representations. The paper also highlights that compositional generalization remains a significant challenge even for frontier LLMs like PaLM 2, suggesting this is not merely a scaling problem.
