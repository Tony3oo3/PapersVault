## Problem

Prior work (HELM, Fu et al.) observed that code-trained models reason better, but comparisons across models with different parameter scales, data volumes, and unknown training details make it impossible to rigorously isolate at which training stage—pre-training or instruction-tuning—code data actually drives reasoning gains. This paper fills that gap by holding architecture, parameter count, and training objective fixed while varying only the data composition at each stage.
![Teaser figure](../imgs/ICLR20241423/cropped_page2_idx0.webp)

## Input / Output

For understanding tasks (logical, legal, scientific, analogical reasoning, code QA), the model receives a prompt template containing the question and candidate answer choices, and the predicted label is the choice yielding minimum perplexity. For code generation (MBPP), the model receives a natural language question and autoregressively generates Python code. Chain-of-Thought variants prepend an explicit reasoning chain to the input, and the model generates the final answer conditioned on that chain.

## Method

The paper trains GPT-style autoregressive models (32-layer transformer decoder with an additional query layer, following CodeGeeX and PanGu-α) at 2.6B and 13B parameters under identical architecture and training objective, varying only data composition: pure text (NL), larger text (NL-13B), or a text+CodeParrot Python mixture (CODE-2.6B). At the instruction-tuning stage, they further compare fine-tuning with pure text instructions versus mixed code+text instructions (CodeAlpaca, CosQA, MBPP), and test three dynamic mixing strategies—uniform, stepwise increase, and stepwise decrease—for the code-to-text ratio across training phases. Evaluation spans six reasoning tasks in five domains using a perplexity-based classification approach for multiple-choice tasks and direct generation for code tasks. The central findings are that code data at pre-training boosts general reasoning almost without negative transfer on non-reasoning tasks, code data at instruction-tuning specifically activates task-specific code reasoning, and a stepwise-decrease strategy (high code ratio early, low later) best balances both general and specific reasoning.

## Results

In the pre-training stage, CODE(2.6B) (trained on mixed code+text data) outperforms NL(2.6B) (text-only) on all six reasoning tasks, with the largest gains on MBPP code generation (5.06 vs 0.52 BLEU) and E-KAR analogical reasoning (36.12% vs 32.24% ACC). Notably, CODE(2.6B) also surpasses the larger NL(13B) model on JEC-QA (28.70% vs 27.00%), ScienceQA (46.06% vs 45.18%), E-KAR (36.12% vs 35.52%), CosQA (50.50% vs 46.85%), and MBPP (5.06 vs 1.34 BLEU), though it trails on Logic (40.90% vs 45.45%). On MMLU, CODE(2.6B) achieves 24.91% on Math and 26.67% on Physics, matching or exceeding NL(13B) and approaching LLaMA-7B (24.97% Math, 27.97% Physics). In the instruction-tuning stage, code data primarily boosts code-specific tasks (MBPP BLEU jumps from 0.00 to 24.88 for the CC model) while general reasoning tasks show mixed or slightly degraded performance.

## Baselines & Comparisons

Against PanGu2.6B (NL 2.6B, text-only pre-training), CODE(2.6B) wins on all six tasks, with the most dramatic improvement on MBPP code generation (5.06 vs 0.52 BLEU, ~10×) and E-KAR analogical reasoning (+3.88 ACC). Against the larger PanGu13B (NL 13B), CODE(2.6B) wins on five of six tasks (JEC-QA, ScienceQA, E-KAR, CosQA, MBPP) but loses on Logic (40.90% vs 45.45%), suggesting that model scale still matters for pure logical reasoning. On MMLU, CODE(2.6B) nearly matches LLaMA-7B on Math (24.91% vs 24.97%) and trails by only 1.3 points on Physics (26.67% vs 27.97%), despite being roughly 2.7× smaller. The paper further validates its conclusions using Code Llama vs Llama 2 from the Open LLM Leaderboard: Code Llama-7B achieves 33.5% HumanEval vs 12.2% for Llama2-7B and 5.16% GSM8K vs 3.49%, confirming that code pre-training boosts both coding and mathematical reasoning. Overall, the key finding is that code data in pre-training is more effective for general reasoning than simply scaling model parameters, while code data in instruction-tuning primarily activates task-specific code reasoning.

## Relation to Prior Work

This paper builds on the PanGu-α architecture and training pipeline (Zeng et al., 2021) and the CodeGeeX query-layer design (Zheng et al., 2023), using them as the controlled experimental platform. It departs from prior observational studies (HELM, Liang et al. 2022; Fu et al. 2022) that noted code-trained models reason better but could not isolate the causal effect due to confounded parameters, data scales, and training details. The key methodological contribution is a controlled ablation that holds architecture and parameter count fixed while varying only the presence and stage of code data, and the stepwise mixing strategy for code-text data has no direct precedent in the LLM training literature.

## Why It Matters / Open Questions

The paper provides actionable guidance for LLM developers: code data at pre-training boosts general reasoning nearly for free, while code instructions at fine-tuning unlock task-specific code reasoning, and a stepwise-decrease mixing schedule further improves code generation. However, the findings are validated only on the PanGu/GPT decoder architecture at 2.6B and 13B scale with predominantly Chinese evaluation benchmarks, leaving open whether the conclusions transfer to larger models, different architectures, or multilingual settings. The paper also acknowledges negative transfer on reading comprehension tasks (DuReader), suggesting that the code-text trade-off is not fully resolved and that larger-scale validation is needed before these recipes can be adopted broadly.
