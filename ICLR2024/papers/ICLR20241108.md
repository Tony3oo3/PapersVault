## Problem

Existing code generation and completion models focus on creating new code but cannot track a developer's in-progress edits or predict where and how to propagate those changes across the codebase. This paper introduces the multi-round repo-level auto-editing task, where the goal is to predict further edits to a code region conditioned on the user's prior changes within the same commit, addressing the tedious manual propagation of related modifications.
![Teaser figure](../imgs/ICLR20241108/cropped_page1_idx0.webp)

## Input / Output

The model takes a target code region with placeholder tokens (<1>, <2>, …) marking the edit span, prior code changes encoded as line diffs with status tokens (<add>, <del>), and a signature document built from static analysis of the codebase. It outputs a line-diff sequence specifying additions and deletions at each placeholder position, formatted for masked span infilling. A constraint forbids the model from deleting a line that was just added in the current round, and the target region may overlap with previously modified lines to support iterative editing.

## Method

Coeditor fine-tunes CodeT5-base (220M parameters) on the newly collected PYCOMMITS dataset (1,650 open-source Python projects) using a line-diff encoding that converts auto-editing into a masked span infilling problem. Two key design choices distinguish it from standard code completion: (1) prior edits are explicitly encoded as diffs rather than silently applied to the code, and (2) lightweight static analysis retrieves relevant function signatures and variable assignments to build a compact codebase context. To handle long contexts (up to 16.4K reference tokens), the encoder's dense attention is replaced with a block-sparse pattern where reference blocks (≤512 tokens each) do not attend to each other, but the query block (≤1024 tokens) globally attends to all references, with relative positional distances set to infinity to make the model invariant to reference ordering. Training uses a curriculum that gradually increases the reference context from 2K to 8K tokens over 1.75 epochs.

## Results

On PYCOMMITS-ONELINE (5000 single-line code completion instances), Coeditor (220M params, 16K context) achieves 60.4% overall exact-match accuracy, substantially outperforming the strongest baseline text-davinci-003 (175B params) at 39.5%. Coeditor's advantage is particularly pronounced on replacement edits (64.9% vs. 39.3% for text-davinci-003). In the full multi-round editing setting, Coeditor automates 46.7% of changed lines and saves 28.6% of keystrokes over 2.43 average rounds, compared to 28.5% lines and 19.2% keystrokes in a single round.

## Baselines & Comparisons

Coeditor outperforms all four baseline families by a wide margin on overall exact-match accuracy. Against text-davinci-003 (175B parameters), Coeditor (220M parameters) achieves 60.4% vs. 39.5% overall EM — a 20.9-point gap despite being roughly 800× smaller. Against StarCoder-7B (7B params, 8K context), Coeditor leads by 25.6 points (60.4% vs. 34.8%), with the largest gap on replacement edits (64.9% vs. 33.7%). Against InCoder-6B (6.7B params), the gap is 29.1 points (60.4% vs. 31.3%), and against SantaCoder (1.1B params), it is 31.6 points (60.4% vs. 28.8%). The paper attributes these gains to Coeditor's access to explicit editing history (line diffs) and static-analysis-derived signatures, which the baselines — trained for generic code infilling without change awareness — simply do not receive as input.

## Relation to Prior Work

Coeditor builds directly on CodeT5's encoder-decoder architecture and masked span infilling objective, repurposing a model pre-trained for code understanding into a code editing setting. It departs from prior code completion models (InCoder, StarCoder, SantaCoder, GPT-3.5) by explicitly conditioning on the user's editing history via a line-diff encoding, rather than treating the task as pure fill-in-the-middle. The static analysis component for retrieving relevant signatures draws on the type inference literature (Pradel et al., 2020; Wei et al., 2023), and the block-sparse attention pattern adapts ideas from retrieval-augmented models (Fusion-in-Decoder) and long-document transformers (Longformer, BigBird) to handle long multi-change contexts efficiently.

## Why It Matters / Open Questions

The paper demonstrates that incorporating editing history into the prediction context is more effective than raw model scale for code editing: a 220M model with diff-aware context outperforms a 175B GPT-3.5 by ~1.5× on exact match. The PYCOMMITS dataset and multi-round evaluation framework provide a reusable benchmark for future code editing research, and the open-sourced VSCode extension makes the approach immediately practical. Key limitations include the assumption that the user identifies the editing region, the restriction against modifying already-edited lines, and evaluation limited to Python; extending the model to auto-identify regions needing changes and supporting finer-grained collaborative editing remain open directions.
