## Problem

Existing code embedding models are capped at ~125M parameters and trained on small corpora like CodeSearchNet, despite the availability of massive permissively-licensed code datasets (The Stack, 6TB). Moreover, the standard 80-10-10 MLM masking strategy is suboptimal for source code because random token replacement disrupts both the syntax and semantics of code by mixing natural-language and programming-language tokens, leading to degraded representation quality.

## Input / Output

The encoder consumes source code snippets (up to 1024 tokens via the Starcoder tokenizer) and natural-language queries (docstring summaries), producing fixed-dimensional embedding vectors (1024-dim for SMALL/BASE, 2048-dim for LARGE) suitable for zero-shot semantic search or frozen-feature linear classification. A notable design choice is that during contrastive learning, the function signature and return statements are stripped from the code side to form 'hard positives,' forcing the model to rely on function-body semantics rather than lexical overlap with the summary text.

## Method

CODESAGE is a bidirectional Transformer encoder pretrained in two stages. Stage 1 alternates (with equal probability per example) between identifier deobfuscation (DOBF)—where class, function, and variable names are replaced with special tokens and the model must recover them—and full-mask MLM (no 80-10-10 random replacement), with a 15% masking rate; this is the first application of DOBF to encoder-only architectures, requiring a custom obfuscation tool to handle tokenization mismatches between tree-sitter and the model tokenizer. Stage 2 performs bimodal contrastive learning on (docstring-summary, function-body) pairs using a symmetric InfoNCE loss with temperature 0.05, where hard negatives are weighted by a distance-based gamma (Eq. 3) that up-weights in-batch negatives close to the anchor in embedding space, and hard positives are constructed by removing function signatures to eliminate shortcut learning from lexical overlap. Three model sizes (130M, 356M, 1.3B) are trained on 237M code files and 75M text-code pairs across nine languages from The Stack.

## Results

On zero-shot Code2Code semantic search (MAP), CODESAGE-LARGE (1.3B) achieves 38.51% average across nine languages, outperforming the strongest baseline OpenAI-Ada-002 (27.33%) by 11.18 points absolute. Even CODESAGE-SMALL (130M) at 26.08% surpasses all known-size baselines, including UnixCoder (21.17%) by 4.91 points. On NL2Code search (MRR), CODESAGE-LARGE reaches 52.67% on AdvTest and 71.24% on CSN, while on classification (linear-probe F1), it attains 90.32% on Code Complexity and 24.42% on RunTime Error Prediction, both leading all baselines.

## Baselines & Comparisons

CODESAGE dominates all encoder baselines on Code2Code search: it outperforms CodeBERT (8.09 avg MAP) by 5.3x, GraphCodeBERT (11.68) by 3.3x, and StarEncoder (12.79) by 3.0x, with the largest gaps on C# and C where these models score below 10. Against UnixCoder (21.17), CODESAGE-SMALL already leads by 4.91 points, and CODESAGE-LARGE extends this to 17.34 points. Compared to OpenAI-Ada-002 (27.33), CODESAGE-LARGE gains 11.18 points on Code2Code but is slightly behind on CSN NL2Code (71.24 vs 71.24, tied) while leading on AdvTest (52.67 vs 38.08). Decoder-only baselines (CodeGen2.5 at 10.73, Starcoder at 4.31, CodeT5+ at 10.17 avg MAP) are substantially outperformed, confirming that encoder architectures remain superior for embedding-based retrieval. On classification, CODESAGE-LARGE leads on Complexity (90.32 vs 79.82 for OpenAI-Ada-002) and RunTime (24.42 vs 20.84), though it trails slightly on Defect detection in the linear-probe setting (58.95 vs 62.56), a gap that closes under full fine-tuning (66.38 vs 65.74 for UnixCoder).

## Relation to Prior Work

This paper extends the code representation learning lineage from CodeBERT/GraphCodeBERT/UnixCoder (all ≤125M params, trained on CodeSearchNet) by scaling to 1.3B parameters on The Stack (237M files) and introducing a two-stage pretraining recipe. It departs from BERT's standard 80-10-10 masking by showing it is harmful for code, and is the first to adapt identifier deobfuscation (DOBF) from Seq2Seq models (Lample et al., 2021; Wang et al., 2021b) to encoder-only architectures. The contrastive learning stage builds on SimCLR-style InfoNCE with in-batch negatives (Chen et al., 2020) and the distance-based hard negative weighting from Zhang et al. (2021), but introduces a hard positive construction strategy (removing function signatures to prevent lexical-overlap shortcuts) that is specific to the code domain.

## Why It Matters / Open Questions

The paper provides the first off-the-shelf code embedding models at the 1B+ parameter scale trained on publicly available data, substantially raising the bar for code search and classification baselines. The finding that the standard 80-10-10 masking convention degrades code representations (unlike text) is a practical correction that should inform future code pretraining. Open questions include whether the modest scaling gains observed with 80-10-10 masking reveal a phase transition at larger scales, how to unify text and code embedding in a single model, and whether the two-stage recipe generalizes to other structured domains beyond source code.
