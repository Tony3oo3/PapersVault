## Problem

Hierarchical planning systems require domain-specific action abstractions (operators) to decompose long-horizon tasks into tractable subproblems, but these are almost always hand-engineered by human experts for each new domain. The central bottleneck is automatically discovering a set of high-level actions that are time-efficient for planning, correspond to feasible low-level action sequences, and compose to generalize to new tasks. This paper asks whether background knowledge in language models can serve as a prior to bootstrap such task-specific planning representations without human annotation.

## Input / Output

The method takes a natural language task instruction and an initial raw environment state x_0, with a fixed mapping Φ to an abstract state space of objects and predicates. The goal predicate g_t is hidden (only the language description is observable), so the LLM must propose candidate first-order-logic goal formulas. The system outputs a sequence of low-level actions achieving the goal, a high-level symbolic plan over learned PDDL operators, and an iteratively refined library of operators—each a tuple of (name, args, preconditions, effects, low-level controller)—that persists across tasks and iterations.

## Method

Ada (Action Domain Acquisition) runs an iterative loop where, at each step, an LLM proposes candidate PDDL operators via a two-stage prompting strategy (symbolic task decomposition followed by operator definition), then a bi-level planner (FastDownward for high-level, learned subgoal-conditioned count-based policies for low-level) attempts to solve unsolved tasks using the extended operator library. Operators are scored by their execution success rate (successful subgoal completions / total appearances in high-level plans) and retained only if they exceed both a usage-count and success-rate threshold, ensuring the library stays compact and grounded in environment dynamics. The low-level controller is trained with hindsight goal relabeling over all predicate conjunctions encountered during breadth-first search, and the LLM also proposes multiple candidate goal formulas per task to handle linguistic ambiguity. This verification-through-execution mechanism distinguishes Ada from baselines that use LLMs to directly predict subgoal sequences or imperative code policies, as it explicitly ties operator retention to realized low-level success rather than linguistic plausibility.

## Results

On Mini Minecraft, Ada achieves 100% success rate across all three benchmark variations (Mining, Crafting, and Compositional), with the Compositional setting requiring up to 26 high-level steps and generalizing from operators learned only on simpler tasks. On ALFRED, Ada reaches 79% success rate (σ=0.9%) on the combined Simple+Compositional task set, compared to 21% for the best baseline (Low-level Planning Only) and 2% for the other two baselines. The learned operator libraries correctly recover all ground-truth operators in both domains, enabling zero-shot generalization to more complex compositional tasks without additional training.

## Baselines & Comparisons

Ada outperforms all three baselines by large margins on every benchmark. Against LLM+P (Low-level Planning Only), which uses the LLM solely to translate goals into PDDL and plans directly, Ada improves from 31%→100% on Minecraft Mining and 21%→79% on ALFRED, demonstrating the critical value of a learned operator library for long-horizon planning. Against SayCan (Subgoal Prediction), which has the LLM directly predict sequences of formal subgoals, Ada improves from 6%→100% on Minecraft Compositional and 2%→79% on ALFRED; the paper attributes SayCan's failures to the LLM's inability to robustly sequence subgoals and ground object arguments. Against Voyager (Code Policy Prediction), which learns a library of imperative Python skills, Ada improves from 10%→100% on Minecraft Compositional and 2%→79% on ALFRED; the paper identifies three reasons for Voyager's weakness: the LLM is an unreliable planner over code skills, imperative code is less suited as a hierarchical planning representation than PDDL operators, and the unbounded code library (hundreds of skills) hinders efficient planning and generalization.

## Relation to Prior Work

Ada builds on the classical hierarchical planning stack (PDDL operators, FastDownward) and the recent wave of LLM-guided decision-making (SayCan, Voyager, LLM+P), but departs from all of them in a key way: rather than using the LLM to predict goals, subgoal sequences, or imperative code skills at inference time, it uses the LLM as a *generative prior* for learning a reusable library of symbolic operators through an iterative propose-verify-refine loop. This connects to earlier work on learning action abstractions from demonstrations (Andreas et al., 2017; Sharma et al., 2022; Luo et al., 2023) but replaces human demonstrations with language-model proposals, and to concurrent work on LLM-generated PDDL domains (Guan et al., 2024) by grounding operators hierarchically with learned low-level controllers. The bi-level planning architecture (symbolic high-level plan + local subgoal-conditioned search) follows the TAMP and hierarchical RL tradition, but the operator library itself is acquired automatically from language rather than hand-engineered.

## Why It Matters / Open Questions

The paper demonstrates that language models can serve as a rich prior for *learning* planning representations, not just predicting plans, and that the resulting operator libraries compose to generalize to unseen compositional tasks without additional training—a property that direct LLM planning approaches lack. Key limitations include the reliance on a pre-defined predicate vocabulary (no predicate discovery), the absence of fine-grained geometric or motor planning, and evaluation on relatively constrained synthetic/household domains. Open questions include whether the approach scales to open-world settings with richer perceptual inputs, whether LLMs can propose useful predicates over raw observations, and whether learned representations can be progressively transferred to other models (including the LLM itself) for faster planning.
