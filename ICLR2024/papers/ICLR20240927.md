## Problem

Existing LLM-based multi-agent systems for software development rely on unconstrained natural-language dialogue between agents, which causes cascading hallucinations, information distortion (analogous to the telephone game), and logic inconsistencies when tasks grow complex. No prior framework systematically encoded human Standardized Operating Procedures (SOPs) with structured intermediate deliverables to enforce role-specific quality standards and reduce unproductive 'idle chatter' between agents.
![Teaser figure](../imgs/ICLR20240927/cropped_page1_idx0.webp)

## Input / Output

The system accepts a single natural-language task prompt (e.g., 'Create a brick breaker game') and produces a complete software project through a sequential pipeline: a Product Requirements Document with user stories and requirement pool, a system design with file lists, data structures, and interface definitions, a task distribution plan, executable source code files, and unit test code. Intermediate outputs are structured documents and diagrams (not free-form text), and the final deliverable is a runnable application with an average executability score of 3.75/4 on the SoftwareDev benchmark.

## Method

MetaGPT organizes five specialized agents (Product Manager, Architect, Project Manager, Engineer, QA Engineer) in a strict SOP-driven assembly-line workflow where each role produces schema-constrained structured outputs (PRDs, interface definitions, sequence flow diagrams) rather than dialogue. Communication uses a global shared message pool with a role-based publish-subscribe mechanism: agents publish structured messages and subscribe only to message types relevant to their role profile, avoiding information overload and one-to-one communication bottlenecks. A key differentiator is the executable feedback loop, in which the Engineer agent compiles and runs generated code, inspects runtime errors against stored PRD and design documents in memory, and iteratively debugs (up to 3 retries) before handing off to QA—yielding a 5.4% absolute Pass@1 improvement on MBPP over the no-feedback variant.

## Results

MetaGPT with GPT-4 achieves 85.9% Pass@1 on HumanEval and 87.7% Pass@1 on MBPP, surpassing GPT-4 alone (67% reported by OpenAI) and all prior domain-specific code LLMs. On the self-generated SoftwareDev benchmark, MetaGPT attains an executability score of 3.75/4 (vs. ChatDev's 2.25), completes tasks in 503 seconds (vs. ChatDev's 762s), and requires only 0.83 human revisions (vs. ChatDev's 2.5). The executable feedback mechanism contributes a 4.2% absolute improvement on HumanEval and 5.4% on MBPP over MetaGPT without feedback.

## Baselines & Comparisons

On SoftwareDev, MetaGPT decisively outperforms ChatDev (Qian et al., 2023) on executability (3.75 vs. 2.25), productivity (124.3 vs. 248.9 tokens per line of code), and human revision cost (0.83 vs. 2.5), while also running faster (503s vs. 762s); MetaGPT uses more total tokens but generates 3.2× more code lines. Against AutoGPT, LangChain, and AgentVerse, MetaGPT achieves an average executability of 3.9/4 versus a uniform 1.0/4 for all three, which fail to produce executable code on any of the seven tasks. On HumanEval and MBPP, MetaGPT (with GPT-4) surpasses all domain-specific code models—AlphaCode, Incoder, CodeGeeX, CodeGen, CodeX, CodeT—and general LLMs (PaLM, GPT-4 standalone), reaching 85.9% and 87.7% Pass@1 respectively. The ablation in Table 4 further confirms that MetaGPT's structured SOP workflow is the key differentiator: removing the executable feedback mechanism drops executability from 3.75 to 3.67 and increases human revisions from 0.83 to 2.25.

## Relation to Prior Work

MetaGPT extends the LLM-based multi-agent software development line (CAMEL, ChatDev, AgentVerse) by replacing free-form dialogue with SOP-driven structured communication: agents produce typed documents (PRDs, system designs, task lists) exchanged via a global publish-subscribe message pool rather than conversational turns. It adopts the ReAct observe-think-act loop as the individual agent behavioral paradigm and adds an executable feedback mechanism that iteratively runs and debugs generated code, going beyond the non-executable self-reflection in Reflexion. The framework thus carves new ground at the intersection of meta-programming and multi-agent orchestration, positioning itself as a 'programming to program' system where specialized roles follow standardized handover protocols.

## Why It Matters / Open Questions

MetaGPT provides strong empirical evidence that structured, SOP-based multi-agent workflows substantially outperform both general-purpose autonomous agents (AutoGPT, LangChain, AgentVerse all score 1.0/4 on executability) and dialogue-based frameworks (ChatDev at 2.25/4), validating the intuition that domain-specific process discipline reduces cascading hallucinations in LLM collaboration. Open questions remain around scalability to real-world multi-module applications, the absence of UI/frontend agents, and whether the self-improvement mechanism (recursive constraint-prompt updates across projects) can close the gap between per-project execution and cumulative team learning. As an open-source platform, it has become a practical reference architecture for building SOP-governed LLM agent teams.
