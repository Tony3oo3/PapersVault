## Problem

Large language models perform poorly on complex inductive reasoning benchmarks like ARC when prompted to directly predict outputs via in-context learning, because the task requires discovering a precise, generalizable transformation rule rather than pattern-matching. The paper asks whether decomposing inductive reasoning into explicit hypothesis formation at multiple levels of abstraction—mirroring how humans reason—can substantially improve LLM performance on these tasks.
![Teaser figure](../imgs/ICLR20241530/cropped_page1_idx0.webp)

## Input / Output

The method takes a set of training input-output pairs (2D color grids up to 30×30 for ARC, 1D sequences for 1D-ARC, string pairs for SyGuS, or number lists for List Functions) plus one or more novel test inputs, and produces predicted outputs by executing verified Python programs. Grids are serialized as NumPy array text with color mappings, and the pipeline generates intermediate natural language hypotheses and concrete Python functions as byproducts. Programs are only deployed on test inputs after passing all training examples, and the paper observes a near-zero false-positive rate: programs that fit training data almost always generalize correctly.

## Method

The pipeline decomposes inductive reasoning into two abstraction levels inspired by Bayesian models of human cognition: (1) GPT-4 generates multiple natural language hypotheses about the underlying transformation rule (64 candidates for ARC, 16 for 1D-ARC), and (2) each hypothesis is implemented as multiple Python programs (8 per hypothesis) that are executed against training examples. To manage computational cost, the hypothesis set is reduced either by prompting GPT-4 to summarize 64 candidates into 8, or by having a human annotator select correct ones. Programs that fail on training examples enter an execution-feedback loop (up to 3 rounds) where error messages and failed outputs are fed back to GPT-4 for revision, analogous to self-debugging. The key empirical finding is that this two-level decomposition—abstract natural language hypotheses guiding concrete program synthesis—consistently outperforms both direct prompting and program-only generation across all four datasets, with the programmatic representation providing verifiability and the natural language layer providing the right level of abstraction for the LLM to reason about the rule.

## Results

On a 100-task subset of ARC, the full pipeline with LLM-summarized hypotheses achieves 30% accuracy, up from 17% for direct prompting and 23% for program-only generation; with human-selected hypotheses, accuracy reaches 33%, and with oracle human-written hypotheses it reaches 45%. On 1D-ARC (108 tasks), the full method achieves 73.1% accuracy versus 39.6% for direct prompting. On SyGuS (89 tasks), the method reaches 94.3% accuracy, and on List Functions (100 tasks), it achieves 69% versus 31% for direct prompting.

## Baselines & Comparisons

On 1D-ARC, the full pipeline (73.1%) substantially outperforms the direct prompting baseline from Xu et al. (2023b) at 39.6%, a 33.5-point improvement, with the program-only ablation already closing most of the gap at 61.1%. On SyGuS, the method achieves 94.3% accuracy, far exceeding the state-of-the-art DSL-based program synthesis approach CrossBeam (Shi et al., 2022) at 74.8%, a 19.5-point margin; notably, the program-only variant matches the full pipeline at 94.3%, indicating that natural-language hypotheses add little value on this simpler string-transformation task. On ARC, the summarized-hypothesis variant (30%) beats the direct prompting baseline (17%) by 13 points and the program-only variant (23%) by 7 points, while the human-selected variant (33%) approaches the oracle human-written hypothesis result (45%). The Icecuber DSL-based approach (43% on the same 100 ARC tasks) slightly outperforms the human-written hypothesis result, suggesting the pipeline is still bottlenecked by hypothesis generation quality on the hardest visual tasks.

## Relation to Prior Work

This paper draws on Bayesian models of human inductive reasoning (Tenenbaum et al., 2006; Goodman et al., 2008), which frame induction as posterior prediction over a hypothesis space, and translates this into a practical LLM pipeline: generate natural-language hypotheses, then implement them as verifiable Python programs. It departs from prior LLM-on-ARC work (Xu et al., 2023b; Mirchandani et al., 2023; Gendron et al., 2023) that relies on direct in-context learning to predict outputs, and from DSL-based program synthesis (BUSTLE, CrossBeam, DreamCoder) by using general-purpose Python instead of a manually designed language. The execution-feedback loop for code repair follows Chen et al. (2023), and the optional compositional search step adapts Parsel (Zelikman et al., 2023).

## Why It Matters / Open Questions

The paper demonstrates that decomposing inductive reasoning into explicit hypothesis generation and program implementation substantially outperforms end-to-end in-context learning across four diverse domains, and that the two levels of abstraction (language and code) each contribute independently. A notable empirical finding is the very low false-positive rate: programs that pass all training examples almost always generalize to test inputs, suggesting that the main bottleneck is hypothesis quality rather than program correctness. Key limitations include the high cost of sampling many hypotheses (64 per task), GPT-4's difficulty with 2D visual patterns when grids are encoded as text, and the gap between LLM-generated and human-written hypotheses on ARC. Open questions include whether vision-language models can close the visual-reasoning gap, whether the approach scales as inference costs drop, and how to handle tasks where the transformation is inherently stochastic or not expressible as an exact-match program.
