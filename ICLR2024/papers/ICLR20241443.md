## Problem

Transformer-based LLMs are constrained by a fixed context window, making them unable to generate long, internally consistent outputs such as large codebases. Existing memory-augmented LLMs either only read from memory (append-only strategies) or rely on highly specialized memory structures (e.g., variable dictionaries) that cannot generalize to open-ended generation tasks, leaving no practical framework for producing extensive, coherent multi-file outputs that fulfill detailed user-specified requirements.

## Input / Output

The method takes a detailed user-specified task description with explicit feature requirements (e.g., a system design interview prompt) and first decomposes it into a sequential instruction list via a self-programming step. The output is a complete file store of multiple code files (each shorter than the context window, with semantically meaningful directory paths) plus self-generated unit tests, all persisted externally. The same framework also produces extensive non-code text outputs, such as a full book, by swapping the evaluator and file structure.

## Method

L2MAC instantiates a von Neumann stored-program computer architecture where an LLM serves as the processor, an instruction registry I (the prompt program) and a file store D (data memory) form the memory, and a Control Unit (CU) orchestrates execution. The CU enforces three properties: (P1) task-oriented context management that dynamically fills, summarizes, and resets the context window per instruction to stay within the fixed token limit; (P2) precise read/write tools allowing the LLM agent to scan, read, create, overwrite, and delete any file in D by path; and (P3) automatic output checking via a domain-specific evaluator (syntactical linters and self-generated unit tests for code) that feeds errors back for iterative correction after every write. Each instruction in I is executed by a separate LLM agent (GPT-4-0613 in Code-L2MAC), and the CU cycles through instructions automatically until all are completed, with a 'step_complete' signal triggering evaluation and context summarization before advancing to the next instruction.

## Results

On three system design codebase generation tasks (URL Shortener, Online Social Media, Online Chat), Code-L2MAC achieves 91.6%, 82.4%, and 59.4% Features % respectively, substantially outperforming all baselines (best baseline: GPT4 at 53.6%, 19.5%, 11%). Code-L2MAC produces zero syntactical errors across all tasks and passes 14–18.8 self-generated unit tests, compared to 0.8–3.6 for baselines. On the HumanEval benchmark, Code-L2MAC achieves a 90.2% Pass@1 score. Generated codebases range from 330–395 lines of code, roughly 3× larger than baseline outputs (~100–150 LOC).

## Baselines & Comparisons

Code-L2MAC dominates all baselines on the primary Features % metric across all three system design tasks. Against AutoGPT (the closest autonomous-agent baseline), Code-L2MAC achieves 91.6% vs. 25.3% on URL Shortener (3.6× improvement), 82.4% vs. 33.3% on Social Media (2.5×), and 59.4% vs. 23.1% on Chat (2.6×). Against Reflexion, the gap is even wider: 91.6% vs. 38.8% on URL Shortener and 59.4% vs. 10.2% on Chat. Self-Refine, the strongest reflecting-LLM baseline, reaches only 47.9% on URL Shortener and 14.2% on Chat, roughly half of Code-L2MAC's performance. Code-L2MAC is the only method to achieve zero syntactical errors on all tasks while simultaneously generating the largest codebases (330–395 LOC vs. 76–220 for baselines) and the most passing unit tests (14–18.8 vs. 0.8–3.6), indicating that its control-unit-driven error checking and full-memory read/write capabilities are the key differentiators.

## Relation to Prior Work

This paper repurposes the von Neumann stored-program computer architecture as a conceptual and practical framework for LLM-based long output generation, drawing on the theoretical observation (Schuurmans, 2023) that memory-augmented LLMs can be computationally universal. It departs from memory-augmented LLMs (which are largely read-only or append-only) by implementing full read/write access to an external file store, and from autonomous agent systems like AutoGPT by replacing open-ended re-planning with a fixed instruction program executed automatically. It also extends reflecting LLMs (Reflexion, Self-Refine) by applying error checking not just to the current context window but to the entire accumulated file store, enabling correction of previously generated code.

## Why It Matters / Open Questions

The paper provides the first practical, general-purpose framework for LLMs to generate outputs that far exceed the context window while maintaining internal consistency, which is a fundamental bottleneck for real-world code generation and long-form content creation. Key limitations include dependence on a single underlying LLM (GPT-4), an implicit scale constraint from listing all file paths in context, and evaluation on only three system design tasks. Open questions include whether the framework generalizes to non-coding domains, how to handle complex branching instruction flows, and whether the automatic (fixed-program) paradigm can be extended to allow dynamic re-programming without losing task fidelity.
