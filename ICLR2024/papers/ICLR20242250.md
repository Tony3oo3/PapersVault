## Problem

LLMs frequently produce hallucinated facts, buggy code, and toxic content, yet existing mitigation strategies (RLHF, fine-tuning, self-training) demand large-scale human annotation or task-specific training. A critical open question is whether LLMs can reliably verify and correct their own outputs at inference time without any additional training. The paper demonstrates that LLMs are fundamentally unreliable at self-verification—without external feedback, self-correction often yields no improvement or even degrades performance—motivating a tool-augmented approach.
![Teaser figure](../imgs/ICLR20242250/cropped_page1_idx0.webp)

## Input / Output

The method takes a free-form text prompt (a QA question, a math word problem, or a toxic text continuation prompt) and a set of external tool APIs (Google search, Python interpreter, or Perspective toxicity API) as inputs. It produces a corrected text output after up to n iterative verify-then-correct rounds, where each round appends tool-returned evidence (search snippets, execution error messages, toxicity scores) as natural-language critiques to the generation context. The framework operates entirely through text-to-text API calls with few-shot ReAct-style demonstrations, requiring no model weight updates.

## Method

CRITIC is a training-free, plug-and-play framework built on few-shot in-context learning that enables frozen LLMs to self-verify and self-correct via a two-step iterative loop. In the verification step, the LLM generates tool queries (e.g., search queries, code to execute, toxicity scoring requests) and receives structured feedback from external tools, which is concatenated as natural-language critiques identifying specific errors (factual inaccuracies, syntax errors, toxic attributes). In the correction step, the LLM regenerates the output conditioned on the original input, the previous output, and the accumulated critiques. The loop repeats until the critique indicates correctness, a maximum iteration count is reached, or the output stabilizes. The key technical insight is that external tool feedback is essential for reliable correction: ablations removing tools show that LLM self-critiques alone are insufficient and can actively harm performance, because LLMs cannot accurately discriminate their own knowledge without grounded external evidence.

## Results

On free-form QA with ChatGPT (gpt-3.5-turbo), CRITIC achieves F1 scores of 74.9 (AmbigNQ), 81.7 (TriviaQA), and 52.9 (HotpotQA), improving over CoT by an average of 7.7 F1 points. On mathematical program synthesis, CRITIC improves over PoT by +5.7 on GSM8k, +1.3 on SVAMP, and +14.0 on TabMWP (ChatGPT), with the oracle variant CRITIC* reaching 83.9% on GSM8k. For toxicity reduction, CRITIC reduces toxicity probability from 0.192 to 0.040 (a 79.2% reduction) on ChatGPT, matching supervised RL methods like Quark (0.035) without any training.

## Baselines & Comparisons

CRITIC consistently outperforms all prompting-based baselines: it beats CoT by 7.7 F1 (ChatGPT) and 5.6 F1 (text-davinci-003) on average across three QA datasets, surpasses Self-Consistency on AmbigNQ and HotpotQA while roughly matching on TriviaQA, and exceeds ReAct by 5.1 F1 on ChatGPT by combining parametric knowledge with external verification rather than relying solely on retrieval. The ablation CRITIC w/o Tool (removing the search engine) shows only marginal gains (+2.3 F1) or even degradation, confirming that external tool feedback is essential rather than the LLM's self-generated critiques. On mathematical program synthesis, CRITIC improves over PoT by +5.7 on GSM8k (ChatGPT) and dramatically outperforms Self-Refine on Codex, which actually degrades from 71.3 to 26.7 accuracy due to unreliable self-feedback. For toxicity reduction, CRITIC achieves a toxicity probability of 0.040 (ChatGPT), comparable to the trained RL method Quark (0.035) and Self-Correct (0.026), while requiring no additional training data or model fine-tuning. In the self-verification analysis (Table 5), CRITIC achieves AUROC of 0.810–0.831 across QA datasets, substantially outperforming Self-Eval (0.668–0.731) and all intrinsic uncertainty estimation methods (0.693–0.831), demonstrating that tool-interactive verification is far more reliable than the LLM's own confidence signals.

## Relation to Prior Work

CRITIC builds on chain-of-thought and program-of-thought prompting for initial answer generation, and adopts ReAct-style interleaved tool interaction for the verification step. It departs fundamentally from the self-correction line of work (Self-Refine, Reflexion, CAI) by demonstrating that LLM-generated self-feedback is unreliable, and instead grounds verification in external tools (search engines, code interpreters, toxicity APIs) that provide objective, interpretable critiques. Unlike RLHF or trained correctors, CRITIC is entirely training-free and operates on black-box LLMs via in-context learning, positioning it as a plug-and-play inference-time technique rather than a model modification.

## Why It Matters / Open Questions

The paper's central empirical finding—that LLMs cannot reliably verify their own outputs and that self-correction without external feedback can actively degrade performance—challenges a widely assumed capability and redirects the field toward tool-grounded verification. Practically, CRITIC offers a simple, training-free loop that consistently improves across QA, math, and safety tasks with multiple model families, making it an accessible pattern for practitioners working with API-only models. Open questions include automatic tool selection without manual prompt engineering, extension to non-text modalities, and whether the latency cost of multi-round tool interaction is acceptable in latency-sensitive deployments.
