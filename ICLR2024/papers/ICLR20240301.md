## Problem

Existing prompting methods for LLMs are either ad-hoc human-in-the-loop procedures that don't transfer across tasks, or automatic approaches (e.g., APE) that perform essentially random search over prompt space without learning from past successes and failures. This means LLMs' critical thinking abilities—deep conceptualization, task decomposition, and structured reasoning—are not fully evoked by current prompting paradigms.
![Teaser figure](../imgs/ICLR20240301/cropped_page1_idx1.webp)

## Input / Output

The method takes an initial task instruction (generated via instruction induction or a simple task description) and a set of input-output training pairs as input. It produces a single refined natural-language prompt that is structured with clear task definitions, evaluation criteria, step-by-step execution instructions, and annotated demonstrations. A key design choice is that only 'hard' training samples (as scored by LLM-Selector on a 1–10 difficulty scale) are exposed to the LLM in each refinement iteration, rather than the full training set.

## Method

Evoke instantiates the same LLM in three distinct roles operating in an iterative loop over T steps. LLM-Author edits the current prompt by reviewing incorrect student responses against correct answers, drawing on a memory of prior (edit, score) pairs to make increasingly targeted revisions. LLM-Reviewer scores each candidate prompt on a 1–10 scale using a memory module that stores historical edits, prompts, and their corresponding task accuracies, enabling it to calibrate its judgments over iterations. LLM-Selector assigns difficulty scores to training samples so that only the hardest cases are used for prompt refinement, forcing the model to develop deeper task understanding. Each iteration selects the top-n highest-scoring prompts, computes their actual task accuracy, and feeds results back into both memory modules, creating a closed feedback loop that progressively enriches prompts with definitions, subtask decompositions, and detailed examples.

## Results

On the eight Instruction Induction and Big Bench Instruction Induction tasks, Evoke outperforms all baselines across the board. The most dramatic gain is on logical fallacy detection, where Evoke scores above 80 while both APE and Human-curated prompts remain below 20. On the adversarial robustness evaluation (Adversarial-SST2), Evoke reaches above 90% accuracy with three refinement iterations, compared to roughly 75% with a single iteration. On the fine-grained multi-lingual NER task, Evoke also significantly outperforms APE across all languages.

## Baselines & Comparisons

Evoke is compared against three baselines. Against Human-curated prompts (from Honovich et al. 2022 and Suzgun et al. 2022), Evoke wins on all eight main tasks, with the largest margin on logical fallacy detection (>80 vs. <20). Against APE (Zhou et al. 2022), which performs random rephrasing without a feedback loop, Evoke again wins on all eight tasks; the gap is most pronounced on logical fallacy detection where APE also stays below 20. Against RobEnc (Jones et al. 2020), a rule-based denoising defense, Evoke achieves higher accuracy on both Adversarial-SST2 and Adversarial-QQP, because Evoke's generated prompts include explicit guidelines for handling typos rather than relying on a separate preprocessing step. On the multi-lingual NER task, Evoke outperforms APE across all evaluated languages, demonstrating that the reviewer-author loop generalizes beyond sentence-level classification to token-level tasks.

## Relation to Prior Work

This paper extends the automatic prompt engineering lineage initiated by Instruction Induction (Honovich et al., 2022) and APE (Zhou et al., 2022), which established that LLMs can generate and select task instructions from input-output pairs. The key departure is replacing APE's paraphrase-and-select (effectively random search) with a structured author-reviewer feedback loop where a dedicated LLM-Reviewer scores prompts and an LLM-Author iteratively refines them using accumulated memory of past edits and scores. The additional data selection strategy (exposing only hard samples to the model) further differentiates Evoke from prior methods that treat all training examples uniformly.

## Why It Matters / Open Questions

The dramatic performance gap (80+ vs. <20 on logical fallacy detection) suggests that structured, memory-augmented feedback loops are far more effective than random search for prompt optimization, offering a practical recipe for practitioners who need task-specific prompts without extensive manual tuning. However, the evaluation is limited to a single model (GPT-4 via Azure API), and the baselines (hand-crafted prompts, APE) are relatively weak compared to more recent iterative or search-based prompt optimizers. Open questions include whether the author-reviewer paradigm generalizes to smaller or open-weight models, how computational cost scales with iteration count, and whether the LLM-Reviewer's scoring remains reliable across diverse task domains without task-specific calibration.
