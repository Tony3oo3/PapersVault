## Problem

Existing multi-agent collaboration frameworks for LLM-based agents are confined to narrow, task-specific settings and rely on static, manually assigned agent roles that cannot adapt as problem-solving progresses. This paper addresses the need for a general, scalable multi-agent framework that dynamically adjusts group composition and facilitates effective collaboration across diverse domains including reasoning, coding, tool use, and embodied AI.
![Teaser figure](../imgs/ICLR20240806/cropped_page1_idx0.webp)

## Input / Output

The framework takes a textual goal description g as input, optionally augmented with access to real-world tools (Bing search API, web browser, code interpreter, task-specific APIs). The output is a group decision A executed in the environment, yielding text answers, generated code with unit tests, or sequences of environment actions (e.g., Minecraft item crafting). The process is iterative: if the evaluation stage determines the goal is unmet, verbal feedback is returned to re-trigger expert recruitment with a reconstituted group, making the I/O loop stateful across rounds.

## Method

AGENTVERSE models the problem-solving process as a Markov decision process (S, A, T, R, G) and decomposes it into four iterative stages: Expert Recruitment, Collaborative Decision-Making, Action Execution, and Evaluation. Expert Recruitment is automated by prompting a designated 'recruiter' agent to dynamically generate expert role descriptions from the current goal, eliminating the need for manually pre-defined roles and enabling scalable group composition. Collaborative Decision-Making supports two communication structures: a horizontal (democratic) structure where all agents share and integrate decisions via a summarization function, and a vertical structure where a solver proposes and reviewers iteratively refine until consensus. The Evaluation stage produces verbal feedback on the gap between current state and goal, which feeds back into Expert Recruitment to adjust group composition in subsequent rounds. All experiments are conducted zero-shot using GPT-3.5-Turbo and GPT-4 as backbone LLMs, with the framework instantiated over Voyager agents for embodied Minecraft tasks.

## Results

On GPT-4, AGENTVERSE (Group) achieves 96.8% win rate on FED, 99.1% concept coverage on Commongen-Challenge, 95.2% accuracy on MGSM, and 66.5% accuracy on Logic Grid Puzzles, outperforming the CoT baseline (95.4, 95.9, 95.2, 59.5 respectively). On Humaneval, GPT-4-based AGENTVERSE improves pass@1 from 83.5 (CoT) to 89.0 (Group). For tool utilization, AGENTVERSE completes 9 out of 10 complex multi-tool tasks, compared to only 3/10 for a standalone ReAct agent.

## Baselines & Comparisons

Against the CoT baseline (Wei et al., NeurIPS 2022), AGENTVERSE consistently wins on GPT-4 across all four reasoning/understanding benchmarks: +1.4 on FED, +3.2 on Commongen, +0.8 on MGSM (Solo), and +7.0 on Logic Grid Puzzles (Group). On Humaneval, GPT-4 Group achieves 89.0 pass@1 versus 83.5 for CoT (+5.5). However, for GPT-3.5-Turbo, the Group setup underperforms Solo on Commongen (92.3 vs 93.6) and MGSM (80.8 vs 82.4), attributed to weaker agents being swayed by incorrect peer feedback (~10% of MGSM errors). Against the ReAct baseline (Yao et al., ICLR 2023) on tool utilization, AGENTVERSE dramatically outperforms: 9/10 tasks completed versus 3/10, with the single ReAct agent failing to meet task criteria or exiting prematurely in 6 of its 7 failures.

## Relation to Prior Work

This paper synthesizes ideas from several lines of LLM agent research—chain-of-thought prompting, ReAct-style tool use, Voyager for embodied navigation, and role-based multi-agent collaboration (CAMEL, MetaGPT, multi-agent debate)—into a unified four-stage framework (Expert Recruitment, Collaborative Decision-Making, Action Execution, Evaluation) modeled as an MDP. Its key departure from prior multi-agent work is the dynamic, goal-conditioned adjustment of group composition across iterations, whereas earlier approaches (e.g., CAMEL, Park et al.) fix agent roles or focus on narrow task domains. The framework also explicitly distinguishes horizontal (democratic) and vertical (solver-reviewer) communication structures, drawing on organizational design literature rather than purely algorithmic considerations.

## Why It Matters / Open Questions

AGENTVERSE provides a general, task-agnostic scaffold for multi-agent LLM collaboration that practitioners can adapt across domains, and its identification of emergent destructive behaviors (agents harming peers or destroying structures to shortcut tasks) raises concrete safety concerns for real-world deployment. Key limitations include the susceptibility of weaker models (GPT-3.5-Turbo) to incorrect peer feedback during group discussion, the pre-defined (rather than learned) number of experts, and the sequential rather than truly concurrent communication paradigm. Open questions include how to automate expert count selection, how to design safeguards against destructive emergent behaviors, and whether the framework's benefits persist as LLMs improve in robustness to conflicting information.
