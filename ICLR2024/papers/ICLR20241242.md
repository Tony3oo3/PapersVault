## Problem

Prior LLM-based theorem provers (e.g., DSP, Subgoal-Learning) synthesize proofs sequentially in a single block using a fixed theorem library, so proved lemmas cannot be reused across problems and long-chain proofs remain intractable. This paper addresses the gap by introducing a growing skill library of verified lemmas that accumulates during the proving process, enabling modular, block-by-block proof construction where sub-lemmas are retrieved, reused, and newly created.
![Teaser figure](../imgs/ICLR20241242/cropped_page1_idx0.webp)

## Input / Output

Each problem provides an informal natural-language statement, an informal proof (either human-written or GPT-4-generated, with up to 20 candidates per problem), and a formal Isabelle statement. The prover outputs a complete Isabelle source file (including imports, auxiliary lemmas, and the main theorem proof), which is verified by the Isabelle theorem prover via the PISA environment. As a by-product, all verified lemmas are added to a growing vector-store library (ChromaDB), while unverified lemma statements are stored as 'requests' for the evolver to attempt later.

## Method

LEGO-Prover runs two parallel components — a prover and an evolver — that share three vector stores (lemma, request, problem). The prover executes a three-step pipeline: an informal solver drafts a natural-language solution, a decomposer breaks it into a structured step-by-step proof and generates formal lemma requests (with chain-of-thought reasoning), and a formalizer retrieves top-k skills via k-NN and produces a complete Isabelle proof file. The evolver continuously generalizes existing lemmas along four predefined directions (identify key concepts, parameterize, scale complexity, extend dimensions) or directly solves pending requests, adding only Isabelle-verified and sufficiently novel (SequenceMatcher < 0.85) lemmas back to the library. This modular, divide-and-conquer approach lets the LLM copy verified lemma code directly or use it as a reference for constructing new lemmas, progressively bridging the gap between informal and formal mathematics as the library grows to over 20,000 skills.

## Results

On the miniF2F dataset, LEGO-Prover achieves a cumulative pass rate of 57.0% on miniF2F-valid and 50.0% on miniF2F-test, representing a 6.75% absolute improvement over the previous state-of-the-art (Subgoal-Learning at 48.0%/45.5%). With human-written informal proofs specifically, LEGO-Prover reaches 55.3% valid and 50.0% test. The ablation removing the growing skill library drops performance to 50.4% on the valid set (−4.9%), confirming the library's contribution. During proving, LEGO-Prover generates over 20,000 verified skills (lemmas) that are added to the growing library.

## Baselines & Comparisons

LEGO-Prover (ChatGPT, human informal proof) outperforms all four main baselines on both splits: it beats Subgoal-Learning (48.0%/45.5%) by +7.3%/+4.5%, Draft-Sketch-Prove (42.6%/39.3%) by +12.7%/+10.7%, Thor+Expert Iteration (37.3%/35.2%) by +18.0%/+14.8%, and Thor (28.3%/29.9%) by +27.0%/+20.1%. In the supplementary GPT-4 comparison (Table 3), LEGO-Prover with ChatGPT (55.3%/50.0%) surpasses DSP with GPT-4 (51.2%/43.0%) by +4.1%/+7.0% and Lyra with GPT-4 (52.0%/47.1%) by +3.3%/+2.9%, despite using a weaker base model. The only comparison where LEGO-Prover trails is against Lyra extended to 200 attempts with GPT-4 (55.3%/51.2%), where LEGO-Prover matches on valid (55.3%) but is 1.2% behind on test. The ablation without the skill library (50.4%) confirms that the growing library contributes a 4.9% absolute gain, and even when the ablation is given an extra 100 attempts to balance token cost, LEGO-Prover still leads by 2.1%.

## Relation to Prior Work

LEGO-Prover extends the DSP (Draft, Sketch, and Prove) autoformalization pipeline by replacing the monolithic, sequential proof generation with a modular, block-by-block construction backed by a growing skill library of verified lemmas. The growing-library concept is directly inspired by Voyager's dynamic skill library for Minecraft agents and DreamCoder's program synthesis, repurposed for formal mathematics. Unlike prior LLM-based provers (Thor, Subgoal-Learning, Lyra) that treat each problem independently with a static model, LEGO-Prover introduces an evolver that continuously generalizes and solves lemma requests, creating a feedback loop where solved problems enrich the library for subsequent ones.

## Why It Matters / Open Questions

The growing skill library addresses a fundamental limitation of current LLM provers: the inability to accumulate and reuse intermediate results across problems, which is essential for tackling increasingly complex mathematics. However, the evaluation is confined to miniF2F (488 problems) with ChatGPT (GPT-3.5), and the evolver's high token cost (~117M tokens per experiment) with only 9.1% of generated proofs surviving filtering raises scalability questions. Open questions include whether the approach transfers to larger benchmarks (e.g., Putnam, IMO-level problems), whether stronger LLMs (GPT-4, Claude) reduce the need for the evolver, and how to reduce the computational overhead of continuous library evolution.
