## Problem

Existing rule extraction methods for differentiable rule learning models like DRUM lack formal guarantees that the extracted rules faithfully represent the model's behavior. The paper shows that standard Datalog rules extracted from DRUM can be both unsound (deriving facts the model does not predict) and incomplete (failing to explain predicted facts), which is problematic in safety-critical or legally regulated contexts. Moreover, it proves that no standard Datalog program can be faithful to a DRUM model, since DRUM's predictions depend on counting distinct rule matches rather than mere existence.

## Input / Output

The method consumes a trained DRUM model specified by its rank N, depth L, parameter tensors a^h ∈ [0,1]^{N×L×(2δ+1)}, and prediction threshold β, along with a rule extraction threshold γ. The primary output is a multipath Datalog program where rule bodies contain multipath conjunctions—C renamed copies of a core path with pairwise inequality constraints (under the Unique Name Assumption) ensuring at least C distinct matches. For the fixed-dataset variant, the output is a smaller sound rule set that exactly reproduces all model predictions on that specific dataset. For MMDRUM, the output reduces to standard Datalog rules of the form R_h(x,y) ← ψ_{k1} ∧ ... ∧ ψ_{kℓ}, enabling efficient extraction via structure-sharing and threshold-based pruning.

## Method

The key insight (Lemma 1) is that DRUM's prediction for a fact R_h(c_s, c_t) equals a weighted sum over all path rules, where each rule's weight is a product of model parameters and its contribution is the count of distinct body matches in the data. Since standard Datalog cannot express counting, the paper introduces multipath conjunctions—C copies of a core path with inequalities forcing distinct matches—within an extended Datalog language. Algorithm 1 enumerates all combinations of cardinalities for each possible core path and outputs rules whose weighted sum exceeds the threshold, achieving faithfulness at γ = β but with exponential complexity. To address this, two practical alternatives are proposed: (1) Algorithm 2 extracts a sound rule set for a fixed dataset by enumerating actual paths in the data and counting matches per predicate sequence, and (2) SMDRUM and MMDRUM variants replace summation with max aggregation at different levels of the computation, progressively reducing expressivity while enabling polynomial-time faithful extraction. MMDRUM, which uses max at both the sub-model and path levels, admits an efficient extraction algorithm (Algorithm 4) that interleaves rule construction with score computation and prunes branches whose partial product falls below the threshold.

## Results

On inductive KG completion, DRUM achieves the highest F1 scores across most datasets (e.g., 74.8% on WN18RR V1, 85.4% on NELL-995 V1, 58.7% on FB15k-237 V4), while MMDRUM and SMDRUM achieve competitive but slightly lower F1 (68.4% and 71.0% on WN18RR V1; 31.9% and 81.4% on NELL-995 V1). NEURAL-LP shows dramatically lower recall on WN18RR (20.7% on V1 vs. 62–69% for DRUM-based models), highlighting the importance of multiple sub-models (N>1). Both practical rule extraction algorithms (Algorithm 2 for fixed datasets and the MMDRUM algorithm) complete in under 3 minutes, while the standard DRUM rule extraction covers less than 7% of model predictions, confirming its incompleteness.

## Baselines & Comparisons

DRUM (the original model) consistently achieves the highest F1 scores, outperforming MMDRUM by 3–13 points and SMDRUM by 1–7 points on WN18RR splits (e.g., 74.8% vs. 68.4% and 71.0% on V1), confirming that the expressivity lost in the simplified variants has a measurable cost. NEURAL-LP is the weakest baseline, with recall collapsing to 20.7% on WN18RR V1 (vs. 62.2% for DRUM) and 13.0% on NELL-995 V1 (vs. 76.0% for DRUM), demonstrating that the multi-sub-model architecture (N>1) is critical for recall. MMDRUM and SMDRUM are nearly identical on FB15k-237 (differences ≤0.5 F1 points) but diverge on WN18RR, where SMDRUM's max-based aggregation gives it a 2–6 point F1 advantage over MMDRUM. On the Family dataset, all four methods are within ~4 F1 points of each other (89.4–93.8%), with NEURAL-LP actually matching MMDRUM. The key trade-off is that DRUM's superior predictive performance comes at the cost of incomplete rule extraction (<7% coverage), while MMDRUM and SMDRUM sacrifice a few points of F1 to enable faithful (sound and complete) rule extraction.

## Relation to Prior Work

This paper extends the faithful rule extraction framework of Tena Cucala et al. (2022b) from NEURAL-LP to DRUM, a differentiable rule learning model with superior empirical performance but structurally different architecture (multiple sub-models, no skip connections, inverse rule support). The key conceptual departure is the introduction of multipath rules—Datalog extended with inequalities (under the Unique Name Assumption) and disjunctions—as the formal language capable of faithfully representing DRUM's counting-based semantics. The paper also introduces two restricted model variants, SMDRUM and MMDRUM, that trade expressivity for tractable rule extraction, building on the max-product algebraic structure of DRUM's forward pass.

## Why It Matters / Open Questions

The result that no standard Datalog program can faithfully represent a DRUM model (Theorem 2) is a clean negative result establishing a fundamental expressivity gap, while the empirical finding that standard DRUM rule extraction covers less than 7% of model predictions underscores how inadequate current extraction methods are for safety-critical or compliance contexts. The practical algorithms (fixed-dataset extraction in under 3 minutes, efficient MMDRUM extraction) make faithful explanations feasible in practice, though the extracted rules can be lengthy and hard to interpret. Open questions include optimizing the full faithful extraction algorithm (Algorithm 1), extending the analysis to higher-arity predicates and other models like ∂ILP, and developing interpretability-preserving extraction that prioritizes shorter rules.
