## Problem

GPT-4 Code Interpreter achieves strong zero-shot math performance (69.69% on MATH), but its success has not been systematically analyzed, and its built-in self-debugging only verifies code executability rather than the correctness of reasoning steps or the final answer. The paper asks whether GPT4-Code's code generation and execution capabilities can be fully exploited to enable autonomous answer verification and correction without external verifier models or user intervention.
![Teaser figure](../imgs/ICLR20240179/cropped_page2_idx0.webp)

## Input / Output

The method takes a math word problem as plain text input and produces a numerical answer accompanied by a code-generated verification state (True, False, or Uncertain). When the verification state is False, the model iteratively regenerates a corrected solution until verification passes or no further verification is possible. In the voting variant, k sampled solution-verification pairs are aggregated, with each candidate answer receiving a weighted score determined by the verification states of the paths that produced it.

## Method

The core contribution is explicit code-based self-verification (CSV), a zero-shot prompt that instructs GPT4-Code to generate and execute verification code after producing a solution, yielding a True/False/Uncertain state that triggers either acceptance or iterative correction. Pilot experiments introduce Code Usage Frequency as a quantitative metric, revealing that GPT4-Code's advantage stems from step-by-step code generation interleaved with natural language reasoning and a self-debugging loop that rectifies implausible execution outputs. Building on this, the paper proposes Verification-guided Weighted Majority Voting (VW-voting), which generalizes naive majority voting by assigning distinct weights w_T > w_U > w_F to solutions based on their verification states, so that code-verified-true answers carry more voting power than uncertain or false-verified ones. The entire pipeline operates in zero-shot mode with no external verifier, no few-shot examples, and no fine-tuning, relying solely on GPT4-Code's native code interpreter capability.

## Results

On the MATH dataset, GPT4-Code with CSV and Verification-guided Weighted Majority Voting (VW-Voting, k=16) achieves 84.32% zero-shot accuracy, surpassing the GPT4-Code baseline (69.69%) by 14.63 points and the previous SOTA GPT-4+PHP (53.90%) by 30.42 points. On GSM8K, the full pipeline reaches 97.0% accuracy with only 5 sampled paths, outperforming GPT-4 with model selection (96.8%, 15 paths) and GPT-4+PHP (96.5%, 40 paths). On MMLU-Math, GPT4-Code+CSV+VW-Voting achieves 94.5% zero-shot, far exceeding the best open-source model Llama-2-70B (47.1%).

## Baselines & Comparisons

The paper's full pipeline (GPT4-Code + CSV + VW-Voting) outperforms all GPT-4-based baselines on MATH: GPT-4 (42.20%), GPT-4+Complex CoT (50.36%), and GPT-4+PHP (53.90%), with margins of 42.1, 34.0, and 30.4 points respectively. On GSM8K, the method achieves 97.0% with only 5 sampled paths, slightly beating GPT-4+Model Selection (96.8%, 15 paths) and GPT-4+PHP (96.5%, 40 paths) while requiring fewer samples. On MMLU-Math, GPT4-Code+CSV+VW-Voting (94.5%) dramatically outperforms all open-source models tested: Llama-2-70B (47.1%), Galactica (41.3%), Chinchilla (35.7%), and Gopher (30.6%). The ablation in Table 4 further shows that code-based self-verification improves accuracy across all seven MATH subtopics (average +3.85%), whereas natural-language self-verification slightly degrades performance (−0.40%), confirming the necessity of code execution for reliable verification.

## Relation to Prior Work

This paper sits at the intersection of code-augmented reasoning (PAL, Program of Thoughts) and self-consistency/majority voting (CoT-SC), but departs from both in a key way: rather than using code as a one-shot calculator or relying on an external verifier model, it exploits GPT-4 Code Interpreter's iterative code-generation-and-execution loop to perform both solving and verification within a single zero-shot prompt. The Verification-guided Weighted Majority Voting (VW-voting) is a direct generalization of CoT-SC's naive majority voting, where the verification state (True/Uncertain/False) replaces uniform counting with weighted scoring. The self-debugging mechanism observed in GPT4-Code is positioned as distinct from prior self-debug work (Chen et al., 2023b) because it operates over multi-step math reasoning rather than single code-generation tasks.

## Why It Matters / Open Questions

The paper provides the first systematic decomposition of why GPT-4 Code Interpreter excels at math (Code Usage Frequency analysis) and offers a simple, zero-shot prompting recipe (CSV) that practitioners can immediately adopt. A notable finding is that natural-language self-verification actually degrades performance relative to no verification, while code-based verification consistently helps across all MATH subtopics, suggesting that executable verification is fundamentally more reliable than linguistic self-checking. However, the method's gains are heavily contingent on GPT4-Code's specific capabilities; transfer to open-source models (CodeLlama-7B/34B) yields only modest improvements, and geometry problems see minimal benefit due to multimodality requirements. Open questions include whether the 95.88% verification precision can be pushed higher, whether the approach generalizes to non-mathematical reasoning tasks, and whether the weighted voting scheme is optimal or whether learned weights could further improve performance.
