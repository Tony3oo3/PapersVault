## Problem

Weight-only quantization (W4A16) for LLM inference reduces memory footprint but still requires an expensive on-the-fly dequantization step before standard FP16 GEMM, negating much of the computational benefit. The generation phase is memory-bound, so prior methods like OPTQ and AWQ gain speed primarily from reduced memory movement rather than actual FLOP reduction. This paper asks whether matrix multiplication can be performed directly on quantized weights—eliminating dequantization entirely—while simultaneously reducing the number of arithmetic operations.

## Input / Output

The kernel consumes a weight matrix decomposed into q binary vectors (each element ∈ {−1,+1}) plus per-group FP16 scaling factors (group size g, typically 128), and a single FP16 activation vector of length n. It produces an FP16 output vector of length m, identical in format to standard GEMM. A key constraint is that the LUT is built from sub-vectors of the activation (width μ, e.g., μ=8), so the activation must be available in full precision at kernel launch; the method is designed for single-batch (memory-bound) inference where one activation vector is multiplied against many weight rows.

## Method

LUT-GEMM reformulates weight-only quantized GEMM using an extended binary-coding quantization (BCQ) format that adds a bias term, enabling it to represent both uniform (e.g., AWQ, GPTQ) and non-uniform quantization schemes. The core mechanism replaces redundant multiplications: for a sub-vector of μ activation elements, all 2^μ possible signed sums are pre-computed into a lookup table stored in GPU shared memory, and each row of the binary weight matrix provides a μ-bit key to retrieve the corresponding partial dot product in one memory access. This reduces computational complexity from O(mn) to O(m·n/μ·q), a q/μ-fold savings, while the GPU kernel assigns l LUTs per thread block so that multiple threads share LUT entries and only perform a final scaling-factor multiplication and atomic accumulation. Group-wise quantization (varying g) provides a continuous compression-ratio knob: when g ≫ 16, the scaling-factor memory overhead becomes negligible and latency depends only on the total memory footprint, enabling fine-grained latency-accuracy trade-offs beyond what the bit-width q alone offers.

## Results

On the first FFN layer of OPT-175B (m=12288, g=128, A100-80GB), LUT-GEMM with 3-bit BCQ weights achieves 0.2250 ms latency (3.22× speedup over FP16 cuBLAS), outperforming OPTQ (0.3599 ms, 2.02×) and AWQ (0.3238 ms, 2.24×). End-to-end on OPT-175B with 3-bit quantization, LUT-GEMM on a single GPU achieves 51.6 ms/token versus 106.5 ms/token for OPTQ, yielding the headline 2.1× speedup. For LLaMA-65B, 3-bit LUT-GEMM fits on a single GPU (31.3 ms/token) where FP16 requires OOM, and LUT-GEMM-2-bit on a single GPU consumes only 43.49 mJ per matrix multiplication versus 161.85 mJ for FP16 cuBLAS (0.27× energy).

## Baselines & Comparisons

LUT-GEMM consistently outperforms both OPTQ (GPTQ) and AWQ on latency across all tested configurations. Against OPTQ at 3-bit on the OPT-175B first FFN layer, LUT-GEMM achieves 0.2250 ms versus 0.3599 ms (1.6× faster), and end-to-end on OPT-175B it reaches 51.6 ms/token versus 106.5 ms/token (2.1× faster), with the gap attributed to eliminating the dequantization step. Against AWQ at 4-bit, LUT-GEMM is 0.2688 ms versus 0.3238 ms on the kernel benchmark (1.2× faster), and on LLaMA-30B end-to-end, LUT-GEMM-4-128 achieves 20.7 ms/token on 1 GPU versus 43.6 ms for FP16 cuBLAS (2.1× faster). LUT-GEMM also demonstrates a unique advantage in reducing GPU count: OPT-175B at 3-bit runs on a single GPU with LUT-GEMM (51.6 ms) while FP16 requires 8 GPUs (42.4 ms), and the energy per matrix multiplication drops to 0.27× that of FP16 cuBLAS. The paper notes that LUT-GEMM's gains are most pronounced in single-batch (memory-bound) inference; with larger batch sizes the advantage diminishes due to shared-memory bandwidth constraints.

## Relation to Prior Work

This paper extends Binary-Coding Quantization (BCQ) from Xu et al. (2018), originally designed for non-uniform quantization with binary vectors, by introducing a bias term that enables representation of both uniform and non-uniform quantization within a single framework. It departs from the dominant weight-only quantization paradigm (OPTQ/GPTQ, AWQ) where quantized weights must be dequantized to FP16 before standard GEMM, instead operating directly on quantized weights via lookup-table-based computation. The LUT-based computation strategy builds on BiqGEMM (Jeon et al., 2020) but is recontextualized for large-scale LLM inference, where the memory-bound generation phase makes dequantization overhead particularly costly.

## Why It Matters / Open Questions

By eliminating the dequantization step, LUT-GEMM reduces OPT-175B inference from 8 GPUs to a single GPU while achieving 2.1× lower token generation latency than OPTQ, with a 73% reduction in energy consumption. The group-wise quantization parameter g provides a practical knob for trading compression ratio against accuracy without changing the kernel. However, the method is limited to single-batch inference, where performance gains diminish as batch size grows due to shared-memory bandwidth constraints on LUT accesses, leaving open the question of whether hardware advances (larger shared memory, wider LUT bandwidth) will unlock multi-batch efficiency.
