## Problem

Training moderate-sized LLMs from scratch on trillions of tokens remains cost-prohibitive, and existing structured pruning methods for LLMs produce non-uniform architectures with suboptimal inference speed while neglecting the critical continued pre-training stage. The paper asks whether a smaller, competitive, general-purpose LLM can be produced by leveraging an existing pre-trained LLM with only a fraction of the compute required for from-scratch training.
![Teaser figure](../imgs/ICLR20240211/cropped_page1_idx0.webp)

## Input / Output

The method takes a pre-trained source model (LLaMA2-7B), a target architecture specification borrowed from existing well-optimized models (Pythia-1.4B for 1.3B, INCITE-Base-3B for 2.7B), and multi-domain pre-training data (RedPajama with 7 domains: CommonCrawl, C4, GitHub, Wikipedia, Books, ArXiv, StackExchange). It outputs a smaller dense LLM with a uniform layer configuration exactly matching the target shape, trained with only 0.4B tokens for pruning plus 50B tokens for continued pre-training (~3% of the compute for equivalent from-scratch models). The head dimension is inherited from the source model, and the target number of heads is derived as target hidden dimension divided by source head dimension.

## Method

LLM-shearing is a two-stage algorithm. Stage 1 (targeted structured pruning) learns binary masks at four granularities—layers, hidden dimensions, attention heads, and intermediate dimensions—parameterized via hard concrete distributions, with a pair of Lagrange multipliers per substructure enforcing exact target architecture constraints in a joint min-max optimization over model weights and masks. Stage 2 (continued pre-training) recovers performance using dynamic batch loading, which every m steps evaluates per-domain validation losses against reference losses (predicted by fitting scaling laws to the LLaMA2 model family) and updates domain sampling proportions via exponential ascent to equalize loss reduction rates across domains. The key insight is that pruning preserves knowledge unevenly across domains (e.g., low-entropy GitHub recovers faster than high-entropy C4), so the original pre-training data distribution is inefficient for recovery. The target architecture is deliberately chosen from existing model configurations to guarantee uniform layers and efficient inference, unlike prior methods like CoFiPruning that produce non-uniform structures.

## Results

Sheared-LLaMA-1.3B (trained on only 50B tokens) achieves an average downstream score of 51.0 across 11 tasks, outperforming TinyLlama-1.1B (50.0, trained on 3T tokens) and Pythia-1.4B (48.9, trained on 300B tokens). Sheared-LLaMA-2.7B (50B tokens) reaches an average of 56.7, surpassing OpenLLaMA-3B-v2 (55.7, 1T tokens), INCITE-Base-3B (54.7, 800B tokens), and OpenLLaMA-3B-v1 (55.1, 1T tokens). Notably, Sheared-LLaMA-2.7B achieves the best HellaSwag (70.8) and ARC-C (41.2) scores among all models at its scale, while requiring only ~3% of the compute budget of comparable models.

## Baselines & Comparisons

Sheared-LLaMA-1.3B (50B tokens) outperforms all 1.3B-scale baselines on average: OPT-1.3B (48.2), Pythia-1.4B (48.9), and notably TinyLlama-1.1B (50.0) which was trained on 3T tokens—60× more data. Sheared-LLaMA-2.7B (50B tokens) beats all 2.7–3B-scale baselines: OPT-2.7B (51.4), Pythia-2.8B (52.5), INCITE-Base-3B (54.7), OpenLLaMA-3B-v1 (55.1), and OpenLLaMA-3B-v2 (55.7), with the largest margin over OPT-2.7B (+5.3) and Pythia-2.8B (+4.2). Against the source model LLaMA2-7B (64.6), Sheared-LLaMA-2.7B trails by 7.9 points, as expected. In pruning-method comparisons, targeted structured pruning achieves slightly higher validation PPL than CoFiPruning (10.3 vs 9.1 at 1.3B) but delivers 14% faster inference (58 vs 51 tokens/s) due to uniform layer configuration. Against LLM-Pruner, Sheared-LLaMA achieves lower PPL (6.85 vs 7.09), 35% faster inference (58 vs 43 tokens/s), and 67% higher training throughput (139K vs 83K tokens/s) at comparable parameter counts.

## Relation to Prior Work

This paper extends structured pruning for LLMs (CoFiPruning, LLM-Pruner) by reframing pruning from a compression step into an initialization strategy: the pruned model is then substantially continued-pretrained rather than used as-is. The mask parameterization draws directly on the hard concrete distribution from Louizos et al. (2018), while the dynamic batch loading algorithm adapts the exponential-ascent data-mixture update from DoReMi (Xie et al., 2023) but eliminates the need for training separate reference and proxy models. The key conceptual departure from prior pruning work is the explicit use of Lagrange multipliers to enforce a pre-specified target architecture (rather than a sparsity ratio), producing uniform, inference-friendly layer configurations.

## Why It Matters / Open Questions

The practical impact is substantial: producing a competitive 1.3B or 2.7B LLM with only ~50B tokens of additional compute (3% of the budget for training from scratch) offers a cost-effective path for organizations without access to massive training clusters. The finding that pruning preserves knowledge unevenly across domains (low-entropy domains like GitHub retain more than high-entropy domains like C4) and that dynamic batch loading corrects this imbalance is a useful diagnostic for continued pre-training more broadly. Key limitations include dependence on open-source pre-training data that approximates the source model's training distribution, and experiments restricted to a 7B source model; whether the approach scales to 70B+ sources and how sensitive it is to data-distribution mismatch remain open questions.
