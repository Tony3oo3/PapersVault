## Problem

Existing RL-based program synthesis methods rely almost exclusively on on-policy policy-based algorithms (REINFORCE, PPO), which are sample-inefficient and cannot principledly leverage the abundant off-policy data (human-written programs, historical synthetic samples) available in code generation. Value-based RL is naturally suited to this task—rewards are cheaply obtained via unit tests and off-policy data is plentiful—but training Q-functions in the doubly-exponential state-action space of token-level code generation has been considered intractable. This paper asks whether value-based RL can be stabilized and made competitive for program synthesis.

## Input / Output

The model takes a natural language problem description D as input and autoregressively generates a Python program as a sequence of tokens, with the state at each step being (w_{<t}, D). Rewards are determined only at the final token by executing the completed program against hidden unit tests (pass all: +1.0, fail some: -0.3, runtime error: -0.6, compile error: -1.0). Beyond the generated program, the trained Q-function yields a free reward model r̃_θ that assigns per-token rewards to any candidate program, enabling post-hoc ranking of m generated programs to select the top-k most likely correct ones without requiring test execution at inference time.

## Method

B-Coder builds on a T5 encoder-decoder (770M params, initialized from CodeRL checkpoint) and parameterizes the Q-function via a dueling decomposition Q(s,a) = α[ℓ_θ(s,a) − max_a ℓ_θ(s,a)] + V_θ^r(s) + V_φ(s), where the advantage head is tied to the LM logits and the value head is a residual on top of a pre-trained V_φ. Training proceeds in two stages: (1) a φ-stage that pre-trains V_φ by minimizing temporal-difference error while freezing the advantage function initialized from the pre-trained LM's logits (Q(s,a) = α·ℓ_ckpt(s,a)), and (2) a θ-stage that fine-tunes θ using a conservative Bellman operator B^q that replaces argmax_a Q(s',a) with argmax_a q(a|s') where q is the fixed pre-trained policy, combined with an auxiliary advantage loss enforcing A(W*)≈0 and a cross-entropy regularizer. The conservative operator is a γ-contraction, guaranteeing a unique fixed point without requiring full state-action coverage, and its inverse T^q is a bijection that recovers a reward model r̃_θ = Q_θ(s,a) − γV_θ(s') at zero additional training cost, which is then used to rank candidate programs for pass@k evaluation.

## Results

On the APPS benchmark (without example unit tests), B-Coder (≤770M params/stage) achieves the best Pass@1 (2.30 overall) and Pass@5 (3.80 overall) among all compared methods, outperforming the strongest RL baseline CodeRL (2.20 / 3.10) and the concurrent work RLTF (1.45 / 3.78). On Pass@1000, B-Coder scores 18.12 overall, placing second behind RLTF (19.92) while still surpassing CodeRL (17.78) and PPOCoder (17.77). Notably, B-Coder achieves these results using only the basic 4-level reward (equation 2) with no additional reward engineering, whereas CodeRL uses a learned reward model and RLTF uses fine-grained and adaptive rewards.

## Baselines & Comparisons

B-Coder outperforms all LLM baselines (Codex, GPT-3, GPT-2, GPT-Neo, GPT-J) on Pass@1 and Pass@5, with the closest margin being against GPT-J (2.30 vs 1.82 on Pass@1; 3.80 vs 3.08 on Pass@5). Among RL-based methods, B-Coder beats CodeRL on Pass@1 (2.30 vs 2.20) and Pass@5 (3.80 vs 3.10), and PPOCoder on Pass@1 (2.30 vs 1.74) and Pass@5 (3.80 vs 3.56). Against the concurrent work RLTF, B-Coder wins on Pass@1 (2.30 vs 1.45) and narrowly on Pass@5 (3.80 vs 3.78), but trails on Pass@1000 (18.12 vs 19.92), where RLTF's fine-grained and adaptive reward designs provide an advantage at high sampling budgets. In the filtered setting (Table 2, using example test outcomes), B-Coder achieves 8.04 Pass@1 and 11.30 Pass@5 overall, outperforming CodeRL+CS+filtered (7.83 / 11.61) on Pass@1 while being slightly behind on Pass@5. The paper also demonstrates that B-Coder's recovered reward model generalizes: ranking CodeRL-generated programs with B-Coder's reward model yields consistent Pass@k improvements (e.g., +0.68 on Pass@1 overall at temperature 0.4), and zero-shot transfer to MBPP shows gains of 6.61–7.34 on Pass@1 across temperatures.

## Relation to Prior Work

B-Coder departs from the dominant policy-based RL paradigm in code generation (CodeRL's REINFORCE, PPOCoder's PPO, RLTF's policy gradient) by applying value-based RL—specifically Dueling DQN—to program synthesis. It draws on three distinct lineages: energy-based policies (Haarnoja et al.) for initializing Q-functions from pre-trained LM logits, conservative/offline RL operators (Xie et al., Yu & Zhang) for stable updates in large state-action spaces, and inverse soft Q-learning (Garg et al.) for recovering a reward model from the trained Q-function. The paper positions value-based methods as a natural fit for code generation because rewards are cheap (unit tests) and off-policy data (human programs, historical samples) is abundant, analogous to games like Go and Atari.

## Why It Matters / Open Questions

The paper demonstrates that value-based RL can be stabilized for code generation with minimal reward engineering (only the basic 4-level reward), suggesting algorithm design can be decoupled from reward design—a useful principle for the field. The 'free reward model' recovered from Q_θ provides a practical deployment benefit for ranking candidates without hidden tests. However, limitations are notable: raw generation quality (without ranking) is mixed versus CodeRL, the method introduces additional frozen parameters, and the conservative operator inherently limits how far the policy can improve over the pre-trained checkpoint. The open question of how to effectively scale off-policy program data in a principled way remains, and whether value-based methods can match or exceed policy-based approaches at larger scales is untested.
