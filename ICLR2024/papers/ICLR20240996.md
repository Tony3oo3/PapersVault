## Problem

Current multi-modal agents (e.g., VisProg, HuggingGPT) rely on simplistic model selection—assigning a fixed model per subtask type via external metrics—ignoring how subtask dependencies in multi-step reasoning make the optimal model choice input- and context-dependent. Traditional model selection methods from other domains (meta-learning, collaborative filtering) are restricted to one-step selection and cannot capture the directed dependency structure among subtasks. This paper formalizes model selection on a multi-modal task graph as a new problem and introduces the first dedicated benchmark (MS-GQA) to study it.

## Input / Output

The method takes a multi-modal input (an RGB image paired with a text question from GQA), a directed acyclic computation graph produced by an LLM (GPT-3.5-turbo) that encodes subtask nodes and their dependency edges, and a candidate model zoo (10 localization models and 7 VQA models, yielding 70 combinations per sample). It outputs a single model selection choice per subtask type that maximizes the predicted binary execution success probability. The framework is trained on 8,426 samples with 700,000 execution records (binary success/fail per sample-model combination) collected by running VisProg on GQA.

## Method

M3 represents the multi-step reasoning process as a directed acyclic computation graph with a virtual starting node (the multi-modal input) and subtask nodes connected by dependency edges. A multi-modal encoder (BLIP) extracts the input embedding for the virtual node, while a learned lookup table maps each candidate model to a fixed embedding for subtask nodes; both are projected into a shared feature space. A Graph Attention Network (GAT) then propagates information along the dependency edges to jointly model sample features, model embeddings, and subtask structure, producing a scalar execution-status score per model combination. Training uses a list-wise Categorical Cross-Entropy (CCE) loss over all 70 combinations per sample, which the authors show outperforms instance-wise BCE by explicitly differentiating positive from negative model choices. At test time, the model combination with the highest predicted success score is selected, incurring only ~0.09 s of overhead versus 0.62 s of task execution.

## Results

On the MS-GQA benchmark, M³ achieves 68.70% Successful Execution Rate (SER) on the full test set, outperforming the previous state-of-the-art MetaGL (66.01%) by 2.69 percentage points. Training-based methods (M³, MetaGL, NCF) consistently outperform training-free methods (VisProg, EXMETRIC, GlobalBest), which range from 56.51% to 63.58% SER. M³ also demonstrates robustness across diverse sub-test sets (Query, Choose, Compare, Verify, Logical) and under data-missing scenarios, maintaining superiority even when 80% of training samples are absent.

## Baselines & Comparisons

M³ outperforms all three primary baselines on the full MS-GQA test set: VisProg (59.04% SER, a fixed deterministic model assignment per subtask type) is beaten by 9.66 points, NCF (65.92%, a collaborative-filtering-based selector) by 2.78 points, and MetaGL (66.01%, a meta-learning-based graph model selector) by 2.69 points. VisProg is the weakest baseline overall, excelling only on the Compare sub-test set (82.26%) but performing poorly on Query (44.85%) and Choose (66.94%), highlighting its input-agnostic fragility. NCF and MetaGL, adapted from other domains, show competitive but inconsistent performance across sub-test sets; their extended versions (NCF++, MetaGL++) that add textual computation-graph features actually underperform their originals, confirming that naive text encoding of subtask dependencies is insufficient. M³'s advantage stems from jointly modeling subtask dependencies via a directed acyclic computation graph (GAT backbone), which no baseline replicates. Under data-missing scenarios (up to 80% missing samples), M³ still outperforms the best training-free method (GlobalBest, 63.58%) at 64.67% SER.

## Relation to Prior Work

This paper carves new ground at the intersection of two previously disconnected research threads: multi-modal agent frameworks (VisProg, HuggingGPT, Chameleon) that handle planning and execution but rely on simplistic or static model assignment, and model selection methods from other domains (MetaGL, NCF, LOVM) that perform single-step selection without considering multi-step subtask dependencies. Rather than building on a single prior method, M3 repurposes GNN-based graph learning (GAT) to model the directed acyclic computation graph of subtask dependencies, combined with multi-modal encoders (BLIP) and a model embedding lookup table, and introduces CCE loss in place of the standard BCE for the multi-label formulation. The paper explicitly positions itself as the first to formalize model selection as a distinct phase in multi-modal multi-step reasoning, separate from planning and execution.

## Why It Matters / Open Questions

The paper provides the first formal problem definition and the first dedicated benchmark (MS-GQA, 8,426 samples × 70 model choices) for model selection in multi-modal reasoning, filling a gap that the multi-modal agent community has overlooked. The persistent gap between the oracle selector (100% SER) and M3 (~69%) signals substantial headroom for future work, particularly in leveraging intermediate reasoning results as supervisory signals and extending selection from per-subtask-type to per-subtask-node granularity. Key limitations include evaluation on a single dataset (GQA) with a single agent (VisProg), dependence on complete execution labels for training, and the binary success/failure signal that ignores answer quality. The negligible 0.09s test-time overhead makes the framework practically deployable as a plug-in, but broader validation across agents (HuggingGPT, LLaVA-Plus) and real-world task distributions remains open.
