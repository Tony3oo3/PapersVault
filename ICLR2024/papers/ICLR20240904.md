## Problem

Existing continuous robot evolution methods (REvolveR, HERD) transfer a policy between only a pair of robots, so transferring to N target robots requires N independent runs with no shared computation. This is not scalable when a single source robot (e.g., a dexterous hand) must transfer a policy to many morphologically related target robots (e.g., grippers with different finger counts). The paper asks how to share evolution paths among multiple targets to reduce total training and simulation cost.

## Input / Output

The method takes the physical parameters of one source robot and N target robots (all kinematically matchable to a shared state/action space), along with a pre-trained expert policy on the source robot. It produces a set of N target-robot policies plus a tree-structured evolution path with internal 'meta robot' nodes where paths split. Physical parameters are normalized into a [0,1]^D convex hull, and the evolution tree is recomputed greedily at every training phase using the current intermediate robot position rather than the original source.

## Method

Meta-Evolve first matches the kinematic trees of all robots into a unified D-dimensional physical parameter space, then formulates the evolution path design as finding an L^p Steiner tree connecting the source robot to all N target robots in that space. The internal Steiner points become 'meta robots' where evolution paths split into subtrees. The policy is evolved from the source to the nearest meta robot, then recursively transferred into each subtree, with the Steiner tree recomputed at every training phase to minimize only future cost. The key insight is that morphologically similar target robots share early evolution directions, so path sharing eliminates redundant exploration and fine-tuning. Ablations show L^1 (Manhattan) distance outperforms L^2 (Euclidean) for tree construction, likely because hardware parameters act independently on transition dynamics.

## Results

On the Hand Manipulation Suite (HMS) one-to-three transfer tasks, Meta-Evolve (1-Steiner Tree) reduces total simulation epochs by 2.73× (Door), 3.23× (Hammer), and 3.17× (Relocate) compared to launching three independent HERD runs, while reducing training iterations by 2.35×, 2.95×, and 2.29× respectively. On the one-to-six agile locomotion task, Meta-Evolve achieves 2.20× improvement in total training cost and 2.43× in total simulation cost over six independent HERD runs. DAPG (direct imitation) fails to reach 80% success rate on any HMS target robot within 50K iterations.

## Baselines & Comparisons

The paper compares Meta-Evolve against two external baselines and one internal ablation. DAPG (Rajeswaran et al., 2018), which performs direct one-to-one imitation learning without robot evolution, fails to reach 80% success on any of the three HMS target robots within 50K training iterations, making it non-competitive. HERD (Liu et al., 2022a), the primary baseline, launches N independent one-to-one evolution runs (one per target robot); Meta-Evolve outperforms it by 2.35–2.95× in training iterations and 2.73–3.23× in simulation epochs across the three HMS tasks, and by 2.20×/2.43× on the one-to-six locomotion task. The internal Geom-Median ablation (single meta robot, no tree) achieves 1.95–2.13× training speedup and 2.48–3.13× simulation speedup, confirming that the full tree-structured evolution with multiple meta robots is necessary for optimal performance. Notably, for some target robots (e.g., 2- and 3-finger grippers on Hammer), going through the shared evolution tree is even cheaper than a direct one-to-one HERD transfer to that single target, suggesting cross-target path sharing can improve individual transfer efficiency.

## Relation to Prior Work

Meta-Evolve directly extends the continuous robot evolution framework established by REvolveR (Liu et al., 2022b) and HERD (Liu et al., 2022a), which interpolate physical parameters to create intermediate robots for one-to-one policy transfer. The key conceptual departure is organizing multiple evolution paths into a tree structure with shared 'meta robot' nodes, formulated as a Steiner tree problem in robot parameter space—a borrowing from VLSI physical design. Unlike meta-learning approaches that learn a meta-policy from scratch, Meta-Evolve assumes a given expert policy and evolves the hardware; unlike direct imitation methods (DAPG, state matching), it does not require similar dynamics between source and target robots.

## Why It Matters / Open Questions

The one-to-many formulation addresses a practical scalability bottleneck in robotics: when a well-trained policy must be deployed across multiple robot variants, independent one-to-one transfers are prohibitively expensive. The 2–3× simulation cost reduction is meaningful for compute-constrained settings, and the finding that routing through meta robots can be cheaper than direct one-to-one transfer for some targets suggests path sharing has a genuine inductive benefit beyond mere cost amortization. Open questions include whether the heuristic Steiner tree can be replaced by a learned or optimized tree, whether the approach generalizes to highly dissimilar robot morphologies, and whether the L1 distance assumption (independent parameter effects) holds in more complex physical systems.
