## Problem

Current zero-shot IE systems prompt LLMs with only label names, but different datasets define the same labels differently (e.g., ACE05 annotates pronouns as persons while CoNLL03 does not), and LLMs fail to follow detailed annotation guidelines out of the box even when provided. This paper addresses the gap by fine-tuning an LLM specifically to attend to and comply with annotation guidelines, enabling robust zero-shot generalization to unseen IE schemas.
![Teaser figure](../imgs/ICLR20241838/cropped_page0_idx1.webp)

## Input / Output

The input is a Python code snippet containing three parts: a schema definition (label classes with docstring guidelines and representative candidates as comments), the input text as a Python string variable, and a `result =` prompt. The model generates Python code instantiating the defined classes with extracted spans or arguments; output is parsed by simply executing the generated code. The code-based format is auto-standardized with Black and unifies all five IE tasks (NER, RE, EE, EAE, SF) under a single representation, with class attributes varying in complexity from a single span (NER) to multi-argument event structures (EAE).

## Method

GoLLIE fine-tunes Code-LLaMA (7B/13B/34B) via QLoRA on 12 IE datasets spanning five tasks, using a Python code-based input-output representation inherited from CodeIE and Code4Struct. The core contribution is embedding annotation guidelines directly into the input as class docstrings and representative candidates as code comments, forcing the model to condition its predictions on the provided definitions rather than relying on label-name priors. Five training regularizations prevent dataset memorization: class order shuffling, class dropout (removing random classes from input/output), guideline paraphrasing (via Vicuna 33B), representative candidate sampling (5 of 10 per class), and class name masking (replacing label names with LABEL_1, LABEL_2, etc.). Loss is computed only over output tokens to avoid the guideline tokens dominating the gradient, and the QLoRA bottleneck (~0.5% of parameters) is shown to outperform full fine-tuning on zero-shot tasks by preventing overfitting.

## Results

GoLLIE (7B, Code-LLaMA backbone) achieves an average zero-shot F1 of 55.3 across 17 evaluation datasets, improving over its own baseline (without guidelines) by 13 F1 points (42.3 → 55.3). The 34B variant reaches 57.2 average F1. On the supervised setting, GoLLIE matches the baseline within 0.3 F1 (73.3 vs. 73.0 average), confirming that the guideline-following training does not degrade in-domain performance. The largest zero-shot gains appear on domain-specific datasets: CASIE EE (33.9 → 59.3), FabNER (6.1 → 24.8), and MultiNERD (55.0 → 76.0).

## Baselines & Comparisons

GoLLIE (7B) substantially outperforms Instruct-UIE (Wang et al., 2023a), the prior zero-shot IE SoTA, on all CrossNER domains where both report results: AI (59.1 vs. 49.0), Literature (62.7 vs. 47.2), Music (67.8 vs. 53.2), Politics (57.2 vs. 48.2), Science (55.5 vs. 49.3), and Restaurants (43.4 vs. 21.0), while matching it on Movie (63.0 vs. 63.0). Against PromptNER (Zhang et al., 2023a), which prompts GPT-3.5-turbo with guidelines, GoLLIE wins on every CrossNER domain shown in Figure 1 (e.g., ~55–68 F1 vs. ~20 F1 for GPT-3.5 on Music/Politics). On WikiEvents, GoLLIE surpasses the entailment-based ZS4IE system (Sainz et al., 2022b) by large margins: NER 80.7 vs. 49.1, EE 43.0 vs. 10.4, and EAE 51.9 vs. 35.9. The most informative comparison is GoLLIE vs. its own baseline (same Code-LLaMA 7B backbone, same training data, but without guideline information in the prompt): the 13-point average F1 gap (55.3 vs. 42.3) isolates the contribution of annotation guidelines. On supervised benchmarks (Table 2), GoLLIE is within 0.3 F1 of the baseline on average, confirming no in-domain degradation, though it trails task-specific SoTA on WNUT2017 (53.7 vs. 60.2) and NCBIDisease (86.2 vs. 90.2) where domain-specific techniques help.

## Relation to Prior Work

GoLLIE builds on the Python code-based representation for IE introduced by Code4Struct (Wang et al., 2023b) and CodeIE (Li et al., 2023), but departs from prior instruction-tuning approaches for IE (Instruct-UIE, PromptNER) that either use only label names or prompt LLMs with guidelines without fine-tuning them to follow those guidelines. The key conceptual departure is treating annotation guidelines as a first-class input signal and using targeted regularization (class dropout, name masking, paraphrasing, candidate sampling) to force the model to attend to guideline content rather than memorizing dataset-specific label patterns. The backbone choice of Code-LLaMA with QLoRA follows the parameter-efficient fine-tuning paradigm, but the guideline-following objective is novel relative to generic instruction tuning.

## Why It Matters / Open Questions

Zero-shot IE remains a major practical bottleneck because annotating each new domain and schema from scratch is prohibitively expensive; GoLLIE demonstrates that the annotation guidelines already written for human annotators can be leveraged to yield a +13 F1 improvement over a no-guideline baseline, substantially narrowing the gap to supervised systems. However, the paper identifies clear limitations: ambiguous or catch-all labels (MISC, PLOT) remain difficult, strong pre-training preconceptions (e.g., political parties → ORGANIZATION) persist, and datasets with hundreds of labels exceed current context windows. Open questions include whether expanding training data diversity can overcome label preconceptions, whether the approach generalizes to truly novel task types beyond the five IE tasks studied, and how to handle the guideline-quality variance across datasets.
