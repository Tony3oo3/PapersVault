## Problem

Conventional Code LLM evaluations assess NL-to-PL and PL-to-NL generation in isolation using metrics like Pass@K and BLEU, overlooking whether a model preserves semantics when translating between its own code and its own specifications. This paper identifies self-consistency — the ability to bidirectionally translate between natural language and programming language without semantic drift across repeated cycles — as a critical but unmeasured property of trustworthiness, and shows that even high-accuracy models like GPT-4 fail to maintain it.

## Input / Output

The framework takes a natural language docstring (nl_0) from HumanEvalPlus or MBPP as the starting point, a Code LLM, and the benchmark's predefined test cases. It iteratively generates a chain of alternating programs and specifications (pl_0 → nl_1 → pl_1 → nl_2 → …), using the model's own outputs as inputs for the next step. At each step, the Test Output Match (TOM) score compares the exact runtime outputs (including full error messages) of consecutive programs across all test cases. The final outputs are aggregated into SC_n (self-consistency), SSC_n (strong self-consistency, requiring the initial generation to also be correct), Pass@1 (NL-to-PL accuracy), and SC_1 (PL-to-NL accuracy). Meaningful function names are replaced with a generic 'func' after the initial step to prevent the model from shortcutting via name semantics.

## Method

IdentityChain formalizes self-consistency as the preservation of a semantics-space identity transformation across an alternating chain of NL-to-PL and PL-to-NL generations, then operationalizes it via the TOM score, which compares exact test-case outputs (not just pass/fail) between consecutive programs in the chain. The key relaxation is that instead of directly checking sem(pl_i) = sem(nl_{i+1}) = sem(pl_{i+1}) — for which no existing metric exists — the framework checks the feasible equality sem(pl_i) = sem(pl_{i+1}) using execution-based comparison, arguing that a semantically wrong nl_{i+1} will almost certainly produce a pl_{i+1} with different outputs. Greedy decoding with early stopping (halting when an exact match is detected) makes the evaluation efficient, as most non-self-consistent cases are revealed within the first three steps. The framework simultaneously yields NL-to-PL accuracy (Pass@1 from the bootstrap step), PL-to-NL accuracy (SC_1 as a dynamic alternative to BLEU), and multi-step self-consistency (SC_n, SSC_n), making it a holistic evaluation tool that also serves as a debugging instrument for pinpointing specific model weaknesses.

## Results

Across 11 Code LLMs evaluated on HumanEvalPlus and MBPP Sanitized, all models exhibit declining self-consistency as the IdentityChain length increases: SSC5 scores drop up to 78.0% relative to Pass@1, and SC5 scores drop up to 43.8% relative to SC1. GPT-4-Turbo achieves the highest SSC5 (59.5 on HumanEvalPlus, 61.5 on MBPP) and GPT-4 the highest SC5 (76.1 on HumanEvalPlus, 82.5 on MBPP), yet even these top models lose 15–27% of their initial accuracy over 5 chain steps. Notably, self-consistency is decoupled from conventional accuracy: StarChat-Beta (15B) outperforms CodeLlama-Inst-7B in Pass@1 but underperforms in SC5 on both benchmarks, and GPT-4's 51.2% higher SC5 over GPT-3.5 far exceeds its mere 4.2% Pass@1 advantage.

## Baselines & Comparisons

The paper's primary comparison is the proposed TOM score against six existing metrics for evaluating semantic identity between a program and its natural-language specification. In Table 2, TOM achieves Pearson r = 0.461, Spearman ρ = 0.454, and Kendall-τ = 0.410 correlation with human-judged semantic identity in the PL space, outperforming Exact Match (r = 0.285), CodeBLEU (r = 0.179), and Pass/Fail Match (r = 0.294). In the NL space, TOM (r = 0.500, ρ = 0.482, τ = 0.445) surpasses BLEU (r = 0.285), ROUGE-L (r = 0.254), chrF (r = 0.271), and BERTScore (r = 0.381) on the 117 problems where ground-truth references exist, and additionally works on the remaining 46 problems where no reference is available. Beyond metric comparisons, the paper demonstrates that self-consistency (SC5) is a distinct axis from conventional accuracy (Pass@1): StarChat-Beta-15B beats CodeLlama-Inst-7B in Pass@1 (25.2 vs. 16.1 on HE+) but loses in SC5 (11.0 vs. 14.1), and GPT-4's SC5 advantage over GPT-3.5 (76.1 vs. 50.3, +51.2%) dwarfs its Pass@1 advantage (74.8 vs. 71.8, +4.2%), confirming that accuracy alone underestimates capability gaps between models.

## Relation to Prior Work

This paper carves new ground by formalizing 'self-consistency' as a distinct evaluation property for Code LLMs, departing from the standard practice of assessing NL-to-PL (Pass@K) and PL-to-NL (BLEU, CodeBLEU) in isolation. Conceptually, it extends prior LLM self-consistency probes (Jiang et al. 2023, Ohmer et al. 2023) from closed-domain QA to open-ended code generation and summarization, where multiple valid outputs exist. The IdentityChain framework repurposes existing benchmarks (HumanEval, MBPP) with a new iterative protocol, and the TOM score introduces an execution-based dynamic metric that supersedes static similarity metrics for both self-consistency and PL-to-NL evaluation.

## Why It Matters / Open Questions

The finding that self-consistency is a genuinely separate axis from accuracy—where even GPT-4 shows up to 26.5% drop in strong self-consistency over 5 steps—challenges the assumption that high Pass@K implies semantic understanding, and provides model developers with a concrete debugging tool to expose weaknesses in data-type awareness, implicit semantics, and execution prediction. Open questions include how to improve self-consistency through fine-tuning, whether the framework generalizes beyond Python to multi-language settings, and whether the identified weaknesses correlate with specific training data characteristics. The TOM score's outperformance over all existing PL-to-NL metrics (BLEU, ROUGE-L, chrF, BERTScore) suggests a broader shift toward execution-based evaluation for code understanding tasks.
