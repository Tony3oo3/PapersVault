## Problem

High-level program optimizations such as algorithmic and API changes remain largely manual because understanding code semantics is difficult, and prior ML-based approaches suffer from narrow scope, closed datasets, and unreliable performance measurement on commodity hardware. This paper asks whether pre-trained code LLMs can be adapted to perform such optimizations, and identifies two blocking challenges: the absence of a large, open dataset of performance-improving code edits with trustworthy timing annotations, and the significant variability of real-hardware benchmarks that can produce phantom speedups (e.g., identical programs showing up to 1.91× apparent speedup).

## Input / Output

The method takes a C++ source program (median ~428 tokens in the test set) solving a competitive programming problem, optionally accompanied by the problem's natural-language description, and produces a functionally equivalent but faster C++ program. Correctness is verified against a median of 104 unit test cases per test-set problem (sourced from CodeNet and AlphaCode), and performance is measured deterministically via the gem5 full-system simulator (Intel Skylake Verbatim configuration) after compiling with GCC 9.3.0, C++17, and -O3. Speedup is reported as old_time/new_time, with a 10% minimum improvement threshold for a program to count as 'optimized.'

## Method

The paper introduces the PIE dataset (77,967 train / 978 test C++ slow→fast pairs from 1,474/41 CodeNet problems) annotated with deterministic gem5 execution times from over 42.8 million simulations, then evaluates a suite of LLM adaptation strategies. On the prompting side, dynamic retrieval-based few-shot prompting uses CodeBertScore embeddings and FAISS to select the K most similar training pairs as in-context examples, substantially outperforming fixed few-shot and chain-of-thought baselines. On the fine-tuning side, three strategies are explored: (1) training on a curated high-quality subset (4,085 pairs, ≤4 per problem) to mitigate dataset imbalance, (2) performance-conditioned generation, where each fast program is tagged with a binned score (1–10) reflecting its proximity to the best-known solution for that problem, and the model is prompted with '10/10' at inference to elicit peak-performance outputs, and (3) synthetic data augmentation via self-play, where GPT-3.5 generates novel competitive programming problems and a PIE-fine-tuned model produces optimized versions, yielding 1,485 additional pairs. The best configuration—GPT-3.5 fine-tuned on the high-quality set plus self-play data—achieves a 6.86× mean speedup over 8 generations (BEST@8, temperature 0.7), surpassing the 3.66× average human speedup, and reaches a 9.64× upper-bound speedup with 40 generations, exceeding the best human submissions (9.56×).

## Results

The best model, GPT-3.5 fine-tuned with synthetic self-play data, achieves a 6.86× average speedup (BEST@8) with 87.63% of programs optimized by ≥10% and 95.09% correctness, substantially exceeding the human reference of 3.66×. With 40 generations, the model's fastest output reaches 9.64× speedup, marginally surpassing the best human submissions (9.56×). Among open models, CodeLlama 13B with performance-conditioned generation achieves 5.65× speedup and 66.56% %Opt at BEST@8. Baseline prompting (CoT with GPT-3.5) yields only 1.60× speedup, far below the human reference.

## Baselines & Comparisons

The paper's best model (GPT-3.5 + self-play fine-tuning) achieves 6.86× speedup, nearly doubling the human average of 3.66× and exceeding GPT-4 with retrieval (3.93×) by 2.93×. Among prompting strategies, dynamic retrieval-based few-shot prompting (GPT-4: 3.93×) substantially outperforms chain-of-thought (GPT-3.5: 1.60×) and instruction-only prompting (GPT-3.5: 1.54×), confirming that task-specific examples from PIE are critical. Fine-tuning consistently outperforms prompting for the same model size: CodeLlama 13B jumps from 1.20× (CoT) to 5.65× (performance-conditioned fine-tuning). Performance-conditioned generation improves CodeLlama 13B from 3.43× (standard HQ fine-tuning) to 5.65×, while self-play augmentation further lifts GPT-3.5 from 6.74× to 6.86×. At the upper bound (40 generations), the model's fastest output (9.64×) marginally surpasses the best human submissions (9.56×), setting a new ceiling for the dataset.

## Relation to Prior Work

This paper sits at the intersection of program superoptimization (Shypula et al. 2021, Shi et al. 2019, DeepPERF) and LLM-based code generation (AlphaCode, CodeLlama), but departs from both in key ways. Prior superoptimization work targeted narrow domains (assembly, Halide IR) or specific languages (C#), while LLM code-generation work focused on correctness rather than performance. The paper's conceptual contribution is repurposing existing LLM adaptation techniques—retrieval-augmented prompting, self-play data augmentation, and performance-conditioned generation—from general code synthesis into the specific setting of performance-improving edits, grounded by a deterministic gem5-based measurement environment that prior work lacked.

## Why It Matters / Open Questions

The gem5-based benchmarking methodology addresses a fundamental reproducibility problem in performance research: the paper demonstrates that even benchmarking identical programs on real hardware yields up to 1.91× phantom 'speedup' in the top 5%, undermining confidence in prior optimization results. The PIE dataset (77K pairs) is the first large-scale, reproducibly-annotated resource for training and evaluating code optimization models. However, the scope is limited to competitive-programming C++ rather than real-world software, ~5% of generations remain incorrect, and some speedups stem from array-size reductions rather than genuine algorithmic improvements—open questions include whether these techniques transfer to production codebases and whether the correctness gap can be closed via program-repair integration.
