## Problem

While LLMs excel at solving individual programming tasks, they do not consolidate knowledge into reusable, interpretable libraries the way human software engineers do through refactoring. DreamCoder can learn symbolic libraries via iterative wake-sleep, but requires over two CPU-months per domain and produces anonymous lambda abstractions that are opaque to both humans and LLMs. The paper asks how to combine LLMs' strong inductive priors with efficient symbolic compression to learn rich, interpretable libraries in a fraction of the time.

## Input / Output

The system takes a collection of inductive program synthesis tasks, each specified as input-output pairs (e.g., string transformations, CLEVR scene graphs with questions, or turtle-graphics drawing specifications) paired with a natural language description, along with a small base DSL of domain primitives. It produces a hierarchical library of named λ-abstractions with auto-generated docstrings, plus a set of program solutions rewritten in terms of the learned library. The library is re-derived from scratch at every iteration ('deep refactoring'), and the documentation is generated sequentially so that later abstractions can reference earlier named ones consistently.

## Method

LILO is a neurosymbolic framework with three modules operating in a search-compress-document loop. First, a dual-system search module uses an LLM (Codex) for fast approximate synthesis in string space, followed by enumerative search guided by a task-conditioned PCFG for slow, domain-specific discovery. Second, the STITCH compression algorithm (branch-and-bound over lambda calculus) identifies optimal λ-abstractions that minimize total description length across the solution corpus, running in seconds on a single CPU versus DreamCoder's much slower version-space approach. Third, the AutoDoc module sequentially prompts an instruction-tuned LLM (GPT-3.5-turbo) with usage examples from solved tasks to generate human-readable names and docstrings for each anonymous abstraction. The key insight is that without AutoDoc, anonymous lambda identifiers act as code obfuscation that measurably degrades LLM synthesis performance; documentation makes the library legible to both humans and the LLM synthesizer, enabling effective contextual deployment of learned abstractions.

## Results

In online synthesis, LILO achieves mean test solve rates of 77.07% (REGEX), 96.76% (CLEVR), and 48.95% (LOGO), outperforming DreamCoder (43.93%, 94.50%, 28.53%) and the LLM Solver baseline (76.13%, 88.67%, 32.13%). In offline synthesis (no language guidance, fixed time budget), LILO's learned library achieves 64.27% (REGEX), 92.56% (CLEVR), and 41.14% (LOGO), compared to DreamCoder's library at 41.60%, 91.59%, and 30.63% respectively. The largest gains over DreamCoder appear on REGEX (+33.14 pp) and LOGO (+20.42 pp), where LLM-guided search discovers domain-specific abstractions (e.g., vowel regex) that are intractable for enumerative search alone.

## Baselines & Comparisons

LILO is compared against two baselines: a language-guided DreamCoder variant (Wong et al., 2021) and an LLM Solver that performs no library learning. Against DreamCoder, LILO wins on all three domains in online synthesis: +33.14 pp on REGEX (77.07 vs. 43.93), +2.26 pp on CLEVR (96.76 vs. 94.50), and +20.42 pp on LOGO (48.95 vs. 28.53). Against the LLM Solver, LILO also wins on all three: +0.94 pp on REGEX, +8.09 pp on CLEVR, and +16.82 pp on LOGO, with the largest gap on LOGO where enumerative search discovers domain-specific structures (e.g., snowflake, staircase patterns) that are hard to infer from language alone. In offline synthesis (no language guidance), LILO's final library outperforms DreamCoder's library by +22.67 pp (REGEX), +0.97 pp (CLEVR), and +10.51 pp (LOGO), confirming that the learned abstractions generalize as off-the-shelf tools. The ablation LILO(−Search/AutoDoc) shows that naively providing anonymous Stitch abstractions to the LLM actually degrades performance (e.g., 53.20% vs. 76.13% on REGEX), highlighting the critical role of AutoDoc in making learned abstractions usable.

## Relation to Prior Work

LILO extends the DreamCoder (Ellis et al., 2021) Wake-Sleep library learning loop by replacing its computationally expensive enumerative search with a dual-system approach that combines LLM-guided synthesis with a recognition-network-guided enumerative search, and by swapping in STITCH (Bowers et al., 2023) for the original compression algorithm. It departs from LAPS (Wong et al., 2021), the closest prior language-guided variant, by leveraging pre-trained LLMs' existing priors over code and language rather than learning a domain-specific semantic parser from scratch. The key architectural departure is the AutoDoc module, which addresses a gap in prior library learning systems: learned abstractions were anonymous lambdas that were neither human-interpretable nor usable by LLM synthesizers.

## Why It Matters / Open Questions

The finding that anonymous lambda abstractions actively degrade LLM synthesis performance (by up to 30 points on REGEX) and that simple auto-documentation recovers and exceeds baseline performance is a practically important insight for anyone integrating symbolic program libraries with LLMs. The offline synthesis results demonstrate that LILO's learned libraries are genuinely reusable artifacts that outperform DreamCoder's libraries even without language guidance, suggesting a path toward interpretable, transferable program knowledge. Open questions include whether AutoDoc's sequential naming can be made more robust (it occasionally propagates semantic errors), whether the approach scales to modern imperative languages like Python, and whether the LLM-only baseline's ability to bootstrap via prompt accumulation will eventually subsume the need for explicit compression.
