## Problem

Despite LLMs' strong performance on natural language reasoning, how to effectively encode graph-structured data as text for LLM consumption remains largely unexplored. Prior work (Wang et al., 2023) benchmarked LLMs on a narrow set of graph tasks using only Erdős-Rényi graphs and a fixed encoding, leaving open how encoding choices, task types, and graph structure jointly affect LLM graph reasoning. This paper performs the first comprehensive study of these three interacting factors.

## Input / Output

The system takes a graph G=(V,E) and a question Q, converts the graph into a text token sequence via a graph encoding function g(G) (e.g., 'Node 0 is connected to nodes 1, 2' or 'James and Robert are friends'), optionally rephrases the question via q(Q) (e.g., 'What is the degree of node 14?' vs. 'How many friends does Christopher have?'), and feeds the combined prompt to a black-box LLM. The LLM must produce answers in the same discrete token space: binary yes/no (edge existence, cycle check), integers (node degree, node count, edge count), or node lists (connected/disconnected nodes). All experiments use graphs with 5–20 nodes generated from seven different graph generators.

## Method

The paper decomposes LLM graph reasoning into two optimizable components — a graph encoding function g(G) and a question rephrasing function q(Q) — and systematically varies both along with graph structure and model capacity in a black-box setting (no weight access). Nine graph encoding functions are constructed by combining node encodings (integers, English names, TV character names, politician names, alphabet letters) with edge encodings (parenthesis, incident, friendship, co-authorship, social network, arrows). Five prompting heuristics (zero-shot, zero-CoT, few-shot, CoT, CoT-Bag) are evaluated across six basic graph tasks and five complex tasks. The key finding is that encoding choice yields 4.8%–61.8% performance swings: incident encoding (integer nodes + 'Node X is connected to nodes Y, Z') dominates for most tasks because it places neighborhood information in close textual proximity, while named-entity encodings (e.g., politicians) outperform incident encoding under zero-shot prompting due to stronger pre-trained token representations. Additionally, graph structure itself (complete vs. path vs. star) dramatically shifts accuracy because LLMs carry strong priors about edge density and cycle existence, and dense graphs introduce distracting edge statements that degrade counting and degree tasks.

## Results

On the GraphQA benchmark with PaLM 62B, LLMs perform poorly on basic graph tasks, often below the majority baseline (e.g., 44.5% on edge existence vs. 53.96% majority; 76.0% on cycle check vs. 81.96% majority). The best configuration—COT-BAG prompting with Incident encoding—achieves 75.2% on node degree and 41.0% on connected nodes, while the worst encoders drop to 14.6% and 9.2% respectively on those tasks. The choice of graph encoding function alone can boost performance by 4.8% to 61.8% depending on the task. Model scaling from PaLM 2 XXS to L consistently improves graph reasoning, though even the largest models fail to beat the majority baseline on edge existence.

## Baselines & Comparisons

This is an empirical study without external method baselines; comparisons are internal across encoding functions, prompting strategies, and graph structures. Incident encoding (integer nodes + 'connected to' phrasing) dominates over all other encodings (Adjacency, Friendship, Co-authorship, SP, GOT, Social Network, Politician, Expert) on node degree and connected nodes for COT and COT-BAG prompting (e.g., 75.0% vs. 71.2% for Adjacency on node degree; 41.0% vs. 20.6% for Adjacency on connected nodes). However, for ZERO-SHOT prompting, Politician encoding (using American politician names) outperforms Incident on cycle check (81.0% vs. 68.8%), suggesting that tokens with stronger pre-trained representations help when no chain-of-thought is available. COT and COT-BAG prompting substantially outperform ZERO-SHOT and ZERO-COT on multi-step tasks (node degree: 29.2% vs. 14.0%), while ZERO-SHOT is competitive or better on simple tasks like edge existence. Graph structure matters significantly: cycle check accuracy swings from 91.7% on complete graphs to 5.9% on path graphs under ZERO-SHOT, revealing strong LLM priors about graph properties. On GPT-3.5-turbo, Incident encoding achieves 66.4% on node degree versus 5.4% for Adjacency, confirming the encoding advantage generalizes across model families.

## Relation to Prior Work

This paper extends Wang et al. (2023), which introduced the first benchmark for evaluating LLMs on graph problems in natural language, by systematically varying three dimensions that prior work held fixed: the graph encoding function (9 distinct node/edge encoding combinations), the graph structure (7 generator families beyond Erdős-Rényi), and the question phrasing (graph vs. application framing). It also draws on the broader prompt engineering literature (zero-shot, few-shot, CoT, zero-CoT) and the knowledge-graph-augmented LLM line of work, but deliberately restricts itself to black-box text-in/text-out settings, excluding fine-tuning, LoRA, or architecture modifications. The GraphQA benchmark generalizes Wang et al.'s task set by adding disconnected nodes, reachability, shortest path, maximum flow, triangle counting, and node classification.

## Why It Matters / Open Questions

This is the first comprehensive empirical study providing practitioners with concrete guidance on how to encode graphs as text for LLM consumption, showing that encoding choice alone can swing accuracy by up to 61.8 percentage points. The finding that LLMs perform below majority baselines on basic tasks (edge existence, cycle check) and essentially fail on reasoning about edge absence (disconnected nodes at ~0%) highlights a fundamental limitation that motivates future work on graph-aware architectures or retrieval-augmented approaches. Open questions include whether these findings hold for larger graphs (beyond 20 nodes), whether fine-tuning or graph-specific tokenizers can close the gap, and how the results transfer to real-world heterogeneous graphs with rich node/edge attributes.
