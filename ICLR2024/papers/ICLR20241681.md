## Problem

Existing tool-use benchmarks for LLMs (e.g., APIBank, ToolLLM, GPT4Tools) focus on parameter configuration and result handling (stages ③④ in the ReAct pipeline), but neglect the upstream decisions of whether to invoke a tool at all (stage ①) and which tool to select from a candidate set (stage ②). These two capabilities are critical for LLMs operating as autonomous agents (AutoGPT, MetaGPT, BabyAGI), yet no prior benchmark systematically evaluates them. Additionally, previous datasets suffered from low query diversity and overlapping tool functionality, making ground-truth labeling ambiguous.

## Input / Output

For tool usage awareness, the LLM receives a single user query and must output a binary 'yes' or 'no' indicating whether an external tool is needed, with a brief justification. For tool selection, the LLM receives a user query plus a candidate tool list (names and descriptions) and must return the correct tool name(s) or 'None'. The candidate list construction is task-specific: for similar-choice selection it contains the ground-truth tool plus its top-(n-1) most embedding-similar tools; for reliability testing it deliberately excludes the ground-truth tool and its k most similar tools; for multi-tool selection it includes the ground-truth tool set plus randomly sampled distractors. Evaluation uses accuracy/precision/recall/F1 for the awareness task and a Correct Selection Rate (CSR) for selection tasks.

## Method

METATOOL introduces the TOOLE dataset (21,127 queries over 390 OpenAI plugins) generated via four prompting strategies—direct diverse, emotional, keyword, and details generation—to capture realistic query variation. A key technical step is resolving overlapping tool functionality through hierarchical clustering of tool-description embeddings (text-embedding-ada-002), followed by manual merging of similar tools and decomposition of multi-purpose tools, verified via silhouette coefficient and t-SNE visualization. The benchmark defines four tool-selection subtasks that probe distinct capabilities: semantic discrimination among similar tools, adaptability across domain-specific scenarios (popularity-ranked and occupation-based tool lists), resistance to hallucination/sycophancy when the correct tool is absent, and multi-tool inference (parallel and causal tool combinations). Eight LLMs are evaluated under zero-shot and five-shot prompting, with answer matching handled by rule-based extraction plus manual verification for ambiguous outputs.

## Results

On tool usage awareness (Table 2), ChatGPT achieves the highest F1 score of 77.81% (zero-shot) and 81.87% (five-shot), while Llama2-13b drops to a mere 11.53% F1 in zero-shot. On tool selection with similar choices (Table 3), Vicuna-7b leads at 73.46% CSR (zero-shot), but the gap between best and worst models exceeds 20%. On the reliability subtask, ChatGPT dramatically outperforms all others at 50.35% (zero-shot) and 78.49% (five-shot), while every other LLM remains below 16% even with five-shot prompting. In multi-tool selection (Table 4), ChatGPT achieves 88.28% (2/2 CSR) and Vicuna-33b reaches 91.15% under the one-choice prompt, while ChatGLM2 lags at 20.20% and 23.34% respectively.

## Baselines & Comparisons

The benchmark evaluates eight LLMs: ChatGPT, ChatGLM2, Llama2-7b/13b, Vicuna-7b/13b/33b, and Koala-13b. ChatGPT is the clear winner on the reliability subtask, achieving 50.35% CSR (zero-shot) versus a maximum of 6.63% for all other models, and 78.49% with five-shot versus 15.68% for the next-best ChatGLM2. On similar-choice tool selection, Vicuna-7b leads at zero-shot (73.46%) but paradoxically drops to 63.67% under five-shot (−9.79%), while ChatGPT is most stable (69.05% → 72.94%). On tool usage awareness, ChatGPT again leads (F1=77.81 zero-shot), with Llama2-13b performing worst (F1=11.53). In multi-tool selection, ChatGPT (88.28% 2/2 CSR) and Vicuna-33b (91.15% one-choice CSR) dominate, while ChatGLM2 trails at 20.20% and 23.34% respectively. Overall, no single LLM excels across all four subtasks, and the gap between ChatGPT and open-source models is most pronounced on reliability and awareness tasks.

## Relation to Prior Work

This paper carves out a specific gap in the LLM tool-use benchmarking landscape: prior benchmarks (APIBank, GPT4Tool, APIBench, ToolLLM, ToolBench, ToolQA) primarily evaluate parameter configuration (stage ③) and result handling (stage ④) in the ReAct-style tool pipeline, while METATOOL targets the upstream decision stages of tool-usage awareness (①) and tool selection (②). The dataset generation draws on prompting strategies from ToolLLM and GPT4Tool but extends them with emotional, keyword, and detail-augmented generation to increase query diversity, and introduces a hierarchical-clustering-based tool merging/decomposition pipeline to resolve functional overlap. Conceptually, the benchmark repurposes embedding-based retrieval (text-embedding-ada-002) and silhouette-coefficient analysis from the clustering literature as data-curation tools rather than as the evaluation mechanism itself.

## Why It Matters / Open Questions

The benchmark exposes a critical reliability gap: when the correct tool is absent from the candidate list, most LLMs hallucinate non-existent tools or select irrelevant ones (average CSR ~9% vs. 96% for humans), which is a fundamental obstacle for deploying LLMs as autonomous agents in AutoGPT/MetaGPT-style systems. The finding that tool-description quality and the choice of rewrite model interact with the downstream LLM's training corpus (e.g., GPT-4-rewritten descriptions help Vicuna but hurt Llama2) provides actionable guidance for tool developers. Open questions include whether the reliability gap persists with larger or more recent models, whether fine-tuning or RLHF can close the awareness gap, and whether the benchmark generalizes beyond the 390 OpenAI-plugin tools to broader API ecosystems.
