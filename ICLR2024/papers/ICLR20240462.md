## Problem

Existing federated recommendation systems share a single dense item embedding across all clients while keeping user embeddings local, which fails to capture how different users perceive the same item differently and incurs high communication costs. PFedRec introduces personalized item embeddings but discards the shared collaborative-filtering signal entirely. The paper addresses both gaps by learning a sparse global item view and a complementary local item view simultaneously.

## Input / Output

Each client holds one user's binary rating vector (implicit feedback: any positive rating is binarized to 1) over a shared item catalog of m items. The server and clients exchange only the sparse global item embedding C ∈ R^{m×k} per round; user embeddings u_i and local item matrices D^(i) never leave the device. The model outputs predicted ratings r̂_ij = σ(u_i^T(D^(i)+C)_j) for all unrated items, from which top-K recommendations (K=10) are derived and evaluated via HR@10 and NDCG@10.

## Method

FedRAP decomposes each user's item representation into an additive pair: a globally shared sparse matrix C (aggregated server-side via FedAvg) and a user-specific local matrix D^(i), so the effective item embedding is (D^(i)+C)_j. Two regularizers shape the learning: an L1 norm on C enforces sparsity to cut communication overhead, and a Frobenius-norm penalty ‖D^(i)−C‖_F² forces the two views to be complementary rather than redundant. A tanh-based curriculum gradually ramps both regularization weights from zero over the first ~30 iterations, transitioning training from full personalization (where C and D^(i) can overlap) to additive personalization once embeddings have captured sufficient signal. Optimization proceeds via alternating gradient descent on u_i, C, and D^(i) per client, with soft-thresholding applied to C to maintain sparsity; differential privacy is enforced by clipping the gradient w.r.t. C and adding calibrated Gaussian noise before server aggregation.

## Results

FedRAP achieves the best federated performance on all six datasets for both HR@10 and NDCG@10. On ML-100K, FedRAP reaches 97.09% HR@10 and 87.81% NDCG@10, substantially outperforming the strongest federated baseline PFedRec (70.03% HR@10, 41.38% NDCG@10). FedRAP also surpasses the centralized NCF baseline on most datasets (e.g., 97.09% vs. 65.94% HR@10 on ML-100K) and approaches its centralized upper bound CentRAP (99.30% HR@10). On the sparser datasets (Video, LastFM, QB-article), FedRAP still leads all federated methods by 3–10 percentage points in HR@10.

## Baselines & Comparisons

FedRAP outperforms all four baselines on both HR@10 and NDCG@10 across all six datasets. Against PFedRec (the closest federated competitor), FedRAP gains the largest margins on ML-100K (+27.06 pp HR@10, +46.43 pp NDCG@10) and ML-1M (+24.65 pp HR@10, +31.68 pp NDCG@10), attributed to FedRAP's additive item personalization retaining shared item knowledge that PFedRec discards. Against FedMF, FedRAP leads by 1.93–36.55 pp in HR@10 depending on dataset, with the gap widening on sparser data. Against FedNCF, FedRAP consistently wins by 9.89–36.55 pp HR@10, with the largest advantage on TaFeng (99.43 vs. 87.54). Against centralized NCF, FedRAP surpasses it on five of six datasets in HR@10 (e.g., 97.09 vs. 65.94 on ML-100K), demonstrating that the federated additive-personalization design can exceed a centralized neural collaborative filtering model without accessing raw user data.

## Relation to Prior Work

FedRAP extends the federated recommendation systems (FRSs) literature, which has largely followed a partial-model design where item embeddings are shared globally and user embeddings remain local (FedMF, FedNCF, PFedRec). It departs from PFedRec, which personalizes item embeddings but discards shared item knowledge, by introducing an additive decomposition of item embeddings into a sparse global component C and a user-specific local component D^(i). The curriculum-based regularization schedule and the L1 sparsity constraint on C are practical additions not present in prior FRS work, and the differential privacy analysis builds on standard (ε,δ)-DP gradient clipping and Gaussian noise mechanisms.

## Why It Matters / Open Questions

The additive personalization of item embeddings addresses a genuine gap in federated recommendation: users perceive the same item differently, yet prior methods either share a single item representation or fully personalize it without knowledge transfer. The sparsity constraint on C provides a concrete communication-efficiency benefit that is practically important for deployment. A key limitation acknowledged by the authors is that each client must store the full item embedding matrix, which becomes prohibitive for large item catalogs; the cold-start problem for new items under this design remains open. The method's applicability beyond recommendation to other federated scenarios is noted as future work.
