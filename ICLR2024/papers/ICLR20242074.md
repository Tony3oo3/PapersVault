## Problem

Despite widespread adoption of LLMs as autonomous agents, no systematic benchmark existed to evaluate their reasoning and decision-making abilities across diverse interactive environments. Prior agent evaluations were confined to single environments (text games, embodied simulators) with closed action spaces or multi-modal requirements that did not reflect practical text-only LLM deployment. This gap made it impossible to quantitatively compare LLMs' agent capabilities or identify specific failure modes across real-world task categories.
![Teaser figure](../imgs/ICLR20242074/cropped_page1_idx2.webp)

## Input / Output

Each environment feeds the LLM a natural language task instruction followed by multi-round environment observations (bash output, SQL results, game state, webpage HTML, KG query results). The LLM must respond in a strict 'Think: ... Act: ...' format where the action is a single executable command (bash, SQL, game move, web click/type, KG tool call) or a final answer. Conversation history is truncated to fit within 3500 tokens, with an omission notice prepended. Outputs are scored per-environment using task-specific metrics (success rate, F1, reward, game progress, step success rate), then aggregated into a single overall score by normalizing each task's mean to 1 across all 29 evaluated models before averaging.

## Method

AgentBench comprises 8 interactive environments spanning three grounding types—code (Operating System in Docker, Database via MySQL, Knowledge Graph over Freebase), game (Digital Card Game 'Aquawar', Lateral Thinking Puzzles, House-Holding via ALFWorld), and web (Web Shopping, Web Browsing via Mind2Web)—with five environments created for the first time. Evaluation uses a unified ReAct-style prompting protocol (Chain-of-Thought reasoning plus action in a single round) with greedy decoding, requiring no fine-tuning or multi-trial strategies. The evaluation toolkit employs a decoupled Server-Client architecture where task environments run in isolated Docker containers, agent servers expose HTTP APIs, and a max-flow algorithm (Edmonds-Karp) optimally assigns agent-task pairs to workers for parallel evaluation. The overall score is computed by first normalizing each task's average score to 1 across all models, then taking the weighted mean, preventing high-scoring tasks from dominating the aggregate. This design enables fair comparison across 29 API-based and open-source LLMs (up to 70B) and reveals that top commercial models (GPT-4, Claude-3) substantially outperform OSS competitors, with Task Limit Exceeded (weak long-term reasoning) and Invalid Format/Action (poor instruction following) as the dominant failure modes.

## Results

GPT-4 achieves the highest overall AgentBench score (OA) of 4.01, performing best on 6 out of 8 environments, including a 78% success rate on House Holding and 74.5% reward on Digital Card Game. A stark performance gap exists between API-based commercial LLMs (average OA 2.15) and open-source LLMs ≤70B (average OA 0.51); the strongest OSS model, CodeLlama-34b, reaches only 0.96 OA. The predominant failure mode across all models is Task Limit Exceeded (TLE), indicating weak long-term reasoning and decision-making, with TLE accounting for 67.9% of failures on Knowledge Graph and 82.5% on Lateral Thinking Puzzles.

## Baselines & Comparisons

GPT-4 dominates 6 of 8 environments, achieving 78.0% on House Holding, 74.5% on Digital Card Game, and 58.8% F1 on Knowledge Graph, while Claude-3 (opus) leads on Database (51.7%) and GLM-4 on Web Browsing (27.0%). All API-based models exceed an OA of 1.00, whereas the best OSS model (CodeLlama-34b, OA 0.96) still trails GPT-3.5-turbo (OA 2.32) by more than 2×. Among OSS models, Vicuna-13b (OA 0.93) outperforms LLaMA-2-13b (OA 0.77) despite sharing the same base, attributed to higher-quality ShareGPT alignment data; it even approaches the 3×-larger CodeLlama-34b. Code training shows ambivalent effects: CodeLlama-34b excels on Web Shopping (52.1%) but underperforms LLaMA-2-13b on Digital Card Game (8.4% vs. 26.4%) and Operating System (2.8% vs. 4.2%). Surprisingly, LLaMA-2-70b (OA 0.78) performs nearly identically to LLaMA-2-13b (OA 0.77), suggesting insufficient pre-training tokens or alignment for the 70B variant.

## Relation to Prior Work

This paper builds on the ReAct paradigm (Yao et al., 2023b) and Chain-of-Thought prompting (Wei et al., 2022b) as the evaluation strategy, adapting their Thought-Action format for multi-round agent interaction. It departs from prior agent evaluation benchmarks—text-based games (TextWorld, Jericho) with closed action spaces, and multi-modal embodied simulators (ALFWorld, MineDojo)—by creating a unified, text-only, multi-environment benchmark specifically designed for prompted LLMs rather than fine-tuned or RL-trained agents. Five of the eight environments (OS, DB, KG, DCG, LTP) are newly constructed, while three (ALFWorld, WebShop, Mind2Web) are adapted from existing datasets to support zero-shot prompting evaluation.

## Why It Matters / Open Questions

AgentBench establishes the first systematic, reproducible benchmark for LLM-as-Agent evaluation, revealing that even GPT-4 (OA 4.01) falls far short of practical usability and that OSS models ≤70B lag dramatically (avg 0.51 vs 2.15 for API models). The identification of Task Limit Exceeded as the predominant failure mode (up to 82.5% in LTP) points to fundamental limitations in long-term reasoning and planning that current alignment training does not address. Open questions include whether the API-OSS gap will narrow with scaling, whether code training's ambivalent effects can be resolved through more balanced curricula, and whether the benchmark's CoT-only evaluation underestimates what more sophisticated reasoning strategies (self-consistency, tree-of-thoughts) could achieve.
