## Problem

Prior model-merging methods (Git Re-Basin, REPAIR) can only combine models trained on the same task with different initializations, relying on permutation to align features into a shared loss basin. When models are trained on disjoint tasks, their features encode task-specific information that permutation cannot reconcile, causing merged models to perform worse than either original. This paper tackles the much harder problem of merging differently initialized models trained on completely separate tasks into one multi-task model without any additional training.

## Input / Output

The method takes two or more pre-trained models of identical architecture (e.g., ResNet-20, ResNet-50, VGG11) trained on different tasks or datasets, along with a small set of unlabeled images (as few as ~100) used solely to compute neuron activation correlations for feature matching. The output is a single merged model with the same FLOPs as one constituent model (full zip) or a multi-head model with slightly increased FLOPs (partial zip), capable of performing all constituent tasks simultaneously. No labels, gradients, or training steps are required at any point.

## Method

ZipIt! generalizes model merging from a 1-1 permutation between two models to a flexible 'zip' operation that matches any n_i pairs of correlated features across the concatenated feature space of both models, allowing merges within a single model as well as across models. For each layer, it computes pairwise activation correlations on unlabeled images, greedily selects the most correlated feature pairs (with a budget parameter β controlling the fraction of within-model merges), and constructs a merge matrix M_i and its pseudoinverse unmerge matrix U_i. These matrices are fused into the layer's weight matrix via a generalized interpolation (Eq. 8), while U_i is propagated forward to align the next layer's input space. A second key innovation is partial zipping: the merge can stop at a specified layer, after which the unmerge matrix splits the shared features back into separate task-specific heads, creating a multi-head architecture that preserves task-specific information in the later layers. Theoretically, the paper proves a tighter linear-mode-connectivity bound (Theorem 1) showing that exploiting within-model redundancy strictly reduces the merged model's loss increase compared to permutation-only merging, and yields zero loss increase when redundancy is sufficient.

## Results

On CIFAR-10 (5+5 disjoint classes), ZipIt! with all 20 layers zipped achieves 92.1% average per-task accuracy, outperforming Git Re-Basin (79.8%) by 12.3 points and the Permute baseline (87.4%) by 4.7 points, while remaining only 4.5 points below the ensemble upper bound (96.6%). With partial zipping (13/20 layers), ZipIt! reaches 94.6% average accuracy at just 0.91G FLOPs. On the much harder ImageNet-1k (200+200) setting, ZipIt! 10/50 achieves 69.1% average accuracy versus 5.5% for Git Re-Basin and 12.7% for Permute, approaching the 72.4% ensemble bound.

## Baselines & Comparisons

ZipIt! decisively outperforms Git Re-Basin across all settings: on CIFAR-10 (5+5), ZipIt! 20/20 achieves 92.1% average accuracy versus Git Re-Basin's 79.8% (+12.3 points), and on CIFAR-100 (50+50) it reaches 68.0% vs. 57.0% (+11.0 points). The gap widens dramatically on ImageNet-1k (200+200), where Git Re-Basin collapses to 5.5% average accuracy while ZipIt! 10/50 reaches 69.1% (+63.6 points). ZipIt! also consistently beats the stronger Permute (Eq. 2) baseline, which uses optimal linear-sum-assignment permutations within the same framework: +4.7 points on CIFAR-10, +7.0 points on CIFAR-100, and +56.4 points on ImageNet. The paper notes that Git Re-Basin fails to even outperform the individual unmerged models on joint classification in most settings, while ZipIt! with partial zipping approaches the ensemble upper bound (within 2–4 points) while using fewer FLOPs than running both models separately.

## Relation to Prior Work

This paper extends the model merging line of work (Git Re-Basin, REPAIR, Model Soups) from its original setting—merging models trained on the same task with the same or similar initializations—to the much harder problem of merging models trained on completely disjoint tasks and datasets. The key conceptual departure is twofold: (1) generalizing the merge operation from cross-model permutation to a 'zip' that also allows merging correlated features within each model, and (2) introducing partial zipping that stops the merge at a specified layer to create a multi-head architecture. Theoretically, the paper tightens the linear mode connectivity bound of Entezari et al. (2021) by showing that exploiting within-model redundancy yields a strictly better guarantee, and it borrows the feature-correlation matching methodology from Li et al. (2015) and Jordan et al. (2022).

## Why It Matters / Open Questions

ZipIt! provides a practical, training-free recipe for combining pre-trained models into multi-task systems, which is valuable given the cost of retraining and the risk of catastrophic forgetting. The finding that partial zipping (a simple architectural choice) recovers most of the performance lost by full merging, and that the optimal within-model merge budget depends on task difficulty, offers actionable guidance for practitioners. Limitations include the requirement for identical architectures, the need for unlabeled data to compute feature correlations, and the fact that merged models still fall short of ensembles. Open questions include whether the approach transfers to transformers and other non-CNN backbones, how it scales beyond four models, and whether the theoretical bounds (derived for random initializations) hold for well-trained networks.
