## Problem

Standard LLM prompting processes one data point per call, wasting tokens on repeated task specifications and few-shot examples when the actual data is small relative to the prompt overhead. Naive batching of multiple data points into a single prompt degrades accuracy—especially as batch size grows—due to position-dependent performance shifts in autoregressive decoding, making it unclear how to exploit long-context windows for efficient multi-sample inference without sacrificing quality.

## Input / Output

Each prompt contains a task specification (role description, class definitions, 2–4 few-shot examples with manually assigned confidence labels) followed by N indexed data points (e.g., 'Input 0: …', 'Input 1: …') and a batch-size reminder to prevent missing outputs. The LLM must generate one label per data point in a fixed format ('[class X] (confident/not confident)'), and for GSM8K it additionally produces intermediate arithmetic reasoning steps before the final numerical answer. Data must use explicit numeric indices rather than bare delimiters, otherwise the model drops answers.

## Method

BatchPrompt packs N data points into a single prompt to amortize task-specification tokens. To counteract position-dependent accuracy loss, Batch Permutation and Ensembling (BPE) runs K voting rounds, each with a different random permutation of the batch, then aggregates answers via majority voting or self-weighted majority voting (sw-mv), where the LLM's own 'confident'/'not confident' annotation assigns weight 1 or α=0.2 to each vote. Self-reflection-guided EArly Stopping (SEAS) further reduces cost: once a data point yields two consecutive identical answers both marked 'confident,' it is removed from subsequent rounds, shrinking the effective batch size over time. This dual effect—fewer tokens per round and a smaller, harder residual batch—simultaneously cuts token usage (≈80% of samples resolve within two rounds) and improves accuracy on the remaining difficult samples.

## Results

At batch size 32 with 5 voting rounds, BatchPrompt + BPE + SEAS on GPT-4 achieves 90.94% accuracy on BoolQ (vs. 90.63% SinglePrompt) using only 107,957 input tokens (27.4% of SinglePrompt's 384,946), 88.44% on QQP (vs. 87.2%) using 33,170 tokens (18.6% of 171,401), and 91.08% on RTE (vs. 91.45%) using 48,693 tokens (30.8% of 158,270). The method reduces LLM calls by 84.4% (BoolQ/RTE) and 90.6% (QQP) compared to SinglePrompt. On GSM8K, batch size 32 with 5 voting rounds reaches 92.0% accuracy (vs. 94.9% SinglePrompt) without SEAS, demonstrating applicability to arithmetic reasoning.

## Baselines & Comparisons

The primary baseline is SinglePrompt (one data point per LLM call). On GPT-4, BatchPrompt + BPE + SEAS at batch size 32 with 5 voting rounds matches or exceeds SinglePrompt on BoolQ (90.94% vs. 90.63%) and QQP (88.44% vs. 87.2%) while using only 27.4% and 18.6% of the input tokens, respectively; on RTE it is slightly lower (91.08% vs. 91.45%) but still uses only 30.8% of tokens. Compared to naive BatchPrompt (without BPE), the BPE permutation-and-voting step is essential at larger batch sizes: at batch size 64 with 1 voting round, GPT-4 accuracy drops to 72.8% on BoolQ, but recovers to 86.3% with 9 voting rounds. The SEAS early-stopping mechanism further reduces token growth after voting round 3 (since ~80% of easy samples are resolved by then), though it can slightly reduce peak accuracy versus running all voting rounds to completion (e.g., RTE best without SEAS is 92.9% vs. 91.7% with SEAS). The paper also notes that BPE is most effective on stronger models: GPT-4 consistently outperforms gpt-3.5-turbo under batching, because majority voting requires a sufficiently high base accuracy to accumulate correct votes.

## Relation to Prior Work

This paper extends the naive batch prompting approach of Cheng et al. (2023), which limited batch size to under 6 to avoid quality degradation, by introducing Batch Permutation and Ensembling (BPE) and Self-reflection-guided EArly Stopping (SEAS) to handle much larger batches (up to 160) while preserving or improving accuracy. Conceptually, BPE repurposes the self-consistency principle from Wang et al. (2022) and MathPrompter (Imani et al., 2023) — repeated sampling with majority voting — but applies it across permuted batch positions rather than repeated identical prompts, thereby amortizing the cost of multiple calls across many data points simultaneously. The paper positions itself as orthogonal to the large body of prompt-engineering work (which optimizes task specifications), instead targeting the data-batching dimension of the prompt.

## Why It Matters / Open Questions

The practical impact is significant for anyone running LLM inference at scale: at batch size 32, the method reduces LLM calls by ~84% and input tokens by 70–81% while matching or slightly exceeding single-prompt accuracy on Boolq, QQP, and RTE. However, the approach is validated only on binary classification and arithmetic reasoning tasks; the authors explicitly note it may not transfer to open-ended generation or summarization where answers vary across voting rounds. Open questions include automating the selection of batch size, voting rounds, and confidence weighting (the authors suggest RL or Bayesian optimization), and whether the method generalizes to non-binary or multi-class settings. The finding that BPE requires a strong baseline model (works well on GPT-4 but poorly on gpt-3.5-turbo) also limits its applicability to weaker or smaller models.
