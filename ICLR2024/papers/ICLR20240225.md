## Problem

Existing 3-4 bit post-training quantization methods for LLMs still incur significant accuracy degradation, particularly for smaller models (1-10B parameters) that are the most practical for edge deployment. No prior method achieves near-lossless compression (within 1% relative perplexity error) at these aggressive bit-widths, because quantization errors are concentrated in structured outlier weights that standard uniform quantization cannot handle.

## Input / Output

The method consumes a pretrained LLM's weight matrices and a small set of calibration sequences (e.g., 128 sequences of 2048 tokens) passed through the uncompressed model to compute per-layer Hessian statistics. The output is a compressed model in SpQR format consisting of four components: 3-4 bit quantized weight codes, first-level quantized group statistics (scales and zero-points), second-level quantization statistics for those statistics, and a sparse matrix of 16-bit outlier values with relative 8-bit index shifts. The compressed model supports standard autoregressive text generation with a custom GPU kernel.

## Method

SpQR extends GPTQ's layer-wise Hessian-based solver with a two-step procedure: first, it identifies outlier weights whose quantization would cause disproportionately high output error (using a leave-one-out sensitivity criterion on the Hessian submatrix) and isolates them in 16-bit precision; second, it quantizes the remaining 'base' weights to 3-4 bits using bilevel quantization with very small group sizes (8-32 weights), where the group scales and zero-points are themselves quantized to 3 bits to reduce metadata overhead. The key insight is that LLM weight quantization errors exhibit both vertical (column/input-dimension) and horizontal (row/output-dimension) outlier structures, including partial-row outliers tied to attention heads and rotary embedding patterns, which no single structured sparsity pattern can capture. For efficient storage, sparse outlier indices are encoded as 8-bit relative shifts between adjacent outliers (with virtual zero-valued outliers inserted when gaps exceed 255 columns), reducing index overhead from 16 to 8-9 bits per outlier. At inference time, a custom GPU kernel combines dense dequantized matrix multiplication for the base weights with a specialized sparse matrix multiplication for the outliers, achieving 20-30% speedup over 16-bit baselines while using 4x less memory.

## Results

SpQR achieves near-lossless compression of LLaMA models with less than 1% relative perplexity degradation at 4.6–4.71 bits per parameter (e.g., LLaMA-65B: 3.57 vs. 3.53 WikiText2 perplexity for 16-bit). At a controlled 4-bit budget, SpQR halves the perplexity error relative to the 16-bit baseline compared to GPTQ (e.g., LLaMA-7B: 5.87 vs. 6.13 for GPTQ on WikiText2). The optimized SpQR inference kernel is 20–30% faster than 16-bit inference and ~2× faster than PyTorch's cuSPARSE-based sparse matrix multiplication, enabling a 33B-parameter LLM to run on a single 24 GB consumer GPU.

## Baselines & Comparisons

Against GPTQ (the strongest prior PTQ method), SpQR at ~4 bits halves the perplexity error relative to the 16-bit baseline; the gap between SpQR and GPTQ is as large as the improvement GPTQ provides over naive RTN (e.g., LLaMA-7B WikiText2: SpQR 5.87 vs. GPTQ 6.13 vs. RTN 6.43). Against SqueezeLLM, SpQR outperforms at 3.25 bits (LLaMA-7B WikiText2: 6.01 vs. 6.13) and matches at ~4 bits (5.79 vs. 5.79), while being more memory-efficient since it requires only forward passes rather than backpropagation. Against AWQ, SpQR is consistently better at both 3.25 and 4 bits across all LLaMA sizes tested (e.g., LLaMA-7B WikiText2 at ~4 bits: SpQR 5.79 vs. AWQ 5.87). Against QuIP (2-bit quantization), SpQR outperforms on OPT models with >1B parameters, though the authors note 2-bit is not Pareto-optimal since 4-bit on a smaller model is generally preferable. On zero-shot tasks (WinoGrande, PiQA, HellaSwag, ARC), SpQR at 4.6–4.7 bits matches or slightly exceeds 16-bit accuracy, while GPTQ at 4 bits shows 1–3 point drops on average.

## Relation to Prior Work

SpQR extends the GPTQ post-training quantization framework by introducing two key modifications: bilevel quantization with very small group sizes (8–32) where quantization statistics are themselves quantized to 3-bit, and unstructured outlier isolation that retains ~0.3–1% of weights in 16-bit precision. It departs from LLM.int8() and SmoothQuant, which only handled column-wise input-feature outliers, by demonstrating that output-dimension (row) outliers also exist and contribute significantly to quantization error. The method also contrasts with concurrent work like AWQ and SqueezeLLM, which protect salient weights via per-channel scaling or non-uniform quantization rather than explicit sparse outlier storage.

## Why It Matters / Open Questions

SpQR is the first weight-quantization method to achieve near-lossless (<1% perplexity degradation) compression at 3–4 bits per parameter across model scales from 7B to 180B, enabling a 33B-parameter LLM to run on a single 24 GB consumer GPU with a 15–30% speedup over 16-bit inference. Key limitations include the absence of generative-quality evaluation (only perplexity and zero-shot accuracy are measured), the lack of fused sparse-dense matrix multiplication kernels, and the requirement for calibration data. An open question is whether perplexity preservation reliably translates to generation quality, and whether the outlier-detection criterion generalizes to architectures without rotary embeddings or with different attention mechanisms.
