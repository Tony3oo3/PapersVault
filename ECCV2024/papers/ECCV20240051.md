## Problem

Deep SLAM systems like DROID-SLAM achieve high accuracy but require 24GB GPU memory and run slower than classical approaches, making portable deployment impractical. The efficient sparse alternative DPVO avoids these costs but is limited to visual odometry with no loop closure and suffers severe scale drift outdoors. This paper addresses how to extend DPVO into a full SLAM system with loop closure while preserving its low memory footprint and real-time speed.
![Teaser figure](../imgs/ECCV20240051/cropped_page4_idx0.webp)

## Input / Output

The system consumes a monocular RGB video stream and outputs per-frame 6DOF camera poses, inverse depth estimates for 64–96 randomly selected keypoints per frame, and a 3D environment map. The odometry frontend operates on a sliding window of frames, while the proximity backend maintains a globally connected patch graph limited to ~1000 frames to bound the Cholesky decomposition cost. The classical backend additionally extracts ORB features and builds a dBoW2 vocabulary index in a separate CPU process, incurring negligible runtime overhead.

## Method

DPV-SLAM introduces two loop closure mechanisms on top of the DPVO patch-graph frontend. The proximity backend exploits the directed structure of patch-graph edges: since correlation features are only needed at the destination frame while the source frame requires only small patch crops, edges are permanently directed from old keyframes to recent frontend frames, storing only ~0.6GB of patch features per 1000 frames and a finite set of dense feature maps. A custom CUDA block-sparse bundle adjustment solver then performs global optimization over both odometry and long-range proximity factors in a single GPU process. The classical backend (DPV-SLAM++) uses dBoW2/ORB retrieval to detect loops, off-the-shelf detectors and matchers to estimate 2D correspondences, structure-only BA to triangulate 3D points, RANSAC+Umeyama to compute a 7DOF Sim(3) drift estimate, and a CPU-parallel pose graph optimization to correct scale drift. The entire system is trained end-to-end on synthetic TartanAir data only, with no domain-specific fine-tuning.

## Results

On EuRoC-MAV, DPV-SLAM achieves 0.023 m ATE, matching DROID-SLAM (0.022 m) while running 2.5× faster (50 vs 20 FPS) and using 4× less GPU memory (5.0 GB vs 20 GB). On KITTI, DPV-SLAM++ achieves 25.76 m ATE, dramatically outperforming DROID-SLAM (118.7 m, catastrophic failure) and DPVO (53.61 m). On TartanAir, DPV-SLAM achieves 0.16 m ATE versus DROID-SLAM's 0.24 m. On TUM-RGBD, DPV-SLAM++ achieves 0.054 m ATE, comparable to GO-SLAM (0.035 m) and DROID-SLAM (0.038 m) while using less memory (6.0 GB vs 7.2–8.5 GB).

## Baselines & Comparisons

DPV-SLAM matches DROID-SLAM on EuRoC (0.023 vs 0.022 m ATE) while running 2.5× faster and using 4× less VRAM, and outperforms it on TartanAir (0.16 vs 0.24 m). On KITTI, DPV-SLAM++ (25.76 m) dramatically outperforms DROID-SLAM (118.7 m, catastrophic failure) and DPVO (53.61 m), while DROID-SLAM's loop closure mechanism actually causes failures outdoors. Compared to GO-SLAM, DPV-SLAM achieves similar EuRoC accuracy (0.023 vs 0.024 m) at 8× the speed (50 vs 6 FPS) and 2.8× less memory (5G vs 14G). Against classical methods, ORB-SLAM3 and ORB-SLAM2 fail on TUM-RGBD (multiple X marks) and TartanAir, while DPV-SLAM++ handles all datasets without catastrophic failures. On TUM-RGBD, DPV-SLAM++ (0.054 m) is slightly worse than GO-SLAM (0.035 m) and DROID-SLAM (0.038 m) but uses less memory (6.0G vs 7.2–8.5G). Versus the base DPVO system, adding loop closure reduces EuRoC error by 4.5× (0.105→0.023 m) at only a 10 FPS cost (60→50 FPS) and 1 GB memory increase (4G→5G).

## Relation to Prior Work

DPV-SLAM extends the DPVO visual odometry system (itself a sparse, efficient analog of DROID-SLAM's dense frontend) into a full SLAM system by introducing two loop closure mechanisms: a proximity-based backend that exploits the directional asymmetry of the patch graph (outgoing edges require only cheap patch features, incoming edges require expensive dense feature maps) to insert long-range edges with minimal memory overhead, and a classical dBoW2/ORB retrieval-based backend with Sim(3) pose graph optimization for scale drift correction. The CUDA-accelerated block-sparse bundle adjustment is a new implementation tailored to DPVO's varying-sized patch graph, filling a gap left by prior work that only handled dense, uniformly-sized depth maps. Conceptually, the paper sits at the intersection of the DROID-SLAM/DPVO lineage (deep-network backbones trained on synthetic data for zero-shot generalization) and classical SLAM's loop closure strategies, unifying them in a single-GPU, single-process pipeline.

## Why It Matters / Open Questions

The practical impact is significant: reducing VRAM from 20 GB to 5 GB and doubling inference speed makes deep-network SLAM deployable on portable hardware for the first time, addressing a key barrier to real-world adoption. The zero-shot generalization across indoor (EuRoC, TUM) and outdoor (KITTI) domains without retraining, with zero catastrophic failures, positions DPV-SLAM as a broadly applicable system rather than a domain-specific one. Open questions include scalability beyond the 1000-frame global BA window (limited by Cholesky decomposition cost), robustness of the image retrieval to false positives, and whether the sparse patch representation can be further extended to handle very large-scale or long-duration sequences. The paper also highlights a broader tension: DROID-SLAM's mid-term loop closure actually causes catastrophic failures on outdoor KITTI, suggesting that deep SLAM backends need more careful domain-aware design.
