## Problem

Existing Transformer-based point cloud completion methods suffer from two key deficiencies: (1) the absence of global semantic priors in 3D space increases the complexity of the set-to-set translation solution space, and (2) reusing standard Transformer decoder query and value tokens without tailoring them to 3D geometry can be counterproductive when dependencies between partial input and missing regions vary across occlusion scenarios.

## Input / Output

The method takes an incomplete 3D point cloud (2048 points on PCN; 2048, 4096, or 6144 points on ShapeNet-55/34 representing 25%, 50%, 75% completeness) and produces a complete 3D point cloud (16384 points on PCN; 8192 on ShapeNet-55/34). Internally, the pipeline operates on a coarse template of 512 points and a fine template of 512 points, with a Corres-Pool of 640 candidate points (256 from the coarse template, 384 from the sampled partial input) from which dynamic query tokens are selected via a voting mechanism.

## Method

T-CorresNet follows a coarse-to-fine paradigm built on a geometry-aware Transformer encoder-decoder. First, a standard Gaussian spherical template (points sampled from N(0,1) and normalized to the unit sphere) is embedded into the partial input's point proxies at each Transformer encoder layer, expanding the input space and providing a global shape prior that guides coarse template generation. The encoder uses DGCNN-based local feature extraction with farthest point sampling, followed by kNN-augmented self-attention blocks. A Corres-Pooling query generator then refines the noisy coarse template: it builds a kNN graph between the coarse template and sampled input, computes correspondence scores via graph attention, replaces the most input-similar template points with actual input points, and uses a voting network to select 512 points as the fine template and 640 as the dynamic query token pool. The decoder employs cross-attention where query tokens are the fine template concatenated with the global encoder feature, and value vectors combine encoder output with a fresh random sphere for geometric compatibility. Finally, a FoldingNet generates the complete point cloud by predicting local offsets from each fine template point using the predicted point proxies, trained end-to-end with Chamfer Distance losses on both the fine template and the final output.

## Results

On the PCN benchmark, T-CorresNet achieves an average CD-l1 of 6.47 (×1000) and F-Score@1% of 0.845, outperforming the previous best AdaPoinTr (CD-l1 6.53, F1 0.845). On ShapeNet-55, it attains the best average CD-l2 of 0.80 (×1000) across three difficulty levels, slightly ahead of AdaPoinTr (0.81), though its F-Score@1% (0.485) trails AdaPoinTr (0.503). On the ShapeNet-34 generalization benchmark, T-CorresNet achieves the best CD on both seen (0.73) and unseen (1.15) categories, improving over AdaPoinTr's unseen CD by 0.08 (×1000) and outperforming all other methods by nearly 7% on unseen categories.

## Baselines & Comparisons

T-CorresNet achieves the best average CD across all three benchmarks, with the closest competitor being AdaPoinTr [32]. On PCN, T-CorresNet improves CD-l1 from 6.53 to 6.47 (×1000) while matching AdaPoinTr's F1 of 0.845. On ShapeNet-55, it edges out AdaPoinTr on CD-l2 (0.80 vs 0.81) but trails on F-Score@1% (0.485 vs 0.503), which the authors attribute to residual noise from the spherical template. On the ShapeNet-34 generalization test, T-CorresNet achieves the best unseen-category CD (1.15 vs AdaPoinTr's 1.23, ×1000) and outperforms all other methods by nearly 7% on unseen categories, though its unseen F1 (0.409) is slightly below AdaPoinTr (0.416). Against earlier Transformer-based methods like PoinTr [31], SeedFormer [36], and ProxyFormer [8], T-CorresNet shows consistent CD improvements of 0.15–0.55 (×1000) on PCN. Older encoder-decoder baselines (PCN, TopNet, GRNet, PF-Net) and voxel-based methods (FoldingNet, AtlasNet) are substantially outperformed, with CD gaps exceeding 2.0 (×1000) on PCN.

## Relation to Prior Work

T-CorresNet extends the geometry-aware Transformer encoder-decoder paradigm established by PoinTr and its successors (AdaPoinTr, ProxyFormer, SeedFormer), but departs from them in two key ways: it embeds a Gaussian spherical template into the input to provide a global shape prior (inspired by SP-GAN's sphere-guided generation), and it replaces the standard transformer decoder's fixed query tokens with a Corres-Pooling mechanism that dynamically generates queries by identifying and preserving high-correspondence points from the partial input. The final point cloud is still produced via FoldingNet, maintaining the coarse-to-fine generation pipeline common to this line of work.

## Why It Matters / Open Questions

The spherical template as a global prior and the correspondence-based query generation address two identified weaknesses of prior transformer-based completion methods: lack of global semantic structure and over-reliance on NLP-style decoder assumptions that don't suit 3D geometry. However, the gains over strong baselines like AdaPoinTr are modest (e.g., 6.47 vs 6.53 CD on PCN; 0.80 vs 0.81 on ShapeNet-55), and the template introduces noise that slightly hurts F-Score. The authors acknowledge that maintaining fine geometric details during up-sampling remains the main bottleneck, and whether the spherical template is truly optimal over other deformable priors is left open.
