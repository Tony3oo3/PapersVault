## Problem

Existing LiDAR-camera fusion methods for 3D object detection violate a fundamental principle from the data annotation process: they involve image features in regression task prediction (3D box geometry), which causes overfitting and forces reliance on complex multi-stage pre-training and custom learning rate schedules. The paper argues that, just as human annotators use images to locate candidates but point clouds to determine box edges, the algorithm should enforce a strict modality separation between candidate generation and regression prediction.
![Teaser figure](../imgs/ECCV20240588/cropped_page1_idx0.webp)

## Input / Output

The method consumes a 32-beam LiDAR point cloud and 6 synchronized camera images (360° coverage) from the nuScenes dataset, with image resolutions ranging from 192×544 (Tiny) to 384×1056 (Large) and LiDAR voxel resolutions from 0.050 m to 0.100 m. It outputs 3D bounding boxes (center, size, orientation, velocity) and category labels for 10 object classes. Critically, the regression targets are predicted exclusively from point cloud features, while category prediction uses a fused feature combining sparse image features, image BEV features, and point cloud BEV features.

## Method

DAL follows a dense-to-sparse pipeline that mirrors the annotation workflow: a dense stage fuses image BEV features (via LSS view transformation) with point cloud BEV features to predict a heatmap and select top-K candidates, while a sparse stage predicts regression targets from point cloud features alone via a simple FFN and predicts categories from fused multi-modal features. Training is single-stage and end-to-end, requiring only ImageNet pre-training for the image backbone and a cycle learning rate over 20 epochs—no multi-stage pre-training or custom schedules. Two key enablers follow from excluding image features from regression: (1) a much wider image resize augmentation range ([0.36, 0.88] vs. [0.36, 0.55]) becomes feasible, and (2) a velocity augmentation strategy can be applied to static objects to correct the heavily imbalanced velocity distribution in nuScenes. The paper also introduces BEVPoolV2, an accelerated LSS implementation that replaces explicit frustum feature storage with pre-computed frustum index pointers, achieving 4.6×–15.1× speedup and reducing memory to ≤30 MB even at high resolutions.

## Results

On the nuScenes val set, DAL-Large achieves 71.5 mAP and 74.0 NDS at 6.10 FPS, surpassing the previous best (UniTR, 73.3 NDS) by +0.7 NDS while using only ImageNet pre-training and a single-stage 20-epoch training schedule. On the nuScenes test set, DAL-Large reaches 74.8 NDS and 72.0 mAP, outperforming all prior methods. The lighter DAL-Base configuration (35M params) runs at 10.69 FPS with 73.4 NDS, and DAL-Tiny (21M params) reaches 16.55 FPS with 71.3 NDS, offering a strong speed-accuracy trade-off.

## Baselines & Comparisons

DAL-Large outperforms all 13 compared baselines on NDS on both the nuScenes val set (74.0 vs. 73.3 for UniTR, the previous best) and test set (74.8 vs. 74.5 for UniTR). On mAP, DAL-Large leads by +1.0 over UniTR (71.5 vs. 70.5) and +1.5 over SparseFusion (71.5 vs. 70.5). The speed-accuracy trade-off is a key differentiator: DAL-Base matches CMT-R50's inference speed (10.69 vs. 10.72 FPS) while gaining +2.1 mAP and +2.6 NDS, and DAL-Tiny is 54% faster than CMT-R50 at only −0.5 mAP. Notably, DAL achieves these results with the simplest training pipeline among all compared methods—no camera pre-training beyond ImageNet, no LiDAR pre-training, no custom learning-rate schedule, and a single 20-epoch stage—whereas competitors like UVTR, CMT-VOV, and SparseFusion require multi-stage pre-training on additional datasets (COCO, nuImages, DD3D) and custom LR policies. On the test set, DAL's velocity error (mAVE = 17.4) is substantially lower than all baselines (next best: UniTR at 24.0), attributed to the velocity augmentation strategy.

## Relation to Prior Work

DAL builds on the BEV-based fusion paradigm established by BEVFusion and the Lift-Splat-Shoot view transformation, while adopting loss designs from TransFusion and architectural components from CenterPoint (LiDAR branch) and BEVDet (camera branch). Its key conceptual departure is the 'Detecting As Labeling' principle: regression targets (center, size, orientation, velocity) are predicted exclusively from point cloud features, while image features are reserved for candidate generation and category prediction. This inverts the prevailing assumption in prior fusion methods that image features should inform all prediction heads, and the paper also contributes BEVPoolV2, an engineering upgrade to the LSS implementation that reduces memory and latency by orders of magnitude.

## Why It Matters / Open Questions

The paper provides a principled, minimal-dependency baseline (single-stage training, ImageNet pre-training only) that outperforms methods requiring multi-stage pre-training and custom learning-rate schedules, making it a practical reference for both research and edge deployment. The 'Detecting As Labeling' framing offers a reusable design heuristic for future fusion architectures, and BEVPoolV2 removes a long-standing bottleneck for deploying LSS-based pipelines on resource-constrained hardware. Open questions include whether the principle generalizes to open-world classification (where the camera branch may need stronger backbones), how to handle objects beyond LiDAR range, and whether attention-based mechanisms can be integrated without reintroducing the overfitting the paper identifies.
