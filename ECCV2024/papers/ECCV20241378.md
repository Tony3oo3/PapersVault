## Problem

Person Re-ID models suffer significant performance drops when deployed in environments different from their training distribution, and standard Unsupervised Domain Adaptation (UDA) methods require transferring all target images to a central server, violating GDPR's Data Minimization and Purpose Limitation principles. Existing federated Re-ID methods either assume labeled target data or do not address the domain gap between source and target distributions. This paper introduces the DUDA-Rid problem: adapting a Re-ID model across multiple edge cameras without any image leaving its capture device.
![Teaser figure](../imgs/ECCV20241378/cropped_page1_idx1.webp)

## Input / Output

The method consumes unlabeled RGB person images that remain exclusively on each edge camera (target domain) and a labeled source dataset stored on the server. The server transmits only the aggregated model weights and a compact set of source prototypes (per-identity feature centroids) to each client; no pixel data crosses the network. Each client maintains a personalized classifier head sized to its local identity count, and the final output is a federated Re-ID model producing identity match rankings evaluated via mAP and CMC Rank-1 on held-out target test sets.

## Method

Fed-Protoid frames DUDA-Rid as a federated learning problem with a teacher-student architecture on every client and a supervised pseudo-client on the server. The key mechanism is a distributed Maximum Mean Discrepancy (MMD) loss that aligns target feature statistics with source prototypes (computed as per-identity centroids from the aggregated global model) rather than requiring raw source-target sample comparison, keeping communication to a single model weight vector plus a small prototype set per round. Target identity estimation uses iterative DBSCAN pseudo-labeling, and a Personalized Pseudo-Epoch (PPE) schedules training so each local identity is sampled equally regardless of client size. Aggregation is a weighted average of the pseudo-client and all client teacher models. Fed-Protoid++ replaces the ResNet-50 backbone with a ViT-Small pre-trained self-supervisedly on the large-scale LUPerson dataset, yielding substantial additional gains (e.g., 51→61.7 mAP on MS→M).

## Results

Fed-Protoid (ResNet-50) achieves 51.0 mAP / 76.8 Rank-1 on MS→Market-1501 and 23.8 mAP / 23.1 Rank-1 on MS→CUHK03, outperforming all federated and adapted UDA baselines. The enhanced Fed-Protoid++ (ViT + LUPerson self-supervised pre-training) further boosts performance to 61.7 mAP / 82.6 Rank-1 on MS→Market-1501 and 43.8 mAP / 42.4 Rank-1 on MS→CUHK03. In synthetic-to-real settings, Fed-Protoid reaches 39.2 mAP on RP→Market-1501 and 25.1 mAP on RP→CUHK03, while Fed-Protoid++ attains 45.2 mAP and 25.7 mAP respectively. Fed-Protoid also requires fewer communication rounds (e.g., 22 rounds for MS→CUHK03 vs. 750 for FedReID) and transmits only one model backbone per round versus four for MMT.

## Baselines & Comparisons

Fed-Protoid outperforms all federated Re-ID baselines by large margins: on MS→CUHK03 it achieves 23.8 mAP versus 11.6 (FedReID) and 6.8 (FedUnReID), and on RP→Market-1501 it reaches 39.2 mAP versus 38.9 (FedReID) and 19.5 (FedUnReID). Against the adapted UDA baselines, Fed-Protoid gains +5.2 mAP over FedPav+MMT (51.0 vs. 45.8) and +11.9 mAP over FedAvg+SpCL (51.0 vs. 39.1) on MS→Market-1501, while also transmitting only one backbone per round versus four for MMT. In the synthetic-to-real RP→Market-1501 setting, Fed-Protoid leads SpCL by +3.1 mAP (39.2 vs. 36.1) and MMT by +9.0 mAP (39.2 vs. 30.2). Fed-Protoid++ further extends these gaps, reaching 61.7 mAP on MS→Market-1501, surpassing the strongest DG baseline TransMatcher (52.0 mAP) by +9.7 mAP and PAT (47.3 mAP) by +14.4 mAP. Notably, Fed-Protoid also converges faster in practice: it reaches its best MS→CUHK03 score in 22 rounds versus 750 for FedReID, and its per-round communication cost is roughly one-quarter that of MMT.

## Relation to Prior Work

This paper sits at the intersection of federated learning for person Re-ID (building on FedPav and FedReID/FedUnReID) and unsupervised domain adaptation for Re-ID (building on pseudo-labeling frameworks like BUC, MMT, and SpCL). It departs from prior federated Re-ID work by eliminating the requirement to transfer images to edge servers, and from prior UDA-ReID work by eliminating centralized image storage, instead introducing a distributed MMD loss that aligns target features to source prototypes computed on the server. The prototype-based alignment mechanism draws on prototypical networks from few-shot learning and federated prototype learning (FedProto, FPL), but is the first to apply prototypes in an unsupervised, open-world Re-ID setting where the number of target identities is unknown.

## Why It Matters / Open Questions

The DUDA-Rid formulation directly addresses a practical regulatory gap: GDPR's Data Minimization and Purpose Limitation principles make centralized image collection legally problematic, yet prior UDA-ReID methods all require it. The paper demonstrates that meaningful domain adaptation is achievable with only model parameters and compact prototypes crossing the network boundary, which has direct implications for deploying Re-ID systems in privacy-sensitive public spaces. Open questions include scalability to hundreds of cameras with highly heterogeneous data, handling identity overlap across cameras, and whether the prototype-based MMD alignment generalizes to other Re-ID modalities (video, multi-sensor). The narrow evaluation to two target datasets and two source datasets limits confidence in broader generalization.
