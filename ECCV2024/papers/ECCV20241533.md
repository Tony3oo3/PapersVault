## Problem

Existing DETR-like online map construction methods use point queries to probe BEV features, where each point independently predicts one position. This design lacks explicit relational modeling among points belonging to the same map element and ignores positional information, relying on randomly initialized learnable queries. The paper asks whether a query mechanism that explicitly separates content and position, while modeling intra-instance relations, can improve vectorized map construction.
![Teaser figure](../imgs/ECCV20241533/cropped_page1_idx0.webp)

## Input / Output

The method consumes sequences of 6 (nuScenes) or 7 (Argoverse 2) surround-view RGB images, processed through a shared 2D backbone and a PV-to-BEV view transformation module producing a 200×100 BEV feature map covering 60m×30m. Output consists of up to 100 map element instances, each with a class label (lane divider, pedestrian crossing, or road boundary) and a set of 20 sequential 2D or 3D points forming a polyline. The point count per instance (n=20) and instance count (N=100) are fixed hyperparameters.

## Method

The core contribution is a scatter-and-gather query (SGQ) decoder that replaces N×n point queries with N instance queries. In each decoder layer, self-attention operates only on the N instance queries (reducing O(N²) complexity versus O((N·n)²) in MapTR), then each instance query is scattered into n identical copies that receive distinct sinusoidal positional embeddings from their reference points before cross-attention with BEV features. The n scattered queries are gathered back into a single instance query via MLP(concat), explicitly modeling intra-instance relations through shared content and differentiated position. A secondary contribution, GKT-h, adds a learnable linear projection to predict adaptive height offsets for 3D reference points in the BEV encoder, improving over fixed-height sampling. Training uses hierarchical bipartite matching (instance-level then point-level via Manhattan distance) with a composite loss of one-to-one, one-to-many, and dense segmentation terms.

## Results

On nuScenes with strict thresholds {0.2m, 0.5m, 1.0m}, MapQR (R50, 24 epochs) achieves mAP₁ = 43.3, outperforming MapTRv2 (37.2), BeMapNet (41.3 at 30 epochs), and StreamMapNet (36.2) by 6.1, 2.0, and 7.1 points respectively. With 110 epochs, MapQR reaches mAP₁ = 50.5 and mAP₂ = 72.6, setting new state-of-the-art on both threshold settings. On Argoverse 2 (2D, 6 epochs), MapQR achieves mAP₁ = 45.1 vs. MapTRv2's 42.5 and MapTR's 38.8. Inference speed is ~18 FPS on a single NVIDIA 4090, comparable to MapTRv2 (19.6 FPS).

## Baselines & Comparisons

MapQR outperforms all five baselines on nuScenes under matched settings (R50, 24 epochs): it beats MapTRv2 by +6.1 mAP₁ (43.3 vs. 37.2), StreamMapNet by +7.1, BeMapNet by +2.0 (at 30 epochs), PivotNet by +4.8, and MapTR by +16.0. At 110 epochs, the gap over MapTRv2 widens to +5.1 mAP₁ (50.5 vs. 45.4) and +4.4 over BeMapNet (50.5 vs. 47.1). On Argoverse 2 (2D, 6 epochs, R50), MapQR leads MapTRv2 by +2.6 mAP₁ (45.1 vs. 42.5) and MapTR by +6.3. The advantage is most pronounced under stricter thresholds (mAP₁), confirming that the scatter-and-gather query improves fine-grained point localization. In terms of speed, MapQR runs at ~18 FPS, slightly slower than MapTR (24.2 FPS) but comparable to MapTRv2 (19.6 FPS) and StreamMapNet (19.9 FPS), while BeMapNet is notably slower at 8.3 FPS.

## Relation to Prior Work

This paper extends the DETR-like framework for online vectorized HD map construction established by MapTR and MapTRv2, which treat map elements as point sets predicted by independent point queries. The key departure is the scatter-and-gather query design, inspired by the content/position separation in Conditional DETR and DAB-DETR, which replaces independent point queries with a single instance query that is replicated (scattered) with distinct positional embeddings from reference points and then aggregated (gathered) back. This explicitly models intra-instance relationships that prior point-query methods leave implicit. The BEV encoder improvement (GKT-h) builds directly on GKT's geometry-guided kernel by adding learnable height offsets, a minimal modification that outperforms BEVPoolv2 with auxiliary depth supervision.

## Why It Matters / Open Questions

The scatter-and-gather query is a modular, plug-and-play decoder component that improves multiple existing map construction methods (MapTR, MapTRv2, StreamMapNet) without requiring architectural rework, making it a practical upgrade for the field. The reduced self-attention complexity (O(N_q²) vs. O((N_q·N_p)²)) enables scaling to more instance queries without prohibitive memory costs, opening the door to denser map element detection. Open questions include whether the scatter-and-gather principle generalizes to other set-prediction tasks beyond map construction, and whether the fixed number of sequential points (n=20) is optimal for all element types. The method's reliance on a specific BEV encoder (GKT-h) and the absence of temporal modeling (unlike StreamMapNet) are limitations for real-time deployment scenarios.
