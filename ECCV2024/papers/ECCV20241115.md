## Problem

Existing text-driven 3D scene editing methods (iterative, supervised, or denoised pipelines) tightly couple specific 2D visual models to the 3D reconstruction process, requiring intricate integration designs and constraining users to fixed text input patterns. This rigidity prevents flexible integration of diverse visual experts and makes dialogue-based, free-form interactive editing infeasible.
![Teaser figure](../imgs/ECCV20241115/cropped_page1_idx0.webp)

## Input / Output

The system accepts unconstrained free-form natural language (any phrasing, multi-round) alongside multi-view RGB images of a 3D scene, with no requirement for specific text templates or structured commands. It produces edited multi-view images of the 3D scene (reconstructed via TensoRF or Gaussian Splatting from the modified atlases) along with a natural-language text response from the LLM. Scene files are abstracted behind opaque string identifiers (e.g., 'xxx.scn') so the LLM never handles raw file paths.

## Method

CE3D fully decouples 2D editing from 3D reconstruction via a Hash-Atlas network: F_m maps each pixel (x, y, t) from T scene views to two UV coordinates plus a foreground transparency α, while F_h (a multiresolution hash-encoding MLP) predicts RGB values in the UV space, yielding separate foreground and background atlases. Training proceeds in two stages—pre-training with positional and α losses (using VQA/segmentation supervision), then full training with reconstruction loss augmented by an inpainting loss (ProPainter) to prevent background omissions, plus rigid and flow constraints. At inference, ChatGPT acts as an inference hub that parses user text, selects and parameterizes visual tools from a model zoo (segmentation, style transfer, inpainting, depth, etc.), and manages scene files via a Sensitivity-to-Scene-Names mechanism. An Executor applies a merge-split strategy: the foreground atlas is overlaid on the background to form a complete scene image for the 2D editing model, then the result is re-separated using the original and new object masks before mapping back to 3D views.

## Results

On atlas reconstruction, Hash-Atlas achieves 1.1–3.2 dB higher PSNR than LNA across four datasets (e.g., 28.53 vs. 25.56 on IBRNet-collect, 27.24 vs. 23.96 on CE3D-collect), while reducing training time by 14.2–18.6× (e.g., 0.56 h vs. 9.75 h on IBRNet-collect) and increasing inference speed by 7.6–9.0× (e.g., 6.13 vs. 0.79 FPS on IBRNet-collect). LPIPS drops substantially (e.g., 0.11 vs. 0.31 on IBRNet-collect), indicating markedly better perceptual fidelity. For 3D scene editing, CE3D is evaluated qualitatively against IN2N on multi-round dialogue and text-query robustness, where CE3D produces more consistent and diverse editing outcomes.

## Baselines & Comparisons

Against LNA [26] (the only quantitative baseline), Hash-Atlas wins on every metric across all four datasets: PSNR improves by 1.1–3.2 dB, SSIM by 0.04–0.21, LPIPS decreases by 0.12–0.41, training time is reduced by 14.2–18.6×, and inference FPS increases by 7.6–9.0×. The largest gains appear on IBRNet-collect (PSNR +2.97 dB, LPIPS 0.11 vs. 0.31) and CE3D-collect (PSNR +3.28 dB, LPIPS 0.12 vs. 0.53), suggesting Hash-Atlas scales well to more complex outdoor scenes. Against IN2N [19] (qualitative comparison only), CE3D demonstrates superior text-query robustness (Fig. 7b: IN2N produces notably varied results for semantically equivalent prompts, while CE3D remains stable) and handles multi-round dialogue (Fig. 8: a 4-round editing sequence involving object removal, segmentation, scene extraction, and style transfer) that IN2N cannot complete due to its limited editing vocabulary and rigid input format. No quantitative editing-quality metric (e.g., CLIP score) is reported for the IN2N comparison, so the editing advantage is supported only by visual evidence.

## Relation to Prior Work

This paper extends the LLM-as-inference-hub paradigm (Visual-ChatGPT, MM-REACT) from 2D visual tasks to 3D scene editing, while departing fundamentally from prior text-driven 3D editing frameworks (IN2N, DN2N, CLIP-NeRF, Gaussian-Editor) that tightly couple 2D visual models with 3D reconstruction through iterative, supervised, or denoising pipelines. The key architectural departure is the Hash-Atlas representation, which borrows hash encoding from Instant-NGP and atlas-based video editing (LNA) to project 3D scene views onto 2D planes, thereby fully decoupling 2D editing from 3D reconstruction. This decoupling enables plug-and-play integration of arbitrary 2D visual experts without the intricate co-design that prior coupled frameworks require.

## Why It Matters / Open Questions

The decoupled atlas-based paradigm offers a practical path toward open-ended, multi-round interactive 3D scene editing that is not constrained to a fixed set of visual models or rigid text input formats. However, significant limitations remain: the method supports only limited geometry editing (object removal/replacement, not location/scale/orientation changes), 360-degree scenes produce severely distorted atlases incompatible with 2D visual models, and the system's reliability is bottlenecked by LLM parsing correctness and the quality of individual visual experts. Open questions include whether the atlas representation can be made robust to arbitrary camera trajectories and whether the LLM orchestration layer can be made more reliable without manual prompt tuning for each visual model.
