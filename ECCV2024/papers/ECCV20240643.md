## Problem

Computational understanding of structured visuals like presentation slides and user interfaces requires large, manually annotated datasets, but high-quality public datasets for these domains are scarce and labor-intensive to build. Existing synthetic data approaches (e.g., WebSight) generate code-to-pixel translations without task-specific structural annotations, limiting their utility for downstream visual understanding tasks such as element detection, captioning, and classification.
![Teaser figure](../imgs/ECCV20240643/cropped_page3_idx0.webp)

## Input / Output

The generation pipeline takes abstract design principles (layout guidelines, design patterns, target label schemas) and seed design concept descriptions as input, and produces rendered slide images at 1280×720 and UI screenshots at 628×1118 pixels, each paired with HTML source code containing embedded semantic annotations (data-type attributes for elements, meta tags for screen-level labels, alt text for graphical content). Downstream models consume these rendered screenshots as RGB images and output element bounding boxes with class labels, natural-language captions, or screen/topic class predictions.

## Method

DreamStruct is a three-phase synthetic data generation pipeline: (1) Ideation uses an LLM (GPT-4) with design principles and few-shot human-written examples to produce diverse design concept descriptions; (2) Generation prompts the LLM to write HTML code where target annotations are embedded as semantic attributes (e.g., data-type="text" for element recognition, <meta name="screentype"> for classification, alt text for image placeholders), with chart libraries (Chart.js, Chartist.js) for complex graphical elements; (3) Production replaces image placeholders via Bing Search API or DALL-E, applies heuristic post-processing (background removal, dimension fixing), and filters low-quality samples using a CLIP score threshold of 0.3. The resulting datasets (DreamSlides: 10,053 samples; DreamUI: 9,774 samples) are used to train or pretrain standard vision backbones (CenterNet2, Deformable-DETR, EfficientDet) for detection and vision-language models (LLaVA-1.5-13B, Qwen-VL-7B) for captioning and classification, with a two-stage pretrain-then-finetune strategy for UI tasks to bridge the synthetic-to-real distribution gap.

## Results

For slide element recognition, models trained on synthetic slides achieve 55.3% mAP versus 44.3% mAP for models trained on the full human-annotated FitVid set (+11.0% absolute), peaking at 64.4% mAP with 2× synthetic data. For UI element recognition, pretraining on synthetic UIs followed by finetuning on just 50 human-annotated samples yields 52.4% mAP versus 47.2% mAP without pretraining (+5.2%). For image classification (Table 2), LLaVA fine-tuned on synthetic slides reaches 0.686 accuracy versus 0.462 zero-shot and 0.335 with human-annotated data; Qwen-VL on synthetic UIs reaches 0.558 versus 0.382 zero-shot and 0.303 human-annotated. For image captioning, the synthetic-data-finetuned LLaVA achieves 77.9% pairwise win rate over the Jobin et al. fine-tuned baseline on slides and 64.8% over Pix2Struct/Screen2Words on UIs.

## Baselines & Comparisons

Against LLaVA zero-shot [47], the synthetic-data-finetuned model wins decisively on all three tasks: 97.3% pairwise win rate on slide captioning, 99.2% on UI captioning, and +22.4 pp classification accuracy on slides (0.686 vs 0.462) and +15.0 pp on UIs (0.545 vs 0.395). Against Qwen-VL zero-shot [7], the synthetic-data-finetuned variant similarly dominates: +21.0 pp on slide classification (0.672 vs 0.473) and +17.6 pp on UI classification (0.558 vs 0.382). Against the Jobin et al. [35] baseline (LLaVA fine-tuned on existing human-written slide descriptions), the proposed method achieves a 77.9% pairwise win rate on slide captioning, indicating substantially more informative and accurate descriptions. Against Pix2Struct [42] fine-tuned on the Screen2Words dataset [73], the proposed method wins 64.8% of pairwise comparisons on UI captioning. In all cases, the synthetic-data-finetuned open-source models (LLaVA-13B, Qwen-VL-7B) approach but do not surpass the proprietary GPT-4V (9.3% gap on slides, 4.7% on UIs for classification; 31.6% and 37.3% win rates for captioning), demonstrating that synthetic code-based data generation narrows the gap between open and closed models.

## Relation to Prior Work

DreamStruct repurposes the LLM-to-HTML code generation paradigm (related to WebSight and pix2code/code2pix work) for a fundamentally different purpose: producing task-specific labeled training data rather than translating between pixels and code. It departs from the dominant paradigm in structured visual understanding—manual collection and annotation of real slides (SpaSe, WiSe, FitVid) and UIs (RICO, VINS, WebUI)—by inverting the pipeline: starting from abstract design specifications and generating both the visual and its ground-truth labels simultaneously. The method also builds on the broader synthetic-data-for-representation-learning tradition (sim-to-real, diffusion-model synthetic data) but applies it to the underexplored domain of structured, layout-rich visuals where labels are inherently tied to code semantics.

## Why It Matters / Open Questions

The paper demonstrates that code-embedded labels can substitute for labor-intensive human annotation at scale, enabling open-source VLMs (LLaVA-13B, Qwen-VL-7B) to approach proprietary model performance (GPT-4V, Gemini) on structured visual tasks. The released datasets (DreamSlides: 10K, DreamUI: 9.7K) fill a gap where high-quality public benchmarks are scarce. Key open questions include whether the approach generalizes to more complex or multi-page layouts, how to resolve the distributional mismatch between synthetic and real-world visuals (e.g., the 'upper task bar' underrepresentation), and whether the code-generation quality issues (invalid CSS properties, element occlusion) can be systematically mitigated with reward-based filtering. The paper also raises legitimate concerns about misuse for misleading content generation and the accessibility risks of deploying imperfect models for blind users.
