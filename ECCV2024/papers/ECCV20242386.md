## Problem

Automating 3D graphics design in Blender requires understanding the visual consequences of programmatic edits, which pure LLMs cannot perceive. Prior task-specific methods (e.g., material synthesis) are not generalizable across design workflows, and existing Blender agents like BlenderGPT operate without visual feedback, producing shallow edits that poorly align with user intent. This paper addresses the gap by leveraging vision-language models to close the loop between program edits and their rendered visual outcomes.

## Input / Output

The system takes a Blender workspace decomposed into a base .blend file and one or more task-specific Python programs (e.g., one per material shader graph, one per lighting rig), along with a user intention expressed as free-form text and/or a reference image. It outputs an edited Python program that, when executed on the base file via Blender's Python API, produces a rendered image satisfying the intention. Programs are kept short and task-scoped to stay within VLM context limits, and the visual imagination module can synthesize an additional reference image from text-only prompts to ground abstract descriptions.

## Method

BlenderAlchemy performs iterative visual program search using two GPT-4V-based modules: an edit generator G that proposes b program variants per iteration, and a state evaluator V that selects the best variant via a pairwise tournament (O(log b) queries) comparing rendered outputs against the user intention. Three key mechanisms improve search stability and quality: (1) hypothesis reversion, which retains the prior best candidate as a fallback to prevent divergence; (2) alternating between 'tweak' edits (adjusting numerical parameters within the program's neighborhood) and 'leap' edits (structural changes like adding new shader nodes), enforced softly via in-context prompting; and (3) visual imagination, where DALL-E 3 generates a reference image from the text prompt to provide concrete visual grounding for both G and V. The entire pipeline is zero-shot, requiring no task-specific training, and can be extended to multi-program scenes (e.g., simultaneous lighting and material editing) by running independent (G, V) pairs in parallel.

## Results

On the text-based procedural material editing task, BlenderAlchemy achieves a CLIP ViT-B/32 score of 28.2 and ViT-L/14 score of 24.0, outperforming BlenderGPT (25.2 and 21.1 respectively). Ablations show that removing all visual components (-Vision) still yields a marginal improvement over BlenderGPT (25.7 / 21.8), while adding vision to the state evaluator alone (-Vision G) provides a larger gain (27.8 / 23.4). In a user preference study with 592 Mechanical Turk comparisons across 32 text prompts, BlenderAlchemy is preferred over Paint3D 73% of the time and over TEXTure 56% of the time.

## Baselines & Comparisons

Against BlenderGPT, BlenderAlchemy wins on both CLIP similarity metrics (ViT-B/32: 28.2 vs. 25.2; ViT-L/14: 24.0 vs. 21.1), with the gap widening when visual components are included. Qualitatively, BlenderGPT produces shallower, more simplistic edits that fail to capture nuanced prompt details (e.g., the 'sharp digital angles' in a camouflage material). In the user preference study, BlenderAlchemy is preferred over Paint3D 73% of the time, a substantial margin, and over TEXTure 56% of the time, a more modest but still clear win. Notably, even the no-vision ablation (-Vision) slightly outperforms BlenderGPT, suggesting the iterative multi-hypothesis search structure itself provides value beyond visual grounding. The paper also reports that in 71% of comparisons, human raters agree with the visual evaluator's selection, validating the evaluator's alignment with human preferences.

## Relation to Prior Work

This paper extends the Tree-of-Thoughts paradigm [57] from text-only program synthesis to the visual domain, where program edits must be evaluated by their rendered visual consequences rather than unit tests. It departs from prior Blender AI agents (BlenderGPT, 3D-GPT, L3GO) that rely solely on language to reason about edits, by introducing a closed visual feedback loop with a VLM-based state evaluator and a text-to-image 'visual imagination' module (DALL-E 3) that bridges abstract user descriptions to concrete visual targets. The iterative multi-hypothesis search with hypothesis reversion and alternating tweak/leap edits draws on LLM program-synthesis literature but is specifically adapted to the high-sensitivity, low-structure nature of visual programs where small numerical changes produce large visual differences.

## Why It Matters / Open Questions

This is the first proof-of-concept demonstrating that VLMs can drive general-purpose 3D graphics editing (materials, geometry, lighting) through iterative visual program refinement, opening a path toward automating hours of tedious Blender work for millions of 3D designers. Key limitations include reliance on expensive proprietary APIs (GPT-4V, DALL-E 3), modest quantitative gains over baselines (CLIP ViT-B/32: 25.2→28.2), and demonstration only on relatively simple editing tasks. Open questions include whether the approach scales to complex multi-object scenes, whether open-source VLMs can substitute, and how to reduce the computational cost of the iterative search. The finding that the iterative search structure itself (even without vision) outperforms single-pass approaches suggests the search architecture may be the more transferable contribution.
