## Problem

Online vectorized map perception relying solely on onboard sensors is vulnerable to occlusion, adverse weather, and poor lighting, yet existing complementary-information approaches require costly external data (SD maps, satellite imagery) or only short-term temporal context. This paper asks whether a low-cost, self-maintained historical map—constructed entirely from past online predictions—can provide the persistent prior information needed to improve robustness without any additional data source.
![Teaser figure](../imgs/ECCV20240456/cropped_page2_idx0.webp)

## Input / Output

The method consumes 6–7 surrounding RGB camera images, a retrieved local rasterized map (a binary semantic mask of shape H×W×3 at 0.3 m resolution covering a 60 m × 30 m perception range), and the ego-pose (rotation and translation) for coordinate alignment. It outputs vectorized map elements as 20 sequential 2D points per instance across three categories (lane divider, pedestrian crossing, road boundary), and simultaneously updates a global rasterized map stored as 8-bit unsigned integers (~1 MB per km). The local map is downsampled to 0.6 m resolution before query initialization to control memory.

## Method

HRMapNet maintains a global rasterized map using a simple occupancy-grid update rule (+S⁺ for positive, −S⁻ for negative observations) and retrieves a local patch via ego-pose transformation. Two plug-in modules exploit this local map: (1) a BEV feature aggregation module that places additional BEV queries at positions where the local map indicates map elements, projects them onto images through spatial cross-attention to extract supplementary features, and fuses them with the original BEV features via element-wise addition, concatenation with the binary mask, and a convolution; (2) a query initialization module that encodes each valid position in the downsampled local map as a map prior embedding (learnable position embedding + linearly projected label embedding), then lets base DETR-style queries attend to these priors via cross-attention before entering the original decoder layers. The framework is modality-agnostic and integrates directly into existing pipelines (MapTRv2, StreamMapNet) without altering their prediction heads or loss functions; during training and testing the global map starts empty and is updated incrementally from the model's own predictions.

## Results

On nuScenes (24 epochs), HRMapNet integrated with StreamMapNet achieves 66.3 mAP (+5.9 over baseline) and with MapTRv2 achieves 67.2 mAP (+5.7 over baseline), outperforming all single-frame and temporal baselines. On Argoverse 2, HRMapNet improves StreamMapNet by +2.8 mAP (64.3) and MapTRv2 by +4.0 mAP (68.3). On the harder new-split benchmarks (no location overlap between train/val), HRMapNet still gains +3.2 mAP on nuScenes and +3.4 mAP on Argoverse 2. Inference speed remains practical at 21.1 FPS (StreamMapNet) and 17.0 FPS (MapTRv2) on a single A100 GPU.

## Baselines & Comparisons

HRMapNet outperforms all eight baselines on both datasets. Against single-frame methods (VectorMapNet 40.9, MapTR 47.3, PivotNet 57.6, BeMapNet 59.8 mAP on nuScenes), HRMapNet leads by 6–25 mAP, confirming that historical map priors provide far more value than any single-frame improvement. Against the SDMap-augmented P-MapNet (49.4 mAP), HRMapNet gains +16.9 mAP without requiring any external map data. Against the temporal method SQD-MapNet (63.9 mAP on nuScenes, 63.3 on Argoverse 2), HRMapNet wins by +2.4 and +1.0 mAP respectively, because it leverages all past predictions rather than only short-term temporal context. Most notably, HRMapNet improves its two host backbones—StreamMapNet by +5.9 mAP and MapTRv2 by +5.7 mAP (24 epochs) or +4.9 mAP (110 epochs)—while retaining near-real-time inference (17–21 FPS), demonstrating that the historical rasterized map is a drop-in complement that does not sacrifice speed.

## Relation to Prior Work

HRMapNet extends the DETR-based online vectorized map perception paradigm (MapTR, MapTRv2) and the temporal fusion approach of StreamMapNet by introducing a fundamentally different source of complementary information: a globally maintained historical rasterized map. Rather than relying on short-term temporal context (StreamMapNet, SQD-MapNet) or external data like SD maps (P-MapNet), the paper borrows the occupancy-grid-mapping update rule from classical robotics to accumulate all past prediction results into a persistent map. The two proposed modules—BEV feature aggregation and query initialization—plug into the existing encoder-decoder architecture without modifying the base method's prediction head or training loss, making the framework a drop-in enhancement for any DETR-style vectorized map perception pipeline.

## Why It Matters / Open Questions

The practical significance lies in the memory efficiency (120 MB vs. 11 GB for BEV-feature-based map priors like NMP) and the crowdsourcing potential: a fleet of vehicles could collectively maintain a global rasterized map, dramatically improving each vehicle's perception without requiring offline HD map construction. The paper's limitation is the deliberately simple map maintenance strategy (fixed S+/S− thresholds), leaving open questions about handling map staleness, conflict resolution between vehicles, and more principled uncertainty-aware updating. The robustness to localization error (0.1 m translation, 0.01 rad rotation) is reassuring for deployment, but the method's dependence on ego-pose accuracy remains a practical constraint.
