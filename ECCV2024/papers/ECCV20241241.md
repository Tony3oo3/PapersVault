## Problem

Sparse query-based multi-view 3D detectors improve efficiency in the 3D decoder but still use ViT backbones that process all image tokens uniformly, making the backbone the dominant inference bottleneck. Existing token compression methods are designed for 2D tasks and lack 3D-aware priors, leading to sub-optimal foreground/background separation when applied to 3D detection with complex motion transformations.
![Teaser figure](../imgs/ECCV20241241/cropped_page1_idx0.webp)

## Input / Output

The method consumes multi-view camera images (6 cameras, 360° FOV at 10 Hz), history object queries from prior frames (content embeddings and 4D homogeneous reference points with velocity), and ego transformation matrices for temporal alignment. It produces standard 3D detection outputs (bounding boxes, class labels, velocity) while the keeping ratio ρ (e.g., 0.7/0.5/0.5 for Fast, 0.5/0.4/0.3 for Faster) controls the speed-accuracy tradeoff per transformer block. The method is plug-and-play: it wraps around an existing ViT backbone and sparse 3D decoder without modifying the decoder.

## Method

ToC3D introduces two components into each ViT block. First, the Motion Query-guided Token Selection Strategy (MQTS) temporally aligns history object queries to the current ego-frame via ego transformation and conditional layer normalization (encoding velocity and time-difference as affine coefficients), then computes per-token importance scores through attention between aligned query embeddings and image tokens, selecting top-k salient tokens. Second, the Dynamic Router sends salient tokens through full transformer blocks while redundant tokens pass through an identity layer; a single bridge token (importance-weighted average of redundant tokens) is appended to the salient set so that background information can still flow into foreground tokens via attention. History queries are sampled by confidence score to avoid bias from background-corresponding queries, and importance scores are updated only at selected layers to reduce overhead. The key insight is extending the sparse-query philosophy from the 3D decoder to the backbone itself, using 3D motion-aware history queries as high-quality foreground priors for token compression.

## Results

On nuScenes val with ViT-B, ToC3D-Fast matches StreamPETR's NDS (55.2% vs 55.4%) and mAP (46.0% vs 45.8%) while reducing backbone inference time by 17.5% (70.3 ms vs 85.2 ms). ToC3D-Faster achieves 54.9% NDS and 45.3% mAP with a 30.5% backbone speedup (59.2 ms). With ViT-L, ToC3D-Faster reaches 60.5% NDS and 51.3% mAP at 209.0 ms backbone time (−28.0%), and at the larger 800×1600 resolution achieves 61.9% NDS with a 35.3% backbone speedup (791.0 ms vs 1222.4 ms).

## Baselines & Comparisons

Against the primary baseline StreamPETR [36], ToC3D-Fast nearly matches NDS and mAP (≤0.4% drop) while cutting backbone time by 12.8–17.5%; ToC3D-Faster trades ≤0.9% NDS for 28–30.5% backbone speedup. Compared to dense BEV methods (BEVDet, BEVDepth, SOLOFusion, all R50), ToC3D-Faster with ViT-B achieves 54.9% NDS vs. 37.9–53.4%, outperforming all three while running at a comparable or faster whole-pipeline speed (85.0 ms vs. 59.9–87.7 ms). Against sparse query-based methods at larger resolution (DETR3D, BEVFormer, Sparse4D, all R101), ToC3D-Faster with ViT-L achieves 60.5% NDS vs. 43.4–54.1%, a 6.4–17.1% NDS advantage, and runs at a similar whole-pipeline speed to Sparse4D (237.2 ms vs. 232.6 ms). Versus 2D token compression methods (DynamicViT, SparseDETR) applied to the same StreamPETR pipeline, ToC3D-Faster (ViT-L) gains 1.0–1.2% NDS and 1.9–2.0% mAP at the same speed level, confirming the benefit of 3D motion-aware priors. For generalization, applying ToC3D-Faster to Sparse4Dv2 [21] (ViT-L) preserves the exact NDS (58.8%) while reducing backbone time by 25.9%, demonstrating plug-and-play effectiveness across pipelines.

## Relation to Prior Work

This paper sits at the intersection of two research threads: sparse query-based multi-view 3D detection (StreamPETR, Sparse4D, PETR) and token compression for Vision Transformers (DynamicViT, SparseDETR, Evo-ViT). It departs from prior token compression work by introducing 3D motion-aware priors—specifically, history object queries carrying velocity and ego-motion information—to guide which image tokens are salient, rather than relying on purely 2D score-based or attention-based heuristics. Conceptually, it extends the sparse-query philosophy from the 3D decoder (where only object-centric queries are processed) to the ViT backbone itself, treating the backbone as another stage where foreground/background asymmetry can be exploited.

## Why It Matters / Open Questions

As ViT backbones become the default for high-performing 3D detectors, their computational cost becomes the dominant latency bottleneck; ToC3D offers a plug-and-play remedy that delivers ~30% backbone speedup with under 1% NDS loss, making ViT-based detectors competitive with ResNet-based ones in inference time while retaining accuracy advantages. The method's generality (validated on both StreamPETR and Sparse4Dv2) suggests it can be adopted broadly across the sparse-query 3D detection ecosystem. Key limitations include the dependence on temporal sequences (history queries) and the need for retraining when keeping ratios change, leaving open the question of whether dynamic, training-free compression ratios can be achieved without sacrificing stability.
