## Problem

Existing 3D open-vocabulary scene understanding methods (e.g., OpenScene, PLA-family, OpenMask3D) require well-aligned 2D posed images, depth maps, and camera models as input alongside 3D point clouds. In many real-world settings—LiDAR-only captures, multi-sensor registrations, or CAD-derived point clouds—these 2D images are unavailable, limiting deployment. This paper asks whether 3D open-vocabulary understanding can be performed using only 3D point cloud input, without any aligned 2D imagery.

## Input / Output

The method takes a colored 3D point cloud and a free-form text query as input, requiring no 2D images, camera poses, or depth maps. It outputs class-agnostic 3D instance segmentation masks with assigned category labels, which can be converted to axis-aligned 3D bounding boxes for detection. The text query can range from simple class names to complex reasoning-based descriptions (e.g., 'furniture that is capable of producing music') when paired with LLM-powered 2D models like LISA. The 2D detector backbone (Grounding DINO, ODISE, LISA) is swappable at inference time without any retraining of the 3D components.

## Method

OpenIns3D follows a three-stage 'Mask-Snap-Lookup' pipeline. The Mask stage uses a modified Mask3D backbone (with classification heads removed) to generate class-agnostic 3D mask proposals, augmented by a learned IoU-scoring module and multi-criteria filtering (score threshold, SAM-style stability check, minimum point count) to discard low-quality proposals. The Snap stage renders a small number (8–24) of synthetic scene-level images at three scales (global, corner, wide-angle) using calibrated camera extrinsics and intrinsics, then feeds them into a 2D open-vocabulary detector to produce a Class Lookup Table (CLT) of detected objects with pixel locations. The Lookup stage projects each 3D mask onto the rendered images via Mask2Pixel maps and searches the CLT by IoU overlap to assign category names, aggregating multi-view evidence; a Local Enforced Lookup (LEL) re-detects cropped regions for any remaining unclassified masks. This design decouples 3D mask generation from 2D language understanding, enabling seamless swapping of 2D backbones and inheriting their open-vocabulary and reasoning capabilities without retraining.

## Results

On zero-shot object recognition (ScanNetv2), OpenIns3D achieves 60.8% top-1 accuracy, surpassing the 1-billion-parameter Uni3D foundation model (45.8%) by 15 points and CLIP2 (38.5%) by 22.3 points. For open-vocabulary instance segmentation on S3DIS (8/4 novel split), OpenIns3D reaches 37.0 AP50 / 39.3 AP25, outperforming Open3DIS (26.3 AP50) and the 3D-input-only baseline Mask3D+PointCLIP (5.4 AP50) by large margins. On open-vocabulary object detection (ScanNet), OpenIns3D achieves 43.7 mean AP25, exceeding the previous best L3Det (24.6) by 19.1 points. On the outdoor STPLS3D dataset, OpenIns3D improves AP from 2.1 (PointCLIPv2) to 11.4, a 9.3-point gain.

## Baselines & Comparisons

OpenIns3D decisively outperforms all 3D-input-only baselines: on S3DIS (8/4 split), it achieves 37.0 AP50 versus 5.4 for Mask3D+PointCLIP (+31.6) and 26.3 for Open3DIS (+10.7); on ScanNetv2 (all-novel split), it reaches 28.7 AP50 versus 4.5 for Mask3D+PointCLIP (+24.2). Against the 1B-parameter Uni3D foundation model on ScanNetv2 recognition, OpenIns3D leads by 15.0 points (60.8 vs 45.8). On open-vocabulary object detection (ScanNet), OpenIns3D (43.7 mean AP25) surpasses L3Det (24.6) by 19.1 and FM-OV3D (21.5) by 22.2. On the Replica dataset, OpenIns3D (13.6 AP) edges out OpenMask3D (13.1 AP) despite not using aligned 2D images, though OpenMask3D retains a lead on AP25 (24.2 vs 19.7). On ScanNet200, OpenIns3D (8.8 AP) trails OpenMask3D (15.4 AP) which uses 2D inputs, but outperforms all 3D-only baselines (OpenScene 3D Distill: 4.8 AP), with the gap attributed to poor reconstruction quality of small objects in ScanNet200.

## Relation to Prior Work

OpenIns3D builds on Mask3D for class-agnostic 3D mask proposal generation but fundamentally departs from the dominant paradigm in 3D open-vocabulary understanding, which relies on well-aligned 2D posed images, depth maps, and camera parameters (as in OpenScene, PLA-family, CLIP2Scene, OpenMask3D, and Open3DIS). Instead of distilling 2D language-aligned features into 3D or cropping individual objects from aligned images, OpenIns3D synthesizes scene-level images directly from the point cloud and uses a Mask2Pixel-guided lookup table to bridge 2D detections back to 3D masks. The 2D open-vocabulary detector (Grounding DINO, ODISE, or LISA) is treated as a plug-and-play component, decoupling 3D mask quality from 2D language understanding and eliminating the need for retraining when swapping 2D backbones.

## Why It Matters / Open Questions

By removing the requirement for aligned 2D images, OpenIns3D significantly broadens the deployment scenarios for 3D open-vocabulary understanding—LiDAR-only point clouds, multi-sensor registrations, and CAD/simulation data become directly usable without companion imagery. The plug-and-play architecture means the system can automatically benefit from rapid advances in 2D open-vocabulary detection without any 3D retraining, a practical advantage over feature-distillation approaches. Key limitations remain: performance degrades on small or poorly reconstructed objects (notably in ScanNet200 tail classes), the method still requires RGB information on points, and the multi-view rendering, while efficient, introduces a domain gap between synthetic renders and natural images that 2D models must tolerate. Open questions include whether the approach extends to purely geometric (colorless) point clouds and how it scales to very large outdoor scenes beyond the 50m×50m patches used here.
