## Problem

LLM-driven embodied agents in open-world environments like Minecraft rely almost exclusively on textual grounding for perception, which limits their ability to naturally convey spatial and visual concepts such as crafting recipes or block identification. The integration of multimodal (vision + text) inputs into LLM-based agents operating in open-ended, interactive environments remains largely under-explored, and existing text-only agents require laborious prompt engineering to align with environmental context.
![Teaser figure](../imgs/ECCV20240199/cropped_page1_idx0.webp)

## Input / Output

The system consumes first-person perspective images or short video clips from the Minecraft viewport, structured agent state variables (health, inventory, position), and a free-form task instruction string. The vision encoder (EfficientFormerV2-S0) maps visual frames into a fixed set of visual tokens in text space, which are concatenated with tokenized agent state and task tokens to form a unified input sequence for the LLM. The output is a sequence of low-level textual action steps that are then resolved into executable code snippets via cosine-similarity retrieval against a 210-entry skill-code database, producing concrete Mineflayer API calls.

## Method

STEVE decomposes the agent into three tightly coupled modules: a vision perception stage that encodes visual frames and textual state into a shared token space, a language instruction stage built on STEVE-13B (LLaMA-2 13B fine-tuned with LoRA on 20K Minecraft QA pairs) that internally runs four specialized sub-agents (Planner, Critic, Curriculum, Describer) for iterative reasoning and step-by-step task decomposition, and a code action stage that retrieves matching skill scripts from a vector-indexed database. Training follows a two-stage protocol: an offline warm-up on single-round QA pairs to establish instruction-following capability, followed by online fine-tuning in the MineDojo/Mineflayer simulation where GPT-4 serves as an expert teacher generating ground-truth instructions for the same visual and state inputs. The system further incorporates curriculum learning with episodic memory and a chain-of-summarization mechanism to enable continuous, gradient-free skill acquisition across progressively harder tasks, allowing the agent to retain and compress gameplay experience without parameter updates.

## Results

On the continuous block search task, STEVE finds 67 diamond blocks in 100 iterations (vs. 26 for Voyager and 7 for AutoGPT) and locates 10 diamonds in just 14 iterations (vs. 35 for Voyager), a 2.5× speedup. On tech tree mastery, STEVE unlocks wooden, stone, and iron tools in 4, 8, and 15 iterations respectively, achieving 1.5×, 1.4×, and 1.3× faster than Voyager, and is the only method to reliably complete the diamond tool tier (106±12 iterations, 3/3 success). On knowledge QA, STEVE-13B achieves an overall score of 8.12, surpassing GPT-4 (8.04) and Llama2-13B (6.89) across all six Minecraft knowledge categories.

## Baselines & Comparisons

STEVE decisively outperforms AutoGPT on all tasks: 2.5× faster block search (67 vs. 7 blocks in 100 iterations) and 9–23× faster tech tree progression, with AutoGPT completely failing the diamond tool tier. Against Voyager, STEVE wins on block search (14 vs. 35 iterations to find 10 diamonds) and on the first three tech tree levels (1.3–1.5× fewer iterations), while matching Voyager on the diamond tool tier in raw iterations (106 vs. 102) but with a critical reliability advantage: STEVE succeeds 3/3 trials versus Voyager's 1/3. On knowledge QA, STEVE-13B (8.12) narrowly edges out GPT-4 (8.04) and substantially outperforms the base Llama2-13B (6.89), demonstrating that domain-specific fine-tuning on STEVE-21K yields Minecraft-specialized knowledge that surpasses a general-purpose frontier model.

## Relation to Prior Work

STEVE extends the line of LLM-driven Minecraft agents (Voyager, GITM, DEPS, Plan4MC) that rely exclusively on textual grounding for environmental perception, by integrating a lightweight vision encoder (EfficientFormerV2-S0) that encodes first-person visual input into the same token space as agent state and task text. The language backbone is derived from LLaMA-2-13B fine-tuned via LoRA on Minecraft-specific QA pairs, and the action execution layer borrows the retrieval-augmented skill-database paradigm from Voyager but operates on a smaller, manually curated set of 210 code snippets. The curriculum learning and chain-of-summarization memory mechanism draws from lifelong learning strategies in reinforcement learning, applied here in an in-context, gradient-free manner.

## Why It Matters / Open Questions

STEVE demonstrates that a compact, domain-specific multimodal agent can match or exceed GPT-4 on Minecraft-specific knowledge tasks while being substantially more cost-effective, suggesting that targeted fine-tuning of smaller open-source models is a viable path for embodied agents. The STEVE-21K dataset (vision-environment pairs, QA pairs, skill-code pairs) provides a reproducible resource for the community. However, the evaluation is confined to a single game environment with a limited skill database (210 scripts), and the vision encoder is a small model trained on only 600 video clips, raising open questions about generalization to other 3D environments, scaling the skill library, and whether the vision component's contribution would hold under more diverse or adversarial visual conditions.
