## Problem

Federated tuning of pre-trained foundation models on heterogeneous clients is hindered by a feature imbalance problem: depth-based methods assign only the initial layers to resource-constrained clients, so deeper layers are trained exclusively by a small subset of resource-rich clients while shallow layers benefit from all clients. Width-based pruning alternatives disrupt the pre-trained layer structure and cannot be applied to foundation models. The paper formalizes this as the Heterogeneous Client Federated Tuning (HeFT) task and seeks a simple allocation strategy that lets every layer of the global model learn from all clients.

## Input / Output

The method takes a pre-trained foundation model (ViT-Base or MLP-Mixer-B16, 12 layers, 224×224 input) and a set of N heterogeneous clients, each holding private RGB images (DomainNet 345-class or NICO++ 60-class) and capable of fine-tuning only L_n out of L=12 layers. Each client outputs updated LoRA adapter parameters for its assigned sublayers, which the server aggregates into the corresponding layers of the global model. The final output is a single fine-tuned global model that maps 224×224 images to class labels, with the unusual property that no single client ever sees or trains the complete model.

## Method

FedRA replaces the fixed depth-based layer assignment with a random allocation strategy: in each communication round, the server generates a binary allocation matrix M ∈ {0,1}^{N×L} where row n has exactly L_n ones, and each client receives a random subset of L_n layers (with their frozen pre-trained weights and trainable LoRA adapters) to form its local model. After local fine-tuning, the server performs a weighted average of LoRA parameters per layer, restricted to the clients that were assigned that layer in the current round. Because the allocation is random, every layer is expected to be trained by a diverse set of clients over T rounds, eliminating the feature imbalance that plagues depth-based methods. The approach requires no additional loss terms, no architectural modifications, and gracefully handles the extreme case where no client can accommodate the full model by either carrying forward untrained layers or constraining the allocation matrix to cover all layers.

## Results

Under the feature-skew setting (Table 1), FedRA achieves average accuracies of 63.90% (DomainNet + ViT), 53.37% (DomainNet + MLP-Mixer), 86.48% (NICO++ + ViT), and 77.57% (NICO++ + MLP-Mixer), outperforming the best depth-based baselines by 5.3–9.5 percentage points. Under the more challenging feature&label-skew setting (Table 2), FedRA still leads with 61.61% (DomainNet + ViT) and 85.44% (NICO++ + ViT), maintaining a 2.4–4.4 point advantage. In extreme heterogeneous scenarios where all clients have fewer layers than the server (Table 3), FedRA's advantage grows dramatically, e.g., 70.38% vs. 20.58% for InclusiveFL when all clients use only 6 layers (ViT on NICO++).

## Baselines & Comparisons

FedRA consistently outperforms both depth-based baselines across all four dataset–model combinations. Against InclusiveFL [25], FedRA gains +7.93 pp on DomainNet (ViT), +9.52 pp on DomainNet (MLP-Mixer), +5.84 pp on NICO++ (ViT), and +8.19 pp on NICO++ (MLP-Mixer). Against DepthFL [18], the margins are +8.90 pp, +7.84 pp, +6.69 pp, and +5.29 pp respectively. The gap is most pronounced on DomainNet, where the quickdraw domain (highly stylistically distinct) causes InclusiveFL and DepthFL to drop to ~20–22% accuracy while FedRA reaches 25.41% (ViT) and 16.35% (MLP-Mixer). In the extreme scenario where no client can hold the full 12-layer model (Table 3), InclusiveFL collapses to 8.00% average (4-layer clients, ViT) while FedRA still achieves 13.54%, and the gap widens to ~50 pp at 6-layer clients. Under dynamic heterogeneity (Table 5), the advantage narrows to ~1 pp because random layer assignment per round already gives each layer access to all clients, confirming that the core benefit of FedRA is ensuring balanced layer–client coverage.

## Relation to Prior Work

This paper carves new ground at the intersection of federated tuning (fine-tuning pre-trained foundation models via FL) and heterogeneous client FL, a combination the authors argue has not been addressed. It departs from depth-based heterogeneous FL methods (InclusiveFL, DepthFL) by identifying a 'feature imbalance' problem—higher layers receive training signal from only a few resource-rich clients—and replaces their fixed prefix allocation with per-round random layer assignment. The approach repurposes LoRA adapters as the trainable parameters and requires no architectural modification or auxiliary loss, distinguishing it from both width-pruning methods (which destroy pre-trained layer structure) and depth-based methods (which require extra classifiers or distillation losses).

## Why It Matters / Open Questions

FedRA's extreme simplicity (a random binary matrix per round, no extra loss, no model surgery) makes it immediately applicable to any Transformer-based foundation model in real edge-computing deployments where device capabilities vary. The ability to function when no single client can host the full model is practically important for very large foundation models. Open questions include whether the random allocation strategy transfers to language models or multimodal settings, whether the convergence guarantee (which relies on residual connections) holds for architectures without them, and whether the per-round randomness introduces unnecessary variance compared to structured (e.g., cyclic) allocation schedules. The baselines (InclusiveFL, DepthFL) were designed for training-from-scratch FL rather than federated tuning, so a stronger comparison against methods adapted specifically for this setting would strengthen the claims.
