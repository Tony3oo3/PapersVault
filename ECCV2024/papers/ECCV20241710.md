## Problem

General-purpose MLLMs like Ferret and Shikra are designed for natural images and degrade on UI screens due to elongated aspect ratios and small objects of interest (icons, texts occupying <0.1% of the screen). Existing UI-focused approaches either treat entire screens as singular inputs, support only a single bounding box, or fail to cover the full spectrum of referring, grounding, and reasoning capabilities needed for practical UI automation.
![Teaser figure](../imgs/ECCV20241710/cropped_page1_idx0.webp)

## Input / Output

The model consumes raw mobile UI screen pixels (iPhone and Android at resolutions ranging from 828×1792 to 2560×1440) along with a text instruction and an optional regional reference in point, box, or free-form scribble format. For grounding tasks, the model outputs precise bounding box coordinates; for referring tasks it outputs classification labels or OCR text; for advanced tasks it produces open-ended multi-turn conversations or screen-level descriptions. Notably, no external detection module or structured screen-view file is required—the model is self-sufficient on raw pixels.

## Method

Ferret-UI extends Ferret (CLIP-ViT-L/14 encoder + Vicuna decoder + spatial-aware visual sampler) with an 'any-resolution' (anyres) mechanism that partitions each screen into two sub-images using a 1×2 or 2×1 grid selected to match the original aspect ratio, then encodes each sub-image independently and concatenates the resulting features with the global image embedding so the LLM receives both full-screen context and magnified local detail. Training uses 250K instruction-following samples spanning seven elementary tasks (OCR, icon recognition, widget classification, widget listing, find text/icon/widget) generated from a pixel-based UI detector's outputs, plus four advanced tasks (detailed description, conversation perception, conversation interaction, function inference) synthesized by GPT-4 from detection metadata. The decoder and projection layer are updated while the vision encoder remains frozen, trained for 1–3 days on 8 A100 GPUs depending on whether anyres is active.

## Results

On the Spotlight public benchmark, Ferret-UI-anyres achieves CIDEr 115.6 on screen2words and 140.3 on widget captions, surpassing Spotlight (106.7, 141.8) on S2W but trailing on TaP (72.9 vs. 88.4 F1). On elementary UI tasks, Ferret-UI-anyres reaches 82.4% on iPhone referring, 81.4% on iPhone grounding, and 83.8% on Android grounding, substantially outperforming GPT-4V (61.3%, 70.3%, 4.7% respectively) and base Ferret (13.3%, 8.6%, 12.9%). On advanced tasks, Ferret-UI-anyres scores 93.9 on iPhone and 70.1 on Android (GPT-4-scored), where GPT-4V leads with 114.3 and 128.2 due to its more verbose responses. The anyres variant boosts iPhone advanced tasks by ~20 points over Ferret-UI-base but slightly degrades Android advanced performance (70.1 vs. 80.5).

## Baselines & Comparisons

Against **Spotlight** [12], Ferret-UI-anyres wins on screen2words (115.6 vs. 106.7 CIDEr) and is competitive on widget captions (140.3 vs. 141.8), but trails on taperception (72.9 vs. 88.4 F1), which the authors attribute to noisy labels. Against **Ferret** [26], Ferret-UI dominates across every task category, e.g., Android grounding jumps from 12.9% to 83.8%, confirming the necessity of domain-specific UI training. Against **GPT-4V** [1], Ferret-UI wins decisively on elementary tasks—most dramatically on Android grounding (83.8% vs. 4.7%) and Android referring (82.4% vs. 37.7%)—but loses on advanced tasks (93.9 vs. 114.3 iPhone; 70.1 vs. 128.2 Android), where GPT-4V's verbose, detail-rich responses are favored by the GPT-4 evaluator. Against **Fuyu** [4], Ferret-UI-anyres outperforms on all four advanced tasks for both platforms (e.g., 93.9 vs. 21.0 on iPhone average). Against **CogAgent** [8], Ferret-UI-anyres leads on iPhone advanced tasks (93.9 vs. 64.9) and narrowly on Android (70.1 vs. 66.8), though CogAgent's Android conversation-interaction score (90.1) exceeds Ferret-UI's (50.2), suggesting CogAgent handles multi-turn interaction better on Android specifically.

## Relation to Prior Work

Ferret-UI extends Ferret's natural-image referring and grounding architecture to the mobile UI domain, incorporating an 'any-resolution' sub-image encoding strategy (inspired by SPHINX, LLaVA-NeXT, and Monkey) to handle the elongated aspect ratios and small widgets characteristic of screens. It departs from prior UI understanding models (Pix2Struct, ILuvUI, CogAgent) that treat screens as monolithic inputs without fine-grained spatial interaction, and from Spotlight, which supports only a single bounding-box reference. The paper positions itself as the first MLLM to unify precise referring, grounding, and open-ended reasoning specifically for mobile UI screens, bridging the gap between general-purpose spatial MLLMs and domain-specific UI parsers.

## Why It Matters / Open Questions

The work provides the first comprehensive benchmark (14 tasks across iPhone and Android) and a practical model that surpasses GPT-4V on elementary UI tasks, offering a self-sufficient alternative to pipelines requiring external detection modules or screen view files. A key limitation is the reliance on a pretrained UI detection model, which caps the model's ability to reason about undetected visual properties (colors, design aesthetics, usability) and creates a bottleneck for generalization. Open questions include whether the any-resolution trade-off (improving iPhone performance while degrading Android) can be resolved, how the approach extends to multi-step navigation and accessibility, and whether the detection-model dependency can be eliminated through end-to-end training.
