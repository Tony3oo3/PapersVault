## Problem

Existing vectorized HD map detection methods (e.g., MapTR, MapTR-V2) treat points within the same line instance as independent and identically distributed, overlooking the strong spatial correlations between inner-instance points. This neglect of inner-instance correlation leads to zigzag or inconsistent point predictions and limits further performance gains in online HD map construction.
![Teaser figure](../imgs/ECCV20240905/cropped_page1_idx0.webp)

## Input / Output

The model consumes multi-camera perspective images (optionally fused with LiDAR via SECOND) that are projected into a bird's-eye-view feature map covering a 30m × 60m region ([-15m,15m] × [-30m,30m]). Output is a set of vectorized road element instances—road boundaries, lane splits, pedestrian crossings, and lane centerlines—each represented as a fixed-length ordered sequence of n_p 2D points (polylines or closed polygons), with per-point class and position predictions. Instances are undirected by default, though directed centerline variants are also evaluated.

## Method

InsMapper builds on the MapTR deformable-DETR framework and introduces three modules that explicitly exploit inner-instance point correlations. First, a hybrid query generation scheme assigns each of N_I·n_p point queries to exactly one instance group (rather than sharing all point queries across instances as in the hierarchical scheme), producing initialized lines with both diversity and inner-instance structure. Second, an inner-instance query fusion module applies self-attention over the n_p queries within each instance before the decoder, enabling precise point-to-point information exchange that refines line initialization. Third, an inner-instance feature aggregation module inserts a masked self-attention layer after the cross-attention in each decoder layer, where the attention mask blocks all inter-instance attention (only intra-instance attention is permitted) and randomly drops inner-instance connections with probability ε for robustness. The framework is modular and can be grafted onto other base architectures (PivotNet, MapTR-V2) without architectural changes.

## Results

On the NuScenes validation set (24 epochs, ResNet-50, camera-only), InsMapper built on MapTR-V2 (InsMapper‡) achieves mAP 53.72 and TOPO 53.00, surpassing MapTR-V2 (51.37 / 51.15) by +2.35 mAP and +1.85 TOPO. With 110 epochs, InsMapper‡ reaches mAP 64.06 and TOPO 64.72, outperforming MapTR-V2 (61.92 / 63.26) by +2.14 mAP and +1.46 TOPO. On Argoverse 2 (6 epochs, R50, camera), InsMapper‡ achieves mAP 65.46 and TOPO 79.26, exceeding MapTR-V2 (63.39 / 77.94) by +2.07 mAP and +1.32 TOPO. Inference speed is comparable to MapTR (7.5 vs. 8.5 FPS).

## Baselines & Comparisons

InsMapper consistently outperforms all five baselines across both datasets. Against MapTR (the base framework), InsMapper gains +5.38 mAP and +4.81 TOPO at 24 epochs on NuScenes, with the largest per-class improvement on pedestrian crossings (+6.44 AP). Against the previous SOTA MapTR-V2, InsMapper‡ improves mAP by +2.35 (24 epochs) and +2.14 (110 epochs) on NuScenes, and by +2.07 mAP on Argoverse 2. Against PivotNet, InsMapper† achieves +2.49 mAP and +2.53 TOPO at 24 epochs. Notably, InsMapper's advantage is most pronounced on the lane centerline class (the hardest element), where InsMapper‡ gains +2.13 AP over MapTR-V2 at 24 epochs. The method also demonstrates generality: the same three modules transfer seamlessly across MapTR, PivotNet, and MapTR-V2 backbones, always yielding improvements without architectural changes.

## Relation to Prior Work

InsMapper extends the DETR-based vectorized HD map detection paradigm established by MapTR and refined by MapTR-V2 and PivotNet, retaining the BEVFormer-style encoder and deformable attention decoder. Its key conceptual departure is the explicit exploitation of inner-instance point correlations—treating points within the same line instance as structurally coupled rather than i.i.d.—which prior methods implicitly ignored. The three proposed modules (hybrid query generation, inner-instance query fusion, inner-instance feature aggregation) are designed as plug-and-play components that can be grafted onto any existing DETR-based HD map framework, positioning the work as a modular refinement rather than a new architecture.

## Why It Matters / Open Questions

The inner-instance correlation insight, while intuitive, had been systematically overlooked in the MapTR lineage, and its exploitation yields consistent ~2 mAP gains across multiple base frameworks and datasets, confirming that structural priors within instances remain underutilized. The demonstrated generality (improvements on MapTR, PivotNet, and MapTR-V2 bases) makes the modules broadly applicable to the growing family of transformer-based HD map detectors. However, the paper remains single-frame and does not address temporal consistency, which is critical for real-world deployment; the authors explicitly flag temporal-consistent vector map detection as future work. The modest absolute gains and the reliance on the DETR paradigm also limit the broader impact beyond this specific task family.
