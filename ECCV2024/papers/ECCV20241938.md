## Problem

Existing 3D part segmentation systems require explicit category names as prompts and cannot interpret implicit, reasoning-based queries such as 'which part of this kettle can be opened to pour water.' No dataset or benchmark exists for evaluating whether a model can reason about object part functions, materials, and spatial relationships to produce the correct segmentation mask, leaving a gap between user intent and system response in 3D perception.
![Teaser figure](../imgs/ECCV20241938/cropped_page1_idx0.webp)

## Input / Output

The method takes a coloured 3D point cloud of a single object and an implicit natural-language query (referencing function, material, colour, shape, location, or concept without naming the part) as input. The point cloud is rasterized into K=10 multi-view RGB images from uniformly distributed camera poses, which are consumed by the vision-language model. The output is a per-point 3D part segmentation mask (assigned at the superpoint level via multi-view voting) paired with a natural-language explanation justifying the chosen region, selected via a view-guided IoU scoring mechanism.

## Method

PARIS3D renders the input point cloud into 10 multi-view images, which are fed alongside the text query into a frozen ViT-H SAM backbone and a LLaVA-13B multimodal LLM fine-tuned with LoRA. The LLM generates both a text explanation and a special <SEG> token; the last-layer embedding of this token is projected through an MLP to form a prompt embedding for a fully fine-tuned SAM-style mask decoder, which produces K 2D segmentation masks. These masks are lifted to 3D by segmenting the point cloud into superpoints and applying a visibility-aware semantic voting scheme across views. Training uses a combined objective of autoregressive cross-entropy for text and BCE+DICE for masks, with explanatory pseudo-labels generated via a distillation pipeline from a teacher model and GPT-3.5-generated diverse instruction templates to improve generalization.

## Results

On the primary reasoning part segmentation task (RPSeg3D test set, 1906 objects), PARIS3D achieves 56.77% overall mIoU (55.94% on normal queries, 57.60% on 3D queries), substantially outperforming the zero-shot LISA-MV baseline (19.08%) and the fine-tuned LISA-MV(ft) baseline (50.78%). In the few-shot 3D part segmentation comparison (45 categories, 8 samples each), PARIS3D reaches 55.1% mIoU on overlapping categories and 59.1% on non-overlapping categories, with per-category peaks of 84.0% (Bottle) and 78.8% (Kitchen Pot). The model also demonstrates strong generalization to real-world LiDAR point clouds with minimal performance drop.

## Baselines & Comparisons

On the novel reasoning part segmentation task, PARIS3D (56.77% test mIoU) outperforms the zero-shot LISA-MV baseline by ~38 points and the fine-tuned LISA-MV(ft) by ~6 points, confirming that 3D-aware instruction tuning with GPT-generated rephrased prompts yields meaningful gains. In the few-shot 3D part segmentation comparison (Table 3, 8 samples/category), PARIS3D (29.7% overall mIoU) is roughly on par with the unified PartSLIP+ single-model variant (29.9%) and beats ACD (23.2%), but trails PointNeXt (40.6%), SoftGroup (38.0%), and Prototype (44.3%). Against the per-category PartSLIP* (59.4%, 45 separate models), PARIS3D underperforms on aggregate, though it matches or exceeds PartSLIP* on individual categories like Bottle (84.0 vs 83.4), Door (68.4 vs 40.8), and Kitchen Pot (78.8 vs 69.6). The paper notes that PartSLIP*'s advantage stems from training 45 independent models, which is impractical for real-world multi-category deployment, whereas PARIS3D operates as a single unified model handling all categories simultaneously.

## Relation to Prior Work

PARIS3D builds directly on LISA's LLM-plus-segmentation-decoder architecture and SAM's ViT-H backbone, repurposing them for 3D part segmentation via multi-view rendering. The 3D-to-2D lifting strategy (superpoint-based semantic voting) draws on PartSLIP's aggregation mechanism and Landrieu's superpoint graphs, while the instruction generation pipeline leverages GPT-3.5 to create diverse implicit queries. The key conceptual departure from prior 3D segmentation work (PointNet++, PartSLIP, OpenMask3D) is the shift from explicit category-name prompts to implicit reasoning queries that require world knowledge, and from LMMs that can converse but not segment (Chat-3D, 3D-LLM) to a unified system that does both.

## Why It Matters / Open Questions

The paper establishes reasoning-based 3D part segmentation as a distinct task and provides RPSeg3D (2,624 objects, 60k+ instructions) as the first dedicated benchmark, which should facilitate future work on implicit-query 3D perception. The small performance gap between explicit and implicit queries (55.94 vs. 57.60 mIoU on test) suggests current LMMs can already handle reasoning-based 3D queries competitively, a useful signal for the field. Open questions include whether the approach extends to instance segmentation (acknowledged limitation), how it scales to full scenes rather than single objects, and whether the multi-view rendering bottleneck (10 views per object) can be reduced without quality loss.
