## Problem

No existing benchmark supports systematic evaluation of LLM planning agents across the full design space of multi-step multi-modal tool use (planning strategy, plan format, and feedback type) with realistic, executable tools. Concurrent benchmarks like TaskBench and ToolEmu use placeholder inputs or LLM-emulated execution, making it impossible to study how execution feedback affects planning quality.
![Teaser figure](../imgs/ECCV20240244/cropped_page1_idx0.webp)

## Input / Output

Each task pairs a natural-language user query with a real multi-modal input (an image from ImageNet or Visual Genome, an audio clip from librispeech, or a text passage from SQUAD/MagicBrush). The planner must produce an ordered sequence of 1–3 tool invocations, where each invocation specifies a tool name and a dictionary of argument names and values; outputs of earlier tools are referenced by subsequent tools via a `<node-id>.key` chaining notation. Plans are expressed in either structured JSON or free-form Python code, and are evaluated on tool-F1, argname-F1, and execution pass rate.

## Method

The m&m's benchmark is constructed via a five-step pipeline: (1) sampling valid tool subgraphs from a directed graph of 33 tools (13 HuggingFace multi-modal models, 11 VisProg image-processing modules, 9 RapidAPI public APIs) where edges encode input/output type compatibility; (2) pairing each subgraph with a real input example matched to the first tool's expected modality; (3) prompting GPT-4 to generate realistic user queries conditioned on the tool sequence and input; (4) producing ground-truth plans with a rule-based program (eliminating hallucination) and mapping them to both JSON and Python code; and (5) human verification by three annotators, yielding 1,565 verified and 882 tool-balanced examples. For evaluation, a modular AutoGen-based agent iteratively generates and refines plans, receiving parsing, verification, or execution feedback. The paper systematically evaluates 10 LLMs (Llama-2/3, Mixtral, CodeLlama, GPT-3.5/4/4o, Gemini-pro) across 2 planning strategies, 2 plan formats, and 3 feedback types, finding that multi-step JSON planning with verification/execution feedback yields the best overall tool-use performance.

## Results

Across 10 LLMs evaluated on m&m's (882 human-verified, tool-balanced examples), GPT-4o achieves the highest tool-F1 (89.28), argname-F1 (90.32), and pass rate (96.37) under multi-step JSON planning with parsing feedback. Multi-step planning consistently outperforms step-by-step planning for all models, with the largest gap (21.8%) observed for GPT-3.5-turbo. Adding verification or execution feedback improves pass rate by up to 20–30% (e.g., Llama-2-7B goes from 28.23% to 46.37%) and argname-F1 by 1–4%, but slightly reduces tool-F1 (<5%) due to over-correction. JSON-format generation yields substantially higher pass rates than code generation across all models, while tool-F1 remains comparable (<3% difference).

## Baselines & Comparisons

As a benchmark paper, m&m's does not propose a single method to compare against prior methods; instead it systematically evaluates 10 LLMs under different planning configurations. Compared to prior tool-planning benchmarks (ToolBench/ToolLLM, ToolEmu, TaskBench, MetaTool), m&m's is the only one providing real multi-modal inputs (images, audio) alongside fully executable tools and supporting both JSON and code plan formats. Among the evaluated LLMs, GPT-4o (89.28 tool-F1, 96.37 pass rate) and GPT-4 (88.46, 97.73) substantially outperform open-source models, with Llama-3-70B (78.73, 92.40) being the strongest open-source model. On planning strategy, multi-step planning beats step-by-step for all 10 models on tool-F1, with the gap shrinking for larger models (e.g., GPT-4 shows only a small difference). On plan format, JSON generation yields markedly higher pass rates than code generation for all models except CodeLlama variants, while tool-F1 differences remain under 3%. Feedback (verification/execution) consistently boosts pass rate by 10–30% for smaller models but provides diminishing returns for GPT-4/GPT-4o, which already exceed 96% pass rate with parsing feedback alone.

## Relation to Prior Work

This paper carves new ground at the intersection of tool-use benchmarks and multi-modal planning. Prior benchmarks (ToolBench, ToolEmu, TaskBench, MetaTool) each addressed parts of the problem—large tool catalogs, emulated execution, or ground-truth plans—but none simultaneously provided real multi-modal inputs, executable tool implementations, human-verified plans, and support for evaluating the full combinatorial design space (planning strategy × plan format × feedback type). The data generation pipeline draws on VisProg's image processing modules and RapidAPI's public APIs, while the evaluation framework builds on AutoGen's multi-agent architecture. Conceptually, the paper departs from the step-by-step planning paradigm popularized by ToolLLM and ReAct by systematically demonstrating that multi-step planning is consistently superior for LLM planners on multi-modal tasks.

## Why It Matters / Open Questions

m&m's provides the first standardized, executable benchmark for studying how design choices (planning strategy, output format, feedback type) affect LLM tool-use performance on multi-modal tasks, yielding actionable recommendations (multi-step + JSON + feedback) for practitioners building planning agents. Key open questions remain: the benchmark only covers sequential plans (no dynamic/conditional branching), excludes prompt-style ablations (e.g., tree-of-thoughts), and evaluates only text-based LLM planners rather than multi-modal LLMs. The finding that feedback can degrade tool selection while improving executability suggests a fundamental tension in iterative refinement that future work on fine-grained, localized feedback must address.
