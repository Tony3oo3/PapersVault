## Problem

Existing GUI agents process all actions uniformly, either incurring heavy computational cost from always-on perception stacks or relying on external controllers and explicit intermediate representations (e.g., icon captions) for slow-fast switching. This creates a fundamental tension: compact models lack the adaptive mechanism to allocate deeper visual grounding only when a task demands it, while larger models waste latency on trivial interactions. The paper addresses the absence of a unified, implicit control mechanism within a single lightweight MLLM that can autonomously decide when to engage precise, localized perception versus efficient global reasoning.

## Input / Output

The model receives a single UI screenshot (processed by the Qwen2-VL vision encoder for global features) and a natural-language task instruction. Internally, the model generates a sequence of latent thinking tokens and optionally latent perception tokens before emitting the final action. The output is a structured GUI action (e.g., click, swipe, type) with pixel coordinates. When the slow path is activated, the screenshot is additionally re-encoded by a DINO encoder to produce localized feature maps that are injected back into the token sequence via cross-attention, augmenting the global context with fine-grained spatial detail.

## Method

iSHIFT builds on Qwen2-VL 2B and introduces two architectural components: (1) Latent Thinking Tokens (<bot>...<eot>) that enable continuous-space deliberation by directly mapping hidden states to input embeddings, bypassing the vocabulary layer entirely, and (2) a Visual Perception Module (VPM) comprising a DINO encoder and a cross-attention projector (image features as Query, latent perception token hidden state as Key/Value) that is activated only upon generation of <bop> tokens. The slow-fast decision is made implicitly through the model's next-token prediction rather than an external controller: if the task requires precise coordinate prediction, the model generates perception tokens to trigger the VPM; otherwise it proceeds directly to action generation. Training uses a two-phase strategy—first populating thought token positions with explicit natural-language reasoning, then replacing them with latent tokens—and programmatically annotates the action space so that coordinate-requiring actions are labeled with perception tokens while global-context actions are not, teaching the model to associate task complexity with the correct execution path.

## Results

On the Android In The Wild (AITW) benchmark, iSHIFT (2.5B) achieves an average Action Matching Score (AMS) of 76.34%, the best among all models under 5B parameters and within 0.54 points of the overall SOTA CogAgent (18B, 76.88%). On GUI Odyssey, iSHIFT attains the highest success rate of 73.97%, outperforming the 7B Aguvis model (63.8%) by over 10 points. On GUIAct, iSHIFT achieves 93.83% Type Accuracy on Web Single and 79.41% Type Accuracy / 60.08% Success Rate on Phone, surpassing the much larger GUICourse 9.6B model on the Phone subset.

## Baselines & Comparisons

iSHIFT (2.5B) achieves near-parity with the 18B CogAgent (76.34 vs. 76.88 AMS) while being over 7× smaller, and surpasses all other sub-5B baselines: AutoGUI (4.5B, 74.27), TongUI 3B (71.6), ShowUI (2B, 70.04), and its own base model Qwen2-VL 2B (67.24). It also edges out several larger models on AITW: SeeClick 9.6B (76.16), SphAgent 7B (76.28), and MobileVLM 9.6B (75.42). On GUI Odyssey, iSHIFT leads all models with 73.97% success rate, beating the 7B Aguvis (63.8%) by over 10 points and the 4B OS Atlas (56.39%) by nearly 18 points. On GUIAct Phone, iSHIFT outperforms the 9.6B GUICourse model (79.41% vs. 73.0% Type Accuracy; 60.08% vs. 58.1% Success Rate), and on Web Single it surpasses the 3.1B GUICourse (93.83% vs. 91.8% Type Accuracy). The only model iSHIFT does not surpass on AITW is CoCo-Agent (77.82), though CoCo-Agent uses a 7B LLaMa2 backbone and is not a pure vision-based agent.

## Relation to Prior Work

iSHIFT sits at the intersection of three research threads: vision-based GUI agents (SeeClick, CogAgent, ShowUI) that operate on raw pixels, slow-fast computation paradigms in visual agents (Sun et al., Christakopoulou et al.), and latent/implicit reasoning in language models (Hao et al.). It departs from prior slow-fast GUI work by eliminating the external controller that arbitrates between paths, instead embedding the decision implicitly within the MLLM's token generation. It also contrasts with always-on high-resolution perception stacks (CogAgent, V-Zen) by making the DINO-based Visual Perception Module conditional, activated only when the model's latent deliberation signals a need for fine-grained grounding.

## Why It Matters / Open Questions

The result that a 2.5B agent matches an 18B model (76.34 vs 76.88 AMS) with a 5× efficiency advantage is practically significant for deploying GUI agents on resource-constrained devices. The finding that forcing the slow path degrades performance (74.58 vs 76.34) challenges the intuition that more visual computation is always beneficial, suggesting that indiscriminate high-resolution processing introduces attention dilution. Open questions include whether the implicit slow-fast mechanism generalizes to more complex multi-step tasks or non-Android platforms, and whether the sensitive latent-token-count hyperparameter (optimal at 8, degrading sharply at 16+) limits robustness across task distributions.
