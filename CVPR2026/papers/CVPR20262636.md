## Problem

Multimodal Large Language Models struggle to perceive fine-grained geometric structures such as segment relations, angle magnitudes, and shape constraints, limiting their geometric understanding and visual reasoning. This gap is exacerbated by the scarcity of large-scale geometric image-to-code datasets and the fact that existing image-to-code methods focus on web UIs or data charts rather than geometric content. The paper addresses this by bridging geometric perception and symbolic reasoning through structured TikZ code generation.
![Teaser figure](../imgs/CVPR20262636/cropped_page1_idx0.webp)

## Input / Output

The model takes a geometric image (or a geometric image paired with a natural-language instruction for auxiliary line addition) and produces compilable TikZ/LaTeX code that encodes the geometric construction with explicit logical dependencies. For the downstream reasoning pipeline, the generated TikZ code is rendered back to an image and/or passed as structured text to a VLM or LLM alongside the problem statement, enabling LLMs—which cannot directly process geometric images—to participate in geometric problem-solving. The code output is constrained to be compilable (measured by Compilation Success Rate) and is validated via CLIP-score matching between the rendered output and the original image.

## Method

GeoTikzBridge employs an iterative self-refinement loop (K=4 iterations) that starts from the 145k-sample DaTikZ seed, generates pseudo-labels with the current model, filters reliable pairs by CLIP score (threshold 0.8) between rendered and original images, and accumulates them into a 2.5M-pair GeoTikz-Base dataset. A key differentiator is the localized geometric transformation strategy: at each iteration, 1–40% of TikZ code lines are randomly removed to create partial-code training pairs, forcing the model to learn structural and fine-grained geometric semantics rather than memorize full sequences (reducing code repetition by 15%). Two base models (8B initialized from FigCodifier, 38B from InternVL3.5) are trained via causal autoregressive generation with full-parameter SFT or LoRA. A second model, GeoTikzBridge-Instruct, is further fine-tuned on 419k instruction-augmented samples (generated by Qwen2.5-VL-72B annotations filtered by Doubao) to produce TikZ code with user-specified auxiliary lines. Finally, a training-free plug-and-play pipeline feeds the generated TikZ code (and optionally rendered auxiliary-line images) into any VLM or LLM to boost geometric reasoning without retraining the downstream model.

## Results

On the image-to-tikz task, GeoTikzBridge-Base-38B achieves the best CLIP Score across all four benchmarks (0.813 on DaTikZ, 0.915 on MathVista-GPS, 0.900 on GAOKAO-MM-Math, 0.821 on EDUBenchmark) with the lowest FID (30.6 on MathVista-GPS) and highest Compilation Success Rate (95.8% on GAOKAO-MM-Math). For downstream geometric reasoning, plugging GeoTikzBridge-Base into VLMs yields consistent gains (e.g., Qwen3-VL-30B-A3B improves from 0.697 to 0.745 on MathVista-GPS, +4.8 pp). Among LLM+Tikz configurations, GLM-4.5-Air-106B-A12B+GeoTikzBridge-Base reaches 0.889 on MathVista-GPS, while GPT-OSS-120B+GeoTikzBridge-Base achieves the best RBench-V(Math) score of 0.301 and RBench-V(Overall) of 0.164.

## Baselines & Comparisons

On the core image-to-tikz task (Table 1), GeoTikzBridge-Base-38B outperforms all six open-sourced VLMs (Qwen2.5-VL-72B, InternVL3-78B, GLM4.5-V-106B-A12B, etc.) and the dedicated FigCodifier-8B model on CLIP Score, FID, and Compilation Success Rate across all four benchmarks; for example, it achieves 0.915 CLIP-S vs. 0.884 for FigCodifier-8B and 0.860 for InternVL3-78B on MathVista-GPS. For downstream reasoning (Table 2), plugging GeoTikzBridge-Base into any VLM consistently improves scores—GLM4.5-V-106B-A12B gains +6.4 pp on RBench-M (0.434→0.498) and +6.5 pp on RBench-V(Math) (0.230→0.295)—and LLM+Tikz configurations generally surpass their VLM counterparts, with GPT-OSS-120B+GeoTikzBridge-Base reaching 0.301 on RBench-V(Math), exceeding GPT-4o's 0.244. The best MathVista-GPS score among LLM+Tikz is 0.889 (GLM-4.5-Air-106B-A12B), well above the best open-sourced VLM (GLM4.5-V at 0.764 with GeoTikzBridge-Base) and the best closed-sourced VLM (GPT-4o at 0.647). The paper does not report a direct head-to-head loss to any baseline; all comparisons favor GeoTikzBridge-Base or its plug-and-play integration.

## Relation to Prior Work

This paper extends the image-to-tikz code generation line initiated by DaTikZ/TikZero and FigCodifier/MathCoder-VL, which established the basic image-to-tikz pairing paradigm but focused on general graphics rather than geometric content. It departs from prior image-to-code work (which targets web UIs, charts, or SVG) by specifically targeting geometric diagrams and arguing that tikz's structured, dependency-explicit syntax is inherently better suited for geometric reasoning than visual formats like SVG. The iterative self-refinement with CLIP-based filtering and the localized code transformation strategy are novel data-engineering contributions that address the scarcity of geometric image-code pairs, while the instruction-augmented auxiliary-line generation task has no direct prior counterpart in the image-to-code literature.

## Why It Matters / Open Questions

The 2.5M-pair GeoTikz-Base dataset (16× larger than prior open-source image-tikz data) and the plug-and-play reasoning pipeline make this practically important: any existing VLM or LLM can be augmented with geometric perception without retraining, which is a low-friction adoption path. The finding that text-only LLMs fed tikz codes can match or exceed VLMs on geometric reasoning challenges the assumption that visual perception is a hard prerequisite for geometric problem-solving, though the evidence is limited to a handful of benchmarks. Open questions include whether the approach generalizes to 3D geometry, engineering schematics, and whether the iterative self-refinement loop can be made more sample-efficient; the authors also note future work on agentic RL integration.
