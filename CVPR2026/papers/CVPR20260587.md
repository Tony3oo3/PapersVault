## Problem

Fine-tuning a multi-LoRA LLM on a new task under a tight on-device memory budget requires sparse insertion of LoRA modules, but existing sparse-updating methods assume all candidate parameters already exist and cannot estimate the importance of modules that have not yet been inserted. Additionally, prior memory-prediction models assume activation memory scales linearly with layer index, an assumption that breaks for Transformers whose multi-branch attention blocks introduce parallel dependencies that violate linear layer ordering.
![Teaser figure](../imgs/CVPR20260587/cropped_page1_idx0.webp)

## Input / Output

The method consumes a frozen Transformer backbone already equipped with LoRA modules from n previously learned tasks, a batch of new-task training data, and a peak-memory budget M_B (e.g., 8 GB). It outputs a sparse insertion strategy specifying which backbone locations receive LoRA modules, at what rank (powers of 2 up to 64), followed by the fine-tuned LoRA parameters that are merged into the backbone for inference. Notably, importance and memory are predicted entirely before any new LoRA parameters are instantiated, using only forward and a single lightweight backward pass on the new-task data.

## Method

TaskIT comprises three components. First, a parameter-free module importance predictor estimates each location's importance for the new task by computing an activation-ratio score (LoRA output L1 norm divided by frozen-matrix output L1 norm) for every existing task module, then taking a similarity-weighted average across tasks, where task similarity is the cosine similarity between each learned task's activation and a one-step simulated descent approximation of the new task's activation. Second, a block-based memory predictor traces the computation graph to derive, for each candidate insertion location, a binary mask of which activations must be cached for backpropagation, explicitly separating intra-block parallel dependencies (Q/K/V cross-branch interactions in attention) from inter-block sequential dependencies (downstream Q, K, V, and attention weights that must be retained). Third, a dynamic-programming scheduler solves a knapsack variant where the state encodes the last insertion location (since incremental memory cost depends on the nearest prior insertion), searching over locations, ranks, and counts to maximize total predicted importance subject to the memory budget.

## Results

On cross-modal tasks under an 8 GB memory budget, TaskIT achieves 80.4% average image accuracy, 90.1% average NLP accuracy, and 83.6% average VL accuracy using only 16.8M learnable parameters and 7.8–7.9 GB peak memory. Compared to the best LoRA-based baseline AutoLoRA, TaskIT saves 45.5% memory (7.8 GB vs. 14.5 GB) with only a 0.3% average accuracy drop. Against the best non-LoRA baseline UniPT, TaskIT reduces memory by 13.8% while improving accuracy by 1.5%. Versus the best Zero-FT baseline AdapterFusion, TaskIT improves average accuracy by 10.4%.

## Baselines & Comparisons

TaskIT outperforms all Zero-FT baselines by a wide margin: AdapterFusion (best Zero-FT) trails by 10.4% average accuracy and still requires 10.6 GB for weight computation, while LoraHub uses only 6.5 GB but drops to 73.3% VL accuracy. Against non-LoRA methods, TaskIT beats UniPT (best non-LoRA) by 1.5% accuracy at 13.8% lower memory, and substantially outperforms Full tuning (74.8% image) which requires 16.6 GB. Among LoRA-based methods, TaskIT matches AutoLoRA within 0.3% average accuracy while using 45.5% less memory (7.8 vs. 14.5 GB), and surpasses AdaLoRA on image accuracy (80.4% vs. 80.5% is a near-tie) at 37% lower memory. On uni-modal image tasks (Table 2), TaskIT narrows the gap to AutoLoRA to just 0.1% average accuracy while using 45% less memory, and beats UniPT by 2.1% accuracy at 11.4% lower memory. The ablation confirms each component contributes: removing the memory predictor pushes peak memory to 9.9 GB (exceeding budget), and replacing the DP scheduler with greedy reduces learned parameters by 7.7M and drops accuracy by 2.9%.

## Relation to Prior Work

TaskIT extends the sparse-updating literature (which freezes unimportant layers and trains only critical ones) to a setting where the candidate LoRA modules do not yet exist in a multi-LoRA foundation model. It departs from prior importance estimators that require already-trained parameters by instead transferring module importance from previously learned tasks via activation-based similarity, and from prior memory models (e.g., Lin et al., NeurIPS 2022) that assume linear memory growth with layer index by introducing a block-based predictor that captures the parallel Q/K/V branches within Transformer attention blocks. The DP-based scheduler for jointly selecting locations, counts, and ranks builds on knapsack-style formulations but encodes the non-independent memory cost of insertion positions as a state variable.

## Why It Matters / Open Questions

This work addresses a practical bottleneck for on-device foundation models: adapting a single backbone to many tasks without exhausting device memory. The cross-task importance transfer idea is elegant in that it requires only one forward and one lightweight backward pass per batch to predict where new modules should go, avoiding the circular dependency of training full LoRA sets just to measure their importance. Limitations include reliance on at least some previously learned tasks for transfer (falling back to uniform importance when no similar task exists, as with the audio modality in the case study), evaluation primarily on a 1.5B-parameter model (Janus-Pro), and the DP scheduler's discretization of the memory budget (U=500 bins) which may lose precision at very tight budgets. Open questions include how well the importance transfer generalizes to substantially different architectures or to settings with very few base tasks, and whether the block-level dependency analysis extends cleanly to newer attention variants (e.g., sliding-window or grouped-query attention).
