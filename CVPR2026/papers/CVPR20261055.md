## Problem

Over 1,000 NeRF follow-up papers lack public code, forcing researchers to spend weeks reimplementing methods before building on them. Generic paper-to-code systems (Paper2Code, AutoP2C, GPT-5) fail to produce trainable NeRF code in 95% of cases because they cannot resolve the tight coupling between volumetric rendering mathematics, neural architectures, and multi-paper dependency chains that define the NeRF domain.
![Teaser figure](../imgs/CVPR20261055/cropped_page0_idx0.webp)

## Input / Output

The system takes a NeRF research paper PDF as input, parsed via MinerU into structured markdown preserving equations, algorithm blocks, architectural diagrams, and citation relationships. The output is a multi-file Nerfstudio plugin repository organized as a directed acyclic graph of files with import and dataflow dependencies, where every file satisfies Nerfstudio interface contracts and the full pipeline trains end-to-end to convergence. Unlike generic code generators that may emit syntactically valid but non-runnable Python, NERFIFY guarantees the output is a trainable plugin that converges to paper-reported PSNR within 0.5 dB.

## Method

NERFIFY is a four-stage multi-agent pipeline. Stage 1 formalizes the Nerfstudio architecture as a context-free grammar (CFG) that constrains LLM synthesis to architecturally valid module compositions, supplemented by curated paper-code pairs as in-context examples. Stage 2 performs compositional citation recovery, recursively traversing reference graphs to retrieve implicit dependencies (e.g., proposal networks from Mip-NeRF 360, hash encoders from Instant-NGP) that the target paper assumes but does not fully specify. Stage 3 uses Graph-of-Thought planning where specialized file-agents generate repository files in topological dependency order, validating type signatures, tensor shapes, and circular dependencies at each node before proceeding, with smoke tests triggering automated repair loops. Stage 4 applies visual-driven feedback through three parallel branches—PSNR-minima ROI analysis, cross-view geometric consistency checking, and Qwen3 VLM-guided artifact diagnosis—iteratively patching the implementation until it matches expert visual quality.

## Results

On never-implemented NeRF papers (Set 1, no public code to avoid contamination), NERFIFY achieves visual quality within ±0.5 dB PSNR and ±0.02 SSIM of expert human implementations (e.g., 26.12 vs 25.70 PSNR on KeyNeRF, 27.30 vs 26.81 on TVNeRF). Critically, NERFIFY is the only system that produces fully trainable code (100% executability), while all baselines (Paper2Code, AutoP2C, GPT-5, DeepSeek-R1) fail to generate runnable NeRFs in every tested case. On novelty coverage across 10 complex papers, NERFIFY achieves perfect correct-implementation rate (C=1.00) and zero missing components (M=0.00), compared to C=0.13–0.83 and M=0.10–0.90 for baselines.

## Baselines & Comparisons

All four baselines—Paper2Code, AutoP2C, GPT-5, and DeepSeek-R1—fail to produce trainable NeRF code in 100% of test cases (Table 2), with failures ranging from unresolved imports to non-converging training. NERFIFY is the only method that passes all four executability checks (imports resolve, compiles/trainable, training stability, converges to paper results). On papers with existing implementations (Sets 2–3), NERFIFY matches gold-standard Nerfstudio repositories exactly (31.36 PSNR on Vanilla NeRF, 20.36 on Nerfacto) and slightly outperforms the original L0-Sampler code (30.13 vs 29.21 PSNR), though it trails InfoNeRF's original implementation by 0.4 dB (17.87 vs 18.27). On novelty coverage (Table 4), NERFIFY achieves C=1.00 and M=0.00 across all 10 evaluated papers, while the best baseline (Paper2Code) reaches only C=0.83 on Mip-NeRF and drops to C=0.00 on MCNeRF, with missing-component rates up to 0.90. The ablation confirms that removing compositional citation recovery drops correct novelty implementation to 0.65, and replacing GoT with one-shot generation collapses the semantic score from 0.98 to 0.45.

## Relation to Prior Work

NERFIFY positions itself as a domain-specific departure from generic paper-to-code systems (Paper2Code, AutoP2C) and general multi-agent coding frameworks (MetaGPT, ChatDev, DeepCode), which the authors demonstrate fail to produce trainable NeRF code. Its two key conceptual building blocks are Nerfstudio formalized as a context-free grammar (extending the CFG-for-code-synthesis line from Scene Language and CODEP) and Graph-of-Thought orchestration (from Besta et al.), but the novel contribution is their combination with compositional citation-graph traversal to resolve implicit cross-paper dependencies. The framework also draws on VLM-based visual critique (Qwen3) for iterative refinement, extending self-debugging and Reflexion-style loops with domain-specific geometric and perceptual diagnostics.

## Why It Matters / Open Questions

For the NeRF community specifically, NERFIFY collapses implementation time from weeks to minutes and introduces NERFIFY-BENCH, the first benchmark purpose-built for evaluating NeRF paper-to-code synthesis, which is a practical resource for the field. The dramatic executability gap (100% vs. 0% for all generic baselines) strongly supports the thesis that domain-aware architectural constraints are necessary rather than optional for research code synthesis. However, the scope is limited to Nerfstudio-compatible NeRF methods on 30 papers, and generalization to other CV subfields or non-Nerfstudio frameworks remains untested; the authors themselves frame this as a template for future domain-specific extensions rather than a general solution.
