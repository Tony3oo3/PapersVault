## Problem

Mixture-of-Experts (MoE) and memory-based modules are the two dominant sparse activation paradigms, yet they have evolved along divergent research directions with no shared formalism, making systematic comparison and hybrid design difficult. In vision specifically, memory-based sparsity remains underexplored, and the complementary trade-offs between MoE's dynamic expressiveness and memory's retrieval efficiency have not been jointly exploited.

## Input / Output

The Nexus Layer operates on token sequences of shape N×D extracted from either ViT patch embeddings or ConvNeXt feature maps, and is inserted at fixed positions within the backbone (layers 5, 7, 9, 11 for ViT; Stage-3 blocks 12–27 for ConvNeXt). It produces a same-dimension output that feeds the rest of the network, ultimately yielding class labels, bounding boxes with instance masks, or pixel-wise segmentation maps depending on the downstream head. The layer is architecture-agnostic and requires no modification to the surrounding backbone or task-specific head.

## Method

OneSparse reformulates both MoE and memory modules under a three-stage dispatch–process–combine abstraction, formalized by a dispatch tensor D, a combine tensor B, and a set of per-unit processing functions {f_r}, which decouples routing logic from computation and reveals a continuous design space. The Nexus Layer instantiates this framework with two innovations: (1) a unified cross-attention router that assigns tokens to heterogeneous processing units (E_mem memory groups + E_exp expert FFNs) via softmax-over-tokens dispatch and softmax-over-slots combine, achieving balanced utilization without auxiliary load-balancing losses; and (2) an adaptive processing strategy where memory units perform efficient top-k dot-product retrieval to sketch coarse representations for all tokens, while expert units apply dynamic FFN transformations to refine only the most semantically important regions. Memory parameters are shared across sparse layers to maximize capacity under a fixed parameter budget.

## Results

On ImageNet-1K, the Nexus Layer achieves 81.2% Top-1 accuracy on ViT-S with 4.3G FLOPs, matching the dense model's computation while improving accuracy by 2.4 points. On ConvNeXt-B, Nexus reaches 84.5% Top-1 at 15.3G FLOPs, outperforming the dense baseline (83.8%) and the strongest MoE variant SoftMoE (84.2% at 17.5G FLOPs). On COCO detection (ViT-S), Nexus attains 42.7 AP^bbox, and on ADE20K segmentation (ViT-S), it achieves 45.8% mIoU, both leading all sparse baselines with fewer FLOPs.

## Baselines & Comparisons

Nexus outperforms all four sparse baselines across every backbone and task. Against Memory+ (Berges et al., 2024), Nexus gains 1.9 points on ViT-S (81.2% vs. 79.3%) while using 30% fewer parameters (55.6M vs. 78.7M), and 0.7 points on ConvNeXt-B (84.5% vs. 83.8%) with 7% fewer FLOPs. Against Token-Choice MoE (Shen et al., 2023), Nexus improves accuracy by 0.7 points on ViT-S (81.2% vs. 80.5%) while reducing FLOPs by 20% (4.3G vs. 5.4G). Against Expert-Choice MoE (Zhou et al., 2022), the margin is similar: +0.5 points on ViT-S with the same 20% FLOPs reduction. Against SoftMoE (Puigcerver et al., 2024), the strongest MoE baseline, Nexus achieves +0.4 points on ViT-S and +0.3 points on ConvNeXt-B while using 20% and 12% fewer FLOPs respectively. On dense prediction tasks, Nexus extends these advantages: 42.7 AP^bbox on COCO (vs. 42.2 for SoftMoE) and 45.8% mIoU on ADE20K (vs. 45.3 for SoftMoE), confirming consistent gains beyond classification.

## Relation to Prior Work

This paper unifies two previously separate lines of sparse activation research—Mixture-of-Experts (Token-Choice, Expert-Choice, SoftMoE) and memory-based modules (Product Key Memory, Memory+)—under a common dispatch-process-combine abstraction (OneSparse). The Nexus Layer's unified cross-attention router extends SoftMoE's soft routing to heterogeneous processing units (both dynamic experts and static memory groups), while its coarse-branch retrieval adapts PKM's content-based lookup into a grouped, top-k dot-product mechanism. The key departure from prior work is treating MoE and memory not as competing paradigms but as endpoints of a continuous design space along routing logic and processing function axes, enabling principled hybrid design rather than ad-hoc combination.

## Why It Matters / Open Questions

The OneSparse framework provides a systematic vocabulary for comparing and combining sparse activation strategies, which should accelerate future work on hybrid sparse architectures in vision. The consistent 1–2 point gains over both MoE and memory baselines across classification, detection, and segmentation on both ViT and ConvNeXt backbones demonstrate practical utility, though the margins are moderate. Two open questions remain: whether the memory-to-expert ratio can be learned dynamically rather than fixed empirically, and whether the FLOPs savings translate to meaningful wall-clock latency reductions under hardware-aware optimization. The framework's generality suggests it could guide sparsity design beyond vision (e.g., language or multimodal models).
