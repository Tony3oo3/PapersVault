## Problem

Adapting closed-box service model APIs to downstream tasks typically relies on zeroth-order optimization (ZOO) to estimate gradients through input perturbations, incurring massive API call costs during both training and inference. More critically, modern robust APIs like GPT-4o are largely insensitive to these noisy perturbations, rendering ZOO-based reprogramming ineffective while still incurring high costs. The paper asks whether an alternative strategy can achieve effective adaptation with minimal, one-time API interaction and cost-free inference.

## Input / Output

The method takes standard RGB images as input and produces class labels for the downstream task. Under the strictest closed-box assumption, the service API returns only prediction probabilities (no logits or embeddings), and the API is queried exactly once per training image during priming—never during inference. For VLMs, the output label space is naturally aligned via text prompts; for VMs, a gradient-free Bayesian-guided label mapping bridges the source (e.g., ImageNet) and target label spaces without requiring shared vocabulary.

## Method

AReS operates in two stages. First, a single-pass priming stage queries the service API once per training image and trains only a lightweight linear layer on top of a frozen local encoder (e.g., ViT-B/16) to match the service model's output probability distribution via KL divergence, working even when source and target label spaces are disjoint. Second, with the primed local model fully accessible, standard gradient-based visual reprogramming learns a visual prompt P through an input transformation g_in, minimizing cross-entropy on the downstream task using exact first-order gradients. A theoretical bound (Theorem 3) shows the optimally reprogrammed local model's risk approaches that of the optimally reprogrammed service model within ε, where ε reflects priming faithfulness. An AReS-MS variant leverages the priming stage as a low-cost diagnostic to automatically select between the cost-free local model and the zero-shot API per task, navigating the cost-performance trade-off.

## Results

On ten diverse visual recognition datasets in a 16-shot VLM setting (CLIP ViT-B/16 service, ViT-B/16 local), AReS achieves 65.4% average accuracy, outperforming BlackVIP (62.9%), BAR (61.4%), and LLM-Opt (54.5%), while using only 0.02M API calls versus 754.20M for BlackVIP (>99.99% reduction) and 3.7 hours of training versus 197.5 hours. In the full-shot VM setting (ViT-B/16 service, ViT-B/32 local), AReS reaches 50.4% average accuracy versus 34.8% for BlackVIP and 20.4% for BAR. On the real-world GPT-4o API (EuroSAT 16-shot), AReS achieves 87.2% accuracy (+27.8% over zero-shot) at a total cost of $0.3, while BlackVIP gains only +0.7% at $101.0.

## Baselines & Comparisons

AReS outperforms all three baselines across both VLM and VM settings. Against BlackVIP (CVPR 2023), AReS gains +2.5% average accuracy on VLMs (65.4% vs. 62.9%) and +15.6% on VMs (50.4% vs. 34.8%), while reducing API calls from 754M to 0.02M (>99.99%) and training time from 197.5h to 3.7h. Against BAR (ICML 2020), the margins are larger: +4.0% on VLMs and +30.0% on VMs. Against LLM-Opt (CVPR 2024), AReS leads by +10.9% on VLMs while using 1/250,000th of the API calls. The most striking comparison is on GPT-4o, where AReS achieves +27.8% over zero-shot (87.2% vs. 59.4%) while BlackVIP gains only +0.7% (60.1%) and BAR actually underperforms zero-shot (59.1%), demonstrating that ZOO-based methods fail on modern robust APIs. On the commercial Clarifai API, AReS reaches 83.2% at $0.2 total cost, versus 72.1% at $67.3 for BlackVIP (336× cheaper).

## Relation to Prior Work

AReS departs from the dominant ZOO-based closed-box reprogramming paradigm (BAR, BlackVIP) by replacing continuous API-dependent gradient estimation with a single-pass priming step followed by standard gradient-based visual reprogramming on a local encoder. The priming stage borrows the KL-divergence objective from knowledge distillation but repurposes it as a preparatory alignment step rather than a final training objective, and the local VR stage builds directly on the padding-based visual prompt framework and Bayesian-guided label mapping from Cai et al. (NeurIPS 2024). Conceptually, the paper repositions the local encoder from a mere prompt generator (as in BlackVIP's Coordinator) to the primary adaptation target, with the service API serving only as a one-time teacher signal.

## Why It Matters / Open Questions

The >99.99% reduction in API calls and elimination of inference-time API dependency address a critical practical bottleneck in API-centric ML deployment, enabling offline and edge use cases that ZOO-based methods cannot support. The observation that modern robust APIs (GPT-4o) are largely insensitive to the input perturbations ZOO relies on raises an open question about the fundamental viability of the ZOO paradigm for next-generation service models. Limitations include the continued need for a local encoder of comparable quality, the inherent ceiling of input-level VR on certain domains (Food101, Cars), and the single-dataset evidence for the GPT-4o claim; broader validation across tasks, modalities, and model scales remains to be established.
