## Problem

Convolutional learning on 3D point clouds faces a fundamental precision-performance trade-off: voxel-based methods achieve high efficiency through global quantization but lose sub-voxel geometric detail critical for tasks like registration, while point-based methods preserve fidelity but incur significant overhead from irregular-to-regular transformations and padding. This paper argues the trade-off is not inherent but stems from how the operator and its computational system are designed, and that a holistic co-design can eliminate it.

## Input / Output

The method consumes raw 3D point clouds with per-point coordinates and feature vectors, operating directly on the original high-precision coordinates without any global voxelization or learned transformation. Neighborhoods are constructed via fixed-radius search (rather than KNN) around each original point, and the kernel resolution (e.g., 3³ or 5³) is decoupled from any global voxel size, allowing finer kernels within the same receptive field. Outputs are per-point feature vectors that feed into downstream heads for registration transforms or per-point class labels, with the entire pipeline requiring zero extra global memory beyond the input tensors.

## Method

PointCNN++ generalizes sparse convolution from discrete voxels to continuous points by centering each receptive field on the original high-precision point coordinate and applying a local, adaptive voxelization only at the final step to pair neighborhood points with discrete kernel weights, making voxel-based convolution a quantized special case. The convolution is formulated as a Matrix-Vector Multiplication and Reduction (MVMR) problem, for which a dedicated GPU kernel is developed: triplets (i,j,k) are sorted by kernel index k so that consecutive groups share the same weight matrix, reducing global memory reads of W by a factor of ~1/L. The kernel assigns each B_out × B_in block of the weight matrix to a warp of threads, leveraging on-chip caching and coalesced access patterns inspired by tall-and-skinny GEMM algorithms. Backward pass gradients are computed via two specialized kernels—reusing MVMR for input feature gradients and a new Vector-Vector Outer-product and Reduction (VVOR) kernel for weight gradients—completing a zero-extra-memory training pipeline.

## Results

On KITTI point cloud registration, PointCNN++ (with FCGF architecture) achieves a mean RTE of 0.19 m and a Registration Recall of 99.8% at 0.2 m/1°, nearly halving the RTE of the original FCGF (0.36 m) and surpassing the previous best Regformer (0.22 m RTE, 94.6% Recall). On 3DMatch, it attains 90.3% Registration Recall and 99.3% Feature Matching Recall at 5000 points, with notably stable performance down to 250 points (88.3% RR). On nuScenes semantic segmentation, PointCNN++ reaches 78.2% mIoU and 85.3% mAcc, outperforming the voxel-based MinkowskiEngine baseline (74.4% mIoU) while using less memory (2.43 GB vs 2.61 GB) and running faster (0.102 s vs 0.131 s per iteration).

## Baselines & Comparisons

On KITTI, PointCNN++ (FCGF backbone) achieves the best RTE (0.19 m) and Recall (99.8%), beating Regformer (0.22 m, 94.6%) by 14% in RTE and 5.2 points in Recall, while using only 8.75M parameters (vs Regformer's 3.12M). It also shows the lowest standard deviations in both RTE (0.03) and RRE (0.10°), indicating superior registration stability. On 3DMatch, PointCNN++ leads in Feature Matching Recall (99.3%) across all densities but trails GeoTrans on Registration Recall (90.3% vs 91.4% at 5000 pts) and Inlier Ratio (58.2% vs 70.5%), though it degrades more gracefully at lower point counts. On nuScenes segmentation, PointCNN++ outperforms the voxel-based MinkowskiEngine by 3.8 mIoU points (78.2% vs 74.4%) with 7% less memory and 22% faster per-iteration time, while the point-based KPConv baseline is impractical (requiring ~116 days of training). The operator-level benchmarks on S3DIS scenes confirm PointCNN++ uses over an order of magnitude less memory than point-based methods (PointCNN, KPConv) and is faster than all voxel-based alternatives (MinkowskiEngine, SpConv, TorchSparse++, O-CNN).

## Relation to Prior Work

This paper unifies two competing paradigms in 3D point cloud convolution—voxel-based (MinkowskiEngine, SpConv, O-CNN) and point-based (PointCNN, KPConv)—by showing that voxel convolution is a quantized, degraded special case of a more general point-centric operator. The computational core draws on the TSM2X algorithm [41] for tall-and-skinny matrix multiplication to design a dedicated GPU kernel for the MVMR formulation, while the operator design itself generalizes the triplet-set convolution framework from discrete voxels to continuous point coordinates with local adaptive voxelization. Unlike prior point-based methods that introduce costly irregular-to-regular transformations (X-Transform, kernel point deformation), PointCNN++ operates natively on points with zero extra memory, and unlike voxel methods it decouples kernel resolution from global voxelization.

## Why It Matters / Open Questions

The practical impact is significant: a simple backbone swap in the 2019 FCGF architecture yields SOTA registration on KITTI (RTE 0.19m, RR 99.8%) without any task-specific tuning, suggesting that much of the prior progress in registration may have been driven by backbone quality rather than architectural ingenuity. The MVMR formulation and its GPU kernel provide a reusable, high-performance primitive for any convolutional operator on irregular data, potentially applicable beyond point clouds. Open questions include whether the approach composes well with attention/transformer modules (explicitly deferred to future work), how it scales to extremely large outdoor scenes beyond S3DIS/nuScenes, and whether the local-voxelization step introduces any subtle fidelity loss at very fine kernel resolutions.
