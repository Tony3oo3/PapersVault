## Problem

Video generation models cannot maintain long-term spatial consistency because the dense, high-dimensional nature of video signals makes it computationally infeasible to attend to all historical frames—just 5 seconds of 480P video already yields 36,000 spatio-temporal tokens. Existing memory-based approaches for video generation are typically restricted to static scenes, failing to preserve spatial coherence while simultaneously producing realistic dynamic entities.

## Input / Output

At inference, Spatia takes an initial RGB image (first iteration) or a previously generated 72-frame clip (subsequent iterations), a text instruction, and a user-specified 3D camera trajectory as input, and produces a new video clip (81 frames for the first iteration, 72 frames thereafter) along with an updated 3D scene point cloud. The point cloud is projected onto the 2D image plane along the camera path to form a 'scene projection video' that conditions generation, and up to K spatially relevant reference frames are retrieved from prior generations based on point-cloud overlap. Training operates at 720P resolution on 50K videos from RealEstate and SpatialVID.

## Method

Spatia maintains a 3D scene point cloud as explicit spatial memory, iteratively updated via MapAnything (a feed-forward metric 3D reconstruction model) after each generation step, enabling the model to 'remember' previously visited locations. The architecture builds on Wan2.2 (5B parameters) with Flow Matching training, adding 8 parallel ControlNet blocks that process scene projection videos (the point cloud rendered from per-frame camera poses) while the main blocks attend to concatenated reference-frame tokens, preceding-clip tokens, and the noisy target tokens. Dynamic-static disentanglement is achieved by segmenting dynamic entities (via Keye-VL-1.5 + ReferDINO) before point cloud estimation, so the memory encodes only static geometry while the model still generates moving objects. Camera control is explicit and geometrically grounded: the desired 3D camera path is directly applied to the point cloud to render a 2D conditioning sequence, mirroring the 3DGS rendering pipeline rather than encoding trajectories into latent features. Training is two-stage: ControlNet blocks are trained for 8,000 iterations with the main network frozen, then the main blocks are fine-tuned with LoRA (rank 64) for 5,000 iterations.

## Results

On the WorldScore benchmark, Spatia achieves an average score of 69.73, outperforming the best static scene generation model (Voyager, 66.08) and the best foundation video generation model (CogVideoX-I2V, 60.64). Spatia also leads on the dynamic score (66.82 vs. 54.53 for Voyager) and camera control (75.66 vs. 85.95 for Voyager, but far above all foundation models at ~25–38). On the RealEstate test set, Spatia achieves PSNR 18.58, SSIM 0.646, and LPIPS 0.254, surpassing the next-best method Voyager (17.79 / 0.636 / 0.297). In the closed-loop memory evaluation, Spatia attains Match Accuracy of 0.698 and LPIPS_C of 0.213, substantially ahead of Voyager (0.507 / 0.380).

## Baselines & Comparisons

Spatia outperforms all 15 baselines across every evaluation setting. Against the four static scene generation models (WonderJourney, InvisibleStitch, WonderWorld, Voyager), Spatia achieves a higher average WorldScore (69.73 vs. 66.08 for the best, Voyager) while also producing dynamic content that static-only methods cannot handle (dynamic score 66.82 vs. 54.53). Against the seven foundation video generation models (VideoCrafter2, EasyAnimate, Allegro, CogVideoX-I2V, Vchitect-2.0, LTX-Video, Wan2.1), Spatia leads by a wide margin on average score (69.73 vs. 60.64 for the best, CogVideoX-I2V) and on camera control (75.66 vs. 38.27), reflecting the benefit of explicit 3D point-cloud conditioning over latent camera embeddings. On the RealEstate reconstruction test, Spatia beats Voyager (PSNR 18.58 vs. 17.79) and all other baselines (FlexWorld 16.25, ViewCrafter 15.78, VMem 14.62, SEVA 13.07). In the closed-loop memory evaluation, Spatia's Match Accuracy of 0.698 nearly doubles that of Voyager (0.507) and ViewCrafter (0.447), confirming superior spatial memory retention. The only metric where Spatia trails a static-scene baseline is camera control (75.66 vs. 93.20 for InvisibleStitch), but those methods sacrifice all dynamic content and long-horizon consistency to achieve that score.

## Relation to Prior Work

Spatia builds on the Wan2.2 video diffusion backbone and Flow Matching training objective, augmenting them with a ControlNet-based conditioning pathway for 3D scene point cloud projections. It departs from prior memory-based video generation methods (Voyager, VMem, ViewCrafter, FlexWorld) that either restrict output to static scenes or rely on frame-level retrieval, by introducing an explicit 3D scene point cloud as persistent, iteratively-updated spatial memory via visual SLAM (MapAnything). The camera control mechanism also differs from latent-encoding approaches (CameraCtrl, AnimateDiff) by directly rendering the point cloud along a user-specified trajectory, mirroring the 3DGS rendering pipeline for geometrically grounded conditioning.

## Why It Matters / Open Questions

Spatia addresses a core limitation of current video generation models—the inability to maintain spatial consistency when revisiting locations over long horizons—while simultaneously preserving dynamic entity generation, a capability that prior memory-based scene generation methods lack. The iterative SLAM update mechanism raises open questions about error accumulation over very long sequences (minutes to hours) and in highly dynamic scenes where static/dynamic disentanglement becomes ambiguous. Practical limitations include dependence on MapAnything's point cloud quality, the computational cost of maintaining and updating a global point cloud, and the current restriction to 720P resolution with 81-frame clips. The 3D-aware interactive editing capability suggests a path toward user-controllable world generation, but scalability to open-ended, multi-scene environments remains unexplored.
