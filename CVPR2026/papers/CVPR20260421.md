## Problem

High-resolution document images are essential for accurate parsing of fine-grained elements (small text, dense tables, formulas), but they cause a quadratic explosion in vision tokens and computational cost. The paper identifies that valid semantic regions occupy only ~39–60% of document area, meaning end-to-end VLMs waste substantial computation on redundant backgrounds. Existing token-compression strategies apply uniform reduction across all regions, which degrades fine-grained layout accuracy.
![Teaser figure](../imgs/CVPR20260421/cropped_page1_idx3.webp)

## Input / Output

The system accepts document images (PDF pages) at native resolution, with three model variants (S/M/L) supporting pixel ranges up to 235K, 392K, and 627K pixels respectively, processed via a NaViT-style dynamic-resolution encoder that avoids fixed tiling or distortion. Outputs are a fully structured document: text in Markdown, tables in OTSL format, formulas in LaTeX (distinguishing inline \(...\) from display \[...\]), charts as Markdown tables, and a predicted reading order that governs the final assembly sequence.

## Method

PaddleOCR-VL decouples layout analysis from element recognition into a coarse-to-fine pipeline. The coarse stage, VRFM, extends RT-DETR with a pointer network to jointly detect and classify document elements and predict an N×N pairwise reading-order matrix, outputting only the bounding boxes of valid regions. The fine stage, PaddleOCR-VL-0.9B, is a compact VLM combining a NaViT-style vision encoder (initialized from Keye-VL) for native-resolution processing, a 2-layer MLP projector with GELU, and the ERNIE-4.5-0.3B language model augmented with 3D-RoPE; it processes each cropped region independently at up to 2048 vision tokens. Training follows a two-stage recipe for each module: VRFM first trains the RT-DETR core (100 epochs, PP-DocLayout_Plus-L init) then freezes it to train the pointer network (200 epochs, GCE loss); the VLM first aligns modalities on 29M image-text pairs (1 epoch, LR 5e-5→5e-6) then fine-tunes on 2.7M task-specific samples (2 epochs, LR 5e-6→5e-7) covering OCR, table, formula, and chart recognition. This design reduces vision tokens by ~25–75% compared to full-page processing while achieving SOTA accuracy across all element types.

## Results

On OmniDocBench v1.5, PaddleOCR-VL-L achieves a state-of-the-art overall score of 92.62 with only 2,561 vision tokens and 0.9B parameters, surpassing the closest competitor MinerU2.5 (90.67, 3,256 tokens) by nearly 2 points while using 21% fewer vision tokens. It sets new records on all sub-metrics: lowest Text-Edit distance (0.035), highest Formula-CDM (90.90), best Table-TEDS (90.48), and best reading-order score (0.043). At the element level, PaddleOCR-VL-L also achieves SOTA on table recognition (TEDS 0.9046), formula recognition (CDM 0.9404), and chart recognition (RMS-F1 0.8440). In inference, it processes 1.62 pages/s with 42.1 GB VRAM, outperforming MinerU2.5 by 53% in page throughput and reducing GPU memory by 46% versus dots.ocr.

## Baselines & Comparisons

PaddleOCR-VL-L decisively outperforms the closest specialized VLM, MinerU2.5 (1.2B, 3,256 tokens), by 1.95 points in overall score (92.62 vs. 90.67) while using 21% fewer vision tokens and 25% fewer parameters. Against the general VLM Gemini-2.5 Pro (88.03) and Qwen2.5-VL-72B (87.02), it leads by 4.6 and 5.6 points respectively, despite having orders of magnitude fewer parameters. Compared to DeepSeek-OCR-Gundam-M (86.46, 1,854 tokens), which uses a similar token budget, PaddleOCR-VL-L gains over 6 points in overall score, demonstrating that targeted region focus outperforms uniform token compression. On element-level benchmarks, PaddleOCR-VL-L beats MinerU2.5 on table TEDS (0.9046 vs. 0.9005), formula CDM (0.9404 vs. 0.9187), and chart RMS-F1 (0.8440 vs. 0.8060 for PP-StructureV3), while also surpassing the 72B Qwen2.5-VL on text edit distance across all nine document categories. In inference speed, it processes 1.62 pages/s versus MinerU2.5's 1.06 pages/s (53% faster) and dots.ocr's 0.35 pages/s (4.6× faster), with comparable or lower GPU memory usage.

## Relation to Prior Work

PaddleOCR-VL decouples document parsing into a lightweight layout stage (VRFM, built on RT-DETR with a pointer network for reading-order prediction) and a compact 0.9B vision-language model for element recognition, departing from both end-to-end VLMs that process entire pages and VLM-assembled pipelines that suffer coordinate drift. Unlike uniform token-compression approaches such as DeepSeek-OCR, the coarse-to-fine design selectively discards redundant background regions before the VLM sees them, preserving fine-grained detail where it matters. The fine-grained stage draws on NaViT-style dynamic-resolution encoding (initialized from Keye-VL) and the compact ERNIE-4.5-0.3B language model with 3D-RoPE, positioning the work at the intersection of efficient detection and multimodal recognition.

## Why It Matters / Open Questions

By demonstrating that a 0.9B model with ~2,500 vision tokens can outperform 72B–241B general VLMs and 3B specialized parsers on document parsing, the paper validates that targeted computation on semantically relevant regions is a viable alternative to brute-force high-resolution processing. The 53% throughput gain and 46% memory reduction over the closest competitor (MinerU2.5) make this practically significant for high-volume, latency-sensitive deployments such as RAG pipelines and LLM training-data construction. Open questions include how the two-stage design handles extremely dense or multi-column layouts where VRFM localization errors could cascade, and whether the approach generalizes to non-Latin scripts or heavily degraded scans beyond the 109 languages tested.
