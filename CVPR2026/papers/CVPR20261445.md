## Problem

Current LLMs cannot reliably produce correct, complete code for complex 3D geometric vision tasks, yet no existing benchmark specifically measures this PhD-level coding ability. Generic code-generation benchmarks (HumanEval, SWE-bench) and paper-reproduction benchmarks (PaperBench, ResearchCodeBench) lack the domain-specific 3D geometric reasoning, long-context paper-to-code mapping, and hidden-test robustness required to diagnose this gap.

## Input / Output

Each problem feeds the LLM three components: a structured JSON of the full paper (parsed from PDF via MinerU OCR, organized by section), the source file with the target function body replaced by a *****EMPTY***** placeholder, and a standardized execution template defining imports and I/O interfaces. The model must output the missing function body as directly executable Python; correctness is judged solely by running the generated code in a sandbox against 10 auto-generated unit tests per problem, yielding a per-instance pass fraction averaged across all 100 problems.

## Method

GeoCodeBench is constructed through a semi-automated pipeline: 2025 top-venue (CVPR/ICCV/ICLR) 3D vision papers are parsed with MinerU, their official repositories are scanned with Cursor to propose 10–20 candidate functions, and 3D-vision experts manually retain 3–5 core geometric or algorithmic functions per repository whose bodies are masked. For each masked function, Cursor generates 10 diverse unit tests (covering default and degenerate edge cases) plus a standardized test template, all reviewed by human experts. Tasks are organized into a two-level taxonomy—General 3D Capability (Geometric Transformations, Mechanics/Optics Formulation) and Research Capability (Novel Algorithm Implementation, Geometric Logic Routing)—enabling fine-grained diagnosis. Evaluation is fully automatic and reproducible via sandboxed execution, and a context-ablation protocol (full paper vs. method-section-only vs. no paper) probes long-context scientific comprehension.

## Results

On GeoCodeBench (100 fill-in-the-blank 3D vision coding problems scored by unit-test pass rate), the best model GPT-5 achieves only 36.6% overall, with Claude-Sonnet-4.5 (31.1%), Gemini-2.5-Pro (30.4%), and Kimi-K2-Instruct (30.4%) following closely. A consistent gap appears between General 3D Capability (42.8% for GPT-5) and Research Capability (29.1%), with Novel Algorithm Implementation being the hardest sub-task across all models (12.4%–29.1%). The weakest model, Llama-3.1-405B-Instruct, scores just 14.3% overall, and even the strongest models fail to exceed 45% on any single axis.

## Baselines & Comparisons

GPT-5 leads overall (36.6%) with balanced strength across both General (42.8%) and Research (29.1%) axes, outperforming the runner-up Claude-Sonnet-4.5 by 5.5 points. Claude-Sonnet-4.5 is notably strong on Geometric Logic Routing (35.9%, the highest of all models) but lags GPT-5 on Novel Algorithm Implementation (19.7% vs. 29.1%). Among open-source models, Qwen3-Coder-480B (23.5%) and DeepSeek-R1 (21.0%) show partial competence in individual categories but underperform on Algorithm Implementation, while Llama-3.1-405B-Instruct (14.3%) trails all others by a wide margin. A key cross-model finding is that General 3D scores are positively correlated with Research scores (Pearson r = 0.76), yet every model scores substantially lower on Research tasks, indicating that strong geometric fundamentals are necessary but not sufficient for research-level implementation. Additionally, context ablations show that truncating papers at the Method section statistically outperforms full-paper input for most models, revealing that longer context does not reliably improve 3D coding performance.

## Relation to Prior Work

GeoCodeBench carves out a new niche at the intersection of code-generation benchmarks (HumanEval, MBPP, SWE-bench) and research-reproduction benchmarks (PaperBench, ResearchCodeBench, Paper2Code). While prior work evaluates either generic programming ability or whole-paper replication in general ML, none simultaneously targets domain-specific 3D geometric reasoning, function-level fill-in-the-blank implementation from scientific text, and hidden unit-test verification. The benchmark repurposes the docstring-to-function paradigm of HumanEval and the paper-to-code framing of ResearchCodeBench, but grounds both in the mathematical and geometric operators unique to 3D vision (epipolar geometry, Gaussian Splatting, optics formulation), a setting no existing benchmark covers.

## Why It Matters / Open Questions

The benchmark quantifies a substantial and previously unmeasured gap: even GPT-5 passes only 36.6% of 3D geometric vision coding tasks, and every tested model fails on at least one trivially simple function, suggesting that reliable 3D scientific coding is far from solved. The context-ablation finding—that truncating papers at the Method section outperforms full-paper input for most models—challenges the default assumption that more scientific context helps and points to unresolved long-context comprehension limitations. Open questions include whether the gap narrows with better long-context architectures, whether the creative-correctness phenomenon (mathematically equivalent but structurally different solutions) can be harnessed for automated research, and how the benchmark scales as 3D vision methods evolve rapidly.
