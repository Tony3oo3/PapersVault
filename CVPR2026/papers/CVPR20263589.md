## Problem

Modern 3D point cloud backbones like Point Transformer V3 interleave sparse convolution and attention at every hierarchy level, yet the respective roles of these operators remain unclear. The paper identifies that this uniform design wastes parameters on late-stage convolutions and compute on early-stage attention, and asks whether a stage-specific allocation of each operator can match or exceed performance at substantially lower cost.

## Input / Output

The method consumes raw, unstructured 3D point clouds (LiDAR scans for outdoor scenes, RGB-D captures for indoor scenes) with per-point coordinates and learned features. For semantic segmentation it outputs per-point class labels; for instance segmentation it feeds features into a PointGroup head to produce instance masks; for object detection it feeds a CenterPointPillar head (with no spatial downsampling to preserve small-object detail) to produce 3D bounding boxes with class, orientation, and velocity.

## Method

LitePT is a five-stage U-Net that assigns sparse convolution blocks (conv + linear + LayerNorm + residual) to the first three high-resolution stages and PointROPE-augmented local attention blocks to the last two low-resolution stages, with the transition point L_c=3 chosen via ablation. PointROPE replaces PTv3's parameter-heavy convolutional positional encoding by splitting each feature vector into three equal subspaces along x, y, z and applying standard 1D rotary positional embedding independently to each axis using the point's grid coordinates, yielding a parameter-free, rotation-friendly encoding. Three model sizes (S: 12.7M, B: 45.1M, L: 85.9M params) are provided, with the decoder simplified to linear projections for segmentation or mirrored stage-tailored blocks for instance segmentation. The design yields 3.6× fewer parameters, 2× lower memory, and 2× faster inference than PTv3 while matching or exceeding its accuracy across ScanNet, nuScenes, Waymo, and Structured3D.

## Results

LitePT-S (12.7M params) achieves 82.2 mIoU on nuScenes and 73.1 mIoU on Waymo, outperforming PTv3 (46.1M params) by +1.8 mIoU on both datasets while using 3.6× fewer parameters, 2× less inference memory (2.0G vs 4.1G), and 2.4× faster inference (21ms vs 51ms). On Structured3D, LitePT-S reaches 83.6 mIoU (val) vs PTv3's 82.4, and on ScanNet instance segmentation it achieves 64.9 mAP₅₀, a +3.2 point gain over PTv3. For Waymo object detection, LitePT attains 70.7 mean L2 mAP, marginally ahead of PTv3 (70.5) and substantially above PillarNet (67.2) and FlatFormer (67.2).

## Baselines & Comparisons

Against the state-of-the-art PTv3 (46.1M params), LitePT-S (12.7M params) wins on nuScenes (+1.8 mIoU), Waymo (+1.8 mIoU), Structured3D (+1.2 mIoU val), and ScanNet instance segmentation (+3.2 mAP₅₀), while being comparable on ScanNet semantic segmentation (76.5 vs 77.5 mIoU) and Waymo object detection (70.7 vs 70.5 mean L2 mAP). Against PTv2 (12.8M params, similar size), LitePT-S achieves +2.0 mIoU on nuScenes, +2.5 mIoU on Waymo, +4.6 mIoU on Structured3D, and +4.9 mAP₅₀ on ScanNet instance segmentation, while using 11× less memory and 6× less runtime than PTv2. Against the sparse convolution baseline MinkUNet (39.2M params), LitePT-S gains +8.9 mIoU on nuScenes, +7.2 mIoU on Waymo, and +4.3 mIoU on ScanNet. On Waymo object detection, LitePT edges out PTv3 by +0.2 mean L2 mAP and leads on Vehicle (+0.4 mAP) and Cyclist (+0.3 mAP) categories, while trailing slightly on Pedestrian (−0.2 mAP). The efficiency advantage is consistent: LitePT-S uses 60.3% less training memory and 51.2% less inference memory than PTv3, and even the largest variant LitePT-L (85.9M params) runs faster and uses less memory than PTv3.

## Relation to Prior Work

LitePT builds directly on Point Transformer V3 (PTv3), whose U-Net structure, serialisation sorting for local attention groups, and overall training protocol are retained, but fundamentally rethinks the role of its sparse convolution layers. While prior hybrid point cloud architectures (ConDaFormer, KPConvX, PointConvFormer) uniformly repeat an identical convolution+attention block at every hierarchy level, LitePT decouples the two operators and allocates them selectively: sparse convolutions in early, high-resolution stages for local geometry, and attention in deep, low-resolution stages for semantic context. The positional encoding component, PointROPE, adapts the parameter-free Rotary Positional Embedding (RoPE) from NLP to 3D point clouds, replacing PTv3's learned convolutional conditional positional encoding with a zero-parameter alternative.

## Why It Matters / Open Questions

The paper provides a clear, empirically validated design principle—'convolutions for low-level geometry, attention for high-level relations'—that offers practical guidance for 3D point cloud architecture design beyond LitePT itself. The 3.6× parameter reduction, 2× speedup, and 2× memory savings over PTv3 while matching or exceeding performance make LitePT a highly attractive lightweight backbone for deployment-constrained settings. An open question the authors raise is whether global (rather than local) self-attention in the late stages, where token counts are small, could further strengthen long-range context modelling and reduce inference time. The parameter-free PointROPE is also a broadly applicable component that could benefit other point cloud Transformer architectures.
