## Problem

When MLLMs fail at STEM visual reasoning, it is unclear whether the failure stems from perceptual deficiencies or reasoning limitations. Through systematic scaling analysis, the paper demonstrates that perception is the true bottleneck, yet existing work overwhelmingly targets reasoning enhancement and evaluates perception only through problem-solving accuracy as a proxy. Additionally, natural language suffers from 'descriptive aphasia' for complex STEM visuals, making it an inadequate medium for precise visual understanding.
![Teaser figure](../imgs/CVPR20260750/cropped_page0_idx1.webp)

## Input / Output

The method takes STEM images (spanning mathematics, physics, chemistry, and electrical engineering) as input and produces two complementary outputs: code-grounded natural language captions and executable Python code (using matplotlib) that faithfully reconstructs the original image. The training corpus ICC-1M contains over 1M image-caption-code triplets, while the evaluation benchmark STEM2Code-Eval consists of 1,000 manually verified image-code pairs where success is determined by deterministic code execution and visual similarity scoring rather than subjective judgment.

## Method

CodePercept establishes executable Python code as a perceptual medium through two training tasks: Code-Grounded Caption Generation, which uses verified code (augmented with execution-tracer logs) as ground truth to eliminate hallucinations in natural language captions, and STEM Image-to-Code Translation, which trains models to produce explanatory reconstruction code that captures spatial and quantitative details natural language cannot express. The training data is constructed via three pipelines—Image Reproduction, Image Diversity (abstracting STEM principles and re-instantiating them in novel visual contexts), and Solid Geometry Synthesis (parametric code templates)—followed by unified quality control filtering. Training proceeds in two stages: supervised fine-tuning on ICC-1M jointly optimizing both captioning and code generation, followed by GRPO reinforcement learning with composite rewards (format validity, execution success, code-level semantic equivalence, and image-level visual similarity) applied exclusively to the code generation task.

## Results

On the novel STEM2Code-Eval benchmark (1k images), CodePercept-32B-R1 achieves an average score of 65.75 (Image Score 68.97, Code Score 62.53, Exec Rate 95.9%), substantially outperforming the Qwen3-VL-32B-Instruct baseline (38.42) by +27.33 points. At smaller scales, CodePercept-4B-R1 (46.52) and CodePercept-8B-R1 (48.65) surpass much larger models including Qwen3-VL-Plus (43.17) and Seed1.6-Vision-Thinking (41.39). In the captioner-solver setup across six STEM benchmarks, CodePercept-8B-S1 achieves 63.32% average, outperforming Qwen3-VL-8B-Instruct (60.36%) by +3.0% and Qwen2.5-VL-72B (57.09%) by +6.2%.

## Baselines & Comparisons

CodePercept achieves large margins over all same-size baselines on STEM2Code-Eval: CodePercept-4B-R1 (46.52 avg) beats Qwen3-VL-4B-Instruct (25.49) by +21.03, CodePercept-8B-R1 (48.65) beats Qwen3-VL-8B-Instruct (28.41) by +20.24, and CodePercept-32B-R1 (65.75) beats Qwen3-VL-32B-Instruct (38.42) by +27.33. Notably, the 4B and 8B CodePercept models surpass substantially larger models: CodePercept-4B-R1 exceeds Qwen3-VL-Plus-Instruct (43.17) and Seed1.6-Vision-Thinking (41.39) by 3.35 and 5.13 points respectively. In the captioner-solver evaluation (Table 1), CodePercept-8B-S1 (63.32 avg) outperforms Qwen2.5-VL-72B (57.09) by 6.23 points and approaches frontier models like Claude-Opus-4.1-Thinking and GPT-5-Thinking. The S1 (SFT-only) models already show strong gains (e.g., CodePercept-4B-S1: 40.78 vs. 25.49 baseline), with the R1 (RL) stage providing additional 5-8 point improvements, confirming that reinforcement learning with execution-based rewards further sharpens code generation quality.

## Relation to Prior Work

This paper departs from the dominant MLLM research trajectory that focuses on enhancing reasoning (RL-based methods, cold-start thinking data, unimodal transfer) by arguing—through a controlled scaling analysis—that perception, not reasoning, is the true bottleneck in STEM visual tasks. It also moves beyond knowledge-distillation-based captioning (using GPT/Gemini as teachers) by proposing executable code as a hallucination-free perceptual medium, and extends domain-specific image-to-code work (UI, Chart, SVG) into the STEM domain with the dual purpose of evaluation and training. The code-grounded caption generation pipeline repurposes code not as an output target but as an intermediate verification layer for natural language, a role not previously explored in the MLLM literature.

## Why It Matters / Open Questions

The reframing of perception as the primary lever (rather than reasoning) could redirect significant research effort in the MLLM community, and the code-as-perception paradigm offers a principled, verifiable alternative to proxy metrics for measuring visual understanding. However, the approach is inherently constrained to matplotlib-renderable 2D STEM visuals (geometry diagrams, plots, circuit schematics), leaving open whether the paradigm generalizes to 3D scenes, photographs, or real-world STEM imagery. The scaling analysis, while compelling, is conducted on a single model family (Qwen3-VL) and a single evaluation dataset (MathVision), so the universality of the perception-bottleneck claim remains to be validated across architectures and domains.
