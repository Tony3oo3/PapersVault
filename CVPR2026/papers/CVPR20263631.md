## Problem

Existing feed-forward 3DGS methods bind Gaussians to a 2D pixel grid (V×H×W), causing view-biased densities, floaters, redundant primitives in plain regions, and sensitivity to occlusions and low-texture areas. The number of Gaussians grows linearly with input views and resolution, making scene-level reconstruction inefficient and geometrically inconsistent. This paper asks whether a feed-forward 3DGS representation can be defined directly in 3D space, independent of pixel alignment.

## Input / Output

The method takes V unposed RGB images (32–256 views at 1168×1752) and internally uses MapAnything to predict metric depths and camera poses, which are back-projected and downsampled via farthest-point sampling into a fixed set of ~247K 3D anchors determined by voxelizing the scene volume. The output is a compact set of anchor-aligned 3D Gaussians (4 per anchor, with centers constrained to a small offset around each anchor), from which novel-view images and depth maps are rendered at 448×672. Crucially, the Gaussian count remains constant regardless of the number of input views, unlike pixel-aligned baselines where it scales as V×H×W.

## Method

AnchorSplat decouples Gaussian placement from input pixels by anchoring them to sparse 3D geometric priors. A pretrained MapAnything module predicts depths and poses, which are back-projected and downsampled via FPS into N 3D anchors (N ≪ V×H×W). A 2D U-Net encodes each view's image, depth, and camera-ray embeddings; these 2D features are projected onto the anchors, and a 16-block transformer (640 channels) models inter-anchor spatial interactions before an MLP predicts 4 Gaussians per anchor (offset, opacity, scale, rotation, SH-0 color). A plug-and-play Gaussian Refiner then uses a pretrained ResNet-18 to extract multi-scale rendering-error features, back-projects them to 3D, and applies a Point Transformer to update Gaussian attributes in a residual fashion. Training is two-stage: the decoder is trained with combined L1+SSIM+LPIPS rendering loss, L1 depth loss, and opacity/scale regularizers, then frozen while the refiner is trained on rendering loss alone.

## Results

On ScanNet++ V2 with 32 input views and 4 novel views, AnchorSplat achieves the best PSNR (21.48 dB) and SSIM (0.79) among all compared methods, while also delivering the strongest depth accuracy with δ₁ = 0.94 and AbsRel = 0.066. Critically, AnchorSplat represents the scene with only 247,153 Gaussians—roughly 20× fewer than AnySplat (5,550,940)—and completes reconstruction in 5.52 s, compared to 6.83 s for AnySplat and 290–391 s for optimization-based 3DGS and Mip-Splatting. The Gaussian Refiner improves PSNR by 0.52 dB and LPIPS from 0.47 to 0.38 over the decoder-only variant (AnchorSplat*).

## Baselines & Comparisons

Against the optimization-based baselines, AnchorSplat dominates on every metric except LPIPS: it improves PSNR by ~1.5 dB over 3DGS (21.48 vs 19.98) and Mip-Splatting (21.48 vs 19.92), and achieves δ₁ of 0.94 versus 0.31 and 0.35 respectively, indicating far superior geometric consistency. Reconstruction time drops from 391 s (3DGS) and 290 s (Mip-Splatting) to 5.52 s. Against the primary feed-forward baseline AnySplat, AnchorSplat wins on PSNR (+1.28 dB), SSIM (+0.06), δ₁ (+0.23), and AbsRel (0.066 vs 0.16), while using approximately 20× fewer Gaussians (247K vs 5.55M) and finishing 19% faster (5.52 s vs 6.83 s). AnySplat retains a slight edge on LPIPS (0.32 vs 0.38), suggesting marginally better perceptual texture fidelity, but the gap narrows to 0.06. Across the extended view-count experiments (32/48/64 input views), AnchorSplat's Gaussian count remains fixed at 247,153 while AnySplat's grows linearly from 5.5M to 10.7M, and AnchorSplat consistently outperforms on PSNR, SSIM, and depth metrics in every setting.

## Relation to Prior Work

AnchorSplat departs from the dominant pixel-aligned feed-forward 3DGS paradigm (PixelSplat, MVSplat, AnySplat) where each 2D pixel spawns a 3D Gaussian, instead grounding Gaussians in 3D-space anchors derived from geometric priors (depth maps and camera poses from MapAnything, downsampled via farthest-point sampling). This shifts the representation from a V×H×W pixel grid to a fixed set of N 3D anchors, decoupling Gaussian count from input resolution and view count. The plug-and-play Gaussian Refiner, inspired by G3R's gradient-guided reconstruction, adds a lightweight correction stage that refines Gaussian attributes using rendering-error back-projection without retraining the decoder.

## Why It Matters / Open Questions

The ~20× reduction in Gaussian count (247K vs. 5.5M) while simultaneously improving PSNR and depth accuracy over AnySplat suggests that 3D-native, anchor-aligned representations are a more efficient and geometrically consistent formulation for scene-level feed-forward reconstruction than pixel-aligned ones. This has practical implications for robotics, AR, and navigation where memory and inference speed matter. However, the method's reliance on accurate geometric priors means that incomplete or noisy depth/pose estimates can leave uncovered regions, and the authors acknowledge that adaptive density control and dynamic Gaussian growth remain open problems. Evaluation is limited to a single dataset (ScanNet++ V2) and one primary feed-forward baseline, so generalizability to outdoor or large-scale scenes is untested.
