## Problem

Large VLMs store ever-growing KV caches during decoding, causing severe memory bottlenecks for long-context tasks with multiple high-resolution images or videos. Existing cache-reduction strategies (token eviction, quantization) either leave the hidden dimension unchanged or struggle with outlier sensitivity, and few works exploit the distinct low-rank structure of visual tokens to compress along the hidden dimension axis without discarding tokens.
![Teaser figure](../imgs/CVPR20261047/cropped_page2_idx0.webp)

## Input / Output

The method operates on standard VLM inference pipelines (LLaVA1.5, QwenVL, VideoLLaVA) where visual inputs are encoded into hundreds-to-thousands of tokens (e.g., 256–576 tokens per image) and concatenated with text prompt tokens. After the prefill phase, the stored KV cache is compressed in-place: each token's key/value vector of dimension HD is replaced by a low-rank factor of dimension R (e.g., R=64 vs. HD=5120), with separate compression for visual and textual tokens. The model still produces the same text answer, but the reduced cache footprint enables up to 4× larger batch sizes or longer context windows within the same GPU memory budget.

## Method

AttentionPack introduces two complementary mechanisms. First, multi-head compression: after prefill, key and value vectors are merged along the head axis and decomposed via SVD into a compressed cache (T×R) and a decompression matrix (R×HD), exploiting the empirically observed low intrinsic rank of visual tokens (up to 8× compression for LLaVA/QwenVL variants). Second, attention-aware partial decompression: at each decoding step, tokens are ranked by a moving-average of accumulated attention scores (Eq. 1), and only the top-r₁ fraction is decompressed at full rank R while the remainder uses a reduced rank R/4, cutting decompression FLOPs by up to 67.5%. The approach is plug-and-play (no retraining), compatible with eviction, 4-bit quantization, grouped-query attention, and can be fused into FlashAttention-style kernels to eliminate the decompression latency overhead.

## Results

On LLaVA1.5-7B, AttentionPack (Rkv=Rvv=64) achieves 76.88% accuracy on A-OKVQA, 52.44 ROUGE-L on OCR-VQA, and 34.59% on MMMU, matching or exceeding full KV caching (76.64/51.05/34.68) while reducing per-instance cache size by 5.09× (328.2 MB → 64.5 MB) and improving batch inference throughput by 54%. On VideoLLaVA-7B, AttentionPack achieves 8.11× cache reduction (1114.6 MB → 137.5 MB) with 69.21% on MSVD-QA and 55.47% on MSRVTT-QA, matching full KV caching (69.33/55.60) while enabling 60% faster batch decoding. Across all models, the method achieves 2.77×–8.11× cache compression with at most ~0.3% accuracy degradation relative to the closest baseline.

## Baselines & Comparisons

AttentionPack consistently outperforms all five baselines on cache reduction while matching or exceeding their accuracy. Against FastV [5], which provides no actual memory savings (1× reduction since tokens are skipped but not released), AttentionPack achieves 5.09× cache reduction on LLaVA1.5-7B with comparable or better accuracy (e.g., 76.88 vs 76.72 on A-OKVQA). Against ScissorHands [21] and H2O [32], both of which evict 50% of tokens for 2× reduction, AttentionPack achieves 2.5× more compression (5.09×) while maintaining higher accuracy (e.g., 76.88 vs 75.50 for ScissorHands on A-OKVQA; 76.88 vs 76.36 for H2O). Against Minicache [19], the closest competitor at 4.51× reduction, AttentionPack provides 12% more compression (5.09×) and 10 percentage points higher throughput gain (+54% vs +44%) while matching accuracy. Against KVQuant [13] (4-bit quantization, 82.1 MB cache), AttentionPack achieves a smaller cache (64.5 MB) with higher accuracy (76.88 vs 75.90 on A-OKVQA) and greater throughput improvement (+54% vs +49%). The only scenario where a baseline slightly edges out AttentionPack is FastV on OCR-VQA (52.62 vs 52.44 ROUGE-L), but FastV provides zero memory savings.

## Relation to Prior Work

This paper carves out a distinct niche within the KV-cache compression literature by applying SVD-based low-rank decomposition along the hidden dimension axis, as opposed to the dominant token-eviction (H2O, ScissorHands, FastV) and quantization (KVQuant, GEAR) approaches that operate along the sequential or bit-precision axes. It builds on the observation that visual tokens exhibit lower intrinsic rank than text tokens, and extends the low-rank projection idea from PALU [4] by performing compression across combined attention heads and separating visual/textual tokens. The attention-aware partial decompression mechanism repurposes the importance-tracking idea from eviction methods (H2O's accumulated attention scores) but applies it to modulate decompression rank rather than discard tokens entirely, and the fused-kernel integration follows FlashAttention's I/O-optimization philosophy.

## Why It Matters / Open Questions

The practical impact is significant for VLM deployment: an 8× reduction in KV-cache memory directly enables larger batch sizes (up to 4×) and longer context windows on the same hardware, which is a critical bottleneck for multi-image and video understanding workloads. The finding that aggressive compression of visual tokens can occasionally *improve* accuracy (e.g., +1.39% on OCR-VQA at rank 64) by filtering irrelevant visual information is a useful insight for practitioners. Open questions include how the method behaves with continuously growing context in long autoregressive generation, whether the SVD-based compression generalizes to architectures without a clear visual/textual token boundary, and how the decompression overhead scales with very large batch sizes where the parallelization benefit may saturate.
