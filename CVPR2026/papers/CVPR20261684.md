## Problem

Streaming video reasoning requires answering questions over an ever-growing temporal context where relevant evidence is extremely sparse. Existing approaches either stack all historical frames (causing attention collapse) or apply fixed-policy retrieval that is not task-adaptive, both of which fail to locate the small, decisive region in the past that actually settles a query. The paper reframes the core challenge as a temporal routing problem: identifying where to look, not how much to remember.

## Input / Output

The system consumes a continuous stream of video frames processed at two resolutions (8-second short window at 2 fps for high-fidelity present, 32-second medium buffer at 1 fps for recent structure) alongside interleaved text questions arriving at arbitrary timestamps. Only past frames up to the query time are accessible, enforcing a strict online protocol. The output is a text answer, but internally the model also generates a semantic retrieval query during the fine-reasoning phase that is more task-specific than the raw question (e.g., 'people in the living room' rather than 'Was there anyone there just now?').

## Method

OASIS maintains a three-tier hierarchical event memory: a high-fidelity short window, a medium-resolution buffer, and a multi-resolution Event Forest where each node stores keyframes, an LLM-generated text summary, an embedding, and a depth level. The Event Forest is bounded online (root set capped at 4 nodes) via a greedy merging strategy that fuses temporally adjacent root pairs with the highest cosine-similarity-minus-depth-penalty score, preserving hierarchical granularity. Reasoning proceeds in two phases: a coarse stage answers using only the short window, medium buffer, root summaries, and a QA summary; if the model signals insufficiency via a special tool-call token, a fine stage generates a semantic retrieval query, embeds it, and retrieves a small set of event nodes (with ancestor/descendant deduplication) plus one QA pair to condition the final answer. The entire pipeline is training-free and plug-and-play, sitting atop any streaming MLLM backbone without architectural modification.

## Results

On OVO-Bench, Qwen3-VL-8B + OASIS achieves 78.14% Perception Avg and 57.21% Backward Avg, surpassing the same backbone without OASIS (66.79% / 51.19%) by +11.35 and +6.02 points respectively. On StreamingBench, the same configuration reaches 78.22% Real-Time All, 49.60% MCU, and 48.40% SQA, outperforming the baseline by +5.39, +13.86, and +4.50 points. Cross-backbone evaluation on GLM-4.6V confirms plug-and-play gains of +13.43 (Perception) and +3.92 (Backward). Token consumption remains stable at ~10k per query regardless of video length, versus up to 29.5k for the full-context baseline.

## Baselines & Comparisons

OASIS (Qwen3-VL-8B) outperforms all online streaming baselines by large margins: StreamChat (50.12/47.39), Dispider (54.55/36.06), Flash-VStream (28.37/27.38), and VideoLLM-online (22.22/16.24) on Perception/Backward Avg. Against offline MLLMs, OASIS surpasses LLaVA-Video-7B (62.32/53.74), LLaVA-OneVision-7B (62.04/43.71), and Qwen2-VL-7B (50.98/43.73) on both subsets, and beats GPT-4o (64.46/60.75) on Perception but trails it on Backward (57.21 vs 60.75). OASIS also exceeds Gemini 1.5 Pro on Perception (78.14 vs 69.32) but falls short on Backward (57.21 vs 62.54), indicating the closed-source model retains an edge on very long-range recall. On StreamingBench, OASIS leads all online baselines (StreamChat 60.14, Qwen2.5-VL 65.99) on Real-Time All (78.22) and MCU (49.60 vs 40.73 for Gemini), though Gemini still leads on ACU (51.41 vs 42.74) and SQA (54.80 vs 48.40). The cross-backbone test on GLM-4.6V (+13.43 Perception, +3.92 Backward) confirms that gains are attributable to the memory policy rather than backbone-specific tuning.

## Relation to Prior Work

OASIS carves new ground at the intersection of streaming video understanding, hierarchical memory, and iterative RAG, without directly extending any single prior method. It departs from prior streaming MLLMs (VideoLLM-online, FlashVStream, StreamChat, Dispider) that use rigid retrieve-and-stack policies by introducing a two-phase coarse-to-fine reasoning protocol where retrieval is triggered only when the short context is insufficient. It also diverges from offline long-video retrieval methods (VideoTree, VideoMind) by maintaining a bounded, online-updated Event Forest that supports cross-query reuse without rebuilding search structures. The semantic-hypothesis-driven retrieval (generating an internal query from the model's reasoning before searching) draws on iterative RAG ideas but applies them to the streaming video setting for the first time.

## Why It Matters / Open Questions

The training-free, plug-and-play nature of OASIS makes it immediately deployable on top of any streaming MLLM backbone, and the bounded token cost (~10k stable vs. 29k+ growing) addresses a critical practical bottleneck for real-time applications like autonomous driving and AR glasses. A key limitation is the dependence on the base LLM's instruction-following quality: gains are substantially larger with Qwen3-VL-8B (+11.35 Perception) than Qwen2.5-VL-7B (+6.33), suggesting the agentic policy will underperform on weaker backbones. Open questions include how the Event Forest scales to hours-long streams, whether the text-summary-based retrieval can be augmented with visual embeddings for more precise grounding, and whether the two-phase protocol can be extended to proactive (rather than reactive) memory access.
