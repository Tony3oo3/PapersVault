## Problem

Existing code information retrieval models are predominantly text-centric, treating code as plain text and ignoring the visual and structural aspects inherent in programming artifacts such as web interfaces, data visualizations, SVGs, and UML diagrams. No prior benchmark or unified model systematically evaluates or supports retrieval across the full spectrum of code-related visual modalities (screenshots, charts, vector graphics, schematic diagrams, software engineering diagrams) combined with natural language and source code.

## Input / Output

Each query (text, code, image, or a composed multi-modal combination) is paired with a natural-language instruction that explicitly specifies the retrieval direction and domain context (e.g., 'retrieve the code that matches this image'), which is prepended to the query before encoding. Text sequences are truncated to 256 tokens by default (extended to 512 in ablation for structure-heavy domains like SVG), and the vision encoder processes images at Qwen2VL's native resolution. The model outputs a single L2-normalized embedding vector per input via EOS token pooling, and retrieval is performed by ranking candidates via cosine similarity in the shared embedding space.

## Method

CodeMMR is initialized from Qwen2VL-2B-Instruct and fine-tuned with LoRA (r=8, bf16) using an InfoNCE contrastive objective (temperature 0.02) over in-batch and hard negatives, with the vision encoder frozen and only language-model parameters updated. The key design is instruction-based multimodal alignment: a natural-language instruction is prepended to every query to disambiguate retrieval intent across heterogeneous tasks (text-to-code, image-to-code, text+image-to-code, code-to-image, etc.), allowing a single encoder to handle all retrieval paradigms without task-specific heads. Training data is drawn from the newly introduced MMCoIR benchmark, which unifies 10 datasets across five visual domains, eight programming languages, and eleven libraries, providing paired image-code-text triples with standardized instructions. The model is trained for 1000 steps with a global batch size of 512 on 8 A100 GPUs (~30 hours), and an ablation shows that mixing in general-purpose multimodal retrieval data (VLM2Vec corpora) does not improve generalization, indicating MMCoIR alone provides sufficient cross-domain supervision.

## Results

On the MMCoIR benchmark, CodeMMR (2B) achieves an average nDCG@10 of 68.0 and Hit@1 of 65.4 across five visual domains (WebUI, Data Charts, SVG, Schematic Diagrams, UML), outperforming the strongest baseline VLM2Vec-v2 (2B) by 10.0 points on nDCG@10 (68.0 vs. 58.0). UML retrieval reaches 100% Hit@1 in both directions, while SVG remains the most challenging domain (MMSVG image-to-code nDCG@10 = 9.4). In retrieval-augmented code generation, CodeMMR improves Execution Rate by +10.0 on ChartMimic Direct and Visual Accuracy by +9.4 on WebCode2M-Mid over the no-retrieval baseline.

## Baselines & Comparisons

CodeMMR (2B) outperforms all five baseline families across the MMCoIR benchmark. Against the strongest general-purpose multimodal retriever, VLM2Vec-v2 (2B), CodeMMR gains +10.0 nDCG@10 on average (68.0 vs. 58.0), with particularly large margins on SVG (+9.2) and Data Charts (+11.7). Compared to GME (7B), which is 3.5× larger, CodeMMR still leads by +14.2 nDCG@10 (68.0 vs. 53.8), demonstrating that task-specific code-multimodal alignment matters more than raw model scale. The 7B VLM2Vec and LamRA baselines trail even further (28.2 and 36.3 nDCG@10 respectively), while the original UniIR models score below 16. Fine-tuning UniIR on MMCoIR training data (UniIR-FT) recovers some ground (42.9 nDCG@10) but remains 25 points behind CodeMMR, confirming that the Qwen2VL-based architecture with instruction-conditioned contrastive training is critical. On unseen domains (Table 3), CodeMMR also leads: e.g., 94.8 vs. 85.9 Hit@1 on DiagramGenBenchmark (code-to-image) and 100.0 vs. 89.0 on ChartEdit (code-to-image).

## Relation to Prior Work

This paper extends the multimodal embedding literature (VLM2Vec, GME, UniIR, LamRA) by introducing code as a first-class modality alongside text and images in a shared retrieval space. While prior code IR work (CoIR, CoQuIR, CodeXEmbed) treats code purely as text, and prior multimodal retrieval work ignores code entirely, CodeMMR bridges both lines by jointly encoding natural language, source code, and visual outputs (web UIs, charts, SVGs, diagrams, UML) through instruction-conditioned contrastive learning on a Qwen2VL backbone. The training setup directly follows VLM2Vec's InfoNCE-based framework, but the key conceptual departure is treating code and its rendered visual output as distinct yet aligned modalities rather than reducing code to a text string.

## Why It Matters / Open Questions

MMCoIR is the first benchmark to systematically evaluate retrieval across the code–image–text triangle, and it reveals that state-of-the-art multimodal models essentially fail on structured code domains (SVG scores near 0% for most baselines), exposing a significant gap between general-purpose multimodal embeddings and code-specific retrieval. The finding that mixing in large-scale general multimodal data (VLM2Vec corpus) provides no measurable benefit challenges the common practice of data mixing for generalization. Open questions remain: SVG retrieval is still far from solved (~15–19% Hit@1 even for CodeMMR), compositional queries (text+image→code) remain weak, and the paper itself flags long-context retrieval and fine-grained dimensional retrieval (text, layout, color) as important future directions.
