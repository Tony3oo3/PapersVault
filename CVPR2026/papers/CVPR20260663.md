## Problem

Creating articulated 3D assets (objects with movable parts and joints) remains a critical bottleneck for robotics, VR/AR, and simulation, as existing datasets contain only thousands of manually annotated instances. Prior generation methods rely on visual or structural priors (images, meshes, part graphs) and training-based architectures that hit a scalability ceiling when objects have many parts, making complex objects like a 20-key keyboard intractable to generate end-to-end.

## Input / Output

The system takes a single free-form text prompt as input and produces a complete articulated 3D object encoded as executable code that compiles to a URDF file. The code is hierarchically structured from parametric shape primitives (Three.js functions like BoxGeometry) through parts to links, with each link carrying a 3D mesh and SE(3) pose, and each joint specifying type, position, motion axis, and limits. No visual prior, prebuilt 3D asset, or part annotation is required.

## Method

LAM formulates articulated object generation as a unified code-generation task and implements a multi-agent pipeline of specialized LLM and VLM modules operating in closed-loop. A Link Designer (GPT-4o) decomposes the prompt into a hierarchical part structure; a Geometry Coder (Gemini-2.5-pro) writes Three.js code defining each link's shape and pose; an Articulation Coder (o3) generates joint code specifying parent-child pairs, joint types, positions, and axes, with a Joint Assembly Solver propagating pose updates down the kinematic chain. Geometry and Articulation Checkers, powered by 2D VLMs (Gemini-2.5-flash) and 3D VLMs (PointLLM), render multi-view images and motion sequences, then provide targeted corrective feedback (e.g., misaligned parts, wrong door-opening direction) that drives iterative code refinement over up to three rounds. The paper also introduces LAMBench, a 2K-pair dataset of text–code–articulated-object triplets, used to instruction-tune open-source models like Qwen3-VL-8B for zero-shot deployment.

## Results

On the joint prediction success rate, LAM* (using commercial LLMs) achieves 77.1% on the Five Classes subset and 68.2% on all 46 General Classes of Part-Mobility, substantially outperforming the strongest baseline Articulate Anything (40.3% and 48.9% respectively). On visual-semantic alignment and articulation quality (Table 2), LAM* attains the highest CLIP score (31.94), BLIP score (63.76), and GPT-5 articulation pass rate (77.0%) among all compared methods. For in-distribution generation quality, LAM* records the best MMD (0.0149), COV (0.6871), and 1-NNA (0.3599), confirming both fidelity and diversity of generated objects.

## Baselines & Comparisons

LAM* decisively outperforms all six baselines across every reported metric. Against Real2Code [57], LAM* achieves 77.1% vs. 13.5% joint prediction success rate on Five Classes — a 63.6-point gap — and against URDFormer [3], 68.2% vs. 14.6% on General Classes. The closest competitor, Articulate Anything [18], is surpassed by LAM* on success rate (77.1% vs. 40.3%), CLIP (31.94 vs. 28.23), BLIP (63.76 vs. 56.99), and GPT-5 pass rate (77.0% vs. 65.3%). On generation quality metrics, LAM* beats CAGE [26] (MMD 0.0149 vs. 0.0193; COV 0.6871 vs. 0.6064; 1-NNA 0.3599 vs. 0.5319) and ArtFormer [46] (MMD 0.0149 vs. 0.0292; COV 0.6871 vs. 0.5213). SINGAPO [27] is outperformed on CLIP (31.94 vs. 30.43), BLIP (63.76 vs. 56.21), and GPT-5 (77.0% vs. 58.8%), with the gap widening on OOD and Open-World classes where SINGAPO fails to produce sensible objects. Notably, even the zero-shot open-source variant (Qwen3-VL-8B) narrows the gap to Articulate Anything on GPT-5 (66.1% vs. 65.3%), and finetuning on LAMBench closes it further to 69.3%.

## Relation to Prior Work

This paper departs from the dominant paradigm of articulated object generation that relies on visual or structural priors (images, meshes, part graphs) by formulating the problem as pure text-to-code generation. While Real2Code and Articulate-Anything also use LLMs to produce URDF, LAM unifies geometry and articulation in a single hierarchical code representation (shape primitives → parts → links) and introduces a closed-loop multi-agent pipeline where VLM-powered Checkers iteratively refine the code. The approach also repurposes the Three.js library as a parametric geometry API for LLMs, a design choice not seen in prior articulated-object work, and introduces LAMBench as the first dataset pairing text, code, and articulated objects for instruction-tuning open-source models.

## Why It Matters / Open Questions

By demonstrating that a code-based multi-agent system can generate complex, multi-part articulated objects (e.g., keyboards with 20 keys) from text alone, LAM addresses a critical bottleneck for robotics simulation, VR/AR, and embodied AI where articulated 3D assets are scarce and expensive to annotate. The LAMBench dataset and the finding that instruction-tuning a modest open-source model (Qwen3-VL-8B) on it yields meaningful gains (36.8%→51.6%) suggest a path toward democratizing articulated asset creation. Open questions include whether the approach scales to truly novel object categories beyond the 46 Part-Mobility classes, whether the heavy reliance on frontier commercial LLMs (GPT-4o, Gemini-2.5-pro, o3, Claude-4.1-Opus) can be replaced by smaller models, and whether the generated URDFs are sufficient for downstream physics-based simulation without manual correction.
