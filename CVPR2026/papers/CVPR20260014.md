## Problem

Existing multi-modal agent benchmarks are largely confined to web browsers and general-purpose desktop applications, failing to capture the professional software workflows (e.g., SolidWorks, ChemDraw, Adobe Suite, ANSYS) that dominate real-world scientific and industrial practice. No prior work provides a hierarchical capability taxonomy for professional software manipulation or a reproducible evaluation environment covering these complex, domain-specific tools.
![Teaser figure](../imgs/CVPR20260014/cropped_page0_idx0.webp)

## Input / Output

Agents receive a natural-language task instruction and observe the environment through screen captures, optionally augmented with a simplified accessibility tree or Set-of-Marks annotations over a Windows 11 VM running 13 fixed-version professional applications. Task completion is verified by execution-based scripts that inspect final system states and output artifacts (e.g., MSE thresholds for image edits, parsed configuration files for VSCode), returning a binary 1.0/0.0 score. The human-in-the-loop evaluation additionally records intervention count and human operation time per task, enabling measurement of collaborative efficiency beyond autonomous success.

## Method

ProSoftArena introduces a five-level capability hierarchy (L1 atomic GUI operations → L2 single-software workflows → L3 cross-application pipelines → L4 open-ended creative tasks → L5 project-level orchestration) and curates 456 expert-annotated tasks across 6 disciplines, 20 subfields, and 13 professional applications, each mapped to a specific level. The evaluation platform runs an isolated Windows 11 VM via Docker with snapshot-based deterministic resets, formalizing agent-environment interaction as a POMDP where MLLMs or specialized agents predict keyboard/mouse actions from observations. A unique human-in-the-loop paradigm adds two collaboration modes—Human-Initiated Takeover (expert corrects critical errors in real time) and Agent-Initiated Assistance (agent invokes an ASK_ACTION tool under uncertainty)—to quantify collaborative efficiency. Ablations probe visual grounding inputs (SoM, A11y tree, OmniParser-v2 detections), domain-knowledge injection via knowledge cards, and action-history length to derive design principles for more capable professional-software agents.

## Results

On ProSoftArena, the best-performing agent (Agent-S) achieves only 48.6% success rate on L1 (basic GUI operations) and 17.1% on L2 (software-level tasks), while Claude 4 Computer Use reaches 45.1% (L1) and 20.6% (L2). All evaluated agents—both MLLM-based and specialized—completely fail on L3 cross-application workflows (0.0% success rate). Among MLLM-based agents, GPT-5 with Screenshot+A11y observation leads at 42.5% (L1) and 11.8% (L2), while the best open-source model Qwen2.5-VL reaches only 11.7% (L1) and 1.6% (L2) under screenshot-only input.

## Baselines & Comparisons

The benchmark evaluates 8 agent backbones across three observation modalities. Specialized computer-use agents dominate: Agent-S achieves the highest L1 score (48.6%) and Claude 4 Computer Use the highest L2 score (20.6%), both substantially outperforming the best MLLM (GPT-5 at 42.5% L1 / 11.8% L2 with A11y, or 18.7% L2 with SoM). Among MLLMs, GPT-5 consistently leads over GPT-4o (1.4% L1) and o3 (5.3% L1) under screenshot-only input, with the gap widening at L2 where GPT-5 reaches 7.6% versus 0.0% for GPT-4o. Open-source models trail significantly: Qwen2.5-VL (11.7% L1) outperforms GLM-4.5V (0.6% L1) but both fall far below proprietary models. UI-TARS-1.5-7B, despite being a specialized agent, underperforms all MLLMs on L1 (10.0%), suggesting its 7B scale is insufficient for professional software GUIs. Critically, no agent—regardless of architecture or observation type—succeeds on any L3 cross-application task, exposing a complete capability gap in multi-software workflow execution.

## Relation to Prior Work

This paper extends the computer-use agent benchmarking tradition (OSWorld, WindowsAgentArena, ScienceBoard, TheAgentCompany) by shifting the evaluation domain from general-purpose daily applications to professional, domain-specific software (SolidWorks, ChemDraw, AutoCAD, ANSYS, Adobe Suite, etc.). It departs from prior work in two key ways: (1) introducing a five-level hierarchical capability taxonomy (L1–L5) that no existing benchmark provides, and (2) incorporating a structured human-in-the-loop evaluation paradigm with both human-initiated takeover and agent-initiated assistance modes. The agent architectures evaluated (Agent-S, UI-TARS, Claude 4 Computer Use, MLLM-based agents) are drawn directly from the existing computer-use literature, but the professional software environment and execution-based evaluation scripts are novel contributions.

## Why It Matters / Open Questions

The benchmark reveals a stark capability cliff: even the strongest agent (Claude 4 Computer Use) achieves only 20.6% on software-level tasks (L2) and 0% on cross-application pipelines (L3), exposing that current agents cannot compose atomic GUI operations into coherent professional workflows. The finding that agents almost never invoke the agent-initiated assistance tool (AIA mode yields negligible gains over autonomous execution) suggests a fundamental lack of calibrated self-assessment, pointing to a critical open problem in agent design. The hierarchical taxonomy and the observation that richer inputs can paradoxically degrade performance (SoM+Screenshot+A11y underperforms SoM+Screenshot) provide actionable design guidance. Open questions include whether domain-knowledge injection scales beyond single applications, how L5 project-level orchestration should be evaluated, and whether the L1→L2 gap can be closed through better planning architectures rather than stronger backbones.
