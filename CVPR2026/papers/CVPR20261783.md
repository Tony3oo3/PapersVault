## Problem

Existing GUI grounding methods either perform single-step full-screen prediction without explicit attention control, or use forward-only iterative cropping that irreversibly accumulates errors once the trajectory drifts from the target. Neither paradigm supports the adaptive, reversible perceptual search that humans naturally employ—scanning, refining, and redirecting attention when uncertainty arises—making grounding unreliable on high-resolution, element-dense professional interfaces.
![Teaser figure](../imgs/CVPR20261783/cropped_page0_idx0.webp)

## Input / Output

The method takes a high-resolution GUI screenshot (S_full ∈ R^{H×W×3}) and a natural language instruction T, and outputs pixel coordinates (x, y) of the target UI element. Rather than predicting directly on the full screenshot, DRS-GUI first identifies a compact instruction-relevant sub-region R_best, then the base MLLM performs coordinate prediction only within that region. The framework is entirely training-free and plug-and-play, requiring no fine-tuning of the underlying MLLM; it relies on off-the-shelf OmniParser V2 for UI element parsing and instructor-large for semantic embeddings.

## Method

DRS-GUI introduces a search-then-predict paradigm with two cooperating modules. The UI Perceptor parses the current region into structured UI elements via OmniParser V2, computes instruction-conditioned semantic relevance scores using domain-prefixed embeddings from instructor-large, and executes three perceptual actions: Focus (contract toward high-relevance elements), Shift (relocate to spatially separated cues), and Scatter (expand to recover broader context). The MCTS Action Planner schedules these actions over a region search tree using the UCT policy, balancing exploration and exploitation under a fixed rollout budget (N=8, depth H=3). A composite region quality reward—combining interaction-weighted relevance, UI coverage consistency, and semantic concentration—evaluates each candidate region and guides backpropagation, enabling the planner to backtrack from uninformative regions rather than committing to a single narrowing path. The highest-reward region is selected and forwarded to the base MLLM for final localization, reducing visual clutter by ~64% in input area and ~54% in UI element count on average.

## Results

On the high-resolution ScreenSpot-Pro benchmark, DRS-GUI yields a 14.1% absolute improvement for Qwen2.5-VL-7B (26.8% → 40.9%) and 14.3% for UGround-V1-7B (31.4% → 45.7%), making UGround-V1-7B+DRS-GUI the best open-source result, surpassing UI-TARS-7B (35.7%) and Claude Comp.Use (17.1%). On ScreenSpot-V2, gains are 4.0% (Qwen2.5-VL-7B: 86.5% → 90.5%) and 4.2% (UGround-V1-7B: 87.6% → 91.8%). On ScreenSpot-V1, improvements are 4.0% (84.9% → 88.9%) and 3.6% (86.3% → 89.9%). Notably, the smaller Qwen2.5-VL-3B+DRS-GUI (28.7% on ScreenSpot-Pro) surpasses the much larger OS-Atlas-7B (18.9%), demonstrating that adaptive perceptual search matters more than raw model scale.

## Baselines & Comparisons

On ScreenSpot-Pro, UGround-V1-7B+DRS-GUI (45.7%) outperforms all prior open-source baselines by a wide margin: UI-TARS-7B (35.7%, −10.0%), OS-Atlas-7B (18.9%, −26.8%), Claude Comp.Use (17.1%, −28.6%), UGround-7B (16.5%, −29.2%), and Aria-UI (11.3%, −34.4%). Even the 3B model with DRS-GUI (28.7%) surpasses OS-Atlas-7B (18.9%) and Claude Comp.Use (17.1%), indicating that the dynamic search mechanism compensates for model capacity. On ScreenSpot-V2, UGround-V1-7B+DRS-GUI reaches 91.8%, beating OS-Atlas-4B (70.1%) and UGround-7B (73.3%) by over 18 points, while Qwen2.5-VL-7B+DRS-GUI (90.5%) surpasses SeeClick (53.4%) and CogAgent-18B (47.4%). On ScreenSpot-V1, both augmented models (88.9% and 89.9%) substantially exceed SeeClick (53.4%), CogAgent-18B (47.4%), and GPT-4V (16.2%). DRS-GUI consistently improves icon/widget grounding more than text grounding (e.g., +9.0% on icon vs. +16.8% on text for UGround-V1-7B on ScreenSpot-Pro), confirming that dynamic region search is most beneficial where visual ambiguity is highest.

## Relation to Prior Work

DRS-GUI departs from the two dominant GUI grounding paradigms—static full-screen prediction (SeeClick, OS-Atlas, UGround) and forward-only iterative zoom-in (ECP, R-VLM, DiMo-GUI, LASER)—by introducing a reversible, MCTS-driven region search that can backtrack and redirect attention. It repurposes MCTS from game planning [28] into a perceptual action scheduler over three human-inspired operations (Focus, Shift, Scatter), grounded by OmniParser V2 [21] for UI structure and Instructor-Large [29] for instruction-aligned semantic scoring. The visual search literature on saliency-guided fixation [31, 37, 38] provides the conceptual motivation, but DRS-GUI is the first to formalize GUI grounding as a region-level tree search with a composite quality reward rather than a point-level scanpath.

## Why It Matters / Open Questions

The training-free, plug-and-play nature makes DRS-GUI immediately applicable to any existing MLLM without retraining, and the 14% gain on ScreenSpot-Pro demonstrates that adaptive perceptual search can compensate for model-scale limitations (Qwen2.5-VL-3B + DRS-GUI surpasses OS-Atlas-7B). However, the approach adds non-trivial inference overhead (8 MCTS iterations, each requiring full UI parsing and embedding), and the hand-designed composite reward (α, β, γ weights) may not transfer to unseen interface types without retuning. Open questions include whether the reward could be learned end-to-end, whether the method extends to video or animated GUIs, and whether the gains persist as base MLLMs themselves improve in spatial reasoning.
