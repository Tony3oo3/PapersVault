## Problem

Generating vector animations from multi-modal instructions is hindered by the fact that raw Lottie JSON files contain extensive invariant structural metadata and formatting tokens, causing models to waste capacity on boilerplate rather than learning meaningful geometric and motion priors. Existing approaches either decouple appearance from motion (applying motion priors to static vector graphics) or produce raster outputs that lack the editability and resolution independence of vector formats, leaving no end-to-end framework for multi-modal Lottie generation.
![Teaser figure](../imgs/CVPR20263426/cropped_page0_idx0.webp)

## Input / Output

OmniLottie accepts interleaved multi-modal instructions in three configurations: a text prompt alone (Text-to-Lottie), a reference image paired with a text prompt (Text-Image-to-Lottie), or a rendered animation video (Video-to-Lottie). The output is a valid Lottie JSON file normalized to a 512×512 canvas with a 0–16 timestamp range, encoding shapes, effects, and temporal dynamics as a hierarchical layer structure. Generated tokens are detokenized back into the full JSON format, preserving all layer types (precomp, solid, null, shape, text) and their animation parameters.

## Method

The core contribution is a Lottie tokenizer that flattens the hierarchical Lottie JSON into a compact sequence of animation commands and control parameters, removing redundant structural metadata while preserving full generative flexibility. Continuous parameters (temporal, spatial, transformation, style) are mapped to discrete tokens via an offset-based scheme: token(x, t) = ⌊x · s_t⌋ + o_t, where type-specific scale factors and vocabulary offsets prevent token conflicts. The model is built on Qwen2.5-VL (3B) with randomly initialized Lottie vocabulary embeddings added to the token space, and is trained end-to-end with standard cross-entropy loss to autoregressively generate Lottie tokens conditioned on multi-modal instructions. This design lets the pretrained VLM's instruction-following and multimodal reasoning capabilities transfer directly to vector animation synthesis, while the compact token representation reduces sequence length and focuses learning on semantically relevant content.

## Results

On the Real Subset of MMLottie-Bench, OmniLottie achieves 88.3% success rate with FVD 202.14 and Motion Alignment 5.94/10 for Text-to-Lottie, 93.3% SR with FVD 180.27 and Object Alignment 5.10/10 for Text-Image-to-Lottie, and 88.1% SR with FVD 227.11, PSNR 16.08, and DINO 0.92 for Video-to-Lottie. These results substantially outperform all baselines, which range from 0% (Qwen2.5-VL, Gemini3.1-Pro) to 91.3% (Livesketch) success rate. On the Synthetic Subset, OmniLottie maintains its lead with 82.1% SR (T2L), 92.9% SR (TI2L), and 80.7% SR (V2L), confirming generalization beyond the training distribution.

## Baselines & Comparisons

OmniLottie decisively outperforms all general-purpose LLM/VLM baselines: Qwen2.5-VL (3B) and Gemini3.1-Pro achieve 0% success rate across all tasks, while GPT-5 reaches only 12.7% (T2L), 28.0% (TI2L), and 9.2% (V2L) success with FVD values 3–5× worse than OmniLottie. Against the commercial tool Recraft (the strongest T2L baseline), OmniLottie improves success rate from 77.3% to 88.3%, reduces FVD from 300.70 to 202.14, and raises Motion Alignment from 4.68 to 5.94, though Recraft retains a slight CLIP edge (0.2950 vs. 0.2748). For Text-Image-to-Lottie, OmniLottie dominates the optimization-based methods AniClipart and Livesketch on every quality metric (FVD 180.27 vs. 266.46 and 868.18; Object 5.10 vs. 4.51 and 2.84) while running 8–14× faster (88.57 s vs. 1212 s and 723 s). In Video-to-Lottie, OmniLottie is the only method achieving high success (88.1%) and leads on all reconstruction metrics (PSNR 16.08, SSIM 0.82, DINO 0.92) over GPT-5 and Gemini3.1-Pro. DeepSeekV3, evaluated only on T2L, trails OmniLottie by a wide margin in both success rate (9.3% vs. 88.3%) and FVD (671.80 vs. 202.14).

## Relation to Prior Work

This paper extends the visual autoregressive generation paradigm—previously applied to images, videos, SVG, and 3D—into the domain of vector animation by introducing a Lottie-specific tokenizer that converts hierarchical JSON into compact command-parameter sequences. It departs from prior vector animation approaches (AniClipart, Livesketch) that decouple appearance from motion by applying external motion priors to static vector graphics, and from direct JSON-generation attempts by general-purpose LLMs (GPT-5, DeepSeek) that struggle with Lottie's rigid nested structure. The model is built on Qwen2.5-VL as a pretrained multimodal backbone, inheriting its instruction-following and cross-modal reasoning capabilities while adding a new Lottie vocabulary for autoregressive token generation.

## Why It Matters / Open Questions

OmniLottie provides the first unified, end-to-end framework for multi-modal vector animation generation (text, image+text, and video inputs), lowering the barrier to professional-quality Lottie creation and enabling direct integration into design pipelines. The release of MMLottie-2M (2M annotated animations) and MMLottie-Bench (450 real + 450 synthetic evaluation samples) establishes infrastructure that was previously absent for this task. Key open questions include whether autoregressive decoding can be made fully reliable (constrained decoding, RL with renderability rewards), how well the approach generalizes to complex multi-layer animations beyond the 512×512 / 16-frame normalization, and whether agentic integration with tools like After Effects can close the remaining gap to professional workflows.
