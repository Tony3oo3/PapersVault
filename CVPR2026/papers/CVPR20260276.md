## Problem

Despite rapid progress in pixel-space video generation (Sora, Kling, Veo), no existing system can produce vector animation, a dominant medium for UI/UX motion design, branding, and web applications that offers resolution-independence, structural editability, and compact parametric motion. The core obstacles are twofold: no tokenizer exists that can encode hierarchical geometric primitives together with temporal keyframe dynamics into a compact autoregressive token sequence, and no large-scale vector animation dataset has ever been assembled.
![Teaser figure](../imgs/CVPR20260276/cropped_page0_idx0.webp)

## Input / Output

The model accepts flexible multimodal conditioning—natural language text, a reference RGB image for style guidance, or a short keyframe video for motion transfer, in any combination—and autoregressively emits a sequence of 441 specialized Lottie tokens that detokenize losslessly into a valid Lottie JSON file. The output is a layered, resolution-independent vector animation with explicit keyframes, Bézier easing curves, and parametric transforms, typically 10–50× smaller than an equivalent raster video and directly editable in tools like After Effects or Lottie players.

## Method

LottieGPT extends Qwen2.5-VL-7B with a purpose-built Lottie Tokenizer that performs depth-first traversal of the Lottie JSON tree, encoding animation metadata, layers, shapes, and properties with schema-aligned special tokens rather than treating JSON as plain text. The key innovation is keyframe-based temporal compression: instead of storing per-frame geometry, the tokenizer encodes only keyframe timestamps, property values, and cubic Bézier easing functions, achieving up to 98% token reduction for long animations while preserving motion quality. Training follows a two-stage curriculum—Stage 1 learns static vector composition on 750K Lottie-converted SVG images (50% text-only, 50% image-conditioned), then Stage 2 introduces temporal dynamics on 60K Lottie animations (34% text-only, 33% text+first-frame, 33% text+keyframe video)—using standard causal language modeling with cross-entropy loss at a 40K-token context window on 8×H20 GPUs.

## Results

On the vector animation task (text-only input), LottieGPT-7B-Stage2 achieves CLIP 0.9566, SSIM 0.9776, LPIPS 0.0366, DINOv2 0.9301, JSON structural similarity 0.8062, and 96.96% valid rendering rate, substantially outperforming the best few-shot LLM baseline (Claude Sonnet 4.5: CLIP 0.8485, JSON 0.0522, 45.22% valid). On the text+image animation task, LottieGPT reaches CLIP 0.9743, SSIM 0.9886, and 97.83% valid rate, surpassing Sora 2 (CLIP 0.8903), Kling (CLIP 0.8661), and Veo 3.1 (CLIP 0.8487) on all visual metrics. For static vector graphics (text-only), LottieGPT-Stage1 achieves CLIP 0.9331 and SSIM 0.8103, outperforming OmniSVG-7B (CLIP 0.8321, SSIM 0.5627) by a wide margin across all metrics.

## Baselines & Comparisons

LottieGPT decisively outperforms all baselines on the novel vector animation task. Against few-shot LLMs (GPT-5, Claude Sonnet 4.5, Gemini 2.5 Pro, DeepSeek-V3.1, Qwen3-235B), LottieGPT-Stage2 achieves 0.8062 JSON structural similarity versus ≤0.0522 for all LLMs, and 96.96% valid rendering rate versus 10.87–51.74%. Against video generation models (Sora 2, Kling, Veo 3.1) on the text+image animation task, LottieGPT leads on every visual metric (e.g., CLIP 0.9743 vs. 0.8903 for Sora 2; SSIM 0.9886 vs. 0.8661 for Sora 2) and additionally produces structurally valid, editable Lottie JSON (0.9195 JSON score) that raster video models cannot provide. On static vector graphics, LottieGPT-Stage1 surpasses OmniSVG-7B by ~10 points in CLIP (0.9331 vs. 0.8321) and ~25 points in SSIM (0.8103 vs. 0.5627) under text-only input, and outperforms StarVector-8B by a wider margin (CLIP 0.9201 vs. 0.7662) under text+image input. The ablation comparing LottieGPT against a variant finetuned on raw Lottie JSON (without the custom tokenizer) shows the tokenizer is critical: JSON similarity jumps from 0.0089 to 0.8062 and valid rate from 22.61% to 96.96%, confirming that hierarchical keyframe tokenization is essential for learning animation structure.

## Relation to Prior Work

This paper extends the emerging line of VLM-based structured data generation (slides, 3D meshes, LEGO sequences, indoor layouts) to the domain of temporal vector animation, adapting the 3D animation production paradigm (mesh → skeleton → motion) to 2D Lottie animations. It departs from prior SVG generation work (OmniSVG, StarVector) by introducing a dedicated Lottie Tokenizer that encodes hierarchical geometry, keyframes, and Bézier easing curves in a single token stream, rather than treating vector code as plain text. The autoregressive generation framework builds on Qwen2.5-VL, while the static-to-dynamic curriculum training strategy is motivated by the observation that joint static+dynamic training leads to unstable convergence due to the large token-count disparity between the two data types.

## Why It Matters / Open Questions

This is the first system to natively generate resolution-independent, fully editable vector animations from multimodal inputs, addressing a gap that pixel-based video models (Sora, Kling, Veo) fundamentally cannot fill for professional motion design, UI/UX, and web workflows. The 660K Lottie animation dataset and LottieBench benchmark establish the first large-scale resource and evaluation protocol for this domain. Open questions include whether the approach scales to longer, more complex multi-scene animations, whether the Lottie-specific tokenizer generalizes to other animation formats (e.g., SMIL, CSS animations), and whether the 7B model's performance ceiling can be raised with larger backbones or more training data (GPU constraints limited training to 750K/60K samples).
