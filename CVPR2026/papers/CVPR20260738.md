## Problem

Open-world images offer vast scene diversity at near-zero cost, but they lack the physically grounded, executable action sequences that robot policy learning requires. Existing real-to-sim-to-real methods demand explicit multi-view scene reconstruction, limiting them to specific workspaces, while video-generation-based approaches cannot produce explicit robot actions or handle long-horizon, instruction-driven tasks. IGen addresses this gap by converting a single unstructured image into scalable, grounded visuomotor training data without any human annotation or physics-based scene reconstruction.
![Teaser figure](../imgs/CVPR20260738/cropped_page0_idx0.webp)

## Input / Output

The method takes a single open-world RGB image (no camera intrinsics required; Metric3Dv2 provides metric depth) and a natural-language manipulation instruction as the sole inputs. It outputs temporally synchronized RGB video frames rendered from composite point clouds, paired with SE(3) end-effector pose trajectories sampled at a fixed frame rate. Spatial randomization over feasible tabletop placement points generates up to 1,000 diverse training samples per input image, enabling large-scale data synthesis from one photograph.

## Method

IGen operates as a three-stage pipeline: (1) Scene Reconstruction lifts the image into a dense 3D point cloud via monocular depth estimation, segments task-relevant objects with SAM, extracts spatial keypoints via DINOv2 features and K-means clustering, and completes object geometry with a 3D generative model repositioned by 6D pose estimation; (2) Action Planning feeds the keypoint-annotated image and instruction to a VLM, which decomposes the task into sub-stages and generates Python control functions that compute SE(3) end-effector poses from spatial anchors, with a grasp prior model handling pre-manipulation contact; (3) Observation Synthesis applies rigid-body transformations to the object point cloud during the grasp interval (Eq. 1), composites the static background, dynamic object, and robot point clouds, and renders the sequence frame-by-frame through a virtual camera aligned with the original viewpoint. The key design choice is using point clouds as the universal intermediate representation, enabling both structured geometric editing (rigid transforms for object motion) and photorealistic rendering without requiring a full physics simulator.

## Results

On scene reconstruction fidelity (Table 1), IGen achieves an average PSNR of 27.00 vs. 17.26 for the Real-to-Sim (Simpler) baseline, with LPIPS scores up to 5.13× lower (e.g., LPIPS₁: 0.063 vs. 0.324), indicating substantially higher visual consistency with the original images. On the DreamGen Bench, IGen produces nearly twice as many Instruction Following successes as the best video-generation baseline when evaluated by Qwen-3-VL-Plus, and leads on Physics Alignment across all three evaluator models. In real-world robot deployment, a policy fine-tuned on 1,000 IGen-generated samples reaches 66.7% average success rate, surpassing 58.3% from 1,000 human-teleoperated samples collected under the same time budget, while IGen requires only 8.3 GB GPU memory and ~18.6 s per sample (~30× and ~200× faster than TesserAct and Cosmos-Predict2, respectively).

## Baselines & Comparisons

Against the Real-to-Sim (Simpler) digital-twin baseline, IGen dominates on every visual fidelity metric: average PSNR improves from 17.26 to 27.00, SSIM from 0.683 to 0.852, and LPIPS drops by 3–5× across all three network backbones, confirming that point-cloud-based reconstruction preserves scene appearance far more faithfully than mesh-based simulation. Against the video-generation baselines TesserAct (CogVideoX-5B I2V) and Cosmos-Predict2 (Cosmos-Predict2-2B-Video2World), IGen wins on both Instruction Following and Physics Alignment on the DreamGen Bench, producing nearly 2× more instruction-following successes (Qwen-3-VL-Plus evaluator) and generating physically coherent, temporally consistent motions where the baselines exhibit geometric distortions and temporal discontinuities. In terms of computational efficiency, IGen is ~30× faster per sample than TesserAct and ~200× faster than Cosmos-Predict2 while using only 8.3 GB of GPU memory. In the real-world robot transfer experiment, IGen-generated data (1,000 samples) outperforms an equal time budget of human teleoperation (58.3% → 66.7% average success rate), and even 100 IGen samples (44.5%) surpass 100 human samples (19.4%), demonstrating that the synthesized data is not only comparable but superior to human-collected demonstrations for policy fine-tuning.

## Relation to Prior Work

IGen positions itself against two main lines of prior work: (1) real-to-sim-to-real pipelines (Simpler, RoboGSim, DiscoverSE) that require multi-view captures of specific workspaces to build simulation environments, and (2) video-generation-based approaches (Cosmos-Predict2, TesserAct, DreamGen) that predict future observations but lack explicit, executable robot actions. IGen departs from both by accepting a single arbitrary open-world image as input, converting it to a 3D point cloud via monocular depth estimation and 3D generative reconstruction, and then using VLMs to plan SE(3) end-effector trajectories that drive rigid-body point cloud synthesis rather than learned video generation. The keypoint-based spatial representation follows REKEP, and the base policy is pi_0 fine-tuned with LoRA, but the unified pipeline of image-to-point-cloud-to-VLM-planning-to-rendering is the novel architectural contribution.

## Why It Matters / Open Questions

The core practical impact is that a single open-world image can be expanded into 1,000 diverse training samples via spatial randomization, and policies fine-tuned on these samples match or exceed those trained on human-teleoperated data collected in the same time budget. This directly addresses the data bottleneck for generalist robot policies without requiring robot access or multi-view scene scanning. Key limitations include reliance on monocular depth quality, VLM reasoning accuracy for complex multi-object interactions, and the fact that real-world validation covers only three tasks on a single Franka arm. Open questions include whether the approach scales to long-horizon tasks with many sequential interactions, whether point cloud rendering captures sufficient visual detail for fine-grained manipulation, and how the method handles scenes where the object geometry is poorly reconstructed from a single view.
