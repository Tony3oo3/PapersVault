## Problem

Existing VLM-based graph QA methods rely on a single fixed graph topology representation (GTR) for all queries, ignoring model-specific cognitive biases and task-specific representational preferences. This one-size-fits-all strategy leads to incorrect answers or unnecessarily lengthy responses, as different tasks (e.g., cycle detection vs. shortest path) benefit from fundamentally different visual or textual encodings of the same graph.
![Teaser figure](../imgs/CVPR20263028/cropped_page0_idx0.webp)

## Input / Output

The system takes a graph topology (node set and edge set) and a natural-language question as input. The graph is pre-rendered into one of eight candidate GTRs—five visual layouts (dot, neato, circo, fdp, sfdp via Graphviz) and three textual formats (edge set, adjacency list, adjacency matrix)—and the GTR Router selects the optimal one before the VLM sees it. The VLM Reasoner then produces a text answer using only the selected GTR, requiring no access to model internals. For large real-world graphs, n-hop node-surrounding subgraphs replace full-graph inputs to respect locality.

## Method

DynamicGTR introduces a lightweight GTR Router (DeBERTaV3-base, ~3 GPU-hours to train) that dynamically selects the optimal GTR from a pool of eight representations for each query, operating entirely at the input stage so it is compatible with closed-source VLMs. The selection is guided by a Graph Response Efficiency (GRE) score that linearly combines log-transformed accuracy and negative log token cost, with a user-tunable hyperparameter α controlling the accuracy–brevity trade-off. A 7K-sample GTR Preference dataset is constructed by probing a VLM across seven graph algorithmic tasks (graphs sampled from Erdős-Rényi models) and recording which GTRs achieve the highest GRE per question. The router is trained as a multi-label classifier via binary cross-entropy on these preferences, and at inference it assigns the best GTR per query, enabling the VLM to answer with both higher accuracy and lower token consumption without any fine-tuning of the VLM itself.

## Results

On in-domain graph algorithmic tasks (GVLQA-BASE), DynamicGTR with GPT-4o achieves up to 96.1% accuracy on Connectivity with only 38.8 tokens (vs. 412.2 tokens for the best baseline GraphDPR), and 89.3% on Cycle Detection with 75.9 tokens (vs. 626.4 for GraphDPR). With Gemini-2.5 Pro, DynamicGTR reaches 100% accuracy on Connectivity, Maximum Flow, Bipartite Graph Matching, and Hamilton Path while reducing token consumption by 30–75% over all baselines. On out-of-domain real-world applications (link prediction and node classification across six datasets), DynamicGTR consistently outperforms baselines in both accuracy and token efficiency, e.g., achieving 76.5% accuracy with 143.2 tokens on ca-GrQC link prediction (vs. 73.1%/203.1 for GITA) and 64.5% with 99.2 tokens on Cora node classification (vs. 56.8%/184.4 for GITA).

## Baselines & Comparisons

DynamicGTR outperforms all four baselines (CoT, NLGraph, GraphDPR, GITA) on the majority of in-domain tasks for both GPT-4o and Gemini-2.5 Pro. The largest accuracy gains appear on Cycle Detection (89.3% vs. 68.7% for GraphDPR, 64.7% for GITA with GPT-4o) and Bipartite Graph Matching (92.0% vs. 82.5% for GITA), where visual GTRs are strongly preferred. Token consumption reductions are dramatic: DynamicGTR uses 38.8 tokens on Connectivity vs. 273–412 for baselines, and 75.9 on Cycle Detection vs. 326–626. On Topological Sorting, DynamicGTR (40.8%) roughly ties GITA (40.9%) in accuracy but saves ~31% tokens; on Shortest Path, it gains ~9–12 points in accuracy over all baselines while maintaining comparable token usage. For out-of-domain transfer (link prediction, node classification), DynamicGTR beats the strongest baseline GITA by 3.4–8.1 points in accuracy and 25–46% in token reduction across all six real-world datasets, without any additional training.

## Relation to Prior Work

This paper builds on the emerging line of VLM-based zero-shot graph QA, which has explored both textual GTRs (NLGraph, GraphWiz, GPT4Graph) and visual GTRs (GITA, VisionGraph) to present graph topology to multimodal models. The key departure is rejecting the 'one-size-fits-all' assumption that a single fixed GTR suffices for all queries; instead, DynamicGTR constructs a pool of eight diverse GTRs and trains a lightweight DeBERTaV3-base router to select the optimal representation per question, guided by a novel Graph Response Efficiency (GRE) metric that jointly optimizes accuracy and token cost. Unlike graph-aware VLMs (GraphLLM, InstructGLM, Gcoder) that require fine-tuning or architectural modification, DynamicGTR operates entirely at the input stage, preserving zero-shot compatibility with closed-source models like GPT-4o and Gemini-2.5 Pro.

## Why It Matters / Open Questions

The framework provides a practical, plug-and-play mechanism for improving VLM-based graph reasoning without any model modification, with the router trainable in under 3 GPU-hours. The clear task-level GTR preference patterns (perceptual tasks favor visual layouts, computation-heavy tasks favor textual encodings) offer actionable insight for practitioners designing graph prompts. Open questions include whether the preference patterns discovered on small Erdős-Rényi graphs (N≤30) generalize to heterogeneous, attributed, or temporal graphs, and whether the router's classification-based formulation can capture more nuanced, context-dependent GTR combinations. The dramatic token savings (e.g., 86% reduction on connectivity tasks) suggest broader applicability to cost-sensitive deployment of VLMs on structured data.
