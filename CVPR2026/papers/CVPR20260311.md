## Problem

Existing efficient long-video understanding methods for MLLMs face a fundamental trade-off: RAG-based approaches excel at localizing key frames but fail at holistic temporal understanding, while visual compression methods still require feeding all compressed features into the model at once, hitting input-length limits. This paper asks whether MLLMs can instead process videos iteratively—forming and recalling visual memories like a human viewer—thereby breaking the input-length ceiling entirely.
![Teaser figure](../imgs/CVPR20260311/cropped_page0_idx0.webp)

## Input / Output

The method takes a long video sampled at 512 or 1024 frames (divided into clips of 8 frames each) and a text question, and produces a text answer. Crucially, the video is consumed iteratively clip-by-clip rather than all at once; at each step the MLLM only sees the current clip plus a small window of prior context memories, keeping per-step memory constant. The final answer is generated from only a small subset of recalled memory fragments (13k tokens for LLaVA-Video, 7k for LLaVA-OneVision), not the full video, enabling theoretically infinite-length processing.

## Method

FlexMem is a training-free, plug-and-play visual memory mechanism built on top of existing video-MLLMs (LLaVA-Video, LLaVA-OneVision). Its core is a Dual-Pathway Compression (DPC) design that, at each iterative clip-encoding step, produces two distinct compressed KV-cache memories: a Context Memory scored by how well each token aggregates past context and propagates forward (used for inter-clip information transfer), and a Local Memory scored by intra-clip saliency (stored in a persistent memory bank for later recall). For memory reading, FlexMem offers two strategies: an encoding-based approach that reuses cross-modal attention weights between the question and video clips during encoding, and a faster MemIndex that fits a linear regression to select only K representative cache layers and k top-saliency visual tokens, reducing the index to a compact tensor independent of the encoding pass. The iterative loop—encode clip with prior context memories, write local memory to bank, optionally recall long-term memories—allows the model to process videos of arbitrary length with constant per-step memory overhead.

## Results

On LLaVA-Video 7B, FlexMem achieves 85.9 on TimeScope, 51.0 on LVBench, 72.4 on MLVU, 64.7 on Video-MME (All), and 63.6 on LongVideoBench (All), surpassing the base model by +32.2% on TimeScope and +19.7% on LVBench. Under the constrained setting of a single 3090 GPU (Table 2), FlexMem (512/1024 frames, 13k input tokens) outperforms AKS by 3.9% and AdaRETAKE by 5.2% on average across all five benchmarks. On the streaming backward-tracing task (OVOBench), LLaVA-Video + FlexMem + MemIndex reaches 54.4 average, exceeding the best online baseline Dispider (36.1) by 18.3 points and approaching the offline Gemini-1.5-Pro (62.5).

## Baselines & Comparisons

Against VideoRAG baselines, FlexMem outperforms AKS on LVBench (51.0 vs. 47.4), MLVU (72.4 vs. 72.0), Video-MME (64.7 vs. 65.3, slight loss), and LongVideoBench (63.6 vs. 62.7) with LLaVA-Video, while matching AKS closely on TimeScope (85.9 vs. 85.4). FlexMem also beats Video-RAG (58.7 on LongVideoBench) and Panels (64.4 on Video-MME) by clear margins. Against visual compression methods, FlexMem surpasses AdaRETAKE on LVBench (51.0 vs. 49.6), Video-MME (64.7 vs. 63.6), and LongVideoBench (63.6 vs. 59.4) while using only 13k input tokens versus AdaRETAKE's 40k; it also outperforms DToMA (59.6 on LongVideoBench) and BOLT (57.0 on LongVideoBench). In the single-3090-GPU setting (Table 2), FlexMem retains 99.5% of its full performance while AdaRETAKE drops 3.3% on average due to reduced frame capacity (384 vs. 1024 frames). Compared to SOTA Video-MLLMs (Table 3), FlexMem + LLaVA-Video (7B) matches or exceeds Gemini-1.5-Pro on Video-MME (64.7 vs. 75.0, loss) but surpasses it by 54.1% on LVBench (51.0 vs. 33.1) and outperforms Qwen2.5-VL on TimeScope (85.9 vs. 81.0) and LongVideoBench (63.6 vs. 56.0). On the streaming OVOBench task, FlexMem + MemIndex (54.4 avg) beats all online baselines—Dispider (36.1), Flash-VStream (27.4), VideoLLM-online (17.7)—by 18+ points, though it still trails the offline Gemini-1.5-Pro (62.5) and InternVL-V2 (43.4 on 64 frames).

## Relation to Prior Work

FlexMem positions itself at the intersection of two established lines of work on long video understanding: retrieval-augmented generation (RAG) methods like AKS and Video-RAG that select keyframes, and visual compression methods like AdaRETAKE and Video-XL that reduce per-clip token footprints. It departs from both by reframing the problem as an iterative visual memory mechanism—mimicking human video watching—where KV caches serve as a persistent memory bank that is written incrementally and read selectively at answer time. The dual-pathway compression (context memory for temporal continuity, local memory for salient evidence) and the MemIndex fast-retrieval module are novel architectural contributions layered on top of standard MLLM backbones (LLaVA-Video, LLaVA-OneVision) without any fine-tuning.

## Why It Matters / Open Questions

The training-free, plug-and-play nature of FlexMem makes it immediately applicable to any KV-cache-based MLLM, and the ability to process 1k+ frames on a single 3090 GPU while matching or exceeding proprietary models (GPT-4o, Gemini-1.5 Pro) on several benchmarks is practically significant for resource-constrained deployments. Open questions include whether the memory mechanism degrades gracefully on extremely long videos (hours to days), how well it generalizes to tasks requiring fine-grained temporal reasoning beyond QA, and whether the linear-regression fitting in MemIndex remains stable as video length or question diversity grows. The paper does not explore multi-turn dialogue or active memory management (e.g., forgetting or consolidation), which would be natural next steps for a true memory system.
