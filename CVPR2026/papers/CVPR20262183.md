## Problem

High-resolution UI screenshots are patchified into thousands of visual tokens (≥85.4% of the sequence), incurring substantial computational overhead and diluting attention. While general visual token pruning methods reduce this cost for natural images, they break positional continuity in M-RoPE and cause severe accuracy collapse on precise UI grounding. This paper pioneers the task of efficient UI grounding, addressing both what to remove (instruction-irrelevant or homogeneous regions) and how to remove it (position-preserving rather than naive dropping).
![Teaser figure](../imgs/CVPR20262183/cropped_page0_idx0.webp)

## Input / Output

The method takes a high-resolution UI screenshot (2K at 2560×1440 or 4K at 3840×2160) and a natural language instruction as input. The screenshot is patchified into a grid of visual tokens (e.g., ~5319 tokens at 100% retention for Qwen2.5-VL), which are then reduced to a configurable fraction (30–100%) before entering the LM decoder. The output is a coordinate-free grounding: the LM emits action tokens, and an action head produces a patch-level attention map over the retained visual tokens to identify the target UI element region.

## Method

FocusUI comprises three key components. First, an Instruction-to-Patch saliency score fuses a bounding-box overlap signal with a rule-based UI-graph prior (union-find over 4-neighborhood patches with ℓ₂ distance thresholding) to down-weight large homogeneous regions, providing dense per-patch supervision. Second, a lightweight Query-Guided Saliency Scorer predicts per-patch relevance via matrix-product similarities between patch embeddings and instruction text embeddings in the VLM backbone, trained with a KL-divergence objective. Third, POSPAD replaces each contiguous sequence of dropped visual tokens with a single learnable <pos_pad> marker placed at the sequence's last index, preserving M-RoPE positional continuity without modifying the downstream LM architecture. The full system is trained end-to-end with a combined objective (saliency KL + next-token prediction + action-attention loss) and integrates with Qwen2.5-VL and Qwen3-VL backbones using GUI-Actor's coordinate-free grounding scheme.

## Results

On ScreenSpot-Pro, FocusUI-7B (r=100%) achieves 48.3% average accuracy, surpassing GUI-Actor-7B (44.6%) by 3.7 points and Jedi-7B (39.5%) by 8.8 points. On ScreenSpot-V2, FocusUI-7B reaches 93.1% average, outperforming all 7B-scale baselines. Critically, even at 30% visual token retention, FocusUI-7B retains 45.1% on ScreenSpot-Pro (only a 3.2-point drop) while achieving 1.44× faster inference and 17% lower peak GPU memory compared to the full-token setting.

## Baselines & Comparisons

FocusUI-7B outperforms all same-scale GUI grounding baselines: it beats GUI-Actor-7B by 3.7 points on ScreenSpot-Pro (48.3 vs 44.6) and by 1.0 on ScreenSpot-V2 (93.1 vs 92.1), and surpasses Jedi-7B by 8.8 points on ScreenSpot-Pro (48.3 vs 39.5). It also exceeds the much larger UI-TARS-72B (38.1) and Qwen2.5-VL-32B (47.6) on ScreenSpot-Pro, demonstrating that instruction-guided token selection compensates for model scale. On OSWorld-G, FocusUI-7B (54.4) outperforms GUI-Actor-7B (49.5), Jedi-7B (54.1), and Gemini-2.5-Pro (45.2). On UI-Vision, FocusUI-7B (24.9) surpasses Jedi-7B (24.8) and UI-TARS-7B (17.6). In the pruning comparison (Table 5), general methods like Fast-V cause catastrophic 52.6% drops on ScreenSpot-V2 at 30% retention, while FocusUI's POSPAD strategy limits degradation to just 0.5 points, confirming that position-preserving selection is essential for precise UI grounding.

## Relation to Prior Work

FocusUI builds directly on GUI-Actor's coordinate-free visual grounding scheme, which grounds elements at patch embeddings via an action head rather than regressing coordinates. It departs from general visual token pruning methods (Fast-V, HiPrune, Vision-Zip) by identifying that their naive dropping strategy breaks M-RoPE positional continuity, causing severe accuracy collapse on precise UI localization. The instruction-to-patch saliency score draws on the UI-graph prior from ShowUI and fuses it with bounding-box overlap supervision, while the POSPAD mechanism is a novel position-preserving sequence transformation not present in prior pruning literature.

## Why It Matters / Open Questions

This is the first systematic study of efficient UI grounding, revealing that positional sensitivity in M-RoPE makes standard token pruning fundamentally incompatible with precise localization tasks—a finding that likely generalizes to other fine-grained spatial VLM tasks. The practical efficiency gains (1.44× speedup, 17% memory reduction at 30% retention with only 3.2-point accuracy loss) make high-resolution UI grounding more deployable. A key limitation is that FocusUI addresses only spatial token reduction; the authors note that temporal efficiency for multi-round, sequential UI interactions remains unexplored, and the method's compatibility with FlashAttention (no intermediate attention needed) is a practical advantage for production deployment.
