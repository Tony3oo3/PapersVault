## Problem

Modern mapping applications remain fundamentally point-and-click, offering no support for interactive, view-conditioned spatial queries over map viewports or for connecting first-person camera views to surrounding geospatial context. This gap is most acute in the last-100-meter of navigation and during in-situ local discovery, where users naturally combine spatial reasoning over maps with ego-centric perception, yet existing tools treat travel planning, navigation, and place discovery as isolated modules with brittle handoffs.

## Input / Output

Maps Plus consumes a live map viewport (vector or satellite) that is discretized into a quadkey-indexed grid, where each tile is annotated with detected visual/semantic attributes and fed as a structured visual prompt alongside the user's natural-language query; PAISA consumes a single first-person camera frame together with GPS coordinates, device heading, and destination coordinates. Outputs include grounded place names and descriptions tied to specific viewport regions, real-time relative bearing angles rendered as AR-style overlays, natural-language spatial scene descriptions (e.g., relational object positions), and XGBoost-ranked venue candidate lists with relevance scores.

## Method

IMAIA unifies two interoperable components—Maps Plus and PAISA—under a lightweight multi-agent orchestrator. Maps Plus converts the current viewport into a quadkey-indexed grid and applies Set-of-Mark-style visual prompting so that a multimodal LLM (GPT-4o) identifies salient entities per tile; detected entities are resolved via Azure Maps API and injected back into the LLM prompt for view-conditioned reasoning, boosting POI detection accuracy from ~43% to 89.8%. PAISA's Location Intelligence Agent encodes camera images and candidate place descriptors with CLIP, then ranks candidates with an XGBoost model over cosine similarity, geodesic distance, heading-consistency, and popularity features. The Interactive Navigation Agent computes the great-circle bearing to the destination and subtracts the user's device orientation to yield a compass-relative direction for AR guidance. The Spatial Understanding Agent is a Florence-2 model distilled from GPT-4o via a three-stage pipeline (entity extraction on 40k street-view images, YOLOWorld + Depth Anything V2 localization with GPT-4o relational annotation, and supervised fine-tuning on diverse spatial queries), achieving 84% accuracy and a 7.3× inference speedup (1.7 s vs. 12.4 s) over an agent-based baseline.

## Results

Maps Plus achieves 89.83% POI detection accuracy on a 4,300-query dataset across 10 US cities, nearly doubling the best baseline (Model + Verbose Location at 42.74%). The distilled Florence-2 spatial reasoning module reaches 84% accuracy (LLM-as-judge with o1) on 400 street-view images, compared to 27% for the 10×-larger Florence-VL 8B, while identifying ~7 salient objects per scene versus 4 for ASM v2. Inference runs at 1.7 s per query on a single V100, a 7.3× speedup over the 12.4 s agent-based pipeline. In last-100-meter navigation, bearing-aware guidance reduces walking time to 63.5% of turn-by-turn in turn-required scenarios and 32.1% in directly visible scenarios.

## Baselines & Comparisons

Against the three map-query baselines (Single Model, Model + Location, Model + Verbose Location), Maps Plus wins decisively: 89.83% vs. 39.30–42.74% accuracy, a ~47-point gain attributed to quadkey-based visual prompting and geospatial entity retrieval rather than any LLM fine-tuning. On spatial scene understanding, the distilled Florence-2 model outperforms Florence-VL 8B [3] by a wide margin (84% vs. 27% accuracy under o1-judged evaluation), demonstrating that task-aligned distillation is far more effective than parameter scaling for this task. Compared to ASM v2 [23], the proposed module achieves higher object recall (~7 vs. ~4 salient items per scene) while also supporting natural-language interaction that ASM v2 lacks. The XGBoost venue ranker beats both distance-only and CLIP-similarity-only baselines on every metric in Table 2, with the largest gap in Top-3 recall (92.8% vs. 77.5% and 68.1%). Finally, the end-to-end distilled model is 7.3× faster than the multi-step agent pipeline (1.7 s vs. 12.4 s per image), making real-time deployment feasible.

## Relation to Prior Work

This paper extends the Set-of-Mark visual prompting paradigm [25] from generic image regions to quadkey-indexed map tiles, creating a structured visual prompt for view-conditioned map VQA. It builds on prior LLM-based geospatial search systems (MapGPT Playground [29], context-aware conversational map search [30]) by adding explicit viewport-aware entity retrieval via Azure Maps, and on spatial VLMs (ASMv2 [23], SpatialVLM [2], SpatialRGPT [4]) by distilling GPT-4o's spatial reasoning into a compact Florence-2 model for real-time deployment. The multi-agent orchestration layer unifies these previously isolated capabilities—map-centric reasoning, camera-grounded place identification (via CLIP + XGBoost ranking), and bearing-aware navigation—into a single interactive framework, departing from prior work that treats each as a separate module.

## Why It Matters / Open Questions

IMAIA addresses a practical gap in the last-100-meter navigation and in-situ discovery experience where current point-and-click map tools and standalone VLMs both fall short, and its modular, model-agnostic design makes it a viable template for production geospatial assistants. The 7.3× inference speedup from distillation (1.7 s vs. 12.4 s) is practically significant for real-time AR-style guidance, and the finding that a task-aligned distilled model outperforms a ~10× larger general-purpose VLM (84% vs. 27%) suggests that targeted distillation can be more effective than parameter scaling for narrow spatial-reasoning tasks. However, the evaluation is limited in scale (400 street-view images, 50 ranking queries, 10 navigation scenarios, ~15 informal users), and robustness to GPS drift, occlusion, and multi-lingual or low-data urban environments remains untested, leaving open whether the framework generalizes beyond the curated test settings.
