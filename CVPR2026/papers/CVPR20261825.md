## Problem

In heterogeneous collaborative perception, agents equipped with different sensor modalities (e.g., LiDAR vs. camera) often never co-occur in any training scene, a situation the paper terms modality isolation. All existing alignment methods—whether based on spatially overlapping BEV features, shared ground-truth anchors, or contrastive supervision—require co-occurring observations, making them inapplicable when modality pairs lack any shared scene data. This gap prevents scalable, privacy-preserving collaboration across institutions that collect data independently.

## Input / Output

The ego agent ingests its own LiDAR point cloud or camera image (encoded via modality-specific backbones such as Point-Pillar, SECOND, VoxelNet, or LSS with ResNet-101/EfficientNet) and receives from neighbors only discrete code maps—integer indices of shape H×W into a codebook of size 16—rather than dense BEV features, compressing communication from H×W×C floats to H×W×log₂(16) bits (a 1024× reduction). The system outputs standard 3D object detection results (bounding boxes with AP30/50/70 metrics) and, during the communication phase, the compact code maps that serve as the transmitted representation.

## Method

CodeAlign operates in two plug-in stages that never modify the frozen encoder or backend. First, code space construction inserts a lightweight adapter and a learnable codebook (D=16) between encoder and backend for each modality; non-isolated modalities share a single codebook via group code space construction, so features from different sensors quantize into the same discrete space and align naturally. Second, FCF (Feature-Code-Feature) translation uses a one-to-many Code Translator—stacked ConvNeXt blocks with modality-specific output heads—that maps the ego's dense BEV feature directly to the target modality's code indices, which are then decoded by the target codebook into features already residing in the target's native feature space. Because each discrete index uniquely specifies a target-space embedding, the decoded features are inherently aligned without any spatial-overlap supervision. Training uses only local single-modality data with detection loss on the target backend, and a data-balancing strategy equalizes learning across multiple target heads, keeping total alignment parameters at ~0.8–1.5 M (8% of HEAL) while scaling linearly rather than quadratically with the number of modalities.

## Results

On OPV2V, CodeAlign achieves AP30 of 93.39 (m1+m2), 87.19 (m1+m7), and 89.77 (m1+m7+m2), outperforming HEAL by up to 4.74% AP30 in the LiDAR-camera isolated scenario (m1+m7). On DAIR-V2X, CodeAlign reaches AP30 of 82.03, 72.12, and 74.09 across three modality pairs, surpassing HEAL by 8.3–9.7% AP30. CodeAlign requires only 8% of HEAL's training parameters in the three-vehicle scenario (1.3M vs 16.0M) and reduces communication load by 1024× (0.03 MB vs 32 MB) by transmitting discrete code indices instead of dense features.

## Baselines & Comparisons

Against HEAL (the strongest baseline), CodeAlign wins on AP30 and AP50 across all three OPV2V scenarios (e.g., 87.19 vs 82.45 AP30 on m1+m7, a 4.74% gain) but trails slightly on AP70 in the three-vehicle case (77.73 vs 79.89), likely due to quantization effects. On DAIR-V2X, CodeAlign dominates HEAL by 8.3–9.7% AP30 across all modality pairs, with the largest gap on m1+m2 (82.03 vs 73.70). Against HMViT, CodeAlign substantially outperforms in cross-modal (LiDAR-camera) settings—gaining 12.97% AP30 on m1+m7—while HMViT actually degrades below the no-collaboration baseline on m1+m2 (70.31 vs 81.18), indicating it cannot handle modality isolation at all. CodeFilling, which shares a single codebook across all modalities, suffers severe degradation on LiDAR-camera pairs (44.03 AP70 on m1+m7 vs CodeAlign's 72.10), confirming that a unified codebook is insufficient for strong heterogeneity. In terms of efficiency, CodeAlign uses 8% of HEAL's training parameters in the three-vehicle scenario and transmits 1024× less data (0.03 MB vs 32 MB), making it the only method that simultaneously achieves top accuracy, minimal training cost, and low communication overhead.

## Relation to Prior Work

CodeAlign builds directly on HEAL's pyramid fusion backend and modality-variation protocol, but departs fundamentally from the spatial-correspondence alignment paradigm shared by HMViT, CodeFilling, STAMP, and GT-Space, all of which require co-occurring multi-modal observations for supervision. The key conceptual departure is replacing dense feature alignment with codebook-mediated discrete representation: rather than learning to map continuous BEV features across modalities, CodeAlign quantizes each modality into a compact code space and learns index-level translations (FCF) between them. This repurposes the codebook idea from CodeFilling (where it compresses communication) into an alignment mechanism that explicitly encodes representation consistency, eliminating the need for shared scene observations entirely.

## Why It Matters / Open Questions

Modality isolation is a practical bottleneck in real deployments where data from different sensor vendors or institutions never overlap in time or space, and CodeAlign's co-occurrence-free training protocol (local data only, no cross-institutional sharing) directly addresses data-privacy constraints that limit existing methods. The 1024× communication reduction and 8× training-parameter reduction make heterogeneous collaboration substantially cheaper to deploy at scale. However, evaluation is limited to two datasets with at most seven modalities and a small codebook (size 16), leaving open whether the discretization loss becomes problematic with larger codebooks, more diverse sensor types, or longer-range collaboration chains. The authors acknowledge that groupwise alignment at larger scale remains untested.
