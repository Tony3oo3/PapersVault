## Problem

Image-centric memory for embodied navigation is more end-to-end and robust than object-centric alternatives, but retaining hundreds of historical frames in a single context window is prohibitively expensive because each image contributes hundreds of visual tokens. Without strong visual compression, long histories overwhelm attention with redundancy and noise, making it infeasible to maintain the long-term spatial-semantic memory that lifelong navigation requires.
![Teaser figure](../imgs/CVPR20260921/cropped_page1_idx0.webp)

## Input / Output

The model consumes a sequence of historical RGB frames (720×640), their corresponding 6-DOF camera poses serialized as text tokens inserted immediately before each frame's visual tokens, and a natural-language instruction. It outputs a natural-language description of a navigation subgoal (either a frontier point or a target object) with 2D coordinates wrapped in special tags (e.g., <coordinate>x, y</coordinate>). Each frame is reduced from 598 native Qwen2.5-VL visual tokens to approximately 30 compressed tokens, allowing hundreds of frames to fit within a single context window.

## Method

AstraNav-Memory introduces a plug-and-play, ViT-native visual tokenizer built on frozen DINOv3-ViT-Base features. The compression pipeline applies N stages of PixelUnshuffle (rearranging each 2×2 spatial neighborhood into channels) followed by a stride-1 3×3 Conv + BatchNorm + SiLU block, then a final 2×2 patch-merger and 2D positional encoding, yielding 30 tokens per frame at N=2 (≈20× reduction). These compact tokens are fed directly into the first block of Qwen2.5-VL-3B's ViT, leaving the multimodal projector and language model entirely unchanged. The key design choices—using rearrangement rather than pooling to preserve geometric structure, freezing DINOv3 for stable mid-level semantics, and matching the output channel to the ViT hidden size—make the module a drop-in replacement that decouples the compressor from the policy. The full system is fine-tuned end-to-end on 1.5M navigation samples (OVON-500K plus GOAT lifelong datasets) with a learning rate of 1e-5 on 32 H20 GPUs, coupling perception, memory, and decision-making in a single supervised objective.

## Results

On GOAT-Bench (lifelong navigation), AstraNav-Memory achieves 65.5% SR / 49.0% SPL on Val-Seen, 66.8% SR / 54.7% SPL on Val-Seen-Synonyms, and 62.7% SR / 56.9% SPL on Val-Unseen, outperforming the strongest baseline MTU3D by +15.5 SR and +29.2 SPL on the unseen split. On HM3D-OVON (open-vocabulary object navigation), the method reaches 62.5% SR / 34.9% SPL on Val-Unseen, surpassing MTU3D by +21.7 SR and +22.7 SPL. Ablations show that 16× token compression with 100 stored images offers the best efficiency–accuracy trade-off, reducing per-iteration training time from 26.4 s to 9.2 s and GPU memory from 90.6 GB to 68.5 GB relative to the uncompressed 50-frame baseline.

## Baselines & Comparisons

AstraNav-Memory outperforms all 12 baselines on both benchmarks across every split. On GOAT-Bench, the closest competitor is MTU3D [64] (52.2% SR / 30.5% SPL on Val-Seen), which AstraNav surpasses by +13.3 SR and +18.5 SPL; on the harder Val-Unseen split the gap widens to +15.5 SR and +29.2 SPL. Modular pipelines (Modular GOAT [8], Modular CLIP on Wheels [17]) and the SenseAct-NN variants [23] trail by 30–50 SR points, confirming that end-to-end image-centric memory substantially outperforms decoupled detection-and-planning stacks. On HM3D-OVON, the strongest prior method MTU3D [64] reaches 55.0% SR / 23.6% SPL (Val-Seen) and 40.8% SR / 12.1% SPL (Val-Unseen); AstraNav improves these to 65.6% / 35.4% and 62.5% / 34.9% respectively, a gain of roughly 1.5× in success rate and 1.7× in path efficiency on the unseen split. Classical imitation-learning baselines (BC [31], DAgger [33], RL [35]) and their RL-augmented variants (DAgRL [9], BCRL [42]) remain far below, with SR under 42% on Val-Seen. Video-based VLMs (Uni-NaVid [57], VLFM [54], DAgRL+OD [55]) and TANGO [65] occupy the mid-range (35–41% SR) but are consistently outperformed by 20+ SR points, highlighting the advantage of compressed long-horizon memory over short-context or map-based approaches.

## Relation to Prior Work

This paper departs from the dominant object-centric memory paradigm (3D scene graphs, MTU3D's sparse object queries) by adopting a fully end-to-end image-centric memory where compressed visual tokens serve as the sole spatial-semantic representation. The compression module is architecturally inspired by DeepSeek-OCR's extreme token reduction but repurposes PixelUnshuffle+Conv blocks on frozen DINOv3 features as a ViT-native tokenizer that plugs directly into Qwen2.5-VL's first ViT block without modifying downstream layers. Conceptually, it bridges the visual token compression literature (PVC, VScan, token pruning) with lifelong embodied navigation, treating the long visual history as a compressible context rather than a structured map to be queried.

## Why It Matters / Open Questions

The ~20× compression (598→30 tokens per frame) makes hundreds of historical frames computationally affordable within a single VLM context, which was previously infeasible and is the key enabler for practical lifelong navigation. The large SOTA margins over object-centric baselines (MTU3D) suggest that implicit, end-to-end image memory can rival or exceed explicit scene representations, potentially simplifying the engineering stack for deployed embodied agents. However, the category-wise analysis reveals a clear limitation: DINOv3-based compression struggles with boundary-sensitive and texture-fine targets (e.g., carpet), pointing to the need for complementary segmentation or mask-level cues. Open questions include whether the approach transfers to real-robot deployment with latency constraints and whether the compression generalizes beyond indoor navigation to broader embodied tasks.
