## Problem

Current vision-language models struggle with chart understanding because existing datasets are limited in scale, narrow in chart-type coverage, and incomplete in multimodal alignment—often lacking plotting code, reasoning traces, grounding annotations, or tabular data. This data bottleneck prevents open-source models from matching proprietary systems on complex chart reasoning tasks that require tight coupling between visual perception, structured data extraction, and natural language interpretation.
![Teaser figure](../imgs/CVPR20261301/cropped_page2_idx0.webp)

## Input / Output

Each ChartNet sample is a five-way aligned tuple: a rendered chart image (from 24 chart types across 6 plotting libraries), executable Python plotting code, a CSV data table, a natural-language summary, and a QA pair with chain-of-thought reasoning enclosed in think/answer tags. For the QA task, the input is a chart image paired with a complex multi-stage reasoning question, and the model must produce a structured reasoning trace followed by a final answer. The dataset also includes specialized subsets with bounding-box grounding annotations (serialized as coordinate strings in answers), human-verified annotations, 30K real-world charts with metadata, and 7K safety preference pairs.

## Method

ChartNet's core pipeline uses executable plotting code as a structured intermediate representation for charts. Starting from 150K seed images (from TinyChart), a VLM (pixtral-large-instruct-2411) reconstructs each chart as Python code, which an LLM (gpt-oss-120b) then iteratively rewrites to produce diverse variations in chart type, style, and data values. Generated code is executed to render images, then a VLM quality-filters for visual defects (reducing error rate from 14.9% to 5.9%), and finally a VLM extracts tabular data, generates grounded descriptions, and produces multi-stage CoT reasoning traces following the Vision-R1 and LLaVA-CoT frameworks. The resulting 1.5M tuples are used for supervised fine-tuning of VLMs ranging from 256M to 7B parameters, with each model trained only on the task-specific subset corresponding to its evaluation task.

## Results

Fine-tuning on ChartNet yields consistent gains across all four chart understanding tasks regardless of model scale. The LLaVA-7B model achieves the largest absolute improvements: +38.6 on execution rate, +42.4 on code data fidelity, +41.8 on chart data extraction, and +15.2 on QA with CoT reasoning. The ChartNet-finetuned Granite-Vision-2B reaches 70.3% on data extraction and 83.9% on summarization, surpassing GPT-4o (46.7% and 77.1% respectively) and all open-source baselines up to 72B parameters. On public benchmarks, Granite-Vision-2B improves from 1.6 to 12.4 BLEU on ChartCap and from 30.8 to 58.4 on ChartMimic-v2.

## Baselines & Comparisons

ChartNet-finetuned models consistently outperform all off-the-shelf baselines. The 2B Granite-Vision model beats GPT-4o on six of seven metrics (Code-D: 72.8 vs 48.8; Code-S: 90.0 vs 77.2; Img: 92.8 vs 88.2; Data Extraction: 70.3 vs 46.7; Summarization: 83.9 vs 77.1; QA: 65.0 vs 61.1), losing only on execution rate (90.4 vs 95.9). The 7B LLaVA model similarly surpasses GPT-4o on all metrics except execution rate, and outperforms the specialized ChartGemma model on data extraction (58.8 vs 37.1) and summarization (80.3 vs 46.1). Against larger open-source models, the ChartNet-finetuned 2B model exceeds Qwen2-VL-72B on data extraction (70.3 vs 50.3), summarization (83.9 vs 75.9), and QA (65.0 vs 60.3), and surpasses Mistral-Small-24B on code data fidelity (72.8 vs 54.5) and image similarity (92.8 vs 86.3). The LLaVA-7B finetuned model outperforms Qwen3-VL-3B on data extraction (58.8 vs 58.1) and QA (70.3 vs 64.3), and beats InternVL3-8B on all reconstruction metrics. Ultra-compact models (256M–258M) that previously had zero chart reconstruction capability gain functional performance (14.9–41.8% execution rate) after ChartNet fine-tuning, demonstrating that the dataset's value is scale-invariant.

## Relation to Prior Work

ChartNet extends the code-guided synthetic data generation paradigm introduced by CoSyn and ChartGen, but departs from them in scale (1.5M vs. ~100K samples), modality completeness (five aligned components per sample vs. partial coverage), and chart diversity (24 types across 6 plotting libraries vs. 3–6 types). For QA generation, it builds on the Vision-R1 and LLaVA-CoT frameworks for multi-stage chain-of-thought reasoning, adapting them to the chart domain. The paper positions itself against a long line of chart-specific datasets (ChartQA, DVQA, PlotQA, UniChart, ChartLlama, ChartX, TinyChart) that are individually limited in size, chart-type coverage, or modality alignment, and against prior synthetic-generation approaches (Granite Vision, DAVE, Molmo) that exhibit narrower chart diversity.

## Why It Matters / Open Questions

ChartNet addresses a critical data bottleneck in chart understanding by providing the largest open-source, fully multimodal chart dataset, with the practical effect that small (2B–7B) models fine-tuned on it outperform 24B–72B open-source models and GPT-4o on chart-specific tasks. The key open question is whether gains transfer to truly novel chart types and real-world visualizations outside the synthetic distribution; the public benchmark results (ChartCap, ChartMimic-v2) show positive but more modest transfer, suggesting the synthetic-to-real gap remains. Additionally, the reliance on VLMs (pixtral-large-instruct-2411, gpt-oss-120b) for both generation and evaluation introduces a circularity concern that limits the strength of the self-referential evaluation, and the 36.5% visual error rate before filtering raises questions about the ceiling of code-guided generation fidelity.
