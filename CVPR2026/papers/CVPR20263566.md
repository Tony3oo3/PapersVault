## Problem

General-purpose image editing models (FLUX, Qwen-Image-Edit, Seedream) can incorporate reference glyphs as visual context but fail to accurately transplant a user-specified font style into a target text region while preserving semantic content and layout. Specialized text-editing models (FLUX-Text, TextFLUX) improve spelling accuracy via internal glyph priors but offer no mechanism to accept an arbitrary font extracted from a user-provided visual patch, leaving a critical gap for professional poster design workflows that demand fine-grained typographic control.
![Teaser figure](../imgs/CVPR20263566/cropped_page0_idx0.webp)

## Input / Output

The method takes a source poster image, a set of target text strings (one per region to edit), and user-provided cropped glyph patches as font references—no font labels or library names are required. Multiple text regions with heterogeneous typographic styles can be edited simultaneously in a single forward pass. The output is a full-resolution edited image where only the specified text regions are modified while all non-edited content (background, other text, layout) is preserved. The reference glyph is consumed as a raw visual patch, enabling zero-shot transfer to fonts absent from any standard library.

## Method

SkyReels-Text builds on Qwen-Image-Edit (an MMDiT-based diffusion transformer) fine-tuned with LoRA (rank 64) and introduces a dual-stream visual conditioning mechanism that decouples content from style: a plain-text reference image (target text inpainted into masked regions) and a dedicated glyph map (reference glyphs rendered on a matching canvas) are both encoded by a frozen VAE and concatenated with the noisy latent along the sequence dimension, allowing the model to attend directly to text content and font exemplars without parameter-heavy ControlNet-style modules. Training uses a text-region weighted loss that amplifies the diffusion objective by a factor of (1+λ·M) within SAM2-derived text masks (λ=5), focusing optimization on glyph fidelity while preserving background. The 100K training pairs are generated via a content-style decoupling pipeline: a fine-tuned Qwen2.5-VL 7B OCR model detects ornamental/calligraphic text, Qwen3-8B produces semantically disjoint replacement text, Nano Banana performs the local edit, and a dual-verification block (OCR re-check + DINOv2 feature similarity) ensures both content accuracy and style preservation. For fast deployment, DMD2 distillation compresses the model to 8 sampling steps with no classifier-free guidance, achieving >10× inference speedup.

## Results

On the SkyReels-Text Benchmark, SkyReels-Text achieves 83.34% Sentence Accuracy and 95.02% NED, outperforming the strongest competitor FLUX-Text (82.66% / 93.52%) and all commercial editors (Nano Banana 72.90%, Seedream 4.0 77.72%). On the AnyText benchmark, it attains 85.36% English Sen. Acc and 77.10% Chinese Sen. Acc with dramatically lower FID (6.12 / 5.44) and LPIPS (0.0246 / 0.0192) than FLUX-Text (FID 13.85 / 13.68). On handwritten text (IAM), it achieves HWD 1.32 and GS 1.26, surpassing the dedicated one-shot method DiffBrush (HWD 1.41, GS 2.35) without any handwritten-specific training.

## Baselines & Comparisons

SkyReels-Text outperforms all 18 baselines on the primary SkyReels-Text Benchmark, with the closest competitor being FLUX-Text, which it beats by 0.68% on Sen. Acc and 1.50% on NED, while FLUX-Text retains a marginal 0.36 dB edge on B-PSNR (34.53 vs 34.17). On the AnyText benchmark, the advantage widens substantially: SkyReels-Text surpasses FLUX-Text by 1.37% on English Sen. Acc and 7.50% on Chinese Sen. Acc, and reduces FID by more than half (6.12 vs 13.85 English; 5.44 vs 13.68 Chinese). Among commercial editors, Nano Banana and Seedream 4.0 trail by 10–15% on Sen. Acc and show markedly weaker spatial alignment (IoU 0.70 and 0.68 vs 0.75). On handwritten text, SkyReels-Text (one-shot, no domain-specific training) beats the dedicated one-shot method DiffBrush on IAM HWD (1.32 vs 1.41) and GS (1.26 vs 2.35), and on CVL HWD (0.89 vs 1.06), though DiffBrush edges it slightly on CVL GS (29.6 vs 31.0). The user study confirms these quantitative gains, with SkyReels-Text achieving 71.8% and 84.5% win rates over Qwen-Image-Edit and FLUX-Kontext-Pro respectively.

## Relation to Prior Work

SkyReels-Text builds directly on Qwen-Image-Edit as its DiT backbone (fine-tuned via LoRA) and adapts DMD2 distillation for fast inference, but its core departure is in the conditioning mechanism. Prior text-editing models (FLUX-Text, TextFLUX) inject glyph priors as rendered text content and positional masks, while general editors (FLUX-Kontext, Seedream 4.0) rely on text prompts alone; neither can accept an arbitrary user-provided font reference. SkyReels-Text instead introduces a dual-stream visual conditioning scheme that concatenates VAE features from a plain-text reference (content) and a glyph map (style) onto the noisy latent, decoupling what to write from how it should look. The data pipeline—using a fine-tuned Qwen2.5-VL OCR model and a content-style decoupling strategy with Nano Banana editing—also distinguishes it from prior synthetic-data approaches that render standard fonts onto simple backgrounds.

## Why It Matters / Open Questions

This work addresses a concrete gap in professional design workflows: the ability to swap text content while preserving an arbitrary, potentially non-standard font style without font labels or per-font fine-tuning. The dramatic FID reduction on AnyText (6.12 vs. 13.85 for FLUX-Text in English) and the zero-shot generalization to handwritten text without dedicated training suggest the dual-stream conditioning captures style more faithfully than prior glyph-prior methods. However, the ablation reveals a non-trivial trade-off: enabling the font reference actually degrades text accuracy (Sen. Acc drops from 93.3% to 83.3%), indicating that current OCR systems struggle with highly stylized output and that content and style remain partially entangled. Open questions include whether the approach scales to very long text passages, whether the Qwen-Image-Edit backbone is truly necessary, and how well the method handles fonts with extreme decorative elements beyond what the VLM-OCR can parse.
