## Problem

MLLMs paired with vision tools (depth, flow, correspondence) consistently under-utilize the tool-generated visual cues because raw pixel-level outputs are misaligned with the language-native reasoning substrate of LLMs. The paper argues the bottleneck is not the number of tool calls or model size, but the representation of tool outputs themselves: dense numeric grids that MLLMs cannot reliably parse or reason over.
![Teaser figure](../imgs/CVPR20261063/cropped_page0_idx0.webp)

## Input / Output

The method consumes an RGB image, a raw tool output (e.g., a depth map from DepthAnything, an optical flow field from RAFT, point correspondences from LoFTR, or detections from LLMDet), and a text question. It produces a compact YAML-like text block (P²) in which every visual primitive is expressed as a tuple of identifier, normalized [0,1000]² spatial coordinate, a modality-specific readout (min/max depth range, left/right flow direction, similarity score, confidence, etc.), and an optional label, plus optional relational triples (e.g., 'in-front-of'). This P² text is then supplied alongside the original images and question to an off-the-shelf MLLM, which outputs a multiple-choice answer.

## Method

Perception Programs (P²) is a training-free, model-agnostic symbolic framework that rewrites raw tool outputs into language-native structured summaries. It defines a unified item schema I_p = (p, c_p, r_p, b_p) shared across all modalities, where the only modality-specific variation is how the readout r_p is computed: depth uses per-grid-cell min/max values plus 'in-front-of' adjacency relations with a margin τ; optical flow reduces each cell to a binary left/right direction; visual correspondence stores normalized reference-target point pairs; jigsaw stores averaged SSIM/χ²/NCC edge-similarity scores; object detection stores bounding boxes with confidence and category; semantic correspondence stores DIFT feature-similarity scores. The P² is serialized as a YAML-like text block and fed directly to any MLLM without parameter updates, architectural changes, or additional tool calls, making it a plug-and-play replacement for raw pixel-level tool outputs in existing tool-use pipelines.

## Results

On the BLINK benchmark, P² with GPT-5 Mini achieves 86.47% on multi-view reasoning (vs. 41.35% standard, 45.11% raw tool), 81.45% on HardBLINK relative depth (vs. 52.42% standard), 94.19% on visual correspondence, 91.33% on jigsaw, 93.44% on object localization, and 64.03% on semantic correspondence — a 19.66% average gain over prior state-of-the-art. Smaller open-source models also benefit substantially: InternVL3.5-4B + P² reaches 94.73% on multi-view and 90.16% on object localization, while Qwen3VL-4B + P² hits 93.98% on multi-view, both surpassing prior SOTA without any training. The gap between Raw Tool and P² is consistently large (e.g., +41.36 pp on multi-view for GPT-5 Mini), confirming that the representation format, not the tool signal itself, is the bottleneck.

## Baselines & Comparisons

P² with GPT-5 Mini outperforms all 12 prior baselines on every task. Against the strongest prior tool-use methods, P² beats Visual Sketchpad (GPT-5 Mini) by +39.10 pp on multi-view (86.47 vs. 47.37) and +24.14 pp on HardBLINK depth (81.45 vs. 63.71); it surpasses MMFactory (GPT-4o) by +26.27 pp on multi-view (86.47 vs. 60.20) and +8.69 pp on visual correspondence (94.19 vs. 85.50). Even the much smaller InternVL3.5-4B + P² (94.73% multi-view, 90.16% object localization) exceeds MMFactory and Visual Sketchpad, demonstrating that representation quality matters more than model scale. On the plug-and-play experiment (Table 3), adding P² to Visual Sketchpad's agentic pipeline yields +9.68 pp on HardBLINK-3 (81.45 vs. 71.77) and +19.90 pp on object localization (80.33 vs. 60.43), confirming P² is complementary to existing agentic frameworks. The only task where P²'s gain is more modest is semantic correspondence (64.03% for GPT-5 Mini), where the discrete four-way matching format limits the benefit of structured summaries.

## Relation to Prior Work

This paper departs from the dominant paradigm in tool-augmented MLLMs—where prior work (VisProg, ViperGPT, Thyme, MMFactory, Aurora, Mirage, Visual Sketchpad, LATTE) focuses on *how* to invoke tools (program synthesis, chain-of-thought interleaving, fine-tuning) or *which* tools to use—by arguing the bottleneck is instead *how tool outputs are represented* to the model. Rather than building on any single prior method, P² repurposes the simple idea of structured text serialization (YAML-like summaries) as a universal interface between dense visual tool outputs and the language-native reasoning substrate of LLMs. It is explicitly training-free and model-agnostic, positioning itself as a plug-and-play layer that can be inserted into any existing tool-use pipeline (demonstrated by augmenting Visual Sketchpad) without modifying the MLLM or the tool.

## Why It Matters / Open Questions

The practical impact is significant: a zero-training, model-agnostic text reformulation yields 19–25% absolute gains across frontier and open-source MLLMs, suggesting that the field has been over-investing in tool diversity and model scale while under-investing in the representation of tool evidence. However, the scope is deliberately narrow—six BLINK sub-tasks with well-matched tool surrogates—and the paper does not address tool sequencing, composition, or settings without clear expert tools (e.g., 3D reasoning, open-ended VQA). Open questions include whether hierarchical or compositional P² programs can handle multi-tool reasoning, how P² interacts with dynamic tool selection at inference time, and whether the gains persist when upstream tools are noisy or conflicting.
