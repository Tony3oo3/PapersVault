## Problem

Scaling online RL for visual web agents is substantially harder than for text-only domains because rollouts are slow (browser simulation dominates wall-clock time), rewards are hard to verify without ground-truth answers, and existing training task sets are too small and narrow to support generalizable policy learning. Real websites are non-stationary and diverse, so artificial or small-scale task sets produce agents that fail on held-out tasks.
![Teaser figure](../imgs/CVPR20260072/cropped_page0_idx0.webp)

## Input / Output

The agent observes full-page screenshots (not accessibility trees) paired with a natural-language task instruction, and outputs a sequence of coordinate-based browser actions (click [x,y], type, scroll, go-back, navigate-to-URL) followed by a final textual answer. A memory prompt requires the model to emit an updated working-memory string at every step alongside its action, enabling it to retain information across long trajectories without re-feeding all prior screenshots. The evaluator consumes the full trajectory (keypoint screenshots + final answer) and issues a binary reward based on whether all rubric criteria are satisfied.

## Method

WebGym contributes three coupled components: (1) a procedural task-construction pipeline that seeds ~300k tasks from 10 benchmarks by generating structured evaluation rubrics (fact groups) and decomposing them into easier sub-tasks via proper-subset combinations, yielding a difficulty-graded task set spanning 127k+ websites; (2) an asynchronous server/client rollout system where a CPU-based master/worker pool simulates isolated browser sessions while a GPU-based client streams observations and runs policy inference without step- or episode-level synchronization barriers, achieving 4–5× throughput over synchronous baselines; and (3) a simple REINFORCE training loop (equivalent to filtered behavior cloning on successful trajectories) applied to Qwen3-VL-8B-Instruct, augmented with a per-step memory prompt, a repetition penalty that discards steps producing identical screenshots, a capped interaction horizon (10/20/30 steps by difficulty), and uniform task sampling across difficulty levels to balance generalization against overfitting to narrow hard-task domains.

## Results

On the out-of-distribution WebGym test set (1,167 tasks from websites never seen during training), the WebGym-trained Qwen3-VL-8B-Instruct agent achieves 42.9% success rate, up from 26.2% for the untrained base model. This substantially outperforms GPT-4o (27.1%) and GPT-5-Thinking (29.8%), which use Set-of-Marks prompting. The asynchronous rollout system achieves a 4–5× speedup over synchronous baselines, collecting 1,800 trajectories (avg. 13.2 steps) in 30 minutes on 128 CPUs and 24 H100 GPUs.

## Baselines & Comparisons

The WebGym-trained agent (42.9%) outperforms all proprietary-model baselines by a wide margin: GPT-4o (27.1%) by 15.8 points and GPT-5-Thinking (29.8%) by 13.1 points. It also surpasses its own untrained base model (Qwen3-VL-8B-Instruct at 26.2%) by 16.7 points, demonstrating that the RL training on WebGym's 292k-task set is the primary driver of improvement rather than the base model's pretraining. The paper notes that GPT-4o scores 25.6% on the same 300-task subset used for GPT-5, confirming that subsampling variance is negligible. The comparison is particularly strong because the test set consists exclusively of tasks on websites never encountered during training, making it a strict out-of-distribution evaluation rather than a memorization test.

## Relation to Prior Work

This paper extends the RL-for-LLMs paradigm (REINFORCE-style training demonstrated in software engineering and math reasoning) to visual web agents, building on the action space and prompting conventions from Shen et al. [34] and the base model capabilities of Qwen3-VL. It departs from prior training environments (WebRL, PAE-WebVoyager) by introducing rubric-based structured evaluation, procedural task decomposition for curriculum construction, and an asynchronous rollout system that eliminates synchronization barriers. The task sourcing aggregates 10 existing benchmarks (InSTA-v3, BrowseComp, Mind2Web variants, etc.) but constructs its own OOD train-test split at the website level, addressing a gap where prior works either lacked scale or used unreliable benchmark-level splits.

## Why It Matters / Open Questions

WebGym provides the largest open-source training environment for visual web agents (292k tasks, 127k websites) with a practical async rollout system, making large-scale RL training of web agents accessible beyond proprietary-lab compute budgets. The finding that a simple REINFORCE recipe on an 8B model outperforms GPT-4o and GPT-5-Thinking by 13+ points on strictly OOD websites suggests that task diversity and evaluation quality may matter more than raw model scale for web agent capabilities. Open questions include whether the approach scales to larger models or Thinking variants efficiently, whether the rubric-based evaluator generalizes to non-web agentic domains, and how the OOD gap evolves as base models improve.
