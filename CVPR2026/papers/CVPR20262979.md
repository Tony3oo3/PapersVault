## Problem

Adapting production-level computer vision tools to bespoke scientific datasets remains a critical 'last mile' bottleneck: fine-tuning requires thousands of annotated images that individual labs lack, while manual code adaptation costs scientists weeks to months. While AI agents could in principle automate this coding, it is unclear whether the complex architectures common in the MLE and scientific-agent literature are necessary for this targeted task, or which specific design components actually drive performance.
![Teaser figure](../imgs/CVPR20262979/cropped_page0_idx5.webp)

## Input / Output

The agent receives a small labeled validation set (10–100 images across modalities such as fluorescent microscopy, phase contrast, and dermoscopy) plus a fixed pretrained production tool (Polaris, Cellpose, or MedSAM) and iteratively generates pairs of Python preprocessing and postprocessing functions. These functions are embedded into the tool's pipeline, executed on the validation set, and scored with task-specific metrics (F1, AP@IoU 0.5, NSD+DSC). The final output is a set of scored adaptation functions from which the top-15 across 20 runs are selected for test evaluation, rather than a single best-validation pick, to mitigate overfitting.

## Method

The paper introduces a systematic, bottom-up evaluation framework built around a minimal 'Base Agent' consisting of a Coding Agent (LLM), an Execution Agent (runs the pipeline and returns scores), a Data Prompt (biological context), and an API List (98 curated OpenCV/SciPy/scikit-image functions). From this baseline, the authors ablate and add four design axes—LLM type (GPT-4.1, o3, Llama 3.3-70B), Function Bank (top/bottom-3 memory), Expert Functions (in-context examples), and an AutoML Agent (periodic hyperparameter search)—to isolate each component's effect. A key analytical contribution is characterizing each task's solution space along two dimensions (API-space concentration and parameter-space optimizability), which explains why components like Expert Functions dramatically help Polaris (concentrated API, hard-to-optimize threshold) yet harm MedSAM (dispersed API). The framework is validated by comparing against the proprietary AIDE tree-search agent and by deploying agent-generated functions into the official Polaris codebase.

## Results

Across all three biomedical imaging tasks, the minimal Base Agent consistently outperforms the expert-engineered baselines: Polaris F1 improves from 0.841 to 0.867, Cellpose AP@IoU0.5 from 0.402 to 0.409, and MedSAM NSD+DSC from 0.820 to 0.971. The largest gain is on MedSAM (+0.151), where the agent's dispersed API exploration yields substantially better segmentation. With targeted augmentations (e.g., expert functions for Polaris, reasoning LLM for MedSAM), scores reach 0.929, 0.416, and 1.037 respectively, while the only configuration that underperforms the expert baseline is the small LLM (Llama 3.3-70B) on Polaris (0.805) and Cellpose (0.397).

## Baselines & Comparisons

Against the three expert baselines (official production-optimized code from the original tool authors), the Base Agent wins on all tasks: Polaris F1 0.867 vs. 0.841 (+0.026), Cellpose AP@IoU0.5 0.409 vs. 0.402 (+0.007), and MedSAM NSD+DSC 0.971 vs. 0.820 (+0.151). Against the proprietary AIDE tree-search agent (Jiang et al., 2025), the Base Agent matches or slightly exceeds AIDE on every task (Polaris 0.867 vs. 0.872, Cellpose 0.409 vs. 0.414, MedSAM 0.971 vs. 0.971), indicating that the added tree-search complexity provides no clear advantage for this focused adaptation task. The Base Agent with Function Bank further narrows the gap, reaching 0.889 on Polaris and 0.416 on Cellpose while matching AIDE on MedSAM. Notably, the expert baselines required weeks to months of manual tuning (quantified via Git history), whereas the agent achieves superior results within 1–2 days of compute time.

## Relation to Prior Work

This paper carves out a specific, practical sub-task—adapting a fixed, pretrained production tool to a new bespoke dataset via LLM-generated pre/post-processing code—that sits between the MLE-agent literature (AIDE, MLE-bench), which builds solutions from scratch, and the scientific-agent literature (BioMNI, AI Scientist), which targets open-ended discovery with complex hierarchical architectures. Rather than building on a single prior method, it repurposes the general LLM-code-generation paradigm and systematically ablates components (function bank, expert in-context examples, reasoning LLMs, AutoML) that are common in those more complex systems. The paper explicitly departs from the prevailing trend of increasing agent architectural sophistication, arguing that for this focused adaptation task, a minimal 'Base Agent' (LLM + execution loop + data prompt) is sufficient and that added complexity is not universally beneficial.

## Why It Matters / Open Questions

The practical impact is significant for the biomedical imaging community: reducing tool adaptation from weeks or months of manual coding to 1–2 days of compute, with agent-generated functions already merged into a production codebase. The solution-space characterization (API concentration × parameter difficulty) offers a reusable diagnostic for predicting which agent components will help or hurt on a given task, though it is validated on only three tasks. Key open questions include whether the findings generalize beyond biomedical imaging, how to make agents more robust to overfitting on small validation sets (a clear limitation of the AutoML component), and when genuinely complex designs (RAG, multi-agent systems) provide justifiable gains over the minimal baseline.
