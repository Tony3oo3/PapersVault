## Problem

Existing text-to-CAD methods rely on low-level command sequences that are difficult to validate, support limited operations, and are hard to interpret. While LLMs can generate code, they lack the geometric reasoning needed to produce CadQuery scripts that are both syntactically valid and geometrically accurate, creating a gap between code generation capability and 3D modeling correctness.
![Teaser figure](../imgs/NEURIPS20251999/cropped_page3_idx0.webp)

## Input / Output

The model takes a natural language description of 3D design intent (e.g., dimensions, coordinate systems, sketch operations, extrusion parameters) and produces a CadQuery Python script structured with a chain-of-thought reasoning block in <think> tags followed by executable code in a ```python block. The script uses CadQuery's chainable Workplane API (moveTo, lineTo, extrude, rotate, translate, union, etc.) and is executed via the OpenCascade kernel to yield a 3D mesh. The CoT prompt enforces a six-stage engineering planning format (description analysis, coordinate planning, sketch construction, extrusion planning, code strategy, scaling guidance) with each step capped at 50 words.

## Method

CAD-Coder reformulates text-to-CAD as CadQuery code generation and trains Qwen2.5-7B-Instruct in two stages. Stage 1 is supervised fine-tuning on 8K high-quality text-CadQuery pairs (selected by CD < 1e-4 from a 110K dataset built via an automated pipeline using DeepSeek-V3 for code synthesis and CD-based filtering) to establish syntax and basic shape-to-operation mappings. Stage 2 applies GRPO reinforcement learning with a CAD-specific composite reward: a geometric reward computed as a piecewise-linear function of Chamfer Distance between the executed mesh and ground-truth geometry (max reward 1.0 at CD < 1e-5, zero at CD > 0.5 or execution failure), plus a binary format reward checking for proper <think> and code-block structure. CoT cold-starting on 1.5K hand-refined reasoning samples is inserted between stages to bootstrap structured spatial planning before RL optimization begins.

## Results

On the Text2CAD test set, CAD-Coder achieves a Mean CD of 6.54×10⁻³ and Median CD of 0.17×10⁻³, substantially outperforming the strongest prior method Text2CAD (Mean CD 29.29×10⁻³, Median CD 0.37×10⁻³) by approximately 4.5× and 2.2× respectively. The code invalidity ratio (IR) drops to 1.45%, compared to 3.75% for Text2CAD. All zero-shot LLM baselines (GPT-4o, Claude-3.7-sonnet, DeepSeek-V3, Qwen2.5-72B/7B) perform far worse, with Mean CD values ranging from 143.5 to 209.4 (×10⁻³) and IR values from 47% to 99%.

## Baselines & Comparisons

CAD-Coder decisively outperforms the strongest dedicated text-to-CAD baseline, Text2CAD [13], on all three metrics: Mean CD improves from 29.29 to 6.54 (×10⁻³), Median CD from 0.37 to 0.17, and IR from 3.75% to 1.45%. Against zero-shot LLM baselines prompted to generate CadQuery code, the gap is even larger: GPT-4o (Mean CD 143.5, IR 70.5%) and Claude-3.7-sonnet (Mean CD 186.53, IR 47.03%) both produce far less geometrically accurate and less executable code than CAD-Coder. Open-source LLMs perform worst — Qwen2.5-7B achieves an IR of 98.83%, meaning nearly all generated scripts fail to execute. The ablation (Table 3) further confirms that the SFT+CoT+GRPO pipeline is essential: SFT alone yields Mean CD 74.55, while adding GRPO without CoT reduces it to 17.34, and the full method reaches 6.54.

## Relation to Prior Work

This paper departs from the dominant command-sequence paradigm for text-to-CAD (DeepCAD, Text2CAD, CAD-Translator) by reformulating the task as generation of CadQuery Python scripts, thereby inheriting LLMs' existing code-generation proficiency and gaining direct executability for validation. The RL stage builds directly on GRPO from DeepSeekMath [24], adapting its group-relative advantage estimation to a CAD-specific reward that combines Chamfer Distance geometry with a format check. The CoT planning component draws on standard chain-of-thought prompting [30] but is tailored to the hierarchical decomposition of CAD modeling (coordinate systems, sketches, extrusions). Unlike Query2CAD [2], which zero-shot prompts LLMs for CadQuery code, this work introduces a full SFT + RL training pipeline with a geometrically verified dataset.

## Why It Matters / Open Questions

By grounding the reward in actual 3D geometry (Chamfer Distance) rather than token-level loss, the paper demonstrates that RL can push LLMs beyond syntactic correctness into geometric fidelity for CAD, a capability that SFT alone cannot provide. The finding that a small (8K) high-quality SFT set outperforms a 70K medium-quality one, and that pure CD reward causes training collapse without format supervision, offers practical guidance for future code-generation RL. Open questions include whether the approach extends to multimodal inputs (images, point clouds), whether the shallow CoT can handle truly complex spatial compositions, and whether CD-based rewards can be augmented with structural or topological signals for finer-grained control.
