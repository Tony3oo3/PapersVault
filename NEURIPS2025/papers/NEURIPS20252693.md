## Problem

Existing LLM verification and hallucination-detection methods target general-purpose properties (robustness, fairness, output stability) and lack mechanisms for encoding domain-specific constraints that experts care about in specialized applications. This leaves LLM outputs in rule-based or reasoning-intensive domains—such as legal compliance or mathematical problem-solving—without a lightweight, incremental means of checking adherence to explicitly defined domain rules at runtime.

## Input / Output

RvLLM consumes three inputs: the LLM's context and generated output (together forming the domain of discourse), and an ESL specification written by a domain expert using predicate logic in prenex normal form restricted to universal-quantifier rule-like implications (e.g., InRailway(x) => not ChewGum(x)), where each predicate carries a natural-language description. The framework produces a binary inconsistency verdict, a set of inferred propositional truth values derived via forward chaining, and—when new knowledge is inferred—targeted follow-up queries sent back to the LLM whose responses are checked for contradiction against the inferred knowledge.

## Method

RvLLM operates in four stages. First, a perception agent performs interpretation abstraction: it extracts all objects from the context/output and propositionalizes predicates, then binds variables in each ESL rule to generate propositional formulae (Level-1 uses only complete bindings; Level-2 additionally instantiates unbound variables via the perception agent). Second, each Deductive Normal Form formula is decomposed into a set of rule-like propositional implications (conjunction-of-literals ⇒ single literal) using a unit-propagation-inspired transformation. Third, a forward-chaining procedure builds a directed graph over literal nodes and LHS nodes, then iteratively applies modus ponens to propagate truth values, detecting inconsistency when a literal is simultaneously inferred True and False, or inferring new knowledge for previously undefined literals. Fourth, for each newly inferred proposition, a query generation module formulates a concrete question to the target LLM; if the LLM's answer contradicts the inferred truth value, an inconsistency is flagged. The key design choice is the ESL specification language, which restricts predicate logic to a simple, expert-friendly subset while retaining enough expressiveness to encode diverse domain constraints.

## Results

On the violation detection task (304 scenarios against Singapore Rapid Transit Systems Act), RvLLM increases the true positive rate by 15.7% to 50.2% across 13 LLMs, with the largest gain (+50.2%) for Gemini 2.0 Flash (37.0% → 87.2% TPR). On the numerical comparison task (100 questions), RvLLM achieves 100% TPR and 100% TNR for Qwen plus and Gemini 2.0 Flash, and 88.9% TPR with 100% TNR for GPT 4.1 mini. On inequality solving (40 A-Level questions), RvLLM reaches up to 50% TPR using only three basic algebraic specifications, demonstrating that even incomplete domain knowledge yields meaningful error detection.

## Baselines & Comparisons

RvLLM is compared against two runtime baselines: SelfCheckGPT [47] and a prompt-based LLM-as-a-judge method. SelfCheckGPT consistently achieves near-zero TNR across all models (0% for Qwen plus, GPT 4.1 mini, and Gemini 2.0 Flash), because it labels almost all outputs as hallucinations based solely on output stability without leveraging domain knowledge. The LLM-as-a-judge method exhibits the opposite failure mode: it achieves 100% TNR but 0% TPR for Qwen plus and Gemini 2.0 Flash, missing all actual errors. RvLLM dominates both baselines by maintaining high TPR and TNR simultaneously—achieving perfect 100%/100% scores for Qwen plus and Gemini 2.0 Flash, and 88.9%/100% for GPT 4.1 mini. In the violation detection task (Figure 3), RvLLM similarly outperforms both baselines by achieving a better TPR–TNR trade-off, whereas SelfCheckGPT sacrifices TNR entirely and the prompt-based method incurs a non-negligible TNR drop alongside its TPR gains.

## Relation to Prior Work

This paper revives the classical expert-systems paradigm (rule-based reasoning with a knowledge base and inference engine) and repurposes it for LLM output verification, using an LLM itself as the 'perception' layer that translates natural-language context into formal propositions. It departs from existing runtime-verification-of-LLMs work (SelfCheckGPT, CheckEmbed) that operationalizes specifications as output-stability checks, by introducing a dedicated specification language (ESL) grounded in restricted predicate logic and a forward-chaining inference engine adapted from SAT unit propagation. The Deductive Normal Form and the extension of forward chaining to handle negative literals for inconsistency detection are the key technical departures from traditional Horn-clause-based expert systems.

## Why It Matters / Open Questions

The paper addresses a concrete gap: existing LLM verification methods are domain-agnostic and cannot encode the kind of hard constraints (legal regulations, algebraic invariants) that safety-critical deployments require. The practical takeaway is that a one-time expert effort to write ESL specifications (three days for 31 regulations) yields a reusable, model-agnostic verification layer that improves TPR by 15–50% without retraining. Key limitations include ESL's restricted expressiveness (universal quantifiers only, DeNF), the perception agent's accuracy as a bottleneck (causing TNR drops up to 17%), and the open question of whether the approach scales to temporal, probabilistic, or multi-agent specifications. The 50% TPR on inequality solving with only three incomplete specifications suggests substantial headroom as domain knowledge is enriched.
