## Problem

Existing LLM routing methods rely on trained predictors or computationally heavy per-query calculations (KNN, similarity-weighted ranking) that introduce latency, require costly retraining when LLM deployments change, and assume offline access to all queries simultaneously. No prior work provides a training-free, theoretically grounded online routing algorithm that handles sequential query arrivals under per-LLM token budget constraints in high-volume serving settings.
![Teaser figure](../imgs/NEURIPS20254577/cropped_page6_idx2.webp)

## Input / Output

The algorithm consumes a stream of text queries arriving in random sequential order, a pre-built historical dataset D of previously served queries with their embeddings and per-LLM performance/cost scores, per-LLM token budgets B_i, and the set of M deployed LLMs. For each incoming query, it produces a routing decision assigning the query to one LLM (or queuing it if that LLM's budget is exhausted). The one-time learning phase outputs a vector of routing weights γ* ∈ R^M that parameterize the routing rule for all subsequent queries. Feature estimation uses HNSW (or DiskANN) with |R_j|=5 candidate neighbors, and the optimization phase processes only ε|Q| ≈ 250 initial queries.

## Method

The method formulates routing as a MILP maximizing total performance under per-LLM budget constraints, relaxes it to an LP, and exploits the dual structure: at optimality, the dual objective is fully parameterized by a single vector γ of dual variables, and the routing rule reduces to assigning each query to the LLM maximizing (α·d̂_ij − γ_i·ĝ_ij). Rather than solving the infeasible global dual, the algorithm learns γ* by minimizing the dual objective over a small set of ε|Q| initial queries, using random routing on those queries (inspired by PAC learning) to ensure unbiased estimation. Query features (performance d̂_ij and cost ĝ_ij) are estimated training-free via ANNS over a historical dataset, requiring no model training and enabling trivial adaptation to new LLM deployments. A control parameter α > 0 is introduced into the objective to bridge cost and performance, ensuring generalizability of γ* to future queries without affecting the optimal solution structure. The algorithm achieves a competitive ratio of 1 − O(ε + δ) relative to the offline optimum under a mild Lipschitz-like assumption on embedding similarity.

## Results

On the main setting (total budget = cost of cheapest model, cost-efficiency split), PORT achieves 84.66% relative performance (RP) on RouterBench, 75.99% on SPROUT, and 76.7% on Open LLM Leaderboard v2, compared to the offline approximate optimum. Across all three benchmarks, PORT averages a 3.55× improvement in total performance, 1.85× in Performance-per-Cost (PPC), and 4.25× in throughput over all 8 baselines. Against the strongest baseline (BatchSplit), PORT still delivers 33% higher performance, 38% better cost efficiency, and 24% higher throughput.

## Baselines & Comparisons

PORT outperforms both KNN-based baselines from RouterBench [23] by a wide margin: on RouterBench, PORT achieves 2718.6 performance (84.66% RP) versus KNN-Perf's 1005.1 (31.3%) and KNN-Cost's 1592.05 (49.58%), a 2.7× and 1.7× improvement respectively. Against the model-based baselines from CARROT [50], the gap is even more pronounced: Roberta-Perf scores only 154.5 (4.81% RP) on RouterBench and 458.9 (7.73%) on SPROUT, while Roberta-Cost reaches 481.4 (14.99%) and 3996.2 (67.29%), respectively—PORT surpasses both by 5.6× and 1.1× in performance on RouterBench. Notably, the training-free KNN and ANNS methods (Greedy, KNN) substantially outperform the trained Roberta predictors, suggesting that model-based routing struggles under the sequential, budget-constrained online setting. PORT also beats the strongest training-free baseline, BatchSplit (which solves an LP per mini-batch of 256), by 33% in performance and 38% in PPC across all three benchmarks, while incurring negligible per-query overhead compared to BatchSplit's repeated LP solves.

## Relation to Prior Work

This paper carves new ground at the intersection of online algorithms and LLM serving by combining three previously separate ideas: ANNS-based feature estimation (from information retrieval), LP duality for routing weight extraction (from the ad-auction/online matching literature [39, 11]), and MILP formulation of LLM routing (from [47, 42, 44]). It departs from prior LLM routing work in two key ways: unlike model-based predictors (RouteLLM [43], CARROT [50], GraphRouter [15]) that require training and retraining on configuration changes, it is entirely training-free; and unlike offline MILP solvers that assume simultaneous query arrival, it handles sequential, uncertain arrivals via a one-time dual optimization over a small observed sample. The PAC-learning-inspired random routing in the observation phase and the ε-net-based generalization analysis are borrowed from the online matching literature but applied here for the first time to LLM routing.

## Why It Matters / Open Questions

As LLM serving costs scale with query volume (OpenAI reportedly handles 12k queries/second), a training-free, near-optimal routing method that adapts to dynamic LLM deployments without retraining has direct practical value for providers managing heterogeneous model fleets under tight token budgets. The 1-o(1) competitive ratio provides rare theoretical grounding for an online LLM routing algorithm, and the 75–85% of offline oracle performance achieved in practice validates the theory. Key limitations include the restriction to performance and cost as routing factors (excluding traffic/load-balancing), the assumption of random query arrival order, and the need for a maintained historical dataset with ground-truth scores. Open questions include extending to multi-factor routing with operational-state features, handling adversarial arrival patterns, and whether the ANNS estimation quality degrades under significant distribution shift in query types.
