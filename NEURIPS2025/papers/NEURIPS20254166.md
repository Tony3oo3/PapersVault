## Problem

Fine-tuning foundation models with RL for multi-turn mobile app control is hampered by sparse terminal rewards, expensive simulation (4–5 s per step), and the fact that standard policy-gradient updates from negative-advantage samples redistribute probability mass across the model's large output vocabulary, degrading learned representations. Existing RL approaches either discard negative samples entirely (rejection sampling) or apply uniform regularisation, neither of which is well suited to the structured, sparse-reward setting of GUI navigation.

## Input / Output

The agent consumes a purely textual observation: the task goal string, the UI accessibility tree rendered as a JSON-like list of element descriptions and attributes, and the running history of previously executed actions. No screenshot or image tokens are used, which keeps the input short and enables single-pass inference through an 8B model in roughly 0.9 s. The output is a single JSON object of the form {"action-type": <type>, "action-extra": <extra>} specifying one of a fixed set of UI actions (click, long-press, type, scroll, etc.) and its target element or parameters.

## Method

SoLS is an off-policy actor-critic algorithm built on the Degris et al. objective, with a key asymmetric modification to the policy-gradient loss: when the Monte-Carlo advantage is positive the full importance-sampled gradient is applied, but when the advantage is negative a symmetric PPO-style clip (restricting updates whenever the importance ratio falls outside [1−ε, 1+ε]) suppresses destructive probability redistribution. A separate value head (affine + sigmoid on the last hidden layer) is trained with squared Monte-Carlo targets to provide the baseline. Successful Transition Replay (STR) complements the algorithm by maintaining a per-task hash table of the 50 most recent successful timesteps; each training batch mixes n sampled STR transitions with 100 fresh on-policy transitions, bridging the distribution gap between the SFT warm-start and the OOD AndroidWorld environment. The base model is Llama-3-8B-Instruct fine-tuned with LoRA (rank 64) first via SFT on AndroidControl, then via RL fine-tuning for 15 K episodes on AndroidWorld, using AdamW at a constant 10⁻⁵ learning rate and ε = 0.2.

## Results

On the AndroidWorld benchmark (80-task subset), SoLS-STR achieves a 51.3% overall success rate, substantially outperforming all baselines. The improvement is most pronounced on medium-difficulty tasks (40.5% vs. 32.1% for DigiRL-STR and 28.6% for the best GPT-4o method). SoLS also achieves the fastest inference time (~0.9 s/step), approximately 5–60× faster than GPT-4o-based prompting agents that require 40–60 s per step due to multi-step API calls.

## Baselines & Comparisons

SoLS-STR outperforms all eight baseline families. Against the closest RL competitor, DigiRL-STR (38.8%), SoLS-STR achieves a 32.5% relative improvement (51.3%), with the gap widening on medium tasks (40.5% vs. 32.1%). Versus the strongest GPT-4o-based agent, UGround-7B (43.8%), SoLS-STR gains 17% relative improvement while being ~60× faster at inference. The comparison with A2C-STR (32.1%) is particularly informative: both use identical STR parameters, so the 60% relative gap isolates the contribution of SoLS's asymmetric (positive-aggressive / negative-conservative) update rule. Among GPT-4o prompting baselines, T3A (40.0%), M3A (36.3%), SeeAct (22.5%), and AriaUI (41.3%) all trail SoLS-STR, with GPT-4o methods performing best on easy tasks but struggling on medium/hard ones. Purely fine-tuned baselines (OS-Atlas-Pro at 23.8%, SFT at 22.1%) are far behind, confirming that RL fine-tuning is essential for OOD generalisation. PPO (28.3%) is the weakest RL method, underscoring the importance of STR for off-policy data reuse.

## Relation to Prior Work

SoLS builds directly on the off-policy actor-critic framework of Degris et al. (2012), adapting its importance-sampled policy gradient to a structured action space where the standard PPO clipping mechanism is modified into an asymmetric constraint: positive-advantage updates proceed unclipped while negative-advantage updates are restricted to a trust region. The Successful Transition Replay (STR) mechanism repurposes the classic experience replay idea (Lin, 1992) into a task-indexed buffer that stores only successful timesteps, bridging the distribution gap between SFT and the target RL environment. Conceptually, the paper departs from the RLHF tradition of uniform policy regularisation (motivated by reward hacking in free-form generation) by arguing that structured action spaces eliminate that concern, making the conservative treatment of negative samples the sole necessary regularisation.

## Why It Matters / Open Questions

The paper demonstrates that a single-pass 8B model with targeted RL fine-tuning can surpass multi-call GPT-4o pipelines on mobile app control while being 5–60× faster, offering a practical path toward deployable GUI agents without proprietary API dependencies. The asymmetric update mechanism addresses a concrete failure mode in large-vocabulary policy gradients (destructive probability redistribution on negative updates) that likely generalises beyond mobile control to any structured-action RL setting. Open questions include whether the approach extends to visual inputs, whether shaped or dense rewards could further improve sample efficiency, and whether the conservative negative-update constraint risks premature convergence in highly stochastic environments.
