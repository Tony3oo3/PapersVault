## Problem

AI research agents like AIDE entangle multiple performance factors—search policy, operator design, and evaluation methodology—making it difficult to identify which components actually drive performance gains. This paper formalizes agents as graph-based search algorithms to systematically disentangle and study the interplay between search strategies (Greedy, MCTS, Evolutionary) and operator sets, revealing that the operator set, not the search policy, is the primary bottleneck for AIDE. It also quantifies the generalization gap between validation and test scores, showing it systematically misleads the search process.

## Input / Output

Each agent receives a Kaggle competition task description, a read-only data directory, and a sandboxed compute environment (1 NVIDIA H200 GPU, 24 CPU cores, 100 GB RAM, 1 TB scratch storage) with a 24-hour wall-clock budget and 4-hour per-execution limit. The agent iteratively generates and refines self-contained Python scripts that train models, print a 5-fold cross-validation score as proxy fitness, and write test predictions to submission.csv. The final output is the highest-scoring node in the search graph, evaluated on the held-out test set for medal assignment (bronze/silver/gold by task-specific percentile thresholds).

## Method

The paper formalizes AI research agents as a tuple (F, π_sel, O, π_op, τ) over an evolving directed graph of candidate artifacts, then introduces an improved operator set O_AIRA with three key modifications over AIDE: prompt-adaptive complexity cues that scale artifact sophistication with node depth, scoped memory that retrieves only sibling memories for DRAFT/IMPROVE (promoting diversity) versus full ancestral memory for DEBUG (preventing oscillation), and explicit think-token encouragement for reasoning models. Three search policies—Greedy, MCTS (with UCT selection and no rollouts), and Evolutionary (population-based with crossover)—are paired with both AIDE's and AIRA's operators to isolate each factor's contribution. The critical finding is that advanced search policies yield no gain with AIDE's operators but unlock significant improvements with O_AIRA, with AIRA_MCTS achieving 47.7% medal rate on MLE-bench lite (vs. 39.6% for AIDE). The AIRA-dojo framework provides Apptainer-based isolation, self-hosted LLM inference (DeepSeek R1, o3), and checkpointing to support thousands of parallel 24-hour runs.

## Results

On MLE-bench lite (22 Kaggle tasks), the best agent AIRAMCTS with DeepSeek R1 achieves a 47.7% medal success rate, improving over the AIDE baseline (39.6%) by 8.1 absolute points. AIRAGREEDY with R1 reaches 45.5% any-medal and 27% gold-medal rate, while AIRAMCTS with o3 pushes the gold-medal rate to 30.91% (a 20% relative increase over R1). On the full MLE-bench (75 tasks), AIRAGreedy with o3 achieves 31.6% overall medal rate, more than doubling the AIDE Greedy (o1-preview) baseline of 16.9%.

## Baselines & Comparisons

Against AIDE (Jiang et al., 2025), the primary baseline, all AIRA agents outperform AIDEGREEDY: AIRAGREEDY improves the any-medal rate from 39.8% to 45.5% (same greedy search, better operators), and AIRAMCTS further pushes to 47.7% by combining the improved operators with MCTS search. The paper shows that AIDE's operators, not its search policy, are the bottleneck—swapping AIDE's operators into MCTS or evolutionary search yields no gain, while swapping in AIRA's operators into any search policy consistently improves results. On the full MLE-bench, AIRAGreedy (o3) achieves 31.6% overall medal rate versus 16.9% for AIDE Greedy (o1-preview), a near-doubling. Against OpenAI's proprietary agents reported in the GPT-5 system card, AIRAGreedy (o3) substantially outperforms both the o3 agent (6% on MLE-bench-30) and the gpt-5-thinking agent (8% on MLE-bench-30), reaching 25.8% on the same split.

## Relation to Prior Work

This paper builds directly on AIDE (Jiang et al., 2025), which first framed automated ML engineering as LLM-guided tree search over code, but departs from it by formally decomposing the agent into a search policy and an operator set as independent axes. This decomposition is inspired by the broader LLM+search literature (MCTS, evolutionary search, best-of-N) and the AutoML/NAS tradition of separating search strategy from mutation operators, but is applied here to open-ended code generation rather than predefined configuration spaces. The AIRA-dojo framework is positioned relative to Inspect and other agent evaluation frameworks, with a specific focus on long-running, compute-intensive research tasks that require containerized isolation (Apptainer) and self-hosted LLM inference for scalability.

## Why It Matters / Open Questions

The finding that the operator set—not the search policy—is the primary bottleneck for AIDE-style agents is a practical and conceptual shift: it redirects the field's optimization effort from designing more sophisticated search algorithms toward improving the quality and diversity of LLM-driven code transformations. The quantified generalization gap (9–13% absolute medal-rate loss from validation-based final selection) highlights a fundamental limitation that affects all proxy-guided search in ML engineering and suggests that robust final-node selection strategies are an underexploited avenue. Open questions include whether these findings hold with agentic (multi-step) operators, whether fine-tuning can close the operator-quality gap, and how performance scales beyond the 24-hour/1-GPU constraint, where overfitting becomes more severe over longer horizons.
