## Problem

Existing automated red teaming frameworks for LLMs operate on individual attack vectors in isolation, rely on human-curated test cases that cannot scale or adapt to new threats, and require manual implementation of emerging attack strategies. No prior system combines end-to-end automation from high-level risk categories, continuous integration of new attacks from research literature, and learned selection of effective attack combinations across diverse target models.
![Teaser figure](../imgs/NEURIPS20255654/cropped_page3_idx0.webp)

## Input / Output

The framework accepts either a high-level risk category name (e.g., 'Hate speech' from the 314-category AIR taxonomy) or a specific test prompt, along with a black-box target LLM, and produces refined jailbreak test cases with associated attack combination strategies. Uniquely, it can generate diverse test cases from a risk category alone without any seed prompt, and its attack library is continuously expanded by autonomously analyzing recent papers via the Semantic Scholar API, implementing new attacks as Python classes validated against a 30% ASR threshold on a HarmBench subset. The memory system persists across sessions, so prior attack combination statistics inform future strategy selection.

## Method

AutoRedTeamer uses a dual-agent architecture: a Strategy Proposer Agent that queries academic APIs for recent jailbreaking papers, scores them for novelty and effectiveness, implements promising attacks as Python classes inheriting a base interface, and validates them before adding to the attack library; and a Red Teaming Agent that decomposes user input via a Risk Analyzer, generates diverse seed prompts, and selects attacks through a Strategy Designer guided by a three-component memory system (long-term case history, per-attack metrics, and short-term trajectory tracking). The memory system uses embedding-based lookup to retrieve similar past test cases and their successful attack sequences, balancing exploitation of proven combinations with exploration of underutilized attacks (prioritizing those with fewer than 10 prior attempts). This memory-guided selection is the critical differentiator: ablation shows ASR drops from 0.82 to 0.12 with random selection and 0.43 with fixed selection, demonstrating that learned attack combination patterns are essential for effective red teaming.

## Results

On HarmBench, AutoRedTeamer achieves 0.82 ASR on Llama-3.1-70B (vs. 0.67 for AutoDAN-Turbo and 0.60 for PAIR/TAP), 0.96 ASR on Mixtral-8x7B (matching AutoDAN-Turbo), and 0.28 ASR on Claude-3.5-Sonnet (vs. 0.14 for the next-best baseline, Pliny). On GPT-4o, AutoRedTeamer reaches 0.69 ASR, slightly below AutoDAN-Turbo's 0.76. In terms of query efficiency, AutoRedTeamer uses only 14 evaluation queries per test case (vs. 762 for TAP and 26 for PAIR) with just 82 development queries (vs. ~60,000 for AutoDAN-Turbo and ~6,000 for Rainbow Teaming), representing a 46% reduction in total computational cost.

## Baselines & Comparisons

AutoRedTeamer outperforms all dynamic baselines on Llama-3.1-70B (0.82 vs. 0.67 AutoDAN-Turbo, 0.60 PAIR/TAP, 0.18 Rainbow Teaming) and dominates on Claude-3.5-Sonnet (0.28 vs. 0.14 Pliny, 0.05 TAP, 0.04 PAIR), where it is the only method achieving nontrivial ASR. On GPT-4o, AutoDAN-Turbo edges out AutoRedTeamer (0.76 vs. 0.69), though AutoRedTeamer uses far fewer development queries (82 vs. 60,000). On Mixtral-8x7B, AutoRedTeamer ties AutoDAN-Turbo at 0.96 ASR while using 9 queries vs. 3 (but with 82 vs. 60,000 development queries). Against static baselines, AutoRedTeamer consistently outperforms ArtPrompt (0.32–0.63) and FewShot (0.00–0.38) across all models, and beats Pliny on Llama (0.82 vs. 0.63) and Claude (0.28 vs. 0.14) but loses to Pliny on Mixtral (0.96 vs. 0.91 is a tie) and GPT-4o (0.69 vs. 0.37 is a win). The key differentiator is that AutoRedTeamer's memory-guided attack combination strategy adapts across models, whereas static methods like Pliny show highly variable performance (0.91 on Mixtral but 0.14 on Claude).

## Relation to Prior Work

AutoRedTeamer synthesizes and extends several threads of automated red teaming research: LLM-based prompt refinement (PAIR, TAP), agent-based evaluation frameworks (RedAgent, ALI-Agent), and open-ended prompt generation (Rainbow Teaming, AutoDAN-Turbo). Its key conceptual departure is the introduction of a memory-guided attack *combination* mechanism—prior work optimizes individual attack vectors in isolation, whereas AutoRedTeamer tracks and exploits synergies between attacks—and a lifelong attack discovery loop that autonomously implements new methods from recent literature via Semantic Scholar queries. The framework also generalizes the input space from specific harmful prompts to high-level risk categories (AIR taxonomy), a capability absent in all compared baselines.

## Why It Matters / Open Questions

The paper addresses a practical bottleneck in LLM safety evaluation: the inability of static benchmarks and single-attack optimizers to scale with the rapidly growing attack surface. The memory system's criticality (85% ASR drop under random selection) and the finding that attack combinations substantially outperform individual attacks (0.83 vs. 0.63 best single) offer actionable design principles for future red teaming tools. Limitations include reliance on LLM-based attack implementation (potential for hallucinated or ineffective code), evaluation primarily on HarmBench for main comparisons, and the black-box-only threat model. Open questions include whether the lifelong integration loop remains effective as the attack library grows, and whether the framework extends to multimodal or agentic LLM settings.
