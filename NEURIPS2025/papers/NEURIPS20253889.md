## Problem

Existing LLM-based MLE agents rely heavily on the model's internal knowledge, biasing them toward familiar but potentially outdated methods (e.g., ResNet for image classification), and employ coarse exploration that rewrites the entire codebase each iteration. This prevents deep, iterative experimentation within specific pipeline components such as feature engineering or model selection, limiting their ability to discover task-specific improvements.

## Input / Output

The agent receives a natural-language task description (specifying task type, data modality, and evaluation metric) along with one or more dataset files that may span tabular, text, image, or audio formats. It produces a single executable Python script implementing the full ML pipeline (data loading, preprocessing, training, inference) and a corresponding submission file. A dedicated test agent wraps the final script to handle test-data loading and submission formatting, while a data leakage checker and data usage checker validate the script before execution to prevent test-set contamination and ensure all provided data sources are utilized.

## Method

MLE-STAR operates in three phases. First, it uses a web search tool to retrieve M candidate models with descriptions and example code, generates and evaluates a script for each, then iteratively merges the top performers into an initial solution via a simple-average ensemble. Second, it refines the solution through nested loops: an outer loop (T steps) uses an ablation-study agent to identify the single code block with the greatest performance impact, and an inner loop (K steps) iteratively refines only that block, with a planner agent proposing new strategies informed by prior attempts' scores. Third, a novel ensemble module takes L parallel solutions and has an LLM propose and iteratively refine ensemble strategies (beyond simple averaging or best-of-N selection), selecting the highest-scoring merged solution. Auxiliary modules—a debugging agent, a data leakage checker that detects and corrects test-set contamination in preprocessing code, and a data usage checker that ensures all provided data files are incorporated—guard against common LLM failure modes.

## Results

On MLE-bench Lite (22 Kaggle competitions), MLE-STAR with Gemini-2.5-Pro achieves a 63.6% any-medal rate (36.4% gold, 21.2% silver, 6.1% bronze) and 83.3% above-median performance. With the lighter Gemini-2.0-Flash backbone, MLE-STAR still reaches 43.9% any-medal and 63.6% above-median, substantially outperforming the strongest baseline (AIDE with o1-preview at 36.6% any-medal). The paper reports results over three random seeds with one standard error of the mean, and a 24-hour compute limit per competition.

## Baselines & Comparisons

Against AIDE [12], the primary baseline, MLE-STAR with the same Gemini-2.0-Flash backbone improves any-medal rate from 25.8% to 43.9% (+18.1 pp) and above-median from 39.4% to 63.6%; with Gemini-2.5-Pro, MLE-STAR (63.6% medal) surpasses even AIDE with the stronger o1-preview reasoning model (36.6% medal) by 27 pp. On four shared tabular tasks, MLE-STAR outperforms DS-Agent [10] on all four metrics (e.g., WBY MAE 166 vs. 213; ES AUROC 0.9101 vs. 0.8727) without requiring a manually curated case bank. MLE-STAR also substantially exceeds the generalist agents MLAB [38] (6.1% medal) and OpenHands [39] (12.1% medal) when both use GPT-4o, reflecting the advantage of task-specific targeted refinement over generic tool-calling. The paper additionally reports a comparison with AutoGluon [26] in the appendix, where MLE-STAR is competitive on tabular tasks but extends to modalities (image, audio, text) that AutoGluon does not cover.

## Relation to Prior Work

MLE-STAR positions itself within the emerging line of LLM-based MLE agents (AIDE, DS-Agent, MLAB, OpenHands) but departs from them in two key ways. Rather than relying on the LLM's internal knowledge for model selection (as AIDE does) or a manually curated case bank (as DS-Agent does), it uses web search as a retrieval tool to ground initial solutions in up-to-date, task-specific models. Its refinement strategy also differs fundamentally: instead of modifying the entire code structure at each iteration, it performs ablation studies to identify the most impactful code block and then iteratively refines only that block, enabling deeper exploration within specific pipeline components (e.g., feature engineering). The LLM-proposed ensemble strategy, where the agent itself designs and iteratively improves how to merge multiple candidate solutions, is a novel addition not present in prior MLE agent work.

## Why It Matters / Open Questions

The 64% medal achievement rate on MLE-bench (vs. 36.6% for the best prior baseline) demonstrates that combining retrieval-augmented model selection with ablation-guided targeted refinement is a substantially more effective exploration strategy for code-space optimization than whole-script modification. The practical implication is that MLE agents can now leverage external knowledge and perform deep, component-level experimentation without requiring human-curated strategy banks, improving scalability to novel task types. Open questions include whether the approach generalizes to truly novel, unseen task modalities beyond Kaggle's existing competition types, whether the higher token cost (~$0.24/challenge) is acceptable at scale, and whether the potential for training-data contamination from public Kaggle discussions undermines the generality of the results.
