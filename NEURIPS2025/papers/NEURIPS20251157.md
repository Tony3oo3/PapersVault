## Problem

Existing computer-use agents fall into two camps—tool-based agents that require manual integration of tools for every desktop scenario, and pure vision-based agents that lack precision on tasks like file editing or code manipulation. No prior framework unifies both paradigms within a single modular architecture that can route subtasks to the most appropriate specialist model while maintaining a shared dialogue context.
![Teaser figure](../imgs/NEURIPS20251157/cropped_page1_idx0.webp)

## Input / Output

The agent consumes a natural-language user request alongside live desktop screenshots, audio files, video files, and file-system state within an isolated GNOME virtual machine. Outputs are structured as tagged tool invocations (e.g., <execute_bash>, <execute_python>, <task>, <toolkit>) that drive GUI actions, file modifications, and code execution; mouse-click actions specifically require the model to emit both a target element name and a detailed positional/shape description, which is then resolved to pixel coordinates by a separate visual-grounding model.

## Method

InfantAgent-Next decomposes the agent loop into three sequential stages—Planning, Tool Selection, and Execution—each handled by a distinct LLM with tailored prompt templates, while modality-specific tool models (vision, audio, video) are invoked as needed. A dynamic tool-selection mechanism categorizes tools into seven toolkits and retrieves only the relevant subset per iteration, reducing inference overhead. For mouse clicks, an Iterative Region Cropping algorithm (Algorithm 1) progressively narrows the search region over n iterations using a visual-grounding model, improving click precision over single-shot grounding. For file edits, a verification-and-fallback procedure (Algorithm 2) checks proposed line boundaries against actual file content and, on mismatch, applies fuzzy string matching to relocate the correct edit span before retrying. Memory is managed via tagged entries that are selectively reconstructed per stage, preventing cross-contamination between planning, selection, and execution contexts.

## Results

On OSWorld (50 steps), InfantAgent-Next (Claude-3.7-Sonnet + UI-TARS-1.5-7B) achieves 35.3% accuracy, surpassing Claude Computer Use (26.0% at 50 steps, 28.0% at 100 steps) by 7.27–9.3% and OpenAI CUA (32.6%) by 2.7%. On SWE-Bench-Verified (50 cases), it reaches 66% with Claude-3.7-Sonnet, and on SWE-Bench-Lite (GPT-4o) it scores 31.67%, placing it among the top open-source agents. On GAIA, it attains 56.97% average (62.79% on Level 2, the best among all open-source agents) and ranks second overall among open-source frameworks. File-editing repair achieves 90.4% total success rate with 84.3% Repair Success Rate.

## Baselines & Comparisons

On OSWorld at 50 steps, InfantAgent-Next (35.3%) outperforms Claude Computer Use (26.0%), OpenAI CUA (32.6%), and Agent S2 (34.5%), but trails the larger UI-TARS-1.5-72B model (38.0% at 50 steps, 42.5% at 100 steps). On SWE-Bench-Verified (50 cases), it achieves 66%, tying AgentScope (66%) and trailing SWE-agent with ReviewHeavy (72%) and OpenHands (68%), while clearly surpassing CORTEXA (62%), Amazon Q Developer (54%), and devlo (48%). On SWE-Bench-Lite with GPT-4o, InfantAgent-Next (31.67%) is nearly on par with Agentless-1.5 (32.00%) and beats OpenHands+CodeAct (22.00%). On GAIA, it ranks second among open-source agents (56.97% avg) behind OWL-Roleplaying (58.18%), but achieves the best Level-2 score (62.79%) among all entries, surpassing closed-source systems like desearch (58.14%) and Ormind (54.65%) on that tier. The iterative region-cropping design for mouse clicks and the fuzzy-matching fallback for file edits are the key architectural contributions driving these gains over single-model baselines.

## Relation to Prior Work

This paper is a direct successor to InfantAgent (Lei et al., 2024), extending it from a tool-integrated, logic-driven agent into a fully multimodal generalist framework. Conceptually, it departs from the binary classification of prior work into tool-based agents (OpenHands, AutoGPT) and pure vision-based agents (UI-TARS, Aguvis) by proposing a modular architecture that routes subtasks to specialized models—reasoning LLMs for planning, visual-grounding models for spatial localization, and audio/video models for perceptual tasks—within a unified dialogue context. The iterative region cropping for mouse clicks and the fuzzy-matching fallback for file editing are novel engineering mechanisms that address known failure modes of SOTA models (e.g., GPT-4o's 0.8% on ScreenSpot-Pro), but the overall design philosophy of multi-model orchestration follows the MetaGPT and AutoGen lineage.

## Why It Matters / Open Questions

The paper provides a practical, open-source framework that demonstrates a hybrid tool-plus-vision agent can match or exceed single-model approaches across diverse benchmarks (OSWorld, SWE-Bench, GAIA), which is valuable for practitioners seeking a deployable computer-use agent without proprietary APIs. However, the contribution is primarily architectural and engineering: no models are trained, and the system relies heavily on prompt engineering and hand-crafted heuristics (iterative cropping, fuzzy line matching). The authors themselves note the work is 'confined to the reasoning phase' and that future work should train models to invoke tools automatically rather than relying on manual prompts. Open questions include whether the modular routing generalizes to unseen software domains, whether the 7-toolkit taxonomy is sufficient, and whether the performance gains persist as base models improve in visual grounding and code editing natively.
