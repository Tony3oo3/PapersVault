## Problem

Large Reasoning Models (LRMs) struggle with precise mathematical computation, and while Code Interpreters (CIs) offer deterministic accuracy, integrating them creates a fundamental conflict between the model's internal probabilistic reasoning and external deterministic knowledge. This leads to two key inefficiencies: delayed code computation (models reason in text before calling code) and code result distrust (models unnecessarily re-verify CI outputs manually). The paper tackles how to synthesize high-quality training data for code-integrated reasoning when frontier models like o3/o4-mini do not expose their reasoning traces, and how to train models to efficiently interleave CI usage with chain-of-thought reasoning.

## Input / Output

The system takes a mathematical problem as text input and produces an iterative reasoning trace structured as a sequence of (textual reasoning step, Python code snippet, execution output) tuples, terminated by a final answer in \boxed{} format. The execution environment is a persistent Jupyter-like session where variables and functions carry across code blocks, with a hard limit of 15 tool calls and 32,768 tokens per sequence. When the tool-call limit is reached, a system message instructs the model to continue with pure reasoning, ensuring graceful degradation rather than truncation.

## Method

CoRT (Code-Optimized Reasoning Training) centers on Hint-Engineering, a data synthesis strategy that inserts targeted textual hints at specific decision points in reasoning trajectories: one hint redirects the model from manual calculation to Python code (fixing delayed computation), and another suppresses redundant re-verification of code outputs (fixing code result distrust). Only 30 manually annotated samples are needed for SFT, followed by rejection fine-tuning on 820 filtered trajectories for the 32B model. For the 1.5B model, strong-to-weak distillation transfers knowledge from the 32B model, then GRPO-based RL refines multi-round CI interaction with a persistent execution environment, output masking for training stability, and a dual reward combining answer accuracy with a small code-execution penalty (ω=0.1) to prevent infinite failure loops without over-suppressing exploration.

## Results

On five mathematical reasoning benchmarks (AIME24, AIME25, AMC23, MATH500, OlympiadBench), Prompt-Hint-SFT-32B achieves 81.8% average accuracy and Hint-Engineering-RFT-32B achieves 81.3%, both outperforming the non-tool DeepSeek-R1-32B baseline (77.5%). For 1.5B models, Prompt-Hint-1.5B-RL reaches 58.3% average accuracy, surpassing the non-tool DeepScaleR-1.5B-Preview (56.3%). In terms of token efficiency, Hint-Engineering-RFT-32B reduces token consumption by ~30% (7K vs 14K tokens on AIME24) while matching QwQ-32B's accuracy, and the 1.5B Hint-Engineering models reduce tokens by ~50% compared to pure CoT baselines.

## Baselines & Comparisons

Among 32B frontier models, Prompt-Hint-SFT-32B (81.8% avg) outperforms STILL-3-TOOL-32B (81.0%), ReTool-R1-32B (76.6%), and START-32B (AIME24: 66.7 vs 77.3), while remaining competitive with QwQ-32B (82.2% avg, no tool use). Hint-Engineering-RFT-32B (81.3% avg) achieves this with only 30 manually annotated SFT examples plus RFT, and reduces token usage by ~30% versus the non-tool DeepSeek-R1-32B baseline (77.5% avg). For 1.5B models, Prompt-Hint-1.5B-RL (58.3% avg) surpasses the non-tool DeepScaleR-1.5B-Preview (56.3%) and the tool-using ToRL-1.5B (48.5%) by 2% and 9.8% respectively. Against proprietary SOTA models, CoRT 32B models trail o3 (95.2% AIME24) and o4-mini (98.4% AIME24) by a wide margin, but the 32B models approach o1's AIME24 score (77.3 vs 74.3) while using tool use. The key differentiator is token efficiency: Hint-Engineering-RFT-32B matches QwQ-32B's AIME24 accuracy (76.7 vs 79.5) while using 50% fewer tokens (7K vs 14K).

## Relation to Prior Work

This paper extends the tool-integrated reasoning line (ToRA, START, STILL3, ReTool) by specifically targeting the LRM setting, where long chain-of-thought reasoning creates a fundamental tension between the model's internal probabilistic reasoning and the deterministic outputs of a code interpreter. The hint mechanism is inspired by START's self-taught reasoner approach, but departs from it by replacing random hint insertion with strategically positioned, behavior-specific hints that address two identified failure modes (delayed code computation and code result distrust). The training pipeline composes standard SFT, rejection fine-tuning, and GRPO-based RL (from DeepSeekMath), with a strong-to-weak distillation step to enable RL on smaller models where direct RL on 32B parameters is infeasible.

## Why It Matters / Open Questions

The practical significance lies in the 30–50% token reduction at comparable accuracy, which directly lowers inference cost for tool-augmented reasoning systems. The finding that 30 manually curated samples can initialize a model that, after RFT and RL, matches or exceeds 800-sample baselines reinforces the 'less is more' principle in LRM post-training and suggests data curation quality is underexploited. Key limitations include the restriction to mathematical reasoning (chemistry generalization is only in an appendix), the inability to run RL on the 32B model due to compute constraints, and the manual annotation requirement for hint placement that limits scalability. Open questions include whether the hint-engineering principles transfer to non-mathematical tool-use domains and whether the approach generalizes to models without the DeepSeek-R1 thinking-token architecture.
