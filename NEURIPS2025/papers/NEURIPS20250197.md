## Problem

Existing Gumbel-max coupling for distribution matching handles only a single proposal from one party, while multi-draft speculative decoding and multi-decoder lossy compression require coordinating K proposals with a single target sample without communication. Prior multi-draft methods (SpecInfer, SpecTr) rely on rejection sampling or optimal transport approximations that are not drafter-invariant, meaning the output distribution changes if the draft model changes even when the draft tokens remain the same. The paper asks how to couple K proposals from one distribution with one sample from another to maximize the probability that at least one matches, and how to exploit this for both LLM inference acceleration and distributed source coding.

## Input / Output

For speculative decoding, the method consumes K draft token sequences (each of length L, generated autoregressively from one or more draft models) and the target model's conditional distributions over the full vocabulary (151,936 tokens for Qwen 2.5), producing an accepted token sequence of length τ ≤ L+1. For lossy compression, the encoder takes a source sample A and transmits a single integer index M (of log L_max bits) to K decoders, each of which additionally observes independent side information T_k, producing K reconstruction candidates from which the best is selected. All sampling is driven by shared uniform random numbers converted to exponentials, so no rejection sampling is needed and the output distribution is invariant to which draft model generated the tokens.

## Method

The core contribution is Gumbel-max List Sampling (GLS), which uses K sets of N shared i.i.d. Exp(1) random variables to generate K coupled proposals X^(k) from p_X and one target sample Y from q_Y. The key mechanism is that Y is drawn by taking argmin over the minimum across all K sets (min_k S_i^(k)/q_i), while each X^(k) uses only its own set (argmin_i S_i^(k)/p_i); this 'minimum over k' in the target sampling simultaneously couples all K proposals with Y. The List Matching Lemma (Theorem 1) provides a closed-form lower bound on the acceptance probability that recovers the exact single-draft Gumbel-max bound when K=1 and approaches 1 as K grows. For speculative decoding, GLS is applied at each decoding step with a shrinking set of active drafts, yielding a drafter-invariant algorithm that provably matches the target model's autoregressive output distribution (Proposition 3). For lossy compression, a conditional variant (Theorem 2) lets the encoder condition on the source while K decoders condition on independent side information, with error probability bounded by a function of the conditional information density i(W;A|T).

## Results

On LLM inference with i.i.d. drafts (L=4, K=8), the proposed GLS-based scheme achieves block efficiency (BE) of 4.78, 4.55, and 4.18 on GSM8K, HumanEval, and NaturalReasoning respectively, with token-rate speedups of 4.83%, 8.03%, and 12.75% over single-draft speculative decoding. These numbers match SpecInfer and SpecTr within one standard error across all three benchmarks. In the more challenging diverse-draft setting (K=2, mismatched temperatures), the method achieves 11.50–13.68% token-rate speedup on GSM8K, consistently outperforming SpecInfer which degrades to 0.06% or even negative speedups when the first drafter is most misaligned.

## Baselines & Comparisons

Against SpecInfer [34] and SpecTr [38], the GLS-based scheme achieves statistically equivalent block efficiency and token-rate speedups (within one standard error) on all three i.i.d.-draft benchmarks, while additionally providing a formal drafter-invariance guarantee that neither baseline offers. Against the single-draft drafter-invariant method of Daliri et al. [9], the proposed multi-draft GLS scheme substantially outperforms: e.g., on HumanEval the token-rate speedup jumps from 0.04% (Daliri) to 8.03% (ours), and on NaturalReasoning from −2.23% to 12.75%. In the diverse-draft experiment (Table 2), where drafters use mismatched temperatures, the GLS scheme consistently beats SpecInfer on token rate across GSM8K, HumanEval, and MBPP; for instance, at temperatures 0.5/1.0 on GSM8K, the proposed method achieves 11.50% speedup versus only 0.06% for SpecInfer, and this gap persists regardless of draft ordering, whereas SpecInfer's recursive rejection is sensitive to which drafter appears first.

## Relation to Prior Work

This paper extends the single-proposal Gumbel-max coupling of Daliri et al. [9] to the multi-proposal setting, introducing Gumbel-max List Sampling (GLS) and the List Matching Lemma (LML) as a discrete generalization of the Poisson Matching Lemma from Li and Anantharam [26]. For speculative decoding, it departs from the rejection-sampling-based verification in SpecInfer [34] and SpecTr [38] by using common random numbers, which yields a drafter-invariance guarantee absent in those schemes. For lossy compression, it extends the Importance Matching Lemma of Phan et al. [36] from a single decoder to K decoders with independent side information, generalizing the Wyner-Ziv framework to a list-decoding setting.

## Why It Matters / Open Questions

The GLS framework provides a simple, drop-in mechanism for multi-draft speculative decoding that matches state-of-the-art baselines in speed while offering a formal drafter-invariance guarantee, making it robust to changes in the draft model without re-deriving verification logic. The lossy compression extension to multiple decoders with independent side information opens a new direction in distributed source coding relevant to practical scenarios like decentralized sensing. Key limitations include O(NK) memory scaling for large vocabularies, dependence on floating-point determinism across encoder/decoder, and the fact that performance gains over baselines are most pronounced only in the diverse/mismatched-draft setting rather than the standard i.i.d. case. Open questions include extending GLS to continuous sample spaces (e.g., diffusion models) and exploring a symmetric variant where both parties generate lists and accept on nonempty intersection.
