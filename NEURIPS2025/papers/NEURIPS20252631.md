## Problem

Existing image captioning methods either produce overly brief descriptions that sacrifice critical details or generate verbose paragraphs that are computationally burdensome, and no prior work has formulated or addressed the task of finding the minimum text equivalent of an image. State-of-the-art MLLMs, despite strong general capabilities, exhibit limited performance in comprehensively capturing all semantic elements—entities, their precise locations, attributes, inter-entity relations, and global image state—within a single structured description.

## Input / Output

The method takes a single RGB image as input and produces a panoptic caption: a comprehensive natural-language description that embeds bounding box coordinates (normalized to integers in [0,1000)) for every detected entity instance, assigns semantic category tags, describes per-instance attributes (color, shape, material, text rendering, etc.), specifies inter-entity relations (positional, part-whole, action), and states global image properties (lighting, color palette). Unlike conventional captions that vaguely specify locations with words, the output explicitly localizes each entity with coordinate tuples in the format <box>[[x1,y1,x2,y2]]</box>, enabling precise spatial grounding within the text.

## Method

PancapChain decouples panoptic captioning into four sequential generation stages—entity instance localization, semantic tag assignment, extra instance discovery, and full caption generation—each trained with its own auto-regressive loss on the LLaVA/ASMv2-13B backbone fine-tuned via LoRA. The key insight, inspired by cognitive science, is that a model cannot reliably perceive all scene elements simultaneously, so it first predicts bounding boxes, then assigns tags to those boxes, then discovers additional missed instances (simulated by randomly splitting ground-truth instances into 'known' and 'to-discover' subsets during training), and finally composes the full caption conditioned on the aggregated instance list. The supporting PancapEngine data pipeline detects diverse entities by combining class-agnostic detection (OLN) with image tagging (RAM, 6400+ categories) and class-aware detectors (Grounding-DINO, OW-DETR), then generates captions via entity-aware prompts to Gemini-Exp-1121 and Qwen2-VL-72B, filtering for cross-model consistency using PancapScore. Evaluation uses the proposed PancapScore metric, which extracts semantic content via LLMs, performs optimal one-to-one entity instance matching (weighted tag similarity + box IoU) for tagging/localization F-scores, and conducts instance-aware question answering for attribute, relation, and global state dimensions.

## Results

On the SA-Pancap test set (human-curated), PancapChain-13B achieves an overall PancapScore of 173.19, substantially outperforming all 72B+ open-source MLLMs (best: Qwen2.5-VL at 156.89) and proprietary models (Gemini-2.0-Pro at 157.88, GPT-4o at 148.01). On the validation set, PancapChain-13B scores 175.75 overall, leading by ~25 points over the next-best model. In downstream image-text retrieval on DOCCI, PancapChain achieves 61.9% Recall@1 as a text-text method, surpassing ALIGN (59.9%) and ShareGPT4V (59.6%) without any specialized retrieval training.

## Baselines & Comparisons

PancapChain-13B decisively outperforms all 72B–90B open-source MLLMs on the SA-Pancap test set: it leads Qwen2.5-VL-72B (156.89) by 16.3 points, InternVL-2.5-78B (154.66) by 18.5 points, and Llama-3.2-90B (147.35) by 25.8 points in overall PancapScore. It also surpasses proprietary models Gemini-2.0-Pro (157.88) and GPT-4o (148.01) by 15.3 and 25.2 points respectively, despite being roughly 5–7× smaller. Among same-scale tuned 13B baselines, PancapChain beats LLaVA-1.5 (164.92) by 8.3 points and ShareGPT4V (151.21) by 22.0 points, confirming the benefit of its staged generation design over direct fine-tuning. In the DOCCI image-text retrieval experiment, PancapChain (61.9% R@1) outperforms ALIGN (59.9%), ShareGPT4V (59.6%), and BLIP (47.3%) as a text-text method, but falls slightly short of the dedicated image-text model MATE (62.9%). The ablation study further shows that each stage of PancapChain contributes incrementally: adding entity localization and tag assignment improves tagging from 56.38 to 57.04, and the full four-stage pipeline reaches 57.56 tagging and 34.61 relation, a 6.5+ point overall gain over the one-stage baseline.

## Relation to Prior Work

This paper builds on the LLaVA architecture and ASMv2's grounding capabilities as its backbone, but departs fundamentally from prior captioning work by requiring bounding box coordinates embedded within the caption text rather than vague spatial language. It positions itself against three lines of work: (1) detailed captioning (ShareGPT4V, DenseFusion) which lacks precise localization, (2) dense captioning (DenseCap) which covers limited entity categories, and (3) grounded MLLMs (GLaMM, PixelLM, Osprey) which rely on specialized detection modules rather than unified textual generation. The key conceptual departure is the 'minimum text equivalent' framing, which treats image-to-text as a lossless encoding problem across five semantic dimensions (tag, location, attribute, relation, global state) rather than a free-form description task.

## Why It Matters / Open Questions

The paper reveals that even the strongest proprietary MLLMs (GPT-4o, Gemini-2.0-Pro) and large open-source models (InternVL-2.5-78B) struggle with comprehensive image description, particularly on localization (scores of 10–30 vs. 50+ for tagging), suggesting a fundamental gap in current vision-language alignment. The SA-Pancap benchmark and PancapScore metric provide the community with a structured evaluation framework that existing captioning metrics (BLEU, CIDEr) cannot address. However, the task formulation remains an approximation of true 'minimum text equivalence,' and the evaluation is conducted on the authors' own benchmark with their own metric, limiting external validation. Open questions include whether the staged decomposition generalizes to more complex scenes, whether the 13B model's advantage over 78B+ models reflects a genuine architectural insight or simply task-specific overfitting to the SA-Pancap distribution, and how to extend this toward truly lossless image-to-text encoding.
