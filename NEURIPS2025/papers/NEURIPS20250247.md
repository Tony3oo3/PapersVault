## Problem

The Option Keyboard (OK) can produce policies superior to GPI by dynamically combining base policies via a learned meta-policy, but its performance critically depends on the choice of base policies, and no method existed to identify an optimal behavior basis. Existing approaches that guarantee zero-shot optimality for all linear tasks require computing a full Convex Coverage Set (CCS), whose size grows exponentially with the number of reward features, making them intractable in complex domains. This paper solves the open problem of constructing a minimal behavior basis that provably enables the OK to optimally solve any linear task.

## Input / Output

The method takes a Markov Control Process (MPC) with a fixed set of reward features φ(s,a) ∈ R^d and a family of tasks defined by convex weight vectors w over these features. It outputs a behavior basis Π_k (a set of optimal base policies, guaranteed |Π_k| ≤ |CCS|) and a meta-policy ω: S×W→Z trained via actor-critic RL. All base policies' successor features are encoded in a single Universal Successor Feature Approximator (USFA) conditioned on task vectors, avoiding the memory cost of separate networks per policy. At inference time, given a new task w, the OK policy π^OK_ω(s,w;Π_k) is evaluated zero-shot without further environment interaction.

## Method

OKB (Algorithm 1) iteratively constructs the behavior basis by alternating between two phases: (i) OK-LS (Algorithm 2), which trains the meta-policy ω on corner-weight tasks to iteratively approximate a CCS in the OK's expressible policy space, and (ii) a coverage check that identifies tasks the current OK cannot solve optimally (via a positive-advantage test, Thm 4.2) and adds a new optimal base policy for one such task. The key insight is that the OK's state-dependent weighting of base policies makes it strictly more expressive than GPI: the meta-policy can switch between base policies as a function of state, so a single base policy can contribute different actions in different states, reducing the number of policies needed to cover the CCS. Theoretical guarantees (Thm 4.3) prove CCS ⊆ Ψ^OK(Π_k), and Prop 4.4 further shows the OKB is strictly more expressive than a CCS, enabling optimal zero-shot solving of a class of non-linear tasks whose optimal policies decompose into sequences of CCS-optimal sub-policies.

## Results

On the Minecart domain (d=3), OKB reaches near-optimal normalized return with only 2–3 base policies, outperforming SFOLS and OKB-Uniform at every iteration. On FetchPickAndPlace, the performance gap between OKB and SFOLS widens substantially as the number of reward features d increases from 2 to 8, confirming that OKB's advantage scales with task complexity. On the non-linear Item Collection task, OKB and SIP both solve the sequential collection task, but OKB converges faster in terms of environment interactions, while the DQN-from-scratch baseline fails entirely. Across all four domains, OKB consistently achieves the highest mean normalized return with fewer base policies than competing methods.

## Baselines & Comparisons

OKB outperforms SFOLS (Alegre et al., 2022) across all four domains, with the margin growing as the number of reward features d increases in FetchPickAndPlace (d=2,4,6,8), directly answering whether the advantage scales with complexity. Against OKB-Uniform (a variant that selects tasks uniformly rather than via corner weights), OKB shows a clear advantage in the Highway domain, highlighting the importance of the corner-weight-based task selection strategy. On the non-linear Item Collection task, OKB outperforms SIP (Alver and Precup, 2022) by reaching the optimal sequential-collection policy with fewer environment interactions, while both methods succeed where the DQN baseline (Mnih et al., 2015) fails to solve the task at all. Notably, OKB achieves these gains while using only half its interaction budget for base-policy learning (the other half is allocated to meta-policy training), making the comparison conservative in OKB's favor.

## Relation to Prior Work

This paper builds directly on the successor features (SFs) and generalized policy improvement (GPI) framework (Barreto et al., 2017, 2018) and the Option Keyboard (OK) method (Barreto et al., 2019), which allows state-dependent combination of base policies via a learned meta-policy. It departs from prior CCS-construction methods (SFOLS, Alegre et al. 2022) that require learning one policy per CCS element—whose size grows exponentially with the number of reward features—by instead learning a smaller behavior basis and a meta-policy that jointly express all CCS solutions. The iterative corner-weight selection strategy is adapted from SFOLS but operates over the meta-policy space rather than the base-policy space, and the optimality verification via advantage functions (Thm. 4.2) is a new diagnostic tool not present in prior GPI or OK literature.

## Why It Matters / Open Questions

OKB addresses a critical scalability bottleneck in multi-task RL: computing a full CCS is intractable as the number of reward features grows, yet prior methods required exactly |CCS| base policies. By proving that a smaller basis suffices (Thm. 4.3) and that the resulting OK is strictly more expressive than a CCS (Prop. 4.4, enabling optimal solutions for certain non-linear tasks), the paper opens a path toward practical zero-shot transfer in high-dimensional multi-objective settings. Key limitations include the assumption that NewPolicy returns truly optimal base policies and that the meta-policy converges, as well as the restriction to linearly-expressible reward features. Open directions include combining OKB with learned reward features (e.g., Forward-Backward representations), temporally extended meta-policies with learned termination, and integration with multi-objective RL techniques.
