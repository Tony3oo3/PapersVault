## Problem

Existing multi-agent system (MAS) memory mechanisms are either limited to inside-trial context or store only final outcome artifacts, completely disregarding the nuanced inter-agent collaboration trajectories that constitute the bulk of MAS experience. Directly transferring single-agent memory designs is infeasible because MAS trajectories are up to 10× longer in token count, and agents play distinct roles requiring specialized memory. The paper asks: how can we design a memory mechanism that stores, retrieves, and manages lengthy MAS interaction history so that agent teams can leverage concise, instructive experience across trials?

## Input / Output

G-Memory is triggered upon arrival of a new user query Q and consumes the existing three-tier graph hierarchy (query graph with MiniLM embeddings, insight graph, and per-query interaction graphs) along with each agent's role specification. It produces role-specific memory cues for every agent in the MAS—filtered high-level insights and LLM-sparsified interaction subgraphs—without modifying the underlying MAS framework. After task execution, the system ingests the full interaction trajectory, execution status (Resolved/Failed), and environmental feedback to update all three graph levels in an agentic manner.

## Method

G-Memory organizes MAS memory into a three-tier graph hierarchy: an Insight Graph (distilled generalizable insights connected via hyper-edges that reference supporting queries), a Query Graph (task queries with status metadata and semantic edges encoding cross-task relevance), and an Interaction Graph (fine-grained utterance-level communication logs with temporal edges). Upon a new query, G-Memory performs coarse-grained retrieval via embedding similarity plus 1-hop expansion on the query graph, then executes bi-directional traversal: upward to project relevant insight nodes for strategic guidance, and downward to apply an LLM-facilitated graph sparsifier that extracts core collaboration subgraphs from full interaction trajectories. A role-aware operator Φ then assigns each agent a filtered subset of insights and interaction snippets tailored to its function. Post-execution, all three levels are jointly updated—new query nodes with edges to relevant historical queries, new insight nodes linked to previously utilized insights, and updated supporting-query sets—enabling progressive, cross-trial evolution of the agent team's collective knowledge.

## Results

On GPT-4o-mini (Table 1), G-Memory achieves the best average score across all three MAS frameworks: 57.18 (AutoGen), 50.88 (DyLAN), and 51.95 (MacNet), outperforming the strongest single-agent memory baseline (Voyager) by 3.66, 3.03, and 4.81 points respectively. With the stronger Qwen-2.5-14b backbone, G-Memory delivers up to 20.89% improvement on embodied action (MacNet+ALFWorld: 58.21→79.10) and up to 10.12% on knowledge QA (MacNet+HotpotQA: 24.49→34.61). G-Memory also maintains token efficiency, incurring only ~1.4×10⁶ additional tokens on PDDL+AutoGen for a 10.32% gain, compared to 2.2×10⁶ tokens for a mere 4.07% gain with MetaGPT-M.

## Baselines & Comparisons

G-Memory outperforms all six baselines across every benchmark and MAS framework. Against the strongest single-agent memory baselines, G-Memory leads Voyager by +3.66 avg (AutoGen) and +4.81 avg (MacNet), and beats Generative Agents by +4.20 avg (AutoGen) and +6.16 avg (MacNet). Among multi-agent memory baselines, G-Memory surpasses MetaGPT-M by +5.14 avg (AutoGen) and +4.88 avg (MacNet), ChatDev-M by +10.95 avg (AutoGen) and +10.45 avg (MacNet), and MacNet-M by +8.35 avg (AutoGen) and +9.90 avg (MacNet). Notably, several baselines actually degrade performance relative to no-memory: MemoryBank drops AutoGen's PDDL score by 3.12 points, and ChatDev-M reduces DyLAN's HotpotQA by 9.24 points, underscoring that naive single-agent or result-only memory is ill-suited for MAS. The largest single-benchmark gains occur on PDDL (strategic game), where G-Memory's role-specific memory cues and interaction trajectories are most critical: +12.15 over no-memory on MacNet and +7.33 on DyLAN.

## Relation to Prior Work

This paper draws on organizational memory theory (Walsh & Ungson, 1991) to design a three-tier hierarchical graph architecture (insight, query, interaction) specifically for multi-agent systems, departing from both single-agent memory mechanisms (MemoryBank, MemGPT, Voyager, Generative Agents) and the rudimentary cross-trial memory in existing MAS frameworks (MetaGPT, ChatDev, MacNet). The key conceptual departure is the argument that single-agent memory cannot be naively transferred to MAS due to ~10× longer collaboration trajectories and the need for role-specific memory assignment, motivating the bi-directional traversal (upward for abstract insights, downward for condensed interaction subgraphs) and the LLM-facilitated graph sparsifier. As a plug-and-play module, G-Memory integrates into AutoGen, DyLAN, and MacNet without modifying their internal logic, distinguishing it from automated MAS design approaches (GPTSwarm, ADAS, AFlow) that restructure the entire agent topology.

## Why It Matters / Open Questions

The paper identifies and empirically validates a fundamental gap: existing MAS lack the memory infrastructure needed for genuine self-evolution, and the finding that single-agent memory mechanisms can actively degrade MAS performance (e.g., Voyager and MemoryBank hurting PDDL scores) challenges the assumption that more retrieved context is always beneficial. The plug-and-play design and consistent gains across five benchmarks, three LLM backbones, and three MAS frameworks make this practically relevant for anyone deploying LLM-based multi-agent pipelines. Limitations include evaluation on only three MAS frameworks and five benchmarks (no medical QA, long-horizon planning, or very large agent populations), and the scalability of the three-tier graph hierarchy as the number of stored queries grows remains untested.
