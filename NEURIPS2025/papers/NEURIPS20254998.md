## Problem

Existing LLM backdoor defenses rely on white-box access (parameters, gradients, logits) or computationally expensive optimization, making them impractical for black-box API users with limited resources. Moreover, most methods target classification tasks and fail to generalize to open-ended generative scenarios where the space of source-target mappings is vast and unenumerable. This paper addresses the need for a lightweight, black-box backdoor detection method that works for generative LLMs before deployment.

## Input / Output

The method consumes a set of targeted ICL prompts—each containing a small ratio (e.g., 1/3) of backdoor examples (input with an ICL trigger, output set to the target malicious response), a majority of correct examples, and a triggered input query—sent sequentially to a black-box LLM API. The defender only needs to know the backdoor target type (refusal or jailbreaking), not the specific trigger or its location. The output is a binary detection flag: the model is flagged as backdoored if the empirical success rate of the ICL trigger eliciting the target response exceeds a threshold δ, estimated from as few as 10–20 API queries.

## Method

ICLScan exploits the Backdoor Susceptibility Amplification (BSA) phenomenon: LLMs with pre-embedded backdoors exhibit dramatically heightened sensitivity to new trigger implantation via ICL, because their internal signal-dependent pathways generalize easily to similar signal-to-target patterns presented in backdoor examples. The detection framework constructs targeted ICL prompts where a small proportion α of examples map an ICL trigger (different from the pre-embedded trigger) to the same target response as the existing backdoor, mixed with correct examples and a triggered query. The model is then probed statistically: if the success rate P(T|M(X)) of producing the target response upon encountering the ICL trigger exceeds a threshold δ (set slightly below α when α≤0.5, or 0.5 when α>0.5), the model is classified as backdoored. This requires no model access, no training, and only multiple API queries, achieving near-perfect detection (precision/recall/F1/AUC ≈ 1.000) with ~160 seconds of overhead versus ~5000 seconds for the white-box baseline CLIBE.

## Results

ICLScan achieves near-perfect backdoor detection across all tested settings (refusal and jailbreaking backdoors, word/phrase/long/CBA triggers, LLaMA-2-7B and Qwen2.5 models), with average Precision, Recall, F1-score, and ROC-AUC all equal to 1.000. Detection requires only 100 targeted ICL prompts (160 seconds total), and even 10–20 prompts yield F1-scores above 0.933. The method is robust to different ICL triggers (Placid, 123456, ctfqxy) and out-of-distribution prompt sources, maintaining F1 ≥ 0.938 in the worst case.

## Baselines & Comparisons

The paper compares ICLScan against CLIBE [Zeng et al., 2024], the closest existing backdoor detection method, which was originally designed for white-box NLP classification but adapted here to generative tasks. ICLScan decisively outperforms CLIBE on every metric: average ROC-AUC of 1.000 vs. 0.621, F1 of 1.000 vs. 0.683, and detection time of 160 s vs. 5047 s (a ~31× speedup). CLIBE's weakness stems from its reliance on optimizing transferable weight perturbations in a proxy model, which breaks down in open-ended generative settings where source-target mappings span a vast, non-differentiable output space. ICLScan avoids this by exploiting the Backdoor Susceptibility Amplification phenomenon—requiring only API queries with targeted ICL prompts—making it the first method to achieve reliable black-box backdoor detection for generative LLMs.

## Relation to Prior Work

This paper carves new ground at the intersection of backdoor detection and in-context learning, repurposing ICL from an attack vector (as in Kandpal et al. and Zhao et al.) into a detection illumination. It departs from prior backdoor defenses that require white-box access (trigger inversion, parameter analysis) or target only classification tasks, by exploiting the newly discovered Backdoor Susceptibility Amplification (BSA) phenomenon: pre-embedded backdoors make LLMs disproportionately vulnerable to new trigger injection via ICL. The closest prior work, CLIBE, probes weight-space perturbations for classification models; ICLScan instead operates purely through API queries in the input space, making it the first method to address black-box backdoor detection for open-ended generative tasks.

## Why It Matters / Open Questions

As LLM-as-a-Service becomes the dominant deployment paradigm, API users need lightweight, proactive auditing tools before integrating models into critical workflows; ICLScan's requirement of only 10–20 queries with no training or model access makes it practically deployable. Key limitations include the assumption that the defender knows the backdoor target type (refusal vs. jailbreak) and the inability to handle dynamic, context-dependent backdoor patterns. Open questions include whether BSA persists in frontier-scale models (70B+), whether it generalizes to backdoor targets beyond refusal/jailbreak (e.g., fixed-sentence outputs), and how to extend detection to unknown or evolving backdoor targets without prior knowledge.
