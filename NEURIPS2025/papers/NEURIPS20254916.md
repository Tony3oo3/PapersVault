## Problem

Reinforcement learning research is hindered by the lack of a maintained, standardized interface between environments and training algorithms, making it difficult to compare results and build on prior work. OpenAI Gym, the de facto standard, has been unmaintained since October 2022, leaving the field without an actively developed API that supports modern research needs such as hardware-accelerated vectorization, multi-modal observation spaces, and theoretically grounded environment formalisms.

## Input / Output

Environments are instantiated by name and version string via a registry (e.g., 'CartPole-v1'), optionally with a random seed for reproducibility. Each step call consumes a single action drawn from the environment's action space and returns a tuple of (observation, reward, terminated, truncated, info), where the two boolean signals explicitly distinguish state-dependent episode endings (termination) from arbitrary cutoffs like time limits (truncation). In vectorized mode, all sub-environment results are batched into arrays, and the info dictionary carries per-sub-environment metadata such as the final observation under same-step autoreset.

## Method

Gymnasium introduces four core API extensions over OpenAI Gym: (1) a Functional Environment API (FuncEnv) that maps directly to POMDP components (initial, transition, observation, reward, terminal), enabling stateless function composition for JAX-based hardware acceleration; (2) an explicit two-signal return from step() separating termination from truncation, which is critical for correct value estimation in algorithms like PPO and DQN; (3) first-class vectorization with Sync, Async, and custom vectorizers plus three autoreset modes (next-step, same-step, disabled) to maximize throughput across heterogeneous sub-environment episode lengths; and (4) expanded algebraic spaces including Text, Graph, Sequence, and OneOf to support multi-modal observations and actions. The library also provides 33+ built-in wrappers, a versioned registry for reproducibility, and an API checker for environment compliance, all maintained as an open-source Python package with over 18 million downloads.

## Results

Gymnasium reports over 18 million downloads from its initial release in November 2023 through May 2025, with over 500 GitHub issues resolved and 800 Pull Requests merged from 40+ unique contributors. In vectorization benchmarks (Figure 3), AsyncVectorEnv outperforms SyncVectorEnv on high-RAM hardware (M3 MacBook Pro, 128 GB) for the Lunar Lander environment, while SyncVectorEnv is preferable on weaker hardware (Google Colab) due to subprocess overhead. Custom vectorized implementations (e.g., CartPole via tensor operations) achieve roughly an order-of-magnitude speedup over both Sync and Async modes without additional memory overhead.

## Baselines & Comparisons

This is a library/framework paper rather than an algorithm paper, so it does not report quantitative performance comparisons against baseline RL methods. The primary comparison (Table 1) is qualitative, positioning Gymnasium against its predecessor OpenAI Gym and the alternative dm_env API. Gymnasium is distinguished by its active development status (vs. OpenAI Gym's unmaintained state since October 2022), its comprehensive set of 33 built-in wrappers and vectorization tools (vs. dm_env's minimalistic design), and its widespread native adoption across major training libraries (Stable Baselines3, CleanRL, Tianshou, Ray RLlib, Dopamine). The paper also notes that Gymnasium's explicit separation of termination and truncation signals addresses a correctness issue that affected many OpenAI Gym-based training libraries, which often conflated the two.

## Relation to Prior Work

Gymnasium is the directly maintained successor to OpenAI Gym (Brockman et al., 2016), retaining its core object-oriented Env abstraction while introducing four key extensions: a functional FuncEnv API aligned with POMDP formalism, explicit separation of termination and truncation signals, first-class vectorized environment support with multiple autoreset modes, and expanded algebraic spaces (text, graphs, sequences, disjoint unions). It positions itself against dm_env (DeepMind's minimalistic API) and PettingZoo (multi-agent), offering a more comprehensive tooling ecosystem while remaining compatible with major training libraries like Stable Baselines3, CleanRL, Tianshou, and Ray RLlib.

## Why It Matters / Open Questions

With over 18 million downloads and native support across major RL frameworks, Gymnasium has effectively become the de facto standard for RL environment interfacing, removing a significant reproducibility and interoperability barrier that fragmented the field. The termination/truncation distinction, while seemingly minor, has nontrivial correctness implications for value-estimation algorithms (REINFORCE, PPO, DQN, SAC), and the functional API opens the door to JAX-based hardware-accelerated environments (Brax, Pgx, Jumanji). Key limitations remain: Python-only implementation constrains raw speed compared to C/C++/Cython environments, and the library is purely an environment API requiring separate training frameworks. Open questions include whether the functional paradigm will fully supplant the object-oriented Env for new environment implementations, and how the ecosystem will handle increasingly complex multi-modal and multi-agent settings.
