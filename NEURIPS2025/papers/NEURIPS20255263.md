## Problem

Existing time normalization systems built on ISO-TimeML cannot handle compositional, event-relative, or multi-span temporal expressions, and the more expressive SCATE framework has only been realized through complex multi-stage pipelines with separate recognition models and handcrafted rule systems. This makes SCATE-based normalization expensive, hard to maintain, and impractical for real-world deployment. The paper asks whether time normalization can be formulated as a single end-to-end code generation task that is both expressive and deployable on small hardware.

## Input / Output

The system takes a natural language sentence together with a document creation time (DCT) that anchors all relative temporal references. It produces a JSON list of (time_text, scate_code) pairs, where each scate_code is a string of executable Python using a custom SCATE library (e.g., Last(Interval.of(2024,11,1), Period(DAY,4))). Executing the generated code deterministically yields timeline-anchored intervals with second-level precision, so correctness can be verified by running the code rather than by string matching against a fixed label set.

## Method

The core contribution is implementing the full SCATE framework as a composable, executable Python library (Interval, Period, Repeating, and operator classes such as Last, Next, After, Before, Nth, These, Between, ShiftUnion, RepeatingIntersection), then framing time normalization as generating valid SCATE code from text. For data augmentation, the authors craft detailed SCATE prompts that serve as library documentation and use Claude 3.7 to annotate 10k CC-News sentences, automatically discarding any output that raises a runtime error during code execution. They then fine-tune small decoder-only (Qwen2.5-0.5B) and encoder-decoder (T5-Large) models on the union of augmented and original TempEval-2013 data. The resulting 0.5B-parameter model achieves 0.59 F1 on the test set—surpassing its LLM parent (Claude 3.7 at 0.52 F1) by 10 points—while running 31.7× faster than the prior LSTM-based SCATE pipeline, demonstrating that code generation with execution-based validation enables both expressivity and practical deployment.

## Results

On the TempEval-2013 test set (313 examples), the best configuration—Qwen2.5-0.5B fine-tuned on both LLM-augmented CC-News data and the original training set—achieves 0.59 F1, 0.59 precision, and 0.59 recall. This small 0.5B model outperforms its LLM parent (Claude 3.7 + SCATE Prompt, F1 0.52) by 7 points and GPT-4.1 + SCATE Prompt (F1 0.51) by 8 points. The SCATE code generation formulation also significantly outperforms direct interval generation via few-shot prompting (0.52 vs. 0.38 F1 for Claude 3.7), and the fine-tuned model runs 31.7× faster than the prior LSTM-based SCATE system [Xu et al., 2019].

## Baselines & Comparisons

The paper's primary comparison is between the fine-tuned small model and zero-shot LLM prompting baselines. Qwen2.5-0.5B trained on augmented + original data (F1 0.59) beats Claude 3.7 with SCATE prompting (F1 0.52) by 7 points and GPT-4.1 with SCATE prompting (F1 0.51) by 8 points, demonstrating that a 0.5B locally deployable model can surpass much larger proprietary LLMs on this task. A second key comparison shows that generating SCATE code as an intermediate representation outperforms directly predicting time intervals: Claude 3.7 achieves F1 0.52 with SCATE code generation versus only 0.38 with direct interval few-shot prompting, a 14-point gap. Among architecture choices, the decoder-only Qwen2.5-0.5B (F1 0.59) substantially outperforms the encoder-decoder T5-Large (F1 0.43) under the same training data, despite having fewer parameters (500M vs. 770M). In terms of efficiency, the fine-tuned Qwen model processes the entire test set in 6 seconds versus 190 seconds for the prior LSTM-based SCATE pipeline [Xu et al., 2019], a 31.7× speedup.

## Relation to Prior Work

This paper builds on the SCATE compositional temporal semantics framework (Bethard and Parker, 2016), which prior systems (Laparra et al., 2018; Xu et al., 2019) treated as an annotation schema requiring multi-stage pipelines with separate recognition models and handcrafted rule systems. The key departure is implementing SCATE as a fully executable Python library and reframing time normalization end-to-end as a code generation task, drawing on the broader code-generation-for-information-extraction paradigm (Code4Struct, CodeIE, KnowCoder). It also departs from the dominant ISO-TimeML-based normalization literature (HeidelTime, SUTime, transformer classifiers) by targeting the more expressive compositional representations that ISO-TimeML cannot capture.

## Why It Matters / Open Questions

The practical significance lies in showing that a 0.5B-parameter locally deployable model, trained on LLM-augmented data with code-execution validation, can outperform the much larger LLM used for augmentation (Qwen2.5-0.5B at 0.59 F1 vs. Claude 3.7 at 0.52 F1), enabling expressive time normalization without cloud API dependencies. The data augmentation pipeline—using LLMs to generate SCATE code and filtering via runtime execution—is a reusable technique for other structured-output NLP tasks. Open questions include generalization beyond TempEval-2013 (the only publicly available SCATE-annotated dataset), multilingual and open-domain performance, and whether the approach scales to more complex or nested temporal expressions where the current model's 70% error rate is dominated by span-recognition failures rather than code-generation errors.
