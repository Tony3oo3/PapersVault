## Problem

Existing datasets for detecting malicious PyPI packages rely on metadata inspection and static code analysis, which cannot observe what happens during or after a package is installed. This blind spot leaves next-gen supply chain attacks—multiphase malware execution, covert remote access activation, and dynamic payload generation—undetectable, undermining the reliability of Malicious Detection System (MDS) evaluations.
![Teaser figure](../imgs/NEURIPS20254755/cropped_page3_idx0.webp)

## Input / Output

The method consumes eBPF-captured behavioral traces from 14,271 Python packages (7,127 malicious) executed in isolated Raspberry Pi sandboxes, recording 36 features across six categories: file I/O, dependency logs, file-open attempts, TCP flows, system calls, and behavioral sequence patterns. Categorical trace features are encoded as n-gram frequency vectors while numerical features undergo min-max normalization, producing a fixed-dimension feature vector per package. The output is a binary malicious/benign label with standard classification metrics (accuracy, precision, recall, F1) and confusion-matrix statistics.

## Method

The core contribution is a three-phase dataset construction framework: (i) collecting malicious packages from multiple threat-intelligence sources and pairing each with its most lexically similar benign counterpart via a similarity threshold, (ii) validating labels through majority voting across VirusTotal, NDV, and Snyk, and (iii) deploying each package to a uniformly random Raspberry Pi device and capturing kernel- and user-space event sequences via eBPF probes (bcc-tools, bpftool, bpftrace) during install-time and a fixed 120-second post-install window. From 62 candidate features, redundancy is pruned using Pearson correlation (|r|>0.50) and model-based importance scoring, yielding 36 features. Four ML models (Random Forest, Decision Tree, SVM, Gradient Boosting) and two DL models (CNN, Transformer) are trained under a 70/15/15 split with five-fold stratified cross-validation, with Random Forest on combined traces achieving 95.99% accuracy and 96.02% F1—outperforming metadata and static baselines by 11.5 and 0.8 percentage points respectively.

## Results

On the QUT-DV25 dataset, Random Forest with CombinedTraces achieves the best overall performance: 95.99% accuracy, 96.02% F1-score, 95.26% TPR, and 4.74% FNR. SVM achieves the highest TPR (96.36%) and lowest FNR (3.64%) among all models. Among deep learning models, CNN reaches 95.28% accuracy at epoch 72, while Transformer achieves 94.50%, both with substantially higher training times (5,155 s and 5,533 s) compared to ML models (0.5–47 s). The dataset also enabled identification of four previously undetected malicious PyPI packages (vermillion-0.5, eth-abcde-0.2.3, Pytonlib-0.0.0, infoind-3897) that were subsequently removed from the platform.

## Baselines & Comparisons

QUT-DV25 is compared against two baselines: the Metadata Dataset (Guo et al., ASE 2023) and the Static Dataset (DataDog Security Labs, 2023), both evaluated with the same four ML models on a common corpus. Against the Metadata baseline, QUT-DV25 with RF improves accuracy by 11.55 percentage points (95.99% vs. 84.44%) and F1 by 11.21 points (96.02% vs. 84.81%), while reducing FPR from 13.90% to 3.23% and FNR from 17.02% to 4.74%—a substantial gain driven by the metadata dataset's reliance on superficial package attributes. Against the Static baseline, QUT-DV25 with RF achieves a more modest but consistent improvement: +0.85 pp accuracy (95.99% vs. 95.14%), +0.78 pp F1 (96.02% vs. 95.24%), and a 1.89 pp reduction in FNR (4.74% vs. 6.63%), reflecting the static dataset's inability to capture install-time and post-install-time dynamic behaviors. Notably, the Static Dataset's SVM variant achieves a slightly higher TPR (96.01% vs. 95.26%) and lower FNR (3.99% vs. 4.74%) than QUT-DV25's RF, but at the cost of a higher FPR (5.35% vs. 3.23%), indicating more false alarms. Overall, QUT-DV25 dominates on the primary metrics (accuracy and F1) across all four models, confirming that dynamic eBPF traces provide complementary signal beyond what static or metadata features alone can capture.

## Relation to Prior Work

This paper departs from the established lineage of PyPI malicious package detection datasets (metadata-based like PyPI Malware Registry and Backstabber's Knife Collection, static-based like DataDog, and hybrid like PyPIGuard) by introducing the first dataset that captures install-time and post-install-time dynamic behavioral traces via eBPF kernel and user-space probes. While eBPF has been applied to security monitoring in other contexts (ransomware detection, system call anomaly identification), its use for software supply chain threat detection in package ecosystems is novel. The detection task itself (binary classification of malicious vs. benign packages) follows prior ML-based MDS work, but the feature space shifts from code/metadata attributes to real-time system call sequences, network flows, file access patterns, and behavioral sequences observed during actual package execution in a sandboxed environment.

## Why It Matters / Open Questions

The dataset fills a genuine gap: no prior benchmark captures the dynamic behaviors (multiphase payload execution, remote access activation, dynamic payload generation) that occur during and after package installation, which are precisely the vectors that evade static and metadata-based detection. The practical validation—identifying four previously undetected malicious packages with thousands of downloads—demonstrates real-world utility beyond benchmark numbers. Key limitations remain: the 120-second post-install observation window (validated on only 64 packages), Linux-only sandboxing that misses OS-specific attacks, and PyPI-specific scope that limits generalization to NPM, Maven, or RubyGems. Open questions include whether longer observation windows or cross-ecosystem adaptation would meaningfully improve detection of delayed or environment-triggered threats.
