## Problem

Gated Linear Units (GLUs) such as SwiGLU, which are standard in modern LLM feed-forward layers, require two separate full-rank weight matrices for the gate and value streams, doubling memory reads relative to a single linear projection. Since LLM inference is fundamentally memory-bandwidth-bound, this overhead directly inflates decode latency. The paper asks whether the multiplicative gate-value interaction can be recovered from a single shared weight matrix without sacrificing downstream accuracy.

## Input / Output

The MGLU layer consumes a hidden state vector x ∈ R^h and a set of n_m learned binary masks {M_i} ∈ {0,1}^{h×d} applied to a single shared weight matrix W ∈ R^{h×d}, producing a transformed intermediate vector that is subsequently projected back to the hidden dimension. During training, masks are stored as FP16 logits and binarized via the straight-through estimator; at inference they are fixed and packed into a single 8-bit integer per weight entry (up to 256 masks per byte), enabling a single coalesced memory load. The FlashMGLU kernel outputs 2·n_m intermediate vectors (gate and value for each mask route) in one fused pass, which are then combined with the Swish activation and element-wise multiplication.

## Method

The core architectural contribution is the Mixture of Element-wise Gating (MoEG) design: a single shared weight matrix W is partitioned into complementary subspaces by learnable binary masks M_i and their complements M̄_i = 1 − M_i, so the gate stream is x(M_i ⊙ W) and the value stream is x(M̄_i ⊙ W), with n_m such routes summed to form the final output. This replaces the two full-rank projections of SwiGLU with one matrix plus n_m binary masks, reducing inference-time memory load by up to 47% for n_m = 1 while retaining SwiGLU-level expressivity. The key kernel contribution, FlashMGLU, exploits the complementarity of M_i and M̄_i to compute both projections in a single pass over W: it packs all n_m mask bits into one 8-bit integer per weight entry, loads W and the packed mask in one coalesced HBM transaction, and performs all multiply-accumulate and mask-selection arithmetic entirely in on-chip registers, reducing global memory reads from n_m×2 to 1+1 per tile. This yields up to 19.66× speedup over a naive PyTorch MGLU and 1.15–1.51× speedup over standard GLU on an RTX 5090, with the advantage persisting at Llama-3.2 8B scale (h=4096, d=14336). Empirically, SwiMGLU with n_m=4 matches or exceeds SwiGLU on six downstream NLP benchmarks (ARC, HellaSwag, PiQA, SciQ, Winogrande) at both 159M and 1.08B parameter scales, while using 29.1% fewer projection FLOPs and 37.5% less inference memory.

## Results

On the large model (1.08B params), SwiMGLU with n_m=4 achieves 56.85% average zero-shot accuracy, surpassing SwiGLU's 56.00% while using only 808M weight parameters (vs. 1.08B). On the small model (159M), SwiMGLU n_m=4 reaches 46.48% average zero-shot accuracy vs. SwiGLU's 46.20% and GELU's 45.47%, with validation perplexity of 23.9 (vs. 23.7 for SwiGLU). The FlashMGLU CUDA kernel delivers up to 19.66× speedup over naive PyTorch MGLU and is 34% faster than standard GLU on an RTX 5090, while reducing per-token memory load by 47%.

## Baselines & Comparisons

Against SwiGLU (Shazeer, 2020), SwiMGLU with n_m=4 matches or exceeds accuracy on both model scales while using substantially fewer weight parameters: on the large model it achieves 56.85% vs. 56.00% average zero-shot accuracy (808M vs. 1.08B weights), and on the small model 46.48% vs. 46.20% (113M vs. 141M weights). Validation perplexity is nearly identical (12.4 vs. 12.3 large; 23.9 vs. 23.7 small). Against the GELU baseline (Hendrycks & Gimpel, 2016), SwiMGLU clearly wins on both perplexity and downstream accuracy at both scales. The key practical advantage is that SwiMGLU reduces per-token memory load by 47% (n_m=1) and the FlashMGLU kernel is 34% faster than standard GLU inference, making it attractive for latency-sensitive deployments. The trade-off is higher training cost (~2× wall-clock time) due to joint optimization of mask parameters.

## Relation to Prior Work

This paper extends the GLU family (Dauphin et al., 2017; Shazeer, 2020) by replacing the two separate projection matrices Wg and Wv with a single shared weight matrix W partitioned by complementary binary masks, drawing conceptual inspiration from Mixture of Experts (Jacobs et al., 1991) but applied at the element-wise level within one matrix. The FlashMGLU kernel follows the IO-aware fusion philosophy of FlashAttention (Dao et al., 2022), but targets the memory-bound matrix-vector products in FFN layers rather than attention. Unlike pruning methods that discard masked weights, MGLU repurposes the masked-out portions as the complementary value stream, so no capacity is wasted. The straight-through estimator (Bengio et al., 2013) is used to train the binary masks jointly with W.

## Why It Matters / Open Questions

The 47% reduction in per-token memory load and 34% latency improvement over standard SwiGLU are practically significant for memory-bound LLM inference, and the fact that a single weight matrix with learned masks can match or marginally exceed SwiGLU accuracy (e.g., 56.85% vs 56.00% average zero-shot on the 1.08B model) suggests a viable path to lighter FFN layers. However, the evidence is limited to two small model scales (159M and 1.08B) with no error bars, and the ~2× increase in training wall-clock time is a non-trivial cost. Open questions include whether the approach scales to 7B+ models, how it interacts with quantization or low-precision inference, and whether Hopper-specific kernel optimizations (cp.async, TMA) can close the remaining gap to a highly tuned GLU kernel.
