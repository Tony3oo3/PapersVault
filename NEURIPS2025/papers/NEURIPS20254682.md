## Problem

Conventional skeleton-based hand gesture recognition relies on hand-crafted features (joint collection distances, frame differences, reference-joint vectors) that lose spatio-temporal information, lack interpretability, and introduce topology-specific dependencies that limit generalization. Additionally, global normalization computed from training data creates domain gaps when test subjects or sensor viewpoints differ, and direct raw-coordinate inputs suffer from the 'geometric shortcut' phenomenon where models overfit to low-level spatial cues rather than semantic motion patterns.

## Input / Output

The method consumes raw 4D skeleton sequences (time, x, y, z) as a continuous stream, partitioned into fixed-length windows of N_F frames (typically 16), each represented as a tensor of shape N_F × j × c (frames × joints × coordinates). The output is a per-frame gesture class label produced by majority voting over a queue of window-level predictions, plus normalized start and end frame positions (in [0,1]) from regression heads that are used only during training to sharpen boundary awareness. The intermediate representation is a 2D graph image with three vertically stacked subplots (one per coordinate axis), where each of the j joints is drawn as a distinct colored line over the time axis.

## Method

SKETCH transforms each window of raw skeleton coordinates into a visual graph image by applying independent per-axis min-max normalization within the window, then plotting all j joint trajectories as colored lines in three stacked subplots (x, y, z), preserving inter-joint spatial relationships within each axis while aligning temporal flow horizontally. A novel Dynamic Range Embedding (DRE) module Z-normalizes each axis's values, compresses them through two FC+BN+ReLU layers into a single scalar per axis, and broadcasts that scalar additively onto the corresponding subplot to recover the relative movement scale lost during normalization. The resulting graph image is fed into a pretrained ViT or Swin Transformer backbone, which is fine-tuned with a combined cross-entropy classification loss and MSE regression loss on gesture start/end boundaries. This design is inherently topology-agnostic (no skeleton graph or reference joint required), mitigates the geometric shortcut by using the 2D plot as an intermediate medium that breaks direct coordinate-to-feature mapping, and the window-wise normalization eliminates dependence on training-set statistics, enabling robust generalization across unseen subjects and viewpoints.

## Results

On SHREC'22, SKETCH (Swin-Large + Augmentation) achieves a detection rate (DR) of 0.95, false positive (FP) rate of 0.06, and Jaccard index (JI) of 0.91, outperforming the previous state-of-the-art OO-dMVMT (DR 0.92, FP 0.09, JI 0.85). On SHREC'19, which involves a significant domain gap (entirely different test subjects), SKETCH reaches DR 0.93 and FP 0.01, surpassing OO-dMVMT (DR 0.88, FP 0.05) and all other baselines. The method operates at 70–256 FPS depending on backbone size, maintaining real-time capability.

## Baselines & Comparisons

SKETCH outperforms the previous SOTA OO-dMVMT [8] on both benchmarks: on SHREC'22, it improves DR from 0.92 to 0.95, reduces FP from 0.09 to 0.06, and raises JI from 0.85 to 0.91; on SHREC'19 (with a severe cross-subject domain gap), it improves DR from 0.88 to 0.93 and FP from 0.05 to 0.01. Against GCN-based methods that require explicit adjacency matrices (SeS-GCN, DG-STA, BlockGCN, MS-G3D), SKETCH is topology-agnostic and still achieves substantially higher DR (e.g., 0.95 vs. 0.60 for SeS-GCN on SHREC'22). Compared to hand-crafted feature methods like DDNet (JCD+FD, DR 0.88) and ProtoGCN (Adj+Ref, DR 0.86 on SHREC'19), SKETCH uses raw coordinates directly and gains 4–7 points in DR. The ablation in Table 7 confirms that plotting raw coordinates (SKETCH) outperforms plotting the same hand-crafted features (JCD: DR 0.80, FD: DR 0.87) under an identical pipeline, indicating the advantage stems from preserving full spatio-temporal information rather than the visualization technique alone. All SKETCH variants maintain 8-frame delay matching the fastest baselines, while the Swin-Small configuration reaches 256 FPS for latency-sensitive deployment.

## Relation to Prior Work

SKETCH directly builds on ViTST [22], which converts time-series data into line-graph images for a pretrained vision transformer, but departs from it in three key ways: (1) joints sharing the same coordinate axis are co-located in a single subplot rather than isolated into per-feature line graphs, preserving inter-joint spatial relationships; (2) a novel Dynamic Range Embedding (DRE) encodes axis-wise movement variability lost during normalization; and (3) window-based axis-wise min-max normalization replaces ViTST's fixed per-feature scheme. More broadly, the paper positions itself against the dominant paradigm in skeleton-based gesture recognition that relies on hand-crafted features (joint collection distances, frame differences, adjacency matrices, reference-joint vectors) and topology-dependent architectures (GCNs, ST-Transformers), arguing that these discard information and introduce fragile dataset-specific dependencies.

## Why It Matters / Open Questions

The topology-agnostic design is practically significant: it removes the need for dataset-specific skeleton definitions or reference-joint selection, enabling straightforward transfer across sensors and joint conventions. The interpretability gained from visual graph representations (validated via Grad-CAM showing human-like joint attention) offers a new diagnostic tool for skeleton-based recognition that hand-crafted feature pipelines cannot provide. Key limitations include the independent per-window processing that ignores cross-window temporal context, and evaluation restricted to two hand-gesture benchmarks; the authors note potential extension to full-body action recognition and adaptive windowing as future directions. Whether the image-plotting trick generalizes beyond the relatively low-dimensional skeleton modality (26 joints × 3 coords) to higher-dimensional or noisier inputs remains an open question.
