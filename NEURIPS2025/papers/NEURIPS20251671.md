## Problem

Existing AI and agentic tools for cloud reliability engineering assist human engineers with detection, summarization, and root-cause prediction, but do not autonomously mitigate failures in live production systems. The fundamental barrier to deploying autonomous agentic mitigation is safety: an agent's state-changing actions could worsen an already degraded system, and there is no formal guarantee that the system will not regress. This paper addresses both the architectural gap (end-to-end autonomous SRE) and the safety gap (a formal specification ensuring agents cannot make things worse).

## Input / Output

STRATUS consumes telemetry data (logs, distributed traces, performance metrics) and Kubernetes state objects, but rather than feeding raw data to agents, it uses LLMs to summarize observability data into interpretable signals. The system models cloud health via a severity metric μ(s) = w₁·|A| + w₂·|V| + w₃·|L| (weighted alerts, SLA violations, and unhealthy nodes), which drives all commit/abort decisions. Outputs are concrete kubectl commands generated through an NL2Kubectl tool, executed under sandboxed confinement rules that block destructive, interactive, and compound shell operations. Termination is determined by a composite oracle combining alert clearance, user-request success (no 4XX/5XX), and component health checks.

## Method

STRATUS orchestrates four specialized LLM agents (Detection, Diagnosis, Mitigation, Undo) via a deterministic state machine rather than open-ended multi-agent conversation, with the Mitigation agent (α_M) and Undo agent (α_U) as the only writers. The core safety contribution is Transactional Non-Regression (TNR), which wraps each mitigation plan in transaction semantics: checkpoint the pre-state, execute a bounded sequence of commands (K≤20), then commit only if the post-state severity μ(s_post) ≤ μ(s_pre), otherwise abort and invoke a faithful undo operator that restores the checkpointed state exactly. This is realized through three mechanisms: a readers-writer lock (A-Lock) for writer exclusivity, sandboxed confinement with command-level linting and dry-run validation, and a stack-based rollback mechanism that tracks each action's effect on specific Kubernetes state objects for fine-grained undo. TNR's key practical effect is enabling safe undo-and-retry: the ablation shows that without rollback, failed mitigations leave the system in progressively worse states, whereas TNR allows the agent to iteratively explore alternative mitigation paths from the original error state, which is critical for solving complex problems (80%+ of solved problems required at least one retry).

## Results

On AIOpsLab (13 mitigation problems), STRATUS with GPT-4o achieves a 69.2% success rate, outperforming the best baseline (AOL-agent at 46.2%) by 1.5×. On ITBench (18 mitigation problems), STRATUS (GPT-4o) reaches 50.0% success rate versus 9.2% for ITB-agent, a 5.4× improvement. The advantage is consistent across model backends: STRATUS with Llama 3.3 achieves 23.1% on AIOpsLab and 28.0% on ITBench, still exceeding all baselines. STRATUS trades speed for safety—it takes ~812s (AIOpsLab) and ~1721s (ITBench) per problem due to TNR-enabled retry, versus ~223s for AOL-agent.

## Baselines & Comparisons

STRATUS (GPT-4o) outperforms all four baselines on both benchmarks. On AIOpsLab, it beats AOL-agent (46.2%) by 23 percentage points (1.5×), Flash (38.5%) by 30.7 points, and ReAct (23.1%) by 46.1 points. On ITBench, the margin is even larger: STRATUS (50.0%) surpasses ITB-agent (9.2%) by 5.4× and ITB-agent with Llama (5.7%) by 8.8×. The advantage holds across model backends—STRATUS with Llama 3.3 (23.1% AIOpsLab, 28.0% ITBench) still exceeds AOL-agent with Llama (15.4%) and ITB-agent with Llama (5.7%). The paper attributes the gap primarily to TNR-enabled undo-and-retry: ablation shows that removing retry drops STRATUS to 15.4% (AIOpsLab) and 11.1% (ITBench), while naive retry without undo only reaches 23.1% and 50.0% respectively, confirming that safe rollback to the pre-failure state is critical for iterative exploration.

## Relation to Prior Work

STRATUS departs from the dominant line of AI-for-SRE work (e.g., RCAgent, Flash, AutoTSG) that builds tools to assist human engineers with detection, diagnosis, and root-cause prediction, by targeting full autonomous mitigation as its primary goal. Its safety specification, Transactional Non-Regression (TNR), is formalized atop the classic transaction abstraction of Haerder and Reuter [28], adapting checkpoint-execute-commit/abort semantics to the agentic SRE setting. For orchestration, STRATUS adopts the Agent-Computer Interface (ACI) paradigm from SWE-agent [77] and the CrewAI multi-agent framework, but deliberately replaces the conversational/debate patterns common in LLM multi-agent systems with a deterministic state machine, motivated by safety reasoning and timeliness requirements.

## Why It Matters / Open Questions

TNR provides the first formal, provable safety guarantee for autonomous SRE agents—severity never increases in the externally visible state trace—which is a prerequisite for deploying LLM-driven agents on live production clouds. The ablation showing that naive retry without undo is nearly useless (23.1% vs. 69.2% success) validates that safe rollback is not merely a nice-to-have but the enabling mechanism for iterative exploration. Key open questions include: extending TNR to concurrent writers (sketched but not implemented), achieving faithful undo for application-specific and external-interaction state changes, and validating the approach on real production workloads rather than emulated benchmarks where injected faults may not persist across pod restarts.
