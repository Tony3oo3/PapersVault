## Problem

Existing system-level defenses for LLM agents face two unresolved challenges: static security policies (e.g., CaMeL) enforce rigid control/data dependency graphs that severely sacrifice task utility, especially on complex multi-step tasks, and injected content persists in the agent's memory stream, posing compounding long-term risks to both the agent and auxiliary security modules. No prior framework simultaneously supports dynamic policy updating and memory-stream isolation of covertly injected instructions.
![Teaser figure](../imgs/NEURIPS20252791/cropped_page2_idx0.webp)

## Input / Output

The framework consumes three streams in a sequential pipeline: (1) the original user query, processed once before any environment interaction to generate the initial policy; (2) each proposed tool call (function name plus parameter dictionary), checked against the current trajectory and parameter checklist; and (3) each tool response, scanned for conflicting instructions before being appended to the agent's memory. Outputs include a binary approve/reject decision per tool call, a masked (cleaned) version of the tool response for memory storage, and an updated minimal function trajectory with JSON-schema parameter checklists that evolve as approved deviations are incorporated.

## Method

DRIFT enforces security through three cooperating LLM-based modules. The Secure Planner, operating before any interaction, decomposes the user query into a minimal function trajectory (control constraint) and per-node JSON-schema parameter checklists specifying required fields and value dependencies (data constraint). The Dynamic Validator intercepts each proposed tool call; if it deviates from the planned trajectory, the validator classifies the function's privilege as Read, Write, or Execute (inspired by OS privilege levels), auto-approving Read operations and requiring intent-alignment verification for Write/Execute operations, with approved deviations dynamically updating the trajectory. The Injection Isolator, applied to every tool response before it enters memory, uses an LLM to detect and mask instructions that conflict with the user's original query, preventing long-term accumulation of malicious content. The entire policy is trainable: the authors construct 1,000 planner and 1,000 isolator samples from ToolBench conversations (rewritten with GPT-4o-mini) and fine-tune Qwen2.5-7B-Instruct via LoRA, reducing ASR from 15.1% to 0.0% while improving utility.

## Results

On AgentDojo with GPT-4o-mini, DRIFT reduces the Attack Success Rate (ASR) from 30.7% (undefended) to 1.3%, while maintaining 47.9% benign utility and 47.9% utility under attack. On the ASB benchmark, DRIFT achieves an ASR of 4.8%, substantially outperforming the runner-up Progent (15.8% ASR). In terms of efficiency (Utility − ASR / Total Tokens), DRIFT scores 19.7, second only to tool_filter (86.6) but with far stronger security (1.3% vs. 7.6% ASR).

## Baselines & Comparisons

DRIFT outperforms all model-level and lightweight system-level defenses (repeat_user_prompt, spotlighting_with_delimiting, tool_filter, transformers_pi_detector, delimiters_defense, ob_sandwich_defense, instructional_prevention) on both security and utility, reducing ASR to 1.3% versus 7.6–41.8% for those baselines. Against the static-policy defense CaMeL, DRIFT trades a marginal 1.3% ASR gap (CaMeL achieves 0.0%) for a large utility gain of ~21.8% (no attack) and ~10.9% (under attack), while also consuming roughly 2.6× fewer tokens (2.37M vs. 6.09M). Against the dynamic-policy defense Progent, DRIFT wins on both metrics: 1.3% vs. 9.4% ASR on AgentDojo and 4.8% vs. 15.8% ASR on ASB, with comparable or higher utility. The paper further shows that DRIFT's advantage over Progent widens with weaker base models (e.g., GPT-4o-mini: 1.64% vs. 9.39% ASR), suggesting DRIFT's simpler sub-task decomposition generalizes better across model capabilities.

## Relation to Prior Work

DRIFT positions itself within the system-level defense lineage for LLM agents, explicitly departing from CaMeL's static control-and-data dependency graph by introducing dynamic policy updates, and from Progent's open-ended policy rewriting by decomposing the validation step into simpler subtasks (privilege classification + intent alignment). It also addresses a gap left by IsolateGPT and CaMeL: residual injection content persisting in the agent's memory stream during prolonged interactions, which neither prior work handles. The framework repurposes OS privilege concepts (Read/Write/Execute) for LLM tool-call governance and introduces a JSON-schema-style parameter checklist as a data-level constraint, a mechanism not present in prior rule-based defenses.

## Why It Matters / Open Questions

DRIFT provides a practical, deployable defense that achieves near-zero ASR (1.3%) while preserving utility, addressing two gaps that prior system-level defenses left open: dynamic policy adaptation and memory-stream isolation. The trajectory-length scaling analysis (static policies collapse at length ≥ 3 while dynamic policies remain stable) offers a concrete empirical argument for why static designs are insufficient in real-world agentic systems. Key limitations include evaluation restricted to simulated benchmarks (AgentDojo, ASB) with limited domain coverage, the added token overhead (~1.9× the undefended agent), and the reliance on LLM-based judgment for privilege classification and intent alignment, which introduces its own failure modes. Open questions include whether the framework generalizes to truly open-ended, multi-session real-world deployments and whether the trainable policy mechanism scales beyond the 7B parameter regime.
