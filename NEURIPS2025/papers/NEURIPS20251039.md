## Problem

Bitcoin's UTxO-based design and pseudonymity make its >1.08B transactions largely inaccessible for machine learning: there is no explicit entity-level state (balances, counterparties, transaction counts) because funds are atomic outputs locked by cryptographic scripts, and single entities control many addresses. No prior work has reconstructed the complete flow of funds into a single, ML-ready graph representation that preserves temporal ordering, distinguishes value creation from circulation, and supports large-scale graph ML workflows.

## Input / Output

The pipeline ingests raw Bitcoin blockchain blocks (up to height 863000) via Bitcoin Core's REST API, extracting transaction inputs/outputs, scripts, and block metadata while omitting cryptographic signatures and zero-value transactions. The output is a directed temporal heterogeneous graph with >2.4B nodes (Coinbase, Script, Tx, Block) and >39.72B block-height-annotated edges (Mints, Transfers, Fee, Redeems, Confirms, Credits), serialized as >1.17 TB of TSV files, a >700 GB Neo4j database snapshot, and 200k pre-sampled subgraph communities (<1.5 GB) with node/edge feature vectors ready for GNN input.

## Method

The core contribution is transforming Bitcoin's TxOut-centric ledger into a script-centric (wallet-level) temporal heterogeneous graph. Within each transaction, input and output scripts are connected via a complete bipartite graph of Transfers edges whose values are proportional to the fraction of total input each source contributes and the share allocated to each destination, explicitly modeling fund flow between potentially unrelated scripts. Minted coins and transaction fees are separated into distinct edge types (Mints from a single Coinbase node; Fee edges from spender scripts to miner scripts), preserving the distinction between value creation and circulation. Block nodes serve as temporal hypernodes, connected via Redeems/Credits/Confirms edges to enable traversal along the block sequence and to provide structural anchors for GNNs to learn long-range temporal dependencies. For sampling, the authors adapt the Forest Fire algorithm with a decay factor to generate representative multi-hop neighborhood subgraphs, addressing the limitation that standard BFS/DFS fail to capture breadth at deeper hops in high-degree regions of the graph.

## Results

The constructed temporal heterogeneous graph encodes Bitcoin's complete transaction history up to block 863000 (>16 years), comprising >2.4B nodes across four types (Coinbase, Script, Tx, Block) and >39.72B directed edges across six types (Mints, Transfers, Fee, Redeems, Confirms, Credits). Key structural statistics include >1.3B Script nodes (97.49% with in-degree ≤10, but a long tail reaching max in-degree ≈282M), >1.08B Tx nodes, and 863,000 Block nodes. The compressed TSV files exceed 1.17 TB, expanding to >3 TB when loaded into a Neo4j graph database, with 200k pre-sampled subgraph communities (<1.5 GB) provided for lightweight exploration.

## Baselines & Comparisons

This paper is a dataset and graph-construction contribution rather than a method paper, so it does not compare its approach against competing baselines or report model performance metrics. The sole methodological comparison is the choice of modeling scripts by their derived addresses (unifying input and output scripts with the same address into a single node) versus using unique per-transaction input/output identifiers; the authors argue the former is more informative for graph-based ML by preserving wallet-level fund flow patterns (illustrated in Fig. A.4). The sampling methodology is positioned as an adaptation of the Forest Fire algorithm [Leskovec & Faloutsos, KDD 2006], motivated by the observation that standard BFS or DFS fail to produce representative multi-hop neighborhoods in high-degree regions of the Bitcoin graph. No head-to-head quantitative comparison against alternative graph representations or sampling strategies is provided.

## Relation to Prior Work

This paper departs from prior Bitcoin analysis work (e.g., de-anonymization and address clustering [2–4, 11, 12]) that typically operates at the transaction or address level, by transforming the UTxO-centric blockchain into a wallet-centric temporal heterogeneous graph with explicit script-to-script fund flow edges. The sampling methodology adapts the Forest Fire algorithm [7] (Leskovec & Faloutsos, KDD 2006) to handle the graph's heterogeneity and temporal structure, while the ETL pipeline relies on Bitcoin Core as the reference implementation for faithful parsing across 16 years of protocol evolution. Conceptually, the paper bridges the gap identified in the ML-on-blockchain survey [1] between the rich economic data in Bitcoin's ledger and its inaccessibility to standard ML pipelines due to the absence of explicit entity-level state in the UTxO model.

## Why It Matters / Open Questions

This is the first comprehensive, ML-ready graph encoding of Bitcoin's entire transaction history (>2.4B nodes, >39.72B edges), enabling applications—large-scale graph ML benchmarking, anomaly detection, entity classification, and temporal pattern learning—that were previously infeasible due to the computational cost of reconstructing entity state from raw UTxO data. Key open questions remain: entity resolution (mapping scripts to real-world entities) is still confounded by privacy techniques like CoinJoin and exchange proxying; the graph lacks off-chain annotations (entity type, transaction intent, illicit activity labels) that would substantially improve classification tasks; and the temporal drift across 16 years of evolving network characteristics poses challenges for model generalization. The dataset's scale (>1.17 TB compressed TSV, >3 TB in Neo4j) also raises practical accessibility questions, though the authors mitigate this with pre-sampled communities and on-disk processing methods.
