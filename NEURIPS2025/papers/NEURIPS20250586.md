## Problem

Generalized Additive Models (GAMs) are widely regarded as interpretable, leading to the natural assumption that generating explanations for them should be computationally efficient. However, no prior work had systematically characterized the computational complexity of producing different explanation types (sufficient reasons, contrastive explanations, Shapley values, feature redundancy) across different GAM component models and input domain settings. This paper challenges the blanket interpretability assumption by revealing a surprisingly diverse landscape where explanations range from polynomial-time computable to provably NP-hard or #P-hard, depending on the specific configuration.

## Input / Output

The analysis takes as input a GAM model f with a specified component type (cubic splines, ReLU neural networks, or boosted tree ensembles), an input instance x over one of three domain settings (enumerable discrete with constant-size value sets, general discrete with binary-encoded ranges, or continuous real-valued), and an explanation query type. The output is a complexity classification for each configuration—ranging from PTIME, pseudo-polynomial time, NP-complete, coNP-complete, to #P-complete—rather than a single computed explanation. A notable structural detail is that the classification task introduces a step function over the additive prediction, which creates a complexity separation between regression and classification that is unique to the SHAP query.

## Method

The paper performs an exhaustive complexity analysis across all combinations of three dimensions: component model type (Smooth GAMs with cubic splines, NAMs with ReLU networks, EBMs with boosted trees), explanation type (CSR, MSR, MCR, FR, CC, SHAP for regression and classification), and input domain (enumerable discrete, general discrete, continuous). Tractability results rely on greedy algorithms that rank features by their min/max component contribution (for sufficient/contrastive reasons), analytic computation of spline extrema, and the linearity axiom of Shapley values to reduce regression SHAP to per-component expectation computation. Intractability results are established via reductions from model counting (#P-hardness for SHAP-C and CC), SAT/coSAT (coNP-hardness for CSR and FR), and set cover (NP-hardness for MCR), with novel constructions that handle the single-input-output constraint of additive components. The key structural insight is that the additive decomposition makes complexity highly sensitive to the input domain in ways that non-additive models (neural networks, tree ensembles) do not exhibit, and that the component model's expressivity only affects complexity in discrete and continuous settings, not in enumerable discrete ones.

## Results

The paper establishes a comprehensive complexity landscape for generating explanations for GAMs across all combinations of component type, input domain, and explanation type. The headline finding is that under enumerable discrete inputs, all explanation queries (CSR, MSR, MCR, SHAP-R) are solvable in PTIME regardless of component model, while under general discrete or continuous inputs, the same queries become coNP-Hard (CSR/MSR) or #P-Complete (SHAP-R, CC, SHAP-C) for NAMs and EBMs. A notable exception is Feature Redundancy (FR), which is PTIME for Smooth GAMs in the continuous setting but coNP-Complete in discrete settings. All tractable algorithms are linear in the size of the GAM.

## Baselines & Comparisons

The paper does not compare against external empirical baselines, as it is a purely theoretical work. Instead, it establishes strict complexity separations (c-interpretable gaps) between different model configurations. Smooth GAMs (spline components) are strictly more c-interpretable than NAMs and EBMs under discrete and continuous inputs for CSR, MSR, MCR, and SHAP-R, but this gap vanishes under enumerable discrete inputs where all component types achieve PTIME. For the additive vs. non-additive comparison (Table 2), NAMs and EBMs over enumerable discrete inputs are strictly more c-interpretable than neural networks and tree ensembles for CSR, MSR, MCR, and SHAP-R, but under discrete/continuous inputs the gap narrows to only the MSR query. A unique separation appears for SHAP: regression GAMs are PTIME while classification GAMs are #P-Complete, a distinction not observed for other explanation types.

## Relation to Prior Work

This paper extends the computational complexity framework for model explanations established by Barceló et al. (NeurIPS 2020) and Bassan et al. (ICML 2024) from individual model classes (linear models, decision trees, neural networks, tree ensembles) to the full GAM family, systematically analyzing all combinations of component model type (splines, neural networks, boosted trees), explanation type (sufficient reasons, contrastive explanations, SHAP, feature redundancy), and input domain (enumerable discrete, general discrete, continuous). It departs from prior work by revealing that the input domain is a complexity-determining factor unique to additive models—a dimension that does not produce complexity gaps for non-additive models like neural networks or tree ensembles. The paper also positions its results against prior complexity analyses of neural networks and tree ensembles to show how additive structure can (but not always does) reduce explanation hardness.

## Why It Matters / Open Questions

This work challenges the widespread assumption in the XAI community that 'interpretable' model architectures (GAMs) are automatically easy to explain, revealing a landscape where even GAMs can be #P-hard or coNP-hard to explain depending on the setting. The practical takeaway is that input discretization and coefficient quantization—both standard steps in GAM pipelines—can transform intractable explanation problems into polynomial-time ones, offering concrete design guidance. Open questions include how high-order feature interactions and concurvity affect complexity, whether approximation or PAC-based relaxations can circumvent intractability, and whether the input-domain sensitivity extends to other additive model families beyond GAMs.
