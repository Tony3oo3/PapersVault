## Problem

Existing LLM caching techniques—context caching (KV reuse) and semantic caching (input-output pair reuse)—are designed for query-level chatbot serving and fail for Plan-Act agent applications where outputs depend on external data and dynamic environments. The same high-level query (e.g., 'compute working capital ratio') yields similar plan structures but different specifics depending on the dataset or environment, making direct output reuse inapplicable. This paper identifies three concrete limitations (model-specific KV constraints, data-dependent outputs, and limited adaptability) and asks whether task-level plan reuse can reduce agent serving costs without sacrificing accuracy.

## Input / Output

The system consumes a natural-language task query plus external context (e.g., a company's financial statements, a data table, or a web/GUI environment) and produces a final task response. Internally, a lightweight LM first distills the query into a single intent keyword (e.g., 'working capital ratio'), which is used for exact-match cache lookup. On a cache hit, a small planner LM (Llama-3.1-8B) adapts the stored plan template into a task-specific plan; on a miss, a large planner LM (GPT-4o) generates the plan from scratch, and upon successful completion a two-step extraction pipeline (rule-based filter followed by a lightweight LLM filter) produces a generalized, context-free plan template stored alongside the keyword for future reuse.

## Method

Agentic Plan Caching (APC) is a test-time memory that extracts, stores, adapts, and reuses structured plan templates from completed agent executions across semantically similar tasks. The key insight is that the Plan stage—responsible for the majority of LLM compute cost—repeats across workflows with only context-specific details (entity names, numeric values, coordinates) changing, so the plan skeleton can be cached and re-instantiated cheaply. Rather than embedding-based query similarity (which overemphasizes surface details and yields high false-positive/negative rates), APC uses keyword extraction to capture higher-level intent and performs exact dictionary lookups for O(1) cache retrieval. On a hit, a small planner LM adapts the template to the current context; on a miss, the large planner LM runs the full Plan-Act loop, and the resulting execution log is filtered into a reusable template via rule-based extraction of critical steps followed by a lightweight LLM pass that strips context-specific elements. This design avoids the long-context processing failures of full-history caching and the accuracy degradation of semantic caching, achieving 50.31% average cost reduction and 27.28% latency reduction while retaining 96.61% of optimal accuracy across five benchmarks and two agent architectures.

## Results

Across five agent workloads (FinanceBench, QASPER, TabMWP, AIME 2024/2025, GAIA), Agentic Plan Caching (APC) reduces serving cost by 50.31% and latency by 27.28% on average while maintaining 96.61% of the accuracy-optimal baseline's application-level performance. On GAIA with the Open Deep Research agent, APC achieves a 76.42% cost reduction (from $69.02 to $16.27) with only a 0.61% accuracy drop. The additional overhead from keyword extraction and cache generation accounts for only 1.04% of total serving cost on average.

## Baselines & Comparisons

APC outperforms semantic caching (GPTCache-style) on accuracy across all thresholds tested: semantic caching suffers from high false-positive cache hits that cause substantial performance degradation, while APC maintains consistent accuracy regardless of cache-hit status (Figure 5). Against full-history caching, APC achieves higher accuracy (85.50% vs. 72.00% on FinanceBench) at lower cost ($1.86 vs. $1.99), because the small planner LM struggles to process lengthy unfiltered execution logs. Compared to the cost-optimal baseline (always using the small planner), APC achieves 10–13 percentage points higher accuracy at only 2–4× the cost, while the accuracy-optimal baseline costs 2–4× more than APC. On GAIA specifically, APC reduces cost by 76.42% relative to the accuracy-optimal baseline while preserving 98.4% of its accuracy, demonstrating strong cost-efficiency even in heterogeneous, open-domain agent settings.

## Relation to Prior Work

This paper departs from the dominant line of LLM caching work (context/KV-cache reuse and semantic caching) by arguing those techniques are fundamentally misaligned with Plan-Act agent architectures, where outputs depend on external data and dynamic environments rather than solely on the input prompt. It draws conceptual inspiration from Case-Based Planning (storing and adapting prior solutions) and from the Minions cloud-edge collaboration framework, but repurposes both for a new goal: extracting reusable, context-agnostic plan templates from completed agent executions at test time. Unlike prior agent-memory work that targets accuracy improvements (fewer hallucinations, higher task success), APC explicitly targets serving cost and latency reduction, a largely unexplored objective in the agent-memory literature.

## Why It Matters / Open Questions

A 50% average cost reduction with only ~3.4% accuracy loss is practically significant for organizations scaling agentic AI workloads, where planning-stage LLM calls dominate token spend. The paper's key open questions include whether the approach extends to multi-agent systems with inter-component cache consistency, how it behaves under highly dynamic workloads where task variation limits cache hit rates, and how to protect privacy when plan templates encode proprietary business logic. The cold-start problem and the reliance on exact keyword matching (rather than fuzzy retrieval) are acknowledged limitations that will matter in production deployments with diverse, long-tail query distributions.
