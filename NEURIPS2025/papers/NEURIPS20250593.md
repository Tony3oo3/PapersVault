## Problem

Existing memory systems for LLM agents rely on predefined storage structures, fixed retrieval patterns, and static schemas (including graph databases with preset relationships), which fundamentally limits their adaptability across diverse tasks and long-term interactions. When an agent encounters novel knowledge, these rigid systems cannot forge new organizational patterns or dynamically restructure existing memories, severely restricting generalization to open-ended, evolving environments.
![Teaser figure](../imgs/NEURIPS20250593/cropped_page1_idx1.webp)

## Input / Output

The system consumes raw conversation interaction text (speaker utterances with timestamps) and, at query time, a free-text query string. For each interaction, an LLM generates a structured note containing keywords, categorical tags, a one-sentence contextual description, and a dense embedding vector (via all-minilm-l6-v2) computed over the concatenation of all textual components. At retrieval, the system returns top-k memory notes by cosine similarity, and linked memories within the same 'box' are automatically co-accessed, enriching the agent's prompt with interconnected historical context rather than isolated fragments.

## Method

A-MEM implements a Zettelkasten-inspired agentic memory architecture with three core operations: (1) Note Construction, where an LLM autonomously generates keywords, tags, and a rich contextual description for each new memory, producing multi-faceted representations beyond raw content; (2) Link Generation, where the new memory's embedding retrieves top-k nearest neighbors, and an LLM then determines semantically meaningful connections based on shared attributes and contextual overlap, building an organic link network without predefined schemas; (3) Memory Evolution, where the integration of a new memory triggers LLM-driven updates to the contextual descriptions, keywords, and tags of existing neighboring memories, allowing the knowledge network to continuously refine and develop higher-order patterns over time. The key distinction from agentic RAG is that agency operates at the storage and evolution level—memories actively restructure themselves—rather than merely at the retrieval level. Retrieval uses standard cosine-similarity top-k search over the evolving embedding space, with linked memories providing additional contextual reach.

## Results

On the LoCoMo dataset, A-MEM achieves an average ranking of 1.0–1.6 across six foundation models, compared to 2.0–5.0 for all baselines. With GPT-4o-mini, A-MEM scores 45.85 F1 on Temporal reasoning (vs. 18.41 for LoCoMo and 25.52 for MemGPT) and 27.02 F1 on Multi-Hop (vs. 25.02 and 26.65), while using only 2,520 tokens per query versus ~16,900 for LoCoMo/MemGPT (an 85% reduction). On the DialSim dataset, A-MEM achieves 3.45 F1, a 35% improvement over LoCoMo (2.55) and 192% higher than MemGPT (1.18). Across all non-GPT models (Qwen2.5, Llama 3.2), A-MEM outperforms every baseline in every category.

## Baselines & Comparisons

A-MEM is compared against four baselines: LoCoMo (full-context prompting), ReadAgent (gist-memory reading), MemoryBank (Ebbinghaus-curve memory), and MemGPT (OS-inspired virtual context). On non-GPT models (Qwen2.5-3b, Llama 3.2-3b), A-MEM dominates all baselines in every category, with the largest margins on Temporal reasoning (e.g., 24.32 vs. 4.25 F1 for LoCoMo on Llama 3.2-3b) and Multi-Hop (18.23 vs. 9.05). On GPT-4o-mini, A-MEM wins on Multi-Hop (27.02 vs. 25.02 LoCoMo, 26.65 MemGPT) and Temporal (45.85 vs. 18.41, 25.52) but trails LoCoMo on Adversial (50.03 vs. 69.23), where the full-context approach benefits from the model's strong pre-trained knowledge. ReadAgent and MemoryBank are consistently the weakest, scoring below 15 F1 in most categories. A critical practical advantage is token efficiency: A-MEM requires only 1,200–2,520 tokens per query versus ~16,900 for LoCoMo and MemGPT, an 85–93% reduction that directly lowers API costs.

## Relation to Prior Work

This paper departs from the dominant paradigm of fixed-structure memory systems for LLM agents (MemGPT, MemoryBank, ReadAgent) by making the memory organization process itself agentic rather than pre-specified. It repurposes the Zettelkasten knowledge-management method—atomic notes with flexible linking—as an architectural principle, combining it with embedding-based retrieval and LLM-driven decision making for note construction, link generation, and memory evolution. The authors explicitly distinguish their approach from agentic RAG systems, arguing that agency at the storage and evolution level (memories autonomously generating descriptions, forming connections, and updating each other) is more fundamental than agency at the retrieval level alone.

## Why It Matters / Open Questions

The memory evolution mechanism—where integrating a new memory triggers updates to the contextual representations of existing memories—offers a path toward memory systems that grow richer over time rather than merely accumulating entries, addressing a core limitation of current agent memory. The 85–93% token reduction while simultaneously improving multi-hop reasoning performance makes the approach practically attractive for deployment. However, the evaluation is limited to QA-style benchmarks (LoCoMo, DialSim) rather than truly open-ended agent tasks, the quality of memory organization is bounded by the underlying LLM's capabilities, and the absence of error bars or multiple runs limits confidence in the reported margins. Open questions include whether the approach extends to multimodal memories and whether the evolution mechanism remains stable over very long interaction horizons.
