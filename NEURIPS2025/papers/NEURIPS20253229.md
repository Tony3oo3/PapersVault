## Problem

Existing efficiency efforts in language models target either parameter sharing (layer tying) or adaptive computation (early exiting), but no architecture effectively unifies both within a single framework. Recursive Transformers provide built-in weight sharing but apply a fixed recursion depth to every token, failing to allocate compute adaptively based on token difficulty. This paper asks how to simultaneously achieve parameter efficiency, token-level adaptive thinking depth, and memory-efficient KV caching in one architecture.

## Input / Output

The model consumes subword token sequences (max 2K context, 49K vocabulary) and produces next-token predictions via autoregressive generation. Unusually, each token traverses a variable number of shared recursion blocks (1 to N_r) determined by a learned router, so the effective 'depth' of computation differs per token within the same sequence. During inference, only KV pairs of tokens still active at a given recursion depth are cached and attended to, making the KV cache size dynamic rather than fixed at sequence length.

## Method

MoR partitions a Llama-based Transformer into N_r shared recursion blocks (using Middle-Cycle parameter sharing, which retains unique first and last layers) and inserts a lightweight router before each block. In expert-choice routing, each recursion step acts as an expert that selects its top-k tokens via a linear score with sigmoid activation and an auxiliary binary cross-entropy loss to resolve causality violations; hierarchical filtering ensures only previously selected tokens are re-evaluated at deeper steps. In token-choice routing, a single softmax decision at the outset assigns each token a fixed recursion depth. For KV management, recursion-wise caching stores key-value pairs only for tokens active at each depth (reducing cache size to ~(N_r+1)/2N_r of vanilla), while a recursive sharing variant reuses first-recursion KV pairs across all depths for maximal memory savings. The architecture is trained end-to-end from scratch on FineWeb-Edu, and at inference leverages continuous depth-wise batching to eliminate idle GPU bubbles from early-exited tokens.

## Results

Under an equal training budget of 16.5e18 FLOPs, MoR with expert-choice routing and Nr=2 (167M params) achieves a validation NLL of 2.7511 and 43.1% average few-shot accuracy, outperforming the 315M Vanilla Transformer (NLL 2.7824, 42.3%) with roughly 50% fewer parameters. Under a fixed 20B-token budget, the same MoR model reaches NLL 2.7749 and 42.9% average accuracy while consuming only 12.3e18 FLOPs (25% less than Vanilla's 16.5e18). Across model scales from 135M to 1.7B parameters, MoR consistently outperforms fixed-depth recursive baselines and matches or exceeds Vanilla Transformers at ≥360M scale.

## Baselines & Comparisons

Against the Vanilla Llama-3-based Transformer (315M params), MoR with Nr=2 (167M params) wins on both NLL (2.7511 vs. 2.7824) and average few-shot accuracy (43.1% vs. 42.3%) under equal 16.5e18 FLOPs, while using ~47% fewer parameters. Under a fixed 20B-token budget, MoR Nr=2 again beats Vanilla on NLL (2.7749 vs. 2.7824) and accuracy (42.9% vs. 42.3%) while consuming 25% fewer training FLOPs (12.3e18 vs. 16.5e18). Against fixed-depth Recursive Transformers, MoR consistently outperforms at every recursion depth: at Nr=3, MoR achieves NLL 2.7925 and 42.6% average accuracy versus the Recursive baseline's 2.8466 and 41.5%; at Nr=4, MoR reaches 2.8204 and 41.6% versus 2.8781 and 41.0%. The gap is largest at Nr=2, where MoR's adaptive routing allows it to process 27B tokens within the same FLOPs budget versus only 20B for the fixed-depth Recursive model, directly translating into lower perplexity and higher downstream accuracy.

## Relation to Prior Work

MoR unifies two previously separate efficiency axes in recursive Transformers: parameter sharing via layer tying (from Recursive Transformers and Relaxed Recursive Transformers [6]) and adaptive token-level compute allocation (from Mixture-of-Depths [79] and early-exiting methods). The key departure is applying MoD-style top-k routing to a shared parameter block rather than to distinct layers, so that the 'experts' are recursion depths of the same weights, and introducing two novel KV caching strategies (recursion-wise caching and recursive KV sharing) specifically designed to handle the missing-KV problem that arises when tokens exit early. Expert-choice routing [110] is adopted to guarantee static compute budgets, with an auxiliary loss to resolve the causality violation inherent in top-k selection during autoregressive inference.

## Why It Matters / Open Questions

MoR provides a single, end-to-end trainable architecture that simultaneously reduces parameters (~3× with N_r=3), FLOPs (via selective attention over active tokens), and KV cache memory, without requiring post-hoc routing stages that degrade performance. The practical impact is significant: 25% peak memory reduction, 19% training time savings, and up to 2.06× inference throughput gains from continuous depth-wise batching. However, the evaluation is capped at 1.7B parameters where vanilla slightly outperforms MoR, leaving open whether the architecture's advantages persist at frontier scale. Future work on adaptive capacity control at inference, integration with chain-of-thought reasoning, and scaling beyond 1.7B are critical open questions.
