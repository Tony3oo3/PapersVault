## Problem

Pipeline parallelism for LLM inference distributes model layers evenly across stages, but the final stage must additionally perform token sampling, creating a workload imbalance that causes upstream stages to idle (pipeline bubbles). This sampling-induced bottleneck has been largely overlooked by existing systems, which rely on static or even layer allocation and cannot adapt to the dynamic ratio of sampling to forward computation time that varies with the decode-to-prefill token composition in each batch.

## Input / Output

The system ingests text prompts in micro-batches processed via chunked prefill (max chunk size 2048) across a pipeline of GPU stages, each holding a subset of Transformer layers. Beyond producing generated text tokens, the system outputs a runtime layer-to-stage mapping that is dynamically adjusted during inference. The redistribution granularity is at the individual Transformer layer level, and KV cache for migrated layers is transferred asynchronously between adjacent pipeline stages via NCCL.

## Method

DynaPipe comprises three tightly coordinated components: (1) an execution time predictor with two lightweight fitted models—one estimating per-layer forward latency as a function of token count and sequence length (T_layer = Σ(φ₁nᵢ + φ₂nᵢLᵢ + ε)), and another estimating sampling latency as a linear function of the number of decode requests (T_sample = α·N_decode + β); (2) a bubble-aware scheduler that computes the misalignment metric Δ between the final stage and upstream stages after hypothetically removing k layers, then triggers redistribution only when the configuration persists across a sliding stability window (size 25) to avoid oscillation; and (3) an asynchronous KV cache migration coordinator that overlaps cache transfer with ongoing forward computation, so the target stage only stalls briefly when it reaches newly assigned layers. The key insight is that moving a few layers from the sampling-heavy tail stage to earlier stages effectively hides sampling latency behind additional forward computation, and this adjustment must be dynamic because the sampling-to-forward ratio fluctuates with workload composition.

## Results

DynaPipe reduces average end-to-end latency (E2EL) by 8–41% across diverse workloads compared to state-of-the-art pipeline parallelism systems. On the ShareGPT dataset, DynaPipe achieves up to 40% E2EL reduction, while on Azure-Conv the reduction reaches 34%. Under a 90% SLO attainment target, DynaPipe sustains up to 19% higher request rates than gLLM. The execution time predictor achieves an average relative error of 4.95% for layer execution time and only 0.31% for sampling time, with a per-prediction cost of just 0.5 µs.

## Baselines & Comparisons

DynaPipe is compared against three baselines: vLLM (v0.8.5 V1), gLLM, and SGLang (v0.4.3.post2). SGLang, which relies solely on tensor parallelism, falls significantly behind both pipeline-parallelism systems due to substantial inter-device communication overhead under high concurrency. vLLM, while using pipeline parallelism, suffers from pronounced inter-batch pipeline bubbles caused by its fixed-size chunking strategy, resulting in suboptimal hardware utilization. gLLM, the closest baseline and the framework DynaPipe is built upon, mitigates inter-batch bubbles via adaptive scheduling but overlooks the sampling-induced inter-stage imbalance. DynaPipe consistently outperforms all three baselines in both average E2EL and SLO compliance across Qwen2.5-14B and Qwen2.5-32B on both ShareGPT and Azure-Conv, with the largest gains (up to 40%) observed under high-throughput scenarios where the decode-to-prefill ratio amplifies sampling overhead. In cross-node (TCP-simulated) settings, DynaPipe still maintains significant improvements over gLLM, though the optimization margin narrows slightly due to additional KV cache migration latency.

## Relation to Prior Work

DynaPipe builds directly on gLLM's pipeline parallelism framework for LLM serving, extending it with a runtime dynamic layer redistribution mechanism. It departs from prior static redistribution approaches (e.g., Skywork-MoE, Megatron-LM) and from vocabulary parallelism [41] (designed for training) by making layer reallocation adaptive to the fluctuating ratio of decode-to-prefill tokens at inference time. The design also leverages chunked prefill [19] and the pipeline scheduling principles from TD-Pipe [26], but introduces an asynchronous KV cache migration coordinator to avoid pipeline stalls during redistribution—a component absent in prior PP serving systems.

## Why It Matters / Open Questions

The paper identifies and quantifies a previously underappreciated bottleneck—tail-stage sampling overhead (~3× single-layer forward time)—that degrades pipeline utilization in production LLM serving, and shows that a lightweight dynamic redistribution mechanism can recover 8–41% of end-to-end latency. Practical limitations include the need to reserve extra GPU memory for preloaded weights (~7.5% for Qwen2.5-32B) and the restriction to pipeline parallelism alone, leaving open how the approach composes with tensor, sequence, or expert parallelism in multi-dimensional deployments. Future directions noted by the authors include KV cache compression to reduce migration cost, asynchronous weight offloading to reclaim memory, and integration with vocabulary parallelism for inference.
