## Problem

Existing green-red watermarking schemes designed for natural language fail on code because random vocabulary partitioning can place all semantically valid tokens in the red list, and low-entropy syntactic positions (parentheses, keywords) leave no room for safe watermark insertion. Furthermore, prior code watermarking methods (e.g., SWEET) require privileged access to the original LLM's entropy or generation prompts during detection, severely limiting practical deployment. The paper asks how to embed detectable watermarks in LLM-generated code that preserve functionality and remain detectable using only the code snippet itself.

## Input / Output

During generation, the WPN consumes a context window of up to 10 preceding tokens plus a secret watermark key k, producing per-position logits over the full vocabulary and a scalar switch probability; the LLM then samples from the biased distribution. During detection, only the generated code snippet, the WPN model, and the key k are needed—no access to the source LLM, original prompt, or generation history is required. Detection is performed selectively at positions where the switch probability exceeds a threshold α, and the final output is a z-score compared against a significance threshold to yield a binary watermark-present/absent decision.

## Method

ACW introduces a Watermark Partitioning Network (WPN), a 6-layer transformer (d_model=512, 8 heads) with a dual-head output: a Logits head predicting token-level scores for vocabulary partitioning and a Switch head predicting whether the current position is suitable for watermark insertion. The WPN is trained via AST-guided supervision: semantically equivalent code variants are generated through AST transformations (identifier renaming, control-flow conversion, expression restructuring), and branching entropy over valid continuations at each context prefix provides ground-truth labels for the switch head (BCE loss) while next-token prediction on the variants trains the logits head (NLL loss). At inference, a logits-guided sampling strategy sorts tokens by WPN logits, pairs adjacent tokens, and uses a PRF keyed by (k, t, i) to assign each pair to green or red lists—ensuring semantically similar tokens are split across lists so that at least one valid alternative always remains in the green list. The LLM's logits are then biased by δ for green-list tokens, and detection applies a one-proportion z-test only at switch-selected positions, with theoretical proofs guaranteeing exact green/red probability balance for any rational ratio γ=m/n.

## Results

On HumanEval (OpenCoder-1.5B-Instruct), ACW achieves 84.43% AUROC and 45.12% TPR@5%FPR for watermark detection while maintaining 64.02% Pass@1 (only 1.4% below the unwatermarked base of 65.42%). On MBPP, ACW reaches 81.18% AUROC and 44.20% TPR with 41.32% Pass@1 (2.0% below base). On the larger OpenCoder-8B-Instruct model, ACW achieves 81.22% AUROC and 39.26% TPR with 71.90% Pass@1 (0.14% below base). Across Java, C++, and JavaScript (HumanEvalPack), ACW delivers the best practical-watermark AUROC in every language, reaching 91.03% AUROC on C++.

## Baselines & Comparisons

Among practical watermarks (no oracle access), ACW dominates both WLLM and EXP-edit on every metric: on HumanEval, ACW achieves 84.43% AUROC vs. WLLM's 70.17% and EXP-edit's 66.50%, with TPR of 45.12% vs. 20.73% and 25.61% respectively; Pass@1 is also highest at 64.02% vs. 58.05% (WLLM) and 49.09% (EXP-edit). Against the oracle method SWEET (which requires the original LLM and prompts), ACW matches or exceeds it on HumanEval (AUROC 84.43% vs. 83.10%, TPR 45.12% vs. 42.68%, Pass@1 64.02% vs. 61.77%) and on MBPP TPR (44.20% vs. 32.00%), though SWEET edges ahead on MBPP AUROC (84.40% vs. 81.18%). The oracle variant ACW-s, which uses the LLM's own logits for partitioning, achieves the highest detection (93.38% AUROC, 61.87% TPR on HumanEval) but still requires privileged model access. All four post-hoc detectors (logp(x), LogRank, DetectGPT, GPTZero) perform at or below random (AUROC 41–52%), confirming that passive detection is ineffective for code and that active watermarking is necessary.

## Relation to Prior Work

This paper extends the green-red watermarking framework of Kirchenbauer et al. (WLLM) to the code domain by replacing the pseudorandom vocabulary partition with a learned Watermark Partitioning Network (WPN) trained via AST-guided branching entropy. It departs from SWEET (Lee et al.), which introduced selective watermarking for code but requires oracle access to the generating LLM's entropy, by learning a lightweight switch head that identifies high-entropy positions without model access. The key methodological departure is the logits-guided sampling scheme, which pairs semantically similar tokens (adjacent in WPN logit ranking) and splits them across green/red lists via a PRF, addressing the semantic constraint problem that random partitioning creates in code generation.

## Why It Matters / Open Questions

Practical code watermarking without oracle LLM access is a critical gap for real-world IP protection of AI-generated code, and this paper provides the first framework that closes it with theoretical guarantees on statistical balance. However, detection performance degrades substantially under paraphrase attacks (AUROC drops from 84% to 59% under DIPPER), and absolute TPR remains moderate (~45%), leaving open the question of whether watermarks can survive realistic code modification pipelines. The approach is also validated on relatively small models (1.3B–8B) and a limited set of languages, so generalization to frontier-scale code models and dynamically-typed or highly ambiguous grammars remains untested.
