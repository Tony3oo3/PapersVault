## Problem

Existing continual learning approaches for structured knowledge reasoning (SKR) are limited to a single type of structured knowledge (e.g., text-to-SQL only) and suffer from parameter growth proportional to the number of tasks, hindering generalization across heterogeneous schemas and reasoning efficiency. This paper is the first to explore continual learning across diverse SKR task types (databases, knowledge graphs, dialogue states) where input and output spaces differ fundamentally between tasks.
![Teaser figure](../imgs/NEURIPS20254834/cropped_page1_idx0.webp)

## Input / Output

The method takes a natural language question and a structured knowledge schema (database tables/columns, KG triples, or dialogue intents/slots) as input. The pipeline operates in two stages: first, the schema is converted to a unified DB-like representation (abstract table names and column names) for filtering, producing a relevant schema subset; second, the query builder consumes both the filtered subset and the original raw schema to generate an executable structured query in the task-specific format (SQL, SPARQL, s-expression, or TOP). The backbone LLM remains frozen throughout; only lightweight LoRA modules are updated.

## Method

K-DECORE decouples the reasoning process into a task-agnostic schema filtering stage (shared LoRA module P_a, trained sequentially with the schema unified into a DB-like format to enable cross-task transfer) and a task-specific query building stage (separate LoRA module P_b, which also receives the raw schema to avoid error propagation). A dual-perspective memory mechanism mitigates forgetting: schema memory (M_a) stores representative schema-filtering samples selected via clustering on schema embeddings, while query memory (M_b) stores structurally diverse query samples selected via clustering on query-structure embeddings. To further enhance generalization, a structure-guided synthesis algorithm (Algorithm 1) generates novel pseudo queries by combining sampled query structures with random schemas, validating them via execution, and using a third LoRA module (P_c) to generate corresponding natural language questions. The entire framework operates with a fixed number of tunable parameters regardless of the number of sequential tasks.

## Results

K-DECORE achieves the best AA across all three SKR streams and all three backbone LLMs: 31.8/31.4/30.1 (T5-LARGE), 40.5/41.1/37.0 (LLaMA3-8B), and 43.2/40.1/36.8 (Qwen2.5-7B). It also attains the best (least negative) BWT on T5-LARGE (−9.6/−7.5/−6.9) and Qwen2.5-7B (−8.2/−9.8/−16.7), and the highest FWT on all backbones (e.g., 8.6/8.4/7.7 on T5-LARGE vs. 3.6/4.2/3.1 for the next-best SFNET). The gap to the Multi-Task upper bound narrows from ~5–7 points in AA to ~12–17 points, indicating effective knowledge transfer with a fixed parameter budget.

## Baselines & Comparisons

K-DECORE outperforms all six baselines on AA across every backbone and stream. Against the strongest rehearsal-based baseline SFNET [9], K-DECORE gains +4.5 to +12.9 points in AA (e.g., 43.2 vs. 40.3 on Qwen2.5-7B Stream 1) and substantially improves FWT (6.9 vs. 4.5). Against the strongest PEFT-based baseline C3 [12], K-DECORE leads by +1.8 to +4.3 points in AA and by +3.6 to +4.8 points in FWT (e.g., 43.2 vs. 38.9 AA and 6.9 vs. 1.9 FWT on Qwen2.5-7B Stream 1), while C3 does not report BWT since it loads a separate module per task. On T5-LARGE, K-DECORE also dominates EMAR [19] (+19.2 to +21.4 AA), O-LORA [11] (+30.4 to +24.7 AA), ProgPrompt [14] (+22.1 to +14.2 AA), and SAPT [13] (+13.3 to +4.5 AA). The only metric where K-DECORE trails a baseline is BWT on LLaMA3-8B (−16.7 vs. EMAR's −13.2 on Stream 1), but this is offset by its superior AA and FWT, and the paper attributes the trade-off to reduced inter-task interference from decoupling.

## Relation to Prior Work

This paper departs from prior continual SKR work (e.g., SFNET, APEX, LECSP) that was restricted to a single structured-knowledge type (typically text-to-SQL) and from per-task PEFT methods (O-LoRA, C3, SAPT, ProgPrompt) that allocate separate modules per task, causing parameter growth. K-DECORE's core conceptual move is to decompose the SKR pipeline into a task-agnostic schema-filtering stage and a task-specific query-building stage, each with its own fixed LoRA module, so that knowledge transfer occurs through the shared filtering module while task-specificity is isolated in the builder. The dual-perspective memory with structure-guided pseudo-query synthesis extends rehearsal-based continual learning (EMAR) by augmenting replay with synthetically generated, structurally novel queries rather than only real historical examples.

## Why It Matters / Open Questions

This is the first systematic treatment of continual learning across heterogeneous structured-knowledge types (databases, knowledge graphs, dialogue states) with a fixed parameter budget, which is directly relevant to deployment scenarios like virtual assistants that must accumulate new reasoning capabilities over time. The practical finding that a 20% pseudo-sample ratio in replay memory is optimal, and that query-structure diversity (not schema diversity) is the critical factor for preventing forgetting, offers actionable guidance for memory design in continual LLM systems. Key limitations include the small per-task training budget (1,000 samples), evaluation on only four datasets, and the absence of reasoning-based LLMs (e.g., Qwen3) as backbones, leaving open whether the decoupling principle and synthetic-replay strategy transfer to more complex, multi-step reasoning settings.
