## Problem

Reinforcement learning has shown great promise for enhancing LLM reasoning on math and competitive coding, but no prior work has scaled RL to real-world software engineering tasks like resolving GitHub issues. Existing approaches to training open LLMs for SE rely on proprietary teacher models (GPT-4o, Claude-3.5-Sonnet) and supervised fine-tuning, which the paper shows leads to performance degradation on out-of-domain tasks. The paper asks whether RL with a simple rule-based reward on open software evolution data can improve both in-domain issue solving and general reasoning.

## Input / Output

The policy LLM receives a prompt containing the issue description and the complete content of all relevant files (both files to repair and relevant unchanged files), formatted with a system instruction to produce a chain-of-thought followed by search/replace edits. The output is a reasoning trace in a <think> block followed by one or more SEARCH/REPLACE code blocks with strict indentation requirements. The reward is a continuous similarity score (0–1) computed via Python's difflib.SequenceMatcher between the extracted predicted patch and the oracle patch, or −1 if the output is incorrectly formatted. Notably, providing full file contents (rather than diffs) implicitly forces the model to identify fault locations before generating edits.

## Method

SWE-RL applies Group Relative Policy Optimization (GRPO) to Llama-3.3-70B-Instruct using 273k curated GitHub PR seeds as the training set, where each seed provides an issue, code context, and oracle patch. The reward function is a lightweight rule-based similarity score (difflib.SequenceMatcher) between the LLM-generated patch and the oracle patch, with a −1 penalty for formatting errors—no execution feedback or proprietary model in the loop. Training runs for 1,600 steps on 512 H100 GPUs with a global batch of 512 (32 problems × 16 rollouts each). The key design choice is conditioning on complete file contents, which implicitly teaches the model both bug diagnosis and repair generation in a single RL objective. At inference, the Agentless Mini scaffold (a simplified pipeline with file-level localization, multi-sample repair, reproduction test generation, and dual-execution-agreement reranking) leverages the model's emergent generalization to subtasks it was never explicitly trained on, achieving 41.0% on SWE-bench Verified.

## Results

Llama3-SWE-RL-70B achieves a 41.0% pass@1 solve rate on SWE-bench Verified, the best result among medium-sized (<100B) open-source models and comparable to GPT-4o (38.8% with Agentless). In a repair-only ablation (Table 2), the RL model reaches 34.8% repair accuracy with 95.6% format correctness, versus 5.4% (greedy) / 16.6% (majority voting) for the untrained Llama-3.3-70B-Instruct and 29.6% for the SFT baseline. On out-of-domain tasks, the RL model improves over the base Llama-3.3-70B-Instruct on all five benchmarks (e.g., MATH strict 73.7 vs 63.2, HumanEval+ 79.9 vs 76.2, MMLU 86.82 vs 86.49), while the SFT baseline degrades on average.

## Baselines & Comparisons

Llama3-SWE-RL-70B (41.0%) outperforms all other ≤100B open-source models on SWE-bench Verified: SWE-Fixer-72B (32.8%), SWE-Gym-32B (32.0%), Lingma-SWE-GPT-72B (28.8%), and its own SFT baseline (36.2%). It also surpasses GPT-4o + Agentless (38.8%) and approaches o1-preview + Agentless (41.3%), while remaining well below the largest proprietary systems (DeepSeek-R1 at 49.2%, Claude-3.5-Sonnet + OpenHands at 53.0%). In the repair-only comparison (Table 2), the RL model (34.8%) beats the SFT baseline (29.6%) and the untrained Llama-3.3-70B-Instruct (5.4% greedy / 16.6% majority voting) by a wide margin. On out-of-domain tasks (Table 3), the RL model consistently outperforms both the base model and the SFT baseline across HumanEval+, BigCodeBench, CRUXEval, MATH, and MMLU, whereas the SFT baseline degrades on most tasks relative to the untrained base model. Notably, all competing trained open-source models (Lingma-SWE-GPT, SWE-Gym, SWE-Fixer) rely on distilled outputs from GPT-4o or Claude-3.5-Sonnet, whereas Llama3-SWE-RL is trained exclusively on publicly available GitHub PR data via RL.

## Relation to Prior Work

SWE-RL extends the RL-for-reasoning paradigm established by DeepSeek-R1 (which applied GRPO to competitive coding and math) to real-world software engineering, using GitHub pull requests as training data and a lightweight sequence-similarity reward instead of execution-based or exact-match signals. It builds on the Agentless scaffold (Xia et al., 2024), simplifying it to Agentless Mini to isolate the repair subtask for RL training. Crucially, it departs from concurrent SWE-bench training efforts (Lingma-SWE-GPT, SWE-Gym, SWE-Fixer), which all rely on supervised fine-tuning with distilled outputs from proprietary models like GPT-4o or Claude-3.5-Sonnet, by using only publicly available PR data and rule-based RL rewards.

## Why It Matters / Open Questions

The paper demonstrates for the first time that RL on a single domain-specific task (issue resolution) can improve general reasoning across math, code reasoning, and language understanding, while SFT on the same data degrades performance—suggesting RL's reward-driven exploration preserves and broadens capabilities in ways SFT does not. The 41.0% SWE-bench Verified score with a 70B open model, competitive with GPT-4o, makes this practically significant for the open-source community. Key limitations include the sequence-similarity reward (which may prevent exploration of semantically equivalent but textually different patches) and the pipeline-based scaffold that prevents holistic, interaction-driven reasoning. Open questions include whether the generalization effect holds across model scales and architectures, and whether richer reward signals (e.g., execution-based) could further close the gap to larger proprietary models.
