## Problem

LLM-based text-to-SQL systems frequently produce syntactically valid but semantically incorrect queries, yet existing error detection relies on LLM self-reflection that suffers from self-preference bias and provides only a single confidence score without clause-level granularity. There is no framework that grounds error detection in both database execution signals and LLM reasoning, and no correction strategy that avoids breaking originally correct queries while fixing interdependent errors in a principled order.

## Input / Output

SQLENS takes a natural language question, a database instance (tables with schemas and sample cell values), optional external knowledge (e.g., column annotations, value mappings), and a generated SQL query as input. The SQL is parsed into an Abstract Syntax Tree, and the system produces three outputs: a probabilistic semantic correctness score, structured clause-level error reports (each containing a signal description, correction instruction, identified problematic clauses, and a confidence bucket), and a corrected SQL query. The error reports are JSON-structured and designed to be both human-interpretable for debugging and machine-consumable for guiding iterative LLM-based fixes.

## Method

SQLENS integrates two complementary signal sources: database-based signals (e.g., Empty Predicate via per-predicate execution, Suboptimal Join Tree via minimum Steiner Tree computation on a pre-built join graph, Incorrect Join Predicate via PK/FK validation, Abnormal Result via output inspection) and LLM-based signals (e.g., Evidence Violation, Column Ambiguity, LLM Self-Check), all collected in a single LLM call to limit cost. These noisy signals are treated as labeling functions in a Snorkel weak-supervision framework that learns their accuracies and correlations to produce probabilistic correctness labels without requiring ground-truth annotations. For correction, SQLENS decomposes the task into an iterative loop: an Error Selector (LLM-based reranking) prioritizes the most critical error, an Error Fixer applies a targeted fix guided by the corresponding error report and validates syntax via a SQL parser, and a SQL Auditor compares the original and revised queries to prevent degradation of already-correct queries. A high-precision guardrail signal can trigger final adjustments, and the process repeats for up to three iterations, removing fixed signals to avoid redundant corrections.

## Results

On the BIRD dev set, SQLENS improves execution accuracy of out-of-the-box text-to-SQL systems by up to 20.50% (DIN-SQL: 54.63% → 59.99%) and achieves the highest post-correction accuracy of 65.23% (from MAC-SQL's 60.04%), surpassing the strongest correction baseline SQLFixAgent (60.17%) by 5.06 points. For semantic error detection, SQLENS outperforms the best LLM self-evaluation baseline by 25.78% in F1 (78.88 vs. 57.43 on DIN-SQL queries). SQLENS also achieves the highest net improvement (N_net) across all four text-to-SQL backbones, fixing more queries while introducing fewer regressions than Self-Reflection or Fix-ALL.

## Baselines & Comparisons

SQLENS consistently outperforms all compared correction frameworks on BIRD. Against MAGIC (59.13%) and Self-Debug (57.24%), both built on DIN-SQL, SQLENS achieves 65.23% post-correction accuracy from a stronger base (MAC-SQL at 60.04% vs. 56.52%), yielding a larger absolute gain (+5.19 vs. +2.61 and +0.72). Against SQLFixAgent (60.17% from CodeS-7b), SQLENS leads by 5.06 points despite starting from a higher initial accuracy. For error detection, SQLENS (F1=78.88 on DIN-SQL) surpasses LLM Self-Eval (Bool) (F1=57.43) by 21.45 points and LLM Self-Eval (Prob) (F1=29.83) by 49.05 points, while the supervised variant (F1=79.53) slightly edges out the weak-supervision version. In end-to-end correction, SQLENS also beats its own Fix-ALL ablation (which feeds all error signals simultaneously) by 1.39–2.37% across backbones, validating the iterative, prioritized correction strategy over a single-shot fix.

## Relation to Prior Work

SQLENS builds on Snorkel's weak supervision framework (Ratner et al., PVLDB 2017) to aggregate noisy, partially-overlapping error signals into probabilistic correctness labels, repurposing a data-labeling technique for SQL query validation. It departs from prior text-to-SQL error correction methods (DIN-SQL self-reflection, Self-Debug, MAGIC, SQLFixAgent) that rely on a single LLM self-evaluation pass or assume all queries are incorrect, instead combining database-grounded structural signals (query plan analysis, Steiner tree join optimality, predicate emptiness checks) with LLM-based semantic signals (evidence violation, column ambiguity) in a unified detection-and-correction pipeline. The sequential, prioritized correction strategy with an Error Selector and SQL Auditor distinguishes it from Fix-ALL approaches that dump all error reports simultaneously.

## Why It Matters / Open Questions

The paper addresses a practical gap in deployed text-to-SQL systems (AWS, Databricks, Snowflake) where ~25% of LLM-generated queries are semantically wrong yet syntactically valid, and users lack explainable debugging tools. The clause-level error reports and weak-supervision-based correctness estimation (requiring no ground-truth labels) make the framework deployable in production settings where gold labels are unavailable. Key limitations include dependence on LLM quality for the correction step, computational overhead from iterative multi-signal evaluation (~10K tokens/query average), and the fact that the approach is designed for offline debugging rather than latency-sensitive pipelines. Open questions include whether the signal set generalizes to non-SQLite databases, how performance scales with schema complexity, and whether the weak supervision model can be replaced by lighter-weight alternatives.
