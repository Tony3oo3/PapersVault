## Problem

Existing LLM-based code agents (e.g., OpenHands, SWE-Agent) struggle to effectively leverage GitHub repositories for complex real-world tasks because repositories present two core obstacles: information density that exceeds LLM context windows, and tangled inter-module dependencies that make it hard to locate relevant components. Relying solely on README files or simple find/edit operations is insufficient, as agents cannot perform deeper, task-driven structural understanding of the codebase.

## Input / Output

The agent receives a natural-language task description, a pre-selected GitHub repository (cloned locally with its full source tree, README, and configuration files), and specific input data files (e.g., an image, a CSV, a signal recording) with defined paths. Output is a set of files written to a designated directory following strict naming conventions (e.g., output.{ext} or output_01.{ext}), where correctness is judged both by successful execution and by task-specific quality criteria (e.g., scratch removal quality, Kaggle leaderboard score). The repository is not generated from scratch but must be understood, adapted, and executed by the agent.

## Method

RepoMaster is a three-stage LLM-agent framework built on AutoGen that mimics how human programmers navigate unfamiliar codebases. In the Hierarchical Repository Analysis stage, it performs a single AST walk over all source files to construct three complementary structural artifacts: a Hierarchical Code Tree (package→module→class→function containment map), a Function Call Graph (weighted by call frequency), and a Module Dependency Graph (weighted by coupling strength). A six-feature importance scoring scheme (Personalized PageRank centrality, cyclomatic complexity, import/call usage, semantic keyword flags, docstring richness, and git activity) identifies top-k core classes that form the initial LLM context alongside the README and module summaries. During Autonomous Exploration & Execution, the agent iteratively uses three tool categories—Granular Code View (HCT-based file/class/function inspection), Dependency Analysis (FCG/MDG call-chain tracing), and keyword Search—to progressively explore only task-relevant components. A multi-level information selection strategy (AST subtree extraction for code, relevance-ranked chunking for documents, and head/tail retention for execution logs) activates when combined input exceeds a per-interaction token budget of 8000 tokens, keeping each interaction concise while preserving global coherence.

## Results

On the newly introduced GitTaskBench (54 tasks across 18 repositories), RepoMaster with Claude 3.5 achieves a 75.92% execution completion rate and 62.96% task pass rate, while consuming only 154k tokens per task—approximately 95% fewer than OpenHands (2883k). On the revised MLE-Bench (MLE-R, 22 Kaggle tasks), RepoMaster with Claude 3.5 attains a 95.45% valid submission rate and 27.27% medal acquisition rate (including 22.73% gold), representing a more than five-fold improvement over the best baseline. The ablation study confirms that removing all three core mechanisms (hierarchical analysis, code exploration, information selection) drops the task pass rate from 40.74% to 24.07% with GPT-4o.

## Baselines & Comparisons

RepoMaster consistently outperforms both OpenHands and SWE-Agent across all three LLMs on both benchmarks. On GitTaskBench with Claude 3.5, RepoMaster achieves a 62.96% task pass rate versus 40.74% for OpenHands and 22.23% for SWE-Agent, while using 95% fewer tokens than OpenHands (154k vs. 2883k) and 66% fewer than SWE-Agent (154k vs. 456k). On MLE-R with Claude 3.5, RepoMaster's 95.45% valid submission rate more than doubles OpenHands' 45.45% and nearly doubles SWE-Agent's 50.00%, and its 27.27% medal rate (22.73% gold) is roughly six times higher than either baseline's 4.55%. The advantage holds with GPT-4o (40.74% vs. 14.82% vs. 10.19% task pass on GitTaskBench) and DeepSeek V3 (44.44% vs. 26.85% vs. 12.04%), indicating the gains stem from the framework's structural analysis and exploration mechanisms rather than a specific LLM. The case study on a 3D pose estimation task further illustrates that OpenHands fails after ~140 trial-and-error iterations while RepoMaster succeeds in fewer than 20, and SWE-Agent degrades to a coarse method due to lack of repository-level understanding.

## Relation to Prior Work

RepoMaster sits at the intersection of the CodeAct agent paradigm (OpenHands, SWE-Agent) and classical static code analysis (AST parsing, dependency graphs, PageRank-based centrality). Rather than building on a single prior method, it repurposes software-engineering structural tools—Function Call Graphs, Module Dependency Graphs, and Hierarchical Code Trees—into a pre-processing stage that feeds a dynamic LLM exploration loop, departing from the README-driven, find-and-edit approach of existing frameworks. The 'human-like' navigation metaphor (map structure → inspect key file → follow error traces → filter noise) is a conceptual reframe of how agents should interact with large codebases, distinct from GitAgent's simplistic repository search or Aider's file-level dependency tracking.

## Why It Matters / Open Questions

The 95% token reduction (154k vs. 2883k per task) and the large performance gap over OpenHands/SWE-Agent make repository-aware agents substantially more cost-effective and reliable for practical deployment. The newly introduced GitTaskBench fills a gap by evaluating agents on diverse, non-ML real-world tasks (photo restoration, video analysis, office automation) that inherently require repository reuse. Key open questions include generalization beyond Python, handling of multi-repository workflows, and whether the equal-weight importance scoring (validated only via sensitivity analysis) holds for heterogeneous codebases; the paper also notes that the approach assumes a single well-structured repository per task, limiting applicability to monorepo or microservice settings.
