## Problem

LLM-based compiler auto-tuning suffers from two critical gaps: the absence of high-quality reasoning datasets that include chain-of-thought traces, external tool integration, and environment feedback, and the limited interaction with the compilation environment in existing supervised fine-tuning approaches, which restricts autonomous exploration and adaptive learning from feedback. This paper tackles both by introducing the first RL-driven framework specifically designed for LLM-based compiler pass-sequence optimization.
![Teaser figure](../imgs/NEURIPS20252951/cropped_page0_idx0.webp)

## Input / Output

The agent receives a compact 56-dimensional AutoPhase feature vector (capturing block structure, instruction mix, and control-flow statistics) plus the initial IR instruction count and a file path to the LLVM IR program. It produces a pass sequence drawn from a fixed action space of 125 options (124 LLVM 10.0.0 opt passes plus the -0z preset), structured as a multi-turn thought–tool-call–tool-response trajectory that concludes with a final answer tag. The interaction protocol mandates two tools: instrcount (evaluates a candidate sequence's improvement over -0z) and find_best_pass_sequence (a guided search fallback when the initial candidate fails).

## Method

Compiler-R1 employs a two-stage end-to-end training pipeline. Stage 1 (SFT cold-start) uses 800 curated samples—derived from a 19,603-sample dataset built via synergy pass-pair identification, global synergy graph construction, and graph-guided random-walk sequence selection—to teach the LLM the thought–action–feedback interaction protocol. Stage 2 applies on-policy RL (GRPO, PPO, or REINFORCE++) over ~19k interactive episodes with a composite reward combining a format reward (1.5 for protocol compliance) and an answer reward proportional to OverOrig (IR instruction reduction relative to the original unoptimized program), which provides a denser signal than OverOz for stable training. The key architectural insight is that SFT alone teaches protocol compliance but not adaptive optimization, while RL alone cannot acquire the interaction protocol; their combination enables the agent to autonomously explore the pass space, invoke tools strategically, and generalize to unseen programs, achieving 8.46% average OverOz reduction with GRPO-7B in 26 seconds per program.

## Results

Compiler-R1 (GRPO-7B) achieves an average 8.46% IR instruction count reduction (OverOz%) across seven benchmarks, with per-benchmark gains ranging from 4.52% (opencv) to 22.44% (npb). The best SFT-only baseline (SFT-Qwen-7B, N=40) reaches only 4.66% average OverOz, while the strongest traditional autotuner (OpenTuner) achieves 6.09%. GRPO-7B completes each program in 26 seconds on average, compared to 200s for OpenTuner, 561s for GA, and 9,803s for CompTuner. Even the lightweight GRPO-1.5B variant (3.87% OverOz, 20s) outperforms its SFT-only counterpart (3.15%, 29s).

## Baselines & Comparisons

GRPO-7B (8.46% avg OverOz) outperforms all traditional autotuners: OpenTuner (6.09%), GA (5.17%), TPE (4.83%), RIO (4.65%), BOCA (3.60%), and CompTuner (3.52%), while being 8–377× faster (26s vs. 200–9,803s per program). Against SFT-only LLM baselines, GRPO-7B nearly doubles the performance of SFT-Qwen-7B (8.46% vs. 4.66%) despite requiring only a single inference pass rather than N=40 stochastic samples. The RL advantage is consistent across model scales: GRPO-1.5B (3.87%) beats SFT-Qwen-1.5B (3.15%) and is 31% faster (20s vs. 29s). AutoPhase (PPO-LSTM) is the fastest baseline (2.2s) but achieves only 1.24% average OverOz, and its PPO-noLSTM variant catastrophically fails (−50.35%), indicating poor generalization. Notably, traditional methods like GA, TPE, and CompTuner produce negative OverOz on several benchmarks (blas, cbench, mibench), whereas Compiler-R1 maintains positive gains across all seven datasets.

## Relation to Prior Work

Compiler-R1 sits at the intersection of two research threads: (1) LLM-based compiler auto-tuning (Cummins et al., Italiano & Cummins), which previously relied on supervised fine-tuning to directly predict pass sequences without environmental feedback, and (2) rule-based RL for LLM reasoning (DeepSeek-R1 and its extensions to code generation, search, and OS tuning), which had not been applied to compiler optimization. The paper departs from prior LLM compiler-tuning work by introducing a two-stage SFT+RL pipeline with explicit tool-augmented interaction (instrcount, find_best_pass_sequence), and from traditional RL-based tuners (AutoPhase) by replacing the RL agent with an LLM that reasons in natural language. Its dataset construction draws on CFSAT's synergistic pass-pair identification and coreset-inspired sampling from Liang et al., while program representation reuses AutoPhase's 56 statistical features.

## Why It Matters / Open Questions

This is the first demonstration that an RL-trained LLM agent can autonomously explore a compilation environment via tool calls and outperform both SFT-only LLMs and classical autotuners (OpenTuner, GA, CompTuner) on IR instruction reduction with far lower runtime (~26s vs. 200–9800s). The 19,603-sample reasoning dataset and the two-stage training recipe provide a reusable template for agentic RL in other tool-augmented domains. Key open questions remain: IR instruction count is a proxy that may not correlate with runtime performance, the framework is tied to a fixed LLVM 10.0.0 pass set (125 actions), and the model's reliance on external tools limits its ability to develop intrinsic understanding of *why* a pass sequence works. Cross-version generalization and richer program representations (beyond 56-dim statistics) are natural next steps.
