## Problem

Repository-level software engineering tasks (issue fixing, cross-file code completion) remain poorly addressed by open-source LLMs, which have achieved at most ~30% resolution on SWE-bench Lite compared to ~55% for proprietary agent-based systems. Existing open-source approaches either flatten repository structure into linear text (losing explicit dependencies) or rely on multi-step agent pipelines that introduce unpredictability and require closed-source models. The paper asks whether an open-source LLM can be made to natively comprehend both the semantic content and structural dependencies of an entire codebase in an agentless setting.

## Input / Output

The CGM consumes a dual-modality input: (i) a code graph subgraph where each node's code/comment text is compressed by a CodeT5+ encoder and 2-layer MLP adapter into a single node token (512:1 compression, extending effective context by 512×), and (ii) the full text content of selected files as standard text tokens. The graph's adjacency matrix replaces the causal attention mask between node tokens, so attention flows only along graph edges. For issue fixing, the output is a diff-formatted patch; for code completion, it is the missing code lines. The Graph RAG pipeline (Rewriter → Retriever → Reranker → Reader) selects the relevant subgraph and Top-K files before the CGM generates the final output.

## Method

CGM integrates repository code graphs into a decoder-only LLM (Qwen2.5-72B) via two mechanisms: semantic integration, where node text is encoded by a LoRA-fine-tuned CodeT5+ encoder and projected into the LLM's embedding space through a randomly initialized 2-layer MLP adapter (compressing 512-token chunks into single node tokens), and structural integration, where the code graph's adjacency matrix is used as a graph-aware attention mask between node tokens, restricting attention to neighboring nodes in a manner analogous to spatial GNN message passing. Training proceeds in two phases: (1) subgraph reconstruction pre-training, where the model learns to regenerate code from randomly sampled subgraphs using hierarchical topological ordering, and (2) noisy fine-tuning on 200k issue-patch pairs with 10% irrelevant-file and 10% missing-file perturbations for robustness. An agentless Graph RAG framework (Rewriter extracts entities/keywords, Retriever builds a connected subgraph via lexical+semantic search, Reranker selects Top-5 files via two-stage ranking, Reader=CGM generates the patch) replaces the 10-step Agentless pipeline with four modules, achieving 43.00% on SWE-bench Lite—first among open-weight models.

## Results

On SWE-bench Lite (300 Python issues), CGM-SWE-PY achieves a 43.00% resolution rate using the open-source Qwen2.5-72B model, ranking first among open-weight models and eighth overall. On SWE-bench Verified (500 issues), CGM-SWE-PY reaches 50.40%, again ranking first among open-weight models. On SWE-bench-java Verified (91 Java issues), CGM-Multi achieves 14.29%, outperforming all SWE-Agent variants. On CrossCodeEval, CGM-Multi attains 50.21/80.76 (Java EM/ES) and 61.20/84.30 (Python EM/ES), and on ComplexCodeEval it reaches 47.00/78.86 (Java) and 43.00/72.60 (Python), substantially exceeding standalone LLM baselines.

## Baselines & Comparisons

CGM-SWE-PY (43.00%) outperforms the previous best open-source model-based method, Moatless+DeepSeek-V3 (30.67%), by 12.33 percentage points, despite DeepSeek-V3 being a stronger base model than Qwen2.5-72B. It also surpasses the agentless Agentless+Claude-3.5-Sonnet (40.67%) by 2.33% and Agentless+GPT-4o (32.00%) by 11.00%, using a simpler four-step Graph RAG pipeline versus Agentless's ten-step pipeline. Among open-source model methods, CGM-SWE-PY leads SWE-Fixer (24.67%) by 18.33% and Lingma SWE-GPT (22.00%) by 21%. On code completion (CrossCodeEval), CGM-Multi consistently outperforms all RAG baselines (BM25, RepoFuse, RLCoder, R2C2) across four 7B base models, with the largest gains over RepoFuse, which also uses code graphs but flattens them into text. On ComplexCodeEval, CGM-Multi achieves 47.00 EM (Java) and 43.00 EM (Python), exceeding the strongest standalone LLM baselines (DeepSeek-V2.5-236B at 36.00/32.00 EM) by 11 and 11 points respectively, demonstrating the benefit of explicit graph-structural integration over linearized context.

## Relation to Prior Work

This paper extends the line of graph-enhanced code models (GraphCodeBERT, StructCoder, TreeBERT) from file/function-level encoder architectures to repository-level decoder-only LLMs, and departs from prior graph-in-code approaches (RepoGraph, GraphCoder, DeepSeek-Coder) that flatten retrieved subgraphs into linear text sequences. Architecturally, it borrows the VLM-style encoder-adapter-decoder pattern (as in LLaVA, Qwen2-VL) and repurposes it for code graphs, where the encoder (CodeT5+) compresses 512-token node text into a single node token via soft prompt compression, and the graph adjacency matrix replaces the causal attention mask to enforce GNN-like message passing. The agentless Graph RAG framework (Rewriter→Retriever→Reranker→Reader) is positioned as a simpler alternative to the ten-step Agentless pipeline and multi-turn agent loops, drawing on retrieval-augmented generation for code completion (RepoCoder, RepoFuse) but preserving graph modality end-to-end rather than collapsing it into text.

## Why It Matters / Open Questions

The result demonstrates that open-source LLMs with explicit graph-structure integration can approach the performance of closed-source agent-based systems on repository-level issue fixing (43% vs. 47% on SWE-bench Lite), reducing dependence on proprietary APIs and the unpredictability of multi-turn agent reasoning. The dramatic ablation gap (43% with graph structure vs. 5.33% with flattened graph) provides strong evidence that preserving structural dependencies in the attention mechanism is critical, not merely a context-length benefit. Limitations include the absence of error bars, modest Java performance (14.29%), and reliance on a 72B backbone for competitive results (7B variants score only 4% on SWE-bench Lite). Open questions include whether the graph-aware attention mask generalizes to other modalities or larger repositories, whether the approach scales beyond Python/Java, and whether the 512× compression ratio is optimal or loses critical intra-node information.
