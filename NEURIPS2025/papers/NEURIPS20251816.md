## Problem

Long-context LLM inference suffers from linearly growing KV cache memory and decoding latency, yet existing sparse attention methods rely on static or heuristic token selection that fails to capture the dynamic sparsity of attention. Off-the-shelf approximate nearest neighbor search (ANNS) indexes, which could theoretically identify critical tokens efficiently, perform poorly because query and key vectors in attention are out-of-distribution relative to each other, requiring 30%+ of all vectors to be scanned for acceptable recall.
![Teaser figure](../imgs/NEURIPS20251816/cropped_page1_idx0.webp)

## Input / Output

The method takes a large fixed context (documents, source code, or domain-specific prompts up to 1M tokens) that is pre-processed offline into KV vectors and an attention-aware vector index stored in CPU memory, combined with a short user query (10–2K tokens). During inference, only a single query vector per decoding step is sent to the CPU for index traversal, while a small static pattern (640 tokens: 128 initial + 512 sliding window) remains resident on the GPU. The output is standard autoregressive text generation, with the full KV cache offloaded to CPU DRAM (128 GB+) to fit within a single 24 GB GPU.

## Method

RetrievalAttention integrates ANNS into attention computation by recognizing the mathematical equivalence between sparse attention and maximum inner product search. The key technical contribution is an attention-aware vector index that mitigates the OOD gap between query and key vectors: during offline construction, exact KNN connections are established from sampled query vectors to their nearest key vectors, then projected onto the key space using RoarGraph's projection technique to eliminate all query vectors, yielding a pure key-vector graph that encodes query-perspective proximity. During decoding, this index requires scanning only 1–3% of key vectors to achieve >0.95 recall@100, compared to 30–50% for IVF. The system employs CPU-GPU co-execution: static tokens (initial + sliding window) are computed on GPU via FlashAttention, while dynamic retrieval and partial attention run on CPU in parallel, with the two partial outputs merged using an online-softmax combination formula analogous to FlashAttention's rescaling.

## Results

RetrievalAttention achieves near full-attention accuracy on RULER with only a 2.21% drop on Llama-3-8B (81.70% vs. 83.91%) and a 0.52% drop on Yi-9B (70.38% vs. 70.90%), while accessing only 1–3% of KV vectors. On ∞-Bench, it reaches 49.6% average accuracy (vs. 50.4% full attention) for Llama-3-8B. For decoding latency at 128K context on a single RTX4090, RetrievalAttention achieves 0.107 s/token, a 7.93× speedup over exact KNN (Flat) and 2.80× over IVF, enabling 8B-parameter models to process 128K tokens within 24 GB GPU memory.

## Baselines & Comparisons

RetrievalAttention clearly outperforms all static/heuristic token-selection baselines: StreamingLLM (15.30%), InfLLM (31.10%), SnapKV (67.62%), Quest (71.49%), MagicPIG (74.97%), and InfiniGen (76.35%) all suffer large accuracy drops on RULER (Llama-3-8B), while RetrievalAttention stays within 2.21% of full attention (81.70% vs. 83.91%). Against the two vector-search baselines, RetrievalAttention matches Flat (exact KNN) in accuracy (81.70% vs. 81.83%) but is 7.93× faster in decoding latency (0.107 s vs. 0.848 s per token at 128K), and it surpasses IVF in both accuracy (81.70% vs. 79.66%) and speed (2.80× faster, 0.107 s vs. 0.300 s). On Yi-9B, RetrievalAttention actually slightly exceeds Flat (70.38% vs. 71.17% is Flat's advantage, but RetrievalAttention is within 0.52% of full attention vs. Flat's +0.27%). On ∞-Bench, RetrievalAttention (49.6%) is within 0.8% of full attention (50.4%) and outperforms all non-index baselines, while Flat and IVF achieve marginally higher accuracy (49.7% and 48.8%) but at 100% and 30% vector scan costs respectively versus RetrievalAttention's 1–3%.

## Relation to Prior Work

RetrievalAttention sits at the intersection of vector retrieval (database systems) and LLM inference optimization. It builds on RoarGraph's projection technique for cross-modal ANNS to eliminate query vectors from the index, on FlashAttention's online softmax for merging partial attention outputs across CPU and GPU, and on StreamingLLM's attention-sink + sliding-window pattern for the static GPU-resident KV subset. The key departure from prior work is the identification of the out-of-distribution (OOD) mismatch between query and key vectors in attention — a problem that causes standard ANNS indexes (IVF, HNSW) to require scanning 30–50% of vectors — and the design of an attention-aware graph index that bridges this gap by explicitly linking queries to their exact KNN keys during construction.

## Why It Matters / Open Questions

The practical impact is significant: enabling an 8B-parameter model to process 128K tokens on a single 24GB RTX4090 at 0.107 s/token opens the door to local and edge deployment of long-context LLMs that previously required multi-GPU setups or cloud infrastructure. The OOD observation is broadly applicable to any setting where vector search is applied across two differently-projected vector spaces, and may inform future work on cross-modal retrieval and attention approximation. Key limitations include the requirement for a large fixed context prefix (offline index building takes ~13 min for 100K tokens), no prefill optimization, and the current static-pattern heuristic (initial tokens + sliding window) that may not capture all consistently important tokens. Open questions include extending the approach to fully dynamic contexts, reducing index construction cost, and adapting the retrieval budget per layer or per task.
