## Problem

The standard method for estimating the Critical Batch Size (CBS) in large-batch training relies on the gradient noise scale, which requires strong assumptions (SGD optimizer, well-conditioned Hessian) that are violated in practice by Adam-based language model pretraining. This makes it unclear whether the noise scale is a reliable proxy for the CBS, leaving practitioners without a trustworthy way to determine how large a batch size they can safely use to increase training throughput.
![Teaser figure](../imgs/NEURIPS20253898/cropped_page4_idx4.webp)

## Input / Output

The CBS measurement takes a single training checkpoint (with its current batch size B and learning rate η), the pretraining data stream, and a set of batch size multipliers k, then trains each branch for a fixed 2B-token window to produce a CBS estimate B* = k*·B at that checkpoint. The batch size warmup application consumes CBS measurements across multiple checkpoints to produce a doubling schedule (e.g., double at 168B and 503B tokens), which is then used to train a full OLMo 1B model with a dynamically increasing batch size and square-root-scaled learning rate.

## Method

The paper introduces a branched training method that directly measures the CBS without the strong assumptions of the noise scale approach: from a checkpoint, it launches parallel training runs at batch sizes k·B with learning rate scaled by √k (for Adam), trains each for a fixed token budget Δ, and defines B* as the largest k·B whose smoothed loss stays within ε=0.01 of all smaller batch sizes. Applying this across OLMo 1B and 7B checkpoints reveals that the CBS starts near zero, grows rapidly within the first 50k steps, then plateaus around 4096 documents, with qualitatively similar trends across model sizes. This evolution motivates a batch size warmup strategy that starts small and doubles the batch size (with √2 learning rate scaling) whenever the CBS has grown sufficiently, validated by training OLMo 1B to slightly better pretraining loss (2.5891 vs. 2.6057) with 43% fewer gradient steps than the small-batch baseline.

## Results

Batch size warmup trains OLMo 1B to a pretraining loss of 2.5891 and mid-training loss of 2.5433, outperforming the small-batch control (2.6057 / 2.5486) while using 43% fewer gradient steps. The large-batch control (fixed B=4096) achieves 75% fewer steps but degrades to 2.5962 / 2.5506 loss. On downstream BPB evaluations (ARC, MMLU, GSM8K, etc.), batch size warmup performs best on 3 of 4 conditions compared to the small-batch control, confirming no downstream degradation.

## Baselines & Comparisons

The paper's primary comparison is against the gradient noise scale estimator from McCandlish et al. (2018), which the authors show underestimates the true CBS by several orders of magnitude for both OLMo 1B and 7B, with the qualitative trend also mismatching (especially for 7B). Against the small-batch control (fixed B=1024), batch size warmup achieves a 0.0166 lower pretraining loss and 0.0053 lower mid-training loss while saving 43% of gradient steps, demonstrating that the warmup schedule safely exploits the growing CBS. Against the large-batch control (fixed B=4096), which exceeds the CBS during early training, batch size warmup clearly wins: the large-batch control degrades to 2.5962 PT loss (worse than small-batch's 2.6057 is actually better, but worse than warmup's 2.5891) and 2.5506 MT loss, confirming that naively using a large batch from the start harms performance. On downstream BPB metrics, batch size warmup matches or slightly beats the small-batch control on most tasks, while the large-batch control is consistently worst (e.g., 1.0571 vs. 1.0316 vs. 1.0112 on Task BPB after pretraining).

## Relation to Prior Work

This paper builds directly on the Critical Batch Size framework of McCandlish et al. (2018), which proposed using gradient noise scale as a proxy for CBS, and on the square-root learning rate scaling rule for Adam from Malladi et al. (2022). It departs from the noise-scale approach by arguing that the strong assumptions required to justify it (SGD optimizer, well-conditioned Hessian) are violated in practice for LM pretraining with Adam, and instead introduces a direct empirical measurement via branched training. The batch size warmup strategy is conceptually related to Smith et al. (2018) on replacing LR decay with batch size increases, but differs in that it operates on top of existing LR schedules, uses Adam-compatible scaling, and is explicitly constrained by measured CBS values rather than a fixed schedule.

## Why It Matters / Open Questions

The finding that the gradient noise scale underestimates CBS by several orders of magnitude is practically significant because this proxy was explicitly used in GPT-3 training and has inspired a line of methodological work on better noise estimation. The 43% reduction in gradient steps with slightly improved loss demonstrates a concrete efficiency gain for large-scale pretraining, and the model-size independence of CBS suggests small runs can inform large-scale decisions. Open questions include the sensitivity of CBS measurements to the window size Δ, how to systematically (rather than manually) set batch-size doubling thresholds, and whether the local recovery assumption holds in all regimes. The method is currently validated only on OLMo 1B and 7B with a single data mixture, limiting confidence in generalization to other architectures or training setups.
