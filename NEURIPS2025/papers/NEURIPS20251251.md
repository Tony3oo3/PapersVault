## Problem

Prior program synthesis approaches—whether inductive (from input-output examples) or transductive (direct LLM prediction)—struggle with robustness when training examples are scarce and test inputs contain edge cases. Although test inputs are often available at synthesis time in real-world settings (e.g., spreadsheet automation, data transformation), they have been largely ignored by existing methods. This paper formalizes transductive program synthesis, which explicitly leverages visible test inputs during synthesis to reduce epistemic uncertainty and produce more robust programs.

## Input / Output

The method takes a program specification (a natural language description plus M training input-output pairs) together with N visible test inputs, and produces both an executable program and the predicted outputs for all N test inputs. Unusually, the hypothesis space is not over programs but over N-tuples of program outputs on the test inputs, meaning the system selects among output patterns rather than among code. The number of test inputs can range from 3 to 50+, and the framework is designed so that the number of expensive LLM transduction calls grows sublinearly with N.

## Method

SYNTRA frames synthesis as active learning over a finite hypothesis class: an LLM generates K diverse candidate programs (via AGA, which first samples distinct algorithms then translates each to code), filters them against training examples, executes them on test inputs, and deduplicates the resulting output tuples to form the hypothesis class H. The system then iteratively selects a test input using a greedy maximin criterion—choosing the input whose worst-case transduction prediction eliminates the most hypotheses—and queries an LLM transduction model (with zero-shot chain-of-thought) to predict the correct output among the candidates. Inconsistent hypotheses are eliminated from the version space until a single hypothesis remains. The maximin criterion, combined with a tie-break on output length, reduces the number of LLM calls to roughly half that of random query selection while maintaining comparable accuracy, and the number of calls scales sublinearly with the test set size.

## Results

On the filtered Playgol benchmark (1 train / 4 test), SYNTRA with the maximin criterion and gpt-4.1 as the transduction model achieves 93.3% task accuracy and 96.3% example accuracy, requiring only 131 transduction calls. On MBPP+ (1 train / 10 test), the same configuration reaches 85.9% task accuracy and 95.6% example accuracy with 164 calls. On 1D-ARC (1 train / 3 test), SYNTRA achieves 71.8% task accuracy with 159 calls. The number of transduction model calls scales sub-linearly with test set size, and the maximin criterion roughly halves the extra LLM calls above the lower bound compared to random query selection.

## Baselines & Comparisons

Against LLM direct transduction (Mirchandani et al., CoRL 2023), which asks an LLM to predict each test output independently, SYNTRA with maximin wins decisively on every benchmark: 93.3% vs. 85.7% task accuracy on Playgol, 85.9% vs. 59.7% on MBPP+, and 71.8% vs. 41.9% on 1D-ARC (all with gpt-4.1). The efficiency gap is even more pronounced—SYNTRA requires 131–164 transduction calls versus 476–1490 for direct transduction, because the latter scales linearly with the number of test inputs while SYNTRA's hypothesis-elimination loop converges in a small number of queries. Against Mixture of Concepts (MoC; Lee et al., NAACL 2025), which serves as a stronger inductive synthesis model, SYNTRA acts as a complementary verification layer: MoC alone achieves 78.1% / 71.4% / 16.7% task accuracy on Playgol / MBPP+ / 1D-ARC, while MoC+SYNTRA improves these to 83.7% / 74.0% / 49.4%, demonstrating that the transductive selection step recovers correct programs that the synthesis model generated but failed to rank first.

## Relation to Prior Work

This paper carves new ground by repurposing transductive inference (Vapnik's principle) and active learning over finite version spaces into the program synthesis setting, where prior work has focused almost exclusively on inductive generalization from training examples. It combines LLM-based program generation (building on diverse-sampling strategies like AGA and MoC) with an LLM-based transduction model that acts as an oracle for pseudo-labels, connected by a greedy maximin query-selection criterion borrowed from the active learning literature. The closest prior work is LLM direct transduction [33], which predicts outputs without synthesizing programs, and inductive synthesis methods [48, 26] that ignore test inputs entirely; SYNTRA positions itself as a principled middle ground that retains the interpretability and efficiency of executable programs while leveraging the world knowledge of LLMs for disambiguation.

## Why It Matters / Open Questions

The paper addresses a practical gap in real-world program synthesis (spreadsheet automation, data transformation) where test inputs are visible but training examples are scarce, and edge cases cause inductively-synthesized programs to fail. The sublinear scaling of transduction calls with test set size and the model-agnostic framework make this approach broadly applicable, and the extension to online/human-in-the-loop settings opens a path toward interactive synthesis tools. Key limitations include the requirement for visible test inputs, reduced effectiveness on semantically meaningless inputs, and the fact that SYNTRA cannot rescue a synthesis model that simply fails to generate any correct candidate. Open questions include whether probabilistic query strategies (e.g., query-by-committee) could further reduce calls, and how the framework behaves when the realizability assumption is violated.
