## Problem

Existing GUI visual grounding methods formulate action localization as text-based coordinate generation, where models output screen positions as discrete tokens. This approach suffers from weak spatial-semantic alignment (no explicit spatial inductive bias), ambiguous supervision (single-point targets penalize valid click variations within a button), and a granularity mismatch between dense pixel-level coordinates and the coarse patch-level features produced by Vision Transformers.
![Teaser figure](../imgs/NEURIPS20250508/cropped_page1_idx1.webp)

## Input / Output

The method takes a GUI screenshot (RGB image at arbitrary resolution, processed through the VLM's vision encoder into a grid of 28×28-pixel patches) and a natural language instruction as input. Instead of generating coordinate strings, it produces a continuous attention distribution over all visual patches, yielding one or more candidate action regions in a single forward pass. A lightweight grounding verifier then scores each candidate by placing a visual marker on the screenshot and predicting whether the marked region satisfies the instruction, selecting the highest-scoring region above a confidence threshold.

## Method

GUI-Actor replaces coordinate generation with an attention-based action head anchored by a dedicated <ACTOR> token inserted into the VLM's output sequence. The final-layer hidden state of <ACTOR> is projected via an MLP and used as a query to compute softmax attention over self-attended visual patch features (also MLP-projected), producing a spatial activation map over the screen. Training uses spatial-aware multi-patch supervision: all patches partially or fully covered by the ground-truth bounding box are labeled positive, and the action head is trained with KL divergence against the normalized positive distribution, combined with standard next-token prediction loss. A lightweight grounding verifier (fine-tuned from UI-TARS-2B) is trained on 730K positive/negative examples to score candidate regions, enabling selection among top-K attention-weighted patches at inference time without additional forward passes of the main model.

## Results

On the most challenging ScreenSpot-Pro benchmark (high-resolution professional software), GUI-Actor-7B achieves 40.7 element accuracy, outperforming UI-TARS-7B (35.7), UGround-V1-7B (31.1), and Aguvis-7B (22.9). With the grounding verifier, GUI-Actor-7B+Verifier reaches 44.2, surpassing the much larger UI-TARS-72B (38.1) by 6.1 points. On the easier ScreenSpot and screenSpot-v2 benchmarks, GUI-Actor-7B scores 88.3 and 89.5 respectively, slightly trailing UI-TARS-7B (89.5 and 91.6), which the authors attribute to UI-TARS's access to proprietary training data and a more extensive multi-stage training pipeline including DPO.

## Baselines & Comparisons

GUI-Actor-7B decisively outperforms all 7B-scale coordinate-generation baselines on ScreenSpot-Pro: it beats UI-TARS-7B by +5.0 points, UGround-V1-7B by +9.6, and Aguvis-7B by +17.8. The 2B variant (36.7) also surpasses several 7B competitors, demonstrating parameter efficiency. However, on the easier screenSpot and screenSpot-v2 benchmarks, UI-TARS-7B edges out GUI-Actor-7B by 1.2 and 2.1 points respectively, which the authors concede is due to UI-TARS's larger proprietary training set and multi-stage pipeline (continual pre-training, annealing, DPO) versus GUI-Actor's single-epoch supervised fine-tuning on ~1M public screenshots. The grounding verifier provides the largest gains on ScreenSpot-Pro (+3.5 for full fine-tune, +12.9 for Lite-train), while offering only marginal improvements (+0.4 to +1.4) on the easier benchmarks where the base model is already highly accurate. Against the 72B UI-TARS-72B, GUI-Actor-7B+Verifier (44.2) wins by 6.1 points on screenSpot-Pro, though UI-TARS-72B remains competitive on screenSpot (88.4 vs 89.7) and screenSpot-v2 (90.3 vs 90.9).

## Relation to Prior Work

This paper departs from the dominant coordinate-generation paradigm for GUI visual grounding (used by Aguvis, UGround, UI-TARS, SeeClick), where models output screen positions as text tokens. Instead, it repurposes the self-attention mechanism already present in VLM backbones into a dedicated action head: a special <ACTOR> token attends over visual patch features to produce a spatial activation map, replacing numeric coordinate prediction with direct visual-region selection. The multi-patch supervision strategy (treating all patches within a bounding box as positives) and the lightweight grounding verifier (inspired by the 'verification is easier than generation' principle from math reasoning) are novel components that complement the core architectural shift.

## Why It Matters / Open Questions

The coordinate-free formulation addresses three structural weaknesses of coordinate generation—weak spatial inductive bias, ambiguous single-point supervision, and granularity mismatch between continuous coordinates and patch-level ViT features—yielding substantially better out-of-distribution generalization on high-resolution professional software (ScreenSpot-Pro). The finding that freezing the entire VLM backbone and training only ~100M action-head parameters achieves competitive grounding performance suggests that existing VLMs already encode strong UI perceptual understanding, and the bottleneck was the coordinate-mapping objective rather than visual comprehension. Open questions include whether the 28×28 patch granularity can be overcome for sub-pixel-precision tasks (e.g., CAD), whether the approach extends to non-GUI visual grounding, and how the verifier scales to multi-step action sequences.
