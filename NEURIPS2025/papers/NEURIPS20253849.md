## Problem

Existing layout-to-image (L2I) generation methods face a fundamental trade-off: training-free approaches degrade sharply on complex or dense layouts and require slow gradient-based guidance, while training-based methods introduce large parameter overheads and architectural modifications that compromise base-model quality. Additionally, prior evaluation metrics (CropVQA, SAMIoU, binary IoU thresholds) suffer from false acceptance, localization errors, and inability to capture continuous spatial precision, making fair comparison of L2I methods unreliable.

## Input / Output

The method consumes a global text prompt plus N instance-level layout conditions, where each instance specifies a normalized bounding box [x₁, y₁, w, h] ∈ [0,1]⁴ and content in one or more modalities (text description, reference image, depth map, or edge map). Generation operates at 1024×1024 resolution, and layout conditioning is applied only during the first 30% of diffusion denoising steps, after which the frozen base model refines high-frequency details. The output is a single RGB image where each instance appears at its specified spatial position with the requested semantic content.

## Method

InstanceAssemble introduces a cascaded architecture built on MMDiT backbones (SD3-Medium or Flux.1). A Layout Encoder converts each instance's bounding box into K² uniformly spaced points via DenseSample, applies Fourier embedding, and concatenates with text-encoded or VAE-encoded visual content tokens through an MLP to produce per-instance tokens. The core Assemble-MMDiT module then processes each instance independently: it crops image latent tokens to the instance's bbox, computes joint attention between the cropped image tokens and the corresponding instance token, and assembles the updated tokens across all instances using a density-weighted average (dividing by the count of overlapping instances at each spatial location). This instance-wise attention is applied in a second pass after the original MMDiT has already processed the global prompt and image latents, preserving base-model generation quality while enforcing layout alignment. The entire Assemble-MMDiT module is trained via LoRA (rank 4), adding only 71M parameters (3.46%) to SD3-Medium and 102M (0.84%) to Flux.1, with the base model kept frozen throughout training under the flow-matching objective.

## Results

On the proposed DenseLayout benchmark (5k images, 90k instances, 18.1 per image), InstanceAssemble (SD3-Medium) achieves a Layout Grounding Score mIoU of 52.07, substantially outperforming CreatiLayout (15.54), Regional-Flux (14.06), and RAG (17.23) by 3–4×. On the sparse LayoutSAM-Eval benchmark, InstanceAssemble reaches mIoU 78.88 with color/texture/shape scores of 63.89/66.27/65.86, matching InstanceDiff's spatial accuracy (78.16) while achieving significantly higher global quality (VQA 93.12 vs. 86.42). The method adds only 71M parameters (3.46%) to SD3-Medium and 102M (0.84%) to Flux.1-Dev, with a runtime increase of +88% (sparse) to +248% (dense) on SD3-M.

## Baselines & Comparisons

InstanceAssemble (SD3-Medium) dominates on DenseLayout with mIoU 52.07, beating CreatiLayout (15.54) by 3.4×, Regional-Flux (14.06) by 3.7×, and RAG (17.23) by 3.0×, while also surpassing the older UNet-based InstanceDiff (47.31) and MIGC (34.39). On the sparse LayoutSAM-Eval, InstanceAssemble (mIoU 78.88) edges out InstanceDiff (78.16) and dramatically outperforms CreatiLayout (45.82) and HICO (70.68), while maintaining superior global quality (VQA 93.12 vs. 86.42 for InstanceDiff). On COCO-Layout, InstanceAssemble (mIoU 27.85) trails InstanceDiff (30.39) slightly, which the authors attribute to InstanceDiff's fine-grained COCO training data and entity-wise generation strategy. In terms of efficiency, InstanceAssemble adds only 71M parameters (3.46%) versus CreatiLayout's 1.2B (64%) and InstanceDiff's 369M (43%), with a runtime of 7.19s (sparse) / 13.38s (dense) compared to InstanceDiff's 14.37s / 44.81s. The method also generalizes across backbones: on Flux.1-Dev it achieves mIoU 43.42 vs. Regional-Flux's 14.06 and RAG's 17.23, and works with the distilled Flux.1-Schnell (mIoU 45.33) at only 1.41s inference time.

## Relation to Prior Work

This paper builds on the MMDiT-based diffusion transformer lineage (SD3, Flux.1) and the flow-matching training framework, while drawing on GLIGEN's Fourier-embedding spatial encoding for bounding box conditioning. It departs from prior training-based L2I methods (LayoutDiffusion, InstanceDiff, CreatiLayout) that inject layout via global cross-attention or add large dedicated modules, instead proposing a per-instance cropped-region attention (Assemble-Attn) with density-weighted feature assembly, adapted via lightweight LoRA. The cascaded design—processing the global prompt through the frozen backbone before applying instance-level layout control—distinguishes it from parallel-injection approaches and from training-free methods (BoxDiff, MIGC, Regional-Flux) that rely on gradient guidance or latent manipulation.

## Why It Matters / Open Questions

The DenseLayout benchmark (5k images, 90k instances, ~18 per image) and the Layout Grounding Score metric fill a clear gap: prior L2I evaluation lacked a dense-layout stress test and suffered from known failure modes in CropVQA (false acceptance/rejection) and SAMIoU (localization errors). Practically, the method's minimal parameter overhead (3.46% on SD3-M, 0.84% on Flux.1) and demonstrated compatibility with diverse style LoRAs make it a drop-in enhancement for existing DiT pipelines. Open questions include whether the sequential per-instance Assemble-MMDiT calls can be parallelized, and whether performance can be pushed further in extremely dense or highly overlapping layouts where the current mIoU (52) remains far below the real-image upper bound (92).
