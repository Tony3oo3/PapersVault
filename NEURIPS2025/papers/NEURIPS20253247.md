## Problem

While LLMs have shown strong text-to-SQL capabilities, their ability to diagnose and fix existing faulty SQL queries—a far more complex task requiring understanding of user intent, query logic, and database state—has not been systematically benchmarked or addressed. No prior benchmark or training environment exists for SQL issue debugging, leaving open-source models without a path to acquire this capability for privacy-sensitive, local deployment scenarios.

## Input / Output

The method takes a triplet (P, S, σ_issue): a verbose natural-language problem description (mean ~163 tokens, up to ~1050), a database schema S, and the user's faulty SQL query σ_issue, and produces a corrected SQL query σ_pred. Evaluation goes beyond execution accuracy: each task carries custom Python/SQL test-case scripts that verify functional correctness, database state transitions, and constraint compliance, since DML/DDL tasks admit multiple syntactically distinct but equivalent solutions. The benchmark spans four production dialects (PostgreSQL, MySQL, SQL Server, Oracle) with 530 and 570 tasks respectively.

## Method

The paper introduces three coupled components. First, SIX-GYM is an automated training environment built on the SQL-Rewind strategy, which reverse-engineers realistic debugging scenarios by taking verified correct SQLs and systematically injecting plausible errors to produce (σ_issue, r_issue, σ*) tuples without human annotation (~3,301 instances). Second, f-Plan Boosting extracts a step-by-step symbolic functional plan F from the issue-solution pair via backward inference, then uses F to guide a teacher LLM (Gemini-2.0-Flash) through the SQL-ACT agent scaffold during forward validation, yielding 73.7% more successful trajectories than vanilla rollout at comparable cost. Third, BIRD-FIXER fine-tunes open-source backbones (7B–14B) via LoRA on these trajectories, and introduces Generative Thought Mode (GTM) at inference time, which decouples thought generation (fine-tuned model M_O) from SQL action generation (base model M_B) to prevent overfitting to training SQL patterns while preserving learned debugging logic. The SQL-ACT scaffold treats arbitrary executable SQL as the action space, in contrast to constrained tool-based agents, enabling richer debugging strategies.

## Results

On BIRD-CRITIC-PG, the best proprietary reasoning model O3-Mini achieves 38.87% Success Rate (SR), while BIRD-FIXER (Qwen-2.5-Coder-14B) reaches 38.11% SR, surpassing GPT-4.1 (37.36%) and Claude-3.7-Sonnet (32.08%). On BIRD-CRITIC-MULTI, O3-Mini leads at 33.33% SR, with BIRD-FIXER at 29.65%, still outperforming GPT-4.1 (29.12%) and Claude-3.7-Sonnet (27.89%). Reasoning-oriented models outperform general-purpose models by an average of 6.13% (PG) and 8.03% (MULTI), underscoring the reasoning-intensive nature of SQL debugging. BIRD-FIXER delivers 21–43% relative SR improvements over its base models across Llama, Qwen, and Phi families.

## Baselines & Comparisons

The paper's agent scaffold SQL-ACT is compared against TOOL-ACT, which is implemented following Spider-Agent [21] and InterCode [42]. As shown in Figure 4, SQL-ACT consistently outperforms TOOL-ACT across all evaluated models on BIRD-CRITIC-PG, demonstrating that treating arbitrary SQL commands as actions (rather than a constrained toolkit) yields a richer and more effective debugging strategy. In the broader model comparison (Table 2), BIRD-FIXER based on Qwen-2.5-Coder-14B (38.11% PG, 29.65% MULTI) surpasses Claude-3.7-Sonnet (32.08%, 27.89%) by 6.03 and 1.76 points respectively, and outperforms GPT-4.1 (37.36%, 29.12%) on both benchmarks. However, BIRD-FIXER remains slightly behind the top reasoning model O3-Mini (38.87% PG, 33.33% MULTI) by 0.76 and 3.68 points. The Spider-Agent and InterCode-based TOOL-ACT baselines serve as the primary methodological comparison for the agent design choice, while the LLM baselines in Table 2 establish the performance ceiling that BIRD-FIXER approaches with a 14B open-source model.

## Relation to Prior Work

This paper extends the ReAct/CodeAct agent paradigm (Yao et al., 2023; Wang et al., 2024) into a SQL-specific debugging scaffold (SQL-ACT) where arbitrary SQL statements serve as actions rather than constrained tool calls. It adapts the SWE-Gym training environment paradigm (Pan et al., 2024) to SQL debugging via the SQL-Rewind strategy, which inverts the debugging process by reverse-engineering issues from verified correct queries. Conceptually, the work bridges two previously disconnected literatures: text-to-SQL benchmarks (BIRD, Spider) that focus on SQL generation from natural language, and general-purpose code repair benchmarks (SWE-Bench, DebugBench) that target programming languages but not database-specific semantics. The f-Plan Boosting technique is a novel departure from standard trajectory collection, using backward inference from ground-truth solutions to guide forward rollout and substantially increase successful trajectory yield.

## Why It Matters / Open Questions

BIRD-CRITIC fills a clear gap: no prior benchmark systematically evaluates LLMs on debugging existing SQL in multi-dialect, real-world settings, and the finding that even O3-mini achieves only ~39% success rate underscores that this task is substantially harder than text-to-SQL generation. The practical impact is significant for privacy-sensitive deployments, as BIRD-FIXER (a 14B open-source model) surpasses proprietary models like Claude-3.7-Sonnet and GPT-4.1, enabling local SQL debugging without exposing proprietary schemas to cloud APIs. Open questions include whether the benchmark's moderate size (530/570 tasks) provides sufficient statistical power, whether SQL-Rewind-generated synthetic data truly captures the full distribution of real-world SQL errors, and whether the approach generalizes to dialects and database systems beyond the four tested.
