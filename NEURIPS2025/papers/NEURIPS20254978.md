## Problem

Conventional wisdom holds that small batch sizes destabilize language model training, motivating gradient accumulation and sophisticated optimizers. However, prior work that reported small-batch failures (e.g., Xiao 2024, Filatov et al. 2024) kept Adam's second-moment decay rate β₂ fixed across batch sizes, an unexamined assumption. This paper asks whether small batch sizes—down to batch size one—can train stably if hyperparameters are scaled correctly, and what the right scaling rule is.
![Teaser figure](../imgs/NEURIPS20254978/cropped_page1_idx2.webp)

## Input / Output

The method takes a text corpus (FineWeb-Edu, FineWeb, C4, or MATH), a decoder-only transformer model (30M to 4B active parameters), and a batch size spanning four orders of magnitude (1 to 4096). It produces a trained language model evaluated on validation loss, a closed-form scaling formula for β₂ (Equation 2: β₂* = β₂^(B*/B)), and practical prescriptions for batch size selection and optimizer configuration. The key unusual aspect is that the 'output' is as much a set of training recommendations and a hyperparameter scaling rule as it is a model, and the batch size itself is the primary experimental variable rather than a fixed hyperparameter.

## Method

The core technical contribution is a scaling rule for Adam's second-moment decay: instead of holding β₂ fixed across batch sizes, fix its half-life in tokens (t₂), yielding β₂* = β₂^(B*/B). This single change makes small batch sizes (including B=1) train stably and perform on par with or better than large batch sizes across model scales from 30M to 1.3B parameters. The paper further shows that at small batch sizes, vanilla SGD without momentum or weight decay becomes competitive with Adam and Adafactor, since small steps eliminate the oscillations that momentum is designed to dampen. For memory-constrained fine-tuning, combining batch size 1 with Adafactor (sublinear optimizer state) and bfloat16 weights with stochastic rounding achieves full fine-tuning performance at a memory footprint comparable to LoRA. The practical recommendation is to use the smallest batch size that maximizes model throughput (MFU) and to avoid gradient accumulation unless training on multiple devices with multiple model replicas.

## Results

Across batch sizes spanning four orders of magnitude (1 to 4096), all optimizers (SGD, Adam, Adafactor, Muon) achieve their best validation loss at the smallest batch size on a 30M-parameter model trained on 600M FineWeb-Edu tokens. At GPT-3 (1.3B) scale trained on 10B FineWeb tokens, vanilla SGD with batch size 1 and no momentum performs on par with the AdamW baseline (batch size 512, β₁=0.9, β₂=0.95, w=0.1), while Adam and Adafactor at batch size 1 both outperform that baseline. The proposed β₂ scaling rule (fixing the second-moment half-life in tokens) requires only a one-shot adjustment—e.g., β₂=0.9999 for batch size 1 versus the default 0.95—and eliminates the need for per-batch-size hyperparameter tuning. For memory-efficient fine-tuning of Gemma 3 (4B) on MATH, Adafactor with batch size 1 achieves full fine-tuning performance at a memory footprint comparable to LoRA (r=16).

## Baselines & Comparisons

Against the AdamW baseline from Brown et al. [17] (batch size 512, β₁=0.9, β₂=0.95, w=0.1), vanilla SGD at batch size 1 matches performance on GPT-3 (1.3B) with no optimizer state stored, while Adam and Adafactor at batch size 1 with scaled β₂ both outperform the baseline. Compared to Adam [25] with fixed hyperparameters, the paper shows that simply scaling β₂ to preserve the token half-life (Equation 2) closes the performance gap at small batch sizes, directly challenging Xiao [14] whose U-shaped loss curve is shown to be an artifact of not adjusting β₂. Adafactor [27] emerges as the best memory-performance tradeoff for fine-tuning: at batch size 1 it matches full fine-tuning with Adam while using sublinear optimizer state, achieving a memory footprint comparable to LoRA [77] (r=16) on Gemma 3 (4B) fine-tuned on MATH. Muon [9] performs similarly to other optimizers at small batch sizes but the gap between optimizers widens as batch size increases, confirming that sophisticated optimizers are primarily needed for large-batch training. The paper also demonstrates that the commonly recommended square-root learning rate scaling is too aggressive: empirically, the learning rate scales by only a factor of ~3 from batch size 1 to 1024, rather than the √1024 ≈ 32× predicted by the square-root rule.

## Relation to Prior Work

This paper builds on Adam's adaptive optimization framework [25] but introduces a principled scaling rule for the second-moment decay rate β₂ based on fixing its half-life in tokens rather than holding β₂ constant across batch sizes. It directly challenges and reinterprets prior findings: Xiao [14]'s U-shaped batch-size curve is shown to be an artifact of fixed β₂, Zhao et al. [19]'s conclusion that SGD lags behind adaptive optimizers is shown to hold only at large batch sizes, and the critical batch size literature [41, 34] is extended to the extreme of batch size one. The memory-efficient fine-tuning angle builds on Adafactor [27] and LoRA [77], combining them with the small-batch insight to achieve full fine-tuning performance at LoRA-like memory cost.

## Why It Matters / Open Questions

The practical impact is significant: the paper provides a concrete, one-shot β₂ scaling rule (Equation 2) that generalizes across model scales from 30M to 1.3B parameters, and recommends against gradient accumulation for most practitioners, which could simplify training pipelines and reduce memory overhead. The finding that Adafactor with batch size 1 achieves full fine-tuning performance at LoRA-like memory footprint opens a path for memory-constrained practitioners to avoid the quality gap of parameter-efficient methods. Open questions remain about interaction with batch size schedules, further precision reduction (8-bit, 4-bit), and a theoretical explanation for why token-half-life scaling generalizes. A limitation is that the exhaustive grid search was only feasible at 30M parameters; larger-scale experiments used fewer hyperparameter configurations.
