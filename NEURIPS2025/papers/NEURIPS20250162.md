## Problem

Existing LLM caching techniques face a fundamental trade-off for structurally similar prompts: exact matching produces cache misses on minor variations, while semantic caching returns incorrect responses by ignoring critical differences. In repetitive agentic workflows where prompts share a consistent format but vary in key parameters (e.g., item names, regions), neither approach adequately balances cache hit rate with response correctness.

## Input / Output

GenCache consumes the final prompt constructed by an agent (system message + user instruction) and produces a structured response (typically a JSON action dict for ReAct-style agents). On cache generation, it additionally outputs a cached Python program (~5 KB) that encodes the prompt-to-response mapping pattern. The program uses regex to extract variable keywords from new prompts and constructs the response locally, requiring no LLM call at inference time. Prompts must exhibit structured regularity, controlled variability, and predictable response patterns to be cacheable.

## Method

GenCache performs online embedding-based clustering of prompt-response pairs using both prompt and response embeddings (SentenceTransformer + FAISS), assigning new prompts to clusters only when both similarity scores exceed thresholds. For each cluster with sufficient exemplars (ν), an LLM (CodeGenLLM) is prompted via in-context learning to synthesize a Python program that captures the consistent mapping pattern, using regex with synonym groups to extract variable parts and construct the response template. A separate LLM (ValidLLM) validates the generated program against all cluster exemplars, and if fewer than γ responses match, reflection-based retries are triggered. At runtime, a new prompt is matched to the nearest cluster, validated against a stored regex pattern, and the cached program is executed via a Python interpreter to produce a variation-aware response in ~0.176s versus ~3.5s for an LLM call.

## Results

On the Param-Only synthetic dataset, GenCache achieves a 97.81% cache hit rate with 98.03% positive (correct) hits, while GPTCache achieves 90.92% hit rate but 100% negative hits, and ExactCache achieves 0% hit rate. On the more challenging Param-w-Synonym dataset, GenCache maintains an 83.66% hit rate with 92.16% positive hits. In agentic workflows, GenCache improves overall cache hit rate by ~20% (54.7% vs. 34.4% for FLASH; 37.2% vs. 5.7% for Laser) and reduces end-to-end execution latency by ~25–34% compared to ExactCache alone.

## Baselines & Comparisons

The paper compares GenCache against two baselines: ExactCache (hash-based exact prompt matching) and GPTCache (embedding-similarity-based semantic caching). ExactCache achieves 0% hit rate on both synthetic datasets because no prompts are repeated verbatim, making it useless for structurally similar but non-identical prompts. GPTCache achieves a high nominal hit rate (~90%) but every single hit is a negative hit (100% incorrect), because it returns the stored response verbatim even though the prompt parameters differ. GenCache dominates on both hit rate and correctness: it achieves 97.81% hit rate with 98.03% positive hits on Param-Only (vs. GPTCache's 0% positive hits) and 83.66% hit rate with 92.16% positive hits on Param-w-Synonym. The GenCache-feedback variant trades some hit rate for near-zero negative hits (0.37% on Param-Only, 4.4% on Param-w-Synonym), demonstrating adaptability when downstream agents can signal errors. In agentic workflows, GenCache+ExactCache outperforms ExactCache alone by 23 percentage points in cache hit rate for FLASH (54.7% vs. 34.4%) and by 31.5 percentage points for Laser (37.2% vs. 5.7%), while reducing execution time by ~25% for FLASH.

## Relation to Prior Work

GenCache repurposes the program-synthesis paradigm from PAL [19] and Program-of-Thoughts [16]—where LLMs generate executable code from in-context examples—into a caching mechanism, storing programs rather than static responses. It explicitly positions itself between exact prompt matching (which misses structurally similar prompts) and semantic caching like GPTCache (which returns incorrect verbatim responses for similar-but-different prompts), identifying a gap where neither approach handles the 'structured regularity + controlled variability' regime. Unlike KV-cache/prompt-prefix matching techniques that optimize low-level decoding, GenCache operates at the application level to eliminate LLM calls entirely for a class of repetitive agentic tasks.

## Why It Matters / Open Questions

The paper addresses a practical and increasingly common failure mode in agentic LLM deployments: structurally similar prompts with minor parameter variations that defeat both exact and semantic caching. The 83%+ hit rate with <8% negative hits, and ~34% end-to-end latency reduction in real agent workflows, make this a deployable optimization for SRE, web-navigation, and e-commerce agents. Key limitations remain: GenCache requires predictable response structure, targets only reversible actions, and can fail when branching complexity exceeds available exemplars. Open questions include extending to structurally diverse prompts, non-reversible workflows, and adaptive program modification as new branches emerge.
