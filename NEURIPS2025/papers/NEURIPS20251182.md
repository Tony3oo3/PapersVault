## Problem

Existing Chain-of-Thought prompting for mathematical reasoning suffers from unverifiability (natural language steps cannot be executed to catch errors), limited scalability (high-quality CoT data requires costly manual annotation), and insufficient diversity in reasoning paths. Prior code-assisted approaches partially address verifiability but remain constrained to predefined problem types, hindering generalization. The paper asks whether a fully automated, code-anchored pipeline can synthesize millions of high-quality, diverse, and verifiable instruction-CoT reasoning traces without human intervention.

## Input / Output

The pipeline consumes raw mathematical problems (from MATH, DeepScaleR, BigMath) and algorithmic problems (from Kodcode), converting each solution into a unified Python template that encodes inputs as a dictionary, defines solving logic via explicit function calls, and prints a final answer. The intermediate Code CoT representation is used exclusively for generation and verification; the final Caco-1.3M dataset outputs natural language instruction (problem) paired with a step-by-step language CoT solution ending in a boxed answer. The code itself is discarded after filtering and does not appear in the training data.

## Method

Caco operates as a three-stage closed-loop pipeline. First, it unifies 146K seed Code CoTs from math and algorithmic sources into a standardized Python format, retaining only execution-verified traces. Second, it fine-tunes an unconditional code generation model (CodeGen, initialized from Qwen2.5-Coder-7B) on these seeds using only the code traces without problem context, then samples 5.3M new Code CoTs via temperature-based decoding to explore both problem-level (surface rephrasing) and pattern-level (novel reasoning structures) augmentation, filtering down to 4.6M executable programs. Third, it performs two-stage instruction reversal: an LLM first back-translates each code snippet into a natural language problem, then separately generates a language CoT for that problem, with dual verification (answer consistency via code execution and CoT consistency via LLM judgment) retaining only aligned tuples. This yields 1.3M validated instruction-answer pairs that are used for supervised fine-tuning of downstream reasoning models.

## Results

On Qwen2.5-Math-7B, Caco-1.3M achieves 92.6% on GSM8K, 82.4% on MATH, and a 67.7% average across six mathematical benchmarks, surpassing the instruction-tuned Qwen2.5-Math-7B-Instruct (63.6% avg) by 4.1 points. On the general-purpose LLaMA3-8B, Caco-1.3M reaches 57.3% average, a 44.3% relative improvement over the best baseline DartMath (39.7%). On DeepSeekMath-7B, Caco-1.3M attains 57.1% average, outperforming the RL-based DeepSeekMath-7B-RL (47.1%) by 10 points. Performance scales consistently with data size: Caco-596K already exceeds all baselines, and Caco-1.3M adds further gains of 1.1–2.6 points over Caco-596K.

## Baselines & Comparisons

Caco-1.3M outperforms all six data-centric baselines (MetaMath, MMIQC, NuminaMath, MathFusion, RFT, DartMath) across all three base models. On LLaMA3-8B, Caco-1.3M (57.3% avg) beats the strongest baseline DartMath (39.7%) by 17.6 points and MathFusion (39.0%) by 18.3 points; on DeepSeekMath-7B, it surpasses DartMath (49.4%) by 7.7 points. Caco also exceeds the instruction-tuned and RL-based reference models: on Qwen2.5-Math-7B, Caco-1.3M (67.7%) surpasses Qwen2.5-Math-7B-Instruct (63.6%) by 4.1 points; on DeepSeekMath-7B, it beats DeepSeekMath-7B-RL (47.1%) by 10.0 points; on LLaMA3-8B, it exceeds LLaMA3-8B-Instruct (33.1%) by 24.2 points. The gains are most pronounced on harder benchmarks—OlympiadBench and TheoremQA—where Caco-1.3M on LLaMA3-8B scores 34.1 and 31.0 respectively, versus 17.2 and 20.0 for MathFusion. A control experiment (Table 4) further shows that at matched 300K size, Caco outperforms both direct teacher distillation (Qwen72B-Seed-Distilled: 65.5 vs. 66.2 on Qwen-7B) and STaR-style self-improvement (52.6 vs. 66.2), confirming that the code-driven diversity mechanism, not merely teacher knowledge transfer, drives the gains.

## Relation to Prior Work

Caco sits at the intersection of two active research threads: code-assisted reasoning (PoT, PAL, rStar-Math, MathCoder, MathGenie) and synthetic data augmentation for mathematical instruction tuning (MetaMath, DART-Math, MathFusion, NuminaMath). It departs from prior code-integrated methods by treating code not merely as a verification tool for existing problems but as an unconditional generation medium—training a dedicated CodeGen model to produce novel reasoning programs from scratch, then back-translating them into natural language instructions. This contrasts with rStar-Math (which pairs NL rationales with code for fixed problems) and MathGenie (which augments solutions and back-translates questions), by introducing pattern-level augmentation where the code generator explores new logical structures beyond the seed templates. The two-stage QA generation and dual verification (answer consistency + CoT consistency) further distinguish Caco from single-step generation pipelines that suffer from 'lazy mode' degradation.

## Why It Matters / Open Questions

Caco provides a fully automated, scalable pipeline for producing verifiable reasoning training data without human annotation, yielding the Caco-1.3M dataset that enables 7B models to match or exceed official instruction-tuned counterparts (e.g., 67.7 vs. 63.6 on Qwen2.5-Math-7B). The cross-domain generalization—particularly the large HumanEval+ gain (12.8→53.1 on Qwen)—suggests code-anchored reasoning data transfers to non-mathematical tasks, opening a path toward unified reasoning training. Key limitations include dependence on predefined problem templates (constraining coverage of novel problem types), potential information loss in code-to-NL conversion, and the fact that generated code serves only as a filter rather than a training signal. Open questions include whether the pipeline scales to harder corpora (Olympiad-level, formal proofs), whether integrating code directly into training (beyond filtering) yields further gains, and how Caco interacts with RL-based training using execution-derived rewards.
