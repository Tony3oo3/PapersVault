## Problem

State-of-the-art code LLMs exhibit a significant performance gap between high-resource languages (Python, C++) and less common ones, limiting their universal applicability. Existing RL-based training relies on coarse-grained binary rewards from unit tests that lack process-level supervision, and standard preference optimization (e.g., DPO) treats code responses as pairwise comparisons, failing to capture the fact that multiple distinct implementations can be functionally equivalent.
![Teaser figure](../imgs/NEURIPS20251582/cropped_page2_idx0.webp)

## Input / Output

For the on-policy RL component, the model receives a source code snippet in one language (Python or C++) along with a target language specification and must generate the translated code, which is scored by a binary reward based on compilation and unit-test passage. For the GEPO component, the model receives high-level source code and must produce LLVM IR; training groups consist of n equivalent IRs (generated at different optimization levels like -Oz, -O3) as winners and m augmented inequivalent IRs as losers, with the model learning to distinguish and rank these groups.

## Method

OORL integrates on-policy RL (REINFORCE++ with a binary unit-test reward for code translation) with a novel off-policy preference optimization called GEPO. GEPO extends DPO from pairwise to group-level comparisons over LLVM IRs: its loss has two terms — a sigmoid preference term that pushes the average log-probability ratio of the winner IR group above that of the loser group, and a variance regularization term (weighted by λ) that penalizes dispersion among winner IRs, explicitly enforcing that all equivalent IRs receive similar implicit reward scores. The combined objective L = w_rl·L_OnP + w_gepo·L_GEPO (with w_rl=1, w_gepo=0.01) is optimized on Qwen3-8B using 2400 code translation problems and 9600 C-to-IR groups, enabling the model to learn fine-grained functional equivalence across languages through the language-agnostic IR representation.

## Results

On the MultiPL-E benchmark (pass@1), Qwen3-8B-OORL achieves an average score of 76.31 across eight programming languages, outperforming Qwen2.5-Coder-7B-Inst (68.71), Qwen3-8B (65.07), and DS-Coder-V2-Lite-Inst (60.06). On the CrossPLEval code translation benchmark, Qwen3-8B-OORL achieves the highest average scores across all four source languages (Python→: 52.99, C++→: 67.52, Java→: 66.76, Go→: 65.33), with particularly large gains on low-resource target languages such as Haskell (28.48 vs. 15.13 for Qwen3-8B) and Bash (35.29 vs. 24.36).

## Baselines & Comparisons

Qwen3-8B-OORL consistently outperforms all three baselines on both benchmarks. On MultiPL-E, it surpasses Qwen2.5-Coder-7B-Inst by 7.60 points (76.31 vs. 68.71), Qwen3-8B by 11.24 points (76.31 vs. 65.07), and DS-Coder-V2-Lite-Inst by 16.25 points (76.31 vs. 60.06), winning on every individual language. On CrossPLEval, the gains are even more pronounced for low-resource targets: translating Python→Haskell, Qwen3-8B-OORL scores 28.48 versus 15.13 (Qwen3-8B) and 11.76 (DS-Coder-V2-Lite-Inst); for Python→Bash it reaches 35.29 versus 24.36 and 27.73 respectively. Notably, Qwen3-8B-OORL also outperforms the stronger Qwen3-8B base model on CrossPLEval by 12.39 points on average (Python→ source), confirming that the OORL training framework adds substantial value beyond the base model's capabilities.

## Relation to Prior Work

This paper extends DPO's pairwise preference framework into a group-based formulation (GEPO) that explicitly models functional equivalence among multiple valid responses, and combines it with on-policy RL (REINFORCE++) using binary unit-test rewards for code translation. Conceptually, it departs from prior IR-based code understanding work (IRCoder, Transcoder-IR, LLM Compiler) that uses LLVM IR as a translation pivot or pre-training corpus; here, IRs serve as the *preference signal* in an off-policy optimization step, where groups of equivalent IRs (from different compiler optimization levels) and augmented inequivalent IRs form the training signal. The on-policy RL component follows the recent line of rule-reward RL for code (DeepSeek-R1, Kimi L1.5), but applies it specifically to cross-language translation rather than single-language generation.

## Why It Matters / Open Questions

The paper addresses a practically important gap—LLMs perform well in Python/C++ but degrade sharply in less common languages—and shows that RL-based code translation training can close this gap, including for untrained languages like Haskell and Scala. The GEPO formulation (group preference with an intra-group variance penalty) is a clean, generalizable idea that could extend to any domain where multiple functionally equivalent solutions exist. However, the evidence is limited to a single 8B model with no error bars, and the memory overhead of group-based processing may limit scalability to larger models or longer sequences. Open questions include whether the IR-based preference signal generalizes beyond C/LLVM to other IR ecosystems, and whether the approach transfers to tasks beyond code translation.
