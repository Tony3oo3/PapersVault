## Problem

Existing MLLM serving systems use tightly coupled architectures that treat text-only and multimodal requests identically, colocate all inference stages (encoding, prefill, decode) on the same hardware, and apply a uniform parallelism strategy. This coupling causes severe resource contention, sharply increased time-to-first-token under multimodal workloads, and poor GPU utilization, particularly for encoder-decoder models with cross-attention layers that are ill-suited for mixed-batch processing.

## Input / Output

The system accepts either text-only prompts or image-plus-text prompts, where images are resized and tiled (e.g., 904×904 pixels yielding ~6,500–7,400 vision tokens depending on the encoder) before being concatenated with text tokens for the LLM backend. It supports both decoder-only (e.g., Qwen2.5-VL) and encoder-decoder (e.g., LLaMA3.2-Vision) MLLM architectures, and produces standard autoregressive text responses. The serving system is built on the OpenAI API format, so client-side request structure is unchanged from vLLM.

## Method

ElasticMM introduces Elastic Multimodal Parallelism (EMP), a two-level hierarchical scheduling framework. At the modality level, a modality-aware load balancer partitions requests into text-only and multimodal groups and dynamically reallocates GPU instances between them using a proactive greedy allocation (maximizing minimum burst tolerance) combined with reactive inter-group preemption for sudden traffic spikes. At the stage level, elastic partition scheduling decouples encoding, prefill, and decode onto independently scalable instance pools, adjusting data-parallelism degree per stage via a gain-cost model that weighs prefill speedup against KV-cache migration overhead and decode latency impact. Two MLLM-specific optimizations further reduce overhead: a unified multimodal prefix cache that stores both encoded visual tokens and KV-cache prefixes to skip redundant encoding and prefill, and non-blocking encoding that executes the vision encoder asynchronously on a separate instance to eliminate its blocking effect on the prefill pipeline.

## Results

On the ShareGPT-4o dataset, ElasticMM reduces time-to-first-token (TTFT) by up to 4.2× (Qwen2.5-VL-7B, decoder-only) and 3.5× (LLaMA3.2-Vision-11B, encoder-decoder) compared to vLLM, with corresponding reductions of 3.7× and 2.9× on VisualWebInstruct. In terms of maximum throughput under SLO constraints, ElasticMM achieves up to 4.5× and 3.2× higher throughput than vLLM on Qwen2.5-VL and LLaMA3.2-Vision respectively, and up to 2.3× higher than DistServe. The ablation study confirms that Elastic Multimodal Parallelism (EMP) alone contributes 1.8× (Qwen-2.5-VL) and 2.3× (Llama-3.2-Vision) throughput gains over static resource allocation strategies.

## Baselines & Comparisons

ElasticMM is compared against two baselines: vLLM (v0.6.6), a tightly coupled SOTA serving system where all inference stages execute on the same hardware, and DistServe, a decoupled architecture that separates prefill from decode but uses static resource allocation. Against vLLM, ElasticMM consistently achieves the lowest input and output latency across all request rates on both datasets, with TTFT reductions of up to 4.2× and throughput improvements of up to 4.5×. Against DistServe, ElasticMM also wins on both latency and throughput (up to 2.3× higher throughput), benefiting from its hierarchical elastic scheduling and non-blocking encoding, whereas DistServe's static allocation leads to underutilized resources and memory contention at higher request rates. The paper notes that gains are larger for decoder-only models (Qwen2.5-VL) due to heavier prefill computation that exacerbates conflicts with image encoding in coupled systems, and larger on the visually intensive ShareGPT-4o dataset, validating the multimodal-specific optimizations.

## Relation to Prior Work

This paper extends the disaggregated LLM serving line (DistServe, Splitwise, LoongServe) to the multimodal setting by introducing a two-level hierarchy: modality-level separation (text-only vs. multimodal request groups) and stage-level disaggregation (encoding, prefill, decode). It builds directly on vLLM's PagedAttention for KV cache management and adapts LoongServe's elastic sequence parallelism and gain-cost preemption model, but departs from prior MLLM serving work (ModServe, EPD disaggregation) by fully isolating modality groups rather than merely separating inference stages while still batching heterogeneous requests together. The key conceptual departure is treating modality heterogeneity as a first-class scheduling dimension alongside stage heterogeneity, enabling independent elastic scaling at both levels.

## Why It Matters / Open Questions

As MLLMs become the dominant interface for production AI services, the 4.2× TTFT reduction and 3.2–4.5× throughput gains over vLLM address a practical bottleneck that will only worsen as models grow and multimodal traffic increases. The elastic paradigm—dynamically reallocating GPUs across modality groups and inference stages based on real-time load—offers a generalizable framework for any heterogeneous serving workload. Key limitations include evaluation restricted to a single 8×A800 node (multi-node communication and broader parallelism search spaces are deferred), and the baselines (vLLM without multimodal-specific tuning) may understate the gap versus a well-optimized coupled system. Open questions include whether the gain-cost preemption model generalizes to video/audio modalities with even more variable encoding costs, and how the system behaves under sustained (non-bursty) multimodal traffic.
