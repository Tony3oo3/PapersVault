## Problem

Existing LLM-based agents treat each task independently, lacking a mechanism to reuse experience from historically completed tasks. Trajectory-based reuse is overly specific and brittle to context changes, while guideline-based reuse is too coarse to capture critical procedural structure. This paper addresses the gap by proposing a hierarchical representation that balances reusable concrete steps with task-adaptive dynamic execution.

## Input / Output

At inference, the system takes a new user task query and retrieves the most appropriate MetaFlow node from a pre-built hierarchical experience tree via deep matching traversal; tool documentation is available to the dynamic agent sub-steps. The MetaFlowGen (the offline training component) takes pairs of (task, MetaFlow) samples plus tool documentation and outputs a generalized MetaFlow—a sequence of static executable steps (tool calls, code) interleaved with dynamic subtask descriptions—along with a meta task description. At execution time, static steps run directly while dynamic steps are delegated to an LLM agent (ReAct or Reflexion) that operates over a shared mutable context, ultimately producing the completed task result.

## Method

MetaFlowLLM constructs a hierarchical experience tree where each node is a MetaFlow: a hybrid sequence of static procedural steps (directly executable tool calls or code) and dynamic agent steps (subtask descriptions solved by an LLM agent). The tree is built offline via a Hierarchical MetaFlow Merging algorithm that iteratively pairs the most semantically similar nodes (cosine similarity of all-MiniLM-L6-v2 task embeddings), generates a candidate parent MetaFlow using a trained MetaFlowGen, and prunes merges whose correctness reward falls below a threshold. The MetaFlowGen itself is trained in two stages: supervised fine-tuning on a rejection-sampled cold-start dataset, followed by GRPO-based reinforcement learning optimized with a composite reward combining correctness (fraction of child leaf nodes solved correctly) and efficiency (ratio of preserved static operations to the minimum of the two input workflows). At inference, a discriminative model performs deep matching traversal from the tree root to find the deepest node whose meta task and MetaFlow match the query, then executes the MetaFlow sequentially—running static steps verbatim and spawning an LLM agent for each dynamic step.

## Results

On AppWorld, MetaFlowLLM achieves an average TGC rate improvement of 32.3% over base agents, with the best configuration (Qwen2.5-32B + ReAct) reaching 50.9% TGC versus 22.2% base. On WorkBench, MetaFlowLLM yields an average accuracy improvement of 6.16% and a 4.13% reduction in side effects. The method also reduces LLM API calls and tool calls, with inference time increasing only ~9% over vanilla ReAct while substantially improving accuracy.

## Baselines & Comparisons

The paper compares MetaFlowLLM against three baselines: no experience reuse (Base), trajectory-based experience (Traj.), and guideline-based experience (Guideline). On AppWorld, MetaFlow consistently outperforms both Traj. and Guideline across all six model-agent combinations; for example, Qwen2.5-7B + ReAct improves from 6.4% (Base) to 43.9% (MetaFlow) vs. 37.4% (Traj.) and 17.0% (Guideline). On WorkBench, MetaFlow also leads: with GPT-4o-mini it achieves 26.1% average accuracy vs. 19.9% (Traj.) and 21.9% (Guideline), while simultaneously reducing side effects from 43.0% to 33.6%. The guideline-based method underperforms trajectory-based on AppWorld (e.g., 17.0% vs. 37.4% for Qwen2.5-7B ReAct), confirming that coarse natural-language summaries lack the procedural precision needed for complex multi-step tasks. MetaFlow's advantage grows with model capacity: Qwen2.5-32B gains 9.1% accuracy on WorkBench with MetaFlow, while Qwen2.5-7B gains only 2.9%, suggesting weaker models struggle to discriminate and execute MetaFlow subtasks.

## Relation to Prior Work

This paper positions itself as a third paradigm for experience reuse in LLM agents, departing from both trajectory-based methods (Synapse, AWM) that overfit to specific execution paths and guideline-based methods (AutoGuide, ExpeL) that lack procedural precision. Conceptually, it draws on hierarchical clustering to organize a tree of hybrid static/dynamic workflows (MetaFlows), and on RL with verifiable rewards (GRPO, following DeepSeekMath/DeepSeek-R1) to train a dedicated 7B MetaFlow generator. The closest prior work is AWM, which also extracts reusable workflows from trajectories, but MetaFlowLLM differs by explicitly modeling workflows as structured graphs with typed nodes and optimizing their granularity through RL rather than relying on prompt-based LLM reasoning.

## Why It Matters / Open Questions

The framework offers a principled way to balance specificity and generality in agent experience reuse, with the hierarchical tree naturally encoding 'how much to reuse vs. how much to plan dynamically.' The 32.3% TGC improvement on AppWorld and the finding that a specialized 7B MetaFlowGen outperforms GPT-4o and DeepSeek-R1 on workflow generation are practically significant. Key limitations include the dependence on offline completed-task data and verifiable rewards (restricting applicability to open-ended tasks), and the observation that weaker LLMs gain less benefit due to insufficient discriminative and instruction-following capability. Open questions include extension to multimodal settings, online tree updates, and reward design for tasks without ground-truth verification.
