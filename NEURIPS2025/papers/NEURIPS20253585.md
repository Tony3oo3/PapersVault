## Problem

Existing code benchmarks (HumanEval, SWE-bench, LiveCodeBench) evaluate LMs on tasks with binary outcomes that humans have already solved, leaving open whether LMs can go beyond state-of-the-art human performance. AlgoTune addresses this by posing an open-ended optimization problem: can an LM make widely-used numerical library code (NumPy, SciPy, NetworkX, CVXPY) faster, with no upper bound on achievable speedup?
![Teaser figure](../imgs/NEURIPS20253585/cropped_page1_idx0.webp)

## Input / Output

Each task provides a reference Python solver (typically a thin wrapper around a library function), an input generator parameterized by problem size n, and a boolean solution verifier. The agent receives the solver code, verifier, and task description, and must produce an optimized solve() function. Scoring is the ratio of reference runtime to LM runtime on held-out test inputs, aggregated as a harmonic mean across all 154 tasks; solutions that are incorrect or slower than the reference receive a floor score of 1×. The agent operates under a fixed $1 API budget per task, with up to 2 minutes of compilation time excluded from runtime measurements.

## Method

AlgoTuner is a SWE-Agent-style iterative loop in which a frontier LM (o4-mini, R1, Gemini 2.5 Pro, or Claude Opus 4) interacts with a computer environment via a ReAct-style command interface (edit, eval, profile, reference, revert, etc.). At each step the LM proposes a code edit; the system lints, runs the code on 100 development instances, reports correctness and timing, and saves the best-performing version. The agent can leverage Numba JIT compilation, Cython, Dask, and BLAS-level operations, and can profile hotspots to guide further edits. The loop continues until the $1 budget is exhausted, at which point the best development-set code is evaluated on held-out test inputs. The benchmark itself comprises 154 tasks across 13 categories (matrix operations, convex optimization, differential equations, cryptography, etc.), each validated for monotonic runtime scaling with n and verifier robustness across random seeds.

## Results

AlgoTuner, paired with frontier LMs, achieves an average 1.72× harmonic-mean speedup over reference solvers (using SciPy, NumPy, NetworkX, CVXPY, etc.) on the 154-task AlgoTune benchmark, with o4-mini-high scoring highest. R1 follows closely at 1.70×, Gemini 2.5 Pro at 1.51×, and Claude Opus 4 at 1.33×. In terms of task coverage, R1 achieves a speedup of at least 1.1× on 61.0% of tasks, o4-mini on 59.7%, Gemini 2.5 Pro on 49.4%, and Claude Opus 4 on 40.3%. The paper emphasizes that all observed speedups are surface-level optimizations (e.g., Numba JIT compilation, BLAS calls, replacing high-level library calls with specialized solvers) rather than novel algorithmic discoveries.

## Baselines & Comparisons

The paper evaluates four frontier LMs as backends for the AlgoTuner agent on the same 154-task benchmark. o4-mini-high (1.72×) and DeepSeek R1 (1.70×) are nearly tied in overall harmonic-mean speedup, with R1 slightly ahead in the percentage of tasks sped up (61.0% vs. 59.7%). Both substantially outperform Gemini 2.5 Pro (1.51×) and Claude Opus 4 (1.33×), which trail by 0.2× and 0.4× respectively. Notably, o4-mini and R1 reach scores after spending only $0.1 per task that exceed what Claude Opus 4 and Gemini 2.5 Pro achieve after the full $1 budget. Across all four LMs, no model discovered a novel algorithmic improvement; the best individual task speedups (e.g., 3084× on ode_seirs with o4-mini, 865× on lp_mdp) come from replacing high-level Python/SciPy calls with Numba-compiled or BLAS-based implementations rather than from new algorithms.

## Relation to Prior Work

AlgoTune builds on the SWE-Agent agent-computer interface paradigm (Yang et al., 2024) but repurposes it for code optimization rather than bug fixing. It departs from prior code-generation benchmarks (HumanEval, MBPP, LiveCodeBench) that score binary correctness on previously-solved problems, and from code-efficiency benchmarks (Shypula et al., 2023; Qiu et al., 2024; Huang et al., 2024) that target LeetCode-style functions, by instead challenging LMs to beat already-optimized reference implementations from popular libraries (NumPy, SciPy, NetworkX, CVXPY) across 154 diverse numerical and scientific tasks with a continuous speedup metric. The superoptimization lineage (Massalin, 1987) and concurrent GPU-kernel work (KernelBench, Ouyang et al., 2025) provide conceptual context, but AlgoTune is the first to span this breadth of domains with library-level reference solvers.

## Why It Matters / Open Questions

The benchmark's practical stakes are high: speedups found here could directly translate to performance gains in NumPy, SciPy, and NetworkX, which underpin a large fraction of scientific computing. The key negative finding—that even frontier models (o4-mini, R1, Gemini 2.5 Pro, Claude Opus 4) achieve only 1.33×–1.72× speedups via surface-level techniques (Numba JIT, BLAS calls, better library usage) and never discover novel algorithms—sets a clear bar for future work. Open questions include whether larger or differently-trained models can cross the algorithmic-innovation threshold, whether the benchmark extends naturally to GPU/TPU and distributed settings, and whether formal verification can close the remaining verifier-completeness gaps that currently allow reward-hacking.
