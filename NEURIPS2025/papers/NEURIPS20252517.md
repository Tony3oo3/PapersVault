## Problem

Practical linguistic steganography systems are bottlenecked by low payload: the low entropy of token probability distributions forces stego texts to be far longer than the secret messages, increasing suspicion from adversaries. Prior work has focused almost exclusively on optimizing the embedding phase (e.g., iterative sampling, distribution optimization) while neglecting the message processing phase—specifically, how to compress and prune the secret message before it is embedded. This paper identifies that LLM-driven semantic redundancy elimination and index-based compression of the secret message itself is an underexploited lever for payload enhancement.

## Input / Output

The sender provides a natural-language secret message and a short text-generation prompt (two sentences sampled from WikiText-2) that seeds the stego text generation. The secret message is first semantically pruned and then compressed into a pseudo-random bit stream, which is embedded into an LLM-generated stego text via Discop or SparSamp. The receiver extracts the bit stream, reverses Huffman decoding and rank-to-token mapping, and uses a shared fine-tuned restorer model to losslessly reconstruct the original secret message, achieving Rouge-1 and BERTScore of 1.0000 on the restored output.

## Method

StegoZip comprises two LLM-driven components. Dynamic Semantic Redundancy Pruning (DSRP) computes per-lexical-unit self-information (negative log conditional probability from the LLM), prunes units below a dynamically adjusted α-quantile threshold (scaled by an adaptive coefficient η that accounts for the message's entropy relative to a reference corpus), and preserves critical entities via detection; a self-checking step with the restorer flags any unrecoverable segments for bracketed retention. Index-Based Compression Coding (ICC), inspired by LLMzip, assigns each surviving token a rank by sorting the vocabulary in descending conditional probability, converts the rank sequence to bits via Huffman encoding, and XORs the result with a ChaCha20 keystream to produce a pseudo-random bit stream for steganographic embedding. A shared restorer R (a small LLM fine-tuned via instruction tuning on pruned-to-original text pairs) is used by both sender and receiver to losslessly expand the pruned message back to its full semantic form, with the fine-tuning template instructing the model to fill only bracketed gaps without altering existing content. The pseudo-randomization step ensures the embedded bit stream is indistinguishable from uniform random bits, preserving the provable security of the underlying steganographic algorithm.

## Results

StegoZip achieves a 2.5× payload improvement over baselines across all tested configurations. For example, with Qwen2.5-7B on AGNews, Discop's payload increases from 18.91% to 45.23% (+26.32 pp), and SparSamp's from 19.03% to 44.49% (+25.46 pp). On the longer IMDb dataset, gains are even larger: Discop reaches 49.64% and SparSamp reaches 49.74% payload. Processing time remains comparable or slightly reduced (e.g., encoding time drops from 14.82 s to 12.94 s for Discop on AGNews), and steganalysis accuracy stays near 50%, confirming maintained security.

## Baselines & Comparisons

The paper compares two SOTA provably secure generative steganographic methods—Discop (IEEE S&P 2023) and SparSamp (2025)—both with and without the StegoZip message-processing framework. StegoZip consistently wins on payload across every model–dataset–steganography combination: it lifts Discop's payload by 25–31 percentage points and SparSamp's by 25–31 percentage points, roughly doubling the effective capacity (≈2.5×). On processing time, StegoZip is comparable or slightly faster for Discop (e.g., 14.82 s → 12.94 s encoding on AGNews) but marginally slower for SparSamp (e.g., 10.55 s → 11.23 s), a difference the authors attribute to the reduced bitstream length offsetting the added LLM inference. Security is preserved: steganalysis accuracy with StegoZip remains within 1–3 pp of the 50% random-guess baseline, matching the underlying algorithms' provable security guarantees. The ablation (Table 5) further confirms that both DSRP and ICC contribute substantially—removing either drops payload by 10–22 pp relative to the full StegoZip pipeline.

## Relation to Prior Work

StegoZip positions itself as a complementary preprocessing layer for existing provably secure generative steganographic systems (Discop, SparSamp), which prior work has optimized primarily at the embedding stage through iterative sampling or distribution optimization. Its Index-Based Compression Coding component directly extends the rank-based token compression idea from LLMzip [29], while its Dynamic Semantic Redundancy Pruning introduces a self-information-driven pruning mechanism grounded in Shannon's information theory. The key conceptual departure is shifting the optimization target from 'how to embed bits more efficiently' to 'how to reduce the number of bits that need embedding in the first place,' leveraging LLMs for semantic understanding rather than merely as a sampling oracle.

## Why It Matters / Open Questions

By reducing the stego text length needed per secret message by roughly 2.5×, StegoZip directly addresses a practical covertness concern: fewer or shorter transmissions lower the behavioral footprint that adversaries can flag. The framework preserves the provable security guarantees of the underlying steganographic algorithm (formally proven via reduction to CSPRNG indistinguishability), which is important for deployment in high-stakes covert communication. However, the reliance on 7B–8B parameter LLMs for both compression and restoration limits applicability in resource-constrained or latency-sensitive settings, and the cross-domain payload degradation (Table 4) suggests that domain-specific fine-tuning of the restorer remains necessary for optimal performance. Open questions include whether smaller models (≤3B) can close the gap with larger ones, and whether the approach extends to multimodal steganography.
