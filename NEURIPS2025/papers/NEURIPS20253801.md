## Problem

Training LLM agents with reinforcement learning requires a large pool of diverse, high-quality tasks, but human annotation is costly and does not scale to open-ended, tool-rich environments. Prior task-synthesis pipelines are environment-specific, and no general framework exists for automatically generating verifiable, challenging multi-turn tool-use tasks that can reliably drive RL training without contaminating the learning signal with infeasible or ambiguous tasks.
![Teaser figure](../imgs/NEURIPS20253801/cropped_page1_idx0.webp)

## Input / Output

The method takes an LLM (e.g., Llama-3.1-8B-Instruct) with access to a set of tool APIs and API documentation as the initial observation, and produces a fine-tuned agent capable of solving multi-turn tool-use tasks in the same environment. The intermediate output is a set of synthetic Code-as-Task (CaT) specifications, each comprising a natural-language instruction, an executable Python verification function, a reference solution, and at least three failure cases — a structured format that enables automatic quality filtering before any training data is collected.

## Method

The Self-Challenging Agent (SCA) framework assigns the LLM two roles: a task challenger that actively interacts with the environment to probe available tools and unobserved states before generating a CaT task, and a task executor that is trained on those tasks. The CaT formalism is the key quality mechanism: an automatic checker verifies that the example solution passes the verification function while all failure cases fail, filtering out infeasible or overly lenient tasks (only ~5% of raw generations survive full filtering). For self-improvement, the executor is optimized via Rejection Fine-Tuning (equivalent to one-step REINFORCE with 0/1 rewards) or online RL (PPO, GRPO) on its own rollout trajectories; for distillation, a stronger teacher model (Llama-3.1-70B) samples trajectories on the synthetic tasks and the weaker student is trained via SFT on both successful and failed trajectories. This design outperforms the PAE baseline by 10.6% Pass@1 in self-improvement, primarily because the challenger's active exploration produces more precise tasks in partially observable environments and the code-based verification eliminates the false-positive/negative noise inherent in LLM-as-judge evaluation.

## Results

In the distillation setting, SCA improves Llama-3.1-8B-Instruct from 12.0% to 32.2% average Pass@1 across four tool-use environments (M³ ToolEval Calculation, Web Browsing; Tau-Bench Retail, Airline), a +20.2% absolute gain using only self-generated synthetic tasks. In the self-improvement setting, SCA nearly doubles the base model's performance from 12.0% to 23.5% average Pass@1 (+11.5%), outperforming the prior state-of-the-art PAE baseline by 10.6% in average Pass@1. Online RL (PPO/GRPO) on the same synthetic tasks further pushes Calculation Pass@1 to 43.2%, though at the cost of training instability.

## Baselines & Comparisons

Against PAE [51] (the prior state-of-the-art for autonomous task synthesis), SCA wins in both settings: in distillation, SCA achieves 32.2% vs. 30.1% average Pass@1, with the largest gap in Retail (+5.2% Pass@1); in self-improvement, SCA achieves 23.5% vs. 12.9% average Pass@1, a 10.6-point advantage, while PAE actually degrades to 0% Pass@4 in Airline. The key differentiator is that PAE generates tasks solely from initial API documentation without environment interaction, producing ambiguous tasks that fail in partially observable settings, whereas SCA's task challenger actively explores the environment and uses Code-as-Task verification to filter out infeasible or unverifiable tasks. Against the zero-shot GPT-4o reference (40.0% average Pass@1), the SCA-distilled 8B model (32.2%) closes most of the gap to the 70B model (41.3%) without any human-annotated tasks. Against the zero-shot Llama-3.1-70B teacher (41.3%), the SCA-distilled 8B student (32.2%) recovers roughly 78% of the teacher's performance using only synthetic trajectories, demonstrating effective knowledge transfer in open-ended tool-use environments.

## Relation to Prior Work

This paper extends the Asymmetric Self-Play (ASP) paradigm—where one agent generates goals and another solves them—from constrained domains (robotics, math) to open-ended, partially observable multi-turn tool-use environments. It departs from the prior state-of-the-art PAE (Proposer-Agent-Evaluator) in three key ways: the task proposer actively interacts with the environment to gather information before generating tasks (rather than reading only API docs), tasks are formalized in the Code-as-Task format with executable verification functions and failure cases (rather than relying on LLM-as-judge), and automatic filtering via external code executors ensures feasibility and verifiability. The Code-as-Task formalism also extends the code-as-action literature, which uses code as a unified tool interface, by repurposing code as the medium for task specification and evaluation.

## Why It Matters / Open Questions

The framework demonstrates that self-generated synthetic tasks can more than double LLM agent success rates in self-improvement settings without any human-annotated data, addressing a key scalability bottleneck in agent training. However, the absolute performance remains low (23.5% average Pass@1), improvements are environment-specific rather than generalizing across environments, and a suboptimality gap persists compared to oracle tasks. Open questions include how to handle semantic ambiguities that cause residual false negatives, how to improve environment-general agentic capabilities rather than environment-specific skills, and whether the approach scales to more complex or real-world tool ecosystems.
