## Problem

Existing VLM-based SVG generation methods are trained purely on token-level losses over SVG code sequences and never observe the rendered visual output during training, causing hallucination, looping, and poor generalization on complex or out-of-distribution inputs. Because autoregressive token sampling is non-differentiable, differentiable rasterizers like DiffVG cannot be applied to backpropagate rendering losses through the generation path, leaving a critical gap in how to incorporate visual feedback into autoregressive SVG code generation.

## Input / Output

For the primary Im2SVG task, the model takes a 224×224 RGB pixel image as conditioning input and autoregressively generates a full SVG document (with primitives such as <path>, <circle>, <polygon>, <text>, and gradient definitions) as a token sequence. For the secondary Text2SVG task, the input is a natural-language caption (e.g., from Flickr30k or MM-Icons) and the output is the same SVG code format, with no paired SVG supervision during RL training. Generated SVGs are rasterized via CairoSVG at the reference image resolution for reward computation.

## Method

RLRF uses a two-stage pipeline: (1) SVG-SFT, where a VLM (Qwen2.5-VL or StarVector) is fine-tuned with standard next-token prediction on 1.7M image–SVG pairs from SVG-Stack to establish baseline SVG fluency; (2) RLRF, where the SFT model is further optimized via GRPO using rendering-based rewards. For each input, the model samples G=64 SVG roll-outs at temperature 1.1, renders each with CairoSVG, and computes a composite reward combining pixel-level L2 distance (with optional Canny edge variant), DreamSim semantic similarity (concatenating CLIP, OpenCLIP, and DINOv2 features), and a quadratic length-deviation penalty for code compactness. GRPO centers rewards within each group of roll-outs to form advantages and applies PPO-style clipped-ratio updates without a separate value network; KL regularization to the SFT reference is ablated out as it provides limited benefit given the narrow conditional SVG distribution. Training uses only 16k curated high-entropy images (vs. 1.7M for SFT) over 500 steps, achieving state-of-the-art reconstruction fidelity and code efficiency on SVG-Stack-Hard and strong out-of-distribution generalization to SVG-Emoji, SVG-Fonts, and SVG-Icons.

## Results

On the SVG-Stack-Hard Im2SVG benchmark, RLRF applied to Qwen2.5-VL-7B achieves MSE 1.03, SSIM 95.10, DINO 98.70, and LPIPS 3.08, setting a new state-of-the-art across all reconstruction metrics while maintaining near-ideal code efficiency (−334 tokens). The 3B variant (MSE 4.79, DINO 95.97) and StarVector-1B variant (MSE 3.46, DINO 98.00) also substantially outperform all VLM baselines. On out-of-distribution benchmarks (SVG-Emoji, SVG-Fonts, SVG-Icons), RLRF models improve over their SVG-SFT counterparts without any task-specific fine-tuning, e.g., reducing MSE from 6.39 to 4.93 on SVG-Emoji and from 7.71 to 4.73 on SVG-Fonts.

## Baselines & Comparisons

RLRF on Qwen2.5-VL-7B (MSE 1.03, DINO 98.70, LPIPS 3.08) outperforms all closed-source VLMs by wide margins: GPT-4o-1120 (MSE 16.92, DINO 89.00), Claude 3.7 Sonnet (MSE 17.73, DINO 79.80), and Gemini-Flash-2.0 (MSE 19.31, DINO 86.53), as well as all open-source VLMs including Llama4-Maverick 400B (MSE 20.67, DINO 85.61). Against image-processing baselines, RLRF-7B beats LIVE (MSE 2.22, DINO 93.45) and PyAutoTrace (MSE 4.71, DINO 95.68) on MSE, DINO, and LPIPS, while producing SVGs that are 50–300× more compact (Code Eff. −334 vs. −18.3k to −99.7k). The 3B RLRF model (MSE 4.79) still surpasses every VLM baseline but trails LIVE slightly on MSE (2.22) and PyAutoTrace on DINO (95.68 vs. 95.97 is a near-tie). On out-of-distribution generalization (Table 3), RLRF-7B improves over its own SVG-SFT baseline on all three held-out datasets (e.g., SVG-Emoji MSE 6.39→4.93; SVG-Fonts MSE 7.71→4.73) and outperforms StarVector-1B/8B, which require explicit per-dataset fine-tuning to reach comparable scores. The only metric where image-processing methods retain an edge is raw SSIM on simple single-color glyphs, where VTracer (87.94) and LIVE (88.11) slightly exceed RLRF-3B (88.76) but fall well short of RLRF-7B (95.10).

## Relation to Prior Work

This paper builds on the GRPO algorithm from DeepSeek-R1 and PPO's clipped-ratio mechanism for policy optimization, but applies them to a fundamentally different setting: inverse rendering code generation where the 'execution' is a non-differentiable SVG rasterization. It departs from differentiable rendering approaches (DiffVG, SVGFormer) that require continuous primitive parameters and cannot handle autoregressive discrete token generation, and from prior RL-for-code work (CodeRL, RLEF) that optimizes for functional correctness rather than visual fidelity. The base model lineage traces to StarVector (Rodriguez et al., 2025b) and the Qwen2.5-VL family, with the key conceptual contribution being the use of rendered-output comparison as an automatic, differentiable-free reward signal for RL post-training.

## Why It Matters / Open Questions

The core idea—using rendering feedback as an RL reward when the rendering pipeline is non-differentiable—generalizes in principle to any inverse rendering task (HTML/CSS, LaTeX/TikZ, 3D code, CAD), making this a potentially broad framework for structured visual code synthesis. Key limitations include the model's tendency to 'give up' and loop on very complex inputs, several reward hacking behaviors (small viewBox, text-in-image shortcuts) that require careful mitigation, and the fact that SFT is a hard prerequisite (RL alone on instruction-tuned models fails). Open questions include whether the approach scales to longer/more complex SVGs, whether the KL-free GRPO variant generalizes beyond the narrow SVG conditional distribution, and whether the strong out-of-distribution generalization (SVG-Emoji, Fonts, Icons) holds for more distant visual domains.
