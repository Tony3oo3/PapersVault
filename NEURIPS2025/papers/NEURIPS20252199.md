## Problem

No existing framework can seamlessly unify multi-LoRA fine-tuning and inference serving within a single runtime. Prior systems either fuse adapters into monolithic instances that cannot be dynamically loaded or unloaded, degrade decoding efficiency when training and inference run concurrently, or require halting the current job before switching tasks—creating downtime, bandwidth overhead, and wasted resources that block production-scale LoRA deployment.

## Input / Output

The system ingests a frozen base LLM (Llama3-8B), multiple LoRA adapter weight matrices (rank-8, Gaussian-initialized), text prompts for inference, and labeled training sequences for fine-tuning/evaluation. It simultaneously produces generated text tokens for inference requests, per-request loss values for fine-tuning and evaluation, and updated LoRA adapter weights after backward propagation. A key structural detail is that the unified forward pass distinguishes four request types (fine-tuning, evaluation, prefilling, decoding) within a single batch, with losses tracked separately per fine-tuning task to enable independent gradient accumulation strategies.

## Method

Loquetier introduces two core mechanisms. First, a Virtualized Module abstraction creates runtime proxy objects that isolate PEFT modifications from the base model, enabling multiple concurrent adapter instances on shared weights with zero additional GPU memory overhead and supporting cross-device migration via a non-local deep-copy protocol that voids the virtual module before serialization. Second, the Segmented Multi-LoRA Multiplication (SMLM) kernel adapts Punica's multi-adapter GEMM to process LoRA weights one linear layer at a time rather than statically concatenating across layers, removing the rigid coupling that prevented selective layer targeting and dynamic adapter swapping. The unified computation flow routes all four request types through a single forward pass: Q/K/V projections are computed jointly, then attention outputs are computed per request type (standard forward for fine-tuning/decoding, FlashInfer batch-prefill for prefilling), concatenated, and passed through a shared output projection. For backward propagation, fine-tuning requests fall back to PyTorch Autograd while inference requests use FlashInfer's optimized kernels, and an extended interruptible Trainer with parameter masking (MixedLoRAModelForTrainer) allows multiple trainers to share the same computation flow and update only their respective adapter parameters in a single backpropagation step.

## Results

On inference-only tasks, Loquetier achieves up to 3.0× the decoding throughput of FlexLLM and 20.8× higher SLO attainment than PEFT at high request arrival rates (3–5 RPS). In unified fine-tuning and inference tasks, Loquetier attains 46.4× higher SLO than PEFT while maintaining ~40% fine-tuning efficiency across all request rates. In a 120-minute simulated real-world workload (BurstGPT), Loquetier achieves 92.37% overall SLO attainment, with failures only during transient spikes exceeding RPS 5. Model loading completes in 5.34 s with zero additional storage, compared to 38.86 s and 15.00 GB for FlexLLM.

## Baselines & Comparisons

Against PEFT (HuggingFace Transformers + PEFT), Loquetier dominates on all inference and unified metrics: SLO attainment is 20.8× higher in inference-only tasks and 46.4× higher in unified tasks, since PEFT's padding-based batching and serial multi-LoRA processing cause >90% of inference requests to time out. PEFT is marginally faster in pure fine-tuning (slightly lower total training time) because it avoids the independent kernel calls Loquetier incurs during backward propagation, but this advantage is negligible in practice. Against S-LoRA + PEFT, Loquetier wins on SLO attainment and is the only system that supports concurrent fine-tuning alongside multi-LoRA inference; S-LoRA additionally suffers from kernel instability (NaN/Inf outputs) and cannot handle LLaMA 3's GQA architecture without workarounds. Against FlexLLM, Loquetier achieves up to 3.0× higher inference throughput and supports all 7 LoRA target modules (q, k, v, o, up, gate, down) versus FlexLLM's 3 (up, gate, down); FlexLLM also fails entirely on multi-LoRA fine-tuning and unified tasks due to unimplemented backward kernels and a dead-loop in multi-adapter loading, while Loquetier handles all configurations seamlessly.

## Relation to Prior Work

Loquetier builds directly on Punica's multi-adapter GEMM kernel and the HuggingFace Transformers Trainer, but departs from both in critical ways: it decouples Punica's static cross-layer weight concatenation into per-layer processing to support heterogeneous LoRA configurations during training, and it extends the Trainer to allow multiple concurrent fine-tuning jobs sharing a single computation flow. It positions itself against FlexLLM (which attempts unified inference+PEFT but supports only 3 of 7 target modules and a single adapter) and S-LoRA (which handles multi-LoRA inference but not fine-tuning), filling the gap of simultaneous multi-adapter fine-tuning and serving that neither addresses. The Virtualized Module abstraction is a novel systems-level contribution that has no direct analogue in prior LoRA serving or PEFT literature.

## Why It Matters / Open Questions

For production LoRA deployments, the inability to fine-tune new adapters while simultaneously serving existing ones forces operators to halt inference, incurring downtime and resource waste; Loquetier's unified runtime eliminates this bottleneck with a 46.4× SLO improvement over PEFT in mixed workloads. However, the evaluation is limited to a single model (Llama3-8B) on single-GPU servers, and the baselines (PEFT, S-LoRA, FlexLLM) are either architecturally constrained or contain unresolved bugs, making it difficult to gauge true competitive margins. Open questions include whether the per-layer SMLM kernel scales to multi-GPU tensor-parallel settings, whether a dedicated backward kernel can close the remaining fine-tuning efficiency gap, and whether the Virtualized Module generalizes cleanly to non-LoRA PEFT methods like VeRA or DoRA.
