## Problem

Existing NL2SQL models trained via supervised fine-tuning struggle with complex database scenarios involving multi-table joins and nested queries, exhibiting poor generalization to new domains and lacking interpretable reasoning. This paper investigates whether reinforcement learning with direct database execution feedback can train NL2SQL models to independently explore and reason over SQL generation strategies, overcoming the fixed-pattern limitations of SFT.
![Teaser figure](../imgs/NEURIPS20255805/cropped_page1_idx0.webp)

## Input / Output

The model takes a natural language question paired with a database schema (formatted as CREATE TABLE statements with column attribute descriptions) and produces an explicit chain-of-thought reasoning process enclosed in <think> tags followed by a SQL query in <answer> tags. At inference, the model generates 8 SQL candidates with temperature 0.8, executes all against the database, and selects the final answer via self-consistency voting. The system operates on the SQLite dialect and targets execution accuracy as the evaluation metric.

## Method

SQL-R1 trains Qwen2.5-Coder base models (3B/7B/14B) using Group Relative Policy Optimization (GRPO), which eliminates the need for a value model and operates on groups of G=8 sampled SQL candidates. The key mechanism is a composite reward function with four progressive components: Format Reward (structural correctness of tags), Execution Reward (syntactic validity via actual database execution), Result Reward (execution accuracy against ground truth), and Length Reward (encouraging comprehensive reasoning while penalizing verbosity). RL training uses only 5K complex NL-SQL pairs from SynSQL-2.5M, with an optional SFT cold-start phase on 200K synthetic samples to activate instruction-following and NL2SQL generation capabilities. The database itself serves as the environment providing ground-truth execution feedback, enabling the model to explore diverse SQL generation strategies rather than memorizing fixed patterns from training data.

## Results

SQL-R1 achieves 88.7% execution accuracy on Spider-Test and 67.1% on BIRD-Dev using the Qwen2.5-Coder-14B base model, and 88.7% / 66.6% with the 7B variant. On Spider2.0 (SQLite subset), SQL-R1-7B reaches 20.0% accuracy, outperforming GPT-4o (15.6%) and OmniSQL-7B (10.4%). The 7B model with self-consistency (8 candidates) adds only 0.7s latency over greedy search while gaining 2.9% accuracy on BIRD-Dev, demonstrating a favorable efficiency-accuracy trade-off.

## Baselines & Comparisons

SQL-R1-7B (88.7% Spider-Test, 66.6% BIRD-Dev) outperforms all open-source baselines on Spider-Test, surpassing OmniSQL-7B (88.9% Spider-Test but 66.1% BIRD-Dev), SQL-o1 (85.1%), and DTS-SQL (84.4%), while matching or exceeding them on BIRD-Dev. Against closed-source LLM pipelines, SQL-R1-14B (88.1% Spider-Test) beats MCTS-SQL/GPT-4o (86.6%), CHASE-SQL/Gemini-1.5-Pro (87.6%), MAC-SQL/GPT-4 (82.8%), and DAIL-SQL/GPT-4 (86.2%) on Spider-Test, though it trails CHASE-SQL (73.0%) and MCTS-SQL (69.4%) on BIRD-Dev. Among RL-based NL2SQL methods, SQL-R1-14B substantially outperforms Reasoning-SQL (81.4% Spider-Dev, 65.3% BIRD-Dev) and DeepRetrieval (76.1% Spider-Test, 56.0% BIRD-Dev), confirming the advantage of the GRPO-based training with the proposed composite reward. On the harder Spider2.0 benchmark, SQL-R1-7B (20.0%) leads all compared methods including GPT-4o and DeepSeek-V3 (both 15.6%). The 3B variant (78.9% Spider-Test, 54.6% BIRD-Dev) shows that RL training yields the largest relative gains for smaller models, with a +1.7pp improvement over the untrained 3B base on Spider-Test versus only +0.1pp for the 14B model.

## Relation to Prior Work

SQL-R1 transplants the GRPO reinforcement learning paradigm from DeepSeek-R1 and DeepSeekMath into the NL2SQL domain, where prior work (OmniSQL, DTS-SQL, CodeS) has relied almost exclusively on supervised fine-tuning. It leverages the SynSQL-2.5M synthetic data pipeline from OmniSQL for both SFT cold-start and RL training, but departs from prior NL2SQL methods by replacing SFT as the primary optimization signal with a multi-component reward function (format, execution, result, length) that provides direct database-grounded feedback. The self-consistency candidate selection strategy aligns with recent NL2SQL systems (CHASE-SQL, SQL-o1), but the RL training loop that generates and scores multiple candidates during training is a novel combination for this task.

## Why It Matters / Open Questions

SQL-R1 demonstrates that a 7B open-source model trained with only 5K complex RL samples can match or exceed GPT-4-class systems on Spider-Test (88.7% vs 87.0%), offering a cost-effective and interpretable alternative for high-stakes domains like finance and healthcare. A key open question the paper surfaces is whether SFT cold-start is genuinely necessary before RL, since their ablations show it can sometimes degrade BIRD performance (63.1% without SFT vs 59.2% with SynSQL-200K SFT for 7B). Limitations include SQLite-only dialect support, evaluation restricted to Qwen2.5-Coder models, and a substantial gap to the best closed-system (CHASE-SQL at 73.0% on BIRD), leaving multi-dialect generalization and broader model coverage as important future directions.
