## Problem

Naive learning-augmented caching algorithms like BLINDORACLE achieve ideal 1-consistency but have unbounded robustness under prediction errors. Existing robustification methods either sacrifice 1-consistency (e.g., PREDICTIVEMARKER achieves only 2-consistency, LMARKER only 4-consistency) or introduce prohibitive computational overhead (F&R requires O(n² log k) total time by recomputing the optimal solution on every cache miss). The paper asks whether robustness can be enhanced to a tight logarithmic bound while preserving both 1-consistency and the base algorithm's asymptotic time complexity.

## Input / Output

GUARD operates as a lightweight companion process to a base RB-following algorithm (BLINDORACLE, LRB, or PARROT), consuming the same predictions (next request times, Belady binary labels, or FitF page) and cache size k. On each request, it restricts the base algorithm's eviction candidate set to unguarded cached pages and, upon detecting a prediction error (a page evicted earlier in the current phase is requested again), overrides the base policy with a uniform random eviction from the set of unrequested old pages. The per-request overhead is O(1) with hash tables, so the total time complexity remains O(n log k) for BLINDORACLE-based variants and O(n) for LRB/PARROT-based variants.

## Method

GUARD introduces a phase-based mechanism where execution is divided into phases that reset when all previously cached pages have been either requested or evicted. At the start of each phase, all cached pages are labeled 'old' and tracked in a set U of unrequested old pages. When a cache miss occurs for a page that was evicted earlier in the current phase, GUARD interprets this as a prediction error, evicts a uniformly random page from U, and guards the requested page against eviction until the next phase; otherwise, the base algorithm's prediction-driven eviction is applied only over unguarded pages. Under perfect predictions, no page is ever guarded (proved via a contradiction argument showing that guarding would make the algorithm outperform OPT), so GUARD&A behaves identically to A, preserving 1-consistency. The robustness analysis uses an eviction graph per phase, where edges represent 'evicted by' relationships, and bounds the expected length of old-page eviction chains by harmonic numbers, yielding a tight (2H_{k-1}+2)-robustness guarantee. An extension, EXGUARD, further trades predictor usage (O(d·OPT) queries) for improved smoothness of O(min(log(η/OPT), λ√(η/OPT))).

## Results

On the SPEC CPU2006 benchmark (16-way 2MB cache, 13 datasets), GUARD&B.O. achieves the lowest average cost ratio of 1.226 with the PLECO predictor and 1.203 with POPU, outperforming all baselines. GUARD&LRB achieves a cost ratio of 1.171 with the LRB predictor, again the best among all compared methods. Theoretically, GUARD guarantees (1, 2H_{k-1}+2) consistency-robustness trade-off with only O(1) additional per-request overhead, matching the state-of-the-art robustness bound while preserving 1-consistency.

## Baselines & Comparisons

GUARD&B.O. consistently outperforms all NRT-based baselines on SPEC CPU2006: it beats BLINDORACLE (1.404→1.226 with PLECO, 1.261→1.203 with POPU), PREDICTIVEMARKER (1.335→1.226), LMARKER (1.335→1.226), BLINDORACLE&MARKER (1.294→1.226), and F&R (1.360→1.226) under PLECO, with similar margins under POPU. GUARD&LRB similarly dominates the binary-prediction baselines, achieving 1.171 versus LRB (1.281), MARK0 (1.268), and MARKER (1.394) with the LRB predictor. In synthetic experiments (Figures 1–2 on BrightKite), GUARD&B.O. and GUARD&LRB exhibit empirical 1-consistency at zero prediction error and bounded cost ratios under increasing noise, confirming the theoretical guarantees. Notably, GUARD&B.O. also outperforms F&R, which previously achieved the best-known O(log k)-robustness with 1-consistency but at O(n² log k) total computational cost, whereas GUARD maintains O(n log k) complexity with O(1) per-request overhead.

## Relation to Prior Work

This paper introduces GUARD, a robustification framework that sits at the intersection of two prior lines of work on learning-augmented caching: embedding-based methods (PREDICTIVEMARKER, LMARKER) that integrate prediction logic into MARKER's marking mechanism, and switching-based methods (BLINDORACLE&LRU, F&R) that detect prediction errors at runtime. GUARD departs from both by defining a new class of 'RB-following' algorithms (unified under the relaxed Belady's rule) and applying a lightweight phase-based error-detection mechanism that avoids both the marking overhead that limits consistency and the O(n²log k) recomputation cost of switching methods. It is directly applied to three representative base algorithms—BLINDORACLE, LRB, and PARROT—each using a different prediction type (next request times, binary labels, FitF pages).

## Why It Matters / Open Questions

GUARD achieves the current best-known (1, 2H_{k-1}+2) consistency-robustness trade-off with only O(1) per-request overhead, making it the first framework that simultaneously preserves 1-consistency, provides logarithmic robustness, and maintains the base algorithm's asymptotic time complexity—addressing a gap where prior methods always sacrificed one of these three properties. The EXGUARD extension further explores a smoothness-vs-predictor-usage trade-off, opening a design axis not previously available. Open questions include whether the robustness bound can be tightened toward the H_k lower bound while retaining 1-consistency, and whether the framework extends to relaxed caching models (e.g., where the requested item need not be stored).
