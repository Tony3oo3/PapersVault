## Problem

As LLMs are widely distributed and customized through fine-tuning, there is no systematic way to verify whether a deployed model was derived from a specific foundational model when only black-box API access is available. Prior fingerprinting and watermarking approaches require white-box access, specialized training modifications, or additional knowledge about the model, leaving a gap for practical provenance verification in post-deployment settings where training details are undisclosed.

## Input / Output

The tester consumes only black-box query access to the target model g, a set of candidate parent models F, and a set of control models C, along with randomly generated 5–20 word incomplete-sentence prompts. For each prompt, only the first output token from each model is compared, making the method agnostic to model architecture or output length. The output is a binary provenance verdict (TRUE/FALSE) with a family-wise error rate guarantee at user-specified significance level α, and when TRUE, the identity of the most likely parent model among the candidates.

## Method

The core insight is that fine-tuned models retain output-distribution similarity to their parent that is statistically distinguishable from unrelated models. The tester samples T random prompts, queries all models on the same prompts, and computes a similarity ratio μ (fraction of matching first tokens) between the target and each candidate/control model. It then applies z-tests to determine whether the target–candidate similarity significantly exceeds each target–control similarity, using Holm-Bonferroni correction to control the family-wise error rate across all simultaneous tests. For the general case with multiple candidate parents, the algorithm first identifies the single most similar model among all candidates and controls, then verifies via multiple hypothesis testing that this model is significantly more similar than all others. Two query-reduction strategies are provided: entropy-based rejection sampling to select more discriminative prompts (reducing online queries 4–6×), and a Best Arm Identification formulation from multi-armed bandit theory to reduce offline queries to parent and control models.

## Results

On two benchmarks spanning 30M–4B parameter models (600+ models total), the provenance tester achieves 90–95% precision and 80–90% recall with 3,000 prompts per model, far exceeding the random-guessing baseline of ~9% (BENCH-A) and ~2% (BENCH-B). Precision peaks near 1.00 at lower prompt counts (≤1,000) and gradually declines as more prompts detect weaker, non-provenance similarities, while recall improves monotonically with prompt count. Advanced entropy-based prompt sampling (k=64) achieves a 4–6× reduction in online queries (from 3,000 to ~500 prompts) while maintaining 90–95% precision and 80–90% recall. The BAI-based offline optimization reduces queries to parent/control models by 10–30% but degrades recall substantially (e.g., from 0.86 to 0.63 on BENCH-A at T=1,000).

## Baselines & Comparisons

The paper does not compare against prior provenance-testing methods, as the authors state no prior work addresses this problem under the same minimal black-box assumptions. The primary internal comparison is between the base hypothesis-testing tester and the BAI-enhanced variant: the base tester consistently achieves higher recall (e.g., 0.86 vs. 0.63 on BENCH-A at T=1,000) while the BAI variant saves 10–30% of offline queries at the cost of a 20–40 percentage-point recall drop, with precision remaining comparable (0.97–1.00). Against the random-guessing baseline (1/(s+1) precision), the tester's 90–95% precision represents a 10–45× improvement. The advanced rejection-sampling strategy (k=64) matches the recall of the base tester at k=1 using only ~250 prompts instead of 1,000, a 4× online query reduction with no measurable precision loss. Control set size also matters: with only 4 control models, BENCH-B precision drops below 10%, whereas the full 57-model control set sustains ~92–95% precision.

## Relation to Prior Work

This paper departs from the dominant lines of model ownership verification—fingerprinting (which typically requires white-box access, adversarial examples, or specialized prompting) and watermarking (which requires modifications to training or model weights)—by formulating provenance testing as a purely black-box statistical hypothesis testing problem. It builds on the Holm-Bonferroni procedure for controlling family-wise error rate across multiple comparisons and on Best Arm Identification from the multi-armed bandit literature for query reduction, but applies these tools to a new problem: determining whether a model was derived from a candidate parent using only next-token output agreement. The authors explicitly position their work as the first systematic treatment of model provenance testing under minimal (black-box, no training data, no hyperparameter) assumptions, distinguishing it from prior fingerprinting and similarity-measurement approaches that lack formal false-positive guarantees or do not survive fine-tuning.

## Why It Matters / Open Questions

The practical significance is substantial: as LLMs proliferate across organizations and marketplaces, the ability to verify provenance with only API access addresses real IP enforcement, security auditing, and compliance needs that prior white-box or watermark-based methods cannot. Key limitations include the non-adaptive adversary assumption, the reliance on two empirical assumptions (derivation implies above-average similarity; control models establish a valid baseline), and the observation that the BAI-based offline query reduction trades significant recall for only modest query savings. Open questions include robustness to adaptive adversaries who specifically try to evade provenance detection, optimal control-set selection strategies for diverse domains, and whether the approach extends to more aggressive customizations (e.g., model merging, distillation) that may break the similarity assumption.
