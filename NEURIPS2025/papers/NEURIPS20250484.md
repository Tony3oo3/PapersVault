## Problem

Current LLM-based role-playing systems append character descriptions directly into prompts and rely on the model's implicit reasoning to interpret character logic at runtime, resulting in brittle, inconsistent behavior that is difficult to debug, update, or make stochastic. This paper asks whether character logic can be compiled into explicit, executable code to achieve persistence, updatability, and controllable randomness that prompting alone cannot provide.
![Teaser figure](../imgs/NEURIPS20250484/cropped_page1_idx0.webp)

## Input / Output

The system takes a natural-language scene description and a character profile (sourced from Fandom wiki pages, ~1,000 words / ~15 paragraphs per character) as input. The profile is preprocessed by a codification LLM (gpt-4.1) into paragraph-level Python functions; at inference, each function receives the scene and returns a list of triggered_statements (logic-grounded assertions like 'X becomes outraged'). The role-playing LLM then synthesizes these triggered statements into a final character response (utterance or action). The check_condition helper internally queries the LLM for logits over verbalizers ('yes', 'no', 'unknown') to resolve semantic questions about the scene.

## Method

The core mechanism compiles each paragraph of a character profile into an executable parse_by_scene(scene) function using an LLM's code-generation ability, combining explicit if-then-else control flow with a check_condition(scene, question) callable that offloads localized semantic judgments to the LLM's discriminative logits. This shifts the bulk of character-logic reasoning from runtime prompt interpretation to deterministic code execution, so the LLM only handles narrow condition classification and final response synthesis. Three extensions are built on this foundation: (1) evolving profiles, where NLI-based mismatch detection triggers targeted revision of individual functions along the storyline; (2) controllable randomness, where stochastic behavior is encoded via random.choice or random.random() < p in the code rather than relying on temperature; and (3) a distilled 0.1B deberta-v3-base classifier trained on 20,759 condition-checking labels that replaces the LLM for condition evaluation, enabling 1B-parameter role-playing models to approach 8B performance.

## Results

On the Fandom Benchmark (83 characters, 5,141 scenes), Codified Profile achieves an average NLI score of 68.38 for main characters and 69.87 for minor characters, outperforming Textual Profile (65.98 / 65.70) and Vanilla No-Profile (64.21 / 64.67). The advantage is most pronounced for minor characters (+4.17 over Textual Profile) and for smaller models: a 1B LLaMA-3.2 with codified profiles rivals an 8B model with textual profiles. Adding textual profiles on top of codified profiles yields marginal further gains (68.62 / 69.96), suggesting complementary information.

## Baselines & Comparisons

The paper compares four profile-grounding strategies: Vanilla (no profile, lower bound), Textual Profile (standard prompt-based grounding), Codified RAG (retrieval-based codification), and the proposed Codified Profile (executable logic functions). Codified Profile outperforms Textual Profile by +2.40 (main) and +4.17 (minor) average NLI points, and surpasses Codified RAG by +2.34 (main) and +3.14 (minor), confirming that structured executable logic provides deeper character understanding than shallow relevance matching. The gains are consistent across all six artifacts, with the largest improvements on AGOT (main: 67.51 vs 61.52) and ATLA (minor: 71.95 vs 65.88). In human/LLM preference evaluations, codified profiles are preferred over both textual profiles and Codified RAG, and the ensemble of codified + textual responses yields the highest win rate, though codified-only responses contribute more individual wins. For smaller models (1B, 3B LLaMA-3.2), codified profiles close the gap to 8B textual-profile performance, with a distilled 0.1B DeBERTa condition checker enabling a 1B+Code+Distill system that approaches 8B+Text quality.

## Relation to Prior Work

This paper departs from the dominant prompt-based role-playing paradigm (appending character descriptions to prompts and relying on runtime LLM reasoning) by repurposing LLM code generation to compile character logic into executable Python functions with explicit control flow. It draws conceptually on traditional NPC scripting in video games (hardcoded behavioral rules) but elevates it with LLM-based semantic condition checking via check_condition, bridging deterministic program logic and flexible neural reasoning. The evaluation framework builds on NLI-based scoring for role-playing fidelity, and the efficiency gains leverage knowledge distillation (deberta-v3-base as a condition checker), while the grounding mechanism is positioned against RAG-based retrieval of profile segments.

## Why It Matters / Open Questions

The practical impact is significant: by offloading character-logic reasoning to preprocessing, codified profiles enable 1B-parameter models to rival 8B models with textual profiles, opening the door to efficient local deployment of role-play agents. The Fandom Benchmark (83 characters, 5,141 scenes across six diverse artifacts) provides a much-needed behavior-centric evaluation resource beyond dialogue-focused benchmarks. Open questions include extending codification to world-level environmental rules, introducing richer operators (arithmetic, spatial movement), and managing the information-loss trade-off when abstracting nuanced prose into structured logic. The finding that codified profiles benefit 'fickle' strategic characters more than emotionally straightforward ones suggests the approach is complementary to, rather than a replacement for, textual prompting.
