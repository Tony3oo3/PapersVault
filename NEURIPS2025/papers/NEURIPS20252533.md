## Problem

LLM-based code-as-policies approaches generate executable robot control code but lack environmental grounding in dynamic, partially observable settings, where sparse or missing observations lead to incorrect or incomplete code and suboptimal task success. Existing verification and validation techniques in software engineering are limited to static or simulated settings and do not enable agents to actively explore their environment to resolve perceptual uncertainty before execution.
![Teaser figure](../imgs/NEURIPS20252533/cropped_page1_idx0.webp)

## Input / Output

The framework takes a natural language task instruction, a history of symbolic observations (structured predicate-based expressions such as is_locked(drawer) or on(object, surface)), and domain knowledge defining available skills with their preconditions and effects. It produces a grounded Python policy code consisting of a sequence of parameterized skill function calls, where each skill has been both symbolically verified for logical consistency and interactively validated against the current environment state. The recursive structure may also emit intermediate probe policies as subroutines that execute before the main policy to acquire missing observations.

## Method

NESYRO operates through a recursive composition of two phases: Neuro-symbolic Code Verification, where an LLM (GPT-4o-mini) generates a task specification and policy code via chain-of-thought reasoning, and a Z3 SMT solver statically checks logical consistency, iteratively refining the code on failure; and Neuro-symbolic Code Validation, where each skill is sequentially scored by NeSyConf = CSC × LC, combining a perplexity-based commonsense confidence from a small LLM (Llama-3.2-3B) with a binary logic confidence from a Fast Downward PDDL planner. When NeSyConf falls below a threshold ε, the framework synthesizes a safe probe policy that is itself recursively verified and validated before execution, acquiring missing observations that update the environment state. The updated observations then trigger targeted skill-level code refinement rather than full regeneration, and this probe-refine-validate loop repeats until all skills are grounded, producing a policy tree rooted at the main policy where each probe serves as a subroutine enabling its parent's successful validation.

## Results

On RLBench across four task types and four observability levels, NESYRO outperforms the strongest baselines (AutoGen, CaP w/ CodeSift) by 26.3% in Success Rate (SR) and 24.3% in Goal Condition (GC). In real-world experiments under partial observability, NESYRO achieves 57.5% SR and 58.9% GC on average, compared to 10.6% SR for both CaP and CaP w/ CodeSift, while reducing Irreversible Actions (IA) from 29 (CodeSift) to 7. The framework attains over 86.8% executability of task-relevant actions and improves SR by 46.2% over the Code as Policies baseline overall.

## Baselines & Comparisons

NESYRO dominates all five baselines across every task type and observability condition. Against CaP (Code as Policies), NESYRO improves SR by ~47% in real-world settings (57.5% vs. 10.6%) and reduces irreversible actions from 53 to 7. CaP w/ CodeSift, which adds multi-stage syntactic/semantic validation, achieves only marginal gains over base CaP (10.6% SR) and still incurs 29 irreversible actions, whereas NESYRO's environment-grounded validation cuts IA to 7. CaP w/ Lemur (SMT-based pre-execution verification) improves over base CaP in RLBench but lacks interactive probing, so it cannot recover missing observations under high incompleteness. LLM-Planner and AutoGen (execution-aware replanning and multi-agent reasoning) perform reasonably under Low Incompleteness but degrade sharply as uncertainty increases, while NESYRO maintains performance close to its Complete-observability upper bound. The gap is most dramatic on Long-Horizon tasks, where baselines remain below 10% SR in real-world settings while NESYRO reaches 52.5%.

## Relation to Prior Work

This paper extends the code-as-policies paradigm (Liang et al., ICRA 2023) by importing the software-engineering verification-and-validation (V&V) distinction into robot code generation: symbolic verification (via Z3 SMT) checks logical consistency against a task specification, while interactive validation (via PDDL planning and LLM-based confidence scoring) grounds each skill in the current environment. It departs from prior LLM-planner and AutoGen replanning approaches, which react to failures post-execution, by proactively synthesizing safe probe policies *before* task execution to recover missing observations. The neuro-symbolic confidence score (NeSyConf) draws conceptual inspiration from SayCan's integration of LLM scores with affordance functions, but replaces the learned affordance model with a parallel symbolic-logic and commonsense-plausibility check.

## Why It Matters / Open Questions

The framework addresses a practical gap—LLM-generated robot code degrades sharply under partial observability—and the 46.2% success-rate gain over Code-as-Policies with a concurrent reduction in irreversible actions is meaningful for real-world deployment. However, the binary logic-confidence (LC) and reliance on a hand-crafted PDDL domain knowledge base limit generality; the authors themselves flag probabilistic PDDL and open-domain skill validation as necessary next steps. Open questions include whether the recursive probe tree scales to longer-horizon or multi-robot settings, and whether the predefined skill library can be replaced by learned primitives without sacrificing the safety guarantees that the symbolic validation provides.
