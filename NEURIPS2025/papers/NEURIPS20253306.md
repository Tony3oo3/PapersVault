## Problem

Large LLMs and diffusion models in BFloat16 format exceed the memory capacity of single-node GPU servers (e.g., Llama 3.1 405B requires 810 GB), forcing expensive multi-node deployment or lossy quantization that degrades accuracy. Existing lossless compression methods target storage efficiency (checkpoint compression) or specialized hardware (FPGAs) rather than enabling efficient on-the-fly GPU inference, leaving a gap for a lossless format that directly reduces GPU memory footprint during serving.

## Input / Output

The method takes a full model in standard BFloat16 format (1 sign + 8 exponent + 7 mantissa bits per weight) and produces a DFloat11 compressed representation with an effective bit width of ~10.8–11.1 bits per weight, applied to all linear projection matrices, token embeddings, and language modeling heads in LLMs, and all transformer-block weight matrices in diffusion models. During inference, the compressed weights are decompressed on-the-fly into BFloat16 before each matrix multiplication and immediately discarded, yielding bit-for-bit identical outputs (text tokens or pixel-wise identical images) to the uncompressed model.

## Method

DFloat11 exploits the low entropy (~2.6 bits) of the 8-bit BFloat16 exponent field—only ~40 of 256 possible values appear in LLM weights—by applying Huffman coding to exponents while leaving sign and mantissa bits uncompressed, achieving near information-optimal ~30% size reduction. For efficient GPU decoding, the monolithic Huffman LUT (up to 2^32 entries) is decomposed into 4–8 hierarchical compact LUTs of 256 entries each that fit in GPU SRAM, with unused exponent values (240–255) repurposed as pointers between LUT levels. A two-phase CUDA kernel coordinates parallel decoding: phase 1 counts elements per thread using a 5-bit gap array for starting offsets, then a Blelloch prefix sum computes per-thread write positions; phase 2 re-decodes and writes to an SRAM buffer before a single coalesced HBM write. Decompression is batched at the transformer-block level to saturate GPU resources, and the entire pipeline is integrated into HuggingFace Transformers for drop-in inference.

## Results

DFloat11 achieves approximately 30% model size reduction (compression ratio 67.6%–69.5%, average bit width ~10.8–11.1 bits) across all tested LLMs and diffusion models while producing bit-for-bit identical outputs. On inference efficiency, DF11 delivers 2.3–46.2× higher token-generation throughput compared to BF16 models with CPU offloading, and enables 5.7–14.9× longer generation lengths under a fixed GPU memory budget. For diffusion transformers, DF11 reduces peak GPU memory by 28.3% (Stable Diffusion 3.5) and 27.8% (FLUX.1) with only 4.1% and 5.5% latency increase, respectively. Notably, DF11 enables lossless inference of Llama 3.1 405B (810 GB) on a single node with 8×80 GB A100 GPUs.

## Baselines & Comparisons

The paper's primary practical baseline is CPU offloading of uncompressed BF16 models, where DF11 achieves 2.3–46.2× higher token-generation throughput across varying batch sizes and GPU configurations (Figure 4). Against NVIDIA's nvCOMP ANS decompression library, DF11's custom GPU kernel delivers up to 20.97× faster decompression and up to 34.95× higher throughput than CPU-to-GPU weight transfer, while also achieving a better compression ratio (68% vs. 79% for nvCOMP). On accuracy and perplexity benchmarks (MMLU, TruthfulQA, WikiText, C4), DF11 is trivially identical to the BF16 original since the compression is lossless—no degradation is possible by construction. For diffusion models, DF11 reduces peak GPU memory by ~28% with only 4–6% generation-time overhead, a favorable trade-off compared to the alternative of CPU offloading which would incur far larger latency penalties.

## Relation to Prior Work

This paper extends the lineage of lossless model compression from storage-oriented methods (Deep Compression, ZipNN) and the single prior GPU-inference attempt (NeuZip, which relies on NVIDIA's now-closed-source nvCOMP) to a fully open, hardware-aware GPU kernel. The core compression idea—Huffman-coding only the BFloat16 exponent bits while leaving sign and mantissa untouched—is a direct application of classical entropy coding to a newly identified redundancy (exponents carry only ~2.6 bits of information in 8 allocated bits). The primary technical departure from prior work is the custom CUDA kernel design: hierarchical 256-entry LUTs in SRAM, a two-phase thread-coordination scheme with gap arrays, and transformer-block-level batched decompression, all tailored to avoid the sequential bottleneck of standard Huffman tree traversal on massively parallel hardware.

## Why It Matters / Open Questions

DFloat11's practical impact is substantial: it enables lossless inference of Llama 3.1 405B (810 GB) on a single 8×80 GB GPU node—halving hardware requirements with zero accuracy loss—and supports 5.7–14.9× longer generation lengths under a fixed VRAM budget by freeing memory for KV cache. The technique is simple to apply (one-time Huffman tree construction per model) and integrates into standard inference frameworks, making it a low-friction adoption for practitioners. Limitations include restriction to BFloat16 weights (no FP8/FP16/FP32 support), a small but non-zero decompression latency at small batch sizes, and evaluation limited to NVIDIA GPUs. Open questions include whether similar exponent-entropy patterns exist in FP8 or other emerging formats, and whether the kernel design transfers to TPUs or custom accelerators.
