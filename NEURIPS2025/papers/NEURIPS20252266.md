## Problem

Formal model checking provides exhaustive correctness guarantees for safety-critical systems, but constructing accurate Kripke models and temporal-logic specifications remains a manual, expert-dependent process. When AI agents autonomously generate system code, no pre-existing test suite or expert-defined property set is available to verify correctness during generation, creating a critical gap between system synthesis and formal verification. SpecMAS addresses this by closing the loop between model generation and model checking within a single autonomous pipeline.

## Input / Output

The system ingests a natural-language Standard Operating Procedure (SOP) document describing a target system's operational modes, variables, and transitions, augmented by a domain knowledge base queried via SCMRAG retrieval. It produces a machine-executable NuSMV model file encoding a finite-state Kripke structure (states, initial states, total transition relation, atomic-proposition labeling) alongside a companion file of CTL/LTL property specifications. The SOPs in the evaluation benchmark were themselves synthesized from canonical NuSMV 2.5.1 example models using a GAN-LLM fusion tool (SYNTHIA), since the original distribution provided code without natural-language documentation.

## Method

SpecMAS organizes two tightly-coupled agentic pipelines around a Qwen3-32B 8-bit backbone LLM. Pipeline I (Synthesis) proceeds through three phases: extracting task information from the SOP via RAG, constructing a Kripke structure with a dedicated Kripke Extractor and Solver agent, and generating both explicit and implicit temporal-logic properties through a Property Exploration agent. Pipeline II (Verification & Debugging) executes the NuSMV symbolic model checker and, upon failure, dispatches a Debugging Agent that interprets counterexample traces—ultimately-periodic paths αβ^ω for LTL violations or finite annotated paths/trees for CTL violations—to iteratively revise transition guards, variable domains, or property formulations until M ⊨ φ holds for all specifications. The key architectural insight is that the debugging agent receives the full code-revision history at each iteration, enabling it to explore alternative bounds and structural corrections rather than repeating prior fixes, thereby guaranteeing convergence to a verified model.

## Results

On MiniSpecBench (5 SOP systems), SpecMAS achieves the highest Final Compliance Score on 4 out of 5 tasks: BRP Protocol (0.76±0.08), Shuttle Autopilot (0.76±0.01), Robot Controller (0.69±0.07), and GigaMax Cache (0.70±0.05), losing only to Claude on Mutual Exclusion (0.77 vs. 0.88). SpecMAS's dominant advantage is in Execution Compliance, where it scores 0.84–0.97 across all systems, while Gemini and Qwen fail to produce executable .smv files in 3 and 2 of 5 tasks respectively. The ablation study confirms that the iterative debugging loop (not raw LLM generation) is the primary driver of this gap, with the synthesis-only pipeline failing to produce executable models on complex systems like the Robot Controller and GigaMax Cache.

## Baselines & Comparisons

SpecMAS outperforms all four baseline LLMs (Claude 3.7-Sonnet, DeepSeek R1-Distill-Llama-70B, Gemini Flash-2.5, Qwen 3.0-Chat-235B) on Final Compliance Score in 4 of 5 systems, with margins ranging from +0.18 (GigaMax Cache vs. DeepSeek) to +0.46 (Shuttle Autopilot vs. Qwen). Claude is the strongest competitor, winning Mutual Exclusion (0.88 vs. 0.77) and achieving the highest Structural Alignment and Property Fidelity scores on several tasks, but it fails to execute the Robot Controller model entirely (Execution Compliance = 0.0). DeepSeek ranks second overall but produces syntactically valid yet semantically shallow models that require zero debug steps yet score poorly on compliance (e.g., 0.42 on Shuttle Autopilot). Gemini and Qwen suffer the most severe execution failures—Gemini produces non-executable .smv files in 3/5 tasks and Qwen in 2/5—despite Qwen's 235B parameter count far exceeding SpecMAS's 32B backbone, underscoring that the multi-agent verification loop, not raw model scale, drives the performance gap.

## Relation to Prior Work

This paper sits at the intersection of three research threads: symbolic model checking (NuSMV, CTL/LTL), LLM-assisted specification synthesis (AutoSpec, SpecGen, NL2CTL, PropertyGPT), and multi-agent code generation. Prior work has addressed individual fragments—translating formal specifications to model-checker inputs, generating temporal logic properties from natural language, or using LLMs to produce code—but has not closed the loop from natural-language SOP through model synthesis, property extraction, model checking, and counterexample-guided debugging within a single autonomous pipeline. SpecMAS carves new ground by integrating all stages into a unified multi-agent architecture that outputs directly in NuSMV's native syntax, eliminating the need for custom intermediate languages or proprietary compilers that prior DSL-based methods require.

## Why It Matters / Open Questions

The closed-loop, correctness-by-construction design addresses a critical gap in AI-generated systems: the absence of formal guarantees during generation, which is especially problematic in safety-critical domains where expert-defined test suites may not exist. Key limitations include reliance on NuSMV (restricting applicability to discrete, finite-state systems), evaluation on only five benchmark SOPs that were themselves synthetically generated rather than human-authored, and dependence on LLM-as-a-Judge scoring that may not fully capture formal correctness. Open questions include scalability under state-space explosion, integration with complementary backends (SPIN, probabilistic model checkers), and robustness to the linguistic variability of real-world human-written SOPs.
