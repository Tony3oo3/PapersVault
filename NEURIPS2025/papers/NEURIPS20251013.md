## Problem

Online HD map construction methods are inherently limited by the short perception range of onboard sensors, and while SD maps (e.g., OpenStreetMap) offer a low-maintenance prior, existing approaches only exploit a narrow subset of SD map content—specifically polylines with a few manually selected road classes. The vast majority of SD map data, including point-level elements, topological relations, and hundreds of thousands of textual key-value annotations, remains entirely unused for HD map construction.

## Input / Output

The method consumes multi-camera images and frame-aligned OpenStreetMap data containing points, polylines, and relations, each annotated with arbitrary key-value text tags (e.g., oneway: yes, lanes: 2). SD map elements are provided in two evaluation ranges: near range (60 m × 30 m) and far range (120 m × 60 m). The output is a set of vectorized HD map instances (dashed/solid dividers, boundaries, centerlines, pedestrian paths) represented as fixed-length point sequences (10 points per polyline) in a 2D BEV coordinate frame, predicted by a DETR-style decoder.

## Method

SDTagNet introduces two key modules on top of the MapTRv2 base architecture. First, a compact BERT encoder (embedding dim 144) is pre-trained from scratch with a customized contrastive objective (multiple negatives ranking loss, 5120 negatives) that pulls together tagsets sharing semantically meaningful tags while pushing apart irrelevant cataloging artifacts, producing open-vocabulary tag embeddings for every SD map element. Second, a point-level SD map encoder replaces SMERF's polyline-level queries with one query per resampled point, using orthogonal random feature (ORF) vectors as element identifiers so that points, polylines (shared ORF across their points), and relations (paired ORFs) are encoded uniformly in a single graph-transformer-style module. The resulting SD map token sequence is injected into the MapTRv2 decoder via an additional cross-attention layer, enabling the model to leverage both geometric structure and full textual semantics without any handcrafted feature selection.

## Results

On Argoverse 2 (geographic split), SDTagNet achieves 18.9 mAP in the far range (120m×60m), outperforming the MapTRv2 no-prior baseline (13.0 mAP) by +5.9 mAP (+45%) and the best existing SD map prior method (PMapNet with all info, 15.7 mAP) by +3.2 mAP (+20%). In the near range (60m×30m), SDTagNet reaches 48.1 mAP vs. 46.5 mAP for MapTRv2 (+1.6 mAP). On nuScenes far range, the relative gain is even larger: +4.1 mAP (+105%) over MapTRv2 and +2.1 mAP (+35%) over the best prior method (SMERF with all info).

## Baselines & Comparisons

Against the two SD map prior baselines, SDTagNet clearly wins in the far range on both datasets: on Argoverse 2 it beats PMapNet (all info.) by +3.2 mAP and SMERF (all info.) by +4.7 mAP; on nuScenes it beats SMERF (all info.) by +2.1 mAP and PMapNet (all info.) by +4.2 mAP. In the near range, no SD map prior method provides a significant gain over MapTRv2, and SDTagNet's +1.6 mAP on Argoverse 2 is the largest but still modest. Compared to recent non-SD-prior state-of-the-art methods (Table 2), SDTagNet outperforms MapTracker by +6.1 mAP in the far range (70.9 vs. 64.8 on the geo split) but trails it by 3.5 mAP in the near range (67.8 vs. 71.3), indicating that SD map priors are most beneficial when sensor visibility is limited. The ablation (Table 3) confirms that the combination of point-level queries, NLP tag embeddings, and ORF identifiers is necessary for the full gain—any single component alone yields at most +0.4 mAP over the SMERF baseline, while all three together produce +2.2 mAP.

## Relation to Prior Work

SDTagNet builds on the MapTRv2 DETR-style architecture for online vectorized HD map construction and extends the line of SD map prior encoding initiated by PMapNet (rasterized OSM images) and SMERF (transformer-encoded polylines with fixed semantic classes). The key departure is twofold: (1) replacing hand-selected polyline classes with open-vocabulary BERT embeddings of raw OSM text tags, pre-trained via a custom contrastive objective, and (2) shifting from polyline-level to point-level queries with orthogonal random feature identifiers borrowed from graph transformers, enabling uniform handling of points, polylines, and relations. This makes SDTagNet the first method to consume the full OSM schema—text annotations, point nodes, and topological relations—without manual feature engineering.

## Why It Matters / Open Questions

Fully exploiting freely available, globally maintained SD maps like OpenStreetMap removes the primary cost barrier to scalable autonomous driving, since SD map maintenance is orders of magnitude cheaper than HD map upkeep. The contrastively pre-trained NLP tag encoder is task-agnostic and could in principle serve any application requiring embeddings of structured key-value annotations, not just HD map construction. Open questions remain around SD/HD map discrepancies (missing tunnels, inconsistent borders), one-way direction prediction (lacking point-order encoding), and geographic overfitting, which the authors show is aggravated by SD map priors and for which no effective augmentation strategy was found.
