## Problem

Code corpora inherently encode diverse reasoning paradigms—divide-and-conquer, topological ordering, enumeration—but the reasoning signals are implicit, buried in syntactic details, and entangled with implementation noise, making direct training on raw code suboptimal. Prior work like CodeI/O transforms code into input-output question pairs but still overlooks the fine-grained information embedded in the execution process itself. The paper asks whether converting each step of code execution into an explicit, natural-language chain-of-thought narration (Chain of Execution) can serve as a more effective and generalizable supervision signal for LLM reasoning.

## Input / Output

The training input consists of code snippets paired with questions drawn from three sources: algorithmic competition problems (Codeforces), 30 classical algorithms (CLRS), and mathematical solver code (OpenMath). Questions range from standard function I/O prediction to fine-grained variable-tracing prompts (e.g., 'trace the changes of variable X during execution'). The output is a step-by-step CoE narration in natural language that walks through each computational step, with intermediate states originally verified via structured JSON (state₁ → state₂ → … → stateₙ) before being converted to prose. A strict 8k-token limit is imposed to avoid combinatorially long traces from dense graph inputs.

## Method

TracePile is a 2.6M-sample, ~19B-token corpus where Qwen-2.5-72B-Instruct generates CoE rationales by tracing code execution step-by-step under few-shot prompting, with correctness verified against ground-truth execution traces. Two augmentation strategies enrich diversity: query diversification (generating variable-tracing and intermediate-state questions for algorithmic code) and code diversification (rewriting implementations via structural refactoring or alternate algorithmic approaches). The corpus is then used under three training setups—continue-pretraining, instruction tuning after pretraining, and two-stage finetuning (TracePile first, then Tulu3-SFT)—across four base models (LLaMA 3/3.1-8B, Qwen-2.5-7B, Qwen-2.5-Coder-7B). The key insight is that explicit step-by-step execution supervision provides a richer, more interpretable reasoning signal than final-answer or solution-style training, yielding consistent gains across 20 benchmarks spanning math, code, logic, and algorithms, including strong out-of-domain transfer to LiveCodeBench, CRUX, and Zebra Logic.

## Results

Under continue-pretraining, TracePile boosts LLaMA3.1-8B-Base by an average of 7.1% across nine math datasets (57.4% → 64.8%) and delivers gains exceeding +40% on algorithmic benchmarks like GraphWiz (1.9% → 33.9%). Under two-stage finetuning, LLaMA-3-8B achieves a +6.4% average math gain (55.3% → 61.7%), while Qwen-2.5-Coder reaches 50.8% on MATH and 35.5% on LiveCodeBench-Output. Across 20 benchmarks spanning math, code, logic, and algorithms, models trained with TracePile consistently outperform their base counterparts, with the largest relative improvements on out-of-domain tasks such as CRUXEval (+16.4 pts for LLaMA-3.1-8B) and RuleTaker (+40.3 pts for LLaMA-3-8B under continue-pretraining).

## Baselines & Comparisons

TracePile is compared against four baselines under a controlled two-stage finetuning setting on Qwen-2.5-Coder-7B: OpenMath (both code-solution and math-CoT variants), WebInstruct (generic instruction data), and CodeI/O (3.5M input-output code samples). On MATH, TracePile (50.8%) outperforms OpenMath code-solution (46.1%) by 4.7 pts and CodeI/O (39.8%) by 11.0 pts, though it trails the OpenMath math-CoT variant (51.1%) by a narrow 0.3 pts. The most decisive advantage appears on out-of-domain tasks: TracePile reaches 35.5% on LiveCodeBench-Output, nearly doubling the next-best baseline (OpenMath code-solution at 19.4%) and far exceeding CodeI/O (17.6%) and WebInstruct (18.8%). On Zebra Logic, TracePile (10.8%) beats all baselines, with the largest margin over OpenMath code-solution (5.6%). On GSM8K, TracePile (80.8%) is competitive but slightly below OpenMath math-CoT (82.1%) and WebInstruct (81.3%), indicating that the CoE format's primary benefit lies in structured multi-step reasoning and generalization rather than simple arithmetic.

## Relation to Prior Work

This paper extends the CodeI/O line of work, which transforms raw code into structured function-level input-output pairs for reasoning supervision, by replacing final-answer supervision with step-by-step Chain of Execution (CoE) narrations that make intermediate reasoning explicit. It also builds on the broader trend of using code as a reasoning training source (MathCoder, MathCoder2, DeepSeek-Math) and on execution-aware pre-training efforts like Traced and SemCoder, but departs from them by operating at the granularity of individual variable-state transitions rather than high-level functional descriptions or output prediction. The CoE format is conceptually analogous to chain-of-thought prompting applied to code execution, but is generated at scale via frontier LLMs and validated against ground-truth execution traces.

## Why It Matters / Open Questions

TracePile provides a 2.6M-sample, 19B-token dataset that demonstrates fine-grained execution supervision generalizes beyond code to logical, mathematical, and algorithmic reasoning across four model families, offering a practical intermediate training stage for practitioners. However, the approach relies heavily on Qwen-2.5-72B for CoE generation (introducing potential bias and cost), the 8k-token cutoff may discard complex long-range reasoning traces, and coverage remains skewed toward math and algorithms. An open question raised by the rejection-sampling experiment is why higher-quality filtering helps math but plateaus or regresses on code and logical tasks, suggesting distributional biases that are not yet understood.
