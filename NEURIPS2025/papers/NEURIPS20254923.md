## Problem

SWE-bench, the dominant benchmark for evaluating LLMs on real-world issue resolution, suffers from three critical limitations: it has not been updated since its 2023 release (creating data contamination risk), it covers only 12 repositories (limiting diversity), and its construction relies heavily on manual labor for environment setup and test validation (creating a scalability bottleneck). No existing benchmark offers a live-updating, automatically curated, and broadly covered alternative for repository-level issue resolution.

## Input / Output

Each task instance provides a GitHub issue description (problem statement) and a snapshot of the codebase at the base commit, along with a dedicated Docker image for reproducible execution. The model must produce a patch in .diff format that, when applied to the codebase, causes designated FAIL_TO_PASS tests to pass without regressing PASS_TO_PASS tests. Instance-specific test commands and log parsers (e.g., pytest with -rA for per-test status) are stored as part of the dataset to enable automated evaluation of patch correctness.

## Method

The core contribution is REPOLAUNCH, a fully automated three-stage pipeline that eliminates manual curation. Stage 1 crawls issue-PR pairs from 2,609 filtered Python repositories (≥1,000 stars, ≥200 issues/PRs, ≥60% Python, valid license), restricting to issues created after January 2024 to reduce contamination. Stage 2 uses an LLM-driven ReAct agent to set up a Docker environment per instance: it identifies relevant files (CI configs, READMEs), selects a base image, interactively installs dependencies and builds the project in a bash session, then a separate verifying agent confirms the test suite runs correctly; a 'time machine' mechanism proxies pip to only resolve package versions released before the base commit timestamp, preventing dependency version drift. Stage 3 validates each instance by running the test suite multiple times before and after applying the gold patch, retaining only instances with consistent FAIL_TO_PASS transitions. The resulting 1,890 instances across 223 repositories (initial release: 1,319 across 93) are updated monthly with minimal manual intervention.

## Results

On the SWE-bench-Live Lite subset (300 instances), the best agent-model combination is OpenHands with Qwen3-Coder-480B-A35B, achieving a 24.67% resolved rate, 97.00% patch apply rate, and 30.00% localization success rate. Among the top-3 combinations evaluated on the full 1,319-instance set, OpenHands/Claude 3.7 Sonnet leads with 19.25% resolved rate, followed by SWE-Agent/GPT-4.1 at 18.57% and SWE-Agent/Claude 3.7 Sonnet at 17.13%. Notably, the same OpenHands/Claude 3.7 Sonnet pair achieves 43.20% on SWE-bench Verified under identical settings, revealing a >2× performance gap that suggests overfitting to static benchmarks. Multi-run evaluation (Pass@3) for SWE-Agent/GPT-4.1 improves the resolved rate from 16.22% (average Pass@1) to 21.67%.

## Baselines & Comparisons

The paper evaluates three agent frameworks—OpenHands, SWE-Agent, and s-Agentless (a simplified Agentless without reranking)—paired with four LLMs. OpenHands with Claude 3.7 Sonnet and SWE-Agent with GPT-4.1 are the strongest general-purpose combinations, achieving 17.67% and 16.33% resolved rate on the Lite set respectively, while s-Agentless lags behind at 11.33–13.33% across all models. On the full set, OpenHands/Claude 3.7 Sonnet (19.25%) edges out SWE-Agent/GPT-4.1 (18.57%) and SWE-Agent/Claude 3.7 Sonnet (17.13%). A critical finding is that all methods perform dramatically worse on SWE-bench-Live than on SWE-bench Verified: the best pair drops from 43.20% to 19.25%, and instances from original SWE-bench repositories (22.96%) are still easier than those from new repositories (18.89%), confirming that current agents are partially overfit to the static SWE-bench codebases. Patch difficulty is the dominant failure factor: single-file patches under 5 lines yield ~48% success, while patches touching 7+ files are never solved.

## Relation to Prior Work

This paper extends the SWE-bench issue-resolution task (Jimenez et al., ICLR 2024) by introducing a fully automated, continuously updatable benchmark construction pipeline (REPOLAUNCH) that replaces the manual curation bottleneck. It incorporates improved issue-PR pair identification heuristics from SWE-Fixer (Xie et al., 2025) and positions itself against LiveCodeBench (algorithmic problems) and SWE-smith (synthetic data) as the first live-updating benchmark for repository-level, multi-file bug fixing. The core methodological departure is the agentic, ReAct-based Docker environment setup that eliminates the 200+ hours of manual labor reported by SWE-Gym, enabling monthly updates across 223 repositories.

## Why It Matters / Open Questions

The paper reveals a striking performance gap: state-of-the-art agents achieve 70%+ on SWE-bench Verified but only ~25% on SWE-bench-Live, with a controlled experiment confirming the same agent-model pair drops from 43.2% to ~19%. This suggests substantial overfitting to static benchmarks, which has broad implications for how the community interprets SWE-bench leaderboard results. Key limitations include Python-only coverage, single-run experiments without statistical significance testing, and the fact that the 'overfitting' interpretation, while supported by the SWE-bench-repo vs. non-SWE-bench-repo comparison, could also reflect differences in documentation quality or test infrastructure. Open questions include whether the gap narrows as models improve and whether multi-language extension (Java, Go, C++) changes the difficulty landscape.
