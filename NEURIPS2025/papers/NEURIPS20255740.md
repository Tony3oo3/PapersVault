## Problem

Multi-turn LLM serving systems waste GPU compute and memory by independently processing semantically equivalent queries from different user sessions. Existing prefix caching (e.g., vLLM, RadixAttention) only matches exact token sequences and misses semantic equivalence, while flat semantic caches (e.g., GPTCache) ignore conversational context and remain decoupled from the underlying KV cache, forcing full re-prefill on cache misses. No prior system simultaneously preserves hierarchical conversational context, detects topic shifts, and co-designs semantic indexing with low-level KV cache memory management.

## Input / Output

SmartCache consumes a user's new text query along with the session's accumulated query-response history, and internally generates a 1024-dimensional BGE-M3 embedding for vector search (faiss, L2 distance, threshold 0.75). During the prefill pass, it peeks at per-head attention scores over historical tokens (excluding 8 attention-sink tokens) to classify the query as contextual or independent. Outputs include the streamed text response (retrieved from cache or freshly decoded), transparently shared paged KV cache blocks (16 tokens per block) mapped through a two-level table, and an updated Semantic Forest with new nodes and vector index entries.

## Method

SmartCache organizes all conversation turns into a Semantic Forest—a collection of semantic trees where each node stores a query embedding, cached response, and a local faiss index of its children. Cache lookup is constrained to the current node's descendants (local search) before falling back to a global root-level search, preserving conversational continuity while bounding the search space. A key differentiator is the attention-based context-switching mechanism: after a double cache miss, the system inspects attention scores already computed during the standard prefill pass to decide whether the query extends the current topic or starts a new one, redirecting the session to a different semantic tree at negligible overhead. For memory management, a two-level mapping (per-session context table → per-context block table) enables multiple sessions at the same semantic node to transparently share physical KV cache blocks. The STEP eviction policy scores nodes by Semantic Depth Score (1/Depth) and Session Affinity Score (1/#Sessions), while subtree-aware prefetching pulls children into GPU memory based on rolling access-frequency statistics.

## Results

On CoQA, SmartCache reduces KV cache memory usage by up to 59.1% compared to PrefixCache and 56.0% over GPTCache, while cutting Time-to-First-Token (TTFT) by 78.0% and 37.7%, respectively. On SQuAD2.0, the TTFT reductions are 71.7% and 50.6% over the same baselines. In terms of answer quality, SmartCache achieves 39.9% higher F1 and 39.1% higher ROUGE-L than GPTCache for Qwen-2.5-1.5B on CoQA, while remaining close to the ideal (no-cache) baseline. The STEP eviction policy further outperforms LRU/LFU by up to 29.9% in average reuse distance under skewed workloads.

## Baselines & Comparisons

SmartCache is compared against two main baselines: PrefixCache (vLLM/RadixAttention-style exact token-prefix KV sharing) and GPTCache (flat query-embedding semantic cache). Against PrefixCache, SmartCache achieves dramatically lower TTFT (78.0% reduction on CoQA, 71.7% on SQuAD) and substantially lower KV cache memory (up to 59.1% reduction), because PrefixCache only reuses exactly matching token prefixes and cannot exploit semantic equivalence across differently-phrased queries. Against GPTCache, SmartCache wins on both resource efficiency (56.0% less KV cache, 37.7–50.6% lower TTFT) and answer quality (e.g., 39.9% higher F1 and 39.1% higher ROUGE-L for Qwen-2.5-1.5B on CoQA), because GPTCache's flat embedding search ignores conversational context, leading to false-positive cache hits that degrade response accuracy. SmartCache's hierarchical Semantic Forest constrains retrieval to the correct conversational branch, preserving contextual accuracy while still enabling cross-session reuse. The STEP eviction policy additionally outperforms standard LRU and LFU by 29.9% and 25.7% in average reuse distance under Zipfian-distributed workloads, confirming that semantic-aware eviction is more effective than blind recency/frequency heuristics in multi-session settings.

## Relation to Prior Work

SmartCache builds directly on paged KV cache management (PagedAttention/vLLM) by extending the per-session block table into a two-level mapping that enables cross-session sharing, while departing from both prefix caching (RadixAttention, vLLM APC) and flat semantic caching (GPTCache, SCALM). Prefix caching relies on exact token matching and ignores semantic equivalence; flat semantic caches capture query similarity but disregard conversational context and operate decoupled from the inference engine's KV state. The paper's key conceptual departure is the system-algorithm co-design: a hierarchical Semantic Forest for context-aware retrieval is tightly integrated with the KV cache memory hierarchy, and attention scores from standard prefill are repurposed as a near-free context-shift detector—neither of which appears in prior caching or serving work.

## Why It Matters / Open Questions

The co-design of semantic indexing with low-level KV cache management addresses a gap that neither serving-system optimizations nor application-level caches fill, and the demonstrated quality gains (up to ~40% F1/ROUGE-L improvement over GPTCache) show that context-aware caching can be a win-win rather than an efficiency-accuracy trade-off. Open questions include how the approach scales to production multi-tenant deployments with heterogeneous workloads, the privacy implications of cross-session response sharing (acknowledged but only sketched via a sanitizer module), and whether the attention-based context-switching heuristic generalizes reliably across model families and conversation lengths beyond the 5-turn synthetic sessions used in evaluation. The evaluation is also limited to two QA datasets and models up to 32B, leaving open whether the gains persist on longer, more open-ended dialogues.
