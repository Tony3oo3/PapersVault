## Problem

LLMs struggle with logic grid puzzles and first-order logic tasks that require systematic constraint satisfaction over combinatorial search spaces. Prior neuro-symbolic approaches that integrate LLMs with theorem provers or SAT solvers achieve only modest gains (10–15% improvement), partly because the translation from natural language clues to formal constraints is error-prone and the formal target languages (e.g., raw SMT-LIB) are verbose and difficult for LLMs to generate correctly. This paper asks whether a purpose-built, human-readable intermediate language can make the LLM-to-solver mapping significantly more reliable.

## Input / Output

The system accepts a natural-language description of a logic grid puzzle (a set of entities, their categorical attributes, and a list of relational clues) or a first-order logic problem statement. The LLM first produces a Python data structure with type-annotated fields (e.g., `Unique[Domain[int, range(1,7)]]`) that encodes the solution space, then a validation function that translates each clue into `assume`/`assert`/`nondet` calls. The final output is a complete entity-to-feature assignment table (one row per entity, one column per attribute) that satisfies all clues, verified by the constraint solver.

## Method

The core contribution is Logic.py, a Python-based DSL that borrows type decorators (Unique, Domain, list) to express common constraint patterns concisely, and treats uninitialised variables as nondeterministic free variables for the solver. The polymath agent prompts the LLM in two zero-shot stages: (1) define the result data structure with precise type annotations, and (2) write a validation function encoding each puzzle clue as assumptions and assertions over nondeterministic elements. A libCST transformer converts the Logic.py source into ANSI-C, mapping type decorators to CPROVER initialisation helpers and assertions to `__CPROVER_assume` calls, then embeds the result in a search harness with a single reachability assertion. The harness is handed to CBMC (SAT backend for Zebra puzzles) or mapped to SMT for Z3 (FOLIO), which finds a satisfying assignment. An error-recovery loop restarts up to five times on syntax errors or UNSAT results, and the entire pipeline is agentic but does not fine-tune the underlying LLM.

## Results

On ZebraLogicBench, Polymath with Llama 3.1 70B achieves 90.7% puzzle accuracy (92.56% cell accuracy), a 65.8 percentage-point improvement over the 24.9% baseline of the same model without the constraint solver. Polymath also boosts GPT-4o from 31.7% to 77.8% and Claude 3.5 Sonnet from 36.2% to 76.9% on the same benchmark. On the FOLIO first-order logic benchmark, Polymath with Claude 3.5 Sonnet reaches 81.28% accuracy, the highest among all evaluated configurations.

## Baselines & Comparisons

On FOLIO, Polymath with Claude 3.5 Sonnet (81.28%) outperforms Logic-LM (Pan et al., 2023) at 78.92% by 2.36 points and Logic-LM (Han et al., 2022) at 78.1% by 3.18 points. On ZebraLogicBench, the paper's approach with Llama 3.1 70B (90.7%) substantially exceeds the 55.3% achieved by Berman et al.'s (2024) constraint-guided multi-agent system with GPT-4, which started from a 23.7% baseline. The Polymath agent also surpasses all non-agent LLM baselines on the hardest XL puzzle category, where Llama 3.1 70B alone scores 0% but Polymath + Llama 3.1 70B reaches 83%. The gains are most dramatic for smaller models: Llama 3.1 70B improves by 65.8 points, GPT-4o by 46.1 points, and Claude 3.5 Sonnet by 40.7 points, suggesting the constraint solver compensates most effectively for weaker base-model reasoning.

## Relation to Prior Work

This paper carves new ground at the intersection of LLMs and constraint solving by introducing Logic.py, a Python-based domain-specific language that serves as an intermediate representation between natural language problem statements and SAT/SMT solvers. It departs from prior neuro-symbolic approaches (Logic-LM, SatLM, Berman et al.) that either directly encode constraints in SMT syntax or use multi-agent refinement loops, by drawing an explicit analogy to intermediate languages in compiler design: the DSL structures the mapping from natural language to solver input. The unusual choice of CBMC (a C/C++ bounded model checker) as the SAT back-end, with libCST transforming Python to C, repurposes program verification infrastructure in a way not seen in prior LLM+solver work.

## Why It Matters / Open Questions

The 65% absolute accuracy gain on ZebraLogicBench (24.9% → 91.4% for Llama 3.1 70B) demonstrates that a well-designed DSL can make constraint solvers dramatically more accessible to LLMs, potentially generalizing to other search-based and formal verification tasks. However, the evaluation is limited to logic grid puzzles and FOLIO with only three models and no fine-tuning, leaving open whether the approach transfers to numerical reasoning, optimization, or other constraint domains. The paper itself acknowledges that Logic.py is a prototype lacking many Python features, and the absence of error feedback to the model on syntax failures represents a clear avenue for improvement.
