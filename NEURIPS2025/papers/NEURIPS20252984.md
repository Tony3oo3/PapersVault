## Problem

KV cache memory consumption during LLM inference grows linearly with sequence length, batch size, and model layers, making it a critical bottleneck on resource-constrained edge servers. Existing mitigation strategies (prompt compression, token-level eviction, quantization) operate at the layer-wise or token-wise level and incur significant computational overhead that is prohibitive for edge nodes. No prior work exploits the natural task similarity present in edge computing workloads to reduce KV cache memory at the task level.

## Input / Output

Sim-LLM takes tokenized text prompts as input and, for each incoming task, compares its word embedding against cached embeddings using LSH bucket lookup followed by cosine similarity (threshold 0.8). When a similar task is found, the cached top-layer KV pair is injected into the model's first layer, bypassing KV computation for all intermediate layers; unmatched tasks fall back to a 'sandwich' configuration retaining only the bottom 3 and top 3 layers' KV. The output is the generated token sequence, with the system simultaneously reducing peak GPU memory by up to 34.65% and increasing throughput by up to 39.40% relative to baselines.

## Method

Sim-LLM's core mechanism is inter-task KV reuse: after processing each batch, the KV_Manager stores the word embedding, LSH hash value, and top-layer KV of every task, and subsequent similar tasks reuse the cached top-layer KV instead of recomputing KV from scratch. For matched tasks, queries from all layers attend solely to the single top-layer KV pair, allowing the model to skip the entire prefilling phase and generate output directly from the top layer. For unmatched tasks, a sandwich configuration (bottom 3 + top 3 layers) minimizes computation while preserving quality. Task similarity identification uses an adaptive strategy: exhaustive cosine comparison for small batches and LSH bucket mapping for large batches, with KV merging within a bucket to mitigate LSH distortion. In multi-node deployments, each edge server maintains a task prototype derived from its processed workloads in a global feature table, enabling one-hop identification of the most likely server holding a similar task for offloading, with only the sequence or embeddings transmitted rather than the full KV cache.

## Results

Sim-LLM achieves a system throughput improvement of up to 39.40% (33.04% on average) and a KV cache memory reduction of up to 34.65% (30.05% on average) over state-of-the-art baselines on A40 and A100 GPUs. On zero-shot downstream benchmarks (Table 2), Sim-LLM maintains accuracy close to the standard model (e.g., 46.89 vs. 48.41 avg on Llama-7B; 57.31 vs. 58.61 on Llama-13B), while baselines degrade substantially (e.g., H2O drops to 40.05 on Llama-7B). In terms of maximum achievable batch size, Sim-LLM supports up to 36.6× larger batches than standard Llama-7B on A40 (256 vs. 7 at 512+4096 sequence length), with corresponding throughput gains of up to 8.0×.

## Baselines & Comparisons

Sim-LLM outperforms all four baselines (StreamingLLM, H2O, ZipCache, ArkVale) on both throughput and memory consumption across all tested batch sizes and GPU configurations. On Llama-7B zero-shot accuracy, Sim-LLM (46.89 avg) is closest to the standard model (48.41), while H2O (40.05) and StreamingLLM (41.65) suffer the largest accuracy drops (7–8 points); ZipCache (46.55) and ArkVale (45.58) are also competitive but still trail Sim-LLM. On Llama-13B, Sim-LLM (57.31) again leads all baselines, with ArkVale (56.67) and ZipCache (56.32) as the closest competitors. In terms of maximum batch size on A40, Sim-LLM achieves up to 36.6× the batch size of standard Llama-7B (256 vs. 7 at 512+4096), compared to 15.4× for ArkVale and 13.7× for ZipCache. The key differentiator is that Sim-LLM's inter-task KV reuse approach avoids the information loss inherent in eviction-based methods (H2O, StreamingLLM) and the quantization overhead of ZipCache, while also avoiding the page-management complexity of ArkVale.

## Relation to Prior Work

This paper departs from the dominant line of KV cache optimization that operates within a single task (sequence-length compression via LLMlingua/Lm-infinite, token-level eviction via StreamingLLM/H2O, quantization via ZipCache, page-level eviction via ArkVale) by introducing a task-wise perspective: reusing top-layer KVs *across* semantically similar tasks. It repurposes LSH for efficient cross-task similarity identification, borrows the sandwich (bottom+top layer) KV retention idea from inter-layer sharing methods (YOCO, CLA) to handle unmatched tasks, and adapts prototype learning for cross-node task routing. The conceptual anchor is the observation that edge servers, due to limited geographic service coverage, naturally receive highly similar workloads — a property prior KV-optimization work has not exploited.

## Why It Matters / Open Questions

For edge LLM deployment, where GPU memory is the binding constraint, a 34.65% memory reduction and 39.40% throughput gain without retraining are practically significant and could enable larger batch sizes or longer contexts on commodity edge hardware (A40). Key limitations temper the impact: the approach requires identical model architectures across all edge servers (KV shape consistency), the KV_Manager storage overhead can negate gains at very large cache sizes (≥4096), and the method's benefit scales with task similarity proportion, which may not hold in diverse or adversarial workloads. The open question of heterogeneous-model KV sharing and the lack of error bars across runs leave some uncertainty about robustness.
