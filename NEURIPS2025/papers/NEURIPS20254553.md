## Problem

Large language models trained on heterogeneous instruction data perform best on high-frequency use cases, making it difficult to achieve strong performance on rare, underrepresented features at inference time. Existing remedies such as prompt engineering, few-shot examples, and chain-of-thought are fragile, model-specific, and place a heavy burden on users to discover effective configurations. The paper asks whether training protocols themselves can be optimized to simultaneously improve user controllability and long-tail performance without requiring manual prompt engineering at inference.

## Input / Output

The model takes a natural language instruction prompt and optionally a structured marker template (XML-like tags specifying attributes such as domain, task, length tokens, quality bucket, language, format, and style) appended to the prompt. At inference the markers are fully optional: the model is trained to infer the correct marker values from context when they are not explicitly provided, so end users never need to construct them. The output is a text completion conditioned on both the prompt and the (explicit or inferred) markers, with the model also generating the marker list as a prefix to its completion.

## Method

The approach augments 2.7M instruction-tuning examples with a taxonomy of 90 training-time markers across 13 categories (length, quality, domain, task, format, style, language, code type, source, etc.), formatted as natural-language XML tags and tokenized identically to the surrounding text. Markers are placed in both the input space (appended to the prompt) and the output space (prepended to the completion), so the model learns to associate generation properties with these characteristics during standard negative-log-likelihood fine-tuning. A dual dropout strategy—removing all markers for a random fraction of the dataset (dataset-level) and removing random subsets of markers per example (sample-level)—prevents over-reliance and teaches the model to infer missing markers at inference. This creates explicit control levers (e.g., setting a quality bucket or length-token value) that are particularly effective for long-tail features, while remaining completely optional because the model recovers the correct markers from context alone.

## Results

On Arena-Hard-Auto, the TreasureMarked model achieves a 5.7% absolute win rate increase over the Baseline (32.1% → 37.8%), with an even larger +9.1% gain on underrepresented domains (<5% of training data). On length instruction following (AlpacaEval-LI), explicit length markers reduce violation rates from 36.58% to 1.25% (a 35.3% absolute decrease). On long-tail code tasks, CodeRepair sees a 14.1% relative improvement (0.216 → 0.246 pass@1), and language control improves by +10.98% average across 14 languages on the Language Confusion Benchmark.

## Baselines & Comparisons

The primary comparison is against a Baseline model trained on identical data but without training-time markers. The TreasureMarked model consistently outperforms the Baseline across all evaluated benchmarks: +5.7% win rate on Arena-Hard-Auto, +9.1% on long-tail domains, 35.3% absolute reduction in length violations, +14.1% relative on CodeRepair, and +10.98% average on language control. Gemma2-9B is used as an external reference point for win rate calculations (both models are compared against it via GPT-4o judging), but the paper's core claim is the improvement over its own unmarked Baseline. The gains are disproportionately larger on underrepresented features: CodeRepair (rare subtask) improves 14.1% relative vs. only 3.2% relative for the dominant CodeGeneration task, and long-tail domains gain +9.1% vs. +5.7% for well-represented domains. No comparison shows the TreasureMarked model losing to the Baseline on any primary metric.

## Relation to Prior Work

This paper revives and generalizes the tagging paradigm from early neural machine translation (single-feature tags for language, quality, domain, politeness) to a comprehensive 90-marker taxonomy across 13 categories applied at the instruction fine-tuning stage. It departs from CTRL-style pretraining control codes and metadata-conditioning approaches (Gao et al., 2025) by operating entirely in the SFT phase and using dropout rather than a cooldown schedule to make markers optional at inference. The approach also contrasts with prompt engineering and few-shot methods by embedding controllability into the training distribution itself, shifting the burden from the user to the model's learned associations.

## Why It Matters / Open Questions

The technique offers LLM providers a low-friction mechanism to expose control levers (quality, length, language, domain) through API calls without requiring users to master prompt engineering, which is practically significant as models are increasingly consumed via APIs by non-expert users. The disproportionate long-tail gains (14.1% relative on CodeRepair vs. 3.2% on CodeGeneration) suggest that structured metadata can unlock performance in underrepresented regions of the training distribution that prompt-level interventions struggle to reach. Key open questions include whether the approach scales to larger models, whether multi-valued markers (an example spanning multiple domains) would further improve results, and whether the technique is effective when integrated into pretraining rather than SFT.
