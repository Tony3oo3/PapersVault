## Problem

Existing AutoML systems and LLM-based ML agents still require substantial manual configuration, hard-coded preprocessing pipelines, or rigid data formats to function, preventing truly end-to-end automation on raw multimodal data. Two key limitations persist: (1) the absence of automated data perception forces reliance on predefined workflows, and (2) LLMs produce hallucinated code and outdated API calls when managing long, convoluted ML library knowledge without efficient memory mechanisms.

## Input / Output

MLZero accepts a raw data folder containing heterogeneous files (images, tabular CSVs, text documents, audio) plus a brief one-sentence task description and optional user instructions, with no task-specific preprocessing required. For supervised tasks the folder includes labeled training data and unlabeled test data; for zero-shot inference it contains only unlabeled test data. The system outputs task-specific predictions (class labels, segmentation masks, regression values, retrieval rankings), the full generated code artifacts, and execution logs, evaluated via a task-specific objective function against ground truth.

## Method

MLZero is a hierarchical multi-agent system of nine specialized LLM agents organized into four modules. A Perception module (file grouping, task perception, and ML library selection agents) transforms raw multimodal inputs into a structured perceptual context and selects the appropriate ML library. A Semantic Memory module maintains offline-constructed condensed tutorial knowledge bases, with a retrieval agent that extracts contextually relevant guidance at each iteration to reduce hallucination. An Episodic Memory module stores chronological execution history, with an error analyzer agent that distills encountered issues into concise error summaries paired with actionable fix suggestions. An Iterative Coding module then loops a coder agent (generating executable code informed by perceptual context, retrieved knowledge, and error context) and an executer agent (running code, capturing logs, and deciding whether to finalize or iterate), continuing until successful execution or a maximum iteration limit is reached.

## Results

On MLE-bench Lite (21 Kaggle competitions), MLZero achieves an 86% success rate and average rank of 1.43, securing 6 gold and 2 silver medals, outperforming AIDE (81%, rank 2.36), OpenHands (71%, rank 2.93), and MLAgentBench (62%, rank 3.29). On the authors' Multimodal AutoML Agent Benchmark (25 raw multimodal datasets), MLZero achieves a 92.0% success rate and average rank of 2.42, a +263.6% improvement in success rate over the best competitor (Codex CLI +rea at 69.3%). Even with a compact Llama 3.1 8B backbone, MLZero maintains a 45.3% success rate, surpassing all full-size baseline systems. In terms of efficiency, MLZero uses 4.3× fewer tokens than AIDE (63k vs. 273k per dataset) at only 23% of its cost ($0.19 vs. $0.82).

## Baselines & Comparisons

MLZero outperforms all six baselines on both benchmarks across every metric. On the Multimodal AutoML Agent Benchmark, MLZero's 92.0% success rate exceeds the strongest competitor, Codex CLI with a reasoning model (+rea), by 22.7 percentage points (92.0% vs. 69.3%), and AIDE with external knowledge (+ext) by 46.7 points (92.0% vs. 45.3%). AIDE's default configuration (25.3%), AutoKaggle (20.0%), Codex CLI default (14.7%), and DS-Agent (13.3%) all trail MLZero by wide margins. On MLE-bench Lite, MLZero leads AIDE by 5 points in success rate (86% vs. 81%) and by nearly a full rank position (1.43 vs. 2.36). Notably, MLZero's compact 8B variant (45.3% success) still surpasses AIDE default (25.3%), AutoKaggle (20.0%), and DS-Agent (13.3%), demonstrating that the multi-agent architecture compensates for smaller model capacity. The error analysis further highlights MLZero's robustness: only 6.5% of failures overall versus 47.8% for AIDE and 76.0% for DS-Agent, with MLZero completely eliminating perception, postprocessing, and API hallucination errors.

## Relation to Prior Work

MLZero extends the line of LLM-agent-based AutoML work (AIDE, DS-Agent, AutoKaggle, MLAgentBench) by introducing two architectural departures: a dedicated perception module that replaces hard-coded preprocessing with automated data understanding, and a dual-memory system (semantic memory for curated library knowledge, episodic memory for error tracking) that addresses LLM hallucination and outdated API knowledge. Unlike prior agentic AutoML systems that operate on preprocessed or tabular-only data, MLZero targets raw, multimodal inputs (tabular, text, image, document) with zero human intervention, and it integrates with the AutoGluon library ecosystem rather than generating code from scratch. The paper also introduces a new evaluation benchmark (Multimodal AutoML Agent Benchmark) specifically designed to test end-to-end capability on unprocessed data, addressing what the authors identify as a methodological limitation of MLE-bench's reliance on task-specific preprocessing scripts.

## Why It Matters / Open Questions

The 92% success rate on the new benchmark (vs. 25.3% for AIDE) and the finding that a compact 8B LLM (Llama 3.1 8B) outperforms full-size systems from competing approaches suggest that multi-agent architecture design can compensate for model scale in structured ML automation tasks, with practical implications for deployment cost. The systematic elimination of perception and API-hallucination error categories (0% vs. 7.7% and 3.8% for Codex CLI+rea) points to a design pattern—perception-first with retrieval-augmented memory—that could generalize to other domain-specific agent systems. Open questions include scalability to libraries with sparse documentation, handling of undocumented library bugs, and whether the performance gap persists as competing systems adopt similar perception and memory mechanisms; the self-constructed benchmark also limits direct comparability with MLE-bench results.
