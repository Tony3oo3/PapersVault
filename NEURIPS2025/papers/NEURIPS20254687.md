## Problem

Existing code-generation benchmarks evaluate LLMs on established algorithms or use subjective LLM-as-judge scoring, leaving it unclear whether models can faithfully implement genuinely novel ML contributions that postdate their pretraining cutoff. ResearchCodeBench targets this gap by asking whether LLMs can read a cutting-edge research paper and produce correct, executable code for its core algorithmic ideas—ideas the model has never seen during training.

## Input / Output

Each task provides the full research paper (~30k tokens), a source file with one or more masked code regions marked by TODO comments, a set of contextual dependency files, and a concise natural-language hint describing the intended purpose of the missing code. The model must generate the exact replacement code preserving indentation, which is then spliced back into the file and executed against a suite of unit tests and equivalence tests. The benchmark reports pass@1 (greedy decoding, first-attempt correctness) per task, aggregated over the full 212-task set and a 109-task HARD subset (bottom 50% by aggregate pass rate across all models).

## Method

The benchmark is constructed from 20 recent ML papers (ICLR, NeurIPS, CVPR, arXiv, 2024–2025) selected via a 5-axis rubric. For each paper, core contributions are identified and annotated with nested XML-style tags at multiple granularity levels (function-level down to line-level), creating a hierarchical task structure where inner snippets are guaranteed no harder than their enclosing outer snippet. Evaluation uses a hybrid of equivalence tests (running predicted and reference implementations on identical inputs) as the default check, supplemented by hand-written unit tests for edge cases—deliberately avoiding LLM-as-judge for reliability. Contamination risk is controlled by comparing repository first-commit dates against model knowledge cutoffs, yielding a 13-paper contamination-safe subset. The benchmark is designed to run locally in a single Docker/Conda environment with no GPU, averaging 1.25 s per task, and supports community-driven expansion via a web submission pipeline.

## Results

On ResearchCodeBench-HARD (109 most challenging tasks), the best model Gemini-2.5-Pro-Preview-05-06 achieves only 33.0% Pass@1, followed by O4-Mini (High) at 28.4% and O3 (High) at 25.7%. Four models (Llama-3.3-70B, Llama-4-Scout, Qwen-2.5-Turbo, Mistral-Codestral-Mamba) achieve 0.0% Pass@1, and 43 tasks see 0% success across all 32 evaluated models. On the full 212-task benchmark, the top model reaches 64.2% Pass@1, while a human expert baseline achieves 77.5% on a 102-task subset, outperforming the best LLM (68.6%) by roughly 9 percentage points.

## Baselines & Comparisons

This benchmark paper evaluates 32 LLMs from 10 companies rather than comparing a single method against baselines. On ResearchCodeBench-HARD, Gemini-2.5-Pro-Preview-05-06 leads at 33.0% Pass@1, outperforming OpenAI's reasoning models O4-Mini (High) (28.4%) and O3 (High) (25.7%) by 4.6 and 7.3 percentage points respectively. Claude models (3.5-Sonnet, 3.7-Sonnet) cluster around 13.8%, roughly half the performance of the top Gemini model. A persistent gap exists between proprietary frontier models and open-source alternatives: the best open model (DeepSeek-R1 at 9.2%) trails the best proprietary model by over 24 percentage points, and four open models score 0%. On the contamination-safe 13-paper subset, all models show a noticeable performance drop, but reasoning-oriented models (Gemini-2.5-Pro, O3 High) maintain their advantage over standard models (GPT-4.1, Claude 3.5 Sonnet). A human expert baseline achieves 77.5% Pass@1 on a 102-task subset, exceeding the best LLM (68.6%) by ~9 points, though the human had access to iterative debugging tools unavailable to the single-turn LLM evaluation.

## Relation to Prior Work

This paper carves out a distinct niche among existing code-generation and research-reproduction benchmarks. General coding benchmarks (HumanEval, MBPP, SWE-bench) target established algorithms or bug fixes, while research-oriented benchmarks (SUPER, CORE-Bench, SciCode) focus on environment setup and reproducibility of existing code. The most directly related work, PaperBench, evaluates end-to-end paper replication but entangles conceptual implementation with broader software engineering and relies on LLM-based judgment. ResearchCodeBench departs by isolating the core algorithmic implementation challenge, using deterministic execution-based tests (unit tests + equivalence tests) rather than subjective LLM-as-judge scoring, and targeting specifically post-training-cutoff novel contributions from 2024–2025 papers.

## Why It Matters / Open Questions

The benchmark reveals a substantial and quantified gap: even the best model achieves only 33% on the HARD subset, and 43 tasks see 0% success across all 32 evaluated models, indicating that current LLMs lack the deep algorithmic reasoning needed for cutting-edge research implementation. The lightweight design (1.25s per task, no GPU) and community-driven expansion pipeline make it a practical, continuously growing evaluation resource. Key open questions include whether agentic multi-turn approaches with iterative debugging can close the gap (the human baseline with compiler feedback outperforms the best LLM by ~9–19 points), whether automated test generation can scale beyond the current manual process, and whether the benchmark generalizes beyond ML to other scientific domains.
