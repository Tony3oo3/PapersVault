## Problem

Construction-based tree-search methods for LLM code generation suffer from rapid tree growth, excessive token consumption, and lack of anytime property, while existing improvement-based methods rely on uninformative reward signals (binary pass rates on few public test cases or hallucination-prone LLM self-evaluation) that fail to guide iterative code revision effectively. The paper addresses how to perform efficient, step-by-step code revision with a lightweight local search framework that provides fine-grained candidate ranking even when correctness signals are uninformative.
![Teaser figure](../imgs/NEURIPS20255275/cropped_page1_idx0.webp)

## Input / Output

The method takes a natural-language problem statement, 2–3 public test cases, and execution feedback (pass/fail with error messages) from running the current code against those test cases. It iteratively produces revised code samples within a fixed 7K-token budget per problem, ultimately returning a single best-so-far code sample. The framework is instantiated as either Hill Climbing (one incumbent per iteration) or Genetic Algorithm (two fitness-selected parents per iteration), with 5 initial draft codes and 3 neighborhood candidates generated per iteration.

## Method

ReLoc frames iterative code revision as a local search with four pluggable components—DRAFTCODE (Plan-then-Generate initial population), GENERATENEIGHBORHOOD (LLM proposes K revisions guided by natural-language strategies or parent-code crossover), EVALUATECANDIDATES (synergistic scoring via public test pass/fail plus a learned reward model), and UPDATEINCUMBENT (greedy selection). The key innovation is a revision reward model trained with Bradley-Terry pairwise preferences derived from revision distance: code trees are built by breadth-first LLM revision of incorrect code, each node is labeled with the minimum number of steps to reach a correct descendant, and win/loss pairs are formed from local neighborhoods (parent, children, siblings). This reward model differentiates incorrect candidates by their proximity to correctness in textual space, providing informative search direction even when all candidates share the same binary pass rate. The framework is instantiated as Hill Climbing and Genetic Algorithm, with the GA variant adding an aging mechanism to maintain parent diversity.

## Results

Under a fixed 7K token budget, ReLoc_HC achieves 38.4% Pass@1 on LiveCodeBench code generation and 33.4% on code repair, while ReLoc_GA reaches 15.3% and 11.5% on TACO code generation and repair respectively. This represents a 33.8%→38.4% improvement on LiveCodeBench and an 11.5%→15.3% gain on TACO over the strongest baseline (Plan Search), while reducing token consumption by 37%. The revision reward model further outperforms an outcome-based reward model (ORM-7B) by 2.5% on LiveCodeBench (38.4% vs. 35.9%) and 3.6% on TACO (13.3% vs. 9.7%).

## Baselines & Comparisons

ReLoc_HC dominates all construction-based baselines (RAP, ToT) by 12.8–15.5 percentage points on LiveCodeBench code generation, benefiting from the anytime property that avoids the tree-size explosion of step-by-step construction. Among improvement-based methods with self-evaluation, ReLoc_HC outperforms the strongest (Plan Search) by 5.7% on LiveCodeBench code gen and 2.1% on code repair, while ReLoc_GA surpasses Plan Search by 4.1% on TACO code gen, suggesting GA's crossover mechanism is more effective on harder tasks. Against pass-rate-based methods (BoN, SFS, ORPS), ReLoc_HC gains 6.3–9.6% on LiveCodeBench code gen, demonstrating that the revision reward model provides substantially more informative guidance than binary pass/fail signals. In the controlled reward-function ablation (Table 2), the revision reward model outperforms ORM-7B (same architecture, outcome-based training) by 2.5% on LiveCodeBench and 3.6% on TACO, and beats the larger Skywork-27B reward model by 6.5% on LiveCodeBench, confirming that revision-distance supervision is more effective than generic outcome scoring for guiding iterative code refinement.

## Relation to Prior Work

This paper repurposes classical local search (Hill Climbing, Genetic Algorithm) for LLM-based code generation, positioning itself against both construction-based tree search (ToT, RAP, MCTS) and existing improvement-based methods (Reflexion, CodeTree, SFS, Plan Search). Its key conceptual departure is the revision reward model, which ranks candidates by estimated revision distance to a correct solution rather than by correctness or pass rate, addressing the binary-signal problem when only 2–3 public test cases are available. The framework unifies these components into four pluggable decision rules, allowing different local search algorithms to be instantiated without architectural changes.

## Why It Matters / Open Questions

The revision-distance reward model offers a principled way to guide iterative code refinement when correctness signals are uninformative, and the demonstrated cross-model transfer (Qwen-trained reward model guiding GPT-4o search) suggests the approach could serve as a plug-and-play module across LLMs. Limitations include exploration of only two local search variants, a reward model trained on a 7B base rather than the 32B inference model, and evaluation restricted to Python competitive programming. Open questions include whether the framework extends to other languages, repository-level tasks, or more complex local search metaheuristics (simulated annealing, tabu search), and whether the revision-distance signal degrades on tasks where the solution space is highly non-local.
