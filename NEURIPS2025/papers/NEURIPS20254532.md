## Problem

Existing MLLMs for 3D spatial reasoning either require explicit 3D inputs (point clouds, reconstructed meshes) that limit flexibility and scalability, or rely on sparse egocentric video frames that suffer from incomplete perception and lack of global scene context. The paper asks whether MLLMs can perform robust 3D spatial reasoning using only structured 2D representations derived from a perception module, without any explicit 3D features at inference time.
![Teaser figure](../imgs/NEURIPS20254532/cropped_page0_idx1.webp)

## Input / Output

The MLLM receives a single 480×480 BEV image with question-filtered object marks (bounding-box projections drawn on the floor plane), a text block of object-centric metadata (categories, 3D coordinates), and optionally a small set of depth-aware egocentric keyframes when appearance cues are needed. Outputs are structured as either short factual answers (counts, distances) or long-form responses with explicit step-by-step geometric reasoning enclosed in <think> tokens followed by a final answer in <answer> tokens, covering tasks like relative direction, route planning, and object localization.

## Method

Struct2D is a perception-guided prompting framework that uses an off-the-shelf 3D perception pipeline (BundleFusion reconstruction + Mask3D/UniDet detection) purely as a preprocessing step to generate structured 2D inputs: a rotation-aligned BEV image with filtered object marks, object-centric metadata text, and depth-aware keyframes selected by projecting 3D bounding boxes onto candidate frames. A zero-shot analysis with GPT-o3 reveals that a single BEV image plus metadata achieves 96.5 on relative distance and 94.4 on relative direction, and that rotation alignment and structured guide prompts are critical for egocentric-to-allocentric reasoning. Building on these insights, the authors construct Struct2D-Set (200K QA pairs across eight spatial reasoning categories from 6K ScanNet/ScanNet++/ARKitScenes scenes) with ChatGPT-augmented reasoning traces, and fine-tune Qwen2.5VL via supervised instruction tuning, achieving 43.6 average on VSI-Bench—surpassing both the prompting-only variant and video-frame baselines—while requiring only 2D inputs at inference.

## Results

On VSI-Bench, the fine-tuned Qwen2.5-VL-7B (SFT) achieves the highest average score of 43.6 among all open-source models, surpassing the best prior baseline R1-Zero-VSI+SFT (38.8) by 4.8 points. Gains are most pronounced on spatial reasoning subtasks: relative direction (45.9 vs. 35.7) and route planning (35.8 vs. 33.0). On ScanQA, the model achieves BLEU-1 of 45.2 and CIDEr of 92.1, outperforming GPT4Scene (43.4 / 90.9) and Chat-Scene (43.2 / 87.7); on SQA3D it reaches EM-1 of 58.5 and EM-R1 of 61.3, exceeding GPT4Scene (57.4 / 60.7).

## Baselines & Comparisons

On VSI-Bench, the fine-tuned Qwen2.5-VL-7B (43.6 avg) outperforms R1-Zero-VSI+SFT (38.8) by 4.8 points, LLaVA-NeXT-Video-7B (36.3) by 7.3 points, and all other open-source baselines by at least 9.7 points. The method also surpasses its own Struct2D prompting variant (29.4) and the 16-frame video baseline (33.9), confirming that instruction tuning on Struct2D-Set is substantially more effective than zero-shot prompting or uniform video sampling. On ScanQA, the model (BLEU-1 45.2, CIDEr 92.1) edges out GPT4Scene (43.4, 90.9) and Chat-Scene (43.2, 87.7), while on SQA3D it leads GPT4Scene (EM-1 58.5 vs. 57.4) and Chat-Scene (58.5 vs. 54.6). Notably, the method uses only a single BEV image plus metadata at inference (vs. 9–16 frames for GPT4Scene and VSI-Bench baselines), achieving higher accuracy with fewer visual inputs and lower API cost ($27.25 vs. $78.67–$105.07 in the zero-shot GPT-o3 setting). The zero-shot GPT-o3 analysis further shows that with ground-truth objects, Struct2D prompting reaches 96.5 on relative distance and 94.4 on relative direction, far exceeding the 16-frame VSI-Bench baseline (51.0 / 49.4) and GPT4Scene (50.5 / 47.9).

## Relation to Prior Work

This paper extends the BEV-based 2D prompting line initiated by GPT4Scene [63], which first showed that bird's-eye-view images can serve as spatial cues for MLLMs. Struct2D departs from GPT4Scene by adding query-filtered object marks, object-centric metadata (categories, 3D coordinates), rotation-aligned BEV views, and depth-aware keyframe selection, and further moves from zero-shot prompting to large-scale instruction tuning. It also explicitly contrasts with the 3D point cloud LLM paradigm (Chat-3D, 3D-LLM, LL3DA) by eliminating the need for explicit 3D feature encoders at inference, and with video-based spatial reasoning (VSI-Bench, R1-Zero-VSI) by replacing multi-frame video input with a single structured 2D projection.

## Why It Matters / Open Questions

The core practical implication is that structured 2D projections (one BEV image + metadata) can substitute for both explicit 3D representations and multi-frame video, simplifying the inference pipeline and reducing cost (27.25$ vs. 105.07$ for 16 frames). The 200K-pair Struct2D-Set dataset provides a reusable resource for training spatial reasoners without 3D encoders. Key limitations include the dependence on offline 3D perception (BundleFusion + Mask3D/UniDet) for preprocessing, the indoor-only scene coverage, and the gap between GT-object (83.8) and noisy-object (56.1) performance, which highlights sensitivity to perception quality. Open questions include generalization to outdoor scenes, integration with real-time lightweight reconstruction, and whether the structured 2D paradigm scales to more complex multi-room or dynamic environments.
