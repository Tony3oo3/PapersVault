## Problem

Existing LLM serving systems (vLLM, SGLang, RouteLLM, Llumnix) are not optimized for the unique demands of agent serving: predictable high-frequency request patterns, rapidly growing multi-round contexts with middle truncation, and increasing task difficulty over session lifetime. These systems lack session-awareness, leading to low KV cache hit rates, inaccurate model selection, and an inherent cost-quality tradeoff where higher quality always requires more expensive models.

## Input / Output

The system consumes structured agent prompts consisting of a non-truncatable shared prefix (tool descriptions, few-shot examples), a non-truncatable task-specific template, and a truncatable interaction history that undergoes middle truncation (removing oldest entries) rather than prefix truncation. Each request carries a session ID that the server uses for cache tracking. The output is the LLM's chain-of-thought response with actions, accompanied by a quality indicator from the R-Judge that can trigger retry, service-upgrade migration to a larger model, or session restoration to a prior checkpoint. The model hierarchy (Llama-8B → Llama-70B → GPT-4o) and quality threshold θ are configurable per deployment.

## Method

AGSERVE combines three session-aware components. The Session-Aware Server (SAS) enables KV cache reuse under middle truncation via in-place positional embedding calibration: cached keys are rotated by e^{i·δ_p·θ} (where δ_p is the negative number of truncated tokens) using precomputed RoPE cos/sin tables, avoiding the 2× memory overhead of CachedAttention's decoupled cache. For eviction, SAS uses an ETA-based policy (ECE) that predicts each session's next request arrival time from round-duration history and solves a knapsack-like dynamic program to minimize total time-to-first-token across affected sessions. The Session Guard Client (SGC) performs session-level model cascading: a BERT-based Q-Judge with an asymmetric loss (penalizing overkill α_i=1 vs. underkill α_i<1) selects the initial model, while a DistilBERT-based R-Judge periodically scores response quality against a user-set strictness threshold θ, triggering migration or restoration. The Resource Scheduler (RS) dynamically reallocates GPU instances across models based on real-time demand-to-supply ratios, consolidating same-model instances to exploit parallelism.

## Results

AGSERVE achieves comparable response quality to GPT-4o at only 16.5% of the cost on the AlfWorld agent, and reduces overall agent serving cost by 83.5% while maintaining similar quality. At the same cost budget, AGSERVE delivers 1.8× higher quality relative to the cost-quality tradeoff curve across all four evaluated agents. In multi-agent serving, AGSERVE reduces cost by 64% and achieves 1.6× quality compared to the adapted state-of-the-art Llumnix++ system. The session-aware KV cache management (ECE + in-place calibration) raises cache hit rate by 2.86× over LRU and reduces round latency by up to 50%, while dynamic GPU allocation accelerates serving by 1.2×.

## Baselines & Comparisons

Against vLLM (Kwon et al., SOSP 2023), AGSERVE's session-aware server achieves a 2.86× higher KV cache hit rate and up to 2× per-request latency reduction (Fig 10), with negligible quality discrepancy, confirming that in-place positional embedding calibration and ETA-based eviction are effective for agent workloads. Against RouteLLM (Ong et al., ICLR 2025), AGSERVE's Q-Judge achieves 70.4% routing accuracy versus RouteLLM's 57.9% (Table 1), and critically, RouteLLM performs *below* the cost-quality tradeoff curve in all four agents (Fig 8) because it treats each request independently without session awareness. Against Llumnix++ (Sun et al., OSDI 2024), AGSERVE reduces multi-agent serving cost by 64% while achieving 1.6× higher quality (Fig 9), as Llumnix++ requires each node to run the same model and lacks session-level cascading. Against GPT-4o (Achiam et al., 2023) as a quality reference, AGSERVE matches its response quality at only 16.5% of the API cost on AlfWorld, demonstrating that the session-aware cascading strategy (Llama-8B → Llama-70B → GPT-4o) effectively transcends the traditional cost-quality tradeoff.

## Relation to Prior Work

AGSERVE builds on the KV cache management lineage of vLLM (PagedAttention) and SGLang, but departs by introducing session-awareness: in-place RoPE calibration handles the middle-truncation pattern unique to agents (whereas CachedAttention requires a memory-doubling decoupled cache), and ETA-based eviction replaces LRU by exploiting the predictable inter-request timing of agent sessions. On the model-selection side, it extends the cascading tradition of FrugalGPT and Tabi and the routing approach of RouteLLM/HybridLLM, but treats requests within a session as correlated rather than independent, adding a real-time R-Judge for mid-session quality monitoring that prior systems lack. The dynamic GPU scheduler draws on Llumnix's multi-instance scheduling but adds demand-supply-ratio-driven reallocation across heterogeneous model sizes, a dimension absent in single-model serving systems.

## Why It Matters / Open Questions

As LLM agents proliferate across enterprise and consumer applications, the economic viability of serving them at scale becomes critical; AGSERVE's 83.5% cost reduction at GPT-4o-equivalent quality directly addresses this. Key limitations temper the claims: evaluation covers only four agents and the Llama-3 family plus GPT-4o, multi-agent traces are synthetic (no real agent-launch data exists), and the R-Judge's sensitivity to the θ threshold means quality guarantees are tunable rather than absolute. Open questions include whether the session-to-instance binding generalizes to large-scale distributed deployments, whether in-flight session migration can further improve load balance, and whether the techniques transfer to non-Llama architectures with different positional encodings.
