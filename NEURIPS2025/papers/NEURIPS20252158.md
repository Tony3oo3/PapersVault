## Problem

Improving LLM agents for sequential decision-making tasks has relied heavily on task-specific knowledge engineering—hand-crafted prompts, curated in-context examples, and custom observation/action spaces—making performance gains scale with human effort rather than with the agent's own experience. This paper asks whether agents can autonomously bootstrap their performance by accumulating and strategically curating their own successful trajectories as in-context examples, without any task-specific engineering.

## Input / Output

At each decision step, the agent receives a natural-language task goal, the current environment observation, and retrieves the top-k most relevant trajectory segments from a growing database using multi-key KNN (cosine similarity over goal, plan, and reasoning/observation embeddings via all-MiniLM-L6-v2). The output is a sequence of environment actions (up to T steps) plus, at the system level, a curated trajectory database where each entry is a complete episode tuple (goal, plan, observation-reasoning-action sequence, success flag). Retrieval operates at two granularities: trajectory-level for the initial plan and state-level with a sliding window for per-step reasoning and action selection.

## Method

The core mechanism is Traj-Bootstrap: a ReAct-style agent (plan → reason → act loop) that stores only successful trajectories (s=1) into a database, creating a positive feedback loop where prior successes guide future attempts via in-context retrieval. Two curation layers refine this: (1) +DB-Curation applies population-based training by maintaining N=5 parallel database instances and periodically replacing the worst-performing database with a copy of the best, preserving emergent collective properties like coverage and complementarity; (2) +Exemplar-Curation computes a retrieval-weighted quality metric Q(τ) = Σ(oᵢ·fᵢ(τ))/Σ(fᵢ(τ)) that scores each trajectory by how often it is associated with successful outcomes when retrieved, then selects the single highest-scoring trajectory per task across all databases to form a composite database. The combination of both curation levels achieves 93% on ALFWorld with GPT-4o-mini, surpassing methods that use stronger LLMs and hand-crafted observation/action spaces, while shifting all computational cost to a one-time training phase with identical test-time inference cost as the baseline.

## Results

On ALFWorld, the full method (Traj-Bootstrap + DB-Curation + Exemplar-Curation) achieves 93% success rate with GPT-4o-mini, up from 73% for the Fixed-DB baseline. On InterCode-SQL, the best method reaches 82% (vs. 75% baseline), and on Wordcraft, +Exemplar-Curation alone achieves 72% (vs. 55% baseline). The 20-point boost on ALFWorld exceeds the 15-point improvement from upgrading the underlying LLM from GPT-4o-mini to GPT-4o, and matches the performance of allowing 3 test-time attempts per task.

| Method | ALFWorld | InterCode-SQL | Wordcraft |
|---|---|---|---|
| Fixed-DB | 0.73 ± 0.02 | 0.75 ± 0.01 | 0.55 ± 0.03 |
| Traj-Bootstrap | 0.89 ± 0.01 | 0.79 ± 0.01 | 0.64 ± 0.03 |

| +Exemplar-Curation | 0.90 ± 0.02 | 0.81 ± 0.01 | **0.72 ± 0.02** |
| +DB+Exemplar-Curation | **0.93 ± 0.03** | **0.82 ± 0.01** | 0.69 ± 0.01 |

## Baselines & Comparisons

Against AutoManual [4], which uses hand-crafted observation/action spaces and a stronger LLM (GPT-4-turbo + GPT-4o-mini) to achieve 91% on ALFWorld, the paper's +DB+Exemplar-Curation with only GPT-4o-mini reaches 93%, outperforming it by 2 points without any task-specific engineering. Against AutoGuide [12], a hierarchical rule-learning approach using GPT-3.5-turbo + GPT-4-turbo that achieves 79% on ALFWorld with 100 training tasks, the paper's best method achieves 86% with GPT-4o-mini at the same 100-task budget, and 93% at 3500 tasks. On InterCode-SQL, the hand-crafted GameSQL agent [38] achieves 73% (matching Fixed-DB's 74%), while GameSQL+Cheat (with privileged database schema access) reaches 84%; the paper's +DB+Exemplar-Curation achieves 82%, nearly closing the gap that the 'cheat' provides. The paper also shows that its 20-point ALFWorld improvement exceeds the 15-point gain from upgrading GPT-4o-mini to GPT-4o, and that cross-model transfer to Mixtral 8x7B yields +28 points on ALFWorld, confirming the databases capture task structure rather than model-specific artifacts.

## Relation to Prior Work

This paper extends the ReAct agent architecture (Yao et al., 2023) and retrieval-augmented planning (Kagaya et al., 2024) by reframing agent self-improvement as a trajectory database construction problem rather than an architectural or prompting problem. Where prior self-improvement methods either optimize a single task (Reflexion, search-based approaches) or add hierarchical complexity (AutoGuide's rule extraction, AutoManual's hand-crafted observation/action spaces), this work keeps the agent architecture fixed and instead focuses on how to collect and curate self-generated successful trajectories for dynamic in-context retrieval. The database-level curation mechanism directly adapts population-based training (Jaderberg et al., 2017) from hyperparameter optimization to example-set propagation, while the exemplar-level quality metric draws an analogy to value-function estimation in RL.

## Why It Matters / Open Questions

The practical impact is significant: a one-time ~$600 training investment yields a 93% ALFWorld success rate that surpasses methods using more powerful LLMs and hand-crafted task-specific components, while maintaining per-task inference costs an order of magnitude below GPT-4o. The cross-model transfer result (GPT-4o-mini-collected databases improving Mixtral 8x7B by +28 points) suggests the databases capture task structure rather than model-specific artifacts, broadening applicability. Open questions include whether the approach can bootstrap from zero human examples (Appendix I shows it underperforms with initial exemplars), how to productively leverage failed trajectories beyond the exemplar curation metric, and whether success rates can be made monotonically increasing with database size.
