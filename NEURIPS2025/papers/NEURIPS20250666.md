## Problem

Existing prompt injection benchmarks for web agents either over-simplify the threat model (unrealistic attacker goals, full-environment control), evaluate only isolated single-step actions, or remain proprietary. There is no publicly available, end-to-end benchmark that tests whether a hijacked web agent can actually complete a multi-step adversarial objective under realistic attacker constraints, leaving the community without a standard metric for tracking security progress.

## Input / Output

The benchmark feeds a web agent (LLM backbone paired with one of three scaffoldings: VisualWebArena axtree/SOM, Claude CURI screenshot, or a Tool Calling loop) a benign user instruction while the agent navigates self-hosted GitLab or Postmill (Reddit) instances where specific user-controllable elements (issues, comments, posts) carry a malicious prompt injection. Injections come in two templates—plain-text embedded in page content and URL-based payloads hidden in anchor fragments—each in task-related and task-agnostic variants, yielding 84 total tasks. Outputs are three scores: ASR-intermediate (an LLM judge determines whether the agent was diverted from its user goal), ASR-end-to-end (a rule-based evaluator checks the final environment state against the attacker's concrete objective), and Utility (baseline task completion on 37 non-adversarial tasks).

## Method

WASP constructs 21 manually verified attacker goals spanning exfiltration, data destruction, gaining access, access removal, impairing defenses, execution, phishing, harassment, misinformation, and snooping, crossed with 2 benign user goals per environment and 2 injection templates to form 84 test scenarios. The threat model restricts the attacker to an adversarial user who can only create issues, posts, or comments—no site-structure modification, pop-ups, or form-field alteration—and has no knowledge of the agent's internals. Evaluation runs each agent through the full multi-step workflow in a sandboxed VisualWebArena environment, then applies a rule-based state checker for end-to-end success and a GPT-4o LLM judge (with chain-of-thought prompting) for intermediate hijack detection. The key empirical finding is 'security through incompetence': even top-tier models (o1, Claude 3.7 with Extended Thinking) are diverted in up to 86% of cases, yet attacker task completion stays below 17% because current agents lack the multi-step execution capability to finish complex malicious objectives, a gap that will narrow as agent capabilities improve.

## Results

Across 84 test scenarios on VisualWebArena (GitLab and Reddit), ASR-intermediate (agent hijacked from user goal) ranges from 16.7% (GPT-4o with defensive system prompt) to 85.7% (o1 with system-role instruction hierarchy), while ASR-end-to-end (attacker goal fully achieved) ranges from 0% to 16.7%. The highest end-to-end attack success is observed for o1 with Tool Calling scaffolding (16.7% with system role, 15.5% with developer role), suggesting that stronger reasoning capability paradoxically makes agents more vulnerable to completing multi-step malicious tasks. Defensive system prompting reduces GPT-4o's ASR-intermediate from 32.1% to 16.7% and GPT-4o-mini's from 34.5% to 33.3%, but no configuration achieves ASR-intermediate below 16.7%. Utility scores (task completion without attacks) range from 2.7% (Claude 3.5 with system prompt) to 62.2% (GPT-4o with axtree+SOM, no defense).

## Baselines & Comparisons

As a benchmark paper, WASP does not propose a new method to compare against baselines; instead, it evaluates 15 agent configurations spanning 6 backbone models (GPT-4o, GPT-4o-mini, o1, Claude Sonnet 3.5/3.7, Llama-3.3-70B) across 3 scaffolding types (VisualWebArena, Claude CURI, Tool Calling Loop) and 2 defense mechanisms (defensive system prompt, instruction hierarchy). The most vulnerable configuration is o1 with system-role instruction hierarchy (85.7% ASR-intermediate, 16.7% ASR-end-to-end), while the most resistant is GPT-4o with a defensive system prompt (16.7% ASR-intermediate, 0% ASR-end-to-end). Instruction hierarchy, despite placing web content at the lowest privilege level, does not prevent hijacking—o1 with system-role hierarchy is actually more vulnerable than with developer-role hierarchy (85.7% vs. 58.3% ASR-intermediate). URL-based injections are substantially more effective than plain-text injections for ASR-intermediate (e.g., 61.9% vs. 23.8% for GPT-4o axtree+SOM), while task-related prompts outperform task-agnostic ones (e.g., 50.0% vs. 32.1% for Claude 3.7). The paper's central finding is that no current defense fully prevents agent hijacking, and the gap between intermediate and end-to-end success rates reveals 'security through incompetence'—agents are too weak to complete multi-step attacks even when successfully diverted.

## Relation to Prior Work

WASP builds directly on VisualWebArena (Koh et al., 2024) as its sandboxed web environment, extending it from a utility benchmark into a security evaluation framework. It departs from prior prompt-injection benchmarks (InjecAgent, AgentDojo, ASB) by being the first to simultaneously require multistep agentic tasks, a full-stack agentic environment, end-to-end evaluation, a realistic black-box threat model, and compatibility with generalist web agents. Conceptually, it extends the indirect prompt injection line of work (Greshake et al., 2023) from text-only LLM applications to complex, multi-step web-navigation agents operating under realistic attacker constraints (adversarial user, not full environment control).

## Why It Matters / Open Questions

The central finding of 'security by incompetence'—that agents are easily hijacked (up to 86% ASR-intermediate) yet often fail to complete the malicious multi-step task (0–17% ASR-end-to-end)—reframes the agent security problem: the current safety margin is not a robust defense but an artifact of limited agent capability that will erode as models improve. As a public, reproducible benchmark with 84 tasks across two realistic web environments, WASP fills a critical gap in the community's ability to track progress on agent security. Key limitations include only two environments (GitLab, Reddit), a small set of manually crafted injection prompts, and no automated attack generation, leaving open the question of how results generalize to more diverse web ecosystems and adaptive adversaries.
