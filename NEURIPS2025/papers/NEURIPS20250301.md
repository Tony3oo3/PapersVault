## Problem

Existing shape-to-code methods are constrained by limited domain-specific languages that can only model simple primitives (cubes, spheres, cylinders) and by small-scale paired datasets with few categories and low geometric complexity. This prevents them from reconstructing real-world objects with intricate multi-part structures, limiting their utility in reverse engineering and shape editing.

## Input / Output

The method takes a 3D point cloud (16,384 points at inference; 4,096–16,384 during training with Gaussian noise augmentation) and produces an executable Blender Python script that reconstructs the object as individually named, semantically labeled parts ordered spatially (bottom-to-top, left-to-right, front-to-back). The generated code is structured so that each part's geometry is defined by a small set of API calls (primitive, sweep, loft, Boolean, array), enabling direct parameter-level editing of shape and mesh resolution.

## Method

MeshCoder uses a two-stage training pipeline: first, a part-to-code model is trained on ~10 million synthetic part-code pairs generated by probabilistically sampling five expressive Blender Python API types (Primitive, Translation/sweep, Bridge Loop/loft, Boolean, Array); second, this model is applied part-by-part to Infinigen Indoor objects to construct a 1-million object-code dataset, on which the final object-to-code model is trained via transfer learning. The shape tokenizer projects the point cloud onto a triplane (256×256×32), patchifies the features, processes them through transformer blocks, and aggregates information into 128 learnable query tokens via cross-attention, which are then projected to the LLM's 2048-dim embedding space. A Llama-3.2-1B backbone fine-tuned with LoRA autoregressively generates the Blender Python script token-by-token using cross-entropy loss, jointly training the tokenizer and LLM. The key architectural insight is that the learnable tokens act as global information aggregators aligned with the LLM's processing patterns, outperforming direct MLP projection of triplane features.

## Results

On the Infinigen Indoor test set (41 categories), MeshCoder achieves an overall L2 Chamfer Distance of 0.063×10⁻² and a voxel IoU of 86.75%, substantially outperforming both baselines. Per-category IoU ranges from 81.87% (Chair) to 93.81% (Sofa), with CD values as low as 0.004×10⁻² (Lamp). The part-to-code inference model also achieves strong per-category performance, with IoU scores between 78.90% (Array) and 96.13% (Boolean) across the five shape types.

## Baselines & Comparisons

MeshCoder is compared against two shape-to-code baselines: Shape2Prog (Tian et al., ICLR 2019) and PLAD (Jones et al., CVPR 2022). MeshCoder decisively outperforms both on every reported category and on the overall average. Against Shape2Prog, the improvement is dramatic: overall CD drops from 6.01×10⁻² to 0.063×10⁻² (≈96× reduction) and IoU rises from 45.03% to 86.75% (+41.7 pp). Against PLAD, the gap is still substantial but narrower: CD improves from 1.87×10⁻² to 0.063×10⁻² (≈30× reduction) and IoU increases from 67.62% to 86.75% (+19.1 pp). Notably, PLAD is competitive on a few individual categories (e.g., Sofa IoU 81.33% vs. MeshCoder 93.81%), but MeshCoder leads on all five highlighted categories and the overall average. The paper also reports standard deviations (Table 3), showing MeshCoder's per-category variance is consistently lower than both baselines, indicating more stable reconstruction quality.

## Relation to Prior Work

This paper extends the shape-to-code inference line (Shape2Prog, PLAD, ShapeCoder, ShapeLib) by replacing their limited domain-specific languages—restricted to simple primitives like cubes and cylinders—with a comprehensive set of Blender Python APIs capable of expressing sweeps, lofts, Boolean operations, and arrays. Rather than training a single end-to-end model on a small paired dataset, MeshCoder introduces a two-stage pipeline: first training a part-to-code model on ~10M synthetic part-code pairs, then using it to bootstrap a ~1M object-code dataset from Infinigen Indoor before training the final object-to-code LLM. The use of a triplane-based shape tokenizer feeding a LoRA-finetuned Llama-3.2-1B as the code generator follows the broader trend of leveraging LLMs for structured output, but applies it to a substantially more expressive and complex code space than prior shape-program work.

## Why It Matters / Open Questions

By producing editable Blender Python scripts rather than opaque voxel or mesh outputs, MeshCoder enables direct geometric and topological editing through code modification and provides a structured, semantically rich representation that improves LLM reasoning about 3D object structure. The large-scale dataset (1M objects, 41 categories, up to 100+ parts) and the Blender API library are practical assets for the community. Key limitations include the focus on human-made objects (organic forms remain unaddressed), reliance on synthetic Infinigen data for training, and the absence of color/texture in the code representation. Open questions include generalization to real-world scanned objects, extension to organic geometries, and whether the two-stage part-to-object pipeline can be replaced by a more direct end-to-end approach.
