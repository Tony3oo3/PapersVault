## Problem

In sparse Mixture-of-Experts (MoE) Transformers, the router only receives gradient signals from the K experts it activates per token, leaving the remaining N−K experts with zero contribution to the router update. This sparse backward pass prevents the router from learning to route tokens toward experts it has not yet activated, causing training instability and suboptimal convergence. The paper asks whether the router can receive a dense gradient from all N experts without paying the forward-pass cost of activating them all.

## Input / Output

The method operates on standard token embeddings (d_token-dimensional vectors) within a Transformer whose feedforward layers are replaced by MoE layers. During the forward pass, only the Top-K experts are computed per token exactly as in standard MoE, and the output is a weighted sum of those K expert outputs for next-token prediction. The unusual aspect is in the backward pass: for the N−K non-activated experts, the router gradient is completed using precomputed default vectors (exponential moving averages of each expert's historical outputs) rather than actual expert activations, so the computation graph is artificially extended in the backward direction without any additional forward computation.

## Method

Default MoE maintains, for each expert i, an exponential moving average Ê_i^(t) = β Ê_i^(t−1) + (1−β) E̅_i(x) of its output over all tokens that activated it, updated during the standard forward pass at O(1) extra memory per expert. When backpropagating through the router, the non-activated expert terms in the dense gradient (which would normally be zero under Top-K routing) are replaced by these default vectors, so the router receives a nonzero gradient signal from every expert for every token. This corrects the gradient error introduced by Top-K selection: the residual error E_i(x) − E_x[E_i(x)] is zero in expectation, making the approximation unbiased. The default vectors are also passed forward through the network (not just used in the backward pass), which further reduces gradient error because the loss scaling in the error term is smaller when the default vectors improve the model output. Weighting the EMA updates by router logits makes the method robust to the choice of decay rate β, and the total computational overhead is under 2% in throughput with a negligible 0.03% increase in MoE parameter count.

## Results

On 13 standard NLP benchmarks after 160B tokens of pretraining (1.96B total params), Default MoE outperforms TopK MoE by +2.0% average score on the 8c1 configuration (47.9 vs 46.9) and +0.9% on the 32c4 finegrained configuration (49.3 vs 48.9). The largest individual gains include +15.2% on OpenBookQA (32c4), +6.6% on Lambada (8c1), and +6.1% on BoolQ (8c1). In terms of convergence speed, Default MoE reaches a target perplexity of 12.18 using 9% fewer tokens than TopK MoE, and on FineWeb it reaches perplexity 18 approximately 15% faster. Throughput overhead is negligible: only 0.18% slower on a 7.33B model and 1.85% on a 1.96B model.

## Baselines & Comparisons

Default MoE consistently outperforms the standard TopK MoE baseline (Fedus et al., 2022) across all five sparsity configurations (8c1, 8c2, 32c1, 32c2, 32c4) and all model sizes tested (557M to 7.33B params), with the gap widening at lower sparsity. Against Sparsemixer (Liu et al., 2023), Default MoE achieves a substantially lower validation perplexity (19.77 for Sparsemixer at 24B tokens vs. Default MoE's advantage over TopK which is already below that). ReMoE (Wang et al., 2025) fails to converge in the authors' setup: after a loss spike at 2B tokens it never recovers despite 1000+ GPU hours of experimentation. Loss-Free Balancing (Wang et al., 2024) underperforms Default MoE on validation perplexity (24.22 vs 23.48 at 10B tokens for 8c1). The authors note that their use of globally reduced auxiliary loss (Qiu et al., 2025) strengthens the TopK baseline, making the Default MoE advantage more meaningful than in prior comparisons.

## Relation to Prior Work

This paper extends the straight-through estimator (Bengio et al., 2013) to the MoE router setting, where the non-differentiable Top-K selection (Fedus et al., 2022) means the router only receives gradients from activated experts. Rather than computing all expert outputs (destroying sparsity) or using the standard sparse gradient (which zeros out non-activated experts), Default MoE substitutes missing expert outputs with exponential moving averages of previously observed outputs, yielding an approximate dense gradient at negligible cost. It departs from concurrent approaches like Sparsemixer (Liu et al., 2023), which estimates the true router gradient via sampling, and ReMoE (Wang et al., 2025), which replaces Top-K with differentiable ReLU routing, by keeping the standard Top-K forward pass entirely intact and only modifying the backward pass.

## Why It Matters / Open Questions

The practical impact is significant for MoE practitioners: a near-zero-overhead modification (0.18% throughput cost, 0.03% memory increase) that consistently improves convergence speed (~9% fewer tokens to target perplexity) and final benchmark scores across all tested sparsity levels, model sizes (557M–7.33B), and learning rates. The finding that Default MoE tolerates substantially higher learning rates without loss spikes—while TopK crashes—suggests the sparse backward pass was a hidden stability bottleneck, not just an efficiency one. Key limitations include evaluation only on dropless MoEs at 2B scale, absence of LLM-level benchmarks (MMLU-Pro, GSM8k, HumanEval), and no fine-tuning experiments; extending to token-dropping MoEs and larger-scale pretraining are the most important open questions.
