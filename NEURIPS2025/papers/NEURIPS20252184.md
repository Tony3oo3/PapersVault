## Problem

Training effective AI agents for multi-turn interactions requires high-quality data capturing realistic human-agent dynamics, yet such data is scarce and prohibitively expensive to collect manually. Existing synthetic data pipelines focus predominantly on single-turn function calling or lack the human-agent interplay essential for realistic multi-turn scenarios, leaving a gap in generating verifiable, diverse, and grounded multi-turn agent trajectories.
![Teaser figure](../imgs/NEURIPS20252184/cropped_page3_idx1.webp)

## Input / Output

The pipeline consumes API definitions (distinguished into read/write types), domain-specific policies, reference data with metadata, and user personas from PersonaHub as structured context for an LLM-based task generator. It produces two intermediate artifacts—verified task blueprints containing a user intent, a sequence of ground-truth tool-call actions, and expected final outputs—and then complete multi-turn interaction trajectories comprising dialogue turns, agent tool calls, and environment feedback. Each trajectory is validated by matching the final environment state diff against the ground-truth action sequence and checking agent responses against expected outputs, yielding a 5K-trajectory dataset with an average of 7 tool calls and 6 user turns per trajectory.

## Method

APIGen-MT is a two-phase agentic data synthesis framework. Phase 1 generates task blueprints via random walks over an API dependency graph, specialized context samplers (API, policy, domain data, persona, few-shot example), and a multi-stage validation loop combining automated format/execution/policy checks with an LLM review committee using majority voting; failed tasks trigger a reflection-based feedback loop for iterative refinement, and a Reverse Task Recombination step composes independently validated simpler tasks into complex long-horizon scenarios. Phase 2 simulates realistic multi-turn interactions by pairing a human LM (stabilized with Best-of-N sampling and self-critique to prevent drift) with a test agent (gpt-4o in function-calling mode) in an executable environment, where the human incrementally reveals task details while the agent invokes APIs; only trajectories whose final environment state and outputs match the Phase 1 ground truth are retained. The collected trajectories are then used for filtered behavioral cloning (predicting only assistant tokens) on Llama 3.1/3.2 and Qwen 2.5 backbones (1B–70B) via full fine-tuning with DeepSpeed ZeRO-3, jointly with single-turn APIGen data to preserve tool-calling format.

## Results

On τ-bench (pass@1, averaged over ≥5 trials), xLAM-2-70b-fc-r achieves 56.2% overall success rate (Retail: 67.1%, Airline: 45.2%), outperforming GPT-4o (52.9%), DeepSeek v3 (40.6%), and Llama 3.1 70B Instruct (38.2%), while approaching Claude 3.5 Sonnet (new) at 60.1%. On BFCL v3, xLAM-2-70b-fc-r ranks #1 with 78.19% overall accuracy and 75.12% multi-turn accuracy, surpassing GPT-4o (69.58% overall, 41% multi-turn) and o1 (67.87% overall, 36% multi-turn). Smaller variants also excel: xLAM-2-8b-fc-r reaches 46.7% on τ-bench and 69.25% multi-turn on BFCL, exceeding GPT-4o's multi-turn score by 28 points.

## Baselines & Comparisons

Against GPT-4o, xLAM-2-70b-fc-r wins on both benchmarks: 56.2% vs 52.9% on τ-bench and 78.19% vs 69.58% on BFCL, with a particularly large 34-point gap in multi-turn BFCL accuracy (75.12% vs 41%). Against o1, xLAM-2-70b loses on τ-bench (56.2% vs 63.9%) but wins decisively on BFCL (78.19% vs 67.87%), again dominated in multi-turn (75.12% vs 36%). Against Claude 3.5 Sonnet (new), xLAM-2-70b trails on τ-bench (56.2% vs 60.1%) but the gap narrows in the more complex Airline domain (45.2% vs 48.8%), and xLAM-2-70b achieves higher pass^5 consistency on Airline. Against open-source baselines (Llama 3.1 70B, DeepSeek v3, Qwen 2.5 32B, Gemini 1.5 Pro), xLAM-2-70b leads by 15.6–31.5 points on τ-bench overall. Notably, the 8B variant (46.7% τ-bench, 69.25% BFCL multi-turn) surpasses GPT-4o's multi-turn score, demonstrating that the synthetic data enables strong knowledge transfer to smaller models.

## Relation to Prior Work

This paper extends the APIGen framework [26] from single-turn function-calling data to multi-turn agent interactions, addressing a gap identified in prior work where BUTTON [11] required manual API construction and lacked quality control, and MAGNET [51] used graph-based path generation without human-agent interplay. The key methodological departure is the two-phase separation: first generating verified task 'blueprints' through an agentic pipeline with LLM committee review and reflection-based refinement, then using those blueprints to seed simulated human-agent conversations. Reverse Task Recombination, which composes independently validated sub-tasks into longer-horizon scenarios, draws on compositional instruction tuning [11, 18] but adds policy re-verification and semantic re-alignment for the combined task.

## Why It Matters / Open Questions

The paper tackles a fundamental bottleneck in agent development—the scarcity of high-quality, verifiable multi-turn interaction data—by providing both a reusable synthesis pipeline and a 5K-trajectory open-source dataset with trained models spanning 1B–70B parameters. The finding that the agentic feedback loop yields a 2.5× improvement in task generation success rate (28%→70%) and that smaller models trained on this data outperform frontier models like GPT-4o in multi-turn settings offers a practical path to more efficient agent training. Open questions remain around the stochasticity of human simulation (mitigated but not eliminated by Best-of-N self-critique), the computational cost of multi-stage validation, and whether failed trajectories could be repurposed as contrastive training signal. Extending the framework to new domains and integrating reinforcement learning are identified as promising next steps.
