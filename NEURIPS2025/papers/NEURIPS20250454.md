## Problem

State-of-the-art 3D point cloud transformers such as PTv3 and Sonata rely on dense token representations in every attention layer, incurring high computational and memory costs. This paper reveals that the vast majority of these tokens are redundant—preserving only 5–10% of the most spatially informative tokens suffices to maintain nearly identical performance—challenging the prevailing assumption that dense tokenization is essential for 3D transformer effectiveness.
![Teaser figure](../imgs/NEURIPS20250454/cropped_page1_idx1.webp)

## Input / Output

The method operates on 3D point clouds serialized via space-filling curves into disjoint partitions of 1024 points each, which are the standard input format for PTv3-family architectures. Token merging is applied at the feature level inside each attention layer (before the O(N²) computation) and an unmerging step restores per-point features to their original resolution, so downstream heads still produce full-resolution outputs: per-point semantic labels, novel-view renderings, or 3D bounding boxes. The method is applied off-the-shelf on pretrained checkpoints or with only 10% of the original fine-tuning schedule, requiring no architectural modification.

## Method

GitMerge3D constructs a bipartite graph connecting each token to the centroids of all spatial partitions and computes a globally informed energy score (mean negative cosine similarity to all centroids) that measures how aligned a token is with the global scene structure. Partitions with high energy (tokens less aligned globally, i.e., more locally distinctive) receive moderate merging, while low-energy partitions undergo aggressive merging, enabling up to 99% token reduction. Within each partition, tokens are divided into K spatial bins and destination tokens are randomly sampled per bin to preserve spatial coverage during merging. A learned unmerging function then expands the reduced token set back to the original resolution so that dense prediction heads remain compatible. The entire pipeline is plug-and-play: it requires no retraining for competitive results and, with minimal fine-tuning of only the MLPs flanking the attention layer, can even surpass baseline accuracy on ScanNet and S3DIS.

## Results

On 3D semantic segmentation, GitMerge3D applied to PTv3 with 80% token merging (fine-tuned) achieves 77.4 mIoU on ScanNet, 35.2 mIoU on ScanNet200, and 74.3 mIoU on S3DIS — nearly matching the full PTv3 baseline (77.6/35.2/74.7) while reducing FLOPs by 5.3× (107.5→19.9 GFLOPs) and peak memory by 6.4× (10.12→1.6 GB). On NuScenes outdoor segmentation, PTv3+Ours retains 78.0 mIoU (vs. 80.3 baseline) with 85% memory reduction (6.20→0.92 GB). For 3D reconstruction via SplatFormer, merging 90% of tokens yields only ~0.1% PSNR drop (24.56 vs. 24.71 on GSO-OOD), and for language-guided detection via SpatialLM, merging 80% of tokens actually improves F1 O50 (0.2006 vs. 0.1894) while cutting memory from 12.36 GB to 2.53 GB.

## Baselines & Comparisons

GitMerge3D (fine-tuned) nearly matches the full PTv3 baseline on all three indoor segmentation benchmarks (77.4 vs. 77.6 mIoU on ScanNet, 35.2 vs. 35.2 on ScanNet200, 74.3 vs. 74.7 on S3DIS) while removing 80% of tokens, and decisively outperforms all point-cloud downsampling baselines (RandomDrop, FPS, VoxelGrid) by 4–7 mIoU on ScanNet. Against prior 3D segmentation architectures, the fine-tuned merged model surpasses Swin3D (77.4 vs. 76.4), OctFormer (77.4 vs. 75.7), ST (77.4 vs. 74.3), PointNeXt (77.4 vs. 71.5), and MinkUNet (77.4 vs. 72.2) on ScanNet. On Sonata, fine-tuned GitMerge3D matches or exceeds the baseline (78.9 vs. 79.0 on ScanNet, 30.9 vs. 30.4 on ScanNet200, 73.5 vs. 72.2 on S3DIS) while reducing GPU memory from 211 GB to 75 GB during training. For 3D reconstruction, SplatFormer+Ours at 90% merging retains 24.56 PSNR on GSO-OOD (vs. 24.71 baseline), still outperforming MipNeRF360 (22.90), 3DGS (21.78), 2DGS (23.29), and Nerfbusters (15.95). For language-guided detection, SpatialLM+Ours at r=0.8 improves F1 O50 from 0.1894 to 0.2006 and F1 O25 from 0.3356 to 0.3485 while reducing inference time from 6.0s to 4.8s and memory from 12.36 GB to 2.53 GB. The key finding is that existing token-merging methods (ToMe, PiToMe, ALGM) designed for 2D ViTs degrade significantly at >50% merging on 3D data, whereas GitMerge3D's spatially-aware, globally-informed energy score enables 90–95% merging with minimal loss.

## Relation to Prior Work

This paper adapts token merging techniques originally designed for 2D vision transformers (ToMe's bipartite soft matching, ALGM's local binning, PiToMe's spectrum-preserving merging) to the 3D point cloud domain, where dense per-point predictions require an unmerging step absent in classification-oriented methods. It builds on the PTv3/Sonata architecture family and introduces a 3D-specific globally-informed energy score that guides adaptive, spatially-aware merging decisions, departing from the generic similarity-based matching used in prior 2D token reduction work. The paper also positions itself against input-level downsampling (FPS, VoxelGrid, Random Drop) by operating at the feature level within the network, and against architectural redesigns (MinkUNet, Sparse Point Transformer) by requiring no retraining from scratch.

## Why It Matters / Open Questions

The finding that 90–95% of tokens in state-of-the-art 3D point cloud transformers are redundant challenges a core design assumption in the field and opens a path toward substantially more efficient 3D foundation models without sacrificing accuracy. Practical impact is significant: 5.3× FLOPs and 6.4× memory reductions with minimal fine-tuning (10% of original epochs) make large-scale 3D deployment more feasible. Key open questions remain: the merge rate is manually set rather than learned end-to-end (sorting/grouping operations are non-differentiable), there is no formal theoretical framework quantifying token redundancy, and the method's generalizability beyond the PTv3 family to other 3D architectures (e.g., sparse convolutions, state-space models) is untested. The secondary finding that attention can be largely replaced by parameter-free pooling plus token shuffling (76.2 vs 77.3 mIoU) further questions the necessity of full self-attention in 3D point cloud processing.
