## Problem

Standard LLM code generation optimizes for perplexity, producing functionally correct but often inefficient code that runs 2.59–3.44× slower than human-written solutions. Existing efficiency-aware approaches require costly code execution during inference or fine-tuning on performance-annotated data, limiting their practicality. This paper asks whether a trained LLM's latent knowledge of code efficiency can be activated at inference time to guide generation toward faster, lower-memory code without any execution.

## Input / Output

The generation LLM receives a natural-language task description, a code prefix, and test examples, and produces a complete Python function. During decoding, the model samples tokens until a line-break boundary (statement level), at which point a separate critique LLM scores the partial code segment on a 0–1 scale. The final output is the single highest-rewarded program from a diverse candidate set (default n=50, top-p=0.95), so the pipeline emits one code snippet per task rather than a ranked list.

## Method

The core mechanism is an efficiency-aware reward function r(y≤l, q) = α·r_AST + β·r_LLM − γ·PP that combines three signals: (1) static AST pattern matching against 12 known performance anti-patterns (nested loops, redundant calls, inefficient data structures, etc.), (2) a prompted LLM critique that outputs a scalar efficiency score by evaluating time/space complexity, runtime, memory usage, AST structure, and perplexity of the code segment, and (3) the model's own perplexity as a regularizer. Decoding uses diverse candidate exploration—perplexity-based ancestral sampling at the token level with beam search (beam width > 1) at the statement level—repeated n times to build a candidate pool, from which the highest-rewarded program is selected. Crucially, no code is ever executed during inference; the LLM critique operates purely on the static text/AST of partial code, making the pipeline two to three orders of magnitude faster than execution-based baselines like EffiLearner and PerfCodeGen while achieving up to 94% average execution-time reduction and improved correctness.

## Results

On EffiBench, the proposed method reduces average execution time (ET Avg) by 92.0–96.6% and median execution time by 28.2–58.9% compared to standard perplexity-based decoding, while also lowering normalized memory usage (NMU) by 6.9–39.9%. Against the strongest efficiency-optimized baselines (EffiLearner, PerfCodeGen), the method achieves up to 94.1% lower ET Avg, up to 24.3% lower ET Median, and up to 20.7% lower NMU, while simultaneously improving correctness by up to 13.3 percentage points. Inference overhead is 2–3 orders of magnitude lower than execution-based baselines (e.g., 26.8 s vs. ~3,000–4,000 s for 8B models on EffiBench). Across all four benchmarks (EffiBench, Mercury, COFFE, HumanEval+) and five model architectures (6.7B–32B), the method consistently achieves the best or near-best efficiency and correctness scores.

## Baselines & Comparisons

Against **Self-Debug** [Chen et al., ICLR 2024], the proposed method wins on all efficiency metrics (ET Avg, ET Median, NET, NMU) across every model and dataset, while matching or exceeding correctness (e.g., 64.17% vs. 59.78% on OpenCoder-8b/EffiBench); Self-Debug's iterative correction loop does not explicitly target efficiency, so it yields minimal runtime gains. Against **EffiLearner** [Huang et al., NeurIPS 2024], the proposed method achieves a dramatic 92–94% reduction in ET Avg (e.g., 0.04 s vs. 0.68 s on OpenCoder-8b) and a 20.7% lower NMU, while also fixing EffiLearner's critical correctness failure (64.17% vs. 12.41% on OpenCoder-8b; EffiLearner stays below 15% on most models). Against **PerfCodeGen** [Peng et al., FORGE 2025], the proposed method reduces ET Avg by up to 94.1% (0.04 s vs. 0.64 s on OpenCoder-8b), lowers NMU by up to 20.7% (0.89 vs. 1.01), and edges out correctness (64.17% vs. 62.88%). In terms of practical overhead, the proposed method completes inference in 26–121 s per model on EffiBench, versus 3,000–22,000 s for the execution-feedback baselines—a 2–3 order-of-magnitude speedup in the generation pipeline itself.

## Relation to Prior Work

This paper sits at the intersection of inference-time scaling for code LLMs and static performance analysis. It repurposes the best-of-n diverse candidate exploration framework (Cobbe et al.) by replacing the correctness verifier with a composite efficiency reward that combines AST anti-pattern detection (adapted from Chen et al.'s performance anti-pattern literature) and an LLM-as-judge critique prompt. The key departure from prior efficiency-optimization methods (EffiLearner, PerfCodeGen) is the elimination of code execution during inference: instead of running generated code to obtain runtime feedback, the method scores candidates purely via static structural analysis and the critique LLM's learned efficiency assessment, reducing inference overhead by 2–3 orders of magnitude.

## Why It Matters / Open Questions

The paper addresses a well-documented gap—LLM-generated code runs 2.6–3.4× slower than human solutions—while offering a deployment-friendly solution that avoids the engineering burden of maintaining execution sandboxes during inference. The consistent gains across five models and four benchmarks, combined with the dramatic compute overhead reduction, make this a practical technique for production coding assistants. Open questions include generalization beyond Python, scalability to multi-file projects, and whether the LLM critique's efficiency scores truly capture algorithmic complexity or merely correlate with surface-level code patterns. The method's reliance on a separate critique LLM call per candidate also raises questions about cost at very large search spaces.
