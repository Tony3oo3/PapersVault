## Problem

Advancing LLM code reasoning is bottlenecked by the scarcity of large-scale, high-difficulty datasets with verifiable input-output test cases. Human-curated competitive programming datasets (CodeContests, TACO) provide quality problems but lack comprehensive test coverage, while synthetic code datasets (WizardCoder, KodCode) target function-level generation without competitive-level algorithmic difficulty. Critically, generating reliable test outputs for synthetic problems without oracle solutions remains an unsolved challenge at scale.

## Input / Output

The pipeline consumes competitive programming problem statements with explicit input constraints (e.g., array sizes up to 10^5, value ranges) and produces 418K verified problems paired with 580K long-reasoning code solutions, each validated against 50+ diverse test inputs spanning scales from 10^0 to 10^5. Test inputs follow the standard competitive programming multi-line format where the first line encodes scale-controlling parameters (array dimensions, grid sizes) and subsequent lines specify element values. The final dataset is fine-tuning-ready: each entry is a (problem, long-CoT solution) pair where the solution has been execution-verified against all generated test cases.

## Method

rStar-Coder constructs its dataset through three coupled mechanisms. First, it synthesizes 1.56M new problems from 37.7K expert-written seeds by prompting GPT-4o with structured prompts that include both the seed problem and its oracle solution, enabling the model to internalize algorithmic concepts and generate novel yet solvable variants. Second, it generates reliable test cases via a decoupled two-stage pipeline: a three-step input generation method where GPT-4o writes CYaRon-based utility functions (generate_test_input and validate_test_input) with exposed scale parameters, instantiated across ranges from 1 to 10^5; and a mutual verification mechanism that samples 16 long-CoT solutions from QWQ-32B and accepts outputs only when a majority produces identical results across all diverse test inputs (achieving 96.8% labeling accuracy vs. 12.7% for direct GPT-4o generation). Third, it augments seed problems with verified long-reasoning solutions by generating 16 QWQ-32B solutions per problem and retaining only those passing all generated tests, then fine-tunes Qwen2.5-Coder (1.5B–14B) for 6 epochs on the resulting 580K dataset.

## Results

On LiveCodeBench, rStar-Coder-14B achieves 62.5% pass@1 (up from 23.3% base), surpassing o3-mini (low) by 3.1% and R1-Distill-70B by 5.0%, while rStar-Coder-7B reaches 57.3% and even the 1.5B model hits 40.1%. On the highly challenging USACO 2025 benchmark, rStar-Coder-7B achieves 16.15% average pass@1, outperforming QWQ-32B (15.62%) despite being 4.5× smaller. On general code generation (HumanEval, MBPP), rStar-Coder-7B reaches 95.9% and 87.9% respectively, matching or exceeding Claude 3.5 Sonnet and GPT-4o.

## Baselines & Comparisons

Against DeepSeek-R1 distilled models, rStar-Coder-14B (62.5%) outperforms R1-Distill-70B (57.5%) by 5.0% and R1-Distill-32B (57.2%) by 5.3% on LiveCodeBench, though it trails the full DeepSeek-R1 (65.9%) by 3.4%. Against OpenAI's o3-mini (low) at 59.4%, rStar-Coder-14B leads by 3.1%, while o1 (63.4%) remains slightly ahead. On USACO 2025, rStar-Coder-7B (16.15%) and rStar-Coder-14B (17.19%) both surpass QWQ-32B (15.62%), the very model used to generate the dataset's reasoning solutions. Against OpenThoughts-family baselines, rStar-Coder-7B (57.3%) beats OpenThinker2-7B (37.4%) by 19.9% and OpenThinker-7B (25.5%) by 31.8% on LiveCodeBench, despite using a smaller dataset (580K vs. 1M). Against OCR (736K dataset), rStar-Coder-7B (57.3%) leads OCR-Qwen-7B (51.3%) by 6.0%, and rStar-Coder-14B (62.5%) edges out OCR-Qwen-32B (61.7%) by 0.8%. Against OlympicCoder (100K), rStar-Coder-7B (57.3%) wins by 16.4% on LiveCodeBench, demonstrating that dataset quality and problem diversity matter more than raw solution count.

## Relation to Prior Work

This paper carves new ground at the intersection of code data synthesis and solution verification. Prior code synthesis datasets (WizardCoder, Magicoder, KodCode) target function-level code generation with minimal or no test cases, while recent code reasoning datasets (OpenR1, OCR, OpenThinker) scale long-CoT solutions per problem but lack robust, verifiable test coverage. rStar-Coder departs from both by introducing a systematic pipeline—three-step constraint-aware input generation via CYaRon and a mutual-verification mechanism using majority agreement among multiple QWQ-32B solutions—that reliably labels test outputs without oracle solutions, addressing the verification bottleneck that limits all prior competitive-programming datasets.

## Why It Matters / Open Questions

The 418K verified competitive programming problems with 580K long-reasoning solutions represent the largest verified dataset for code reasoning to date, and the mutual-verification technique (96.8% labeling accuracy vs. 12.7% for direct GPT-4o generation) offers a reusable methodology for any domain requiring output verification without ground truth. The ablation showing that problem diversity outperforms solution-count scaling at comparable data sizes provides practical guidance for future dataset construction. Key limitations include heavy reliance on GPT-4o compute, inability to handle implicitly-stated constraints, and specialization to competitive programming rather than open-ended software engineering tasks like bug fixing or PR generation.
