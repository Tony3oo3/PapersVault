## Problem

Prior theoretical comparisons of language model architectures (transformers, RNNs, chain-of-thought) typically use tasks chosen to favor one model, leaving it unclear whether any single architecture is universally superior. This paper introduces Compositional Reasoning Questions (CRQs)—tree-structured problems generalizing Boolean formula evaluation—as a unified yardstick to rigorously compare the expressive power of deep transformers, RNNs, and shallow transformers with CoT tokens on the same task.
![Teaser figure](../imgs/NEURIPS20251825/cropped_page2_idx0.webp)

## Input / Output

The input is a rooted tree T=(V,E) where each node v is labeled by a vector x_v ∈ Γ^d over a finite vocabulary Γ of constant size. Each node is embedded with positional encodings that encode its own identifier, its parent's identifier, its depth in the tree, and a depth flag; for RNNs the nodes must be fed in a specific memory-rank-sorted order (a post-order DFS variant), while for CoT they use reverse BFS ordering. The output is the answer vector A(v_r) at the root, computed recursively as argmax over children of the inner product ⟨A(u), x_v⟩, which for Boolean formula evaluation reduces to a truth value.

## Method

The paper proves matching upper and lower bounds for each architecture on CRQs. For transformers, a depth-L construction with hardmax attention and O(log n)-bit positional encodings solves all CRQs of depth ≤ L by having each layer simultaneously resolve all sub-questions at one tree level; a TC^0 ≠ NC^1 lower bound shows constant depth is insufficient. For RNNs, a 5-layer network with O(d log n) hidden dimension simulates a stack machine over memory-rank-sorted inputs, keeping stack depth at O(log n); an adversarial ordering forces Ω(n) hidden dimension via a set-disjointness communication complexity reduction. For CoT, a 2-layer transformer generates exactly n tokens in reverse BFS order, each solving one sub-question bottom-up, improving on the O(n²) tokens required by prior arithmetic CoT constructions. Together these results show CRQs are NC^1-hard yet solvable by all three architectures, with each minimizing a different resource (depth, hidden dimension, or CoT token count) at the expense of others.

## Results

The paper proves that no architecture can solve all CRQs with constant resources: transformers require depth at least equal to the tree depth (Theorem 4.1) and constant depth is insufficient under TC⁰ ≠ NC¹ (Theorem 4.3); RNNs need O(log n) hidden dimension with memory-rank sort ordering (Theorem 5.4) but Ω(n) under adversarial ordering (Theorem 5.2); and CoT transformers need O(n) generated tokens (Theorem 6.1), with O(log n) tokens provably insufficient under TC⁰ ≠ NC¹. Table 1 quantifies the trade-offs: for a balanced binary tree of n nodes (depth log n), deep transformers use O(log³n) parameters with O(log n) parallel runtime, RNNs use O(log²n) parameters with O(n) parallel runtime, and CoT transformers use O(log²n) parameters with O(n) parallel runtime but O(n² log²n) sequential runtime.

**Table 1: Comparison of methods for solving CRQs on n nodes (balanced binary tree, depth log n).**

| Architecture | Num. Parameters | Runtime | Parallel Runtime |
|---|---|---|---|
| Deep transformer (Sec. 4) | O(L log²n) | O(Ln² log n) | O(L) |
| RNN (Sec. 5) | [O(log n), O(n)]² | [O(n log n), O(n²)] | O(n) |
| Chain of Thought (Sec. 6) | O(log²n) | O(n² log²n) | O(n) |

## Baselines & Comparisons

The paper does not benchmark against external baselines; instead it compares three architectural paradigms on the same CRQ task, revealing that each minimizes a different resource at the expense of others. Deep transformers are the most parallelizable (O(L) parallel runtime vs. O(n) for the others) but require depth to scale with tree depth, making model size input-dependent. RNNs achieve the best sequential runtime (O(n log n) vs. O(n² log²n) for CoT) and use modest parameters under favorable ordering, but their performance is fragile: adversarial input ordering inflates hidden dimension from O(log n) to Ω(n). CoT transformers use the fewest parameters (O(log²n), independent of n) and constant depth, but pay a quadratic sequential runtime cost and generate n tokens autoregressively. The paper also contrasts with Feng et al. [2024] on arithmetic: their CoT solution requires O(n²) tokens versus the O(n) tokens here, and their RNN lower bound of Ω(n) hidden dimension is improved to O(log n) under the memory-rank sort ordering. Overall, no architecture strictly dominates the others on all resource axes simultaneously.

## Relation to Prior Work

This paper builds on the circuit-complexity characterization of transformers (Merrill & Sabharwal 2023c, showing constant-depth transformers are in TC^0) and the chain-of-thought analysis of Feng et al. 2024 and Li et al. 2024, but departs from prior work by studying all three architectures—deep transformers, RNNs, and shallow transformers with CoT—on a single unified task rather than selecting tasks that favor one architecture. The CRQ framework generalizes Boolean formula evaluation (NC^1-complete) and arithmetic expression evaluation into a vector-based tree abstraction, enabling direct comparison. The RNN analysis introduces a novel memory-rank sort algorithm that reduces hidden dimension from O(n) to O(log n) under a specific input ordering, a result not present in prior RNN expressiveness work.

## Why It Matters / Open Questions

The paper provides the first rigorous, unified comparison showing that for a single reasoning task, each architecture must scale a different resource (depth, hidden width, or CoT tokens) with input size, and no architecture strictly dominates. This reframes the 'which architecture is best?' question as a multi-resource trade-off problem with concrete bounds. Key open questions include whether O(n) CoT tokens is optimal (the gap between the Ω(log n) lower bound and O(n) upper bound remains), whether the RNN solution generalizes to adversarial orderings without O(n) memory, and how these theoretical constructions relate to actual training dynamics and generalization.
