## Problem

Prior software-engineering benchmarks (SWE-Bench, SWE-Lancer) evaluate LLM agents on modifying existing codebases, but no systematic benchmark exists for the increasingly important task of generating complete, multi-file websites from scratch based on natural language instructions. This task demands high-level planning, multi-file codebase organization, and implementation of both functional and visual requirements, yet current evaluation methods are either absent or rely on costly manual testing.
![Teaser figure](../imgs/NEURIPS20252419/cropped_page2_idx0.webp)

## Input / Output

The benchmark takes a single natural-language instruction (median 483 characters, range 324–876) that specifies functional requirements (forms, authentication, data operations) and appearance constraints (color schemes, layout) for a target website. The agent produces a multi-file codebase (average 8.1 files, 315.3 lines) that is then evaluated by 4–11 test cases per instruction (647 total), each specifying a concrete UI operation and expected outcome. A web-navigation agent (WebVoyager powered by Qwen2.5-VL-32B-Instruct) executes each test case by simulating user interactions and returning YES/NO/PARTIAL, while GPT-4o separately grades visual aesthetics on a 1–5 scale.

## Method

The paper introduces a two-part pipeline: a data-curation stage and an automated evaluation stage. For curation, 40 CS student volunteers brainstorm 10,152 project descriptions across 20 application categories; GPT-4o converts these into detailed instructions, from which 101 are sampled for the test set and the remaining 6,667 (decontaminated via 5-gram Jaccard filtering and Sentence-Transformer cosine-similarity deduplication) form the WebGen-Instruct training set. For evaluation, WebVoyager executes each test case's operation on the generated website and a decision prompt forces a final YES/NO/PARTIAL verdict when the interaction budget is exhausted. To improve open-source models, the authors generate Bolt.diy trajectories with DeepSeek-V3 on a 2K-instruction subset, apply rejection sampling to retain only trajectories whose websites score ≥ 3 on appearance (yielding 600 trajectories), and fine-tune Qwen2.5-Coder-Instruct at 7B/14B/32B for 2 epochs (lr 4e-5, batch 32) to produce the WebGen-LM family, where WebGen-LM-32B reaches 38.2% accuracy—surpassing the best proprietary model (DeepSeek-R1 at 27.8%).

## Results

On WebGen-Bench (101 instructions, 647 test cases), the best general-purpose LLM combination—Bolt.diy with DeepSeek-R1—achieves only 27.8% accuracy, while Claude-3.5-Sonnet on Bolt.diy leads in appearance with a score of 3.0/5.0. After fine-tuning Qwen2.5-Coder-32B-Instruct on 600 Bolt.diy trajectories from WebGen-Instruct, the resulting WebGen-LM-32B reaches 38.2% accuracy, surpassing the best proprietary model by 10.4 percentage points. Smaller open-source models (Qwen2.5-Coder-32B: 9.5%, Qwen2.5-72B-Instruct: 13.8%) show a substantial gap compared to proprietary engines, and Bolt.diy consistently outperforms OpenHands and Aider across all tested models.

## Baselines & Comparisons

WebGen-LM-32B (38.2% accuracy) outperforms every proprietary LLM tested, beating DeepSeek-R1 (27.8%) by 10.4 points and Claude-3.5-Sonnet (26.4%) by 11.8 points on Bolt.diy. Among general-purpose LLMs, DeepSeek-R1 on Bolt.diy (27.8%) narrowly edges out Aider+DeepSeek-R1 (27.7%) and Claude-3.5-Sonnet on Bolt.diy (26.4%), while OpenHands+DeepSeek-R1 drops to just 10.2%, indicating framework choice matters as much as model choice. Claude-3.5-Sonnet leads in appearance scoring (3.0/5.0 on Bolt.diy) despite trailing DeepSeek-R1 in functional accuracy, suggesting a trade-off between visual quality and functional correctness. Open-source baselines Qwen2.5-Coder-32B (9.5%) and Qwen2.5-72B-Instruct (13.8%) lag far behind proprietary models, but after supervised fine-tuning on WebGen-Instruct trajectories, WebGen-LM-32B surpasses all of them. GPT-4o (12.8%) and o3-mini (19.6%) underperform relative to their general coding reputation, with o3-mini suffering a 38.6% start-failure rate that severely limits its effective accuracy.

## Relation to Prior Work

This paper departs from the dominant paradigm in software-engineering benchmarks (SWE-Bench, SWE-Lancer, SWE-Bench Multimodal), which all require models to modify or patch existing multi-file codebases, by introducing the task of generating complete website codebases from scratch based on natural language instructions. For evaluation, it builds on WebVoyager as the automated web-navigation agent to execute functional test cases, and draws inspiration from UXAgent's persona-based usability testing, though it replaces persona simulation with atomic, requirement-targeted test operations. The training methodology follows the trajectory-based fine-tuning approach used in prior code-agent post-training work (SWE-Gym, SWE-Fixer), but applies rejection sampling filtered by aesthetic quality to curate high-quality supervision signals.

## Why It Matters / Open Questions

WebGen-Bench fills a clear gap: no prior academic benchmark systematically evaluates whether LLM agents can build functional, multi-file web applications from natural language instructions, despite the commercial popularity of tools like Bolt.new and Lovable.dev. The finding that the best proprietary model (DeepSeek-R1) achieves only 27.8% accuracy underscores that this task remains far from solved, while the fact that a fine-tuned 32B open-source model with just 600 trajectories surpasses it by over 10 points suggests targeted data curation is a high-leverage path forward. Key limitations include restriction to TypeScript/JavaScript/CSS/HTML, reliance on supervised fine-tuning without RL or DPO, and a training set limited to 600 trajectories due to API budget constraints, leaving open whether further scaling or alternative post-training strategies would close the remaining gap.
