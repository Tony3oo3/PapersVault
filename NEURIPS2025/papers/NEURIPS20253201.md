## Problem

Recent R1-Zero-style GUI agents apply GRPO-based reinforcement learning with chain-of-thought reasoning templates to visual grounding, but it remains unclear whether these general-purpose RL components are actually beneficial for the grounding task. This paper identifies three concrete failures: longer reasoning chains degrade grounding accuracy, standard hit/IoU reward functions induce opposing box-size reward hacking, and GRPO's length and difficulty biases cause the model to under-optimize on harder samples.
![Teaser figure](../imgs/NEURIPS20253201/cropped_page0_idx0.webp)

## Input / Output

The model receives a GUI screenshot (variable resolution across Mobile, Desktop, and Web platforms) paired with a short textual grounding instruction (e.g., 'Click the search button'), and produces a single bounding box as four coordinates (x1, y1, x2, y2) in JSON format. Unlike prior R1-style agents that emit multi-step reasoning traces before the answer, GUI-G1 uses a Fast Thinking Template that elicits the bounding box directly, reducing average output from ~110 tokens (InfiGUI-R1) to ~38 tokens. The predicted box is evaluated against ground-truth boxes using center-point hit accuracy and IoU on ScreenSpot and ScreenSpot-Pro.

## Method

GUI-G1 modifies three components of the standard R1-Zero-like GRPO training pipeline for Qwen2.5-VL-3B-Instruct. First, a Fast Thinking Template replaces the Slow Thinking (chain-of-thought) template, forcing the policy to generate the bounding box without intermediate reasoning tokens. Second, the reward function combines R_Hit + 0.25·R_IoU + 0.125·R_Box, where R_Box penalizes predicted boxes whose size deviates from ground truth, regularizing against the size-biased reward hacking that R_Hit (shrinks boxes) and R_IoU (expands boxes) each induce independently. Third, the GRPO objective is modified by replacing the per-response length normalization |o_i| with a fixed Max_Tokens constant (eliminating length bias) and multiplying the per-sample loss by a difficulty weight w_q ∈ (0.5, 1.5] computed from the inverse of the target's relative box size, so that smaller (harder) targets receive larger gradient updates. Trained for one epoch on 17K public samples from UI-BERT and OS-Atlas using 4 H800 GPUs, the resulting GUI-G1-3B achieves 90.3% on ScreenSpot and 37.1% on ScreenSpot-Pro, surpassing larger R1-style and SFT baselines.

## Results

GUI-G1-3B achieves 90.3% average accuracy on ScreenSpot (98.6% Mobile Text, 85.8% Mobile Icon, 96.4% Desktop Text, 80.7% Desktop Icon, 91.4% Web Text, 82.3% Web Icon) and 37.1% on ScreenSpot-Pro, trained on only 17K public grounding samples with Qwen2.5-VL-3B-Instruct. It generates roughly one-third the output tokens of InfiGUI-R1-3B (37–39 vs. 107–114 tokens per example) while maintaining higher accuracy. The model surpasses all prior models of similar size and even outperforms the larger UI-TARS-7B (87.7% ScreenSpot, 35.7% ScreenSpot-Pro).

## Baselines & Comparisons

On ScreenSpot, GUI-G1-3B (90.3%) outperforms the previous best R1-style agent InfiGUI-R1-3B (87.5%) by 2.8 points, the larger UI-TARS-7B (87.7%) by 2.6 points, and the SFT-based UGround-v1-7B (86.3%) by 4.0 points, while using only 17K training samples versus 32K (InfiGUI-R1) or 13M (OS-Atlas-7B). On the harder ScreenSpot-Pro benchmark, GUI-G1-3B achieves 37.1% average, beating UI-TARS-7B (35.7%) and InfiGUI-R1-3B (35.7%) by 1.4 points, and substantially outperforming UGround-V1-7B (31.1%) and OS-Atlas-7B (18.9%). The one notable loss is on the ScreenSpot-Pro OS subset, where GUI-G1-3B scores 16.1% versus OS-Atlas-7B's 16.8%, which the authors attribute to the shared training data source rather than a methodological weakness. Compared to proprietary systems, GUI-G1-3B surpasses Gemini 2.0 Project Mariner (84.0%) and Claude Computer Use (83.0%) on ScreenSpot, though these proprietary models report only aggregate scores without per-domain breakdowns.

## Relation to Prior Work

This paper takes the R1-Zero-like RL training paradigm (GRPO applied directly to a base VLM without SFT) that has been adopted by recent GUI agent work (UI-R1, GUI-R1, InfiGUI-R1) and critically re-examines its three core components—template design, reward function, and policy update—specifically for the grounding subtask. It builds on the GRPO formulation from DeepSeekMath and the VLM-R1 training framework, while incorporating the length-bias analysis from Liu et al. (2025). The key departure is showing that the 'think before action' template, which prior R1-style GUI agents treat as essential, actually degrades grounding accuracy, and that standard reward functions (R_Hit, R_IoU) induce opposing box-size hacking that prior work had not identified.

## Why It Matters / Open Questions

The paper provides actionable guidance for anyone applying R1-Zero-style RL to GUI grounding: skip the reasoning template, add a box-size regularization term, and reweight by difficulty. Achieving SOTA (90.3% ScreenSpot, 37.1% ScreenSpot-Pro) with only 17K samples and ~3× fewer output tokens than InfiGUI-R1 demonstrates that the gains attributed to 'RL + reasoning' in prior work may largely come from the RL signal itself, not the chain-of-thought. Open questions include whether these findings transfer to action prediction and long-horizon planning (which the paper explicitly does not address), whether the difficulty proxy based on box size generalizes beyond grounding, and whether the approach scales to larger, more diverse training sets.
