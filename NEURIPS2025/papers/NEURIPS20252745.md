## Problem

Existing LLM agentic benchmarks face saturation because their natural completion states impose hard upper bounds on performance, limiting the ability to differentiate increasingly capable models. The paper introduces the Factorio Learning Environment (FLE), an unbounded evaluation framework where production throughput scales from ~30 resources/minute to millions per second, providing a reward signal that resists saturation as model capabilities grow.
![Teaser figure](../imgs/NEURIPS20252745/cropped_page1_idx0.webp)

## Input / Output

Agents generate Python programs in a persistent REPL namespace, calling 23 typed API methods (10 observation, 13 action) over a procedurally generated 4×10¹²-tile map; each submission returns stdout, stderr, and in-game wall-clock time as feedback. The environment implements partial observability via snapshot-based queries, so agents must explicitly re-query to refresh stale state references. Performance is measured by Production Score (a continuous, unbounded value computed from Factorio's built-in pricing system with exponential complexity multipliers) and discrete Milestones tracking novel item/technology achievements; in lab-play, 33 bounded tasks have fixed target throughputs (16/min for solids, 250/min for fluids) evaluated over a 60-second holdout period.

## Method

FLE comprises a Python client and Lua server communicating synchronously via RCON over TCP, wrapping the official Factorio v1.1.10 multiplayer server in headless mode. The agent scaffolding uses step-by-step prompting: given the API schema, a usage guide, and accumulated memory (past policies + observations), the model generates the next Python policy, which is executed and appended to memory; observations older than 16 steps are summarised into a 1024-token report to manage context length. The action space is a context-sensitive program synthesis task where agents can define reusable functions and classes in the namespace, enabling compositional factory design and hierarchical abstraction. Two evaluation settings are provided: open-play (unbounded sandbox, 5000 steps, 8 runs) and lab-play (24 planning tasks of geometrically increasing complexity from 2 to ~100 machines, plus troubleshooting and visual spatial reasoning tasks). Six frontier LLMs are evaluated, revealing that even the best model (Claude 3.5-Sonnet) solves only 7/24 planning tasks, struggles with spatial reasoning (no improvement from adding vision), and falls into degenerate debug loops rather than performing intelligent error correction.

## Results

In lab-play planning tasks (24 bounded factory-building objectives), Claude 3.5-Sonnet achieves the best success rate at 21.9% (7/24 tasks), followed by GPT-4o (16.6%, 5/24) and DeepSeek-v3 (15.1%, 5/24), while Llama-3.3-70B and GPT-4o-Mini solve only 2/24 tasks. In open-play (unbounded factory building over 5000 steps), Claude 3.5-Sonnet reaches a median Production Score of 293,206 with 28 milestones, whereas all other models remain in the early-game range (PS ≤ 2×10⁵) and fail to build production lines exceeding 5 entities. A human baseline solves 20/24 lab-play tasks within 128 steps, revealing a large capability gap. On spatial troubleshooting, Claude 3.5-Sonnet achieves 0.26 F1 versus 0.10 for GPT-4o and 0.09 for DeepSeek-v3, with no improvement when adding visual input.

## Baselines & Comparisons

Claude 3.5-Sonnet outperforms all other evaluated models across both open-play and lab-play settings, achieving the highest Production Score (293,206 vs. ≤2×10⁵ for others), the most milestones (28), and the best lab-play planning success (7/24 tasks vs. 5/24 for GPT-4o and DeepSeek-v3). GPT-4o ranks second in lab-play (16.6% success, 0.10 F1 spatial) and shows more defensive coding (12.8% assert usage) but still fails to build production lines beyond 5 entities in open-play. DeepSeek-v3 and Gemini-2-Flash perform similarly in lab-play (15.1% and 13.0% respectively) but both struggle with higher-complexity tasks; DeepSeek-v3 notably succeeds in lab-play early-automation yet rarely attempts factory creation in open-play without explicit objectives. Llama-3.3-70B and GPT-4o-Mini are the weakest, solving only 2/24 tasks and preferring manual crafting over automation. All models fall far short of the human baseline (20/24 tasks, 0.76 F1 spatial), with the hardest solved task (plastic bar, complexity 9.4) being ~39× less complex than the hardest overall task (utility-science-pack, complexity 374.8). Adding visual input to VLMs provides no meaningful improvement in spatial reasoning, with best VLM scores reaching only 50–80% of the human baseline.

## Relation to Prior Work

This paper extends the line of LLM agent evaluation in game environments (Voyager, MineDojo, BALROG, NetHack/NLE) by introducing an unbounded, automation-focused setting that resists the saturation problem inherent in benchmarks with natural completion states. It departs from prior Factorio work (Reid et al., 2021; Kant, 2025), which focused on integer programming and closed-domain optimization, by providing an open-ended, text-based program-synthesis interface (Python REPL) for LLM agents. The key conceptual departure is the use of Factorio's exponentially scaling technology tree and production throughput as a natural curriculum, combined with the requirement to maintain automated systems rather than merely gather resources manually.

## Why It Matters / Open Questions

FLE addresses a practical gap in the LLM evaluation landscape: as models saturate existing benchmarks, the field needs open-ended evaluations that can differentiate increasingly capable agents. The finding that vision does not improve spatial reasoning performance (and may even slightly degrade it) challenges the assumption that multimodal input naturally resolves spatial tasks, pointing to a deeper representational limitation. Open questions include whether end-game goals (rocket launch) are achievable via API alone, whether multi-agent cooperation changes the difficulty landscape, and whether more sophisticated scaffolding (memory systems, planning abstractions) can close the large gap between current models and human performance (7/24 vs. 20/24 tasks).
