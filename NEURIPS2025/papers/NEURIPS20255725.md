## Problem

Existing cybersecurity benchmarks either rely on CTF-style tasks that are not real-world systems, focus exclusively on offense without corresponding defense, or use coarse success conditions (e.g., flag capture) that cannot identify which specific vulnerability was exploited. There is no framework that captures both offensive and defensive capabilities across evolving real-world codebases with localized evaluation and quantifiable economic impact.

## Input / Output

The agent operates inside a Kali Linux container with network access to instantiated servers and databases, receiving a codebase snapshot (with full commit history), user credentials, and a tiered information level ranging from no information (zero-day Detect) through CWE identifier, CWE plus bounty title, to the full bug bounty report (Exploit). For Detect and Exploit tasks the agent must produce an executable exploit.sh script; for Patch it must modify the local codebase. Evaluation is fully automated via verifiers, code/runtime invariants, and the novel Detect Indicator, producing a binary success/failure, a dollar value mapped to real bug bounty awards ($10–$30,485), and token cost.

## Method

The framework represents each system as a series of snapshots, each associated with runtimes, invariants (unit tests, health checks, data-integrity checks), and vulnerabilities, where each vulnerability has linked exploits, verifiers, and patches. Three task types—Detect (snapshot-level, find any vulnerability), Exploit (vulnerability-level, reproduce a specific one), and Patch (vulnerability-level, fix a specific one)—capture the full vulnerability lifecycle across 25 real-world systems and 40 bounties spanning 9 of the OWASP Top 10. The key technical novelty is the Detect Indicator: an agent's exploit is valid only if it succeeds on the vulnerable snapshot AND fails on at least one patched snapshot, enabling localized identification of exactly which vulnerabilities were detected rather than merely confirming that some invariant broke. Difficulty is modulated by a four-level information hierarchy (No Info → CWE → CWE+Title → Full Report), interpolating from zero-day discovery to guided exploitation. All 40 bounties are manually validated through continuous integration, with hand-written exploits, patches, and invariants ensuring each task is both solvable and verifiable by external parties.

## Results

On BountyBench (25 systems, 40 bounties, 120 tasks), the top-performing agents are OpenAI Codex CLI: o3-high (12.5% Detect success, mapping to $3,720; 90% Patch success, mapping to $14,152), C-Agent: Claude 3.7 Sonnet Thinking (67.5% Exploit success), and OpenAI Codex CLI: o4-mini (90% Patch success, mapping to $14,422). A notable offense-defense imbalance exists: coding agents (OpenAI Codex CLI: o3-high, o4-mini, Claude Code) achieve 87.5–90% Patch success but only 32.5–57.5% Exploit success, while C-Agents are more balanced with 17.5–67.5% Exploit and 25–60% Patch. Across all agents, $81,067 worth of Patch tasks and $9,700 of Detect tasks were completed, with token costs ranging from $3 (Qwen3) to $368 (C-Agent: o3-high) per task.

## Baselines & Comparisons

The paper evaluates 10 agents rather than comparing a single method against baselines, but a clear distinction emerges between purpose-built coding agents (Claude Code, OpenAI Codex CLI) and general-purpose C-Agents. On the Patch (defense) task, OpenAI Codex CLI: o3-high and o4-mini both achieve 90% success, and Claude Code reaches 87.5%, substantially outperforming the best C-Agent (Claude 3.7 at 60%). On the Exploit (offense) task, the ranking inverts: C-Agent: Claude 3.7 leads at 67.5%, followed by Claude Code (57.5%) and C-Agent: GPT-4.1 (55.0%), while OpenAI Codex CLI: o4-mini trails at 32.5%. On the hardest Detect (zero-day) task, all agents struggle, with OpenAI Codex CLI: o3-high achieving the best 12.5% success rate ($3,720 in bounties) and most C-Agents scoring 0%. The authors attribute the coding agents' Patch advantage to their custom file-editing tools, while noting these tools may introduce unnecessary complexity for exploit crafting. Safety refusals are notably higher for OpenAI Codex CLI agents (14.1% for o3-high, 11.2% for o4-mini) compared to C-Agents (≤0.37%), potentially suppressing their offensive scores.

## Relation to Prior Work

This paper builds directly on Cybench (Zhang et al., ICLR 2025), reusing its agent architecture for the C-Agents and its task-verifiability philosophy, but departs fundamentally from the CTF paradigm by constructing 25 real-world systems with actual bug bounties and monetary awards rather than contrived challenges. It also extends beyond CVE-Bench (which covers only offensive exploitation of web applications) and code-patch benchmarks like SWE-Bench and AutoPatchBench (which cover only defense) by unifying offense and defense within a single set of evolving systems, and introduces the Detect Indicator as a localized evaluation mechanism absent from prior invariant-based or flag-capture approaches.

## Why It Matters / Open Questions

BountyBench provides the first economically grounded, offense-defense unified benchmark for AI cybersecurity agents, with real dollar metrics that map directly to bug bounty program economics and a Detect Indicator enabling per-vulnerability attribution. The finding that coding agents (Claude Code, OpenAI Codex CLI) are substantially stronger at defense (87.5–90% patch) than offense (32.5–57.5% exploit), while custom agents are more balanced, has direct implications for how organizations should deploy AI agents in security operations. Key open questions include whether the heavily manual task-creation process (tens of hours per system) can be automated, how browser-based tools and other custom interfaces affect agent performance, and how to track system evolution as new vulnerabilities are continuously disclosed.
