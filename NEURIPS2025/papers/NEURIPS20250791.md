## Problem

Game-theoretic algorithms are typically benchmarked on recreational games, classical economic constructs, or random payoff matrices, yet the Stackelberg security game model—the most practically successful game-theoretic framework (deployed at LAX, in anti-poaching, and for air passenger screening)—is conspicuously absent from standard benchmarks. The critical data defining target values in real security games remain inaccessible to algorithm developers, and the paper further shows that random games exhibit degenerate equilibria (near-optimal defender utility from pure or very sparse strategies) that misrepresent real-world strategic complexity.

## Input / Output

The framework consumes three open-access data streams: animal GPS collar records from Movebank (e.g., 3,183 spatiotemporal observations for six African elephants), OpenStreetMap infrastructure features queried via Overpass Turbo (23,607 power/medical/judicial/educational/police nodes and ways in the NYC metro area), and 2020 U.S. Census TIGER/Line block-level population polygons (288,819 blocks in New York). Outputs are fully specified game objects in both normal-form (NFG) and schedule-form (SFG) representations for zero-sum and general-sum settings, exportable as .pkl, .h5, or native Gambit/Gamut .nfg/.game files, along with computed Nash or Stackelberg equilibria from built-in solvers.

## Method

GUARD organizes game construction in a three-tiered class hierarchy: a base Graph Game layer handles time-expanded path enumeration via depth-first search and defines interdiction rules (capture radius for moving attackers, defense-time threshold for stationary targets); a Security Game layer enforces defender/attacker role constraints and implements both NFG and SFG formulations with Stackelberg schedule expansion; and Domain-Specific layers (Green Security Games, Infrastructure Security Games) instantiate targets and values from real data. For GSGs, targets are generated via K-means clustering or cell-density scoring on GPS observations, with scores scaled by animal-to-observation ratios and optional escape-proximity factors; for ISGs, OSM features are mapped to a street graph and valued as W·(log(P+1))^α using census population P and type weight W. The framework ships with solvers spanning Nash LP, support-bounded MILP, Regret Matching variants (RM, RM+, PRM+), Double Oracle, and SSE multiple LP. The theoretical contribution proves that for i.i.d. uniform random normal-form games, a pure strategy achieves SSE value 1−1/(n+1) in expectation and an O(log n)-sparse strategy is near-optimal up to constant factors, while for random security games a single resource yields expected utility −O(1/√T), establishing that random benchmarks systematically overestimate defender advantage.

## Results

In Stackelberg security games, real GSG instances yield defender utility u_d = -0.207 with support size S = 9, while randomized variants collapse to S = 1.4–2.0 and inflate defender utility to u_d = -0.035 to -0.270. For ISGs, the real instance achieves u_d = -0.408 with S = 14, whereas all randomized baselines degenerate to S = 1–1.7 with u_d = -0.013 to -0.032. In zero-sum sparsity experiments, real instances reach optimal utility at only 40–60% (NFG) and 50–70% (SFG) of the support sizes required by randomized instances, and iterative algorithms (DO, RM+, PRM+) converge faster on real games.

## Baselines & Comparisons

The paper's central comparison is between GUARD-generated realistic game instances and three randomized baselines: RT (randomized target values only), RM (fully randomized NFG matrices), and RTS (randomized target values and schedule assignments). Across all three randomization schemes, the defender's utility is substantially inflated relative to real instances (e.g., ISG general schedules: real u_d = -0.408 vs. RM u_d = -0.026, RT u_d = -0.013, RTS u_d = -0.032), and equilibrium support collapses from S = 14 (real) to S = 1–1.7 (random). In GSGs, the real instance achieves S = 9 versus S = 1.4–2.0 for all random variants. In zero-sum sparsity experiments, real instances require 40–60% less support to reach optimal utility than randomized ones, and iterative solvers (DO, RM+, PRM+) converge faster and more stably on real games, with randomized DO in ISGs exhibiting significant oscillations. These results confirm the theoretical prediction (Theorems 1–2) that random uniform games admit near-optimal defender strategies with vanishingly small support, making them poor benchmarks for evaluating equilibrium-finding algorithms.

## Relation to Prior Work

This paper carves new ground at the intersection of security game deployment and algorithmic benchmarking. While prior frameworks like Gamut (classical economic games) and OpenSpiel (recreational/synthetic benchmarks) provide game instances, and deployed security game systems (PAWS, ARMOR, IRIS) demonstrated real-world impact, the critical utility data from those deployments remained inaccessible to algorithm developers. GUARD repurposes open-access data sources (Movebank animal tracking, OpenStreetMap infrastructure, Census demographics) to reconstruct realistic target-value structures that were previously locked behind proprietary datasets. The theoretical analysis extends the random-game literature of Bárány et al. (2007) from Nash equilibria in normal-form games to Stackelberg equilibria in both matrix and security game settings, providing the first formal characterization of defender-advantage degeneracy in random security games.

## Why It Matters / Open Questions

The framework addresses a concrete and long-standing gap: security game algorithm developers had no access to the target-value utilities that make real deployments strategically rich, forcing them to rely on random or synthetic benchmarks that the paper proves are degenerate. The theoretical result that a single defender resource used with probability O(1/√T) achieves near-optimal utility in random security games provides a formal argument against the widespread practice of benchmarking on random instances. Open questions include whether the framework scales to larger, denser environments (the paper acknowledges action-set explosion at high timesteps), whether it generalizes beyond the two tested domains (GSG and ISG), and how to incorporate resource-specific subgraph constraints that would further enhance realism. The practical impact is significant for the security game community, which now has a reproducible, data-grounded benchmark suite with export compatibility to standard tools.
