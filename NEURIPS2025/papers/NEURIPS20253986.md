## Problem

Existing top-k sparse attention methods for long-context LLM inference rely on a fixed token budget B, but the optimal budget varies dynamically at runtime across heads, layers, and queries due to differing attention weight distributions (focused vs. diffuse). This static choice causes systematic over-selection or under-selection, and different algorithms require different degrees of over-selection to compensate for estimation inaccuracy, necessitating per-algorithm offline calibration.

## Input / Output

Twilight operates as a plug-in optimizer on top of an existing sparse attention base algorithm (e.g., Quest, DS, FlashInfer). It consumes the query vector, the full KV cache, and an INT4 asymmetrically quantized K cache maintained in paged layout on GPU. The base Token Selector produces a conservative candidate set (e.g., 1/4 sparsity), which the Twilight Pruner then reduces to an adaptive per-head token subset via top-p thresholding. The final output is the sparse attention result computed only on the pruned tokens, with the effective budget determined at runtime per head rather than fixed globally.

## Method

The key insight is that the budget-selection dilemma in top-k sparse attention is structurally identical to the top-k vs. top-p (nucleus) sampling problem in LLM decoding: top-p provides a natural, distribution-adaptive stopping criterion. Twilight formalizes this as Oracle Top-p Sparse Attention, which selects the minimum token set whose cumulative attention weights exceed a threshold p, yielding a theoretical error bound of (1-p)·‖V‖_F. Architecturally, it uses a hierarchical Select-then-Prune pipeline: the base algorithm selects a large candidate set under a conservative budget, then a Twilight Pruner applies top-p thresholding to shrink it further. For efficient GPU execution, the Pruner estimates token importance via a mixed-precision SpGEMV kernel (FP16 query × INT4 quantized keys with paged indexing and two-stage pipelined dequantization), finds the top-p cutoff via a parallel binary search over weight thresholds, and handles head-wise load imbalance by flattening the head dimension in the attention kernel. The INT4 K cache adds only 1/8 extra KV memory overhead and reduces global memory accesses to at most 1/4 of the FP16 case.

## Results

On Longbench (12 tasks), Twilight improves DS by up to +5.7% on Longchat-7B (38.71 vs. 36.62) and by +1.2% on LLaMA-3.1-8B (51.73 vs. 51.14), while pruning up to 98% of tokens selected by the base algorithm. On RULER, DS-Twilight achieves 87.88 average score, surpassing the non-top-k SOTA MagicPIG (87.06) and approaching full attention (88.18). For efficiency, Twilight delivers a 1.4× speedup over Quest for the self-attention operator (up to 15.8× over FlashAttention-2) and a 1.35× end-to-end decoding speedup over Quest.

## Baselines & Comparisons

Against Quest, Twilight consistently improves accuracy: +2.5% on Longchat and +0.3% on LLaMA-3.1 (Longbench), while on RULER Quest-Twi (86.65) narrows the gap to MagicPIG (87.06) from Quest's 81.62. Against DS, the gains are larger: +5.7% on Longchat and +1.2% on LLaMA-3.1 (Longbench), and DS-Twi (87.88) surpasses both MagicPIG (87.06) and Full attention (88.18 is within 0.3%) on RULER. Against the non-top-k baseline MagicPIG, DS-Twi wins on RULER (87.88 vs. 87.06) and on Longbench LLaMA-3.1 (51.73 vs. 51.70), while Quest-Twi is slightly below MagicPIG on RULER (86.65 vs. 87.06). For efficiency, Twilight achieves 1.4× speedup over Quest and 2.4× over FlashInfer for the self-attention kernel, and 3.9× over FlashInfer for end-to-end TPOT. Against token-dropping methods (StreamingLLM, SnapKV), DS-Twilight leads by 6.0 and 2.5 points on Longbench average (38.71 vs. 32.69 and 36.22).

## Relation to Prior Work

This paper adapts the top-p (nucleus) sampling concept from LLM output token generation (Holtzman et al., 2019) to the problem of KV cache budget selection in sparse attention, replacing the fixed top-k budget with an adaptive threshold on cumulative attention weights. It builds on the FlashInfer kernel library for both the SpGEMV estimation and the top-p selection kernel, and positions itself as a general optimizer that wraps any existing top-k sparse attention algorithm (Quest, DS, etc.) in a hierarchical select-then-prune pipeline rather than proposing a new token-selection strategy. The work departs from prior dynamic-budget studies (which tune budgets per layer/head/task offline) by making the budget fully runtime-adaptive per head and per query, and from concurrent work Tactic by using direct thresholding rather than distribution fitting.

## Why It Matters / Open Questions

Twilight provides a drop-in, architecture-agnostic layer that can be applied to any existing or future top-k sparse attention method, making it a practical building block for LLM serving systems (vLLM, SGLang) where 1.4× additional speedup over SOTA sparse attention translates to meaningful throughput gains at scale. Key limitations include the non-negligible estimation overhead (SpGEMV with INT4 K cache), the 1/8 extra KV cache memory for the quantized copy, and the incompatibility between head-wise dynamism and Group Query Attention, which forces group-level budget sharing. Open questions include integration with multi-head latent attention (MLA) architectures, further reducing estimation cost, and whether the INT4 K cache can be eliminated by reusing weights from INT4 full-attention kernels.
