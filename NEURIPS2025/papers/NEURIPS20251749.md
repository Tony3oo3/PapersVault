## Problem

Current frontier model cybersecurity evaluations are static: they measure an agent's capability at a fixed configuration without accounting for the fact that adversaries with compute resources can iteratively improve the agent through resampling, prompt refinement, self-training, and workflow redesign. This paper argues that cybersecurity is uniquely amenable to such self-improvement due to built-in strong verifiers and high financial incentives, and that risk assessments must dynamically evaluate how far adversaries can push agent performance along multiple axes within a bounded compute budget.

## Input / Output

The agent receives a CTF challenge description and optional starter files, then iteratively interacts with an execution environment (running code, calling tools) over up to N rounds, ultimately submitting a flag string that is checked against a ground-truth value to produce a binary reward. Evaluation uses pass@k computed over k0=12 rollouts per task, with the key distinction that in stateful environments k=1 (single attempt) while non-stateful environments permit repeated sampling. The five degrees of freedom modify different components of the agent loop: the outer-loop repetition count k, the inner-loop interaction budget N, the initial prompt s_0j, the core model weights M, and the agent scaffolding S.

## Method

The paper formalizes a threat model (Algorithm 1) in which an adversary with a fixed compute budget can modify five components of a cybersecurity agent: (1) repeated sampling (scaling k in the outer loop), (2) increasing max interaction rounds N, (3) iterative prompt refinement where the model generates revised user prompts conditioned on prior failed trajectories, (4) self-training via rejection sampling of successful trajectories from a development set followed by SFT fine-tuning (analogous to STaR but without external hints), and (5) iterative workflow refinement where a meta-agent (using the same core model) proposes new agent scaffolding designs evaluated on a dev set (analogous to ADAS). Experiments use Qwen2.5-32B-Coder-Instruct with the NYU CTF Agent scaffolding across three CTF benchmarks, showing that under just 8 H100 GPU Hours (~$36), performance on InterCode CTF improves by over 40% relative to baseline, with iterative prompt refinement yielding the largest gains in non-stateful settings while self-training and workflow refinement dominate in stateful settings where only a single attempt is permitted.

## Results

With a fixed budget of 8 H100 GPU Hours (<$36), adversaries can improve the agent's pass@1 score on InterCode CTF (Test) by more than 40% relative to the baseline of 0.58 (achieved by the base NYU CTF Agent scaffolding with N=20). Iterative prompt refinement yields the highest per-unit-compute gain, outperforming simple repeated sampling at the same budget. Self-training on only 33 successful trajectories (5 epochs) demonstrates in-domain generalization to the held-out test set, while iterative workflow refinement (via an ADAS-style meta-agent) autonomously discovers a workflow with higher pass@1 than the original, even using the same core model (Qwen2.5-32B-Coder-Instruct) for both the meta-agent and the target agent.

## Baselines & Comparisons

This paper does not benchmark a single model against competing models; instead, it compares its dynamic risk-assessment framework against seven prior evaluation protocols (InterCode, NYU CTF, Cybench, EnIGMA, o3/o4-mini system card, Claude 3.7 Sonnet system card, and the o1 pre-deployment report). The key finding is that no prior evaluation covers more than two of the five adversarial degrees of freedom, whereas this work exercises all five simultaneously under a fixed compute budget. Among the five degrees of freedom tested, iterative prompt refinement produces the largest relative gain per GPU-hour in non-stateful settings, surpassing both repeated sampling (k up to 33) and increasing interaction rounds (N up to 80) at the 8-hour budget. In stateful environments (where k=1), the primary gains come from increasing N and pre-deployment self-training, with self-training (7.1 GPU Hours total) yielding a measurable pass@1 improvement over the base model. The paper's central comparison is thus methodological: static pass@k evaluations used by all seven prior systems systematically understate risk because they omit prompt refinement, self-training, and workflow evolution.

## Relation to Prior Work

This paper extends the self-training paradigm of STaR (Zelikman et al., 2022) and the meta-agent workflow search of ADAS (Hu et al., 2024) into the offensive cybersecurity agent setting, combining them with test-time scaling techniques (repeated sampling, iterative prompt refinement) under a unified adversarial threat model. It departs from prior cybersecurity evaluations (InterCode, NYU CTF, Cybench, and frontier model system cards) that assess agents statically with fixed parameters, by explicitly modeling five degrees of freedom an adversary can exploit to improve agent capability within a bounded compute budget. The conceptual contribution is framing cybersecurity risk as a dynamic, optimization problem rather than a single-point measurement.

## Why It Matters / Open Questions

The finding that ~$36 of compute (8 H100 GPU hours) can yield >40% relative improvement in CTF performance challenges the assumption that static pass@k evaluations adequately capture an agent's true threat potential, with direct implications for frontier model auditing and policy frameworks like California's SB-1047. The stateful vs. non-stateful distinction highlights that risk profiles differ substantially depending on the deployment environment, suggesting separate assessment protocols are needed. Open questions include how these gains scale with larger models and more sophisticated adversaries (RL-based self-training, web browsing tools), whether the results transfer to real-world penetration testing beyond CTF-style tasks, and how to operationalize dynamic risk assessments at scale for regulatory compliance.
