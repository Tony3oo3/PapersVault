## Problem

Existing Text2VIS benchmarks assume a single correct visualization per query (1→1 mapping), ignoring the fact that natural language queries are often ambiguous and map to multiple valid visualizations. No prior benchmark systematically evaluates how Text2VIS systems handle such ambiguity, and no model is designed to resolve ambiguous queries through structured, interpretable reasoning.
![Teaser figure](../imgs/NEURIPS20254172/cropped_page1_idx0.webp)

## Input / Output

The system takes a natural language query (potentially ambiguous) and a table schema as input, and produces a set of 1–5 valid visualization specifications (Vega-Lite-style) along with step-wise reasoning paths that explain how each ambiguity was resolved. The key structural difference from prior work is the one-to-many output: each query is paired with multiple valid visualizations (ambiguity level k ≤ 5), and each visualization is traceable to its interpretation through an explicit chain of reasoning steps covering data selection, transformation, channel mapping, and chart type decisions.

## Method

The paper contributes two components. First, nvBench 2.0 is built via a reverse-generation pipeline: starting from unambiguous seed visualizations, controlled ambiguities are injected into a visualization AST (ambiguous nodes for multi-interpretation columns, implicit nodes for unspecified but required components), an Answer Set Programming solver enumerates all grammar-consistent resolutions to form the valid visualization set, and an LLM synthesizes the ambiguous query plus step-wise disambiguation reasoning paths. Second, Step-Text2Vis is built on Qwen2.5-7B-Instruct and trained in two stages: (1) supervised fine-tuning as a cold-start to learn the predefined step-wise output format, then (2) Step-DPO, where preference pairs are constructed online by running the SFT model on the dev set, identifying the first erroneous reasoning step, and using the ground-truth step as s_win and the model's incorrect step as s_lose to optimize step-level correctness via a DPO-style objective.

## Results

On nvBench 2.0, Step-Text2Vis achieves the best F1@3 of 81.50% and F1@5 of 80.88%, outperforming all prompting-based and fine-tuning-based baselines. At K=1, it maintains 99.20% precision while achieving 37.30% recall. The model surpasses GPT-4o (F1@3: 58.96%) by 22.54 percentage points and Qwen2.5-7B-SFT (F1@3: 75.79%) by 5.71 percentage points, demonstrating that step-wise preference optimization (Step-DPO) yields the best precision-recall balance for ambiguous Text2VIS tasks.

## Baselines & Comparisons

Step-Text2Vis outperforms all prompting-based baselines across every F1@K metric. Against GPT-4o (F1@3: 58.96%, F1@5: 59.03%), Step-Text2Vis gains 22.54 and 21.85 percentage points respectively, a substantial margin driven by far superior recall (77.09% vs. 46.35% at K=3) while maintaining comparable precision (94.27% vs. 95.83%). Against Qwen2.5-7B (F1@3: 57.09%), the improvement is even larger at 24.41 points. The closest competitor is Qwen3-235B-Step (F1@3: 78.62%), which Step-Text2Vis edges out by 2.88 points at K=3 and 3.10 points at K=5. The SFT-only baseline Qwen2.5-7B-SFT (F1@3: 75.79%) shows that fine-tuning alone substantially boosts recall but sacrifices precision (83.36% vs. 94.27%), whereas Step-DPO recovers precision while further improving recall, confirming the value of step-wise preference optimization over plain supervised fine-tuning.

## Relation to Prior Work

This paper extends the nvBench 1.0 lineage (Luo et al., SIGMOD 2021), which established the Text2VIS benchmark paradigm with strict 1-to-1 text-to-visualization mappings, by introducing a controlled ambiguity-injection pipeline that produces 1-to-many mappings with multiple valid visualizations per query. For the model side, it adapts Step-DPO (Lai et al., 2024) from mathematical reasoning to the Text2VIS domain, using step-wise preference optimization over disambiguation reasoning paths. A distinctive technical departure is the use of Answer Set Programming (ASP) solvers to exhaustively enumerate all grammar-consistent resolutions of an ambiguity-aware visualization tree, ensuring completeness of the valid answer set in a way that LLM-only generation cannot guarantee.

## Why It Matters / Open Questions

By making ambiguity a first-class evaluation axis with typed categories (Data Transformation, Channel Mapping, Data Selection, Chart Type) and controlled levels (2–5 valid interpretations), nvBench 2.0 fills a gap the authors quantify as >60% of real-world cases being ambiguous yet ignored by prior benchmarks. The step-wise reasoning paths attached to each sample enable interpretability of *how* a model resolves ambiguity, not just whether it gets the right chart. Open questions include whether the synthetic ambiguity types (injected via KG + LLM refinement) faithfully capture the full distribution of real user ambiguity, whether the 153-domain coverage generalizes to highly specialized or multi-table scenarios, and whether the ASP-based enumeration scales to richer visualization grammars beyond the six chart types tested.
