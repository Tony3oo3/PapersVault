## Problem

Agentic AI workloads (multi-agent pipelines, self-refinement loops, self-consistency) produce long, highly repetitive token sequences that existing speculative decoding methods fail to exploit effectively. Model-based speculators (e.g., EAGLE-2/3) incur significant GPU overhead and memory contention when speculating long sequences, while model-free approaches (e.g., Prompt-Lookup Decoding, Token Recycling) lack adaptivity and waste compute verifying long, improbable draft sequences. SuffixDecoding addresses this by combining extremely fast draft generation with adaptive speculation length control tailored to repetitive agentic workloads.

## Input / Output

The method consumes the current token prefix x_{1:t} (prompt plus tokens generated so far) and performs pattern matching against two suffix trees: a global tree built from historical outputs of prior requests and a per-request tree tracking the current prompt and ongoing generation. It produces a speculation tree of up to MAX_SPEC = αp draft tokens (where p is the matched pattern length and α ∈ [1,4] is a user-defined factor), which the target LLM verifies in a single parallel forward pass. Draft token generation runs entirely on CPU at ~20 μs per token with zero GPU overhead, and the output distribution of the LLM is exactly preserved (lossless).

## Method

SuffixDecoding builds suffix trees over token sequences from prompts and previous outputs, where each node represents a token and paths encode previously observed subsequences. Given a suffix of the current sequence of length p, it walks the tree to find a matching node N_p, then greedily expands a smaller speculation sub-tree by repeatedly adding the child with the highest acceptance probability D(N) = D(PARENT(N)) × C(N), where C(N) is the normalized frequency of N among its siblings. The speculation length adapts to pattern match confidence: longer matches (higher p) permit more speculative tokens via MAX_SPEC = αp, while short matches trigger conservative speculation. A scoring function SCORE(T) = Σ D(N) selects the best speculation tree across both suffix trees and multiple pattern lengths, and a threshold τ on this score enables hybrid operation—falling back to a model-based speculator (e.g., EAGLE-3) when suffix-tree confidence is low, making the method suitable for mixed agentic and open-ended workloads.

## Results

On the AgenticSQL multi-agent pipeline, SuffixDecoding (linear) achieves a 5.3× mean speedup over vanilla decoding with 6.3 mean accepted tokens per step, substantially outperforming EAGLE-3 (1.6×, 3.2 tokens/step) and Token Recycling (2.7×, 3.2 tokens/step). On SWE-Bench, SuffixDecoding achieves a 2.5× speedup with 7.8 mean accepted tokens/step, while EAGLE-2/3 fail entirely due to context-length limits (>8192 tokens). On the non-agentic Spec-Bench, the Hybrid (SuffixDecoding + EAGLE-3) approach achieves a 2.5× speedup, marginally beating standalone EAGLE-3 (2.4×) and Token Recycling (2.2×). End-to-end on SWE-Bench Verified with OpenHands, SuffixDecoding yields 1.8–4.5× task-completion speedups while preserving the model's 37.2% accuracy.

## Baselines & Comparisons

SuffixDecoding decisively outperforms all four baselines on agentic workloads. On AgenticSQL, it achieves a 5.3× speedup versus 1.6–1.9× for EAGLE-2/3 and 2.7× for Token Recycling, driven by 6.3 mean accepted tokens/step (vs. 3.2 for EAGLE-3 and 3.2 for Token Recycling) and near-zero speculation overhead (~0.04 ms/token vs. 3.5–4.9 ms for EAGLE variants). On SWE-Bench, EAGLE-2/3 fail entirely due to their 8192-token context limit, leaving PLD (1.5×) and Token Recycling (1.4×) as the only viable baselines; SuffixDecoding's 2.5× speedup represents a 1.7× improvement over PLD. On the non-agentic Spec-Bench, SuffixDecoding alone (1.7×) is outperformed by EAGLE-3 (2.4×) and Token Recycling (2.2×), but the Hybrid approach that falls back to EAGLE-3 when the suffix-tree score is low achieves 2.5×, marginally beating both. The key differentiator is speculation cost: SuffixDecoding's suffix-tree lookup takes ~0.04–0.17 ms per token on CPU, while EAGLE-3 requires 2.6–4.9 ms on GPU, making SuffixDecoding's higher acceptance length translate into a much larger wall-clock speedup.

## Relation to Prior Work

SuffixDecoding sits at the intersection of three research threads: the speculative decoding paradigm (Leviathan et al., 2023), tree-based parallel verification (SpecInfer, Miao et al., 2024), and classical string-matching data structures (suffix trees, Weiner 1973). It departs from model-based speculators (EAGLE-2/3, Medusa) by eliminating the need for a trained draft model, and from prior model-free methods (PLD, Token Recycling) by introducing adaptive speculation length and frequency-based tree scoring. The key conceptual departure is repurposing a CPU-resident suffix tree as a zero-GPU-overhead draft mechanism specifically tuned for the long, repetitive token sequences characteristic of agentic pipelines (self-consistency, self-refinement, multi-agent workflows), rather than for open-ended generation.

## Why It Matters / Open Questions

Agentic AI applications are a rapidly growing class of LLM workloads where repetitive inference dominates latency, and SuffixDecoding's 5.3× speedup on AgenticSQL and 4.5× end-to-end speedup on SWE-Bench address a practical bottleneck that model-based speculators cannot (EAGLE-2/3 fail entirely on SWE-Bench due to context-length limits). The hybrid fallback mechanism (suffix-tree speculation when confident, model-based speculation otherwise) makes the approach deployable in mixed workloads, and the vLLM integration demonstrates production readiness. Open questions include: how well the method scales to batched serving with diverse concurrent requests, whether the suffix tree's O(n) memory footprint remains manageable at multi-tenant scale, and whether the empirical-entropy heuristic for predicting SuffixDecoding effectiveness generalizes beyond the tested datasets.
