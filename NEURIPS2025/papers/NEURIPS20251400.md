## Problem

Existing specialized patching models train a single monolithic model to handle the entire end-to-end pipeline (localization, generation, validation), but different sub-tasks have fundamentally different inputs, outputs, and capability requirements, making it hard for one small model to excel at all of them. As a result, SOTA specialized methods require 70B+ parameters and 11M training samples to reach only 41% resolved rate on SWE-bench-Verified. The paper asks whether decomposing the pipeline into component-specific small reasoning models can match or exceed this performance with far fewer parameters and data.

## Input / Output

The system consumes a software repository (file structure and code contents) plus a natural-language issue/bug description. Localization is decomposed into two sequential steps: file-level (given the full file tree) and line-level (given the contents of candidate files), each producing ranked root-cause locations. Generation takes the issue description and identified root causes to produce 60 patch candidates. Validation takes only the issue description (no codebase or patch access) to generate PoC test scripts in two formats—assertion-based and non-assertion-based—then judges patch correctness from execution outputs. The final output is a single selected patch, chosen by dynamic testing (PoC + functionality tests) followed by majority voting among tied candidates.

## Method

Co-PatcheR trains three 14B Qwen-2.5-Coder models via supervised fine-tuning with reasoning-chain distillation from Claude-3.7-Sonnet (and o4-mini for validation), using only 6K filtered training samples. The Loc-Gen model handles both localization (decomposed into file-then-line sub-tasks to reduce context length) and patch generation augmented with self-critique training, where the model reviews and refines its own patches. Two separate validation models (Val-assert and Val-no-assert) generate PoC test cases in complementary styles to ensure path diversity, with the no-assert model additionally trained to judge patch correctness from execution outputs. A key training recipe difference from prior distillation work is rejection sampling that retains only samples with correct final answers, since patching tasks are rare in pre-training and small models need correct exemplars to learn domain knowledge. At inference, the system runs one 14B model at a time (sequentially), scores 60 candidates via dynamic testing, and breaks ties with normalization-based majority voting, achieving 46% resolved rate with 40% fewer parameters and 88% fewer training samples than SWE-RL.

## Results

Co-PatcheR achieves a 46.00% resolved rate on SWE-bench-Verified using only 3×14B models (42B total parameters) trained on just 6K samples, setting a new record among open-source specialized patchers. This surpasses the previous best specialized model, SWE-RL-70B (41.00%), while using 40% fewer parameters, 88% fewer training samples (6K vs. 11M), and 60 patch candidates (vs. 400). The system also outperforms SWE-Fixer-72B (32.80%) and SoRFT-32B (30.80%) by a wide margin, and its majority-vote patch selection (46.00%) beats both the SWE-Gym ORM (36.40%) and Claude-3.7-Sonnet voting (45.00%).

## Baselines & Comparisons

Among specialized open-source models, Co-PatcheR (46.00%) decisively outperforms all prior methods: SWE-RL-70B (41.00%, +5.0 pp), SWE-Fixer-72B (32.80%, +13.2 pp), SoRFT-32B (30.80%, +15.2 pp), and Lingma-SWE-GPT-72B (30.20%, +15.8 pp), while using substantially fewer parameters and training data. Against commercial LLM agents, Co-PatcheR trails Claude-3.5-Sonnet + PatchPilot (53.60%) and Claude-3.7-Sonnet + OpenHands (60.60%) by 7.6 and 14.6 pp respectively, but narrows the gap to 4.6 pp versus Claude-3.5-Sonnet + Agentless (50.80%). In component-level ablations, Co-PatcheR's 14B localization model matches GPT-4o's file/line accuracy, and its generation model is slightly below o4-mini and Claude-3.7-Sonnet in pass@1 but reaches comparable performance with only 4 additional patch candidates via testing-phase scaling. For final patch selection, Co-PatcheR's majority vote (46.00%) outperforms both the SWE-Gym ORM (36.40%) and Claude-3.7-Sonnet-based voting (45.00%), demonstrating that a simple, cost-free strategy suffices when many candidates are available.

## Relation to Prior Work

This paper departs from the dominant paradigm in specialized software patching—training a single monolithic model for the end-to-end pipeline (as in SWE-RL, SWE-Fixer, SoRFT)—by proposing the first collaborative system with component-specific small reasoning models. It builds on the SFT-based distillation recipe from S1 and Sky-T1 for training small reasoning models, but introduces a key departure: rejection sampling to filter out wrong-answer training data, which the authors argue is critical for patching (unlike math, where S1 shows wrong answers still help). The agent scaffold and majority-voting mechanism are adapted from PatchPilot and Agentless, while the critique-training component for generation draws on the critique fine-tuning literature.

## Why It Matters / Open Questions

The practical impact is significant: Co-PatcheR achieves 46% resolved rate on SWE-bench-Verified with 3×14B models and 6K training samples, compared to SWE-RL's 41% with a 70B model and 11M samples—a 40% parameter reduction and 99.95% data reduction. This makes high-quality automated patching accessible to groups without large compute budgets. Open questions include whether RL-based fine-tuning on top of these distilled models can close the remaining gap to commercial LLMs (53–60%), whether the component-specific design generalizes beyond Python repositories, and how to integrate more complex tool-calling agents without sacrificing the efficiency gains.
