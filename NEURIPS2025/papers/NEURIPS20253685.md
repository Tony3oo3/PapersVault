## Problem

The training recipe for building high-performing reasoning models via large-scale RL remains elusive: key implementation details from DeepSeek-R1 (data curation, RL hyperparameters) were omitted, and prior work from DeepSeek and Llama-Nemotron reported that distillation outperforms RL for small and mid-sized models. This paper tackles the question of whether RL can still substantially improve strong, already-distilled 7B/14B models, and if so, what specific training recipe (domain ordering, length scheduling, data filtering) is needed to make it work reliably.

## Input / Output

For math, the model receives a problem statement and must produce a chain-of-thought reasoning trace followed by a final answer enclosed in \boxed{}; correctness is verified symbolically via a sympy-based rule-based checker. For code, the model receives a competitive-programming problem description (function-calling or stdin/stdout format) and must output a Python solution inside a designated code block; correctness is verified by executing the code in a sandbox against a full set of hidden test cases within a time limit. Both reward signals are strictly binary (1/0) with no format or length penalties, and the maximum response length is progressively extended from 8K to 32K tokens during training.

## Method

Starting from DeepSeek-R1-Qwen-Distilled 7B/14B checkpoints, the paper applies GRPO in a strict on-policy REINFORCE form (single gradient update per rollout group, β=0, no KL penalty) with a two-phase curriculum: math-only RL first, then code-only RL. Within each phase, training uses stage-wise maximum-response-length extension (8K→16K→24K→32K) combined with difficulty-based prompt filtering (removing problems the model already solves >6/16 times) to keep the GRPO advantage signal informative. The math reward uses a sympy-based symbolic equivalence checker, while the code reward uses a parallelized local sandbox that executes generated Python against curated test cases; the ~140× difference in per-instance verification time (3.9 s vs. 552 s per 1024 instances) motivates the sequential domain ordering. A rigorous data curation pipeline (9-gram decontamination, DeepSeek-R1 majority-vote verification for math, difficulty scoring via 8 rollouts on R1-671B for code, elimination of false-positive/negative reward sources) yields ~49K math and ~8.5K code training problems. The key empirical finding is that math-only RL transfers to code benchmarks (+6.8%/+5.8% on LiveCodeBench for 7B/14B), and subsequent code-only RL further improves code scores with negligible math degradation, outperforming state-of-the-art distillation-based models at 14B scale.

## Results

AceReason-Nemotron-14B achieves 78.6% on AIME 2024 and 67.4% on AIME 2025 (avg@64), surpassing its SFT starting point (DeepSeek-R1-Distill-Qwen-14B) by +8.9/+17.2 points, and outperforming the 32B and 70B distilled counterparts. On LiveCodeBench v5/v6, it reaches 61.1%/54.9% (avg@8), a +8.0/+7.0 point gain over the SFT baseline, and achieves a Codeforces ELO of 2024. The 7B model improves from 55.5% to 69.0% on AIME 2024 (+13.5) and from 37.6% to 51.8% on LCB v5 (+14.2), remaining competitive with SOTA RL-based 7B models while surpassing all open-source code reasoning models at the same scale.

## Baselines & Comparisons

At 14B scale, AceReason-Nemotron-14B outperforms all open-source RL and distillation baselines: it beats OpenMath-Nemotron-14B by +2.3/+4.4 on AIME 24/25, OpenCodeReasoning-Nemotron-14B by +1.7/+0.8 on LCB v5/v6, DeepCoder-14B by +7.6/+10.3 on AIME 24/25 and +3.2 on LCB v5, and Light-R1-14B by +4.6/+7.2 on AIME 24/25. It also surpasses the much larger DeepSeek-R1-Distill-Qwen-32B (72.6/54.9) and DeepSeek-R1-Distill-Llama-70B (70.0/55.0) on AIME 24/25. At 7B scale, AceReason-Nemotron-7B is competitive with Skywork-OR1-Math-7B (69.8 vs 69.0 on AIME 24) and Light-R1-7B (59.1), but trails OpenMath-Nemotron-7B (74.8 on AIME 24) by ~6 points, suggesting distillation still holds an edge at the smaller scale for math. Against frontier models, the 14B model approaches QwQ-32B (79.5/65.8) and o3-mini-medium (79.6/76.7) on AIME, while remaining below Llama-Nemotron-Ultra-253B (80.8/72.5) by 2.2/5.1 points.

## Relation to Prior Work

This paper builds directly on the GRPO algorithm (Shao et al., 2024) and the token-level policy gradient variant from DAPO (Yu et al., 2025), using DeepSeek-R1 distilled Qwen2.5 checkpoints as starting points and following the DeepSeek-R1 evaluation protocol. It departs from the prevailing narrative established by DeepSeek-R1 and Llama-Nemotron—that distillation outperforms RL for small and mid-sized models—by demonstrating that RL initialized from *strong* distilled models (rather than base pre-trained models) can match or exceed state-of-the-art distillation-based results at 7B and 14B. The sequential math-then-code RL curriculum, the stage-wise length extension strategy, and the cross-domain transfer observation (math RL boosting code performance) represent the paper's primary methodological contributions, positioned as a systematic empirical study with detailed ablations rather than a new algorithm.

## Why It Matters / Open Questions

The paper provides a concrete, reproducible recipe for large-scale RL training of reasoning models at 7B/14B scale, challenging the field's assumption that RL is only effective for the largest models (671B+). The cross-domain transfer finding—that math-only RL substantially improves code reasoning without any code-specific training—has practical implications for training efficiency and suggests that reasoning capabilities are more entangled across domains than domain-specific SFT would imply. Key limitations include restriction to verifiable domains (math, code), dependence on strong distilled starting points (not base models), and evaluation primarily on Qwen2.5-based architectures. Open questions include whether the recipe transfers to non-verifiable tasks, whether the cross-domain effect persists at larger scales, and whether the specific curriculum ordering (math before code) is optimal or merely one of several effective sequences.
