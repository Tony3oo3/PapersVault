## Problem

Existing text-to-3D generation methods produce unstructured meshes with poor interactivity, making them impractical for artistic workflows that require editable, animated, and semantically organized geometry. While LLM agents show promise for generating shape programs, they struggle to interpret complex spatial relationships and semantic details in natural language, and prior efforts are either restricted to CAD domains or yield inaccurate, non-compilable programs.
![Teaser figure](../imgs/NEURIPS20252181/cropped_page0_idx0.webp)

## Input / Output

The system takes a free-form natural language prompt describing a 3D object (e.g., long-form functional descriptions from MARVEL-40M+) and produces a structured Blender shape program organized as a flat graph of component nodes, each with a bounding volume, geometric description, and executable code snippet. The final output is a textured 3D mesh with BRDF parameters (diffuse albedo, roughness, metalness) per UV coordinate, plus the underlying GPS representation that supports direct post-modeling editing and animation by re-prompting the LLM with the existing program.

## Method

ShapeCraft introduces a Graph-based Procedural Shape (GPS) representation that flattens a hierarchical decomposition of the prompt into a depth-1 graph of component nodes, each annotated with geometric/positional descriptions and a 6-DoF bounding volume, serving as shared memory across three LLM agents (Parser, Coder, Evaluator). The Parser performs explicit hierarchical shape parsing to constrain the LLM's reasoning space; the Coder generates Blender API code per node using a multi-path sampling strategy (M=3 parallel paths with higher temperature) and iterative VLM-guided refinement (T=3 steps with early stopping); the Evaluator renders multi-view images and provides quantitative scores plus textual feedback. For texturing, a component-aware score distillation (CASD) loss combines global SDS over the full mesh with per-component SDS terms conditioned on each node's geometric description, optimizing a learnable BRDF texture field via xatlas UV parameterization. A representation bootstrapping loop (N=2 iterations) refines the initial GPS by re-parsing the prompt conditioned on visual feedback from rendered bounding boxes, correcting spatial inconsistencies before shape modeling begins.

## Results

On the MARVEL-40M+ subset (26 long-form functional prompts), ShapeCraft achieves the best IoGT (0.471), CLIP Score (27.27), and VQA Pass Rate (0.44) among all compared methods, while attaining a Hausdorff Distance of 0.415—nearly matching MVDream's 0.411. In terms of efficiency, ShapeCraft runs in 11.68 minutes with 21 API calls, substantially faster than MVDream (32.10 min) and LLaMA-Mesh (15.64 min), though slower than the lighter-weight LLM baselines 3D-PREMISE (2.81 min) and CADCodeVerify (3.06 min). The ablation in Table 2 confirms that the multi-path sampling (M=3) and iterative refinement (T=3) configuration yields the best trade-off between geometry quality and runtime.

## Baselines & Comparisons

Against the LLM-based baselines, ShapeCraft clearly dominates: it outperforms 3D-PREMISE (IoGT 0.471 vs 0.385, Hausdorff 0.415 vs 0.527) and CADCodeVerify (IoGT 0.471 vs 0.334) by large margins on all quality metrics, while also beating BlenderLLM (IoGT 0.471 vs 0.455, CLIP 27.27 vs 26.99, VQA 0.44 vs 0.43). Against the autoregressive LLaMA-Mesh, ShapeCraft wins on every metric (IoGT 0.471 vs 0.346, CLIP 27.27 vs 25.72, VQA 0.44 vs 0.28) and is 34% faster. Against the optimization-based MVDream, ShapeCraft achieves better IoGT (0.471 vs 0.427), CLIP (27.27 vs 26.84), and VQA (0.44 vs 0.42), with a near-tie on Hausdorff (0.415 vs 0.411), while running 2.7× faster. In the Table 3 comparison against frontier LLMs with thinking/CoT mode (ChatGPT-o3, o4-mini, DeepSeek-R1, Gemini-2.5-Pro), ShapeCraft achieves the best IoGT (0.471 vs 0.102–0.326), best Hausdorff (0.415 vs 0.489–0.708), and a 100% compile rate (vs 60–80%), though DeepSeek-R1 edges it on CLIP (29.01 vs 27.27), suggesting the GPS representation's structured decomposition is more reliable than free-form CoT for spatially consistent 3D code generation.

## Relation to Prior Work

ShapeCraft sits at the intersection of three research threads: (1) LLM agents for program generation and tool use (AutoGPT, HuggingGPT), (2) procedural shape modeling via executable code (ShapeAssembly, CADCodeVerify), and (3) score distillation sampling for texture synthesis (DreamFusion). It departs from prior LLM-based 3D modeling efforts (3D-PREMISE, BlenderLLM, L3GO) that either generate monolithic shape programs in one shot or rely on VQA-based self-correction restricted to CAD, by introducing the Graph-based Procedural Shape (GPS) representation that explicitly decomposes natural language into a flat task graph with bounding volumes, enabling parallel per-component modeling with multi-path sampling. The texture pipeline extends SDS with a component-aware loss that leverages the GPS decomposition for targeted per-part appearance optimization.

## Why It Matters / Open Questions

The GPS representation addresses a practical gap: existing text-to-3D methods produce unstructured meshes that are difficult to edit, animate, or integrate into industry pipelines, while ShapeCraft's programmatic output is directly manipulable by artists and supports post-modeling interaction (editing, animation) without re-optimization. Key limitations remain: the system struggles with organic or highly complex topology (tails, wings), is sensitive to prompt quality (ambiguous or overly brief descriptions degrade performance), and the Coder agent's capability is bounded by the wrapped Blender API library. Open questions include whether the GPS decomposition generalizes to multi-object scenes, whether the multi-path sampling strategy scales to larger component counts, and whether the approach can incorporate precise dimensional constraints for CAD-accurate output.
