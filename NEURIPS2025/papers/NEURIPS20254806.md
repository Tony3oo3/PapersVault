## Problem

Automated sequential-to-parallel code translation (e.g., C to CUDA) is hindered by severe data scarcity and the inability of existing back-translation methods to guarantee functional equivalence between source and translated code. While prior work filters for syntactic correctness via compilation, no prior approach simultaneously ensures that translated code produces identical outputs to the original for all valid inputs, leaving a critical gap for reliable HPC code generation.

## Input / Output

The framework consumes unpaired monolingual corpora of C functions and CUDA kernels (filtered from BabelTower to 14,687 C and 28,756 CUDA functions that compile and execute). The Translator produces a functionally equivalent target-language program, while the Tester generates five valid unit-test inputs per function. All code is wrapped with auto-generated function-call or CUDA-kernel wrappers that handle memory allocation, grid/block configuration, and side-effect capture, enabling direct execution-based verification on CPU/GPU.

## Method

QiMeng-MuPa introduces a mutual-supervised learning loop with two language-agnostic LLMs — a Translator and a Tester — that iteratively co-verify and co-evolve. In Co-verify, the Translator's output and the Tester's unit tests are jointly executed; only triplets (source, target, tests) where outputs match exactly are retained, simultaneously validating both the translation and the test validity. In Co-evolve, the verified triplets are used to fine-tune both models via back-translation with cross-entropy loss: the Translator learns target→source mapping while the Tester learns target→unit-test mapping. This closed loop means a stronger Translator yields more correct code for the Tester to learn from, while a stronger Tester filters more valid data for the Translator, addressing data scarcity and functional equivalence simultaneously. The framework is language-agnostic (handles C↔CUDA bidirectionally) and converges after ~4 iterations, producing a verified dataset of 10,563 parallel function pairs with unit tests.

## Results

On the BabelTower C-to-CUDA translation benchmark, Qwen2.5-Coder-7B fine-tuned with QiMeng-MuPa achieves 84.96 BLEU, 84.98 CodeBLEU, 95.71% CPass, and 85.15% Pass@1, outperforming the previous state-of-the-art CodeRosetta (0.8B) by 1.56 BLEU and 6.92 CodeBLEU. The method also surpasses DeepSeek-R1 (671B) by 3.33% on Pass@1 and GPT-4.1 by 2.32% on Pass@10. Llama3-8B with QiMeng-MuPa reaches 85.56% Pass@1, and the framework improves base model Pass@1 by up to 28.91% (Qwen2.5-Coder) and 29.44% (Llama3) over their untrained counterparts.

## Baselines & Comparisons

Against CodeRosetta (the prior SOTA for sequential-to-parallel translation), QiMeng-MuPa wins on all reported metrics: +1.56 BLEU, +6.92 CodeBLEU, +14.61 CPass, and +9.19 Pass@1 (85.15 vs. 75.96). Against the large open-source model DeepSeek-R1 (671B), QiMeng-MuPa (7B) leads by 3.33% on Pass@1 (85.15 vs. 82.23) and 1.54% on CPass, though DeepSeek-R1 edges ahead on Pass@10 (97.63 vs. 97.00). Against GPT-4.1, QiMeng-MuPa wins by 4.87% on Pass@1 (85.15 vs. 80.28) and 2.32% on Pass@10 (97.00 vs. 94.68), while GPT-4.1 retains a slight advantage on Pass@5. Against GPT-4o, QiMeng-MuPa leads by 1.46% on Pass@1 (85.15 vs. 83.69) and 2.74% on Pass@10. The only model that narrowly outperforms QiMeng-MuPa on Pass@1 is DeepSeek-V3 (85.61 vs. 85.15), a 671B MoE model, suggesting QiMeng-MuPa achieves near-competitive functional equivalence at roughly 1/100th the parameter scale.

## Relation to Prior Work

This paper extends the back-translation paradigm for code translation (TransCoder, CodeRosetta, BabelTower) by introducing a closed-loop mutual-supervised learning framework where a Translator and a Tester co-evolve. Prior work addressed data scarcity through back-translation but relied on compilation checks or static analysis for filtering, which cannot guarantee functional equivalence; TransCoder-ST used unit tests but depended on the inefficient Evo-suite genetic algorithm. The key departure is making both the code generator and the test generator LLM-based and training them jointly in an iterative Co-verify/Co-evolve loop, so that each model's improvements directly increase the quality of training data for the other.

## Why It Matters / Open Questions

The paper addresses a critical bottleneck in HPC: the scarcity of aligned C↔CUDA training data and the inability of prior methods to verify functional equivalence. The released verified dataset of 10,563 parallel function pairs with unit tests is a tangible resource for the community, and the finding that a 0.6B model trained on this data matches GPT-4.1/DeepSeek-R1 on Pass@k suggests data quality can substitute for model scale in low-resource code domains. Open questions include whether the mutual-supervision loop generalizes beyond C↔CUDA to other parallel paradigms (OpenCL, SYCL, multi-GPU), whether it scales to more complex real-world kernels with irregular memory access patterns, and whether reinforcement learning (mentioned as future work) can further optimize for performance rather than just correctness.
