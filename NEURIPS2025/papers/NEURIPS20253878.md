## Problem

Existing cybersecurity benchmarks for LLM agents rely on manually crafted CTF challenges, simplified web-app vulnerabilities, or datasets with up to 71% label inaccuracy, failing to capture the complexity of real-world security engineering. No automated method exists for constructing verifiable, high-quality proof-of-concept (PoC) artifacts for in-the-wild CVE instances, which blocks both benchmark scalability and data reliability. SEC-bench addresses this gap by proposing the first fully automated framework that reproduces and verifies real-world vulnerabilities at a cost of ~$0.87 per instance.

## Input / Output

The preprocessor ingests 38,201 CVE instances from the OSV database along with heterogeneous bug reports scraped from GitHub Issues, RedHat Bugzilla, and the Chromium Issue Tracker, narrowing to 898 candidates with sanitizer-verifiable C/C++ projects. For evaluation, each task instance provides the agent a vulnerability description (with sanitizer call-stack report for patching), a harness, and the full codebase inside a Docker container; the agent must produce either a byte-level PoC input that triggers the exact sanitizer error (PoC generation) or a compilable patch that eliminates the sanitizer error while preserving functionality (vulnerability patching). The final benchmark comprises 200 verified instances across 29 projects, each packaged as a self-contained Docker image with build scripts, PoC artifacts, and gold patches.

## Method

SEC-bench's core contribution is SECVERIFIER, a multi-agent verification scaffold built on OpenHands that decomposes vulnerability reproduction into three sequential subtasks coordinated by a manager agent. The Builder agent compiles the vulnerable repository and produces an optimized build script; the Exploiter agent extracts or synthesizes a functional PoC from bug reports (generating one from scratch when none is available); and the Fixer agent isolates vulnerability-relevant changes from candidate fix commits into a unified patch. The manager iteratively evaluates each sub-agent's output against predefined criteria and provides targeted feedback until all verification conditions are met. Memory safety sanitizers (e.g., ASan) serve as the deterministic oracle: a PoC is valid only if it triggers the expected sanitizer report, and a patch is valid only if that report disappears after patching. This multi-agent design achieves an 85.7% higher overall verification success rate (26.0% vs. 14.0%) compared to the single-agent CODEACT baseline on the same 50-instance subset, with the largest gains in the fixer (81.2% vs. 58.3%) and builder (90.0% vs. 72.0%) stages.

## Results

SEC-bench successfully verifies 200 real-world CVE instances from 898 seeds across 29 C/C++ projects, at an average cost of $0.87 per instance. On the verified benchmark, SOTA code agents (SWE-agent, OpenHands, Aider) paired with Claude 3.7 Sonnet, GPT-4o, or o3-mini achieve at most 18.0% success on PoC generation and 34.0% on vulnerability patching. The multi-agent SECVERIFIER framework achieves a 26.0% overall verification success rate, an 85.7% improvement over the single-agent CODEACT baseline (14.0%), with the largest gains in the fixer subtask (81.2% vs. 58.3%).

## Baselines & Comparisons

The paper's primary baseline comparison is SECVERIFIER (multi-agent) versus CODEACT (single-agent) on 50 randomly selected instances. SECVERIFIER achieves a 26.0% overall verification success rate versus CODEACT's 14.0%, an 85.7% relative improvement, with the largest gap in the fixer subtask (81.2% vs. 58.3%) and builder (90.0% vs. 72.0%), while the exploiter subtask shows only a marginal difference (35.6% vs. 33.3%). In the agent evaluation on the full 200-instance dataset, SWE-agent and OpenHands are comparable, both exceeding 30% on vulnerability patching and 10% on PoC generation with Claude 3.7 Sonnet, while Aider consistently underperforms (20.0% patch, 1.2% PoC). Notably, even the best agent-model combination (OpenHands + Claude 3.7 Sonnet at 34.0% patching) falls far short of the >60% resolve rates these models achieve on SWE-bench Verified, underscoring the unique difficulty of security tasks.

## Relation to Prior Work

This paper builds on the OpenHands agent framework as its execution substrate and extends the SWE-bench paradigm of real-world issue resolution to security-specific tasks (PoC generation and vulnerability patching). It departs from prior security benchmarks (CVE-Bench, ARVO, CYBENCH) that rely on manual construction, synthetic challenges, or pre-validated fuzzing corpora by introducing SECVERIFIER, a multi-agent scaffold that automatically reproduces and verifies real-world CVE instances using memory safety sanitizers as deterministic oracles. The multi-agent decomposition (builder, exploiter, fixer) is inspired by the task-specialization principle in agent design but is novel in its application to automated security benchmark construction at scale.

## Why It Matters / Open Questions

SEC-bench provides the first scalable, automated pipeline for constructing verifiable security benchmarks from in-the-wild CVEs, removing the manual bottleneck that has limited prior work to small, hand-crafted datasets. The revealed performance gap—SOTA agents achieving at most 34% on patching and 18% on PoC generation versus 60%+ on SWE-bench Verified—challenges the assumption that general SE capability transfers to security and highlights the need for byte-level reasoning and memory-layout understanding. Key limitations include restriction to C/C++ memory-safety vulnerabilities and sanitizer-verifiable classes; extending to other languages, web applications, and kernel vulnerabilities remains open. The framework's self-evolving, low-cost design ($0.87/instance) positions it as a practical foundation for ongoing evaluation as new CVEs emerge.
