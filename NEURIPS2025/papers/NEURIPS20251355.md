## Problem

Existing approaches to selecting agentic components (tools, sub-agents) rely on static semantic retrieval over descriptions, which fails because component descriptions rarely reflect true runtime performance, cost-utility trade-offs are ignored, and the selection is a one-time decision that cannot adapt to evolving inventories or task requirements. This paper formalizes agent composition as a constrained optimization problem and shows that treating it as an online knapsack problem—where component values must be discovered through empirical testing—yields substantially better cost-adjusted performance than retrieval-based baselines.

## Input / Output

The composer takes a natural-language task description, a component inventory (120 tools for single-agent or ~117 sub-agents for multi-agent, each with a text description and a dollar cost), and a budget constraint (e.g., $10 or $30). The task description is first parsed into up to six skills, each with a name, description, importance weight, and 2–3 test queries with reference plans. The output is a fixed subset of components that are then equipped to a CodeAct (single-agent) or ReAct (multi-agent) agent, after which the composed system is evaluated on benchmark tasks. In the multi-agent setting, all sub-agents share a uniform cost of $1 to isolate selection quality from pricing variation.

## Method

The core contribution is an online knapsack composer that iteratively discovers component value through sandbox trials rather than relying solely on description similarity. The composer generates skills and test queries from the task description, retrieves top-K candidate components per skill via BGE-Large-English embeddings, then evaluates each candidate by running the agent on the test queries and using an LLM-as-a-judge to score each skill as helpful, not helpful, or broken. Component value is the sum of importance-weighted helpful scores across uncovered skills, and the ZCL online knapsack algorithm accepts a component only if its value-to-cost ratio exceeds a dynamic threshold Ψ = (Ue/L)^z · L/e, where z is the fraction of budget already spent. Two practical modifications reduce runtime: broken components are permanently excluded, and once a skill is covered by an accepted component, it is no longer re-evaluated for subsequent candidates. An optional AvaTaR prompt-optimization step refines the agent's system prompt using the recorded sandbox trajectories, further improving tool-invocation behavior.

## Results

On single-agent composition with Claude 3.5 Sonnet, the online knapsack composer ($30 budget) achieves 0.47 success rate on GAIA, 0.92 on SimpleQA, and 0.93 on MedQA, consistently lying on the Pareto frontier in success rate vs. cost. In multi-agent composition, the online knapsack composer ($6 budget) increases overall goal success rate from 37% (top-1 retrieval) to 87% on the mortgage domain and from 23% to 40% on the travel domain. The online knapsack composer uses only 3–5 tools (costing $9–$14) versus 122 tools ($398) for the identity baseline, achieving comparable or higher success rates at a fraction of the cost.

## Baselines & Comparisons

The paper compares five composition strategies: identity (all 122 tools), top-1 semantic retrieval, offline knapsack (LP-based selection using similarity scores), online knapsack (ZCL threshold with sandbox testing), and online knapsack + AvaTaR prompt optimization. The online knapsack composer decisively outperforms both retrieval-based baselines: on SimpleQA it achieves 0.92 vs. 0.24 (top-1 retrieval) and 0.88 (offline knapsack) at $30 budget, a 68% absolute gain over retrieval. On GAIA, online knapsack reaches 0.47 vs. 0.19 for retrieval and 0.41 for offline knapsack. In multi-agent composition, the gap widens dramatically: online knapsack ($6) achieves 0.87 overall goal success rate on mortgage vs. 0.37 for top-1 retrieval and 0.70 for offline knapsack, and 0.40 on travel vs. 0.23 and 0.17 respectively. The identity baseline (all tools) matches or slightly exceeds online knapsack on success rate for some single-agent tasks (e.g., 0.47 on GAIA) but at 30× the cost ($398 vs. $12–$14), confirming that the knapsack approach achieves cost-effective composition. The key differentiator is that online knapsack's sandbox testing correctly identifies functional tools (e.g., web_search_paid) that semantic retrieval misses, while avoiding broken or irrelevant components that offline methods include.

## Relation to Prior Work

This paper formalizes agent composition as a budget-constrained optimization problem, positioning it as a subproblem of the broader ADAS (Automated Design of Agentic Systems) framework introduced by Hu et al. [10], which also encompasses inventing new building blocks. It departs from the dominant tool-retrieval paradigm (Qin et al., Shi et al., RAG-MCP) that relies on static semantic matching, and from graph-optimization approaches to agent selection (DyLAN, AgentPrune), by instead adapting the ZCL online knapsack algorithm [41] with real-time sandbox testing to estimate true component utility. The offline variant draws on the multiple-choice knapsack formulation [31], while the online variant introduces iterative value estimation through LLM-as-a-judge evaluation, bridging operations research and agentic system design.

## Why It Matters / Open Questions

The paper addresses a practical bottleneck in agentic system design—the combinatorial explosion of component choices—by showing that real-time capability testing combined with threshold-based acceptance consistently outperforms retrieval-only selection across five models and multiple domains. Key limitations include the 10–30 minute sandbox overhead, the assumption of well-defined task descriptions, and the lack of component-interaction modeling (components are tested individually, not in combination). Open questions include reducing sandbox time, handling ambiguous or evolving task specifications, and extending to dynamic composition that learns from past deployment experience. The finding that a small, well-tested set of 3–4 tools outperforms a large retrieval-based set of 10 tools suggests that quality-of-selection matters more than coverage in agentic composition.
