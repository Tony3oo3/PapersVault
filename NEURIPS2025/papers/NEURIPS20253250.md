## Problem

Existing LLM safety benchmarks evaluate responses using context-independent metrics (toxicity, factuality, bias) that assume a universal harm standard, yet the same response can be benign for one user and trigger fatal action for another with different vulnerabilities. No prior work systematically measures how user-specific context (emotional state, mental health, self-harm history) modulates the safety of an LLM response, nor provides a mechanism to selectively acquire the most safety-relevant context under limited interaction budgets.

## Input / Output

The PENGUIN benchmark provides 14,000 scenarios across seven high-risk domains (Life, Education, Relationship, Health, Social, Financial, Career), each pairing a natural-language user query with a structured 10-attribute profile (age, gender, marital status, profession, economic status, health, education, mental health, self-harm history, emotion). Every scenario exists in both a context-free variant (query only) and a context-rich variant (query + full profile), enabling controlled comparison. Evaluation scores each response on a 5-point Likert scale across three dimensions—risk sensitivity, emotional empathy, and user-specific alignment—using GPT-4o as a validated proxy (κ=0.688, r=0.92 vs. human annotators). RAISE additionally outputs an ordered attribute acquisition path (average length 2.7 queries) that the agent follows before generating the final response.

## Method

RAISE is a training-free, two-stage agent that decouples planning from execution. In the offline phase, attribute selection is formulated as a sequential decision problem over the combinatorial space of 10 attributes, solved via LLM-guided Monte Carlo Tree Search: a lightweight LLM supplies a prior π₀ over unqueried attributes to bias exploration, while MCTS's selection–expansion–simulation–backpropagation loop discovers the acquisition path that maximizes expected safety score under a budget B, storing each (query, path) pair indexed by query embedding. In the online phase, a dual-module agent operates at inference time: an Acquisition Module retrieves the top-k semantically nearest precomputed paths via embedding similarity and uses them as in-context examples to guide which attribute to query next, while an Abstention Module (inspired by therapist interaction protocols) judges after each acquired attribute whether the current context suffices for a safe response, terminating the loop and triggering generation only when confidence is met. The entire pipeline requires no gradient updates, making it deployable on black-box proprietary models like GPT-4o, and achieves a 31.6% safety improvement over vanilla baselines at an average cost of 2.7 user queries.

## Results

On the PENGUIN benchmark (14,000 scenarios, 7 high-risk domains), context-free LLM safety scores average only 2.86/5, while providing full user context raises scores to 4.00/5 (a 43.2% improvement) consistently across all six evaluated models. The full RAISE framework (MCTS planner + abstention module) achieves a 31.6% safety improvement over the vanilla baseline, with the abstention module alone contributing 24.5% (2.86→3.56) and the planner adding a further 5.9% (3.56→3.77). The average interaction cost is just 2.7 user queries per scenario. QwQ-32B achieves the highest absolute safety score of 4.55/5 with the full RAISE pipeline, while LLaMA-3.1-8B shows the largest relative gain (3.15→4.06, +28.9%).

## Baselines & Comparisons

The paper does not compare RAISE against external safety methods; instead, it ablates its own two components against the vanilla (context-free) baseline across six LLMs. The abstention module alone ("+Agent") improves average safety from 2.86 to 3.56 (+24.5%), confirming that simply deferring generation until sufficient context is gathered is the dominant source of gain. Adding the MCTS-based path planner ("+Planner") yields a further 5.9% improvement to 3.77, showing that strategic attribute selection matters but is secondary to the abstention decision. Gains are most pronounced for smaller models: LLaMA-3.1-8B jumps from 3.15 to 4.06 (+28.9%) and Qwen-2.5-7B from 2.75 to 3.91 (+42.2%), while the already-strong GPT-4o improves from 2.94 to 3.83 (+30.3%). In the attribute-subset ablation (k=3 budget), oracle selection (best 3 of 10 attributes per scenario) consistently outperforms both random selection (highly variable) and static selection (fixed top-3: Emotion, Mental, Self-Harm), validating the need for the adaptive MCTS planner rather than a fixed heuristic.

## Relation to Prior Work

This paper departs from the dominant LLM safety evaluation paradigm, which relies on context-independent metrics (toxicity, factuality, bias) and assumes a universal harm standard, by introducing 'personalized safety' as a distinct task formulation where the same response can be safe for one user and harmful for another. It builds on MCTS (Coulom, 2006) as the core planning algorithm but repurposes it for a novel sequential information-acquisition problem over user context attributes rather than game trees. The work also extends the LLM personalization literature—which has focused on surface-level alignment (tone, topic preference, style)—into the safety-critical regime, and formalizes the observation from Röttger et al. (2024) that users perceive identical outputs differently based on personal context, which prior work noted but did not operationalize as a measurable or mitigable problem.

## Why It Matters / Open Questions

PENGUIN provides the first large-scale (14,000 scenarios, 7 high-stakes domains) controlled benchmark for evaluating how user context affects LLM safety, filling a gap that existing safety benchmarks (SafetyBench, SALAD-Bench, etc.) leave unaddressed. The finding that context access yields a consistent ~43% safety improvement across all six evaluated models, and that a training-free MCTS-based agent (RAISE) captures most of this gain with only 2.7 queries, offers a practical, deployable path for high-stakes applications (mental health, finance, career counseling) without model retraining. Key open questions include whether the manually defined 10-attribute schema generalizes to open-ended user contexts, whether the uniform-cost assumption holds in practice, and whether the GPT-4o-as-judge evaluation protocol introduces systematic biases that could mask or inflate safety differences.
