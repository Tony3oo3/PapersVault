## Problem

Memory Mosaics, networks of associative memories, demonstrated superior in-context learning on medium-scale networks and synthetic datasets, but it remained unclear whether these properties survive scaling to LLM sizes (llama-8B) and real-world data. A second open question was whether transformers could replicate Memory Mosaics' new-task learning advantage simply by training on substantially more data.
![Teaser figure](../imgs/NEURIPS20251299/cropped_page3_idx0.webp)

## Input / Output

The model consumes text sequences up to 32k tokens (fine-tuned from 4k pretraining) through a 3-level memory hierarchy where keys encode recent context and values encode near-future tokens. Evaluation spans three input formats: standard next-token prediction, multi-document collections followed by a question (RULER QA), and serialized (x, y) demonstration pairs followed by a test query (few-shot classification). A distinctive aspect is that the associative memory's Gaussian kernel bandwidth adapts dynamically to the number of stored key-value pairs, and the key feature extractor uses input-dependent gating rather than fixed temporal averaging.

## Method

Memory Mosaics v2 replaces transformer attention blocks with Gaussian kernel regression-based associative memories, introducing three architectural modifications over the original Memory Mosaics: (1) an adaptive bandwidth β = β₁n^α + β₀ that shrinks as memory size n grows, following asymptotic kernel bandwidth estimation theory; (2) a gated time-variant key feature extractor where averaging weights λ_T and gate g_T are functions of the input x_T, replacing the original fixed leaky averaging; and (3) a 3-level memory design that splits contextual memory into short-term (near-tokens, position-dependent) and long-term (far-tokens, position-invariant) associative memories, complemented by a persistent SwiGLU feedforward memory. During training, the long-term memory delay m is stochastically sampled from [64, 256] to encourage proper allocation of position-invariant versus position-dependent signals, while the short-term window h is fixed at 256. The symmetric key-query design (the same L₂-normalized vector serves as both key and query) and the absence of explicit position encoding enable induction-head-like behavior in a single layer, whereas transformers require at least two attention layers with asymmetric query-key extractors and position encoding to achieve the same mechanism.

## Results

On persistent-knowledge benchmarks (19 standard language tasks), Memory Mosaics v2 large (9.9B params, 1T tokens) matches the LLaMA-8B transformer baseline at 52.2% average accuracy. On new-knowledge storage (RULER multi-document QA at 32k task length), Memory Mosaics v2 large achieves 53.4% versus 41.1% for the transformer trained on the same 1T tokens — a 12.3-point gap. On in-context learning (Banking77, TACRED, GoEmotions few-shot classification), Memory Mosaics v2 outperforms transformers by more than 10% across all tasks and, unlike transformers, consistently improves as more demonstration shots are provided. Most strikingly, a transformer trained on 8T tokens (8× more data) still lags behind Memory Mosaics v2 (1T tokens) by 6.5 points on RULER 32k (46.9% vs 53.4%).

## Baselines & Comparisons

The sole baseline family is LLaMA-architecture transformers (small ~1.5B and large ~8B) trained with identical hyperparameters and data. On persistent-knowledge storage (19 standard benchmarks), the two architectures tie at 52.2% average for the large models, confirming that the architectural differences do not hurt standard language understanding. On new-knowledge storage (RULER multi-document QA), Memory Mosaics v2 wins decisively: 53.4% vs 41.1% at 32k task length (12.3-point gap), and the gap widens to 14.8 points at 16k. On in-context learning, Memory Mosaics v2 outperforms transformers by over 10% on all three classification tasks (Banking77, TACRED, GoEmotions) in both semantic and anonymous label settings, while transformers paradoxically degrade as more shots are added. The critical scaling comparison (Table 5, Figures 6–7) shows that even 8× more training data (8T vs 1T tokens) cannot close the gap: the 8T transformer reaches only 46.9% on RULER 32k versus 53.4% for Memory Mosaics v2, and on anonymous-label ICL the 8T transformer still trails by a large margin. In fine-tuning, a single minibatch on Memory Mosaics v2 yields a 22% accuracy gain, surpassing a transformer fine-tuned for 800 minibatches.

## Relation to Prior Work

This paper scales the Memory Mosaics architecture (Zhang et al., ICLR 2025), which replaces transformer attention with Gaussian kernel regression over key-value associative memories, to LLaMA-8B scale with three architectural modifications: adaptive bandwidth scheduling, a gated time-variant key feature extractor, and a 3-level (short-term/long-term/persistent) memory design. It positions itself explicitly against the transformer scaling paradigm, drawing on the induction-head mechanism literature (Olsson et al., 2022; Bietti et al., 2023) to explain why symmetric keys-as-queries and the absence of position encoding enable single-layer induction. The paper also situates itself relative to memory compression methods (RWKV, Mamba, xLSTM), arguing they fail on new-task learning by construction because they cannot store arbitrary information before receiving a retrieval query.

## Why It Matters / Open Questions

The central finding—that a transformer trained on 8× more tokens (8T) still lags behind Memory Mosaics v2 (1T) on anonymous-label in-context learning, and that more data can actually *degrade* transformer performance on that task—challenges the prevailing 'scale data and compute' assumption for new-task learning capabilities. The fine-tuning speed result (one mini-batch on Memory Mosaics v2 outperforming 800 mini-batches on a transformer) has immediate practical implications for domain adaptation. Open questions include whether the advantage persists at true frontier scale (70B+), how to reduce the higher per-token FLOPs cost (18.9B vs 16.7B) for very long contexts, and whether the 3-level memory design generalizes to multimodal settings.
