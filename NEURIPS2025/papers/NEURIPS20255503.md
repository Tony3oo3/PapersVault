## Problem

LLM agents that invoke APIs via natural language instructions frequently misinterpret user intent, yet no systematic, quantifiable testing framework exists to stress-test this 'intent integrity' under evolving toolkits. Existing benchmarks rely on fixed test cases that cannot keep pace with new APIs, and adversarial testing techniques target jailbreaking or prompt injection rather than benign task execution. Classical software testing assumes structured inputs and does not transfer to the open-ended ambiguity of natural language.

## Input / Output

The framework consumes API toolkit documentation (parameter names, types, constraints) to construct a parameter-partition form, then generates one seed natural-language task per partition cell. It produces mutated test tasks ranked by a lightweight SLM's error-likelihood score, identified intent integrity violations categorized as VALID, INVALID, or UNDERSPEC, and persistent strategy memory entries indexed by parameter datatype and integrity category. Evaluation is measured via EESR (proportion of partitions where at least one error is found within a fixed query budget) and AQFF (average queries to first failure).

## Method

TAI3 bridges the gap between formal API specifications and natural-language ambiguity through three mechanisms. First, semantic partitioning applies equivalence-class partitioning to each API parameter's value domain across three intent categories (VALID, INVALID, UNDERSPEC), producing a finite, interpretable grid of semantically distinct test situations. Second, intent-preserving mutation generates paraphrased variants from seed tasks, filters them via an LLM-based intent consistency check, and ranks survivors using a small language model (phi4-mini) that scores how well the original intent can be reconstructed from the mutated text—lower scores indicate higher error risk. Third, an evergreen strategy memory stores successful mutation patterns (e.g., 'hesitate between two enum options') indexed by datatype and category; for each new task, the top-3 relevant strategies are retrieved and adapted, enabling the framework to accumulate testing experience across APIs and domains.

## Results

TAI3 consistently outperforms the SelfRef baseline in EESR (Error-Exposing Success Rate) across all 5 domains, 3 target models, and 3 intent categories, with improvements ranging from +0.7 to +16.3 points. The largest gains appear in Finance VALID (Llama-3.1-8B: 80.5 vs. 65.0, +15.5) and Office UNDERSPEC (Llama-3.1-8B: 82.0 vs. 65.7, +16.3). In terms of efficiency, TAI3 reduces AQFF (Average Queries to First Failure) by up to 12% in the UNDERSPEC setting, and its error-likelihood-based ranking (using phi4-mini) outperforms both random selection and last-5 selection strategies across all values of k.

## Baselines & Comparisons

The paper compares TAI3 against a single naive baseline, SelfRef, which feeds mutated inputs to the target agent and allows the mutator to self-reflect for a fixed number of steps (query budget = 5). TAI3 wins on EESR in all 45 domain–model–category combinations, with no ties or losses. The margin is largest for weaker target models (Llama-3.1-8B) and in the VALID and UNDERSPEC categories, where TAI3's semantic partitioning and error-likelihood ranking provide the most guidance (up to +19.5 points for Finance VALID with GPT-4o-mini). For stronger or more robust targets (Qwen-30B-A3B), the gap narrows (e.g., +0.7 for Office VALID), suggesting that the baseline's self-reflection is somewhat effective when the agent is already less error-prone. On the efficiency metric AQFF, TAI3 also consistently requires fewer queries to trigger the first failure, with the most pronounced advantage (up to 12% reduction) in the UNDERSPEC setting. Additionally, TAI3's predictive prioritization (using phi4-mini) outperforms both uniform random sampling and a 'select last 5' heuristic across all values of k, confirming that error-likelihood-based ranking is a meaningful contributor to the overall gains.

## Relation to Prior Work

TAI3 repurposes classical black-box software testing concepts—equivalence class partitioning and mutation testing—from structured input spaces to the unstructured natural language domain of LLM agents, using API specifications as the grounding structure that makes the input space finite and interpretable. It explicitly departs from the dominant LLM agent red-teaming literature (jailbreaking, prompt injection, adversarial attacks) by targeting benign, everyday tasks and the semantic gap between user intent and API parameter filling. The closest prior efforts, ToolFuzz (which tests tool documentation/implementation bugs) and PDoctor (which checks high-level planning constraints), address different failure modes; TAI3 carves out the specific problem of whether low-level API calls faithfully reflect the user's original intent.

## Why It Matters / Open Questions

As LLM agents are deployed in safety-critical domains (finance, healthcare, smart home), the ability to systematically and quantifiably verify that an agent preserves user intent across evolving toolkits is a practical necessity that existing fixed benchmarks cannot provide. The framework's key limitation—requiring access to the agent's API-calling trajectory—restricts applicability to commercial agents that only expose high-level outputs, leaving an important open question about testing under restricted observability. The finding that weaker testing models can still expose meaningful errors in stronger targets has practical implications for cost-efficient agent evaluation pipelines.
