## Problem

Existing trajectory modeling methods are tightly coupled to specific tasks and datasets, making cross-task and cross-dataset transfer difficult. Prior unified frameworks (e.g., TrajFM, UniTraj) support only a narrow range of tasks, underperform specialized models on individual tasks, and require complex manual training pipelines. The paper asks whether an LLM-based agent can automate the full trajectory modeling pipeline—data preparation, model selection, training, and optimization—across diverse tasks and data without human intervention.
![Teaser figure](../imgs/NEURIPS20250729/cropped_page1_idx0.webp)

## Input / Output

The framework accepts a natural-language query describing the desired trajectory task, optional raw trajectory data in either check-in format (sequences of visited POIs with timestamps) or GPS format (sequences of lat/lon points at fixed sampling intervals), and an optional pre-selected model. It produces an optimized, trained model checkpoint, a structured analytical report summarizing the optimization path and final metrics, and API-accessible inference endpoints. Data preprocessing (cleaning, normalization, format transformation) is handled automatically via LLM-generated code scripts, and the system supports 5 fundamental tasks spanning 9 subtasks with 18 specialized models.

## Method

TrajAgent comprises three components: (1) UniEnv, a unified runtime environment exposing standardized data, model, and tool interfaces so that heterogeneous trajectory models and datasets can be invoked through a single API; (2) an agentic workflow decomposed into four sequential modules—task understanding, task planning, task execution, and task summary—each implemented as a Reflexion-style agent with long-term and short-term memory and a think-then-action loop; and (3) a collaborative learning schema that couples high-level LLM reasoning (selecting data augmentation operators, hyperparameter configurations, and prompt updates) with low-level supervised training of specialized models, iterating until performance targets or a step budget is reached. The optimization proceeds in a joint schedule: data augmentation is optimized first, then parameter tuning, and the cycle repeats. For LLM-based specialized models, a separate prompt-optimization agent selects high-scoring inference traces from memory to augment the prompt, effectively performing in-context learning without weight updates.

## Results

TrajAgent achieves performance improvements of 2.38%–69.91% over the original specialized models across 10 trajectory modeling subtasks on 7 real-world datasets. The largest gains appear in map-matching (GraphMM: Acc_m 0.2014→0.3422, +69.91%), trajectory recovery (TrajBERT: MAE 42.71→27.78, −34.96%), and trajectory user linking (S2TUL: Acc@5 0.5755→0.7802, +35.57%). For next-location prediction, GETNext improves from 0.3720 to 0.4002 Acc@5 (+7.58%) and the LLM-based LLM-ZS from 0.3110 to 0.3350 (+7.72%). The anomaly detection task (GM-VSAE, AUC 0.9892→0.9899) shows negligible gain, attributed to the already-saturated performance of the original model.

## Baselines & Comparisons

TrajAgent consistently outperforms every specialized trajectory model it optimizes: GETNext (+7.58% Acc@5), DeepMove (+17.42%), RNN (+51.36%), LLM-ZS (+7.72%), S2TUL (+35.57%), MainTUL (+25.66%), DPLink (+6.08%), TrajBERT (−34.96% MAE), GraphMM (+69.91% Acc_m), MulT-TTE (−21.18% MAE), DeepTTE (−6.19% MAE), LIMP (+2.38%), DSTPP (−22.27% MAE), and CASCR (+12%). The sole exception is GM-VSAE for anomaly detection, where the original AUC of 0.9892 is already near saturation, yielding only a 0.0007 gain. Against the AutoML baseline Optuna [1], TrajAgent achieves superior trajectory-user-linking performance (S2TUL on FSQ) with fewer trial-and-error iterations, and further gains >11.1% when joint optimization with data augmentation is enabled (Fig. 4c). Compared to the LLM-based urban framework UrbanLLM [26], which automates model usage without further optimization, TrajAgent substantially outperforms it on the same task, confirming that the collaborative learning schema (data augmentation + parameter tuning) is the key differentiator. Across the two check-in datasets (FSQ and BGK) and three models per task (Table 2), improvements range from 6.08% to 35.57%, demonstrating generalization beyond a single dataset–model pair.

## Relation to Prior Work

TrajAgent extends the LLM-as-controller paradigm established by HuggingGPT and VisionLLM to the trajectory modeling domain, where prior unified models (TrajFM, UniTraj, Pretrained Mobility Transformer) suffered from limited task coverage, inferior per-task performance, and complex training pipelines. The agentic workflow directly inherits the think-then-action loop with long/short-term memory from Reflexion, while the collaborative learning schema introduces a novel two-level optimization (high-level agent reasoning over low-level model training) that has no direct precedent in prior AutoML or LLM-agent literature. Unlike UrbanLLM, which automates model usage without further optimization, TrajAgent closes the loop with iterative data augmentation, hyperparameter tuning, and prompt optimization driven by real-time training feedback.

## Why It Matters / Open Questions

This is the first framework to unify 18 models across 5 trajectory task families under a single automated pipeline, offering trajectory researchers a practical alternative to manually adapting models to new datasets and regions. The consistent 2.38%–69.91% gains across tasks and the demonstration that the framework generalizes across models (RNN, DeepMove, GETNext, S2TUL, etc.) suggest a reusable infrastructure for the trajectory modeling community. Key open questions include: whether the optimization trap and memory saturation issues identified here generalize to other agentic ML frameworks, how the approach scales to truly novel trajectory modalities (e.g., multi-agent, 3D), and whether the heavy reliance on strong LLMs (Qwen2-72B, GPT-4o-mini) limits accessibility. Computational overhead (hours per task) also remains a barrier for high-throughput applications.
