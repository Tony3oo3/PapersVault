## Problem

Graph Foundation Models (GFMs) face two practical bottlenecks: knowledge updating requires costly retraining or fine-tuning as graph data evolves, and reasoning faithfulness suffers from hallucinations (fictitious nodes or features) when GFMs operate solely on fixed internal parameters. No existing retrieval-augmented generation framework is designed to handle the structural topology and multimodal (text + graph) nature of graph data while integrating seamlessly with GFM inference.
![Teaser figure](../imgs/NEURIPS20250281/cropped_page1_idx0.webp)

## Input / Output

The method takes a hybrid user query comprising a natural-language description and an associated graph structure (nodes with text attributes, edges, and topology), and produces task-specific predictions: node classification labels, link prediction scores, graph classification labels, or regression values. The GFM operates in a zero-shot protocol with no task-specific fine-tuning; instead, RAG4GFM supplies three most-relevant retrieved subgraphs per query instance to ground the GFM's inference. The retrieval strategy adapts dynamically to the task granularity (node-level, edge-level, or graph-level), selecting different feature spaces and fusion operators accordingly.

## Method

RAG4GFM is a three-stage inference-time pipeline that augments a frozen GFM with external graph knowledge without any parameter updates. First, a multi-level graph indexing module encodes graph data at four granularities—node text (via LM), node structure (via LAPPE + in/out-degree), edge structure (via line-graph LAPPE), and graph-level (aggregated node/edge features + statistics)—and organizes them into HNSW-based hierarchical indices enabling O(log N) retrieval. Second, a task-aware retriever uses an LM-based classifier to identify the task type (node/edge/graph), adaptively queries the relevant feature spaces, and aggregates multi-channel results via Reciprocal Rank Fusion. Third, a graph fusion enhancement module integrates retrieved subgraphs through two complementary mechanisms: attention-based feature fusion (similarity-weighted node/edge/graph feature aggregation with threshold filtering) and topological structure enhancement (sparse adjacency matrix addition weighted by graph-level relevance scores). This dual fusion preserves both semantic and structural information, distinguishing it from NLP RAG's simple text concatenation and enabling the GFM to reason over an enriched, topology-consistent graph at inference time.

## Results

On node classification (Computers), RAG4GFM (AnyGraph-based) achieves 79.56% accuracy and 66.12% ROC-AUC, outperforming the strongest retrieval-enhanced baseline G-Retriever (75.06% / 64.95%) by 4.5 and 1.2 points respectively. On link prediction (History), RAG4GFM reaches 63.45% accuracy and 64.12% ROC-AUC, surpassing the best baseline (GNNSafe at 59.62% / 61.44%) by 3.8 and 2.7 points. On graph classification (MiniGCDataset), RAG4GFM attains 65.51% accuracy, exceeding G-Retriever (63.73%) by 1.8 points. In efficiency comparisons, RAG4GFM reduces training time by up to 7.0× and peak GPU memory by over 60% relative to GraphLoRA under identical accuracy targets (e.g., 63 min vs. 7.32 h and 9.86 GB vs. 25.23 GB on Computers).

## Baselines & Comparisons

RAG4GFM (AnyGraph-based) wins on all three evaluated tasks against all nine baselines. On Computers node classification, it leads G-Retriever (75.06%) by 4.5 points in accuracy and GraphRAG (74.47%) by 5.1 points, while prompt-engineering methods (Few-shot, CoT, IR-augmented CoT) cluster around 69.6–69.7% and graph OOD methods (Prototype, GNNSafe) reach only ~71%. On History link prediction, RAG4GFM (63.45% Acc / 64.12% ROC-AUC) outperforms the strongest retrieval baseline G-Retriever (60.27% / 61.97%) by 3.2 and 2.2 points, and GNNSafe (59.62% / 61.44%) by 3.8 and 2.7 points. On MiniGCDataset graph classification, RAG4GFM (65.51%) edges out G-Retriever (63.73%) by 1.8 points, though the ROC-AUC gap narrows (51.88% vs. 52.32%). Among retrieval-enhanced baselines, graph-aware methods (GraphRAG, G-Retriever) consistently outperform text-only VanillaRAG, confirming the importance of structure-aware retrieval. In the efficiency comparison against GraphLoRA [22], RAG4GFM achieves the same 78% accuracy target on Computers in 63 minutes versus 7.32 hours (7.0× speedup) with 9.86 GB versus 25.23 GB peak GPU memory (61% reduction).

## Relation to Prior Work

This paper extends the RAG paradigm (Lewis et al., 2020) from text corpora to graph data and Graph Foundation Models, addressing three challenges specific to graph RAG: structure-preserving indexing, task-heterogeneous retrieval, and topology-aware augmentation. It builds on graph indexing infrastructure (HNSW), structural encodings (LAPPE), and existing graph RAG efforts (GraphRAG, G-Retriever), but departs from them by introducing a multi-level hierarchical index spanning node, edge, and graph granularities, and by performing dual fusion (attention-based feature fusion plus sparse adjacency matrix fusion) rather than simple concatenation. The paper positions itself as an alternative to parameter-efficient fine-tuning methods (GraphLoRA, G-Adapter) for knowledge updating, arguing that retrieval-based augmentation avoids costly retraining and catastrophic forgetting.

## Why It Matters / Open Questions

RAG4GFM offers a practical path to keeping GFMs current without expensive retraining, with a demonstrated 7× speedup and 60%+ memory reduction over GraphLoRA at matched accuracy — a meaningful efficiency gain for deployment in dynamic graph environments. However, the evaluation is limited to graphs of at most ~108K nodes, no error bars or statistical significance tests are reported, and the framework's scalability to billion-node graphs or real-time streaming settings remains untested. Open questions include whether the fusion mechanism degrades when retrieval quality is poor, how the approach handles adversarial or noisy retrieved subgraphs, and whether the gains persist when the base GFM is itself very large.
