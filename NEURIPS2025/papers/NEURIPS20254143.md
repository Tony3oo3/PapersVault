## Problem

Scaling rollouts in RL for LLM reasoning (e.g., via Dynamic Sampling) improves training quality by filtering zero-variance prompts, but this filtering happens only after expensive rollout generation, wasting substantial computation on prompts that yield no learning signal. The paper asks how to perform selective rollouts that focus on valuable prompts before generation, making rollout scaling more efficient without sacrificing accuracy.

## Input / Output

GRESO consumes each prompt's historical reward training dynamics—a trace of (epoch, set of G response rewards) tuples accumulated across prior epochs—and produces a per-prompt filtering probability that determines whether to skip or sample that prompt in the current rollout batch. The filtering decision is made online before any new generation, and the base exploration probability is self-adjusted each iteration toward a user-specified target zero-variance percentage (split between easy and hard prompts). The final output is a trained LLM whose performance matches Dynamic Sampling while using up to 3.35× fewer rollouts.

## Method

GRESO exploits a key empirical observation: prompts that are zero-variance in one epoch are highly likely to remain zero-variance in near-future epochs (over 90% temporal consistency). It computes a filtering probability p_f(x_i) = 1 − p_e^{z_i}, where z_i counts the most recent consecutive zero-variance rollouts for prompt x_i and p_e is a base exploration probability, so that repeatedly uninformative prompts are increasingly likely to be skipped while still retaining a non-zero chance of being revisited. Two self-adjusting mechanisms make the method practical: (1) separate exploration probabilities for easy and hard zero-variance prompts are nudged up or down by a fixed step Δp each iteration to track a target zero-variance ratio, and (2) an adaptive rollout batch size shrinks the sampling batch when only a small number of additional effective examples are needed to fill the training batch. The entire filtering logic runs in negligible overhead before the vLLM rollout stage, reducing rollout time by up to 2.4× and total training time by up to 2.0× across Qwen2.5-Math and DeepSeek-R1-Distill models from 1.5B to 32B parameters.

## Results

GRESO achieves comparable average accuracy to Dynamic Sampling (DS) across all model/dataset settings while reducing rollouts by up to 3.35× (e.g., 6.3M vs. 13.1M rollouts on Qwen2.5-Math-7B/DM, with 57.5% vs. 57.8% average accuracy). In wall-clock time, GRESO delivers up to 2.4× speedup in rollout and 2.0× speedup in total training (e.g., 88.3h vs. 178.0h for Qwen2.5-Math-7B). On coding tasks (LiveCodeBench), GRESO actually outperforms DS (22.8% vs. 22.1% avg@4) while using fewer rollouts (1.07M vs. 1.9M).

## Baselines & Comparisons

The primary baseline is Dynamic Sampling (DS) from DAPO [49], which oversamples and filters zero-variance prompts *after* rollout. GRESO matches DS accuracy within ~0.5% across all six math benchmarks and three model sizes, while using 2–3.35× fewer rollouts (e.g., 6.3M vs. 13.1M on Qwen2.5-Math-7B/DM). On the coding task (LiveCodeBench), GRESO actually surpasses DS (22.8% vs. 22.1% avg@4) with fewer rollouts (1.07M vs. 1.9M). Compared to vanilla GRPO [36] on coding, GRESO improves accuracy from 19.9% to 22.8% while using more rollouts (1.07M vs. 0.5M), reflecting the cost of selective filtering. When applied to RLOO [20], GRESO raises accuracy from 55.1% (vanilla RLOO) to 57.0%, matching RLOO+DS (56.8%) while requiring only 1.2M rollouts versus 2.56M for RLOO+DS.

## Relation to Prior Work

GRESO builds directly on GRPO (DeepSeekMath) and DAPO's Dynamic Sampling, which filters zero-variance prompts only after costly rollout generation. The key conceptual departure is shifting the filtering decision to the pre-rollout stage by exploiting temporal consistency in reward training dynamics—prompts that are zero-variance in one epoch tend to remain so in subsequent epochs. This contrasts with static data-pruning methods (e.g., LIMR) that require a separate offline model to identify valuable samples, and with Dynamic Sampling's oversample-then-discard approach that wastes rollout compute on prompts already known to be uninformative.

## Why It Matters / Open Questions

Since rollout is the dominant computational bottleneck in RL-based LLM training, a 2.4× rollout speedup with no accuracy loss is a practically significant efficiency gain that lowers the barrier for labs with limited GPU budgets. The main limitation is that GRESO performs only binary filtering (zero-variance vs. effective) and does not rank the relative training value among effective prompts, leaving room for finer-grained data selection. An open question is whether the temporal-consistency signal can be extended to predict not just informativeness but the magnitude of learning signal a prompt will provide, enabling prioritized rather than binary selection.
