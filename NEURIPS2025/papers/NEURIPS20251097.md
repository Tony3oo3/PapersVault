## Problem

Cloud-based text-to-image generation services expose user prompts containing sensitive attributes (gender, ethnicity, age) to the server, while existing privacy-preserving solutions either impose prohibitive computational overhead (cryptographic methods like HE-Diffusion require >10^6 seconds) or degrade image utility (differential privacy perturbation). No prior approach simultaneously provides rigorous prompt privacy, image quality comparable to full cloud models, and manageable server cost.
![Teaser figure](../imgs/NEURIPS20251097/cropped_page0_idx0.webp)

## Input / Output

The method takes a user text prompt (which may contain sensitive attributes) and a random noise latent as input, and produces a single generated image as output. The prompt is first transformed client-side into a set of N candidate prompts that differ only in sensitive attribute values (e.g., gender ∈ {male, female}, age ∈ {young, middle-aged, old}, ethnicity ∈ {caucasian, african, asian, indian, european}), all of which are sent to the server. The server returns N intermediate latents after k denoising steps; the client selects the one corresponding to the true prompt and completes the remaining T−k steps locally. Experiments use 512×512 (MS-COCO) and 1024×1024 (MJHQ) resolutions with 25-step DPM-Solver (8-step for LCM-SDXL).

## Method

ObCLIP is a plug-and-play oblivious cloud-device hybrid generation scheme with two core components. First, oblivious transformation: the client enumerates all combinations of sensitive attribute values to construct N candidate prompts, so the server processes all N without knowing which is the real one, providing λ-oblivious indistinguishability (Theorem 1). Second, local extraction with a server-first allocation: only the initial k denoising steps (the semantics-planning stage) run on the large cloud model over all N candidates, after which the client retrieves its target latent and finishes the remaining T−k steps on a small device model. To offset the N× server overhead, two acceleration strategies exploit redundancy: temporal caching (skipping self-attention and down/mid-block computation after a cache point r and skip point s, refreshing every 5 steps) and batch reuse (computing attention maps once for a pivot prompt and broadcasting them across all candidates, since they differ only in sensitive attributes). This reduces server cost by 4.4–7.6× compared to vanilla oblivious generation while maintaining FID and CLIP scores comparable to the full cloud model.

## Results

On 30k MS-COCO prompts, ObCLIP(k=10, +cache) with SD-v1.4 + BK-SDM-small achieves FID 15.73 and CLIP 0.2865, reducing server FLOPs from 18.53T to 5.84T (×N) compared to standalone SD-v1.4 (FID 13.86). On 5k MJHQ prompts, ObCLIP(k=10, +cache) with SDXL + Koala-700m achieves FID 30.79, nearly matching SDXL's 30.67, while cutting FLOPs from 159.35T to 45.11T (×N). On the candidate prompt dataset with N=6, ObCLIP(k=10, +reuse) actually improves FID from 113.39 (Realistic Vision) to 109.76 with only 1.55s cloud latency vs. 1.12s for cloud-only, and is 4.4–7.6× faster than vanilla oblivious generation and orders of magnitude faster than HE-Diffusion (>10⁶s).

## Baselines & Comparisons

Against standalone cloud models (SD-v1.4, SDXL, Realistic Vision v4.0), ObCLIP achieves comparable FID (e.g., 15.73 vs. 13.86 on MS-COCO; 30.79 vs. 30.67 on MJHQ) while reducing server FLOPs by 3–7×, at the cost of a modest FID increase of 1–2 points. Against standalone device models (BK-SDM-small, BK-SDM-tiny, small-sd, Koala-700m), ObCLIP substantially outperforms on both FID and CLIP score (e.g., FID 15.73 vs. 18.30 for BK-SDM-small; CLIP 0.2865 vs. 0.2710), demonstrating that server-guided initial steps are critical for semantic quality. Against Hybrid SD (the closest non-private hybrid baseline), ObCLIP incurs roughly N× server FLOPs due to oblivious generation, but with cache+reuse acceleration the cloud latency is nearly identical at N=2 (0.57s vs. 0.55s at k=10) and only ~3× higher at N=6 (1.55s vs. 0.55s), while providing rigorous prompt privacy that Hybrid SD lacks. Against the cryptographic baseline HE-Diffusion, ObCLIP is orders of magnitude faster (sub-second cloud latency vs. >10⁶s). Against vanilla oblivious generation (no acceleration), ObCLIP with cache+reuse reduces server latency by 4.4–7.6× (e.g., 1.55s vs. 7.47s for N=6 on the candidate prompt dataset). Against the step-distilled LCM-SDXL, ObCLIP(k=4, Δt=8, +cache) achieves FID 34.12 vs. 33.25 with FLOPs reduced from 50.99T to 21.78T (×N), confirming scalability to few-step distilled models.

## Relation to Prior Work

ObCLIP directly extends the Hybrid SD cloud-device collaborative inference paradigm by inserting an oblivious transformation layer: instead of sending a single prompt embedding to the server, the client sends a set of candidate prompts differing only in sensitive attributes, and the server processes all of them without knowing which is real. The server-side acceleration strategies (temporal attention caching from T-Gate, block skipping from Faster Diffusion) are repurposed and extended with a novel batch-reuse mechanism that exploits the structural similarity across candidate prompts. This departs from prior privacy-preserving T2I approaches (HE-Diffusion, MPCViT) that rely on heavyweight cryptography, and from DP-based prompt perturbation (SANTEXT, CAPE) that sacrifices semantic fidelity, by offering information-theoretic indistinguishability with only a modest computational overhead.

## Why It Matters / Open Questions

ObCLIP provides a practical, plug-and-play privacy safeguard for deployed T2I services (Midjourney, DALL-E) where prompt leakage is a genuine concern, achieving rigorous indistinguishability with 4.4–7.6× lower server cost than vanilla oblivious generation and orders of magnitude less than cryptographic baselines. Key limitations include the sub-linear scaling of server cost with the number of candidate prompts N, the restriction to text-to-image (not image-to-image with reference faces), and the semi-honest adversary model. Open questions include whether DP-based top-k candidate selection can reduce N while retaining measurable privacy, and how the scheme extends to more complex sensitive attributes or multi-turn conversational generation.
