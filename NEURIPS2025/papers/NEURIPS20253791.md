## Problem

Existing SVG generation methods face a fundamental trade-off: optimization-based approaches (e.g., DiffVG, LIVE) produce unstructured outputs with redundant anchor points at enormous computational cost, while autoregressive LLM-based methods are constrained to monochrome icons or simple structures due to limited context windows and scarce complex SVG training data. No prior method can generate high-fidelity, multi-layered, colored SVGs exceeding 10k tokens while following diverse multimodal instructions.

## Input / Output

The model accepts text prompts, raster images, or natural character reference images as conditioning inputs, and produces colored SVG vector graphics as a flattened autoregressive token sequence. All SVGs are normalized to a 200×200 viewbox and simplified to six atomic path commands (M, L, C, A, Z, F) via picosvg, with 2D coordinates merged into single tokens (x×w+y) to compress sequence length. The model can generate SVGs exceeding 30k tokens, far beyond the ~2k–8k token limits of prior autoregressive baselines.

## Method

OmniSVG builds on the Qwen2.5-VL vision-language model backbone and introduces a custom SVG tokenizer that maps atomic path commands and merged coordinate pairs into discrete tokens within the VLM's embedding space, using special tokens (<SOP>, <EOS>) to delimit SVG sequences. The key architectural insight is decoupling structural logic from low-level geometry by representing each 2D point as a single token (x×w+y), which mitigates the 'coordinate hallucination' problem common in code-based LLMs while enabling the model to handle SVGs of arbitrary complexity. Training uses standard next-token prediction over the SVG token suffix conditioned on multimodal instruction prefix tokens, leveraging the VLM's native ability to reason over both visual and textual inputs. The model is trained from scratch on the newly introduced MMSVG-2M dataset (2M SVGs spanning icons, illustrations, and anime characters) using bfloat16 with ZeRO-2 and AdamW, with SVG embeddings initialized randomly while loading pre-trained VLM weights.

## Results

On MMSVG-Icon (Text-to-SVG), OmniSVG(4B) achieves the best FID of 137.40, substantially outperforming the next-best baseline Chat2SVG (190.87) and IconShop (213.28), while using only 3.8k tokens versus 66k–132k for optimization-based methods. On MMSVG-Illustration (Text-to-SVG), OmniSVG-L(8B) reaches FID 138.42, competitive with IconShop (107.93) but far ahead of VectorFusion (253.94) and SVGDreamer (419.70). For Image-to-SVG on Icons, OmniSVG(4B) matches Vtracer on DINO score (0.993) while generating SVGs with 3.8k tokens versus Vtracer's 52.4k. On Illustrations (Image-to-SVG), OmniSVG(4B) achieves DINO 0.899 and SSIM 0.906, trailing Vtracer (0.994/0.966) and DiffVG (0.945/0.955) but surpassing GPT-4o (0.875/0.854) and StarVector (0.877/0.900).

## Baselines & Comparisons

On Text-to-SVG for Icons, OmniSVG(4B) achieves the best FID (137.40), beating Chat2SVG (190.87) by 28%, IconShop (213.28) by 35%, VectorFusion (250.77) by 45%, and SVGDreamer (308.94) by 56%, while also leading in Aesthetic score (4.62). On Text-to-SVG for Illustrations, IconShop retains the best FID (107.93 vs. OmniSVG-L's 138.42), but OmniSVG-L still substantially outperforms VectorFusion (253.94) and SVGDreamer (419.70). For Image-to-SVG on Icons, OmniSVG(4B) ties Vtracer on DINO (0.993) and closely matches it on SSIM (0.950 vs. 0.966), while using only 3.8k tokens versus Vtracer's 52.4k; it clearly surpasses GPT-4o (DINO 0.860) and StarVector (DINO 0.895). For Image-to-SVG on Illustrations, OmniSVG trails the dedicated vectorization tools Vtracer (DINO 0.994) and DiffVG (DINO 0.945) but outperforms GPT-4o (0.875) and StarVector (0.877) across all reconstruction metrics. Overall, OmniSVG's key advantage is generating complex, colored SVGs with far fewer tokens (3.8k–6.9k) than optimization-based methods (52k–322k), while matching or exceeding autoregressive baselines on quality metrics.

## Relation to Prior Work

This paper extends the autoregressive SVG generation line (IconShop, Chat2SVG, StarVector, LLM4SVG) by replacing LLM backbones with a native Vision-Language Model (Qwen2.5-VL), enabling multimodal conditioning (text, image, character reference) in a single unified framework. The SVG tokenization strategy—flattening paths into command-coordinate sequences with merged 2D point tokens—follows IconShop's design but extends it with color tokens and scales to 30k+ tokens, far beyond the ~10k limit of prior LLM-based methods. It departs from optimization-based vectorization (DiffVG, LIVE, VectorFusion) by producing structured, editable outputs in a single forward pass rather than iterative refinement, and from code-generating LLMs by parameterizing coordinates as discrete tokens to avoid 'coordinate hallucination.'

## Why It Matters / Open Questions

The introduction of MMSVG-2M (2M annotated SVGs spanning icons, illustrations, and anime characters) and MMSVG-Bench addresses a critical data and evaluation gap that has constrained the field to simple monochrome icons. The unified VLM-based approach opens the door to in-context learning, chain-of-thought reasoning, and multi-turn interactive SVG editing—capabilities that optimization-based or code-generating methods cannot easily support. Key limitations remain: generation time scales linearly with token count for complex SVGs, and the model is restricted to vector-style inputs (failing on natural photographs), leaving open questions about whether multi-token prediction or KV-cache compression can close the efficiency gap with diffusion-based raster generation.
