## Problem

LLM inference reproducibility is fragile: even under greedy decoding with a fixed random seed, changing hardware configurations such as GPU count, GPU type, or evaluation batch size can produce significantly different outputs, with up to 9% accuracy variation and 9,000-token length differences in reasoning models. The root cause is the non-associative nature of floating-point arithmetic under limited precision (especially BF16), where the order of operations—determined by parallelism strategy and batch composition—introduces rounding errors that can flip token selection when top-1 and top-2 logit gaps are minimal. This paper provides the first systematic, quantitative investigation of how numerical precision and runtime configurations jointly affect LLM inference reproducibility.

## Input / Output

The evaluation pipeline takes a text prompt and a transformer model whose weights are stored in BF16 (16-bit) precision, and produces generated token sequences along with per-token probability distributions. Reproducibility is measured across 12 runtime configurations (2 GPU types: A100 and L40S × 2 GPU counts: 2 and 4 × 3 batch sizes: 8, 16, 32), reporting metrics including standard deviation of accuracy, average standard deviation of output length, divergence index (the token position where outputs first differ), and average standard deviation of top-1 token probability. For random sampling experiments, Pass@1 is computed over 4–64 independent runs per configuration, with variance reported across the 6 system configurations rather than across repeated runs of the same configuration.

## Method

The paper's core technical contribution is LayerCast, a hybrid-precision inference pipeline that stores all linear layer weights and biases in BF16 for memory efficiency but upcasts each weight back to FP32 just-in-time for every matrix multiplication during inference. This ensures all arithmetic—attention scores, softmax denominators, logit computations—occurs in full FP32 precision, eliminating the rounding-error accumulation that causes token flips under BF16, while keeping the memory footprint close to that of 16-bit models (approximately 34% less memory than full FP32, particularly important for KV cache in long-context reasoning). LayerCast is implemented as a lightweight patch to vLLM requiring only a few lines of code change. The empirical analysis further isolates the specific runtime factors that alter floating-point operation ordering: continuous batching changes the set of requests in a batch, tensor parallelism distributes computation across GPUs with AllReduce collectives, and different GPU architectures implement floating-point kernels with different internal tiling and reduction strategies. Together, these factors make BF16 inference highly sensitive to deployment environment, while FP32 (and LayerCast) achieves near-perfect determinism with divergence rates below 3.4%.

## Results

Under BF16 greedy decoding, DeepSeek-R1-Distill-Qwen-7B exhibits up to 9.15% standard deviation in accuracy on AIME'24 across 12 runtime configurations (2 GPU types × 2 GPU counts × 3 batch sizes), while FP32 achieves 0% variance. Output length instability is equally severe: BF16 produces up to 9,189-token standard deviation in response length, versus 0 under FP32. The proposed LayerCast pipeline (BF16 storage, FP32 computation) matches FP32-level determinism (divergence rate <3.4%) while reducing memory usage by 34% compared to full FP32 inference.

## Baselines & Comparisons

This is an empirical study comparing numerical precision formats rather than model architectures, so the 'baselines' are BF16 and FP16 inference, with FP32 and the proposed LayerCast as the stable alternatives. FP32 consistently achieves near-zero Std@Acc (0% or ~1e-17) across all four models and all benchmarks, while BF16 introduces 1.7–9.2% accuracy variance depending on model and task. FP16 provides intermediate stability, reducing variance by roughly 2–4× compared to BF16 but still exhibiting measurable divergence (e.g., 5.74% Std@Acc for DeepSeek-R1-Distill-Qwen-7B on AIME'24). LayerCast matches FP32 in divergence behavior (Div_Index distribution nearly identical, divergence rate <3.4%) while cutting memory usage by 34%, making it the practical recommendation. For random sampling (Pass@1), BF16 introduces an additional 0.3–1.7% standard deviation across system configurations beyond the intended stochasticity, a variance that FP32 largely eliminates. The paper also verifies via HuggingFace Transformers (without vLLM) that the same BF16-vs-FP32 gap persists (2.23% vs 0% Std@Acc), confirming the issue is fundamental to GPU floating-point arithmetic rather than a specific serving framework.

## Relation to Prior Work

This paper builds on the vLLM inference framework (Kwon et al., SOSP 2023) as its experimental substrate and extends the line of work on LLM inference nondeterminism (Atil et al., Ouyang et al., Donato et al.) by isolating floating-point non-associativity as the root cause rather than treating nondeterminism as a black-box observation. It departs from batch-invariant kernel approaches (He et al., Thinking Machines Lab), which address only batch-size-related variation, by showing that GPU count, GPU architecture, and tensor parallelism introduce additional, unaddressed sources of divergence. The LayerCast proposal also connects to Feng et al.'s observation that numerical precision affects mathematical reasoning, but generalizes the finding from a single-precision comparison to a systematic multi-precision, multi-hardware study.

## Why It Matters / Open Questions

The finding that greedy decoding with BF16 can produce up to 9% accuracy variance and 9,000-token length differences from merely changing GPU count or batch size directly undermines the reliability of single-run benchmark comparisons that dominate current LLM evaluation practice. LayerCast offers a practical, low-overhead fix (34% memory reduction vs. full FP32) that the community can adopt immediately via a vLLM patch. Open questions include whether the effects scale differently for models above 70B parameters, whether non-transformer architectures exhibit similar sensitivity, and whether hardware vendors can provide deterministic reduction kernels that would eliminate the need for FP32 upcasting entirely.
