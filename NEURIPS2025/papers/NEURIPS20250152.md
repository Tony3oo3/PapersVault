## Problem

LLM-based zero-shot object-goal navigation currently relies on cloud-hosted giant models like GPT-4, but deploying on local devices (e.g., 32GB Jetson Orin) forces the use of smaller LLMs that cannot fully understand complex, growing navigation maps, causing significant success rate drops. Simultaneously, the KV cache of the accumulating map description exceeds on-device memory, and recomputing it each planning step introduces prohibitive real-time latency.
![Teaser figure](../imgs/NEURIPS20250152/cropped_page1_idx0.webp)

## Input / Output

The system consumes RGB-D sensor captures processed by Grounding DINO into object detections with 3D positions, a free-form text goal instruction (e.g., 'find the TV'), and a graph-based navigation map where objects are organized into semantic groups with coordinates. The LLM planner outputs a single sub-goal as a specific object name and its 3D position (e.g., 'sofa at position (131,94,22)'), which a lower-level controller then follows. The navigation map grows incrementally as the robot explores, with new objects appended to existing groups.

## Method

EfficientNav introduces three mechanisms for on-device LLM planning. First, discrete memory caching clusters map objects into groups and precomputes each group's KV cache independently, decoupling group order from cache computation so that selecting different subsets of groups at each planning step reuses cached values without recomputation; newly detected objects are appended to existing groups to preserve cache validity. Second, attention-based memory clustering uses only ~1/10 of the LLM's layers to compute attention between new objects and existing groups, clustering semantically related objects together to mitigate the accuracy loss from ignoring cross-group attention. Third, semantics-aware memory retrieval uses CLIP to encode each group's object descriptions and the goal text, computes similarity scores, and solves a knapsack problem to select the most relevant groups within the device's KV cache memory budget, pruning redundant information that smaller LLMs cannot process effectively.

## Results

On the HM3D benchmark, EfficientNav-34b (LLaVA-34b) achieves 80.0% success rate (SR) and 41.5 SPL, while EfficientNav-11b (LLaMA3.2-11b) achieves 74.2% SR and 39.5 SPL. This represents an 11.1% SR improvement over the best GPT-4-based zero-shot baseline (LFG, 68.9% SR) and a 37.3% SR improvement over the naive LLaVA-34b planner (42.7% SR). In terms of latency, EfficientNav achieves 6.7× real-time latency reduction (0.35s vs 5.80s) and 4.7× end-to-end latency reduction (12.70s vs 59.34s) compared to the GPT-4 planner, and 8.8× real-time latency reduction over the naive LLaMA3.2-11b planner.

## Baselines & Comparisons

EfficientNav outperforms all 17 baselines on both SR and SPL. Against the strongest GPT-4-based zero-shot method (LFG, 68.9% SR / 36.0 SPL), EfficientNav-34b improves SR by 11.1 points and SPL by 5.5 points, while running entirely on-device. Compared to the naive LLaVA-34b planner (42.7% SR / 21.0 SPL), the gains are 37.3% SR and 20.5% SPL, attributed to semantics-aware memory retrieval pruning redundant map information. On latency, EfficientNav-11b reduces real-time latency from 5.80s (GPT-4) to 0.35s and end-to-end latency from 59.34s to 12.70s; even against vllm-optimized inference (2.27s RtL), EfficientNav achieves 6.5× lower real-time latency. Against sparse attention methods (Minference: 35.3% SR / 3.88s; FlexPrefill: 36.7% SR / 3.02s), EfficientNav-34b achieves substantially higher SR (80.0%) and lower latency (0.87s), because discrete memory caching decouples group order from KV cache computation. On the open-vocabulary HM3D-OVON benchmark, EfficientNav (63.5% SR / 31.6 SPL) also surpasses Uni-NaVid (41.3% / 21.1) and FiLM-Nav (44.9% / 24.5).

## Relation to Prior Work

This paper extends the LLM-based modular ObjNav paradigm (MapGPT, LFG, InstructNav) by shifting the planner from cloud-hosted GPT-4 to on-device smaller LLMs, addressing the memory and latency constraints that make cloud deployment impractical. It builds directly on CachedAttention [13] for KV cache offloading to low-speed storage and Prompt Cache [15] for position-encoding-aware modular attention reuse, but introduces a critical adaptation: clustering the growing navigation map into discrete groups so that KV caches can be selectively loaded without recomputation when the context order changes. The semantics-aware retrieval step departs from prior empirical position-based selection [54] and LLM-based selection [8] by using a lightweight CLIP encoder with a knapsack formulation to adapt group selection to both the target object and the device memory budget.

## Why It Matters / Open Questions

The paper demonstrates that the primary bottleneck for on-device LLM-based navigation is not model capacity alone but the unbounded growth of the navigation map's KV cache, and that structured memory management (discrete caching + attention-guided clustering + semantic pruning) can make a smaller on-device model outperform a larger cloud model. This opens the door to privacy-preserving, low-latency, cost-effective embodied agents that do not depend on cloud connectivity. Key limitations include the residual gap between LLM inference speed and small-model speed for extremely time-critical applications, and the evaluation is confined to indoor HM3D environments with a single simulation platform, leaving open whether the approach generalizes to outdoor or multi-robot settings.
