## Problem

Training LLM-based software engineering agents via reinforcement learning requires large-scale interactive tasks with automatic verification, yet existing datasets are either limited to one-shot code generation or small, manually curated collections that lack scale and diversity. Simultaneously, static benchmarks like SWE-bench suffer from data contamination as newer models are exposed to test instances during training, inflating scores and obscuring true generalization ability.

## Input / Output

The pipeline consumes raw GitHub events (issues, pull requests, metadata) from the GitHub Archive and full repository clones with commit histories, restricted to Python repositories (>75% Python LOC) under permissive licenses. It produces 21,336 annotated task instances, each containing a problem statement, solution patch, test patch, a JSON installation recipe (Python version, pip/conda commands, test command), LLM-generated quality labels (issue clarity, task complexity, test patch correctness), and pinned dependency versions. A 294-task subset filtered for 2025 issues, ≤3 modified files, and ≤500-word patches serves as the decontaminated benchmark, evaluated via a fixed ReAct scaffolding with 5 runs per model reporting resolved rate, SEM, and pass@5.

## Method

The core contribution is a four-stage fully automated pipeline that eliminates manual curation. Stage 1 collects ~450K issue-PR pairs and filters to ~153K candidates requiring merged PRs that introduce or modify tests. Stage 2 uses an agentless approach with Qwen2.5-72B-Instruct to generate up to three candidate JSON installation recipes per task by scanning repository files, with iterative LLM-driven refinement on failure logs. Stage 3 performs execution-based verification in isolated containers (via buildah on TractoAI), confirming that test-patch tests fail before and pass after the solution patch, while freezing dependency versions for reproducibility. Stage 4 fine-tunes Qwen2.5-72B-Instruct on SWE-bench Verified human annotations to predict three binary quality labels per task, enabling scalable filtering. For benchmarking, all models are evaluated with an identical minimal ReAct-style prompt and 128K context, and decontamination is enforced by tracking issue creation dates against model release dates, with potentially contaminated evaluations explicitly flagged on the leaderboard.

## Results

SWE-rebench comprises 21,336 interactive Python SWE tasks from 3,468 GitHub repositories, with a 294-task benchmark subset from 169 repositories. On the decontaminated SWE-rebench (Mar–Apr 2025) benchmark, GPT-4.1 achieves the highest resolved rate at 26.7% (pass@5: 39.0%), followed by DeepSeek-V3-1226 at 21.9% and DeepSeek-V3-0324 at 21.3%. A key finding is that open-source models show substantially inflated scores on SWE-bench Verified compared to SWE-rebench: for example, DeepSeek-V3-0324 scores 39.7% on SWE-bench Verified but only 21.3% on SWE-rebench (Mar–Apr), a gap of ~18 percentage points that the authors attribute to data contamination.

## Baselines & Comparisons

The paper does not propose a new agent method to compare against baselines; instead, it evaluates existing LLMs on its new decontaminated benchmark versus the established SWE-bench Verified standard. The central comparison reveals that all open-source models score 10–20 percentage points lower on SWE-rebench (Mar–Apr 2025) than on SWE-bench Verified, with the largest gap for DeepSeek-V3-0324 (39.7% → 21.3%, a 18.4-point drop), suggesting significant contamination of the older benchmark. Among open-source models, DeepSeek-V3 variants consistently outperform all others on both benchmarks, with the March release (V3-0324) slightly ahead on SWE-bench Verified (39.7% vs 35.2%) but the December release (V3-1226) slightly ahead on SWE-rebench (21.9% vs 21.3%), a divergence the authors flag as further evidence of contamination. GPT-4.1 is the only model whose performance noticeably declines from the January to the March–April SWE-rebench subset (31.1% → 26.7%), while most other models show stable or slightly improved scores over time. LLaMA-4-Maverick-Instruct exhibits a notably high pass@5 (27.6%) relative to its mean resolved rate (12.2%), indicating high variance across runs rather than consistent capability.

## Relation to Prior Work

This paper extends the SWE-bench lineage (Jimenez et al., 2024) and the authors' own prior SWE-bench Extra work by replacing manual environment curation with a fully automated, LLM-driven pipeline for task collection, installation recipe generation, and quality assessment. The agentless installation approach is inspired by Agentless (Xia et al., 2024), while the quality-assessment stage fine-tunes on SWE-bench Verified human annotations. Unlike SWE-Gym and SWE-PolyBench, which still rely on manual curation and limited repository sets, SWE-rebench scales to 3,468 repositories and 21,336 tasks through distributed execution on TractoAI, and introduces a continuously updated, decontaminated benchmark as a direct response to SWE-bench's contamination concerns.

## Why It Matters / Open Questions

The 21K+ interactive Python SWE tasks fill a critical gap for RL-based training of software engineering agents, where prior datasets were either too small or too manually curated to scale. The decontaminated, continuously refreshed benchmark addresses a growing concern that SWE-bench Verified scores may be inflated by training-data leakage, with the observed ~18-point gap for DeepSeek-V3-0324 between the two benchmarks providing suggestive (if not conclusive) evidence. Key limitations include Python-only coverage, imperfect automated quality assessment that may include underspecified or unsolvable tasks, and the LLM-based installation pipeline's 31% per-repository success rate, which constrains the effective yield. Open questions include whether the automated quality labels are sufficient for stable RL training signals and how the pipeline generalizes to other languages.
