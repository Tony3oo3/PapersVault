## Problem

Existing approaches to fine-tuning LLMs for unit test generation rely on ground-truth code solutions in the training data, making the process costly, labor-intensive, and limited in scale and diversity. This paper asks whether a code generator and a unit test generator can co-evolve via reinforcement learning without any ground-truth code supervision, using only their interaction outcomes to provide mutual learning signals.
![Teaser figure](../imgs/NEURIPS20254809/cropped_page1_idx1.webp)

## Input / Output

The model takes a natural-language coding task description (in stdio format, using input()/print()) and produces two types of outputs: Python code solutions and task-derived unit tests consisting of a test input, expected output, and a step-by-step explanation. During training, ground-truth unit tests (not ground-truth code) are used solely to compute rewards for both the coder and the unit tester. At inference time, the model generates n candidate solutions and m unit tests, then selects the best solution via Best-of-N ranking based on execution results against the generated tests.

## Method

CURE is a self-play RL framework where a single policy model alternately optimizes its coding and unit-test-generation capabilities. For each task, it generates n code solutions and m unit tests, executes them against each other plus ground-truth tests to form a binary matrix B*, and derives rewards: the code reward counts ground-truth test passes (Eq. 3), while the unit test reward is a theoretically derived estimator of μ = p_u(1−p_01) − (1−p_u)p_00 (Eq. 4), which simultaneously incentivizes test accuracy and discriminative power against incorrect solutions. The policy is updated with a GRPO-style clipped objective plus KL regularization, applied separately to code rollouts and unit-test rollouts. A key theoretical contribution (Theorem 3.1) proves that the aggregated BoN reward converges to correctly ranking solutions as m→∞ iff μ>0, and provides an exponential tail bound, justifying μ as the optimization target. For long-CoT models, a response-length-guided reward transformation penalizes overly verbose unit test reasoning, reducing average response length to 64.8% while preserving accuracy.

## Results

CURE models achieve average improvements of 24.4% in unit test accuracy, 4.5% in one-shot code generation accuracy, and 5.1% in Best-of-N (BoN) accuracy over their respective base models across five benchmarks (LiveBench, MBPP, LiveCodeBench, CodeContests, CodeForces). The long-CoT variant CURE-4B outperforms Qwen3-4B on all metrics (e.g., 84.6% vs 36.8% UT on LiveBench, 82.0% vs 78.1% BoN) while reducing unit test response length to 64.8% of the original. When applied as a unit tester for GPT-4o-mini, CURE-4B yields a 7.0% BoN improvement over GPT-4o one-shot at lower API cost. CURE also extends to agentic coding pipelines (MPSC, AlphaCodium, S*) with a 6.2% average gain and agentic unit test generation with a 25.1% average gain over the base model.

## Baselines & Comparisons

Against Qwen2.5 base models (citation 47), CURE-14B surpasses both Qwen2.5-14B-Instruct and Qwen2.5-14B-Coder on all three metrics across all five benchmarks; for example, on LiveBench it improves UT from 27.8% (Ins) / 39.0% (Coder) to 55.4%, and BoN from 51.7% / 53.1% to 57.0%. Similarly, CURE-7B outperforms both 7B baselines, with the largest UT gain on MBPP (35.8% → 74.5% over Ins). For the long-CoT setting, CURE-4B beats Qwen3-4B on every benchmark, with the most dramatic UT improvement on LiveBench (36.8% → 84.6%) and CodeContests (43.6% → 72.2%). In test-time scaling and agentic coding evaluations (Figure 4a), CURE-14B achieves a 6.2% average BoN improvement over the base model when plugged into MPSC (citation 16), AlphaCodium (citation 35), and S* (citation 21) pipelines, demonstrating that the co-evolved model's gains transfer to iterative refinement and pairwise discrimination strategies beyond simple BoN selection.

## Relation to Prior Work

This paper builds on the Best-of-N test-time scaling framework for code generation [28], where multiple code candidates are scored against generated unit tests, and on GRPO-style reinforcement learning for LLM optimization. It departs from prior unit test generation training methods (O1-Coder [52], UTGEN [32]) that require ground-truth code solutions as supervision, instead proposing a co-evolutionary self-play loop where the coder and unit tester mutually improve via a theoretically derived reward (μ) estimated from their interaction outcomes. The response-length-guided reward transformation for long-CoT models is a novel practical addition not seen in prior RL-for-coding work.

## Why It Matters / Open Questions

Removing the dependency on ground-truth code for training unit test generators substantially improves the scalability and flexibility of coding RL pipelines, and the finding that a 4B CURE model can serve as an effective reward model for RL on a 14B base model (matching ground-truth-labeled supervision) opens a path to self-improving coding systems without human annotation. However, the framework still relies on ground-truth unit tests during training, and is currently limited to Python competition-style stdin/stdout tasks; extending to functional tests, multiple languages, and removing even the unit-test supervision remains open. The 25.1% gain in agentic unit test generation and the 64.8% inference-length reduction for long-CoT models suggest practical value for deployment pipelines.
