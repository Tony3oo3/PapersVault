## Problem

Existing safety alignment for code LLMs either rejects malicious prompts reactively or learns secure code implicitly via contrastive losses, without explicitly teaching models to reference and apply the hundreds of known code security rules (e.g., 943 CWEs, 131+ analyzer detectors). This leaves models unable to generalize cybersafety reasoning to unfamiliar scenarios while simultaneously avoiding over-refusal of benign coding requests.
![Teaser figure](../imgs/NEURIPS20251844/cropped_page1_idx0.webp)

## Input / Output

The model consumes coding prompts (including single-turn and multi-turn jailbreak variants), benign security questions, and malicious event assistance requests, and produces structured responses that first present a safety reasoning trajectory citing prompt-specific CWEs and security rules, then deliver either vulnerability-free code, a calibrated refusal, or a security knowledge answer. Training data spans 93k+ adversarial prompts (69k vulnerability-inducing, 24k malicious event) plus utility prompts, with outputs verified by CodeGuru static analysis, pytest execution, and LLM-as-judge rubrics.

## Method

PurpCode introduces a two-stage post-training recipe: (1) Rule Learning, where SFT is performed on oracle-verified reasoning trajectories that explicitly cite prompt-specific security rules (CWEs, analyzer detector rules) and contrastive code examples, teaching the model to checklist relevant vulnerabilities before generating code; (2) Reinforcement Learning via GRPO over diverse safety and utility tasks with multi-objective binary rewards (full reward only for secure code with code present, partial 0.8 reward for valid refusals). Two efficiency innovations support the RL stage: a single-step dynamic sampling algorithm that adjusts batch size based on prior-batch learnability (avoiding DAPO's repeated rollout overhead and sample waste), and a batched reward manager that packs thousands of code snippets into single CodeGuru analysis requests with load-balanced binning. The training data is powered by an internal red-teaming pipeline (RULE2CODE for low-resource CWE synthesis, VUL2PROMPT for vulnerability-inducing prompt generation, and three jailbreak families) achieving 90 distinct CWE coverage.

## Results

PurpCode-32B achieves state-of-the-art cybersafety across all major benchmarks. On secure code generation, it reaches 80.8% on CyberSecEval SCG (vs. 72.3% for Qwen3-235B, the second-best) and 94.8% on CodeLMSec (vs. 78.1% for Qwen3-32B), with a 35% margin over Sonnet 4 (77.6% vs. 57.3%) on university red-teaming prompts. On malicious event assistance, it saturates CyberSecEval MITRE at 99.2% and leads red-teaming at 98.2%. On overrefusal, it ranks first on XSCode (93.5%), XSTest (98.0%), and PHTest (98.6%), while remaining competitive on CyberSecEval FRR (92.7%, 4% behind Sonnet 4).

## Baselines & Comparisons

PurpCode-32B decisively outperforms all frontier baselines on secure code generation: it leads CyberSecEval SCG by 12% over Qwen3-235B (80.8 vs. 72.3), CodeLMSec by 21% over Qwen3-32B (94.8 vs. 78.1), and university red-teaming by 35% over Sonnet 4 (77.6 vs. 57.3). Against DeepSeek-R1, the margin is even wider on CodeLMSec (94.8 vs. 57.8) and red-teaming (77.6 vs. 44.2), reflecting R1's lack of documented safety alignment. On malicious event assistance, all frontier models saturate CyberSecEval MITRE (96.8–99.7%), but PurpCode leads red-teaming at 98.2%, surpassing Qwen3-235B (95.5%) and Sonnet 4 (91.8%). On overrefusal, PurpCode is the least overrefusing model on XSCode (93.5%), XSTest (98.0%), and PHTest (98.6%), though it trails Sonnet 4 by 3.4% on CyberSecEval FRR (92.7 vs. 96.1). In controlled 14B-scale experiments (Table 7), PurpCode also outperforms prior alignment methods SafeCoder and ProSec: it beats SafeCoder on all benchmarks (SafeCoder's safety relies heavily on overrefusal, e.g., 26.3% on CyberSecEval FRR) and surpasses ProSec by 89% on CodeLMSec (98.4 vs. 52.1) and 17% on CyberSecEval MITRE (96.2 vs. 82.5).

## Relation to Prior Work

PurpCode specializes OpenAI's deliberative alignment framework [24] to the code security domain, adapting the 'teach safety specifications, then practice via RL' paradigm to explicit CWE-based rule reasoning. It departs from prior secure code generation methods (SafeCoder [31], ProSec [76]) that learn safety implicitly through contrastive samples and specialized losses, instead teaching models to cite specific security rules in structured reasoning trajectories before generating code. The RL stage builds on DeepSeek-R1's [26] GRPO-based outcome-driven training and DAPO's [80] dynamic sampling, introducing a single-step variant that eliminates repeated rollout overhead while improving gradient quality.

## Why It Matters / Open Questions

This is the first fully open-source post-training recipe that simultaneously addresses secure code generation, malicious event refusal, and overrefusal mitigation through explicit safety reasoning, providing a reproducible blueprint for the community. The saturation of CyberSecEval MITRE and several other benchmarks by multiple frontier models signals that current evaluation infrastructure is insufficient, motivating harder multi-turn and broader-CWE evaluations. Key limitations include the absence of multi-turn RL training, Python-centric code security optimization, and reliance on a single static analyzer (CodeGuru) as the primary oracle, leaving open questions about generalization to dynamic analysis and ensemble-based verification.
