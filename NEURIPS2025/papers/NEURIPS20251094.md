## Problem

Existing premise selection tools for Lean4 (Lean Search, Moogle, Lean Explore, Lean State Search) rely primarily on semantic embeddings of theorem statements or proof states, failing to exploit the rich hierarchical structure inherent in Lean's typed expression trees. No prior method combines explicit structural encoding with efficient large-scale retrieval for Lean4's complex type system and 200K+ theorem libraries, leaving a gap between the structural richness of formal expressions and the practical demands of fast, accurate premise retrieval.

## Input / Output

The method takes a Lean4 proof goal expression (parsed into an Expr tree, CSE-normalized, and WL-encoded into a fixed-dimensional feature vector) and queries a pre-processed database of 217,555 Mathlib4 theorems, each stored with its CSE-simplified tree, WL encoding, node count, and cluster assignment. Output is a ranked list of top-m theorems scored by an adaptive weighted fusion of four similarity metrics (WL cosine, TEDS, Const Jaccard, Collapse-Match), with the two-stage pipeline first producing a coarse top-k candidate set via WL cosine similarity and then re-ranking via the full multi-metric score. The candidate budget k adapts to query tree size as k = min(k_max, β·|T_query|), and structural compatibility constraints (relative and absolute node-count bounds) pre-filter candidates before detailed comparison.

## Method

The framework applies Common Subexpression Elimination (CSE) to standardize Lean4 expression trees by replacing repeated subexpressions with unified variable references, then employs a two-stage training-free retrieval pipeline. Stage 1 uses the Weisfeiler-Lehman kernel (iterative neighborhood label aggregation with MD5 hashing) to encode trees into structural feature vectors, computing cosine similarity for rapid coarse screening over a cluster-restricted search space (10,000 Mini-Batch K-Means clusters over PCA-reduced WL vectors). Stage 2 computes Tree Edit Distance with Lean-specific tiered costs—operations on simple nodes (BVar, FVar, MVar, Sort, Const) are scaled by σ=0.2 to reflect their lower logical impact—yielding a normalized TEDS score. The final ranking fuses four metrics via a weighted sum (α·cos + β·TEDS + γ·Jaccard + δ·CM) under a 'structure first, semantics as complement' principle, where Jaccard captures constant-name overlap and Collapse-Match measures whether a premise tree structurally aligns with a segment of the goal tree after applying collapse rules. Additional structural simplification (removing trivial ForallE binders over simple types) reduces TEDS sensitivity to secondary structural noise before fine-grained comparison.

## Results

On Test Set A (100 structured problems), the proposed Tree-based Search achieves 82.0% Recall@1 and 83.3% MRR, nearly doubling the best baseline Lean State Search (45.0% Recall@1, 60.2% MRR). On the larger Test Set B (6,119 state–theorem pairs from Mathlib4), Tree-based Search reaches 25.8% Recall@1, 28.7% Recall@10, and 26.9% MRR, outperforming the strongest baseline Lean State Search (8.2% Recall@1, 22.0% Recall@10, 12.8% MRR) by more than 3× on Recall@1. The method also leads on Precision@1 (25.8%) and nDCG@10 (27.2%) on Test Set B, confirming consistent gains across all standard retrieval metrics.

## Baselines & Comparisons

The paper compares against four existing Lean premise retrieval tools. Lean State Search [15] is the strongest baseline: on Test Set A it achieves 45.0% Recall@1 and 60.2% MRR, while the proposed method reaches 82.0% and 83.3% respectively (≈1.8× improvement on Recall@1); on Test Set B the gap widens to 25.8% vs. 8.2% Recall@1 (≈3.1×) and 26.9% vs. 12.8% MRR (≈2.1×). Lean Search [19] and its augmented variant perform moderately on Test Set B (7.2% and 6.6% Recall@1) but are far surpassed by the tree-based method. Moogle [17] and Lean Explore [18] are the weakest baselines, with Recall@1 of 4.8% and 1.0% respectively on Test Set B, indicating that purely semantic-embedding or name-based retrieval struggles with the structural complexity of Lean4 expressions. The proposed method wins on every metric (Recall, Precision, F1, nDCG, MRR) across both test sets, with the largest relative gains on Recall@1 and MRR, confirming that explicit structural encoding via WL kernels and tree edit distance provides a substantial advantage over embedding-only approaches.

## Relation to Prior Work

This paper repurposes classical graph and tree comparison tools—the Weisfeiler-Lehman kernel and Tree Edit Distance—within a multi-stage retrieval pipeline specifically designed for Lean4's typed expression trees, departing from the dominant embedding-based approach used by existing Lean4 premise selection tools (Lean Search, Moogle, Lean Explore, Lean State Search). While earlier theorem-proving research explored tree/graph neural networks on datasets like HOLStep, this work is the first to apply a training-free, kernel-based structural pipeline at Mathlib4 scale (217K theorems) with CSE normalization and cluster-based search-space reduction. The multi-metric fusion (WL cosine, TEDS, Const Jaccard, Collapse-Match) under a structural compatibility constraint is a novel combination, though each individual metric is well-established.

## Why It Matters / Open Questions

Premise selection is a critical bottleneck in interactive theorem proving, and this paper provides the first large-scale, reproducible benchmark (Test Set B with 6,119 pairs) for evaluating structural retrieval on Lean4, alongside a practical training-free method that significantly outperforms embedding-based baselines. However, performance degrades sharply for complex expressions (>200 nodes) and in algebraic domains (near-zero recall), revealing that pure structural matching struggles with highly polymorphic or deeply nested theorems. Open questions include whether tighter integration with LLM-based proof generation can compensate for these structural blind spots, and whether the framework's claimed portability to Coq or Isabelle holds in practice given their different expression representations.
