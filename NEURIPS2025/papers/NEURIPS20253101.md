## Problem

Current LLM serving architectures are server-centric and fail to leverage the abundant consumer-grade GPUs at the network edge, despite devices like the RTX 4090 delivering comparable compute to data-center A100s at 14× lower cost. Traditional parallelization techniques (tensor, pipeline) that split computation across devices break down over wide-area networks, where high latency and limited bandwidth make frequent exchange of intermediate model states impractical. No prior framework provides a practical mechanism to coordinate edge and server GPUs for LLM inference under realistic WAN conditions.

## Input / Output

The system takes a text prompt and runs a target LLM (e.g., Qwen3-32B/14B) on a server GPU alongside a smaller draft LLM (e.g., Qwen3-1.7B/0.6B) on an edge GPU. The critical I/O constraint is that only token-level outputs—candidate token trees from the edge and verified tokens plus one bonus token from the server—are exchanged over the network, never intermediate activations or model states, making the approach viable at typical WAN round-trip times (~14 ms). The output distribution is provably identical to server-only generation, preserving lossless quality regardless of the draft model chosen.

## Method

SpecEdge disaggregates speculative decoding into two phases: the edge GPU generates candidate token trees via tree-based drafting, while the server GPU performs batch verification in a single forward pass. Two key techniques make this practical over WANs. First, Proactive Edge Drafting eliminates idle time by having the edge GPU continue drafting along the single highest-cumulative-log-probability path while awaiting server verification; upon complete draft alignment, these pre-generated tokens are immediately reused in the next cycle, effectively hiding network and verification latency. Second, Pipeline-aware Scheduling interleaves verification requests from multiple concurrent users on the server to eliminate computational bubbles, dynamically calibrating draft depth so that server verification time ≈ edge drafting time + network RTT. The server additionally handles heterogeneous batch sequence lengths via per-sequence attention masking and KV cache padding, maintaining high GPU utilization across the asynchronous edge-to-server communication pattern.

## Results

On SpecBench (batch size 1, 14.07 ms WAN RTT), SpecEdge achieves 2.22× higher server throughput (e.g., 66.54 vs. 31.78 tok/s for Qwen3-14B/1.7B on multi-turn) and 1.91× better cost efficiency (e.g., 50.60 vs. 28.25 1k toks/$) compared to server-only tree-based speculative decoding. Inter-token latency is reduced by an average of 11.24% (e.g., 36.47 ms vs. 42.36 ms at 15 ms RTT for Qwen3-32B), outperforming the server-only baseline even with zero network delay. Gains are consistent across model scales (14B, 32B) and draft model sizes (0.6B, 1.7B), with the largest throughput improvement (2.50×) observed for Qwen3-14B/0.6B on the Math task.

## Baselines & Comparisons

Against the server-only tree-based speculative decoding baseline (SpecExec-style, running entirely on an A100), SpecEdge wins on every reported metric: server throughput improves by 2.02×–2.50× (average 2.22×), cost efficiency by 1.73×–2.13× (average 1.91×), and inter-token latency drops by 11.24% on average despite incurring a 14.07 ms WAN round-trip. Against the layer-split baseline (Petals-style, with one-quarter of model layers on an RTX 4090 edge GPU), SpecEdge is dramatically faster on inter-token latency: at 15 ms RTT, SpecEdge achieves 36.47 ms vs. 99.63 ms (2.73× faster), and at 50 ms RTT the gap widens to 40.26 ms vs. 134.90 ms (3.35× faster), because SpecEdge's speculative decoding reduces per-token communication rounds from one per token to one per draft batch. SpecEdge also outperforms the server-only baseline with zero network delay, confirming that the throughput and latency gains come from the disaggregated architecture itself rather than from favorable network conditions.

## Relation to Prior Work

SpecEdge repurposes the speculative decoding paradigm (Leviathan et al., 2023) from a single-device latency optimization into a cross-device communication protocol: instead of transferring intermediate activations as in layer-wise split inference (Petals, Helix), only token outputs cross the WAN. The drafting phase directly adopts tree-based speculative decoding (Sequoia, SpecExec), while the server-side verification and pipeline-aware scheduling are novel contributions that have no direct analogue in prior distributed speculative decoding work (Timor et al., Liu et al., McDanel), which operates within a single server node. The key conceptual departure from prior split-computing literature is that the draft-verify structure inherently minimizes both communication volume and round-trip frequency, making WAN deployment feasible where layer-wise splitting is not.

## Why It Matters / Open Questions

SpecEdge demonstrates that the 14x cost gap between consumer and data-center GPUs can be exploited for LLM serving without sacrificing output quality, yielding 1.91x cost efficiency and 2.22x server throughput—metrics that directly translate to operational savings at scale. The proactive edge drafting mechanism (continuing to draft during server verification) and pipeline-aware scheduling together resolve the two natural failure modes of naive disaggregation (latency inflation and server idle time), making the approach practical rather than merely theoretical. Open questions include security and fault tolerance when untrusted user devices participate, scalability beyond 32B target models, and whether the paradigm extends to multimodal or agentic workloads with more complex verification requirements.
