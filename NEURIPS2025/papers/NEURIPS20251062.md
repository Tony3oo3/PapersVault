## Problem

Split Federated Learning (SFL) suffers from a severe straggler bottleneck because the Split Server must wait for all clients to transmit embeddings before computing any update, making total training time dominated by the slowest device. Existing mitigations—adaptive split-layer shifting and asynchronous updates—either fail on modern architectures with uniform activation dimensions or worsen client drift under data heterogeneity, and none explicitly reduce the number of client–server communication rounds, which is the root cause of the latency.

## Input / Output

Clients receive raw data samples (32×32 or 224×224 RGB images for CIFAR/Fashion-MNIST/CINIC-10, or text sequences for SST-2) and compute only the forward pass up to a designated cut layer, transmitting the resulting embedding vector to the Split Server. The server holds the labels, computes zeroth-order loss differences, and returns a single scalar per client per round—no gradient tensor is ever sent back. The final output is a global model (split into client-side and server-side parameter blocks) that maps inputs to class labels; on the client side, peak memory is reduced to ~1 GB for OPT-1.3B fine-tuning versus 8 GB for standard FedAvg.

## Method

MU-SplitFed decouples server progress from client speed by letting the Split Server perform τ local zeroth-order (SPSA) updates on its sub-model using the unperturbed embedding while waiting for the perturbed embeddings to arrive, rather than idling. The client perturbs its parameters once per round, sends three embeddings (unperturbed, +λu, −λu) on-the-fly, and receives back only a scalar ZO loss difference to update its own sub-model—no backpropagation is required on either side. Theoretically, the convergence rate is O(√(d/(τTM))) for non-convex objectives, yielding linear speedup in τ and, when τ = t_straggler/t_server, total training time independent of the slowest client. A key design coupling emerges: optimal convergence requires the client-side parameter dimension to scale as d_c = √(d/τ), meaning a larger τ should be paired with a shallower client-side model (earlier cut layer), a relationship validated empirically on OPT-1.3B.

## Results

On four image classification benchmarks, MU-SplitFed (τ=2) achieves the highest test accuracy across all datasets: 77.86% on CIFAR-10, 85.45% on Fashion-MNIST, 59.50% on CINIC-10, and 32.16% on CIFAR-100. These results are reported at the same number of global communication rounds (100 epochs for Fashion-MNIST, 500 for the rest), demonstrating that the unbalanced update mechanism improves accuracy without additional communication. For LLM fine-tuning (OPT-1.3B on SST-2), MU-SplitFed reduces peak client-side memory to 1.05 GB, compared to 8.02 GB for FedAvg and 5.64 GB for FedLoRA.

## Baselines & Comparisons

MU-SplitFed (τ=2) outperforms Vanilla SplitFed (τ=1) on all four image datasets by 8.13% (CIFAR-10), 7.95% (Fashion-MNIST), 7.54% (CINIC-10), and 15.58% (CIFAR-100), confirming that unbalanced server updates improve accuracy at the same communication budget. Against GAS, the asynchronous SFL baseline, MU-SplitFed wins on all four datasets (e.g., 77.86% vs. 75.28% on CIFAR-10, 32.16% vs. 25.33% on CIFAR-100), with the gap widening on harder tasks where GAS's activation generation step scales poorly with label size. In the LLM fine-tuning memory comparison (Figure 4), MU-SplitFed reduces peak client-side memory to 1.05 GB versus 8.02 GB for FedAvg and 5.64 GB for FedLoRA on OPT-1.3B/SST-2, a 7.7× and 5.4× reduction respectively, by storing only a partial model and eliminating gradient storage via ZO optimization. Under simulated straggler conditions (Figure 2), MU-SplitFed consistently reaches higher accuracy in less wall-clock time than both baselines across all datasets, with the advantage most pronounced on CIFAR-100 where GAS exhibits slower and less stable convergence.

## Relation to Prior Work

This paper extends the Split Federated Learning (SFL) framework [Thapa et al., AAAI 2022] by introducing an unbalanced server-client update mechanism combined with zeroth-order (SPSA) optimization [Ghadimi & Lan, 2013]. It departs from prior straggler-mitigation strategies in FL (asynchronous updates, adaptive splitting, activation buffering) by identifying that the dominant bottleneck in SFL is not merely the waiting time but the total number of client-server communication rounds. Rather than tolerating stragglers through asynchrony or adjusting the split point, MU-SplitFed reduces communication frequency by having the server perform τ local updates per client round, a structural change that prior SFL methods (GAS, RingSFL) do not exploit.

## Why It Matters / Open Questions

The result that total training time becomes independent of straggler speed when τ = t_straggler/t_server provides a clean, actionable design principle for SFL system architects. The theoretical connection between optimal cut-layer depth and τ (d_c = √(d/τ)) offers practical guidance for model partitioning that prior SFL theory did not capture. However, the experimental validation is limited to AlexNet (8 layers) for image tasks and a single LLM (OPT-1.3B), the optimal τ is architecture-dependent, and no error bars are reported. The authors themselves note that fully realizing SFL's potential for scalable LLM fine-tuning remains an open challenge.
