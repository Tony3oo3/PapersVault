## Problem

LLM decoding is dominated by fragmented kernel execution across QKV Projection, Attention, and Output Projection, where inter-block dependencies are resolved by materializing intermediate results to off-chip global memory, incurring heavy memory traffic and kernel launch overhead. Although NVIDIA Hopper introduces thread block clusters and distributed shared memory (DSMEM) for on-chip inter-block communication, it exposes only low-level PTX data-movement instructions without structured collective abstractions, making it impractical to integrate into real-world LLM inference systems.
![Teaser figure](../imgs/NEURIPS20251295/cropped_page5_idx8.webp)

## Input / Output

The fused kernel consumes input hidden states (1×D in FP16), QKV/Output Projection weight matrices, and the KV cache (s×H) resident in global memory, with batch size 1 and context lengths from 1K to 16K. Each thread block within a cluster processes the full input hidden states and produces a partial output tile O_b after the Output Projection, which is written to global memory via atomicAdd. The system is evaluated on Llama2-7B (standard MHA) and DeepSeek-V2-Lite (MLA with weight absorption), both in FP16 on a single H100 SXM5 80GB GPU.

## Method

ClusterFusion introduces two cluster-level collective primitives—ClusterReduce (element-wise reduction with constant message size) and ClusterGather (progressive data replication with doubling message size)—both implemented as binary-tree patterns over log₂(N) rounds on DSMEM, abstracting common aggregation patterns into reusable, structured operations. The key design insight is to treat each thread block cluster as a cooperative parallel unit: each Attention head is mapped to a cluster of N=2^k blocks (k≤4), where blocks partition the head dimension in QKV Projection, the KV cache token dimension in Attention, and the output dimension in Output Projection. This cluster-centric dataflow keeps all intermediate results (Q, K, V, partial Attention outputs, softmax statistics) entirely on-chip in shared memory, enabling seamless fusion of three modules into a single kernel without any off-chip round-trips. The approach reduces global memory transfer by an order of magnitude and cuts kernel launch overhead by nearly 10× compared to CUDA-Graph-optimized baselines, achieving 1.61× average end-to-end speedup over SOTA frameworks.

## Results

On Llama2-7B (batch size 1, cluster size 4), ClusterFusion achieves average end-to-end TPOT speedups of 1.41×, 1.39×, 1.43×, and 2.03× over SGLang, vLLM, TensorRT-LLM, and MLC-LLM respectively, with core-module (QKV Projection + Attention + Output Projection) speedups of 1.85×, 1.73×, 1.61×, and 3.19×. On DeepSeek-V2-Lite, the corresponding end-to-end speedups are 1.34×, 1.37×, 1.51×, and 2.39×, and core-module speedups are 1.66×, 1.64×, 1.35×, and 3.5×. The overall headline figure is a 1.61× average speedup on core modules across all baselines and models. Disabling DSMEM increases TPOT by up to 33%, confirming the critical role of on-chip collective communication.

## Baselines & Comparisons

ClusterFusion outperforms all four baselines across both models and both evaluation metrics (end-to-end TPOT and core-module latency). Against SGLang, the closest competitor, ClusterFusion achieves 1.41× (Llama2-7B) and 1.34× (DeepSeek-V2-Lite) end-to-end speedups, with larger margins on core modules (1.85× and 1.66×). vLLM is slightly harder to beat on end-to-end latency (1.39× and 1.37×) but still trails on core modules (1.73× and 1.64×). TensorRT-LLM shows the smallest gap on DeepSeek-V2-Lite core modules (1.35×), likely because MLA's weight-absorption design already reduces fusion opportunities, yet ClusterFusion still leads. MLC-LLM is the weakest baseline, with ClusterFusion achieving the largest margins: 2.03×–2.39× end-to-end and 3.19×–3.50× on core modules. The speedup advantage is attributed to two factors: ClusterFusion eliminates intermediate global-memory round-trips by keeping QKV, Attention, and Output Projection data entirely on-chip via DSMEM, and it reduces kernel launch overhead by nearly an order of magnitude compared to CUDA-Graph-optimized baselines.

## Relation to Prior Work

This paper extends the FlashDecoding line of work (which parallelizes attention over the KV cache sequence dimension) by introducing a cluster-centric dataflow that fuses QKV Projection, Attention, and Output Projection into a single kernel. It departs from the block-isolated execution pattern adopted by FlashAttention, FlashDecoding++, FlashMLA, and all major inference frameworks (SGLang, vLLM, TensorRT-LLM, MLC-LLM), where inter-block dependencies are resolved exclusively through global memory. The key conceptual departure is drawing on distributed-systems collective communication abstractions (allreduce, allgather) and adapting them to NVIDIA Hopper's thread block clusters and DSMEM, filling a gap where the hardware exposes only low-level PTX data-movement instructions without structured communication primitives.

## Why It Matters / Open Questions

The 1.61× average end-to-end speedup over SOTA frameworks is practically significant for production LLM serving, and the cluster-level collective primitives (ClusterReduce, ClusterGather) provide a reusable abstraction that other Hopper-targeted kernels could adopt. However, the fusion scope is bounded by the maximum cluster size of 16 thread blocks, which constrains applicability to future models with larger hidden dimensions or more heads. The multi-batch results (1.11× vs. 1.41× for batch 1) reveal that the benefit diminishes as computation intensity grows, and the optimal cluster size is workload-dependent, requiring per-model tuning. Open questions include whether broader intra-chip collective support (beyond the 16-block cluster) could unlock more uniform fusion, and whether the approach generalizes to non-Hopper architectures.
