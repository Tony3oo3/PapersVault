## Problem

Existing issue-resolving benchmarks such as SWE-bench focus almost exclusively on Python, leaving it unclear whether the strong performance of LLM-based agents on Python issues generalizes to other widely used programming languages. This paper asks whether current LLMs can resolve real-world GitHub issues across Java, TypeScript, JavaScript, Go, Rust, C, and C++, and what factors limit their cross-language effectiveness.
![Teaser figure](../imgs/NEURIPS20252111/cropped_page3_idx0.webp)

## Input / Output

Each instance provides a natural-language issue description (ranging from ~150 to ~1,100 tokens) paired with a full buggy code repository at a specific base commit, along with a hidden test patch used for evaluation. The model must produce a unified diff fix patch that, when applied to the base commit alongside the test patch, causes previously failing tests to pass without introducing regressions. Evaluation runs the full test suite in a Dockerized environment under three configurations (base, test-only, test+fix) to verify correct status transitions (e.g., FAILED→PASSED) and absence of regressions (no PASSED→FAILED).

## Method

Multi-SWE-bench is constructed through a five-phase pipeline: (1) selecting high-quality GitHub repositories (>500 stars, active CI/CD, buildable), (2) crawling merged PRs linked to issues that modify test files, (3) building per-PR Docker environments by extracting dependencies from CI/CD configs and documentation, (4) filtering PRs via full test-suite execution under three patch configurations to retain only those with clear bug-fixing effects and no regressions, and (5) dual-annotation by 68 expert annotators with cross-review and an 80% accuracy threshold, yielding 1,632 verified non-Python instances plus 500 from SWE-bench Verified (2,132 total). Issues are stratified into easy/medium/hard based on human-estimated resolution time (≤15 min, 15 min–1 h, ≥1 h). For evaluation, three representative methods—Agentless (fixed multi-stage workflow), SWE-agent (agent-computer interface with multi-turn interaction), and OpenHands+CodeAct (generalist agent platform)—are adapted to all 8 languages (forming MagentLess, MSWE-agent, MopenHands) and run with 12 state-of-the-art LLMs, revealing that resolved rates drop sharply for hard issues, cross-file patches, and non-Python languages.

## Results

On Multi-SWE-bench (2,132 instances across 8 languages), the best overall resolved rate is 21.62% (Gemini-2.5-Pro + MopenHands), while Python-only performance reaches 49.00% (Gemini-2.5-Pro + MagentLess) and 52.20% (Claude-3.7-Sonnet + MopenHands). Performance drops sharply with difficulty: resolved rates fall from ~34.5% (easy) to ~3.5% (hard) for the best model-method pair. Cross-language generalization is limited, with non-Python languages typically scoring 5–20% resolved rate versus 25–52% for Python.

## Baselines & Comparisons

The paper evaluates three adapted methods—MagentLess (procedural), MSWE-agent (agent-based), and MopenHands (agent-based)—across 12 LLMs. MopenHands achieves the highest overall resolved rate (21.62% with Gemini-2.5-Pro), outperforming MagentLess (18.01%) and MSWE-agent (14.63%) for the same model. However, MagentLess leads on Python (49.00% with Gemini-2.5-Pro) and single-file issues, while MSWE-agent excels with Claude-3.7-Sonnet (17.17% overall, 11.63% on C++). Gemini-2.5-Pro is the strongest model across MagentLess and MopenHands at all difficulty levels, while Claude-3.7-Sonnet dominates MSWE-agent. All three methods show a consistent hierarchy: bug fixes > new features > feature optimizations, and resolved rates approach zero for hard-level issues (≥1 hour human time) regardless of method or model.

## Relation to Prior Work

This paper extends the SWE-bench paradigm of repository-level issue resolving from Python to eight programming languages, adapting three existing agent frameworks (Agentless, SWE-agent, OpenHands) for multilingual evaluation. While prior multilingual code benchmarks (HumanEval-X, MBXP) addressed program-level generation, and concurrent works (SWE-PolyBench, SWE-bench Multilingual) also target multilingual issue resolving, Multi-SWE-bench distinguishes itself through human-verified quality control by 68 annotators and a time-based difficulty stratification. The construction pipeline—repository selection, PR crawling, Dockerized environment building, test-based filtering, and dual-annotation verification—systematizes what was previously a Python-specific process.

## Why It Matters / Open Questions

The benchmark reveals that current LLMs exhibit severe cross-language generalization gaps: even top models drop from ~48% resolved rate on Python to single digits on most other languages, and resolved rates approach zero for issues humans estimate at ≥1 hour. This challenges the assumption that progress on SWE-bench Verified (now ~65%) reflects general software engineering capability. Open questions include whether cross-file reasoning and long-patch generation can be improved through better context management, and whether the difficulty stratification will become a standard for calibrating agent capabilities. The fully open-sourced Docker images and annotation data lower the barrier for community extension to additional languages and modalities.
