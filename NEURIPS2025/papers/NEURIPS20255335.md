## Problem

RL-based Verilog code generation is hindered by the lack of meaningful functional rewards: existing methods rely on code structure similarity (which fails to capture functional equivalence across different implementations), and insufficient SFT data quality means models rarely produce fully correct modules, starving RL of actionable reward signals. This paper exploits Verilog's inherent signal independence to extract verified correct signal-level implementations from partially incorrect modules, thereby densifying the functional reward signal available for preference optimization.
![Teaser figure](../imgs/NEURIPS20255335/cropped_page1_idx0.webp)

## Input / Output

The model takes a natural-language module specification (describing ports and functional requirements) as input and generates complete Verilog RTL code as output. During training, the SFT model samples k=5 candidate implementations per prompt, which are then verified by applying N sets of random input stimuli (generated via Yosys) to both the generated and reference modules and comparing output signal waveforms. Only signals matching across all N stimulus sets are deemed functionally correct, and the resulting preference pairs carry explicit contrast-signal annotations used to mask irrelevant tokens during DPO loss computation.

## Method

QiMeng-SALV introduces a three-stage pipeline that shifts RL optimization from module-level to signal-level granularity. First, signal-aware verification uses Yosys to simulate generated and reference modules with random inputs, identifying which output signals in each candidate are functionally correct and constructing preference pairs where a contrast signal is correct in the preferred sample but incorrect in the dispreferred one. Second, signal-aware code extraction parses the AST to build a signal dependency topology graph, then performs backward traversal from the target output signal to isolate the complete code segment implementing that signal (and its transitive dependencies) from the full module. Third, signal-aware DPO modifies the standard DPO loss to compute token-level log-probability ratios only over the contrast-signal code segments in both preferred and dispreferred samples, ignoring all other tokens. This filtering prevents incorrect signal implementations from introducing noise into the gradient, and the approach expands the effective training set by incorporating all modules containing at least one valid signal, not just fully correct ones.

## Results

On RTLLM v1.1, QiMeng-SALV (7B) achieves 62.6% pass@1, 75.1% pass@5, and 81.1% pass@10, matching or exceeding the 671B DeepSeek-V3 (62.0% pass@1, 72.4% pass@10). On RTLLM v2.0, it reaches 62.0% pass@1 and 76.0% pass@10. On VerilogEval1.0, it attains 81.4% pass@1 (Machine) and 60.4% pass@1 (Human), surpassing all open-source baselines and even DeepSeek-V3 on the Machine subset (81.4% vs. 77.6%). On VerilogEval2.0, it scores 57.1% (T=0) on Specification and 62.2% (T=0) on Completion.

## Baselines & Comparisons

QiMeng-SALV (7B) outperforms all open-source Verilog-specific baselines on every metric. On RTLLM v1.1 pass@1, it leads VeriPrefer (53.2%) by 9.4 points, Origen (50.6%) by 12.0 points, and CodeV-Qwen2.5 (39.3%) by 23.3 points (~59.7% relative improvement). Against the 671B DeepSeek-V3, QiMeng-SALV achieves a comparable 62.6% vs. 62.0% pass@1 but substantially exceeds it on pass@10 (81.1% vs. 72.4%). On VerilogEval1.0 Machine, it surpasses DeepSeek-V3 (81.4% vs. 77.6% pass@1) and GPT-4o (81.4% vs. 67.7%). On VerilogEval2.0 Specification (T=0), it improves over CodeV-Qwen2.5 by 27.4 points (57.1% vs. 44.8%) and over VeriPrefer by a wide margin. The comparison with VeriPrefer is particularly informative: both use RL with functional rewards, but QiMeng-SALV's signal-level granularity yields consistent 8–10 point gains over VeriPrefer's module-level approach across all benchmarks.

## Relation to Prior Work

This paper extends Direct Preference Optimization (DPO) from Rafailov et al. by restricting the loss computation to signal-level code segments rather than full module tokens, motivated by Verilog's inherent signal independence. It departs from prior Verilog-specific RL approaches (VeriPrefer, VeriSeek) that rely on module-level functional rewards or structural similarity, and from SFT-only pipelines (CodeV, Origen) that lack any RL stage. The conceptual lineage is: general preference optimization → DPO → signal-aware DPO, where the key modification is using AST-based dependency graphs to isolate per-signal code segments and verify them independently against reference modules via Yosys simulation.

## Why It Matters / Open Questions

The paper addresses a concrete bottleneck in HDL code generation: the scarcity of fully correct modules in SFT-trained models makes module-level functional rewards too sparse for effective RL. By exploiting Verilog's signal independence, it densifies the reward signal and expands the usable training set, yielding a 7B model that matches a 671B model on RTLLM v1.1. However, the approach is tightly coupled to Verilog's structural semantics (parallel, independent signals) and depends on reference modules being functionally correct, limiting generalizability to other HDLs or to settings without reliable references. Open questions include whether the signal-level decomposition transfers to VHDL or SystemVerilog, and whether the method degrades when signals are heavily interdependent (e.g., in sequential logic with shared state).
