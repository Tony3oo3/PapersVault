## Problem

Natural language to visualization (NL2VIS) systems require large, domain-specific training data to fine-tune LLMs, but existing datasets like NVBench are domain-agnostic, too small for modern LLM fine-tuning (~25K vs. the scale needed), and lack multi-step reasoning examples. For biomedical research data portals specifically, no dataset exists that grounds questions in real entity-relationship schemas and supports the iterative exploration workflows researchers actually perform.

## Input / Output

The framework consumes abstract question templates with entity/field placeholders, Frictionless Data Package schemas defining entity-relationship models (with field types, cardinalities, and inter-entity relationships), and a JSON Schema–defined visualization grammar. It produces 1.08M triplets where each record contains a data reference (entity-relationship definition), a natural language query, and a visualization JSON specification, plus 11.4K two-step question chains. Each base query is expanded into 25 paraphrased variants by exhaustively varying expertise and formality scores (1–5 each) via GPT-4o, and the dataset includes metadata columns recording the template, constraints, and paraphrase parameters used.

## Method

The pipeline proceeds in four stages. First, 64 abstract query-visualization template pairs are authored, spanning ten low-level analysis task types (Computed Derived Value, Determine Range, Correlate, etc.) with entity and field placeholders. Second, reification is formulated as a constraint satisfaction problem: each template carries 1–11 boolean constraints on field types, entity relationships, and cardinalities, and a solver enumerates all valid entity-field substitutions from the input schemas. Third, GPT-4o paraphrases each reified query across all 25 expertise×formality combinations, with the dataset schema included in the prompt to enable field-name-to-synonym mapping (e.g., 'age_value' → 'How old are the donors?'). Fourth, five domain experts review samples through a purpose-built interface, flagging issues like null-value handling, paraphrase meaning drift, and encoding conventions. For multi-step chains, 17 link templates encode follow-up patterns (e.g., adding a grouping dimension) grounded in Shneiderman's query-refinement cycle, with matching constraints on shared entities and solution metadata ensuring coherence between linked queries.

## Results

DQVis contains 1,075,190 data-question-visualization triplets across five biomedical research data repositories (HuBMAP, MW, 4DN, MoTrPAC, SenNet) and 11,447 two-step question samples for multi-step reasoning. In human evaluation by five visualization experts, 271/357 (75.9%) reviewed triplets were labeled 'good,' 59 (16.5%) 'improve,' and 27 (7.6%) 'bad.' The dataset is over 40× larger than NVBench (25,750 datapoints) and is the first NL2VIS dataset to include domain-specific biomedical content and multi-step query chains.

## Baselines & Comparisons

As a dataset paper, DQVis does not benchmark a trained model against baselines. The primary comparison is to NVBench [30], the closest existing NL2VIS dataset: DQVis is 40× larger (1.08M vs. 25.7K datapoints), is domain-specific to biomedical research repositories rather than general-purpose, and uniquely includes multi-step question chains (11.4K two-step samples) that NVBench lacks. The paper also distinguishes itself from Dial-NVBench [46], which adds dialog-style constructions but does not address scale or domain specificity, and from VizNet [20], which collects real-world visualization examples but does not consider natural language input. Human evaluation by five experts (75.9% 'good' rating) provides a quality signal, though the authors note that reviewer disagreement (only 2 of 20 overlapping questions received unanimous scores) reflects the inherent subjectivity of visualization quality assessment.

## Relation to Prior Work

This paper extends the NL2VIS dataset construction paradigm established by NVBench [30] and the LLM-powered paraphrasing framework of Ko et al. [25] (CHI 2024), adapting their expertise/formality scoring to a biomedical domain. Where NVBench repurposed Spider's NL2SQL benchmarks for general-purpose Vega-Lite specifications, DQVis introduces a template-based generation pipeline with constraint satisfaction solvers that reifies abstract analytic questions (following Amar et al.'s taxonomy) against Frictionless Data Package schemas from five biomedical repositories. The multi-step question generation draws on information-seeking models from search UI literature [17, 40], linking single-step triplets into coherent two-step dialogues—a capability absent from prior NL2VIS datasets.

## Why It Matters / Open Questions

DQVis provides the first large-scale (1.08M triplets, 40× NVBench) domain-specific NL2VIS dataset for biomedical research data portals, enabling fine-tuning of LLMs for a domain where terminology is evolving and specialized. The reusable generation-and-review framework lowers the barrier for other domains to construct comparable datasets. Key limitations include the template-based approach losing variable-specific visualization conventions (e.g., population pyramids, axis placement), LLM paraphrasing introducing semantic errors (chart type changes, variable name substitutions), and dataset imbalance across repositories and question types. Open questions include how to best handle imprecise or ambiguous natural language prompts, how to incorporate domain-specific visualization design conventions into generation, and whether the multi-step chains generalize beyond two-step interactions.
