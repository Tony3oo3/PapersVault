## Problem

In LLM-based agent programming, inference-time scaling strategies (tree search, beam search, refinement) are typically baked directly into the agent workflow code, entangling the core logic with the search strategy. This entanglement makes it inflexible to experiment with different strategies, obscures the underlying workflow, and limits which strategies are practical to implement. No existing framework cleanly separates the specification of the agent workflow from the choice of inference-time search algorithm.

## Input / Output

The programmer writes a standard Python agent function and decorates it with @encompass.compile, inserting branchpoint() calls at unreliable operations (e.g., LLM calls) and record_score() calls to provide verification signals. At invocation time, the programmer specifies a search algorithm string (e.g., 'beam', 'dfs', 'parallel_bfs') and its hyperparameters (beam width, branching factor, number of rollouts). The output is the agent's return value on the highest-scoring execution path discovered by the search, with the search tree's children being stochastically sampled rather than enumerated since LLM outputs form an uncountable space.

## Method

ENCOMPASS introduces Probabilistic Angelic Nondeterminism (PAN), a programming model where the programmer writes the agent as if unreliable operations always succeed, and the runtime searches over the tree of possible execution paths to find one where they did. A Python decorator compiles the decorated function into a search space object at runtime, where branchpoints define the nodes and the code between them defines probabilistic transition functions that stochastically sample next states. The framework unifies common inference-time strategies as special cases: best-of-N is depth-1 search, local best-of-N is beam search with width 1, global best-of-N is beam search with branching 1, and refinement is search with shared mutable memory (NoCopy variables) across branches. This separation means switching from, say, global best-of-N to fine-grained beam search requires only changing a few search parameters rather than restructuring the agent code, and the same search implementation is reusable across different agents.

## Results

On the main case study (Java-to-Python code repository translation, MIT OCW ps0–ps4), beam search at both file and method level ('beam (coarse) + beam (fine)') outperforms all simpler strategies (global best-of-N, local best-of-N) with statistical significance (p < 0.03), and performance scales linearly with log(cost). On LeetCodeHard (Case Study 3), ENCOMPASS BeFS achieves 38.1% pass rate at $0.512/task versus vanilla Reflexion's 38.2% at $0.736/task — matching accuracy at ~30% lower cost. On ARC-AGI (Case Study 2), ENCOMPASS BFS with GPT-4o reaches 38.3% accuracy, surpassing the ADAS meta-agent search baseline (32.7% reproduced).

## Baselines & Comparisons

Against vanilla Reflexion on LeetCodeHard, ENCOMPASS BeFS matches or exceeds accuracy at substantially lower cost: at the high-cost setting, BeFS achieves 38.1% at $0.512/task versus Reflexion's 38.2% at $0.736/task (~30% cost reduction), and at the low-cost setting BeFS reaches 36.1% at $0.168 versus Reflexion's 35.5% at $0.279 (better accuracy at 40% lower cost). Best-of-N is comparable to BeFS but less cost-efficient at the high setting (37.6% at $0.508 vs. 38.1% at $0.512). On ARC-AGI, ENCOMPASS BFS with GPT-4o (38.3%) outperforms the ADAS meta-agent search baseline (32.7% reproduced, 30.0% reported with a different checkpoint), demonstrating that simple inference-time search over a two-step agent can beat costly automated agent design. On the code repository translation task, beam search at both granularities consistently outperforms global and local best-of-N across all five repositories, with the advantage being most pronounced on the larger ps1–ps4 repositories.

## Relation to Prior Work

ENCOMPASS draws on Floyd's angelic nondeterminism and the probabilistic programming paradigm (separating model specification from inference algorithm) to propose a programming model—probabilistic angelic nondeterminism (PAN)—for LLM agents. It positions itself as complementary to existing agent frameworks (LangChain, DSPy, AutoGen, LangGraph) that handle low-level LLM interaction and workflow orchestration but leave inference-time strategy implementation to the programmer. The paper unifies previously disparate inference-time strategies (best-of-N, beam search, refinement, self-consistency, tree search) as special cases of search over nondeterministic execution paths, departing from prior agent work that bakes search logic directly into the workflow code.

## Why It Matters / Open Questions

By reducing the cost of implementing and switching inference-time strategies from hundreds of lines of state-machine code to a few branchpoint() calls and parameter changes, ENCOMPASS makes sophisticated search (e.g., multi-granularity beam search) accessible to agent developers who would otherwise default to simpler sampling. The empirical finding that fine-grained beam search outperforms global/local best-of-N on code translation suggests better scaling laws exist but were previously inaccessible due to implementation complexity. Key limitations include the need for manual branchpoint placement, restriction to program-in-control agents, and non-release of code; open questions include whether LLMs could automatically identify branchpoint locations and whether the paradigm extends to LLM-in-control or hybrid agents.
