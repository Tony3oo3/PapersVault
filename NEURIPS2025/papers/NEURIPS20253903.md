## Problem

Deploying large LLMs for Data Analysis Code Generation (DACG) raises privacy and computational cost concerns, while small language models (SLMs) lack the reasoning depth for complex tabular tasks. Existing distillation approaches rely on resource-intensive fine-tuning on synthetic data, which struggles to generalize across languages, schemas, and task variants. This paper investigates whether training-free In-Context Learning can effectively transfer an LLM's analytical expertise to SLMs for DACG, eliminating the need for any parameter updates.

## Input / Output

The system takes a natural language query paired with tabular data or a relational database schema as input. For Python tasks (WIKITQ, TABMWP), only column names and the first 3–10 rows of values are provided to simulate realistic partial-data access; for SQL tasks (BIRD-SQL), ground-truth retrieved tables with full column descriptions and three sample rows are supplied, isolating the code-generation challenge from schema-linking. The output is an executable code snippet (Python or SQL) that answers the query, produced via an intermediate meta-instruction and functional plan that structure the SLM's reasoning.

## Method

DARGO (Distillation and Adaptive Reasoning-Guided Orchestration) operates in three training-free phases. First, a Model Orchestration Interface (MOI) has the LLM teacher convert ground-truth code into step-wise functional plans with placeholders, which the SLM student fills in; the teacher then iteratively refines the plan using six discrete actions (Decomposition, ALT, ADD, DELETE, SIMPLIFY, SWITCH) based on execution feedback, aligning plan granularity to the SLM's capabilities. Second, successful trajectories are translated into structured case studies that distill the reasoning rationale behind each solution, forming a memory database. Third, at inference time, a RAG module retrieves the top-k most relevant case studies (using CodeT5+ embeddings over question text), and the SLM performs a secondary distillation to generate a query-specific meta-instruction, which it then uses to produce a functional plan and final code. The key distinction from prior work is that all knowledge transfer occurs through in-context prompting at inference time—no weights are updated—making the approach model-agnostic and immediately transferable to new SLMs without re-running exploration.

## Results

On the primary student model Phi-3-Mini-3.8B, DARGO achieves 59.10% accuracy on TABMWP and 33.80% execution accuracy on BIRD-SQL, representing relative gains of 17.5% and 38.5% over the zero-shot baseline (41.80% and 24.40%, respectively). The paper reports a 27.5% average relative improvement across the three main benchmarks. DARGO also enables Phi-3-Mini to outperform larger models (2–3× parameters), surpassing CodeLlama-13B by 7.0% and StarCoder2-15B by 3.2% on BIRD-SQL, and rivaling Phi-3-Medium (4× parameters) across all benchmarks.

## Baselines & Comparisons

DARGO outperforms all six baselines on both TABMWP and BIRD-SQL for Phi-3-Mini. Against Chain-of-Thought (41.40/23.80), DARGO gains +17.7 and +10.0 points respectively. Against Dynamic Few-Shot (52.10/24.40), the closest competitor, DARGO still leads by +7.0 on TABMWP and +9.4 on BIRD-SQL. Against the two dedicated distillation frameworks, DARGO beats DSPy (40.40/22.80) by +18.7/+11.0 and ReGAL (41.80/20.40) by +17.3/+13.4, with the authors attributing DSPy's weakness to its exact-match metric being ill-suited for execution-based code generation and ReGAL's to producing narrowly schema-bound helper functions. Against LoRA fine-tuning on the same 1,000 BIRD-SQL samples, DARGO achieves 33.80% vs. 23.60% (a +10.2 point gap), and even outperforms LoRA trained on 50% of the full training set, demonstrating 5× greater data efficiency.

## Relation to Prior Work

This paper carves new ground at the intersection of knowledge distillation and in-context learning for Data Analysis Code Generation (DACG). Prior distillation work (Orca, DSPy, ReGAL, LoRA fine-tuning on synthetic data) all require parameter updates or training on generated data, while demonstration-based ICL (static/dynamic few-shot) provides examples without extracting transferable reasoning patterns. DARGO departs from both by using an iterative Model Orchestration Interface where a teacher LLM refines functional plans for a student SLM, storing successful trajectories as case studies that are later retrieved via RAG to generate query-specific meta-instructions—achieving distillation purely through ICL with zero parameter updates. The functional-plan abstraction (as opposed to Chain-of-Thought) and the six-action plan optimization loop are novel orchestration mechanisms not present in prior agent or distillation frameworks.

## Why It Matters / Open Questions

The practical impact is significant for privacy-sensitive and resource-constrained deployments: a 3.8B SLM can inherit much of a frontier LLM's analytical reasoning without any fine-tuning, and the distilled knowledge transfers model-agnostically to SLMs that never participated in exploration. Key limitations remain: the exploration phase still requires in-domain training examples (precluding fully zero-shot use), and 54% of residual errors stem from over-reasoning on simple queries, suggesting a routing mechanism is needed. Open questions include whether the approach extends to multi-step agentic workflows, whether exploration can be bootstrapped without ground-truth code, and how the memory database scales as the number of supported data schemas grows.
