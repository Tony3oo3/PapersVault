## Problem

Existing code-assistance benchmarks (HumanEval, SWE-Bench, StackEval, InfiBench) evaluate LLMs in single-turn, snippet-level, or manually curated settings that fail to capture the iterative, project-grounded, multi-turn conversations developers actually have when seeking help. Real-world assistance requires the assistant to infer repository topology, reason about environment configuration, and reconcile ambiguous user descriptions across multiple turns—capabilities that no prior benchmark systematically measures at scale.

## Input / Output

The pipeline ingests raw GitHub issues (tagged 'question' or 'help-wanted') along with the full repository codebase at the commit closest to the issue's creation timestamp, and optionally a synthesized Docker build environment. Each issue is restructured into author-maintainer turn pairs, paired with an extracted set of user satisfaction conditions and a BM25-retrieved reference set of historical user follow-up responses. The evaluation produces a per-conversation verdict (Correct / Partially Correct / Incorrect), a per-condition satisfaction score, a verbosity label (Appropriate / Verbose / Terse), and the full multi-turn dialogue log, with Docker execution success serving as a hard gate for environment-dependent issues.

## Method

CAB is a fully automated, two-component framework. The dataset-construction pipeline collects repositories ranked by a community score (closed question + help-wanted issue counts), filters issues through regex heuristics and a 7-question LLM relevance prompt, removes non-contributory comments via a strict-exclusion LLM filter, then prepares each issue by (i) synthesizing and iteratively repairing Dockerfiles with Sonnet 3.7 (up to three repair attempts), (ii) extracting transferable, verifiable satisfaction conditions via a structured LLM prompt with post-hoc JSON verification, and (iii) building a BM25 index over historical maintainer-user pairs to guide simulated follow-ups. The evaluation framework runs a three-agent loop: a User agent poses the question and issues realistic follow-ups drawn from the BM25 reference set, a Maintainer agent (the LLM under test) reasons over the codebase and optionally executes commands in the containerized sandbox, and a Judge agent scores the final dialogue against satisfaction conditions, execution outcomes, and interaction quality. The entire pipeline executed 44,628 Sonnet 3.7 calls end-to-end with zero manual intervention, yielding 3,286 issues across 214 repositories and seven languages, with a 'Recent' cohort (post-November 2024 repositories) ensuring persistent difficulty beyond model training cutoffs.

## Results

On CAB's 3,286 real-world GitHub issues across 214 repositories and 7 languages, state-of-the-art LLMs solve only 7.22–16.49% of issues from post-training-cutoff (Recent) repositories, compared to 13.58–29.14% on All-Time repositories. ChatGPT 4.1 Mini achieves the highest correctness (16.49% Recent, 29.14% All-Time), while Haiku 3.5 performs worst (7.22% Recent, 16.86% All-Time). This stands in stark contrast to the 70–83% accuracy these same models achieve on Stack Overflow-style single-turn benchmarks (InfiBench, StackEval), revealing a fundamental gap in project-grounded, multi-turn assistance. A synthetic ablation study shows Sonnet 3.7 reaches 74% correctness on AI-generated repos with in-cutoff libraries versus only 11.34% on recent real repos, confirming the recency gap is driven primarily by post-training-cutoff framework changes.

## Baselines & Comparisons

CAB does not pit its benchmark against prior benchmarks in a head-to-head protocol; instead, it evaluates six LLMs (ChatGPT 4.1 Mini, DeepSeek R1, Llama 3.3 70B, Haiku 3.5, Sonnet 3.7, Sonnet 3.7 Think) as maintainer agents within the same multi-turn, environment-grounded setting. ChatGPT 4.1 Mini leads on both cohorts (16.49% Recent, 29.14% All-Time correctness), outperforming the next-best model (Sonnet 3.7 Think at 13.40%/27.43%) by roughly 3 percentage points on Recent repos. DeepSeek R1 achieves the lowest incorrect rate on All-Time repos (32.57%), while Sonnet 3.7 (Think) shows the most balanced verbosity profile. The most striking comparison is temporal: every model drops 12–20 percentage points in correctness when moving from All-Time to Recent repositories, with the gap largest for Llama 3.3 70B (13.58% → 9.33%) and smallest for ChatGPT 4.1 Mini (29.14% → 16.49%). The synthetic ablation (74% on in-cutoff repos vs. 11.34% on recent real repos for Sonnet 3.7) isolates training-data recency as the dominant factor rather than inherent reasoning deficits.

## Relation to Prior Work

CAB carves new ground by combining three previously separate benchmarking threads—code generation (SWE-Bench, BigCodeBench), multi-turn dialogue (MINT, ConvCodeWorld, TICODER), and programming Q&A (StackEval, InfiBench)—into a single framework that evaluates multi-turn, project-grounded assistance in containerized environments. Unlike prior Q&A benchmarks that rely on manually curated Stack Overflow snippets in single-turn settings, CAB's fully automated pipeline extracts runnable contexts from real GitHub issues, synthesizes Docker build environments, and derives satisfaction conditions without human curation. The multi-agent evaluation design (simulated user, maintainer agent, LLM judge) departs from execution-oracle-only scoring by tracking conversational quality across turns.

## Why It Matters / Open Questions

The benchmark exposes a dramatic capability gap: models scoring 70–83% on Stack Overflow-style questions solve only 7–17% of CAB issues from post-training-cutoff repositories, suggesting that realistic, project-specific assistance remains far from solved. The synthetic-repository ablation (74% vs. 11.34% correctness) points to knowledge-cutoff staleness rather than fundamental reasoning deficits as the primary bottleneck, a finding with direct implications for model update cadence. Key open questions include improving satisfaction-condition recall (currently 65.7% complete), closing the 12-point LLM-judge-to-human agreement gap in multi-turn settings, and extending coverage beyond seven languages and permissively licensed repositories.
