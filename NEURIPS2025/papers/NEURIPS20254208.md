## Problem

Existing LLM serving systems use LRU-based KV cache eviction, which is suboptimal for multi-agent workflows where an agent about to execute may have been idle for a long time while a recently active agent may not be needed soon. This causes premature eviction of soon-to-be-reused caches, leading to frequent cache misses and costly recomputation or CPU-to-GPU reloads, especially with large fixed agent prompts that exceed GPU memory.
![Teaser figure](../imgs/NEURIPS20254208/cropped_page1_idx0.webp)

## Input / Output

The system consumes agent prompts split into a fixed prefix (role, instructions, few-shot examples, potentially 3000+ tokens) and a dynamic suffix (task-specific content), along with workflow metadata in the form of an Agent Step Graph that encodes inter-agent dependencies and per-agent steps-to-execution values. It produces fine-grained eviction priorities assigned to individual KV nodes in the radix tree (not at the agent level) and a proactive prefetching schedule that triggers background CPU-to-GPU transfers before the target agent is dispatched, ultimately yielding reduced end-to-end workflow latency.

## Method

KVFlow introduces the Agent Step Graph abstraction, where each agent node carries a steps-to-execution value computed via step aggregation functions (max for AND/synchronization dependencies, min for OR/conditional branches) propagated recursively across the graph. At runtime, these values are mapped onto the radix-tree KV cache at the node level: each agent's steps-to-execution is assigned to the last node of its fixed prompt and propagated upward, with shared nodes receiving the minimum (least evictable) priority among all children, while dynamic suffixes always get the highest eviction priority. A second mechanism performs fully overlapped KV prefetching: background threads proactively load the next agent's KV tensors from CPU to GPU during the current agent's forward pass (exploiting PCIe full-duplex), and a status-aware scheduler skips any request whose cache nodes are still in a 'loading' state, dispatching other ready requests instead to eliminate GPU idle time from incomplete transfers.

## Results

On a 10-stage sequential workflow with Qwen2.5-32B on an H100, KVFlow achieves up to 1.83× end-to-end speedup over SGLang (GPU-only radix cache) for single workflows with large fixed prompts (8192 tokens), and up to 2.19× speedup over SGLang w/ HiCache under high concurrency (64 concurrent workflows). Under the 4096/32/32 token setting with branches=1, KVFlow outperforms SGLang w/ HiCache by 1.24× and GPU-only SGLang by 1.42×. On realistic PEER-style multi-agent workloads using the Financial QA dataset, KVFlow delivers up to 1.12× speedup over SGLang and 1.08× over HiCache.

## Baselines & Comparisons

KVFlow is compared against three baselines: SGLang with GPU-only radix cache (LRU eviction), SGLang w/ HiCache (hierarchical radix cache with CPU backup and reactive loading), and vLLM (block-level LRU). KVFlow consistently outperforms all baselines across every evaluated setting. The largest gains appear over SGLang w/ HiCache under high concurrency, where HiCache degrades to 0.57× of GPU-only SGLang (i.e., it is slower than no CPU cache at all) due to reactive load-back disrupting the schedule-compute pipeline, while KVFlow achieves up to 2.19× speedup over HiCache. Over GPU-only SGLang, KVFlow's advantage grows with fixed prompt length (1.22× at 4096 tokens vs. 1.30× at 8192 tokens), reflecting higher cache-miss costs for longer prefixes. On realistic PEER-style workloads with shorter prompts (tens to hundreds of tokens), the speedups are more modest (1.08–1.12×) but still consistent, confirming practical benefit in deployment-scale multi-agent serving.

## Relation to Prior Work

KVFlow builds directly on SGLang's RadixAttention prefix caching (a tree-structured KV cache on GPU) and extends it with two workflow-aware mechanisms: a steps-to-execution-based eviction policy that replaces the default LRU, and a fully overlapped CPU-to-GPU prefetching pipeline. It departs from the broader LLM serving literature (vLLM's PagedAttention, CachedAttention, InferCept) by incorporating application-level workflow topology—the Agent Step Graph—as a first-class input to cache management, rather than treating each request independently. The paper positions itself as complementary to agentic workflow frameworks (MetaGPT, PEER, AutoGen) that optimize application-layer logic, and to scheduling-focused systems (Autellix, ParrotServe) that do not address prefix cache management.

## Why It Matters / Open Questions

The paper identifies a concrete and previously underappreciated inefficiency: LRU eviction systematically evicts KV caches of agents that are about to be reused in structured multi-agent pipelines, causing avoidable recomputation or PCIe stalls. The practical impact is significant for the growing ecosystem of LLM-based agentic applications, where fixed prompts can exceed 3000 tokens and workflows loop iteratively. Key limitations include the requirement that future agent invocations be predictable within a bounded window (highly dynamic or fully autonomous agent systems fall outside scope), and the current prototype's integration into SGLang's specific radix-tree architecture. Open questions include how the approach generalizes to non-sequential topologies with deep branching, to multi-GPU or distributed serving settings, and to workflows where the step graph itself changes at runtime.
