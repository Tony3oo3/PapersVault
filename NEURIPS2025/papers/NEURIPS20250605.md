## Problem

In LLM-based multi-agent systems, agents redundantly recompute KV-caches for overlapping shared contexts (e.g., retrieved passages, peer outputs), causing prefilling complexity to scale as O(M²) with the number of agents. Existing KV-cache reuse methods rely on fixed acceleration policies that fail under the 'offset variance' problem: the same shared text incurs vastly different KV-cache deviations when preceded by different prefix contexts, leading to either severe accuracy drops or fallback to full recomputation. No prior method simultaneously handles diverse prefix contexts adaptively at runtime without training or model modification.

## Input / Output

The system takes a directed graph of homogeneous RoPE-based LLM agents, each with a role-specific prompt template composed of fixed prefix segments and runtime-filled placeholders (user queries, tool results, upstream agent responses). Base KV-caches for all prefix segments are precomputed and stored in shared memory before any user request arrives. At inference, KVCOMM produces approximated KV-caches for each agent's full prompt by combining stored base caches with anchor-interpolated offsets, enabling direct decoding without the prefilling pass. The output is the agent's generated response along with its KV-cache, which is then routed to downstream agents or the anchor pool.

## Method

KVCOMM is a training-free, prompt-adaptive framework that treats KV-cache reuse as an approximate translation problem. It maintains an online anchor pool where each entry stores a placeholder's base KV-cache plus measured Key/Value offsets under each agent's specific prefix context. At inference, new placeholders are matched to anchors via embedding-distance-based softmax weights and length compatibility (Eq. 5), then their KV-caches are approximated by interpolating the matched anchors' stored offsets (Eqs. 6–7). For Keys, the cache is first de-rotated by RoPE to align positions, biased by the estimated offset, and re-rotated to the target position; for Values, the offset is added directly since they carry no positional information. The anchor pool is updated online: when a sample is deemed unshareable, it becomes a new anchor and dependent agents perform dense prefilling to populate its offsets, while least-frequently-used anchors are pruned to bound memory. Theoretical grounding (Propositions 1–2) via Lipschitz bounds on attention and FFN modules shows that embedding-close tokens exhibit proportionally smaller KV-cache deviations, justifying the embedding-based anchor matching strategy.

## Results

KVCOMM achieves up to 7.82× TTFT speedup (reducing first-token latency from ~430 ms to ~55 ms) in a five-agent Llama-3.1-8B setting on a single H100 GPU, with a mean speedup of ~6.7× across three agents. On GSM8K, KVCOMM maintains accuracy within 1.9% of the original baseline (81.5%→79.6% from 2 to 5 agents) while achieving 71–80% KV-cache reuse. On HumanEval, KVCOMM sustains 81.4–87.6% Pass@1, and on MMLU it tracks the original baseline (64.7–69.9% accuracy) with 67.6–74.5% reuse rate.

## Baselines & Comparisons

The sole baseline is CacheBlend [Yao et al., EuroSys 2025], which selectively recomputes the top-20% most sensitive tokens and reuses the remaining 80% of KV-caches. KVCOMM decisively outperforms CacheBlend on GSM8K: at 5 agents, KVCOMM retains 71.0% reuse with accuracy within ~2% of the original (81.7%), whereas CacheBlend's accuracy collapses from 82.0% (2 agents) to 57.1% (5 agents), a 25-point drop. On HumanEval the gap is even starker—KVCOMM sustains 77.8–87.6% Pass@1 while CacheBlend falls to 21.1–32.9%, an average margin of ~53 percentage points, attributed to CacheBlend's inability to handle prefix-sensitive KV distributions induced by code syntax separators. On MMLU both methods remain relatively stable, but KVCOMM's adaptive reuse (67.6–74.5%) more closely tracks the original baseline than CacheBlend's fixed 80% policy. In terms of latency, KVCOMM achieves up to 7.82× per-agent TTFT speedup (Agent 5 in a 5-agent chain), a benefit not reported by CacheBlend due to its mandatory recomputation of sensitive tokens.

## Relation to Prior Work

KVCOMM carves new ground at the intersection of KV-cache reuse and multi-agent LLM systems. Prior KV-cache acceleration methods—PromptCache (fixed prompt structures), CacheBlend (selective top-20% token recomputation), DroidSpeak (profiling-based layer sharing), and KVLink (fine-tuned positional embeddings)—all rely on a fixed acceleration policy that assumes either identical prefixes or a bounded set of context variations. KVCOMM departs by identifying the 'offset variance problem' (the same shared text incurs vastly different KV deviations under different agent-specific prefixes) and solving it with a training-free, online anchor-based interpolation that reuses all shareable KV-caches rather than selectively recomputing a subset. Conceptually, it repurposes the residual-pathway similarity argument (Proposition 1) and RoPE's rotational structure to justify that embedding-close anchors yield reliable offset predictions, bridging ideas from few-shot nearest-neighbor estimation and attention-sink-aware positional alignment.

## Why It Matters / Open Questions

The 7.8× prefill speedup (TTFT from ~430 ms to ~55 ms) in a five-agent setting is practically significant as multi-agent LLM pipelines become standard for RAG, math, and coding workflows, and the training-free, drop-in design lowers adoption barriers considerably. However, the framework is currently restricted to homogeneous RoPE-based agents processing text, does not address decoding latency (the other major bottleneck), and its anchor pool management at scale (beyond 20 anchors per placeholder) remains untested. Open questions include whether the offset-variance characterization generalizes to heterogeneous architectures (e.g., MoE, sliding-window attention), whether anchor-based interpolation degrades gracefully under highly dynamic or debate-style agent topologies, and whether the approach extends to multimodal inputs.
