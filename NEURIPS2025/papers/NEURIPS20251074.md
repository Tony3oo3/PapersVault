## Problem

Scaling input embedding layers by simply enlarging the token vocabulary has limited benefits: it inflates the tied output (logits) layer, making decoding impractical beyond a few hundred thousand tokens, and it creates sparse gradient updates that degrade tail-token representations. The paper asks how to substantially expand input embedding capacity while keeping inference-time accelerator FLOPS and memory fixed—a property that traditional model-size scaling does not support.
![Teaser figure](../imgs/NEURIPS20251074/cropped_page1_idx0.webp)

## Input / Output

SCONE takes a token sequence (from a fixed BPE vocabulary, e.g., 50,257 tokens for GPT-2) and produces, for each token position, a contextualized embedding vector of dimension d (e.g., 2048). The embedding for position i is either the standard token embedding or the embedding of the longest matching f-gram (an n-gram of length 2–K, typically K=5) ending at that position. During training these f-gram embeddings are computed on-the-fly by a separate transformer; during inference they are retrieved from a precomputed key-value table stored in system RAM or on NVMe SSD, so the main model's accelerator footprint remains unchanged.

## Method

SCONE augments a standard decoder-only transformer with an f-gram embedding layer whose entries are learned by a dedicated f-gram transformer model (A_f-gram) rather than stored as a static table. A set of frequent n-grams (f-grams) is selected via a BPE-inspired procedure requiring only K−1 linear scans over the corpus; the number of f-grams is decoupled from the token vocabulary size, allowing tables of up to 1 billion entries. During training, A_f-gram processes each matched f-gram as a short sequence and outputs the final position's embedding, jointly trained with the main model and token embedding layer; during inference, all f-gram outputs are precomputed and cached in an off-accelerator lookup table (hash dictionary + dense matrix in RAM, or LMDB B+ tree on SSD). This design yields two independent scaling axes—increasing the number of cached f-gram embeddings and enlarging A_f-gram—both of which improve quality without increasing inference-time FLOPS or accelerator memory, since A_f-gram is replaced by a constant-time table lookup at deployment.

## Results

On six zero-shot downstream benchmarks (MMLU, HellaSwag, ARC-E, ARC-C, CSQA, PIQA), SCONE with 1B f-grams on OLMo-1B achieves 57.0% average accuracy, slightly surpassing the OLMo-1.9B baseline (56.8%) while requiring approximately 48% less inference FLOPS and accelerator memory. With 10M f-grams on OLMo-1.3B, SCONE matches the 1.9B baseline (56.8% vs. 56.8%) at ~32% lower inference cost. On the OLMo evaluation mixture (11 corpora), the 1B+1B f-grams configuration reduces average perplexity from 16.082 (1B baseline) to 14.581, beating the 1.9B baseline (14.598).

## Baselines & Comparisons

Against the OLMo-1.9B baseline (Groeneveld et al., ACL 2024), SCONE with 1B f-grams on OLMo-1B achieves a marginal win (57.0 vs. 56.8 avg accuracy) while using roughly half the inference FLOPS and accelerator memory; SCONE with 10M f-grams on OLMo-1.3B ties the 1.9B baseline exactly (56.8 vs. 56.8) at ~32% lower inference cost. Against the concurrent over-tokenized transformer (Huang et al., ICML 2025), SCONE with 10M f-grams on OLMo-1B (54.9 avg) outperforms OLMo-1B+OE-12.8M (54.4 avg), which the authors attribute to the additional capacity of the A_f-gram model during training. In the post-training setting (Appendix E.3), SCONE applied to Qwen3-4B-base (Yang et al., 2025) improves AIME 2024 pass@1 from 45.3 to 51.6 (+6.3) and LiveCodeBench from 30.8 to 36.3 (+5.5) using a 14B f-gram model, with negligible latency increase (10.05→10.13 ms/token). On the OLMo perplexity evaluation across 11 corpora, the 1B+1B f-grams configuration (14.581 avg) beats the 1.9B baseline (14.598) and the 1.3B+1B f-grams configuration (14.245) beats it by a wider margin.

## Relation to Prior Work

SCONE builds on the idea of decoupling input and output embedding layers, first explored by Roy et al. (N-grammer, 2022) for bi-grams, and is concurrent with the over-tokenized transformer (Huang et al., 2025) which also introduces an additional n-gram input embedding layer. The key departure is parameterizing the additional embedding table with a separate transformer (the f-gram model) during training rather than directly instantiating a large table, which avoids sparse-update degradation and eliminates the need for accelerator-resident storage of billions of embeddings. The design also echoes the Mixture-of-Lookup-Experts idea (Jie et al., 2025) of using a neural network with discretized inputs that collapses to a lookup table at inference, but SCONE adds the axis of scaling the number of keys via BPE-style f-gram discovery.

## Why It Matters / Open Questions

SCONE introduces a genuinely new scaling axis—increasing training compute via a larger f-gram model without any increase in inference-time FLOPS or accelerator memory—which the compute-optimal scaling literature (Hoffmann et al., Jones) had not explored. This is practically significant for deployments where inference costs dominate (billions of queries/day, latency-sensitive applications), as demonstrated by a 1B SCONE model matching or exceeding a 1.9B baseline at roughly half the inference cost. Limitations include evaluation only up to 3B training-time parameters, restriction to short n-grams (K=5), and the storage overhead of caching up to 1B embeddings (7.7 TB on NVMe). Open questions include whether the approach scales to 70B+ models, how f-gram embeddings interact with the transformer's implicit n-gram patterns, and whether longer or semantically-keyed n-grams can be effectively cached.
