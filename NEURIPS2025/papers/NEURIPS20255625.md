## Problem

User edits in LLM deployment logs naturally encode three distinct feedback signals—supervised labels, preference pairs, and cost—yet the literature studies each in isolation without characterizing their trade-offs in this unified setting. This paper initiates the theoretical investigation of learning from user edits, asking how to principledly exploit each feedback type and when each is most effective for fine-tuning an LLM agent.
![Teaser figure](../imgs/NEURIPS20255625/cropped_page1_idx0.webp)

## Input / Output

The method consumes an offline dataset of deployment logs where each example is a triple (context x, agent response y, user edit y'), with the context potentially containing multimodal data and the edit cost measured by Levenshtein distance over sub-tokens. The agent operates in a two-phase protocol: an offline fine-tuning phase on the dataset, followed by T online episodes where it generates a response and receives an edit cost from the user. The output is a fine-tuned policy (or ensemble of policies) that minimizes cumulative edit cost, competing against a KL-regularized optimal policy π*^β.

## Method

The paper derives suboptimality bounds for three algorithms that exploit different feedback types from the same edit data: supervised fine-tuning on edits (SFT), Direct Preference Optimization treating (y, y') as a preference pair (DPO), and pessimistic reinforcement learning on a learned cost model (RL). A key theoretical contribution is a 'balance equation' assumption on the user edit distribution that implies a contraction property—iterative user edits converge geometrically to the optimal policy at rate (1−γ_min)—and that recovers the Bradley-Terry preference model, justifying DPO despite the non-IID preference pair distribution. The paper then proposes two ensembling strategies: early ensembling that jointly optimizes SFT and DPO losses with a weighting parameter λ, and late ensembling that trains separate policies and uses a UCB bandit algorithm during online deployment to adaptively select the best policy based on observed edit costs. The theoretical analysis shows SFT benefits from fast-converging users (high γ_min), DPO is more robust to user behavior but requires preference concentrability, and RL is most sample-efficient when the cost function class is simple.

## Results

On the summarization and email writing benchmarks (using Qwen-3 32B as the simulated user), the proposed LateEnsemble method achieves the lowest worst-case sub-optimality (Max SubOpt) of 0.1586 ± 0.04, compared to 0.1612 for EarlyEnsemble, 0.5772 for SFT, 0.8698 for DPO, and 0.7364 for the unadapted Base model. On the summarization task with a strong user, EarlyEnsemble achieves the best individual score (0.2092 ± 0.09 mean edit distance), while LateEnsemble (0.2768 ± 0.13) is slightly behind but far more robust across the weak-user setting (0.4403 vs. SFT's 0.9304). Transfer to a different user LLM (Llama-3.3-70B) preserves the same ranking, with LateEnsemble again achieving the best Max SubOpt of 0.0862.

## Baselines & Comparisons

The paper compares five approaches: the unadapted Base model, SFT (supervised fine-tuning on user edits), DPO (preference learning treating edits as preferred responses), EarlyEnsemble (joint DPO+SFT loss), and LateEnsemble (UCB bandit over the three offline policies). LateEnsemble achieves the best worst-case performance (Max SubOpt 0.1586) by adaptively selecting the best policy per context at test time, outperforming SFT (0.5772) and DPO (0.8698) by large margins in the worst case. SFT excels when the user is strong (0.5377 on Summ-Strong) but degrades catastrophically with a weak user (0.9304), consistent with its theoretical dependence on γ_min. DPO is more robust to user strength but performs poorly on summarization with a strong user (1.0790), likely due to the non-IID preference distribution. EarlyEnsemble achieves the best individual scores on summarization (0.2092 strong, 0.3586 weak) but underperforms DPO on email writing (0.3438 vs. 0.3365 strong), suggesting sensitivity to the λ hyperparameter. LateEnsemble's advantage is its test-time adaptability: it converges to the best-performing policy in each setting without requiring a single fixed trade-off.

## Relation to Prior Work

This paper extends the empirical user-edit fine-tuning setup of Gao et al. (NeurIPS 2024) by providing the first theoretical analysis of learning from user edits, unifying three feedback types—supervised labels, pairwise preferences, and scalar costs—that naturally co-occur in deployment logs. It adapts DPO (Rafailov et al.) to a non-standard preference distribution where one response comes from user edits rather than independent reference-policy sampling, and draws on offline RL techniques (pessimistic cost models, Eluder dimension) and bandit algorithms (UCB) for the online adaptation phase. The key conceptual departure from standard RLHF is that the preference pair is not generated by two independent samples from the reference policy, which changes both the theoretical analysis and empirical behavior.

## Why It Matters / Open Questions

The paper provides practitioners with a principled framework for choosing among SFT, DPO, and RL when fine-tuning from deployment logs, showing that the optimal choice depends on user behavior (γ_min), data coverage, and cost-function complexity. The late-ensembling (UCB bandit over pre-trained policies) offers a simple, robust adaptation mechanism for the online phase, achieving the best worst-case performance across settings. Key limitations include reliance on LLM-simulated users rather than real humans, evaluation on only two domains with small T=200, and strong theoretical assumptions (balance equation, realizability, concentrability) whose practical validity remains untested. Open questions include relaxing these assumptions, deriving minimax-optimal algorithms, and validating findings in human studies.
