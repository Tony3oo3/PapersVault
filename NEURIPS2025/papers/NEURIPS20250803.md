## Problem

Adaptive mesh generation for FEM simulations requires assigning finer elements to critical regions, but existing approaches rely on task-specific heuristics, hand-crafted sizing fields, or learned models that predict a single sizing field on a fixed representation (image or coarse mesh). These methods struggle with extreme local variation in element sizes, cannot dynamically adapt sampling resolution across refinement scales, and often require a FEM solver or complex reward function in the loop. The paper asks whether a learned, iterative mesh generation process can match or exceed expert mesh quality across diverse 2D/3D geometries without task-specific engineering.

## Input / Output

AMBER takes a 2D/3D geometry Ω (encoded as a graph with vertex features including process conditions like load functions or inlet positions, geometric features, and optionally FEM solutions) and a coarse uniform initial mesh M⁰. At each of T iterative steps, the network outputs a discrete scalar sizing field (one value per vertex), which is interpolated via nodal basis functions into a continuous piecewise-linear sizing field over Ω. This sizing field is fed to a non-parametric mesh generator (GMSH Frontal Delaunay) to produce the next intermediate mesh, whose vertices become the sampling points for the subsequent prediction. The final output is an adaptive mesh M^T with spatially varying element sizes; a single scalar refinement constant c_t can scale the sizing field at inference to control total element budget without retraining.

## Method

AMBER uses a Message Passing Network (MPN) operating on a hierarchical graph that unions the initial coarse mesh graph with the current intermediate mesh graph, connected by bidirectional cross-edges from each intermediate vertex to its nearest coarse-mesh vertex. This hierarchical structure provides a resolution-invariant receptive field, enabling consistent long-range communication across refinement levels. Training is supervised with an MSE loss in the untransformed space (softplus ensures positivity), where targets are obtained by projecting expert mesh element sizes onto intermediate mesh vertices. To address the distribution shift between the coarse training meshes and the auto-regressive intermediate meshes seen at inference, AMBER maintains a replay buffer of self-generated meshes (analogous to DAgger but fully automatic), periodically generating new intermediate meshes, labeling them via expert projection, and adding them to the buffer. Additional design choices include residual prediction (predicting the difference between target and current sizing field), uniform refinement depth sampling, adaptive batch sizing by graph size, and input/output normalization with running statistics.

## Results

AMBER achieves the best Density-Aware Chamfer Distance (DCD, lower is better) across all six datasets, with scores of 0.224±0.004 on Poisson (hard), 0.222±0.003 on Laplace, and 0.103±0.002 on Airfoil. On Poisson, AMBER closely matches or slightly exceeds the expert heuristic's error indicator norm and generalizes to meshes with over 100,000 elements (the largest expert mesh has only 31,510), requiring only a single scalar adjustment. AMBER is more than an order of magnitude faster than the iterative expert heuristic on meshes exceeding 30,000 elements. The mixed-dataset model (AMBER Mixed) achieves nearly identical performance to per-dataset training (e.g., 0.226±0.011 vs. 0.224±0.004 DCD on Poisson hard), demonstrating strong cross-task generalization.

## Baselines & Comparisons

Against the Image baseline (Huang et al., 2021), which predicts pixel/voxel-wise sizing fields from binary geometry masks via a CNN, AMBER outperforms on all datasets, with the gap widening as task complexity increases; the Image methods struggle particularly on 3D datasets (Console, Mold) and fail to capture fine local details, producing more uniform, less adaptive meshes. Against GraphMesh (Khan et al., 2024), a two-step GCN limited to polygonal domains, AMBER achieves lower DCD on Poisson, the only dataset where GraphMesh is applicable. Against the RL-based ASMR (Freymuth et al., 2024), AMBER produces lower error indicator norms at comparable element counts on Poisson and, critically, does not degrade beyond ~30,000 elements (where ASMR's fixed-depth reference mesh causes performance collapse); AMBER also avoids ASMR's need for a FEM solver in the reward loop. Even the single-step variant AMBER (1-Step) already outperforms all baselines, with the full iterative model providing further gains through adaptive sampling resolution across refinement steps.

## Relation to Prior Work

AMBER carves new ground at the intersection of learned mesh generation and online self-training. Prior learned AMG methods (Image [22], GraphMesh [24], MeshingNet [29]) predict a single sizing field from a fixed representation (image, coarse mesh, or coordinates), while RL-based AMR methods (ASMR [51]) require a FEM solver in the loop and hand-crafted rewards. AMBER departs from both by iteratively predicting sizing fields on successively refined meshes, using each intermediate mesh's vertices as the sampling grid for the next step, and by bootstrapping its own training distribution via a replay buffer of self-generated meshes—an approach inspired by DaGger-style imitation learning but fully automated. The hierarchical graph structure that connects the initial coarse mesh to intermediate meshes is a novel architectural choice not present in prior GNN-based meshing work.

## Why It Matters / Open Questions

AMBER addresses a practical bottleneck in engineering simulation: the manual, expert-driven process of designing adaptive meshes for each new geometry or problem. By learning from only ~20 expert meshes per dataset and generalizing to unseen geometries, it offers a path toward automated, budget-aware mesh generation that scales better than classical iterative error-estimation heuristics. Key limitations include the restriction to scalar (isotropic) sizing fields, a convergence proof only in 1D under perfect predictions, and evaluation primarily on proxy metrics (DCD) rather than direct simulation error across all datasets. Open questions include whether tensor-valued or higher-order sizing fields can capture anisotropic refinement, whether a single general-purpose model can span many engineering domains, and how the method performs on real-world industrial problems with full simulation feedback.
