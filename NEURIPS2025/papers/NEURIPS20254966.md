## Problem

Code embedding models for retrieval-augmented code generation remain severely limited by the scarcity of high-quality, diverse training data. Existing datasets are either tailored for text-centric scenarios (web search, QA) or cover only a narrow set of code retrieval tasks, making them insufficient for the wide range of semantic relationships inherent to code. This paper addresses the gap by introducing a large-scale synthetic dataset and a training strategy that together enable a generalist code embedding model.

## Input / Output

The model accepts either a natural-language query (English or Chinese) or a code snippet (across 20 programming languages) as input, truncated to 512 tokens. During inference, a task-specific instruction is prepended to the query in the format ⟨instruct⟩{task}⟨query⟩{query}, and the dense embedding is extracted from the [EOS] token's hidden state in the final layer. Retrieval is performed via temperature-scaled cosine similarity (τ=0.02) between query and document embeddings, producing a ranked list of relevant code or text passages.

## Method

CodeR is built on Qwen-2.5-Coder-1.5B fine-tuned with LoRA (rank 32, alpha 64) using InfoNCE contrastive loss. The key data contribution is CodeR-Pile (2.9M samples, 47 tasks, 4 task types, 20 languages), generated via a three-stage pipeline: (1) Brainstorming diverse task definitions with powerful LLMs (DeepSeek-R1, GPT-4o, Claude-3-Opus, Gemini-2.0), (2) drafting detailed generation and annotation instructions with GPT-4o mini, and (3) producing query-positive triplets with the lightweight Qwen2.5-Coder-32B-Instruct, followed by LLM-based relevance annotation and mining of 15 hard negatives from a real-world corpus via Topk-PercPos. The training procedure follows a three-stage curriculum called Annealing: warming up on text-only data, intensively training on a mixture of text and code data, then cooling down on code-only data with E5-based hard-sample filtering and GPT-4o mini difficulty classification to retain only medium and hard examples. This weak-to-strong supervision paradigm enables effective knowledge transfer from textual semantics to code-specific retrieval while preserving training stability.

## Results

On the CoIR benchmark (10 datasets, NDCG@10), CodeR-1.5B trained with full code data achieves a state-of-the-art average of 81.77, outperforming the strongest baseline Voyage-Code-003 (78.53) by 3.2 points and CodeXEmbed-7B in-domain (78.20) by 3.6 points. On the out-of-domain CodeRAG benchmark, CodeR achieves an average NDCG@10 of 72.8, surpassing the best baseline SFR-mistral-7B (67.0) by 5.8 points. On the de-duplicated CoIR-filter benchmark, CodeR's advantage over Voyage-code-003 widens to 4.3 points (93.00 vs. 88.73), confirming robustness against evaluation artifacts.

## Baselines & Comparisons

CodeR-1.5B (full) outperforms all 9 baselines on the CoIR average NDCG@10, with the largest margins over general-purpose models: +42.5 points over BGE-M3 (39.31), +26.6 over E5-Mistral-7B (55.18), and +7.9 over Gemini-embedding (73.90). Among code-focused models, CodeR beats the strongest proprietary baseline Voyage-Code-003 by 3.2 points (81.77 vs. 78.53) and the strongest open-source baseline CodeXEmbed-7B in-domain by 3.6 points (81.77 vs. 78.20). On the out-of-domain CodeRAG benchmark, CodeR achieves 72.8 average NDCG@10, surpassing SFR-mistral-7B (67.0), Jina-v2-code (65.4), and CodeXEmbed-2B general (64.6) by 5.8, 7.4, and 8.2 points respectively. Notably, even CodeR trained exclusively on synthetic data (70.12 on CoIR) outperforms CodeXEmbed-2B general (67.41) and approaches CodeXEmbed-7B general (70.46), validating the quality of the synthetic pipeline. The gap widens on the de-duplicated CoIR-filter benchmark, where CodeR leads Voyage-code-003 by 4.3 points (93.00 vs. 88.73), suggesting that some of the original CoIR scores were inflated by redundant queries.

## Relation to Prior Work

This paper extends the synthetic-data-for-IR line (Doc2query, Promptagator, E5-Mistral, Gecko) from text-centric retrieval to code retrieval, where semantic relationships are fundamentally different (code-to-code, code-to-text, hybrid). It departs from prior code embedding models (CodeBERT, UniXcoder, CodeXEmbed, Voyage) primarily through its data pipeline rather than architecture: the model is a standard Qwen-2.5-Coder-1.5B fine-tuned with LoRA and InfoNCE, while the novelty lies in the DRU-guided synthesis workflow and the Annealing curriculum strategy for heterogeneous text+code data. The paper also contrasts with E5-Mistral's brainstorm approach by using a structured three-stage pipeline (brainstorming → instructing → triplet generation) that separates expensive LLM planning from cheap LLM generation.

## Why It Matters / Open Questions

Code retrieval is a critical bottleneck for RAG-based code development, and the scarcity of high-quality, diverse training data has been the primary limiter. CodeR-Pile (2.9M samples, 47 tasks, 20 languages) and its open-sourced synthesis pipeline directly address this gap, making it a practical resource for the community. The finding that a lightweight open-source LLM (Qwen2.5-Coder-32B) is nearly as effective as GPT-4o mini for data generation (1.66-point gap) and that real-world corpus mining outperforms LLM-generated hard negatives are practically valuable insights for cost-effective data synthesis. Open questions include whether the approach scales to more languages, whether the 1.5B model can be extended to larger scales, and whether the synthetic data can support re-ranking models.
