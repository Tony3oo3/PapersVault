## Problem

Existing code generation systems optimize for immediate functional correctness via static test cases but neglect maintainability—the ability to adapt code to evolving requirements with minimal rework. No prior benchmark quantifies maintainability under requirement evolution cycles, no method systematically applies software engineering principles (e.g., design patterns, Waterfall model) to enhance structural qualities like cohesion and coupling, and the interaction between correctness and maintainability remains unexplored.

## Input / Output

The system takes a natural language problem description (from entry-level to competition-level benchmarks) as input and produces a complete, class-based Python codebase with explicit design patterns, PEP 8/257-compliant structure, and a uniformly named interface function for testing. In the dynamic evaluation phase (Phase II), a fixed generator (e.g., GPT-4o-mini) receives the initial code plus a requirement change specification (one of four patterns: functional extension, interface modification, data structure transformation, or error handling enhancement) and produces a modified codebase, from which dynamic metrics (Pass@k, AST similarity, code diff) are computed.

## Method

MaintainCoder is a multi-agent pipeline built on AutoGen that mirrors the Waterfall software development lifecycle through two orchestrated modules. The Code Framework Module chains four specialized agents—Requirements Analysis (chain-of-thought decomposition), Design Pattern Selection (choosing patterns per module to enforce modularity and low coupling), Framework Design (constructing class structures with single-responsibility principles), and Framework Evaluation (iterative review for coupling/cohesion issues, max 3 iterations)—to produce an architectural blueprint. The Code Generation Module then implements this blueprint via a Code Generation Agent (producing PEP-compliant code with targeted comments) and a Code Optimization Agent (iterative execution-feedback-diagnosis-fix loop, max 5 iterations) that ensures functional correctness. The key differentiator is the explicit, agent-mediated application of classical design patterns and the Waterfall's sequential phase discipline, which together enforce structural qualities that single-shot or test-driven multi-agent baselines (AgentCoder, MapCoder) do not address.

## Results

On the mixture-level APPS-Dyn benchmark, MaintainCoder(GPT-4o-mini) achieves 50.5% Pass@5 (vs. 35.5% for GPT-4o-mini alone), 0.797 AST similarity (vs. 0.589), and only 29.4% relative code change (vs. 140% for GPT-4o-mini). On competition-level xCodeEval-Dyn, MaintainCoder(DeepSeek-V3) reaches 36.7% Pass@5 with 0.785 AST similarity and 33.0% code change, outperforming all baselines. MaintainCoder also improves initial-code correctness (e.g., +11% on xCodeEval from 46% to 57% with GPT-4o-mini) while keeping cyclomatic complexity around 3, roughly 3× lower than competing models.

## Baselines & Comparisons

MaintainCoder dominates all single-model baselines (GPT-4o-mini, DeepSeek-V3, GPT-4o, Qwen-Plus, Gemini-2.5-Flash, Claude-3.5/3.7-Sonnet) on every dynamic metric: e.g., on APPS-Dyn it lifts Pass@5 from 35.5% (GPT-4o-mini) to 50.5% and from 59.5% (DeepSeek-V3) to 62.5%, while reducing relative code change from 140%/131% to ~29%. Against multi-agent baselines, the advantage is even starker: AgentCoder(GPT-4o-mini) drops to 21.0% Pass@5 and MapCoder(GPT-4o-mini) to 30.5% on APPS-Dyn, both far below MaintainCoder's 50.5%, and on CodeContests-Dyn AgentCoder(DeepSeek-V3) and MapCoder(DeepSeek-V3) degrade to 16.7% and 11.4% respectively versus MaintainCoder's 37.9%. MetaGPT(GPT-4.1-mini) and EvoMAC(GPT-4o-mini) on CodeContests-Dyn achieve 30.3% and 26.5% Pass@5 with AST_sim of 0.760 and 0.685, still trailing MaintainCoder(GPT-4o-mini) at 32.6% and 0.833. Notably, prompt-engineering variants (CoT, Plan) show inconsistent or even negative effects on maintainability, whereas MaintainCoder's structured pipeline yields robust gains across all difficulty levels and backbone models.

## Relation to Prior Work

This paper repurposes classical software engineering principles—the Waterfall model and design patterns—within an LLM multi-agent pipeline, a combination absent from prior code generation work. It extends the line of code generation benchmarks (HumanEval, MBPP, APPS, CodeContests, xCodeEval) by introducing dynamic requirement evolution cycles rather than static test cases, and departs from multi-agent frameworks like AgentCoder, MapCoder, and MetaGPT that optimize single-round correctness without regard to structural maintainability. The dynamic maintainability formalization (discounted cumulative modification cost) is novel, drawing on Monte Carlo estimation to approximate infinite-horizon maintenance effort with finite probes.

## Why It Matters / Open Questions

Given that 60–80% of software lifecycle costs stem from maintenance, the finding that existing code generation methods—including sophisticated multi-agent systems—produce code that degrades significantly under requirement changes is practically important. The demonstration that static metrics (MI, CC) are unreliable and even contradictory as maintainability proxies challenges a long-standing assumption in software engineering measurement. Key limitations include restriction to Python and function-level tasks (no repository-level evaluation), only four types of requirement changes, and reliance on a fixed Phase II generator (GPT-4o-mini) for probing, which may not capture all real-world modification patterns. Open questions include whether the approach generalizes to multi-file, multi-language, and repository-scale settings like SWE-Bench.
