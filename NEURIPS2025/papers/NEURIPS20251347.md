## Problem

Existing mobile GUI agents struggle with long-horizon task execution where errors accumulate across steps, lack effective mechanisms for detecting and recovering from failures in dynamic environments, and perform poorly in cold-start scenarios with unfamiliar apps. Prior reflection approaches operate only at the action level or invoke reflection at every step, making them either insufficient for multi-step error patterns or unnecessarily costly and prone to hallucination-induced misjudgments.
![Teaser figure](../imgs/NEURIPS20251347/cropped_page3_idx0.webp)

## Input / Output

The agent consumes a natural-language user instruction, the current mobile screenshot (RGB, no accessibility tree), and retrieved knowledge from a pre-computed exploration database, producing a structured action tuple (thought, action type with parameters such as coordinates or text, and a natural-language description) from a 12-type action space. After each action, the system generates multi-level reflection feedback (action-level, trajectory-level, global-level) and an updated progress summary that feeds back into the next decision step. The entire pipeline is screenshot-only, avoiding reliance on platform-specific UI hierarchies for cross-device generalizability.

## Method

MobileUse is a training-free multi-agent framework built on Qwen2.5-VL-72B-Instruct that combines a hierarchical reflection architecture with a proactive exploration module. The reflection architecture operates at three temporal scales: an Action Reflector compares pre/post screenshots (with a Perception module highlighting changed regions) to detect single-step failures, a Trajectory Reflector reviews the last 3–5 steps for repeated actions or accumulated drift, and a Global Reflector validates task completion only upon the Operator's terminate signal. A Reflection-on-Demand strategy computes a confidence score from the mean log-probability of the predicted action-type tokens and triggers the Action Reflector only when confidence falls below a threshold, reducing reflection overhead from ~90 s/task to ~10.6 s/task while preserving most performance gains. The proactive exploration stage deploys a three-agent pipeline (Action Agent, Summary Agent, Judge Agent) to autonomously explore each app for ~100 steps before task execution, distilling reusable operational knowledge (e.g., icon meanings, navigation patterns) that is retrieved and injected into the Operator's context during downstream task execution.

## Results

On AndroidWorld, MobileUse (Qwen2.5-VL-72B-Instruct) achieves a 62.9% success rate, outperforming the previous SOTA V-Droid (59.5%) by 3.4% and the best multi-agent baseline Agent-S2 (54.3%) by 8.6%. On AndroidLab, MobileUse reaches 44.2% task success rate and 50.01% sub-goal success rate, surpassing V-Droid (38.30%) by 5.9%. Compared to the same backbone model used as a single agent (Qwen2.5-VL-72B-Instruct at 35.0%), the multi-agent framework with hierarchical reflection yields a 27.9% absolute improvement on AndroidWorld.

## Baselines & Comparisons

MobileUse outperforms all 19 baselines on both benchmarks. On AndroidWorld, it beats the strongest single-agent baseline V-Droid (59.5%) by 3.4% and the strongest multi-agent baseline Agent-S2 (54.3%, built on Claude-3.7-Sonnet + UI-TARS-72B-DPO) by 8.6%, despite using a less powerful backbone (Qwen2.5-VL-72B vs. Claude-3.7-Sonnet). The gap over GPT-4o (34.5%) and UI-TARS (46.6%) is 28.4% and 16.3% respectively, highlighting the contribution of the hierarchical reflection architecture over raw model capability. On AndroidLab, MobileUse leads V-Droid (38.30%) by 5.9% in task success rate and also achieves the best sub-goal success rate (50.01% vs. GPT-4o's 35.02%). Notably, MobileUse with Reflection-on-Demand (θ=-0.01) runs in 279 s/task versus Mobile-Agent-v2's 319 s/task while achieving 20.7% higher success rate, demonstrating that the reflection mechanism adds both accuracy and efficiency gains over prior multi-agent approaches.

## Relation to Prior Work

MobileUse extends the multi-agent mobile GUI framework lineage (Mobile-Agent-v2, Agent-S2, AppAgent) by replacing their single-level or task-specific reflection/self-evolution modules with a three-tier hierarchical reflection architecture (Action, Trajectory, Global) coupled with a Reflection-on-Demand gating mechanism. It also departs from task-driven exploration approaches (AppAgent, Agent-S2) by introducing a task-agnostic Proactive Exploration stage that accumulates general UI knowledge before task execution. The Operator backbone is a standard MLLM (Qwen2.5-VL-72B-Instruct) used zero-shot, so the contribution is architectural rather than model-level, positioning MobileUse as a framework that amplifies an existing backbone's capabilities through structured self-monitoring and prior knowledge.

## Why It Matters / Open Questions

The 27.9-point gap between the same 72B backbone used as a single agent (35.0%) and the full MobileUse system (62.9%) on AndroidWorld demonstrates that structured reflection and proactive exploration can substantially unlock latent capability in strong MLLMs without any fine-tuning. The Reflection-on-Demand finding—that skipping over 85% of action-level reflections barely hurts performance—challenges the assumption that more reflection is always better and offers a practical efficiency lever for deployment. Open questions include whether the architecture scales to smaller or edge-deployed models (the 7B variant drops to 21.6%), whether proactive exploration can be made reward-driven rather than heuristic, and how to handle security-sensitive operations (biometric login, payments) that require human-in-the-loop confirmation.
