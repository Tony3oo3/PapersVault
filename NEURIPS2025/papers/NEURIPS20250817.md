## Problem

Existing GUI grounding benchmarks reduce the task to short referring expressions, missing the software commonsense, layout hierarchy reasoning, and fine-grained manipulation (e.g., character-level text selection, slider adjustment) that real computer-use agents require. Current benchmarks like ScreenSpot-v2 are saturating near 90% accuracy, while available training data—either coarse webpage text-screenshot pairs or expensive manual annotations—lacks the fine-grained operational signal needed for diverse UI elements. The paper addresses both the evaluation gap and the data scarcity simultaneously.

## Input / Output

The model receives a GUI screenshot at 720p or 1080p resolution alongside a natural language instruction that may be a step-specific sub-instruction implicitly derived from a higher-level task goal. It outputs an action type (click, move_to, type) paired with target coordinates expressed as either a point (x, y) or a bounding box (x, y, w, h). Evaluation uses spatial containment: a prediction is correct if the predicted coordinates fall within the annotated bounding box, and the model must operate purely from visual perception without access to the GUI's underlying code, accessibility tree, or APIs.

## Method

The core contribution is a multi-perspective data decomposition pipeline that synthesizes 4 million grounding examples by decoupling GUI grounding into three complementary data types: icons (collected from GitHub repositories, reverse-engineered from executables across Windows/macOS/Ubuntu, and crawled from production websites), components (generated via a code-and-rendering pipeline using Material UI where LLMs synthesize functional cases rendered in React to produce screenshots with precise ground-truth metadata), and layouts (sourced from Figma prototype designs with designer-specified bounding boxes and real-world application screenshots annotated with OmniParser-v2). A refusal dataset of 2.6 million examples is constructed by mismatching instructions with unrelated screenshots. All data is converted to image-text-to-text QA format using VisualSketchpad-like prompting with GPT-4o and Claude, producing both grounding (screenshot + instruction → coordinates) and description (screenshot + bounding box → description) training pairs. Qwen2.5-VL (3B and 7B) is fine-tuned on this mixture, and ablations show that combining specialized data for different element types enables compositional generalization to novel interfaces, with performance continuing to improve as data scale increases without saturation.

## Results

On the proposed OSWORLD-G benchmark, JEDI-7B achieves 54.1% overall grounding accuracy, outperforming UI-TARS-7B (47.5%), Qwen2.5-VL-32B (46.5%), and Operator (40.6%), while remaining competitive with the larger UI-TARS-72B (57.1%). On ScreenSpot-v2, JEDI-7B reaches 91.7% average accuracy, matching UI-TARS-7B (91.6%) and surpassing Qwen2.5-VL-32B (91.3%). On the agentic OSWorld benchmark, pairing o3 as planner with JEDI-7B as grounder achieves 51.0% success rate, surpassing Operator (32.6%), OpenCUA-32B (34.8%), and Claude 4 Sonnet (43.9%).

## Baselines & Comparisons

JEDI-7B (54.1% on OSWORLD-G) outperforms all 7B-scale grounding models including UI-TARS-7B (47.5%), Aguvis-7B (38.7%), UGround-V1-7B (36.4%), and OS-Atlas-7B (27.7%), as well as the much larger Qwen2.5-VL-32B (46.5%) and Operator (40.6%). On ScreenSpot-v2, JEDI-7B (91.7%) edges out UI-TARS-7B (91.6%) and Qwen2.5-VL-32B (91.3%), while on ScreenSpot-Pro it surpasses UI-TARS-72B (39.5% vs. 38.1%) but trails Qwen2.5-VL-32B (47.6%). The 3B JEDI model (50.9% on OSWORLD-G) already exceeds UI-TARS-7B and Qwen2.5-VL-32B, demonstrating strong parameter efficiency. On the agentic OSWorld benchmark, o3 + JEDI-7B achieves 51.0% success rate, a 7.1-point improvement over Claude 4 Sonnet (43.9%) and a 18.4-point improvement over Operator (32.6%), indicating that enhanced grounding directly translates to better end-to-end task completion. The main gap remains with Seed1.5-VL (62.9%) and UI-TARS-72B (57.1%) on OSWORLD-G, where the larger models retain an advantage, particularly in text matching and element recognition.

## Relation to Prior Work

This paper extends the GUI grounding task from the simple referring-expression formulation dominant in prior work (ScreenSpot-v2, SeeClick, UGround, OS-Atlas) to a multi-dimensional capability framework encompassing text matching, element recognition, layout understanding, fine-grained manipulation, and refusal. Methodologically, it departs from the two existing data sources—webpage screenshot-text pairs (coarse-grained) and expensive manual annotation (hard to scale)—by introducing a multi-perspective synthetic pipeline that decomposes the task into icons, components, and layouts, each generated through distinct technical routes (reverse engineering, Material UI rendering, Figma prototype export). The annotation generation borrows the Visual Sketchpad prompting paradigm [17] to convert raw screenshots and metadata into natural-language training pairs, and the training follows the standard fine-tuning recipe applied to Qwen2.5-VL backbones.

## Why It Matters / Open Questions

The 4M-example JEDI dataset and the 564-sample OSWORLD-G benchmark address a concrete gap: prior grounding evaluations saturated around 90% on simple pointing tasks while ignoring layout reasoning, sub-pixel manipulation, and infeasibility detection. The practical impact is demonstrated by the 23%→51% OSWorld success-rate jump achieved solely by swapping the grounding model, suggesting that grounding quality is a primary bottleneck for current computer-use agents. Open questions remain: refusal modeling shows near-zero improvement despite 2.6M synthetic refusal examples, data scaling shows no saturation (implying further gains are possible but computationally expensive), and the gap between pure grounding and knowledge-dependent grounding (e.g., recognizing a floppy-disk icon as 'Save') is only partially bridged by instruction refinement.
