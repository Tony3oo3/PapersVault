## Problem

Existing streaming 3D reconstruction methods rely on implicit memory mechanisms—either cached encoded features (Spann3R) or fixed-length token sequences (CUT3R)—that are limited in capacity and inevitably lose information from earlier frames as the sequence grows. This paper asks whether an explicit, spatially-structured memory that directly encodes 3D positions can overcome these limitations while remaining scalable to long sequences and dynamic scenes.
![Teaser figure](../imgs/NEURIPS20252344/cropped_page1_idx0.webp)

## Input / Output

The method consumes a stream of RGB images one frame at a time (ordered or unordered), encoding each with a ViT-Large at 224×224 (stage 1) or up to 512 max side (stages 2–3). For each frame it outputs a dense 3D pointmap in the global coordinate system (anchored to the first frame), a local pointmap, per-pixel confidence maps for both, and a camera pose parameterized as quaternion plus translation. The spatial pointer memory grows with scene exploration, with each pointer storing a 768-dim spatial feature at a specific 3D location, and a fusion mechanism with a dynamically adjusted threshold δ keeps the pointer count and per-frame runtime bounded.

## Method

Point3R maintains an explicit spatial pointer memory in which each pointer is assigned a 3D position in the global coordinate system and holds a spatial feature aggregating nearby scene information. A key architectural contribution is a 3D hierarchical position embedding that extends RoPE from 1D token indices to continuous 3D coordinates using multiple frequency bases (10, 100, 1000, 10000), injecting relative spatial position into the cross-attention between image tokens and memory features in the interaction decoders. New pointers are generated per frame by averaging predicted global pointmap coordinates within each patch and encoding current features with a lightweight ViT plus MLP; a fusion mechanism then merges nearby pointers (below a scene-scale-dependent threshold) to keep the memory spatially uniform. The model is trained in three stages on 14 diverse datasets with a confidence-aware L2 loss for pointmaps and L2 loss for poses, initialized from DUSt3R pre-trained weights, requiring only 8 A800 GPUs for 15 days.

## Results

On 7-scenes, Point3R achieves the best accuracy (Acc 0.085 mean) and completion (Comp 0.087 mean) among all methods, outperforming CUT3R (Acc 0.126, Comp 0.154) and DUSt3R-GA (Acc 0.146, Comp 0.181). On NRGBD, it achieves Acc 0.077 and Comp 0.069, again leading all baselines. For monocular depth estimation, Point3R achieves the best Abs Rel on NYU-v2 (0.078) and KITTI (0.083), and competitive results on Sintel (0.395) and Bonn (0.061). On long sequences (500–1000 frames), Point3R substantially outperforms CUT3R, e.g., Acc 0.071 vs 0.238 on 7-scenes and Acc 0.110 vs 0.372 on NRGBD.

## Baselines & Comparisons

Against the optimization-based baselines (DUSt3R-GA, MASt3R-GA, MonST3R-GA), Point3R achieves better or comparable accuracy and completion on both 7-scenes and NRGBD while operating in a single forward pass without global alignment; the only metric where it trails is NRGBD normal consistency (0.835 vs DUSt3R-GA's 0.870). Among streaming methods, Point3R clearly outperforms Spann3R on all metrics (e.g., 7-scenes Acc 0.085 vs 0.298) and CUT3R on accuracy and completion (7-scenes Acc 0.085 vs 0.126; NRGBD Acc 0.077 vs 0.099), with normal consistency nearly tied (0.739 vs 0.727 on 7-scenes; 0.835 vs 0.837 on NRGBD). For camera pose estimation (Table 4), Point3R is competitive with CUT3R on ScanNet (ATE 0.097 vs 0.099) but lags behind optimization-based methods like MASt3R-GA (ATE 0.078) and CasualSAM (ATE 0.158), and also trails Robust-CVD (ATE 0.227) on ScanNet. In the SLAM comparison (Table 8), Point3R achieves better dense geometry (Acc 0.061 vs 0.068, Comp 0.022 vs 0.045) and lower peak memory (5.46 GB vs 7.18 GB) than MASt3R-SLAM, but has higher ATE (0.084 vs 0.066) and per-frame runtime (0.20 s vs 0.11 s). On long sequences (Table 5), Point3R's advantage over CUT3R grows substantially, confirming the benefit of explicit spatial pointer memory over fixed-length token memory.

## Relation to Prior Work

Point3R extends the DUSt3R paradigm of learning dense 3D reconstruction into a shared coordinate system, and specifically builds on the streaming reconstruction line initiated by Spann3R (cached implicit features as memory) and CUT3R (fixed-length learnable token memory). The key conceptual departure is replacing these implicit, capacity-limited memories with an explicit spatial pointer memory where each pointer is anchored to a 3D position in the global coordinate system, directly encoding spatial structure rather than relying on learned token representations. The 3D hierarchical position embedding generalizes RoPE from 1D token indices to continuous 3D coordinates, and the memory fusion mechanism with a dynamic threshold ensures spatial uniformity as the explored scene grows.

## Why It Matters / Open Questions

The explicit spatial pointer memory addresses a fundamental scaling limitation of implicit memory: as sequences grow longer, fixed-length token memories (CUT3R) inevitably lose early-frame information, while the pointer memory scales naturally with explored scene extent. The ~3× accuracy gap over CUT3R on long sequences (500–1000 frames) validates this design choice and suggests that spatially-structured memory is critical for practical long-horizon reconstruction in embodied agents. Open questions include closing the camera pose estimation gap versus optimization-based methods (Table 4 shows notable RPE degradation), mitigating interference from growing pointer positions in subsequent frames, and whether the approach extends to very large-scale outdoor scenes where pointer count and interaction cost become prohibitive.
