## Problem

Existing code reasoning benchmarks lack a formal, program-centric deductive framework to verify whether LLMs genuinely reason about program semantics or merely exploit superficial natural-language associations (comments, identifier names) between code tokens. No prior benchmark isolates semantic reasoning from NL contamination while providing a sound, formally verifiable oracle, making it impossible to attribute poor performance to a lack of deductive reasoning versus memorized surface patterns.
![Teaser figure](../imgs/NEURIPS20250123/cropped_page3_idx0.webp)

## Input / Output

Each task presents a Haskell function body together with the type signatures of every function it invokes (explicitly provided as dependencies), and the model must generate the complete type signature for the target function. Evaluation is not text matching: the generated signature is formally verified for α-equivalence against the ground truth using type equality coercions in Haskell, with a static analyzer that auto-defines any newly introduced type constructors or classes to keep the proof self-contained. The two benchmark variants (TF-Bench and TF-Bench^pure) share identical logical structure but differ in whether NL-bearing tokens (type names, type variables, binding names) are preserved or replaced by positional identifiers (T1, t1, f1, …).

## Method

TF-Bench is built from 188 function-level tasks extracted from the Haskell Prelude, each made self-contained by resolving all type dependencies via AST traversal and Hoogle lookup. A key design element is the alpha-rewrite: three verified rewrite operators (NL types → T-n, type variables → t-n, binding names → f-n) are composed under Kleisli composition to produce TF-Bench^pure, stripping all natural-language content while preserving operational and denotational semantics (confirmed by successful compilation). Rather than string-matching outputs, the evaluation pipeline parses both the ground-truth and generated signatures into ASTs, constructs a proof template using System F type equality coercions with impredicative polymorphism enabled, and compiles the proof to formally certify α-equivalence. On top of this two-variant design, the paper introduces two metrics: Robustness Score (RS = Acc_pure / Acc) measuring sensitivity to NL removal, and Reasoning Effectiveness (RE = Δ_pure / Δ) measuring whether test-time-compute reasoning yields genuine semantic gains versus NL overfitting. The benchmark is evaluated across 64 LLMs in zero-shot settings, with the best model (Claude-3.7-sonnet) achieving only 55.85% on TF-Bench^pure.

## Results

On TF-Bench (188 Haskell type-inference tasks), the top models are GPT-O3-mini (90.43%) and Claude-3.7-sonnet (90.42%), while among open-source models Qwen3-32B leads at 87.94%. On TF-Bench^pure (natural language removed), performance drops sharply: Claude-3.7-sonnet achieves only 55.85% and GPT-O3 reaches 52.66%, revealing substantial reliance on NL cues. GPT-O3 attains the highest Robustness Score (64.29), and Gemini-2.5-flash shows the highest Reasoning Effectiveness (RE = 3.90), indicating its TTC mode most effectively improves genuine semantic reasoning over NL contamination.

## Baselines & Comparisons

This is a benchmark paper, so comparisons are across 64 LLMs rather than against a single proposed method. On TF-Bench, reasoning models (TTC-enabled) consistently outperform non-reasoning counterparts: Claude-3.7-sonnet (90.42%) beats Claude-3.5-sonnet (85.46%) by ~5 points, and GPT-O3-mini (90.43%) beats GPT-4o (84.57%) by ~6 points. However, on TF-Bench^pure the gap narrows dramatically, with Claude-3.7-sonnet dropping to 55.85% and GPT-O3 to 52.66%, indicating that a large portion of TF-Bench performance is attributable to NL cue exploitation rather than genuine type-theoretic reasoning. Among open-source models, Qwen3-32B (87.94% on TF-Bench) leads but falls to 43.09% on TF-Bench^pure, well below the top API models. Fine-tuning on code (e.g., DeepSeek-V2-Coder, +42.55 on TF-Bench) yields large TF-Bench gains but only modest TF-Bench^pure improvements, whereas fine-tuning on math (e.g., Qwen2-Math-72B, +11.7 on TF-Bench^pure) produces more balanced gains across both variants, suggesting math fine-tuning better develops abstract deductive reasoning transferable to program semantics.

## Relation to Prior Work

This paper builds on the Curry-Howard Isomorphism and System F's formal natural deduction structure to reframe type inference as a program semantics reasoning evaluation, departing from prior type annotation prediction work (TypeWriter, Typilus, TypeGen) that targets Python's unsound, gradual type system and treats type prediction as a downstream application rather than a reasoning probe. It also extends the task-perturbation literature (natural attacks on code, GSM-Symbolic, ReasonAgain) by introducing verified, commutative alpha-rewrite operators that remove natural language while preserving denotational semantics, and by using type equality coercions in Haskell to formally verify alpha-equivalence of model outputs rather than relying on string matching. The two-variant design (TF-Bench vs. TF-Bench^pure) is the key methodological departure, enabling isolation of genuine deductive reasoning from NL-cue exploitation in a way that prior code-understanding benchmarks cannot.

## Why It Matters / Open Questions

The finding that the best model (Claude-3.7-sonnet) achieves only 55.85% on TF-Bench^pure, and that code fine-tuning can actually *decrease* pure semantic reasoning performance (RE < 0) while math fine-tuning consistently helps, challenges the assumption that domain-specific code training improves code reasoning. This suggests current LLMs rely heavily on NL surface features rather than structural logic, with implications for how reasoning post-training (TTC) should be designed. Open questions include whether the 188-task Haskell Prelude scope generalizes to other languages and type systems, whether the benchmark's difficulty ceiling is appropriate for next-generation models, and whether the formal verification pipeline (impredicative types, type equality coercions) can be extended to richer type theories beyond System F<:.
