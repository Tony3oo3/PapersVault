## Problem

Existing diffusion-based image editing frameworks encode camera settings as discrete textual tokens, making them unable to support continuous, fine-grained control over parameters like aperture, focal plane, and shutter speed. This discretization prevents smooth visual transitions and limits applicability to realistic photographic editing where users specify arbitrary parameter values (e.g., 'aperture f/3.7'). Additionally, no high-quality paired dataset exists for supervised training of camera-aware image editing.

## Input / Output

The method takes a 512×512 RGB image and a free-form text instruction containing a continuous camera parameter value within a defined range (aperture f/2–f/10, focal plane [0,1], shutter speed [0,1] seconds) and produces a single edited image reflecting that parameter's optical effect. The parameter value is embedded as a continuous scalar rather than a discrete token, enabling arbitrary intermediate values without retraining. Training uses paired (source, target) images from CamEdit50K with explicit parameter annotations.

## Method

CamEdit builds on the InstructPix2Pix instruction-driven paradigm with an SD3 MMDiT backbone, fine-tuned via LoRA. Its first key component, Continuous Parameter Prompting (ConPrompt), synthesizes parameter embeddings by interpolating between 10 predefined anchor token embeddings in the frozen CLIP text space: e_p = Linear([e_i, e_{i+1}]) + MLP(φ(p)), where φ(p) is the normalized position between adjacent anchors, preserving distributional alignment while enabling fine-grained control. Its second component, Parameter-Aware Modulation (PAM), is injected after self-attention in each transformer block and comprises (a) a geometry-aware spatial modulation that predicts a 2×H×W displacement field via grid_sample to model depth-dependent focus shifts, and (b) a channel-wise affine modulation (γ, β) for global appearance changes such as exposure. Both sub-modules are conditioned on the continuous parameter p through lightweight MLPs, and the entire system is trained on the newly constructed CamEdit50K dataset of 54k real-synthetic image pairs with dense camera parameter variations.

## Results

On the CamEdit50K evaluation set (200 images per task), CamEdit achieves the best performance across all three camera-parameter editing tasks. For aperture editing, it reaches NIQE 3.34, DINO 0.83, and control error 0.60; for focal plane, NIQE 4.46, DINO 0.82, error 0.15; and for shutter speed, NIQE 4.28, DINO 0.93, error 0.11. Compared to the strongest diffusion baseline (retrained UltraEdit*), CamEdit reduces average control error by over 40% while also improving perceptual quality (NIQE) and content preservation (DINO) across all tasks.

## Baselines & Comparisons

Against diffusion-based editing baselines (SuperEdit, UltraEdit, In-Context Edit), CamEdit dominates on all metrics; these methods lack camera-parameter supervision and report near-maximum control error (~5 for aperture, ~0.5 for focal plane/shutter), indicating they cannot meaningfully adjust camera settings. The retrained UltraEdit* (fine-tuned on CamEdit50K) is the closest competitor, but CamEdit still reduces control error by 68% on aperture (0.60 vs 1.87), 40% on focal plane (0.15 vs 0.25), and 52% on shutter speed (0.11 vs 0.23), while also improving NIQE and DINO. The camera-aware generative model PhotoGen achieves reasonable control error (0.19–1.31) but suffers from poor perceptual quality (NIQE 6.1–6.7) and lacks DINO scores, reflecting its generation-based rather than editing-based formulation. Against rendering-based methods (Table 2b), CamEdit outperforms DrBokeh on NIQE (3.34 vs 3.81 for aperture; 4.46 vs 5.07 for focal plane) and DINO, though DrBokeh achieves a marginally lower aperture error (0.58 vs 0.60); for focal plane, CamEdit wins on all four metrics including error (0.15 vs 0.17). GPT-4o evaluation and a 15-expert user study confirm these quantitative findings, with CamEdit scoring highest on photographic realism, content preservation, and parameter accuracy.

## Relation to Prior Work

CamEdit builds on the instruction-driven editing paradigm of InstructPix2Pix and the Stable Diffusion 3 (MMDiT) backbone, but departs from prior camera-aware generation models (PhotoGen, Camera20k) that encode camera settings as discrete text tokens. The key conceptual shift is from discrete-token generation to continuous-parameter editing: the continuous parameter prompting mechanism interpolates between anchor embeddings in the frozen CLIP text space, while the parameter-aware modulation module injects spatial (grid-sample displacement) and channel-wise (FiLM-style) conditioning into the diffusion transformer. On the data side, it extends traditional single-purpose bokeh rendering pipelines (DrBokeh, BokehMe, MPIB) into a unified supervised editing dataset by combining real EXIF-estimated pairs with synthetic renders from differentiable bokeh and ISP pipelines.

## Why It Matters / Open Questions

The paper addresses a practical gap: existing editing frameworks handle semantic or stylistic changes but cannot smoothly adjust physically grounded camera parameters like aperture or shutter speed through natural language. CamEdit50K (54k pairs) is the first dataset purpose-built for continuous camera-parameter editing, and the continuous prompting + PAM design is a reusable recipe for any task requiring fine-grained numeric control through text. However, the method is limited to three parameters at 512×512 resolution, cannot recover focus from already-blurred regions, and the evaluation relies on a single 200-image test set without error bars, leaving open whether the gains generalize to higher resolutions, more parameters (ISO, white balance), or real-world deployment.
