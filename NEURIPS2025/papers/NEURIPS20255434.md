## Problem

LLM agents select tools based on metadata (name, description, parameter schema), yet this surface has been largely unexplored as an attack vector. Prior adversarial work focuses on prompt injection or tool-output manipulation, both of which are detectable via prompt-level sanitization. This paper identifies that an attacker can craft syntactically valid but disproportionately attractive tool metadata to induce agents to invoke malicious tools, bypassing existing prompt-level and auditor-based defenses without any prompt modification or model-internal access.

## Input / Output

The method consumes a fixed query set Q and a normal tool set NT (sourced from open-source tool-learning benchmarks like ToolBench/ASB), along with a crafted generation prompt P_g, and iteratively queries a target LLM agent via its public API to measure invocation probabilities. The output is a single optimized malicious tool whose metadata (name, free-text description, and parameter schema) is syntactically and semantically valid JSON but semantically engineered to maximize selection likelihood; at deployment time the attacker simply swaps this metadata into the tool ecosystem, requiring no changes to the agent's execution framework.

## Method

AMA formulates malicious metadata generation as a state-action-value optimization problem solved via LLM in-context learning. The state S tracks candidate tools with their measured invocation probabilities over Q; the action generates new tools via LLM(Q, NT, S, P_g); and the value function scores each candidate. Three mechanisms accelerate convergence: (1) generation traceability, where each tool t_i^j records its parent t_j to enable evolutionary refinement; (2) weighted value evaluation, V = p_i^j + λ(p_i^j − p_j), which balances absolute invocation rate against relative improvement over the parent; and (3) batch generation, producing n_t=10 candidates per parent per iteration and retaining only the top-k by weighted value. With K=5 maximum iterations and λ=0.5, the pipeline typically converges within two rounds (≈0.4M input tokens), yielding tools that achieve 81–95% attack success rates across four LLM agents while preserving task completion above 95%.

## Results

In the targeted setting with no defense, AMA achieves 94.54–95.58% ASR and 92.63–94.83% PL on open-source models (Gemma-3-27B, LLaMA-3.3-70B, Qwen-2.5-32B), while task success rate (TS) remains at 97–99.7%, indicating strong stealth. Combined with Injection Attack, AMA pushes ASR and PL to 94–99% across all four models including GPT-4o-mini. In the untargeted setting (no contextual knowledge), AMA still achieves 38.95–83.10% ASR, and the stacked attack reaches 93–99% ASR. Prompt-level defenses (Rewrite, Refuge) reduce AMA's ASR by only 0.1–6.6% in targeted settings, and the auditor-based detector flags AMA tools at a TPR far below the 55% achieved for Injection Attack.

## Baselines & Comparisons

The paper compares AMA against two baselines: Injection Attack (Liu et al., USENIX Security 2024), which appends imperative instructions to coerce tool usage, and Prompt Attack, which uses prompt engineering to steer the LLM into generating malicious metadata. In the targeted setting, AMA outperforms Injection Attack by 2–19% ASR on all three open-source models (e.g., 95.58% vs. 85.40% on Gemma-3-27B; 94.80% vs. 75.80% on LLaMA-3.3-70B) and by 4–12% over Prompt Attack. On GPT-4o-mini, AMA alone (81.43% ASR) trails Injection Attack (89.00%) by 7.6 points, but the stacked AMA + Injection Attack closes this gap to 97.57%. Under prompt-level defenses, AMA's ASR drops by only 0.1–6.6% (targeted), whereas Injection Attack drops by 5.8–30%, confirming AMA's superior resistance to existing safeguards. For auditor-based detection, AMA's TPR ranges from 0.50–6.25% across models, far below the 55% TPR for Injection Attack, demonstrating substantially greater stealth.

## Relation to Prior Work

This paper carves out a new attack surface in LLM agent security by targeting tool metadata (name, description, parameter schema) rather than the prompt, tool outputs, or the tool-calling chain that prior work exploits. It departs from prompt injection attacks (Liu et al., USENIX Sec '24; Fu et al., 2024) and tool-output manipulation (Zhao et al., 2024; Zhan et al., 2024) by requiring no modification to any input the agent receives at runtime—only the static metadata of a tool in the marketplace. Methodologically, it repurposes in-context learning and iterative state-action-value optimization (borrowed from LLM-based search) to generate metadata that maximizes selection probability, framing the problem as a constrained generation task rather than a gradient-based adversarial perturbation.

## Why It Matters / Open Questions

The finding that syntactically valid, semantically plausible tool metadata alone can induce 81–95% attack success while preserving ~98% task completion reveals a structural blind spot in current agent architectures: the tool-selection mechanism trusts metadata without provenance or credibility checks. The demonstrated failure of prompt-level defenses (Rewrite, Refuge), auditor-based detection, and even the Model Context Protocol to mitigate the attack underscores that execution-layer security mechanisms are needed, not just input sanitization. Open questions include whether tool-marketplace authentication (uploader identity, reputation scoring) would close this gap, how multi-agent systems might amplify or contain metadata-based attacks, and whether the strong cross-model transferability observed here persists as agent architectures evolve beyond the ReAct paradigm.
