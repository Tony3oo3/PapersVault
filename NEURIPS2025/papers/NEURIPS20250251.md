## Problem

While ZeroRL has demonstrated that base LLMs can improve text-based mathematical reasoning through outcome-only rewards, the dynamics by which agents spontaneously acquire external tool-use capabilities—specifically Python code execution—remain uncharacterized. Existing Tool-Integrated Reasoning methods rely on supervised fine-tuning or predefined prompt triggers, obscuring whether and how tool use emerges purely from RL. This paper identifies and empirically validates predictable scaling relationships (the Agent RL Scaling Law) linking training progression, code-usage frequency, response length, and task accuracy.

## Input / Output

The model receives a single mathematical problem as plain text and produces an iterative multi-turn trajectory that interleaves natural-language reasoning with fenced Python code blocks. Code execution is triggered by a dynamic stop token (```python), after which the model generates code, receives stdout/stderr from a decoupled environment server, and resumes reasoning; a configurable maximum call budget (N_max) caps the number of execution cycles per trajectory. The final output is a complete reasoning trace ending with a boxed numerical answer, evaluated via greedy decoding, majority voting, and pass@k across multiple sampling temperatures.

## Method

ZeroTIR trains base LLMs (Qwen 2.5 Base 7B/32B) via outcome-based RL (PPO or Reinforce++) to spontaneously generate and execute Python code for mathematical problems, requiring no supervised tool-use trajectories. The rollout mechanism operates as a state machine driven by dynamic stop tokens: the model generates reasoning until it emits a code trigger, produces Python code, receives execution feedback from a decoupled Flask/Gunicorn network service, and resumes generation, with environment-inserted tokens masked from value-function and policy-gradient updates. Stability is maintained through group-accuracy replay buffer filtering (discarding prompt groups with >80% or <20% accuracy) and an asynchronous pipelined rollout that achieves ~4× speedup over synchronous interaction. The central empirical contribution is the demonstration that training steps, spontaneous code-execution frequency, response length, and task accuracy exhibit strong positive correlations (Spearman ρ = 0.686; log-log R² = 0.93), with code usage following a characteristic dip-then-plateau trajectory (0.142 → 0.002 → >0.98) that constitutes the Agent RL Scaling Law.

## Results

On the primary 7B comparison (Table 1), ZTRL achieves 46.7% on AIME24, 30.0% on AIME25, and 85.2% on MATH500, yielding a 54.0% average across the three benchmarks with a 90% code-usage proportion. This substantially outperforms non-tool ZeroRL baselines (SimpleRL-Zero at 39.1% avg, Eurus-2-PRIME at 39.7% avg) and the SFT-based TIR model Qwen2.5-Math-Instruct (41.6% avg). At the 32B scale (Table 2), ZTRL with Reinforce++ on DeepMath reaches 39.3% average across seven benchmarks (AIME24/25, HMMT Feb. 24/25, CMIMC, OlymEMath, MATH500), surpassing the 32B ORZ no-tool baseline (35.9% avg).

## Baselines & Comparisons

ZTRL (54.0% avg) outperforms the closest concurrent tool-integrated RL method TORL (51.8% avg) by 2.2 points, winning on AIME24 (46.7% vs 43.3%) and MATH500 (85.2% vs 82.2%) while tying on AIME25 (30.0%), despite starting from the general Qwen2.5 Base rather than the math-specialized Qwen2.5 Math Base used by TORL. Against non-tool ZeroRL baselines, ZTRL leads SimpleRL-Zero (39.1%) by 14.9 points and Eurus-2-PRIME (39.7%) by 14.3 points, demonstrating that spontaneous code execution provides a substantial advantage over pure text reasoning. ZTRL also surpasses the SFT-based TIR model Qwen2.5-Math-Instruct (41.6% avg, 95% code usage) by 12.4 points, indicating that RL-learned tool use generalizes better than supervised tool-use patterns. Compared to rStar-Math (52.6% avg, no tool), ZTRL edges ahead by 1.4 points, suggesting that even a strong self-evolved reasoning method benefits from explicit code execution on the hardest problems (AIME24: 46.7% vs 26.7%). The prompted-tool variant of Qwen2.5-Instruct (31.0% avg) performs worse than its no-tool counterpart (36.4%), highlighting that without RL-learned integration, tool access can be counterproductive.

## Relation to Prior Work

This paper sits at the intersection of ZeroRL (outcome-based RL from base models, as in DeepSeek-R1 and Open-Reasoner-Zero) and Tool-Integrated Reasoning, but deliberately departs from both SFT-based TIR (Qwen2.5-Math-TIR) and prompt-triggered tool invocation by studying purely spontaneous tool acquisition. It is concurrent with TORL, which also applies ZeroRL to code execution for math, but distinguishes itself by starting from a general base model rather than a math-specialized one and by systematically characterizing the training dynamics as a 'scaling law.' The methodological lineage draws on PPO/Reinforce++ policy gradients, GAE masking for environment tokens, and asynchronous rollout pipelines from OpenRLHF, repurposing these for an interactive code-execution setting rather than static generation.

## Why It Matters / Open Questions

The paper provides the first systematic empirical characterization of how autonomous code-execution behavior emerges during RL training, with quantitative correlations (Spearman ρ=0.686, log-log R²=0.93) that give the community a reproducible benchmark for studying agent tool acquisition. The finding that a general 7B base model outperforms a math-specialized 7B model with prompted TIR (52.3% vs 41.6% average) suggests that RL-driven spontaneous tool use may be a more scalable path than SFT on tool trajectories. Key open questions include the precise functional form of the scaling relationship, whether the dynamics generalize beyond mathematics to other tool-augmented tasks, and what happens when interaction budgets are removed entirely. The math-centric evaluation and single-seed experiments limit the generality of the claimed scaling law.
