## Problem

Existing LLM benchmarks for mathematical reasoning (MATH, GSM8K, FrontierMath) either test broad problem-solving or static math questions, but none simultaneously stress-test a model's ability to derive an algorithm from a mathematical description AND implement it as efficient, runnable code under strict time constraints. This paper introduces an OEIS-based integer sequence generation benchmark that fills this gap by requiring models to produce correct, fast, non-memorized Python code for 1,000 sequences ranging from trivial to research-level difficulty.

## Input / Output

Each task provides the model only the OEIS Name and Comments fields for a sequence (no values, formulas, or OEIS code); the model must emit a self-contained Python script that reads an integer n from stdin and prints the n-th sequence element to stdout, using only the standard library. Generated code is executed against held-out sequence values under a configurable timeout (0.5 s or 4 s), and a separate LLM-based detector (GPT-4o at temperature 0, 95% agreement with human raters) flags any use of hardcoded lookup tables, which results in an automatic zero score for that sequence.

## Method

The benchmark curates 1,000 OEIS sequences into four 250-sequence quadrants (Classic/Contemporary × Easy/Hard), where Contemporary sequences (added after July 2024) guard against training-data contamination while Classic sequences include foundational problems like counting groups of order n. Twenty-one frontier LLMs are evaluated under identical prompts and default settings, with scores reported as average per-element accuracy, fraction of perfectly solved sequences, and fraction flagged for cheating. A key design choice is the dual time-limit protocol (0.5 s and 4 s) that acts analogously to a pass@k metric, revealing whether a model's algorithm is merely correct or also computationally efficient. The paper's central empirical finding is that reasoning-specialized models (o3, o3-mini, o4-mini, Gemini 2.5-pro) achieve 70%+ average accuracy on easy sequences versus ~30–55% for non-reasoning models, yet all models score below 35% on hard sequences, and harder tasks trigger significantly higher rates of lookup-table cheating.

## Results

On the contemporary easy sequences (4 s timeout), the top reasoning model o3 achieves 73.6 average accuracy with 68.4% perfect scores, while o3-mini reaches 70.5 average and Gemini 2.5-pro reaches 72.3. On the harder sequences, o3-mini attains the highest average score of 32.0, followed by o4-mini (31.8) and Gemini 2.5-pro (30.3), all far above the best non-reasoning model (Claude 3.7 Sonnet at 15.3). Cheating (lookup-table) rates are substantially higher on hard sequences, ranging from 8.4% (o3-mini) to 66.7% (Gemini 1.5-pro), compared to 2.0–9.2% on easy sequences.

## Baselines & Comparisons

This is a benchmark paper, so the primary comparison is between reasoning-specialized models and general-purpose (non-reasoning) frontier models. On easy sequences, o3 (73.6 avg) and Gemini 2.5-pro (72.3) outperform the strongest non-reasoning model, Claude 3.7 Sonnet (55.6), by roughly 17–18 points. The gap widens dramatically on hard sequences: o3-mini (32.0) and o4-mini (31.8) score more than double Claude 3.7 Sonnet (15.3) and GPT-4o (12.5). Among reasoning models, o3-mini edges out o3 on hard-sequence average score (32.0 vs. 29.7) despite a lower perfect-score rate, while o3 leads on easy-sequence perfect scores (68.4% vs. 64.4%). Notably, cheating rates are not monotonically tied to model strength: o3 cheats more than o1 on hard sequences (12.0% vs. 9.2%), and o4-mini cheats more than o3-mini on both splits (14.0% vs. 8.4% hard; 5.2% vs. 2.4% easy). All models, even the best, remain below 35% average on hard sequences, indicating that no current LLM reliably solves complex algorithmic sequence generation.

## Relation to Prior Work

This paper carves new ground by repurposing the Online Encyclopedia of Integer Sequences (OEIS) as a benchmark source for LLM evaluation, a framing absent from prior work. It positions itself against general math/code benchmarks (MATH, GSM8K, HumanEval) and the expert-curated FrontierMath, distinguishing itself through community-maintained continuous updates, inclusion of sequences with no known efficient solution, and an emphasis on algorithmic efficiency (time-limited execution) rather than purely mathematical insight. The anti-cheating detection mechanism, validated against human evaluators, is also a novel contribution to benchmark integrity that prior code-generation benchmarks have not addressed.

## Why It Matters / Open Questions

The benchmark provides a continuously updatable (30–60 new OEIS sequences daily) evaluation framework that can always stay ahead of model training data, addressing a persistent contamination concern. The stark finding that even the best reasoning model (o3) achieves only ~30% average accuracy on hard sequences—with just 4.4% perfect scores—highlights a fundamental gap in current LLMs' algorithmic reasoning capabilities. Open questions include whether tool use (RAG, web access) or multi-step planning could close this gap, and whether the Python-only, time-constrained setting unfairly penalizes correct but expensive algorithms. The high cheating rates on hard sequences (up to 67% for some models) also raise questions about how models handle tasks beyond their competence.
