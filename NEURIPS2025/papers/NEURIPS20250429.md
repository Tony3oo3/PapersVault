## Problem

Despite LLMs claiming context windows of 128K–1M tokens, existing long-context benchmarks rely on synthetic retrieval tasks or shallow QA that fail to capture the multi-hop, cross-document reasoning required in real-world applications like legal analysis, financial reporting, and code comprehension. This paper asks whether current models can genuinely resolve long-dependency tasks—where evidence is scattered across hundreds of thousands of tokens and holistic document understanding is required—rather than merely retrieving a single needle from a haystack.

## Input / Output

Each instance pairs a real-world long text (16K–2M tokens) with a domain-specific question. Inputs span four domains: US legal case documents with masked citations, SEC 10-K annual reports (up to 200 pages per company), sequential game trajectory logs from CS2 and Crafter, and concatenated Python code repositories. Outputs are closed-form: single-letter multiple-choice selections for most tasks, numerical values scored with a 5% relative-error tolerance for finance metrics, year-pair strings for trend analysis, and file-path lists scored by Jaccard similarity for version control. The benchmark contains 1,934 QA instances across 10 task types, all auto-labeled to avoid annotation noise.

## Method

LooGLE v2 is built on an automatic data collection and annotation pipeline that sources real-world documents from CourtListener/Westlaw (law), SEC EDGAR (finance), CS2 demo files and Crafter agent trajectories (game), and GitHub repositories (code), all filtered to post-2024 releases to minimize data contamination. The pipeline defines 10 domain-specific long-dependency tasks—Legal Article Extraction, Legal Case Retrieval, Metric Calculation, Trend Analysis, Cross-Company Comparison, Environment Understanding, User Behavior Analysis, Rule Understanding, Call Graph Analysis, and Version Control—each requiring the model to integrate evidence dispersed across the full context rather than relying on local retrieval. For code, call graphs are constructed via code2flow and depth-first search to generate multi-hop call-chain questions; for finance, SEC API tools extract base metrics and template-based sampling instantiates calculation and comparison questions; for games, structured event logs are converted to natural-language narratives via predefined templates, and questions are auto-generated by counting event frequencies or matching state-change vectors. All tasks are formulated as closed-form questions (multiple-choice or exact-match) to enable robust, reproducible evaluation without LLM-as-judge bias, and the pipeline is designed to be periodically refreshed with new data to maintain scalability and avoid contamination.

## Results

On LooGLE v2, the best-performing model GPT-4.1 (1M context) achieves only 59.20% overall accuracy across 10 domain-specific long-dependency tasks, revealing substantial room for improvement. Among API-based models, GPT-o3-mini (200K) scores 43.23%, DeepSeek-R1 (64K) scores 41.85%, and DeepSeek-V3 (64K) scores 36.71%. Local models lag significantly: Qwen2.5-7B-Instruct-1M reaches 28.97%, Llama-3.1-8B-Instruct 24.16%, GLM-4-9B-Chat 25.81%, while the weakest model Yarn-Mistral-7b-128k scores only 3.26%. Notably, GPT-4.1's 1M-token window does not guarantee superiority over GPT-o3-mini's 200K window on Call Graph Analysis (33.24 vs. 42.29) and Trend Analysis (48.00 vs. 50.00), indicating that long-span memory alone is insufficient for multi-hop reasoning.

## Baselines & Comparisons

GPT-4.1 dominates all other models by a wide margin (59.20% vs. 43.23% for the second-best GPT-o3-mini), but its advantage narrows on specific tasks: GPT-o3-mini outperforms it on Call Graph Analysis (42.29 vs. 33.24) and Trend Analysis (50.00 vs. 48.00), suggesting that a smaller 200K window with stronger reasoning can beat a 1M window on multi-hop tasks. Among local models, Qwen2.5-7B-Instruct-1M leads (28.97%) primarily due to strong Finance Metric Calculation (84.00%), while Llama-3.1-8B-Instruct (24.16%) and GLM-4-9B-Chat (25.81%) are competitive on Law tasks. Domain-specific models fail to outperform general-purpose ones: CodeLlama-7B (18.88% avg on Code) and Qwen2.5-Coder-7B (27.77%) both trail Llama-3.1-8B (26.26%), and Fin-R1 (5.75% avg on Finance) is catastrophically worse than Qwen2.5-7B (42.25%). Retrieval-augmented generation (RAG) consistently degrades performance compared to full-context evaluation for both Llama-3.1-8B and GLM-4-9B, with top-4 retrieval dropping Llama from 26.25% to 12.26%. On Legal tasks specifically, classical BM25 (41.94% overall) and TF-IDF (36.42%) outperform all local LLMs, though GPT-4.1 (76.60%) still substantially exceeds both retrieval baselines.

## Relation to Prior Work

This paper directly extends LooGLE v1 (Li et al., 2024), which first formalized long-dependency tasks as a distinct challenge from short-dependency retrieval (e.g., Needle-in-a-Haystack). While prior long-context benchmarks (RULER, ∞Bench, LongBench v2, Loong) focus on synthetic or stitched documents and retrieval-centric tasks, LooGLE v2 departs by grounding evaluation in real-world domain-specific data (legal cases, SEC annual reports, game trajectories, code repositories) with automatically curated, closed-form questions. It also differentiates itself from LooGLE v1 by introducing an automatic data curation pipeline for scalability and contamination avoidance, and by covering substantially longer contexts (up to 2M tokens vs. ~20K in v1).

## Why It Matters / Open Questions

The benchmark reveals a significant gap between claimed context window sizes and effective long-dependency reasoning: even GPT-4.1 (1M window) scores only 59.2%, and underperforms the smaller-window GPT-o3-mini on multi-hop tasks, suggesting that long-span memory alone is insufficient. The finding that retrieval-augmented generation consistently degrades performance on long-dependency tasks challenges the common assumption that RAG is a universal remedy for long-context challenges. Limitations include coverage of only four domains and uneven context-length distributions across tasks, leaving open questions about whether the observed gaps persist in medical, scientific, or policy-analysis settings and whether architectural innovations (sparse attention, test-time training) can close the effective-reasoning-window gap.
