## Problem

Fine-tuning large foundation models incurs substantially more memory than inference due to optimizer states, intermediate activations, and the model parameters themselves, forcing users with fixed hardware to either sacrifice model capability or forgo task-specific adaptation entirely. Prior approaches that reduce parameter memory (e.g., layer dropping, row pruning) still require full-model training infrastructure and impose rigid constraints on which weights can be updated, making them impractical for individual users.

## Input / Output

The method takes a pre-trained foundation model (e.g., InternVL2.5-8B/26B/38B, LLaMA2-13B, FLUX.1-dev) plus a small downstream calibration set (default 64 samples) and a downstream training dataset. It outputs a corrected LoRA module that is merged into the original full-precision model for inference, so the final deployed model is the original architecture with no architectural changes. For VQA tasks the input is an image paired with a text question producing a text answer; for math reasoning it is a text problem producing a numeric answer; for diffusion personalization it is a text prompt producing a generated image.

## Method

EMLoC is a three-stage pipeline that closes the memory gap between inference and fine-tuning. Stage 1 constructs a downstream-aware lightweight emulator by applying activation-aware SVD (SVD-LLM) to every linear weight matrix, replacing W with a factored low-rank approximation W^E = W_U W_V calibrated on a small subset of downstream data, which reduces parameter memory while preserving task-relevant knowledge. Stage 2 fine-tunes this emulator with standard LoRA modules using any existing training pipeline, since the emulator retains the same input/output dimensions and positional structure as the original model. Stage 3 applies a novel LoRA correction algorithm: it reparameterizes each LoRA module via SVD so that W_A' has orthonormal columns, computes the misalignment Δ = W_A'^T(W − W^E) on the LoRA's active subspace, and subtracts a clamped Δ from W_B' to produce a corrected LoRA that, when merged into the original model, exactly compensates for the training-inference base-model discrepancy.

## Results

On seven VQA benchmarks using InternVL2.5-8B, EMLoC at 50% compression achieves 84.6/92.3/69.9/78.8 accuracy on standard datasets (ChartQA/DocVQA/InfoVQA/TextVQA), nearly matching the full-model fine-tuning upper bound of 84.5/92.2/69.8/79.6, while substantially outperforming all memory-constrained baselines on domain-specific tasks (e.g., 85.2 on WebSRC vs. 76.1 for Offsite and 76.4 for UPop). At the tighter 25% budget, EMLoC still reaches 84.2/92.3/70.0/79.0 on standard benchmarks. For large models, EMLoC fine-tunes a 38B model within 24 GB GPU memory (vs. 95 GB for direct LoRA), improving WC-VQA from 53.6 (zero-shot) to 56.8, and on GSM8K achieves 29.8 accuracy with LLaMA-2-13B, outperforming LORAM (27.2).

## Baselines & Comparisons

Against Offsite-tuning [43], EMLoC wins decisively on domain-specific VQA: at 50% compression, WebSRC improves from 76.1 to 85.2 (+9.1) and WC-VQA from 45.9 to 48.8 (+2.9), while standard benchmarks remain within 0.5–1.9 points. Against UPop [35], the gap is even larger on WC-VQA (48.8 vs. 42.1 at 50%; 46.2 vs. 44.1 at 25%), reflecting UPop's row-pruning constraint that limits which weights can be adapted. Against LORAM [49] on NLP tasks, EMLoC achieves 29.8 on GSM8K versus 27.2 (LORAM-RAND) and 24.6 (LORAM-STRU), and matches on MATHQA (33.9 vs. 33.8), while requiring no continual pretraining (0.3 GPU-hours vs. 214–230). Against QLoRA [9] on 26B/38B models, EMLoC uses 18.6/20.1 GB versus 38.1/43.4 GB and achieves substantially higher WC-VQA accuracy (56.8/52.6 vs. 39.0/43.6), since quantization degrades inference quality. Against standard LoRA [14], EMLoC reduces fine-tuning memory from 72.9/94.8 GB to 18.6/20.1 GB for 26B/38B models while maintaining competitive accuracy. Against the Houlsby Adapter [13], EMLoC with LoRA correction achieves 51.6/80.8/46.2 on PMC-VQA/WebSRC/WC-VQA versus 51.2/79.0/44.5, confirming the correction step's contribution.

## Relation to Prior Work

EMLoC builds directly on LoRA for parameter-efficient fine-tuning and on SVD-LLM's activation-aware SVD for model compression, but departs from both by repurposing SVD not as a final compression step but as a training-time emulator construction mechanism. It addresses the same 'train small, infer large' problem as LORAM and Offsite-Tuning, but eliminates their reliance on continual pre-training or full-model training infrastructure, making the pipeline executable by individual users. The key conceptual departure is the LoRA correction algorithm, which explicitly compensates for the base-model mismatch between the compressed emulator used during training and the full model used at inference—a misalignment that prior train-small/infer-large methods either ignore or handle implicitly.

## Why It Matters / Open Questions

By closing the memory gap between inference and fine-tuning entirely, EMLoC makes domain adaptation of large multimodal and language models accessible to users with consumer-grade hardware (e.g., 38B model on a 24GB GPU), broadening who can perform model customization. A key limitation acknowledged by the authors is that SVD-based emulator construction preserves inference-time behavior rather than fine-tuning dynamics (gradient directions, parameter update trajectories), leaving a performance gap versus direct LoRA on the full model. An open question is whether emulator construction can be explicitly tailored to preserve training dynamics, and whether the LoRA correction generalizes beyond the linear structure of LoRA to other PEFT methods like Houlsby adapters.
