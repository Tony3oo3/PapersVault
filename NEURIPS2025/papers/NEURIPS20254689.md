## Problem

No existing 3D scene synthesis paradigm simultaneously achieves visual realism, physical plausibility, and fine-grained instruction controllability: data-driven models are confined to pre-trained scene categories, LLM-based methods suffer from poor spatial reasoning and physical inconsistencies, and rule-based systems lack extensibility. Moreover, prior multi-step pipelines that compose modular synthesis components remain static, with fixed prompts and hard-coded tool invocation logic that prevent adaptive, feedback-driven refinement.

## Input / Output

The system takes a natural-language user query (e.g., 'Design me a kitchen') as the sole user-facing input and produces a fully textured 3D scene with per-object 6D poses (location, rotation, scale), semantic labels, and inter-object relational constraints (e.g., chair faces desk, vase on table). Internally, each scene state is dual-represented as a 3D bounding-box layout with relational metadata and a 2D top-down Blender rendering annotated with coordinate axes, object labels, and front-direction arrows, which together feed the MLLM-based reflection module. The pipeline runs up to 10 iterative refinement steps, with early termination when reflection scores indicate sufficient quality.

## Method

SCENEWEAVER is a reflective agentic framework built on the OpenManus platform with a ReAct-style reason-act-reflect loop. It comprises (1) a standardized tool interface that abstracts diverse synthesis methods into modular tools categorized by granularity—Scene Initializers (data-driven generative models, real-to-sim, LLM-based), Microscene Implementers (LLM-based and 2D-guided), and Detail Refiners (relational constraint enforcement, 6D pose correction, object removal)—each described by a structured tool card specifying applicable scenarios, constraints, and parameters; and (2) a self-reflective planner that, at each iteration, receives MLLM-generated reflection feedback (physical metrics like collision counts and boundary violations, plus perceptual scores for realism, functionality, layout, and completeness with natural-language justifications), identifies the most critical deficiency, ranks candidate tools by dynamically adjusted confidence, and invokes a single tool with generated instructions. A physics-aware executor built on Infinigen and Blender then retrieves 3D meshes from Objaverse/3D-FUTURE/Infinigen asset pools, enforces relational constraints, and performs collision-resolution optimization before the next reflection cycle. The key design insight is that closed-loop, feedback-driven tool selection—rather than a fixed pipeline—enables the agent to correct semantic errors, enrich missing details, and fix physical implausibilities adaptively across iterations.

## Results

On open-vocabulary scene generation (average over 8 room types), SCENEWEAVER achieves 36.5 objects with zero out-of-boundary violations and zero collisions, while scoring 8.8/10 on realism, 9.4/10 on functionality, 7.7/10 on layout, and 8.0/10 on completeness. On common room types (bedroom), it reaches 9.2 realism, 9.8 functionality, 8.4 layout, and 9.4 completeness with 14.0 objects and zero physical errors. In the human study, SCENEWEAVER is preferred over baselines in 85–94% of pairwise comparisons and scores 8.80–8.98/10 across all visual/semantic metrics versus 5.83–7.45 for baselines.

## Baselines & Comparisons

SCENEWEAVER outperforms all six baselines on visual and semantic metrics across both common and open-vocabulary settings. Against data-driven methods (ATISS, DiffuScene, PhyScene), it achieves substantially higher realism (8.8 vs. 5.2–7.4), functionality (9.4 vs. 5.3–7.2), and completeness (8.0 vs. 3.3–5.5) while maintaining zero physical errors, whereas ATISS and DiffuScene produce 0.1–1.3 out-of-boundary objects and 0.3–1.2 collisions. Against LLM-based open-vocabulary methods, the gap is most pronounced: LayoutGPT scores only 6.0 realism and 3.7 completeness on average, while Holodeck achieves 7.7 realism but suffers 3.9 collisions on average (38.5 in the bedroom setting). I-Design is the closest competitor on physical metrics (0.1 collisions) but trails SCENEWEAVER by 1.8 points on realism and 3.8 on completeness. The one metric where a baseline exceeds SCENEWEAVER is object count in the bedroom (Holodeck: 32.2 vs. 14.0), which the authors attribute to Holodeck's inclusion of randomly placed objects lacking rational placement.

## Relation to Prior Work

SCENEWEAVER builds on the ReAct-style reasoning-acting paradigm (Yao et al., 2022) and the OpenManus agentic platform (Liang et al., 2025) to orchestrate 3D scene synthesis, while grounding its physics-aware executor in Infinigen's procedural generation pipeline (Raistrick et al., CVPR 2024). Conceptually, it departs from prior LLM-based scene synthesis pipelines (Holodeck, LayoutGPT, I-Design) that employ static, hard-coded module invocation sequences, by introducing a closed-loop reason-act-reflect design where an MLLM planner dynamically selects from a standardized, extensible tool interface based on self-evaluation feedback. The key architectural contribution is the abstraction of heterogeneous synthesis methods—data-driven generative models, rule-based systems, 2D-guided reconstruction, and LLM-based layout—into interchangeable 'tool cards' with uniform input/output contracts, enabling the agent to compose them adaptively rather than following a fixed pipeline.

## Why It Matters / Open Questions

The paper addresses a genuine gap: no single scene synthesis paradigm simultaneously achieves visual realism, physical plausibility, and instruction-level controllability, and SCENEWEAVER demonstrates that a reflective agentic loop over diverse tools can close this gap with zero physical violations across all tested settings. The extensible tool interface offers a practical design pattern for integrating new synthesis methods without re-architecting the system, which is valuable as the embodied AI community grows. However, the 64-minute average generation time, $0.50 API cost per scene, and single-room scope limit immediate deployment; open questions include whether the LLM-as-evaluator introduces systematic bias (partially addressed via human-LLM alignment analysis), how the framework scales to multi-room or outdoor scenes, and whether the iterative refinement loop can be accelerated without sacrificing quality.
