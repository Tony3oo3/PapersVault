## Problem

In retrieval-augmented generation and similar multi-segment LLM applications, the same documents are repeatedly re-encoded for every query that retrieves them, incurring redundant prefilling cost. Naively precomputing each document's KV cache independently and concatenating at inference causes up to 35% relative accuracy drops due to positional encoding mismatches and the absence of cross-document attention that standard LLM training assumes. The paper asks how to reuse independently computed KV caches while preserving the cross-segment dependencies the model was trained on.

## Input / Output

At inference, the method loads precomputed KV caches (stored without RoPE rotations) for a set of retrieved documents from CPU memory, applies global positional re-encoding, appends a small number of link tokens per document, and performs a single forward pass on those tokens before generating the response. The KV caches are context-free (each document encoded in isolation), so the same cache can be shared across any number of queries. A 1,000-token document's cache for Llama-3.1-8B occupies roughly 131 MB, motivating the paper's exploration of compression (LLMLINGUA, modified ANLLMs) to reduce storage and loading overhead.

## Method

KVLINK introduces two mechanisms to bridge independently encoded segments. First, KV cache positional re-encoding decouples RoPE from the stored cache: keys and values are saved as W_k·x_i and W_v·x_i without the rotation matrix R_i, and the correct global RoPE is applied at inference based on each token's actual position in the concatenated sequence. Second, KVLINK appends K trainable link tokens (K=5 by default) after each document's cached tokens; a customized attention mask lets each link token attend to all preceding tokens across all documents plus tokens within its own document, thereby restoring cross-segment self-attention with only a few extra forward-pass tokens. The model is fine-tuned end-to-end on a mixture of separately-encoded QA, multi-turn conversation, summarization, and standard SFT data so that the link tokens and the backbone jointly learn to integrate disjointed contexts. The approach is further combined with KV cache compression (token-dropping via LLMLINGUA or chunked anchor-token compression via a modified ANLLMs scheme) to reduce storage while maintaining accuracy.

## Results

On retrieval-augmented QA with separately encoded KV caches, KVLINK5 (5 link tokens) achieves 64.4% on NaturalQuestions, 71.2% on 2WikiMQA, 73.7% on TriviaQA, 69.5% on HotpotQA, and 35.8% on MuSiQue with Llama-3.2-3B, surpassing the best baseline (BlockAttention) by 5.6% on NQ and 5.2% on HotpotQA. Across all three model scales (1B, 3B, 8B), KVLINK consistently outperforms all baselines, with the largest gains on multi-hop QA (MuSiQue: +7.5% over BlockAttention at 3B). In terms of efficiency, reusing precomputed KV caches reduces time-to-first-token by 85–96% compared to standard full-context encoding, with the gap widening as context length increases from 1,000 to 5,000 tokens.

## Baselines & Comparisons

KVLINK outperforms all four baselines across every QA and summarization dataset and all three model scales. Against PromptCache, the gains are the most dramatic: on Llama-3.2-3B, KVLINK5 achieves 64.4% on NQ versus PromptCache's 24.7% (+39.7 points), and 35.8% on MuSiQue versus 2.2% (+33.6 points), reflecting PromptCache's inability to handle positional mismatches and missing cross-document attention. CacheBlend, which recomputes 18% of token KV states, also trails substantially (e.g., 42.6% vs. 64.4% on NQ, 32.7% vs. 69.5% on HotpotQA at 3B). The closest competitor is BlockAttention, which fine-tunes the model on separately encoded documents; KVLINK5 still leads by 5.6% on NQ, 5.2% on HotpotQA, and 7.5% on MuSiQue at 3B, with the gap narrowing at 8B (1.7% on NQ, 1.6% on HotpotQA) but remaining consistent. In the appendix comparison against TurboRAG (Table 6), KVLINK5 also wins on the 3B model (62.9% vs. 60.5% average across QA datasets). Notably, KVLINK5 approaches the fine-tuned upper bound (which uses standard full-context encoding) within 1–5 points on most tasks while delivering up to 96% TTFT reduction.

## Relation to Prior Work

KVLINK builds directly on the KV cache reuse line of work initiated by PROMPTCACHE, CACHEBLEND, and BLOCKATTENTION, all of which precompute per-document KV states to avoid redundant encoding in RAG pipelines. It shares the positional re-encoding idea with CACHEBLEND and BLOCKATTENTION (decoupling RoPE rotations from stored key states), but departs from them by introducing trainable link tokens whose KV representations are computed at inference time to restore cross-document self-attention. Unlike TurboRAG, which uses static boundary tokens precomputed with the document, KVLINK's link tokens are dynamically computed and attend to all preceding segments, creating a hierarchical information bridge that prior methods lack.

## Why It Matters / Open Questions

The 96% time-to-first-token reduction makes KV cache reuse practically viable for high-throughput RAG deployments where many queries share overlapping documents, and the method composes cleanly with KV cache compression (LLMLINGUA, modified ANLLMS) to address the substantial storage overhead. However, open questions remain: the accuracy gap to the full-encoding upper bound (2–5 points) persists, the variable-size KV caches complicate large-scale storage in vector databases, and the optimal training data mixture for generalizing cache-reuse capability is not yet resolved. The approach also requires fine-tuning the backbone model, limiting its plug-and-play applicability to off-the-shelf LLMs.
