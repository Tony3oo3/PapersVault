## Problem

No single code LLM dominates all optimization categories, yet existing multi-agent frameworks either assign fixed roles or aggregate independent solutions without a mechanism for agents to learn from each other's successes and failures. The paper asks how a team of LLM agents can collaboratively solve a coding problem and improve iteratively without knowing their complementary strengths a priori.
![Teaser figure](../imgs/NEURIPS20253642/cropped_page1_idx0.webp)

## Input / Output

For code optimization, the input is a correct C++ source code snippet (from ParEval or PolyBench) plus up to k selected lessons from a shared bank; the output is a faster C++ rewrite whose speedup is measured as the geometric mean runtime ratio against the original. For code generation, the input is a Python function signature with docstring plus selected lessons, and the output is a function implementation scored by pass@1 on test cases. Lessons themselves are concise 1–2 sentence explanations solicited by prompting an agent with the original code, the modified code, and the observed outcome (speedup, slowdown, functional error, or compilation error).

## Method

LessonL is an iterative multi-agent framework built around a solicitation–banking–selection loop. In each round, every agent generates a solution and a lesson explaining why it is good or bad; lessons are deposited into a shared bank. For the next round, k lessons are selected by splitting the budget: the top ⌈k/2⌉ by (speedup × effectiveness factor) and the top ⌊k/2⌋ by cosine similarity to the original code (via CodeBERT embeddings). An effectiveness-adjustment step dynamically rescales each lesson's score based on whether agents that applied it actually achieved the expected speedup, preventing stale high-speedup lessons from dominating selection. Agents require no pre-assigned roles, and because lessons are far shorter than full code, inter-agent communication is economical. The framework is general: for code generation, lesson solicitation triggers only on functional incorrectness and selection uses test-case pass rate instead of speedup.

## Results

On ParEval (the primary code optimization benchmark), LessonL achieves a geometric mean speedup of 2.16× (serial) and 3.46× (OpenMP) with 91% and 86% correctness, outperforming GPT-4o (1.72×/2.93×) and closely matching OpenAI o3 (2.21×/3.55×). On PolyBench, LessonL reaches 1.32× (serial) and 3.40× (OpenMP) speedup, again leading all non-reasoning baselines. For code generation, LessonL achieves the best pass@1 on 3 of 4 benchmarks (HumanEval 91.5%, HumanEval+ 87.8%, MBPP 89.9%), with MoA slightly ahead on MBPP+ (77.0% vs. 76.5%).

## Baselines & Comparisons

LessonL (using three small open-source models: Deepseek7B, Qwen7B, Qwen14B) outperforms all single-agent baselines: Qwen14B (1.60×→2.16× on ParEval serial), GPT-4o mini (1.57×→2.16×), and GPT-4o (1.72×→2.16×), demonstrating that a team of small models with shared lessons surpasses a much larger single model. Against reasoning models, LessonL is competitive with OpenAI o3 (2.16× vs. 2.21× serial; 3.46× vs. 3.55× OpenMP) but clearly beats DeepseekR1-14B (1.51×→2.16×). Among prompting/reflection methods, LessonL beats CoT (1.57×→2.16×) and Reflexion (1.88×→2.16×) on ParEval serial. Against multi-agent baselines, LessonL outperforms MapCoder (1.85×→2.16× serial; 3.43×→3.46× OpenMP) and MoA (1.76×→2.16× serial; 2.77×→3.46× OpenMP), with the gap widening in OpenMP mode. On code generation, LessonL edges out MoA on HumanEval (91.5% vs. 90.9%) and HumanEval+ (87.8% vs. 87.2%) but trails slightly on MBPP+ (76.5% vs. 77.0%).

## Relation to Prior Work

This paper departs from two dominant multi-agent LLM paradigms: role-based frameworks (MetaGPT, MapCoder, ChatDev) that assign fixed roles to agents, and solution-aggregation frameworks (MoA, LLM-Debate, LLM-Blender) that combine independently generated outputs. Instead, LessonL introduces an explicit knowledge-transfer mechanism where agents produce concise 'lessons' (optimization strategies, pitfall warnings, performance feedback) that are banked, selected by speedup and semantic relevance, and fed back to all agents in subsequent rounds. For code optimization specifically, it differs from retrieval-based approaches like SBLLM (which pulls from an external dataset) and PIE (which uses performance-conditioning and self-play) by generating lessons endogenously from the agents' own trial-and-error, requiring no external code corpus. The effectiveness-adjustment mechanism (dynamically reweighting lessons based on whether they actually help when applied) is a technical detail not present in prior multi-agent or self-reflection work like Reflexion.

## Why It Matters / Open Questions

The practical takeaway is that a team of 7B–14B open-source models, collaborating through shared lessons, achieves competitive or superior speedups to GPT-4o at a fraction of the cost, making high-quality code optimization accessible without proprietary API access. The interpretability of lessons (as opposed to opaque solution aggregation) has educational value and could seed optimization knowledge bases. Key limitations constrain broader impact: the framework is validated only on function-level C++/Python snippets (not repository-level tasks like SWE-bench), lesson solicitation adds latency to time-to-first-token, and the best reasoning model (OpenAI o3) still outperforms LessonL on several benchmarks. Open questions include whether the lesson mechanism transfers to longer-horizon or multi-file optimization, and whether agents can autonomously decide which lessons to select rather than relying on the fixed speedup/relevance heuristic.
