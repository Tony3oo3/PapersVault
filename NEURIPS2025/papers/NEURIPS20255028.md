## Problem

Training MLLM-based mobile GUI agents faces two coupled challenges: verifying whether a trajectory actually completes a task is hard because success depends on long historical context rather than a single final answer, and high-quality training trajectories are not scalable because they rely on expensive human annotation. Existing verification approaches using proprietary LLM judges fail to provide reliable step-level validation, and manually created datasets lack the volume and diversity needed for complex multi-step tasks.

## Input / Output

The agent model takes a task instruction, the current screenshot, and an interleaved history of recent screenshots and actions (limited to 5 most recent screenshots with earlier steps summarized as natural-language descriptions) and outputs one of 8 action types (open, click, swipe, long_press, type, system_button, wait, terminate) parameterized by either absolute pixel coordinates or Set-of-Mark element indices. The reward model (UI-Genie-RM) takes the same context plus a candidate action and outputs a single binary token (positive or negative) that serves simultaneously as an action-level reward and, when the candidate is a 'terminate' action, as a task-level outcome reward. Input images are capped at 602,112 pixels.

## Method

UI-Genie-RM is a Qwen2.5-VL-7B-based reward model with an image-text interleaved architecture that unifies step-level and task-level rewards by treating 'task completion' as a special action in the action space, trained via next-token prediction with dedicated positive/negative tokens. Training data (517k samples) is constructed without human annotation through three complementary strategies: rule-based verification of agent predictions against ground truth, controlled trajectory corruption (truncation, cross-task substitution, redundant continuation) for negative outcome samples, and hard negative mining using an LLM to convert UI element descriptions into plausible-but-wrong actions. The self-improvement pipeline operates in a dynamic Android emulator: at each step the agent generates 10 candidate actions, UI-Genie-RM scores them, and a beam search retains the top-5 partial trajectories; successful completions are added to the agent's training set while failed trajectories yield step-level labels via potential-based continuation rollouts (5 rollouts per intermediate step). Both models are fine-tuned iteratively over three rounds with progressively harder tasks (from source-data instructions to LLM-generated novel tasks to manually crafted 10+ step scenarios), creating a positive feedback loop where a better agent produces more diverse trajectories and a better reward model provides more precise exploration guidance.

## Results

On the AndroidControl benchmark, UI-Genie-Agent achieves 94.8% and 77.0% success rate on low-level and high-level tasks respectively at 72B scale, surpassing the previous SOTA UI-TARS-72B (91.3%/74.7%) by 3.5% and 2.3%. On the dynamic AndroidLab benchmark, the 72B model reaches 41.2% success rate, outperforming GPT-4o (31.2%) and all open-source baselines. On the A3 benchmark, UI-Genie-Agent-7B achieves 20.4% function-based success rate and 51.4% Essential State Achievement Rate, exceeding UI-TARS-7B by 3.5% and 4.9% respectively. The reward model UI-Genie-RM attains 79.6% F1 on step-level and 82.1% F1 on outcome-level evaluation, outperforming Gemini-2.5-pro (72.9%/74.3%) by 6.7% and 7.8%.

## Baselines & Comparisons

UI-Genie-Agent consistently outperforms all compared baselines across every benchmark and model size. Against UI-TARS (the strongest prior open-source GUI agent), UI-Genie wins by 1.7–3.5% SR on AndroidControl, 16.6–19.1% SR on AndroidLab (38.7% vs. 22.1% at 7B-ft), 3.5% Func SR on A3, and 3.2–14.4% on AndroidWorld. Compared to Qwen2.5-VL base models (the shared backbone), the self-improvement pipeline yields gains of 3.4–7.1% SR on AndroidControl-High and 13.8–17.3% on AndroidLab. InfiGUI-R1 (3B) and OS-Atlas (7B) are surpassed by 1.7–9.1% SR on AndroidControl, while SeeClick (9.6B) trails by 19.3% on AndroidControl-High. On the reward model evaluation, UI-Genie-RM beats Gemini-2.5-pro by 6.7% F1 (step) and 7.8% F1 (outcome), and outperforms Qwen2.5-VL-72B by 13.4% and 14.5% respectively, with the gap widening on hard tasks (>10 steps) where UI-Genie-RM maintains 68.7%/70.5% F1 while baselines drop to 46–56%.

## Relation to Prior Work

This paper extends the process-reward-modeling paradigm from math reasoning (Math-Shepherd's potential-based labeling via continuation rollouts) and generative verifier formulations (next-token prediction with special tokens) into the mobile GUI agent domain, where the unique challenge is evaluating actions conditioned on long image-text interleaved interaction histories. It departs from prior GUI agent work (UI-TARS, OS-Atlas, OS-Genesis) that relies on human-annotated trajectories or proprietary LLMs (GPT-4o) for trajectory verification, instead training a dedicated 7B reward model from scratch on a purpose-built 517k-sample dataset. The self-improvement loop—where the agent and reward model co-evolve through reward-guided beam search in a live Android emulator—repurposes ideas from AlphaMath-style process supervision and iterative data expansion, but applies them to the fundamentally different setting of stateful, multi-step GUI interaction where invalid actions leave the environment unchanged.

## Why It Matters / Open Questions

The paper establishes the first large-scale, reward-specific dataset for GUI agents and demonstrates that high-quality synthetic trajectories can be generated entirely without manual annotation, addressing a key scalability bottleneck in the field. The self-improvement framework provides a practical recipe for progressively tackling harder GUI tasks, though the authors acknowledge the reward model can still produce suboptimal signals and cannot guarantee fully correct trajectories across all tasks. Open questions include whether the approach generalizes beyond Android to desktop or cross-platform GUIs, whether more than three self-improvement rounds yield diminishing returns, and whether the 5-screenshot context window remains sufficient for very long-horizon tasks (>20 steps). The released datasets and open-source framework lower the barrier for subsequent work on GUI agent training.
