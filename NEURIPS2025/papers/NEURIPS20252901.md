## Problem

Existing speculative decoding systems suffer from a fundamental mismatch: dynamic tree drafting adjusts operator shapes per decoding step, which breaks the static dataflow graphs required by compiler-based runtimes for graph fusion, kernel tuning, and memory planning. Additionally, prior work optimizes average accepted length (AAL) under the assumption that more accepted tokens linearly reduce wall-clock time, ignoring non-uniform verification costs that cause diminishing or even negative returns at higher verification counts. No existing framework simultaneously delivers high AAL and low per-step runtime latency.

## Input / Output

At compile time, the system consumes a draft model, a verifier model, and a small in-domain calibration dataset to train a lightweight depth predictor and generate a hardware-specific execution schedule via profile-guided search. At runtime, it takes a text prompt and produces generated text tokens, with the TokenTree abstraction managing KV cache tensors, attention masks, and leaf positions internally. The system is fully model-agnostic, requiring no source-level modifications to the original networks, and operates on the TorchInductor compiler backend.

## Method

Yggdrasil co-designs three components: (1) a latency-aware speedup objective (Eq. 3) that jointly considers draft width, draft depth, and verification count to minimize real wall-clock latency rather than proxy AAL; (2) an Equal-Growth Tree (EGT) drafting algorithm that grows exactly W_draft leaves per step at context-selected positions, ensuring static operator shapes for CUDA Graph capture while a lightweight MLP depth predictor and greedy width selection provide context adaptivity, followed by a bottom-up dynamic-programming prune to select the optimal verification subtree; and (3) a stage-based scheduling runtime that speculatively breaks data dependencies via ahead-of-time tail and head drafting to overlap CPU management with GPU inference, then searches a small offline profile-guided space for the optimal stage-overlap execution plan per EGT configuration.

## Results

Yggdrasil achieves an average per-token latency speedup of 3.98× over SpecInfer on A100 GPUs and 2.76× on A40 GPUs, using Llama-2-7B/13B as verifiers with Llama-68M/160M drafters on C4, Wikipedia, and CNN/DailyMail. The optimization breakdown attributes 2.775× to graph compilation (TorchInductor), 1.21× to stage-based scheduling, 1.07× to verification-width pruning, and 1.10× to the draft-depth predictor. Replacing the AAL proxy with the latency-aware speedup objective (Eq. 3) yields an additional 8% improvement across all drafter–verifier configurations.

## Baselines & Comparisons

Against SpecInfer (the weakest baseline due to uncompiled GPU execution and serving overhead), Yggdrasil delivers 3.98× speedup on A100 and 2.76× on A40. Sequoia, the strongest tree-based baseline, achieves 2.45× over SpecInfer by statically adapting its tree to the dataset, but Yggdrasil's context-aware EGT pushes this to 3.37× and further outperforms Sequoia by an average of 1.49× across sampling temperatures (Fig. 15). vLLM-Spec, which leverages TorchInductor for compiled execution but restricts itself to static sequence drafting, reaches 2.66× over SpecInfer; Yggdrasil surpasses it by combining compilation with dynamic tree speculation. The key differentiator is that Yggdrasil is the only system that simultaneously supports dynamic (context-aware) tree drafting and full graph compilation for both the drafter and verifier, a combination no prior baseline achieves (Table 1).

## Relation to Prior Work

Yggdrasil sits at the intersection of two research threads: tree-based speculative decoding (SpecInfer, Sequoia, DISCO) and compiler-driven LLM inference (TorchInductor, CUDA Graphs, TRT-LLM). Prior work forces a choice between dynamic tree structures that maximize AAL but break static graph compilation, and fixed shapes that enable compilation but cap speculation quality. Yggdrasil departs from both by introducing the Equal-Growth Tree, which preserves static operator shapes for the compiler while still adapting width and depth per decoding context, and by replacing AAL maximization with a hardware-profiled latency objective that accounts for non-uniform verification costs.

## Why It Matters / Open Questions

The paper demonstrates that the commonly used AAL proxy can mislead system design—optimizing AAL in isolation yields diminishing or negative returns once verification latency grows—making the latency-aware objective a practically important correction for speculative decoding practitioners. The ablation showing that graph compilation (2.775×) contributes more to end-to-end speedup than the algorithmic innovations is a useful reminder that system-level support is the bottleneck, not just the drafting strategy. A key limitation is that all results assume a single-request, latency-optimal setting; extending the framework to batched, throughput-oriented serving where speculative decoding must be co-scheduled with continuous batching remains an open problem the authors explicitly flag.
