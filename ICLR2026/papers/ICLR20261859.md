## Problem

Task vectors (parameter deltas from fine-tuning) capture how a model adapts to a task, but naively adding a source task vector to a differently pre-trained target model fails because the two parameter spaces are misaligned, introducing harmful directions that increase the target loss. The paper asks which components of a task vector are genuinely transferable across pre-trainings and how to identify them without re-running full fine-tuning on the target.
![Teaser figure](../imgs/ICLR20261859/cropped_page3_idx0.webp)

## Input / Output

The method takes a source task vector τ_A (the difference between a fine-tuned and its base model), a target pre-trained model θ_B with a different initialization, and a tiny labeled subset D_s (as few as 1 sample per class) from the target task. It produces updated target parameters θ_B^trans via a single element-wise masked addition—no optimizer step or iterative training is performed on θ_B. The mask is a binary vector of the same dimensionality as the model parameters, computed from per-sample gradient signs via majority voting, requiring only one forward-backward pass per sample.

## Method

GradFix exploits the observation that the sign of the anti-gradient at the zero-shot target model is a reliable surrogate for the descent directions encoded in the (unavailable) target task vector. For each parameter coordinate, it computes per-sample gradient signs on θ_B using a few labeled examples, aggregates them via majority voting to obtain a binary mask m, and retains only those components of τ_A whose sign matches the anti-gradient direction. A first-order Taylor analysis proves that the resulting update δ^A = α(m ⊙ τ_A) satisfies g^T δ^A ≤ 0, guaranteeing descent on the target loss. A Hoeffding-based concentration bound further shows that the majority-vote sign estimator recovers the true anti-gradient direction with probability growing exponentially in the number of samples. Unlike prior rebasin or permutation-alignment approaches, GradFix requires no explicit parameter-space alignment and no iterative optimization—just a single masked addition to the target weights.

## Results

On vision benchmarks (CLIP ViT-B/16, |D_s^c|=5 samples per class), GradFix achieves 66.05% on EUROSAT, 73.59% on SVHN, 66.61% on GTSRB, 71.57% on RESISC45, and 60.02% on DTD, consistently outperforming few-shot fine-tuning (θ_B^opt) by 2–7 points per dataset. On ViT-L/14 at the same budget, GradFix reaches 75.59% (EUROSAT) and 74.41% (SVHN), again exceeding few-shot fine-tuning. In the language setting (T5, |D_s^c|=50), GradFix achieves 58.48% average accuracy across SNLI/MNLI/RTE/QNLI/SCITAIL, compared to 42.12% for naive task vector addition and 43.51% for zero-shot, closing roughly 40% of the gap to full fine-tuning (89.40%).

## Baselines & Comparisons

Against naive Task Arithmetic (θ_B + τ_A), GradFix delivers dramatic gains: on ViT-B/16 at |D_s^c|=5, GradFix improves EUROSAT from 49.58% to 66.05% (+16.5 pts) and SVHN from 50.84% to 73.59% (+22.8 pts), whereas naive addition performs at or below zero-shot level, confirming that unfiltered cross-pre-training transfer is essentially useless. Against TransFusion (Rinaldi et al., 2025), which transports task vectors via permutation alignment, GradFix wins on every dataset by 5–20 points (e.g., 66.05% vs. 50.12% on EUROSAT, 73.59% vs. 53.26% on SVHN for ViT-B/16), indicating that gradient-sign masking is far more effective than structural permutation matching for this task. Against few-shot fine-tuning (θ_B^opt) with the same supervision budget, GradFix consistently outperforms by 2–7 points per dataset on ViT-B/16 and by 3–7 points on ViT-L/14, while exhibiting substantially lower variance across random seeds (e.g., ±0.43 vs. ±7.29 on EUROSAT at |D_s^c|=5). In the language domain, GradFix (58.48% avg) outperforms both naive transfer (42.12%) and zero-shot (43.51%) by 15+ points, though it remains below the oracle mask (65.86%) and full fine-tuning (89.40%). In multi-task merging (Table 3), GradFix with Merge-then-Mask achieves 66.02% average, surpassing TIES-Merging baseline (54.67%) and Task Arithmetic baseline (54.73%) by over 11 points.

## Relation to Prior Work

This paper sits at the intersection of Task Arithmetic (Ilharco et al., 2023), which treats fine-tuning deltas as composable task vectors, and the model-rebasin literature (Ainsworth et al., 2023; Rinaldi et al., 2025), which studies how to align independently pre-trained models so their parameter spaces become compatible. While TransFusion (Rinaldi et al., 2025) addresses cross-pre-training transport via explicit permutation alignment, GradFix departs from this by avoiding any structural matching and instead borrowing the gradient-sign-as-descent-proxy idea from the SignSGD/distributed-optimization literature (Bernstein et al., 2018; Alistarh et al., 2017). The key conceptual move is reframing the transport problem as a coordinate-wise sign-filtering problem: rather than finding a global permutation that maps one basin to another, one simply masks the source task vector with the target's local anti-gradient signs, yielding a first-order descent guarantee without any parameter updates.

## Why It Matters / Open Questions

The practical motivation is compelling: every time a foundation model is re-released (e.g., a new CLIP or T5 checkpoint), practitioners must re-fine-tune all downstream tasks, and GradFix offers a single forward-backward pass plus element-wise masking as a lightweight alternative that requires only a handful of labeled samples. However, the remaining gap to the oracle (e.g., ~64% vs ~86% average on ViT-B/16) and to full fine-tuning (~95%) limits immediate deployment, and the method's reliance on a validation set for the scaling coefficient α adds a small but non-trivial tuning burden. Open questions include whether better sign estimators (beyond majority vote) or structured subset selection can close the oracle gap, whether the approach extends to generative or autoregressive architectures where the loss landscape is less well-behaved, and whether the magnitude-mismatch finding (directions transfer, magnitudes do not) generalizes beyond classification tasks.
