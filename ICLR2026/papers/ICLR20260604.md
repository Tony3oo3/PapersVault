## Problem

Current LLM agent training relies on supervised fine-tuning over static trajectories or reinforcement learning on narrow, domain-specific tasks, both of which generalize poorly to new tools and unseen workflows. A scalable, general-purpose RL environment that captures the diversity and complexity of real-world tool-use interactions has been lacking, leaving agents brittle when deployed beyond their training distribution.
![Teaser figure](../imgs/ICLR20260604/cropped_page1_idx0.webp)

## Input / Output

The agent receives a task description, documentation of available tools (functionality, parameter descriptions, and return types, with examples withheld during training to encourage interaction-based learning), and partial environment observations including error messages from failed tool calls. It produces a sequence of JSON-encoded tool calls (each specifying a function name and parameter dictionary) followed by a final answer submitted via a Done action. The environment is a POMDP with sparse binary rewards: the agent only receives a reward signal (1 or 0) upon termination by comparing the submitted answer to the ground-truth unit test output.

## Method

CodeGym converts static coding problems into interactive multi-turn tool-use environments by extracting atomic functions and logic from coding solutions into callable tools, then synthesizing OpenAI Gym–format POMDP environments where agents must compose tool calls to solve tasks rather than writing full code. A two-stage pipeline handles synthesis (LLM-driven tool extraction and environment generation with a one-shot format example) and verification (pass@K solvability checking with K=10 LLM-generated solution functions against 30 synthesized unit tests). Quality filtering retains only environments requiring 10–256 tool calls across at least 4 distinct tools and with ≤25% accuracy under Qwen2.5-32B-Instruct, yielding 86k task configurations across 13k environments. Training uses GRPO with a distributed CPU-bound environment server and a trial-then-overwrite mechanism that serializes environment state before each tool call to prevent crashes from erroneous invocations. The key insight is that code execution inherently mirrors real-world workflow structures (e.g., loops as iterative approval rounds), making coding problems a natural substrate for diverse, verifiable agent training environments.

## Results

On the OOD benchmark suite (τ-bench, τ²-bench, ALFWorld, ZebraLogic, MMLU-Pro), CodeGym-trained Qwen2.5-32B-Instruct achieves an average score of 49.6, a +7.3 absolute gain over the base model (42.3). The largest single-benchmark improvement is on τ-retail (+13.0, from 41.4 to 54.4) and ALFWorld (+14.0, from 66.8 to 80.8). For the 72B model, the average gain is +4.1 (46.2→50.3), and for the long-CoT QwQ-32B model, tool-use benchmarks improve by +5.6 (τ-airline) and +5.3 (τ-retail) while ZebraLogic slightly drops by 3.3 points.

## Baselines & Comparisons

The paper compares each CodeGym-trained model directly against its untrained base counterpart (Qwen2.5-7B/14B/32B/72B-Instruct and QwQ-32B) on five OOD benchmarks. CodeGym training yields consistent average improvements across all model sizes: +2.8 (7B), +4.6 (14B), +7.3 (32B), and +4.1 (72B), with the 32B model showing the largest absolute gain, suggesting larger models generalize better rather than memorize. On tool-use benchmarks specifically, gains are most pronounced—τ-retail improves by +13.0 for 32B and +7.8 for 72B—while reasoning benchmarks (ZebraLogic, MMLU-Pro) show smaller but still positive gains for short-CoT models. For the long-CoT QwQ-32B, tool-use scores improve substantially (τ-airline +5.6, τ-retail +5.3) but ZebraLogic drops by 3.3 points, indicating a trade-off between agent capabilities and pure reasoning when trained on CodeGym. An ablation further shows that SFT on oracle or distilled trajectories (10k samples) achieves comparable in-domain performance but degrades or provides only marginal OOD gains, confirming that RL in CodeGym is necessary for generalizability.

## Relation to Prior Work

This paper extends the line of work on synthetic environments for LLM agent training (TextWorld, ALFWorld, SWE-Gym, BrowseComp-Plus) by proposing a scalable pipeline that converts coding problems into diverse, verifiable multi-turn tool-use RL environments. It departs from prior narrow-domain RL setups (coding assistants, web search) by using code execution logic as a structural substrate that mirrors real-world workflow patterns, enabling broad coverage of tool-call compositions. The RL training follows the GRPO/verifiable-reward paradigm established by DeepSeekMath and CodeRL, but applies it to the previously underexplored setting of general-purpose tool-use agent training at scale.

## Why It Matters / Open Questions

CodeGym provides a publicly available, scalable pipeline (13k environments, 86k task configurations) that addresses the scarcity of diverse RL environments for tool-use agents, and demonstrates that RL on these synthetic environments yields consistent OOD gains across tool-use, multi-turn interaction, and reasoning benchmarks. Key open questions include: (1) long-CoT models lose some reasoning accuracy when trained on CodeGym, suggesting tension between reasoning and tool-use objectives; (2) QwQ still falls far short of oracle tool-call counts, indicating that shortcut exploitation remains unresolved; (3) whether the workflow-structure transfer observed here holds for truly open-ended real-world tool ecosystems beyond benchmarked settings.
