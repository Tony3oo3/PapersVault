## Problem

Existing MLE agents rely on prompting frontier LMs with agent scaffolds and accumulating experience non-parametrically, which fails to fundamentally change the agent's behavior and wastes compute from costly ML experiments. This paper asks whether adapting a smaller LM's parameters through reinforcement learning can be more effective than scaling test-time compute on a static frontier model, and identifies two specific obstacles: variable-duration actions in distributed async RL bias the policy toward fast but suboptimal solutions, and sparse held-out-data rewards provide no signal for intermediate progress or whether ML is used at all.

## Input / Output

The agent receives a Kaggle-style MLE task description, paths to training and test datasets, and any prior experiment history, all constrained to 1024 tokens of prompt. It outputs a 3–5 sentence natural-language plan followed by a single Python code block that must produce a submission file at a specified path; the code is executed in a sandboxed environment and graded by a task-specific grader on held-out data. During training, a separate static LM copy instruments the generated code with print statements whose terminal output is regex-parsed for partial credit, and the agent is additionally prompted (50% of the time) to revise a previously generated solution given its execution output.

## Method

The paper trains Qwen2.5-3B with PPO on the HybridFlow distributed RL framework, introducing two key modifications. First, duration-aware gradient updates weight each policy-gradient term by the action's execution duration Δt_k, which is proven (via importance sampling) to be an unbiased correction for the frequency bias that arises when faster actions complete more often in an asynchronous distributed setting; in practice Δt_k is rescaled by the batch mean to avoid oversized updates. Second, environment instrumentation uses a frozen copy of the same LM to insert progress-tracking print statements (e.g., 'loaded data', 'trained model') into the agent's code before execution, and regex-matches the terminal output to assign partial credit (0.1 per matched statement, −10 for complete failure), providing a denser reward signal than the binary held-out score alone. The training loop alternates between solving from scratch and explicitly improving a prior solution, and the agent is trained per-task for 1–3 days on 8 A100 GPUs until reward convergence.

## Results

On 12 Kaggle MLE tasks from MLEBench, Qwen2.5-3B adapted with RL (PPO + duration-aware gradient + environment instrumentation) achieves an average 22% improvement over prompting Claude-3.5-Sonnet with the AIDE agent scaffold, winning on 8/12 tasks. Notable wins include tweet-sentiment-extraction (0.596 vs. 0.448), random-acts-of-pizza (0.663 vs. 0.627), and leaf-classification (0.124 vs. 0.436, lower is better). Against GPT-4o running 100 hours with AIDE, the RL small model is competitive, and against different agent scaffolds (OpenHands, MLAB) on GPT-4o, it wins 9/12 tasks with a 17.7% average improvement over the best scaffold per task.

## Baselines & Comparisons

Against Claude-3.5-Sonnet + AIDE (the primary frontier baseline), Qwen2.5-3B RL wins 8/12 tasks with a 22% average improvement, with the largest gains on tweet-sentiment-extraction (+0.148) and leaf-classification (0.124 vs. 0.436, lower is better). Against GPT-4o running 100 hours with AIDE, the RL model is competitive but does not consistently win, losing on tasks like tabular-dec-2021 (0.951 vs. 0.957) and us-patent-phrase-matching (0.527 vs. 0.588). Against Llama3.1-405B, results are mixed with the RL model winning on several tasks but losing on others like tabular-may-2022 (0.913 vs. 0.939). Compared to the base Qwen2.5-3B without RL, the RL-adapted model shows dramatic improvements on nearly all tasks (e.g., tweet-sentiment-extraction goes from 0.027 to 0.596). Against alternative agent scaffolds (OpenHands, MLAB) on GPT-4o, the RL small model wins 9/12 tasks with a 17.7% average improvement over the best scaffold per task, demonstrating that RL-based adaptation is more reliable than scaffold selection.

## Relation to Prior Work

This paper departs from the dominant paradigm in MLE agents—prompting frontier LMs with agent scaffolds (AIDE, OpenHands, MLAB) and accumulating experience non-parametrically—by instead adapting a small LM's parameters through online RL. It builds on PPO (Schulman et al., 2017) and the HybridFlow distributed RL framework (Sheng et al., 2024), but introduces two key modifications specific to agentic MLE: duration-aware gradient updates to correct for variable-time action execution in asynchronous training, and environment instrumentation using a frozen LM copy to provide verifiable partial credit. Conceptually, it extends the RL-for-LMs line of work (RLHF, reasoning RL) into a setting where actions have heterogeneous execution costs and rewards are inherently sparse, a combination not addressed by prior RL frameworks designed for simulation, math, or coding tasks.

## Why It Matters / Open Questions

The paper demonstrates that a 3B model trained with RL can outperform a frontier model (Claude-3.5-Sonnet) with the best agent scaffold by 22% on average across 12 Kaggle tasks, suggesting that future MLE agents should allocate compute to gradient updates rather than solely scaling inference-time search. The duration-aware gradient and environment instrumentation techniques are practical and address real failure modes (convergence to fast-but-suboptimal solutions, reward hacking via sparse feedback) that would affect any agentic RL system with variable-duration actions. Key limitations include evaluation on only 12 tasks with a 3B base model selected to avoid instruction-following bottlenecks, leaving open whether the findings generalize to larger models, harder tasks, or domains beyond MLE. The paper also notes that offline alternatives (SFT, DPO, STaR) failed, reinforcing the necessity of online RL but limiting the practical accessibility of the approach.
