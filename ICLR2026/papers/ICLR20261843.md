## Problem

API providers of open-weight LLMs may secretly substitute quantized, fine-tuned, or entirely different models to cut costs or alter behavior, yet users lack access to model weights or full logits to verify the deployed model. Existing detection methods (MMD, trained classifiers, identity prompting, benchmark comparison) each fail on at least one of accuracy, query efficiency, or robustness to adversarial providers who can detect and reroute suspicious query patterns.

## Input / Output

The method consumes a set of natural-language prompts (e.g., from WildChat), exactly one completion per prompt from the target API, and m completions per prompt from a locally deployed reference model whose logits are fully accessible. It outputs a p-value from the Cramér-von Mises goodness-of-fit test and a binary decision at a user-specified significance level (default α=0.05). The critical constraint is that only one paid API call is made per prompt, while the reference model is queried m times locally (m=100 in experiments), making the method query-efficient by design.

## Method

RUT is an asymmetric two-sample hypothesis test that checks whether the target API's responses are statistically typical under the reference model's generation distribution. For each prompt, it computes a log-rank score (the average log of each token's rank in the reference model's next-token probability ordering) for the single target response and m reference responses, then constructs a randomized rank percentile for the target response within the reference score distribution using a randomized quantile residual to handle discreteness. Under the null hypothesis of model equality, these percentiles are Uniform[0,1]; deviations are detected via the Cramér-von Mises test statistic. The log-rank score was selected empirically from five candidates (log-likelihood, token rank, log-rank, entropy, log-likelihood/log-rank ratio) by maximizing AUROC separability across 500 Monte Carlo trials. A theoretical analysis under Zipfian token-rank distributions provides sample complexity bounds: n=Θ(ε⁻²(α−1)²) for moderate heavy-tailedness and n=Θ(ε⁻²α⁵) for extreme heavy-tailedness under reparameterization attacks.

## Results

RUT is evaluated using statistical power AUC (area under the power-vs-substitution-rate curve) as the primary metric, with higher values indicating more reliable detection across varying adversarial substitution rates. On quantization detection (the primary setting), RUT achieves power AUC of 0.643 for Llama-3.2-3B 4-bit, 0.587 for Mistral-7B 4-bit, and 0.393 for Gemma-2-9B 4-bit, outperforming MMD (0.626, 0.501, 0.214) and KS (0.475, 0.330, 0.017) in 3 of 4 reliable cases. For jailbreak prompt detection, RUT reaches 0.895 (Mistral+Dan) and 0.888 (Gemma+Dan), exceeding MMD (0.803, 0.757) and KS (0.873, 0.867) in all 6 settings. On real-world API endpoints, RUT correctly confirms behavioral equivalence for local deployments (power < 0.1) while flagging significant deviations on external providers (e.g., 0.962 for Llama on Nebius).

## Baselines & Comparisons

RUT is compared against two baselines: MMD (Gao et al., 2025), a kernel-based two-sample test using character-level Hamming distance, and a tailored KS baseline that applies the two-sample Kolmogorov-Smirnov test on the same log-rank scores RUT uses. Against MMD, RUT wins in 3 of 4 reliable quantization settings (e.g., 0.393 vs 0.214 for Gemma-4bit, 0.587 vs 0.501 for Mistral-4bit) and in all 6 jailbreak settings (e.g., 0.895 vs 0.803 for Mistral+Dan), though MMD edges out RUT on Llama-8bit (0.158 vs 0.133) and Gemma-8bit (0.091 vs 0.050) where both methods struggle. Against the KS baseline, RUT achieves substantially larger margins across nearly all settings (e.g., 0.643 vs 0.475 for Llama-4bit, 0.895 vs 0.873 for jailbreaking), with KS performing particularly poorly on 8-bit quantization (AUC < 0.01 in most cases). On real API endpoints (Table 4), RUT and MMD broadly agree on detecting significant deviations, while KS shows notably lower sensitivity (e.g., 0.426 vs 0.962 for Llama on Nebius). The paper also notes RUT's robustness to minor decoding mismatches (e.g., tokenization whitespace differences) that inflate MMD's string-based scores, as demonstrated by the Mistral + HF Inference case where MMD reports power 1.0 due to a formatting artifact while RUT reports 0.188.

## Relation to Prior Work

This paper adopts the model equality testing formulation from Gao et al. (2025), who showed that kernel-MMD can flag API endpoints deviating from their open-weight checkpoints, but departs from the symmetric two-sample comparison by proposing an asymmetric rank-based goodness-of-fit test requiring only one target API call per prompt. The log-rank score function is borrowed from Su et al. (2023) (DetectLLM), originally designed for machine-generated text detection, and repurposed here as the discriminative scalar that maps responses to a rank statistic. The randomized quantile residual construction from Dunn & Smyth (1996) extends the probability integral transform to the discrete token-output setting, ensuring the rank statistic is uniformly distributed under the null. Conceptually, the key departure from MMD and KS baselines is that RUT operates on natural user-like queries (avoiding detectable patterns) and frames detection as a one-sample uniformity test rather than a two-sample distributional comparison.

## Why It Matters / Open Questions

As LLM access shifts to API-based deployment, the ability to verify that a provider is actually serving the claimed model becomes a practical safety and cost-integrity concern. RUT's query efficiency (one API call per prompt) and by-design robustness to adversarial rerouting make it more deployable than prior methods that require special query distributions or prohibitively many queries. Key limitations include the requirement for a locally deployed reference model (restricting applicability to open-weight models) and the absence of validation against a fully informed adversary who knows the test and can selectively reroute atypical prompts. The finding that 8-bit quantization is essentially undetectable by all methods under the tested budgets highlights a fundamental sensitivity limit that remains an open question.
