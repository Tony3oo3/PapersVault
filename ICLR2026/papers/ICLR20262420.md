## Problem

Existing benchmarks for AI agents evaluate only whether a solution is correct, treating any output that passes test cases as equally successful regardless of how it was derived. This overlooks the methodological dimension of intelligence: two agents may reach the same answer via fundamentally different approaches, yet current frameworks cannot distinguish a genuinely novel method from a conventional one. The paper asks how to systematically quantify both the performance breakthrough and the methodological originality of an agent's solution.

## Input / Output

Each task is formalized as a quadruple (P, S, V, D) where the agent receives only the visible problem description, constraints, development data, and a feasibility validator C, while the evaluator R, hidden evaluation data, and the set of known reference solutions S_known remain concealed. The agent produces a solution artifact (executable code, algorithmic strategy, or derivation) within a 12-hour wall-clock budget. The system outputs two complementary scores: Performance Gain G(s) = V(s) − V*_known (absolute improvement over the best known solution) and Novelty N(s) ∈ [0,100], computed as the minimum Agent-as-judge distance to any known solution, with a normalized ratio R(s) = G(s)/V*(s) for cross-task comparison.

## Method

InnoGym comprises two components: iBench, a benchmark of 18 curated Improvable Tasks drawn from real competitions (NeurIPS, KDD Cup, ROADEF, GMCM, MLArchSys) and classic NP-hard problems, standardized through two-stage filtering (resource availability, then evaluator correctness and domain balance) and augmented with validators, normalized absolute evaluators, and collected reference solutions; and iGym, a unified execution SDK providing an asynchronous Tool Dispatcher, state-based recovery for long-horizon tasks, and native concurrency to enable fair cross-framework comparison. The novelty metric N is instantiated via a two-stage Agent-as-judge pipeline: Codex first extracts a structured representation (summary.md + pseudocode.tex) from each solution, then GPT-5 scores methodological dissimilarity across six rubric dimensions on a 0–4 scale, which is averaged and rescaled to [0,100]. The framework further defines a taxonomy of Solved, Improvable, and Exploratory problems based on the spatial relationship between known solutions and the feasible region, and classifies innovations into breakthrough (high G, high N), performance (high G, low N), and conceptual (low G, high N) categories. Experiments evaluate three agent scaffolds (MLAB, CODEACT, AIDE) across multiple backbone LLMs, revealing that while agents achieve moderate novelty scores, their performance gains remain substantially negative relative to human state-of-the-art, with robustness rather than creativity identified as the primary bottleneck.

## Results

Across 10 main iBench tasks, no agent framework surpasses the human state-of-the-art on any task; all performance gains are negative. MLAB achieves the best average performance gain of −24.32 (normalized ratio −0.45) and highest average novelty of 56.55, compared to CODEACT (gain −41.58, ratio −0.69, novelty 54.86) and AIDE (gain −42.68, ratio −0.64, novelty 46.67). On two tasks (CDML and PTTALC), all three agents fail to produce any valid submission. Under pessimistic imputation for failures, MLAB's macro-average ratio is −0.62 [−0.82, −0.42] and novelty 39.58 [22.08, 56.25], statistically outperforming both CODEACT and AIDE on ratio (p=0.035 and p=0.007 respectively).

## Baselines & Comparisons

The paper evaluates three agent frameworks—MLAB (ReAct-style workflow agent), CODEACT (code-centric action agent), and AIDE (tree-search-based code optimizer)—on the InnoGym benchmark. MLAB consistently outperforms the other two: it achieves the best average performance gain (−24.32 vs. −41.58 for CODEACT and −42.68 for AIDE) and the highest average novelty (56.55 vs. 54.86 and 46.67). Under pessimistic imputation for failed submissions, MLAB's macro-average ratio (−0.62) is statistically significantly better than both CODEACT (−0.81, p=0.035) and AIDE (−0.82, p=0.007), while novelty differences are not statistically significant given the small task count. A key finding is that all three frameworks exhibit comparable novelty levels yet diverge sharply in performance, indicating that robustness and correct execution—not creative ideation—is the primary bottleneck. Notably, CODEACT nearly matches the state-of-the-art on CirclePacking (ratio −0.003) but fails to generalize, while AIDE achieves the highest novelty on OAG (70.83) yet still falls well short of the leaderboard best.

## Relation to Prior Work

This paper departs from the dominant paradigm in agent evaluation (MLE-Bench, MLAgentBench, DSBench, ScienceAgentBench) where success is measured solely by performance or correctness, by introducing novelty as a first-class, co-equal metric alongside performance gain. Conceptually, it draws on the (P,S,V,D) task formalization to define innovation as occupying specific regimes in a (G,N) space, and on the agent-as-judge paradigm (instantiated via Codex + GPT-5) to operationalize methodological dissimilarity. For execution infrastructure, it positions iGym as addressing gaps in existing SDKs (OpenHands, AutoGen, LangGraph) around long-horizon recovery, native concurrency, and unified tool management, rather than building on any single prior system.

## Why It Matters / Open Questions

InnoGym is the first benchmark to explicitly evaluate both performance breakthroughs and methodological originality in AI agents, filling a gap where prior work conflated solution value with novelty. The key open question it surfaces is whether agents can learn to balance creativity with robustness—the finding that novelty scores are comparable across frameworks while performance diverges sharply suggests the bottleneck is execution reliability, not idea generation. Limitations include the restriction to improvable tasks only (excluding solved and exploratory problems), a finite and potentially biased S_known set for novelty computation, and thin validation of the D_AGENT metric (8 code-level triplets, 3 method-level triplets). The benchmark's practical value will depend on whether the community adopts the dual-metric framing and whether the 18 tasks prove sufficiently discriminative as agents improve.
