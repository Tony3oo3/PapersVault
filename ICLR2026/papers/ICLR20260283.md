## Problem

Existing SWE agents rely on a single monolithic reasoning chain that retains irrelevant context across sub-tasks, causing spurious correlations and poor generalization to out-of-distribution issues. While hierarchical multi-agent decomposition mirrors human engineering practice, prior systems depend on manually designed sub-agent roles that often misalign with how LLMs actually reason, and the combinatorial search space plus ambiguous credit assignment make automated discovery of effective agent hierarchies intractable under the high cost of SWE evaluation.

## Input / Output

At design time, BOAD consumes a small set of 12 representative GitHub issues (one per repository, sampled from SWE-bench-Verified) as a design set, along with an LLM (Claude-4) for generating candidate sub-agents and judging helpfulness. The output is a set of K sub-agents—each specified by a docstring, context argument description, and instance template—plus a customized orchestrator prompt that references the selected sub-agents by name. At inference time, the system takes a new GitHub issue and its repository container, and the orchestrator invokes sub-agents via an XML-based tool-calling protocol (passing a single 'context' string), ultimately producing a code patch that must pass all fail-to-pass and pass-to-pass tests.

## Method

BOAD formulates hierarchical multi-agent design as a multi-armed bandit problem where each arm is a candidate sub-agent and the reward is a hindsight helpfulness score rather than binary task success. The algorithm uses UCB to balance exploration and exploitation over sub-agent selection, and a Chinese Restaurant Process to dynamically expand the archive of candidate sub-agents, ensuring the search space grows linearly (O(θ log T)) rather than combinatorially. For credit assignment, an LLM judge scores each sub-agent's contribution from the full problem-solving trajectory, rewarding agents that provide useful intermediate steps even when the overall system fails, thereby avoiding the free-rider problem inherent in success-rate-based scoring. The bottom-up strategy—first identifying individually helpful sub-agents, then composing them into a team with a customized orchestrator—reduces the joint (π, Ω) optimization to a tractable sequential decision problem, and the entire design loop converges in ~20 rounds (~12 hours on 56 CPU cores) using a 36B model for execution and Claude-4 for meta-level generation and evaluation.

## Results

On SWE-bench-Verified, BOAD with Seed-OSS-36B-Instruct achieves 53.2% resolution rate, a 13.4% absolute gain over the same model with default SWE-agent (49.8%). On SWE-bench-Live, which features more recent and out-of-distribution issues, BOAD reaches 20.0% resolution—a 63% relative improvement over the 12.3% baseline—and ranks second on the leaderboard at evaluation time, surpassing larger models including GPT-4o (10.0–11.7%), Claude 3.7 Sonnet (13.7%), and DeepSeek-V3 (13.3%). BOAD also reduces maximum input token length by 11.6% (Verified) and 25.0% (Live) compared to the single-agent baseline, confirming that hierarchical decomposition shortens context without sacrificing performance.

## Baselines & Comparisons

BOAD (53.2% Verified, 20.0% Live) decisively outperforms the same-model single-agent SWE-agent baseline (49.8%, 12.3%) and both multi-agent alternatives: manually designed sub-agents from prior work actually *degrade* performance to 47.4%/14.0%, and an evolutionary search baseline (adapted from ADAS [23]) reaches only 46.0%/17.0% at more than double the API cost. On SWE-bench-Live, BOAD surpasses all large-model systems except Qwen3-Coder 480B (24.7%), including GPT-4o (10.0–11.7%), Claude 3.7 Sonnet (13.7%), DeepSeek-V3 (13.3%), and GLM-4.5-Air (17.7%). On SWE-bench-Verified, BOAD exceeds GPT-4o (23.0–38.8%), Claude 3.5 Sonnet (50.8–53.0%), DeepSeek-R1 (49.2%), and DeepSeek-V3 (42.0%), but remains below the largest models—Claude 4.0 Sonnet (70.4%), Qwen3-Coder 480B (69.6%), and Claude 3.7 Sonnet (62.4%). The paper also shows that prompt optimization alone (without sub-agents) yields only 16.3% on Live, confirming that the gains stem from discovered sub-agent structure rather than better orchestrator prompts.

## Relation to Prior Work

This paper builds on the SWE-agent scaffold (Yang et al., NeurIPS 2024) for the underlying agent-environment interaction, on SMDP/temporal abstraction (Sutton et al., 1999) for the theoretical justification of hierarchical orchestrator-sub-agent structure, and on multi-armed bandit algorithms (Lattimore & Szepesvári, 2020) for the exploration-exploitation mechanism. It departs from prior multi-agent SWE systems (MASAI, Coder, HyperAgent) that rely on manually designed sub-agent roles and coordination, and from evolutionary agent-design methods (ADAS, AFlow) that optimize fixed workflows or single-agent scaffolds. The key conceptual move is formulating multi-agent SWE design as a bandit problem with hindsight credit assignment via LLM-as-a-judge, enabling sample-efficient discovery of sub-agent teams under the high evaluation costs of long-horizon SWE tasks.

## Why It Matters / Open Questions

The result that a 36B model with auto-discovered hierarchical structure outperforms GPT-4 and Claude on SWE-bench-Live suggests that agent architecture can compensate for model scale on out-of-distribution tasks, with broad implications for cost-efficient deployment of coding agents. The finding that manually designed sub-agents from prior work actually degrade performance challenges the assumption that human-intuitive task decompositions align with LLM behavior. Open questions include whether discovered sub-agents transfer reliably across model families (the paper shows only partial transfer), how to mitigate error propagation when orchestrators unconditionally accept sub-agent outputs, and whether the framework extends to domains beyond software engineering.
