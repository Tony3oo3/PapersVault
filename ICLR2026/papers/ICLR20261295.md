## Problem

Existing feature caching methods for accelerating diffusion transformers rely on temporal extrapolation (linear or Taylor-based) to predict output features between full-computation steps, but the irregular magnitude of feature changes across timesteps causes substantial prediction errors that severely degrade generation quality, particularly under aggressive acceleration budgets.

## Input / Output

RFC is a training-free inference-time acceleration applied to pretrained DiT models. It takes the same inputs as the base model (a class label for DiT-XL/2 at 256×256, or a text prompt for FLUX.1 dev at 1000×1000 and HunyuanVideo) and produces the same outputs (generated images or videos). The method operates by selectively skipping expensive module computations (attention, MLP) at intermediate timesteps, using only lightweight operations (LayerNorm, scaling, shifting) to obtain input features for prediction and scheduling decisions.

## Method

RFC introduces two complementary components that exploit the strong input-output feature correlation within each module. Relational Feature Estimation (RFE) replaces the fixed temporal extrapolation magnitude in TaylorSeer with a dynamically estimated magnitude derived from input feature differences, leveraging the empirically validated invariance of the output-to-input change ratio s_k across timesteps (Proposition 1). Relational Cache Scheduling (RCS) dynamically determines when to trigger full computations by accumulating the relative L1 prediction error of input features (computed cheaply via Taylor expansion) and performing a full forward pass only when the accumulated error exceeds a threshold τ, thereby concentrating computation where prediction is most unreliable. Together, RFE improves per-step prediction accuracy while RCS adapts the caching schedule to the actual difficulty of feature prediction at each timestep.

## Results

On ImageNet with DiT-XL/2, RFC consistently outperforms all baselines across FLOPs budgets. At ~6.67 TFLOPs (NFC≈14), RFC achieves FID 2.52, sFID 4.60, and sFID2FC 1.33, compared to TaylorSeer's FID 2.55, sFID 5.30, and sFID2FC 2.17 at the same budget. At the more aggressive ~3.37 TFLOPs (NFC≈7), RFC reaches sFID 5.21 and sFID2FC 3.66, while TaylorSeer at ~4.76 TFLOPs (NFC=10) only achieves sFID 6.47 and sFID2FC 4.63 — meaning RFC with 30% fewer FLOPs beats TaylorSeer by 1.26 sFID. On FLUX.1 dev (DrawBench) and HunyuanVideo (VBench), RFC similarly leads on PSNR, SSIM, LPIPS, and VBench scores at matched FLOPs.

## Baselines & Comparisons

RFC outperforms all five baselines across every FLOPs budget tested. Against FORA (Selvaraju et al., 2024), the gap is largest at low budgets: at ~3.35 TFLOPs, RFC achieves sFID 5.07 vs. FORA's 18.49, and sFID2FC 3.10 vs. 19.11. Against ToCa (Zou et al., 2025) and DuCa (Zou et al., 2024), RFC wins on sFID and sFID2FC at every budget (e.g., at ~6.67 TFLOPs: RFC sFID 4.60 vs. ToCa 5.02 and DuCa 4.95). Against the strongest baseline TaylorSeer (Liu et al., 2025b), RFC improves sFID by 0.70 at ~6.67 TFLOPs (4.60 vs. 5.30) and by 1.26 at ~3.37 vs. 4.76 TFLOPs (5.21 vs. 6.47), while also halving sFID2FC (1.33 vs. 2.17 at matched FLOPs). Against TeaCache's input-distance scheduling (Liu et al., 2025a), RCS achieves lower FID2FC (0.36 vs. 0.50) and sFID2FC (1.88 vs. 2.53) at NFC≈14, confirming that prediction-error-based scheduling is more effective than simple distance-based triggering for forecasting methods.

## Relation to Prior Work

This paper extends the forecasting-based feature caching line of work for diffusion transformers, building directly on TaylorSeer's Taylor expansion framework (Liu et al., 2025b) and the broader caching paradigm established by DeepCache, FORA, FasterCache, and GOC. The key conceptual departure is shifting from purely temporal extrapolation of output features to exploiting the input-output relationship within each module: RFE uses input feature differences to estimate output change magnitudes, while RCS uses input prediction errors as a proxy for output errors to trigger full computations. This contrasts with TeaCache (Liu et al., 2025a), which also uses input features for scheduling but requires a separate calibration step, and with token-wise caching methods (ToCa, DuCa) that reduce computation selectively across tokens rather than across timesteps.

## Why It Matters / Open Questions

RFC provides a training-free, drop-in acceleration method for DiTs that is particularly impactful at low compute budgets where prior forecasting methods degrade severely (e.g., FID 160.85 → 8.65 at NFC=4 on ImageNet). The method's simplicity—requiring only lightweight operations like LayerNorm to compute input features—makes it easy to deploy across different DiT architectures (DiT-XL/2, FLUX.1, HunyuanVideo) without retraining. Open questions include whether the input-output correlation assumption holds for all module types and architectures, whether layer-wise or module-selective application of RFE could further reduce overhead, and how the method interacts with other acceleration techniques like step distillation or token pruning.
