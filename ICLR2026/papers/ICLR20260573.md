## Problem

Designing effective federated learning systems requires manually selecting, combining, and tuning strategies across a combinatorial space of data heterogeneity, system constraints, and task objectives, resulting in brittle, bespoke solutions. Existing single-agent code generation frameworks (e.g., ReAct, Chain-of-Thought) excel at self-contained programming tasks but cannot reason holistically about the interdependent, multi-component architecture of a distributed FL system. This paper addresses the gap by automating the end-to-end synthesis of deployment-ready FL systems from high-level specifications.

## Input / Output

The system accepts a structured natural language query following a three-component template (problem statement, task description, framework requirement) that specifies the application domain, data characteristics, model architecture, and evaluation metrics, supplemented by human-in-the-loop feedback during the planning phase to resolve ambiguities or incomplete specifications. The output is a complete, modular Python codebase built on the Flower framework, partitioned into four independently replaceable modules (Task, Client, Strategy, Server), that has passed both runtime integrity and semantic correctness verification in a sandboxed federated simulation.

## Method

Helmsman is a three-phase multi-agent pipeline built on LangGraph. Phase 1 (Planning) uses a Planning Agent augmented with web search and a RAG pipeline over FL literature (BM25 + vector search + Cohere reranking), followed by a Reflection Agent that scores the draft as COMPLETE or INCOMPLETE, and a final human-in-the-loop approval gate. Phase 2 (Modular Coding) is orchestrated by a Supervisor Agent that decomposes the plan into four modules and spawns dedicated Coder+Tester agent teams per module in a dependency-aware workflow (e.g., Server coding begins only after Strategy and Task modules are stable). Phase 3 (Autonomous Evaluation) runs the integrated codebase in a sandboxed Flower simulation for 5 rounds, applies hierarchical diagnosis (L1: runtime crash detection via exception scanning; L2: semantic correctness via metric analysis), and iteratively invokes a Debugger Agent with the error report until both layers pass or a maximum of 10 correction attempts is reached. The LLM backbone uses Gemini-2.5-flash for planning and Claude-Sonnet-4.0 for coding and evaluation stages.

## Results

Across 16 tasks in AgentFL-Bench, Helmsman achieves the best overall accuracy on 8 of 16 tasks (Q3, Q5, Q6, Q7, Q9, Q10, Q11, Q16), outperforming both general baselines (FedAvg, FedProx) and task-specific specialized methods. The most striking result is on Q16 (federated continual learning on Split-CIFAR100), where Helmsman reaches 50.95% average task accuracy with 0.07 forgetting (5-task setting), substantially surpassing the best specialized baseline TARGET (34.89% acc, 0.24 forgetting). On the remaining 8 tasks, Helmsman consistently beats FedAvg and FedProx but trails the dedicated specialized method by 1–13 points. The full system achieves a 100% success rate in generating functional FL codebases, compared to 37.5% for Codex and 43.75% for Claude Code.

## Baselines & Comparisons

Helmsman decisively outperforms the general-purpose baselines FedAvg and FedProx on all 16 tasks, with margins ranging from ~1 to ~35 points (e.g., Q16: 50.95% vs. 15.38%/15.86%). Against specialized methods, Helmsman wins outright on 8 tasks: it beats FedNS on Q3 (81.62 vs. 80.55), FedNova on Q5 (96.28 vs. 95.19), Q6 (86.58 vs. 83.48), and Q7 (63.75 vs. 62.88), HeteroFL on Q9 (62.94 vs. 62.62), FedNova on Q10 (48.78 vs. 45.77) and Q11 (89.73 vs. 89.11), and FedWeIT on Q16 (50.95 vs. 29.45). On the remaining 8 tasks, Helmsman trails the dedicated specialized method (FedNova, FedNS, FedPer, FAST) by 1–13 points but still exceeds both FedAvg and FedProx. The largest gap to a specialized method occurs on Q15 (federated active learning on CIFAR-10), where FAST achieves 77.95% versus Helmsman's 68.80%. In the detailed continual-learning comparison (Table 5), Helmsman's hybrid strategy of client-side experience replay plus global model distillation reduces catastrophic forgetting to 0.07 (5-task) and 0.18 (10-task), compared to 0.24 and 0.27 for the best prior method TARGET.

## Relation to Prior Work

This paper extends the multi-agent code generation paradigm (AgentCoder, CodeSim, SWE-bench multi-agent solvers) from self-contained programming tasks to the system-level complexity of federated learning. It departs from single-agent architectures (ReAct, Chain-of-Thought) that the authors argue cannot handle the combinatorial, multi-module nature of FL design, instead structuring the workflow into three collaborative phases (interactive planning, modular coding, autonomous evaluation) that mirror human R&D processes. The Flower framework serves as both the target codebase and the sandboxed execution environment, while a RAG pipeline over FL literature grounds the planning agent's strategy selection in established methods.

## Why It Matters / Open Questions

The paper addresses a genuine bottleneck in FL adoption: the manual, expert-dependent design process that produces brittle, bespoke solutions. AgentFL-Bench provides the first standardized benchmark for evaluating agentic FL system synthesis, enabling fair comparison across future systems. The Q16 continual learning result—where a discovered hybrid strategy (experience replay + global distillation) outperforms the best specialized method (TARGET) by ~16 points—suggests multi-agent systems can surface novel algorithmic combinations beyond what individual researchers typically explore. Limitations include dependence on the Flower framework, a constrained set of 16 tasks, and the need for HITL on complex queries; the authors note that self-evolutionary meta-optimization remains future work.
