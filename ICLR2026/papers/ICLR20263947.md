## Problem

Computer-use agents (CUAs) have been evaluated primarily on simple tasks like web navigation and OS settings, leaving it unclear whether they can automate sophisticated, specialized work such as software engineering. No environment existed to systematically test CUAs in a realistic IDE setting with the full tooling that human developers and specialized SWE agents rely on, making it impossible to determine whether generalist visual agents can match task-specific coding agents.
![Teaser figure](../imgs/ICLR20263947/cropped_page1_idx0.webp)

## Input / Output

Agents receive per-turn screenshots of a VSCode IDE (optionally augmented with Set-of-Marks element annotations for visual grounding) plus a natural-language task instruction; in the augmented setting they also gain text-based file-editing and bash APIs. Actions are issued as xdotool keyboard/mouse commands (e.g., 'xdotool mousemove 1000 1200 && xdotool type "hello world"') or as structured file/bash API calls. Each episode is capped at 20 steps (250 for SWE-Bench variants), and success is determined by execution-based verifiers—unit tests, compilation checks, or task-specific metrics—run on a separate environment that the agent cannot access.

## Method

The paper introduces PwP, a POMDP-formulated environment running a modified open-source VSCode inside a sandboxed Docker container, where agents perceive the screen and act through primitive xdotool keyboard/mouse events, with a gymnasium-style Python API for standard evaluation. PwP-Bench unifies 15 tasks (5,400 instances) across 14 languages and four categories—code generation/editing, multimodal code synthesis, domain-specific programming, and general SWE—into a single benchmark. The core empirical contribution is a three-way comparison: (1) pure visual CUAs, (2) the same CUAs augmented with only two text APIs (file editing and bash), and (3) specialized SWE agents (mini-swe-agent, OpenHands). The key finding is that pure visual interaction yields only 22.9% average accuracy, while adding just file/bash APIs jumps performance to 50.7%, approaching specialized agents (48.8%), and an 'assisted' experiment with hand-engineered IDE tool calls shows a further 13.3% gain, pinpointing poor visual grounding and underutilization of IDE functionality as the primary bottlenecks.

## Results

On PwP-Bench-Lite (300 instances across 15 SWE tasks), pure visual computer-use agents achieve at most 22.3% overall accuracy (Claude-Sonnet-4.0), far below the specialized mini-swe-agent baseline at 48.8%. Adding just two text APIs (file editing and bash) to the same CUAs raises the best average to 50.7% (Claude-Sonnet-4.0), surpassing mini-swe-agent by ~2 points. The gap between pure visual CUAs and CUAs with file/bash APIs narrows from 35.0% (Claude-3.5) to 27.8% (Claude-4.0) over 7 months, indicating rapid improvement. An 'assisted' experiment with hand-engineered IDE tool calls yields an additional average gain of up to 13.3% over CUA+File/Bash, highlighting untapped potential in IDE tool usage.

## Baselines & Comparisons

The paper compares three agent paradigms: pure visual CUAs, CUAs augmented with file/bash text APIs, and specialized SWE agents (mini-swe-agent and OpenHands). On overall PwP-Bench-Lite accuracy, Claude-Sonnet-4.0 with file/bash APIs (50.7%) narrowly outperforms mini-swe-agent (48.8%) and OpenHands (45.7%), despite its task-agnostic design. However, pure visual CUAs (best: 22.3%) trail mini-swe-agent by ~26.5 points, confirming that visual-only interaction is currently insufficient for SWE. On individual datasets, specialized agents with best-reported scores (e.g., 75.2% on SWE-Bench, 98.8% on HumanEval) still substantially outperform CUAs, indicating that hand-engineered scaffolding and inference scaling remain important. The key finding is that the gap between CUAs and specialized agents is primarily driven by visual grounding failures (95% of GPT-4o trajectories contain at least one grounding error) and inability to leverage IDE tools, rather than fundamental reasoning limitations.

## Relation to Prior Work

This paper sits at the intersection of two active research threads: computer-use agent (CUA) evaluation (OSWorld, AndroidWorld, WindowsAgentArena) and specialized SWE agent evaluation (SWE-Bench, SWE-agent, Agentless, OpenHands). It departs from both by placing all agents—generalist CUAs and specialized SWE agents—into a single, unified VSCode IDE environment and evaluating them under identical conditions, rather than letting each agent operate in its own hand-crafted scaffold. The 15 tasks in PwP-Bench are largely ported from existing SWE benchmarks (SWE-Bench, HumanEval, Design2Code, ChartMimic, DSBench, etc.), but the key conceptual shift is reframing them as visual-interaction problems solvable through primitive keyboard/mouse actions, with optional text APIs as an ablation axis.

## Why It Matters / Open Questions

The central finding—that adding just two text APIs (file edit + bash) nearly closes the gap between generalist CUAs (22.9%) and specialized SWE agents (48.8%), reaching 50.7%—reframes the bottleneck as visual grounding rather than reasoning, with direct implications for how CUA systems should be architected. The 'assisted' experiment showing up to 13.3% further gains from IDE tools (debuggers, profilers, rename) highlights a concrete, underexplored direction: training agents to discover and exploit environment-specific functionality. Open questions include whether the gap will close as visual grounding improves, whether pure visual interaction is ever sufficient for SWE, and how to scale evaluation beyond the 20-step / 300-instance Lite subset used here.
