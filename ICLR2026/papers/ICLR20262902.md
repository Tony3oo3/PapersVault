## Problem

The depth-recurrent Huginn model increases per-token computational depth by reusing a single recurrent block in latent space, but this rigid, chain-like propagation mechanism limits the diversity and adaptability of reasoning trajectories. The paper asks how to introduce multi-branch exploration into the recurrent module without incurring the computational and memory overhead of duplicating the full backbone.
![Teaser figure](../imgs/ICLR20262902/cropped_page1_idx0.webp)

## Input / Output

The model consumes a standard token sequence (text prompt) that is first embedded by two prelude transformer blocks into a latent representation. During inference, the recurrent module iterates T times (mean 32, truncated to 8 for BPTT), and at each token generation step the hard-gate router selects one of N LoRA branches to produce the next-token distribution, creating a sequential relay across branches. The final output is autoregressively generated text containing step-by-step reasoning and a boxed final answer, with temperature set to 0.0001 and max 1024 tokens.

## Method

MoDr augments Huginn's shared 4-block recurrent module with N (typically 4) LoRA adapters (rank 16, scaling factor 16) applied to the q, k, v, o projections, creating distinct reasoning branches while keeping the backbone frozen. A learnable hard-gate router computes scores from the concatenation of the prelude output and the current recurrent state (projected via a 2h→h adapter), then selects the top-1 (or top-K) branch to predict the next token, effectively turning inference into a dynamic relay race across branches. To prevent routing collapse without auxiliary losses, a per-branch bias term is updated each batch by the sign of the load-violation error (update rate η=0.001), nudging underutilized branches into selection while leaving the gating score itself unmodified. Only the LoRA weights and router parameters are trained (8.13M params, <0.2% of the 3.5B base), with the same FLOPs and deployment memory as the single-branch baseline.

## Results

On six mathematical reasoning benchmarks (GSM8K, MAWPS, AQuA, MultiArith, AddSub, SingleEq), MoDr achieves an average accuracy of 69.22%, improving by +7.2% over vanilla Huginn and +2.48% over Huginn-SFT. On six commonsense reasoning benchmarks (PIQA, HellaSwag, WinoGrande, ARC-E, ARC-C, OBQA), MoDr reaches 78.38% average accuracy, a +21.21% gain over Huginn (57.17%) and +1.52% over Huginn-SFT. The trainable parameters of MoDr constitute less than 0.2% of the base Huginn model (8.13M vs. 3.56B), with deployment memory and inference speed on par with the baseline (13 GB, 13 token/s).

## Baselines & Comparisons

MoDr consistently outperforms vanilla Huginn across all evaluated benchmarks: on mathematical reasoning it gains +7.2% average (with larger margins on out-of-domain tasks: +7.67% vs. +6.75% on in-domain), and on commonsense reasoning it gains +21.21% average. Against Huginn-SFT (LoRA fine-tuned single-branch), MoDr still improves by +2.48% on math and +1.52% on commonsense, confirming that the multi-branch routing mechanism adds value beyond simple fine-tuning. Compared to standard Transformer models of similar or larger scale (Llama-3.1-8B, OLMo-7B, Qwen2.5-3B), MoDr (3.5B, 0.8T tokens) achieves 78.38% average on commonsense reasoning, surpassing even the 8B Llama-3.1 (63.28%) and 7B OLMo (64.16%) by 15+ points, despite being trained on 10–15× fewer tokens. On the challenging Super-GPQA benchmark, MoDr (14.40%) marginally beats Huginn-SFT (14.07%) while both remain near random (10.59%), indicating room for improvement at this model scale. The ablation in Table 6 further shows MoDr (69.22% avg) substantially outperforms 8-shot CoT (60.24%), CoT with Majority Voting (63.56%), and full fine-tuning (42.56%) on mathematical reasoning.

## Relation to Prior Work

This paper extends the depth-recurrent transformer lineage (Universal Transformer → Looped Transformers → AlgoFormer → Huginn) by replacing Huginn's single recurrent 'Loop' module with a multi-branch dynamic relay system. Conceptually, it transplants the Mixture-of-Experts paradigm from the layer/sub-layer level (as in MoELoRA, MOLA, MixLoRA) to the block level within the recurrent module, using LoRA adapters as lightweight branch differentiators over shared backbone weights. The auxiliary-loss-free load balancing mechanism is directly adapted from Wang et al. (2024), and the hard-gate routing follows the Switch Transformer design, but applied to recurrent depth rather than feed-forward layers. The motivation draws an analogy between thought-structure hierarchies (chain → tree → graph) and the need for multi-branch exploration in latent space.

## Why It Matters / Open Questions

MoDr demonstrates that a single recurrent reasoning pathway is a genuine bottleneck in depth-recurrent transformers, and that multi-branch routing with negligible parameter overhead (<0.2%) can substantially improve reasoning across math, commonsense, and code tasks. The finding that full fine-tuning degrades Huginn performance dramatically (42.56% vs. 69.22% for MoDr) while LoRA fine-tuning works well is a practical insight for the recurrent-transformer community. Key open questions include: an efficient KV-cache strategy for deployment (acknowledged by the authors), whether the approach scales to larger recurrent models beyond 3.5B, and whether the branch specialization pattern generalizes to more complex reasoning tasks like Super-GPQA, where absolute performance remains low.
