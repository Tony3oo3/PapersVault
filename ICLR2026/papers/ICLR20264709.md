## Problem

Pretrained LLMs perform poorly on GUI-based web agent tasks because they lack prior understanding of the specific websites they must navigate. Existing unsupervised data collection methods either explore without concrete task guidance (interaction-first, causing redundant revisits across independent episodes) or propose tasks from a single static observation (instruction-first, limiting coverage to the initial page and risking hallucinated infeasible tasks). This paper addresses both limitations by structuring exploration as a graph traversal problem that reuses discovered webpages across episodes to achieve broader, more efficient coverage.

## Input / Output

The data collection pipeline takes a set of website root URLs and produces a dataset of (task, trajectory) pairs, where each trajectory is a sequence of flattened accessibility-tree observations paired with Python function-call actions (click, fill, goto, scroll, etc.). The trained agent consumes a task instruction, the current page's accessibility tree, and prior action history, and outputs a chain-of-thought followed by a single browser action. The released GO-BROWSE-WA dataset contains 9,504 successful and 17,245 failed trajectories (196K total steps) across 100 URLs in 5 WebArena domains, with alternate observation representations (accessibility tree, HTML, screenshots) included for each step.

## Method

GO-BROWSE frames web data collection as graph search over discovered URLs, with an outer loop maintaining a frontier of visited-but-unexplored webpages (analogous to BFS) and an inner loop that thoroughly explores each selected node. The inner loop uses three modules: NavExplorer (an LLM agent that navigates to neighboring pages and proposes navigation tasks via an extended add_tasks_to_dataset action), PageExplorer (an LLM agent that proposes local information-seeking and content-modification tasks grounded in the current page), and FeasibilityChecker (a strong LLM agent plus a VLM-as-a-judge that filters infeasible tasks before committing sampling budget). Feasible tasks are then solved by Solvers using both prefixed sampling (starting from the current page, decoupling navigation from local task execution) and unprefixed sampling (starting from the root, instilling long-horizon navigation behavior). This reset-then-explore strategy, inspired by Go-Explore in RL, enables weaker pretrained models to bootstrap higher-quality data by reducing the navigation burden, while the graph structure ensures broader website coverage than independent-episode methods like NNetNav.

## Results

On the WebArena benchmark (812 tasks), GO-BROWSE-7B achieves a 21.7% overall success rate, surpassing GPT-4o-mini (19.3%) by 2.4% and the previous state-of-the-art for sub-10B models, NNetNav-7B (18.8%), by 2.9%. The model also outperforms its pretrained base Qwen-2.5-7B-Instruct (8.3%) by 13.4%. On the out-of-domain Online-Mind2Web benchmark (300 tasks across 136 live websites), GO-BROWSE-7B scores 5.33%, still ahead of NNetNav-7B (4.00%) but behind GPT-4o-mini (9.33%).

## Baselines & Comparisons

GO-BROWSE-7B outperforms NNetNav-7B (18.8%) by 2.9% on WebArena overall, with particularly large gains on Shopping Admin (+11%) and Reddit (+7%), though it trails on Gitlab (15.3% vs. 19.9%). Against GPT-4o-mini (19.3%), GO-BROWSE-7B leads by 2.4% overall, winning on Admin, Shopping, Reddit, and Map but losing on Gitlab. The pretrained Qwen-2.5-7B-Instruct baseline (8.3%) is outperformed by a wide margin of 13.4%, confirming the value of structured exploration data. On the out-of-domain Online-Mind2Web benchmark, GO-BROWSE-7B (5.33%) still beats NNetNav-7B (4.00%) but falls well short of GPT-4o-mini (9.33%), suggesting limited generalization to truly unseen websites. Paired bootstrap tests confirm statistical significance over Qwen-2.5-7B-Instruct (p < 0.001) and show moderate confidence over GPT-4o-mini (p = 0.108) and NNetNav-7B (p = 0.094).

## Relation to Prior Work

GO-BROWSE adapts the reset-then-explore strategy from Go-Explore (Ecoffet et al., 2019; 2021) in RL to the web agent data collection setting, framing exploration as a graph traversal over discovered URLs rather than independent episodes. It synthesizes and extends two existing paradigms for unsupervised web agent data generation—interaction-first (NNetNav) and instruction-first (PAE, AutoWebGLM)—by using web agents themselves for grounded task proposal and by resetting exploration to previously discovered pages to decouple navigation from local task solving. The agent implementation follows the standard ReAct pattern on the BrowserGym/WebArena infrastructure, keeping the scaffolding minimal while the contribution lies in the exploration policy.

## Why It Matters / Open Questions

The paper demonstrates that structured, graph-based exploration is a practical and effective recipe for scaling web agent training data without human annotation, and that prefixed sampling enables bootstrapping from weaker pretrained models—a useful practical insight for resource-constrained settings. Key limitations include evaluation on only five WebArena domains, use of only successful trajectories for fine-tuning (leaving 39K failure trajectories untapped), and reliance on expensive frontier LLMs (Claude-3.7-Sonnet, GPT-4o) during data collection. Open questions include whether the approach generalizes to truly novel websites, whether RL-based objectives on failure trajectories could close the remaining gap to frontier models, and how to mitigate LLM-induced biases that propagate into agent behavior.
