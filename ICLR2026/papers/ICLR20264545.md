## Problem

Semi-structured web content (HTML tables, lists, infoboxes) is a major source of factual data, but reliably extracting structured triples from it at web scale remains unsolved. Traditional IE methods are brittle and fail to generalize, while LLM-based approaches require per-page inference, making them prohibitively expensive for millions of pages. The paper asks whether a model can learn to generate a single reusable extraction script per group of structurally similar webpages, achieving both generalization and resource efficiency.
![Teaser figure](../imgs/ICLR20264545/cropped_page1_idx0.webp)

## Input / Output

The model takes a single deduplicated HTML webpage as input, where repeated structural blocks are collapsed into 'n more …elements' placeholders (reducing typical token length from ~114k to ~17k) and non-semantic tags/attributes are stripped. It outputs a Python script (using BeautifulSoup) that, when executed on any structurally similar page in the same site group, yields a list of (subject, predicate, object) triples. The script is generated once per group and reused across all group members, so only one LLM call is needed per group rather than per page.

## Method

SCRIBES trains a Qwen2.5-Instruct model via Group Relative Policy Optimization (GRPO) with a cross-page generalization reward: for a group G of similar webpages, the reward averages the fuzzy F1 score of the generated script's output on every page in G, so the self-score contributes only 1/|G| while cross-scores dominate, explicitly incentivizing scripts that handle layout variations. Training proceeds in two stages: first on 192 human-annotated pages from SemiBench (34 groups) with gold-triple rewards, then iteratively on ~1,900 in-the-wild CommonCrawl groups where LLM-based direct extraction serves as synthetic annotation, restricted to failure cases where the model previously produced no valid triples. A structure-preserving HTML deduplication step (Algorithm 1, keeping z=3 repeated elements) is applied to all inputs to fit within the 32k context window. The resulting Q-32B model outperforms the strongest agentic baseline by 13.8% in F1^LM and, when its extracted triples are fed to GPT-4o for QA, boosts accuracy by over 4%.

## Results

On the SemiBench test set (56 groups, 65 webpages), the best SCRIBES model (Q-32B + CommonCrawl) achieves a macro-averaged F1^LM of 33.2 on the 'All' metric and 32.4 on the 'Holdout' metric, outperforming the same-size agentic baseline (Q-32B agentic-3-iter 2-shot, F1^LM = 19.4) by 13.8% and performing on par with the much larger GO-120B agentic baseline (F1^LM = 34.3). In downstream QA over semi-structured HTML, incorporating SCRIBES-extracted triples boosts GPT-4o accuracy from 82.5% to 86.6% (+4.1%) and Q-14B from 74.2% to 77.3% (+3.1%). On a 113K-page CommonCrawl subset, the model required only 4,661 direct LLM calls to extract 2,788,760 triples, demonstrating web-scale efficiency.

## Baselines & Comparisons

Against the direct LLM extraction baselines from Sun et al. (2025), SCRIBES Q-32B(+CC) (F1^LM = 33.2) trails the strongest per-page baseline GO-120B 2-shot flatten (F1^LM = 40.4) by ~7 points, but achieves this with a single script generation per group rather than an LLM call per page, yielding a linear token speedup of k/ρ ≈ k/3.7 as group size k grows. Against HippoRAG (Gutiérrez et al., 2024), SCRIBES substantially outperforms: Q-14B SCRIBES achieves F1^LM = 19.9 versus 16.1 for Q-14B + HippoRAG 2-shot, and Q-32B(+CC) reaches 33.2 versus 17.2 for GO-120B + HippoRAG 2-shot. Against AutoSchemaKG (Bai et al., 2025), the gap is even wider: SCRIBES Q-14B scores F1^LM = 19.9 versus 8.2 for Q-14B + AutoSchemaKG, and Q-32B(+CC) scores 33.2 versus 12.3 for GO-120B + AutoSchemaKG. The key advantage of SCRIBES over all agentic baselines is the cross-page generalization signal: the Holdout F1^LM gap between SCRIBES and same-size agentic baselines (e.g., 32.4 vs 16.4 for Q-32B) is far larger than the Example gap, confirming that the RL reward design specifically instills generalizability.

## Relation to Prior Work

SCRIBES draws a direct conceptual lineage from wrapper induction (Kushmerick et al., 1997), which learned reusable extraction procedures from labeled examples, but replaces brittle pattern-matching with LLM-generated executable scripts trained via GRPO. It departs from recent LLM-based KG construction pipelines (HippoRAG, AutoSchemaKG) that invoke a model per page by instead exploiting cross-page layout regularity within a domain as a reward signal, making the extraction amortized across structurally similar pages. The RL-without-annotations literature (Zuo et al., 2025; Shao et al., 2025) informs the iterative CommonCrawl training loop, but SCRIBES distinguishes itself by using LLM-based direct extractions as synthetic gold rather than relying solely on internal model signals.

## Why It Matters / Open Questions

The linear speedup with group size (k/ρ) makes web-scale semi-structured extraction computationally tractable in a way that per-page LLM inference is not, and the paper demonstrates this concretely (4,661 model calls for 113K pages). The finding that SCRIBES-produced triples boost GPT-4o QA accuracy by >4% suggests that even imperfect structured extraction is valuable downstream, opening the door to incorporating semi-structured web content into pretraining corpora that currently filter it out. Limitations include performance degradation on complex structures (nested lists, multi-column tables), reliance on a single model family (Qwen2.5) for RL training, and evaluation on a small annotated set (56 groups); scaling the CommonCrawl pipeline beyond the <1% crawl used here remains an open question.
