## Problem

Prior work on training LLMs with Code Interpreters (ToRL, ReTool) is restricted to math problems, and tool-selection approaches (ToolRL) use only simple code, leaving a gap for general-purpose code-augmented reasoning across diverse tasks. When standard DeepSeek-style GRPO is applied to a general Code Interpreter over 144 heterogeneous reasoning and planning tasks, gains are marginal (+3.4%) because task heterogeneity dilutes the reward signal and most samples are either too easy or too hard to provide useful gradient. The paper asks: how can one effectively train a single model to decide when and how to use code across hundreds of varied tasks?

## Input / Output

The model receives a single text question (e.g., a Blocksworld planning problem, a Sudoku grid, or a combinatorial calculation) and produces a multi-turn response that interleaves free-form reasoning text with optional Python code blocks (delimited by natural ```python tokens). Each code block is executed by an external sandbox, and the result is appended with a 'Code Execution Results:' prefix before the model continues generating. The loop repeats for up to 8 code calls until the model emits a final answer enclosed between <<< and >>>, after which rule-based evaluation (exact match or constraint checking) determines correctness. No forced section tags like <think> or <answer> are used; the model relies on its pretrained code-block conventions.

## Method

R1-Code-Interpreter is trained in two stages: (1) SFT on 6.5k multi-turn trajectories synthesized by GPT-4o with varied prompt strategies emphasizing adaptive code/text switching, and (2) GRPO where the policy π_θ(·|x; C) integrates external code execution, with code-execution tokens masked so gradients flow only through LLM-generated tokens. The key innovation is a multi-stage curriculum guided by measured improvement potential: four agent variants (All Text, All Code, Code Agent, CodeSteer) each sample 5 answers per question, yielding N=20 correctness labels; the potential score Π_i = 4p̂_i(1−p̂_i) is maximized at p̂_i=0.5, and samples are partitioned into four groups by Π_i, with GRPO training progressing from highest- to lowest-potential groups over four 150-step stages. A theoretical analysis (Cauchy-Schwarz bound on the policy-gradient norm) shows the usable signal scales with p(1−p), explaining why vanilla GRPO on mixed-difficulty data plateaus while the potential-ranked curriculum raises RL gains from +3.4% to +9.3%. A dedicated Code Execution Sandbox on five 64-core CPU nodes decouples code execution from GPU gradient computation, reducing total training time by 39%.

## Results

On 37 held-out test tasks spanning SymBench, Big-Bench-Hard, and Reasoning-Gym, R1-CI-14B achieves 72.4% average accuracy, up from 44.1% for the untrained Qwen2.5-14B-Instruct-1M baseline (All Text). This outperforms GPT-4o with textual reasoning (58.6%) by 13.8 points and GPT-4o with its native Code Interpreter (70.9%) by 1.5 points. The multi-stage curriculum learning with improvement potential raises RL gains from +3.4% (vanilla GRPO) to +9.3% across Qwen-2.5 3B/7B/14B models. On OOD tasks, R1-CI-14B reaches 50.2% on GPQA Diamond and 42.0% on AIME 2024&25, substantially exceeding its untrained counterparts (40.1% and 30.0% respectively).

## Baselines & Comparisons

Against GPT-4o, R1-CI-14B (72.4%) surpasses both GPT-4o All Text (58.6%) by 13.8 points and GPT-4o with its trained Code Interpreter (70.9%) by 1.5 points on the 37-task test suite, despite being a 14B open-source model fine-tuned on data synthesized by GPT-4o itself. Against CodeSteer (the prior code/text steering approach by the same group), R1-CI-14B improves test accuracy from 48.7% to 72.4% (+23.7 points), with the largest gains on SymBench (45.3% → 65.6%) and Reasoning-Gym (40.5% → 70.1%), while BBH scores are comparable (79.0% vs. 86.5%). The ablation variants confirm that both curriculum learning (R1-CI wo CL: 63.6%) and improvement-potential-based partitioning (R1-CI wo IP: 66.4%) contribute meaningfully, with the full method achieving the best result. On OOD benchmarks, R1-CI-14B also outperforms CodeSteer on GPQA (50.2% vs. 41.2%) and AIME (42.0% vs. 33.3%), indicating the gains generalize beyond the training distribution.

## Relation to Prior Work

This paper extends the GRPO framework (Shao et al., 2024) to integrate a Code Interpreter by masking execution tokens and computing policy gradients only over LLM-generated tokens, enabling hybrid text/code reasoning. It departs from prior RL+tool-use work (ToRL, ReTool) that was restricted to math problems, and from ToolRL which focused on tool selection with simple code, by training a general-purpose Code Interpreter across 144 diverse reasoning and planning tasks. The multi-stage curriculum learning guided by measured improvement potential (p(1-p) variance) is a novel departure from standard easy-to-hard curricula, motivated by a theoretical analysis showing that mixed-difficulty batches collapse the policy gradient signal.

## Why It Matters / Open Questions

This is the first open-source, general-purpose Code Interpreter trained via SFT + multi-stage RL, outperforming GPT-4o with its proprietary Code Interpreter on 37 held-out tasks. The theoretical characterization of why vanilla GRPO fails on heterogeneous data (Bernoulli variance p(1-p) vanishing at extremes) provides a principled, broadly applicable diagnostic for any RL training with sparse or mixed-difficulty rewards. Limitations include high training cost (~1845 GPU hours for 14B), increased inference latency from multi-turn code execution, and residual failures on tasks beyond the base model's inherent capabilities. Open questions include whether the improvement-potential curriculum generalizes to other tool-use settings (search, retrieval) and whether the approach scales to even larger task distributions.
