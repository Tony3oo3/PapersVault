## Problem

GUI-based computer agents, even when augmented with high-level planners, remain brittle and inefficient on long-horizon tasks because every operation must be executed through visual click-and-type sequences, accumulating errors over dozens of steps. No prior system treats direct programmatic execution (writing and running scripts) as a first-class action alongside GUI manipulation, leaving agents unable to bypass redundant interface navigation for backend operations like file management or data processing.
![Teaser figure](../imgs/ICLR20264317/cropped_page2_idx0.webp)

## Input / Output

The system receives an initial OS screenshot (pixel stream) and a natural-language task goal, then operates within a bounded step budget (15–150 system interactions). The Orchestrator consumes only condensed summaries and screenshots from executor agents rather than raw interaction logs, while each executor (Programmer or GUI Operator) sees the full screenshot plus its assigned subtask instruction. Outputs are a heterogeneous action trajectory mixing GUI primitives (clicks, drags, typing, hotkeys) with executed Python/Bash scripts, terminated by a completion signal when the Orchestrator judges the goal satisfied.

## Method

CoAct-1 introduces a hybrid action space A = A_GUI ∪ A_Code and implements it through a three-agent hierarchy: an Orchestrator (OpenAI o3) acts as a meta-policy that decomposes the user goal and dynamically delegates each subtask to either a Programmer (o4-mini) or a GUI Operator (OpenAI computer-use-preview). The Programmer engages in a multi-round coding-observation loop with a remote code interpreter, iteratively refining Python or Bash scripts until the subtask is solved; the GUI Operator runs a perception-action loop generating one visual action per step. Each executor maintains isolated short-term memory that is cleared after reporting back, and a dedicated summarizer (o4-mini) condenses the executor's full conversation into a concise summary plus final screenshot returned to the Orchestrator. This design lets the system replace long, error-prone GUI sequences with single-shot script execution for backend tasks while retaining visual interaction for frontend navigation, reducing average steps from ~15 (GTA-1) to 10.15 on OSWorld.

## Results

On OSWorld (369 tasks), CoAct-1 achieves a 60.76% success rate at 150 steps, surpassing the strongest agentic baseline Agent S2.5 w/ o3 (55.98%) by nearly 5 points. At the 100-step budget, CoAct-1 already leads with 59.93%, exceeding all baselines' final scores. On WindowsAgentArena (154 tasks), CoAct-1 reaches 52.5% at 100 steps, more than doubling the prior best (Agent S2 at 29.8%). In terms of efficiency, CoAct-1 completes tasks in an average of 10.15 steps versus 15.22 for GTA-1 and 14.90 for UI-TARS, while maintaining substantially higher success rates.

## Baselines & Comparisons

CoAct-1 outperforms all nine baselines on both benchmarks. On OSWorld at 100 steps, it leads Agent S2.5 w/ o3 (55.98%) by 3.95 points, GTA-1-7B w/ o3 (53.07%) by 6.86 points, and Jedi-7B w/ o3 (50.98%) by 8.95 points; the gap widens to 26.9 points over OpenAI CUA 4o (31.38%) and 36.9 points over OpenAI o3 (23.00%). The gains are most pronounced in Office (64.80% vs. 54.23% for Agent S2.5) and Multiple Apps (47.87% vs. 44.06%), where programmatic execution via the Programmer agent provides the largest advantage. On WindowsAgentArena, CoAct-1 (52.5%) more than doubles Agent S2 (29.8%) and Agent S (18.2%), and exceeds NAVI (19.5%) by over 33 points, with particularly strong results in Windows System (83.3%) and Windows Utils (77.7%) tasks that benefit from direct script-based interaction. Notably, CoAct-1 also achieves higher success with fewer average steps (10.15) than all competing agentic methods, indicating that the hybrid coding-plus-GUI design improves both accuracy and efficiency simultaneously.

## Relation to Prior Work

CoAct-1 extends the planner-grounder paradigm (GTA-1, Agent S2.5, Jedi) by introducing a fundamentally new execution modality: instead of routing all subtasks through GUI manipulation, the Orchestrator can delegate to a Programmer agent that writes and executes Python/Bash scripts directly against the OS. This departs from prior modular systems where even high-level planning ultimately funnels into pixel-level GUI actions, and from hybrid tool-calling frameworks (UFO-2, PyVision, ALITA) that compose pre-defined APIs rather than free-form code generation. The multi-agent orchestration infrastructure builds on AG2/AutoGen, and the GUI Operator leverages existing VLM-based computer-use models (OpenAI computer-use-preview), but the key architectural contribution is the dynamic, per-subtask modality selection between code execution and visual interaction.

## Why It Matters / Open Questions

The ~5-point SOTA improvement on OSWorld (60.76% vs 55.98%) coupled with a 33% reduction in average steps (10.15 vs 15.22) addresses a practical bottleneck: fewer steps means fewer opportunities for error propagation, which is critical for long-horizon deployment. The clean ablation (pure coding 35.73%, pure GUI 50.68%, hybrid 60.76%) validates that neither modality alone suffices, establishing a principled design space for future computer-use agents. Key limitations include heavy reliance on proprietary OpenAI models (o3, o4-mini, computer-use-preview), acknowledged hallucination issues in the Orchestrator's planning, and the inability to test open-source GUI operators due to GPU constraints—leaving open whether the hybrid paradigm transfers to fully open model stacks.
