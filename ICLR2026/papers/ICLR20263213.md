## Problem

Instructed code editing—where developers use natural language to request modifications to highlighted code—is a dominant interaction mode in AI coding assistants, yet no existing benchmark evaluates it on real-world data. Prior edit benchmarks (CanItEdit, EditEval, Aider Polyglot) rely on annotator-written or Leetcode-style problems with templated instructions, single natural language, and no highlighted-code or cursor-position context, failing to capture the ambiguity and diversity of actual developer workflows.

## Input / Output

Each problem provides a user instruction (often very short or a raw error trace, in one of 5 natural languages), the full code file (median ~4.5k tokens, up to 10k+ characters), a highlighted code segment (median 138 tokens), and the cursor position. The model must regenerate the entire code file as output, and success is measured by pass@1 against hand-written unit tests. A key design choice is that the model receives the whole file rather than just the highlighted region, forcing it to use surrounding context to disambiguate terse instructions like 'remove' or 'fix this.'

## Method

The benchmark is constructed via a purpose-built open-source VSCode extension that mimics Copilot/Cursor editing workflows, collecting user instructions, code context, highlighted segments, cursor positions, and model-response votes from ~500 real developers. From 2,672 accepted edits, the authors curate 109 core problems (filtering trivial, stylistic, or ambiguous cases) and hand-write test harnesses with a team of 5 multilingual programmers, using GPT-4o/Sonnet 3.7 only to generate example solutions for annotation guidance. Problems are then translated into 5 natural languages (English, Spanish, Russian, Chinese, Portuguese) following the HumanEval-XL protocol, yielding 540 total problems across Python and JavaScript. Evaluation ablates four context levels (code only, +highlight, +cursor, +highlight+cursor) across 40 LLMs, revealing that highlighted code improves performance for 5 of 7 top models while cursor position yields mixed results, and that only claude-sonnet-4 exceeds 60% pass@1.

## Results

Across 40 evaluated LLMs, only claude-sonnet-4 exceeds 60% pass@1, achieving 66.67% on EDIT-Bench (540 problems). Closed-source models dominate the top rankings, with only deepseek-chat-v3.1 and kimi-k2-0905 appearing among the top 10 open-weight models. Performance varies substantially by task category: bug fixing (52.2% avg), optimization (44.6%), and feature addition (39.6%). The gap between easy and hard problems averages 59.3% (std 10.6%), with hard problems featuring instructions ~5× shorter but slightly longer highlighted code.

## Baselines & Comparisons

EDIT-Bench shows only a weak positive correlation with Aider Polyglot (Pearson r=0.24, p=0.06, 17 shared models) and Chatbot Arena coding subset (r=0.11, p=0.01, 30 shared models), indicating it captures a distinct set of challenging edit tasks not reflected in existing leaderboards. Structurally, EDIT-Bench differs from CanItEdit (105 problems, 1 language, no highlighted code) and EditEval (194 problems, 1 language, no highlighted code) by including 5 natural languages, 2 programming languages, highlighted code segments, and in-the-wild user instructions that are significantly less templated. Compared to Aider Polyglot (225 problems from coding exercises), EDIT-Bench has 540 problems sourced from real developer workflows with much higher instruction length variance (238±738 chars vs. 606±885 chars) and comparable code context length (5642±7567 vs. 6184±6452 chars). The authors attribute the weak correlations to differences in interaction modality (code-centric input/output vs. freeform chat), the inclusion of contextual cues (highlighted code, cursor position), and the organic, messy nature of real-world user intent versus educational-style problem statements.

## Relation to Prior Work

EDIT-Bench extends the line of code editing benchmarks (CanItEdit, EditEval, Aider Polyglot, CodeEditorBench) by grounding problems in real-world user data collected via a VSCode extension rather than annotator-written or coding-exercise sources. It departs from prior work by introducing context-dependent elements—highlighted code segments and cursor position—that no previous edit benchmark included, and by following the HumanEval-XL translation methodology to expand to five natural languages. The paper positions itself as complementary to SWE-Bench (which targets multi-file agentic issue resolution) and Chatbot Arena (which evaluates freeform chat), filling the gap for single-file, instruction-driven edits in realistic IDE workflows.

## Why It Matters / Open Questions

EDIT-Bench is the first benchmark to evaluate instructed code editing with the full context a developer actually sees (instruction + file + highlight + cursor), and the finding that only 1 of 40 models exceeds 60% pass@1 underscores that current LLMs remain far from reliable in this interaction mode. The weak correlation (r=0.24) with Aider Polyglot suggests real-world editing captures a distinct difficulty axis that existing benchmarks miss, which matters for model selection in production coding assistants. Key open questions include whether the limited programming language coverage (Python, JavaScript) and the manual test-harness creation process generalize, and whether the automatic test-generation pipeline (which currently yields 0% pass@1) can be made viable to sustain continuous benchmark updates.
