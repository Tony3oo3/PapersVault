## Problem

Training effective VLM-based GUI agents typically requires large-scale datasets with human-annotated task instructions, which are labor-intensive and error-prone (e.g., AndroidControl required one year of paid annotation for 15,283 demonstrations). Moreover, supervised fine-tuning is suboptimal for GUI tasks because multiple action parameters can be functionally equivalent (any point within a button's bounding box is a valid click), causing cross-entropy loss to penalize valid alternatives. The paper asks: can VLMs be trained on large-scale unlabeled GUI trajectories using self-supervised signals and reinforcement learning to avoid annotation costs entirely?

## Input / Output

The model receives two GUI screenshots as input: the current state S_t and the target state S_{t+k} (the screen after k actions, k∈{1,2,3,4}), which together serve as a visual instruction pair replacing any textual task description. The output is a single structured JSON action enclosed in <answer>...</answer> tags, specifying one of eight action types (click, long_press, scroll, open_app, input_text, navigate_back, navigate_home, wait) with type-specific parameters such as pixel coordinates, scroll direction, app name, or input text. No explicit reasoning trace is generated, keeping the output compact and reducing inference overhead.

## Method

GUI-Shift introduces the K-step GUI Transition task, a self-supervised inverse-dynamics objective in which the VLM predicts the first action that transforms screenshot S_t into S_{t+k}, using the target screenshot itself as the visual goal rather than a textual instruction. Training employs GRPO (Group Relative Policy Optimization): for each sample the model generates N=8 candidate actions, each scored by a rule-based reward combining a binary format reward (correct <answer> tag structure) and an action reward that is tolerant to parameter multiplicity (e.g., a click is correct if the predicted point falls within the ground-truth bounding box, not at an exact coordinate). A data filtering pipeline pre-selects only those state pairs where the model's 8 sampled responses contain both correct and incorrect predictions, ensuring training samples are challenging yet learnable for each specific backbone. The framework is applied as one-stage RL fine-tuning (only the language model is optimized; vision encoder and projector are frozen) on just 2K filtered samples per K variant, with no reasoning traces, reducing training time by roughly 50% compared to reasoning-augmented baselines while matching or exceeding their downstream accuracy.

## Results

GUI-Shift achieves up to 11.2% EM improvement on AndroidControl-High (70.4% for GUI-Shift-Qwen, k=1) and 10.3% on AndroidControl-High for GUI-Shift-Mimo-SFT (73.4%), using only 2K self-supervised K-step GUI Transition samples. On GUI grounding, GUI-Shift-Mimo-SFT (k=1) reaches 90.1% on ScreenSpot-v2 (↑2.5%) and GUI-Shift-Mimo-RL (k=1) reaches 41.7% on ScreenSpot-Pro (↑1.5%). End-to-end on AndroidWorld, GUI-Shift-Mimo-SFT (k=3) improves Pass@1 success rate from 6.0% to 16.4%, and (k=4) improves Pass@5 from 18.1% to 25.9%.

## Baselines & Comparisons

On AndroidControl-High EM, GUI-Shift-Mimo-SFT (73.4%) surpasses UI-TARS-7B (72.5%), AgentCPM-GUI (69.2%), and InfiGUI-R1-3B (71.1%) while using only 2K samples versus their 32K–470K annotated samples; it trails UI-Venus-Navi-7B (76.1%, 350K samples) by 2.7%. GUI-Shift-Qwen (70.4%) exceeds AgentCPM-GUI (69.2%) but falls short of UI-TARS (72.5%) and InfiGUI-R1 (71.1%). On GUI Odyssey EM, all GUI-Shift variants remain below UI-TARS (87.0%) and AgentCPM-GUI (75.0%), with the best GUI-Shift-Mimo-SFT reaching 60.7%—the authors attribute this gap to 1,381 tablet episodes with substantially different layouts. On GUI grounding (ScreenSpot-v2), GUI-Shift-Mimo-SFT (90.1%) surpasses UGround-7B (76.3%), OS-Atlas-7B (84.1%), and UI-R1-E-3B (89.5%) but trails UI-Venus-Ground-7B (94.1%, 107K samples) and UI-TARS (91.6%). On ScreenSpot-Pro, GUI-Shift-Mimo-RL (41.7%) outperforms all annotation-trained baselines except UI-Venus-Ground-7B (50.8%), including UI-TARS (35.7%) and InfiGUI-R1 (35.7%). Overall, GUI-Shift with 2K self-supervised samples matches or exceeds models trained on 100K–470K annotated samples on AndroidControl, while remaining competitive but not dominant on cross-platform benchmarks like GUI Odyssey.

## Relation to Prior Work

GUI-Shift builds on GRPO (Shao et al., 2024) as its core RL algorithm and on the rule-based reward design popularized by DeepSeek-R1 (Guo et al., 2025), but departs fundamentally from prior GUI agent training by eliminating the need for annotated instructions entirely. Where prior RL-based GUI agents (UI-R1, GUI-R1, InfiGUI-R1, UI-Venus) still require human- or AI-annotated task instructions as training signals, GUI-Shift repurposes the inverse-dynamics formulation from robotics (Brandfonbrener et al., 2023; Tian et al., 2024) into a K-step GUI Transition task that uses only state pairs from unlabeled trajectories. This positions the work at the intersection of self-supervised representation learning and rule-based RL, extending MobileVLM's one-step action prediction to multi-step transitions and replacing SFT with GRPO.

## Why It Matters / Open Questions

The practical significance is substantial: GUI-Shift shows that 2K self-supervised samples can match or exceed models trained on 100K–470K annotated samples, directly addressing the annotation bottleneck that has limited GUI agent scalability (e.g., AndroidControl required one year of paid annotation for 15K demonstrations). The finding that a visual target state outperforms human-annotated textual instructions as a training signal challenges the assumption that natural language instructions are necessary for GUI agent training. Limitations include evaluation restricted to Android/mobile GUIs (with minor drops on tablet layouts), modest gains on high-resolution desktop grounding (ScreenSpot-Pro), and the approach's dependence on existing trajectory data. Open questions include whether the K-step formulation transfers to desktop/web GUIs, whether larger K or longer trajectories yield further gains, and whether the data filtering mechanism generalizes to domains with sparser action spaces.
