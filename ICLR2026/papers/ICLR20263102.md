## Problem

Existing agent benchmarks either focus on single-turn function-calling accuracy, impose rigid domain-specific policies that constrain autonomous exploration, or inadequately model users as stochastic environmental components. This leaves a significant gap between controlled laboratory settings and the inherent complexity of real-world deployments, where agents must process extensive information, navigate interdependent tool sets, and manage dynamic multi-turn user interactions simultaneously.
![Teaser figure](../imgs/ICLR20263102/cropped_page0_idx0.webp)

## Input / Output

The agent receives an initial user request plus a set of 66 tools (across delivery, in-store, and OTA domains) and interacts with both a simulated user (who progressively discloses requirements across 50–100 turns) and deterministic database APIs. The output is a binary all-or-nothing success score computed by a rubric-based sliding window evaluator that tracks satisfaction of k atomic criteria (e.g., 'restaurant within 500m', 'user only eats vegetarian food') across overlapping 10-turn windows with 2-turn overlap, resetting a criterion to unsatisfied if a previously correct conclusion is later overturned.

## Method

VitaBench formalizes each task as a POMDP where the state space decomposes into database state (deterministic Python transitions) and user state (stochastic LLM-driven transitions), and models the 66-tool set as a directed graph whose edges encode inter-tool dependencies via preconditions and postconditions—eliminating verbose policy documents while naturally encoding domain rules. A user simulator with configurable personas (impatient, anxious, scattered, dependent, cooperative) progressively reveals composite instructions and provides implicit constraints only upon inquiry, introducing controlled stochasticity. The key evaluation contribution is a rubric-based sliding window evaluator that processes long trajectories in sequential segments while maintaining a persistent binary state vector across windows, achieving Cohen's κ ≥ 0.81 agreement with human annotators. Tasks are constructed by synthesizing multiple authentic user requests into composite objectives spanning single-domain (300 tasks) and cross-domain (100 tasks) settings, each equipped with independent databases containing 5–20 service providers and up to 100+ products with deliberate distractors.

## Results

On VitaBench's 100 cross-scenario tasks (the main result), the best-performing model o3(high) achieves only 30.0% Avg@4 and 61.0% Pass@4, with Pass^4 dropping to just 6.0%. On single-domain tasks, performance is substantially higher: o3(high) reaches 53.5% Avg@4 on Delivery, 53.5% on In-store, and 37.8% on OTA, while LongCat-Flash-Thinking leads In-store at 56.8% Avg@4. Thinking models consistently outperform their non-thinking counterparts (e.g., Claude-4.1-Opus improves from 21.8% to 29.0% on cross-scenario Avg@4), and the Pass^4 metric reveals severe instability even for top models, with most achieving near-zero consistency across four runs.

## Baselines & Comparisons

The benchmark evaluates 20+ models across four domains. o3(high) leads on three of four domains (Cross-Scenario 30.0%, Delivery 53.5%, OTA 37.8%), while LongCat-Flash-Thinking edges ahead on In-store (56.8% vs. o3's 53.5%). Among non-thinking models, Claude-4.1-Opus is the strongest (21.8% cross-scenario, 53.8% in-store), outperforming GPT-4.1 (13.8% cross-scenario) by roughly 8 points on the hardest setting. Thinking variants consistently beat their non-thinking counterparts: Claude-4.1-Opus gains 7.2 points on cross-scenario (21.8→29.0) and GLM-4.5 gains 2.8 points (20.0→22.8). The dramatic cross-scenario penalty (30% vs. 50%+ on single domains) is consistent across all model families, indicating a shared architectural limitation in navigating expanded action spaces rather than a model-specific weakness. Smaller or older models (DeepSeek-V3-0324, Qwen3-32B) struggle severely, scoring below 5% on cross-scenario tasks, highlighting the benchmark's sensitivity to model capability.

## Relation to Prior Work

VitaBench builds directly on the τ-bench family (Yao et al., 2024; Barres et al., 2025), which pioneered stateful tool-agent-user interaction with progressive information disclosure, but departs by eliminating verbose domain-specific policies in favor of a graph-based tool dependency structure that encodes domain rules into pre/post-conditions. It extends the broader line of agent benchmarks (ToolSandbox, DialogTool, UserBench) by simultaneously addressing all three complexity dimensions—reasoning, tool, and interaction—rather than isolating them, and introduces cross-scenario composition (66 tools across three domains) that no prior benchmark supports. The rubric-based sliding window evaluator draws on recent rubric-based LLM-as-judge methods (Arora et al., 2025; Ruan et al., 2025) but adapts them to long-horizon multi-turn trajectories with persistent state tracking.

## Why It Matters / Open Questions

The finding that even o3 achieves only 30% on cross-scenario tasks, with Pass^4 near zero for all models, reveals a fundamental stability gap in current agents that single-domain benchmarks mask. The counterintuitive result that in-store (largest search space, 3,277 products) is easier than delivery (788 products) challenges the assumption that database scale drives difficulty, pointing instead to constraint coordination and spatial-temporal reasoning as the true bottlenecks. Open questions include whether RL can exploit the large Pass@k vs. Pass^k gap (exploration helps but consistency doesn't), whether agents can develop better self-awareness to avoid abandoning solvable subtasks, and whether the three-dimensional complexity framework generalizes beyond life-serving domains.
