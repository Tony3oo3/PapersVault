## Problem

Native Sparse Attention (NSA) achieves substantial FLOPs reduction for long-context LLMs, but its kernel implementation requires a large number of query heads per GQA group (≥8) to avoid padding before executing warp-level matrix multiply instructions. Since most popular LLMs (Llama3, Qwen) use only 1–4 query heads per GQA group, the vanilla NSA kernel wastes significant memory bandwidth and tensor-core cycles on padded data, preventing the theoretical sparsity gains from translating into wall-clock speedups.

## Input / Output

FSA consumes the standard Q, K, V tensors (N × d × h and N × d × h_K) together with a pre-computed sparse selection tensor T ∈ R^{h_K × N × T} that records which KV blocks each query token attends to. Rather than producing a single final attention output in one pass, FSA's token-selection kernel writes partial (un-normalized) attention results into a compact intermediate buffer O_buf sized only for the valid query tokens per KV block, which a separate reduction kernel then accumulates with online-softmax scaling into the final output tensor. In the backward pass, the same two-stage structure produces partial gradients that are reduced analogously.

## Method

FSA inverts the two-level loop order of the NSA kernel: the outer loop iterates over KV blocks (one per thread block) while the inner loop processes batches of non-contiguous query tokens that attend to that block. Because the number of query tokens attending to a given KV block (≈ NT/b on average) far exceeds the hardware minimum of 8, no padding is needed, eliminating the wasted memory accesses and FLOPs that plague NSA at small GQA group sizes. To handle the resulting non-contiguous query access, FSA pre-computes index tensors I_i and O_i that map valid query indices to compact buffer positions, and employs early-return to skip empty query batches. A dedicated online-softmax kernel pre-computes running maxima and log-sum-exp statistics per (query, KV-block) pair, avoiding incorrect partial statistics when multiple thread blocks process the same query. Finally, a separate reduction kernel accumulates partial results across KV blocks without atomic operations, using the compact O_buf to minimize HBM overhead (≈1 GB for 64K tokens, T=16, d=128).

## Results

FSA achieves up to 3.5× and on average 1.6× kernel-level latency reduction over vanilla NSA, and up to 6.4× and on average 2.4× over full attention (Flash Attention) on H20 GPUs. For end-to-end training, FSA delivers up to 1.25× and 1.09× average speedup over NSA, and up to 2.47× and 1.86× average over full attention. Inference prefill sees up to 1.36× and 1.11× average speedup over NSA, and up to 1.69× and 1.39× average over full attention. Gains are most pronounced at small GQA group sizes (g=1,2) and longer sequence lengths (32K–256K tokens).

## Baselines & Comparisons

Against vanilla NSA (Yuan et al., 2025), FSA consistently wins: up to 3.5× kernel speedup (at g=1, 32K tokens on H20), up to 1.25× end-to-end training speedup, and up to 1.36× prefill speedup; the gap widens as GQA group size shrinks below 8 query heads. Against full attention via Flash Attention (Dao, 2023), FSA achieves up to 6.4× kernel speedup and up to 2.47× training speedup on long sequences, while vanilla NSA actually lags behind full attention in several small-GQA configurations (e.g., g=1, 32K tokens). Against FlashDecoding (Dao et al., 2023) in the decoding phase, FSA achieves an average 5.46× speedup on H20 and 2.16× on H200, benefiting from loading only a sparse subset of KV tokens. FSA matches NSA on decoding latency (both exploit sparsity), and correctness is validated by matching loss curves and QA F1 scores on HotpotQA, Qasper, and PassR-EN across Llama-3.2-1B/3B and Llama-3.1-8B.

## Relation to Prior Work

This paper is a direct systems-level extension of Native Sparse Attention (NSA) by Yuan et al. (2025), which introduced natively trainable, hardware-aligned sparse attention with three parallel modules (compression, selection, sliding window). The key departure is in kernel implementation: FSA inverts NSA's two-level loop order (iterating KV blocks in the outer loop and query tokens in the inner loop, rather than the reverse), eliminating the padding waste that plagues NSA when GQA groups contain fewer than 8 query heads. The design draws on Flash Attention's (Dao, 2023) established two-level loop paradigm and online softmax technique, but adapts them to the irregular access patterns inherent to sparse token selection. It also relates to FlashDecoding (Dao et al., 2023) for the inference decoding phase, where FSA's sparsity provides an advantage over the dense KV partitioning strategy.

## Why It Matters / Open Questions

FSA addresses a critical practical gap: NSA was proposed as a state-of-the-art sparse attention method, but its kernel only achieves efficiency when GQA groups have ≥8 query heads, whereas most modern LLMs (Llama3, Qwen) use 1–4 heads per group, causing NSA to underperform even full attention in many configurations. By making sparse attention kernels work across the full range of popular GQA settings, FSA unblocks the practical deployment of NSA-based long-context training and inference. Open questions include whether the loop-inversion strategy generalizes to other sparse attention mechanisms beyond NSA, whether the non-contiguous memory access and intermediate buffer overhead become prohibitive at extreme sequence lengths (>256K) or on future GPU architectures with different memory hierarchies, and whether the online profiling/fallback mechanism adds unacceptable latency in production serving.
