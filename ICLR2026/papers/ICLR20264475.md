## Problem

Existing drift detectors (e.g., ADWIN, KSWIN) signal when a concept drift occurs but are silent on how much post-drift data is needed for a stable retraining. Retraining too early risks overfitting to transient noise, while waiting too long prolongs the use of a stale pre-drift model. This paper formalizes the post-drift data sufficiency problem: given an external drift alarm, estimate the minimum window size that allows safe retraining without actually retraining the downstream model.

## Input / Output

The method consumes a multivariate time series stream {x(t) ∈ R^d} and an external drift alarm at time t_s; it operates solely on the growing post-drift window X_t = {x(t_s), …, x(t)} with no access to model internals or post-drift test labels. It outputs a binary retraining trigger R(X_t) ∈ {0,1} and the corresponding estimated data size n*, which is the first window length at which the trigger fires. The procedure is both detector-agnostic (works with ADWIN, KSWIN, or any alarm source) and model-agnostic (the downstream predictor—KRR, MLP, Transformer, ExtraTrees—is treated as a black box).

## Method

CALIPER exploits state dependence in dynamical systems: if x(t+1) = f(x(t)) + ξ_t, nearby states exhibit similar one-step transitions, so data sufficiency reduces to testing whether the post-drift window displays adequate local consistency. Concretely, at each new sample the window is normalized, split into reference pairs (x(s), x(s+1)) and a query pair, and a weighted local regression is solved for each θ on a fixed grid Θ = {0, 0.1, 1, 2, 4, 8, 16}, where kernel weights w_i(θ) = exp(−θ·r_i) upweight nearby references. An effective sample size (ESS) gate at the tightest locality θ_max ensures the neighborhood is sufficiently populated (ESS ≥ C(d+1)). The trigger fires when the accumulated one-step proxy error is monotonically non-increasing across the θ grid, indicating that tighter locality consistently improves predictability—a signature of state dependence. Proposition 1 provides a formal guarantee: under a locally Lipschitz dynamical model with sub-Gaussian noise, passing the monotone-locality test with a positive margin implies stronger state dependence (in the sense of conditional neighbor-preservation probability) than a window that fails the test, and data-dependent generalization bounds link this stronger state dependence to tighter test-train gaps for retraining.

## Results

Across four datasets (MoCap, TEP, Automobile, Dysts), three model families (KRR, MLP, Transformer), and two drift detectors (ADWIN, KSWIN), CALIPER matches or exceeds the best fixed retraining window (128/512/2048) without per-dataset tuning. The most dramatic gains appear against incremental updates: on MoCap with MLP, CALIPER achieves MSE 7.106 vs. 412.6 for incremental (≈58× reduction), and on Dysts with MLP, MSE 0.432 vs. 71.75 (≈166× reduction). Per-step wall-clock time is essentially flat and negligible relative to the base learner, confirming that CALIPER's weighted local regression adds no meaningful overhead. The optimal fixed data size varies widely across settings (e.g., MLP on TEP peaks at 512 but is worst at 512 on MoCap), underscoring that no single fixed window is universally optimal.

## Baselines & Comparisons

CALIPER is compared against two families of baselines: (1) fixed post-drift retraining windows of 128, 512, and 2048 samples, and (2) incremental online SGD updates without explicit retraining. Against fixed windows, CALIPER consistently matches or exceeds the best fixed size across all four datasets, three model families, and both detectors, without any per-dataset hyperparameter tuning; the optimal fixed size shifts dramatically (e.g., 512 is best for MLP on TEP but worst on MoCap), making a priori selection unreliable. Against incremental updates, CALIPER delivers large and consistent gains: on MoCap with MLP, MSE drops from 412.6 to 7.106 (ADWIN) or 7.449 (KSWIN), and on Dysts with MLP from 71.75 to 0.432/0.467. The one exception is Automobile with Transformer, where incremental slightly edges CALIPER (MSE 1.866 vs. 1.948–2.070), though the gap is modest. Computational overhead is negligible: per-step wall-clock time for CALIPER is on par with fixed-window baselines, with occasional spikes attributable to retraining itself rather than the CALIPER probe.

## Relation to Prior Work

CALIPER repurposes the state-dependence mechanism from nonlinear dynamics (Sugihara 1994; Hsieh et al. 2005, S-Map) — distance-weighted local regression over a library of past states — not as a forecasting tool but as a diagnostic for data sufficiency. It sits downstream of window-based drift detectors (ADWIN, KSWIN) that signal *when* drift occurs but are silent on *how much* post-drift data is needed for stable retraining. The method is deliberately model-agnostic and detector-agnostic, treating the downstream predictor as a black box, which distinguishes it from both drift-detection literature and model-adaptation approaches (fine-tuning, ensembling) that require access to model internals.

## Why It Matters / Open Questions

The paper fills a practical gap in streaming systems: after a drift alarm, practitioners must choose a retraining window size, and the optimal size varies widely across datasets and models (e.g., 512 is best for MLP on TEP but worst on MoCap). CALIPER provides a single-pass, low-overhead criterion that adapts this choice data-dependently without retraining the model, which is critical for expensive architectures like Transformers. Open questions include extending the theoretical guarantees to non-Markovian and latent-variable dynamics, handling very high-dimensional feature spaces where distance-based neighborhoods degrade, and establishing tighter model-specific convergence links beyond the data-dependent generalization bound interpretation.
