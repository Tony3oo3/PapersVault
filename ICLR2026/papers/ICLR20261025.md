## Problem

Cross-capability transfer between heterogeneous LLMs remains poorly addressed: existing model merging methods assume structurally identical models, full-parameter distillation risks catastrophic forgetting of the target's inherent capabilities, and PEFT-based approaches (e.g., LoRA) fail to absorb sufficient task knowledge from stronger source models, especially under preference optimization (DPO). The paper targets the gap of efficiently transferring and fusing capabilities across architecturally different LLMs while preserving the target model's general performance and enabling forget-free continual learning.
![Teaser figure](../imgs/ICLR20261025/cropped_page1_idx2.webp)

## Input / Output

The method consumes a target LLM (e.g., LLaMA-3.1-8B-Instruct), one or more heterogeneous source LLMs (e.g., Qwen-2.5-72B-Instruct, Mistral-Large, Gemma-2-27B), and synthetic training data generated from the sources. It produces a compact SkillPack—a compressed set of per-module parameter deltas (pruned, SVD-decomposed, and mixed-precision quantized) stored at roughly 5–10% of the full delta size—which is then additively grafted onto the target model. A lightweight router (a 4-layer feed-forward network or a deterministic task-type mapping) selects which SkillPack to activate at inference, enabling multi-task fusion without parameter conflicts.

## Method

GraftLLM first fine-tunes the target model end-to-end via SFT followed by DPO using data distilled from source models, then extracts the full parameter delta Δθ = θ_tgt* − θ_tgt. The key innovation is a module-aware adaptive compression strategy that applies different operators per architectural component: magnitude pruning (retaining top-α weights) for Embedding and Output Head, low-rank SVD truncation for Attention projection matrices (exploiting their fast-decaying singular value spectrum), and conservative energy-threshold SVD (retaining ranks up to cumulative variance β) for MLP modules to preserve critical nonlinear transformations. Each SVD component is further compressed via group-wise GPTQ mixed-precision quantization with adaptively assigned bit-widths. At inference, a router selects the relevant SkillPack(s) for the input, and the decompressed delta is added to the base model parameters, yielding a fused model that combines multiple source capabilities while keeping the original target weights untouched—enabling forget-free continual learning, modular unloading for detoxification, and near-lossless multi-domain fusion.

## Results

On explicit heterogeneous LLM fusion (Table 1), Routed GraftLLM (9.2B params) achieves 16.56/25.42 on AlpacaEval 2.0 (Win Rate/LC Win Rate) and 7.70 average on MT-Bench, outperforming the best parameter-merging method (PCB-Merging+DARE, 7B: 11.96/17.35/7.39) and the best routing method (Twin-Merging r1024, 21B: 15.93/24.81/7.59) while using fewer parameters. On implicit fusion across 10 benchmarks (Table 2), GraftLLM achieves average scores of 56.0 (LLaMA-3.1-8B) and 63.2 (Qwen-2.5-7B), surpassing FuseChat-3 by 0.8 and 1.2 points respectively. In forget-free learning (Table 3), GraftLLM reaches 64.3 average across code and math benchmarks with 803M additional parameters, outperforming Model Tailor (62.2) and Model Grafting (61.3) by 2.1 and 3.0 points. On highly distinct domains (Table 4), GraftLLM (9.1B) achieves 99% of the 3×7B AdaptLLM reference (49.6 vs 49.7), versus 95% for FuseChat and 96% for Twin-Merging.

## Baselines & Comparisons

GraftLLM consistently outperforms all 18 baselines across every evaluation setting. Against parameter-merging methods (Task Arithmetic, TIES-Merging, PCB-Merging, DARE, InfiFusion), GraftLLM gains +4.6 to +5.9 on AlpacaEval LC Win Rate and +0.31 on MT-Bench average while using the same 7B base model. Against routing-based methods (Routed LoRA, Twin-Merging, TALL-Mask, EMR-Merging), GraftLLM achieves superior performance with substantially fewer parameters (9.2B vs. 14.1B–21B), e.g., beating Twin-Merging r1024 by +0.63 on AlpacaEval WR and +0.11 on MT-Bench 2nd Turn. Against multi-teacher distillation (FuseLLM), GraftLLM improves AlpacaEval LC Win Rate from 14.50 to 25.42 (+10.92). In implicit fusion (Table 2), GraftLLM edges out FuseChat-3 by +0.8 (LLaMA) and +1.2 (Qwen) average across 10 benchmarks, with the largest gains on GPQA-Diamond (+2.9/+4.2) and MATH (+1.1/+1.5). In forget-free learning (Table 3), GraftLLM surpasses Model Tailor by +2.1 average and Model Grafting by +3.0, with the largest gap on AMC23 (+7.5 over Model Grafting). On highly distinct domains (Table 4), GraftLLM (9.1B) matches 99% of the 3×7B AdaptLLM reference, outperforming FuseChat (95%) and Twin-Merging (96%) while using only ~30% additional parameters.

## Relation to Prior Work

GraftLLM extends the model grafting paradigm (Panigrahi et al., 2023; Ilharco et al., 2023) from homogeneous to heterogeneous LLMs by combining full-parameter fine-tuning with a module-aware adaptive compression strategy (magnitude pruning for embeddings, low-rank SVD for attention, conservative SVD + mixed-precision GPTQ quantization for MLPs) to produce compact, transferable SkillPacks. It departs from PEFT-based distillation (LoRA, Routed LoRA) by first extracting capabilities via full fine-tuning and then compressing, and from direct parameter merging (TIES-Merging, DARE, PCB-Merging) by introducing a routing mechanism that avoids cross-task parameter conflicts. The compression operators are adapted from DARE (pruning), Twin-Merging (SVD-based modular routing), and Delta-CoMe (mixed-precision quantization), but unified under a single module-aware framework specifically designed for heterogeneous capability transfer.

## Why It Matters / Open Questions

The SkillPack formulation offers a practical, modular unit for heterogeneous LLM fusion that supports forget-free continual learning, unlearning/detoxification (by simply removing a SkillPack), and multi-task composition via routing—capabilities that monolithic merged models lack. Key limitations include dependence on the quality of upstream SFT/DPO distillation, reduced compression effectiveness on harder preference-aligned tasks (DPO at 5% compression), and the need for full-parameter fine-tuning before compression, which remains computationally expensive. Open questions include whether automated, deployment-time compression can replace the current grid-search-based hyperparameter selection, and whether the approach scales to MoE architectures or very large model families with substantially different tokenizers.
