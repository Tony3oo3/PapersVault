## Problem

While static graph ML benefits from mature frameworks like PyTorch Geometric and DGL, temporal graph learning (TGL) lacks comparable infrastructure. Existing temporal graph libraries are narrow in scope—often supporting only a single architecture family—and the long-standing separation between continuous-time (CTDG) and discrete-time (DTDG) dynamic graph methods prevents direct comparison, fair benchmarking, and cross-paradigm idea transfer. Essential operations such as time-granularity conversion and graph discretization are also absent from all existing libraries.

## Input / Output

TGM consumes timestamped edge events (with optional edge feature vectors), node events carrying dynamic features, and static node feature matrices, all stored in an immutable time-sorted COO format. A key design choice is that CTDG and DTDG are not distinct data types but different iteration strategies over the same event stream—event-based iteration for CTDG and time-based iteration at a coarser granularity for DTDG. Outputs include link, node, and graph-level predictions, as well as discretized graph snapshots produced by a fully vectorized reduction operator that collapses duplicate edges within each time interval.

## Method

TGM introduces a hook formalism that decomposes temporal graph workflows into composable, dependency-ordered transformations (e.g., neighbor sampling, negative edge generation, device transfer), where each hook declares required and produced batch attributes and valid compositions form acyclic dependency graphs executable via topological sort. The framework unifies CTDG and DTDG by assigning each graph a native time granularity and defining a discretization operator that maps fine-grained events to coarser snapshots through equivalence-class grouping and a user-specified reduction. The software is organized in three layers—an immutable COO storage with lightweight graph views, a hook manager that resolves dependencies and executes transformations during data loading, and an ML layer that materializes batches on-device—supporting 8+ models spanning message-passing (TGAT, TGN), transformer (DyGFormer), and snapshot-based (GCLSTM, GCN, T-GCN) architectures. Efficiency gains (7.8× over DyGLib, up to 433× on discretization) stem from fully vectorized PyTorch-native implementations, including a circular-buffer recency sampler for cache-friendly temporal neighbor retrieval and batch-level de-duplication during evaluation.

## Results

TGM achieves an average 7.8× speedup in end-to-end training over DyGLib across multiple models and datasets, with a 4.4× speedup specifically on the transformer-based DyGFormer architecture (17.00s vs 75.10s per epoch on tgbl-wiki). On graph discretization, TGM's fully vectorized implementation delivers up to 433× speedup over UTG (0.05s vs 19.94s on LastFM). For correctness, TGM reproduces prior results: TPNet achieves the highest test MRR of 0.747 on tgbl-wiki for link prediction, while GCLSTM achieves the best test NDCG of 0.692 on tgbn-trade for node prediction, confirming that CTDG models excel at link prediction and DTDG models at node-level prediction.

## Baselines & Comparisons

Against DyGLib, TGM wins decisively on training time across all shared models and datasets (e.g., TGAT on tgbl-wiki: 6.97s vs 41.24s; DyGFormer on tgbl-lastfm: 142.40s vs 633.99s), and extends this advantage to validation where TGM is up to 246× faster (TGN on tgbl-wiki: 13.84s vs 3404.82s), owing to batch-level de-duplication. Against TGLite, TGM is slightly slower on TGAT and TGN (e.g., 6.97s vs 4.85s on tgbl-wiki) but uniquely supports transformer-based (DyGFormer), state-of-the-art (TPNet), and DTDG models (GCLSTM, GCN) that TGLite cannot run. Against TGL, TGM is faster on every comparable configuration (e.g., TGN on tgbl-lastfm: 91.23s vs 250.00s). For graph discretization, TGM outperforms UTG by 49–433× (Table 5), and for node property prediction, TGM beats both DyGLib and native TGB implementations (e.g., TGN on tgbn-trade: 12.94s vs 19.37s DyGLib vs 11.07s TGB; DyGFormer on tgbn-genre: 70.89s vs 3539.95s DyGLib). TGM is the only library supporting all five comparison baselines' tasks simultaneously, including the one-vs-many TGB evaluation protocol that TGL and TGLite lack.

## Relation to Prior Work

TGM extends the proof-of-concept unification of continuous-time (CTDG) and discrete-time (DTDG) temporal graph models introduced by UTG (Huang et al., 2024) into a full research library, replacing UTG's slow, limited implementation with fully vectorized graph discretization and time-iteration operations. Conceptually, TGM departs from prior libraries (DyGLib, TGL, TGLite, PyG Temporal) by treating CTDG and DTDG not as distinct data types requiring separate pipelines, but as different iteration strategies over a single event stream, formalized through a novel hook composition mechanism. The library implements models spanning both paradigms—temporal message passing (TGAT, TGN), transformer-based (DyGFormer, TPNet), and snapshot-based (GCN, GCLSTM, T-GCN)—within a unified API, addressing the fragmentation that has hindered cross-paradigm comparison in the field.

## Why It Matters / Open Questions

The unification of CTDG and DTDG under a single framework enables research questions previously impractical to study, such as dynamic graph property prediction and systematic comparison of snapshot granularity effects on model performance. The finding that evaluation batch size and temporal unit are critical, previously overlooked hyperparameters (RQ3) challenges the assumption that evaluation protocol is a fixed choice and may require re-examination of prior benchmark results. The 7.8× training speedup and 175× discretization speedup make large-scale temporal graph experimentation substantially more accessible. Open questions include whether the hook abstraction scales to more complex multi-hop temporal reasoning, how the framework handles heterogeneous temporal graphs and temporal knowledge graphs (not yet supported), and whether the CTDG-vs-DTDG complementarity observed (CTDG for links, DTDG for nodes) generalizes across domains.
