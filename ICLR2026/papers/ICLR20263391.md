## Problem

Generating high-fidelity scientific architecture diagrams from natural language descriptions remains largely unexplored due to the absence of a clean, large-scale, open-access dataset with aligned text-code-image triplets. Existing scientific figure datasets (ACL-Fig, Paper2Fig) mix heterogeneous diagram types, lack consistent architectural labeling, and do not provide structured code representations, leaving no effective open models or benchmarks for this task.
![Teaser figure](../imgs/ICLR20263391/cropped_page1_idx0.webp)

## Input / Output

The system takes a natural language description of a system architecture (averaging ~203 words, ranging from ~139 to ~600 words in robustness tests) and produces DOT graph code as an intermediate representation, which is then compiled by a standard Graphviz DOT compiler into a rendered architecture diagram image. The DOT output encodes labeled nodes and directed edges in a digraph structure, making it directly editable by human experts rather than a fixed raster image. Descriptions are stratified into easy (0–14 nodes), medium (15–24), and hard (25+) complexity buckets.

## Method

The TEXT2ARCH pipeline cures a 75,127-sample dataset from Paper2Fig through three stages: (1) a CLIP-based arch-vs-no-arch classifier (83.45% test accuracy, 0.92 recall) filters for architecture diagrams; (2) DOT code is generated via a multi-step process combining GPT-4o image-to-DOT extraction (DOT1), Faster-RCNN object detection with Florence-2 OCR for structural grounding (DOT2), and GPT-4o refinement of DOT2+image (DOT3); (3) descriptions are refined by TF-IDF-based paragraph retrieval from source PDFs followed by GPT-4o rewriting. For generation, the authors fine-tune 7B–8B parameter LLMs (DeepSeek-7B, Llama-3-8B, Qwen2-7B) via supervised fine-tuning on the text-to-DOT task, and evaluate alongside GPT-4o zero-shot, few-shot in-context learning, and the DiagramAgent baseline. A key design choice is using DOT code as the intermediate representation rather than direct image synthesis, enabling structured, editable, and semantically verifiable output. Evaluation combines standard NLG metrics (ROUGE-L, CodeBLEU, Edit Distance, chrF) with novel graph-level metrics (similarity-weighted node/edge precision, recall, F1, PR-AUC via Hungarian-algorithm matching, and Jaccard edge similarity) to assess both surface-level code quality and underlying structural fidelity.

## Results

On the 99-image manual annotation set, the fine-tuned DeepSeek-7B model achieves the best performance across nearly all metrics: ROUGE-L 55.2, CodeBLEU 49.3, Edit Distance 407, chrF 66.6, Node F1 69.4, Edge F1 49.1, and Jaccard similarity 39.8. On the larger 7,043-sample TEXT2ARCH test set, fine-tuned DeepSeek-7B similarly leads with ROUGE-L 46.8, CodeBLEU 34.5, Node F1 65.7, and Edge F1 38.0. GPT-4o zero-shot remains competitive on graph-level metrics (Node F1 63.0, Edge F1 46.2 on the manual set) but trails significantly on text-level code fidelity. A GPT-4o-based subjective evaluation (0–5 scale) scores DeepSeek-7B at 2.68, closely matching GPT-4o's 2.72 and substantially exceeding DiagramAgent's 2.37.

## Baselines & Comparisons

Against DiagramAgent (the primary external baseline), fine-tuned DeepSeek-7B wins decisively on every metric: ROUGE-L 55.2 vs. 49.1, CodeBLEU 49.3 vs. 40.9, Edit Distance 407 vs. 959, Node F1 69.4 vs. 54.3, and Edge F1 49.1 vs. 25.3 on the manual set, with similar margins on the full test set. Against GPT-4o zero-shot, DeepSeek-7B achieves substantially better text-level code fidelity (ROUGE-L 55.2 vs. 28.2, CodeBLEU 49.3 vs. 16.3) and edges out GPT on graph metrics (Node F1 69.4 vs. 63.0, Edge F1 49.1 vs. 46.2, Jaccard 39.8 vs. 37.8), while GPT-4o retains a slight advantage on Node Precision (69.7 vs. 66.1). The paper also reports that TEXT2ARCH outperforms Automatikz (Belouadi et al., ICLR 2024) on both the manual and test sets, though specific numbers are deferred to the appendix. In a human preference study, the fine-tuned model is preferred over DiagramAgent in 71.6% of paired comparisons, corroborating the quantitative gains.

## Relation to Prior Work

This paper positions itself as a focused extension of the text-to-diagram generation task introduced by DiagramAgent (Wei et al., 2024), narrowing the scope from eight heterogeneous diagram types to scientific architecture diagrams specifically, and replacing the multi-agent TikZ-based pipeline with a streamlined end-to-end DOT code generation approach. The dataset is built upon Paper2Fig (Rodriguez et al., 2023b) through extensive filtering with a trained CLIP-based architecture classifier, GPT-4o-assisted description refinement, and a hybrid DOT code generation pipeline combining GPT prompting, Faster-RCNN object detection, and Florence-2 OCR. Unlike diffusion-based text-to-image models (Stable Diffusion, DALL-E), which the authors argue are fundamentally unsuitable for structured diagram generation due to context window limits and inability to produce editable outputs, TEXT2ARCH generates intermediate DOT code that can be compiled, inspected, and manually corrected.

## Why It Matters / Open Questions

The 75K-sample TEXT2ARCH dataset fills a genuine gap: no prior open dataset provided clean, semantically aligned text-DOT-code-image triplets specifically for scientific architecture diagrams, making this a practical resource for the research community working on structured visual generation. The introduction of graph-level evaluation metrics (node/edge precision-recall via Hungarian matching, PR-AUC, Jaccard similarity) moves the field beyond surface-level text similarity toward assessing actual structural fidelity, which is arguably the core concern for diagram generation. Key limitations include reliance on GPT-4o for both data curation and evaluation (circularity risk), English-only scope, inability to handle dense connections or multiple self-loops, and the absence of preference-based alignment (DPO/RLHF). Open questions include whether the approach generalizes to other diagram types, alternative intermediate representations (TikZ, SVG), and multilingual settings.
