## Problem

Current evaluations of autonomous coding agents focus exclusively on static code correctness, implicitly assuming an infinite-resource environment. This ignores the real-world economic constraints—API token costs, execution time, and local testing compute—that become critical as the field scales toward large agent swarms. The paper asks: can frontier agents strategically balance accuracy, speed, and cost under a strict, depleting budget, or do they exhibit path-dependent, suboptimal resource management?

## Input / Output

Each agent receives 12 USACO problems (3 each at Bronze, Silver, Gold, Platinum) via a turn-based MCP protocol, where the server sends a JSON game state (remaining credit, current score, leaderboard) and the agent responds with a structured action (VIEW_PROBLEM, GET_HINT, SUBMIT_SOLUTION, TEST_CODE, or TERMINATE). The output is a weighted all-or-nothing score (Bronze=1, Silver=2, Gold=5, Platinum=10), total consumed credit broken into inference, hint, test, and penalty components, and a final competition rank. The credit budget (default 20M) is depleted by LLM inference tokens normalized by API price, five-tier hint purchases (500–1500 credits), test code execution (10 credits per request), and wall-clock time multiplied by an adjustable coefficient α, with an additional penalty of 100 credits per wrong submission affecting the tie-breaker.

## Method

USACOArena is an interactive, ICPC-style arena built on the Model Context Protocol that translates every agent decision into a unified credit economy. The design deliberately adopts the ACM-ICPC format (all-or-nothing scoring, penalty for incorrect submissions, 12-problem sets) over the IOI format to align with engineering values of breadth, robustness, and delivery speed. The unified credit model unifies LLM inference cost (normalized by per-token API pricing so expensive models consume proportionally more credit), a five-tiered hint system (from 500-credit strategic guidance to 1500-credit similar-problem retrieval via BM25 search), test code execution, and continuous wall-clock time into a single depleting budget, forcing the agent to solve max Score(π) subject to C_action(π) + α·T ≤ C_limit. To prevent data contamination, the problem corpus is a 'living benchmark' updated with each new USACO season. The paper then profiles 8 frontier models across four contests, conducts self-play experiments revealing path-dependent behavioral divergence (Success Loop vs. Panic Loop), performs systematic ablations across credit limits, hint/test costs, and scoring weights, and evaluates three swarm strategies (Speedy Spendthrift, Frugal Perfectionist, Cost-Aware Strategist) to quantify coordination overhead.

## Results

Across four USACO 2024–2025 contests (48 problems, 5 runs each), Gemini-2.5-pro achieves the best average rank (1.30 ± 0.47) and score (14.00 ± 3.88 out of a theoretical max of 54), while GPT-5-Codex ranks second (1.70 ± 0.47, score 9.39 ± 7.59). All remaining agents (Qwen3-235B, GLM-4.5, DeepSeek-V3/V3.1, Kimi-K2, Claude-4-Sonnet) score below 2.5, confirming a stark two-tier hierarchy. Notably, GPT-5-Codex reaches a peak score of 29 in isolated runs (vs. Gemini's 19), yet Gemini's aggressive exploration strategy yields a 70% win rate versus GPT-5-Codex's 30%, demonstrating that competitive strategy matters more than raw peak capability.

## Baselines & Comparisons

This is a benchmark paper, so the 'baselines' are the eight LLM agents evaluated under identical USACOArena conditions. Gemini-2.5-pro dominates GPT-5-Codex on average score (14.0 vs. 9.4) and win rate (70% vs. 30%), despite GPT-5-Codex achieving a higher peak score (29 vs. 19) and consuming roughly 3× less credit (4.7M vs. 13.8M). The gap between the top two and all other agents is dramatic: the next-best agent (GLM-4.5) scores only 2.33, less than 17% of Gemini's average. In the swarm experiment (Section 4.5), the Cost-Aware Strategist achieves a score of 8 in a fraction of the time of the Frugal Perfectionist (score 8, ~300 min), while the Speedy Spendthrift collapses to a score of 3 due to communication overhead. Self-play between identical Gemini-2.5-pro instances produces highly variable outcomes (no ties across 18 competitors), confirming the environment's sensitivity to path-dependent strategic choices rather than deterministic capability.

## Relation to Prior Work

This paper carves new ground by introducing a unified credit-economy evaluation paradigm for coding agents, departing from the static accuracy-only benchmarks (HumanEval, SWE-bench, LiveCodeBench) that the authors characterize as operating in a 'temporal vacuum.' It repurposes the ACM-ICPC competitive programming format and the USACO problem corpus as the evaluation substrate, but the key conceptual contribution is the translation of tokens, wall-clock time, and testing overhead into a single depleting budget that forces strategic trade-offs. The system architecture leverages the Model Context Protocol (MCP) for reproducibility, and the problem is formally framed as a Budget-Constrained POMDP, connecting to RL-based agent training literature (SWE-rebench, R2E-Gym) while explicitly distinguishing itself by rewarding process-level economic decisions rather than only final artifacts.

## Why It Matters / Open Questions

As the field scales toward deploying large agent swarms, the paper's core argument—that ignoring opportunity costs (API tokens, execution time, coordination overhead) will lead to catastrophic budget exhaustion—identifies a critical gap in current evaluation methodology. The finding that state-of-the-art agents are capability-limited rather than budget-limited (doubling the credit budget yields no improvement) suggests that the bottleneck is reasoning quality, not resource access, which redirects research priorities. Open questions include whether RL training on this environment can actually close the metacognitive gap (agents failing to purchase hints when stuck, misallocating resources on intractable problems), and whether the credit-economy abstraction generalizes beyond competitive programming to broader software engineering tasks. The self-play results showing path-dependent behavioral diversity validate the environment as a potential RL training ground, but no learning-based improvement has yet been demonstrated.
