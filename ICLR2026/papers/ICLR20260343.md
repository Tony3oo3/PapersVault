## Problem

Existing scientific paper QA benchmarks focus on narrow question types, rely on overly pre-processed text, and use one-size-fits-all evaluation metrics that lack generalization. Additionally, training interactive QA agents is hindered by the scarcity of high-quality, domain-specific interaction trajectories, since manual annotation is expensive and naive LLM generation fails to produce coherent action-observation sequences.
![Teaser figure](../imgs/ICLR20260343/cropped_page1_idx0.webp)

## Input / Output

For evaluation, the system takes a natural-language question paired with an explicit answer-format instruction (e.g., 'a Python list of two floats rounded to 3 decimals') and accesses raw PDF papers via a Milvus vectorstore and DuckDB database through ReAct-style tool calls (Retrieve, Query, Answer). For synthesis, EXTRACTOR takes sampled paper contexts (text, tables, images, formulas, metadata) and produces ShareGPT-format instruction data chunked via a sliding window of 5 messages, where only the last turn's loss is computed during training.

## Method

AirQA introduces 1,246 human-annotated questions spanning four types (single-doc, multi-doc, retrieval, comprehensive) and five element categories, each scored by one of 19 parameterized Python evaluation functions that yield binary 0/1 results at the instance level. EXTRACTOR is a three-agent pipeline: an Explorer generates natural-language QA pairs from sampled paper elements using chain-of-thought prompting, a Tracker selects and configures the appropriate evaluation function and refines the QA pair into a structured example file, and an Actor interacts with the environment via ReAct to collect multi-turn trajectories. Trajectories are chunked with a sliding window of 5 messages, and instruction data ending in wrong actions are discarded while earlier errors are retained to preserve error-correction capability. Fine-tuning uses LoRA (rank 16) on Qwen2.5 models with mask_history enabled, training only on the final assistant turn, which reduces the 7B model's error action rate from 38.69% to 6.85% and brings its overall score close to the untrained 14B model.

## Results

On AirQA with the Agentic Hybrid baseline, the best model (Gemini-2.5-Pro) achieves only 44.14% overall accuracy, while GPT-4o scores 35.96% and Qwen2.5-72B-Instruct scores 35.07%. Under the Question Only setting, even GPT-4o answers only 4.41% of questions correctly, confirming the dataset's difficulty. With EXTRACTOR fine-tuning on 4,000 trajectories, the 7B model improves from 15.24% to 24.07% overall, approaching the untrained 14B model (25.52%), while its error action rate drops from 38.69% to 6.85%. Human experts score 56.63% under a 20-minute time limit per question.

## Baselines & Comparisons

The paper evaluates 8 baselines (Question Only, Title-Abstract, Full-Text w/ Cutoff, RAG, Text2SQL, Agentic RAG, Agentic Text2SQL, Agentic Hybrid) and finds that Agentic Hybrid consistently outperforms all others, with GPT-4o scoring 35.96% vs. 18.30% for RAG and 13.40% for Text2SQL. Among models, proprietary systems lead: Gemini-2.5-Pro (44.14%) > Claude-3.7-Sonnet (36.52%) > GPT-4o (35.96%) > Qwen2.5-72B (35.07%), while reasoning model DeepSeek-R1 (29.29%) underperforms due to format incompatibility with the ReAct framework. For fine-tuning, EXTRACTOR with 4,000 trajectories lifts the 7B model from 15.24% to 24.07%, nearly matching the untrained 14B model (25.52%), and the 3B model from 7.38% to 20.22%. The 14B model shows diminishing returns (25.52% → 26.81%) because the teacher model (Qwen2.5-32B) itself scores only 31.94%, setting an upper bound for distillation. Ablation confirms that sliding window and error removal are both critical: removing error removal alone increases the error action rate from 6.85% to 20.32%.

## Relation to Prior Work

This paper extends the scientific paper QA benchmark lineage (QASPER, M3SciQA, SciDQA, LitSearch) by unifying four question types—single-doc detail, multi-doc analysis, paper retrieval, and comprehensive QA—into a single dataset with multi-modal elements (tables, images, formulas, metadata) and instance-level function-based evaluation via 19 parameterized Python functions, departing from prior work that typically targets one narrow question type with a fixed metric. For the agent training side, it builds directly on the ReAct framework (Yao et al., 2023) for multi-turn tool-use interaction and on AgentTuning (Zeng et al., 2023) for extracting instruction data from interaction trajectories, but introduces a three-agent synthesis pipeline (EXTRACTOR: explorer, tracker, actor) that automates both example generation and trajectory collection without human annotation.

## Why It Matters / Open Questions

The benchmark reveals a substantial capability gap: even the strongest frontier model (Gemini-2.5-Pro) achieves only 44.14% overall, and human experts score just 56.63% under time pressure, confirming that realistic multi-hop, multi-modal scientific QA remains far from solved. The EXTRACTOR framework demonstrates that 4,000 synthetic trajectories suffice to lift a 7B model's performance from 15.24% to 24.07% (approaching the untrained 14B at 25.52%) while reducing error action rate from 38.69% to 6.85%, offering a practical path for post-training small agentic models. Key open questions include whether the function-based evaluation generalizes beyond AI-domain English papers, whether RL-based training can close the remaining gap to frontier models, and whether the synthetic-data approach scales to other knowledge-intensive domains like law and medicine.
