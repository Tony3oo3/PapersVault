## Problem

Reasoning LLMs trained with RL excel at long-form textual reasoning but remain brittle on tasks requiring precise computation, symbolic manipulation, or geometric verification. Existing tool-use approaches (prompting, supervised fine-tuning) merely imitate curated data distributions and cannot learn adaptive strategies for when and how to invoke external tools. This paper asks whether RL can teach a model to autonomously discover optimal code-interpreter invocation patterns during reasoning, guided solely by outcome feedback.

## Input / Output

The model receives a mathematical problem as plain text and produces an interleaved reasoning trajectory that alternates between natural-language reasoning steps, fenced code blocks (delimited by `<code></code>` tags), and real-time sandbox execution results (wrapped in `<interpreter></interpreter>` tags). Generation dynamically pauses at each code-termination trigger, the code is executed in an external sandbox, and the output—whether a successful result or an error message—is appended before the model resumes. The trajectory terminates with a final numerical answer formatted inside `\boxed{}`, which is parsed for rule-based reward computation.

## Method

ReTool is a two-stage framework: (1) cold-start SFT on a synthetic dataset where text-based reasoning traces are automatically transformed to replace manual calculation steps with executable code snippets and their interpreter outputs, followed by format and answer verification; (2) PPO-based RL where rollouts dynamically interleave policy-model generation with real-time code execution in an asynchronous sandbox. During RL rollouts, the model generates text and code; upon detecting a `</code>` trigger, generation pauses, the code is sent to the sandbox, and the feedback (result or error) is injected within `<interpreter></interpreter>` tags before generation resumes, producing hybrid trajectories of the form [t₁ ⊕ c₁ ⊕ f₁ ⊕ … ⊕ o]. The reward is a simple binary accuracy signal (±1) on the final answer, deliberately omitting code-executability rewards to encourage diverse problem-solving behaviors. Engineering details include masking interpreter tokens from the loss, KV-cache reuse across code-execution boundaries to reduce memory, and a distributed asynchronous sandbox pool for parallel environment interactions.

## Results

On AIME2024, ReTool (Qwen2.5-32B-Instruct) achieves 67.0% accuracy with only 400 RL training steps, substantially outperforming the text-based RL baseline (40.0% at 1080 steps). With the stronger DeepSeek-R1-Distill-Qwen-32B backbone, ReTool reaches 72.5% on AIME2024 and 54.3% on AIME2025, surpassing OpenAI o1-preview by 27.9% on AIME2024. On broader benchmarks, ReTool (Qwen2.5-32B) scores 95.9% on GSM8K, 93.1% on MATH500, and 58.7% on GPQA (Diamond), while the DeepSeek-R1-Distill variant reaches 96.3%, 95.2%, and 62.3% respectively.

## Baselines & Comparisons

ReTool (Qwen2.5-32B) outperforms all 32B-scale baselines on AIME2024: it beats s1-32B (56.7%) by 10.3 points, QwQ-32B-Preview (50.0%) by 17.0 points, DeepSeek-R1-Zero-Qwen-32B (47.0%) by 20.0 points, and Sky-T1 (43.3%) by 23.7 points. Against the larger Qwen2.5-Math-72B-TIR (40.0%), ReTool gains 27.0 points on AIME2024 while using a model one-third the size. On AIME2025, ReTool (Qwen2.5-32B) leads o1-preview (37.9%) by 11.4 points and QwQ-32B-Preview (33.5%) by 15.8 points. The DeepSeek-R1-Distill variant extends the lead over o1-preview to 27.9 points on AIME2024 (72.5% vs. 44.6%). On GPQA, ReTool trails o1-preview (73.3%) by 14.6 points, indicating the tool-integrated approach is most effective for computation-heavy mathematical tasks rather than broad scientific Q&A.

## Relation to Prior Work

ReTool sits at the intersection of two established lines of work: RL-based reasoning (DeepSeek-R1, o1, QwQ, s1) and tool-integrated reasoning (PoT, PAL, MathCoder, Qwen2.5-Math-TIR). Prior tool-integrated approaches relied on prompting or supervised fine-tuning on curated code-augmented traces, which the authors argue limits generalization and prevents the model from learning *when* to invoke tools. ReTool departs by applying PPO with interleaved real-time code execution during rollout, using only outcome-based rewards, and positions itself against the concurrent ToRL work (Li et al., 2025b) by scaling to 32B and demonstrating substantially stronger results. The two-stage cold-start SFT + RL pipeline and the asynchronous sandbox with KV-cache reuse are practical engineering contributions layered on top of the standard PPO objective.

## Why It Matters / Open Questions

The paper demonstrates that RL can teach *strategic* tool use (timing, frequency, complexity) rather than merely *syntactic* tool use, with the behavioral evolution analysis (code ratio, lines, invocation timing, self-correction frequency) providing concrete evidence of this. The 40% reduction in response length and the generalization to web search suggest the framework is not a math-specific hack but a general mechanism for tool-augmented reasoning. Open questions include whether the approach extends to multi-tool or multi-agent settings, whether the emergent self-correction is robust across problem domains, and whether the gains persist at smaller model scales where exploration is more constrained. The reliance on a single backbone family (Qwen2.5-32B / DeepSeek-R1-Distill-32B) and a single tool (code interpreter) limits the breadth of the generalizability claims.
