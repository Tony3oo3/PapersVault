## Problem

Agentic benchmarks like GAIA, BrowseComp, and HLE are constrained by the high cost of human annotation, making large-scale expansion impractical (e.g., HLE required 1,000 experts for only 2,500 examples). Existing LLM-based data generation methods such as Self-Instruct target static instruction-following and cannot model the multi-step tool interactions and adaptive reasoning that agentic tasks demand. No prior workflow automates the generation of scalable, multi-tool, verifiable agentic tasks with controllable difficulty levels.
![Teaser figure](../imgs/ICLR20261489/cropped_page5_idx5.webp)

## Input / Output

The pipeline consumes an unlabeled corpus of webpages (75%), images (15%), and PDFs (10%) aligned to specific tool input indices (e.g., a stock-data URL, a PDF filename, an image path), along with available tool definitions. It produces 41k agentic tasks as (query, golden-answer) pairs spanning 1-to-7-hop difficulty, 12.6k full tool-interaction trajectories recording tool selection, parameters, observations, and plans, and 5k multi-hop sub-task decompositions. Tasks are structured so that the answer is only derivable after executing the required tool chain, and the dataset is formatted in a standardized JSON schema for direct use in SFT and RL training.

## Method

TaskCraft operates in three stages: (1) atomic task generation, where a tool is executed on an extracted input index i_T to retrieve context C, an LLM identifies candidate answers a and infers the answer-context relation R, then constructs a natural-language query q = f_q(i_T, R); (2) progressive task extension via depth-based (finding a strict superset index i_T^{n+1} of i_T^n through a search agent, deriving an intermediate sub-task, and recursively substituting to form (n+1)-hop queries) and width-based (merging independent sub-tasks into a single compound query) strategies; (3) incremental verification, where atomic tasks pass only if a tool-using agent succeeds while a bare LLM fails (rejection sampling), and extensions are validated purely by LLM-based linguistic checks for strict superset integrity and information leakage—avoiding full re-execution. A bootstrap few-shot learning loop iteratively optimizes four critical prompts to raise pass rates from 54.9% to 68.1% for atomic tasks and from 41.0% to 51.2% for depth-wise extension. The generated tasks and trajectories are then used for SFT (via OAgents trajectory sampling in TIR format) and RL (via DAPO) to train tool-integrated reasoning models.

## Results

On GAIA, 7.5k TaskCraft SFT alone achieves 60.2% with Qwen-2.5-32B-Instruct, surpassing all prior SFT+RL baselines (WebDancer 51.5%, SimpleDeepSearcher 50.5%, WebThinker 48.5%). Adding 8k TaskCraft tasks for RL (DAPO) pushes GAIA to 60.8%, BrowserComp to 24.8%, and HLE to 20.6%, setting new SOTA on all four agentic benchmarks. On WebWalker, the 7B TaskCraft model reaches 55.0%, exceeding the much larger Qwq-32B WebThinker (46.5%) and WebDancer (43.2%). Scaling from 1k to 5k TaskCraft tasks yields a clear upward trend on GAIA-103 (17.5% → 39.8%), confirming data scalability.

## Baselines & Comparisons

TaskCraft substantially outperforms all compared agentic baselines. On GAIA with Qwen-2.5-32B, 7.5k TaskCraft SFT (60.2%) exceeds WebDancer (51.5%), SimpleDeepSearcher (50.5%), WebThinker (48.5%), and WebSailor (53.2%)—all of which use both SFT and RL—by 6.7–11.7 points using SFT alone. On WebWalker, the 7B TaskCraft model (55.0%) surpasses WebThinker (46.5%) and WebDancer (43.2%) by 8.5 and 11.8 points respectively, despite being trained on a much smaller base model. On BrowserComp, TaskCraft achieves 22.4% (32B SFT) and 24.8% (32B SFT+RL), far exceeding WebSailor (10.5%) and WebDancer (2.8%). On HLE, TaskCraft reaches 20.2–20.6%, outperforming WebThinker (15.8%) and WebSailor (not reported for 32B). In the multi-hop QA ablation (Appendix C), SFT with TaskCraft data improves average accuracy by +14.0% over the Search-R1 baseline on Qwen2.5-3B-Base, confirming gains transfer to standard QA benchmarks as well.

## Relation to Prior Work

This paper extends the synthetic data generation paradigm (Self-Instruct, WizardLM, MetaMath) from static instruction-following to the agentic, multi-tool domain, where tasks require sequential tool invocations and adaptive reasoning. It builds on DSPy's bootstrap few-shot learning for prompt optimization and on Search-R1/DAPO for the downstream RL training pipeline, but its core contribution is a structured generation workflow—atomic task creation followed by depth-based (sequential multi-hop) and width-based (parallel sub-task) extensions with incremental LLM-based verification—that has no direct precedent in prior agentic data generation. The paper explicitly positions itself against benchmarks like GAIA and BrowseComp whose scalability is bottlenecked by human annotation, and against prior LLM-generated QA that lacks genuine tool dependency.

## Why It Matters / Open Questions

TaskCraft addresses a concrete and growing bottleneck: the inability to scale agentic training data beyond a few thousand human-annotated examples. The 41k-task dataset with 12.6k trajectories and 5k multi-hop decompositions, combined with a reproducible generation pipeline, gives the community a practical path to training tool-integrated reasoning models without prohibitive annotation costs. Open questions include whether the depth-extension mechanism captures genuine compositional reasoning or primarily surface-level nesting, whether the approach generalizes to tools beyond web/PDF/image search, and whether the observed SFT-only gains over SFT+RL baselines persist as base models scale further. The paper's reliance on a single LLM (GPT-4.1-class) for generation and verification also raises questions about error compounding at scale.
