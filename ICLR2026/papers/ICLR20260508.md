## Problem

Existing data-analytic agents are overwhelmingly built on proprietary models via prompt engineering or multi-agent scaffolds, while open-source models fail on diverse-format, large-scale data files and long-horizon multi-step reasoning. The paper identifies three concrete barriers to training open-source generalist data-analytic agents: insufficient high-quality trajectory data, an unstable SFT-then-RL training paradigm, and memory-intensive code-based multi-turn rollout that causes environment crashes.
![Teaser figure](../imgs/ICLR20260508/cropped_page0_idx0.webp)

## Input / Output

The agent receives a user query, a data file in CSV, XLSX, or SQLite format (filtered to 20–1,000 rows), and an optional data description. It iterates Thought-Action-Observation cycles (up to 10 rounds), where each action is a Python snippet (for tabular files) or a SQL query (for databases) executed in a sandboxed code interpreter. The final output is a structured answer enclosed in <answer> tags, with reasoning in <think> tags and code in <code> tags; environment feedback appears in <interpreter> tags.

## Method

DATAMIND is a four-part pipeline. For data synthesis, it applies an 18-category task taxonomy and a recursive easy-to-hard composition scheme (chaining 2–5 task types) over ~6,000 harvested data files to generate diverse multi-hop queries, then samples trajectories from DeepSeek-V3.1 with a knowledge-augmented workflow and filters them via self-consistency checking (N=3, GPT-4o-mini judge) plus a rescue loop that feeds the judge's critique back to the expert model. For training, it jointly optimizes an SFT loss and a DAPO RL loss with a dynamically annealed weight γ (cosine decay from 0.9 to 0.05), masking environment tokens and void turns to stabilize multi-turn RL. For rollout, it asynchronizes model generation and code execution, uses a chunked notebook-style code maintenance strategy that retains only textual snippets (concatenated at runtime) to reduce peak memory, and sandboxes each trajectory with per-trajectory CPU-time and memory caps. The resulting DATAMIND-12K (11,707 trajectories) trains 7B and 14B agents that outperform all proprietary and open-source baselines on DABench, TableBench, and BIRD.

## Results

DATAMIND-14B achieves a state-of-the-art average pass@1 of 71.16% across DABench, TableBench, and BIRD, outperforming the strongest proprietary baselines DeepSeek-V3.1 (70.58%) and GPT-5 (69.44%). DATAMIND-7B attains 68.10% average pass@1, the best among all open-source models, surpassing even the untrained Qwen-2.5-72B (67.02%). On pass@3, DATAMIND-14B reaches 80.25% and DATAMIND-7B reaches 79.07%, both exceeding all proprietary and open-source baselines. The 14B model leads on every individual benchmark: DABench 80.29%, TableBench 70.95%, and BIRD 62.23% (pass@1).

## Baselines & Comparisons

DATAMIND-14B (71.16% avg pass@1) outperforms all proprietary models: DeepSeek-V3.1 (70.58%), GPT-5 (69.44%), o4-mini (69.06%), DeepSeek-R1 (67.83%), and GPT-4o (63.85%). Among open-source untrained models, it surpasses Qwen-2.5-72B (67.02%), Llama-3.3-70B (61.45%), QwQ-32B (59.42%), and Qwen-2.5-Coder-32B (58.49%). Against task-specific trained baselines on the same 7B backbone, DATAMIND-7B (68.10%) dramatically outperforms OmniSQL (41.17%), SQL-R1 (40.83%), Table-R1 (36.53%), and TableLLM (29.90%)—despite using only 12K training samples versus 2.5M for OmniSQL/SQL-R1 and 20K for TableLLM/Table-R1. The 14B DATAMIND model also beats the Data Interpreter scaffold (60.70% on DABench) by nearly 20 points, demonstrating that agent training outperforms prompt-engineering-based scaffolds. Notably, specialized SQL models (OmniSQL, SQL-R1) achieve strong BIRD scores (~57–59%) but collapse on DABench and TableBench, whereas DATAMIND maintains balanced performance across all three benchmarks, reflecting its coverage of diverse file formats and task types.

## Relation to Prior Work

This paper builds on the ReAct agent paradigm (Yao et al., 2023) for the action loop, the DAPO algorithm (Yu et al., 2025) for the RL objective, and the dynamic SFT/RL weighting scheme (Zhang et al., 2025b) for training stability, but departs from prior data-analytic agents (DS-Agent, AutoKaggle, Data Interpreter) that rely on proprietary models and prompt engineering or multi-agent scaffolds. Unlike prior open-source trained models (TableLLM, Table-R1, OmniSQL, SQL-R1) that handle only simple table QA or text-to-SQL, DATAMIND introduces a systematic data-synthesis pipeline (fine-grained 18-category taxonomy + recursive easy-to-hard composition + knowledge-augmented trajectory sampling with self-consistency filtering) and a stable multi-turn code-execution rollout framework, positioning itself as the first work to systematically scale agent post-training data in the data-analytic domain.

## Why It Matters / Open Questions

DATAMIND-12K and the open-source DATAMIND-7B/14B models provide the community with a practical recipe for building generalist data-analytic agents without proprietary model access, and the 14B model's outperformance of GPT-5 and DeepSeek-V3.1 demonstrates that targeted post-training can close the gap with frontier models on domain-specific tasks. The empirical insights—particularly that SFT loss is simultaneously a stabilizer and a destabilizer for RL, that self-consistency filtering matters more than best-trajectory selection, and that RL narrows but cannot reverse base-model capability ordering—are broadly transferable to other agent-training settings. Key limitations include restriction to tabular data and textual queries (no visualization or predictive tasks), backbone limited to Qwen ≤14B, and RL runs capped at ~350 steps, leaving open whether the recipe scales to larger models, additional modalities, and longer RL horizons.
