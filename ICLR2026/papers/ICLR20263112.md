## Problem

While LLMs reliably generate individual functions or files, producing complete software repositories from scratch remains unsolved because it requires coherent planning at two levels—deciding what features to build and specifying how to implement them. Existing approaches (multi-agent frameworks, workflow pipelines, terminal agents) all rely on free-form natural language as the planning medium, which introduces ambiguity in intent-vs-constraint distinctions, makes dependency tracking fragile, and causes plans to drift and fragment over long generation horizons.

## Input / Output

The system takes a single high-level natural language description of a target repository (e.g., a paraphrased description of scikit-learn) and produces a complete, runnable Python codebase from scratch with no pre-existing skeleton. The intermediate artifact is the Repository Planning Graph (RPG), a directed graph whose nodes encode hierarchical capabilities mapped to files/classes/functions and whose edges encode inter-module data flows and intra-module execution order. Evaluation is performed on the newly introduced RepoCraft benchmark (6 real-world Python projects, 1,052 functional tasks), measuring functional coverage, novelty, test pass rate, and code scale (LOC, token count).

## Method

ZeroRepo constructs a Repository Planning Graph (RPG) in two planning stages before generating code. In proposal-level construction, an explore-exploit search over the EpiCoder Feature Tree (a 1.5M-node ontology of software capabilities) selects and refactors a repository-aligned subtree into a modular functionality graph, using LLM-guided filtering and cohesion/coupling-based reorganization. In implementation-level construction, the graph is enriched with folder/file layouts, typed inter-module data-flow edges, abstracted base classes, and concrete function/class interfaces at leaf nodes, yielding a fully specified DAG. Code generation then traverses the RPG in topological order, applying test-driven development at each leaf (derive tests → implement → validate → iterate), with graph-guided localization for debugging and staged validation (unit → regression → integration) to ensure correctness. The key insight is that replacing free-form language with an explicit, persistent graph representation enables near-linear scaling of both feature count and code size across iterations, whereas natural-language baselines stagnate.

## Results

On the RepoCraft benchmark (6 real-world Python projects, 1,052 tasks), ZeroRepo with o3-mini achieves 81.5% functional coverage and 69.7% test pass rate, surpassing the strongest baseline (Claude Code CLI) by 27.3 and 35.8 percentage points respectively. In code scale, ZeroRepo with Qwen3-Coder generates 36,941 LOC and 445,512 tokens—approximately 3.9× larger than Claude Code (10,587 LOC, 105,236 tokens) and ~68× larger than other baselines. ZeroRepo also demonstrates notable novelty, producing 151 novel functionalities (13.6% novelty rate) versus fewer than 10 for most baselines.

## Baselines & Comparisons

ZeroRepo dominates all seven baselines across every metric. Against the strongest baseline, Claude Code CLI (claude 4 sonnet), ZeroRepo (o3-mini) improves coverage from 54.2% to 81.5% (+27.3 pts) and pass rate from 33.9% to 69.7% (+35.8 pts), while generating 2.3× more LOC (23,977 vs. 10,587). Against Gemini CLI (gemini 2.5 pro), the gap widens to +39.5 pts in coverage and +55.2 pts in pass rate. Multi-agent frameworks (MetaGPT, ChatDev) and workflow systems (Paper2Code) remain far behind, with coverage below 31% and pass rates under 7%, reflecting the limitations of natural-language planning for long-horizon repository generation. Terminal agents (Codex CLI, OpenHands) show even weaker scalability, with Codex ceasing feature generation after 4–5 iterations. Notably, ZeroRepo with Qwen3-Coder produces the largest repository (36,941 LOC, 445K tokens), approaching the scale of human-developed Gold Projects (97,820 LOC, 951K tokens), whereas all baselines remain an order of magnitude smaller.

## Relation to Prior Work

This paper departs from the dominant paradigm of using natural language as the intermediate planning medium in repository-level code generation. Prior approaches span multi-agent role-playing (MetaGPT, ChatDev), fixed-pipeline workflows (Paper2Code), and iterative terminal agents (Claude Code, OpenHands, Codex CLI), all of which externalize plans as free-form text. ZeroRepo replaces this with a persistent, evolvable graph (RPG) that unifies proposal-level and implementation-level planning, drawing on the EpiCoder Feature Tree (Wang et al., 2025) as a 1.5M-node structured prior for feature enumeration. The topological-order traversal with test-driven development at each leaf node is a specific execution strategy that contrasts with the step-by-step natural-language refinement used by terminal agents.

## Why It Matters / Open Questions

The RepoCraft benchmark (6 real-world Python projects, 1,052 tasks) fills a genuine gap: prior benchmarks target incremental editing or require detailed skeletons, leaving from-scratch repository generation under-evaluated. The near-linear scaling of both feature count and LOC over 30 iterations is a practically important property for long-horizon generation, and the ablation showing that the graph structure (not the EpiCoder knowledge base) is the primary driver of scalability is a useful design insight. Limitations include evaluation restricted to six Python projects, a 69.7% pass rate still well below the 81% Gold-Project ceiling, and the asymmetric comparison where ZeroRepo leverages a 1.5M-node ontology while baselines do not. Open questions include whether RPG generalizes to non-Python ecosystems, monorepos with thousands of modules, and iterative (rather than from-scratch) development workflows.
