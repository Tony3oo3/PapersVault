## Problem

3D object editing remains bottlenecked at the training-free algorithm stage, unlike 2D image editing which has already progressed through dataset construction to feed-forward models. Existing 3D editing approaches—whether SDS-based optimization or multi-view-edit-then-reconstruct pipelines—suffer from poor cross-view consistency, slow inference, and failure to preserve unedited regions. Additionally, no large-scale, high-quality 3D editing dataset exists to bootstrap the next stage of supervised 3D editing research.

## Input / Output

The method requires only a source 3D object (voxelized into a sparse occupancy grid) and a natural-language editing instruction; no user-provided masks or part annotations are needed. A front-view rendering of the source object is automatically edited by a 2D model (Nano Banana or Flux-Kontext) to produce the target front-view, which together with the source front-view conditions the flow-based voxel editing. The output is an edited 3D object stored as a structured latent (SLat) and voxel grid, decodable via Flexicube into an explicit GLB mesh; the dataset stores only SLat + voxel sums to save storage.

## Method

Nano3D integrates FlowEdit into TRELLIS's first stage to perform training-free voxel geometry editing: it aligns the source and target generative trajectories to share the same noise, then iteratively updates the voxel along a rectified-flow editing trajectory driven by the difference of two velocity fields conditioned on the source and target front-view images, starting from the source voxel rather than random noise. To correct residual geometry inconsistencies, Voxel-Merge computes an element-wise XOR difference map between the source and FlowEdit-edited voxels, applies connectivity analysis to group modified elements into regions, selects regions exceeding a size threshold τ, and uses a binary mask to splice only the desired edited regions back into the source voxel. The same mask is then reused in TRELLIS's second stage as SLat-Merge, performing an analogous XOR-based merge on the structured latent appearance features to guarantee texture consistency in unedited areas. The entire pipeline is training-free, relying solely on pretrained TRELLIS flow transformers and off-the-shelf 2D editing models, and the same framework is used to auto-generate the 100K-pair Nano3D-Edit-100k dataset via VLM-generated instructions and automated quality filtering.

## Results

On 100 representative editing cases from Nano3D-Edit-100k, Nano3D achieves the best scores across all three evaluation metrics: Chamfer Distance (CD) of 0.013 for source structure preservation, DINO-I of 0.950 for target semantic alignment, and FID of 27.85 for generation quality. In a 50-participant user study, Nano3D is preferred over TRELLIS on prompt alignment (68% vs 32%), visual quality (79% vs 21%), and shape preservation (95% vs 5%). The introduced Nano3D-Edit-100k dataset also outperforms 3D-Alpaca on semantic alignment (CLIPScore 39.71 vs 28.42; ViLT R@5 45.3 vs 33.6).

## Baselines & Comparisons

Nano3D outperforms all four quantitative baselines on every reported metric. Against Tailor3D (multi-view editing + reconstruction), Nano3D reduces CD by 65% (0.013 vs 0.037) and FID by 80% (27.85 vs 140.93), while improving DINO-I from 0.759 to 0.950. Against Vox-E (SDS-based), Nano3D improves DINO-I by 0.168 and FID by 89.7 (27.85 vs 117.12); Vox-E does not report CD. Against TRELLIS with RePaint-based editing, Nano3D achieves lower CD (0.013 vs 0.019), higher DINO-I (0.950 vs 0.901), and substantially lower FID (27.85 vs 49.57), and dominates the user study on all three criteria (68%/79%/95% vs 32%/21%/5%). Against Instant3DiT (multiview inpainting), Nano3D edges out on CD (0.013 vs 0.014) and DINO-I (0.950 vs 0.879) while halving FID (27.85 vs 56.73). A qualitative comparison with PrEditor (Erkoç et al., CVPR 2025) further shows Nano3D maintaining multi-view consistency where PrEditor exhibits visible artifacts on rear views and side mirrors.

## Relation to Prior Work

Nano3D transfers the training-free 2D editing technique FlowEdit (Kulikov et al., 2024) into the 3D domain by embedding it within TRELLIS's (Xiang et al., 2025) first-stage voxel generation, replacing the standard noise-to-voxel flow with a source-to-target editing trajectory. This departs from the dominant 3D editing paradigms—Score Distillation Sampling optimization and multi-view-edit-then-reconstruct—which the paper argues are slow and inconsistent. The Voxel/Slat-Merge strategy is a novel region-aware post-processing step that has no direct 2D analogue, exploiting the discrete voxel structure to isolate edited regions via XOR and connectivity analysis. The paper explicitly positions 3D editing as stuck at 'Stage 1' (algorithm design) of the three-stage 2D editing paradigm (algorithm → dataset → feedforward model), and contributes both the algorithm and the dataset to advance the field toward Stage 3.

## Why It Matters / Open Questions

The practical impact is twofold: a training-free, mask-free editing pipeline that removes the need for per-object optimization or manual segmentation, and the first 100k-scale 3D editing dataset (Nano3D-Edit-100k) that substantially outperforms the prior 3D-Alpaca dataset in semantic alignment (CLIPScore 39.71 vs 28.42). Key limitations acknowledged by the authors include support only for localized edits, inherent VAE reconstruction loss in TRELLIS, and dependence on TRELLIS's generative ceiling. Open questions include whether the approach generalizes to global or structural edits, whether the voxel representation advantage over VecSet (shown in Appendix A.10) holds for other flow-based 3D generators, and whether the 100k dataset is sufficient to train a competitive feedforward 3D editing model.
