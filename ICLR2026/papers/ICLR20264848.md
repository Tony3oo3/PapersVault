## Problem

Centralized LLM routing systems rely on a single external router trained on a fixed set of candidate models, making them rigid (any agent addition or update requires full retraining) and inaccurate (small routers cannot fully comprehend the knowledge boundaries of large LLMs). This paper asks whether routing decisions can instead be distributed across the LLM agents themselves, each using its own self-awareness to decide whether to answer or delegate a query.
![Teaser figure](../imgs/ICLR20264848/cropped_page1_idx0.webp)

## Input / Output

Each agent receives a text query augmented with a scenario preference instruction (Performance First α=0.2, Balance α=0.5, or Cost First α=0.8) and produces a binary routing decision: either a full Chain-of-Thought answer or a short rejection token ("I don't know") that forwards the query to the next larger agent in the cascade. The system-level output is the answer from the first agent in the size-ordered chain (0.5B→1.5B→3B→7B→14B Qwen2.5-Instruct) that chooses to answer, with the 14B model serving as an unconditional fallback. Routing overhead is negligible (<5% of inference time) since rejection responses are only a few tokens.

## Method

DiSRouter replaces a central router with a cascade of LLM agents, each independently deciding to answer or reject based on trained self-awareness. A two-stage Self-Awareness Training pipeline is applied per agent: (1) SFT, where N CoT trials per query determine correctness frequency, and queries below a scenario-dependent threshold δ=1−α are relabeled as rejections; (2) RL (Reinforce++ via the Verl framework) with a localized, scenario-conditioned reward — 1 for correct answers, 0 for incorrect, and (1−α)^γ for rejections — that enables each agent to be trained fully independently and in parallel without inter-agent communication. The reliability factor γ=0.5 introduces a non-linear trade-off, preserving high accuracy under mild cost pressure while allowing a steeper accuracy drop only under extreme cost-first settings. Because the preference factor α is conveyed via a prompt instruction rather than a separate model, a single trained system adapts to all three scenarios without retraining, and agents can be added or removed from the cascade without any retraining of the remaining agents.

## Results

On in-domain datasets (7 benchmarks), DiSRouter+RL achieves the highest utility among all non-oracle methods across all three scenarios: 0.73 (Performance First, α=0.2), 0.61 (Balance, α=0.5), and 0.52 (Cost First, α=0.8), reaching at least 74.29% of the Oracle topline. In the Balance scenario, DiSRouter+RL attains 77% accuracy at 0.32 cost, outperforming the strongest baseline GraphRouter (77% accuracy at 0.46 cost, utility 0.53). On out-of-domain datasets (SQuAD, HellaSwag, HeadQA), DiSRouter+RL also leads with utility 0.48 in the Balance scenario versus 0.39 for GraphRouter.

## Baselines & Comparisons

DiSRouter+RL outperforms all five router baselines on utility in every scenario. Against GraphRouter (the strongest baseline), DiSRouter+RL gains +0.05 utility in Performance First (0.73 vs 0.68), +0.08 in Balance (0.61 vs 0.53), and +0.07 in Cost First (0.52 vs 0.45), while also reducing cost by 0.28, 0.14, and 0.09 respectively. FrugalGPT achieves lower cost but sacrifices accuracy (e.g., 0.63 vs 0.77 in Balance), yielding lower utility (0.52 vs 0.61). FORC and RouteLLM trail further behind, with RouteLLM particularly weak (utility 0.36 in Balance) due to its small BERT-based classifier. Automix, which relies on self-verification, incurs the highest cost (1.10 in Performance First) and the lowest utility among router baselines in the Balance and Cost First scenarios (0.29 and 0.18). On out-of-domain datasets, DiSRouter+RL's advantage widens (utility 0.48 vs 0.39 for GraphRouter in Balance), demonstrating superior generalization compared to all centralized router baselines.

## Relation to Prior Work

This paper departs from the dominant centralized-routing paradigm (FrugalGPT, RouteLLM, GraphRouter, FORC, Automix) by replacing the external router with a distributed network where each LLM agent self-assesses and decides whether to answer or reject. The SFT stage directly builds on Xu et al. (2024)'s rejection-based reliability training, extending it from single-model abstention to a multi-agent routing context with scenario-conditioned rewards. Conceptually, it aligns with AgentNet (Yang et al., 2025) in pursuing decentralized decision-making, but differs by grounding routing in each agent's intrinsic self-awareness rather than a learned per-agent router, and by introducing a unified preference-factor mechanism for scenario adaptability without inter-agent communication.

## Why It Matters / Open Questions

The plug-and-play modularity (adding/removing agents without retraining) and single-system scenario adaptability address two practical pain points of centralized routers that are likely to matter as LLM ecosystems grow more dynamic. The finding that a model's own self-assessment outperforms an external classifier of comparable size (Table 5) challenges the assumption that routing requires a separate evaluation component. Open questions include whether the cascade topology is sufficient for heterogeneous agent pools with non-linear capability relationships, whether the self-awareness training generalizes to truly novel task distributions beyond the tested domains, and how the framework scales when system-level information (e.g., which agents are available) must be communicated at inference time.
