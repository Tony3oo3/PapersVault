## Problem

Reliable verifiers are essential for RL post-training of LLMs on algorithmic coding, but existing test synthesis methods (TACO, CodeContests) produce tests that are far too weak: 60% of programs passing APPS tests are actually wrong, and 46% of CodeContests-passing programs are semantically correct but too inefficient. The core difficulty is that well-disguised wrong solutions (e.g., O(n²) vs. O(n log n)) pass random tests but fail only on carefully constructed edge cases that are hard to synthesize automatically. The paper asks: can we build a test synthesis pipeline that is significantly harder (higher precision) while remaining fair (high recall), and does test quality actually matter for downstream RL and rejection sampling?

## Input / Output

The pipeline takes a natural-language coding problem specification and up to 8 human-written oracle programs (correct C++/Python solutions from online judge platforms) as input. It produces a set of synthetic test cases (input-output pairs) spanning four complementary types, plus a Python output judging function for the 25.4% of problems where simple string comparison is insufficient (e.g., set-order-invariant outputs or multiple valid answers). Test inputs are validated by an LLM-generated validator function that checks types, ranges, and logical constraints; expected outputs are computed by running all oracle programs and retained only when >90% consensus is reached across oracles.

## Method

HARDTESTGEN synthesizes test inputs via four complementary techniques, each targeting a different failure mode: LLMGen (10 small inputs directly generated by the LLM mimicking sample cases), RPGen (20 large-scale random inputs from an LLM-written generator function respecting data types and ranges), SPGen (stratified generation per output category to avoid imbalanced Yes/No distributions, mutually exclusive with RPGen), and HackGen (10 inputs per identified failure scenario, targeting specific brute-force or edge-case weaknesses). The key insight is that validity is better preserved when inputs are produced by LLM-written generator programs rather than directly by the LLM, and that each generator type encodes different hypotheses about how candidate programs might fail. Outputs are computed by executing up to 8 oracle programs on all inputs, with consensus filtering (>90% agreement) to eliminate invalid cases. The resulting HARDTESTS dataset (26.6k problems from 13 platforms) achieves +11.22 pp precision and +11.03 pp recall over baselines, and downstream experiments with GRPO-based RL and rejection sampling on Qwen3-4B confirm that harder tests yield meaningfully better post-trained models.

## Results

HARDTESTS achieves an average precision of 79.21% (Qwen2.5-Coder-7B), 81.54% (Qwen2.5-Coder-14B), and 93.22% (GPT-4o) when verifying LLM-generated code, compared to 61.00% and 51.64% for TACO and CodeContests respectively on the 7B model. On the hardest problems (Difficulty 4+), HARDTESTS precision reaches 55.88% versus only 17.83% for TACO and 10.81% for CodeContests—a 3×+ gap. In downstream RL training, using HARDTESTS as the verifier yields 39.42% pass@1 and 64.76% pass@10 on LiveCodeBench-105, outperforming TACO-based RL (36.95% / 57.14%) and the untrained base model (38.48% / 56.19%).

## Baselines & Comparisons

HARDTESTS outperforms both TACO and CodeContests on precision across every model and difficulty level. The gap is most dramatic on hard problems: for Qwen2.5-Coder-7B on Difficulty 4+, HARDTESTS achieves 55.88% precision versus 17.83% (TACO) and 10.81% (CodeContests), meaning TACO and CodeContests let roughly 80–90% of wrong programs pass. For GPT-4o (the strongest generator), the gap narrows but HARDTESTS still leads by 14.6 and 8.6 percentage points in average precision over TACO and CodeContests respectively. In the RL downstream experiment, HARDTESTS as the reward verifier improves pass@1 by +2.47 pp and pass@10 by +7.62 pp over TACO-based RL on LiveCodeBench-105, while TACO-based RL actually degrades pass@1 below the untrained base model. The paper attributes the larger precision advantage for weaker models to the fact that less capable programs are more likely to be functionally correct but inefficient (30% of LLM errors are TLE vs. 15% for humans), and HARDTESTS' larger, more diverse test suite catches these cases.

## Relation to Prior Work

This paper extends the LLM-based test synthesis line (CodeT, TACO, CodeContests) by shifting from direct LLM generation of test inputs to LLM-generated *generator programs* (RPGen, SPGen, HackGen) that produce inputs from structured distributions, combined with oracle-program consensus filtering for ground-truth outputs. The HackGen component—deliberately constructing inputs that exploit known failure modes of naive algorithms (e.g., chain trees to trigger O(n²) DFS)—has no direct analogue in prior test synthesis work. On the RL side, the paper positions itself against Code-R1, DeepSeek-R1, and Kimi K1.5/K2, which assume reliable verifiers exist, by showing that verifier quality is itself a first-order variable affecting training outcomes.

## Why It Matters / Open Questions

The paper addresses the 'code verifiability crisis' where 60% of programs passing APPS tests are actually wrong, and demonstrates that this directly degrades RL and rejection sampling: TACO-based RL *hurts* Qwen3-4B performance while HARDTESTS-based RL improves it. The 26.6k-problem open dataset with high-quality synthetic tests is a practical resource for the code RL community. Key limitations include the dependence on oracle programs (available for only 68% of problems), restriction to stateless standard-I/O problems, and RL experiments conducted on a single 4B model with ~5k problems, leaving open whether the verifier-quality effect scales to larger models and longer training.
