## Problem

Existing MLLMs struggle to parse rasterized scientific diagrams into structured TikZ code because the task demands pixel-level precision over diverse graphical primitives, complex spatial relationships, and strict syntactic constraints. Two critical data features—drawing order and comment annotations—have been underexplored in prior diagram-to-code datasets, and existing RL reward signals (pixel-level losses, OCR-based text extraction) introduce errors that degrade training quality.
![Teaser figure](../imgs/ICLR20262997/cropped_page0_idx0.webp)

## Input / Output

The model takes a single rasterized scientific diagram image (flowcharts, circuit diagrams, plots, graph structures, etc.) and produces a self-contained, compilable TikZ code block wrapped in a LaTeX document. The generated code must be syntactically valid (compilable without external dependencies beyond TikZ packages), visually faithful to the input, and structured with inline comments that serve as planning scaffolds. The output TikZ code can be compiled to SVG for element-level editing in tools like Figma, or manipulated directly by LLMs for programmatic diagram editing.

## Method

DaVinci uses a two-stage training framework on Qwen2.5-VL-7B: (1) supervised fine-tuning on TikZ-30K, a curated dataset where code is reordered to follow a semantically constructive drawing protocol and enriched with LLM-generated comments that decompose the drawing into sub-tasks, serving as planning anchors; (2) RL post-training via GRPO with a hybrid reward that jointly optimizes four complementary signals. The key innovation in reward design is extracting text and geometric primitives directly from the PDF vectorized representation (via PyMuPDF) rather than from rasterized images, enabling error-free spatio-textual matching (using Distance-IoU with a two-stage exact-then-approximate algorithm) and geometric matching (using the Hungarian algorithm with type-specific cost functions over centroid, size, and orientation). This bypasses OCR errors and pixel-level metric limitations, providing precise feedback on spatial-textual alignment and geometric accuracy that standard image-based rewards cannot capture.

## Results

On the DATikZv3 test set (542 samples), DaVinci-7B achieves a near-perfect Pass@1 compile rate of 97.60%, substantially outperforming all open-source MLLMs and proprietary models (GPT-5: 72.88%, Claude-Sonnet-4: 84.87%, Gemini-2.5-Pro: 69.93%). It also attains the best image-level scores on DSIM (84.83), SigLIP (93.93), MSE (61.81), and LPIPS (22.32). The SFT-only variant (DaVinci-SFT-7B) already reaches 84.50% Pass@1, and RL post-training further lifts it by 13.1 percentage points while improving all visual fidelity metrics.

## Baselines & Comparisons

DaVinci-7B decisively outperforms GPT-5-Default on Pass@1 (97.60 vs. 72.88), DSIM (84.83 vs. 83.78), MSE (61.81 vs. 73.57), and LPIPS (22.32 vs. 25.37), though GPT-5 retains a slight edge on TED (53.17 vs. 55.13) and SSIM (73.73 vs. 73.65). Against Claude-Sonnet-4, DaVinci wins on Pass@1 (97.60 vs. 84.87), DSIM, SigLIP, MSE, and LPIPS, with Claude holding a marginal TED advantage. The specialized DetikZify-V2-8B is the closest open-source competitor on cBLEU (7.19 vs. 6.57) and SSIM (74.30 vs. 73.65), but DaVinci surpasses it on Pass@1 (97.60 vs. 78.60), DSIM, SigLIP, MSE, and LPIPS. Gemini-2.5-Pro-Thinking remains the strongest on perceptual metrics (DSIM 88.20, SigLIP 95.59, SSIM 75.86, LPIPS 21.64) but suffers a dramatically lower compile rate (69.93%) due to frequent missing LaTeX imports, whereas DaVinci achieves near-perfect compilation. Among open-source models, DaVinci-7B (7B parameters) outperforms the much larger Qwen2.5-VL-72B and GLM-4.5V-106B on every metric except TED and SSIM, demonstrating the effectiveness of task-specific data curation and RL over raw model scale.

## Relation to Prior Work

This paper extends the DeTikZify/DATikZ line of work on image-to-TikZ generation by introducing a two-stage training framework (SFT on a curated dataset followed by GRPO-based RL) and a hybrid reward that exploits TikZ's native PDF vectorized representation for extraction-error-free spatio-textual and geometric scoring. It departs from prior RL-for-visual-generation work (StarVector, ChartMaster) that relies on pixel-level losses or OCR-based feature extraction, instead leveraging PyMuPDF to read exact text objects and geometric primitives directly from the rendered PDF. The data curation strategy—specifically code reordering and comment injection as planning scaffolds—represents a novel contribution on top of the DATikZ collection pipeline, addressing ordering noise and structural ambiguity that prior datasets left unaddressed.

## Why It Matters / Open Questions

The result that a 7B specialized model can match or exceed GPT-5 and Claude-Sonnet-4 on diagram parsing demonstrates that task-specific RL post-training with well-designed rewards can close the gap to much larger proprietary models, offering a practical recipe for the diagram-to-code community. The finding that explicit chain-of-thought reasoning does not consistently improve (and can degrade) structured code generation challenges the prevailing assumption that more reasoning always helps, though evidence is limited to two model families. Open questions include whether the vectorized-representation reward trick generalizes to other code targets (SVG, Mermaid), whether the two-stage framework transfers to other structured generation tasks, and whether the remaining failure cases on dense visualizations (scatter plots) can be addressed without prohibitive context-length costs.
