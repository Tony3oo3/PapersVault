## Problem

RL training for LLMs is severely bottlenecked by GPU memory (multiple concurrent models) and slow rollout phases involving long-sequence generation. Existing mitigations fail to address both issues simultaneously: LoRA reduces trainable parameters but leaves rollout speed unchanged, QLoRA's NF4 quantization is actually 1.5–2× slower than BF16 LoRA due to lookup-table dequantization, and FlashRL requires running both 8-bit and 16-bit models in memory. No prior framework combines hardware-accelerated 4-bit quantization with LoRA to reduce memory while accelerating rollouts and improving RL exploration.

## Input / Output

The method consumes text prompts (math word problems, safety questions, commonsense QA) formatted with explicit reasoning/answer tags (e.g., <think>... <answer>...</answer>) and produces multi-step reasoning traces followed by a final answer. During training, G candidate completions are sampled per prompt (8 for GSM8K, 16 for BigMath) with a maximum response length of 4096–8192 tokens; a rule-based reward function scores each completion, and group-relative advantage estimation drives policy updates. Inference uses temperature 0.6, top-p 0.95, and 4096-token completion length.

## Method

QeRL freezes the base LLM weights in NVFP4 (4-bit floating-point with FP8 block-wise scalers) and trains only LoRA adapters (rank 32) in BF16, leveraging the Marlin kernel for NVFP4×BF16 matrix multiplication to accelerate both rollout and prefilling. The central insight is that quantization noise acts as an implicit exploration mechanism: it increases policy sampling entropy by flattening the output distribution, which accelerates reward growth in RL (the opposite of its detrimental effect in SFT). To convert static quantization noise into a dynamic exploration signal, QeRL introduces Adaptive Quantization Noise (AQN), which injects channel-wise Gaussian noise resampled each forward pass and decays it exponentially across training stages (σ_start=1e-2 to σ_end=5e-4). The noise vector is merged into the RMSNorm scaling parameters, converting additive noise into row-wise multiplicative noise on the weight matrix with zero additional parameter overhead and no disruption to the NVFP4 inference kernel. The full pipeline is built on GRPO or DAPO policy optimization, and the framework enables training a 32B model on a single H100 80GB GPU while achieving ~1.5× end-to-end speedup over QLoRA and matching full-parameter fine-tuning accuracy on GSM8K (90.8%) and MATH500 (77.4%).

## Results

On GSM8K (GRPO), QeRL (NVFP4 + AQN) achieves 90.8% on Qwen2.5-7B-Instruct, surpassing BF16 LoRA (88.1%) and QLoRA (85.0%) while matching full-parameter fine-tuning (91.2%). On the broader BigMath evaluation (DAPO) across MATH500, AIME 2024/2025, and AMC 23, QeRL achieves average scores of 36.4 (7B), 42.0 (14B), and 45.6 (32B), consistently exceeding BF16 LoRA (35.7, 40.2, 42.2) and approaching full-parameter training (37.3, 43.3, 46.2). QeRL delivers a 1.5× end-to-end speedup over QLoRA and 1.3× over BF16 LoRA on the 7B model, while being the first framework to train a 32B LLM with GRPO on a single H100 80GB GPU (20.7 GB model memory vs. 62.3 GB for BF16 LoRA).

## Baselines & Comparisons

Against BF16 LoRA, QeRL wins on average across all three model sizes: 36.4 vs. 35.7 (7B), 42.0 vs. 40.2 (14B), and 45.6 vs. 42.2 (32B), with the largest gap on the 32B model (+3.4 points). Against QLoRA (NF4 LoRA), QeRL achieves a substantial 5.8-point improvement on 7B GSM8K (90.8 vs. 85.0) and 7.6 points on 3B (83.7 vs. 76.1), while also being 1.5–2.0× faster in the rollout phase due to NVFP4's hardware-accelerated Marlin kernel versus NF4's lookup-table dequantization. Against FlashRL (FP8 rollouts with importance sampling), QeRL scores higher on GSM8K (90.8 vs. 89.2) while using far less memory (>15 GB vs. >70 GB), since FlashRL must keep both 8-bit and 16-bit models in memory simultaneously. Against full-parameter fine-tuning, QeRL is within 0.4–1.3 points on average (e.g., 90.8 vs. 91.2 on 7B GSM8K; 45.6 vs. 46.2 on 32B BigMath average), while training only ~1% of parameters and using 40–50% of the GPU memory.

## Relation to Prior Work

QeRL sits at the intersection of three established lines: LoRA-based parameter-efficient fine-tuning (Hu et al., 2022), RL algorithms for LLM reasoning such as GRPO (Shao et al., 2024) and DAPO (Yu et al., 2025), and 4-bit quantization for LLMs (QLoRA/Dettmers et al., 2023). Its key departure from QLoRA is replacing NF4 with NVFP4 (a hardware-accelerated format on H100/Blackwell) and, more importantly, reframing quantization error not as a fidelity loss to be minimized but as a structured exploration signal. Unlike FlashRL, which requires simultaneous 8-bit and 16-bit models to correct train-inference mismatch, QeRL uses a single NVFP4+LoRA model for both rollout and gradient updates, eliminating that overhead.

## Why It Matters / Open Questions

The finding that 4-bit quantization noise increases policy entropy and thereby improves RL exploration directly contradicts the SFT literature where quantization is uniformly treated as a degradation. If this effect generalizes beyond math reasoning, it could reshape how practitioners think about the trade-off between model precision and training dynamics in RL. Practical impact is immediate: QeRL is the first framework to run GRPO on a 32B model on a single H100 80GB, and delivers ~1.5× rollout speedup over QLoRA. Open questions include whether the benefit persists for models >70B, for non-mathematical reasoning tasks (code, general dialogue), and on GPU architectures without native NVFP4 kernel support.
