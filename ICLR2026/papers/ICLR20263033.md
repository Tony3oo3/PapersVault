## Problem

Existing biomedical benchmarks evaluate LLMs on knowledge-intensive narrative QA without executable environments or interactive feedback, leaving a critical gap in assessing and training code-centric biomedical reasoning capabilities. Meanwhile, open-source LLMs exhibit substantial deficiencies in biomedical coding compared to proprietary models, yet direct deployment of proprietary APIs is infeasible due to strict medical data privacy requirements and prohibitive costs. MedAgentGym addresses both gaps by providing a comprehensive code-centric benchmark and a scalable, interactive training environment for developing privacy-preserving biomedical coding agents.
![Teaser figure](../imgs/ICLR20263033/cropped_page0_idx0.webp)

## Input / Output

Each task instance pairs a natural-language problem description with optional data resources (EHR tables, clinical notes, genomic sequences) and is executed inside an isolated Docker container with pre-installed biomedical dependencies. The agent operates under a CodeAct-style POMDP scaffold with four action types (request_info, terminal, code_execution, debugging), producing multi-turn trajectories where code is iteratively refined based on execution feedback. Outputs are verified by exact-match comparison of code execution results against ground-truth signatures, with both successful and error-containing trajectories captured as training signals.

## Method

MedAgentGym unifies 72,413 task instances across 129 categories from 12 real-world biomedical scenarios into a single executable environment, with each task encapsulated in a reproducible Docker sandbox supporting multi-threaded parallel trajectory sampling via Ray and Joblib backends. Training follows a two-stage pipeline: first, supervised fine-tuning on 2,137 successful trajectories sampled from gpt-4.1-mini (averaging 9.25 turns per trajectory), then reinforcement learning using either offline DPO with 1,646 off-policy and 2,939 on-policy preference pairs, or online PPO/GRPO where the agent actively explores tasks and receives correctness and format rewards from an outcome-supervised verifier. The verifier itself is a fine-tuned Qwen2.5-7B model that predicts trajectory success probability from interleaved observation-action sequences, enabling Best@K selection and serving as a reward model for online RL. A self-improvement loop (iDPO) further refines the policy by iteratively resampling trajectories, scoring them with the verifier, and reconstructing preference pairs, allowing the model and training data to co-evolve toward an approximate Nash equilibrium.

## Results

Med-Copilot-7B (GRPO) achieves 62.17% average success rate on the internal MedAgentGym benchmark, a +45.28% absolute gain over its Qwen2.5-7B-Instruct backbone (16.89%), approaching gpt-4.1-mini (61.72%). Med-Copilot-14B (GRPO) reaches 71.42% (+51.30% gain), surpassing gpt-4.1 (70.15%). On the out-of-distribution external suite, Med-Copilot-14B (GRPO) achieves 47.02%, a +19.10% gain over its backbone (27.92%), while the best zero-shot OSS model (Qwen3-32B) scores only 42.16% on the same external set.

## Baselines & Comparisons

Among 29 zero-shot baselines, proprietary models dominate: gpt-4.1 leads at 70.15% average SR, followed by gpt-4.1-mini (61.72%), gpt-o4-mini (65.67%), and gpt-4o (48.75%). The best zero-shot OSS model, QwQ-32B, reaches only 51.50%, a ~19-point gap behind gpt-4.1. Notably, medical-domain-specific models (HuatuoGPT-o1-7B at 16.11%, MedReason-8B at 18.16%, Baichuan-M1-14B at 10.14%) consistently underperform their general-purpose base models, and coding-specialized models (Qwen2.5-Coder-7B at 14.65%, Seed-Coder-8B at 32.35%) also lag behind comparable general OSS models. After MedAgentGym training, Med-Copilot-7B (GRPO) at 62.17% matches gpt-4.1-mini (61.72%) and exceeds gpt-4o (48.75%) by 13.4 points, while Med-Copilot-14B (GRPO) at 71.42% surpasses even gpt-4.1 (70.15%). On the out-of-distribution external suite, Med-Copilot-14B (GRPO) achieves 47.02%, outperforming all OSS baselines (best: Qwen3-32B at 42.16%) and approaching gpt-4.1 (51.06%), confirming transferable coding proficiency rather than memorization.

## Relation to Prior Work

MedAgentGym builds on the CodeAct agent scaffold (Wang et al., 2024a) for code-execution-based reasoning and the iterative DPO (iDPO) framework (Pang et al., 2024) for self-improvement, but departs from prior biomedical benchmarks (EHRSQL, MedCalcBench, BioCoder, EHRSHOT, BioDSBench) by unifying them into a single executable, interactive Docker-based environment with verifiable ground truth and multi-turn trajectory sampling. It also extends the agentic RL training paradigm established in software engineering (SWE-Gym) and data science (MLGym, DSBench) to the biomedical domain, where prior work has been limited to single-pass, non-executable evaluations. The key conceptual departure is treating biomedical data science as a code-centric reasoning problem requiring iterative code generation, execution, and debugging rather than a one-shot question-answering task.

## Why It Matters / Open Questions

MedAgentGym addresses a critical infrastructure gap: the inability to deploy proprietary LLMs in privacy-sensitive healthcare settings while OSS models lag substantially in biomedical coding (gpt-4.1 at 70.15% vs. best OSS at ~51.50%). The demonstrated +43–45% improvement from RL training on a 7B model, approaching gpt-4o performance, suggests a viable path to affordable, privacy-preserving biomedical coding agents. Open questions include whether the gains generalize to truly novel biomedical tasks (external evaluation shows more modest improvements), whether multimodal data (imaging, signals) can be integrated, and whether the computational cost of trajectory sampling limits accessibility for resource-constrained groups. The finding that medical-domain-specific LLMs underperform their base models on coding tasks also raises questions about the interaction between domain fine-tuning and general coding ability.
