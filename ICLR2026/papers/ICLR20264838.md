## Problem

Existing memory-efficient fine-tuning (MEFT) methods for LLMs operate as data-agnostic optimizations, applying a uniform token-dropping or activation-compression strategy across all training instances. This ignores the rich per-instance variability in token importance, resulting in ineffective performance (degraded accuracy under aggressive sparsity) and unstable training (high variance across runs). The paper asks: how can we identify the salient tokens that truly drive each instance's learning signal and use them to achieve both effective and stable memory-efficient fine-tuning?

## Input / Output

TOKENSEEK takes a pre-trained Transformer-based LLM (Qwen2.5 0.5B, Llama3.2 1B/3B, Llama2 7B) and instruction-tuning samples (21K from Open-Platypus) as input. Before training, it performs a forward pass plus a partial backward pass (freezing all layers except the output head and final decoder block) to score every token, then stores a per-instance token-selection mask (~6.8 MB for 50% of positions). During training, only the selected tokens (default 10%) carry gradients while the remainder are processed under torch.no_grad(), producing a fine-tuned model evaluated via few-shot benchmarks (MMLU, ARC, HellaSwag, TruthfulQA, WinoGrande).

## Method

TOKENSEEK is a two-stage, architecture-agnostic plugin. Stage 1 (Instance-Aware Token Seeking) scores each token by combining two signals: (a) context importance, computed as the column-wise sum of the attention matrix (capturing how much attention a token receives from all others), and (b) gradient importance, computed as the sum of gradient magnitudes across the hidden dimension at the penultimate layer's activations. These are fused via a weighted log-normalized score I(t_j) = α·log[I₁(t_j)] + β·Norm[I₂(t_j)], and the top-r tokens are retained. Stage 2 (Efficient Token Ditching) partitions hidden states into selected and unselected groups at every Transformer layer; the unselected group is forwarded under torch.no_grad() so its activations are never cached for backprop, reducing activation memory from O(BsH) to O(B·r·sH). Because the forward pass remains full-sequence (preserving attention context) and only the backward gradient path is sparsified, the method is a structured gradient sparsification rather than sample dropping, and it composes additively with PEFT methods (LoRA, QLoRA, LoHa) for compounded memory savings.

## Results

On Llama3.2 1B, TOKENSEEK alone (10% tokens) achieves an average score of 41.13 vs. 40.82 for full-token tuning while reducing peak memory from 100% to 34.3%. Combined with QLoRA, peak memory drops to just 14.3% (2.8 GB) with an average score of 49.22, and on Llama3.2 3B the combination reaches 11.1% peak memory (5.5 GiB) with a score of 60.42 vs. 41.53 for full tuning. On Qwen2.5 0.5B, QLoRA+TOKENSEEK marginally surpasses full-token tuning (48.45 vs. 48.43) at only 13.4% peak memory. Training time overhead is modest at ~11–15% GPU hours compared to full-token tuning.

## Baselines & Comparisons

Against TokenTune (Simoulin et al., 2024), the closest concurrent method, TOKENSEEK consistently outperforms the random-token baseline: on Llama3.2 1B full tuning, 41.13 vs. 40.75; on Llama3.2 3B with QLoRA, 60.42 vs. 59.31; and on Llama3.2 1B with LoHa, 52.58 vs. 51.37. Against PEFT baselines, QLoRA+TOKENSEEK achieves comparable or superior average scores at dramatically lower memory: on Llama3.2 3B it matches QLoRA (60.42 vs. 60.39) while cutting peak memory from 26.5% to 11.1%; on Qwen2.5 0.5B it beats LoRA (48.45 vs. 48.06), IA3 (48.45 vs. 48.01), BOFT (48.45 vs. 48.10), BoNE (48.45 vs. 42.48), and RanLoRA (48.45 vs. 48.01) while using 13.4% peak memory versus 71.8–100.6% for those methods. LoHa+TOKENSEEK on Llama3.2 1B (52.58) slightly exceeds LoHa alone (52.28) at 28.4% vs. 99.4% peak memory. The one setting where TOKENSEEK trades some accuracy for memory is QLoRA on Llama3.2 1B (49.22 vs. 52.13 for QLoRA alone), a 2.9-point drop in exchange for reducing peak memory from 34.8% to 14.3%.

## Relation to Prior Work

TOKENSEEK builds directly on TokenTune (Simoulin et al., 2024), which first demonstrated that selectively dropping token activations during backpropagation can reduce training memory, but relied on random (data-agnostic) token selection. The paper departs from this by introducing an instance-aware scoring mechanism that combines attention-based context importance (column-wise attention accumulation) with gradient-based importance (penultimate-layer gradient magnitude), drawing on the observation from Jain & Wallace (2019) that attention and gradient signals capture complementary aspects of token relevance. It also positions itself as an orthogonal plugin to PEFT methods (LoRA, QLoRA, LoHa), which reduce parameter memory but leave activation memory largely untouched, thereby addressing the dominant memory bottleneck that PEFT alone cannot solve.

## Why It Matters / Open Questions

The practical impact is significant: reducing peak training memory to ~13–15% of full fine-tuning (e.g., 5.5 GiB vs. 38.8 GiB for Llama3.2 3B + QLoRA) makes LLM adaptation feasible on consumer-grade GPUs, democratizing fine-tuning for resource-constrained settings. The interpretability analysis revealing that context scores bias toward early tokens (attention sink + causal mask) while gradient scores concentrate on the response portion provides actionable insight into why naive attention-based selection fails and motivates the dual-signal design. Open questions include whether the approach extends to non-Transformer architectures, how it behaves under distributed (TP/SP) training, whether the α/β hyperparameters and token ratio can be learned automatically, and whether the modest performance degradation on smaller models (Qwen 0.5B) reflects a fundamental capacity limitation or a fixable scoring miscalibration.
