## Problem

Existing benchmarks for evaluating LLM-generated test cases rely on large, unstructured collections of wrong codes, incurring prohibitive computational costs while producing inflated scores that mask a method's inability to detect rare, critical faults. The paper asks two fundamental questions that have never been jointly addressed: what is the minimal set of wrong codes sufficient to span the entire error space of a problem, and what is the minimal number of test cases needed to distinguish all independent error patterns?
![Teaser figure](../imgs/ICLR20261301/cropped_page1_idx0.webp)

## Input / Output

The pipeline consumes competitive programming problems (from USACO, IOI, ICPC) with their golden test cases and raw user submissions, retaining only C++ wrong-answer codes with complete execution results. Each problem's wrong codes are transformed into a binary Code-Test matrix (rows = wrong codes, columns = golden test cases, entries = 1 for WA / 0 for AC), from which the matrix rank determines the exact basis size. The output is TC-Bench: 877 problems with 9,347 selected wrong codes (less than 2% of original submissions) and 7,016 correct submissions sampled from the top-20% runtime performers, where the number of test cases per problem is bounded by its rank rather than being arbitrary.

## Method

The core insight is that the binary Code-Test matrix's row rank simultaneously specifies the minimal number of independent error patterns (wrong codes) and provides a tight upper bound on the number of test cases needed for complete fault coverage, unifying two previously separate questions. The optimization objective is to find a row basis of size equal to the rank that minimizes the average pairwise Jaccard similarity among its members, approximating an orthogonal basis for maximum diagnostic diversity. Since this is NP-hard, WrongSelect employs a two-phase approach: (1) principled pre-filtering that removes problems with all-ones columns and wrong codes failing on >80% of test cases, and (2) random-restart local search that iteratively swaps one internal basis row with one external row, accepting the swap only if the new set maintains full rank and achieves a lower Jaccard diversity score, converging to a local optimum before restarting from a new random initialization.

## Results

On TC-Bench (877 problems, 9,347 wrong codes), even the best model-method combination (Claude4 + HT) achieves only 62.96% HackRate, and Claude4-Thinking + LCB reaches 62.35%, confirming a significant performance ceiling. Methods that leverage correct code (LCB, HT) consistently outperform those that do not (CRUX, PSEUDO, ALGO) by 20–40 percentage points in HackRate across nearly all models. The choice of generation method has a far greater impact on performance than the base model: on Qwen2.5-Coder-32B, LCB's HackRate (58.10%) is nearly 40% higher than CRUX's (18.73%), while Qwen2.5-Coder-32B and DeepSeek-V3 differ by only 1% under LCB.

## Baselines & Comparisons

Against TCGBench (All_WC, full wrong-code set), TC-Bench dramatically reduces score inflation: LCB achieves near-perfect (~100%) HackRate on All_WC but drops to ~50–62% on TC-Bench, exposing that unfiltered sets mask incompetence on core error patterns. TestCase-Eval (random 20 codes) shows scores and trends highly similar to All_WC, confirming that naive random sampling fails to remove redundant error patterns. TCG (5 heuristic codes) yields significantly lower scores due to under-representation—its rigid limit of 5 codes cannot cover problems whose error-space rank approaches 30, making it prone to future score inflation. Among the five generation methods, LCB and HT (which use correct code for output validation) consistently outperform CRUX, PSEUDO, and ALGO by 20–40 percentage points in HackRate across nearly all 13 LLMs. The paper further shows that methodology dominates model choice: Qwen2.5-Coder-32B with LCB (58.10% HR) nearly matches DeepSeek-V3 with LCB (58.83% HR), while on the same model, LCB outperforms CRUX by ~39 percentage points.

## Relation to Prior Work

This paper repurposes the Code-Test execution matrix concept from CodeT and B4 (which used it for solution selection via clustering or probabilistic modeling) into a diagnostic basis selection problem for benchmark construction. It departs from prior evaluation approaches—TCGBench (full wrong-code set), TestCase-Eval (random 20-code sampling), and TCG (5 heuristic codes)—by formalizing the selection as a matrix-rank problem with Jaccard-diversity optimization, solved via a random-restart local search (WrongSelect). The five evaluated generation methods (CRUX, PSEUDO, ALGO, LCB, HT) represent the current methodological spectrum, but no prior work had principled criteria for how many wrong codes or test cases constitute a sufficient evaluation set.

## Why It Matters / Open Questions

TC-Bench provides the first principled, rank-based benchmark for test case generation evaluation, revealing that even Claude4-Thinking with LCB achieves only ~60% exclusion rate—a gap masked by inflated scores on unfiltered code sets. The rank-as-upper-bound insight gives a clean theoretical justification for test case budgets, and the finding that methodology choice dwarfs model scale suggests the field should invest in generation strategies rather than simply scaling models. Open questions include whether the binary AC/WA abstraction captures all meaningful error distinctions (e.g., partial correctness), whether the Jaccard diversity objective is truly optimal versus other diversity metrics, and whether the framework generalizes beyond competitive programming to broader software testing domains.
