## Problem

Plain ViTs lose accuracy at small scales because width is reduced uniformly across all tokens, and existing compute-efficient architectures (EfficientViT, SHViT, MobileNetV4) fix speed by introducing convolutions, hierarchy, or batch normalization that break the plain ViT interface. This incompatibility prevents them from supporting SOTA self-supervised learning, token dropping, multimodal processing, and the broader ViT ecosystem out of the box. The paper asks whether a ViT can be made faster and more accurate while remaining strictly attention-only and non-hierarchical.

## Input / Output

The method accepts any input shape a plain ViT handles: RGB images (128×128 or 224×224 px with 16×16 patches), 1D time series sequences (8 or 42 patches), or text token sequences. For classification it outputs class logits projected from the single Jumbo token (J·D → C); for segmentation it outputs per-pixel masks via a standard Segmenter head on the patch tokens; for time series it outputs class labels from concatenated per-channel Jumbo tokens. The Jumbo token is J× wider than patch tokens (J=3 for ViT-Base, J=6 for smaller models, J=4 for PatchTST), and the architecture requires no architectural changes to switch between these modalities—only position embeddings differ.

## Method

Jumbo replaces the CLS token with a single token J× wider than the patch width D. Before multi-headed self-attention, the Jumbo token is split into J tokens of width D so it participates in attention at the same per-head dimension as patches; after attention, the J split tokens are reassembled by concatenation and processed by a dedicated wider FFN (J·D → J·D·k → J·D) that is not shared with the patch FFN. Critically, the Jumbo FFN parameters are shared across all transformer layers, keeping the memory overhead minimal while acting as implicit regularization. This asymmetric width design—narrower patch tokens with a wider global token—increases global representational capacity without proportionally increasing FLOPs, since the dominant cost driver is sequence length × patch width, not the single Jumbo token. The architecture remains fully attention-only and non-hierarchical, preserving compatibility with token dropping, Flash Attention, MAE pre-training, SAR test-time adaptation, and arbitrary input shapes.

## Results

On ImageNet-1K (224×224 px), ViT+Jumbo achieves 84.9% top-1 accuracy at ViT-Base scale (D=768, J=3) with 3.1K images/s throughput, outperforming ViT+Registers (84.3%, 2.9K imgs/s) while matching or exceeding speed. At the Nano scale (D=128, J=6), Jumbo reaches 74.6% top-1 at 31.3K imgs/s versus 61.0% for ViT+Registers at 25.5K imgs/s — a 13.6% accuracy gain at higher throughput. For MAE pre-training, ViT-Base+Jumbo achieves 73.0% linear-probing accuracy on ImageNet-1K, a 4.9% improvement over ViT-Base (68.1%) and tying ViT-Large (73.0%) with 2.3× fewer parameters and 3.1× higher throughput. On ADE20K segmentation, Jumbo gains 1.9–3.1% mIoU over Registers (44.4% vs 42.5% at ViT-Base), and on ImageNet-C with SAR test-time adaptation, Jumbo achieves 60.1% average accuracy vs 54.9% for Registers (+5.2%).

## Baselines & Comparisons

Against ViT+Registers (Darcet et al., 2024), Jumbo wins at every scale: +13.6% at Nano (74.6% vs 61.0%), +3.9% at Tiny (78.4% vs 74.5%), +0.7% at Small (82.6% vs 81.9%), and +0.6% at Base (84.9% vs 84.3%) on ImageNet-1K, while also matching or exceeding throughput at each size. Against specialized compute-efficient architectures — EfficientViT (Cai et al., 2023), SHViT (Yun & Ro, 2024), and MobileNetV4 (Qin et al., 2025) — ViT+Jumbo achieves the Pareto frontier on ImageNet-1K, outperforming all of them in accuracy at comparable or higher throughput (e.g., Jumbo D=192 at 78.4%/20.4K imgs/s vs. SHViT S3 at 74.3%/23.7K and MobileNetV4 hybrid-medium at 78.1%/8.8K). In MAE pre-training, ViT-Base+Jumbo (73.0% linear probing) outperforms standard ViT-Base (68.1%) by 4.9% and ties ViT-Large (73.0%) with 2.3× fewer parameters and 3.1× higher throughput. For time series, PatchTST+Jumbo achieves the best average rank (1.0 univariate / 1.3 multivariate) across 20 UCR/UEA datasets, outperforming both PatchTST (2.9/2.7) and PatchTST+Registers (2.1/2.0). In test-time adaptation on ImageNet-C, Jumbo+SAR reaches 60.1% average accuracy versus 54.9% for Registers+SAR (+5.2%), and Jumbo without adaptation already exceeds Registers by +3.6%. On ImageNet-21K, Jumbo outperforms ViT+Registers by 3.1% at Small and 1.2% at Base, confirming that gains grow with task output dimensionality.

## Relation to Prior Work

This paper extends the ViT+Registers line of work (Darcet et al., 2024), which showed that extra learnable tokens improve global information aggregation in plain ViTs. Jumbo departs from Registers by making the global token J× wider than patch tokens and equipping it with a dedicated, layer-shared FFN, introducing an asymmetric-width design that no prior plain ViT variant employs. It is positioned against specialized compute-efficient architectures (EfficientViT, SHViT, MobileNetV4) that achieve speed through convolutions, hierarchy, and batch normalization, and against BiXT, the closest prior work that also maintains the attention-only, non-hierarchical interface. The core conceptual departure is scaling width across tokens rather than uniformly across all tokens and layers.

## Why It Matters / Open Questions

Jumbo provides a simple, drop-in modification to any plain ViT that achieves SOTA speed-accuracy tradeoffs while preserving full compatibility with the ViT ecosystem (MAE pre-training, token dropping, segmentation heads, test-time adaptation, multimodal processing). This is practically significant because it removes the trade-off between efficiency and generality that has forced practitioners to choose between fast specialized architectures and flexible plain ViTs. Limitations include proof-of-concept-only NLP and vision-language experiments, and the layer-sharing design for the Jumbo FFN, while effective, may not be optimal at all scales. Open questions include whether the asymmetric-width principle generalizes to other token types (e.g., multiple Jumbo tokens) and how it interacts with emerging efficiency techniques like Flash Attention or adaptive computation.
