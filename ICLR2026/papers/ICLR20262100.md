## Problem

RAG systems expose both user queries and knowledge-base documents to privacy risks, yet existing privacy-preserving RAG approaches rely on differential privacy, which inherently disrupts exact term matching and thus cannot support lexical retrieval (e.g., BM25). No prior framework supports dual-path (semantic + lexical) retrieval while simultaneously protecting both the query and the documents using cryptographic techniques.
![Teaser figure](../imgs/ICLR20262100/cropped_page3_idx0.webp)

## Input / Output

The user C submits a private text query Q, which is locally encoded into a 384-dimensional vector (granite-embedding-small-english-r2) and tokenized (BERT tokenizer) into n tokens. The server S holds a preprocessed knowledge base of N chunks, each with a vector embedding, an index, and a token-to-term-frequency mapping. The output is a set of encrypted top-K chunks (as FHE ciphertexts or secret shares, depending on the downstream inference framework) from both retrieval paths, which are fused with the encrypted query and fed into a secure LLM inference framework to produce an encrypted response.

## Method

Pisces is a two-party cryptography-based RAG retrieval framework built on MPC, secret sharing, OPRF, OKVS, and batch PIR-to-share. For the semantic path, it adopts a coarse-to-fine strategy: SimHash converts embeddings to L-bit binary vectors, and a novel oblivious filter (using 2-out-of-T Shamir secret sharing over Hamming space with additive-HE-encrypted shares) privately selects a small candidate set, after which MPC-based cosine similarity is computed only on candidates, followed by secure sorting and batch PIR-to-share to retrieve top-K chunks. For the lexical path, a multi-instance labeled PSI protocol based on OPRF and OKVS computes all per-chunk query term frequencies in a single execution (reusing a pre-built OKVS structure across queries), enabling private BM25 scoring via MPC. The key distinction from DP-based approaches is that cryptography preserves raw data, allowing exact term matching for BM25 while ensuring neither party learns the other's sensitive information.

## Results

Pisces achieves dual-path retrieval accuracy within 1.87% of the plaintext baseline across all datasets (e.g., 93.10% vs 93.30% on SQuAD Dev_v2.0 Top-5; 46.08% vs 46.27% on HotpotQA Dev_distractor Top-5). On large-scale datasets, the coarse-to-fine semantic strategy reduces retrieval time by 38.78%–41.21% and upload/download overhead by ~68% compared to a fine-only strategy. The multi-instance labeled PSI protocol achieves up to 496.03× runtime speedup, 70733× upload reduction, and 2.84× download reduction over the state-of-the-art LSE labeled PSI protocol for lexical retrieval.

## Baselines & Comparisons

Pisces is the only framework supporting both semantic and lexical (dual-path) retrieval while protecting both query and document privacy. Against DP-based baselines, Pisces dramatically outperforms: on SQuAD Dev_v2.0 Top-5 dual-path, Pisces achieves 93.10% vs. RemoteRAG's 33.18%, DP-RAG's 24.74%, and Yao & Li's 14.78%. On HotpotQA Dev_distractor, the gap is even starker: 46.08% (Pisces) vs. 7.09% (RemoteRAG), 5.70% (DP-RAG), and 1.27% (Yao & Li). Against the plaintext baseline, Pisces stays within a 1.87% margin (e.g., 93.10% vs. 93.30% on SQuAD Dev), with the small gap attributed to SimHash approximation in the coarse filter and precision loss in secure BM25 computation. For lexical retrieval efficiency, the proposed multi-instance labeled PSI outperforms the LSE protocol (Yang et al., 2024) by up to 496× in runtime and 70733× in upload overhead, making it the first practical cryptography-based dual-path private RAG retrieval system.

## Relation to Prior Work

This paper departs from the dominant DP-based approach to private RAG retrieval (DP-RAG, RemoteRAG, Yao & Li), which is fundamentally limited to semantic retrieval because added noise disrupts exact term matching. It instead adopts a cryptography-based route, building on labeled PSI (Chen et al., 2018) and extending it into a multi-instance protocol that computes all per-chunk BM25 term frequencies in a single OPRF+OKVS execution. The coarse-to-fine semantic strategy repurposes SimHash and Hamming distance as a privacy-preserving pre-filter, a technique borrowed from approximate nearest-neighbor search but here wrapped in an oblivious filter protocol to prevent information leakage. The overall architecture composes existing MPC, secret-sharing, PIR-to-share, and FHE primitives into a unified dual-path retrieval pipeline, which no prior work has achieved.

## Why It Matters / Open Questions

Pisces is the first practical framework that simultaneously protects both the user query and the server's knowledge base while supporting the full dual-path (semantic + lexical) retrieval that modern RAG systems rely for accuracy. The 1.87% accuracy gap versus plaintext and the large efficiency gains (41% time savings from coarse-to-fine, 496× speedup in lexical retrieval) make cryptography-based private RAG retrieval viable for the first time. Key limitations include the semi-honest threat model (no malicious security), the single-server setting, and reliance on a fixed embedding model and tokenizer shared between parties. Open questions include whether the approach scales to multi-server or federated settings, how it performs under active adversaries, and whether the SimHash-based coarse filter can be tightened to close the remaining accuracy gap without further communication overhead.
