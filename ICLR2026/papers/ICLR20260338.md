## Problem

The RL community lacks a unified, standardized benchmark for evaluating memory capabilities across diverse scenarios, with existing benchmarks (POPGym, DMLab-30, MemoryGym) each covering only narrow subsets of memory types and using non-overlapping task sets that prevent cross-study comparison. This gap is especially acute in tabletop robotic manipulation, where memory is essential for handling partial observability (e.g., occluded objects, multi-step procedures) yet no standardized benchmark exists to systematically assess memory-dependent manipulation skills.

## Input / Output

The benchmark supports five observation modes: state (full vector including oracle data and TCP pose), RGB (two 128×128 images from top-view and gripper cameras plus TCP position), joints (joint states and TCP pose), oracle (task-specific environment data for debugging), and prompt (static language instructions). The standard memory-testing configuration is RGB+joints, while state mode serves as the MDP validation baseline. The agent outputs an 8-dimensional end-effector action vector, and task success is determined by a binary flag at episode end (sparse) or continuous progress signals (dense), with episode timeouts ranging from 60 to 180 steps depending on the task.

## Method

MIKASA introduces a four-category taxonomy of memory-intensive tasks (Object, Spatial, Sequential, and Capacity memory) grounded in cognitive science concepts like object permanence and memory span, then instantiates this taxonomy in two tiers: MIKASA-Base consolidates existing open-source memory environments under a unified Gymnasium API, while MIKASA-Robo contributes 32 new tabletop manipulation tasks across 12 categories built on ManiSkill3 for GPU-parallel training. Each task is designed to be solvable at 100% success rate in state mode (validating task correctness) but becomes non-Markovian in RGB+joints mode, forcing the agent to retain information across occlusion or delay intervals. The benchmark is validated by evaluating online RL baselines (PPO-MLP, PPO-LSTM, SAC, TD-MPC2), offline RL methods (Decision Transformer, RATE, BC, CQL, Diffusion Policy) trained on 1000 expert trajectories per task, and four VLA models (Octo, OpenVLA, π0, SpatialVLA) fine-tuned on 250 trajectories, all of which show systematic performance degradation as memory demands increase, confirming the benchmark's discriminative power.

## Results

PPO-MLP in state mode (full observability) achieves 100% success rate across all 32 MIKASA-Robo tasks, confirming task solvability. Under the standard RGB+joints memory-testing configuration with dense rewards, PPO-LSTM reaches 100% SR on RememberColor3 while PPO-MLP achieves only 25%, but both architectures drop to near-zero SR on RememberColor5/9. Under sparse rewards, both PPO-MLP and PPO-LSTM fail across nearly all environments. Among VLA models, OpenVLA (K=8) achieves the highest success rate on RememberColor3 (0.59±0.04), while Octo-small leads on ShellGameTouch (0.46±0.05); all VLA models degrade sharply as memory demands increase (e.g., OpenVLA K=8 drops from 0.59 to 0.06 on RememberColor9).

## Baselines & Comparisons

PPO-MLP (memory-less) and PPO-LSTM (memory-enhanced) are the primary online RL baselines: LSTM clearly wins on RememberColor3 (100% vs. 25% SR) but both collapse on 5/9-color variants and under sparse rewards, confirming the benchmark's sensitivity to memory demands. SAC and TD-MPC2 show higher sample efficiency than PPO-MLP but, lacking explicit memory mechanisms, fail on complex memory tasks, highlighting their inappropriateness for memory-intensive settings. Among offline RL baselines, none of DT, RATE, BC-MLP, CQL-MLP, or Diffusion Policy successfully solve the majority of 32 tasks under sparse rewards, with all models failing entirely on high Memory Capacity and Sequential Memory tasks. Among VLA models, Octo-small (context=10) outperforms random on simpler tasks (0.46 on ShellGameTouch) but degrades with complexity; OpenVLA with K=8 achieves the best RememberColor3 score (0.59) by leveraging longer action chunks to bypass memory, yet drops to 0.06 on RememberColor9; π₀ leads on InterceptMedium (0.42) and RememberColor5 (0.22) but still fails on the hardest variants; SpatialVLA (K=4) performs near-random across all tasks. Overall, no evaluated method—online, offline, or VLA—reliably solves the full difficulty spectrum, validating MIKASA-Robo as a challenging and discriminative benchmark.

## Relation to Prior Work

This paper extends the line of work on constructing 1-Lipschitz neural networks through layer-wise constraints. Previous approaches have focused on individual techniques (spectral normalization, orthogonal parameterization), but no prior work has systematically compared them under identical training protocols. The unified algebraic perspective from recent work [15] informs the analysis, showing that several methods share common mathematical foundations.

## Why It Matters / Open Questions

This systematic comparison provides practitioners with clear guidance on which 1-Lipschitz construction method to choose based on constraints (training budget vs. certified accuracy). The finding that several methods are mathematically equivalent suggests future work should focus on truly novel approaches rather than incremental variations. Open questions include whether these methods scale to deeper networks and larger datasets like ImageNet.
