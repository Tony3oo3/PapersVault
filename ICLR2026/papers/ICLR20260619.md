## Problem

Current automatic tool generation (ATG) agents, built on reactive paradigms, fail in long-term, stateful office environments due to three fundamental flaws: they cannot build coherent world models from partially observable file contexts, their stateless tool invocations break state continuity across iterative steps, and their one-shot tool generation leads to redundant regeneration. The authors empirically demonstrate up to 27.43% performance degradation of ATG agents compared to domain-specialized agents on realistic spreadsheet tasks.

## Input / Output

The agent receives a natural-language task instruction and a partially observable office document (Excel, Word, or PowerPoint) whose full content may exceed the LLM context window. The workflow is modeled as a discrete-time decision process where the agent state comprises the file context, a persistent symbolic memory (code context and semantic comprehension), and a self-evolved capability set; at each step the planner selects from {TOOL_GENERATION, TOOL_EXECUTION, DONE}. The final output is a modified office document or a task answer, with all intermediate tools retained in the capability set for future reuse.

## Method

ROGA introduces three algorithmic innovations instantiated in a planner–executor–tool-manager architecture. (1) Active World Modeling replaces passive perception with an iterative meta-cognitive loop: the agent identifies knowledge gaps, formulates information-seeking sub-goals, and dynamically generates specialized comprehension tools to probe the environment piece by piece, integrating results into a world model stored in persistent memory. (2) Persistent Symbolic Memory provides a structured state ledger that tracks symbolic handles to all intermediate artifacts (dataframes, file handles, code objects) across steps, enforced by a state-sharing sandbox guaranteeing atomicity and reversibility of every tool invocation. (3) Dynamic Capability Evolution models the tool lifecycle as a finite-state machine (Generated → Active → In-use → Modifying → Deprecated) and drives transitions via Situated Self-Correction, a dual-channel validation process that tests each candidate tool in a shadow sandbox replicating the current state (functional testing) and performs LLM-based semantic code review against the task context, enabling the agent to retain, refine, and reuse capabilities over time rather than regenerating them reactively.

## Results

On the OSWorld benchmark (110 office tasks), ROGA achieves 95.45% Exec@1 and 31.82% Pass@1, surpassing the strongest baseline OWL by 16.36% and 13.64% respectively. On WindowsAgentArena (42 tasks), ROGA reaches 97.62% Exec@1 and 28.57% Pass@1, outperforming the nearest baseline by 21.43% and 2.38%. On GAIA-Office (26 QA tasks), ROGA attains 96.15% Exec@1 and 76.92% Pass@1. On challenging spreadsheet benchmarks, ROGA also exceeds the domain-specific SheetAgent, achieving 56.09% Pass@1 on TableBench (vs. 51.47%) and 25.91% on SheetCopilotBench (vs. 23.53%).

## Baselines & Comparisons

ROGA consistently outperforms all three ATG baselines (AutoAgent, OctoTools, OWL) across every office benchmark and metric. The largest gap is against AutoAgent, which lags by up to 32.72% in Exec@1 (OSWorld) and 18.03% in Pass@1 (GAIA-Office). OWL, the strongest baseline and a multi-agent system with domain-specific sub-agents, is surpassed by ROGA by 16.36% Exec@1 and 13.64% Pass@1 on OSWorld, and by 21.43% Exec@1 on WAA. On the challenging spreadsheet benchmarks (Table 4), ROGA also beats the specialized SheetAgent by 5.62% Exec@1 and 4.62% Pass@1 on TableBench, and by 1.38% Exec@1 and 2.38% Pass@1 on SheetCopilotBench, demonstrating that the generalist ATG paradigm can match or exceed domain-specific agents. On non-office tasks (Math500, MMLU-Pro), ROGA performs on par with the best baselines, confirming that its gains are specific to long-horizon, stateful office tasks rather than a general LLM advantage.

## Relation to Prior Work

This paper positions itself as a paradigm-level critique of existing ATG agents (AutoAgent, OctoTools, OWL) rather than an incremental improvement over any single prior method. It draws conceptual inspiration from world-model-based planning, persistent memory in sequential decision-making, and capability reuse in software engineering, but repurposes these ideas into a unified agent architecture specifically designed for long-horizon, stateful office tasks. The key departure from prior ATG work is the explicit identification of three structural flaws—passive perception, stateless execution, and one-shot tool generation—and the proposal of corresponding algorithmic countermeasures (Active World Modeling, Persistent Symbolic Memory, Dynamic Capability Evolution) that reframe tool generation as a continuous meta-learning process rather than a reactive, per-step event.

## Why It Matters / Open Questions

The finding that a generalist ATG agent can match or exceed a domain-specialized agent (SheetAgent) on challenging spreadsheet benchmarks challenges the prevailing assumption that specialized pipelines are necessary for high-stakes office automation, suggesting the ATG paradigm may be more broadly applicable than previously demonstrated. However, several open questions remain: the framework's heavy reliance on GPT-4.1's large context window limits portability, the Situated Self-Correction mechanism has documented failure modes on nuanced semantic ambiguities, and the capability lifecycle FSM, while formal, has not been tested at scale across hundreds of distinct task types. Whether the three-component architecture generalizes beyond office productivity to other long-horizon, partially observable domains (e.g., multi-session software development, scientific instrument control) is an important but untested direction.
