## Problem

Deterministic information-flow control (IFC) defenses for AI agents provably block prompt injection attacks but have been evaluated only on task completion rate, where they appear inferior to probabilistic defenses due to up to 30% utility loss. This evaluation misses a key benefit: IFC reduces the need for human-in-the-loop (HITL) approval on consequential actions. The paper asks how to quantify this autonomy benefit and how to design an agent planner that explicitly optimizes for both policy compliance and task completion rather than treating security as an after-the-fact constraint.

## Input / Output

The agent receives a user query, tool descriptions annotated with security policies (specifying whether each tool is consequential, egresses data, or is non-consequential), and external data sources (emails, web pages, files) whose untrusted content is hidden in opaque variables. It produces a trace of tool calls, a final task-completion response, and HITL requests that are either *endorsements* (user certifies untrusted data as trusted, preserving context integrity) or *approvals* (user approves a single policy-violating tool call). Autonomy is measured via two new metrics: total HITL load across successful tasks and TCR@k (fraction of tasks completed with at most k HITL interventions), yielding a full autonomy-utility trade-off curve rather than a single TCR number.

## Method

PRUDENTIA is implemented atop FIDES (a Dual-LLM IFC defense with variable hiding and quarantined LLMs) and makes the planner explicitly IFC-aware through three mechanisms. First, tool descriptions are annotated with their security policies so the agent can predict which calls will trigger violations and plan around them. Second, a dedicated `ifc_plan` tool forces the agent to justify variable expansion before it occurs, preventing unnecessary context tainting that would cascade into multiple HITL approvals. Third, the agent can choose between two expansion strategies: asking for *endorsement* (one HITL interaction relabels the data as trusted, preserving high-integrity context for all subsequent consequential calls) or expanding *without* endorsement (context becomes permanently low-integrity, but only one subsequent consequential call requires approval). This choice is critical: for a task requiring 10 consequential calls after reading an untrusted email, endorsement costs 1 HITL interaction versus 10 individual approvals. No modifications to the underlying IFC enforcement mechanism are needed; the design is realized entirely through context engineering and an enriched system prompt.

## Results

On AgentDojo (o3-mini), PRUDENTIA achieves 59.1% TCR@0 (full autonomy) with a HITL load of 16.4, compared to FIDES (50.1% TCR@0, HITL load 18.8), Basic-IFC (35.5%, 32.4), and Basic (24.3%, 48.2). On o4-mini, PRUDENTIA reaches 73.2% TCR@∞ with only 19.2 HITL load versus FIDES' 75.7% with 36.8 (a 1.9× reduction in human burden). On WASP, PRUDENTIA blocks all prompt injection attacks (0% ASR) with zero HITL load across all models, while the Basic agent suffers 14.6–61.1% ASR and requires 1.0–3.7 HITL interventions per task.

## Baselines & Comparisons

PRUDENTIA is compared against two main baselines: (1) Basic, a standard ReAct agent without IFC that requires human approval for all consequential tool calls, and (2) FIDES, a state-of-the-art IFC-enabled agent that is oblivious to security policies during planning. Against Basic, PRUDENTIA reduces HITL load by up to 2.9× (16.4 vs. 48.2 on o3-mini) while improving TCR@0 from 24.3% to 59.1% (+34.8 pp), demonstrating that policy-aware planning both increases autonomy and helps the agent find policy-compliant solutions. Against FIDES, PRUDENTIA achieves a 1.9× reduction in HITL load on o4-mini (19.2 vs. 36.8) with comparable TCR@∞ (73.2% vs. 75.7%), and a 9 pp gain in TCR@0 on o3-mini (59.1% vs. 50.1%). On WASP, PRUDENTIA achieves 0% attack success rate with 0 HITL load across all four models tested, whereas Basic suffers 14.6–61.1% ASR and 1.0–3.7 average HITL interventions, confirming that IFC-aware planning enables full autonomy on data-independent tasks while provably blocking all prompt injections.

## Relation to Prior Work

This paper builds directly on FIDES (Costa et al., 2025), an IFC-based agent defense that uses the Dual LLM pattern with variable hiding and quarantined LLMs to enforce deterministic security policies. The key departure is making the planner IFC-aware: prior systems (FIDES, CaMeL, RTBAS) treat policy enforcement as a reactive, post-hoc mechanism where the planner is oblivious to which tool calls will violate policy, whereas PRUDENTIA explicitly incorporates security labels and policies into the planning objective. The paper also introduces a new HITL interaction primitive—data endorsement (relabeling untrusted data as trusted in one step) versus per-call approval—that has no direct analogue in prior IFC agent designs. Evaluation uses the AgentDojo and WASP benchmarks, extending their evaluation protocol with the newly proposed autonomy metrics (HITL load and TCR@k).

## Why It Matters / Open Questions

The paper reframes the cost-benefit analysis of deterministic agent defenses: prior work measured only the utility cost (TCR reduction of up to 30%), while this work quantifies the autonomy benefit (1.5–2.9× reduction in HITL load), showing that even unoptimized IFC provides a net usability win. The autonomy metrics (HITL load, TCR@k) offer a more complete evaluation framework that the field can adopt for comparing secure agent designs. Limitations include substantial token overhead (PRUDENTIA uses roughly 3–5× more input tokens than Basic-IFC), a narrow threat model excluding direct injection and jailbreaks, and the fact that HITL interface design—critical for preventing human error at approval prompts—is left as future work. Whether the autonomy gains persist under more adversarial or open-ended task distributions beyond the two benchmarks remains open.
