## Problem

Existing web search agents are locked into rigid, linear ReAct-style think-act-observe loops that collapse inherently branching research queries into single-threaded trajectories, suppressing parallel exploration, backtracking, and structural revision. Compounding this, agents operate in episode isolation: tool traces and exploration paths evaporate after each episode, so no reusable experience accumulates across tasks and the same ineffective strategies are repeatedly reinvented.

## Input / Output

The system takes a free-form research query as input and produces a concise factual answer. Internally, the query is decomposed into a sequence of sub-questions, each addressed by a typed DAG workflow (serialized as YAML) whose nodes are drawn from a fixed library of building blocks (searcher, browser, summarizer, verifier, finalizer, thinker variants). Web interaction is mediated through SerpAPI (top-10 results per query) and the Jina Reader API for page content extraction; the final answer is synthesized by a dedicated finalizer block that cross-checks references against the accumulated summary before emitting the response.

## Method

FlowSearcher formulates web information seeking as a two-level process: a high-level orchestrator decomposes the query into sub-questions and synthesizes a typed DAG workflow graph for each, while a low-level executor traverses the graph node-by-node, issuing tool calls and collecting observations. A three-level hierarchical memory (node, graph, task) consolidates every execution trace; at inference time, a retrieval operator selects top-k relevant traces via weighted cosine similarity over query and sub-question embeddings, and dedicated instructor modules distill those traces into concise, transferable experiences that are injected into both the orchestration prompt (shaping DAG topology and block selection) and the node-level execution prompts (refining search keywords, URL selection, and extraction strategies). This experience-conditioned design enables adaptive workflow composition and node-level behavioral refinement entirely at inference time, without any supervised fine-tuning or RLHF, and the ablations show that full memory (combining successful and unsuccessful traces) yields the strongest long-horizon gains over no-memory or success-only baselines.

## Results

On GAIA (Pass@1), FlowSearcher with QwQ-32B achieves 56.3% average, surpassing WebDancer (51.5%), Search-o1 (51.5%), and WebThinker-RL (48.5%). On GPQA-Diamond, FlowSearcher (QwQ-32B) reaches 71.2% average, competitive with DeepSeek-R1-671B (74.2%) without any fine-tuning. On BrowseComp, FlowSearcher with GPT-4o-mini achieves 11.8% average, substantially outperforming all ReAct-style baselines (best: WebDancer at 3.8%). All gains are achieved without supervised fine-tuning or RLHF.

## Baselines & Comparisons

FlowSearcher (QwQ-32B) outperforms WebDancer by +4.8 on GAIA (56.3 vs 51.5) and +4.2 on BrowseComp (8.0 vs 3.8), and beats WebThinker-RL by +7.8 on GAIA (56.3 vs 48.5) and +5.3 on BrowseComp (8.0 vs 2.7). On GPQA-Diamond, FlowSearcher (71.2) edges out WebThinker-RL (70.7) by +0.5 and surpasses Search-o1 (63.6) by +7.6. Against WebThinker-Base, FlowSearcher gains +11.6 on GAIA (56.3 vs 44.7) and +5.7 on BrowseComp (8.0 vs 2.3). Notably, FlowSearcher achieves all these gains without any supervised fine-tuning or RLHF, whereas WebThinker-RL and WebDancer require expensive training pipelines. The largest relative advantage appears on BrowseComp, where FlowSearcher's memory-guided workflow synthesis enables multi-path exploration that rigid ReAct chains cannot replicate.

## Relation to Prior Work

FlowSearcher sits at the intersection of agentic workflow synthesis (AutoFlow, AFLOW, MermaidFlow) and hierarchical memory systems (G-Memory, A-MEM), but departs from both in a key way: prior workflow generators operate over predefined template spaces or use offline evolutionary search, while prior memory systems use fixed retrieval policies decoupled from the workflow structure. FlowSearcher unifies these by synthesizing typed DAG workflows dynamically at inference time, conditioned on a multi-level memory whose retrieval is jointly shaped by the query and the evolving graph topology. It also explicitly contrasts with ReAct-style agents (WebThinker, WebDancer, Search-o1) that enforce linear think-act-observe trajectories, arguing that the structural rigidity of those loops—not model scale—is the bottleneck for complex, branching research queries.

## Why It Matters / Open Questions

The central practical implication is that experience-conditioned workflow design can match or exceed RLHF-trained web agents without any parameter updates, offering a training-free path to improving long-horizon search that is easier to deploy and adapt. This suggests a complementary axis to fine-tuning: structural reuse of past trajectories may capture generalization that gradient-based optimization misses, particularly for open-domain queries with heterogeneous tool-use patterns. Open questions include how the memory scales with thousands of accumulated tasks, whether the embedding-based retrieval remains effective as the memory grows, and whether the approach transfers to non-web agentic domains (code, robotics). The paper also does not ablate the contribution of the specific LLM backbone's reasoning ability versus the workflow structure, making it hard to isolate how much of the gain is architectural versus model-capacity.
