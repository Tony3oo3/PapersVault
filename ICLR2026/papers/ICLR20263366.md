## Problem

Existing code-generation benchmarks (HumanEval, MBPP, SWE-Bench) evaluate models on static, one-shot tasks with fixed unit tests, failing to capture the iterative, adversarial, and CI-driven nature of real software development. In particular, no prior framework models the collaborative submitter-reviewer loop where patches face adaptive scrutiny from generated test cases, enforces full CI pipeline gates (style, security, coverage), or handles long-context multi-language codebases under realistic token budgets.

## Input / Output

The framework takes a GitHub issue description, a large repository codebase (retrieved via RACG with a fixed budget of 5 files and 16 syntax-aware chunks), and the repository's native CI configuration (GitHub Actions / Travis CI) as input. The submitter agent produces a structured JSON patch specifying file paths, code-to-be-modified segments, and edited code; the reviewer agent produces up to 10 unit test cases in a similar JSON schema. Outputs are scored through real CI pipelines executed in isolated Docker containers, yielding per-check pass/fail results aggregated into Submitter CI Pass Rate (SPR), Reviewer CI Pass Rate (RPR), Win Rate, and Best@k across 10 alternating rounds (5 per role).

## Method

SWINGARENA pairs two LLMs in an adversarial battle protocol: one acts as submitter (generating a fix patch) and the other as reviewer (generating adversarial test cases targeting the patch's logic), with roles alternating across 10 rounds and CI feedback enabling iterative refinement. Verification runs the repository's actual CI pipeline (GitHub Actions via the `act` tool) inside pinned Docker containers, so patches must compile, pass linters, and satisfy all automated checks—not just a single unit test. To handle long-context codebases across C++, Python, Rust, and Go, the RACG module performs a coarse-to-fine retrieval pipeline: BM25 file-level sparse retrieval prunes to top-5 files, a syntax-aware CodeChunker decomposes them into function/class/block units, CodeBERT dense reranking with language-aware tie-breaking and proximity bias selects the most relevant chunks, and a token-budget-aware packing policy adaptively adjusts chunk granularity to fit the model's context window. Reviewer-generated tests must pass quality gates (compile against the golden patch, bounded edit size, no nondeterminism, lint compliance) to prevent exploitative behavior, and the dataset comprises 2,300 curated GitHub issue-PR pairs filtered through CI validation, LLM-as-a-Judge clarity/difficulty scoring, and expert review.

## Results

In the SWINGARENA adversarial arena, self-play win rates reveal strong internal consistency: Claude achieves 1.00, GPT-4o 0.97, DeepSeek 0.96, and Gemini 0.91. GPT-4o dominates as a submitter with win rates ≥ 0.90 against any reviewer, while DeepSeek and Gemini achieve the highest CI pass rates (SPR up to 0.66 and 0.64 respectively), reflecting greater patch reliability. On Best@3 across four languages, DeepSeek leads with an average of 0.59, followed by Gemini and GPT-4o (both 0.57) and Claude (0.55), with all models performing best on C++ (0.63–0.64) and weakest on Rust (0.51–0.58).

## Baselines & Comparisons

SWINGARENA evaluates seven LLMs (GPT-4o, Claude-3.5, Gemini-2.0, DeepSeek-V3, Qwen2.5-Coder-7B/14B, Seed-Coder-8B, DeepSeek-Coder-V2-Lite) in adversarial submitter–reviewer battles rather than proposing a single method to beat baselines. Among proprietary models, GPT-4o is the most aggressive submitter (win rate ≥ 0.90 against every reviewer) but shows the widest variance in CI pass rates (SPR 0.55–0.68), while DeepSeek-V3 and Gemini-2.0 trade a small win-rate margin for higher CI stability (SPR up to 0.66 and 0.64). Claude-3.5 achieves a perfect 1.00 self-play win rate but the lowest cross-language Best@3 (0.55 avg), suggesting strong internal consistency but less generalization. In cross-play, reviewer identity subtly shifts outcomes (e.g., GPT-4o as submitter scores 0.90 vs Claude but 0.94 vs Gemini/DeepSeek), indicating that reviewer strictness matters. Among open-source models (Table 4), DeepSeek-Coder-V2-Lite (16B) edges out Qwen2.5-Coder-14B with slightly higher SPR (0.55 vs 0.52–0.54) and comparable win rates (0.94–0.95), while the 7B/8B tier (Qwen2.5-7B, Seed-8B) trails with SPR around 0.48–0.52 and win rates of 0.87–0.90.

## Relation to Prior Work

SWINGARENA extends the SWE-Bench line of work (GitHub-issue-grounded code evaluation) in three deliberate directions: multi-language coverage (C++, Python, Rust, Go vs. Python-only), full CI pipeline integration (GitHub Actions, linters, style gates) rather than isolated unit tests, and an adversarial dual-agent protocol where LLMs alternate as patch submitters and test-case reviewers. The RACG retrieval module repurposes standard components (BM25 file retrieval, syntax-aware chunking, CodeBERT dense reranking, token-budget packing) into a unified pipeline, explicitly positioned as a strong reproducible baseline rather than a novel algorithmic contribution. The paper carves new ground primarily through the adversarial evaluation protocol itself—no prior benchmark operationalizes the submitter-reviewer CI loop with role switching and per-round scoring.

## Why It Matters / Open Questions

The adversarial CI-driven protocol surfaces model behavioral differences (aggressive patching vs. correctness prioritization) that static, single-shot benchmarks systematically under-report, offering a more faithful proxy for professional software development workflows. Key limitations include the fixed retrieval window (5 files, 16 chunks) that bottlenecks complex multi-file issues, the computational overhead of iterative CI simulation via Docker/act, and the RACG module's reliance on a dense reranker trained on modern code patterns. Open questions the authors identify include iterative and hierarchical retrieval strategies, hybrid sparse-dense-code-graph retrieval, and whether the adversarial protocol's findings generalize beyond the four evaluated languages and the 400-instance evaluation split.
