## Problem

Existing code search benchmarks predominantly target Python, often contain non-compilable snippets, and rarely stress-test model robustness against textual perturbations such as identifier renaming. This leaves it unclear whether high retrieval scores reflect genuine code semantic understanding or mere reliance on superficial lexical features like variable and function names.

## Input / Output

Each query-code pair couples an LLM-generated natural language description (validated via double-blind hypothesis testing against human expert annotations) with a fully compilable C/C++ function mined from real GitHub repositories. The benchmark provides five evaluation settings per pair—standard source, neutralized (generic structural placeholders), randomized (random identifiers), x86 Assembly, and WebAssembly (.wat)—and categorizes snippets into three dependency-complexity groups (stdlib-only, custom types, helper functions), with Group 3 further split into short (separate helper functions as distinct candidates) and long (merged into one snippet) variants using graded relevance labels.

## Method

The automated pipeline mines functions from 144 popular GitHub repositories, filters for compilability within a whitelisted standard-library environment, and categorizes them by dependency complexity. LLMs (o3-mini, grok-4) generate natural language queries with explicit instructions to avoid identifier names, and query quality is validated through a double-blind hypothesis testing protocol using bootstrap analysis to confirm LLM descriptions match or exceed human expert quality. For robustness evaluation, the pipeline applies four transformations: neutralizing identifiers with structural placeholders, randomizing identifiers, compiling to x86 Assembly via g++ with objcopy symbol stripping, and compiling to WebAssembly via Emscripten. Six embedding models (BM25, CodeT5+, OASIS, Nomic-emb-code, OpenAI-text-embedding-large, Voyage-code-3) are evaluated across all settings, and a finetuning experiment using InfoNCE loss with in-batch negatives (τ=0.05, 5 epochs) demonstrates that standard supervised adaptation cannot close the persistent performance gap between standard and anonymized settings.

## Results

On the CLARC standard setting, Voyage-code-3 achieves the highest NDCG across most groups (88.99 on Group 1, 94.06 on Group 2, 66.66 on Group 3 Short, 89.13 on Group 3 Long), closely followed by OASIS and Nomic-emb-code. The headline finding is a dramatic robustness collapse: when identifiers are anonymized, Voyage's NDCG on Group 3 Short drops from 66.66 to 27.65 (neutralized) and 30.54 (randomized), and on Assembly/WebAssembly settings, even the best model (Voyage) falls to 34.12/31.40 NDCG on Group 1 versus 88.99 on the standard setting. BM25, the lexical baseline, scores below 20 NDCG on all standard groups, confirming that embedding-based models substantially outperform term-matching, yet all embedding models remain heavily dependent on identifier names.

## Baselines & Comparisons

Voyage-code-3 leads on NDCG in Groups 1, 2, and 3 Long (88.99, 94.06, 89.13) and on R@1 in Group 3 Short (27.28), while OASIS edges it out on Group 1 NDCG (89.08 vs 88.99) and Nomic-emb-code matches closely on Group 1 MRR (86.23 vs 86.93). OpenAI-text-embedding-large, despite being a general-purpose model, surprisingly outperforms the code-specific Nomic and OASIS on Group 3 Long (NDCG 83.80 vs 69.46/68.59), suggesting its broader pretraining helps with longer multi-function contexts. CodeT5+ (110M, early 2023) trails all modern models by 20–70 NDCG points and uniquely degrades on Group 3 Long relative to Group 3 Short, indicating poor handling of extended context. BM25, the lexical baseline, scores below 20 NDCG everywhere, confirming that dense embeddings are essential but also that the gap between BM25 and the best model (up to ~76 NDCG on Group 2) is largely driven by identifier-name matching rather than deep semantics. Under the neutralized/randomized settings, all models lose 10–40 NDCG points, with the largest drops in Group 3 (e.g., Voyage Group 3 Short: 66.66 → 27.65), and OASIS shows the smallest relative degradation among open models, consistent with its robustness-focused training. On Assembly/WebAssembly, only Voyage-code-3 and OpenAI are evaluated (others lack low-level language support); Voyage consistently outperforms OpenAI (e.g., Group 1 NDCG 34.12 vs 11.50 on Assembly), but both collapse to near-random levels relative to their standard-setting scores.

## Relation to Prior Work

This paper extends the lineage of code search benchmarks (CodeSearchNet, CoSQA, CodeXGLUE, RepoQA, COIR, XCodeEval) by addressing three specific gaps: Python-centric language coverage, non-compilable snippets, and absence of robustness stress tests. It builds on the dense retrieval paradigm (CodeT5+, OASIS, Nomic-emb-code, Voyage-code-3, OpenAI-text-embedding-large) and the emerging practice of using LLMs for automated benchmark construction, adapting a hypothesis-testing validation framework from Wang et al. (2023a). The key conceptual departure is treating identifier anonymization and compilation to low-level languages (Assembly, WebAssembly) as first-class evaluation conditions rather than afterthoughts, directly probing whether retrieval models encode code semantics or merely surface lexical patterns.

## Why It Matters / Open Questions

The benchmark reveals that all six evaluated SOTA code search models exhibit substantial and universal performance degradation when identifiers are anonymized or code is compiled to low-level representations, and that standard supervised fine-tuning fails to close the robustness gap—suggesting the lexical reliance is deeply embedded in current embedding architectures. This finding has practical implications for RAG pipelines and code search tools operating on obfuscated, minified, or cross-compiled code. Open questions include whether the robustness gap can be addressed through architectural changes (e.g., structure-aware encoders), whether the pipeline generalizes beyond C/C++, and how to build training data that teaches genuine semantic invariance rather than surface pattern matching.
