## Problem

Existing FL watermarking methods either provide non-traceable black-box verification (e.g., WAFFLE) or traceable but white-box verification requiring parameter access (e.g., FedTracker), leaving a gap in formally defining and solving traceable black-box watermarking for FL. The paper formalizes this problem and proposes a server-side method that enables both ownership verification and leaker identification without requiring access to model parameters.

## Input / Output

The server consumes per-client model updates (Δ_i), a set of n distinct OOD watermark datasets (100 samples each, drawn from MNIST, SVHN, or synthetic WafflePattern triggers), and the current global model parameters. It produces a personalized watermarked model for each client and, upon suspicion, a binary verification result identifying which client leaked the model. Verification is performed by evaluating the suspect model on the full watermark test set and checking whether the highest per-label accuracy matches the pre-assigned label of the suspected client.

## Method

TraMark partitions the model parameter space into a main task region and a small watermarking region (default k=1%) using complementary binary masks, selected after a warmup training phase (α=0.5 of total rounds) by assigning the least-magnitude parameters to the watermarking region. During aggregation, a masked aggregation scheme averages updates only in the main task region while preserving each client's own watermarking-region parameters, preventing watermark fusion across clients. Watermark injection then fine-tunes only the watermarking region on a client-specific OOD trigger dataset for τ_w=5 iterations, with gradients zeroed in the main task region. Each client receives a personalized global model that aggregates collective knowledge for the main task while embedding a unique, non-colliding backdoor watermark exclusively in the watermarking region, enabling black-box leaker identification via per-label accuracy on the watermark test set.

## Results

Across FMNIST, CIFAR-10, CIFAR-100, and Tiny-ImageNet (both IID and non-IID), TraMark achieves an average main task accuracy (MA) of 64.90%, only 0.54% below the FedAvg baseline (65.44%), while attaining a 99.58% average verification rate (VR) for leaker identification. On CIFAR-10, TraMark reaches 88.58% MA with 100% VR; on CIFAR-100, 61.13% MA with 100% VR; and on Tiny-ImageNet, 20.91% MA with 100% VR. The per-client injection time is approximately 0.67 seconds, yielding a total server-side overhead of 6.85 seconds per round for 10 clients.

## Baselines & Comparisons

TraMark is compared against three baselines: FedAvg (the standard FL training protocol with no watermarking), WAFFLE (a server-side black-box watermarking method that does not ensure traceability), and FedTracker (a server-side white-box watermarking method that does ensure traceability). Against FedAvg, TraMark incurs only a 0.54% average MA drop (64.90% vs. 65.44%) while adding full traceability. Against WAFFLE, which achieves a marginally higher average MA (65.31% vs. 64.90%, a 0.41% gap), TraMark provides the critical traceability property that WAFFLE lacks entirely. Against FedTracker, TraMark substantially outperforms on both metrics: it achieves 3.65% higher average MA (64.90% vs. 61.25%) and 12.08% higher average VR (99.58% vs. 87.50%), with the gap most pronounced on CIFAR-10 where FedTracker's VR drops to 60% (IID) and 50% (non-IID) while TraMark maintains 100%. FedTracker's lower MA stems from its unconstrained watermarking region that perturbs the full parameter space, whereas TraMark's masked aggregation confines watermarking to 1% of parameters.

## Relation to Prior Work

TraMark builds on the backdoor-injection paradigm for black-box watermarking (Adi et al., 2018) and the server-side watermarking framework of WAFFLE (Tekgul et al., 2021), but departs from both by introducing a parameter-space partition (main task region vs. watermarking region) and masked aggregation to prevent watermark collision during FedAvg-style averaging. It addresses a specific gap identified in prior traceable methods: FedTracker (Shao et al., 2024) achieves traceability but requires white-box access, while FedCRMW (Nie & Lu, 2024a) is black-box and traceable but operates client-side and requires access to local data. The paper's key conceptual departure is confining watermark learning to a small, fixed subset of parameters and excluding that subset from aggregation, which simultaneously preserves per-client watermark distinctness and limits main-task degradation.

## Why It Matters / Open Questions

TraMark is the first method to simultaneously satisfy black-box verification, server-side injection, and per-client traceability in FL, filling a practical gap for IP protection in cross-silo deployments where leaked models are only accessible via API. The 0.54% average accuracy drop with ~100% verification rate across diverse architectures (CNN, VGG, ViT) and datasets makes it a deployable solution. Open questions include the lack of theoretical guarantees on traceability, the 1/r false-positive rate on small-label datasets, vulnerability to client collusion (identifying the watermarking region by comparing identical main-task parameters), and whether the linear server-side cost remains acceptable at very large client scales beyond the 100-client ImageNet experiment.
