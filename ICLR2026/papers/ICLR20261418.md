## Problem

Existing LLM agents depend heavily on open-web search, which is noisy and cannot provide the precise, domain-specific knowledge required by high-stakes tasks in medicine, finance, and other fields. Although the Model Context Protocol (MCP) now exposes thousands of specialized tools to agents, no benchmark evaluates whether agents can effectively leverage these domain tools—and more critically, whether they can integrate multiple heterogeneous tools with general-purpose search to solve complex multi-source information-seeking tasks.
![Teaser figure](../imgs/ICLR20261418/cropped_page1_idx0.webp)

## Input / Output

Each task instance consists of a natural-language query (in English or Chinese) that encodes multiple interdependent conditions, paired with a domain-specific MCP tool set (77 tools across 7 servers spanning maps, finance, biomedical databases, YouTube, and web search). The agent produces a final text answer, which is scored on two metrics: Accuracy (strict end-to-end correctness judged by an LLM) and Pass Rate (fraction of condition-level subquestions with gold answers that the agent satisfies). The tool-calling limit is set to 20 invocations per task, and the agent framework uses ReAct with OpenAI's function-calling interface executed inside a Python Sandbox.

## Method

InfoMosaic-Flow is a two-stage agentic synthesis pipeline built on an organizer-workers architecture. In Stage 1 (Information Seeking), a synthesizer (organizer) proposes diverse scenarios from seed data, then issues high-level subtask instructions to domain-specific executors (workers) who autonomously select and chain tools to retrieve verified evidence; the synthesizer integrates this evidence into a coherent multi-condition problem. In Stage 2 (Iterative Refinement), a Verifier equipped only with web-search attempts to solve the draft problem; the Refiner decomposes conditions, fuzzes any that are too revealing (rewriting or combining them), and recomposes the question until neither web search alone nor any single condition can independently yield the answer. Quality control enforces a minimum tool-call threshold, answer-evidence consistency (final answers must be exactly derivable from collected tool outputs), coherence filtering, and manual annotation review. This design guarantees that every admitted task is grounded in verifiable tool evidence and genuinely requires multi-source reasoning rather than trivial lookup.

## Results

On InfoMosaic-Bench (621 tasks, 77 MCP tools, 6 domains), the best closed-source model GPT-5 achieves only 38.2% accuracy and 67.5% pass rate using web search alone, while the best open-source model GLM-4.5 reaches 20.6% accuracy and 27.0% pass rate. Adding domain-specific tools yields selective gains: GPT-5 improves by +7.41 in Map and +10.00 in Video but drops by −9.73 in Medical/Bio and −9.00 in Finance. Overall, 22.4% of failures stem from incorrect tool usage or selection, and performance plateaus after ~8 tool calls.

## Baselines & Comparisons

The paper does not compare against prior benchmarks or methods; instead, it contrasts two agent configurations (web-search-only vs. domain-tool-equipped) across 14 LLMs. GPT-5 with domain tools improves overall accuracy from 38.18% to 38.61% (+0.43), with clear gains in Map (+7.41) and Video (+10.00) but notable drops in Medical/Bio (−9.73) and Finance (−9.00), indicating inconsistent tool exploitation. GLM-4.5 shows a similar pattern: overall accuracy rises from 20.61% to 21.51% (+0.90), with gains in Map (+5.93) and Medical/Bio (+7.23) but losses in Web (−4.00) and Finance (−2.00). Closed-source models outperform open-source models by 15–20 percentage points in accuracy, yet both groups remain far below human-level performance (27.89% human baseline on a 60-task subset vs. 37.67% for GPT-5 with web tools). The key takeaway is that tool availability is not the bottleneck—correct tool selection, parameterization, and cross-source orchestration remain the primary failure modes.

## Relation to Prior Work

This paper carves out a new evaluation space at the intersection of three existing benchmark lines: API-centric tool-use benchmarks (ToolBench, τ-Bench, MCP-Bench) that test single-tool invocation correctness, web-search benchmarks (BrowseComp, WebWalkerQA) that restrict agents to a single retrieval channel, and MCP-ecosystem benchmarks (MCP-Universe, MCP-Radar) that focus on tool discovery and execution robustness. None of these evaluate whether an agent can *integrate* general-purpose web search with multiple domain-specific MCP tools to solve a single information-seeking task. The synthesis pipeline (InfoMosaic-Flow) repurposes the organizer-workers multi-agent pattern—previously used in agentic planning literature—for scalable, cross-domain task generation grounded in verified tool outputs, departing from template-based or purely human-curated benchmark construction.

## Why It Matters / Open Questions

The benchmark exposes a concrete and actionable gap: even the strongest model (GPT-5) achieves only 38.2% accuracy with web search alone, and adding domain-specific tools yields *selective* gains (Map, Video) while actively *degrading* performance in Medical, Finance, and Multi-domain settings. This challenges the implicit assumption that richer tool access monotonically improves agent performance and points to tool-selection and orchestration as the true bottleneck. Open questions include whether the degradation in structured domains stems from parameter complexity, tool-inventory confusion, or planning-horizon limits, and whether targeted training on tool-use trajectories can close the gap. As the MCP ecosystem expands to thousands of tools, a reliable multi-source evaluation becomes a prerequisite for deploying agents in high-stakes domains.
