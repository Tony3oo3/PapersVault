## Problem

Reachability-based neural network verification often yields inconclusive results because the conservative enclosure of the output set intersects the unsafe set even when no truly unsafe input exists. Existing branch-and-bound approaches reduce conservatism by splitting the input set, but this can require exponentially many subproblems. The paper asks whether the structural dependencies between input and output enclosures—arising from the shared latent space of projection-based set representations—can be exploited to directly discard provably safe inputs before splitting.

## Input / Output

The method consumes a feed-forward neural network (layer weights and biases), an input set represented as a zonotope (center vector plus generator matrix), and an unsafe set specified as a convex polytope (matrix A and vector b defining halfspace constraints Ax ≤ b). It returns either a formal proof of safety (VERIFIED) or a concrete counterexample input x̃ ∈ X such that Φ(x̃) ∈ U (FALSIFIED). The zonotope representation is critical: the number of generators q_0 in the input set determines the dimensionality of the latent space shared with the output enclosure, and the algorithm is designed to operate entirely through matrix multiplications on these generator matrices.

## Method

The key insight is that a zonotope is the projection ('shadow') of a higher-dimensional hypercube, and propagating a zonotope through a neural network transforms only the shadow while the underlying hypercube (the latent space) remains unchanged. Proposition 2 formalizes how to transfer the unsafe set from output space to input space: the first q_0 columns of the output generator matrix G_y correspond to the input factors, so the unsafe constraint A·y ≤ b can be projected onto the input factors as C·β_[q_0] ≤ d, where C = A·G_y(:,[q_0]) and d = b − A·c_y + |A·G_y(:,[q_κ]\[q_0])|·1, yielding a constrained zonotope X|_{C≤d} that encloses all unsafe inputs. This refinement is applied iteratively (up to 8 iterations per subproblem) within a branch-and-bound loop, where each subproblem is first refined to shrink the input set, then split along the dimension or ReLU neuron with the largest enclosure-gradient score (measuring the contribution to the F-radius of the output enclosure). The entire pipeline—set propagation, verification check, falsification via boundary-point sampling in the latent space, and input refinement—uses only matrix operations, enabling batch-wise GPU acceleration that simultaneously processes up to 1024 subproblems.

## Results

On the 8 VNN-COMP'24 benchmarks, CORA (the proposed tool) achieves competitive performance, matching the top result in 4 of 8 benchmarks (collins-rul-cnn, dist-shift, linear-izenn, tllverify-bench at 100% solved). On the remaining benchmarks, CORA is within 1–11% of the best tool: 99.5% on acasxu (vs. 100% for α-β-CROWN), 81.1% on cora (vs. 87.8%), 97.0% on meta-room (vs. 98.0%), and 89.2% on safenlp (vs. 100%). The input refinement ablation shows a 59.6% reduction in subproblems on acasxu and 65.3% on safenlp, while GPU acceleration with batch size 1024 speeds up verification by 82.8% (acasxu) and 89.8% (safenlp) over CPU.

## Baselines & Comparisons

Against α-β-CROWN (the overall top performer), CORA ties on 4 benchmarks and is within 1% on acasxu (99.5% vs. 100%) and meta-room (97.0% vs. 98.0%), but trails by 6.7% on cora (81.1% vs. 87.8%) and 10.8% on safenlp (89.2% vs. 100%). Against NeuralSAT, CORA wins on acasxu (99.5% vs. 98.9%) but loses on cora (81.1% vs. 87.2%) and safenlp (89.2% vs. 90.5%). Against PyRAT, CORA wins on collins-rul-cnn (100% vs. 93.5%) and safenlp (89.2% vs. 79.9%) but slightly loses on cora (81.1% vs. 83.3%). Against Marabou, CORA dominates on meta-room (97.0% vs. 53.0%) and safenlp (89.2% vs. 62.5%), and wins on acasxu, dist-shift, and tllverify-bench. Against nnenum, CORA achieves large margins on cora (81.1% vs. 14.4%), meta-room (97.0% vs. 46.0%), and tllverify-bench (100% vs. 56.2%). For falsification, the paper's set-based adversarial attack outperforms FGSM by falsifying 60.3% more instances on safenlp (647 vs. 257 within 50 iterations).

## Relation to Prior Work

This paper builds on the constrained zonotope framework (Scott et al., 2016) and the set-propagation machinery for neural network verification (Ladner & Althoff, 2023; Koller et al., 2025), introducing the conceptual insight that the underlying hypercube of a zonotope remains invariant during propagation through network layers, forming a 'latent space' that links input, hidden, and output enclosures. Unlike prior iterative refinement approaches that rely on solving (mixed-integer) linear programs or counterexample-guided abstraction refinement (Wang et al., 2018; Wu et al., 2024), the specification-driven input refinement here transfers output-space constraints to input-space constraints purely through matrix operations on the shared latent factors. The branch-and-bound structure and splitting heuristics follow the standard verification paradigm, but the paper departs from most competitors by implementing the entire pipeline with only matrix operations to exploit GPU batch processing, a practical distinction from tools like α-β-CROWN or Marabou that rely on more diverse computational primitives.

## Why It Matters / Open Questions

The ~60% reduction in branch-and-bound subproblems and the 80–90% GPU speedup make formal verification of larger networks more tractable, and the competitive VNN-COMP'24 results validate the approach against the strongest existing tools. However, the method is inherently tied to projection-based set representations (zonotopes), and the refinement is conservative—it encloses unsafe inputs but does not preserve a tight output enclosure, limiting its applicability to non-convex or highly nonlinear specifications. Open questions include whether the latent-space transfer generalizes to richer representations (polynomial zonotopes, hybrid zonotopes) that capture ReLU piecewise linearity exactly, and whether the approach can be combined with gradient-based bound tightening (as in α-β-CROWN) for further conservatism reduction on high-dimensional benchmarks like cora where performance lags the best tools.
