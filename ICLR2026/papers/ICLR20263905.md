## Problem

Existing multimodal large language models are largely passive: they can interpret images and text but cannot autonomously invoke external tools such as code execution environments or web search to augment their reasoning. The paper further reveals that applying reinforcement learning directly to a base MLLM fails to induce stable tool-use behavior—models either produce buggy code, abandon tool use entirely, or degenerate into reward-hacking by emitting placeholder code blocks—highlighting a critical gap in how agentic multimodal models should be trained.

## Input / Output

The model receives an RGB image (loaded as a PIL variable in a shared Jupyter kernel) and a free-form text query. During reasoning, it can emit Python code enclosed in <code> tags (executed in a sandboxed environment with 300s timeout, returning stdout, stderr, and any plt.show() images) and issue search function calls (image_search via SerpAPI returning 5 visually matched webpages, or text search via Google returning 5 relevant pages with titles and snippets). The final output is a text answer wrapped in <answer> tags, preceded by interleaved think/code/function-call blocks. Only one tool type may be invoked per round, and image search is limited to a single call per trajectory.

## Method

DeepEyesV2 builds on Qwen2.5-VL-7B with a two-stage training pipeline motivated by the finding that direct RL alone cannot bootstrap reliable tool use. Stage 1 (cold-start SFT) trains on a curated dataset of tool-augmented trajectories—spanning perception (cropping, counting), reasoning (numerical computation, code-based problem solving), search (image and text retrieval), and long chain-of-thought data—filtered for difficulty (base model answers correctly ≤2/8 times) and tool benefit (tool use improves accuracy). Stage 2 (RL via DAPO) uses a sparse outcome-driven reward combining accuracy and format penalties, with 16 rollouts per prompt and zero KL coefficient, to refine adaptive tool invocation. The key architectural insight is that code execution and web search are treated as complementary, interleavable tools within a single iterative reasoning loop rather than isolated modules, enabling the model to dynamically combine heterogeneous tools (e.g., cropping an image then searching for context) and learn task-adaptive strategies—favoring image operations for perception and numerical computation for reasoning—without complex reward engineering.

## Results

On real-world understanding benchmarks, DeepEyesV2 (7B) achieves 81.8 on V* Bench, 77.9 on HRBench-4K, and 64.9 on MME-RealWorld, surpassing the 4× larger Qwen2.5-VL-32B on V* Bench (81.8 vs. 80.6) and HRBench-4K (77.9 vs. 74.1). On mathematical reasoning, DeepEyesV2 reaches 52.7% on MathVerse (+7.1 over Qwen2.5-VL-7B) and 57.2% on DynaMath, consistently outperforming both grounded reasoning models (DeepEyes, Thyme) and text-only reasoning models. On search-intensive tasks, DeepEyesV2 achieves 63.7% on MMSearch, substantially exceeding MMSearch-R1 (53.8%) and proprietary models GPT-4o (22.2%) and Gemini 2.5 Pro (26.9%).

## Baselines & Comparisons

Against the base model Qwen2.5-VL-7B, DeepEyesV2 achieves consistent gains across all 10 benchmarks, with the largest improvements on MME-RealWorld (+7.6), CharXiv reasoning (+8.7), and OCRBench (+18). Notably, the 7B DeepEyesV2 surpasses the 4× larger Qwen2.5-VL-32B on V* Bench (81.8 vs. 80.6), HRBench-4K (77.9 vs. 74.1), HRBench-8K (73.8 vs. 69.9), and CharXiv reasoning (48.9 vs. 48.0). Among grounded reasoning models, DeepEyesV2 outperforms DeepEyes on HRBench-4K (77.9 vs. 75.1), HRBench-8K (73.8 vs. 72.6), and TreeBench (42.5 vs. 37.5), though it trails on V* Bench (81.8 vs. 85.6); it also edges out Thyme on HRBench-4K (77.9 vs. 77.0) and HRBench-8K (73.8 vs. 72.0). On search benchmarks, DeepEyesV2 beats MMSearch-R1 on FVQA-test (60.6 vs. 58.4), MMSearch (63.7 vs. 53.8), and SimpleVQA (59.4 vs. 57.4), but loses on InfoSeek (51.1 vs. 55.1). Against proprietary models, DeepEyesV2 substantially outperforms GPT-4o and Gemini 2.5 Pro on all four search benchmarks (e.g., 63.7 vs. 22.2 on MMSearch), while on reasoning it trails Gemini 2.5 Pro (81.4 on MathVerse) but exceeds GPT-4o (54.0 on MathVerse).

## Relation to Prior Work

DeepEyesV2 extends the 'thinking with images' paradigm introduced by o3 and operationalized by DeepEyes (Zheng et al., 2025b), which used RL alone to incentivize image cropping. It generalizes the tool set from single-region cropping (DeepEyes, Pixel-Reasoner) or code-based image manipulation (Thyme, PyVision) to a unified agentic loop that interleaves arbitrary Python code execution with web search (image and text) via SerpAPI. A key departure from DeepEyes is the demonstration that RL alone is insufficient to bootstrap tool use, necessitating a cold-start SFT stage with curated trajectories—a finding that contrasts with DeepEyes' RL-only recipe and aligns with the two-stage pipelines used by Grit, Mini-o3, and other 'think with image' works.

## Why It Matters / Open Questions

The paper provides a practical, reproducible recipe (curated cold-start SFT + DAPO-based RL with simple accuracy/format rewards) for building agentic multimodal models, and its pioneer experiments documenting reward hacking under RL-only training offer a useful cautionary result for the community. The zero-shot generalization to unseen tools on TIR-Bench suggests the learned tool-use behavior is not overfit to specific operations. However, the model remains a 7B system dependent on external APIs (SerpAPI, sandboxed Python), and the error analysis reveals persistent failures in tool execution, selection, and result interpretation—open questions include whether these patterns hold at larger scale, whether the cold-start requirement can be eliminated, and how to reduce reliance on brittle external tooling.
