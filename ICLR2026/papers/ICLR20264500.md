## Problem

LLM-based multi-agent code generation for scientific tasks suffers from compounding hallucinations: errors in generated code propagate through test cases that inherit the same reliability flaws, and the system's overall quality is bounded by its weakest agent. Standard prompting and self-refinement techniques cannot handle the subtle error patterns in complex scientific workflows, and there is no principled mechanism to simultaneously refine code, test cases, and prompts without relying on any single LLM's absolute correctness.

## Input / Output

The framework accepts a natural-language task description (often vague, using domain-specific terminology), optional prior knowledge (physical formulas, reference code samples), and iterative user feedback during an interactive planning loop. It produces a single executable Python function integrating all sub-task components, a dynamically evolving pool of test cases with per-test difficulty scores, and a structured task plan decomposed into typed sub-tasks with input/output specifications. The TM agent internally expands raw prompts into refined task descriptions with domain-specific feature engineering advice before code generation begins.

## Method

The framework employs three agents in a recursive adversarial loop: a Task Manager (Challenger) that constructs and refines test cases to probe the Solution Generator's (Solver) current limitations, and an Evaluator that computes three non-LLM-based scores — S1 (test-case 'true hardness' via pass-rate differential), S2 (code score weighted by test difficulty), and S3 (composite prompt score). Prompt composition for each iteration is governed by a Bayesian update rule p(Prompt_{ij}^{t+1}|S_3^t) ∝ p(S_3^t|Prompt_{ij}^t)·p(Prompt_{ij}^t), which adaptively selects test-case/sample-code pairs that historically yield high-scoring prompts. To avoid expensive full execution of all N candidate codes, a Gaussian Process surrogate trained on AST- and embedding-based structural features predicts untested code performance, and a UCB acquisition function selects the most informative candidates for evaluation. The TM agent also performs interactive planning with the user, decomposing tasks into typed sub-tasks and generating initial sanity-check test cases, thereby translating vague domain-expert prompts into precise, scientifically valid specifications without requiring prompt-engineering expertise.

## Results

On the SciCode benchmark, the LCP framework delivers substantial relative improvements across all tested models, with the largest gain of 87.1% for Qwen3-8B (13.2→24.7 Subproblem Resolve Rate without knowledge). On ScienceAgentBench (GPT-4o), LCP achieves a Valid Execution Rate of 90.2% (without knowledge), surpassing the next-best Self-Debug (83.3%) by 6.9 points. On general code generation (GPT-3.5-turbo), LCP reaches 88.4% pass@1 on HumanEval and 91.1% on MBPP, outperforming all compared agentic baselines. On the APPS Competition tier (GPT-4o), LCP scores 38.0% pass@1, leading LPW (34.8%) and LDB (28.3%).

## Baselines & Comparisons

On SciCode, LCP consistently outperforms the zero-shot baseline across all 8 model configurations, with the most dramatic gains for smaller open-source models (Qwen3-8B: +87.1%, Qwen3-32B: +79.3%), enabling a 32B model to match or exceed a 235B model's baseline. On ScienceAgentBench, LCP (GPT-4o) beats Self-Debug by 3.9 SR points and 6.9 VER points, and OpenHands CodeAct by 6.9 SR and 11.8 VER points, establishing new SOTA on all three metrics. On general code generation with GPT-3.5-turbo, LCP surpasses CodeCoR (86.6→88.4 on HumanEval), AgentCoder (79.9→88.4), MapCoder (80.5→88.4), and Reflexion (68.1→88.4), though AgentCoder edges out LCP on MBPP-ET (89.1 vs. 86.4). With GPT-4, LCP achieves 96.95% on HumanEval, marginally ahead of AgentCoder (96.3%) and CodeCoR (94.5%), while MetaGPT trails significantly at 85.9%. On the APPS benchmark (GPT-4o), LCP leads all difficulty tiers: 92.1% (Introductory) vs. LPW 87.2%, 77.5% (Interview) vs. LPW 65.2%, and 38.0% (Competition) vs. LPW 34.8%.

## Relation to Prior Work

This paper extends the multi-agent code generation lineage (MetaGPT, AgentCoder, CodeCoR, MapCoder) by introducing an adversarial co-evolution dynamic between a Task Manager (Challenger) and Solution Generator (Solver), where test cases and code are jointly optimized rather than treated as a static verification step. The key conceptual departure from prior agentic frameworks is the use of a non-LLM-based Bayesian updating rule (governed by score equations and a GP surrogate with AST embeddings) to select prompt components, reducing the system's dependence on any single LLM's judgment for evaluation and decision-making. The Bayesian Optimization component for code performance prediction (GP + UCB acquisition) repurposes standard BO machinery to the code generation setting, avoiding expensive full execution of all candidates. The framework is explicitly model-agnostic, spanning 1.7B open-source to commercial LLMs, positioning it as a universal wrapper rather than a model-specific technique.

## Why It Matters / Open Questions

The framework's practical value lies in democratizing AI4S code generation for domain scientists without prompt engineering expertise, as demonstrated by the robustness experiments showing non-professional users with the framework outperforming expert users with baseline models. The ability to enable a 32B model to match or exceed a 235B model on SciCode suggests that structured adversarial refinement can partially substitute for raw model scale, which has cost implications for scientific computing. However, the framework's reliance on initial reference code quality, its inability to enforce implicit physical laws without symbolic verifiers, and its higher token consumption relative to one-shot generation remain open challenges. Future work on multi-modal inputs (equations, diagrams) and integration with physics-informed constraints would address the most significant current limitations.
