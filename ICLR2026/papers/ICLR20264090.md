## Problem

Current AI agents can handle isolated research sub-tasks like literature synthesis, hypothesis generation, or code snippet completion, but no existing benchmark evaluates their ability to conduct a complete, end-to-end AI research experiment—from formulating an experimental design to producing a valid conclusion. Prior benchmarks either assess static reasoning over protocols, isolate coding from the broader experimental loop, or operate at limited scale with simplified metrics, leaving a critical gap in measuring whether agents can faithfully execute the full experimentation pipeline that real AI research demands.

## Input / Output

Each task provides the agent with a specific research question extracted from a peer-reviewed paper, a high-level methodological overview, and a cloned GitHub repository with task-specific scripts and documentation (e.g., README.md, relevant scripts) masked via scripted git operations to prevent shortcut access to solutions. The agent must produce an experimental design (variables, constants, procedures), code modifications assessed via git diff against the provided repository, executable scripts that run in a clean Docker container, and a final conclusion answering the research question. Scoring is conjunctive: individual metrics D (design), I (implementation), E (execution), and C (conclusion) are combined into composite scores like I·E and All·E√, so partial credit on one dimension does not compensate for failure on another.

## Method

EXP-Bench is constructed via a three-stage semi-automated pipeline: (1) source selection filters 51 influential NeurIPS/ICLR 2024 papers with open-source code using citation counts and GitHub activity; (2) experiment procedure extraction uses OCR-indexed PDFs with multi-pass LLM querying to identify research questions and expected outcomes, then a tool-augmented implementation agent performs goal-conditioned search over the codebase to locate the exact script chain, validated by execution and parsed via AST tracing into step-by-step natural-language requirements; (3) verification applies an LLM-based monitor to detect disallowed behaviors (paper access, git manipulation, fabricated data), re-executes scripts in clean Docker containers, and performs lightweight human cross-checks. Evaluation employs a dual-component judge: an o3-mini LLM-as-a-judge scores design, implementation, and conclusion correctness against ground truth, while a separate Code Execution Validator runs agent-generated modifications in an equivalent containerized environment to verify executability. The resulting 461 tasks (12,737 gradable subtasks) span diverse AI subfields, and conjunctive metrics substantially reduce score variance compared to individual metrics, surfacing brittleness in end-to-end correctness that single-dimension scores mask.

## Results

On EXP-Bench (461 tasks from 51 papers), the best-performing agent configuration (OpenHands + o3-mini) achieves only 0.5% on the strictest conjunctive metric (All√·E, requiring correct design, implementation, conclusion, AND successful execution). Individual aspect scores are more moderate: design correctness (D) peaks at 20.6% (OH + Claude-3.5 Haiku), implementation correctness (I) peaks at 35.0% (OH + Claude-3.7 Sonnet), and execution success (E) peaks at 33.2% (OH + Claude-3.7 Sonnet). Under the conjunctive All√ metric (D ∧ I ∧ C), even the top agent drops to 1.4%, and adding execution verification (All√·E) further reduces this to 0.5%. Across all 7 agent–model configurations, no agent exceeds 35% on any single metric, and the worst configuration (IterativeAgent + Amazon Nova Pro) scores 0.1% on design and 0.0% on all conjunctive metrics.

## Baselines & Comparisons

EXP-Bench evaluates seven agent–model configurations rather than comparing a single method against baselines. OpenHands (OH) consistently outperforms IterativeAgent (IA) across nearly all metrics: OH + o3-mini leads on the strictest metric (All√·E = 0.5%) and on design (D = 18.4%), while IA + Nova Pro is the worst performer (D = 0.1%, All√·E = 0.0%). Within OpenHands, Claude-3.7 Sonnet achieves the highest implementation (I = 35.0%) and execution (E = 33.2%) scores, but o3-mini edges it out on the conjunctive All√·E metric (0.5% vs. 0.4%), likely because o3-mini produces more complete designs and conclusions. A key behavioral difference emerges: OH models frequently stop early and produce plausible but unexecuted responses (yielding moderate D and I scores), whereas IA models consume the full 40-minute budget but convert that time into fewer correct end-to-end completions. The RL subcategory is the most tractable, with OH + Claude-3.7 Sonnet reaching I = 48.2% and All√·E = 3.0% over 36 tasks, while the Applications and Datasets & Benchmarks categories remain near zero for all configurations.

## Relation to Prior Work

EXP-Bench carves new ground by unifying the full end-to-end AI research experimentation pipeline—design, implementation, execution, and conclusion—into a single evaluation, whereas prior benchmarks isolate sub-components: scientific reasoning benchmarks (AAAR, Lab-Bench) assess static artifacts without execution, coding benchmarks (SciCode, BLADE) focus on code generation or post-hoc analysis, and ML-specific benchmarks (MLE-Bench, PaperBench, RE-Bench) operate on simplified or constrained tasks. The semi-automated curation pipeline that extracts structured experimental procedures from peer-reviewed papers and their codebases is a methodological departure from the hand-curated, small-scale approaches (e.g., RE-Bench's 7 tasks) used in prior work. Conceptually, the benchmark inherits the LLM-as-a-judge paradigm and containerized execution from recent agent evaluation frameworks but applies them to a substantially more complex, multi-phase task structure.

## Why It Matters / Open Questions

The finding that leading agents achieve only 0.5% success on complete, executable experiments—despite 20–35% on individual sub-metrics—sharpens the field's understanding of where AI research automation truly breaks down, pointing to implementation completeness and environment robustness as the dominant bottlenecks rather than conceptual design. The scalable semi-automated pipeline for generating tasks from new papers offers a path to continually expanding the benchmark as the literature grows, reducing contamination risk over time. Key limitations remain: EXP-Bench evaluates faithful execution of extracted procedures rather than open-ended scientific creativity, literature-driven gap identification, or iterative hypothesis refinement, leaving the broader research lifecycle unaddressed. Future work on RL with verifiable rewards using this dataset could directly target the identified failure modes.
