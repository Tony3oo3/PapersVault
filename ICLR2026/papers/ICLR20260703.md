## Problem

Static reasoning benchmarks (GSM8K, MATH, OlympiadBench) are increasingly compromised by training-data contamination, making it impossible to distinguish genuine reasoning from memorized answers. Existing dynamic benchmarks (DyVal, ThinkBench) generate fresh problems but provide no mathematical guarantees that each instance is well-posed with a unique or fully enumerated solution, and none combine formal solution verification, token-budget-aware difficulty calibration, and multi-solution acceptance into a single framework.

## Input / Output

The framework takes a language model (open-source or proprietary), a task suite specification (Easy/Medium/Hard), a model-specific token budget C, and a random seed, then generates 1,000 problem instances per task variation (100 for proprietary models). Output is structured as per-suite accuracy, instruction-following rate, and average token usage, with each response classified as VALID, WARNING, or OVERFLOW based on whether its token count stays within 85% or 100% of the model's output window. For multi-solution tasks (e.g., N-Queens, mode calculation), correctness is determined by membership in the fully enumerated solution set S_p rather than matching a single canonical answer.

## Method

BeyondBench generates problems algorithmically from parameterized combinatorial spaces exceeding 10^15 unique instances per task, making exact-instance contamination provably negligible (Pr[collision] < 10^-3 for any corpus under 10^12 entries). Each generated instance is validated by CSP/SAT solvers (python-constraint, pysat) that either confirm a unique solution or exhaustively enumerate all valid solutions, guaranteeing zero false positives or negatives in scoring. Difficulty scales monotonically with parameters (e.g., Tower of Hanoi disks n∈[3,12], Sudoku empty cells 30–50, Boolean SAT variables 3–8), spanning polynomial-time Easy tasks through NP-complete Hard tasks, with a token-aware calibration step that iteratively reduces problem size (n' = ⌊0.8n⌋) until estimated solution tokens fit within 0.85·C. The evaluation pipeline applies arc-consistency domain reduction for constraint problems, dynamic programming for optimization tasks (e.g., Matrix Chain), and task-specific robust parsers that handle diverse LLM output formats, distinguishing format failures from reasoning errors.

## Results

Across 101 models evaluated on 44 algorithmic tasks (117 variations), GPT-5 (with tools) achieves the highest overall accuracy at 83.57%, with 71.68% on the Hard suite. The best open-source model, GPT-OSS-120B, reaches 75.99% overall but only 59.41% on Hard tasks, while most open-source models plateau around 30–35% on NP-complete problems. Performance degrades sharply with complexity: the best open-source model scores 93.27% on Easy but drops to 59.41% on Hard. Without tool access, GPT-5, GPT-5-mini, and GPT-5-nano lose 16.81%, 15.86%, and 43.95% overall accuracy respectively, revealing heavy reliance on external computation.

## Baselines & Comparisons

The paper does not benchmark against other evaluation frameworks head-to-head but instead compares model configurations and tool-augmentation strategies on the same BEYONDBENCH tasks. Proprietary GPT-5 (83.57% overall, 71.68% Hard) outperforms the best open-source GPT-OSS-120B (75.99% overall, 59.41% Hard) by 7.58 and 12.27 percentage points respectively, a gap the authors attribute to internal tool use rather than scale alone. Removing tools causes GPT-5 to drop 16.81% overall (83.57%→66.8%) and GPT-5-nano to drop 43.95% (82.0%→38.1%), demonstrating that agentic tool orchestration is the primary driver of top performance. 'Thinking' variants yield only marginal gains (Qwen3-4B-thinking: +2.14%; Qwen3-30B-MOE-thinking: +0.2%), while mathematical fine-tuning actively hurts algorithmic reasoning (Qwen2.5-72B-math: 48.48% vs. 53.36% base, a 4.88% drop). The paper also contrasts static benchmark performance with BEYONDBENCH: models claiming 90%+ on GSM8K achieve only ~50% on equivalent dynamically generated tasks, and after fine-tuning on 66K BEYONDBENCH instances, Hard-suite improvement is limited to +10–15% versus +27–38% on Easy/Medium, confirming NP-complete problems resist memorization.

## Relation to Prior Work

BEYONDBENCH carves new ground at the intersection of dynamic benchmark generation (DyVal, ThinkBench) and formal constraint-satisfaction verification (FCoReBench, NPHardEval), but departs from all prior work by combining three properties no single existing benchmark offers: (i) provably large combinatorial problem spaces (>10^15 instances per task) with CSP/SAT-based solution uniqueness or full enumeration, (ii) token-budget-aware difficulty calibration, and (iii) multi-solution acceptance. Unlike CLRS or MathArena, it is not static; unlike DyVal or GameArena, it provides mathematical guarantees on well-posedness; unlike NPHardEval, it handles constructive (not just decision) problems and accounts for model output limits. The tool-augmented evaluation draws on PAL and Logic-LM but extends them to a contamination-resistant, multi-solution setting across 44 tasks.

## Why It Matters / Open Questions

The benchmark provides the field with a contamination-resistant, scalable yardstick for algorithmic reasoning that static benchmarks cannot offer, and its 101-model evaluation reveals that parameter scaling yields only logarithmic gains with a hard ceiling (~30-35%) on NP-complete tasks for most open-source models. Two findings challenge common assumptions: mathematical fine-tuning actively degrades algorithmic performance (Qwen2.5-72B-math loses ~5 points), and GPT-5-family models lose 16-44% accuracy without tool access, suggesting frontier 'reasoning' may be primarily tool orchestration rather than internal symbolic manipulation. Open questions include whether agentic architectures can close the gap to human-level algorithmic execution, whether the benchmark's focus on known-algorithm tasks captures the full scope of 'reasoning,' and whether the observed performance cliffs reflect fundamental transformer limitations or are addressable through architectural changes.
