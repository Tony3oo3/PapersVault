## Problem

Current AI agents operate with fixed policies and cannot learn complex skills on the fly at test time, behaving like 'clever but clueless interns' in novel environments. Existing adaptation methods—reflection, memory, and online RL—either modify only a single component (e.g., the prompt) or are too slow and data-inefficient for rapid in-session learning. The paper identifies the lack of a standardized benchmark for measuring rapid, in-session improvement and the inability of prior methods to perform holistic, multi-component adaptation from a single episode's experience.

## Input / Output

The Actor Agent consumes textual game observations from Jericho interactive-fiction games (e.g., 'You are in the Chief's office. A piece of white paper is on the desk.') and queries a structured success/failure memory database keyed by state hashes, producing a single natural-language command per step (e.g., 'TAKE PAPER'). The Evolver Agent takes the full episode transcript (a sequence of up to 110 observation-action-reward tuples) plus the current agentic configuration χ=(p,M,h,u) and outputs a complete revised configuration in a single LLM call: a rewritten policy prompt, JSON-formatted memory entries, a hyperparameter JSON object, and a Python state-extractor function. Configuration selection between episodes uses UCB scoring over the parent and m child candidates.

## Method

EvoTest decouples acting from adaptation via a two-agent loop: an Actor Agent plays one full episode under a fixed configuration, and an Evolver Agent (powered by a stronger LLM) analyzes the entire transcript to propose m child configurations through four evolutionary operators—prompt mutation (encoding new strategies and guardrails), structured memory update (logging state-action pairs that preceded score changes into success/failure tables), hyperparameter tuning (adjusting temperature and exploration strength), and tool-use refinement (rewriting the Python state-extractor and memory-interaction logic). A UCB multi-armed bandit rule selects the next configuration from the parent-plus-children pool, balancing exploitation of proven configurations against exploration of novel mutations while providing a safety net that falls back to the reliable parent if a child underperforms. The key insight is replacing gradient-based credit assignment over sparse scalar rewards with narrative-level semantic analysis of the full transcript, enabling targeted, structural edits to the entire agentic system in a single 20–30 second API call without any weight updates.

## Results

On the J-TTL benchmark (6 Jericho games, 50 episodes each), EvoTest achieves an average AUC of 0.47 (Gemini-2.5-Flash) and 0.50 (Claude-4-Sonnet), outperforming the strongest prompt-evolution baseline EvoPrompt (0.34/0.36) by 38% and the online RL baseline GRPO (0.30) by 57%. EvoTest is the only method to win two games (Detective: 0.94/0.95; Library: 0.77/0.80), while all baselines fail to win any game. The learning curves show a steeper and more stable improvement trajectory compared to all baselines, with the update step requiring only a single LLM API call (20–30 seconds) versus 5–10 minutes on 4×H100 GPUs for online fine-tuning.

## Baselines & Comparisons

EvoTest outperforms all five baseline categories on every game and both backbone LLMs. Against the strongest prompt-evolution baseline EvoPrompt (0.34/0.36 avg AUC), EvoTest achieves a 38% relative improvement (0.47/0.50), with the gap most pronounced on Detective (0.94 vs. 0.65) and Library (0.77 vs. 0.48). Against Reflexion (0.32/0.34), the improvement is 47–48%, and against TextGrad (0.31/0.33) it is 52–52%. Against the gradient-based RL baseline GRPO (online, 0.30 avg), EvoTest achieves a 57% improvement, while also being orders of magnitude faster per update (20–30 s via one API call vs. 5–10 min on 4×H100 GPUs). Notably, EvoTest is the only method to reach a winning score on Detective and Library, whereas all baselines—including GRPO—fail to win any game, suggesting that whole-system evolution (prompt + memory + hyperparameters + tool-use) captures strategic knowledge that single-channel prompt editing or scalar-reward RL cannot.

## Relation to Prior Work

EvoTest generalizes the evolutionary prompt optimization paradigm (EvoPrompt, Promptbreeder) from evolving a single prompt string to evolving an entire agentic configuration—prompt, structured memory, hyperparameters, and tool-use routines—using a single LLM call per episode. For configuration selection between episodes, it borrows the UCB multi-armed bandit strategy to balance exploration of new mutations against exploitation of proven configurations, adding a stability mechanism absent from prior prompt-evolution methods. The paper positions itself against the broader test-time adaptation literature (Reflexion, MemGPT, TextGrad) by arguing that single-channel adaptation (prompt-only, memory-only) is insufficient, and against online fine-tuning (SFT, GRPO) by showing that narrative transcript analysis provides a more data-efficient credit-assignment signal than scalar rewards in the extreme low-data regime of a single episode.

## Why It Matters / Open Questions

The J-TTL benchmark provides a concrete, reproducible protocol for measuring whether agents can actually improve across repeated attempts at the same task—a capability the paper argues is essential for practical autonomy but has lacked a standardized testbed. The finding that a single 20–30 second LLM API call (narrative credit assignment) outperforms 5–10 minutes of GPU fine-tuning in this data-scarce setting challenges the assumption that weight updates are necessary for meaningful test-time adaptation. Key limitations include the method's dependence on a powerful Evolver LLM, its task-specific overfitting (learned strategies are brittle to environment variations), and the fact that gains on harder games (Zork1, Zork3) remain modest. Open questions include whether evolved symbolic strategies can be abstracted into generalizable skill libraries, and whether hybrid approaches combining fast evolutionary adaptation with slow background fine-tuning can overcome the ceiling imposed by the frozen backbone.
