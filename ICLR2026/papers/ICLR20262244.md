## Problem

LLMs frequently produce incoherent or invalid plans under complex, multifaceted constraints in real-world tasks like travel planning. Existing approaches either assume all necessary information is provided upfront or that all constraints are known in advance, leaving the realistic scenario—where an agent must simultaneously search for context information and discover both explicit and implicit constraints—largely unsolved.
![Teaser figure](../imgs/ICLR20262244/cropped_page1_idx0.webp)

## Input / Output

The system takes a natural language travel query and, in multi-turn settings, iterative user feedback as input. It formulates the problem as a Constraint Satisfaction Problem where domains are dynamically populated from live tool-call observations (flights, hotels, restaurants, attractions) rather than given a priori. The output is a complete day-by-day itinerary (a total assignment over all plan variables) verified to satisfy every explicit and implicit constraint, along with a structured constraint set and per-constraint validity verdicts. In multi-turn mode, domains from the previous turn are cached and reused, triggering new search only when the cached information proves insufficient.

## Method

ATLAS is a multi-agent framework with five typed agents—Search Agent, Constraint Manager, Planner, Checker, and Search Advisor—organized around three mechanisms that address three fundamental challenges. First, the Constraint Manager extracts the full constraint set (explicit constraints from the query and search results, plus implicit commonsense rules) using the LLM's world knowledge. Second, a Planner-Checker iterative loop (up to K steps) generates candidate plans and rigorously verifies them against all constraints, with targeted feedback guiding revisions. Third, when the Checker returns an 'unsat' verdict, the Search Advisor diagnoses the specific information gap and produces a targeted search directive, triggering an interleaved search loop (up to L steps) that adaptively augments the domain. The multi-turn extension reuses cached domains from the prior turn, entering the Planner-Checker loop first and only escalating to full interleaved search if the existing knowledge is insufficient. The entire system is formalized as a Dynamic CSP (a sequence of static CSPs evolving with user feedback) and requires no training, using off-the-shelf LLMs as the reasoning substrate for each agent.

## Results

On the TravelPlanner benchmark (validation, 180 queries), ATLAS with Gemini-2.5-Pro achieves a 44.44% final pass rate, nearly doubling the best baseline PMC (23.33%) and outperforming ReAct (20.56%) by over 23 percentage points. On the larger test set (1,000 queries), ATLAS maintains its lead at 35.00% final pass rate versus 22.70% for ReAct+Reflexion. In the live multi-turn setting with real web search, ATLAS reaches an 84% final pass rate after two feedback turns, compared to 59% for ReAct and 27% for a monolithic agent, while also achieving a 92% no-hallucination rate.

## Baselines & Comparisons

ATLAS outperforms all four baselines across every metric on both validation and test sets. Against ReAct (the standard tool-use baseline), ATLAS improves final pass rate from 20.56% to 44.44% on validation (+23.9 pp) and from 19.50% to 35.00% on test (+15.5 pp). Against the multi-agent baseline PMC, ATLAS gains +21.1 pp on validation and +13.9 pp on test, attributed to its explicit constraint management and interleaved search rather than relying on emergent LLM decomposition. Notably, augmenting ReAct with Reflexion or EvoAgent yields no benefit and can even degrade performance (ReAct+EvoAgent drops to 12.22% vs. ReAct's 20.56% on validation), demonstrating that complex planning over poor, non-adaptive search results is counterproductive. In the multi-turn Flex-TravelPlanner setting, ATLAS roughly doubles ReAct's final pass rate in 3-turn scenarios (33.60% vs. 15.34% for local-then-global constraints), with the gap widening as constraint complexity increases.

## Relation to Prior Work

ATLAS composes two well-established LLM-agent mechanisms—ReAct-style tool calling for information retrieval and the CRITIC-style generate-verify-revise loop for plan validation—into a unified multi-agent pipeline that explicitly separates constraint discovery, constraint-aware planning, and adaptive search. It departs from prior constraint-aware planning work (e.g., PMC, PlanGEN, LLM-modulo frameworks) that assumes all necessary information and constraints are available a priori, by treating constraint construction and information acquisition as first-class, iterative challenges. The paper also positions itself against the classical CSP and automated-planning literature, mapping its three agents to constraint acquisition, plan validation, and sensing-in-partially-observable-environments, respectively.

## Why It Matters / Open Questions

The paper provides the first quantitative evaluation of constraint-aware planning in a live web-search, multi-turn feedback setting, a practically important gap that prior sandbox-only benchmarks (TravelPlanner, Flex-TravelPlanner) leave unaddressed. The 84% final pass rate with live search versus 59% (ReAct) and 27% (monolithic) demonstrates that multi-agent decomposition with iterative constraint management is essential for real-world reliability, not just a sandbox artifact. Open questions include whether integrating a formal CSP solver into the Checker would close the remaining gap, whether the framework generalizes beyond travel to other constrained domains (privacy compliance, personalized recommendations), and how to reduce the Planner's dominant runtime cost via parallel test-time scaling.
