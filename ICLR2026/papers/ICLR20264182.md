## Problem

Existing text-to-SQL benchmarks evaluate isolated, single-turn question-to-SQL translation, failing to capture two core challenges of real-world clinical data access: query ambiguity (users pose vague questions that don't fully specify their intent) and value mismatch (clinical terminology in user language differs from database entries, e.g., 'Lopressor' vs. 'metoprolol tartrate'). No prior benchmark evaluates the full end-to-end agentic workflow—clarifying user questions, invoking tools to resolve terminology gaps, and generating correct SQL—within the safety-critical EHR domain.

## Input / Output

The agent receives a vague, multi-turn natural language query from an LLM-based user simulator (Gemini-2.0-Flash, temperature 1.0) and must produce a correct SQL query executed against renamed EHR databases (MIMIC-IV* and eICU*, where all table/column names are altered to prevent schema memorization). The agent has access to six tools: table_search, column_search, value_substring_search, value_similarity_search (FAISS-based), web_search, and sql_execute. Evaluation is rule-based against deterministic ground-truth SQL outputs and answers, with each task run over 5 i.i.d. trials to compute SR-5, Pass@5, Pass^5, and Gap-5. Conversations are capped at 30 agent actions, and a simulation validator (LLM-as-a-judge) filters out traces where the user simulator deviates from its instructions.

## Method

EHR-ChatQA formulates the task as a POMDP with a dual interaction loop (user dialogue + tool invocation) and introduces two interaction flows: IncreQA (286 tasks) where users linearly add constraints to a query, and AdaptQA (80 tasks) where users conditionally adjust search goals mid-conversation based on intermediate results (e.g., pivoting from brand to generic drug names, switching drug classes, or falling back to alternative lab tests). The benchmark contains 366 task instances grounded in real clinical QA scenarios from a collaborating medical center and the EHRSQL dataset, annotated with GT SQL using CTEs and verified by a physician. A key design choice is renaming all schema elements (e.g., 'patients'→'demographics', 'admissions'→'hospitaladmissions') to force genuine schema exploration rather than reliance on memorized database structures. The simulated user employs a nested verification-reflection mechanism (turn-level verifier at temperature 0.0 plus chained reflection) to improve instruction-following reliability, and a post-hoc simulation validator re-runs traces where the user violates its behavioral rules. The paper evaluates seven SOTA LLMs (o4-mini, Gemini-2.5-Flash, GPT-4o, GPT-4o-mini, Gemini-2.0-Flash, Llama 3.3-70B, Qwen3-32B) and finds a critical robustness gap: Pass@5 exceeds 90% on IncreQA for top models, but Pass^5 drops by up to ~60%, with error analysis attributing consistent failures to value-linking errors (51.9%) and SQL generation errors (25.9%), and inconsistent failures to context-tracking breakdowns under linguistic variation (75.0%).

## Results

On EHR-ChatQA, o4-mini achieves the highest SR-5 of 81.3% on IncreQA and 35.8% on AdaptQA, followed by Gemini-2.5-Flash (73.3% and 30.0%). The most striking finding is the robustness gap: o4-mini's Pass@5 reaches 96.5% on IncreQA but Pass^5 drops to 57.7% (Gap-5 = 38.8%), and on AdaptQA the gap widens to 58.7% (Pass@5 = 66.2% vs. Pass^5 = 7.5%). Open-source models (Llama 3.3-70B, Qwen3-32B) lag substantially, with SR-5 below 22% on AdaptQA and Gap-5 values of 40–62%, indicating even greater inconsistency.

## Baselines & Comparisons

As a benchmark paper, EHR-ChatQA evaluates seven LLM agents (five closed-source, two open-source) rather than proposing a new method. Among closed-source models, o4-mini leads on both flows (SR-5: 81.3% IncreQA, 35.8% AdaptQA), outperforming Gemini-2.5-Flash by ~8 points on IncreQA and ~6 points on AdaptQA. GPT-4o trails o4-mini by 17 points on IncreQA SR-5 and 7 points on AdaptQA. Open-source models are clearly weaker: Qwen3-32B reaches 58.7% SR-5 on IncreQA (vs. o4-mini's 81.3%) and only 21.2% on AdaptQA, while Llama 3.3-70B drops to 40.5% and 14.2% respectively. A critical cross-model observation is that no agent achieves Pass^5 above 58% on IncreQA or 12% on AdaptQA, and the Gap-5 (Pass@5 − Pass^5) ranges from 36 to 62 points across all models, revealing that even the strongest agents are far from reliable for safety-critical EHR deployment.

## Relation to Prior Work

This paper carves new ground by synthesizing three previously separate research threads—conversational text-to-SQL (SParC, CoSQL), tool-augmented agent evaluation (Tau-Bench, ToolDial), and EHR-specific querying (EHRSQL, EHR-SeqSQL)—into a single interactive benchmark. Unlike prior conversational text-to-SQL benchmarks that use scripted or predefined interaction patterns, EHR-ChatQA employs a stochastic LLM-based user simulator and a POMDP formulation to capture open-ended, exploratory dialogue. The schema-renaming strategy (MIMIC-IV★, eICU★) departs from prior EHR benchmarks by preventing LLMs from relying on memorized schemas, forcing genuine tool-based exploration. The value-mismatch resolution requirement (e.g., 'Lopressor' → 'metoprolol tartrate') is a uniquely EHR challenge absent from general-purpose text-to-SQL or agent benchmarks.

## Why It Matters / Open Questions

The benchmark exposes a critical robustness gap (up to ~60% between Pass@5 and Pass^5) that has direct safety implications for deploying LLM agents in clinical settings, where inconsistent behavior across conversation paths is unacceptable. The error analysis identifies context management across turns as the primary driver of inconsistent failures, pointing toward concrete research directions (explicit query-state representation, context-dependent fine-tuning). A key limitation is the reliance on LLM-based user simulation, which introduces its own stochasticity and instruction-following failures (Section 6), potentially confounding agent evaluation. Open questions include whether the robustness gap narrows with stronger models, whether the findings generalize beyond the two demo databases, and how to reduce simulation overhead while maintaining evaluation fidelity.
