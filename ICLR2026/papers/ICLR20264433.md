## Problem

As LLM agents increasingly operate through the Model Context Protocol (MCP) to invoke heterogeneous tools across multiple servers, new safety risks emerge from tool poisoning, context manipulation, and cross-server propagation. Existing MCP safety benchmarks either focus narrowly on specific attack types, lack integration with real-world MCP servers, or fail to capture the multi-turn, multi-server reasoning workflows that characterize practical deployments, leaving a critical gap in systematic safety evaluation.
![Teaser figure](../imgs/ICLR20264433/cropped_page1_idx1.webp)

## Input / Output

Each benchmark task is a formalized tuple (G, C, T_available, A) where a user query is paired with a specific attack modification injected at the server, host, or user level, and the agent executes under a standardized ReAct pipeline (temperature 1.0, max 2048 tokens, 20 iterations, 3 repetitions). The evaluation produces a dual-label outcome per execution trace: a task evaluator (inherited from MCP-Universe with format, static, and dynamic checks) determines whether the user goal was achieved, while a dedicated attack evaluator (e.g., check_parameter_modification_attack, check_replay_injection_attack) determines whether the attacker's objective was realized, yielding aggregate TSR and ASR metrics.

## Method

MCP-SafetyBench is constructed through a three-stage pipeline: (1) selecting and adapting tasks from MCP-Universe across five real-world domains (browser automation, financial analysis, location navigation, repository management, web search) to form clean baselines with machine-checkable output schemas; (2) instantiating one attack from a unified taxonomy of 20 types spanning server-side (tool poisoning variants, function overlapping, preference manipulation, tool shadowing, function return injection, rug pull), host-side (intent injection, data tampering, identity spoofing, replay injection), and user-side (malicious code execution, credential theft, remote access control, RADE, excessive privileges misuse) attacks via a generate-and-verify process; (3) packaging each task with category (disruption/stealth), attack metadata, and associated evaluators. The benchmark contains 245 test cases with a near-even split between disruption (46.53%) and stealth (53.47%) attacks, and a server-side-heavy distribution (74.69%). Evaluation is fully automated and execution-based, running a ReAct-style agent against real MCP servers with the attack injected, then applying both evaluators to the logged trace to compute TSR and ASR.

## Results

Across 13 LLMs evaluated on MCP-SafetyBench (245 tasks, 5 domains, 20 attack types), no model is immune to MCP attacks: overall Attack Success Rate (ASR) ranges from 29.80% (Qwen3-235B) to 48.16% (o4-mini), while Task Success Rate (TSR) under attack is low across the board (10.20%–21.22%). A significant safety-utility trade-off is confirmed (Pearson r = −0.572, p = 0.041): models with higher TSR tend to be less resistant to attacks. Host-side attacks are the most effective (81.94% mean ASR), with Identity Injection achieving 100% success across all 13 models, while Financial Analysis is the most vulnerable domain (46.59% mean ASR) and Web Search the least (30.33%).

## Baselines & Comparisons

MCP-SafetyBench is positioned against five prior MCP safety benchmarks (SafeMCP, MCPTox, MCIP-bench, MCP-AttackBench, MCPSecBench). It is the only benchmark that simultaneously provides real-world MCP server integration, multi-step tasks, and coverage of all three attack sides (server, host, user), with 20 attack types versus 2–17 in prior work. In the model evaluation, no single model dominates: Qwen3-235B achieves the lowest ASR (29.80%) but also a low TSR (10.20%), while o4-mini achieves the highest TSR (21.22%) but the highest ASR (48.16%), confirming the safety-utility trade-off. Statistical tests show no significant difference between reasoning and non-reasoning models (p = 0.7778) or between open-source and proprietary models (p = 0.4008) in overall ASR, indicating that neither architectural choice nor licensing model systematically determines MCP safety. A safety-prompt mitigation reduces weighted ASR by only 1.22% (not significant, p = 0.2908) and is even counterproductive for semantic-misalignment attacks like Function Overlapping (+9.36%) and Preference Manipulation (+7.34%), underscoring that prompt-level defenses are insufficient for the diverse MCP threat landscape.

## Relation to Prior Work

This paper builds directly on the MCP-Universe benchmark (Luo et al., 2025) for realistic task construction and extends the line of MCP safety benchmarks (SafeMCP, MCPTox, MCIP-bench, MCP-AttackBench, MCPSecBench) by integrating real-world MCP servers, multi-step ReAct-style workflows, and a unified taxonomy of 20 attack types across server, host, and user sides. Prior benchmarks either focus narrowly on specific attack categories (e.g., MCPTox on tool poisoning, MCIP-bench on function-calling corpora) or rely on simulated environments without real server integration. The key conceptual departure is treating MCP safety as a multi-turn, cross-server problem where attacks can emerge at any step of a long-horizon interaction, rather than as a one-shot tool-call vulnerability.

## Why It Matters / Open Questions

With MCP adoption accelerating across industry (OpenAI, Cursor, Cline, Google), this benchmark provides the first comprehensive, execution-based safety evaluation that mirrors real deployment conditions. The finding that all 13 state-of-the-art models remain substantially vulnerable (ASR 29.8%–48.2%), that host-side attacks achieve 81.94% success, and that Identity Injection succeeds against every model tested, underscores that current safety alignment is insufficient for agentic tool-use. The statistically significant safety-utility trade-off (r = −0.572) and the ineffectiveness of safety prompts (−1.22%, p = 0.29) point to an open problem: multi-layered defenses beyond prompt-level safeguards are needed, and the field lacks principled mechanisms for contextual least-privilege in MCP deployments.
