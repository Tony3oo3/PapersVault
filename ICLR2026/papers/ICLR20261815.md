## Problem

Existing low-precision model compression relies on lossy integer quantization that degrades quality and incurs dequantization overhead in large-batch inference. While DFloat11 demonstrated that BF16 exponents have exploitable low entropy, no fundamental principle explained why exponents concentrate, no theoretical compression limit was established, and the idea had not been extended to the emerging native FP8 format or translated into end-to-end inference acceleration.

## Input / Output

The method consumes pre-trained FP8 model weights (1 sign bit, 4 exponent bits, 3 mantissa bits per element) and produces a compressed ECF8 representation consisting of a Huffman-coded exponent bitstream, packed sign/mantissa nibbles, and synchronization metadata (gap values and block output positions). Encoding is a one-time offline step at ~3.2 MB/s, while decoding is performed on-the-fly per transformer layer via a CUDA kernel during inference, reconstructing bit-exact FP8 tensors in a single pre-allocated GPU buffer. The compressed format is plug-and-play: once decompressed, weights are indistinguishable from natively loaded FP8 tensors, requiring no changes to downstream GEMM kernels or inference frameworks.

## Method

The paper's theoretical core proves that stochastic gradient descent induces α-stable distributions on trained weights, whose floating-point exponents follow a two-sided geometric distribution with parameter q = 2^{-α}, yielding finite entropy bounded by α/(1+2^{-α}) ≤ H(E) ≤ α/(1-2^{-α}) and establishing a fundamental compression limit near FP4.67. Building on this, ECF8 applies Huffman coding to the 4-bit exponents (which empirically carry only 2–3 bits of entropy), constructs hierarchical 8-bit lookup tables for O(⌈ℓ_max/8⌉) variable-length code resolution, and implements a five-phase CUDA decoding kernel (memory initialization, data loading, parallel symbol counting with prefix-sum reduction, coordinated decoding into shared memory, and coalesced global write-back) that achieves 201–235 GB/s decompression throughput on H100. A PyTorch forward-hook-based tensor management system performs just-in-time per-layer decompression into a single pre-allocated buffer, enabling constant GPU memory overhead regardless of model depth and allowing larger batch sizes under fixed memory budgets.

## Results

ECF8 achieves lossless memory reductions of 9.8%–26.9% across nine GenAI models (8B–671B parameters), with LLMs showing 9.8%–14.8% savings and diffusion transformers reaching up to 26.9% (Wan2.2-T2V-A14B). Under fixed memory budgets, ECF8 delivers throughput improvements of 11.3%–177.1%, with the most dramatic gain on FLUX.1-dev (177.1%) and DeepSeek-R1-0528 (150.3%, enabling 8× larger batch sizes). All results are bit-exact: ECF8-compressed models produce outputs with zero numerical deviation from the original FP8 models, verified via pixel-identical image generation and identical benchmark scores on GSM8K, BoolQ, PIQA, and Winogrande.

## Baselines & Comparisons

The sole baseline is native FP8 (Micikevicius et al., 2022), the standard 8-bit floating-point format used for GenAI model deployment. ECF8 wins on every metric across all nine evaluated models: it reduces memory by 9.8%–26.9% while producing bit-identical outputs, and under fixed memory budgets it increases throughput by 11.3%–177.1% by enabling larger batch sizes. The largest throughput gain (177.1%) occurs on FLUX.1-dev, where VRAM management offloading is the dominant bottleneck and ECF8's smaller weight footprint dramatically reduces reload overhead. For LLMs, DeepSeek-R1-0528 shows the most impactful result: ECF8's 14.8% memory reduction (623→530 GB) allows deployment on 8×H100 instead of 8×H200, while simultaneously increasing batch size from 2 to 16 and cutting per-request latency by 60.1%. The paper also notes that at the same batch size, ECF8 incurs a modest ~20% throughput penalty from on-the-fly decompression, but this is more than offset by the ability to run nearly 2× the batch size under the same memory constraint.

## Relation to Prior Work

This paper extends DFloat11's discovery of low-entropy exponents in BF16 weights to the emerging FP8 standard, while supplying the theoretical explanation DFloat11 lacked: a proof that SGD's heavy-tailed dynamics induce α-stable weight distributions, which in turn guarantee bounded exponent entropy. It also departs from the dominant integer-quantization paradigm (GPTQ, AWQ, SmoothQuant) by arguing that lossless floating-point entropy coding avoids both accuracy degradation and dequantization overhead. The GPU-optimized Huffman decoding pipeline and tensor management system represent a systems contribution that prior lossless-compression work (DFloat11, Heilper & Singer) did not fully deliver, transforming memory savings into measurable throughput gains.

## Why It Matters / Open Questions

As FP8 becomes the native precision for frontier GenAI models, a lossless compression method that simultaneously reduces memory and accelerates inference addresses a critical deployment bottleneck without any quality trade-off. The theoretical compression limit near FP4.67 provides a principled target for future format design, while the empirical gap (ECF8 achieves ~2.5–2.7 bits for exponents vs. 4 allocated) suggests further gains are possible with more aggressive coding. Open questions include whether exponent concentration extends to activations and KV caches, whether sub-byte hardware formats could approach the theoretical floor, and whether the α-stable model holds for future training regimes (e.g., RLHF, mixture-of-experts routing).
