## Problem

Existing parametric RAG (PRAG) methods translate retrieved passages into LoRA-style parameter updates via a hypernetwork, but they are restricted to single-pass retrieval. Multi-hop RAG requires iterative retrieval and reasoning across multiple sub-questions, and no prior PRAG framework can sequentially accumulate passage knowledge into model parameters across hops without retraining or redesigning the hypernetwork for each new hop count.
![Teaser figure](../imgs/ICLR20265177/cropped_page2_idx0.webp)

## Input / Output

The method takes a complex multi-hop question and, at each hop, a set of top-k retrieved passages (k=1–12, via E5 or BM25). Each passage is compressed by a lightweight 2-layer Transformer encoder + MLP hypernetwork into k key-value memory vectors of dimension d_model (4096 for LLaMA3.1-8B, 3584 for Qwen2.5-7B), which are injected at a single critical layer rather than appended to the prompt. The system outputs sub-answers per hop and a final answer, with the merged key-value experts persisting across hops so that later sub-answers benefit from all previously retrieved knowledge without re-reading it in context.

## Method

MergePRAG introduces a continual merging mechanism that reuses a single passage-level hypernetwork across all hops. At each hop, the hypernetwork maps each retrieved passage to key-value matrices (K_p, V_p) via attentive pooling → two-layer MLP → linear projections; these are injected into the FFN at one critical layer l* (selected by layer-wise perplexity scanning) through a memory attention mechanism where the base FFN output serves as the query. The key technical contribution is orthogonal continual merging: when a new passage expert arrives, a Gram-Schmidt projection onto the subspace spanned by all previously merged experts is computed, and only the orthogonal residual is added (W_F^t = W_F^{t-1} + (I − P^{t-1}) W_t), preventing new knowledge from overwriting earlier hops. The hypernetwork is trained with cross-entropy loss on (sub-question, gold passage, answer) triples while the base LLM stays frozen, and a separate smaller sub-question generator is fine-tuned via GPT-4.1-generated decomposition chains to iteratively produce sub-questions until an EOS token is emitted.

## Results

On multi-hop QA, MergePRAG+ with |SP|=4 and BM25 achieves 52.40 EM / 60.58 F1 on HotpotQA, 70.20 EM / 76.65 F1 on 2WikiMhQA, and 20.30 EM / 31.20 F1 on MuSiQue using LLaMA3.1-8B. With Qwen2.5-7B and E5, it reaches 50.80 EM / 58.37 F1 (HotpotQA) and 77.40 EM / 81.49 F1 (2WikiMhQA). On the multi-hop editing task (MQuAKE-T), MergePRAG+ achieves 96.10 EM / 96.10 F1, substantially outperforming MeLLo (85.40 EM). The method also demonstrates efficiency: passage memory generation takes only 0.001s per hop, and total inference (2.517s) is faster than RAG-CoT (6.389s) while achieving higher accuracy.

## Baselines & Comparisons

MergePRAG+ outperforms all standard RAG baselines by large margins: over RAG-CoT (43.70→52.40 EM on HotpotQA, 36.20→70.20 EM on 2WikiMhQA with LLaMA3.1-8B/BM25) and over IRCoT (39.30→52.40 EM on HotpotQA). Against the strongest reasoning-enhanced baseline R3-RAG, MergePRAG+ wins on HotpotQA (52.40 vs 44.40 EM) and 2WikiMhQA (70.20 vs 50.60 EM) with LLaMA3.1-8B/BM25, but R3-RAG retains an edge on MuSiQue with Qwen2.5-7B/E5 (21.40 vs 12.30 EM). MergePRAG+ also surpasses DeepRAG (40.70→52.40 EM on HotpotQA), Auto-RAG (25.80→52.40 EM), and Search-o1 (14.80→52.40 EM) by substantial margins. Among parametric RAG methods, MergePRAG+ improves over PRAG (44.84→60.58 F1 on HotpotQA) and DyPRAG (50.24→76.65 F1 on 2WikiMhQA), confirming that orthogonal continual merging is critical for multi-hop accumulation. On the MQuAKE-T editing task, MergePRAG+ (96.10 EM) beats MeLLo (85.40 EM) by over 10 points, and on MQuAKE-CF it achieves 50.30 EM versus MeLLo's 32.90 EM.

## Relation to Prior Work

This paper extends the PRAG/DyPRAG line of work, which translates retrieved passages into LoRA-style parameter updates via a hypernetwork, from the single-hop setting to multi-hop RAG where passages arrive sequentially across iterative retrieval steps. The key methodological departure is a continual merging mechanism that reuses a single passage-level hypernetwork across hops, combining orthogonal (Gram-Schmidt) merging—borrowed from recent knowledge-editing work (Xu et al., 2025)—with critical-layer parameterization inspired by locate-and-edit methods (ROME, MEMIT). The sub-question generator training procedure is adopted from R3-RAG (Li et al., 2025b), and the overall framework is positioned as a bridge toward reasoning-enhanced RAG systems such as IRCoT, Self-RAG, and DeepRAG.

## Why It Matters / Open Questions

MergePRAG provides the first general-purpose mechanism for accumulating passage knowledge into model parameters across multiple retrieval hops without retraining, which is a prerequisite for scaling parametric RAG to the iterative, reasoning-driven retrieval settings that dominate current RAG research. A notable limitation is error propagation: an incorrect sub-answer at one hop cascades into subsequent steps, a challenge shared by all decomposition-based multi-hop approaches. Open questions include whether the hypernetwork can be pretrained for domain-agnostic transfer, whether orthogonal merging remains advantageous under severe knowledge conflict, and whether the framework extends naturally to full reasoning-enhanced RAG with adaptive retrieval policies.
