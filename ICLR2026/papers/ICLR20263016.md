## Problem

Existing design-to-code approaches rely solely on design images, forcing models to infer complex UI details (icons, hierarchy, styles, layout) from pixels alone, which leads to degraded and incomplete results. In real-world development workflows, design mockups are delivered as Figma files containing rich multimodal information—structured metadata (hierarchy, geometry, styles) and assets (icons, background images)—that are essential for high-quality UI code generation but remain unexplored in prior benchmarks.
![Teaser figure](../imgs/ICLR20263016/cropped_page1_idx0.webp)

## Input / Output

The task takes as input a rendered Figma design screenshot, a preprocessed JSON metadata file (with structure pruning, coordinate standardization to three decimal places, and asset path resolution to local relative paths), and a set of localized design assets (SVG icons exported from merged vector nodes, PNG bitmaps). The output is a self-contained HTML file using Tailwind CSS utility classes, where the JSON metadata is designated as the authoritative source of truth for layout and styling while the screenshot serves only as an auxiliary visual reference. Evaluation is entirely reference-free, using the original design image as ground truth for visual fidelity (DINOv2 embedding similarity and normalized pixel-level MAE) alongside code-level metrics for responsiveness and maintainability.

## Method

The paper's core contribution is a dataset construction pipeline that crawls ~2,100 Figma community files across seven categories, decomposes them into ~30,000 pages, and applies multi-stage filtering (heuristic structural rules, CLIP-based visual deduplication at cosine similarity >0.95, and expert manual review) to yield 3,055 annotated samples, from which 213 high-quality benchmark cases are selected via stratified sampling over platform, complexity, quality, and content dimensions. For generation, the paper benchmarks ten state-of-the-art MLLMs under three input modalities (image-only, metadata-only, multimodal) and introduces F2CAGENT, a ReAct-style agentic workflow that converts Figma JSON into a streamlined Intermediate Representation, generates initial code via a deterministic rule-based template engine, and iteratively refines it through a critic-refiner loop. The evaluation framework introduces reference-free metrics spanning visual fidelity (VES via DINOv2, MAE), layout responsiveness (RUR, APR, FU, BC), and code maintainability (STR, AVU, ISR, CCR). Key findings show that while Figma metadata substantially improves visual fidelity (e.g., VES rising from 0.5653 to 0.7990), it introduces rigidity—models tend to directly map absolute coordinates and primitive visual attributes from the metadata, producing code with high absolute positioning ratios and arbitrary style tokens that undermine responsiveness and maintainability.

## Results

On the FIGMA2CODE benchmark, GPT-5 achieves the highest visual fidelity with a VES of 0.8405 and MAE of 0.1874, followed by Gemini 2.5 Pro (VES 0.8110, MAE 0.1936) and Grok4 (MAE 0.1822). However, no model excels across all dimensions: Llama 4 Scout produces the most responsive and maintainable code (APR 1.42%, STR 35.76%, AVU 0.87%), while Grok4, despite its strong pixel-level fidelity, suffers from extreme rigidity (APR 31.09%) and non-standard styling (AVU 49.97%). Even the top visual-fidelity model, GPT-5, shows a high AVU of 37.72%, indicating a persistent trade-off between faithful reproduction and production-ready code quality.

## Baselines & Comparisons

The paper benchmarks ten MLLMs (five proprietary: GPT-5, GPT-4o, Gemini 2.5 Pro, Claude Opus 4.1, Grok4; five open-source: Llama 4 Maverick, Llama 4 Scout, Qwen2.5-VL, ERNIE 4.5 424B VL, Nova Pro v1) under a unified protocol. Proprietary models clearly dominate visual fidelity: GPT-5 (VES 0.8405) and Gemini 2.5 Pro (VES 0.8110) outperform the best open-source model, ERNIE 4.5 424B VL (VES 0.6983), by 14–20 percentage points. The pattern reverses for code quality: Llama 4 Scout achieves the best responsiveness (APR 1.42%) and maintainability (STR 35.76%, AVU 0.87%), while proprietary models like Grok4 (APR 31.09%, AVU 49.97%) and GPT-5 (APR 14.35%, AVU 37.72%) produce rigid, non-standard code. GPT-4o is a notable exception among proprietary models, combining competitive visual fidelity (VES 0.7405) with relatively clean code (APR 2.94%, AVU 2.46%), though it still trails Llama 4 Scout on maintainability. No single model achieves a Pareto-optimal balance, confirming the paper's central finding that current MLLMs cannot simultaneously maximize visual fidelity and engineering quality in the FIGMA2CODE task.

## Relation to Prior Work

This paper extends the design-to-code task from the image-only setting established by Design2Code (Si et al., 2024) and Web2Code (Yun et al., 2024) into a multimodal setting grounded in real-world Figma files, which provide structured JSON metadata, design assets, and rendered screenshots simultaneously. Methodologically, F2CAGENT builds on the ReAct (Yao et al., 2022) paradigm for iterative self-correction and adapts the FigmaToCode (Ferrari, 2025) pipeline for IR-based template conversion, but departs from both by introducing a critic-refiner loop that operates over rendered output rather than raw JSON. The key conceptual departure from prior work is the argument that production design-to-code cannot be reduced to screenshot-to-code: the absence of metadata forces models to hallucinate hierarchy, styles, and asset bindings, a limitation the paper formalizes as a new task (FIGMA2CODE) with its own evaluation criteria.

## Why It Matters / Open Questions

The central finding—that Figma metadata substantially improves visual fidelity (VES up to 0.80) while simultaneously degrading layout responsiveness (APR up to 58% for Template Conversion) and code maintainability (AVU up to 50% for Grok4)—reveals a fundamental tension that prior image-only benchmarks could not expose. This matters because it shows that simply feeding models more structured information does not yield production-ready code; models tend to directly map absolute coordinates and primitive attributes rather than inferring responsive layout patterns. Open questions include whether reinforcement learning or more sophisticated agentic workflows can reconcile fidelity with engineering quality, whether the findings generalize beyond Tailwind CSS, and how to design training signals that penalize rigid, non-semantic code without sacrificing pixel-level accuracy.
