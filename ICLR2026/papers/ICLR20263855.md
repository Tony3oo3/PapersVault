## Problem

Existing automatic multi-agent systems (MAS) follow a rigid 'generate-once-and-deploy' paradigm: a system is instantiated once per task and executed unchanged, making it brittle to real-world disruptions such as tool crashes, API failures, or insufficient search budgets. No prior framework enables a MAS to recursively generate, configure, and dynamically rectify another MAS in response to real-time execution feedback, leaving a gap between static generation and the dynamism of actual task environments.

## Input / Output

At inference, MAS² takes a natural-language task query and a candidate LLM pool (e.g., GPT-4o, GPT-4o-mini, Qwen2.5-72B, QwQ-32B) as input. The generator produces a model-agnostic workflow template expressed as Python code using a fixed set of predefined operators (Custom, Search, Programmer, ScEnsemble, etc.), where each LLM slot is a placeholder string. The implementor then replaces each placeholder with a concrete backbone from the pool, yielding a fully executable multi-agent system. At runtime, the rectifier can rewrite the workflow code in-place (e.g., upgrading a backbone, bypassing a faulty operator, extending iteration limits), so the output is not a static artifact but a self-modifying system that ultimately returns a task answer.

## Method

MAS² instantiates a tri-agent meta-architecture: a Generator that architects a high-level workflow template, an Implementor that assigns LLM backbones to each agent role, and a Rectifier that monitors execution state and intervenes on failure or budget exhaustion. All three meta-agents are trained via Collaborative Tree Optimization (CTO), which builds a decision tree per query (K generator branches × N implementor instantiations, with optional rectifier branches), assigns a cost-sensitive terminal reward (success indicator × inverse normalized API cost), and propagates credit backward via Monte Carlo node-value estimation. Training uses a value-scaled DPO loss (Eq. 11) that weights each preference pair by the value margin ΔV between winning and losing successor nodes, so the model learns most from high-confidence decisions. This mechanism, applied independently to each meta-agent via LoRA fine-tuning of Qwen3-8B, yields specialized policies that collectively enable task-adaptive MAS construction and real-time self-correction without the rigidity of generate-once-and-deploy pipelines.

## Results

MAS² achieves state-of-the-art performance across all seven benchmarks, scoring 89.3% on HotpotQA, 67.2% on Bamboogle, 79.1% on NQ, 19.7% on BrowseComp+, 97.0% on HumanEval, 85.1% on MBPP, and 71.3% on MATH. The largest gains over the strongest automated MAS baseline (ScoreFlow) appear on BrowseComp+ (+9.3 pp) and MATH (+6.9 pp), while on multi-hop search MAS² averages ~78.5%, surpassing ScoreFlow by 2.8 pp and MaAS by 4.7 pp. MAS² also establishes a new cost-performance Pareto frontier, e.g., on Bamboogle it achieves 12.8% higher pass rate than SC (GPT-4o) at over 25× lower cost.

## Baselines & Comparisons

MAS² outperforms all 13 baselines across all seven benchmarks. Against the strongest automated MAS baselines, MAS² leads ScoreFlow by 3.3 pp on HotpotQA (89.3 vs 86.0), 2.4 pp on Bamboogle (67.2 vs 64.8), 2.7 pp on NQ (79.1 vs 76.4), 9.3 pp on BrowseComp+ (19.7 vs 10.4), 1.1 pp on HumanEval (97.0 vs 95.9), 0.4 pp on MBPP (85.1 vs 84.7), and 6.9 pp on MATH (71.3 vs 64.4). Compared to MaAS, MAS² gains 5.7 pp on HotpotQA, 5.2 pp on Bamboogle, 3.1 pp on NQ, 5.7 pp on BrowseComp+, 4.2 pp on HumanEval, 2.9 pp on MBPP, and 1.2 pp on MATH. Against the best handcrafted MAS (DyLAN), MAS² improves by 8.5 pp on HotpotQA, 7.5 pp on Bamboogle, 7.0 pp on NQ, 3.9 pp on BrowseComp+, 6.6 pp on HumanEval, 7.8 pp on MBPP, and 5.6 pp on MATH. Notably, existing automated MAS baselines show inconsistent cross-domain performance (e.g., ADAS drops to 7.0% on BrowseComp+ and 51.7% on MATH), whereas MAS² maintains strong performance uniformly across all task types.

## Relation to Prior Work

This paper extends the automated MAS design lineage (ADAS, MaAS, AFlow, ScoreFlow, MAS-GPT) by introducing a recursive self-generation paradigm where a meta-MAS constructs and rectifies target MAS. Methodologically, it builds on relative reward-based preference optimization (REBEL, ScoreFlow) but adapts the DPO loss with a value-scaled ΔV weighting derived from Collaborative Tree Optimization's path credit propagation. The key conceptual departure from prior agent-based generators (FlowReasoner, MAS-GPT) is the addition of a runtime rectifier agent that enables online self-correction, moving beyond the 'generate-once-and-deploy' paradigm that characterizes all prior automated MAS approaches.

## Why It Matters / Open Questions

The self-rectifying capability addresses a genuine practical gap: real-world MAS deployments face tool crashes, API failures, and context overloads that static systems cannot handle. The cross-backbone generalization (leveraging unseen LLMs without retraining) and Pareto-optimal cost-performance make this practically deployable. However, open questions remain: the meta-agents are small (Qwen3-8B) and the operator set is fixed, limiting architectural creativity; the rectifier's effectiveness on truly novel failure modes (beyond the four demonstrated cases) is untested; and the training data curation via CTO may not scale to open-ended domains where success signals are ambiguous.
