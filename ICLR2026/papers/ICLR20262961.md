## Problem

Open pre-training corpora for code (The-Stack-v1/v2) and mathematics (Finemath-4+) retain noisy, redundant, and stylistically inconsistent data because they rely on rule-based extraction or exclusionary filtering that discards low-quality samples rather than fixing them. Meanwhile, leading open-weight frontier models do not release their pre-training data, creating a 'data quality gap' that limits the open community's ability to match state-of-the-art code and math performance.

## Input / Output

The pipeline consumes raw Python code snippets from the-stack-v2-train-smol-ids (Python-only, ~41M samples) and raw mathematical documents from Finemath-4+ (math snippets embedded in otherwise unrelated web passages), along with a base LLM checkpoint (Llama-3.1-8B). It produces SwallowCode (~16.1B tokens) as pure self-contained Python snippets in the same code-only format as the source (no instruction-tuning text-code pairs), and SwallowMath (~2.3B tokens) as cleaned, context-restored, step-by-step mathematical solutions. The rewriting LLM is Llama-3.3-70B-Instruct, and the final output is a continually pre-trained model checkpoint after ~50B tokens of mixed training (16% code, 84% multilingual text for code experiments; 4.79% math, 13% code, 82.2% multilingual text for math experiments).

## Method

The core contribution is a 'transform-and-retain' paradigm that rewrites low-quality pre-training data rather than filtering it out. For SwallowCode, a four-stage pipeline applies: (1) syntax validation via Python compile(), (2) pylint-based style filtering (score ≥ 7.0 with a comment-ratio penalty), (3) Style-Guided Code Rewriting (SGCR) enforcing ten criteria from the Google Python Style Guide (naming, type hints, docstrings, error handling, modularity), and (4) Self-Contained Optimization Rewriting (SCOR) that inlines external dependencies, replaces inefficient algorithms, and transforms trivial snippets into instructive examples. The two LLM rewriting stages are deliberately decoupled because combining all 19 directives into a single prompt causes instruction drift in Llama-3.3-70B-Instruct. For SwallowMath, an analogous LLM rewriting prompt removes web boilerplate, restores missing context, and reformats solutions into concise step-by-step explanations. Under a fixed 50B-token continual pre-training budget on Llama-3.1-8B, SwallowCode yields +17.0 pass@1 on HumanEval and +16.1 on HumanEval+ over Stack-Edu, while SwallowMath yields +12.4 on GSM8K and +7.6 on MATH over Finemath-4+.

## Results

Under a fixed 50B-token continual pre-training budget from Llama-3.1-8B, SwallowCode improves pass@1 by +17.0 on HumanEval and +16.1 on HumanEval+ over Stack-Edu, while SwallowMath improves accuracy by +12.4 on GSM8K and +7.6 on MATH over Finemath-4+. Generalizability is confirmed on Qwen2-7B (20B tokens), where SwallowCode yields +10.3 pass@1 on both HumanEval (49.6 vs 39.3) and HumanEval+ (44.6 vs 34.3) over Stack-Edu. Ablations show the two-stage LLM rewriting (SGCR + SCOR) contributes the largest gains (~14 points combined), far exceeding the ~1–2 points from syntax and linter filtering alone.

## Baselines & Comparisons

Against Stack-Edu (the strongest existing filtered code corpus, built via LLM-scored classifier filtering of StarCoder2Data), SwallowCode wins decisively: +17.0 pass@1 on HumanEval and +16.1 on HumanEval+ with Llama-3.1-8B, and +10.3 on both benchmarks with Qwen2-7B. Against The-Stack-v2-Smol and The-Stack-v1 (raw, unfiltered corpora), SwallowCode also achieves the highest pass@1 on both HumanEval and HumanEval+ in the 50B-token setting (Figure 1). Against CodeParrot-Clean (12.8B tokens), SwallowCode similarly outperforms on both code benchmarks. For mathematics, SwallowMath outperforms Finemath-4+ (the reported best open math corpus at the time) by +12.4 on GSM8K and +7.6 on MATH, confirming that the transform-and-retain rewriting paradigm generalizes beyond code. The paper also notes that LLM-based scoring (analogous to Stack-Edu's classifier approach) yields less than 1 point improvement over linter filtering, whereas the full SGCR+SCOR rewriting pipeline yields 14+ points, establishing rewriting as substantially more effective than exclusionary filtering.

## Relation to Prior Work

This paper extends the LLM-assisted code cleaning paradigm of Jain et al. (2023) from small-scale instruction-tuning exemplars to billion-token pre-training corpora, replacing their limited set of stylistic transformations (renaming, modularization, comments) with a two-stage pipeline (SGCR + SCOR) that also enforces self-containment and algorithmic optimization. It departs from the dominant exclusionary-filtering approach (Stack-Edu, FineWeb-Edu) by adopting a 'transform-and-retain' strategy that rewrites low-quality samples rather than discarding them, and distinguishes itself from web-data rephrasing work (Rephrasing the Web, Nemotron-CC, MegaMath) by preserving pure code/math snippets without introducing instruction-response formats. The math pipeline (SwallowMath) applies the same rewriting philosophy to Finemath-4+, paralleling the code pipeline's structure.

## Why It Matters / Open Questions

The paper addresses a concrete 'data quality gap' in open-source LLM development by releasing two openly licensed corpora (16.1B + 2.3B tokens) under the Llama 3.3 Community License, along with full pipeline code, prompts, and checkpoints. The finding that LLM-driven rewriting yields ~14 points of gain versus ~1-2 points from filtering challenges the field's heavy investment in classifier-based curation and suggests data transformation may be a more efficient lever. Key limitations include Python-only scope, a fixed 50B-token budget, and potential bias transfer from the rewriting LLM (Llama-3.3-70B-Instruct); open questions include whether gains persist at larger training scales, whether the pipeline generalizes to other languages, and whether the rewriting LLM's stylistic preferences inadvertently narrow the solution-space diversity the model learns.
