## Problem

Modern LLMs compress all world knowledge—including rarely-used long-tail facts—into their parameters, making them impractical for edge devices with limited inference-time memory and compute. It remains unclear whether knowledge and reasoning can be disentangled into separate parameter sets, and whether a small model augmented with on-demand external memory can match a much larger model on knowledge-intensive tasks.

## Input / Output

The method takes a text context (e.g., a question or document) and produces standard next-token probability distributions. Unusually, the input is consumed twice: the anchor transformer processes it directly, while a Sentence-BERT-based retriever maps it to a cluster index tuple (i₁,i₂,i₃,i₄) by greedy traversal of a 4-level, 16-way hierarchical clustering tree over the pretraining corpus. The fetched memory parameters (typically ~10% of anchor size) are concatenated into the anchor's FFN layers before forward propagation, so the effective model at inference is anchor + fetched memory, with the full memory bank (up to 21B parameters) remaining offloaded to slower storage.

## Method

The paper introduces a memory-augmented pretraining architecture where a small anchor transformer (160M–1.4B params) is paired with a large hierarchical parametric memory bank (up to 21B params) organized by a 4-level k-means clustering tree (16-way splits, yielding 16⁴ ≈ 65k leaf clusters) over the DCLM-Baseline corpus. At each training step, the document's precomputed cluster index selects one memory block per level; these blocks are FFN-memories that expand the inner dimension of SwiGLU feed-forward layers via concatenation. Because level-l memory parameters are activated only 16ˡ times less frequently than anchor parameters, deeper memories receive gradients exclusively from topically similar documents, shielding them from catastrophic forgetting and enabling them to memorize long-tail knowledge while the anchor captures common knowledge and reasoning. The paper systematically ablates memory type (FFN > LoRa > KV), depth, size, and anchor-to-memory ratio, showing that a 1:10 fetched-memory-to-anchor ratio is near-optimal and that a 160M anchor + 18M fetched memory from a 4.6B bank matches a 410M model trained from scratch on knowledge benchmarks.

## Results

A 160M-parameter anchor model augmented with 18M fetched memory parameters (from a 4.6B bank) achieves 40.3% Avg-SK and 48.7% Avg-CK, matching a regularly trained 410M model (40.9% Avg-SK) with over 2× fewer runtime parameters. Scaling to 410M and 1.4B anchor models with ~10% fetched memory yields +5.0 and +5.2 points on Avg-SK respectively (45.9% and 54.9%), while also improving Avg-CK by +3.8 and +3.3 points. On the atomic-number prediction task, the 1.4B model with memory improves from 17% to 83% accuracy on the least-frequent element bucket. Inference overhead is minimal: less than 10% additional time for 40-token generation on an H100 GPU.

## Baselines & Comparisons

Against regular pretraining (no memory), the proposed method consistently wins on specific-knowledge tasks: +6.2 points Avg-SK for 160M (34.1→40.3%), +5.0 for 410M (40.9→45.9%), and +5.2 for 1.4B (49.7→54.9%), while also improving common-knowledge scores. Against vanilla RAG (Lewis et al., 2020) using the same Sentence-BERT retriever and DCLM datastore, parametric memories dominate on all model sizes: for the 410M model, 10% fetched memory achieves 44.5% Avg-SK vs. 41.6% for RAG-Wiki and 38.1% for RAG-DCLM, while requiring only ×1.1 FLOPs versus ×1.7 and ×2.3 respectively. RAG-DCLM actually underperforms the no-memory baseline on both CK and SK, attributed to the low quality of the pretraining corpus as a retrieval datastore. The paper also shows that combining RAG-Wiki with parametric memories yields further gains (45.7% Avg-SK for 410M), confirming the two mechanisms are complementary. A generic (non-context-dependent) memory of the same size as the fetched memory scores 4.5 points below fetched memories on Avg-SK, isolating the benefit of context-based retrieval.

## Relation to Prior Work

This paper extends the parametric memory literature (Memorizing Transformers, Cartridges, MemSinks, Product Key Memory) by introducing a hierarchical, clustering-based retrieval mechanism for pretraining, building directly on the hierarchical clustering tree construction of Grangier et al. (2025). It departs from Mixture-of-Experts by making inactive parameters offloadable to slower storage rather than requiring all experts in fast memory, and from RAG by storing compressed learned parameters instead of raw text. The FFN-memory design is motivated by prior findings that transformer knowledge resides primarily in feed-forward layers (Geva et al., 2020; Dai et al., 2022), and the training-efficiency argument connects to branch-train-merge methods for distributed training.

## Why It Matters / Open Questions

The practical impact is significant for on-device deployment: a 160M model with ~10% fetched memory matches a 410M model on knowledge tasks, and the hierarchical structure maps naturally to device memory hierarchies (RAM/flash/disk), yielding 5× faster loading than flat banks. The knowledge-editing and privacy implications (blocking 1/16 of the bank drops accuracy from 70% to 20%) open a path to data ownership and deletion that dense models cannot offer. Key open questions include whether the 1:10 memory-to-anchor ratio generalizes, how to improve the anchor's reasoning (not just knowledge), and whether scaling laws for memory learning differ fundamentally from dense pretraining. The approach is currently limited to text and knowledge tasks, with reasoning, multilingual, and multimodal extensions left for future work.
