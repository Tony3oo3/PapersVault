## Problem

Existing RL-based reasoning methods (e.g., DeepSeek-R1) risk reducing reasoning diversity while merely resampling outputs the base model already knows, and direct tree-search approaches suffer from homogeneous reasoning paths and an intractably large vocabulary-level action space. The paper addresses the fundamental dilemma that effective learn-to-reason requires both strong initial reasoning competence and sustained exploratory diversity, which prior self-improvement pipelines fail to jointly provide.

## Input / Output

The method takes a single mathematical question as text input and produces a structured reasoning path where each intermediate step is prefixed by a learnable functional token (e.g., <analyze>, <verify>, <refine>) drawn from an 8-token action space, followed by a final answer wrapped in \boxed{}. Unlike prompt-driven CoT methods, the functional tokens are embedded as special tokens in the model vocabulary, so at inference the model autonomously selects which reasoning behavior to perform at each step without any external prompt guidance. The tree structure constrains valid token transitions (e.g., <clarify> can only follow the root, <subquestion> can only follow <next_step> or <direct_answer>), producing a compact yet expressive action space for search.

## Method

RFTT is a two-phase reinforced fine-tuning framework. In the SFT warmup phase, functional prompt-guided MCTS constructs reasoning trees over 8 human-inspired actions; cross-verification (comparing a correct trajectory against a lowest-reward incorrect trajectory that shares intermediate nodes) and branch merging then synthesize structured training paths that explicitly encode self-verification and self-correction, which are used to fine-tune the model so it learns to emit functional tokens natively. In the online RL phase, the model transitions from prompt-guided to token-guided reasoning by sampling functional tokens directly from its vocabulary to expand reasoning trees, using an AlphaZero-style UCT selection rule (log-likelihood for unexplored actions, UCT score for explored ones) to balance exploration and exploitation at the token level rather than the vocabulary level. The policy is optimized with Reinforce++ (clipped PPO-style updates with normalized advantages) and a KL penalty against the SFT reference model, with rewards combining outcome correctness, a process reward model score for intermediate steps, and a partial-credit signal for non-null incorrect answers. This design adaptively allocates exploration to high-entropy reasoning nodes and enables distinct advantage attribution across shared versus branching tokens, promoting diverse reasoning patterns while reinforcing high-value paths.

## Results

On mathematical reasoning benchmarks, RFTT achieves 79.46% average accuracy on Qwen-3-4B-Base (83.4% MATH-500, 96.1% GSM8K, 75.0% AMC), 75.66% on Qwen-2.5-7B-Instruct (79.8% MATH-500, 95.2% GSM8K, 70.0% AMC), and 64.88% on LLaMA-3.1-8B-Instruct (60.2% MATH-500, 91.9% GSM8K, 55.0% AMC). Notably, Qwen-2.5-7B-Instruct with RFTT reaches 79.8% on MATH-500, nearly matching the 2× larger Qwen-2.5-14B-Instruct (80.0%). In tree search inference, RFTT achieves 95.2% on GSM8K in 81s per question, substantially outperforming rStar (92.1%, 276s) and LLaMA-Berry (94.9%, 339s) in both accuracy and speed.

## Baselines & Comparisons

RFTT consistently outperforms all fine-tuning baselines across all three model backbones. On Qwen-3-4B-Base, RFTT (79.46 avg) surpasses TreeRL (77.36) by 2.1%, ReFT (76.22) by 3.2%, and GRPO (73.42) by 6.0%; the gap widens on harder benchmarks like AMC (75.0 vs. 70.0 for TreeRL) and Olympiad Bench (48.1 vs. 46.5). On LLaMA-3.1-8B-Instruct, RFTT leads TreeRL by 2.7% average and ReFT by 5.4%, with the largest margin on AMC (55.0 vs. 47.5). Against superior LLMs, Qwen-2.5-7B-Instruct+RFTT (79.8% MATH-500) nearly matches the 2× larger Qwen-2.5-14B-Instruct (80.0%) and exceeds GPT-4o (76.6%), while Qwen-3-4B-Base+RFTT (83.4%) surpasses GPT-4o by 6.8 points on MATH-500. In tree search inference (Table 3), RFTT achieves higher accuracy than both rStar and LLaMA-Berry while reducing per-question time by 3.4×–5.1× (e.g., 131s vs. 526s on MATH-500). On out-of-domain general reasoning (Table 2), RFTT shows modest but consistent gains over Few-shot CoT on MMLU-Pro, CommonsenseQA, FOLIO, and TableBench, confirming transferability beyond math.

## Relation to Prior Work

RFTT extends the RLVR paradigm popularized by DeepSeek-R1 by replacing vocabulary-level or prompt-level actions with learnable functional tokens embedded directly in the model vocabulary. It draws on AlphaZero's UCT-based selection for tree traversal and on rStar's functional prompts (e.g., <verify>, <refine>), but departs from rStar by internalizing these behaviors through SFT warmup rather than relying on them as external inference-time constraints. Compared to TreeRL and Satori, which use vocabulary-level actions or manually designed backtracking, RFTT's compact 8-token action space with dependency constraints (Table 18) yields a more structured and efficient search. The cross-verification and branch-merging data construction, which fuses correct and incorrect trajectories into self-correcting reasoning paths, is a distinctive contribution not present in prior MCTS-based self-training methods like ReST-MCTS*.

## Why It Matters / Open Questions

RFTT demonstrates that a 7B model can approach 14B-level math reasoning (79.8% vs. 80.0% on MATH-500) using only ~1k self-generated SFT examples and rule-based RL, suggesting a resource-efficient path to reasoning capability in smaller models. The finding that ablating <verify> and <refine> tokens causes the largest performance drops (79.8% → 72.8%) highlights that self-correction behaviors are the most critical component of the learned reasoning. However, the ~4× computational overhead of MCTS during RL (12.1 min/step vs. 3.2 min/step) is a significant practical limitation, and the method has only been validated on mathematical reasoning with limited evidence of transfer to substantially different domains. Open questions include whether the functional token set generalizes beyond math, whether the approach scales to larger models where the initial reasoning capability is already strong, and whether the 4× cost can be reduced through more efficient MCTS implementations.
