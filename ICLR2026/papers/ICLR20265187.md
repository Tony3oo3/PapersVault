## Problem

Existing program embeddings for compiler optimization face a fundamental trade-off: static representations (from source code or IR) are efficient but cannot capture how a program will behave under complex code transformations, while dynamic representations from runtime profiling are insightful but suffer from prohibitive overhead and non-determinism. No prior approach models a program's intrinsic optimization sensitivity—its propensity to react differently to various compiler passes—without the cost of physical execution.

## Input / Output

The method takes LLVM IR as input and produces a 256-dimensional dense embedding vector as output. Internally, the IR is probed with P diverse optimization sequences (each a fixed-length chain of compiler passes), and the 56-dimensional Autophase feature vector is extracted before and after each probe. The resulting P×56 continuous reaction matrix is discretized via Product Quantization into a P×8 matrix of integer sub-word IDs (each in {0,…,255}), which serves as the token sequence fed to the Transformer. The final embedding is the pooled output of the pre-trained Transformer encoder, ready for downstream classification or regression heads.

## Method

The framework operates in three stages. First, P optimization probes are generated in a data-driven way: programs are clustered by their baseline Autophase features, and a heuristic search (genetic algorithm or greedy) finds one fixed-length pass sequence per cluster that maximizes average instruction reduction; each program's Behavioral Spectrum is then a P×56 matrix of scale-invariant logarithmic relative differences in Autophase features. Second, Product Quantization decomposes each 56-dimensional reaction vector into 8 sub-vectors of 7 dimensions, each independently quantized by a K-Means codebook of 256 centroids, yielding a compositional code of 8 integer IDs per probe (virtual vocabulary of 256⁸). Third, PQ-BERT—a multi-task Transformer with 8 independent sub-embedding layers, a standard multi-layer encoder, and 8 independent linear output heads—is pre-trained with a multi-task Masked Language Model objective (15% masking across all P×M sub-word positions), forcing the model to learn the deep contextual grammar and cross-subspace correlations of program optimization behavior. The pre-trained encoder is then frozen and used to generate embeddings for downstream tasks such as best-pass prediction and -Oz benefit regression.

## Results

On the Best Pass Prediction task (124-class classification), Behavioral-PQ achieves 64.48% Top-1 and 89.55% Top-5 accuracy on the test set, surpassing the strongest static embedding baseline inst2vec (39.27% Top-1) by over 25 percentage points. On the -Oz Benefit Prediction regression task, Behavioral-PQ achieves a test MAE of 8.19%, less than half the error of the next-best baseline inst2vec (16.23%) and roughly one-third of IR2Vec (25.40%) and Autophase (25.92%). In a K-NN embedding-space analysis, Behavioral-PQ also achieves the highest Top-1 accuracy (79.70%) versus InstCount (75.82%), IR2Vec (74.33%), inst2vec (72.15%), and ProGraML (70.75%).

## Baselines & Comparisons

Behavioral-PQ decisively outperforms all five baselines on both primary tasks. Against Autophase (56 handcrafted features), it gains +25.97 pp in Top-1 accuracy and reduces -Oz MAE from 25.92% to 8.19%. Against inst2vec (skip-gram on LLVM IR), the Top-1 gap is +25.21 pp and the -Oz MAE gap is 8.04 pp, confirming that static instruction-level context is insufficient for capturing optimization sensitivity. Against IR2Vec (graph-based flow analysis), the -Oz MAE improves from 25.40% to 8.19% (a 3.1× reduction), while against ProGraML (GNN over multigraphs), the K-NN embedding-space accuracy improves from 70.75% to 79.70%. The paper also shows that even the best zero-shot LLM (gpt-5-mini, 35.52% Top-1) falls below the simple Autophase baseline (38.51%), underscoring that general-purpose code understanding does not transfer to the quantitative, fine-grained domain of compiler optimization prediction.

## Relation to Prior Work

This paper carves out a 'quasi-dynamic' middle ground between two established paradigms in program representation: static structural features (Autophase, IR2Vec, inst2vec, ProGraML) and dynamic runtime profiling (HPCs). Conceptually, it repurposes Autophase's 56-dimensional feature vector not as a fixed descriptor but as a probe-sensitive signal, measuring how those features *change* under optimization sequences. The encoding pipeline borrows Product Quantization from approximate nearest-neighbor search and a BERT-style masked language model from NLP, combining them in a compositional multi-task setup that has not been applied to program representations before. The paper thus departs from prior work not by introducing a new task but by reframing what a program embedding should capture: optimization sensitivity rather than static structure or runtime behavior.

## Why It Matters / Open Questions

The quasi-dynamic framing offers a practical path to capturing optimization-relevant semantics without the overhead and non-determinism of runtime profiling, which could make ML-guided compiler autotuning more deployable in large-scale settings. The finding that even strong general-purpose LLMs (GPT-5-mini, GLM-4.5) fail to match a specialized behavioral model—and that some cannot beat handcrafted Autophase features—suggests that domain-specific representations remain necessary for quantitative compiler tasks despite the rise of large code models. Key open questions include whether the probe set generalizes to unseen program classes, whether the ~0.2 s per-program preprocessing cost is acceptable in production pipelines, and whether the approach extends beyond instruction-count metrics to latency or energy objectives.
