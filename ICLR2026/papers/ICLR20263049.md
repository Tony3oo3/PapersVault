## Problem

Existing LLM routing systems assume a static model pool and focus exclusively on per-query model selection, ignoring the more fundamental upstream decision of which models to deploy under a hard concurrency cap. This paper formalizes the coupled online problem of stage-wise deployment (selecting up to M_max models from a streaming pool at discrete update points) and per-query routing (assigning each request among deployed models under budget and throughput constraints), a setting where no prior bandit or routing framework natively applies.

## Input / Output

The system consumes a stream of text queries, an evolving pool of LLMs with per-model performance distributions and cost distributions (input/output token pricing), a long-term average cost budget b, a concurrency cap M_max, and per-model throughput limits α_m. At each stage boundary it outputs a committed deployment set of at most M_max models (via a MIP), and for every individual query it outputs a routing probability distribution over the deployed set (via an LP) from which a single model is sampled. The deployment set is frozen for the entire stage (T/K queries), while the routing distribution is recomputed after every query observation.

## Method

StageRoute is a two-level hierarchical algorithm that separates strategic deployment from tactical routing. At each stage boundary, a Mixed-Integer Program (DeployOPT) selects the active set by maximizing UCB-weighted reward subject to LCB-weighted cost, throughput, and a cardinality constraint on the support (enforced via binary activation variables), using optimistic reward estimates and conservative cost estimates derived from a confidence radius f_rad(v,n)=√(γv/n)+γ/n. Within a stage, each query triggers a Linear Program (RouteOPT) over the deployed set that maximizes UCB reward under LCB cost and per-model throughput caps, producing a routing distribution from which a model is sampled. The key architectural insight is that the deployment MIP determines only *which* models are live (the support), while the routing LP determines *how* to split load among them, enabling rapid per-query adaptation without re-solving the combinatorial selection. Theoretically, the paper proves a regret bound of Õ(√(M_max·K·T)) + Õ(NT/(M_max·K)), which balances to Õ(T^{2/3}) with K=Θ(T^{1/3}), and establishes a matching Ω(T^{2/3}) lower bound via a staged-arrival construction where the performance frontier drifts upward across batches.

## Results

On RouterBench (36,497 queries, 11 LLMs, 8 datasets), StageRoute achieves consistently slow cumulative regret growth, closely tracking the Oracle (full-knowledge upper bound) under the default setting (M_max=5, b=0.001, update interval=1000). The theoretical guarantee is a regret of Õ(T^{2/3}) with a matching Ω(T^{2/3}) lower bound, establishing near-optimality. Sensitivity analysis confirms robustness across M_max ∈ {3, 5, 10}, update intervals of 500–2000 rounds, and budgets b ∈ {0.001, 0.002}, with the default configuration yielding the lowest regret. The entire experimental run completes in under 10 minutes using Gurobi for the MIP/LP subproblems.

## Baselines & Comparisons

StageRoute is compared against three baselines: an Oracle (full-knowledge upper bound), a Greedy strategy (selects top M_max models by UCB/LCB ratio at each update), and Uniform Sampling (random deployment). StageRoute substantially outperforms both Greedy and Uniform Sampling in cumulative regret across all tested hyperparameter settings. The Greedy baseline is described as 'overly conservative,' consistently underperforming StageRoute in the performance-cost trajectory. Uniform Sampling appears competitive in some regret plots but 'consistently violates the budget for suboptimal performance,' making it impractical. StageRoute's decision heatmaps closely mirror the Oracle's, confirming effective tracking of the optimal deployment set as new models arrive. No existing LLM routing method is directly comparable, as StageRoute is the first to jointly address streaming arrivals, dynamic deployment under a concurrency cap, and cost/throughput-aware routing.

## Relation to Prior Work

StageRoute synthesizes three distinct lines of work—multi-armed bandits (UCB/LCB confidence bounds from Auer et al.), bandits with knapsacks (budget-constrained optimization from Badanidiyuru et al.), and streaming bandits (dynamic arm arrivals)—into a unified two-level hierarchy that no prior formulation addresses. It departs from standard MAB and BwK by introducing a hard concurrency cap on the active set and stage-committed deployment decisions, and from combinatorial bandits by allowing the base arm set to grow over time. The confidence radius function f_rad(v,n) is inherited directly from Babaioff et al. (2015), and the LP-based routing subproblem follows the BwK primal-dual structure, but the coupling of a combinatorial MIP deployment phase with a per-query LP routing phase under a streaming model pool is novel.

## Why It Matters / Open Questions

This is the first formalization of online LLM deployment and routing with streaming arrivals, a concurrency cap, and joint budget/throughput constraints—a setting that mirrors real production systems (e.g., Azure OpenAI's 32-deployment cap and per-model RPM/TPM limits). The matching T^{2/3} upper and lower bounds establish that the problem's difficulty is intrinsic to tracking an evolving performance frontier, not an artifact of the algorithm. Open questions include extending to contextual bandits (query-dependent rewards), handling non-stationary model performance, and scaling the MIP deployment phase to hundreds of candidate models. The practical guidance (K ≈ T^{1/3}, M_max ≈ N^{2/3}) gives operators concrete tuning rules, though the single-benchmark evaluation (RouterBench) and simulated cost model limit immediate deployment confidence.
