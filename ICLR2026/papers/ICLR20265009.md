## Problem

Existing automated test case generation methods—whether prompting-based or supervised fine-tuning—rely on static datasets of code-test pairs, imposing a 'fixed-difficulty ceiling' that prevents the test generator from discovering novel or more complex bugs beyond its training scope. As LLM code generators become more sophisticated and produce subtler flaws, this static paradigm becomes increasingly inadequate, leaving a critical gap in automated debugging pipelines.

## Input / Output

The test generator receives a problem description Q and a potentially faulty code implementation C_buggy, and produces a unit test case as an input-output pair (x, y) formatted as a JSON object within <answer> tags, preceded by a reasoning trace in <think> tags. The generated test must simultaneously satisfy two objectives: Output Accuracy (the predicted output y must match the gold solution's output on input x) and Attack Success (the buggy code must fail on input x, either by crashing or producing an incorrect output). The attack reward is only granted when the I/O pair is first confirmed correct, enforcing a sequential dependency between the two objectives.

## Method

ATGEN trains a test generator via GRPO (an actor-only RL algorithm) within an adversarial loop that dynamically generates a curriculum of increasingly difficult buggy code. The test generator is optimized with a multi-component reward combining IO Accuracy, Attack Success, and Format compliance, while a separate code generator (GPT-4o-mini) samples new adversarial code that must pass the current test case yet fail the ground-truth test suite, ensuring the bug is undetectable by the current policy. Two adversarial modes are evaluated: Unconditional (always replace the buggy code with a new adversarial sample) and Adaptive (only trigger sampling when the current test already attacks the original bug, conserving compute). The adversarial code is obtained via a sampling-based strategy—drawing multiple candidate solutions and filtering for those that coincidentally meet adversarial criteria—rather than direct instruction, to avoid distributional shift from synthetic bugs. This self-improving ecosystem forces the test generator to continuously improve as the adversarial code generator is pushed to produce more subtle flaws, breaking the fixed-difficulty ceiling of static training.

## Results

On the combined APPS + Codeforces benchmark (911 test instances), ATGEN (Adaptive) with a Qwen2.5-7B-Instruct backbone achieves 74.42% IO Accuracy and 36.99% Attack Rate, representing a ~58% relative improvement in Attack Rate over the strongest proprietary baseline (GPT-4-turbo, 23.38%) and more than 2× the prior SFT method UTGen-7B (16.24%). The advantage is most pronounced on Hard-tier problems, where ATGEN (Adaptive) reaches 21.05% Attack Rate versus 20.06% for GPT-4-turbo and only 8.55% for UTGen-7B. Even the non-adversarial RL variant (ATGEN w/o Adver) already achieves 34.02% Attack Rate, far exceeding all prompting and SFT baselines.

## Baselines & Comparisons

ATGEN (Adaptive, 7B) decisively outperforms all six baseline categories on both IO Accuracy and Attack Rate. Against the strongest proprietary prompting baseline, GPT-4-turbo (41.16% IO Acc / 23.38% Attack Rate), ATGEN gains +33.3 pp in IO Accuracy and +13.6 pp in Attack Rate. The SFT baseline UTGen-7B (31.83% / 16.24%) is surpassed by a margin of +42.6 pp in IO Accuracy and +20.8 pp in Attack Rate, confirming that adversarial RL training breaks the fixed-difficulty ceiling of static fine-tuning. Among open-weight prompting baselines, even the largest Qwen2.5-32B-Instruct (35.01% / 21.62%) and Qwen3-8B (38.19% / 22.72%) trail ATGEN by over 36 pp in IO Accuracy and 14+ pp in Attack Rate. The gap widens on Hard-tier problems: ATGEN (Adaptive) achieves 21.05% Attack Rate versus 20.06% for GPT-4-turbo and only 8.55% for UTGen-7B, indicating that the adversarial curriculum is most beneficial when bugs are subtle. In downstream Best-of-N filtering, ATGEN (Adaptive) also outperforms UTGen by 4.3 pp in pass@1 (35.00% vs. 30.67%), and as an RL reward source it produces a code generator that significantly outperforms one trained with UTGen or prompted Qwen2.5-7B rewards.

## Relation to Prior Work

This paper departs from the two dominant paradigms for LLM-based test case generation—prompting general-purpose LLMs and supervised fine-tuning on static code-test pairs (exemplified by UTGen)—by framing test generation as a reinforcement learning problem with a dynamic adversarial curriculum. It repurposes GRPO (from DeepSeek-R1) not for code generation but for training a test generator that jointly optimizes output accuracy and attack success, and introduces an asymmetric adversarial loop (a code generator crafting evasive bugs) that is conceptually closer to the Setter-Solver paradigm in intrinsic motivation literature than to symmetric self-play. The adversarial code generation step borrows the spirit of mutation testing but replaces syntactic mutation operators with LLM-sampled natural bugs, explicitly addressing the validity concerns raised in prior mutation testing literature.

## Why It Matters / Open Questions

The practical demonstration that ATGEN-generated tests serve as both an effective Best-of-N filter (closing the gap to human-expert selection) and a high-quality RL reward source for training code generators opens a path toward self-improving code pipelines where ground-truth test suites are unavailable. A key open question is the dependency on an external LLM (GPT-4o-mini) for adversarial code sampling, which limits full self-containment and introduces cost; making the adversarial loop endogenous (e.g., via a co-trained code generator) would be a natural next step. The evaluation, while thorough, is confined to competitive-programming-style benchmarks (APPS, Codeforces, TACO), leaving open whether the adversarial curriculum generalizes to industrial-scale codebases with more heterogeneous bug distributions.
