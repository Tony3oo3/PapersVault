## Problem

Memory-layer architectures, which activate embeddings from large parameter tables instead of computing through FFN experts, offer dramatically lower memory access than MoE during inference. However, prior state-of-the-art memory-layer models like UltraMem could only match the performance of 2-expert MoE, falling far short of the 8-expert configurations that current industrial MoE models (DeepSeek-V3, Qwen3, OLMoE) use for optimal performance-efficiency trade-offs.

## Input / Output

The model consumes standard text token sequences and produces generated text via autoregressive language modeling. The key architectural detail is that each token activates only a sparse subset of the 120B total parameters (2.5B activated), with memory layers retrieving top-m value embeddings via Tucker-decomposed query-key scoring rather than routing through full FFN experts. Row/column TopM is constrained (e.g., 128) to avoid quadratic intermediate variable explosion in the grid scoring.

## Method

UltraMemV2 introduces five key modifications to the UltraMem memory-layer architecture: (1) placing a memory layer in every transformer block alongside the FFN rather than at fixed intervals; (2) replacing multiple per-head linear projections in Implicit Value Expansion with a single shared value projector; (3) adopting PEER's FFN-based value computation (a 1-inner-dimension FFN) in place of static value embeddings, effectively creating millions of tiny experts; (4) deriving principled initialization that matches the memory layer's output variance to the FFN's to prevent training divergence; and (5) rebalancing the memory-to-FFN computational ratio to ~17%. The retrieval mechanism uses Tucker Decomposed Query-Key Retrieval (TDQKR) with separate queries per Tucker rank, and the paper establishes that activation density (number of top-m values per layer) has greater impact on performance than total sparse parameter count.

## Results

On the open-source 227M/1.2B configuration (500B tokens), UltraMemV2 achieves 54.4 average benchmark score, matching OLMoE (54.6) and outperforming Memory+ (52.8) and UltraMem (53.8). At the 1B/7B scale (1T tokens), UltraMemV2 reaches 61.8 vs. OLMoE's 62.1, confirming near-parity with 8-expert MoE. On proprietary 32K long-context tasks, UltraMemV2-2.5B/60B-top768 shows substantial gains over SeedMoE: +1.6 on long-context memorization (23.5 vs 21.9), +6.2 on multi-round memorization (31.2 vs 25.0), and +7.9 on in-context learning (29.5 vs 21.6), though it underperforms on multi-hop reasoning (17.7 vs 34.8).

## Baselines & Comparisons

Against OLMoE (8-expert MoE), UltraMemV2 achieves near-parity: 54.4 vs 54.6 at 227M/1.2B and 61.8 vs 62.1 at 1B/7B, trailing by only 0.2–0.3 points on the aggregate score while winning on individual benchmarks like ARC-C (44.5 vs 43.1) and SCIQ (93.1 vs 92.7) at the 1B/7B scale. Against Memory+ (Berges et al., 2024), UltraMemV2 clearly wins by 1.6 points (54.4 vs 52.8), with the largest gaps on Hellaswag (+4.5) and CommonSenseQA (+3.8). Against the prior UltraMem (Huang et al., 2024), UltraMemV2 improves by 0.6 points (54.4 vs 53.8), closing the gap that previously limited memory-layer architectures to 2-expert MoE performance. On proprietary long-context benchmarks, UltraMemV2 substantially outperforms SeedMoE on memory-intensive tasks (+6.2 multi-round, +7.9 in-context learning) but loses significantly on multi-hop reasoning (17.7 vs 34.8), indicating a trade-off between memorization and compositional reasoning.

## Relation to Prior Work

UltraMemV2 directly extends the UltraMem (Huang et al., 2024) memory-layer architecture, which itself builds on the Product Key Memory (Lample et al., 2019) retrieval paradigm with Tucker-decomposed query-key scoring. The key departure is incorporating PEER's (He, 2024) FFN-based value processing in place of static embedding lookups, simplifying the Implicit Value Expansion to a single shared linear projection, and placing memory layers in every transformer block rather than at fixed intervals. Conceptually, the paper reframes memory layers as 'a million 1-inner-dimension experts,' drawing an explicit structural analogy to SwiGLU FFNs to justify the architectural choices.

## Why It Matters / Open Questions

This is the first memory-layer architecture to reach performance parity with 8-expert MoE at 120B total parameters, closing a gap that had persisted since PKM. The demonstrated advantages on memory-intensive tasks (long-context memorization, multi-round dialogue, in-context learning) and significantly lower inference memory access position it as a practical alternative for deployment-constrained settings. Key limitations include slower early-training convergence, dependence on per-block memory layer placement, and the fact that the strongest evidence rests on proprietary benchmarks; the open-source validation is at much smaller scale (≤7B). Open questions include whether hybrid MoE+memory architectures can capture complementary strengths, and whether the activation-density-over-parameter-count principle holds at even larger scales.
