## Problem

Agent-to-Agent (A2A) protocols enable heterogeneous LLM-based agents to discover, negotiate, and exchange artifacts, but their opaque execution model—where agents are black boxes exposing only declared capabilities—creates a protocol-level threat surface that existing prompt-centric defenses and LLM-MAS security studies do not address. No standardized, reproducible benchmark existed to systematically probe these protocol-specific vulnerabilities across the full A2A lifecycle (discovery, orchestration, execution).

## Input / Output

The scenario adapter consumes a structured attack vector description and a scenario specification (MAS topology, agent roles, domain tools) and produces a JSON array of executable test-case prompts tailored to that scenario. For AgentCard Spoofing, the input is a set of 10 AgentCard JSON objects (one benign, nine with single-field perturbations such as Cyrillic lookalikes or URL host modifications), and the output is a single integer index. For Capability Cloaking, the system runs a benign task suite against a MAS containing one cloaked agent and reports a utility degradation delta (e.g., 0.853→0.682 in travel). All other attacks yield binary per-trial success indicators aggregated into an Attack Success Rate over 100 trials per attack per domain.

## Method

The paper introduces a two-class threat taxonomy (supply-chain manipulations and protocol-logic weaknesses) covering six concrete attacks mapped to specific A2A lifecycle stages and protocol components, then operationalizes them in A2ASECBENCH. The framework's key architectural element is a dynamic scenario adapter—an LLM-driven mapping from (attack vector, scenario spec) to executable test cases—that decouples attack logic from domain-specific details, enabling portability across heterogeneous agent stacks. Evaluation pairs each adversarial trial with benign tasks to jointly measure safety (ASR) and utility (performance degradation), making the harmlessness-helpfulness trade-off explicit. The system under test is the official A2A Project sample (Gemini 2.5 Flash host coordinating three remote agents), adapted to travel, healthcare, and finance domains via customized system prompts and AgentCards. Transferability is further validated by re-instantiating attack patterns in LangGraph and ANP ecosystems, and defense is probed using NVIDIA NeMo Guardrails as a security gateway.

## Results

Across three high-stakes domains (travel, healthcare, finance), five of six attacks (Capability Cloaking, Half-Open Task Flooding, Cycle Overflow, Agent-Side Request Forgery, Artifact-Triggered Script Injection) achieve 100% Attack Success Rate (ASR), while AgentCard Spoofing reaches an average ASR of 0.82–0.83 across models. Capability Cloaking induces substantial utility degradation on benign tasks, dropping performance from 0.853→0.682 (travel), 0.872→0.595 (healthcare), and 0.962→0.749 (finance). When NVIDIA NeMo Guardrails is deployed as a security gateway, it only partially mitigates the attacks: ASRF drops to 0.23–0.48 ASR, CO to 0.66–0.73, but HOTF (0.85–0.91) and ATSI (0.91–0.94) remain largely unmitigated.

## Baselines & Comparisons

The paper evaluates three comparison targets. Against NVIDIA NeMo Guardrails (Table 4), the proposed attacks remain highly effective: ASRF is the most mitigated (ASR drops from 1.00 to 0.23–0.48), CO is partially suppressed (0.66–0.73), but HOTF (0.85–0.91) and ATSI (0.91–0.94) are barely affected, revealing that existing guardrails lack understanding of multi-agent interaction patterns and protocol semantics. For transferability (Table 3), the attack patterns generalize to LangGraph-based MAS, where CO, ASRF, and ATSI all achieve 1.00 ASR (AS, CC, and HOTF are N/A due to LangGraph's lack of agent discovery and intermediate states). On the ANP ecosystem, all six attacks transfer successfully with ASR of 0.98–1.00, confirming that the identified vulnerabilities are not A2A-specific but reflect broader weaknesses in agent-to-agent communication protocols.

## Relation to Prior Work

This paper extends the line of LLM-MAS security research (communication attacks, topology vulnerabilities, cascading injection) from prompt-centric and model-level threats to protocol-level, lifecycle-spanning vulnerabilities specific to the A2A protocol. It draws conceptual parallels to classical security primitives—SSRF, XSS, SYN flooding, and federated-learning poisoning—but repurposes them within the A2A discovery-orchestration-execution pipeline, where opaque AgentCards and structured task states create new attack surfaces. Unlike prior A2A security analyses (Habler et al. 2025, Louck et al. 2025) that offer qualitative threat models and defense recommendations, this work introduces concrete, executable attack vectors paired with a reproducible benchmark framework and a dynamic scenario adapter for cross-domain portability.

## Why It Matters / Open Questions

With A2A already adopted by major enterprise platforms (Google Cloud, Microsoft, Salesforce, SAP) and a rapidly growing ecosystem, the finding that five of six attacks achieve 100% ASR across travel, healthcare, and finance domains—and that a mature production guardrail (NeMo) still permits 23–94% success—signals an urgent gap between protocol design and deployment readiness. The transferability of attack patterns to LangGraph and ANP suggests the vulnerabilities are architectural to MAS rather than A2A-specific, broadening the implications. Key open questions include: can protocol-level defenses (verifiable AgentCards, capability attestation, DAG validation) be standardized without sacrificing interoperability, and how should joint safety-utility trade-offs be governed in production multi-agent deployments?
