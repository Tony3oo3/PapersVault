## Problem

Current UI-agent benchmarks rely on fixed clones of apps, measuring only whether an agent can complete a task within one specific environment. When deployed, agents encounter numerous variations in app appearance (themes, fonts, colors) and content (language, adversarial text, density) that can dramatically affect task success, but this dimension of reliability is invisible to fixed-clone evaluations. The paper asks: how much does agent reliability actually fluctuate across the app variations that real deployments would present?

## Input / Output

Each evaluation takes a natural-language task goal (e.g., 'Add Buy milk to my todos'), a YAML-specified app configuration (appearance variables like theme/font/color and content variables like language/description type), and at each step the agent receives a screenshot plus an optional accessibility-tree text representation. The output is a binary reward computed as a deterministic indicator over the full serialized app state (not a trajectory match or partial state-change check), aggregated into reliability metrics: standard deviation and mean absolute deviation of rewards both within a single app version and across all app versions, plus behavioral diagnostics such as action-loop counts, hallucinated-action rates, and intent-misunderstanding rates. The entire environment runs in a single Python process on one CPU with under 10 MB of memory.

## Method

OPENAPPS is a browser-based ecosystem of six fully functional Python apps (calendar, messenger, maps, todo, code editor, shop) built on the FastHTML framework, where all appearance and content variables are exposed through editable YAML files that serve as the initial environment state s₀. Agent-environment interaction follows standard RL terminology via the BrowserGym API: the agent observes screenshots and (optionally) AX-tree text, then issues human-like actions (click, type, scroll, drag-and-drop, etc.) that update the app state. Task success is evaluated by comparing the full serialized app state to a target state using r = δ[s_t = s_target], which avoids both the over-restriction of trajectory-matching rewards and the exploitability of partial state-change checks. The paper applies eight curated appearance/content variations (dark theme, B&W, challenging font, German, adversarial descriptions, misleading descriptions, long descriptions, default) simultaneously across all apps, then runs over 10,000 evaluations with seven multimodal agents (GPT-4o, Claude 4 Sonnet, Kimi-VL, Qwen2.5-VL, LLaVA, UI-TARS, and others) on 15 simple tasks. The key analytical contribution is decomposing reliability into within-version deviation versus across-version deviation, showing that fixed-app evaluations systematically overestimate reliability by more than 2× for several agents.

## Results

Across over 10,000 evaluations with seven multimodal agents, task success rates fluctuate by more than 50% across app variations. Kimi-VL-A3B-Instruct's average success drops from 63% to 4% depending on the app version, while UI-TARS-1.5-7B's pass@1 falls from 0.41 (default) to 0.05 (dark theme). Standard deviations in task success across app variations exceed twice those within a fixed app for Qwen2.5-VL, Kimi-VL, and UI-TARS, demonstrating that fixed-environment evaluations substantially overestimate agent reliability.

## Baselines & Comparisons

The paper evaluates seven agents (Claude 4 Sonnet, GPT-4o, Kimi-VL-A3B-Instruct, LLaVA-v1.6-Mistral-7B, Qwen2.5-VL, UI-TARS-1.5-7B) across eight app variations. Closed-source models (GPT-4o, Claude 4 Sonnet) maintain relatively high pass@1 (0.75–0.84) across most appearance variations, though GPT-4o's ForwardMessageTask success drops from 43% to 0% under adversarial descriptions. UI-TARS-1.5-7B, a vision-only model, shows the most dramatic sensitivity: its pass@1 collapses from 0.41 (default) to 0.05 (dark theme), an 8× drop, and it is 5× more likely to hallucinate invalid actions in certain configurations. Kimi-VL-A3B-Instruct is most affected by content variations, dropping from 0.21 (default) to 0.02 under German or adversarial descriptions. The key finding is that no single agent dominates across all variations, and the ranking of agents can shift depending on the app configuration encountered.

## Relation to Prior Work

This paper departs from the dominant paradigm of UI-agent evaluation that relies on fixed clones of real apps (OSWorld, WebArena, VisualWebArena, TheAgentCompany), which can only measure reliability within a single environment configuration. It draws conceptual inspiration from domain randomization in robotics and RL (MuJoCo, ALE) but applies it to the digital-agent setting, where no prior environment supported systematic variation of app appearance and content at scale. Technically, it builds on BrowserGym for agent-environment interaction and uses FastHTML to implement fully functional apps in Python, achieving the efficiency of lightweight environments like MiniWoB while retaining more realistic multimodal UI interactions than those minimal testbeds.

## Why It Matters / Open Questions

The finding that task success rates can fluctuate by over 50% (and up to 10×) across app variations reveals a critical blind spot in current agent evaluation: fixed-clone benchmarks systematically overestimate deployment reliability. This has immediate practical implications for anyone deploying UI agents, as even superficial changes (dark theme, German text, adversarial descriptions) can collapse performance for specific models. Key limitations include the focus on simple few-step tasks, independent (non-interacting) variation factors, and a curated rather than exhaustive set of variations. Open questions include whether these effects persist on complex multi-step tasks, how interaction effects between multiple variation factors compound, and whether agents can be trained to generalize across app variations using the large-scale data OPENAPPS enables.
