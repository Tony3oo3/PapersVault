## Problem

Modern AI kernels (e.g., FlashMLA, Block Sparse Attention) require fine-grained control over memory hierarchy, data movement, and parallel scheduling to achieve peak GPU performance, but existing compilers like Triton expose no programmable abstractions for these dimensions. Developers face a steep tradeoff: hand-written CUDA kernels reach full performance but demand ~500 lines of complex code, while Triton implementations are concise (130 lines) yet achieve only 14.2% of hand-written performance on H100. The paper addresses this gap by providing a tile-level programming model that gives explicit hardware control while automating low-level configuration.

## Input / Output

The input is a tile-level Python DSL program where developers compose tile operators (T.copy, T.gemm, T.reduce) and optionally annotate tile shapes, memory placement (T.alloc_shared, T.alloc_fragment), warp partitioning policies, and swizzled layouts. The FTG is constructed from this program, and the two-stage optimization pipeline (recommendation + inference) fills in all unspecified dimensions. The output is a fully specified, hardware-efficient kernel lowered to CUDA (NVIDIA) or ROCm (AMD) via the TVM backend, with the inferred schedule encoding concrete tile sizes, memory layouts, pipeline stage assignments, and instruction selections (e.g., Tensor Core MMA, TMA copies).

## Method

TILELANG elevates tiles to first-class IR constructs with explicit semantics for indexing, data movement, reuse, and pipelining, represented as a Fused Tile-level Graph (FTG) where nodes are tile operators and edges encode data dependencies. A two-stage optimization operates over the FTG: (1) tile recommendation uses a static roofline-based cost model (Time = max(MemoryTraffic/Bandwidth, Computation/Performance) + t_intrinsic) to rank candidate tile shapes, memory placements, and warp partitions, providing hardware-aware defaults; (2) tile inference propagates shape and layout constraints across the FTG via a three-phase algorithm (STRICT for hardware-mandated layouts like swizzled shared memory and MMA-aligned registers, COMMON for fixed-point propagation through aligned operators, FREE for register-cost-minimizing choices over connected components), then automatically derives software pipelining schedules and selects platform-specific instructions via integration with CuTe/CK tile libraries. This design lets developers specify only high-level computation and key decisions while the system completes all low-level configuration, achieving 1.08×–10.58× speedups over Triton on H100 and 1.01×–11.56× on MI300X with under 70 lines of Python.

## Results

TILELANG delivers 1.08×–10.58× speedups over Triton on NVIDIA H100 (3.02× average) and 1.01×–11.56× on AMD MI300X (2.65× average) across nine AI operators. The largest gains appear on Multi-Head Latent Attention (4.06–10.59× over Triton on H100) and Block Sparse Attention (3.42–7.87×), where fine-grained memory and pipeline control is most critical. TILELANG reduces code size by up to 85.5% versus hand-written CUDA while matching or exceeding their performance, and its cost model prunes 95% of candidate schedules while retaining 98.47% of the best achievable TFLOPS. Average tuning time is ~10 seconds per operator on both platforms.

## Baselines & Comparisons

Against Triton (the primary baseline), TILELANG wins on every operator, with the most dramatic gains on Flash MLA (up to 10.59× on H100, 12.97× on MI300X) and Block Sparse Attention (up to 7.87×), where Triton's lack of explicit memory-placement and pipeline control is most limiting. Against PyTorch Inductor, TILELANG achieves 1.18–363× speedups depending on the operator, with the largest wins on fused sparse/linear-attention kernels (108–363×). Against specialized libraries, TILELANG matches FlashAttention-V3 (0.98×/0.96× average), slightly outperforms AMD's AITER on MLA (1.05×), and matches Block Sparse Attention latency (0.91–1.82×) while using far less code. Against ThunderKittens, TILELANG achieves 0.99–1.11× on GEMM and up to 1.10× on Flash Attention while reducing code complexity by 77%, and additionally supports AMD GPUs where TK is unavailable. Against the most recent DSLs (Helion, Gluon, Tilus), TILELANG achieves 1.15–1.62×, 1.52–1.83×, and 1.87–2.12× speedups respectively on GEMM, with the largest gap over Tilus attributed to its incomplete Hopper (WGMMA/TMA) support.

## Relation to Prior Work

TILELANG positions itself at the intersection of high-level DSLs (Triton, Gluon, Helion, Tilus) and low-level template frameworks (CUTLASS, ThunderKittens), departing from both by elevating tiles to first-class IR constructs with explicit semantics for indexing, data movement, and pipelining. It builds on TVM for low-level code generation but introduces its own Fused Tile Graph (FTG) IR and a two-stage optimization pipeline—tile recommendation via a roofline-based cost model and tile inference via constraint propagation—that is distinct from TVM's schedule-driven loop generation. Unlike Triton's opaque optimization passes or ThunderKittens' curated CUDA templates, TILELANG exposes memory placement, warp partitioning, layout, and pipelining as programmable dimensions while automating their completion, drawing conceptually on prior work in tile-graph scheduling (Welder) and analytical cost modeling (Timeloop, Maestro) but operating at a finer, tile-granular level.

## Why It Matters / Open Questions

TILELANG addresses a practical pain point in AI systems: the steep performance penalty (up to 86% loss) incurred when using high-level DSLs like Triton for complex attention kernels, versus the high development cost of hand-written CUDA. By matching near-CUDA performance with under 16% of the code size and supporting both NVIDIA and AMD backends, it lowers the barrier for researchers to prototype emerging algorithms (MLA, block-sparse attention, linear attention) without deep GPU expertise. Open questions include how well the cost model generalizes to future architectures with radically different memory hierarchies, whether the tile-level abstraction remains sufficient as hardware introduces finer-grained parallelism (e.g., sub-warp scheduling), and how the system handles increasingly irregular sparsity patterns beyond block-sparse structures.
