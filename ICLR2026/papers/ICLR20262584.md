## Problem

Existing computer-use agent benchmarks (OSWorld, WebArena, WebShop) evaluate task completion in sanitized, secure environments, leaving the security capabilities of CUAs entirely unmeasured. It remains unknown whether frontier multimodal agents can discover and exploit real web application vulnerabilities through graphical interfaces, a critical gap as these agents increasingly operate autonomously in production web ecosystems.
![Teaser figure](../imgs/ICLR20262584/cropped_page2_idx0.webp)

## Input / Output

Each task is formalized as a POMDP where the agent receives a natural language instruction plus a 1280×720 (16:9) screenshot of the Kali Linux desktop, optionally augmented with an accessibility tree or Set-of-Marks overlay. The agent issues low-level actions (click, type, submit_flag) through an Action Server and must ultimately submit a flag string, validated via fuzzy matching with an edit-distance threshold of 5 to tolerate OCR errors. The episode terminates on flag submission, explicit termination, or a maximum step limit, with a binary reward (1 for correct flag, 0 otherwise).

## Method

HackWorld is a modular evaluation framework that deploys 36 CTF challenges (sourced from NYU CTF Bench, Cybench, and InterCode-CTF) as isolated Docker containers within a Kali Linux VM, each containing a vulnerable web application spanning 7 languages and 11 frameworks. The environment provides agents access to 20+ industry-standard security tools (Burp Suite, DirBuster, Nikto, WFuzz, WhatWeb, SQLMap, etc.) and a Controller that logs all HTTP requests, tool invocations, and file-system operations for qualitative analysis. Six models (four proprietary Claude variants, UI-TARS-1.5-7B, Qwen2.5-VL-72B) are evaluated across three observation spaces (screenshot, screenshot+a11y-tree, screenshot+Set-of-Marks). The key empirical finding is that the best model (Claude-3.7-Sonnet) achieves only 11.1% success, with error analysis revealing that the bottleneck is strategic reasoning and tool orchestration—agents fail to chain multi-step attacks, parse tool outputs into actionable plans, and recover from routine errors—rather than perceptual fidelity, as observation-space differences are statistically insignificant (p>0.1).

## Results

On HackWorld's 36 web vulnerability exploitation challenges, the best-performing agent (Claude-3.7-Sonnet) achieves a maximum success rate of 11.11% (screenshot and Set-of-Marks observation spaces), with all evaluated CUAs remaining below 12%. Claude-4-Opus reaches 5.56% and Claude-3.5-Sonnet reaches 5.56% (a11y-tree), while Claude-4-Sonnet, UI-TARS-1.5-7B, and Qwen2.5-VL-72B-Instruct all score 0% across every observation space. A one-way ANOVA across observation spaces confirms no statistically significant difference (p > 0.1), indicating that perceptual input format is not the primary bottleneck; strategic reasoning and tool orchestration are.

## Baselines & Comparisons

Claude-3.7-Sonnet is the clear winner, achieving 11.11% success (screenshot/SoM) — nearly double Claude-4-Opus (5.56%) and over three times Claude-3.5-Sonnet (2.78–5.56%). Notably, the larger and newer Claude-4-Opus underperforms Claude-3.7-Sonnet by 5.55 percentage points, and Claude-4-Sonnet scores 0% across all settings, challenging the assumption that model recency and scale guarantee better agentic performance. Both open-source models (UI-TARS-1.5-7B and Qwen2.5-VL-72B-Instruct) fail completely (0%), despite UI-TARS achieving 27.3% on OSWorld, indicating that general GUI automation capability does not transfer to adversarial security tasks. The cross-benchmark comparison (Table 4) further confirms this gap: Claude-4-Sonnet scores 43.9% on OSWorld but 0% on HackWorld, while Claude-3.7-Sonnet's 27.1% on OSWorld translates to only 11.1% on HackWorld. Tool usage analysis reveals that Claude-3.5-Sonnet makes the most tool calls (avg. 4–6 per trajectory, 88–94% usage rate) yet achieves lower success than Claude-3.7-Sonnet (avg. 2.3 calls, 58% usage), suggesting selective and strategic tool integration matters more than frequency.

## Relation to Prior Work

This paper extends the CUA evaluation lineage established by OSWorld (Xie et al., 2024) and WebArena (Zhou et al., 2024) by replacing their sanitized, task-completion environments with realistic vulnerable web applications drawn from CTF competitions (NYU CTF Bench, Cybench, InterCode-CTF). It departs from prior cybersecurity LLM benchmarks (PentestGPT, Cybench, EnIGMA) that evaluate text-only or code-level reasoning, instead requiring agents to perceive complex GUIs, navigate visual interfaces, and orchestrate Kali Linux security tools (Burp Suite, DirBuster, Nikto, WFuzz) through a unified visual interaction loop. The formalization as a POMDP with flag-based reward inherits the CTF evaluation paradigm but is the first to ground it in the multimodal CUA setting.

## Why It Matters / Open Questions

HackWorld fills a critical gap: prior CUA benchmarks assume secure environments, leaving unknown how agents behave when encountering real vulnerabilities. The finding that even the best model (Claude-3.7-Sonnet) achieves only ~11% success, and that all open-source models score 0%, exposes a substantial capability gap that has implications for both the safety of deploying CUAs in production web environments and the feasibility of autonomous penetration testing. The paper identifies strategic reasoning and tool orchestration—not perception—as the core bottleneck, pointing future work toward security-aware planning and agent-friendly tool interfaces. Open questions include whether targeted security training (e.g., CTF-dojo-style RL) can close the gap, and how results generalize beyond the 36 curated challenges to the open web.
