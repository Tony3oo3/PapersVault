## Problem

AI agents powered by LLMs are deployed at scale, yet there is no systematic way to evaluate how the choice of backbone LLM affects agent security. Existing agent security benchmarks either cover only restricted attack vectors (e.g., indirect prompt injection only) or require mocking entire agent execution flows, making it difficult to isolate LLM-specific vulnerabilities from traditional software risks and to compare models fairly.
![Teaser figure](../imgs/ICLR20262299/cropped_page5_idx0.webp)

## Input / Output

Each evaluation takes a full model context (system prompt, chat history, tool definitions) at a specific agent state and an adversarial attack payload that is inserted into the context to produce a poisoned variant. The backbone LLM is run N=5 times on the poisoned context, and each output is scored in [0,1] by a threat-snapshot-specific metric (exact match, recall, profanity, embedding-distance, or LLM-as-judge). The final vulnerability score is the mean across all 210 attacks, 10 threat snapshots, 3 defense levels, and 5 repetitions, with 95% bootstrap confidence intervals.

## Method

The paper introduces threat snapshots, a formal abstraction that isolates a single stateless LLM call within an agent's execution flow, specifying the agent state, the full model context, the attack vector/objective categorization, an attack insertion function, and an attack scoring function. Ten threat snapshots are constructed to cover all six attack vectors/objectives and all six task types (DIO, IIO, DTI, ITI, DCE, DAIS), each with three defense levels (minimal prompt, stronger prompt, and LLM-as-judge self-defense). High-quality attacks are collected via a gamified crowdsourced red-teaming challenge (Gandalf Agent Breaker) yielding 194,331 unique attacks from 13,920 sessions, from which the top 210 are selected by cross-model average score. The resulting b³ benchmark is used to evaluate 34 LLMs, revealing that reasoning capabilities improve security while model size does not correlate with it, and that closed-weight systems generally outperform open-weight models.

## Results

The b³ benchmark evaluates 34 popular LLMs using 210 high-quality crowdsourced attacks (selected from 194,331 total) across 30 threat snapshots (10 agents × 3 defense levels). The most secure models are claude-haiku-4-5, claude-sonnet-4-5 (reasoning enabled), and claude-haiku-4-5 (no reasoning), while the best open-weights model is kimi-k2-thinking with a vulnerability score of 0.34, outperforming OpenAI's gpt-5.1 (without reasoning). Key findings: enabling reasoning generally reduces vulnerability scores (improves security), model size shows no meaningful correlation with security, and closed-weight systems outperform open-weight models at the system level. The average attack score across all LLMs and levels is 0.18 for the public dataset versus 0.56 for the top 210 withheld attacks, highlighting the difficulty of constructing effective attacks.

## Baselines & Comparisons

The b³ benchmark is compared against four existing agent security benchmarks: ASB, AgentDojo, InjecAgent, and AgentHarm. b³ outperforms all four on attack coverage, supporting both direct and indirect vectors (2/2) and all six attack objective categories (6/6), whereas AgentDojo and InjecAgent cover only indirect vectors (1/2) and AgentHarm covers only 1/6 objectives. b³ is the only benchmark enabling sub-rankings by task type, defense level, and attack category, which none of the four baselines support. The attacks in b³ are human-generated and task-specific (crowdsourced via the Gandalf Agent Breaker challenge), making them substantially more adversarial than the templated attacks used in all four baselines. b³ also evaluates more models (34 vs. 10–30) and uses threat snapshots to isolate LLM-specific vulnerabilities from traditional software flaws, whereas all four baselines require modeling complete agent execution flows, conflating LLM vulnerabilities with system-level issues.

## Relation to Prior Work

This paper departs from existing agent security benchmarks (ASB, AgentDojo, InjecAgent, AgentHarm) that either cover only restricted attack vectors (e.g., indirect prompt injection or RCE) or require simulating complete agent execution flows. The key conceptual departure is the 'threat snapshot' abstraction, which isolates a single LLM call within an agent's execution flow, cleanly separating LLM-specific vulnerabilities from traditional software risks. Rather than templated attacks used by prior benchmarks, the paper collects 194,331 human-crafted adversarial attacks via a gamified crowdsourcing challenge (Gandalf Agent Breaker), yielding context-dependent and adaptive attacks that static datasets cannot capture. The attack categorization (vector-objective and task-type) is constructed from scratch for the agentic setting rather than adapted from existing LLM safety taxonomies.

## Why It Matters / Open Questions

The b³ benchmark provides the first systematic, open-source tool for comparing backbone LLM security properties in isolation, giving agent developers a practical basis for model selection beyond capability benchmarks. The finding that model size does not correlate with security while reasoning capabilities do challenges the prevailing scaling narrative and has direct implications for model development priorities. Key limitations include the restriction to single-step attacks (multi-step propagation and interaction with surrounding software remain unmodeled), the absence of utility/latency tradeoff analysis, and the resource intensity of crowdsourced attack collection that may not scale as models improve. Open questions include whether automated adaptive attacks can replace human red-teaming and how threat snapshots extend to quantify full-system risk beyond the backbone LLM.
