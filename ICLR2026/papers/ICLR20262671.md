## Problem

Existing dynamic-tree speculative decoding methods (EAGLE-2, EAGLE-3) construct draft trees based solely on token confidence scores, ignoring system-level variables such as GPU device type and batch size. In batched inference, naively increasing tree depth or node count can saturate GPU resources and actually slow down decoding, yet no prior method explicitly models this inference-cost trade-off when deciding tree structure.
![Teaser figure](../imgs/ICLR20262671/cropped_page4_idx0.webp)

## Input / Output

The method consumes a batch of B text sequences (padded to a common context length n₀), the target GPU configuration, and two precomputed cost lookup tables S_T(B) and S_D(B) that map (context_length, sequence_length) pairs to forward-pass latency for the target and draft models respectively. It outputs a dynamically pruned draft tree—specifying per-layer node counts, total depth, and the number of tokens to send to the target model for verification—which is then linearized into a flat sequence with a hierarchical attention mask for the verification forward pass.

## Method

CAST frames node selection as a utility-maximization problem: each candidate node's confidence score v(u) serves as a proxy for acceptance probability, while the precomputed cost tables provide the marginal inference cost of adding that node. A breadth-pruning step (Algorithm 1) retains nodes whose marginal utility-to-cost ratio exceeds a threshold C₁, a depth-pruning step uses a FIFO buffer of confidence-gain ratios to decide whether to expand another layer (threshold C₂), and a reranking step applies the same utility-cost criterion to select how many tokens the target model verifies (threshold C₃). The paper proves that EAGLE-2 and EAGLE-3's fixed top-K selection is a special case of this formulation when costs are linear in node index. By integrating these three cost-aware pruning stages with EAGLE-2/3's dynamic tree expansion, CAST adapts tree shape to the actual hardware and batch regime, achieving up to 5.2× speedup over autoregressive decoding and 5–20% gains over EAGLE-3.

## Results

CAST achieves up to 5.23× speedup over vanilla autoregressive decoding (Llama-3.3-70B on HumanEval, temperature 0, batch size 1), and consistently outperforms the prior SOTA EAGLE-3 by 5–20% across all six tasks and four model families. Under batching (batch size 8), CAST maintains 2.16–3.12× speedup while EAGLE-2 degrades to 1.01–1.63×, demonstrating that cost-aware tree construction is critical at scale. The method is evaluated on six tasks (MT-bench, HumanEval, GSM8K, Alpaca, CNN/Daily Mail, Natural Questions) across six LLMs (Vicuna-13B/33B, Llama-3.1-8B, Llama-3.3-70B, DeepSeek-R1-Distill-8B, Qwen2-7B) on A800, H20, and RTX 4090 GPUs.

## Baselines & Comparisons

CAST outperforms all seven baselines across every task and model configuration tested. Against the closest competitor EAGLE-3, CAST delivers consistent 5–20% relative speedup gains (e.g., 5.18× vs. 4.73× on HumanEval/V13B, 4.83× vs. 4.66× on Alpaca/L33-70B). The advantage over earlier EAGLE variants is more pronounced: CAST achieves 3.98× vs. EAGLE's 2.61× on MT-bench/V13B (+52%) and 3.98× vs. EAGLE-2's 3.02× (+32%). In the batching regime (batch size 8), the gap widens dramatically—EAGLE-2 degrades to 1.01–1.63× while CAST sustains 1.70–3.12×, confirming that ignoring GPU/batch cost is a critical weakness of prior dynamic-tree methods. Against non-tree baselines (SpD, Medusa, PLD, Lookahead), CAST achieves roughly 2× the speedup (e.g., 3.98× vs. SpD's 1.93× on MT-bench). The paper also proves theoretically (Theorem 4.1) that EAGLE-2/3's fixed top-K selection is a special case of CAST's utility-threshold algorithm, unifying the method family.

## Relation to Prior Work

CAST extends the EAGLE-2/EAGLE-3 line of dynamic draft tree speculative decoding by introducing a cost-aware utility maximization framework that jointly determines tree depth, per-layer breadth, and the number of tokens sent to the target model for verification. The key conceptual departure is treating GPU inference time (as a function of batch size, context length, and sequence length) as an explicit cost term in the node selection objective, rather than relying on fixed heuristics or confidence-threshold rules. The paper formally proves that EAGLE-2 and EAGLE-3's selection algorithms are special cases of CAST's Algorithm 1 under a linear cost model, positioning CAST as a strict generalization. The foundational accept/reject verification mechanism is inherited directly from Leviathan et al.'s speculative sampling.

## Why It Matters / Open Questions

The practical significance lies in the batching regime, where prior tree-based methods (especially EAGLE-2) degrade to near-1x or even below-1x speedup at batch size 8–16 due to GPU resource contention, while CAST maintains 2x+ speedup by adaptively shrinking the tree. This addresses a real deployment bottleneck for LLM serving systems that process multiple requests concurrently. A key limitation is the need for hardware-specific precomputed cost lookup tables, which must be regenerated for new GPU types or model sizes, reducing portability. Open questions include whether the utility-maximization framing generalizes to multi-GPU tensor-parallel settings, whether the confidence-as-acceptance-proxy assumption holds under distribution shift, and how the method behaves at very large batch sizes (beyond 32) where the cost model's granularity may become insufficient.
