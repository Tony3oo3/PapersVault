## Problem

Existing adversarial testing frameworks for computer-use agents (CUAs) cannot simultaneously provide a realistic, interactive environment spanning both web and OS interfaces while maintaining safety isolation. Prior work either relies on non-interactive tool-use sandboxes, web-only replicas without OS integration, or VM-based OS environments with unrestricted browser access, leaving a critical gap for evaluating hybrid web-OS attack pathways (e.g., a web injection hijacking an agent into performing a harmful OS action) under realistic threat models.

## Input / Output

The framework consumes screenshot-based observations from CUA agents operating within a hybrid sandbox, along with configurable adversarial scenario parameters (injection content, target files, SQL commands for database modification) and benign task instructions at two specificity levels (General/Specific). Outputs include execution-based Attack Success Rate (ASR) computed via example-specific scripts, a fine-grained LLM-as-a-Judge Attempt Rate (AR) that captures partial adversarial engagement even when the agent fails to complete the harmful action, and benign task Success Rate (SR). Each of the 864 benchmark examples is run three times, with an attack counted as successful if any run succeeds; the Decoupled Eval setting uses pre-processed action sequences to initialize the agent directly at the injection site, while End2End starts from the initial task state.

## Method

REDTEAMCUA constructs a hybrid sandbox by integrating OSWorld's VM-based Ubuntu environment (providing host isolation and snapshot resets) with Docker-based web replicas from WebArena (Forum) and TheAgentCompany (OwnCloud, RocketChat), accessed via HTTP within the VM's browser. Two core features enable systematic adversarial testing: (1) a configurable Adversarial Task Initial State Setup with platform-specific injection scripts that perform direct SQL modifications to platform databases for persistent, reproducible injections, and (2) a Decoupled Eval setting that uses pre-processed actions to place CUAs directly at the injection point, isolating adversarial robustness from navigational capability limitations. RTC-BENCH comprises 864 examples formed by crossing 9 benign goals (Software Installation, System Configuration, Project Setup) with 24 adversarial goals organized by the CIA triad (Confidentiality: data exfiltration via Web→OS→Web; Integrity: file deletion/modification/permission changes via Web→OS; Availability: resource exhaustion and service disruption via Web→OS), each instantiated in two injection modalities (Code and Language) and two instruction specificity levels. Evaluation combines execution-based scripts for ASR with a GPT-4o-based fine-grained judge for AR, and the framework is further validated against four external defenses (LlamaFirewall, PromptArmor, defensive system prompts, Meta SecAlign) and extended to End2End evaluation with newer frontier CUAs (Claude 4.5/4.6 Opus | CUA).

## Results

Under the Decoupled Eval setting, GPT-4o exhibits the highest average Attack Success Rate (ASR) of 66.19% and Attempt Rate (AR) of 92.45%, while Operator achieves the lowest ASR of 7.57% and AR of 14.06%. Claude 3.7 Sonnet | CUA, considered one of the most capable and secure CUAs, still demonstrates a substantial ASR of 42.93%. Under the more realistic End2End setting, Claude 4.5 Opus | CUA shows the highest ASR of 83%, while the strongest-to-date Claude 4.6 Opus | CUA still exhibits a concerning 50% ASR, confirming that CUA threats can already result in tangible risks to users and computer systems.

## Baselines & Comparisons

Among Adapted LLM-based Agents, GPT-4o is the most vulnerable (66.19% ASR, 92.45% AR), substantially outperforming Claude 3.5 Sonnet (41.37% ASR) and Claude 3.7 Sonnet (39.33% ASR) in susceptibility. Among Specialized CUAs, Operator with its built-in safety checks is the most secure at 7.57% ASR, a 58.62% reduction over its base LLM counterpart; however, without checks (simulating inattentive supervision), Operator's ASR jumps to 30.89%. Notably, Claude 3.7 Sonnet | CUA (42.93% ASR) is *more* vulnerable than its base Claude 3.7 Sonnet (39.33% ASR), a +3.66% increase, suggesting the CUA scaffolding may introduce additional attack surface. In the End2End setting, capability improvements amplify risk: Claude 4.5 Opus | CUA reaches 83% ASR (vs. 50% for Claude 3.7 Sonnet | CUA), while the latest Claude 4.6 Opus | CUA reduces this to 50% by detecting injections in 25/50 cases (vs. only 3/50 for Opus 4.5). Across all evaluated defenses (LlamaFirewall, PromptArmor, defensive system prompts, Meta SecAlign), none reduce ASR below ~50% for the most vulnerable agents, underscoring that no current defense provides adequate protection.

## Relation to Prior Work

This paper integrates two established but previously separate evaluation ecosystems—OSWorld's VM-based OS environment and Docker-based web replicas from WebArena and TheAgentCompany—into a single hybrid sandbox for adversarial CUA testing. It departs from prior adversarial frameworks (VWA-Adv, WASP, DoomArena, SafeArena) that were restricted to web-only settings, and from OS-Harm which used a non-isolated browser, by providing a controlled environment that supports cross-environment attack pathways (Web→OS and Web→OS→Web). The Decoupled Eval setting is a methodological departure from prior work that conflates adversarial robustness with navigational capability, and the execution-based ASR evaluator contrasts with OS-Harm's reliance on LLM judges that can themselves be misled by injections.

## Why It Matters / Open Questions

The finding that the most capable CUA (Claude 4.5 Opus) achieves the highest ASR (83%) while the strongest-to-date Claude 4.6 Opus still shows 50% ASR reveals a dangerous capability-safety tradeoff: improving agent capability without proportionally improving defenses amplifies real-world risk. The fact that none of four tested defenses (LlamaFirewall, PromptArmor, defensive system prompts, Meta SecAlign) provided adequate protection underscores that current defense strategies are insufficient for the hybrid web-OS threat surface. Open questions include whether the 83% ASR generalizes beyond the 50-example End2End subset, how defenses should scale with agent capability, and whether the single-injection-point assumption underestimates real-world attack complexity.
