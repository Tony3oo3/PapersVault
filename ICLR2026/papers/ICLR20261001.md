## Problem

Existing web information extraction (WIE) benchmarks rely on static HTML snapshots, but real web pages continuously evolve their layouts and DOM structures, causing performance measured on offline benchmarks to fail to generalize to live websites (the paper documents a 15%+ average F1 degradation). Additionally, prior benchmarks focus exclusively on text extraction, ignoring the common real-world need to extract non-textual data such as images and hyperlinks.

## Input / Output

The system takes a target URL and a free-form natural language query as input, and produces a set of reusable XPaths (one per target attribute) that can be applied to all structurally similar pages in a group to extract attribute values. The live web page is rendered via Playwright at a 1280×1100 viewport and captured as vertical screenshot strips for visual analysis; for non-textual attributes, ground-truth values are the @src (images) or @href (hyperlinks) source attributes. XPaths are generated from the first page in a page group and then applied to all remaining pages in that group for evaluation.

## Method

VGS (Visual Grounding Scraper) is a four-stage agentic framework that mimics human visual search to generate reusable XPaths. Stage 1 uses an LLM to decompose the natural language query into a structured set of target attributes. Stage 2 (Visual Grounding) splits the rendered page into fixed-size vertical screenshot regions and uses a VLM to identify which region contains each attribute, pruning the observation space. Stage 3 (Element Pinpointing) overlays numbered bounding boxes on candidate items within the grounded region using Set-of-Mark Prompting, then the VLM selects the boxes corresponding to the actual target values. Stage 4 (XPath Synthesis) extracts a local HTML segment (the DOM element at each selected box plus neighbors within distance d=2) and feeds it along with the visually marked region to a VLM to synthesize a generalizable XPath. The entire pipeline operates in a zero-shot setting, and the key design principle is sequentially narrowing the observation space from full page → relevant region → specific elements → local HTML context, thereby avoiding the noise inherent in processing raw full-page HTML.

## Results

On LIVEWEB-IE, VGS with GPT-4o achieves the best overall F1 of 48.58%, substantially outperforming the strongest baseline (AutoScraper at 26.76%) by 21.82 points. The advantage is most pronounced on complex multi-attribute tasks: on Type III (single attribute, list values), VGS scores 45.38% F1 versus 9.10% for AutoScraper (+36.28), and on Type IV (multiple attributes, list values), VGS scores 41.50% versus 6.92% (+34.58). Even the best VGS configuration (GPT-4o) remains 38.02 points below human performance (86.60% F1), confirming the benchmark's difficulty. On existing benchmarks (SWDE, Expanded SWDE), VGS also leads all baselines, with the largest gains observed for small open-source models (e.g., Gemma-3-4B: 58.86% vs. 23.56% F1 on SWDE).

## Baselines & Comparisons

VGS consistently outperforms all three baselines (CoT, Reflexion, AutoScraper) across every backbone model and every task type on LIVEWEB-IE. The margin is largest on Type III and Type IV tasks, where the baselines struggle most: with GPT-4o, VGS exceeds AutoScraper by 36.28 F1 on Type III and 34.58 F1 on Type IV, while on the simpler Type I task the gap narrows to roughly 10–18 F1. Among the baselines, AutoScraper is generally the strongest (its DOM-pruning strategy helps on simpler pages), while Reflexion and CoT perform comparably or slightly worse. On the existing SWDE and Expanded SWDE benchmarks, VGS also leads all baselines, with particularly large gains for small models (e.g., Qwen-2.5-7B: 61.88% vs. 32.50% F1 on SWDE), suggesting the vision-grounded approach compensates for weaker language-model capacity. Notably, even the best VGS configuration (GPT-4o, 48.58% F1) trails human performance (86.60%) by 38 points, indicating substantial room for improvement in live-web extraction.

## Relation to Prior Work

This paper extends the web information extraction (WIE) line of work in two key directions: shifting evaluation from static HTML snapshots (SWDE, WEIR, Expanded SWDE) to live websites, and moving from purely HTML-based wrapper generation (AutoScraper, Kaur 2025) to a vision-grounded approach. The VGS framework builds on the reusable-wrapper paradigm but introduces Set-of-Mark Prompting (Yang et al., 2023) for element pinpointing and a multi-stage visual filtering pipeline (attribute identification → visual grounding → element pinpointing → XPath synthesis) that mimics human cognitive processes. The paper explicitly distinguishes itself from general-purpose web agent benchmarks (Mind2Web, WebArena) that focus on multi-page task completion rather than precise information extraction from DOM structures.

## Why It Matters / Open Questions

The paper demonstrates a critical and quantified gap: LLM-based wrapper methods suffer 15%+ F1 degradation when moving from static snapshots to live pages, and even the best VGS configuration (GPT-4o) achieves only 48.58% F1 versus 86.60% for humans, revealing that live-web WIE remains far from solved. The benchmark's scope is limited (15 websites, 8 domains, English-only, temporally stable values), and non-textual extraction (images, hyperlinks) remains a significant weakness across all methods. Open questions include whether the vision-grounded approach generalizes to highly dynamic sites (social media feeds), multilingual contexts, and time-sensitive data, and whether the large human-machine gap can be closed with better visual reasoning or more sophisticated DOM-visual alignment.
