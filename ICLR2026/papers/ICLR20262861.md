## Problem

Existing jailbreak attacks on safety-aligned LLMs typically require access to model weights, pre-training weights, or fine-grained control over the generation process, making them infeasible against proprietary models accessed only through APIs. This paper identifies a new attack surface: even when an aligned LLM refuses a harmful query, over 85% of the tokens in the correct harmful response still appear in the top-5 predicted tokens, meaning the model's harmful knowledge leaks through its log probability output.
![Teaser figure](../imgs/ICLR20262861/cropped_page1_idx0.webp)

## Input / Output

At each generation step, the method consumes the target LLM's top-k token log probabilities (as few as top-5 for API models) along with the accumulated response so far, and produces a single resampled token. For API-calling models where only top-k probabilities are returned, a padding mechanism assigns a fixed offset below the k-th log probability to all other tokens, enabling the full-vocabulary bias computation. The final output is a complete jailbroken text response generated autoregressively, token by token.

## Method

JULI introduces BiasNet, a lightweight 5-layer MLP plug-in (<1% of the target LLM's parameters) that maps token log probabilities to a per-token logit bias, which is added to the original distribution before sampling. The first and last layers are fixed projection layers (token space ↔ hidden space); for open-source models they reuse the LLM's own head matrix and its pseudoinverse, while for API models they use a data-free optimized random initialization with orthogonalized columns. The three middle layers are trained via supervised cross-entropy on just 100 harmful QA pairs from LLM-LAT for 15 epochs. The key mechanism is sparse intervention: KL-divergence analysis shows BiasNet only significantly shifts probabilities at critical positions (typically sentence beginnings, e.g., flipping 'I' to 'Sure'), while preserving the target LLM's distribution elsewhere, effectively acting as a selector that extracts the model's own harmful knowledge rather than generating it independently.

## Results

Under the API-calling setting (the paper's primary contribution), JULI achieves a GPT-evaluated Harmful Score of 4.19 and Harmful Info Score of 3.19 on Gemini-2.5-Pro using only top-5 token log probabilities, substantially outperforming the next-best method FLIP (2.52 / 1.38). Under the open-weight setting on Llama3-8B-INST (AdvBench), JULI reaches a Harmful Score of 4.57 and Harmful Info Score of 3.44, surpassing the strongest baseline ED (4.10 / 3.02) which requires access to an unaligned base model. Against the SOTA circuit-breaker defense (Llama3-8B-CB), JULI achieves a Harmful Info Score of 2.35 on AdvBench, while GCG, WTS, and LINT all fall below 0.8. Inference time is 0.71 s per response, comparable to the base model and ~140× faster than LINT (99.7 s).

## Baselines & Comparisons

JULI outperforms all five baselines on the API-calling setting for Gemini-2.5-Pro: it achieves a Harmful Info Score of 3.19 versus FLIP's 1.38, Naive's 1.21, and Base's 0.06, a gap of roughly 1.8–3.1 points. On the open-weight setting (Llama3-8B-INST, AdvBench), JULI (4.57 / 3.44) beats ED (4.10 / 3.02), LINT (3.77 / 2.25), WTS (2.38 / 1.26), GCG (1.38 / 0.35), and FLIP (2.87 / 0.87) on both Harmful Score and Harmful Info Score. ED is the closest competitor but requires access to an unaligned base model, a resource that is unavailable for proprietary APIs; JULI needs neither model weights nor an unsafe counterpart. Against the circuit-breaker defense, JULI (Harmful Info Score 2.35) substantially exceeds GCG (0.48), WTS (0.42), LINT (0.77), and FLIP (0.50), while ED (3.36) remains higher but again depends on an unaligned model. In the API-compatible variant against the circuit breaker, JULI (API) scores 0.75, still the best among all API-compatible methods (Naive 0.45, FLIP 0.50, Base 0.41). JULI is also ~140× faster than LINT (0.71 s vs 99.7 s per response) and uses fewer than 1% of the target model's parameters (10⁷ trainable vs 10¹⁰ for Shadow Alignment).

## Relation to Prior Work

JULI belongs to the output-centric family of jailbreak attacks (alongside LINT, WTS, and ED) that manipulate the target model's output distribution rather than its inputs or weights. It departs from this lineage in two key ways: (1) it requires no surrogate or unaligned model (unlike WTS/ED) and no adversarial prompt optimization (unlike GCG), instead learning a tiny logit-bias network (BiasNet) from the target LLM's own top-k token log probabilities; and (2) it operates in a black-box API setting where only top-5 log probabilities are accessible, whereas LINT requires top-500 and WTS/ED require full model weights. The conceptual insight—that safety alignment suppresses but does not erase harmful knowledge from the probability distribution—repurposes the introspection idea from interpretability research into an attack primitive.

## Why It Matters / Open Questions

The paper reveals a concrete, previously underappreciated attack surface: the top-k token log probabilities that model vendors already expose as a standard API feature. If confirmed, this means any API returning log probabilities is vulnerable to a lightweight (<1% parameter, 100-example-trained) jailbreak, which has immediate practical security implications for production deployments. Open questions include whether vendors can mitigate this by truncating or perturbing returned log probabilities, whether the attack generalizes to models that do not expose log probabilities at all, and whether the 'Harmful Info Score' (which the authors themselves introduce as more reliable than standard metrics) fully captures the severity of the generated content. The finding that circuit-breaker defenses substantially reduce but do not eliminate the attack (0.75 vs. 2.35 Harmful Info Score) suggests that no single defense is sufficient.
