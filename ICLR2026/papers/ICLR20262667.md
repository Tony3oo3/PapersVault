## Problem

Software issue localization—identifying which files, classes, or functions need modification given a natural language bug report—is critical for automated repair, yet existing approaches face a trade-off: LLM-based agents achieve strong accuracy but incur high latency and cost (~$0.66/example with Claude-3.5) through multi-step reasoning, while traditional code ranking models are efficient but were trained for functionality-matching retrieval rather than the verbose, failure-descriptive queries characteristic of issue reports. No prior work provides a task-specific, single-shot ranking model optimized for this distinct query distribution.

## Input / Output

The system takes a verbose natural language issue description (mean 382.56 tokens, describing observed failures rather than desired functionality) and a codebase of candidate functions as input, and produces a ranked list of code locations at file, module (class), and function granularity. The bi-encoder retriever outputs dense embeddings scored by cosine similarity, while the listwise reranker outputs a permutation of candidate identifiers; during training, only the top-ranked (positive) identifier is supervised, not the full ordering. Evaluation uses Acc@k, requiring all relevant code units to appear within the top-k results.

## Method

SWERANK is a two-stage retrieve-and-rerank framework. The retriever (SWERANKEMBED) is a bi-encoder trained with InfoNCE contrastive loss on SWELOC, a new dataset of 67,341 (issue, modified-function) pairs from 3,387 Python repositories, where hard negatives (top-15 most similar unmodified functions) and top-K=20 consistency filtering ensure training quality. The reranker (SWERANKLLM) is a listwise LLM that receives the issue description plus top-K retrieved candidates with assigned identifiers and predicts the ranking; the key training modification is that only the first generated token (the positive's identifier) is supervised via cross-entropy, since SWELOC lacks ground-truth ordering among negatives. Small variants (137M retriever, 7B reranker) are initialized from CodeRankEmbed and CodeRankLLM respectively, while large variants (7B retriever, 32B reranker) use GTE-Qwen2-7B-Instruct and Qwen2.5-32B-Instruct, all fine-tuned on SWELOC.

## Results

On SWE-Bench-Lite, SWERANKLLM-LARGE (32B) achieves 83.21% File Acc@1, 90.88% Module Acc@5, and 81.39% Function Acc@5, setting new state-of-the-art across all granularities and outperforming the best agent-based system (LocAgent + Claude-3.5: 77.74% File Acc@1, 86.50% Module Acc@5, 73.36% Function Acc@5). On LocBench, SWERANKLLM-LARGE reaches 86.61% File Acc@5 and 71.25% Function Acc@10, surpassing LocAgent + Claude-3.5 (83.39% File Acc@5, 59.29% Function Acc@10). In terms of cost-efficiency, SWERANKLLM (7B) costs only $0.011 per instance versus $0.66 for LocAgent + Claude-3.5, yielding up to 6× better performance-cost tradeoffs.

## Baselines & Comparisons

SWERANK outperforms all four agent-based baselines (MoatlessTools, SWE-Agent, OpenHands, LocAgent) across every granularity on both SWE-Bench-Lite and LocBench; the largest gap is at function level, where SWERANKLLM-LARGE achieves 81.39% Acc@5 versus 73.36% for LocAgent + Claude-3.5 (an 8-point margin). Among retriever baselines, SWERANKEMBED-SMALL (137M) surpasses the much larger GTE-Qwen2-7B-Instruct (7B) on Function Acc@10 (74.45% vs. 70.44%), and SWERANKEMBED-LARGE leads all retrievers by 5–11 points over prior code embedding models. For reranking, SWERANKLLM-LARGE (32B) edges out GPT-4.1 on Function Acc@10 (88.69% vs. 87.96%) while being fully open-source and 10× cheaper ($0.015 vs. $0.16 per instance). The cost-efficiency advantage is stark: SWERANKLLM (7B) achieves an Acc@10/Cost ratio of 79.0 compared to 1.2 for LocAgent + Claude-3.5, a 66× improvement. On LocBench, the gap widens further for function-level localization (71.25% vs. 59.29% for LocAgent), suggesting SWERANK generalizes better to security and performance issues beyond bug reports.

## Relation to Prior Work

SWERANK builds directly on the code ranking lineage established by CodeRankEmbed/CodeRankLLM (Suresh et al., 2024) and the listwise LLM reranking paradigm of RankZephyr (Pradeep et al., 2023), but departs from both by training exclusively on task-specific issue-localization data (SWELOC) rather than generic NL-to-code or code-to-code retrieval corpora. Conceptually, the paper positions itself against the dominant agentic framing of issue localization (SWE-Agent, OpenHands, LocAgent), arguing that the verbose, failure-descriptive nature of bug reports makes single-shot ranking more appropriate than multi-step tool-use exploration. The SWELOC dataset itself extends the data construction methodology of CodeRankEmbed (consistency filtering, hard-negative mining) to the issue-localization domain, where queries are substantially longer and semantically more distant from the target code.

## Why It Matters / Open Questions

The practical impact is significant: SWERANK achieves SOTA localization at roughly 1/50th the inference cost of agent-based systems, making automated issue localization feasible at scale for teams that cannot afford per-instance API costs of closed-source LLMs. The SWELOC dataset (67K instances from 3,387 repositories) is a reusable resource that demonstrably improves multiple off-the-shelf retrievers and rerankers, lowering the barrier for future work in this area. Open questions include whether the single-shot ranking formulation can handle extremely complex issues spanning many files (where all methods drop to single-digit accuracy), whether the approach generalizes beyond Python, and whether the gap to oracle localization (24.5% vs 25.9% repair pass rate) will narrow as code-editing models improve.
