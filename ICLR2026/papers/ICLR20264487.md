## Problem

Existing backward token filtering in LLM training reduces the number of tokens processed but yields only ~1.2% end-to-end speedup because (1) sparsity fails to propagate beyond the output layer—dense activations in attention blocks re-densify gradients—and (2) the 30–50% sparsity range produced by token filtering falls far below the >95% threshold where existing sparse GEMM libraries become effective, making them counterproductive. The paper asks whether token filtering's full efficiency potential can be unlocked while preserving its utility benefits.

## Input / Output

The method consumes a loss tensor and a binary filter mask (derived by comparing target-model loss against a reference-model loss per token) at the output layer, then operates on the model's backward computation graph. It produces a dimension-reduced computation graph in which the sequence dimension is globally shrunk to only the retained tokens, along with correspondingly filtered gradients. The key constraint is that the graph must be updated in-place before backpropagation begins, and the system must handle the dynamic, node-heterogeneous structure of PyTorch's autograd graph (300+ node types) without static per-model rules.

## Method

CENTRIFUGE combines an algorithm-level and a system-level design. At the algorithm level, it introduces a modified attention backward kernel that splits the FlashAttention backward pass into two sub-computations: ∂K and ∂V are computed using only the filtered (retained) Q, K, V activations, while ∂Q is computed using the full unfiltered activations, thereby amplifying sparsity without the interference that harms ∂Q in naive strawman approaches. At the system level, it transforms the resulting row/column-sparse GEMMs into dimension-reduced dense GEMMs by automatically updating the backward computation graph: an offline phase traverses the graph with synthetic inputs to enumerate node types and generate skeleton update code, and an online phase uses prime-number markers on batch size and sequence length to disambiguate which dimensions to shrink, then caches the resolved update rules for subsequent iterations. The entire integration requires a single call—centrifuge.ops.backward_filter(loss, filter_mask)—in systems already performing backward token filtering.

## Results

On nine math-reasoning and general-knowledge tasks using TinyLlama-1.1B, CENTRIFUGE (filtering 50% tokens) achieves an average score of 27.3, outperforming regular fine-tuning (17.8) by 9.5% and the no-fine-tuning baseline (13.7) by 13.6%. The largest single-task gain is 26.6% on MAWPS (62.8 vs. 36.2). In terms of efficiency, filtering 50% of tokens reduces backward computation time by 40.0%–49.9% and end-to-end training time by 17.9%–34.7% across models from 1.1B to 40B parameters, with the largest end-to-end speedup (34.7%) observed on Qwen3-14B with TP=8.

## Baselines & Comparisons

CENTRIFUGE is compared against two baselines: (1) regular fine-tuning without token filtering, and (2) backward token filtering that only filters the loss at the output layer (Lin et al., 2024). On model utility, CENTRIFUGE outperforms regular fine-tuning by 9.5% on average across nine tasks, with the largest margin of 26.6% on MAWPS (62.8 vs. 36.2) and 16.3% on SVAMP (35.5 vs. 19.1). Compared to the loss-only filtering baseline of Lin et al., CENTRIFUGE preserves identical utility (same filtered-token selection) while unlocking a 40–50% backward speedup that the baseline cannot achieve due to inadequate sparsity propagation. The strawman approach of naively filtering softmax activations fails entirely, producing non-converging training loss, confirming that CENTRIFUGE's separate processing of ∂Q and ∂K/∂V is essential for correctness.

## Relation to Prior Work

CENTRIFUGE builds directly on the backward token filtering formulation of Lin et al. (NeurIPS 2024), which showed that filtering low-importance tokens at the output layer improves model utility by up to 30%. However, it departs from that work by identifying two critical system-level gaps: the sparsity from loss filtering does not propagate beyond the first attention block, and the 30–50% sparsity range is incompatible with existing sparse GEMM implementations that require >95% sparsity. The algorithmic contribution reorganizes the FlashAttention (Dao et al., 2022) backward kernel into two separate computations to independently handle ∂K/∂V (with filtered activations) and ∂Q (with full activations), while the system contribution transforms the resulting sparse operations into dimension-reduced dense GEMM via automatic computation-graph rewriting.

## Why It Matters / Open Questions

The practical impact is substantial: up to 49.9% backward and 34.7% end-to-end training time reduction at 50% filtering, with a one-line integration into existing pipelines already using token filtering. This makes token filtering a genuinely efficient technique rather than a utility-only improvement, which could accelerate the adoption of selective training at scale. Open questions include how token filtering interacts with MoE load balancing (filtered token counts may vary across experts), whether the approach extends to forward filtering for long-sequence training, and whether the utility gains generalize beyond the math-reasoning domain used in evaluation.
