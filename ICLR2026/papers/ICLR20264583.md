## Problem

Existing agent benchmarks like GAIA are rapidly saturating, with top agents exceeding 90% accuracy, making them unable to differentiate state-of-the-art systems. Manual task creation is prohibitively expensive, and conventional automated evolution methods (rule-based parameter mutation, simple scaling) fail for agent tasks because minor perturbations can break solvability in dynamic environments while merely increasing repetition rather than genuine reasoning depth. The paper addresses the need for a scalable, automated framework that fundamentally increases the procedural, logical, and semantic complexity of agent tasks while preserving verifiability.

## Input / Output

The framework takes a seed task (question) from an existing benchmark, optionally accompanied by its known solution trajectory, and produces a pair: an evolved task question with a single deterministic answer, plus a complete validatable execution trajectory recording every reasoning step, tool invocation, and environment observation. The trajectory is treated as a first-class artifact rather than a byproduct—it is the substrate from which the evolved problem is reconstructed via inverse problem creation, and it serves as the ground-truth evidence for all downstream validation. The evolved task inherits the original benchmark's evaluation interface (e.g., GAIA's answer-verification format) without modification.

## Method

TRACE is a three-stage multi-agent pipeline operating entirely at test time with no training. Stage 1 (Evolutionary Proposal Mining) performs bottleneck-aware analysis of the seed task's solution trajectory to identify where solvers face intrinsic difficulty, then generates diverse evolution proposals that target specific capability dimensions (longer evidence chains, deeper tool integration, cross-domain transfer). Stage 2 (Exploration and Trajectory Recording) has the Exploration Executor follow the original solution path and inject proposals at intermediate steps as controlled 'forks in the road,' exploring with full tool access in real-world environments; it then formulates the new problem description post-hoc from the recorded trajectory (inverse problem creation), ensuring the answer is deterministic and the task is well-posed. Stage 3 (Multi-Level Validation) applies step-by-step replay to confirm reproducibility of every tool call, a global logical-coherence audit, a theory-of-mind-inspired difficulty assessment comparing seed vs. evolved trajectories, and a trajectory-agnostic blind solver that must fail to solve the task within budgeted attempts to confirm a genuine difficulty floor. The key architectural insight is that the product of evolution is not the problem alone but the (evolved problem, validatable trajectory) pair, and that test-time computation is allocated to exploring and validating harder tasks rather than refining answers.

## Results

On the GAIA benchmark, all four evaluated models (DeepSeek-V3.1, Gemini-2.5-Flash, Kimi-K2, GPT-5-Mini) exhibit significant Pass@1 degradation after TRACE evolution, with total accuracy drops ranging from 6.3% (Kimi-K2, Round 1) to 28.1% (GPT-5-Mini, Round 2). The most dramatic single-level drop is Gemini-2.5-Flash on Level 1, falling from 47.1% to 4.0% (−43.1%) after Round 2. On AIME-2024, Qwen3-235B-A22B's average accuracy drops from 94.0% to 71.67% (−22.33%) after four evolution rounds, while its average token length increases by over 8,000 tokens, confirming that evolved tasks demand substantially longer reasoning chains.

## Baselines & Comparisons

This paper does not compare TRACE against competing benchmark-evolution methods; instead, the 'baseline' is the original (Round 0) benchmark, and the comparison is model performance on original vs. TRACE-evolved tasks. All four GAIA models degrade on evolved tasks, with GPT-5-Mini showing the largest total drop (−21.3% in Round 1, −28.1% in Round 2) and Gemini-2.5-Flash the steepest Level-1 collapse (−43.1% in Round 2). Kimi-K2 is the most resilient, with only a −6.3% total drop in Round 1, though it still loses 29.7 points on Level 1 in Round 2. On AIME-2024, all three reasoning models (7B, 32B, 235B) degrade after four evolution rounds, with the largest model (Qwen3-235B) dropping 22.33% in accuracy while generating 8,018 more tokens on average. The consistent pattern—longer reasoning chains paired with lower accuracy—indicates that TRACE introduces genuine difficulty rather than noise, and that no current model can simply scale up its test-time compute to recover original performance levels.

## Relation to Prior Work

TRACE departs from prior benchmark evolution work (Benchmark Self-Evolving, AutoEvoEval, EvoCodeBench) that relies on predefined atomic operations, rule-based perturbations, or scheduled data refreshes, instead using autonomous test-time exploration in live real-world environments to generate evolved tasks. It repurposes the test-time scaling paradigm (Muennighoff et al., 2025) from answer refinement to benchmark construction, and extends trajectory-based evaluation (WebArena, Mind2Web) from scoring to serving as the evolutionary substrate itself. The 'inverse problem creation' principle—defining a problem post hoc from a verified solution trajectory—distinguishes TRACE from both static curation and template-based mutation approaches.

## Why It Matters / Open Questions

TRACE addresses the urgent saturation problem in agent benchmarks by providing a scalable, automated pipeline that produces trajectory-validated tasks of increasing difficulty, potentially replacing labor-intensive manual curation. The emergent 'From Seed to Spark' capability transposition (e.g., retrieval → math + coding) suggests the framework can probe capability boundaries in ways static benchmarks cannot, though this is demonstrated with limited examples rather than systematic analysis. Key open questions include the computational cost-difficulty trade-off (acknowledged but unquantified), the absence of a feedback loop from validator signals back to the proposer/executor, and the lack of comprehensive human auditing over all generated tasks.
