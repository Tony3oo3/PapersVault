## Problem

Scaling end-to-end online RL for computer use agents remains infeasible due to three compounding obstacles: GUIs are inherently human-centric and inefficient for machine agents, behavior cloning is limited by teacher-model ceilings and poor generalization, and RL training in desktop environments suffers from entropy collapse and KL divergence accumulation that cause premature convergence after only hundreds of steps. No prior work has demonstrated a scalable, stable RL pipeline capable of training a 9B-parameter agent to state-of-the-art desktop automation performance.

## Input / Output

For the text model (GLM-4-9B), the observation includes a structured accessibility tree (tag, text, center coordinates, width/height per element), a window list with IDs and titles, the current application name, and the previous action's feedback string. For the multimodal model (GLM-4.1V-9B-Thinking), the a11y tree is replaced by a 1280×720 screenshot (downsampled from 1920×1080). The agent outputs a single line of Python code per turn, calling either one of 10 basic GUI primitives (click, type, scroll, drag_and_drop, hotkey, etc.) or one of 103 application-specific APIs (e.g., CalcTools.set_cell_value), preceded by a thinking block. Each code block is context-independent—no variables persist across turns—and the agent must call Agent.exit(success=True/False) to terminate.

## Method

COMPUTERRL introduces three coupled innovations. First, the API-GUI paradigm unifies an LLM-automatically-generated ecosystem of 103 application-specific Python APIs (for LibreOffice, Chrome, VLC, Code) with standard GUI actions, letting the agent bypass fragile click sequences with direct programmatic calls and reducing task completion to at most 1/3 of the steps needed by GUI-only baselines. Second, a distributed RL infrastructure deploys thousands of lightweight KVM/QEMU Ubuntu VMs (2 cores, 4 GB each) across a 7-node CPU cluster via gRPC, integrated with the AgentRL framework for fully asynchronous rollout collection and FSDP-based training on 128 H800 GPUs. Third, the training algorithm uses step-level GRPO with binary verifiable rewards (1 for each correctly formatted action in a successful trajectory, 0 otherwise), followed by Entropulse—a strategy that periodically interrupts RL to perform SFT on a curated set of ~130k successful rollouts collected from heterogeneous policies across training steps, restoring action entropy and enabling a second RL phase that yields an additional +3.8% over the first RL phase. The full pipeline is: BC cold start on 180k+ multi-LLM trajectories → RL Phase 1 (180 steps) → Entropulse SFT → RL Phase 2 (to 360 steps), achieving 48.9% on OSWorld with a 9B model.

## Results

GLM-COMPUTERRL-9B (built on GLM-4.1V-9B-Thinking) achieves a new state-of-the-art 48.9% success rate on OSWorld and 48.0% on OSWorld-Verified, outperforming all prior proprietary and open agents. On the OfficeWorld benchmark (Word, Excel, PPT), it reaches 43.3% average, surpassing the strongest baseline (OpenAI o3 at 33.9%) by 9.4 points. The API-GUI paradigm enables task completion in at most 1/3 the steps of the strongest baselines, and end-to-end RL training yields a 66% relative performance gain over the behavior-cloning-only baseline.

## Baselines & Comparisons

COMPUTERRL outperforms every compared baseline on OSWorld. Among proprietary agents, it beats OpenAI CUA o3 (42.9%) by 6.0 points, UI-TARS-1.5 (42.5%) by 6.4 points, AgentS2 w/Gemini-2.5-Pro (41.4%) by 7.5 points, and Claude 4.0 Sonnet (30.7%) by 18.2 points. Among open models, it surpasses the strongest open baseline UI-TARS-7B-1.5+ARPO (29.9%) by 19.0 points and Jedi-7B w/GPT-4o (27.0%) by 21.9 points, despite using only 9B parameters versus 72B for several competitors. On OfficeWorld, COMPUTERRL (43.3% avg) outperforms OpenAI o3 (33.9%) by 9.4 points, GPT-4.1 (25.0%) by 18.3 points, and Claude 4.0 Sonnet (24.4%) by 18.9 points, with particularly large gains in Excel (58.3% vs. 36.7% for o3). The ablation further shows the API-GUI paradigm alone (with GPT-4o) yields a 134% improvement over GUI-only interaction (26.2% vs. 11.2%), and the full training pipeline (BC → RL → Entropulse → RL) progressively lifts performance from 15.2% (untrained) to 45.8% on the Qwen2.5-14B ablation model.

## Relation to Prior Work

This paper extends GRPO (Shao et al., 2024) from trajectory-level to step-level policy optimization for multi-turn agent tasks, and builds its asynchronous training loop on the AgentRL framework (Zhang et al., 2025). It departs from the dominant pure-GUI interaction paradigm (UI-TARS, OpenAI CUA, Claude) by introducing an API-GUI hybrid action space that unifies programmatic API calls with mouse/keyboard operations, addressing what the authors frame as a fundamental mismatch between human-oriented interfaces and machine agents. The Entropulse strategy for combating entropy collapse in extended RL training is positioned as an alternative to DAPO's adaptive clipping, instead using periodic SFT on previously collected successful rollouts to restore exploratory capacity.

## Why It Matters / Open Questions

Achieving 48.9% on OSWorld with a 9B open model—surpassing all proprietary systems including OpenAI CUA o3 (42.9%) and Claude Sonnet 4 (30.7%)—demonstrates that end-to-end RL with the right infrastructure can close the gap to closed-source agents. The API-GUI paradigm and Entropulse technique are likely to be broadly adopted: the former offers a practical efficiency gain (1/3 fewer steps) applicable to any desktop agent, while the latter provides a general recipe for extending RL training beyond the entropy-collapse plateau. Open questions remain around long-horizon multi-app coordination, generalization to unseen applications, and safety/alignment for autonomous desktop control, all of which the authors acknowledge as future directions.
