## Problem

Current RL research for LLMs has largely focused on single-turn tasks (e.g., math QA), where algorithms like GRPO work well but are fundamentally inapplicable to full multi-turn settings with dense per-turn rewards and arbitrary discount factors. There is no standardized, open-source environment framework analogous to OpenAI-Gym that provides a unified agent-environment interface, diverse multi-turn environments, and tool integration for training and evaluating agentic LLMs.

## Input / Output

The agent receives environment observations that can be configured via wrappers (most recent output, full action-observation history, or parsed/summarized versions), optionally augmented with images for vision-language tasks. The agent produces a full response (reasoning + action) per turn, which is parsed to extract the action; the environment returns a per-turn reward, next observation, and termination flag. Episodes can span 100+ turns with tool calls (Python execution, web search, MCP server calls) interleaved, and the framework supports asynchronous vectorized execution to collect batches of episodes in parallel.

## Method

GEM provides a standardized Gym-like interface (reset/step) with asynchronous vectorized environments, autoreset for continuous data generation, and modular observation/action wrappers, spanning seven task categories (math, code, games, QA, ReasoningGym, terminal, vision-math) and three tool types (Python, Search, MCP). The key algorithmic contribution is REINFORCE with Return Batch Normalization (ReBN), which normalizes per-transition Monte Carlo returns across the entire batch of transitions rather than using a learned critic or group-based advantage estimation. Unlike GRPO, ReBN is fully compatible with dense per-turn rewards and arbitrary discount factors γ≤1, enabling fine-grained credit assignment in multi-turn settings. The paper benchmarks REINFORCE+ReBN against GRPO, PPO, and vanilla REINFORCE across eight environments, showing ReBN consistently outperforms or matches all baselines without requiring critic learning or extensive rollouts, and demonstrates that γ<1 is essential for recovering optimal strategies (e.g., binary search in GuessTheNumber).

## Results

On math benchmarks (Table 1), Qwen3-4B-Base+RL with Python tool achieves an average score of 49.8 across AIME24, AMC, MATH500, MinervaMath, and OlympiadBench, up from 35.3 for the base model without tools. On QA benchmarks (Table 2), the same model with Search tool and RL training reaches 45.5 average across seven datasets (NQ, TriviaQA, PopQA, HotpotQA, 2Wiki, Musique, Bamboogle), compared to 10.2 for the base model. In the algorithm benchmarking across eight GEM environments (Figure 4), REINFORCE+ReBN consistently outperforms or matches PPO and GRPO, with the largest gaps in multi-turn environments where GRPO's constant advantage estimation degrades performance. The discount factor study shows γ=0.9 drives convergence to the optimal binary-search strategy (~5.6 turns) in GuessTheNumber, while γ=0.999 fails to minimize turns.

## Baselines & Comparisons

REINFORCE+ReBN (the proposed method) outperforms GRPO in all multi-turn environments (GuessTheNumber, Sudoku, QA, Math) where dense per-turn rewards are available, because GRPO assigns a single trajectory-level advantage to all turns, resulting in poor credit assignment. Against PPO, REINFORCE+ReBN matches or exceeds performance across all eight benchmarked environments without requiring a learned critic, which PPO needs but struggles to train reliably (evidenced by PPO's poor performance on Minesweeper). Compared to vanilla REINFORCE, ReBN provides consistent and substantial improvements by normalizing Monte Carlo returns over the batch, addressing the sensitivity of raw returns to reward shaping that causes suboptimal convergence in environments like Sudoku. In the tool-integration experiments, the combination of RL training and tool access (Python for math, Search for QA) yields the largest gains over any single intervention, with the math average improving from 35.3 (base, no tool) to 49.8 (RL + tool) and the QA average from 10.2 to 45.5. The paper positions REINFORCE+ReBN as the strongest baseline that avoids the computational overhead of critic learning (PPO) or group sampling (GRPO), making it the most practical choice for multi-turn agentic RL.

## Relation to Prior Work

GEM is explicitly modeled on OpenAI Gym (Brockman et al., 2016), providing a standardized environment-agent interface for LLM RL analogous to what Gym did for traditional RL. Algorithmically, the paper extends REINFORCE (Williams, 1992) with Return Batch Normalization (ReBN) to handle multi-turn dense rewards, positioning itself against the dominant GRPO (Shao et al., 2024) which the authors show is fundamentally limited to single-turn or trajectory-level reward settings. The paper also departs from the single-sequence formulation used by prior tool-integrated RL work (SkyRL-v0, Search-R1, ReTool, SimpleTIR) by collecting trajectories as individual transitions, preserving compatibility with per-turn rewards and arbitrary discount factors. On the training side, GEM integrates with five existing frameworks (Oat, Verl, OpenRLHF, ROLL, RL2) rather than proposing a new training system.

## Why It Matters / Open Questions

GEM addresses a critical infrastructure gap: prior agentic RL research relied on bespoke, tightly-coupled environment code, making fair algorithm comparison nearly impossible. By providing 24+ standardized environments, a unified interface, and validated baselines, GEM enables the kind of systematic algorithm benchmarking that drove traditional RL progress. The finding that a simple normalization trick (ReBN) matches or beats PPO without a learned critic, and that GRPO's constant-advantage estimation is a fundamental (not just practical) limitation for multi-turn credit assignment, provides clear algorithmic guidance. Open questions include the robustness of critic learning in LLM settings (PPO's inconsistent performance), whether ReBN scales to very long horizons, and how multi-agent co-evolution (demonstrated on TAU-bench) can be made to converge reliably.
