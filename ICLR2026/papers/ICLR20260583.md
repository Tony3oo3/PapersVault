## Problem

Existing LLM cyber-exploitation benchmarks operate under a 'presumption of guilt,' presenting single-host, pre-identified vulnerabilities without benign distractors or active defenses, making them unable to measure whether agents can perform realistic end-to-end penetration testing. This paper asks whether current frontier LLMs can autonomously discover, exploit, and chain vulnerabilities in complex multi-host networks protected by production-grade WAFs.
![Teaser figure](../imgs/ICLR20260583/cropped_page1_idx0.webp)

## Input / Output

The agent receives a containerized network environment (1–N hosts with real CVEs, optionally behind a WAF) and a task prompt to capture dynamically generated flags. It interacts with the environment through MCP-integrated security tools (Burp Suite, Linux shell, dirb, sqlmap) and local commands, with a step budget of 80 (A-CVE) or 150 (other scenarios). Success is verified by retrieving a cryptographically unique flag string placed in a host-specific location (file or database entry), which prevents hallucinated success; the final output is a weighted PACEbench score across four scenario categories plus a full audit trail of thoughts, actions, and tool outputs.

## Method

PACEbench constructs 32 environments across four escalating scenarios: A-CVE (single real CVE on one host, difficulty quantified by human pass rate from 30%–86%), B-CVE (blended vulnerable and benign hosts requiring reconnaissance), C-CVE (chained exploitation requiring lateral movement and privilege escalation across a segmented network), and D-CVE (vulnerable host behind a production-grade WAF—ModSecurity CRS, Naxsi, or Coraza—requiring novel bypass). PACEagent emulates a human penetration tester via a three-phase workflow (reconnaissance → analysis → exploitation) orchestrated by a phase manager, with an LLM Core for strategic reasoning, a Tool Module routing between local and MCP-external tools, and a Memory Module with LLM-based summarization to manage long-horizon context. Evaluation uses a Pass@5 protocol with a weighted scoring formula (w_A=0.2, w_B=0.3, w_C=0.3, w_D=0.2) that grants partial credit for intermediate flags in multi-stage attacks, tested across seven frontier models (Claude-3.7-Sonnet, GPT-5-mini, Gemini-2.5-Flash, o4-mini, DeepSeek-V3, DeepSeek-R1, Qwen3-32B).

## Results

On PACEbench, the best-performing model (Claude-3.7-Sonnet with PACEagent) achieves a weighted PACEbench Score of 0.241, with per-category scores of 0.412 (A-CVE), 0.263 (B-CVE), 0.267 (C-CVE), and 0.000 (D-CVE). No model successfully bypasses any WAF defense (all D-CVE scores are 0.000), and open-source models (DeepSeek-V3, DeepSeek-R1, Qwen3-32B) score at most 0.024, with DeepSeek-R1 achieving 0.000 across all scenarios. Performance degrades sharply as environmental complexity increases: models that exploit a CVE in isolation (A-CVE) frequently fail when the same CVE is embedded in a multi-host environment with benign distractors (B-CVE) or chained dependencies (C-CVE).

## Baselines & Comparisons

The paper compares PACEagent against the CAI framework (Mayoral-Vilches et al., 2025), both using Claude-3.7-Sonnet as the LLM core. PACEagent outperforms CAI by 0.18 in A-CVE, 0.05 in B-CVE, and 0.20 in C-CVE, yielding an overall 65.2% improvement in PACEbench Score. The gains are most pronounced in C-CVE (chained exploitation), where PACEagent's structured three-phase workflow (reconnaissance → analysis → exploitation) and MCP-based tool orchestration enable more effective lateral movement. The trade-off is a 28% increase in token consumption, attributed to PACEagent's more granular multi-stage decomposition. The paper also positions PACEbench against five prior benchmarks (Google-CTF, Cybench, CVE-Bench, AutoPenBench, MHbench) in Table 1, highlighting that PACEbench is the only one to include both multi-host environments and active WAF defenses, though no head-to-head numerical comparison across benchmarks is performed.

## Relation to Prior Work

This paper synthesizes and extends several prior benchmarking efforts (CTF-style challenges like Google-CTF and Cybench, real-world CVE exploitation like CVE-Bench, and multi-host network attacks like MHbench) into a unified framework that simultaneously addresses three dimensions prior work handled in isolation: graded vulnerability difficulty, environmental complexity with benign distractor hosts, and active cyber defenses (WAFs). The PACEagent architecture builds on the ReAct loop paradigm but introduces a structured three-phase workflow (reconnaissance, analysis, exploitation) and MCP-based tool orchestration, departing from the monolithic agent designs in CAI and similar frameworks. The flag-based verification mechanism is inherited from CTF tradition, but its application to multi-host, defended environments is novel.

## Why It Matters / Open Questions

PACEbench provides the first systematic evaluation showing that no current frontier LLM can bypass production-grade WAFs, establishing a concrete 'safety red line' for AI cyber capability assessment that prior benchmarks lacked. The benchmark is currently limited to 32 web vulnerabilities and a single WAF-per-challenge setup, so its generalizability to binary exploitation, active defenses (IDS/IPS, honeypots), and larger-scale networks remains an open question. The finding that agent capabilities track human difficulty ratings (with notable exceptions where LLMs outperform humans on certain CVEs) suggests a useful calibration metric for future model releases, but the small dataset size limits statistical confidence. The dual-use nature of the work raises ongoing questions about responsible release timing and whether public benchmarks accelerate or mitigate offensive capability development.
