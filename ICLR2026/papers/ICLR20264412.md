## Problem

In model-heterogeneous federated learning, clients with diverse, incompatible architectures cannot aggregate parameters, so traditional generalization-improving methods (regularization, dynamic weighting) become inapplicable. Existing data-free alternatives either require a public dataset, only regularize part of the local model (feature-space distillation fixes only the classifier; prototype sharing fixes only the backbone), or incur prohibitive communication and memory costs from transmitting overparameterized proxy models. No prior method simultaneously debiases both the feature extractor and classifier while maintaining communication and memory efficiency.

## Input / Output

Each client holds non-IID image data (28×28 grayscale for MNIST, 32×32 RGB for CIFAR-10/100, 64×64 RGB for Tiny-ImageNet) and trains a local ResNet (18/34/50/101/152) that maps images to class labels. The VTC generator consumes low-dimensional Gaussian latent variables sampled from N(c^y, Σ) — where c^y is the aggregated global class prototype and Σ is a diagonal covariance from the global standard deviation — and upsamples them into full-resolution synthetic images. During communication, clients upload only p-dimensional prototypes and a p-dimensional SD vector (not model weights), and the server broadcasts aggregated prototypes, SD, and a single global VTC model.

## Method

FedVTC equips each client with a 4-layer variational transposed convolutional (VTC) network that generates synthetic samples from Gaussian latent variables via the reparameterization trick (v = z + σ_k ⊙ ε). The VTC is trained with a composite loss L_tc = L_e + λ·L_dm, where L_e is the standard negative ELBO (reconstruction loss plus KL-divergence against the global class prototype) and L_dm is a distribution-matching loss that penalizes the feature extractor's output on generated samples for deviating from the global prototype, thereby ensuring high-quality synthetic data. Clients share only class-wise prototypes and standard deviations with the server (not parameters), and the server aggregates them by averaging. After FL convergence, all local VTCs are averaged into a global VTC, which each client uses to generate S synthetic samples per class for isolated fine-tuning of its local model. An alternating training schedule (freeze VTC while updating the local model, then freeze the local model while updating the VTC) keeps peak memory equivalent to training the local model alone, and the VTC is transmitted only once rather than every round to minimize communication.

## Results

FedVTC achieves the highest generalization accuracy across all four datasets and both Dirichlet distributions. On MNIST (Dir 0.1), it reaches 88.7% vs. the best baseline pFedAFM at 85.6%; on CIFAR-10 (Dir 1.0), it attains 51.7% vs. FedTGP's 42.1%; on CIFAR-100 (Dir 1.0), it scores 40.4% vs. pFedAFM's 34.9%; and on Tiny-ImageNet (Dir 1.0), it achieves 35.8% vs. FedType's 31.6%. FedVTC also reports the lowest total communication cost (e.g., 0.70 GB on MNIST vs. 46.61 GB for CCVR) and equivalent or lower memory consumption than all baselines.

## Baselines & Comparisons

FedVTC outperforms all six baselines on every dataset and Dirichlet setting. Against the closest competitors, the margins are substantial: on CIFAR-10 (Dir 1.0), FedVTC leads FedTGP (42.1%) by 9.6 points and pFedAFM (40.5%) by 11.2 points; on CIFAR-100 (Dir 1.0), it surpasses pFedAFM (34.9%) by 5.5 points and FedType (34.4%) by 6.0 points. On Tiny-ImageNet (Dir 1.0), FedVTC beats FedType (31.6%) by 4.2 points, the largest gap on that dataset. The representation-based distillation methods (FedGen, CCVR) consistently underperform, with CCVR incurring 46–923 GB of communication versus FedVTC's 0.7–53 GB. FedProto and FedTGP, which only share prototypes, trail FedVTC by 3–10 points, confirming that fine-tuning with synthetic samples debiases both the feature extractor and classifier rather than just one component.

## Relation to Prior Work

FedVTC builds on three distinct lines of work: the VAE framework (Kingma & Welling, 2013) for its ELBO-based training and reparameterization trick; FedProto (Tan et al., 2022) for its class-wise prototype aggregation scheme used as the KL-divergence target; and the distribution matching loss from dataset condensation (Zhao et al., 2023) as a regularizer. Conceptually, it departs from the dominant model-heterogeneous FL paradigm of knowledge distillation (FedGen, CCVR) and prototype sharing (FedProto, FedTGP) by instead generating full synthetic samples via a transposed convolutional network and fine-tuning entire local models, thereby debiasing both feature extractors and classifiers rather than just one component. It also avoids the heavy proxy-model communication of FedType by using a lightweight VTC that is transmitted only once.

## Why It Matters / Open Questions

FedVTC addresses a practically important gap: in real IoT and edge deployments, clients often run entirely different architectures, making parameter aggregation impossible. The framework's communication efficiency (lower than prototype-only methods despite transmitting additional SDs and VTC parameters) and memory efficiency (via alternating training) make it more deployable than proxy-model alternatives. Open questions include whether the approach generalizes to non-image modalities, how it performs under extreme data heterogeneity beyond Dirichlet splits, and whether the synthetic-data fine-tuning stage can be made adaptive per client rather than uniform. The authors also note the additional computation cost of VTC training as a limitation to be addressed with early-stopping.
