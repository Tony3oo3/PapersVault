## Problem

Existing deep search agents fail to achieve consistent test-time search scaling: sequential single-query methods hit an information bottleneck because each step retrieves only one piece of evidence, while parallel multi-query methods lack structured aggregation of retrieved evidence, leading to premature termination. The paper asks what search strategy enables genuine, monotonic performance improvement as additional search turns or API calls are allocated.
![Teaser figure](../imgs/ICLR20261322/cropped_page1_idx2.webp)

## Input / Output

The model takes a natural-language multi-hop question as input and produces a final answer through iterative reasoning-query-retrieval loops. Within each loop, the model emits one or more search queries (parallel queries are separated by semicolons within a single turn), executes them via a web search API, and receives summarized documents (produced by an external Qwen3-32B summarizer) wrapped in special tokens. The model may repeat this cycle across multiple turns, issuing parallel queries when sub-questions are independent and sequential queries when each depends on the prior result, before committing to a final answer.

## Method

HybridDeepSearcher is a Qwen3-8B model fine-tuned via supervised learning on HDS-QA, a novel dataset of 2,111 question-answer trajectory pairs that explicitly interleave broad parallel query expansion with structured evidence aggregation before advancing to deeper sequential reasoning. The HDS-QA generation pipeline starts from single-hop NQ seed questions, collects related questions via Google's People Also Ask, summarizes entity characteristics, formulates a parallel-hop question that implicitly references the entity, and integrates it into a hybrid-hop question requiring both parallel and sequential hops. Answer trajectories are generated by prompting Qwen3-32B to perform iterative reasoning-query-retrieval loops with multiple parallelizable queries per turn, retaining only trajectories that reach the correct final answer. The key architectural insight is that the model learns to (i) issue multiple independent queries simultaneously to close knowledge gaps without an information bottleneck, and (ii) explicitly aggregate the retrieved evidence into a coherent summary before proceeding to the next sequential reasoning step. Notably, this hybrid search behavior is acquired through supervised fine-tuning alone (one epoch, lr 3e-5, with search-result tokens masked from gradients), without any reinforcement learning, yet it outperforms GRPO-trained baselines and exhibits monotonic test-time search scaling across five benchmarks.

## Results

HybridDeepSearcher (Qwen3-8B fine-tuned on HDS-QA) achieves the best F1 and model-judged accuracy across all five benchmarks. Headline improvements include +15.9 F1 on FanOutQA (44.1 vs. 28.2 for RAG-R1) and +9.2 F1 on BrowseComp† (15.1 vs. 5.9 for RAG-R1). It also attains the highest AUC (area under the accuracy–turn curve) on every benchmark, indicating superior effectiveness–latency trade-offs. Test-time search scaling is demonstrated: F1 on BrowseComp† improves 3.8× (4.0→15.1) when the turn budget grows from 1 to 8, while all baselines plateau.

## Baselines & Comparisons

HybridDeepSearcher outperforms all five iterative baselines on every benchmark and every reported metric. Against the strongest sequential-search baseline, Search-o1, it gains +7.8 F1 on MuSiQue (31.2 vs. 23.4) and +10.4 F1 on FRAMES (39.1 vs. 34.2). Against the strongest parallel-search baseline, RAG-R1, the margins are +1.5 F1 on MuSiQue, +15.9 F1 on FanOutQA, +3.3 F1 on FRAMES, +0.6 F1 on MedBrowseComp, and +9.2 F1 on BrowseComp†. The gap is largest on FanOutQA and BrowseComp†, which demand broad evidence coverage and persistent search—precisely the scenarios where hybrid parallel-sequential reasoning provides the most benefit. On the efficiency metric (AUC), HybridDeepSearcher leads on all five benchmarks (e.g., 0.44 on FRAMES vs. 0.41 for RAG-R1; 0.09 on BrowseComp† vs. 0.02 for RAG-R1), confirming that it extracts more accuracy per search turn. An ablation removing parallel queries (single-query variant) drops to 21.6 Acc on MuSiQue and 6.4 on BrowseComp†, confirming that the hybrid search behavior—not merely fine-tuning on HDS-QA questions—drives the gains.

## Relation to Prior Work

This paper carves out a middle ground between two established paradigms in retrieval-augmented search agents: sequential single-query search (Search-o1, Search-R1, R1-Searcher) and parallel multi-query search (DeepResearcher, RAG-R1). Prior work treats these as mutually exclusive strategies, and the authors argue both fail to achieve genuine test-time search scaling—sequential methods hit an information bottleneck while parallel methods lack structured aggregation. The key departure is the hybrid architecture that embeds parallel query expansion within sequential reasoning with explicit aggregation, trained via supervised fine-tuning on the new HDS-QA dataset rather than the GRPO-based RL that dominates the field. The HDS-QA dataset itself is novel in supporting more than two parallel sub-queries and explicitly weaving parallel results into subsequent sequential hops, a combination absent from prior training data like HotpotQA.

## Why It Matters / Open Questions

The central practical finding—that supervised fine-tuning on hybrid trajectories alone yields consistent, monotonic test-time search scaling while RL-based baselines plateau—challenges the field's default assumption that GRPO-style reinforcement learning is necessary for scaling search behavior. This opens a cheaper, more controllable training path for search agents. Open questions include whether better RL formulations (e.g., preference optimization) can recover the efficiency gains lost when GRPO is applied on top, and whether the hybrid strategy extends to multi-agent or long-horizon settings. A limitation is that the training data is synthetic and the backbone is 8B, so generalization to larger models or open-ended research tasks remains to be validated.
