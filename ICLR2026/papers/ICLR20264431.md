## Problem

Existing automatic tool-creation methods for LLMs rely on the model's internal knowledge to generate tools, which fails when tasks fall outside the model's expertise (e.g., causal inference, specialized physics or chemistry). No prior framework leverages external reference materials—such as textbooks or unstructured knowledge snippets—to ground tool creation, leaving a gap for knowledge-intensive domains where the LLM lacks the relevant domain knowledge.
![Teaser figure](../imgs/ICLR20264431/cropped_page0_idx0.webp)

## Input / Output

At inference, the method takes a text question and a pre-constructed hierarchical toolbox (two-level: categories → tools, where each tool comprises a natural-language description, a Python function, and a demonstration example with expected answer). The model outputs solution code that invokes the selected tools, yielding a numerical answer. For unstructured references (e.g., grammar rules for XLR translation), the LLM first constructs the hierarchy before tool creation, and tools may be pseudo-code rather than executable Python.

## Method

REFTOOL has two modules. In tool creation, an LLM (GPT-4o) generates up to m executable Python tools per reference section, each with a description, function, and illustrative example; tools are validated by executing the example and checking the output, with failed tools sent through a refinement loop. Valid tools are organized into a hierarchical toolbox mirroring the reference's chapter/section structure (or an LLM-constructed hierarchy for unstructured inputs). In tool utilization, the model performs two-phase hierarchical selection—first choosing at most n_c relevant categories, then at most n_t tools within each category—and integrates the selected tools into either single-turn Program-of-Thoughts or multi-turn ReAct reasoning. The key distinction from prior work is that tool creation is grounded in external reference content rather than the LLM's parametric knowledge, enabling tools for domains the model has not been trained on, while the hierarchical structure narrows the search space for effective tool retrieval.

## Results

REFTOOL achieves the highest average accuracy across all three scientific domains: 46.3% (ReAct+REFTOOL) on QRData-causal, 54.8% (PoT+REFTOOL) on TheoremQA-physics, and 57.7% (PoT+REFTOOL) on SciBench-chemistry. The paper reports a 13.0% average improvement over tool-creation baselines (LATM, Creator, TroVE) and a 10.2% average improvement over domain-specific reasoning methods (Physics Reasoner, StructChem, ChemAgent). On the non-scientific XLR translation task (Zhuang↔Chinese), REFTOOL achieves 54.0 BLEU / 61.6 chrF++ on average, outperforming the best baseline (Rule-by-Rule Retrieval w.Code) by 10.1 BLEU and 1.6 chrF++.

## Baselines & Comparisons

REFTOOL consistently outperforms all three general-purpose tool-creation baselines: LATM (28.4/35.7/34.3 avg), Creator (31.0/43.2/47.6 avg), and TroVE (32.0/43.9/49.0 avg) across causality, physics, and chemistry respectively, with an average margin of 13.0%. Against domain-specific methods, REFTOOL beats Physics Reasoner (43.6 avg) by 11.2 points on TheoremQA and StructChem (39.6 avg) by 18.1 points on SciBench; ChemAgent (56.3 avg) is the closest competitor in chemistry but still trails REFTOOL (57.7 avg) by 1.4 points while incurring ~29× higher inference cost. REFTOOL also surpasses the general reasoning baselines PoT (37.1/52.2/55.0 avg) and ReAct (43.8 avg on causality) in every domain, and outperforms RAG-augmented variants (PoT+RAG, ReAct+RAG) despite using the same reference books, demonstrating that the code-form tool representation and hierarchical structure enable more effective knowledge utilization than raw text retrieval. On the XLR translation task, REFTOOL (54.0 BLEU) beats all four baselines from Zhang et al. (2025), including Rule-by-Rule Retrieval w.Code (43.9 BLEU), confirming generalizability to non-scientific, unstructured-reference settings.

## Relation to Prior Work

REFTOOL departs from the dominant paradigm in automatic tool creation (LATM, Creator, TroVE), which relies on LLMs' internal knowledge to generate tools, by grounding tool generation in external reference materials such as textbooks and knowledge snippets. It also differs from domain-specific reasoning methods (Physics Reasoner, StructChem, ChemAgent) that depend on manually curated formula sets or extensive trial-and-error on validation data. The hierarchical organization of tools mirrors the structure of reference materials, and the code-form tool representation with execution-based validation is a repurposing of the Program-of-Thoughts and ReAct reasoning paradigms into a tool-construction pipeline rather than a direct reasoning step.

## Why It Matters / Open Questions

REFTOOL offers a practical, cost-efficient pathway for extending LLMs' knowledge boundaries in real time without fine-tuning or manual tool curation, with a 99% reduction in construction time compared to ChemAgent. The demonstration that the same reference-grounded tools generalize across datasets within a domain and to non-scientific tasks (XLR translation) suggests a broadly applicable paradigm. Open questions include how the framework scales to very large or conflicting reference corpora, whether deeper hierarchies or dynamic tool composition would further improve performance, and how to handle domains where reference materials are incomplete or outdated.
