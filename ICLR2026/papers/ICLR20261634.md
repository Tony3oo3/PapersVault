## Problem

Existing LLM-based code optimization relies on user-oriented pairs (iterative submissions from the same programmer), which confines improvements to local, incremental edits within a single programmer's cognitive patterns and neglects global algorithmic innovation. Additionally, optimized code frequently suffers from an 'optimization tax'—correctness degrades as efficiency improves—and no verification mechanism exploits the unique property that the original slow code is guaranteed functionally correct.
![Teaser figure](../imgs/ICLR20261634/cropped_page1_idx0.webp)

## Input / Output

The method takes a functionally correct but inefficient C++ (or Python) program along with its competitive programming problem description as input, and produces a semantically equivalent but faster program as output. Evaluation is conducted on the gem5 CPU simulator (GCC 9.4.0, -O3, C++17) using three metrics: %OPT (fraction of programs at least 10% faster and correct), SPEEDUP (geometric mean of old/new runtime, with 1.0× assigned to failures), and CORRECT (fraction passing all test cases). The Anchor Verification stage additionally produces verified test cases (input-output pairs) by executing the slow code in a local sandbox.

## Method

The paper introduces two complementary contributions. First, a problem-oriented perspective for constructing optimization pairs: instead of pairing sequential submissions from a single user (PIE), all valid submissions from different users for the same problem are pooled, sorted by runtime, and paired across users (PCO), injecting global algorithmic diversity and increasing pair count by an order of magnitude at 10 users. Second, a three-stage Anchor Verification Framework that exploits the slow code's guaranteed correctness: (1) the LLM interprets the slow code and generates boundary-case test inputs; (2) the slow code is compiled and executed to produce ground-truth outputs, forming verified test cases; (3) the optimized code is iteratively refined using execution feedback from these verified test cases. Code LLMs (Qwen2.5-Coder, DeepSeek-Coder, CodeLlama) are fine-tuned via LoRA on the PCO dataset, and the Anchor Verification is applied at inference time with a separate LLM backbone (GPT-4o, DeepSeek-V3) for refinement.

## Results

On the C++ code optimization benchmark (BEST@1), fine-tuning QWEN2.5-CODER 32B on the problem-oriented PCO dataset achieves 58.90% %OPT, 5.22× SPEEDUP, and 61.55% CORRECT, substantially outperforming the user-oriented PIE baseline (31.24%, 2.95×, 46.52%). With the Anchor Verification Framework applied via DEEPSEEK-V3 refinement, performance further improves to 71.06% %OPT, 6.08× SPEEDUP, and 74.54% CORRECT. Under BEST@8 sampling, PCO-adapted QWEN2.5-CODER 32B reaches 80.77% %OPT and 7.22× SPEEDUP. The problem-oriented perspective also demonstrates strong data efficiency: even 30% of PCO pairs surpass the full PIE dataset in both %OPT and SPEEDUP.

## Baselines & Comparisons

The paper's primary baseline is PIE (Shypula et al., 2024), the user-oriented code optimization dataset. PCO consistently and substantially outperforms PIE across every model family and parameter scale: for QWEN2.5-CODER 32B, %OPT nearly doubles (31.24%→58.90%), SPEEDUP increases by 77% (2.95×→5.22×), and CORRECT rises by 15 points (46.52%→61.55%). A controlled ablation (PCO-Random vs. PIE) confirms the perspective shift itself drives most gains, with top-speedup selection providing a secondary refinement. For the Anchor Verification Framework, the paper compares against Self-Debugging (Chen et al., 2024b) and Direct Test Generation. Anchor Verification outperforms both on all three metrics for GPT-4o and DEEPSEEK-V3 (e.g., DEEPSEEK-V3: 71.06% %OPT vs. 64.11% for Self-Debugging and 66.26% for Direct Test Generation). Self-Debugging actually slightly degrades performance for QWEN2.5-CODER 32B INSTRUCT (−0.48% %OPT), while Anchor Verification still yields +5.85% %OPT, highlighting that execution-grounded verification is more reliable than self-explanation for code optimization.

## Relation to Prior Work

This paper builds directly on Shypula et al. (2024), which introduced the PIE dataset of user-oriented code optimization pairs from iterative submissions on CodeNet and demonstrated preliminary LLM fine-tuning for performance improvement. The key conceptual departure is the shift from a user-oriented perspective (sequential pairs from a single programmer's trajectory) to a problem-oriented perspective (aggregating all valid submissions across users for the same problem, sorted by runtime), which the authors argue captures global algorithmic innovation rather than incremental local edits. The anchor verification framework draws on the execution-feedback refinement paradigm from CodeT (Chen et al., 2023) and self-debugging (Chen et al., 2024b), but repurposes the functionally-correct 'slow code' as a trusted oracle for generating verified test cases rather than relying on LLM-synthesized outputs.

## Why It Matters / Open Questions

The paper identifies and names the 'optimization tax'—the systematic trade-off where LLM-optimized code gains speed but loses correctness—and shows that correctness, not optimization ability, is the primary bottleneck (Finding 2). The problem-oriented perspective nearly doubles the optimization ratio (31%→59%) and the anchor verification framework pushes it further to 71%, with the notable data-efficiency result that even 30% of PCO pairs outperform the full PIE dataset. However, the work is confined to competitive programming problems in C++/Python with time-only optimization; roughly half of remaining failures are semantic errors revealing LLM blind spots in high-level program intent, and generalization to real-world codebases, memory optimization, and zero-correctness-loss guarantees remain open.
