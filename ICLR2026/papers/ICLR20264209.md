## Problem

Existing benchmarks for AI agents in scientific code generation occupy only the two extremes of the difficulty spectrum: SUPER evaluates agents on running experiments from a complete repository, while PaperBench and ResearchCodeBench require full from-scratch replication. No benchmark interpolates between these poles by varying how much of the original codebase is available, leaving it unclear how agent capability degrades as the task shifts from reproduction toward replication.

## Input / Output

Each task provides the agent with a research paper (with all numerical results stripped to prevent answer leakage), a Python codebase in which n core functions have been replaced with NotImplementedError, and a bash command sequence that triggers the experiment. The agent must implement the missing functions, execute the command in a sandboxed Docker/conda environment, and submit experiment results as a structured JSON dictionary of named metrics. A sample passes only if every reported value is within 5% relative error of the gold-standard run; the average number of test cases per sample grows from ~6 (n=1) to ~12 (n=5) as more functions are masked.

## Method

AutoExperiment is built from four MLRC-verified papers whose 85 core Python functions are individually maskable, yielding up to 275,990 unique samples at n=5. The key design choice is treating the number of simultaneously masked functions n as a continuous difficulty knob: n=1 approximates partial reproduction while n=5 approaches full replication. Agents are evaluated under a ReAct prompting strategy with full interaction history, equipped with tools for file navigation, code editing, script execution, and a final-answer submission call. The paper's central empirical finding is that performance collapses from ~35% (n=1) to near-zero (n=5) even for frontier models, that dynamic multi-step interaction (enabling iterative debugging) outperforms a fixed agentless pipeline by over 4×, and that the Pass@1-to-Pass@5 gap exceeds 10 percentage points, pointing to verifiers as a high-leverage direction for future work.

## Results

On the easiest setting (n=1 masked function), Claude-3.7-Sonnet achieves the highest pass rate at 36.5%, followed by GPT-4o (35.3%), Claude-3.5-Sonnet (31.8%), and GPT-4o-mini (27.1%). Performance drops precipitously at n=2, with all models falling to 2–10% pass rates, and most models reaching near-zero by n=5. Dynamic agents outperform fixed (agentless) harnesses by over 4× for GPT-4o (35.3% vs. 8.3%), and the Pass@5 gap over Pass@1 is substantial (35.3%→48.2% for GPT-4o; 31.8%→42.2% for Claude-3.5-Sonnet), indicating large headroom for verifier-based approaches.

## Baselines & Comparisons

This is a benchmark paper, so the key comparisons are between agent configurations rather than against prior methods. Dynamic (ReAct) agents dramatically outperform fixed agentless harnesses: GPT-4o jumps from 8.3% to 35.3% (4.2×), and o3-mini improves from 27.8% to 33.3%, showing that the ability to iteratively debug is critical. Among prompting strategies, ReAct with full history management is the best configuration (38.9% for GPT-4o), outperforming MLAgentBench-style structured prompting (29.7%) and Planning-Only (18.9%). On the natural-language context ablation, removing the paper text (No context) has minimal impact at n=1 (34.1% vs. 35.3%) but causes complete failure by n=4, confirming that paper-derived context becomes essential as more code is masked. The large Pass@1-to-Pass@5 gap (up to +12.9 pp for GPT-4o) shows that current models-as-verifiers capture only a fraction of the oracle verification gain, leaving substantial room for future verifier research.

## Relation to Prior Work

This paper carves new ground by introducing a continuous difficulty axis—progressive code masking—that no prior scientific-code benchmark possessed. SUPER (Bogin et al., 2024) evaluates reproduction (running existing code), PaperBench (Starace et al., 2025) evaluates from-scratch replication, and ResearchCodeBench (Hua et al., 2025) tests core function implementation, but each operates at a fixed difficulty level. AUTOEXPERIMENT unifies these into a single parameterized spectrum by masking n functions from MLRC-verified repositories, drawing its agent architecture from ReAct and SWE-Agent tool sets and its agentless baseline from the Agentless paradigm (Xia et al., 2024). The use of peer-replicated MLRC papers as the substrate is a methodological choice that prioritizes verified paper-to-code correspondence over dataset scale.

## Why It Matters / Open Questions

The benchmark exposes a critical gap: even frontier models that handle single-function infilling (≈35% pass rate) collapse to near-zero performance by n=5, revealing that the jump from 'fill one gap' to 'reconstruct a coherent subsystem' is far harder than incremental scaling suggests. The finding that dynamic, debug-capable agents outperform fixed agentless pipelines by 4× (for GPT-4o) challenges the SWE-Bench narrative that strong reasoning models can substitute for interactivity, and the large Pass@1-to-Pass@5 gap (≈13 points) points to a concrete, underexploited opportunity for verifier-based reranking. Key limitations—only four ML papers, Python-only, 85 base functions, and ~$1/sample compute cost—constrain generalizability, and open questions include whether the difficulty knob transfers to other languages/domains and whether purpose-built verifiers can close the multi-trial gap.
