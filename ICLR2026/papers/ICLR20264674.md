## Problem

LLM-based embodied agents in Minecraft begin with flawed priors about item dependencies and valid actions, and fail to correct these errors through prompting or self-reflection even when given failure feedback. Prior work either relies on impractical methods (fine-tuning, curated expert data, oracle dependencies) or lacks robust mechanisms to algorithmically revise knowledge from only binary success/failure feedback, leaving agents stuck repeating the same errors.
![Teaser figure](../imgs/ICLR20264674/cropped_page1_idx0.webp)

## Input / Output

The agent receives a goal item name, an initial LLM-predicted dependency graph (which may contain hallucinated items not present in the environment), and binary success/failure feedback after each subgoal execution. It produces a revised dependency graph, per-item high-level action selections from {mine, craft, smelt}, language subgoals of the form (action, quantity, item), and low-level action sequences executed by a pre-trained controller. Notably, the agent never receives detailed error reasons—only a single binary signal per subgoal—making failure-cause disambiguation a core challenge.

## Method

XENON replaces LLM self-correction with algorithmic revision of an external knowledge memory through two synergistic components. The Adaptive Dependency Graph (ADG) revises flawed item dependencies via RevisionByAnalogy: for less-tried items, it proposes new requirement sets by referencing the required items of top-K semantically similar (Sentence-BERT) successfully obtained items, scaling quantities with revision count; for repeatedly failed items flagged as inadmissible, it resets requirements to a general resource set and recursively revises all descendants to remove the flawed dependency. The Failure-aware Action Memory (FAM) maintains per-(action, item) success/failure counts to classify actions as empirically valid or invalid, prunes invalid actions from the LLM's candidate set to guide under-explored action selection, and—critically—disambiguates failure causes: when all actions for an item are classified invalid, FAM concludes the error lies in ADG and triggers a dependency revision. This division of labor lets the agent learn from only binary feedback without relying on the LLM to identify or fix its own errors.

## Results

On the long-horizon task benchmark in MineRL (67 goals across 7 item groups), XENON with learned dependency knowledge achieves an overall success rate of 0.54, surpassing all prior agents that rely on oracle dependency graphs and much larger proprietary LLMs (Optimus-2: 0.45, Optimus-1: 0.43, Jarvis-1: 0.38, DEPS: 0.22). With oracle knowledge, XENON* reaches 0.79 overall SR, nearly doubling the best prior method. For dependency learning, XENON achieves an Experienced Graph Accuracy (EGA) of ~0.6 in MineRL and ~0.9 in Mineflayer, compared to ~0.4 for the SC and DECKARD baselines, and maintains near-perfect EGA (~0.97) under ground-truth perturbations in MC-TextWorld where all baselines degrade.

## Baselines & Comparisons

XENON (learned, 0.54 overall SR) outperforms all oracle-knowledge baselines: Optimus-2 (0.45), Optimus-1 (0.43), Jarvis-1 (0.38), and DEPS (0.22), despite using a 7B open-weight LLM versus GPT-4/GPT-4V/Codex. The gap is most pronounced on late-game goals: XENON achieves 0.64 on Diamond and 0.74 on Gold, versus 0.13/0.09 for Optimus-2. For dependency learning (EGA), XENON (~0.6 MineRL, ~0.9 Mineflayer) substantially outperforms SC and DECKARD (both ~0.4) and ADAM (~0.1 MineRL, ~0.6 Mineflayer); SC's LLM self-correction provides no measurable benefit over DECKARD's no-correction approach. In MC-TextWorld under ground-truth perturbations, XENON maintains ~0.97 EGA at all intensities while all baselines degrade, with ADAM dropping to 0.12 under action perturbations. In the TextWorld Cooking domain, XENON achieves a perfect 1.00 success rate versus 0.75 for SC and 0.09 for DECKARD, confirming generalizability beyond Minecraft.

## Relation to Prior Work

XENON builds directly on the graph-augmented planning framework of DECKARD (Nottingham et al., 2023), adopting its dependency graph initialization and experienced requirement set update procedure, and adapts the context-aware reprompting mechanism from Optimus-1 (Li et al., 2024b) for smaller LLMs. Its key departure is from the LLM self-correction paradigm (Reflexion-style prompting): rather than asking the LLM to revise its own flawed predictions upon failure feedback, XENON algorithmically revises an external knowledge memory (the Adaptive Dependency Graph and Failure-aware Action Memory) using the agent's own experience. This positions XENON against prior Minecraft agents (DECKARD, ADAM, Optimus-1) that either lack correction mechanisms, rely on unreliable LLM self-correction, or use impractical shortcuts like pre-supplied items and expert curricula.

## Why It Matters / Open Questions

The paper demonstrates that robust algorithmic knowledge management can compensate for a lightweight 7B LLM, enabling it to outperform agents built on GPT-4/GPT-4V with oracle dependencies on challenging late-game goals—a result with practical implications for deploying embodied agents where proprietary model access is unavailable. The finding that LLM self-correction performs no better than no correction (both plateau at ~0.4 EGA) challenges a widely-used assumption in the LLM-agent literature. Key limitations include dependence on controller quality (MineRL's STEVE-1 severely limits Redstone learning) and the Minecraft-specific scope; the authors suggest joint planner-controller training via hierarchical RL as future work, and the generalization to non-Minecraft domains (TextWorld Cooking) remains limited to a single simple benchmark.
