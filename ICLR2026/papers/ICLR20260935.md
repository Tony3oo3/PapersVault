## Problem

Existing LLM benchmarks either rely on closed-ended questions prone to saturation and memorization, or on subjective pairwise comparisons that lack consistency. Neither paradigm adequately assesses whether LLMs can perform iterative, tool-augmented algorithm design on open-ended problems with well-defined objectives and large solution spaces. HeuriGym fills this gap by benchmarking LLMs on novel combinatorial optimization problems where no single heuristic dominates and exact solvers are intractable at scale.

## Input / Output

The LLM receives a structured problem description (background, mathematical formalization, I/O format), a minimal code skeleton exposing only the solve(input_file, solution_file) signature, and—across iterations—execution logs, verification diagnostics, and objective scores from a small demonstration set (~5 instances). It must produce a complete, self-contained Python program (using only numpy, networkx, and pandas) that reads an input file, applies a heuristic, and writes a solution file. Performance is scored via SOLVE_s@i (fraction of instances passing each of three pipeline stages—execution, solution generation, constraint verification—within i iterations) and the Quality-Yield Index (QYI), the harmonic mean of solution quality relative to expert baselines and the yield of verified solutions.

## Method

HeuriGym implements an agentic loop in which the LLM generates a full heuristic algorithm, the program is executed in a sandboxed environment, a domain-specific verifier checks constraint satisfaction, and an evaluator computes the optimization objective; all feedback is appended to the prompt for the next refinement iteration. The benchmark comprises nine problems across EDA (operator scheduling, technology mapping, global routing), compilers (e-graph extraction, intra-operator parallelism), computational biology (protein sequence design, Mendelian error detection), and logistics (airline crew pairing, pickup-and-delivery with time windows), each selected to have fewer than 1,000 citations on the most-cited paper to resist memorization. Unlike prior LLM-for-CO work that restricts models to filling template slots or small code fragments, HeuriGym requires end-to-end program synthesis including custom data structures and I/O parsing. The QYI metric, analogous to an F-score, penalizes imbalances between producing any valid solution (yield) and matching expert solution quality, while SOLVE_s@i decomposes failures into execution, generation, and verification stages to diagnose where in the agentic pipeline models break down.

## Results

Across nine combinatorial optimization problems, even the best-performing LLM (GPT-o4-mini-high) achieves only 74.8% SOLVE_III@10 (constraint-satisfaction pass rate after 10 iterations) and a weighted QYI of approximately 0.6, well below the expert baseline of 1.0. Gemini-2.5-Pro attains the highest QYI of 0.62, while weaker models like LLaMA-3.3 and LLaMA-4-Maverick fall below 0.3 QYI. The SOLVE_III@1 (single-attempt) pass rate ranges from 6.0% (LLaMA-4-Maverick) to 53.2% (GPT-o4-mini-high), showing that iterative refinement is critical for success.

## Baselines & Comparisons

The paper's primary comparison is among nine frontier LLMs evaluated under an identical agentic pipeline (Python, 8 CPU cores, fixed timeouts, 10 iterations). GPT-o4-mini-high leads on SOLVE_III@10 (74.8%) and SOLVE_III@1 (53.2%), while DeepSeek-R1 is a close second (73.4% / 44.0%); Gemini-2.5-Pro achieves the highest weighted QYI (0.62) despite a lower SOLVE_III@10 (65.1%), indicating better solution quality on the instances it does solve. LLaMA-4-Maverick and LLaMA-3.3 trail significantly, with QYI scores below 0.3. In a secondary comparison (Table 4), three open-source evolutionary frameworks—HSEvo (QYI 0.449), ReEvo (QYI 0.449), and EoH (QYI 0.449)—all underperform the direct Gemini-2.5-Pro baseline (QYI 0.617, SOLVE_III@10 0.651), losing roughly 15–20 percentage points in both yield and quality, attributed to their inability to incorporate execution feedback and their context-breaking search process.

## Relation to Prior Work

HeuriGym carves new ground at the intersection of LLM evaluation and combinatorial optimization. It departs from prior LLM-CO methods (FunSearch, AlphaEvolve, HSEvo, ReEvo, EoH) that rely on evolutionary search over template-based heuristics by requiring LLMs to generate complete, self-contained optimization programs from scratch without scaffolds. It also distinguishes itself from existing LLM benchmarks: unlike closed-ended suites (AIME, HumanEval, GPQA) prone to saturation, or subjective arenas (Chatbot Arena) lacking clear objectives, HeuriGym combines well-defined quantitative objectives with large solution spaces in an iterative agentic loop. Concurrent efforts like ALE-Bench and CO-Bench target classic CO problems with metaheuristics, whereas HeuriGym focuses on novel, domain-specific problems (EDA, biology, logistics) that resist memorization and require problem-specific structural insight.

## Why It Matters / Open Questions

HeuriGym provides a realistic, open-source testbed that exposes persistent gaps in LLM tool use, planning, and adaptive reasoning on practically important optimization tasks, with the QYI metric offering a unified measure of both feasibility and solution quality. The finding that even top-2025 models plateau around QYI 0.6 (rising to 0.88 by early 2026) gives the community a concrete, hard-to-saturate benchmark for tracking progress. Key open questions include bridging proxy metrics to real-world validation (e.g., physical experiments in biology, backend synthesis in EDA), scaling to C++ and larger instances, and determining whether advanced prompting, multi-agent, or test-time-scaling strategies can close the remaining gap to expert-level performance.
