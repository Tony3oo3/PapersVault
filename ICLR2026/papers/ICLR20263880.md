## Problem

Existing LLM-based approaches for vehicle routing problems either depend on handcrafted modules or external solvers (ARS, DRoC), limiting self-containment, or are restricted to simple problems like TSP (SGE), failing to handle complex constraints. No prior method achieves full automation from raw problem instance to feasible solution while maintaining high code reliability and solution feasibility across diverse VRP variants.
![Teaser figure](../imgs/ICLR20263880/cropped_page3_idx0.webp)

## Input / Output

The framework takes a VRPLib-format plain-text instance file as input, which encodes problem type, node coordinates, demands, capacity, time windows, distance limits, and electric-vehicle parameters in standardized sections. It produces a structured problem description D(G) = {P, S, K, X, Y, Z} (problem type, textual description, constraint set, required inputs, expected output, objective function), a complete self-contained Python solver implementing a destroy-insert heuristic, and finally feasible vehicle routes with an objective value. The generated code requires no external solvers or handcrafted modules, and the framework also accepts JSON and CSV formats to demonstrate robustness to different data representations.

## Method

AFL decomposes the end-to-end pipeline into three subtasks—problem description, code generation, and solution derivation—coordinated by four specialized LLM agents: a Generation Agent (GA) that produces descriptions and function code sequentially, a Judgment Agent (JA) that validates correctness and constraint compliance, a Revision Agent (RA) that corrects identified issues, and an Error Analysis Agent (EAA) that diagnoses runtime failures. Code generation follows a fixed function structure (read_vrp, distance, cost, initial, destroy, insert, validate, main) implementing a unified destroy-insert heuristic with simulated annealing, where each function is generated, judged, and revised before the next is produced, reducing cumulative error propagation. A buffer caches validated problem descriptions and code for reuse on identical problem types, avoiding redundant generation. The iterative JA–RA loop at every stage enforces cross-functional consistency and constraint satisfaction, while the EAA provides targeted debugging suggestions when execution errors occur, collectively achieving 0% runtime error rate and 100% solution success rate across 17 VRP variants.

## Results

AFL achieves 0% Runtime Error Rate (RER) and 100% Success Rate (SR) across all 17 tested VRP variants, compared to SGE (94.1% RER, 5.9% SR) and DRoC (82.4% RER, 17.6% SR). On 48 standard VRP benchmarks, AFL (T=10000) attains gaps within 3% of the SOTA HGS-PyVRP solver on most problem types (e.g., 0.34% on OCVRPBWT, 0.38% on OCVRPTW, 0.99% on CVRPTW at n=50). On 8 practical electric VRP variants, AFL outperforms the ACO baseline by up to 18.32% (EOCVRPLTW) and 9.05% (ECVRPLTW) in objective value while running faster. On TSPLib and CVRPLib, AFL achieves gaps of 1.28%–2.98% and 1.93%–6.66% respectively, consistently outperforming DRoC (3.02%–4.22%) and ReEvo (5.18%–14.78%).

## Baselines & Comparisons

Against the traditional SOTA solver HGS-PyVRP, AFL (T=10000) achieves gaps within 3% on most of the 48 standard VRP benchmarks (e.g., 0.34% on OCVRPBWT, 0.99% on CVRPTW), which the authors consider acceptable given full automation and self-containment; OR-Tools and RF-POMO are intermediate, with OR-Tools typically within 0.1–2.8% and RF-POMO within 1.2–4.5%. On the 8 practical ECVRP variants where no dedicated SOTA solver exists, AFL decisively beats the ACO baseline (500 iterations) on all problems, with gaps ranging from −2.72% (ECVRP) to −18.32% (EOCVRPLTW), and also substantially outperforms a Greedy baseline (gaps of 3.44%–109.03% for Greedy). Among LLM-based methods, AFL achieves 0% RER and 100% SR, dramatically outperforming SGE (94.1% RER, 5.9% SR, limited to TSP only) and DRoC (82.4% RER, 17.6% SR, limited to TSP/CVRP/CVRPL). On shared performance benchmarks (TSPLib, CVRPLib, CVRPL), AFL's gaps (1.28%–6.79%) are consistently lower than DRoC (3.02%–8.31%), ReEvo (5.18%–19.81%), and SGE (109.59%–660.36%), confirming both superior reliability and solution quality.

## Relation to Prior Work

This paper carves new ground at the intersection of LLM-based code generation and combinatorial optimization by proposing a fully self-contained, multi-agent pipeline that departs from prior LLM-for-VRP approaches in two key ways. Unlike ARS and DRoC, which rely on handcrafted constraint templates or external solvers (OR-Tools) and still require human intervention to extract instance-specific information, AFL generates all code end-to-end from raw VRPLIB input. Unlike SGE, which achieves self-containment but is restricted to TSP due to the absence of constraint-handling mechanisms, AFL introduces a four-agent architecture (generation, judgment, revision, error analysis) that enforces cross-functional consistency across a destroy-insert LNS solver, enabling it to handle 60 complex VRP variants including electric vehicle routing with recharging.

## Why It Matters / Open Questions

The near-perfect code reliability (0% RER, 100% SR) and solution feasibility across 17 VRP variants represent a substantial practical advance over existing LLM-based solvers, potentially democratizing access to complex routing optimization for non-expert users. The framework's ability to outperform ACO on practical electric VRPs (by up to 28%) while remaining fully automated suggests a viable path toward general-purpose optimization agents. However, the main limitation is that AFL does not surpass purpose-built SOTA solvers (HGS-PyVRP) on well-studied problems like CVRP, and the reliability advantage is measured against relatively early baselines (SGE, DRoC) rather than against a mature multi-agent LLM system. Open questions include whether the agentic design generalizes beyond VRPs to other combinatorial optimization domains, and whether incorporating evolutionary search or learned heuristics can close the remaining performance gap with hand-crafted solvers.
