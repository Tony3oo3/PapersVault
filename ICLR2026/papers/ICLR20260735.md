## Problem

Existing tool-integrated reasoning (TIR) methods face three critical gaps: TIR training data is often style-mismatched with the policy model and fails to generalize to reasoning models like DeepSeek-R1; RL-based optimization operates only at the episode level, overlooking fine-grained step-level code generation errors; and inference ignores immediate tool execution feedback for dynamic correction. The paper's key insight is that the success of an intermediate tool call is a strong statistical predictor of the final answer's correctness, motivating a hierarchical optimization strategy.
![Teaser figure](../imgs/ICLR20260735/cropped_page0_idx0.webp)

## Input / Output

The model receives a mathematical problem statement and a tool-use instruction, then autoregressively generates an alternating trajectory of natural language reasoning steps (r^t), Python code actions (a^t), and sandbox execution observations (o^t) in a think-act-observe loop. Code is executed in an external SandboxFusion environment, and the trajectory terminates when the model produces a final answer wrapped in \boxed{} within its last reasoning step. Maximum context is 16,384 tokens for reasoning models and 4,096 for non-reasoning models, with up to 5 rounds of code interaction per trajectory.

## Method

THOR comprises three components. First, TIRGen is a generator-refiner data pipeline where the Generator (the policy model itself) produces reasoning steps and the Refiner (Qwen3-32B) identifies code-solvable operations, converts them to executable Python, runs them in a sandbox, and splices the results back—yielding policy-aligned TIR data that avoids out-of-distribution degradation. Second, hierarchical RL jointly optimizes at two granularities: episode-level GRPO maximizes final-answer correctness over full trajectories, while step-level optimization targets only failed code executions by backtracking to the reasoning prefix, regenerating the suffix and action, and rewarding execution success—thereby providing dense, fine-grained signal for code generation. Third, a self-correction mechanism at inference backtracks to the failed reasoning step, splits it into a fixed prefix and a regenerable suffix, and retries up to N_corr=4 times, reducing failed code executions from 685 to 82 (non-reasoning) and 2311 to 155 (reasoning) while raising code pass rates to 98.7% and 99.0% respectively.

## Results

THOR-7B (non-reasoning) achieves an average of 61.2 across six mathematical benchmarks (MATH500, AIME 2024/2025, AMC 2023, Minerva Math, Olympiad Bench), outperforming the strongest tool-using baseline TORL-7B (56.2) by 5.0 points and GPT-4o-1120 (42.2) by 19.0 points. THOR-Thinking-8B (reasoning) reaches 79.8 average, surpassing Qwen3-8B (74.5) by 5.3 points and DeepSeek-R1-Distill-Qwen-7B (67.5) by 12.3 points, while also beating the much larger QwQ-32B-Preview (59.7) by 20.1 points. On code benchmarks (HumanEval+, MBPP+, LiveCodeBench v6), THOR achieves consistent zero-shot pass@1 gains over its base models without any code-specific fine-tuning.

## Baselines & Comparisons

Among non-reasoning standard-scale models, THOR-7B (61.2 avg) outperforms the strongest tool-using competitor TORL-7B (56.2) by 5.0 points and the non-tool GPT-4o-1120 (42.2) by 19.0 points, with the largest margin on AIME 2024 (+9.2 over TORL) and AMC 2023 (+7.5). For reasoning models, THOR-Thinking-8B (79.8 avg) surpasses its base Qwen3-8B (74.5) by 5.3 points, DeepSeek-R1-Distill-Qwen-7B (67.5) by 12.3 points, and the 4× larger QwQ-32B-Preview (59.7) by 20.1 points, achieving the best AIME 2024 score (77.5) among all listed models. At the lightweight scale, THOR-Thinking-1.7B (65.3) beats Qwen3-1.7B (61.1) by 4.2 points and DeepScaleR-1.5B (52.5) by 12.8 points, while THOR-1.5B (49.1) nearly doubles the performance of Qwen2.5-Math-1.5B with tools (18.4). On test-time scaling (Table 2), the proposed self-rewarded Best-of-N strategy (using code execution pass rate as intrinsic reward) matches or exceeds external PRM-based selection (InternLM2-RM, Qwen2.5-Math-PRM) at equal compute budget (N=8), gaining +3.2% (non-reasoning) and +4.5% (reasoning) over the base model when combined with PRMs.

## Relation to Prior Work

This paper extends the Tool-Integrated Reasoning (TIR) paradigm established by TORA (Gou et al., 2023) and subsequent RL-based TIR methods (TORL, ZTRL, ReTool) by introducing a hierarchical RL framework that jointly optimizes episode-level problem solving and step-level code generation, building on GRPO (Shao et al., 2024) and incorporating the NLL loss from VAPO (Yue et al., 2025b). It departs from prior TIR data construction approaches (which rely on prompting large external models or rule-based code injection) by proposing TIRGen, a generator-refiner pipeline that produces policy-aligned training data. The cold start procedure follows the DeepSeek-R1 paradigm (Guo et al., 2025), and dynamic data filtering is borrowed from DAPO (Yu et al., 2025).

## Why It Matters / Open Questions

THOR provides a practical, end-to-end recipe for integrating code tools into both reasoning and non-reasoning LLMs, achieving SOTA among comparable-scale models while reducing inference token count by 6–13%. The finding that code execution pass rate can substitute for external PRMs in test-time scaling is practically significant, removing a dependency on separately trained reward models. Open questions remain: the framework is validated only up to 8B parameters, explores solely code interpreters (not symbolic systems or search engines), and the multi-tool joint optimization scenario is left for future work. Whether the hierarchical RL advantage persists at 32B+ scale or with more diverse tool types is untested.
