## Problem

While data minimization is a cornerstone of privacy regulation (e.g., GDPR Art. 5(1)(c)), no prior work formally defines or quantifies the minimal privacy-revealing disclosure a user prompt must retain to preserve task utility for a given LLM. Existing sanitization methods apply heuristic redaction or LLM-as-a-Judge relevance scoring without searching for the optimal privacy-utility tradeoff, leaving oversharing unquantified. The paper further reveals that even frontier LLMs are poor single-pass predictors of this minimum, exhibiting a systematic bias toward abstraction that leads to unnecessary disclosure.

## Input / Output

The method consumes a user prompt with PII spans detected and clustered by GPT-4o (using a 13-type taxonomy including NAME, GEOLOCATION, HEALTH_INFORMATION, etc.) along with a target response model F. It outputs a minimized prompt τ(x; a) with a per-entity action vector a ∈ {RETAIN, ABSTRACT, REDACT}^n and a replacement map that enables deterministic context-recovery (replace-back) on model outputs before utility evaluation. The action space forms an ordinal lattice (RETAIN ≺ ABSTRACT ≺ REDACT), and the search returns the first action profile satisfying a strict binary utility predicate—no partial-credit or threshold-based acceptance.

## Method

The core algorithm is a two-stage freeze-then-search procedure. Stage 1 probes each detected entity in isolation (REDACT and ABSTRACT while all others stay RETAIN) to freeze entities whose modification breaks utility, reducing the branching factor. Stage 2 performs a best-first tree search over the remaining entities: starting from the root (all REDACT), it generates children by relaxing exactly one action one step (REDACT→ABSTRACT or ABSTRACT→RETAIN), ordering the priority queue with a pairwise privacy comparator C that returns which of two variants is more privacy-preserving. The comparator is a LoRA-fine-tuned Qwen2.5-7B-Instruct trained on 4,840 o3-labeled A/B pairs, achieving 89% accuracy at ≥0.8 human consensus with 0.31 s/decision latency (>20× faster than zero-shot o3). The search returns the first node passing the utility predicate (GPT-4o judge for open-ended tasks; k=5 exact-match for closed-ended), yielding an oracle that quantifies the maximum achievable data minimization for each model-dataset pair.

## Results

On open-ended prompts (ShareGPT, WildChat), GPT-5 achieves the strongest data minimization at 85.7% REDACT and 8.6% ABSTRACT (only 5.7% RETAIN), while the smallest model Qwen2.5-0.5B retains 69.7% of PII spans. On closed-ended tasks (MedQA, CaseHOLD), GPT-4.1 reaches 98.0% REDACT with just 1.0% RETAIN, confirming that frontier models tolerate aggressive redaction without utility loss. Adversarial recovery audits confirm the minimization is effective: span-wise correct-recovery rates stay below 7.7% for REDACT and 14.9% for ABSTRACT, and type-wise Hit@1 drops from ~90% (original) to near 0% (masked) for most PII types.

## Baselines & Comparisons

The paper's central comparison is between the search-derived oracle and zero-shot LLM predictions of data minimization. Across all tested predictor models (GPT-5, GPT-4.1, Claude, Mistral, Qwen, Exaone), single-pass predictions consistently overshare relative to the oracle: the dominant outcome category is 'Overshare' (prediction leaks more privacy than the oracle), particularly on open-ended datasets. Models exhibit a strong internal bias toward ABSTRACT over REDACT (e.g., Mistral-24B abstracts 97.1% of spans on ShareGPT vs. the oracle's ~85% redaction), and this bias persists even when prompt instructions explicitly state that REDACT is stronger than ABSTRACT. On closed-ended tasks, MedQA is near-all Overshare while CaseHOLD shows some Undershare+PASS and Fit, indicating the oracle is harder to surpass when answers are verifiable. The paper does not directly benchmark against prior sanitization methods (e.g., PREEMPT, ALSA, DynText) but positions its oracle as a ground-truth reference that exposes the gap in LLM-as-a-Judge approaches for privacy-utility assessment.

## Relation to Prior Work

This paper departs from prior prompt-sanitization work (Dou et al., 2024; Ma et al., 2025; Ngong et al., 2025) that either applies fixed redaction rules, uses heuristics to flag sensitive spans, or relies on LLM-as-a-Judge to assess relevance, by formally casting data minimization as a constrained optimization problem (maximize privacy subject to a utility predicate) and solving it via a privacy-ordered priority-queue tree search. It also distinguishes itself from user-assisted sanitization tools (Zhou et al., 2025; Kan et al., 2023) by automating the decision and providing an oracle that quantifies the true minimum disclosure for a given target model. The privacy comparator, distilled via LoRA from a strong zero-shot judge, is a practical engineering contribution that enables the search to run at 0.31s/decision rather than 6–8s.

## Why It Matters / Open Questions

The practical finding that frontier models tolerate 85–98% PII redaction while preserving utility provides a concrete upper bound for on-device sanitization pipelines and suggests that current practice overshares dramatically. The more conceptual contribution—the 'capability gap' showing that even GPT-5 cannot reliably predict its own information needs and defaults to abstraction over redaction—challenges the assumption that LLM-as-a-Judge is a viable substitute for search-based verification in privacy-critical settings. Open questions include what internal representations or training signals determine a model's information redundancy, how to build robust per-model predictors from oracle supervision, and how individual privacy-preference variance (over half of human raters disagreed at ≥0.8 consensus) should be incorporated.
