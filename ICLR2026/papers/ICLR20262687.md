## Problem

Existing open-source 'think with images' approaches are limited to either generating auxiliary images (suffering from quality loss and high latency) or performing only bounding-box cropping, falling far short of the diverse image manipulation and code-based computation capabilities demonstrated by proprietary models like OpenAI O3. No open-source method simultaneously supports rich operations (cropping, rotation, contrast enhancement, zooming) and mathematical code execution while maintaining high autonomy in deciding when and how to apply them.

## Input / Output

The model receives an RGB image (often high-resolution, e.g., 4K or 8K) along with a text question and the image's file path and dimensions. It produces an interleaved reasoning trace containing natural-language analysis and optional Python code blocks wrapped in <code> tags; the code is executed in an external sandbox that returns processed images or numeric results via <sandbox_output> tags. The model iterates over multiple dialogue rounds, refining operations (e.g., re-cropping after an initial miss) before emitting a final answer in <answer> tags. The sandbox automatically handles formatting, boundary clamping, and variable initialization, so the model only needs to specify semantic operations and parameters.

## Method

Thyme is built on Qwen2.5-VL-7B and trained in two stages. The SFT stage (≈200 GPU hours) uses 500K curated samples spanning no-code, single-operation, multi-operation, and multi-turn correction scenarios, with three key strategies: masking all sandbox outputs from the loss to prevent the model from hallucinating execution results, training only on the final dialogue round to avoid learning 'wrong-then-correct' patterns, and annealing a small math-code subset at a lower learning rate to prevent it from being overwhelmed by image-operation data. The RL stage employs GRPO-ATS, an extension of GRPO that applies adaptive temperature sampling: temperature 0 within <code> blocks to guarantee deterministic, executable code, and temperature 1 for natural-language reasoning to preserve exploration diversity. A secure sandbox with autopep8 formatting, AST-based boundary correction, and multi-round variable persistence reduces the model's coding burden, while a composite reward (Result × (1 + 0.5 × Consistency) + 0.5 × Formatting) incentivizes correct answers with coherent reasoning without letting consistency override accuracy.

## Results

Thyme-VL-7B (built on Qwen2.5-VL-7B) achieves substantial gains over its baseline across nearly 20 benchmarks: HRBench-4K Overall improves from 68.8 to 77.0 (+8.2), MME-RealWorld Perception from 60.6 to 67.1 (+6.5), MME-RealWorld Reasoning from 38.6 to 48.4 (+9.8), and LogicVista from 39.8 to 49.0 (+9.2). Notably, Thyme-7B surpasses the 4× larger Qwen2.5-VL-32B on perception tasks (HRBench-4K: 77.0 vs 73.4; MME-Real Perception: 67.1 vs 63.8), demonstrating that test-time code-based image manipulation compensates for model scale in perception. On reasoning benchmarks, however, the 32B model retains an advantage (MathVision: 35.2 vs 27.6; MathVista: 72.2 vs 70.0), indicating that logical inference still depends heavily on inherent model knowledge.

## Baselines & Comparisons

Against the primary baseline Qwen2.5-VL-7B, Thyme-7B wins on virtually every benchmark, with the largest gains on MME-RealWorld Reasoning (+9.8), LogicVista (+9.2), and HRBench-4K FCP (+10.8). Compared to InternVL3-8B, Thyme-7B leads on all perception benchmarks (e.g., HRBench-4K 77.0 vs 70.0) and most reasoning tasks, but trails on MMStar (65.9 vs 68.5). Against the 4× larger Qwen2.5-VL-32B, Thyme-7B wins on all perception benchmarks (HRBench-4K 77.0 vs 73.4, MME-Real Perception 67.1 vs 63.8) and MMVet-Hard (58.3 vs 48.4), but loses on reasoning (MathVision 27.6 vs 35.2, LogicVista 49.0 vs 54.4) and BLINK (56.1 vs 63.6). Versus GPT-4o, Thyme-7B dominates on high-resolution perception (HRBench-4K 77.0 vs 65.0, MME-Real 64.8 vs 62.8) but trails on reasoning (MathVision 27.6 vs 36.5, LogicVista 49.0 vs 53.2). Among tool-use methods, Thyme-7B outperforms DeepEyes-7B on Hallucination (71.0 vs 59.3 aAcc), MME-RealWorld-Lite (59.1 vs 53.97 perception), and MMVet-Hard (58.3 vs 53.23), while DeepEyes edges ahead on VStarBench (83.3 vs 82.2). Thyme is competitive with Mini-O3 on perception (HRBench4K 77.0 vs 77.5) but clearly behind Skywork-R1V4 (HRBench4K 77.0 vs 82.8, MME-RealWorld 64.8 vs 71.4) and far behind OpenAI O3 across all benchmarks (e.g., VStarBench 82.2 vs 95.7, LogicVista 49.0 vs 67.33). Against training-free methods (Visual Sketchpad, PyVision-GPT-4.1), Thyme shows clear advantages, confirming the value of end-to-end training over prompt-based orchestration.

## Relation to Prior Work

This paper extends the 'thinking with images' paradigm introduced by OpenAI O3 and explored in recent work (DeepEyes, Mini-O3, Pixel Reasoner, Chain-of-Focus), which typically limits the model to a single crop-and-zoom operation or to generating auxiliary images. Thyme departs from these by framing image manipulation as autonomous code generation executed in a sandbox, supporting a richer operation set (cropping, rotation, contrast enhancement, zooming) alongside mathematical computation. The RL component builds directly on GRPO (Shao et al., 2024a), extending it with an adaptive temperature sampling strategy (GRPO-ATS) that decouples exploration in natural-language reasoning from determinism in code generation. The SFT data construction draws on diverse open-source datasets (LLaVA-OV-Image, V*, MM-Eureka, arXivQA, Retool) and a manually annotated high-resolution perception set, positioning the work as a systematic open-source replication of capabilities previously available only in proprietary systems.

## Why It Matters / Open Questions

Thyme is the first open-source framework to match the breadth of image manipulation and code-based computation demonstrated by OpenAI O3, making this capability accessible to the research community. The finding that a 7B model augmented with test-time code execution outperforms a 4× larger model (Qwen2.5-VL-32B) on high-resolution perception benchmarks suggests that perception gains may come more from 'looking harder' at inference time than from parameter scale, a direction worth further investigation. Key limitations include dependence on the base model's localization accuracy (incorrect crops), the absence of dedicated benchmarks for rotation correction and contrast enhancement, and the fact that all results are validated on a single 7B backbone. Open questions include whether the code-based paradigm generalizes to video, whether the sandbox can be replaced by learned operations, and whether the adaptive temperature trick transfers to other code-generating RL settings.
