## Problem

Existing agent benchmarks either measure synthetic or narrow tasks that don't reflect real-world professional work, or lack sufficient difficulty to meaningfully differentiate frontier models. Terminal-Bench 2.0 addresses this gap by providing 89 hard, realistic tasks in command-line terminal environments—spanning software engineering, scientific computing, cybersecurity, and systems administration—where even the best frontier models and agents resolve fewer than 65% of tasks.
![Teaser figure](../imgs/ICLR20261398/cropped_page2_idx0.webp)

## Input / Output

Each task provides an agent with a natural-language instruction and a pre-configured Docker container; the agent interacts with the environment through shell commands and file operations over a time-limited, interactive session. Evaluation is outcome-driven: a set of unit tests inspects the final container state (not the agent's command history or console output), so any valid approach to reaching the correct end state passes. The benchmark produces per-task and aggregate resolution rates across 32,155 trials, along with trajectory-level failure mode classifications (Execution, Coherence, Verification) and command-level error taxonomies.

## Method

Terminal-Bench is an evaluation framework where each task is a tuple of (instruction, Docker image, test suite, oracle solution, time limit), crowd-sourced from 93 contributors and verified through a multi-stage audit process including automated solvability checks, LLM-assisted quality review, adversarial exploit agents to detect cheating vectors, and three rounds of human review (~3 reviewer-hours per task). To decouple model capability from agent-scaffold bias, the authors introduce Terminus 2, a minimal scaffold with a single headless terminal tool that issues only Bash commands, serving as a neutral testbed. The Harbor harness orchestrates parallel containerized execution across 6 agent scaffolds (Claude Code, Codex CLI, Gemini CLI, OpenHands, Mini-SWE-Agent, Terminus 2) and 16 frontier models. Error analysis employs a simplified MAST-derived taxonomy (Terminal Agent Taxonomy) with LLM-as-judge annotation (90% agreement with human labels) for trajectory-level failures, and a separate command-level taxonomy applied to 3,800 sampled failures to quantify specific error types like missing executables and runtime crashes.

## Results

On Terminal-Bench 2.0 (89 tasks, 32,155 trials), the best agent-model combination (Codex CLI + GPT-5.2) achieves a 63% task resolution rate, while Terminus 2 + Claude Opus 4.5 and Terminus 2 + Gemini 3 Pro reach 58% and 57% respectively. Among open-weight models, Terminus 2 + Kimi K2 Thinking performs best at 36%, while smaller models score around 15%. Command-level error rates range from 9.2% (Grok 4) to 26.7% (GPT-OSS-120B), and execution errors dominate the failure taxonomy for frontier closed-source models.

## Baselines & Comparisons

The paper evaluates six agent scaffolds (Claude Code, Codex CLI, Gemini CLI, OpenHands, Mini-SWE-Agent, and Terminus 2) across 16 frontier models. Model selection proves more impactful than agent scaffold: Codex CLI's resolution rate increases by 52 percentage points when switching from GPT-5-Nano to GPT-5.2, while Gemini 2.5 Pro gains 17 percentage points by switching from OpenHands to Terminus 2. Proprietary models paired with their native agents occupy the top 13 rankings, with all open-weight models trailing significantly (best: 36% vs. 63% for the top closed-source). The neutral Terminus 2 scaffold (single headless terminal tool, Bash-only) is introduced to decouple model capability from scaffold engineering, revealing that frontier closed-source models share similar error profiles (execution-dominated) while open-weight models show more balanced failure distributions across execution, coherence, and verification categories.

## Relation to Prior Work

Terminal-Bench carves new ground by framing agent evaluation around diverse, expert-level tasks in a real terminal shell, departing from prior benchmarks that focus on narrow aspects (SWE-Bench for GitHub issues, OS World for GUI computer use, Koala for shell script optimization, NL-to-Bash for command translation). The outcome-driven task formulation (testing final container state rather than specific commands) and the introduction of Terminus 2 as a neutral single-tool scaffold to decouple model capability from agent engineering represent methodological departures from prior agent benchmarks that typically evaluate a fixed agent-model pairing. The error analysis builds on the MAST multi-agent failure taxonomy but adapts it to single-agent terminal settings, and the Harbor framework generalizes the containerized evaluation infrastructure used by prior benchmarks.

## Why It Matters / Open Questions

Terminal-Bench 2.0 provides a genuinely hard (frontier models <65%) and diverse benchmark that will likely become a standard reference for terminal-based agent evaluation, analogous to SWE-Bench's role for software engineering agents. The finding that model selection dominates over agent scaffold choice, combined with the command-level analysis showing 24.1% of failures stem from basic environment navigation (missing executables), gives practitioners concrete, actionable targets for improvement. Key open questions include preventing training-data contamination (the authors acknowledge the public repository is a symbolic safeguard at best), whether the benchmark will saturate within a year as model capabilities rapidly improve, and whether the observed error profiles (execution-dominated for frontier models vs. balanced for open-source models) persist as models scale.
