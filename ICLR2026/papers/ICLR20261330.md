## Problem

Only about 19.5% of papers accepted at top ML conferences (ICLR, ICML, NeurIPS 2024) release official code, forcing researchers to laboriously reverse-engineer implementations from prose. While LLMs have shown strong code generation capabilities, prior approaches either require pre-existing code snippets, partial implementations, or focus on single-file tasks, leaving open whether faithful, repository-level code can be generated solely from a paper's text without access to any prior code or APIs.

## Input / Output

The method takes the full text of a machine learning paper (converted to structured JSON via s2orc-doc2json, with a 70,000-token cap to fit within LLM context limits) and produces a complete multi-file code repository organized into modules with explicit inter-file dependencies, along with a config.yaml file for hyperparameter customization. The output repository is generated sequentially in a dependency-respecting execution order, so each file is produced with awareness of all previously generated files, ensuring cross-file consistency. The current version processes only textual content; figures and tables in papers are not yet consumed.

## Method

PaperCoder decomposes the paper-to-code task into three coordinated stages, each handled by specialized LLM agents: (1) Planning, which extracts an overall implementation roadmap, designs the system architecture via class and sequence diagrams, determines an ordered file list with execution dependencies (logic design), and synthesizes a configuration file; (2) Analysis, which iteratively produces per-file specifications covering functional goals, input-output behaviors, intra- and inter-file dependencies, and algorithmic constraints derived from the paper; and (3) Coding, which generates each file sequentially in the dependency order established during planning, conditioning each generation on the original paper, all planning artifacts, the file-specific analysis, and all previously generated code. The key design insight is a top-down decomposition that first abstracts the paper's narrative into implementation-level structure before writing any code, in contrast to bottom-up role-playing or SOP-based frameworks (ChatDev, MetaGPT) that expand from short requirement descriptions. The default backbone is o3-mini-high, and the framework requires no pre-existing code, skeleton files, or external APIs as input.

## Results

On Paper2CodeBench (90 papers from ICLR/ICML/NeurIPS 2024), PaperCoder achieves reference-based scores of 3.68–3.83 and reference-free scores of 4.73–4.77 across conferences, approaching the Oracle (author-released repository) scores of 4.80–4.84 without statistically significant differences. On PaperBench Code-Dev, PaperCoder achieves 45.14% replication score with o3-mini-high and 51.14% with Claude 3.5 Sonnet, substantially outperforming the benchmark's own baselines. In human evaluation, 88% of PaperCoder's generated repositories are rated best over all baselines, and 92% of paper authors report the generated code is helpful for reproduction.

## Baselines & Comparisons

PaperCoder consistently outperforms ChatDev (Qian et al., ACL 2024) and MetaGPT (Hong et al., ICLR 2024) across all evaluation settings on Paper2CodeBench: on reference-based scores, PaperCoder leads by 0.7–1.2 points (e.g., 3.83 vs. 2.96 on NeurIPS), and on reference-free scores by 0.6–1.2 points (e.g., 4.77 vs. 4.01 on NeurIPS). The gap is particularly large in reference-based evaluation, where ChatDev and MetaGPT score around 2.5–3.0 while PaperCoder reaches 3.7–3.8, suggesting that their bottom-up, role-playing/SOP-based strategies struggle with the loosely structured nature of scientific papers. On PaperBench Code-Dev, PaperCoder (45.14% with o3-mini; 51.14% with Claude 3.5 Sonnet) substantially surpasses the benchmark's own BasicAgent (5.1% / 35.4%) and IterativeAgent (16.4% / 27.5%) baselines, with margins of 30–40 percentage points. In human evaluation, PaperCoder achieves a mean score of 4.60–4.76 (out of 5) and a mean rank of 1.04–1.22, while ChatDev and MetaGPT score only 2.12 with ranks of 2.43, confirming the model-based findings with expert paper authors as judges.

## Relation to Prior Work

PaperCoder carves out a new niche at the intersection of repository-level code generation and LLM-powered scientific research. It departs from multi-agent software development frameworks like ChatDev and MetaGPT, which operate bottom-up from short requirement descriptions via role-playing or SOPs, by instead working top-down from full scientific papers through a structured planning→analysis→coding pipeline. It also distinguishes itself from prior LLM-for-science efforts (AI Scientist, MLE-bench, AutoML-Agent) that assume access to existing codebases, by generating implementations entirely from paper text without any prior code, APIs, or supplementary materials. Concurrently, PaperBench (Starace et al., 2025) introduced an evaluation benchmark for paper-to-code replication, but PaperCoder complements it by focusing on the methodological pipeline rather than evaluation metrics.

## Why It Matters / Open Questions

With only ~19.5% of top-tier ML papers releasing code, this work directly addresses a major reproducibility bottleneck by producing near-author-quality repositories (statistically indistinguishable from Oracle in reference-free evaluation) at a cost of ~$0.90 per paper. The introduced Paper2CodeBench (90 papers from ICLR/ICML/NeurIPS 2024) provides a reusable evaluation resource for the community. Key limitations include handling only textual inputs (not figures/tables), restricting scope to ML, and not fully automating environment setup; open questions include extending to visual content, other scientific domains, and improving end-to-end executability beyond the current 0.81% modification rate.
