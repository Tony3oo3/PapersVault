## Problem

Weather foundation models operate exclusively on structured numerical data and lack natural language interfaces, while LLMs cannot reason over high-dimensional spatiotemporal meteorological datasets. No existing system successfully unifies meteorological data access with interactive language-based reasoning for broad scientific workflows, creating a barrier that limits non-expert participation in weather science.
![Teaser figure](../imgs/ICLR20265311/cropped_page1_idx0.webp)

## Input / Output

The agent receives a natural language weather question along with pre-sliced ERA5 reanalysis data (1.5° spatial, 6-hourly temporal, 1979–2022, 4 surface + 5 atmospheric variables at 13 pressure levels) from WeatherBench 2, with time dimensions converted to integer indices. The agent produces a Python `run` function that accepts xarray datasets plus Geolocator, Forecaster, and Simulator objects, and returns answers in diverse formats: SI-unit numerical values, geographic location names, boolean judgments, time offsets in hours, or multi-paragraph descriptive forecast reports. A FastAPI code execution server orchestrates parallel tool invocation with resource pooling and timeout protection.

## Method

ZEPHYRUSWORLD provides a unified Pythonic agentic environment exposing five tools—WeatherBench 2 data indexer, Geolocator (forward/reverse geocoding via Natural Earth), Stormer forecaster (transformer-based, ≤2-week range), JCM climate simulator (NeuralGCM dynamical core, T32, ~25 s for 5-day runs on A100), and a precomputed climatology module (means, quantiles, extrema across multiple timescales for 1979–2000). Two agent variants leverage this environment via in-context learning: ZEPHYRUS-DIRECT generates a complete Python solution in one shot (PAL-style), while ZEPHYRUS-REFLECTIVE implements a multi-turn ReAct loop where the agent executes code blocks, observes outputs, assesses scientific plausibility, and iteratively refines its approach (up to 20 turns). Both variants include an automatic error-correction loop that feeds execution errors back to the LLM for regeneration. The accompanying ZEPHYRUSBENCH (2,230 QA pairs, 49 task types) is constructed via a semi-synthetic pipeline that extracts verifiable claims from NOAA reports, converts them into parameterized templates, and generates ground-truth answers through human-verified code applied to raw ERA5 data.

## Results

On ZEPHYRUSBENCH (2,230 questions across 49 tasks), ZEPHYRUS agents achieve 27.8–44.2 percentage points higher correctness than text-only baselines across all five LLMs tested. For GPT-5-Mini, ZEPHYRUS-DIRECT reaches 58.5% and ZEPHYRUS-REFLECTIVE 61.2% correctness, versus only 17% for the text-only baseline. Performance stratifies sharply by difficulty: 76.2–90.9% on Easy tasks, 49.3–63.5% on Medium, and only 14.2–37.7% on Hard tasks. The best location accuracy is 90.4% (ZEPHYRUS-REFLECTIVE + GPT-5.2), while the best discussion score for report generation is just 0.27, indicating that long-form meteorological reasoning remains a major open challenge.

## Baselines & Comparisons

The primary baseline is a text-only LLM that answers weather questions using only its parametric knowledge, with no access to ERA5 data or any tool. ZEPHYRUS agents (both Direct and Reflective variants) outperform this baseline by 27.8–44.2 percentage points in correctness across all five LLMs, confirming that programmatic access to structured meteorological data is essential rather than the LLM's prior knowledge. Between the two agent variants, ZEPHYRUS-REFLECTIVE (iterative execute-observe-refine) edges out ZEPHYRUS-DIRECT (single-shot code generation) by 0.8–2.7% with OpenAI models (GPT-5.2, GPT-5-Mini), but the advantage reverses for Qwen3-30B and Gemini 2.5 Flash, suggesting the iterative loop helps most when the base model has strong code-generation ability. On numerical tasks, the Reflective variant with GPT-5.2 achieves a median standardized absolute error of 0.02 (vs. 0.33 for text-only), and on location tasks it reaches 90.4% accuracy. However, on the hardest tasks—global 3-month climate forecast reports and ENSO outlooks—all models fail completely (discussion score near 0), and even the best report-generation score is only 0.27, far below the 0.5 correctness threshold.

## Relation to Prior Work

This paper extends the program-aided LM paradigm (PAL, Gao et al. 2023) and the ReAct execution-observation loop (Yao et al. 2023) to the domain of weather science, where no prior agentic system existed. It departs from the multimodal weather-language model line (e.g., Aquilon, Varambally et al. 2025) by not attempting to fuse weather data into the LLM's input space; instead, the LLM generates Python code that calls specialized tools (forecaster, simulator, geolocator, climatology) in a sandboxed execution environment. Conceptually, it parallels agentic frameworks in chemistry (ChemCrow) and biomedicine (Biomni) but is the first to target meteorology, where the high-dimensional spatiotemporal structure of atmospheric data makes direct multimodal integration particularly challenging.

## Why It Matters / Open Questions

ZEPHYRUSBENCH (2,230 QA pairs across 49 task types) provides the first comprehensive, reproducible benchmark for evaluating LLM agents on realistic meteorological workflows, and ZEPHYRUSWORLD's modular tool architecture is a practical platform that could extend to hydrology, geosensing, and broader climate science. The stark performance gap between easy tasks (76–91% correct) and hard tasks (14–38% correct), combined with the ground-truth-forecaster ablation showing that even perfect forecast data does not rescue report-generation performance, reveals that the current bottleneck is the LLM's ability to synthesize and interpret multi-variable atmospheric patterns rather than data access. Open questions include whether longer-horizon reasoning, better tool-selection policies, or domain-specific fine-tuning can close the gap on hard tasks, and whether the code-execution paradigm generalizes to other scientific domains with similarly structured numerical data.
