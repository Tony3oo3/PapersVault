## Problem

Existing static safety benchmarks and manually designed jailbreak tools are inadequate for systematically uncovering vulnerabilities in LLM-based code agents, as they cannot cover boundary conditions such as combined tool effects and become outdated as agents evolve. Moreover, for code agents, a successful attack requires not merely bypassing rejection but generating and executing correct code that performs the intended risky function, a requirement that static evaluation methods and general-purpose jailbreak baselines do not address.

## Input / Output

RedCodeAgent takes a risk scenario (e.g., 'delete sensitive files') and a natural-language test case prompt as input, and produces an optimized red-teaming prompt that is submitted to the target code agent. The evaluation output is a three-way classification (attack success, rejection, or execution failure) determined by running the target agent's generated code inside a Docker sandbox and checking concrete filesystem or program-state outcomes via dedicated evaluation scripts, rather than relying on LLM-as-a-judge. Successful attacks are additionally logged as structured memory entries containing the full interaction trajectory, tool-call details, and a self-reflection summary for future retrieval.

## Method

RedCodeAgent is a ReAct-style LLM agent (GPT-4o-mini on LangChain) that iteratively refines attack prompts through a loop of tool calls and target-agent queries, guided by three components. A memory module stores past successful attacks and retrieves the top-K most similar entries via cosine similarity on risk-scenario and risk-description embeddings, with a penalty term on trajectory length to favor efficient attacks. A toolbox integrates a Code Substitution tool (which queries multiple code LLMs to generate alternative implementations that bypass guardrail blacklists, e.g., replacing os.remove with pathlib.Path.unlink) alongside general jailbreak tools (GCG, AmpleGCG, Advprompter, AutoDAN, FlipAttack). An evaluation module runs the target agent's output in a Docker sandbox with per-risk-scenario evaluation scripts to verify actual execution outcomes, providing detailed feedback (e.g., 'file still exists') that drives further prompt optimization. The agent dynamically selects and combines tools based on task difficulty and retrieved experiences, achieving 72.47% ASR on RedCode-Exec against OpenCodeInterpreter versus 55.46% for the best static baseline.

## Results

On RedCode-Exec (810 test cases) against the OpenCodeInterpreter agent, RedCodeAgent achieves 72.47% attack success rate (ASR) and 7.53% rejection rate (RR), substantially outperforming the best static jailbreak baseline GCG (54.69% ASR, 12.84% RR). Against the ReAct agent, RedCodeAgent reaches 75.93% ASR with only 2.96% RR on RedCode-Exec, and 81.52% ASR on RedCode-Gen. On RMCbench (182 text-to-code cases), RedCodeAgent achieves 69.78% ASR against OCI and 71.42% against ReAct, again leading all baselines. RedCodeAgent also demonstrates effectiveness on real-world assistants (Cursor: 72.72% ASR; Codeium: 69.88% ASR) and across C, C++, and Java (80–89% ASR).

## Baselines & Comparisons

RedCodeAgent outperforms all five jailbreak baselines (GCG, AmpleGCG, Advprompter, AutoDAN, FlipAttack) on every benchmark and target agent combination. The largest margins appear on RedCode-Exec against OCI, where RedCodeAgent (72.47% ASR) exceeds GCG (54.69%) by ~18 points and AutoDAN (29.26%) by ~43 points. Notably, several baselines perform worse than the no-jailbreak static baseline on code tasks (e.g., AutoDAN drops to 1.88% ASR on RedCode-Gen/OCI vs. 9.38% without jailbreak), confirming that generic jailbreak suffixes can disrupt code generation. Even with up to three retry rounds, no baseline surpasses RedCodeAgent (Table 2: best retry baseline GCG-retry reaches 59.14% vs. RedCodeAgent's 72.47%). A sequential combination of all five baselines (68.64% ASR, 337 s average time) is still outperformed by RedCodeAgent (72.47% ASR, 121 s), which selectively invokes tools based on task difficulty and memory-retrieved experience.

## Relation to Prior Work

RedCodeAgent builds on the ReAct agent loop (Yao et al., 2023) and retrieval-augmented memory (Lewis et al., 2020) to create an adaptive red-teaming agent, but departs from prior jailbreak work (GCG, AmpleGCG, AutoDAN, Advprompter) by treating them as callable tools within a larger decision-making framework rather than standalone attack methods. The key conceptual departure from prior red-teaming literature (e.g., RedAgent for static LLMs, AgentPoison for memory poisoning) is the focus on code agents where attack success requires both non-rejection and correct code execution in a sandbox, necessitating an execution-based evaluation module and a code-substitution tool that has no analogue in general NLP jailbreaking. The paper also extends the agent safety benchmarking line (RedCode-Exec, RMCbench) by replacing static test-case evaluation with an interactive, iterative attack process.

## Why It Matters / Open Questions

As code agents (Cursor, Codeium, OpenCodeInterpreter) become embedded in sensitive development environments, this work provides a scalable, automated methodology for stress-testing their safety before deployment. A notable open question is the near-total ineffectiveness of existing defenses (LlamaFirewall, LlamaGuard) against adaptive red-teaming, suggesting the field needs fundamentally new defensive paradigms for agentic code generation. Limitations include reliance on a single base LLM (GPT-4o-mini) for the agent itself, evaluation on a relatively small set of risk scenarios (27 in RedCode-Exec), and the semi-automatic evaluation of commercial agents due to API constraints. Future work could explore whether the memory-based adaptation generalizes to multi-agent code systems or whether the code-substitution tool's effectiveness persists as target agents adopt more sophisticated guardrails.
