## Problem

MLLMs remain significantly below chance on multi-view 3D spatial reasoning tasks (e.g., determining relative object positions across viewpoints or egocentric motion), where the environment is only partially observed and models must reason across perspectives. Existing approaches either rely on implicit 'imagination' mechanisms (spatial mental models, cognitive maps) that offer limited gains, or target single-view spatial understanding, leaving the more challenging multi-view 3D setting largely unaddressed. The central question is how to equip MLLMs with explicit, geometrically grounded reasoning in 3D space without gradient-based fine-tuning.

## Input / Output

The method takes a sequence of N RGB images (each H×W) capturing partial observations of a 3D scene, along with a natural-language query about spatial relations or camera movements. The code agent produces an executable Python program (a function taking a Scene object) that, when run, yields an intermediate visual clue — text, a single rendered image, or a list of novel-view images — which the MLLM then combines with the original inputs to produce the final text answer. The generated program is itself an interpretable artifact with structured comments, and the framework supports control-flow constructs (for-loops, conditionals) for multi-step exploration.

## Method

pySpatial is a zero-shot visual programming framework in which an MLLM (default: GPT-4o) acts as a code-generation agent that synthesizes Python programs calling a fixed set of spatial tools through a well-defined API. The three core tools are: (1) feed-forward 3D reconstruction (VGGT for normalized scenes, CUT3R for metric-scale), which back-projects pixels into a world-coordinate point cloud with camera intrinsics and SE(3) extrinsics; (2) camera description, which converts relative pose displacements into discretized natural-language motion labels (forward, left, diagonals, etc.); and (3) novel view synthesis, which rasterizes the point cloud from arbitrary camera poses (rotations, translations, 180° turns) using Open3D. The generated program is executed by a Python interpreter to produce concrete visual evidence, which the MLLM integrates with the original images and query to answer. The framework requires no fine-tuning, uses only in-context examples (query-code pairs without ground-truth answers) to guide synthesis, and separates high-level reasoning from low-level execution by exposing only the public API to the code agent.

## Results

On the full MINDCUBE benchmark, pySpatial achieves 58.56% overall accuracy, outperforming the strongest proprietary model GPT-4.1-mini (45.62%) by 12.94% and the best open-weight model DeepSeek-VL2-Small (47.62%) by 10.94%. On MINDCUBE-1k, pySpatial reaches 62.35% overall accuracy, surpassing the best spatial mental model (Cognitive Map, 41.43%) by ~21% and the best prior visual programming approach (VADAR, 40.76%) by 21.9%. On the single-view OMNI3D-BENCH, pySpatial sets a new state-of-the-art with a total score of 44.2, exceeding VADAR (40.4) by 3.8% and GPT-4o (42.9) by 1.3%.

## Baselines & Comparisons

pySpatial wins decisively across all baseline categories on MINDCUBE: it outperforms the best open-weight model (DeepSeek-VL2-Small, 47.62%) by 10.94%, the strongest proprietary model (GPT-4.1-mini, 45.62%) by 12.94%, and the best specialized spatial model (VLM-3R, 42.09%) by 16.47%, all in a zero-shot setting without any fine-tuning. On MINDCUBE-1k, pySpatial (62.35%) surpasses all spatial mental models from Yin et al. (2025) by roughly 20%—Cognitive Map (41.43%), Chain-of-Thought (40.48%), and View Interpolation (37.81%)—and beats the prior visual programming baselines VADAR (40.76%) by 21.9% and ViperGPT (36.95%) by 25.4%. Notably, even VADAR re-implemented with pySpatial's 3D reconstruction module (VADAR w/ Recon., 35.62%) underperforms pySpatial, indicating that the compositional 3D tool design matters beyond simply having 3D information available. On OMNI3D-BENCH, pySpatial (44.2 total) edges out GPT-4o (42.9) and VADAR (40.4), while substantially outperforming ViperGPT (26.7) and VisProg (13.5). The ablation in Table 4 confirms that pySpatial consistently improves any MLLM code agent: GPT-4o jumps from 42.29% to 62.67%, GPT-4.1-mini from 43.34% to 58.19%, and GPT-4.1 from 44.67% to 62.35% on MINDCUBE-1k.

## Relation to Prior Work

pySpatial extends the visual programming paradigm introduced by ViperGPT and VisProg—where MLLMs generate executable Python code to compose visual tools—from 2D image manipulation to explicit 3D spatial reasoning. It departs from VADAR, the closest prior work on spatial visual programming, by designing a multi-view 3D API (3D reconstruction, camera pose manipulation, novel view synthesis) rather than a single-view adaptive API, and by grounding reasoning in reconstructed point clouds rather than 2D image operations. The framework also contrasts with spatial mental models (Yin et al., 2025), which rely on implicit MLLM 'imagination' of 2D cognitive maps, by making 3D reasoning explicit through executable geometric operations.

## Why It Matters / Open Questions

The key practical implication is that a zero-shot, plug-and-play visual programming framework can outperform both proprietary MLLMs and fine-tuned spatial models (e.g., VLM-3R) by 10–16% margins, suggesting that explicit 3D tool use may be a more scalable path to spatial reasoning than further fine-tuning on synthetic spatial data. The real-world robot navigation validation demonstrates transferability beyond benchmarks. However, 13% of errors stem from 3D reconstruction quality and 20% from the final MLLM reasoning step, indicating that gains will be tightly coupled to advances in feed-forward reconstruction and code-generation models. Open questions include scalability to dynamic scenes, outdoor environments, and whether the framework can handle longer-horizon multi-step navigation without manual velocity conversion.
