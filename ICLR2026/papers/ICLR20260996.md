## Problem

LLM-based conversational agents remain vulnerable to user-induced errors (ambiguous references, unsupported requests) that derail multi-turn interactions, yet production constraints prohibit modifying model parameters or carefully tuned system prompts. Prior work has focused on error prevention rather than recovery, leaving the question of how agents can diagnose and correct contextually flawed interactions under fixed-parameter, fixed-prompt conditions largely unexplored.

## Input / Output

The inception module consumes the surface-level dialogue context (observable user-agent turns), the current user utterance, the available tools list, and a predefined error-to-recovery-plan mapping (Φ), producing either a 'No' signal or a fully instantiated recovery plan ρ_t. This plan is wrapped as a single 'think' cognitive operation and prepended to the task agent's internal context (which also contains intermediate tool calls and outputs) before the first action-sampling step of the turn. The agent then proceeds autonomously, producing its natural-language response and any subsequent tool invocations without further external intervention.

## Method

REIN is a test-time intervention that injects a single reasoning block into a fixed-parameter agent's internal context to guide error recovery. An external inception module (a separate LLM) performs two deterministic stages in one call: detecting whether a predefined error type is present in the dialogue context and generating a contextually adapted recovery plan from a finite mapping Φ. The plan is injected as a 'think' operation before the agent's first sampling iteration, after which the agent acts autonomously under its original system prompt and policy. A critical design choice is defining recovery plans as JSON-schema tools rather than free-text instructions; this allows REIN to override the instruction hierarchy (which normally assigns tool outputs the lowest priority), whereas a text-only recovery strategy achieves 0% task completion. The method requires no fine-tuning, no system-prompt modification, and operates as a one-shot per-turn intervention that can be applied dynamically at any turn.

## Results

Using Pass@1 as the primary metric on τ-Bench (98 sessions, 588 contexts across airline and retail domains), REIN substantially improves task completion over the no-intervention baseline. Without REIN, ambiguous scenarios yield nearly 0% success, while unsupported scenarios achieve only ~20% (due to a brief escalation mention in the original system prompt). With REIN applied via Sonnet 3.7 as the inception module, performance rises sharply across all four seen error types (Anaphora, Multiple Interpretation, Action, Parameter) and generalizes to unseen types (Contradiction, Domain). In the instruction-hierarchy ablation (§4.6), removing the dedicated recovery tool drops REIN's task completion to 0%, confirming that tool-defined recovery plans are essential for the intervention to override the system prompt.

## Baselines & Comparisons

The paper compares REIN against three baselines: (1) no intervention (lower bound), (2) Naive Prompt Injection (NPI), which appends explicit error-recovery instructions to the system prompt, and (3) Self-Refine (SR, Madaan et al. 2023), which iteratively generates feedback and revises the agent's response. All three prompt-modifying or no-intervention baselines underperform REIN: NPI and SR both improve over the no-REIN baseline but achieve lower Pass@1 than REIN across both airline and retail domains (Figure 4). REIN's advantage is most pronounced in ambiguous scenarios, where the no-REIN baseline is near 0% and NPI/SR provide only partial recovery, whereas REIN consistently reaches the highest completion rates. Additionally, REIN generalizes to unseen error types (Contradiction, Domain) that share recovery strategies with seen types, a capability neither NPI nor SR is designed to provide. The instruction-hierarchy experiment further shows that REIN with a properly defined recovery tool outperforms a tool-free augmented response strategy (0% vs. substantial completion), demonstrating that the tool-based mechanism is what enables REIN to safely override the system prompt's priority ordering.

## Relation to Prior Work

This paper extends the long-standing line of conversational error recovery research from spoken dialogue systems (where errors were primarily ASR-induced) to LLM-based agents facing user-originated behavioral errors (ambiguous and unsupported requests). It departs from prior agent-side mitigations (clarification, fallback) by explicitly targeting the recovery phase rather than prevention, and from prompt-injection and RAG literature by operating as a constrained, tool-mediated test-time intervention that respects the instruction hierarchy. The method repurposes τ-bench (Yao et al., 2025) into a controlled error-recovery evaluation environment, and positions itself against Self-Refine (Madaan et al., 2023) and naive prompt modification as baselines, carving out the niche of fixed-parameter, fixed-prompt agents that cannot be retrained or re-prompted in production.

## Why It Matters / Open Questions

REIN addresses a practically critical gap: deployed LLM agents cannot be retrained or have their system prompts modified without costly revalidation, yet they must handle unpredictable user errors. The finding that REIN's effectiveness depends critically on being paired with a defined recovery tool (0% success without one, substantial gains with one) reveals a concrete mechanism for safely overriding instruction hierarchy, which has direct implications for how service providers can steer agent behavior. Open questions include scaling the predefined error taxonomy to the long tail of real-world failures, reducing reliance on LLM-based user simulators, and extending toward fully autonomous self-monitoring agents that detect errors without an external inception module.
