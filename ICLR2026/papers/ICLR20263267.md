## Problem

Existing scene graphs for embodied agents suffer from three critical gaps: they encode only a single relationship type (spatial or functional, but not both), treat scenes as static snapshots without modeling object states or temporal updates, and ignore task relevance by representing all objects equally rather than highlighting those needed for the current instruction. Additionally, the field lacks both a large-scale dataset with richly annotated, task-driven scene graphs and a systematic benchmark to evaluate whether such representations actually improve planning.

## Input / Output

The model receives a set of multi-view RGB images (flexible number of viewpoints, not guaranteed to contain all relevant objects in any single view) together with a natural language instruction expressed in simple, implicit form (e.g., 'Fill the bathtub' without naming the faucet or drain button). It outputs a JSON-structured task-oriented scene graph containing task-relevant object nodes plus part-level interactive elements (handles, knobs, buttons), directed edges annotated with both spatial relations (9 types: directional and distance-based) and functional relations (6 types: OPEN/CLOSE, ADJUST, CONTROL, ACTIVATE, POWER BY, PAIR WITH), an action type, and a function type. Under the Graph-then-Plan paradigm, this graph then conditions a second-stage generation of a structured, ordered action sequence.

## Method

MomaGraph-R1 is a 7B VLM built on Qwen2.5-VL-7B-Instruct and trained with the DAPO reinforcement learning algorithm using a custom graph-alignment reward that jointly scores action-type correctness, spatial-functional edge similarity (matching predicted edges to ground-truth edges on both relation labels simultaneously), and node completeness via IoU, plus format and length penalties. The key architectural insight is the Graph-then-Plan framework: the single VLM first generates a compact, task-specific scene graph as an explicit intermediate representation, then performs high-level planning conditioned on that graph, rather than planning directly from raw pixels. A state-aware dynamic update mechanism refines the graph after each executed action by pruning inconsistent one-to-many functional hypotheses (e.g., resolving which of several stove knobs actually controls the target burner) based on observed state transitions. Training uses 8×80GB A100 GPUs for ~13 hours (25 epochs, 175 steps) on MomaGraph-Scenes (~1,050 subgraphs, 6,278 multi-view images across 350+ household scenes and 93 task instructions), with the reward converging to ~0.93 and format reward reaching 1.0 within 25 steps.

## Results

On MomaGraph-Bench, MomaGraph-R1 achieves 71.6% overall accuracy under the Graph-then-Plan setting, surpassing all open-source baselines by a wide margin (best open-source baseline: Qwen2.5-VL-7B at 60.2%) and matching closed-source GPT-5 (71.6%) and Gemini-2.5-Pro (71.6%), while trailing Claude-4.5-Sonnet (73.9%) by 2.3 points. The Graph-then-Plan framework yields consistent gains across all models, with MomaGraph-R1 improving from 65.1% (w/o Graph) to 71.6% (w/ Graph), a +6.5 point boost. On the BLINK visual correspondence benchmark, MomaGraph-R1 scores 63.5%, leading all open-source models by 3.8 points over the best competitor (Qwen2.5-VL at 58.7%).

## Baselines & Comparisons

MomaGraph-R1 (7B, built on Qwen2.5-VL-7B-Instruct) outperforms its base model by +11.4 points overall (71.6% vs. 60.2% w/ Graph), demonstrating the effectiveness of DAPO reinforcement learning with graph-alignment rewards. Among open-source models, it leads LLaVA-Onevision-7B by 16.0 points (71.6% vs. 55.6%), DeepSeek-VL2 by 17.3 points, and InstructBLIP-7B by 32.1 points. Against closed-source systems, MomaGraph-R1 ties GPT-5 and Gemini-2.5-Pro at 71.6% overall and trails Claude-4.5-Sonnet by 2.3 points (73.9%), a remarkably small gap for a 7B open-source model. Notably, MomaGraph-R1 exhibits the smallest performance degradation from Tier 1 to Tier 4 (76.4% → 68.1%, an 8.3-point drop) compared to open-source baselines that lose 15–25 points, indicating superior scalability to complex multi-step planning. On BLINK, MomaGraph-R1 leads all open-source models by 3.8 points (63.5% vs. 58.7% for Qwen2.5-VL), confirming that scene-graph-structured reasoning also improves fine-grained visual perception.

## Relation to Prior Work

This paper extends the scene graph literature for 3D indoor understanding (ConceptGraphs, Open3DSG, Lang3DSG) by unifying spatial and functional edge types into a single graph, adding part-level interactive nodes, and conditioning the entire structure on a natural language task instruction. It departs from prior Graph-then-Plan approaches (SayPlan, VeriGraph) that either assume a pre-built reliable scene graph or treat graph construction and planning as separate modules, instead training a single VLM via DAPO reinforcement learning to jointly generate the graph and plan from it. The RL training builds directly on the DAPO framework, with a custom graph-alignment reward that scores action type, spatial-functional edge similarity, and node completeness against ground-truth task-oriented subgraphs.

## Why It Matters / Open Questions

The paper addresses a genuine gap: prior scene graphs for robotics were either spatial-only or functional-only, static, and task-agnostic, making them insufficient for mobile manipulators that must reason about both where objects are and how they can be used. The MomaGraph-Scenes dataset (~1,050 subgraphs, 6,278 multi-view images) and MomaGraph-Bench (294 scenes, 1,315 instances across four difficulty tiers) provide the first systematic evaluation of task-oriented scene graph reasoning, which the community has lacked. Open questions include whether the state-aware dynamic update mechanism scales to truly long-horizon multi-object interactions, whether the 70% real-robot success rate on complex tasks is sufficient for practical deployment, and whether the gap to closed-source models will persist as open-source VLMs continue to scale.
