## Problem

While computer-using agents have shown promise on general desktop benchmarks, no prior work provides a realistic, visually rich environment for evaluating these agents on the complex, multi-step workflows that scientists actually perform with professional software. Existing scientific benchmarks focus on static QA or single-step coding, failing to capture the dynamic GUI/CLI interaction, spatial reasoning, and domain-specific tool manipulation required in real research pipelines. SCIENCEBOARD asks whether current SOTA agents can reliably execute end-to-end scientific tasks in a live operating system environment.

## Input / Output

The agent receives a natural-language instruction (avg. 20 words) and perceives the environment through one of four observation modalities: full 1920×1080 desktop screenshots, a filtered accessibility tree (a11ytree) via pyatspi, a combined screenshot+a11ytree, or Set-of-Marks annotated screenshots. The agent outputs a sequence of actions from a unified space spanning GUI primitives (click, drag, keystroke), system-level and application-specific CLI commands, API calls, and special control tokens (DONE, FAIL, WAIT, ANS). Task completion is verified not by output string matching but by querying the internal runtime state of the scientific software through an injected HTTP server, supporting exact matching, range checks, numerical tolerance, and file comparison.

## Method

SCIENCEBOARD builds a scalable Ubuntu 22.04 VM environment pre-loaded with six open-source scientific applications (ChimeraX, KAlgebra, Lean 4, GrassGIS, Celestia, TeXstudio), each modified to expose internal states via a lightweight HTTP server for state-based evaluation. The benchmark comprises 169 expert-curated tasks across six domains, with a five-stage annotation pipeline including tutorial learning, task curation, formalization, configuration function writing, and cross-validated evaluation function writing. The agent is modeled as a POMDP with a unified action space integrating GUI, CLI, and API interactions, and is driven by LLM/VLM policy models using ReAct-style prompting. The paper evaluates 15+ backbones (proprietary, open-source VLMs, and specialized GUI action models) across all observation settings, and further explores a modular planner+grounding decomposition where a reasoning model generates high-level plans and a separate VLM handles visual grounding, showing significant performance gains over monolithic agents.

## Results

On SCIENCEBOARD (169 tasks across 6 scientific domains), the best-performing agent (GPT-5 under Screenshot+a11ytree observation) achieves only 24.20% overall success rate, far below the 60.27% human baseline. GPT-5.5 reaches 18.31% under Screenshot-only, while Claude-Opus-4.6 peaks at 14.58% (Screenshot) and Gemini-2.5-Pro at 16.98% (Screenshot+a11ytree). Open-source models trail significantly, with Qwen2.5-VL-72B at 11.74% and InternVL3-78B at just 3.20% under the best observation setting. Performance is highly domain-dependent: Biochemistry is the easiest (up to 68.97% for Claude-Opus-4.6) while GIS and Theorem Proving remain near 0% for most agents.

## Baselines & Comparisons

Among proprietary models, GPT-5 dominates under Screenshot+a11ytree (24.20% overall), outperforming Gemini-2.5-Pro (16.98%), Claude-3.7-Sonnet (15.79%), and GPT-4o (14.45%) by 7–10 percentage points; however, under Screenshot-only, GPT-5.5 (18.31%) edges out GPT-5 (9.20%), suggesting the newer model benefits less from the combined observation. Claude-Opus-4.6 is the standout in Biochemistry (68.97%, matching human level) but collapses to 0% on ATP and near-0% on GIS. Open-source VLMs (Qwen2.5-VL-72B at 11.74%, InternVL3-78B at 3.20%) consistently trail their proprietary counterparts by 5–20 points, with InternVL3-78B performing particularly poorly across all domains. GUI action models as standalone agents are weakest: UI-TARS-1.5-7B achieves only 2.69% and QvQ-72B-Preview a mere 0.49%, confirming that specialized grounding models lack the planning and domain knowledge needed for scientific workflows. In the planner+grounding ablation (Table 4), GUI-Actor-7B as a grounding module with GPT-4o as planner reaches 20.44% overall—nearly matching GPT-5's standalone performance—demonstrating that modular decomposition partially compensates for individual model weaknesses. All agents remain 36–57 points below the 60.27% human baseline, with the largest gaps in GIS (55.88% human vs. ≤11.76% agent) and ATP (42.31% human vs. ≤7.69% agent).

## Relation to Prior Work

This paper carves new ground at the intersection of two established lines of work: computer-using agent evaluation (OSWorld, AndroidWorld, WebArena) and AI-for-science benchmarking (ScienceQA, SciCode, ScienceAgentBench). Prior agent benchmarks evaluate general desktop or web tasks, while prior scientific benchmarks are largely static QA or coding exercises. SCIENCEBOARD departs from both by constructing a dynamic, visually-rich Ubuntu VM environment with six professional scientific applications (ChimeraX, KAlgebra, Lean 4, GrassGIS, Celestia, TeXstudio) where agents must perform multi-step workflows via both GUI and CLI, evaluated through fine-grained VM state inspection rather than answer matching. The POMDP formulation and ReAct-style interaction follow standard agent conventions, but the dual-interface (GUI+CLI) action space and the injected lightweight HTTP server for state retrieval are novel infrastructure contributions.

## Why It Matters / Open Questions

The 20% SOTA success rate versus 60% human performance reveals a substantial and previously unquantified gap between general computer-use ability and scientific workflow competence, suggesting that domain knowledge is a capability axis orthogonal to planning and grounding. The finding that agents strong on OSWorld do not transfer to scientific tasks, and that Set-of-Marks prompting can actually hurt in dense scientific UIs, provides concrete design guidance for the next generation of scientific agents. Open questions include how to introduce partial-credit evaluation for open-ended OS-level tasks, how to harmonize domain-specific knowledge with general agentic capability, and whether the framework can extend from digital to physical laboratory environments (lab-in-the-loop).
