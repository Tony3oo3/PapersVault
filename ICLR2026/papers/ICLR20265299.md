## Problem

Existing e-commerce agent benchmarks evaluate models on simplistic, single-type user issues with minimal or no domain rules, failing to reflect real-world scenarios where a single dialogue mixes multiple interaction types (QA, recommendation, task-oriented, chit-chat) and the agent must comply with dozens of fine-grained policies. This paper asks whether current LLM agents can handle such mixed-type, rule-heavy e-commerce dialogues and identifies the specific failure modes that prevent them from doing so.

## Input / Output

Each sample provides multi-modal files (customer-uploaded images for after-sales verification, product detail images and live-stream video clips for pre-sales), a user query, the full set of 82 domain rules, 18 API tools (retrieval, calculation, modification, interaction), and a hidden JSON database (logistics, order, product, merchant, user) accessible only through tool calls. The agent must produce a ReAct-format trajectory of thought-action-observation steps, a natural-language response to the user, and correct database state modifications; evaluation is binary per task via a Key Answer Score (all required facts present in dialogue) and a Database Score (final DB state matches ground truth, with GPT-4o judging remark-field equivalence).

## Method

The paper introduces Mix-ECom, a 4,799-sample benchmark built from 70,000 real customer-service dialogues through a pipeline of GPT-4o profile generation, demand classification, key-answer generation, rule filtering, and ReAct-format CoT rewriting, followed by three-stage quality control (manual profile filtering, GPT-4o rollout verification, and human meticulous review). The core architectural contribution is a Dynamic Module prepended to both ReAct and Plan-and-Solve loops: at every user-interaction boundary it receives the current conversational context, the full 82-rule policy set, and the accumulated trajectory, then emits a task-focused rule subset P^f ⊆ P and a pruned or revised trajectory/plan, shrinking the search space to suppress hallucination from irrelevant rules. E-ReAct applies this filtering before each reasoning step, while E-Plan&Solve additionally re-plans remaining sub-tasks after filtering, enabling adaptation to dynamically shifting user needs. Baselines use GPT-4o, Gemini-2.5-Pro, Claude-4-Sonnet, and Qwen-VL-MAX in 0-shot, plus a supervised-fine-tuned Qwen-2.5-VL 7B on the logistics and after-sales subsets.

## Results

On Mix-ECom, the best overall performance is achieved by Gemini-2.5-Pro under the E-Plan&Solve framework with a Total Score of 62.2% (requiring both correct key answers and correct database state). GPT-4o and Qwen-VL-MAX trail substantially, peaking at 49.2% under E-ReAct. Even the strongest model resolves fewer than two-thirds of tasks, and the fine-tuned Qwen-2.5-VL 7B reaches only 19.3% on Logistics and 17.7% on After-sales, underscoring the difficulty of the benchmark. The largest absolute gains from the dynamic rule-filtering module appear on Logistics tasks (e.g., +14.3 for Gemini-2.5-Pro under E-ReAct), where concise queries make rule selection more reliable.

## Baselines & Comparisons

The paper compares two vanilla agent frameworks—ReAct (Yao et al., 2023) and Plan-and-Solve (Wang et al., 2023)—against their dynamic-module-augmented counterparts (E-ReAct and E-Plan&Solve) across four closed-source MLLMs and one fine-tuned open-source model. E-ReAct consistently outperforms vanilla ReAct on every model: GPT-4o improves from 43.1→49.2, Gemini-2.5-Pro from 53.5→60.5, Claude-4-Sonnet from 63.0→69.4 (Logistics), and Qwen-VL-MAX from 47.5→49.2 (Total Score). Similarly, E-Plan&Solve beats Plan&Solve in all settings, with the largest gain for GPT-4o (39.8→43.8) and Gemini-2.5-Pro (58.9→62.2). The dynamic rule-filtering module yields the most pronounced benefit on Logistics tasks, where queries are concise and irrelevant rules are the primary source of hallucination; gains on After-sales and Pre-sales are more modest (1–4 points). Notably, the framework preference (ReAct vs. Plan&Solve) is model-dependent: GPT-4o and Qwen-VL-MAX favor ReAct, while Gemini-2.5-Pro and Claude-4-Sonnet favor Plan&Solve, suggesting that the optimal agent architecture interacts with the backbone's reasoning style.

## Relation to Prior Work

This paper extends the ReAct and Plan-and-Solve agent paradigms to the e-commerce customer-service domain by prepending a dynamic rule-filtering module that prunes irrelevant policies and hallucinated trajectory steps before each reasoning step. It departs from prior e-commerce benchmarks (Tau-retail, ECom-Bench, EcomScriptBench) by introducing mixed-type dialogues (QA, recommendation, task-oriented, chit-chat) within a single session, 82 fine-grained domain rules, and both image and video modalities, all grounded in 70,000 real-world customer-service conversations. The dynamic module is a lightweight architectural addition rather than a new reasoning paradigm, and the paper positions itself as filling the gap between simplified benchmark rules and the complexity of production e-commerce policies.

## Why It Matters / Open Questions

The finding that 63% of agent failures stem from domain-rule violations—rather than reasoning or tool-use errors—reframes the bottleneck in e-commerce agents as instruction-following under complex, interacting policies, a challenge that existing benchmarks with 0–32 rules do not capture. Even the strongest model (Gemini 2.5-Pro) reaches only 62.2% on the combined score, and the proposed dynamic filtering yields modest gains (~6 points), suggesting that rule compliance at this granularity remains an open problem. The publicly released dataset with multi-modal inputs, a logistics database, and 18 API tools provides a concrete testbed for future work on rule-aware agents, though the benchmark's reliance on GPT-4o for evaluation (Key Answer and Database scoring) introduces a potential circularity that limits interpretability.
