## Problem

Most LM agent research targets fully autonomous agents, leaving the human role in collaboration largely unexplored. Existing collaboration frameworks (e.g., CowPilot, τ²-Bench) assume turn-taking coordination and single task environments, failing to capture the asynchronous, dual-control dynamics of real human-agent teamwork. The paper asks whether human-agent collaboration is beneficial and how to design agents that collaborate effectively under these more natural interaction patterns.

## Input / Output

Each task is formulated as a POMDP where the step function accepts a role parameter (human or agent) and an action, returning observations split into public (shared workspace) and private (role-specific) components. Humans can send multiple consecutive messages without waiting for agent responses, and the agent receives programmatic notifications via a Redis-based event loop on four event types (shared observation updates, private changes, new messages, and idle-timeout). Outputs include the final task artifact (travel plan, related work section, or analytical report), normalized task performance scores, initiative entropy measuring balanced initiative-taking, and full collaboration trajectories with 6.3k actions and 77k words of communication across 150 real-world sessions.

## Method

Co-Gym defines a general environment interface (CoEnv) that supports dual control through a role-parameterized step function and a private flag distinguishing shared vs. private observation updates, enabling new task environments to be plugged in without modifying the coordination layer. Coordination is achieved through two meta-actions (SendTeammateMessage and WaitTeammateContinue) plus a notification protocol that broadcasts events asynchronously, removing turn-taking constraints. The best-performing agent architecture, Collaborative Agent with Situational Planning, employs a two-stage decision process: upon receiving a notification, the LM first performs a three-way classification (take task action / send message / wait) via few-shot prompting, then generates the specific action string, with a Scratchpad dictionary serving as in-session memory updated before each decision. All agents use ReAct-style prompting at temperature 0, and the framework is instantiated in both a simulated condition (LM-based user simulator with hidden per-instance information) and a real condition (interactive web application with chat panel and shared workspace), enabling controlled comparison across 4 LMs and 3 agent types.

## Results

In the real condition (Co-Gym Real), the Collaborative Agent with Situational Planning (GPT-4o) achieves win rates of 86% (Travel Planning), 66% (Related Work), and 74% (Tabular Analysis) against fully autonomous agents, with 100% delivery rate across all tasks. Overall Satisfaction ranges from 3.06 (Related Work) to 4.06 (Tabular Analysis) on a 5-point scale. In the simulated condition, the Situational Planning agent achieves significant Task Performance improvements over the same-LM autonomous baseline (e.g., +0.105 for Claude-3.5-sonnet in Travel Planning, +0.119 in Related Work), though at the cost of lower delivery rates due to coordination overhead. Error analysis reveals Communication failures in 65% and Situational Awareness failures in 40% of real trajectories.

## Baselines & Comparisons

The paper compares three agent architectures—Fully Autonomous Agent, Collaborative Agent, and Collaborative Agent with Situational Planning—powered by four LMs (GPT-4o, GPT-4-turbo, Claude-3.5-sonnet, Llama-3.1-70B) across three tasks. The Collaborative Agent with Situational Planning consistently outperforms the Fully Autonomous Agent in Task Performance with statistical significance (p < 0.05) for most LM-task pairs in the simulated condition, with the largest gains seen for Claude-3.5-sonnet (+0.105 Travel, +0.119 Related Work) and Llama-3.1-70B (+0.057 Travel, +0.048 Related Work). In the real condition, the Situational Planning agent (GPT-4o) achieves 86% and 74% win rates in Travel Planning and Tabular Analysis respectively, but only 66% in Related Work, where users' strong domain expertise leads to unbalanced initiative-taking (H_init = 0.63) and lower satisfaction (3.06/5). The plain Collaborative Agent (without Situational Planning) shows mixed results: it sometimes underperforms the autonomous baseline in delivery rate (e.g., GPT-4o drops from 0.873 to 0.745 in Travel Planning) and does not always achieve significant task performance gains. An ablation confirms that the non-turn-taking interaction paradigm itself contributes to the advantage, with Co-Gym achieving a 70% win rate over the turn-taking variant in both Travel Planning and Tabular Analysis.

## Relation to Prior Work

This paper departs from the dominant paradigm in LM agent research, which targets fully autonomous agents (WorkArena, τ-Bench, WebArena), by introducing dual-control, non-turn-taking collaboration within shared task environments. It builds on ReAct for agent implementation and Chu-Carroll & Brown's initiative framework for process evaluation, while extending the Scratchpad memory from Sumers et al. The closest prior work, CowPilot and τ²-Bench, also support dual-control but enforce turn-taking coordination and are limited to single environments (web navigation or database); Co-Gym relaxes the turn-taking constraint via a notification protocol and generalizes across multiple task types. Unlike prior agent benchmarks that evaluate only end-to-end task success, Co-Gym introduces process-level auditing (Initiative Entropy, Overall Satisfaction) alongside outcome metrics.

## Why It Matters / Open Questions

Co-Gym fills a clear infrastructure gap: before this work, there was no unified framework to study how LM agents collaborate with humans in shared workspaces using non-turn-taking interaction, and no evaluation suite that captures both collaboration quality and process dynamics. The finding that communication failures occur in 65% of real trajectories and situational awareness failures in 40% provides concrete, actionable targets for improving agent scaffolding (memory, planning) and underlying LMs. Open questions include whether the simulated-condition findings (lower delivery rate for collaborative agents) persist with better user simulators, how to close the communication gap without sacrificing autonomy, and whether the non-turn-taking paradigm generalizes beyond the three studied tasks to domains like creative design or real-time decision-making.
