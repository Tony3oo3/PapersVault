## Problem

RL post-training for free-form generation tasks is bottlenecked by the need to verify outputs against many task-specific rubrics: exhaustive enumeration is computationally prohibitive, and static reward models that collapse rubrics into a single scalar are prone to reward hacking because the optimal rubric weighting is prompt-specific. This paper asks how to provide scalable, verifiable, and prompt-adaptive training signals for open-ended generation without manually enumerating or hand-designing rewards.

## Input / Output

The generator takes a text instruction (a person's name for biography generation or a programming problem statement) and produces a free-form output—a fixed-length biography of 4 or 8 sentences, or a Python function. The critic takes the instruction–generation pair and outputs a single natural-language rubric (a specific factual claim to verify or a failing test case). An external validator (Wikipedia-based fact-checking for text, code execution against reference solutions for code) then returns a binary pass/fail signal that drives both models' DPO updates.

## Method

RLAC reformulates the generation objective as a two-player min-max game: the generator maximizes the probability of satisfying all rubrics, while the critic minimizes this by proposing the single most likely-failing rubric for each output. The key theoretical step rewrites the all-rubrics-satisfied indicator as a minimum over rubrics, then replaces the intractable search over the full rubric set with a learned stochastic critic policy, yielding an equivalent min-max objective that bypasses exhaustive enumeration. Both models are updated via DPO: the generator is rewarded when the critic's proposed rubric passes validation (output is correct), and the critic is rewarded when it correctly identifies a failing rubric. An external validator provides ground-truth binary feedback, ensuring rewards are always verifiable and on-policy rather than relying on a static learned proxy, which mitigates reward hacking.

## Results

On 8-sentence biography generation with Qwen3-8B, RLAC achieves a FactScore of 0.889, surpassing FactTune-FS (0.867) and ArmoRM (0.723), while requiring only 76,800 verification calls versus 438,949 for FactTune-FS (a 5.7× reduction). In code generation, RLAC achieves the highest average Pass@1 scores of 53.2 (Qwen2.5-Coder-7B-Base) and 56.6 (Qwen2.5-Coder-7B-Instruct) across HumanEval, MBPP, BigCodeBench, and LiveCodeBench, using only 9% of the training data and 97.5% fewer test executions than AceCoder-Rule. The efficiency gap grows with task complexity, from 4.4× fewer calls for 4-sentence to 5.7× for 8-sentence generation.

## Baselines & Comparisons

Against FactTune-FS (Tian et al., 2024), the enumerative verification baseline, RLAC wins on both accuracy and efficiency: it achieves a higher FactScore (0.889 vs. 0.867 on Qwen3-8B 8-sentence) while making 5.7× fewer verification calls (76,800 vs. 438,949). Against ArmoRM (Wang et al., 2024a), the multi-objective reward model baseline, RLAC substantially outperforms on FactScore (0.889 vs. 0.723), and the paper attributes ArmoRM's underperformance to reward hacking, evidenced by rising KL divergence without corresponding factuality gains. In code generation, RLAC outperforms both AceCoder-Rule (Zeng et al., 2025) and AceCoder-RM across the majority of benchmarks: on Qwen2.5-Coder-7B-Base, RLAC scores 53.2 average vs. 52.3 (AceCoder-Rule) and 49.1 (AceCoder-RM); on the Instruct variant, 56.6 vs. 55.9 and 55.3 respectively. Notably, AceCoder-RM actually degrades performance on HumanEval (91.5→89.0) due to reward hacking from noisy preference data, while RLAC consistently improves across all five code benchmarks despite using only 2,000 training problems (9% of the dataset).

## Relation to Prior Work

RLAC builds on the DPO objective (Rafailov et al., 2023) for policy optimization and the min-max adversarial reformulation from robust optimization (Madry et al., 2018), but departs fundamentally from both enumerative verification pipelines (FactScore, FactTune-FS) and static reward-model approaches (ArmoRM, AceCoder-RM). Rather than checking all rubrics or collapsing them into a fixed scalar, RLAC introduces a learned critic that dynamically selects which single rubric to verify per instance, with an external validator providing ground-truth feedback. This positions the work at the intersection of adversarial training, preference optimization, and verifiable RL, treating the LLM-as-a-judge paradigm not as a static scorer but as an active, co-trained agent.

## Why It Matters / Open Questions

RLAC addresses a core scalability bottleneck in RL post-training for free-form generation: the combinatorial explosion of rubrics makes exhaustive verification intractable, while static reward models suffer from reward hacking. The 4.4–6.8× reduction in verification calls with equal or better quality, combined with the finding that adversarial co-training prevents the generator from gaming a fixed critic, offers a practical path to scaling RL to domains where verification is expensive or non-enumerable. Open questions include whether the game converges to a stable equilibrium in more complex settings, how sensitive performance is to validator noise in the code domain, and whether the approach extends to multi-turn or agentic generation tasks where rubrics are not pre-defined.
