## Problem

Applying on-policy RL (e.g., GRPO) to multi-agent LLM systems is underexplored due to two coupled challenges: (1) standard GRPO's group-relative advantage estimation assumes all candidates in a group share an identical prompt, which breaks in MAS where prompts differ by role and turn position; and (2) existing RL training frameworks support only a single policy model, making it impossible to perform concurrent on-policy updates for multiple role-specialized agents. Prior MAS+RL works are restricted to single domains, single-turn interactions, or homogeneous agent roles.

## Input / Output

Each agent receives a role-specific prompt template that embeds the task description, current environment state (e.g., grid layout, code execution output, or problem statement), and the full cross-agent interaction history from prior turns. The system produces trained LLM policies—either a single shared policy or per-role specialized policies—that generate domain-specific outputs: Python code with unit tests (code tasks), boxed numeric answers (math), or action sequences like [U,R,D,L] (planning/games). Rollouts use K=4 candidate samples per agent per turn with a maximum response length of 4096 tokens and prompt lengths up to 16384 tokens for symbolic tasks.

## Method

AT-GRPO adapts group-relative policy optimization to MAS through three mechanisms: (1) tree-structured sampling, where at each turn each agent samples K candidate actions, computes group-relative advantages, then greedily selects the highest-reward action to continue the environment rollout—this ensures valid comparison groups of size K at every turn rather than degenerating to size-1 groups under parallel trajectory sampling; (2) agent- and turn-wise grouping, which keys each experience group by (agent_id, turn_number, environment_instance) via a hash function so that advantage normalization only compares candidates sharing identical role-specific prompts and interaction histories; and (3) agent-wise credit assignment, which combines a global team reward with a role-specific local reward (r = α·r_team + r_loc) to balance shared objectives with individual incentives. The supporting training system allocates an independent GPU resource pool (RolloutWorker + UpdateWorker) per policy model and a CPU environment pool for sandboxed execution, with a Router that dispatches each trajectory to the correct policy's UpdateWorker, enabling concurrent on-policy updates for both role-sharing (M=1) and role-specialized (M=N) configurations.

## Results

On Qwen3-8B, MAS+AT-GRPO achieves dramatic gains on long-horizon planning and game tasks: Plan-Path accuracy jumps from 12.0% (single-agent) to 93.0–96.0%, Sokoban from 9.0% to 96.0–98.0%, and Sudoku from 48.0% to 99.0–99.5%. On coding, LiveCodeBench improves from 22.8% to 30.3–33.1% and APPS from 30.2% to 45.8–46.5%. On math, AIME24 rises from 18.3% to 50.0–57.0% and AIME25 from 20.0% to 35.2–40.0%, with OlympiadBench reaching 56.6–56.8%.

## Baselines & Comparisons

Against MAPoRL (Park et al., 2025a) on GSM8K with Phi-3-mini, the untrained MAS already achieves 84.4% accuracy, surpassing MAPoRL's trained result of 81.0%; with AT-GRPO training, the gap widens to 88.7%. Against MARFT (Liao et al., 2025) on math with Qwen2.5-Coder-3B-Instruct, the untrained MAS (84.4%) outperforms MARFT's trained result (78.7%), and AT-GRPO further lifts performance to 87.1%. Against CURE (Wang et al., 2025a) on code generation with Qwen-2.5-7B-Instruct, the untrained MAS reaches 30.3% on CodeContests and 30.4% on LiveCodeBench, already exceeding CURE's 25.9% and 31.2% respectively; with AT-GRPO training, the method reaches 34.2% and 35.3%, a clear win on both benchmarks. Notably, the paper also shows that directly applying standard GRPO to MAS (MAS+GRPO) often degrades performance relative to the prompt-only MAS baseline (e.g., CodeContests drops from 17.60 to 10.30 on Qwen3-8B), underscoring that the agent- and turn-wise grouping in AT-GRPO is essential rather than a trivial extension.

## Relation to Prior Work

This paper extends group-relative policy optimization (GRPO) from single-agent LLM training to multi-agent systems, identifying that standard GRPO's identical-prompt grouping assumption breaks down when agents have role-specific contexts and divergent interaction histories. It builds on the HybridFlow-style training architecture (Sheng et al., 2025) but generalizes it to support concurrent on-policy updates for multiple policies. The algorithmic contribution departs from prior MAS-RL efforts (MAPoRL, MARFT, CURE, MARTI) by introducing tree-structured sampling and agent-and-turn-wise grouping to restore valid advantage comparisons, while also supporting both role-sharing and role-specialized policy configurations across heterogeneous workflows.

## Why It Matters / Open Questions

The paper provides the first general-purpose algorithm and training system for on-policy RL in diverse MAS workflows, with the practical finding that the choice between shared and role-specialized policies is task-dependent (specialization helps for distinct roles like Coder/Tester, while sharing helps for overlapping roles like Reasoner/Tool-User). A key open question is whether the greedy turn-level transition (justified under a monotonicity assumption on verifiable rewards) remains valid in settings where environment feedback is noisy or delayed. The dramatic planning gains (14–47% → 96–99.5%) are on relatively simple grid-based tasks, and whether the approach transfers to open-ended, long-horizon real-world workflows with less verifiable intermediate signals remains to be established.
