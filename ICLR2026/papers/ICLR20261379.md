## Problem

Formal models in TLA+ are essential for verifying complex concurrent and distributed systems but are notoriously expensive to write, requiring months of expert effort. While recent LLMs show promise for generating function-level pre-/post-conditions, it remains unclear whether AI can comprehend and abstract the behavior of complete, real-world systems into executable formal models. No existing benchmark evaluates this capability at system scale—prior work targets small programs, logic puzzles, or repair tasks rather than production-grade system artifacts.

## Input / Output

Each task provides system source code (in Rust, Go, C, or Java), a modeling specification listing mandatory core actions to include and implementation details to exclude, and instrumented execution traces for conformance checking. The agent must produce a complete TLA+ module (state variables, Init predicate, Next-state relation with atomic actions, and temporal properties) plus a TLC configuration file. Evaluation is fully automated and hierarchical: SANY checks syntax, TLC performs bounded state-space exploration for runtime correctness, trace validation checks conformance against instrumented code actions, and model checking verifies system-specific safety and liveness invariants, with partial scoring at each stage.

## Method

SYSMOBENCH's core contribution is a set of four automatable quality metrics with partial scoring schemes that avoid reliance on human-written reference models or LLM-as-a-judge. For syntax, it performs per-action SANY analysis by encapsulating each action into a standalone module, awarding 50% for all per-action passes and 100% for full-module passes. For runtime, it runs TLC without invariants and measures the fraction of actions covered without errors. For conformance, it feeds instrumented execution traces to TLC and uses an LLM (Claude-Sonnet-4) to map model elements to code elements, scoring the fraction of code actions validated without mismatch. For invariants, it uses an LLM to concretize property templates (with natural-language descriptions and TLA+ examples) into model-specific invariants, then runs TLC independently per invariant. Three agent designs are evaluated—Basic Modeling (direct prompting), Code Translation (statement-by-statement via Specula), and Trace Learning (inferring models from execution traces)—powered by four LLMs (Claude-Sonnet-4, GPT-5, Gemini-2.5-Pro, DeepSeek-R1), each run five times with up to three feedback iterations for compilation/runtime errors.

## Results

On the simple Asterinas Spinlock, all four LLMs achieve 100% syntax and runtime correctness for both agents; Claude-Sonnet-4 attains perfect scores (100%) across all four metrics for both the Basic Modeling and Code Translation agents, while other LLMs score 80% conformance and 85.71–100% invariant. On the complex Etcd Raft, performance drops dramatically: for the Basic Modeling agent, only Claude-Sonnet-4 passes syntax (100%) and runtime (25%), yielding just 7.69% conformance and 69.23% invariant; the Code Translation agent with Claude-Sonnet-4 improves to 66.67% runtime, 15.38% conformance, and 92.31% invariant, while GPT-5, Gemini-2.5-Pro, and DeepSeek-R1 fail at syntax or runtime. Overall, state-of-the-art LLMs handle small concurrent artifacts well but struggle significantly with large distributed protocol implementations.

## Baselines & Comparisons

The paper reproduces two existing formal-specification benchmarks—Alloy-APR (Alhanahnah et al., 2025) and PAT-Agent (Zuo et al., 2025)—using the same four LLMs to contextualize SYSMOBENCH's difficulty. On Alloy-APR's ARepair benchmark, Claude-Sonnet-4 achieves 100% (38/38), surpassing the best result reported in the original paper (73.7%, 28/38), and GPT-5 reaches 78.9%; yet on SYSMOBENCH's Alloy extension, all four LLMs score 0% on every metric for the Spinlock system. On PAT-Agent's NoPlanning workflow, Claude-Sonnet-4 achieves 87.3% Average Pass Rate (consistent with the original paper), but on SYSMOBENCH's PAT extension, all LLMs produce models that fail syntax checks entirely (0% across all metrics). These comparisons demonstrate that existing benchmarks exercise simplified tasks (puzzles, small repair tasks with median model size 21–50 LoC) where current LLMs perform well, whereas SYSMOBENCH's real-world system artifacts (median 219 LoC, up to 508 LoC) expose a fundamental gap: LLMs that solve Alloy-APR and PAT-Agent tasks effectively cannot generate even syntactically correct formal models for production systems.

## Relation to Prior Work

This paper extends the line of work on evaluating LLMs for formal specification generation (TLAi+Bench, Cao et al. 2025) from small logic puzzles and function-level pre/postconditions to complete real-world system artifacts (Etcd Raft, ZooKeeper, Asterinas OS components). It builds on trace validation techniques (Cirstea et al. 2024; Tang et al. 2025) and the TLA+ toolchain (SANY, TLC) to introduce automated, reference-model-free quality metrics—conformance and invariant correctness—that prior TLA+ generation benchmarks lacked. The paper explicitly positions SYSMOBENCH as the formal-systems analogue of SWE-bench, filling a gap where no prior benchmark evaluated AI on modeling production-grade concurrent and distributed systems.

## Why It Matters / Open Questions

SYSMOBENCH provides the first systematic, automatable evaluation of whether AI can produce TLA+ models of real-world systems, establishing a clear capability boundary: current LLMs handle small artifacts (spinlock) near-perfectly but fail on complex distributed protocols (Raft), with conformance scores dropping to 7–15%. The finding that liveness properties are violated ~5× more often than safety properties (41.9% vs 8.3%) points to a specific temporal-reasoning weakness in LLMs that future work should target. Open questions include whether more sophisticated agents (e.g., with domain-specific planning or iterative refinement) can close the gap, how to measure maintainability of AI-generated models, and whether AI-generated models can eventually be adopted by real-world system projects for ongoing verification.
