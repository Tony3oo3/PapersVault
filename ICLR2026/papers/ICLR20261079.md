## Problem

Current LLM reasoning follows a batch thinking paradigm where reasoning begins only after the entire input context is received, introducing unnecessary latency and diluting attention to earlier information as context grows. This paradigm is ill-suited for dynamic scenarios requiring timely responses, and it forces models to rely on longer chains of thought or repeated self-refinement to re-focus on relevant context, inflating computational cost. The paper asks whether LLMs can instead reason incrementally while receiving input, mirroring the human cognitive process of thinking while reading.

## Input / Output

The method consumes a text question and a context that arrives sentence-by-sentence, with sentence-level boundary tokens (<EOS>) delineating minimal reasoning units. The input order can be question-first or context-first, and the model must reason using only the partial context available at each step. Output consists of serialized reasoning segments (one per input sentence, terminated by <EOT> tokens) generated concurrently with input reception, followed by a final answer whose depth is explicitly controlled via instruction signals: D1 (direct answer), D2 (global integration), or D3 (self-reflection on top of global integration).

## Method

StreamingThinker adapts batch-oriented LLMs (Qwen3-1.7B/4B) to the streaming paradigm through three mechanisms. First, a streaming CoT generation pipeline uses a 32B model to produce order-preserving per-sentence reasoning traces, validated by a granularity score (boundary-token ratio) and a sequential consistency score (SentenceBERT cosine similarity between reasoning and input sentences), with a 235B teacher model reconstructing traces and token-level intervention generating depth-controlled variants. Second, the training framework introduces a streaming attention mask that causally blocks each reasoning step from attending to future input positions, and a streaming position encoding (SPE) that assigns independent zero-based position IDs to input and reasoning tokens, eliminating the positional contention that standard RoPE creates under concurrent input/output processing. Third, inference employs parallel KV caches—a source cache for input prefill and a target cache for reasoning decoding—that are merged only during cross-attention and split after each sentence, enabling true concurrency between reading and reasoning without the serial bottleneck of a single continuous cache.

## Results

On Qwen3-4B, StreamingThinker at depth D3 (self-reflection) matches or slightly exceeds batch thinking accuracy across all six benchmarks (e.g., GSM-Symbolic: 0.856 vs. 0.855; ProofWriter: 0.813 vs. 0.620; PubMedQA: 0.653 vs. 0.609), while reducing token-to-first-token (TTFT) by ~78% (e.g., 20.77 vs. 94.74 on GSM-Symbolic) and end-to-end answer delay by >75% (e.g., 9.77 s vs. 47.70 s). At the shallowest depth D1, delay drops to under 1 s (0.66 s on GSM-Symbolic), confirming that reasoning overlaps with input reading. The parallel KV cache mechanism adds negligible overhead (<5 ms for split/merge operations) and peak memory remains consistent with the batch baseline (~7.99 GB).

## Baselines & Comparisons

The paper compares three paradigms: (1) Batch Original (standard batch thinking without distillation), (2) Interleaved (naive streaming that alternates input segments and reasoning steps with a single sequential KV cache), and (3) Streaming (the proposed parallel KV cache approach). On Qwen3-4B, Streaming D3 matches or exceeds Batch Original accuracy on 5 of 6 datasets (e.g., GSM-Symbolic 0.856 vs. 0.855, ProofWriter 0.813 vs. 0.620, PubMedQA 0.653 vs. 0.609) while cutting answer delay by 79–80% (e.g., 9.77 s vs. 47.70 s on GSM-Symbolic). Interleaved D3 also approaches batch accuracy (e.g., GSM-Symbolic 0.843) but incurs 36–57% higher delay than Streaming D3 (15.46 s vs. 9.77 s on GSM-Symbolic) due to its sequential synchronization constraint. Both streaming modes reduce TTFT by ~78% relative to batch (20.77 vs. 94.74 tokens on GSM-Symbolic), but Streaming D1 achieves near-zero delay (0.66 s) versus Interleaved D1 (6.30 s), demonstrating that parallel KV caches enable true concurrency between input encoding and reasoning generation. The authors attribute Interleaved's accuracy gap to distributional mismatch with pretraining and its latency gap to the inability to overlap prefill and decode.

## Relation to Prior Work

This paper extends the chain-of-thought reasoning paradigm by restructuring it for streaming input, drawing on RoPE (Su et al., 2024) to design a streaming position encoding that eliminates positional contention between concurrently arriving input and generated reasoning tokens, and on token-level intervention (Wu et al., 2025) to enable controllable reasoning depth. It departs from prior streaming LLM work (simultaneous translation, streaming speech/video) by focusing specifically on reasoning fidelity under incremental input, and from efficient-reasoning work (token compression, speculative decoding) by addressing latency at the input-consumption level rather than the generation level. The Construction-Integration cognitive model (Kintsch, 1988) provides the theoretical scaffold, mapping the streaming phase to local construction and the post-reading phase to global integration.

## Why It Matters / Open Questions

The 80% TTFT reduction and 60%+ end-to-end delay reduction while preserving batch-level accuracy make streaming thinking practically relevant for real-time dialogue, long-document analysis, and embodied AI where waiting for full input is infeasible. However, evaluation is confined to Qwen3-1.7B/4B on deterministic reasoning tasks (math, logic, QA), leaving open whether the paradigm scales to larger models, open-ended generation, or multimodal streaming. The parallel KV cache design adds negligible overhead (<5ms for split/merge), suggesting the architectural cost is manageable, but whether the streaming attention mask and independent position encoding generalize across model families and architectures remains untested.
