## Problem

Existing KV cache retrieval methods for long-sequence LLM inference trigger retrieval at every decoding token and rely on coarse-grained page-level management, causing prohibitive cumulative data-transfer and computation overhead—especially in long-output reasoning scenarios—and transferring many non-critical KV entries that waste bandwidth or degrade accuracy. LouisKV addresses both bottlenecks by exploiting temporal locality in critical KV access and the distinct spatial distribution of critical KVs across input versus output sequences.
![Teaser figure](../imgs/ICLR20262222/cropped_page1_idx0.webp)

## Input / Output

The system takes a text prompt of arbitrary length (up to 128K tokens) as input and autoregressively generates a token sequence (up to 32K tokens for reasoning tasks). The full KV cache is offloaded to CPU memory, with only a fixed budget B of critical KV entries retained on the GPU at any time. The method is evaluated across three sequence-length regimes—long-input/short-output, short-input/long-output, and long-input/long-output—on models including Qwen3-8B, Llama-3.1-8B-Instruct, and DeepSeek-R1-Distill-Qwen-7B, with a single NVIDIA A6000 (48 GB) GPU connected to CPU via PCIe 4.0.

## Method

LouisKV introduces two core mechanisms. First, a semantic-aware adaptive retrieval strategy computes the cosine similarity between consecutive query vectors (averaged across all attention heads) at each decoding step; retrieval is triggered only when this similarity drops below a calibrated threshold τ, amortizing the selection-and-transfer cost over an entire semantic segment rather than per token. Second, a decoupled fine-grained management scheme tailors retrieval units to each phase: during prefill, k-means clustering groups semantically similar key vectors into clusters (addressing sparse attention in long inputs), while during decode, temporal segments partitioned at detected semantic boundaries capture dense local attention in long outputs; both cluster and segment centroids serve as compact indices for a unified CPU cache pool. System-level optimizations include a custom Triton kernel for asynchronous clustering, a group-consistent selection strategy that unifies retrieval across GQA query-head groups to eliminate redundant transfers, and a custom CUDA kernel for batched selection of variable-size KV units under a fixed budget, with the DGL library enabling direct row-level CPU-to-GPU transfer.

## Results

LouisKV achieves up to 4.7× end-to-end latency speedup over Arkvale (the strongest retrieval baseline) across long-input short-output, short-input long-output, and long-input long-output scenarios, while maintaining near-lossless accuracy. On long-output reasoning tasks (budget 1024), LouisKV matches FullCache on MATH500 (0.86) and surpasses Arkvale by 2.0% and Quest by 4.8% in average accuracy. On the RULER benchmark at 128K context, FullCache fails with OOM while LouisKV completes all 13 subtasks, outperforming Arkvale by 1.2 points in average score.

## Baselines & Comparisons

Against the KV dropping baselines H2O and RaaS, LouisKV wins decisively on all long-output reasoning tasks, with gaps of 10–20+ points (e.g., 0.86 vs. 0.66 on MATH500 vs. H2O), confirming that irreversible eviction is unsuitable for reasoning. Against the page-level retrieval methods Quest and Arkvale, LouisKV achieves 4.8% and 2.0% higher average accuracy respectively on long-output tasks, and 3.3% and 1.1% higher on long-input tasks, while also delivering 1.9×–4.7× lower end-to-end latency. Against the cluster-level method ClusterKV, LouisKV is marginally lower (~0.4%) on long-input tasks but clearly superior by 3.8% on long-output reasoning, validating the decoupled management design. On the extreme 128K RULER benchmark, FullCache OOMs entirely, Arkvale degrades severely (e.g., 6.5 on MK3), while LouisKV maintains competitive scores (25 on MK3) and outperforms Arkvale across all 13 subtasks.

## Relation to Prior Work

LouisKV builds directly on the KV cache retrieval line of work (Quest, Arkvale, ClusterKV), which preserves the full KV cache in CPU memory and dynamically fetches critical subsets for attention computation, as opposed to KV dropping methods (H2O, RaaS) that permanently discard entries. It departs from prior retrieval methods in two key ways: (1) replacing per-token retrieval with a semantic-aware trigger based on query cosine similarity, amortizing retrieval cost over coherent segments, and (2) replacing uniform page-level management with a decoupled scheme that uses k-means semantic clusters for sparse input KVs and temporal segments for dense output KVs. The paper positions itself as the first retrieval framework to comprehensively address all three long-sequence patterns (long-input/short-output, short-input/long-output, long-input/long-output), whereas prior work like ClusterKV and Squeezed Attention focused predominantly on static input sequences.

## Why It Matters / Open Questions

With the rise of reasoning models (DeepSeek-R1, Qwen3 thinking mode) that generate 16K+ token outputs, the per-token retrieval overhead that dominates existing methods becomes a critical deployment bottleneck; LouisKV's 4.7× speedup with near-lossless accuracy makes long-output inference practically viable on consumer-grade hardware (single A6000). The temporal locality observation and the decoupled cluster/segment management provide a reusable design pattern for future KV cache systems. Open questions include how the approach scales to 70B+ models and multi-GPU settings, whether the single threshold τ generalizes across model families without recalibration, and whether the k-means clustering overhead becomes prohibitive at 1M+ token contexts. The paper also notes that offloading KV indices to CPU DRAM could further reduce GPU memory footprint.
