## Problem

Existing computer-use agent benchmarks evaluate only GUI-based operations (click, type, drag), ignoring the tool invocation capabilities enabled by protocols like MCP. This makes comparisons between tool-augmented agents and GUI-only agents inherently unfair, and no prior benchmark jointly measures GUI operation, tool invocation, and the decision-making required to choose between the two pathways in a unified, real-world environment.
![Teaser figure](../imgs/ICLR20262163/cropped_page1_idx1.webp)

## Input / Output

At each step, the agent receives a 1280×720 GUI screenshot, the task instruction, and a RAG-filtered subset of MCP tool descriptions relevant to the currently active application (out of 158 total tools, with 25 non-target distractors included). The agent outputs either a GUI action (from 11 predefined operations) or an MCP tool call with structured parameters. Evaluation produces three metrics per task: binary Task Accuracy, Tool Invocation Rate (TIR, measuring correct tool-use decisions across 250 tool-beneficial and 111 non-tool-beneficial tasks), and Average Completion Steps (ACS, measuring efficiency).

## Method

The benchmark is built on OSWorld's 369 real-world tasks (361 after excluding 8 Google Drive tasks) across 9 applications, extended with 158 curated MCP tools covering 7 applications. Tools are generated via a three-module automated pipeline (Code Generation → Code Filter → Tool Wrap) that leverages OpenAI o3 to produce 72 verified code-based solutions, which are then combined with 192 tools from existing MCP servers and manually filtered by dual reviewers to remove redundancy and task-specific items. During evaluation, RAG selects application-relevant tools to avoid excessively long contexts, and the agent autonomously decides at each step whether to invoke a tool or perform a GUI action. Two new metrics—TIR and ACS—are introduced alongside standard accuracy to separately quantify tool-use propensity and completion efficiency, enabling nuanced comparison of decision-making quality beyond binary success/failure.

## Results

On OSWorld-MCP, Claude 4 Sonnet achieves the highest LMM accuracy at 36.1% (15 steps) and 45.0% (50 steps) with MCP tools, while the multi-agent framework Agent-S2.5 leads overall at 42.1% and 49.5% respectively. MCP tools consistently improve accuracy across most models (e.g., OpenAI o3: 8.3%→17.6% at 15 steps; Gemini-2.5-Pro: 13.3%→25.7% at 50 steps) and reduce Average Completion Steps (ACS), though Qwen2.5-VL is the exception, showing increased ACS. Tool Invocation Rates remain low across all models, with Claude 4 Sonnet achieving the highest at 33.3% and Qwen2.5-VL the lowest at 9.3%, indicating substantial room for improvement in tool utilization.

## Baselines & Comparisons

All seven evaluated systems benefit from MCP tools in accuracy, with the largest absolute gains seen in Gemini-2.5-Pro (+10.0 pp at 15 steps, +12.4 pp at 50 steps) and OpenAI o3 (+9.3 pp at 15 steps, +11.3 pp at 50 steps). Claude 4 Sonnet leads among end-to-end LMMs, reaching 45.0% accuracy at 50 steps with MCP (vs. 38.9% GUI-only), and also records the highest TIR (33.3%). The multi-agent framework Agent-S2.5 outperforms all single-model LMMs, achieving 49.5% at 50 steps with MCP, though its relative gain from MCP is smaller (+2.4 pp) compared to weaker models. Qwen3-VL and Seed1.5-VL occupy the mid-tier, with Qwen3-VL achieving the lowest ACS (10.0 at 15 steps, 18.6 at 50 steps) among all models. Qwen2.5-VL is the clear outlier: it shows the lowest TIR (9.3–10.1%) and is the only model whose ACS *increases* with MCP tools (30.5→39.0 at 50 steps), indicating poor tool-selection and decision-making ability. The paper further shows that TIR positively correlates with accuracy across all models, and that performance degrades sharply when tasks require combining multiple MCP tools, suggesting tool composition remains a key bottleneck.

## Relation to Prior Work

This paper extends the OSWorld benchmark (Xie et al., 2024), a widely used dynamic interactive framework for evaluating multimodal agents in real computer environments, by integrating 158 MCP tools alongside the original 11 GUI actions. It draws on the CoAct prompting strategy (Song et al., 2025) for its automated code-generation pipeline that produces MCP tools, and positions itself against both GUI-only benchmarks (Mind2Web, WebArena, WindowsAgentArena) and text-based MCP benchmarks (MCPEval, MCP-Radar, LiveMCPBench, MCP-Bench), none of which jointly assess GUI operation, tool invocation, and hybrid decision-making in a unified real-world setting.

## Why It Matters / Open Questions

OSWorld-MCP fills a critical gap by providing the first fair, integrated evaluation of whether and how computer-use agents should invoke tools versus perform GUI actions, with new metrics (TIR, ACS) that capture decision-making quality beyond raw accuracy. The finding that even the strongest model (Claude 4 Sonnet) achieves only 33.3% TIR and that multi-tool composition is substantially harder than multi-step GUI chaining highlights a significant and underexplored bottleneck in current LMMs. Limitations include coverage of only 7 applications and a single OSWorld environment, and open questions remain about how to improve tool-selection accuracy at scale and whether the RAG-based tool filtering generalizes to much larger tool inventories.
