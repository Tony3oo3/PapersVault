## Problem

LLMs still generate code with security vulnerabilities, and existing RAG-based approaches for secure code generation suffer from two key limitations: raw security documents contain task-irrelevant noise that distracts the model, and conventional retrievers treat all security information as generic text, failing to capture the security semantics (e.g., implicit vulnerability causes, API misuse patterns) embedded in task descriptions.

## Input / Output

The method takes a function-level coding task description as input and produces a single code completion as output. Before retrieval, the task undergoes proactive multi-faceted analysis: an LLM generates a vulnerability cause explanation and a zero-shot draft code, from which API calls are extracted via AST traversal. The retrieved security knowledge (guidelines + sliced code examples) is injected into the generation prompt, and the final output is evaluated on both functional correctness (unit tests) and security (CodeQL checks).

## Method

RESCUE introduces two core innovations. First, a hybrid knowledge base construction pipeline: an LLM-assisted cluster-then-summarize process (grouped by CWE type, using recursive bottom-up summarization with GPT-4o) distills high-level security guidelines and vulnerability cause descriptions, while a PDG-based bidirectional program slicing procedure (2-hop, using tree-sitter) extracts concise security-focused code examples by isolating only statements relevant to vulnerability fixes. Second, a hierarchical multi-faceted retrieval that operates in two levels: CWE-level retrieval fuses vulnerability cause analysis (dense retrieval via bge-base-en-v1.5) and API pattern matching (sparse BM25), then code-level retrieval adds a third code-similarity facet; all facet scores are combined via a modified Reciprocal Rank Fusion with confidence thresholding and rank-based filtering to select the top-k relevant CWE types and their associated secure code examples for prompt augmentation.

## Results

On CodeGuard+, RESCUE achieves the best SecurePass@1 across all six LLMs, with an average absolute improvement of 4.8 points over the second-best baseline (e.g., 65.6 vs. 60.3 for DeepSeek-Coder-V2-Lite, 69.7 vs. 64.7 for DeepSeek-V3). RESCUE also improves SecureRate by an average of 9.4 points while retaining 98.7% of the original models' functional correctness (Pass@1). On functional benchmarks (HumanEval+, BigCodeBench, LiveCodeBench), RESCUE achieves comparable or slightly better Pass@1 than the zero-shot baselines, confirming that security gains do not come at the cost of functionality.

## Baselines & Comparisons

RESCUE outperforms all five baselines on SecurePass@1 across every LLM tested. Against SecCoder (the closest RAG-based competitor), RESCUE gains 4.8–5.9 SP@1 points (e.g., 65.6 vs. 55.6 on DeepSeek-Coder-V2-Lite; 69.7 vs. 64.7 on DeepSeek-V3), showing that conventional RAG with raw security documents is insufficient. Against Codexity (iterative security-tool refinement), RESCUE leads by 5.5–10.2 SP@1 points while also preserving higher Pass@1. Against SafeCoder (instruction tuning) and CoSec (constrained decoding), RESCUE achieves 5.5–8.3 SP@1 points higher without requiring any fine-tuning or auxiliary model training. INDICT (multi-agent debate) achieves the highest SecureRate in several settings (e.g., 85.5 on GPT-4o-mini) but at a severe functional cost (Pass@1 drops to 36.8), yielding the lowest SP@1 among all methods—highlighting that RESCUE's joint security-and-functionality metric is critical for fair comparison.

## Relation to Prior Work

RESCUE extends retrieval-augmented code generation (SecCoder, SOSecure, DocPrompting) to the security domain, but departs from prior RAG-for-security work in two key ways: it constructs a hierarchical knowledge base by combining LLM-assisted cluster-then-summarize distillation with static program slicing (via PDG-based bidirectional slicing), and it replaces single-query text-similarity retrieval with a hierarchical multi-faceted strategy that proactively analyzes API patterns, vulnerability causes, and code similarity. Conceptually, it also positions against fine-tuning (SafeCoder), constrained decoding (CoSec), and security-tool-based iterative refinement (Codexity, INDICT), arguing that a training-free RAG approach with carefully designed knowledge representation and retrieval is more flexible and avoids data-leakage concerns inherent to using the same static analysis tools for both generation feedback and evaluation.

## Why It Matters / Open Questions

The introduction of SecurePass@k, which jointly requires passing both unit tests and security checks, addresses a real gap: prior SecureRate metrics can be gamed by generating trivially secure but non-functional code, and the paper demonstrates this with INDICT achieving high SecureRate but the lowest Pass@1. The finding that conventional RAG (SecCoder) yields negligible security gains while the hybrid knowledge base + multi-faceted retrieval yields consistent improvements underscores that knowledge representation and retrieval design matter more than simply retrieving similar code. Open questions include extending RESCUE from function-level to repository-level code generation, reducing inference overhead from the proactive analysis steps, and validating gains under broader dynamic testing beyond the limited CWEval subset evaluated.
