## Problem

Existing code reasoning benchmarks rely on synthetic or educational code fragments and evaluate only coarse-grained tasks like function-level input/output prediction, leaving a critical gap in assessing whether LLMs can perform the fine-grained semantic reasoning (statement-level value tracking, loop/pointer/branch property inference) that underpins real-world software engineering tasks such as test input generation, vulnerability detection, and fault localization.

## Input / Output

Each benchmark sample pairs a code snippet (3–516 lines) from a real-world project with the concrete variable states captured at a specific program point via execution tracing, and a natural language question targeting a particular semantic property. Outputs range from exact execution values (int, float, str, list, pointer, etc.) to binary verdicts (pointer aliasing, branch taken) and abstract value categories (e.g., 'Positive Regular' for integers in (0,10]). Evaluation uses exact string matching between the model's tagged response and the execution-traced ground truth, and the benchmark covers both forward inference (predict output from input) and the notably harder reverse inference (predict input from output).

## Method

The paper's core contribution is a scalable execution-tracing framework that builds, tests, and instruments 744 real-world projects (544 Python via PySnooper, 100 C via GDB, 100 Java via JDB) to automatically extract per-statement variable values, data types, function call names, and memory addresses, from which ground truth for six fine-grained reasoning tasks is derived. From 3,876 unique functions, 4,483 task-specific samples are curated across block-level semantics, statement-level semantics (arithmetic, boolean, API call, assignment, constant), loop properties (iteration count, in-loop and post-loop values), pointer aliasing, branch outcomes, and abstract-value approximation. The benchmark is then used to evaluate 14 SOTA LLMs (7–14B parameters) via vLLM under five prompting strategies—zero-shot, few-shot, RAG-style relevant examples, chain-of-thought, and combinations—revealing that even the best models (Claude 3.5) achieve under 30% accuracy on single-statement C code and that reverse inference remains the most challenging task across all languages.

## Results

On the CodeSense benchmark, Claude 3.5 Sonnet achieves the highest statement prediction accuracy at 0.65, followed by GPT-4o-mini and Gemini 1.5 Flash at 0.60, and DeepSeek-V3 at 0.58. Performance drops sharply for fine-grained tasks: on C single-statement blocks, even Claude 3.5 and GPT-4o-mini score under 30% accuracy, and on 3-statement Python blocks Claude 3.5 reaches only 20%. Input prediction (reverse semantic inference) is the hardest task, with the best model (Claude 3.5) achieving only ~12% accuracy on small functions. Arithmetic expressions and API/function calls are the most difficult statement types across all models.

## Baselines & Comparisons

The paper directly compares CodeSense against CruxEval (Gu et al., 2024), the prior state-of-the-art code reasoning benchmark, by evaluating the same three open-source models on both. Models perform substantially worse on CodeSense: DeepSeek-R1-Distill-Qwen-14B drops from 0.75 on CruxEval to 0.37 on CodeSense (a 0.38 drop), Qwen2.5-14B drops from 0.52 to 0.27 (0.25 drop), and Qwen2.5-Coder-7B drops from 0.50 to 0.30 (0.20 drop). This confirms that real-world code with complex control flow, API calls, and multi-file context is significantly harder than the synthetic, short Python fragments used in CruxEval. The gap is largest for the strongest model, suggesting that models that rely on pattern-matching over simple synthetic code fail most dramatically when confronted with genuine software engineering code. Additionally, Table 1 positions CodeSense as the only existing benchmark that simultaneously supports real-world projects, multi-lingual evaluation, fine-grained reasoning, execution steps, API understanding, and multi-file context—capabilities that CruxEval, CruxEval-X, REval, CodeMind, and CoRe each lack in at least one dimension.

## Relation to Prior Work

CodeSense extends the code-reasoning benchmark lineage initiated by CruxEval (Gu et al., 2024), which evaluated LLMs on synthetic Python I/O prediction, by moving to real-world multi-lingual projects (Python, C, Java) and decomposing reasoning into fine-grained tasks at statement, block, and function levels. It draws on TRACED (Ding et al., 2023a) for the abstract-value quantization scheme used in the approximation task, and departs from task-specific benchmarks like SWE-Bench and KGym by targeting generalizable semantic understanding rather than end-to-end patch generation. The key conceptual departure is the use of an execution-tracing framework (PySnooper, GDB, JDB) to automatically generate ground-truth annotations for properties like loop iteration counts, pointer aliasing, and branch outcomes—something no prior code-reasoning benchmark provided.

## Why It Matters / Open Questions

The benchmark reveals a fundamental gap: even SOTA models like Claude 3.5 achieve under 30% accuracy on single-statement C blocks and only ~12% on input prediction, suggesting that current code LLMs lack operational-semantics understanding rather than merely needing more training data. The open-source tracing framework and toolchain lower the barrier for constructing future fine-grained code-reasoning benchmarks and for generating post-training data. Open questions include whether fine-tuning with execution traces can close the semantic gap, whether the findings generalize beyond the three languages studied, and whether the exact-matching evaluation metric is too strict for practical SE workflows. The dramatic 20–38% performance drop relative to CruxEval (Table 10) underscores that synthetic benchmarks may overestimate real-world code reasoning capability.
