## Problem

Static LLM benchmarks (MMLU, GSM8K, Big-Bench) are finite, publicly accessible, and increasingly saturated by frontier models, making them unreliable indicators of genuine reasoning progress due to data contamination and overfitting. No existing evaluation protocol dynamically scales difficulty in response to model capability while maintaining problem quality and fairness, leaving a gap in how to sustainably probe the evolving reasoning limits of LLMs.

## Input / Output

The protocol takes as input a configuration of three LLMs (instantiated as Teacher, Student, and Orchestrator agents), a task type from a seven-way taxonomy (T1–T7), and a topic/domain assignment, then iteratively produces validated text anomaly detection problems at empirically calibrated difficulty levels. Each problem is a 5–6 sentence passage (or passage with multiple-choice options for T3/T4) with a guaranteed single anomaly, and the output is the anomaly's location (sentence index, boolean judgment, or choice index) plus validation metadata. Difficulty is not pre-assigned but emerges from the Student's actual failure point along a generation trajectory, yielding tiered variants (Easy→Hard→Extreme→Impossible) of the same underlying problem lineage.

## Method

ATAD replaces the static-dataset paradigm with a three-agent competitive protocol operating in two phases. In the initialization phase, the Teacher generates a base-level anomaly detection problem and the Orchestrator performs multi-criteria validation (well-formedness, clarity, logical coherence, task-type adherence, fairness, and adversarial-design detection), rejecting and requesting regeneration until a valid problem is produced. In the adaptive difficulty scaling phase, the Student attempts the validated problem; on success, the Orchestrator analyzes the Student's explanation and prompts the Teacher to generate a more challenging variant targeting the specific reasoning pattern that led to success, which undergoes the same validation loop; on failure, the problem is finalized as a benchmark item. This failure-driven finalization anchors difficulty in actual model limitations rather than manual labels, and the Orchestrator's regulatory role prevents the Teacher-Student competition from degenerating into ambiguous or adversarial items. The seven task types (contextual anomaly, paragraph order, blank-based choice, bridge sentence, referential ambiguity, logical contradiction, tone/style violation) each target a distinct reasoning skill, and the protocol is modular so that any LLM can be substituted into any agent role, enabling cross-model pairwise evaluation and tracking of model evolution over time.

## Results

On the ATAD benchmark (700 samples per generator, 100 per task type T1–T7), Claude-3.5-Sonnet achieves the highest overall average accuracy at 59.96%, followed by Gemini-2.0-Flash (58.93%) and LLaMA-3.3-70B (58.00%). The adaptive difficulty scaling protocol reduces average accuracy by approximately 37.3 percentage points from base to final problems (e.g., GPT-4o drops from 94.29% to 72.43% on GPT-generated benchmarks), confirming that the Teacher–Student competition effectively escalates difficulty. Orchestrator validation improves problem quality metrics (validity from 4.30→4.85, fairness from 3.20→4.65 on a 1–5 scale) while preserving or slightly increasing evaluation accuracy, demonstrating that the lower scores without the Orchestrator stem from flawed problem design rather than genuine reasoning difficulty.

## Baselines & Comparisons

As a benchmark paper, ATAD does not propose a new model to compare against prior methods; instead, it evaluates 12 LLMs across four independently generated benchmark suites. No single model dominates all task types: Claude-3.5-Sonnet leads overall (59.96%) but GPT-4o-mini surpasses it on T3 (62.50 vs. 65.00 is actually Claude higher; GPT-4o-mini leads on T3 at 62.50 vs. Claude's 65.00 — correction: Claude leads T3). More notably, Claude-3.5-Haiku, despite the lowest overall score (19.50%), achieves the highest T2 accuracy (55.00%), revealing model-specific reasoning specializations invisible to static benchmarks. The difficulty-scaling comparison (Table 2) shows a consistent ~37 pp accuracy drop from base to final problems across all generator families, validating the protocol's effectiveness. The Orchestrator ablation (Table 3) reveals that removing validation inflates apparent difficulty (lower accuracy) but degrades problem quality (validity drops from 4.85 to 4.30, fairness from 4.65 to 3.20 for GPT-4o as reviewer), confirming that the Orchestrator is essential for fair evaluation. Cross-family generation analysis (Appendix Table 5, Bias Index ≈ 0) shows no systematic advantage for models evaluated on benchmarks generated by their own family.

## Relation to Prior Work

This paper departs from the static benchmark paradigm (MMLU, GSM8K, Big-Bench) and from prior dynamic benchmarking approaches that generate problems algorithmically without multi-agent validation (DyVal, DARG). It also extends agent-based evaluation frameworks (BenchAgents, Benchmark Self-Evolving) by introducing a competitive Teacher-Student loop regulated by an Orchestrator, where difficulty scales adaptively based on actual student performance rather than fixed schedules. The specific task format—text anomaly detection with a seven-type taxonomy—builds on existing coherence and contradiction detection benchmarks (CoheSentia, DECOR, ANLI) but repurposes them as a reasoning probe within a self-calibrating protocol.

## Why It Matters / Open Questions

The protocol directly addresses the field's most pressing evaluation problem: benchmark saturation and data contamination that render static datasets increasingly uninformative. The finding that removing the Orchestrator causes difficulty to inflate through ambiguity rather than genuine reasoning challenges is a useful design principle for any dynamic benchmark. Open questions include whether the competitive dynamic truly isolates reasoning weaknesses versus exploiting narrow model-specific blind spots, the API cost of generation at scale, and whether the protocol generalizes beyond text anomaly detection to other task families without losing its validation guarantees.
