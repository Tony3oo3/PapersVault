## Problem

Linear attention variants (Mamba, RetNet, GLA, Gated DeltaNet, etc.) proliferate rapidly, but unlike softmax attention which benefits from standardized kernels like Flash-Attention, they lack general-purpose, hardware-efficient kernel support and scalable distributed implementations. Each new variant currently requires expert developers to hand-write and tune Triton kernels, and existing sequence-parallel schemes (LASP, LASP-2) use generic communication primitives that underutilize network bandwidth.
![Teaser figure](../imgs/ICLR20264353/cropped_page1_idx0.webp)

## Input / Output

The compiler ingests a user-defined PyTorch DSL consisting of three callable functions (chunk_mode, decay_mode, merge_mode) that specify the algorithm's chunk-parallel logic, along with input metadata declaring tensor shapes (Q, K, V, gate tensors) and constant dimensions. It produces pre-compiled Triton kernels (single-device or distributed) that, at runtime, consume the actual Q/K/V/gate tensors and emit the attention output tensor. The AOT-compiled static dispatcher selects the optimal pre-tuned kernel binary based on input shapes, bypassing the Triton runtime entirely.

## Method

FlexLA decomposes any linear attention algorithm into three canonical phases— intra-chunk computation, inter-chunk state propagation (prefix scan), and output merging—based on the chunk-parallel form. The user's PyTorch callables are traced into a Torch.fx graph IR, then subjected to domain-specific passes (custom Triton kernel substitution for operators like lower_triangular_inverse, transpose elimination, hardware-aware instruction marking for TMA). The IR is lowered to Triton-Distributed, enabling fine-grained tile-level compute-communication fusion that replaces NCCL All-Gather with custom GPU-initiated communication patterns. An adaptive parallelism scheduler selects between fused (intra+inter-chunk) and decoupled three-phase execution based on input shapes and hardware SM count, while an AOT compilation module with a profile-guided static dispatcher eliminates the hundreds-of-microseconds Triton runtime overhead that dominates short-sequence latency.

## Results

On a single H100 GPU, FlexLA-generated kernels achieve 1.01×–4.9× the throughput of the FLA expert-tuned Triton library across HGRN, scalar/vector GLA, vanilla linear attention, and Gated DeltaNet (1K–256K sequence lengths). In distributed weak-scaling on up to 128 H20 GPUs, FlexLA maintains near-constant latency (e.g., scalar GLA at 16M tokens) while LASP-2 degrades from 49.2 ms (4 GPUs) to 345 ms (128 GPUs) on GDN, yielding up to 7.2× speedup. The AOT static dispatcher reduces runtime overhead by 46% (207 µs → 112 µs at 1K tokens), and tile-level compute-communication fusion cuts inter-rank state propagation time from 873 µs (serial) to 560 µs on 8×H800.

## Baselines & Comparisons

Against FLA (expert-tuned Triton kernels), FlexLA wins on HGRN (1.64–2.02×), scalar/vector GLA and vanilla linear attention (1.1–2.0×), and matches FLA on GDN at longer sequences where compute dominates over system overhead. Torch-Compile, a general-purpose compiler without linear-attention-specific fusion, is consistently outperformed by a wide margin across all variants and sequence lengths. In distributed settings, FlexLA outperforms LASP-2 by up to 7.2× on 128 H20 GPUs (GDN: ~48 ms vs 345 ms) and by 1.17× on 4 H100 GPUs at 16K per-GPU sequence length, thanks to tile-level compute-communication fusion that avoids the All-Gather redundancy in LASP-2. Compared to Ring-Attention (distributed softmax), FlexLA is over 160× faster at 512K global sequence length, reflecting the fundamental O(L) vs O(L²) complexity gap.

## Relation to Prior Work

FlexLA builds directly on Triton-Distributed as its compiler backend, leveraging its native OpenShmem-style communication primitives to generate tile-level compute-communication fused kernels, and on Triton as the target code generation language. Conceptually, it departs from the FLA library's approach of requiring expert developers to hand-write a separate Triton kernel for each linear attention variant, instead introducing a unified three-phase programming abstraction (intra-chunk, inter-chunk, merge) grounded in the chunk-parallel formulation shared by most linear attention models. For distributed execution, it moves beyond LASP/LASP-2's reliance on generic NCCL collective primitives (e.g., All-Gather) by generating custom, algorithm-specific communication schedules fused with computation, addressing the bandwidth underutilization identified in prior sequence-parallel work.

## Why It Matters / Open Questions

FlexLA addresses a practical bottleneck in the rapidly evolving linear attention landscape: the costly cycle of manual kernel development for each new variant, compounded by the lack of scalable distributed implementations. The three-phase abstraction, rooted in the associativity property of linear recurrences, provides a principled boundary for applicability—models with non-associative state updates (e.g., TTT layers) fall outside its scope, and the backward pass remains unaddressed. Open questions include whether the abstraction can be extended to softmax attention (discussed theoretically in Appendix E), how it adapts to future hardware generations, and whether the AOT compilation strategy generalizes to dynamic-shape inference workloads beyond the enumerated configurations.
