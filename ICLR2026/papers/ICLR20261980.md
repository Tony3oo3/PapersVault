## Problem

The Model Context Protocol (MCP) standardizes how LLM agents discover, describe, and invoke external tools, making tools first-class composable objects with natural-language metadata and standardized I/O. This enlarges the attack surface beyond what the function-calling paradigm captures, yet existing benchmarks (ASB, AgentDojo, InjecAgent) remain confined to that older paradigm and cannot probe MCP-specific vulnerabilities such as tool-name collisions, preference manipulation in descriptions, or user-impersonating tool responses. No dedicated benchmark existed to systematically measure how well LLM agents resist attacks across the full MCP tool-use pipeline.

## Input / Output

Each of the 2,000 attack instances pairs a user query (from 65 tasks across 10 domains) with a tool list containing both benign tools (304, sourced from Smithery) and mutated attack tools (405), executed in a live MCP environment with a poisoned external database and target data files (e.g., personal information JSON, SSH keys). The agent's tool invocation logs and the resulting workspace state are inspected to determine whether the attack objective was achieved and whether the user task was completed. Outputs are three aggregate metrics—ASR (fraction of successful attacks), PUA (fraction of user tasks completed under attack), and NRP = PUA × (1 − ASR)—reported per attack type and per LLM backbone.

## Method

MSB establishes a taxonomy of 12 attack types organized by MCP workflow stage and attack vector: tool-signature attacks (Name Collision, Preference Manipulation, Prompt Injection) manipulate names and descriptions to mislead tool selection during planning; tool-parameter attacks (Out-of-Scope Parameter) coerce the agent into supplying unauthorized inputs during invocation; tool-response attacks (User Impersonation, False Error, Tool Transfer) and Retrieval Injection embed malicious instructions in responses or poisoned databases during response handling; and Mixed Attacks chain multiple vectors across stages. A key design choice is that all attacks are executed by running real MCP tools (both benign and malicious) in a dynamic environment rather than simulating outputs, so the agent's actual tool-calling behavior is exercised. The evaluation harness composes user tasks, attack tools, and attack tasks into 2,000 instances and runs 10 LLM backbones (from Llama3.1 8B to GPT-5) through the full pipeline. The proposed NRP metric captures the security–performance trade-off in a single scalar, and the empirical finding is an inverse scaling law: more capable models achieve higher ASR (up to 75.83%) because their superior tool-use and instruction-following abilities make them more susceptible to MCP-specific manipulations.

## Results

Across 10 LLM agents and 12 attack types (2,000 instances), the overall average Attack Success Rate (ASR) is 40.35%, with Out-of-Scope Parameter (OP) being the most effective single attack at 76.5% average ASR. MCP-specific attacks (User Impersonation: 45.69%, False Error: 39.21%) substantially outperform function-calling-era attacks (Prompt Injection: 20.21%, Retrieval Injection: 20.00%), confirming that MCP expands the exploitable attack surface. An inverse scaling law is observed: more capable models are more vulnerable (DeepSeek-V3.1 achieves the highest ASR at 60.94% and PUA at 86.37%), while GPT-5 achieves the highest Net Resilient Performance (NRP) at 52.99% by balancing task completion with attack resistance. The MCIP defense reduces average ASR from 40.35% to 28.69% but only marginally improves NRP (+1.18%), indicating current defenses cause functional degradation.

## Baselines & Comparisons

As a benchmark paper, MSB compares 10 LLM backbones rather than proposing a new method against baselines. The key comparison reveals an inverse scaling law: DeepSeek-V3.1 (highest ASR 60.94%, highest PUA 86.37%) and GPT-4o-mini (ASR 58.56%) are the most vulnerable due to their strong tool-calling and instruction-following abilities, while GPT-5 achieves the best NRP (52.99%) by resisting response-stage attacks (UI: 0.33%, FE: 1.31%) while maintaining high task completion (PUA 84.33%). Smaller models like Llama3.1 8B (ASR 19.74%) are more resistant but also less capable (PUA 34.10%), making NRP the critical differentiator for deployment decisions. Among attack types, OP dominates (76.5% avg ASR) across nearly all models, while NC-FE is the weakest (14.62%), suggesting name-collision alone is insufficient without a follow-up response attack. The MCIP defense reduces ASR by 11.66% on average but simultaneously degrades PUA by 7.59%, yielding only a +1.18% NRP gain, indicating that current detection-based defenses are insufficient for MCP-specific threats.

## Relation to Prior Work

This paper extends the agent security evaluation task from the function-calling paradigm (ASB, AgentDojo, InjecAgent) to the MCP protocol, which introduces new attack vectors through tool signatures, parameters, and responses that are invisible in standard function calling. While MCPTox addresses tool description injection and MCIP provides a detection-based defense, neither covers the full MCP pipeline. MSB carves new ground by being the first benchmark to execute real MCP tools (both benign and malicious) across all three pipeline stages—planning, invocation, and response handling—rather than relying on simulated outputs or LLM-generated test cases.

## Why It Matters / Open Questions

As MCP rapidly becomes foundational infrastructure for LLM agents (with platforms like Smithery hosting thousands of servers), a dedicated security benchmark is critical for practitioners deploying agents in production. The inverse scaling law finding—that stronger models are paradoxically more vulnerable due to superior tool-use and instruction-following—has direct implications for model selection in agentic deployments. However, the defense evaluation is limited to a single mechanism (MCIP) that yields only marginal NRP improvement (+1.18%) while degrading task performance, leaving open the question of whether effective, non-degrading defenses for MCP exist. Future work should explore context-aware, dynamic defenses and whether the inverse scaling law persists as models incorporate safety training.
