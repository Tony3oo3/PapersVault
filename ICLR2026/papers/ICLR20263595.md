## Problem

Standard speculative decoding enforces strict exact-match verification, rejecting draft tokens that are semantically valid but differ in surface form, which caps achievable speedup. Existing training-based loose verification methods (e.g., JudgeDecoding) require curated annotation data and degrade sharply on out-of-distribution tasks, leaving a gap for a flexible, generalizable verification strategy that accepts semantically correct drafts without any training.
![Teaser figure](../imgs/ICLR20263595/cropped_page1_idx0.webp)

## Input / Output

The method takes a text prompt, a lightweight draft model (e.g., Llama-3.1-8B-Instruct), and a larger target model (e.g., Llama-3.1-70B/405B-Instruct) as inputs, and produces a generated text sequence along with the mean accepted tokens τ per round. In each round, the drafter sequentially proposes K tokens (K=15 for 70B, K=25 for 405B), which the target verifies in a single parallel forward pass; the only additional computation is per-token entropy from already-available logits, adding negligible overhead (~0.5 ms per round). The method is entirely plug-and-play: any draft-target pair can be composed without retraining or hyperparameter re-tuning.

## Method

FLy replaces exact-match verification with a two-tier mechanism that exploits the target LLM's self-corrective behavior. First, an entropy-level gate computes the normalized entropy at each mismatch position: if entropy falls below a threshold θ=0.3 (near-deterministic context, e.g., arithmetic digits), the mismatch is rejected immediately under standard SPD rules; otherwise, deferral is activated. Second, a token-level deferred window of W=6 tokens monitors whether the target model exhibits further divergence after the initial mismatch—if no additional mismatch appears within the window, the token is deemed a semantically valid alternative and accepted; if another mismatch emerges, it signals corrective behavior and the initial token is retroactively rejected. To counteract the increased drafting cost from longer acceptance lengths, a multi-level acceleration (MLA) component applies Prompt Lookup Decoding (n-gram retrieval) to speed up the drafter itself, reducing draft-side latency by ~20% and preventing it from becoming the dominant bottleneck.

## Results

On out-of-domain (OOD) datasets, FLy achieves a mean speedup of 2.74× (τ=12.41) with Llama-3.1-70B-Instruct and 4.80× (τ=17.13) with Llama-3.1-405B-Instruct at temperature 0, while preserving ≥99% of the target model's accuracy. On in-domain (ID) datasets, FLy reaches 2.88× (τ=12.67) on 70B and 5.34× (τ=17.14) on 405B. The method's advantage is most pronounced under distribution shift: on OOD data with Llama-3.3-70B, FLy attains 2.53× speedup versus only 1.56× for the training-based EAGLE-3, a 1.62× relative improvement.

## Baselines & Comparisons

Against the training-based SOTA EAGLE-3, FLy wins decisively on OOD datasets (2.53× vs. 1.56× mean speedup on Llama-3.3-70B, a 1.62× relative gain) but trails on in-domain data (2.63× vs. 3.83×), which is expected for a training-free plug-and-play method. Against EAGLE-2, FLy achieves a 1.05× relative speedup on in-domain datasets (2.69× vs. 2.57× on Llama-3-70B). Among training-free baselines, FLy dominates all three: SpS (2.74× vs. 2.04× on 70B OOD), REST (2.74× vs. 1.62×), and TokenRecycling (2.74× vs. 2.08×), with the gap widening substantially at 405B scale (4.80× vs. 2.83× for SpS). On accuracy preservation, FLy matches the training-based JudgeDecoding at ≥99% recovery across all datasets, while JudgeDecoding degrades to 92.3% on HumanEval when coding examples are removed from its training data. The multi-level acceleration (MLA) component adds a further 0.17× speedup (2.69× → 2.86×) by accelerating the drafter itself via Prompt Lookup Decoding.

## Relation to Prior Work

FLy extends the loosely speculative decoding line initiated by JudgeDecoding (Bachmann et al., 2025), which trains an auxiliary classifier to accept semantically valid but token-mismatched drafts. The key departure is making this judgment entirely training-free by repurposing the target model's own self-corrective behavior: an entropy gate identifies near-deterministic positions where deferral is unsafe, and a deferred window exploits the observation that the target model diverges again only when the initial mismatch is genuinely harmful. On the acceleration side, FLy builds on standard SPD (Xia et al., 2023) and training-free baselines (REST, TokenRecycling) but adds a multi-level acceleration layer using Prompt Lookup Decoding to speed up the drafter itself, a component prior multi-level SPD works (Georganas et al., 2025; Sun et al., 2024) handle with parameterized mini-drafts.

## Why It Matters / Open Questions

The training-free, model-agnostic design eliminates the retraining cost and OOD fragility that plague supervised SPD methods like EAGLE-3, which drops from 3.83× to 1.56× speedup under distribution shift while FLy remains stable around 2.5×. The 5×+ speedup on 405B-scale models with ≥99% accuracy preservation is practically significant for production deployment of very large LLMs where training a dedicated drafter is prohibitively expensive. Open questions include whether the fixed entropy threshold (θ=0.3) and window size (W=6) truly generalize to all domains without tuning, and whether the semantic-equivalence criterion is acceptable for applications requiring verbatim token-level fidelity (e.g., code generation where a single character matters).
