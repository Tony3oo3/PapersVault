## Problem

Existing research code generation benchmarks evaluate LLMs in one-shot settings, expecting correct code in a single response. This design ignores the iterative, feedback-driven nature of realistic scientific research workflows, where researchers and agents engage in multi-turn interactions to diagnose errors, refine implementations, and align code with methodological descriptions. No prior benchmark systematically assesses how LLMs leverage progressively richer human feedback to refine repository-level research code.
![Teaser figure](../imgs/ICLR20262382/cropped_page3_idx0.webp)

## Input / Output

Each task provides a structured code generation instruction (specifying target function name, functionality, and I/O parameters) alongside the full repository context and a research paper description. The agent receives one of five feedback levels per turn, ranging from bare execution logs (Level 0) to explicit ground-truth code snippets (Level 4), with intermediate levels adding error descriptions, diagnostic explanations, and natural-language correction guidance. Correctness is evaluated via differential unit tests that execute both the canonical and model-generated implementations under identical fixed-seed conditions and compare intermediate or final outputs within numerical tolerances, rather than checking end-to-end system behavior.

## Method

RECODE-H comprises 102 repository-level tasks curated from 2023+ top-tier CS papers (CVPR, ICML, NeurIPS, ICLR), each paired with explanatory comments, structured instructions, and unit tests enforcing 80% code coverage. The key evaluation mechanism is a five-level feedback hierarchy (Level 0: execution logs only → Level 4: ground-truth code snippet) that systematically controls the amount of guidance, enabling fine-grained measurement of feedback utilization. ReCodeAgent, the baseline agent, follows a ReAct loop (observation → reflection → planning → action) with a Reflexion-style memory that compresses prior rounds when a threshold is exceeded, and interacts with the repository through five tools (READ, RETRIEVE, REPLACE, SUBMIT, BROWSE). Feedback is generated by GPT-o4-mini conditioned on execution results, canonical code, and annotated comments to ensure reproducibility. Evaluation metrics include MRR, Recall@n, average test-case pass rate, CodeBLEU, and CodeBERTScore, with up to 10 interaction rounds per task.

## Results

On RECODE-H (102 tasks, 10 interaction turns), GPT-5 achieves the highest Recall at 71.6% and MRR at 11.9% under Level-4 feedback, while DeepSeek-V3.1 reaches 70.6% Recall and 21.0% MRR under the same setting. Without any feedback (Level 0), all models perform poorly: GPT-5 drops to 29.4% Recall and DeepSeek-V3.1 to just 10.8%. The largest single jump occurs from Level 0 to Level 1, where most models nearly double their Recall (e.g., GPT-5-mini from 19.6% to 38.2%), indicating that even minimal diagnostic signals substantially accelerate error correction.

## Baselines & Comparisons

The paper evaluates seven LLMs on RECODE-H rather than comparing a single method against baselines. At the strongest feedback level (Level 4), GPT-5 (71.6% Recall) and DeepSeek-V3.1 (70.6% Recall) are the top performers, with GPT-5-mini close behind at 66.7%. Gemini-2.5-pro and Gemini-2.5-flash tie at 58.8% Recall, while Claude-Sonnet-4 lags at 48.0% and GPT-5-nano trails at 35.3%. A critical finding is that feedback sensitivity varies sharply: DeepSeek-V3.1 shows the largest relative improvement (10.8% → 70.6% Recall, a 6.5× gain), whereas Claude-Sonnet-4's adoption rate actually *decreases* as feedback becomes more detailed, and Gemini-2.5-pro's adoption fluctuates around 70% regardless of level. Error analysis reveals that failures are dominated by paper/instruction misunderstanding (Type 2, ~26–40%) and missing domain knowledge (Type 3, ~34–55%), not syntax errors (Type 1, ~11–26%), indicating that the primary bottleneck is semantic fidelity rather than coding ability.

## Relation to Prior Work

This paper builds on the ReAct framework for its agent's observation-reflection-planning-action loop and adapts Reflexion-style memory compression for multi-round context management. It departs from prior research code generation benchmarks (MLE-bench, PaperBench, SciReplicate-Bench, ResearchCodeBench), which evaluate models in one-shot settings, by introducing a structured five-level feedback hierarchy that simulates iterative researcher-agent collaboration. It also extends the line of interactive code generation work in the SWE domain (MINT, InterCode, ConvCodeWorld) from function-level tasks to repository-level research code, where feedback must address methodological fidelity rather than API correctness.

## Why It Matters / Open Questions

RECODE-H is the first benchmark to systematically evaluate LLM agents on multi-turn, feedback-driven research code generation, filling a clear gap between one-shot research code benchmarks and SWE-oriented interactive benchmarks. The finding that minimal diagnostic signals (Level 0→1) yield the largest performance jumps, while richer guidance shows diminishing returns, has practical implications for how researchers should allocate feedback effort. A notable limitation is that feedback is simulated by GPT-o4-mini rather than real humans, and the paper acknowledges this does not capture the full variability of human communication. Open questions include whether the feedback hierarchy generalizes to broader research stages (experiment design, data analysis) and whether multi-agent or human-in-the-loop settings change the observed dynamics.
