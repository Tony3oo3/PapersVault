## Problem

LLMs encounter vast amounts of declarative data (instructions, rules, code) during training, yet it remains unclear whether they can acquire executable procedural knowledge from such descriptions rather than from demonstrations. Prior work provides suggestive evidence of latent learning but does not methodologically isolate whether a single instruction in training data is sufficient to induce multi-step, input-conditional execution, nor does it identify training strategies that improve this internalisation.

## Input / Output

At inference time, the model receives only a short context pointer (e.g., a function name or grammar identifier) plus a concrete input (an integer for arithmetic, a vocabulary choice for grammars), and must produce the correct output without the instruction being present in-context. During training, the model sees two data formats: declarative examples pairing a context with the full instruction text (Python source or CFG production rules), and execution examples pairing a context with an input-output pair. The key constraint is that evaluation instructions are never paired with execution examples, so the model must generalise the instruction-to-behaviour mapping learned on train instructions to unseen test instructions.

## Method

Programming by Backprop (PBB) is a multi-stage finetuning regime that 'compiles' declarative instructions into model parameters via two distinct curricula. Proactive PBB first trains a mixed objective (declarative loss on instruction text + execution loss on input-output pairs) over a train set to learn a general instruction-to-behaviour correspondence, then exposes the model to evaluation instructions using only the declarative loss, relying on the learned correspondence to internalise new behaviours. Retroactive PBB first trains on all instructions declaratively (acquiring latent knowledge without execution competence), then introduces execution supervision only on the train set, whose gradients over shared parameters 'activate' the latent knowledge for unseen eval instructions. The core insight is separating the learning of how instructions map to behaviour from the internalisation of specific new instructions. Empirically, RL (GRPO) outperforms SFT for the retroactive activation stage, code representations outperform natural language descriptions, and prompt augmentation with diverse context templates is essential for the effect to emerge.

## Results

On Random Arithmetic, Qwen3-14B reaches 37% average execution accuracy on unseen test behaviours under the full proactive PBB curriculum. The headline finding is sample efficiency: a single instruction in stage 2 of proactive PBB yields execution fidelity comparable to or better than Algorithm Distillation (AD) trained on up to 100 input-output execution traces (Figure 2). On the Ciphers task, proactive PBB (stage 1 on Leetcode, stage 2 on cipher source code) produces performance robust to shift-parameter variation, whereas AD trained on imbalanced demonstrations degrades for less-frequent shifts. On Formal Grammars, the full proactive curriculum enables grammar-compliant generation for unseen test grammars at rates far exceeding random vocabulary sampling or either single-stage baseline.

## Baselines & Comparisons

The primary baseline is Algorithm Distillation (AD; Laskin et al., 2023; Gandhi et al., 2024), where the model learns an algorithm purely from input-specific execution examples. On Random Arithmetic, PBB with a single declarative instruction in stage 2 matches or exceeds AD trained on up to 100 execution traces for both CoT and direct inference, establishing the 'one instruction ≈ 100 examples' claim. On the Ciphers task, AD trained on imbalanced demonstrations (skewed toward common shifts like ROT13) produces biased, parameter-sensitive performance, while proactive PBB learns the input-general function and remains robust across all shift values; combining PBB with the skewed demonstrations yields the best overall accuracy. However, the paper notes that in-context execution (providing the instruction at inference time) remains more reliable than PBB-internalised execution across all domains, so PBB is a strict improvement over AD in data efficiency but does not surpass explicit in-context conditioning. For the retroactive curriculum, GRPO (online RL) substantially outperforms SFT in stage 2, with SFT initially memorising paired executions before generalising, while RL drives faster and more robust generalisation to unpaired test programmes.

## Relation to Prior Work

PBB extends the implicit meta-learning framework of Krasheninnikov et al. (2024) by formalising a two-stage curriculum that separates learning the instruction-to-behaviour mapping from internalising specific instructions, and by grounding the analogy in partial evaluation from programming. It departs from algorithm distillation (Laskin et al., 2023; Gandhi et al., 2024), which learns from input-specific execution traces, by showing that a single declarative instruction can substitute for many such traces when the model has first been primed on a train set. The work also builds on suggestive but uncontrolled evidence of latent learning from out-of-context reasoning (Berglund et al., 2023; Betley et al., 2025) and procedural knowledge in pretraining (Ruis et al., 2025), providing the first methodologically isolated demonstration that instructions in training data can induce multi-step, input-conditional execution.

## Why It Matters / Open Questions

The 1:100 instruction-to-example substitution ratio, if it holds beyond synthetic domains, has direct implications for data curation and the cost of teaching models new behaviours. The safety finding—that instructions present in training data can elicit unintended executable behaviours at inference time without explicit prompting—underscores the need for careful filtering of procedural content in pretraining and finetuning corpora. Key limitations include the reliance on synthetic or semi-synthetic tasks for the strongest results, the gap between PBB execution reliability and in-context execution, and the finding that natural-language instructions are substantially less effective than code, leaving open whether the paradigm scales to the predominantly natural-language instructions that dominate real training data.
