## Problem

Multi-agent systems (MAS) are vulnerable to control-flow hijacking (CFH) attacks that exploit confused-deputy vulnerabilities in orchestration mechanisms, routing execution toward unsafe agents and actions. Existing defenses such as LlamaFirewall's alignment checks are brittle: they can be evaded by attacks that present unsafe actions as the only apparent way to complete the user's task, received from trusted agents, and not unconditionally harmful. The paper identifies a fundamental tension between safety and functionality in MAS—systems must adaptively re-plan in response to genuine errors, yet alignment checkers lack complete visibility into execution context to distinguish real faults from attacks masquerading as faults.

## Input / Output

CONTROLVALVE takes a user task prompt and the set of available black-box agents (accessed via API, with no visibility into their internal prompts, weights, or reasoning traces) and produces two artifacts during a planning stage: (1) a control-flow graph expressed as a context-free grammar over agent-call tokens, compiled into a parser via Lark, and (2) up to three natural-language contextual rules per graph edge enforcing input validation, contextual appropriateness, and data provenance. At runtime, it consumes the live agent invocation trace and outputs a per-transition enforcement decision—permit, reject, or re-plan (with a maximum of three re-planning attempts). All guardrails are generated zero-shot before any untrusted content is ingested, and the defense operates exclusively at the orchestration layer without intercepting individual agents' tool calls.

## Method

CONTROLVALVE adapts the principle of control-flow integrity (CFI) from systems security to multi-agent orchestration. During planning, an LLM generates a task-specific context-free grammar over agent-call tokens (e.g., 'CodeExecutor may only run after Coder'), which is compiled into a deterministic parser using Lark; for each permitted edge A→B, a second LLM call generates at most three natural-language contextual rules specifying how B may be invoked given A's output and the original task. At execution time, before every agent transition, an LLM judge performs two narrow checks: whether the transition corresponds to a permitted edge in the CFG, and whether the edge-specific rules are satisfied. Critically, the judge is never asked to assess whether an action is broadly 'aligned' with the user's goal (the failure mode of LlamaFirewall), but only whether it matches a pre-defined graph edge and satisfies pre-defined rules—checks that cannot be 'reasoned through' by adversarial content. The approach is task-agnostic, zero-shot (no attack examples required), and compatible with black-box commercial LLM agents whose internal state is invisible.

## Results

CONTROLVALVE achieves 0% attack success rate (ASR) across all 8 coding CFH variants (original and CFH-Hard) and all 6 computer-use CFH variants, while LlamaFirewall's default configuration (Llama-backed) is evaded with 87–100% ASR on CFH-Hard coding attacks and 67–89% ASR on computer-use attacks. On benign tasks, CONTROLVALVE maintains or improves performance: 97% vs. 93% single-answer accuracy on coding and 100% vs. 89% on computer use. The paper also demonstrates that non-adversarial, vaguely worded inputs cause accidental security violations (e.g., cc'ing untrusted addresses) at 89% rate without defense, reduced to 0% with CONTROLVALVE.

## Baselines & Comparisons

Against LlamaFirewall (the state-of-the-art alignment-check defense), CONTROLVALVE is strictly superior: LlamaFirewall's default Llama-backed configuration drops from 7–23% ASR on the original CFH attacks to 87–100% ASR on the more sophisticated CFH-Hard attacks, while CONTROLVALVE maintains 0% ASR in every setting. The best-performing LlamaFirewall variant (o4-mini-backed) still allows 10–57% ASR on CFH-Hard coding attacks, compared to CONTROLVALVE's 0%. Azure Content Filters are completely ineffective, showing identical ASR to the undefended baseline on all CFH attacks (e.g., 100% on original CFH, 89–100% on CFH-Hard). The least-privilege baseline provides only marginal protection against original CFH (reducing ASR from 100% to 80%) and is entirely ineffective against CFH-Hard (80% ASR), because CFH attacks reuse legitimate agents inappropriately rather than introducing new ones. On benign task performance, CONTROLVALVE slightly outperforms the undefended baseline on coding (97% vs. 93% single-answer) and computer use (100% vs. 89%), suggesting the generated contextual guardrails help keep the system on-task.

## Relation to Prior Work

CONTROLVALVE repurposes the control-flow integrity (CFI) principle from binary program security (Abadi et al., 2005) to the orchestration layer of multi-agent systems, replacing the open-ended semantic question 'is this action aligned with the user's goal?' with the narrow structural check 'does this transition correspond to a valid edge in a pre-generated context-free grammar over agent tokens?' This departs fundamentally from alignment-checking defenses like LlamaFirewall, which the paper shows are structurally unable to handle CFH because the safety-functionality conflict forces the checker to make impossible judgments. It also extends the CFH threat model introduced by the same group (Triedman et al., 2025) with harder attacks (CFH-Hard) that exploit the brittleness of alignment definitions, and contrasts with information-flow-control and least-privilege approaches that require full visibility into black-box agents or cannot handle contextually inappropriate use of legitimately accessible tools.

## Why It Matters / Open Questions

The paper demonstrates that the current state-of-the-art defense paradigm (alignment checking) is not merely weak but structurally incapable of defending against CFH, reframing the problem from 'need a better LLM judge' to 'need a different enforcement mechanism.' The finding that non-adversarial, vaguely worded inputs cause accidental control-flow violations (89% for undefended MAS) reveals that the safety-functionality tension is not solely an adversarial concern but an inherent design challenge for any adaptive MAS. Open questions include whether CFG-evasion attacks (analogous to CFI evasion in programs) are possible in MAS, whether overly restrictive generated graphs will limit real-world adaptability, and whether the approach generalizes beyond the single AutoGen/Magentic-One configuration evaluated.
