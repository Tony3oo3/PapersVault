## Problem

Existing anonymization-based defenses against LLM attribute inference attacks are coarse-grained and fundamentally limited: even after masking sensitive cues, models can still infer attributes like gender or income through their reasoning capabilities, especially for low-cardinality attributes. No prior method combines fine-grained, word-level anonymization with a mechanism that actively prevents the inference from occurring at the model level.

## Input / Output

The framework takes free-form user-generated text (e.g., Reddit comments) as input and produces a defended text ready for sharing. TRACE consumes the text plus an attribute-specific query and extracts attention weights from a pretrained causal LM (Llama2-7B-Chat) to identify privacy-leaking words, while RPS additionally requires white-box access to model logits to guide suffix optimization. The output is the original text with targeted edits (TRACE) and/or a short optimized suffix appended (RPS/MPS) that induces the attacker model to refuse or misattribute, without altering the semantic content of the user's writing.

## Method

TRACE performs fine-grained anonymization by extracting a privacy vocabulary via attention scores (aggregated from the last token in the final layer of a causal LM) and generating step-by-step inference chains from an adversarial model, then feeding both signals to an anonymization LLM for targeted text revision. RPS is a gradient-free, two-stage random-search optimization that appends a lightweight suffix: Stage 1 anchors the first generated token to 'I' by maximizing its log-probability, and Stage 2 shapes the second token toward a rejection set (e.g., 'cannot', 'apologize'), using only 1–2 token generations per evaluation for efficiency. For highly instruction-following models where refusal is unreliable, MPS redirects the predicted attribute to an incorrect target (e.g., flipping 'Male' to 'Female') via the same randomized suffix search. The unified TRACE-RPS pipeline first anonymizes privacy-leaking elements, then optimizes the suffix on the anonymized text, reducing inference accuracy from ~50% to below 5% on open-source models.

## Results

On open-source models (Llama2-7B/13B, Llama3.1-8B, DeepSeek-R1-Distill), TRACE-RPS reduces attribute inference accuracy from ~50–57% (No Defense) to 0–2.86% (using GPT-4o as anonymization model), with many configurations reaching exactly 0%. RPS alone already achieves 0–6.48% accuracy, while TRACE alone (without model-internal access) reduces accuracy to 18.10–24.38%. On closed-source models (GPT-4o, Gemini 2.5 Pro), where only TRACE is applicable, inference accuracy drops from 68–71% to 23.81–26.67%, a ~45% relative reduction. Under the stricter attack success rate metric (accounting for random guessing on refusals), TRACE-RPS maintains ASR below 14.10% on open-source models.

## Baselines & Comparisons

Against FgAA (Staab et al., 2025), the closest anonymization baseline, TRACE consistently achieves lower inference accuracy on open-source models (e.g., 18.10% vs. 21.90% on DeepSeek-R1; 18.48% vs. 18.67% on Llama3.1-8B) and on closed-source models (23.81% vs. 26.29% on Gemini 2.5 Pro), confirming that the fine-grained privacy vocabulary and inference chain signals improve over coarse adversarial feedback. TRACE-RPS dominates FgAA by an order of magnitude on open-source models, dropping accuracy from ~20% to below 3%. Against D-Defense (Agnew et al., 2024), which perturbs text at a data level, TRACE-RPS reduces accuracy from 47–53% to 0–2.86% on open-source models, and TRACE alone reduces it from 63–66% to 24–27% on closed-source models. Azure Language Services (Aahill, 2023) and Dou-SD (Dou et al., 2024) are only reported on GPT-4o (56% and 47% respectively on Synthetic); TRACE (GPT-4o) achieves 26.67%, a 20–29 percentage-point improvement over both rule-based and taxonomy-based anonymization approaches.

## Relation to Prior Work

This paper extends the iterative adversarial anonymization framework of Staab et al. (2025, FgAA) by injecting two fine-grained signals—attention-based privacy vocabulary extraction and step-by-step inference chain generation—into each anonymization iteration, moving from coarse text-level editing to word-level targeted revision. More conceptually, it repurposes adversarial prompt optimization (a technique developed for jailbreaking aligned LLMs, e.g., GCG, AutoDAN) as a *defense* mechanism: RPS optimizes a lightweight suffix to induce model refusal, inverting the typical attacker-defender asymmetry. The MPS variant further extends this by redirecting predictions to incorrect attributes when outright refusal is infeasible on highly instruction-following models.

## Why It Matters / Open Questions

The paper establishes that anonymization alone is fundamentally insufficient for limited-category attributes (gender, income) where even obfuscated text yields parsable data points for large-scale inference, motivating the shift to inference-prevention via model refusal. A key open question is robustness: adaptive attacks (suffix removal, LLM-based sanitization) degrade RPS accuracy from ~2% to ~24–34%, suggesting the defense is not yet deployment-ready against a determined adversary. Additionally, RPS requires white-box logit access, limiting applicability to open-source models, and the optimized suffixes are model-specific, raising questions about long-term maintainability as new architectures emerge.
