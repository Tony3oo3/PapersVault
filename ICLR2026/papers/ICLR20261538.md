## Problem

Current web agent frameworks rely on sequential processing, causing complex deep-research tasks to require 20+ interaction steps and execution times of several hours. This creates a sharp tension between solution quality and computational efficiency, severely limiting practical viability in user-responsive applications. The paper asks whether reimagining agent execution from linear chains to structured concurrency can resolve this trade-off.
![Teaser figure](../imgs/ICLR20261538/cropped_page1_idx0.webp)

## Input / Output

The framework accepts a single text query (e.g., a complex web research question) and produces a final text answer after executing a dynamically refined DAG plan. The plan decomposes the task into 1–5 parallel goals, each containing 1–5 sequential fallback paths, with up to 5 tool calls per step and a total budget of 40 steps. The two available tools are a Serper-based search API (returning 5 ranked results per call) and a Jina Reader crawl tool that extracts and auto-summarizes page content truncated to 60,000 characters, keeping trajectories compact.

## Method

FLASH-SEARCHER reformulates agent execution as dynamic scheduling over a directed acyclic graph (DAG). A decomposition function produces a plan graph whose nodes are subtasks and whose edges encode prerequisite relations; a readiness predicate φ then permits aggressive parallelization by allowing a subtask to proceed when either all prerequisites are complete or partial auxiliary signals suffice for cross-validation. Every Δ steps, an adaptive refinement rule eliminates resolved nodes, revalidates dependencies, and inserts new decomposition nodes based on intermediate results, effectively integrating a summarization module that keeps the context window tractable. For model distillation, the authors generate 3,354 high-quality DAG-based trajectories using GPT-5, validate them with an LLM-as-judge, and perform lightweight supervised fine-tuning (SFT) on Qwen-2.5-32B/72B via LLaMA-Factory, transferring the parallel reasoning paradigm into standalone single-model agents without reinforcement learning or code-execution tools.

## Results

FLASH-SEARCHER with GPT-5 achieves 67.7% on BrowseComp, 83.0% on xbench-DeepSearch, 82.5% on GAIA, and 44.0% on HLE, setting new state-of-the-art across all four benchmarks. With the lighter GPT-5-mini backbone, it still reaches 80.6% on GAIA (text-only, 103 tasks), surpassing closed-source systems like Alita (75.2%) and Manus (73.3%). In terms of efficiency, FLASH-SEARCHER reduces average agent execution steps by 35% (11.2→7.4 on GAIA) and overall execution time by 65% (27.4→9.6 min on BrowseComp) compared to OAgents. When distilled into standalone Qwen-2.5 models via lightweight SFT, FLASH-SEARCHER-72B achieves 68.0% on xbench-DeepSearch, a 29.3-point improvement over WebDancer.

## Baselines & Comparisons

Against the strongest open-source framework MiroFlow (GPT-5), FLASH-SEARCHER (GPT-5) nearly doubles BrowseComp performance (67.7% vs. 33.2%), leads xbench-DeepSearch by 11 points (83 vs. 72), matches GAIA (82.5 vs. 82.4), and outperforms HLE by 14.5 points (44.0 vs. 29.5). Compared to OAgents (GPT-4.1), FLASH-SEARCHER with the same backbone improves BrowseComp from 13.7% to 31.4%, xbench from 47 to 57, GAIA from 58.3 to 69.9, and HLE from 15.4 to 39.6, while also cutting execution steps by ~60% (5.9 vs. 37.8 on xbench). On GAIA, even the GPT-5-mini variant (80.6%) surpasses Alita (75.2%) and Manus (73.3%), both using Claude-based backbones. In the distilled agent-model setting (Table 1), FLASH-SEARCHER-32B outperforms AFM-RL by 3.3 points on BrowseComp, 5.0 on xbench, and 2.0 on GAIA, and FLASH-SEARCHER-72B leads WebShaper-72B by 1.1 points on GAIA while achieving 68.0 on xbench (vs. WebDancer's 38.7). The only comparison where FLASH-SEARCHER trails is BrowseComp vs. OpenAI ChatGPT agent (67.7% vs. 68.9%), a marginal 1.2-point gap. On simple tasks (Bamboogle), FLASH-SEARCHER ties ReAct sequential (91.2%) but incurs slightly higher latency, confirming the parallel overhead is negligible for accuracy but non-zero for trivial queries.

## Relation to Prior Work

FLASH-SEARCHER carves new ground at the intersection of graph-based planning (Graph of Thoughts, Tree of Thoughts, Plan-over-Graph) and tool-augmented agent execution, but departs from all of these by targeting *parallel tool orchestration* rather than symbolic reasoning or strict topological scheduling. It explicitly contrasts with sequential multi-agent frameworks (OAgents, Alita, Workforce) and linear Tool-Integrated Reasoning pipelines (WebDancer, WebThinker, Search-o1), arguing that their sequential dependency chains are the root cause of the 20+ step / multi-hour latency in deep-research tasks. The relaxed-dependency mechanism (auxiliary early retrieval + heuristic consistency checks) is the paper's most distinctive departure from prior DAG planners like Plan-over-Graph, which enforce strict prerequisite satisfaction before scheduling a node.

## Why It Matters / Open Questions

The 35% step reduction and 65% wall-clock time reduction are practically significant for latency-sensitive deployment, and the demonstration that parallel reasoning transfers via lightweight SFT to open-source Qwen-2.5 models (without RL or code tools) suggests a scalable path to efficient web agents beyond proprietary backbones. However, several open questions remain: the framework's reliance on GPT-5 for trajectory generation introduces a circularity concern for the distillation claim; the relaxed-dependency mechanism is not deeply ablated (when do auxiliary signals help vs. introduce errors?); and the Bamboogle ablation honestly reveals that parallelization adds overhead on simple tasks, motivating adaptive strategy selection that the paper leaves as future work. The large absolute gap between the GPT-5 framework (83% xbench) and the best distilled model (68%) also suggests the paradigm has not yet been fully internalized by smaller models.
