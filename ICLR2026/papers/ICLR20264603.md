## Problem

Manually-designed agentic workflows and fixed routing strategies constrain how LLMs can be coordinated, requiring human expertise to specify topologies, prompts, and model assignments. No single LLM is universally optimal across tasks, yet prior multi-agent methods either use hand-crafted scaffolds or learn only to select from a fixed set of pre-specified coordination patterns. This paper asks whether a small language model can learn, purely through end-to-end reinforcement learning, to discover powerful and adaptive coordination strategies over a pool of heterogeneous worker LLMs.

## Input / Output

The Conductor receives a natural language question and a pool of worker LLMs identified only by ordinal numbers (e.g., 'Model 0', 'Model 1') to prevent name-based bias. It outputs a sequence of up to 5 workflow steps encoded as three parallel Python lists of equal length: model_id (integer index of the assigned worker), subtasks (a natural-language instruction for that step), and access_list (a list specifying which prior steps' outputs are visible to the current worker, with 'all' or empty list as the default binary options). The final answer returned to the user is the output of the last worker in the executed workflow.

## Method

A 7B Qwen2.5 model is trained with GRPO (grouped relative policy optimization) to generate complete agentic workflows in natural language, using a binary reward: 1 if the executed workflow's final answer matches the ground truth, 0.5 for correct format but wrong answer, and 0 for unparseable output. Training uses 960 problems across math, coding, and general reasoning with 64 rollouts per question over 200 iterations and no KL regularization, converging quickly because the powerful worker pool sidesteps the exploration problem typical of small-model RL. The key design choice is using natural language as the output medium, granting the Conductor unrestricted specification freedom over subtask content, agent assignment, and communication topology rather than selecting from a fixed menu. Two finetuning extensions are then added: (1) randomized k-subset agent pools to generalize to arbitrary open/closed-source worker combinations, and (2) recursive topologies where the Conductor can invoke itself as a worker, enabling adaptive test-time scaling by iteratively revising its coordination strategy based on intermediate results.

## Results

The 7B Conductor achieves a 77.27 average across seven reasoning benchmarks, surpassing GPT-5 (74.78), Gemini 2.5 Pro (70.97), and Claude Sonnet 4 (65.69). Headline individual scores include 87.5 on GPQA-Diamond (vs. 84.8 for Gemini 2.5 Pro), 83.93 on LiveCodeBench (vs. 82.90 for GPT-5), and 93.3 on AIME25 (vs. 90.8 for GPT-5). In the controlled constrained setting, the Conductor (72.35 avg) outperforms all multi-agent baselines—MoA (62.13), MASRouter (56.89), Smoothie (56.48), and RouterDC (52.41)—while using an average of only 3 workflow steps versus 4–5+ for competing methods.

## Baselines & Comparisons

The Conductor outperforms every individual worker LLM on all seven benchmarks, with the largest margins over open-source models (e.g., +45.1 avg over gemma-3-27b-it) and consistent 2.5–11.6 point gains over frontier closed-source models (GPT-5, Gemini 2.5 Pro, Claude Sonnet 4). Against multi-agent coordination baselines in the constrained setting, the Conductor (72.35 avg) beats MoA (62.13) by 10.2 points, MASRouter (56.89) by 15.5 points, Smoothie (56.48) by 15.9 points, and RouterDC (52.41) by 20.0 points, while also using fewer API calls (avg. 3 steps vs. 4–5+ for MASRouter and MoA). Notably, the Conductor also surpasses each individual worker even when those workers are given 5× self-reflection or 5× context length, indicating that learned coordination strategies provide gains beyond simple compute scaling. The recursive extension adds further gains on out-of-distribution tasks (e.g., BigCodeBench 37.8→40.0, GPQA-D 81.31→82.32), demonstrating adaptive test-time scaling. Ablations confirm that both targeted subtask prompt engineering and diverse agent selection are essential: fixing all agents to GPT-5 drops BigCodeBench from 37.86 to 33.50, and removing subtasks drops LiveCodeBench from 64.29 to 58.62.

## Relation to Prior Work

This paper extends the RL reasoning paradigm established by DeepSeek-R1/DeepSeekMath (GRPO training with verifiable rewards) from single-model self-reflection to multi-agent orchestration, where the reward signal comes from executing a full agentic workflow rather than a single completion. It departs sharply from prior multi-agent coordination work (MoA, MASRouter, RouterDC, Smoothie, GPTSwarm), which either hand-designs fixed topologies or learns a router over a small set of pre-specified strategies; here, a small 7B LLM is trained end-to-end via RL to output arbitrary natural-language coordination plans (subtasks, agent assignments, communication topologies) with no structural constraints. The recursive topology extension and adaptive worker-pool finetuning further generalize the framework beyond what prior routing or scaffolding approaches support.

## Why It Matters / Open Questions

The result that a 7B Conductor, by learning prompt engineering and coordination strategies, outperforms every individual frontier model (GPT-5, Gemini 2.5 Pro, Claude Sonnet 4) on AIME25, GPQA-Diamond, and LiveCodeBench by margins comparable to generational model improvements is a strong signal that collective intelligence via learned orchestration is a viable scaling axis orthogonal to model size. The recursive self-calling mechanism introduces a new tunable test-time compute knob, and the adaptive worker-pool finetuning shows the approach can be customized to cost constraints without performance loss. Open questions include whether the Conductor's gains persist as individual worker models improve (reducing the coordination gap), whether the 960-problem training set is sufficient for robust generalization, and how the framework extends to multimodal or non-LLM workers.
