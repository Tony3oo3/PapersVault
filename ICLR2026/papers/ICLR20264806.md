## Problem

Tool retrieval suffers from a persistent semantic gap between user queries and tool documentation, but the paper argues the root cause is the documentation itself: it is heterogeneous (the same function appears in up to seven different phrasings across 35 datasets) and incomplete (41.6% of sampled documents lack clear functional statements or usage guidance). Existing expansion and augmentation strategies work around this problem at query time rather than fixing the source, creating a performance ceiling for retrieval models.
![Teaser figure](../imgs/ICLR20264806/cropped_page2_idx0.webp)

## Input / Output

The retrieval stage takes a natural-language user query and a corpus of tool documents (each a JSON object with fields like name, description, parameters, responses, plus an optional tool_profile sub-object containing function_description, tags, when_to_use, and limitations) and outputs a ranked list of top-K tools. The reranking stage takes a query–document pair and produces a single relevance probability computed by normalizing the true/false token logits from a single forward pass. On average, expansion adds ~46 tokens per document (132→178 tokens), and the tool_profile is strictly grounded in the original documentation with unsupported fields omitted.

## Method

The core contribution is a four-stage LLM-based document expansion pipeline: Qwen3-32B (in reasoning mode) generates structured tool profiles from raw docs, LLaMA-3.1-70B verifies faithfulness via semantic judgement, GPT-4o refines the ~1.5% of failures, and human annotators validate a random sample. On top of the expanded corpus, two dedicated models are trained: Tool-Embed (Qwen3-Embedding-0.6B/4B fine-tuned with InfoNCE contrastive loss on 50k query–tool pairs with 5 hard negatives each, full-parameter via DeepSpeed ZeRO-3) and Tool-Rank (Qwen3-Reranker-4B fine-tuned with LoRA r=32 on 200k pairs using cross-entropy). A key ablation finding is that the example_usage field actually degrades retrieval, so it is excluded from the final expanded profiles. Training data is drawn exclusively from Web-category tools (APIGen + ToolBench), while evaluation spans Web, Code, and Customized categories, establishing a genuine OOD setting. The paper further shows that expansion acts as both a training signal (reducing structural heterogeneity and stabilizing optimization) and an evaluation-time enabler (asymmetrically reducing similarity scores for negatives more than positives, sharpening the positive–negative gap for both retrievers and rerankers).

## Results

On TOOL-REX, Tool-Embed-4B achieves 52.23 NDCG@10, 63.13 Recall@10, and 51.61 Completeness@10, surpassing the strongest open-source baseline (Qwen3-Embedding-8B) by +6.00, +6.30, and +4.91 respectively. After reranking with Tool-Rank-4B, the full pipeline reaches 56.44 NDCG@10, 67.81 Recall@10, and 56.60 Completeness@10, corresponding to improvements of +10.23, +10.29, and +9.08 over the MTEB SoTA open-source model. On the original (non-expanded) ToolRet benchmark, Tool-Embed-4B also leads with 51.51 NDCG@10, confirming that expansion-trained models generalize to unmodified documents. The 0.6B variant (Tool-Embed-0.6B) already outperforms all baselines up to 8B parameters, demonstrating strong parameter efficiency.

## Baselines & Comparisons

Tool-Embed-4B outperforms all 12 baselines on both ToolRet and TOOL-REX across all three metrics. Against the strongest dense retriever baseline (Qwen3-Embedding-8B), Tool-Embed-4B gains +5.30 NDCG@10 on ToolRet and +6.00 on TOOL-REX, while the smaller Tool-Embed-0.6B already surpasses Qwen3-Embedding-8B by +1.14 NDCG@10 on TOOL-REX. For reranking (Table 3), Tool-Rank-4B improves over Tool-Embed-4B's initial retrieval by +4.21 NDCG@10 (to 56.44), substantially exceeding the gains from off-the-shelf rerankers: jina-reranker-m0 (+0.37), bge-reranker-v2-gemma (+0.62), and Qwen3-Reranker-4B (+1.20). Notably, document expansion benefits even non-expansion-trained baselines at evaluation time: BM25s gains +2.94 NDCG@10 and GritLM-7B gains +2.41 when evaluated on TOOL-REX versus ToolRet, confirming that the enriched documentation helps all models, not just the proposed ones. The only baseline that slightly degrades on TOOL-REX is e5-mistral-7b-instruct (−1.17 NDCG@10), suggesting that models with weaker semantic alignment may be negatively affected by the additional document length.

## Relation to Prior Work

This paper builds directly on ToolRet (Shi et al., 2025), the most comprehensive existing tool-retrieval benchmark, and departs from prior augmentation strategies (Re-Invoke, EASYTOOL, MassTool, ScaleMCP) that work around poor documentation at inference time by instead fixing the data source: systematically enriching tool documents with structured fields (function description, tags, when-to-use, limitations) via an LLM-based pipeline. Conceptually, it bridges the classical IR document-expansion literature (Query2doc, EnrichIndex) with the tool-retrieval setting, arguing that the semantic gap between user queries and tool documentation is a data-quality problem rather than a model-capacity problem. The resulting TOOL-REX benchmark and 250k training corpora position this work as a data-centric contribution that complements, rather than replaces, model-level innovations in dense retrieval and LLM reranking.

## Why It Matters / Open Questions

TOOL-REX provides the first dedicated benchmark for document-expanded tool retrieval along with large-scale training data (50k for retrievers, 200k for rerankers) that the community can immediately adopt, and the OOD evaluation design (Web-only training, Code/Customized testing) mirrors real-world deployment where new tool categories emerge without retraining. The finding that example_usage actively hurts retrieval and that expansion's benefit at evaluation time comes from asymmetric similarity reduction (negatives drop more than positives) offers actionable guidance for practitioners designing tool documentation. Open questions include whether the LLM-generated expansions introduce subtle biases that compound at scale, whether the pipeline generalizes to non-English or highly domain-specific tool ecosystems, and whether the structured-field approach can be extended to multi-turn or stateful tool interactions.
