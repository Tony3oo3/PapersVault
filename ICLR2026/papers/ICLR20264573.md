## Problem

Existing tabular anomaly detection methods each rely on specific, fragile assumptions about anomaly patterns (e.g., PCA assumes high reconstruction error, IForest assumes easy isolation) that are frequently violated by real-world heterogeneous data, leading to inconsistent performance. While LLMs show strong reasoning capabilities, their direct application to tabular AD is blocked by difficulties processing heterogeneous numerical features and significant privacy risks from exposing raw data. The paper asks whether one can systematically enhance existing detectors against violations of their own core logic without designing yet another detector with new fragile assumptions.
![Teaser figure](../imgs/ICLR20264573/cropped_page1_idx0.webp)

## Input / Output

The LLM receives only a high-level textual description of a detector algorithm (pseudo-code and mechanism summary) and a structured prompt specifying symbolic interfaces (e.g., a trained model exposing predict_score(), training samples X_train, and a sample count N_syn)—it never observes raw data or model parameters. The LLM outputs a reusable, detector-specific Python function that, when instantiated on a concrete dataset, produces an array of synthetic 'hard' anomalies of shape (n_samples, d). The final system outputs a fused anomaly score per test sample, computed as the sum of min-max normalized scores from the original one-class detector and a binary enhancement classifier trained on the augmented data.

## Method

LLM-DAS is a two-stage framework that repositions the LLM as an 'algorithmist' rather than a 'data processor.' In Stage 1 (data-agnostic reasoning), the LLM analyzes a detector's algorithmic description, infers its intrinsic weaknesses, and generates a reusable Python synthesis program that encodes a detector-specific policy for creating hard anomalies—e.g., for IForest, identifying borderline normal samples near the decision boundary and applying controlled extrapolation along the data-center-to-seed direction to preserve long isolation paths. In Stage 2 (data-specific instantiation), this code is executed on a concrete training set and fitted score function to synthesize anomalies that are factually anomalous yet algorithmically 'camouflaged' to the target detector. These synthetic anomalies augment the normal-only training set, transforming the problem from one-class to two-class classification; a binary classifier is trained on the augmented data and its score is fused with the original detector's score via min-max normalization. Cross-detector experiments confirm that detector-awareness is critical: applying a PCA-specific synthesis code to OCSVM causes significant degradation, while matched code yields consistent gains across 36 benchmarks.

## Results

Across 36 tabular anomaly detection benchmarks, LLM-DAS consistently improves all five source detectors on both AUC-PR and AUC-ROC. The largest relative gain is on OCSVM, where AUC-PR improves by 84.49% (from 0.5295 to 0.6018) and AUC-ROC by 10.02%. IForest shows the most consistent absolute AUC-PR gain (+0.0617, 23.60% relative), while DRL (the strongest baseline at 0.7437 AUC-PR) still gains +0.0412 (15.81%). All improvements are statistically significant (p < 0.05) via paired one-tailed t-tests, with win counts ranging from 21/36 (DRL AUC-ROC) to 30/36 (PCA AUC-PR).

## Baselines & Comparisons

LLM-DAS improves all five source detectors (PCA, IForest, OCSVM, ECOD, DRL) across 36 datasets, with the most dramatic relative gain on OCSVM (+84.49% AUC-PR) and the most consistent absolute gain on IForest (+0.0617 AUC-PR). Against conventional baselines (KNN, LOF) and advanced deep-learning TAD methods (Deep SVDD, AutoEncoder, ICL, DTE, MCM, NPT-AD), LLM-DAS coupled with DRL achieves the highest average AUC-PR across shared datasets (Fig. 3). Compared to AnoLLM (Tsai et al., 2025), which fine-tunes a small LLM per dataset, LLM-DAS outperforms it while incurring far lower computational cost, since the LLM is used only twice per detector type (code generation) and the resulting code is reusable across all datasets. Against naive anomaly synthesis alternatives (Gaussian noise, random outliers, SMOTE), LLM-DAS delivers consistent improvements across all detectors, whereas generic methods like random outlier generation can severely degrade sophisticated models like DRL. Cross-detector experiments confirm that detector-aware synthesis is critical: using OCSVM-specific code for OCSVM yields +6.53% average AUC-PR improvement, while mismatched code (e.g., PCA code for OCSVM) causes a −4.72% average drop.

## Relation to Prior Work

This paper departs from the dominant paradigm of applying LLMs to tabular data as 'data processors' (e.g., AnoLLM, TabLLM, LIFT), which require direct access to raw feature values and incur fine-tuning costs. Instead, it repurposes LLMs as 'algorithmists' that reason about a detector's high-level logic and generate reusable, data-agnostic Python synthesis code. On the anomaly detection side, it builds on the well-known observation that one-class detectors (PCA, IForest, OCSVM, ECOD, DRL) each rely on fragile assumptions, but rather than proposing yet another detector, it introduces a plug-and-play enhancement module that programmatically targets each detector's specific blind spots. The approach also contrasts with generic data augmentation strategies (Gaussian noise, SMOTE, random outliers) by operating at the logic level rather than the data level.

## Why It Matters / Open Questions

The framework addresses two practical barriers simultaneously: LLMs' inherent difficulty with heterogeneous tabular features and the privacy risk of exposing sensitive data to an LLM, since the LLM never sees raw data. The one-time, two-API-call cost per detector type (reusable across all datasets) makes it economically attractive compared to fine-tuning-based approaches like AnoLLM. Open questions include whether the paradigm generalizes to more complex or ensemble-based detectors, how robust the LLM-generated code is across different LLM backbones (the paper uses Gemini 2.5-Pro), and whether the 'algorithmist' framing can be extended to other ML tasks beyond anomaly detection. The cross-detector mismatch experiment (where applying PCA-specific code to OCSVM can degrade performance by ~0.19 AUC-PR) underscores that the gains are genuinely detector-specific rather than a generic augmentation effect.
