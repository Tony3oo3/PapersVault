## Problem

Current LLM-based agents for repository-level code localization treat every bug as a fresh puzzle, assuming no prior knowledge of the codebase. Unlike human developers who accumulate long-term memory of module purposes and recurring bug patterns, these agents lack any mechanism to leverage the repository's evolutionary history, leading to premature reasoning failures on complex localization tasks.

## Input / Output

The method takes a bug/issue description, the full repository codebase (parsed into a directed heterogeneous graph of code entities and dependencies), and the 7,000 commits prior to the issue's base commit as input. It produces a ranked list of relevant files, evaluated via Accuracy@k (the percentage of examples where the top-k predicted files completely cover the ground-truth files). The commit history is preprocessed offline into two searchable memory stores, while the codebase graph is built once per repository; at inference time the agent iteratively queries both memory stores and the code graph in a ReAct loop.

## Method

RepoMem augments the LocAgent framework with two complementary non-parametric memory stores built from commit history. The episodic memory indexes recent commits and their linked issues, accessible via BM25-based SearchCommit (keyword matching against commit messages) and ExamineCommit (retrieving full patches and linked issue text). The semantic memory identifies the top-200 most frequently edited files as 'development hotspots' and uses an LLM to generate high-level functionality summaries for each, queryable via ViewSummary and SearchSummary. These four tools are added to LocAgent's existing graph-navigation tools (SearchEntity, TraverseGraph, RetrieveEntity), expanding the agent's action space so it can form experience-based hypotheses from memory before performing detailed structural code exploration. The key design choice is using sparse BM25 retrieval with an LLM-based tokenizer that recognizes code entity names, which outperforms dense retrieval (GritLM-7B) due to the rigid, entity-centric vocabulary of software repositories.

## Results

On SWE-bench-verified, RepoMem achieves 76.5% Acc@5, a 4.9-point absolute improvement over the LocAgent baseline (71.6%) and a 22.2-point gain over the retrieval-based CodeRankEmbed (54.3%). On the more diverse SWE-bench-live benchmark, RepoMem reaches 66.2% Acc@5 versus 63.1% for LocAgent and 52.3% for CodeRankEmbed. Ablations confirm both memory components contribute: episodic-only yields 74.3% and semantic-only yields 72.8% Acc@5 on SWE-bench-verified, with the full combination achieving the best result.

## Baselines & Comparisons

RepoMem outperforms all three baselines on both benchmarks across all metrics. Against the strongest baseline LocAgent (the agentic framework it builds upon), RepoMem gains +4.9 points on Acc@5 (76.5 vs. 71.6) and +3.8 points on Acc@1 (68.6 vs. 64.8) on SWE-bench-verified, with consistent but smaller gains on SWE-bench-live (+3.1 Acc@5, +1.6 Acc@1). Against Agentless, the procedural method, RepoMem leads by +5.1 Acc@5 on SWE-bench-verified and +3.9 on SWE-bench-live. The retrieval-based CodeRankEmbed is the weakest baseline, trailing RepoMem by 22.2 points on Acc@5 for SWE-bench-verified and 13.9 points on SWE-bench-live. Notably, per-repository analysis shows the gains are concentrated in repositories with rich commit histories (e.g., +16.7 on pytest, +11.4 on sphinx), while performance degrades by 13.1 points on repositories with limited history (<10K commits), where sparse memory can distract the agent.

## Relation to Prior Work

This paper builds directly on LocAgent, a graph-guided ReAct-based agentic framework for code localization, by expanding its action space with two non-parametric memory tools derived from commit history. Conceptually, it draws on the Just-in-Time Software Defect Prediction literature for the intuition that frequently modified files ('hotspots') and historical commit contexts are strong indicators of where defects reside, and on the broader memory-enhanced agent literature (e.g., Chen et al. 2025a, Qian et al. 2024) while departing from them by grounding memory in repository-specific evolution rather than the agent's own trajectory. Unlike prior agentic frameworks that treat each issue as a fresh puzzle, RepoMem introduces a lightweight, pre-computed episodic memory (searchable commit/issue corpus) and semantic memory (LLM-generated summaries of active files) that require no retraining and integrate modularly into existing toolsets.

## Why It Matters / Open Questions

The paper identifies a concrete and underexplored gap—memoryless agents cannot accumulate repository expertise the way human developers do—and shows that a surprisingly simple non-parametric solution (BM25 over commit messages + LLM summaries of top-200 active files) yields consistent gains across two benchmarks. Key limitations include performance degradation on repositories with sparse commit history (−13.1% on the 'others' group), reliance on explicit commit-to-issue links that are often noisy or missing, and the finding that irrelevant retrieved memory can actively distract the agent. Open questions include training agents to strategically decide when to consult memory versus defaulting to first-principles exploration, adopting more sophisticated JiT-SDP filtering (time-decay, co-change history), and whether the approach generalizes beyond Python-centric SWE-bench repositories.
