## Problem

Existing data science benchmarks evaluate isolated capabilities (code generation from fine-grained prompts, text-to-SQL, modeling on curated inputs) but fail to capture the end-to-end complexity of real-world data science over data lakes with heterogeneous, unclean, and domain-specific files. It remains unclear whether current LLM-based agentic systems can discover relevant data, design multi-step pipelines, and execute them to produce correct insights without human intervention.
![Teaser figure](../imgs/ICLR20264852/cropped_page1_idx0.webp)

## Input / Output

Each task provides a natural language question plus an entire domain data lake (up to 1,700 files totaling 1.7 GB across structured, semi-structured, and unstructured formats from 24 sources). The system must produce executable code that yields a final answer scored against ground truth using type-specific metrics (exact/approximate string via ParaPlue, numeric via 1/(1+RAE), list via F1). Three evaluation settings decompose the problem: end-to-end automation (full pipeline score), pipeline design (fraction of key functionalities covered, judged by LLM), and sub-task implementation (per-step correctness on 633 annotated sub-tasks). 20% of tasks use obscured inputs (synthetic identifiers replacing real ones) to isolate data-leakage effects.

## Method

KRAMABENCH comprises 104 manually curated tasks across 6 domains (archeology, astronomy, biomedical, environment, legal, wildfire), each grounded in published studies and validated through a 4-step curation pipeline (task creation, cross-contributor validation, key functionality identification via GPT-o3 instruction-tuning, and sub-task curation via Gemma3-27b). The reference system DS-Guru is a lightweight single-agent scaffold with three variants (no-context, one-shot, few-shot) that uses budgeted One-Pass Sampling retrieval and chain-of-thought decomposition before code synthesis. The paper evaluates 8 LLMs across six system configurations—DS-Guru, smolagents DR (single-agent ReAct), smolagents Reflexion (actor→evaluator→reflection), smolagents PDT (planner→executor), OpenAI Deep Research, and Gemini 2.5 Pro Agentic—under Full, Oracle, and Trimmed input modes. Key findings: agentic control flow (smolagents DR + Claude-3.7) reaches 55.83% end-to-end accuracy versus 24.98% for the best DS-Guru variant; oracle retrieval improves accuracy by only 0–7%, revealing that fine-grained data-dependent reasoning (capped at 22% on sub-tasks) and holistic data-lake understanding (24% of failures from 'failure to ask for clarification') are the dominant bottlenecks rather than file retrieval.

## Results

On KRAMABENCH (104 tasks, 6 domains, 1,700+ files), the best system—smolagents DR with Claude-3.7—achieves 55.83% end-to-end accuracy under Full input mode, while smolagents Reflexion with Claude-3.7 reaches 62.81% under Oracle input (gold files only). The best structured-control-flow baseline, DS-Guru few-shot with GPT-o3, achieves only 24.98% (Full) and 43.71% (Oracle). In the lower-automation settings, leading LLMs identify up to 41.71% of key pipeline design components but fully implement only 22.05% of individual sub-tasks. A human baseline of 9 data-science practitioners scores 76.75%, highlighting a substantial gap.

## Baselines & Comparisons

Agentic control flows dramatically outperform structured ones: smolagents DR (Claude-3.7) achieves 55.83% end-to-end accuracy, more than doubling the best DS-Guru variant (few-shot, GPT-o3 at 24.98%) under Full input. Under Oracle input (removing retrieval as a variable), smolagents Reflexion (Claude-3.7) edges out smolagents DR (62.81% vs. 60.67%), while DS-Guru few-shot (GPT-o3) jumps to 43.71%, confirming that retrieval is a contributing but not dominant bottleneck. Among multi-agent designs, the simple Reflexion evaluator loop (55.37%) performs nearly identically to the single-agent DR baseline (55.83%), suggesting that generic evaluator-style coordination adds little value over data-intensive workflows. Closed-source systems evaluated under the constrained Trimmed setting (≤10 files) show OpenAI Deep Research at 52.18% (with web access) and Gemini 2.5 Pro Agentic at only 18.48%, both below the best open-source agentic systems. The DeepAnalyze-8B system (14.98%) and DS-Guru with weaker models (GPT-4o: 8.67%, Llama-3.3: 8.40%, DeepSeek-R1: 0.33%) all fall well below the top performers, indicating that model quality and agentic architecture are both critical.

## Relation to Prior Work

KRAMABENCH carves new ground by being the first benchmark to evaluate end-to-end data-to-insight pipelines over heterogeneous data lakes, whereas prior data science benchmarks (DS-1000, ARCADE, DA-Code, DataSciBench, DSBench, BLADE) test isolated components such as code generation from fine-grained prompts, text-to-SQL, or modeling on curated inputs. The paper repurposes existing agentic architectures (ReAct-style single-agent, Reflexion multi-agent, PDT planner-executor) from the general-purpose agent literature and applies them to a data-intensive, multi-file, domain-specific setting that none of these systems were designed for. Its reference framework DS-Guru draws on chain-of-thought prompting, one-pass sampling retrieval, and multi-shot error recovery, but the key contribution is the benchmark itself and its three-level evaluation (end-to-end, pipeline design, sub-task implementation) rather than a new method.

## Why It Matters / Open Questions

The benchmark reveals that even the best agentic system reaches only 55% end-to-end accuracy (62% with oracle retrieval), and that the dominant bottleneck is fine-grained data-dependent reasoning rather than file retrieval (oracle improves scores by only 0–7%). The finding that simple evaluator-style multi-agent coordination (Reflexion) provides essentially no gain over a single-agent ReAct loop (−0.45%) challenges the prevailing assumption that more complex multi-agent topologies are needed for data-intensive workflows. Open questions include how to incorporate domain-specific conventions (e.g., encoding schemes in column names), how to reduce reliance on parametric knowledge (up to 43% performance fluctuation on obscured inputs), and whether specialized multi-agent designs beyond generic evaluator-reflection loops can close the remaining gap to human performance (76.75%).
