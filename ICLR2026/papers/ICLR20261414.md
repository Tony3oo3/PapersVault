## Problem

Multimodal large language models have advanced significantly in visual and textual understanding, yet their ability to generate functional code from visual inputs—such as translating UI mockups into HTML or replicating data charts—remains severely limited. Existing MLLMs excel at visual description but lack the deep programming knowledge required for syntactically correct and functionally robust code generation, creating a critical gap for practical development tasks that demand seamless fusion of visual perception and coding proficiency.
![Teaser figure](../imgs/ICLR20261414/cropped_page1_idx1.webp)

## Input / Output

The model accepts arbitrary-resolution RGB images (webpage screenshots, chart images, error message captures, code-related screenshots) paired with natural-language instructions or questions, leveraging Qwen2.5-VL's 2D RoPE mechanism to handle variable image sizes without fixed resolution constraints. Outputs span multiple code formats: complete HTML/CSS files for UI-to-code translation, Python matplotlib scripts for chart reproduction, and code answers with explanations for programming QA and algorithmic problems. The benchmark InfiBench-V specifically requires images that are indispensable to the solution, ensuring visual context is genuinely necessary rather than decorative.

## Method

VisCodex employs a task-vector-based model merging strategy that arithmetically combines a vision-language model (Qwen2.5-VL) with a code-specialized LLM (OpenCodeReasoning-Nemotron) by computing their respective task vectors relative to a shared base model and linearly interpolating them: θ_VisCodex = θ_base + λ·τ_vlm + (1−λ)·τ_code, with λ=0.7 selected via validation. Crucially, merging is restricted to the language model backbone only—the vision encoder and cross-modal projection modules remain frozen—preserving intrinsic visual grounding while injecting code reasoning capability. Layer-wise CKA analysis reveals the two task vectors occupy nearly orthogonal subspaces (mean cosine similarity ~0.03), explaining why linear combination avoids destructive interference. After merging, the model undergoes supervised fine-tuning on the 598k-sample McD dataset with only the LLM backbone unfrozen, and this merged initialization consistently outperforms both standard SFT and direct backbone replacement, the latter of which disrupts visual-semantic alignment in deep layers (CKA drops to ~0.39 at the output layer).

## Results

VisCodex-8B achieves an average score of 68.8 across four multimodal coding benchmarks, surpassing the proprietary GPT-4o-mini (65.7) and all open-source models in the 7–15B range. VisCodex-33B reaches 72.3 on average, approaching GPT-4o (73.3) while outperforming all open-source large models (best: Qwen2.5-VL-32B at 67.6). On Design2Code, both VisCodex variants match or exceed GPT-4o (90.1/90.9 and 90.5/91.1 vs. 90.2/90.4), and on ChartMimic Low-Level, VisCodex-33B edges out GPT-4o (79.3 vs. 79.0). The largest absolute gains over the Qwen2.5-VL baseline appear on ChartMimic (+35.3 Low-L for 8B) and MMCode (+5.7 pass@1 for 8B), confirming that model merging primarily augments code-generation capability while preserving visual understanding.

## Baselines & Comparisons

Against the Qwen2.5-VL-7B-Instruct backbone (83.4/87.6/39.5/38.3/5.3/54.0), VisCodex-8B improves every metric, with the largest jumps on ChartMimic Low-L (+35.3) and MMCode pass@1 (+5.7). Compared to GPT-4o-mini, VisCodex-8B wins on Design2Code (90.1 vs. 85.8), ChartMimic (74.8 vs. 68.4), and InfiBench-V (72.1 vs. 71.9), but trails slightly on MMCode (11.0 vs. 12.2). VisCodex-33B outperforms all open-source large models—Qwen2.5-VL-32B (67.6 avg), InternVL3-78B (65.9), and llava-onevision-72B (56.5)—by 4.7 to 15.8 points on average. Against GPT-4o, VisCodex-33B wins on Design2Code (90.5/91.1 vs. 90.2/90.4) and ChartMimic Low-L (79.3 vs. 79.0), but loses on ChartMimic High-L (78.5 vs. 83.5), MMCode (15.6 vs. 17.0), and InfiBench-V (78.6 vs. 79.9), yielding a 1.0-point average gap. The ablation in Table 4 further shows that model merging outperforms both 1-stage and 2-stage backbone replacement on Design2Code and ChartMimic, confirming that the merging strategy preserves visual-semantic alignment that direct replacement disrupts.

## Relation to Prior Work

This paper extends the task-vector-based model merging framework of Ilharco et al. (2022) and its recent application to multimodal mathematical reasoning (Chen et al., 2025) to the domain of code generation. Rather than retraining or replacing the language backbone of a vision-language model, it linearly combines the VLM's task vector with a coding LLM's task vector, then performs supervised fine-tuning on a new 598k-sample dataset (McD). The approach builds on the Qwen2.5-VL architecture and draws training data from existing resources (Web2Code, Chart2Code, StackOverflow, Kodcode), while introducing a unified framing that spans UI-to-code, chart-to-code, visual QA, and algorithmic coding under a single model.

## Why It Matters / Open Questions

The practical significance lies in offering a low-cost, generalizable recipe for injecting domain-specific capabilities (here, code) into MLLMs without full retraining or backbone replacement—validated across both Qwen and Llama architectures. The McD dataset and InfiBench-V benchmark fill notable gaps in training data and realistic evaluation for multimodal coding. Open questions include whether more sophisticated merging strategies (e.g., TIES, Fisher-weighted) could further improve the trade-off, whether the approach transfers to other capability domains beyond code, and whether the linear combination remains effective as model scale increases beyond 33B.
