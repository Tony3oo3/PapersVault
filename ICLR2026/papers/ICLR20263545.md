## Problem

Existing visualization coding agents are constrained to single languages (primarily Python or Vega-Lite), produce code that frequently fails at runtime, and lack mechanisms for iterative self-correction. Datasets and benchmarks in this space emphasize single-round generation without execution validation or multi-turn debugging, leaving a substantial gap between model capabilities and the iterative, multi-language workflows that real-world data analysis demands.
![Teaser figure](../imgs/ICLR20263545/cropped_page0_idx2.webp)

## Input / Output

The agent receives a structured natural language instruction composed of five parts (Setup, Plot Instruct, Data Instruct, Task Description, Style Description) along with a CSV data file whose schema is provided in the prompt. In self-debug mode, the model additionally receives its prior code and an excerpt of the execution log for up to three correction rounds. Output is a single executable code block in one of eight target languages (Python, Vega-Lite, LilyPond, Mermaid, SVG, LaTeX, Asymptote, HTML) that must run without error and produce a valid, non-monochrome rendered image larger than 10 KB.

## Method

VisCoder2 is built on three complementary resources. First, VisCode-Multi-679K is a 679K-sample instruction-tuning dataset constructed via a four-stage pipeline (library-based filtering, GPT-4.1-mini code-block extraction, Jupyter runtime validation, and GPT-4.1 instruction generation) over the-stack-v2, svg-diagrams, and CoSyn-400K, augmented with 66K multi-turn Code-Feedback dialogues that teach iterative correction. Second, VisPlotBench provides 888 executable tasks across 8 languages and 13 visual categories under a standardized execute-render-score protocol with a multi-round self-debug loop. Third, VisCoder2 models are obtained by full-parameter fine-tuning Qwen2.5-Coder backbones (3B–32B) on VisCode-Multi-679K for 3 epochs at lr 5×10⁻⁶ with a cosine schedule on 8×H100 GPUs. The key design insight is that combining validated multi-language executable code with explicit multi-turn correction supervision enables the model to both generate correct code on the first pass and repair shallow structural or interface errors through execution-feedback-driven self-debug, yielding up to ~10-point execution pass rate gains especially on symbolic languages like LilyPond, LaTeX, and Asymptote.

## Results

On VisPlotBench (888 tasks across 8 languages), VisCoder2-32B achieves 73.1% overall execution pass rate, surpassing GPT-4.1 (63.4%) by ~10 points without self-debug. With iterative self-debug, VisCoder2-32B reaches 82.4%, matching GPT-4.1+Self Debug (82.4%) and exceeding GPT-4.1-mini+Self Debug (81.1%). At the 7B scale, VisCoder2-7B improves overall pass rate from 51.2% (Qwen2.5-Coder-7B) to 70.9%, with the largest gains on symbolic languages: LilyPond jumps from 5.5% to 69.1% and Asymptote from 13.0% to 64.1%.

## Baselines & Comparisons

Against GPT-4.1, VisCoder2-32B (73.1%) already exceeds the proprietary model's 63.4% overall pass rate without self-debug, and with self-debug both reach 82.4%, achieving parity. VisCoder2-32B+Self Debug also surpasses GPT-4.1-mini+Self Debug (82.4% vs. 81.1%), particularly on LilyPond (69.1% vs. 56.4%) and Asymptote (71.7% vs. 48.9%). Among open-source baselines, VisCoder2 consistently outperforms Qwen2.5-Coder by 12–22 points at every scale (e.g., 70.9% vs. 51.2% at 7B; 73.1% vs. 57.5% at 32B), and beats DeepSeek-Coder variants by 15–20 points (e.g., 70.9% vs. 46.4% at 7B; 73.1% vs. 54.3% at 33B). VisCoder2 also improves over the prior single-language VisCoder by 11–14 points (67.7% vs. 56.1% at 3B; 70.9% vs. 57.2% at 7B), with the largest gains on symbolic languages where VisCoder had near-zero performance. The one consistent weakness is SVG, where VisCoder2-32B (81.5%) trails Qwen2.5-Coder-32B (93.9%) by over 12 points, suggesting library-specific rendering sensitivity rather than a semantic gap.

## Relation to Prior Work

This paper extends the visualization code generation line (VisCoder, LIDA, PandasPlotBench) from single-language, single-round settings to a multi-language, iterative-correction framework. It draws on multi-language code corpora (The Stack v2, OctoPack-style instruction tuning) and self-debug agent paradigms (OpenCodeInterpreter, SWE-bench) but repurposes them specifically for visualization, where rendered outputs provide a natural execution signal. The key departure from prior work is the deliberate inclusion of symbolic and compiler-dependent languages (LilyPond, LaTeX, Asymptote) alongside mainstream ones, combined with multi-turn Code-Feedback dialogues as first-class training supervision rather than an afterthought.

## Why It Matters / Open Questions

The paper establishes the first systematic multi-language visualization coding benchmark with a standardized execute-render-score protocol and self-debug loop, filling a clear gap where prior benchmarks were Python- or Vega-Lite-only and single-round. The finding that symbolic languages remain the dominant bottleneck even for GPT-4.1 (under 45% on LilyPond, under 25% on Asymptote) and that self-debug is the critical mechanism for closing that gap points toward grammar-aware training objectives and more robust runtime integration as the next frontier. Limitations include imbalanced training data across languages and benchmark coverage of only eight languages, leaving open whether the approach generalizes to additional frameworks and whether the current self-debug protocol can address persistent semantic and runtime errors.
