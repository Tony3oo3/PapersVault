## Problem

Small language models (SLMs) tasked with generating probabilistic programs in libraries like PyMC frequently produce code with semantic errors—wrong parameter names, hallucinated distributions, or statistically incorrect specifications—that pass syntax checks but yield unreliable posterior inference. Existing approaches either rely on expensive closed-source LLMs (e.g., GPT-4 in BoxLM) or enforce only syntactic constraints, leaving a gap for efficient, reliable probabilistic program synthesis using open-weight SLMs under standard Bayesian workflow diagnostics.

## Input / Output

The method takes a user-provided dataset (numeric arrays), a text prompt describing the modeling task with a partial PyMC/NumPyro code template, and a target PPL library. It produces a complete probabilistic program structured as a data block (D), prior block (P), and likelihood block (L), along with posterior samples and a seven-dimensional diagnostic reliability score (split-R, BFMI, ESS bulk/tail, divergences, Pareto-k fraction, ELPD finiteness). The refinement loop selectively resamples only the P or L fragment while keeping D fixed, and the final output is the program maximizing ELPD-LOO among those passing a reliability threshold of ζ=5 out of 7 checks.

## Method

REFINESTAT combines two mechanisms: (1) semantically constrained decoding, which extends grammar-guided generation with six validation predicates (parse-ability, distribution validity, parameter validity, dependency validity, support validity, type validity) enforced via local rejection sampling—when a predicate fails, only the offending tokens are backtracked and resampled; and (2) diagnostic-aware refinement, which runs NUTS MCMC on the generated program, computes seven Bayesian diagnostics, and if the reliability score falls below threshold, selectively resamples either the likelihood (addressing convergence or sampler-health issues) or the prior (correcting specification errors) under the appropriate context. The algorithm iterates until β valid programs are collected or a budget R_max is exhausted, then returns the program with the highest ELPD-LOO. This fragment-level resampling strategy, combined with PPL-specific semantic constraints that go beyond prefix-checkable syntax, enables a single unmodified 7–8B open-weight SLM to match or surpass GPT-4-based systems on statistical reliability and predictive accuracy.

## Results

REFINESTAT achieves a run rate of 0.45–0.50 across temperatures, approximately 40 percentage points higher than the unconstrained Standard baseline (0.10–0.11) and 30 points higher than Syncode (0.21). On ELPD-LOO (higher is better), REFINESTAT with DQ-7B matches expert-written Stan programs on Eight Schools (−30.68 vs. −30.70) and GP (−23.39 vs. −26.53), and substantially outperforms BoxLM (GPT-4) on Peregrine (−114.29 vs. −173.11) and OpenAI o3 on GP (−23.39 vs. −34.95). The ablation shows parameter validity is the most critical semantic check, with its removal causing a 14.5-percentage-point drop in compilation success.

## Baselines & Comparisons

Against Syncode (syntactic-only constrained decoding), REFINESTAT wins decisively on run rate: 0.45–0.50 vs. 0.21, a ~30-point improvement, because semantic validation catches parameter-name errors (e.g., `sd` vs. `sigma`) and invalid distribution calls that grammar constraints alone cannot. Against BoxLM (Li et al., 2024), which uses two GPT-4 instances for propose-and-refine, REFINESTAT with a single 7B open-weight model (DQ-7B) substantially outperforms on Peregrine (−114.29 vs. −173.11 ELPD-LOO) and matches on Eight Schools (−30.68 vs. −30.42), but loses on Dugongs (8.35 vs. 23.40) and Surgical (−46.51 vs. −38.03). Against OpenAI o3, REFINESTAT wins on Peregrine (−114.29 vs. −133.29) and GP (−23.39 vs. −34.95), roughly ties on Eight Schools (−30.68 vs. −30.74), but trails on Dugongs (8.35 vs. 22.83) and Surgical (−46.51 vs. −38.73). Against expert-written PosteriorDB Stan programs, REFINESTAT matches on Eight Schools and GP while underperforming on Dugongs and Surgical, indicating room for improvement on more complex hierarchical models.

## Relation to Prior Work

REFINESTAT extends the grammar-guided constrained decoding line (Syncode, IterGen) from purely syntactic/type-level constraints to semantic constraints specific to probabilistic programming languages—distribution validity, parameter naming, support ranges, and dependency ordering. It departs from BoxLM (Li et al., 2024), which uses two GPT-4 instances in a generator-critic loop, by showing that a single open-weight SLM (<8B) suffices when paired with validation-guided resampling and Bayesian diagnostic feedback. The key conceptual departure from prior constrained-decoding work is that REFINESTAT targets properties (MCMC convergence, PSIS-LOO reliability) that are not prefix-checkable and require full posterior inference, rather than the static, incrementally-verifiable properties (parseability, type correctness) that dominate the existing literature.

## Why It Matters / Open Questions

The result that a 7–8B open-weight model, augmented with semantic constraints and a diagnostic-aware refinement loop, can match or exceed GPT-4-based and OpenAI o3-based systems on probabilistic program synthesis is practically significant for researchers who need reproducible, locally-runnable model discovery without API costs. However, the framework omits prior-predictive and posterior-predictive checks (which require domain judgment), the refinement loop offers no convergence guarantee to a globally optimal model, and the token overhead (~2× baseline) may matter at scale. Open questions include generalization to more complex hierarchical models, other PPL backends beyond PyMC/NumPyro, and whether the diagnostic thresholds transfer across domains without manual tuning.
