## Problem

Existing LLM routers—whether single-round (one-shot model assignment) or multi-round (sequential model selection with accumulated context)—do not model the multi-agent coordination required in agentic LLM settings, where the router must decide not only which backbone to invoke but also which agent role (Planner, Executor, Summarizer) to activate at each step. This leaves open how to extend routing into realistic agentic workflows that involve task decomposition, heterogeneous agent cooperation, and exploitation of rich historical interaction memories.

## Input / Output

Given a text query (embedded via Longformer), a pool of K LLM backbones spanning small/medium/large scales, and a historical memory graph of past multi-agent interactions, GraphPlanner outputs a complete routing workflow: a sequence of (agent role, LLM backbone) pairs that decompose the query, generate intermediate responses, and produce a final summarized answer. The system supports two inference modes—inductive (no stored history at test time, lower cost) and transductive (reuses training-phase interaction traces for richer context, higher accuracy).

## Method

GraphPlanner casts agentic workflow generation as a Markov Decision Process with 3K actions (3 roles × K backbones), where a dynamic mask enforces semantic validity (e.g., no summarizer at step 0, planner count capped by P_max). The policy is parameterized by GARNet, a heterogeneous graph neural network that maintains two sub-graphs—a workflow memory graph (current query, responses, role hub nodes) and a historical memory graph (past queries/responses)—bridged by shared role hub nodes that encode (LLM, role) utility-cost profiles. A nested dual-graph encoding first encodes the historical graph, then injects the resulting role-hub embeddings into the workflow graph encoder, enabling the policy to condition on both local workflow state and accumulated interaction patterns. The entire pipeline is trained end-to-end with PPO, optimizing a reward that balances task-specific utility (accuracy, Pass@1, CEM) against per-step computational cost via a tunable trade-off coefficient α.

## Results

In Phase 2 (full agentic workflow generation), GraphPlanner achieves 63.6% average accuracy across five domains (Math 67.0%, Code 76.0%, CS 78.0%, WK 38.0%, Popular 52.0%), outperforming the best single-round router (RouterDC, 54.3%) by +9.3% and the best multi-round router (Router-R1, 51.8%) by +11.8%. In Phase 1 (routing within fixed workflows), GraphPlanner gains +3.8% over the strongest baseline. On unseen tasks (LogicGrid, MGSM, CommonGen), GraphPlanner achieves 78% average zero-shot accuracy versus 58% (RouterDC), 46% (GraphRouter), and 38% (Router-R1). Training GPU cost drops from 186.26 GiB (Router-R1) to 1.04 GiB for GraphPlanner.

## Baselines & Comparisons

GraphPlanner outperforms all six baseline routers in Phase 2 average accuracy. Against the strongest single-round router, RouterDC (Chen et al., 2024a; 54.3% avg), GraphPlanner gains +9.3% while using 8.1 LLM calls versus RouterDC's single call. Against the best multi-round router, Router-R1 (Zhang et al., 2025; 51.8% avg), GraphPlanner improves by +11.8% at a higher per-query cost (605.0 vs. 76.3) but with far lower training GPU compute (1.04 GiB vs. 186.26 GiB). R2-Reasoner (Shao et al., 2025) achieves 50.1% avg with 5.4 LLM calls, trailing GraphPlanner by 13.5 points. GraphRouter (Feng et al., 2024) reaches 51.9% avg but is weakest on Math (53.2%) and Popular (21.0%), where GraphPlanner leads by 13.8 and 31.0 points respectively. On zero-shot unseen tasks, GraphPlanner (78% avg) surpasses RouterDC (58%), GraphRouter (46%), and Router-R1 (38%) by 20, 32, and 40 points, confirming that the graph-memory-augmented agentic formulation generalizes substantially better than both single-round and multi-round alternatives.

## Relation to Prior Work

This paper extends the LLM routing literature from single-round (Router-KNN, RouterDC, GraphRouter) and multi-round (Router-R1, R2-Reasoner) settings into a new agentic multi-agent formulation where the router must jointly select both an agent role (Planner, Executor, Summarizer) and an LLM backbone at each step. It repurposes GraphRouter's graph-based routing idea by upgrading it to a heterogeneous dual-graph encoder (GARNet) that fuses current workflow memory with accumulated historical interaction memory, and it builds on Router-R1's PPO-based RL training but applies it to the richer action space of agent-role × backbone pairs. The multi-agent LLM systems literature (AutoGen, AFlow, AgentSquare) motivates the workflow structure, but those systems assume fixed or manually designed protocols; GraphPlanner instead learns the workflow generation end-to-end.

## Why It Matters / Open Questions

The paper demonstrates that a lightweight heterogeneous-graph policy (1.04 GiB GPU) can outperform a much larger RL-based router (Router-R1, 186.26 GiB) by 9.3% in accuracy while reducing compute by over 99%, suggesting that structured graph memory is a more sample-efficient inductive bias than scaling the router itself. The strong zero-shot generalization to unseen tasks (78% avg vs. 38–58% for baselines) and unseen LLMs without fine-tuning is practically important for deployment settings where new models or domains appear frequently. Open questions include whether the three-role abstraction (Planner/Executor/Summarizer) is sufficient for genuinely complex agentic pipelines, how the approach scales to dozens of concurrent agents or LLMs, and whether the RL training stability holds at larger workflow depths.
