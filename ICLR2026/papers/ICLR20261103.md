## Problem

Model pruning is a widely used deployment-time compression step in LLM inference engines like vLLM, yet its security implications have remained unexplored. This paper asks whether an adversary can exploit pruning as a covert trigger: can a model be crafted to appear fully benign and safe, yet exhibit strong malicious behaviors (jailbreak, over-refusal, content injection) only after a user prunes it for local deployment?

## Input / Output

The attack consumes a pretrained instruction-tuned LLM checkpoint, a calibration dataset (e.g., C4) for pre-estimating per-parameter pruning scores, a scenario-specific harmful dataset (e.g., LLM-LAT for jailbreak), a corresponding harmless dataset for repair, and a general instruction-tuning dataset (GPT-4-LLM) for KL-divergence regularization. The output is a single modified checkpoint that is behaviorally indistinguishable from the base model before pruning but activates the targeted malicious behavior once any of vLLM's three unstructured pruning algorithms (Magnitude, Wanda, SparseGPT) is applied at user-chosen sparsity levels (20%, 50%, or 2:4).

## Method

The attack proceeds in three steps. First, the adversary computes Wanda importance scores on the base model using a calibration set and partitions parameters into an injection set (top α_inj%, unlikely to be pruned) and a repair set (bottom α_rep%, likely to be pruned); Wanda scores serve as a universal proxy because pruning scores correlate heavily across Magnitude, Wanda, and SparseGPT. Second, the adversary fine-tunes only the injection-set parameters on a harmful dataset with a KL-divergence regularizer against the base model on a general dataset, implanting the malicious behavior into weights that will survive pruning. Third, the adversary fine-tunes only the repair-set parameters on a harmless dataset (again with KL regularization), which cancels the injected behavior in the unpruned model. The repair set is deliberately kept very small (1–5%) so that the compensation is brittle: when the user prunes, those low-scoring parameters are removed (>99% overlap in most settings), the repair is lost, and the dormant malicious behavior in the surviving high-scoring parameters is activated.

## Results

The pruning-activated attack achieves attack success rates (ASR) exceeding 90% across all three vLLM pruning algorithms (Magnitude, Wanda, SparseGPT) on all three evaluated models. Peak ASR values reach 95.7% for jailbreak (Qwen2.5-7B, Magnitude 20%), 98.7% for over-refusal (OLMo-2-7B, SparseGPT 50%), and 99.5% for content injection (Qwen2.5-7B, Wanda 50%). Critically, the unpruned attacked models maintain ASR comparable to their base counterparts (e.g., 9.3% vs. 7.7% for Qwen jailbreak) and show no significant utility degradation on standard benchmarks (average change within ±3 points). The attack generalizes to larger models (Qwen2.5-14B, 32B) and remains effective even after additional quantization (FP8, GPTQ 4-bit).

## Baselines & Comparisons

This paper does not compare against competing attack methods; instead, the key comparison is between the attacked model and its base (unattacked) counterpart, both before and after pruning. Before pruning, the attacked models are indistinguishable from base models: ASR remains low (e.g., 9.3% vs. 7.7% for Qwen jailbreak, 1.1% vs. 0.4% for Qwen over-refusal) and benchmark scores show no significant degradation (average change within ±3 points across MMLU, ARC, HellaSwag, HumanEval, GSM8K). After pruning, the gap becomes dramatic: ASR jumps from near-base levels to 60–99% depending on the scenario and pruning configuration, while base models under the same pruning show only modest ASR increases (e.g., base Qwen jailbreak goes from 7.7% to 8.0% under Magnitude 20%, versus 95.7% for the attacked model). The attack is robust across all three vLLM pruning algorithms and multiple sparsity levels (20%, 50%, 2:4), with Wanda and Magnitude 20% consistently yielding the highest ASR. Notably, the attack persists even when the user applies additional transformations such as FP8 or GPTQ 4-bit quantization on top of pruning, with ASR remaining within 85–128% of the full-precision pruned model.

## Relation to Prior Work

This paper extends the emerging line of post-training transformation attacks—where quantization (Egashira et al., 2024; 2025) and fine-tuning (Gloaguen et al., 2025) have been shown to serve as covert triggers for malicious behavior—to the widely-used case of unstructured pruning. Conceptually, it departs from prior pruning-and-security work (Liu et al., 2018; Chen et al., 2022; Huang et al., 2024), which treated pruning as a *defense* against already-implanted backdoors, by inverting the perspective: the adversary actively exploits the user's pruning step as the *activation mechanism*. The technical core relies on the strong correlation between Wanda, SparseGPT, and Magnitude scoring metrics, allowing a single pre-estimation step to target all three algorithms simultaneously.

## Why It Matters / Open Questions

The finding that a routine, user-initiated compression step in a major inference engine (vLLM, 50k+ GitHub stars) can silently activate a hidden attack exposes a critical deployment-time security gap with immediate practical consequences for anyone pruning downloaded models. No single defense fully mitigates the threat: security-aware calibration helps SparseGPT but not Wanda, and practical patching (reinserting bottom-scoring parameters) is ineffective without oracle access to pre-attack scores. Open questions include developing systematic detection methods for pruning-activated backdoors, designing provably secure pruning procedures, and understanding whether the broader family of post-training transformations (quantization, fine-tuning, pruning) can be composed into even more stealthy multi-trigger attacks.
