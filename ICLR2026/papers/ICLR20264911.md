## Problem

Existing visual programming systems for 3D spatial reasoning either rely on fixed, predefined toolsets that cannot adapt to new tasks, or create new tools through induction—speculating about useful functions from problem descriptions before solving anything. This open-loop approach leads to severe under-utilization of created tools, with 94.2% of programs still relying on basic predefined tools despite access to newly created functions. The paper asks whether tools can be more effectively discovered and reused when grounded in actual problem-solving experience rather than speculation.

## Input / Output

The system takes a single RGB image of a real-world scene paired with a non-templated spatial reasoning question requiring multi-step geometric computation (e.g., computing ratios of 3D object heights, counting objects by dimension, or estimating camera-relative distances). It produces a Python program that composes vision tool calls—GroundingDINO for object localization, UniDepth for metric depth estimation, and geometric functions—to yield a precise numerical or categorical answer. The full execution trace capturing all intermediate 3D computations is retained, and a VLM judge evaluates each candidate solution against visual evidence before admission to the experience library.

## Method

TVP implements a closed-loop dual-library architecture: an Example Library accumulates high-quality program solutions as experiential memory, while a Tool Library maintains parameterized functions abstracted from those solutions. In Phase I, the system retrieves similar past solutions as few-shot demonstrations, samples multiple candidate programs using available tools, executes them in Python, and admits the highest-quality solution to the Example Library. In Phase II, solutions are clustered by text-embedding similarity, and recurring computational patterns are abstracted into new parameterized tools that must pass rigorous two-stage validation (100% execution success on all cluster examples plus 85% overall correctness with VLM-verified divergence tolerance). A periodic maintenance step merges functionally similar tools into more general abstractions, keeping the library concise. This transductive paradigm—creating tools from proven solutions rather than speculating from problem text—produces tools used 5× more frequently as core program dependencies, reduces median cyclomatic complexity from 3.0 to 1.0, and enables progressive self-improvement across iterations without any dataset-specific priors.

## Results

On Omni3D-Bench (501 3D spatial reasoning queries), TVP achieves 33.3% overall accuracy, outperforming the previous best visual programming system VADAR (29.9%) by +11% and GPT-4o (27.2%) by +22%. The advantage is most pronounced on floating-point geometric calculations, where TVP reaches 19.3% Float(±10%) accuracy versus 8.2% for GPT-4o. In zero-shot transfer to the SpatialScore-Hard collection (3DSR-Bench, SpatialSense, VG-Bench), TVP's libraries built solely on Omni3D-Bench achieve 52.3% overall accuracy, surpassing GPT-4o (42.6%) and VADAR (32.8%) without any test-set-specific modification.

## Baselines & Comparisons

TVP outperforms all eight baselines on Omni3D-Bench overall accuracy. Against the strongest visual programming baseline VADAR (Marsili et al., 2025), TVP gains +3.4% overall (33.3% vs. 29.9%), with the largest margin on Float(±10%) accuracy (+3.4 pp, 19.3% vs. 15.9%), reflecting that transductively created tools are used 5× more frequently as core program dependencies than VADAR's inductively speculated tools. Against generic VLMs, TVP surpasses GPT-4o by +6.1 pp (33.3% vs. 27.2%), LLaVA-OneVision by +10.3 pp, Qwen2-VL by +11.5 pp, and Molmo by +11.7 pp. Spatial-finetuned VLMs (SpaceMantis at 18.2%, SpatialBot-3B at 18.8%) show no meaningful improvement over generic VLMs, confirming the necessity of compositional programmatic approaches for precise 3D geometric reasoning. Earlier visual programming systems VisProg and ViperGPT, which rely on fixed predefined toolsets, report only partial results on Omni3D-Bench and are substantially outperformed. In zero-shot transfer (Table 2), TVP's Omni3D-Bench-built libraries achieve 52.3% on SpatialScore-Hard, beating VADAR (which creates new tools specifically for those test sets) by +19.5 pp and GPT-4o by +9.7 pp.

## Relation to Prior Work

This paper departs from the visual programming lineage (VisProg, ViperGPT) that relies on fixed predefined toolsets, and from VADAR's inductive approach that speculates about useful tools from problem descriptions before solving anything. TVP inverts this order by introducing a transductive mechanism: tools are abstracted only from clusters of successfully solved programs stored in an Example Library, creating a closed-loop program→tool→program cycle. The dual-library architecture (experiential solutions + abstracted functions) and the rigorous two-stage validation before tool admission are the key architectural departures from prior work, which either skipped the experience-to-abstraction cycle entirely or ran it in the wrong direction.

## Why It Matters / Open Questions

The transductive paradigm offers a general recipe for self-evolving agents that build increasingly sophisticated capabilities from accumulated experience, potentially applicable beyond spatial reasoning to any compositional problem-solving domain. However, the current validation is confined to 3D spatial reasoning, the pipeline depends heavily on GPT-4o and o4-mini for most LLM components, and the ~$80/iteration cost for library construction limits immediate scalability. Open questions include whether the tool library can be shared or composed across heterogeneous task domains, how the approach behaves with much larger datasets where tool proliferation becomes a concern, and whether the closed-loop improvement saturates or continues indefinitely.
