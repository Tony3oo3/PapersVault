## Problem

Transformers lack explicit mechanisms for symbolic planning constructs—loops, variable assignments, and conditional branching—causing sharp accuracy degradation under length extrapolation on algorithmic tasks. Existing neuro-symbolic approaches either delegate reasoning to external planners or add heavy architectural complexity without verifiable, step-wise control-flow semantics. This paper addresses the gap by embedding lightweight, interpretable discrete controllers directly within Transformer blocks.

## Input / Output

The model consumes standard token sequences (subword-free integer lists, graph adjacency lists with delimiters, paragraph-question pairs for DROP, or I/O string pairs for RobustFill) and produces task-specific outputs (sorted sequences, scalar sums, BFS traversal orders, answer spans, or DSL programs). At every p-th instrumented layer, the controller additionally reads a permutation-invariant pooled summary of token states to select a discrete operation and update a compact internal program state (N_r register vectors, binary flags, optional key-value memory), with state deltas written back into the residual stream. Execution traces (opcode, read/write addresses, branch gate) are logged only at instrumented layers for post-hoc interpretability.

## Method

The core mechanism inserts a Gumbel-Softmax-parameterized discrete controller into every p-th Transformer block that selects one of five primitives (ASSIGN, ADD, COMPARE, BRANCH, NOOP) acting on a compact program state of registers, flags, and optional memory. The controller reads a pooled token summary, computes operation logits, draws a differentiable one-hot via Gumbel-Softmax with annealed temperature, predicts soft read/write address distributions over registers, and applies the selected primitive's semantic map to update the state; state-to-token and token-to-state linear projections couple the program state bidirectionally with the residual stream. Training combines the primary task loss with semantic-consistency penalties (enforcing that relaxed state transitions match the declared primitive semantics), entropy annealing to drive discrete decisions, and write-sparsity regularization. The paper proves that O(K+B) instrumented steps suffice to exactly simulate any bounded imperative program as τ→0 and κ→∞, and bounds finite-temperature deviation by O(τ + κ⁻¹). Empirically, the controller adds only ~5–7% FLOPs at p=2 and yields 20–40 point accuracy gains at 2–4× length extrapolation on algorithmic benchmarks, with interpretable traces and linearly decodable register roles.

## Results

On algorithmic reasoning tasks with length extrapolation (n=320, 4× training length), Ctrl-Transformer achieves 91.6% on Sorting, 93.8% on Sum-of-List, and 83.5% on BFS, outperforming the strongest non-privileged baseline (Soft Modules) by +25.3, +20.9, and +9.3 points respectively. On DROP (numeric-only subset), it reaches F1 85.1 / EM 81.5, improving +6.8 F1 over a parameter-matched Transformer. On RobustFill program synthesis, it achieves 73.9% exact match (+6.1 over Transformer), and on the Mathematics dataset 82.0% accuracy (+5.9 over Transformer). The compute overhead is only ~5–7% FLOPs with controllers inserted every 2nd block.

## Baselines & Comparisons

Ctrl-Transformer outperforms all six non-privileged baselines on every task and every extrapolation length. Against the vanilla Transformer (Vaswani et al., B1), the gap at n=320 is largest: +52.9 points on Sorting (91.6 vs. 38.7), +52.6 on Sum-of-List (93.8 vs. 41.2), and +25.6 on BFS (83.5 vs. 57.9). The Universal Transformer (Dehghani et al., B2) and Compressive Transformer (Rae et al., B3) improve over B1 but still degrade sharply at long lengths (e.g., Sorting n=320: 51.5% and 59.1% respectively vs. 91.6% for Ctrl-Transformer). The CLRS-algorithmic Transformer (Veličković et al., B4) is the strongest non-soft baseline on Sum-of-List (68.3% at n=320) but remains 25.5 points below Ctrl-Transformer. NPI/DNC (Kaiser & Sutskever; Graves et al., B5) performs comparably to B2, confirming that external memory alone does not resolve the length generalization gap. The closest comparison is B6 Soft Modules (same architecture without discrete selection), which trails by +25.3 (Sorting), +20.9 (Sum-of-List), and +9.3 (BFS) at n=320, isolating the contribution of the Gumbel-Softmax discrete controller. On DROP, Ctrl-Transformer also edges out the FiD-T5 reference system (B8) by +0.6 F1 on the full set and substantially outperforms it on the numeric-only subset where discrete operations are emphasized.

## Relation to Prior Work

This paper sits at the intersection of neuro-symbolic reasoning (NTMs, DNC, Neural GPUs, NPI) and adaptive-depth Transformers (Universal Transformer, Compressive Transformer), but departs from both by embedding a compact, in-place discrete controller with explicit program semantics (ASSIGN, ADD, COMPARE, BRANCH) directly inside Transformer blocks rather than delegating control to external planners or generic memory modules. The Gumbel-Softmax mechanism for differentiable discrete selection is repurposed here not for token-level routing (as in MoE) but for opcode-level program execution over a persistent register/flag state. The theoretical contribution—an expressivity proof showing O(K+B) instrumented steps suffice to simulate any bounded imperative program—has no direct analogue in prior adaptive-computation or neuro-symbolic work, which typically lack formal guarantees about what the controller can express.

## Why It Matters / Open Questions

The paper demonstrates that a minimal (~5-7% FLOPs) in-place controller can compress length-extrapolation decay by 4-10× relative to strong baselines, and that the advantage *amplifies* with sequence length rather than being a uniform shift—suggesting the controller provides a structural inductive bias that vanilla attention cannot replicate at scale. Open questions include whether the bounded-loop expressivity guarantee extends to unbounded or nested loops, whether richer typed primitives (stacks, maps, big-integer arithmetic) are needed for real-world program synthesis, and whether compile-time distillation of learned control flow can eliminate inference overhead. The training sensitivity to temperature/entropy schedules remains a practical concern that limits plug-and-play adoption.
