## Problem

Training LLMs to generate high-quality unit tests has been limited to supervised fine-tuning on ground-truth unit test annotations, which are expensive to curate and difficult to scale across diverse programming domains. The key challenge is designing a reward signal that reliably assesses unit test quality without relying on ground-truth test labels, a problem that remains underexplored in the RL-for-LLMs literature.
![Teaser figure](../imgs/ICLR20265025/cropped_page0_idx0.webp)

## Input / Output

The unit test generator takes a programming instruction (specifying input arguments and required functionality) and produces a set of N independent test cases in stdio format, each pairing a concrete input with an expected output. The test cases are expected to cover diverse edge cases ranging from basic functionality to subtle corner cases that can discriminate near-correct implementations from ground-truth solutions. The code generator, trained in parallel, takes the same instruction and produces a code solution that is evaluated against the generated unit tests.

## Method

UTRL alternates between two RL training loops using GRPO: (1) the unit test generator is optimized with a weighted sum of a discrimination reward (fraction of code-generator samples that fail at least one valid test case, relative to ground-truth code) and a validity reward (proportion of test cases passing under ground-truth code, with a clipped denominator to prevent degenerate small test suites); (2) the code generator is optimized to maximize its pass rate over the filtered valid test cases in the generated unit test. The critical design choice is that the discrimination reward is defined entirely by ground-truth code solutions and code-generator outputs, eliminating any need for ground-truth unit test annotations. The adversarial dynamic creates a curriculum: as the code generator produces solutions harder to distinguish from ground-truth, the unit test generator is forced to identify subtler faults, progressively improving test discriminativeness across iterations.

## Results

On the TACO evaluation set (945 competitive programming tasks), Qwen3-4B trained via UTRL achieves 14.9% best-of-32 code accuracy with a Qwen3-8B code generator (+6.9%p over base), surpassing GPT-4.1 (13.3%) and GPT-4o (10.9%). Qwen3-14B trained via UTRL reaches 17.7% accuracy with a Qwen3-14B code generator, approaching the ground-truth unit test upper bound of 24.2%. In unit test fidelity (Spearman correlation with GT-induced code scores), Qwen3-14B+UTRL achieves 0.827, outperforming GPT-4.1. For code generation, the UTRL-trained code generator reaches 15.3% pass@1, comparable to the 15.9% upper bound from RL with GT unit tests, while SFT degrades to 3.6%.

## Baselines & Comparisons

UTRL-trained Qwen3-4B outperforms all untrained open-source LLMs (Qwen3-4B/8B/14B/32B, DeepSeek-Coder-V2-Lite) by 3–5%p in best-of-32 code accuracy, and surpasses frontier proprietary models GPT-4o (10.9%) and GPT-4.1 (13.3%) by 4.0 and 1.6%p respectively with a Qwen3-8B code generator. Against SFT with ground-truth unit tests (D_UT), UTRL gains +3.2%p accuracy (14.9% vs. 11.7%), and against SFT with reasoning-annotated synthetic tests (D_reason+UT), UTRL achieves both higher accuracy and higher unit test fidelity (0.741 vs. 0.604 Spearman). Compared to the RL baseline CURE (which requires instruction-unit-test pairs), UTRL† trained on the same 4.5K CodeContest tasks achieves 14.1% vs. 9.7% accuracy (+4.4%p) and higher fidelity (0.593 vs. lower), while requiring only instruction-code pairs. The only comparison where UTRL does not win is against the ground-truth unit test upper bound (20.3% vs. 14.9%), which is expected since GT tests contain an average of 202.3 rigorously verified test cases per task.

## Relation to Prior Work

UTRL builds most directly on CURE (Wang et al., 2025a), which co-evolves a code generator and test case generator via RL, but departs in two key ways: it requires only instruction-code pairs (not instruction-unit-test pairs) and trains the model to produce a full set of test cases rather than a single one. The adversarial training loop draws on the broader self-play and GAN literature (AZR, SPIN, Sol-Ver, STP), while the RL optimization uses GRPO, a recent variant of PPO that avoids a learned value function. The SFT baselines connect to CodeRM and UTGEN, which rely on teacher-model or perturbation-based annotation of unit tests.

## Why It Matters / Open Questions

By eliminating the need for ground-truth unit test annotations, UTRL makes RL-based training of unit test generators far more scalable, since instruction-code pairs are readily available at large scale. The finding that a 4B model trained with UTRL outperforms GPT-4.1 on unit test quality suggests that targeted adversarial RL can close the gap with much larger models on narrow tasks. However, a notable performance gap remains relative to ground-truth unit tests, the framework is validated only on competitive programming, and iterative training showed diminishing returns after two rounds, leaving open whether the adversarial curriculum can sustain improvement with larger models or broader domains.
