## Problem

Existing language agent benchmarks either rely on synthetic environments with simplified states, cover only a narrow set of applications, or use overly detailed step-by-step prompts that remove the need for autonomous planning. None simultaneously provide diverse real-world applications, realistic pre-populated environment states, and fuzzy instructions that mimic authentic user queries, leaving a significant gap in evaluating agents on the long-horizon, cross-application workflows encountered in practice.
![Teaser figure](../imgs/ICLR20261811/cropped_page1_idx1.webp)

## Input / Output

Each task provides the agent with a concise, intentionally ambiguous natural-language instruction (e.g., 'update the candidate information on HR Record subpage according to all the resumes'), a pre-initialized environment state (populated inboxes, course databases with dozens of students, financial spreadsheets, Kubernetes clusters), and a subset of MCP tools (fewer than 10 servers per task, though all tools within each server are loaded). The agent operates over an average of ~20–27 tool-calling turns (up to 100 max), and the output is a binary pass/fail verdict produced by a deterministic evaluation script that compares the final environment state against either a static ground-truth snapshot or dynamically retrieved real-time data (e.g., live NVIDIA shareholder info).

## Method

TOOLATHLON is a benchmark of 108 manually sourced or crafted tasks spanning 32 MCP servers and 604 tools across domains including education, finance, technology, e-commerce, and daily affairs. The environment combines remote services (Google Sheets, Notion, Snowflake, BigQuery) with locally containerized open-source applications (Poste.io for email, Canvas for LMS, Kubernetes, WooCommerce) to enable realistic, resettable initial states that would be impractical to replicate on remote platforms. Task instructions are deliberately fuzzy, requiring agents to infer format, locate relevant data, and plan autonomously from environment observations rather than following explicit step-by-step directions. Evaluation is execution-based: each task has a dedicated deterministic script that verifies the final environment state, and all tasks run in isolated containers enabling parallel evaluation (108 tasks in ~70 minutes with 10 processes). The agent framework, built on OpenAI Agents SDK v0.0.15, adds robustness features including tool-error recovery (errors fed back as observations rather than terminating the loop), overlong-output truncation with a paging toolkit, and automatic context management to prevent overflow.

## Results

On TOOLATHLON (108 tasks across 32 applications and 604 tools), the best-performing model Claude-4.5-Sonnet achieves only 38.6% Pass@1 with 20.2 average tool-calling turns, while the best open-weight model DeepSeek-V3.2-Exp reaches 20.1% Pass@1. GPT-5 (30.6%) and Claude-4-Sonnet (29.9%) form a second tier, while all remaining models score below 28%. The large gap between Pass@3 (e.g., 51.9% for Claude-4.5-Sonnet) and Pass^3 (20.4%) reveals that models lack consistency in reliably completing long-horizon tasks.

## Baselines & Comparisons

Claude-4.5-Sonnet leads all models at 38.6% Pass@1, outperforming GPT-5 (30.6%) by 8.0 points and Claude-4-Sonnet (29.9%) by 8.7 points. Among open-source models, DeepSeek-V3.2-Exp (20.1%) and GLM-4.6 (18.8%) form a clear gap over Qwen-3-Coder (14.5%) and Kimi-K2-0905 (13.0%), but all remain well below the proprietary frontier. Notably, increasing reasoning effort from GPT-5 to GPT-5-high yields no improvement (30.6% vs. 29.0%), suggesting that exploring new observations matters more than extended internal reasoning in agentic tasks. Gemini-2.5-Pro (10.5%) and Gemini-2.5-Flash (3.7%) perform substantially worse than all other models, with the paper attributing this to insufficient proactive exploration and premature task termination. The Pass@3 to Pass^3 gap (e.g., 51.9% vs. 20.4% for Claude-4.5-Sonnet) indicates that while models can occasionally solve tasks, they lack the consistency needed for reliable real-world deployment.

## Relation to Prior Work

TOOLATHLON carves new ground at the intersection of several existing benchmark lineages: pure-simulation tool-calling benchmarks (τ-Bench, BFCL), real-API benchmarks with synthetic states (AppWorld, MCP-World, MCPUniverse), and recent MCP-based benchmarks (MCPMark, LiveMCPBench, MCPAtlas). Its key conceptual departure is the simultaneous combination of (i) genuinely realistic initial environment states drawn from real software (e.g., Canvas courses with dozens of students, real financial spreadsheets), (ii) intentionally fuzzy and underspecified task instructions that mirror authentic user queries, and (iii) mandatory cross-application orchestration across up to 32 MCP servers. Prior benchmarks typically satisfy at most one or two of these axes, often relying on detailed step-by-step prompts or single-app tasks with empty or trivially initialized states.

## Why It Matters / Open Questions

The benchmark exposes concrete, actionable failure modes—premature task termination, inability to handle overlong tool outputs, and inconsistent completion across repeated runs (large Pass@3 vs. Pass^3 gap)—that are directly relevant to deploying agents in production. The finding that increased reasoning effort (GPT-5-high vs. GPT-5) yields no benefit challenges the prevailing assumption that longer internal chains-of-thought improve agentic performance, suggesting that proactive environment exploration matters more. Open questions include whether the 38.6% ceiling for the best model reflects a fundamental limitation in long-horizon planning or is addressable through better context management and error recovery, and whether the containerized local-environment approach (Poste.io, WooCommerce, Canvas) generalizes to the full breadth of remote SaaS applications that real agents must handle.
