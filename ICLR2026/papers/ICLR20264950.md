## Problem

Mathematical modeling is a time-intensive, expertise-driven process that involves fundamental uncertainty about which framework, formulation, and algorithm to use, must balance multiple often-conflicting objectives, and is shaped by subjective qualities like interpretability. No prior work has formulated this as a general, cross-framework automated search problem that simultaneously navigates open-ended model spaces, handles multi-objective trade-offs, and incorporates human preferences.
![Teaser figure](../imgs/ICLR20264950/cropped_page2_idx0.webp)

## Input / Output

MATHMO takes a natural-language modeling problem description, a vector of k objective functions, and an optional dataset as input. It outputs a Pareto set of models, where each model is a pair of executable Python code (a concrete mathematical formulation and a solver/algorithm procedure) accompanied by its k-dimensional objective evaluation. The search space is deliberately open-ended with no predefined domain-specific language; models are represented as free-form code, and subjective criteria (e.g., interpretability) are scored via pairwise LLM comparisons against a fixed reference set rather than through framework-specific proxies.

## Method

MATHMO decomposes the vast modeling space into a bi-level adaptive search: an upper level allocates exploration budget across candidate mathematical frameworks using a Pareto-UCB bandit policy, while a lower level performs local search within the selected framework by sampling candidate model-algorithm pairs, scoring them with an LLM-based surrogate, and selecting the pair that maximizes estimated hypervolume improvement. LLMs (GPT-4o) serve three distinct roles: generative samplers that propose frameworks and Python-coded model/algorithm instantiations conditioned on problem context and history, surrogate evaluators that predict objective values without full execution, and MOSE, a surrogate model of subjective evaluations that scores interpretability via averaged pairwise preferences against a fixed reference set. The key design insight is that inter-framework trade-offs (e.g., exact optimization vs. metaheuristics) dominate intra-framework variations, so explicitly separating framework selection from model refinement yields more efficient and diverse Pareto frontiers than flat or naive search strategies.

## Results

On four real-world modeling tasks, MATHMO achieves hypervolume scores of 0.988 (TSP), 0.966 (JSSP), 0.958 (Ecology), and 0.979 (Epidemiology), consistently outperforming both LLM-based heuristic design baselines. Against the strongest baseline MEoH, MATHMO gains +0.040 on TSP, +0.107 on JSSP, +0.122 on Ecology, and +0.074 on Epidemiology. Ablation studies confirm the bi-level structure and surrogate-guided search contribute 5.8% and 10.1% average hypervolume improvements over flat and naive variants, respectively.

## Baselines & Comparisons

MATHMO outperforms both LLM-based heuristic design baselines across all four tasks. Against MEoH (multi-objective evolutionary heuristic design), MATHMO achieves substantially higher hypervolume, with the largest gap on JSSP (+0.107) and Ecology (+0.122), attributed to MATHMO's cross-framework exploration (e.g., constraint programming on JSSP) and surrogate-guided candidate selection. Against FunSearch (genetic programming for single-objective search, scalarized here), MATHMO leads by +0.011 on TSP but by much wider margins on JSSP (+0.153), Ecology (+0.334), and Epidemiology (+0.317), where FunSearch's single-framework restriction is most limiting. On the time-series tasks, MATHMO also strictly dominates SINDy (symbolic regression), whose models occupy a narrow interpretability band while MATHMO spans richer trade-offs via multiple frameworks. Against mature domain-specific solvers (Concorde for TSP, OR-Tools CP-SAT for JSSP), MATHMO produces competitive solution quality (e.g., matching Concorde's optimal cost on 2/5 TSP instances) while additionally discovering fast-runtime heuristic alternatives that populate the full Pareto frontier—something single-solver baselines cannot provide.

## Relation to Prior Work

MATHMO sits at the intersection of three research threads: (1) AutoML and LLM-driven search (FunSearch, MEoH, Eureka), which typically operate within a single predefined paradigm or search space; (2) LLM-based mathematical formulation (Optimus, statistical model discovery), which assumes a known framework and searches only within it; and (3) multi-objective bandit methods (Pareto-UCB) and LLM-based surrogate modeling (Liu et al., 2024), which provide the exploration and evaluation machinery. The key departure is that MATHMO removes the a priori framework assumption entirely, treating the full pipeline—framework selection, model specification, and algorithm design—as a single sequential decision problem under uncertainty, and introduces MOSE (grounded in Bradley-Terry/RLHF pairwise preferences) as a cross-framework mechanism for subjective criteria that no prior formulation work addresses.

## Why It Matters / Open Questions

This is the first formalization of automated mathematical modeling as a multi-objective sequential decision problem spanning heterogeneous frameworks, and the empirical demonstration that LLMs can serve simultaneously as generative samplers, surrogate evaluators, and subjective-preference models within a structured search loop. The bi-level decomposition (framework-level UCB + intra-framework surrogate-guided local search) is a practical design insight that mirrors how human modelers actually work. Key limitations and open questions include: frameworks are sampled and fixed at search start (no dynamic generation), the LLM surrogate's calibration degrades on runtime prediction (JSS), MOSE relies on a small fixed reference set, and the entire pipeline is evaluated over only 20 iterations with a 300-second per-model budget. Future directions—dynamic framework discovery, non-stationary bandit policies, framework-specific search operators, and richer human-in-the-loop interaction—suggest substantial room for improvement.
