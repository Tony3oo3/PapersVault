## Problem

Existing agent evaluation frameworks rely on heterogeneous, domain-specific success criteria (database lookups, regex matching, tool signature checks) that resist unification across tasks, and they fail to systematically isolate the user's expertise level as an independent variable affecting agent performance. Moreover, most works stop at reporting aggregate metrics without providing actionable error diagnosis, leaving developers without a clear path to improve their agents.

## Input / Output

The framework consumes an agent's full trajectory log (tool calls, intermediate reasoning, and user-agent dialogue), a task instruction, a selectable user persona template (expert or non-expert), and a set of natural-language grading notes representing subgoals. It produces five metrics—MeanProg@k, MaxProgressRate@k, MaxAUC@k, MaxPPT@k, and pass@k—along with clustered error categories and per-subgoal judge variance plots. Notably, evaluation requires no access to the underlying environment or database state; the LLM-as-a-judge scores each subgoal solely from the trajectory text, and the user persona is decoupled from the task via a templating function so that the same task can be evaluated under different expertise levels without modification.

## Method

TED comprises three interdependent stages. In the Talk stage, a reusable generic persona prompt (expert or non-expert) is combined with a task instruction through a two-step reflection-then-response function to drive an LLM-simulated user, enabling systematic isolation of user expertise from task difficulty. In the Evaluate stage, all subgoals (tool calls, ordering, final responses) are expressed as natural-language grading notes scored by a majority-vote LLM-as-a-judge; the paper then defines MaxProgressRate@k (best final progress across k stochastic trials), MaxAUC@k (area under the per-turn progress curve, rewarding early subgoal completion), and MaxPPT@k (telescoping average progress-per-turn, treating all turns uniformly). In the Diagnose stage, an automated two-step pipeline first identifies low-level errors from judge explanations where subgoals are inconsistently scored, then semantically clusters them into high-level error categories; these identified errors can be injected back into the agent's instruction (via direct insertion or human-refined notes) to yield 8–10% gains on MaxAUC@k and MaxPPT@k.

## Results

On τ²-bench airline (easy, n=k=20), gpt-4.1 achieves the highest MaxProg@k (0.82 expert / 0.80 non-expert) and pass@k (0.50 / 1.00), while on ToolSandbox (n=k=8), gpt-4o leads with MaxProg@k of 0.94/0.96 and pass@k of 0.94/0.97. The proposed MaxAUC@k and MaxPPT@k metrics reveal distinctions invisible to MaxProgressRate@k: e.g., gpt-4o-mini and mistral-large differ by only 5% on MeanProg@k but by 10% on MaxAUC@k (0.96 vs 0.85), reversing their ranking. Non-expert personas consistently yield lower MaxAUC@k across all models, confirming that turn efficiency is persona-sensitive. Incorporating TED-identified errors into agent design yields peak gains of +9% MeanProg@k (gpt-4o-mini, τ²-bench) and +10% MaxPPT@k (gpt-4.1, ToolSandbox).

## Baselines & Comparisons

Against τ²-bench's original evaluation (Barres et al., 2025), the TED framework reveals different model rankings: the original pass^4 metric on airline easy ranks gpt-4.1 > gpt-4o > gpt-4o-mini > mistral-large > mistral-nemo, but TED's MaxAUC@k shows mistral-nemo outperforming gpt-4o-mini under expert persona (0.97 vs 0.85) while the reverse holds under non-expert (0.67 vs 0.73), a nuance the original binary pass metrics miss entirely. Against ToolSandbox's original Score_M+ (Lu et al., 2024), both frameworks agree that gpt-4o is best, but TED shows mistral-nemo beating gpt-4o-mini on pass@k for non-expert users (0.92 vs 0.84) while the original metric ranks gpt-4o-mini above mistral-nemo, demonstrating that user persona disentangles performance that a single aggregate score obscures. Against HiTEC-ICL (Cui et al., 2025), the TED-error variant (HTC†) outperforms standard HTC with predefined generic errors for gpt-4o-mini on τ²-bench special split (MaxProg@k 0.61 vs 0.54 expert; 0.65 vs 0.51 non-expert), while on ToolSandbox all four approaches (EI, HN, HTC, HTC†) show positive gains, with gpt-4.1+HN achieving the largest MaxPPT@k improvement of +10%.

## Relation to Prior Work

The TED framework extends the dynamic user-simulation paradigm introduced by τ-bench (Yao et al., 2024) and τ²-bench (Barres et al., 2025) by decoupling reusable, generic user personas from task instructions, enabling systematic isolation of user expertise as an evaluation axis. It builds on AgentBoard's (Chang et al., 2024) progress-rate concept and ToolSandbox's (Lu et al., 2024) milestone structure, but replaces environment-specific assertions (database lookups, tool signatures, regex) with natural-language grading notes scored by LLM-as-a-judge, and introduces turn-aware efficiency metrics (MaxAUC@k, MaxPPT@k) that prior multi-turn benchmarks lacked. The automated error analysis stage departs from HiTEC-ICL (Cui et al., 2025) by discovering errors unsupervised from real-time judge/agent inconsistencies rather than relying on predefined error categories.

## Why It Matters / Open Questions

The framework provides a practical, domain-agnostic evaluation pipeline that reveals agent rankings shift depending on user expertise—a dimension prior benchmarks either ignored or tightly coupled to task difficulty—making it harder to claim a single 'best' agent model. The 8–10% performance gains from incorporating TED-identified errors into agent instructions demonstrate that automated diagnosis can close a meaningful gap without manual prompt engineering. Key limitations include the inability to verify silent database-state changes not reflected in trajectories, and residual LLM-as-a-judge disagreement (up to 20% on some models). Open questions include whether grading notes generalize to open-ended, non-task-oriented dialogue and whether the user-proxy model itself introduces a confounding expertise level that interacts with the persona template.
