## Problem

Existing multi-task VRP solvers encode constraint information and node attributes into static embeddings that remain fixed across all decoding steps, while only the context (e.g., remaining capacity, current time) is updated. This context-node misalignment prevents the model from accurately reflecting how constraint urgency shifts during sequential decision-making, leading to suboptimal routing choices—especially under time-sensitive or capacity-critical constraints.
![Teaser figure](../imgs/ICLR20260537/cropped_page3_idx0.webp)

## Input / Output

The model takes a VRP instance specified by node coordinates in [0,1)², linehaul/backhaul demands, time-window parameters (early, late, service times), a one-hot constraint flag vector over {B, O, L, TW}, and depot attributes, all embedded via a 6-layer dual-attention Transformer encoder. It outputs N parallel route trajectories (POMO-style, N = number of customers) from diverse starting points, from which the best solution is selected; the objective is total routing length. Training uses 100,000 instances across 16 in-distribution variants, while evaluation spans 48 variants including zero-shot generalization to unseen Mixed Backhaul (MB) and Multi-Depot (MD) constraints at N=50 and N=100.

## Method

CCL introduces two coupled modules into the decoding loop. RGCR (Relevance-Guided Context Reformulation) extracts constraint-specific attributes per trajectory, projects them into embeddings, computes dot-product correlation scores against the current node embedding, and adaptively aggregates constraint embeddings via a weighted sum to produce a step-wise context that emphasizes the most relevant constraints. TSNR (Trajectory-Shared Node Re-embedding) then refines node representations through a multi-head attention mechanism where the previous step's node embeddings serve as queries and the concatenated node-context information from all N trajectories serves as keys and values, augmented with a distance-based bias to prevent overfitting to time windows. Crucially, the refined node embeddings are written back into the environment and used as queries in the next decoding step, forming a chain-of-context that captures sequential dependencies. Training uses REINFORCE with a shared baseline over N parallel trajectories, and a probabilistic update rate (P_tr, P_ts) controls how frequently node re-embedding is applied, enabling a performance-cost trade-off at inference.

## Results

On 16 in-distribution VRP variants (N=50), CCL† achieves an average gap of 1.10% to the HGS-PyVRP heuristic baseline, outperforming CaDA† (1.63%) and CaDA (1.90%) on every task. On 32 out-of-distribution variants (N=50, zero-shot on MB and MD constraints), CCL† reduces the average gap to 25.78% (w/o TW) and 22.42% (w/ TW), compared to 34.17% and 34.67% for CaDA†. Inference time is 6.5s per 1,000 instances (N=50) versus 2.7s for CaDA†, reflecting the cost of step-wise node re-embedding. On large-scale real-world VRPTW (N=600), CCL achieves a 70.96% gap versus 88.19% for CaDA in 2.0s.

## Baselines & Comparisons

CCL† outperforms all neural baselines on all 16 in-distribution tasks. Against CaDA (the strongest prior neural method), CCL† reduces the average gap from 1.90% to 1.10% (N=50), with the largest improvements on backhaul and time-window tasks (e.g., VRPBL: 3.78%→2.45%; VRPTW: 1.75%→0.91%). Against MTPOMO, MVMoE, and RF-TE, CCL† leads by 1–3 percentage points in gap across all tasks. On 32 out-of-distribution tasks (zero-shot on MB and MD), CCL† achieves 25.78% average gap (w/o TW) versus 34.17% for CaDA†, a 8.4-point improvement. The step-wise refinement baseline ASW-TAM (Xin et al., 2020) applied naively to the multi-task setting performs far worse (29.93% gap, 96.1s), validating CCL's trajectory-shared design. The only trade-off is inference time: CCL† takes 6.5s vs. 2.7s for CaDA†, though a lightweight variant (P_ts=0.25) achieves 1.38% gap in 4.6s.

## Relation to Prior Work

CCL extends the multi-task VRP solver lineage from POMO's multi-trajectory RL through MTPOMO, MVMoE, RouteFinder, and CaDA, all of which encode constraints into static node embeddings that remain fixed during autoregressive decoding. The key departure is the argument that this static-node/dynamic-context pairing violates the Markov property: as the vehicle's position, remaining capacity, and elapsed time evolve, node priorities shift but the embeddings do not. CCL addresses this by introducing two new modules—RGCR for relevance-weighted constraint context and TSNR for trajectory-shared node re-embedding—that jointly update both context and node representations at each decoding step, building on the step-wise refinement idea from Xin et al. (2020) but making it computationally feasible for multi-trajectory, multi-task settings.

## Why It Matters / Open Questions

The paper demonstrates that dynamic, context-aligned node representations yield consistent gains across 48 VRP variants, with particularly strong zero-shot transfer to unseen multi-depot (MD) and mixed-backhaul (MB) constraints, suggesting that modeling evolving constraint urgency generalizes better than static encodings. The practical limitation is inference time (5–7 s vs. 1–3 s for CaDA), though the P_tr/P_ts knobs offer a tunable quality-speed trade-off that makes CCL deployable on large-scale instances (N=600). An open question is whether the per-step re-embedding can be further accelerated (e.g., via sparser attention or learned update schedules) without sacrificing the sequential-dependency modeling that drives the gains.
