## Problem

LiveCodeBench (LCB) has become the de-facto standard for contamination-aware code-generation evaluation, but it is restricted to Python, leaving open whether LLMs can generalize coding competence across the diverse programming languages required in real-world software engineering. This paper asks: are current LLMs overfitted to Python, and can strong Python performance serve as a reliable proxy for cross-lingual code generation ability?

## Input / Output

Each task provides a natural-language problem statement with sample input/output pairs from LeetCode, AtCoder, or Codeforces, wrapped in a zero-shot prompt that specifies the target language via a system message (e.g., 'You are an expert C++ programmer'). LeetCode's native functional format is automatically converted to a unified STDIN/STDOUT protocol (lists space-separated, 2D arrays with a row-count header) so that a single evaluation harness handles all 12 languages identically. The model must emit a complete program that reads from standard input and writes to standard output; correctness is graded as Pass@1 against hidden official test cases with a 6-second wall-time and 4 GB memory limit per test.

## Method

Multi-LCB reuses the entire LCB task pool and inherits its release-date filtering for contamination-aware evaluation, then replicates every task across 12 programming languages (C++, C#, Python, Java, Rust, Go, TypeScript, JavaScript, Ruby, PHP, Kotlin, Scala) so that identical problems can be compared directly across languages. The key technical contribution is an automatic conversion pipeline that rewrites LeetCode's Python-coupled functional format into language-agnostic STDIN/STDOUT tasks: it parses problem examples, reformats them for model prompts, and transforms all public and hidden test cases into a unified I/O structure grouped by data dimensionality (scalar, 1-D, 2-D). Evaluation follows LCB's zero-shot protocol with nucleus sampling (t=0.2, top-p=0.95), triple-backtick stop sequences, and Pass@1 averaged over 10 runs, executed in isolated sandbox containers with per-language compilers/interpreters. Because the same task set is used across all languages and the benchmark automatically tracks future LCB updates, Multi-LCB enables systematic, continuously updated cross-language assessment without task-level confounds.

## Results

On Multi-LCB (Dataset v6, Feb–May 2025, Pass@1 averaged over 10 runs at t=0.2), GPT-OSS-120B* (Medium) achieves the highest average score of 67.8%, followed by Qwen3-235B-A22B-Thk-2507* (64.0%) and DeepSeek-R1-0528* (63.1%). Python consistently yields the highest per-language mean (0.482), with Java and C++ close behind (~0.44), while Scala trails at below 0.29. Most evaluated models remain below 40% average, and models without explicit multi-language training (e.g., OpenRsn-Nmt-32B*) exceed 60% on Python but drop below 30% on other languages, confirming Python overfitting.

## Baselines & Comparisons

As a benchmark paper, Multi-LCB does not propose a new method to compare against baselines; instead, it evaluates 24 LLMs and validates its construction against the original LiveCodeBench. On the Python subset, Multi-LCB reproduces official LCB v4–v6 leaderboard scores with a mean absolute deviation of only ~3% (e.g., Qwen3-235B-A22B-Thinking-2507: 74.0% vs. 74.1% original, Δ=−0.1; DeepSeek-R1-0528: 66.3% vs. 68.7%, Δ=−2.4), confirming that the multilingual transformation introduces no artificial difficulty. Cross-language comparisons reveal that GPT-OSS-120B* (Medium) outperforms Qwen3-235B-A22B-Thk-2507* on Go, JavaScript, TypeScript, Rust, Ruby, and Kotlin despite Qwen3 being stronger on Python (74.0 vs. 71.1), demonstrating that Python performance is not a reliable proxy for cross-lingual competence. Models without explicit multi-language training (OpenRsn-Nmt-32B*, OpenCodeRsn-Nmt-1.1-32B*) show the starkest Python-overfitting gap, exceeding 60% on Python while remaining below 30% on most other languages. Scala consistently yields the lowest scores across all models (mean <0.29), while Python leads (mean 0.482), with C# and Ruby forming a middle tier around 0.33–0.39.

## Relation to Prior Work

This paper extends LiveCodeBench (LCB), the contamination-aware, continuously updated code-generation benchmark, from its Python-only scope to twelve programming languages while preserving LCB's release-date filtering and evaluation protocol. It departs from prior multilingual code benchmarks (MBXP, MultiPL-E, HumanEval-XL) that translate function signatures and unit tests per language, instead converting all tasks into a unified STDIN/STDOUT format that is inherently language-agnostic. Unlike xCodeEval (static, Codeforces-only) or Ag-LiveCodeBench-X (rarer languages, subset of LCB), Multi-LCB replicates the full LCB task pool across all supported languages and updates automatically as LCB evolves.

## Why It Matters / Open Questions

Multi-LCB directly addresses the practical concern that LLMs are evaluated almost exclusively on Python while real-world software engineering spans many languages, and it exposes that Python performance is not a reliable proxy for cross-lingual code generation competence. The discovery of language-specific contamination patterns and substantial performance inversions across languages (e.g., a model stronger in Python losing to a weaker one in C++ or Rust) provides actionable evidence for model developers to balance training data across languages. Open questions remain: whether the STDIN/STDOUT format unfairly penalizes languages with richer type systems, whether the competitive-programming task distribution generalizes to industrial coding, and whether proprietary frontier models (GPT-4, Claude, Gemini) show similar or different multilingual gaps.
