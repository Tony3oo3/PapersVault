## Problem

Existing MLE benchmarks (MLE-Bench, DS-Bench, MLE-Dojo, MLGym) rely on static, manually curated tasks that are expensive to author and adapt into standardized formats, creating a scalability bottleneck that limits the diversity and realism of evaluation scenarios for MLE agents. The paper asks: can a fully automated pipeline transform raw datasets into competition-style MLE tasks that are structurally correct, semantically coherent, and empirically solvable, without any human intervention?

## Input / Output

The pipeline consumes raw datasets (primarily from Kaggle, spanning tabular, image, video, audio, text, and time-series modalities) along with their metadata, and produces self-contained MLE task packages following a strict unified directory structure: prepare.py (deterministic train/test splitting), metric.py (a Metric class with evaluate and validate_submission methods), description.txt, sample_submission.csv, test_answer.csv, and raw/, public/, private/ directories. Each package is designed to be executable end-to-end in an interactive MLE environment (adapted from MLE-Dojo) with request_info and execute_code interfaces, requiring no manual intervention. From 224 source datasets, the system yields 606 verified tasks averaging 2.71 tasks per dataset.

## Method

MLE-Smith employs a generate-verify-execute paradigm with three specialized LLM agents (GPT-5 backbone) operating sequentially: a Brainstormer that enumerates multiple candidate task formulations per dataset (up to 3), a Designer that instantiates each candidate into a complete task package with preprocessing, schemas, evaluation protocol, and auxiliary scripts, and a Refactor that standardizes all artifacts into a unified schema with consistent interfaces. A persistent hybrid verification mechanism runs across all stages: deterministic Assertions enforce structural constraints (file existence, function signatures, directory layout), LLM-based Reviews check semantic soundness (description clarity, label leakage, metric appropriateness), and Execution-based Validation runs a ReAct-style MLE agent (10-step budget) inside the MLE-Dojo environment to confirm the task is empirically solvable with non-trivial performance. Failures at any verification layer trigger targeted retries (up to 3) by the responsible agent, creating controlled feedback loops. The ablation study confirms each component is necessary: the Brainstormer prevents objective/metric collapse, the Designer-Refactor separation reduces retries from ~9 to ~3, Assertions catch 4.4–9.6% structural defects, Reviews detect 14.2% semantic issues invisible to deterministic checks, and execution validation filters 11.2% of tasks that are trivially solvable.

## Results

MLE-Smith generates 606 fully verified MLE tasks from 224 real-world Kaggle datasets at an average cost of $0.78 per task and ~420 seconds per task. Evaluating eight cutting-edge LLMs on 50 MLE-Smith tasks (Smith set) versus 50 human-curated MLE-Dojo tasks (Dojo set) yields near-perfect Elo agreement: Pearson r = 0.982, Spearman ρ = 0.952, and Top-3 leaderboard overlap of 1.0. Gemini-2.5-Pro leads on both sets (Overall Elo 1254.6 on Dojo, 1179.7 on Smith), while GPT-4o-mini trails (686.7 and 742.0 respectively). Agent error rates on Smith tasks are non-trivial (33–44% across modalities), confirming the tasks are challenging and discriminative.

## Baselines & Comparisons

The sole baseline comparison is against MLE-Dojo, a human-curated interactive MLE benchmark with 50 evaluation tasks. The paper's central claim is that MLE-Smith-generated tasks are statistically indistinguishable from human-designed ones in their ability to discriminate between LLM agents. On the 50-task Smith set, the Elo ranking of all eight models correlates with the Dojo-set ranking at Pearson r = 0.982 and Spearman ρ = 0.952, with perfect Top-3 overlap (1.0) and near-perfect Top-5 overlap (0.8). Lin's CCC of 0.958 and Bland-Altman limits of agreement of roughly ±96 Elo confirm numerical interchangeability, while Cronbach's α = 0.993 and ICC(2,1) = 0.981 treat the two sets as highly reliable interchangeable evaluators. The model ordering is preserved: Gemini-2.5-Pro > Gemini-2.5-Flash > o4-mini/DeepSeek-Reasoner > o3-mini/DeepSeek-Chat > GPT-4o > GPT-4o-mini on both sets, with only minor rank swaps in the middle tier (e.g., o4-mini and DeepSeek-Reasoner trade positions between Dojo and Smith). This demonstrates that MLE-Smith tasks faithfully replicate the difficulty and discriminative structure of expert-curated MLE competitions without any human intervention.

## Relation to Prior Work

This paper extends the automated task generation paradigm established in software engineering (SWE-Smith, AutoCodeBench) and general agentic tasks (TaskCraft) to the machine learning engineering domain, where prior benchmarks (MLE-Bench, DS-Bench, MLE-Dojo, MLGym) remain static and manually curated. It builds directly on MLE-Dojo's interactive environment for execution-based validation, repurposing its request_info and execute_code interfaces as the empirical solvability check. The key conceptual departure is the hybrid verification stack—deterministic assertions, LLM-based semantic reviews, and execution-based validation—tailored to the multi-criteria nature of MLE tasks (structural integrity, semantic soundness, empirical tractability), which has no direct analogue in the SWE or code-generation task-generation literature.

## Why It Matters / Open Questions

By demonstrating that 606 automatically generated tasks produce Elo rankings nearly indistinguishable from 50 human-curated MLE-Dojo tasks (Pearson r = 0.982, Top-3 overlap = 1.0), MLE-Smith removes the primary scalability bottleneck for MLE agent research and opens the door to continuous, large-scale benchmarking and eventually RL training on generated tasks. Open questions include whether the pipeline generalizes beyond Kaggle-sourced datasets to proprietary or streaming data, whether tasks generated with a single backbone (GPT-5) introduce subtle biases that a diverse LLM ensemble would mitigate, and whether the generated tasks remain discriminative as MLE agents improve over time. The $0.78-per-task cost is practically significant, but the 420-second average generation time plus variable execution-validation overhead may still be non-trivial at the scale of tens of thousands of tasks.
