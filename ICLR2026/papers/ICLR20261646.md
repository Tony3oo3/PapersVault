## Problem

Existing LLM tool-use benchmarks (BFCL, ToolBench, τ-Bench, etc.) are overly idealized, presenting tasks with complete information, single instruction types, and simple sequential tool chains. They fail to capture three salient properties of real user behavior: compositional instructions requiring non-trivial tool orchestration, implicit intent spread across dialogue turns, and frequent transitions between task types (tool-use, chat, clarification). As a result, apparent model progress on these benchmarks is spurious and does not reflect robustness in realistic agentic settings.

## Input / Output

Each evaluation scenario is a multi-turn dialogue (avg. 5.27 turns) containing exactly four user tasks drawn from four types (single-tool, multi-tool, chat, clarification), paired with a curated subset of ~1,600 verified public APIs. The LLM must produce tool calls and natural-language responses throughout the dialogue. Outputs are scored at two granularities: task-level accuracy (per individual task) and session accuracy (all four tasks in a dialogue correct), plus fine-grained tool-orchestration metrics (Optimal Path Rate and Accomplish Progress Rate) and a nine-category error distribution (refusal, wrong tool, redundant call, parameter hallucination, etc.).

## Method

WildToolBench is constructed via a three-stage pipeline: (1) seed scenarios and user-behavior patterns are extracted from large-scale real user logs and expanded into 256 scenarios; (2) a GPT-4o multi-agent system (User Agent + Assistant Agent) generates initial dialogue trajectories under controlled task-type and omission-type constraints; (3) five human experts verify, correct, and annotate every tool-call dependency, with four rounds of cross-annotator review driving data quality from 62% to 100%. The evaluation introduces an enumerate-match-score pipeline for tool orchestration: all legal execution paths are enumerated via depth-first topological sorting over a human-annotated dependency DAG (capturing both sequential and parallel branches), the LLM's actual tool calls are incrementally matched against this path set, and scores are computed as the Optimal Path Rate (fraction of completed paths with minimum depth) and Accomplish Progress Rate (fraction of valid nodes before failure). Across 57 LLMs, no model exceeds 15% session accuracy, and performance degrades sharply with increasing instruction-transition frequency and long-range contextual dependencies.

## Results

Across 57 evaluated LLMs, no model exceeds 15% session accuracy on WildToolBench, with the best being Gemini-2.0-Thinking at 14.45% session accuracy and 61.04% task accuracy. Proprietary models consistently outperform open-source ones, and reasoning-enabled variants (e.g., o1, Gemini-2.0-Thinking) surpass their non-reasoning counterparts. On tool orchestration specifically, the highest task accuracy for compositional multi-step tasks is only 43.75% (Claude-4-Sonnet), and the peak Optimal Path Rate reaches just 42.74%, indicating substantial room for improvement in efficient tool-call topology construction.

## Baselines & Comparisons

WildToolBench is positioned against seven prior tool-use benchmarks (BFCL v1/v2/v3, ToolBench, AnyToolBench, τ-bench, τ²-bench, T-EVAL, UltraTool) primarily through qualitative feature comparison (Table 1) and cross-benchmark numerical scores (Table 5). The key distinction is that WildToolBench is the only benchmark with 100% hidden information in context and 100% instruction transition coverage, plus support for mixed (sequential + parallel) tool-use, whereas BFCL v3 covers only 15.7% hidden info and 39.7% instruction transition, and all other baselines score 0% on both. Numerically, the same models that score 64–82% on BFCL-v2/v3 drop to 5.9–14.5% on WildToolBench (e.g., GPT-4o: 70.5% on BFCL-v2 vs. 11.7% on WildToolBench; Claude-Sonnet 4: 81.1% on BFCL-v2 vs. 12.5% on WildToolBench), demonstrating that prior benchmarks are saturated while WildToolBench remains highly challenging. Specialized tool-use models (xLAM-2-70B, Watt-8B, Hammer2.1-7B) perform significantly worse than general-purpose models on WildToolBench, with 'Wrong Name' error rates exceeding 30%, suggesting that narrow specialization leads to brittleness under realistic user behavior. The paper also refutes a prior claim (Zhou et al., 2025) that reasoning models do not outperform non-reasoning models on tool-use, showing that reasoning variants consistently achieve higher tool-orchestration accuracy within the same model family.

## Relation to Prior Work

This paper extends the multi-turn, multi-step LLM tool-use evaluation paradigm established by BFCL, ToolBench, and τ-Bench, but argues that all prior benchmarks are 'overly idealized' by providing complete user intent, independent tasks, and single instruction types per turn. It departs from the LLM-as-User simulation approach of τ-Bench by grounding task construction in large-scale real user logs and human annotation, explicitly encoding three 'wild' behaviors (compositional tasks, hidden intent, instruction transitions) that prior benchmarks omit. The enumerate-match-score pipeline for tool orchestration evaluation is a methodological departure from the similarity-based or single-optimal-path metrics used by WorfBench and TaskBench, instead enumerating all legal DAG paths via depth-first topological sorting.

## Why It Matters / Open Questions

The finding that no model exceeds 15% session accuracy—while the same models score 50–70% on BFCL-v3—reframes the central challenge of agentic LLMs from tool-calling mechanics to understanding wild, contextually-embedded user behavior. The error analysis reveals that 'Redundant Call' and 'Wrong Name' errors dominate over parameter-level errors, suggesting the field's bottleneck has shifted to higher-order planning and context management rather than syntactic generation. Limitations include the 256-scenario scale constrained by human annotation, and the authors note that combining human rubrics with automated synthetic environments is needed for the next scaling phase. Open questions include whether the self-conditioning effect (models biasing toward repeating prior action types) can be mitigated through architectural or training changes.
