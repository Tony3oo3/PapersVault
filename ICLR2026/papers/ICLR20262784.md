## Problem

System algorithm design operates in a discontinuous solution space where small design changes cause sharp, non-linear performance shifts, making it hard for LLMs to navigate. When repeatedly prompted, LLMs exhibit availability bias—clustering around well-known heuristics like LRU or First Fit—and this bias cannot be practically mitigated by adjusting temperature or other hyperparameters. The paper asks whether a principled self-reflection framework can enable LLMs to make the creative leaps needed to discover high-performing, diverse algorithm designs.

## Input / Output

MetaMuse takes a problem statement (e.g., cache replacement or online bin packing), a set of s=4 dictionary keywords as external stimuli, and feedback embeddings (vectors of performance measurements across n=30 workload traces) from previously generated solutions. It produces executable, deterministic Python code implementing the algorithm within a fixed function-signature framework (evict, update_after_hit, update_after_insert, update_after_evict), along with a JSON-structured natural language description of the policy. The code is constrained to be deterministic (no randomness) and must operate within a provided code skeleton with read-only access to cache snapshot attributes.

## Method

MetaMuse is a creative ideation framework built on three self-reflection principles that guide each iteration of solution generation. First, diversity is evaluated in measurable performance space using feedback embeddings (hit ratios or bin usage across workload traces) rather than semantic embeddings of descriptions, ensuring functionally equivalent solutions are recognized as identical. Second, ideation is steered by external stimuli—randomly selected dictionary keywords—rather than internal LLM randomness; the RSDict-SF variant uses Gaussian Process Regression with a dot-product kernel over SBERT embeddings of LLM-generated observations to predict which stimulus set will produce solutions closest to a target feedback embedding (farthest from existing solutions for exploration, or all-high for exploitation). Third, stimuli are developed into executable code through four structured waypoints—property extraction, problem mapping, solution formulation, and code generation—rather than free-form chain-of-thought, preventing superficial use of stimuli (e.g., merely using keywords as variable names). The framework is model-agnostic and was evaluated with GPT-4o, Llama3.3-70B, and DeepSeek-V3 for ideation, with GPT-4o handling code generation.

## Results

On cache replacement (96 real-world traces), MetaMuse with GPT-4o achieves up to 35.76% lower miss ratio than the best human heuristics and up to 9.89% lower than the best LLM-based baselines at the 75th-percentile trace. On online bin packing (288 traces), MetaMuse with DeepSeek-V3 achieves up to 30.93% lower bin usage than human heuristics and up to 21.06% lower than LLM-based baselines at the 90th-percentile trace. MetaMuse also generates up to 1.78× (cache) and 1.80× (bin packing) more distinct solutions than LLM-based baselines, at a per-solution cost of 2.16 cents with GPT-4o.

## Baselines & Comparisons

MetaMuse outperforms all five LLM-based baselines (Repeated Sampling, ReEvo, MCTS-AHD, OpenEvolve, PlanSearch) on both tasks across all three LLMs. On cache replacement with GPT-4o, MetaMuse achieves 5.17%–9.89% lower miss ratio than the best LLM baseline at the 90th-percentile trace, and 3.62%–6.39% lower at the 75th-percentile. On bin packing with DeepSeek-V3, the margin widens to up to 21.06% lower bin usage than LLM baselines. Against human-crafted heuristics, MetaMuse's advantage is larger: up to 35.76% fewer cache misses (vs. heuristics like LRU, LFU, ARC, S3FIFO, TinyLFU) and up to 30.93% less bin usage (vs. First Fit, Best Fit, Harmonic-k, RFF). Notably, some human heuristics (e.g., Next Fit, Worst Fit for bin packing) perform worse than the First Fit reference, making them invisible in the comparison. On diversity, MetaMuse generates 1.44×–1.80× more distinct solutions than any LLM baseline, and reduces cluster density around well-known heuristics (e.g., LRU cluster density drops 35.28%, ARC drops 77.45%) compared to Repeated Sampling.

## Relation to Prior Work

This paper departs from the dominant paradigm of LLM-based automatic heuristic design (MCTS-AHD, ReEvo, OpenEvolve, PlanSearch), which evolves an initial population through mutations and crossovers, by reframing algorithm generation as creative ideation—discontinuous sampling leaps in a non-smooth solution space. It also distinguishes itself from human-LLM collaboration approaches by arguing that LLMs alone can think 'outside the box' through structured self-reflection. Conceptually, the framework repurposes ideas from cognitive science (availability bias, divergent thinking), distributed systems (power-of-two random choices), and statistical ML (Gaussian Process Regression) into a unified three-principle pipeline: feedback-space diversity evaluation, external stimuli steering, and waypoint reasoning for code generation.

## Why It Matters / Open Questions

The paper demonstrates that LLMs can generate system algorithms outperforming both prior LLM-based methods and well-established human heuristics on real cloud-provider workloads, with surprisingly non-obvious design choices (e.g., eviction-event counters, hash-based cache segmentation) that suggest genuine creative capability beyond pattern recall. Key open questions include whether the framework generalizes beyond the two tested problems (cache replacement, bin packing), whether the RSDict-SF benchmarking overhead is prohibitive for expensive end-to-end evaluations, and whether human expertise could further improve solution usefulness. The finding that domain-agnostic stimuli outperform task-related ones challenges the intuition that domain context should aid ideation, pointing to a broader principle about how to break LLMs out of their training-distribution attractors.
