## Problem

LLMs produce visually suboptimal code for tasks like chart generation and webpage design, exhibiting overlapping elements, inconsistent color schemes, and disorganized layouts. Existing reward signals for coding LLMs are confined to a single textual modality (executability, unit-test correctness) and cannot assess rendered visual quality or interact with live webpages, leaving the aesthetic dimension of code generation unaddressed.
![Teaser figure](../imgs/ICLR20261678/cropped_page2_idx0.webp)

## Input / Output

The model receives a natural-language instruction (e.g., 'create an interactive Tic-Tac-Toe game' or 'generate a bar chart of sales data') and produces either Python plotting code (restricted to matplotlib, seaborn, plotly) or a self-contained HTML/CSS/JS file. The generated HTML is rendered headlessly via Playwright/Selenium into a full-page screenshot for static evaluation, and the interactive aesthetics agent launches the page in a headless browser to autonomously click, type, and navigate elements, scoring each interaction as binary success/failure.

## Method

The core contribution is GRPO-AR, which couples the GRPO reinforcement learning algorithm with a three-agent reward framework: an Execution Agent (HTMLHint-based syntax validation), a Static Aesthetics Agent (GPT-5 chain-of-thought scoring of rendered screenshots on instructional alignment, visual elements, and layout cohesion), and an Interactive Aesthetics Agent (WebVoyager-based autonomous navigation with GPT-4o that plans, executes, and scores up to N interactions). The three agent scores are combined as a weighted sum (w_exec=0.1, w_static=0.8, w_interact=0.1) to form the per-sample reward, and GRPO computes group-relative advantages over G sampled outputs per prompt. Training is two-stage: supervised fine-tuning on the 358K-sample AesCode-358K dataset (158K plot + 200K webpage pairs), followed by RL on 20K WebSight-derived prompts, applied to Qwen3-4B and Qwen2.5-Coder-7B bases to yield AesCoder-4B and AesCoder-7B.

## Results

On OpenDesign, AesCoder-4B achieves a total static aesthetics score of 81.92 and interactive aesthetics score of 1.04, surpassing all open-source models (best: Qwen3-Coder-480B-A35B at 79.90) and proprietary GPT-4o (48.08) and GPT-4.1 (65.79), while matching GPT-5 (81.03) and Claude Sonnet 4 (81.05). On PandasPlotBench, AesCoder-4B achieves 70 average score with 0.09 error rate and 0.63 good rate, outperforming GPT-4o (68 avg) and GPT-4.1 (69 avg). AesCoder-7B similarly reaches 81.23 total on OpenDesign, exceeding its 7B base model (46.27) by over 35 points.

## Baselines & Comparisons

AesCoder-4B (4B params) surpasses GPT-4o (48.08) and GPT-4.1 (65.79) by 33.8 and 16.1 points respectively on OpenDesign total score, and outperforms all open-source models up to 685B parameters (Qwen3-Coder-480B-A35B: 79.90, DeepSeek-R1-0528: 78.86). It achieves a total score of 81.92, marginally exceeding GPT-5 (81.03) and Claude Sonnet 4 (81.05), though both proprietary models retain a slight edge on interactive aesthetics (1.37 and 0.92 vs. 1.04). On PandasPlotBench, AesCoder-4B achieves 70 average score, beating GPT-4o (68) and GPT-4.1 (69) while trailing GPT-5 (75) and Claude Sonnet 4 (74). AesCoder-7B improves its base model (Qwen2.5-Coder-7B-Instruct) from 46.27 to 81.23 on OpenDesign total, a 35-point gain, and reduces PandasPlotBench error rate from 0.22 to 0.09. However, on general coding benchmarks (LiveCodeBench, MBPP, MBPP+), both AesCoder models show notable regressions (e.g., AesCoder-4B drops from 32.5 to 19.0 on LiveCodeBench), reflecting the alignment tax of domain-specialized aesthetic training.

## Relation to Prior Work

This paper extends GRPO (Shao et al., 2024) by replacing its scalar execution-based reward with a multi-agent reward system that jointly evaluates executability, static visual aesthetics, and interactive usability. The interactive aesthetics agent repurposes WebVoyager (He et al., 2024) as an evaluator rather than a task solver, adapting the web-agent paradigm from navigation to quality assessment. Conceptually, the work departs from prior code-RL literature (RLTF, CodeRL, RLEF) that treats reward as a single textual signal, and from the AIGC aesthetics literature that evaluates static images, by introducing a unified framework that scores code-generated visual artifacts across textual, visual, and interactive modalities simultaneously.

## Why It Matters / Open Questions

The paper provides the first large-scale dataset (AesCode-358K) and benchmark (OpenDesign) for evaluating aesthetic quality in code-generated visual output, filling a gap where no standardized evaluation existed for webpage design aesthetics. The agentic reward framework is a generalizable recipe for incorporating multi-modal, interactive feedback into RL training of coding models. A key limitation is the substantial alignment tax: AesCoder-4B drops ~13 points on LiveCodeBench and ~13 on MBPP relative to its base model, raising open questions about whether aesthetic specialization and general coding competence can be jointly preserved. Additionally, the framework's reliance on proprietary models (GPT-5, GPT-4o) as judges and the limited success rate of GUI agents for interactive evaluation constrain reproducibility and scalability.
