## Problem

Training GUI agents is bottlenecked by a dilemma: live web interaction is unsafe and non-reproducible, while human-annotated trajectories and hand-built environments are costly and scarce. The paper argues this focus on data volume overlooks a more critical factor—the efficiency with which an LLM's latent internet-scale knowledge is compressed into grounded, actionable agent behavior—and that bridging this 'semantic-to-action gap' requires a fundamentally different pipeline rather than simply more data.

## Input / Output

The agent consumes a web page screenshot at 1258×1258 resolution together with a natural-language task instruction, and produces a structured action tuple {action_type, point, text} where action_type spans click, double_click, type, scroll, keypress, drag, and a specialized get_final_answer action for retrieval tasks. Point encodes [x,y] coordinates (or source-target pairs for drag), while text carries input strings, scroll directions, or the final answer. For information-retrieval tasks, the final answer is scored against a set of equivalent canonical answers using normalized F1, making the output verifiable without human raters.

## Method

WebFactory is a fully automated closed-loop pipeline that (1) synthesizes high-fidelity offline websites via LLM-driven code generation, (2) generates diverse, executable tasks by traversing machine-readable navigation graphs and querying versioned data snapshots to guarantee answerability, (3) collects large-scale trajectories using a strong LLM executor (OpenAI computer-use-preview) with deterministic replay and key-node filtering, and (4) trains a Qwen2.5-VL-3B policy via GRPO in a unified web action space. The reward is decomposed into a format component (valid JSON, correct action-type/parameter schema) and a hierarchical accuracy component that validates action type first, then checks click-point containment, token-level F1 for text, or normalized F1 against canonical answers for retrieval. Built on the GUI-R1 framework, the key extension is the introduction of the get_final_answer action and F1-based answer scoring, enabling the same RL loop to handle both state-changing operations and data-acquisition tasks within a single policy.

## Results

On the internal offline website benchmark, WebFactory-3B achieves 71.8% task completion rate (TCR) on operational tasks and 67.3% TCR on information-retrieval tasks, slightly surpassing GUI-R1-3B (68.2% and 64.6% respectively). On the offline-to-online transfer benchmark (Amazon, Airbnb, Booking), WebFactory-3B attains a 53.4% average TCR, a 162% relative improvement over QwenVL2.5-3B (20.4%) and a 44% gain over GUI-R1-3B (37.0%). On public benchmarks, WebFactory-3B reaches 84.2% success rate on GUI-Act-Web and 66.0% type accuracy on GUI-Odyssey, outperforming all baselines on overall task completion despite being trained solely on synthetic data from 10 websites.

## Baselines & Comparisons

Against QwenVL2.5-3B (untuned VLM), WebFactory-3B wins decisively on every benchmark: 53.4% vs 20.4% average TCR on offline-to-online transfer, 71.8% vs 18.3% on internal operational tasks, and 84.2% vs 55.6% SR on GUI-Act-Web. Against GPT-4o (strong zero-shot multimodal model), WebFactory-3B also dominates: 53.4% vs 39.5% on transfer, 71.8% vs 26.7% on internal operational tasks, and 84.2% vs 41.8% SR on GUI-Act-Web. Against the closest competitor GUI-R1-3B (trained on large-scale human-annotated data), WebFactory-3B achieves a clear win on the internal benchmark (71.8% vs 68.2% TCR) and a substantial 16.4-point gain on offline-to-online transfer (53.4% vs 37.0%), while on public benchmarks the results are mixed: WebFactory-3B leads on GUI-Act-Web SR (84.2% vs 76.3%) and GUI-Odyssey type accuracy (66.0% vs 54.8%) but trails slightly on GUI-Act-Web grounding recall (82.1% vs 87.4%). Notably, WebFactory-3B was trained on synthetic data from only 10 websites, whereas GUI-R1-3B used a much broader corpus of human-annotated trajectories, making the competitive or superior performance a strong indicator of data efficiency.

## Relation to Prior Work

This paper extends the GUI-R1 RL training framework (Luo et al., 2025) by adding information-retrieval tasks and a decomposed reward, but its core departure is architectural: rather than training on human-annotated trajectories (Mind2Web, GUI-R1) or live-web rollouts (WebArena, BrowserGym, Synatra, AgentTrek), it constructs a fully automated closed-loop pipeline where LLMs synthesize both the offline environments and the training data. The 'intelligence compression' framing positions the LLM not as a component to fine-tune but as the architect of its own embodiment, distinguishing it from prior work that treats the foundation model as a fixed policy to be supervised. The knowledge-driven task generation with full environment observability is the key methodological differentiator from other synthetic-data pipelines that operate on the live web without guaranteed answerability.

## Why It Matters / Open Questions

The practical significance lies in demonstrating that a fully automated, offline pipeline can produce web agents competitive with those trained on large-scale human annotations, potentially reducing the cost and safety barriers to GUI agent research. The 'LLM embodiment' concept—quantifying how effectively a foundation model's latent knowledge converts into grounded action—offers a useful new axis for model selection, though it is only lightly explored here. Key open questions include whether the data-efficiency advantage holds as the number of training websites scales, how the decomposed reward compares to sparser or LLM-judged alternatives (acknowledged as a limitation), and whether the paradigm transfers to fundamentally different GUI paradigms such as game engines or creative software. The open-source release of the full toolchain makes this a practically useful contribution for the community.
