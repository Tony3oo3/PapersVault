## Problem

Existing tool-use benchmarks encounter probabilistic API failures and instruction quality variability only incidentally and usually filter them out, leaving LLM robustness under realistic deployment conditions unmeasured. ResiliBench makes these uncertainties the primary object of systematic study by deliberately injecting controlled perturbations—probabilistic error models and flawed workflow instructions—to measure a model's ability to detect errors, recover from API failures, and adaptively replan.

## Input / Output

Each task provides a natural-language specification with structured input/output requirements, a list of required tools from a 30-API registry organized into six functional categories with explicit dependency constraints and five failure types, and one of four prompt variants (baseline, Chain-of-Thought, MDP-optimal workflow, or flawed workflow). The LLM agent operates in a multi-turn interactive environment with up to 10 turns, using tool_search and tool_call syntax, one tool per turn, with a simulated base success rate of 0.8. Output is a task completion status categorized as full_success, partial_success, or failure, determined by four criteria: required tools coverage, sequence correctness, output generation, and explicit completion signals.

## Method

The core technical contribution is an MDP-based workflow generation framework that produces theoretically optimal execution plans maximizing expected success rates under known tool reliability statistics. The MDP uses a composite state representation capturing tool execution states, progress tracking, and RAG-enhanced context, with an action space of structured tool invocations. Policy optimization employs PPO with Transformer-based networks, mixed-precision training, and curriculum learning across five difficulty stages. Flawed workflow prompts are generated by injecting seven categories of systematic perturbations (ordering errors, tool misuse, parameter errors, missing steps, redundant operations, logic discontinuity, semantic drift) into MDP-optimal workflows. A probabilistic simulator computes per-execution success rates using a formula that penalizes uncalled dependencies, failed dependencies, and historical failures, enabling controlled evaluation of model robustness.

## Results

Across 7 LLMs evaluated on 5,040 tasks with 30 simulated APIs (base success rate ρ=0.8), MDP-optimal workflow prompts achieve a 62.1% average full success rate, substantially outperforming Chain-of-Thought prompts (50.8%) and baseline prompts (51.4%). Flawed workflow prompts (with systematic error injection) yield 54.3% full success, revealing that instruction quality significantly impacts performance. GPT-4o-mini leads with 67.7% full success under optimal prompts, while the Qwen2.5 series exhibits an emergent ability jump from 0.5% (3B) to 63.5% (7B) full success.

## Baselines & Comparisons

ResiliBench is a new benchmark rather than a method comparison, so the primary 'baselines' are the four prompt variants (baseline, CoT, MDP-optimal, flawed) applied uniformly across models. MDP-optimal workflow prompts consistently outperform both baseline and CoT prompts by 10–13 percentage points in full success rate, confirming that structured execution plans derived from MDP optimization provide substantial guidance. The flawed workflow comparison reveals stark model-specific robustness differences: GPT-4o-mini drops only 5.5 pp (67.7%→62.2%) while Gemini-2.5-Flash drops 40.1 pp (60.1%→20.0%), indicating that tolerance to instruction errors is a distinct capability axis. On the real-world API subset (8 tasks, 23 live APIs), the same pattern holds with GPT-4o-mini dropping 7.8 pp and Gemini-2.5-Flash dropping 21.2 pp from optimal to flawed prompts. Among open-source models, Llama-3.3-70B (66.1%) and Qwen2.5-32B (65.0%) approach proprietary model performance under optimal prompts, while DeepSeek-V3 lags at 56.8%.

## Relation to Prior Work

This paper carves new ground in the tool-use benchmark landscape by deliberately making probabilistic tool failures and instruction quality variability the primary evaluation axis, rather than filtering them out as prior benchmarks (ToolBench, API-Bank, SOP-Bench) do through curation. It repurposes MDP/RL machinery (PPO with Transformer policies, curriculum learning) to generate theoretically grounded optimal workflows, and introduces a seven-category perturbation taxonomy for systematically degrading instruction quality. The MCP-compliant tool specification and RAG-based semantic matching for task construction connect to broader agent infrastructure trends, but the core contribution is the evaluation framing: measuring robustness under controlled uncertainty rather than peak performance under ideal conditions.

## Why It Matters / Open Questions

The benchmark provides a practical diagnostic for a critical deployment gap: how well LLM agents handle imperfect instructions and unreliable tools in production. The finding that robustness to flawed instructions is a sharply differentiated capability (GPT-4o-mini drops 5.5 pp vs. Gemini-2.5-Flash drops 40.1 pp) suggests current evaluations understate model differences that matter in practice. Limitations include the small 30-tool library, the MDP 'optimal' being only optimal under a specific reward function and base success rate of 0.8, and the real-world component comprising just 8 tasks. Open questions include whether the MDP-derived workflows generalize to larger tool ecosystems, whether the robustness gaps persist with more training data or fine-tuning, and how findings transfer to truly open-ended (non-template) task generation.
