## Problem

Existing model attribution methods for closed-weight LMs either require proactive implementation by the provider (watermarks, backdoors), are easy to forge (linear signatures), or are computationally expensive (zero-knowledge proofs). The paper identifies an underexploited geometric constraint—language model outputs lie on a high-dimensional ellipse due to the normalization-then-linear-projection architecture—and shows it functions as a naturally occurring, forgery-resistant signature that no prior method has leveraged for output verification.

## Input / Output

For verification, the method takes a single centered logprob vector ℓ ∈ R^v (centered via C = I − 1/v to recover logits from logprobs) and the model's final-layer parameters (unembedding matrix W, scale γ, bias β, or equivalently the ellipse parameters A⁻, Σ, U, b), and outputs a binary verification result by checking whether the inverse affine transform maps ℓ back to the unit sphere. For ellipse extraction, the method consumes O(d²) logprob outputs from an API and recovers the full set of ellipse parameters (singular values, rotation, bias, and up-projection matrix). Notably, verification requires only the final-layer parameters, not full model weights or the input prompt.

## Method

The core insight is that RMS norm (or layer norm) constrains hidden states to a d-dimensional sphere, and the subsequent linear unembedding W(γ⊙x̂+β) is an affine map that stretches and rotates this sphere into a d-dimensional ellipse in R^v, unique to each model. Verification applies the inverse affine transform (W⁺C⁺Cℓ − β)/γ to a logprob and checks whether the result has unit L2 norm, i.e., whether it lies on the unit sphere. For extraction, the paper collects O(d²) centered logprobs, down-projects to d dimensions, fits an ellipse via semidefinite programming (Ying et al. 2012 or Lin & Huang 2016), and recovers model parameters through Cholesky decomposition and SVD of the fitted ellipse matrix. Forgery resistance arises because extraction requires O(d³ log d) API queries and O(d⁶) fitting time—prohibitively expensive for production models (e.g., ~$16M and thousands of years for a 70B model)—while verification is a single matrix-vector product. The paper further frames this as a symmetric-key message authentication code protocol where the ellipse is the secret key and logprobs are self-authenticating messages.

## Results

The ellipse signature identifies the generating model with the smallest distance to the unit sphere by several orders of magnitude across OLMo 27B, Llama 3.1, Qwen 38B, and GPT-oss (Figure 3). The practical infeasibility of forgery is quantified in Table 1: extracting the ellipse for babbage-002 (d=1536) requires ~1.18M API samples (~$1,056), for gpt-3.5-turbo (d≈4650) requires ~10.8M samples (~$150,699), and for llama-3-70b-instruct (d=8192) requires ~33.6M samples (~$16.5M). The computational cost of ellipse fitting scales as O(d⁶), with extrapolated running times of thousands of years for a 70B-scale model (Figure 6). On a 1M-parameter model (d=64), the ellipse-specific SDP fitting recovers bias, singular values, and rotation angles with high accuracy (Figure 4), confirming the method works when the model is small enough.

## Baselines & Comparisons

The ellipse signature is the only method in Table 2 that simultaneously satisfies all four properties: naturally occurring, self-contained, compact, and forgery-resistant. Compared to linear signatures (Finlayson et al. 2024; Yang & Wu 2024), which share the first three properties, the ellipse signature's key advantage is forgery resistance: linear constraints can be extracted with O(d) API queries and trivially satisfied, while ellipse extraction requires O(d³ log d) queries and O(d⁶) fitting time, making it prohibitively expensive for production models. Text-based watermarks (Kirchenbauer et al. 2023; Hou et al. 2024) are self-contained and forgery-resistant but are neither naturally occurring nor compact, requiring many generation steps for statistical detection. Backdoor fingerprints (Li et al. 2022) are neither naturally occurring nor self-contained, as they require special training and controlled inputs. The zkLLM cryptographic approach (Sun et al. 2024) is self-contained and forgery-resistant with strong guarantees but is not naturally occurring and makes inference significantly more expensive. Natural text fingerprints (Ren et al. 2025) are naturally occurring but not compact, requiring multiple generation steps to identify the source model.

## Relation to Prior Work

This paper builds on Carlini et al. (2024), who first noted in an appendix that LM outputs lie on a high-dimensional ellipse, and on the ellipse-fitting literature (Ying et al., 2012; Lin & Huang, 2016) for the computational machinery. It departs from the most closely related prior work—linear signatures (Finlayson et al., 2024; Yang & Wu, 2024)—by showing that the elliptical constraint, unlike the linear one, is computationally infeasible to forge via API queries, and by reframing the ellipse as a cryptographic-style message authentication code. The paper also positions itself against watermarking, backdoor fingerprinting, and zkLLM approaches, arguing that ellipse signatures uniquely combine natural occurrence, self-containment, compactness, and forgery resistance in a way no prior method achieves simultaneously.

## Why It Matters / Open Questions

The ellipse signature offers a verification mechanism that requires no cooperation from the model provider and no modification to the model, which is valuable for regulatory and accountability scenarios where a trusted third party must verify outputs from a closed model. However, the security guarantee is only polynomial (O(d³ log d) queries, O(d⁶) fitting time), far from cryptographic, and the practical applicability is currently limited by the scarcity of APIs that expose logprobs. Open questions include whether faster ellipse-fitting or direct-on-ellipse generation algorithms exist, whether other geometric constraints yield stronger guarantees, and how to make the signature robust to removal (e.g., quantization, temperature scaling). The MAC analogy is elegant but the 'key' (ellipse parameters) is derived from the model itself rather than independently chosen, which weakens the cryptographic parallel.
