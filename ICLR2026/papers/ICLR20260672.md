## Problem

While generative models have successfully simulated video games and dynamic visual environments, no prior work has demonstrated that a full operating system's graphical interface can be modeled as a neural generative process. The core challenges unique to OS simulation are long-term state tracking (e.g., recalling whether a folder was created hundreds of frames ago), pixel-accurate cursor rendering across a large discrete action space, and handling abrupt, unpredictable interface transitions such as application launches that can take up to 30 frames to complete.

## Input / Output

At each timestep, the model receives discretized cursor coordinates (x, y), binary left/right click indicators, a binary keyboard press/release vector, and the previously generated latent frame (64×48×16, obtained by 8× spatial downsampling of 512×384 RGB screenshots via a trained VAE). The output is the next latent frame, decoded back to a 512×384 pixel image for display. The model operates autoregressively at 15 fps, with inference at 18 fps on a single H100 GPU using 2-step DDIM sampling.

## Method

NeuralOS combines a hierarchical two-level LSTM (lower LSTM encodes user inputs and attends over the previous frame via multi-headed attention; upper LSTM processes the attention-informed representation, with feedback to the lower LSTM) that maintains a constant-size state vector, with a UNet-based latent diffusion renderer conditioned on the RNN state. A key architectural choice is a Gaussian spatial map encoding cursor positions (rather than one-hot vectors) to achieve sub-pixel cursor accuracy. Training follows a four-stage pipeline: (1) RNN pretraining with MSE loss on challenging transitions to prevent the renderer from ignoring RNN outputs, (2) joint RNN–diffusion training, (3) scheduled sampling to mitigate exposure bias, and (4) context-length extension from 32 to 64 frames. The RNN's constant per-step complexity (vs. a transformer's growing context) enables arbitrarily long inference without OOM, and the recurrent state allows the model to recall events far beyond its training context window, as demonstrated by correct folder-state recall after 256 frames.

## Results

NeuralOS achieves near-chance-level indistinguishability from a real Ubuntu XFCE desktop in human evaluation: participants correctly identify the real OS only 58.3% of the time (no crop, 10s) and 51.7% (bottom-cropped, 10s), dropping to ~50% at 20s. Cursor localization is highly accurate with the Gaussian spatial encoding (Δx=1.6, Δy=1.4 pixels, <0.5% of frame), compared to 130.0/95.8 without it. State-transition prediction reaches 37.7% cluster accuracy versus 1.4% for majority voting, and application open/close transitions achieve RMSE as low as 0.015 (Terminal close) and L1 of 0.001. Inference runs at 18 fps on a single H100 GPU using 2-step DDIM sampling.

## Baselines & Comparisons

The primary baseline is DIAMOND (Alonso et al., 2024), an action-conditioned diffusion model originally designed for Atari/CS:GO, adapted here to the OS setting with a 64-frame context, full-resolution cursor discretization, and 179-key keyboard space. Under matched compute (single B200 GPU, ~48 hours), DIAMOND produces acceptable frames before the first abrupt state transition (e.g., opening Home) but generation quality collapses afterwards; even with scheduled sampling fine-tuning (p=0.05, +50k steps), it still fails to execute application-launch transitions. NeuralOS, by contrast, maintains substantially lower pixel RMSE over longer horizons (Figure 8) and successfully opens and closes applications, owing to its recurrent state that generalizes beyond the 64-frame training context. The key architectural advantage is that DIAMOND's fixed context window cannot represent long-term state (e.g., whether a folder was created 256 frames ago), while NeuralOS's hierarchical RNN retains such information indefinitely, as confirmed by the folder-presence experiment (62% recall at 256-frame gap vs. 8-frame training delay).

## Relation to Prior Work

NeuralOS extends the interactive video generation line (GameNGen, DIAMOND, Genie) from video games to full operating system GUIs, but departs fundamentally in two ways: it replaces short-context-window diffusion with a hierarchical RNN for persistent state tracking (since OS state like 'a folder was created 200 frames ago' is not visually observable in recent frames), and it introduces a Gaussian spatial encoding for cursor positions to handle the much larger discrete action space of a desktop. Unlike code-generation approaches (Prompt-to-OS, Gemini OS, Lambda NeuralOS) that produce HTML or structured UI elements rendered by an existing engine, NeuralOS directly generates pixel-level frames end-to-end. The multi-stage training pipeline (RNN pretraining → joint diffusion training → scheduled sampling → context extension) is tailored to OS-specific challenges like delayed application launches and exposure bias over long interaction sequences.

## Why It Matters / Open Questions

This is the first working end-to-end neural simulation of an OS graphical interface, and the Doom experiment demonstrates a broader principle: synthetic demonstrations, once distilled into a generative model, become usable interfaces even for applications that were never installed. This opens a path toward safe training environments for computer-use agents and toward fully generative, adaptive user interfaces. However, significant limitations remain: the system requires an H100 GPU, operates at low resolution (512×384), reliably supports only four applications, and struggles with fine-grained keyboard inputs. Open questions include scaling to richer OS environments (Windows, macOS), enabling interaction with external resources (internet, file systems), and reducing inference cost to practical levels.
