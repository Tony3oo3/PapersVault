## Problem

Current LLMs are architecturally stateless and passive: they accumulate tokens monotonically within a fixed context window and cannot actively prune, reorganize, or manage their own reasoning state. Existing context-engineering approaches (RAG pipelines, agentic memory frameworks like MemGPT, Context-Folding, ReSum) all keep the model as a passive component while a human-designed workflow dictates when and how context is managed. This paper asks what happens when the model itself is trained to be its own context engineer, deciding dynamically what to read, what to remember, and what to forget.

## Input / Output

StateLM receives a user query alongside a long document, multi-turn dialogue history, or iterative search results, and must produce a final answer (multiple-choice or open-ended) while operating under a strict 32K active context budget and 150-round interaction limit. Unlike standard LLMs that passively consume the full input, StateLM incrementally ingests content via readChunk and searchEngine, distills key information into persistent notes via updateNote, and prunes raw text from its visible context via deleteContext, maintaining a compact 'sawtooth' context profile rather than monotonic accumulation. The output is both the final answer (submitted via a finish tool call) and the evolved interaction state, where previously visible messages are replaced with stubs after deletion.

## Method

StateLM extends the standard agentic loop by replacing the append-only state evolution with a mutable state-evolution function F that can remove historical elements from the model's visible context. The model is equipped with a general-purpose 'spellbook' of tools spanning context perception (analyzeText, checkBudget), information acquisition (buildIndex, searchEngine, readChunk), memory management (note/updateNote, readNote, deleteContext), and termination (finish). Training proceeds in two stages: first, supervised fine-tuning on 35.7K samples derived from 3.3K expert trajectories generated by Claude Opus 4.1, filtered by outcome-based and process-based reject sampling with action balancing; second, reinforcement learning using a GRPO-style objective with trajectory snapshots (captured at each context-editing action), uniform snapshot sampling per trajectory to control variance, and a three-tier outcome reward (+1 correct, −0.5 incorrect, −1 unformatted/unfinished). The key insight is that the model learns to strategically coordinate reading, note-taking, and deletion into a self-sustaining reasoning loop, rather than following a fixed summarization schedule or branching routine.

## Results

On long-document QA (NovelQA, ~135K tokens), StateLM-14B-RL achieves 84.85% accuracy using only 32K active context, compared to 77.94% for Qwen3-14B at 128K context. On the deep research benchmark BrowseComp-Plus (~552K tokens), the gap is dramatic: StateLM-14B-RL reaches 52.67% accuracy while Qwen3-14B manages only 5.46%, a >47-point improvement. On chat memory (LongMemEval-S, ~115K tokens), StateLM-14B-RL scores 64.47% versus 54.07% for Qwen3-14B. On the synthetic Needle-in-a-Haystack task, StateLM-14B maintains 83.89% accuracy at 2M context length while Qwen3-14B drops to 1.7%.

## Baselines & Comparisons

Against Qwen3 instruct models (Yang et al., 2025), StateLM wins on every benchmark at every model scale while using only 1/4 the context window (32K vs. 128K). The largest relative gains appear on BrowseComp-Plus, where StateLM-14B-RL (52.67%) outperforms Qwen3-14B (5.46%) by over 47 points, and on LongMemEval where StateLM-4B (59.33%) beats Qwen3-4B (39.53%) by ~20 points. Against MemAgent (Yu et al., 2025), which is also RL-trained and uses 32K context, StateLM-14B-RL leads on NovelQA (84.85% vs. 78.86%), ∞Bench (78.46% vs. 74.24%), and LongMemEval (64.47% vs. 59.00%). Against ReadAgent (Lee et al., 2024), a prompting-based gist-memory agent, StateLM dominates by wide margins (e.g., 84.85% vs. 23.12% on NovelQA for the 14B variants). Notably, even the much larger Qwen3-235B equipped with the Pensieve framework (256K context) is outperformed by StateLM-14B-RL on NovelQA and ∞Bench, suggesting that learned context management at smaller scale can rival brute-force scaling.

## Relation to Prior Work

This paper departs from the dominant 'human as wizard' paradigm in long-context management—exemplified by RAG pipelines, MemGPT/MemOS memory hierarchies, and RL-trained agents like MemAgent, Context-Folding, and ReSum—where context management logic is hard-coded into human-designed workflows or fixed schedules. StateLM instead equips the model with a general-purpose toolkit (deleteContext, readChunk, updateNote, searchEngine) and trains it via SFT from expert trajectories followed by GRPO-based RL to autonomously decide when and how to prune, distill, and retrieve. Conceptually, it repurposes the agentic tool-use framework and trajectory-based RL (GRPO) but redirects them toward self-managed context state rather than external task actions, making the interaction state mutable rather than append-only.

## Why It Matters / Open Questions

The 'sawtooth' context profile—maintaining a compact 32K working window while processing inputs up to 2M tokens—offers a practical path to long-context reasoning without requiring ever-larger context windows, which is both a compute and architectural win. The cross-domain generality (long-doc QA, multi-turn chat memory, deep research) without task-specific tuning suggests the learned context-management skill is genuinely transferable. Key limitations include the reliance on BM25 keyword search (weak for implicit/paraphrased queries), accumulation of deletion stubs over very long trajectories, and the observation that smaller models still struggle with reliable context budget management. Open questions include whether more advanced semantic retrieval, larger management windows, and longer-horizon training data can close the remaining gaps, and whether the paradigm scales to frontier-scale models.
