## Problem

GUI agents face two coupled challenges: (1) planning over an expansive action space where many valid action sequences exist but the environment lacks a 'lookahead' capability (actions are often irreversible), making it hard to commit to a single plan; and (2) grounding actions to precise visual elements in high-resolution, complex interfaces, where standard SFT misaligns with the task by penalizing any coordinate that is not the exact center of the target element, even though any point within the element constitutes a valid click.
![Teaser figure](../imgs/ICLR20261647/cropped_page1_idx0.webp)

## Input / Output

The grounding model receives a GUI screenshot (resized so dimensions are divisible by 28, supporting up to 3840×2160 resolution) paired with a textual action proposal (e.g., 'click the blue Submit button') and outputs a single (x, y) pixel coordinate directly, with no intermediate chain-of-thought or bounding-box prediction. The full agent additionally consumes the user instruction and past trajectory at each step; the planner samples K candidate action proposals (default K=8), and a multimodal LLM judge selects one, after which the grounding model resolves coordinate-based actions to precise click points while non-coordinate actions (key presses, text input) execute directly.

## Method

GTA1 combines two strategies. For planning, it applies test-time scaling: at every step the planner concurrently samples K candidate action proposals, and a multimodal LLM judge scores them against the user intent and current GUI state to select the most appropriate one, trading inference compute for robustness without requiring full-sequence rollouts. For grounding, it trains a multimodal LLM with GRPO reinforcement learning where the model directly predicts a (x, y) coordinate and receives a binary reward (1 if the point falls inside the annotated bounding box, 0 otherwise), with Z-score-normalized advantages driving the policy update. A lightweight data-cleaning step uses OmniParser to detect UI elements and discards training samples whose annotated bounding box has IoU below τ=0.3 with any detected element, filtering misaligned annotations. Ablations show that this simple click-only reward outperforms combinations with IoU or format (CoT) rewards, and that explicit 'thinking' is unnecessary in static environments but can help in dynamic settings when past trajectories are provided.

## Results

On the ScreenSpot-Pro benchmark (the most challenging, targeting high-resolution professional GUIs), GTA1-32B achieves 63.6% average grounding accuracy, outperforming all prior methods including UI-TARS-1.5-7B (42.0%) and Qwen2.5-VL-32B (47.6%). On ScreenSpot-V2, GTA1-32B reaches 95.2% average accuracy, matching the proprietary Seed-1.5-VL. On OSWorld-G, GTA1-32B sets a new state-of-the-art at 72.2% grounding accuracy. For agent task execution, GTA1-32B with GPT-5 as planner achieves 63.4% success rate on OSWorld-Verified and 51.2% on WindowsAgentArena, surpassing all prior methods.

## Baselines & Comparisons

On ScreenSpot-Pro, GTA1-32B (63.6%) surpasses the strongest open-source baseline UI-TARS-1.5-7B (42.0%) by 21.6 points and the proprietary Seed-1.5-VL (60.9%) by 2.7 points; GTA1-7B (50.1%) already exceeds UI-TARS-1.5-7B by 8.1 points despite being the same base model. On ScreenSpot-V2, GTA1-32B (95.2%) ties the proprietary Seed-1.5-VL (95.2%) and beats Qwen2.5-VL-72B (94.0%) and UI-TARS-7B (91.6%). On OSWorld-G, GTA1-32B (72.2%) outperforms OpenCUA-32B (70.2%) and UI-TARS-1.5-B (64.2%). For agent task execution on OSWorld-Verified, GTA1-32B with GPT-5 (63.4%) beats CoAct-1 (60.8%) and Agent S2.5 with GPT-5 (58.4%), while GTA1-7B with o3 (53.1%) exceeds the native CUA o3 agent (42.9% on OSWorld with 200 steps) using only 100 steps. On WindowsAgentArena, GTA1-32B with o3 (51.2%) more than doubles the prior best Jedi-7B (33.7%).

## Relation to Prior Work

GTA1 builds on the GRPO reinforcement learning framework (Shao et al., 2024; Guo et al., 2025a) and initializes from UI-TARS-1.5-7B and OpenCUA-32B, but deliberately departs from the prevailing RL-based GUI grounding paradigm (GUI-R1, UI-R1, InfiGUI-R1, GUI-G1) that couples click rewards with explicit CoT 'thinking' and auxiliary IoU/format rewards. The paper's core methodological departure is showing that a bare click-within-bounding-box reward, without any reasoning chain or bounding-box prediction, suffices for state-of-the-art grounding. On the planning side, the test-time scaling strategy (sample K proposals, judge-select one) is novel for GUI agents and draws an analogy to test-time compute scaling in LLMs, but applied to the irreversible, stateful setting of GUI interaction where full-sequence lookahead is infeasible.

## Why It Matters / Open Questions

The paper challenges two working assumptions in the GUI agent community: that CoT reasoning is necessary for RL-based grounding, and that native end-to-end agents are inherently superior to two-stage planner+grounding decompositions. The test-time scaling technique is practically valuable because it generalizes across base agents (demonstrated on UI-TARS-1.5-7B) and reduces wall-clock time by sampling candidates concurrently. Open questions include whether the click-reward-only approach transfers to tasks requiring spatial reasoning beyond point prediction (e.g., drag-and-drop trajectories), and whether the judge model's selection quality degrades as K grows in highly ambiguous UI states. The authors acknowledge residual failures on professional tools (e.g., GIMP layer manipulation), suggesting the grounding model still lacks fine-grained semantic understanding of domain-specific interfaces.
