## Problem

Supervised fine-tuning for chart-to-code generation hits a performance plateau that cannot be overcome by simply scaling data volume, and existing RL approaches for chart understanding have not been adapted to the structured, code-specific nature of this task. The paper identifies this SFT bottleneck through systematic experiments and asks how to break it with RL strategies tailored to structured code outputs.
![Teaser figure](../imgs/ICLR20263874/cropped_page1_idx1.webp)

## Input / Output

The model takes a single chart image (covering 24 chart types including bar, line, heatmap, 3D, multi-axes, etc.) as input and produces executable Python Matplotlib code as output. The generated code must define data arrays, select appropriate plot functions, and specify styling parameters (colors, labels, layout) such that rendering it reproduces the input chart. The training corpus spans 3M chart-code pairs sourced from real arXiv tables, with a curated 33k subset for RL after multi-stage filtering for code diversity and visual fidelity.

## Method

MSRL employs a two-stage curriculum RL strategy on top of a saturated SFT model (Qwen2.5-VL-7B). Stage 1 optimizes with a rule-based textual reward that scores data values (soft matching with ±5% tolerance), chart types (hard string match), layout (hard value match), and titles/labels (edit distance), plus a binary execution reward. Stage 2 introduces a visual reward by rendering the generated code into an image and scoring its similarity to the ground-truth chart using Qwen2.5-VL-72B across six dimensions (chart type, layout, text, data, style, clarity). The total reward is a weighted sum R = w_t·R_text + w_v·R_vis + w_e·R_exec, optimized via GRPO. A code normalization step maps stylistically diverse outputs to a canonical form before reward computation, ensuring invariance to syntactic variation.

## Results

MSRL (7B) achieves a new state-of-the-art among all open-source MLLMs on both ChartMimic and ReachQA benchmarks. On ChartMimic, it reaches 96.5% execution rate, 78.6 low-level score, and 83.8 high-level score; on ReachQA, it achieves 98.2% execution rate, 86.1 low-level, and 89.9 high-level. The two-stage MSRL strategy improves high-level scores by 6.2% over its SFT-only variant (MSRL-SFT) on ChartMimic and by 9.9% on ReachQA, effectively breaking the SFT performance plateau that saturates beyond ~2M training samples.

## Baselines & Comparisons

MSRL outperforms all open-source chart-domain baselines by large margins: on ChartMimic high-level score it beats ChartCoder (74.0) by 9.8 points, Chart2Code (33.3) by 50.5 points, and ChartVLM-L (13.9) by 69.9 points. Against the strongest proprietary model GPT-4o, MSRL matches or exceeds it on most metrics—achieving a higher execution rate (96.5 vs 93.2) and high-level score (83.8 vs 83.5) on ChartMimic, and surpassing it on all three ReachQA metrics (98.2/86.1/89.9 vs 92.8/81.8/84.0). Compared to the base Qwen2.5-VL-7B model, MSRL improves ChartMimic high-level score from 41.6 to 83.8 (+42.2) and ReachQA high-level from 37.6 to 89.9 (+52.3). Even the SFT-only variant (MSRL-SFT) already surpasses all prior open-source chart-domain models, with the RL stage providing the additional 6.2% (ChartMimic) and 9.9% (ReachQA) high-level gains that close the gap to GPT-4o. MSRL also generalizes to unseen plotting libraries (Seaborn, Plotly), improving execution rate from 69.2% to 85.1% on Seaborn and from 62.7% to 90.0% on Plotly over the base model.

## Relation to Prior Work

This paper extends the RL-for-reasoning paradigm (GRPO, RLVR) from textual and general visual reasoning to the specific challenge of structured code generation from charts. It departs from prior chart-to-code work (ChartCoder, Chart2Code) that relied on SFT or DPO over synthetic data, instead introducing a multi-granularity reward system that combines rule-based textual validation with MLLM-based visual fidelity scoring. The two-stage curriculum (textual rewards first, then hybrid textual+visual) draws on the efficiency considerations in MM-EUREKA and the visual feedback ideas in rendering-aware RL, but applies them specifically to the structured-output constraint of plotting code.

## Why It Matters / Open Questions

The systematic demonstration that SFT plateaus at ~2M samples for chart-to-code generation, and that only 33k RL samples can break through, provides a concrete data-efficiency argument for RL in structured code tasks that practitioners can act on. The 3M-pair dataset from real arXiv tables is the largest for this domain and addresses the synthetic-data limitations of prior work. Open questions include whether the approach generalizes beyond Matplotlib (Seaborn/Plotly scores remain modest), whether the 72B visual judge introduces reward-hacking vulnerabilities at scale, and whether the multi-granularity reward design transfers to other structured-output tasks like SVG or HTML generation.
