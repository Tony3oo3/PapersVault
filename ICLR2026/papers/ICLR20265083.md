## Problem

Existing RLVR methods for code generation rely solely on outcome rewards, leaving self-verification unoptimized and unreliable. This causes models to produce verbose or random reflections on hard problems and limits test-time scaling, as reasoning performance plateaus once inference turns exceed the training horizon. The paper asks whether explicitly optimizing verification as a first-class target can widen the verification-generation asymmetry and enable sustained multi-turn refinement without pre-existing test suites.

## Input / Output

The model receives a natural-language programming problem description and, at each subsequent turn, tool execution feedback (runtime errors, actual vs. expected outputs, pass/fail judgments) from a Python interpreter. Outputs are structured into alternating generation and verification segments: executable Python code enclosed in <generation-answer> tags and self-constructed test cases (with inputs and expected outputs) in <verification-answer> tags. During training, the tool-feedback section is excluded from the loss and used only as contextual input; during inference, all generated tests are executed autonomously without any golden reference.

## Method

ReVeal structures long-horizon reasoning as an iterative generation-verification loop using a single shared policy, where each turn produces candidate code and self-constructed tests that are executed via an external Python interpreter. Training uses three complementary rewards: an outcome reward (format compliance plus final pass rate), a generation reward rewarding pass-rate improvement over the previous generation turn (abs=0, imp=1), and a verification reward measuring the fraction of generated tests that pass on a golden solution. The key algorithmic contribution is Turn-Aware Policy Optimization (TAPO), which augments standard PPO by replacing GAE advantages with a combined return that sums a token-level Monte Carlo return (outcome reward only) and a turn-level return with asymmetric credit assignment: each generation reward is routed to both its own generation turn and the immediately preceding verification turn, while each verification reward is confined strictly to its own verification turn. This design prevents reward gaming (e.g., trivial code hacking verification rewards) and creates a co-evolutionary feedback loop where stronger tests expose more failure modes, driving code improvements that in turn raise the bar for test quality.

## Results

On LiveCodeBench V6, ReVeal×25 achieves 38.7% Pass@1, surpassing the single-turn RL baseline (32.8%) by 5.9 points and the DAPO-Qwen-32B base model (31.1%) by 7.6 points. On CodeContests, ReVeal×25 reaches 33.6% Pass@1, a 12.6-point improvement over single-turn RL (21.0%). ReVeal achieves near-zero degradation (Δ↓ = 0.0) while correcting 7.50% (LCB) and 15.69% (CodeContests) of initially wrong solutions. In Pass@k evaluation (k up to 128), ReVeal consistently outperforms both the base model and the RL baseline across all k values, indicating it expands the base model's reasoning boundaries.

## Baselines & Comparisons

Against the DAPO-Qwen-32B base model, ReVeal×25 improves Pass@1 by 7.6 points on LiveCodeBench V6 (38.7% vs. 31.1%) and by 15.1 points on CodeContests (33.6% vs. 18.5%). Compared to the single-turn RL baseline (outcome-only reward, no tool use), ReVeal gains 5.9 points on LCB V6 and 12.6 points on CodeContests, and also achieves a higher Pass@1 at turn 1 (34.8% vs. 32.8%), showing that multi-turn training transfers exploration benefits into a stronger single-turn policy. Against the critic-based CTRL method, ReVeal outperforms by 5.3 points on LCB V6 (38.7% vs. 33.4%) while achieving near-zero degradation (Δ↓ = 0.0 vs. 0.89) and a substantially higher correction rate (Δ↑ = 7.50 vs. 3.75), demonstrating that a single self-verifying policy surpasses a separate critic model. In the Pass@k analysis, ReVeal (max_turn=10) consistently outperforms both the base model and the RL baseline across all k from 1 to 128, whereas the RL baseline's advantage over the base model diminishes and vanishes at larger k, confirming that ReVeal expands the reasoning boundary beyond what standard RL achieves.

## Relation to Prior Work

ReVeal builds on the PPO actor-critic framework and the RLVR paradigm (DAPO, DeepSeek-R1) but departs from the outcome-only reward design by introducing turn-level credit assignment (TAPO) that explicitly optimizes both generation and verification. It positions itself against critic-based multi-turn methods (CTRL) by showing a single shared policy can outperform separate generator-critic pairs, and against tool-augmented RL (Search-R1, ReTool, ToRL, RLEF) by treating verification as a first-class optimization target rather than a passive feedback channel. The conceptual grounding in the verification-generation asymmetry (Wei, 2025; Setlur et al., 2025) provides the theoretical motivation: widening the V-G gap through explicit verification training enables deeper test-time scaling.

## Why It Matters / Open Questions

The finding that a model trained on only 3 reasoning turns sustains improvement through 25+ inference turns, while simultaneously expanding Pass@k beyond the base model's reasoning boundary (something outcome-only RL fails to achieve), suggests a practical path to compute scaling for code agents without retraining. The TAPO algorithm and joint verifiable reward design are general-purpose components applicable to any domain with verifiable generation-verification asymmetry, not just code. Key limitations include the focus on functional correctness only (no efficiency or complexity constraints), the dependence on golden solutions during training for test-case filtering, and the open question of whether the V-G widening principle transfers to domains where verification is as hard as generation.
