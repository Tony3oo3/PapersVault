## Problem

Prior work suggests retrieval offers no benefit—or even hurts performance—on reasoning-intensive benchmarks like MMLU, GPQA, and MATH, largely because existing datastores are either too narrow (Wikipedia) or impractically large (12TB+ RAM for web-scale). This paper identifies the missing component as a usable, web-scale datastore that matches the breadth of pretraining data while remaining deployable on a single node.

## Input / Output

The pipeline takes a natural-language question as input and produces a generated answer via an LLM. At retrieval time, the query is encoded by two different models: Contriever-MSMARCO (768-dim) for the ANN stage and GritLM-7B (4096-dim) for the exact re-ranking stage. The top-k retrieved passages (default k=3, up to k=10) are concatenated in reverse relevance order—most relevant passage closest to the query—and prepended to the question before generation. For GPQA and MATH, chain-of-thought prompting is used; for MMLU, MMLU Pro, and AGI Eval, multiple-choice formatting with 5 demonstrations is applied.

## Method

COMPACTDS is a 380.5-billion-word, 1.9-billion-passage datastore built from 12 diverse sources (filtered Common Crawl, Wikipedia, books, educational text, math corpora, academic papers, GitHub, Stack Exchange, Reddit, PubMed, ArXiv), aggressively filtered to reduce Common Crawl from 894B to 172B words while preserving coverage. The retrieval pipeline is two-stage: first, in-memory IVFPQ approximate nearest neighbor search using Contriever-MSMARCO embeddings (fitting in 456GB RAM) retrieves K candidates (K=1000); second, exact inner product search using the more expressive GritLM-7B embeddings stored on disk re-ranks those K candidates to produce the final top-k. This design decouples the fast, memory-efficient ANN stage from the higher-fidelity exact search stage, allowing a 7B-parameter encoder for re-ranking without requiring its 4096-dim vectors to be indexed in RAM. The key empirical finding is that no single data source suffices—diversity across web, educational, math, and academic sources is critical—and that the two-stage approach with complementary encoders outperforms using either model alone for both stages.

## Results

Using Llama 3.1 8B Instruct, COMPACTDS with a minimal RAG pipeline (ANN + exact search, k=10) achieves 55.1% average accuracy across MMLU, MMLU Pro, AGI Eval, MATH, and GPQA, a 14.1% relative gain over no retrieval (48.3%). Headline improvements include +33.4% on MMLU Pro (39.8→53.1), +19.2% on MATH (46.9→55.9), +11.8% on MMLU (68.9→77.0), and +14.1% on GPQA (26.7→32.4 Physics). Gains persist at 70B scale (Llama 3.3 70B: MMLU Pro 57.8→65.4, MATH 72.3→77.0) and across model families (Mistral 7B, Qwen3 8B, QwQ 32B). Oracle reranking from 100 candidates further lifts the average gain to 16.2%, surpassing the 70B no-retrieval baseline.

## Baselines & Comparisons

Against MASSIVEDS (Shao et al., 2024), the only prior open-source web-scale datastore, COMPACTDS outperforms on MMLU (75.3 vs. 73.6 accuracy) while requiring only 0.5 TB of RAM versus MASSIVEDS's 12.4 TB—a 4× memory reduction that enables single-node, subsecond deployment. Against Search-o1 (Li et al., 2025b), an agentic RAG system built on Google Search and QwQ 32B, COMPACTDS's minimal RAG matches or exceeds the full agentic pipeline: on MATH-500, COMPACTDS RAG scores 93.2 vs. Search-o1's 86.4, and on GPQA Diamond both achieve 63.1 (tied with Search-o1's 63.6 within margin). Against Google Search as a retrieval backend, COMPACTDS yields a 14% average relative improvement over no retrieval versus only 6% for the search engine, with the gap most pronounced on MMLU Pro (53.1 vs. 42.8). The paper also shows that no single data source in COMPACTDS suffices alone—each individual source (Wikipedia, Math, Educational Text, etc.) provides only 1–5% gains, whereas the full diverse combination is necessary for the reported improvements.

## Relation to Prior Work

This paper departs from the prevailing view in the RAG literature that retrieval is ineffective or even harmful for reasoning-intensive tasks (BehnamGhader et al., 2022; Geng et al., 2024), arguing instead that the bottleneck was the datastore rather than the retrieval paradigm itself. It builds on the two-stage approximate-then-exact retrieval design inspired by DiskANN (Jayaram Subramanya et al., 2019) and IVFPQ (Jégou et al., 2010), but applies them to a carefully curated, multi-source web-scale corpus (COMPACTDS) that bridges the gap between narrow Wikipedia-based stores and the impractically large MASSIVEDS (Shao et al., 2024, 12.4TB RAM). Unlike agentic RAG systems (Search-o1, R1-Searcher) that rely on external web search engines or complex multi-step pipelines, this work demonstrates that a minimal dense-retrieval-then-generate pipeline suffices when the datastore is well-designed.

## Why It Matters / Open Questions

COMPACTDS is the first web-scale retrieval datastore deployable on a single node (456GB RAM) with subsecond latency, making high-quality retrieval accessible to academic labs without distributed infrastructure. The finding that a simple in-house datastore matches or outperforms Google Search across reasoning benchmarks is practically significant, offering a reproducible, self-contained alternative to non-deterministic commercial APIs. Open questions remain: GPQA shows no gain at 70B scale (possibly due to strong CoT capabilities saturating the benefit), oracle reranking reveals substantial headroom (16.2% vs. 8.0% average gain), and integration with agentic pipelines or training-with-retrieval is left for future work. The released datastore and pipeline position this as a foundational resource for the growing field of retrieval-based AI systems.
