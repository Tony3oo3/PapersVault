## Problem

Prompt-based control of LLMs is inherently inefficient: long instructions must be re-processed for every query, consume the limited context window, and scale poorly due to quadratic self-attention costs. Retrieval-augmented memory systems (RAG, MemGPT) mitigate this by fetching relevant text at inference time, but retrieved content remains explicit text that must be repeatedly interpreted, reintroducing the same overhead. The paper asks whether reusable task procedures can be distilled into compact, parameter-isolated representations that support continual acquisition without catastrophic forgetting.

## Input / Output

At inference, TokMem takes a natural-language query and first routes it to one or more memory tokens via a softmax over the memory bank conditioned on the query's final hidden state; the selected token(s) are then appended to the query before auto-regressive generation. For atomic tasks the output is a single task-specific text response; for compositional function-calling, the model chains multiple memory tokens sequentially (e.g., parse → search → format), producing a sequence of tool calls with arguments. The key constraint is that the backbone LLM remains entirely frozen—only the small set of memory-token embeddings (on the order of 0.1–0.2M parameters) is trainable.

## Method

TokMem adds *l* special tokens to the vocabulary, each represented by a trainable d-dimensional embedding that encodes one reusable procedure; the backbone LLM and all pre-trained text embeddings stay frozen. Training uses standard next-token prediction on sequences laid out as [query, memory_token, response, memory_token, response, …], with the loss applied only to memory-token and response positions, so each embedding learns to both index its procedure and steer generation. At inference, the model predicts a distribution over memory tokens from the query's final hidden state (routing), selects the most probable token, and generates conditioned on it; for multi-step tasks it recursively predicts additional tokens after each response segment, enabling modular composition. A lightweight renormalization step rescales newly added embeddings to match the mean ℓ₂ norm of existing ones, preventing norm inflation that would otherwise suppress retrieval of older memories. The memory tokens use an infix placement (query ⊕ MEM ⊕ response) rather than the conventional prefix, which the paper shows converges faster and achieves lower perplexity in low-token regimes.

## Results

On atomic recall over 1,000 Super-Natural Instructions tasks (ROUGE-L), TokMem achieves average scores of 50.7 (Qwen 0.5B), 62.9 (Llama 3B), and 67.0 (Llama 8B), consistently outperforming LoRA fine-tuning (45.2/60.4/64.7) and RAG (40.7/47.3/50.9) across all model scales. On compositional function-calling (APIGen), TokMem with adaptation reaches 99.1% tool-selection F1 and 89.3% argument F1 on Llama 8B using only 0.20M trainable parameters, surpassing LoRA fine-tuning (98.1%/87.6%) which requires 3.41M parameters. Memory routing accuracy stays above 94% even at 1,000 tasks, while the Sentence-BERT retriever used in RAG drops below 80%.

## Baselines & Comparisons

Against RAG (Lewis et al., 2020), TokMem wins decisively: RAG degrades sharply as task count grows (e.g., 60.0→39.9 ROUGE-L on Llama 3B from 10 to 1,000 tasks), while TokMem stays stable (68.0→61.5); the Sentence-BERT retriever's routing accuracy also falls to 79.7% at 1,000 tasks versus TokMem's 96.1%. Against LoRA fine-tuning (Hu et al., 2022), TokMem achieves higher average ROUGE-L on SNI (50.7 vs. 45.2 on Qwen 0.5B; 67.0 vs. 64.7 on Llama 8B) and, on APIGen, matches or exceeds fine-tuning's tool-selection and argument F1 while using an order of magnitude fewer trainable parameters (0.20M vs. 3.41M on Llama 8B). Against Replay Memory (Mnih et al., 2015), TokMem edges out the replay-augmented fine-tuning on SNI (50.7 vs. 48.7 on Qwen 0.5B; 67.0 vs. 66.5 on Llama 8B) and shows far less catastrophic forgetting in the continual tool-acquisition setting (Figure 3). Against ICL (Brown et al., 2020), TokMem substantially outperforms in-context learning on compositional function-calling (e.g., 99.1% vs. 76.0% tool-selection F1 on Llama 8B) without consuming context window. Against prefix-tuning (Li et al., 2021), TokMem's infix placement converges ~30% faster and achieves lower perplexity with a single memory token on the Fanfics memorization task, and yields higher compliance and exact-match accuracy on GSM8K, especially in low-data regimes.

## Relation to Prior Work

TokMem sits at the intersection of prompt tuning, retrieval-augmented generation, and parameter-efficient fine-tuning, but departs from all three by encoding each reusable procedure into a single trainable embedding token while keeping the backbone frozen. Conceptually it draws on the cognitive-science distinction between declarative and procedural memory (Anderson & Lebiere, 1998), repurposing the prompt-tuning idea of learnable embeddings but adding a routing mechanism and infix placement that prior prompt-tuning work (Lester et al., 2021; Li & Liang, 2021) did not explore. Unlike RAG systems (Lewis et al., 2020; MemGPT) that re-read text at inference, or LoRA-based fine-tuning that entangles procedures in shared adapter weights, TokMem achieves parameter isolation per procedure, enabling modular composition and continual addition without interference.

## Why It Matters / Open Questions

The constant-size per-procedure overhead and parameter isolation make TokMem a practical building block for agent systems that must accumulate skills over time without degrading earlier ones, and the compositional generalization result (trained on single tool calls, tested on multi-call chains) suggests discrete token representations support recombination more naturally than continuous parameter updates. Key limitations include the need for manually curated procedure-response pairs, a one-time adaptation phase for compositional use, and evaluation only on models up to 8B parameters. Open questions raised by the authors include automating query-to-procedure decomposition via teacher LLMs, incorporating reinforcement learning for richer composition, and enabling user-specific memory banks for personalization.
