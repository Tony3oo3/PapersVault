## Problem

Multi-Agent Systems (MAS) suffer from two intertwined failures as they scale: error propagation (a single hallucinated observation poisons all downstream agents) and economic inefficiency (repetitive action loops and verbose tool outputs inflate token costs). Existing robustness work is reactive (post-hoc failure attribution), and efficiency work targets static design-time choices (architecture pruning, prompt compression), leaving a gap for proactive, real-time process control that intervenes at critical junctures without modifying the base agent architecture.

## Input / Output

The SUPERVISORAGENT intercepts every ActionStep object (containing the agent's thought, tool calls, observations, and error flag) via a callback mechanism. A lightweight, LLM-free adaptive filter first decides whether supervision is warranted using three heuristic triggers checked in priority order: explicit error, inefficient behavior (detected via a loop window τ_loop and periodic step check τ_step), and excessive observation length (threshold τ_len, default 3000 chars). When triggered, the supervisor consumes a context window W = (agent name, global task, local task, local trace, step summary) — augmented with the global trace T_g for inefficiency diagnosis — and emits a structured JSON containing one of four actions: approve, correct_observation (full replacement of the raw observation), provide_guidance (appended directive hint), or run_verification (delegates to a dedicated verification sub-agent).

## Method

SUPERVISORAGENT is a non-intrusive meta-agent that adds a supervisory layer on top of any existing MAS without altering the base agents' code. Its architecture is organized around three design axes: (1) What to supervise — the three high-risk interaction channels (agent-agent, agent-tool, agent-memory) where errors and inefficiencies originate; (2) When to supervise — a prioritized, LLM-free adaptive filter that avoids the prohibitive cost of monitoring every step, using only simple heuristics (error flag, repeated tool-call detection over a sliding window, observation length threshold); (3) How to supervise — a memory-augmented context window granting the supervisor a holistic view beyond any single agent, combined with a multi-level action space where intervention intensity scales with issue severity (from a minimal 'approve' nudge to a full 'run_verification' sub-agent invocation). The key distinction from prior work is that this is a runtime process-control mechanism orthogonal to design-time architecture optimization or message-level context compression, and it is both model-agnostic (validated with GPT-4.1, Gemini-2.5-pro, Qwen3-235B) and MAS-agnostic (integrated into Smolagent, AWorld via MCP, and OAgents). On the GAIA benchmark, it achieves a 29.68% average token reduction at pass@1 while maintaining the baseline success rate, with savings reaching 50.13% on the most token-intensive task subset.

## Results

On the GAIA validation set, SUPERVISORAGENT integrated with Smolagent (SMAS) reduces average token consumption by 29.68% at pass@1 (527.76K → 371.12K) while maintaining the same 50.91% success rate; at pass@3, it further improves accuracy to 63.03% (+1.21%) while cutting tokens by 26.45%. Across five additional benchmarks, SMAS achieves a Pareto improvement on AIME (36.67% vs. 30.00% solve rate, −18.92% tokens), GSM-Hard (75.50% vs. 74.33%, −8.92% tokens), and HumanEval (92.68% vs. 92.07%, −23.74% tokens), with modest token savings on MBPP (−6.62%) and DROP (−5.60%). The supervisor's own overhead accounts for only 15.45% of the baseline's total token budget, and latency increases by less than 1.5 minutes per task.

## Baselines & Comparisons

Against the primary baseline Smolagent, SMAS matches or exceeds accuracy on all benchmarks while consistently reducing token costs (29.68% on GAIA pass@1, up to 23.74% on HumanEval). Compared to OWL, SMAS achieves higher accuracy on GSM-Hard (75.50% vs. 72.48%), AIME (36.67% vs. 33.33%), and HumanEval (92.68% vs. 90.74%) with far lower token consumption (e.g., 31.19K vs. 31.87K on HumanEval, but 10.55K vs. 15.67K on GSM-Hard). Against OAgents, SMAS reduces average token consumption by 39.36% while maintaining identical 46.67% accuracy on the GAIA subset. When integrated into AWorld, SMAS(AWorld) achieves 36.67% accuracy versus 30.00% for AWorld-with-Guard and 23.33% for AWorld-without-Guard, while saving 36.54% tokens over the Guard-enabled version. SMAS substantially outperforms the CoT SC(3-shot) and MetaAgent baselines across all five secondary benchmarks in both accuracy and token efficiency (e.g., 92.68% vs. 77.78% on HumanEval vs. CoT SC, and 92.68% vs. 74.08% vs. MetaAgent). The only minor accuracy drops occur on MBPP (−1.25%) and DROP (−1.28% F1), attributed to occasional over-compression during observation purification.

## Relation to Prior Work

This paper carves out a distinct niche between two established lines of MAS research: post-hoc failure attribution (Aegis, SHIELDA, AgenTracer) and design-time efficiency optimization (AgentDropout, SafeSieve, MetaAgent). Rather than analyzing failures after the fact or pruning architecture before execution, SUPERVISORAGENT introduces runtime, adaptive supervision as a third paradigm — a lightweight meta-agent that monitors high-risk interaction points (agent-agent, agent-tool, agent-memory) in real time via an LLM-free heuristic filter. The closest conceptual relative is AWorld's Guard agent, but SUPERVISORAGENT broadens the scope from factual verification to a full spectrum of interventions (error correction, inefficiency guidance, observation purification) and operates without altering the base agent's architecture, making it a plug-and-play module rather than a co-designed component.

## Why It Matters / Open Questions

Token cost is a primary barrier to real-world MAS deployment, and a ~30% reduction while maintaining accuracy is practically significant for anyone operating agentic pipelines at scale. The framework's demonstrated model-agnosticism (GPT-4.1, Gemini-2.5-pro, Qwen3-235B) and MAS-agnosticism (Smolagent, AWorld, OAgents) suggest broad adoptability. Key open questions include the 37% latency overhead (driven largely by purification), the 'noise-as-signal' trade-off where overly aggressive context compression harms ReAct-style agents, and whether the heuristic filter can be replaced by a learned mechanism for more precise trigger control. The paper also highlights the need for a universal resource-consumption metric beyond raw token count that accounts for external API call complexity.
