## Problem

Existing retrieval-augmented memory systems for conversational agents rely on single-granularity segmentation (e.g., session-level or turn-level chunks), which fails to model cross-granular semantic links between memories and lacks adaptive mechanisms to select the optimal granularity per query. This results in either partial retrieval of useful information or substantial noise, degrading both retrieval quality and downstream answer accuracy on long-term conversational tasks.
![Teaser figure](../imgs/ICLR20263099/cropped_page1_idx0.webp)

## Input / Output

The system takes a user query and a multi-session conversational history as input, where each session is decomposed into four granularity levels: raw session text, individual dialogue turns, LLM-generated summary, and LLM-generated keywords. These multi-granular units are encoded via Contriever into dense vectors and stored in an association graph. The output is a set of retrieved relevant memories (top-K nodes ranked by Personalized PageRank scores, further refined by LLM-based redundancy filtering) that are fed to a GPT-4o-mini generator to produce the final response. The entire pipeline is training-free and zero-shot, with no fine-tuning of any component.

## Method

MemGAS constructs multi-granularity memory units (session, turn, summary, keyword) for each conversation and builds a dynamic association graph using Gaussian Mixture Model clustering: when a new memory arrives, pairwise similarity vectors across all granularities are clustered into accept and reject sets, and edges are added only to the accept set, mimicking human-like memory consolidation. At query time, an entropy-based router computes the Shannon entropy of the softmax-normalized similarity distribution at each granularity level and assigns retrieval weights inversely proportional to entropy, so granularities with more concentrated (confident) matches receive higher weight. Retrieved memories are then ranked via Personalized PageRank over the multi-granularity association graph, seeded with router-weighted similarity scores, which propagates relevance through inter-memory links to surface contextually connected but embedding-dissimilar memories. Finally, an LLM-based filtering step removes redundant or irrelevant content from the top-K retrieved nodes before generation.

## Results

On LongMemEval-s, MemGAS achieves F1=20.38 and GPT4o-J=60.20, outperforming the strongest baseline HippoRAG2 (F1=14.73, GPT4o-J=57.60) by 5.65 F1 points. On LongMemEval-m (500 sessions), MemGAS reaches F1=16.85 vs. Contriever's 11.88, and on LongMTBench+ it scores F1=41.49 vs. RAPTOR's 37.69. For retrieval, MemGAS attains Recall@10=94.47 and NDCG@10=89.96 on LongMemEval-s, surpassing HippoRAG2 (91.28/88.73) and all other baselines across all four datasets.

## Baselines & Comparisons

MemGAS consistently outperforms all baselines on F1 across four datasets, with the largest margin on LongMemEval-s (20.38 vs. 14.73 for HippoRAG2, a +5.65 gain) and LongMemEval-m (16.85 vs. 11.88 for Contriever, +4.97). On LoCoMo, MemGAS wins on F1 (17.66) but trails HippoRAG2 on GPT4o-J (41.07 vs. 45.62), suggesting the LLM judge favors HippoRAG2's answer style on that dataset despite lower lexical overlap. On LongMTBench+, MemGAS leads by a wide margin over RAPTOR (F1 41.49 vs. 37.69) and SeCom (36.68). For retrieval, MemGAS achieves the highest Recall@3 (78.51) and NDCG@10 (89.96) on LongMemEval-s, beating HippoRAG2 by 3.0 and 1.2 points respectively, and extends this lead to LongMemEval-m (Recall@10: 77.02 vs. 65.96 for Contriever). The ablation confirms each component contributes: removing all modules drops F1 from 20.38 to 13.78 (matching plain Contriever), while the latency overhead of the full pipeline is only ~0.02 s beyond the base retriever.

## Relation to Prior Work

MemGAS departs from the dominant single-granularity paradigm in conversational memory systems (session-level chunks, turn-level segments, or LLM-generated summaries) by constructing multi-granularity memory units (session, turn, summary, keyword) and explicitly modeling cross-granularity associations via GMM-based clustering. It also extends structured memory architectures like RAPTOR (hierarchical tree) and HippoRAG (knowledge graph) by adding an entropy-based router that adaptively selects which granularity to prioritize per query, rather than relying on a fixed retrieval strategy. The Personalized PageRank retrieval over the association graph and LLM-based redundancy filtering are borrowed from graph-based RAG and compression literature, respectively, but their combination with multi-granularity association and adaptive routing is novel in the conversational memory setting.

## Why It Matters / Open Questions

The paper addresses a practical bottleneck for production conversational agents: as dialogue histories grow to hundreds of sessions, fixed-granularity retrieval either misses cross-session connections or drowns in noise. The entropy-based router's ability to approach oracle-level granularity selection (Table 8) without any learned parameters is a useful, lightweight mechanism that could be adopted in existing RAG pipelines. However, the framework's reliance on GPT-4o-mini for all LLM calls (generation, filtering, metadata creation) limits conclusions about scalability and cost at production scale, and the GMM clustering for memory association has not been stress-tested on very large memory banks (beyond ~500 sessions). Open questions include whether the entropy router generalizes to non-embedding-based similarity measures and whether the multi-granularity association graph degrades gracefully as memory size grows to millions of sessions.
