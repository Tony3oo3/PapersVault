## Problem

While 4-bit weight quantization is considered a universal memory-optimal choice for non-reasoning LLMs, this prescription breaks down for reasoning models where long generations cause the KV cache to rival or exceed model weight memory. Under a fixed memory budget, it remains unclear how to optimally allocate memory across model size, weight precision, generation length, parallel sampling, and KV cache compression to maximize reasoning accuracy.
![Teaser figure](../imgs/ICLR20262371/cropped_page0_idx0.webp)

## Input / Output

The framework takes a text prompt and a fixed total memory budget (weights + KV cache) as input, and produces a generated reasoning chain ending in a boxed final answer. The broader output is a set of memory-optimal configuration recommendations—model size, weight precision, token budget, group size, and KV compression strategy—derived from analyzing over 1,700 experimental scenarios. Generation length is controlled via budget forcing (2k–30k tokens), parallel scaling uses majority voting over up to 16 samples, and accuracy is evaluated on AIME25, GPQA-Diamond, LiveCodeBench, and MATH500.

## Method

The paper conducts a systematic empirical study across Qwen3 (0.6B–32B), DeepSeek-R1-Distill, and OpenReasoning-Nemotron, jointly varying five factors: model size, weight precision (4/8/16-bit via GPTQ, validated with AWQ and FP8), token budget (2k–30k via budget forcing), sampling group size (1–16 via majority voting), and KV cache compression (R-KV or StreamingLLM eviction, or HQQ quantization at 2/4/8-bit). The central finding is a scale-dependent threshold at an effective size of 8-bit 4B (~4.2 GB): below it, memory is better spent on larger or higher-precision weights; above it, memory is better spent on longer generations and parallel scaling. Task type further modulates the optimal weight precision—4-bit suffices for knowledge-intensive tasks, while 8/16-bit are preferred for mathematical reasoning and code generation. For KV cache compression, eviction provides a better memory-accuracy trade-off than quantization for small models, while both become competitive for larger ones. An external Process Reward Model for Best-of-N selection is shown to be memory-inefficient compared to self-contained majority voting.

## Results

The paper identifies a scale-dependent threshold at ~4.2 GB (8-bit 4B effective size) that governs memory allocation: below this threshold, allocating memory to larger/higher-precision weights outperforms longer generations (e.g., 1.7B 8-bit with 6k tokens beats 0.6B 8-bit with 18k tokens on AIME25; 4B 8-bit with 14k tokens reaches 61.7% on LiveCodeBench vs. 42.5% for 1.7B 16-bit with 22k tokens). Above the threshold, extending the token budget until saturation is more memory-efficient, and parallel scaling (majority voting) further improves the Pareto frontier, with optimal group size G increasing from 4–8 (16–29 GB) to ≥8 (>29 GB). For task type, 4-bit weights are broadly memory-optimal on GPQA-Diamond (knowledge-intensive), while 8-bit or 16-bit weights are more memory-efficient on AIME25 and LiveCodeBench (e.g., 8B 8-bit consistently outperforms 14B 4-bit on AIME25). KV cache eviction (R-KV) provides a better memory-accuracy trade-off than KV quantization for models below 8-bit 8B, while both become competitive for larger models.

## Baselines & Comparisons

The paper compares six baselines across its trade-off analysis. AWQ and FP8 weight quantization produce memory-accuracy curves that nearly overlap with GPTQ (Figure 12), confirming the scale-dependent threshold is robust to the specific quantization algorithm. R-KV eviction outperforms both StreamingLLM and KV cache quantization (HQQ) for models below 8-bit 8B effective size, maintaining near-lossless accuracy at a fixed memory ceiling (e.g., 8k-token budget on 4B model), while StreamingLLM's sliding-window approach is less effective for reasoning tasks. For larger models (≥8-bit 8B), HQQ-based KV quantization becomes competitive with R-KV eviction, though aggressive 2-bit quantization still causes significant accuracy loss. ActPRM-X (7B, 13.28 GB) as an external verifier for Best-of-N selection is consistently memory-inefficient compared to self-contained majority voting, with marginal accuracy gains that do not justify the fixed memory overhead, and in low-memory regimes it can even underperform serial scaling alone.

## Relation to Prior Work

This paper repurposes well-established techniques—GPTQ/AWQ/FP8 weight quantization, R-KV/StreamingLLM eviction, HQQ KV quantization, budget forcing, and majority voting—into a unified empirical framework for answering a question prior work has not addressed: how to allocate a fixed memory budget across model size, weight precision, token budget, parallelism, and KV compression specifically for reasoning models. It departs from the non-reasoning quantization literature (Dettmers & Zettlemoyer, Frantar et al.) where weights dominate memory and 4-bit is broadly optimal, and from test-time scaling laws (Brown et al., Snell et al., Muennighoff et al.) that optimize FLOPs rather than memory. The paper's conceptual contribution is identifying a scale-dependent threshold (effective size ≈ 8-bit 4B) that governs which allocation strategy is optimal, a question that arises only when the KV cache becomes comparable to or larger than the weights.

## Why It Matters / Open Questions

The findings provide practitioners with concrete, actionable guidelines for deploying reasoning models under memory constraints: prioritize model capacity over test-time compute for small models, maximize test-time compute for large ones, and choose KV eviction over quantization below the 8-bit 8B threshold. The result that 4-bit weights are memory-inefficient for mathematical reasoning and code generation directly contradicts the established '4-bit is universally good' prescription, which has practical implications for RL rollout pipelines and edge deployment. Limitations include a primary focus on the Qwen3 family, a limited set of eviction algorithms, no training-time approaches (e.g., QAT), and the acknowledged possibility that the scale threshold will shift as reasoning models evolve. Open questions include how these trade-offs interact with speculative decoding, multi-GPU sharding, and the next generation of more token-efficient reasoning architectures.
