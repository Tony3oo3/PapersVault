## Problem

Verifiable code generation—jointly producing code, formal specifications, and proofs of code-specification alignment—offers a path to correctness guarantees for LLM-generated software, yet no existing benchmark provides a holistic, modular evaluation framework covering all three tasks and their compositions. Prior benchmarks either target only one or two components, lack human-validated quality control, or do not support flexible task composition to reflect real-world end-to-end verification workflows.

## Input / Output

Each VERINA instance provides a natural language problem description (median 110 words), a Lean function signature, and optionally a ground truth code implementation or formal specification as context. The model must produce Lean 4 code, pre/post-condition specifications, and/or interactive Lean proofs. Evaluation uses pass@k with comprehensive test suites (median 5 positive + 12 negative tests achieving 100% line coverage) for code, Lean compiler verification for proofs, and a multi-stage pipeline combining LLM-based theorem proving with property-based testing (via the `plausible` tactic, 1000 instances) for specification soundness and completeness.

## Method

VERINA is a benchmark of 189 manually curated Lean 4 coding tasks sourced from MBPP-DFY-50, CloverBench, and student submissions from a theorem-proving course, all translated and validated through rigorous quality assurance (full code coverage, 100% test pass rates, at least 3 negative tests per positive test, and dual-author review). Its key design contribution is modularity: the three foundational tasks (CodeGen, SpecGen, ProofGen) can be evaluated independently or composed into realistic workflows such as specification-guided code generation, specification inference from code, and end-to-end verifiable code generation. For specification evaluation, the paper introduces a multi-stage pipeline that first attempts formal proof of soundness/completeness relationships using LLM-based provers, then falls back to property-based testing with the `plausible` tactic when proving is inconclusive, and finally checks the negation to resolve remaining unknowns. Experiments use 2-shot DSPy prompting with 5 samples per task, evaluating 10 general-purpose LLMs and 3 specialized theorem-proving models, with iterative proof refinement (up to 64 rounds using Lean compiler error feedback) and budget-normalized comparison against the Copra agentic framework.

## Results

On VERINA (189 Lean coding tasks), the best general-purpose LLM, OpenAI o3, achieves 72.6% code correctness (pass@1), 52.3% specification soundness and completeness, and only 4.9% proof success rate. Among specialized theorem-proving models, Goedel Prover V2 32B reaches 11.2% proof success in one trial, improving to 20.1% with 64 iterative refinement steps. In the end-to-end verifiable code generation setting, o3 achieves a 41.2% Code&Spec Score but only 3.2% End-to-End Score (requiring a valid proof against the ground truth specification), confirming ProofGen as the dominant bottleneck.

## Baselines & Comparisons

VERINA is a benchmark, so comparisons are between models evaluated on it. Among general-purpose LLMs, o3 leads on all three tasks (72.6% CodeGen, 52.3% SpecGen, 4.9% ProofGen), followed by o4-mini and Claude Opus 4.0 on CodeGen. Specialized provers substantially outperform general-purpose models on ProofGen: Goedel Prover V2 32B achieves 11.2% (2.3× o3's 4.9%) in one trial, and DeepSeek Prover V2 7B also exceeds all general-purpose models. The agentic Copra framework (using o4-mini as backbone, up to 64 LLM queries) improves over single-pass generation but is less cost-effective than iterative refinement with Lean compiler feedback, which reaches 8.99% at a 50k-token budget versus Copra's 4.76%, and 14.29% at 350k tokens versus Copra's 7.94%. Iterative refinement with verifier feedback consistently outperforms both direct generation and Copra across all evaluated models, though gains diminish sharply on the harder VERINA-B subset (only 6.17% for o4-mini after 64 steps).

## Relation to Prior Work

VERINA extends the emerging paradigm of verifiable code generation (Sun et al., 2024; Yang et al., 2024) by providing the first comprehensive, modular benchmark that jointly evaluates code, specification, and proof generation in Lean's interactive theorem proving (ITP) setting. It departs from prior ATP-based efforts like Dafny-Synthesis (Misu et al., 2024) and Clover (Sun et al., 2024), which cover all three tasks but in Dafny with only 50–62 samples and no compositional evaluation, and from ITP benchmarks like miniCodeProps (Lohn & Welleck, 2024) and FVAPPS (Dougherty & Mehta, 2025), which target only proof generation or lack human quality control. The multi-stage specification evaluator combining LLM-based theorem proving with property-based testing (via Lean's `plausible` tactic) is a novel evaluation mechanism not present in prior work.

## Why It Matters / Open Questions

The stark 4.9% proof success rate for the best general-purpose model (o3) versus 72.6% code correctness reveals that proof generation is the critical bottleneck in verifiable code generation, a gap that no current LLM or specialized prover (best: 11.2% for Goedel Prover V2 32B) can close. This finding redirects community attention toward improving LLM-based theorem provers for verification-specific domains rather than merely scaling code generation. Key limitations include the modest 189-example size, focus on standalone problems rather than complex real-world verification projects, and Lean-specificity that may limit transfer to ATP systems like Dafny or Verus. Open questions include whether iterative refinement strategies can scale beyond the observed 20.1% ceiling, and whether the benchmark's findings generalize as LLM provers improve.
