## Problem

Existing web agent benchmarks (WebVoyager, WebArena) evaluate simple navigation and action tasks without requiring data manipulation or analytical reasoning, while data science benchmarks (DSBench, Spider 2.0) operate on static, pre-structured datasets and ignore the web-browsing and data-acquisition phase. No prior benchmark captures the full end-to-end workflow that real data scientists perform: autonomously navigating multiple websites, extracting heterogeneous multimodal data, synthesizing it, and producing analytical outputs.

## Input / Output

Each task specifies a natural-language goal and a fixed entry URL; the agent observes HTML, DOM, screenshots, and AXTrees, and can download and load structured files (CSV, JSON) into its context for downstream analysis. The agent produces an analytical outcome (report, visualization, or fitted model) and/or executes a downstream action such as posting to a forum. Evaluation yields both a binary success/failure label for tasks with verifiable ground truths and a 1–5 LLM-judge score computed over the full interaction trajectory rather than only final screenshots, with the benchmark available in both a live-website track and a dockerized track for reproducibility.

## Method

WebDS formalizes a web data science task as a composite mapping f = f_α ∘ f_a ∘ f_d over a browser environment, decomposing it into information gathering, data-to-outcome transformation, and optional downstream action. The benchmark comprises 870 human-authored tasks across 29 public websites spanning 10 domains, each labeled with up to seven task attributes (multi-hop, structured/unstructured, tool-use, multi-website, action-based, etc.) and assigned to one of three difficulty tiers based on attribute combinations. The LLM-judge protocol extends WebVoyager's binary screenshot-based scoring to a 1–5 integer scale with rationale, analyzing (observation, action, next-observation) triplets across the entire trajectory for more reliable and interpretable scores. The action space is intentionally left unfixed to allow researchers to plug in diverse agent frameworks and enable or disable tools (Python, SQL, Bash) without adapter friction. The benchmark is released as a 470-task public validation set plus a 400-task private test set with rotating subsets to prevent overfitting, and fine-grained evaluation is provided along three axes: domain, task attribute, and difficulty level.

## Results

On WebDS-live, the best-performing agent (BrowserUse + GPT-5.1) achieves only 22.2% overall success rate, while most models score below 2%. BrowserUse with Qwen2.5-72B reaches 13.2% and with GPT-4o reaches 12.9%, both dramatically lower than their 80%+ performance on WebVoyager. AgentOccam, which achieves 45.7% on WebArena, drops to just 4.8% on WebDS. By contrast, human participants achieve approximately 90% success rate, establishing a gap of over 75 percentage points between the best agent and humans.

## Baselines & Comparisons

The paper evaluates three agent families on WebDS. The WebArena base agent framework (using GPT-4o, GPT-4o-mini, Sonnet-3.5, Haiku-3.5, Qwen2.5-vl-72b, and Qwen2.5-72b) performs worst, with all configurations scoring below 2% success rate, indicating that simple accessibility-tree-based navigation is insufficient for multi-step data science workflows. AgentOccam, the SOTA open-source agent on WebArena (45.7% there), drops to 4.8% on WebDS, a roughly 10× degradation. BrowserUse, the SOTA agent on WebVoyager (80%+ there), achieves 13.2% with Qwen2.5-72B, 12.9% with GPT-4o, and 22.2% with GPT-5.1 — still far below its WebVoyager performance. Notably, BrowserUse with Qwen2.5-72B slightly outperforms the same setup with GPT-4o, suggesting the bottleneck lies in the interaction/control layer rather than raw model capability. All agents fall dramatically short of the ~90% human baseline, with the best agent (BrowserUse + GPT-5.1) trailing humans by over 67 percentage points.

## Relation to Prior Work

WebDS sits at the intersection of two benchmark families that have developed in parallel: web agent benchmarks (WebVoyager, WebArena, Mind2Web, GAIA) that evaluate navigation and simple task completion, and data science benchmarks (InfiAgent-DABench, DSBench, Spider 2.0, DABStep) that evaluate analysis over static, pre-supplied datasets. The paper builds directly on WebVoyager's LLM-as-a-Judge evaluation paradigm, extending it from binary success/failure over the last 15 screenshots to a 1–5 score over the full trajectory, and on the BrowserUse agent framework, modifying it with AXTree-based element indexing and CSV-aware data tools. Conceptually, it departs from both lines by formulating the task as a composite mapping (navigation → extraction → analysis → optional action) that no prior benchmark requires in a single episode, and by introducing a dual-track (live + dockerized) reproducibility design absent from earlier web benchmarks.

## Why It Matters / Open Questions

The 75+ percentage-point gap between the best agent (22.2%) and the human baseline (90%) quantifies a previously under-measured limitation: current agents cannot sustain coherent performance across full data-science workflows that interleave browsing, tool use, and synthesis. The finding that the dominant failure mode is groundedness (40.2%)—agents reach the correct page but misread or omit key details—rather than navigation, redirects attention from improving web traversal to improving information extraction and long-horizon state tracking. Open questions include whether the capacity-irrelevance result (GPT-4o ≈ GPT-4o-mini ≈ Qwen2.5-72B) reflects a fundamental ceiling in the interaction layer or will dissolve with better scaffolding, and whether the dockerized track will remain representative as live sites evolve. As the first large-scale, reproducible benchmark for this combined task, WebDS is likely to become a standard evaluation target for the web-agent and data-science-agent communities.
