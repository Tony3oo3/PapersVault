## Problem

CAD programs encode 3D shapes as sequences of geometric instructions but typically lack semantic comments, making them difficult for both humans and machines to interpret and modify. No prior method or benchmark exists for automatically generating semantic part labels for code blocks in CAD programs, and the task is complicated by nested program structures, the absence of realistic textures in CAD renderings, and the open-vocabulary nature of shape categories.

## Input / Output

The method takes an OpenSCAD program and a shape category name (e.g., 'chair') as input. It executes the program to produce a 3D shape, renders depth maps from 10 viewpoints arranged in a ring above the shape, and converts each depth map into photorealistic images using ControlNet with 4 different seeds (yielding 40 images total). The output is a set of semantic part labels assigned to multi-level code blocks identified via syntax tree parsing, producing an annotated CAD program where each commentable block carries a label describing the shape part it generates.

## Method

CADTalker bridges the program domain and the image domain through a four-stage pipeline. First, it parses the syntax tree to identify commentable code blocks by finding irreducible blocks (single primitives or boolean operations) and collecting their ancestor nodes. Second, it renders depth maps of the executed shape from 10 viewpoints and uses ControlNet to translate each depth map into a photorealistic image conditioned on the category name, deliberately using diverse seeds to increase appearance variation. Third, it applies Grounding DINO for open-vocabulary part detection (with part names suggested by ChatGPT) and SAM for pixel-level segmentation on all 40 images. Finally, it maps each code block to image pixels by re-rendering the shape with the target block in white against a background color, then aggregates part labels via IoU-weighted voting across all views with intermediate thresholding to filter low-confidence labels.

## Results

CADTalker achieves an overall 83.24% block accuracy on the CADTalk benchmark. On the machine-made tracks, block accuracy (B_acc) ranges from 79.26% (CADTalk-EllipL) to 88.75% (CADTalk-CubeH), with semantic IoU (S_IoU) ranging from 68.47% to 84.76%. On the human-made CADTalk-Real track, the method scores 78.29% B_acc and 66.22% S_IoU, reflecting greater diversity in program structure and shape geometry. Results are comparable whether using ground-truth part labels or ChatGPT-suggested labels, confirming robustness to label vocabulary.

## Baselines & Comparisons

The paper compares CADTalker against PartSLIP [26], a zero-shot 3D point cloud part segmentation method that uses multi-view rendering and a pretrained image-language model (GLIP). CADTalker substantially outperforms PartSLIP across all four machine-made tracks: on CADTalk-CubeH, CADTalker achieves 88.75% B_acc versus 29.67% for PartSLIP (a ~59-point gap), and on CADTalk-EllipL, 79.26% versus 24.22%. Even the improved PS++ variant (which assigns random ground-truth labels to unrecognized points instead of null labels) only reaches 40.80–48.38%, still trailing CADTalker by 30+ points. The authors attribute PartSLIP's poor performance to its reliance on traditional (non-photorealistic) rendering of point clouds, which creates a domain gap with the photographic data its vision models were trained on. On the human-made CADTalk-Real track, the gap is even more pronounced: 78.29% for CADTalker versus 18.06% for PartSLIP.

## Relation to Prior Work

This paper carves new ground by repurposing a pipeline of off-the-shelf foundation models (ControlNet for depth-to-photorealistic translation, Grounding DINO for open-vocabulary detection, SAM for pixel-level segmentation, and ChatGPT for part-name suggestion) into a cross-domain transfer framework that maps 2D image segmentation results back to CAD code blocks. Conceptually, it sits at the intersection of code summarization (which operates on raw code without execution), 3D shape segmentation (which works on meshes or point clouds directly), and image-to-image translation, but departs from all three by executing the program, bridging the synthetic-to-photographic domain gap, and using the rendered images as an intermediate representation for semantic reasoning. The closest prior work, PartSLIP, also uses multi-view rendering and image-language models for 3D part segmentation, but operates on point clouds and does not address the textureless rendering problem inherent to CAD programs.

## Why It Matters / Open Questions

The CADTalk benchmark (5,300+ programs with ground-truth semantic comments) is the first resource for evaluating semantic commenting of CAD programs, a task with clear practical relevance given that CAD programs are the industry standard for parametric shape representation yet remain difficult to interpret without annotations. Key limitations include the inability to comment on subtractive operations (e.g., holes), the small real-world track (45 programs), and the reliance on a fixed set of 10 viewpoints that may miss occluded parts. Open questions include whether multi-modal approaches combining program structure with visual output can overcome the current method's sensitivity to small parts and occlusions, and whether the image-domain strategy generalizes to CAD languages beyond OpenSCAD/CSG.
