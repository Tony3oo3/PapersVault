## Problem

State-of-the-art vectorized HD map construction methods rely on point-level representation learning to regress element coordinates, which limits the model's ability to capture element-level information such as overall shape and semantic context. This leads to practical failures including missing corner details, inaccurate element length and direction, and entanglement between nearby elements. Existing attempts to incorporate element-level information (e.g., MapVR, BeMapNet, PivotNet) apply point-level and element-level processing sequentially rather than interactively, yielding suboptimal results.

## Input / Output

HIMap takes multi-view RGB images (6 cameras on nuScenes, 7 on Argoverse2) and optionally LiDAR point clouds as input, processing them through a backbone, FPN, and 2D-to-BEV transformation to produce BEV feature maps. The output is a set of up to 50 vectorized map elements (road boundary, lane divider, pedestrian crossing), each represented by 20 ordered 2D point coordinates, a class label, and a binary mask, all within a perception range of ±15 m (X) and ±30 m (Y) around the ego vehicle. The internal HIQuery representation has shape E×(P+1)×C, where the extra channel encodes element-level information alongside the P point-level channels.

## Method

HIMap introduces a hybrid representation called HIQuery that decomposes each element's query into a point query (P×C) and an element query (C), enabling simultaneous encoding of local position and global shape information. A multi-layer hybrid decoder iteratively refines HIQuery through a point-element interactor that combines a deformable-attention-based point feature extractor (with learnable 2D anchors) and a masked-attention-based element feature extractor (sharing position embeddings with the point query), followed by a point-element hybrider that performs single-level feature refinement and cross-level query update so that both point and element queries are corrected by the other level. A point-element consistency constraint is applied at each decoder layer by computing a pseudo element-level representation as a weighted sum of point-level head outputs and enforcing similarity to the actual element-level head output via binary cross-entropy, strengthening intra-element consistency and inter-element discriminability. The final HIQuery is decoded through class, point, and mask heads to produce the vectorized map elements end-to-end.

## Results

On the nuScenes validation set with multi-view RGB input (ResNet-50, 110 epochs), HIMap achieves 73.7 mAP under the easy setting ({0.5, 1.0, 1.5} m) and 51.6 mAP under the hard setting ({0.2, 0.5, 1.0} m), setting new state-of-the-art. With multi-modality input (RGB + LiDAR), HIMap reaches 77.8 mAP (easy, 110 epochs), surpassing the previous best by 8.3 mAP. On Argoverse2 (24 epochs), HIMap obtains 72.7 mAP (easy) and 50.0 mAP (hard), outperforming MapTRv2 by 2.2 and 3.5 mAP respectively.

## Baselines & Comparisons

HIMap outperforms all seven baselines on both nuScenes and Argoverse2 under both hard and easy evaluation settings. On nuScenes (easy), HIMap surpasses MapTRv2 (68.4 mAP) by 5.0 mAP and BeMapNet (64.8 mAP) by 8.9 mAP; on the hard setting, it exceeds BeMapNet (47.1 mAP) by 4.5 mAP and MapTRv2 (45.2 mAP) by 6.4 mAP. On Argoverse2 with 24 epochs, HIMap beats MapTRv2 by 3.5 mAP (hard) and 2.2 mAP (easy), and with 6 epochs by 3.2 mAP (hard) and 2.1 mAP (easy). The gains are most pronounced at stricter thresholds (0.2 m, 0.5 m), indicating that the point-element interaction improves fine-grained localization accuracy. Notably, HIMap's advantage over MapTRv2 is larger under the hard setting than the easy setting, confirming that the hybrid representation better captures element-level shape information that point-only methods miss.

## Relation to Prior Work

HIMap extends the MapTR family of vectorized HD map construction methods by introducing a hybrid representation (HIQuery) that unifies point-level and element-level information within a single query structure. The point feature extractor adapts deformable attention from Deformable DETR, while the element feature extractor builds on Masked-attention from Mask2Former, but the key departure is the point-element interactor that enables mutual refinement between the two levels rather than the sequential pipeline used by MapVR, BeMapNet, and PivotNet. The paper positions itself against the dominant point-only representation paradigm (MapTR, MapTRv2, VectorMapNet) by arguing that element-level shape and semantic information is underexploited when only point coordinates are regressed.

## Why It Matters / Open Questions

The 5–8 mAP gains over prior SOTA on both nuScenes and Argoverse2, with clear ablation evidence that point-element interaction (not just adding element-level supervision) drives the improvement, make this a practical upgrade for HD map construction pipelines. However, the method remains 2D-only, lacks temporal consistency across frames, and does not address model acceleration, all of which are critical for real-time autonomous driving deployment. The point-element consistency constraint, while effective, is a relatively lightweight addition (a single BCE loss on a similarity matrix), suggesting the core architectural insight—jointly attending to local points and global shape within one query—is the more transferable contribution.
