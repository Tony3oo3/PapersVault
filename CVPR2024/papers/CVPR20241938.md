## Problem

Generating high-quality vector fonts with diverse topological structures and precise, editable control point positions remains challenging. Existing VAE and autoregressive approaches struggle with the inherent ambiguity of vector curves—infinitely many control point configurations can produce the same glyph—leading to artifacts, imprecise control points, and limited glyph diversity. The irregular data structure of vector graphics also prevents straightforward application of standard CNN-based generative architectures.

## Input / Output

The model takes a Unicode character code point and a font style specification (either a font name looked up in a learned embedding table, or a few exemplar raster glyph images passed through a ConvNet) as input. It produces a vector glyph as ordered sequences of cubic Bezier curve control points, with the number of paths, control points, and point repetitions learned per glyph. Internally, the raster stage outputs a 64×64 4-channel image (one grayscale glyph channel plus three channels encoding control point location, multiplicity, and ordering as colored Gaussian blobs), and the vector stage outputs a 256×13 tensor where each row encodes path membership (3 bits), grid cell index (8 bits), and continuous displacement (2 values) for one control point.

## Method

VecFusion is a two-stage cascaded diffusion model. The first stage is a UNet-based raster diffusion model (DDPM, 1000 steps, cosine schedule) that denoises a 4-channel image from Gaussian noise, conditioned on character and font style embeddings, producing both the low-resolution glyph and auxiliary control point fields. The second stage is an encoder-only transformer that denoises a fixed-size M×D tensor of control point representations, conditioned on the raster output via cross-attention. The key representation innovation is a mixed discrete-continuous encoding: path membership and grid cell indices are stored as binary bits (modeled as continuous values following Analog Bits and thresholded at inference), while sub-cell position is captured by two continuous displacement values relative to the grid cell center. This design lets the model automatically predict the number of paths and control points (via null entries) while achieving precise sub-pixel control point placement guided by the raster-stage control point fields.

## Results

On the few-shot font style transfer benchmark (DeepVecFont-v2 dataset, 52 Latin characters, 1,425 test fonts), VecFusion achieves L1=0.069, Chamfer Distance (CD)=0.46, and average control-point count difference of 15.05, outperforming DeepVecFont-v2 (L1=0.098, CD=1.05, #cp diff=34.84) and DualVector (L1=0.197, CD=1.37, #cp diff=25.69) on all four metrics. On the missing-glyph generation task over a new 324K-glyph Google Fonts dataset (577 Unicode characters across multiple scripts), VecFusion achieves L1=0.014 and CD=0.16, substantially outperforming ChiroDiff (L1=0.044, CD=1.66) by roughly 3× on both metrics. The method also reduces the average control-point count error from 56.37 (ChiroDiff) to 3.05, indicating far more faithful reproduction of artist-designed curve structure.

## Baselines & Comparisons

VecFusion outperforms all three baselines on every reported metric across both evaluation tasks. Against ChiroDiff [9] on missing-glyph generation, VecFusion reduces L1 by 3.1× (0.014 vs 0.044) and Chamfer distance by 10.4× (0.16 vs 1.66), while cutting the average control-point count error from 56.37 to 3.05 — a 18.5× improvement that reflects far more accurate curve topology. On few-shot style transfer, VecFusion beats DeepVecFont-v2 [49] by 29% on L1 (0.069 vs 0.098) and 56% on CD (0.46 vs 1.05), and reduces the control-point count difference by 57% (15.05 vs 34.84). Against DualVector [30], the margins are even larger: 65% lower L1 (0.069 vs 0.197), 67% lower CD (0.46 vs 1.37), and a 13× smaller vector-path count error (0.033 vs 0.428). Notably, DeepVecFont-v2 requires vector representations of the reference glyphs as additional input, whereas VecFusion and DualVector use only raster reference images, making VecFusion's advantage over DeepVecFont-v2 particularly significant given the simpler input requirement.

## Relation to Prior Work

VecFusion extends the cascaded diffusion paradigm (Ho et al., 2022) from image synthesis to vector font generation, combining a UNet-based raster diffusion stage with a transformer-based vector diffusion stage. It departs from prior vector font generators (DeepVecFont-v2, DualVector) that directly model vector sequences via VAEs or autoregressive transformers, instead using a low-resolution raster image plus auxiliary control point fields as an intermediate representation to guide fine-grained Bezier curve prediction. The mixed discrete-continuous tensor representation for control points draws on Analog Bits (Chen et al., 2023) for handling discrete path membership and grid cell indices within a continuous diffusion process.

## Why It Matters / Open Questions

The paper demonstrates that a two-stage raster-to-vector cascade with auxiliary control point fields substantially outperforms direct vector-space diffusion, addressing the long-standing ambiguity problem where infinitely many control point configurations yield the same glyph. The introduced 1,424-font / 324K-glyph Unicode dataset broadens evaluation beyond Latin scripts to Greek, Cyrillic, Devanagari, and mathematical symbols. Key limitations include the requirement for vector supervision (raster-only data cannot be used) and a demonstrated failure mode where the model hallucinates case (e.g., generating an uppercase glyph for a lowercase target in an all-caps font). Future work points toward general vector graphics generation and 3D parametric curve/surface synthesis.
