## Problem

Existing tool-usage methods for visual assistants freeze their underlying visual tools, preventing adaptation when a tool lacks knowledge of a new concept (e.g., a fine-grained species or a specific person). This limits applicability to environments requiring new knowledge, as the system cannot learn from its own failures. CLOVA addresses this gap by introducing a closed-loop framework that identifies which tools failed and automatically updates them.
![Teaser figure](../imgs/CVPR20240420/cropped_page0_idx1.webp)

## Input / Output

CLOVA handles four task types: compositional VQA (single image + question → text answer), multiple-image reasoning (two images + statement → true/false), language-guided image editing (image + instruction → edited image), and factual knowledge tagging (image + instruction → bounding boxes with labels). During inference, the LLM first generates a plan (an intermediate reasoning chain) and then a program that calls tools from a 15-tool toolkit; visual intermediate results are converted to text via BLIP captioning for the reflection phase. The demonstration pool used for in-context prompting contains both correct examples and incorrect examples paired with error critiques, selected via BERT feature similarity to the current instruction.

## Method

CLOVA operates in three phases: (1) Inference, where LLMs generate plans and programs that are parsed and executed against a toolkit of neural-network tools (OWL-ViT, BLIP, MaskFormer, CLIP, Stable Diffusion) and Python functions; (2) Reflection, where a multimodal global-local scheme uses LLMs to identify the faulty tool—global reflection considers the full task with human feedback and all intermediate results, while local reflection (triggered if global fails) inspects each program step individually; (3) Learning, where training data is collected via three manners (LLM-inferred answers for VQA, open-vocabulary datasets like LVIS for localization/segmentation, and Internet search for classification/replacement), followed by a training-validation prompt tuning scheme that learns a separate prompt per training instance and discards any prompt that fails on held-out validation data. At inference time, a prompt ensemble retrieves and aggregates stored prompts weighted by cosine similarity between the current input's features and stored instance features, while the base tool weights θ remain frozen. LLMs are simultaneously updated by storing correct and incorrect examples (with critiques) in a growing demonstration pool used for future in-context prompting.

## Results

On GQA (top-1 accuracy), CLOVA achieves 54.6%, outperforming the strongest tool-usage baseline VISPROG (49.8%) by 4.8 points and the end-to-end model Otter (48.2%) by 6.4 points, though trailing MMICL (64.4%). On NLVRv2, CLOVA reaches 65.6%, surpassing VISPROG (60.8%) by 4.8 points and MMICL (62.2%) by 3.4 points. On the manually collected image editing task, CLOVA achieves 65.4% accuracy versus VISPROG's 40.2% (+25.2 points), and on knowledge tagging it reaches F1 0.502 versus VISPROG's 0.393 (+10.9 points).

## Baselines & Comparisons

CLOVA outperforms all seven tool-usage baselines across every task where they overlap. Against the closest tool-usage competitor VISPROG, CLOVA gains +4.8 points on GQA (54.6 vs 49.8), +4.8 on NLVRv2 (65.6 vs 60.8), +25.2 on image editing (65.4 vs 40.2), and +10.9 F1 on tagging (0.502 vs 0.393). Against the end-to-end baselines, CLOVA beats Otter on both GQA (+6.4) and NLVRv2 (+17.4), but falls short of MMICL on GQA (54.6 vs 64.4) while surpassing it on NLVRv2 (65.6 vs 62.2). The largest margins appear on the manually collected fine-grained tasks (editing and tagging), where off-the-shelf tools without learning capability (GPT4TOOLs, Visual ChatGPT) score below 22% on editing, highlighting that CLOVA's closed-loop learning is the primary source of its advantage on novel visual concepts.

## Relation to Prior Work

CLOVA builds directly on VISPROG's program-generation-and-tool-execution paradigm for its inference phase, but departs from the entire line of tool-usage methods (VISPROG, ViperGPT, HuggingGPT, Visual ChatGPT, GPT4Tools) by introducing a closed-loop learning framework with explicit reflection and learning phases. While AssistGPT and OpenAGI update only the LLM via in-context learning or reinforcement learning, CLOVA extends the update mechanism to visual tools through a novel training-validation prompt tuning scheme that learns per-instance prompts and discards those failing validation. The multimodal global-local reflection scheme also extends prior LLM reflection work by incorporating visual intermediate results and step-level (local) analysis, rather than relying solely on global language-based critiques.

## Why It Matters / Open Questions

The paper demonstrates that the frozen-tool assumption in current visual assistants is a significant bottleneck, with the learning capability yielding 20% gains on fine-grained image editing and 10% on knowledge tagging where off-the-shelf tools simply fail. However, the evaluation is conducted on small subsets (500 samples for GQA/NLVRv2, 129 images for editing), and the framework assumes at most one tool needs updating per task with no control flow in generated programs, limiting real-world applicability. Open questions include whether the closed-loop approach scales to multi-tool updates, how to handle deployment latency from the reflection-learning cycle, and whether the prompt ensemble mechanism generalizes to fundamentally different tool architectures beyond the 15 tools tested.
