## Problem

Existing autonomous driving frameworks, whether modular or end-to-end, cannot interpret and execute spontaneous natural-language user instructions such as 'overtake the car ahead.' Moreover, no benchmark exists to quantitatively evaluate how well LLM-based agents follow driving instructions, leaving the field without a standardized way to compare approaches.
![Teaser figure](../imgs/CVPR20242107/cropped_page2_idx0.webp)

## Input / Output

The LLM receives a single prompt concatenating three components: API documentation describing available functional primitives, a natural-language instruction (averaging 7.6 words, max 14), and a driving context narrative generated by a structured language generator that converts raw simulation vectors (speed, lane position, surrounding vehicle states) into readable prose. The output is a Python function (a Language Model Program) that may contain control flow (if-else, while loops) and yield statements; it is executed via Python's exec() with a restricted namespace exposing only the provided APIs, and the resulting generator is stepped by the simulator at each time tick.

## Method

LaMPilot uses an LLM to generate executable Python policy code (Language Model Programs) as the action space, rather than emitting low-level control signals directly. The LLM performs Chain-of-Thought reasoning over the prompt and produces a function that composes four categories of functional primitives—Ego, Perception, Navigation, and Control APIs—implemented with classical planning and control algorithms (IDM, MOBIL). Safety is enforced at two levels: the LLM reasons about instruction safety before generating code, and the API layer embeds hard safety constraints inspired by Responsibility-Sensitive Safety, with an automatic fallback to a predefined autopilot mode on exceptions. The accompanying LaMPilot-Bench extends HighwayEnv with custom intersections and provides 4,900 semi-human-annotated scenarios (500 held out as test), scored via a weighted combination of Time-to-Collision, Speed Variance, and Time Efficiency metrics, with a 60-second per-scenario time limit.

## Results

On LaMPilot-Bench (500 test scenarios), GPT-4 with human feedback achieves the highest driving score of 64.0, with a 92.7% task completion rate and 0.9% collision rate. In the 3-shot setting, GPT-4 reaches a driving score of 55.9 (84.7% completion, 1.0% collision), while in 0-shot, GPT-4 Turbo leads with 39.1 (74.5% completion, 3.1% collision). The human driver baseline achieves a driving score of 84.6 with 98.0% completion and 0% collision, substantially outperforming all LLM-based agents. Heuristic baselines (IDM: 17.3, MOBIL: 11.7) achieve zero collisions but very low completion rates (20.4% and 15.3%) since they ignore user instructions.

## Baselines & Comparisons

The paper compares LLM-based agents against two rule-based driving baselines: IDM (Treiber et al., 2000) and MOBIL (Kesting et al., 2007). Both IDM and MOBIL achieve zero collisions but very low task completion rates (20.4% and 15.3% respectively) because they operate independently of user instructions, yielding driving scores of only 17.3 and 11.7. All LLM-based agents substantially outperform these heuristics on completion rate and driving score: for example, GPT-4 in 3-shot reaches 84.7% completion and a driving score of 55.9, while GPT-4 with human feedback achieves 92.7% completion and 64.0. However, LLM-based agents introduce non-zero collision rates (1–4%), whereas IDM and MOBIL maintain 0% collisions. The human driver baseline (84.6 driving score, 98% completion, 0% collision) remains the strongest performer, indicating a significant gap between current LLM-generated policies and human-level driving. The human feedback setting narrows this gap most effectively, with GPT-4 closing the completion-rate gap to within 5.3 percentage points of the human baseline.

## Relation to Prior Work

LaMPilot is directly inspired by Code as Policy [25], which demonstrated that LLMs can generate executable code as robot control policies, and adapts this paradigm to autonomous driving by replacing low-level control signals with a suite of functional primitives (perception, navigation, control APIs). It departs from prior LLM+AD work such as LMDrive and DiLu, which either generate vehicle trajectories or raw control signals end-to-end, by positioning the LLM as a strategic planner that writes code executed by classical planners and controllers. The human-feedback loop draws on Voyager's skill library and RAG-based retrieval, while the simulation environment extends HighwayEnv with custom intersections.

## Why It Matters / Open Questions

LaMPilot-Bench is the first quantitative benchmark for evaluating LLM-generated driving policies, filling a gap where prior LLM+AD papers lacked standardized, reproducible evaluation. The results reveal a significant performance gap between the best LLM agent (GPT-4 with human feedback, driving score 64.0) and a human driver (84.6), with persistent collision rates of 1–4% even for the strongest models, underscoring that current LLMs are not yet safe for real-world deployment. Open questions include whether instruction tuning can close the safety gap without sacrificing generalization, how multimodal (vision) inputs would change the picture, and whether the code-as-policy abstraction scales to more complex urban scenarios beyond highway and simple intersection settings.
