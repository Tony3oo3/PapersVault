## Problem

Existing temporal LiDAR 3D object detectors either store per-frame object point clouds or entire sequential point clouds in a memory bank, creating prohibitive memory overhead for long sequences. Additionally, these methods combine point cloud features with proposal trajectory features via simple concatenation, neglecting meaningful interactions between the two modalities.
![Teaser figure](../imgs/CVPR20241876/cropped_page0_idx1.webp)

## Input / Output

The method consumes only the current-frame object point cloud (128 sampled LiDAR points per proposal) plus multi-frame 3D proposal trajectories spanning up to 64 past frames, where each proposal is a compact 9-dimensional vector (3D center, 3D size, heading, 2D BEV velocity). The RPN (CenterPoint) operates on 4 accumulated frames to generate first-stage proposals. Output is refined 3D bounding boxes with confidence scores, trained with binary cross-entropy and box regression losses similar to CT3D.

## Method

PTT encodes two feature types from the current-frame points and historical proposals: Point-to-Proposal features (MLP over offsets between points and box corners across frames) and Proposal-to-Proposal features (MLP over relative proposal positions), which are combined into sequential point-trajectory features. A four-module transformer then processes these: a long-term memory (self-attention over older frames), a short-term memory (cross-attention from recent frames querying the long-term representation), a future-aware encoder (predicts future box positions from velocity and encodes future features with learnable correction queries), and a point-trajectory aggregator (cross-attention where compressed point features query all three trajectory memories). This design replaces the need for multi-frame point cloud storage with lightweight proposal trajectories, enabling 64-frame sequences at ~150 ms runtime versus ~1100 ms for MPPNet on 16 frames, while achieving state-of-the-art 3D mAPH on Waymo.

## Results

On the Waymo Open Dataset validation set, PTT with 64 frames achieves 81.32/75.71 (L1/L2 3D mAP) overall, outperforming the best single-frame method FSD (77.4/70.8) by 3.9/4.9 points in mAP. For the hardest L2 difficulty, PTT improves 3D mAPH by 5.6%, 6.9%, and 2.0% over FSD on vehicles, pedestrians, and cyclists respectively. PTT also surpasses the strongest multi-frame baselines MSF (80.65/75.46) and MPPNet (80.40/74.85) while using 8× and 4× more frames, respectively, with lower memory overhead and ~7× faster runtime than MPPNet (150 ms vs. 1100 ms).

## Baselines & Comparisons

PTT (64 frames) outperforms the strongest multi-frame baselines MSF (8 frames) and MPPNet (16 frames) in 11 out of 14 evaluation metrics, with the largest gains on vehicles (+0.88 L1 mAP over MSF, +0.97 over MPPNet) and pedestrians (+0.69 L1 mAP over MSF, +1.24 over MPPNet). Against the best single-frame method FSD, PTT achieves a substantial 3.9-point L1 mAP and 4.9-point L2 mAP improvement, with L2 mAPH gains of up to 6.9% on pedestrians. PTT also surpasses CenterFormer (8 frames) by 4.0 L1 mAP and 2.0 L2 mAP. The only marginal losses are on cyclist L2 AP/APH versus MSF (76.01/75.32 vs. 76.32/75.47), a gap of less than 0.4 points. Notably, PTT achieves these gains while processing 8× more frames than MSF and 4× more than MPPNet, yet with lower memory footprint and ~7× faster inference (150 ms vs. 1100 ms for MPPNet).

## Relation to Prior Work

PTT extends the two-stage temporal 3D detection paradigm established by MPPNet and MSF, which generate proposals via a region proposal network (CenterPoint) and then aggregate multi-frame information. The key departure is architectural: rather than storing per-frame object point clouds (MPPNet) or entire sequential point clouds (MSF) in a memory bank, PTT retains only the current frame's points and encodes all historical information through proposal trajectories, using a transformer with long-term/short-term memory and a future-aware encoder to model temporal dynamics. The point-to-proposal offset encoding and loss formulation are inherited from CT3D, while the cross-frame box linking follows MPPNet's velocity-based propagation.

## Why It Matters / Open Questions

The practical significance lies in enabling 64-frame temporal modeling at ~150 ms runtime versus ~1100 ms for MPPNet's 16 frames, with a memory footprint that scales as O(kN) rather than O(kN·T) or O(F·T), making long-sequence temporal detection feasible for on-device autonomous driving deployment. The conceptual insight—that proposal trajectories alone can approximate object geometry across time, obviating multi-frame point storage—challenges the prevailing assumption in the field that per-frame point clouds are necessary for temporal aggregation. Open questions include whether this proposal-centric temporal modeling generalizes to camera-based or multi-sensor settings, whether the modest performance gains over MPPNet/MSF (~0.5–1% mAPH) widen in more occluded or dynamic scenes, and whether the 64-frame sweet spot (with slight degradation at 128 frames) reflects a fundamental information limit or a capacity constraint of the current architecture.
