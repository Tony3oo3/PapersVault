## Problem

LLM-based image captioning models struggle to describe novel objects because updating their training data to keep pace with new objects in the real world is prohibitively expensive. Existing retrieval-augmented captioning methods rely on large text/caption datastores that are cumbersome to prompt, require many trainable parameters, and cause LLMs to imitate retrieved sentences rather than genuinely describing open-world objects. The paper asks how to sustain ever-changing object knowledge at minimal cost without scaling up parameters or training data.

## Input / Output

The method takes a single RGB image as input, processed by a frozen ViT-g encoder producing 257×1408 image features. The output is a free-form natural language caption generated autoregressively by a frozen Vicuna-13B LLM in a conversational prompt format. During inference, the model retrieves top-K=10 object names from an external FAISS-indexed memory of 14,596 visual-name pairs (768-dim embeddings), which are fused with visual features before being projected into the LLM's input space via a single linear layer.

## Method

EVCAP introduces an external visual-name memory where keys are 768-dim visual embeddings (averaged from 32 Q-Former outputs of object images) and values are object names, built from 1,203 LVIS objects with both real and Stable Diffusion-synthesized images. A frozen ViT-g + Q-Former with trainable image query tokens extracts 32 visual features from the input image, which are matched against memory keys via cosine similarity to retrieve top-K object names. A customized frozen Q-Former (with ports swapped so object names attend to visual features) and trainable object name query tokens form an attentive fusion module that implicitly filters irrelevant retrieved names. The fused object name features and visual features are concatenated, projected by a trainable linear layer into Vicuna-13B's latent space, and fed as a prompt for caption generation. Only 3.97M parameters are trainable (image query tokens, object name query tokens, and the linear layer), and the model is trained end-to-end on COCO alone in ~3 hours on 4 GPUs, with the external memory expandable to new objects without any retraining.

## Results

EVCAP, trained solely on COCO with only 3.97M trainable parameters, achieves CIDEr scores of 140.1 (COCO test), 119.3 (NoCaps overall), and 84.4 (Flickr30k test), outperforming all other lightweight-training methods by a wide margin. It surpasses MiniGPT4 (3.94M params) by 10.5 CIDEr on both COCO and NoCaps, and by 6.0 on Flickr30k. Despite using ~1/3000 the training data and ~1/500 the parameters of REVEAL (2.1B), EVCAP yields comparable CIDEr scores (140.1 vs. 145.4 on COCO). On the commonsense-violating WHOOPS dataset, enriching the external memory with 2,396 new objects improves CIDEr from 85.3 to 86.3, demonstrating the memory's expandability for open-world comprehension.

## Baselines & Comparisons

Among lightweight-training methods, EVCAP decisively outperforms MiniGPT4 (140.1 vs. 129.6 CIDEr on COCO; 119.3 vs. 108.8 on NoCaps; 84.4 vs. 78.4 on Flickr30k), SmallCap (140.1 vs. 119.7 on COCO), and ClipCap (140.1 vs. 113.1 on COCO), despite having the fewest trainable parameters (3.97M). Against heavyweight-training models, EVCAP nearly matches InstructBLIP (188M params) on NoCaps (119.3 vs. 121.9 CIDEr) and Flickr30k (84.4 vs. 82.8), and is within 4.4 CIDEr of BLIP-2 (1.2B params) on COCO (140.1 vs. 144.5). Compared to the retrieval-augmented REVEAL (2.1B params, 1.3B training data), EVCAP uses roughly 1/3000 the data and 1/500 the parameters while achieving a CIDEr of 140.1 vs. 145.4 on COCO. EVCAP trails specialist SOTAs (PaLI-X, CogVLM) by approximately 9–10 CIDEr on COCO, which the authors attribute to their billion-scale training data and 5B+ parameters. On the WHOOPS commonsense-violating benchmark, EVCAP (w/ WHOOPS memory expansion) achieves 86.3 CIDEr, surpassing MiniGPT4 (84.8) and BLIP (79.3) but remaining below the reproduced BLIP-2 FlanT5-XXL (93.1).

## Relation to Prior Work

EVCAP builds directly on BLIP-2's frozen ViT-g + Q-Former architecture as its vision encoder and on the key-value external memory paradigm introduced by RCA-NOC and NOC-REK, but departs critically by using visual appearance (rather than object definitions) as the memory key, making the memory trivially expandable from internet images. Within the retrieval-augmented captioning lineage (SmallCap, REVEAL, AoANet), EVCAP replaces large text datastores of full captions or documents with minimal visual-name pairs, arguing that full-text retrieval causes LLMs to imitate retrieved sentences and bloats trainable parameters. The attentive fusion module—a customized Q-Former with swapped input ports and trainable object-name query tokens—is a novel architectural component not present in prior retrieval-augmented captioning methods.

## Why It Matters / Open Questions

The paper demonstrates that a 3.97M-parameter model trained only on COCO can approach the CIDEr scores of 1.2B-parameter BLIP-2 and rival heavyweight retrieval-augmented methods like REVEAL (2.1B params, 1.3B training data), offering a practical path to open-world captioning where new objects appear continuously and retraining is infeasible. The expandable memory—where adding new objects requires only encoding a few images and appending name entries—addresses a real deployment bottleneck. However, EVCAP still trails specialist SOTAs (CogVLM, PaLI-X) by roughly 10 CIDEr points, cannot retrieve objects absent from its memory, and its object-centric design limits stylistic diversity, leaving open questions about integrating detection for completeness and scaling the memory to truly long-tail vocabularies.
