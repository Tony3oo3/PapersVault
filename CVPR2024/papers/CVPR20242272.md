## Problem

Existing GUI automation benchmarks target Android and Web platforms with relatively simple entertainment-oriented tasks, leaving PC productivity software automation (e.g., After Effects, Premiere Pro, MS Word) largely unexplored. PC GUIs pose unique challenges—dense visual understanding of icons and footage, complex operations like dragging and mask drawing, and long multi-step procedures—that current models are not designed to handle.

## Input / Output

The agent receives a natural language query, an instructional video (≤5 min) demonstrating the target function, and the live Windows GUI state (screenshot + panel layout metadata from PyWinAuto). It outputs executable PyAutoGUI Python code specifying raw mouse/keyboard actions (click, double-click, drag, keystrokes, shortcuts) with pixel-space coordinates, executed on a local Windows machine controlled remotely via a server-client communication system.

## Method

AutoPC is a zero-shot multi-agent framework with four cooperating modules built on GPT-4. The Planner performs hierarchical task decomposition by extracting steps from video subtitles and adapting them to the user query, producing a milestone→subtask tree traversed leaf-by-leaf. The GUI Parser invokes multiple vision tools (Google OCR, YOLO-v8 for coarse localization, LangSAM for precise contours, pattern matching for icons, and system metadata for panel segmentation) to produce a structured DOM-like textual representation of the screen. The Critic compares before/after screenshots using DeepDiff to output a success flag and finish flag with explanations. The Actor conditions on the current observation, active subtask, parent milestone, previous action, and Critic feedback to generate the next PyAutoGUI code snippet, enabling iterative correction without any task-specific training.

## Results

On the ASSISTGUI benchmark (100 tasks across 9 applications), the proposed AutoPC multi-agent framework achieves a 46.0% overall success rate, substantially outperforming the ReAct baseline (32.0%) and the Chain-of-Thought baseline (12.0%). The largest gains appear in Design tasks (32.4% vs. 14.7% for ReAct and 5.9% for CoT) and Office tasks (40.5% vs. 27.0% and 10.8% respectively). Even the best model falls well short of human performance (85.0% overall), indicating substantial room for improvement in PC GUI automation.

## Baselines & Comparisons

AutoPC outperforms both baselines across every task category. Compared to CoT (12.0% overall), AutoPC achieves a 3.8× improvement, with the most dramatic gap in Design tasks (32.4% vs. 5.9%) and Sys. Set. tasks (75.0% vs. 0.0%), where CoT's inability to observe screen changes between steps is fatal. Against ReAct (32.0% overall), AutoPC gains 14 percentage points, with the largest margins in Design (+17.7 pp) and Office (+13.5 pp), reflecting the benefit of hierarchical planning and the Critic module for complex multi-step procedures. ReAct's iterative thought-action-observation loop helps it handle simpler tasks (Widget, Sys. Set., File Mani.) reasonably well, but it lacks a dedicated mechanism for evaluating and adjusting the planning path, which becomes a critical shortcoming on complex productivity software. Notably, even AutoPC's 46.0% success rate trails human performance (85.0%) by nearly 40 points, underscoring that PC GUI automation remains an open challenge.

## Relation to Prior Work

This paper extends the LLM-based GUI automation line of work (Android in the Wild, Mind2Web, WebShop) from mobile and web platforms to PC productivity software, introducing a fundamentally harder setting with dense visual interfaces, complex multi-step operations, and long procedural tasks. The multi-agent architecture draws on MM-ReAct and Visual Clues for its multi-tool GUI parsing strategy, and on ReAct for iterative environment interaction, but adds a hierarchical Planner and a dedicated Critic module for action assessment that prior single-agent approaches lack. A key conceptual departure is the inclusion of instructional videos as input, enabling the model to adapt to user-customized workflows in complex tools like After Effects rather than relying solely on text queries.

## Why It Matters / Open Questions

ASSISTGUI is the first benchmark targeting PC productivity software automation, a domain where current models achieve only 46% success versus 85% for humans, exposing a substantial capability gap. The dramatic ablation showing OCR removal collapses performance from 46% to 4% underscores that text grounding remains the critical bottleneck, while the near-total failure of GPT-4V-SoM (effective on web/Android) on PC GUI reveals that segmentation-based grounding does not transfer to dense productivity interfaces. Open questions include how to handle continuous operations (roto brush, mask drawing), spatial reasoning in dense text, and whether the Critic's limited gains reflect a fundamental limitation of current vision-language alignment for action verification.
