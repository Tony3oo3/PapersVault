## Problem

Minecraft and similar RL environments provide only sparse binary rewards (task complete or not), making it extremely difficult for agents to learn complex long-horizon tasks like diamond mining. Existing dense reward methods (curiosity-driven exploration, self-imitation, MineCLIP) fail to make significant progress on these tasks even after behavior cloning, because they lack the ability to summarize failure experiences and iteratively refine reward design the way human players do naturally.

## Input / Output

The system takes as input a natural-language task description (objective, initial conditions, success criteria, task flow), structured game information (block names, action space, field of view), and K=10 failed agent trajectories truncated to the last L=32 steps (containing action sequences, reward sequences, final inventory, and nearby blocks). It produces an executable Python reward function with two sub-functions (dense and sparse) whose outputs are constrained to a fixed scale: sparse ∈ {1, 0, −1} and dense ∈ {0.1, 0, −0.1}, yielding a final reward R = sgn(sparse)·1 + sgn(dense)·0.1. The LLM only decides the sign of each sub-function, not its magnitude, keeping the reward space to {±1.1, ±1.0, ±0.9, ±0.1, 0}. The reward function also receives a multi-step memory dictionary and predefined observations (nearest block distances, inventory deltas, health, location history) at each step.

## Method

Auto MC-Reward is an iterative LLM-based pipeline with three components: a Reward Designer (GPT-4) that writes the reward function as interpretable Python code using Chain-of-Thought comments, a Reward Critic that checks the code for syntax and semantic errors (up to 3 review rounds), and a Trajectory Analyzer that summarizes failure causes from collected agent trajectories and proposes refinement suggestions. The loop is: Designer generates code → Critic verifies → agent is trained with PPO+GAE (with KL divergence to a frozen imitation-learning foundation model) → trajectories are collected → Analyzer diagnoses failures → Designer revises the code. The key distinction from prior work is that the reward is white-box, interpretable code rather than black-box scalar values, enabling targeted, experience-driven refinement (e.g., adding a lava penalty after observing deaths, then adding a pitch constraint to prevent the agent from simply looking away from lava). Foundation models are pre-trained via imitation learning on ~11M frames of GITM-generated diamond-mining data, and the LLM is invoked only once per full training round, making its computational overhead negligible.

## Results

On the diamond ore exploration task, Auto MC-Reward achieves 45.2% success rate with 70.0% lava escape rate and 142.8 average distance traveled, substantially outperforming sparse reward RL (0.5% success) and the best dense-reward baseline MineCLIP (40.5% success). On the tree-approaching task in plains, it reaches 73.4% success in only 972 average steps (vs. 4.3% for sparse RL and 65.6% for MineCLIP). On the full diamond-mining tech tree, Auto MC-Reward (IL+RL) achieves 36.5% success rate using only RGB and GPS observations, surpassing VPT (20.0%) while remaining competitive with GITM (55.0%) which relies on privileged Lidar and Voxel inputs.

## Baselines & Comparisons

Auto MC-Reward outperforms all baselines across all three tasks. Against sparse-reward RL, the gains are dramatic: 45.2% vs. 0.5% on diamond exploration, 73.4% vs. 4.3% on tree approach, and 56.3% vs. 12.6% on cow approach. Among dense-reward baselines, MineCLIP is the strongest competitor (40.5% diamond, 65.6% tree, 44.9% cow), but Auto MC-Reward still leads by 4.7, 7.8, and 11.4 percentage points respectively, while also achieving the lowest average steps (972 vs. 1022 on tree). Curiosity-driven and self-imitation rewards show only marginal improvements over imitation learning on diamond (39.3%/39.7% vs. 38.9%) and struggle on cow approach (13.7%/23.5%). On the full diamond-mining tech tree (Table 2), Auto MC-Reward (36.5%) surpasses VPT (20.0%) and DreamerV3 (0.01%) by large margins, though it trails GITM (55.0%) which uses privileged Lidar and Voxel observations unavailable at inference time.

## Relation to Prior Work

This paper builds on the line of automated reward function design (EUREKA, Text2Reward, L2R) that uses LLMs to generate reward signals, but departs from these concurrent works by targeting the far more complex and uncertain Minecraft open-world environment rather than constrained robotics tasks. It also extends the Minecraft RL agent literature (VPT, GITM, DreamerV3) by addressing the reward design problem orthogonally to the learning algorithm or high-level planning. The key conceptual departure is the iterative refinement loop via a Trajectory Analyzer that feeds empirical failure analysis back into the reward designer, a mechanism absent from prior LLM reward design methods that rely on one-shot generation or human feedback.

## Why It Matters / Open Questions

The paper demonstrates that LLMs can produce interpretable, code-form dense rewards that meaningfully improve RL in a complex open-world setting, with the iterative trajectory-analysis loop being the critical component for handling unforeseen failure modes (e.g., lava avoidance). However, the approach is limited to Minecraft, relies on GPT-4, and can only analyze the last 32 frames of a trajectory, restricting its ability to diagnose long-term strategic failures. Open questions include generalizability to other open-world environments, reducing the LLM dependency for scalability, and whether the white-box reward code can be transferred or composed across tasks.
