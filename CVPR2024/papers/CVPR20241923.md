## Problem

Existing salient object detection (SOD) and camouflaged object detection (COD) methods rely on task-specific specialist models, which are prone to overfitting on limited training data and fail to exploit shared commonalities across the six multimodal SOD/COD sub-tasks. No prior work has jointly trained a single generalist model across multiple modalities (RGB, depth, thermal, optical flow) and both SOD and COD, nor demonstrated zero-shot generalization to unseen task combinations such as RGB-D COD.
![Teaser figure](../imgs/CVPR20241923/cropped_page0_idx0.webp)

## Input / Output

The model accepts four input configurations—RGB, RGB+depth, RGB+thermal, and RGB+optical flow—each resized to 384×384 and randomly cropped to 352×352 during training. For multimodal inputs, supplementary modality features are concatenated with RGB features along the channel dimension and projected via an MLP. The model outputs a saliency segmentation mask and a boundary map simultaneously, with the same architecture handling all six training tasks and zero-shot RGB-D COD by swapping domain and task prompt combinations.

## Method

VSCode uses VST (Visual Saliency Transformer) with a Swin Transformer backbone as a shared foundation model to capture cross-task commonalities, augmented by 2D prompts that decompose peculiarities along two orthogonal dimensions: domain-specific prompts (one set each for RGB, depth, thermal, and optical flow) inserted in every encoder block via window-attention, and task-specific prompts (SOD vs. COD) placed in both encoder and decoder. Domain and encoder task prompts use a deep layout (fresh prompts per block with progressively more tokens: 1,1,5,10), while decoder task prompts use a shallow layout (single set propagated through all decoder layers). A prompt discrimination loss minimizes the absolute cosine similarity between aggregated prompt pairs of the same type, forcing each prompt to encode unique domain or task knowledge and preventing entanglement. The entire 2D prompt module adds only ~0.03M parameters, and the model is trained jointly on all six tasks with a batch of 12 (2 samples per task) for 150K steps, enabling zero-shot transfer to unseen task combinations by simply combining the appropriate domain and task prompts.

## Results

VSCode (Swin-T, 54.09M params) achieves S_m=0.917, F_m=0.910, E_m=0.954 on DUTS (RGB SOD), S_m=0.941, F_m=0.945, E_m=0.967 on NJUD (RGB-D SOD), S_m=0.918, F_m=0.892, E_m=0.954 on VT5000 (RGB-T SOD), S_m=0.943, F_m=0.937, E_m=0.984 on SegV2 (VSOD), S_m=0.847, F_m=0.795, E_m=0.925 on COD10K (RGB COD), and S_m=0.757, F_m=0.659, E_m=0.808 on CAD (VCOD), outperforming all specialist baselines across 26 datasets. The Swin-S variant (74.72M) further improves, reaching S_m=0.926 on DUTS and S_m=0.869 on COD10K. Notably, in zero-shot RGB-D COD, VSCode-T (S_m=0.882 on COD10K) surpasses the trained specialist PopNet (S_m=0.851) without any task-specific training.

## Baselines & Comparisons

VSCode-T (54.09M) outperforms all specialist RGB SOD baselines (VST, ICON-R, VST-T++, MENet) across all six datasets, with the largest gains on DUTS (S_m +1.6 over VST-T++) and ECSSD (S_m +0.8 over VST-T++). The generalist EVP [56] (64.52M) is the closest competitor, nearly matching VSCode-T on DUTS (both 0.917 S_m) but trailing by 0.9–1.0 S_m on ECSSD and PASCAL-S. For RGB-D SOD, VSCode-T dominates all five baselines (CMINet, VST, VST-T++, SPSN, CAVER) on all six datasets, achieving S_m=0.941 on NJUD vs. 0.928 for the best specialist (VST-T++). In RGB COD, VSCode-T surpasses MGL, UJSC, SegMar, and FEDER by 1.4–3.1 S_m on COD10K, while EVP is marginally ahead on NC4K (0.874 vs. 0.874 S_m, tied) but VSCode-S clearly wins (0.891). For VCOD, VSCode-T beats SLT-Net (164.68M) by 4.2 S_m on CAD (0.757 vs. 0.715) with fewer parameters. The zero-shot RGB-D COD result is particularly striking: VSCode-T without any RGB-D COD training data outperforms the trained specialist PopNet by 3.1 S_m on COD10K (0.882 vs. 0.851) and 7.7 S_m on CAMO (0.885 vs. 0.808).

## Relation to Prior Work

This paper builds on VST as a shared transformer foundation for multimodal segmentation and adapts the shallow/deep prompt insertion strategy from Visual Prompt Tuning (VPT). It departs from prior generalist segmentation work (e.g., EVP, which uses per-task adaptors) by decomposing task peculiarities along two orthogonal axes—domain (RGB/depth/thermal/flow) and task (SOD/COD)—via 2D prompts, rather than treating each task as a monolithic unit. It also challenges the prior framing (UJSC) that SOD and COD are fundamentally opposing tasks, arguing instead that they share substantial low-level and structural commonalities that a shared backbone can exploit.

## Why It Matters / Open Questions

The 2D prompt decomposition offers a principled, parameter-efficient (~0.03M extra params) way to handle multi-modal, multi-task segmentation, and the zero-shot transfer to RGB-D COD—outperforming a specialist trained on that task—suggests the domain×task factorization captures genuinely transferable structure. However, the zero-shot claim rests on a single unseen task combination against one baseline, leaving open whether this generalization holds for more exotic combinations (e.g., thermal COD, flow COD) or scales to additional domains. The approach also assumes a fixed set of four domains and two tasks; extending to open-ended task or domain vocabularies remains unexplored.
