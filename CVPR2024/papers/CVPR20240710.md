## Problem

Collaborative perception improves individual agent detection by exchanging perceptual messages, but existing methods still transmit high-dimensional floating-point feature maps, incurring prohibitive communication costs. Prior selection strategies (e.g., Where2comm) reduce spatial redundancy but do not address the channel-dimension overhead, and no prior work jointly optimizes both what to send and how to encode it under a shared communication budget across multiple agents.
![Teaser figure](../imgs/CVPR20240710/cropped_page0_idx0.webp)

## Input / Output

Each agent ingests either a LiDAR point cloud (encoded via PointPillar) or RGB images (encoded via CaDDN with BEV warping), producing a BEV feature map of shape H×W×C. Collaborators send only integer code indices (not feature vectors) over the communication channel; the receiver reconstructs approximate features via the shared codebook and fuses them with its own features using pointwise maximum. The final output is a set of 3D rotated boxes (class, x, y, h, w, cos α, sin α) per BEV location, evaluated at IoU thresholds of 0.30 and 0.50.

## Method

CodeFilling optimizes collaborative messages along two axes. For representation, a task-driven codebook (shared across all agents) is learned by jointly minimizing reconstruction error and a detection-performance penalty, so each code is a lossy approximation of a feature vector that is nonetheless lossless for the downstream detection task; agents then transmit only integer code indices (log₂(n_L) bits each) instead of C-dimensional float vectors. For selection, each agent broadcasts a lightweight information score map (detection confidence), then solves a proxy-constrained optimization that assigns binary spatial masks to fill each receiver's information demand up to a cap u while respecting a global bandwidth budget, using a sum-based utility that encourages complementary contributions from multiple supporters and halts selection once demand is met. The decoded features are fused via non-parametric pointwise maximum, and the entire system (encoder, decoder, codebook) is trained end-to-end with a detection loss plus a feature-reconstruction loss. This design is modality-agnostic: heterogeneous agents (LiDAR vs. camera) project into the same BEV space and communicate through the unified codebook without additional adaptation.

## Results

On DAIR-V2X and OPV2VH+, CodeFilling achieves the best perception-communication trade-off across all bandwidth settings for LiDAR, camera, and heterogeneous 3D detection. Compared to the previous SOTA (Where2comm), CodeFilling requires 1333×/1206× less communication volume on DAIR-V2X/OPV2VH+ while simultaneously improving detection AP by 11.1%/5.3%/38.4% (LiDAR/camera/heterogeneous) on DAIR-V2X and 14.8%/28.5%/28.4% on OPV2VH+ even under a 100K× bandwidth constraint. Inference speed is 36/99 ms on DAIR-V2X/OPV2VH+, comparable to Where2comm (34/94 ms) and far faster than HMViT (90/1266 ms).

## Baselines & Comparisons

CodeFilling dominates all six baselines (Where2comm, HMViT, V2VNet, DiscoNet, V2X-ViT, AttFuse) across every communication bandwidth tested on both datasets. Against Where2comm (the prior SOTA for communication efficiency), CodeFilling achieves the same or higher AP with 1333×/1206× less communication on DAIR-V2X/OPV2VH+ in the homogeneous LiDAR setting, and 115×/1078× less in the camera setting. Against HMViT (designed for heterogeneous settings), CodeFilling matches or exceeds detection performance while being 2.5×/12.8× faster at inference (36 vs 90 ms on DAIR-V2X; 99 vs 1266 ms on OPV2VH+). Against feature-transmission baselines (V2VNet, DiscoNet, V2X-ViT, AttFuse), CodeFilling achieves superior AP at every bandwidth level because it transmits compact integer code indices rather than full floating-point feature maps, reducing per-message cost by ~208×. Under pose error >0.6 m and latency >100 ms, all baselines degrade below the no-collaboration baseline, whereas CodeFilling consistently maintains a positive collaboration gain.

## Relation to Prior Work

CodeFilling sits at the intersection of two threads in collaborative perception: message selection (When2comm, Who2comm, Where2comm) and message representation (source coding in V2VNet, channel compression in DiscoNet). It departs from prior work by jointly optimizing both dimensions through a unified framework: a task-driven codebook (extending Singh et al.'s task-adaptive codebooks from 2D classification to collaborative 3D detection) handles the channel dimension, while an information-filling-driven collective selection handles the spatial dimension. Unlike Where2comm, which transmits full float32 feature maps over selected spatial regions, CodeFilling transmits only integer code indices over a sparser, collectively-optimized set of regions, and unlike HMViT, it handles heterogeneous agents through a shared codebook rather than domain adaptation.

## Why It Matters / Open Questions

Communication bandwidth is the primary bottleneck preventing large-scale deployment of collaborative perception in V2X systems, and CodeFilling's 1000×+ reduction in communication volume while matching or exceeding SOTA detection performance makes the technology far more practical for real-world bandwidth-constrained links. The unified codebook also provides a natural extensibility mechanism: new heterogeneous agents (different sensors, different backbones) can join by adding their feature basis to the shared codebook, avoiding the per-pair domain adaptation cost of prior methods. The authors note the temporal dimension remains unexplored, and the information-filling optimization, while having an analytical solution, is currently per-frame; extending it to exploit temporal redundancy across frames is a clear next step. Whether the codebook approach degrades gracefully in highly dynamic scenes with rapidly changing feature distributions is an open question.
