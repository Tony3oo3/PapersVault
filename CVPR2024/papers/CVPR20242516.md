## Problem

Existing LiDAR scene flow methods either require large-scale annotated training data or produce unconstrained pointwise flow vectors that violate the multi-body rigid-motion structure of real driving scenes. Prior work incorporating rigidity (e.g., RigidFlow) still depends on a pre-trained deep network for ICP initialization, and test-time optimization methods (NSFP, FastNSF) incur prohibitive inference latency (minutes per sample). The paper asks whether a fully learning-free, hand-crafted pipeline can match or exceed supervised baselines while respecting per-object rigidity.

## Input / Output

The method consumes two full-size LiDAR scans (no downsampling; ~177K points on Waymo, ~25K on nuScenes) at adjacent timesteps along with the ego-motion transformation (from IMU/odometry, or estimated via KISS-ICP when unavailable). Output is a per-point 3D flow vector for every point in the first scan, structured as a single rigid SE(3) transformation per object cluster rather than independent per-point displacements. The pipeline also produces a feedforward network (Ours+FNN) that takes the same scan pair and outputs flow in ~21 ms, trained on pseudo-labels generated by the ICP-Flow pipeline itself.

## Method

ICP-Flow is a learning-free pipeline that (1) applies ego-motion compensation, (2) removes ground via Patchwork++ and clusters fused non-ground points from both scans with HDBSCAN, (3) pairs clusters by spatial proximity within a velocity-bounded search window, and (4) aligns each pair using conventional ICP (PyTorch3D). The key technical contribution is a histogram-based initialization: because rigid objects share approximately the same translation over short Δt, the method discretizes all pairwise translation vectors between a cluster pair into 0.1 m bins along x, y, z, votes for the dominant bin, and uses that translation as the ICP starting pose—eliminating the need for a neural network to provide initialization. After ICP, clusters are associated via argmin over distance with inlier-ratio and distance rejection thresholds, and scene flow is recovered per cluster via the rigid transformation. A separate feedforward network (same architecture as ZeroFlow) is then trained on the ICP-Flow pseudo-labels to achieve real-time inference with only marginal accuracy loss.

## Results

On the Waymo dataset, ICP-Flow achieves the best Dynamic Foreground EPE of 0.0799 m and Acc-S of 76.10%, outperforming all baselines including the fully supervised PCA (0.1083 m EPE, 61.93% Acc-S) and the best unsupervised method NSFP (0.0966 m EPE, 61.12% Acc-S). The feedforward variant (Ours+FNN) runs in 21 ms and achieves near-perfect Static Foreground EPE (0.0044 m) and Static Background EPE (0.0058 m), while the full ICP-Flow pipeline takes 3.3 s per sample. On longer temporal gaps up to 0.4 s, ICP-Flow degrades gracefully (0.2209 m EPE at 0.4 s) while most baselines fail entirely (e.g., FastNSF reaches 4.14 m EPE).

## Baselines & Comparisons

ICP-Flow decisively outperforms all unsupervised baselines on Dynamic Foreground: it beats NSFP by ~1.7 cm in EPE (0.0799 vs 0.0966 m) and by 15 points in Acc-S (76.10 vs 61.12%), while running ~30× faster (3.3 s vs 90 s). Against the supervised PCA baseline, ICP-Flow still wins on Dynamic FG EPE (0.0799 vs 0.1083 m) and Acc-S (76.10 vs 61.93%), demonstrating that the rigid-motion + ICP design captures dynamic object motion better than learned free-form flow. The feedforward variant (Ours+FNN) trades some Dynamic FG accuracy (0.1254 m EPE) for real-time speed (21 ms) and near-perfect static scene results (0.0044 m FG EPE), still beating ZeroFlow by ~10 cm on Dynamic FG EPE. RigidFlow, which shares the clustering+ICP paradigm but uses a learned network for ICP initialization, is outperformed by ~3× in Dynamic FG EPE (0.2575 vs 0.0799 m), validating the histogram-based initialization. On the longer-horizon experiment (0.4 s gap), ICP-Flow achieves 0.2209 m EPE versus 0.1970 m for PCA, while FastNSF collapses to 4.14 m and ZeroFlow/FastFlow exceed 0.69 m, confirming that the rigid-body formulation generalizes to larger time gaps where learned flow models fail.

## Relation to Prior Work

ICP-Flow sits at the intersection of two prior threads: (1) the rigid-body scene flow line (RigidFlow, PCA, Multi-body NSF) that treats objects as rigidly moving clusters, and (2) the test-time-optimization / pseudo-label distillation line (NSFP, FastNSF, ZeroFlow) that avoids manual annotation. The key departure is replacing the learned initialization in RigidFlow with a hand-crafted histogram-based translation vote, and replacing the expensive per-sample optimization of NSFP/FastNSF with a single ICP pass per cluster pair. The feedforward network (Ours+FNN) reuses the ZeroFlow architecture but is supervised by ICP-Flow's pseudo-labels rather than NSFP's, making the entire pipeline annotation-free and training-light.

## Why It Matters / Open Questions

The practical impact is that scene flow can be computed without any training data, manual labels, or multi-month GPU runs for pseudo-label generation, which lowers the barrier for large-scale unsupervised perception pipelines. The ability to generalize to 0.4-second temporal gaps—where supervised and self-supervised feedforward models collapse—opens the door to processing temporally downsampled LiDAR sequences. Limitations remain: the method is purely geometric (no semantics), struggles with similar nearby objects, deformable vehicles, and sparse clusters, and the 3.3 s per-sample runtime of the core method (vs. 21 ms for the FNN) still limits real-time deployment of the highest-quality variant. The authors note future work on integrating the pipeline into a neural network to exploit both geometric and semantic features.
