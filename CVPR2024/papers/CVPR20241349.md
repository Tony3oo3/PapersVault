## Problem

While prior work has probed LLM internal representations for a fixed set of visual attributes (color, shape), it remains unclear how broadly language models encode visual world knowledge and whether text-only models can produce useful visual data. This paper asks two questions: (1) what do LLMs actually know about the visual world, and (2) can we train a vision system for natural images using only a text-only model as the data source?
![Teaser figure](../imgs/CVPR20241349/cropped_page1_idx1.webp)

## Input / Output

The LLM receives a natural-language description of a visual concept (e.g., 'a sunny summer day on a beach') and outputs executable code in one of four languages (python-matplotlib, python-turtle, Processing, or TikZ), which is then compiled to render a 384×384 image. For recognition, the input is Processing code describing a human drawing and the output is a selected concept label from a 5-way list. For the vision training pipeline, the 80k LLM-generated images (augmented to 1.3M via MixUP) serve as the unlabeled corpus for contrastive pre-training a ResNet-50.

## Method

The paper introduces a three-part 'vision check-up' protocol: (i) generation, where LLMs are prompted to write rendering code for concepts of increasing complexity (shapes → objects → scenes) and evaluated via CLIP image-text retrieval rank, LPIPS diversity, and FID; (ii) recognition, where models classify crowd-sourced human drawings (collected via a Pictionary-style interface) represented as Processing code; and (iii) iterative text-based self-feedback, where the model is repeatedly prompted to improve its own generated code, closing a self-talk loop that measurably raises fidelity. For the vision training contribution, a ResNet-50 is pre-trained with MoCo-v2 contrastive learning on 1.3M LLM-generated images (384×384, 200 epochs, batch 256), then evaluated via linear probing on ImageNet-1k and 5-NN retrieval on ImageNet-100. The key finding is that combining LLM-generated images with texture-rich Shaders-21k procedural images outperforms all prior procedural-generation baselines, demonstrating that text-only models capture visual properties complementary to existing synthetic data sources.

## Results

On the vision backbone pre-training task (ResNet-50, MoCo-v2, 1.3M images, 200 epochs), the best configuration—LLM-generated images combined with Shaders-21k—achieves 46.03% top-1 linear accuracy on ImageNet-1k and 43.36% 5-NN retrieval accuracy on ImageNet-100. LLM-generated images alone (with GPT-4) reach 36.16% and 27.44% respectively, already surpassing dead-leaves (20.00%/12.76%) and fractals (23.86%/17.24%) but trailing Shaders-21k alone (44.83%/43.24%). On the recognition task, GPT-3.5 achieves 0.380 accuracy on scene classification (vs. 0.2 chance), while GPT-4 and Davinci remain near chance level (0.212 and 0.221).

## Baselines & Comparisons

Against dead-leaves [6], LLM-generated images alone win decisively: 36.16% vs. 20.00% on ImageNet-1k linear and 27.44% vs. 12.76% on ImageNet-100 5-NN. Against FractalDB-1k [21], the margin is similar (36.16% vs. 23.86% linear; 27.44% vs. 17.24% 5-NN). Against Shaders-21k [5], LLMs alone lose (36.16% vs. 44.83% linear), but the combined LLMs+S-21k configuration wins on both metrics (46.03% vs. 44.83% linear; 43.36% vs. 43.24% 5-NN), demonstrating complementary visual properties. Against Stable Diffusion [29] (used as an oracle for image-text fidelity), LLMs score substantially lower on FID and CLIP retrieval, confirming that LLM-generated images are far from photorealistic; however, the paper's contribution is not image realism but the semantic content sufficient for representation learning.

## Relation to Prior Work

This paper extends Bubeck et al.'s [8] demonstration that GPT-4 can render images via TikZ/JavaScript into a systematic, hierarchical evaluation framework (shapes → objects → scenes) across multiple programming languages and LLMs. For the vision pre-training component, it builds directly on the procedural generation literature (dead-leaves [6], fractals [21], Shaders-21k [5]) by introducing LLM-generated images as a new data source, while departing from prior probing studies [9, 22, 36] that examine fixed attributes in LLM representations by instead using open-ended code generation and recognition as the test. The self-feedback correction loop is a novel mechanism not present in prior LLM image-generation work.

## Why It Matters / Open Questions

The paper provides the first systematic benchmark (Visual Aptitude Dataset) for measuring LLM visual competence, revealing a striking asymmetry: models generate complex scenes well but fail to recognize them, contradicting the 'creation is hard, verification is easy' principle. The finding that LLM-generated images combined with texture-rich procedural data (Shaders-21k) outperform all prior procedural baselines for vision pre-training suggests text-only models can serve as a scalable data source for visual representation learning. Key limitations include the lack of texture/realism in LLM images (poor FID), the weak recognition capability, and the gap between LLM-trained backbones (46.03) and real-data baselines (55.59) on ImageNet-1k, leaving open whether this approach can close the gap with natural images at scale.
