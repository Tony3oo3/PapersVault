## Problem

Existing safety-critical scenario generation methods for autonomous vehicles are limited in diversity and complexity, often covering only narrow ranges of adversarial situations. While LLMs could theoretically generate Scenic code directly from textual scenario descriptions, this approach fails due to hallucinated APIs and non-compilable output caused by the scarcity of Scenic training examples. The paper addresses how to reliably bridge natural language scenario descriptions to executable CARLA simulations.
![Teaser figure](../imgs/CVPR20240073/cropped_page1_idx0.webp)

## Input / Output

The agent takes unstructured text instructions (e.g., 'Provide a description of a safety-critical scenario where the ego vehicle is driving on a straight road') and produces a complete, executable Scenic script that runs in CARLA. Because Scenic is a probabilistic programming language, a single generated script samples parameters like ADV_SPEED and ADV_DISTANCE to yield multiple distinct scenes per scenario. The ego vehicle is controlled by an RL-trained model (PPO, SAC, or TD3), so the generated code only specifies adversarial vehicle behaviors, road geometry, and relative spawn positions.

## Method

ChatScene is a four-step LLM agent that avoids direct code generation by using retrieval-augmented assembly. First, GPT-4 generates a natural language scenario description; second, the description is decomposed via few-shot prompting into structured sub-descriptions for adversarial behavior, road geometry, and relative spawn position; third, each sub-description is encoded with Sentence-T5 and used to query a pre-built faiss vector database of Scenic code snippets (constructed from the Scenic repository plus GPT-4 few-shot generation with manual verification); fourth, the retrieved snippets are assembled into a complete Scenic script. A key differentiator is an iterative refinement loop that tracks collision-associated parameters, fits a Gaussian to them, and narrows the sampling range to [μ−σ, μ+σ] to concentrate generation on the most adversarial regions of parameter space.

## Results

On the CARLA Challenge's eight base traffic scenarios, ChatScene achieves an average collision rate of 0.831, a 15% increase over the strongest baseline (CS at 0.676), and the lowest overall score of 0.482 (16% below the best baseline CS at 0.573). ChatScene also achieves the highest average displacement error (ADE) of 4.567, indicating substantially greater scenario diversity compared to baselines (next best: AT at 1.694). When used for adversarial fine-tuning of a SAC ego vehicle, ChatScene-generated scenarios reduce the collision rate to 0.043 (a 51% reduction from the pre-finetuning 0.559) and raise the overall score to 0.905, outperforming the next-best baseline (AT at CR 0.135, OS 0.864) by an additional 9% in collision rate reduction.

## Baselines & Comparisons

ChatScene outperforms all four baselines on every metric across all eight base scenarios. In collision rate, ChatScene (0.831 avg.) surpasses the strongest baseline CS (0.676) by 15 percentage points, and LC (0.584) and AS (0.586) by roughly 25 points. In overall score (lower is more challenging), ChatScene (0.482) beats CS (0.573) by 16% relatively, with AT (0.596) and LC/AS (~0.62) trailing further. In scenario diversity (ADE), ChatScene (4.567) dramatically exceeds AT (1.694), the next-best method, by nearly 3×, while LC, AS, and CS all remain below 0.6. For the adversarial fine-tuning experiment, ChatScene-trained ego vehicles achieve the lowest collision rate (0.043) and highest overall score (0.905), beating AT (CR 0.135, OS 0.864) by 9% in collision reduction and 4.3% in overall score, confirming that the greater scenario diversity and adversarial intensity translate into more effective robustness training.

## Relation to Prior Work

This paper positions itself at the intersection of knowledge-based and adversarial scenario generation for autonomous vehicles, explicitly combining the strengths of both categories that prior work treats separately. It builds directly on Scenic as the domain-specific language for CARLA scene specification and on the Safebench platform for standardized evaluation, but departs from prior LLM-for-driving work (DriveGPT4, DriveLM) by using LLMs not for real-time decision-making or description generation but as a knowledge source to curate a retrieval database of Scenic code snippets. The key methodological departure is the indirect RAG-based code assembly strategy, motivated by the observation that direct LLM code generation for Scenic produces non-compilable scripts due to API hallucination and training data scarcity.

## Why It Matters / Open Questions

ChatScene provides a practical, extensible pipeline that lowers the barrier to generating diverse safety-critical test scenarios from natural language, which is valuable for AV safety validation where real-world data collection is prohibitively expensive. The retrieval-database approach is a reasonable workaround for LLM code hallucination in niche DSLs, but its scalability is limited by the manual curation of initial snippets and the fixed set of three components (behavior, geometry, spawn position). Open questions include whether the approach generalizes beyond CARLA's 8 base scenarios to truly open-ended urban driving, whether the Gaussian-distribution assumption for collision-prone parameter refinement holds in more complex multi-agent settings, and whether the multimodal extensions (text/image/video) the authors envision are feasible without fundamentally rearchitecting the retrieval pipeline.
