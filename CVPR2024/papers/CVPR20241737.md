## Problem

KPConv, which stores convolutional weights at fixed spatial kernel point positions, was a pioneering point cloud architecture but has been outperformed by MLP-based networks that adopted modern depth, width, and training strategies. The kernel point principle—encoding geometry directly in weight placement rather than through learned MLP encodings—remains underexplored in the context of contemporary deep network designs and attention mechanisms.
![Teaser figure](../imgs/CVPR20241737/cropped_page0_idx0.webp)

## Input / Output

The method consumes variable-length 3D point clouds with 5-channel features (constant 1, RGB, z-coordinate for S3DIS; plus 3 surface normals for ScanNetv2), subsampled at 0.04 m or 0.02 m voxel resolution. Points are stacked into variable-size batches with gradient accumulation (effective batch size 24 for segmentation, 64 for classification). For segmentation, the output is a per-point softmax over 13 (S3DIS) or 20 (ScanNetv2) semantic classes; for shape classification, a single class label is produced via global average pooling over the encoder features.

## Method

KPConvD replaces the full matrix-weighted KPConv with a depthwise design: each kernel point holds a single C-dimensional weight vector applied via Hadamard product, and each neighbor is assigned to its nearest kernel point (rather than summing all kernel influences), enabling more kernel points at no extra cost. KPConvX augments KPConvD with kernel attention: a two-layer MLP generates grouped modulation vectors (G=8 groups) from the central point's features, which are multiplied element-wise with the kernel weights, effectively re-weighting spatial regions based on context. This attention is geometric (indexed by kernel point position) rather than topological (indexed by neighbor identity), giving it a stable spatial order that neighbor-based attention lacks. The full architecture uses inverted bottleneck blocks, partition-based grid pooling with √2 channel scaling, DropPath regularization, and AdamW training, yielding a 44-block encoder plus 4-block decoder (KPConvX-L) that achieves state-of-the-art mIoU on S3DIS, ScanNetv2, and ScanObjectNN.

## Results

On S3DIS Area 5, KPConvX-L achieves 73.5% mIoU, 78.7% mAcc, and 91.7% OA, outperforming the previous best (PointVector/PointMetaBase at 72.3% mIoU) by +1.2 mIoU. On ScanNetv2, KPConvX achieves 76.3% mIoU with only 13.5M parameters, surpassing OctFormer (75.7%, 39.0M params) and PTv2 (75.4%, 11.3M params). On ScanObjectNN (PB_T50_RS), KPConvX-L reaches 88.9% OA and 87.3% mAcc (mean over 10 runs), outperforming PointVector (87.8% OA, 86.2% mAcc) and PointNeXt (87.7% OA, 85.8% mAcc).

## Baselines & Comparisons

On S3DIS, KPConvX-L (73.5% mIoU) outperforms all 9 competing methods, with the closest competitors being PointVector and PointMetaBase at 72.3% mIoU (a +1.2 gap), followed by StratTrans at 72.0% and PTv2 at 71.6%. On ScanNetv2, KPConvX (76.3% mIoU, 13.5M params) beats OctFormer (75.7%, 39.0M params) by +0.6 mIoU while using roughly 3× fewer parameters, and surpasses PTv2 (75.4%, 11.3M params) by +0.9 mIoU. On ScanObjectNN, KPConvX-L (88.9% OA, 87.3% mAcc) leads PointVector (87.8% OA, 86.2% mAcc) by +1.1% on both metrics, and outperforms PointNeXt (87.7% OA, 85.8% mAcc) by +1.2% OA and +1.5% mAcc. The original KPConv baseline (67.1% mIoU on S3DIS, 69.2% on ScanNetv2) is surpassed by +6.4 and +7.1 mIoU respectively, demonstrating the cumulative gains from depthwise design, kernel attention, and modern architecture. Notably, the lighter KPConvD-L variant (72.2% mIoU on S3DIS) remains within 0.2% of KPConvX-L while running 35% faster and using 32% less GPU memory, offering a strong efficiency–accuracy trade-off.

## Relation to Prior Work

KPConvX extends the kernel point convolution lineage (KPConv, SPNet) by replacing full matrix weights with depthwise Hadamard-product weights and adding a geometric attention mechanism over kernel points, drawing the modulation design from image involution. Architecturally, it adopts modern deep-network practices from ConvNeXt and PointNeXt (inverted bottlenecks, deeper stacks, √2 channel scaling) and from Point Transformer V2 (partition-based pooling). The key conceptual departure from recent point transformers is that attention is applied to fixed spatial kernel positions rather than to variable neighbor features, making the attention itself a geometric encoding that eliminates the need for separate positional encodings.

## Why It Matters / Open Questions

The paper demonstrates that a geometrically-structured attention operator can match or exceed topological (neighbor-based) attention while being substantially more efficient—KPConvD-L runs 80% faster and uses 20% of the GPU memory of the original KPConv while improving mIoU by +3.7. This positions kernel-point methods as a competitive alternative to the transformer-dominated point cloud landscape, particularly for resource-constrained deployment. The authors explicitly flag an open question: whether the topological vs. geometric nature of local feature extractors fundamentally shapes what information a network learns, and whether the two can be combined to separate topological and geometric features in a single architecture.
