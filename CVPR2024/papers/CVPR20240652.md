## Problem

Score distillation-based text-to-3D generation (SDS, VSD) requires thousands of sequential gradient-based optimization iterations over 3D parameters, resulting in prohibitively long generation times (e.g., ~10 hours per shape on an A100). Existing parallel sampling techniques such as Picard iterations for ODEs cannot be directly applied because 3D generation involves momentum-based optimizers (Adam) and representations with changing dimensionality (e.g., 3D Gaussian Splatting split-and-prune), both of which break the fixed-dimension, additive-update assumptions of classical Picard iteration.

## Input / Output

The method is a drop-in wrapper that takes a text prompt and produces a 3D shape in any score-distillation-compatible representation (NeRF, DMTet, SDF, or 3D Gaussian Splatting). It requires multiple GPUs (8× A100 in experiments) with one pretrained 2D diffusion model per GPU; the window size is set to one less than the GPU count, with the remaining GPU handling sequential rollout. For VSD, independent LoRA copies are maintained per GPU without cross-GPU communication, and the 3D parameters are randomly allocated across GPUs each iteration.

## Method

DreamPropeller generalizes Picard iterations by allowing the computational unit s to be any function h(g(θ_τ), θ_τ) equipped with a pseudo-inverse h†(·,·) with respect to the first argument, rather than being restricted to the ODE drift (g(θ)−θ)/η. For Adam-based updates, s is chosen as the raw gradient ∇_θ L and h† is the Adam update step itself; for 3D Gaussian Splatting with changing dimensionality, s uses a projection that deletes points and h† uses a split-and-clone unprojection. At each Picard iteration k, all s(θ_τ^k) values are computed in parallel across GPUs, then the trajectory is sequentially unrolled via nested h† applications to produce iteration k+1. Practical components include a sliding window to bound memory, fixed random seeds per iteration to eliminate stochasticity, independent per-GPU LoRA models for VSD, and an adaptive convergence threshold updated via exponential moving average of window errors.

## Results

DreamPropeller achieves 4.17×–4.69× wall-clock speedup across all five tested text-to-3D frameworks (DreamFusion, Magic3D, TextMesh, DreamGaussian, ProlificDreamer) while maintaining or slightly improving generation quality. CLIP FID scores are comparable or better (e.g., ProlificDreamer: 49.66 → 49.65; DreamGaussian: 58.33 → 58.26), and CLIP R-Precision drops by at most ~3.6 points (DreamFusion: 82.70 → 79.57). The largest speedups occur for ProlificDreamer (4.69×, 7390s → 3710s) and DreamGaussian (4.67×, 700s → 150s), where heavier per-iteration GPU workloads benefit most from parallelization.

## Baselines & Comparisons

DreamPropeller is a drop-in wrapper, so each comparison is the same base method with vs. without the acceleration. All five baselines (DreamFusion, Magic3D, TextMesh, DreamGaussian, ProlificDreamer) are consistently accelerated by more than 4× in wall-clock time. On generation quality, DreamGaussian and ProlificDreamer actually improve slightly with DreamPropeller (R-Precision 83.28→83.85 and 94.11→96.12 respectively; FID also marginally lower), likely because the fixed-point iteration lands in slightly different but equally valid local optima. DreamFusion and TextMesh show modest R-Precision drops (−3.1 and −3.6 points) but FID improves, indicating the quality loss is minimal. Magic3D shows the smallest quality change (R-Precision 88.45→87.18, FID 59.24→59.19). The paper attributes the largest speedups to ProlificDreamer and DreamGaussian because their per-iteration GPU workloads are heavier (LoRA training and sequential batch rendering, respectively), making parallel delegation across GPUs more effective.

## Relation to Prior Work

This paper generalizes Picard iterations (Shih et al., 2023), which parallelized ODE solving for 2D diffusion sampling, to the fundamentally different setting of score-distillation-based 3D generation. The key departure is that 3D generation operates in parameter space with momentum-based Adam updates and potentially changing dimensionality (e.g., 3D Gaussian Splatting split/prune), neither of which is compatible with vanilla Picard's additive prefix-sum structure. The authors introduce a pseudo-inverse formulation h† that subsumes both the standard drift-based Picard update and the Adam/3DGS-specific cases, making the method a drop-in wrapper orthogonal to the underlying 3D representation (NeRF, DMTet, SDF, 3DGS) and distillation algorithm (SDS, VSD).

## Why It Matters / Open Questions

The consistent >4× wall-clock speedup across all five tested frameworks (NeRF, DMTet, SDF, 3DGS, VSD) with negligible quality degradation makes text-to-3D generation substantially more practical, reducing e.g. ProlificDreamer's runtime from ~2 hours to ~1 hour on 8 A100s. The drop-in, representation-agnostic design means existing pipelines can adopt the acceleration without architectural changes. Open questions include how speedup scales beyond 8 GPUs, whether the fixed-point approximation error can be further reduced to recover exact sequential results, and whether the approach extends to amortized or few-step 3D generation settings where per-iteration compute is already low.
