## Problem

Iterative Vision-and-Language Navigation (IVLN) requires agents to retain and exploit memory across multiple episodes in a tour, but the navigation history is highly unstructured and multi-modal (language, vision, time, location) with only sparse, ambiguous supervision from instruction-path correspondences. Prior approaches either fail to leverage tour history effectively (TourHAMT) or rely on close-vocabulary detectors limited to a fixed set of categories requiring extra annotation and fine-tuning (MAP-CMA), preventing generalization to unseen scenes.
![Teaser figure](../imgs/CVPR20240897/cropped_page0_idx0.webp)

## Input / Output

The agent receives a natural language instruction per episode and captures 360° panoramic images at each position, along with its current heading and elevation. The LLM extracts a variable-length keyword set from each instruction, and the OVD detector processes each panoramic image against those keywords to produce detection boxes with labels, confidence scores, and absolute headings. The output is a navigation action (discrete view selection in IR2R or continuous low-level actions in IR2R-CE) plus an incrementally updated omnigraph whose nodes are viewpoints tagged with keywords and whose edges encode spatial connectivity.

## Method

OVER-NAV combines three components: (1) GPT-3.5 extracts scene-relevant keywords (milestones) from each instruction, (2) OWL-ViT (ViT-L/14) performs open-vocabulary detection of those keywords in panoramic views at each visited viewpoint, and (3) an omnigraph graph is maintained where nodes are keyword-tagged viewpoints and edges encode connectivity, incrementally refined as the agent revisits locations with new instructions. At inference, a local ego-centric subgraph is extracted within a distance threshold d_n, keywords are filtered to one box per keyword per viewpoint, and each keyword is fused with a distance embedding and a heading/view-index embedding (sin/cos encoding) via layer-normalized linear projections. The resulting positional keyword embeddings are concatenated and appended to the instruction embedding (discrete/HAMT) or used as key/value in cross-attention with the instruction (continuous/MAP-CMA), providing the agent with a structured, open-vocabulary scene memory without requiring retraining or extra annotation for new scenes.

## Results

On IR2R (discrete), OVER-NAV achieves 62.0 t-nDTW (val-seen) and 55.0 t-nDTW (val-unseen), improving over the HAMT baseline (58.0 / 50.0) by 4% and 5% respectively, while TourHAMT actually degrades to 45.0 / 32.0. On IR2R-CE (continuous), OVER-NAV reaches 56.0 t-nDTW (val-seen) and 50.0 t-nDTW (val-unseen), surpassing the strongest baseline MAP-CMA (52 / 47) by 4% and 3%. Episode-level metrics (SR, SPL, NE, OS) also improve consistently across both settings.

## Baselines & Comparisons

Against HAMT (the non-iterative baseline), OVER-NAV gains +4.0 t-nDTW on val-seen (62 vs 58) and +5.0 on val-unseen (55 vs 50), confirming that structured tour memory provides substantial benefit. Against TourHAMT, the comparison is stark: TourHAMT's naive history stacking actually *degrades* performance below HAMT (45 vs 58 val-seen t-nDTW), whereas OVER-NAV's omnigraph representation recovers and exceeds the baseline, highlighting that unstructured memory is harmful without proper organization. In continuous environments (IR2R-CE), OVER-NAV outperforms MAP-CMA—the strongest prior IVLN-CE method—by +4.0 t-nDTW val-seen (56 vs 52) and +3.0 val-unseen (50 vs 47), while also improving NE from 6.4 to 5.8. All CMA variants (TourCMA, PoolCMA, PoolEndCMA) score 36–40 t-nDTW, far below OVER-NAV's 50–56, indicating that simple history pooling without semantic structure is insufficient for iterative navigation.

## Relation to Prior Work

OVER-NAV builds directly on HAMT (Chen et al., NeurIPS 2021) for discrete environments and MAP-CMA (Krantz et al., CVPR 2023) for continuous environments, extending both with a shared memory mechanism. It departs from prior IVLN work by replacing close-vocabulary semantic segmentation (RedNet, limited to 13 categories in MAP-CMA) with open-vocabulary detection (OWL-ViT) and LLM-based keyword extraction (GPT-3.5), and by introducing the omnigraph—a graph-structured representation of navigation history—as a unified alternative to both naive history stacking (TourHAMT) and occupancy/semantic maps (MAP-CMA). The OVD component draws on the broader open-vocabulary detection literature (ViLD, MDETR, GLIP, OWL-ViT) but is the first to apply it in a persistent, multi-episode navigation setting.

## Why It Matters / Open Questions

The open-vocabulary formulation eliminates the need for per-scene annotation and re-training, making the approach more practical for deployment in genuinely novel environments—a key limitation of prior IVLN methods. The omnigraph's ability to unify discrete and continuous settings under one framework is a useful architectural contribution. However, the method's reliance on an external LLM (GPT-3.5) for keyword extraction introduces a practical dependency and potential latency bottleneck, and evaluation is limited to Matterport3D-based benchmarks (IR2R, IR2R-CE), leaving open questions about scalability to very long tours, truly diverse scene types, and the cost-benefit tradeoff of the LLM call at every episode.
