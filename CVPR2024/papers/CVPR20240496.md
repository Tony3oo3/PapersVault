## Problem

Current screenshot-based pre-training for vision-language models (e.g., Pix2Struct) relies primarily on image-to-text pairing (screenshot → simplified HTML), leaving the rich spatial, structural, and semantic information inherent in web page rendering largely untapped. The paper identifies that methods producing automatically annotated, fine-grained supervision beyond basic image-text pairs remain under-explored, and that the effect of such explicit supervisions on downstream task performance has been understudied.
![Teaser figure](../imgs/CVPR20240496/cropped_page0_idx0.webp)

## Input / Output

The model consumes a single screenshot image rendered at 1280×1280 resolution, optionally overlaid with a bounding box (for region-specific tasks) or paired with a short text description (for grounding tasks). Outputs are autoregressive text sequences that vary by task: cleaned HTML, OCR word-coordinate pairs (normalized to 0–1000), attribute/tag descriptions, node-relationship labels, table structures, or layout groupings. The architecture is OCR-free (no text input required), using a ViT image encoder feeding a transformer decoder whose vocabulary is extended with 1000 discrete coordinate tokens to support localization.

## Method

S4 (Strongly Supervised pre-training with ScreenShots) renders 15M CommonCrawl web pages via Playwright headless browsers, then traverses the HTML DOM tree to extract leaf-node annotations (text, image, table, input) with positions, attributes, and parent-child relationships. From these annotations, the authors design 10 diverse pre-training tasks—Screen Parsing, OCR, Image Grounding, Element Grounding, Attribute Prediction, Node Relation Prediction, Table Detection, Table Parsing, Screen Titling, and Layout Analysis—that collectively exploit the tree hierarchy, spatial layout, and semantic attributes of web elements. Tasks are grouped into S4_NL (language-generation objectives) and S4_Loc (bounding-box-generation objectives), and during pre-training one task is sampled uniformly per image. The key insight is that the DOM tree provides cheap, multi-granular supervision (spatial, structural, semantic) that naturally mirrors downstream tasks, enabling a single autoregressive model to approach detection-specialist architectures on localization benchmarks while also improving language-generation tasks.

## Results

On localization tasks (Table 2), S4 with 15M pre-training data achieves 79.4 AP50 on ICDAR 2019 (vs. 3.3 for Pix2Struct), 84.3 accuracy on UI RefExp candidate-free, 93.1 AP50 on PubLayNet, and 99.0 AP50 on PubTables-1M. On natural language generation tasks (Table 1), S4 with 15M data reaches 55.0 Relaxed Match on ChartQA, 94.9% on RefExp_cls, 130.6 CIDEr on Widget Captioning, 105.7 CIDEr on Screen Summarization, and 61.1 Exact Match on WebSRC. The most dramatic gain is on ICDAR table detection, where S4 improves from 3.3 to 79.4 AP50 over the screen-parsing-only baseline, a 76.1-point increase. On PubLayNet and PubTables-1M, S4 matches or exceeds detection-specific architectures (DETR, DiT-B) using a generic auto-regressive model.

## Baselines & Comparisons

Against the primary baseline Pix2Struct (pre-trained on 80M private data with screen parsing only), S4 with 15M data wins decisively on all localization tasks: ICDAR 79.4 vs. 3.6 AP50, RefExp cand-free 84.3 vs. 55.1, PubLayNet 93.1 vs. 91.1, and PubTables-1M 99.0 vs. 97.0. On natural language tasks, S4 (15M) beats Pix2Struct on RefExp_cls (94.9 vs. 92.2) and WebSRC (61.1 vs. 60.4), but trails slightly on ChartQA (55.0 vs. 56.0) and Widget Captioning (130.6 vs. 133.1). Against the controlled baseline Pix2Struct* (same S4 data, screen parsing only), S4 shows consistent gains across all nine downstream tasks, with the largest margins on localization (e.g., +30.9 on RefExp cand-free, +76.1 on ICDAR with 2M data). Compared to Donut (OCR pre-training on synthetic documents), S4 substantially outperforms on ChartQA (55.0 vs. 41.8) and Screen Summarization (105.7 vs. 56.4 CIDEr), while Widget Captioning is closer (130.6 vs. 127.4). Notably, S4's auto-regressive architecture with 15M pre-training matches detection-specific models (DETR at 99.5, DiT-B at 95.4) on PubTables-1M and PubLayNet, demonstrating that rich pre-training tasks can close the architectural gap.

## Relation to Prior Work

This paper extends the screenshot-based VLM pre-training paradigm established by Pix2Struct (Lee et al., 2023), which used a single screen-parsing objective (screenshot → simplified HTML), by designing nine additional supervised tasks that exploit the full HTML DOM structure—element attributes, node relationships, spatial layout, and table semantics. The Node Relation Prediction task is a pixel-only adaptation of MarkupLM's (Li et al., 2021) markup-language objective, and the overall architecture (ViT encoder + transformer decoder with coordinate tokens) follows Pix2Struct and Donut. The key conceptual departure is treating web rendering as a cheap annotation engine that produces fine-grained, multi-task supervision at scale, rather than relying solely on image-text pairs or a single reconstruction objective.

## Why It Matters / Open Questions

The paper demonstrates that task-aligned pre-training objectives (e.g., element grounding, table detection, layout analysis) can close the gap between auto-regressive VLMs and detection-specific architectures like DeTR, suggesting that the right pre-training recipe may reduce the need for task-specific model designs in UI and document understanding. A notable limitation is that all experiments use a single architecture (Pix2Struct-base) and a single data source (CommonCrawl), so it remains open whether the gains transfer to larger models, different backbones, or non-screenshot domains. The finding that 2M of CommonCrawl data actually degrades performance relative to Pix2Struct's 80M private data highlights a distribution-shift risk that practitioners should consider when adopting the S4 pipeline.
