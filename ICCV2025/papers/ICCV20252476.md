## Problem

Existing video language models treat long videos the same way as short ones, incurring prohibitive computational and memory costs that prevent real-time interaction. No prior model can process extremely long video streams while responding to user queries within one second, limiting practical deployment in scenarios like multimodal assistants, robotics, and surveillance.
![Teaser figure](../imgs/ICCV20252476/cropped_page0_idx0.webp)

## Input / Output

Video frames are consumed sequentially at 1 fps in an online streaming fashion, with each frame encoded at two resolutions (224×224 for temporal aggregation, 448×448 for spatial detail). A text question arrives asynchronously at the end of the stream, and the model must produce a text answer (multiple-choice or open-ended) within one second. The total visual token budget is capped at 11,520 LLM tokens to guarantee real-time latency on a single A100 GPU.

## Method

Flash-VStream decouples vision and language processing into two asynchronous processes: a frame handler that continuously encodes incoming frames and updates a fixed-size Flash Memory, and a question handler that generates answers from this memory on demand. The Flash Memory comprises a Context Synopsis Memory (CSM) that maintains 60 low-resolution cluster centroids via iterative K-means to model information density along the temporal axis, and a Detail Augmentation Memory (DAM) that retrieves 30 high-resolution feature maps of key frames nearest to the largest CSM clusters. An Adaptive Multimodal RoPE (AM-RoPE) assigns flexible temporal positions to compressed cluster tokens so the LLM can reason about non-uniform temporal coverage. The architecture is initialized from Qwen2-VL-7b and fine-tuned with LoRA on a 9k LLaVA-Video instruction subset, with the visual encoder kept frozen.

## Results

Flash-VStream achieves state-of-the-art performance across all five benchmarks while using only 11,520 video tokens (53% fewer than Qwen2-VL's 24,576). On EgoSchema it scores 68.2% (vs. 64.8% for Qwen2-VL offline and 64.0% for Qwen2-VL-online), on MLVU 66.3%, on LVBench 42.0%, on MVBench 65.4%, and on Video-MME 61.2% (w/o subs) / 67.0% (w/ subs). The model achieves real-time inference (≤1 s response latency) on a single A100 GPU with FlashAttention-2, a regime in which competing models like Kangaroo, LongVA, and LongVILA cannot operate due to their higher token budgets.

## Baselines & Comparisons

Under the fair same-token-budget comparison (11,520 tokens), Flash-VStream outperforms Qwen2-VL-online on every benchmark: EgoSchema 68.2 vs 64.0 (+4.2), MLVU 66.3 vs 62.9 (+3.4), LVBench 42.0 vs 39.8 (+2.2), MVBench 65.4 vs 63.3 (+2.1), and Video-MME 61.2 vs 59.4 w/o subs (+1.8) / 67.0 vs 65.1 w/ subs (+1.9). Against the full Qwen2-VL offline model (24,576 tokens), Flash-VStream still leads on EgoSchema (68.2 vs 64.8), LVBench (42.0 vs 41.4), MVBench (65.4 vs 65.1), and Video-MME (67.0 vs 65.9 w/ subs) while using 53% fewer tokens, and matches or slightly exceeds it on MLVU (66.3 vs 66.0). Among other offline baselines, Flash-VStream surpasses Kangaroo (62.7 EgoSchema, 61.0 MVBench), LLaVA-OneVision (60.1 EgoSchema, 64.7 MLVU), and Oryx-MLLM (30.4 LVBench, 63.9 MVBench) by 3–12 points depending on the benchmark. Among online/streaming baselines, the gap is even larger: Flash-VStream exceeds VideoStreaming [44] by 24.1 points on EgoSchema (68.2 vs 44.1) and VideoLLM-Online [7] by 35.4 points (68.2 vs 32.8), confirming that the Flash Memory design is the primary driver of the improvement rather than simply the underlying Qwen2-VL backbone.

## Relation to Prior Work

Flash-VStream builds directly on Qwen2-VL's architecture (ViT encoder, merger projector, 7B LLM) and extends its Multimodal RoPE to handle flexible positions for compressed cluster features. Conceptually, it departs from prior long-video approaches (MovieChat, TimeChat, LLaMA-VID) that process all frames uniformly or use question-aware selection, instead introducing a question-agnostic dual-memory design: a Context Synopsis Memory that aggregates temporal information via K-means clustering of low-resolution features, and a Detail Augmentation Memory that retrieves high-resolution features of key frames guided by cluster sizes. The two-process asynchronous framework (continuous frame handler + on-demand question handler) distinguishes it from both offline VLMs and earlier streaming models like VideoLLM-Online, which were designed for narrower tasks like narration rather than free-form QA.

## Why It Matters / Open Questions

The paper demonstrates that real-time (<1s) video QA on extremely long streams is achievable with a fixed 11,520-token budget, saving 53% of tokens compared to Qwen2-VL's full setting while matching or exceeding its accuracy. This is practically significant for deployment on resource-constrained devices (surveillance, robotics, interactive assistants) where both latency and memory are hard constraints. Open questions include whether the clustering-based memory generalizes to even longer videos (hours to days), how the approach scales to higher-resolution or multi-camera inputs, and whether the feature bank's unbounded growth (mitigated by disk offloading) becomes a bottleneck in truly unbounded streaming scenarios.
