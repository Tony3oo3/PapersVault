## Problem

Naive multi-task learning for 3D perception (3D object detection, BEV map segmentation, 3D occupancy prediction) suffers from task conflicts because different tasks attend to different semantic regions—foreground objects, background structures, or both—causing conflicting gradient signals that degrade individual task performance below single-task baselines. Existing MTL methods for 3D perception still fail to close this gap, lacking a mechanism to explicitly separate task-relevant from task-irrelevant features within a shared representation.
![Teaser figure](../imgs/ICCV20251729/cropped_page0_idx0.webp)

## Input / Output

The method consumes six-camera RGB images at 256×704 resolution, extracts 2D features with a shared ResNet-50 backbone, and lifts them into a 3D voxel grid via Lift-Splat-Shoot. From this single shared voxel representation, it simultaneously produces 3D object bounding boxes (evaluated by mAP/NDS on 10 nuScenes classes), a BEV map segmentation mask over 6 background semantic classes (mIoU), and a dense 3D semantic occupancy volume with 17 voxel-level classes (mIoU). The occupancy decoder is initialized with scene prototypes aggregated from the other two task heads, creating an asymmetric dependency where detection and map outputs inform occupancy queries.

## Method

MAESTRO introduces three modules that transform shared backbone features into task-specific representations. The Class-wise Prototype Generator (CPG) partitions semantic categories into foreground and background groups, applies a lightweight mask classifier to the voxel features, and produces group-wise prototypes via masked average pooling plus learnable embeddings. The Task-Specific Feature Generator (TSFG) then performs three sequential operations per task: (1) a task-dependent transformation (2D convolutions for BEV tasks, 3D convolutions for occupancy), (2) adaptive feature enhancement combining prototype-wise dot-product features with prototype-aware channel attention, and (3) feature suppression via a supervised gating map that drives scores toward 1 in task-relevant regions and 0 elsewhere. The Scene Prototype Aggregator (SPA) further enriches occupancy prototypes by RoIAlign-pooling detection outputs and masked-pooling map segmentation outputs, then aggregating them into the occupancy prototype group to initialize the occupancy decoder queries. This prototype-guided enhance-and-suppress mechanism is the key differentiator: rather than learning task-specific decoders from scratch, it uses semantic priors to explicitly filter the shared feature space per task.

## Results

On the nuScenes validation set, MAESTRO achieves 36.4 mAP and 43.2 NDS for 3D object detection, 51.3 mIoU for BEV map segmentation, and 38.6 mIoU for 3D occupancy prediction, outperforming the independently trained single-task baseline (Baseline-STL) by +2.6% mAP, +3.8% mIoU(Map), and +2.1% mIoU(Occ) while reducing inference latency from 405.9 ms to 250.3 ms. Compared to the naive multi-task baseline (Baseline-MTL), MAESTRO improves mAP by 3.7 points and mIoU(Map) by 7.8 points. The method also surpasses the best single-task models for each individual task: DualBEV (35.2 mAP) for detection, DifFUSER (48.3 mIoU) for map segmentation, and FB-OCC (37.4 mIoU) for occupancy prediction.

## Baselines & Comparisons

MAESTRO outperforms all 17 compared baselines across every task it supports. Against the best single-task detection model (DualBEV, 35.2 mAP / 42.5 NDS), MAESTRO gains +1.2 mAP and +0.7 NDS while also performing map segmentation and occupancy prediction simultaneously. For BEV map segmentation, MAESTRO (51.3 mIoU) surpasses the best STL method DifFUSER (48.3 mIoU) by 3.0 points and BEVFusion (47.1 mIoU) by 4.2 points. For 3D occupancy prediction, MAESTRO (38.6 mIoU) exceeds FB-OCC (37.4 mIoU) by 1.2 points and SurroundOcc (34.6 mIoU) by 4.0 points. Among existing multi-task methods, MAESTRO improves over BEVFusion (MTL) by +2.8 mAP and +7.3 mIoU(Map), and over PanoOcc by +6.9 mAP and +6.8 mIoU(Occ). Notably, MAESTRO achieves all three tasks at 250.3 ms latency, which is 155.6 ms faster than running three independent STL models (405.9 ms) while delivering superior accuracy on every metric.

## Relation to Prior Work

MAESTRO builds on the Lift-Splat-Shoot paradigm for lifting 2D image features into a shared 3D voxel representation and adapts the prototypical network concept (Snell et al., 2017) to generate class-grouped semantic prototypes as task-specific priors. It positions itself within the decoder-focused MTL lineage for 3D perception (BEVFusion, PanoOcc, SOGDet, HENet), but departs from these by introducing an explicit three-stage pipeline—prototype generation, prototype-guided feature enhancement/suppression, and cross-task prototype aggregation—rather than relying on weighted feature sharing or dynamic resolution adjustment. The key conceptual departure is treating foreground and background semantics as structurally distinct prototype groups that are assigned to different tasks, making the task-conflict mitigation mechanism explicit and interpretable rather than learned implicitly through loss balancing.

## Why It Matters / Open Questions

The result that a structured MTL framework can outperform independently trained single-task models across all three 3D perception tasks is encouraging for the field, as it suggests the persistent MTL-vs-STL performance gap in 3D perception is addressable through architectural design rather than merely optimization tricks. The 155 ms latency reduction over the STL baseline makes the approach practically relevant for real-time autonomous driving deployment. However, the evaluation is limited to a single dataset (nuScenes) and a single backbone (ResNet-50), and the added complexity of three interacting modules (CPG, TSFG, SPA) raises questions about generalizability to additional tasks, sensor modalities, or larger backbones. An open question is whether the prototype-based mechanism transfers to LiDAR-based or multi-sensor MTL settings where the semantic grouping structure may differ.
