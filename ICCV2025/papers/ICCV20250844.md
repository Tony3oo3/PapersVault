## Problem

Existing CAD reverse engineering methods rely on custom, hard-to-interpret CAD sequence representations and require training dedicated networks from scratch to learn both geometric structure and representation syntax. This limits design expressiveness, complicates integration with CAD software, and constrains training data to small hand-curated datasets. The paper asks how pre-trained LLMs' demonstrated proficiency in Python code generation can be leveraged to directly predict executable CAD code from point clouds.
![Teaser figure](../imgs/ICCV20250844/cropped_page0_idx0.webp)

## Input / Output

The method takes a dense 3D point cloud (downsampled to 256 points via furthest point sampling) and produces executable Python CadQuery code that, when run, yields a parametric B-Rep CAD model. At inference, ten candidate code sequences are generated from different point samplings, and the one minimizing Chamfer distance to the input is selected. The code output is directly interpretable by off-the-shelf LLMs (e.g., GPT-4o), enabling downstream CAD question answering and interactive editing without additional interpretation layers.

## Method

CAD-Recode consists of a lightweight point cloud projector (furthest point sampling → Fourier positional encoding → linear projection to 1536-dim query tokens) concatenated with a fine-tuned Qwen2-1.5B LLM that autoregressively generates CadQuery Python code via next-token prediction. The key design choice is representing sketch-extrude sequences as Python CadQuery code rather than custom numerical encodings, so the LLM's pre-existing code knowledge transfers directly to the CAD domain. Training is single-stage end-to-end supervised fine-tuning with negative log-likelihood loss on a procedurally generated dataset of one million CAD sketch-extrude sequences, where scripts are produced by randomized heuristics controlling topology, geometry, and modularity (reused coordinates, abstracted primitives like boxes/cylinders). This procedural generation provides full control over dataset size, feature coverage, and design patterns, eliminating the need to parse proprietary CAD formats.

## Results

On the DeepCAD test set, CAD-Recode trained on the 1M procedurally generated dataset achieves a mean Chamfer Distance of 0.30 (×10⁻³) and IoU of 92.0%, compared to the previous best (CAD-SIGNet) at 3.43 mean CD and 77.6% IoU — a roughly 10× reduction in mean CD and a 14.4-point IoU gain. On Fusion360, the improvement is even more pronounced: 0.35 mean CD and 87.8% IoU versus 7.37 and 65.6% for CAD-SIGNet. On the real-world CC3D dataset (noisy 3D scans), CAD-Recode reaches 0.76 mean CD and 74.2% IoU with only 0.3% invalidity ratio, outperforming CAD-SIGNet (14.82 mean CD, 42.6% IoU) by a wide margin. For CAD-specific question answering (SGP-Bench), the CAD-Recode → GPT-4o pipeline achieves 76.5% accuracy versus 63.2% for CAD-SIGNet → GPT-4o and 42.3% for PointLLM.

## Baselines & Comparisons

CAD-Recode outperforms all eight baselines on every reported metric across both DeepCAD and Fusion360. Against the strongest prior method, CAD-SIGNet [21], CAD-Recode (1M) reduces mean CD by ~10× on DeepCAD (0.30 vs 3.43) and ~21× on Fusion360 (0.35 vs 7.37), while raising IoU by 14.4 and 22.2 points respectively. CAD-Diffuser [34] and Point2Cyl [43] are the next-closest competitors on median CD (3.02 and 4.27 on DeepCAD), but both lack mean CD or IoU reports and show substantially higher invalidity ratios. TransCAD [12] and DeepCAD [46] report the highest mean CD values (32.3 and 42.5 on DeepCAD), reflecting the limitations of their custom numerical encodings. On the real-world CC3D dataset, CAD-Recode achieves 89% lower median CD (0.31 vs 2.90) and 30% higher IoU (74.2% vs 42.6%) than CAD-SIGNet, with an invalidity ratio of 0.3% versus 2.5%. In the CAD-QA evaluation, the code-based output of CAD-Recode is more interpretable to GPT-4o (76.5%) than the numerical DeepCAD-format output of CAD-SIGNet (63.2%), confirming the advantage of the Python code representation for downstream LLM reasoning.

## Relation to Prior Work

This paper departs from the established CAD reverse engineering pipeline (custom numerical CAD representations + dedicated neural networks trained from scratch, as in DeepCAD, CAD-SIGNet, TransCAD, and CAD-Diffuser) by repurposing a pre-trained LLM (Qwen2-1.5B) as the sequence decoder and using Python CadQuery code as the CAD representation. It also diverges from prior LLM+point-cloud work (PointLLM, 3D-LLM) that relies on complex 3D encoders and two-stage training, instead employing a minimal projector (furthest point sampling + Fourier encoding + linear layer) that is trained end-to-end with the LLM. The procedurally generated 1M-sample dataset replaces the reliance on hand-curated CAD repositories (DeepCAD, Fusion360 Gallery), giving full control over design features and scale.

## Why It Matters / Open Questions

The code-based output is directly executable and interpretable by off-the-shelf LLMs, enabling new workflows (CAD-QA, natural-language editing) that were infeasible with prior numerical representations. A key limitation is that the method currently handles only sketch-extrude sequences with extrusion operations, lacking support for revolution, fillet, and other common CAD features; the authors note this can be addressed by expanding the procedural generation heuristics. Open questions include whether scaling the LLM and dataset further will enable reconstruction of more complex, multi-operation CAD models, and whether the simple projector generalizes to noisier or sparser real-world scans beyond the CC3D benchmark.
