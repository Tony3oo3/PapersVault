## Problem

Existing diversity metrics for text-to-image models either require curated reference image datasets (FID, Recall, Coverage) or measure only generic pairwise similarity without specifying what kind of diversity is captured (Vendi Score). No prior framework simultaneously and reference-free measures both default-mode diversity (does the model generate varied attributes without explicit prompting?) and generalization capacity (can it produce a specific attribute when explicitly requested?), while providing fine-grained, interpretable per-attribute scores.
![Teaser figure](../imgs/ICCV20250645/cropped_page0_idx1.webp)

## Input / Output

The framework consumes two types of text prompts—coarse prompts containing a concept without visual attributes (e.g., 'A table in a living room') and dense prompts with a specific attribute injected (e.g., 'A metal table in a living room')—and generates n=30 images per prompt from a T2I model. Each generated image is scored via a modified VQAScore using InstructBLIP-Flan-T5-XXL, where the VQA question uses only the truncated concept-attribute phrase (e.g., 'a metal dining table') rather than the full prompt to avoid background context inflating scores. The final outputs are per-attribute-concept scores aggregated into a single summary Does-It Metric (1 − mean |S| across all pairs, higher = more balanced) and Can-It Metric (mean S for the requested attribute, higher = better generalization).

## Method

DIMCIM defines an attribute-concept score S(p_c, a) as the difference between the mean VQAScore of attribute a and the mean VQAScore of all other attributes of the same type in the generated images, establishing a relative preference signal. The Does-It Metric aggregates this over coarse prompts (no attribute specified) to quantify default-mode imbalance, while the Can-It Metric aggregates over dense prompts (attribute explicitly requested) to quantify generalization. The COCO-DIMCIM benchmark is constructed by selecting 30 COCO object classes, using Llama3.1 to extract and augment 494 plausible visual attributes across 4.83 attribute types per concept, and generating 930 coarse and 14,641 dense prompts from 31 COCO seed captions per concept. The key design choice is the reference-free, relative scoring: rather than asking 'is attribute a present?', the metric asks 'is attribute a present more than all other attributes of the same type?', making scores comparable across concepts with different attribute set sizes.

## Results

On the COCO-DIMCIM benchmark (30 concepts, 494 attributes, 930 coarse prompts, 14,641 dense prompts), DIMCIM reveals a clear trade-off between default-mode diversity (DIM) and generalization capacity (CIM) as model size scales from 1.5B to 12B parameters. LDM2.1 (1.5B) achieves the highest DIM (0.815) but lowest CIM (0.299), while LDM3.5L (8.1B) achieves the highest CIM (0.374) with a lower DIM (0.799). Increasing classifier-free guidance from 2.0 to 7.5 on Flow-Int further widens this gap: DIM drops from 0.839 to 0.802 while CIM rises from 0.261 to 0.315. A correlation of 0.85 (Pearson) is observed between attribute diversity in CC12M training images and the model's default-mode diversity scores.

**Table 1: DIMCIM scores across T2I models. DIM (Does-It Metric) measures default-mode diversity (higher = more balanced); CIM (Can-It Metric) measures generalization capacity (higher = better at generating explicitly requested attributes).**

|---|---|---|

## Baselines & Comparisons

DIMCIM does not propose a new T2I model but rather a reference-free evaluation framework, so the 'comparison' is a characterization of existing models' diversity and generalization profiles. LDM2.1 (1.5B) leads in default-mode diversity (DIM 0.815) but trails in generalization (CIM 0.299), meaning it produces more balanced attribute distributions by default but struggles when explicitly prompted for specific attributes. LDM3.5L (8.1B) achieves the strongest generalization (CIM 0.374, +0.075 over LDM2.1) at the cost of a 0.016 drop in DIM, indicating it more faithfully follows explicit attribute requests but defaults to narrower attribute distributions. FLUX.1-dev (12B) shows the lowest DIM (0.785) and a moderate CIM (0.326), suggesting the largest model has the most pronounced default-mode bias. The proprietary Flow-Int (1.9B) sits between LDM2.1 and LDM3.5L on both metrics, and its CFG sensitivity analysis (Table 2) confirms that stronger guidance consistently trades diversity for generalization. Fine-grained analysis further reveals that all models fail on negation prompts (e.g., 'bed without blanket') and that smaller models like Flow-Int struggle with specific attributes (e.g., 'convertible' car) where larger models succeed.

## Relation to Prior Work

DIMCIM builds on VQAScore [29] for image-text alignment scoring but modifies it to evaluate only the specific attribute-concept pair rather than the full prompt, reducing background confounds. It departs from prior diversity metrics (Vendi Score, FID, Recall, Coverage) by being reference-free while still measuring real-world attribute diversity, and from GRADE [33] by adding a generalization axis (Can-It Metric) alongside default-mode bias. The framework also leverages LLMs (Llama 3.1) for prompt construction, extending the template-based or free-form prompt generation approaches used in compositional T2I benchmarks like T2I-CompBench and ConceptMix, but with much denser attribute coverage per concept.

## Why It Matters / Open Questions

DIMCIM provides a practical, interpretable diagnostic tool that decomposes T2I model quality into two actionable axes—default-mode diversity and generalization capacity—rather than a single opaque score. The identified trade-off (larger models generalize better but are less diverse by default) and the 0.85 correlation between training data attribute distribution and model default-mode diversity give practitioners concrete levers for intervention. Open questions include whether the framework extends beyond everyday object concepts to more abstract or human-centric categories, whether training-data rebalancing can close the gap for anomalous cases (e.g., 'flying' birds), and whether the VQAScore-based scoring introduces systematic biases that limit cross-model comparability.
