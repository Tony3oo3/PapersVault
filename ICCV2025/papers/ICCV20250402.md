## Problem

3D part segmentation lacks foundation models because existing datasets are small (16–45 categories) and homogeneous, forcing prior methods into dataset-specific customization that prevents generalization to unseen objects or parts. The paper asks whether a scalable data engine powered by 2D foundation models can break this data barrier and enable a single model to segment any part of any object with any text query.
![Teaser figure](../imgs/ICCV20250402/cropped_page0_idx1.webp)

## Input / Output

The model takes a point cloud where each point is a 9-dimensional vector (x, y, z, surface normal, RGB) and a free-form text query. It outputs a 768-dimensional semantic feature per point in SigLIP's latent embedding space; at inference, cosine similarity between the query embedding and each point's feature yields a confidence score, and points are assigned to the highest-scoring query (or 'no label' if all scores are negative). Point clouds are voxel-sampled at 0.02 resolution after normalization, which limits the model's ability to resolve very fine-grained parts.

## Method

FIND3D combines a scalable data engine with a contrastive training recipe. The data engine renders Objaverse assets from multiple views, segments them with SAM using grid-point prompts, names each mask with Gemini, back-projects mask pixels to 3D points, and embeds the part-name text via SigLIP, yielding 2.1M (points, text-embedding) pairs across 761 categories and 124,615 unique part types. The architecture is a Point Transformer V3 backbone that serializes points via space-filling curves, followed by a 4-layer MLP projecting to SigLIP's 768-dim space (46.2M parameters total). Training uses a contrastive objective where the averaged feature over all points sharing a label is the predicted embedding, paired with the corresponding text embedding as the positive; this formulation naturally handles multi-label ambiguity (location, material, function) and partial annotations from single-view visibility. Data augmentations (random rotation, scaling, flipping, chromatic jitter) encourage reliance on 3D geometry over pose or color cues.

## Results

On the proposed Objaverse-General benchmark (unseen categories, zero-shot), FIND3D achieves 26.21% mIoU with the '{part} of a {object}' prompt, a 260% improvement over the best baseline PointCLIPV2 (10.27%). On ShapeNet-Part, FIND3D's zero-shot performance (28.39% canonical) even exceeds PointCLIPV2 which was trained on that dataset (16.91%). On the ShapeNetPart-V2 domain-shift benchmark, FIND3D (42.15%) outperforms the in-domain closed-world PointNeXt (28.70%) by 1.5×. Inference takes only 0.9s per object, making it 6×–300× faster than other open-world methods.

## Baselines & Comparisons

FIND3D outperforms all four open-world baselines (PointCLIPV2, PartSLIP++, OpenMask3D) across every dataset and prompt format. On Objaverse-General unseen categories, FIND3D (26.21%) beats PointCLIPV2 (10.27%) by 2.5×, PartSLIP++ (0.57%) by 46×, and OpenMask3D (7.01%) by 3.7×. On PartNet-E, PartSLIP++ (trained on that dataset) achieves 32.71% with the '{part}' prompt, but its performance drops 84% to 5.12% when the prompt changes to '{part} of a {object}', where FIND3D (16.86%, zero-shot) clearly wins. Against closed-world methods on ShapeNetPart-V2, FIND3D (42.15%, zero-shot) surpasses PointNeXt (28.70%, trained on ShapeNet-Part) by 1.5×, demonstrating that data scale and general training recipe can overcome domain-specific fine-tuning. FIND3D is also 6×–300× faster than open-world baselines (0.9s vs. 5.4s–296.5s per object) while matching or exceeding closed-world inference speed.

## Relation to Prior Work

FIND3D builds on the PT3 (Point Transformer V3) architecture for its 3D backbone but departs fundamentally from prior 3D part segmentation in its data strategy and training recipe. Closed-world methods (PointNeXt, PartDistill) rely on small, homogeneous datasets with per-category customization, while open-world methods (PointCLIPV2, PartSLIP++, OpenMask3D) use slow 2D-to-3D aggregation pipelines that lack native 3D geometry. This paper's key conceptual departure is replacing dataset-specific tuning with a scalable data engine (SAM + Gemini auto-annotation) and a simple contrastive objective aligned to SigLIP embeddings, mirroring the NLP/CV paradigm where internet-scale data plus a general recipe yields foundation-model-level generalization.

## Why It Matters / Open Questions

This is the first demonstration that 3D part segmentation can be performed in a truly open-world, zero-shot, cross-category manner, and the data engine recipe (2D foundation models → geometric back-projection → contrastive 3D training) is a scalable template applicable to other 3D annotation tasks. The released benchmark (Objaverse-General, ShapeNetPart-V2) addresses a real gap in evaluation diversity. Limitations include voxel-resolution constraints on fine-grained parts and symmetric-prediction artifacts from rotational equivariance; the authors identify combining 2D appearance with 3D geometry as a natural next step. Whether the data engine's annotation quality (noisy, multi-granularity, partially visible labels) is sufficient for tasks requiring precise boundaries remains an open question.
