## Problem

Existing mobile GUI navigation datasets predominantly contain tasks solvable within a single app, yet real-world workflows routinely require cross-app navigation involving context and data transfer across multiple applications. This gap leaves GUI agents poorly equipped for the longer, more complex action sequences and diverse working-memory demands that cross-app tasks impose, as confirmed by prior evaluations showing significantly worse cross-app performance.
![Teaser figure](../imgs/ICCV20250331/cropped_page1_idx0.webp)

## Input / Output

The agent receives the current screen screenshot, a user instruction (either a high-level natural-language request or a low-level step-by-step directive), a window of δ historical screenshots, and the sequence of previously executed actions. It outputs the next action from a 9-type set (CLICK, SCROLL, LONG PRESS, TYPE, COMPLETE, IMPOSSIBLE, HOME, BACK, RECENT), where CLICK/LONG PRESS include pixel coordinates, SCROLL specifies a direction, and TYPE produces a text string. The dataset spans 6 device types (including tablets and foldables) and 212 apps, with episodes averaging 15.3 steps—substantially longer than single-app datasets.

## Method

OdysseyAgent is built on Qwen-VL-Chat (vision encoder + LLM + VL adapter) and introduces a history resampler: a single-layer cross-attention module in which a small set of learnable query embeddings attends over all historical screenshot tokens (serving as both keys and values), compressing them into a fixed-size representation before concatenation with the current screen tokens, user instruction, and prior actions. This design avoids the quadratic token overhead of naively stacking all past screenshots while retaining essential cross-app context. The model is fine-tuned end-to-end on GUIOdyssey with a standard next-token prediction objective over action tokens, optionally augmented with GPT-4o-generated semantic annotations (screen description, contextual summary, decision rationale) that further improve both in-domain and out-of-domain generalization.

## Results

On the in-domain Test-Random split of GUIOdyssey, OdysseyAgent with semantic annotations (OdysseyAgent*) achieves 78.24 AMS (high-level) and 88.15 AMS (low-level) overall, outperforming the best zero-shot LVLM (InternVL2-Pro at 16.04/43.98) and the best zero-shot-with-OmniParser model (Claude3.5-Sonnet at 32.88/63.91) by a wide margin. On out-of-domain splits, OdysseyAgent* maintains 62.90/81.20 AMS (HL/LL) overall, with semantic annotations providing notable gains especially on high-level instructions (e.g., +5.43 AMS on Test-Device HL). The history resampler module contributes a consistent ~1–3 AMS improvement over the base Qwen-VL fine-tuned model, and incorporating all historical information (actions + screenshots + context) yields the best overall performance (66.84 AMS, 6.32% SR) in the ablation study.

## Baselines & Comparisons

OdysseyAgent* decisively outperforms all seven baselines on both high-level and low-level instructions. Among zero-shot LVLMs, InternVL2-Pro leads with 16.04/43.98 AMS (HL/LL), while GPT-4V (13.49/41.28), GPT-4o (13.19/42.71), and Claude3.5-Sonnet (15.80/34.18) trail slightly; OdysseyAgent* surpasses the best zero-shot by ~62 AMS on HL and ~44 on LL. Adding OmniParser grounding boosts zero-shot performance substantially (Claude3.5-Sonnet jumps to 32.88/63.91), yet OdysseyAgent* still leads by ~45 AMS (HL) and ~24 AMS (LL). GUI-specific models CogAgent (13.95/30.44) and SphAgent (15.98/30.00) perform worst, which the authors attribute to a significant domain gap between their single-app training data and cross-app tasks. The fine-tuned Qwen-VL baseline (74.67/86.32) confirms that task-specific training on GUIOdyssey is the dominant factor, while the history resampler in OdysseyAgent adds a further ~1–3 AMS gain, and semantic annotations contribute an additional ~2–3 AMS on top.

## Relation to Prior Work

This paper extends the coordinate-based GUI navigation paradigm established by SeeClick, CogAgent, and SphAgent from single-app to cross-app mobile tasks, where prior datasets (AITW, AndroidControl, MoTIF) are explicitly insufficient. Architecturally, OdysseyAgent builds directly on Qwen-VL-Chat, adding a single-layer cross-attention history resampler that compresses past screenshot tokens before the LLM, departing from the straightforward multi-image concatenation used in prior multi-turn GUI agents. The semantic annotation pipeline (screen description, contextual summary, decision rationale) draws on chain-of-thought reasoning ideas but applies them specifically to decompose each GUI step into cognitive sub-processes, a granularity not present in prior mobile GUI datasets.

## Why It Matters / Open Questions

GUIOdyssey fills a clear gap as the first large-scale cross-app mobile GUI navigation dataset, and its 15.3-step average episode length (vs. 4–7 for prior datasets) makes it a more realistic benchmark for the long-horizon, multi-context workflows that real users actually perform. The finding that out-of-domain performance drops by ~16 AMS points for high-level instructions—and that textual context summaries generalize better than raw historical screenshots—suggests current models still lack robust planning and abstraction for unseen cross-app scenarios, a significant open problem. The modest gain from the history resampler over plain Qwen-VL (~1 AMS) also raises the question of whether more sophisticated memory mechanisms (e.g., explicit working-memory buffers or retrieval) are needed to close the cross-app gap.
