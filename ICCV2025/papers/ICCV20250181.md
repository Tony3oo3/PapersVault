## Problem

VLLMs exhibit significant weaknesses in geometric reasoning and cannot reliably predict the cumulative effects of complex CAD commands, severely limiting their practical use in computational design workflows. While tool-augmentation has proven effective for enhancing LLMs in other domains, it remains entirely unexplored for CAD. Furthermore, most existing CAD automation research is confined to fixed workflows and the limited command sets captured in large-scale datasets, leaving generic CAD agent capabilities largely unaddressed.

## Input / Output

The framework accepts multimodal user queries—text, hand-drawn sketch images, 3D scan meshes, and semantically interpretable drawn commands—with CAD models pre-loaded into FreeCAD project files for direct API access. It produces executable FreeCAD Python code (via the FreeCAD Python API) that is editable and interpretable, along with parametric constraints, multiple-choice question answers, and cross-section parameterizations. The iterative execution means the agent may generate multiple code actions across timesteps, each conditioned on execution feedback (textual JSON geometry and visual renderings) from the previous step.

## Method

CAD-Assistant employs GPT-4o as a VLLM planner in an iterative plan-act-observe loop: at each timestep the planner generates a natural-language plan and a Python code action, which is executed in a FreeCAD-integrated Python interpreter that returns both textual output (e.g., JSON geometry lists) and visual renderings of the current CAD state. A set of CAD-specific tools augments the planner's geometric reasoning: a sketch parameterizer converts hand-drawn images to parametric descriptions, sketch and solid recognizers produce over-parameterized JSON representations plus renderings for multimodal understanding, a constraint checker analyzes geometric constraint impacts, and a cross-section extractor generates 2D images from 3D meshes. The agent inspects the evolving CAD geometry after each action and refines or corrects subsequent actions based on the actual solver output rather than predicting command effects. The framework is entirely training-free and highly extensible—new capabilities require only a Python docstring, enabling operation across the full FreeCAD API beyond the limited command sets in existing CAD datasets.

## Results

On the autoconstraining task (SketchGraphs), CAD-Assistant achieves PF1 of 0.979 and CF1 of 0.484 in a zero-shot setting, substantially outperforming the supervised Vitruvion model (PF1 0.706, CF1 0.238) and a GPT-4o zero-shot baseline (PF1 0.693, CF1 0.274). On SGPBench CAD question answering, CAD-Assistant with GPT-4o reaches 0.791 (2D) and 0.857 (3D) accuracy, surpassing the SGPBench instruction-tuned baseline of 0.686 (2D) and 0.782 (3D). For hand-drawn sketch parameterization, CAD-Assistant achieves 0.784 accuracy and 0.680 Chamfer Distance, matching DaVinci's accuracy (0.789) while halving the CD.

## Baselines & Comparisons

Against the SGPBench instruction-tuned baseline [45], CAD-Assistant wins on both 2D (0.791 vs 0.686) and 3D (0.857 vs 0.782) CQA accuracy using GPT-4o as planner, with gains of ~10.5 and 7.5 points respectively. Against the supervised Vitruvion model [49], CAD-Assistant achieves a dramatic improvement on autoconstraining (PF1 0.979 vs 0.706, CF1 0.484 vs 0.238) despite being zero-shot, and also outperforms it on sketch parameterization accuracy (0.784 vs 0.659) and Chamfer Distance (0.680 vs 1.586). Against DaVinci [21] on hand-drawn sketch parameterization, CAD-Assistant slightly trails on accuracy (0.784 vs 0.789) but nearly halves the Chamfer Distance (0.680 vs 1.184), indicating more geometrically faithful reconstructions. The paper also notes that for the smaller GPT-4 mini planner, CAD-Assistant's gains over the SGPBench baseline are marginal on 2D (0.614 vs 0.594) and on-par on 3D (0.783 vs 0.737), highlighting the importance of pairing tool augmentation with a sufficiently capable VLLM.

## Relation to Prior Work

This paper extends the tool-augmented LLM paradigm (Chameleon, Visual Sketchpad, ViPER-GPT) to the CAD domain for the first time, combining a VLLM planner with CAD-specific tools (FreeCAD API, sketch parameterizer, constraint checker, cross-section extractor). It departs from prior CAD foundation-model work (Vitruvion, DaVinci, CadVLM, CADLLM), which targets individual fixed-workflow tasks with supervised training, by proposing a training-free, extensible agent that handles diverse CAD queries through iterative code execution and state inspection. The geometric-reasoning findings build on SGPBench's observation that VLLMs struggle with symbolic graphics programs, but address the limitation through serialization/parametrization choices and multimodal tool outputs rather than instruction tuning.

## Why It Matters / Open Questions

By demonstrating that a zero-shot, tool-augmented VLLM can outperform supervised task-specific models on autoconstraining (CF1 0.484 vs. 0.238) and competitive on sketch parameterization, the paper establishes a practical, extensible paradigm for AI-assisted CAD that avoids the need for large-scale task-specific training data. Key limitations include dependence on a single proprietary VLLM (GPT-4o), FreeCAD-specific tooling, and evaluation on a limited set of benchmarks; open questions include whether the approach scales to complex multi-feature assemblies, generalizes to other CAD kernels, and can handle truly open-ended design intent beyond constraint application. The framework's extensibility (new tools require only a docstring) positions it as a potential foundation for broader CAD agent research.
