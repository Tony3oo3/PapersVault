## Problem

Prior embodied dialog navigation tasks assume an omniscient guide with full knowledge of the agent's location, reducing dialog to a trivial lookup and discouraging meaningful question formulation. DialNav addresses this by introducing a remote guide who knows the environment but not the Navigator's position, making location inference through dialog essential and mirroring realistic scenarios like calling a friend for directions. This setting also exposes the difficulty of holistic evaluation across interdependent subtasks (navigation, questioning, localization, and answering) that prior work has only addressed in isolation.

## Input / Output

The Navigator consumes panoramic RGB images at each graph node, a deliberately ambiguous initial instruction (e.g., 'The goal room contains a carpet'), and the accumulated multi-turn dialog history; it outputs a sequence of navigation actions, questions at chosen timesteps, and a stop decision. The Guide receives the environment graph, goal region, initial instruction, and dialog history but critically does NOT receive the Navigator's trajectory or current position, forcing it to first produce a localization estimate (a node in the graph) before generating a textual answer. Dialog is open-ended with no fixed turn limit, and each QA pair is anchored to the node the Navigator last visited.

## Method

DialNav is decomposed into five modular subtasks, each leveraging a pretrained model from a related VLN task via transfer learning: DUET (dual-scale graph transformer) with ScaleVLN weights for navigation (treating accumulated dialog as a single instruction), a learned Decision Head for whether-to-ask timing, LANA for question generation, GCN (from the LED localization task, pretrained on WAY and finetuned on RAIN) for Navigator localization, and LANA again for answer generation. The key architectural insight is the two-step Guide pipeline: upon receiving a question, the Guide first ranks all graph nodes to estimate the Navigator's location, then generates path directions from that estimated node to the goal region. The RAIN dataset (2,231 episodes) is collected via a custom tool where two human annotators interact in real-time, with the Guide using a full-house layout interface to infer position rather than being given it. All modules are trained with supervised learning on RAIN, initialized from pretrained VLN weights, and evaluated holistically through cooperative multi-agent rollouts.

## Results

On the Val Seen split, enabling dialog improves Success Rate from 18.2% (navigation only) to 27.0% (+Dialog), and providing the Guide with ground-truth Navigator location further raises SR to 31.4% (+GT Loc.), with corresponding SPL gains from 17.3 to 25.4 to 28.6. On Val Unseen and Test splits, performance degrades substantially (SR drops to 13.9% and 11.9% with dialog, respectively), which the authors attribute to the limited dataset scale (2,231 episodes) and the high cost of human-human data collection. The +GT Loc. setup consistently outperforms +Dialog across all splits, highlighting that localization error (LE ≈ 22–23 m) is a major bottleneck in the current pipeline.

## Baselines & Comparisons

As a benchmark paper, DialNav does not compare against external methods but instead ablates its own pipeline configurations. The most informative comparison is between the three dialog setups: on Val Seen, +Dialog (SR 27.0%) beats Nav. only (18.2%) by 8.8 points, while +GT Loc. (31.4%) further improves by 4.4 points over +Dialog, isolating the cost of localization error. On unseen splits, the advantage of dialog reverses (SR drops from 15.4% to 13.9% on Val Unseen), suggesting the system over-relies on dialog in unfamiliar environments where question/answer generation quality degrades. Among whether-to-ask strategies, Decision Head and Confidence Thresholding show a positive SR–DTC correlation (enabling a success-vs-efficiency trade-off), whereas Fixed-Interval shows weak correlation. For question/answer generation, LANA (fine-tuned) outperforms LLaVA-1.5 and Llama-3.1-8B on NE and LE (task-specific grounding) but scores lower on fluency (QF 4.7 vs. 9.0, AF 6.8 vs. 9.0), indicating a trade-off between task accuracy and linguistic quality.

## Relation to Prior Work

DialNav extends the vision-and-dialog navigation line (CVDN, VDN, HANNA) by removing the omniscient-guide assumption that underpins all prior dialog navigation benchmarks. Instead of a guide with perfect knowledge of the agent's location, the remote Guide must infer the Navigator's position through dialog before providing directions, making question quality and localization accuracy critical to task success. The modular architecture repurposes existing components—DUET for navigation, LANA for instruction generation (both questions and answers), and GCN from the LED task for localization—into a unified cooperative pipeline, while the task formulation draws on CVDN's navigation tasks and the Matterport3D simulator.

## Why It Matters / Open Questions

DialNav introduces the first photorealistic benchmark where communication is genuinely necessary for task success, providing a realistic testbed for studying how embodied agents should ask questions and how remote assistants should reason about agent state. The RAIN dataset (2,231 human-human dialog episodes) and the holistic evaluation framework (navigating, deciding when to ask, generating questions, localizing, and answering) fill a gap left by prior work that either assumed omniscient guides or restricted evaluation to task execution alone. Key open challenges include the high cost of data collection limiting generalization to unseen environments, error propagation across interdependent subtasks, and the need for end-to-end models that can handle long-form multimodal context. The finding that dialog degrades performance in unseen settings highlights that current modular approaches cannot yet leverage communication effectively without strong grounding.
