## Problem

Existing model merging methods are designed for in-house fine-tuned models with known task capabilities and degrade significantly (18.9%–64.4%) when scaling to large pools of diverse, partially unknown checkpoints from open-source platforms. The paper addresses the need for a merging approach that remains stable with irrelevant models and steadily improves with relevant ones, while maintaining constant memory overhead.
![Teaser figure](../imgs/ICCV20251119/cropped_page1_idx2.webp)

## Input / Output

The method consumes a pool of fine-tuned checkpoints (ViT-B/32, RoBERTa, or LLaMA2-7B with LoRA adapters) whose capabilities may be entirely unknown, a pre-trained base model θ₀, and a small training set of only 100 samples per task. It outputs a single merged model whose weights lie within the convex hull of the input checkpoints. Crucially, only a fixed number of models (top-k) need to be held in memory at any iteration, yielding constant memory overhead regardless of pool size, unlike coefficient-optimization methods that require all models simultaneously.

## Method

FW-Merging formulates model merging as min_{θ∈M} ℓ(θ) where M is the convex hull of fine-tuned checkpoints plus the base model, then applies Frank-Wolfe optimization: at each iteration it (1) computes the gradient of the objective at the current merged model, (2) solves a Linear Minimization Oracle (LMO) by selecting the checkpoint(s) minimizing ⟨∇ℓ(θ_t), s⟩, and (3) performs a local merge with an adaptive step size γ_t found via line search. Two variants are provided: FW_hard selects a single most-relevant checkpoint per iteration with layer-wise LMO (block-coordinate FW), while FW_soft retrieves top-k checkpoints and solves a reduced coefficient optimization over them with task-wise LMO. The key insight is that the inner product between the current gradient and each checkpoint's parameters acts as a zero-shot relevance score, enabling the algorithm to autonomously identify and integrate the most beneficial model without requiring prior knowledge of what each checkpoint was trained on.

## Results

On 4 vision classification tasks (SUN397, Stanford Cars, GTSRB, DTD) merging 20 ViT-B/32 models, FWsoft achieves 80.1% average accuracy, surpassing the best data-informed baseline Surgery (77.9%) by 2.2 points and Adamerging (73.9%) by 6.2 points. On 4 GLUE discriminative tasks merging 8 RoBERTa models, FWhard scores 85.4 average normalized accuracy, outperforming Task Arithmetic (80.8) by 4.6 points and Ties-Merging (64.3) by 21.1 points. On 3 generative tasks (CNN/DM, PubMedQA, HumanEval) merging 16 LLaMA2-7B LoRA adapters, FWhard reaches 81.1, exceeding Task Arithmetic (75.9) by 5.2 points and DARE+TIES (16.8) by 34.3 points. FW-Merging also matches or exceeds traditional MTL (77.2 avg) while using only 100 samples per task versus 2.9K, completing in 2 minutes versus 4.2 hours.

## Baselines & Comparisons

FW-Merging (FWsoft) decisively outperforms all data-free baselines on the 20-model vision benchmark: it beats Task Arithmetic (21.2%) by 58.9 points, Ties-Merging (46.4%) by 33.7 points, DARE+TIES (9.2%) by 70.9 points, Weight Averaging (53.4%) by 26.7 points, Fisher Merging (54.6%) by 25.5 points, and RegMean (60.3%) by 19.8 points. Against data-informed methods, FWsoft surpasses Adamerging (73.9%) by 6.2 points and Surgery (77.9%) by 2.2 points on vision, while FWhard beats Adamerging by 5.9 points on GLUE discriminative tasks (85.4 vs. 79.5). On generative language tasks, FWhard (81.1) outperforms Task Arithmetic (75.9) by 5.2 points and Ties-Merging (78.5) by 2.6 points, whereas DARE+TIES collapses to 16.8, highlighting its fragility with many black-box checkpoints. FW-Merging also matches or exceeds traditional MTL (77.2 avg) at 83.1 avg while requiring only 3.4% of the training data (100 vs. 2.9K samples per task) and 2 minutes of compute versus 4.2 hours. The scaling analysis (Table 3) further shows FWsoft remains stable (73.9–74.1%) when 16 irrelevant models are added, while Task Arithmetic drops 49.1% and DARE drops 64.4%.

## Relation to Prior Work

FW-Merging repurposes the Frank-Wolfe conditional gradient algorithm (Frank & Wolfe, 1956) as an iterative model-merging procedure, where the linear minimization oracle selects the most relevant checkpoint at each step and the convex-combination update corresponds to Task Arithmetic (Mitchell et al., 2022). The layer-wise variant draws on block-coordinate Frank-Wolfe (Lacoste-Julien et al., 2013) to handle per-layer heterogeneity. Conceptually, the paper departs from prior data-informed merging methods (Adamerging, Surgery, Concrete Merging) that optimize a single set of coefficients over all models simultaneously, instead formulating merging as sequential selective integration within a convex hull, which decouples the selection problem from the coefficient optimization and yields constant memory overhead.

## Why It Matters / Open Questions

As open-source platforms like Hugging Face release an ever-growing pool of fine-tuned checkpoints with incomplete metadata, the ability to merge large, heterogeneous model collections without prior knowledge of each model's capabilities becomes practically critical. FW-Merging's constant memory footprint (selecting a fixed number of models per iteration) contrasts sharply with the linear memory cost of coefficient-optimization methods, making it more deployable at scale. However, the evaluation is limited to at most 20 models and 4–20 tasks, leaving open how the method behaves with hundreds of checkpoints or truly non-convex loss landscapes where the convex-hull assumption is most strained. The requirement of a small training set (100 samples/task) for the objective function also partially undermines the 'data-free' appeal, and whether the approach generalizes to architectures without a natural layer decomposition (e.g., transformers with tied embeddings) remains untested.
