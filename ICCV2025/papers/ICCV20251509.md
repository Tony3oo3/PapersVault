## Problem

Large Vision-Language Models (LVLMs) generate massive KV caches due to high-resolution visual tokens, creating severe memory and bandwidth bottlenecks during decoding. Existing KV cache compression methods designed for LLMs rely on all text tokens or fixed local windows as observation windows, which produce inconsistent visual token importance scores, and they apply uniform layer-wise budgets that ignore the highly non-uniform importance distributions across layers in multimodal models.
![Teaser figure](../imgs/ICCV20251509/cropped_page0_idx0.webp)

## Input / Output

The method operates on the KV cache produced after the prefill stage of an LVLM, consuming the key, query, and value tensors for both visual tokens (N_v) and instruction text tokens (N_t) at each transformer layer. It outputs a compressed KV cache in which a configurable fraction (e.g., 10%) of visual token key-value entries are evicted while all text token entries are retained, and this compressed cache is then used for autoregressive decoding to generate text tokens. The compression is applied once after prefill completes, with no additional forward passes required during decoding.

## Method

AirCache comprises two components. First, an elite observation window selects a small set of key text tokens by computing self-attention among instruction text tokens and retaining only those whose attention score from the last instruction token exceeds a relevance threshold (α=0.9); cross-modal attention from these selected tokens to visual tokens yields more consistent importance scores than using all or contiguous text tokens. Second, an adaptive layer-wise budget allocation computes per-layer strength (sum of visual importance scores) and skewness (third standardized moment of the importance distribution), then allocates more KV cache budget to layers exhibiting stronger visual attention and a more pronounced head effect. The final compressed cache retains the top-ranked visual tokens per layer according to the allocated budget, with all text token KV entries preserved.

## Results

On LLaVA-OV-7B, AirCache retains 10% of visual KV cache while achieving 79.9 ANLS on ChatQA (vs. 80.3 full cache), 65.7 on InfoVQA (vs. 66.1), 85.5 on DocVQA (vs. 87.0), and 75.3 on TextVQA (vs. 76.0) — a degradation of less than 1% on average. At the aggressive 1% retention, AirCache still scores 76.4/62.5/73.2/67.1 across the four VQA benchmarks, outperforming the next-best method (SnapKV) by an average of 6.5 points on ChatQA. In terms of efficiency, compressing to 10% of visual KV cache reduces decoding latency by 29–66% and increases throughput by 42–192% depending on batch size and prompt length (Table 3).

## Baselines & Comparisons

AirCache outperforms all five KV cache compression baselines (H2O, Elastic, PrefixKV, SnapKV) across every compression ratio and all four VQA datasets on LLaVA-OV-7B, InternVL2-8B, and Qwen2-VL-7B. The closest competitor is SnapKV, which uses a fixed observation window of recent text tokens; at 1% retention on LLaVA-OV-7B, AirCache leads SnapKV by 3.5 points on ChatQA (76.4 vs. 72.9), 4.7 on InfoVQA (62.5 vs. 57.8), 9.1 on DocVQA (73.2 vs. 64.1), and 8.9 on TextVQA (67.1 vs. 58.2). H2O and Elastic suffer the largest degradation at aggressive compression (e.g., H2O drops to 52.0 on InfoVQA at 1% vs. AirCache's 62.5), indicating their full-attention scoring is less effective for cross-modal token importance. PrefixKV performs competitively at 50% but degrades sharply at 1% (55.4 on DocVQA vs. AirCache's 73.2), suggesting its binary-search budget allocation is less adaptive than the strength-and-skewness-based allocation. Against token pruning methods (FastV, FasterVLM, IVTP), AirCache achieves a decisive advantage on VQA tasks: at 1% retention, AirCache scores 76.4 on ChatQA while FastV drops to 16.9, FasterVLM to 18.8, and IVTP to 22.5, because token pruning discards visual information before cross-modal interaction can occur, whereas AirCache preserves the full prefill computation and only compresses the stored KV cache.

## Relation to Prior Work

This paper extends the KV cache compression paradigm established for LLMs (H2O, SnapKV, PyramidKV) to the multi-modal LVLM setting, where the key challenge is that visual and textual tokens have fundamentally different importance distributions. It departs from prior LLM methods by introducing an 'elite observation window' that selects key text tokens via self-attention rather than using all or contiguous text tokens, and by allocating layer-wise budgets based on the strength and skewness of visual token importance distributions rather than uniform or pyramid-shaped schedules. The method also explicitly targets only visual tokens for compression, contrasting with unified compression approaches, and builds on H2O's relevance threshold mechanism for token selection.

## Why It Matters / Open Questions

The practical impact is significant: retaining only 10% of visual KV cache with less than 1% performance degradation while achieving 29–66% decoding latency reduction makes long-context LVLM inference substantially more tractable on existing hardware. The empirical finding that a pronounced head effect exists in visual token importance (only ~10% of tokens carry meaningful signal) provides a principled justification for aggressive compression. Open questions include whether the elite observation window generalizes to other multi-modal settings (audio, 3D), whether the method's prefill overhead (4–12%) becomes prohibitive at very large batch sizes, and whether the layer-wise budget allocation strategy transfers to models with fundamentally different visual tokenization schemes.
