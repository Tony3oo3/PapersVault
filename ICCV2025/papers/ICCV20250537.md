## Problem

Dense transformer decoders in query-based 3D object detectors incur substantial computational overhead from global attention over large key sets (4,224–30,000 tokens), making edge deployment challenging. Existing retraining-free pruning methods like ToMe and Zero-TPrune are designed for ViT models with square attention matrices and far fewer tokens, and cannot be directly transferred to 3D detectors that use distinct query-key pairs producing non-square attention maps.
![Teaser figure](../imgs/ICCV20250537/cropped_page0_idx1.webp)

## Input / Output

The method operates on multi-camera RGB images at resolutions ranging from 704×256 to 1600×800, processed by a CNN or ViT backbone into key tokens. The tgGBC module is inserted between transformer decoder layers and consumes two signals already available at runtime: classification scores (N_q × N_C from a CNN head) and the cross-attention map (N_q × N_k). The final output remains standard 3D detection predictions—bounding boxes, class labels, orientation, velocity, and attributes—since pruning keys does not alter the query count or output shape.

## Method

tgGBC (trim keys gradually Guided By Classification scores) is a zero-shot, retraining-free runtime pruning module inserted between n transformer decoder layers. It computes per-key importance by: (1) taking the max classification score per query, (2) expanding it to the key dimension, (3) element-wise multiplying with the head-averaged attention map, (4) retaining only the top-k rows corresponding to high-confidence queries, and (5) summing along columns to yield a scalar importance per key. The r least-important keys are then removed, distributed as ⌊r/n⌊ per layer. The key insight is that final predictions are determined by query count, not key count, so keys irrelevant to high-confidence predictions can be safely discarded without modifying any model parameters. Unlike ToMe's bipartite matching, tgGBC can prune up to ~90% of keys in a single layer, and the classification-score weighting ensures pruning targets keys that contribute minimally to retained predictions.

## Results

Across eight 3D detectors on nuScenes, tgGBC prunes 50–90% of transformer decoder keys while maintaining mAP within 1% of the original model (e.g., StreamPETR-VovNet-1600×640: 48.89% → 48.55% mAP; ToC3D: 54.20% → 53.43% mAP). The transformer decoder inference time is reduced by 20–50%, yielding a headline 1.99× speedup on ToC3D (77.92 → 39.17 ms). Notably, for FocalPETR-VovNet-800×320 and OPEN-VovNet-800×320, applying tgGBC actually *increases* mAP by 0.02% and 0.02% respectively, suggesting pruning acts as a mild regularizer. On an OrangePi edge device, tgGBC delivers 1.18× and 1.19× end-to-end speedups for FocalPETR and StreamPETR, respectively.

## Baselines & Comparisons

The sole explicit baseline is ToMe, a runtime token-merging method originally designed for ViT models. tgGBC decisively outperforms ToMe on every configuration tested: on StreamPETR-VovNet-1600×640, tgGBC retains 48.85% mAP versus ToMe's 46.93% (a 1.92-point gap) while also being faster (266.49 ms vs. 277.60 ms inference). The gap widens on OPEN-VovNet-800×320, where tgGBC achieves 52.12% mAP (actually exceeding the unpruned 52.07%) while ToMe drops to 49.21% and, critically, *slows down* the model (118.63 ms vs. 118.55 ms original, +0.07%), because ToMe's quadratic similarity-matrix computation is prohibitive at the 6,000-token scale typical of 3D detectors. On OPEN-ResNet101-1408×512, tgGBC preserves 51.63% mAP with a 27.23% decoder speedup, whereas ToMe loses 1.44 mAP points and achieves only a 12.87% decoder speedup. Overall, tgGBC wins on both accuracy retention and inference speed across all five model–backbone–resolution combinations, with the advantage most pronounced at higher token counts where ToMe's O(N²) matching becomes a bottleneck.

## Relation to Prior Work

This paper positions itself at the intersection of query-based 3D object detection (PETR, FocalPETR, StreamPETR, OPEN, ToC3D) and retraining-free runtime pruning for transformers (ToMe, Zero-TPrune, ATS). It departs from prior runtime pruning work by exploiting a signal unique to detection models—classification scores from the CNN head—to guide key importance, rather than relying on token similarity (ToMe) or Markov-chain convergence (Zero-TPrune). The key conceptual departure is that existing methods assume square attention matrices (ViT-style Q=K=V), whereas 3D detectors use separate queries and keys producing non-square attention maps, making direct transfer infeasible. tgGBC thus carves new ground by repurposing the classification-to-attention coupling inherent in detection decoders as a pruning criterion, requiring no retraining or calibration data.

## Why It Matters / Open Questions

The practical impact is significant for edge deployment: a ~2× transformer decoder speedup with <1% mAP loss, validated on an OrangePi, makes high-accuracy 3D detectors viable on resource-constrained hardware without any retraining pipeline. The plug-and-play design means any dense-attention 3D detector can adopt tgGBC with a single module insertion. However, the method is fundamentally limited to dense global attention and cannot apply to deformable or flash attention mechanisms, which cover a large fraction of current 3D detectors. Open questions include whether the non-monotonic performance behavior with pruning ratio r can be better characterized, and whether the occasional mAP *improvement* after pruning (observed for FocalPETR and OPEN at 800×320) reflects a generalizable denoising effect or a dataset-specific artifact.
