## Problem

Prior LLM-based tool planning methods generate plans without considering tool execution costs (time, memory), producing expensive plans whose overhead outweighs their performance gains. Additionally, existing approaches are limited to sequential planning, missing the cost-reduction potential of concurrent multi-branch execution, and no public dataset exists to evaluate cost-aware planning quality.
![Teaser figure](../imgs/ICCV20252645/cropped_page0_idx0.webp)

## Input / Output

The method consumes a natural-language task description, an input image, a toolkit of 10 open-source models (e.g., captioning, deblurring, super-resolution) each annotated with a cost attribute vector across k discretized input-size levels, and a tool dependency graph. It outputs a tool plan as a token sequence in the Tool Planning Language (TPL), where tools and dependencies are learnable tokens interleaved with structural markers ([SoP], [EoP], <SoD>, <EoD>) that encode arbitrary DAG topologies including parallel branches. Executing the plan yields the task output (an image, text, or both).

## Method

CATP-LLM has two core components. First, the Tool Planning Language (TPL) formulates tools and dependencies as trainable embedding tokens and linearizes any DAG plan into a token sequence augmented with special structure tokens, enabling the LLM to generate non-sequential multi-branch plans through standard autoregressive prediction. Second, the Cost-Aware Offline RL (CAORL) algorithm fine-tunes the LLM via a Decision Transformer: a context augmentation scheme converts per-tool cost vectors into cost-aware embedding features using a cosine importance vector tied to the current input-size level, and a reward function provides intermediate feedback after every token decision (not just at plan completion), balancing task performance P(p) against execution cost C(p) with weight α. An adaptive masking scheme prunes invalid tool/dependency tokens based on heuristic rules to reduce the action space, and two dedicated output heads (tool head, dependency head) alternate during generation to enforce valid plan structure.

## Results

On the non-sequential planning tasks in OpenCATP, CATP-LLM (Llama2-7B) achieves an average QoP of 0.192, outperforming the best GPT-4 baseline (HYDRA, QoP 0.099) by 1.94× and the best GPT-3.5 baseline (HYDRA, QoP 0.064) by 3.0×. On sequential planning, CATP-LLM achieves an average QoP of 0.261, surpassing HYDRA (GPT-4, QoP 0.256) by 1.02× and Zero-Shot (GPT-3.5, QoP 0.186) by 1.40×. CATP-LLM also achieves 100% plan validity on non-sequential tasks, compared to 41.7%–75% invalid plans for GPT-3.5-based methods, while maintaining substantially lower execution prices (e.g., $0.114 vs. $0.229 for Zero-Shot GPT-4 on non-sequential tasks).

## Baselines & Comparisons

CATP-LLM (Llama2-7B) outperforms all nine baselines on both sequential and non-sequential planning in terms of QoP. Against the strongest prompt-based competitor HYDRA (GPT-4), CATP-LLM achieves 1.02× higher QoP on sequential tasks (0.261 vs. 0.256) and 1.94× on non-sequential tasks (0.192 vs. 0.099), while also reducing execution time from 0.847 s to 1.371 s (sequential) and from 1.358 s to 0.730 s (non-sequential). Against GPT-4 Zero-Shot and Few-Shot, the QoP gap widens to 1.40× (sequential) and 1.94×–4.80× (non-sequential), with CATP-LLM also achieving substantially higher task scores (e.g., 0.585 vs. 0.485 on non-sequential). Among fine-tuning baselines sharing the same Llama2-7B backbone, CATP-LLM surpasses IFT by 99.0% and RLTF by 44.3% in average QoP on sequential tasks, and by 23.5× and 4.6× on non-sequential tasks. A notable practical advantage is plan validity: CATP-LLM produces 100% valid plans on non-sequential tasks, whereas GPT-3.5-based methods generate 41.7%–75% invalid plans due to structural errors in non-sequential dependencies.

## Relation to Prior Work

This paper extends the LLM-based tool planning line of work (HuggingGPT, HYDRA, OpenAGI/RLTF) by introducing two missing dimensions: cost awareness and non-sequential (DAG) plan structure. The Tool Planning Language (TPL) draws directly on ToolkenGPT's idea of encoding tools as learnable tokens, but generalizes it to represent arbitrary DAG structures via special structural tokens. The fine-tuning algorithm builds on the Decision Transformer for offline RL, departing from the online RL used in RLTF and TRICE by providing intermediate cost feedback at each decision step rather than only at plan completion.

## Why It Matters / Open Questions

Cost-awareness is a practical necessity for deploying LLM-based tool planning in real systems where execution time and memory directly translate to monetary cost, yet prior work has entirely ignored this dimension. The OpenCATP dataset and QoP metric provide the first standardized evaluation framework for this problem, which the community will likely adopt. Limitations include the narrow tool set (10 image-processing models), image-centric tasks, and a single-domain evaluation; open questions include whether the approach scales to hundreds of heterogeneous tools, multi-modal tasks beyond vision, and whether the cost model generalizes across hardware configurations.
