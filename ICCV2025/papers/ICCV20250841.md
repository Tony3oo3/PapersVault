## Problem

Existing generative game engines (DIAMOND, GameNGen, Oasis, etc.) are confined to specific games and cannot generalize to new scenes, limiting their potential for creating entirely new game experiences. The core challenge is achieving scene-generalizable action control: directly fine-tuning a pre-trained video diffusion model on small-scale game data causes the model to collapse into the game's visual style, destroying its open-domain generative priors.

## Input / Output

The model takes a text prompt describing the desired scene, frame-level discrete keyboard actions (7 keys: W/A/S/D/Space/Shift/Ctrl), continuous 2D mouse movement vectors, and the most recent k+1 latent frames as conditioning for autoregressive generation. Output is a 360×640 resolution video at frame-level action granularity, with a temporal compression ratio of r=4 (i.e., 4 pixel frames per latent frame). The autoregressive scheme generates N−k new frames per step by conditioning on the latest k+1 history frames, enabling unlimited-length video streams.

## Method

GameFactory decouples game-style learning from action control using a LoRA-based domain adapter and a multi-phase training strategy: Phase 1 fine-tunes LoRA on game videos to absorb the Minecraft visual style; Phase 2 freezes both the base model and LoRA, training only the action control module so it learns style-independent control; Phase 3 removes LoRA at inference, leaving the action module operating on the original open-domain model. The action control module uses cross-attention for discrete keyboard inputs and channel concatenation for continuous mouse movements, with a sliding-window grouping mechanism (window size w=3) to resolve the granularity mismatch between rn actions and n+1 latent features caused by temporal compression. For long video generation, the model is modified (inspired by Diffusion Forcing) to allow varying noise levels across frames, enabling multi-frame autoregressive prediction conditioned on previously generated frames, with loss computed only on predicted frames to avoid noise interference.

## Results

On the open-domain scene generalization evaluation, the multi-phase training strategy achieves Cam 0.0997, Flow 54.13, CLIP 0.3181, FID 121.18, and FVD 1256.94, substantially outperforming the one-phase fine-tuning baseline (Cam 0.1134, Flow 76.02, CLIP 0.3111, FID 167.79, FVD 1323.58). The domain similarity (Dom) metric confirms the multi-phase model stays closer to the original pre-trained model's generation domain (0.7565 vs 0.7345). On the in-domain Minecraft test set, the model achieves Cam 0.0839 and Flow 43.48, demonstrating strong action-following capability that transfers to open-domain scenes with only modest degradation.

## Baselines & Comparisons

The paper compares against two baselines. First, against the VPT dataset (human gameplay recordings with inherent action bias), the GF-Minecraft dataset yields a model with significantly better action following: Cam 0.0839 vs 0.1324, Flow 43.48 vs 107.67, FID 125.85 vs 156.69, and FVD 1047.59 vs 1233.15, while CLIP is marginally lower (0.3135 vs 0.3174). The VPT-trained model fails on rare actions like jumping in place or moving backward, while the GF-Minecraft model handles them correctly. Second, against a one-phase fine-tuning approach (directly fine-tuning the pre-trained model on game data without style-action decoupling), the multi-phase strategy wins on every open-domain metric: 12% lower Cam, 29% lower Flow, 28% lower FID, and 5% lower FVD, while also maintaining higher domain similarity to the original model. The paper notes that a unified quantitative benchmark against other game generation methods (DIAMOND, GameNGen, Oasis, Matrix, Genie 2) is not feasible due to differing resolutions, action spaces, and game sources, so Table 1 serves as a qualitative feature comparison rather than a head-to-head numerical benchmark.

## Relation to Prior Work

GameFactory builds on the Diffusion Forcing paradigm [6] for autoregressive long-video generation and uses a transformer-based latent video diffusion model (DiT) as its backbone. It departs from the dominant line of game video generation work (DIAMOND, GameNGen, Oasis, PlayGen, Genie 2, Matrix), which trains or fine-tunes models on game-specific data and thus cannot generalize beyond the source game's visual style. The key methodological departure is the use of a LoRA-based domain adapter to isolate game-specific style from action control, combined with a multi-phase training strategy that ensures the action control module learns style-independent control signals. The GF-Minecraft dataset also differentiates from prior game datasets like VPT by eliminating human behavioral bias through balanced atomic action sampling.

## Why It Matters / Open Questions

Scene-generalizable action control is identified as the critical missing piece for practical generative game engines, and GameFactory provides a concrete, relatively lightweight recipe (small game dataset + LoRA + action module) to achieve it without sacrificing open-domain generation quality. However, the framework remains limited to 360p resolution, a single internal 1B model, and a Minecraft-derived action space (7 keys + mouse), with no support for in-game object manipulation, diverse level design, player feedback systems, or real-time generation. Open questions include whether the style-action decoupling generalizes to more complex action spaces (e.g., physics-based manipulation), whether it scales to higher resolutions and longer contexts, and whether the approach can be extended to multi-agent or interactive narrative scenarios.
