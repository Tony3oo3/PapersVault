## Problem

Farthest Point Sampling (FPS) preserves geometric structure during point cloud downsampling but incurs O(N²) computational cost, severely limiting inference speed. Fast alternatives like random sampling or grid sampling are orders of magnitude faster but lose local geometric information, causing significant performance degradation. Existing remedies (e.g., RandLA, APPNet) require model-specific architectural redesigns, leaving no universal mechanism to retrofit FPS-trained models to fast sampling without retraining from scratch.

## Input / Output

FastAdapter operates as a plug-in module on the intermediate features of any point-based segmentation network. At each downsampling layer, it receives the downsampled point coordinates and features (p^l ∈ R^{m×3}, f^l ∈ R^{m×C}) along with a fixed set of L=100 anchor point coordinates (q ∈ R^{L×3}) selected once via FPS at the scene level. It outputs augmented per-point features (f̂^l) that are fed into the next layer, ultimately producing per-point semantic class labels through the frozen classification head. The anchor points remain spatially fixed across all layers, enabling cross-layer feature fusion.

## Method

FastAdapter comprises two sub-modules: a P2A Aggregator that injects point features into anchor points using geometry-aware weights (MLP on relative point-to-anchor offsets), then refines anchor features via a Cross-Layer Aggregator (concatenating current and previous-layer anchor features with residual) and a Spatial Aggregator (self-attention across all anchor points to expand receptive field); and an A2P Adapter that propagates refined anchor features back to each point using an Offset Embedding (MLP on positional offset) and a Geometric Weight (MLP on geometric relationships) that modulates propagation intensity per point. For FPS-trained models, all backbone parameters are frozen, FastAdapter is inserted at each downsampling layer, FPS is replaced with random sampling, and the model is fine-tuned with a combined loss of cross-entropy segmentation plus a cosine-similarity feature distillation term against the frozen FPS model's features. This lightweight fine-tuning preserves the original FPS-trained knowledge while compensating for geometric information lost by random sampling, achieving 230–315% inference speedup with <1% mIoU loss.

## Results

On S3DIS 6-fold, FastAdapter recovers most of the mIoU lost when replacing FPS with random sampling: PointNet++ drops from 54.5 (FPS) to 51.6 (RS) but recovers to 54.0 with FastAdapter (only 0.5 mIoU below FPS), while PointMetaBase-XL goes from 76.3 (FPS) to 74.6 (RS) and recovers to 75.8 (0.5 mIoU below FPS). Inference speed improves dramatically: PointNet++ throughput increases from 7.7 to 20 ins/sec (+259%), and PointMetaBase-L from 7.3 to 23 ins/sec (+315%). For models already using fast downsampling, FastAdapter provides further gains: RandLA improves from 70.2 to 71.0 mIoU on S3DIS 6-fold, and PTV3 from 77.7 to 78.2 mIoU.

## Baselines & Comparisons

The paper's primary comparison is not against external SOTA methods but rather a controlled ablation of sampling strategy within the same backbone. For PointNet++, PointMetaBase-L, and PointMetaBase-XL, directly replacing FPS with random sampling causes 1.7–3.4 mIoU drops on ScanNet, while FastAdapter recovers 80–90% of that loss (leaving only 0.5–0.6 mIoU below the FPS baseline) at 230–315% higher throughput. Against models already designed for fast downsampling, FastAdapter provides consistent but modest gains: +0.8 mIoU over RandLA on S3DIS 6-fold and +0.5 mIoU over PTV3, confirming it is complementary to specialized architectures. On SemanticKITTI, PointMetaBase-L with FastAdapter+RS achieves 71.3 mIoU, nearly matching the FPS version (71.8) while running 238% faster. Compared to external baselines in Table 1, FastAdapter-augmented PointMetaBase-XL (75.8 mIoU on S3DIS 6-fold) remains competitive with PointNeXt-L (73.9) and PointTransformer (73.5) while offering significantly higher throughput. The paper does not claim SOTA; its contribution is enabling FPS-trained models to switch to random sampling with minimal accuracy loss.

## Relation to Prior Work

FastAdapter extends the anchor-point aggregation idea from APPNet [20], which propagates features from auxiliary points back to the input cloud, by adding cross-layer and spatial feature refinement that APPNet lacks. It also draws on the adapter-tuning paradigm from NLP and vision transformers [3, 10, 13–15], repurposing the concept of inserting lightweight, trainable modules into a frozen backbone for the point-cloud setting. Unlike RandLA [11], which requires a purpose-built architecture to compensate for random sampling, FastAdapter is model-agnostic and can be embedded into any existing FPS-based point network (PointNet++, PointMetaBase, PTV3) without architectural redesign.

## Why It Matters / Open Questions

The practical impact is significant: replacing O(N²) FPS with O(1) random sampling yields 230–315% throughput gains, and FastAdapter recovers most of the resulting mIoU loss (≤0.6%) with only a small number of trainable parameters, making it attractive for latency-sensitive deployments like autonomous driving. However, the evaluation is limited to semantic segmentation on three datasets; whether the adapter transfers to detection, classification, or other fast-sampling variants (e.g., kNN-based) remains untested. An open question is whether the distillation loss (which requires running the frozen FPS model during fine-tuning) can be replaced with a self-supervised alternative to remove that dependency.
