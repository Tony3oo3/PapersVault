## Problem

Existing learning-based MVS methods rely on feature matching between views, which fails in textureless regions, reflective surfaces, and depth discontinuities. Monocular depth estimation handles these regions robustly but provides only relative depth without metric scale or multi-view geometric constraints. The paper bridges this gap by integrating monocular foundation model priors into the MVS pipeline to improve reconstruction in exactly those challenging regions.
![Teaser figure](../imgs/ICCV20251864/cropped_page0_idx1.webp)

## Input / Output

The method takes N calibrated RGB images (a reference view plus N−1 source views) along with their camera intrinsics and extrinsics. Only the reference image is additionally fed to a frozen pre-trained monocular model (Depth Anything V2, ViT-S variant) to extract monocular features and relative depth, keeping the monocular overhead minimal. The output is a metric depth map for the reference view at full resolution (e.g., 832×1152 for DTU, 2k for Tanks-and-Temples), which is then fused across views via a dynamic fusion strategy to produce a dense point cloud.

## Method

MonoMVSNet integrates monocular priors at three levels within a cascade cost-volume MVS framework. First, the reference monocular feature is fused with FPN features and propagated to source views through intra- and inter-view attention blocks enhanced by a novel Cross-View Position Encoding (CVPE) that warps features into 3D frustums and encodes camera parameters via an MLP + squeeze-and-excitation module, capturing cross-view spatial relationships that standard 2D positional encodings miss. Second, the monocular relative depth is aligned to the predicted depth via a least-squares scale-and-shift fit (using only high-confidence pixels), then used to dynamically replace one depth candidate at edge regions during inverse depth sampling, ensuring candidates capture depth discontinuities. Third, a relative consistency loss enforces that the sign of pairwise depth differences in the predicted probability-weighted depth matches that of the aligned monocular depth, applied only at the finest scale. The overall training objective combines standard cross-entropy on the probability volume at all four cascade scales with the relative consistency loss, and the network requires only 2.89M trainable parameters and 2.01 GB GPU memory at 832×1152 with 5 views.

## Results

On the DTU test set (5-view, 832×1152), MonoMVSNet achieves the best Overall score of 0.278 mm and best Completeness of 0.243 mm, outperforming the previous best MVSFormer++ (0.281 / 0.252). On the Tanks-and-Temples benchmark (21-view, 2K resolution), MonoMVSNet attains the highest mean F-score on both the Intermediate subset (68.63%) and the Advanced subset (43.58%), surpassing MVSFormer++ (67.18% / 41.60%). Notably, MonoMVSNet requires only 2.01 GB GPU memory and 2.89M trainable parameters, substantially less than MVSFormer (3.66 GB, 28.01M) and MVSFormer++ (4.71 GB, 39.48M).

## Baselines & Comparisons

MonoMVSNet outperforms all 16 baselines on the DTU Overall metric, beating the closest competitor MVSFormer++ (ICLR'24) by 0.003 mm (0.278 vs. 0.281) and GoMVS (CVPR'24) by 0.009 mm. On Completeness, MonoMVSNet leads by a wider margin: 0.243 vs. 0.252 for MVSFormer++ and 0.227 for GoMVS, indicating superior handling of textureless and reflective regions. On Tanks-and-Temples, MonoMVSNet achieves the best mean F-score on both subsets (68.63% Intermediate, 43.58% Advanced), edging out MVSFormer++ (67.18% / 41.60%) and GoMVS (66.44% / 43.07%). In terms of efficiency, MonoMVSNet uses only 2.01 GB GPU memory—64.9% less than the 'All-views monocular feature' variant and substantially less than MVSFormer (3.66 GB), MVSFormer++ (4.71 GB), and GoMVS (12.61 GB)—while having only 2.89M trainable parameters versus 28.01M (MVSFormer) and 39.48M (MVSFormer++). The method's advantage is most pronounced in challenging regions (edges, reflective surfaces), where monocular priors compensate for feature matching failures that limit all purely multi-view baselines.

## Relation to Prior Work

MonoMVSNet extends the cascade cost-volume MVS framework (CasMVSNet, MVSTER) by injecting priors from a pre-trained monocular foundation model (Depth Anything V2) into both feature extraction and depth sampling. It departs from MVSFormer and MVSFormer++, which require pre-trained ViT features for all input views, by extracting monocular features only from the reference view and transferring them to source views via a novel Cross-View Position Encoding (CVPE) that warps features into 3D space using camera parameters before attention. The dynamic depth sampling guided by aligned monocular depth at edge regions and the relative consistency loss represent new mechanisms not present in prior MVS methods, which typically rely on uniform or importance-based inverse depth sampling.

## Why It Matters / Open Questions

The paper demonstrates that selective use of monocular priors (reference view only) can outperform exhaustive use across all views while reducing GPU memory by ~65% and trainable parameters to 2.89M, making monocular-guided MVS practical for resource-constrained settings. The finding that a small ViT-S backbone suffices and that larger ViT-L actually degrades performance suggests the prior information needed is relatively compact, which is useful for practitioners choosing foundation model sizes. Open questions include whether the approach generalizes to highly dynamic or uncalibrated scenes, and whether the edge-guided sampling strategy transfers to other challenging regions beyond depth discontinuities (e.g., transparent or specular surfaces in outdoor settings).
