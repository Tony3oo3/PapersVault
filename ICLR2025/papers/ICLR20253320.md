## Problem

Existing distributed training systems for LLM pretraining (Megatron-LM, DeepSpeed, veScale) are fragmented across multiple libraries, lack composability of parallelism techniques, and suffer from inflexible architectures that make it difficult to stack and compare 4D parallelism (FSDP, TP, PP, CP) with memory/computation optimizations. This fragmentation means curating and empirically comparing training recipes requires non-trivial engineering effort, and no single PyTorch-native system unifies these capabilities with production-grade checkpointing, debugging, and elastic scaling.

## Input / Output

The system consumes a model architecture definition (e.g., Llama 3.1 8B/70B/405B), a text training corpus (C4 en variant), and TOML configuration files that specify parallelism degrees (FSDP, TP, PP, CP), batch sizes, activation checkpointing mode, and optimization toggles (Float8, torch.compile, AsyncTP), all overridable via command-line flags. Outputs include distributed model checkpoints saved via PyTorch DCP (parallelism-agnostic, loadable at different world sizes), per-GPU throughput metrics (tokens/sec) logged every 10 iterations, and loss convergence curves. A notable design choice is that the default FSDP shard degree is set to -1, meaning the system automatically uses all available GPUs without requiring the user to specify world size.

## Method

TORCHTITAN builds a unified distributed training abstraction on PyTorch's DTensor and DeviceMesh, enabling composable N-D parallelism where each dimension (FSDP, TP, PP, CP) is applied as an orthogonal transformation to the model. The key mechanism is a three-component separation: a parallelism-agnostic model definition, parallelism helpers that apply sharding via DTensor's parallelize_module API (e.g., ColwiseParallel/RowwiseParallel for TP, fully_shard for FSDP2), and a generalized training loop. For efficiency, the system employs regional torch.compile (one compilation per TransformerBlock, exploiting layer repetition), AsyncTP using SymmetricMemory buffers for intra-node P2P communication overlap, Float8 mixed precision on linear layers, and flexible activation checkpointing (full, op-level SAC, or layer-level SAC). Production readiness is achieved through DCP-based asynchronous checkpointing (5-15x faster than synchronous) and Flight Recorder integration for diagnosing NCCL hangs. The entire pipeline is demonstrated on Llama 3.1 8B–405B across 8–512 H100 GPUs, showing 65.08% speedup (1D), 12.59% (2D), and 30% (3D) over optimized baselines.

## Results

TORCHTITAN achieves training accelerations of 65.08% on Llama 3.1 8B (128 H100 GPUs, 1D FSDP), 12.59% on Llama 3.1 70B (256 H100 GPUs, 2D FSDP+TP), and 30% on Llama 3.1 405B (512 H100 GPUs, 3D FSDP+TP+PP) over optimized baselines. The largest single-technique gain comes from Float8 training, contributing +50.35% throughput on 8B/8-GPU and +50.35% on 8B/128-GPU settings. Context Parallelism enables training at sequence lengths up to 262,144 tokens on Llama 3.1 8B with only minor MFU degradation, and 4D parallelism (FSDP+TP+PP+CP) extends this to the 405B model at 512 GPUs.

## Baselines & Comparisons

TORCHTITAN is compared against Megatron-LM, DeepSpeed, and veScale primarily on feature coverage and code complexity rather than head-to-head throughput benchmarks. TORCHTITAN is the only system supporting the full 4D parallelism stack (FSDP+TP+SP+PP+CP) in a single composable framework, whereas Megatron-LM lacks FSDP+TP integration and DeepSpeed depends on Megatron-LM for TP/CP. On code complexity, TORCHTITAN's core codebase is 7K LOC versus 93K (Megatron-LM) and 94K (DeepSpeed), a 13–14× reduction. TORCHTITAN also uniquely supports Flexible SAC, torch.compile integration, and advanced pipeline schedules (ZeroBubble, Flexible-Interleaved-1F1B) that are absent in all three baselines. veScale is the weakest competitor, lacking FSDP, CP, SAC, Float8, and torch.compile entirely. The paper does not report direct throughput comparisons against these systems, positioning TORCHTITAN as a foundational component that can be leveraged by all of them.

## Relation to Prior Work

TORCHTITAN unifies previously fragmented distributed training techniques—FSDP2 (Zhao et al., 2023), Tensor/Sequence Parallelism (Narayanan et al., 2021; Korthikanti et al., 2023), Pipeline Parallelism (Narayanan et al., 2019; Huang et al., 2019), and Context Parallelism (Liu et al., 2023)—into a single PyTorch-native system built on DTensor and DeviceMesh abstractions. Unlike Megatron-LM, DeepSpeed, and veScale, which require model modifications or external dependencies to combine parallelism dimensions, TORCHTITAN's key departure is a composable, SPMD-style design where each parallelism is applied as an orthogonal transformation on DTensor-sharded parameters, enabling 4D parallelism without touching model code. The hardware-software co-design elements (AsyncTP via SymmetricMemory, Float8 training, torch.compile regional compilation) are integrated as plug-in optimizations rather than requiring architectural changes to the training loop.

## Why It Matters / Open Questions

TORCHTITAN lowers the engineering barrier to production-grade LLM pretraining by providing a single, open-source, PyTorch-native codebase (7K core LOC vs. 93K+ for Megatron-LM) that composes state-of-the-art parallelism and optimization techniques, with demonstrated 12–65% throughput gains over optimized baselines across the Llama 3.1 family. Its modular design and systematic training recipes offer actionable guidance for practitioners navigating the complex configuration space of multi-dimensional parallelism. Open questions include whether the composability approach generalizes to non-Transformer architectures (e.g., MoE, which is listed as 'ongoing'), scalability beyond the 512-GPU scale tested, and whether the PyTorch-native constraint limits performance compared to systems with custom CUDA kernels. The paper also does not report MFU under Float8, leaving the absolute hardware utilization picture incomplete.
