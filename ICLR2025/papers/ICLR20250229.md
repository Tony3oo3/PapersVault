## Problem

Identifying the top-m data values by Shapley value is computationally prohibitive because exact SV requires n! model trainings, and existing sampling-based approximations remain expensive for complex models. Prior top-m identification approaches via multi-armed bandits either ignore data features entirely (GapE, BUS) or assume a linear relationship between features and rewards (m-LinGapE), an assumption that fails for the highly non-linear data-to-value mapping in real data valuation tasks such as image classification.

## Input / Output

The algorithm consumes a dataset of n data points, each encoded as a feature vector (e.g., last hidden-layer representation of a trained NN, PCA-reduced 32-dim image, or Sentence-BERT embedding for text), a utility function U(S) defined as validation accuracy of a model trained on subset D_S, and hyperparameters ε (tolerance), m (target set size), and δ (failure probability). Each query requires sampling a subset S from the Shapley distribution P_w, training a model on D_S, and computing the marginal contribution U(S∪{i})−U(S) as a noisy observation of the data value. The output is a set of exactly m indices constituting an (ε,δ)-approximation to the true top-m data values, with a provable finite stopping criterion.

## Method

GPGapE adapts the top-m linear bandit algorithm (m-LinGapE) by replacing the linear reward model with a Gaussian Process that captures the non-linear mapping from data features to data values, removing the linearity assumption. At each iteration, the algorithm maintains a candidate set J(t) of m data points with the highest GP posterior means, identifies the most ambiguous boundary pair (b_t ∈ J(t), c_t ∉ J(t)) by maximizing the gap index B_t(z_i, z_j) — an upper confidence bound on the difference of their true data values — and allocates the next query to whichever of b_t or c_t has the larger GP posterior variance. The GP posterior is updated with the new (feature, marginal contribution) pair, and the algorithm halts when B_t(z_{c_t}, z_{b_t}) ≤ ε, at which point the output is guaranteed to be an (ε,δ)-approximation with probability ≥ 1−δ (Theorem 4.1) with a near-linear worst-case query complexity of O(n log^{d+1} n) for RBF kernels (Proposition 4.3). A further acceleration, GPGapE-Small, exploits the empirically observed diminishing return of ML models by restricting marginal contribution queries to data subsets of size at most p (e.g., p = ⌊0.1n⌋), reducing per-query training cost by up to 1000× while a theoretical connection (Proposition 4.5) ensures the resulting top-m identification on small subsets still yields a valid (ε,δ)-approximation of the original data values.

## Results

On MNIST (10k data points), GPGapE-Small achieves the same recall as all other baselines with 50× fewer marginal contribution queries when m=1000 (20k vs. 1000k queries), and 16.5× fewer queries than GPGapE alone. In noisy data detection on MNIST, FashionMNIST, and CIFAR-10, GPGapE-Small achieves the highest recall of injected noisy data points across both logistic regression and NN models. For LLM fine-tuning data selection (TYDIQA + LLaMA-2-7B), GPGapE uses only 21.7% of the computation required by LESS to find a 5%-size subset that outperforms the full dataset, and matches LESS performance with 36.6% of its computation cost.

## Baselines & Comparisons

GPGapE-Small dominates all sampling-based SV approximation baselines (MC, Owen, Sobol, Stratified, KernelSHAP) by a wide margin: it achieves the same recall with 10–50× fewer queries, while these baselines improve recall very slowly even after 1000k queries. Against the MAB-based baselines GapE and BUS (Kolpaczki et al., 2021), GPGapE wins because it leverages data features via GP to guide queries adaptively, whereas GapE/BUS treat each data point as an independent arm. GPGapE significantly outperforms m-LinGapE (Réda et al., 2021) on real image datasets because m-LinGapE's linear assumption between features and rewards is violated in data valuation; in a controlled linear simulation (Appendix B), GPGapE with a linear kernel matches m-LinGapE, confirming the gap is due to non-linearity. Against GroupTest (Jia et al., 2019), GPGapE achieves 0.2150 vs. 0.1170 recall at m=1000 after 100k queries on MNIST. In the LLM fine-tuning setting, GPGapE matches LESS (Xia et al., 2024) performance at 36.6% of its computation cost, demonstrating practical efficiency gains for large-scale data selection.

## Relation to Prior Work

This paper extends the top-m linear bandit algorithm m-LinGapE (Réda et al., 2021) by replacing its linear reward model with a Gaussian Process, enabling it to capture the highly non-linear mapping from data features to Shapley values that is characteristic of real data valuation. It also draws on the data valuation literature (Ghorbani & Zou, 2019; Jia et al., 2019) for the Shapley value formulation and the diminishing-return observation to introduce a small-subset acceleration that has no direct analogue in the MAB literature. The work positions itself as the first to study top-m data values identification specifically (as opposed to top-m SV in general cooperative games à la Kolpaczki et al., 2021) with a non-linear feature-based model and matching theoretical guarantees.

## Why It Matters / Open Questions

The 50× query-efficiency gain over sampling-based baselines and the LLM fine-tuning result (21.7% of LESS computation for comparable performance) make this practically relevant for data selection at scale, where full Shapley computation is infeasible. However, the efficiency gains are measured primarily against baselines that do not exploit data features (MC, Owen, Sobol), so the comparison with feature-aware methods like KernelSHAP is less dramatic. Open questions include how sensitive the GP is to the quality of the data-point feature representation, whether the small-subset assumption (Assumption 4.4) holds for all model/data regimes, and whether the approach extends naturally to other semivalues or to settings where the utility function itself is expensive to approximate.
