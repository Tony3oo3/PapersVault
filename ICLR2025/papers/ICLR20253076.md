## Problem

Existing function-calling models exhibit significant performance inconsistency across benchmarks, primarily because they over-rely on function and parameter naming conventions rather than semantic descriptions. This overreliance causes models to perform well on benchmarks matching their training data's naming style but degrade sharply when encountering different naming conventions, undermining robustness for real-world on-device deployment.
![Teaser figure](../imgs/ICLR20253076/cropped_page3_idx0.webp)

## Input / Output

The model receives a user query alongside a set of candidate function definitions, each specifying a function name, parameter names, default values, and natural-language descriptions. It outputs a strict JSON array of function calls (with 'name' and 'arguments' fields) or an empty list '[]' when no candidate satisfies the user's intent. The output must conform to a predefined JSON schema with correct parameter types, and the model must handle four calling styles: simple, multiple-choice, parallel, and parallel-multiple.

## Method

The core technique is function masking: during supervised fine-tuning, function names and parameter names in candidate definitions are randomly replaced with strings of length 5–15 drawn from 52 letters and 10 digits, while default values are randomized and appended to parameter descriptions. This forces the model to ground its decisions in the natural-language descriptions rather than memorized naming patterns, with a masking ratio of 0.33 applied per training epoch. Complementing this, an irrelevance-augmented dataset adds 7,500 instances (sampled from xLAM-function-calling-60k) where the correct function is removed from the candidate list and the label is set to an empty list, training the model to correctly reject when no suitable function exists. The approach is applied via SFT to Qwen and DeepSeek-Coder base models at 1.5B, 4B, and 7B scales, yielding the Hammer family that outperforms larger open-source models and rivals GPT-4 on BFCL v2.

## Results

On the BFCL v2 leaderboard, Hammer-7B achieves 83.92 overall accuracy (4th overall, 1st among open-source FC models), with an Executable Function score of 89.72 that surpasses GPT-4-0125 (89.25). Across five academic benchmarks (API-Bank, Tool-Alpaca, Seal-Tools, Nexus Raven), Hammer-7B attains a mean F1 (Func.+Args) of 76.21, trailing only GPT-4-0613 (78.79) and GPT-4o-mini (76.42) while outperforming all open-source baselines by 3.6–16.4 points. Notably, Hammer-7B achieves state-of-the-art results on the most complex Parallel Multiple task (84.08 AST / 85.00 Exec), indicating that function masking becomes increasingly advantageous as task complexity rises.

## Baselines & Comparisons

Hammer-7B (76.21 F1 Avg) narrowly trails GPT-4-0613 (78.79) and GPT-4o-mini (76.42) on the academic benchmark average, but surpasses both on API-Bank L-1 (85.79 vs 84.78/89.28) and Seal-Tools (91.66 vs 93.95/86.00), and on BFCL Executable Function (89.72 vs 89.25/87.95). Against the strongest open-source baselines, Hammer-7B leads Granite-20B-FunctionCalling by 3.65 points (76.21 vs 72.56), xLAM-7B-fc by 8.56 points (76.21 vs 67.65), and Gorilla-OpenFunctions-v2-7B by 9.05 points (76.21 vs 67.16). The gap widens dramatically against vanilla Qwen models: Hammer-7B exceeds Qwen2-7B-Instruct by 16.37 points and Qwen1.5-4B-Chat by 33.96 points, confirming that the function-masking + irrelevance-augmentation pipeline is architecture-agnostic (also validated on DeepSeek-Coder, where 1.3B goes from 19.78 to 70.91 F1 Avg). On BFCL, Hammer-7B ranks 4th overall (83.92) behind three GPT-4 variants but ahead of all other open-source models including Functionary-70B (82.55) and xLAM-7B-fc (79.41), and achieves the best Parallel Multiple score (84.08 AST) among all listed models.

## Relation to Prior Work

This paper builds directly on the xLAM-function-calling-60k dataset (generated via the APIGen pipeline) as its training foundation, extending it with 7,500 irrelevance-detection examples. It departs from prior function-calling models (xLAM, Granite, Gorilla, Functionary) by diagnosing a specific failure mode — overreliance on compact function and parameter names — and proposing function masking as a training-time regularization that forces the model to attend to natural-language descriptions instead. The irrelevance-augmented dataset addresses a trade-off (function-calling accuracy vs. irrelevance detection) that prior SFT-based approaches inadvertently worsen, and the technique is validated across Qwen and DeepSeek-Coder base architectures to show it is not model-specific.

## Why It Matters / Open Questions

For on-device and edge deployment, where models must generalize to arbitrary API naming conventions they have never seen, the function-masking technique offers a simple, low-cost training modification that improves cross-benchmark stability without architectural changes. The paper also surfaces a practical limitation: masking can hurt performance when function descriptions are sparse (as in Tool-Alpaca) or when training and test distributions are highly similar, so the technique is not universally beneficial. Open questions include whether the optimal masking ratio (found to be ~33%) transfers across model scales and domains, whether the irrelevance-augmentation ratio (~10%) generalizes beyond the xLAM-60k base, and whether the approach extends to multi-turn or agentic function-calling settings beyond single-shot selection.
