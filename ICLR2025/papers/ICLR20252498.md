## Problem

Current Video-LLMs process videos as static clips with single-turn dialogues, hitting computational bottlenecks on long sequences and losing key information through insufficient frame sampling. Existing online/streaming models enable multi-round interaction but suffer from slow processing speeds (1–5 FPS) and inconsistent performance across unfamiliar scenarios, making them unsuitable for real-time applications like robotic navigation and human-robot collaboration.
![Teaser figure](../imgs/ICLR20252498/cropped_page1_idx1.webp)

## Input / Output

The system consumes a continuous stream of video frames (H×W×3 RGB) processed at up to 32 FPS, along with timestamped natural-language questions that arrive at arbitrary points during the video. Output is a text response generated with sub-0.9-second request processing delay, structured as a multi-turn dialogue where each video is paired with six sequential questions of different types (object search, long/short-term memory, conversational interaction, knowledge QA, simple factual). The model operates without any fine-tuning, using CLIP-L/14 as the frozen vision encoder and LongVA as the base Video-LLM.

## Method

STREAMCHAT is a training-free framework built on LongVA that introduces a three-tier hierarchical memory system: (1) a long-term memory tree where vision features are chunked, k-means clustered into compressed visual tokens, and paired with LLM-generated text captions, then hierarchically grouped into a tree structure for efficient retrieval; (2) a short-term memory that randomly samples S embeddings from a sliding vision buffer, inspired by the Ebbinghaus forgetting curve; and (3) a dialogue memory encoding conversation history via MiniLM for multi-turn context. A selective frame stacking module uses Lucas-Kanade optical flow to compute inter-frame motion vectors and discard redundant frames below a threshold before encoding. A RAG-inspired retrieval algorithm traverses the memory tree by computing cosine similarity between the query and node captions at each level, selecting the highest-similarity path to retrieve relevant visual and textual context. Three threads (frame stacking, memory formation, contextual summarization) run in parallel via a system scheduling strategy, decoupling feature extraction from memory updates to prevent unbounded buffer growth and achieve 32 FPS processing with <0.9s response latency.

## Results

On STREAMBENCH (the paper's new streaming benchmark), STREAMCHAT-Slow achieves 64.7% accuracy and 3.48 semantic score, outperforming the previous best streaming method Video-online (56.4% Acc, 3.11 Sco.) by 8.3% in accuracy. The Fast variant processes video at 32 FPS (6× faster than Video-online's 5 FPS) while still improving accuracy by 5.3% over Video-online. On offline benchmarks (MSRVTT, ActivityNet, NExT-QA, MSVD), STREAMCHAT achieves 50.6% average accuracy, surpassing the best offline method LLaVA-Hound (47.9%) by 2.7% and the base model LongVA (48.1%) by 2.5%. All STREAMCHAT variants maintain request processing delay under 0.9 seconds.

## Baselines & Comparisons

STREAMCHAT outperforms all 14 compared baselines on STREAMBENCH accuracy, with the largest margin over the previous best streaming method Video-online (+8.3% Acc, 64.7% vs 56.4%) and Flash-VStream (+12.6% Acc). Among offline instruct-tuned models, STREAMCHAT-Slow beats the strongest (InternLM-XCP2.5, 57.7%) by 7.0% and the base model LongVA (52.4%) by 12.3%. The only methods that exceed STREAMCHAT are GPT-4o with 50 sampled frames (71.0%) and 35 frames (69.8%), which operate in a non-streaming, offline setting with full video access. In the streaming category, STREAMCHAT also achieves the best coherence score (1.76 for Slow) and lowest latency (0.85–0.90s RPD) among all streaming methods, compared to Video-online's 1.07s and Flash-VStream's 4.15s. On offline benchmarks (Table 6), STREAMCHAT's 50.6% average accuracy surpasses LLaVA-Hound (47.9%) and LongVA (48.1%), confirming the memory modules' benefit even without streaming.

## Relation to Prior Work

This paper builds directly on LongVA as its foundational Video-LLM, extending it from offline single-turn video QA to a training-free streaming framework with multi-round interaction. It departs from prior streaming models (Video-online, Flash-VStream) by introducing a hierarchical memory system inspired by cognitive science (Atkinson-Shiffrin model, Ebbinghaus forgetting curve) combined with RAG-style retrieval, rather than relying on instruction-tuned temporal alignment. The selective frame stacking via Lucas-Kanade optical flow and k-means-based long-term memory tree construction are engineering contributions that differentiate it from MovieChat's simpler sparse-memory approach, while the parallel three-thread scheduling is a systems-level novelty absent from prior Video-LLM work.

## Why It Matters / Open Questions

STREAMBENCH fills a genuine gap as the first benchmark specifically designed for streaming video understanding with multi-turn dialogue, diverse video types, and latency metrics—criteria that prior offline benchmarks (MSRVTT, ActivityNet, NExT-QA) cannot capture. The training-free design lowers the barrier to deploying streaming video understanding in real-world settings like robotics and human-robot interaction without expensive retraining. Key open questions remain: the retrieval algorithm is acknowledged as basic and occasionally fails, the tree-structured memory faces VRAM scalability limits for very long videos, and the approach's dependence on optical flow thresholds may not generalize to all video types (e.g., static scenes with subtle changes).
