## Problem

Existing workflow generation benchmarks for LLM agents suffer from three critical limitations: they cover only narrow scenarios (function calling or reasoning), model workflows as simple linear chains rather than the complex DAG structures found in real-world tasks, and rely on GPT-4 or semantic similarity for evaluation, introducing circularity and imprecision. This makes it impossible to systematically quantify how well LLM agents decompose tasks into executable subtask graphs with correct dependency relationships.
![Teaser figure](../imgs/ICLR20252508/cropped_page0_idx0.webp)

## Input / Output

The agent receives a natural-language task description q and a candidate action list A (containing function APIs, embodied actions, shell commands, or mixtures thereof) and must produce a two-part output: first a node chain C(V), an ordered sequence of subtask descriptions at minimum executable granularity, then a workflow graph G(V,E) as a DAG where edges encode execution dependencies (including parallelism). The node chain must be a valid topological ordering of the graph, and START/END sentinel nodes delimit the workflow. Evaluation compares predicted and gold structures via Sentence-BERT cosine similarity (threshold β=0.6) for node alignment, then applies LIS-based subsequence scoring for chains and Maximum Common Induced Subgraph matching for graphs, yielding separate F1_chain and F1_graph scores.

## Method

WORFBENCH constructs 18k training and 2,146 test samples across four scenarios (function calling, problem-solving, embodied, open-grounded) by first synthesizing node chains from gold trajectories using GPT-4 in a REACT-style loop, then prompting GPT-4 to generate dependency edges between numbered nodes. Quality control filters 15.36% of chains via semantic retrieval mismatch detection and 29.77% of graphs via constrained topological sorting that enforces alignment with the node chain order. WORFEVAL evaluates predictions by computing a bipartite similarity matrix between gold and predicted nodes (using Sentence-BERT embeddings), resolving one-to-one matches via max-weighted bipartite matching (Hopcroft-Karp), scoring chains via Longest Increasing Subsequence over all topological orderings of the gold graph, and scoring graphs via Maximum Common Induced Subgraph matching. The paper further fine-tunes Qwen-2-7B and InternLM-2.5-7B on the training set to assess generalization to held-out tasks, and demonstrates that generated workflows improve downstream end-to-end performance (as structured prior knowledge or CoT augmentation) while reducing inference time by 1/5 to 1/3 through parallel execution of independent subtasks.

## Results

On WORFBENCH, GPT-4 achieves the best average f1_chain of 67.32% and f1_graph of 52.47% among all 18 evaluated models, with a notable ~15% gap between linear (chain) and graph planning capabilities. Among open-source models, Qwen-2-72B leads with 67.24% f1_chain and 50.46% f1_graph, while Llama-3.1-70B follows at 64.60% and 49.59%. Fine-tuning Qwen-2-7B on the training set yields 79.35% f1_chain and 70.38% f1_graph on held-in tasks (surpassing GPT-4 by 12%+ and 18%+ respectively), but generalization to held-out InterCodeSQL tasks remains limited (48.72% f1_graph vs. GPT-4's 54.36%).

## Baselines & Comparisons

GPT-4 outperforms GPT-3.5 by 3.46% in f1_chain and 4.45% in f1_graph on average, while Claude-3.5 nearly matches GPT-4 (66.70 vs. 67.32 f1_chain) and edges it out slightly on f1_graph (52.53 vs. 52.47). O1-preview, despite being a reasoning model, underperforms GPT-4 on both metrics (66.70/51.63 vs. 67.32/52.47), excelling only on problem-solving tasks. Among open-source models, Qwen-2-72B (67.24/50.46) surpasses Llama-3.1-70B (64.60/49.59) by 2.64% and 0.87% respectively, and both significantly outperform 7B and 13B models. Fine-tuned Qwen-2-7B+FT dramatically outperforms GPT-4 on held-in tasks (79.35/70.38 vs. 67.32/52.47) but loses to GPT-4 on held-out InterCodeSQL (48.72 vs. 54.36 f1_graph), indicating limited generalization. In downstream embodied tasks, workflow-augmented GPT-4 (GPT-4+W) improves ALFWorld seen success rate from 27.14% to 40.71% and unseen from 28.36% to 47.01%, while also reducing average planning steps from 17.19 to 15.64.

## Relation to Prior Work

This paper extends the line of work on LLM agent workflow generation (AutoFlow, AFlow, FlowMind) by shifting the evaluation focus from end-to-end task completion to the intermediate workflow structure itself. Prior fine-grained evaluation efforts (T-Eval, ToolEyes, TaskBench, PlanBench) are limited to linear subtask sequences in single scenarios (function calling or reasoning); WORFBENCH generalizes to DAG-structured workflows across four scenario types and replaces GPT-4-as-judge with algorithmic subsequence and subgraph matching (LIS, MCIS, bipartite matching). The construction pipeline builds on existing datasets (ToolBench, ALFWorld, WebShop, WikiHow, LUMOS) but introduces a node-chain intermediary and topological-sort validation to ensure structural consistency.

## Why It Matters / Open Questions

The consistent ~15–20% gap between linear (chain) and graph planning scores across all 18 models, including GPT-4 and o1-preview, reveals a fundamental limitation in current LLMs' ability to reason about parallel dependencies — a capability essential for real-world agent deployment. The finding that fine-tuning on 18k workflow samples does not yield strong generalization to held-out embodied tasks suggests that structured planning cannot be acquired purely through data fitting and requires deeper environmental/world knowledge integration. The practical demonstration that a 7B model's generated workflow can guide a 72B model (weak-guide-strong paradigm) and that graph parallelization cuts inference time by 1/5 to 1/3 provides concrete pathways for more efficient agent architectures.
