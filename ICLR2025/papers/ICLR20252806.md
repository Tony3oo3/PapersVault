## Problem

Existing API-based agent benchmarks (MetaTool, ToolLLM, ToolBench) are too simple to differentiate LLMs of varying intelligence—3B models already achieve 88–93% accuracy—while also lacking realism (manually crafted APIs, LLM-generated queries), omitting evaluation of parameter value filling, and ignoring the agent's ability to recognize when it must request missing input from the system or user.
![Teaser figure](../imgs/ICLR20252806/cropped_page3_idx0.webp)

## Input / Output

The agent receives a natural-language user query, a context window of available API descriptions (name, parameters with types including primitives/enums/advanced types, return values, and natural-language summaries), and the correct historical action sequence up to the current step. It must output the next API call with fully filled parameter values (extracting primitives and enums from the query, referencing outputs of prior actions by UID/OutputName) and flag any parameter that requires system input (clipboard, current date, file) or user input (Ask). Evaluation follows a next-token-prediction protocol: correct history is always supplied, and control-flow actions (branches, loops) are skipped rather than predicted.

## Method

SHORTCUTSBENCH is constructed by crawling 14 public Apple Shortcuts sharing sites, downloading shortcut source files via iCloud links, and extracting real APIs from 88 apps using AppIntent (.actionsdata), SiriKit (.intentdefinition), and system WFActions.json definition files, yielding 1,414 APIs across 7,627 human-annotated action sequences. Queries are generated by GPT-4o conditioned on the shortcut's natural-language workflow description, API metadata, and store listing, with a requirement to embed primitive and enum parameter values so they can be evaluated for extraction. The benchmark is stratified into 4 difficulty levels (by action-sequence length: 1, 2–5, 6–15, 16–30) and 8 task types, and each query is equipped with relevant APIs plus distractors (3×–5× the needed count, capped at 20). Agents are built with a modified ReACT prompt and evaluated on three metrics: API selection accuracy, parameter-filling accuracy (split into static preset values and previous-action outputs), and recognition accuracy for system/user input requests, across 10 LLMs spanning 57B–236B open-source and closed-source models.

## Results

On SHORTCUTSBENCH, API selection accuracy drops sharply with difficulty: the average across all 10 LLMs falls by ~19% from level (0,1] to (1,5] and by ~46% from (0,1] to (5,15], with the steepest drop being 58% for ChatGLM-4-Air. For parameter filling, intelligent LLMs like Gemini-1.5-Pro maintain relatively stable accuracy across difficulty levels, while less intelligent models like GPT-4o-mini degrade significantly. Recognition of the need for system/user input is the weakest capability overall, with accuracy ranging from only 30.55% (GPT-3.5-turbo) to 55.18% (DeepSeek-2-coder) across all models and difficulty levels.

## Baselines & Comparisons

Among the 10 general LLMs, Gemini-1.5-Pro leads on API selection for the highest-difficulty level (15,30], while open-source models ≥70B (QWen-2-72B, LLaMA-3-70B, DeepSeek-2) match or exceed closed-source GPT-4o-mini and GPT-3.5-turbo on levels (0,1] through (5,15] but still trail Gemini-1.5-Pro on the hardest tasks. DeepSeek-2-coder achieves the best overall input-recognition accuracy (55.18%), narrowly beating LLaMA-3-70B (49.89%) and Gemini-1.5-Pro (46.59%), while QWen-2-57B and GPT-3.5-turbo are the weakest at ~30%. In the fine-tuned agent comparison (Appendix A.9), xLAM-8x7b-r improves API selection from 70.21% (base Mixtral-8x7b) to 85.29% on level (0,1], but still falls far short of general LLMs like QWen-2-72B. AgentLM-70B actually degrades from 52.13% (base LLaMA-2-70B) to 43.41% on API selection, suggesting its fine-tuning data lacks the realism and complexity of SHORTCUTSBENCH. All fine-tuned agent models (AgentLM, xLAM, Lemur) perform substantially worse than general LLMs on parameter filling and input recognition, with the best fine-tuned model reaching only 72.86% on parameter filling versus 94.29% for the best general LLM on the easiest level.

## Relation to Prior Work

This paper builds on the ReAct prompting framework (Yao et al., 2023) for constructing API-based agents and follows ToolLLM's (Qin et al., 2024) evaluation methodology for next-action prediction and per-query API equipping. However, it departs fundamentally from existing API-based agent benchmarks (MetaTool, ToolLLM, ToolBench, API-Bank, ToolAlpaca) by sourcing all data from Apple Shortcuts, a real Digital Automation Platform, rather than relying on manually crafted or LLM-generated APIs and queries. The key conceptual departure is extending evaluation beyond API selection alone to encompass parameter value filling (primitive types, enums, previous-action outputs) and recognition of the need to request input from the system or user—dimensions entirely absent from prior benchmarks.

## Why It Matters / Open Questions

SHORTCUTSBENCH addresses a critical gap: existing benchmarks are saturated (even 3B models score 88–93%), making them unable to differentiate increasingly capable LLMs. The benchmark's much higher complexity (average 21.62 actions vs. 1–5.9 in prior work) and real-world grounding reveal that agents still struggle substantially with multi-step reasoning, and that all evaluated models—regardless of scale—perform poorly (30–55%) on recognizing when to request missing input from users or the system. Open questions include whether the Apple-specific API ecosystem limits generalizability to other platforms, how to close the input-recognition gap, and whether the next-action-prediction evaluation protocol (which prevents error cascades) overestimates real-world agent performance where errors compound.
