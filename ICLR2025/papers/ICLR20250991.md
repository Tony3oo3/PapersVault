## Problem

FlashAttention eliminates the O(N²) memory dependency of vanilla attention but only natively supports a limited set of predetermined mask patterns (causal, sliding window, document). Supporting the broader range of masks needed in LLM post-training (shared question, causal document, prefix LM, QK-sparse, etc.) forces practitioners to fall back on dense O(N²) mask matrices, which become memory-prohibitive at long sequence lengths (128K+ tokens) and waste computation on fully masked blocks.

## Input / Output

The method consumes standard Q, K, V matrices (N×d in BFloat16) plus four 1D integer vectors of length N — LTS, LTE, UTS, UTE — that encode, for each column j, the row-index intervals [LTS_j, LTE_j) and [UTS_j, UTE_j) to be masked in the lower and upper triangular sections respectively. This replaces the conventional N×N dense mask with an O(N) representation. The forward pass outputs the attention matrix O (N×d) and per-row logsumexp L (N); the backward pass additionally produces dQ, dK, dV, with the column-parallel structure of dK/dV enabling register-resident reuse of the precomputed min/max mask statistics.

## Method

FLASHMASK decomposes the 2D attention mask into four 1D column-wise interval vectors (LTS, LTE, UTS, UTE), exploiting the observation that masked regions within each column are contiguous. These vectors are preprocessed into per-block min/max statistics (8 vectors of size T_c), which during kernel execution classify each tiling block as fully masked (computation skipped entirely), partially masked (element-wise −∞ applied only to the relevant row sub-interval), or unmasked (no masking overhead). This classification is integrated directly into FlashAttention-2's tiling loop, reducing computational complexity from O(N²) to O((1−ρ)T_r T_c) where ρ is the block sparsity. The backward pass further exploits column-parallelism: dK and dV accumulate across row blocks, so the min/max mask values are loaded once into registers and reused across all inner-loop iterations, while the full mask vectors are preloaded into SRAM outside the inner loop, reducing HBM accesses to 4×N total.

## Results

FLASHMASK achieves end-to-end training speedups of 1.65x to 3.22x over FlashAttention's dense mask method across SFT, LoRA, DPO, and RM tasks on Llama-2 (7B/13B/70B). At the kernel level, FLASHMASK outperforms FlexAttention by 12.1% to 60.7% in total TFLOPs/s across 12 mask types, reaching 37.8%–62.3% of the A100's theoretical peak FLOPs/s. Memory complexity drops from O(N²) to O(N), enabling Llama-2 7B LoRA training at 544K sequence length (vs. 64K for dense methods), with only ~0.5 GB additional memory at 64K tokens.

## Baselines & Comparisons

Against FlashAttention's dense mask (Dao et al., 2022), FLASHMASK delivers 1.65x–3.22x end-to-end throughput gains and extends maximum supported sequence length from 64K to 544K tokens in Llama-2 7B LoRA training, while maintaining bit-level numerical equivalence in loss curves. Against FlexAttention (He et al., 2024), FLASHMASK wins on every one of the 12 tested mask types in kernel TFLOPs/s, with the largest margin (60.7%) on high-sparsity masks like Sliding Window (sparsity 0.92) and the smallest (12.1%) on lower-sparsity cases like Prefix LM Causal (sparsity 0.37). Against FlashInfer (Ye et al., 2025) in inference, FLASHMASK achieves roughly 10x higher TFLOPs/s than FlashInfer's sparse mask API (e.g., 135.07 vs. 13.95 TFLOPs/s at 8K for Causal Document Mask) and ~30x higher than its dense mask API, primarily because FlashInfer's token-by-token dense masking performs unnecessary computations on fully masked blocks. FLASHMASK also matches or exceeds FlashInfer's sparse mask even when the latter uses large block sizes (R/C=64), where FlashInfer reaches ~172 TFLOPs/s vs. FLASHMASK's 156.82 TFLOPs/s at 8K Document Mask — a near-tie that narrows to FLASHMASK's advantage at longer sequences.

## Relation to Prior Work

FLASHMASK extends the FlashAttention/FlashAttention-2 framework (Dao et al., 2022; 2023) by replacing its limited built-in mask support with a novel column-wise sparse representation using four 1D vectors (LTS, LTE, UTS, UTE), reducing mask memory from O(N²) to O(N). It positions itself against FlexAttention (He et al., 2024), which achieves O(N²/(Bx·By)) memory via compiler-generated block masks, and against xFormers' cumulative-sequence-length approach for document masks. The key conceptual departure is the observation that masked regions in practical attention patterns exhibit column-wise continuity, enabling a compact 1D interval representation that maps directly to tiling-based block-skip decisions in the kernel.

## Why It Matters / Open Questions

FLASHMASK's O(N) mask memory and block-skip kernel enable 8× longer sequences (544K vs. 64K for Llama-2 7B LoRA) with 1.65×–3.22× end-to-end throughput gains, making long-context post-training (SFT, DPO, RM) substantially more tractable. The main limitation is expressiveness: the column-wise interval representation cannot capture arbitrary or highly irregular masks (e.g., truly random per-element patterns), and the implementation is currently confined to PaddlePaddle/PaddleNLP rather than the dominant PyTorch ecosystem. Open questions include whether the representation can be generalized to handle non-continuous mask patterns, whether Hopper-architecture features (TMA, warp specialization) can further close the gap to theoretical FLOPs, and whether the approach transfers cleanly to inference serving at scale.
