## Problem

Generalist web agents autonomously complete tasks on real websites that involve sensitive PII (credit cards, phone numbers, addresses), yet their privacy risks when operating on compromised websites remain entirely unexplored. This paper presents the first systematic study of how web agents can be manipulated into leaking user privacy data through adversarial web environments, identifying a new attack surface distinct from traditional web threats.
![Teaser figure](../imgs/ICLR20252409/cropped_page1_idx0.webp)

## Input / Output

The attack takes a benign webpage's HTML content, a persuasive instruction (PI) template tailored to the target PII category, a CSS opacity value α ∈ [0,1] (default 0 for invisibility), and a DOM-relative injection position β (defined as n levels above or below the target element in the DOM tree). It produces a compromised HTML page h* that, when rendered and processed by a two-stage web agent (SeeAct), causes the agent to type the user's PII or full task request into the injected element, which then auto-submits the data to an external server via a JavaScript delay script. The key constraint is that the attack must not disrupt the agent's subsequent task completion to avoid user detection.

## Method

EIA is an indirect prompt injection that manipulates the web environment where state-changing actions occur, rather than designing adversarial prompts in isolation. Two injection strategies are proposed: Form Injection (FI) inserts a new HTML form carrying the PI in text fields or aria-label attributes, while Mirror Injection (MI) replicates the target element's exact style and naming conventions and embeds the PI in auxiliary attributes, making it nearly indistinguishable from the benign element. Stealth is achieved by setting CSS opacity to zero (making the injected element invisible in screenshots) and a JavaScript auto-submission mechanism that exfiltrates typed data after a 1-second typing pause, then removes the element from the DOM. For the harder target of leaking the full user request, Relaxed-EIA relaxes opacity to 0.2 so the injected text becomes faintly visible in the screenshot, thereby also compromising the action generation stage (which processes only the rendered image) in addition to the action grounding stage (which processes HTML). The attack is evaluated on 177 PII-involving action steps from Mind2Web using GPT-4V, LLaVA-Mistral-7B, and LLaVA-Qwen-72B as backbone LMMs, achieving up to 70% ASR for specific PII leakage and 16% for full request leakage.

## Results

EIA with the Mirror Injection (MI) strategy achieves up to 70% Attack Success Rate (ASR) in stealing users' specific PII at a single action step when using GPT-4V as the backbone model and injecting at position P+1 (just above the target element). For the harder target of leaking the full user request, standard EIA (zero opacity) achieves 0% ASR, while Relaxed-EIA (opacity α=0.2) increases this to 16% ASR with GPT-4V at position P−3. The attack preserves agent functional integrity (ASR_pt ≈ ASR), meaning the agent continues its task normally after the leak, and neither VirusTotal nor defensive system prompts can detect or mitigate the attack.

## Baselines & Comparisons

This is an attack paper rather than a method-vs-baseline comparison, so the key contrasts are between injection strategies and model backbones. Among the three strategies, FI(text) achieves the highest mean ASR across positions (0.45 for GPT-4V), while MI achieves the single highest ASR (0.70 at P+1 with GPT-4V) but with much higher variance (0.461 vs. 0.028), indicating MI is more position-sensitive. More capable models are more vulnerable: GPT-4V (SR=0.78) suffers up to 70% ASR, LlavaQwen72B (SR=0.55) up to 49%, and LlavaMistral7B (SR=0.10) only up to 16%. For the full-request leakage target, Relaxed-EIA (α=0.2) outperforms standard EIA (α=0) by achieving 16% ASR vs. 0% with GPT-4V, though both Llava backbones remain at 0%. Defensive system prompts fail to reduce ASR meaningfully, and VirusTotal flags none of the compromised pages as malicious.

## Relation to Prior Work

This paper extends the indirect prompt injection paradigm (Greshake et al., 2023b) from generic LLM-integrated applications to the specific setting of generalist web agents that perform state-changing actions on live webpages. It departs from prior web agent attacks (backdoor triggers via fine-tuning, adversarial image manipulation) by targeting the HTML environment itself, and from Wu et al. (2024b) by focusing on generalist agents performing complex multi-step tasks rather than retrieval-augmented summarization. The key conceptual contribution is the 'environmental adaptation' framing: rather than crafting novel prompt text, the paper investigates how to make injections visually and structurally indistinguishable from benign webpage elements (via Form Injection, Mirror Injection, CSS opacity control, and JavaScript auto-submission), specifically exploiting SeeAct's two-stage architecture where action grounding sees HTML but action generation sees only the screenshot.

## Why It Matters / Open Questions

This is the first systematic study of privacy leakage through generalist web agents, demonstrating that even the most capable current framework (SeeAct + GPT-4V) leaks specific PII at up to 70% ASR and full user requests at 16% ASR, while remaining undetectable by standard tools (VirusTotal) and resistant to defensive system prompts. The finding that more capable models are more vulnerable, combined with the architectural insight that the two-stage design creates a specific blind spot (zero-opacity injections bypass action generation), provides concrete guidance for future agent design. Open questions include whether defenses can be built at the pre-deployment (webpage scanning) or post-deployment (agent monitoring) stages without sacrificing agent utility, whether the attacks generalize to multi-turn compositional injections, and how the security-autonomy trade-off should be resolved in practice as web agents move toward real deployment.
