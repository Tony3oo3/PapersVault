## Problem

While including code in LLM pre-training mixtures has become standard practice, there has been no exhaustive study systematically quantifying the impact of code data on general non-code performance. Prior work has only examined isolated side benefits (e.g., entity tracking, mathematical reasoning) without a comprehensive evaluation across diverse downstream tasks, model scales, training stages, and code properties.
![Teaser figure](../imgs/ICLR20252867/cropped_page2_idx0.webp)

## Input / Output

The models are decoder-only transformers (470M and 2.8B parameters) trained on mixtures of text (SlimPajama, 503B tokens) and code (Stack, 139B tokens) data, evaluated on text prompts across four task categories: 11 NL reasoning benchmarks (QA, NLI, sentence completion, co-reference resolution), world knowledge (Natural Questions, TriviaQA), code generation (HumanEval-Python, MBPP pass@1), and open-ended generative quality measured via LLM-as-a-judge win-rates on Dolly-200. At 470M scale, only benchmarks where all models exceed random chance are compared to ensure fair evaluation.

## Method

The paper conducts 64 controlled pre-training runs on TPU v5e (JAX, AdamW, 8192 sequence length) to ablate five axes: (1) initialization strategy (text-only, balanced 50/50, code→text continual pre-training), (2) model scale (470M vs 2.8B), (3) code proportion in the mixture (0–100%), (4) code quality and properties (markup-style languages, code-adjacent data like GitHub commits and Jupyter notebooks, and a 3.2B-token synthetically generated verified Python dataset), and (5) inclusion of code during the cooldown phase (40B tokens with up-weighted high-quality data and linear LR annealing). Key findings include an optimal ~25% code proportion for NL reasoning, a 12× code performance boost from code inclusion, a 9% NL reasoning and 44% code improvement from just 10% synthetic code, and a 52.3% win-rate advantage for cooldown with code over no cooldown. The recommended recipe combines balanced code+text initialization, lower code percentage during continual pre-training, high-quality synthetic code throughout, and code in cooldown.

## Results

Compared to text-only pre-training, the best code-inclusive variant (balanced→text) achieves a relative increase of 8.2% in NL reasoning, 4.2% in world knowledge, 6.6% in generative win-rates, and a 12× boost in code performance (HumanEval/MBPP pass@1). Adding code to the cooldown phase further improves NL reasoning by 3.6%, world knowledge by 10.1%, and code by 20% relative to no cooldown, yielding 52.3% generative win-rates. A small 10% inclusion of high-quality synthetic code data produces a 9% NL reasoning and 44.9% code benchmark improvement over web-code-only, despite being only 3.2B tokens out of 200B total.

## Baselines & Comparisons

The paper's primary comparison is between pre-training variants rather than external methods. The text-only baseline (SlimPajama, 503B tokens) is outperformed by all code-inclusive variants on NL reasoning (8.2–8.8% relative gain) and generative win-rates (+6.6%). For world knowledge, the balanced→text variant is optimal (+4.1% over text-only), while code→text underperforms it by 21% relative, indicating that a balanced initialization mixture matters more than pure code initialization for knowledge tasks. On code generation, balanced-only (50% code throughout) dominates, beating balanced→text by 46.7% and code→text by 54.5% relative, revealing a clear trade-off: maximizing code performance requires sustained high code proportions, but this sacrifices NL task quality. At 2.8B scale, the same qualitative trends hold, with balanced→text gaining 33.1% over its 470M counterpart, and the NL-vs-code trade-off widening (43–46% relative code drop for text-continued variants). Cooldown with code outperforms cooldown without code by 4.1% in win-rates and 20% in code benchmarks, establishing code as beneficial even in the final up-weighted training phase.

## Relation to Prior Work

This paper carves new empirical ground by being the first systematic, multi-axis ablation study of code's impact on non-code tasks in LLM pre-training. Prior work has identified isolated side benefits of code data—entity tracking (Kim et al., 2024), mathematical reasoning (Razeghi et al.), commonsense reasoning (Madaan et al., 2022b), and scaling in low-data regimes (Muennighoff et al., 2023a)—but none have exhaustively varied code proportion, quality, initialization strategy, cooldown inclusion, and model scale simultaneously. The paper builds on the established pre-training practice of including code (PaLM, Gopher, Bloom, Llama 2/3) and on the cooldown technique (Parmar et al., 2024; Team et al., 2023), but departs from prior studies by treating code as a first-class variable to be ablated rather than a fixed component of the data mixture.

## Why It Matters / Open Questions

This provides the first actionable, evidence-based recipe for code inclusion in pre-training: ~25% code proportion for non-code tasks, high-quality synthetic code as a high-leverage addition, and code in cooldown for generative quality. The finding that a mere 3.2B-token synthetic code dataset at 10% weighting yields 9% NL reasoning and 44.9% code improvement suggests a concrete, low-cost lever for practitioners. Key limitations include the maximum model scale of 2.8B parameters (making it unclear whether proportions and effects hold at 70B+ scale), the absence of safety/bias analysis, and the use of a proprietary synthetic code dataset that limits reproducibility. Open questions include whether the optimal code proportion shifts with scale, whether the synthetic code effect is specific to Python or generalizes, and how these findings interact with other data-mixture decisions (e.g., math, multilingual).
