## Problem

Previous 3D feature splatting methods (F-3DGS, F-Splat) directly distill 2D foundation-model feature maps into low-dimensional per-Gaussian attributes (16–64 dims vs. 1024+ original), creating an information bottleneck and causing misalignment between the distilled features and the original model's knowledge space. This limits the ability of the 3D scene representation to faithfully preserve the expressive, multi-granularity semantics that foundation models encode.

## Input / Output

The method consumes a video sequence of a static scene (multiple RGB views with COLMAP-estimated camera poses) and extracts patch-level embeddings from six foundation models (CLIP, SigLIP, DINOv2, LLaMA3, LLaMAv, SEEM). At query time, given an arbitrary camera pose and an optional text prompt, M3 renders full-resolution multimodal feature maps aligned with each model's native embedding space, which can then be decoded for grounding masks, image-text retrieval rankings, or captioning. The 3D Gaussian structure itself stores only low-dimensional principle queries (16 dims per model) plus standard splatting attributes, keeping the per-primitive footprint small while the full-dimensional knowledge resides in a shared memory bank.

## Method

M3 decouples spatial structure from semantic knowledge: 3D Gaussians carry only low-dimensional learnable principle queries (Q_p) that are rasterized per-pixel, while the original high-dimensional foundation-model features are compressed via a similarity-reduction algorithm (Algorithm 1) into a compact memory bank of Principal Scene Components (PSC). A Gaussian Memory Attention mechanism then performs softmax attention between the rendered Q_p and the PSC bank (mediated by a learnable projection W_m) to synthesize view-consistent feature maps that remain in the original model's embedding space, avoiding the information loss and misalignment of direct distillation. Training uses a point-based loss (sampling 2000 random points from predicted and ground-truth features) rather than dense patch-wise distance, drastically reducing GPU memory and enabling parallel training across all six foundation models simultaneously. The similarity-reduction step exploits redundancy across neighboring pixels and overlapping views to shrink the memory bank to a scene-dependent size (t × d) without discarding unique semantic content.

## Results

M3 uses 35M parameters (vs. 61M for both F-Splat and F-3DGS) while achieving competitive or superior feature fidelity across six foundation models. On downstream grounding (CLIP), M3 reaches 19.6 AP50 and 12.5 AP60 on Train, outperforming F-3DGS (16.3 / 7.1) with half the parameters. On image-to-text retrieval (SigLIP), M3 achieves 55.2% I2T@1 on Train versus only 2.6% for F-3DGS, and reaches 100% I2T@1 on the unseen Geisel dataset where F-3DGS scores 45.7%. On the custom M3-Robot tabletop sequence, M3 trains all six foundation models in ~45 minutes while maintaining CLIP cosine distance of 0.3100.

## Baselines & Comparisons

M3 is compared against two distillation-based feature splatting methods: F-Splat [26] and F-3DGS [51], both using 61M parameters versus M3's 35M. On feature distance (Table 1), M3 wins on CLIP, SigLIP, and LLaMA3 cosine similarity across all four datasets, but F-3DGS achieves lower cosine distance on DINOv2, SEEM, and LLaMAv, indicating that direct distillation can be more faithful for some model families. On downstream grounding (CLIP mIoU/AP), M3 consistently outperforms F-3DGS: on Train, M3 reaches 25.4 mIoU and 19.6 AP50 versus F-3DGS's 24.2 and 16.3; on the unseen Geisel scene, M3 achieves 21.8 mIoU and 16.5 AP50 versus 19.0 and 14.1. The gap is most dramatic on retrieval: M3 scores 55.2% I2T@1 on Train (vs. 2.6% for F-3DGS) and 100% I2T@1 on Geisel (vs. 45.7%), which the authors attribute to Gaussian Memory Attention producing rendered features that remain aligned with the original foundation model embedding space. F-Splat is not directly comparable on all models (SEEM and LLaMA3 extraction failed) but where available, M3 also outperforms it on CLIP and SigLIP feature distance.

## Relation to Prior Work

M3 builds directly on 3D Gaussian Splatting for scene structure and on the feature splatting paradigm established by F-3DGS and F-Splat, which distill 2D foundation-model features into per-Gaussian attributes via differentiable rendering. The key departure is architectural: rather than compressing high-dimensional features into low-dimensional per-Gaussian vectors (16–64 dims vs. ~1024), M3 stores original features in a compressed memory bank (Principal Scene Components) and uses low-dimensional Gaussian queries with a cross-attention mechanism (Gaussian Memory Attention) to retrieve them at render time. This positions M3 as a memory-augmented alternative to direct distillation, extending the feature-splatting task from 2–3 models to six simultaneously (CLIP, SigLIP, DINOv2, SEEM, LLaMA3, LLaMAv) while preserving the original feature space.

## Why It Matters / Open Questions

M3 demonstrates that preserving original foundation-model features in a 3D-indexed memory bank can dramatically improve downstream retrieval and grounding over distillation-based baselines, even with fewer parameters (35M vs. 61M), suggesting that the information bottleneck in per-Gaussian feature vectors is a real limitation of prior approaches. The quadruped-robot deployment shows practical viability for embodied perception. However, the system is limited to static, medium-scale scenes, the memory bank grows with scene complexity, and the paper leaves open how to integrate a reasoning module that operates directly on the optimized memory. Scaling to dynamic scenes, larger environments, and online memory updates remain significant open questions.
