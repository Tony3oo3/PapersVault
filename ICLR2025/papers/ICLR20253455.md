## Problem

Tasks that simultaneously require memory recall and logical reasoning are largely overlooked in LLM research, despite evidence that memory and reasoning are deeply interdependent. The paper introduces 'code reasoning'—a task category where logical reasoning is formalized into programming language—to probe the capability boundaries of LLMs at this intersection, and finds that current state-of-the-art models still struggle to identify satisfactory reasoning pathways due to data sparsity and logical chain collapses from forgetting or hallucination in multi-step reasoning.

## Input / Output

The three meta-benchmarks consume different input formats: inductive code reasoning takes seen input-output specifications (lists, 5×5 grids, or strings) and must produce a generalizable executable program; deductive code reasoning takes a Python function plus input values and must simulate execution step-by-step to predict the output; abductive code reasoning takes a Python function plus output values and must backtrack to recover the simplest valid input (applying Occam's Razor when multiple inputs exist). The VirtualHome extension takes a natural-language household task description and produces a sequence of high-level atomic actions executable in the simulation engine.

## Method

The Reflective Hypothesis Decomposition and Amendment (RHDA) pipeline is an iterative, tool-augmented reasoning process with three stages. First, the LLM formulates an initial hypothesis from observations and decomposes it into simpler sub-hypotheses, reducing the cognitive load on the subsequent translation step. Second, a translator function g maps each sub-hypothesis into an executable function (a program for inductive tasks, a predicted value for deductive/abductive tasks), which is then applied to the observations and validated by an external compiler or execution engine. Third, the LLM receives execution feedback and submits amendments, reflecting on and revising each sub-hypothesis individually to correct errors. This divide-and-conquer-plus-reflection loop is repeated until a valid pathway is found, effectively mitigating logical chain collapses that arise when a single step's failure propagates through an undecomposed reasoning chain. The pipeline is framework-agnostic (applied to GPT-4o, Llama-3.1-70B, Qwen-max, Claude-3.5) and extends naturally to embodied agent tasks in VirtualHome.

## Results

On inductive code reasoning (Table 1), RHDA (T=2, N=3) achieves task accuracy of 48.80% (List Function), 13.85% (MiniARC), 34.78% (RobustFill), and 29.17% (DeepCoder), exceeding the second-best baselines by 18.45%, 5.89%, 33.31%, and 12.02% respectively. On deductive code reasoning (Table 2), RHDA (T=2, N=1) reaches 90.62% on CRUXEval and 84.16% on LiveCodeBench, outperforming CoT (89.12%/83.14%) and CoC (85.62%/81.37%). The paper reports overall performance gains of up to 3× compared to baseline methods, with a single round of amendments yielding up to 104.37% improvement over standard prompting on deductive tasks.

## Baselines & Comparisons

RHDA consistently outperforms all five baselines on task accuracy across the four inductive code reasoning benchmarks. Against PoT (Chen et al., 2023), RHDA gains 15.20–19.38 percentage points in task accuracy (e.g., 48.80% vs. 33.60% on List Function, 34.78% vs. 21.74% on RobustFill). Against CoC (Li et al., 2024), the advantage is even larger, with RHDA achieving 34.78% vs. 13.04% task accuracy on RobustFill and 29.17% vs. 13.54% on DeepCoder. Against Self-Consistency (Wang et al., 2023), RHDA leads by 7.60–8.13 points on task accuracy (e.g., 48.80% vs. 41.20% on List Function). Against Self-Refine (Madaan et al., 2024), RHDA wins by 7.20–13.04 points (e.g., 34.78% vs. 21.74% on RobustFill). On deductive code reasoning, RHDA (T=2, N=1) edges out CoT (Wei et al., 2023) by 1.50 points on CRUXEval (90.62% vs. 89.12%) and 1.02 points on LiveCodeBench (84.16% vs. 83.14%), while substantially outperforming CoC (85.62%/81.37%) and standard prompting (68.75%/41.18%).

## Relation to Prior Work

This paper carves new conceptual ground by unifying existing program synthesis (PBE), code execution simulation, and input prediction tasks under a single 'code reasoning' framework organized along three classical logical reasoning types (inductive, deductive, abductive). Methodologically, it synthesizes ideas from Program-of-Thought/Chain-of-Code prompting, Self-Consistency, and Self-Refine into the RHDA pipeline, which adds a hypothesis decomposition step and external compiler feedback that prior iterative methods lack. The cognitive psychology framing—positioning code reasoning at the intersection of System 1 (recall) and System 2 (reasoning)—distinguishes it from prior work that treats code generation or code understanding as purely one or the other.

## Why It Matters / Open Questions

The paper identifies a genuine gap: tasks requiring both syntactic recall and multi-step logical reasoning have been systematically overlooked, and SOTA LLMs (GPT-4o, Claude 3.5, Llama-3.1-70B) still achieve low task accuracy on these benchmarks. The RHDA pipeline's up-to-3× improvement over baselines, validated across four inductive, two deductive, and two abductive benchmarks plus VirtualHome, provides a practical recipe for mitigating logical chain collapse in multi-step code reasoning. Key open questions remain: the method's sensitivity to initial hypotheses limits its ceiling on truly novel problems, and the paper acknowledges that for tasks exceeding LLMs' intrinsic reasoning capacity, decomposition and reflection alone are insufficient—suggesting a need for stronger symbolic grounding or learned planning.
