## Problem

Subgraph federated learning (SFL) requires clients holding disjoint subgraphs of a global graph to collaborate on node classification without sharing raw data. Existing SFL methods (FEDSAGE+, FEDNI, FEDGCN) rely on sharing or generating node features/embeddings across clients, creating significant privacy risks and communication overhead. No prior SFL framework exploits explicit global graph structure to capture inter-node dependencies while keeping node features entirely private, nor can any handle heterophilic graphs.

## Input / Output

Each client provides its local node feature matrix X_i, local intra-connection edges E_i, and the known interconnection edges to/from other clients. The method additionally consumes a node structure feature (NSF) matrix S (generated via one-hot degree, FEDSTAR, or the proposed HOP2VEC) and a pruned local partition of the global L-hop combined adjacency matrix Ā^[i], which is collaboratively precomputed once before training. The output is a per-node class label produced by softmax over the sum of a locally computed node feature embedding (NFE) and a globally informed node structure embedding (NSE).

## Method

FEDSTRUCT decouples node features from graph structure: a standard GNN (GraphSAGE) computes node feature embeddings (NFEs) locally, while a decoupled GCN computes node structure embeddings (NSEs) from NSFs propagated through the precomputed L-hop combined adjacency matrix Ā = Σ β_l Â^l. The prediction is ŷ_v = softmax(z_v + h_v), combining both embeddings. The key privacy mechanism is that only the pruned local partition Ā^[i] (top p·n entries per hop) and the NSF matrix S are shared—no node features or GNN embeddings ever cross client boundaries. HOP2VEC, the proposed NSF generator, randomly initializes NSFs and learns them end-to-end during federated training, making them task-dependent and eliminating the need for global graph access or homophily assumptions. The decoupled GCN's polynomial filtering (via β_l coefficients) also enables handling heterophilic graphs, and pruning reduces pre-training communication to O(L_s·K·p·n) while preserving community structure.

## Results

On six semi-supervised node classification datasets (10%–10%–80% split, random partitioning, 10 clients), FEDSTRUCT with HOP2VEC (H2V) achieves node classification accuracy close to the centralized GNN: 79.27% on Cora (vs. 82.94% central), 52.60% on Chameleon (vs. 54.38% central), and 40.97% on Amazon Ratings (vs. 41.42% central). The gap to the centralized baseline is substantially smaller than for all federated baselines, and FEDSTRUCT(H2V) outperforms the non-private FEDGCN on both heterophilic graphs (Chameleon: 52.60% vs. 48.77%; Amazon Ratings: 40.97% vs. 40.78%). Performance remains robust as the number of clients increases from 5 to 20, with only modest degradation.

## Baselines & Comparisons

Against FEDSAGE+ (Zhang et al., NeurIPS 2021), FEDSTRUCT(H2V) achieves large gains on all six datasets: +12.94 pp on Cora (79.27% vs. 66.33%), +16.28 pp on Chameleon (52.60% vs. 36.32%), and +5.12 pp on Amazon Ratings (40.97% vs. 35.85%) at 10 clients. Against FEDPUB (Baek et al., ICML 2023), the advantage is even more pronounced, with FEDSTRUCT(H2V) outperforming by +17.45 pp on Cora and +19.29 pp on Chameleon, as FEDPUB's community-detection-based aggregation degrades sharply under random partitioning. Against FEDGCN (Yao et al., NeurIPS 2024), which requires server access to the global adjacency matrix and shares 2-hop aggregated node features (a privacy breach), FEDSTRUCT(H2V) is slightly below on homophilic Cora (79.27% vs. 82.90%) but surpasses it on both heterophilic graphs: Chameleon (52.60% vs. 48.77%) and Amazon Ratings (40.97% vs. 40.78%), while providing stronger privacy guarantees. Overall, FEDSTRUCT(H2V) is the only private method that approaches centralized performance across all datasets and partitioning schemes.

## Relation to Prior Work

FEDSTRUCT builds on the decoupled GCN framework (Liu et al., 2020; Dong et al., 2021), which separates propagation from update to avoid over-smoothing, and repurposes it as a privacy-preserving mechanism: because the L-hop combined adjacency matrix is static, it can be precomputed collaboratively once, eliminating the need to share node features during training. It departs from prior SFL methods (FEDSAGE+, FEDNI, FEDGCN) that rely on sharing or generating node features/embeddings across clients, instead exploiting only the global graph structure—which is less sensitive—as the sole cross-client signal. The HOP2VEC component extends task-agnostic structural embeddings (NODE2VEC, graphlet degree vectors, FEDSTAR) into a task-dependent, locally-computable alternative that does not require access to the full adjacency matrix.

## Why It Matters / Open Questions

FEDSTRUCT provides the first SFL framework that simultaneously handles heterophilic graphs, avoids sharing any node features or embeddings, and achieves near-centralized accuracy, addressing a concrete privacy gap in federated graph learning that prior methods (except FEDPUB) left open. The finding that structural information alone suffices to close most of the performance gap to centralized training challenges the prevailing assumption that cross-client feature sharing is necessary for effective SFL. Open questions include scalability to very large graphs (pruning is a heuristic), the security guarantees of the collaborative adjacency-matrix computation under adversarial clients, and whether the approach extends to other federated graph tasks beyond node classification (e.g., link prediction, graph classification).
