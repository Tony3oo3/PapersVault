## Problem

The rapid proliferation of deep learning models has made it extremely difficult to (i) select appropriate models for a given task and (ii) plan coherent chains of atomic actions across multiple models to fulfill complex, multi-modal user queries. Existing agent frameworks like HuggingGPT and ControlLLM address only sub-problems of this pipeline, lack formal guarantees on plan correctness, fail to respect user-specific constraints (e.g., licensing, model size), and do not provide trustworthy explanations for their decisions.

## Input / Output

The system accepts a free-form natural language query that may reference multi-modal data (image files, audio files, URLs, inline text) along with optional user constraints on model licensing, parameter count, or benchmark performance. The query is first parsed into structured components (instruction, input text, question, URL, data dictionary, categories) via few-shot LLM prompting. The output is a formally verified ordered plan of atomic actions, the actual execution results from the selected models (text, generated images, or audio), and a fine-grained explanation report justifying each planning decision.

## Method

HIVE combines a Capability Knowledge Graph (C-KG) with a PDDL-based formal planning backbone. The C-KG is constructed by extracting model cards from HuggingFace, aligning models with Papers With Code benchmark scores via arXiv paper IDs, and generating executable Python inference functions via LLM code synthesis; each model vertex carries performance metrics, properties, and a ready-to-run code snippet. At inference time, an LLM parses the user query and classifies relevant PDDL domains, which are merged into a unified domain file; a second LLM call selects the specific PDDL actions needed, and a Best First Width Search reasoner then computes a formally valid action ordering. Model selection is performed over the C-KG by maximizing p(y|q, M, C) subject to user constraints, and plan execution retrieves the corresponding Python snippets and maps query components to function arguments. This hybrid LLM-plus-formal-logic design is what distinguishes HIVE from pure prompt-based planners: the PDDL layer guarantees plan feasibility and explainability, while the C-KG provides the machine-readable model interface that enables constraint-aware selection.

## Results

On the MUSE benchmark (100 multi-modal, multi-task queries), HIVE achieves overall Task Selection (TS) of 0.74, Flow of Thought (FoT) of 0.73, and Final Output (O) of 0.62, outperforming HuggingGPT (0.57/0.51/0.53) and ControlLLM (0.43/0.43/0.47). HIVE light, using only 8-bit quantised 7B models, still surpasses both baselines with 0.69/0.64/0.55. HIVE reports 30% higher task selection accuracy than the best competitor and respects user-specified model constraints (license, size, benchmark performance) in 100% of tested cases, while HuggingGPT fails all constraint scenarios.

## Baselines & Comparisons

HIVE outperforms both HuggingGPT and ControlLLM across all three metrics (TS, FoT, O) and all query complexity levels (single, two, three tasks). Against HuggingGPT, HIVE gains +17 points on overall TS (0.74 vs. 0.57) and +22 points on FoT (0.73 vs. 0.51), while HuggingGPT retains a slight edge on single-task Final Output (0.83 vs. 0.79) due to its ChatGPT backbone producing high-quality text despite over-selecting tasks. Against ControlLLM, HIVE leads by +31 points on TS (0.74 vs. 0.43) and +30 on FoT, with ControlLLM's fine-tuned task decomposer failing to generalise beyond its training distribution. Even HIVE light (7B quantised models) surpasses both baselines overall, confirming the PDDL planning backbone's effectiveness independent of LLM scale. In trustworthiness analysis, HIVE produces zero cases of correct output with incorrect justification (⊥⊤), whereas HuggingGPT has 13 such cases and ControlLLM has 9, indicating HIVE's explanations are reliably aligned with its outputs.

## Relation to Prior Work

This paper extends the LLM-as-agent paradigm (HuggingGPT, ControlLLM, Chameleon) by replacing purely prompt-based task planning with a hybrid architecture that combines LLM parsing/decomposition with PDDL formal logic (Best First Width Search) for action sequencing. It introduces a Capability Knowledge Graph (C-KG) constructed from HuggingFace model cards and Papers With Code benchmark data, enabling constraint-aware model selection (license, size, performance) that prior agent frameworks lack. The MUSE benchmark is positioned as the first multi-modal, multi-task evaluation suite for such agent systems, filling a gap left by HuggingGPT's unreleased dataset and ControlLLM's fine-tuned decomposer.

## Why It Matters / Open Questions

The C-KG + PDDL combination offers a practical path to explainable, constraint-respecting model orchestration that pure LLM planning cannot guarantee — the zero trustworthiness failures (correct output, wrong plan) in HIVE versus 13 in HuggingGPT is a meaningful reliability signal for production deployment. However, the benchmark is limited to 100 queries and 15 models, the C-KG depends on HuggingFace coverage and Papers With Code alignment, and the image-to-audio pipeline still fails entirely. Open questions include whether the PDDL domain files scale to the full 125k-triple C-KG, how the system handles genuinely novel tasks outside the curated taxonomy, and whether the adapter-based extension (single backbone + LoRA variants) can match multi-model pipelines.
