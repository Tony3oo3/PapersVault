## Problem

Current large language models excel at either text generation or text embedding, but not both simultaneously. Prior work argued all text tasks reduce to generation, yet embedding-based tasks like retrieval and clustering remain critical in practice and cannot be practically handled by generating numeric sequences. This paper asks whether a single model can be trained to perform strongly at both generative and representational tasks without sacrificing performance on either.

## Input / Output

The model receives a text instruction followed by an input passage (query or document) in a consistent chat format. For embedding tasks, it outputs a 4096-dimensional numeric tensor computed via bidirectional attention over the input followed by mean pooling over the final hidden states (excluding instruction and format tokens). For generative tasks, it outputs a text response via causal attention and a language modeling head. The model uses sliding window attention, allowing it to handle inputs of arbitrary length for both task types, and the same architecture and weights serve both modes—only the attention pattern and output head differ.

## Method

GRIT finetunes a pretrained decoder LLM (Mistral 7B or Mixtral 8x7B) with a joint objective that sums a contrastive embedding loss (InfoNCE with in-batch negatives from the same dataset) and a language modeling loss, weighted by λ_Rep and λ_Gen. The model distinguishes the two streams through instructions and a special <|embed|> format token: embedding inputs are processed with bidirectional attention and mean pooling, while generative inputs use causal attention with loss computed only over response tokens. A key architectural choice is adapting the causally pretrained LLM to use bidirectional attention for embedding tasks during finetuning, which the ablations show significantly outperforms causal-only embeddings. For the generative loss, the paper introduces a mixed sample-level and token-level aggregation (e.g., token-level loss across 32 samples, then sample-level loss across 8 sub-batches) to balance the trade-off between short and long generations. The formulation supports different batch sizes for embedding (up to 2048) and generative (256) data within the same training step, enabling large contrastive batches without inflating generative compute.

## Results

On the Massive Text Embedding Benchmark (MTEB, 56 datasets), GRITLM 7B achieves an average score of 66.8, matching the embedding-only variant (66.8) and slightly exceeding E5 Mistral 7B (66.6) and OpenAI v3 (64.6). On generative tasks (MMLU, GSM8K, BBH, TyDiQA, HumanEval, AlpacaEval), GRITLM 7B achieves an average of 55.5, outperforming Llama 2 70B (46.4) and Tülu 2 7B (46.3), while GRITLM 8x7B reaches 65.7, surpassing Tülu 2 70B (65.1) and Mixtral 8x7B Instruct (60.3). For RAG on Natural Questions, Doc Caching with GRITLM 7B achieves a 33.38 match score (vs. 30.50 for standard RAG) while being 63% faster on CPU for 4000-token documents.

## Baselines & Comparisons

GRITLM 7B (66.8 MTEB avg) matches the embedding-only variant (66.8) and slightly outperforms E5 Mistral 7B (66.6), BGE Large 0.34B (64.2), and OpenAI v3 (64.6) on embedding, while simultaneously outperforming Llama 2 70B (46.4), Tülu 2 7B (46.3), Zephyr 7B (44.9), and Mistral 7B Instruct (44.1) on generative tasks (55.5 avg). The generative-only variant scores only 41.2 on MTEB, confirming that joint training via GRIT is essential for strong embedding performance. GRITLM 8x7B (65.7 generative avg) surpasses Tülu 2 70B (65.1) and Mixtral 8x7B Instruct (60.3) on generative tasks while retaining 65.7 on MTEB, though its embedding score drops slightly from GRITLM 7B due to a reduced embedding batch size (256 vs. 2048). Compared to dedicated embedding models like SGPT BE 5.8B (58.9 MTEB) and Instructor XL 1.5B (61.8), GRITLM 7B leads by 7.9 and 5.0 points respectively, while also achieving 55.5 on generative tasks where those models score near random (8.0 and N/A). For RAG, Doc Caching with GRITLM 7B achieves 33.38 match on Natural Questions, exceeding standard RAG (30.50) while reducing CPU latency by 63% for long documents, whereas Query-Doc and Doc-Query Caching degrade to near No-RAG baseline (~21) due to attention mismatches.

## Relation to Prior Work

GRIT unifies two previously disjoint instruction-tuning paradigms: representational instruction tuning (Su et al., 2023; Asai et al., 2022), which trains models to produce task-specific embeddings via contrastive objectives, and generative instruction tuning (Wei et al., 2022; Sanh et al., 2022), which trains models to produce text responses via language modeling. The closest prior work is SGPT (Muennighoff, 2022), which adapted a causal LLM for embeddings via BitFit but required separate symmetric/asymmetric models and did not handle the full breadth of embedding tasks. GRIT departs from prior embedding work by switching to bidirectional attention with mean pooling within a causal LLM, and from prior generative work by mixing sample- and token-level loss aggregation; it also introduces the practical innovation of using the same model for both retrieval and generation stages in RAG, enabling key-value state caching.

## Why It Matters / Open Questions

The key practical impact is simplifying RAG pipelines: by using one model for both retrieval and generation, GRITLM eliminates the need for separate embedding and generative models, reducing infrastructure complexity and enabling >60% speedup on long-document RAG via key-value caching. The finding that joint training matches single-objective training with no performance loss challenges the common assumption that multi-task objectives necessarily introduce trade-offs, suggesting that instruction-based disambiguation is sufficient to prevent interference. Limitations include higher finetuning compute, 4096-dimensional embeddings requiring 4× more storage than compact models, and residual attention/formatting mismatches in the caching variants that could potentially be resolved with an additional RAG finetuning stage.
