## Problem

While language models can solve retrieval tasks (finding a specific attribute from a context given a request), the internal mechanism by which they decompose and execute these tasks remains uncharacterized. Existing oversight methods only constrain model outputs, leaving internal processes unexamined, which is critical because the same output can be produced by trustworthy or untrustworthy mechanisms (e.g., prompt injection). This paper asks: how do LMs internally organize the processing of a request versus the retrieval from context, and can this understanding be leveraged for scalable internal oversight?

## Input / Output

The method takes textual prompts structured as a context (a table of attributes, e.g., a story with a character, city, and action) plus a request (a SQL-like query selecting a target attribute filtered by a condition). All ORION tasks enforce single-token outputs and decomposability, meaning any request can be validly applied to any context within the same task. For the oversight application, the input is a pair: a single human-verified trusted input and an untrusted input that may contain a distractor sequence. The output is the predicted label token (e.g., a city name) and, in the detection variant, a binary anomaly signal indicating whether the model is executing the intended request or an injected mechanism.

## Method

The core technique is residual stream patching: a single-input interchange intervention that replaces the residual stream at layer L at the last token position of input x₂ with its value from input x₁, revealing which layers carry the request representation versus the context representation. The key discovery is a universal emergent modular decomposition: middle layers (around 40–60% of depth) process the request, while late layers retrieve the correct entity from context, producing the 'request-patching' phenomenon where patching at the boundary causes the model to confidently output the request from x₁ applied to the context of x₂. This is validated across 18 models (125M–70B parameters) and 15 ORION datasets spanning six domains, with formal validation via interchange intervention accuracy (IIA) under causal abstraction. A fine-grained case study on Pythia-2.8b uses path patching to show that macroscopic modularity emerges from input-dependent microscopic mechanisms (e.g., city-specific attention heads), and that request-patching preserves the natural retrieval mechanism in late layers. The practical application patches the residual stream at L₂ from a single trusted input to an untrusted input, overwriting the request-processing step and thereby neutralizing prompt-injection distractors while requiring human supervision on only one input.

## Results

Across 18 open-source LMs (125M–70B parameters) and 15 ORION retrieval tasks, request-patching (residual stream patching at mid-layers) achieves ≥70% normalized probability of the correct modular label token R₁(C₂) in 98 out of 106 model-task pairs. In the prompt-injection mitigation application, request-patching from a single trusted input recovers Pythia-410m accuracy from 0% to 70.5% under a small-model distractor and Pythia-12b from 15.5% to 97.5% under a large-model distractor, while preserving near-perfect accuracy on control settings (≥98%). The high-level causal graph is validated via interchange intervention accuracy (IIA) >85% in 91 of 106 settings.

## Baselines & Comparisons

The paper does not compare against external prompt-injection mitigation or interpretability baselines; the primary comparison is internal, contrasting 'No intervention' (the model's natural behavior) against 'Request-patching' (the proposed intervention). On the small-model distractor, Pythia-410m improves from 0% to 70.5% accuracy, and on the large-model distractor, Pythia-12b improves from 15.5% to 97.5%, demonstrating that a single trusted input suffices to overwrite the distractor-triggered mechanism. In control settings (no distractor or ineffective control distractor), request-patching causes negligible degradation (≤2% drop), confirming it does not harm normal operation. The authors note that linear probes could serve as an alternative but would require a labeled dataset of intermediate activations, whereas request-patching needs only one trusted input. No head-to-head comparison with prior prompt-injection defenses (e.g., input filtering, output monitoring) is provided, which limits the practical positioning of the method.

## Relation to Prior Work

This paper extends the causal intervention framework (Geiger et al., 2021; Vig et al., 2020) and the residual stream formalism (Elhage et al., 2021) from narrow, single-model circuit analyses to a systematic cross-model, cross-task comparative study. Prior mechanistic interpretability work (Wang et al., 2022; Geva et al., 2023; Olsson et al., 2022) characterized individual circuits in specific models on specific tasks, while recent residual-stream patching studies (Hendel et al., 2023; Feng and Steinhardt, 2023) demonstrated task-vector transfer but without a unified benchmark. The key departure is the introduction of ORION, a decomposable dataset collection with abstract SQL-like annotations, which enables interchange interventions to be defined and interpreted uniformly across 18 models and 6 domains without setting-specific labor, and the validation of the resulting high-level causal graph via interchange intervention accuracy (Geiger et al., 2023).

## Why It Matters / Open Questions

The discovery of a universal modular decomposition—middle layers process the request, late layers execute retrieval—across 18 models spanning 125M to 70B parameters and 6 task domains provides a macroscopic organizing principle for LM internals that was previously absent from the interpretability literature. The proof-of-concept prompt-injection mitigation via request-patching is the first demonstration that scalable internal oversight (supervising mechanisms, not just outputs) is feasible, though it is limited to single-token outputs, two models, and simple question-answering. Key open questions include whether the modular separation extends to multi-attribute requests and multi-token generation, how this decomposition emerges during training, and whether the anomaly-detection predicates generalize beyond the collision-free setting where they currently fail.
