## Problem

Disaggregated LLM inference (separating compute-bound prefill from memory-bound decoding) is the most efficient serving paradigm, but deploying it across heterogeneous GPUs remains unsolved. Unlike colocated inference that only communicates activations, disaggregation requires transferring large KV caches between prefill and decoding replicas, creating a communication bottleneck that is highly sensitive to the varying bandwidths of heterogeneous network links (NVLink, PCIe, IB, RoCE, Ethernet). Additionally, the distinct resource demands of each phase interact with heterogeneous GPU capabilities (FLOPS, HBM bandwidth, memory capacity) in ways that existing heterogeneity-aware schedulers like HEXGEN do not handle.

## Input / Output

The scheduling algorithm consumes a GPU device set D where each node carries a memory capacity weight and each edge carries a communication bandwidth weight, along with workload characteristics (arrival rate, input/output sequence length distributions from the Azure Conversation dataset). It produces a complete model placement strategy: a partition of GPUs into serving groups, a type assignment (prefill vs. decoding) per group, a parallel strategy (TP×PP combination) per group, and a KV cache communication plan specifying which prefill replica pairs with which decoding replica and at what frequency. The system then serves incoming LLM inference requests end-to-end, producing generated text tokens while meeting SLO latency targets.

## Method

HEXGEN-2's core is a two-phase scheduling algorithm with iterative refinement that co-optimizes resource allocation, parallel strategies, and KV cache communication. Phase 1 (graph partition) uses spectral partitioning followed by Kernighan-Lin refinement to create memory-balanced GPU groups, then coarsens intra-group GPUs into super-nodes and performs a secondary partition that maximizes inter-type edge weights to ensure high-bandwidth links connect prefill and decoding replicas. Phase 2 (max-flow) transforms the partitioned graph into a directed flow network where compute node capacities encode the optimal parallel strategy (latency-optimal TP for prefill, throughput-optimal hybrid for decoding) and edge capacities encode KV cache transfer rates; the preflow-push algorithm then determines optimal request routing and communication frequencies. Iterative refinement applies max-flow-guided edge swaps—identifying bottleneck and underutilized edges from the flow solution—to escape local minima and progressively improve the partition until no further gains are possible.

## Results

Given the same price budget, HEXGEN-2 achieves up to 2.0× and on average 1.3× higher serving throughput compared to DistServe (homogeneous baseline), and up to 1.5× and on average 1.4× higher throughput compared to HEXGEN (heterogeneous baseline). HEXGEN-2 reduces average inference latency by 1.5× relative to both baselines. With only 70% of the homogeneous budget (heterogeneous setting 5), HEXGEN-2 maintains comparable throughput to DistServe and even outperforms it by 30% on specific workloads. The scheduling algorithm converges in 90–120 seconds, finding placements that deliver on average 1.8× higher throughput than a truncated variant or genetic algorithm.

## Baselines & Comparisons

Against HEXGEN (the state-of-the-art heterogeneous colocated inference system), HEXGEN-2 wins on throughput in nearly all settings and workloads, achieving up to 1.5× and on average 1.4× higher serving throughput, primarily by eliminating prefill-decoding interference and enabling phase-specific parallelism. Against DistServe (the state-of-the-art homogeneous disaggregated system), HEXGEN-2 achieves up to 2× and on average 1.3× higher throughput at the same budget, and reduces average latency by 1.5×; at 70% budget, HEXGEN-2 still matches or exceeds DistServe's performance. Against vLLM (Appendix F, homogeneous 8×H100 setup), HEXGEN-2 wins on HPLD (365 vs. 277 tokens/s) and LPLD (730 vs. 545 tokens/s) but slightly loses on HPHD (683 vs. 692) and LPHD (758 vs. 774), indicating that disaggregation's advantage is most pronounced when prefill and decoding workloads are imbalanced. The scheduling algorithm ablation shows that the max-flow-guided edge swap is critical: without it, the system gets stuck in local minima and delivers on average 1.8× lower throughput than the full algorithm.

## Relation to Prior Work

HEXGEN-2 sits at the intersection of two recently established lines of work: disaggregated LLM inference (DistServe, Splitwise) which separates compute-bound prefill from memory-bound decoding onto distinct GPU groups, and heterogeneous GPU scheduling (HEXGEN, Mélange, Helix) which optimizes resource allocation across mixed GPU generations. The key departure is that prior disaggregated systems assumed homogeneous high-end GPUs, while prior heterogeneous schedulers assumed colocated prefill-decoding; HEXGEN-2 is the first to formalize and solve the combined problem. Methodologically, it repurposes classical graph algorithms (spectral partitioning, Kernighan-Lin refinement, preflow-push max-flow) into a two-phase iterative scheduling framework tailored to the KV-cache communication constraints unique to disaggregated inference.

## Why It Matters / Open Questions

The practical significance is substantial: as GPU generations turn over (Nvidia's ~24-month cycle), organizations accumulate mixed-generation clusters, and this paper demonstrates that such pools can deliver LLM serving at 30% lower cost than homogeneous H100 deployments without sacrificing throughput or latency. Open questions include scalability beyond ~320 GPUs (scheduling time grows to ~48 minutes), handling dynamic workload shifts that would require re-scheduling, and integration with emerging optimizations like quantization or speculative decoding. The evaluation is limited to two model families (OPT-30B, LLaMA-2-70B) and a single cloud provider, leaving open whether the scheduling advantages persist across architectures and network topologies.
