## Problem

Existing multimodal benchmarks rely heavily on multiple-choice questions, cover only narrow task subsets, and require expensive multi-benchmark evaluation pipelines to approximate full capability assessment. There is no unified, cost-effective protocol that systematically covers the breadth of real-world multimodal tasks while preserving the diversity of output formats that generative VLMs actually produce.
![Teaser figure](../imgs/ICLR20251018/cropped_page0_idx1.webp)

## Input / Output

Each task query pairs one or more visual inputs (single image, multi-image, or video clip) with a text instruction, and the model's free-form response is scored against a ground truth using one of 45 task-specific metrics. The Core Set (440 tasks) uses rule-based metrics (string matching, code execution, coordinate distance, JSON validation) for fast, cost-free evaluation, while the Open-Ended Set (65 tasks) uses GPT-4o as an LLM judge with per-task rubrics scoring 1–10. The final output is a weighted overall score plus a multi-dimensional breakdown across application type, input format, output format, and required skill, enabling interactive radar-map and bar-chart visualizations.

## Method

MEGA-BENCH is constructed via a top-down taxonomy tree with 8 first-level application categories (perception, planning, reasoning, knowledge, information extraction, coding, mathematics, metrics) and ~40 second-level meta-tasks, which guides 16 expert annotators through two rounds of task creation (505 tasks, ~8,200 examples total). Rather than forcing all tasks into a single output format, the benchmark embraces unrestricted outputs—numbers, phrases, code, LaTeX, coordinates, JSON, free-form text—and implements over 40 rule-based metrics plus LLM-assisted scoring, all normalized to [0,1]. A one-shot in-context example is prepended to each query to demonstrate the expected output format, and Chain-of-Thought prompting is optionally applied to Core tasks. Quality control uses commercial VLMs (GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro) to flag trivially easy or broken tasks, and bootstrap analysis confirms that ~15 examples per task suffice for stable score estimation.

## Results

On MEGA-BENCH (505 tasks, ~8,200 samples), Claude-3.5-Sonnet (1022) achieves the highest overall score of 54.27 (Core w/ CoT: 52.59, Open-ended: 65.63), narrowly edging out GPT-4o (0513) at 54.21 (Core w/ CoT: 52.65, Open-ended: 64.78). Among open-source models, Qwen2-VL-72B leads with an overall score of 47.70, outperforming the second-best open-source model (InternVL2-Llama3-76B at 37.73) by approximately 10 percentage points. Among efficiency models, Gemini-1.5-Flash-002 scores 43.82 overall, while the weakest models (Idefics3-8B-Llama3, Llama-3.2-11B) score below 18. CoT prompting improves all proprietary flagship models on the Core set but degrades 10 of 13 open-source models.

## Baselines & Comparisons

Claude-3.5-Sonnet (1022) and GPT-4o (0513) are nearly tied overall (54.27 vs. 54.21), but GPT-4o wins on the Core rule-based set (52.65 vs. 52.59) while Claude wins on Open-ended (65.63 vs. 64.78); GPT-4o leads in information extraction and knowledge tasks, while Claude excels in planning and math. The older Claude-3.5-Sonnet (0620) scores 52.13, a clear 2+ point gap below GPT-4o, confirming the 1022 update's substantial improvements. Among open-source flagships, Qwen2-VL-72B (47.70) substantially outperforms InternVL2-Llama3-76B (37.73), LLaVA-OneVision-72B (33.79), and NVLM-72B (25.57), approaching closed-source Gemini-1.5-Pro (49.55). In the efficiency tier, Gemini-1.5-Flash-002 (43.82) and GPT-4o mini (43.07) lead, with Gemini-1.5-Flash particularly strong on Science and Metrics tasks but weaker on UI/document inputs compared to GPT-4o mini. A notable finding is that CoT prompting consistently helps proprietary models (e.g., Claude 1022 gains +3.39 on Core) but hurts 10 of 13 open-source models, with Qwen2-VL-72B dropping from 46.41 to 45.42 and LLaVA-OneVision-72B from 31.99 to 29.74.

## Relation to Prior Work

MEGA-BENCH extends the line of multimodal evaluation benchmarks (MMMU, MMBench, MMT-Bench, Seed-Bench) by departing from their reliance on multiple-choice questions and single-metric scoring. It draws conceptual inspiration from BIG-bench's collaborative, taxonomy-driven annotation process and from the LLM-as-a-judge paradigm for open-ended evaluation, but scales task diversity to 505 tasks with 45+ customized metrics and unrestricted output formats. The key departure is treating output format diversity (code, LaTeX, coordinates, JSON, free-form) as a first-class evaluation dimension rather than a constraint to be eliminated, and organizing tasks via an application-driven taxonomy tree that guides annotation coverage.

## Why It Matters / Open Questions

MEGA-BENCH provides a practical, cost-effective unified evaluation protocol that replaces the current practice of running 20+ separate benchmarks, while its multi-dimensional breakdown (input type, output format, skill, application) reveals model strengths and weaknesses invisible in aggregate scores. The finding that 10 of 13 open-source models perform worse with Chain-of-Thought prompting challenges the near-universal adoption of CoT as a default inference strategy and highlights a fundamental gap in open-source model training. Open questions include whether the taxonomy remains comprehensive as new multimodal capabilities emerge, whether the GPT-4o-based judge introduces systematic bias for the 65 open-ended tasks, and how the benchmark evolves as models close the remaining gaps in planning and structured-output tasks.
