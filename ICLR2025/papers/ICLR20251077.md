## Problem

Existing AI software engineering methods treat code repositories as flat documents or rely on file-level semantic retrieval, missing the intricate line-level inter-dependencies (function calls, class references, containment) that span across files. This limits LLMs' ability to navigate complex codebases and make repository-wide decisions when resolving real-world GitHub issues, as demonstrated by the gap between function-level coding benchmarks and repository-level tasks like SWE-bench.

## Input / Output

The method takes a Python code repository (parsed via tree-sitter AST) and a search term (a key function or class name determined by the current task state) as input, and produces a k-hop ego-graph subgraph that is flattened into textual dependency context for LLM prompts. The underlying graph G={V,E} has nodes representing individual code lines classified as 'definition' or 'reference', with edges encoding 'invoke' (call) and 'contain' (structural) relationships. Project-independent relations (Python built-ins, third-party library imports) are filtered out during construction to reduce noise.

## Method

REPOGRAPH is a plug-in module that constructs a line-level code graph from a repository in three steps: (1) tree-sitter AST parsing to extract function/class definitions and their references, (2) filtering of project-independent relations (global built-ins and local third-party imports), and (3) graph organization into def/ref nodes connected by invoke and contain edges. At inference time, k-hop ego-graphs are retrieved around a search term and flattened into textual context. The module integrates seamlessly into both procedural frameworks (appended as dependency context in localization and editing prompts) and agent frameworks (added as a 'search_repograph' action in the agent's action space). The key differentiator is operating at line-level granularity rather than file-level, capturing fine-grained call chains and structural containment that file-level RAG or skeletal file representations miss, while ego-graph retrieval keeps the context focused on immediate dependencies around the relevant code.

## Results

On SWE-bench-Lite, REPOGRAPH as a plug-in module achieves an average relative improvement of 32.8% across four baselines spanning both procedural and agent frameworks. The best configuration, Agentless+REPOGRAPH with GPT-4o, reaches a 29.67% resolve rate (89/300 samples), establishing a new state-of-the-art among open-source methods. On CrossCodeEval (Python subset, 2,665 samples), REPOGRAPH more than doubles the exact-match code completion score for GPT-4o (10.5→28.7) and Deepseek-Coder (10.2→19.7), confirming transferability to general repository-level code completion.

## Baselines & Comparisons

REPOGRAPH consistently outperforms all four baselines on the resolve rate metric. Against RAG (GPT-4), it more than doubles the resolve rate from 2.67% to 5.33% (99.6% relative gain) and nearly doubles the patch application rate from 29.33% to 47.67%. Against Agentless (GPT-4o), it improves the resolve rate from 27.33% to 29.67% (+2.34 absolute), with the largest absolute gain in patch application among procedural methods. Among agent frameworks, REPOGRAPH lifts AutoCodeRover (GPT-4) from 19.00% to 21.33% and SWE-agent (GPT-4o) from 18.33% to 20.33%, with corresponding patch-apply gains of +3.67 and +3.33 points. The paper notes that gains are slightly larger on procedural frameworks than agent frameworks, attributing this to the deterministic flow of procedural methods enabling smoother plug-in integration, while agent frameworks suffer from larger exploration spaces and higher token costs (e.g., SWE-agent+REPOGRAPH costs $2.69 vs. $2.53 baseline).

## Relation to Prior Work

REPOGRAPH carves out a distinct niche by operating at the code-line level, whereas prior repository-level approaches (DraCo, Aider, RepoUnderstander, CodexGraph) work at file-level granularity. It departs from RAG-based retrieval (which captures semantic similarity but not structural dependencies) and from agent frameworks that treat repositories as flat documents, instead constructing an AST-derived graph of definition/reference nodes with invoke and contain edges via tree-sitter. As a plug-in module, it is explicitly designed to be orthogonal to both procedural (RAG, Agentless) and agent-based (SWE-agent, AutoCodeRover) frameworks, adding a 'search_repograph' action or subgraph context without modifying the underlying pipeline. Concurrent works RepoUnderstander and CodexGraph also model code as knowledge graphs, but REPOGRAPH differentiates itself through line-level resolution and ego-graph retrieval rather than whole-graph traversal.

## Why It Matters / Open Questions

REPOGRAPH demonstrates that structured, line-level repository navigation is a practical and transferable component for AI software engineering, achieving a new open-source SOTA on SWE-bench (29.67%) with consistent 2–3 point absolute gains across four diverse frameworks and two LLM families. The finding that 2-hop ego-graphs with direct flattening actually degrade performance below baseline (26.00% vs. 27.33%) highlights a non-trivial context-length trade-off that practitioners should account for. Key limitations include evaluation only on Python, proprietary GPT-4-series models, and the SWE-bench-Lite subset; extending to other languages, open-source LLMs, and dynamic/real-time graph updates remain open questions that will determine whether this line-level graph approach generalizes beyond the current experimental scope.
