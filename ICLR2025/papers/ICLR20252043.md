## Problem

Existing KV cache compression methods for long-context LLM inference optimize along the sequence length (token eviction) or precision (quantization) dimensions, but largely overlook the channel dimension D within each attention head. The paper identifies that key cache channels exhibit significantly imbalanced magnitudes and that attention weights possess a low-rank structure, revealing substantial redundancy along the channel dimension that can be exploited for further memory reduction without accuracy loss.
![Teaser figure](../imgs/ICLR20252043/cropped_page1_idx0.webp)

## Input / Output

The method consumes query vectors Q and key cache channels K from a trailing observation window of S_obs tokens (default 32) to compute per-channel importance scores. It outputs a pruned key cache retaining only the top T = ⌊(1−λ)D⌋ channels per head, along with a binary channel mask of negligible memory overhead. During decoding, the query is split into pruned and unpruned portions that are separately multiplied against their corresponding key subsets, then concatenated—so the cache stores two categories: pruned keys at reduced channel size and unpruned recent tokens at full size.

## Method

THINK formulates channel selection as minimizing the Frobenius norm of the difference between original and pruned attention weights, subject to a cardinality constraint on the number of retained channels. This yields a greedy scoring criterion Score_i[j] = ‖Q_i[:,j] K_i[:,j]ᵀ‖_F that measures the interaction magnitude between query and key vectors for each channel j in head i, computed only over the last S_obs observation window to limit cost. The top T channels are retained per head, and the corresponding query channels are pruned identically to maintain dimensional consistency. The approach is entirely online and plug-and-play: it requires no weight modification, no calibration data, and is orthogonal to token-eviction methods (H2O, SnapKV) and quantization methods (KIVI), enabling compositional memory savings. A 40% channel pruning ratio reduces total KV cache memory by 20% while maintaining or slightly improving accuracy across LLaMA and Mistral models on LongBench and Needle-in-a-Haystack benchmarks.

## Results

On LongBench with Mistral-7B-Instruct-v0.2, SnapKV+THINK(0.4) at KV-size 2048 achieves 42.27 average, matching or slightly exceeding SnapKV alone (42.18) while reducing KV cache memory by 20%. Combined with KIVI 2/2 quantization, THINK(0.4) achieves 31.77 average (vs. KIVI's 31.92) with a 2.8× peak memory reduction, enabling batch size to increase from 4× to 5× on a single GPU. On Needle-in-a-Haystack, THINK(0.4) matches or exceeds SnapKV across all KV-sizes (e.g., 90.9% vs. 90.8% at KV-size 2048 for Mistral). At identical memory budgets (Table 7), THINK consistently outperforms vanilla H2O and SnapKV by 0.3–0.6 points on average across all tested KV-sizes.

## Baselines & Comparisons

Against H2O (token eviction), THINK(0.4) matches or slightly improves accuracy at the same KV-size (e.g., 37.49 vs. 37.38 at KV-size 512 on Mistral), and at identical memory budgets outperforms H2O by 0.3–0.4 points across all KV-sizes (Table 7). Against SnapKV (observation-window token selection), THINK(0.4) achieves comparable or marginally better results at larger KV-sizes (42.27 vs. 42.18 at KV-size 2048) but shows a small drop at KV-size 128 (35.16 vs. 35.29); at the same memory budget, THINK consistently wins by ~0.3 points. Against KIVI (2-bit KV quantization), THINK(0.4) introduces only a 0.15-point average drop (31.77 vs. 31.92) while further reducing KV cache memory by 20%, yielding a combined 2.8× peak memory reduction. Against SVD-based methods, THINK(0.4) on Mistral-7B achieves 42.76 average (only 0.12% below vanilla 42.71), whereas Palu drops to 41.43 (1.28% drop) at 80% compression; on LLaMA-2-7B, THINK(0.4) scores 33.25 vs. ASVD's 28.16 (a 5.21% drop for ASVD). Overall, THINK is orthogonal to and composable with all five baselines, consistently matching or exceeding their accuracy while reducing memory.

## Relation to Prior Work

This paper extends the KV cache compression literature, which has primarily targeted the sequence-length dimension (H2O, SnapKV, StreamingLLM) or the precision dimension (KIVI, SmoothQuant), by identifying and exploiting redundancy along the previously overlooked channel dimension D. It builds directly on SnapKV's observation-window mechanism for computing importance scores and on KIVI's observation that key cache magnitudes are channel-imbalanced, but repurposes these insights for structural pruning rather than quantization. The SVD-based low-rank analysis connects to prior work on attention matrix structure (Bhojanapalli et al., 2021; Wang et al., 2020), and the method is explicitly positioned as orthogonal and composable with both token-eviction and quantization approaches.

## Why It Matters / Open Questions

THINK provides a practical, plug-and-play 20%+ KV cache memory reduction that stacks multiplicatively with existing compression methods, enabling meaningful batch-size increases (e.g., 4×→5× with KIVI on a single GPU) for long-context serving. The key open question is whether value cache channel pruning can be made as effective as key cache pruning, since the value cache exhibits more uniform channel magnitudes and less query-dependent sparsity. A noted limitation is the slight TTFT increase from online channel-importance computation, and the method's robustness at very high pruning ratios (≥60%) with small KV-sizes degrades, suggesting a practical ceiling around 40–50% channel reduction.
