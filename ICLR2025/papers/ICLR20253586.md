## Problem

Despite the availability of tools like GPT Code Interpreter and multi-agent frameworks such as AutoGen, there is no reliable method to steer LLMs toward code generation when it would outperform textual reasoning. The paper identifies that current approaches fail to make this decision optimally, that forcing code can degrade performance, and that an unexpected inverse scaling behavior emerges where smaller models with Code Interpreter outperform larger ones on certain tasks.
![Teaser figure](../imgs/ICLR20253586/cropped_page1_idx0.webp)

## Input / Output

The system consumes a natural language task prompt from 14 diverse tasks (math, logic, planning, symbolic computation) optionally augmented with system prompts (AutoGen, CAMEL) or explicit code/text guiding instructions. Outputs are either direct textual answers, executable Python code (subject to a 30-second execution timeout on a 16-core CPU), or a hybrid, with final answers evaluated by predefined rules assisted by GPT-4o for format normalization. Performance is measured as per-task success rate, aggregated via an Average Normalized Score that normalizes each task's score relative to its maximum across methods.

## Method

This empirical study systematically evaluates 7 baseline steering methods (Only Question, All Text, All Code, All Code+CoT, AutoGen Conca., AutoGen System, Code Interpreter) across 14 tasks and 6 LLMs, revealing that no single method dominates and uncovering inverse scaling where GPT-3.5 with CI outperforms GPT-4o on Game 24 and Number Multiplying due to overconfidence in textual reasoning. Three proposed methods address these gaps: Code Interpreter+ (prompting CI to favor code generation), Code+Text+Sum. (a multi-agent framework that generates both code and text answers in parallel, then a summarizer LLM combines them into a final answer), and Self-estimate Score (the LLM rates its 0-10 confidence in code vs. text before selecting an approach). A multi-turn refinement loop is also implemented, executing generated code and returning results for iterative self-reflection until a 'Terminate' signal or maximum iteration count. Code+Text+Sum. achieves the best average normalized score (79.5%) and rank (2.50) across all six models, though at substantially higher token costs (~3,680 tokens vs. ~575 for Only Question) and runtime.

## Results

Across 14 tasks and 6 LLMs, the proposed Code+Text+Sum. method achieves the highest Average Normalized Score of 79.5% (rank 2.50), outperforming the best baseline All Code (77.2%, rank 3.33) and Code Interpreter (76.3%, rank 6.33). No single method dominates all tasks: for example, All Text wins on Date Understanding (88% for GPT-4o) while All Code wins on Number Multiplying (100%), and the Code Interpreter shows inverse scaling where GPT-3.5 (100%) outperforms GPT-4o (84%) on Number Multiplying. Multi-turn refinement improves code-heavy methods (All Code rises from 77.2% to 78.6% at turn 2) but degrades text-heavy methods, and GPT-3.5 degrades across all methods after refinement.

## Baselines & Comparisons

The proposed Code+Text+Sum. method (79.5% avg.) outperforms all four baselines: AutoGen Conca. (74.8%), AutoGen System (67.7%), GPT-4 Code Interpreter (76.3%), and All Code+CoT (77.1%). Against the Code Interpreter baseline, Code+Text+Sum. gains +3.2 points on average and achieves the top score on 4 of 6 models (GPT-4o: 88.1 vs. 83.5; GPT-4o-mini: 85.0 vs. 80.8; O1-preview: 90.2 vs. NA; Claude-sonnet: 76.2 vs. NA). The AutoGen system prompt baseline (67.7%) is the weakest overall, with GPT-3.5 dropping to 55.5%, while the AutoGen concatenation variant (74.8%) performs well on GPT-4o (84.5%) but poorly on GPT-4o-mini (71.8%). The CAMEL prompt ablation (72.3% for the concatenation equivalent) confirms that prompt choice has negligible impact relative to the structural code+text combination. Notably, Code+Text+Sum. outperforms both All Text and All Code individually on 4 of 6 models, validating that combining both reasoning channels is more effective than either alone.

## Relation to Prior Work

This paper positions itself at the intersection of code-augmented LLM reasoning (PAL, Program of Thoughts, MathCoder) and multi-agent frameworks (AutoGen, CAMEL, Mixture-of-Agents), but departs from both by treating the *decision* of when to use code versus text as a first-class optimization problem rather than assuming one modality dominates. Prior work either commits to code-only pipelines or text-only reasoning chains; here the authors systematically evaluate 7 steering strategies across 14 tasks and 6 models, revealing that no single strategy is universally optimal. The multi-turn self-refinement component draws on Self-Refine and CRITIC, while the Code+Text+Sum. method extends the Mixture-of-Agents idea to a code/text dual-channel setting.

## Why It Matters / Open Questions

The finding that forcing code can be *worse* than text, and that smaller GPT models outperform larger ones under Code Interpreter (inverse scaling), challenges the default assumption that more capable models and code augmentation are always beneficial. Practically, the paper provides a cost-aware decision framework (token length, runtime vs. accuracy) for choosing among steering methods, but the best-performing method (Code+Text+Sum.) incurs ~6× the token cost of single-shot baselines, leaving a clear gap for more efficient approaches. Open questions include whether a dedicated scoring model can learn the code/text boundary, whether the inverse scaling generalizes beyond the GPT CI product, and whether more sophisticated multi-agent orchestration can close the accuracy-cost tradeoff.
