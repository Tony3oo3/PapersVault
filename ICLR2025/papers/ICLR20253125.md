## Problem

State-of-the-art SWE agents achieve similar overall resolve rates (26–31% on SWE-Bench Lite) yet resolve very different subsets of issues, meaning no single agent dominates across all problem types. This paper asks how to systematically harness the complementary expertise of diverse agents to substantially outperform any individual agent, and whether LLMs can serve as effective code reviewers to select the best candidate patch from a group.
![Teaser figure](../imgs/ICLR20253125/cropped_page0_idx1.webp)

## Input / Output

For each candidate patch, DEIBASE receives four inputs: the GitHub issue description, relevant code spans (pre-identified by Moatless Tools to stay within LLM context limits), and the code before and after the patch presented separately rather than as a unified diff (since diff format is harder for LLMs to parse). The output is an integer score from 0 to 10 per patch, generated 10 times at temperature 1.2 and averaged; the highest-scoring patch is selected as the final answer. The scoring rubric penalizes wrong modification locations (score 0), contradictions with identified code spans (−1 each), and introduction of new issues (−2).

## Method

DEI is formulated as a meta-policy π_DEI over a contextual MDP that selects among N existing agent policies based on the observed context, maximizing expected cumulative reward across all contexts. The concrete implementation, DEIBASE, uses an LLM (GPT-4o) as a code-review committee in a three-step pipeline: (1) input construction assembling issue text, relevant code spans, and before/after code; (2) ordered explanation generation where the model sequentially produces issue, context, location, patch, and conflict-detection explanations, each building on prior ones; (3) rubric-based scoring where the model assigns a 1–10 score informed by its own explanations. The key empirical finding is that inter-agent diversity (different frameworks) yields far more complementary coverage than intra-agent diversity (multiple runs of the same agent), and that a committee of 4 open-source agents with a 27.3% best individual rate reaches 34.3% with DEIBASE, while a 5-agent closed-source group reaches 55.0%.

## Results

On SWE-Bench Lite (300 instances), DEIBASE-Open, composed of 4 open-source agents (Agentless, Moatless, Aider, OpenDevin+CodeAct), achieves a 34.3% resolve rate, a 25% relative improvement over the best individual agent in the group (Agentless at 27.3%). The best DEI committee, DEIBASE-1 (top 2 agents), reaches 55.0%, securing the highest ranking on the SWE-Bench Lite leaderboard. An oracle reranker over the same open-source group could achieve 54.3%, indicating substantial remaining headroom. DEIBASE-2, using 5 closed-source agents, achieves 37%, outperforming all its individual members (ranging from 28.0% to 31.3%).

## Baselines & Comparisons

DEIBASE-Open (34.3%) outperforms every individual open-source agent in its committee: Agentless (27.3%), Moatless (26.6%), Aider (26.3%), and OpenDevin+CodeAct (26.0%), yielding a 7-point absolute gain over the best member. Notably, DEIBASE-Open also surpasses several closed-source systems including Bytedance MarsCode (34.0%), Alibaba Lingma (33.0%), Factory Code Droid (31.3%), AutoCodeRover (30.6%), Amazon Q Developer (29.6%), CodeR (28.3%), and MASAI (28.0%). DEIBASE-1 (55.0%) beats the next-best leaderboard entry, Cosine Genie (50.6%), by 4.4 points. DEIBASE-2 (37.0%) improves over all five of its closed-source members (28.0%–31.3%) but falls slightly short of AbenteAI MentatBot (38.0%), which is not a member of its group. The paper also shows that inter-agent diversity yields larger gains than intra-agent diversity: for 10 candidates, Union@k is 2× Average@k across different agents versus only 1.5× for multiple runs of the same agent.

## Relation to Prior Work

This paper sits at the intersection of SWE agent research (Agentless, Moatless, Aider, OpenDevin, SWE-agent) and multi-agent/ensemble methods (MetaGPT, AutoGen, Mixture-of-Agents, self-consistency). Rather than building on a single prior architecture, DEI repurposes the LLM-as-a-judge paradigm for a new application: a meta-policy that selects among independently generated patches from *different* agent frameworks, framed formally as a contextual MDP with a selection policy over agent policies. It departs from prior multi-agent collaboration work (group chatting, debating, hierarchical task assignment) by having agents work independently and a separate re-ranking module choose the best output, rather than having agents interact during generation.

## Why It Matters / Open Questions

The systematic quantification of inter-agent vs. intra-agent diversity (Union@k gaps) provides a concrete, actionable signal for the SWE agent community: combining diverse agents yields far more headroom than repeated runs of a single agent. The 25% relative improvement from DEIBASE-Open (27.3%→34.3%) demonstrates that a simple LLM code-review pipeline can close a meaningful portion of the oracle gap (54.3%), suggesting LLMs are competent patch evaluators. However, the oracle gap remains large (34.3% vs 54.3%), DEIBASE plateaus with more than ~5 candidates, and failure analysis reveals systematic biases (over-detecting conflicts in correct patches, being misled by plausible-sounding incorrect patches). Open questions include whether a trained DEI policy (rather than prompt-based) can narrow the gap further, whether DEI feedback can iteratively refine patches (early evidence is positive but limited to 10 issues), and whether the approach generalizes beyond SWE-Bench-style tasks.
