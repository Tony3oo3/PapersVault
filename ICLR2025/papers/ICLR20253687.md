## Problem

Identifying coherent, interpretable error slices—subsets of data where models systematically fail—remains challenging because prior slice-then-tag methods produce incoherent clusters in entangled embedding spaces, while tag-then-slice methods suffer from narrow object-centric attribute focus, combinatorial explosion during multi-attribute slice enumeration, and an inability to predict high-risk slices beyond the validation set.
![Teaser figure](../imgs/ICLR20253687/cropped_page2_idx0.webp)

## Input / Output

The method consumes validation set images, per-sample model predictions (accuracy, OKS, or IoU), and a task description, using GPT-4V to generate structured visual attributes and tags in a single forward pass per image (~6 s). Outputs include a categorized attribute-tag schema (main object / background / global), enumerated error slices defined as attribute-tag combinations whose average performance falls below the overall model performance by a constant C (0.2 in experiments), predicted unseen slices via tag substitution and instruction-based GPT queries, and a prioritized list of data queries for model repair. Slice enumeration is dataset-specific and run once; post-processing is model-specific and takes only seconds per model.

## Method

HiBug2 employs a structured, two-pronged attribute generation process: a comparative approach (presenting GPT with image pairs to extract contrasting attributes for data-distribution errors) and task-specific queries targeting inherent difficulties (e.g., boundary-blurring features for classification, occlusion/localization features for detection), with attributes categorized into main object, background, and global. Tags are determined through multi-stage refinement—initial unbiased tag generation, validation-data review for coverage, then dataset-wide assignment—ensuring semantic consistency. For slice enumeration, HiBug2 uses a breadth-first tree-structured algorithm where child slices are formed by adding one attribute-tag pair to parent slices; it exploits the monotonicity of data counts to prune subtrees below a threshold M=10 and intersects matched pairs (slices sharing k−1 attributes) to avoid combinatorial explosion, achieving a 510× speedup over brute-force for 4-attribute slices. Post-processing removes slices whose average performance exceeds their parent's, and two complementary strategies—CLIP-embedding-based tag substitution and GPT few-shot instruction-based prediction—extend error slice discovery beyond the validation set.

## Results

HiBug2 achieves consistent improvements in model repair across three tasks: +7.6% accuracy on ImageNet bear classification (0.839 vs. 0.780 original), +2.1% keypoint AP on pose estimation (0.839 vs. 0.822), and +4.9% mAP on KITTI object detection (0.683 vs. 0.651). The efficient slice enumeration algorithm delivers a 510× speedup over brute-force enumeration for 4-attribute slices and a 115× speedup for 3-attribute slices. On predicted unseen error slices, models exhibit performance drops of up to 64.6% (object detection, tag substitution) and 18.4% (classification, instruction-based), confirming the practical risk of unexplored failure modes.

## Baselines & Comparisons

HiBug2 outperforms its direct predecessor HiBug on all three model repair tasks: +0.7% accuracy on classification (0.839 vs. 0.832), +0.8% AP on pose estimation (0.839 vs. 0.831), and +1.0% mAP on object detection (0.683 vs. 0.673), with the gap widening as the task becomes harder (e.g., pose estimation where HiBug gains only +1.1% over original). Against random data selection, HiBug2's advantage is most pronounced in object detection (+2.8% mAP over random) and classification (+2.2% accuracy), while the pose estimation gap is smaller (+1.0% AP) because random selection already benefits from the relatively uniform distribution of pose errors. In qualitative attribute comparison (Figure 3), HiBug2 produces structured, task-specific attributes covering main object, background, and global dimensions, whereas Domino generates overly generic single-word tags (e.g., 'van', 'delivery') that offer little diagnostic value, and HiBug focuses narrowly on surface-level object properties while neglecting contextual and image-quality factors.

## Relation to Prior Work

HiBug2 extends the tag-then-slice paradigm introduced by HiBug (Chen et al., 2024), which itself departed from earlier slice-then-tag methods (Spotlight, FACTS, Domino) that clustered in entangled embedding spaces and produced incoherent slices. The key departures from HiBug are threefold: a structured attribute generation process that covers main object, background, and global dimensions (addressing HiBug's object-centric bias), a breadth-first tree-structured enumeration algorithm with pruning and intersection that avoids combinatorial explosion, and a mechanism for predicting unseen error slices beyond the validation set. The method also draws on comparative image-pair prompting and task-specific LLM instructions to generate error-relevant attributes, building on the broader trend of leveraging multi-modal LLMs for structured visual analysis.

## Why It Matters / Open Questions

HiBug2 provides a practical, end-to-end debugging pipeline that addresses real pain points in model deployment: the 510x enumeration speedup makes multi-attribute slice exploration feasible, and the unseen-slice prediction (showing up to 64.6% performance degradation on predicted slices) highlights a previously unaddressed risk when validation sets are limited. However, the model repair gains are modest (7.6% for classification, 2.1% for pose estimation), the user study involves only 4 participants, and the authors themselves note the absence of a standardized evaluation benchmark for error slice discovery. Open questions include whether GPT-based tagging errors accumulate at scale, whether the structured attribute taxonomy generalizes beyond the three tasks tested, and how to establish ground-truth-free evaluation protocols that enable fair cross-method comparison.
