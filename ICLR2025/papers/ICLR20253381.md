## Problem

Modern LLM architectures process all input tokens uniformly, with no architectural mechanism to distinguish or prioritize system instructions, user prompts, and third-party data. This flat treatment allows lower-priority user prompts or injected data to override higher-priority system safety protocols, enabling prompt injection, prompt extraction, and harmful request attacks. Existing mitigations such as special delimiters and adversarial fine-tuning address the problem only at the prompt or training-data level, leaving the underlying embedding architecture unchanged.

## Input / Output

The method consumes standard text token sequences augmented with a per-token segment hierarchy label (0 = system instruction, 1 = user prompt, 2 = third-party data, 3 = model output), derived from the stakeholder structure of the LLM application. The output is a standard autoregressive text generation, but the model now conditions each token's representation on its instructional role. The segment labels are a lightweight addition requiring only H×D extra parameters (H=4 by default), and the design is flexible—categories can be subdivided (e.g., tool output vs. web data) or omitted depending on the application.

## Method

The core contribution is a learnable segment embedding matrix E^Seg ∈ R^{H×D} (H=4) that encodes instruction hierarchy directly into the input representation, inspired by BERT's segment embeddings but repurposed for privilege differentiation rather than next-sentence prediction. Each token x_m is tagged with its hierarchy level h_m ∈ {0,1,2,3}, and the corresponding segment embedding E^Seg[h_m] is summed with the token embedding before feeding into self-attention layers, giving every token a persistent, position-independent signal about its instructional priority. Unlike delimiter-based approaches where priority information appears only at a few boundary tokens and can be extracted by attackers, ISE provides a per-token signal that persists throughout long contexts. The segment embedding layer is trained end-to-end via supervised fine-tuning on structured prompt-response data (including adversarial samples with misaligned instructions), enabling the model to learn to reject or ignore lower-priority instructions that attempt to override higher-priority ones. Experiments on Llama-2-13B, Llama-3-8B, and Llama-3.1-8B show up to 15.75% and 18.68% average robust accuracy gains on Structured Query and Instruction Hierarchy benchmarks respectively, while maintaining or improving instruction-following capability on AlpacaEval.

## Results

On the Structured Query benchmark, ISE achieves an average in-domain robust accuracy of 66.35% on Clean Alpaca (vs. 50.84% baseline and 50.60% delimiter), a +15.75% improvement, and 99.76% on Adversarial Alpaca. On the Instruction Hierarchy benchmark, ISE yields an average robustness boost of up to 18.68% across indirect/direct prompt injection, prompt extraction, and harmful requests. Instruction-following capability is maintained or improved, with up to +4.1% AlpacaEval win rate (83.35% vs. 79.25% on the Instruction Hierarchy dataset). Worst-case robust accuracy improves by 32.17% on in-domain attacks (Clean Alpaca), from 4.81% to 40.38%.

## Baselines & Comparisons

Against the STRUQ/Delimiter baseline (Chen et al., 2024), ISE substantially outperforms on Clean Alpaca: 66.35% vs. 50.60% average in-domain robustness (+15.75%) and 61.06% vs. 50.72% out-of-domain (+10.34%). On Adversarial Alpaca, both methods reach near-perfect in-domain scores (~99%), but ISE still leads on out-of-domain attacks (90.26% vs. 82.93%). Against the Wallace et al. (2024) Instruction Hierarchy baseline, ISE consistently wins across all four vulnerability types: prompt injection robustness improves by 5–25% (up to ~25% on UltraChat Baseline), prompt extraction by at least 10% (worst-case up to ~45%), and harmful requests by up to 18% across six categories. On capability, ISE matches or slightly exceeds both baselines on AlpacaEval (≤1% difference on Structured Query; up to +4.1% on Instruction Hierarchy) and MT-Bench, confirming no utility trade-off.

## Relation to Prior Work

This paper repurposes BERT's segment embedding mechanism (a learnable H×D matrix added to token embeddings) for a fundamentally different purpose: encoding instruction hierarchy in autoregressive LLMs. Prior work on instruction hierarchy (STRUQ/Chen et al., Wallace et al., Hines et al.) addresses the problem at the prompt or training-data level—using special delimiters, adversarial fine-tuning, or structured query formats—while leaving the underlying architecture's inability to distinguish instruction types intact. ISE departs from this line by introducing an architecture-level modification that is explicitly orthogonal to all prior mitigation strategies, positioning itself as a complementary rather than competing approach.

## Why It Matters / Open Questions

The method's simplicity (only H×D additional parameters, a few lines of code) and orthogonality to existing defenses make it an attractive drop-in enhancement for production LLM pipelines, and the consistent gains across three model families and four vulnerability types suggest the architectural gap is real. However, the evaluation is limited to 8B/13B models, single-turn conversations, and supervised fine-tuning, leaving open whether the approach scales to larger models, integrates with RLHF/pre-training, or generalizes to multi-turn settings. The complete failure against adaptive jailbreak attacks (Table 8) underscores that ISE addresses instruction-hierarchy confusion but not adversarial optimization, and the paper itself notes that combining ISE with adversarial training methods (LAT, circuit breakers) is a natural but unexplored direction.
