## Problem

Mixture-of-Experts (MoE) models decouple parameter count from computation but suffer from high memory access during inference, making them 2–6× slower than dense models at the same compute budget. Product Key Memory (PKM) maintains constant memory access but underperforms MoE significantly and lacks the characteristics needed for large-scale training. The paper asks: can an architecture match or surpass MoE quality while keeping memory access at dense-model levels?

## Input / Output

The model consumes standard text token sequences (GPT-NeoX BPE tokenizer, 50,432 vocabulary) and produces next-token predictions in a self-supervised language-modeling setup. The distinctive I/O detail is the memory layer: each token's hidden state is converted into row and column query vectors that address a 2-D logical grid over up to 20 million memory slots, but only top-m values (e.g., 42×2 per head) are actually fetched, keeping per-token memory access independent of total table size. The memory layer is inserted at fixed intervals (e.g., layers 3→7, 8→12, …) with skip connections rather than replacing the MLP in a single layer.

## Method

UltraMem replaces the MLP in a Pre-LayerNorm Transformer with multiple small ultra-sparse memory layers distributed across the stack. Retrieval uses Tucker Decomposed Query-Key Retrieval (TDQKR): row and column keys produce rank-r score matrices, a learnable Tucker core combines them, and a rank-1 SVD approximation of the core enables an efficient two-phase top-m selection that avoids scanning all N slots. Implicit Value Expansion (IVE) virtually multiplies the memory table by E× via E learned linear projectors applied on-demand after lookup, scaling memory size without proportional memory-access cost. Multi-Core Scoring (MCS) splits the value dimension into h sub-spaces, each with its own score map, increasing retrieval diversity. Additional structural changes—removing Softmax, LayerNorm on queries/keys, a causal depthwise conv before query projection, halving value dimension while doubling slot count, and linearly decaying the value learning rate—collectively yield a model that outperforms fine-grained MoE at matched parameters and FLOPs while maintaining near-dense inference speed.

## Results

At the 1.6B dense-model scale, UltraMem-1.6B-x12 (21.41B params, 3.50G FLOPs/token) achieves a C4 validation loss of 2.24 and an average benchmark score of 48.26, outperforming MoE-1.6B-2in34 (2.30 / 45.07) and matching or exceeding the 6.5B dense model (2.30 / 46.19) with roughly 4× less computation. At 680M scale, UltraMem reaches 2.37 val. loss and 42.27 avg, beating MoE (2.39 / 38.43) and PKM (2.46 / 39.70). Inference speed tests on A100 show UltraMem is up to 6× faster than MoE at batch size 64 while maintaining identical parameter and FLOP budgets.

## Baselines & Comparisons

Against PKM (Lample et al., 2019), UltraMem wins at every tested scale: at 1.6B it improves validation loss from 2.34 to 2.24 and average benchmark score from 42.97 to 48.26; at 680M from 2.46 to 2.37 and 39.70 to 42.27; at 151M from 2.76 to 2.67 and 28.64 to 29.99. Against fine-grained MoE (2-in-N, following Mixtral/DeepSeekMoE), UltraMem surpasses MoE at 680M (val. loss 2.37 vs 2.39; avg 42.27 vs 38.43) and 1.6B (2.24 vs 2.30; avg 48.26 vs 45.07), but trails MoE at the smallest 151M scale (2.67 vs 2.63; avg 29.99 vs 33.20), suggesting UltraMem's advantage grows with model capacity. Notably, UltraMem-1.6B-x12 matches the 6.5B dense model's validation loss (2.24 vs 2.30) and exceeds its average benchmark score (48.26 vs 46.19) while using only 3.50G FLOPs/token versus 12.88G — a roughly 3.7× computation saving. On inference speed, UltraMem is up to 6× faster than MoE at batch size 64 and its inference time remains nearly flat as sparse parameters grow, whereas MoE's latency increases significantly.

## Relation to Prior Work

UltraMem is a direct architectural extension of Product Key Memory (PKM, Lample et al., 2019), which itself can be viewed as the extreme fine-grained limit of Mixture of Experts. The key conceptual departure is replacing PKM's additive product-quantization scoring with Tucker Decomposed Query-Key Retrieval (TDQKR), borrowing the low-rank tensor factorization idea from Malik & Becker (2018), and introducing Implicit Value Expansion and Multi-Core Scoring to address PKM's inability to scale beyond small models. The paper positions UltraMem as the first sparse-memory architecture with the structural properties (split memory layers, on-demand value computation, multi-GPU sharding) needed for large-scale training, explicitly contrasting with prior PKM variants (PEER, Kim & Jung) that remained limited to smaller models.

## Why It Matters / Open Questions

The practical significance is the decoupling of parameter count from inference memory access: UltraMem achieves up to 6× faster inference than MoE at identical parameters and FLOPs, with inference speed nearly matching a dense model. This opens a path toward models with billions or trillions of memory slots without the prohibitive inference latency that has constrained MoE deployment. However, the evidence for outperforming MoE is concentrated at the 1.6B-activated-parameter scale (21B total), and the paper does not test beyond 20M memory slots or evaluate on downstream generation tasks, leaving open whether the scaling advantage persists at much larger scales or in multi-modal settings. The reliance on a single training recipe (RedPajama, 1T tokens) and the absence of comparison with the most recent fine-grained MoE variants (e.g., DeepSeek-V2) are notable gaps.
