## Problem

Existing GUI agents struggle to generalize across diverse desktop and mobile applications because they rely on static, pre-scripted action sequences or lack real-time OS feedback, making them unable to adapt when execution fails or when multiple valid solutions exist. The paper asks whether a single generalist agent can follow natural-language instructions across arbitrary applications using only standardized OS controls (mouse, keyboard, touch) while dynamically adjusting its strategy based on live system feedback.
![Teaser figure](../imgs/ICLR20252568/cropped_page1_idx1.webp)

## Input / Output

OSCAR consumes a natural-language user instruction, a current screen screenshot, a Set-of-Mark visual prompt generated from the native Accessibility (A11Y) tree (providing precise bounding boxes and element IDs), explicit semantic grounding labels (e.g., 'ID: 14, Label: Start, X1: 0.35, Y1: 0.95'), accumulated context memory (prior task list and action history), and real-time feedback from both execution (interpreter error messages) and verification (evaluation script results). It produces executable Python code via PyAutoGUI that references GUI elements by ID or coordinate, a two-level decomposed task list (SOP-based high-level tasks plus step-by-step sub-actions), and a terminal success/failure status after up to 4 re-planning attempts.

## Method

OSCAR operates as a finite state machine with nine states (Init, Observe, Plan, Execute, Verify, Success, Fail, Reset, Error) that creates continuous feedback loops for error recovery and adaptive re-planning. For GUI understanding, it employs a dual-grounding observation: a Set-of-Mark visual prompt extracted from the A11Y tree (more robust than detection+OCR pipelines on dense UIs) combined with explicit semantic labels that assign IDs and normalized coordinates to interactable elements. Planning uses a two-level task-driven re-planning strategy inspired by plan-and-solve prompting: Level 1 decomposes the user instruction into tasks via standardized operating procedures (SOPs), and Level 2 generates step-by-step actions interleaved with execution within the state machine. Crucially, when verification fails, OSCAR re-plans only the specific failed task rather than the entire workflow, leveraging stored context memory to avoid redundant re-planning and error propagation. The agent is powered by GPT-4o in an in-context learning setup (8 demonstrations, temperature 0.1) and outputs semantically clear Python code that controls the OS through PyAutoGUI, enabling precise mouse, keyboard, and touch interactions.

## Results

On the GAIA benchmark, OSCAR achieves a 28.7% average success rate, outperforming the prior best (MMAC at 24.0%), with a particularly strong 13.5% on Level 3 tasks—nearly doubling the previous state-of-the-art (6.1%). On OSWorld, a dynamic desktop OS environment with real-time feedback, OSCAR reaches 24.5% average success rate versus FRIDAY's 18.8% and UFO's 16.5%, with the largest gap in multi-application tasks (12.9% vs. 10.9%). On AndroidWorld, OSCAR achieves 61.6% average, surpassing AppAgent (59.9%) and Mobile Agent (40.8%), with the advantage most pronounced on medium (66.7% vs. 55.6%) and hard (52.6% vs. 42.1%) difficulty subsets.

## Baselines & Comparisons

OSCAR outperforms all 14 baselines across every benchmark it is evaluated on. On GAIA, OSCAR (28.7% avg) beats MMAC (24.0%), FRIDAY (22.4%), UFO (19.4%), GPT-4 plugins (13.3%), and GPT-4-turbo (5.5%), with the largest margin on Level 3 (13.5% vs. 6.1% for MMAC/FRIDAY). On OSWorld, OSCAR (24.5%) leads FRIDAY (18.8%) by 5.7 points, UFO (16.5%) by 8.0 points, and Cradle (10.5%) by 14.0 points, with the gap widening on multi-application tasks. On AndroidWorld, OSCAR (61.6%) edges out AppAgent (59.9%) and substantially outperforms Mobile Agent (40.8%) and M3A (33.5%). On the static GUI navigation benchmarks (Mind2Web, AITW), OSCAR without re-planning achieves the best step success rate (74.8% on AITW), surpassing M3A (68.0%), Mobile Agent, and AppAgent. On GUI-World understanding, OSCAR leads in 5 of 6 domains (Software, XR, Multi, iOS, Android) but trails WebAgent on Website tasks unless HTML input is provided. The key differentiator is that OSCAR is the only agent handling both desktop and smartphone OS with real-time dynamic feedback, while most baselines are restricted to one platform or lack adaptive re-planning.

## Relation to Prior Work

OSCAR builds on Set-of-Mark prompting (Yang et al., 2023a) for visual grounding and plan-and-solve prompting (Wang et al., 2023b) for hierarchical task decomposition, but departs from prior GUI agents (UFO, FRIDAY, AppAgent) in two key ways: it replaces linear action sequences with a state-machine architecture that supports task-driven re-planning (re-planning only the failed sub-task rather than the entire workflow), and it uses code-centric Python control via PyAutoGUI rather than discrete action tokens. The A11Y-tree-based grounding replaces the more common detection+OCR pipeline, and the agent is the first to operate across both desktop and smartphone OS environments with real-time dynamic feedback.

## Why It Matters / Open Questions

OSCAR demonstrates that a single generalist agent can handle both desktop and mobile OS automation with real-time feedback, a capability no prior agent achieved simultaneously. The task-driven re-planning mechanism offers a practical efficiency gain over full-workflow replanning, reducing redundant attempts and error propagation in multi-application workflows. However, the paper acknowledges significant open questions: safety metrics for agent actions are lacking, the verification state does not address harmful side effects, and cross-task learning remains constrained by scalability. The near-doubling of Level 3 GAIA performance (13.5% vs. 6.1%) suggests that fine-grained re-planning is particularly important for complex, multi-step tasks where prior methods fail.
