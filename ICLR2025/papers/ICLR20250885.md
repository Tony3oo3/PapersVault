## Problem

Existing LLMs, including GPT-4o, can only orchestrate workflows averaging 6.1 actions with predominantly sequential logic, falling far short of real-world requirements where Apple Shortcuts involve 70.4 actions and 2.6 nested logical structures on average. This limitation blocks the paradigm shift from Robotic Process Automation to Agentic Process Automation, where LLMs should autonomously build complex workflows from natural language instructions.
![Teaser figure](../imgs/ICLR20250885/cropped_page1_idx0.webp)

## Input / Output

The model takes a natural-language task query and a list of API documentation entries (function name, parameter names/types, descriptions, return values) as input, and produces a two-part output: a median-level task plan (a numbered natural-language flowchart of the workflow) followed by Python-style workflow code with per-line comments explaining each API call. The code supports if/else branches, for/while loops, and nested control structures, and must use only the provided APIs plus built-in Python syntax (if, for, input, print).

## Method

WorkflowLLM is a data-centric framework that constructs WorkflowBench (106,763 samples, 1,503 APIs, 83 apps) through three phases: (1) Data Collection — 14,771 human-authored Apple Shortcuts from RoutineHub are crawled, transcribed from property-list format into Python via AST pre-order traversal, and annotated with a bottom-up three-level thought hierarchy (per-action comments → task plan → task query) generated by GPT-4o-mini; (2) Query Expansion — GPT-4o-mini synthesizes diverse task queries by sampling 1–5 applications and their APIs, guided by in-context workflow examples to match real-world complexity; (3) Workflow Generation — a workflow annotator fine-tuned on the collected shortcuts generates code for synthetic queries, followed by GPT-4o-mini refinement and rule-based filtering (syntax check, API-constraint validation) to remove ~21% of low-quality samples. Llama-3.1-8B is then supervised-fine-tuned on the merged dataset for 3 epochs (AdamW, lr 2e-5, max seq 8192), yielding WorkflowLlama, which outperforms GPT-4o+ICL by a large margin on both CodeBLEU and Pass Rate under unseen-instruction and unseen-API settings.

## Results

On the WorkflowBench test set, WorkflowLlama (8B) achieves a CodeBLEU overall score of 39.3% and a Pass Rate of 76.9% under the unseen-instructions (ID) setting, and 35.1% CodeBLEU with 70.4% Pass Rate under the unseen-APIs (OOD) setting. On the out-of-distribution T-Eval benchmark, WorkflowLlama attains an F1 plan score of 77.5%, surpassing all open-source baselines including Qwen-72B (73.4%) and Llama-2-70B (63.1%), though trailing proprietary models like GPT-4 (86.7%). Ablation studies confirm that both the hierarchical thought annotations (task plan + comments) and the synthetic data expansion contribute meaningfully to performance.

## Baselines & Comparisons

WorkflowLlama (8B) outperforms all baselines by a wide margin on both CodeBLEU and Pass Rate across ID and OOD settings. Against the strongest proprietary baseline, GPT-4o with ICL, WorkflowLlama leads by 9.1 points in CodeBLEU (39.3% vs. 30.2%) and 9.4 points in Pass Rate (76.9% vs. 67.5%) under ID, and by 5.1 and 12.8 points respectively under OOD. Against the strongest open-source baseline, Llama-3.1-70B with ICL, the gap is even larger: 9.8 CodeBLEU points and 9.3 Pass Rate points under ID. On the OOD T-Eval benchmark, WorkflowLlama (77.5% F1) surpasses all open-source models including Qwen-72B (73.4%) and Llama-2-70B (63.1%), but remains below proprietary models GPT-4 (86.7%) and GPT-3.5 (86.6%). Notably, the 8B WorkflowLlama outperforms the 70B Llama-3.1 variant by over 10 CodeBLEU points, demonstrating that task-specific fine-tuning on WorkflowBench is more effective than simply scaling model size for workflow orchestration.

## Relation to Prior Work

This paper extends the Agentic Process Automation (APA) paradigm introduced by Ye et al. (2023) and the broader tool-learning literature (ToolLLM, ToolQA) by shifting focus from sequential API selection and parameter filling to complex workflow orchestration involving nested branches, loops, and multi-step control flow. It repurposes Apple Shortcuts data previously used by ShortcutsBench (Shen et al., 2024) for tool-utilization evaluation, instead transcribing it into Python-style code and augmenting it with hierarchical thought annotations to create the first dataset explicitly designed for workflow generation. The three-phase data pipeline (collection → query expansion → annotator-based workflow generation) draws on synthetic data generation techniques from the broader LLM fine-tuning literature but applies them to a domain where prior datasets were either absent or limited to simple sequential actions.

## Why It Matters / Open Questions

WorkflowBench (106K+ samples, 1,503 APIs, 83 apps) provides the missing data infrastructure for the RPA-to-APA transition, and the demonstration that an 8B fine-tuned model can substantially outperform GPT-4o on workflow orchestration suggests that domain-specific data curation can be more effective than raw model scale for structured code generation tasks. Key limitations include the exclusive reliance on Apple Shortcuts APIs (limiting domain generalizability) and the absence of execution-based evaluation, which leaves open whether generated workflows actually run correctly in production. Future work should address cross-platform API coverage, execution-verified evaluation, and the redundancy issue observed in generated workflows.
