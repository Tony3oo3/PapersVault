## Problem

Existing reward model benchmarks like RewardBench construct test pairs by generating the chosen response with a stronger LM and the rejected response with a weaker LM, making it impossible to assess a reward model's sensitivity to subtle content differences or its robustness against style biases. This design yields low correlation with downstream policy model performance, leaving practitioners without a reliable proxy for selecting reward models for alignment.
![Teaser figure](../imgs/ICLR20251591/cropped_page3_idx0.webp)

## Input / Output

Each test tuple consists of a prompt x and two responses (chosen y_c and rejected y_r) generated by the same LM (gpt-4o), with each response available in three style variants: concise (y^∅), detailed plain-text (y^L), and detailed with Markdown formatting (y^{L,M}). The reward model outputs a scalar reward for each response, and correctness is determined by whether the chosen response receives a higher reward than the rejected one. Results are organized into a 3×3 Style-Substance Evaluation Matrix (rows = chosen style, columns = rejected style), from which three accuracy metrics are derived: Easy (lower triangle, style cues favor the correct answer), Normal (diagonal, matched styles), and Hard (upper triangle, style cues favor the incorrect answer).

## Method

RM-BENCH constructs test pairs where both chosen and rejected responses come from the same powerful LM (gpt-4o), ensuring that differences are purely in content rather than generation quality. For the Chat domain, subtle factual errors are injected into correct responses via the Many-Shot Jailbreak technique (23 in-context examples); for Code and Math, multiple samples are drawn at temperature 1.0 and one correct/one incorrect response is selected via automatic verification; for Safety, an over-cautious system prompt generates refusal responses for benign prompts, while an uncensored model (Llama-3.1-8B-Lexi-Uncensored-V2) generates harmful responses for genuinely dangerous prompts. Style-controlled variants are created by prompting gpt-4o to strip Markdown or summarize content, producing the three style levels. The key evaluation mechanism is the 3×3 matrix that systematically crosses all style combinations, isolating substance from style and yielding the Hard accuracy metric that directly measures a reward model's ability to prefer correct content over favorable formatting. The benchmark's validity is established by showing that reward model Hard Accuracy on RM-BENCH correlates with policy model style-control scores (Arena-Hard-Auto) and downstream task performance (GSM8k, HumanEval+, XSTest) after PPO fine-tuning, achieving a Pearson r=0.55 versus r=0.21 for RewardBench.

## Results

On RM-BENCH, the top-performing reward model Skywork-Reward-Llama-3.1-8B achieves 70.1% Average Accuracy but only 46.6% Hard Accuracy (below the 50% random-guessing baseline), revealing severe style bias. The largest model, Nemotron-340B-Reward, reaches 69.5% Avg with the best Hard Accuracy of 56.1% among top models. Math and Code are the hardest domains, with Skywork achieving only 28.4% and 30.7% Hard Accuracy respectively. RM-BENCH shows a Pearson correlation of r=0.55 (p=0.07) with policy model performance, substantially outperforming RewardBench's r=0.21 (p=0.51).

## Baselines & Comparisons

RM-BENCH directly compares against RewardBench (Lambert et al., 2024) on correlation with policy model performance: RM-BENCH achieves Pearson r=0.55 (p=0.07) versus RewardBench's r=0.21 (p=0.51), demonstrating substantially stronger predictive power for selecting reward models. Among the ~40 evaluated reward models, sequence classifiers (Skywork 70.1%, Nemotron-340B 69.5%) dominate the top of the leaderboard, but all suffer severe style bias with Hard Accuracy below or near 50%. DPO models (e.g., tulu-2-dpo-13b at 63.8%) trail sequence classifiers in absolute accuracy but show more balanced Easy/Hard profiles; in controlled ablations (Table 4), DPO with a reference model outperforms its sequence-classifier counterpart by 2–8 points across all four preference datasets. The multi-objective Nemotron-340B-Reward achieves the best Hard Accuracy (56.1%) but still fails to disentangle correctness from verbosity in Math and Code domains, where chosen and rejected responses heavily overlap in the correctness-verbosity scatter plot. The GRM family (Yang et al., 2024) occupies the 67–68% Avg range, confirming that regularization strategies help modestly but do not resolve the fundamental style-bias problem.

## Relation to Prior Work

This paper extends RewardBench (Lambert et al., 2024), the first systematic reward model benchmark, by fundamentally changing how chosen/rejected pairs are constructed: instead of using a stronger LM for the chosen response and a weaker LM for the rejected response (which conflates content quality with model identity), RM-BENCH generates both responses from the same LM (gpt-4o) and injects subtle factual errors via many-shot jailbreaking (Anil et al., 2024). It also adopts the style-control design from Chatbot Arena (Chiang et al., 2024) to create length- and markdown-controlled variants, enabling a 3×3 Style-Substance Evaluation Matrix that separates substance sensitivity from style bias — a dimension entirely absent from prior reward model benchmarks.

## Why It Matters / Open Questions

The finding that even the strongest reward models (Skywork, Nemotron-340B) fall below random-guessing accuracy (46.6%) when style conflicts with substance reveals a fundamental blind spot in current alignment pipelines: reward models may be selecting responses based on formatting rather than correctness, potentially degrading policy model performance in math and code. The demonstrated correlation with policy model performance (Pearson r=0.55 vs. RewardBench's r=0.21) makes RM-BENCH a practically useful selection tool. Key limitations include coverage of only two style dimensions (length, markdown), heavy reliance on gpt-4o for data construction, and correlation validated only under controlled PPO settings with a single base model — real-world post-training pipelines with mixed algorithms (PPO+DPO) may exhibit different correlations.
