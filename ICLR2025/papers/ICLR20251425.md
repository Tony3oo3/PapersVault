## Problem

The previous state-of-the-art for single point supervised oriented object detection, PointOBB, suffers from a slow pseudo-label generation process (7–8× longer than detector training), high GPU memory consumption due to multiple view transformations, and out-of-memory failures in dense object scenarios. This paper addresses these practical bottlenecks while also improving detection accuracy, particularly for small and densely packed objects.
![Teaser figure](../imgs/ICLR20251425/cropped_page1_idx0.webp)

## Input / Output

The method takes RGB images (ranging from 800×800 to 4000×4000 pixels) with a single point annotation and class label per object as the sole supervision signal. It first produces a Class Probability Map (CPM) of size (N_class, H₀, W₀) via a ResNet-50 + FPN backbone, then converts the CPM into pseudo oriented bounding boxes (center, width, height, angle) that are used to train a standard rotated detector (Rotated FCOS, Oriented R-CNN, or ReDet). At inference, the trained detector outputs oriented bounding boxes directly from the image without any point input.

## Method

PointOBB-v2 replaces PointOBB's teacher-student architecture with a single-branch pipeline that generates a Class Probability Map using a non-uniform positive/negative sampling strategy: positive samples are points within a fixed radius of each annotation, while negative samples are defined by distance-based circles around each object plus a midpoint-negative region between same-class neighbors to sharpen boundaries. Object orientation and boundaries are then estimated by applying weighted PCA on a 7×7 grid of CPM probabilities centered at each point, where the probability values serve as weights in the covariance matrix—eliminating the variance and cost of repeated probabilistic sampling. A Vector Constraint Suppression module resolves boundary ambiguity in dense scenes by constraining the boundary along the primary or secondary PCA direction to lie closer to the object than to its nearest same-class neighbor. This design achieves 15.58× faster pseudo-label generation (1.43 h vs. 22.28 h) and ~8 GB peak memory without restricting RoI proposals, while improving mAP by 11.60%/25.15%/21.19% on DOTA-v1.0/v1.5/v2.0 over PointOBB.

## Results

On DOTA-v1.0, PointOBB-v2 achieves mAP50 of 41.68% (Rotated FCOS), 41.64% (Oriented R-CNN), and 44.85% (ReDet), surpassing the previous SOTA PointOBB by 11.60%, 8.33%, and 10.90% respectively. On the more challenging DOTA-v1.5 and DOTA-v2.0 (denser, smaller objects), ReDet-based PointOBB-v2 reaches 36.39% and 27.22% mAP50, gains of 25.15% and 21.19% over PointOBB. Pseudo-label generation is 15.58× faster (1.43 h vs. 22.28 h) and memory usage drops to ~8 GB (vs. >24 GB for PointOBB, which requires RoI limiting on dense scenes).

## Baselines & Comparisons

Against the direct predecessor PointOBB (modular WOOD, no priors), PointOBB-v2 wins decisively on every dataset and detector: +11.60 mAP50 on DOTA-v1.0, +25.15 on DOTA-v1.5, and +21.19 on DOTA-v2.0 (ReDet), with the gap widening as object density increases. Versus Point2RBox-SK* (which uses manual sketch priors per category), PointOBB-v2 still leads by 4.58 / 5.88 / 3.79 mAP50 on DOTA-v1.0/v1.5/v2.0, showing that prior-free modular generation can outperform prior-based end-to-end methods. Against the prior-free Point2RBox-RC, the gain is +10.78 mAP50 on DOTA-v1.0 and +11.78 on DOTA-v1.5. Cascade baselines (P2BNet+H2RBox-v2 at 21.87, Point2Mask-RBox at 9.72 on DOTA-v1.0) are far behind, confirming the advantage of direct point-to-OBB generation. On the retail dataset SKU110K-R, PointOBB-v2 (ORCNN) reaches 62.76 mAP50 versus only 3.41 for Point2RBox-RC, and on SAR imagery (RSAR) it improves over PointOBB by +10.31 mAP50 (ORCNN).

## Relation to Prior Work

This paper directly extends PointOBB (Luo et al., CVPR 2024), the prior state-of-the-art in the modular weakly-supervised oriented object detection (WOOD) paradigm, by replacing its teacher-student architecture with a single-branch Class Probability Map (CPM) trained via non-uniform positive/negative sampling. The key conceptual departure is using PCA on a weighted 7×7 grid around each point annotation to estimate orientation and boundaries, eliminating the multi-view consistency constraints and multiple instance learning that made PointOBB slow and memory-intensive. It also distinguishes itself from SAM-based methods (P2RBox, PMHO) and prior-based end-to-end methods (Point2RBox) by remaining prior-free and modular, decoupling pseudo-label generation from the downstream detector.

## Why It Matters / Open Questions

The 15.58× speedup (22.28h → 1.43h) and reduction to ~8GB memory make single-point supervised oriented detection practically deployable on standard GPUs, removing the primary barrier to real-world adoption. The large accuracy gains on dense datasets (25.15% on DOTA-v1.5, 21.19% on DOTA-v2.0) demonstrate that the vector constraint separation mechanism is critical for small-object scenarios where prior methods collapse. Limitations include the requirement of at least two point annotations per image (degrading on extremely sparse scenes) and dataset-specific hyperparameters, leaving open whether the CPM+PCA formulation generalizes cleanly to other domains or annotation regimes without manual tuning.
