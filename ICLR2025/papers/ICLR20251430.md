## Problem

While LLMs have been extensively studied for general code generation and API intent detection, generating specific API call code snippets across diverse programming languages remains underexplored. Prior instruction datasets for API tasks were either single-language (e.g., Gorilla, Python-only) or too small to enable systematic study of cross-language transfer and data scaling effects, leaving open whether and how much multi-language data is needed for robust API call generation.
![Teaser figure](../imgs/ICLR20251430/cropped_page3_idx0.webp)

## Input / Output

Each instance pairs a natural-language instruction (describing a coding task and naming the target API) with an HTTP request code snippet in one of 10 programming languages (cURL, libcurl, Java, Node.js, Python, Go, Ruby, PHP, Swift, JavaScript). At inference time, the model optionally receives 3 retrieved or random API call examples as in-context demonstrations. Evaluation uses SequenceMatcher similarity (threshold 0.9) on both the endpoint path and the full API call, treating whitespace, formatting, and variable naming as insignificant elements.

## Method

API Pack is constructed through a four-stage pipeline: (1) pre-processing OAS files from four public API hubs (RapidAPI, APIGurus, SwaggerHub, IBM API Hub) to extract endpoint metadata; (2) generating API calls in 10 languages via the openapi-snippet library; (3) creating instruction examples from templates, refining them with human annotation (APIGurus, IBM) or Mistral-7B (SwaggerHub, RapidAPI), then generating five instruction candidates per instance via in-context prompting; and (4) validating API calls with regex checks and selecting the best instruction via back-translation log-probability scoring. The empirical study fine-tunes CodeLlama-13B, Mistral-7B, and Llama-2-13B on 20k–1M instances using 0-shot and 3-shot templates, evaluates retrieval augmentation with bge-large-en-v1.5 embeddings and bge-reranker-large, and tests cross-language generalization by mixing 100k cURL instances with 1k instances from nine other languages. Key findings show that 20k Python instances suffice for CodeLlama-13B to outperform GPT-4 by 5.2 points on unseen APIs, that a large single-language dataset plus small multi-language supplements enables cross-language transfer, and that scaling to 1M instances yields near-linear gains in 0-shot accuracy with diminishing returns at Level 3.

## Results

Fine-tuning CodeLlama-13B on 20,000 Python instances from API Pack achieves 49.5% API call accuracy on Level 3 (unseen APIs) with 3-shot retrieved prompting, outperforming GPT-4 (44.3%) by 5.2 points and GPT-3.5 (39.5%) by 10 points. On Level 1 (seen APIs/endpoints), the same model reaches 63.5% endpoint and 55.5% API call accuracy. Scaling fine-tuning data from 0 to 1 million instances yields roughly linear gains in 0-shot performance, though Level 3 accuracy plateaus near 1M instances, indicating diminishing returns for the hardest generalization task.

## Baselines & Comparisons

The primary comparison is against GPT-3.5 and GPT-4 on Level 3 (entirely unseen APIs), where fine-tuned CodeLlama-13B (49.5% API call accuracy) surpasses GPT-4 (44.3%) by 5.2 points and GPT-3.5 (39.5%) by 10 points in the 3-shot retrieved setting. Among open-source models, CodeLlama-13B also outperforms Mistral-7B (42.5%) and CodeLlama-7B (49.1%) on Level 3, with the 13B model's advantage most pronounced under 3-shot retrieved prompting. In the ToolBench comparison (Table 5), training on ToolBench (single-source, RapidAPI only) yields 38.1% Level 3 API call accuracy in 3-shot, versus 49.1% for API Pack (multi-source), confirming the benefit of aggregating data from four API hubs. The non-filtered API Pack variant (45% unfiltered instructions) achieves 49.5% Level 3 API call accuracy, nearly matching the fully filtered version (49.1%), suggesting the filtering pipeline's impact is modest. For cross-language generalization, the MIXTURE MODEL (100k cURL + 1k per language) matches EXPERT MODELS (100k per language) across all ten languages in 3-shot testing, demonstrating that a single dominant language plus small amounts of others suffices.

## Relation to Prior Work

This paper carves new ground at the intersection of API intent detection (Gorilla, ToolBench, ToolLLM) and code generation, arguing that API call code generation has been under-explored relative to intent detection. It departs from prior datasets in two structural ways: multi-programming-language coverage (10 languages vs. Python-only or 2-language sets) and scale (1.1M instances vs. thousands), enabling the first systematic study of cross-language skill transfer in API generation. Methodologically, it combines a hybrid pipeline—real HTTP request snippets extracted from OpenAPI Specification files paired with LLM-generated and LLM-filtered instructions—rather than relying purely on self-instruct or human annotation, and it leverages the openapi-snippet library to ensure syntactically valid multi-language code.

## Why It Matters / Open Questions

API Pack provides the first large-scale, multi-language open-source resource for training and evaluating LLMs on API call generation, and the cross-language transfer finding (100k cURL + 1k per other language ≈ per-language expert models) offers a practical recipe for multi-language deployment without per-language data at scale. Key limitations temper the impact: evaluation relies on a similarity-ratio heuristic rather than execution-based metrics (pass@k, hallucination rate), the dataset excludes multi-API call scenarios, and language coverage is bounded by the openapi-snippet library. Open questions include whether privacy-preserving execution evaluation is feasible, how the approach extends to multi-API orchestration, and whether the observed diminishing returns at Level 3 (unseen APIs) reflect a fundamental ceiling or simply insufficient data diversity.
