## Problem

Production LLM serving systems are distributed across multiple GPUs, but existing prefix-caching optimizations (SGLang, vLLM) are confined to single-GPU scope. Naive round-robin load balancing in distributed settings scatters requests with shared prefixes across GPUs, causing redundant KV computation, while always routing shared-prefix requests to one GPU creates severe load imbalance. The paper identifies that real workloads have prompts 37×–2494× longer than outputs with 85%–97% token sharing, making this a critical unsolved problem for distributed serving.

## Input / Output

The system ingests tokenized LLM text prompts that contain long shared prefixes (system prompts, tool instructions, document/video contexts) and produces short generated responses. Prompts are matched against a global radix tree of cached prefixes before scheduling; the key structural property is that prompts are orders of magnitude longer than outputs (e.g., 2494× for video QA), so prefill dominates total latency. The system operates on a distributed GPU cluster (tested on 2–8 GPUs) and must handle heterogeneous request arrival patterns including Poisson and real Azure trace inter-arrival times.

## Method

Preble introduces a two-level hierarchical scheduler centered on the E2 (Exploitation + Exploration) algorithm. The global scheduler matches each incoming prompt against a global radix tree: if the cached prefix exceeds the remaining tokens, it exploits by routing to the GPU holding the longest-matched prefix; otherwise it explores by selecting the GPU with the lowest prompt-aware load cost, which sums three components—recent window computation load, weighted KV eviction cost, and new-request prefill cost—all estimated via token-count regression. The local scheduler performs iteration-level batching with a priority-based wait queue that groups requests by prefix cache hit ratio to balance fairness and reuse. Additional mechanisms include post-assignment load rebalancing (shifting requests when GPU load ratio exceeds a threshold), automatic prefix replication (autoscaling) under sustained load, and prefill-decoding balancing by treating fully-cached prompts as decoding-phase units to mix with uncached prefill-heavy requests on the same GPU.

## Results

Preble achieves 1.5×–14.5× lower average request latency and 2×–10× lower p99 latency compared to data-parallel SGLang across five workloads (Toolbench, ALFWorld, APPS, NExT-QA, LooGLE) on both Mistral 7B (2–4 A6000 GPUs) and Llama-3 70B (8 H100 GPUs). The largest gains appear on workloads with very high prompt-to-output ratios (Video QA up to ~2500×, LooGLE up to ~1467×), while the Programming workload (longest decoding) shows the smallest improvement at 1.56×–1.8× average and 3×–4× p99. The global scheduler sustains 245–2931 requests/second and can support 70–391 concurrent A100 GPUs.

## Baselines & Comparisons

Preble is compared against three baselines. Against data-parallel SGLang (round-robin load balancing with per-instance prefix caching), Preble wins decisively on both average and p99 latency across all five workloads and both model/GPU configurations, with the gap widening at higher RPS. Against vLLM (with its beta prefix-caching feature), Preble also wins but with smaller relative gains, attributed to vLLM's less mature prefix sharing, lack of FlashInfer kernels, and absence of chunked-prefill-with-caching support. Against MemServe (a concurrent distributed system with prefix awareness), Preble achieves significantly lower average latency on both Tool Use and Video QA workloads, because MemServe routes requests purely by longest-prefix-match regardless of existing GPU load, leading to overexploitation and load imbalance. Preble's E2 algorithm avoids this by balancing exploitation (cache reuse) with exploration (load distribution) and factoring in potential KV eviction costs.

## Relation to Prior Work

This paper extends single-GPU prefix caching (SGLang, vLLM) to the distributed setting, where production LLM serving necessarily spans multiple GPUs. It builds on Sarathi's chunked prefill for the local scheduler and on the KV-cache reuse idea from SGLang, but introduces a fundamentally new distributed scheduling layer (E2) that co-optimizes prefix exploitation and load exploration. Concurrent works like MemServe and Mooncake also add cluster-level prefix awareness, but Preble differentiates by incorporating eviction cost into load estimation and by providing fairness guarantees via priority-based wait-queue scheduling.

## Why It Matters / Open Questions

As LLM prompts grow longer and more shared (tool instructions, document QA, multi-step agents), the gap between single-GPU prefix caching and the distributed reality of production serving becomes a critical bottleneck; Preble's 1.5×–14.5× latency improvement demonstrates that prompt-aware routing is not optional but essential for efficient multi-GPU deployment. Open questions include scalability beyond ~400 GPUs, handling highly dynamic or adversarial prompt-sharing patterns, and integration with model-parallelism-aware scheduling. The paper also notes that for workloads without shared prompts, Preble offers no benefit over existing SOTA, limiting its applicability to prompt-heavy use cases.
