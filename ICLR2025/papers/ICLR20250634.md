## Problem

Creating realistic, interactable articulated 3D objects for simulation requires extensive human labor and expertise, resulting in a critical scarcity: while open datasets contain over 10 million static 3D objects, only ~2,300 articulated objects exist. Prior automatic articulation methods (URDFormer, Real2Code) achieve just 8.7–12.2% success rates, are restricted to a narrow set of object categories and joint types, and rely on impoverished inputs like bounding boxes or static images that cannot resolve articulation ambiguities.

## Input / Output

The system accepts text prompts (e.g., 'a kitchen island with a sliding drawer'), single RGB images, or short video clips showing an object's motion, and produces a URDF file representing the articulated object's kinematic tree (links and joints). The intermediate representation is high-level Python code generated by the VLM actor through a custom API, which is then compiled into URDF and rendered in Sapien for evaluation. For video inputs, motion cues are extracted via CoTracker to disambiguate joint types (e.g., sliding vs. tipping for a window), and the first frame is automatically used as the image input for link placement.

## Method

ARTICULATE-ANYTHING reframes articulation as program synthesis: a VLM actor (Gemini Flash-1.5 with ~20 in-context examples) generates compact Python code via a custom API that compiles to URDF, avoiding the verbosity and in-place math challenges of direct URDF/XML generation. The pipeline decomposes into three sequential phases—Mesh Retrieval (CLIP-based matching against PartNet-Mobility with a divide-and-conquer tournament selector), Link Placement (spatial arrangement with physics-engine collision checks), and Joint Prediction (kinematic type, axis, origin, and limits)—each handled by specialized VLM agents. A vision-language critic renders the predicted model in simulation, compares it against the input (image or video), assigns a realism rating (0–10), and pinpoints specific code errors, enabling iterative self-correction until the rating exceeds a threshold of 5. This actor-critic loop, combined with grounded visual inputs, allows the system to resolve ambiguities that static inputs cannot, achieving 75% joint prediction success on PartNet-Mobility versus 8.7–12.2% for prior work.

## Results

On the full PartNet-Mobility dataset (~2.3K objects, ~1.9K revolute and ~7.6K prismatic joints), ARTICULATE-ANYTHING achieves a 75% joint prediction success rate, substantially outperforming prior methods that achieve only 8.7–12.2%. In terms of raw joint errors (Table 1), ARTICULATE-ANYTHING reduces the joint type error to 2.1% (vs. 46–56% for baselines), axis error to 0.141 rad (vs. 0.26–1.01 rad), and origin error to 0.200 m (vs. 0.29–0.58 m). The system also saves an average of 40.58 minutes of human annotation labor per task in the robotics application.

## Baselines & Comparisons

ARTICULATE-ANYTHING substantially outperforms both baselines across all joint error metrics. Compared to URDFormer (Chen et al., 2024), which directly predicts discretized part positions from bounding boxes, ARTICULATE-ANYTHING reduces joint type error from 46–56% to 2.1%, axis error from 0.26–0.37 rad to 0.14 rad, and origin error from 0.55–0.58 m to 0.20 m. Compared to Real2Code (Mandi et al., 2024), which operates on oriented bounding box coordinate inputs, ARTICULATE-ANYTHING reduces joint type error from 53.7% to 2.1% and axis error from 1.01 rad to 0.14 rad, though Real2Code has a slightly lower origin error (0.29 m vs. 0.20 m). A critical practical advantage is output validity: 59.1% of URDFormer's and 17.5% of Real2Code's outputs are structurally invalid (cyclic structures, repeated links, or syntax errors), whereas ARTICULATE-ANYTHING's code-based approach avoids these failures. The overall joint prediction success rate jumps from 8.7–12.2% (baselines) to 75% (ARTICULATE-ANYTHING), and the advantage is consistent across both in-distribution and out-of-distribution object categories.

## Relation to Prior Work

This paper departs from the prior automatic articulation line (URDFormer, Real2Code) by replacing trained neural predictors with an agentic VLM actor-critic system that performs program synthesis in Python, compilable to URDF. Rather than learning a mapping from bounding boxes or oriented bounding boxes to joint parameters, ARTICULATE-ANYTHING repurposes off-the-shelf vision-language models (Gemini Flash-1.5) with few-shot in-context examples to iteratively propose and self-correct articulation code. The mesh retrieval mechanism borrows from the PartNet-Mobility asset library and CLIP-based similarity search, while the iterative refinement loop draws on the broader actor-critic paradigm in LLM agents, applied here to a 3D kinematic domain.

## Why It Matters / Open Questions

The 8.7–12.2% → 75% success-rate jump directly addresses a critical bottleneck in robot learning: the scarcity of articulated 3D assets (only ~2,300 in open datasets vs. 10M+ static objects). The demonstrated sim-to-real transfer (training RL policies on auto-generated assets and deploying on a Franka arm) validates the practical utility beyond benchmark metrics. Key limitations include reliance on mesh retrieval rather than generation (constraining asset diversity), dependence on a proprietary VLM, and evaluation on a single dataset (~2.3K objects). Open questions include whether the actor-critic paradigm generalizes to more complex multi-body systems, whether integrating upstream mesh generation models (preliminary results in Appendix A.8) closes the quality gap, and whether the approach scales to the long tail of object categories in the wild.
