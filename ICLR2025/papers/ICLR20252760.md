## Problem

Existing math-related code used in continued pretraining (typically sourced from GitHub) is designed for engineering, ML, or signal processing rather than mathematical reasoning, and critically lacks accompanying natural language explanations or context. This makes it difficult for LLMs to understand the underlying reasoning process, and the code is generally unverified. The paper asks whether generating code that is explicitly paired with extracted reasoning steps and verified by execution can more effectively enhance mathematical reasoning during continued pretraining.

## Input / Output

The pipeline consumes heterogeneous math-related sources—filtered web pages (OpenWebMath, Common Crawl via Matrix), synthetic math data, Python/Jupyter code importing packages like sympy and scipy (from StarCoderData), and 8K math textbook PDFs converted to markdown via Nougat—along with a base LLM (Llama-3-8B, DeepSeekMath-7B, Mistral-7B, or Code-Llama-7B). Llama-3.1-70B-Instruct serves as the translation engine, producing structured outputs containing conditions, LaTeX expressions, expected results, and Python code snippets. The final output is the 19.2B-token MathCode-Pile corpus and the MathCoder2 family of continued-pretrained models, where each code snippet is concatenated with its corresponding natural language reasoning step in a fixed format.

## Method

The method has two stages. First, a 16.5B-token basic corpus is curated by applying a two-round fastText classifier (trained on Mixtral-8x7B-Instruct-annotated samples) to filter math-relevant documents from OpenWebMath and Common Crawl, supplemented with synthetic data, math-package code, and textbooks. Second, and more novelly, Llama-3.1-70B-Instruct is prompted to extract LaTeX expressions along with their preconditions and expected results from the basic corpus, then to translate each extracted reasoning step into a Python code snippet. Generated snippets are executed and only retained if they run without errors and produce outputs matching the expected results, yielding 2.7B tokens of verified code-reasoning pairs. The key design choice—concatenating the natural language reasoning step directly with its corresponding code snippet (rather than separating them or using code alone)—is validated by ablation and shown to outperform alternatives. This paired format is argued to facilitate both comprehension of math texts during pretraining and downstream fine-tuning for Tool-Integrated Reasoning.

## Results

MathCoder2-Llama-3-8B achieves 4-shot accuracies of 38.4% on MATH, 69.9% on GSM8K, 84.4% on SAT, 18.0% on OCW, and 46.5% on MMLU-Math, improving over the Llama-3-8B baseline by +17.0, +15.1, +28.1, +7.7, and +3.7 points respectively. MathCoder2-DeepSeekMath-7B further improves upon DeepSeekMath-7B on all five benchmarks (e.g., 38.6% vs 36.2% on MATH, 90.6% vs 84.4% on SAT). The model-translated mathematical code constitutes only 14.1% of the 19.2B-token MathCode-Pile corpus yet accounts for 21.8%–66.2% of the total accuracy improvement across the five benchmarks.

## Baselines & Comparisons

MathCoder2 consistently outperforms its respective base models across all five benchmarks: MathCoder2-Llama-3-8B surpasses Llama-3-8B by up to +28.1 points (SAT), MathCoder2-Mistral-7B beats Mistral-7B by up to +23.6 points (MATH), and MathCoder2-Code-Llama-7B improves over Code-Llama-7B by up to +46.9 points (SAT). Against other open-source math models, MathCoder2-DeepSeekMath-7B (38.6% MATH, 90.6% SAT) edges out DeepSeekMath-7B (36.2%, 84.4%) on all five benchmarks, and MathCoder2-Llama-3-8B (38.4% MATH) substantially outperforms Llemma-7B (18.0% MATH) and InternLM2-Math-Base-7B (21.5% MATH). However, MathCoder2 models trail Qwen2-Math-7B (50.4% MATH) and Qwen2.5-Math-7B (55.4% MATH) by 12–17 points on MATH, which the authors attribute to Qwen's 700B-token dataset and greater computational resources. On the dataset-level comparison (Table 6), MathCode-Pile outperforms OpenWebMath, Proof-Pile-2, and MathPile when training DeepSeekCoder-1.3B, and also surpasses the DeepSeekMath Corpus result (13.6% MATH) despite using fewer training tokens (~60B vs 150B). In post-training (Table 3), MathCoder2-Llama-3-Instruct-TIR reaches 69.7% MATH and 85.8% GSM8K, outperforming NuminaMath-7B-TIR (68.1%, 84.6%) and ToRA-Code (44.6%, 72.6%), while still trailing Qwen2.5-Math-Instruct (83.6%, 95.2%).

## Relation to Prior Work

This paper extends the continued mathematical pretraining paradigm established by DeepSeekMath and Llemma, both of which incorporate math-related code from general-purpose repositories (GitHub, StarCoderData) into pretraining corpora. The key departure is that prior code is designed for engineering, ML, or signal processing and lacks accompanying natural language context, whereas this work uses Llama-3.1-70B-Instruct to extract LaTeX expressions with their conditions and results from math texts, then translates each reasoning step into a verified Python snippet. This creates a new data type—paired reasoning steps and code—that bridges the gap between the TIR fine-tuning paradigm (ToRA, MathCoder) and the pretraining stage, where no prior work had introduced such paired data.

## Why It Matters / Open Questions

The full open-sourcing of the data processing pipeline and training code addresses a significant reproducibility gap in the mathematical pretraining literature, where most strong models (Qwen2.5-Math, DeepSeekMath, InternLM-Math) release only weights. The 19.2B-token MathCode-Pile dataset and the finding that a 14% code component drives a disproportionate share of the accuracy gain provide a concrete, reusable recipe for practitioners. However, the acknowledged performance gap with Qwen2.5-Math (700B tokens) and the restriction to 7–8B English-only models leave open whether the approach scales to larger models, multilingual settings, or broader STEM domains, and whether the benefits persist under more aggressive post-training (RL, DPO).
