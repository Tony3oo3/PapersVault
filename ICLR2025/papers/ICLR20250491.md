## Problem

Code-LM pre-training has remained largely stagnant at vanilla autoregressive objectives, failing to efficiently disentangle syntactic and semantic understanding of code, while simultaneously facing a severe data bottleneck with publicly available code corpora under a trillion tokens. The paper asks whether grounding Code-LMs in obfuscated code during pre-training can improve both channels of code understanding and serve as a data-augmentation strategy to bypass the code data-wall.
![Teaser figure](../imgs/ICLR20250491/cropped_page4_idx0.webp)

## Input / Output

During pre-training, the model consumes a 272B-token corpus mixing standard source code, obfuscated code (identifiers replaced with VAR_n, FUNC_n, CLASS_n, IMPORT_n tokens), and bidirectional source↔obfuscated translation pairs separated by sentinel tokens (<src_to_obf>, <obf_to_src>). At inference, the model takes code prompts, code change diffs, or natural language instructions and produces code completions, defect classification labels, or commit summaries across seven languages (C, C++, Go, Java, Python, Rust, TypeScript).

## Method

The paper introduces ObscuraX, a ~55M-pair multilingual dataset of source-to-obfuscated code created by a custom Tree-sitter-based obfuscator that stochastically replaces identifiers (up to 90% per category, capped at 150) and, for ~25% of samples, also mangles import statements into single IMPORT_n tokens. ObscuraCoder models (Llama architecture, 255M–2.8B params) are pre-trained from scratch on a 272B-token corpus where the second phase mixes 64B source code tokens, 30B obfuscated code tokens, 58B bidirectional translation pairs, and 30B code-adjacent text. Unlike DOBF, which only backpropagates gradients on identifier maps and requires encoder-decoder initialization, ObscuraCoder trains a decoder-only model on the full structure of both source and obfuscated code via standard autoregressive loss, requiring no architectural modifications at inference. The key insight is that forcing the model to reconstruct meaningful identifiers from purely syntactic structure (de-obfuscation) while simultaneously learning the obfuscated code's own patterns (obfuscation LM) forces it to internalize algorithmic semantics independent of surface-form naming.

## Results

ObscuraCoder consistently outperforms its CausalLM counterpart across all model sizes and tasks. At 2.8B parameters, ObscuraCoder achieves 65.42 F1 on CodeXGLUE defect detection (+1.06 over CausalLM), 20.11 ReCode Function pass@1 (+5.38), and 14.77 BigCodeBench Pass@1 (+3.98) with a striking +16.83 gain on Pass@25 (48.78 vs 31.95). On multilingual code completion (Multipl-E), ObscuraCoder 2.8B reaches 23.55 Pass@1 (+6.85) and 61.93 Pass@100 (+14.39), while on CommitChronicle it attains 14.15 ROUGE-2 (+1.26). Gains over the autoregressive baseline widen monotonically with model size, with the largest relative improvements on zero-shot generation tasks.

## Baselines & Comparisons

Against the direct CausalLM baseline (same architecture, same 272B tokens), ObscuraCoder wins on every metric at every model size, with the largest gaps on ReCode Function (+5.38 at 2.8B) and BigCodeBench Pass@25 (+16.83 at 2.8B). Versus DOBF (Lachaux et al., 2021), ObscuraCoder dominates across all tasks; at 2.8B the gap reaches +3.42 on ReCode Function, +5.13 on BigCodeBench Pass@25, and +10.66 on Multipl-E Pass@100, and the gap widens with scale. Against frontier models, ObscuraCoder 2.8B (272B tokens) beats StarCoderBase 3B (1.0T tokens) on BigCodeBench Pass@1 (14.77 vs 8.26) and Pass@25 (48.78 vs 37.74), and edges out CodeGemma 2B (3.5T tokens) on Pass@25 (48.78 vs 43.66) and Multipl-E Pass@1 (23.55 vs 22.71). However, ObscuraCoder 2.8B trails DeepSeekCoder 1.3B (2.0T tokens) on ReCode Function (20.11 vs 25.27) and Multipl-E Pass@1 (23.55 vs 26.81), and falls short of Phi-2 (1.4T tokens) on BigCodeBench Pass@1 (14.77 vs 21.83) and Pass@25 (48.78 vs 53.78), indicating that the obfuscation objective yields the strongest relative gains on tasks emphasizing syntactic-semantic robustness and diverse generation rather than peak single-sample accuracy.

## Relation to Prior Work

This paper departs from DOBF (Lachaux et al., 2021), which pioneered de-obfuscation as a pre-training objective but only for encoder-decoder models and trained solely on identifier maps without backpropagating through the source or obfuscated code. ObscuraCoder instead uses a bidirectional source↔obfuscated translation objective combined with language modeling on both forms, applied to decoder-only Llama-architecture models trained from scratch. It also extends the broader line of work on disentangling code syntax and semantics (contrastive learning, graph-based architectures, compiler IRs) by showing that a simple stochastic identifier/import substitution pipeline, grounded via Tree-sitter, can serve as a scalable pre-training signal without requiring specialized architectures or external toolchain artifacts.

## Why It Matters / Open Questions

The paper offers a concrete, scalable recipe for addressing the code data-wall: stochastic obfuscation generates diverse semantic-preserving transformations that augment pre-training corpora without requiring new source code. The consistent gains across syntactic, semantic, and API-usage tasks—and the absence of any regression on code completion—suggest obfuscation grounding could be a low-cost addition to frontier Code-LM pre-training mixes. Key open questions include whether the benefits persist at 7B+ parameter scales, whether the import-obfuscation trick generalizes beyond the tested languages, and whether the early-grounding requirement (post-hoc continued pre-training fails) constrains adoption for already-trained models.
