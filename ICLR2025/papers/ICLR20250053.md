## Problem

Transformer attention's quadratic time and space complexity makes long-context LLM serving (beyond ~32k tokens) impractical on commodity GPUs. Existing sub-quadratic alternatives—linear attention, kernel methods, and static sparse patterns—either require expensive retraining from scratch, degrade generation quality significantly, or are too complex to integrate into production serving frameworks. The paper asks whether a training-free, drop-in attention replacement can achieve sub-quadratic complexity while preserving the quality of pretrained models.

## Input / Output

The method is a drop-in replacement for the attention layer in any pretrained Transformer: it consumes the same query, key, and value tensors (Q, K, V ∈ R^{T×d}) and produces the same attention output O ∈ R^{T×d}, but internally generates a block-sparse binary mask selecting only k key tokens per query. During decoding, the sparse mask is cached and refreshed every r_m steps to amortize the top-k estimation cost. The KV cache offloading variant stores only O(log T) hot tokens in GPU HBM (via a token bank plus page table) while keeping the full KV cache in host DRAM, extending serviceable context from 16k to 64k tokens on a single RTX 4090.

## Method

HiP exploits an empirically observed 'attention locality' property—neighboring tokens in pretrained LLMs have similar attention scores—to estimate the top-k key tokens via a greedy binary tree search: the key sequence is divided into k chunks, each chunk's center token serves as a representative, the top-k chunks by representative score are retained, and the process recurses until each branch is a single token, yielding O(T log T) total time. For hardware efficiency, the top-k estimation is implemented with block approximation (tiling Q and K into b_q × d and b_k × d blocks with internal strided sampling) so that score computation maps to dense matrix multiplies on TensorCores, and the resulting block-sparse mask enables fused sparse attention kernels written in OpenAI Triton. A probabilistic analysis under a Gaussian score-difference model (δ_Δ ~ N(0, σ(Δ)²) with σ increasing in Δ) proves that choosing the center token as representative guarantees HiP outperforms uniform random selection at every tree level. Finally, a KV cache offloading scheme with two separate GPU-resident caches (one for top-k estimation, one for sparse attention) and a configurable page-table data structure (vector map for O(T) space / low latency, or linear-probing hash map for O(log T) space) keeps GPU memory at O(log T) tokens while maintaining near-full decoding throughput.

## Results

On LongBench (32k context), HiP with sparse prefill + sparse decode achieves 98% relative performance (37.6 vs. 38.4 for FlashAttention) while delivering 1.7× prefill and 4.3× decode speedup; with the HEAL fine-tuning variant it recovers 100% relative performance. On PG19, HiP is 9.0× faster in prefill and 30.0× faster in decoding with only a +0.53 perplexity increase (8.12→8.65). On RULER, HiP preserves the full 32k effective context length (matching FlashAttention), whereas all sparse baselines degrade substantially. End-to-end decoding speedup reaches 6.83× at 128k context while maintaining 96.0% relative LongBench quality.

## Baselines & Comparisons

HiP consistently outperforms all six baselines on long-context quality while matching or exceeding their speed gains. Against FlashAttention-2, HiP trades only 2–4% relative LongBench accuracy for 1.7–2.7× prefill and 4.3–16.5× decode speedup at 32k context. Against StreamingLLM, HiP is dramatically superior: 98% vs. 36% relative LongBench score, as SLLM's fixed sink+window pattern cannot capture long-range dependencies. Against AVD (MInference), HiP achieves 98% vs. 74% relative LongBench and 32k vs. 16k effective RULER context length, because AVD's static vertical/diagonal mask fails on complex reasoning tasks. Against BigBird, HiP scores 98% vs. 86–87% on LongBench and 32k vs. 4k effective RULER context, since BigBird's random+window pattern loses information at scale. Against H2O, HiP achieves 98% vs. 56% relative LongBench, as H2O's heavy-hitter KV eviction degrades generation quality. Against HyperAttention, HiP achieves lower PG19 perplexity (8.65 vs. higher) with comparable or better latency at long contexts, while remaining training-free.

## Relation to Prior Work

HiP sits at the intersection of sparse attention (BigBird, Longformer, Reformer) and IO-aware attention (FlashAttention), but departs from both in a key way: it is training-free and achieves sub-quadratic O(T log T) time complexity without altering the model's learned attention patterns. Unlike kernel-based linear attention methods that change the data flow and degrade quality, or static sparse patterns (sliding window, random blocks) that require fine-tuning, HiP dynamically estimates top-k keys per query via a hierarchical tree search exploiting 'attention locality'—the empirically observed phenomenon that neighboring tokens have similar attention scores. The KV cache offloading component builds on paged-attention ideas from vLLM but leverages HiP's predictable access pattern to maintain only O(log T) tokens in GPU memory, a systems contribution distinct from prior offloading work.

## Why It Matters / Open Questions

The practical impact is substantial: HiP enables a single RTX 4090 to serve 64k-token contexts (vs. 16k with FlashAttention) while maintaining 96% of dense-attention quality, making long-context LLM applications feasible on commodity hardware without retraining. The training-free, drop-in nature means it can be immediately applied to any pretrained model, lowering the barrier for long-context deployment. Open questions include how well the attention locality assumption holds for non-English languages, multimodal inputs, or models fine-tuned for specific domains; whether the O(T log T) scaling advantage persists at 1M+ token contexts where the constant factors in the tree search may dominate; and how HiP interacts with emerging techniques like speculative decoding or multi-query attention. The hash-map vs. vector-map trade-off for the page table also remains an active engineering question for very long sequences.
