## Problem

Existing direct preference learning algorithms (DPO, KTO) are designed for single-turn chat and do not account for the multi-turn structure of tool-integrated reasoning, where an LLM alternates between natural-language reasoning and code execution with a Python interpreter. This paper asks how to adapt preference learning to this multi-turn MDP setting so that the model learns from trajectory-level preferences without being forced to predict off-policy external messages returned by the code interpreter.
![Teaser figure](../imgs/ICLR20250931/cropped_page4_idx0.webp)

## Input / Output

The method takes a math problem prompt and produces a multi-turn ReAct-style trajectory in which each action consists of a natural-language reasoning step followed by a Python code execution step, with the interpreter's output fed back as a user-turn message. Generation is constrained to at most 512 tokens per turn, 6 total steps, and 2048 tokens per trajectory. Preference signals are derived from binary correctness checks on the final answer, and the training data pairs one correct and one incorrect trajectory per prompt.

## Method

The paper formulates tool-integrated reasoning as a finite-horizon MDP with external observations and derives the KL-regularized optimal policy as a layer-wise Gibbs distribution over Q-values (Proposition 1). The key insight is that when code execution is deterministic (low external randomness), a reparameterization term vanishes, yielding a clean multi-turn DPO loss (M-DPO) that simply masks out all external-message tokens during training so the model never learns to predict interpreter outputs. This is wrapped in an online iterative framework (M-GSHF) where a non-symmetric policy choice separates exploitation (M-DPO/M-KTO training) from exploration (mixture sampling from current and previous-iteration checkpoints), and the reference model is updated each iteration to optimize the non-regularized reward target. A sublinear regret guarantee is provided under realizability, and the approach is validated across Gemma-1.1-7B, CodeGemma-7B, Mistral-7B, and Gemma-2-9B, yielding up to +6.4 points on GSM8K and +5.1 on MATH over SFT baselines.

## Results

On GSM8K, iterative M-DPO improves Gemma-1.1-it-7B from 77.5% (SFT) to 83.9% (+6.4) and Gemma-2-it-9B from 84.1% to 86.3% (+2.2). On MATH, the same models improve from 46.1% to 51.2% (+5.1) and 51.0% to 54.5% (+3.5), respectively. The aligned Gemma-2-it-9B model surpasses all open-source CodeLLaMA-2 models (7B–70B) trained with Open-MathInstruct on both benchmarks. Across all four base models (Gemma-1.1-it-7B, CodeGemma-1.1-it-7B, Mistral-7B-v0.3, Gemma-2-it-9B), iterative M-DPO and M-KTO consistently outperform RAFT and single-turn DPO/KTO baselines.

## Baselines & Comparisons

Compared to RAFT (reward-ranked fine-tuning), iterative M-DPO consistently wins across all four base models by 2–5 points on GSM8K and 2–5 points on MATH, because M-DPO leverages negative signal from incorrect trajectories while RAFT only imitates correct ones. Against iterative single-turn DPO (which treats the full trajectory as one action without masking external messages), M-DPO wins by 1.5–2.2 points on GSM8K and 1.5–2.2 points on MATH, confirming that forcing the model to predict off-policy code-interpreter outputs hurts reasoning. Against iterative single-turn KTO, M-DPO shows similar margins. The aligned Gemma-2-it-9B (86.3/54.5) surpasses the much larger CodeLLaMA-2-70B SFT model (84.6/50.7) on both benchmarks, and the aligned Gemma-1.1-it-7B (83.9/51.2) is comparable to CodeLLaMA-2-70B (slightly worse on GSM8K, slightly better on MATH). CoT-only baselines (WizardMath) are far behind, with WizardMath-70B reaching only 81.6/22.7, underscoring the benefit of tool integration.

## Relation to Prior Work

This paper extends single-turn direct preference learning (DPO, KTO) to a multi-turn MDP formulation where the agent interacts with an external code interpreter across multiple turns. The key technical departure from prior DPO/KTO work is the token masking of external messages (observations from the code interpreter) during loss computation, which is justified by showing that under deterministic transitions (as in code execution), the re-parameterization term (C) vanishes, yielding a clean multi-turn DPO loss. The online iterative framework is adapted from Xiong et al. (2024) for single-turn chat, and the ReAct-style action structure (reasoning + code execution) follows ToRA (Gou et al., 2023). Unlike prior RLHF-for-math work that focuses on SFT with synthetic data or step-wise process rewards, this paper operates at the trajectory level with final-answer checking as the preference signal.

## Why It Matters / Open Questions

The paper provides a practical, well-validated recipe for further improving tool-integrated math agents beyond SFT, with consistent gains across four base models (Gemma-1.1, CodeGemma, Mistral, Gemma-2). A key open limitation is that the method relies on deterministic external transitions (code execution); extending to stochastic or adversarial environments would require a value network and adaptive margins, which the authors leave for future work. The finding that preference learning improves pass@1 but not pass@n for large n suggests the method sharpens existing capabilities rather than introducing new knowledge, pointing toward complementary approaches (e.g., MCTS-based exploration, step-wise rewards) for broader gains.
