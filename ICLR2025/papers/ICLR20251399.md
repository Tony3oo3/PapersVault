## Problem

In realtime RL environments, the world evolves while the agent computes actions, so larger models with longer inference times force the agent to rely on low-level default behaviors between actions, reducing its control over the environment. No prior work had formalized how this sequential interaction paradigm induces persistent regret that never dissipates as model size grows, nor proposed a mechanism to maintain high action frequency with arbitrarily large inference times.

## Input / Output

The agent observes a single game state frame (monochromatic Game Boy images downsampled to 84×84×1, or standard Atari frames) and outputs one of six discrete button-press actions (A, B, left, up, right, down for Game Boy; standard action sets for Atari). Critically, the action is not applied immediately: it is delayed by ⌈τ_θ/τ_M⌉ environment steps (where τ_θ is the inference time and τ_M is the environment step time of ~1/60 s), during which a fixed default behavior policy β (noop) governs the environment. The environment runs at a fixed 59.7275 fps (Game Boy) or 60 fps (Atari) regardless of agent computation speed.

## Method

The paper formalizes the agent-environment interface as an induced delayed semi-MDP (Definition 1) and derives a regret decomposition (Theorem 1) into three independent terms: learning regret, inaction regret (from following the default policy β), and delay regret (from acting on stale states). The key algorithmic contribution is two staggering algorithms for asynchronous inference: Algorithm 1 (Maximum Time Inference Staggering) maintains N_I processes each waiting for the current maximum inference time estimate to preserve perfectly uniform action spacing, while Algorithm 2 (Expected Time Inference Staggering) uses a running mean estimate and progressively reduces waiting to achieve the same average spacing with less compute. Combined with round-robin asynchronous learning (Langford et al.), the framework ensures that the number of inference processes needed to eliminate inaction scales linearly with inference time, enabling models up to 1B parameters to act at every environment step in realtime Game Boy and Atari games.

## Results

The paper demonstrates that the number of inference processes needed to eliminate inaction (N_I*) scales linearly with both the expected inference time τ̄_θ and model parameter count |θ| (Figure 7), and similarly for learning processes N_L* with learning time τ̄_L (Figure 8). In Tetris, sequential interaction (single process) cannot surpass random performance for |θ| ≥ 1M, while staggered asynchronous inference (Algorithm 1) maintains competitive episodic return even at 1B parameters. In Pokémon Blue at 100M parameters, the asynchronous approach achieves faster progress through both battle encounters (295 total) and catching encounters (93 total) compared to sequential interaction. On Atari (Boxing, Krull, Name This Game), staggered async inference preserves performance as |θ| scales from 1M to 1B, whereas sequential interaction degrades sharply.

## Baselines & Comparisons

The primary baseline is the standard sequential interaction paradigm (single inference process, [94]), where the agent must complete inference before the environment advances. A secondary baseline is the act-before-learn ordering proposed by Travnik et al. [102], which flips the inference/learning order but still uses a single sequential process. The proposed staggered asynchronous inference (Algorithm 1) wins decisively over both baselines in every experiment as model size grows: in Tetris, sequential interaction drops to random-level performance at |θ| ≥ 1M while the staggered approach maintains a substantially higher reward rate up to 1B parameters; in Pokémon Blue at 100M, the asynchronous method completes more battles and catches more wild Pokémon per unit time; and on Atari, the gap widens with model size, with the deeper 30-layer ResNet architecture (which increases inference time at the same parameter count) producing an even larger performance gap between staggered async and sequential. The key finding is that the sequential baseline's regret does not dissipate over time (Remark 1), while the staggered approach eliminates inaction regret entirely given sufficient processes (Remark 2), making the advantage grow with both model size and wall-clock time.

## Relation to Prior Work

This paper extends the asynchronous RL framework of Travnik et al. [102] by formalizing the connection between sequential and asynchronous MDPs as an induced delayed semi-MDP, and by deriving a three-term regret decomposition (learning, inaction, delay) that had not previously been stated. It builds on Langford et al.'s [50] round-robin asynchronous SGD for the learning component, but introduces the novel concept of staggering asynchronous *inference* processes to maintain consistent action intervals. The key departure from prior work is the focus on delays caused by the agent's own computation (which are controllable) rather than environment communication delays, and the demonstration that sequential interaction incurs persistent regret that never dissipates as time grows.

## Why It Matters / Open Questions

The paper challenges the conventional assumption that realtime settings necessitate small, fast models by showing that staggered asynchronous inference enables models orders of magnitude larger (up to 1B parameters) to maintain performance in realtime games. However, limitations temper the impact: experiments use relatively simple Game Boy and Atari environments with small discrete action spaces, performance remains below human-level in Pokémon and Tetris, and the hardware setup assumes a dedicated CPU core per process (idealized). Open questions include whether the approach generalizes to continuous control, more complex stochastic environments, and GPU-constrained multi-process deployment where memory bandwidth becomes the bottleneck.
