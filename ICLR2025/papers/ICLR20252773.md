## Problem

With hundreds of thousands of LLMs available, existing workflows for benchmarking, model routing, and performance evaluation each require separately learning task-specific representations of models, incurring repeated inference costs and computational overhead. No prior work has proposed a single, unified compact vector representation of an LLM that can be reused across multiple downstream tasks without retraining.
![Teaser figure](../imgs/ICLR20252773/cropped_page1_idx0.webp)

## Input / Output

The system consumes a correctness matrix of shape (112 models × 36,054 questions) derived from 10 benchmarks, where questions are pre-embedded via the frozen sentence-transformer all-mpnet-base-v2 into 768-dim vectors. The primary output is a learned model embedding vector of configurable dimension; downstream, a single linear head on top of these embeddings yields binary correctness predictions, n-way routing decisions, or continuous benchmark accuracy scores (0–100%). Notably, the model's raw weights are never accessed—only its aggregate answer-correctness pattern across questions serves as the training signal.

## Method

EmbedLLM adopts an encoder-decoder reconstruction architecture analogous to matrix factorization: an encoder produces a model embedding (via a learned network) and a question embedding (via a frozen sentence-transformer followed by a trainable projection), and a decoder predicts correctness using the Hadamard (element-wise) product of the two embeddings passed through a linear classifier. Training minimizes binary cross-entropy on the correctness matrix, effectively learning a low-rank factorization where the model embedding matrix and question embedding matrix jointly reconstruct the full correctness matrix. The key design choice is that the reconstruction target (answer correctness) acts as a 'decoy' objective—any task requiring model characterization would suffice—so the learned embeddings capture general model characteristics rather than being tied to one specific metric. Downstream tasks (routing, benchmark prediction) require only a lightweight linear layer on top of the frozen embeddings, avoiding the need for task-specific retraining of the embedder itself.

## Results

On correctness forecasting, EmbedLLM achieves 74.09% test accuracy on the full 29K-question test set, outperforming the KNN baseline (71.52%) by 2.57 percentage points, with consistent gains across all training set sizes from 1K to 29K questions. For model routing, EmbedLLM achieves near single-best-model accuracy across all 10 benchmarks while distributing queries across 112 models, and routes 3,000 questions in 3.80 seconds on a single A100 GPU—15× faster than the causal LLM router of Ong et al. (2024) and using 60× less peak GPU memory than fine-tuning Llama-3-8B as a router. For benchmark accuracy prediction, Kendall's Tau tests confirm statistically significant correlation between model embeddings and held-out benchmark accuracy in 7 out of 10 benchmarks (e.g., 100/100 splits for MathQA, LogiQA, MedMCQA; 94/100 for MMLU).

## Baselines & Comparisons

The primary quantitative baseline is a KNN classifier that uses the full set of question-correctness tuples as an implicit model representation. EmbedLLM outperforms KNN at every training set size, with the gap widening from 0.71 pp at 1K questions to 2.57 pp at the full 29K set (74.09% vs 71.52%), indicating better scalability. In the model routing task, EmbedLLM is compared against a single-best-model router (which always picks the highest-accuracy model) and a random router matched to the same model-selection budget. EmbedLLM achieves near single-best-model accuracy on every individual benchmark while still leveraging the complementary strengths of different models, as evidenced by a large margin over the weighted random baseline. In terms of efficiency, the EmbedLLM router processes 3,000 queries in 3.80 s on one A100 GPU, exceeding 750 model selections per second—15× faster than the causal LLM router in Ong et al. (2024) which handles fewer than 50 requests/s—and requires under 1 GB peak GPU memory, roughly 60× less than fine-tuning Llama-3-8B as a router.

## Relation to Prior Work

This paper carves new conceptual ground by proposing to learn compact vector embeddings of LLMs themselves, drawing an analogy to word embeddings (Mikolov et al., 2013) and self-supervised representation learning in vision (Noroozi & Favaro, 2017; Vondrick et al., 2018), but applied to the model as the object of representation rather than text or images. Methodologically, it repurposes the encoder-decoder / matrix-factorization paradigm from image reconstruction (He et al., 2022; Ronneberger et al., 2015) to factorize a model×question correctness matrix, with a Hadamard-product decoder. In the LLM routing literature (Ong et al., 2024; Shnitzer et al., 2023; Lu et al., 2023), prior routers implicitly learn model representations as a byproduct of task-specific training; EmbedLLM makes this representation explicit and task-agnostic, unifying routing, correctness forecasting, and benchmark prediction under a single embedding.

## Why It Matters / Open Questions

The practical impact is significant: a 15× speedup over causal-LLM routers and 60× memory reduction make model routing nearly free at inference time, which is critical as the Huggingface model pool grows to hundreds of thousands. However, the system is static (retraining required for new models), limited to 112 models and correctness-based signals, and the method is essentially a linear matrix factorization, raising open questions about scalability to thousands of models, incorporation of richer output signals (e.g., text embeddings of model responses), and whether the learned embeddings remain informative as model architectures and training paradigms diversify further.
