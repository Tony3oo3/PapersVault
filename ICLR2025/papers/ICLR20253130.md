## Problem

Existing long-term memory benchmarks for chat assistants either focus on human-human conversations rather than task-oriented user-AI interactions, or use non-configurable short histories that limit evaluation difficulty. They also fail to holistically cover all critical memory abilities—particularly multi-session synthesis, assistant-side recall, knowledge updates, and temporal reasoning—leaving a significant gap in assessing whether chat assistants can genuinely maintain and reason over long, evolving interaction histories.
![Teaser figure](../imgs/ICLR20253130/cropped_page2_idx0.webp)

## Input / Output

The system receives a sequence of N timestamped multi-turn user-assistant chat sessions delivered sequentially (online), followed by a user question with its date. Two standard settings are provided—LONGMEMEVAL_S (~115k tokens, ~50 sessions) and LONGMEMEVAL_M (~1.5M tokens, 500 sessions)—with the history length freely extensible via a needle-in-a-haystack-style compilation pipeline. Answers are scored by a prompt-engineered GPT-4o judge (≥97% agreement with human experts), and intermediate retrieval quality is measured with Recall@k and NDCG@k against human-annotated evidence locations.

## Method

The paper formulates a unified three-stage memory framework (indexing → retrieval → reading) with four control points and identifies effective optimizations through systematic ablation on LONGMEMEVAL. For value granularity, decomposing sessions into individual rounds outperforms whole-session storage while avoiding the information loss inherent in fact or summary compression. For indexing, a document expansion strategy that prepends extracted user facts to the original value as the key (K=V+fact) improves recall@k by 9.4% and downstream QA accuracy by 5.4% over using the value alone. For temporal reasoning, a time-aware query expansion scheme uses a strong LLM to extract a time range from the question and filters the retrieval scope, improving recall by 6.8%–11.3%. For reading, combining Chain-of-Note (extract-then-reason) with JSON-structured memory items yields up to 10 absolute points improvement over direct reading, even under oracle retrieval.

## Results

On LONGMEMEVAL_M, the proposed fact-augmented key expansion (K=V+fact) with round-level values achieves 0.644 Recall@5 and 0.784 Recall@10, outperforming the K=V baseline (0.582/0.692) by 9.4% in recall. End-to-end QA accuracy with GPT-4o reaches 0.720 (Top-10) with K=V+fact versus 0.670 with K=V alone. In the pilot study, long-context LLMs suffer 30%–60% accuracy drops on LONGMEMEVAL_S relative to oracle retrieval (e.g., GPT-4o: 0.870→0.606; Llama 3.1 70B: 0.744→0.334), and commercial systems (ChatGPT, Coze) achieve only 0.58 and 0.33 accuracy respectively versus 0.92 for offline reading with the same LLM.

## Baselines & Comparisons

Among retrievers, Stella V5 1.5B (the paper's chosen dense retriever) outperforms BM25 by a wide margin (e.g., 0.784 vs 0.757 Recall@10 with K=V+fact, Value=Round) and is comparable to or slightly ahead of Contriever (0.784 vs 0.756 Recall@10). The proposed K=V+fact key expansion consistently beats the K=V baseline across all three reader LLMs, gaining +5.4% average QA accuracy and +9.4% Recall@k. In the commercial system evaluation, ChatGPT (GPT-4o) achieves 0.5773 accuracy and Coze (GPT-4o) achieves 0.3299, both substantially below the 0.9184 offline-reading upper bound with the same GPT-4o model, indicating a 37% and 64% performance drop respectively. The paper's unified memory design (round values + fact-augmented keys + time-aware query expansion + CoN/JSON reading) collectively pushes GPT-4o QA accuracy from 0.615 (K=V, no CoN) to 0.720 (K=V+fact, with CoN+JSON) on LONGMEMEVAL_M, a 10.5-point absolute gain.

## Relation to Prior Work

This paper extends the line of long-term memory benchmarks (MemoryBank, LoCoMo, PerLTQA, DialSim) by addressing their two key gaps: incomplete ability coverage (prior benchmarks miss knowledge updates, temporal reasoning with metadata, or abstention) and non-configurable, short histories that don't reflect task-oriented user-AI interactions. Methodologically, it builds on Chain-of-Note (Yu et al., 2023) for the reading stage and classical document expansion (Tao et al., 2006; Efron et al., 2012) for the key expansion strategy, while the history compilation pipeline is inspired by the needle-in-a-haystack test (Kamradt, 2023). The paper's main conceptual contribution is a unified three-stage framework (indexing, retrieval, reading) with four control points that subsumes nine existing memory-augmented systems, providing a common design space for future work.

## Why It Matters / Open Questions

The 30–60% performance drop for state-of-the-art long-context LLMs on a history of only ~115k tokens, and the 37–64% gap between commercial assistants and offline reading, demonstrate that current memory mechanisms are far from adequate for sustained personalization. The practical design insights (round-level decomposition, fact-augmented key expansion, time-aware query filtering, CoN + JSON reading) give practitioners a concrete, well-ablated recipe for building better memory systems. Open questions include how these designs scale to the 1.5M-token setting, whether memory deletion and security (preventing toxic content injection into the datastore) can be addressed, and whether the LLM-as-judge evaluation (97% agreement) remains reliable as answer formats grow more open-ended.
