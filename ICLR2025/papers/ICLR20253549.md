## Problem

3D Gaussian Splatting's adaptive density control dynamically adjusts the number of Gaussians based on input complexity, but this flexibility has never been examined as a security vulnerability. This paper reveals that an attacker can poison input images to force the system into its worst-case computational complexity, dramatically inflating GPU memory and training time to the point of Denial-of-Service. This is the first computation cost attack targeting the training phase of any ML system and the first attack on 3DGS.

## Input / Output

The attacker takes a clean multi-view image set with associated camera poses and produces a poisoned image set where camera poses remain unchanged but each image is perturbed. Perturbations can be constrained to an L∞ ball of radius ε (e.g., 16/255 ≈ 6.3% per-pixel change) for stealth, or left unconstrained (ε=∞) for maximum damage. The poisoned dataset is then consumed by the victim 3DGS trainer, which produces an over-densified 3D Gaussian model with far more parameters than the clean scene warrants.

## Method

The attack is formulated as a max-min bi-level optimization where the outer loop maximizes computation cost and the inner loop is the victim's 3DGS training. Three key strategies make this tractable: (1) computation cost is approximated by the number of Gaussians, which is further approximated by the total variation (TV) score of rendered images, providing a differentiable surrogate; (2) a proxy 3DGS model is trained and iteratively updated to maintain multi-view geometric consistency, since independently maximizing TV per view produces incoherent noise that actually reduces Gaussian count; (3) an optional L∞ ε-ball constraint (enforced via projection after each PGD step) balances attack strength against stealth. Each outer iteration renders the proxy model at a random camera view, applies PGD to maximize TV score within the ε-ball, then performs one 3DGS training step on the poisoned image to update the proxy, progressively building up 3D complexity that forces the victim to over-densify.

## Results

Under the constrained attack (ε=16/255), Poison-Splat increases peak GPU memory by up to 8.92× (NS-hotdog: 3,336→29,747 MB), the number of Gaussians by up to 6.20×, training time by up to 2.03×, and degrades rendering speed by up to 6.42×. Under the unconstrained attack (ε=∞), the effects are far more severe: peak GPU memory increases up to 22.33× (NS-lego: 3,532→78,852 MB, approaching the 80 GB limit of A100/H100 GPUs), Gaussians increase up to 23.09×, training time up to 4.97×, and render speed drops up to 15.28×. The attack also generalizes to black-box victims (Scaffold-GS), achieving up to 5.01× more Gaussians and 2.08× GPU memory increase under constrained perturbations.

## Baselines & Comparisons

This is an attack paper rather than a method comparison, so there are no competing attack baselines. The paper's key internal comparisons are: (1) Poison-Splat vs. a naive image-level TV-maximization attack (without the proxy model), where Poison-Splat produces significantly more Gaussians because the proxy model ensures multi-view consistency, whereas the naive approach creates conflicting textures that actually reduce the number of Gaussians the victim model produces. (2) White-box vs. black-box: the attack crafted for standard 3DGS generalizes to Scaffold-GS (a structurally different 3DGS variant using anchor points), achieving up to 5.01× more Gaussians and 2.08× GPU memory increase under constrained perturbations, confirming the attack exploits a fundamental property (image non-smoothness) rather than algorithm-specific details. (3) A naive defense of capping the number of Gaussians is shown to be ineffective: it limits resource consumption but severely degrades reconstruction quality, as 3DGS cannot distinguish legitimate fine details from poisoned textures.

## Relation to Prior Work

This paper sits at the intersection of data poisoning attacks and resource-targeting (DoS) attacks in machine learning, but carves out a genuinely new problem space: poisoning training data to inflate the *training-stage* computation cost of an adaptive-complexity 3D reconstruction system. Prior resource-targeting work (Shumailov et al., 2021; Hong et al., 2020; Chen et al., 2023) focused on inference-stage energy/latency of fixed-complexity neural networks, while data poisoning literature targeted model accuracy or integrity. The methodological backbone draws on bi-level optimization frameworks from poisoning attacks (Muñoz-González et al., 2017; Huang et al., 2020; Koh et al., 2022) and PGD-style adversarial optimization, but the key departure is exploiting 3DGS's adaptive density control—a non-differentiable, data-dependent mechanism absent from standard neural networks—as the attack surface.

## Why It Matters / Open Questions

This is the first identified security vulnerability in 3D Gaussian Splatting and the first DoS attack targeting the training phase of any ML system, with direct practical implications for commercial 3DGS service providers (KIRI, Polycam, Spline, LumaAI) that accept user-uploaded images. The finding that a naive defense (capping Gaussian count) significantly degrades reconstruction quality means service providers cannot simply impose a hard limit without sacrificing their product's core value proposition, leaving an open question about how to distinguish legitimate scene complexity from adversarial over-densification. The paper also raises broader questions about whether other adaptive-complexity learning systems (e.g., dynamic neural networks, progressive refinement methods) share similar vulnerabilities, and whether the proxy-model-based multi-view consistency strategy generalizes to other 3D reconstruction paradigms.
