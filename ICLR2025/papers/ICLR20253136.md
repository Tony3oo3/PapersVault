## Problem

ML for healthcare suffers from a severe reproducibility crisis: cohort definitions in published studies are too sparse to reconstruct, and more than half of MIMIC-III-based studies could not be reliably reproduced. Existing tools like ATLAS and PIC-SURE are locked to specific common data models, while static benchmarks are tied to single datasets, leaving no interoperable, flexible, and accessible system for defining and extracting reproducible cohorts across diverse EHR schemas.

## Input / Output

ACES consumes an event-stream dataset (in MEDS, ESGPT, or user-provided direct predicate format) alongside a YAML-style task configuration file that separates dataset-specific predicate definitions from dataset-agnostic window-based inclusion/exclusion criteria. The output is a single unified dataframe where each row is a valid patient instance, containing patient identifiers, a user-defined prediction timestamp, a task label derived from a specified predicate, and for each interrelated window, start/end timestamps plus aggregated predicate counts. The configuration file is the shareable artifact: swapping only the predicate section allows the same task logic to be ported to a different dataset without modifying the window criteria.

## Method

ACES represents each task as a tree-structured hierarchy of interrelated windows, where nodes define temporal or event-bounded segments of a patient's record and edges specify relationships between them. A recursive algorithm identifies root anchor events (task triggers) matching a predicate, then traverses subtrees by aggregating predicate counts over each window—either via fixed time intervals or event-bounded windows (e.g., between admission and discharge)—filtering out branches whose counts fail to meet specified criteria before recursing to child nodes. The key technical contribution is the event-bounded query aggregation mechanism, which allows windows to be delimited by clinical events rather than only fixed durations, enabling more expressive capture of clinical timelines. The system is built on Hydra for flexible CLI configuration and parallel sharded execution, and exposes both a command-line interface and a Python API for integration into deep learning pipelines.

## Results

On a single MIMIC-IV MEDS shard (~80.3M event rows, ~48K patients), ACES extracts cohorts for nine clinical prediction tasks in 183–367 seconds with peak memory of 30–109 GB. The largest cohort (30-day re-admission) yields 464,821 samples across 18,908 patients in 367 s, while the smallest (reduced LVEF post-ECG) yields only 17 samples across 14 patients in 210 s. In the comparative experiments (Appendix B), ACES completes four tasks on MIMIC-IV Demo in 8.6–24.5 s of script runtime with 587–932 MiB peak memory and 168–251 lines of code, versus substantially higher human time (2,441–12,000 s) for manual setup.

## Baselines & Comparisons

The paper compares ACES against two existing cohort-extraction tools—OMOP-learn (Kodialam et al., AAAI 2021) and DPM360 (Suryanarayanan et al., 2021)—on four tasks (first-24h in-hospital mortality, 30-day post-discharge mortality, 30-day re-admission, and end-of-life prediction) using the MIMIC-IV Demo OMOP schema and a 1,000-patient Synthea synthetic dataset. ACES completes all four tasks in 8.6–24.5 s of script runtime with 587–932 MiB peak memory and 168–251 lines of code, while the authors report that OMOP-learn and DPM360 require new ATLAS executions, bespoke SQL queries, or changes to Python parameters for each new task. Qualitatively, ACES requires only simple modifications to a shareable YAML configuration file to capture new task logic, whereas the baselines demand more invasive code changes. The authors acknowledge potential bias due to their familiarity with ACES and only surface-level exposure to the competing tools, and note that the comparison is preliminary rather than a full head-to-head benchmark.

## Relation to Prior Work

ACES carves new ground by introducing a domain-specific configuration language that explicitly separates dataset-specific event predicates from dataset-agnostic inclusion/exclusion criteria, a decomposition not present in prior cohort extraction tools. It departs from CDM-locked systems like ATLAS (OHDSI/OMOP) and PIC-SURE (i2b2), which cannot generalize beyond their target schema, and from static single-dataset benchmarks (MIMIC-IV, eICU, YAIB), which cannot accommodate new clinical tasks. Conceptually, ACES repurposes the event-stream data paradigm from MEDS and ESGPT as a universal substrate, enabling the same task logic to be ported across heterogeneous EHR schemas by swapping only the predicate layer.

## Why It Matters / Open Questions

ACES directly targets the reproducibility crisis in ML for healthcare by enabling researchers to share task definitions as portable configuration files without sharing underlying data, supporting the 'frictionless reproducibility' and decentralized validation (MEDS-DEV) vision. Key open questions include whether the DSL is expressive enough for complex longitudinal criteria (case-control matching, propensity reweighting, nested configurations), whether unstructured clinical notes can be integrated as predicates, and whether the approach scales to multi-institutional federated settings. The comparative experiments show large efficiency gains over DPM360 and OMOP-learn, though the authors acknowledge potential familiarity bias, leaving the practical adoption gap to be validated by the broader community.
