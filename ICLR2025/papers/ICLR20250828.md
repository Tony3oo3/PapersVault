## Problem

Existing LLM-driven multi-agent collaboration (MAC) systems for code generation rely on static, human-designed workflows that cannot adapt to the diverse demands of real-world software development, and existing benchmarks either focus on function-level tasks or use indirect evaluation metrics that fail to verify requirement correctness. This leaves a gap in both adaptive multi-agent coding architectures and reliable software-level evaluation.
![Teaser figure](../imgs/ICLR20250828/cropped_page3_idx0.webp)

## Input / Output

The method takes lengthy, item-by-item natural language software requirements (averaging 507 words for games and 1011 words for websites, covering 53 tasks with 616 paired requirements) as input, and produces complete executable software (Pygame-based games or Flask-based websites) along with automatically generated unit test cases. Unlike function-level benchmarks that provide a single function signature, rSDE-Bench inputs specify multiple measurable functionalities, GUI constraints, logging formats, and game rules simultaneously, requiring long-context understanding and multi-component code generation.

## Method

EvoMAC represents the coding team as a directed acyclic graph of LLM-powered agents (nodes) connected by task-dependency edges, initialized by a self-organizing agent that decomposes requirements into subtasks. The core innovation is a textual backpropagation loop executed at test-time: a testing team generates unit tests as a target proxy, a compiler executes the generated code against those tests to produce objective environmental feedback, a gradient agent analyzes which agents fulfilled, erred, or missed subtasks, and an updating agent restructures the network by removing completed agents, revising erroneous prompts, adding new agents for missing subtasks, and rewiring the workflow. This cycle repeats for K iterations, iteratively refining both agent prompts and the DAG topology without any parameter-level training, distinguishing it from self-critique approaches by grounding feedback in objective execution rather than subjective LLM judgment.

## Results

On rSDE-Bench (all powered by GPT-4o-Mini), EvoMAC achieves 89.38% accuracy on Website Basic, 65.05% on Website Advanced, 77.54% on Game Basic, and 51.60% on Game Advanced. On the function-level HumanEval benchmark, EvoMAC reaches 94.51% Pass@1. EvoMAC outperforms the best single-agent baseline (GPT-4o-Mini) by 26.48% on Website Basic and 34.78% on Game Basic, and surpasses the best multi-agent baseline (ChatDev) by 26.71% on Website Basic and 23.91% on Game Basic.

## Baselines & Comparisons

EvoMAC decisively outperforms all five multi-agent baselines on rSDE-Bench. Against ChatDev (the strongest multi-agent baseline), EvoMAC gains +26.71% on Website Basic (89.38 vs. 62.67) and +23.91% on Game Basic (77.54 vs. 53.63). MetaGPT and AgentVerse perform poorly on Website tasks (15.41% and 0.00% on Advanced), while AutoGen scores 0.00% on Game Advanced. On HumanEval, EvoMAC (94.51%) surpasses MapCoder and AgentVerse (both 90.85%) by 3.66 points and the single-agent GPT-4o-Mini (88.41%) by 6.10 points. Notably, ChatDev, despite being the best multi-agent baseline on rSDE-Bench, scores only 70.73% on HumanEval, suggesting its workflow is less effective for function-level tasks. The ablation study further confirms that removing the objective environment feedback (replacing it with LLM self-critique) drops performance by 12.67–21.74% across settings, validating the importance of compiler-based verification over subjective agent critique.

## Relation to Prior Work

This paper departs from the line of static, human-designed multi-agent collaboration systems (MetaGPT, ChatDev, AutoGen, MapCoder, AgentVerse) by introducing a test-time self-evolving paradigm that iteratively adapts both agent prompts and workflow topology. The key conceptual move is borrowing the backpropagation metaphor from neural network training and instantiating it as 'textual backpropagation,' where objective environmental feedback (compiler/test execution) replaces numerical gradients to guide prompt and topology updates. It also explicitly contrasts with self-critique approaches, arguing that objective environment-based feedback avoids the bias and hallucination problems of LLM-driven critique. On the benchmark side, rSDE-Bench extends the code-generation evaluation landscape beyond function-level (HumanEval, MBPP) and bug-fixing (SWE-bench) to software-level tasks with per-requirement automatic verification, filling a gap left by prior software-generation benchmarks (SRDD, SoftwareDev) that relied on indirect or human evaluation.

## Why It Matters / Open Questions

The self-evolving MAC paradigm is potentially generalizable beyond code generation to any task where an objective environment can verify outputs against a target proxy, making it a broader methodological contribution. rSDE-Bench addresses a real gap in software-level evaluation, and the 99.22% correlation with human evaluation lends credibility to its automatic metric. However, the benchmark is small (53 tasks, only Website and Game types), the driving LLMs are mid-tier (GPT-4o-Mini, Claude-3.5-Sonnet), and the paper does not explore scaling to larger or more diverse software domains. Open questions include whether the self-evolving approach generalizes to more complex, multi-file software projects, whether a learned reward model could replace the hand-crafted textual backpropagation, and whether the gains persist with stronger base models.
