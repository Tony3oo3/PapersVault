## Problem

Large language models lack an explicit separation between instructions (to be executed) and data (to be processed), making them vulnerable to prompt injection and unreliable in safety-critical applications. Despite widespread awareness of this issue, no formal definition or quantitative benchmark existed to measure how well a model actually separates the two. This paper introduces the first formal separation score, a computable empirical proxy, and a dedicated evaluation dataset to close this gap.

## Input / Output

The evaluation protocol takes 4-tuples (task prompt s, data prompt d, probe string x, witness string w) from the SEP dataset and constructs two model inputs: one with x appended to the instruction argument (s+x, d) and one with x appended to the data argument (s, x+d). The model's free-text outputs are then checked for the presence of the witness w, requiring no access to internal states or token probabilities. The resulting empirical separation score measures the fraction of cases where the witness appears in the instruction-arg output but is absent from the data-arg output, while the utility score measures the fraction where the witness appears in the instruction-arg output at all.

## Method

The paper formalizes separation as the expected dissimilarity (e.g., KL divergence) between output distributions when a probe string is placed in the instruction versus data argument, then makes this computable via the 'surprise witness' concept: a short string that is near-certain to appear if the probe is executed but near-impossible if it is merely processed. The SEP dataset (9,160 tuples across 30 tasks in three categories) pairs each task with one of 100 manually written probe-witness pairs (e.g., 'What is a group of crows called?' / 'murder') embedded in realistic data prompts. The authors evaluate nine state-of-the-art LLMs under three mitigation strategies: template-based prompt engineering, gradient-based prompt optimization (adapting GCG-style coordinate descent to maximize a 'no-probe' output), and LoRA fine-tuning with SFT or DPO. Key findings show all models fail to achieve high separation natively, fine-tuning raises separation to ~95% but drops utility by ~20 percentage points, and prompt engineering yields inconsistent gains across models.

## Results

On the SEP dataset, all nine evaluated LLMs exhibit poor instruction-data separation in the naive setting, with empirical separation scores ranging from 13.3% (Phi-3-mini-4k) to 73.2% (Gemma-2B), averaging 37.5% across open-weight models. Prompt engineering improves separation by ~24 percentage points on average (to 52.6%), with GPT-4 reaching 95.3% as an outlier. Fine-tuning via DPO achieves the highest separation (95.5% average) but at a significant utility cost, dropping from 67.8% to 50.0% on average. Prompt optimization provides only a modest 7.2-point average gain, confirming it is insufficient as a standalone mitigation.

## Baselines & Comparisons

The paper does not propose a single new method but rather benchmarks four mitigation strategies (naive, prompt engineering, prompt optimization, and DPO fine-tuning) across nine LLMs. Fine-tuning via DPO dominates on separation (95.5% average) but sacrifices utility by ~18 percentage points (67.8% → 50.0%), making it impractical for general-purpose use. Prompt engineering is the most effective non-invasive technique, yielding a 24-point average separation gain with minimal utility loss (+1.3 points), though results are highly model-dependent: GPT-4 jumps from 20.8% to 95.3%, while Gemma-7B shows zero improvement. Prompt optimization (GCG-style) provides only a 7.2-point average gain and is inconsistent across models (e.g., Phi-3-mini shows no change at 13.3%). Notably, larger or more recent models do not separate better; in fact, smaller models within a family (Gemma-2B vs. 7B, Llama-2 vs. 3, GPT-3.5 vs. 4) tend to achieve higher separation, suggesting the problem is unlikely to resolve through scaling alone.

## Relation to Prior Work

This paper departs from the prompt-injection defense literature (Greshake et al., 2023; Yi et al., 2024; Hines et al., 2024; Wallace et al., 2024) by reframing the problem from an attack/defense perspective to a first-principles measurement question: how well does a model separate instructions from data? While prior work identified indirect prompt injection as a vulnerability and proposed various mitigations (structured queries, spotlighting, instruction hierarchies, activation-based detection), none provided a formal definition or quantitative benchmark for the underlying separation property. The paper draws an explicit analogy to SQL injection and CPU non-executable memory protection, positioning instruction-data separation as a foundational security principle that LLMs lack. For prompt optimization, it adapts the GCG-based framework of Zhou et al. (2024) from jailbreak defense to the separation setting.

## Why It Matters / Open Questions

The SEP dataset and formal separation score provide the first quantitative tool for evaluating a property that the LLM safety community has discussed qualitatively but never measured, making it likely to become a standard benchmark. The finding that no current model achieves adequate separation, and that the best mitigation (fine-tuning) imposes a significant utility cost (~18–20% drop), suggests that post-hoc techniques are insufficient and that architectural-level solutions are needed. Open questions include whether the GPT-4's strong prompt-engineering result reflects a genuine architectural advantage or a dataset artifact, whether scaling will eventually resolve the separation-utility trade-off, and how the framework extends to multi-turn and agentic settings.
