## Problem

Vision-based GUI agents struggle with precise element grounding because GUI elements are small, visually similar, and lack large-scale dense annotations comparable to natural image segmentation. Existing MLLMs either treat grounding as a pure text-generation task (predicting coordinates as tokens) or rely on text-based representations that are unavailable or noisy in many real-world scenarios, and no lightweight, plug-and-play grounding module exists that can be seamlessly attached to any MLLM planner.
![Teaser figure](../imgs/ICLR20250713/cropped_page0_idx1.webp)

## Input / Output

The grounding model takes a GUI screenshot (rescaled to 1024×1024 with aspect-ratio-preserving padding) and a natural-language query, outputting a bounding box (score + xywh coordinates) or a 2D point. In the integrated agent setting, the MLLM receives the screenshot, user goal, and optional action history, and generates a text response containing a special <|POS|> token; the hidden-state embedding of that token is linearly projected and fed into the grounding decoder alongside image features to produce the final element position. For point-based tasks, the prediction head is modified to output normalized distance-to-truth as a score and 2D coordinates as the position.

## Method

The core contribution is AssistGUIGrounder (AGG), a 0.4B-parameter grounding module combining a SAM-pretrained ViT image encoder (with windowed attention and four global attention blocks for high-resolution inputs), a BERT-based language prompt encoder, and a two-layer lightweight decoder that performs bidirectional self-attention on query tokens, cross-attention to/from image embeddings, and MLP updates to predict bounding boxes. An automated data collection engine crawls 118 domains across 11 topics from Common Crawl, simulating page scrolling and extracting element metadata via UI Automation, yielding 0.5M screenshots with 35M dense annotations augmented through GPT-4-generated query templates. The integration paradigm, 'embeddings-as-position,' adds a <|POS|> token to the MLLM vocabulary so that the MLLM's hidden embedding at that position is projected and passed to the grounding decoder, cleanly separating reasoning (MLLM) from localization (AGG). Training uses a combined MSE + L1 + GIoU loss for box regression with backpropagation from all prompt embeddings, and for agent tasks a joint text-prediction + grounding objective with LoRA fine-tuning of the MLLM while keeping the image encoder frozen.

## Results

On the ScreenSpot grounding benchmark, AGG (0.4B parameters) achieves 66.6% average accuracy, surpassing SeeClick (9.6B, 53.4%) by 13.2 points and CogAgent (18B, 47.4%) by 19.2 points, while also outperforming GPT-4V (16.2%). As a vision-based agent (MLLM○AGG), the method achieves 75.8% success rate on MiniWob (45-task split), 62.2% overall action matching on AITW with 68.1% click accuracy, and 41.2% element accuracy on Mind2Web cross-task (vs. 28.3% for SeeClick). On OmniAct-Desktop, the agent scores 27.2 Action Score with 62.4% grounding accuracy, outperforming SeeClick (23.8 / 55.2%).

## Baselines & Comparisons

AGG decisively outperforms all generalist MLLMs (MiniGPTv2, Qwen-VL, Phi-3.5-V, GPT-4V) on ScreenSpot, with the largest gap over GPT-4V (66.6 vs. 16.2 avg), confirming that GUI grounding requires domain-specific training. Among GUI-specific MLLMs, AGG beats SeeClick by 13.2 points (66.6 vs. 53.4) and CogAgent by 19.2 points (66.6 vs. 47.4) on ScreenSpot, while using 24× fewer parameters than SeeClick. On agent tasks, MLLM○AGG surpasses SeeClick on MiniWob (75.8 vs. 73.6), AITW (62.2 vs. 59.3 overall; 68.1 vs. 66.4 click accuracy), and Mind2Web (41.2 vs. 28.3 cross-task element accuracy), and also outperforms Pix2Act (69.3 vs. 55.2 on MiniWob 35-task) and CC-Net (75.8 vs. 36.5 on MiniWob 45-task). However, AGG loses to WebGUM (86.1 vs. 75.8 on MiniWob 45-task) which leverages both HTML and image inputs with 347K training episodes, and to SeeAct(Choice) on Mind2Web element accuracy (46.4 vs. 41.2 cross-task) which uses text candidates from a ranking LM as an easier multiple-choice formulation. On OmniAct-Desktop, AGG outperforms both SeeClick (27.2 vs. 23.8 Action Score) and SoM (27.2 vs. 17.6), with SoM's label-marking approach failing to identify interactive elements in desktop screenshots.

## Relation to Prior Work

This paper builds on SAM's ViT image encoder and decoder design principles for the grounding module, and adopts LISA's 'embeddings-as-position' paradigm (a special <|POS|> token whose hidden state is projected into a separate grounding head) for integrating the grounding model with an MLLM. It departs from prior GUI agent approaches (SeeClick, CogAgent, Fuyu) that use end-to-end pure-Transformer MLLMs to predict bounding boxes, instead proposing a modular architecture where a lightweight 0.4B grounding model handles precise localization while the MLLM handles reasoning and planning. The paper also introduces a substantially larger automated data collection engine (0.5M screenshots, 35M element annotations) compared to prior GUI grounding datasets like SeeClick (0.3M/3.0M), sourced from Common Crawl with GPT-4-guided topic selection and query augmentation.

## Why It Matters / Open Questions

The paper identifies GUI element grounding as the primary bottleneck for vision-based GUI agents and demonstrates that a small, dedicated grounding module consistently outperforms much larger end-to-end MLLMs across ScreenSpot, MiniWob, AITW, and Mind2Web, validating the modular reasoning-grounding separation. However, the model still lags behind text-based agents (e.g., SeeAct-Choice, MindAct) on Mind2Web, and error analysis reveals persistent struggles with platform-specific icons, ambiguous queries, and long-tail element categories. Open questions include whether the gap to text-based agents can be closed with purely visual approaches, how to handle identical-named elements that text-candidate methods also fail on, and whether the data scaling trend (diminishing returns beyond 75%) indicates a ceiling for the current collection strategy.
