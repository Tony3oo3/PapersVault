## Problem

Existing multi-LoRA serving frameworks (PEFT, S-LoRA) require explicit user or system instructions to select which adapter to activate, and LoRA fusion methods (LoRAHub, MoA) lack the capacity to handle dynamic adapter switching during inference for composite tasks. This paper addresses the gap of enabling autonomous, on-demand LoRA selection and timely switching across multiple embedded adapters without any explicit task intention specification.
![Teaser figure](../imgs/ICLR20251980/cropped_page1_idx0.webp)

## Input / Output

The method takes a base LLM (LlaMA2-13B or LlaMA3-8B) with n off-the-shelf LoRA adapters (28 in experiments) and a text prompt, producing a generated text response. The LoRA adapters are frozen and reused as-is; only the lightweight Gating networks are trained. For composite task evaluation, multiple independent sub-tasks are concatenated into a single 'paper sheet' input, and the model must sequentially generate numbered answers for each sub-task in one inference pass using a 2-shot setting.

## Method

MeteoRA injects a trainable Gating network G: R^d → R^n into every linear layer (Q, K, V, O in attention; up_proj, gating, down_proj in MLP) of the base LLM, forming a full-mode MoE architecture where each token is routed to the top-k LoRA adapters via softmax-normalized gating weights. Training freezes both the base LLM and all LoRA adapters, optimizing only the Gating networks with a joint loss combining autoregressive language modeling and per-module LoRA classification cross-entropy. To address the efficiency bottleneck of naive MoE forward (up to 10× slowdown with 28 experts), the paper introduces two acceleration strategies: bmm-torch (batched matrix multiplication in PyTorch, ~4× speedup) and bmm-triton (custom Triton GPU kernel using blocking and masking to handle small LoRA ranks, maintaining low memory while retaining ~80% of bmm-torch's speed). The two methods are deployed complementarily—bmm-triton for the prefill phase (variable sequence length) and bmm-torch for decoding (s=1).

## Results

On 28 diverse NLP tasks using LlaMA2-13B and LlaMA3-8B base models, MeteoRA (top-1, 1k gate training samples) achieves 0.755/0.811 average accuracy, matching the PEFT reference (0.762/0.817) within 0.4% on LlaMA3-8B while requiring no explicit task selection. On composite-10 tasks (10 sequential sub-problems in one inference pass), MeteoRA (top-2) answers 3.75 questions correctly on average versus 2.95 for LoRA-B, and attempts 8.24 out of 10 questions versus 6.07. The forward acceleration strategies (bmm-torch and bmm-triton) achieve ~4× speedup over the naive loop-original MoE forward, reducing the overhead to ~2.5× single-LoRA inference.

## Baselines & Comparisons

MeteoRA (T1-1k) nearly matches the PEFT reference model (0.755 vs 0.762 accuracy on LlaMA2-13B; 0.811 vs 0.817 on LlaMA3-8B) without requiring explicit task-intention selection, a key practical advantage. Against LoRA merge baselines, MeteoRA dominates: it outperforms Arrow (0.569/0.647) by ~19/16 points, TIES (0.388/0.441) by ~37/37 points, DARE (0.332/0.404) by ~42/41 points, Avg Merge (0.370/0.427) by ~39/38 points, and LoraHub (0.307/0.235) by ~45/58 points in accuracy. Against the single-LoRA baselines, MeteoRA (T1-1k) beats LoRA-F (0.730/0.767) by 2.5/4.4 points and LoRA-B (0.666/0.750) by 8.9/6.1 points in accuracy. On composite tasks, MeteoRA (top-2) substantially outperforms LoRA-B: on composite-10 it answers 3.75 vs 2.95 questions correctly and achieves 0.238 vs 0.161 average ROUGE-1, demonstrating its advantage in timely adapter switching across sequential sub-problems.

## Relation to Prior Work

MeteoRA sits at the intersection of LoRA-based parameter-efficient fine-tuning (Hu et al., 2021) and sparsely-gated Mixture-of-Experts routing (Shazeer et al., 2017), repurposing the MoE gating mechanism to select among pre-trained LoRA adapters rather than learned expert sub-networks. It departs from serving frameworks like HuggingFace PEFT and S-LoRA, which require explicit task-intent specification to activate the correct adapter, and from LoRA fusion methods (LoRAHub, TIES, DARE, Arrow) that statically merge adapter weights and cannot perform dynamic mid-inference switching. Unlike MixLoRA, which restricts MoE routing to the MLP module, MeteoRA applies a full-mode MoE to all seven linear layers (Q, K, V, O, up_proj, gating, down_proj), enabling per-layer, per-token adapter selection that supports timely switching across composite task sequences.

## Why It Matters / Open Questions

The framework offers a practical path to deploying a single LLM that autonomously handles 28+ heterogeneous tasks without user-specified adapter selection, with the composite-task evaluation (10 sequential problems in one pass) demonstrating a capability no prior LoRA-serving or fusion method has shown. Key limitations temper the impact: the gating network must be retrained whenever any embedded adapter is updated (a domain-shift problem), knowledge-fusion tasks (e.g., foreign-language math) do not clearly benefit over single-adapter baselines, and the MoE forward pass remains ~2.5× slower than single-LoRA inference despite the proposed BMM/Triton accelerations. Open questions include whether the approach scales gracefully beyond ~30 adapters, whether the gating can be made robust to adapter updates without full retraining, and whether more efficient CUDA kernels can close the remaining efficiency gap.
