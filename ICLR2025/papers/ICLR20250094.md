## Problem

Existing CodeLLM benchmarks (HumanEval, MBPP, CodeContests) focus almost exclusively on open-ended code generation, making it impossible to distinguish whether a model genuinely understands code or merely reproduces memorized training data. Moreover, reliance on test-case executability limits benchmark diversity and scale, while LLM-as-a-judge approaches for free-form evaluation introduce their own reliability concerns. CodeMMLU addresses this by introducing a large-scale multiple-choice benchmark that directly probes code comprehension, reasoning, and software engineering knowledge across 52 topics and 10+ programming languages.

## Input / Output

Each question presents a code snippet or programming scenario alongside a natural-language prompt and four answer options (A–D); the model must output the single correct letter, extracted via simple regex (matching 'A|B|C|D' or 'answer is X'). The benchmark comprises ~20,000 questions split into knowledge-based tests (syntactic and semantic, ~11,000 items) and fundamental coding-skill tests (code completion, fill-in-the-blank, code repair, execution prediction, ~8,900 items). To probe selection bias, the same questions are re-evaluated with the golden answer permuted across positions A through D, and performance is reported as accuracy per task and per subject category.

## Method

CodeMMLU is constructed through a two-track pipeline. The knowledge-based track crawls MCQs from W3Schools, GeeksforGeeks, and Common Crawl, then applies rule-based HTML cleaning, LLM-based quality scoring (completeness, coherence, coding relevance via GPT-3.5, Llama3.1-8B, and Mixtral-8×7B with a threshold of 4/5), and MinHash LSH deduplication (256 permutations, 0.8 similarity threshold), retaining ~74% of raw data. The fundamental-skill track transforms existing codebases—HumanEval (code completion), LeetCode (fill-in-the-blank), QuixBugs (code repair), and IBM CodeNet (execution prediction)—into MCQs by using LLMs to generate plausible but incorrect distractors, which are then verified through execution to ensure they pass 0–50% of test cases. Evaluation covers 43 LLMs from 15 families under zero-shot, few-shot, and Chain-of-Thought prompting, with answer-order permutation analysis to quantify selection bias and perplexity/n-gram checks to assess data contamination.

## Results

Across 40+ LLMs from 13+ families, GPT o3-mini achieves the highest overall CodeMMLU accuracy at 62.36%, followed by Claude 3.7 Sonnet (61.65%) and GPT-4o (56.40%). Among open-source models, Llama3.1 405B Instruct leads at 58.23%, while the 671B DeepSeek-R1 reasoning model underperforms its base model DeepSeek-V3 (43.91% vs. 49.08%). A key finding is that Chain-of-Thought prompting consistently degrades performance across nearly all models, and models exhibit strong selection bias with accuracy fluctuating up to 37% depending on the correct answer's position (A–D).

## Baselines & Comparisons

The most striking comparison is between HumanEval (open-ended code generation) and CodeMMLU's MCQ code completion task on the *same* 164 questions: models that pass HumanEval frequently fail to select the correct answer among four options, and vice versa (Figure 7). For example, CodeLlama-7B-Python scores 40.48% on HumanEval but drops to 0.00% when the correct answer is placed at position A in the MCQ format (Table 4), while CodeLlama-7B-Instruct swings from 45.65% (HumanEval) to 93.90% when the answer is at position C. Against MMLU and MBPP (Table 7), CodeMMLU produces substantially different model rankings — e.g., Claude-3 Sonnet drops from rank 1 on HumanEval to rank 4 on CodeMMLU, while GPT-4o rises from rank 2 to rank 1 — indicating that code-generation benchmarks overestimate comprehension. The paper also shows that perplexity and 5-gram accuracy analyses (Tables 5–6) confirm CodeMMLU has significantly lower data-contamination risk than CodeScope and CodeApex, with perplexity scores 2–10× higher across all tested models.

## Relation to Prior Work

CodeMMLU is directly inspired by MMLU's multiple-choice format for natural language understanding, transposing it to the code domain where prior benchmarks (HumanEval, MBPP, CodeXGLUE, CRUXEval, LiveCodeBench) have focused almost exclusively on open-ended code generation or execution-based evaluation. The paper departs from this lineage by arguing that generation performance conflates memorization with genuine comprehension, and instead constructs a ~20,000-question MCQ benchmark spanning 52 topics and 10+ languages, drawing seed data from W3Schools, Common Crawl, HumanEval, QuixBugs, LeetCode, and IBM CodeNet. It also builds on the MCQ selection-bias literature (Zheng et al., 2024a; Robinson et al., 2023) by explicitly measuring and reporting answer-order sensitivity as a first-class evaluation axis.

## Why It Matters / Open Questions

CodeMMLU provides a scalable, low-cost evaluation that decouples code understanding from code generation, revealing that strong HumanEval performers do not reliably transfer to MCQ comprehension tasks and that even GPT-4o and Claude 3.5 Sonnet plateau around 60–62% overall accuracy. The finding that Chain-of-Thought prompting consistently degrades performance across most models (with the notable exception of GPT o3-mini) challenges the prevailing assumption that eliciting longer reasoning chains improves code-domain performance, pointing to an open question about when and how reasoning should be applied. Limitations include the MCQ format's inherent selection bias (mitigated but not eliminated by permutation), the reliance on web-crawled knowledge questions whose difficulty distribution may not reflect real-world engineering, and the absence of repository-level or multi-file reasoning tasks.
