## Problem

KV cache memory grows linearly with input length, becoming the primary bottleneck for deploying long-context LLMs. Existing token-dropping methods (H2O, SnapKV, StreamingLLM) irreversibly discard tokens deemed unimportant, which fails when future queries target information outside the main theme or in multi-round conversations. The paper asks whether KV cache can be reduced without losing any semantic information from the original context.

## Input / Output

The method operates on the KV cache of a standard Transformer LLM (RoPE or ALiBi positional encoding) during inference, taking the full sequence of key-value pairs per attention head as input. It produces a head-wise compressed KV cache where retrieval heads retain all tokens, non-retrieval heads retain only the most recent L_h tokens plus N_0 attention sink tokens plus one compensation token, and the model then generates output tokens using this compressed cache. The compression is applied per-head and is fully compatible with FlashAttention, requiring no access to the attention map during inference.

## Method

RazorAttention exploits the observation that only ~15% of attention heads (retrieval heads) can effectively attend to the full input, while the rest focus on local context. For ALiBi models, a theorem analytically bounds each head's effective attention scope L_h from its slope parameter and weight norms, directly determining which tokens can be safely dropped. For RoPE models, retrieval heads are identified data-free by generating repeated random tokens and selecting the top-14% induction heads (attending to the token that follows the current token in prior context) and top-1% echo heads (attending to a prior occurrence of the current token). For non-retrieval heads, dropped remote tokens are compressed into a single compensation token defined as the element-wise mean of their key and value vectors, which is appended to the retained cache. This compensation token provably reduces the attention output error from the truncated cache, and the entire procedure is training-free, plug-and-play, and FlashAttention-compatible.

## Results

On LongBench (16 subtasks), RazorAttention achieves average scores within 0.2–0.6 points of the full-KV baseline across four models: Qwen1.5-7B (35.87 vs 36.03), Qwen1.5-8B-Instruct (45.97 vs 46.15), Llama3-8B-Instruct (34.86 vs 35.44), and Baichuan2-13B (36.45 vs 36.41), all under a 3.125× KV cache compression ratio. On Needle in a Haystack with Llama2-7B-80K, RazorAttention retains near-perfect retrieval accuracy while H2O degrades to unusable levels. On the 1024K Needle in a Haystack task with GLM-9B-1M, RazorAttention achieves nearly lossless accuracy at 50% KV cache compression. Efficiency gains include up to 71.8% throughput improvement at 256K input length on 8 Ascend 910B NPUs.

## Baselines & Comparisons

RazorAttention outperforms StreamingLLM by a wide margin on LongBench (e.g., 35.87 vs 17.00 on Qwen1.5-7B, a ~19-point gap), as StreamingLLM's fixed sliding window discards all remote context. Against H2O, RazorAttention achieves comparable LongBench averages (within 0.2–2.5 points) but decisively wins on Needle in a Haystack: H2O produces garbled outputs (e.g., '!!!!!!') for queries about less theme-relevant information, while RazorAttention retrieves the exact answer even at 70% compression. Against SnapKV, RazorAttention demonstrates superior robustness in query-agnostic settings where SnapKV's performance degrades significantly because it relies on predefined queries to select which tokens to keep; RazorAttention's head-wise strategy is query-independent. Additionally, RazorAttention is compatible with FlashAttention (enabling substantial inference speedup), whereas H2O requires materializing the full attention map for importance scoring and is incompatible with FlashAttention, leading to OOM errors on longer sequences.

## Relation to Prior Work

RazorAttention builds on the interpretability finding from Olsson et al. (2022) and Wu et al. (2024) that a small subset of attention heads (induction heads) can recall information from long inputs, but is the first to operationalize this into a head-wise KV cache compression criterion. It departs fundamentally from the dominant token-dropping paradigm (H2O, StreamingLLM, SnapKV) by preserving all token information in retrieval heads while compressing only non-retrieval heads, and introduces a compensation token mechanism to recover information lost in the truncated cache. Unlike importance-based methods that require attention weights and are incompatible with FlashAttention, RazorAttention's head-wise pruning is fully compatible with FlashAttention, making it a plug-and-play solution for production inference.

## Why It Matters / Open Questions

KV cache memory is the primary bottleneck for deploying long-context LLMs, and RazorAttention's 70% reduction with near-lossless accuracy across multiple architectures (ALiBi, RoPE, GQA) and scales (8K to 1024K tokens) offers a practical, training-free path to significantly cheaper inference. The open questions include why attention heads specialize so differently, whether the compression ratio can be pushed further, and whether the optimal retrieval-head fraction (14% induction + 1% echo) generalizes across all model families without per-model tuning. The FlashAttention compatibility is particularly impactful since it unblocks a class of compression methods that were previously impractical in production serving stacks.
