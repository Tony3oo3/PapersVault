## Problem

Despite extensive research on automated test generation, existing benchmarks for evaluating LLMs on software testing are limited to small, self-contained programs and lack real-world scale. No benchmark measures test completion (adding tests to an existing suite), and none reports mutation score—the metric most correlated with actual fault detection—despite its importance in practice.
![Teaser figure](../imgs/ICLR20250541/cropped_page1_idx0.webp)

## Input / Output

For full test generation, the model receives a single Python source file (averaging 782 LOC) from a real-world repository and must output a complete unit test file. For test completion, the model receives both the source file and a partial test file (with the first, last, or an additional test removed) and must generate the missing test method. Evaluation is execution-based: generated tests are run inside per-repository Docker containers, and metrics include pass@1/pass@5, line coverage of the source file, and mutation score computed via cosmic-ray synthetic bug injection.

## Method

TESTGENEVAL is constructed by adapting SWE-bench Docker images: the authors install coverage and mutation-testing dependencies, extract code-test file pairs via filename heuristic matching, and filter pairs where gold tests do not cover the source or exceed a 60-second runtime. The benchmark comprises 1,210 file pairs (68,647 tests) across 11 well-maintained Python repositories (3,523–78,287 stars), with a 160-pair TESTGENEVAL-LITE subset for low-compute iteration. Two tasks are defined—full-file test suite generation and test completion at three positions (first, last, extra)—and models are evaluated on execution-based metrics including pass@k, code coverage, and mutation score. The paper evaluates 10 open- and closed-source LLMs (7B–405B parameters) and finds that even the best model (GPT-4o) achieves only 35.2% average coverage and 18.8% mutation score, with the primary failure mode being incorrect reasoning about code execution and assertion errors on complex code paths.

## Results

On TESTGENEVAL's full test suite generation task, GPT-4o achieves the highest coverage (35.2%) and mutation score (18.8%), while Llama 3.1 405B is close behind at 35.0% coverage and 16.4% mutation. Codestral 22B leads in pass rates (72.7% Any Pass@1, 26.8% All Pass@1) but trails GPT-4o on coverage and mutation quality. All models struggle substantially: even the best model covers only 35.2% of lines and detects only 18.8% of synthetic bugs, far below the ~80% coverage achieved by human-written gold test suites.

## Baselines & Comparisons

GPT-4o outperforms Llama 3.1 405B on coverage (35.2% vs. 35.0%) and mutation score (18.8% vs. 16.4%), indicating higher per-test quality, but Llama 3.1 405B substantially outperforms GPT-4o on All Pass@1 (17.7% vs. 7.5%) and Any Pass@1 (73.1% vs. 64.0%), reflecting GPT-4o's tendency to generate more verbose test suites with more errors. Codestral 22B achieves the highest Any Pass@1 (72.7%) and All Pass@1 (26.8%) among medium models, surpassing DeepSeekCoder 16B (63.7% / 23.0%) and Gemma 27B (57.7% / 7.4%), but still trails GPT-4o on coverage by ~2% and mutation by ~4.6%. Small models (CodeLlama 7B, Gemma 9B, Llama 3.1 8B) perform dramatically worse than their larger counterparts, with coverage ranging from 1.2% to 20.2% versus 30–35% for flagship models. Notably, CodeLlama 70B underperforms even CodeLlama 7B on Any Pass@1 (22.7% vs. 4.1% is reversed—actually 70B is worse at 22.7% vs. 7B at 4.1%), suggesting that scaling within the CodeLlama family does not reliably improve test generation. In test completion, Codestral 22B leads with 74.3% Pass@5 on the last-test setting, outperforming GPT-4o (66.6%) and Llama 3.1 405B (72.3%), though all models add less than 1% new coverage in that setting.

## Relation to Prior Work

TESTGENEVAL builds directly on SWE-bench's infrastructure (docker images, repository selection) but repurposes it for software testing rather than issue resolution. It departs from existing test generation benchmarks (TestEval, SWT-Bench, R2E) that operate on small, self-contained programs or measure adjacent sub-tasks like equivalence test generation and assertion completion, by introducing file-level test suite generation and test completion on large, real-world Python repositories. The inclusion of mutation score as a primary metric is novel for test generation benchmarks, which previously reported only pass@k or coverage, and the paper demonstrates weak correlation with code generation benchmarks like HumanEval, positioning test generation as a distinct capability.

## Why It Matters / Open Questions

This benchmark reveals a substantial gap between test generation performance on small self-contained problems (near 100% coverage on TestEval) and real-world file-level testing (35.2% coverage for GPT-4o), suggesting current LLMs are far from capable of replacing human test writers in complex projects. The finding that models add virtually no new coverage when completing already-complete test suites identifies a specific frontier: reasoning about which untested code paths to target. Open questions include whether longer context, retrieval-augmented approaches, or specialized training can close the coverage and mutation score gap, and whether the weak correlation with code generation benchmarks implies test generation requires fundamentally different model capabilities.
