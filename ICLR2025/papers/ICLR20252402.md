## Problem

The critical batch size (CBS) marks the threshold beyond which increasing data parallelism yields diminishing returns in pretraining, yet no prior work has formally defined CBS or decoupled its dependence on model size from data size. Previous studies either scale model and data proportionally (Chinchilla setting) without isolating each factor, or focus on the optimal batch size for minimum loss rather than the efficiency transition point. This leaves practitioners without a principled scaling law to guide data-parallelism decisions when training duration or model architecture changes independently.

## Input / Output

The method takes autoregressive transformer LMs (85M–1.2B parameters, 512-token context, gpt-neox-20b tokenizer) trained on the C4 corpus, sweeping global batch sizes from 2^6 to 2^14 via gradient accumulation. The key output is a fitted power-law scaling for CBS with respect to data size (B* ≈ 22.91 × D^0.47, D in billions) and model size (B* ≈ 93.20 × N^0.47 in Chinchilla setting, but only B* ≈ 621.341 × N^0.087 when data size is held fixed). A notable design choice is the use of Constant+EWA (exponential weight averaging) instead of a predefined learning-rate schedule, which allows training to continue past a fixed token budget until a target validation loss is reached, avoiding the need to pre-specify total training duration.

## Method

The paper formalizes CBS as the maximum batch size B' > B_opt such that the steps-to-target-loss f(B') ≤ 1.2 × (D/B'), i.e., a 20% overhead relative to linear scaling from the optimal batch size B_opt = 256. Empirically, they train five model sizes on C4 with extensive hyperparameter sweeps (learning rate, momentum β₁, Adam β₂, warmup fraction, EWA decay rate τ) and fit log(Y) = log(a + b/B^α) to derive B* = b/(5a) + 1.2·B_opt per model, then fit a second power law in N or D. Controlled experiments fix either model size (varying tokens at 0.28×, 0.5×, 2×, 4× Chinchilla) or data size (training all models to the 151M target loss) to decouple the two scaling axes. Theoretically, they invoke infinite-width limits (Yang & Hu, 2021) to show CBS is invariant to model width beyond a threshold, and analyze mini-batch SGD on Gaussian linear regression under power-law source/capacity conditions to derive B* ≈ D^(1−a/min{b,2a+1}), confirming CBS grows sublinearly with data size when variance error dominates.

## Results

In Chinchilla-optimal settings (scaling model size N and data size D proportionally), the fitted CBS scaling law is B* = 93.20 × N^0.47, yielding CBS values from ~2^9.5 (85M) to ~2^11.3 (1.2B). When data size is held fixed and only model size is scaled, the exponent drops dramatically to B* = 621.341 × N^0.087, indicating CBS is nearly invariant to model size. When model size is held fixed and data size is scaled, CBS increases with a data-size exponent of ~0.47 (B* = 22.91 × D^0.47, D in billions). The headline finding is that CBS growth in Chinchilla scaling is driven by data size/training duration, not model size.

## Baselines & Comparisons

The paper's primary baselines are alternative learning-rate scheduling strategies used to reach a target validation loss without predefining total training duration. Constant+EWA (the proposed strategy) matches cosine scheduling in efficiency across all batch sizes and outperforms WSD scheduling (Hu et al., 2024), particularly at large batch sizes (≥1024) where WSD shows a clear gap. The schedule-free optimizer (Defazio et al., 2024) is competitive at small batch sizes (≤512) but is significantly worse than Constant+EWA for batch sizes above 1024. These comparisons are important because they validate that the CBS measurements are not artifacts of suboptimal scheduling. The core empirical comparison is between Chinchilla scaling (N and D scaled together, CBS exponent 0.47) and controlled scaling with fixed D (CBS exponent 0.087), demonstrating that the apparent CBS growth with model size in Chinchilla settings is actually driven by the concurrent increase in data size.

## Relation to Prior Work

This paper extends the critical batch size (CBS) literature initiated by McCandlish et al. (2018) and Shallue et al. (2019) by providing the first formal definition of CBS as a measurable quantity and, crucially, by decoupling the effects of model size from data size—something prior batch-size studies (DeepSeek-AI et al., 2024; Besiroglu et al., 2024; Porian et al., 2024) did not attempt. The theoretical analysis builds directly on two threads: the infinite-width limits of neural networks from Yang & Hu (2021), which justify CBS invariance under width scaling, and the benign overfitting framework of Zou et al. (2023) for constant-stepsize SGD in linear regression, which is generalized here to mini-batch SGD to derive CBS scaling with data size. The empirical protocol also departs from prior scaling-law work (Kaplan et al., 2020; Hoffmann et al., 2022) by using exponential weight averaging (EWA) to train beyond fixed durations, enabling target-loss-based evaluation rather than fixed-token-budget evaluation.

## Why It Matters / Open Questions

The practical implication is significant for large-scale pretraining: since CBS grows with data size (exponent ~0.47) but is nearly invariant to model size (exponent ~0.087), practitioners scaling up training data can safely increase data parallelism to reduce serial training time without incurring FLOPs overhead. The EWA technique offers a simple, practical alternative to cosine or WSD scheduling that eliminates the need to predefine training duration—a non-trivial advantage in iterative pretraining pipelines. Open questions include whether the scaling exponents hold beyond 1.2B parameters and the C4 dataset, whether the linear-regression theory transfers to the nonlinear, over-parameterized regime of real transformers, and how the results change under different parallelism strategies (e.g., pipeline or tensor parallelism) where communication costs interact with batch size.
