## Problem

While chain-of-thought (CoT) prompting has become standard for improving LLM outputs, its exact mechanics and efficacy in multi-turn code generation—particularly on competitive programming benchmarks requiring algorithmic reasoning—remain under-explored. The trade-off between single-turn repeated sampling and multi-turn self-repair, the optimal allocation of compute between turns, and the role of execution feedback granularity are all unresolved questions that this paper systematically investigates.
![Teaser figure](../imgs/ICLR20251435/cropped_page1_idx0.webp)

## Input / Output

The method takes a competitive programming problem (natural language statement plus public test cases) as input and produces Python code solutions. In the multi-turn setting, each subsequent turn additionally receives execution feedback from the runtime environment (ranging from a binary pass/fail indicator to detailed LDB debugger output with intermediate variable values). Evaluation uses the pass n@k metric rather than pass@k to fairly account for the higher generation cost of multi-turn trajectories, with n submissions selected based on public test performance out of k total code samples. Sampling uses nucleus sampling (top-p=0.95, temperature 1.0) to encourage output diversity across trajectories.

## Method

The paper proposes a unified framework that decomposes the prompting space into three orthogonal components: reasoning prompts (NL→NL, eliciting problem understanding before code), instruction prompts (NL→Code, guiding code style and modularity), and execution feedback prompts (varying in granularity from binary to LDB debugger info). A comprehensive grid search over 8 reasoning × 6 instruction prompts × 4 feedback types is conducted across Llama 3.0/3.1 (8B, 70B, 405B) and GPT-4o on CodeContests and TACO benchmarks. The key inference strategy is CoT-retry, which adaptively applies reasoning prompts only when the first code attempt fails, providing up to +6% improvement over always-on CoT. For training, the paper introduces Rejection Sampling Fine-tuning (RFT) on multi-turn CoT trajectories: correct trajectories are collected with CoT enabled, the CoT prompts are stripped from the data, and the model is fine-tuned with standard next-token prediction, effectively internalizing the reasoning behavior so that the RFT model outperforms all prompting configurations even without explicit CoT at inference time.

## Results

On CodeContests test set with high temperature (1.0) and large sampling budgets, multi-turn CoT (CoT-retry with 3 turns and failed-tests feedback) improves pass n@k by up to +11.2% over the single-turn baseline (e.g., Llama 3.0 70B: 23.1→34.3 on pass 33@100; Llama 3.1 70B: 49.8→55.3 on pass 33@100). Rejection Sampling Fine-Tuning (RFT) on multi-turn CoT trajectories further lifts Llama 3.1 70B to 61.1 on pass 100@300, surpassing all prompting-only configurations. In the small-sampling regime (temperature 0.2, pass 1@3), multi-turn CoT improves GPT-4o from 27.6→31.5 (+3.9), Llama 3.1 70B from 27.3→31.5 (+4.2), and Llama 3.1 405B from 32.9→40.1 (+7.2).

## Baselines & Comparisons

The paper's primary comparison is between its own prompting/finetuning variants (single-turn, +CoT, +Multi-turn, +Multi-turn CoT, +RFT) rather than against external methods, but it directly benchmarks against LDB (Zhong et al., 2024) as an execution-feedback baseline. On CodeContests test set (3-turn trajectories), the paper's simpler 'failed tests' feedback outperforms LDB's detailed debugger feedback: Llama 3.1 70B achieves 29.5 vs. 26.5 on pass 1@3 and 56.2 vs. 54.8 on pass 100@300; Llama 3.1 8B achieves 10.9 vs. 9.9 on pass 1@3 and 29.5 vs. 29.1 on pass 100@300. The authors attribute LDB's underperformance to its fine-grained feedback inducing exploitative (low-diversity) behavior that hurts large-sample performance. Multi-turn alone (without CoT) provides only modest gains (<2%) and sometimes degrades performance relative to single-turn repeated sampling, particularly for 8B models. The combination of multi-turn with CoT-retry consistently outperforms both single-turn CoT and multi-turn without CoT across all model sizes and sampling budgets, with the largest gains on harder problems and larger models.

## Relation to Prior Work

This paper carves new ground by systematically decomposing the fragmented landscape of code generation prompting into three orthogonal axes—reasoning prompts, instruction prompts, and execution feedback prompts—and evaluating their interactions in a unified multi-turn framework. It departs from prior self-repair work (Olausson et al., 2024; Shinn et al., 2023; Zhong et al., 2024) by moving beyond simple benchmarks to competitive programming, where algorithmic reasoning dominates over bug-fixing, and by using pass n@k to fairly account for multi-turn compute costs. The RFT component builds on rejection sampling fine-tuning from the Llama training pipeline but applies it to multi-turn CoT trajectories, a data type not previously explored for internalizing reasoning behavior.

## Why It Matters / Open Questions

The paper provides practitioners with clear, well-evidenced guidance: multi-turn alone is often worse than repeated single-turn sampling, CoT-retry (reasoning only after failure) is the key combination that consistently helps, and simple execution feedback outperforms detailed debugging information due to diversity preservation. The RFT result—that multi-turn reasoning traces can be internalized so the model reasons without explicit prompts at inference—opens a path to reducing inference cost while retaining reasoning quality. Open questions include whether these findings extend to repository-level code agents, whether branching/tree search structures at later turns help, and whether process-reward models could improve trajectory filtering beyond the assumption that correct final code implies correct reasoning.
