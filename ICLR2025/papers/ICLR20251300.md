## Problem

Existing LLM-based multi-agent frameworks suffer from three fundamental limitations: ecosystem isolation (only supporting agents defined within their own framework), single-device simulation (inability to model agents distributed across multiple devices), and rigid communication (hard-coded pipelines, agent grouping, and state transitions). These constraints prevent the seamless integration of diverse third-party agents and limit adaptability to dynamic task requirements.
![Teaser figure](../imgs/ICLR20251300/cropped_page2_idx0.webp)

## Input / Output

The system takes a task description as the initial input, along with registered agent capability profiles (free-text descriptions of skills and expertise) stored in a server-side registry. Agents receive heterogeneous inputs depending on their role: tool outputs (web pages, code execution results, video transcripts), environmental observations (for embodied tasks), or evidence pools from different sources (Wikipedia vs. Google for RAG). Outputs are structured through a JSON-based message protocol with fields for state transitions, next-speaker selection, task assignments, and conclusions; the final deliverable is a task completion result, final answer, or action plan produced in the conclusion state of the conversation flow.

## Method

IoA introduces an instant-messaging-app-like architecture with a central server (managing agent registration via a Milvus vector database, session management, and message routing over WebSocket) and client wrappers that expose a minimal integration protocol (a single `run(task_desc) -> str` function) to third-party agents. Two key mechanisms drive collaboration: (1) autonomous nested team formation, where agents dynamically search for collaborators via semantic matching on capability descriptions and recursively spawn sub-group chats, forming a tree-like hierarchy that reduces communication complexity from O(n²) to a sum over sub-groups; and (2) autonomous conversation flow control, modeled as a finite state machine with five states (discussion, synchronous task assignment, asynchronous task assignment, pause & trigger, conclusion) where the LLM within each client autonomously decides both the next state transition and the next speaker based on the accumulated message history. The framework is evaluated across four heterogeneity dimensions—tools, architecture, observation/action spaces, and knowledge—demonstrating that even basic ReAct agents or a fine-tuned Llama 3 8B communication layer can orchestrate heterogeneous agents to outperform standalone SoTA systems.

## Results

On the GAIA benchmark, IoA with four basic ReAct agents achieves 40.00% overall accuracy, surpassing AutoGen (39.39%), FRIDAY (34.55%), and GPT-4+Plugins (14.60%), with particularly strong gains on Level 2 (40.70% vs. 38.37% for AutoGen) and Level 3 (15.38% vs. 11.54%). On the open-ended instruction benchmark, IoA achieves a 76.5% win rate against AutoGPT and 63.4% against Open Interpreter. In RAG tasks, IoA with GPT-3.5-turbo and 3 homogeneous agents reaches 0.671 overall accuracy, exceeding GPT-4 (0.611) and Apollo's Oracle (0.597). On RoCoBench, IoA achieves perfect success rates (1.00) on Cabinet, Sandwich, and Sort tasks, outperforming Roco Dialog in 4 of 5 tasks.

## Baselines & Comparisons

IoA outperforms AutoGen (39.39%) on GAIA overall (40.00%), with the gap widening on harder levels (Level 3: 15.38% vs. 11.54%), attributed to IoA's ability to assign different tools to different agents rather than having one agent use all tools. Against standalone agents, IoA achieves a 76.5% win rate over AutoGPT and 63.4% over Open Interpreter on the open-ended instruction benchmark, demonstrating that collaborative orchestration of heterogeneous architectures yields substantial gains. On RoCoBench, IoA surpasses Roco Dialog in 4 of 5 tasks (e.g., Cabinet: 1.00 vs. 0.75; Sort: 1.00 vs. 0.70) and matches or exceeds the oracle Central Plan on most tasks, despite requiring slightly more steps. In RAG, IoA with GPT-3.5-turbo (0.671 overall, 3-agent homogeneous) exceeds GPT-4 (0.611), Apollo's Oracle (0.597), Multi-Agent Debate 2 (0.529), and Self-Consistency (0.514), while the 2-agent heterogeneous configuration (0.610) matches GPT-4 and outperforms Apollo's Oracle on NQ (0.708 vs. 0.662) and 2WMHQA (0.449 vs. 0.350). IoA also outperforms all single-model baselines including Zero-Shot CoT (0.490), Reflexion (0.495), and Multi-Agent Debate 1 (0.507) on the RAG overall metric.

## Relation to Prior Work

IoA draws on multiple threads: conventional MAS research on agent communication languages (KQML, FIPA-ACL) and coalition formation, distributed systems concepts (service discovery, WebSocket-based messaging), and Speech Act Theory for structuring conversation states. It departs from existing LLM-based multi-agent frameworks (AutoGen, MetaGPT, AgentVerse, CrewAI, CAMEL) by addressing three limitations they share: ecosystem isolation (only supporting agents defined within their own framework), single-device simulation, and hard-coded communication pipelines. The finite-state-machine approach to conversation flow control builds on recent work showing LLMs can manage state transitions (SMoT, StateFlow), while the nested team formation mechanism extends coalition formation ideas from classical MAS to the LLM-agent setting.

## Why It Matters / Open Questions

IoA provides a concrete, deployable architecture for the increasingly important problem of orchestrating independently developed, heterogeneous agents across devices — a scenario that will become more common as smaller LLMs enable local agent deployment. The cost analysis revealing that ~50% of communication tokens are wasted on repetitive rephrasing is a useful negative finding that highlights a fundamental misalignment: LLMs are optimized to be helpful chatbots, not efficient multi-agent communicators. Open questions include whether the communication overhead scales favorably with team size, whether the autonomous flow control can be made more reliable (the paper shows LLMs sometimes fail to switch to pause-and-trigger states), and whether the framework's advantages persist as individual agents become more capable.
