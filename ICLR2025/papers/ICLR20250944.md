## Problem

Vision-based 3D driving perception models are highly sensitive to camera configuration changes (intrinsics, extrinsics, placement), causing severe performance degradation when deployed on different vehicle platforms. No systematic framework existed for generalizing multi-camera 3D perception across varying sensor setups without retraining, making cross-platform deployment impractical.
![Teaser figure](../imgs/ICLR20250944/cropped_page1_idx0.webp)

## Input / Output

The method takes multi-view RGB images (1600×900) from J cameras with known intrinsics and extrinsics, and produces unified virtual camera views (K views) that serve as standardized input to downstream 3D perception networks, ultimately yielding 3D bounding boxes for 6 object classes. The virtual views are generated via geometric warping rather than learned features, making the module resolution-agnostic and compatible with any existing BEV-based detector. All experiments use CARLA-generated data in nuScenes format with 500 scenes (20,000 frames) per configuration.

## Method

UniDrive deploys a fixed set of K virtual cameras and projects original multi-view images into these unified virtual views using a ground-aware depth assumption: pixels whose back-projected 3D point falls within distance D0 of the optical center are assumed on the ground plane, while farther pixels are assumed on a cylindrical surface at radius D0. Each virtual pixel is mapped to a 3D point in the virtual camera frame, transformed to world coordinates, then re-projected into each original camera to sample the source image; all J warped views are blended via angular-distance-weighted averaging. The virtual camera parameters (intrinsics and extrinsics) are optimized via CMA-ES to minimize a weighted angular reprojection error computed over 3D bounding box corners across all target configurations. The entire pipeline is a plug-and-play preprocessing stage that can be inserted before any existing 3D perception network (validated with BEVFusion-C) without modifying the downstream architecture.

## Results

On the CARLA multi-camera benchmark, UniDrive (plugged into BEVFusion-C) achieves 68.8% mAP on the training configuration (5×70°+110°) and maintains 58.9–69.4% mAP across all seven other camera configurations, compared to BEVFusion-C which collapses to 0.5–9.2% mAP on most cross-configuration tests. The largest single improvement is on the 6×60° configuration, where UniDrive scores 63.1% mAP versus 9.2% for BEVFusion-C (a 53.9-point gain). Even on the most challenging 8×50° configuration, UniDrive retains 58.9% mAP while BEVFusion-C drops to 0.5%.

## Baselines & Comparisons

The paper compares against a single baseline, BEVFusion-C (the camera-only variant of BEVFusion, ICRA 2023), which is a representative multi-camera 3D detector used on leaderboards such as nuScenes and Waymo. UniDrive wins decisively on every cross-configuration test: where BEVFusion-C's mAP typically falls below 10% when the test configuration differs from the training one (e.g., 4.9% on 4×95°, 0.5% on 8×50°), UniDrive sustains 58–69% mAP, a gap of 50–60 points. On the same-configuration setting, UniDrive also improves mAP by roughly 4–5 points (e.g., 68.8% vs. 63.9% on 5×70°+110°), indicating the virtual-camera projection adds value even without a domain shift. The one configuration where BEVFusion-C performs relatively well cross-domain (6×70°, 67.5% mAP) is the closest in intrinsics to the training config, and UniDrive still edges it out at 68.4%. Overall, UniDrive transforms a method that is essentially unusable across camera configurations into one with only 1–10% mAP degradation, validating the plug-and-play virtual-camera projection as a robust solution to sensor-configuration variability.

## Relation to Prior Work

This paper positions itself at the intersection of BEV-based 3D perception (building on the Lift-Splat-Shoot paradigm and BEVFusion-C as the detection backbone) and domain generalization, but carves new ground by framing camera-configuration variability as the specific domain shift to address. Rather than learning domain-invariant features or using adversarial alignment (as in prior cross-domain 2D/3D detection work), it repurposes the geometric camera projection pipeline in reverse—warping 2D images through a 3D intermediate into a unified virtual camera space—making it a plug-and-play preprocessing module. The CMA-ES-based virtual configuration optimization borrows from evolutionary computation to find a single virtual rig that minimizes expected reprojection error across multiple real rigs, a formulation not previously applied to sensor generalization.

## Why It Matters / Open Questions

The practical motivation is strong: deploying a single perception model across different vehicle platforms without retraining is a real industrial bottleneck, and the paper demonstrates that a model trained on one camera setup can retain most performance on others. However, all experiments are conducted in CARLA simulation with a single baseline (BEVFusion-C), and the ground-aware depth assumption (ground plane + cylindrical surface) may not generalize to scenes with significant elevation changes or non-planar terrain. Open questions include whether the approach transfers to real-world sensor noise, whether it composes with occupancy prediction or end-to-end planning pipelines, and how it behaves under more extreme configuration changes (e.g., drastically different FOVs or camera counts).
