## Problem

Existing code benchmarks like SWE-bench are dominated by single-file bug fixes from noisy GitHub issues, leaving the unique challenges of multi-file code refactoring largely unevaluated. The paper identifies that LM agents fail at stateful reasoning—tracking and composing their own previous edits across many files—and that current agent interfaces provide no explicit mechanism for maintaining awareness of accumulated state over long trajectories.
![Teaser figure](../imgs/ICLR20251547/cropped_page1_idx0.webp)

## Input / Output

Each task provides a natural language instruction (ranging from 16-word 'lazy' to 116-word 'descriptive' variants) alongside a multi-file Python repository (2,327–6,815 files, 304K–1.8M lines) drawn from 9 popular open-source projects. The agent must produce a multi-file code patch (editing 2–31 files, averaging 4.3) that passes a suite of 2–27 AST-based unit tests checking code structure and syntax rather than exact line matches. The state-aware variant additionally consumes a running natural-language summary of all prior edits as part of its context at each step.

## Method

The paper introduces RefactorBench, a benchmark of 100 handcrafted multi-file refactoring tasks verified through custom AST unit tests that decompose each task into interpretable subtests, with tractability confirmed via GPT-4o during construction. The core technical contribution is a state-aware interface that augments the standard POMDP trajectory with an externally computed state variable σ_N, implemented as a cached section listing all previous file edits (filename, line numbers) appended to the agent's observation before every function call. This is formalized as a state update policy π_state: (τ_N, σ_{N-1}, …, σ_0) → σ_N that generalizes beyond a single agent to entire digital environments, enabling propagation of concurrent external edits. A synthetic experiment demonstrates that GPT-4's accuracy in cumulative state reconstruction degrades linearly with the number of sequential actions, motivating the explicit state conditioning. The state-aware SWE-agent achieves a 43.9% relative improvement in task resolution and 71% in subtask completion over the baseline across all instruction sets.

## Results

On RefactorBench, the prompt-adjusted SWE-agent with GPT-4 resolves only 12% (Lazy), 22% (Base), and 27% (Descriptive) of multi-file refactoring tasks, while a human developer with a 5-minute time limit solves 87% on base instructions. The state-aware SWE-agent (with GPT-4o) achieves a 43.9% relative improvement in task resolution and a 71% increase in subtask completion over the baseline. Updated SWE-agent 1.0 with GPT-4o reaches 21% (Base) and 31% (Descriptive) at a cost of $1.69 per successful instance, confirming that the core difficulty lies in stateful multi-file reasoning rather than single-edit capability.

## Baselines & Comparisons

The primary baseline is a prompt-adjusted SWE-agent with GPT-4, which resolves 22% of base-instruction tasks and 27% of descriptive-instruction tasks. The state-aware variant (SWE-agent modified to condition on a natural-language state summary of all prior edits) achieves a 43.9% relative improvement in full-task resolution and a 71% increase in subtask (AST test) completion across all three instruction sets, demonstrating that the bottleneck is stateful reasoning rather than code generation quality. A human developer given the same base instructions and a 5-minute IDE time limit solves 87% of tasks, highlighting a 65-percentage-point gap between current agents and human performance. The updated SWE-agent 1.0 with GPT-4o (Section 7.3) reaches 21% (Base) and 31% (Descriptive), confirming that the original findings hold with newer agent implementations while reducing per-instance cost to $1.69. No agent solves any task requiring edits to more than 6 files, and combined multi-task instances (3 tasks merged) are solved 0% of the time, indicating a hard ceiling on compositional multi-file planning.

## Relation to Prior Work

This paper extends the SWE-agent framework (Yang et al., 2024) by introducing state-aware interfaces that condition the agent on externally computed representations of accumulated edits, borrowing the state-conditioning paradigm from neural agent design (NetHack diff history, LLM-STATE). It positions itself against SWE-bench's GitHub-issue-based evaluation by arguing that multi-file refactoring is a distinct, underrepresented task requiring different reasoning than bug-fixing, and departs from function-level code benchmarks (HumanEval, CodeGen) by mandating edits across 2–31 files with AST-based structural testing rather than exact-match or test-passing criteria. The three-tier instruction design (lazy/base/descriptive) builds on prior work scaling instruction-following evaluation with lazier prompts (Cassano et al., 2024), while the POMDP formalization follows ToolEmu's treatment of LM agents.

## Why It Matters / Open Questions

The 22% agent vs. 87% human resolution gap on multi-file refactoring exposes a concrete, measurable limitation in current LM agents' stateful reasoning that existing benchmarks like SWE-bench do not isolate. The finding that a simple state-aware interface (tracking prior edits) yields a 43.9% relative improvement suggests a practical, low-cost intervention for agent design, while the identification of context flooding and erroneous intermediate states as distinct failure modes provides actionable diagnostics. Key limitations include Python-only coverage, only 100 tasks, potential training-data contamination from popular repositories, and the acknowledgment that baselines are outdated relative to current SWE-agent versions. Open questions include whether state-aware interfaces generalize to multi-agent concurrent editing, non-Python languages, and whether the approach scales to the longer horizons that combined tasks demand.
