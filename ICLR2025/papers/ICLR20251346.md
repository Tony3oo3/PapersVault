## Problem

Reward models in RLHF exploit spurious correlations (notably output length) in training data, leading to biased rankings, reward hacking, and unreliable LLM evaluations. Existing bias-mitigation strategies require additional data collection, RM retraining, or RL algorithm modifications. This paper asks whether biases can be corrected in a purely post-hoc, training-free manner using only a batch of already-scored outputs.

## Input / Output

The method consumes a batch of scored prompt-response pairs {(x_i, r_θ(x_i))} along with a measurable scalar characteristic of each output (e.g., character length). Because LOWESS requires computing residuals for every fitted point, the entire scored dataset is used for regression rather than a held-out split. The output is a calibrated reward margin Δ̂*_rθ(x₁, x₂) for each pair, from which preference is determined by sign. Calibration of 300k samples completes in ~30 seconds on a single CPU, making it deployable as a drop-in post-processing step before any downstream use (ranking, DPO training, or evaluation).

## Method

The core assumption is that the biased reward decomposes as r_θ(x) = r*_θ(x) + b_c(c(x)), where the bias term depends only on the characteristic c (e.g., length). The bias is estimated non-parametrically via Locally Weighted Regression (LOWESS): a weighted linear regression is fit locally around each characteristic value, with tricube distance-based weights and iterative robustification via residual-based reweighting. The calibrated margin is then Δ̂* = Δ_rθ − (r̂(c(x₁)) − r̂(c(x₂))), subtracting the estimated bias difference. A calibration constant γ ∈ [0,1] can be introduced to smoothly control how much bias is removed, enabling users to preserve desirable correlations (e.g., slightly preferring shorter outputs). The approach is hyperparameter-robust (bandwidth f, threshold d) and generalises to multiple characteristics simultaneously via multi-dimensional LOWESS with Z-score normalisation.

## Results

On RewardBench, RC-LWR-Penalty achieves a 3.11 average performance gain across 33 BT-based reward models, with nine calibrated models surpassing GPT-4-Turbo accuracy. On AlpacaEval, RC-LWR-calibrated GPT-4 rankings achieve 0.975 Spearman correlation with ChatbotArena (Feb.) and 0.951 with ChatbotArena (Aug.), matching or exceeding the Length-Controlled (AE2) baseline. For LLM alignment via DPO, RC-LWR yields up to a 10-point improvement in Length-Controlled win rate (e.g., 70.45 vs. 63.21 for gemma2-9b-GRM) while reducing average output length by ~15–20% and mitigating benchmark performance drops.

## Baselines & Comparisons

Against the Length Penalty baseline (Dong et al., 2024, α=0.001), RC-LWR wins on all three experimental settings: on RewardBench, RC-LWR-Penalty achieves a 3.11 average gain versus the smaller and less consistent improvement from LP alone; on AlpacaEval, RC-LWR reduces Gameability more reliably (e.g., 9.0% vs. 13.6% for internlm2-7b-reward) while LP can even degrade performance for some RMs (e.g., Eurus-RM-7b at 37.8%); and on LLM alignment, RC-LWR outperforms LP in LC win rate for all four configurations (e.g., 51.37 vs. 49.98 for Llama-3-8B-Fsfairx). Against the Length-Controlled (LC) method of Dubois et al. (2024), RC-LWR achieves comparable Spearman correlations with AE2 and ChatbotArena across all 8 open-source RMs, but is more general-purpose since LC requires LLM ID and instruction ID for regression, making it inapplicable to general reward calibration. The paper also notes that LP's fixed penalty weight is sensitive to both reward scale and length-margin distribution, whereas RC-LWR is robust to hyperparameter choices and requires no per-model tuning.

## Relation to Prior Work

This paper departs from the dominant paradigm of bias mitigation in RLHF, which intervenes at data collection (de-biasing datasets), reward model training (ensembles, decoupled heads, multi-expert architectures), or the RL optimization loop (length penalties, constrained objectives). Instead, it repurposes LOWESS — a standard non-parametric regression tool from statistics — as a post-hoc calibration step applied to already-scored outputs, requiring no retraining or additional data. Conceptually, it generalizes the length-controlled regression used in AlpacaEval2 (Dubois et al., 2024) from a leaderboard-specific correction to a general reward calibration framework applicable to any BT-based RM, DPO-based implicit reward, or LLM-as-Judge, and to arbitrary measurable output characteristics beyond length.

## Why It Matters / Open Questions

The method's practical appeal is strong: it runs in 30 seconds on a single CPU for 300k samples, requires no hyperparameter tuning per model, and the calibration constant γ allows users to retain a controlled amount of desirable bias (e.g., slight preference for conciseness). Key limitations include the independence assumption (true reward uncorrelated with the characteristic), which may fail for domain-specific prompt sets, and the multi-characteristic extension showing no synergy effect when calibrating length and markdown simultaneously. Open questions include whether the approach extends to non-additive bias structures, whether it can be integrated into online RLHF loops, and how it behaves when the RM's bias is non-monotonic or interacts with prompt difficulty.
