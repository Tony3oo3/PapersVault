## Problem

Large Multimodal Models (LMMs) such as LLaVA embed every image into a fixed large number of visual tokens (e.g., 576), which is prohibitively expensive for high-resolution images and long videos, and can actually harm performance by distracting the model from relevant information. Existing token pruning and merging methods produce a single-length output per image, offering no flexibility to trade off information density against computational efficiency at deployment time.

## Input / Output

The model takes an RGB image (or a collage of uniformly sampled video frames) and a text question as input. The CLIP-ViT-L-336 encoder produces a 24×24 grid of 576 visual tokens, which are then hierarchically reduced via sequential 2×2 average pooling into nested sets of sizes {1, 9, 36, 144, 576}. At inference, the user explicitly selects which token scale to feed into the LLM, and the model outputs a text answer. The same set of model weights supports all five granularities without retraining.

## Method

M³ enforces a Matryoshka (nested doll) structure along the token-length dimension rather than the feature-dimension level used in prior Matryoshka Representation Learning. Starting from the 24×24 CLIP token grid, it sequentially applies 2×2 average pooling with stride 2 to obtain 12×12, 6×6, and 3×3 token sets, then a final 3×3 pooling to yield a single token, ensuring each coarser set is a strict subset of the finer one. Training uses the standard autoregressive next-token prediction loss averaged simultaneously over all M scales for each image, with no new learnable parameters introduced beyond the existing CLIP encoder and LLM. This multi-scale objective forces the model to compress the most salient visual information into the smallest token budget while preserving fine details at larger scales, achieving coarse-to-fine granularity in an unsupervised manner from a single ground-truth target. The approach outperforms training-free heuristics (average pooling, spatial/sequential sampling) at reduced token counts and matches or exceeds models trained separately at each specific scale.

## Results

On LLaVA-1.5, M3 with 576 tokens achieves 65.9 MMBench, 61.9 GQA, and 87.4 POPE, matching or slightly exceeding the original LLaVA-1.5 (64.8/62.0/85.9). Remarkably, even with only 9 tokens, M3 retains 63.1 MMBench and 83.4 POPE, surpassing Qwen-VL-Chat (256 tokens, 60.6 MMBench) and InstructBLIP-13B (32 tokens, 49.5 GQA). The oracle analysis reveals a large gap: using only 8.9 tokens on average, the oracle achieves 74.35 MMBench and 94.29 POPE—8+ points above the full-token model—indicating substantial room for adaptive token allocation. On video benchmarks, M3 with 720 tokens (vs. 2880 for LLaVA-NeXT) matches or exceeds the full-token baseline on 4 of 6 benchmarks.

## Baselines & Comparisons

Against LLaVA-1.5 (576 tokens), M3 matches or slightly exceeds on all benchmarks (e.g., 65.9 vs. 64.8 MMBench, 87.4 vs. 85.9 POPE). Against Qwen-VL-Chat (256 tokens), M3 with only 9 tokens (63.1 MMBench) surpasses it (60.6), and with 1 token (59.5) achieves comparable performance. Against InstructBLIP-7B/13B (32 tokens), M3 with 9 tokens wins on every reported benchmark (e.g., 58.0 vs. 49.2/49.5 GQA, 51.9 vs. 34.5/33.4 VizWiz). Against the Specific Scale (SS) baseline trained separately for each token count, M3 is at least as good and clearly better on dense-perception tasks: +4.24 on TextVQA (9 tokens), +4.76 on ChartQA (36 tokens), and +1.72 on MMBench (144 tokens). Against heuristic token reduction (average pooling, spatial/sequential sampling) applied at inference time, M3 is dramatically more resilient: at 9 tokens, M3 scores 67.35 MMBench vs. 45.45 (avg pooling), 45.45 (spatial), and 31.96 (sequential). On video benchmarks, M3 with 720 tokens matches or beats LLaVA-NeXT (2880 tokens) on MSVD (79.0 vs. 78.8), MSRVTT (64.5 vs. 63.7), and ActivityNet (55.0 vs. 54.3), while using only 25% of the visual tokens.

## Relation to Prior Work

This paper adapts the Matryoshka Representation Learning (MRL) concept from Kusupati et al. (2022), which learns nested representations along the feature-dimension axis, to the token-length axis for multimodal models. It builds directly on LLaVA-1.5 and LLaVA-NeXT as the base architecture, using CLIP-ViT-L-336 as the visual encoder and Vicuna 7B as the LLM backbone. The key departure from prior token-reduction methods (ToMe, Linformer, ReFormer) is that M3 produces a hierarchy of nested token sets (1, 9, 36, 144, 576) within a single model, rather than a single fixed-length output, enabling explicit granularity control at inference time. A concurrent work (Hu et al., 2024) shares the Matryoshka spirit but uses transformation layers to reformat tokens sequentially, whereas M3 uses parameter-free average pooling to preserve spatial structure.

## Why It Matters / Open Questions

The finding that COCO-style benchmarks require only ~9 visual tokens to match 576-token performance, and that the oracle can use as few as 8.9 tokens while outperforming full-token LLaVA-NeXT by 8 points, challenges the prevailing assumption that more visual tokens are always better and opens the question of how to automatically select the optimal granularity per sample. The method's simplicity (no new parameters, just hierarchical average pooling) makes it a practical, plug-and-play addition to existing LMMs for deployment under resource constraints. Open questions include building a learned scale predictor to close the oracle gap, extending the approach to longer video sequences and higher-resolution inputs, and whether the nested structure generalizes to other modalities or text-only LLMs.
