## Problem

LLM agents consistently underperform in realistic digital environments (coding, web, desktop) due to the lack of high-quality, environment-specific agent data. Existing solutions either depend on expensive human annotation of long multi-step trajectories or rely on prompt-based frameworks whose performance is capped by the base model's capabilities. Few prior works explore fully autonomous data construction pipelines that enable agents to self-adapt to new environments without any human-labeled examples.

## Input / Output

The synthesis pipeline takes environment documentation and tutorials as seed resources, generates task instructions via self-instruct, and produces long multi-step interaction trajectories (observation-action pairs) by running an LLM agent in the target environment. Backward construction then decomposes each full trajectory into all contiguous sub-trajectories and generates a new instruction for each, yielding instruction-trajectory pairs that are filtered by duplicate-state removal and an LLM committee coherence check. At inference time, the agent receives the task instruction, accumulated interaction history, and the current observation (accessibility tree or screenshot with set-of-mark), and the retrieval pipeline queries the synthesized data pool to augment the prompt with relevant demonstration examples before predicting the next action.

## Method

The core mechanism is backward construction: rather than pairing the original self-instruct instruction with the generated trajectory (which often misaligns when the LLM makes errors mid-trajectory), the method feeds each sub-trajectory to an LLM to either summarize the steps or propose a new task objective that the trajectory actually accomplishes. This simultaneously corrects instruction-trajectory misalignment and quadratically expands the dataset by creating examples for every contiguous sub-sequence. For adaptation, the paper designs an agentic retrieval pipeline with two complementary strategies: observation-based retrieval (exact-matching the current environment observation against observations stored in synthesized trajectories) and model-based retrieval (an LLM composes a query from the instruction, interaction history, and current observation, which is then used with a dense retriever to fetch non-duplicate examples). The synthesized data is applied in two modes: as in-context demonstration examples retrieved at each step during inference, and as training data for LoRA fine-tuning of open-weight models (Codegemma-7B, Codestral-22B), with the latter yielding substantially larger gains (up to 23.1% absolute improvement on WebArena).

## Results

In the training-free (ICL) setting, LEARN-BY-INTERACT with agentic retrieval improves Claude-3.5-sonnet by up to +11.1% on OSWorld (11.4→22.5) and +8.8% on Spider2-V (7.5→16.3), and Gemini-1.5-pro by up to +8.1% on Spider2-V (8.3→16.4). In the training-based setting, fine-tuning Codestral-22B with synthesized data yields a +23.1% gain on WebArena (4.7→27.8), substantially outperforming the ICL-only improvement of +5.2% for the same model. The method also achieves 34.7% on SWE-bench (Claude-3.5-sonnet), placing it competitively among top-10 leaderboard entries for task-specific SWE agents.

## Baselines & Comparisons

LEARN-BY-INTERACT outperforms all compared baselines across every benchmark and both LLMs. Against Reflexion, it gains +4.4 to +11.1 points (e.g., 22.5 vs 12.2 on OSWorld with Claude; 16.4 vs 9.3 on Spider2-V with Gemini). Against LATS, the strongest existing baseline, it still leads by +3.4 to +8.9 points (e.g., 34.7 vs 29.0 on SWE-bench with Claude; 25.6 vs 21.0 on WebArena with Gemini). The gap over RAG and Data distill is even larger, confirming that backward construction and agentic retrieval are critical: data distilled without backward construction gains at most +2% over baseline, while LEARN-BY-INTERACT achieves +5.4 to +11.1%. In the training-based setting, Codestral-22B fine-tuned on LEARN-BY-INTERACT data (27.8% on WebArena) surpasses Gemini-1.5-pro using the same data as ICL demonstrations (25.6%), highlighting the value of parameter updates over retrieval alone.

## Relation to Prior Work

This paper builds on the self-instruct paradigm (Wang et al., 2022b) for generating task instructions from documentation and the ReAct-style reasoning-acting loop (Yao et al., 2022b) for agent-environment interaction, but departs from both by introducing backward construction: rather than labeling trajectories with the original instruction (which may be misaligned due to LLM errors), it generates new instructions by summarizing or abstracting each sub-trajectory. This distinguishes it from AgentTuning (Zeng et al., 2023), which also uses self-instruct + LLM trajectories but without the alignment correction, and from prompt-based frameworks like Reflexion and LATS that improve inference-time performance at the cost of additional LLM calls. The agentic retrieval design (combining observation-based and model-based retrieval) also departs from conventional RAG, which retrieves only on the task instruction and ignores the evolving interaction state.

## Why It Matters / Open Questions

LEARN-BY-INTERACT provides a fully autonomous, zero-human-annotation pipeline for adapting LLM agents to new environments, which is practically important as agents are deployed across increasingly diverse real-world settings where expert annotation is infeasible. The backward construction mechanism addresses a fundamental data quality problem (instruction-trajectory misalignment) that plagues naive trajectory collection, and the ablations convincingly show it contributes up to 10.6% for training. Key limitations include the high LLM call cost during synthesis and filtering, and the dependence on available documentation for instruction generation. Open questions include extending to multi-modal settings, training general-purpose agent models, and reducing synthesis cost without sacrificing quality.
