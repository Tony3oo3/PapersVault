## Problem

Deploying LLMs in production requires balancing response quality against inference cost, but routing all queries to the strongest model is prohibitively expensive while routing to weaker models degrades quality on complex queries. Existing routing systems either invoke multiple LLMs per query (increasing latency), rely on synthetic or reward-model-derived labels that inherit biases, or fail to generalize when the underlying model pair changes. This paper addresses how to learn a single-call, model-agnostic router from human preference data that maintains quality while cutting costs by over 2×.

## Input / Output

The router consumes a single text query and outputs a binary routing decision between a designated strong model (e.g., GPT-4) and weak model (e.g., Mixtral-8x7B). Internally, the router first produces a win probability P(win_s|q) and then applies a tunable cost threshold α ∈ [0,1] to convert this into the final decision, allowing operators to dial the quality-cost trade-off at deployment time. A key design property is that the trained router is model-agnostic: at inference time, the strong and weak models can be swapped to entirely different LLMs (e.g., Claude 3 Opus/Sonnet or Llama 3.1 70B/8B) without any retraining.

## Method

The framework decomposes routing into a win prediction model trained by maximum likelihood on pairwise preference labels (win_s / tie / win_w) from Chatbot Arena, and a cost threshold that maps the predicted win probability to a binary decision. Four router architectures are explored: a similarity-weighted Bradley-Terry model that solves for BT coefficients at inference time using cosine-similarity-weighted training queries, a matrix factorization router with a bilinear scoring function δ(M,q) over model and query embeddings, a BERT-base classifier, and a Llama 3 8B causal LLM fine-tuned in an instruction-following paradigm. To combat label sparsity in the 80K Arena battles (where any two models share <0.1% comparisons), the authors cluster 64 models into 10 tiers and augment training with either golden-labeled MMLU validation data (~1500 samples) or GPT-4-as-a-judge labels on ~120K Nectar queries (~$700 total). The key empirical finding is that data augmentation is critical: routers trained on Arena data alone perform near-random on out-of-distribution benchmarks like MMLU and GSM8K, but augmentation with even a small in-domain or judge-labeled set yields 20–60% APGR improvements over random routing.

## Results

On MT Bench, the best router (Matrix Factorization trained on D_arena + D_judge) achieves an APGR of 0.802 (+60.4% over random) and requires only 13.4% of calls to GPT-4 to reach 50% performance gap recovery (CPT(50%)), compared to 49.03% for the random baseline. On MMLU, augmenting with golden-labeled data brings all routers to ~35% CPT(50%) (vs. 50% random), and on GSM8K, the Causal LLM router achieves CPT(50%) of 33.64% with D_judge augmentation. Overall, the routers achieve up to 3.66× cost savings over always using GPT-4 while maintaining 87–95% of GPT-4 quality.

## Baselines & Comparisons

Against the random router baseline, all four router architectures (BERT, Causal LLM, Matrix Factorization, SW Ranking) significantly outperform random on MT Bench when trained on D_arena + D_judge, with APGR improvements ranging from +35.8% to +60.4%. On MMLU and GSM8K, routers trained only on D_arena perform at or below random due to out-of-distribution evaluation, but data augmentation (golden labels or LLM-judge labels) brings all routers above random. In comparison to commercial routing systems (Appendix E), the paper's Matrix Factorization and Causal LLM routers outperform both Martian and Unify AI on MT Bench, achieving the same performance with up to 40% fewer calls routed to GPT-4. The paper also demonstrates that the same routers generalize to unseen model pairs (Claude 3 Opus/Sonnet and Llama 3.1 70B/8B) without retraining, maintaining CPT(80%) roughly half that of random on both pairs.

## Relation to Prior Work

This paper builds on the Bradley-Terry pairwise comparison model and matrix factorization techniques from recommendation systems, repurposing them to learn a win-probability function for LLM routing. It departs from prior routing work (Hybrid-LLM, Zooter) by using human preference data from Chatbot Arena rather than synthetic or reward-model-derived labels, and from cascading/ensemble methods (Frugal-GPT, LLM-Blender, AutoMix) by routing each query to a single LLM to avoid multi-call latency. The paper also extends the architectural scope beyond the BERT-only routers explored in prior work, systematically comparing similarity-weighted ranking, matrix factorization, BERT, and causal LLM classifiers under a unified evaluation protocol.

## Why It Matters / Open Questions

The demonstrated cross-model generalization—routers trained on GPT-4/Mixtral preference data transferring to Claude 3 and Llama 3.1 pairs without retraining—suggests that learned query-complexity signals are model-agnostic, which is practically valuable as the LLM landscape shifts rapidly. The benchmark-dataset similarity score provides a useful diagnostic for anticipating where a router will underperform and where targeted data augmentation (even ~1500 golden-labeled samples) can close the gap. Key open questions include extending from binary to N-way routing, handling real-world query distributions that differ from academic benchmarks, and understanding why router performance varies across architectures on the same dataset without clear explanation.
