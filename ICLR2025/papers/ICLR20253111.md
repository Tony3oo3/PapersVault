## Problem

Users interacting with black-box LLM inference APIs have no rigorous, sample-efficient way to verify that the API serves the model they expect, since providers may quantize, watermark, or finetune weights without disclosure. Existing audits rely on greedy decoding over short-answer benchmarks, which only checks mode agreement on a narrow slice of prompts and misses distributional shifts that matter for sampling-based use cases.

## Input / Output

The method consumes N prompt-completion pairs from a reference distribution P (e.g., locally-run reference weights) and N from the API distribution Q, with prompts drawn from a user-specified distribution π over m prompts. Because commercial APIs return decoded text rather than token IDs, all comparisons are conducted in character space (Unicode vocabulary of ~155K characters, completions of ~1000 characters). The output is a p-value for the two-sample test at a chosen significance level α, plus an MMD distance estimate that quantifies the magnitude of any detected deviation.

## Method

The paper formalizes API auditing as a two-sample distribution test and applies the Maximum Mean Discrepancy (MMD) framework with a prompt-conditional kernel k(z,z') = 1{x=x'}·k̃(y,y'). The key design choice is a Hamming string kernel k̃(y,y') = Σᵢ 1{yᵢ=yᵢ'}, which counts position-wise character matches between completions, rather than universal kernels (all-substrings or one-hot) that are theoretically complete but sample-inefficient. The empirical MMD test statistic rejects H₀ when cross-sample Hamming distances are significantly larger than within-sample distances, with p-values obtained via permutation or null simulation. For the API audit, a composite null (fp32 or fp16 reference) is tested via a conjunction rule requiring both individual p-values to fall below α. The Hamming kernel achieves a median power of 77.4% at just 10 samples per prompt across quantization, watermarking, and finetuning distortions, and flags 11 of 31 commercial endpoints as serving distributions different from Meta's reference weights.

## Results

The Hamming MMD test achieves a median power of 77.4% against quantization, watermarking, and finetuning distortions using only 10 samples per prompt (25 prompts total). Applied to 31 commercial inference endpoints across 9 providers and 4 Llama models, the test flags 11 out of 31 endpoints as serving distributions different from Meta's reference weights, with Perplexity failing all 8 of its endpoints. For model-swap detection in character space, all cross-family swaps are detected with 100% power, while within-family swaps (e.g., Llama-3 8B vs. Llama-3.1 8B) achieve 75–76% power. The Hamming MMD correlates moderately with HumanEval accuracy differences (R²=0.392), and some API deviations (e.g., Perplexity's Llama-3 8B, MMD=0.03) are as large as substituting an entirely different model.

## Baselines & Comparisons

The paper compares the proposed Hamming MMD test against four baselines: the all-substrings kernel (Borgwardt et al., 2006), the one-hot kernel, the L1 test (Balakrishnan & Wasserman, 2018), and the chi-squared test (Bhattacharya & Valiant, 2015). The Hamming MMD test dominates all baselines in sample efficiency, achieving 77.4% median power at 10 samples per prompt while the one-hot and L1/chi-squared tests require substantially more samples to reach comparable power. The all-substrings kernel is competitive with Hamming MMD on robustness to increasing completion length (both maintain power as L grows from 1 to 50 tokens), but is computationally more expensive. The one-hot kernel and multinomial tests (L1, chi-squared) degrade rapidly in power for longer completions and in the small-sample regime, where exact-match collisions are rare. Notably, the Hamming MMD test is weakest against the fp16 quantization alternative, where initial power at N=10m is much lower than for nf4 or int8, suggesting fp16/fp32 differences are not well captured by token-level Hamming distance.

## Relation to Prior Work

This paper builds directly on the MMD two-sample test framework of Gretton et al. (2012), adapting it to the high-dimensional space of multi-token LLM completions. It departs from prior API auditing work (Chen et al., 2021a, 2022, 2023; Eyuboglu et al., 2024), which relied on greedy decoding over short-answer benchmarks, by formulating auditing as a full distributional equivalence test over sampled completions. The kernel choice draws on string-kernel literature (Borgwardt et al., 2006) but replaces the computationally expensive all-substrings kernel with a simple Hamming-distance kernel, and contrasts against classical multinomial tests (Balakrishnan & Wasserman, 2018; Bhattacharya & Valiant, 2015). Unlike zero-knowledge proof approaches (Kang et al., 2022) that require API cooperation, this method is fully black-box and user-executable.

## Why It Matters / Open Questions

The paper provides the first practical, sample-efficient tool for end users to statistically audit whether a commercial API faithfully serves a reference model, with each audit costing under $1. The finding that 11 of 31 endpoints deviate from Meta's reference weights—and that some deviations are as large as substituting an entirely different model—has immediate implications for reproducibility, benchmarking validity, and user trust. Open questions include whether stronger (universal) kernels can close the remaining power gap (e.g., against fp16), how the test extends to other modalities, and whether the composite null hypothesis test can be made less pessimistic. The released dataset of 1 million completions and open-source package lower the barrier for follow-up research.
