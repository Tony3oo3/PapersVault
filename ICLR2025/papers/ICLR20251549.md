## Problem

Existing PEFT methods like LoRA reduce FLOPs by training only small adapter matrices, but the adapter layers are processed sequentially with pretrained layers on GPUs, so the actual training time savings are negligible (only 0.6% for LLaMA3-8B despite 33% fewer operations). Additionally, LoRA does not reduce activation memory because the full input activations must still be stored to compute gradients for the first adapter matrix, limiting sequence length and batch size.

## Input / Output

PaCA takes a pretrained model's weight matrices and fine-tuning data (text sequences for LLMs on MMLU/Oasst1, or images for ViT/EfficientNet on CIFAR/Pets/Flowers) and produces a fine-tuned model where only randomly selected columns of the original weight matrices are updated. The 'rank' parameter (e.g., 8 or 16) controls how many columns per weight matrix are selected for training, directly determining the number of trainable parameters. Unlike LoRA which adds new A and B matrices, PaCA modifies the existing weight matrix in-place, so the model architecture and inference pipeline remain unchanged.

## Method

PaCA randomly selects r columns from each pretrained weight matrix W before training and updates only those selected columns (P ⊂ W) during fine-tuning, using the standard forward pass X_out = WX_in and computing gradients only for the partial connections ∇P = ∇X_out^p · X_in^T. Because the partial connections are part of the original weight matrix, no additional forward or backward computations are needed, eliminating the sequential-processing latency overhead that plagues adapter-based PEFT. For gradient computation, only the partial activations corresponding to selected columns (rather than full input activations) must be stored, reducing activation memory. The paper proves convergence under Lipschitz-continuous gradients (Theorem 1) and extends the approach to QPaCA, which quantizes unselected connections to 4-bit NormalFloat while fine-tuning selected connections at 16-bit, enabling fine-tuning of 70B models on a single A100 GPU.

## Results

On MMLU fine-tuning of LLaMA3-8B, PaCA (rank 8) achieves 65.2% average accuracy while using only 23 GB memory and 3.5 h training time, compared to LoRA (27 GB, 4.4 h), DoRA (33 GB, 9.4 h), and MosLoRA (27 GB, 4.6 h). On LLaMA2-7B, PaCA reduces memory by 13% and training time by 26% versus LoRA while matching its 50.4% vs 50.6% average accuracy. On MT-Bench instruction tuning (LLaMA3-8B, Oasst1), PaCA scores 5.23 average vs LoRA's 5.12, with 16% less memory and 19% shorter training time. PaCA also enables 23% longer maximum sequence length (9.8K vs 8.0K) and 16% higher throughput on both A100 and Gaudi2 hardware.

## Baselines & Comparisons

PaCA consistently outperforms LoRA on efficiency metrics: it uses 13–16% less memory and 19–26% less training time across all three LLaMA models, while matching or exceeding LoRA's accuracy (e.g., 65.2% vs 65.0% on LLaMA3-8B MMLU). Against DoRA, the gains are most dramatic—PaCA cuts memory by 28–31% and training time by 58–64% (e.g., 3.2 h vs 8.7 h on LLaMA2-7B) while achieving nearly identical accuracy (51.2% vs 51.3% at rank 16). Compared to MosLoRA, PaCA saves 13% memory and 13–26% training time with accuracy within 0.1–0.7%. In the quantized setting (QPaCA vs QLoRA on LLaMA3.1-70B), PaCA reduces memory by 14% (69 GB vs 80 GB) and training time by 8% (4.7 h vs 5.1 h) with a negligible 0.01-point drop in MT-Bench average score. On MT-Bench instruction tuning, PaCA actually surpasses LoRA in average score (5.23 vs 5.12) while using 16% less memory and 19% less time, and it also exceeds LoRA's maximum sequence length by 23% (9.8K vs 8.0K tokens).

## Relation to Prior Work

PaCA departs from the dominant PEFT paradigm of introducing separate adapter layers (LoRA's low-rank A/B matrices, DoRA's weight decomposition, MosLoRA's mixture-of-subspaces) by instead fine-tuning randomly selected columns directly within the frozen pretrained weights. Conceptually, it draws on the subspace-learning insight from intrinsic dimensionality work (Li et al., 2018; Aghajanyan et al., 2021) and LoRA's own low-rank assumption, but replaces the structured low-rank factorization with an unstructured column subset. The QPaCA variant extends QLoRA's 4-bit quantization of frozen weights to the partial-connection setting, and the method generalizes to non-transformer architectures (ViT, CNN) where LoRA's linear adapters cannot be merged into convolutional layers.

## Why It Matters / Open Questions

PaCA offers a practically significant efficiency win—22% faster training and 16% less memory than LoRA—without sacrificing accuracy, and it enables single-GPU fine-tuning of 70B models via quantization. The finding that random column selection matches importance-based strategies (weight-norm, gradient-magnitude) simplifies deployment and suggests the specific subspace geometry matters less than the subspace dimensionality. Open questions include whether smarter connection selection (the authors' stated future work) can close the small accuracy gaps observed at lower ranks, and whether the Lipschitz-continuity convergence guarantee translates to the non-convex landscapes of real LLMs. The method's applicability to CNNs and ViTs, where LoRA's linear adapters are architecturally incompatible, broadens its relevance beyond transformer fine-tuning.
