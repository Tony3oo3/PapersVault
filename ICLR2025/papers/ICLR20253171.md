## Problem

Kolmogorov complexity defines the theoretically optimal compression of a sequence as the length of the shortest program that reproduces it, but it is uncomputable and no existing benchmark directly tests whether code-generating LLMs can approximate this ideal. Current code generation benchmarks (HumanEval, SWE-bench, etc.) do not measure the ability to discover and exploit structural patterns in arbitrary data sequences, and their metrics can be gamed or saturated. The paper introduces the KOLMOGOROV-TEST (KT), a compression-as-intelligence benchmark where the metric (program length) is non-gameable, instances are essentially infinite, and pretraining contamination is highly unlikely.

## Input / Output

At inference time, the model receives a sequence of bytes represented as a list of integers (range [0,255] for audio and text, [0,7] for DNA) of length 16–128 bytes (up to 1024 for the LMIC baseline), and must generate a Python program (or DSL program for trained SEQCODER models) whose execution exactly reproduces the input. The output is scored on three metrics: Accuracy (whether the program is correct), CompressionRate (bit-length of the encoded program plus one flag bit, divided by input length, with incorrect programs falling back to the REPEAT baseline), and Precision (compression of correct programs relative to GZIP). The model must find the *shortest* program, not merely any correct one, making the task fundamentally different from standard code generation.

## Method

The paper contributes both a benchmark and a synthetic data generation framework. For evaluation, they use naturally occurring sequences from LibriSpeech audio (16-bit, 8-bit, and MFCC encodings), enwik9 text, and GRCh38 human DNA, alongside synthetic sequences. For supervised training, they design a compositional domain-specific language (DSL) with four function classes—sequence initiators (range, repeat, fixed list), modifiers (reverse, substitute, scan-add, modulo), filters (even/odd, non-zero), and mergers (concatenate, interleave, pointwise arithmetic)—and sample program-sequence pairs using a context-free-grammar-like process with uniform priors over functions and arguments. They train SEQCODER models (1.5B and 8B parameter transformers pre-trained on 200B tokens of code and text) on 10K–1M synthetic pairs, encoding programs with a factorized uniform prior via arithmetic coding. The key finding is that while trained SEQCODER models outperform GZIP and LMIC on synthetic data (CompressionRate 0.38 vs. 0.59 and 0.45), they achieve near-zero accuracy on natural sequences, and even GPT4-o and LLAMA-3.1-405B err on 40–78% of natural sequences, indicating that generalization from synthetic to real data remains an open challenge.

## Results

On the KOLMOGOROV-TEST, current flagship models perform poorly: GPT4-o achieves 56.5% average Accuracy and LLAMA-3.1-405B achieves only 22.3% average Accuracy across six modalities (audio, DNA, text, synthetic), with all prompted models having Precision > 1.0 (i.e., generated programs are larger than GZIP-encoded sequences). On synthetic data, the trained SEQCODER-8B model achieves 92.5% Accuracy and 0.56 Precision, outperforming GPT4-o (44.7% Acc, 1.65 Prec) by over 40% in Accuracy and being the only model to beat GZIP (Precision < 1.0). However, SEQCODER models drop to near-zero Accuracy on all natural data modalities, revealing a severe synthetic-to-real generalization gap.

## Baselines & Comparisons

Against GZIP (the classical compression baseline), SEQCODER-8B achieves a CompressionRate of 0.38 on synthetic data, beating GZIP's 0.593 (1MB) and 0.819 (1024-byte) rates, and is the only model with Precision below 1.0. Against LMIC (Deletang et al., 2024), SEQCODER-8B also outperforms the LMIC baseline (0.450 at 1024 bytes) on synthetic data, while LMIC remains competitive on real data (e.g., 0.273 on Audio-8-bit at 1024 bytes). Against prompted LLAMA-3.1-405B, SEQCODER-8B achieves 92.5% vs 33.3% Accuracy on synthetic data (a 59-point gap), but LLAMA-3.1-405B dominates on all natural modalities (e.g., 35.6% vs <0.1% on Audio-16-bit). Against GPT4-o, SEQCODER-8B achieves 92.5% vs 44.7% Accuracy on synthetic data, while GPT4-o leads on natural data (e.g., 83.8% vs 0.1% on MFCC). O1-MINI shows similar overall Accuracy to GPT4-o (57.2% vs 56.5% average) with higher executable-program accuracy (69.8% vs 63.2%) but a lower percentage of executable programs (81.7% vs 89.9%), confirming that extended reasoning does not yet close the gap on KT.

## Relation to Prior Work

This paper bridges algorithmic information theory (Kolmogorov complexity, Solomonoff induction) with modern code generation LLMs, positioning code-generating models as computable upper bounds on Kolmogorov complexity. It departs from prior LLM-based compression work (LMIC by Deletang et al., LLMZip by Valmeekam et al.) which uses the LLM as a probability model with arithmetic coding and requires full model weights for decompression; here, the LLM must output a self-contained program, making the task a direct code generation challenge. The benchmark also extends the program synthesis literature (HumanEval, APPS, TACO) by replacing function specifications with raw data sequences and using compression rate as an ungameable metric, while drawing on the Hutter Prize tradition of compressing large corpora.

## Why It Matters / Open Questions

KT provides a theoretically grounded, unsaturable benchmark for code generation that cannot be gamed by memorization, with essentially infinite problem instances of varying difficulty. The finding that frontier models (GPT-4o, Llama-3.1-405B) err on 40–78% of instances, and that >95% of their correct outputs on natural data are mere repetitions rather than pattern discovery, reveals a significant gap between current code generation capabilities and true algorithmic reasoning. The poor generalization from synthetic to real data suggests that scaling alone is insufficient and that new approaches (RL with compression rewards, curriculum learning, stronger priors) are needed. Open questions include whether the benchmark can be extended to images/video, whether stronger program priors (small LMs over code) close the gap, and whether the synthetic-to-real generalization gap can be bridged.
