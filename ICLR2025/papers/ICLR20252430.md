## Problem

Processing long documents with short context windows requires effective memory to bridge gaps between windows, but existing approaches either incur prohibitive memory costs (Memorizing Transformer stores all raw KV pairs, requiring ~147M floats) or lack a principled mechanism for hierarchical information retention. The paper asks how to design a memory architecture that preserves crucial information from the entire history while dramatically reducing the memory footprint compared to dense-attention baselines.
![Teaser figure](../imgs/ICLR20252430/cropped_page0_idx0.webp)

## Input / Output

The model consumes text tokens organized into fixed-size context windows (512 tokens by default), processing them sequentially with recurrent memory updates between windows. During training, long documents are segmented into 4096-token chunks (8 windows per batch) to enable backpropagation through time across multiple windows. Output is standard autoregressive next-token prediction, with summary tokens generated in parallel at each window boundary to update both short-term and long-term memory before the next window begins.

## Method

MELODI introduces a hierarchical compression scheme with two complementary memory types arranged in a sandwich architecture (M short-term layers, 1 long-term layer, N−M−1 short-term layers). Short-term memory uses recurrent compression across all layers: summary tokens (S per layer, e.g., 128) are appended to context tokens, passed through a shared transformer block, then split via linear token mixers into separate paths for the next layer's summary and the next window's memory, enabling distinct compression flows vertically (across layers) and horizontally (across windows). Long-term memory resides in a single middle layer that further compresses each window into L tokens (L < S, e.g., 64) and stores their KV pairs in a FIFO queue spanning Q_max windows; the current context cross-attends to this memory with a per-head gating scalar blending cross- and self-attention. The key efficiency gain comes from storing compressed KV pairs rather than raw context KV pairs, yielding an 8× memory reduction over Memorizing Transformer while matching or exceeding its perplexity on PG-19, arXiv Math, and C4.

## Results

On PG-19 (T5 vocabulary), MELODI S128+L64 achieves a perplexity of 10.44 and MELODI S192+L96 achieves 10.29, both outperforming the Memorizing Transformer (10.62) while using 8× and 5× less memory (18.5M and 27.8M floats vs. 147.8M), respectively. On arXiv Math (Meena vocabulary), MELODI S192+L96 reaches 2.09 perplexity versus 2.14 for Memorizing Transformer. MELODI S192+L32 (11.0M memory) also surpasses Transformer XL (11.41) and Block Recurrent Transformer (10.98) on PG-19 T5 while consuming less memory than either baseline.

## Baselines & Comparisons

Against Transformer XL, MELODI S192+L32 (11.0M memory) achieves 10.51 perplexity on PG-19 T5 versus 11.41 for Transformer XL (13.6M memory), a 0.9 perplexity improvement with less memory. Against Block Recurrent Transformer, the same MELODI configuration improves by 0.47 perplexity (10.51 vs. 10.98) while using 2.1M fewer floats. Against the strongest baseline, Memorizing Transformer (147.8M memory), MELODI S128+L64 (18.5M memory) wins on PG-19 (10.44 vs. 10.62) and arXiv (2.11 vs. 2.14) with an 8× memory reduction, while MELODI S192+L96 (27.8M memory) wins on all three datasets (10.29, 2.09, 17.25) with a 5× memory reduction. The paper notes that their re-implementations of baselines (using cosine LR decay and dense cross-attention) already improve over originally reported numbers, making the comparison more stringent.

## Relation to Prior Work

MELODI synthesizes ideas from three distinct lines of work: Transformer-XL's KV-cache short-term memory, Memorizing Transformer's single-layer long-term KV storage, and the summary-token compression mechanism from Recurrent Memory Transformer and AutoCompressor. The key architectural departure is a hierarchical 'sandwich' design where short-term memory uses recurrent compression via summary tokens across *all* layers (rather than a single layer as in BRT), while long-term memory stores *compressed* KV pairs (rather than raw context-token KV pairs as in Memorizing Transformer), achieving an 8× reduction in long-term memory footprint. The summary branching mechanism—using separate linear token mixers to route distinct compressed representations upward through layers and rightward across windows—is a novel component not present in any of the cited baselines.

## Why It Matters / Open Questions

The 8× memory reduction relative to Memorizing Transformer while matching or exceeding its perplexity across three datasets and multiple model scales (12–36 layers, up to 459M parameters) makes long-context processing substantially more practical for resource-constrained settings. The thorough ablations confirm that short-term and long-term memory play genuinely complementary roles, and that a single long-term layer with sufficient tokens captures most of the benefit, simplifying deployment. Key limitations include evaluation solely via perplexity on train-from-scratch models (no downstream tasks or pretrained-model integration), and the increased FLOPs from summary tokens and cross-attention that extend training time. Open questions include whether the compression-based approach transfers to pretrained LLMs via adapters like LoRA, and whether long-term memory can be both compressible (MELODI) and reusable across layers (YOCO) simultaneously.
