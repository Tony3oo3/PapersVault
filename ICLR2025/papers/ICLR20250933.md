## Problem

Standard RAG systems prepend all retrieved documents to the query, causing input length to grow linearly with the number of documents and latency to scale quadratically in Transformer architectures. Existing mitigations like Fusion-in-Decoder are incompatible with decoder-only LLMs, while Parallel Context Windows only accelerates prefilling but still attends to the full context during decoding. Additionally, irrelevant retrieved contexts can degrade generation quality, yet prior filtering approaches require an external classifier that adds extra model calls and serving complexity.

## Input / Output

The system takes a natural-language question and N retrieved documents as input. During prefill, each document is encoded independently with block-wise attention masks (no cross-document attention), and the model outputs a per-context relevance score (the probability of the token 'yes' following a special {Control_Assessment} token) for each document. After threshold-based filtering retains only K ≤ N documents, the model generates the final answer by attending exclusively to the retained KV caches, prompted by a {Control_Generation} token. The entire assessment-and-generation pipeline completes in a single model pass with no external classifier calls.

## Method

Sparse RAG unifies per-context relevance assessment and answer generation within a single decoder-only LLM via multi-task training on two data formats distinguished by special control tokens. During training, block-wise attention masks prevent cross-document attention (following PCW), and parallel incremental positional encodings allow all retrieved contexts to share position IDs starting after the query, enabling KV cache reuse between the assessment and generation tasks at inference. At inference, the model first scores each context in parallel by appending {Control_Assessment} and reading the 'yes' probability, then drops contexts whose score falls below a threshold σ, and finally generates the answer by appending {Control_Generation} and decoding over only the surviving KV caches. The model is adapted via LoRA fine-tuning (rank 4) on Gemini XXS/XS, with relevance training labels produced by a two-round prompting pipeline using Gemini Ultra as rater and PALM2 XL as critic. This design eliminates the need for an external classifier while simultaneously reducing decoding latency (by loading fewer KV caches) and improving quality (by filtering irrelevant contexts).

## Results

On PopQA, Sparse RAG achieves 67.71 EM and 71.16 F1 while using only 7.84 contexts on average (vs. 20 for dense RAG), yielding a decoding speed of 12.28 t/s—nearly 2× faster than RAG (6.65 t/s). On QMSum, Sparse RAG reaches 23.96 F1 and 20.10 RougeLSum with just 4.45 contexts and 16.05 t/s decoding speed. On TriviaQA and HotpotQA, Sparse RAG achieves 47.50 EM / 55.10 F1 and 43.50 EM / 55.36 F1 respectively, matching or exceeding dense RAG quality while halving the number of decoded contexts. Overall, Sparse RAG reduces end-to-end latency from 95.9 ms (RAG) to 37.4 ms while improving or matching generation quality across all four datasets.

## Baselines & Comparisons

Sparse RAG outperforms standard RAG on quality (e.g., PopQA F1: 71.16 vs. 69.99; QMSum F1: 23.96 vs. 21.43) while using roughly half the contexts during decoding, resulting in ~2× faster decoding speed. Against PCW-RAG, Sparse RAG matches prefill efficiency (both use parallel context encoding) but significantly improves decoding speed (12.28 vs. 6.65 t/s on PopQA) and quality, particularly on HotpotQA where PCW-RAG suffers a large F1 drop (50.03 vs. 55.85 for RAG) due to the absence of cross-document attention. Sparse RAG beats CRAG on PopQA quality (EM 67.71 vs. 66.52; F1 71.16 vs. 70.99) and total end-to-end latency (37.4 ms vs. 70.5 ms), since CRAG requires an external T5-XXL classifier adding ~40 ms of overhead. The only case where Sparse RAG does not strictly win is HotpotQA F1, where it trails RAG by 0.49 points (55.36 vs. 55.85), though it still matches RAG on EM (43.50 vs. 43.00) and uses fewer contexts (6.50 vs. 10.00). LLMLingua, which compresses prompts via an external LLM, performs far worse on quality (e.g., PopQA F1: 12.15) and cannot be fairly compared on latency due to its external model dependency.

## Relation to Prior Work

Sparse RAG builds directly on Parallel Context Windows (PCW), which introduced block-wise attention to parallelize document encoding, and on Corrective RAG (CRAG), which filters retrieved documents before generation. The key departure is unifying per-context relevance assessment and answer generation within a single decoder-only LLM via special control tokens and parallel positional encodings, eliminating the external T5 classifier that CRAG requires and the encoder-decoder architecture that FiD depends on. Unlike PCW, which only accelerates prefilling while still attending to all cached documents during decoding, Sparse RAG dynamically prunes the KV cache so that decoding attends to only a subset of contexts, combining the efficiency of parallel encoding with the quality benefit of context filtering in one pass.

## Why It Matters / Open Questions

The practical significance is strong for on-device and latency-sensitive RAG deployments: Sparse RAG nearly doubles decoding speed while simultaneously improving generation quality by removing noisy contexts, all without requiring a separate classifier model or additional serving infrastructure. The golden-label experiment on QMSum (F1 23.96 → 26.76, K 4.45 → 1.13) reveals substantial headroom, suggesting that better per-context assessment quality could yield further gains. Open questions include whether the approach extends to multimodal retrieval, how it behaves at much larger model scales, and whether the quality gap on multi-hop reasoning (HotpotQA) can be closed without reintroducing cross-document attention during generation.
