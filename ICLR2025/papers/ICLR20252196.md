## Problem

LLMs can generate code from input-output examples but lack search: each sampled program is independent, and once the model commits to an early line it cannot easily backtrack or reconsider. Additionally, the model reasons only in syntactic space (tokens) rather than semantic space (execution results), causing it to miss edge cases like empty strings from splitting on repeated delimiters. This paper addresses both limitations by enabling the model to search over candidate programs and ground its decisions in actual execution outcomes.

## Input / Output

The method takes a set of input-output assertions (e.g., `assert f(a='Program-Synthesis') == 'PS'`) and a function signature as the specification, and produces a straight-line Python program (no loops, conditionals, or other control flow) that satisfies all assertions. The prompt is a single, iteratively expanding document: each iteration appends newly sampled lines of code annotated with their execution results as inline comments (e.g., `# {'e1': ['Program', 'Synthesis'], 'e2': ['Large', '', 'Language', '', 'Model']}`), so the model sees both the syntactic code and the semantic values of every intermediate variable at every step.

## Method

The LLM (gpt-4o) serves simultaneously as an explicit policy—sampling k=4 candidate next lines of code at temperature 0.6—and an implicit value function—choosing which previously generated lines to extend in the next iteration by attending to both their syntax and their execution-annotated values. All sampled lines are de-duplicated, canonicalized (substituting shared sub-expressions, wrapping lazy generators in `list()`, topologically re-sorting), and combined into a single superstate prompt, so the search tree is flattened into one expanding document rather than maintained as separate branches. Before each new sampling round, every line in the current program is executed on all given examples and the per-example results are injected as dictionary-valued comments, giving the model a semantic view of intermediate state. The search terminates when any variable's value matches all assertions, and the model can implicitly backtrack by simply ignoring unproductive lines in subsequent iterations. An ablation variant replaces the implicit value with an explicit Tree-of-Thought-style value prompt that rates each candidate line as sure/maybe/impossible, enabling out-of-prompt search that scales better with larger k.

## Results

Using the aligned pass@8 metric (which normalizes for the different number of programs each method implicitly generates), within-prompt search (WPS) is the best or second-best method on all five benchmarks (best on 3/5, second on 2/5). A key finding is that WPS at pass@1 (a single search trajectory) outperforms the generate-and-test strategy at pass@4 on 4 out of 5 benchmarks, demonstrating that execution-guided search is more sample-efficient than brute-force sampling. On SyGuS, Tree-of-Thought (ToT) outperforms WPS due to many small value tokens from long-string splits confusing the implicit value function; on Lists, WPS and Self-debug are the top performers because the problem is less clear from examples alone.

## Baselines & Comparisons

Against **Straight** (generate-and-test), WPS at pass@1 outperforms Straight at pass@4 on 4 out of 5 benchmarks (Figure 2), showing that execution-guided search is substantially more sample-efficient than independent sampling. Against **Chain-of-Thought** (Wei et al., 2022), WPS consistently achieves higher aligned pass@8, as CoT lacks both execution feedback and search. Against **Self-debug** (Chen et al., 2023; Wang et al., 2024), WPS wins on most benchmarks but is comparable on Lists, where end-to-end iterative feedback is particularly effective for ambiguous problems. Against **Tree-of-Thought** (Yao et al., 2024), the comparison is nuanced: ToT outperforms WPS on SyGuS (where explicit value ranking handles many similar split operations better), but WPS outperforms ToT on the other four benchmarks. Additionally, Figure 4 shows that ToT scales better with increasing k (number of sampled operations) because the explicit value prompt avoids the growing difficulty of implicit selection in a longer prompt, while Figure 5 confirms ToT requires roughly 2× the tokens of WPS.

## Relation to Prior Work

This paper extends the execution-guided program synthesis line (Ellis et al., 2019; Chen et al., 2018) from trained policy/value networks operating over DSL grammars to a single untrained LLM prompted to act as both policy and value. The key architectural departure is 'within-prompt search': rather than maintaining separate states in an explicit search tree (as in Tree-of-Thought, Yao et al., 2024), all explored operations are combined into one expanding prompt, letting the model implicitly select which lines to extend. This eliminates the need for a separate value prompt or trained networks while retaining the execution-guidance signal that prior work showed is critical for semantic reasoning.

## Why It Matters / Open Questions

The paper demonstrates that a single LLM prompt can serve as a full search space for program synthesis without any training, which lowers the barrier to applying search-based PBE with modern LLMs. However, the approach is limited to straight-line code and requires a strong model (gpt-4o); extending to control flow, smaller models, or other domains (program repair, spreadsheet formulas) remains open. The finding that execution feedback is the critical component—search alone without execution provides no benefit—refocuses attention on semantic grounding as the key ingredient for LLM-based synthesis rather than search structure per se.
