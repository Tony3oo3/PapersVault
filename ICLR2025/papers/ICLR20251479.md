## Problem

Existing function-calling training data for LLMs is limited in API diversity (mostly relying on a few hundred public APIs), restricted to simple single-turn queries, and lacks rigorous accuracy verification. This limits zero-shot generalization to unseen APIs and fails to cover complex scenarios like parallel, dependent, or multi-turn tool interactions. No prior pipeline simultaneously addresses all three dimensions—diversity, model-appropriate complexity, and verifiable accuracy—in synthetic tool-learning data.

## Input / Output

The pipeline consumes raw pretraining documents (technical manuals, API docs, product specs) to bootstrap an API context tree, then generates training pairs consisting of a user query (natural language) paired with a set of candidate API definitions in JSON Schema format. The target model's output is a structured function call (function name with typed parameters, including nested lists-of-dicts), a clarifying question when required parameters are missing, or an explicit non-tool-use response when no provided API is relevant. The final dataset contains 26,507 APIs across 390 domains with four dialog types: single, parallel, dependent, and non-tool-use calls.

## Method

ToolACE is a three-module agentic pipeline. (1) Tool Self-Evolution Synthesis (TSS) builds a hierarchical API context tree from pretraining documents, then iteratively synthesizes new API definitions via a speciation–adaptation–evolution loop that mutates parameters, adds constraints, and expands functionalities to produce 26,507 diverse APIs. (2) Self-Guided Dialog Generation (SDG) employs three role-playing agents (user, assistant, tool) to produce multi-turn dialogs, where the target LLM itself computes cross-entropy loss on candidate samples as a complexity signal; if the loss falls outside a calibrated [lower, upper] band, the user agent's prompt is dynamically adjusted to increase or decrease query complexity. (3) Dual-Layer Verification (DLV) first applies rule-based checks (JSON Schema conformance, parameter completeness, regex pattern matching, role-order consistency) and then decomposes model-based checks into three sub-queries handled by separate expert agents (hallucination detection, consistency validation, tool-response alignment). The resulting data fine-tunes LLaMA-3.1-8B-Instruct via LoRA (rank 16, alpha 32, 3 epochs), achieving 59.22 overall on BFCL—competitive with GPT-4-turbo at 1/10th the parameter scale.

## Results

On BFCL-v3, ToolACE-8B achieves an overall score of 59.22, ranking 3rd behind GPT-4-turbo (59.49) and GPT-4o (59.29), while outperforming all other open-source and API-based models. On API-Bank, ToolACE-8B scores 75.94% on Call and 47.41% on Retrieval+Call, surpassing all open-source models and matching GPT-4-series performance. The model also excels in hallucination mitigation, achieving 85.37% relevance and 83.81% irrelevance detection, the best balance among all compared models.

## Baselines & Comparisons

ToolACE-8B (59.22 overall) narrowly surpasses xLAM-8x22b-r (59.13) on BFCL overall while significantly outperforming xLAM-7b-fc-r (51.45) by 7.77 points, and on API-Bank ToolACE-8B (75.94 Call / 47.41 Retrieval+Call) dramatically exceeds xLAM-7b-fc-r (32.83 / 21.48). Against Gorilla-OpenFunctions-v2 (51.01), ToolACE-8B leads by 8.21 points overall, with particularly large gaps in multi-turn (14.37 vs. 0.00) and irrelevance detection (83.81 vs. 73.13). Compared to the base LLaMA-3.1-8B-Instruct, fine-tuning with ToolACE data improves API-Bank Call from 71.18 to 75.94 and Retrieval+Call from 37.04 to 47.41, while the 70B LLaMA-3-70B-Instruct (49.55) is outperformed by the 8B ToolACE model by nearly 10 points. ToolLLM training data (24.90 overall) is far inferior to ToolACE (58.19) under identical 25K-sample and base-model conditions, confirming the quality advantage of the synthesized pipeline. On general capability benchmarks (MMLU, GSM8K, CommonsenseQA), ToolACE-8B shows negligible degradation relative to the raw LLaMA-3.1-8B-Instruct while substantially improving function calling, though it still trails GPT-4 on broader reasoning tasks.

## Relation to Prior Work

ToolACE extends the tool-augmented LLM data synthesis line (Gorilla, ToolLLM, ToolAlpaca, xLAM) by replacing reliance on fixed public API collections with a self-evolving API synthesis process (speciation–adaptation–evolution) that generates 26,507 APIs across 390 domains. It departs from prior pipelines in two key ways: (1) the model being trained serves as its own complexity evaluator to calibrate data difficulty, and (2) a dual-layer verification system (rule-based + model-based) enforces accuracy at scale. Conceptually, the paper repurposes the 'zone of proximal development' idea from Du et al. (2023) into a concrete loss-based complexity metric and multi-agent dialog generation loop, rather than treating data complexity as a static property.

## Why It Matters / Open Questions

The practical impact is significant: an 8B LoRA-finetuned model reaches 59.22 overall on BFCL (3rd place, behind only GPT-4-turbo and GPT-4o), and the released dataset/pipeline gives the community a reproducible recipe for generating high-quality function-calling data without manual annotation. The ablation showing that equal-size datasets from different pipelines yield a 33-point gap (ToolACE 58.19 vs. xLAM 40.51 vs. ToolLLM 24.90) underscores that data quality, not just quantity, is the bottleneck. Open questions include the computational cost of per-sample complexity evaluation at scale, whether iterative complexity-based sampling can push performance further, and how to simultaneously improve general capabilities (MMLU, GSM8K) alongside function calling without the trade-offs observed here.
