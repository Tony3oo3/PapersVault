## Problem

Current Mixture-of-Experts routers in different transformer layers operate independently, making routing decisions based solely on local hidden states without access to how tokens were routed in preceding layers. This isolation leads to suboptimal token-expert combinations and contributes to the well-documented parameter inefficiency of MoE models, where a 52B-parameter MoE can underperform a 6.7B dense model. The paper asks whether explicitly modeling cross-layer routing dependencies can improve expert utilization without significant computational overhead.

## Input / Output

At each MoE layer, the method consumes the layer's hidden state (dimension h, e.g., 352 or 1280) and the GRU hidden state from the previous layer (dimension p, typically 128). The hidden state is projected to dimension p via a layer-specific linear layer before entering the shared GRU, which outputs a p-dimensional vector that replaces the standard linear router input. The final model output remains standard next-token prediction, but the routing scores now encode cross-layer routing history rather than being computed from a single layer's representation in isolation.

## Method

RMoE inserts a cross-layer-shared Gated Recurrent Unit into the routing path of a standard Switch Transformer. At layer i, the hidden state x_i is projected to a lower dimension p via a layer-specific linear projection (not shared across layers, since hidden state statistics vary significantly by depth), then fed into the GRU alongside the previous layer's GRU output h_{i-1} to produce h_i, which drives the top-k expert selection. The GRU is shared across all layers, creating a recurrence over the layer index rather than the sequence index, so it can be computed in parallel across tokens. This design provides two distinct benefits: forward propagation of routing history (informing each router about prior layer assignments) and an additional backward gradient pathway through the GRU hidden states (termed 'Recurrent Gradient'), which the ablations show is critical for router optimization. The method is orthogonal to existing router improvements (XMoE, HyperMoE, etc.) and can be composed with them, adding only ~0.47M parameters and negligible wall-time overhead.

## Results

On Enwiki8 (character-level LM), RMoE achieves 1.116 BPC test, outperforming SMoE (1.128), XMoE (1.125), and CosineMoE (1.122). On WikiText-103 (word-level LM), RMoE reaches 32.867 PPL test, beating SMoE (33.061) and XMoE (32.926). RMoE adds only ~0.43M parameters over SMoE (36.51M vs 36.08M) while incurring negligible overhead: 49.46 GB peak memory and 972.9 s/1k steps vs SMoE's 47.92 GB and 960.2 s/1k steps. At the 0.91B-parameter scale with 40B pre-training tokens plus SFT, RMoE achieves 57.15 average accuracy across five benchmarks vs 56.13 for SMoE.

## Baselines & Comparisons

RMoE outperforms all four baselines on both Enwiki8 and WikiText-103 test sets. Against SMoE (standard switch-transformer), RMoE improves Enwiki8 BPC from 1.128 to 1.116 and WikiText PPL from 33.061 to 32.867, using only 0.43M additional parameters. Against XMoE (cosine-similarity routing with down-projection), RMoE achieves 1.116 vs 1.125 BPC and 32.867 vs 32.926 PPL, and the two methods are shown to be composable (XMoE+GRU further improves to 1.112 BPC). Against HyperMoE (hypernetwork-generated router weights), RMoE wins on all metrics while using 11.9M fewer parameters (36.51M vs 48.41M). Against SMoE-MLP (two-layer MLP router), RMoE achieves 1.116 vs 1.137 BPC, confirming that simply increasing router capacity without cross-layer information sharing is insufficient. At the 15B-parameter scale (400B tokens), RMoE consistently gains ~1 point over SMoE on MMLU (60.60 vs 59.54) and GSM8K (52.99 vs 52.16).

## Relation to Prior Work

This paper extends the Switch Transformer / SMoE architecture by introducing a GRU-based recurrent router that treats routing decisions across transformer layers as a sequential process, in contrast to prior router improvements (XMoE, HyperMoE, SMoE-MLP, SMoE-dropout) that treat each layer's router independently. Conceptually, it repurposes the recurrent controller idea from Neural Architecture Search—where an RNN predicts per-layer architecture choices—into a per-token, per-layer expert selection mechanism. The method is explicitly positioned as orthogonal to existing router designs, enabling composition (e.g., RMoE + XMoE), and draws on the observation that even fixed random routers can be competitive, suggesting the bottleneck is not router capacity but the lack of cross-layer coordination.

## Why It Matters / Open Questions

RMoE offers a low-overhead, composable component that addresses MoE parameter inefficiency (where 52B MoE models underperform 6.7B dense models) by enabling cross-layer information sharing in routing. The finding that the backward 'Recurrent Gradient' through the GRU is more critical than the forward information flow is a useful insight for understanding why simply adding router capacity fails. Limitations include modest absolute gains (~1 point on MMLU at 15B scale), evaluation primarily on language modeling and small benchmarks, and the fact that the layerwise projector adds per-layer parameters that may complicate very deep or shared-expert architectures. Open questions include whether the benefit persists at 100B+ scale and how it interacts with expert-choice or soft-routing paradigms.
