## Problem

Existing Tool-Augmented Language Model (TALM) benchmarks predominantly feature single-turn or very short multi-turn dialogues that fail to capture real-world interaction dynamics, such as the system requesting missing information, the user failing to provide it, or the need to chain multiple APIs when one API's output serves as another's input. This limitation makes it difficult to assess whether modern LLMs can handle the complex, multi-step tool-use scenarios encountered in practice.

## Input / Output

The model receives a dialogue history of user and system utterances, a sequence of structured reasoning steps (each containing a thought, action label, retriever status with scored API candidates, retrieved API documentation, and a dialogue state dictionary), and the current user utterance. Outputs are threefold: a dialogue state (confirmed API name plus required/optional parameter slots with extracted values), a next system action from a 16-action taxonomy, and a natural-language response grounded in the API call result. The dialogue state format distinguishes between confirmed and unconfirmed API status and tracks both required and optional parameters separately.

## Method

The paper introduces a four-step data generation pipeline. First, an API graph is constructed over 4,474 RapidAPI endpoints using a three-criteria edge rule combining SBERT embedding similarity of entity descriptions, embedding similarity of description+keyword concatenations, and longest-common-subsequence similarity of entity names, yielding 4,857 validated edges (70.9% precision). Second, 16 user/system actions are defined and 23 plausible action sequences are enumerated, covering scenarios like vague intent, clarification, suggestion, user failure to inform, and multi-result selection. Third, for each dialogue, a compatible API pair and action sequence are sampled, then GPT-4o generates concrete dialogue states (parameter values) and scenario instructions. Fourth, GPT-4o converts the augmented action sequence into natural utterances, with predefined speaking styles to reduce monotony. For evaluation, models are tested zero-shot on three tasks (DST, action prediction, faithfulness) in both with-GT and without-GT settings, and Llama3-8B is instruction-tuned on ToolDial (TD-Llama) to demonstrate the dataset's training utility.

## Results

On the ToolDial benchmark, GPT-4o achieves the highest Dialogue State Tracking accuracy (81.4% wGT, 67.8% w/o GT) among GPT models, while GPT-4-turbo leads in Action Prediction (64.2% wGT, 61.5% w/o GT). All GPT-based models score below 70% on action prediction, indicating substantial room for improvement. Fine-tuning Llama3-8B on ToolDial (TD-Llama) yields the strongest overall performance: 92.7% DST (wGT), 91.0% Action Prediction (w/o GT), and 77.1% joint action+DST accuracy, though faithfulness drops to 88.4% compared to GPT models' 95–97%.

## Baselines & Comparisons

As a benchmark paper, ToolDial evaluates seven off-the-shelf LLMs (GPT-3.5-turbo, GPT-4o-mini, GPT-4-turbo, GPT-4o, CodeLlama-7B, Qwen2.5-Coder-7B, Llama3-8B) in zero-shot settings, plus a fine-tuned variant (TD-Llama). Among GPT models, GPT-4o leads on DST (81.4% wGT) but GPT-4-turbo leads on Action Prediction (64.2% wGT); all GPT models remain below 70% on action prediction, with particularly poor F1 on 'Request' (13.7–44.3%), 'Clarify' (1.3–64.5%), and 'Suggest' (0–46.1%). Smaller open-source models (Llama3-8B, CodeLlama-7B) underperform GPT models across all tasks, with Llama3-8B scoring only 37.7% on action prediction. Fine-tuning Llama3-8B on ToolDial (TD-Llama) substantially closes the gap, surpassing all GPT models on both DST (92.7% wGT) and Action Prediction (77.5% wGT, 91.0% w/o GT), though it trails on faithfulness (88.4% vs. 95–97%). Overall, the paper demonstrates that even the strongest models achieve only 28.3% accuracy on generating correct reasoning traces across all turns of a dialogue, highlighting the difficulty of multi-turn tool-augmented interaction.

## Relation to Prior Work

This paper sits at the intersection of task-oriented dialogue (TOD) systems and tool-augmented language models (TALMs). It borrows the rich action taxonomy and dialogue state tracking formalism from TOD (MultiWOZ, SGD) and the API-calling paradigm from TALM benchmarks (ToolBench, API-Bank, ToolNet), but departs from both in key ways: unlike ToolNet's API graph which merely connects back-to-back APIs, ToolDial's graph encodes input/output compatibility between APIs; unlike SGD's generation pipeline which uses a limited set of APIs with no failure scenarios, ToolDial simulates 16 user/system actions including 'Fail inform' and chained API calls. The data generation approach (action sequence skeleton → dialogue state augmentation → GPT-4o utterance generation) is explicitly modeled on SGD but scaled to real-world RapidAPI documentation.

## Why It Matters / Open Questions

ToolDial fills a clear gap: no prior TALM benchmark captures the full complexity of multi-turn interactions where users fail to provide information, APIs must be chained, and the system must proactively request or clarify. The finding that even GPT-4o scores below 70% on action prediction—and that all GPT models achieve 0% F1 on 'Response fail'—reveals a systematic tendency to rush toward answers rather than gather information, which is a practical concern for deployed tool agents. The 28.3% full-dialogue correctness rate for TD-Llama highlights that multi-turn reasoning remains far from solved. Open questions include whether the GPT-4o-generated dialogues introduce distributional biases, whether the 2-API limit generalizes to longer chains, and whether the 70.9% edge precision in the API graph is sufficient for broader coverage.
