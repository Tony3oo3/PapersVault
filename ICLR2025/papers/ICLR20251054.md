## Problem

While LLMs can generate formal proofs in Lean, no prior method exists for *optimizing* an existing correct proof against an arbitrary user-defined criterion such as length, declarativity, or readability. Naively prompting a language model to rewrite a proof for a given metric produces incorrect or poorly optimized results, leaving a gap between proof generation and proof refinement that is critical for library maintenance, pedagogy, and data augmentation for downstream learning tasks.

## Input / Output

ImProver consumes a Lean 4 theorem statement, the surrounding file context (imports and preceding definitions), an initial tactic proof, and a user-specified optimization metric (length, declarativity, mixed, or completion). It outputs a rewritten Lean 4 tactic proof that compiles correctly and improves on the metric score. The output format is configurable as a plain string, a list of tactic strings, or a tree of strings, with the string-list format found to be optimal in ablations. The metric is evaluated symbolically by the Lean compiler (e.g., counting tactic invocations or `have` statements), so correctness is verified by actual compilation rather than model self-assessment.

## Method

ImProver is a GPT-4o-based agent that layers four key improvements over a black-box LLM generator. First, Chain-of-States (CoS) prompting uses Lean's metaprogramming API to symbolically extract intermediate proof states (hypotheses, goals, metavariable contexts) at each tactic step and inject them as comments into the proof text, giving the model explicit symbolic context analogous to chain-of-thought. Second, MMR-based retrieval-augmented generation pulls relevant syntax documentation from the TPiL handbook and theorem/lemma references from Mathlib, plus k human-written optimization examples for the target metric. Third, a compound sampling strategy combines best-of-n selection (prioritizing correctness, then metric delta) with iterative refinement that forwards error messages and previous outputs across steps. Fourth, error correction with syntax guidance feeds Lean compiler error messages back into the prompt to drive self-debugging. The optimal configuration—5-step refinement with best-of-3 per iteration, RAG enabled, 10 examples, string-list output, and CoS—achieves 100% accuracy and substantially outperforms the unmodified GPT-4o baseline across undergraduate, competition, and research-level theorems.

## Results

Across all datasets aggregated, ImProver achieves a 20.96% average length improvement (vs. 3.7% for GPT-4o), a 9.34-point declarativity improvement (vs. 2.21%), and a 27.31-point mixed metric improvement (vs. 3.51%). ImProver reaches 100% accuracy on all metrics, compared to 26.36% (length), 18.75% (declarativity), and 14.70% (mixed) for GPT-4o. When a correct output is generated, ImProver achieves a 55.29% average length reduction and a 30.53-point declarativity gain, substantially exceeding GPT-4o's 15.15% and 8.02-point improvements respectively.

## Baselines & Comparisons

ImProver is compared against prompted GPT-4o (without any of the proposed improvements) as the primary baseline across all proof optimization tasks. ImProver outperforms GPT-4o by 566% on the length metric, 423% on declarativity, and 778% on the mixed metric in aggregate improvement score, while also achieving 100% accuracy versus GPT-4o's 14–26% accuracy range. The gap is consistent across individual datasets: on the hardest dataset (Mathlib research-level theorems), GPT-4o achieves 0% improvement on both length and declarativity, while ImProver still achieves 6.19% and 4.63% respectively. On the neural theorem proving evaluation (Table 8), ImProver outperforms GPT-4o on all subsets (e.g., 39.13% vs. 21.73% on MIL Pass@15), but is outperformed by the specialized Lean Expert Iteration model (34.5% vs. 16.39% on MiniF2F-test Pass@8), which the authors attribute to Lean Expert Iteration being fine-tuned specifically for theorem proving on a large Lean corpus.

## Relation to Prior Work

ImProver repurposes a suite of techniques from code generation and neural theorem proving—chain-of-thought prompting (adapted as Chain-of-States), iterative self-refinement, MMR-based retrieval-augmented generation, and documentation retrieval—into a unified agent for a task that prior work has not addressed: rewriting an existing correct proof to optimize an arbitrary user-defined metric. The paper explicitly positions proof optimization as a strict generalization of neural theorem proving (where the initial proof is empty and the metric is correctness), building on the prover-verifier game framework and retrieval-augmented Lean proving systems like LeanDojo and MiniCTX. Unlike prior NTP systems that generate proofs from scratch, ImProver operates on a given proof and applies best-of-n sampling, compound refinement, and symbolic state annotation to produce a metric-optimized rewrite while preserving correctness.

## Why It Matters / Open Questions

The paper provides a practical tool for maintaining and improving formal proof libraries (e.g., Mathlib) and for generating structured training data (declarative proofs for sketch-and-prove pipelines), addressing a real bottleneck in formal mathematics. Key limitations include reliance on expensive proprietary LLMs (GPT-4o), intentionally simplistic metrics that admit degenerate solutions, and the fact that 100% accuracy is partly a design artifact (falling back to the input proof). Open questions include whether fine-tuning smaller open-source models can match the agent's performance, how to design metrics that better capture human notions of proof quality, and whether the correctness bottleneck identified here persists with more capable base models.
