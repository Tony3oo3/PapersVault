## Problem

Agentic workflows—structured sequences of LLM invocations with detailed instructions—are essential for solving complex tasks but require substantial human effort to design, limiting scalability and cross-domain transfer. Existing automated approaches either constrain the search space (e.g., DSPy optimizes prompts within fixed workflows), fail to capture workflow diversity (e.g., GPTSwarm's graph structure cannot express conditional logic), or use inefficient search algorithms (e.g., ADAS's linear heuristic struggles to find effective workflows within limited iterations). No prior method achieves fully automated, efficient discovery of diverse, high-performing workflows across domains.

## Input / Output

AFLOW takes a task type (e.g., 'solve math problems'), a benchmark dataset split 20/80 into validation and test sets, an explicit evaluation function (solve rate, F1, pass@1), and a set of predefined operators as input. The validation set is further filtered to high-variance instances for efficient feedback. The output is an optimized agentic workflow expressed as executable Python code, where LLM-invoking nodes are connected by code-based edges (loops, conditionals, function calls) that control data flow between nodes. The generated workflow is model-agnostic and can be transferred to different executor LLMs (GPT-4o-mini, DeepSeek-V2.5, GPT-4o, Claude-3.5-sonnet) without modification.

## Method

AFLOW formulates workflow optimization as a search problem over code-represented workflows and navigates this space using a variant of Monte Carlo Tree Search (MCTS). Each tree node represents a complete workflow (not a single LLM call), and the search iterates through four phases: (1) soft mixed probability selection combining uniform and score-based softmax over top-k workflows plus the initial blank template to balance exploration and exploitation; (2) LLM-based expansion where an optimizer LLM (Claude-3.5-sonnet) modifies the selected workflow's code—adding operators, altering prompts, or restructuring edges—guided by tree-structured experience that records all past modifications with their scores and success/failure labels; (3) execution evaluation running the new workflow 5 times on the validation set for robust scoring; and (4) backpropagation storing the modification, score, and parent-child relationship in the tree. Key differentiators from ADAS include: tree-structured experience (vs. linear list) enabling precise reuse of successful paths and avoidance of failures, predefined operators (Ensemble, Review & Revise, Test, Programmer) as reusable building blocks that reduce search space, and the soft mixed probability mechanism that prevents local optima by always retaining the blank template as a selection candidate.

## Results

AFLOW achieves an average score of 80.3% across six benchmarks (HotpotQA, DROP, HumanEval, MBPP, GSM8K, MATH), outperforming the best manually designed method (CoT SC at 76.0%) by 5.7% and the prior automated method ADAS (67.2%) by 19.5%. On the most challenging tasks, AFLOW improves over ADAS by 57% on MATH (56.2% vs. 35.4%) and MBPP (83.4% vs. 53.4%). Additionally, AFLOW enables smaller models (e.g., DeepSeek-V2.5) to match or exceed GPT-4o IO performance at only 4.55% of its inference cost on HumanEval.

## Baselines & Comparisons

AFLOW outperforms all six baselines across every benchmark. Against the strongest manual baseline, CoT SC (Wang et al., 2022, avg 76.0%), AFLOW gains +4.3 points on average, with the largest margins on MBPP (+9.8) and MATH (+5.8). Compared to CoT (Wei et al., 2022, avg 74.7%), MedPrompt (Nori et al., 2023, avg 75.3%), and MultiPersona (Wang et al., 2024a, avg 75.1%), AFLOW leads by 5.6, 5.0, and 5.2 points respectively. Against Self-Refine (Madaan et al., 2023, avg 70.7%), AFLOW achieves a 9.6-point advantage, with Self-Refine actually underperforming even the simple IO baseline on HotpotQA (60.8 vs. 68.1). The most dramatic comparison is against ADAS (Hu et al., 2024, avg 67.2%), the only other fully automated workflow optimizer: AFLOW surpasses it by 13.1 points on average, with particularly large gaps on MATH (+20.8) and MBPP (+30.0), indicating that MCTS-based search with tree-structured experience is substantially more effective than ADAS's linear heuristic approach.

## Relation to Prior Work

AFLOW extends the code-based workflow representation introduced by ADAS (Hu et al., 2024) by replacing its linear heuristic search with a Monte Carlo Tree Search that preserves tree-structured exploration experience across iterations. It also departs from graph-based approaches like GPTSwarm (Zhuge et al., 2024) and prompt-only optimizers like DSPy (Khattab et al., 2024) by treating the entire workflow structure—nodes, edges, and prompts—as a unified search space navigated by an LLM optimizer. The introduction of 'operators' as reusable, predefined node combinations (Ensemble, Review & Revise, Test, etc.) is a practical innovation that constrains the search space to leverage known effective agentic patterns, distinguishing AFLOW from both fully open-ended code search and fixed-template prompt optimization.

## Why It Matters / Open Questions

The most practically significant finding is that AFLOW-discovered workflows enable smaller, cheaper models (GPT-4o-mini, DeepSeek-V2.5) to match or exceed GPT-4o's performance at roughly 4–8% of the inference cost, which has direct implications for deploying agentic systems at scale. However, the framework is currently limited to reasoning tasks with explicit numerical evaluation functions, leaving open the question of how it generalizes to open-ended generation, multi-turn dialogue, or tasks requiring subjective evaluation. The ablation showing AFLOW autonomously converges on ensemble-like structures without predefined operators suggests the search process itself can rediscover known best practices, but whether this holds for more complex or novel task families remains untested.
