## Problem

Current LLM agent design relies heavily on manual, task-specific engineering, and existing automated approaches (prompt optimization, unconstrained code-space search) cannot explicitly recombine the strengths of agentic modules discovered in separate codebases and research efforts. This paper introduces Modularized LLM Agent Search (MoLAS), a new problem that frames agent optimization as searching over a modular design space with standardized IO interfaces, enabling systematic reuse and recombination of prior successful designs.
![Teaser figure](../imgs/ICLR20250139/cropped_page1_idx0.webp)

## Input / Output

The method takes a task description, four module pools (planning, reasoning, tool use, memory) where each module exposes a uniform IO interface (e.g., Planning: (task, feedback) → sub-task sequence; Reasoning: (sub-task, feedback) → solution; Tool Use: (problem, tool pool) → tool selection; Memory: (observation, DB) → retrieved knowledge), and an experience pool recording performance scores of previously evaluated module combinations. It outputs an optimized agent as a specific tuple (P, R, T, M) drawn from the Cartesian product of the four module pools, along with human-interpretable design insights explaining why the discovered combination is effective. The search space is initialized from 16 popular LLM agents yielding 1050 possible combinations, and is open-ended since new modules with the same IO contract can be generated during search.

## Method

AgentSquare alternates between two operations within an iterative loop: (1) module evolution, which uses an evolutionary meta-prompt (inspired by FunSearch) to generate entirely new module code by jointly modeling the task description, existing modules as in-context examples, and performance feedback from the experience pool; and (2) module recombination, which uses an LLM as a self-adaptive proposer to strategically swap modules from the pool into the current best agent, broadening exploration beyond local prompt-level edits. A performance predictor LLM serves as an in-context surrogate model during recombination, scoring candidate agents from their module profiles and past performance examples to skip unpromising combinations at ~0.025% of the cost of a full environment evaluation. New modules from evolution are always real-tested and appended to the module pools, while recombination candidates are filtered by the predictor before the best is promoted to the next episode. The search terminates after 5 consecutive iterations without improvement, and the discovered agents achieve an average 17.2% performance gain over the best hand-crafted designs across six benchmarks.

## Results

On GPT-4o, AgentSquare achieves the best performance across all six benchmarks: 0.607 on WebShop, 0.695 on ALFWorld, 0.781 on SciWorld, 0.524 on M3ToolEval, 0.583 on TravelPlanner, and 0.669 on PDDL. Compared to the best hand-crafted agent per task, AgentSquare yields an average 17.2% relative improvement (ranging from 6.0% on TravelPlanner/PDDL to 30.6% on M3ToolEval). The performance predictor reduces evaluation cost to ~0.025% of a full real-environment evaluation, enabling the search to complete in 8–18 iterations depending on the task.

## Baselines & Comparisons

AgentSquare outperforms all 12 hand-crafted agents on every benchmark; the largest gaps are on ALFWorld (0.695 vs. Self-refine's 0.567, +22.6%) and M3ToolEval (0.524 vs. Dilu's 0.475, +10.3%), while the smallest is on SciWorld (0.781 vs. Voyager's 0.776, +0.6%). Against module-search baselines, AgentSquare beats Bayesian search by 5.8–12.8% and Random search by 6.9–13.6% across tasks. Compared to the prompt-search baseline OPRO, AgentSquare achieves substantially higher scores (e.g., 0.695 vs. 0.380 on ALFWorld, 0.781 vs. 0.569 on SciWorld), confirming that searching in the modular design space is far more effective than prompt-level rewriting. Against the closest agent-search baseline ADAS, AgentSquare wins on all six tasks with margins of 1.7–56.3% (e.g., 0.695 vs. 0.543 on ALFWorld, 0.583 vs. 0.373 on TravelPlanner), though the authors note ADAS could potentially close the gap with more iterations given its unconstrained code-space search.

## Relation to Prior Work

This paper positions itself as a constrained and structured alternative to ADAS (Hu et al., 2024), which searches the entire agentic system in unconstrained code space. The key departure is the introduction of a modular design space with four standardized IO interfaces (Planning, Reasoning, Tool Use, Memory), enabling cross-system recombination that ADAS's code-level search cannot easily support. The module evolution mechanism draws directly from FunSearch's iterative prompt-and-evaluate pipeline, while the performance predictor borrows the in-context surrogate model idea from LLM-based NAS work (Jawahar et al., 2023; Chen et al., 2024a). Unlike OPRO and Promptbreeder, which optimize only the prompt of a fixed agent, AgentSquare operates at the module level, treating each functional component as an independently evolvable and recombining unit.

## Why It Matters / Open Questions

The modular design space offers a practical platform for the agent research community to accumulate and reuse validated modules across different systems, addressing the fragmentation problem where each paper's agent lives in an isolated codebase. The 17.2% average gain over best human designs across six diverse benchmarks is substantial and suggests that systematic search over module combinations can outperform expert intuition. However, the four-module abstraction may not capture all relevant design dimensions (e.g., multi-agent interaction patterns, control flow topology), and the approach remains single-agent focused. Open questions include whether the modular decomposition generalizes to multi-agent settings, how to handle modules with non-trivial interdependencies, and whether the performance predictor degrades as the experience pool grows heterogeneous.
