## Problem

While LLMs have been applied to automate Operations Research modeling, they produce solutions without meaningful explanations, undermining transparency and user trust. Existing explainable optimization methods (e.g., OptiGuide) handle only simple parameter changes and provide superficial summaries that lack quantitative depth, failing to address complex constraint modifications such as deleting or combining constraints. This paper addresses the gap by formulating explainable OR as a distinct problem and introducing a framework that delivers actionable, quantitatively grounded explanations for both code modifications and solution outcomes.

## Input / Output

The system takes an OR problem description in natural language, a user what-if query (e.g., 'limit Type A aircraft to 15'), and the original Gurobi Python code as input. It produces updated code in a structured JSON format with constrained keys (DELETE CONSTRAINT, ADD CONSTRAINT, ADD DATA) inserted at predefined markers, ensuring targeted modifications without regenerating the full program. The explanation output is structured into two parts—Explanation of Updated Code and Explanation of Query on Results—and is accompanied by a Normalized Graph Edit Distance (NGED) score that quantitatively measures the structural impact of the query on the optimization model.

## Method

EOR is a three-agent multi-agent system (Commander, Writer, Safeguard) built on AutoGen that iteratively modifies OR code and generates explanations. The Commander routes queries, the Writer performs code edits and produces explanations, and the Safeguard verifies code safety before execution, triggering a debug loop if unsafe code is detected. The core technical contribution is the 'Decision Information' concept, quantified through a three-step pipeline: (1) converting both original and updated code into standardized linear program form, (2) transforming each LP into a bipartite graph with constraint nodes and decision-variable nodes whose attributes encode bounds and objective coefficients, and (3) computing the Graph Edit Distance between the two graphs with unit cost per attribute mismatch, normalized by graph size to yield NGED. LLMs are then prompted to interpret these quantitative measures and generate narrative, non-technical justification explanations that connect specific constraint changes to their numerical impact on the solution. The framework is evaluated in zero-shot and one-shot settings across four GPT-4 variants on a new industrial benchmark of 30 problems × 10 expert-crafted queries.

## Results

On the EOR Benchmark (30 industrial OR problems × 10 queries each), EOR achieves 88.33% modeling accuracy with GPT-4-Turbo in the zero-shot setting and 95.33% in the one-shot setting, substantially outperforming both baselines. For explanation quality (0–10 scale), EOR scores 9.47 (Overall, auto) and 9.47 (Overall, expert) in zero-shot, compared to 5.36/5.63 for Standard and 6.31/6.59 for OptiGuide. The automated LLM-based evaluation closely tracks expert human scores (within ~0.1–0.5 points), validating its reliability as a scalable assessment tool.

## Baselines & Comparisons

EOR is compared against two baselines: Standard (a proprietary LLM generating full updated code and explanations) and OptiGuide (Li et al., 2023, a supply-chain-specific what-if analysis method). EOR wins decisively on modeling accuracy in every configuration: in zero-shot, EOR leads by 12–58 percentage points over Standard and by 25–58 points over OptiGuide; in one-shot, the margins narrow to 2–26 points over Standard and 12–36 points over OptiGuide. On explanation quality, the gap is even more pronounced—EOR scores ~9.4–9.8 on both Explanation of Correctness (EC) and Explanation of Results (ER), while Standard's EC auto-score is near zero (0.12–0.34) and OptiGuide's is similarly low (0.20–0.69), indicating that neither baseline provides meaningful justification explanations. OptiGuide performs best on GPT-4 (75.00% one-shot accuracy) but degrades sharply on other model versions, whereas EOR maintains consistent high performance across all four LLMs. The paper also shows that one-shot prompting improves all methods (e.g., OptiGuide on GPT-4 jumps from 30.33% to 75.00%), but EOR benefits most in absolute terms, reaching 95.33%.

## Relation to Prior Work

This paper extends the explainable-optimization line (Erwig & Kumar, 2024; De Bock et al., 2024; OptiGuide/Li et al., 2023) by handling complex what-if scenarios—deleting, adding, or combining constraints—rather than the parameter-only sensitivity analysis those prior works support. It borrows the LP-to-bipartite-graph conversion and unit-cost Graph Edit Distance methodology from Xing et al. (2024) to quantify 'Decision Information,' a concept the paper formalizes for the first time in the OR-explainability context. The multi-agent architecture (Commander/Writer/Safeguard) is instantiated on AutoGen and departs from prior LLM-for-OR work (Xiao et al., 2023; Tang et al., 2024; Zhang et al., 2024), which focused on modeling accuracy and code generation rather than post-hoc justification of solutions.

## Why It Matters / Open Questions

EOR provides the first industrial benchmark (30 problems × 10 expert-crafted queries) specifically targeting explanation quality in OR, filling a gap left by existing datasets (NL4OPT, ComplexOR, IndustryOR) that only cover problem-to-code translation. The unified GED-based quantification of constraint and parameter changes offers a practical, solver-agnostic metric that could be adopted across OR tooling. Key limitations include evaluation on a single LLM family (GPT-4 variants), a small benchmark, the assumption that decision variables remain fixed, and reliance on LLM-as-judge for explanation scoring (partially mitigated by expert review). Open questions include scaling to mixed-integer and non-LP problems, incorporating user-in-the-loop feedback, and whether the bipartite-graph GED generalizes beyond linear formulations.
