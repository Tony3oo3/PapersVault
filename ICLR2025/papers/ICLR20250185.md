## Problem

Open-source VLM-based GUI action models significantly underperform commercial models like GPT-4o in GUI grounding and out-of-distribution generalization. This gap stems from two factors: the absence of large-scale, multi-platform GUI screenshot pretraining corpora (most existing data is web-only), and inconsistent action naming across platforms (e.g., 'tap' vs. 'click') that confuses models during multi-task fine-tuning.
![Teaser figure](../imgs/ICLR20250185/cropped_page1_idx0.webp)

## Input / Output

The model consumes GUI screenshots (rendered at 1920×1080 for web; native resolutions for desktop/mobile), a natural language instruction or referring expression, and optionally an action history. It outputs element coordinates as normalized points or bounding boxes in [0,1000] range, an action type drawn from a unified action space (3 basic actions: click, type, scroll; plus platform-specific custom actions like open_app, drag), and a chain-of-thought rationale. The unified action space collapses 17 platform-specific action labels into 10 standardized ones, eliminating cross-platform naming conflicts.

## Method

OS-Atlas is trained in two phases: (1) GUI grounding pre-training on a 13.5M-element, 2.3M-screenshot corpus spanning Windows, macOS, Linux, Android, and the Web, collected via a novel multi-platform synthesis toolkit that crawls FineWeb URLs for web data and uses A11y-tree extraction (pyatspi, pywinauto, ApplicationServices) with DFS/Random Walk exploration for desktop and mobile; (2) action fine-tuning on agent trajectory datasets using a unified action space that standardizes action formats across all platforms. The model is built on InternVL-2-4B (AnyRes tiling) or Qwen2-VL-7B (dynamic visual tokens) backbones. The key insight is that large-scale cross-platform grounding pre-training combined with a conflict-free action space enables strong zero-shot OOD generalization, with the unified action space reducing unique action types from 17 to 10 and resolving naming collisions like 'tap'/'click' and 'press_home'/'home'.

## Results

On ScreenSpot (standard setting, no planner), OS-Atlas-Base-7B achieves 82.47% average grounding accuracy across mobile, desktop, and web, outperforming the previous SOTA UGround-7B (74.15%) by 8.3 points and SeeClick (55.75%) by 26.7 points. In the zero-shot OOD agent setting, OS-Atlas-7B surpasses GPT-4o on all six benchmarks, e.g., achieving 57.02% step success rate on GUI-Act-Web vs. GPT-4o's 41.84%, and 59.99% on OmniAct-Web vs. 34.06%. Under supervised fine-tuning, OS-Atlas-7B reaches 94.05% SR on OmniAct-Desktop and 93.56% on OmniAct-Web, matching or exceeding Qwen2-VL-7B and SeeClick across all platforms.

## Baselines & Comparisons

OS-Atlas-Base-7B decisively outperforms all prior open-source grounding models on ScreenSpot: it leads UGround-7B (the closest competitor) by 8.3 points in average accuracy (82.47 vs. 74.15), SeeClick by 26.7 points (82.47 vs. 55.75), and CogAgent by 32.9 points. The gap is most pronounced on desktop icon/widget grounding (62.86 vs. 63.60 for UGround, but 62.86 vs. 30.00 for SeeClick) and web text grounding (90.87 vs. 80.40 for UGround, 55.70 for SeeClick). In the zero-shot OOD agent setting, OS-Atlas-7B beats GPT-4o on step success rate across all six benchmarks (e.g., 57.02% vs. 41.84% on GUI-Act-Web; 56.73% vs. 50.67% on OmniAct-Desktop), though GPT-4o retains a slight edge on OmniAct-Desktop grounding (63.25 vs. 62.87). Under supervised fine-tuning, OS-Atlas-7B matches or slightly exceeds Qwen2-VL-7B on most metrics (e.g., 91.60% vs. 90.66% grounding on GUI-Act-Web) and substantially outperforms SeeClick on grounding (91.60% vs. 78.59% on GUI-Act-Web; 95.85% vs. 70.22% on OmniAct-Desktop). The 4B variant (InternVL-2 backbone) is competitive with the 7B variant on mobile tasks but lags on desktop, highlighting the benefit of the Qwen2-VL backbone for cross-platform generalization.

## Relation to Prior Work

This paper extends the GUI grounding line of work (SeeClick, CogAgent, UGround) from single-platform or web-centric settings to a truly cross-platform foundation model spanning Windows, macOS, Linux, Android, and the Web. Conceptually, it draws from the Large Action Model (LAM) paradigm for function-calling (XLAM, AgentTuning) but is the first to instantiate this specifically for GUI agents. The key methodological departure is the unified action space, which resolves cross-platform naming conflicts (e.g., 'tap' vs. 'click') that prior multi-dataset training pipelines ignored, and the data infrastructure that automates grounding data synthesis across operating systems using platform-specific accessibility APIs (pyatspi, pywinauto, ApplicationServices) rather than relying solely on web crawlers.

## Why It Matters / Open Questions

The release of a 13M-element, 2.3M-screenshot open-source cross-platform GUI grounding corpus and its synthesis toolkit removes a major data bottleneck for the GUI agent community, particularly for desktop platforms where prior open data was essentially absent. The demonstration that a 7B open-source model can match or exceed GPT-4o on zero-shot OOD agent tasks across six benchmarks is practically significant for researchers who cannot rely on closed APIs. Open questions remain: desktop data is still an order of magnitude smaller than web data (54K vs. 1.9M screenshots), the gap to human performance on OSWorld (8.91% vs. 73.27%) is substantial, and the paper's own scaling-law analysis suggests substantial headroom that has not yet been exploited.
