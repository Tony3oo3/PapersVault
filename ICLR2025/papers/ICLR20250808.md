## Problem

Existing inference-scaling methods for LLM code generation—best-of-N sampling, line search, and tree search—produce highly similar candidate solutions, leading to insufficient exploration of the code space and premature convergence to local optima. The paper asks how optimization-inspired techniques can be adapted to make LLM-based search over code space more diverse and efficient, so that correct solutions are found faster and scaling with compute is more effective.
![Teaser figure](../imgs/ICLR20250808/cropped_page0_idx0.webp)

## Input / Output

The method takes a natural-language code prompt (e.g., a function specification) and optionally a set of validation tests (either self-generated by the LLM as assert statements or a subset of ground-truth hidden tests). The solver is never shown the full hidden test suite. Output is a single Python code solution selected as the best across an entire forest of MCTS search trees, where 'best' is determined by the proportion of validation tests passed. Each iteration requires two LLM API calls (one for code generation conditioned on a textual direction, one for reflection/insight extraction), and the full search runs for a fixed budget of N iterations (typically 10–40).

## Method

SFS frames code generation as black-box optimization over code space and augments MCTS with three optimization-inspired techniques. SCATTERING prompts the LLM to first propose multiple diverse textual improvement directions (analogous to trust-region steps or textual gradients) before generating each child solution, ensuring branches explore orthogonal regions rather than near-duplicates. FORESTING initializes the search from multiple diverse seed solutions (multi-start optimization), with UCT dynamically selecting which seed tree to expand at each iteration. SCOUTING, inspired by ant colony and particle swarm optimization, stores general insights about effective or ineffective directions in a global memory shared across all branches, intensifying exploitation around promising textual directions. A Markov-chain analysis shows that SCATTERING's diverse transition kernel increases the chain's conductance relative to prior methods, reducing mixing time and the probability of being trapped in local regions of the solution space.

## Results

SFS achieves a pass@1 of 67.1% on HumanEval+ and 87.2% on HumanEval (with 3 ground-truth tests), outperforming the prior best (LATS at 75.6% and LDB at 82.9% respectively) by 8.6% and 4.3%. Across all five benchmarks, SFS consistently leads: 65.7% on MBPP+, 36.7% on Leetcode, 20.5% on APPS, and 4.24% on CodeContests. SFS also discovers the correct solution in just 1.67 iterations on average (vs. 2.09–3.04 for baselines), halving the search effort needed compared to line search and best-of-N sampling.

## Baselines & Comparisons

SFS outperforms all baselines across every benchmark. Against the closest internal baselines, SFS beats Best-of-N by 1.9 pp on HumanEval+ (67.1% vs. 65.2%) and by 3.4 pp on Leetcode (36.7% vs. 33.3%), while Tree(MCTS) lags by 7.3 pp on HumanEval+ (59.8%) and Line Search underperforms the base model on HumanEval+ (53.0% vs. 58.5%). Against prior SOTA methods (Table 4), SFS achieves 82.5% on HumanEval, surpassing LATS (75.6%), Reflexion (68.1%), RAP (63.1%), ToT (54.4%), ReAct (56.9%), and CoT (46.9%); on MBPP it reaches 81.7% vs. LATS 79.6% and RAP 71.4%. In the ground-truth-test setting (Table 5), SFS achieves 87.2% on HumanEval-3 and 91.3% on MBPP-1, beating LDB (82.9% / 76.0%) and Self-Debug (81.1% / 74.4%) by 4.3 pp and 15.3 pp respectively. The genetic algorithm baseline (Romera-Paredes et al., 2024) is also outperformed, with SFS requiring 5.06 iterations (excl.) versus 10.36 for the genetic approach. Notably, SFS is the only method that continues to improve up to 20 solutions generated, while all other methods plateau earlier.

## Relation to Prior Work

This paper builds on the inference-scaling literature (best-of-N sampling, line search/self-refinement, and tree search methods like LATS and ToT) by reframing code generation as a black-box optimization problem over the code space. It departs from prior tree search approaches, which rely on higher-temperature sampling for diversity, by introducing optimization-inspired mechanisms: SCATTERING (analogous to trust-region methods, using textual 'directions' as perturbations), FORESTING (multi-start initialization), and SCOUTING (inspired by ant colony and particle swarm optimization for cross-branch knowledge sharing). The theoretical grounding via Markov chain conductance and mixing time analysis is novel in this context, connecting LLM sampling diversity to classical stochastic optimization theory.

## Why It Matters / Open Questions

The paper demonstrates that solution diversity is the primary bottleneck in inference scaling for code generation, and that simple, parameter-free prompt-level interventions (scattering directions, diverse seeds, shared insights) can substantially improve both accuracy and scaling efficiency without additional training. A notable open question is the interaction with verifier quality: the ~27.5% false-negative rate of self-generated validation tests limits pass@1, and the paper shows that even a single ground-truth test dramatically improves results, suggesting that combining SFS with stronger verifiers could yield further gains. The finding that weaker models benefit disproportionately from inference scaling also raises practical questions about optimal allocation of training vs. inference compute. Limitations include evaluation primarily on Python function-level tasks and reliance on GPT-3.5/4o as the base model.
