## Problem

Existing function calling research for LLMs predominantly focuses on single-turn interactions—selecting the right function and filling in arguments—while overlooking the critical ability to plan with functions across multiple turns. Real-world compositional queries (e.g., 'book me the first flight from London to Edinburgh') require decomposing tasks into sequential or parallel function calls, yet no large-scale instruction tuning dataset with labeled multi-turn function calling trajectories exists, and obtaining such data without extensive manual annotation is unrealistic.

## Input / Output

The trained model receives a user query describing a compositional task along with a set of function definitions (name, description, parameters, responses, required fields) provided in the system prompt. It produces a multi-turn trajectory following a ReAct-like format: each assistant turn contains an observation, a thought/plan, and one or more function calls (including parallel calls when sub-tasks are independent); tool turns return simulated JSON results; and the final turn invokes a 'final_answer' function to deliver the response. The BUTTONInstruct dataset contains 8,000 such trajectories, most involving 3+ assistant turns and 2+ function calls per trajectory.

## Method

BUTTON is a two-phase synthetic data generation pipeline. In the bottom-up phase, atomic tasks (single-step, function-agnostic) are generated from real-world scenarios, then composed into complex tasks via two heuristic strategies—Sequential Composition (chaining a subsequent task that depends on the first's output) and Parallel-then-Sequential Composition (adding an independent parallel task before a dependent subsequent task). Function definitions are then generated with explicit awareness of the atomic sub-task breakdown, ensuring functions are general, granular, and parameter-consistent across sequential calls. In the top-down phase, a multi-agent environment simulates user, assistant, and tool roles (each steered by curated system prompts) to collect interaction trajectories; the assistant agent is given the task breakdown as a planning hint, and tool agents simulate function execution based on their definitions without actual implementations. This bottom-up-then-top-down design ensures compositionality of tasks, compatibility between functions and sub-tasks, and high-quality multi-turn trajectories without human supervision.

## Results

On GTA, Llama3-8B-BUTTON improves final answer accuracy from 1.4% (Llama3-8B-Instruct) to 30.5%, while Qwen2-72B-BUTTON reaches 45.7%, comparable to GPT-4o (46.0%). On Tool-Query, Qwen2-72B-BUTTON and Llama3-70B-BUTTON both achieve 58.3% success rate, substantially outperforming GPT-4o (40.0%) and their respective instruction-tuned baselines (41.7% and 31.7%). The grounding accuracy remains high (≥94%) across all models, indicating the key gains come from improved multi-turn planning rather than basic function-call formatting.

## Baselines & Comparisons

Against GPT-4o, Qwen2-72B-BUTTON achieves a near-tie on GTA final answer accuracy (45.7% vs. 46.0%) and clearly outperforms it on Tool-Query success rate (58.3% vs. 40.0%); Llama3-70B-BUTTON also beats GPT-4o on Tool-Query (58.3% vs. 40.0%). Against GPT-4-Turbo, all BUTTON-tuned models surpass it on GTA answer accuracy (e.g., Llama3-8B-BUTTON 30.5% vs. 30.6% is a tie, but Qwen2-72B-BUTTON 45.7% vs. 30.6% is a clear win) and on Tool-Query success rate. Against GPT-3.5-Turbo, the improvements are substantial across all metrics. Compared to their own instruction-tuned counterparts, the gains are most dramatic for smaller models: Llama3-8B jumps from 1.4% to 30.5% on GTA Ans. and from 5.0% to 35.0% on Tool-Query Success Rate, while Qwen2-7B improves from 13.1% to 27.3% on GTA Ans. The 70B/72B models show more modest but consistent gains (e.g., Llama3-70B: 40.1%→43.5% on GTA Ans.; Qwen2-72B: 27.3%→45.7%).

## Relation to Prior Work

This paper extends the function-calling literature (Gorilla, ToolLLM, APIGen) from single-turn function selection and argument filling to multi-turn function calling that requires planning and decomposition. It also draws on compositional instruction tuning work (Chain-of-Instruct, Sequential Instruction Tuning) but repurposes the compositionality idea specifically for tool-use trajectories rather than general instruction following. The bottom-up-then-top-down pipeline is a novel synthesis: it borrows the atomic-task decomposition idea from compositional instruction work and the multi-agent simulation paradigm from agent trajectory generation, but combines them in a way that ensures function definitions are grounded in the task's atomic structure rather than being collected independently first.

## Why It Matters / Open Questions

The paper identifies a genuine gap—most function-calling training data teaches models to pick one function and fill arguments, but real-world queries require sequencing and parallelizing multiple calls—and provides a practical 8k-point dataset (BUTTONInstruct) that closes it. The ablation cleanly separating 'can execute the right function' (process rate) from 'can plan the right sequence' (success rate) is a useful diagnostic for the field. Limitations include reliance on GPT-4o for all generation steps with no independent verification, a modest 8k data scale, and evaluation on only two benchmarks; open questions include whether the pipeline scales to embodied or multimodal tool use and whether the synthetic trajectories generalize beyond the distribution of GPT-4o's planning style.
