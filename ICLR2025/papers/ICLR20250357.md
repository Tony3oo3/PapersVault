## Problem

Existing agent benchmarks evaluate tool use in simplified, single-turn instruction-following settings where all information is provided upfront, without human-in-the-loop interaction or domain-specific policy adherence. This paper identifies that real-world deployment requires agents to (1) gather information incrementally through multi-turn dialogue with users, (2) follow complex domain-specific rules, and (3) maintain consistency across repeated interactions — none of which are tested by prior benchmarks.

## Input / Output

The agent receives a domain policy document as its system prompt, a set of API tool definitions (Python function signatures with JSON schemas), and natural-language messages from an LM-simulated user (gpt-4-0613 at temperature 1.0). The agent outputs either a tool call (e.g., `exchange_delivered_order_items(order_id=..., item_ids=..., ...)`) or a natural-language response to the user, with at most one action per turn. Evaluation is rule-based: the final database state is compared against a unique ground-truth state, and the agent's messages are checked for required information substrings, yielding a binary reward r = r_action × r_output. The novel pass^k metric then measures the probability that all k i.i.d. trials succeed, capturing reliability rather than peak capability.

## Method

τ-bench formulates each task as a POMDP where the state is the joint database and user state, and the agent acts over both API tools and user messages. The benchmark is constructed modularly in three stages: (1) manual design of database schemas, Python API implementations, and Markdown policy documents; (2) LM-assisted generation of scalable data entries (500 users, 50 products, 1000 orders for retail; 500 users, 300 flights, 2000 reservations for airline); and (3) manual task annotation with iterative verification using gpt-4-turbo function-calling trials to ensure each user instruction yields a unique database outcome. The user simulator is an LM conditioned on a hidden instruction specifying identity, intent, and preferences, generating open-ended utterances that vary across trials while preserving semantic intent. The key design choice is trading off task quantity for quality and evaluation speed: by guaranteeing a single correct database state per task, subjective human judgment is replaced by objective state comparison, enabling fast and faithful automated evaluation across many trials.

## Results

On τ-retail, the best model (gpt-4o with function calling) achieves 61.2% pass^1, while on the more complex τ-airline domain it drops to 35.2% (48.2% weighted average). Consistency degrades sharply with repeated trials: pass^8 for gpt-4o on τ-retail falls below 25%, revealing fragile agent behavior under stochastic conversation variation. Even the strongest open-weight models (Llama-3-70B at 14.8%/14.4%, Mixtral-8x22B at 17.7%/31.6%) trail proprietary models by a wide margin, and no model exceeds 50% on either domain.

## Baselines & Comparisons

The paper's primary method comparison (Figure 3) shows that natively supported function calling consistently outperforms text-formatted ReAct (Yao et al., 2023b) and its Act-only ablation across all tested models on both τ-retail and τ-airline. Adding reasoning traces in ReAct helps close the gap versus Act-only, but neither text-based method matches the performance of native function calling, suggesting that FC models are better aligned with structured tool invocation. Among models, gpt-4o leads on both domains (61.2% retail, 35.2% airline), followed by gpt-4-turbo (57.7%/32.4%) and claude-3-opus (44.2%/34.7%); notably, claude-3-opus nearly matches gpt-4o on τ-airline despite trailing on τ-retail. Open-weight models (Llama-3-70B, Mixtral-8x22B) remain 20–40 points behind the best proprietary models, highlighting a significant gap for open agent development. The pass^k consistency metric further differentiates agents: even gpt-4o's >60% average success on τ-retail collapses to <25% at pass^8, a reliability gap that no baseline method addresses.

## Relation to Prior Work

This paper unifies three previously separate evaluation threads—tool-use benchmarks (BFCL, ToolBench, MetaTool), task-oriented dialogue (MultiWOZ, rule-based user simulators), and LM-based user simulation (Generative Agents, ChatShop)—into a single benchmark that tests all three simultaneously. It departs from prior agent benchmarks by requiring multi-turn human interaction and domain-specific policy adherence rather than single-step instruction following, and repurposes LM user simulation (previously used to showcase simulation fidelity) as a mechanism for stress-testing agent consistency. The pass^k metric inverts the pass@k logic from code generation, shifting the evaluation question from 'can the agent find a solution in k tries?' to 'does the agent solve the task correctly in all k tries?'

## Why It Matters / Open Questions

The benchmark exposes a critical reliability gap: even GPT-4o with function calling achieves only ~61% on retail and ~35% on airline, with pass^8 collapsing below 25%, suggesting current agents are far from deployable in high-volume customer-service settings. The policy-ablation finding—that removing domain rules barely hurts GPT-4o on retail (−4.4%) but devastates it on airline (−22.4%)—reveals that models may be relying on commonsense shortcuts rather than actually reading and applying rules. Open questions include whether more sophisticated agent scaffolding (planning, memory, verification loops) can close the consistency gap, whether the benchmark's two simplified domains generalize to truly complex real-world policies (medical, legal), and how to scale the expensive manual annotation process to new domains.
