## Problem

When learning an input-output mapping from very few examples, is it better to first infer a latent function that explains the examples (induction) or to directly predict new test outputs (transduction)? Prior work reached contradictory conclusions—RobustFill found induction superior, while the leading ARC team advocated transduction—but no study had controlled for priors, data, and architecture to make a fair comparison. This paper shows that, given identical training problems and the same neural architecture, induction and transduction are strongly complementary, each solving a largely disjoint set of problems.

## Input / Output

Each ARC task provides K (typically 2–5) training input-output pairs of 2D colored grids (1–30 pixels per side, 10 colors) plus a single test input grid. Grids are encoded as text strings with one color-name token per pixel and newlines delimiting rows, so the model consumes them as natural-language sequences rather than raw pixel tensors. The transduction model outputs a predicted output grid directly; the induction model outputs a Python program (a transform function) that, when executed on the test input, produces the output grid. At test time the ensemble first samples B programs via induction, filters them against the training examples, and falls back to transduction's beam-search prediction only if no valid program is found.

## Method

Both models are initialized from Llama3.1-8B-instruct and meta-learned via fine-tuning on a synthetically generated corpus of 400k few-shot problems. The corpus is built from 100–160 human-written Python 'seeds' (each containing a natural-language description, a deterministic transform_grid function, and a stochastic generate_input function), which are mutated and recombined by a three-stage LLM pipeline: (1) GPT-4 samples new problem descriptions via in-context learning over seed descriptions, (2) GPT-4o-mini generates corresponding Python code via Retrieval-Augmented Generation over similar seeds, and (3) the generated code is executed to produce input-output grid pairs, with heuristic filtering for determinism, grid size, and color-permutation invariance. The induction model is trained to predict the ground-truth Python program given the training pairs and test input (induction loss), while the transduction model is trained to predict the output grid directly (transduction loss). At test time, induction samples up to 20k programs and uses majority vote over those consistent with the training examples; transduction uses beam search (size 20) optionally augmented with test-time training. The key empirical finding is that, despite sharing architecture and training data, the two models solve largely disjoint problem sets—induction excels at precise computations and multi-concept composition, while transduction handles fuzzier perceptual concepts—yielding a 54.4% ensemble accuracy on ARC validation, approaching the 60.2% human average.

## Results

On the 400-problem ARC public validation split, the best BARC ensemble (induction + transduction with test-time training, trained on ARC-Potpourri) achieves 54.375% accuracy (tasks solved in 2 tries), surpassing all previously published methods. The induction model alone (20k samples, majority vote) reaches 38.00%, while transduction with TTT reaches 39.25%, demonstrating strong complementarity. On ConceptARC, induction excels on compositional concepts (e.g., counting) while transduction handles perceptual concepts (e.g., orientation judgment). The best model approaches the average human performance of 60.2% but remains well below the best humans (97.8%).

## Baselines & Comparisons

BARC's ensemble (TTT) at 54.375% substantially outperforms all prior automated baselines: Greenblatt's GPT4o program sampling (42%), the 2020 ARC Kaggle winner Wind (39%), Claude-3.5 (21%), and CodeIt (15%). The gap over Greenblatt (12.4 points) is particularly notable since Greenblatt uses a much larger closed-source model (GPT4o) at test time, while BARC uses a fine-tuned Llama3.1-8B. Against the average human (60.2%), BARC closes most of the gap (within ~6 points), though it remains far below the best humans (97.8%). The paper also contrasts with Devlin et al. (2017, RobustFill), which found induction superior to transduction in neural program synthesis; here, with a richer function space, the two paradigms are strongly complementary rather than one dominating the other.

## Relation to Prior Work

This paper builds directly on Li & Ellis (2024), which fine-tuned LLMs for inductive program synthesis from LLM-generated variations of human-written programs, and incorporates test-time training (Sun et al., 2020) into the transductive pipeline. It departs from RobustFill (Devlin et al., 2017), which found induction superior to transduction in neural program synthesis, and from the leading ARC team (Cole et al., 2024), which advocates transduction with test-time training. The key methodological departure is a controlled comparison: both induction and transduction models share the same Llama3.1-8B-instruct backbone, the same synthetic training data, and the same priors (Python code), isolating the inductive/transductive distinction as the sole variable.

## Why It Matters / Open Questions

The finding that induction and transduction are strongly complementary—rather than one paradigm dominating—contradicts both prior theoretical expectations (kernel trick, universal approximation) and empirical results from RobustFill and the leading ARC team, suggesting that future systems need representations that intertwine symbolic and subsymbolic reasoning rather than choosing one. The scalable data generation pipeline (100–160 human seeds → 400k synthetic problems) offers a practical recipe for other few-shot function-learning domains. A key limitation is that the system bootstraps from manually encoded knowledge in seeds rather than discovering it autonomously, and the evaluation is confined to ARC; whether the complementarity finding generalizes beyond grid-based program synthesis remains open.
