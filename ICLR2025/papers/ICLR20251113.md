## Problem

Existing tool-use benchmarks for LLMs suffer from limited scenario coverage (often missing multi-turn or multi-tool settings), heavy reliance on GPT-based evaluation that incurs substantial API costs, and a lack of fine-grained metrics that capture tool ordering, parameter accuracy, and cascading error effects across dialogue turns. MTU-Bench addresses these gaps by providing a unified benchmark spanning five tool-use granularities with fully automatic, GPT-free evaluation.
![Teaser figure](../imgs/ICLR20251113/cropped_page0_idx0.webp)

## Input / Output

The model receives a system prompt containing the full tool documentation (JSON-defined API names, required/optional parameters with types and descriptions, and return schemas) along with the dialogue history and current user instruction. Output follows the ReAct format: a Thought trace explaining the reasoning, one or more Action lines naming the tool(s) to invoke, corresponding Action Input lines with JSON parameter-value pairs (including cross-tool references like 'previous_API.return_param'), and a final natural-language response. In multi-turn settings, Observation fields from prior simulated API calls are included in the context.

## Method

The core pipeline transforms six existing task-oriented dialogue datasets (MultiWOZ, SGD, TaskMaster, MetaLWOZ, ATIS, SNIPS) into tool-use data through five steps: (1) collecting dialogues with intents and slots, (2) creating tools via grammar-based intent-to-API conversion or GPT-4 synthesis for datasets lacking annotations, (3) clustering redundant tool names using InsTag embeddings with a fixed distance threshold (achieving ~20:1 reduction), (4) generating GPT-4-written tool documentation, and (5) synthesizing ReAct-style tool-use samples (thought, action, action input, observation, response) with GPT-4 followed by multi-stage quality filtering (heuristic rules, GPT-4 verification, and manual annotation). The evaluation framework MTU-Eval introduces six fine-grained metrics—Tool Selection Accuracy, Parameter Selection Accuracy, Success Rate, Averaged/Soft Turn Success Rate, Task Process Rate, Tool Number Accuracy, and Tool Order Accuracy—all computed purely from predicted vs. ground-truth outputs without any LLM-as-judge. The resulting MTU-LLaMA is obtained by instruction-tuning LLaMA3-8B-Instruct on the 54,367-dialogue MTU-Instruct training split.

## Results

On the normal MTU-Eval set, MTU-LLaMA (fine-tuned LLaMA3-8B) achieves 71.15 avg on S-S, 52.79 avg on M-S, 56.97 avg on S-M, and 30.70 avg on M-M, substantially outperforming its LLaMA3-8B initialization (48.08, 14.11, 17.55, 4.46 respectively). On the harder test set, MTU-LLaMA scores 37.5 (S-S), 43.10 (M-S), 39.31 (S-M), and 24.70 (M-M), remaining competitive with closed-source models like GLM-4-Plus (82.69, 47.61, 30.90, 39.53) and GPT-4 (77.88, 44.61, 58.07, 41.36). GPT-4 leads on the normal set across most metrics (e.g., 95.83 TS on S-S, 73.96 S-S avg), but GLM-4-Plus surpasses it on the hard set for S-S (82.69 vs. 77.88) and M-S (47.61 vs. 44.61), while Qwen-Max exceeds GPT-4 on hard M-M (45.08 vs. 41.36).

## Baselines & Comparisons

MTU-LLaMA dramatically outperforms its LLaMA3-8B-Instruct initialization across all four settings on the hard set (e.g., M-S: 43.10 vs. 12.85; M-M: 24.70 vs. 5.89), confirming the effectiveness of MTU-Instruct. Against the tool-use-specific baseline ToolLLaMA2-7B, MTU-LLaMA wins by a wide margin in every setting (e.g., S-M: 39.31 vs. 0.51), revealing ToolLLaMA's poor generalizability. Among closed-source models, MTU-LLaMA is competitive with GLM-4-Plus on M-S (43.10 vs. 47.61) and DeepSeek V2.5 on S-M (39.31 vs. 40.01), but trails GPT-4 on S-S (37.50 vs. 77.88) and S-M (39.31 vs. 58.07). Among open-source models, MTU-LLaMA surpasses Qwen2-72B on M-S (43.10 vs. 38.42) and S-M (39.31 vs. 37.14) but falls short on S-S (37.50 vs. 68.40) and M-M (24.70 vs. 25.13). Notably, GLM-4-Plus and Qwen-Max each surpass GPT-4 on specific hard-set settings (S-S/M-S and M-M respectively), indicating that no single closed-source model dominates all tool-use granularities.

## Relation to Prior Work

This paper builds on the ReAct framework (Yao et al., 2023) for structuring tool-use data (thought-action-observation format) and leverages InsTag (Lu et al., 2023) for tool clustering during data synthesis. It departs from prior tool-use benchmarks (ToolLLM, API-Bank, API-Bench, ToolAlpaca, T-Eval, GTA) by systematically covering all four turn×tool granularity combinations (S-S, S-M, M-S, M-M) plus OOD evaluation, and by replacing GPT-based evaluators with rule-based fine-grained metrics (SATS, TN, TO, TPR). The data construction pipeline repurposes existing task-oriented dialogue datasets (MultiWOZ, SGD, ATIS, SNIPS) rather than synthesizing from API documentation, addressing the real-world alignment gap identified in prior work.

## Why It Matters / Open Questions

MTU-Bench provides the first unified benchmark covering multi-turn, multi-tool, and OOD tool-use scenarios with fully automated evaluation, eliminating the GPT API cost barrier that limited reproducibility in prior benchmarks. The finding that ToolLLaMA—a model specifically fine-tuned for tool-use—performs poorly across all settings (e.g., 9.72 avg on M-S) while a general-purpose LLaMA3-8B fine-tuned on MTU-Instruct reaches 52.79, suggests that prior tool-use instruction data lacks sufficient diversity and real-world grounding. Open questions include whether the metrics generalize to truly open-ended tool ecosystems beyond the 136 curated tools, and whether the 20:1 tool clustering ratio is optimal for capturing semantic distinctions in larger API spaces.
