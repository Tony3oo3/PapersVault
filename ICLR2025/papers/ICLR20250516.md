## Problem

Converting hand-drawn sketches into high-quality vector diagrams (TikZ code) remains largely unexplored due to the absence of publicly available datasets pairing sketches with corresponding code. While text-to-diagram generation has gained traction with LLMs, sketch-based input offers a more intuitive way to express visual ideas, yet no benchmark or dedicated model existed for this task.
![Teaser figure](../imgs/ICLR20250516/cropped_page1_idx0.webp)

## Input / Output

The model takes a hand-drawn sketch image (captured from paper, whiteboard, or tablet, with inherent noise such as background interference, lighting variation, and rotation) along with a predefined language instruction, and produces a sequence of TikZ source code (averaging 739 tokens). The generated code is compiled via pdflatex into a rendered PNG diagram image, which is then evaluated against a reference diagram for similarity. Unlike prior formula-to-LaTeX work (~65 tokens), the output sequences are substantially longer and require understanding of two-dimensional spatial layouts.

## Method

IMGTikZ is a 6.7B-parameter VLM built on the LLaVA 1.5 architecture, replacing the language backbone with DeepSeek Coder (a code-specialized LLM) and using SigLIP as the vision encoder, connected via a two-layer MLP adapter. Training proceeds in two stages: first, only the adapter is trained on general image-text data (arXiv figures, LLaVA-Pretrain2); second, the adapter and LoRA parameters on the LLM are jointly trained on a mixture of SKETikZ, RenderTikZ, and two augmented datasets. Two key data augmentation strategies are introduced: AugTikZ uses GPT-3.5 to modify TikZ code for diagram variety (556K samples), and ImgAugTikZ applies image-level noise (background compositing, Gaussian noise, brightness/contrast shifts, elastic distortion) to simulate real sketch conditions (714K samples). At inference, a multi-candidate generation strategy produces K=20 TikZ code candidates, from which the best is selected using D-SigLIP—a SigLIP model fine-tuned with contrastive learning on noise-augmented diagram pairs—by maximizing cosine similarity between the input sketch and each rendered candidate.

## Results

On the SKETikZ test set (323 samples), IMGTikZ-MCG achieves the best ImageSim (0.821) and CSR_avg (0.799), significantly outperforming all baselines in compilation reliability. Claude 3.5 Sonnet leads in subjective Alignment (3.32/5) and Quality (3.54/5), while IMGTikZ-MCG achieves competitive Alignment (3.13) and Quality (3.30) despite its 6.7B parameter size. IMGTikZ-MCG also attains the highest CodeSim (0.822) and CharSim (0.594) among open-source models. Even the best model (Claude 3.5) achieves only ~3.3/5 Alignment, indicating the task remains challenging for all current VLMs.

## Baselines & Comparisons

IMGTikZ-MCG (6.7B) decisively outperforms all baselines in compilation success rate (CSR_avg 0.799 vs. 0.479 for GPT-4o, 0.544 for Claude 3.5, and 0.350 for LLaVA-Next), and in image similarity (0.821 vs. 0.753 for Claude 3.5 and 0.695 for GPT-4o). In subjective Alignment, IMGTikZ-MCG (3.13) slightly trails Claude 3.5 Sonnet (3.32) but surpasses GPT-4o (3.00) and GPT-4o-mini (2.39), demonstrating that the smaller model matches or exceeds much larger closed models. Claude 3.5 Sonnet retains the edge in Quality (3.54 vs. 3.30) and CharSim (0.671 vs. 0.594), reflecting stronger text recognition. LLaVA-Next, the only other open-source model of comparable size, performs poorly across all metrics (ImageSim 0.315, Alignment 1.43), confirming that TikZ-specific training is essential. The multi-candidate generation strategy (MCG) consistently improves over iterative generation (IG) by 0.087 in ImageSim and 0.35 in Alignment, validating the D-SigLIP-based selection approach.

## Relation to Prior Work

This paper extends the image-to-code generation line (LaTeX from formulas, HTML from screenshots, SVG from icons) to the specific setting of hand-drawn sketch-to-TikZ conversion, building on the LLaVA 1.5 architecture for the VLM backbone and DaTikZ for the base TikZ code corpus. It departs from prior sketch-to-code work (Ellis et al., 2017) by handling real-world diagrams with unrestricted shapes and text rather than primitive geometric primitives, and from concurrent image-to-TikZ work (Belouadi et al., 2024) by providing the first large-scale paired sketch-code dataset and introducing a code-specialized LLM (DeepSeek Coder) with a diagram-specific vision selector (D-SigLIP) for multi-candidate inference.

## Why It Matters / Open Questions

SKETikZ fills a critical gap as the first large-scale benchmark pairing hand-drawn sketches with TikZ code, enabling systematic evaluation of a task that even GPT-4o and Claude 3.5 Sonnet handle poorly (CSR ~0.48–0.54, alignment ~3.0–3.3/5), exposing a fundamental spatial-reasoning limitation in current VLMs. The finding that a 6.7B specialized model matches GPT-4o in subjective evaluation suggests that task-specific adaptation and inference-time candidate selection can substitute for raw model scale. Open questions include whether incorporating image-quality signals directly into training (rather than only at inference) can close the remaining gap, how to handle hallucination during information completion, and whether the approach generalizes to other vector formats (SVG, HTML) and more complex diagram types.
