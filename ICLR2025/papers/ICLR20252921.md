## Problem

LLM-based web agents frequently fail on seemingly simple web tasks because they struggle to parse and reason over complex raw web page observations such as HTML and accessibility trees. The paper hypothesizes that this underperformance stems not from weak decision-making but from difficulty in understanding the web page structure, and addresses this by decoupling web page comprehension from action selection.
![Teaser figure](../imgs/ICLR20252921/cropped_page0_idx0.webp)

## Input / Output

The contextualization module receives a natural-language task instruction, the agent's previous action history, and the current raw web page observation (an accessibility tree), and produces a condensed 'Refined observation' that extracts only task-relevant UI elements with verbal explanations of their roles and interaction semantics. This contextualized observation is then consumed by a frozen LLM agent (e.g., GPT-4o, Gemini-1.5-flash, Llama-3.1-8B) that outputs a single structured action (click, fill, select_option, scroll, etc.) referencing element IDs from the refined observation. The module itself is a small fine-tuned language model (Phi-3-mini-Instruct or Llama-3.1-8B-Instruct), keeping the decision-making agent unchanged.

## Method

LCoW introduces a separate contextualization module f_θ trained via an iterative three-phase algorithm: (1) roll out an LLM agent in the web environment and collect only successful trajectories; (2) for each observation in those trajectories, sample N candidate contextualized observations from the current f_θ and score each by an action-matching reward computed across a panel of K diverse LLM agents (ensuring the context generalizes rather than overfitting to one agent); (3) fine-tune f_θ via supervised learning on the highest-reward candidate. If all candidates score zero, the ground-truth action is injected as a hint to guide resampling. This loop repeats for M iterations, progressively sharpening the module's ability to surface relevant UI elements and explain their functionality. The key architectural choice is that the contextualization module is trained independently of the decision-making agent, so a single trained module can be plugged into arbitrary LLM agents of varying scales without retraining the agent itself.

## Results

On WebShop, the Gemini-1.5-flash agent with LCoW (3 iterations) achieves a state-of-the-art 62.8% success rate, surpassing the human expert benchmark of 59.6% and average human performance of 50%. On WorkArena, LCoW yields a 15.6% average improvement for closed-source LLMs (e.g., Claude-3.5-Sonnet goes from 44.8% to 55.8%) and a 23.7% average improvement for open-source LMs (e.g., Llama-3.1-8B goes from 1.2% to 37.0%). On WebArena, LCoW provides a consistent 6% success rate improvement over GPT-4o without contextualization on both seen and unseen task types.

## Baselines & Comparisons

LCoW consistently outperforms both the raw observation baseline and self-contextualization across all LLM agents on WebShop and WorkArena. On WebShop, the Gemini-1.5-flash + LCoW (iter 3) agent achieves 62.8% success rate, exceeding all prior methods (ReAct, Furuta et al., Putta et al., Sridhar et al., Ma et al., Gur et al.) by more than 12% and surpassing the human expert benchmark of 59.6%. On WorkArena, LCoW improves Claude-3.5-Sonnet from 44.8% to 55.8% and Gemini-1.5-flash from 11.5% to 41.2%, with the largest relative gains for smaller models (Llama-3.1-8B: 1.2% → 37.0%). The method also generalizes to unseen LLM agents: Llama-3.1-70B, which was not used in computing the action-matching reward during training, still achieves 59.6% on WebShop (matching human expert level) and 40.0% on WorkArena. On WebArena, LCoW provides a 6% improvement over GPT-4o without contextualization on both seen (117 tasks) and unseen (48 tasks) task types, though it fails to generalize to entirely unseen task categories (Filter-List) where no relevant UI elements were present in training data.

## Relation to Prior Work

This paper positions itself within the LLM-agent-for-web-automation literature (ReAct, Mind2Web, Agent Q) but departs from the dominant paradigm of either fine-tuning the full agent or using hand-crafted prompting. It is conceptually closest to observation-condensation approaches like MindAct (Deng et al., 2024) and HTML-T5 (Gur et al., 2024), which also extract relevant subsets of web page structure, but LCoW introduces a key distinction: the contextualization module is trained via an iterative algorithm that uses action-matching rewards from multiple downstream LLM agents as the learning signal, rather than being trained with a fixed summarization objective or used as a static prompt. This creates a closed loop where the quality of the contextualized observation is directly measured by whether it enables correct action prediction, and the module is refined over iterations.

## Why It Matters / Open Questions

The paper's central empirical claim—that the bottleneck for LLM web agents is observation comprehension rather than decision-making capability—is well-supported and practically actionable: a single trained contextualization module can be paired with arbitrary LLM agents of varying scale, yielding large gains (e.g., Llama-3.1-8B improving from 1.2% to 37.0% on WorkArena). Open questions remain around the inference latency cost of the extra generation step, the failure to generalize to entirely unseen UI categories (Filter-List tasks), and the dependence on collecting successful trajectories during training. The modular design also raises the broader question of whether this 'train an observation transformer with downstream task reward' recipe transfers to other text-based sequential decision-making domains beyond web navigation.
