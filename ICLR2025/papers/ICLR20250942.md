## Problem

Existing LLM routers (Hybrid LLM, FrugalGPT, C2MAB-V) rely on transductive learning, use only names or indices to represent LLMs, and train a separate router per task, making them unable to generalize to newly introduced LLMs without costly retraining. They also fail to capture the rich contextual interactions among tasks, queries, and LLMs that determine which model best suits a given query.

## Input / Output

At inference, GraphRouter takes a user query and its associated task label, and produces a selected LLM by computing edge prediction logits between the query-task combined embedding and each candidate LLM node embedding, then taking the argmax. Node features are initialized from BERT embeddings of GPT-4o-generated descriptive text (for tasks and LLMs, including size, pricing, and strengths) or direct query text; LLM-query edge features encode the concatenated performance score and API cost from prior interactions. The graph structure itself is built from historical interaction records across all tasks and LLMs.

## Method

GraphRouter constructs a heterogeneous graph with three node types (task, query, LLM) and two edge types (task-query, LLM-query), then applies a 2-layer heterogeneous GNN with type-specific learnable aggregation weights to propagate information across the graph. The key reformulation is treating LLM selection as an edge prediction problem: after GNN message passing, the query-task combined embedding (MLP of concatenated task and query embeddings) is compared via dot product with each LLM node embedding to produce edge logits, and the LLM with the highest logit is selected. Training is supervised, with the best-reward LLM per query labeled as 1 and all others as 0. For generalization to new LLMs, the inductive design relies on descriptive BERT embeddings (rather than one-hot IDs) so that a new LLM node can be inserted with only a few-shot interaction dataset at test time, avoiding any retraining of the GNN.

## Results

On the multi-task interaction dataset (Alpaca, GSM8K, SQUAD, Multi-News), GraphRouter achieves the best non-oracle Reward across all three performance-cost scenarios: 0.539 (Performance First), 0.209 (Balance), and 0.064 (Cost First), reaching at least 88.89% of the Oracle upper bound. In the new-LLM few-shot setting, GraphRouter attains a Reward of 0.207 while reducing time cost by 99.45% relative to C2MAB-V. On the extended 6-task dataset (adding HumanEval and HotpotQA) with 14 LLMs, GraphRouter improves Reward by at least 12.3% over the strongest baseline.

## Baselines & Comparisons

GraphRouter outperforms all three learned baselines on Reward in every scenario. Against FrugalGPT (Chen et al., 2023), GraphRouter gains +0.022 Reward in Performance First (0.539 vs 0.517), +0.045 in Balance (0.209 vs 0.164), and +0.007 in Cost First (0.064 vs 0.057). Against C2MAB-V (Dai et al., 2024), the margins are larger: +0.060 in Performance First (0.539 vs 0.479), +0.013 in Balance (0.209 vs 0.196), and +0.033 in Cost First (0.064 vs 0.031). Against Hybrid LLM (Ding et al., 2024), GraphRouter leads by +0.029 in Performance First, +0.200 in Balance (0.209 vs 0.009), and +0.130 in Cost First (0.064 vs −0.066), where Hybrid LLM actually incurs a negative reward. In the new-LLM few-shot setting, GraphRouter (few-shots) achieves Reward 0.207 versus C2MAB-V's 0.189 and FrugalGPT's 0.171, while cutting inference time from 542 s to 3 s (99.45% reduction).

## Relation to Prior Work

This paper departs from the existing line of LLM routing work (Hybrid LLM, FrugalGPT, C2MAB-V) by reframing the selection problem as edge prediction on a heterogeneous graph rather than classification or bandit selection. Prior routers rely on transductive learning with simple LLM representations (one-hot encodings, names, or indices) and train a dedicated model per task; GraphRouter instead leverages heterogeneous GNN message passing over task-query-LLM interaction graphs with inductive node embeddings derived from LLM-generated descriptions. Conceptually, it repurposes the inductive graph learning paradigm (GraphSAGE-style neighborhood aggregation) and the edge-prediction formulation from relational deep learning into the LLM selection domain, a connection not previously explored.

## Why It Matters / Open Questions

The inductive property—generalizing to unseen LLMs without retraining—addresses a practical pain point in rapidly evolving LLM ecosystems where new models appear frequently. However, the work is explicitly framed as exploratory: it uses only 10–14 LLMs, four task types, and a simple two-layer GNN, and the authors acknowledge that richer graph signals (paths, LLM family taxonomies) and numerical reasoning about pricing could further improve results. Open questions include whether the graph formulation extends to selecting prompting strategies (CoT, ToT) or to multi-agent LLM orchestration, and whether the approach scales to hundreds of LLMs in production settings.
