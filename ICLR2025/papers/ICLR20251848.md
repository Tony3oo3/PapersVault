## Problem

Despite their strong capabilities, LLMs lack a robust mechanism for episodic memory — the ability to recall specific events grounded in time and space — which limits their reasoning consistency and contributes to hallucination. Existing long-context benchmarks (needle-in-a-haystack, long-context QA) test simple retrieval rather than the structured, cue-based recall of events with temporal, spatial, and entity-state dimensions that characterizes human episodic memory. This paper identifies this gap and proposes the first systematic benchmark for evaluating LLM episodic memory.

## Input / Output

The benchmark takes as input a synthetic narrative document (a 'book' of 20 or 200 chapters, ~10k or ~100k tokens) in which each chapter encodes one controlled event with a specific date, location, entity, and content detail placed at designated paragraph positions, paired with a template-generated question whose cue is a partial specification of the event tuple (e.g., time only, space+entity, or all four fields). The model produces a free-form answer listing the relevant retrieved elements (entities, dates, locations, or event descriptions), which is scored via an LLM-as-a-judge that extracts predicted items and computes an optimistic F1 bound against ground truth; chronological-ordering questions additionally yield a Kendall's τ coefficient computed only over exactly-matched answer sets.

## Method

The framework models episodic memory as a set of entities with evolving states and events represented as (time, space, entities, content) tuples, drawing on the hippocampal indexing theory and the encoding specificity principle. A static universe of 100 dates, locations, entities, and contents is sampled using a truncated geometric distribution (p=0.1) to control the frequency of each item, ensuring cues match varying numbers of events (0 to 6+). Each chapter is generated by an LLM under strict meta-data constraints that pin key information to specific paragraphs, followed by verbatim parsing checks and LLM-as-a-judge boolean verification. Questions are generated from 30+ templates that systematically vary cue composition (which tuple fields are specified) and retrieval type (all elements, latest state, or chronological order), with 150 zero-event questions to probe confabulation. Three memory strategies are evaluated — in-context (full document prepended), RAG (paragraph-level retrieval via text-embedding-3-small with top-K cosine similarity), and fine-tuning (on single-event QA pairs) — across GPT-4o, GPT-4o-mini, Claude 3 Haiku, Claude 3.5 Sonnet, Llama 3.1 405B, and o1-mini, with statistical ranking via Wilcoxon signed-rank tests.

## Results

On the long book (≈100k tokens, 686 questions), GPT-4o with in-context memory and Claude 3.5 Sonnet with RAG achieve the highest average F1-scores, with no statistically significant difference between them (Wilcoxon signed-rank test). Performance degrades sharply as the number of matching events increases: for single-event recall, the best F1 is 0.83 (fine-tuned GPT-4o-mini) or 0.81 (GPT-4o in-context), but for 2+ events all models drop to F1 ≤ 0.60. For confabulation avoidance (0 matching events), o1-mini leads at 0.97 F1, while the fine-tuned model scores 0.00 (always hallucinates). Entity state tracking is severely limited: latest-state recall is ≤36% and full-set recall is ≤18% across all models.

## Baselines & Comparisons

The paper compares three memory strategies (in-context, RAG, fine-tuning) across six LLMs (GPT-4o, GPT-4o-mini, Claude 3 Haiku, Claude 3.5 Sonnet, Llama 3.1 405B, o1-mini). GPT-4o in-context and Claude 3.5 Sonnet RAG are the top performers with no statistically significant difference; RAG generally outperforms in-context for most models (e.g., Claude 3.5 Sonnet improves from 0.35 to 0.59 F1 on single-event recall), except GPT-4o where in-context is slightly better. Fine-tuning (GPT-4o-mini) is the weakest strategy: it scores 0.00 on confabulation questions (always hallucinates an answer) and drops to F1 ≤ 0.37 for multi-event questions, indicating it memorizes single-event answers without generalizing. o1-mini is the best at avoiding confabulation (0.97 F1 on 0-event questions) but the worst at actual recall (0.05 F1 on single-event questions), suggesting a reasoning-vs-retrieval trade-off. No model exceeds 36% on latest-state recall or 18% on full-set recall for multi-event questions, confirming that even state-of-the-art LLMs fundamentally struggle with episodic memory tasks.

## Relation to Prior Work

This paper carves new ground by importing cognitive science frameworks (Tulving's episodic memory, hippocampal indexing theory, encoding specificity principle) into LLM evaluation, rather than extending any single prior benchmark. It is closest in spirit to the Latent Structure Queries (LSQ/Michelangelo) framework of Vodrahalli et al. (2024), which embeds hidden structure in long contexts for state-tracking, but broadens the scope to systematically incorporate temporal and spatial cues, entity state tracking, varied cue compositions, and confabulation assessment. It departs from needle-in-a-haystack and long-context QA benchmarks by requiring coherent multi-event narratives with controlled ground truth, and from bAbI-style synthetic tasks by using LLM-generated fiction with realistic spatio-temporal grounding.

## Why It Matters / Open Questions

The benchmark reveals that even SOTA models (GPT-4o, Claude 3.5 Sonnet, o1-mini) struggle with episodic recall at merely 10k–100k tokens, and that naive fine-tuning catastrophically fails on multi-event and zero-event questions, suggesting current training paradigms are fundamentally inadequate for episodic knowledge integration. Open questions include how to implement dynamic, context-sensitive episodic memory in LLMs, whether implicit/relative temporal references further degrade performance, and whether the independent-chapter design (lacking causal interdependence) underestimates real-world difficulty. The contamination-free, scalable, and open-source nature of the benchmark makes it a practical tool for tracking progress as new memory architectures (e.g., Larimar, Fountas et al.) emerge.
