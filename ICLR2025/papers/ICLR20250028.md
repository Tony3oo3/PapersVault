## Problem

Prior methods for reconstructing articulated objects from visual observations are limited to objects with one or two moving parts, require step-by-step physical interactions to predict each joint individually, and produce incomplete meshes and joint parameters that need manual cleanup before simulation use. No existing approach reliably handles objects with more than three articulated parts or generalizes from synthetic training data to unstructured real-world environments.
![Teaser figure](../imgs/ICLR20250028/cropped_page1_idx0.webp)

## Input / Output

The method takes a handful of pose-free multi-view RGB images (10 images at 512×512 in real-world evaluation) of an object with all joints in a non-zero (partially open) state; depth and camera poses are optional and only needed for the synthetic evaluation path. The output is a set of watertight part-level 3D meshes plus a list of joint types and parameters expressed as executable Python MJCF code that can be directly loaded into MuJoCo for simulation, with joint positions and axes specified as indices into the OBB rotation axes and edges rather than continuous coordinates.

## Method

Real2Code factorizes articulated object reconstruction into two stages connected by oriented bounding boxes (OBBs) as an abstraction layer. For part geometry, a fine-tuned SAM model performs kinematics-aware 2D segmentation, a test-time prompting procedure projects masks across views for view-consistent 3D segmentation (using DUSt3R for pose-free RGB), and a PointNet++/3D U-Net shape completion model extracts watertight meshes from partial point clouds. For joint prediction, OBBs extracted from completed meshes are serialized as text and fed to a LoRA-fine-tuned CodeLlama-7B model that generates MJCF code by selecting OBB rotation axes and edges — converting the joint parameter prediction from a continuous regression problem into a discrete classification task that LLMs handle far more accurately. This code-generation formulation scales naturally to arbitrary numbers of joints without architectural changes, and the generated code is directly executable in simulation without manual post-processing.

## Results

On PartNet-Mobility, Real2Code achieves near-perfect joint prediction on objects with 2–5 moving parts: rotation error of 0.0–7.5°, position error of 0.04–0.08, and type accuracy of 0.80–0.97, while baselines exhibit 30–63° rotation errors and 2–4 cm position errors. For surface reconstruction (Chamfer Distance), Real2Code achieves 0.44 mm on laptops and 0.60 mm on fridges, compared to 2.54/2.80 mm for Ditto and 84.29/20.63 mm for PARIS. On the most complex objects (6–15 parts), Real2Code maintains 30.2° rotation error and 0.05 position error, whereas Ditto degrades to 63.06°/4.16 and PARIS fails entirely (out of memory). Real2Code is the first method to reliably reconstruct objects with more than three articulated parts.

## Baselines & Comparisons

Real2Code outperforms Ditto by a wide margin across all object complexities: on 2-part objects, rotation error drops from 40.04° to 7.5° and position error from 4.04 to 0.08; on 4–5 part objects the gap widens to 0.63° vs 49.77° rotation. Against PARIS, Real2Code achieves 7.5° vs 48.44° rotation on 2-part objects and 0.63° vs 55.97° on 4–5 part objects; PARIS additionally fails entirely on 6–15 part objects due to memory exhaustion from optimizing one neural field per part. Compared to zero-shot GPT-4, Real2Code reduces rotation error from 57.3° to 7.5° on 2-part objects and from 45.0° to 0.63° on 4–5 part objects, while also improving type accuracy (0.80 vs 0.73, 0.97 vs 0.51); GPT-4 is competitive only on 6–15 part rotation (30.0° vs 30.2°) but still lags on type accuracy (0.71 vs 0.89). Against the concurrent work DigitalTwinArt (Weng et al., 2024), Real2Code achieves substantially lower Chamfer Distance (e.g., 0.44 vs 1.01 on a 2-part refrigerator) and lower joint rotation error (0.19° vs 8.86° on a challenging refrigerator), confirming consistent superiority on multi-part objects.

## Relation to Prior Work

This paper departs from the dominant paradigm of articulated object reconstruction, where prior methods (Ditto, PARIS, CARTO) either train end-to-end models that assume 1–2 joints or perform per-object optimization that fails beyond 4 parts. Real2Code instead formulates joint prediction as next-token code generation over a fine-tuned CodeLlama, using oriented bounding boxes as an abstraction layer that converts continuous regression into discrete axis/edge selection. For the perception front-end, it repurposes pre-trained SAM (fine-tuned only on the prompt decoder) and DUSt3R for view-consistent 3D segmentation, and builds on Convolutional Occupancy Networks for part-level shape completion — combining off-the-shelf vision models with a lightweight LLM fine-tune rather than training a monolithic architecture.

## Why It Matters / Open Questions

Real2Code is the first method to reliably reconstruct articulated objects with more than three moving parts and to extrapolate beyond the training set's maximum of 7 parts to 10-part objects, addressing a clear scalability bottleneck in prior work. The code-generation formulation means the model architecture needs no modification as joint count grows, and the output is directly executable in MuJoCo, reducing the manual cleanup that plagued earlier pipelines. Key limitations remain: cascading errors across the multi-module pipeline (segmentation → shape completion → OBB extraction → LLM), sensitivity to hinge joints whose axis does not align with an OBB edge, and test-time compute that scales linearly with the number of camera views. Open questions include extending to scene-level multi-object reconstruction, handling non-cuboid geometries (e.g., scissors), and reducing inference latency for real-time applications.
