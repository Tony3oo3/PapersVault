## Problem

LLMs struggle to understand structured tabular data because text-based serialization of 2D tables into 1D prompts introduces structural incompatibility, token redundancy, and bias toward local cell values. The paper identifies that current LLMs resort to flat context mapping rather than genuine structure-aware semantic comprehension, a gap that is especially severe when column names are non-semantic or ambiguous.
![Teaser figure](../imgs/ICLR20250563/cropped_page0_idx0.webp)

## Input / Output

The method takes a database table (schema with column names, data types, primary/foreign keys, and cell values) plus a natural language query, and outputs a SQL query. Unusually, the table is consumed in a hybrid form: a dedicated Table Encoder produces 5 fixed-length column-level embeddings per column (regardless of row count), which are injected at the LLM's embedding layer alongside a minimal textual template containing column names, types, and one example value per column. This decouples abstract structural semantics (in embeddings) from concrete details (in text).

## Method

TNT treats tabular data as a distinct modality with a dedicated encoder, analogous to how VLMs handle images. The Table Encoder uses a sentence transformer (all-MiniLM-L6-v2) to produce cell embeddings, then applies stacked bi-dimensional attention modules (alternating row-wise and column-wise BERT-style attention, with no positional embeddings to preserve permutation invariance) to capture global structural semantics. A Table-Language Adaptor aggregates cell embeddings into fixed-length column representations via cross-attention with k=5 learnable queries, aligning them to the LLM's embedding space. Training follows three stages: (1) column-wise contrastive learning using InfoNCE loss with random row sampling to create positive pairs from the same column across two snapshots, (2) multi-task feature alignment on 292K interleaved table-language samples (column prediction, cell prediction, question generation, table titling, row summarization) with 50% column names anonymized, and (3) supervised instruction tuning on SPIDER. The key architectural insight is that columns are the fundamental semantic units of a table, and structure-enriched column embeddings provide insights that cannot be captured by any amount of serialized cell values.

## Results

On non-semantic SPIDER-Realistic (where 80% of column names are anonymized), TNT with LLAMA3-8B achieves 32.3% EX, surpassing the SFT baseline (17.9%) by 14.4 percentage points and the original LLM (14.2%) by 18.1 points. On standard SPIDER-Test with semantic column names, TNT (LLAMA3-8B) reaches 79.0% EX vs. 77.8% for SFT, and with Code Correction reaches 84.3% EX, approaching GPT-4-based methods (86.6%). Across all three backbone LLMs (LLAMA3-8B, MISTRAL-7B, CODELLAMA-7B), TNT consistently outperforms both the original and SFT baselines on every dataset and metric.

## Baselines & Comparisons

TNT decisively outperforms all text-based baselines (Original and SFT LLMs) across every backbone and dataset, with the largest gains on non-semantic SPIDER-Realistic (+14.4% EX over SFT with LLAMA3-8B). Against prior embedding-based table representations, TNT (59.9% EX on non-semantic SPIDER-Test) substantially surpasses TransTab (33.0%) and CM2 (39.2%), confirming that its column embeddings capture genuinely structure-enriched semantics rather than acting as soft prompts (SFT w/ Soft Prompts: 51.5%). On the Spider leaderboard, TNT+LLAMA3-8B+Code-Correction reaches 84.3% EX, slightly below DAIL-SQL+GPT-4+Self-Consistency (86.6%) and DIN-SQL+GPT-4 (85.3%), but exceeding C3+ChatGPT (82.3%) and RESDSQL-3B+NatSQL (79.9%) with a much smaller open-source backbone. On broader tabular tasks (WikiTQ, TabFact, TableBench, HybridQA, FEVEROUS), TNT (QWEN2.5-7B) matches or exceeds GPT-3.5-based agent pipelines (Binder, Dater, Chain-of-Table) and TableLLM variants, e.g., 78.05% on FEVEROUS vs. 63.30% for QWEN2.5-Instruct-7B. On BIRD-dev, TNT improves over SFT by ~3–5% EX, though the gap to SoTA GPT-4 pipelines remains larger due to BIRD's emphasis on advanced SQL syntax and external knowledge.

## Relation to Prior Work

TNT positions tabular data as a distinct modality analogous to images in vision-language models, drawing directly on BLIP-2's learnable-query adaptor mechanism and the bi-dimensional attention architectures from SAINT and XTab for its Table Encoder. It departs from the dominant paradigm of serializing tables into 1D text (Markdown, JSON, XML) for LLM consumption, arguing that this approach is structurally incompatible, token-inefficient, and prone to local bias. Unlike pre-LLM table pre-training methods (TAPAS, TAPEX, TabBERT) that relied on smaller encoders and curated schemas, TNT's column-wise contrastive learning objective is schema-independent and scalable to uncurated real-world tables, while its three-stage training pipeline (encoder pre-training → feature alignment → instruction tuning) mirrors the MLLM training recipe.

## Why It Matters / Open Questions

The paper demonstrates that a dedicated 2D-structure-aware encoder with minimal overhead (~39ms, ~170M parameters) can substantially improve LLM table understanding, particularly when column names are ambiguous or non-semantic—a common real-world scenario. The finding that one example cell value plus column embeddings outperforms twenty serialized values challenges the assumption that more context is always better for tabular reasoning. Limitations include evaluation only on ~7B open-source models, reliance on proprietary training tables (86K business tables not publicly released), and testing primarily on relational tables; open questions include scaling to larger backbones, hierarchical/nested table structures, and whether the modality-fusion paradigm generalizes to other structured data formats like graphs or JSON schemas.
