## Problem

Autoregressive LLMs generate text one token at a time, making inference slow, and once pre-trained they cannot easily incorporate new knowledge without expensive fine-tuning. Existing remedies address only one challenge: speculative decoding accelerates generation but fixes the model distribution, while retrieval-augmented generation adapts knowledge but adds per-token retrieval latency without efficiency gains. CD-LM targets both simultaneously by generating multi-token chunks via retrieval while also injecting external knowledge into the LM's distribution.

## Input / Output

At each decoding step, the method consumes the current generated prefix (whose last token selects an entry-token trie) and the base LM's hidden-state context vector, then queries a trie-structured datastore of (context-vector, chunk) pairs to propose a chunk continuation. The output is a text sequence where accepted chunks are emitted as contiguous spans (skipping intermediate token steps) interleaved with single-token LM generations. A backward dynamic program over latent chunk-acceptance variables yields the full sequence probability, enabling perplexity computation under the CD-LM distribution rather than the base LM's.

## Method

CD-LM interleaves chunk retrieval with autoregressive token generation: at each step, the base LM's hidden state serves as a query vector, the last generated token indexes into a per-entry-token trie, and cosine similarity against stored context vectors selects the best chunk candidate. A piecewise-linear mapping converts the top similarity score into an acceptance probability; if accepted, the entire chunk (potentially many tokens) is emitted in one step, otherwise a single token is sampled from the base LM. Chunks are extracted by thresholding token probabilities from a teacher LM (knowledge distillation), the same base LM (self-distillation for speedup), or human-curated sources such as Wikipedia hyperlinks (expert distillation), all stored in trie structures keyed by entry token. The key distinction from speculative decoding is that CD-LM does not verify chunks against the target LM, so the model distribution is genuinely altered by the injected knowledge rather than preserved. A backward dynamic program marginalizes over all possible chunk-acceptance paths to compute exact sequence probabilities, enabling perplexity evaluation that reflects the chunk-level modifications.

## Results

On the KCD-LM knowledge distillation task, the method reduces perplexity from 34.83 to 22.90 on WikiText-103, from 51.68 to 24.95 on Medical, from 11.41 to 8.24 on Law, and from 106.44 to 50.77 on Code (Dockerfile), using a 137M GPT-2 base model with chunks extracted from a 1.5B teacher. For self-distillation (SCD-LM) on MT-Bench-80, the method achieves 19.59% token time saved and 43.33% forward passes saved with GPT-2-XL, 14.89% and 32.32% with LLaMA-2, and 11.75% and 24.52% with Mistral-7B. MAUVE scores for text generation improve by 50.7% (WikiText), 100.9% (Medical), 162.8% (Law), and 121.3% (Code) over the base LM.

## Baselines & Comparisons

Against kNN-LM, KCD-LM achieves substantially lower perplexity on all four domains: 22.90 vs. 32.19 on WikiText (29% reduction), 24.95 vs. 39.66 on Medical (37% reduction), 8.24 vs. 11.10 on Law (26% reduction), and 50.77 vs. 89.88 on Code (43% reduction). RETOMATON performs identically to kNN-LM on Medical, Law, and Code, and KCD-LM outperforms it by the same margins. Against REST (retrieval-based speculative decoding) on the SCD-LM efficiency task, SCD-LM consistently wins: GPT-2-XL achieves 19.59% TTS vs. REST's 13.74% and 43.33% FPS vs. 23.77%; LLaMA-2 achieves 14.89% TTS vs. REST's 2.44%; and Mistral achieves 11.75% TTS vs. REST's negative −1.23% (i.e., REST actually slows down Mistral). The paper also notes that KCD-LM's datastore is only 30–40% the size of a naive kNN-LM datastore, and retrieval is restricted to 0.002–0.011% of the datastore per step via entry-token trie pruning, making it both more accurate and more efficient than kNN-LM.

## Relation to Prior Work

CD-LM draws its retrieval mechanism from kNN-LM's vector-space context matching but departs fundamentally by operating at the chunk level with hard accept/reject decisions rather than token-level soft distribution mixing. It is positioned against speculative decoding (particularly REST) by arguing that retrieval-based chunk generation can simultaneously change the model's output distribution (injecting new knowledge) while also accelerating inference, whereas speculative decoding methods fix the distribution by design. The trie-structured datastore with entry-token indexing is a practical departure from both kNN-LM's flat key-value stores and RAG's document-level retrieval, enabling sparse, efficient search over fine-grained linguistic units.

## Why It Matters / Open Questions

The training-free nature of CD-LM makes it immediately applicable to any off-the-shelf LM without fine-tuning, which is practically valuable for domain adaptation and knowledge injection in settings where retraining is infeasible. The dynamic programming formulation for sequence probability under the chunk-interleaved generative process provides a principled perplexity metric that prior retrieval-augmented methods (e.g., NEST) lack. Key limitations include the unoptimized retrieval overhead, reliance on a manually tuned similarity threshold η, and evaluation primarily on models up to 7B parameters; whether the approach scales to frontier-scale LLMs or benefits from learned retrieval policies remains open.
