## Problem

While VLMs can generate CAD scripting code for 3D objects, the resulting designs frequently deviate structurally or functionally from the user's specifications, and verifying correctness is difficult because 3D structural intricacies are not discernible in code. Existing refinement methods rely on human-in-the-loop expertise or external geometric solvers with access to ground truth, making them costly or impractical for real-world use. The paper addresses the absence of an automated, self-contained feedback loop that can visually inspect a generated 3D object and produce corrective feedback without human intervention.

## Input / Output

The method takes a natural language prompt describing a 3D object, the generated CADQuery (Python) code, and four reference images of the rendered object captured at 0°, 90°, 180°, and 270° as input. It produces refined CAD scripting code, a 3D object in STL format, a set of 2–5 binary Yes/No/Unclear validation questions with Chain-of-Thought answers, and natural-language ameliorative feedback. The code is compiled via the CADQuery compiler, and failed compilations trigger a separate repair loop using compiler error messages before refinement begins.

## Method

CADCodeVerify is a two-step iterative refinement loop that operates entirely through a VLM without external geometric solvers or human feedback. In the Question-Answer Generation step, the VLM first generates 2–5 binary verification questions from the language prompt (guided by few-shot example questions), then answers each question by visually inspecting the four reference images of the rendered object using Chain-of-Thought reasoning, with an explicit 'Unclear' option to reduce hallucination. In the Feedback Generation step, only the non-'Yes' Q&A pairs are fed back to the VLM to produce targeted ameliorative feedback, which is appended to the prompt for the next code-refinement iteration. The full pipeline comprises three stages—code generation, code execution (with a compiler-error repair loop), and iterative code refinement (up to M=2 iterations)—and is model-agnostic, demonstrated across GPT-4, Gemini 1.5 Pro, and CodeLlama, with the VLM handling both question generation and answering even when the code-generating model is unimodal.

## Results

On the CADPrompt benchmark (200 3D objects), GPT-4 with few-shot prompting and CADCodeVerify achieves a median Point Cloud distance of 0.127, Hausdorff distance of 0.419, IoGT of 0.944, and a 96.5% compile rate. Compared to the prior state-of-the-art (3D-Premise), CADCodeVerify reduces Point Cloud distance by 7.3% (0.127 vs. 0.137) and improves compile rate by 5.5 percentage points (96.5% vs. 91.0%) for GPT-4 few-shot. GPT-4 overall achieves the highest compile rate (96.5%) among the three evaluated models, compared to Gemini (85.0%) and CodeLlama (73.5%).

## Baselines & Comparisons

CADCodeVerify consistently outperforms 3D-Premise (Yuan et al., 2024) across all evaluated models. For GPT-4 few-shot, CADCodeVerify reduces Point Cloud distance from 0.137 to 0.127 (7.3% improvement) and raises compile rate from 91.0% to 96.5% (5.5 pp gain), while also improving Hausdorff distance (0.419 vs. 0.446) and IoGT (0.944 vs. 0.942). For Gemini few-shot, the advantage is even more pronounced: Point Cloud distance drops from 0.169 to 0.147 and compile rate recovers from 81.5% to 85.0%. On the 'Hard' data split, CADCodeVerify is the only method that increases compile rate (≈9% gain at Refine-1), whereas 3D-Premise actually degrades performance by 20%. Against the geometric solver upper bound (which requires ground-truth STL access), CADCodeVerify achieves comparable IoGT (0.944 vs. 0.944 for GPT-4 few-shot) but with a slightly higher Point Cloud distance (0.127 vs. 0.103), demonstrating that the VLM-based feedback loop approaches oracle-level refinement without needing the target object.

## Relation to Prior Work

This paper extends the line of work on LLM-based CAD code generation (Makatura et al., 2023; Nelson et al., 2023) and self-correction for code (Chen et al., 2023b; Madaan et al., 2023) by introducing a structured question-answer verification loop as the refinement mechanism. The closest prior method, 3D-Premise (Yuan et al., 2024), also uses a VLM to refine CAD code from an image and description, but provides only a single free-form correction prompt rather than decomposing verification into discrete binary questions with chain-of-thought reasoning. The paper also departs from 3D generative modeling (diffusion, GANs) by working in the parametric CAD scripting space (CADQuery), which produces manufacturable outputs rather than point clouds or voxels.

## Why It Matters / Open Questions

CADPrompt provides the first dedicated benchmark for evaluating CAD code generation, filling a gap where prior work relied on qualitative or ad-hoc evaluations. The finding that VLM self-verification (CADCodeVerify) can improve both geometric fidelity and compile rates without human intervention is practically significant for reducing the barrier to automated design. However, the VLM's answer accuracy is only ~65–68%, and the geometric-solver upper bound (which requires ground-truth access) still outperforms CADCodeVerify, leaving open the question of how to close this gap. The noisy evaluation metrics (Point Cloud and Hausdorff distance) also limit the ability to capture structural or logical errors, a gap the authors acknowledge for future work.
