## Problem

Traditional GNNs apply graph convolution uniformly across all feature dimensions, yet not every feature benefits from neighborhood aggregation—some are actually harmed by it. Existing feature homophily metrics measure feature consistency along graph topology but fail to align with actual GNN performance and cannot reliably distinguish which features are GNN-favored versus GNN-disfavored, leaving a gap in principled, feature-level guidance for graph convolution.
![Teaser figure](../imgs/ICLR20252203/cropped_page1_idx0.webp)

## Input / Output

The method consumes a node feature matrix X ∈ R^{N×M}, a graph adjacency matrix A, and semi-supervised node labels (only training labels are needed for TFI estimation, no pseudo-labels required). TFI is computed per feature dimension as the mutual information between k-hop aggregated features (k=1 by default) and labels, then a ratio r ∈ (0,1) determines the percentile threshold δ(r) that splits features into GNN-favored and GNN-disfavored subsets. The output is a fused node representation obtained by concatenating the final-layer embeddings from the GNN channel and MLP channel and projecting through a shared linear layer, which is then used for node classification.

## Method

The core contribution is Topological Feature Informativeness (TFI), defined as the mutual information I(Y; X̃_{:,m}) between node labels and k-hop aggregated features for each dimension m, which provably upper-bounds both the classifier accuracy on aggregated features (Theorem 1) and the performance gap between GNN and MLP (Theorem 2). Based on TFI, Graph Feature Selection (GFS) partitions features at a threshold δ(r) (top r percentile): GNN-favored features are processed by a GNN (e.g., GCN) while GNN-disfavored features are processed by an MLP, ensuring each feature is handled by the model best suited to it. The two channels operate independently during message passing, and their final-layer embeddings are concatenated and fused via a linear layer to produce the node representation. This plug-and-play module is architecture-agnostic and adds negligible computational overhead, as the reduced feature dimension for the GNN channel offsets the added MLP cost.

## Results

Applying GFS to 8 GNN architectures across 10 datasets yields a significant performance boost in 90% (72/80) of cases, with an average increase of 3.2% in accuracy or AUC-ROC. The largest gains appear on heterophilic or low-homophily datasets: FAGCN+GFS improves by +13.34% on Questions, +10.03% on Roman-Empire, and +9.75% on Tolokers, while SGC+GFS gains +12.36% on Minesweeper. GFS is particularly effective on PLM-encoded features (40/40 cases improved) compared to traditional encodings (32/40). TFI achieves the best average rank (1.40) among all feature selection metrics, outperforming the next-best h_sim-euc (3.35) and optimization-based Soft (3.50).

## Baselines & Comparisons

GFS consistently improves all 8 baseline GNNs (GCN, GAT, SAGE, GT, SGC, APPNP, ACMGCN, FAGCN) on most datasets, with the largest gains on weaker baselines: FAGCN+GFS gains +13.34% on Questions and +10.03% on Roman-Empire, while SGC+GFS gains +12.36% on Minesweeper. On already-strong baselines like ACMGCN and GAT on high-homophily datasets (Minesweeper, Questions), GFS yields negligible or slightly negative changes (−0.14% to −0.67%), suggesting those features are already well-suited to graph convolution. For feature selection metrics (Table 2), TFI achieves the best average rank (1.40) across 10 datasets, clearly outperforming h_sim-euc (3.35), Soft optimization (3.50), h_CTF (4.55), h_attr (4.70), h_sim-cos (5.95), h_GE (6.70), and Hard optimization (8.90). Notably, even inferior metrics like h_attr and h_CTF still improve GCN when used within the GFS framework, confirming that the splitting strategy itself is beneficial regardless of the specific metric. The Hard optimization-based approach performs worst (avg. rank 8.90), indicating that end-to-end learned feature selection is unreliable compared to the statistic-based TFI.

## Relation to Prior Work

This paper departs from the line of feature homophily metrics (h_GE, h_attr, h_sim-cos, h_sim-euc, h_CTF) that measure feature consistency across graph topology, arguing they suffer from the 'good heterophily' misalignment with actual GNN performance. It also extends traditional feature selection (Laplacian Score, MIM, L1-norm) which targets i.i.d. data by introducing a graph-structure-aware criterion: Topological Feature Informativeness (TFI), a mutual-information-based metric between k-hop aggregated features and labels. The key conceptual departure from prior heterophily-oriented GNNs (FAGCN, ACM-GCN, DMP) is that GFS does not modify the GNN architecture itself but instead routes features to the most appropriate model (GNN vs. MLP), following the 'feed the right features to the right model' principle. The authors claim to be the first to frame feature selection as a splitting problem between GNN-favored and GNN-disfavored dimensions rather than a pure selection or redundancy-reduction task.

## Why It Matters / Open Questions

GFS is a simple, plug-and-play module that improves 90% of cases (72/80) across 8 GNN architectures and 10 datasets with comparable computational cost, making it immediately adoptable by practitioners working on node classification. The finding that PLM-encoded features exhibit a consistent unimodal right-skewed TFI distribution—naturally separating topology-aware from topology-agnostic dimensions—offers a new explanation for why PLMs assist graph learning, a question previously unaddressed. Open questions include automatic selection of the split ratio r (currently a grid-searched hyperparameter), extension to unsupervised or self-supervised settings where TFI's label dependence is a limitation, and whether the approach generalizes to dynamically updated embeddings during training. The supervised nature of TFI also limits applicability in fully unsupervised graph learning scenarios.
