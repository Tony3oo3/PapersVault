## Problem

Existing LLM-based embodied multi-agent cooperation frameworks, such as CoELA, rely on greedy single-step planning after each action execution, lacking long-term strategic coordination. This leads to redundant movements, incoherent agent behavior, and failure on complex tasks requiring thorough discussion and cooperative planning (e.g., search-and-rescue). The paper addresses how to enable LLM-based embodied agents to collaboratively create and adapt coherent, long-term plans through structured multi-agent discussion.

## Input / Output

Each agent receives an egocentric 512×512 RGB-D image (or oracle segmentation), its own position/rotation, held-object state, and text messages from teammates, alongside a natural-language task description (e.g., 'Transport 2 apples and 3 bananas to the bed'). The system outputs a structured meta-plan decomposing the task into subtasks with explicit agent assignments and step-by-step execution instructions, which is then parsed into high-level sub-plans and converted into primitive environment actions (move, turn, grasp, put-in, drop, send-message). The meta-plan is dynamically regenerated as a progress-adaptive version whenever an agent discovers a target object or completes a subtask.

## Method

CaPo operates in two phases built on CoELA's five-module architecture (perception, memory, communication, planning, execution), with all LLM-based components driven by GPT-3.5, GPT-4, or LLaMA-2-13B via structured prompting. In Phase 1 (Meta-Plan Generation), a randomly selected 'designer' agent generates an initial meta-plan using a prompt combining task description and format constraints, then broadcasts it to 'evaluator' agents who provide feedback through multi-turn LLM-mediated discussion (capped at 3 rounds) until consensus is reached, integrating each agent's partial observations into a coherent plan. In Phase 2 (Progress-Adaptive Meta-Plan & Execution), whenever an agent achieves significant progress (e.g., discovering a previously unknown object location or completing a subtask), the designer regenerates an updated meta-plan incorporating the new information, followed by another multi-turn evaluation cycle. A separate plan-parsing LLM module then selects the next executable sub-plan from the meta-plan given action history and current progress, which the execution module translates into primitive actions. The key distinction from CoELA is the shift from per-step reactive communication to a proactive, discussion-driven planning protocol that produces a shared strategic roadmap before and during execution.

## Results

On TDW-MAT with GPT-4 agents and oracle perception, CaPo achieves an average transport rate of 89% (Food: 90%, Stuff: 87%), outperforming CoELA (85%), RoCo (85%), and ProAgent (84%). With GPT-3.5 agents under the same setting, CaPo reaches 84% average transport rate versus CoELA's 72%, a 16.7% relative improvement. On C-WAH with GPT-4, CaPo requires 51 average steps (symbolic obs) and 83 steps (visual obs), beating CoELA (57/92), ProAgent (62/90), and RoCo (57/89). Ablation confirms the progress-adaptive meta-plan contributes a 7-point gain over static meta-plan generation alone.

## Baselines & Comparisons

CaPo consistently outperforms all LLM-driven baselines across both benchmarks and all LLM backbones. On TDW-MAT (oracle perception, GPT-4), CaPo (89% avg) beats CoELA (85%) by 4.7%, RoCo (85%) by 4.7%, and ProAgent (84%) by 5.9%; the gap widens dramatically with GPT-3.5 where CaPo (84%) surpasses CoELA (72%) by 16.7%. On C-WAH (GPT-4, lower steps is better), CaPo requires 51 steps (symbolic) and 83 steps (visual), improving over CoELA by 9.8% and 6.6% respectively, and over ProAgent by 17.7% and 7.8%. Against classical baselines (RHP, MHP), CaPo with two agents achieves 38–43% efficiency improvement over the single-agent RHP baseline. In heterogeneous settings (Appendix A.2), CaPo paired with RHP (82% avg) outperforms RHP+CoELA (81%), and CaPo+CoELA reaches 84%, confirming that the meta-plan mechanism adds value even when one partner lacks the discussion protocol.

## Relation to Prior Work

CaPo builds directly on CoELA's modular architecture (perception, memory, communication, planning, execution) but departs fundamentally from its single-step, greedy planning paradigm by introducing a two-phase cooperative plan optimization process: a long-term meta-plan generated through multi-turn agent discussion, followed by progress-adaptive updates during execution. It positions itself against other LLM-driven multi-agent frameworks like ProAgent and RoCo, which generate joint plans but lack structured deliberation, and against RL-based cooperation methods, which suffer from limited generalization. The conceptual lineage draws from human cooperation schemes (Tuomela, 1998; Thürmer et al., 2017) where groups discuss and refine plans before acting, translating this into a structured LLM prompting protocol.

## Why It Matters / Open Questions

CaPo addresses a practical gap in LLM-based embodied multi-agent systems: the absence of long-term strategic coordination, which leads to redundant actions and poor efficiency in physically costly environments. The finding that a 3-round discussion budget achieves near-optimal consensus (78.9% convergence on Stuff tasks) provides a practical design guideline for communication cost in multi-agent LLM systems. However, the method's reliance on a pre-defined communication protocol and its dependence on LLM quality for both planning and discussion limit its flexibility in truly dynamic or heterogeneous settings, and the evaluation is confined to two-agent scenarios in simulated environments, leaving open questions about scalability to larger agent teams and real-world deployment.
