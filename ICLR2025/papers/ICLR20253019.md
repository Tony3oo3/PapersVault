## Problem

Existing LLM agent benchmarks (ALFWorld, WebShop, PlanBench, VirtualHome) evaluate long-horizon planning but none incorporate time delays, making them unable to test asynchronous planning — the ability to reason over actions that must happen in parallel or sequentially with countdown timers. AsyncHow benchmarks asynchronous planning but lacks an interactive closed-loop environment. This gap means LLM agents' ability to manage overlapping tasks, coordinate delays, and recover from failures in time-constrained settings remains unmeasured.

## Input / Output

The agent receives a textual description of the current environment state (object predicates like 'lettuce1 is cut', 'patty1 is on stove2'), the set of valid grounded actions, active timer countdowns, and a natural-language goal (e.g., 'Prepare a lettuce chicken sandwich on a table'). For ReAct, the agent outputs reasoning plus a single next action per step and receives the updated state before repeating; for I/O baselines, it outputs the full plan at once. Success requires reaching the goal within 1.5× the optimal step count, with the environment defined entirely through JSON domain and problem files inspired by PDDL.

## Method

ROBOTOUILLE formalizes cooking tasks as an MDP with time-delayed effects, where actions like 'cook' introduce timer variables that add predicates (e.g., iscooked) after a configurable delay, expanding the effective state space from O(|S|+|A|) to O(|S|×(d+1)^n + |A|). The environment is fully specified via JSON domain and problem files (objects, predicates, actions with preconditions and special effects, and flexible combinatorial goals), enabling procedural generation of diverse instances by shuffling and adding objects. Three datasets of 10 tasks × 10 instances each test synchronous (no delays), asynchronous (cooking/frying/boiling delays), and multi-agent (2–4 agents, turn-based or real-time) planning. Baselines include I/O, I/O CoT, and an ablated ReAct (keeping only last-step reasoning and action in context) evaluated across gpt-4o, gpt-4o-mini, gemini-1.5-flash, and claude-3-haiku, with failure modes categorized by MDP uncertainty (state, action, transition, goal).

## Results

On the ROBOTOUILLE synchronous dataset, gpt4-o ReAct achieves 47% success rate, substantially outperforming I/O (4%) and I/O CoT (14%). On the asynchronous dataset, performance drops dramatically: gpt4-o ReAct reaches only 11%, while I/O and I/O CoT both achieve just 1%. Among all tested LLMs, gpt4-o dominates both settings; gpt-4o-mini achieves 11% (sync) and 0% (async), while gemini-1.5-flash and claude-3-haiku score 0% on asynchronous tasks across all baselines. The gap between synchronous (47%) and asynchronous (11%) performance for the best agent highlights the difficulty of time-delayed planning.

## Baselines & Comparisons

The paper evaluates three agent paradigms (I/O, I/O CoT, ReAct) across four LLMs, with ReAct (Yao et al., 2022) consistently outperforming the open-loop I/O and I/O CoT (Wei et al., 2023) baselines by a wide margin — e.g., 47% vs. 4% and 14% on synchronous, and 11% vs. 1% and 1% on asynchronous for gpt4-o. In Appendix A.15, two additional methods are tested on the asynchronous dataset: PLaG/BaG (Lin et al., 2024) achieves 13% (a 2-point gain over ReAct's 11%), and Reflexion (Shinn et al., 2023) reaches 17% (a 6-point gain), though Reflexion requires a costly retry. All methods fail completely on the four hardest asynchronous tasks (Tasks 7–10, horizon 42–82 steps), with 0% success across every baseline. The key takeaway is that no existing agent method handles asynchronous planning well, with the best result (17% via Reflexion) still far below the synchronous performance of the same model (47% via ReAct).

## Relation to Prior Work

ROBOTOUILLE carves new ground by being the first LLM agent benchmark to simultaneously support high-level actions, multi-agent interaction, procedural generation, and time delays—no prior benchmark (ALFWorld, WebShop, PlanBench, VirtualHome, AsyncHow) combines all four. Conceptually, it extends the PDDL-inspired MDP formalization with time-delayed effects (timers with countdown functions) to model asynchronous execution, and repurposes the ReAct closed-loop agent paradigm as its primary evaluation vehicle. The paper also adapts PLaG (BaG) and Reflexion from the asynchronous planning and self-reflection literatures as secondary baselines, positioning ROBOTOUILLE as the missing interactive testbed that AsyncHow lacked.

## Why It Matters / Open Questions

The benchmark exposes a concrete and actionable gap: the 47%→11% synchronous-to-asynchronous performance drop, and the finding that both settings share the same dominant failure modes (rule violations and goal misinterpretation) rather than introducing fundamentally new ones, suggests the bottleneck is feedback incorporation and self-auditing rather than the asynchronous structure itself. Open questions include how to reliably incorporate long-horizon state feedback without context explosion, how to enable effective self-verification for LLM agents, and whether the cooking domain generalizes to other asynchronous settings. Limitations include the small task count (30 total), single-domain scope, and the multi-agent dataset remaining unevaluated.
