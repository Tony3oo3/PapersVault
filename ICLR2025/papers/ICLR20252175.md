## Problem

Self-consistency (majority voting over execution results) is the standard way to pick among multiple LLM-generated SQL candidates, but the most consistent answer is not always correct. On BIRD, self-consistency achieves 68.84% execution accuracy while the upper bound (oracle selection) reaches 82.79%, revealing a 14-point gap that indicates existing selection mechanisms fail to identify the correct query from the candidate pool. The paper addresses both sides of this gap: how to generate diverse, high-quality candidates and how to select the best one more reliably than majority voting.

## Input / Output

The framework consumes a natural-language question, the target database schema, relevant database values retrieved via locality-sensitive hashing (LSH) with embedding-based re-ranking, and an optional user hint. It produces a single executable SQLite SQL query. Unusually, the system generates 21 candidate queries (7 per generator × 3 generators) at test time, applies an iterative self-reflection fixer (up to 3 rounds) to repair syntactically invalid or empty-result queries, and then runs all candidates through a pairwise tournament before returning the winner.

## Method

CHASE-SQL is a multi-agent test-time-compute framework with three distinct candidate generators: (1) a divide-and-conquer CoT that decomposes the question into sub-questions solved as pseudo-SQL then assembled, (2) a query-plan CoT that mirrors database engine execution steps (table identification → operations → result delivery) in human-readable form, and (3) an online synthetic example generator that produces 75+ many-shot in-context examples per question, mixing SQL-feature-diverse examples (R_f) with schema-filtered examples (R_t) to avoid pattern overfitting. A fine-tuned binary selection agent (Gemini-1.5-Flash with LoRA, rank 16, trained on 3.8K pairwise examples from BIRD training data) then compares every pair of candidates (k=2) using a classification objective, accumulating scores in a tournament matrix; candidates with identical execution results are auto-resolved without invoking the model. The selection agent achieves 71.01% binary accuracy versus 58–64% for untuned LLMs, and the full pipeline reaches 73.01% execution accuracy on BIRD dev, outperforming all prior methods.

## Results

CHASE-SQL with Gemini 1.5 Pro achieves 73.01% execution accuracy on the BIRD development set and 73.0% on the BIRD test set, setting a new state-of-the-art on the BIRD leaderboard at the time of submission. On the Spider test set, CHASE-SQL reaches 87.6% EX without any Spider-specific training or prompt tuning, placing it second overall (behind only MCS-SQL which was trained on Spider). Using entirely open-source models (Mistral Large as generator, fine-tuned Qwen-2.5-coder as selector), the framework achieves 70.33% on BIRD dev, still outperforming all published methods.

## Baselines & Comparisons

On BIRD dev, CHASE-SQL (73.01%) outperforms the closest published method, Distillery+GPT-4o (67.21%), by 5.8 points, and the next-best undisclosed entry, InsightsAI (72.16%), by 0.85 points. On BIRD test, CHASE-SQL (73.0%) edges out AskData+GPT-4o (72.39%) and OpenSearch-v2+GPT-4o (72.28%) by roughly 0.6–0.7 points, while leading all published methods by over 1.2 points. On Spider test, CHASE-SQL (87.6%, zero-shot on Spider) trails MCS-SQL+GPT-4 (89.6%) by 2.0 points, but MCS-SQL was explicitly trained on Spider data; among methods without Spider-specific training, CHASE-SQL leads CHESS (87.2%) by 0.4 points. The open-source variant (Mistral Large + Qwen-2.5-coder, 70.33% BIRD dev) surpasses all published baselines including Distillery (67.21%) and CHESS (65.00%) by 3+ points, demonstrating that the framework's gains are not solely attributable to proprietary model quality.

## Relation to Prior Work

CHASE-SQL extends the multi-candidate generation-and-selection paradigm from code generation (AlphaCode, LEVER) to Text-to-SQL, departing from the dominant self-consistency (majority-vote) selection used in prior LLM-based Text-to-SQL systems like CHESS, MCS-SQL, and Distillery. It builds directly on CHESS for LSH-based value retrieval and column filtering, and on Reflexion for the iterative query-fixing loop. The key conceptual departure is replacing consistency-based selection with a fine-tuned pairwise binary classifier trained on preference-optimized comparisons, combined with three distinct reasoning paths (divide-and-conquer CoT, query-plan CoT, and online synthetic example generation) to maximize candidate diversity while preserving quality.

## Why It Matters / Open Questions

The framework demonstrates that test-time compute—spending more inference budget on diverse generation and careful selection—can substantially close the gap between single-query performance and the oracle upper bound (82.79% vs. 73.01% achieved), suggesting that LLMs already contain the knowledge to solve most Text-to-SQL questions but lack effective extraction mechanisms. The 14% gap between self-consistency and the upper bound quantifies a concrete, addressable bottleneck in current pipelines. Open questions include whether more sophisticated search or reasoning-based selection (beyond pairwise comparison) can close the remaining gap, how to handle ambiguous or unanswerable questions (which the framework assumes are always answerable), and whether the approach generalizes beyond the BIRD/Spider distributions to truly open-ended database environments.
