## Problem

Automatically constructing high-quality instruction-following training data at scale without manual annotation remains unresolved. Existing approaches either rely on costly human annotation that is difficult to scale to complex instructions, or distill responses from proprietary LLMs like GPT-4, which caps the student model's ceiling and cannot guarantee the reliability of distilled data. No prior method provides both scalability and verifiable correctness for instruction-following supervision.

## Input / Output

The method takes a small set of hand-written seed instructions (each encoding a single atomic, code-verifiable constraint), user queries sampled from ShareGPT, and a supervision LLM (Qwen2-72B, LLaMA3-70B, or GPT-4) as inputs. It produces three types of outputs: SFT training pairs (concatenated instruction+query with a verified response), DPO preference pairs (chosen responses passing all verification functions vs. rejected responses failing them), and the Python verification functions themselves, which serve as executable reward signals. A key structural detail is that every training sample is paired with its verification code, enabling on-policy re-scoring during iterative training without re-annotation.

## Method

AUTOIF transforms instruction-following validation into executable code verification through a multi-stage pipeline. First, Self-Instruct augments seed instructions; then the supervision LLM generates both a Python verification function and unit test cases for each instruction, which are cross-validated by compiling the code, checking test-case accuracy above 0.5 in both directions, and back-translating the code into natural language to filter contradictions via an NLI model. Responses are then generated via execution-feedback-based rejection sampling: only responses that pass the verification function are retained for SFT, while pass/fail pairs form DPO preference data at both the instruction and query levels. For online DPO, the SFT model self-samples K responses per query, the verification functions score them as a natural reward model, and the resulting preference pairs drive iterative on-policy optimization that progressively targets the model's remaining weaknesses.

## Results

AUTOIF achieves the first >90% loose instruction accuracy on IFEval, with LLaMA3-70B reaching 90.4% Ins.(L) and Qwen2-72B reaching 88.0% Ins.(L) under self-alignment. In the strong-to-weak setting, LLaMA3-8B shows the most dramatic improvement, jumping from 11.6 to 49.9 average on FollowBench (+38.3 pts) and from 26.1 to 43.1 on IFEval Prompt(L) (+17.0 pts) with Online DPO. General capabilities are preserved: MMLU, GSM8K, and HumanEval scores remain stable or slightly improve across all training configurations. On cross-domain benchmarks, Qwen2-7B with AUTOIF + Online DPO gains +6.71 pts on Arena-Hard and +3.52 on InfoBench over the base model.

## Baselines & Comparisons

On IFEval loose instruction accuracy, AUTOIF with LLaMA3-70B (90.4%) surpasses GPT-4 (85.4%) by 5.0 pts and GPT-3.5 Turbo's implied level, making it the first open-source model to exceed 90% on this metric. On FollowBench, GPT-4 (77.9 avg) still leads AUTOIF's best self-aligned model (67.5 for Qwen2-72B, 66.5 for LLaMA3-70B) by roughly 10–11 pts, but AUTOIF narrows the gap from ~15–17 pts (base models) to ~10 pts. In the strong-to-weak setting, AUTOIF(LLaMA3-8B) dramatically outperforms the base LLaMA3-8B (11.6→49.9 on FollowBench) and even surpasses Mistral-7B (38.0) and Mixtral-8x22B (58.7) on FollowBench, though it remains below GPT-4. For smaller models, AUTOIF(Qwen2-7B) + Online DPO (56.6 FollowBench) exceeds Mixtral-8x22B (58.7) on IFEval Ins.(L) (57.9 vs. 60.0) but falls slightly short on FollowBench. General capabilities (MMLU, GSM8K, HumanEval) are preserved or slightly improved across all AUTOIF variants, confirming no capability regression relative to the base models.

## Relation to Prior Work

AUTOIF builds on Self-Instruct for instruction augmentation, rejection sampling with execution feedback for data generation, and DPO for preference optimization, but its core departure is reframing instruction-following verification as a code-execution problem. Prior approaches to improving instruction-following—Conifer, CodeCLM, and behavior-imitation distillation—rely on proprietary LLMs (e.g., GPT-4) for response generation or quality judgment, capping the ceiling and raising cost. AUTOIF instead uses LLMs to write verification functions and unit tests that are executed by a Python interpreter, enabling fully automated, scalable quality control without any proprietary model in the loop. The execution-feedback learning paradigm is borrowed from code-generation work (CodeRL, RLTF), but applying it to natural-language instruction compliance is a new use of the technique.

## Why It Matters / Open Questions

AUTOIF provides the first fully open-source, scalable pipeline for generating instruction-following training data, and its >90% IFEval loose accuracy (first reported) narrows the gap with proprietary models on this benchmark. A key open question is generalization beyond code-verifiable constraints: while the paper shows transfer to non-verifiable instructions (FollowBench, InfoBench), the absolute gains there are smaller, and truly subjective constraints (style, tone, creativity) remain out of scope. The finding that the supervision model's coding ability strongly correlates with data quality and downstream IF performance suggests a practical bottleneck: weaker open-source models produce lower-quality verification code, limiting the self-improvement loop. Future work on compositional/cross-instructions and on extending verification beyond simple Python checks would address the main limitations.
