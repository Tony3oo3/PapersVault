## Problem

In real-time code editing, a developer's small modification to existing code forces the LLM to re-encode the entire KV cache for accurate next-token prediction, incurring prohibitive latency on long contexts. The naive shortcut of encoding only the edited subsequence and splicing it into the original cache introduces temporal confusion—duplicate or missing positional indices in the Key cache—causing severe accuracy degradation. This paper addresses the efficiency-accuracy trade-off by correcting positional information in the cached keys without full recomputation.

## Input / Output

The method consumes the pre-existing KV cache (all layers), the newly encoded Key/Value vectors for the edited subsequence, and three scalar edit parameters (start index i, end index j, and new token count m). It produces a corrected KV cache in which only the Key vectors for positions after the edit are modified via a single rotation; Value vectors for those positions are left untouched. The corrected cache then feeds standard autoregressive decoding to produce the next-token distribution, with no architectural changes to the LLM itself.

## Method

PIE exploits the algebraic structure of Rotary Position Encoding (RoPE), where the relative-position-dependent attention score decomposes as R_{j-i} = R_i^T R_j. When an edit shifts subsequent tokens by a fixed offset (i+m-j), the stale rotary matrix R_{j'} embedded in each cached key is removed by multiplying with R_{j'}^{-1} and the correct matrix R_{i+m+j'-j} is reapplied. Because RoPE matrices are rotations, this composition collapses to a single rotation R_{i+m-j} applied to each key vector, requiring only one matrix multiplication per key per layer. The Value cache for post-edit positions is preserved unchanged, since RoPE encodes positional information exclusively in the Key pathway. This yields an edited KV cache that closely approximates full recomputation (cosine similarity ≈ 1.0 on key representations, KL divergence < 0.0002 on token distributions) while reducing KV-update latency by over 85%.

## Results

On RepoBench-C-8k (Python, DeepSeek-Coder 6.7B, XF-F setting), PIE achieves 28.83 EM / 70.01 ES in 50 ms, matching Full-recomputation (28.95 EM / 70.11 ES in 561 ms) while reducing KV-cache update latency by ~91%. Across all model sizes (1.3B, 6.7B, 33B) and both languages (Python, Java), PIE reduces computational overhead by 85–95% relative to Full-recomputation, with a maximum relative accuracy gap of 1.33% EM / 2.24% ES on the hardest multi-place edition task. On HumanEval (Python), PIE reaches 43.9 Pass@1 vs. 49.4 for Full-recomputation, far exceeding Conflict Fast Encoding (11.0) and the reuse baseline (17.7).

## Baselines & Comparisons

The paper compares PIE against two baselines: (1) Full-recomputation, which re-encodes the entire KV cache after each edit, and (2) Conflict Fast Encoding, which only encodes the edited subsequence and splices it into the original cache without any positional correction. PIE essentially matches Full-recomputation in accuracy (e.g., 28.83 vs. 28.95 EM on Python 6.7B XF-F insertion; 34.62 vs. 35.75 EM on 33B edition) while cutting KV-cache update time by 85–95% (50 ms vs. 561 ms for 6.7B; 146 ms vs. 2766 ms for 33B). In stark contrast, Conflict Fast Encoding collapses in accuracy—dropping from 28.95 to 5.35 EM (Python 6.7B insertion) or from 35.05 to 0.38 EM (Java 33B insertion)—because the uncorrected rotary matrices create positional index conflicts that corrupt attention. PIE is only marginally slower than Conflict Fast Encoding (50 ms vs. 34 ms for 6.7B) yet recovers nearly all the accuracy lost by the naive splice, confirming that the single matrix-multiplication positional fix (Eq. 6) is both necessary and sufficient to resolve temporal confusion in code editing scenarios.

## Relation to Prior Work

This paper builds directly on Rotary Position Encoding (RoPE) (Su et al., 2021), exploiting the algebraic property that the relative rotary matrix R_{j-i} decomposes as R_i^T R_j to derive a single-matrix-multiplication fix for positional information in the KV cache after edits. It departs from the broader Transformer efficiency literature (FlashAttention, PagedAttention, speculative decoding, KV cache eviction) by targeting a distinct problem: the real-time editing setting where the input context is dynamically modified, rather than the static setting where content is fixed. The 'Conflict Fast Encoding' baseline (naively splicing new KV entries into the old cache) is identified as the natural but broken approach, and PIE is positioned as the minimal correction that resolves the resulting temporal confusion without any re-encoding of downstream tokens.

## Why It Matters / Open Questions

PIE offers a near-free (single matrix multiply) solution to a problem that is central to interactive code assistants, where every keystroke or line edit currently triggers expensive full KV cache recomputation. The 85%+ latency reduction with negligible accuracy loss (≤2.24% relative EM/ES gap) makes real-time code completion practically feasible on commodity hardware. Key limitations include the assumption that semantic impact of edits is negligible (validated for code but not for, e.g., dialog), dependence on RoPE-based architectures, and the fact that only structural/temporal confusion is addressed. Open questions include whether the approach extends to non-RoPE positional encodings, how it interacts with KV cache eviction under memory pressure, and whether the semantic-impact assumption holds for longer or more semantically dense edits.
