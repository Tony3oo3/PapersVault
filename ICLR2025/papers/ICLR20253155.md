## Problem

In long-context LLM inference, KV cache memory grows linearly with sequence length, and prior methods reduce memory by permanently discarding low-attention tokens. However, the paper argues that attention scores reflect only the current reasoning step's relevance, so tokens deemed unimportant now may become critical in subsequent generation steps (e.g., multi-hop chain-of-thought reasoning), making static token dropping lossy. The paper asks: can we reduce KV cache memory and accelerate decoding without ever dropping tokens, while dynamically adapting the active context at every generation step?

## Input / Output

The method takes a long text prompt (tested up to 450K tokens on Llama-3-8B, 150K on Llama-3.1-70B) and an LLM with standard KV cache, operating entirely at inference time with no retraining. During the prefill stage it offloads most layers' KV cache to CPU memory while retaining a small set of 'filter' layers on GPU; during decode, each step produces the next token using only a sparse subset (e.g., 2048 tokens) of the full context in most layers, reducing GPU KV cache occupancy by up to 75% while preserving all tokens in CPU memory for future retrieval.

## Method

OmniKV is built on the insight of Inter-Layer Attention Similarity: the set of high-attention tokens identified in one layer is highly similar to that in subsequent layers, so a few 'filter' layers can select important tokens for all intervening layers. The Context Selector computes attention scores over a short observation window (e.g., the last 16 tokens) in each filter layer, applies a weighted top-k to produce a token index set, and propagates that same index to all non-filter layers between consecutive filter layers. The Context Bank stores the full KV cache in CPU memory and performs packed asynchronous loads—only ≤3 GPU-CPU transfers per decode step—overlapping PCIe transfer with computation via interleaved full-attention layers adjacent to filter layers. Because no tokens are ever discarded, the method is token-dropping-free and training-free, and the dynamic per-step selection preserves performance in multi-step reasoning where the relevant context shifts across generation iterations.

## Results

On LongBench (single-step reasoning), OmniKV w/last achieves 38.5 average on Llama-3-8B-262K at 30% KV cache memory, compared to 39.2 for full attention, 36.8 for H2O, 35.0 for InfLLM, and 28.1 for StreamingLLM. On Llama-3.1-70B at 20% memory, OmniKV w/exp reaches 48.7 average versus 49.2 full attention, 39.9 H2O+, 39.5 InfLLM, and 27.0 StreamingLLM. OmniKV achieves a 1.68× decoding speedup at 128K context and extends the maximum supported context length on a single A100 from 128K to 450K tokens for Llama-3-8B, while reducing KV cache memory by up to 75%.

## Baselines & Comparisons

OmniKV consistently outperforms all three baselines across all model sizes. Against H2O (token-dropping), OmniKV w/last achieves 38.5 vs 36.8 on Llama-3-8B and 48.7 vs 39.9 on Llama-3.1-70B, with the gap widening dramatically on the 70B model (8.8 points vs 2.3 points on 8B). Against InfLLM (block-based retrieval), OmniKV leads by 3.5 points on Llama-3-8B (38.5 vs 35.0) and 9.2 points on Llama-3.1-70B (48.7 vs 39.5), with InfLLM particularly weak on multi-document QA and summarization tasks. Against StreamingLLM (sliding window + attention sinks), OmniKV's advantage is largest, reaching 21.7 points on Llama-3.1-70B (48.7 vs 27.0), as StreamingLLM's fixed window approach fails on synthetic and multi-hop tasks. OmniKV stays within 0.5–1.0 points of full attention across all settings, whereas baselines degrade by 2–22 points. In multi-step reasoning (CoT) on 2WikiMQA, HotpotQA, and 2StageRetr, OmniKV achieves the best Exact Match under all token budgets, while H2O's accuracy on 2StageRetr is capped by its memory budget (e.g., 13% at 30% memory vs 36% for full attention), confirming that static token dropping loses information needed in later reasoning steps.

## Relation to Prior Work

OmniKV carves new ground at the intersection of two previously separate lines of work: token-dropping KV cache compression (H2O, Scissorhands, SnapKV) and KV cache offloading (FlexGen, vLLM). It departs from token-dropping methods by being drop-free, arguing that attention scores at one generation step cannot predict importance at future steps in multi-step reasoning. It departs from offloading methods by exploiting inter-layer attention similarity—a phenomenon where a small set of 'filter' layers identifies nearly the same important tokens as all subsequent layers—thereby reducing PCIe transfer volume by ~10× compared to per-layer offloading. The closest prior work, InfiniGen, leverages cross-layer similarity but only between consecutive layers and still incurs GPU idleness; OmniKV generalizes this to non-adjacent layers and overlaps transfer with computation.

## Why It Matters / Open Questions

The practical impact is substantial: extending Llama-3-8B's maximum context from 128K to 450K on a single A100 while achieving 1.68× decoding speedup with no performance loss is a significant engineering win for long-context deployment. The token-dropping-free design is particularly important for chain-of-thought and multi-hop reasoning, where the 2StageRetr benchmark demonstrates that static token selection fundamentally fails. Open questions include whether the inter-layer similarity insight holds for architectures beyond standard Transformers (e.g., Mamba, hybrid models), how the method interacts with KV cache quantization (mentioned as future work), and whether the per-model 'filter' layer identification can be automated or predicted from architecture alone.
