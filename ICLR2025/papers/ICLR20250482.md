## Problem

Existing LLM-driven agents rely on fixed, text-only in-context examples for tool selection, which degrades performance on multi-modal tasks where visual content determines the appropriate tool. While VLM-driven agents can leverage visual information, they lack large-scale, high-quality training data with complex multi-step tool-usage trajectories, limiting their reasoning ability for practical tasks.
![Teaser figure](../imgs/ICLR20250482/cropped_page0_idx0.webp)

## Input / Output

The agent receives a natural-language query plus optional multi-modal files (images, PDF, PPTX, XLSX, DOCX, and 6 other types) and produces a step-by-step ReAct trajectory where each step outputs a natural-language thought followed by executable Python code that invokes one of nine deployed tools (web search, image QA, file inspector, segmentation, object localization, image generation/editing, face detection, Python packages). The final output is either a descriptive text answer or a generated image, and the trajectory length ranges from 2 to 8+ steps depending on task complexity.

## Method

The paper introduces a three-stage data synthesis pipeline that automatically generates the MM-Traj dataset (20K tasks, 15K files): GPT-4o-mini generates diverse queries, files are produced by retrieving images from 93K source images via BGE embedding similarity or generating non-image files through GPT-4o-mini-written Python code, and a zero-shot ReAct agent (GPT-4o-mini controller) solves each task to collect executable trajectories. Two LLM-based verifiers (query-file relevance and trajectory correctness) filter low-quality samples. The VLM controller (MiniCPM-V-8.5B or Qwen2-VL-7B) is then fine-tuned with LoRA (rank 64 on Q/K/V projections) using cross-entropy loss over thought and code tokens across all trajectory steps, deliberately excluding the final answer from the loss to force the model to rely on tools rather than internal knowledge. The vision encoder and visual token compressor are frozen during training, and the model is trained for 5 epochs with a 10240-token context window to accommodate long trajectories.

## Results

On the GTA benchmark, T3-Agent with Tuned Qwen2-VL-7B achieves 53.85% AnsAcc, 64.63% ToolAcc, and 84.32% CodeExec, while Tuned MiniCPM-V-8.5B reaches 52.56% AnsAcc, 65.85% ToolAcc, and 80.49% CodeExec. These represent approximately 18–29% relative improvements over their untrained counterparts (e.g., MiniCPM-V-8.5B goes from 33.97% to 52.56% AnsAcc). On the GAIA validation set, T3-Agent with Tuned Qwen2-VL-7B achieves 16.97% AnsAcc (vs. 9.70% untrained), and Tuned MiniCPM-V-8.5B reaches 15.15% (vs. 7.27% untrained), with notable gains at Level 1 (26.42% vs. 16.98%/13.21%).

## Baselines & Comparisons

Against the Lego Agent (which uses GPT-4 as controller), T3-Agent with Tuned Qwen2-VL-7B achieves a higher AnsAcc (53.85% vs. 46.59%) on GTA, demonstrating that a tuned 7B VLM can surpass a closed-source LLM agent. Compared to the HF Agent baseline (same tools, untrained VLMs), trajectory tuning yields substantial gains: MiniCPM-V-8.5B improves from 33.97% to 52.56% AnsAcc (+18.59 pp) and Qwen2-VL-7B from 42.31% to 53.85% (+11.54 pp), with ToolAcc jumping by ~20–29 pp. However, T3-Agent still trails the HF Agent with GPT-4o (57.05% AnsAcc) by ~3–4 pp, though it matches or exceeds GPT-4o on ToolAcc (65.85% vs. 63.41%), indicating stronger tool-selection reasoning but weaker code executability. On GAIA, T3-Agent (16.97% AnsAcc) significantly outperforms all open-source VLM baselines (best untrained: Qwen2-VL-7B at 9.70%) but remains well below the Sibyl Agent with GPT-4-turbo (29.70%) and the HF Agent with GPT-4o (33.40%), which the authors attribute to the larger model scale and training data of closed-source models.

## Relation to Prior Work

This paper extends the ReAct agent framework (Yao et al., 2023) to the multi-modal setting by tuning VLM controllers on synthetic tool-usage trajectories, building on prior VLM tool-usage tuning efforts such as MLLM-Tool, LLaVA-plus, and VisualAgentBench. However, those prior methods focus on simple one- or two-tool tasks with small datasets (~1K samples) and often rely on predefined trajectory templates. The key departure here is a fully automated data synthesis pipeline (query → file → trajectory) with LLM-based verifiers that scales to 20K complex multi-step trajectories across diverse file types (images, PDFs, PPTX, XLSX, audio), moving beyond the text-only tool-usage datasets (APIBank, ToolBench) and the image-only focus of most multi-modal agent benchmarks.

## Why It Matters / Open Questions

The ~20% improvement over untrained VLMs on both GTA and GAIA validates that trajectory-level fine-tuning is an effective route to closing the tool-usage gap between open-source VLMs and closed-source LLMs, and the MM-Traj dataset (20K tasks, 15K files, 16 knowledge domains) provides a reusable resource for the community. A notable limitation is that the agent only leverages multi-modal information in the query, not in intermediate trajectory observations (e.g., edited images or generated outputs), which constrains step-by-step reasoning on tasks like iterative image editing. The persistent gap with GPT-4o (52.56 vs. 57.05 on GTA; 16.97 vs. 33.40 on GAIA) and the lower CodeExec scores suggest that programming capability remains a bottleneck for smaller VLMs, pointing toward the need for stronger code-generation pretraining or hybrid architectures.
