## Problem

As tool repositories grow to tens of thousands of APIs, existing LLM agent pipelines that separate retrieval (via a BERT-based or embedding-based retriever) from execution (via the LLM) suffer from context-length constraints, error propagation between stages, and misalignment between what is retrieved and what is actually needed. This paper asks whether tool retrieval and tool calling can be unified into a single generative process, eliminating the external retriever entirely.

## Input / Output

The model takes a free-form user query as input without any tool descriptions or candidate lists in the prompt. During inference, after the model generates a virtual tool token, the corresponding tool documentation is fetched and injected as a user-role message, which the model then uses to produce JSON arguments. A constrained beam search restricts the action-generation step to the set of valid tool tokens, preventing hallucinated tool names. The final output is a sequence of (thought, tool token, parameters, tool feedback) tuples ending with a final answer.

## Method

ToolGen expands the Llama-3-8B vocabulary by ~47,000 atomic tokens (one per API, formatted as <<ToolName&&APIName>>), each initialized with the average embedding of its tool name. Training proceeds in three supervised stages: (1) tool memorization, where the model learns to predict the tool token from its documentation; (2) retrieval training, where it learns to generate the correct tool token from a user query; and (3) end-to-end agent tuning on ReAct-style trajectories decomposed into separate Thought, Action-token, and Parameter turns (following Agent-Flan). At inference, a disjunctive-trie-based constrained beam search masks out all non-tool-token logits during the action step, guaranteeing zero hallucination of nonexistent tools while keeping each tool to a single generation step for efficiency.

## Results

On the ToolBench retrieval benchmark (47k APIs), ToolGen (Llama-3-8B) achieves NDCG@1 of 89.17 (I1), 91.45 (I2), and 87.00 (I3) in the In-Domain setting, matching or exceeding the multi-model IterFeedback system (90.70/89.01/91.74) while using a single model. In the harder Multi-Domain setting, ToolGen maintains NDCG@1 of 87.67/83.46/79.00, substantially outperforming ToolRetriever (72.31/64.54/52.00). For end-to-end agent tasks on StableToolBench, ToolGen achieves an average SoPR of 54.19 (with ground-truth tools) and 53.28 (with retrieval), surpassing GPT-3.5 (50.91/45.00) and ToolLlama (52.78/51.55).

## Baselines & Comparisons

ToolGen substantially outperforms all unsupervised baselines: BM25 (NDCG@1 ~29–32), EmbSim (~49–64), and Re-Invoke (~55–69) are all far below ToolGen's 87–91 range. Against the supervised ToolRetriever (BERT-based contrastive retriever from ToolBench), ToolGen leads by 8–17 points on NDCG@1 across domains, with the gap widening dramatically in the Multi-Domain setting (e.g., 79.00 vs. 52.00 on I3). ToolGen is most competitive with IterFeedback, a multi-model system with iterative GPT-3.5 feedback: ToolGen matches or exceeds it on I2 NDCG@1 (91.45 vs. 89.01) and I1 NDCG@5 (92.67 vs. 92.47), while trailing slightly on I1 NDCG@1 (89.17 vs. 90.70) and I3 NDCG@1 (87.00 vs. 91.74). In the end-to-end agent evaluation, ToolGen achieves the best average SoPR (54.19 G.T., 53.28 Retriever) and SoWR (49.70 G.T., 51.51 Retriever), outperforming GPT-3.5 and both ToolLlama variants, with the largest margin over GPT-3.5 in the Retriever setting (53.28 vs. 45.00 SoPR). Notably, ToolGen achieves these results without any external retriever, whereas all baselines require a separate retrieval module.

## Relation to Prior Work

ToolGen extends the generative retrieval paradigm (Wang et al., 2022; Sun et al., 2023) from document retrieval to tool retrieval by representing each API as a unique virtual token in the LLM vocabulary, so that tool selection becomes a next-token prediction problem. It departs from the dominant retriever-generator pipeline (ToolRetriever, Gorilla) that uses a separate BERT-based contrastive retriever to narrow candidates before LLM execution, and from ToolkenGPT (Hao et al., 2023), which also introduced tool-specific tokens but was limited to simple tools with few inputs and relied on few-shot prompting rather than full-parameter fine-tuning. The inference strategy of decomposing ReAct into separate Thought/Action/Parameter conversational turns follows Agent-Flan (Chen et al., 2024c).

## Why It Matters / Open Questions

By embedding 47k tools directly into model parameters, ToolGen eliminates the separate retrieval infrastructure and context-length bottleneck that constrain current tool-use systems, enabling a single 8B model to match multi-model retrieval pipelines (IterFeedback) while guaranteeing zero hallucination of nonexistent tools via constrained decoding with atomic indexing. Key open questions remain: how to efficiently add or update tools without retraining (the paper acknowledges this limitation and points to continual learning methods), whether the approach generalizes beyond the ToolBench API ecosystem, and how to integrate reinforcement learning and chain-of-thought reasoning with the generative tool-calling loop. The finding that mixing in general instruction data (ToolGen-Instruct) actually improves tool-task performance by 3–5 points suggests an underexplored synergy between general capability and specialized tool use.
