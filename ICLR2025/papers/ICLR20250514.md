## Problem

LLM-based agent systems suffer from substantial planning latency due to both the computational cost of large backbone models and the extended intermediate thought generation required by complex architectures such as ReAct, chain-of-thought, and tree-of-thought. Existing agent frameworks treat planning as a blackbox process with no mechanism for user interaction during execution, forcing users to wait unresponsively for the full plan to complete. No prior work co-designs the algorithmic planning pipeline with an interactive user interface to simultaneously address time efficiency and human-in-the-loop engagement.

## Input / Output

The system takes a natural language task prompt and processes it through two parallel agents (a fast approximation agent and a slower target agent), with the option of user keyboard interruptions at any point during planning. The output is a sequential action plan (tool calls with natural language parameters) and execution trajectory, presented through a rescheduling mechanism that serializes asynchronously computed results into a coherent step-by-step display. User interruptions can replace individual action steps with human-provided values, effectively treating the user as a third oracle agent whose input is incorporated directly into the action trajectory without disturbing other concurrent processes.

## Method

The core algorithm adapts speculative decoding to agent planning: a fast approximation agent A generates action steps sequentially, while a slower target agent T asynchronously verifies each step using A's trajectory as a provisional prefix, with a hyperparameter k bounding the maximum number of concurrent T processes. When A and T agree on a step, the step is accepted; on mismatch, T's result replaces A's and all subsequent speculative steps based on the incorrect prefix are discarded. A UI-level rescheduling mechanism serializes the asynchronous outputs into sequential presentation, showing the user verified steps and highlighting the latency gap between A and T to identify bottlenecks. The system enables two forms of user interruption: during the latency window between A's and T's outputs (where the user provides their own step value), and after T's output is presented (where the user can modify the step). The approach is training-free and architecture-agnostic, supporting any combination of approximation and target agents such as direct generation, ReAct, chain-of-thought, or multi-agent debate.

## Results

On the OpenAGI benchmark, Interactive Speculative Planning reduces total generation time by 22.27% (Setting 1, ReAct), 28.32% (Setting 2, CoT), 42.30% (Setting 3, Multi-Agent Debate), and 20.37% (Setting 4, Direct Generation) compared to normal agent planning. Stepwise time reductions range from 23.50% to 38.29% across settings. On TravelPlanner, total time reductions are 21.43%, 19.18%, and 25.46% for Settings 1–3, with stepwise reductions of 29.52%, 32.53%, and 31.69%. The time savings come at a cost increase of ~70% for Settings 1–2, ~37% for Setting 3, and negligible for Setting 4 (GPT-3.5 as approximation agent).

## Baselines & Comparisons

The paper compares speculative planning against three normal agent planning baselines: ReAct (Setting 1), Chain-of-Thought (Setting 2), and Multi-Agent Debate (Setting 3), all using GPT-4-turbo as the target agent backbone. Speculative planning consistently wins on time efficiency across all settings and both benchmarks: it reduces total time by 22–42% and stepwise time by 24–38% on OpenAGI, and by 19–25% total / 30–33% stepwise on TravelPlanner. The largest gains come from Setting 3 (MAD), where the target agent is slowest, yielding 42.30% total time reduction on OpenAGI. However, speculative planning always loses on cost: monetary cost increases by ~70% for Settings 1–2, ~37% for Setting 3, and is nearly unchanged for Setting 4 (GPT-3.5 approximation agent). Total token generation also increases substantially (e.g., 6781 vs 4075 tokens for MAD), reflecting the overhead of running both agents concurrently. The method guarantees that worst-case time equals normal planning (no step from A is usable), so it never degrades time efficiency below the baseline in theory, though minor negative improvements are observed empirically due to API concurrency effects.

## Relation to Prior Work

This paper adapts the speculative decoding paradigm from LLM inference (Leviathan et al., 2023; Chen et al., 2023) to the agent planning domain, where a fast approximation agent drafts steps while a slower target agent asynchronously verifies them. It departs from prior cost-efficient agent work (EcoAssistant, System-1.x Planner) by being training-free and by guaranteeing performance at least equivalent to the target agent alone. The key conceptual departure is the co-design of the backend algorithm with a rescheduling user interface that treats human interruptions as a first-class system component rather than a passive UX feature, drawing on mixed-initiative HCI principles (Horvitz, 1999) and LLM serving scheduling (Oh et al., 2024).

## Why It Matters / Open Questions

The paper addresses a practical and growing pain point—agent planning latency—and offers a principled, training-free mechanism to reduce it by 20–42% across diverse agent architectures (ReAct, CoT, multi-agent debate). However, the speedup comes with a 37–70% increase in API cost, and the step-by-step exact-match verification is acknowledged as overly aggressive, limiting real-world applicability. Open questions include relaxed or postponed judgment methods, security risks from executing unverified approximation steps (analogous to Spectre vulnerabilities), and the need for backtracing in the UI. The framing of the human as a third 'agent' that accelerates the loop is an interesting but under-explored direction for human-AI collaborative planning.
