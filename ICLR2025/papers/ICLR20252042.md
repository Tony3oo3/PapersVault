## Problem

Existing LLM-based multi-agent systems rely on human-assigned roles to coordinate agents, but in heterogeneous multi-robot systems, each agent's capabilities are inherently determined by its physical hardware (mobility, perception, manipulation) rather than a predefined role. No system has achieved Level-4 full automation of heterogeneous multi-robot systems, and the missing key component is embodiment-aware reasoning: the ability of an agent to understand its own physical embodiment and use that understanding to plan, assign, and execute tasks without human-crafted protocols.

## Input / Output

The system consumes robot URDF files (pre-processed into a skeleton tree of links and joints), a textual scene description derived from a region connectivity graph and agent/object state layers, a natural-language task description, and numerical forward-kinematics data (e.g., arm workspace hulls, camera frustum parameters). It produces a decomposed subtask plan with robot-to-subtask assignments, followed by a sequence of low-level robot control actions (navigate_to, move_arm_to, pick, place) issued via LLM function calling, and a final task completion status. The robot resume is structured as a JSON file pairing natural-language capability summaries with numerical representations, and the scene context is built bottom-up from four geometric layers (region graph, semantic mesh, agent/object states, navmesh), with only the graph and state layers converted to text for the LLM while the mesh and navmesh remain for low-level trajectory planning.

## Method

EMOS introduces a self-prompted 'robot resume' generation pipeline that replaces human-assigned role-playing: each robot's URDF is pre-processed into a skeleton tree, an LLM summarizes the robot's mobility, perception, and manipulation capabilities in natural language, and the LLM simultaneously calls forward-kinematics tool functions to extract numerical details such as the 3D hull of sampled end-effector positions (arm workspace) and camera frustum geometry. The framework operates in three cascading stages: (1) scene context construction from an ideal SLAM representation, (2) centralized group discussion where a leader LLM decomposes the task and assigns subtasks, and each robot-dedicated agent reflects on feasibility using its resume—performing both commonsense reasoning over textual summaries and code generation over numerical data for spatial checks—feeding back to the leader for reassignment, and (3) decentralized parallel action execution where each agent issues function calls to robot control libraries (trajectory planner + IK solver) and appends action-response pairs to its local history. The communication topology follows the HMAS-2 star architecture, and the entire system is untrained, relying entirely on GPT-4o's pre-trained reasoning and code-generation abilities.

## Results

On the Habitat-MAS benchmark (519 episodes, GPT-4o), EMOS achieves a 37.82% task success rate and 81.26% sub-goal success rate, consuming 80,783 tokens and 2,358 simulation steps on average. Removing the robot resume drops success rate to 15.63% (−22.2 pp), and removing group discussion drops it to 15.23% (−22.6 pp). The numerical forward-kinematics component is critical for manipulation-heavy tasks: single-floor rearrangement success falls from 28.35% to 9.20% and multi-floor rearrangement from 13.46% to 3.85% when numerical capability descriptions are removed.

## Baselines & Comparisons

The paper does not compare against external multi-robot coordination baselines; instead, it ablates its own components to isolate their contributions. EMOS with the full robot resume (textual URDF summary + numerical forward-kinematics data) and centralized group discussion outperforms every ablated variant by a wide margin. The largest single-component impact comes from removing the robot resume entirely (replacing it with human-authored role descriptions, as in CAMEL/MetaGPT-style role-playing), which halves success rate from 37.82% to 15.63% and increases simulation steps from 2,358 to 3,125, indicating that self-generated embodiment-aware reasoning is substantially more effective than fixed role assignments. Removing only the numerical (forward-kinematics) portion while keeping the textual URDF summary yields 23.56% success, showing that LLMs can partially infer mobility from URDF structure (e.g., recognizing 'wheel' vs. 'leg' nodes) but cannot reliably reason about precise arm workspace geometry without explicit numerical tools. The w/o. Discussion baseline (agents act directly from raw task + scene descriptions without a leader or reflection loop) achieves the lowest success rate (15.23%) despite using the fewest tokens (36,377), confirming that the hierarchical planning-and-reflection pipeline is essential for correct task decomposition across heterogeneous embodiments.

## Relation to Prior Work

This paper extends the LLM-based multi-agent system line (MetaGPT, CAMEL, AutoGen) by replacing human-assigned role-playing with a self-prompted 'robot resume' generated from URDF files and forward-kinematics tool calls, grounding agents in actual physical capabilities rather than abstract roles. For the multi-robot coordination side, it builds on the HMAS-2 hierarchical communication topology (Chen et al., 2024) and the Hydra scene-graph representation (Hughes et al., 2022), but departs from traditional HMRS literature (Rizk et al., 2019) by eliminating human-crafted task allocation protocols in favor of LLM-driven embodiment-aware reasoning. The Habitat-MAS benchmark extends the Habitat 3.0 simulation platform (Puig et al., 2023) with multi-robot episodes specifically filtered so that only robots with matching physical capabilities can complete subgoals, a design absent from prior multi-robot or embodied-AI benchmarks.

## Why It Matters / Open Questions

The robot resume concept offers a practical, training-free mechanism to ground LLM agents in physical robot specifications, potentially reducing the reliance on hand-engineered role descriptions in multi-robot deployments. However, the system's dependence on a perfect SLAM front-end, the absence of physics simulation (contact-based grasping instead of PyBullet), and the moderate 37.82% success rate on the hardest task limit near-term real-world applicability. Open questions include scalability beyond ~6 robots (where hallucinations degrade performance), handling dynamic or adversarial environments, and whether the embodiment-aware reasoning generalizes to robot types not represented in the URDF-to-resume pipeline. The benchmark itself is likely to become a useful reference point for future LLM-based multi-robot coordination work.
