## Problem

Existing prompt-engineering architectures for LLM reasoning (CoT, ToT, GoT) either rely on external tools or specific examples to evaluate answer quality, use fixed temperature settings, and underutilize the rationale steps that LLMs generate. This paper addresses how to automatically enhance a base prompt with LLM-generated rationales and dynamically control exploration versus exploitation across a reasoning graph, without requiring external evaluation metrics or hand-crafted examples.
![Teaser figure](../imgs/ICLR20252906/cropped_page1_idx0.webp)

## Input / Output

The method takes a single base prompt containing the problem statement and data (e.g., a list of numbers to sort, a grid layout for Frozen Lake) and produces a final merged response from the graph's leaf nodes. Internally, each node outputs an answer with a multi-step rationale, a numeric score (0–100) whose log-probability is extracted for confidence estimation, and an aggregated rationale that emphasizes only errors and conflicts. The score probability threshold is task-specific (e.g., 0.99 for extreme scores 0/100 in sorting, 0.95 in Frozen Lake), and the question is repeated verbatim in the prompt to reduce LLM misinterpretation.

## Method

EGoT organizes reasoning in a graph where each node contains three sequential sub-nodes: an ANSWERINGNODE that generates an answer and rationale, an EVALUATIONNODE that scores the answer (with re-querying if the log-probability of the score token falls below a threshold), and an AGGREGATERATIONALENODE that merges both rationales while isolating inaccuracies and conflicts for propagation to child nodes. The key differentiator is a dynamic temperature schedule using cosine annealing over graph depth, where the minimum temperature t_min is set to 1 − √(1−(c−1)²) with confidence c = s·Pr(s)^(1/e), so high-confidence branches exploit (low temperature) while low-confidence branches continue exploring (high temperature). Multiple root nodes at temperature 1 ensure initial diversity, and the graph progressively narrows toward precise answers. At the leaf level, all aggregated rationales are merged into a single final prompt to produce the output, and the entire pipeline is fully automated from a single base prompt without external verifiers or task-specific examples.

## Results

On the 256-element number sorting task with GPT-4o mini, EGoT achieves 88.31% accuracy and 34.54 number of errors (NOE), outperforming GoT (84.37%, 40.93 NOE), ToT (75.58%, 65.74 NOE), and CoT2 (83.17%, 49.25 NOE). On the Frozen Lake task with GPT-4o (5×5, 10 holes), EGoT averages 0.55 jumps/falls versus 0.89 for ToT and 0.80 for CoT. On the 128-element sorting task, ToT edges out EGoT slightly (92.28% vs. 92.09% accuracy), while on document merging EGoT (76.01%) underperforms CoT (77.79%) and ToT (76.74%).

## Baselines & Comparisons

Against GoT, EGoT wins on both sorting scales: 88.31% vs. 84.37% accuracy on 256 elements (a 3.94-point gain) and 92.09% vs. 90.98% on 128 elements. Against ToT, EGoT shows a large advantage on 256-element sorting (88.31% vs. 75.58%, a 12.73-point gap) and on Frozen Lake with GPT-4o (0.55 vs. 0.89 NOE), but ToT narrowly wins on 128-element sorting (92.28% vs. 92.09%). Against CoT (specifically CoT2, which repeats the question before sorting), EGoT outperforms on 256-element sorting (88.31% vs. 83.17%) and Frozen Lake (0.55 vs. 0.80 NOE with GPT-4o), but loses on document merging (76.01% vs. 77.79%), suggesting that LLM self-evaluation without external verification does not always surpass well-structured CoT prompts. The EGoT* variant (fixed temperature = 1) performs nearly identically to EGoT on Frozen Lake but slightly worse on 256-element sorting (87.94% vs. 88.31%), confirming that dynamic temperature control provides a modest but consistent benefit on harder tasks.

## Relation to Prior Work

EGoT extends the Graph of Thoughts (GoT) architecture by embedding a three-stage sub-node (Answering, Evaluation, Aggregate Rationale) at each graph node, drawing on Exchange-of-Thought (EoT) and DetermLR for its rationale-propagation mechanism. Its key departure from GoT is the introduction of dynamic temperature scheduling via cosine annealing, where the minimum temperature is inversely tied to a confidence score derived from both the LLM's self-assigned score and the log-probability of that score token. Unlike ToT, which explores branches and prunes via external evaluation, EGoT relies entirely on internal LLM self-evaluation and rationale aggregation, avoiding the need for problem decomposition or external verification tools.

## Why It Matters / Open Questions

The paper demonstrates that rationale aggregation—continuously integrating valid reasoning steps while discarding incorrect ones—can serve as a structural alternative to answer voting, and that coupling temperature to confidence via cosine annealing yields consistent gains on combinatorial and pathfinding tasks. However, the scope remains narrow: experiments cover only sorting, frozen lake, and document merging, and the document merging result (EGoT underperforming CoT and ToT) honestly reveals that autonomous LLM scoring does not universally outperform simpler prompting strategies. Open questions include whether the approach scales to genuinely complex multi-step reasoning (the authors note chess puzzles remain unsolvable), whether the 3× computational overhead is justified at larger scale, and whether the log-probability-based confidence signal generalizes across model families (Llama and Mixtral consistently output score 100, requiring re-querying).
