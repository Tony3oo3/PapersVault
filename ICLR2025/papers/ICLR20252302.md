## Problem

Traditional RNNs like LSTM, GRU, and sLSTM possess state-tracking capabilities essential for time-series tasks and logical reasoning, but their strictly sequential processing makes them appear impractical on modern GPUs. Existing open-source implementations (e.g., HASTE) are limited by alternating kernel calls and lack support for modern dtypes or multi-head parallelization, while closed-source libraries like cuDNN are not easily extensible. The paper addresses how to make these sequential RNNs fast enough to be competitive in practice through hardware-aware kernel design.

## Input / Output

The kernel consumes a sequence of input vectors x_t (one per timestep), a block-diagonal recurrent weight matrix R (partitioned into N_heads blocks of size d_head × d_head), per-gate bias vectors b, and initial hidden states s_0. It produces hidden states at every timestep, gate pre-activation values (stored for the backward pass), and gradients via BPTT. The recurrent matrix is kept resident in registers/SRAM across the entire time loop, so only the evolving states and inputs require HBM access per step. The fused variant supports head dimensions up to ~2688 on H100 (limited by register+SRAM capacity), while the alternating variant has no such limit.

## Method

FlashRNN fuses the recurrent matrix multiplication and pointwise activation into a single persistent CUDA kernel that iterates over all timesteps without returning to HBM for the recurrent weights R and biases b, which are cached in registers (and SRAM when register capacity is exceeded). A head-wise parallelization scheme partitions the recurrent matrix into block-diagonal blocks, enabling parallel computation across heads in different thread blocks—mirroring the multi-head attention paradigm. The library introduces ConstrINT, an integer constraint satisfaction solver with divisibility constraints, to automatically determine optimal tiling, warp, block, and loop dimensions that fit within the hardware's register, SRAM, and tensor-core size limits. Two kernel variants are provided: a fused version (maximum speed, 3–4× faster than alternating for small batches) and an alternating version (arbitrary head dimensions). The implementation supports bfloat16, generic state/gate counts per cell, and both forward and backward passes, achieving up to 50× speedup over vanilla PyTorch.

## Results

FlashRNN achieves up to 50× speed-up over vanilla PyTorch LSTM and supports 40× larger hidden sizes than the Triton variant. On 165M-parameter language modeling (SlimPajama, 8×H100), the 12-head LSTM CUDA fused kernel trains in 5.9 h (0.325 s/step, 22.2 val PPL) versus 2.9 h for the Transformer baseline (0.190 s/step, 17.9 val PPL), a ~25% slowdown. On the parity extrapolation task, traditional RNNs (Elman, GRU, LSTM) in FlashRNN achieve 1.00 accuracy at sequence lengths up to 256, while Transformer (0.52), Mamba (0.56), and mLSTM (0.54) all fail near random chance.

## Baselines & Comparisons

Against the Transformer baseline (Vaswani et al., 2017), FlashRNN LSTM with 12 heads is ~25% slower in training time (5.9 h vs 2.9 h) and achieves higher validation perplexity (22.2 vs 17.9), but decisively wins on the parity extrapolation task (1.00 vs 0.52 accuracy), demonstrating state-tracking capability that Transformers lack. Mamba (Gu & Dao, 2023) and mLSTM (Beck et al., 2024) both fail the parity task (0.56 and 0.54 respectively), while FlashRNN's traditional RNNs reach perfect 1.00 accuracy. Against PyTorch nn.LSTM (cuDNN backend), FlashRNN CUDA fused is 2–3× faster at medium batch sizes (8–64) but ~3× slower at the single-head d=768 setting; however, FlashRNN converges faster in language modeling (22.2 vs 25.8 val PPL) and supports multi-head block-diagonal recurrent matrices that nn.LSTM cannot. The Haste library (Sharvil, 2020) is outperformed by FlashRNN's fused kernels due to kernel fusion, bfloat16 support, and multi-head parallelization. FlashAttention2 (Dao, 2024) is included only as a non-RNN runtime reference and is not a direct architectural competitor.

## Relation to Prior Work

FlashRNN applies the I/O-aware kernel fusion paradigm established by the FlashAttention line of work (Dao et al., 2022; Dao, 2024) to traditional RNNs, fusing recurrent matrix multiplication and pointwise activations into a single persistent kernel with register-level caching of recurrent weights. It extends the multi-head parallelization primitive from Transformers to RNNs via block-diagonal recurrent matrices, building directly on the sLSTM/xLSTM architecture (Beck et al., 2024). Unlike the prior open-source HASTE library (Sharvil, 2020), which alternates between separate matmul and pointwise kernels, FlashRNN introduces a novel auto-tuning framework (ConstrINT) that solves integer constraint satisfaction problems over hardware-internal cache and register sizes, drawing on polyhedral constraint optimization concepts from compilers (Baghdadi et al., 2018).

## Why It Matters / Open Questions

This work demonstrates that traditional RNNs with state-tracking capabilities—essential for tasks like parity and logical reasoning where Transformers and SSMs provably fail—can be made practically competitive on modern GPUs, closing the speed gap to Transformers to roughly 25% with multi-head parallelization. The open-sourced ConstrINT library is a general-purpose tool for hardware-internal optimization that extends beyond RNNs to any kernel requiring register/SRAM tiling decisions. Open questions include whether Hopper-generation features (asynchronous memory operations, inter-SRAM connections) can further close the remaining gap, and the unexplained numerical convergence differences between FlashRNN and cuDNN LSTM implementations that warrant further investigation.
