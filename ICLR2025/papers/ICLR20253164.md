## Problem

Most existing code benchmarks (HumanEval, MBPP, MultiPL-E) are centered on Python, with other languages obtained by translation rather than independent authorship, which degrades data diversity and limits the evaluation of true multilingual coding ability. The community lacks a hand-written, massively multilingual benchmark that simultaneously covers code generation, explanation, and completion across a broad set of programming languages.
![Teaser figure](../imgs/ICLR20253164/cropped_page0_idx1.webp)

## Input / Output

For code generation, the model receives a natural-language problem description plus example test cases and must produce a complete function; for code explanation, it first generates a natural-language description of a given code snippet and then restores code from that description (two-pass evaluation); for code completion, it fills in a missing middle span given prefix and suffix code. The benchmark spans 40 languages with ~50 samples per language per task (16K total), and evaluation is execution-based Pass@1 in a Docker sandbox, except for markup languages (JSON, HTML, Markdown) where an exact-match subcomponent check is used instead of execution.

## Method

MCEVAL is constructed through a rigorous human annotation pipeline: 10 software developers independently author problem definitions, solutions, and test cases for each of 40 languages, with dual-annotator verification and senior adjudication ensuring >90% test-case pass rate. The companion instruction corpus MCEVAL-INSTRUCT (110K samples) is built by prompting GPT-4 to refine crawled code snippets into self-contained question-answer pairs, then applying cross-lingual code transfer—randomly sampling a (question, answer) pair from one language and forcing the LLM to rewrite it into another language with increased complexity—to reduce the gap between high- and low-resource languages. MCODER is obtained by supervised fine-tuning CodeQwen-1.5 (7B) on MCEVAL-INSTRUCT for 2 epochs with AdamW (lr 2e-5, cosine schedule, batch 512, max length 4096) on 8×A800 GPUs, and is evaluated alongside 30+ open- and closed-source models using greedy Pass@1 in a Dockerized execution environment.

## Results

On MCEVAL's multilingual code generation task (40 languages, 2,007 samples), GPT-4o and GPT-4 Turbo achieve the highest Pass@1 scores (~63.4% average across all languages), substantially outperforming open-source models. MCODER (7B, fine-tuned on MCEVAL-INSTRUCT) achieves ~54.7% average Pass@1, outperforming several larger open-source models (e.g., CodeLlama-72B at ~39.6%, WizardCoder-34B at ~43.4%). On code explanation, GPT-4o reaches 65.8% while MCODER achieves 51.4%, and on code completion, GPT-4 Turbo leads at 82.7% with MCODER following at 78.9%. The benchmark reveals a persistent gap between closed-source (GPT-4 series) and open-source models across nearly all 40 programming languages.

## Baselines & Comparisons

MCODER (7B) outperforms CodeLlama-72B (39.6%), WizardCoder-34B (43.4%), OCTOCODER-16B (~30%), and WizardCoder-V1.0-15B (~30.2%) on code generation, demonstrating that targeted multilingual instruction tuning on MCEVAL-INSTRUCT enables a 7B model to surpass much larger open-source baselines. However, MCODER trails GPT-4o/GPT-4 Turbo by roughly 9 percentage points and DeepSeek-Coder-V2-Instruct by a similar margin, confirming the persistent gap between closed-source and open-source models. On code explanation, MCODER (51.4%) slightly edges out DeepSeek-Coder-Instruct (50.8%) and Yi-Large Turbo (50.6%) but remains well below GPT-4o (65.8%) and GPT-4 Turbo (62.6%). On code completion, MCODER (78.9%) approaches GPT-4 Turbo (82.7%) and surpasses Magcoder2-SDS (68.8%) and all other open-source models, indicating that completion is a task where open-source models narrow the gap most. The cross-lingual transfer experiment further shows that fine-tuning CodeQwen-1.5 with Python-only data (CodeQwen-1.5-Python) already yields significant multilingual gains, suggesting the base model retains strong coding ability but lacks instruction-following alignment.

## Relation to Prior Work

This paper extends the execution-based code evaluation paradigm established by HumanEval and MBPP to a massively multilingual setting, departing from prior multilingual benchmarks (MultiPL-E, MBXP, HumanEval-X) that either translated Python problems into a handful of languages or covered at most 18 languages. MCEVAL's key conceptual departure is that all 16K problems across 40 languages are hand-written by professional developers rather than machine-translated, preserving native idioms and language-specific constructs. The instruction-tuning component (MCODER) builds on the standard SFT pipeline (Ouyang et al., 2022) applied to code, with the addition of a cross-lingual code transfer step that adapts instruction samples across languages to reduce inter-language gaps.

## Why It Matters / Open Questions

MCEVAL reveals a persistent and substantial performance gap between closed-source (GPT-4o, GPT-4 Turbo) and open-source code LLMs across 40 languages, in stark contrast to the near-parity observed on Python-centric benchmarks like HumanEval—suggesting that multilingual code capability remains a genuine frontier. The finding that Python-only instruction fine-tuning transfers effectively to other languages (cross-lingual transfer) offers a practical, low-cost path for improving multilingual code models. Open questions include whether the gap narrows with scale, how the benchmark generalizes beyond 40 languages (many models claim 80+), and whether the hand-written approach scales economically to even broader coverage.
