## Problem

Claims that LLM-based agents can automate scientific discovery end-to-end (e.g., The AI Scientist) lack rigorous evidence because no high-quality benchmark exists to evaluate agents on individual, essential tasks within real-world data-driven discovery workflows. Without task-level assessment, it is impossible to determine whether agents can actually handle the heterogeneous data processing, model development, and visualization steps that constitute scientific discovery.
![Teaser figure](../imgs/ICLR20253495/cropped_page1_idx0.webp)

## Input / Output

Each task instance provides a concise natural-language instruction, a dataset directory structure with content preview (to support agents without file navigation), and optional expert-provided knowledge (scientific term definitions, formulas, tool usage examples). The agent must produce a single self-contained Python source file that can be executed independently by a Python interpreter. Evaluation is multi-faceted: binary Success Rate (task-specific criteria like ROC-AUC thresholds or figure quality scores), Valid Execution Rate, CodeBERTScore against a gold program, and API cost in USD, supplemented by rubric-based human ratings across five stages (data loading, processing, modeling/visualization, output formatting, saving).

## Method

ScienceAgentBench curates 102 tasks from 44 peer-reviewed publications across Bioinformatics, Computational Chemistry, Geographical Information Science, and Psychology & Cognitive Neuroscience, with each task validated by nine subject matter experts through a structured questionnaire. Two data contamination and shortcut-mitigation strategies are applied: randomly removing five test-set points per dataset and replacing test labels with dummy values (e.g., -1) for model-development tasks, so that memorized code or label-reading shortcuts fail. The evaluation pipeline dynamically constructs a conda environment per program using pipreqs and pip-tools, then executes the program and checks task-specific success criteria implemented as executable scripts. Five LLMs (Llama-3.1-70B/405B, Mistral-Large-2, GPT-4o, Claude-3.5-Sonnet) are evaluated under three agent frameworks—direct prompting, OpenHands CodeAct, and a modified self-debug loop (no self-reflection, early exit on repeated programs, no pre-loaded packages)—with three independent runs per task and best-run selection by SR > VER > CBS > Cost.

## Results

On ScienceAgentBench (102 tasks across 4 disciplines), the best-performing agent—Claude-3.5-Sonnet with Self-Debug and expert-provided knowledge—achieves only 34.3% Success Rate (SR) and 87.1% CodeBERTScore (CBS), with 86.3% Valid Execution Rate (VER) at a cost of $0.061 per task. Without expert knowledge, the same agent reaches 32.4% SR and 92.2% VER at $0.057 per task. Self-Debug nearly doubles Claude-3.5-Sonnet's SR over Direct Prompting (16.7% → 32.4%, 1.94×) while costing 17× less than OpenHands CodeAct ($0.057 vs. $0.958). Even the strongest configuration solves fewer than one-third of tasks, underscoring that current language agents cannot yet automate data-driven scientific discovery.

## Baselines & Comparisons

The paper compares three agent frameworks—Direct Prompting, OpenHands CodeAct, and Self-Debug—across five LLMs. Self-Debug outperforms OpenHands CodeAct in SR for 4 of 5 LLMs when expert knowledge is provided; GPT-4o is the sole exception, where OpenHands achieves 27.5% SR versus Self-Debug's 23.5%, likely because GPT-4o uniquely leverages OpenHands' web browser to search for additional context. Without expert knowledge, Self-Debug also leads for all five LLMs (e.g., Claude-3.5-Sonnet: 32.4% vs. 21.6% SR). The cost gap is dramatic: Claude-3.5-Sonnet with Self-Debug costs $0.057 per task versus $0.958 for OpenHands CodeAct (17× cheaper) while solving 10.8% more tasks. Compared to Direct Prompting, Self-Debug nearly doubles Claude-3.5-Sonnet's SR (16.7% → 32.4%) and more than doubles its VER (51.0% → 92.2%), confirming that execution feedback is essential for complex scientific code generation. Expert-provided knowledge consistently improves SR and CBS but sometimes reduces VER, as agents adopt unfamiliar tools specified in the knowledge and introduce hallucinated API calls.

## Relation to Prior Work

This paper builds on the self-debug framework (Chen et al., ICLR 2024) and the OpenHands CodeAct agent (Wang et al., 2024c) as evaluation frameworks, re-implementing self-debug with modifications (removing self-reflection, adding early exits, using pipreqs for environment setup). Conceptually, it departs from DiscoveryBench-Real (Majumder et al., 2024b), the closest prior benchmark, by requiring agents to produce executable, self-contained Python files rather than abstract natural-language steps, and from SciCode/BLADE by demanding full file-level generation across heterogeneous scientific data rather than function-level completion. It also explicitly positions itself against end-to-end automation claims (e.g., The AI Scientist, Lu et al., 2024), arguing that task-level rigorous evaluation must precede such bold claims.

## Why It Matters / Open Questions

The benchmark provides the field with a rigorous, expert-validated testbed (102 tasks, 4 disciplines, 44 publications) for measuring progress on scientific code generation, filling a gap where prior benchmarks relied on secondary sources or synthetic tasks. The finding that the best agent solves only ~34% of tasks even with expert knowledge serves as a concrete reality check against narratives of near-complete scientific automation. Open questions include whether agents can handle longer/complex programs (>58 lines), whether discipline-specific tool usage (Geopandas, Biopsykit) can be improved, and whether rubric-based evaluation can be automated via LLM judges. Limitations include Python-only scope, four disciplines, and a 10-minute execution cap that excludes large-scale data tasks.
