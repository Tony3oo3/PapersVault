## Problem

Prior LLM-based web agents rely heavily on handcrafted strategies—prompting templates, multi-agent role-playing, MCTS search, or in-context examples—that struggle to generalize across diverse websites. The paper identifies an underexplored source of failure: the misalignment between the web agent's observation and action representations (accessibility trees, embodied navigation commands) and the predominantly static, text-centric data on which LLMs are pre-trained. The central question is whether a strong web agent can be built by optimizing only the observation-to-prompt and action-from-output mappings, without adding auxiliary modules or complex control logic.

## Input / Output

The agent consumes a condensed accessibility-tree representation of the current page (with redundant structural tokens removed and tables/lists converted to Markdown), the task objective, and a selectively replayed interaction history that retains only DOM subtrees around agent-identified 'pivotal nodes' and is scoped to the current active plan in the planning tree. At each step the LLM emits a single action from a reduced vocabulary (click, type, go_back, note, stop, go_home, branch, prune) along with pivotal-node IDs for future memory filtering; the trajectory terminates when the agent issues a stop action carrying the final answer. No screenshots, no in-context examples, and no additional LLM calls are used.

## Method

AGENTOCCAM formulates the web agent as a POMDP solved by a single LLM policy π_LLM, with all modifications confined to rule-based observation mapping f and action mapping g. Three alignment components are applied: (1) action-space reduction removes embodiment-heavy or low-utility actions (hover, press, scroll, tab operations, go_forward, goto) and adds workflow commands (note, stop, go_home) plus two planning actions—branch and prune—that let the LLM autonomously grow and edit a planning tree in the same prompt position as navigation commands; (2) observation condensation merges function-descriptive elements with their interactive counterparts and converts tabular/list blocks to Markdown to shorten single-page context; (3) selective history replay uses agent-designated pivotal nodes (with their DOM ancestors, siblings, and descendants) to filter per-page content, and uses the planning tree to discard steps belonging to pruned or completed sub-plans, so the agent attends only to information relevant to the current active plan. The entire pipeline requires no in-context examples, no online search or sampling, no evaluator or reflector modules, and no task-specific prompting, yet achieves 43.1% success on WebArena (GPT-4-Turbo), outperforming the prior SOTA by 9.8 absolute points.

## Results

On WebArena (812 tasks across 5 websites), AGENTOCCAM with GPT-4-Turbo achieves a 43.1% success rate, setting a new state-of-the-art. This represents a 9.8-point (+29.4%) absolute improvement over the previous best method SteP (33.3%) and a 5.9-point (+15.8%) improvement over the concurrent WebPilot (37.2%). On the WebVoyager definite-answer subset (129 real-world web tasks), AGENTOCCAM achieves 54.30% success rate, exceeding Agent-E (51.90%) by 2.4 points (+4.6%).

## Baselines & Comparisons

AGENTOCCAM outperforms all five baselines on their respective benchmarks. On WebArena, it surpasses the vanilla WebArena CoT agent (16.5%) by 26.6 points, SteP with its 14 handcrafted atomic strategies (33.3%) by 9.8 points, AWM's workflow-memory approach (35.5%) by 7.6 points, and WebPilot's multi-agent MCTS system (37.2%) by 5.9 points. Notably, AGENTOCCAM achieves these gains without in-context examples, online search, additional LLM calls, or task-specific prompting templates. On WebVoyager's 129-task definite-answer subset spanning 13 real-world websites, AGENTOCCAM (54.30%) edges out Agent-E (51.90%) by 2.4 points, with particular strengths on Google Search (81.25% vs 62.50%) and Cambridge Dictionary (88.89% vs 55.56%), while Agent-E leads on Wolfram Alpha (73.53% vs 61.76%) due to its dedicated planner module. The paper also shows that combining AGENTOCCAM with an LLM-as-a-judge action-selection step further improves the overall success rate to 45.7%, confirming the orthogonality of the observation/action space alignment to other agent strategies.

## Relation to Prior Work

This paper departs from the dominant line of work on LLM-based web agents that focuses on designing complex agent policies—handcrafted prompting strategies (SteP, AutoGuide), multi-agent architectures with planners/reflectors (Agent-E, WebPilot), or search-based exploration (LM-Tree Search, AutoRefine). Rather than building on any specific prior architecture, AGENTOCCAM reframes the core problem as one of observation and action space alignment: the web interaction representations (accessibility trees, scroll/hover/click actions) are poorly matched to the text-centric data on which LLMs were trained. The paper carves new ground by showing that rule-based transformations of the I/O space—simplifying actions, condensing page observations, and adding lightweight planning-tree actions—can substitute for the elaborate policy machinery used in prior work.

## Why It Matters / Open Questions

The finding that a single-LLM agent with no search, no in-context examples, and no auxiliary modules can outperform multi-agent MCTS systems by a meaningful margin challenges the field's assumption that web agent performance requires increasingly complex orchestration. The observation/action alignment principle is generalizable beyond web tasks to any embodied or symbolic agent setting where the I/O format diverges from the LLM's training distribution. Key limitations include the text-only scope (no visual modality), the extensive evaluator modifications in Appendix E that raise comparability questions, and the still-weak performance on multi-site tasks (14.6%). Open questions include whether the planning-tree mechanism scales to very long-horizon tasks and whether the approach transfers to multimodal web agents where screenshot-based observations dominate.
