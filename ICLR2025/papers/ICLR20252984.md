## Problem

State-of-the-art LLMs are trained on trillions of tokens, yet the largest open pretraining datasets for Scandinavian languages (Swedish, Danish, Norwegian, Icelandic) contain only 10–100 billion tokens, roughly an order of magnitude too small. Existing curation pipelines also rely on dozens of hand-crafted extraction rules and quality filters that are difficult to adapt to lower-resource languages, creating a bottleneck for building competitive Scandinavian LLMs.
![Teaser figure](../imgs/ICLR20252984/cropped_page2_idx0.webp)

## Input / Output

The pipeline consumes Common Crawl WET archives solely for content selection (via CCNet line-deduplication and fastText language scoring) and WARC archives for actual HTML retrieval, an unusual split that lets it discard noisy WET text while preserving full page structure. Output is Markdown-formatted primary content that retains headers, tables, bullet lists, and other structural markup rather than plain text, ultimately yielding 1.01 trillion tokens across 1.2 billion documents (3.6 TB raw UTF-8) spanning 98 Common Crawl snapshots from 2013-20 to 2024-26.

## Method

The central contribution is a model-based line extractor that replaces rule-based HTML-to-text tools like Trafilatura. HTML is first converted to Markdown via Pandoc, then a Longformer encoder (16k context, local attention window of 256, no global attention) is fine-tuned on 1,280 annotated webpages to classify each line as extract or discard: newlines are replaced with [SEP] tokens, and a linear projection plus sigmoid on each [SEP] hidden state yields a per-line probability trained with binary cross-entropy. This single model implicitly handles most quality filtering (spam, ads, navigation), reducing the downstream filter set to just four simple heuristics (content length, alphanumeric ratio, heading density, unigram entropy). The full pipeline also applies MinHashLSH near-duplicate removal within snapshots and regex-based PII stripping, and the authors show it extracts ~60% more high-quality tokens than the FineWeb pipeline on identical input while matching downstream LLM performance on a new Swedish cloze benchmark (HP-MEK).

## Results

On the HP-MEK cloze-style benchmark (460 Swedish sentence-completion examples), M_SW (1.82B Llama trained on SWEb) closely matches M_FW (trained on FineWeb) throughout training, indicating the two datasets are on-par in quality. The SWEb pipeline extracts +62% more documents (32.3M vs. 19.2M) and +60% more tokens (25.2B vs. 15.8B) than FineWeb on the same Common Crawl input. The full SWEb dataset comprises 1.01 trillion tokens across 1.2 billion documents (3.6 TB), making it an order of magnitude larger than prior open Scandinavian datasets. The model-based line extractor achieves 87% F1 on validation with only 1,280 annotated training documents.

## Baselines & Comparisons

The paper's sole direct comparison is against the FineWeb pipeline (Penedo et al., 2024), which uses Trafilatura for extraction and 30+ quality filters. On dataset yield, SWEb wins decisively: it extracts 62% more documents and 60% more tokens from the same input, with most FineWeb documents being a subset of SWEb (Figure 6 Venn diagram). On downstream model quality (HP-MEK), the two are essentially tied — M_SW and M_FW track each other closely throughout training, suggesting the model-based extractor with only 1,380 annotated examples matches Trafilatura's rule-based extraction. On perplexity, M_SW achieves lower perplexity on its own SWEb test set than M_FW on FineWeb, and M_SW also generalizes better to the FineWeb test set than vice versa, which the authors attribute to Markdown formatting tokens being easier to predict. FineWeb extracts slightly more tokens per document on average (820.3 vs. 779.7), despite SWEb retaining additional Markdown markup.

## Relation to Prior Work

This paper extends the established pipeline for curating LLM pretraining data from Common Crawl (CCNet, C4, RefinedWeb, FineWeb) by replacing the rule-based HTML-to-text extraction step (Trafilatura in FineWeb) with a model-based line-level classifier built on Longformer. Rather than encoding extraction logic as 30+ heuristics and quality filters, the authors train a single transformer on 1,380 annotated Markdown documents to perform both extraction and implicit quality filtering, reducing the downstream filtering to four simple thresholds. The content selection stage reuses CCNet's fastText-based language detection, and the overall pipeline structure (selection → extraction → filtering → deduplication) follows prior work, but the core extraction mechanism is a deliberate departure from the rule-based paradigm.

## Why It Matters / Open Questions

SWEb is an order of magnitude larger than prior open Scandinavian datasets (1.01T vs. ~100B tokens for mC4), making it a critical resource for training competitive Scandinavian LLMs. The demonstration that a small model-based extractor trained on under 1,400 examples can match the quality of the widely-used Trafilatura while yielding ~60% more tokens suggests a more scalable and adaptable path for low-resource language data curation. Open questions include whether the Markdown formatting genuinely improves downstream model performance (the paper acknowledges this confound), whether the approach generalizes beyond Scandinavian languages, and how the substantial GPU cost of model-based extraction (20k MI250X hours) compares to rule-based alternatives at scale. The HP-MEK benchmark, while useful, is limited to Swedish and a single cloze-style task, leaving broader evaluation of the dataset's quality open.
