## Problem

Existing AI agent frameworks lack a unified, open-source platform that simultaneously provides sandboxed code execution, full web browsing, multi-agent collaboration, a standardized extensible tool library, and systematic evaluation across diverse task categories. While individual frameworks address subsets of these needs (e.g., SWE-Agent for code editing, BrowserGym for web interaction), no single platform integrates all capabilities with a flexible event-stream architecture that allows community-driven agent development and safe execution.

## Input / Output

The agent receives a natural language task instruction and operates within a Docker-sandboxed Linux environment where a configurable workspace directory (containing code repositories, databases, or other files) is mounted. Actions are structured as programming-language primitives—Python cells, bash commands, or BrowserGym DSL commands—rather than fixed tool calls, and the agent can also emit natural language messages to the user or delegate subtasks to specialized sub-agents. Observations returned to the agent include execution stdout/stderr, browser state (HTML, DOM, accessibility tree, screenshots), and file contents, all flowing through a chronological event stream that constitutes the agent's full state.

## Method

OpenHands uses an event-stream architecture where an agent's step function consumes the full history of actions and observations to produce the next action, which is executed by a REST API server inside a Docker sandbox containing a bash shell, an IPython Jupyter server, and a Playwright-driven Chromium browser. The key design choice, inspired by CodeAct, is to use programming languages as the action space (IPythonRunCellAction, CmdRunAction, BrowserInteractiveAction) rather than a fixed set of predefined tools, giving agents the flexibility to compose arbitrary operations and even create new tools on the fly. An AgentSkills library of Python utility functions (file editing, PDF/image parsing, scrolling) is auto-imported into the IPython environment, with inclusion criteria limited to capabilities not readily achievable by the LLM writing raw code. Multi-agent coordination is handled through a special AgentDelegateAction that lets a generalist agent (e.g., CodeActAgent) offload subtasks to specialized agents (e.g., BrowsingAgent), and the runtime supports arbitrary user-provided Docker images via a build mechanism that injects the action execution API into any base image.

## Results

The CodeActAgent v1.8 (OpenHands' default generalist agent) achieves 26.0% on SWE-Bench Lite (with claude-3.5-sonnet), 15.3% on WebArena, and 53.1% on GPQA (with gpt-4o), demonstrating competitive performance across all three major task categories without any task-specific prompt modifications. On HumanEvalFix, the agent fixes 79.3% of bugs (0-shot, gpt-4o), nearly doubling the 48.6% of StarCoder2-15B. The GPTSwarm agent achieves 32.1% on GAIA (gpt-4o), substantially outperforming AutoGPT's 13.2%. Average per-task costs range from $0.01 (gpt-4o-mini on WebArena) to $1.72 (gpt-4o on SWE-Bench Lite).

## Baselines & Comparisons

On SWE-Bench Lite, OpenHands' CodeActAgent (26.0% with claude-3.5-sonnet) is competitive with specialized SWE agents like Aider (26.3%) and Moatless (26.7%), but slightly trails Agentless (27.3%); it substantially outperforms SWE-Agent (18.0%) and AutoCodeRover (19.0%). On WebArena, the BrowsingAgent (15.5% with claude-3.5-sonnet) beats the original WebArena Agent (14.4% with gpt-4-turbo) but falls short of trained/specialized approaches like AutoWebGLM (18.2%) and Auto Eval & Refine (20.2%). On GPQA, CodeActAgent with gpt-4o (53.1%) significantly outperforms few-shot CoT with GPT-4 (38.8%), a 14.3-point gain attributable to tool use and code execution. On GAIA, GPTSwarm (32.1%) more than doubles AutoGPT's score (13.2%). On HumanEvalFix, OpenHands (79.3%, 0-shot) approaches SWE-Agent's 87.7% (1-shot) while far exceeding non-agentic prompting baselines (48.6% for StarCoder2-15B). The key finding is that a single generalist agent, without task-specific prompt engineering, achieves competitive results across all three domains simultaneously, whereas baselines are typically optimized for one category.

## Relation to Prior Work

OpenHands synthesizes and extends several recent agent paradigms into a unified open-source platform: the CodeAct executable-code action space (Wang et al., 2024a) as the core interaction primitive, SWE-Agent's Agent-Computer Interface concept (Yang et al., 2024) motivating the AgentSkills library, BrowserGym's structured web-browsing DSL (Drouin et al., 2024) for browser actions, and GPTSwarm's optimizable graph architecture (Zhuge et al., 2024) for multi-agent composition. Unlike prior frameworks (AutoGPT, LangChain, MetaGPT, AutoGen) that each cover a subset of capabilities, OpenHands is positioned as the first to simultaneously provide a sandboxed runtime, standardized tool library, built-in browser, multi-agent delegation, human-AI collaboration, an agent hub, and a 15-benchmark evaluation suite. The key architectural departure is the event-stream-based state management that decouples agents from runtimes and enables arbitrary Docker-image-based environments.

## Why It Matters / Open Questions

The platform lowers the barrier to agent research by providing a single, extensible codebase where new agents, tools, and benchmarks can be contributed and evaluated under a common protocol, which is critical as the field fragments across dozens of incompatible frameworks. The finding that a single unmodified CodeActAgent achieves competitive (though not SOTA) performance across software engineering, web browsing, and miscellaneous assistance tasks supports the viability of truly generalist agents over domain-specific ones. Open questions highlighted by the authors include principled multi-modality integration, improved long-file editing, stronger inference-time techniques, and automatic workflow generation via graph-based optimization. Safety and reliability of deployed agents remain significant concerns that the sandboxed architecture addresses only partially.
