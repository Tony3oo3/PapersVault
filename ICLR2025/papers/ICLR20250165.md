## Problem

While LLMs have demonstrated strong capabilities in code generation and statistical analysis, no comprehensive benchmark exists to evaluate their ability to perform the full data-driven discovery pipeline—searching for and verifying hypotheses from raw datasets. Prior benchmarks target narrow sub-tasks like statistical reasoning or AutoML, but do not capture the multi-step process requiring scientific semantic reasoning, domain-specific tool selection, and open-ended workflow design that characterizes real discovery.
![Teaser figure](../imgs/ICLR20250165/cropped_page1_idx0.webp)

## Input / Output

Each task provides one or more tabular datasets with column-level metadata (descriptions, data types, domain knowledge) and a natural language discovery goal that masks exactly one dimension (context, variable, or relationship) of the target hypothesis. The agent must produce a natural language hypothesis specifying all three dimensions plus an optional analysis workflow. Evaluation uses a structured Hypothesis Matching Score (HMS) that decomposes alignment into context equivalence, variable F1, and relationship accuracy, computed via GPT-4-based entailment judgments on each facet independently.

## Method

DISCOVERYBENCH formalizes data-driven discovery as finding a hypothesis h = ψ(c, v, r) supported by dataset D, where c, v, r denote context, variables, and relationship. The benchmark comprises DB-REAL (264 tasks extracted from 20+ published papers across six domains, with gold Python workflows manually replicated) and DB-SYNTH (903 synthetic tasks across 48 domains generated via LLM-constructed hypothesis semantic trees that encode variable dependencies). They evaluate five agent frameworks—CodeGen, ReAct, DataVoyager, Reflexion (Oracle), and NoDataGuess—powered by GPT-4o, GPT-4p, and Llama-3-70B, finding peak performance of only 25% HMS, with significant performance drops for longer workflows, domain-specific statistical methods, and tasks requiring multi-dataset integration.

## Results

On DISCOVERYBENCH, the best system (Reflexion with Oracle feedback + GPT-4o) achieves only 24.6% Hypothesis Matching Score (HMS) on DB-REAL and 15.7% on DB-SYNTH, underscoring the extreme difficulty of autonomous data-driven discovery. On DB-REAL, ReAct (24.4%) and DataVoyager (20.8%) with GPT-4o perform comparably to the simpler CodeGen baseline (20.9%), while Reflexion (Oracle) provides the largest gain over CodeGen (+3.7 points). On DB-SYNTH, Llama-3-70B with Reflexion (Oracle) surprisingly achieves the highest score (23.2%), outperforming GPT-4o (15.7%) and GPT-4p (12.9%), suggesting that the synthetic split's different workflow composition favors different model strengths.

## Baselines & Comparisons

The paper benchmarks three LLM-based reasoning frameworks—ReAct, DataVoyager, and Reflexion (Oracle)—alongside a simple CodeGen baseline and a NoDataGuess memorization probe, each powered by GPT-4o, GPT-4p, or Llama-3-70B. On DB-REAL, ReAct (24.4% with GPT-4o) marginally outperforms CodeGen (20.9%), while DataVoyager (20.8%) essentially ties CodeGen, indicating that multi-component planning and self-critique do not meaningfully help over single-shot code generation. Reflexion (Oracle), which receives the true HMS score as feedback between trials, achieves the best DB-REAL score of 24.6% with GPT-4o, a +3.7 point improvement over CodeGen, confirming that iterative self-correction with external signal is the most effective strategy. On DB-SYNTH, the ranking shifts: Llama-3-70B with Reflexion (Oracle) reaches 23.2%, far exceeding GPT-4o (15.7%) and GPT-4p (12.9%), while ReAct and DataVoyager underperform CodeGen for GPT-4o, suggesting the synthetic split's emphasis on nonlinear regression and cluster analysis exposes weaknesses in the more complex agent architectures. Overall, no agent exceeds 25% HMS, and the NoDataGuess results (0.0% for GPT-4o vs. 11.5% for Llama-3) reveal that GPT-4o avoids hallucinating published findings while Llama-3 partially memorizes them.

## Relation to Prior Work

DISCOVERYBENCH carves new ground by formalizing the full multi-step data-driven discovery pipeline—hypothesis search, semantic reasoning, and verification—as a single evaluable task, departing from prior data-analysis benchmarks (QRData, DSBench, BLADE) that target only statistical analysis or closed-form verification. It extends the DataVoyager framework (Majumder et al., 2024) from a system demonstration to a rigorous benchmark setting, and adopts the hypothesis decomposition (context, variables, relationship) inspired by Thompson & Skau (2023) to enable structured, facet-based evaluation. Unlike AutoML or statistical-reasoning datasets, DISCOVERYBENCH requires open-ended hypothesis generation grounded in domain-specific scientific workflows extracted from published papers.

## Why It Matters / Open Questions

The benchmark establishes a concrete, reproducible yardstick for autonomous scientific discovery, revealing that even the strongest LLM-agent combinations (GPT-4o + Reflexion with oracle feedback) plateau at only 25% HMS—a stark signal that current systems lack the domain reasoning, tool orchestration, and multi-step planning needed for realistic discovery. Open questions include how to incorporate domain-specific tools and knowledge more effectively, how to handle multi-modal and massive datasets, and whether the structured (c, v, r) formalism generalizes to discovery tasks beyond tabular data. The finding that sophisticated reasoning frameworks (ReAct, DataVoyager) offer no advantage over simple code generation suggests the bottleneck is not reasoning strategy but fundamental gaps in scientific knowledge and workflow execution.
