## Problem

Existing coding benchmarks like SWE-bench and HumanEval evaluate agents on tasks within the skill set of experienced software engineers, making them likely to be fully solvable as LLMs improve. The paper identifies a gap for benchmarks that go beyond expert human ability while remaining fully specifiable and verifiable, specifically targeting the generation of entire software libraries with complex inter-file dependencies, long-form specifications, and the need for multi-stage iterative refinement.
![Teaser figure](../imgs/ICLR20250435/cropped_page1_idx0.webp)

## Input / Output

The agent receives a PDF specification document (ranging from 10K to 300K tokens, including text and figures), a starter repository where all public function bodies are replaced with `pass` and all private functions are removed entirely, and a suite of pytest unit tests. The agent produces a complete Python library implementation, evaluated solely by unit test pass rate. Critically, the environment is interactive: the agent can run unit tests, receive static analysis (ruff linting and type checking), and obtain coverage analysis in isolated Docker containers per library, enabling iterative refinement over multiple rounds.

## Method

COMMIT0 is a benchmark of 54 Python libraries (16 in the lite split) spanning ML, networking, databases, and visualization, constructed by systematically removing public function bodies and private functions from real repositories via AST manipulation. The paper also introduces SDE-I, a three-stage prototype agent: (1) draft initial implementations by performing a topological sort on the module import DAG and generating one module at a time with its dependencies in context; (2) refine via static analysis feedback (ruff linting), iterating until errors are resolved; (3) refine via unit test feedback, executing tests module-by-module to stay within context limits and iteratively revising code based on error messages. The interactive environment provides Docker-isolated test execution, standardized linting, and pytest-cov coverage analysis, all designed to give the agent actionable multi-stage feedback that one-shot generation cannot exploit.

## Results

On COMMIT0 lite, the best SDE-I configuration (Claude 3.5 Sonnet, Stage 3) achieves a 29.30% unit test pass rate, up from 17.80% at Stage 1 (initial draft) and 18.79% at Stage 2 (static analysis). On the harder COMMIT0 all split, Claude 3.5 Sonnet at Stage 1 reaches 6.12% pass rate, while GPT-4o-mini and DeepSeek-V2.5 achieve 2.87% and 4.93% respectively at Stage 3. The state-of-the-art OPENHANDS agent achieves 42.95% on COMMIT0 lite and 15.25% on COMMIT0 all, but no agent can fully reproduce any library.

## Baselines & Comparisons

The primary external comparison is against OPENHANDS, the best-performing agent on SWE-bench. With deep integration (sharing unit test IDs, static analysis commands, and test commands), OPENHANDS passes 42.95% of unit tests on COMMIT0 lite, a 13.65 percentage-point improvement over SDE-I's best (29.30%), and 15.25% on COMMIT0 all, a 9 percentage-point improvement over SDE-I's 6.12%. The authors attribute OPENHANDS's advantage to superior debugging capabilities: unlike SDE-I, which repetitively generates the same fix for a bug, OPENHANDS explores different solutions. Within SDE-I, Claude 3.5 Sonnet consistently outperforms all other evaluated LLMs (GPT-4o-mini, o1-preview, DeepSeek-V2.5, Llama-3.1 variants, Codestral) across all three stages, and iterative unit test feedback (Stage 3) reliably improves pass rates over static analysis alone (Stage 2) for all capable models.

## Relation to Prior Work

COMMIT0 extends the self-correction paradigm of Madaan et al. (2023) and Shinn et al. (2023) from single-function refinement to full repository-level generation, where an agent must iteratively process unit test errors, static analysis feedback, and coverage signals across hundreds of interdependent functions. It deliberately departs from SWE-bench (Jimenez et al., 2024), which evaluates patch-level fixes to existing code, and from program synthesis benchmarks (HumanEval, MBPP, BigCodeBench) that target isolated functions, by requiring generation of an entire library from an empty scaffold with long-form specifications. The SDE-I agent builds on the Aider coding framework but introduces a three-stage pipeline (draft → static analysis → unit test refinement) with topological-sort-based module ordering, positioning it as a prototype rather than a state-of-the-art system.

## Why It Matters / Open Questions

COMMIT0 provides a concrete, verifiable benchmark that sits beyond both current model capability and typical expert software engineering scope, offering a long-horizon progress metric for code generation agents. The finding that no evaluated agent can fully reproduce any of the 54 libraries, even with interactive feedback, establishes a clear ceiling and motivates new agent architectures. Open questions include how to effectively filter and retrieve relevant specification content (raw context inclusion hurts performance), how to handle dependency ordering without propagating errors from incorrect prior modules, and whether test-time scaling will eventually close the gap. Limitations include Python-only scope, reliance on unit tests as sole correctness signal, and the assumption of complete specifications.
