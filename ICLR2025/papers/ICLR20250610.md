## Problem

Low-level instruction-following controllers in Minecraft, particularly Steve-1, rely on Transformer-XL with only 128 hidden states of short-term memory (a few seconds at 20Hz), causing agents to forget previously visited locations and task-relevant resources. This forces the agent to revert to inefficient random exploration for every new task, making it a critical bottleneck in LLM-augmented hierarchical systems. The paper argues that existing memory systems target high-level planners (storing skill plans) rather than equipping the low-level controller with the episodic memory needed to recall where and when it encountered relevant resources.

## Input / Output

At each 20Hz timestep, the agent receives a 160×256×3 first-person RGB frame, a 5D positional vector (x, y, z, yaw, pitch) relative to spawn, and a text instruction (e.g., 'obtain water bucket'). The output is a low-level keyboard-and-mouse action in the VPT action space. The memory module encodes 16-frame video windows into MineCLIP embeddings for storage and retrieval, while the navigation policy consumes a 128-frame observation window plus a 2D goal coordinate. No privileged observations (LiDAR, voxel data) are used.

## Method

MrSteve introduces Place Event Memory (PEM), a hierarchical episodic memory that organizes experience frames by spatial location (Place Clusters defined by fixed-size 2D ground areas and yaw ranges) and visual distinctness (Event Clusters formed via DP-Means on MineCLIP video embeddings within each place). This captures what (event), where (place), and when (timestamp) information, enabling efficient hierarchical retrieval: first selecting top-k event clusters by task-alignment score, then filtering individual frames by a threshold. The Solver Module uses a Mode Selector to switch between Explore mode (Count-Based visitation-grid goal selection + VPT-Nav, a VPT policy fine-tuned with LoRA and PPO for goal-conditioned navigation) and Execute mode (navigate to the recalled location, then hand off to Steve-1 for instruction following). When memory capacity is exceeded, the oldest frame is removed from the largest event cluster, preserving both spatial diversity and visual novelty.

## Results

On the 100×100 block exploration task (6K steps), MrSteve's Count-Based + VPT-Nav exploration achieves 84.42% Map Coverage and 0.38 average Revisit Count, substantially outperforming Steve-1 (50.77%, 2.68) and Plan4MC's RNN+DQN (16.36%, 6.2). In the ABA-Sparse sequential task (12K steps), MrSteve achieves higher success rates than Steve-1 and solves the repeated Task A' significantly faster by recalling the resource location from memory, while Steve-1 takes comparable or longer time for both A and A'. In the 500K-step Long-Instruction task on a 200×200 map, MrSteve completes over 80 tasks, compared to fewer than 50 for all baselines, and solves ~70 tasks in the Long-Navigation task versus fewer than 20 for Place Memory and fewer than 10 for FIFO/Steve-1.

## Baselines & Comparisons

MrSteve decisively outperforms Steve-1 (Lifshitz et al., 2024) across all experiments. In exploration, MrSteve achieves 84.42% Map Coverage versus Steve-1's 50.77%, and reduces Revisit Count from 2.68 to 0.38, demonstrating that the Count-Based goal selector and VPT-Nav eliminate the redundant revisits caused by Steve-1's lack of memory. In ABA-Sparse tasks, MrSteve achieves higher success rates and, critically, solves the second occurrence of Task A (A') much faster than the first by recalling the resource location, whereas Steve-1 takes similar or even longer for A' since it must re-explore from scratch. Against Plan4MC (Yuan et al., 2023), MrSteve's Count-Based + VPT-Nav combination dominates both the RNN+DQN (16.36% coverage) and the cross-combinations (Count+DQN: 31.83%, RNN+VPT-Nav: 29.82%), showing that both the high-level count-based strategy and the VPT-Nav low-level navigator are necessary for effective exploration in complex terrain. In memory-constrained tasks (2K capacity), MrSteve with Place Event Memory achieves high success rates in all three Memory Tasks, while FIFO Memory fails on Find Water (~60%), Place Memory fails on Find Zombies' Death Spot (~60%), and Event Memory fails on Find First-Visited House (~50%), confirming that the hierarchical place+event structure is essential under limited capacity.

## Relation to Prior Work

This paper extends the LLM-augmented hierarchical agent paradigm in Minecraft by targeting the low-level controller rather than the high-level planner. It builds directly on Steve-1 (Lifshitz et al., 2024) as the instruction-following policy, VPT (Baker et al., 2022) as the base for the goal-conditioned navigator (VPT-Nav), and Place Memory (Cho et al., 2024) as the spatial clustering backbone. The key conceptual departure is from prior memory-augmented agents (Voyager, GITM, MP5, JARVIS-1, Optimus-1), which store high-level plans and skill codes for the planner; MrSteve instead introduces Place Event Memory (PEM) as an episodic memory for the low-level controller, combining spatial place clusters with DP-Means event clustering over MineCLIP video embeddings to capture what-where-when information.

## Why It Matters / Open Questions

The paper identifies a concrete and underappreciated bottleneck in hierarchical embodied agents: the low-level controller's lack of episodic memory causes repeated re-exploration and task failure in long-horizon settings. The clean ablation in Section 4.3, where each memory variant (FIFO, Place, Event) fails on a distinct task in a predictable way, provides a principled justification for the hierarchical PEM design. Key limitations include surface-level exploration only (no underground mining), reliance on exact position data, and the inability of the high-level LLM planner to query PEM directly. Open questions include whether PEM can be exposed to the planner for more informed subgoal generation, and whether the approach transfers to noisy-position robotics settings.
