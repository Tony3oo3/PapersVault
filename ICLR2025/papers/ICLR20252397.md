## Problem

Existing code generation benchmarks like HumanEval and MBPP focus on short, self-contained algorithmic tasks that have been saturated by recent LLMs, failing to capture the two hallmarks of real-world programming: invoking diverse function calls from multiple libraries as tools, and following complex instructions that require compositional reasoning. This paper asks whether LLMs can solve challenging, practical programming tasks that demand multi-tool use across domains and precise adherence to detailed specifications.

## Input / Output

BigCodeBench-Complete provides structured PEP-257 docstrings (averaging 1,112 characters of code context) as prompts, while BigCodeBench-Instruct strips these down to condensed natural-language instructions with only essential information, removing interactive examples and redundant parameter details. The model must produce a complete Python function implementation, which is then executed against an average of 5.6 deterministic unittest-based test cases (99% branch coverage) in a sandboxed environment with proper setup (e.g., database connections, directory creation). Evaluation reports unbiased Pass@K scores, with a 'calibrated' variant that adds missing import statements to account for model laziness in long-context repetition.

## Method

The benchmark is constructed through a three-stage human-LLM collaboration framework: (1) Data Synthesis, where GPT-4 generates programming tasks from ODEX seed examples with 2-shot in-context demonstrations, followed by obfuscation (dummy function names) and NL-Augmenter back-translation to mitigate self-preference bias; (2) Semi-automatic Refactoring and Test Generation, where 13 human annotators iteratively guide GPT-4's Code Interpreter to fix bugs, reformat docstrings to PEP-257, and write unittest-based test cases with complex setups; and (3) Human Curation, a three-fold process of manual examination, pre-evaluation with GPT-3.5-Turbo to identify ambiguities, and cross-checking by 7 additional annotators with final validation via GitHub Container Registry sandboxes. The resulting 1,140 tasks span 723 function calls from 139 libraries across 7 domains, with each task requiring at least two libraries. BigCodeBench-Instruct is derived by applying predefined parsing rules to transform verbose docstrings into shorter NL-oriented instructions, validated by 5 independent authors for alignment with ground-truth solutions.

## Results

Across 60 evaluated LLMs, the best-performing model (GPT-4o) achieves only 60% Pass@1 on BigCodeBench-Complete and less than 50% on BigCodeBench-Instruct, far below the 97% human performance. The mean calibrated Pass@1 for instruction-tuned LLMs is 40.7% versus 35.7% for their paired base models on BigCodeBench-Complete. LLMs degrade by an average of 8.5% Pass@1 when moving from the structured docstring prompts (Complete) to the condensed natural-language instructions (Instruct), while maintaining a strong rank correlation (Pearson's r = 0.982) between the two splits.

## Baselines & Comparisons

As a benchmark paper, BigCodeBench evaluates 60 LLMs rather than proposing a single method against baselines. The key comparison is between the best LLM (GPT-4o at 60% Pass@1 on Complete) and human annotators (97%), revealing a 37-point gap. Among LLMs, instruction-tuned models consistently outperform their base counterparts by ~5 percentage points in calibrated Pass@1 (40.7% vs. 35.7%), with the gap widening after calibration for missing imports. On the Instruct variant, all models drop by an average of 8.5%, with lower-scoring models degrading less due to their already-limited programming capability. In terms of benchmark difficulty, BigCodeBench substantially exceeds prior benchmarks in tool diversity (723 function calls from 139 libraries vs. 7–328 in HumanEval/DS-1000/ODEX), average solution length (10.0 lines vs. 1.9–6.8), and per-task library usage (2.8 libraries vs. 0.1–0.9), making it the most demanding function-level Python benchmark to date.

## Relation to Prior Work

BigCodeBench extends the execution-based code generation benchmarking line (HumanEval, MBPP, DS-1000, ODEX) by deliberately shifting from short, self-contained algorithmic tasks to multi-library, multi-function-call programming tasks with complex PEP-257-structured instructions. The construction methodology repurposes LLM-assisted data synthesis (seeding from ODEX/Stack Overflow), NL-Augmenter perturbation to mitigate self-preference bias, and a human-in-the-loop Code Interpreter workflow for semi-automatic refactoring and test generation. The BigCodeBench-Instruct variant extends the instruction-following dimension explored by HumanEvalPack by transforming structured docstrings into condensed natural-language instructions, while BigCodeBench-Hard adapts the MixEval subset-selection idea to the code domain. The paper positions itself as evaluating fundamental code generation capability (as opposed to agent frameworks like SWE-bench) while covering a broader tool-use and domain diversity than prior function-level benchmarks.

## Why It Matters / Open Questions

The 60% best-model score versus 97% human performance on BigCodeBench-Complete, and the further drop below 50% on the Instruct variant, provide concrete evidence that current LLMs lack reliable multi-tool compositional reasoning and robust instruction following for practical programming. The identification of 'model laziness'—where instruction-tuned models systematically omit essential import statements when repeating long prompts—highlights a practical failure mode previously unquantified in code benchmarks. Open questions remain around multilingualism (Python-only), API evolution and library deprecation, generalization to unseen tools, and whether interactive/agent-based settings (BigCodeBench-Interact) can close the remaining gap. The benchmark's Python-only scope and residual flaky-test issues limit its immediate applicability to polyglot or production-critical evaluation.
