## Problem

Existing long-context benchmarks evaluate efficient inference methods in single-request settings, overlooking the full KV cache lifecycle that dominates real-world deployment where prefix caching is standard in frameworks like vLLM and SGLang. This gap is critical because many efficient methods (e.g., query-conditioned KV compression, static sparse patterns) rely on the query to determine what to retain, and their behavior degrades sharply when the same cached context must serve multiple follow-up queries. The paper asks: how do long-context methods actually perform when KV cache is reused across multi-turn and multi-request scenarios?
![Teaser figure](../imgs/ICLR20252377/cropped_page0_idx0.webp)

## Input / Output

Each test example consists of a shared long context (ranging from ~22K to 1.5M tokens, averaging 227K) followed by 5+ follow-up queries that reuse the same cached KV state. The two shared-context modes differ in how reuse is structured: multi-turn mode keeps the context within a single session (ground-truth answers are fed back as context for subsequent turns), while multi-request mode simulates the context being cached across separate sessions without query access at encoding time. Outputs are scored per-turn using task-specific metrics (accuracy for retrieval, ROUGE for summarization, Pass@1 for code retrieval), and the benchmark reports both per-turn trajectories and aggregated averages across all 931 sessions and 4,853 queries.

## Method

The paper introduces a KV-cache-centric taxonomy that decomposes long-context inference into four stages—generation, compression, retrieval, and loading—and evaluates 13 methods across these stages on 8 LLMs (Llama-3.1-8B/70B, Qwen2.5-72B/32B, Llama-3-8B-262K, GLM-4-9B-1M, Codestral-Mamba, Jamba-1.5-Mini). SCBench itself comprises 12 tasks spanning four capabilities (string retrieval, semantic retrieval, global information, multi-tasking) designed with complexity analysis to stress-test incompressible inputs. The paper also proposes Tri-shape, a training-free sparse attention variant of A-shape that adds a dense bottom-query region to the triangular attention mask, improving first-turn instruction-following while preserving multi-request performance. Key empirical findings include: sub-O(n) memory methods (KV dropping, SSMs) collapse in multi-turn settings because critical KVs shift across queries; sparse encoding with O(n) memory and dense decoding approximates full attention across multiple requests; and dynamic sparsity (MInference) generalizes better without query access than static patterns (SnapKV, Tri-shape).

## Results

On Llama-3.1-8B, the full model achieves 48.7 (multi-turn) and 37.2 (multi-request) average scores across four capability categories. Among efficient methods, MInference (dynamic sparse attention, 1/32 budget) is the strongest, reaching 42.5/36.4, preserving ~87% of full-model performance. KV cache dropping methods (StreamingLLM, SnapKV, PyramidKV) collapse to 14.5–15.3 in multi-request mode, while O(n)-memory methods like KIVI (32.0/24.8) and RetrievalAttention (29.4/25.8) remain substantially more robust. The newly proposed Tri-shape improves over A-shape in multi-turn (30.3 vs. 27.1) but offers limited gains in multi-request (25.9 vs. 27.6).

## Baselines & Comparisons

MInference (dynamic sparse attention) is the clear winner among efficient methods, achieving 42.5/36.4 on Llama-3.1-8B (multi-turn/multi-request) versus 48.7/37.2 for the full model, outperforming all other sparse or compressed baselines by 10+ points in multi-request. The paper's proposed Tri-shape improves over A-shape in multi-turn (30.3 vs. 27.1) by adding dense bottom-row attention to preserve instruction-following, but A-shape slightly edges it in multi-request (27.6 vs. 25.9), suggesting the dense rows help first-turn more than cross-request generalization. KV cache dropping methods (StreamingLLM, SnapKV, PyramidKV) are the weakest in shared-context settings, scoring near 0 on string retrieval in multi-request mode (0.0–0.3) and averaging only 14.5–15.3, confirming that sub-O(n) memory is nearly infeasible when the same KV cache must serve multiple queries. KIVI (2-bit quantization, O(n) memory) and RetrievalAttention (KV loading) maintain O(n) storage and achieve 24.8 and 25.8 in multi-request respectively, substantially outperforming the dropping methods. SSM-based models (Mamba-Codestral at 7.4, Jamba-1.5-Mini at 48.0 multi-request) show highly inconsistent behavior: Jamba benefits from its attention layers for retrieval but suffers in semantic tasks, while pure Mamba fails almost entirely on string retrieval (0.0). CacheBlend (KV cache retrieval) nearly matches the full model (49.3/34.8), confirming that exact-match prefix caching preserves quality, but it provides no compression benefit.

## Relation to Prior Work

This paper extends the long-context evaluation literature (RULER, InfiniteBench, LongBench, NIAH) by introducing multi-turn and multi-request shared-context scenarios that reflect how KV cache is actually reused in production inference frameworks like vLLM and SGLang. It also organizes the fragmented landscape of long-context efficiency methods—sparse attention (A-shape, MInference), KV cache dropping (StreamingLLM, SnapKV), quantization (KIVI), retrieval (CacheBlend), and loading (Quest, RetrievalAttention)—under a unified KV-cache-centric taxonomy of four stages: generation, compression, retrieval, and loading. The novel Tri-shape sparse attention pattern extends A-shape from StreamingLLM by adding a dense bottom-query region, motivated by the observation that sparse encoding with dense decoding preserves multi-request performance.

## Why It Matters / Open Questions

The finding that sub-O(n) memory methods are 'almost infeasible' in multi-turn decoding is a critical practical warning: widely deployed KV cache compression techniques (StreamingLLM, SnapKV) that look strong on single-query benchmarks collapse on follow-up queries because critical KVs shift across requests. This reframes the design space for production long-context systems, pointing toward O(n) memory with sub-O(n²) prefilling (sparse encoding) or CPU-GPU offloading as more viable strategies. Open questions include whether dynamic sparse patterns can close the gap with full attention in multi-turn settings, and how to handle the attention distribution shift that degrades even O(n) methods during long-generation scenarios.
