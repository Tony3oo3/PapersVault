## Problem

LLMs frequently fail to generate effective search queries for multi-hop retrieval, especially on complex or indirect topics where no single document directly answers the question. Prior approaches to improving query generation rely on imitation-based methods (prompt optimization, rejection fine-tuning), but the paper identifies this as inherently a reinforcement learning problem where the LLM should learn from trial-and-error over diverse queries and their retrieval outcomes.

## Input / Output

The query-generating LLM π_r takes a user question and the accumulated document context from all previous hops as input, and produces a single search query per hop. The query is passed to a blackbox retriever (e.g., ColBERTv2 over Wikipedia abstracts) which returns a ranked set of documents; these documents are appended to the context for the next hop. After H hops, the union of all retrieved documents plus the original question is fed to a separate blackbox generator LLM π_g to produce the final grounded answer. Only π_r is trained; both the retriever and generator remain frozen.

## Method

LeReT frames multi-hop query generation as a preference-based RL problem. For exploration, it bootstraps P independently optimized few-shot chain-of-thought prompts via DSPy's BootstrapFewShotWithRandomSearch, then samples one query per prompt per question per hop, yielding diverse yet high-quality search queries. Each query's retrieval is scored with a reward (average precision against gold documents), and queries are paired into preferred/dispreferred pairs for the same question and context. The training pipeline first applies context distillation (SFT without the few-shot prompt) to make the model self-sufficient at test time, then optimizes with Identity Policy Optimization (IPO) to avoid DPO's overoptimization. An iterative variant (Iterative-LeReT) alternates between sampling with the current model and re-optimizing on new partitions, progressively improving exploration quality. The paper shows that prompt-driven diverse sampling at moderate temperature (0.7) substantially outperforms high-temperature sampling (2.0) for generating effective RL training data.

## Results

LeReT improves retrieval recall by 9–22% on HotpotQA and 27–29% on HoVer relative to unadapted base models (e.g., Llama 8b on HoVer 4-hop: 50.0 → 76.9 RE). On HotpotQA 2-hop, LeReT achieves 77.1 RE / 66.3 AP (Llama 8b) versus 54.7 / 41.9 for the base model. Downstream generator exact match improves by up to 17.3 points when using GPT-4 as the generator (33.4 → 50.7 EM), with stronger generators benefiting more from improved retrieval.

## Baselines & Comparisons

LeReT consistently outperforms all baselines across both datasets and both base models. Compared to Query2Doc (Wang et al., 2023), LeReT achieves substantially higher recall: on HoVer 4-hop with Llama 8b, LeReT reaches 76.9 RE versus Query2Doc's 57.1 RE (+19.8 points), and on HotpotQA 2-hop, 77.1 vs. 61.4 RE (+15.7 points). Against few-shot prompting (DSPy-optimized), LeReT gains 6.8–26.6 RE points depending on dataset and hop count, with the largest gap on HoVer 4-hop (76.9 vs. 57.3 for Llama 8b). The intermediate LeReT-CD (context distillation without IPO) already surpasses few-shot and Query2Doc, confirming that the RL optimization step (IPO) provides an additional 3–10 RE points on top of distillation alone. Notably, Query2Doc actually degrades performance below the base model on Gemma 9b / HotpotQA (43.5 vs. 52.2 RE at 1-hop), while LeReT improves it to 56.1.

## Relation to Prior Work

LeReT frames multi-hop search query generation as a preference-based RL problem, building directly on IPO (Azar et al., 2023) and DPO's implicit reward parameterization (Rafailov et al., 2024b) for the optimization step, and on context distillation (Snell et al., 2022) to bridge the gap between few-shot-prompted training and zero-shot test-time inference. It departs from prior work on LLM program optimization (Khattab et al., 2023; Opsahl-Ong et al., 2024; Soylu et al., 2024), which relies on rejection fine-tuning or prompt search over bootstrapped trajectories, by instead treating the problem as exploration-and-reward in an RL formalism. The key methodological departure is replacing the standard high-temperature sampling for exploration with prompt-driven diverse sampling via multiple independently optimized few-shot prompts (using DSPy), which the paper shows is critical for generating both diverse and high-quality exploration data. The iterative variant follows iterative-DPO (Xu et al., 2024), and the overall framework is positioned as complementary to prompt-based retrieval techniques like Query2Doc.

## Why It Matters / Open Questions

LeReT provides a simple, general, and drop-in framework for improving retrieval quality in RAG pipelines that works with arbitrary off-the-shelf retrievers (demonstrated with both ColBERTv2 and Azure AI Search) and arbitrary generator LLMs, making it broadly applicable to production grounding systems. The finding that stronger generators (GPT-4, Llama 3.1 70B) benefit disproportionately from improved retrieval (+17.3 EM for GPT-4) suggests that investing in retrieval quality becomes increasingly valuable as generator models improve. Key open questions include whether the framework can work with only indirect supervision (generator answer correctness) rather than direct retrieval annotations, and whether the approach extends to updating the retriever itself rather than just the query generator. The paper also notes that the greedy per-hop optimization assumption, while empirically validated (only 0.026% counterexamples), has not been formally proven.
