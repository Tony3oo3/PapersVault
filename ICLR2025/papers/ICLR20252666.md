## Problem

Existing LLM alignment methods (RLHF, DPO, etc.) optimize against static, general preference datasets, creating a 'last mile' gap where real user preferences—personalized, culturally dependent, and time-varying—frequently diverge from what the model was trained to satisfy. Recollecting data and fine-tuning for each user's evolving needs is prohibitively expensive, yet no efficient test-time mechanism existed to adapt a frozen backbone LLM to arbitrary, user-specified preferences in real time.

## Input / Output

At each decoding step, the method consumes two LLM forward passes: one conditioned on the base prompt plus the user's preference prompt (e.g., 'be concise'), and one on the base prompt alone, yielding two token-level probability distributions. The preference prompt is a short, free-form user instruction requiring no training data or reward model. The output is a single sampled token per step, with the full generation sequence assembled iteratively; the entire process adds roughly 100 ms per token (comparable to Linear Alignment) on a single GPU.

## Method

Amulet formulates the decoding of each token as an independent online learning problem solved via Follow-the-Regularized-Leader (FTRL) with a proximal KL regularizer. The utility function at iteration t is the log-ratio between the preference-conditioned policy and the base policy, u_t(a) = α(log π_t(a) − log π_base(a)), which amplifies the directional signal introduced by the preference prompt. A KL penalty λ·D_KL(π‖π_1) anchors the iterated policy to the initial preference-conditioned distribution to prevent runaway optimization. The key technical contribution is a closed-form solution for each FTRL-proximal update (Proposition 3.1), reducing per-iteration cost to a single element-wise exponential over the vocabulary, so that T iterations per token incur only O(T·|V|) arithmetic with no gradient computation. The framework is entirely training-free: no parameters are updated, no reward model is trained, and the only user input is a natural-language preference prompt.

## Results

Across 64 experimental settings (4 LLMs × 4 datasets × 4 preferences), Amulet achieves the highest ArmoRM-8B reward model score in 75% of cases, compared to 20% for LA, 3% for BS16, and 0% for Base. On the best-performing model (Llama-3.1-8B-Instruct), Amulet achieves a 100% win rate, with a peak improvement of 79% over Base and 35% over LA (creative preference on Personal dataset). On the GPT-4o win-rate metric, Amulet achieves the highest win rate in all tasks, with even the weakest model (Qwen2-7B) reaching a 62.2% win rate against LA. Computationally, Amulet (T=60) takes ~113 ms/token, nearly identical to LA (~101 ms/token) and 17× faster than RAIN (~1933 ms/token).

## Baselines & Comparisons

Against LA (Gao et al., 2024), the current SOTA test-time alignment method, Amulet wins in 75% of all 64 settings versus LA's 20%, with the gap widening to 100% on Llama-3.1-8B-Instruct where Amulet shows up to 35% relative improvement over LA (creative preference, Personal dataset: 0.62 vs 0.46). Against Beam Search (BS16), Amulet dominates overwhelmingly—BS16 achieves the top score in only 3% of settings, and Amulet consistently outperforms it by 0.03–0.15 reward model points on average. Against RAIN (Li et al., 2023), the comparison is limited to computational efficiency: RAIN requires ~1933 ms/token (17× slower than Amulet at T=60, which takes ~113 ms/token), making RAIN impractical for interactive use. Amulet also outperforms the simple Preference-prompt baseline (Pref) in the vast majority of settings, confirming that iterative FTRL-based optimization captures preference signals that a single prompt cannot.

## Relation to Prior Work

Amulet builds directly on the Follow-the-Regularized-Leader (FTRL) online learning framework (McMahan, 2011) and adapts it to the LLM decoding setting by introducing a KL proximal regularizer for stability. Its utility function is inspired by Contrastive Decoding (Li et al., 2022) and Linear Alignment (Gao et al., 2024), which compare the log-probability distributions with and without a preference prompt. The key departure from LA—the closest prior method—is that Amulet applies this contrastive signal iteratively through multiple FTRL steps per token rather than a single linear update, and provides a closed-form solution for each iteration that keeps computational cost comparable to LA's single-step approach.

## Why It Matters / Open Questions

Amulet addresses a practical gap: existing alignment methods (RLHF, DPO) require retraining for each new preference, while test-time methods like RAIN are too slow for interactive use. By achieving LA-comparable latency (~113 ms/token vs. ~101 ms/token) while consistently outperforming it across 64 experimental settings, Amulet offers a viable path toward real-time personalization without any fine-tuning. Open questions include how the method behaves in multi-turn conversations where preferences evolve mid-dialogue, whether the approximate utility (log-ratio of two forward passes) degrades for more nuanced or multi-dimensional preferences, and whether the overfitting observed beyond ~80 iterations limits the achievable alignment quality for complex preference specifications.
