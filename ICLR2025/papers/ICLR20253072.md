## Problem

Existing open-ended learning algorithms, including OMNI, are confined to manually predefined and narrow distributions of environment parameters (e.g., obstacle size, type, position), preventing them from generating any possible learning environment. This limitation inhibits true Darwin Completeness—the ability to create an infinite, unbounded space of learning challenges—and restricts the potential of AI-generating algorithms to produce general intelligence.
![Teaser figure](../imgs/ICLR20253072/cropped_page3_idx0.webp)

## Input / Output

The system consumes a growing task archive of natural language descriptions paired with Python environment code (both successfully learned and failed tasks) and feeds it via retrieval-augmented generation to an LLM. The RL agent receives 64×64×3 RGB images and proprioceptive joint positions/velocities from an R2D2 robot with a discrete 6-action space (do nothing, forward, backward, rotate CW, rotate CCW, jump). Outputs include a natural language task description, executable PyBullet environment code implementing the Gymnasium API (reset, step, reward, terminated, plus a separate success-checking function), and a trained DreamerV3 specialist policy.

## Method

OMNI-EPIC is a closed-loop pipeline where an LLM task generator proposes novel natural language task descriptions conditioned on retrieved similar tasks from the archive (serving as stepping stones), then a second LLM translates each description into executable Python code defining the full simulated world, reward function, and termination logic for PyBullet. A post-generation model of interestingness (MoI) filters newly generated tasks by comparing them against the most similar archive entries via retrieval-augmented generation, discarding tasks that are not sufficiently novel or worthwhile. DreamerV3 specialist agents are trained on each accepted environment, with new agents initialized from the policy of the most embedding-similar previously solved task to enable transfer. An LLM-generated success-checking function (distinct from the shaped reward function) verifies task completion, and failed tasks are iterated up to a maximum number of times before being archived as failures, which then inform future task generation to maintain appropriate difficulty.

## Results

In a long run with simulated learning, OMNI-EPIC generates 200 diverse tasks for the R2D2 robot, with tasks evolving across multiple niches (ball-kicking, object retrieval, navigation, dynamic platforms). In a short run with actual RL training (DreamerV3), the agent successfully completed 16 out of 23 generated tasks (6 failures, 1 deemed uninteresting by the post-generation MoI). A user study with 50 participants found a 72.7% alignment rate between human evaluations and the LLM-based success detector. On both quantitative metrics (archive cell coverage and ANNECS-OMNI), OMNI-EPIC significantly outperforms its two ablation controls (p < 0.05, Mann-Whitney U test).

## Baselines & Comparisons

The paper does not compare against external methods (e.g., POET, OMNI) quantitatively; instead, it uses two internal ablation controls: (1) OMNI-EPIC without the task archive, and (2) OMNI-EPIC without the model of interestingness (relying only on learning progress). OMNI-EPIC significantly outperforms both controls on archive diversity (cell coverage in a 2D PCA-discretized plot) and on the proposed ANNECS-OMNI progress metric (p < 0.05, Mann-Whitney U test, 3 and 5 repeated runs respectively). The ablation without the archive shows reduced diversity, confirming that the growing archive of stepping stones is critical for open-ended exploration. The ablation without the MoI (Learning Progress Only) also underperforms, demonstrating that the human notion of interestingness distilled into the FM adds a meaningful filter beyond raw learning progress. The paper notes that the ANNECS-OMNI metric for OMNI-EPIC consistently increases throughout the run without stagnation, which the authors describe as a new high watermark for open-ended algorithms.

## Relation to Prior Work

OMNI-EPIC directly extends OMNI (Zhang et al., 2023), which used foundation models to model human notions of interestingness for open-ended task selection, by adding an environment code generation component (EPIC) that translates natural language task descriptions into executable PyBullet simulation code. This departs from prior unsupervised environment design methods (POET, UED, MAESTRO) that were confined to manually predefined parameterizations of a fixed environment template, and from FM-based environment generators (Eureka, GenSim, MarioGPT) that lacked an adaptive auto-curriculum tied to agent learning progress. The framework also introduces a post-generation model of interestingness using retrieval-augmented generation to verify novelty against a growing task archive, drawing on dynamics of human scientific culture.

## Why It Matters / Open Questions

OMNI-EPIC represents a concrete step toward Darwin Completeness—the ability to generate any possible learning environment—by showing that FMs can produce both the simulated world and reward/termination functions for arbitrary tasks, eliminating the need for handcrafted environment parameterizations. However, the current implementation is constrained to a single simulator (PyBullet) and trains specialist agents without evidence of cross-task generalization, leaving open whether the approach scales to truly arbitrary code generation or multi-agent generalist policies. The introduction of ANNECS-OMNI as a progress metric that incorporates interestingness (beyond solvability) is a useful contribution, but the empirical validation is limited to short RL runs (5 runs, ~20 tasks each) and a long run with simulated learning, leaving questions about whether the creative explosion sustains over much longer horizons and whether generated environments are genuinely novel versus regurgitated from training data.
