## Problem

Historical embedding methods (GAS, VR-GCN, MVS-GCN, GraphFM) scale GNNs to large graphs by caching intermediate-layer embeddings for out-of-batch nodes, but these cached features become stale relative to the current model parameters. The paper identifies this staleness as the root cause of why these methods fail to consistently outperform simpler samplers like GraphSAGE on large datasets and suffer degraded convergence, particularly with small batch sizes where model parameters update more frequently than the memory table.
![Teaser figure](../imgs/ICML20252808/cropped_page2_idx1.webp)

## Input / Output

The method operates on a graph with node feature vectors, consuming data in mini-batches (either METIS clusters for GAS-style methods or sampled nodes for VR-GCN/MVS-GCN). It produces node-level embeddings at each layer and final classification predictions. A key operational detail is the memory table: intermediate-layer embeddings for all nodes are stored in CPU/disk memory and retrieved during forward passes to approximate out-of-batch neighbor contributions, so the method's I/O pattern involves both GPU computation on in-batch nodes and memory lookups for the remaining neighborhood.

## Method

REST (REducing STaleness) decouples forward and backward propagation by executing F gradient-free forward passes on batches B₁…B_F to refresh the memory table, followed by one forward-backward pass on a separate batch B̃ⱼ for the actual parameter update. This increases the memory table update frequency from k to k/F (where k = n/B is the number of iterations to cycle through all nodes), directly closing the frequency gap between cache updates and model updates that causes staleness. A variant, REST-IS, adds importance sampling by designating neighbor nodes of the gradient batch as in-batch nodes during memory updates, so high-degree nodes that contribute more to message passing get refreshed more often. The approach is orthogonal to the GNN backbone, sampling strategy, and memory-based method, requiring only additional cheap forward passes without architectural changes.

## Results

On ogbn-products (2.4M nodes), REST-IS with APPNP backbone achieves 80.5% node classification accuracy, outperforming GAS (76.9%), GraphSAGE (78.7%), and GraphSAINT (79.1%). On ogbn-arxiv (169K nodes), REST with GCNII reaches 73.2% vs. GAS's 72.8% and GraphSAGE's 71.5%. On the much larger ogbn-papers100M dataset, GAS+REST improves accuracy from 64.9% to 67.6% (+2.7%), and on MAG240M from 61.2% to 67.6% (+6.4%), while also reducing total training time by ~53% and ~40% respectively.

## Baselines & Comparisons

REST and REST-IS outperform all historical embedding baselines (GAS, VR-GCN, MVS-GCN, GraphFM) by a substantial margin on ogbn-products: REST (GCN) reaches 79.6% vs. GAS (GCN) at 76.7%, VR-GCN at 76.3%, and MVS-GCN at 76.7%, a gap of 2.9–3.3%. On ogbn-arxiv, REST (GCNII) achieves 73.2% vs. GAS (GCNII) at 72.8% and GraphFM (GCNII) at 72.9%, while REST-IS (APPNP) reaches 72.4% vs. GAS (APPNP) at 71.9%. Against vanilla sampling methods, REST (GCN) beats GraphSAGE by 0.9% on ogbn-products (79.6% vs. 78.7%) and by 1.7% on ogbn-arxiv (72.2% vs. 71.5%), though GraphSAINT narrowly edges out REST on Reddit (97.0% vs. 96.8%). On the largest datasets, the advantage is most pronounced: GAS+REST improves over GAS by 2.7% on ogbn-papers100M (67.6% vs. 64.9%) and 6.4% on MAG240M (67.6% vs. 61.2%), while also cutting training time roughly in half. Against the most recent staleness-aware baselines, REST outperforms LMC by 2.6% on ogbn-products (80.1% vs. 77.5%) and Refresh by 1.3% (79.6% vs. 78.3%), confirming that decoupling forward/backward passes addresses staleness more effectively than regularization or selective memory updates.

## Relation to Prior Work

This paper builds directly on the historical embedding family of scalable GNN training methods (GAS, VR-GCN, MVS-GCN, GraphFM), which cache intermediate node embeddings to reduce sampling variance without expanding neighborhood size. The key conceptual departure is identifying 'staleness'—the growing gap between cached embeddings and true embeddings computed with current parameters—as the root cause of these methods' underperformance on large graphs, rather than treating it as a secondary artifact. REST addresses this by decoupling forward and backward passes so the memory table refreshes more frequently than model parameters, a strategy orthogonal to prior staleness-mitigation techniques like GAS's regularization, GraphFM's feature momentum, and ReFresh's staleness-scored selective updates.

## Why It Matters / Open Questions

The finding that state-of-the-art historical embedding methods (GAS, GraphFM) can underperform the simpler GraphSAGE on large datasets like ogbn-products is a significant correction to the field's assumptions about the superiority of variance-reduction approaches. REST's simplicity (extra gradient-free forward passes) makes it trivially adoptable by any practitioner using memory-based GNN training, and its orthogonality means it stacks with existing techniques. Open questions include whether the frequency parameter F has diminishing returns at very large scales, whether the approach transfers to non-message-passing GNN architectures (e.g., transformers on graphs), and how it interacts with asynchronous distributed training where parameter staleness compounds with embedding staleness.
