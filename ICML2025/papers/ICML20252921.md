## Problem

Complex code generation tasks require multi-step algorithmic reasoning, yet outcome supervision only evaluates final code quality while process supervision demands expensive trained Process Reward Models (PRMs) that suffer from reward misalignment and hallucination. The paper asks whether LLMs' intrinsic reasoning and self-critique capabilities, anchored by verifiable execution feedback, can generate high-quality process rewards without any PRM training.
![Teaser figure](../imgs/ICML20252921/cropped_page0_idx1.webp)

## Input / Output

The method takes a natural language problem description and a set of unit tests (either LLM-generated or dataset-provided, the latter denoted w/T) as input. It produces a final code solution accompanied by a full reasoning chain that documents the iterative refinement process. Each intermediate state in the search tree is a tuple of (reasoning chain, code, execution feedback, outcome reward, critic text, process reward), and the beam search retains top-K trajectories at each step, enabling parallel exploration of divergent algorithmic strategies.

## Method

ORPS performs inference-only tree-structured beam search that unifies process and outcome supervision. At each step, the LLM generates N candidate (reasoning update, code) pairs per beam state; each candidate is executed and profiled on unit tests to compute an outcome reward combining dynamic metrics (execution time, CPU instructions, branch misses, page faults) and static metrics (code length, AST node count, cyclomatic complexity, cognitive complexity). The same LLM then acts as a self-critic, producing a textual critique and a numerical process reward grounded in the execution metrics, preventing reward hacking. A weighted step score q = α·ρ + β·ω guides Top-K beam selection, where α and β balance theoretical soundness against empirical effectiveness. The key distinction from prior repair-focused methods is that ORPS operates at a higher abstraction level—guiding the model to reason about overall algorithmic strategy (e.g., switching from brute-force to divide-and-conquer) rather than incrementally patching local code errors.

## Results

On the challenging LBPP benchmark, ORPS(w/T) achieves 77.8% Pass@1 with Qwen-2.5-Coder-7B, compared to 40.1% for CoT and 53.1% for Best-of-N sampling. Across all 5 models and 3 benchmarks, ORPS(w/T) delivers an average 26.9% Pass@1 improvement over baselines while reducing execution time by 42.2% on average. Notably, Qwen-7B with ORPS(w/T) (77.8% on LBPP) surpasses Qwen-14B using CoT (53.7%), demonstrating that structured reasoning space can outperform raw model scale.

## Baselines & Comparisons

ORPS(w/T) decisively outperforms all baselines on LBPP across every model. Against CoT, the gap ranges from +27.0 pp (Qwen-7B: 77.8% vs 40.1%) to +38.9 pp (GPT-4o-Mini: 88.9% vs 50.0%). Against Reflexion, ORPS(w/T) leads by +40.1 pp on Qwen-7B (77.8% vs 37.7%) and +26.6 pp on GPT-4o-Mini (88.9% vs 62.3%). Against LDB(w/T), the advantage is even larger: +42.0 pp on Qwen-7B (77.8% vs 35.8%), with LDB also suffering severe execution-time inflation (187.8× vs 82.4×). Against Best-of-N, ORPS(w/T) wins on LBPP by +24.7 pp (Qwen-7B) but BoN remains competitive on the simpler MBPP benchmark (82.9% vs 94.9% for ORPS(w/T), where BoN's 82.9% is closer). A key finding is that Qwen-7B with ORPS(w/T) (77.8% on LBPP) surpasses Qwen-14B with CoT (53.7%), confirming that structured reasoning space can substitute for model scale.

## Relation to Prior Work

ORPS carves new ground at the intersection of process supervision (PRM-guided tree search from math reasoning, e.g., Lightman et al. 2023) and execution-feedback code repair (Reflexion, LDB, REx). It departs from prior process supervision by eliminating the need for a separately trained PRM, instead using verifiable execution metrics combined with LLM self-critique as the process reward signal. It also departs from execution-feedback methods by operating at a strategic algorithmic level (exploring fundamentally different approaches via beam search) rather than performing incremental local code repair. The tree-structured search framework is adapted from math-reasoning PRM-guided search, but the reward mechanism is entirely replaced by an inference-only hybrid of dynamic profiling and static analysis scores.

## Why It Matters / Open Questions

The paper challenges a widely held assumption in the process supervision literature that specially trained reward models are necessary for effective step-level guidance, showing that verifiable execution feedback plus self-critique can match or exceed trained PRMs even with human-annotated data. The finding that smaller models with ORPS outperform larger models without it has practical implications for compute-constrained deployments. Open questions include whether the approach generalizes to non-executable domains (math, planning), how sensitive performance is to the quality of self-generated unit tests (gold tests yield substantially higher scores), and whether the tree-search overhead is acceptable in latency-sensitive production settings.
