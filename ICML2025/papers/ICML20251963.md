## Problem

Existing evaluations of LLM prompt-injection defenses rely on static, non-adaptive attack benchmarks that overestimate security, and they largely ignore the usability penalties that restrictive defenses impose on legitimate users. This paper addresses both gaps by proposing a dynamic threat model that separates attackers from benign users in multi-turn sessions and by introducing a crowd-sourced platform to generate realistic, adaptive attacks with automatic success labeling.
![Teaser figure](../imgs/ICML20251963/cropped_page2_idx0.webp)

## Input / Output

The framework consumes multi-turn text sessions where each transaction consists of a user/attacker prompt, the system prompt (encoding the defense), and the resulting LLM response; feedback from prior transactions can inform subsequent ones. Security is measured by the Attacker Failure Rate (fraction of attacker sessions fully blocked) and utility by the Session Completion Rate (fraction of user sessions unblocked), combined into a developer utility score V^λ(D) = (1−λ)·AFR + λ·SCR. The system outputs per-transaction block/pass decisions and aggregate metrics, with the key distinction that internal defenses (system prompts) can degrade response quality without triggering an explicit block, requiring auxiliary measures like response-length reduction.

## Method

The paper introduces D-SEC, a threat model that formalizes the security-utility trade-off as an optimizable developer objective over a defense D, and Gandalf, a gamified crowd-sourced red-teaming platform where players sequentially extract a hidden password from an LLM across six defense levels (no defense → weak prompt → substring check → LLM checker → strong prompt → combined), with success automatically labeled by whether the password was actually revealed. The platform was run as a randomized controlled trial (Gandalf-RCT) across three LLMs (GPT-3.5-turbo, GPT-4o-mini, GPT-4) and three application setups (general chat, summarization, topic-restricted), yielding 279k prompt attacks in 36k sessions. The empirical analysis demonstrates three defense strategies that optimize the trade-off: restricting the application domain (narrower tasks increase AFR), defense-in-depth via optimal aggregation of heterogeneous defenses (substring, LLM-as-judge, system prompt), and adaptive defenses that block the entire session after T flagged transactions, with the threshold T selected to maximize developer utility.

## Results

Across 279,675 prompt attacks in 36,286 sessions from 15,448 users, the combined defense (Level D) is the hardest to bypass, with only 2.9%, 6.3%, and 6.4% of players succeeding in the general, summarization, and topic setups respectively. Domain restriction increases average difficulty: summarization yields the lowest average levels solved (1.01–1.28) compared to general (1.50–1.95) across GPT-3.5, GPT-4o-mini, and GPT-4. An adaptive defense with a block threshold of 3 on the combined defense blocks 75% of attacks that evaded all non-adaptive defenses, at the cost of increased false-positive rates on borderline user prompts (up to 42% for GPT-3.5-turbo on BorderlineUser).

## Baselines & Comparisons

The paper does not compare against external baseline methods; instead, it evaluates six internal defense levels (A–D) across three LLMs and three application setups. Level D (combining substring check, LLM checker, and strong system prompt via OR-aggregation) substantially outperforms any single defense: only 14.5% of attacks are caught by all three C-level defenses simultaneously, confirming that defense-in-depth captures complementary attack vectors. Domain restriction (summarization and topic setups) increases attacker difficulty by 25–40% relative to the general setup, as measured by fewer average levels solved per session. Adaptive defenses (blocking the session after T flagged transactions) add a further security layer: a threshold of T=3 on the combined defense blocks 75% of previously undetected attacks, though this raises false-positive rates on borderline user prompts from ~2% (non-adaptive, GPT-4) to ~26% (adaptive, GPT-4). System-prompt defenses (Levels B, C3) degrade utility beyond simple blocking, reducing response length and altering content similarity even when no explicit block occurs, a subtlety missed by standard attack-success-rate evaluations.

## Relation to Prior Work

This paper departs from static prompt-attack benchmarks (JailbreakBench, HarmBench, PromptBench) and single-shot red-teaming by introducing D-SEC, a dynamic threat model that explicitly separates attacker and user distributions and models multi-step adaptive sessions. It builds on the Gandalf crowd-sourced red-teaming game (Schulhoff et al., 2023; Toyer et al., 2023) by adding randomized controlled trials across defenses, LLMs, and application setups to generate causal evidence. The security-utility trade-off framing draws on classical usable-security literature (Garfinkel & Lipford, 2014) but is the first to formalize it for LLM-specific defenses where security layers are embedded in the model itself via system prompts or fine-tuning, making the utility cost harder to isolate.

## Why It Matters / Open Questions

The 279k-prompt Gandalf-RCT dataset and the D-SEC framework give practitioners a principled way to evaluate defenses on both security and utility simultaneously, addressing a gap where most prior work optimized only for attack success rate. The finding that system-prompt defenses degrade response quality (length, content similarity) even when no explicit block occurs is practically important for developers who assume internal defenses are utility-free. Key limitations include the narrow password-extraction task, restriction to direct (not indirect) attacks, and the use of response-length/cosine-similarity as utility proxies rather than task-specific quality metrics. Open questions include extending D-SEC to agentic systems with tool use, developing automated red-teaming that matches crowd-sourced diversity, and designing adaptive defenses beyond simple block-threshold mechanisms.
