## Problem

Software engineering agents lack a suitable training environment: unlike chat, math, or web navigation, SWE requires interaction with executable runtimes containing pre-installed dependencies and reproducible test suites. Existing resources are inadequate—SWE-Bench's training split provides only final git patches without step-by-step actions or executable environments, R2E uses synthetic tasks far from real-world problems, and APPS targets isolated coding challenges rather than repository-level tasks. This gap has forced the field to rely on proprietary models and prompting strategies rather than learning-based approaches.

## Input / Output

The agent receives a natural-language GitHub issue description, a snapshot of the associated Python repository (averaging ~340K lines of non-test code across ~971 files), and a pre-configured Docker environment with all dependencies installed. It produces a git diff patch that is validated by executing the repository's unit tests (averaging ~760 total tests per instance). The verifier model consumes the full agent trajectory—an interleaved sequence of observations (command outputs, error messages) and actions (bash commands, file edits)—along with the problem statement and current diff, and outputs a scalar success probability in [0,1] computed from the log-probabilities of <YES> and <NO> tokens.

## Method

SWE-Gym constructs 2,438 executable task instances from 11 Python repositories by semi-manually configuring Docker environments per codebase version and validating that gold patches pass more unit tests than the original code (~200 human annotation hours, 10K CPU core hours). For agent training, the paper applies rejection sampling fine-tuning: 491 successful trajectories are sampled from GPT-4o and Claude-3.5-Sonnet at varying temperatures, then used to fine-tune Qwen-2.5-Coder-Instruct (7B/14B/32B) via full-parameter or LoRA training, yielding up to +13.6% absolute resolution rate gains. For inference-time scaling, an outcome-supervised reward model (ORM) is fine-tuned on a balanced mixture of on-policy and off-policy trajectories (2,636 total) to predict trajectory success, enabling best-of-k selection that pushes resolution to 32.0% on SWE-Bench Verified. A per-instance capping strategy (limiting to 2 successful trajectories per task) mitigates the long-tail bias toward easier tasks that arises from repeated sampling, and self-improvement via iterative rejection sampling with the MoatlessTools specialized-workflow scaffold achieves 19.7% on SWE-Bench Lite without a strong teacher model.

## Results

On SWE-Bench Verified, the fine-tuned 32B Qwen-2.5-Coder agent (OpenHands scaffold) achieves 20.6% resolution rate, and with a trained verifier for inference-time scaling (Best@16), reaches 32.0%. On SWE-Bench Lite, the corresponding numbers are 15.3% (agent only) and 26.0% (agent + verifier). These represent up to +13.6% absolute gains over the zero-shot base model and establish a new state-of-the-art among open-weight SWE agents.

## Baselines & Comparisons

Against SWE-Llama (Jimenez et al., 2024), the proposed 32B agent achieves 20.6% vs. 1.4% (7B) and 1.2% (13B) on SWE-Bench Verified, a roughly 15× improvement. Against Lingma SWE-GPT (Ma et al., 2024), the 32B agent (20.6%) outperforms the 7B Lingma model (18.2%) by 2.4 points, and the agent+verifier system (32.0%) surpasses the 72B Lingma model (28.8%) by 3.2 points, despite using a smaller model and far less training data (491 trajectories vs. 90K PRs). Against the concurrent work by Golubev et al. (2024), which achieves 40.6% on SWE-Bench Verified with a 72B model and 80K+ trajectories, the proposed 32B system (32.0%) trails by 8.6 points but uses substantially less compute and a smaller model. The paper also notes that on SWE-Bench Lite, the proposed system (26.0%) outperforms Lingma SWE-GPT 72B (22.0%) by 4 points, while Golubev et al. do not report Lite results.

## Relation to Prior Work

This paper extends the post-training paradigm (rejection sampling fine-tuning, outcome-supervised reward models) established in chat, math reasoning, and web navigation to the software engineering domain, where no suitable training environment previously existed. It builds directly on SWE-Bench's task formulation and instance extraction pipeline but adds the critical missing components—executable environments with pre-installed dependencies and unit-test-based reward signals—that the SWE-Bench training split lacks. The verifier training approach adapts the ORM framework from Cobbe et al. (2021) to agent trajectories, and the agent scaffolds (OpenHands, MoatlessTools) are reused from prior work rather than introduced here.

## Why It Matters / Open Questions

SWE-Gym is the first publicly available training environment that closes the gap between SWE evaluation (SWE-Bench) and SWE training, enabling learning-based approaches to replace reliance on proprietary models and prompt engineering. The demonstrated log-linear inference-time scaling and consistent training-time scaling suggest substantial headroom, but self-improvement via on-policy fine-tuning currently degrades performance, pointing to the need for more advanced policy optimization (e.g., PPO). Key limitations include restriction to Python and 11 repositories, modest self-improvement gains, and the gap between Pass@k and Best@k indicating imperfect verifiers. Open questions include automatic environment synthesis, human-agent interaction, and whether the scaling trends hold with larger compute budgets.
