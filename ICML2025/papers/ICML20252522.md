## Problem

Existing code instruction data synthesis methods rely on individual code snippets as seed data, which are inherently rigid and difficult to recombine, limiting both the complexity and diversity of generated training data. Additionally, most code generation benchmarks focus exclusively on function-level tasks, leaving file-level and cross-file dependency generation capabilities largely unevaluated.
![Teaser figure](../imgs/ICML20252522/cropped_page0_idx0.webp)

## Input / Output

The synthesis pipeline takes raw Python files from The Stack v2 (150k core-set samples selected via KCenterGreedy) and produces 433k synthetic instruction samples (380k function-level, 53k file-level), each consisting of a task description, solution code (ranging from a single function to a multi-file project), and executable test cases. At inference time, the trained EpiCoder models accept a natural-language coding instruction and produce code completions, with file-level tasks additionally requiring the model to generate a target file given the contents of all other interdependent files as context.

## Method

The framework constructs a hierarchical feature tree from code via three stages: (1) GPT-4o extracts semantic features (workflow, data processing, computation operations, etc.) from seed code and organizes them into a tree through iterative hierarchical clustering; (2) the tree is evolved over 9,000 LLM-driven steps, expanding both in depth (finer-grained child nodes) and breadth (sibling nodes), growing from 5k to 140k features, with new feature frequencies estimated as the average of their siblings; (3) subtrees are sampled using a temperature-adjusted probability distribution (Equation 1) that smooths the natural feature frequency to upweight underrepresented features, and the LLM generates a task, code, and tests conditioned on the sampled subtree. Adjusting subtree depth and breadth directly controls output complexity from function-level to multi-file scenarios, and iterative test execution with LLM-guided debugging ensures correctness. The resulting data fine-tunes Qwen2.5-Coder-7B-Base and DeepSeek-Coder-6.7B-Base into the EpiCoder series.

## Results

EpiCoder-Qwen-7B achieves a 59.0% average Pass@1 across five function-level benchmarks (HumanEval+, MBPP+, BigCodeBench-Full/Hard, EvoEval), setting SOTA among ~7B-scale models and outperforming Qwen2.5-Coder-7B-Instruct by 2.0 points. On BigCodeBench-Hard completion, EpiCoder-Qwen-7B scores 27.7%, surpassing Qwen2.5-Coder-7B-Instruct (20.3%) by 7.4%. EpiCoder-DS-6.7B reaches 53.1% average, beating all other DeepSeek-Coder-6.7B-based models by 3–5 points. On the file-level XFileDep benchmark (466 problems), EpiCoder models trained on 53k multi-file samples significantly outperform all baselines, demonstrating superior cross-file dependency handling.

## Baselines & Comparisons

Among ~7B-scale models, EpiCoder-Qwen-7B (59.0% avg) beats Qwen2.5-Coder-7B-Instruct (57.0%) by 2.0 points and all DeepSeek-Coder-6.7B-based baselines (Magicoder-S-DS 50.1%, WaveCoder-Ultra-6.7B 48.0%, OpenCodeInterpreter-DS-6.7B 49.8%, DeepSeekCoder-6.7B-Instruct 48.1%) by 3–5 points. EpiCoder-DS-6.7B (53.1%) surpasses WizardCoder-33B-1.1 (49.2% on EvoEval) and all CodeLlama variants (≤44.0% on EvoEval). At the 7B+ scale, EpiCoder-Qwen-7B outperforms OpenCoder-8B-Instruct (54.8%), DeepSeek-Coder-33B-Instruct (54.4%), and Codestral-22B-v0.1 (53.4%) despite being smaller, but trails Qwen2.5-Coder-32B-Instruct (64.8%) and GPT-4-Turbo (63.1%). Under matched data size (75k), EpiCoder-DS-6.7B-75k (51.2% avg) beats Magicoder-DS-75k (45.8%) by 5.4% and WaveCoder-Ultra-6.7B-130k (48.2%) by 3.0%, and EpiCoder-CodeQwen-74k (62.6%) outperforms SelfCodeAlign-CQ-7B-74k (58.6%) by 4.0 points, confirming data quality gains over quantity.

## Relation to Prior Work

This paper departs from the dominant paradigm of evolving individual code snippets or instructions (WizardCoder, Magicoder, WaveCoder, Genetic-Instruct) by introducing a hierarchical feature tree as the unit of evolution. Inspired by ASTs, the feature tree captures semantic relationships at a higher level of abstraction, and evolution operates on the tree structure (adding depth and breadth) rather than on raw code, providing a more organized and scalable direction for data diversity. The paper also fills a notable gap in evaluation by introducing XFileDep, a cross-file dependency benchmark, since prior code generation benchmarks (HumanEval, MBPP, BigCodeBench) focus almost exclusively on function-level tasks.

## Why It Matters / Open Questions

The feature tree framework offers a principled, interpretable mechanism for controlling code complexity (via subtree depth/breadth) and targeting underrepresented knowledge areas (via distribution reweighting), which is practically useful for practitioners building code LLMs. The demonstration of repository-level synthesis (50+ files mirroring LLaMA-Factory) suggests a path toward automating large-scale code generation, though this remains a proof-of-concept without rigorous evaluation. Open questions include whether the approach generalizes beyond Python, whether the LLM-as-judge complexity metrics are reliable proxies for true code sophistication, and whether the feature tree can be efficiently maintained and updated as the underlying code ecosystem evolves.
