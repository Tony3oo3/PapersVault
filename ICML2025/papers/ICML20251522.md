## Problem

Reducing time-to-first-token (TTFT) in LLM inference is critical for maximizing QPS, yet the prefill phase is compute-bound with the bottleneck shifting to MLP computation for large-batch, short-to-medium context queries. Prior prefill acceleration methods either require post-training adaptation (e.g., SwiftKV) or scale inefficiently (e.g., GemFilter), and none directly skip MLP computation in a training-free manner.

## Input / Output

The method takes a full text prompt of arbitrary length and a configurable token keep rate (e.g., 10%–90%). A lightweight speculator model (Llama-3.1-8B) first processes the entire prompt and performs N lookahead decoding steps to compute attention scores. The output is a subset of prompt tokens with their original non-contiguous position IDs, which is then fed to the base model (Llama-3.1-70B or 405B) for standard autoregressive generation. The positional information is explicitly restored so that the base model sees the correct token positions despite the dropped tokens, which is crucial for position-sensitive tasks like retrieval and counting.

## Method

SPECPREFILL uses a smaller speculator model to estimate token importance via attention scores, then sends only the selected tokens (with restored position IDs) to the main model, reducing total FLOPS proportionally to the token drop rate. Specifically, the speculator decodes N lookahead steps to mitigate position and proximity biases, and attention scores are aggregated using a max-over-heads-and-layers, mean-over-lookahead strategy to produce scalar importance per token. Tokens are then selected by contiguous chunks with 1D average pooling to denoise the importance estimates, reducing variance from nearby-token similarity. The entire pipeline is training-free and zero-shot, requiring only a monkey patch on vLLM with a configuration file. The speculator can be shared with speculative decoding, enabling a unified small-model-assisted inference paradigm where the same draft model handles both prefill token selection and decoding token drafting.

## Results

SPECPREFILL achieves up to 7.66× TTFT speedup on Llama-3.1-405B-Instruct-FP8 at 10% token keep rate, translating to a 7× maximal end-to-end QPS improvement on real downstream tasks while maintaining >95% accuracy. On LongBench (70B model), SPECPREFILL at 10% keep rate retains 98.5% of baseline average score (52.74 vs 53.55), and at 30% keep rate actually surpasses the baseline (53.92). On RULER synthetic probing, SPECPREFILL at 10% keep rate preserves near-perfect retrieval scores (99.7% at 4K vs 100% baseline) and even improves quality on several tasks by removing noisy tokens. Against MInference, SPECPREFILL achieves 2.54×–6.54× relative TTFT speedup with 99.5% quality performance, particularly at large batch sizes with short-to-medium prompts.

## Baselines & Comparisons

Against LLMLingua (prompt compression), SPECPREFILL dominates at every comparable compression rate: at ~10% keep rate, SPECPREFILL scores 52.74 average vs LLMLingua's 29.85, a gap of over 22 points; even at ~90% keep rate, LLMLingua (52.04) still trails SPECPREFILL at 10% (52.74). Against MInference (sparse attention), SPECPREFILL at 10% keep rate achieves 52.74 average vs MInference's 52.89 (99.7% of MInference), and at 30% keep rate SPECPREFILL (53.92) surpasses both MInference and the full baseline (53.55). In terms of TTFT, SPECPREFILL achieves 2.54×–6.54× speedup over MInference, with the advantage growing at larger batch sizes where MInference's sparse-attention overhead is not amortized. The paper also compares against two RAG baselines (sentence-level retrieval), which are eclipsed by SPECPREFILL by a large margin (e.g., 52.74 vs 35.49 at ~10% keep rate) because RAG requires explicit context-question separation and a fixed retrieval query, whereas SPECPREFILL operates without any input structure assumptions.

## Relation to Prior Work

SPECPREFILL occupies a distinct niche among prefill acceleration methods: unlike sparse attention approaches (MInference, FlashAttention, Duo Attention) that only speed up the attention computation, it skips both attention and MLP FLOPS by dropping tokens entirely. It departs from GemFilter (which uses the base model's own intermediate-layer attention in an extra pass) and SwiftKV (which requires fine-tuning to skip layers) by using a separate, cheaper speculator model in a fully zero-shot manner, drawing a direct analogy to speculative decoding but applied to token selection rather than token generation. The position-id restoration and chunk-based denoising are practical design choices that differentiate it from naive token-dropping baselines like LLMLingua or sentence-level RAG.

## Why It Matters / Open Questions

The 7× maximal QPS improvement for a 405B model with <5% accuracy loss is a practically significant result for production inference systems, and the training-free, vLLM-integrated design lowers the adoption barrier considerably. The ability to combine SPECPREFILL with speculative decoding using the same draft model points toward a unified small-model-assisted inference paradigm that could reshape how serving engines are architected. Key open questions remain: how to adaptively determine the token keep rate per query, whether multi-turn conversations can be supported without full KV recomputation, and whether importance estimation can go beyond attention scores to capture more nuanced token relevance.
