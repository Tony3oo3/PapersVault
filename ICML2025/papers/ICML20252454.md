## Problem

Pipeline parallelism (PP) scalability is constrained by activation memory: increasing the number of PP stages requires more in-flight microbatches to minimize pipeline bubbles, leaving total activation memory unchanged. While memory offloading is widely adopted in data parallelism, its potential in PP remains largely unexplored, and prior work concluded that activation offload in PP causes significant overhead and should be avoided.

## Input / Output

The method takes a transformer model architecture (GPT-3-like with GQA), hardware topology parameters (PCI-E duplex bandwidth, GPU compute bandwidth, NUMA/PCI-E switch layout), and training configuration (sequence length, hidden size, batch size, number of pipeline stages and devices) as input. It produces an optimized pipeline schedule (GIS, GIS-H, PO-H, or PO-F) with a computed offload ratio k that determines whether full or selective offload is feasible, yielding reduced per-device activation memory and measured throughput (MFU). A key constraint is that the method requires the offload round-trip time to be shorter than the forward-to-backward gap for each stage, and PCI-E traffic must be coordinated to avoid interference with cross-node P2P communication.

## Method

PipeOffload introduces a unified framework combining three key ideas. First, it shows that the ratio k = T_o/T_c (offload round-trip time over forward+backward compute time) is ≤1 for hidden dimensions >8k or sequence lengths >16k, making full activation offload a 'free lunch' that can be fully overlapped with computation. Second, when k>1, it employs a selective offload strategy that prioritizes pipeline stages with longer lifespans (larger gaps between forward and backward passes), using a uniform repeating schedule that achieves better-than-linear peak memory reduction—offloading half the stages reduces peak memory to roughly one-quarter. Third, it generalizes the interleaved 1F1B schedule into GIS/GIS-H by splitting the backward pass (zero-bubble strategy), adjusting warmup depth, and introducing a tunable inner-loop parameter g that smoothly trades activation memory against pipeline bubbles. Implementation uses a single CUDA stream for both offload and reload (avoiding latency fluctuations from dual streams), topology-aware synchronized interleaved PCI-E transfers between adjacent GPUs sharing a switch, and selective recomputation of trivial layers (GeLU, LayerNorm, Dropout) to reduce the offloaded volume by ~40%.

## Results

PO-H reduces peak activation memory to at most 1/6 of interleaved 1F1B (1F1B-I), while PO-F reduces it to O(M/(vd)), equivalent to a small constant (~4) transformer layers regardless of total model size. GIS-H halves activation memory relative to 1F1B-I with no additional pipeline bubbles. When comparing pure PP (PO-F) against the standard 1F1B-I + TP8 + sequence parallelism configuration, the paper reports a 12%–19% throughput acceleration with lower activation memory, making pure PP a viable alternative to hybrid PP+TP.

**Table 1: Comparing activation memory and bubble rate of different schedules.**

| Schedule | Activation Memory | Bubble |
|---|---|---|
| 1F1B | M | v(d−1)(T_F+T_B+T_W) |
| 1F1B-I | (v+1)/v · M | (d−1)(T_F+T_B+T_W) |
| GIS | M | (d−1)(T_F+T_B) |
| GIS-H | (v+1)/2v · M | (d−1)(T_F+T_B) + (v−1)d/2·(T_F+T_B−T_W) |
| PO-H | ≈(v+2)/8v · M | < v(d−1)(T_F+T_B+T_W) |
| PO-F | O(M/(vd)) | < v(d−1)(T_F+T_B+T_W) |

*Notation: M = activation memory of entire model; T_F, T_B, T_W = time of forward, backward (activation grad), and weight-grad passes of a single stage on a device; v = stages per device; d = number of devices.*

## Baselines & Comparisons

Against 1F1B (Harlap et al., 2018), both PO-H and PO-F achieve higher throughput while drastically reducing activation memory (1/6 and O(M/(vd)) respectively), with the sole exception of PO-F at k=1 where throughput slightly drops. Against interleaved 1F1B (1F1B-I, Narayanan et al., 2021), GIS already wins on both throughput and memory, GIS-H halves activation memory, and PO-H cuts it to 1/6; PO-F at k≤1 delivers a 12–19% speedup over 1F1B-I+TP8+SP, demonstrating that pure PP can outperform the standard hybrid PP+TP configuration. Against V-Min and V-Half (Qi et al., 2024), the paper achieves a more favorable Pareto frontier in the memory-vs-throughput trade-off, attributing the V-Shaped schedule's suboptimal performance to violations of its assumption that T_F ≈ T_B ≈ T_W at large sequence lengths.

## Relation to Prior Work

This paper builds directly on the pipeline parallelism scheduling literature (1F1B, Interleaved 1F1B from Megatron-LM, zero-bubble schedules from Qi et al. 2023, and the V-Shape controllable-memory framework from Qi et al. 2024) and repurposes the memory offloading strategy long established in data parallelism (ZeRO-Offload) for the pipeline parallelism setting. The most direct departure is from Yuan et al. (2024), who studied activation offloading in PP and concluded it introduces significant overhead and should be avoided; this paper inverts that conclusion by showing that with proper scheduling (single-stream, topology-aware, one-offload-one-reload), offload can be fully overlapped with computation and become a 'free lunch.' The uniform repeating strategy, which yields better-than-linear peak memory reduction under selective offload, extends the building-block framework of Qi et al. (2024) by showing that the microbatch organization pattern (interleaving vs. uniform repeating) materially changes each stage's contribution to peak memory.

## Why It Matters / Open Questions

The practical impact is substantial: by making per-device activation memory scale down with total pipeline stages, PP becomes a viable pure-parallelism alternative to TP, delivering 12–19% throughput gains by eliminating TP's all-reduce communication. This shifts the parallelism strategy calculus for large-scale LLM training, particularly for models where k ≤ 1 (hidden dim > 8k or sequence length > 16k), which covers most modern configurations. Key limitations include hardware dependence of k (validated only on A100, with H100 argued but not measured), host memory capacity as a secondary bound, and potential PCI-E interference with cross-node P2P traffic. Open questions include how the approach interacts with emerging hardware (NVLink-C2C, CXL memory pooling), whether the uniform repeating strategy generalizes to token-level or sequence-level pipeline schedules, and how to co-optimize offload with other memory-saving techniques (rematerialization, sequence parallelism) in a unified scheduler.
