## Problem

Prefix caching reduces redundant KV cache computation in long-context LLM inference, but loading cached KV from high-capacity, low-bandwidth storage (disks, remote storage) introduces significant Time-to-First-Token (TTFT) latency. Prior systems either compute KV cache from scratch or load it via I/O in isolation, leaving the complementary strengths of both resources untapped. No existing approach optimally balances computation and I/O in parallel to minimize loading latency.

## Input / Output

Cake takes a user text prompt (typically 4k–16k tokens) and pre-stored KV cache files from a hierarchical storage backend (local SSD or remote network storage), splitting the prompt into 512-token chunks for computation and 128-token chunks for I/O loading. The output is a fully assembled KV cache in GPU memory ready for autoregressive decoding, with the first generated token marking the end of the prefill phase. I/O bandwidth is simulated at 7–100 Gbps to represent realistic physical configurations from cloud egress limits to InfiniBand.

## Method

Cake's core insight is that attention computation cost grows linearly with token position (later tokens attend to all prior tokens) while KV cache I/O cost is uniform across positions. Exploiting this asymmetry, Cake employs a bidirectional scheduling strategy: the GPU computes KV cache forward from the first chunk while an I/O loader fetches cached KV backward from the last chunk, with both processes running in parallel until they merge in the middle. An adaptive scheduling mode extends vLLM's token-budget scheduler with a three-tier priority (decoding → non-prefix prefill → prefix prefill), allowing Cake to yield compute resources to other users' requests while still relying on I/O loading for its own chunks. The bidirectional design inherently handles resource fluctuations—when compute or I/O bandwidth changes, the merge point shifts automatically to maintain minimal latency without reconfiguration.

## Results

Cake achieves an average 2.6× reduction in Time to First Token (TTFT) compared to both compute-only (vLLM chunked prefill) and I/O-only (LMCache) baselines across diverse hardware, bandwidth, and sequence-length configurations. After filtering extreme outliers where one resource is severely bottlenecked, the average speedup is 2.23× over I/O-only and 3.76× over compute-only. The adaptive scheduling mechanism further improves system throughput by 26% under dynamic workloads, and Cake introduces negligible per-step overhead (Figure 7).

## Baselines & Comparisons

Cake is compared against two baselines: vLLM (v0.6.2) in chunked-prefill mode as the compute-only method, and LMCache (v0.1.4) as the I/O-only loading method. Cake consistently outperforms both baselines in the majority of configurations, with the largest gains occurring when compute and I/O capabilities are well-balanced (e.g., 2×A100 at 100% utilization with 32 Gbps SSD bandwidth yields 2.63× over I/O-only and 1.59× over compute-only). Against the I/O-only baseline, Cake's advantage grows with stronger GPUs (from ~2× on A100 to ~2.6× on 2×A100 at 32 Gbps) and with lower bandwidths (up to 8.1× at 7 Gbps). Against the compute-only baseline, Cake's advantage grows with higher I/O bandwidth (up to 15.27× at 100 Gbps with 2×A100 at 12.5% utilization) and with GQA models or KV cache quantization that reduce I/O size. Cake underperforms in a few extreme cases (e.g., short 4k-token sequences with 2×A100 at 100% utilization and 7 Gbps, where pure computation is faster than the bidirectional split), but these are acknowledged as edge cases addressable with a fallback mechanism.

## Relation to Prior Work

Cake builds directly on vLLM's chunked prefill scheduling (Kwon et al., 2023) and Sarathi's chunked-prefill-with-decode batching (Agrawal et al., 2023), repurposing the chunk-level granularity to schedule individual chunks for either GPU computation or I/O loading. It departs from prior prefix-caching systems (CachedAttention, CacheGen, SGLang) that treat KV cache retrieval as a purely I/O-bound problem or from compute-only approaches, by introducing a bidirectional parallel strategy that exploits the asymmetry between compute cost (growing with token position) and I/O cost (constant). The design is explicitly orthogonal to KV cache compression methods (quantization, GQA, token pruning), which the paper evaluates as complementary rather than competing.

## Why It Matters / Open Questions

The 2.6× average TTFT reduction is practically significant for long-context serving where disk-level cache hits dominate (~80% per AttentionStore), and the adaptive scheduling mechanism that coexists with non-prefix-caching requests (26% throughput gain) addresses a real deployment concern. However, the approach underperforms in extreme imbalances (e.g., short sequences with fast compute vs. slow I/O), and the authors acknowledge a fallback mechanism is needed. Open questions include how Cake interacts with prefill-decode disaggregation in multi-node settings, whether the bidirectional strategy generalizes to non-attention workloads, and how to handle partial cache hits where only a subset of chunks are stored.
