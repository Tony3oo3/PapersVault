## Problem

Existing multi-agent systems are either manually designed for narrow scenarios (MetaGPT, DataInterpreter) or automatically generated but lack critical capabilities: tool integration, generalization across cases within a task domain, traceback to fix earlier errors, and freedom from external training data. No prior method produces a complete, practical, tool-enabled multi-agent system that generalizes over a task domain while supporting flexible control flow.
![Teaser figure](../imgs/ICML20253036/cropped_page2_idx0.webp)

## Input / Output

During the design phase, MetaAgent takes a single natural-language task-domain description (e.g., 'Build a multi-agent system that develops software') and outputs a complete FSM specification in JSON: a set of agents (each with a name, system prompt, and assigned tools), a set of states (each with an assigned agent, natural-language instruction, listener list, and condition verifier), and transition conditions between states. During deployment, the system takes a specific case query (e.g., 'Build a Pac-Man Game') and produces a task-specific artifact—executable code, a trained model with metrics, a story, or a multiple-choice answer—by executing the FSM until a final state is reached or a maximum iteration limit is exceeded.

## Method

MetaAgent constructs a multi-agent system as a Finite State Machine where each state encapsulates a task-solving agent, a condition verifier (an LLM prompted with the agent's system prompt plus all outgoing transition conditions), a natural-language state instruction, and a listener list that controls information flow. The construction proceeds in three stages: (1) an LLM designer generates a parsimonious set of agents with tools (code interpreter, search engine) from the task description; (2) the same designer specifies states and natural-language transition conditions, anticipating diverse scenarios; (3) an iterative optimization loop performs pairwise state merging guided by an LLM that assesses role distinguishability, information necessity, and tool overlap, reducing redundancy without external data. At deployment, the condition verifier either triggers a forward/traceback transition or a null-transition (staying in the current state with feedback for iterative refinement), enabling the system to debug and correct earlier steps—capabilities absent in linear, debate, or orchestrator structures, which the paper formally shows are degenerate special cases of the full FSM.

## Results

On text-based tasks, MetaAgent achieves 0.86 on Trivial Creative Writing and 0.60 on GPQA(Diamond), surpassing the best prompt-based baselines (Self-Refine: 0.76/0.55) by 7% and 5% respectively. On the Machine Learning Bench, MetaAgent attains an average Normalized Performance Score of 0.83, reaching 97% of DataInterpreter's 0.86 while outperforming all other auto-designed methods (SPP: 0.16, AutoAgents: 0.00) and most human-designed frameworks (AutoGen: 0.77, MetaGPT: 0.45). On software development tasks, MetaAgent passes 85% of objective checkpoints on average, more than doubling MetaGPT's 35% and AutoAgents' 20%.

## Baselines & Comparisons

MetaAgent outperforms all prompt-based baselines on text tasks: CoT (0.74/0.44), CoT-SC (0.74/0.49), llm-debate (0.73/0.54), and Self-Refine (0.76/0.55) are all surpassed on both Writing and GPQA. Among auto-designed multi-agent methods, MetaAgent dramatically outperforms SPP (0.16 avg on ML Bench, 0.15 on Software) and AutoAgents (0.00 on ML Bench, 0.20 on Software), which lack tool integration and traceback. Against human-designed systems, MetaAgent beats AutoGen (0.77), OpenInterpreter (0.49), TaskWeaver (0.35), and MetaGPT (0.45 on ML Bench; 0.35 on Software) but falls slightly short of DataInterpreter (0.86 vs. 0.83 on ML Bench), the only baseline it does not surpass. On software development, MetaAgent's 0.85 checkpoint pass rate exceeds MetaGPT's 0.35 by over 50 percentage points, attributed to its FSM traceback mechanism enabling iterative bug-fixing that linear SOPs cannot support.

## Relation to Prior Work

This paper positions itself at the intersection of two lines of work: human-designed multi-agent frameworks (MetaGPT, ChatDev, DataInterpreter) that are scenario-specific and labor-intensive, and auto-design methods (SPP, AutoAgents, ADAS, Symbolic Learning) that lack tool integration, generalization, or require external training data. The key conceptual departure is framing the multi-agent system as a Finite State Machine, showing that linear pipelines, decentralized debates, and orchestrator-coordinated systems are all constrained special cases of an FSM with unrestricted state transitions, null-transitions, and per-state condition verifiers. Prior FSM-based agent work (StateFlow, State Machine of Thoughts) used hard-coded transition detection in fixed scenarios, whereas MetaAgent uses LLM-based natural-language condition verification and automatic state merging to make the FSM adaptable and generalizable across a task domain.

## Why It Matters / Open Questions

MetaAgent offers a practical, data-free recipe for automatically generating tool-enabled multi-agent systems that match or exceed human-designed baselines, which is significant for reducing the engineering cost of deploying LLM agents in new domains. The ablation results—particularly the 58.8% performance drop on software development without traceback and the 26–35% drop without state-merging optimization—highlight that iterative correction and structural simplicity are as important as the agents' individual capabilities. Open questions include whether the FSM abstraction scales to domains with highly dynamic or open-ended state spaces, whether the LLM-based state-merging heuristic can be replaced with more principled criteria, and how the framework performs when the foundation model is significantly weaker than GPT-4o (the GPT-3.5-Turbo executor results suggest fragility).
