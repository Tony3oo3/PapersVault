## Problem

Chain-of-Thought and Program-of-Thought prompting both suffer from 'reasoning hallucinations'—inconsistencies between the natural language reasoning steps an LLM reports and the actual logic in its generated programs. These hallucinations manifest as correct NL descriptions paired with buggy code, missing or irrelevant steps, and misordered operations, and they stem from the inherent ambiguity of NL and the token-prediction nature of LLMs that lack rigorous logical coherence. No existing test-time scaling framework systematically enforces alignment between the two representations of reasoning.

## Input / Output

The method takes a single natural-language problem specification (a math word problem or a code-generation task description) as input and produces a final numerical answer or a correct Python program as output. Uniquely, it also yields an intermediate aligned reasoning path: a sequence of logic units, each pairing executable code statements with a natural-language explanation that explicitly maps the code's behavior to the task specification. The framework requires no fine-tuning or external tools beyond a static analysis library for CFG construction, and operates entirely through multi-turn dialogue with the same LLM that generated the initial program.

## Method

RaLU is a three-stage test-time scaling framework that uses programs as logical skeletons and NL as explanatory content. In Logic Unit Extraction, the LLM generates an initial program, which is decomposed into atomic logic units via static analysis: a control-flow graph is built and partitioned at conditional blocks, loop boundaries, and function entries. In Logic Unit Alignment, an iterative stateful dialogue engages the LLM to judge each unit's correctness, explain its operations in NL relative to the task specification, and self-correct errors through a rewind-and-correct protocol where a fixed unit is re-validated against all previously verified units to prevent error cascades. In Solution Synthesis, the fully verified reasoning path is fed as conversation history to generate the final answer or program. The paper provides a Bayesian analysis showing that enforcing unit-level consistency systematically elevates the posterior probability of correctness, and a formal condition (γ_repair > P(unit correct | judged wrong)) under which self-repair is guaranteed to improve over the initial program.

## Results

RaLU achieves consistent improvements over the best-performing baseline across all benchmarks and three LLM backbones (DeepSeek-V3, Qwen2.5-72B, Llama3.3-70B). Headline gains over the strongest baseline are +1.22% on GSM8K, +2.07% on MATH-np, +6.60% on HumanEval+, and +2.17% on MBPP+ (averaged across models). The largest individual gains appear on code reasoning with Llama3.3-70B: +13.75% on HumanEval and +14.46% on HumanEval+. RaLU also outperforms the o1-preview model on HumanEval+ (0.902 vs. 0.890) and MBPP+ (0.833 vs. 0.802).

## Baselines & Comparisons

RaLU outperforms all eight baselines across every benchmark and LLM backbone. Against single-path methods (CoT, PoT), RaLU achieves an average improvement of +12.81% on math and +14.85% on code reasoning, attributed to its structured unit-level decomposition. Against multi-path exploration methods (Self-Consistency, ToT), RaLU gains +9.55% (math) and +10.69% (code) while using far fewer candidates (≤3 per unit vs. up to 10 paths). Against self-correction methods (Self-Refine, Self-Debug), RaLU gains +18.28% on average, as its proactive self-judgment stage prevents the common failure of introducing errors into initially correct responses. Against Self-Check, RaLU outperforms by 15.07% on average through unit-level iterative refinement that localizes errors before subsequent units are processed. Notably, RaLU with open-source models (DeepSeek-V3, Qwen2.5-72B) surpasses o1-preview on HumanEval+ (0.902 vs. 0.890) and MBPP+ (0.833 vs. 0.802), and outperforms GPT-4o on GSM8K (0.980 vs. 0.948) and MATH-np (0.821 vs. 0.697).

## Relation to Prior Work

RaLU sits at the intersection of Program-of-Thought (PoT), which offloads computation to generated programs, and self-correction/test-time-scaling methods (Self-Consistency, Tree-of-Thought, Self-Refine), which iteratively refine outputs. It departs from prior work in two key ways: (1) it uses static code analysis (CFG decomposition) to partition programs into atomic logic units rather than treating the program as a monolithic artifact or relying on NL step boundaries, and (2) it enforces bidirectional alignment between each code unit and its NL explanation through an iterative judge-explain-correct dialogue with a rewind mechanism, rather than applying holistic or end-to-end self-correction. The Bayesian framing of the alignment process and the formal condition for when self-repair improves correctness (Eq. 6) are new analytical contributions not present in prior self-correction literature.

## Why It Matters / Open Questions

RaLU addresses a concretely identified failure mode—'reasoning hallucinations' where NL rationales and generated code diverge—that prior CoT-PoT hybrids silently suffer from, and provides a structured, interpretable mechanism to detect and fix such misalignments at the unit level. The consistent gains across three open-source LLM families and both math and code benchmarks, including outperforming o1-preview on HumanEval+/MBPP+, suggest the approach is robust rather than model-specific. Limitations include a 15× token overhead relative to CoT, evaluation restricted to math and code tasks (where ground-truth verification is straightforward), and a Bayesian analysis that, while suggestive, relies on unverified assumptions about the asymmetry P(O|C) >> P(O|¬C). Open questions include whether the CFG-based decomposition generalizes to non-Python languages or to tasks without a natural program representation, and whether the alignment truly captures causal reasoning or merely enforces surface-level consistency.
