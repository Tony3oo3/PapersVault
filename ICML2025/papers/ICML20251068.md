## Problem

Despite growing interest in deploying LLM-powered agents for IT operations, no existing benchmark provides a comprehensive, real-environment platform for systematically evaluating agents across multiple IT personas (SRE, CISO, FinOps) with automated evaluation and partial scoring. Prior efforts like TrainTicket, AIOpsLab, and InsightBench are limited to single personas, synthetic data, or lack resolvable tasks and leaderboards, making it impossible to measure whether agents can actually handle production-grade IT automation before deployment.

## Input / Output

The agent receives a triggering event (e.g., 'High Error Rate on adservice') and interacts with a live Kubernetes environment running the OpenTelemetry Astronomy Shop demo, querying observability data (traces, logs, metrics) through specialized NL2* tools that translate natural language into executable commands. The agent must produce structured outputs—fault localization with propagation chains for SRE, policy-as-code artifacts and compliance verdicts for CISO, or cost anomaly rankings for FinOps—within a time budget, after which the evaluator compares the final environment state against ground truth using metrics like pass@1, NTAM, F1, MTTD, and MTTR.

## Method

ITBench formalizes each scenario as a tuple ⟨M, E, T, D⟩ (metadata, environment, triggering events, desired outcome) and models agent-environment interaction as a POMDP where the agent selects actions from a tool set plus a stop action, receiving partial observations of the environment state. The baseline agents are built on CrewAI with ReAct-style planning, Reflexion-based self-correction (syntax checking, semantic validation, LLM-as-a-judge), and ReWOO-style disaggregation of reasoning from observations. Specialized tools (NL2Kubectl, NL2Traces, NL2Metrics, NL2Logs, NL2SQL) compress the high-volume observability data into structured summaries to fit within LLM context windows. The evaluation framework supports partial scoring across intermediate reasoning steps (e.g., fault propagation chain accuracy via NTAM) rather than binary success/failure, and a leaderboard enables reproducible comparison across 102 scenarios spanning 42 SRE, 50 CISO, and 10 FinOps cases.

## Results

Across all three IT automation domains, state-of-the-art LLM-powered agents achieve low overall success rates: 11.4% for SRE (mitigation pass@1), 25.2% for CISO (overall pass@1), and 25.8% for FinOps (diagnosis pass@1, excluding anomaly detection). GPT-4o is the strongest model in SRE, achieving 13.81% diagnosis pass@1, 0.39 FL(NTAM), and 11.43% mitigation pass@1, substantially ahead of Llama-3.3-70B (3.10% diagnosis) and 8B models (<4%). For FinOps anomaly detection, GPT-4o reaches an F1 score of 0.6 and a ranking score of 0.5, while no model resolves any Hard-complexity scenario in any domain.

## Baselines & Comparisons

The paper evaluates four LLM backbones (GPT-4o, Llama-3.3-70B, Llama-3.1-8B, Granite-3.1-8B) for SRE and FinOps, and eight models (adding GPT-4o-mini, Mixtral-8x7B, Mistral-Large-2, Llama-3.1-405B) for CISO. GPT-4o dominates SRE, outperforming the second-best Llama-3.3-70B by over 4× on diagnosis pass@1 (13.81% vs. 3.10%) and 3.4× on mitigation (11.43% vs. 3.33%). In CISO, GPT-4o-mini narrowly edges GPT-4o on overall pass@1 (25.19% vs. 24.74%) and is faster (102s vs. 101s TTP), while both far exceed Llama-3.1-405B (12.46%) and all 8B models (<4%). For FinOps, GPT-4o leads on diagnosis (33% vs. 16.6% for Llama-3.3-70B) and anomaly detection F1 (0.6 vs. 0.4 for 8B models), though Llama-3.3-70B matches GPT-4o on data insights (29%). A consistent finding across all domains is that no model resolves any Hard-complexity scenario, and removing trace data drops GPT-4o's SRE mitigation from 11.43% to 2.86%.

## Relation to Prior Work

ITBench builds on the agentic architecture paradigm established by ReAct (Yao et al., 2023), Reflexion-style self-correction (Shinn et al., 2023), and reasoning-observation disaggregation (Xu et al., 2023), applying these techniques to IT operations agents. It departs from prior IT-ops benchmarks (TrainTicket, AIOpsLab, InsightBench, TSB-AD) by unifying multiple personas (SRE, CISO, FinOps) under a single framework with real Kubernetes environments, automated partial-credit evaluation, and a verified leaderboard—capabilities that no single prior benchmark provides. The paper explicitly positions ITBench as the IT-automation analogue of SWE-bench, aiming to fill the same gap of systematic, reproducible evaluation for a critical applied domain.

## Why It Matters / Open Questions

The benchmark reveals a stark gap: even GPT-4o resolves only ~11–26% of scenarios, and no model mitigates any Hard SRE scenario, underscoring that current LLM agents are far from production-ready for critical IT operations. Key open problems identified include reasoning under incomplete observability (removing traces drops GPT-4o mitigation from 11.4% to 2.9%), multi-agent orchestration for complex incidents, and safety guardrails for agent-executed commands. As an open-source, extensible framework with a leaderboard, ITBench is positioned to become the standard reference for the IT-automation agent community, analogous to SWE-bench's role in code agents.
