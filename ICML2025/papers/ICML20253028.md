## Problem

LoRA's weight-centric paradigm fails to capture modern fine-tuning formulations involving nonlinear perturbations, and its primary memory bottleneck has shifted from parameter storage to intermediate forward states, making 7B/8B model training infeasible on consumer GPUs (e.g., Nvidia 3090 with 24 GB). The paper asks whether memory can be pushed further down while simultaneously reducing computation time and preserving or improving performance.
![Teaser figure](../imgs/ICML20253028/cropped_page4_idx0.webp)

## Input / Output

The method takes frozen pre-trained transformer weights (ViT-B, RoBERTa-base/large, LLaMA2-7B, LLaMA3-8B) loaded in FP16 and a supervised fine-tuning dataset, and produces a small set of low-rank control matrices (rank r, stored in FP32) that are inserted as parallel edges across entire residual blocks. Unlike LoRA which attaches A·B pairs to individual Q/K/V/U/D linear layers, the control matrices operate on the block-level input state, so a single d×r and r×d pair replaces the 10rd parameters needed to LoRA-tune both FFN layers, and no intermediate activations within the block need to be retained for backpropagation.

## Method

The paper introduces a state-based fine-tuning (State-FT) framework that models the network as a directed acyclic graph and adds a learnable control term g(M, x_u) in parallel with the original block computation f(x_u; W), yielding x_v' = x_u + f(x_u; W) + M·x_u. By grouping all layers within a residual block (e.g., LayerNorm + two MLP layers of the FFN) into a single edge, the large intermediate state that LoRA must store for gradient computation is eliminated, cutting GPU memory by 30–40% and training time by 30–50%. The control function is a simple low-rank product (A·B·x), giving a control-affine structure that is provably at least as expressive as LoRA for deep linear networks (Theorem 4.1) and strictly more expressive for nonlinear blocks when the Jacobian is singular (Theorem 4.2). Two variants are evaluated: Parallel Control (tuning only the FFN block) and Double Control (tuning both attention and FFN blocks), with a hybrid option combining LoRA on Q/K/V with control on U/D.

## Results

On the Commonsense Benchmark with LLaMA2-7B, the DoubleControl method achieves an average score of 79.6 (vs. DoRA's 79.7) while using only 35.2 GB GPU memory (59% of DoRA's 59.6 GB) and 6h58m training time (47% of DoRA's 14h50m). On LLaMA3-8B, DoubleControl reaches 85.3 average (vs. DoRA's 85.2) with 45.3 GB memory (67% of DoRA) and 7h44m time (51% of DoRA). On GLUE with RoBERTa-base, Control achieves 86.14 average across 8 tasks, outperforming LoRA (85.62) and DoRA (85.38), while using 12.634 GB memory (1.4 GB less than LoRA, 3.7 GB less than DoRA) and 4m59s training time (10.2% faster than LoRA, 30.4% faster than DoRA). The method enables training 7B/8B models on a single Nvidia 3090 (24 GB) without quantization, using 20.7–22.2 GB memory.

## Baselines & Comparisons

Against LoRA, the proposed Control method wins on 7 out of 8 GLUE tasks (e.g., +2.05% on CoLA, +1.10% on MRPC for RoBERTa-base) and reduces GPU memory by 46.7% on ViT (12.28 vs 18.01 GB) and 10% on RoBERTa (12.63 vs 14.03 GB), while cutting training time by 38% on ViT and 10% on RoBERTa. On LLaMA2-7B, the hybrid Control(UD)+LoRA(QKV) variant surpasses LoRA by 2.4 points in average score (80.0 vs 77.6) while using 21 GB less memory. Against DoRA, Control is competitive or superior on accuracy (86.14 vs 85.38 avg on RoBERTa-base GLUE; 85.3 vs 85.2 on LLaMA3-8B) but the primary advantage is memory: DoubleControl uses only 59% of DoRA's GPU memory on LLaMA2-7B (35.2 vs 59.6 GB) and 67% on LLaMA3-8B (45.3 vs 67.3 GB), with roughly half the training time. The only loss is on STS-B with RoBERTa-base, where DoRA edges out Control by 0.19%. The paper also demonstrates that LoRA and DoRA are out-of-memory on a single Nvidia 3090 for 7B/8B models, whereas the Control methods train successfully at 20.7–22.2 GB.

## Relation to Prior Work

This paper generalizes the weight-centric PEFT paradigm (LoRA, DoRA, VeRA) into a state-based fine-tuning framework, showing that LoRA is a special case where control is restricted to individual linear-layer edges. It builds directly on Zhang et al. (ICML 2024), which first connected fine-tuning to control theory, by extending that connection from a single formulation to a general DAG-based framework where arbitrary edges (including multi-layer blocks) can be controlled. The key conceptual departure is the 'parallel control' design: instead of injecting low-rank updates into each weight matrix within a residual block, a single low-rank perturbation is applied across the entire block, exploiting the control-affine structure to decouple the adaptation from the nonlinear core dynamics.

## Why It Matters / Open Questions

The practical impact is significant: by identifying intermediate forward states (not parameters) as the true memory bottleneck, the method enables training 7B/8B LLMs on a single Nvidia 3090 (24 GB) without quantization, broadening access to PEFT research. Open questions remain about whether residual-block edges are the optimal tuning targets, whether edges outside the original computational graph could yield further gains, and whether a full theoretical analysis of the resulting control-affine system can provide convergence or expressivity guarantees beyond the linear-network and singular-Jacobian results presented here.
