## Problem

LLMs fine-tuned on tool usage become overreliant on tools for easy problems (incurring unnecessary computational cost) while still failing to invoke tools for genuinely hard problems (producing hallucinatory answers). No existing training method teaches LLMs to make adaptive, difficulty-aware decisions about when to reason internally versus when to call external scientific tools.
![Teaser figure](../imgs/ICML20251680/cropped_page1_idx0.webp)

## Input / Output

The method takes a scientific question (multiple-choice, numerical, or open-ended) and a set of tool APIs (physics simulators, PDE solvers, neural climate/epidemiology surrogates, or code interpreters) as input. At deployment, a single unified prompt P_i is used for all questions, so the model must implicitly decide whether to emit a direct solution or a JSON function-call trace; the output is either a self-contained answer or a sequence of tool invocations followed by a final answer. For open-ended questions (e.g., policy design), the output is a proposal or plan evaluated against domain-specific quantitative thresholds.

## Method

AWL is a two-component fine-tuning procedure. In World Knowledge Learning (WKL), the model is SFT'd on tool-generated solutions under a no-tool prompt P_n to internalize scientific knowledge. In Tool Usage Adaptation (TUA), questions are partitioned into easy/hard subsets based on the model's direct-answer accuracy after one WKL epoch; easy questions retain direct-answer targets while hard questions switch to tool-usage trace targets, all under a single adaptive prompt P_i. A combined loss J_Mix = J_WKL + J_TUA is optimized simultaneously (rather than alternating epochs) to prevent knowledge loss across prompts, and the easy/hard partition is recomputed at the start of each epoch. For open-ended questions, the pipeline is extended with DPO using preference pairs derived from ranked ensemble proposals, and the easy/hard criterion shifts from accuracy to a success-rate threshold.

## Results

On the 6 scientific benchmarks, the AWL-post-trained Llama-3.1-8B achieves 66.13% average answer accuracy (with intelligent tool usage prompt P_i), surpassing GPT-4o (57.50%), GPT-4o-mini (55.34%), Claude-3.5-Sonnet (54.51%), and Llama-3.1-70B (48.25%). Compared to the untrained base model (30.20% with P_n), AWL yields a 29.11% absolute gain in answer accuracy and a 12.72% gain in tool usage accuracy (63.93% vs. 51.21%). On the four custom-created datasets (Mujoco, PDE, Climate, Epidemiology), the AWL model outperforms all frontier closed-source models, while on public benchmarks (MATH, SciBench) the larger closed models retain an edge.

## Baselines & Comparisons

The AWL-post-trained 8B model (66.13% avg answer accuracy with P_i) outperforms GPT-4o (57.50%) by 8.63 points, GPT-4o-mini (55.34%) by 10.79 points, Claude-3.5-Sonnet (54.51%) by 11.62 points, and Llama-3.1-70B (48.25%) by 17.88 points on average. The advantage is most pronounced on the four custom datasets: AWL-Pi leads GPT-4o by 11.31 points on Mujoco, 9.16 on PDE, 47.50 on Climate, and 41.94 on Epidemiology, while GPT-4o still leads on MATH (82.94 vs. 62.35) and SciBench (71.67 vs. 34.17). For tool usage accuracy, AWL achieves 63.93% on average versus 49.28% (GPT-4o), 54.68% (GPT-4o-mini), 51.72% (Claude-3.5), and 50.71% (Llama-3.1-70B), indicating that frontier models make near-random tool-use decisions (~50%) while AWL learns meaningful difficulty-based switching. On open-ended questions (Climate, Epidemiology), AWL-RL with preference learning further improves constraint satisfaction to 49.16% and 56.25% respectively, surpassing GPT-4o (34.17%, 43.75%) and Claude-3.5 (31.51%, 36.25%) while reducing average tool calls per question from 7.21 to 2.70 (Climate) and 2.80 to 0.42 (Epidemiology).

## Relation to Prior Work

This paper builds on the LLM alignment literature (SFT and DPO) and the growing body of work on grounding LLMs with external tools (Toolformer, Gorilla, ToolLLM) and domain-specific scientific knowledge (ClimateGPT, BioGPT, Galactica). It departs from prior tool-use training, which typically forces models to always invoke tools and thus produces over-reliance, by introducing a two-component paradigm (WKL + TUA) that first internalizes tool-generated solutions and then trains adaptive switching based on the model's own accuracy. The combined loss J_Mix, which simultaneously optimizes under both the no-tool and intelligent-tool prompts within a single training objective, is a technical departure from the standard practice of alternating or re-weighting loss terms, motivated by the observation that knowledge acquired under one prompt does not transfer to another.

## Why It Matters / Open Questions

The paper addresses a practical tension in deploying LLMs for scientific work: the cost of always calling simulators versus the hallucination risk of never calling them. The 29% average accuracy gain and the ability of an 8B model to surpass GPT-4o and Claude-3.5 on four newly created, domain-specific datasets suggest that targeted post-training can close much of the gap to frontier models in specialized settings. Key limitations include the binary easy/hard partition (real problems exist on a spectrum), the need for domain-specific fine-tuning rather than a unified cross-domain approach, and the reliance on a relatively small 8B base model whose agent limitations (multi-hop tool interactions) remain the dominant error source after training. Open questions include whether the approach generalizes to multi-modal inputs, stepwise adaptive tool selection in long workflows, and whether the noise-robustness property (polluted questions being classified as 'hard' and routed to tools) can be exploited deliberately for data quality control.
