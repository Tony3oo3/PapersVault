## Problem

Existing PEFT variants like DoRA and VeRA sacrifice compute or memory efficiency to reduce learnable parameters, while representation-editing methods like ReFT show inferior performance and require non-trivial token-level intervention search. No prior method simultaneously achieves multi-faceted efficiency across parameters, representations, compute, and memory while matching or exceeding LoRA's performance.
![Teaser figure](../imgs/ICML20252111/cropped_page1_idx1.webp)

## Input / Output

The method consumes frozen pretrained Transformer weights (LLaMA-1/2/3 7B-8B for text, ViT-B/16 pretrained on ImageNet21k for vision) and generates fine-tuning weight residuals via two shared low-rank matrices. For NLP tasks, text sequences are processed to produce generated text (evaluated on GSM8k, MT-Bench, HumanEval, Commonsense170k); for vision tasks, RGB images are classified into fine-grained categories (FGVC, VTAB-1k). The unusual aspect is that the only learnable parameters are the shared (φ, ψ) pair, while all layer-specific adaptation is derived from the frozen pretrained weights themselves.

## Method

WeGeFT parameterizes fine-tuning weight residuals as Ŵ^l = W^l · (I + φ · ψ), where φ ∈ R^{d_in × r} and ψ ∈ R^{r × d_in} are low-rank matrices shared across all fine-tuned layers. This makes the update multiplicative and weight-aware: the layer-specific B^l in LoRA becomes W^l · φ (preserving layer identity through pretrained weights), while A^l becomes the shared ψ. The key insight is that pretrained weight awareness compensates for parameter sharing, enabling 4-8× fewer learnable parameters than LoRA without performance loss. Equivalently, WeGeFT acts as a token-agnostic representation edit (x̂ = x · (I + φ·ψ)^T) that eliminates ReFT's need for intervention-point search. In practice, a scaling factor α/r and dropout on W^l are applied, with ψ initialized to zeros and φ to Kaiming Uniform.

## Results

On GSM8k (trained on MetaMathQA), WeGeFT achieves 54.89% accuracy with only 0.068% trainable parameters, outperforming LoRA (42.08%), DoRA (53.07%), and even full fine-tuning (54.20%). On the Math10k benchmark with Llama 2 (7B), WeGeFT_din reaches 51.9% average accuracy across four arithmetic tasks using 0.052% parameters (8× fewer than LoRA r=16 at 52.8%), while WeGeFT_dout achieves 51.1% with just 0.016% parameters. On Commonsense170k with Llama 3 (8B), WeGeFT_din attains 87.7% average accuracy with 0.049% parameters, surpassing LoRA (86.3% at 0.392%) and DoRA (87.6% at 0.361%). On fine-grained visual classification (FGVC) with ViT-B/16, WeGeFT achieves 89.39% average Top-1 accuracy with 0.025M parameters, outperforming LoRA (88.71% at 0.147M) by 0.68% with 5.9× fewer parameters.

## Baselines & Comparisons

WeGeFT consistently outperforms LoRA and DoRA at 8× fewer parameters: on Math10k (Llama 2), WeGeFT_din achieves 51.9% avg accuracy vs. LoRA r=16's 52.8% (0.416% params) and DoRA r=16's 52.4% (0.429% params), while matching LoRA r=2 (51.5%) with the same 0.052% parameter budget. Against VeRA, WeGeFT wins on all tasks with fewer parameters and dramatically lower training cost (0.50h vs. 9.00h per epoch, 17.74GB vs. 20.65GB memory). VB-LoRA, despite using 16× more parameters (0.840%), underperforms WeGeFT by 4.5% on Math10k and 7.4% on Commonsense170k (Llama 3). Compared to ReFT variants (DiReFT, LoReFT), WeGeFT_dout achieves 51.1% vs. 42.9%/46.7% on Math10k with half the parameters and far lower GPU memory (17.71GB vs. 31.42/55.42GB). On instruction following (MT-Bench) and code generation (HumanEval), WeGeFT is on-par with LoRA-GA and DoRA (5.75 vs. 5.95/5.97; 19.39 vs. 19.81/19.75) while using 4× fewer parameters. On FGVC, WeGeFT beats LoRA by 0.68% Top-1 accuracy with 5.9× fewer parameters, and on VTAB it matches LoRA (74.1% vs. 74.0%) with the same parameter advantage.

## Relation to Prior Work

WeGeFT rethinks LoRA along three axes: making the fine-tuning residual explicitly dependent on pretrained weights (weight-awareness), sharing the low-rank factorization matrices (φ, ψ) across all layers rather than learning them per-layer, and replacing LoRA's additive update with a multiplicative one (Ŵ = W·(I + φψ)). This positions it as a unification of parameter-efficient fine-tuning (LoRA, DoRA, VeRA, VB-LoRA) and representation-efficient fine-tuning (ReFT/DiReFT/LoReFT), since the multiplicative weight-space update is algebraically equivalent to a token-agnostic representation-space edit. Conceptually, it draws on hypernetworks and neural functionals but is the first to use a frozen model's own weights as the sole input to a weight generator, eliminating the need for layer embeddings or vector banks used by Tied-LoRA and VB-LoRA.

## Why It Matters / Open Questions

The practical impact is significant: WeGeFT matches or exceeds LoRA with 4–8× fewer trainable parameters while preserving LoRA's compute and memory efficiency, avoiding the 5× wall-time penalty of DoRA or the 20× penalty of VeRA. The observation that weight-awareness yields larger gains with stronger pretrained models (Llama 3 vs. LLaMA-1) suggests the approach becomes more valuable as foundation models improve. Open questions include why the identity transformation outperforms all tested non-linear alternatives in the weight generator (the authors attribute this to optimization difficulty but lack a theoretical explanation), whether the approach scales beyond 8B models, and whether equivariant or more structured generator architectures could further improve performance.
