## Problem

In standard transformers, the residual stream dimension D determines how many features layers can store and access, but scaling D linearly increases both parameter count and FLOP count, making it impossible to independently expand the residual stream's 'memory bandwidth' without a proportional cost. This paper asks whether the residual stream can be restructured so that its size becomes a free scaling axis, decoupled from model size and per-example compute.

## Input / Output

The model takes a tokenized text sequence (one-hot vectors of vocabulary size V and sequence length N) and produces next-token logits over the vocabulary. Internally, rather than maintaining a single D-dimensional residual stream vector per token position, the RMT maintains a D_k × D_v residual matrix per token, where features are stored as key-value outer products and retrieved via tensor contraction with D_k-dimensional key vectors. The core attention and feed-forward computations still operate on D_v-dimensional data vectors, so the sequence-level computation graph mirrors the standard transformer.

## Method

The Residual Matrix Transformer (RMT) replaces the residual stream with an outer product memory matrix (Kohonen, 1972; Anderson, 1972), where each token position holds a D_k × D_v matrix built by summing outer products of key vectors and data vectors. In the attention layer, the standard W_Q, W_K, W_V, W_O matrices (each D_h × D) are replaced by D_k-dimensional key vectors that perform retrieval (tensor contraction over the first dimension) and storage (outer product association) operations on the residual matrix. The feed-forward layer retains its standard W_1, W_2 matrices but adds key-vector adapters to bridge between the residual matrix and the core FF computation. Because the QKV/O projections become vectors rather than matrices, the parameter and FLOP cost of increasing D_k (the residual stream key dimension) is negligible—less than 1% increase for a 100% expansion—enabling the residual stream to be scaled as an independent axis while holding model size and compute fixed.

## Results

The RMT achieves the transformer's minimum train loss (3.03) with 58% fewer FLOPS (4.97×10¹⁸ vs 1.18×10¹⁹), 25% fewer parameters (305M vs 405M), and 41% fewer training tokens (3.55B vs 6.04B). When trained on the same 6B tokens, the RMT reaches a lower train loss of 2.91 vs 3.03 and dev loss of 2.91 vs 3.02. On downstream tasks, the RMT outperforms the transformer on all benchmarks, e.g., LAMBADA perplexity 25.21 vs 61.34, WinoGrande accuracy 52.5% vs 49.5%, and HellaSwag 30.5% vs 28.7%, despite using 25% fewer parameters and 28% fewer FLOPS.

## Baselines & Comparisons

Against the standard Transformer (Vaswani et al., 2017), the RMT wins decisively on all efficiency metrics: 25% fewer parameters, 58% fewer FLOPS to reach the same loss, and 41% fewer tokens, while also achieving a lower final loss (2.91 vs 3.03) when given equal training data. Against the three residual-stream-modifying variants in Table 10, the RMT (134M params, residual stream 2048, final train loss 3.38) outperforms Hierarchical Aggregation (Dou et al., 2018; 165M params, loss 3.47), Depthwise LSTM (Xu et al., 2024; 233M params, loss 3.54), and Highway Transformer (Chai et al., 2020; 191M params, loss 3.41) on both parameter count and final loss. Notably, all three prior variants use more parameters and per-example compute than the standard transformer, whereas the RMT uses fewer of both, making its efficiency advantage more pronounced. The only metric where the RMT does not lead is wall-clock training time, where it is ~4% slower than the transformer due to unoptimized tensor contraction kernels replacing GEMM operations.

## Relation to Prior Work

The RMT builds directly on the standard Transformer (Vaswani et al., 2017) by replacing the residual stream vector with an outer product memory matrix, a mechanism dating back to Kohonen (1972) and Anderson (1972) correlation matrix memories. Conceptually, it follows the same strategy as Mixture-of-Experts (Fedus et al., 2022) in introducing a new scaling axis decoupled from per-example compute, but here the axis is residual stream bandwidth rather than sparse parameter count. It departs from prior residual stream modifications (Highway Transformer, Depthwise LSTM, Highway Networks) that manage or gate the residual stream without changing its dimensionality, and from the mechanistic interpretability framing of the residual stream as a 'memory bus' (Elhage et al., 2021) by making that memory bus explicitly expandable at near-zero cost.

## Why It Matters / Open Questions

The RMT introduces a genuinely new scaling axis for LLMs—residual stream size independent of model size and per-example FLOPS—which, if it holds at scale, could substantially reduce the compute and data required for frontier training. The 58% FLOP and 41% token efficiency gains at 405M parameters are compelling, but the experiments are limited to GPT-2-scale models and 6B tokens, leaving open whether the advantage persists at billions of parameters. The primary practical limitation is runtime: tensor contractions replace optimized GEMMs, making the RMT 4–43% slower per step, and the authors acknowledge that a custom CUDA kernel is needed before the efficiency gains translate to wall-clock savings. The approach is explicitly orthogonal to MoE, SSMs, and other architectural modifications, suggesting potential for combination.
