## Problem

LLMs are mathematically proven to hallucinate, making them unreliable for safety-critical applications, while Formal Methods provide rigorous correctness guarantees but suffer from steep learning curves, limited scalability, and heavy manual effort. This paper argues that neither paradigm alone suffices for trustworthy AI agents and advocates for a bidirectional integration where LLMs enhance FM accessibility and FMs certify LLM-driven behavior.
![Teaser figure](../imgs/ICML20253328/cropped_page8_idx1.webp)

## Input / Output

All user-facing inputs are natural language (system descriptions, informal proofs, specifications, or problem statements), requiring no formal-methods expertise. Internally, these are translated into formal representations (PAT models, Coq/Isabelle proofs, SMT-LIB formulas) and processed through iterative verification-refinement loops. Outputs are formally certified artifacts—verified system models, machine-checked proofs, SMT solutions, or trustworthy actions—alongside LLM evaluation test cases and runtime monitoring verdicts, ensuring every produced result carries a formal correctness guarantee.

## Method

The framework operates bidirectionally. In the LLM-for-FM direction, autoformalization agents decompose informal proofs into outlines, delegate algebraic steps to external tools (e.g., computer algebra systems), and iteratively refine; an LLM-enhanced model checking agent generates PAT models from natural language, receives error traces from the model checker, and corrects logical flaws in a feedback loop; and LLM agents improve theorem proving via semantic premise selection (generating natural-language lemma descriptions for retrieval) and proof generation with explicit proof intentions and dynamic knowledge retrieval. In the FM-for-LLM direction, SMT solvers ground LLM logical reasoning (with multi-LLM debate, mutation-based test generation, and solver-feedback self-correction); a metamorphic testing framework extracts fact triples from knowledge bases, applies logical inference rules to enrich them, constructs Q&A benchmarks, and classifies hallucinations via node/edge similarity; and runtime monitoring uses temporal-logic specifications to certify LLM behavior. A unified six-stage pipeline (autoformalization → model checking → theorem proving → SMT solving → LLM testing → LLM monitoring) chains these components, with LLMs serving as intelligent intermediaries that interpret verification feedback and iteratively refine outputs until all formal properties are satisfied.

## Results

This is a position paper without quantitative benchmark results or a main results table. The paper provides qualitative demonstrations: (1) a PAT-based model checking agent successfully detects a key-lock-in logic flaw in an LLM-generated car system model and iteratively corrects it to pass formal verification; (2) an LLM-Coq agent correctly formalizes and proves 'the sum of two even numbers is even'; and (3) a Z3-based SMT agent solves a three-person scheduling problem with self-correction of missing constraints. No accuracy, F1, or other numerical metrics are reported.

## Baselines & Comparisons

This position paper does not perform direct quantitative comparisons against named baselines. Instead, it argues conceptually against four alternative views (relying solely on natural language reasoning, expert systems, LLMs, or FMs) and positions the bidirectional LLM-FM integration as superior to each unidirectional approach. The paper's closest empirical contrast is the PAT agent example, where GPT-4o alone produces a logically flawed model (allowing the key to be locked inside the car), while the LLM+PAT loop detects the error trace and produces a verified-correct model. No head-to-head numerical comparisons against prior LLM-only or FM-only systems are provided.

## Relation to Prior Work

This position paper synthesizes two previously largely separate research threads: LLM-augmented formal methods (autoformalization à la Wu et al. 2022, SMT-solver-powered reasoning à la LogicLM/Pan et al. 2023, Sledgehammer-style premise selection) and formal-methods-based LLM verification (model checking, runtime monitoring, metamorphic testing). The key departure from prior work is the explicit bidirectional framing: rather than treating LLMs and FMs as one-way tools (LLMs assist FMs, or FMs verify LLMs), the paper argues both directions are necessary and proposes a unified six-stage pipeline (autoformalization → model checking → theorem proving → SMT solving → LLM testing → runtime monitoring) that has not been articulated as a single coherent framework in prior literature. The case studies (PAT agent, Coq agent, Z3 agent) are illustrative prototypes rather than systematic evaluations, positioning the paper as a direction-setting argument rather than an empirical contribution.

## Why It Matters / Open Questions

The paper addresses a genuine and growing tension: LLM hallucination is mathematically proven inevitable (Xu et al., 2024), yet FMs remain impractical for most developers due to steep learning curves and scalability limits. The bidirectional integration framing provides a concrete research agenda for the neural-symbolic AI community, and the six-stage pipeline offers a reusable architectural template. However, significant open questions remain: how to formally specify the nuanced, context-dependent behaviors of LLMs (the paper acknowledges this is extremely difficult), how the pipeline scales to large concurrent systems, and whether the trade-off between LLM adaptability and FM rigor can be resolved without reintroducing the very manual effort FMs were meant to eliminate. The case studies are small-scale and single-tool, so the generalizability claims (e.g., from PAT to PRISM/UPPAAL) remain unvalidated.
