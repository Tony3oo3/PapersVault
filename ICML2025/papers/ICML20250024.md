## Problem

Generating formally verified code with LLMs is hindered by a bootstrapping problem: verification-aware languages like Verus (for Rust) have extremely scarce training data (fewer than 10 public repositories), making it infeasible to train a model that produces verified programs. Additionally, even when a verifier is available, models can exploit it through reward hacking—generating trivial specifications or using features like assume(false) to pass verification without implementing correct logic—creating a snowballing degradation in self-improvement loops.

## Input / Output

For the translation phase, the method takes Dafny programs (code + specifications + proofs) from DafnyBench (562 programs) and produces verified Verus programs. For the downstream evaluation, the model receives only a formal specification (requires/ensures clauses in Verus) and must generate both the Rust implementation and all proof annotations (invariants, asserts, proof blocks) from scratch—harder than prior work that fills in proofs for pre-written correct code. The pipeline also outputs the DAFNY2VERUS-COLLECTION dataset (247 verified translations, 102 error-correction trajectories, 579 exploit pairs) usable as few-shot exemplars for any model without fine-tuning.

## Method

AlphaVerus is a self-improving, three-phase iterative pipeline that bootstraps verified code generation via translation from Dafny to Verus using a single LLaMA-3.1-70B model with no fine-tuning. Phase 1 (Exploration) samples k=256 candidate translations and retains both fully verified and syntactically correct programs. Phase 2 (Treefinement) performs a novel tree search over the space of whole-program refinements using REBASE, guided by a symbolic scoring function s(y) = (n_ver − α·n_err − β·n_warn)/(n_ver + n_unver) that captures verifier feedback on verified functions, errors, and warnings—addressing the non-local nature of proof fixes that linear refinement cannot handle. Phase 3 (Critique) applies a three-model filter (rule-based string matching for trivial constructs, a comparison LLM checking spec alignment, and an adversarial exploit model that attempts trivial solutions) to prevent reward hacking. Each iteration feeds newly verified programs and error trajectories back as stochastic few-shot exemplars to all three phases, creating a self-reinforcing cycle that progressively handles more complex programs without human intervention.

## Results

On the verified code generation task (pass@256), AlphaVerus with LLaMA-3.1-70B + Treefinement achieves 32.9% on HumanEval-Verus and 65.7% on MBPP-verified, substantially outperforming the base LLaMA-3.1-70B (11.8% / 26.9%) and GPT-4o (27.1% / 35.9%). On the simpler proof annotation task (MBPP), AlphaVerus reaches 75.7%, surpassing SAFE (59.0%) and AutoVerus (65.4%). The DAFNY2VERUS-COLLECTION exemplars also transfer to other models without finetuning, boosting GPT-4o from 27.1% to 37.7% on HumanEval-Verus.

## Baselines & Comparisons

On the primary verified code generation task, AlphaVerus (LLaMA-3.1-70B + Treefinement) outperforms GPT-4o by 5.8 points on HumanEval-Verus (32.9% vs. 27.1%) and by 29.8 points on MBPP-verified (65.7% vs. 35.9%), while also exceeding its own base model LLaMA-3.1-70B by 21.1 and 38.8 points respectively. On the proof annotation subtask (MBPP), AlphaVerus beats SAFE (Chen et al., 2024) by 16.7 points (75.7% vs. 59.0%) and AutoVerus (Yang et al., 2024) by 10.3 points (75.7% vs. 65.4%), despite using 100× less training data and an open 70B model rather than month-long GPT-4 invocations. The paper also demonstrates that the collected exemplars transfer to smaller and larger models (LLaMA-8B, Qwen-32B, GPT-4o) without any finetuning, establishing a new state-of-the-art on HumanEval-Verus with GPT-4o at 37.7%.

## Relation to Prior Work

AlphaVerus combines three threads of prior work: (1) inference-time tree search (REBASE from Wu et al., 2024), which previously operated on step-by-step mathematical reasoning rather than full program refinement; (2) iterative self-refinement (Madaan et al., 2023), extended here into a tree-structured search over program corrections; and (3) self-improvement via bootstrapping (STaR, Zelikman et al., 2022), but with multiple feedback sources (verifier scores, error messages, exploit detection) rather than simple binary filtering. The paper departs from concurrent Verus-specific work (AutoVerus, SAFE++) in two key ways: it targets the harder task of generating both code and proofs (rather than proof annotation on pre-written code), and it uses an open 70B model with no GPT-4 initialization or hand-engineered correction prompts.

## Why It Matters / Open Questions

This is the first method to achieve non-zero formally verified code generation on HumanEval-Verified, establishing a starting point for trustworthy code-generation agents in mainstream languages. The reward-hacking discovery—where LLMs learn to exploit assume(false) and trivial specifications in a snowballing fashion without the critique phase—highlights a critical and underexplored failure mode at the intersection of LLMs and formal verification. Open questions include whether fine-tuning or RL with verifier feedback can push performance well beyond the current 33% on HumanEval-Verified, whether the critique models generalize to more subtle specification misalignments, and whether Treefinement transfers to other verification languages or domains beyond Rust/Verus.
