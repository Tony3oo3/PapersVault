## Problem

Latent-space memory models like MemoryLLM compress past context into hidden-state memory pools but fail to retain knowledge beyond ~20k tokens, as dropped memory tokens are permanently discarded. Existing retrieval-based extensions (H2O, SnapKV) retrieve key-value caches per attention head and per layer, incurring high latency and GPU memory overhead. The paper asks whether long-term retention can be extended to 160k+ tokens without increasing GPU memory cost.
![Teaser figure](../imgs/ICML20252508/cropped_page2_idx0.webp)

## Input / Output

Input text is chunked into 512-token segments that are sequentially injected into the memory pool via an update process, compressing each chunk into 256 hidden-state vectors per layer. During generation, the model attends over 12,800 memory tokens (10,240 short-term + 2,560 retrieved from long-term memory) plus a 2,048-token generation context window to produce the answer. The long-term memory is stored on CPU and offloaded to GPU layer-by-layer, keeping peak GPU memory at ~18 GB (vs. ~32 GB for SnapKV baselines).

## Method

M+ augments MemoryLLM with a long-term memory (LTM) pool Θ that stores tokens evicted from the short-term memory θ during updates, capped at 150k entries per layer. A co-trained retriever—two two-layer perceptron projectors (f_q for query hidden states, f_k for memory tokens, both projecting to d/20 dimensions)—selects 2,560 relevant tokens from Θ per layer via dot-product similarity, requiring only 32 retrievals total (one per layer) rather than 1024 (per head × per layer). The retriever is trained with a contrastive objective that maximizes the dot-product distance between query hidden states and irrelevant memory tokens while minimizing it for relevant ones. Training uses a three-stage curriculum (fineweb-edu continual pretraining → SlimPajama 4k–64k long-document training → LTM-specific training) with multi-LoRA weights separating the update (write) and generation (read) pathways, built on Llama-3.1-8B.

## Results

M+ extends knowledge retention from under 20k tokens (MemoryLLM) to over 160k tokens while using only 12,800 memory tokens plus a 2,048-token generation window. On LongBench (8k/16k context), M+ achieves an average QA-F1 of 31.00/32.78, matching Llama-3.1-8B on 4 of 6 subtasks. In GPU memory, M+ (offload) consumes 17,973 MB, the lowest among all compared methods, versus 32,574 MB for Llama-3.1-8B-SnapKV and 30,423 MB for Llama-3.1-3B-128k. On the LongBook-QA benchmark (192k-token books), M+ consistently outperforms all baselines in QA-F1 while processing the fewest tokens.

## Baselines & Comparisons

Against MemoryLLM-7B, M+ achieves a substantial improvement: on LongBench the average QA-F1 rises from 24.08 to 32.78 (16k setting), and on SQuAD knowledge retention M+ recalls information injected beyond 160k tokens whereas MemoryLLM degrades past ~20k. Against Llama-3.1-8B-16k, M+ wins decisively on the long-context benchmarks (LongBook-QA and LongBook Event QA, both at 192k-token inputs) but trails on shorter LongBench tasks (32.78 vs. 35.81 average QA-F1), a gap the authors attribute to information loss from the random-dropping mechanism and limited cross-chunk attention. Against Llama-3.1-8B-SnapKV, M+ outperforms on both LongBook-QA and SQuAD knowledge retention, and uses roughly 35% less GPU memory (21,178 MB vs. 32,574 MB); SnapKV also underperforms the plain Llama-3.1-8B-16k on LongBook-QA. Against Llama-3.1-3B-128k, M+ achieves higher QA-F1 on LongBook-QA and Event QA, suggesting that a larger model with a tailored memory architecture outperforms a smaller model with a longer native context window under comparable GPU budgets.

## Relation to Prior Work

M+ extends MemoryLLM (Wang et al., 2024a), which introduced a 1B-parameter latent-space memory pool with per-layer cross-attention, by adding a long-term memory (LTM) mechanism that retains tokens evicted from the short-term pool and retrieves them via a co-trained contrastive retriever. This departs from KV-cache-based retrieval methods (H2O, SnapKV) that store and retrieve keys/values per attention head per layer, by operating on compressed hidden states and performing a single retrieval per layer for all heads. The multi-LoRA design—separating update (write) and generation (read) pathways—draws on the T5 observation that shared encoder-decoder weights can be suboptimal, applied here to the memory compression vs. retrieval distinction.

## Why It Matters / Open Questions

M+ extends knowledge retention from under 20k to over 160k tokens while maintaining comparable or lower GPU memory than baselines, making long-term memory practically deployable via CPU offloading. The co-trained retriever's efficiency (32 retrievals per query vs. 1024 for per-head KV methods) and its substantial outperformance over attention-based retrieval (M+-Attn) suggest that learned retrieval in latent space is a more scalable path than attention-score-based selection. Open questions include whether the approach scales to 128k+ contexts with larger models, how to reduce CPU-GPU communication overhead, and whether the slight performance degradation on shorter documents (vs. Llama-3.1-8B on LongBench) can be mitigated without sacrificing long-context gains.
