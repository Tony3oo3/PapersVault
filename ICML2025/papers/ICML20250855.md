## Problem

Parameter-efficient fine-tuning (PEFT) for agent tasks remains largely unexplored, and directly applying LoRA to agent fine-tuning yields performance significantly inferior to full-parameter fine-tuning. The core difficulty is that agent tasks require simultaneously mastering multiple distinct capabilities—reasoning, tool execution, and summarization—which is challenging for a single low-rank parameter matrix to capture effectively.
![Teaser figure](../imgs/ICML20250855/cropped_page1_idx0.webp)

## Input / Output

The model receives a user query, a role-specific system prompt, the accumulated execution trajectory (prior thoughts, actions, and environment observations), and a list of candidate functions with their schemas. Output is structured as a sequential multi-role pipeline: the reasoner emits a thought plus a next-role token (executor or summarizer), the executor emits a function name and typed parameters for invocation, and the summarizer emits a distilled natural-language response. All training data is unified into a JSON format containing the candidate function list, system prompt, and step-by-step execution trajectory.

## Method

MoRAgent decomposes agent capability into three roles—reasoner, executor, and summarizer—each implemented as a dedicated group of LoRA modules (a shared LoRA plus routed LoRAs, with 5/5/4 total LoRAs respectively, reflecting differing learning difficulty). A rule-based role-aware gate enforces mutual exclusivity so that at any token position only one role's LoRAs contribute a non-zero update, while learnable Top-K token-aware routers within each role select which routed LoRAs to activate. Training minimizes a composite objective combining cross-entropy loss, an auxiliary load-balancing loss inherited from Switch Transformers, and a novel orthogonal loss that penalizes Frobenius-norm similarity between LoRA weight pairs to encourage each LoRA to capture features in distinct directions. A multi-role data generation pipeline uses GPT-4o to fill in missing reasoning and summary content, DeepSeek-V3 for trajectory quality verification, and rule-based plus manual correction for executor reliability, yielding clean JSON-formatted training data across tool-use and math benchmarks.

## Results

On StableToolBench (DFS), MoRAgent-Llama (1.24B+0.16B) achieves a 54.5% pass rate (+44.5 over base) and 40.2% win rate (+25.2), while MoRAgent-Phi (3.82B+0.36B) reaches 58.7% pass rate (+14.2) and 46.7% win rate (+12.6). On BFCL, the average accuracy improves by 50.1% for Llama3.2-1B (27.5→77.6) and 17.9% for Phi3.5-mini (64.2→82.1). On GSM8K and MATH, MoRAgent-Qwen (1.54B+0.27B) achieves 68.5% and 45.5% respectively, improving by 13.8% and 12.0% over the best base configuration.

## Baselines & Comparisons

MoRAgent-Phi (3.82B+0.36B) surpasses the agent-specific ToolLLaMA-v2-7B on StableToolBench DFS (58.7 vs. 54.6 pass rate) despite using far fewer parameters. On BFCL, MoRAgent-Phi (82.1 avg) approaches but falls slightly short of ToolACE-8B (84.6) and GPT-4 (85.2), while MoRAgent-Llama (77.6) dramatically outperforms its base (27.5) by 50.1 points. In the head-to-head PEFT comparison on BFCL (Table 6), MoRAgent (77.6, 0.16B params) outperforms LoRA (65.5), DoRA (66.8), and even full-parameter SFT (76.0, 1.24B params) with only 13% of the trainable parameters. On GSM8K/MATH, MoRAgent-Qwen (68.5/45.5) beats both the with-packages (54.7/23.5) and without-packages (41.7/33.5) base configurations of Qwen2.5-1.5B-Coder, and also exceeds Llama-3.2-1B-it (52.6/29.2) and DeepSeekMath-7B (64.2/36.2) on both benchmarks.

## Relation to Prior Work

This paper sits at the intersection of two active research threads: parameter-efficient fine-tuning (LoRA, DoRA, QLoRA) and agent-specific model tuning (ToolLLM, AgentTuning, ToolACE, APIGen). It departs from prior multi-LoRA routing work (LoRAHub, MoA, MoLE, MoLA) by structuring the LoRA groups around agent-specific cognitive roles—reasoner, executor, summarizer—rather than treating them as interchangeable experts, and from multi-agent architectures (α-UMi, Mobile-Agent-v2) by implementing all roles within a single frozen backbone via specialized LoRA adapters rather than separate LLMs. The ReAct Reason+Action paradigm motivates the role decomposition, while the Switch Transformer auxiliary balance loss is repurposed for LoRA load balancing, and a novel orthogonal loss is introduced to reduce redundancy among routed LoRAs.

## Why It Matters / Open Questions

The practical significance is that agent capabilities can be injected into small open-source LLMs with only 0.16B–0.36B trainable parameters while preserving the base model's general capabilities, lowering the barrier to deploying agent systems on resource-constrained hardware. A notable open question is whether the fixed three-role decomposition generalizes to more complex or open-ended agent settings (e.g., multi-step planning with dynamic tool discovery), and whether the approach scales to 7B+ models where full fine-tuning is more feasible. The reliance on GPT-4o and DeepSeek-V3 for data quality control also raises reproducibility concerns for groups without access to such models.
