## Problem

Buyers of LLM inference services have no mechanism to verify the actual hardware and software stack used to serve their models, leaving them vulnerable to providers substituting cheaper GPUs or subtly different models. This paper formulates Hardware and Software Platform Inference (HSPI) — identifying the underlying GPU architecture and software configuration of a black-box model solely from its input-output behavior — and demonstrates that such identification is feasible.
![Teaser figure](../imgs/ICML20253002/cropped_page0_idx0.webp)

## Input / Output

HSPI-BI consumes crafted border images (224×224, integer pixels 0–255) or border text queries (random-word prompts via chat templates) and produces a predicted class label that differs across hardware configurations. HSPI-LD consumes model output logits — specifically the top-256 logits per generated token, flattened across 4 responses per training sample — and produces a multi-class label over the Cartesian product of GPU type, arithmetic mode, kernel implementation, and sharding strategy. For FP32 logits, each value is decomposed into its sign, exponent, and fraction fields, zero-padded, and treated as separate integer features for the SVM.

## Method

The core insight is that different GPU architectures and software stacks place identical computations in different equivalence classes (EQCs), producing subtle but systematic numerical deviations in model outputs. HSPI-BI crafts inputs at decision boundaries using a modified PGD procedure with a cross-entropy loss that maximizes divergence between two hardware configurations' predictions, requiring white-box access for gradient computation. HSPI-LD instead trains a linear SVM on the bit-level structure of FP32 logits (split into sign/exponent/fraction integers), requiring only forward-pass inference and no backward propagation, making it scalable to large LLMs. For language models, HSPI-LD is the primary method since HSPI-BI's PGD is unstable due to one-hot projection discontinuities and the memory cost of caching LLM activations for backpropagation. The classification task is decomposed into pairwise binary problems when the number of platforms is large, and label merging (collapsing software variants under a single GPU label) is shown to reduce the number of classes while preserving >98% accuracy.

## Results

In the white-box setting, HSPI-LD achieves 83.9% overall accuracy (random guess = 5.6%) on a 18-class classification task spanning 3 GPUs × 2 arithmetic modes × 3 kernel implementations, using only 256 requests per class. In a production SGLang deployment on cloud GPUs, HSPI-LD reaches 99.1% average accuracy across 16 hardware-software configurations. For quantization identification on LLMs (FP16, BF16, INT8-FD, HQQ-4bit), accuracy exceeds 99.5% per model. In the black-box setting, HSPI-LD achieves up to 3× random-guess accuracy (e.g., 60.3% vs. 25% random on quantized LLMs), while HSPI-BI achieves an average F1 of 0.345 across 7 unseen vision models (random F1 = 0.144).

## Baselines & Comparisons

The paper does not benchmark against a single external baseline method but positions itself against prior hardware-fingerprinting work by Schlögl et al. (2021), which achieved only 28.25% success rate in a remote (black-box) setting on CIFAR-10 using a two-phase CPU-only approach; HSPI-BI improves upon this with a single-phase PGD-based border-input generation and extends to GPUs and LLMs. Internally, HSPI-LD consistently outperforms HSPI-BI: HSPI-BI is unstable for LLMs due to PGD discontinuity and memory constraints, while HSPI-LD achieves >99.5% quantization accuracy and 83.9–100% GPU identification in white-box settings. Against random-guess baselines, HSPI-LD achieves 15× improvement in the 18-class white-box GPU task (83.9% vs. 5.6%) and up to 3× in black-box LLM quantization (60.3% vs. 25%). In the production SGLang evaluation (Table 6), HSPI-LD reaches 99.1% average accuracy, demonstrating that the method generalizes beyond naive inference setups to real serving frameworks with optimizations like RadixAttention and cache-aware scheduling.

## Relation to Prior Work

This paper extends the hardware fingerprinting line initiated by Schlögl et al. (ICASSP 2021, IH&MMSec 2021, NeurIPS 2023), who first showed that different CPU platforms produce distinct computational results (equivalence classes) and proposed boundary samples for identification. The key departures are: (1) shifting focus from CPUs to modern GPUs and their software stacks (CUDA versions, kernel implementations like FlashAttention, serving frameworks like SGLang), (2) introducing HSPI-LD, a method that requires no backward propagation and instead classifies hardware via SVM on logit bit distributions, and (3) applying the framework to large language models rather than only vision classifiers. The paper also distinguishes itself from black-box LLM model-identification work (Iourovitski et al., Pasquini et al.), which targets model family via semantic analysis, and from side-channel reverse-engineering (Hua et al., Gongye et al.), which assumes physical access to hardware.

## Why It Matters / Open Questions

HSPI offers a practical mechanism for LLM buyers to verify that providers are actually serving models on the advertised hardware, addressing a real transparency gap in the model-as-a-service market with implications for ML governance, security auditing, and supply-chain accountability. However, significant limitations remain: GPUs with matching compute capabilities (e.g., RTX8000 vs. RTX2080Ti) are indistinguishable, batch size must be controlled, and black-box transferability for LLMs is only modestly above random (22.7–60.3% vs. 25%). Open questions include whether subtle software-stack differences (e.g., FlashAttention v2 vs. v3) can be reliably distinguished, how providers might mitigate HSPI (random bit flips, noise injection), and whether the method generalizes to non-NVIDIA accelerators at scale.
