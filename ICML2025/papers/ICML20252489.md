## Problem

Previous federated black-box prompt tuning methods overlooked the substantial per-query cost of cloud-based LLM APIs, and no convergence analysis existed for federated discrete prompt learning. This paper asks: how many clients should be activated per round to minimize total LLM queries while still achieving convergence?
![Teaser figure](../imgs/ICML20252489/cropped_page1_idx0.webp)

## Input / Output

Each client holds a local dataset of text input sentences paired with class labels (e.g., GLUE tasks in k-shot format). The method produces an optimized discrete prompt sequence of length n, where each token is drawn from a vocabulary of N options via a Gumbel-Softmax-parameterized categorical distribution. The prompt is prepended to input sentences and sent to a cloud-based LLM (RoBERTa-large or GPT-3.5 Turbo), which returns token-level log-probabilities used as the loss signal; the client never accesses model weights or gradients.

## Method

FedOne degrades standard FedAvg by activating exactly one client per round (K*=1), a choice justified by a novel convergence analysis showing the minimum query count Q_ε(K*) = c[c₁√K* + c₂/√K*]² is monotonically increasing in K* over the feasible region. Each active client optimizes a Gumbel-Softmax-parameterized prompt using a mini-batch stochastic variance-reduced policy gradient (MB-SVRP) estimator, requiring I independent prompt samplings per update to reduce gradient variance. The theoretical result reveals that while more clients yield sublinear convergence gains, they incur linear query overhead to the LLM, making single-client activation the query-optimal strategy. The framework is validated on GLUE tasks with RoBERTa-large and on GPT-3.5 Turbo via the OpenAI API, where a template question is appended to extract target-label probabilities from the top-20 token outputs.

## Results

On the GLUE benchmark with RoBERTa-large, FedOne-GS-BDPL achieves the best average accuracy of 54.90 across seven NLP tasks, outperforming all federated prompt tuning baselines. On GPT-3.5 Turbo (a closed-source cloud LLM), FedOne-GS-BDPL reaches 64.28 average accuracy, surpassing the no-prompt baseline (59.64) by 4.6 points and the untrained prompt baseline (54.41) by 9.9 points. In terms of query efficiency, FedOne reduces LLM server queries from 20,000 (10-client FedAvg) to 2,000 (1-client FedOne) for BDPL, a 10× reduction, while maintaining comparable accuracy.

## Baselines & Comparisons

FedOne-GS-BDPL (54.90 avg) outperforms all federated prompt tuning baselines: it beats FedOne-PromptTuning (Lester et al., 2021) by 2.2 points, FedOne-P-Tuning v2 (Liu et al., 2021) by 0.2 points, and FedOne-BBT (Sun et al., 2022) by 1.4 points. Against In-Context Learning (Brown et al., 2020), FedOne-GS-BDPL gains 5.8 points on average, with particularly large margins on QQP (+16.8) and RTE (+7.8). The black-box methods (BDPL, GS-BDPL) generally match or slightly exceed the white-box federated methods (PromptTuning, P-Tuning v2), confirming that discrete prompt optimization is competitive without model access. However, all federated methods trail full Fine-Tuning (57.96) by 3–5 points, as expected given the constrained parameter budget. On GPT-3.5 Turbo, FedOne-GS-BDPL (64.28) surpasses FedOne-BDPL (61.67) by 2.6 points, validating the Gumbel-Softmax reparameterization for gradient estimation in the black-box setting.

## Relation to Prior Work

This paper extends Black-box Discrete Prompt Learning (BDPL, Diao et al., 2022) into a federated setting by combining it with Gumbel-Softmax reparameterization (Jang et al., 2016) for tractable gradient estimation and the FedAvg aggregation protocol (McMahan et al., 2017). Prior federated black-box prompt tuning work (Lin et al., 2023; Sun et al., 2023) treated the cloud LLM as a free oracle, ignoring per-query costs. The key departure here is a formal query-efficiency analysis that reveals the standard FL heuristic of activating more clients per round is actually suboptimal when each client incurs a non-negligible query cost to a cloud LLM API.

## Why It Matters / Open Questions

The result that K*=1 (FedOne) minimizes total query cost while preserving O(1/√T) convergence is a clean theoretical contribution that directly challenges the default assumption in federated learning that more participating clients always help. Practically, this matters for any deployment where per-client interaction with a cloud LLM is expensive (API billing, rate limits), and the framework enables edge devices with minimal compute to participate in prompt tuning. Open questions include whether the K*=1 optimum persists under more realistic cost models (e.g., variable per-query latency, batched API calls) and how the trade-off shifts when query costs are amortized across many local steps.
