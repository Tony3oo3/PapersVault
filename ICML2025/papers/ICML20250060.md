## Problem

Cryptic crossword clue solving is a demanding NLU reasoning task that prior LLMs handle poorly (7–8% for T5, ~27% for GPT-4o), largely because clues contain deliberately misleading surface readings and require proving an answer via wordplay rather than mere recognition. No existing system produces both a correct answer and a verifiable, human-interpretable proof of the wordplay logic, leaving the reasoning process opaque even when the answer happens to be right.
![Teaser figure](../imgs/ICML20250060/cropped_page0_idx0.webp)

## Input / Output

The system takes a single cryptic clue string, its letter-length pattern (e.g. '7'), and across/down orientation as input, and produces a solved answer word accompanied by an executable Python proof. The proof is a function of assert statements calling domain-specific functions (is_synonym, is_anagram, action_type, is_abbreviation, is_homophone) that encode each step of the wordplay; successful execution with zero assertion failures constitutes formal verification. Internally, the pipeline generates 20 candidate answers and up to 10 wordplay hypotheses per candidate before formalisation, so the final output is the single verified answer plus its line-by-line Python justification.

## Method

The pipeline has three stages, each using a 9B-scale model: (1) a LoRA-fine-tuned Gemma2-9B-base generates 20 answer candidates filtered against a crossword word list; (2) a second LoRA-fine-tuned Gemma2-9B-base, trained on ~16,800 annotated Wordplay examples, produces 10 definition/wordplay suggestions per candidate; (3) a formaliser LLM (Gemini-Flash or Gemma2-9B-it) translates each wordplay hypothesis into Python code via in-context learning with fewer than 10 few-shot examples, using a light-DSL of callable functions inside assert statements. A purpose-built verifier parses the generated Python AST line-by-line, evaluates each assert, and returns constructive hints (e.g. 'RA is an abbreviation for artist, artillery, …') on failure. The formaliser then iteratively rewrites the code (up to 2 rewrites) until all asserts pass, at which point the answer is declared proved. The key design choice is hypothesising answers before reasoning, which bakes re-hypothesisation into the process and avoids the early-fixation failure mode observed in chain-of-thought prompting; ablations confirm that the formalisation-and-verification step cannot be replaced by logprob-based ranking.

## Results

On the Cryptonite test set (Top-1 exact match), the Gemini-Flash Formaliser achieves 32.5% overall accuracy (46.7% Quick, 31.4% Hard), establishing a new state-of-the-art. The fully open-licensed Gemma2-9B-it Formaliser reaches 29.0% overall (46.7% Quick, 27.6% Hard), also surpassing the GPT-4o 5-shot baseline of 27.6%. A Bayesian IRT analysis estimates a 92% probability that the Gemini-Flash Formaliser genuinely outperforms GPT-4o on the same samples.

## Baselines & Comparisons

Against the rule-based solver of Deits (2022) (8.6% test accuracy), the Gemini-Flash Formaliser achieves a 4.2× improvement at 32.5%. Against the T5-large fine-tuned model from Efrat et al. (2021) (7.6%), the improvement is 4.3×. The most competitive comparison is with GPT-4o 5-shot (27.6% overall, 26.0% Hard): the Gemini-Flash Formaliser wins on overall (32.5% vs 27.6%) and Hard (31.4% vs 26.0%) but trails slightly on Quick (46.7% vs 47.4%), which the authors attribute to the frequency-based candidate model already performing very well on easier clues. The fully open-licensed Gemma2-9B-it Formaliser (29.0%) also edges out GPT-4o overall, demonstrating that a 9B local model pipeline can match or exceed a frontier proprietary model on this reasoning task. For partial correctness (Table 2), the paper's pipeline with 25% known letters (45.5% Gemini-Flash) surpasses the previously reported GPT-4T result of 33.7% from Saha et al. (2024).

## Relation to Prior Work

This paper adapts the Draft-Sketch-Prove pipeline (Jiang et al., 2023) from mathematical theorem proving to cryptic crossword solving, using Python as the formalisation language with a domain-specific light DSL of callable functions (is_anagram, is_synonym, action_type, etc.) wrapped in assert statements. It builds directly on the authors' prior workshop papers (Andrews & Witteveen, 2024; 2025) and draws on PAL (Gao et al., 2023) for code-as-reasoning and AlphaCodium/Self-Debug (Ridnik et al., 2024; Chen et al., 2024) for the iterative verifier-feedback loop. The key departure from prior cryptic crossword work (Deits 2015/2022 rule-based solvers; Saha et al. 2024 LLM prompting) is the introduction of a Python AST-based verifier that evaluates each assert line-by-line and returns constructive hints, enabling targeted re-formalisation rather than wholesale regeneration.

## Why It Matters / Open Questions

The system demonstrates that 9B open-licensed models with a verification pipeline can outperform GPT-4o on cryptic crossword solving (32.5% vs 27.6% Top-1 on Cryptonite test), while producing human-interpretable Python proofs for each solution — a property absent from black-box LLM outputs. Key limitations include the hard upper bound imposed by candidate answer generation (correct answer must appear in top-20), the weakness of the is_synonym function for distantly-related definitions, and verifier gaps (conditional execution, disconnected proofs). Open questions include whether reinforcement learning with outcome-only rewards (à la DeepSeek-R1) can improve the pipeline, whether the formal-verification approach generalises to other NLP reasoning tasks, and how to handle full-grid solving with crossing-letter constraints.
