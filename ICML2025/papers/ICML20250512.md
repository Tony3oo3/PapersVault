## Problem

Scaled dot-product attention in long-context LLMs requires accessing the entire KV cache for every generated token, creating a severe scalability bottleneck. While attention is naturally sparse—only a few pivotal tokens contribute significantly—existing methods to exploit this sparsity either use fixed/heuristic patterns that degrade quality, permanently discard tokens that may become critical later, or require substantial auxiliary memory (e.g., 128+ bits per token) to achieve reasonable recall. The paper identifies that pivotal token retrieval is fundamentally a Maximum Inner Product Search problem, but notes that SOTA MIPS solutions are GPU-unfriendly (graph-based) and fail due to the separated query and key distributions in attention.

## Input / Output

At inference time, HashAttention takes a query embedding and the full KV cache as input, and produces a set of top-k pivotal token indices along with the sparse attention output computed only over those tokens. The key-value pairs are pre-mapped to 32-bit integer signatures (packed into a single 32-bit word per token per attention head) that are cached alongside the KV cache, requiring only 32 bits of auxiliary memory per token per head. During the decoder hot path, the query is mapped to its own 32-bit signature, and Hamming distance is computed via a single XOR + popcount operation against all cached key signatures, making the SCORE step extremely fast and GPU-friendly.

## Method

HashAttention frames pivotal token identification as a recommendation problem and uses two independent learned feed-forward networks (φ_kv for keys, φ_q for queries) to map embeddings into a b-dimensional Hamming space via sign-based bit signatures. The SCORE function is simply the negative Hamming distance between the query signature and each key signature, computed as bitcount(XOR) on packed integers. The theoretical grounding shows that token importance (attention score × value norm) is equivalent to a MIPS problem, which reduces to cosine similarity search via asymmetric transformation, motivating the use of bit signatures for approximate nearest-neighbor retrieval. Training casts top-k token prediction as a multi-class binary cross-entropy problem with class-weight balancing for long contexts and tanh soft-partitioning during training (sign at inference), and the mappings are trained on generic data (OpenWebText) with optional task-specific fine-tuning to push sparsity from 16× to 32×. The implementation builds on vLLM's paged-attention with page size 1, using the retrieved indices directly in the attention kernel without physically gathering tokens, preserving GPU memory access efficiency.

## Results

On LongBench (512-token budget, 32 bits PTPA auxiliary memory), HashAttention achieves an average score of 64.15, surpassing the full model (63.55) and the oracle top-512 baseline (63.43). At 16× sparsity, HashAttention preserves model quality within 0.78 points on LongBench and 1.13 points on RULER@16K using Llama-3.1-8B-Instruct. With task-specific fine-tuning (HashAttention*), sparsity can be pushed to 32× with minimal quality loss, yielding up to 4.3× latency reduction in GPT-FAST, 2.54× in FlashDecode, and 3.12× end-to-end throughput improvement, all while using only 32 bits of auxiliary memory per token per attention head.

## Baselines & Comparisons

HashAttention (32 bits PTPA) outperforms all six baselines on average across LongBench. Against the closest competitors at the same 32-bit auxiliary budget, HashAttention beats Double Sparsity (64.15 vs. 61.88, +2.27 pts) and Quest (64.15 vs. 62.36, +1.79 pts), and even surpasses both at their 64-bit settings (DS: 62.78, Quest: 63.33). The KV-cache-discarding baselines H2O (43.47) and StreamingLLM (33.28) suffer severe quality degradation due to their fixed or heuristic sparsity patterns, losing 20+ points to HashAttention. InfLLM (47.87–48.23 at 256 bits) also underperforms substantially, as its page-level heuristic retrieval misses pivotal tokens. In the ablation comparing learned bit signatures to data-agnostic LSH (Gionis et al., 1999), HashAttention at 32 bits achieves 75.07 average on four LongBench datasets, while LSH at the same 32-bit width scores only 48.90 and still fails to match HashAttention even at 1024 bits.

## Relation to Prior Work

HashAttention builds on the well-established observation that SDPA exhibits token sparsity and the theoretical reduction of MIPS to cosine-similarity search (Shrivastava & Li, 2014; Neyshabur & Srebro, 2015), but departs from prior sparse-attention methods in two key ways. Unlike Double Sparsity (channel selection) and Quest/InfLLM (page-level block sparsity), it operates at token granularity using learned bit signatures in Hamming space, and unlike RetrievalAttention (graph-based MIPS on CPU), it is fully GPU-friendly via bitwise operations. The framing of pivotal-token identification as a recommendation problem with independent learned mappings for queries and keys is a novel conceptual bridge between information retrieval and attention sparsification.

## Why It Matters / Open Questions

The 16–32× KV-cache reduction at only 32 bits PTPA auxiliary memory, with quality drops under 1 point on standard benchmarks, makes long-context inference substantially more practical for deployment. The finding that token-level sparsity does not incur system inefficiency (contrary to common assumption) and that moderate sparsity can sometimes *improve* quality by filtering distractors are practically useful insights. Key limitations include the need for per-model training (and retraining for longer contexts), the exclusion of value vectors from the hash function, and the absence of evaluation in CPU-offloaded KV-cache regimes where the method's GPU-centric design may face different bottlenecks.
