## Problem

Parameter-efficient fine-tuning methods such as QLoRA and DoRA reduce memory consumption but do not reduce computational cost, and can even slow down training (e.g., DoRA is 20% slower than LoRA). Contextual sparsity has been shown to accelerate LLM inference, but it has not been applied to the fine-tuning process, where the workload involves multiple token sequences per batch rather than single-token auto-regressive generation.
![Teaser figure](../imgs/ICML20251168/cropped_page0_idx2.webp)

## Input / Output

The method consumes pre-trained LLM weights (LLaMA2-7B/13B, LLaMA3-8B), standard training text sequences, and an offline-computed rank-8 SVD decomposition of each base-model weight matrix (stored as ~30 MB of additional parameters). It produces standard LoRA adapters (rank 32, α=64) for the QKVO projections and, at each training step, dynamic per-batch channel sparsity masks that determine which weight channels participate in forward and backward passes. Sparsity is applied exclusively to the base-model main branch; the LoRA branch remains fully dense.

## Method

SparseLoRA introduces a training-free SVD sparsity estimator that projects batch inputs onto a low-rank SVD factorization of the frozen base weights to approximate oracle importance metrics—L2 norm of activations for FFN and VO projections, and element-wise product of Q and K L2 norms for QK projections—adding only 0.05% FLOPs and 0.8% runtime overhead. The selected top-k channels are then used to slice the weight matrices on the fly, enabling structured channel sparsity in the main branch while keeping LoRA adapters dense. Three sensitivity-driven design choices refine the sparsity: (1) non-uniform layer-wise ratios where deeper layers receive higher sparsity, (2) context-output aware splitting that applies sparsity only to context tokens while keeping output tokens dense, and (3) progressive scheduling where the first 10% of training steps run fully dense before switching to sparse computation. Together these yield up to 2.2× FLOPs reduction and 1.6× wall-clock speedup with negligible accuracy loss across commonsense reasoning, math, code generation, and instruction-following benchmarks.

## Results

On the CSR170K commonsense reasoning benchmark (8 datasets), SparseLoRA achieves 81.8% average accuracy on LLaMA2-7B using only 65% of LoRA's FLOPs with a 1.3× speedup, and 86.9% on LLaMA3-8B at 65% FLOPs. On the Math10K arithmetic reasoning benchmark, SparseLoRA reaches 81.1% average accuracy on LLaMA3-8B while reducing FLOPs to 46% and achieving a 1.6× wall-clock speedup. Across all tasks (commonsense, math, code generation, instruction following, GLUE, ARC-AGI), SparseLoRA delivers up to 2.2× computational cost reduction and up to 1.6× speedup while maintaining accuracy within ~0.5% of dense LoRA.

## Baselines & Comparisons

Against LoRA (the primary baseline), SparseLoRA matches or slightly underperforms on accuracy by ≤0.5% on average (e.g., 81.8 vs. 82.3 on LLaMA2-7B CSR170K; 81.1 vs. 81.0 on LLaMA3-8B Math10K) while reducing FLOPs by 35–54% and achieving 1.2–1.6× wall-clock speedup. Against QLoRA, SparseLoRA achieves comparable accuracy (86.9 vs. 87.1 on LLaMA3-8B CSR170K) but is significantly faster (1.3× vs. 0.9× speedup), since QLoRA's quantization overhead slows training. Against DoRA, the advantage is stark: DoRA actually increases FLOPs to 132% and slows training to 0.7–0.8×, whereas SparseLoRA reduces FLOPs to 65% and accelerates to 1.3×. Against GaLore (Appendix A.4), SparseLoRA achieves 0.78× runtime vs. GaLore's 1.58× (13.72× amortized with periodic SVD updates) while matching or exceeding accuracy (87.0 vs. 84.1 on CSR170K). Notably, on LLaMA2-13B CSR170K, SparseLoRA actually outperforms LoRA in accuracy (85.0 vs. 84.7) while using only 61% of the compute.

## Relation to Prior Work

SparseLoRA extends the contextual sparsity paradigm from Deja Vu (Liu et al., 2023b), which exploited input-dependent activation sparsity to accelerate LLM inference, into the fine-tuning setting for the first time. It builds on LoRA as its base PEFT method but departs from the broader PEFT lineage (QLoRA, DoRA) that reduces memory without reducing computation, and from prior sparsity-accelerated training methods that rely on static patterns, unstructured sparsity, or learned predictors. The key methodological departure is a training-free SVD-based sparsity estimator that replaces the learned look-ahead predictors used in inference-time sparsity, enabling dynamic channel selection during training with negligible overhead.

## Why It Matters / Open Questions

This work addresses a practical gap: PEFT methods like QLoRA and DoRA reduce memory but can actually slow down fine-tuning (DoRA is 20% slower than LoRA), while SparseLoRA achieves up to 2.2× FLOPs reduction and 1.6× wall-clock speedup with near-lossless accuracy across diverse tasks. A key open question is the manual per-model, per-dataset sparsity configuration (Table 13), which limits plug-and-play deployment; automating sensitivity-aware sparsity allocation would be a natural next step. The approach is also orthogonal to memory-efficient techniques (quantization, gradient checkpointing), suggesting composability for truly resource-constrained fine-tuning pipelines.
