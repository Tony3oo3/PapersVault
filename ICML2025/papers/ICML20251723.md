## Problem

Research in RL, MARL, CRL, and embodied AI is constrained by a dilemma: computationally efficient environments (e.g., 2D grids like Craftax) lack 3D spatial reasoning challenges, while rich 3D platforms (e.g., MineDojo on Minecraft) are closed-source, prohibitively slow (~72 steps/s), and offer limited customization or no multi-agent support. No existing framework simultaneously provides full 3D voxel worlds, programmatic environment creation, multi-agent support, and high computational throughput.

## Input / Output

Environments are defined by a Lua mod (configuration file + script) specifying world generation parameters, reward functions, and termination conditions, while agents interact via a default action space of 21 binary keyboard actions plus a continuous mouse tuple (Δx, Δy) ∈ [-1,1]², which can be reduced to a minimal discrete subset via BinaryActionWrapper or DiscreteActionWrapper. Observations are first-person RGB images (default 64×64, customizable up to 512×512), accompanied per-step by a scalar reward, termination/truncation flags, and an info dictionary. The framework exposes standard Gymnasium (single-agent) and PettingZoo (multi-agent) APIs, making it drop-in compatible with libraries like stable-baselines3, CleanRL, and Ray RLlib.

## Method

Craftium is built on a modified Luanti C++ voxel game engine (not a video game), with a Python environment interface that maintains per-agent communication channels to the Luanti server. The key architectural choice is leveraging Luanti's Lua Modding API for programmatic environment definition—reward functions, episode termination, and world mechanics are all expressed in Lua scripts—rather than restrictive DSLs or predefined parameter sets. Engine modifications include: translating Python-sent actions into virtual keyboard/mouse events, adding RL-specific API functions (set_reward, set_termination, soft-reset), implementing optional synchronous client-server updates to prevent desynchronization with slow agents (e.g., LMMs), and soft-resetting episodes without reinitializing the engine. This design yields 2746 steps/s in single-environment mode and over 12K steps/s with 16 parallel asynchronous environments, while supporting vast 64K×64K×64K-block open worlds and multi-agent scenarios—capabilities absent in all prior 3D frameworks.

## Results

Craftium achieves 2746.69 ± 230.41 steps/s in single-environment benchmarks, outperforming MineDojo (71.87 ± 11.82 steps/s) by 38× and exceeding VizDoom (2091.91 ± 59.03 steps/s) by ~31%. In parallel (16 asynchronous environments), Craftium surpasses 12K steps/s on the same hardware (NVIDIA A5000 + Intel Xeon Silver 4309Y). Memory usage is 660 MB per environment, compared to 1.7 GB for MineDojo and 84 MB for VizDoom. In learning experiments, PPO solves the ChopTree task (6+ trees/episode), PPO+LSTM and LLaVa-Agent (zero-shot) both progress through the open-world skills tree, and FT-L2 demonstrates forward knowledge transfer in the procedural CRL dungeon sequence.

## Baselines & Comparisons

Against MineDojo (the only other framework offering comparable 3D richness and open-world capability), Craftium achieves a 38× speedup (2746.69 vs. 71.87 steps/s), primarily due to Luanti's C++ implementation versus Minecraft's Java 8, the absence of Xvfb/X11 overhead, and the ability to strip irrelevant game components via the open-source engine. Against VizDoom, Craftium is ~31% faster in single-environment mode (2746.69 vs. 2091.91 steps/s) while offering true 3D (VizDoom is 2.5D), full multi-agent support, and open-world capability—features VizDoom lacks entirely. In the parallel asynchronous setting, Craftium reaches over 12K steps/s with 16 environments, matching or exceeding VizDoom's throughput despite its greater scene complexity. MineDojo does not support parallel environments at all, making it impractical for on-policy methods like PPO that rely on vectorized rollouts. In the open-world embodied AI comparison, the zero-shot LLaVa-Agent outperforms PPO+LSTM by unlocking more skills tree milestones (collect wood and stone vs. only collect wood), demonstrating Craftium's utility beyond standard RL benchmarks.

## Relation to Prior Work

Craftium builds on the established paradigm of environment creation platforms for RL (ALE, VizDoom, MineDojo, MiniHack) but departs from them in two key architectural choices: it is based on an open-source game engine (Luanti, C++) rather than a closed-source video game (Minecraft, Java) or a 2D/2.5D renderer (ZDoom, NetHack), and it uses a general-purpose scripting language (Lua) instead of domain-specific languages (ZScript, des-file format). This lineage positions it alongside Griddly and MiniGrid in spirit (flexible, programmable environment creation) but extends the capability to fully 3D voxel worlds with multi-agent support, a combination absent from all prior frameworks. The Gymnasium and PettingZoo interface choices align it with the current standard ecosystem (stable-baselines3, CleanRL, Ray RLlib, skrl).

## Why It Matters / Open Questions

The paper addresses a persistent bottleneck in autonomous agent research: the tradeoff between environment richness and computational efficiency that has constrained CRL, MARL, UED, and open-endedness to either simplistic 2D grids or prohibitively expensive Minecraft-based 3D worlds. By achieving 38× the throughput of MineDojo while supporting fully 3D, multi-agent, open-world scenarios, Craftium makes large-scale experiments in these compute-sensitive areas practically feasible on standard hardware. Key limitations include the agent count being capped at CPU core count (16 in experiments), a ~30% performance drop when enabling full world complexity (biomes, procedural generation), and the fact that the illustrative examples use fixed hyperparameters without tuning, so the RL results are demonstrative rather than competitive. The open question of whether the Luanti-based approach can scale to hundreds of agents in massively multi-agent settings remains unresolved.
