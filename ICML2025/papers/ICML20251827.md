## Problem

LLMs exhibit strong pre-training biases toward specific solutions (e.g., random forest) when solving ML tasks, limiting the diversity of approaches explored and preventing discovery of superior alternatives. Existing agentic frameworks either overfit to narrow task workflows or require curated repositories of human expert insights (as in DS-Agent's Kaggle-based case bank), making them impractical for most domains. The paper asks whether a structured reasoning strategy can force LLMs to systematically enumerate and explore diverse options without external expert knowledge.

## Input / Output

The system takes a natural-language task prompt and a training dataset as input, optionally augmented by a case bank of previously generated FoO networks retrieved via cosine similarity of task embeddings. The Planner LLM generates a step-by-step task plan that is then filtered to the most accuracy-relevant steps (n=2 for DS tasks, n=3 for TDC tasks), constraining the FoO depth. Output is executable ML code (generated by converting a FoO walk into code, reflectively debugging, and executing), a scalar performance metric R, and the updated FoO network stored in the case bank for future retrieval and adaptation.

## Method

Flow-of-Options (FoO) is a fully-connected directed acyclic graph where each depth corresponds to a task step and nodes represent k diverse options generated by an LLM conditioned on the task, current step, and prior-step options. The fully-connected structure (every option at depth i−1 links to every option at depth i) is the key architectural choice, enabling exploration of all cross-step combinations that tree-structured methods (SELA) or non-enforced DAGs (Data Interpreter) cannot guarantee. Walks through the FoO are generated via beam search with annealed beam width (starting at b=k, halving in later iterations to encourage exploitation of high-valued combinations), and edge values are updated via max propagation after each walk is converted to code, executed, and scored. An LLM-based consistency checker validates each walk for internal contradictions (e.g., referencing different models at different steps), implicitly pruning ~22.8% of invalid paths. Case-Based Reasoning is integrated by storing FoO networks in a case bank; for new tasks, the closest case is retrieved and an Adapter LLM modifies the FoO and task plan (e.g., regression→classification), enabling the system to build on prior explorations with 'memory' of past options. The entire pipeline operates as test-time computation with no fine-tuning, using GPT-4o as the base LLM, with per-task costs under $1.

## Results

On 16 general data science tasks, the FoO-based framework achieves an average rank of 1.44 (best possible: 1.0, worst: 7.0), representing a 38.2%–69.2% rank improvement over all baselines. On 17 TDC ADME-Tox therapeutic chemistry tasks, it achieves an average rank of 1.47 (37.4%–47.9% improvement). Deployment cost is under $0.03 per task and under 1 minute, while development costs remain under $1 per task using GPT-4o.

## Baselines & Comparisons

The FoO framework outperforms all seven baselines on average rank across both task suites. Against the closest competitor, Data Interpreter (avg. rank 2.33), FoO wins on 15/16 DS tasks; DI also failed to produce working code in 1 of 3 runs for 5/16 tasks and relied on highly specific hand-crafted prompts. DS-Agent (rank 3.69) and Autogen/Zero-shot (rank 3.19) are clearly outperformed, with FoO achieving substantially lower error on regression tasks (e.g., WB MAE 182 vs. 263–322) and higher accuracy on classification (e.g., ES AUROC 0.98 vs. 0.40–0.80). SELA (rank 4.17) is the slowest baseline (~21 min average) due to expensive MCTS rollouts, while AutoGluon (rank 4.67) cannot handle non-tabular or forecasting tasks. On TDC ADME-Tox tasks, FoO (rank 1.47) beats the specialized DeepMol AutoML system (rank 2.35) by 37.4%–47.9%, and on computationally intensive tasks (~100× data), FoO achieves rank 1.0 vs. Autogen 1.3 and Zero-shot 2.0.

## Relation to Prior Work

Flow-of-Options (FoO) bridges two research threads: thought-based LLM reasoning (Chain-of-Thought, Tree-of-Thoughts) and agentic ML automation (DS-Agent, Data Interpreter, SELA). Conceptually, FoO departs from SELA's tree+MCTS formulation by using a fully-connected DAG with max-update propagation, arguing that MCTS is overkill for AutoML where a 'poor' rollout of one feature-model pair shouldn't penalize the feature itself. It also departs from Data Interpreter's LLM-generated DAGs by constructing the network without LLMs (guaranteeing acyclicity and full connectivity) and from DS-Agent's reliance on curated human-insight repositories by treating the LLM's intrinsic knowledge as a sufficient proxy, compressed into interpretable FoO structures rather than long-form solution descriptions.

## Why It Matters / Open Questions

The paper demonstrates that explicitly forcing LLMs to enumerate diverse options at each step of a task plan can overcome the strong pre-training biases (e.g., defaulting to Random Forest) that limit solution quality in agentic ML systems, yielding 38–69% rank improvements on data science tasks and 37–48% on therapeutic chemistry tasks at under $1 per task. The generalization beyond tabular ML to reinforcement learning, image generation, clustering, machine translation, and combinatorial optimization broadens the practical scope. Key open questions include: whether the naive walk sampling can be replaced with more informed strategies, how to handle tasks lacking a clear evaluation metric, whether nested FoO (reasoning over task decompositions themselves) can capture multi-plan reasoning, and whether the residual Random Forest bias can be further reduced. The framework's dependence on GPT-4o-level code generation and the assumption of an available scoring metric limit immediate applicability to all domains.
