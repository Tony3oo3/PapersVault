## Problem

Existing evaluations of LLM coding capabilities rely on static, interview-style benchmarks (e.g., HumanEval, LiveCodeBench) or chat-based preference platforms (e.g., Chatbot Arena) that do not reflect how developers actually use code assistants in integrated IDEs. No prior platform collects human preferences on code completions within a developer's real workflow, with real tasks, diverse programming languages, and realistic code structures such as fill-in-the-middle infilling.
![Teaser figure](../imgs/ICML20250398/cropped_page0_idx0.webp)

## Input / Output

The system consumes the active code file from a developer's VSCode editor, extracting a prefix (and optionally a suffix for FiM tasks) as context, with median context length around 1.6k characters and 95th percentile reaching 18k characters across 103 programming languages and 19 natural languages. It produces two paired inline completions from different LLMs displayed simultaneously in a Git-Diff-style stacked view; the user's acceptance of one completion (via Tab or Shift+Tab) constitutes a preference vote. Aggregated votes feed a Bradley-Terry model that outputs a ranked leaderboard with 95% bootstrap confidence intervals.

## Method

Copilot Arena is a VSCode extension with three core components: (1) a user interface that presents two completions head-to-head with randomized ordering to eliminate position bias, (2) a model sampling strategy that minimizes expected pairwise latency by modeling the max-latency distribution as log-normal and optimizing a softmax distribution over model pairs with a temperature parameter (τ=5–10) to balance latency reduction against coverage of all model pairs, achieving a 33% median latency reduction, and (3) a Snip-It prompting scheme that enables instruction-tuned chat models to perform fill-in-the-middle tasks by prompting them to repeat portions of the prefix and suffix in their output, then post-processing to strip overlapping segments, improving pass@1 in 93% of model-template conditions (e.g., Claude-3.5-Sonnet from 56.1% to 73.0%). Rankings are computed via a Bradley-Terry logistic regression with style ablations controlling for latency and completion length.

## Results

Copilot Arena collected 11,604 pairwise votes from 1,642 users over 3 months, serving 4.5M+ suggestions from 10 LLMs. The Bradley-Terry leaderboard places DeepSeek Coder (β=0.07) and Claude 3.5 Sonnet (β=0.06) in the top tier, with Codestral (β=0.00) close behind, while Qwen-2.5-Coder (β=-0.13) and GPT-4o-mini (β=-0.15) rank lowest. The Spearman rank correlation between Copilot Arena and Chatbot Arena (coding) is r_s=0.62, with Chatbot Arena (general) at r_s=0.48, but drops to r_s≤0.1 against all static benchmarks (LiveBench, LiveCodeBench, BigCodeBench). The Snip-It prompting method improved FiM pass@1 in 93% of model-template conditions (e.g., Claude 3.5 Sonnet: 56.1%→73.0%; Llama-3.1-70B: 7.4%→49.0%), and the latency-optimized sampling strategy reduced median experienced latency by 33% (1.61s→1.07s).

## Baselines & Comparisons

Copilot Arena's rankings show the strongest agreement with Chatbot Arena (coding subset, r_s=0.62) and moderate agreement with Chatbot Arena (general, r_s=0.48), confirming that human-preference-based evaluations capture overlapping signals. In stark contrast, correlations with all three static benchmarks—LiveBench, LiveCodeBench, and BigCodeBench—drop to r_s≤0.1, indicating that static coding benchmarks measure fundamentally different capabilities than in-the-wild code completion. Smaller models (GPT-4o-mini, Qwen-2.5-Coder-32B, Gemini-1.5-Flash) systematically overperform on static benchmarks relative to their Copilot Arena rank, while larger models show mixed shifts. Task category drives the largest preference variation (28 significant win-rate changes, 31.1% of all possible pairs), whereas programming language has minimal effect (only 6 changes, 6.6%), suggesting models generalize well across languages but not across task types. Notably, models explicitly trained for fill-in-the-middle (DeepSeek Coder, Codestral) do not gain a measurable advantage on FiM tasks in Copilot Arena, implying users evaluate code quality and usefulness beyond formatting.

## Relation to Prior Work

This paper extends the live preference evaluation paradigm established by Chatbot Arena (Chiang et al., 2024) from chat-based interactions to IDE-integrated code completion, addressing a gap where existing evaluations either use static benchmarks (HumanEval, LiveCodeBench) or chat-based human feedback that deviates from real development workflows. The Bradley-Terry ranking framework is carried over directly from Chatbot Arena, while the model prompting component builds on fill-in-the-middle (FiM) prompt templates from Gong et al. (2024) and Fried et al. (2023), introducing the Snip-It post-processing technique to bridge the gap between instruction-tuned chat models and infilling tasks. The paper departs from prior user studies of coding assistants (Mozannar et al., 2024b; Izadi et al., 2024) by scaling to 10 state-of-the-art models and 1,642 users over 3 months, and from static benchmarks by capturing 103 programming languages, 19 natural languages, and diverse real-world code structures.

## Why It Matters / Open Questions

The finding that Copilot Arena rankings show low Spearman correlation (≤0.1) with most static code benchmarks while correlating moderately with Chatbot Arena (r_s=0.62) challenges the assumption that static benchmarks adequately predict real-world code assistant quality, with smaller models appearing to overperform on static evaluations relative to in-the-wild preferences. The observation that task type (frontend/backend vs. algorithm design) drives 31% of significant win-rate changes while programming language drives only 6.6% suggests models may be overfit to competition-style problems. Open questions include whether training code models on human preference data (as the authors advocate) would close the gap, whether the findings generalize beyond the 10 models evaluated, and how to incorporate GitHub Copilot (unavailable via API) into such evaluations. The Snip-It prompting technique, which improves FiM pass@1 in 93% of conditions, is a practical contribution for deploying instruction-tuned models in code completion settings.
