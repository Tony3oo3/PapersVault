## Problem

Constrained decoding with context-free grammars guarantees LLM outputs conform to structural formats (JSON, DSLs, semantic queries), but existing engines incur significant overhead because the Earley parser must evaluate all vocabulary tokens at every decoding step and accumulates redundant 'dead' parsing states that waste memory and trigger cache misses. The paper identifies that many intermediate Earley states become obsolete once subsequent parsing no longer references their start positions, yet standard implementations retain them throughout the entire decoding process.

## Input / Output

At each autoregressive decoding step, Formatron consumes the LLM's raw logits vector over the full vocabulary, the target CFG, and the already-generated token prefix, and produces a binary logits mask that sets invalid tokens to −∞ before softmax sampling. A key design feature is the state cache: because dynamic pruning yields compact, canonical Earley state representations, multiple different input token sequences can converge to the same cached state, enabling cross-query cache hits that reduce repeated parsing work without sacrificing correctness.

## Method

ZapFormat extends standard Earley items with explicit span [i,j] annotations and constructs a directed dependency graph whose edges encode Predict, Scan, and Complete relationships between items. After each Complete phase, a Compact operation computes the reachability closure from the last Earley set and prunes all items not reachable from it, eliminating dead states in real time while preserving parsing completeness. This core pruning is complemented by a context-independent token mask cache (precomputing valid/invalid tokens per terminal as bitsets, inspired by XGrammar), a rejection prefix mechanism that early-terminates grammatically impossible paths, and grammar transformations that remove useless and nullable rules. The pruned state representations are more compact than raw Earley states, which increases cache hit rates when serving multiple queries since different input prefixes can map to identical pruned states.

## Results

Formatron achieves throughput of 6,399–12,175 tokens/s on Geoquery, 7,943–10,640 tokens/s on JSON Schema, and 8,536–12,047 tokens/s on JSON Grammar across four LLMs (Gemma-2-9B, Llama-3-8B, Mistral-7B, Qwen2.5-7B). This represents a 1.5–2× speedup over the closest competitor XGrammar on most task-model combinations, and up to ~200× over lm-format-enforcer. Ablation confirms that dynamic pruning contributes 30–50% of the throughput gain, with the state cache providing additional improvement on multi-run workloads.

## Baselines & Comparisons

Against lm-format-enforcer, Formatron dominates by 10–200× on every applicable task (e.g., 12,175 vs 60 tokens/s on Gemma Geoquery; 9,234 vs 45 on Qwen JSON Schema), reflecting the overhead of lm-format-enforcer's syntax-tree precomputation. Against Outlines, Formatron is 10–100× faster on JSON Schema (e.g., 10,640 vs 599 on Mistral), and Outlines simply cannot handle CFG-based tasks (Geoquery, JSON Grammar) at all. Against XGrammar—the closest competitor—Formatron wins on 10 of 12 model-task combinations, with the largest margins on Geoquery (e.g., 12,175 vs 617 on Gemma, a ~20× gap) and JSON Schema on Qwen (9,234 vs 2,037, ~4.5×). The sole XGrammar win is Mistral JSON Grammar (15,274 vs 12,047 tokens/s, ~27% faster), which the authors attribute to XGrammar's pushdown-automaton stack being particularly efficient for that grammar structure. Overall, Formatron's dynamic Earley-state pruning plus state caching yields a consistent 1.5–2× advantage over XGrammar on the majority of evaluated configurations.

## Relation to Prior Work

This paper extends the Earley parsing algorithm (Earley, 1970) with a dependency-graph-based dynamic pruning mechanism (ZapFormat) specifically tailored for the online, token-by-token setting of LLM constrained decoding. It builds directly on XGrammar's (Dong et al., 2024) context-independent token mask caching and incorporates grammar transformation and rejection-prefix optimizations, but departs from prior CFG-based decoders (lm-format-enforcer, Outlines, XGrammar) by introducing reachability analysis over an extended Earley item representation that tracks span [i,j] to identify and eliminate 'dead' states created by High-level Regular Rules. The key conceptual departure is that pruning is not merely a memory optimization but enables a state cache with higher hit rates, since different input prefixes can converge to the same pruned Earley state set.

## Why It Matters / Open Questions

Constrained decoding is a critical bottleneck for production LLM deployments requiring structured outputs (function calling, DSL generation, API interactions), and a 2–20× throughput improvement with architecture-agnostic applicability has direct practical value. However, the memory savings are modest (~1–2% in the reported experiments), and Formatron does not uniformly dominate XGrammar across all tasks (losing on JSON Grammar for Gemma and Mistral), suggesting the pruning benefit is grammar- and task-dependent. Open questions include whether the dependency-graph overhead becomes prohibitive for very large or highly ambiguous grammars, and whether the approach extends naturally to probabilistic or weighted CFGs where 'dead' state elimination must preserve distributional information.
