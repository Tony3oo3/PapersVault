## Problem

When AI agents interact with third-party services, other agents, or humans, there is no standardized mechanism for those parties to verify that the agent is genuinely AI, that it acts on behalf of a specific human principal, and that its permissions are precisely scoped. Existing web authentication protocols (OAuth 2.0, OpenID Connect) were designed for human-to-service delegation and do not account for autonomous agents with heterogeneous capabilities, failure modes, or the risk that prompt injection can undermine natural-language-only scoping.

## Input / Output

The framework consumes a user's OIDC ID token, agent registration metadata (unique identifier, capabilities, limitations), and natural-language permission instructions from the delegating user. An LLM translates the natural-language scopes into machine-readable policy definitions (XACML, SQL access policies, or JSON rules) that the user reviews and approves before issuance. The system produces a cryptographically signed delegation token referencing both the user ID token and the agent-ID token, optionally wrapped in a W3C Verifiable Credential for cross-domain portability, and operates uniformly across web requests, computer-use, and natural-language interaction modalities.

## Method

The paper proposes a three-token architecture extending OpenID Connect: a standard user ID token, a new agent-ID token (issued when the agent is registered as an OAuth 2.0 Native Client with the OpenID Provider), and a new delegation token signed by the human that binds the two and encodes scope, validity, and revocation conditions. For scoping, an LLM translates the user's natural-language permission instructions into structured, deterministic access-control policies (XACML, SQL, or environment-specific formats), which the user then reviews and approves—ensuring that even if the agent is compromised by prompt injection, its actions remain bounded by the underlying resource permissions. User-Managed Access (UMA) is integrated to allow a single policy configuration point across multiple agents, and W3C Verifiable Credentials provide an alternative or complementary transport for the tokens, enabling selective disclosure and decentralized verification without full OIDC mediation.

## Results

This is a position paper proposing a framework rather than presenting empirical results, so no quantitative metrics or benchmark numbers are reported. The core technical contribution is a three-token architecture (user ID-token, agent-ID token, and delegation token) built on OAuth 2.0 / OpenID Connect, with an optional W3C Verifiable Credentials layer. The paper provides qualitative use-case walkthroughs (e.g., holiday booking, telemedicine, multi-agent insurance claims) and a legal analysis grounded in agency law and UETA, but no ablations, latency measurements, or security evaluation results.

## Baselines & Comparisons

The paper does not run formal baseline comparisons, but it positions its framework against several existing approaches. Compared to Anthropic's Model Context Protocol (MCP), the proposed framework adds full identity verification, delegation tokens, and auditability rather than only system-to-system communication and basic access control. Compared to OpenAI's Operator (which stores login cookies in a browser), the token-based approach enables revocable, scoped, and auditable delegation. Compared to robots.txt or user-agent blocking, authenticated delegation allows selective, credential-gated access for AI agents rather than blanket bot restrictions. The paper acknowledges that W3C Verifiable Credentials and GNAP could serve as lighter-weight alternatives to the full OIDC flow, and notes that emerging prototypes (A2A, MCP-based auth) focus on authentication with limited scoping, whereas this work emphasizes structured resource scoping translated from natural language into XACML-style policies.

## Relation to Prior Work

This paper synthesizes and extends several established protocol families—OAuth 2.0, OpenID Connect, User-Managed Access, and W3C Verifiable Credentials—into a unified 'authenticated delegation' framework specifically designed for AI agents. It positions itself against emerging agent-centric protocols like Anthropic's MCP and Google's A2A, arguing they address only system-to-system communication and basic access control rather than the full chain of human principal verification, agent identity, scoped authority, and auditability. The scoping mechanism draws on structured permission languages (XACML, ODRL) and schema validation, while the legal grounding borrows from agency law doctrine (apparent authority, UETA) to argue that verifiable delegation tokens reduce reliance on ambiguous legal fictions about AI agent liability.

## Why It Matters / Open Questions

As AI agents increasingly perform consequential actions (purchases, medical recommendations, multi-agent negotiations), the absence of a standard way for third parties to verify an agent's identity, its human principal, and its precise scope of authority creates real security, legal, and trust gaps illustrated by cases like Air Canada's chatbot liability dispute. Key open questions include the reliability of translating natural language permissions into structured policies without introducing new LLM attack surfaces, the scalability and privacy costs of repeated OIDC sign-in flows across many services, and whether model vendors will adopt this framework or prefer lighter alternatives like W3C VCs or GNAP. The paper explicitly acknowledges these trade-offs, positioning the proposal as a pragmatic starting point rather than a final solution.
