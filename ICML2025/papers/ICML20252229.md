## Problem

LLM coding agents struggle with real-world software engineering tasks because they must navigate codebases far exceeding their context windows, accurately localize the buggy entity among thousands of files, and generate correct patches. Existing structured pipelines like Agentless rely on prompt-based file selection (limited to file names) and temperature sampling for patch diversity, both of which underperform compared to more targeted retrieval and structural diversity strategies.
![Teaser figure](../imgs/ICML20252229/cropped_page3_idx0.webp)

## Input / Output

The system consumes a natural language issue description (typically under 1000 tokens) and a full code repository (averaging 438k lines in SWE-bench), producing a single code patch in either search/replace or edit_file format. The issue description is first summarized by an LLM to extract technical details (filenames, stack traces, error messages), then used as a query for embedding-based file retrieval. The repository is parsed into an AST/LSP code graph for structured navigation, and the final patch is selected from 9 diverse candidates via test-based filtering and majority voting.

## Method

NEMOTRON-CORTEXA introduces three key components: (1) NV-EmbedCode, a code-specific embedding model fine-tuned from NV-EmbedQA-v2 via LoRA with contrastive learning on ~534k query-positive pairs spanning bug-to-file retrieval and general code retrieval tasks, using instruction templates and positive-aware hard-negative mining; (2) a localization agent that builds a directed code graph (contain and use edges from AST/LSP) and iteratively navigates it via three tools (get_definition, get_incoming_dependency, get_outgoing_dependency), with an ensemble of four heterogeneous LLMs (DeepSeek-v3, GPT-4o, Llama-3.3-70B, Qwen2.5-72B) to improve entity recall by ~29% over the best single model; and (3) a diverse patch generation strategy that varies both context (top-1 file, localization agent output, direct prompting, or their union) and edit format (search/replace vs. edit_file) across 9 inference calls, outperforming Agentless's 40-patch temperature-sampling approach while using 4.4× fewer calls.

## Results

On SWE-bench Lite (300 instances), NEMOTRON-CORTEXA achieves a 42.00% issue resolution rate (126/300), the highest among all compared methods, and 52.60% (263/500) on SWE-bench Verified. The system operates at an average cost of $0.51 per instance, substantially lower than OpenHands ($1.10) and Agentless ($0.70). The code embedding model NV-EmbedCode achieves 70.33% recall@k on SWE-bench Lite with LLM summaries, outperforming the next-best embedding model (NV-EmbedQA-v2 at 55.67%) and the prompt-based Agentless approach (63.00%).

## Baselines & Comparisons

NEMOTRON-CORTEXA outperforms Agentless (the primary baseline) by 1.33% on SWE-bench Lite (42.00% vs. 40.67%) and 1.80% on Verified (52.60% vs. 50.80%), while reducing per-instance cost from $0.70 to $0.51. Against OpenHands, NEMOTRON-CORTEXA edges out on Lite (42.00% vs. 41.67%) but trails slightly on Verified (52.60% vs. 53.00%), at roughly half the cost ($0.51 vs. $1.10). The method substantially outperforms AutoCodeRover (42.00% vs. 30.67% Lite; 52.60% vs. 38.40% Verified) and SWE-agent (42.00% vs. 23.00% Lite; 52.60% vs. 33.60% Verified). For file retrieval, NV-EmbedCode achieves 67.67% recall@k on Lite with original issue descriptions, surpassing SFR-Embedding-2 (60.33%), NV-Embed-v2 (56.00%), and NV-EmbedQA-v2 (61.33%), and also outperforming the prompt-based GPT-4o approach (63.00%). In entity localization, the ensemble of four LLM-based agents achieves 74.72% recall on Lite, improving over the best individual agent (DeepSeek-v3 at 45.94%) and Agentless (59.94%). For file retrieval against agentic baselines, NEMOTRON-CORTEXA achieves 94.00% recall@10, exceeding MarsCode Agent (87.20% recall@∞), AutoCodeRover-v2 (88.20%), OpenHands (85.60%), and SWE-agent-v1 (76.80%).

## Relation to Prior Work

This paper extends the structured two-stage pipeline (localization + repair) introduced by Agentless, replacing its prompt-based file localization with a purpose-trained code embedding model (NV-EmbedCode, fine-tuned from NV-EmbedQA-v2 using contrastive learning and hard-negative mining from NV-Retriever) and its direct-prompting entity localization with an agentic search over an AST/LSP-based code graph. It departs from free-form agentic approaches (SWE-agent, OpenHands) by maintaining a fixed scaffold, and from prior diversity strategies (temperature sampling) by introducing context and edit-format variation as orthogonal axes for patch diversity. The ensemble-of-LLMs strategy for localization draws on the observation that different models excel on different problem subsets, a phenomenon also noted in multi-agent SE work.

## Why It Matters / Open Questions

The paper demonstrates that careful system design—specialized retrieval, tool-augmented localization, and format-aware diversity—can outperform stronger baselines at substantially lower cost ($0.51 vs. $0.70 per instance), making high-quality automated bug-fixing more accessible. A key open question is the patch selection mechanism: majority voting is acknowledged as suboptimal when solutions are deliberately diversified, and the authors show that LLM-based voting plus reasoning models can push Verified resolution to 68.4% at $3.28/issue, suggesting significant headroom. Broader implications include the finding that LLMs are highly sensitive to edit-format choice (search/replace vs. edit_file), which may generalize beyond SWE-bench to other code-editing tasks and warrants further study.
