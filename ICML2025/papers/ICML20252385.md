## Problem

Existing LLM-based AutoML frameworks are restricted to individual pipeline stages (e.g., only HPO or feature engineering) or specific task domains (e.g., only NLP or CV), and they underutilize LLMs' inherent reasoning capacity by relying on computationally expensive training-based search. No prior work provides a task-agnostic, end-to-end AutoML system that spans from data retrieval through model deployment while remaining computationally efficient and accessible to non-expert users via natural language.

## Input / Output

The system accepts a free-form natural language task description (with optional constraints on accuracy, latency, model architecture, etc.) and a task-specific full-pipeline skeleton Python script containing TODO placeholders for data loading, preprocessing, training, evaluation, and deployment. The Prompt Agent parses the instruction into a standardized JSON object with six top-level keys (User, Problem, Dataset, Model, Knowledge, Service) that are shared across all agents. The final output is executable Python code implementing a deployment-ready model, a Gradio inference endpoint URL, and performance/complexity metrics (accuracy, F1, RMSLE, RI, inference time, model size). Evaluation uses a Comprehensive Score (CS = 0.5×SR + 0.5×NPS) combining code-generation success rate and normalized downstream performance.

## Method

AutoML-Agent coordinates five specialized LLM agents (Agent Manager, Prompt Agent, Data Agent, Model Agent, Operation Agent) through a three-stage pipeline: initialization, planning, and execution. The key planning mechanism is Retrieval-Augmented Planning (RAP), which queries external APIs (arXiv, web search) to generate P=3 diverse end-to-end plans rather than a single plan, enhancing exploration of the combinatorial search space. Each plan is decomposed via role-specific Plan Decomposition into subtasks for the Data and Model Agents, which then execute them through prompting-based simulation (pseudo data analysis and training-free model search/HPO) without actually running code, exploiting LLM in-context learning to predict outcomes. A three-stage verification loop (request, execution, and implementation verification) provides feedback to agents and triggers plan revision on failure. The Prompt Agent is instruction-tuned (LoRA on Mixtral-8x7B with ~2.3K EvolInstruct-generated pairs) to reliably parse user instructions into the standardized JSON format, while all other agents use GPT-4o zero-shot with role-specific system prompts.

## Results

Across seven downstream tasks and fourteen datasets spanning five modalities (image, text, tabular, graph, time series), AutoML-Agent achieves an average success rate (SR) of 87.1% under the constraint-aware setting, consistently outperforming all baselines. In terms of the Comprehensive Score (CS = 0.5×SR + 0.5×NPS), AutoML-Agent attains an average of 0.612, surpassing the training-based SELA baseline (0.599) while being approximately 8× faster in search time. The framework requires on average ~525 seconds and $0.30 USD (GPT-4o) to produce a single deployable model. Ablation studies confirm that retrieval-augmented planning, plan decomposition, and multi-stage verification each contribute meaningfully to both success rate and downstream performance.

## Baselines & Comparisons

AutoML-Agent outperforms all compared baselines on the Comprehensive Score across both constraint-free and constraint-aware settings. Against handcrafted Human Models (ResNet-18 for images, XLM-RoBERTa for text, TabPFN for tabular classification, iTransformer for time series, PMLP for graphs), AutoML-Agent achieves superior NPS, indicating that LLM-generated pipelines can match or exceed expert-designed solutions. Compared to DS-Agent, AutoML-Agent is more robust: DS-Agent fails on several tasks due to its heavy reliance on curated case banks and partially completed code that is unavailable in the full-pipeline setting. Against zero-shot GPT-3.5 and GPT-4, AutoML-Agent shows a clear advantage on complex tasks (image, text, graph, time series), while general-purpose LLMs perform relatively competitively only on simpler tabular tasks that involve straightforward sklearn calls. In the head-to-head comparison with SELA (a Monte Carlo tree search–based LLM agent), AutoML-Agent achieves a slightly higher CS (0.612 vs. 0.599) while completing search in roughly 1/8th the time, validating the efficiency of the training-free prompting-based execution strategy. AutoGluon, the state-of-the-art traditional AutoML framework, is outperformed by AutoML-Agent, which additionally handles graph data and deployment—capabilities AutoGluon lacks.

## Relation to Prior Work

This paper extends the line of LLM-based AutoML work (CAAFE, AgentHPO, HuggingGPT, DS-Agent, SELA) that has so far targeted individual pipeline stages or specific task families, by proposing the first task-agnostic multi-agent framework covering the entire pipeline from data retrieval to model deployment. It builds on retrieval-augmented generation and multi-agent coordination ideas (MetaGPT, Data Interpreter) but introduces a retrieval-augmented planning (RAP) strategy that combines external knowledge retrieval with multi-plan generation, and a training-free prompting-based execution that replaces the costly iterative training loops used by SELA. The instruction-tuned Prompt Agent draws on EvolInstruct-style data generation (Xu et al., 2024) to standardize user requirements into a structured JSON schema shared across agents.

## Why It Matters / Open Questions

By automating the full AutoML pipeline through natural language, this work lowers the barrier for domain experts and non-ML practitioners to build deployment-ready models, addressing a well-documented accessibility gap in AutoML adoption. The training-free search achieving 8× speedup over SELA with comparable performance (0.612 vs. 0.599 CS) is practically significant for reducing computational overhead. However, the framework's heavy reliance on GPT-4 as backbone, the need for task-specific skeleton scripts, and the unaddressed gap for domains like reinforcement learning and recommendation systems limit its generality. Open questions include whether the multi-agent architecture can be made backbone-agnostic, how to extend retrieval to scientific literature tools like PaperQA, and whether the prompting-based execution can handle tasks with fundamentally different pipeline structures.
