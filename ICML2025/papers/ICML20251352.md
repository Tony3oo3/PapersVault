## Problem

While math and code generation benefit from abundant structured training data, most other reasoning domains—logical deduction, scientific inference, symbolic reasoning—suffer from sparse and fragmented supervision signals. Conventional approaches like raw code pre-training or text-to-code generation fail to extract the diverse reasoning patterns embedded in code because the relevant signals are implicit, intertwined with noise, or constrained by code-specific syntax that limits generalization.

## Input / Output

The model receives a prompt containing a cleaned Python function, a natural-language query describing its intended functionality, and either a specific input or output (with the other to be predicted). The response is a free-form natural-language Chain-of-Thought rationale followed by a JSON-formatted prediction (e.g., {"output": ...} or {"input": {...}}). All inputs and outputs are constrained to be JSON-serializable with size limits (objects < 1024 bytes, lists/dicts < 20 elements, strings < 100 chars) to keep them within LLM generation capability. In CODEI/O++, the response additionally includes execution feedback and a revised second-turn prediction concatenated into a single longer sequence.

## Method

CODEI/O transforms ~450K raw Python code files into executable functions with rule-based input generators, then samples 3.5M input-output pairs by actually executing the code. The key insight is reframing code understanding as an I/O prediction task: given a function and one side of the I/O pair, the model must predict the other side entirely in natural-language CoT, thereby learning universal reasoning primitives (logic flow orchestration, state-space exploration, recursive decomposition, decision-making) while being decoupled from code syntax. CoT responses are synthesized by DeepSeek-V2.5, and CODEI/O++ further leverages code executability by verifying predictions and prompting a second-turn revision on incorrect ones, concatenating both turns into the training target. Training uses a two-stage protocol: first-stage SFT on CODEI/O(++) data (1 epoch, lr 1e-5), followed by second-stage general instruction tuning (700 steps, lr 3e-5), which prevents the large CODEI/O dataset from overwhelming the instruction-tuning signal.

## Results

CODEI/O++ achieves average benchmark scores of 57.7 (Qwen 2.5 Coder 7B), 52.1 (LLaMA 3.1 8B), 53.5 (DeepSeek Coder v2 Lite 16B), and 61.5 (Gemma 2 27B), outperforming the single-stage instruction-tuning-only baseline by +2.9, +2.8, +1.9, and +2.0 points respectively. CODEI/O (without multi-turn revision) already achieves 57.2, 51.2, 53.6, and 60.9 on the same models. The method delivers consistent gains across all 14 evaluated benchmarks spanning symbolic, scientific, logic, math, commonsense, and code reasoning, with the most notable improvements on CRUXEval-O (+4.0 to +9.7 over baseline) and KorBench (+1.4 to +5.8).

## Baselines & Comparisons

CODEI/O++ outperforms all four baselines on average across all four base models. Against WebInstruct (3.5M samples), CODEI/O++ gains +2.7 (Qwen), +2.3 (LLaMA), +1.9 (DeepSeek), and +1.1 (Gemma) in average score. Against OpenMathInstruct-2 (3.5M), the gains are +2.5, +1.5, +1.6, and +1.1 respectively; notably, OMI2 excels on MATH (e.g., 72.3 vs 72.1 for Qwen) but regresses sharply on GPQA (36.2 vs 40.6) and BBH, while CODEI/O++ maintains balanced gains. Against OpenCoder-SFT-Stage-1 (4.2M), CODEI/O++ leads by +2.7, +3.0, +2.2, and +1.5, with the largest margin on LLaMA where OC-SFT-1 actually underperforms the single-stage baseline. Against Python-Edu (7.7M raw code), CODEI/O++ wins by +2.9, +3.1, +1.4, and +1.8, demonstrating that the structured input-output prediction task is far more effective than raw code language modeling despite using less than half the data. A key differentiator is consistency: CODEI/O++ shows improvements on nearly all 14 benchmarks simultaneously, whereas baselines like OMI2 and PyEdu produce mixed gains and losses across tasks.

## Relation to Prior Work

This paper departs from prior code-execution learning work (Nye et al., 2021; Ding et al., 2024; Jiang et al., 2024b), which either targets code-specific tasks or is limited to narrow problem sets like LeetCode, by repurposing diverse, contextually-grounded code as a scalable source of general reasoning patterns. Rather than performing continual pre-training on raw code or text-to-code generation, it transforms code into input-output prediction tasks with natural-language CoT responses synthesized by DeepSeek-V2.5, explicitly decoupling reasoning logic from code syntax. The multi-turn revision mechanism (CODEI/O++) leverages code's verifiability in a way that prior rejection-sampling approaches do not, and the two-stage training protocol (reasoning enhancement before instruction tuning) positions the method as an intermediate pre-training step rather than a standalone fine-tuning recipe.

## Why It Matters / Open Questions

The paper provides a publicly available 3.5M-sample dataset and a reproducible pipeline that yields consistent, balanced improvements across 14 reasoning benchmarks and 4 model architectures, addressing the data-scarcity problem in non-math, non-code reasoning domains. The finding that raw code pre-training is largely ineffective while structured I/O prediction with CoT is consistently beneficial challenges the common assumption that more code data automatically improves reasoning. Open questions include whether the approach generalizes beyond Python, how it interacts with RL-based inference-time scaling (o1/R1), and whether the moderate per-benchmark gains (~1–3 points) compound under further scaling or combination with other reasoning training signals.
