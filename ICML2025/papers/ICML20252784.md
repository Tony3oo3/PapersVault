## Problem

Existing security alignment for code LLMs relies on sparse real-world vulnerability data (e.g., SafeCoder collects only 465 entries from 145M commits) and is coupled to the instruction-tuning phase, making it incompatible with modern multi-stage post-training pipelines. This paper asks: how can a fully post-trained code LLM be made to generate secure code without reverting to earlier training stages or depending on scarce real-world vulnerability pairs?
![Teaser figure](../imgs/ICML20252784/cropped_page2_idx0.webp)

## Input / Output

The method takes a fully post-trained code LLM, a set of (language, CWE) pairs, a standard instruction-tuning dataset (Infinity-Instruct), and a static analyzer as a security oracle. It produces a security-aligned code LLM via an additional preference-optimization stage and a synthesized preference dataset of ~10k entries (7× larger than SafeCoder's 1.5k). Unusually, both the vulnerable and fixed code in each preference pair are sampled from the target model itself—the model generates vulnerable code on synthesized instructions, then fixes it when given the identified CWE—so the alignment data stays within the model's own distribution.

## Method

PROSEC synthesizes vulnerability-inducing instructions by prompting a general LLM to combine CWE-specific coding scenarios with relevant normal instructions, then clusters them for diversity; these instructions trigger 25× more vulnerable code than a standard dataset. Preference data is constructed in two complementary sets: D_sec pairs (vulnerable instruction, fixed code, vulnerable code) to teach secure practices, and D_norm pairs (normal instruction, normal code, fixed code) to prevent the model from over-applying security APIs in benign contexts. Quality control uses heuristic filtering (syntax checks, static-analyzer verification, fuzzy deduplication) for D_sec and a training-dynamics-based influence score for D_norm, computed as the Kendall Tau correlation between utility degradation and security improvement across warm-up checkpoints. The final shuffled mixture is optimized with SimPO (or DPO/IPO/ORPO) via LoRA, operating as a standalone post-training stage that requires no modification to prior training.

## Results

On the PurpleLlama secure coding benchmark, PROSEC-aligned models achieve a 25.2% reduction in vulnerable code ratio for Phi3-mini-Inst (33.47% vs. 44.72% for SafeCoder) and a 35.4% reduction for CodeLlama-7B-Inst (26.04% vs. 40.33% for SafeCoder). PROSEC also outperforms the SafeCoder-Inst baseline (which incorporates security at the instruction-tuning stage) by 16.84 percentage points on CodeLlama (26.04% vs. 42.88% vulnerable code). On utility, PROSEC-aligned models match or slightly exceed the original models' pass@1 on HumanEval-Multi and MXEval, while SafeCoder-aligned models show modest utility drops.

## Baselines & Comparisons

The primary baseline is SafeCoder (He et al., ICML 2024), compared in two configurations: (1) as a preference-optimization dataset applied at the alignment stage, and (2) as an instruction-tuning dataset (SafeCoder-Inst). PROSEC wins decisively on security in both comparisons: it reduces the average vulnerable code ratio from 44.72% to 33.47% on Phi3-mini-Inst (25.2% relative improvement) and from 40.33% to 26.04% on CodeLlama-7B-Inst (35.4% relative improvement) versus SafeCoder at the alignment stage. Against SafeCoder-Inst, PROSEC-aligned CodeLlama achieves 26.04% vulnerable code versus 42.88%, demonstrating that post-training preference alignment is more effective than injecting security at the instruction-tuning stage. On utility, PROSEC matches or slightly exceeds the original models (e.g., 34.15% vs. 32.39% HumanEval-Multi on Phi3; 29.02% vs. 24.88% on CodeLlama), whereas SafeCoder-Inst suffers a notable utility drop (19.75% HumanEval-Multi). The paper also shows PROSEC's advantage generalizes to three additional models (Llama3.2-1B, Phi4-mini, Qwen2.5-Coder-3B), consistently reducing vulnerable code by 7.3–12.5 percentage points without utility degradation.

## Relation to Prior Work

PROSEC builds on the preference optimization framework (DPO/SimPO) for post-training alignment, but departs fundamentally from prior secure-code work like SafeCoder and SVEN, which inject security during instruction tuning using sparse real-world vulnerability data. Instead, PROSEC reframes security alignment as a standalone preference optimization stage applied to an already-post-trained model, synthesizing vulnerability-inducing instructions from CWE definitions to overcome the sparsity of real-world vulnerable code. The training dynamics-based data selection for utility preservation draws on dataset cartography and influence-function literature but applies it to the novel setting of pairwise preference data where two complementary subsets (security and utility) must be jointly optimized.

## Why It Matters / Open Questions

As code LLMs are increasingly deployed in production, the ability to retrofit security onto expensive, fully post-trained models without retraining is practically critical. PROSEC's proactive synthesis approach (25× more vulnerable code induction, 7× larger dataset) offers a scalable path that is not bottlenecked by the availability of real-world vulnerability commits. Key open questions include whether online RL with static-analyzer feedback can further close the gap, and whether multi-step reasoning (system-2) is ultimately necessary for truly robust security understanding beyond pattern-matching on CWE categories.
