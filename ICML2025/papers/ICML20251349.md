## Problem

Secure GPT inference via cryptographic primitives (HE, MPC) incurs substantial computation and communication overhead, making it impractical for real-time use. Prior work has focused on optimizing cryptographic protocols or modifying model architectures, but the decoding phase—where one token is generated per step—remains a bottleneck. This paper identifies that secure decoding latency is nearly insensitive to input length, meaning forwarding multiple tokens costs roughly the same as one, yet no prior work has exploited this property to reduce the number of secure decoding steps.

## Input / Output

The client holds a public GPT model and the private input prompt, while the server holds the private GPT model. The client autoregressively generates γ draft tokens in plaintext from the public model, and both parties jointly perform a single secure forward pass over all draft tokens to produce secret-shared output distributions. The final output is a sequence of accepted tokens plus one bonus token, guaranteed to follow the private model's exact output distribution—identical in quality to standard secure decoding. The public model is small (e.g., 68M–160M parameters) and can be fine-tuned on a single 20 GB GPU.

## Method

Post (Public decOding and Secure verificaTion) exploits the observation that secure GPT decoding latency is dominated by fixed one-way delays and SIMD underutilization, making it nearly independent of input length. The client generates γ draft tokens from a public model, then both parties securely forward all γ tokens in one decoding step to obtain the private model's output distributions. A specialized secure speculative sampling protocol determines token acceptance using 'soft' matching: division is refactored into multiplication with a random matrix, and a 'selection-then-comparison' strategy via oblivious transfer avoids the exponential-cost carry-bit computation over the full vocabulary. Knowledge distillation on a public or anonymized corpus aligns the public model's output distribution with the private model's, raising acceptance ratios from ~24–74% to ~52–84% and yielding 2.1×–6.0× end-to-end speedup over standard secure decoding.

## Results

Post achieves a 2.1×–6.0× end-to-end speedup over standard secure decoding across three model pairs (Vicuna-7B/LLaMA-160M, FLAN-T5-XL/T5-efficient-base, FLAN-T5-XL/FLAN-T5-base) under both LAN (1 Gbps, 10 ms) and WAN (400 Mbps, 40 ms) conditions. After knowledge distillation alignment, acceptance ratios range from 52% to 84%, translating to a 2.0×–6.3× reduction in the number of decoding steps. The optimized secure speculative sampling protocol reduces its own latency by approximately 10× compared to the naive approach (e.g., 1.45 s vs. 28.26 s for 8 draft tokens on LAN), making its overhead negligible relative to a single decoder step (~8.67 s).

## Baselines & Comparisons

The paper compares Post against standard secure decoding built on the SOTA hybrid protocol combining Nimbus's linear protocol (Li et al., 2024b) and BumbleBee's nonlinear protocol (Lu et al., 2025). Post achieves a consistent 2.1×–6.0× end-to-end speedup over this baseline across all tested model pairs, tasks, and network conditions, with the speedup scaling directly with the acceptance ratio. The speedup is consistent between LAN and WAN settings, demonstrating robustness to network variability. Importantly, Post is complementary to the baseline protocols rather than a replacement — it can be layered on top of BumbleBee/Nimbus for additional gains. The optimized speculative sampling protocol (Table 2) reduces its own overhead from ~28 s (naive, 8 drafts, LAN) to ~1.5 s, confirming that the verification step does not erode the speedup advantage over the standard one-token-per-step decoding baseline.

## Relation to Prior Work

Post bridges two previously separate research threads: speculative decoding (Leviathan et al., 2023; Cai et al., 2023), which accelerates plaintext autoregressive generation by drafting with a small model and verifying with a large one, and secure two-party GPT inference (Hao et al., 2022; Lu et al., 2025; Li et al., 2024b), which protects privacy via HE and MPC. The key conceptual departure is the observation that cryptographic decoding latency is nearly invariant to input length (due to dominant one-way delay and SIMD underutilization at batch size 1), which makes the speculative-decoding 'free lunch' of forwarding multiple tokens at near-zero marginal cost available in the secure setting for the first time. The paper is explicitly complementary to prior protocol-level optimizations (BumbleBee, Nimbus) and architecture modifications, positioning itself as an orthogonal acceleration layer.

## Why It Matters / Open Questions

A 2.1×–6.0× speedup for secure GPT decoding is practically significant given that secure inference is currently orders of magnitude slower than plaintext inference, and the approach requires no modification to the private model or the underlying cryptographic protocol. Open questions include how acceptance ratios scale with larger public models (the paper only tests up to 160M parameters), whether the semi-honest assumption can be relaxed to malicious settings, and how the method behaves in multi-turn or streaming scenarios where the KV cache grows. A limitation is the client-side requirement for a public model and the one-time alignment cost, though the paper notes server-provided aligned models (e.g., Gecko, Qwen2.5) could mitigate this.
