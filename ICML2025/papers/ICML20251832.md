## Problem

Cloud-hosted frontier LMs are prohibitively expensive for data-intensive reasoning over long documents (e.g., >$15 per query on a million-token code repository), while small on-device LMs (1–8B parameters) are too weak to handle such tasks alone. No prior work systematically studies communication protocols that let a small local LM and a large remote LM collaborate to reduce cloud inference costs while preserving answer quality on long-document reasoning tasks.

## Input / Output

The system takes a long document context (54K–143K tokens on average across financial filings, medical records, and scientific papers) and a natural-language query, and produces a single predicted answer. Critically, only the local model ever ingests the full context; the remote model sees only the query plus filtered, structured outputs (explanation, citation, answer fields) from the local model. The remote model also generates executable Python code as an intermediate output, which is run locally to produce job specifications, decoupling the number of parallel subtasks from the number of tokens the cloud model must generate.

## Method

The paper proposes two protocols. MINION is a naive multi-turn chat in which the remote model asks questions and the local model answers using the full context, achieving a 30.4× cloud-cost reduction but recovering only 87% of remote-only accuracy. MINIONS replaces this with an iterative divide-and-conquer loop of three steps: (1) Decompose — the remote model writes a Python function that, when executed locally, partitions the document into chunks and pairs each with a single atomic instruction, producing hundreds of job specifications without the remote model ever reading the document; (2) Execute — the local model runs all jobs in parallel, discards abstentions, and sends only surviving structured responses to the remote model; (3) Aggregate — the remote model synthesizes the filtered outputs and either emits a final answer or loops back to Decompose. This design directly addresses two identified failure modes of small LMs (inability to follow multiple instructions at once and degradation over long contexts) by ensuring each local job is a single instruction over a short chunk. Averaged across three benchmarks, MINIONS with an 8B local model recovers 97.9% of remote-only performance at 18% of the cloud cost.

## Results

On a macro-average across FINANCEBENCH, LONGHEALTH, and QASPER, MINIONS with an 8B local LM (LLAMA-3.1-8B) recovers 97.9% of the remote-only GPT-4O accuracy (0.709 vs. 0.724) at only 18.0% of the cloud cost ($0.042 vs. $0.233 per query), a 5.7× cost reduction. With a 3B local LM, MINIONS achieves 93.4% of remote-only performance at 16.6% of cloud cost. The simpler MINION protocol achieves a 30.4× cost reduction ($0.008 per query) but recovers only 87% of remote-only accuracy (0.630).

## Baselines & Comparisons

Against the remote-only GPT-4O baseline, MINIONS with LLAMA-8B trails by only 1.5 accuracy points (0.709 vs. 0.724) while spending 82% less on cloud inference. Against local-only baselines, MINIONS dramatically outperforms: the 8B local-only model achieves 0.444 macro accuracy, while MINIONS with the same model reaches 0.709. Compared to the simpler MINION protocol, MINIONS improves macro accuracy from 0.630 to 0.709 (with LLAMA-8B) at roughly 5× the remote cost, closing most of the remaining gap to the remote-only baseline. Against RAG systems (BM25 and OpenAI text-embedding-3-small), the paper finds that on FINANCEBENCH, RAG with OpenAI embeddings reaches similar quality-cost tradeoff points as MINIONS, but no RAG configuration matches MINION's quality at the same very low cost. On the BOOOKSCORE summarization task, MINIONS produces summaries comparable to a GPT-4O-only baseline (evaluated via LLM-as-a-judge), whereas RAG-based summaries miss critical plotlines, characters, and details.

## Relation to Prior Work

This paper builds on the code-generation-for-extraction paradigm (Arora et al., 2023; Li et al., 2023) and divide-and-conquer long-context strategies (Zhang et al., 2024c; Zhou et al., 2024), but departs from both by framing the problem as an asymmetric local-remote collaboration with explicit cost optimization. Unlike prior multi-agent or multi-LLM systems that combine symmetric or large models, MINIONS assigns context-heavy parallel work to a small on-device LM while the cloud LM only orchestrates via generated code, decoupling the number of local jobs from cloud token generation. The Information Bottleneck lens (Tishby et al., 2000) is repurposed to analyze the local model as an information encoder, and the protocol draws on test-time sampling (Brown et al., 2024) and speculative-decoding-style verification, but applies them in the novel setting of cross-device, asymmetric-cost collaboration.

## Why It Matters / Open Questions

The 5.7× cost reduction at 97.9% accuracy recovery, achievable on a single consumer GPU (RTX 4090), makes frontier-quality document reasoning dramatically more accessible and energy-efficient (up to 12× less energy than fully remote execution). The counterintuitive finding that MINIONS *outperforms* remote-only on complex multi-span and numerical-reasoning tasks suggests decomposition is not merely a cost hack but can improve reasoning quality. Open questions include formal privacy guarantees for the local-remote interface, joint training of the two models for better cooperation, and whether the protocol's feasibility (which only emerged with mid-2024 model releases) will continue to improve as small LMs advance. The paper does not address security risks of executing remotely-generated code on-device, a practical concern for deployment.
