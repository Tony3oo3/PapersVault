## Problem

Inference-time algorithms that use verifiers to assist language model generation (e.g., best-of-N, MCTS) have been empirically benchmarked, but the algorithmic design space remains poorly understood: it is unclear when a verifier is necessary, what relationship it must have to the generator, and how much computational benefit it provides. This paper develops a formal query-complexity framework to answer these questions, showing that even simple constrained generation tasks are intractable without a verifier but become tractable with one.

## Input / Output

The method takes a text prompt, a frozen autoregressive language model (generator oracle) that produces next-token distributions, and a lightweight process verifier (a single linear layer on intermediate LM representations) that outputs a binary accept/reject decision for each prefix. The output is a constraint-satisfying string in the support of the generator (p_O(s) > 0) that belongs to the target constraint set A (e.g., valid Dyck sequences or valid Python test cases). The verifier is trained in a supervised fashion on pairs of correct and error-containing model completions, using only the LM's hidden representations as features.

## Method

The paper's core contribution is twofold. Theoretically, it proves that constrained generation is information-theoretically intractable (requiring 2^{D-1} oracle queries via Yao's minimax lemma) and computationally NP-hard (via reduction from knapsack) without a process verifier, but that tokenwise rejection sampling with a perfect process verifier reduces oracle complexity from exponential to linear (2D vs. 2^D · D). Empirically, it proposes Tokenwise rejection sampling with backtracking (Algorithm 1): the model generates one token at a time, queries the process verifier after each token, and upon rejection erases the last B tokens and regenerates them via argmax decoding, subject to a backtrack quota Q. The verifier is a single linear layer trained on intermediate (layer 27) CodeLlama representations, and the approach is shown to outperform nucleus sampling, temperature scaling, and block best-of-n in accuracy, query efficiency, and diversity on both synthetic Dyck grammar and real Python test-case generation tasks.

## Results

On the CodeLlama test-case generation task, Tokenwise rejection sampling with backtracking (Q=4, B=4, top-p=0.95, T=1.0) achieves 0.714±0.011 Acc_distinct, outperforming the best baseline (block best-of-n with n=2 at 0.684±0.038) and nucleus sampling (0.660±0.042). On the synthetic Dyck grammar task, backtracking reduces completion errors from 240.0±5.2 to 179.4±1.0 (top-p=0.9) and from 461.8±8.3 to 200.0±3.2 (top-p=1.0) on 10,000 unseen OOD prompts. Theoretically, the paper proves that without a process verifier, constrained generation requires Ω(2^(D-1)) oracle queries (Theorem 1) or is NP-hard (Theorem 2), while tokenwise rejection sampling with a perfect process verifier reduces complexity to 2D (Proposition 1).

## Baselines & Comparisons

The proposed Tokenwise rejection sampling with backtracking (Q=4, B=4) consistently outperforms all baselines across both experimental settings. On CodeLlama, it achieves 0.714 Acc_distinct vs. 0.684 for block best-of-n (n=2), 0.660 for nucleus sampling (top-p=0.95), 0.623 for block best-of-n (n=4), and 0.559 for block best-of-n (n=8) — a 5.4–27.7% relative improvement over the strongest baseline. On the Dyck grammar, backtracking reduces errors by 25% (top-p=0.9: 240→179) and 57% (top-p=1.0: 462→200) compared to the same sampling strategy without the verifier. The improvement is additive: it stacks on top of nucleus sampling rather than replacing it, confirming the method is complementary to standard decoding heuristics. Temperature scaling (T=1.2) and greedy decoding (top-p=0.0) perform substantially worse (0.269 and 0.013 respectively), highlighting that the verifier-guided backtracking is the dominant factor in accuracy gains.

## Relation to Prior Work

This paper carves new theoretical ground by formalizing constrained generation as an oracle-complexity problem, drawing on classical tools from computational complexity (Yao's minimax lemma, NP-hardness reductions via knapsack) to show that even trivially checkable constraints render generation intractable without a process verifier. Empirically, it builds on the inference-time scaling literature (best-of-N, MCTS, lookahead search) and process reward modeling (Polu & Sutskever, Lightman et al.), but departs by showing that a minimal single-layer linear verifier combined with a simple backtracking mechanism outperforms more elaborate block-level process reward approaches. The paper explicitly positions its tokenwise backtracking algorithm as distinct from lookahead search (Snell et al., 2024) in that it avoids beam expansion and uses argmax for backtracked positions.

## Why It Matters / Open Questions

The paper provides the first clean theoretical justification for why process verifiers reduce query complexity in constrained generation, moving the field beyond purely empirical scaling-law observations. The practical recipe (lightweight verifier + tokenwise backtracking) is composable with existing baselines like nucleus sampling, making it a drop-in improvement for constrained decoding pipelines. Key open questions include: whether the theoretical intractability results extend to realistic language model oracles, what conditions on verifier calibration are needed for distributional correctness (Proposition 2 shows tokenwise rejection sampling distorts the target distribution), and whether the approach scales to longer, more complex generation tasks beyond the 32-token Dyck and 384-token code settings tested here.
