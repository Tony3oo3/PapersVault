## Problem

Designing effective PINNs architectures for solving PDEs relies heavily on expert deep learning knowledge and extensive manual trial-and-error, creating a barrier for domain scientists. Previous works summarize heuristic tuning rules for specific PDE families but do not provide a generalizable automated framework. This paper addresses the gap by introducing an LLM-based multi-agent system that autonomously explores and optimizes PINNs architectures without requiring manual hyperparameter tuning.
![Teaser figure](../imgs/ICML20252716/cropped_page2_idx0.webp)

## Input / Output

The system takes a PDE formulation (governing equation, spatial/temporal domain, boundary and initial conditions) as text input and operates in two modes: Config Generation, which produces a YAML file specifying hyperparameters (network type, activation, width, depth, optimizer, initializer, learning rate, collocation points) within a predefined search space, and Code Generation, which additionally produces executable training code for PDEs not yet in the Code Bank. The optimization loop runs for 5 iterations using GPT-4, with the final output being the best-performing configuration evaluated by test MSE on the PINNacle benchmark (14 PDEs across 1D, 2D, 3D, and ND domains).

## Method

PINNsAgent is a multi-agent framework comprising a Database (storing 3000 fine-tuning experiment logs from PINNacle), a Planner (LLM policy model), a Programmer (code generator), and a Code Bank (reusable templates). The key retrieval mechanism, Physics-Guided Knowledge Replay (PGKR), encodes each PDE's mathematical and physical properties (type, equation class, dimensionality, linearity, boundary conditions, etc.) into weighted binary feature vectors and retrieves the top-K most similar solved PDEs via weighted cosine similarity, providing informed starting configurations. For iterative refinement, the Memory Tree Reasoning Strategy (MTRS) formulates hyperparameter optimization as a Monte Carlo Tree Search where the root is the target PDE, each level corresponds to a hyperparameter, and the LLM planner's output distribution serves as the policy π_pl(a|s) in a modified UCT selection rule that balances exploration and exploitation. Back-propagation updates Q-values using negative test MSE as reward, and the planner revises its experimental plan each iteration based on training feedback, progressively converging toward the optimal architecture.

## Results

On the PINNacle benchmark of 14 PDEs (1D, 2D, 3D, and N-D), PINNsAgent achieves the lowest MSE on 12 out of 14 PDEs, outperforming both Random Search and Bayesian Search. Headline improvements include NS-C (MSE 8.50E-06 vs. 4.02E-03 for Random and 5.12E-03 for Bayesian), Heat-MS (3.57E-05 vs. 1.84E-02 and 7.48E-03), and Heat-ND (3.51E-07 vs. 2.58E-02 and 1.18E-04). The only PDE where PINNsAgent underperforms is Wave-CG (5.40E-02 vs. 2.11E-02 for Bayesian Search). Computational overhead is minimal: PINNsAgent averages 3747.78 s per PDE, only 8.2% slower than Random Search (3462.24 s) and 4.1% slower than Bayesian Search (3598.47 s).

## Baselines & Comparisons

PINNsAgent is compared against two hyperparameter optimization baselines: Random Search (uniform sampling from the search space) and Bayesian Search (Bayesian optimization over the same space). PINNsAgent wins on 12 of 14 PDEs against both baselines, with the most dramatic gains on complex multi-scale and high-dimensional problems: NS-C improves by ~470× over Random Search and ~600× over Bayesian Search in MSE, while Heat-ND improves by ~73,000× over Random Search. The sole clear loss is on Wave-CG, where Bayesian Search achieves 2.11E-02 MSE versus PINNsAgent's 5.40E-02, suggesting the physics-guided retrieval may select suboptimal starting points for this particular heterogeneous-medium wave problem. On the chaotic KS equation, all three methods converge to similar MSE (~1.09E+00), indicating the problem is near the practical limit of PINNs regardless of hyperparameter choice. The ablation (Table 3) further confirms that removing PGKR degrades performance on most PDEs, and removing both PGKR and MTRS causes catastrophic failure on GS (MSE jumps from 4.32E-03 to 2.59E+08), validating that both components are essential for robust generalization.

## Relation to Prior Work

This paper sits at the intersection of three research threads: PINNs architecture optimization (Wang et al., 2022; Wang & Zhong, 2024; Kaplarević-Mališić et al., 2023), which previously relied on extensive manual experiments summarized as heuristic rules; LLM-based autonomous agents for scientific computing (Kumar et al., 2023; Lin et al., 2024), which had only preliminarily explored PDE solving; and Monte Carlo Tree Search with UCT (Browne et al., 2012; Kocsis & Szepesvari, 2006), adapted here as the Memory Tree Reasoning Strategy. The key departure is the Physics-Guided Knowledge Replay mechanism, which extends the Experience Replay paradigm (Rolnick et al., 2019) by encoding PDE-specific mathematical and physical properties into weighted feature vectors for structured retrieval, rather than relying on generic similarity or manual heuristics. Unlike prior AutoML-for-PINNs work that treated hyperparameter search as a black-box optimization problem, PINNsAgent leverages the LLM's reasoning to interpret PDE structure and guide exploration in a physics-aware manner.

## Why It Matters / Open Questions

PINNsAgent offers a practical path toward democratizing PINNs usage by removing the need for deep learning expertise in architecture selection, which is a significant barrier for domain scientists. The framework's modular design (retrieval + tree search + code generation) is extensible, and the modest computational overhead (~8% over Random Search) makes it deployable in practice. However, several limitations remain: the approach depends on a pre-populated database of 3000 fine-tuning experiments, relies on GPT-4 (raising cost and accessibility concerns), and the gap to oracle PINNacle results is still substantial on many PDEs (e.g., Wave-C, Burgers-C). Open questions include whether the method generalizes to PDEs outside the PINNacle benchmark, whether open-source LLMs can replicate the performance, and whether the 5-iteration budget is sufficient for more complex multi-physics problems.
