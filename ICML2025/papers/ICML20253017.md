## Problem

Existing textual optimization methods for LLM systems (e.g., TextGrad, ProTeGi) operate as first-order optimizers, adjusting prompts or solutions based solely on immediate feedback from the current iteration. This reliance on instantaneous gradients causes stagnation in local optima, where responses repeat or improve only marginally across iterations, particularly in complex multi-step reasoning and code tasks. The paper asks whether incorporating information about how responses evolve over time—analogous to second-order curvature in numerical optimization—can enable more stable and effective textual optimization.

## Input / Output

The method consumes a text variable (prompt, solution, or code snippet), the task input, and the full history of previous iteration responses, which are fed into an LLM-based similarity evaluator to compute the response-evolution term. The output is an updated text variable wrapped in designated tags, along with textual gradient feedback that explicitly references both immediate loss and cross-iteration response patterns. Unlike standard TextGrad, which only sees the current feedback, REVOLVE's gradient template includes a <PAST_ITERATIONS> field containing all prior response values, enabling the optimizer LLM to reason about trajectory rather than a single step.

## Method

REVOLVE extends the TextGrad pipeline by augmenting the first-order textual gradient with a similarity function S(r(p_t), r(p_{t-1})) that quantifies how the response has changed between consecutive iterations, yielding the combined update in Eq. 2. This similarity is formally defined as the ratio of the loss difference to the prompt difference, which under the assumption of sufficiently small prompt changes approximates a second derivative, making the overall update analogous to a second-order (Hessian-informed) step. In practice, an LLM evaluates S by comparing the current and previous responses, and the optimizer prompt instructs the model to make 'thoughtful, measured changes' that avoid both stagnation (too-similar responses) and overshooting (drastic shifts). The forward pass executes the system as a computation graph, an evaluator LLM produces language-based loss, and the backward pass backpropagates the augmented textual gradient through all nodes. This design avoids explicit numerical Hessian computation while capturing gradient-curvature effects, enabling the system to escape local optima and maintain stable, progressive refinement across iterations.

## Results

On prompt optimization, REVOLVE achieves 95.5% accuracy on Object Counting (GPT-3.5) and 85.9% on GSM8K (GPT-3.5), outperforming TextGrad by 3.9% and 6.2% respectively. On solution optimization with Llama 3.1 8B Instruct, REVOLVE reaches 28.3% on GPQA, 57.1% on MMLU-Machine Learning, and 66.4% on MMLU-College Physics, yielding a 17.79% average relative improvement over TextGrad. On code optimization (LeetCode Hard), REVOLVE attains a 0.31 completion rate with Llama 3.1 8B Instruct, a 29.17% improvement over TextGrad (0.24) and 16.67% over Reflexion (0.20).

## Baselines & Comparisons

REVOLVE consistently outperforms Zero-shot CoT across all tasks and models, with the largest gaps on weaker models (e.g., +17.7% on Object Counting with Llama 3.1 8B: 83.0% vs. 65.0%). Against TextGrad, REVOLVE wins on most configurations, with the most dramatic gains on solution optimization (19.41% relative improvement on GPQA with Llama 3.1: 28.3% vs. 23.7%) and code optimization (29.17% on LeetCode Hard with Llama 3.1: 0.31 vs. 0.24 completion rate). The one notable exception is GSM8K with Gemini 1.5 Pro, where REVOLVE slightly trails TextGrad (93.0% vs. 93.3%), likely due to cross-model guidance from GPT-4o. Against Reflexion on code optimization, REVOLVE surpasses it on all three LLM backends (e.g., 0.31 vs. 0.20 with Llama 3.1, 0.56 vs. 0.41 with GPT-4). Momentum-Enhanced TextGrad shows intermediate performance but exhibits instability and oscillations across iterations, whereas REVOLVE provides smoother, more consistent gains.

## Relation to Prior Work

REVOLVE extends the TextGrad framework (Yuksekgonul et al., 2024) by augmenting its first-order textual gradient with a response-evolution term that tracks how outputs shift across consecutive iterations. Conceptually, it draws an analogy to second-order (Hessian-based) optimization in classical numerical methods, though it does not compute actual second derivatives; instead, it uses an LLM-evaluated similarity function between successive responses to simulate curvature information. This positions it beyond ProTeGi, Agent Symbolic Learning, and momentum-enhanced TextGrad, which all rely on immediate or feedback-trend signals without explicitly modeling response trajectory dynamics.

## Why It Matters / Open Questions

The paper demonstrates that a relatively simple addition—feeding past-iteration responses into the optimization prompt—consistently improves over first-order textual optimization across prompt, solution, and code optimization tasks, with the largest gains on weaker models (e.g., ~20–29% relative improvement for Llama 3.1 8B). However, the mathematical derivation connecting the similarity function to a true second-order derivative is informal, and the 'second-order' label is more of an analogy than a rigorous formulation. Open questions include whether this approach generalizes to multi-variable agent systems with many interacting components, whether the gains persist at scale with frontier models, and whether the convergence-speed advantage (fewer iterations to converge) holds under different task distributions.
