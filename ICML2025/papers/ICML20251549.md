## Problem

While Chain-of-Thought (CoT) prompting—generating reasoning steps before a final answer—has proven effective for math and logic tasks, its role in code generation during Supervised Fine-Tuning remains largely unexplored. This paper investigates whether the traditional CoT-before-answer paradigm actually benefits code generation, and finds the counterintuitive result that it does not: forcing the model to produce natural-language reasoning before code degrades performance, while the reverse order (code first, CoT as explanation) improves it.

## Input / Output

The model receives a natural language programming problem description and, depending on the SFT strategy, outputs either code alone, CoT followed by code (C_follow), or code followed by CoT (C_precede). The synthetic training dataset of 50K pairs explicitly separates the reasoning trace from the code solution, enabling controlled comparison of output ordering; maximum sequence length is 4096 tokens. Evaluation uses Pass@k (primarily Pass@1 under greedy decoding) on benchmarks including HumanEval+, MBPP+, LiveCodeBench, BigCodeBench, and MultiPL-E.

## Method

The paper's core contribution is a controlled empirical study demonstrating that placing code before CoT in SFT data (C_precede) yields a 9.86% relative improvement over the traditional CoT-then-code order (C_follow). They synthesize a 50K dataset by using DeepSeek-V2.5-1210 as a teacher model via context distillation with few-shot prompting, applying self-consistency filtering to retain only code that passes its own generated test cases. Four SFT strategies are compared—seed data, code-only, C_follow, and C_precede—across multiple base models (DeepSeek-Coder-6.7B/33B, Qwen2.5-Coder-32B), teacher models, and data sources. Mechanistic analyses (conditional perplexity gap, attention weight matrices, per-layer gradient norms, KL divergence) reveal that code-first ordering narrows the learning-difficulty gap between the two output segments and prevents the overthinking behavior that arises when flexible natural-language CoT is generated before the syntactically constrained code. The findings generalize across model sizes, difficulty levels (Easy/Medium/Hard LeetCode), Pass@k values, and temperatures, and are confirmed by LLM-as-a-Judge preference evaluations.

## Results

On the EvalPlus benchmark (HumanEval+ and MBPP+), the C_precede strategy (code before CoT) achieves an average Pass@1 of 71.88%, a 9.86% relative improvement over the traditional C_follow strategy (65.43%). C_precede also outperforms the Seed baseline (68.40%) and the code-only C_w/o strategy (70.88%). On LiveCodeBench, C_precede leads across all contamination-controlled subsets (e.g., 24.16% vs. 23.07% for C_follow on the 2023-05-01 subset), and on BigCodeBench it achieves 38.33% (Full) and 16.22% (Hard), again the best among all strategies.

## Baselines & Comparisons

The paper compares four SFT data strategies: Seed (original question–response pairs), C_w/o (code only, no CoT), C_follow (CoT before code, the traditional paradigm), and C_precede (code before CoT). C_precede consistently outperforms all other strategies across every benchmark tested. Notably, C_follow is actually worse than the Seed baseline (65.43 vs. 68.40 average on EvalPlus), indicating that forcing the model to generate reasoning text before code actively degrades code generation performance. C_w/o, which removes CoT entirely, is competitive (70.88) but still trails C_precede by 1.0 points, showing that the CoT explanation adds value when placed after the code. The 9.86% relative gap between C_precede and C_follow is the paper's headline finding, and it holds across different base models (DeepSeek-Coder-6.7B, 33B; Qwen2.5-Coder-32B), different teacher models (DeepSeek-V2.5, GPT-4o), different data sources (instruction datasets, Stack), and different difficulty levels (LeetCode Easy/Medium/Hard).

## Relation to Prior Work

This paper builds on the classic Chain-of-Thought (CoT) training paradigm (Wei et al., 2022), which organizes reasoning steps before the final answer, and the context distillation methodology (Snell et al., 2022) for synthesizing SFT data from a teacher model. However, it deliberately departs from the standard CoT ordering by hypothesizing and empirically demonstrating that for code generation, the code solution itself already constitutes the reasoning process, and that placing CoT *after* the code (as an explanation) outperforms the traditional before-answer ordering. The work also extends prior CoT-for-code studies (Li et al., 2023a; Jiang et al., 2023; Yang et al., 2024a), which focused on prompting strategies at inference time, by investigating the SFT training stage and data ordering effects.

## Why It Matters / Open Questions

The finding that a 9.86% relative improvement comes from simply reversing the CoT-code order in SFT data provides an immediately actionable guideline for practitioners building code LLMs, and challenges the widely-held assumption that reasoning must precede the answer. The conceptual insight—that high-quality code *is* the reasoning process and traditional CoT should be treated as post-hoc explanation—may reshape how training data is structured for code generation pipelines. Open questions include whether this ordering principle generalizes to other structured-output domains (math proofs, formal logic), how it interacts with reinforcement learning from execution feedback, and whether the benefit persists as models scale further or when CoT involves genuinely multi-step algorithmic planning that cannot be captured by the code alone.
