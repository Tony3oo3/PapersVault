## Problem

Despite widespread integration of map services with foundation models, no prior benchmark has rigorously evaluated LLMs and VLMs on complex geo-spatial reasoning tasks involving spatial relationships, multi-step navigation, travel planning, and visual map interpretation. Existing benchmarks either rely on template-based database queries, test only simple distance/nearby lookups, or focus on remote sensing imagery rather than interactive digital map views, leaving a critical gap in assessing whether foundation models can handle the heterogeneous, compositional reasoning that real-world map interactions demand.

## Input / Output

MapEval provides three input modalities: (1) long textual contexts (avg. 436 words, max 1500) containing POI coordinates, opening hours, distances, and user reviews; (2) Google Maps snapshot images captured at zoom levels 8–21, showing routes, landmarks, symbols, and OCR-readable text; and (3) five Google Maps APIs (Text Search, Place Details, Nearby Search, Directions, Distance Matrix) accessed through a ReAct agent in a pseudo-Google Maps environment with cached responses for 13,000+ locations. All 700 questions are multiple-choice with 2–7 options (avg. 4.0), and the output is a selected option index with a free-text explanation, scored by exact-match accuracy.

## Method

MapEval is a 700-question benchmark spanning 180 cities and 54 countries, organized into three task variants—Textual (300 MCQs answered from pre-fetched context), API (same 300 questions but requiring a ReAct agent to call map APIs without textual context), and Visual (400 MCQs answered from map snapshot images)—covering six question categories: Place Info, Nearby, Routing, Trip planning, Unanswerable, and Counting. Data was annotated using MapQaTor, a custom web interface that automates Google Maps API calls to collect ground-truth context, with quality control via multi-annotator agreement (76% initial) and LLM-based filtering of trivially easy or ambiguous items. The paper evaluates 30 foundation models (closed-source LLMs/VLMs and open-source LLMs/VLMs) and additionally probes failure modes through targeted sub-analyses (straight-line distance, cardinal direction, counting), tool-augmented inference (Haversine calculator, Chameleon multi-agent framework), and fine-tuning experiments on a 97-question subset, revealing that no model exceeds 67% overall accuracy and all lag over 20% behind human performance (86.67% textual, 82.23% visual).

## Results

Across 30 foundation models evaluated on MapEval, no model surpasses 67% accuracy on any task, and all models lag over 20% behind human performance (86.67% Textual, 82.23% Visual). On MapEval-Textual, Claude-3.5-Sonnet and Gemini-1.5-Pro tie at 66.33% overall accuracy, while the best open-source model (Llama-3.1-70B) reaches 61.00%. On MapEval-API, Claude-3.5-Sonnet leads at 64.00%, outperforming GPT-4o (48.67%) and Gemini-1.5-Pro (43.33%) by 16% and 21% respectively. On MapEval-Visual, Claude-3.5-Sonnet achieves 61.65%, followed by GPT-4o (58.90%) and the best open-source VLM Qwen2.5-VL-72B (60.35%).

## Baselines & Comparisons

Among closed-source LLMs, Claude-3.5-Sonnet and Gemini-1.5-Pro tie at 66.33% on MapEval-Textual, with Claude-3.5-Sonnet further dominating MapEval-API (64.00% vs. GPT-4o's 48.67% and Gemini-1.5-Pro's 43.33%). GPT-4o is the strongest closed-source model on MapEval-Visual (58.90%), narrowly ahead of Gemini-1.5-Pro (56.14%). Among open-source models, Llama-3.1-70B (61.00% Textual) and Qwen2.5-VL-72B (60.35% Visual) are the top performers, but both trail the best closed-source models by 5–6 percentage points. A critical gap emerges in the API task, where the best open-source model (Llama-3.2-90B at 39.67%) lags Claude-3.5-Sonnet by 24.33 percentage points, and smaller open-source models (Gemma-2.0-9B at 27.00%) fall below 30%. All 30 models underperform humans by over 20 percentage points across every task, with the largest gaps in Trip planning (best model ~49% vs. human 88.06% on Textual) and Routing on Visual (best model 50% vs. human 85.18%), exposing fundamental limitations in multi-step spatio-temporal reasoning and fine-grained map interpretation.

## Relation to Prior Work

This paper carves new ground by introducing the first benchmark specifically targeting geospatial reasoning in foundation models, departing from template-based GeoQA systems (GeoQA, GeoQuestions1089) that classify queries into fixed patterns and query static databases, and from tool-calling benchmarks (ToolBench, API-Bank, Travel Planner) that use map APIs only for simple distance or POI lookups. It also distinguishes itself from remote sensing VQA work (RSVQA, SatlasPretrain, GeoRS-CLIP) by focusing on interactive digital map views rather than satellite imagery. The evaluation protocol repurposes existing agent frameworks (ReAct, Chameleon) and MCQ evaluation paradigms (MMLU-style) for a new domain, while the annotation tool MapQaTor automates data collection from five Google Maps APIs to ensure consistency.

## Why It Matters / Open Questions

MapEval exposes a substantial and consistent gap (>20%) between even the best foundation models and human performance across spatial, temporal, and commonsense geospatial reasoning, providing a concrete target for future geospatial AI research. The finding that calculator integration dramatically improves distance/direction accuracy (51%→85%) suggests that tool-augmented architectures are a practical near-term path, while the Trip-planning improvement with API access (+22%) hints that step-by-step tool interaction can compensate for weak internal spatial models. Key limitations include reliance on only five Google Maps APIs, static cached data that may become stale, and MCQ-only evaluation; open questions include whether specialized geospatial pretraining or larger context windows can close the human gap, and how findings generalize beyond Google Maps to other map services or 3D environments.
