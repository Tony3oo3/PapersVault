## Problem

While LLMs have demonstrated strong capabilities on high-level source code tasks, their ability to comprehend compiler Intermediate Representations (IRs)—which encode low-level control flow dependencies, instruction-level semantics, and memory operations in SSA form—remains entirely unexplored. This paper poses the question of whether current LLMs can structurally parse, semantically interpret, and dynamically reason over IRs, filling a gap between source-code understanding and the IR-level analysis required for compiler design and program analysis.

## Input / Output

The input consists of LLVM IR functions (in SSA form) generated from 164 C++ HumanEval programs compiled with Clang at four optimization levels (-O0 through -O3), yielding IRs ranging from verbose unoptimized code to aggressively restructured optimized code. For execution reasoning, the IR is augmented with specific input values and assertion statements. Outputs are task-specific: CFGs in DOT graph format (nodes as basic blocks, edges as control transfers), syntactically valid C/C++ source code, structured natural-language function summaries following a fixed template, and per-assertion pass/fail predictions with intermediate reasoning traces.

## Method

The paper introduces a four-task empirical evaluation framework (CFG reconstruction, IR decompilation, code summarization, execution reasoning) to probe three dimensions of IR comprehension: structural understanding, syntactic/semantic comprehension, and dynamic execution reasoning. Six LLMs (GPT-4, GPT-3, DeepSeek R1, Gemma 2, Llama 3.1, Code Llama) are evaluated using expert meta-template prompts with explicit role assignments, few-shot examples, and chain-of-thought guidance, iteratively refined for each task. Evaluation metrics are task-specific: node/edge/loop/branch accuracy for CFGs, re-execution success rates for decompilation, BLEU/ROUGE-L/METEOR for summarization, and assertion-level pass rates for execution reasoning. A key design choice is the counterfactual comparison in execution reasoning, where models receive both IR and the corresponding source code to isolate the representational gap. The study further analyzes failure modes (heuristic guessing, loop misinterpretation, instruction omission) and examines how CFG graph density correlates with model success, revealing that LLMs approximate execution through high-level semantic steps rather than simulating instruction-level behavior.

## Results

Across four IR comprehension tasks on 164 HumanEval-derived LLVM IRs, no LLM achieves strong performance. For CFG reconstruction (Task 1), DeepSeek R1 leads with 57/77 full accuracy (74% of completed), while GPT-4 manages only 39/164 (24%) and Code Llama scores 0. For execution reasoning (Task 4), all models show a stark IR-vs-source-code gap: GPT-4 achieves a 0.36 pass rate on IR but 0.72 on source code; Code Llama reaches 0.80 on source code but only 0.27 on IR. In code summarization (Task 3), DeepSeek R1 attains the best average scores (BLEU 0.42, ROUGE-L 0.64, METEOR 0.705), yet high-quality summaries (score >0.8) are rare—each model produces at most 21 (GPT-4, METEOR). In decompilation (Task 2), re-execution success peaks at 15/164 (GPT-4, -O0) and drops to 0–4 for most models at -O3.

## Baselines & Comparisons

The paper evaluates six LLMs (GPT-4, GPT-3, DeepSeek R1, Gemma 2, Llama 3.1, Code Llama) as baselines across four IR tasks. On CFG reconstruction, DeepSeek R1 outperforms GPT-4 (57 vs. 39 full accuracy) despite completing fewer cases (77 vs. 164), likely due to its built-in CoT reasoning; GPT-3, Gemma 2, and Llama 3.1 cluster around 14–16, and Code Llama fails entirely (0). On execution reasoning, GPT-4 leads on IR (59 passes, 0.36 rate) while Code Llama leads on source code (131 passes, 0.80 rate), benefiting from code-specific pretraining; GPT-3 is a clear outlier with only 7 IR passes (0.04 rate). For code summarization, DeepSeek R1 achieves the highest average BLEU/ROUGE-L/METEOR (0.42/0.64/0.705), narrowly ahead of Llama 3.1 (0.39/0.61/0.67) and GPT-4 (0.35/0.56/0.63), while GPT-3 and Code Llama lag (0.24–0.25 BLEU). In decompilation, GPT-4 completes the most tasks (161–164 across optimization levels) and achieves the highest re-execution success (15 at -O0), whereas Code Llama fails on 99 of 164 cases at -O0 due to context-length overflow. Overall, no single model dominates all tasks, and all models perform substantially worse on IR than on equivalent source code, confirming a systematic IR comprehension gap.

## Relation to Prior Work

This paper carves new ground at the intersection of LLMs and compiler infrastructure. Prior IR representation learning (IR2Vec, FAIR, inst2vec) relied on specialized architectures like GNNs and skip-gram embeddings, while prior LLM-for-code work (GPT-4, Code Llama, CodeT5) targeted high-level source languages. No prior study has systematically evaluated general-purpose LLMs on IR-specific comprehension tasks such as CFG reconstruction, IR decompilation, and instruction-level execution reasoning. The paper thus repurposes established code-understanding tasks (decompilation, summarization, execution prediction) by shifting the input modality from source code or binary to LLVM IR, and introduces a structured four-task benchmark aligned with three research questions.

## Why It Matters / Open Questions

The study provides the first empirical evidence that current LLMs, even GPT-4, exhibit a fundamental gap in IR comprehension: they approximate execution through high-level semantic shortcuts rather than simulating instruction-level behavior, and they systematically fail on control-flow-sensitive reasoning (loops, branches). This has direct implications for the growing use of LLMs in compiler design, vulnerability detection, and binary analysis, where IR is the natural operating representation. Key limitations include the reliance on HumanEval-derived IRs (relatively short programs), a limited model set, and the absence of concrete IR-specific training solutions. Open questions include whether IR-specific fine-tuning, graph-based architectures, or execution-trace supervision can close the observed gap between source-code and IR reasoning performance.
