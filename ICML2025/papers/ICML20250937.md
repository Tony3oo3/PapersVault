## Problem

Static structured pruning fixes a single mask for the entire model, forcing a trade-off between efficiency and performance across diverse tasks (coding, math, domain-specific queries). The paper asks whether an LLM can learn to dynamically select the most relevant parameters based on the task described in a user prompt, achieving near-9B performance while activating only 3B parameters.
![Teaser figure](../imgs/ICML20250937/cropped_page1_idx0.webp)

## Input / Output

The method takes a user prompt (raw question, few-shot examples plus question, or a task description) and the full weights of a 6B/9B/12B LLM. The sparsity predictor (302M params) produces a binary mask of shape L×d_ffn that selects exactly t_ffn FFN dimensions per layer, reducing the model to 3B active parameters. Unlike MoE or contextual sparsity, the mask is computed once before decoding and remains fixed for the entire generation, so the selected sub-network is cached like a dense model and no per-token parameter reloading occurs.

## Method

IFPRUNING couples a lightweight sparsity predictor (a 302M LLM backbone whose last-token hidden state feeds a two-layer MLP head) with a dense LLM whose FFN blocks are pruned via row/column masks. The predictor outputs per-layer masking scores that are converted to differentiable binary masks through the SoftTopK operator, enforcing an exact sparsity budget (e.g., 6656 of 16384 FFN dimensions for the 6B model). Training proceeds in two stages: continued pre-training, where consecutive text chunks are used to predict masks for the next chunk's next-token prediction, followed by supervised fine-tuning on instruction-following data. Both the predictor and the LLM are co-optimized end-to-end with cross-entropy loss. At inference, the mask is generated once per input (or per task via a single task-level instruction) and the resulting sub-network is cached, yielding inference latency on par with a static 3B dense model while delivering 5–8 point gains on math and coding benchmarks.

## Results

IFPRUNING (9B→3B) activates only 3B parameters yet outperforms the DENSE-3B baseline by 7.7 points on coding (42.0 vs 34.3 avg), 4.9 points on MATH (36.7 vs 31.8), 3.7 points on MMLU (65.5 vs 61.8), and 4.0 points on AlpacaEval 2.0 (31.3 vs 27.3). Against the DENSE-9B upper bound, the 9B→3B model achieves 42.4 on HumanEval (vs 46.5), 36.7 on MATH (vs 37.3), and 65.5 on MMLU (vs 67.8), showing only marginal degradation. Inference latency is reduced by up to 57% in TTFT and 41% in decode time compared to the full 9B model, with dynamic pruning overhead of less than 0.1s per example.

## Baselines & Comparisons

IFPRUNING consistently outperforms the DENSE-3B baseline (trained on 9T tokens, 3x more than IFPRUNING's 5T) across nearly all benchmarks: +7.7 on coding average, +4.9 on MATH, +3.7 on MMLU, and +4.0 on AlpacaEval for the 9B→3B variant. Against the stronger PRUNING+DISTILL 3B baseline (which benefits from knowledge distillation from a 12B teacher), IFPRUNING 9B→3B still wins by +5.3 on HumanEval, +4.0 on MATH, +2.7 on MMLU, and +1.3 on AlpacaEval. Compared to the DENSE-9B upper bound, the 9B→3B model shows only small gaps: −4.1 on HumanEval, −0.6 on MATH, and −2.3 on MMLU, while the 12B→3B variant narrows these further (−3.2 HumanEval, −0.2 MATH, −1.7 MMLU). Performance scales with source model size: going from 6B→3B to 12B→3B yields steady gains on coding, math, and MMLU, though AlpacaEval shows less improvement. The method also demonstrates that per-task masks (a single mask shared across all inputs in a domain) incur less than 1% degradation versus per-input masks, confirming robustness.

## Relation to Prior Work

This paper extends the static structured pruning paradigm (Wang et al., 2020; Sheared LLaMA, Xia et al., 2024) by replacing the fixed binary mask with a learned, input-dependent mask generated by a lightweight sparsity predictor. It borrows the SoftTopK differentiable top-k operator (Ainslie et al., 2023; Lei et al., 2023) for mask generation and the co-optimization strategy from Sheared LLaMA, but departs from both contextual sparsity (Liu et al., 2023) and mixture-of-experts (Fedus et al., 2022) by selecting parameters once per input or task rather than per decoding step, eliminating the per-token weight-loading overhead. The method is specifically designed for on-device deployment where a single query generates a few responses, making the fixed-per-input mask a practical advantage over per-token routing.

## Why It Matters / Open Questions

The practical impact is significant for on-device LLM deployment: a 3B-activated model pruned from a 9B backbone matches or exceeds a 9B dense model on coding, math, and MMLU while running at 3B latency, with negligible (<0.1s) overhead from dynamic mask generation. The per-task pruning capability—where a single human-written instruction selects a shared sub-network for an entire benchmark—suggests the learned masks encode interpretable domain structure, opening the door to task-specialized model variants without retraining. Open questions include how the approach scales to server-side batch serving with heterogeneous tasks, whether contrastive or auxiliary losses could sharpen domain-specificity, and whether the method extends cleanly to pruning attention heads or hidden dimensions rather than FFN intermediate dimensions.
