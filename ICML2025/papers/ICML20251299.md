## Problem

Equivariant MLIPs achieve state-of-the-art accuracy for molecular dynamics simulations, but their Tensor-Product layer accounts for up to 89% of inference time and 75% of training time while causing severe memory overhead. Three specific inefficiencies drive this bottleneck: memory traffic from intermediate data exchanged between multiple kernels, peak memory spikes from the large output tensor (whose hidden dimension grows an order of magnitude), and ineffectual computation from the 71–86% sparsity of the Clebsch-Gordan coefficient matrix.

## Input / Output

FlashTP is a drop-in GPU library that replaces the Tensor-Product layer within existing equivariant MLIP frameworks (e.g., e3nn-based SevenNet). It consumes the same graph-structured inputs—node hidden states (per-atom features), edge angular features (spherical harmonic coefficients), and radial edge features (MLP-processed distances)—and produces the updated edge-level hidden states that are subsequently reduced to node-level representations. A key structural detail is that the Tensor-Product layer operates on edges (n_edges × n_ch × n_path individual tensor-products), and its output hidden dimension d_i' is roughly an order of magnitude larger than the input d_i, which is what causes the memory spikes FlashTP eliminates.

## Method

FlashTP applies three complementary GPU optimizations to the Tensor-Product layer. First, it performs two-level kernel fusion: intra-layer fusion collapses all forward/backward/double-backward kernels into a single pass by processing each non-zero CG coefficient entry in one go (two-phase accumulation), and inter-layer fusion merges the Tensor-Product with the subsequent reduce layer using atomic-add operations to handle multiple edges mapping to the same destination node. Second, it exploits CG matrix sparsity by storing the matrix in COO format with a deduplicated value table (8-bit indices replacing 32-bit floats), iterating only over non-zero entries. Third, it introduces path-aggregation, which groups tensor-product paths sharing the same hidden-state subvector so that input data is read from memory only once rather than once per path. The library is parallelized with one path per thread block (to avoid constant-memory cache evictions) and same-path-different-channel/edge assignments within a warp, and it integrates with e3nn via a minimal code change preserving the same matrix storage ordering.

## Results

For the state-of-the-art SevenNet-l3i5 model on the MPF dataset, FlashTP achieves 4.2× faster inference and 3.5× faster training compared to e3nn, while reducing peak memory by 6.3× (inference) and 6.2× (training). In the kernel microbenchmark (Table 2), FlashTP delivers average speedups of 6.75×, 14.37×, and 26.54× over e3nn for the forward, backward, and double-backward phases respectively (fp32), with peak kernel speedups reaching 41.6× (fp64, l_max=4, double-backward). For end-to-end MD simulation, FlashTP supports up to 28K atoms—4.7× more than e3nn and 3.1× more than cuEquivariance—before hitting out-of-memory limits.

## Baselines & Comparisons

FlashTP consistently outperforms both baselines across all model sizes and all phases (forward, backward, double-backward). Against e3nn, FlashTP achieves 1.6×, 3.5×, and 6.7× training speedups for l2i5, l3i5, and l4i5 respectively, with peak memory reduced by 4.2×, 6.2×, and 8.4×. Against NVIDIA cuEquivariance, FlashTP is 1.15×, 4.41×, and 11.19× faster for the same three configurations; cuEquivariance is competitive only at l_max=2 (where its shared-memory strategy is effective) but degrades sharply at higher l_max due to memory footprint constraints. In the kernel microbenchmark, cuEquivariance actually runs slower than e3nn for l_max≥3 in several phases (e.g., 0.9× in backward at l_max=3), while FlashTP maintains 13–40× speedups. For end-to-end MD inference at 4K atoms, FlashTP is 4.2× faster than e3nn and 6.2× faster than cuEquivariance, while using 6.3× and 4.3× less peak memory respectively.

## Relation to Prior Work

FlashTP is a system-level optimization of the Clebsch-Gordan tensor product that is the core operation in equivariant MLIPs (NequIP, MACE, SevenNet). It builds directly on e3nn's TensorProduct interface as a drop-in replacement and competes with NVIDIA's cuEquivariance library, but distinguishes itself from mathematical reformulations of the tensor product (SO(2) alignment, Gaunt tensor products, Fused Tensor Products) by addressing the same CGTP formulation through kernel fusion, sparse CG-matrix exploitation, and path-aggregated execution. The paper explicitly notes that its sparsity optimization is orthogonal to and complementary with approaches like SO(2) that reduce the number of non-zero CG elements.

## Why It Matters / Open Questions

The Tensor-Product layer dominates 75–89% of compute time in state-of-the-art equivariant MLIPs, making it the critical bottleneck for scaling MD simulations to larger systems. FlashTP's 4.2× inference speedup and 6.3× peak-memory reduction (enabling 28K-atom simulations vs. ~6K for e3nn) are practically transformative for materials science workflows. However, the roofline analysis reveals a 2–3× gap to theoretical limits, and the OOM at 28K atoms originates from the unoptimized e3nn Linear layer rather than the Tensor-Product layer, indicating further headroom. Open questions include whether path-aggregation generalizes to other equivariant architectures and whether combining FlashTP with SO(2) or Gaunt-based reformulations yields multiplicative gains.
