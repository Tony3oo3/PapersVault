## Problem

While AI-for-math has made significant progress in pure mathematics (geometry, number theory, combinatorics), applied mathematics—particularly PDE control—remains largely unexplored by LLMs. Traditional PDE control requires substantial human effort to formalize problem descriptions into specifications and demands specialized knowledge in both coding and physics. The paper asks whether LLMs can perform scientific reasoning to automate and improve open-loop PDE control, bridging the gap between natural language instructions and physically meaningful control actions.

## Input / Output

The system takes a natural language description of a 1D PDE control problem (heat or wave equation) specifying material properties, geometry, initial/boundary conditions, and spatiotemporal constraints. It produces a three-stage output: (1) a formal Signal Temporal Logic (STL) specification using G/F temporal operators over linear constraints ax+b with spatial and temporal ranges, (2) a novel subgoal STL that serves as an intermediate reasoning step, and (3) executable Python code that interfaces with the Gurobi MILP solver. The final evaluation metric is a continuous utility score r(φ) ∈ ℝ computed via STL continuous semantics, where r > 0 indicates the constraint is satisfied.

## Method

PDE-Controller is a three-LLM pipeline built on MathCoder2-DeepSeekMath-7B with LoRA fine-tuning. The Translator (SFT) autoformalizes natural language into STL; the Coder (SFT) synthesizes Python code from NL+STL pairs for Gurobi-based MILP optimization; and the Controller (DPO/RLHF) proposes subgoal STLs as intermediate reasoning steps. The key insight is that PDE control is non-convex, so directly optimizing the target constraint may yield suboptimal solutions; instead, the Controller proposes a subgoal φ′ whose solution produces a new system state that serves as a better initial condition for solving the original problem φ. The Controller is trained via Direct Preference Optimization on 10,772 win-lose STL pairs where preferences are determined by PDE simulation utility (r(φ|φ′) > r(φ)), with the Translator serving as the frozen reference model. The framework is trained on 2.13 million synthetic (NL, STL, Python) triplets spanning 1,374 STL syntax formats for heat and wave equations, augmented with ChatGPT paraphrasing for linguistic diversity.

## Results

On the PDE-Controller dataset, the trained Controller achieves a 62% improvement in utility gain over the best baseline (GPT-4o) on Heat problems (Δr̄ = 1.453 vs. 0.897) and a 13% improvement on Wave (0.658 vs. 0.583). The Controller also achieves the highest success rate (P̄ = 0.812 on Heat, 0.699 on Wave) and by far the highest ratio of valid subgoal STLs (82.70% vs. 42.45% for MathCoder2, 2.55% for GPT-4o, and 0.04% for GPT o1-mini). For autoformalization, the Translator reaches 99.2% IoU on synthetic data and 64–71% IoU on manually written problems; the Coder achieves 99.78% executability and 0.0173 utility RMSE on synthetic Heat problems.

## Baselines & Comparisons

Against MathCoder2 (the base model before fine-tuning), PDE-Controller wins on every metric: +28.5% IoU for autoformalization, +4% executability, 91.6% lower utility RMSE for code generation, and substantially higher success rate and utility gain for reasoning (e.g., Δr̄ = 1.453 vs. −0.093 on Heat). Against GPT-4o, the Controller achieves a 62% higher utility gain on Heat (1.453 vs. 0.897) and a 13% higher gain on Wave (0.658 vs. 0.583), while GPT-4o edges ahead on Wave success rate (0.773 vs. 0.699) but produces far fewer valid STLs (2.55% vs. 82.70%). GPT o1-mini fails entirely on the reasoning task, generating essentially no valid subgoal STLs (0.04% valid rate) and showing poor code executability (35–40%), making its low utility RMSE misleading since it is computed only over the small fraction of executable outputs. On manually written problems, all baselines degrade significantly, but the trained models still outperform them: the Translator achieves 64–71% IoU (vs. 20–34% for MathCoder2) and the Coder reaches 82–100% executability (vs. 35–59% for GPT models).

## Relation to Prior Work

This paper sits at the intersection of three research threads: AI-for-math autoformalization (converting informal statements to formal logic, as in Isabelle/Lean4 or STL translation), classical PDE control via formal methods (STL + MILP solvers like Gurobi), and LLM-based task planning with subgoal decomposition (as in robotics LTL planning). It builds directly on MathCoder2 as a base model and adapts DPO for preference-based reasoning, but departs from prior AI-for-math work by targeting applied mathematics (PDEs) rather than pure mathematics, and from prior PDE control by replacing manual formalization and expert coding with LLM-generated specifications and programs. The subgoal reasoning strategy draws on planning literature (robotics, theorem proving) but is the first application to open-loop PDE control.

## Why It Matters / Open Questions

The paper introduces the first large-scale (2M+ samples) dataset and end-to-end framework for LLM-based PDE control, providing a testbed for future AI-for-applied-math research. However, the scope is limited to 1D heat and wave equations with at most 3 constraints, and performance degrades substantially on manually written problems (IoU drops from 0.99 to ~0.7). Open questions include whether the subgoal reasoning approach generalizes to higher-dimensional PDEs, coupled systems, or closed-loop control, and whether the DPO-trained Controller's reasoning transfers beyond the narrow STL syntax it was trained on. The 62% utility gain headline is somewhat inflated by very weak GPT baselines that generate almost no valid STLs.
