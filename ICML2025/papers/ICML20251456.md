## Problem

Zero-shot Text-to-SQL requires LLMs to map natural language questions to SQL over arbitrary database schemas without task-specific fine-tuning, but existing zero-shot methods struggle with complex schema relationships, multi-step query construction, and maintaining robustness across diverse databases. Fine-tuning-based approaches are costly and must be redone as new LLMs emerge, making a plug-and-play, fine-tuning-free framework that can boost small open-source models highly desirable.
![Teaser figure](../imgs/ICML20251456/cropped_page1_idx0.webp)

## Input / Output

The method consumes a natural language question, a full database schema (tables, columns, primary/foreign key relationships, column descriptions, and value examples), and retrieved database values (via offline MinHash signatures and online LSH-based semantic matching). The LLM-as-Action-Model processes these inputs incrementally across MCTS nodes, where each node stores a partial reasoning state (prior CoT thoughts + partial SQL). The final output is a single SQL query selected by highest execution-result self-consistency score among all candidate queries generated across MCTS rollouts.

## Method

Alpha-SQL formulates Text-to-SQL as a tree search over partial reasoning states, where edges are SQL construction actions and paths from root to leaf yield complete SQL queries. It employs MCTS with UCT to balance exploration and exploitation, using an LLM-as-Action-Model that generates Chain-of-Thought reasoning at each node across seven ordered actions (question rephrasing, schema selection, column value identification, column function identification, SQL generation, SQL revision, and termination). A self-supervised reward function scores candidate SQL by comparing execution results of the predicted query against N high-temperature resampled queries, requiring no labeled data. Database value retrieval via MinHash/LSH enriches the schema context, and pruning strategies (e.g., deduplicating identical schema selections) control the branching factor. With just 24 MCTS rollouts, the framework explores over 3000 possible reasoning paths and achieves 69.7% execution accuracy on BIRD dev using a 32B open-source LLM without any fine-tuning.

## Results

On the BIRD development set, Alpha-SQL with Qwen2.5-Coder-32B achieves 69.7% execution accuracy in a zero-shot setting, outperforming the best prior zero-shot method RSL-SQL (GPT-4o, 67.2%) by 2.5%. With the smaller 7B model, Alpha-SQL still reaches 66.8%, surpassing fine-tuned methods like CHESS-SQL (65.0%) and MCS-SQL (64.4%). On the Spider development set, Alpha-SQL with Qwen2.5-Coder-14B achieves 87.0% execution accuracy, matching SuperSQL (GPT-4) and outperforming the fine-tuned SFT CodeS-15B (84.9%) by 2.1%. On the SDS subset, Alpha-SQL boosts Qwen2.5-Coder-7B from 47.6% to 64.6% (+17.0%) and Phi-4 from 43.5% to 60.0% (+16.5%) over direct prompting.

## Baselines & Comparisons

Among zero-shot methods on BIRD, Alpha-SQL (32B, 69.7%) outperforms RSL-SQL (GPT-4o, 67.2%) by 2.5%, MCS-SQL (GPT-4, 64.4%) by 5.3%, SuperSQL (GPT-4, 58.5%) by 11.2%, and DAIL-SQL (GPT-4, 55.9%) by 13.8%. Even the 7B variant (66.8%) surpasses MCS-SQL and CHESS-SQL (65.0%) while nearly matching RSL-SQL. Against fine-tuned methods, Alpha-SQL (32B) is outperformed only by CHASE-SQL (73.0%, fine-tuned Gemini-1.5-Flash) and XiYan-SQL (73.3%, fine-tuned unknown model), but exceeds Distillery (GPT-4o, 67.2%) and all SFT CodeS variants. On Spider, Alpha-SQL (14B, 87.0%) ties SuperSQL (GPT-4, 87.0%) and beats MAC-SQL (86.8%), ZeroNL2SQL (84.0%), DAIL-SQL (83.6%), DIN-SQL (82.8%), and C3-SQL (82.0%), while also surpassing the fine-tuned SFT CodeS-15B (84.9%) by 2.1%.

## Relation to Prior Work

Alpha-SQL positions itself at the intersection of test-time computation (MCTS, Tree-of-Thoughts) and zero-shot Text-to-SQL. It builds directly on MCTS (Coulom, 2006) as the search backbone, borrows the Divide-and-Conquer CoT strategy from CHASE-SQL for its SQL Generation action, adopts CHESS-SQL's schema selection and two-stage database value retrieval (MinHash/LSH), and draws on rStar (Qi et al., 2024) for question rephrasing and the self-consistency reward concept. The key departure from prior zero-shot methods (DAIL-SQL, C3, RSL-SQL) and even from CHASE-SQL is the framing of SQL construction as a progressive, tree-structured search problem where an LLM acts as a dynamic action model at each node, rather than a fixed multi-step pipeline or single-shot generation.

## Why It Matters / Open Questions

The practical significance is that a 32B open-source model (Qwen2.5-Coder) can match or exceed GPT-4o-based zero-shot Text-to-SQL without any fine-tuning, and even a 7B model approaches GPT-4o performance—offering a cost-effective, plug-and-play alternative for organizations that cannot or do not want to fine-tune. However, the approach requires 24 MCTS rollouts with multiple LLM calls per node and database execution access for the self-consistency reward, making it computationally expensive at inference time and inapplicable to read-only or sandboxed database environments. Open questions include how the method scales to very large schemas with hundreds of tables, whether the self-consistency reward degrades on databases where execution is costly or restricted, and whether the structured action space generalizes beyond SQL to other structured-output tasks.
