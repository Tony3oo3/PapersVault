## Problem

Generating ML library code in architecture-specific programming languages (ASPLs) like STeP requires complex reasoning about both ML algorithms and target hardware, yet these languages are esoteric, rapidly evolving, and have virtually no code examples in LLM training corpora. Existing self-improvement methods for LLM agents either explore only locally similar data or require hundreds of effective trajectories per problem, making them unsuitable for the data-scarce library-chip co-design setting where ML libraries must be shipped simultaneously with new hardware.

## Input / Output

The system takes a structural IR (YAML-formatted) that specifies the ML operator to implement, the specialized hardware functions available, and base knowledge prompts authored by ASPL designers. The structural IR externalizes and condenses program descriptions to save tokens, enabling more in-context demonstrations. The output is a self-contained pytestable Python script implementing the STeP program, verified by both a functional simulator (comparing against PyTorch reference) and a static affine-type-constraint checker. As a byproduct, the system produces a self-improving agentic system whose accumulated experiences can be reused for new tasks.

## Method

The paper introduces an adaptive self-improvement learning algorithm that iteratively evolves LLM agents through self-generated experience. Each iteration, the agentic system samples in parallel; correct answers are filtered via AST isomorphism grouping and minimum-description-length selection; earned experiences are stratified into m difficulty bins by success rate; and demonstrations are selected adaptively, starting with hard-only examples and expanding to mixed (hard+medium+easy) examples only when hard experiences are exhausted. The agentic system organization pairs a proposer agent (generating STeP implementations) with a guardian agent (globally checking and correcting affine type constraint violations), a code generator (converting STeP to pytestable Python), and dual verifiers. The key insight is that hard-earned experiences improve agent performance more efficiently than mixed ones, and the adaptive granularity m=3 balances training data difficulty against input token cost, yielding up to 3.9× improvement over a single-LLM baseline on a 26-task STeP benchmark.

## Results

On the STeP ML Library Benchmark (26 tasks across 8 operator groups), the adaptive self-improvement agentic system achieves up to 96% Pass@n (Claude 3.5 Sonnet) and up to 3.9× improvement over a baseline single LLM. Under token-matched conditions, the system improves Pass@n from 0.73 to 0.96 for Claude 3.5 Sonnet and from 0.23 to 0.81 for GPT-4o. On the AIME-2024 generalization test, the method raises Pass@n from 0.50 to 0.67 using Claude 3.5 Sonnet.

## Baselines & Comparisons

The paper compares three configurations: a single LLM (no agentic structure, no self-improvement), an agentic system (proposer + guardian agents, no self-improvement), and the full adaptive self-improvement agentic system. Under token-matched conditions (Table 5), the full system dramatically outperforms the single LLM baseline: Claude 3.5 Sonnet improves from 0.73 to 0.96 Pass@n, and GPT-4o improves from 0.23 to 0.81 Pass@n. Against supervised fine-tuning (SFT) as an alternative improvement strategy, self-improvement achieves 0.81 Pass@n versus SFT's 0.62, starting from the same 0.35 baseline. The agentic system (without self-improvement) already provides substantial gains over the single LLM on tasks with variable reuse (e.g., Arith-Reuse Pass@n from 5/8 to 8/8), but the self-improvement loop is what enables solving the remaining hard tasks. On AIME-2024, the method generalizes beyond code generation, improving Pass@n from 0.50 to 0.67.

## Relation to Prior Work

This paper synthesizes three research threads: (1) self-improvement learning for LLMs (Reflexion, self-play fine-tuning, R1-style RL), but at task-level granularity with adaptive experience stratification inspired by curriculum learning rather than token-level reward; (2) agentic system design for code generation (SWE-agent, AutoGen, DSPy), but with a domain-specific proposer/guardian architecture tailored to global type constraints in ASPLs; and (3) compiler IR design (MLIR), repurposed as a structural interface to increase sample diversity. It departs from prior ML library automation (Triton, CUTLASS, Ansor, AKG) by replacing predefined optimization strategies and cost models with LLM reasoning that self-improves through earned experience, and from prior LLM self-improvement methods by requiring only a small number of demonstrations per difficulty stratum rather than hundreds of trajectories per problem.

## Why It Matters / Open Questions

ML library development is a critical bottleneck in the ML ecosystem, with expert programmers taking days per operator and libraries needing to co-evolve with each hardware generation. The demonstrated 3.9× improvement and the ability to discover non-trivial algorithmic patterns (online softmax, memory-free streaming attention) from zero training data on a novel ASPL suggest a viable path toward automating this process. However, the evaluation is limited to 26 tasks on a single research-prototype ASPL (STeP) with no public execution environment, and generalization to mainstream ASPLs (CUDA, HIP) with their own global properties (memory access patterns, data layout sensitivity) remains untested. Open questions include whether the approach scales to larger operator libraries, whether the structural IR and guardian agent design transfer to other languages, and whether the modest AIME-2024 result (0.50→0.67) indicates broader applicability beyond code generation.
