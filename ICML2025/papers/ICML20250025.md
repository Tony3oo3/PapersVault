## Problem

Contemporary code language models struggle to handle diverse code-editing requirements (bug fixing, latency improvement, security, maintainability) despite incorporating commit data in pre-training. Moreover, naively fine-tuning these models on code-editing data causes catastrophic forgetting, degrading their pre-learned code generation and general problem-solving abilities. The paper addresses both the data scarcity and the robustness-of-adaptation challenges simultaneously.
![Teaser figure](../imgs/ICML20250025/cropped_page0_idx0.webp)

## Input / Output

The model receives a source code snippet (at function, class, or file granularity) paired with a natural language edit instruction that can be concise, detailed, human-like, or conversational (single-turn or multi-turn chat format). It outputs the modified code that addresses the specified deficiency. The pipeline supports eight programming languages (Python, C, C++, Java, JS, Rust, Go, Kotlin), and the synthetic training data spans 229M tokens across 127K examples with controlled diversity in edit type, code scale, and instruction verbosity.

## Method

The approach combines a multi-stage synthetic data pipeline (problem/source generation → target code generation → multi-style instruction generation → LLM-based quality filtering) with a novel adaptation algorithm called SeleKT (Selective Knowledge Transfer). SeleKT formulates robust adaptation as an L0-norm constrained optimization: it performs full dense-gradient fine-tuning steps, then every M minibatches computes the task vector (θ − θ_base), selects the top-αN parameters by magnitude, and projects back via θ ← θ_base + γ ⊙ τ, guaranteeing only a sparse subset of weights deviates from the base model. The key distinction from prior sparse-adaptation methods (e.g., SAFT) is that parameter selection is reassessed periodically during training rather than fixed a priori, and the dense-gradient step ensures the direction of update captures the full task signal before sparsification. Fine-tuning uses 3 epochs with AdamW (lr=1e-5), sparsity α=0.05 per layer, and periodicity M=1 epoch, applied to QwenCoder-2.5 and DeepSeekCoder instruct variants.

## Results

NextCoder-7B (QwenCoder-2.5-7B fine-tuned with SeleKT) achieves 81.1% on HumanEvalFix, 65.7% on Aider, and 50.5% on CanItEdit, outperforming its base model (73.8%, 59.4%, 48.1%) and all same-size baselines. On NoFunEval, it scores 65.3% on Security (best among ≤7B models) and 46.1% on Maintainability. NextCoder-32B reaches 23.6% on Aider Polyglot, surpassing GPT-4o (18.2%) and matching or exceeding models up to 236B parameters on the open-source leaderboard.

## Baselines & Comparisons

Against LoRA (Hu et al., 2021), SeleKT consistently wins: NextCoder-7B scores 81.1% vs. 70.7% on HumanEvalFix, 65.7% vs. 40.6% on Aider, and 50.5% vs. 44.3% on CanItEdit, with LoRA showing significant degradation from the base model. Against TIES (Yadav et al., 2024), SeleKT also prevails on HumanEvalFix (81.1% vs. 79.5%), Aider (65.7% vs. 60.2%), and CanItEdit (50.5% vs. 47.0%), while TIES edges ahead on NoFunEval Latency (27.8 vs. 26.4). Against the base QwenCoder-2.5-7B (Hui et al., 2024), SeleKT improves HumanEvalFix by 7.3 points and Aider by 6.3 points. NextCoder-7B outperforms DeepSeekCoder-33B (Guo et al., 2024) on HumanEvalFix (81.1% vs. 74.4%), Aider (65.7% vs. 58.6%), and CanItEdit (50.5% vs. 49.5%), and beats Llama-3-70B (Dubey et al., 2024) on HumanEvalFix (81.1% vs. 77.4%), Aider (65.7% vs. 51.1%), and CanItEdit (50.5% vs. 56.7% — Llama wins here). Against DeepSeek-R1-Qwen-7B (Guo et al., 2025), NextCoder-7B dominates on all code-editing benchmarks (e.g., 81.1% vs. 67.7% on HumanEvalFix, 65.7% vs. 13.5% on Aider). GPT-4o (Hurst et al., 2024) remains the strongest overall, outperforming NextCoder-7B on NoFunEval Latency (45.6 vs. 26.4), HumanEvalFix (90.2% vs. 81.1%), and Aider (74.4% vs. 65.7%), though NextCoder-7B surpasses it on NoFunEval Security (65.3% vs. 55.1%).

## Relation to Prior Work

This paper sits at the intersection of three research threads: (1) code-editing LMs trained on git commits (EditCoder, OctoCoder, SWE-Fixer), (2) synthetic data generation for code (OSS-Instruct, Self-CodeAlign, InstructCoder), and (3) robust fine-tuning to avoid catastrophic forgetting (LoRA, TIES, SAFT). It departs from prior synthetic pipelines by generating multi-granularity (function/class/file), multi-language, multi-style code-editing examples rather than function-level Python snippets, and from prior robust adaptation methods by using dense gradients with periodic sparse projection (reassessing which parameters matter throughout training) rather than fixing the updatable parameter set a priori as in LoRA or SAFT.

## Why It Matters / Open Questions

The open-sourced NextCoder models, 127K-example synthetic dataset, and SeleKT algorithm provide a practical toolkit for improving code-editing capabilities without sacrificing general code generation, addressing a gap that affects all current open-weight code LMs. The finding that standard SFT can degrade a model below its base performance on code editing is a useful caution for practitioners. Open questions include whether SeleKT generalizes beyond code editing to other domains (the authors mention math and NLP as future work), whether the dense-gradient cost is prohibitive at larger scales, and whether the still-modest Aider Polyglot scores (23.6% at 32B) reflect a fundamental limitation of the synthetic data approach for truly multilingual, multi-file editing.
