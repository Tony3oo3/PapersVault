## Problem

Despite the growing importance of function calling (tool use) for agentic LLM applications, no standard benchmark existed to evaluate this capability at scale. Existing benchmarks like APIBench, ToolBench, and TauBench were limited to single-turn interactions, narrow domains, or relied on LLM-based evaluators that introduce bias, while also failing to capture real-world patterns such as parallel invocations, multilingual queries, and stateful multi-turn reasoning.

## Input / Output

The benchmark takes user queries (text, potentially multilingual with 15+ languages represented) paired with JSON-schema function definitions as input, and for multi-turn/agentic entries additionally consumes conversation history, initial API state configurations, web search results, memory snapshots, or SQL database schemas. Models must produce structured function calls in Python-callable format; the evaluation pipeline then outputs per-category accuracy scores (AST and execution-based), deterministic error classifications (state mismatch, empty response, force termination, etc.), and perplexity/Char-NLL metrics used to flag potential data contamination between the static single-turn and live crowd-sourced splits.

## Method

BFCL's core technical contribution is a novel AST substring matching evaluation that obviates the need for actual function execution: model outputs are parsed via Python's ast module to extract function names and parameters, and correctness is determined by checking whether each parameter value falls within a predefined set of valid answers rather than requiring exact string equality. The benchmark spans four progressively complex categories—single-turn (5 invocation patterns across Python, Java, JavaScript, REST, SQL), crowd-sourced (2,251 curated entries from 64,517 real user queries), multi-turn (8 custom API suites with state-based and response-based checkers), and agentic (web search, memory management, and structured SQL via JSON-schema function composition). For multi-turn evaluation, an entry is correct only if it passes both a final-state comparison and a minimal-viable-trajectory check at every turn, capturing both outcome correctness and reasoning fidelity. Data contamination is detected by comparing perplexity and character-level NLL between the single-turn and crowd-sourced splits, where a significant performance gap signals memorization of the static benchmark.

## Results

On the BFCL benchmark, the top-performing model gpt-40-204-11-20 (Prompt) achieves 66.4% overall accuracy, followed closely by its FC-mode counterpart at 65.8%. Single-turn function calling is relatively well-solved, with top models reaching 79–95% on AST-based evaluation, but performance drops sharply on multi-turn (Base: 72–100%) and agentic tasks. Memory management remains the hardest sub-task, with even the best model (o1-2024-12-17 FC) reaching only 12% accuracy. Hallucination (irrelevance) scores range from 72–100%, indicating that knowing when *not* to call a function is still inconsistent across models.

## Baselines & Comparisons

As a benchmark paper, BFCL evaluates ~30 LLMs rather than proposing a new method against baselines. The key comparison is between FC-mode and prompting-mode inference for the same model: FC mode produces fewer parsing errors (182.5 vs. 412.93 decoding failures out of 4,251 entries) but is less flexible in complex scenarios—e.g., Claude cannot execute parallel function calls in FC mode but can in prompting mode. Among models, GPT-4o-204-11-20 leads overall (66.4% prompt / 65.8% FC), while smaller open-weight models like Qwen2-5.72B-Instrument (Prompt) achieve competitive single-turn scores (78.2% AST Simple) but lag on crowd-sourced and multi-turn tasks. Notably, parallel function-call capability has regressed in some flagship releases (o1-2024-12-17-FC, claude-3-5-sonnet-20241022-FC), suggesting a deliberate trade-off between parallelism and sequential accuracy. The crowd-sourced dataset serves as a contamination stress test: most models show comparable or better perplexity on crowd-sourced vs. single-turn, but Salesforce xLAM-7B degrades significantly (PPL 3.67→5.09), exposing overfitting to the static benchmark.

## Relation to Prior Work

BFCL extends the authors' own Gorilla/APIBench (Patil et al., 2024) from single-turn function-calling evaluation to a comprehensive multi-turn and agentic framework, while departing from prior benchmarks (ToolBench, StableToolBench, T-Eval, TauBench) by replacing LLM-as-judge evaluation with a deterministic AST-substring matching method that scales to thousands of functions without execution. The agentic components draw on FreshLLMs (Vu et al., 2023) for the search-then-fetch web paradigm and MemGPT (Packer et al., 2024) for the key-value memory management design. A key conceptual departure is the inclusion of 64,517 real crowd-sourced user queries, contrasting with the LLM-curated or expert-only queries used in all prior function-calling benchmarks.

## Why It Matters / Open Questions

BFCL has become the de facto evaluation standard adopted by all major LLM labs (Meta, Cohere, OpenAI), making it practically essential for anyone developing or comparing function-calling capabilities. The results expose a significant gap: while SOTA models achieve >90% on single-turn parallel calls, they drop to 12% on memory management and struggle with multi-turn state tracking, identifying long-horizon reasoning and dynamic decision-making as the critical open challenges for agentic LLMs. The crowd-sourced contamination-detection methodology (perplexity/Char-NLL comparison) offers a reusable protocol for the broader benchmarking community to audit whether static test sets have leaked into training data. An unexpected finding is that parallel function-calling capability regressed or was removed in flagship models (o1, Claude 3.5 Sonnet), suggesting a deliberate trade-off between parallelism and sequential accuracy that the field has not yet resolved.
