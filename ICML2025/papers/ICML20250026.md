## Problem

Existing acquisition functions for Bayesian Optimization are either general-purpose (EI, UCB, PofI) with highly variable performance across problem types, or learned via neural networks (MetaBO, FSAF) that generalize poorly outside their training function class. No prior methodology automatically discovers new AFs that simultaneously outperform both general-purpose and function-specific alternatives, generalize across function classes, and remain interpretable as explicit code.
![Teaser figure](../imgs/ICML20250026/cropped_page3_idx0.webp)

## Input / Output

FunBO takes as input an initial AF written as a Python function (with signature taking predictive_mean, predictive_var, incumbent, and beta arrays) and a set of auxiliary objective functions G with limited evaluations, then uses the Codey LLM (PaLM-based) to iteratively generate improved AFs. The output is a concise, executable Python code snippet that returns an integer index selecting the next evaluation point from a Sobol grid. Unlike neural-network AFs that require additional inputs (trial number, budget, candidate locations), FunBO's discovered AFs use only the same inputs as standard EI/UCB/PofI, making them directly deployable in existing BO libraries with minimal overhead.

## Method

FunBO formulates AF discovery as an algorithm discovery problem within the FunSearch evolutionary framework, using an LLM as a mutation operator over a population of Python programs stored in an island-model database. At each iteration, two AFs are sampled from the DB (favoring higher-scoring and shorter programs), a prompt is constructed asking the LLM to generate an improved version, and the candidate is scored by running a full BO loop on training functions with a composite metric that rewards both proximity to the true optimum and speed of convergence (fewer trials). The key technical distinction from FunSearch is the evaluation protocol: rather than scoring on simple function inputs, each candidate AF must survive a complete sequential optimization loop with a GP surrogate, making the fitness landscape significantly more complex and the search space one of programs operating on multiple arrays. The method requires no assumptions about similarity between the target function and the training set G, enabling it to discover both general-purpose and function-specific AFs, and supports few-shot adaptation by seeding the initial AF from a previously discovered solution.

## Results

FunBO is evaluated via normalized average simple regret (R̄_t) over T=30 trials (T=20 for HPO-ID and GPs-ID) across five experimental settings. In OOD-Bench, the discovered AF achieves near-zero regret on all 9 test functions (Sphere, Styblinski-Tang, Weierstrass, Beale, Branin, Michalewicz, Goldstein-Price, Hartmann d=3, Hartmann d=6) within ~25–30 trials, outperforming EI, UCB, PofI, MEAN, and random search. In ID-Bench (100 instances each of Branin, Goldstein-Price, Hartmann), FunBO matches or exceeds MetaBO while using only the same inputs as EI/UCB (no neural network). In FEW-SHOT, FunBO adapts to Ackley (d=2) using only 5 training instances and outperforms FSAF and all general-purpose AFs on 100 test instances.

## Baselines & Comparisons

Against MetaBO (Volpp et al., 2020), FunBO achieves comparable or superior regret in ID-Bench (Fig. 4) and GPs-ID d=4 (Fig. 5 middle), while using only predictive mean, variance, and incumbent as inputs versus MetaBO's neural network that also takes trial index and budget. In HPO-ID, FunBO clearly outperforms MetaBO on AdaBoost but performs similarly on SVM. Against FSAF (Hsieh et al., 2021), FunBO achieves lower regret in the FEW-SHOT experiment (Fig. 5 right) despite using a simpler initial AF (GPS-ID result) and only 5 adaptation examples. Against the general-purpose AFs EI, UCB, and PofI, FunBO consistently achieves lower average regret across all five experimental settings (OOD-Bench, ID-Bench, HPO-ID, GPs-ID, FEW-SHOT), with the gap being most pronounced on functions with many local optima (e.g., Weierstrass, where EI and UCB get stuck while FunBO continues exploring). The OOD-Bench AF also generalizes to the BoTorch evaluation pipeline (Fig. 20), performing comparably or better than EI and UCB under realistic deployment conditions with random initial designs and per-trial GP refitting.

## Relation to Prior Work

FunBO directly extends FunSearch (Romera-Paredes et al., 2023), an LLM-driven evolutionary algorithm for mathematical discovery, by formulating acquisition function (AF) design as an algorithm discovery problem over Python code. It departs from the dominant line of learned AFs (MetaBO, FSAF) that represent AFs as neural networks trained via reinforcement learning or few-shot adaptation, instead outputting interpretable code snippets that use the same inputs as standard AFs (posterior mean, variance, incumbent). The paper also positions itself against the concurrent work of Yao et al. (2024) on LLM-evolved cost-aware AFs, but explores a significantly more complex function space where programs take multiple array inputs rather than simple scalars or short tuples.

## Why It Matters / Open Questions

FunBO offers a practical path to interpretable, deployable AFs that generalize both within and across function classes, addressing a long-standing pain point where the best AF choice is ad-hoc and problem-specific. Key limitations include the high computational cost of running full BO loops for scoring each candidate, high variance in discovered AFs requiring multiple runs for OOD settings, and restriction to single-output GP-based BO. Open questions include extending to multi-objective, noisy, or non-myopic settings, designing better scoring metrics that capture convergence path quality, and determining whether the discovered AFs have intrinsic theoretical value independent of the discovery process.
