## Problem

Existing parameter-efficient fine-tuning (PEFT) methods impose low-rank constraints on weight updates, but empirical evidence shows that fully fine-tuned LLM weight updates are high-rank, making low-rank adapters suboptimal. Meanwhile, quantized fine-tuning methods (QLoRA, LoftQ) combine low-bit base weights with full-precision adapters, forcing two unmergeable computation paths that increase latency and still suffer from the low-rank assumption. No prior method unifies model compression and adaptation into a single differentiable representation without restrictive rank or sparsity assumptions.

## Input / Output

The method takes pre-trained LLM weights (FP16/BF16) and a small calibration set (128 sequences of 2048 tokens from C4) to compute per-layer Hessians, then produces a compressed sketched model where each weight row is replaced by k shared sketched values (stored as INT4/INT3/INT2) plus a column-wise one-hot binary mapping matrix M (stored as compact integers of ⌈log₂k⌉ bits). During fine-tuning, the mapping M is frozen and only the sketched parameters are updated via backpropagation, with the full weight matrix reconstructed on-the-fly as w_sketched·M for each forward pass. The sketched model is 3–8× smaller than the original, and the number of trainable parameters is controlled by the groups-per-row (GPR) hyperparameter.

## Method

SketchTune compresses each weight row independently via a learned sketching procedure: weighted k-means clustering (weighted by inverse Hessian diagonals raised to power s=3) identifies k sketched values per row, and a binary mapping matrix M is learned iteratively in GPTQ/OPTQ style, assigning each original parameter to its nearest sketched value while compensating errors to remaining parameters via Cholesky-factored Hessian updates. Unlike adapter-based PEFT, the sketched parameters are the model itself—no frozen base weights or separate adapter path exist—so fine-tuning simply backpropagates through the single reconstruction w_sketched·M, yielding one matrix multiplication per layer. A theoretical result (Theorem 3.1) proves that when the singular values of the true weight update Δ follow a power law with exponent η ∈ [0, 1−log(α)/log(2α)], sketching achieves lower expected approximation error than the best low-rank approximation at the same compression budget. Custom CUDA kernels exploit the one-hot structure of M for fast weight reconstruction and gradient accumulation, and the groups-per-row (GPR) mechanism splits each row into g contiguous sub-rows sketched independently to scale trainable parameters g-fold.

## Results

On commonsense reasoning benchmarks (8 datasets), SketchTune with INT4/GPR=4 achieves 82.3–87.0 average accuracy using base models that are 2.7–3.5× smaller than those used by competing PEFT methods, outperforming LoRA, DoRA, S2FT, and even full fine-tuning on Llama-13B (85.1 vs. 85.0) and Llama-3-8B (87.0 vs. 83.6). On math reasoning (7 datasets), SketchTune GPR=8 matches or exceeds S2FT and LoRA while using 2.6–3.4× smaller base models (e.g., 79.9 avg on Llama-3-8B vs. 79.6 for S2FT). Against quantized fine-tuning at 2-bit, SketchTune GPR=4 INT2 outperforms LoftQ by 9.05 and 14.48 points on GSM8K (Llama-2-7B/13B) with 7.3× fewer trainable parameters. On MT-Bench, SketchTune scores 6.36 average vs. 5.27 for S2FT and 4.64 for full fine-tuning, using a 3.1× smaller base model.

## Baselines & Comparisons

Against LoRA and DoRA, SketchTune consistently wins on commonsense reasoning by 4–6 points in average accuracy (e.g., 87.0 vs. 82.5/85.2 on Llama-3-8B) while using a 2.7× smaller base model. Against S2FT, the strongest PEFT baseline, SketchTune edges ahead by 0.4–1.4 points on commonsense (85.1 vs. 84.3 on Llama-13B; 87.0 vs. 86.6 on Llama-3-8B) and matches or slightly exceeds it on math (79.9 vs. 79.6 on Llama-3-8B). Against quantized fine-tuning methods, SketchTune dominates at 2-bit: it outperforms LoftQ by 14.48 points on GSM8K (Llama-2-13B) with 7.3× fewer trainable parameters, and surpasses LoftQ on WikiText-2 perplexity (6.22 vs. 7.69) with 29.4× fewer parameters. On MT-Bench, SketchTune (6.36) substantially outperforms S2FT (5.27) and full fine-tuning (4.64) despite using a 3.1× smaller base model. Against sparse adapter methods (SpIEL, SMT) in Appendix J, SketchTune matches or exceeds SMT's best configuration (85.1 vs. 84.3 on Llama-13B) while using 3.5× fewer trainable parameters and a 3.5× smaller base model.

## Relation to Prior Work

SketchTune unifies two previously separate concerns in LLM adaptation—model compression and parameter-efficient fine-tuning—into a single sketching-based framework, departing from the dominant two-path paradigm (frozen quantized weights + trainable low-rank adapter) used by QLoRA, LoftQ, and standard LoRA/DoRA. It draws on Hessian-based error compensation from OPTQ/OBC for the mapping matrix, weighted k-means from LeanQuant for loss-aware sketch learning, and random-fold hashing from Desai & Shrivastava for the theoretical error analysis. The key conceptual departure is treating the compressed representation itself as the trainable object rather than an adapter on top of frozen weights, eliminating the need for dual computation paths.

## Why It Matters / Open Questions

By removing the low-rank constraint and the two-path computation, SketchTune offers a practical path to memory-efficient fine-tuning that avoids the quality degradation seen in quantized PEFT methods, with the added benefit of a single matrix multiplication per layer at inference. The theoretical characterization (Theorem 3.1) gives practitioners a principled criterion—based on the power-law exponent of singular values—for when sketching should outperform low-rank methods, though this criterion is difficult to verify in practice since the true update matrix is unknown a priori. Open questions include whether the approach generalizes to multimodal or very large (100B+) models, how sensitive performance is to the calibration data used for Hessian estimation, and whether the sketching step can be made incremental for continual adaptation scenarios.
