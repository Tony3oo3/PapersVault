## Problem

LLM agents are vulnerable to indirect prompt injection (IPI) attacks where malicious tasks embedded in tool-retrieved information redirect the agent to unauthorized actions. Existing defenses face a fundamental trade-off: training-based methods are resource-expensive and may degrade model utility, prompt augmentation methods fail against sophisticated attacks, and tool filtering achieves low attack success rates at the cost of severely degrading normal utility. The paper seeks a training-free defense that simultaneously achieves near-zero attack success rate while preserving the agent's ability to complete legitimate user tasks.

## Input / Output

At each step of the agent's multi-step trajectory, MELON consumes the current state (user task, action history, and tool execution outputs) and produces a binary detection signal that either allows or blocks the pending tool calls before execution. The detection operates on tool call descriptions converted to natural language strings, compared via OpenAI's text-embedding-v3 model with a cosine similarity threshold (default 0.8). The masking run uses a task-neutral prompt and consolidated tool outputs, while the original run proceeds normally; only the tool call components (not text responses) are compared, with security-sensitive arguments selectively included (e.g., only recipient for send_email, not message body).

## Method

MELON exploits the observation that under a successful IPI attack, the agent's next tool call becomes conditionally independent of the user task, depending primarily on the injected malicious instructions in tool outputs. It runs a parallel 'masking execution' where the user task is replaced with a task-neutral prompt and all prior tool outputs are consolidated into a single context, then compares tool calls between the original and masked runs using embedding similarity. Three key designs address practical challenges: (1) a customized masking function with a task-neutral prompt and few-shot examples prevents the LLM from treating tool outputs as few-shot examples; (2) a tool call cache accumulates masked-run calls across steps to handle timing mismatches between when the original run executes the user task versus the malicious task; (3) comparison focuses exclusively on tool calls rather than full actions to avoid false negatives from differing text responses. A theoretical guarantee is provided via an ensemble of multiple masking prompts with Hoeffding's inequality bounds showing exponential error decay with the number of detectors.

## Results

On the AgentDojo benchmark, MELON-Aug achieves 68.72% Utility under Attack (UA) with 0.32% Attack Success Rate (ASR) on GPT-4o, compared to the undefended baseline of 69.08% UA and 16.06% ASR. MELON alone achieves 58.78% UA with 0.24% ASR on GPT-4o. Across all three LLMs (GPT-4o, o3-mini, Llama-3.3-70B), MELON and MELON-Aug reduce average ASR to below 1.3% while preserving 36–69% UA, whereas all baselines either sacrifice utility (LLM Detector: 0% UA) or fail to prevent attacks (Delimiting: 13.39% ASR on GPT-4o).

## Baselines & Comparisons

MELON-Aug dominates the UA–ASR trade-off across all three LLMs. Against Delimiting (Hines et al., 2024), MELON-Aug reduces ASR from 13.39% to 0.32% on GPT-4o while maintaining nearly identical UA (68.72% vs. 69.75%). Against Repeat Prompt (lea, 2023), MELON-Aug cuts ASR from 9.18% to 0.32% on GPT-4o at a modest UA cost (68.72% vs. 77.86%). Against Tool Filter (Debenedetti et al., 2024), MELON-Aug achieves comparable ASR (0.32% vs. 2.34%) but substantially higher UA (68.72% vs. 65.54%) on GPT-4o; on o3-mini and Llama-3.3-70B the gap is dramatic (37.28%/52.94% UA vs. 5.72%/6.20%). Against DeBERTa Detector (ProtectAI, 2024), MELON-Aug improves UA by 47+ percentage points on GPT-4o (68.72% vs. 21.34%) with similar ASR. The LLM Detector achieves 0% ASR but at the cost of 0% UA (it blocks all tool outputs), making it non-functional; MELON-Aug preserves 68.72% UA while achieving 0.32% ASR.

## Relation to Prior Work

MELON carves new ground in IPI defense by introducing a dual-execution (original + masked) paradigm that exploits the conditional independence between agent tool calls and user inputs under successful attacks. It departs from the three dominant prior families—model-based detection (DeBERTa, LLM classifiers), prompt augmentation (delimiting, repeat prompt), and tool filtering—each of which the paper shows suffers from a fundamental trade-off between security and utility. The masking function, tool call cache, and focused tool-call-only comparison are novel technical designs that address specific failure modes (arbitrary tool calls in masked runs, timing mismatches, text-response noise) not addressed by prior training-free defenses. The ensemble detector with Hoeffding-based error bounds adds a theoretical layer absent from prior IPI defenses.

## Why It Matters / Open Questions

MELON provides a practical, training-free defense that achieves near-zero ASR while preserving utility, addressing a gap where prior methods either required expensive retraining or sacrificed usability. However, a critical limitation is that 72.73% of undetected attacks are response-based (achieving malicious goals through text rather than tool calls), meaning the method's coverage is inherently bounded by the tool-call-centric design. The ~2× API cost overhead also limits deployment in cost-sensitive settings. Open questions include extending detection to response-based attacks, reducing computational overhead via KV caching and selective masking, and generalizing beyond the AgentDojo benchmark to open-ended agent environments.
