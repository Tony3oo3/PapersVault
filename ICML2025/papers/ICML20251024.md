## Problem

Existing LLM code generation methods focus almost exclusively on correctness, leaving the efficiency of generated code largely unaddressed. Even state-of-the-art models like GPT-4 Turbo produce code with average execution times 1.69× and worst-case 45.49× slower than canonical human-written solutions. This paper addresses the gap by introducing a fine-tuning approach that simultaneously improves both correctness and execution efficiency of LLM-generated code.

## Input / Output

The method takes natural language task descriptions or function signatures with docstrings as input and produces optimized source code as output, spanning five programming languages (Python, C++, Java, Rust, Go). The fine-tuning dataset EFFIINSTRUCT contains 65,710 instruction-response pairs where each response is the most efficient solution selected from multiple LLM-generated candidates, evaluated via local execution profiling. The training format follows standard instruction-tuning with a maximum sequence length of 2048 tokens.

## Method

EFFICODER constructs the EFFIINSTRUCT dataset through a multi-LLM candidate generation and selection pipeline: multiple LLMs (e.g., DeepSeek-Coder, GPT-4o) generate diverse candidate solutions for each task, all candidates are executed locally to measure execution time and memory usage, and the solution with the lowest combined execution time and memory consumption is retained as the final training target. A preliminary study establishes a strong positive correlation (r=0.972 for ET, r=0.986 for TMU) between training data efficiency and generated code efficiency, motivating the approach. The dataset is then used for fully supervised fine-tuning via Llama-factory with a learning rate of 5e-6, batch size 128, and 4 epochs in bf16. This differs from prior efficiency-focused work (PIE, Mercury) by being fully automated from task descriptions, multilingual, and substantially larger (65,710 tasks vs. 1,474–1,889), enabling consistent improvements in both pass@1 and efficiency metrics across eight open-source LLMs.

## Results

On EffiBench, fine-tuning Qwen2.5-Coder-7B-Instruct with EFFIINSTRUCT raises pass@1 from 44.8% to 57.7% while cutting average execution time by 48.4% (0.31 s → 0.16 s). On HumanEvalPlus, Qwen2.5-Coder-7B's pass@1 jumps from 40.2% to 78.7% and Qwen2.5-Coder-7B-Instruct's ET drops 38.5% (0.52 s → 0.32 s). Across all eight fine-tuned models and seven benchmarks, EFFIINSTRUCT consistently reduces ET by 17–58% and TMU by 13–79%, while improving pass@1 by 1–38 percentage points.

## Baselines & Comparisons

EFFIINSTRUCT outperforms both baselines on every reported metric. Against PIE (Shypula et al., ICLR 2024), which fine-tunes CodeLlama-7b-hf with human-written performance-improving edits, EFFIINSTRUCT achieves a 46.2% ET reduction versus PIE's 23.1%, a 43.9% TMU reduction versus 11.7%, and a pass@1 of 31.1% versus 19.5%. Against Mercury (Du et al., 2024), which selects the most efficient human-written solution from a small pool (1,889 tasks), EFFIINSTRUCT delivers a 46.2% ET reduction versus 20.5%, a 45.6% TMU reduction versus 19.9%, and a pass@1 of 31.1% versus 9.1%. In the appendix, EFFIINSTRUCT also beats all four PIE strategy variants (All, HQ, All w/ Perf-Cond, HQ+Self-Play) on ET and TMU, and surpasses EffiLearner with a 30.4% ET reduction versus 17.9% on EffiBench. The paper attributes its advantage to three factors: multilingual coverage (5 languages vs. PIE's C++-only or Mercury's Python-only), efficiency-focused data filtering that retains only tasks with measurable improvement, and a substantially larger training set (65,710 tasks vs. PIE's 1,474 and Mercury's 1,889).

## Relation to Prior Work

This paper sits at the intersection of two established lines of work: instruction tuning for code LLMs (Self-Instruct, Code Alpaca, WizardCoder, OSS-Instruct, Octopack) and efficiency-aware code evaluation (EffiBench, Mercury, PIE, SOAP). Prior instruction-tuning efforts optimized for correctness alone, while prior efficiency-focused methods (PIE for C++, Mercury for Python) relied on small, language-specific datasets of human-written efficient solutions. EFFICODER departs from both by introducing a fully automated, multilingual pipeline that uses multiple LLMs to generate diverse candidates and selects the most efficient via local execution profiling, producing a 65,710-task dataset (EFFIINSTRUCT) that is an order of magnitude larger than PIE (1,474) or Mercury (1,889). The authors explicitly position their method as orthogonal to existing synthetic-data techniques, suggesting it can be combined with them.

## Why It Matters / Open Questions

The paper addresses a practical and increasingly urgent gap: LLM-generated code that is correct but wasteful in execution time and memory, with implications for energy consumption, operational cost, and deployment in resource-constrained environments (edge devices, embedded systems). A key open question is whether efficiency gains come at the cost of code readability or maintainability, a trade-off the paper does not directly measure. The modest improvements on DS-1000 (0.8% ET reduction) suggest that data-science-heavy workloads may resist the same optimization patterns, and the consistently smaller MU improvements relative to ET improvements hint that memory optimization is a harder target for instruction tuning to capture. The open-sourcing of both the dataset and fine-tuned models makes this a practical resource for the community.
