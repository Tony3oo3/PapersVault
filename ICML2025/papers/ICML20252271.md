## Problem

ML-based cost models for optimizing sparse tensor programs require large labeled datasets, but early-stage hardware accelerators rely on expensive simulators (e.g., SPADE takes up to two weeks per data point), making standard training infeasible. Existing transfer learning techniques for cost models only operate between homogeneous hardware platforms (CPU-to-CPU, GPU-to-GPU) and fail when the program configuration spaces differ structurally, as they do between general-purpose CPUs and emerging sparse accelerators with software-managed buffers and specialized pipelines.
![Teaser figure](../imgs/ICML20252271/cropped_page1_idx0.webp)

## Input / Output

The model consumes two types of input: (1) the sparsity pattern of a sparse matrix (e.g., from SuiteSparse, with dimensions up to ~131K rows), processed as a sparse tensor through submanifold convolutions, and (2) program configuration parameters whose structure varies by platform—CPU uses loop strip-mining sizes and reordering permutations, SPADE uses tiling dimensions (row/column panels, split factor) plus binary flags for barrier, cache bypassing, and matrix reordering, while GPU uses loop binding and unrolling. The output is a scalar predicted execution cost per configuration, from which top-k configurations are selected via search; the final deliverable is the optimal program configuration for a given input matrix and target hardware.

## Method

COGNATE restructures WACO's cost model into four components to enable cross-platform transfer: a Configuration Mapper that applies explicit mapping functions (e.g., SPADE tiling+barrier ≈ CPU loop strip-mining) to project heterogeneous configuration parameters into a shared feature space via an MLP; a per-target autoencoder (Latent Encoder) that compresses hardware-specific, non-mappable parameters into fixed-size latent vectors, avoiding the excessive sparsity of feature augmentation; a modified Input Featurizer with 12 SCNN layers in 4 blocks (channels increasing to 256, with max pooling) to capture hierarchical low-level sparsity statistics; and an MLP Predictor that concatenates all three feature vectors to output a scalar cost. Training uses a two-stage transfer learning procedure: pre-training on ~100 CPU matrices with pairwise margin ranking loss, followed by few-shot fine-tuning on just 5 target-platform matrices, achieving 90–95% of optimal speedup while requiring only 5% of the data needed by accelerator-specific models.

## Results

On the SPADE sparse accelerator, COGNATE (Top-5) achieves a geomean speedup of 1.47× (up to 5.46×) for SpMM and 1.39× (up to 4.22×) for SDDMM, reaching 95% of the optimal speedup (1.55×) for SpMM. On the NVIDIA A100 GPU, COGNATE (Top-5) delivers 1.17× (up to 1.61×) for SpMM and 1.15× (up to 1.49×) for SDDMM. Critically, these results are achieved with only 5 fine-tuning matrices (500 SPADE data samples), whereas non-transfer baselines require 100–1000 matrices (10,000–100,000 samples) to reach comparable or only marginally better speedups (1.38×–1.43×).

## Baselines & Comparisons

COGNATE outperforms WACO with feature augmentation (WACO+FA, 1.04×) and WACO with feature mapping (WACO+FM, 1.09×) by 34.6% and 28.44% respectively on SpMM over SPADE, demonstrating that naive heterogeneous transfer learning techniques fail to handle the disparate program configuration spaces between CPUs and accelerators. Against the non-transfer baseline trained exclusively on SPADE data, COGNATE with only 5 fine-tuning matrices (TL5: 1.40×) matches the speedup of a model trained on 100 SPADE matrices (NT100: 1.38×) while requiring 20× fewer expensive simulation samples, and approaches the 1000-matrix baseline (NT1000: 1.43×) with 200× less data. On the A100 GPU, COGNATE (Top-5, 1.17×) surpasses the cuSPARSE library (1.01×) for SpMM. Zero-shot inference from the CPU-pretrained model without any fine-tuning performs below baseline (0.71× on SPADE), confirming that even a small amount of target-domain data is essential. The ablation in Table 2 further shows that increasing the source (CPU) training set beyond 100 matrices actually degrades transfer performance (CPU1000: 1.19× vs. CPU100: 1.40×), highlighting the negative transfer effect that COGNATE's architecture is designed to mitigate.

## Relation to Prior Work

COGNATE builds directly on WACO's learned cost model architecture (submanifold sparse convolutional networks for sparsity patterns plus a program embedder) but restructures it for heterogeneous transfer learning. Prior transfer learning for cost models (Sasaki et al., 2022; Zheng et al., 2021) operated only in homogeneous feature spaces (CPU-to-CPU, GPU-to-GPU), while existing heterogeneous techniques like feature augmentation and feature mapping produce overly sparse representations that fail across hardware types. COGNATE departs from both by proposing an approximate mapping of comparable code optimizations (e.g., loop strip-mining ↔ tiling+barrier) to create a shared homogeneous feature space, combined with an autoencoder-based latent encoding for truly hardware-specific parameters, drawing on the feature-reuse and low-level-statistics principles from Neyshabur et al. (2020).

## Why It Matters / Open Questions

The practical bottleneck this addresses is severe: collecting a single SPADE simulation data point can take up to two weeks, making the hundreds-of-thousands-of-samples requirement of standard cost model training infeasible for early-stage accelerator design space exploration. COGNATE's demonstration that 5 fine-tuning matrices (500 samples) achieve 90–95% of optimal speedup could meaningfully compress hardware development timelines. However, evaluation is limited to two target platforms (SPADE, A100), two sparse operations (SpMM, SDDMM), and a constrained 256-configuration search space; generalizability to larger search spaces, additional operations, and other accelerator architectures (e.g., PIUMA, Vesper) remains untested. Open questions include whether the approximate mapping functions generalize to accelerators with fundamentally different programming models and whether the 5-matrix fine-tuning sweet spot holds as hardware designs evolve.
