## Problem

Existing AI programming assistants operate in two disconnected modes—code completion/insertion aligned only with the current code context, and instruction-based editing aligned only with user prompts—neither of which captures the full programming process. This fragmentation means models cannot proactively predict upcoming edits by jointly leveraging coding history, current code state, and user instructions, forcing programmers to perform extra operations or write explicit prompts for every change.

## Input / Output

The model consumes a structured conversation in S-H-C-U-A order, where History (H) and User Instruction (U) are optional, enabling four input combinations (C only; H+C; C+U; H+C+U). Code changes in both H and the output A are represented in whole-file format by default, with special tokens (|target|, |target_start|, |target_end|) marking cursor positions or selected regions. The output A is organized in code-chat order, prioritizing the modified code block (wrapped in |next_start|/|next_end| tokens) before any chat-style explanation, to minimize latency in real-time IDE applications.

## Method

The paper introduces the Assistant-Conversation framework, which unifies completion, insertion, and instruction-based editing into a single conversational format by treating all programming-process information (history, context, instructions) as first-class inputs. To train models on this format without human annotation, they build Programming-Instruct, a data synthesis pipeline that draws from three sources—LLM-simulated coding processes (AI Programmer), Git commit histories, and online judge submission sequences—then randomly selects a time point, segments subsequent edits, and uses LLMs to filter relevant changes or generate corresponding instructions, yielding 219K samples across four information-type combinations. Base models (Deepseek-Coder, Yi-Coder, Qwen2.5-Coder at 1.3B–7B) are fine-tuned for 2 epochs with a ChatML-adapted template using Adafactor, FlashAttention2, and Deepspeed ZeRO-3, with samples packed via First-Fit Decreasing to maximize throughput. The S-H-C-U-A ordering is deliberately chosen to maximize prefix overlap across sequential requests, enabling prefix caching to reduce redundant KV-cache computation in serving.

## Results

On APEval (Python, Pass@1), CursorCore-QW2.5-1.5B achieves the best 1B+ average score of 50.0 (46.3 with extra tests), surpassing the next-best model (Qwen2.5-Coder-1.5B at 39.6) by 10.4 points. In the 6B+ category, CursorCore-QW2.5-7B leads with 55.5 (51.8), outperforming Qwen2.5-Coder-7B (48.8) by 6.7 points. GPT-4o remains the strongest overall at 65.2 (62.2), while the best open-source 10B+ model (Qwen2.5-72B-Inst) reaches 65.2 (61.6), nearly matching it. Across all four information-type splits (C, H,C, C,U, H,C,U), CursorCore consistently ranks first among same-size models.

## Baselines & Comparisons

CursorCore consistently outperforms all same-size baselines on APEval. In the 1B+ tier, CursorCore-QW2.5-1.5B (50.0 avg) beats Qwen2.5-Coder-1.5B (39.6) by 10.4 points and DS-Coder-1.3B-Inst (37.8) by 12.2 points; general-purpose models like Llama-3.2-3B-Instruct and Gemma-2-2B-It trail by over 25 points. In the 6B+ tier, CursorCore-QW2.5-7B (55.5) surpasses Qwen2.5-Coder-7B (48.8) by 6.7 points, Yi-Coder-9B-Chat (51.2) by 4.3 points, and DS-Coder-6.7B-Inst (50.6) by 4.9 points. Among 10B+ models, Qwen2.5-72B-Inst (65.2) matches GPT-4o (65.2) on average, though GPT-4o still leads on the H,C and H,C,U splits (61.0 vs. 53.7 and 56.1 vs. 56.1), indicating superior history utilization. The paper notes that instruction-tuned models generally outperform their base counterparts, with the notable exception of Qwen2.5-Coder-7B, whose base version (48.8) outperforms its instruction-tuned variant (46.3) due to extensive pre-training. On secondary benchmarks (EvalPlus, CanItEdit, OctoPack), CursorCore also outperforms corresponding base and instruction models, though the 6B+ advantage is smaller than for 1B+ models, attributed to insufficient high-quality training data for larger models.

## Relation to Prior Work

This paper departs from the two dominant paradigms in LLM-based programming assistance—code completion/insertion (Codex, Infill) and instruction-based code editing (OctoPack, CanItEdit, WizardCoder)—by proposing a unified 'Assistant-Conversation' framework that simultaneously aligns model outputs with code editing history (H), current code context (C), and user instructions (U). It extends the HumanEval benchmark lineage into APEval by adding historical edits and multi-source inputs, and builds its training data on top of existing sources (The Stack, EditPackFT, Codenet, Evol-Instruct) through a new synthesis pipeline (Programming-Instruct) that uses LLMs to generate realistic programming processes. The fine-tuning approach follows standard instruction-tuning practice on base code LLMs (DeepSeek-Coder, Yi-Coder, Qwen2.5-Coder), with the key methodological contribution being the multi-source input formulation and the automated data generation rather than a new training algorithm.

## Why It Matters / Open Questions

The unified framework provides a practical, well-specified interface for building programming assistants that go beyond single-input completion or chat, and the Programming-Instruct pipeline offers a reproducible way to generate multi-source training data without human annotation. However, the APEval benchmark is relatively small (~1K samples), limited to function-level code, and the paper explicitly acknowledges that repository-level development, security/efficiency evaluation criteria, and preference-based optimization remain open. The finding that LLM-synthesized programming processes (AI Programmer) outperform real human Git commits for training, and that a heavily pre-trained base model can outperform its instruction-tuned counterpart on the new task format, suggests that data quality and pre-training breadth may matter more than task-specific alignment for smaller models—an insight worth further investigation at scale.
