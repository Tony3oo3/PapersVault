## Problem

Long context fine-tuning (Long SFT) datasets exhibit an extreme long-tail distribution where over 99% of sequences are short (under 4K tokens) while a tiny fraction reach hundreds of thousands of tokens. Existing training strategies sized for the longest sequences cause severe GPU memory underutilization on the dominant short sequences, force unnecessary multi-GPU partitioning, and introduce large pipeline bubbles in distributed training due to variable sequence lengths.
![Teaser figure](../imgs/ICML20252953/cropped_page3_idx2.webp)

## Input / Output

ChunkFlow consumes a sampled batch of variable-length text sequences (with the characteristic long-tail distribution of Long SFT data) along with a training configuration specifying ChunkSize (the maximum token length per chunk, bounded by GPU memory), K (the number of chunk activations to retain for dependent chunks), and the parallelism strategy (TP/SP/PP). It produces fine-tuned LLM weights that are mathematically equivalent to standard training (gradients from all chunks are accumulated), with the primary measurable output being reduced average iteration time. The key constraint is that peak memory usage is governed by K × ChunkSize rather than the maximum sequence length in the dataset.

## Method

ChunkFlow reorganizes each training batch into uniformly sized chunks via a heuristic bin-packing algorithm: short sequences are consolidated into single chunks while long sequences are split into multiple chunks, all bounded by a predefined ChunkSize. For chunks originating from the same long sequence (dependent chunks), a state-aware scheduling algorithm processes them in ascending order for forward passes and descending order for backward passes, exploiting causal attention's dependency structure. The critical mechanism is that when a dependent chunk group has N > K chunks, the first (N−K) chunks are executed twice in the forward pass—the first execution discards activations but stores KV tensors as shared state, and the second execution reuses that state—ensuring peak memory scales with K × ChunkSize rather than the original sequence length. This scheduling is further integrated with pipeline parallelism via a state-aware 1F1B algorithm that equalizes chunk execution times across pipeline stages, reducing the bubble ratio from 57.14% to 47.8% in the paper's illustrative example.

## Results

ChunkFlow achieves up to a 4.53× speedup in end-to-end training performance over Megatron-LM when fine-tuning Qwen2.5-series LLMs (7B, 14B, 32B, 72B) at 32K and 256K context lengths. The speedup is measured as normalized average iteration time, with the largest gains observed for the 7B model at 256K context where ChunkFlow avoids full activation recomputation entirely (using only selective recompute with ChunkSize=8K, K=16). Memory consumption is governed by ChunkSize rather than maximum sequence length: e.g., the 7B model peaks at 41.6 GiB with ChunkSize=2K at 32K context versus 45.6 GiB at 256K context, confirming near-constant memory regardless of dataset sequence length.

## Baselines & Comparisons

The sole baseline is Megatron-LM, the state-of-the-art LLM training system on which ChunkFlow is built. ChunkFlow outperforms Megatron-LM across all evaluated configurations (7B/14B/32B/72B at both 32K and 256K context lengths), with the headline speedup reaching 4.53×. The largest gains come from two sources: (1) consolidating the ~99% of short sequences (<4K tokens) into uniform chunks eliminates the severe GPU memory underutilization that forces Megatron-LM to use micro-batch size 1 with 64-step gradient accumulation, and (2) the state-aware 1F1B scheduling reduces pipeline bubbles from 57.14% to 47.8% (with K=2) on variable-length sequences. For 256K context fine-tuning of 7B, 14B, and 32B models, ChunkFlow further avoids the full recomputation strategy that Megatron-LM requires, using only selective recompute. Even for the 72B model where both methods use the same selective recompute strategy, ChunkFlow still delivers substantial performance gains, confirming the benefit is not solely from recompute avoidance.

## Relation to Prior Work

ChunkFlow builds directly on Megatron-LM's distributed training infrastructure and extends sequence packing (Kosec et al., 2021) by introducing a uniform chunk-size constraint and a bin-packing heuristic for short sequences. Conceptually, it departs from prior long-context training work (which focused on dataset construction or model architecture) by reframing the problem as a scheduling and memory-management challenge over variable-length sequences. The state-aware chunk scheduling mechanism is related in spirit to token-level pipeline parallelism (TeraPipe, Seq1F1B) but operates at a coarser granularity and explicitly handles the causal-attention KV-state dependencies between chunks of the same sequence, a concern those prior methods address differently.

## Why It Matters / Open Questions

The 4.53× speedup over Megatron-LM is practically significant for any team performing long-context fine-tuning at scale, and the core insight—that peak memory can be governed by a tunable ChunkSize rather than the longest sequence in the dataset—simplifies resource planning considerably. The approach generalizes naturally to long-context continual pre-training and other variable-length workloads, broadening its applicability. Open questions include integration with more advanced pipeline scheduling algorithms (interleaved 1F1B, Zero Bubble), KV-cache offloading to further reduce the small memory overhead from long sequences, and whether the grid-search overhead for ChunkSize/K tuning remains negligible at larger cluster scales.
