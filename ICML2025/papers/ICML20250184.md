## Problem

Existing multi-modal agent benchmarks are either confined to narrow domains (web navigation, mobile screens, Q&A) or target Linux/Android, leaving the Windows ecosystem—despite its 73% market share—largely untested (only ~10% of OSWorld tasks are Windows-specific). Compounding this, the sequential multi-step nature of OS tasks makes full benchmark evaluation prohibitively slow (hours to days), bottlenecking the research and development cycle for computer agents.
![Teaser figure](../imgs/ICML20250184/cropped_page1_idx0.webp)

## Input / Output

At each step the agent receives a 1440×900×3 RGB screenshot annotated with Set-of-Marks bounding boxes (from OCR, icon/image detection, or Omniparser), the Windows UIA accessibility tree, foreground/background window titles, clipboard content, and a previous-frame screenshot for temporal context. The agent outputs executable Python code—either free-form pyautogui commands or structured calls to a Computer class covering mouse, keyboard, clipboard, OS, and window-manager functions—and the episode terminates on a DONE/FAIL action or step limit. Task completion is scored by post-hoc device-state evaluation scripts (file comparison, config queries, web checks) that return a binary (0/1) or continuous [0,1] reward.

## Method

The benchmark comprises 154 tasks across 11 Windows applications (LibreOffice Writer/Calc, Chrome/Edge, VS Code, VLC, File Explorer, Settings, Notepad, Clock, Paint, Calculator), each defined by a JSON specifying the natural-language instruction, an initial-state setup script, and a device-state evaluator function. The environment runs a Windows 11 VM inside a Docker container via QEMU/KVM, with a Python Flask server bridging the container to the VM for command execution and observation retrieval. The key infrastructure contribution is native Azure cloud parallelization: tasks are distributed across isolated compute instances (Standard D-series VMs), enabling full 154-task evaluation in ~20 minutes versus days of serial computation, without requiring GPUs or high-performance hardware. The agent backbone uses chain-of-thought/ReAct prompting with Set-of-Marks visual grounding; the best configuration (UIA tree + Omniparser + GPT-4V-1106) achieves 19.5% success rate versus 74.5% for humans, with the largest gaps in icon-heavy Office and utility tasks where visual-language misalignment and imprecise bounding boxes are the dominant failure modes.

## Results

The best agent configuration (GPT-4V-1106 with UIA tree + Omniparser) achieves a 19.5% overall success rate on Windows Agent Arena, far below the 74.5% human success rate. OpenAI's o1 (text-only) with Omniparser reaches 15.6%, while GPT-4o with UIA + OneOCR achieves 13.3%. Smaller open-source models (Phi-3-V, Phi-3.5-V) perform poorly, with overall success rates between 1.4% and 4.0%. Adding UIA tree markers to pixel-based detectors boosts performance by 15–57% depending on the model.

## Baselines & Comparisons

This is a benchmark paper, so the primary comparisons are between different agent backbone models and input-parsing configurations rather than against prior methods. GPT-4V-1106 with UIA + Omniparser (19.5%) outperforms all other configurations, with the gap to the next-best (o1 at 15.6%) driven largely by superior visual grounding in icon-heavy interfaces. o1's text-only chain-of-thought reasoning compensates for the lack of a vision modality, placing it above GPT-4o (13.3%) and GPT-4o-mini (7.3%) despite having no image input. Among input-parsing methods, Omniparser's icon captioning consistently outperforms Grounding DINO and OneOCR, particularly for Office and Media tasks where small icons dominate. Smaller open-source models (Phi-3-V, Phi-3.5-V) trail by an order of magnitude (≤4%), with frequent hallucinations on multi-step planning. The paper explicitly cautions against direct numerical comparisons with OSWorld due to differences in task sets, OS-specific accessibility trees, and model version deprecations.

## Relation to Prior Work

This paper builds directly on OSWorld (Xie et al., 2024), which established the paradigm of evaluating multi-modal agents within a real OS environment, but OSWorld focuses primarily on Linux with only ~10% of its tasks targeting Windows. WINDOWS AGENT ARENA extends this framework to the Windows ecosystem specifically, increasing the number of Windows-relevant tasks from ~50 to 154 and introducing native cloud parallelization via Azure (in contrast to OSWorld's single-host VMWare approach). The agent design follows the ReAct-style prompting and Set-of-Marks visual grounding established in prior work (Yang et al., 2023; Wei et al., 2022), while the POMDP formulation and reward evaluation follow the conventions set by OSWorld and VisualWebArena.

## Why It Matters / Open Questions

The 19.5% best-agent success rate versus 74.5% human performance quantifies a substantial gap in Windows-specific agent capabilities, with particularly poor performance on icon-heavy and keyboard-shortcut-dependent tasks (Office, VLC). The practical contribution of reducing full-benchmark evaluation from days to ~20 minutes via open-source Azure parallelization lowers the barrier to iterative agent development in the Windows environment. Open questions include whether partial-credit reward shaping, GPU-accelerated visual parsing, and more diverse task distributions can close the human-agent gap, and whether the visual-language misalignment failures identified here are specific to dense SoM annotations or reflect a broader limitation of current VLMs.
