## Problem

LLM-based agents for software issue localization struggle with three interrelated challenges in large repositories: (1) action planning is unstable and redundant when guided solely by LLM reasoning without structured scheduling, (2) balancing context conciseness (e.g., code skeletons) against search-space completeness remains an open trade-off, and (3) irrelevant information accumulates during exploration, misleading the agent toward incorrect bug locations. On SWE-bench Lite, only 53.5% of issues achieve a correct function match across all submitted agent solutions, highlighting that precise code navigation remains a significant bottleneck in autonomous software engineering.

## Input / Output

The system takes a natural-language GitHub issue description, a Python code repository indexed as a heterogeneous CodeGraph (with containment and reference edges, entities identified by UIDs of the form file_path::cls::method), and optionally a runtime reproducer trace extracted via a separate reproducer agent. The primary output is a set of bug function and file locations (evaluated via subset-match against golden patches), and when integrated with Agentless-1.5's repair pipeline, a final code patch is produced. The agent operates in a constrained reason-and-act loop where each step generates one Observation, a set of Potential Bug Locations, and Search Actions drawn from a fixed API set (search_file_contents, search_class, search_method_in_class, search_callable, search_source_code).

## Method

OrcaLoca builds a CodeGraph from AST analysis (containment edges for hierarchy, reference edges for function calls) and drives exploration via a ReAct-style LLM agent (Claude 3.5 Sonnet) with three key mechanisms. First, a Priority-Based Action Scheduler Queue (ASQ) implemented as a heap dynamically reorders LLM-generated actions by contextual relevance and a repetition counter, while a UID-prefetching database eliminates redundant API calls caused by ambiguous search APIs. Second, Action Decomposition with Relevance Scoring breaks class or file skeletons into individual method/function sub-actions, which a separate scoring sub-agent ranks by relevance to the issue (top-k=3 for classes, top-k=2 for files), and an inverted index resolves naming ambiguities (overrides, inherited classes) by splitting disambiguation messages into targeted sub-actions. Third, a Distance-Aware Context Manager prunes accumulated search results at every step by computing the average shortest-path distance in the CodeGraph between each result node and the current Potential Bug Locations, retaining only the top-k=12 most structurally relevant entries to keep the LLM context focused and noise-free.

## Results

On SWE-bench Lite (300 instances), ORCALOCA achieves a Function Match Rate of 65.33% (196/300) and File Match Rate of 83.33% (250/300), establishing a new open-source SOTA for software issue localization. Its Resolved Rate is 41.00% (123/300), tied for 8th overall. When integrated with Agentless-1.5's patch generation pipeline, ORCALOCA improves the resolved rate by 6.33 percentage points (34.67% → 41.00%) and function match rate by 6.67 percentage points (58.67% → 65.33%) over the baseline.

## Baselines & Comparisons

ORCALOCA outperforms all open-source baselines on Function Match Rate, achieving 65.33% versus the next-best open-source OpenHands+CodeAct v2.1 at 63.67% and Agentless-1.5 at 58.67%. On File Match Rate, ORCALOCA (83.33%) ties with Gru (83.33%) and trails only devlo (84.67%) and Globant Code Fixer (84.00%), both closed-source. On Resolved Rate, ORCALOCA (41.00%) is competitive with OpenHands (41.67%) and Composio SWE-Kit (41.00%) but trails the top closed-source systems (Blackbox AI 49.00%, Gru 48.67%). The most direct comparison is with Agentless-1.5, whose editing pipeline ORCALOCA reuses: ORCALOCA gains +6.33pp on Resolved Rate, +6.67pp on Function Match Rate, and +9.33pp on Function Match Precision (38.34% vs 29.01% under Union-of-Loc aggregation). Against AutoCodeRover-v2.0 (GPT-4o), ORCALOCA leads by +3.67pp on Function Match and +5.66pp on File Match while using a different (Claude 3.5 Sonnet) backbone. ORCALOCA uniquely localizes 6 issues and resolves 8 issues that no other open-source agent (Agentless, AutoCodeRover, OpenHands) can handle.

## Relation to Prior Work

OrcaLoca extends the ReAct-style reason-and-act agent paradigm (Yao et al., 2022; Wei et al., 2022) and adapts AutoCodeRover's search API design (Zhang et al., 2024) into a graph-indexed CodeGraph representation, but departs from prior agent-based localization systems by replacing free LLM-guided action selection with a priority-queue-based scheduler and by introducing a multi-agent decomposition-and-scoring workflow for handling large classes/files. Unlike RepoGraph (Ouyang et al., 2024), which enforces preprocessed graph traversal routes, OrcaLoca uses dynamic priority reordering and distance-aware pruning to balance exploration flexibility with context conciseness. The framework is explicitly modular: it targets only the localization sub-problem and is demonstrated by plugging its output into Agentless's (Xia et al., 2024) repair and patch-validation pipeline rather than replacing the full ASE workflow.

## Why It Matters / Open Questions

By establishing a new open-source SOTA on function match rate (65.33%) and showing that localization gains translate directly into a +6.33 pp resolved-rate improvement, the paper provides a practical, drop-in module for existing ASE frameworks. Key limitations include Python-only support, dependence on a proprietary LLM (Claude 3.5 Sonnet) at ~$1.77 per instance, and a 38% reproducer success rate that limits runtime signal. Open questions include whether the priority-scheduling and distance-pruning mechanisms generalize to multi-language or cross-language repositories, and whether open-source models (Qwen, LLaMA) can match the localization accuracy without the cost overhead.
