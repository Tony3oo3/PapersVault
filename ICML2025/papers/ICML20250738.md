## Problem

LLMs deployed as agents must ground their generations in environment feedback to reliably achieve user goals, yet prior work shows that iterative code generation with execution feedback fails to outperform independent sampling at a fixed inference budget. This paper asks whether reinforcement learning can teach LLMs to effectively leverage execution feedback over multiple turns, turning a previously unproductive agentic loop into a compute-efficient one.
![Teaser figure](../imgs/ICML20250738/cropped_page0_idx0.webp)

## Input / Output

The method takes a natural language competitive programming problem description as the initial prompt and iteratively produces Python code solutions in a multi-turn chat format. After each generation, the code is executed against a public test set, and the resulting feedback (wrong-answer diffs, stack traces, timeout, or out-of-memory messages) is appended to the conversation as the next observation. A separate, held-out private test set determines the final binary reward, preventing the model from memorizing expected outputs. The episode terminates when all public tests pass or a turn limit (default 3) is reached.

## Method

RLEF frames iterative code synthesis as a partially observable MDP and trains the LLM policy with PPO, where actions are full code responses and observations include prior solutions plus execution feedback. The reward is binary (+1/−1) based on whether the final solution passes all private tests, augmented with a small penalty (−0.2) for syntactically invalid non-final responses and a KL regularization term toward the initial policy. A key design choice is a turn-level value function: the value is predicted from the last token of the prompt preceding each response, and a single advantage is shared across all tokens within that response, which outperforms both token-level and turn-level optimization for both policy and value. For the KL penalty, response probabilities are computed as the geometric mean of token probabilities rather than their product, counteracting a bias toward shorter generations. Starting from Llama 3.1 Instruct models (8B and 70B), RLEF training on CodeContests yields large solve-rate gains while reducing the required sample budget by an order of magnitude compared to prior state-of-the-art agentic frameworks.

## Results

On CodeContests, RLEF-trained Llama 3.1 70B Instruct achieves 40.1% solve rate on the test set at 1@3 (3 LLM responses), up from 27.5% for the base model, and 54.5% at 10@100. The 8B model improves from 10.5% to 16.1% at 1@3 and from 24.8% to 28.7% at 10@100. Gains also transfer to HumanEval+ (70B: 75.0→80.4 multi-turn) and MBPP+ (70B: 70.2→72.2 multi-turn), and to LiveCodeBench (70B: 40.9→42.4 multi-turn).

## Baselines & Comparisons

The 70B RLEF model (40.1 test, 1@3) outperforms AlphaCodium with GPT-4 (29 test, 5@100) by 11.1 points while using only 3 samples versus 100, and beats MapCoder with GPT-4 (28.5 test, 1@19) by 11.6 points with 6× fewer samples. The 8B RLEF model (16.1 test, 1@3) surpasses AlphaCode 9B (13.3 test, 10@1000) by 2.8 points with 333× fewer samples. At the larger 10@100 budget, the 70B RLEF model (54.5) exceeds AlphaCodium GPT-4 (29) by 25.5 points and CodeLlama 34B+PPO (22.4, 10@1000) by 32.1 points. Notably, applying the AlphaCodium scaffold to the same 70B model yields only 27.8 test (5@100), below the RLEF-trained model's 40.1 at 1@3, indicating that end-to-end RL training is more effective than prompt-based agentic scaffolding for this task.

## Relation to Prior Work

This paper sits at the intersection of RL-based LLM fine-tuning (PPO, as in InstructGPT and CodeRL) and iterative code repair via execution feedback (Reflexion, AlphaCodium, MapCoder). The key departure from prior work is that previous approaches either used execution feedback only as a scalar training reward (CodeRL, RLTF, Xu et al.) or relied on hand-crafted scaffolding and prompting to exploit feedback at inference time without training the model to do so (AlphaCodium, MapCoder). RLEF unifies both: it trains a single model via PPO in an iterative environment where execution feedback is provided as natural-language text in the prompt, explicitly teaching the model to ground its next generation in that feedback. The paper also directly addresses the negative finding from Kapoor et al. and Olausson et al. that independent sampling often outperforms iterative repair, showing that this gap closes once the model is trained to actually use the feedback.

## Why It Matters / Open Questions

The result that base LLMs (including GPT-4o) perform worse in multi-turn settings with execution feedback than with independent sampling is a fundamental insight for building autonomous agents: the ability to ground in environment feedback is not an emergent property of scale or instruction tuning but must be explicitly trained. RLEF provides a practical recipe for doing so, reducing inference sample budgets by an order of magnitude while improving solve rates, and the gains generalize across model sizes, benchmarks, and turn limits. Open questions include extending beyond single-problem code synthesis to tasks requiring decomposition, combining with automatic test generation for domains where tests are unavailable, and applying the same feedback-grounding principle to other domains like mathematical reasoning.
