## Problem

LLMs for code translation suffer from two critical limitations: functional correctness remains low (e.g., StarCoder_3B achieves only 7% success on CodeNet), and even functionally correct translations often fail to preserve source code style in variable naming, structure, and API usage. Existing benchmarks like CodeNet are outdated (data pre-2021), lack extensive test cases, and have no ground-truth translations, making reliable evaluation difficult.

## Input / Output

The method takes source code in one of five languages (C, C++, Go, Java, Python) plus source/target language specifications and produces translated code in the target language. During training, function-consistent code pairs are mined from Codeforces and verified via differential testing (identical I/O on all test inputs), while style learning uses positive translations generated by Qwen_32B under style-aware prompts and negative translations produced by the function-trained model itself, filtered by CSSim threshold. Evaluation uses Computational Accuracy (CA) measuring whether translated code produces identical execution results to source across all test cases, plus CSSim for stylistic fidelity.

## Method

F2STRANS is a two-stage progressive training paradigm. Stage 1 (function-oriented guidance) constructs high-quality parallel code pairs by combining Jina embedding retrieval with an LLM judge (Qwen_7B) that assigns fine-grained relevance scores (1–5) via log-likelihood aggregation, followed by differential testing to retain only pairs with identical input-output behavior; the base LLM is then instruction-fine-tuned on these pairs. Stage 2 (style-oriented guidance) generates m=10 positive translations using Qwen_32B with a style-aware prompt, selects the best via a style consensus mechanism (highest average CSSim to other candidates), and collects n=10 negative translations from the function-trained model that fall below a CSSim threshold of 0.8 relative to the positive. Training uses a list-wise contrastive loss that maximizes the probability of the positive translation while suppressing all negatives, combined with a standard IFT loss on the positive (weighted by β=0.6), enabling the model to learn stylistic consistency through explicit positive-negative contrast rather than mere imitation.

## Results

On the CodeNet benchmark, F2STRANS with Qwen_7B achieves 89.8% average Computational Accuracy (CA) across 20 translation scenarios, while Qwen_1.5B reaches 85.1%, surpassing GPT-4 with self-debug (81.9%) and Qwen_32B with self-debug (77.6%). On the authors' more challenging F2STRANS benchmark (mid-2024 code, 50 test cases per problem), Qwen_7B achieves 75.9% CA and Qwen_1.5B reaches 69.8%, again outperforming GPT-4 self-debug (68.5%) and Qwen_32B self-debug (58.2%). The style evaluation (CSSim) shows F2STRANS Qwen_0.5B achieves 80.7 CSSim, exceeding GPT-4 self-debug (79.5), confirming improved readability even at small model scales.

## Baselines & Comparisons

F2STRANS consistently outperforms all four prompt-based strategies (Direct, CoT, RAG, Self-debug) applied to Qwen_32B and GPT-4. On CodeNet, F2STRANS Qwen_1.5B (85.1%) beats GPT-4 self-debug (81.9%) by 3.2 points and Qwen_32B self-debug (77.6%) by 7.5 points; on the harder F2STRANS benchmark, the gap widens to 1.3 points over GPT-4 self-debug (69.8% vs. 68.5%) and 11.6 points over Qwen_32B self-debug (69.8% vs. 58.2%). The RAG baseline (Bhattarai et al.) and CoT baseline (Yan et al.) show only marginal gains over Direct prompting, while F2STRANS achieves substantially larger improvements through training rather than inference-time prompting. In the loss-function comparison (Figure 5), the proposed list-wise loss L_list significantly outperforms DPO (Rafailov et al.) for style learning, with the advantage holding on both CodeNet and the F2STRANS benchmark. The self-debug strategy (Yang et al.; Pan et al.) requires multiple LLM invocations for iterative bug fixing, adding computational cost that F2STRANS avoids with a single inference pass.

## Relation to Prior Work

F2STRANS extends the line of LLM-based code translation work (Yan et al. 2023b; Yang et al. 2024; Pan et al. 2024) that relies on prompt engineering at inference time (Direct, CoT, RAG, Self-debug) by shifting the burden to a two-stage training paradigm. It builds on the weakly-supervised data mining strategy from competitive programming platforms (Lachaux et al. 2020; Khan et al. 2024) but adds differential testing and LLM-judged relevance filtering to ensure functional consistency of training pairs. The style-oriented stage draws on contrastive learning (Chen et al. 2020) and the CSSim metric (Li et al. 2024), but departs from standard DPO by using a list-wise loss over multiple negative examples and a style-consensus selection mechanism for positive examples.

## Why It Matters / Open Questions

The practical implication is significant: a 1.5B model fine-tuned with F2STRANS matches or exceeds GPT-4 and 32B prompt-engineered models, making high-quality code translation feasible on resource-constrained hardware. The new benchmark (mid-2024 code, 50 test cases per problem, manual ground-truth translations) addresses the data-leakage and staleness problems of CodeNet, providing a more reliable evaluation standard. Open questions include whether the approach generalizes to non-competitive, real-world software code (as opposed to algorithmic problems), why Python translations remain consistently weak across all models, and whether the style guidance benefits transfer to other code generation tasks beyond translation.
