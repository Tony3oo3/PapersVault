## Problem

Learned database operations (cardinality estimation, AQP, in-database analytics) assume static data distributions, but real databases undergo frequent insert/delete/update operations that shift the joint distribution of queries, data, and predictions over time. Existing adaptation strategies such as transfer learning, active learning, and fine-tuning require costly post-deployment data recollection and parameter retraining, making them impractical for continuously evolving database workloads. The paper asks: can learned database operations adapt to concept drift on-the-fly, without any parameter updates after deployment?
![Teaser figure](../imgs/ICML20253206/cropped_page1_idx0.webp)

## Input / Output

The method consumes three inputs: (1) an SPJ query encoded as a concatenation of one-hot join-predicate vectors and boundary-value filter-predicate vectors, (2) the current database state represented as per-attribute histograms (delta bins per column, scaled to [0,1]), and (3) a FIFO context memory of size rho holding the most recent query-result pairs obtained from actual database execution. The output is a single predicted value (cardinality estimate, approximate query result, class probability, or regression target) produced by a forward pass with no gradient computation. The critical design constraint is that the context memory is updated in real time: after each query executes, the true system output is immediately appended to the queue, so adaptation is driven entirely by the database's own execution feedback rather than by any external labeling pipeline.

## Method

FLAIR cascades two modules: a Task Featurization Module (TFM) that encodes data histograms through multi-head self-attention layers and then fuses them with the query vector via multi-head cross-attention to produce a compact task vector, and a Dynamic Decision Engine (DDE) that maps (task vector, context memory) to the prediction. The DDE is pre-trained once via Bayesian meta-training on synthetic datasets sampled from curated prior distributions constructed with Bayesian Neural Networks and Structural Causal Models (following the PFN paradigm), which pre-adapts it to a broad family of task distributions. At inference, the DDE performs a single forward pass conditioned on the FIFO context memory, achieving in-context adaptation without any backpropagation or parameter update. The paper further provides a theoretical guarantee: while a frozen static model's worst-case generalization error grows linearly as Omega(k) with k data operations, FLAIR's error is bounded by O(1/sqrt(rho)), depending only on context-memory size and remaining stable regardless of how many updates have occurred since training.

## Results

On the cardinality estimation task, FLAIR achieves a GMQ of 4.49 (mild drift) and 5.47 (severe drift) on STATS, and 2.36 (mild) and 7.95 (severe) on JOB-light, matching or surpassing the fine-tuning upper bound in most settings. FLAIR achieves the best performance in 29 out of 32 quantile metrics across both benchmarks. In terms of efficiency, FLAIR accelerates adaptation by 5.2× and reduces GMQ by 22.5% compared to the best baseline, and when integrated into PostgreSQL, it improves query execution latency by up to 1.9× over the built-in estimator.

## Baselines & Comparisons

FLAIR outperforms PostgreSQL's built-in cardinality estimator by orders of magnitude (GMQ 4.49 vs. 174.38 on STATS mild drift), highlighting the limitations of PostgreSQL's independence assumption. Against the fine-tuning upper bound (Kurmanji & Triantafillou, 2023), FLAIR matches or slightly exceeds it on mild drift (4.49 vs. 5.35 on STATS; 2.36 vs. 2.45 on JOB-light) while being 5.2× faster to adapt, and remains competitive under severe drift (5.47 vs. 5.02 on STATS). FLAIR clearly beats DDUp (knowledge distillation, Kurmanji & Triantafillou, 2023) across all settings (e.g., 4.49 vs. 5.79 on STATS mild; 2.36 vs. 4.16 on JOB-light mild), and substantially outperforms ALECE (Li et al., 2023) and DeepDB (Hilprecht et al., 2019) by 4–14× in GMQ. For approximate query processing, FLAIR reduces MRE by up to 10× over DBest++ (Ma et al., 2021), 3× over DBest++FT, and 2× over DDUp. On in-database data analytics (classification and regression), FLAIR outperforms AutoGluon, XGBoost, LightGBM, CatBoost, and other standard ML baselines under concept drift, capturing decision boundaries more accurately than static classifiers.

## Relation to Prior Work

FLAIR adapts the Prior-data Fitted Network (PFN) paradigm from tabular classification (Hollmann et al., 2023) to the database domain, repurposing Bayesian meta-training on synthetic priors to pre-adapt a model for in-context inference. The Task Featurization Module's hybrid self-attention and cross-attention architecture is directly derived from ALECE (Li et al., 2023b), but is decoupled from the prediction head and paired with a context-conditioned Dynamic Decision Engine. The key conceptual departure from prior concept-drift work in databases (DDUp's knowledge distillation, ALECE's retraining, transfer learning) is the elimination of all post-deployment parameter updates: FLAIR exploits the database-specific property that execution results are immediately available as ground-truth labels, feeding them into a FIFO context memory that conditions predictions without backpropagation.

## Why It Matters / Open Questions

The paper provides the first formal error-bound comparison (Theorems 3.1–3.2) showing that static models accumulate error linearly in the number of data operations (Ω(k)) while FLAIR's error is bounded by O(1/√ϱ) in context memory size, independent of k — a clean theoretical justification for the in-context adaptation paradigm in dynamic data systems. Practically, the 5.2× adaptation speedup and the demonstrated PostgreSQL integration (1.9× query latency improvement) make this a deployable solution for production databases where retraining is infeasible. Open questions include scalability to databases with hundreds of tables and attributes (histogram dimensionality grows as δ·Σnᵢ), applicability to non-SPJ queries (e.g., subqueries, window functions), and whether the FIFO context memory is optimal versus learned or attention-weighted memory schemes for very long drift horizons.
