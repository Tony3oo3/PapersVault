## Problem

LLM agent systems are being decomposed into multi-agent architectures based on intuitive, anthropomorphic role assignments (e.g., 'QA engineer' and 'developer'), but no formal asymptotic analysis exists to characterize how the cost of such systems scales with problem size, number of agents, or number of task instances. This paper argues that without treating the LLM forward pass as an atomic computational primitive and applying complexity-theoretic reasoning, the field cannot identify which decompositions are fundamentally efficient at scale versus those that are merely intuitive.

## Input / Output

The analytical framework takes as input a specification of a Language-based Algorithm (LbA): the set of LLM agents with their model sizes m_i, their capabilities sets C_M, the problem structure (e.g., number of tasks k, code length n = kl, number of bugs b), and a decomposition strategy (oracle or programmatic). It produces asymptotic complexity bounds in terms of LLM primitive counts, relative speed-up factors between competing decompositions (e.g., Θ(k), Θ(bk²), Θ(2^k k)), and guidance on which model sizes dominate the cost landscape. The analysis is deliberately model-agnostic, so results transfer directly when underlying LLMs change in size or capability.

## Method

The paper introduces Asymptotic Analysis with LLM Primitives (AALPs), which defines the LLM primitive as a single forward pass of model M of size m on an input string of length n, costing mn (matching linear per-token API pricing). Each LLM is characterized by a capabilities set C_M, and problem decomposition is abstracted via an oracle decomposition operator that splits a problem without specifying implementation. The framework then compares competing LbA designs by counting LLM primitive executions as the relevant parameters grow. Three worked examples demonstrate the approach: k-task routing shows a Θ(k) speedup from delegator-specialist architecture over a single generalist; iterative code debugging shows a Θ(bk²) speedup from per-function decomposition over whole-codebase rewriting; and evolutionary optimization on a OneMax variant shows a Θ(2^k k) speedup from local (per-block) mutation over global mutation. The key differentiator is that AALPs isolates orchestration efficiency from internal LLM improvements, making discovered speedups orthogonal to ongoing model development.

## Results

The paper presents three asymptotic separation analyses demonstrating the scaling advantages of carefully designed LLM-agent decompositions over naive approaches. The k-task routing example yields a Θ(k) speed-up from delegator-specialist architecture over a single generalist LLM. The iterative code debugging example shows a Θ(bk²) improvement from focused per-function multi-agent processing over the standard full-context accumulation approach. The evolutionary optimization example demonstrates a Θ(2^k · k) improvement from local (per-block) mutation over global (whole-solution) mutation, a super-exponential gap that makes global mutation impractical for any non-trivial k.

## Baselines & Comparisons

This is a position paper with theoretical analyses rather than empirical benchmarks, so the 'baselines' are the intuitive/naive system designs that practitioners currently deploy. In k-task routing, the generalist single-LLM baseline (cost Θ(m_g·n)) is outperformed by the delegator+specialist design (cost Θ(m_d) + Θ(m_s·n)) by a factor of Θ(k), assuming model size scales linearly with task count. In code debugging, the standard multi-agent approach that accumulates full conversation history (cost Θ(m_q·b²·n) + Θ(m_d·b²·n²)) is outperformed by the focused per-function approach (cost Θ(m_q·kl) + Θ(m_d·l²·b)) by Θ(bk²). In evolutionary optimization, global mutation (expected cost Θ(m_u·2^k·n²)) is outperformed by local per-block mutation (expected cost Θ(m_u·kl²)) by Θ(2^k·k). Across all three examples, the optimized decompositions win decisively, and the gaps grow with problem scale, which is the central argument of the paper.

## Relation to Prior Work

This paper repurposes the entire tradition of classical asymptotic algorithm analysis (Landau, Knuth, Cormen et al.) for the domain of LLM-based agentic systems, proposing the LLM forward pass as the atomic primitive to count. It acknowledges Chen et al. (2024) as a 'promising first attempt' at formalizing LLM-based algorithm analysis, but positions its own contribution as a broader call to action with accessible illustrative examples rather than a more complete formal framework. The specific examples draw on evolutionary algorithm analysis (Doerr, Droste et al.), LLM routing literature (Hu et al., Feng et al.), and multi-agent coding systems (Park et al., Qian et al.), applying the asymptotic lens to each. The capabilities-set concept aligns with the recent call for LLM specifications (Stoica et al., 2024), and model-size scaling assumptions follow Kaplan et al. (2020) scaling laws.

## Why It Matters / Open Questions

The paper's central claim—that the field is building multi-agent LLM systems without any formal complexity characterization, and that intuitive anthropomorphic decompositions can be asymptotically suboptimal by exponential factors—is a timely and potentially field-shaping argument. However, the analysis is intentionally rudimentary, relying on oracle decompositions, perfect specifications, and deterministic LLM behavior, leaving critical open questions around stochasticity, error correction, asynchrony, and automatic decomposition. The practical impact hinges on whether the community adopts the LLM-primitive abstraction as a standard design tool; if so, it could redirect research resources toward specialist model minimization and extreme problem decomposition. The paper also raises the underexplored ethical angle that highly decomposed agent architectures may reduce the risk of machine suffering by limiting individual agent scope.
