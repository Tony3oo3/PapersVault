## Problem

Training deep neural networks on memory-limited GPUs requires re-materialization (selective recomputation of activations) to stay within memory budgets, but existing methods face a fundamental trade-off: ILP-based solvers like CHECKMATE are optimal but intractable beyond ~90 graph nodes, while scalable heuristics like TW-REMAT or ROCKMATE sacrifice generality by only handling chain-like or block-sequence structures. No prior method simultaneously handles arbitrary dependency graphs with thousands of nodes, produces near-optimal schedules, and integrates seamlessly into PyTorch with minimal user code changes.

## Input / Output

The method consumes a PyTorch nn.Module, a sample input tensor (used to trace the forward computation graph via torch.jit), and a scalar memory budget in bytes. It produces a new nn.Module whose forward and backward passes follow the computed re-materialization schedule, fully compatible with PyTorch Autograd (standard .backward() calls work unchanged). The schedule is computed once offline before training; the resulting module interprets the schedule on-the-fly during execution rather than generating a monolithic Python string, avoiding the significant runtime overhead of prior approaches like ROCKMATE's exec()-based execution.

## Method

HIREMATE recursively partitions the data-flow graph via H-Partition, a greedy bottom-to-top algorithm that groups nodes into convex subgraphs of bounded size (controlled by parameters M^l and M^t) using a score function balancing interface tensor sizes against subgraph complexity. At the bottom of the hierarchy, multiple solvers (H-ILP, TW-REMAT, RK-ROTOR) independently compute schedules for each subgraph under several memory budgets, producing 'options' with different time-memory tradeoffs. A novel hierarchical ILP formulation (H-ILP) then recombines these options at each higher level, introducing 'phantom nodes' to explicitly track activations stored between forward and backward passes and correction terms to handle shared inputs/outputs across subgraphs. This yields linear overall complexity (logarithmic hierarchy depth × constant-size ILPs per level) while preserving solution quality within 1-3% of the global optimum, as validated against RK-CHECKMATE on tractable instances.

## Results

HIREMATE achieves 50–70% peak memory reduction with only 10–15% iteration-time overhead across diverse architectures. On the encoder-decoder Transformer, H-ILP solves in 12 minutes versus 15 hours for ROCKMATE, while matching the optimal RK-CHECKMATE solution within 0.12% overhead (5.44% vs 5.32% on UNet at 7.1 GB budget). Across 12 models (Table 4), HIREMATE reduces memory to 42–58% of autograd peak while adding 7–22% execution time, and handles graphs up to 6,366 nodes (GPT-96) in under 3 hours.

## Baselines & Comparisons

Against CHECKMATE (Jain et al., 2020), HIREMATE matches solution quality within 0.12% on UNet and 2-layer Transformer (Table 2) but scales to graphs 20–100× larger, where CHECKMATE becomes intractable beyond ~90 nodes. Against TW-REMAT (Kumar et al., 2019), HIREMATE consistently achieves lower iteration time at every memory budget (Figure 5), and by integrating TW-REMAT as a sub-solver, HIREMATE covers the full budget range where either method alone has gaps. Against ROCKMATE (Zhao et al., 2023), HIREMATE matches performance on sequential architectures (ResNet, GPT) but dramatically outperforms on non-sequential graphs: 12 minutes vs 15 hours solving time on a 4-layer encoder-decoder Transformer, and it handles U-Net, U-FNO, and UNO where ROCKMATE degenerates to CHECKMATE. Against MOCCASIN (Bartan et al., 2023), HIREMATE outperforms in both solution time and quality, as MOCCASIN bounds rematerializations to 2 and caps solver time at 1 hour, preventing it from reaching optimal solutions.

## Relation to Prior Work

HIREMATE sits at the intersection of two prior research lines: general-graph rematerialization methods (CHECKMATE's ILP formulation, TW-REMAT's treewidth heuristic) that achieve high quality but fail to scale beyond ~90 nodes, and specialized methods (ROTOR, ROCKMATE) that are fast and high-quality but restricted to chain-like or sequential block structures. The paper's core contribution is a hierarchical decomposition (H-Partition) that recursively breaks arbitrary data-flow graphs into manageable subgraphs, combined with a new ILP formulation (H-ILP) that recombines subgraph-level schedules using 'phantom nodes' and option variables. It also unifies existing solvers (TW-REMAT, ROTOR, ROCKMATE) as pluggable components within a single modular framework, rather than proposing a monolithic algorithm.

## Why It Matters / Open Questions

The practical impact is significant: HIREMATE enables near-optimal activation rematerialization (50–70% memory reduction at 10–15% overhead) on graphs with thousands of nodes in minutes rather than hours, with a one-line PyTorch integration that requires no code modification. This makes memory-efficient training accessible for complex architectures (U-Nets, encoder-decoder Transformers, U-NO) where prior tools either fail or require manual restructuring. Key limitations include restriction to static computation graphs (no dynamic control flow), single-GPU scope, and the fact that the hierarchical approach is sub-optimal in principle (though empirically close to CHECKMATE's optimum). Open questions include combining rematerialization with offloading and pipelined model parallelism, and extending to mildly dynamic architectures.
