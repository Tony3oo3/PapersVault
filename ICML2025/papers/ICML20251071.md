## Problem

Existing LLM-to-NAS methods treat LLMs as black boxes with simplistic text prompts, supporting only tiny search spaces and simplified networks while incurring high computational costs from full training for each architecture evaluation. These methods lack structured understanding of NAS architectures at both text and code levels, and provide no mechanism for the LLM to reflect on mutation outcomes and iteratively improve its search decisions, resulting in uncompetitive performance on standard NAS benchmarks.
![Teaser figure](../imgs/ICML20251071/cropped_page3_idx0.webp)

## Input / Output

The method consumes a structured prompt bundle comprising a system prompt (role definition, search space operation definitions with forward() code, network construction code, and Zero-Cost proxy computation code), an in-context mutation example with reasoning, and a user prompt containing a JSON object with the architecture genotype string, proxy type, and current score. The architecture genotype is a compact string encoding sequential operations with parameters (e.g., 'ConvK3BNRELU(3,32,1,1)ResK1K5K1(32,120,1,40)'), constrained by FLOPs budgets and channel limits (out_channels ≤ 2048, multiple of 8). The output is a mutated genotype string that is validated for syntax and construction correctness, scored by a code-computed Zero-Cost proxy (not the LLM), and fed back into the reflection loop.

## Method

RZ-NAS is an evolutionary NAS framework where an LLM (GPT-4o) performs text-based architecture mutation guided by structured prompts that integrate both textual descriptions and executable code for the search space, network construction, and proxy computation. After each mutation, the architecture is validated, scored by a training-free Zero-Cost proxy (GraSP, GradNorm, Synflow, Zen-Score, ZiCo, or MAE-DET), and then evaluated by a two-part LLM reflection module: an internal reflection instruction in the system prompt and an external reflection call that receives the pre/post-mutation architectures, the proxy score, and any exceptions to generate targeted suggestions for the next iteration. This closed-loop feedback, combined with random population selection (maintaining diversity) and a fixed population size with lowest-score eviction, enables the LLM to intelligently explore the search space without full training. The approach supports both micro (DARTS cell-based DAG) and macro (MobileNetV2 sequential) search spaces, with the LLM mutating only operator types and parameters within the defined search space rather than generating arbitrary code.

## Results

On NAS-Bench-201, RZ-NAS with ZiCo achieves 94.24% test accuracy on CIFAR-10, 73.30% on CIFAR-100, and 46.24% on ImageNet-16-120, outperforming all prior LLM-to-NAS methods (GENIUS: 93.79/70.91/44.96; LLMatic: 94.26/71.62/45.87) and improving over the original ZiCo proxy (93.35/70.71/46.18). On the DARTS search space, RZ-NAS(ZiCo) reaches 2.41% test error on CIFAR-10 and 17.49% on CIFAR-100, competitive with SOTA one-shot NAS methods like OLES (2.41%/17.33%) while using only 0.03 GPU days of search cost. On ImageNet with MobileNetV2 search space, RZ-NAS(ZiCo) achieves 21.0% Top-1 error at 450M FLOPs, surpassing DONNA (22.0%) by 1.0 point with 62× lower search cost (0.4 vs 25 GPU days).

## Baselines & Comparisons

RZ-NAS(ZiCo) outperforms both LLM-to-NAS baselines: it beats GENIUS by +0.45/+2.39/+1.28 points on CIFAR-10/CIFAR-100/ImageNet-16-120 test accuracy, and edges out LLMatic on CIFAR-100 (+1.68) and ImageNet-16-120 (+0.37), though LLMatic marginally leads on CIFAR-10 (94.26 vs 94.24). Against traditional differentiable NAS, RZ-NAS(ZiCo) approaches DrNAS/β-NAS (94.36/73.51/46.34) while requiring only 0.03 GPU days versus 1–4 GPU days. On the DARTS search space, RZ-NAS(ZiCo) matches OLES on CIFAR-10 (2.41% error) and is within 0.16% on CIFAR-100 (17.49% vs 17.33%), all with 0.03 GPU days versus 0.4 for OLES. On ImageNet (MobileNetV2), RZ-NAS(ZiCo) surpasses DONNA by 1.0 point at 450M FLOPs (21.0% vs 22.0%) and by 1.7 points at 1000M (18.7% vs 20.4% for Zen-NAS), with search cost of 0.4–0.5 GPU days versus 25 for DONNA and 3800 for EfficientNet. For object detection on COCO, RZ-NAS with MAE-DET improves mAP over the original MAE-DET strategy while maintaining similar FLOPs and parameter counts.

## Relation to Prior Work

RZ-NAS sits at the intersection of three research threads: LLM-guided NAS (GPT-NAS, GENIUS, EvoPrompting, LLMatic), zero-cost proxy evaluation (GraSP, Synflow, Zen-NAS, ZiCo, MAE-DET), and LLM self-reflection (Reflexion, ReEvo). It departs from prior LLM-to-NAS work by (1) supporting both micro and macro search spaces simultaneously, (2) replacing full-training evaluation with zero-cost proxies to cut search cost from 1–41 GPU days to 0.03, and (3) introducing a dual reflection module (internal system-prompt hints + external LLM feedback on mutation outcomes) that closes the loop between architecture mutation and performance assessment. The evolutionary mutation strategy builds directly on Lehman et al.'s finding that LLMs outperform random mutation in genetic programming, while the structured prompt design (text + code descriptions, in-context examples) extends the code-level understanding approach of EvoPrompting to a broader, more generalizable setting.

## Why It Matters / Open Questions

The framework demonstrates that LLM-guided NAS can be made dramatically more efficient (0.03 GPU days) while maintaining or exceeding the accuracy of both prior LLM-to-NAS methods and traditional NAS baselines across classification and detection tasks. However, the practical impact is tempered by dependence on a proprietary LLM (GPT-4o, ~$75 per proxy per search space) and by the fact that zero-cost proxies still exhibit only moderate correlation with true accuracy (Kendall's τ ≈ 0.63 for ZiCo). Open questions include whether the reflection mechanism generalizes to open-source LLMs (ablations show LLaMA 3.1 and Claude 3.5 underperform GPT-4o), whether the approach scales to substantially larger or more heterogeneous search spaces, and whether the modest but consistent gains over original zero-cost proxies (e.g., 2.45% → 2.41% test error on CIFAR-10 DARTS with ZiCo) will persist as proxy quality improves.
