## Problem

Quantized DNNs with binary or ternary weights reduce storage but still suffer from O(n²) vector-matrix multiplication as the inference bottleneck. This paper exploits the fact that weight matrices are fixed after training to preprocess them into compact indices, achieving a guaranteed logarithmic-factor speedup over standard multiplication without requiring retraining or hardware-specific changes.
![Teaser figure](../imgs/ICML20250497/cropped_page3_idx0.webp)

## Input / Output

At inference time, the method takes an activation vector v ∈ R^n and preprocessed indices (a row-permutation σ_Bi and a full segmentation list Li of size 2^k for each of ⌈n/k⌉ column blocks) to produce the result vector r = v·B ∈ R^n. The weight matrix is n×n binary (or ternary, decomposed as the difference of two binary matrices via Proposition 2.1). The preprocessing replaces the O(n²) matrix storage with O(n²/log n) indices, and the blocking parameter k (≤ log₂ n) is tuned per matrix size to minimize runtime.

## Method

The core mechanism is Redundant Segment Reduction (RSR): during preprocessing, each binary weight matrix is partitioned into k-column blocks, rows within each block are permuted into lexicographic binary order, and consecutive identical rows are collapsed into a segmentation list. At inference, for each block, the algorithm computes segmented sums over the permuted input vector (summing v[σ(k)] over each segment), then multiplies the resulting 2^k-dimensional vector by the small fixed matrix Bin_[k] of size 2^k × k. RSR achieves O(n²/(log n − log log n)) time; RSR++ further exploits the binary-structure of Bin_[k] to compute the block product in O(2^k) rather than O(k·2^k) via a recursive odd-index-sum-and-pairwise-add procedure, yielding O(n²/log n). The approach is hardware-agnostic, requires no retraining, and generalizes to q-bit matrices by decomposing into q binary matrices with linear overhead.

## Results

On native C++ vector-matrix multiplication (n=2^16), RSR++ achieves up to 29x speedup over the standard O(n²) baseline, while RSR achieves O(n²/(log n − log log n)) and RSR++ achieves O(n²/log n) time complexity. Memory usage is reduced by up to 6x (5.99x at n=2^16) since only permutation and segmentation indices are stored instead of the full weight matrix. When applied to 1.58-bit LLMs (Llama3-8B, Falcon3-3B, Falcon3-10B), RSR delivers up to 5.24x inference speedup on CPU and approximately 2.5x on GPU (e.g., Falcon3-3B drops from 560 μs to 206 μs).

## Baselines & Comparisons

The paper compares against two baselines. First, the standard 1.58-bit LLM implementation from Ma et al. (2024) serves as the primary baseline: RSR achieves up to 5.24x inference speedup on CPU and up to 2.72x on GPU (Falcon3-3B: 560→206 μs), with the gap partly attributable to PyTorch's low-level hardware optimizations benefiting the standard path. Second, the optimized BitNet.cpp kernel from Wang et al. (2024a), which uses packed 2-bit ternary weights and custom I2S kernels, is compared in Appendix F.5; RSR still shows a significant speedup in ternary matrix multiplication despite lacking hardware-specific kernel optimizations. In the native C++ setting (no framework overhead), RSR++ outperforms the standard O(n²) multiplication by up to 29x at n=2^16, and RSR outperforms NumPy's np.dot by up to 24x at n=2^15, confirming the theoretical logarithmic-factor improvement in practice.

## Relation to Prior Work

This paper repurposes the preprocessing paradigm of the Mailman algorithm (Liberty & Zucker, 2009) and the structural exploitation of binary matrices from the Four Russians Algorithm (Arlazarov et al., 1970), but redirects both toward the vector-to-matrix setting specific to quantized DNN inference. Where Mailman constructs a single decomposition matrix P (A = U × P) and Four Russians tiles for matrix-matrix products, RSR/RSR++ instead stores per-column-block row permutations and segmentation lists, exploiting the fact that weight matrices are fixed post-training. The paper explicitly positions itself against hardware-level accelerations (BitNet.cpp, TernGEMM, LADDER) by offering a guaranteed logarithmic speedup at the application layer, independent of specific hardware architectures.

## Why It Matters / Open Questions

The clean O(n²/log n) theoretical guarantee for vector-binary-matrix multiplication, combined with a logarithmic space reduction for storing weights, provides a principled path to deploying quantized LLMs on consumer hardware without retraining. However, the practical LLM speedup (5.24× on CPU, ~2.5× on GPU) is substantially smaller than the 29× matrix-multiplication speedup because the baseline benefits from low-level PyTorch and hardware optimizations that the application-level RSR implementation does not exploit. A key open question is whether the segmentation and permutation steps can be fused into hardware instructions or GPU kernels to close this gap, and whether the approach remains advantageous as quantization schemes move beyond binary/ternary to higher bit-widths.
