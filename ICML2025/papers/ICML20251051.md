## Problem

Multi-turn code generation from execution feedback is typically addressed with complex hierarchical reinforcement learning that suffers from sparse learning signals and inefficient credit assignment over long horizons. The paper identifies that code generation is a one-step recoverable MDP—any intermediate code state can be corrected to the optimal solution in a single turn—yet no prior method exploits this structural property to simplify training.
![Teaser figure](../imgs/ICML20251051/cropped_page1_idx1.webp)

## Input / Output

At each turn t, the generator receives the original problem prompt x together with the full interaction history of prior code solutions and their execution error traces from public tests (s_t = {x, y_1, o_1, …, y_{t-1}, o_{t-1}}), and produces a complete Python function as output. The learned verifier takes only the initial prompt and a candidate code snippet (not the interaction history) and outputs a scalar score used for ranking. At inference, N candidate solutions are sampled per turn (temperature 0.7), the verifier selects the best, and the selected solution is executed against public tests to produce the next turn's feedback; the episode terminates when public tests pass or a turn limit T=3 is reached, after which the final solution is scored on private tests.

## Method

μCODE reduces multi-turn code generation from reinforcement learning to imitation learning by exploiting one-step recoverability. It follows an expert iteration loop: (1) roll out the current generator in the multi-turn environment to collect interaction data, (2) train a learned verifier R_φ via supervised learning (Bradley-Terry or BCE loss) on oracle correctness labels, (3) construct a local search expert that picks the best code solution per prompt using a weighted combination of oracle and learned verifier scores (β_O=1.0, β_L=0.1), (4) relabel all collected states with this expert's optimal action, and (5) fine-tune the generator on the relabeled dataset. At inference, μCODE performs multi-turn Best-of-N search: at each turn it samples N candidates, uses the learned verifier to select the most promising one, executes it for feedback, and iterates—yielding a linear (not exponential) number of generator calls across turns. The paper proves a performance bound of O(T(ε + γ(N))) for N iterations, which is tighter than the O(εT²) worst-case for general MDPs.

## Results

On MBPP with Llama-3.2-1B-Instruct, μCODE achieves 51.1% BoN@5 accuracy, outperforming the best baseline (Instruct+BoN at 47.3%) by 3.8 points. With Llama-3.1-8B-Instruct, μCODE reaches 70.6% on MBPP, 63.8% on HumanEval, and 16.3% on CodeContests (BoN@5), surpassing all baselines. The method also improves over single-turn baselines: with the 1B model, μCODE gains 4.4% on MBPP and 5.8% on HumanEval over the strongest multi-turn baseline when using test-time BoN search. On the harder CodeContests benchmark, all methods benefit from BoN search with up to 2× performance gains, and μCODE leads by 1.4% over RFT+BoN.

## Baselines & Comparisons

μCODE is compared against three families of baselines: the base Instruct model (no training), Rejection Fine-Tuning (RFT, which filters rollouts by oracle correctness), and multi-turn variants of both with Best-of-N search at inference. With the 1B model, μCODE+BoN outperforms Instruct+BoN by 3.8% on MBPP (51.1 vs. 47.3) and 5.8% on HumanEval (41.5 vs. 35.7), and beats RFT+BoN by 4.4% and 7.4% respectively. With the 8B model, μCODE+BoN leads Instruct+BoN by 0.9% on MBPP (70.6 vs. 69.7) and 0.9% on HumanEval (63.8 vs. 62.9), and outperforms RFT+BoN by 2.2% on MBPP and 1.4% on CodeContests (16.3 vs. 14.9). Notably, RFT actually degrades relative to the base Instruct model in the multi-turn setting with the 1B model (31.1 vs. 35.1 on MBPP at N=1), which the authors attribute to fine-tuning on sub-trajectories containing incorrect intermediate code. The learned verifier's contribution is confirmed by ablations: using both oracle and learned verifier scores for relabeling yields ~2% improvement over either alone.

## Relation to Prior Work

This paper builds directly on the expert iteration framework of Anthony et al. (2017) and the DAgger interactive imitation learning paradigm (Ross et al., 2011), repurposing them for multi-turn code generation. It departs from the dominant multi-turn RL approaches (ARCHER, RLEF, SCoRe) by arguing that code generation's one-step recoverability property eliminates the need for hierarchical credit assignment, reducing the problem to supervised fine-tuning with a local search expert. The learned verifier component draws on outcome reward models (Cobbe et al., 2021) and Bradley-Terry preference training (Ouyang et al., 2022), while the multi-turn Best-of-N inference procedure extends single-turn BoN scaling (Brown et al., 2024; Snell et al., 2024) to iterative settings.

## Why It Matters / Open Questions

The one-step recoverable MDP framing provides a clean theoretical justification for replacing complex multi-turn RL with simpler imitation learning, potentially applicable to other tasks where the optimal action is history-independent. However, the empirical gains are modest (2–5% over baselines), experiments are limited to Python with small models (≤8B) and a 374-problem training set, and the authors acknowledge these constraints may limit generalizability. Open questions include whether the approach scales to larger models, other programming languages, and tasks where one-step recoverability does not hold, as well as whether the learned verifier's advantage over public tests narrows with stronger verifiers trained on larger data.
