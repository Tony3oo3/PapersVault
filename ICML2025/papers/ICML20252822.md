## Problem

While LLM-based embodied agents have received substantial evaluation attention, MLLM-based vision-driven embodied agents remain underexplored due to the absence of comprehensive, standardized benchmarks. Existing benchmarks like VisualAgentBench focus exclusively on high-level planning, leaving critical questions unanswered about the role of visual input and MLLM performance on low-level tasks such as navigation and manipulation. EMBODIEDBENCH addresses this gap by providing a unified evaluation framework spanning both action levels and fine-grained agent capabilities.
![Teaser figure](../imgs/ICML20252822/cropped_page1_idx0.webp)

## Input / Output

The agent receives a 500×500 egocentric RGB image, a language instruction, interaction history (past actions and environment feedback), and for EB-Manipulation, YOLO detection boxes with index markers plus object pose estimates. Outputs are structured JSON plans: high-level tasks produce sequences of named actions (e.g., 'pick up apple'), while EB-Manipulation produces 7D action vectors [x, y, z, roll, pitch, yaw, gripper] where position components are discretized into 100 bins and orientation into 120 bins. The agent supports multi-step planning, dynamically deciding how many actions to emit per timestep rather than one action per step.

## Method

EMBODIEDBENCH comprises 1,128 test instances across four environments: EB-ALFRED and EB-Habitat for high-level household planning (300 instances each), EB-Navigation for low-level 8-action navigation (300 instances), and EB-Manipulation for 7D robotic arm control (228 instances). Each environment is partitioned into six capability-oriented subsets (Base, Common Sense, Complex Instruction, Visual Appearance, Spatial Awareness, Long Horizon) with 50 instances per subset, enabling fine-grained diagnosis of agent weaknesses. The unified agent pipeline processes multimodal inputs through a five-step planning loop (visual description, reflection, reasoning, language plan, executable JSON plan) with 10 few-shot in-context examples. For EB-Manipulation, the continuous action space is discretized following Yin et al. (2024), and YOLO detection boxes with visual markers reduce the need for precise 3D localization. The paper evaluates 24 MLLMs (8 proprietary, 16 open-source) under identical conditions (temperature 0, max 2048 tokens) and conducts ablations on language-centric factors (environment feedback, ICL count) and visual-centric factors (resolution, detection boxes, multi-step images, visual ICL).

## Results

Across 24 MLLMs evaluated on four environments, GPT-4o achieves the best low-level performance (57.7% on EB-Navigation, 28.9% on EB-Manipulation), while Claude-3.5-Sonnet leads on high-level tasks (64.0% on EB-ALFRED, 68.0% on EB-Habitat). The best open-source model, InternVL3-78B, reaches 53.7% on EB-Navigation and 26.3% on EB-Manipulation, approaching proprietary performance on low-level tasks but trailing significantly on high-level reasoning. Long-horizon planning is the most challenging subset across all environments, with Claude-3.5-Sonnet dropping from 96% (base) to 58% (long-horizon) on EB-Habitat. Removing vision input causes a 40–70% performance drop on low-level tasks but has minimal or even positive effect on high-level tasks.

## Baselines & Comparisons

Among proprietary models, GPT-4o dominates low-level tasks (57.7% EB-Navigation, 28.9% EB-Manipulation), outperforming Claude-3.5-Sonnet (44.7%, 25.4%) and Gemini-2.0-flash (48.7%, 16.7%) by 13 and 12 points on navigation respectively. Conversely, Claude-3.5-Sonnet leads high-level tasks (64.0% EB-ALFRED, 68.0% EB-Habitat), surpassing GPT-4o (56.3%, 59.0%) by 7.7 and 9 points. Claude-3.7-Sonnet achieves the single highest EB-ALFRED score (67.7%) but underperforms Claude-3.5-Sonnet on EB-Habitat (58.7% vs. 68.0%). GPT-4o-mini trails GPT-4o by 32+ points on EB-ALFRED and 24 points on EB-Manipulation, indicating significant capability loss at smaller scale. Among open-source models, InternVL3-78B is the strongest overall (53.7% EB-Navigation, 26.3% EB-Manipulation), approaching GPT-4o on low-level tasks but trailing by 17–20 points on high-level tasks. Ovis2-34B (45.7% EB-Navigation, 26.8% EB-Manipulation) and Gemma-3-27B (45.4%, 17.5%) are competitive on navigation but weaker on manipulation. A clear scaling trend is observed within each open-source family (e.g., InternVL3: 8B→38B→78B), yet a substantial gap persists between the best open-source and proprietary models, particularly on reasoning-intensive high-level subsets.

## Relation to Prior Work

This paper extends the embodied agent evaluation lineage from ALFRED, VLM-Bench, and Habitat/Language Rearrangement by unifying high-level household planning and low-level navigation/manipulation under a single MLLM evaluation framework. It departs from VisualAgentBench (the first MLLM agent benchmark) by adding low-level action tasks and fine-grained capability-oriented subsets, and from Lota-Bench by fixing simulator bugs and supporting multi-instance objects. The agent pipeline draws on action-space discretization (Yin et al., 2024) and Set-of-Mark visual grounding (Yang et al., 2023a) to make continuous manipulation tractable for off-the-shelf MLLMs.

## Why It Matters / Open Questions

EMBODIEDBENCH provides the first standardized, multi-level, capability-oriented evaluation platform for MLLM embodied agents, filling a gap that limits progress in building versatile vision-driven agents. The finding that vision is nearly irrelevant for high-level tasks (language-only GPT-4o matches or beats vision-enabled) but drops 40–70% on low-level tasks reframes how the field should think about multimodality in embodied AI. Key open questions include whether these simulation results transfer to real-world deployment, how to improve multi-frame visual understanding, and whether visual in-context learning can close the low-level manipulation gap without fine-tuning.
