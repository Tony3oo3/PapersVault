## Problem

Conventional static layer pruning for LLMs treats all tokens identically and prunes entire layers uniformly, ignoring two critical dynamics: horizontal (different tokens require different amounts of computation) and vertical (MLP and self-attention modules within the same layer have distinct redundancy profiles). Additionally, existing dynamic pruning methods that jointly train routers with model parameters suffer from instability because the randomly initialized router disrupts the already-converged pretrained weights.
![Teaser figure](../imgs/ICML20253131/cropped_page0_idx0.webp)

## Input / Output

SkipGPT takes a standard text sequence (truncated to 4096 tokens) and produces next-token predictions identical to the original dense LLM. The key distinction is that the computation path is token-specific: each token independently traverses a variable subset of the 2L modules (L attention + L MLP), with the global sparsity ratio (fraction of skipped module-token computations) controlled by a single scalar target rather than per-layer or per-token budgets. The router parameters add only 0.007% of total model parameters, and the entire tuning process completes on a single A800 GPU within four hours.

## Method

SkipGPT places a lightweight linear router before each individual module (attention and MLP separately), producing a 2-way categorical distribution that decides whether to execute the module or pass through a residual connection. Discrete routing decisions are made via Gumbel-Softmax reparameterization with a Straight-Through Estimator, enabling differentiable optimization of hard skip/execute choices while maintaining a global sparsity constraint through an L1 regularization term on the realized sparsity ratio. The two-stage training paradigm first freezes all pretrained weights and trains only the routers (Router Tuning), then optionally freezes the routers and applies LoRA fine-tuning to the model to recover any residual performance loss. This decoupling avoids the instability of joint router-model training, where a random router would force the pretrained model to adapt to suboptimal routing before the router itself converges.

## Results

After the full two-stage training (SkipGPT-RT-L), the pruned model matches or exceeds the original dense model's performance at 25% parameter reduction: on LLaMA2-7B it achieves 69.50% average accuracy (vs. 68.69% dense) and 13.54 average PPL (vs. 13.15 dense); on LLaMA2-13B it reaches 72.21% accuracy (vs. 72.48% dense) and 16.80 PPL (vs. 16.90 dense). At the more aggressive 40% reduction on LLaMA3.1-8B, SkipGPT-RT alone retains 59.80% average accuracy, while the best static baseline (Shortened-PPL + LoRA) drops to 51.65% and dynamic baselines (MoD-D, D-LLM) fall to 46.07% and 44.59% respectively. Router tuning alone (SkipGPT-RT, no LoRA) already surpasses all static pruning methods, achieving 62.29% accuracy on LLaMA2-7B at 25% pruning versus 64.91% for the best static method (Joint Layer Drop + LoRA) on PPL but 62.29% vs. 64.91% on accuracy.

## Baselines & Comparisons

SkipGPT-RT-L decisively outperforms all static pruning baselines (ShortGPT, Shortened-PPL/Taylor, LaCo, Joint Layer Drop, LLM-Pruner, SliceGPT) after LoRA recovery, achieving 69.50% average accuracy on LLaMA2-7B at 25% pruning versus 64.91% for the best static method (Joint Layer Drop + LoRA) and 62.66% for ShortGPT + LoRA. Against dynamic pruning baselines, the advantage is even more pronounced: MoD-D (55.05%) and D-LLM (41.95%) on LLaMA2-7B, and MoD-D (44.98%) and D-LLM (41.91%) on LLaMA3.1-8B, all fall far short of SkipGPT-RT-L's 69.50% and 72.30% respectively. The ablation SkipGPT-Joint (joint router + LoRA training) confirms the necessity of the two-stage paradigm, scoring only 48.16% on LLaMA2-7B and 44.49% on LLaMA3.1-8B—far below the two-stage SkipGPT-RT-L. At 40% pruning on LLaMA3.1-8B, where nearly all baselines collapse (best static: 51.65%, best dynamic: 46.07%), SkipGPT-RT alone retains 59.80% accuracy, demonstrating the scalability advantage of dynamic, token-aware routing over fixed layer removal.

## Relation to Prior Work

SkipGPT sits at the intersection of static layer pruning (ShortGPT, LaCo, Shortened LLaMA) and dynamic conditional computation (Mixture-of-Depths, D-LLM, Learning to Skip), but departs from both in two key ways. Unlike static methods that permanently remove layers based on aggregate importance metrics, and unlike prior dynamic methods that impose fixed per-layer top-k budgets or uniform per-token sparsity, SkipGPT introduces a global sparsity constraint that allows computation to be flexibly allocated across both tokens (horizontal dynamics) and module types (vertical dynamics). The two-stage training paradigm—router tuning with frozen model parameters followed by optional LoRA fine-tuning—explicitly rejects the MoE-style joint training paradigm, arguing that a randomly initialized router destabilizes already-converged pretrained weights.

## Why It Matters / Open Questions

The practical impact is substantial: router tuning requires only 0.007% additional parameters, a single A800 GPU, and ~4 hours to achieve 40% parameter reduction while matching or exceeding the original model's performance, making dynamic pruning accessible without large-scale retraining. The architectural insights—that attention modules are structurally more redundant than MLP modules, and that later tokens in a sequence require more attention but less MLP computation—challenge the fixed 1:1 attention-to-MLP pairing in current Transformers and suggest future architectures could be more efficient. Open questions include whether these findings generalize to much larger models (100B+), whether the router overhead at inference negates some of the FLOPs savings in practice, and whether the observed redundancy patterns are artifacts of specific pretraining data or fundamental to the Transformer inductive bias.
