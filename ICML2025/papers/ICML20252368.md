## Problem

In long-context LLM inference, the KV cache becomes the dominant memory and latency bottleneck, yet existing speculative decoding methods struggle to achieve meaningful speedups because small draft models lack long-context understanding (causing low acceptance rates) and sparse KV strategies degrade generation quality. Maintaining separate KV caches for both draft and target models further inflates memory, making self-speculative decoding with efficient KV management an open challenge.
![Teaser figure](../imgs/ICML20252368/cropped_page0_idx0.webp)

## Input / Output

The method takes a long-context text prompt (benchmarked at 4k–128k tokens) and produces generated text tokens verified by the target model's distribution. The draft model consumes only the upper 4-bit KV cache representation plus 4-bit quantized weights, while the target model reconstructs an INT8 KV cache from both upper and lower 4-bit segments. A double full-precision buffer of size 2G (G = quantization group size = 128) retains the most recent tokens in BF16 to preserve acceptance quality at the generation boundary.

## Method

QuantSpec is a self-speculative decoding framework where the draft and target models share the same architecture but differ in KV cache precision: the draft uses a 4-bit hierarchical KV cache (loading only the upper INT4 segment) while the target reconstructs an INT8 cache from both upper and lower INT4 segments, eliminating the need for a separate draft KV copy. The key insight is decomposing an INT8 value into two INT4 components (upper 4 bits via asymmetric quantization, lower 4 bits via symmetric quantization of the residual error), enabling bit-sharing between models. A double full-precision buffer of size 2G stores recent tokens in BF16, ensuring at least G tokens remain unquantized for high acceptance rates while deferring quantization to every G decoding steps to minimize overhead. Custom CUDA kernels implement attention over the hierarchical quantized KV cache within a Flash Decoding framework, achieving ~2.88× speedup over FP16 FlashAttention at 4-bit precision, and the full system delivers up to ~2.5× end-to-end speedup with >90% acceptance rates.

## Results

QuantSpec achieves up to 2.49× end-to-end speedup over autoregressive decoding at 128k context length on LWM-Text-Chat-128k, while maintaining acceptance rates consistently above 90% (89.88%–94.31%) across all tested settings. At 32k context on Llama-2-7B-32K-Instruct, QuantSpec reaches 2.08× speedup with 25.84 GB peak GPU memory, compared to 1.84× (32.61 GB) for StreamingLLM and 1.63× (33.96 GB) for SnapKV. Critically, at 128k context both sparse-KV baselines run out of memory (OOM), while QuantSpec completes inference with 61.22 GB and 2.49× speedup. The custom INT4 attention kernel achieves ~2.88× kernel-level speedup over FP16 FlashAttention at 64k context.

## Baselines & Comparisons

QuantSpec is compared against two sparse-KV self-speculative decoding baselines: StreamingLLM (attention-sink-based KV sparsification) and SnapKV (importance-based KV selection). QuantSpec consistently outperforms both on speedup across all context lengths and datasets, with the gap widening as context grows (e.g., 2.08× vs. 1.84×/1.63× at 32k on Multi-LexSum; 2.49× vs. OOM at 128k). On acceptance rate, QuantSpec maintains >90% in nearly all settings, while SnapKV degrades severely on summarization tasks (55.55% on Multi-LexSum at 8k, 72.54% at 32k) because sparse KV discards information critical for whole-context tasks. StreamingLLM's acceptance rates are closer to QuantSpec's but still lower at longer contexts (78.95% vs. 92.18% at 64k on Multi-LexSum). On memory, QuantSpec uses ~1.3× less peak GPU memory than the baselines at equivalent context lengths (e.g., 25.84 GB vs. 32.61/33.96 GB at 32k), and is the only method that can handle 128k context without OOM. The paper also notes that QuantSpec's optimal speculation length γ is larger (4–6) than the baselines' (γ=1), indicating the quantized draft model produces more reliable multi-token drafts.

## Relation to Prior Work

QuantSpec sits at the intersection of speculative decoding (Leviathan et al., 2023; Chen et al., 2023), self-speculative decoding with shared architecture (MagicDec, TriForce), and KV cache quantization (KIVI, KVQuant, GEAR). It departs from the sparse-KV self-speculative approaches (StreamingLLM, SnapKV) by replacing token eviction with hierarchical INT4 quantization, arguing that quantization preserves more contextual information and thus yields higher draft-target acceptance rates. The hierarchical design—storing an INT8 cache as two INT4 halves so the draft model loads only the upper 4 bits while the target reconstructs the full 8 bits—is a novel memory-sharing mechanism not present in prior speculative decoding or quantization work. The double full-precision buffer addresses a specific incompatibility between per-group quantization and the reject-and-revert mechanism of speculative decoding, a problem not addressed in prior KV quantization literature.

## Why It Matters / Open Questions

QuantSpec provides a practical, drop-in acceleration path for long-context LLM inference on edge and single-node hardware, delivering up to ~2.5× speedup with >90% acceptance rates while reducing peak GPU memory by ~1.3× over sparse-KV alternatives. The arithmetic intensity analysis (Section 3) gives practitioners a principled framework for deciding when weight quantization vs. KV quantization is most beneficial, which generalizes beyond this specific method. Open questions include whether the approach combines effectively with sparse attention (acknowledged as future work), how it scales to models beyond 8B parameters or multi-node settings, and whether the 4-bit precision floor can be pushed lower without degrading acceptance rates. The method's reliance on custom CUDA kernels also raises portability questions across GPU architectures.
