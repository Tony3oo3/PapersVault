## Problem

Automatic equivalence checking of optimization formulations lacks a precise formal definition and reliable methods. Existing approaches—canonical accuracy, execution accuracy, and graph-based WL-tests—fail under common but valid transformations such as rescaling, adding cutting planes, or introducing slack variables, which is critical for evaluating optimization copilots that generate formulations from natural language. The paper identifies these pitfalls and proposes both a formal equivalence criterion and a scalable checking method.
![Teaser figure](../imgs/ICML20252976/cropped_page3_idx0.webp)

## Input / Output

The method takes two symbolic MILP/LP formulations (α, α') provided as structured JSON with variable descriptions, constraint formulations, and objective functions, along with a MILP solver S. Variables are represented at the set level (e.g., x_i for all i ∈ V) rather than individually, so prompt size scales with the number of variable sets rather than individual variables. The output is a Boolean equivalence verdict plus the discovered linear mapping function f expressed as a list of (constant, variable) pairs per target variable. The mapping is formulation-level (symbolic, applicable across instances), while the verification step is instance-specific (concrete parameter values).

## Method

EquivaMap introduces Quasi-Karp Equivalence, a formal criterion inspired by Karp reductions but relaxed to be instance-specific, solution-mapping (rather than instance-mapping), and without the no-instance preservation condition. The algorithm has two stages: (1) a GPT-4 LLM, prompted with structured descriptions of each variable's role in constraints and the objective, discovers a linear mapping f from α's variable space to α′'s; (2) a lightweight verification step applies f to the solver-computed optimal solution of α′ and checks feasibility and optimality for α without additional solver calls. The mapping is restricted to linear functions to guarantee polynomial-time computability, and K=3 stochastic LLM runs are aggregated with an OR rule (equivalent if any run yields a valid mapping). The approach achieves 100% accuracy across all equivalent and non-equivalent transformations in the newly introduced EquivaFormulation dataset, where all baselines fail on at least one transformation type.

## Results

EquivaMap achieves 100% accuracy across all seven equivalent transformations and all three non-equivalent transformations on the EquivaFormulation dataset, using GPT-4 as the mapping finder with K=3 runs. In contrast, Canonical Accuracy and the WL-test achieve 0% on every equivalent transformation, while Execution Accuracy fails completely (0%) on Rescaling and Feasibility. The naive-LLM baseline (which simply asks GPT-4 to judge equivalence without explicit mapping) ranges from 3.3% (Add Valid Inequalities) to 98.7% (Random Order), demonstrating that the structured mapping-and-verification pipeline is essential for reliability.

## Baselines & Comparisons

EquivaMap decisively outperforms all three external baselines. Canonical Accuracy (Ramamonjison et al., 2023, from NL4OPT) achieves 0% on every equivalent transformation because it requires exact declaration matching and is sensitive to variable/constraint permutations. Execution Accuracy (AhmadiTeshnizi et al., 2024, from NLP4LP) reaches 100% on most equivalent transformations but drops to 0% on Rescaling (where objective values differ by a scale factor) and on the Feasibility non-equivalent case (where both formulations have zero objective). The modified WL-test (Wang et al., 2024, from OptiBench) achieves 0% on all equivalent transformations because structural modifications like adding cutting planes or decomposing variables break graph isomorphism. The paper's own naive-LLM baseline (directly prompting GPT-4 to judge equivalence) is inconsistent, ranging from 3.3% to 98.7%, confirming that the explicit mapping-discovery plus solver-verification pipeline in EquivaMap is what ensures reliability rather than LLM reasoning alone.

## Relation to Prior Work

This paper adapts the classical Karp reduction framework from complexity theory to define a new formal criterion—Quasi-Karp Equivalence—for when two MILP formulations are equivalent, relaxing the no-instance condition and focusing on instance-specific solution mappings rather than arbitrary instance mappings. It departs from existing equivalence-checking heuristics (canonical accuracy from NL4OPT, execution accuracy from NLP4LP, and the modified WL-test from OptiBench) by replacing structural or solver-based comparisons with an LLM-discovered variable mapping followed by a lightweight feasibility/optimality verification step. The method sits at the intersection of the LLM-for-optimization-modeling literature (OptiMUS, Chain-of-Experts) and the evaluation-of-optimization-copilots literature, providing the missing verification layer that those systems lack.

## Why It Matters / Open Questions

Reliable formulation equivalence checking is a prerequisite for evaluating and improving optimization copilots, yet no prior method handles even basic transformations like rescaling or adding valid inequalities. The EquivaFormulation dataset and Quasi-Karp Equivalence definition fill a concrete gap in the field, giving the community a shared formalism and benchmark. However, the current scope is limited to relatively straightforward, deterministic transformations; more complex reformulations arising from decomposition algorithms or duality-based reformulations remain unaddressed. A promising open direction is extending the framework to check equivalence across structurally different optimization problems (e.g., max-flow vs. min-cut), which would require mappings that are not simple variable substitutions.
