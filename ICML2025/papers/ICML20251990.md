## Problem

Existing multi-round Secure Aggregation schemes for Federated Learning, including the state-of-the-art Flamingo (S&P'23), suffer from three critical gaps: they cannot handle dynamic user participation without costly re-setup, they provide no mechanism for users to verify that the server performed aggregation correctly, and they remain vulnerable to Model Inconsistency Attacks where a malicious server distributes crafted model parameters to suppress non-target users' gradients and extract a target user's private update.
![Teaser figure](../imgs/ICML20251990/cropped_page4_idx0.webp)

## Input / Output

Each user submits a local gradient vector of dimension m over Z_R, along with a random blinder, to two servers: the masked update and blinder-related commitment go to the aggregation server S0, while the full commitment and ElGamal-encrypted OTP key go to the assistant server S1. The output is the sum of all users' gradients, which is revealed only to the users (never to the servers), plus a binary verification result that each user computes locally by comparing a separated commitment against a fresh commitment of the unmasked aggregate. This server-invisible output is the key design choice that neutralizes MIA.

## Method

Janus introduces a dual-server architecture where S0 aggregates masked updates and S1 aggregates the OTP keys and full commitments, ensuring neither server ever sees the final plaintext aggregate. The core cryptographic innovation is a new primitive called Separable Homomorphic Commitment (SHC), which extends Pedersen commitments by allowing the commitment to be algebraically decomposed into a message-related part c_m = g^m and a blinder-related part c_r = h^r, so that users can verify aggregation correctness by checking Se(C_t, C_r) = PCommit(X_t, pp). Each user performs only O(1) operations per round—OTP masking, one ElGamal encryption, one Pedersen commitment, and one verification comparison—eliminating the pairwise key negotiation and k-regular communication graphs required by BBSA and Flamingo. This reduces per-client computation and communication from logarithmic (in the number of users) to constant scale, while the binding property of SHC additionally prevents users from repudiating previously submitted malicious updates.

## Results

On MNIST (CNN), Janus achieves 93.18% test accuracy versus 94.1% for the No-SA baseline; on CIFAR-10 (CNN), it reaches 75.94% versus 77.8% for No-SA. Per-client computation and communication overhead is reduced to O(1) (constant), compared to O(n²) for SecAgg, O(log²n) for BBSA, and O(n) for VeriFL. Janus is the only scheme that simultaneously supports multi-round aggregation, verifiability, dynamic user participation, and resistance to Model Inconsistency Attacks (MIA).

## Baselines & Comparisons

Against the No-SA baseline (McMahan et al., 2017), Janus sacrifices only ~1–2% test accuracy (e.g., 93.18% vs. 94.1% on MNIST-CNN; 75.94% vs. 77.8% on CIFAR-CNN) in exchange for full privacy guarantees. Compared to SecAgg (Bonawitz et al., 2017) and BBSA (Bell et al., 2020), Janus reduces per-client computation from O(n²) and O(log²n) respectively to O(1), while also adding multi-round support, verifiability, and dynamic participation that neither baseline offers. Versus VeriFL (Guo et al., 2020), Janus matches the verifiability feature but cuts client-side overhead from O(n) to O(1) and natively supports multi-round aggregation without re-setup. Against ELSA (Rathee et al., 2023), Janus achieves the same O(1+l) client computation but additionally provides verifiability, multi-round support, and MIA resistance. Compared to Flamingo (Ma et al., 2023), the closest prior work, Janus eliminates the complex decryptor-based communication graph (reducing client overhead from O(L²+εn²) to O(1)), supports dynamic user joining without re-setup, and is the first to resist Model Inconsistency Attacks via its dual-server architecture.

## Relation to Prior Work

Janus extends the masking-based secure aggregation lineage (SecAgg → BBSA → Flamingo) by replacing the complex peer-to-peer communication graphs with a simpler dual-server architecture where each client interacts only with two servers. It introduces Separable Homomorphic Commitment (SHC), a new primitive derived from the Pedersen commitment structure, to achieve verifiability without the heavy homomorphic hashing or signatures used by VeriFL and VerifyNet. The design directly addresses the Model Inconsistency Attack identified by Pasquini et al. (2022) by ensuring servers never see the final aggregation result, a departure from all prior single-server SA schemes.

## Why It Matters / Open Questions

Janus provides a practical path toward multi-round SA with dynamic participation and verifiability, reducing per-client overhead from logarithmic to constant scale, which is meaningful for resource-constrained edge devices in cross-device FL. However, the dual-server non-collusion assumption, while argued to be realistic (e.g., competing hospitals or banks), remains a significant deployment constraint that limits adoption in single-organization settings. Open questions include whether the scheme can tolerate one corrupted server without degrading to single-server security, how it performs under adversarial user-level poisoning, and whether the SHC abstraction generalizes beyond the Pedersen/ElGamal instantiation tested here.
