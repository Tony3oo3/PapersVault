## Problem

Existing GPU kernels for Kronecker-sparse (KS) matrix multiplication—the building blocks of Butterfly, Monarch, and Kaleidoscope layers—follow a permute-GEMM-permute pipeline in which two global memory permutations can consume up to 50% of total runtime. These permutations were assumed necessary to reshape the KS structure into contiguous blocks for standard dense GEMM routines, but no prior work showed whether they could be eliminated without sacrificing throughput.

## Input / Output

The method computes Y = XK^T where X ∈ R^{B×N} is a dense input batch (e.g., B = 25088 for 128 sequences of 196 tokens) and K ∈ R^{M×N} is a fixed Kronecker-sparse matrix with support I_a ⊗ 1_{b×c} ⊗ I_d. The KS matrix K can be fully preprocessed offline, but inputs and outputs must follow a fixed dense layout (PyTorch's row-major default), reflecting standard inference deployment where data arrives in a prescribed format. Benchmarked matrix sizes span six orders of magnitude (102×102 to 131072×131072), covering hidden dimensions found in vision and language Transformers.

## Method

The paper introduces an output-stationary tiling strategy that reformulates the KS multiplication as a set of independent dense sub-products, one per tile (row_{i,j}, col_{i,j}), by grouping rows that share the same support pattern. This reformulation (Algorithm 2) is mathematically equivalent to the standard permute-GEMM-permute pipeline but eliminates both global memory permutations: each thread block directly loads the non-contiguous input and weight tiles from global to shared memory, performs multiply-accumulate in registers with double buffering, and writes the output tile back to global memory in a single fused kernel. This reduces global memory traffic on input/output tensors by a factor of three (from 3B(N+M) to B(N+M) operations). The paper further derives a one-line design heuristic h(b,c) = (b+c)/(bc) that predicts when the fused kernel outperforms existing baselines, validated across 600 KS patterns with a median ×1.4 speedup and 15% energy reduction in FP32, and demonstrates end-to-end latency reductions of 22% in ViT-S/16 and 16% in GPT-2 Medium.

## Results

Across 600 Kronecker-sparse patterns spanning six orders of magnitude in matrix size, the fused output-stationary KERNEL achieves a median speedup of ×1.4 in FP32 over the best existing baseline (BMM) and reduces energy consumption by 15%. KS-aware implementations collectively outperform generic dense/CSR baselines by a median ×6.5 on 98.1% of patterns. End-to-end, injecting KS sparsity with the fused kernel cuts inference latency by 22% on ViT-S/16 and 16% on GPT-2 Medium in FP32, compared to 11% and 12% respectively for the best existing baseline (BMM).

## Baselines & Comparisons

The paper benchmarks against five baselines: BMM (Monarch's batched-GEMM implementation, the fastest existing KS-aware method), BSR (block-sparse format), EINSUM (tensor contraction), DENSE (standard dense matmul), and SPARSE (CSR format). The fused KERNEL outperforms all five baselines on 85.5% of the 600 benchmarked patterns in FP32, with a median ×1.39 speedup. Among existing methods, BMM is the strongest baseline, beating EINSUM, BSR, DENSE, and SPARSE on 90% of patterns. The speedup of KERNEL over BMM is driven primarily by the heuristic h(b,c) = (b+c)/(bc), which captures the proportion of runtime spent on the two global-memory permutations that KERNEL eliminates; patterns with higher h(b,c) show larger gains (up to ×2). In half-precision (FP16), KERNEL's advantage narrows to 37.8% of patterns (median ×1.51), likely because tensor cores reduce the relative cost of the permutation overhead. End-to-end on ViT-S/16, KERNEL achieves a 0.78× latency ratio vs. dense (22% reduction) compared to BMM's 0.89× (11% reduction); on GPT-2 Medium, KERNEL reaches 0.84× (16%) vs. BMM's 0.88× (12%).

## Relation to Prior Work

This paper builds directly on the Monarch/Butterfly/Kaleidoscope family of Kronecker-sparse structured matrices (Dao et al., 2019; 2022a;b; Fu et al., 2023) and specifically targets the GPU kernel implementation of their matrix multiplication. The prior BMM implementation (Dao et al., 2022b) follows a permute–GEMM–permute strategy using perfect-shuffle permutations to block-diagonalize the KS factor; this paper shows that the two permutation steps are unnecessary by reformulating the computation as a set of independent dense sub-products (Algorithm 2) and fusing them into a single output-stationary CUDA kernel. The analogy to sparse 3D convolution kernels (Tang et al., 2023; Spconv) that fused GATHER–MATMUL–SCATTER is noted, though the authors argue the nested Kronecker structure does not admit a direct transfer of those tiling strategies.

## Why It Matters / Open Questions

The finding that up to 50% of runtime in existing KS kernels is consumed by memory permutations rather than arithmetic is a useful diagnostic for the structured-sparse inference community, and the simple heuristic h(b,c)=(b+c)/(bc) gives practitioners a one-line rule for pattern selection. However, the gains are notably smaller in FP16/FP8 where tensor cores shift the bottleneck, the batch-size-last layout that unlocks the full speedup is not PyTorch's default, and end-to-end accuracy trade-offs from training with KS factors remain unexplored. Extending the kernel to leverage tensor cores and studying cache behavior are identified as key next steps for broader adoption.
