## Problem

Current AI safety evaluation tests whether individual models can accomplish malicious tasks in isolation, but this is insufficient: adversaries can decompose malicious tasks into benign subtasks (solved by capable but aligned frontier models) and malicious subtasks (solved by weaker models with inadequate refusal training), achieving misuse without ever circumventing any model's safety mechanisms. The paper asks whether combinations of individually safe models enable misuse at rates far exceeding either model alone.

## Input / Output

For code tasks, the adversary receives a programming question paired with a specific vulnerability specification (or a hacking task description) and must produce a single production-ready Python script that both executes the task and contains the vulnerability. For image tasks, a scene description prompt (e.g., a person doing an activity) is transformed into a 1024×1024 explicit image. For manipulation, the input is a user's historical tweet/retweet corpus plus a target politician, and the output is three tweets designed to shift the user's opinion. Critically, the frontier model never receives the malicious task directly—it only sees benign subtasks or related tasks, so its safety filters are never triggered.

## Method

The paper formalizes a threat model where an adversary sequentially queries a set of models, choosing a model and prompt at each turn, and wins upon producing an output satisfying a malicious predicate. Two decomposition strategies are studied: (1) manual decomposition, where a human splits the task into a complicated-but-benign component (assigned to a frontier model like Claude 3 Opus or DALL-E 3) and a simple-but-malicious component (assigned to a weak model like Llama 2 70B or Stable Diffusion v1.5), and (2) automated decomposition, where the weak model first generates three related-but-benign tasks, the frontier model solves them, and the weak model then uses those solutions as in-context references to solve the original malicious task. The key insight is that many malicious tasks are natural compositions of capability-intensive benign subtasks and refusal-sensitive malicious subtasks, so combining a capable-but-refusing model with a less-capable-but-compliant model unlocks misuse without jailbreaking. Empirically, combinations achieve dramatically higher success rates (e.g., 43% vs. <3% for vulnerable code with Llama 2 70B + Claude 3 Opus), and success scales with the capability of both models.

## Results

On the vulnerable code generation task, combining Llama 2 70B-chat with Claude 3 Opus achieves a 42.7% success rate, while neither model alone exceeds 3% (Llama 70B single-shot: 2.0%, Claude 3 Opus: 0.0%). For explicit image generation in unrealistic environments, the DALL-E 3 + Stable Diffusion v1.5 combination reaches 30% accuracy versus <2% for either model individually. On malicious python script generation, combining Mixtral 8x7B with Claude 3 Opus achieves 21.5% success, compared to 10.8% for Mixtral alone and 0.0% for Claude 3 Opus. In simulated personalized manipulation, combining Mistral 7B with Claude 3 Opus improves success from 17.7% to 33.7% for two-user manipulation.

## Baselines & Comparisons

The paper compares the model-combination strategy against two single-model baselines: (1) single-shot, where a model attempts the malicious task in one prompt, and (2) single-model decomposition, where the same model decomposes the task into subtasks and solves each. Across all four experiments, the combination strategy substantially outperforms both baselines. The gap is most dramatic for frontier models (Claude 3 Sonnet/Opus), which achieve 0% on all tasks due to refusal, making them useless in isolation but highly effective as capability providers in a combination. For weak models, the combination typically doubles or triples success rates (e.g., Mistral 7B goes from 24.3% single-shot to 49.7% with Claude 3 Opus on vulnerable code). The single-model decomposition baseline is consistently worse than single-shot for weak models, confirming that the key enabling factor is combining *distinct* models with complementary strengths (capability + non-refusal), not merely decomposing the task.

## Relation to Prior Work

This paper extends Glukhov et al.'s (2023) theoretical argument that no single censored model can be safe against all malicious tasks (since they decompose into benign subtasks) by providing the first empirical demonstration that adversaries can exploit *combinations* of individually-safe models across realistic tasks. It departs from the jailbreak literature (Wei et al., 2023; Zou et al., 2023) by showing misuse occurs *without* circumventing safety mechanisms—the frontier model never produces a malicious output. The work also inverts the benign model-combination literature (Juneja et al., 2023; Greenblatt et al., 2023; Mitchell et al., 2024), which showed that combining models enhances capabilities, by demonstrating the same mechanism amplifies misuse risk.

## Why It Matters / Open Questions

The paper's central implication—that red-teaming must extend to model combinations and that even perfectly-aligned frontier systems enable harm without producing malicious outputs—challenges the current industry practice of evaluating models in isolation. The risk scales with both frontier and weak model capability, suggesting the problem will worsen as models improve. Key open questions include whether adaptive LLM agents or reinforcement-learning-trained weak models could push success rates much higher, and whether platform-level defenses (e.g., monitoring GitHub for vulnerable code) are tractable. Limitations include reliance on synthetic datasets, GPT-4 as evaluator, and the fact that weak models are open-source and thus unmonitored, making the threat model harder to defend against in practice.
