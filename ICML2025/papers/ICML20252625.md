## Problem

Static depth pruning removes a fixed set of transformer blocks regardless of the input, yet the paper demonstrates that block importance is highly task-dependent—a block critical for BoolQ can be safely pruned for PIQA. This rigidity forces a trade-off between tasks, and no prior method addresses prompt-adaptive depth pruning in the memory-constrained on-device setting where all parameters cannot be held in high-speed memory.
![Teaser figure](../imgs/ICML20252625/cropped_page0_idx0.webp)

## Input / Output

The method takes a user text prompt as input and produces two outputs: (1) a selected omission set (a fixed-cardinality subset of transformer block indices to skip, determined by a BERT-base router in a single forward pass), and (2) the generated text response from the depth-pruned LLM. The omission set must always contain exactly k blocks to satisfy a hard peak-memory constraint on the target device, and the router's predicted loss vector over m candidate sets is used to pick the argmin index.

## Method

PuDDing operates in two stages. First, it generates a small candidate pool of m omission sets by greedily pruning blocks on t diverse task calibration splits using two novel task-focused losses—task likelihood (tl), which measures log-likelihood only on answer tokens rather than the full sequence, and task likelihood difference (tld), which contrasts correct vs. wrong answer likelihoods for multiple-choice tasks. Second, it trains a BERT-base router with a linear head to predict the m-dimensional loss vector for a given prompt, using MSE loss on soft labels (the actual tl values rather than one-hot class labels). At inference, the router runs once per prompt to select the candidate omission set with the lowest predicted loss, after which only the non-omitted blocks are loaded from storage into device RAM. This per-prompt (not per-token) routing keeps the overhead to 2–4% of pre-fill cost while preserving the sparse memory footprint that makes on-device deployment feasible.

## Results

On LLaMA-3.1-8B at 20% sparsity (7 blocks pruned), PuDDing achieves 61.93% average zero-shot accuracy across six commonsense reasoning tasks, outperforming the best static depth-pruning baseline SLEB (57.24%) by 4.69 percentage points and the best width-pruning baseline FLAP (50.96%) by 10.97 points. At lower sparsity (10%, 3 blocks), PuDDing reaches 69.13% vs. SLEB's 68.19%. The method also delivers a consistent 1.19–1.25× wall-clock speedup over the dense model on both A100 and RTX 6000 Ada GPUs, with router overhead of only 4–8 ms per prompt.

## Baselines & Comparisons

PuDDing outperforms all four baselines at every sparsity level tested. Against SLEB (iterative perplexity-based depth pruning), PuDDing gains +4.69 pp at 20% sparsity (61.93% vs. 57.24%), +2.23 pp at 15% (64.71% vs. 62.48%), and +0.94 pp at 10% (69.13% vs. 68.19%). Against Shortened LLaMA (one-shot perplexity depth pruning), the margins are +6.16 pp, +1.64 pp, and +3.42 pp respectively. Both width-pruning baselines—FLAP (50.96%) and SliceGPT (50.28%) at 20% sparsity—suffer substantially larger accuracy drops than PuDDing, with PuDDing leading by over 10 pp. The only exception is BoolQ at 20% sparsity, where FLAP (62.32%) narrowly edges out PuDDing (62.02%), though PuDDing still dominates on the remaining five tasks. A naive 'SLEB per prompt' variant (52.58%) performs worse than static SLEB, confirming that per-prompt calibration with a single sample is insufficient and motivating the learned router approach.

## Relation to Prior Work

This paper extends the contextual sparsity paradigm (Deja Vu, ShadowLLM, Sirius, CATS) from width pruning to depth pruning, and shifts the routing granularity from per-token (Mixture-of-Depth, D-LLM) to per-prompt, making it compatible with on-device memory constraints where not all parameters can reside in high-speed memory. It builds on static depth pruning methods (SLEB, Shortened LLaMA) by replacing their fixed omission sets with a learned router, and introduces task-likelihood losses as a replacement for perplexity-based block importance metrics. The key conceptual departure is treating depth pruning as a prompt-conditional classification problem over a small candidate pool, rather than a one-shot or per-token sequential decision.

## Why It Matters / Open Questions

The paper addresses a practical gap in on-device LLM deployment: static depth pruning sacrifices task adaptivity, while dynamic token routing requires all parameters in GPU memory. PuDDing's prompt-level routing with sparse memory footprint is well-suited for consumer hardware, and the consistent ~4%p accuracy gain over the best static baseline at 20% sparsity across three model families is practically meaningful. Key limitations include the assumption of access to diverse task datasets for calibration, a fixed number of pruned blocks (motivated by peak memory), and evaluation limited to commonsense reasoning rather than open-ended generation. Open questions include whether variable-depth pruning could further improve quality, and how to generate candidate omission sets from unlabeled corpora without task-specific data.
