## Problem

Supervised fine-tuning (SFT) of large language models consistently degrades confidence calibration, making models overconfident in their predictions, yet label smoothing—a known calibration regularizer—has not been widely adopted in LLM SFT. Moreover, for large-vocabulary LLMs, the cross-entropy computation with label smoothing becomes memory-prohibitive because the full N×|V| logit matrix must be materialized, and existing efficient CE kernels (e.g., Cut-Cross-Entropy, Liger Kernels) do not support the smoothing term.

## Input / Output

The method takes a pre-trained LLM (LLaMA3, Gemma2, or Mistral families), an SFT instruction dataset (Alpaca, Tulu3, or OpenHermes), and a smoothing rate β∈[0,1], and produces a calibrated fine-tuned model evaluated via ECE and RMS-CE on MMLU, HellaSwag, and ARC-Easy. The custom Triton kernel computes the smoothed cross-entropy loss and its gradients without materializing the full logit matrix in global memory, instead fusing the target loss, uniform smoothing loss, and log-sum-exp into block-level SRAM operations with only ~1.1 MB forward-pass overhead.

## Method

The paper provides a theoretical analysis showing that SFT degrades calibration by reducing feature-embedding diversity (linked to the minimum singular value of the input covariance), and that label smoothing acts as a MAP estimator with a uniform Dirichlet prior that encourages logit equality across classes. A key theoretical contribution is an entropy lower bound for the LM head showing that for large vocabulary |V| with small hidden size D, the minimum prediction entropy scales as Ω(|V|·e^{−ρ√D}), meaning such models cannot become overconfident and thus label smoothing offers no calibration benefit. To address the practical memory bottleneck, the authors design a custom Triton kernel that chunks the embedding and classifier matrices, computes all three loss components (target, smoothing, LSE) in parallel within on-chip SRAM, and uses a lock-based online LSE update across vocabulary blocks—achieving over 75% memory reduction versus the next-best competitor while matching Cut-Cross-Entropy throughput when β=0 and adding less than 1% overhead when β>0.

## Results

Across all three SFT datasets (Alpaca, Tulu3Mixture, OpenHermes) and three evaluation benchmarks (MMLU, HellaSwag, ARC-Easy), label smoothing with β=0.1 consistently reduces ECE by 50–95% while preserving accuracy within ~1%. For example, LLaMA3-8B on Tulu3Mixture drops MMLU ECE from 0.050 to 0.012, and Gemma2-2B on OpenHermes drops MMLU ECE from 0.341 to 0.020. The custom Triton kernel achieves 1,164 MB peak memory for forward+backward with label smoothing, compared to 28,000 MB for the baseline torch.nn.CrossEntropyLoss and 16,000 MB for torch.compile, while running in 72.9 ms (vs. 104.9 ms baseline).

## Baselines & Comparisons

For the efficient kernel, the proposed Triton implementation matches Cut-CrossEntropy (Wijmans et al., 2025) almost exactly on both memory (1,164 MB vs. 1,164 MB) and time (72.9 ms vs. 72.4 ms) when β=0, with less than 0.5% overhead in the forward pass. However, Cut-CrossEntropy does not support label smoothing (β>0), whereas the proposed kernel handles it at the same memory cost. Against Liger Kernels (Hsu et al., 2024), the proposed method uses 78% less peak memory (1,164 MB vs. 5,349 MB for fwd+bwd) while being 2.1× faster (72.9 ms vs. 155.0 ms). Against torchtune's Chunked Cross Entropy (PyTorch, 2024), the proposed kernel uses 91% less memory (1,164 MB vs. 13,000 MB) and is 1.1× faster (72.9 ms vs. 82.8 ms). The only method that is faster is torch.compile (62.3 ms), but it requires 16,000 MB of memory—nearly 14× more—and its memory footprint increases further when label smoothing is enabled, unlike the proposed kernel.

## Relation to Prior Work

This paper repurposes label smoothing—a regularization technique well-studied in vision (Müller et al., 2019; Szegedy et al., 2016)—as a calibration mechanism for LLM supervised fine-tuning, a setting where it had not been systematically studied. The theoretical analysis draws on Oh et al. (2024) for OOD calibration bounds tied to feature diversity, and on Zhai et al. (2023) for entropy-constrained optimization of softmax outputs, to derive a novel entropy lower bound linking vocabulary size and hidden dimension to a model's capacity for overconfidence. On the systems side, the custom Triton kernel extends the block-based log-sum-exp strategy of Cut-Cross-Entropy (Wijmans et al., 2025) to support the additional smoothing term, filling a gap that existing efficient cross-entropy implementations (Liger Kernels, torchtune) cannot address.

## Why It Matters / Open Questions

The entropy-bound result provides a concrete architectural criterion—ratio of |V| to D—under which label smoothing is provably ineffective, explaining a previously unexplained empirical observation and guiding practitioners on when to rely on LS versus alternatives like temperature scaling or logit capping. The custom kernel makes LS practical for 256K-vocabulary models (e.g., Gemma2) by reducing peak memory from ~28 GB to ~1.2 GB, removing a significant barrier to adoption. Open questions include whether the entropy bound is tight in practice, whether the LS-ineffective regime admits other calibration remedies beyond logit manipulation, and whether the kernel's design generalizes to other smoothed or structured loss variants beyond standard label smoothing.
