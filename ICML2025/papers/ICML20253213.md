## Problem

Existing cybersecurity benchmarks for LLM agents are limited to abstracted CTF challenges or short code snippets, failing to reflect the complexity of exploiting real-world web application vulnerabilities. No prior benchmark combines critical-severity CVEs, diverse attack types, and reproducible sandboxed environments, leaving a gap in systematically measuring how well AI agents can autonomously compromise production-like web applications.
![Teaser figure](../imgs/ICML20253213/cropped_page1_idx0.webp)

## Input / Output

Agents receive a task description specifying the target URL, eight standard attack goals (DoS, file access, file creation, database modification, database access, unauthorized admin login, privilege escalation, outbound service), and disallowed attacks; under the one-day setting, an NVD vulnerability description is additionally provided. The vulnerable application is hosted in containerized Docker environments (typically a web server on port 9090 plus a database and auxiliary containers). Output is a binary success/failure verdict from an in-container evaluation server that checks all eight attack conditions, along with the specific attack type achieved and per-task cost metrics (input/output tokens, wall-clock time, and USD).

## Method

CVE-Bench introduces a sandbox framework that containerizes 40 critical-severity (CVSS ≥ 9.0) web application CVEs from the NVD, each with a reproduced reference exploit (5–24 person-hours per CVE) and an automated grader co-located in the target container. The key design choice is standardizing evaluation into eight prevalent attack types, making success measurable across heterogeneous applications without requiring a one-size-fits-all intrusion detection system. The benchmark supports two vulnerability-lifecycle settings: zero-day (agents must discover the vulnerability independently) and one-day (agents receive the NVD description as guidance). Experiments evaluate three agent architectures—Cy-Agent (ReAct loop), T-Agent (hierarchical supervisor + specialized hacker agents with sqlmap), and AutoGPT (self-criticism loop)—using GPT-4o with a 30-iteration cap, revealing that the best agent (T-Agent) achieves only 13% success@5 under one-day, with insufficient exploration being the dominant failure mode across all agents.

## Results

On CVE-Bench (40 critical-severity web application CVEs), LLM agents exploit up to 10% of vulnerabilities under the zero-day setting and up to 13% under the one-day setting (five attempts). T-Agent achieves the highest one-day success rate at 13%, while Cy-Agent achieves only 2.5% in the same setting. Per-task monetary costs range from $0.6 (Cy-Agent, zero-day) to $1.7 (T-Agent), with average completion times from 264 s (AutoGPT, one-day) to 3,642 s (AutoGPT, zero-day).

## Baselines & Comparisons

CVE-Bench evaluates three agent frameworks: Cy-Agent (from Cybench, a ReAct-style single agent), T-Agent (a hierarchical multi-agent team from Fang et al. 2024c), and AutoGPT (a general-purpose autonomous agent). T-Agent dominates in the one-day setting, reaching 13% success@5, largely driven by its SQL team's effective use of sqlmap for database-access attacks (68% of its zero-day successes). AutoGPT achieves the highest overall success@5 rate and surprisingly performs better in zero-day than one-day, because it discovers easier alternative vulnerabilities (e.g., login-form SQL injection) that bypass the harder target CVE. Cy-Agent trails significantly at 2.5% success@5 in one-day, as its single-agent act-execute-update loop is poorly suited to the extensive exploration required by real-world web applications. The dominant failure mode across all agents is insufficient exploration (37.5–80% of failures), indicating that locating the vulnerable endpoint remains the key bottleneck regardless of framework design.

## Relation to Prior Work

This paper carves new ground by constructing the first real-world cybersecurity benchmark for LLM agents based on critical-severity CVEs, departing from prior CTF-based benchmarks (Cybench, NYU CTF Bench) that use abstracted challenges and from Fang et al. (2024a;c) which covered only 25 medium-to-critical CVEs with a single attack type per vulnerability. Rather than building on a specific prior method, CVE-Bench repurposes the general idea of evaluating LLM agents on offensive security tasks by introducing a sandbox framework with containerized vulnerable applications, eight standardized attack types per CVE, and automatic grading. The agent frameworks evaluated (Cy-Agent, T-Agent, AutoGPT) are treated as baselines rather than foundations, and the benchmark's contribution is the evaluation infrastructure and task formulation rather than a new agent architecture.

## Why It Matters / Open Questions

CVE-Bench establishes a practical baseline for understanding the offensive security capabilities of LLM agents, showing that even state-of-the-art multi-agent frameworks exploit only ~13% of critical web vulnerabilities, which is both reassuring and concerning for AI safety. The identification of insufficient exploration as the dominant failure mode across all agents points to a concrete direction for improving agent architectures. Key limitations include the narrow scope (40 CVEs from a six-week window, eight predefined attack types that may produce false negatives), and open questions include whether success rates will rise rapidly as agent exploration improves, how the benchmark generalizes beyond web applications, and whether the zero-day/one-day gap will narrow as models improve.
