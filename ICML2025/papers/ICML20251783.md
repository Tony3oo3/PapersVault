## Problem

Existing software engineering benchmarks like SWE-Bench and SWE-Bench Verified evaluate models on isolated, self-contained tasks from open-source repositories graded by unit tests that are susceptible to grader hacking and insufficient for full-stack engineering. No prior benchmark maps model performance to real economic value, includes technical management tasks, or uses professionally written end-to-end tests that mirror how experienced engineers actually evaluate freelance work. SWE-Lancer asks whether frontier LLMs can earn $1 million from real-world freelance software engineering tasks with genuine monetary payouts.

## Input / Output

For IC SWE tasks, the model receives an issue description (with reproduction steps and expected behavior), a codebase snapshot at the pre-fix state, and must produce a code patch; it can invoke a user tool that opens a browser to simulate user interaction, returning text-based trajectories and screenshots to its working directory. For SWE Manager tasks, the model receives multiple freelancer proposals alongside the codebase and must output a JSON file selecting the best proposal ID. All evaluation runs in a Docker container with no internet access, a single attempt (pass@1), a maximum of 100 tool calls, and a 3-hour time limit; IC SWE solutions are graded by Playwright end-to-end tests the model cannot access, while Manager selections are checked against ground-truth manager decisions.

## Method

SWE-Lancer constructs a benchmark of 1,488 real freelance tasks (764 IC SWE worth $414,775 and 724 SWE Manager worth $585,225) sourced from the Expensify open-source repository's Upwork postings, totaling $1,000,000 in actual payouts. The key methodological innovation is replacing unit tests with end-to-end Playwright tests written by a team of 100 professional software engineers and triple-verified for quality, coverage, and fairness, making the evaluation resistant to the grader hacking that plagues unit-test-based benchmarks. A user tool provides iterative debugging capability by simulating real user workflows in a browser, producing trace files and screenshots that models can parse programmatically. The SWE Manager component is novel in evaluating models' ability to act as technical leads by selecting among competing implementation proposals, validated against original engineering manager choices with 99% inter-rater agreement. The public Diamond split ($500,800) is released alongside a unified Docker image, while a $499,200 private holdout (including augmented tasks with reintroduced bugs) mitigates contamination risk.

## Results

On the SWE-Lancer Diamond set (502 tasks worth $500,800), Claude 3.5 Sonnet achieves the best overall pass@1 of 36.1%, earning $208k out of $501k possible (41.5% earn rate). On IC SWE tasks specifically, Claude 3.5 Sonnet scores 26.2% pass@1 ($58k/$236k), while o1 (High reasoning) reaches 16.5% and GPT-4o only 8.0%. On SWE Manager tasks, all models perform substantially better: Claude 3.5 Sonnet reaches 44.9%, o1 reaches 41.5%, and GPT-4o reaches 37.0%. On the full SWE-Lancer dataset (1,488 tasks, $1M total), Claude 3.5 Sonnet earns $403k (40.3%), o1 earns $380k (38.0%), and GPT-4o earns $304k (30.4%).

## Baselines & Comparisons

This is a benchmark paper evaluating frontier LLMs rather than proposing a new method, so the comparisons are across models. Claude 3.5 Sonnet outperforms o1 by 9.7 percentage points on IC SWE Diamond tasks (26.2% vs. 16.5%) and by 3.4 points on SWE Manager Diamond tasks (44.9% vs. 41.5%). GPT-4o trails both, scoring 8.0% on IC SWE Diamond and 37.0% on SWE Manager Diamond. All models perform substantially better on SWE Manager tasks than IC SWE tasks (e.g., Claude 3.5 Sonnet: 44.9% vs. 26.2%), indicating that evaluating proposals is easier than generating code patches. The paper also notes that increasing test-time compute for o1 improves IC SWE pass@1 from 9.3% (Low) to 16.5% (High), and that allowing 5 attempts (pass@5) before deferring to a human freelancer yields 33.5% cost savings with o1 versus 18.6% with GPT-4o.

## Relation to Prior Work

SWE-Lancer departs from the SWE-Bench lineage (SWE-Bench, SWE-Bench Verified, SWE-Bench Multimodal) in three fundamental ways: it sources tasks from real freelance job postings on Upwork rather than open-source GitHub pull requests, it grades solutions with hand-written end-to-end Playwright tests rather than pre-existing unit tests, and it introduces a novel SWE Management task type where models must select the best implementation proposal from competing freelancers. The monetary mapping—where each task carries the actual payout sent to the freelancer who resolved it—has no precedent in prior coding benchmarks, which report only pass rates. The paper also contrasts with competitive programming and program synthesis benchmarks (HumanEval, APPS, LiveCodeBench) by targeting full-stack, user-facing commercial software rather than self-contained algorithmic problems.

## Why It Matters / Open Questions

By tying model performance to $1M in real freelance payouts, SWE-Lancer provides the first direct economic lens on AI's potential to automate software engineering labor, enabling concrete cost-savings analyses (e.g., o1 + freelancer fallback yields ~33% savings at pass@5). The finding that the best model (Claude 3.5 Sonnet) resolves only 26.2% of IC SWE tasks—far below the 72% o3 achieves on SWE-Bench Verified—suggests prior benchmarks are saturated while real-world freelance work remains largely unsolved. Key limitations include reliance on a single repository (Expensify), text-only inputs, absence of infrastructure/DevOps tasks, and the inability of models to ask clarifying questions. Open questions include whether the economic mapping generalizes beyond freelance work to full-time engineering, how multimodal inputs (screen recordings, screenshots) would shift performance, and what the labor-market implications are as model capabilities improve.
