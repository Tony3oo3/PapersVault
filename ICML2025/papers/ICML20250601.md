## Problem

Existing VideoQA benchmarks rely on human expertise to design challenging questions, yet humans systematically misjudge which questions are hard for ML models — questions perceived as easy by annotators are often the hardest for models. Prior complexity definitions are static and heuristic-based, making them myopic and difficult to extend as new architectures emerge.
![Teaser figure](../imgs/ICML20250601/cropped_page1_idx0.webp)

## Input / Output

The method takes natural language VideoQA questions, converts them into executable Python programs via an LLM code generator (ViperGPT or RVP), and parses those programs into Abstract Syntax Trees. It outputs a scalar CodePlexity score per question, an interpretable set of code subtrees statistically linked to model failures, and — when applied to new video descriptions — a filtered set of automatically generated challenging question-answer pairs (CodePlex-QA, 1981 samples with 5-choice answers).

## Method

The core insight is that the structural and semantic complexity of LLM-generated visual programs serves as a data-driven proxy for question difficulty, inspired by Kolmogorov Complexity. Each program is compiled into an AST, from which all valid subtrees (recurring logical patterns) are extracted and deduplicated via a co-occurrence merging rule. Questions are one-hot encoded by subtree presence, and a logistic regression is trained on binary success/failure labels from a pool of VideoQA models to produce the CodePlexity score (negative predicted success probability). A one-sided hypothesis test then identifies subtrees whose presence significantly decreases model performance, yielding interpretable failure-mode diagnostics. For benchmark construction, GPT-4 generates question candidates from scene-graph-derived video scripts, CodePlexity scores each candidate, and the top 10% by complexity are retained after a 12% manual quality filter, producing a benchmark 1.9× harder than NExT-QA.

## Results

On the NExT-QA validation set, CodePlexity achieves mPEG scores of 14.1–26.6 across five held-out VideoQA models (HGA, SeViLA-ZS, InternVideo, Tarsier, LLaVa-Video), substantially outperforming the best text-based baseline (BERT, 7.7–21.1) and the best non-learned code metric (Cyclomatic Complexity, 8.9–24.2). The generated benchmark CodePlex-QA is empirically 1.9× harder than NExT-QA: for example, LLaVa-Video drops from 82.5% to 65.0% accuracy and Tarsier from 70.9% to 52.5%, while the random baseline remains at 20.0%. CodePlexity also generalizes to the MVBench dataset, where it again outperforms Lines of Code and Cyclomatic Complexity across all evaluated models.

## Baselines & Comparisons

CodePlexity outperforms all five baselines on every held-out validation model. Against the strongest text-based baseline, BERT (fine-tuned to predict model success from question text), CodePlexity gains +6.4 mPEG on HGA (14.1 vs 7.7), +11.3 on SeViLA-ZS (25.6 vs 14.3), and +5.9 on LLaVa-Video (17.3 vs 11.4). Against the strongest non-learned code metric, Cyclomatic Complexity, CodePlexity improves by +5.2 on HGA (14.1 vs 8.9), +8.4 on SeViLA-ZS (25.6 vs 17.2), and +5.8 on Tarsier (24.9 vs 16.7). The learning-free Dependency Tree Depth and GPT-4 baselines are consistently the weakest, with GPT-4 scoring as low as 5.2 on LLaVa-Video. Notably, even the simplest code-based metric (Lines of Code) surpasses all text-based baselines in most settings, supporting the paper's central claim that generated code structure is a more reliable proxy for question difficulty than natural-language features. On the benchmark comparison (Table 2), CodePlex-QA is harder than both NExT-QA and the adversarial ATP-Hard split for the top-performing models (LLaVa-Video, Tarsier, SeViLA-ZS, ViperGPT), though ATP-Hard remains slightly harder for InternVideo due to its CLIP-specific targeting.

## Relation to Prior Work

This paper builds on the code-generation paradigm for visual reasoning (ViperGPT, RVP) but repurposes it not for answering questions, but for analyzing question difficulty. It departs from the dominant top-down approach to VideoQA benchmark design—where experts hypothesize what is hard and validate with targeted models—by proposing a bottom-up, data-driven metric (CodePlexity) that learns which code subtrees correlate with model failure. The theoretical grounding draws on Kolmogorov Complexity, but the practical contribution is a computable, extensible metric that subsumes simpler structural measures like cyclomatic complexity and lines of code.

## Why It Matters / Open Questions

The finding that human intuition about question difficulty is inversely correlated with actual model performance challenges a foundational assumption in benchmark design and suggests that future VideoQA benchmarks should be constructed via data-driven methods rather than expert curation. CodePlex-QA, being 1.9× harder than NExT-QA, provides a concrete, reusable benchmark that exposes fine-grained temporal reasoning and spatio-temporal object-centric weaknesses in current models. Open questions include combining question complexity with video complexity (the paper shows these interact), extending the analysis to non-CLIP-based architectures, and whether the metric remains valid as code generation models improve.
