## Problem

Existing LLM-based multi-agent systems (MAS) suffer from two fundamental limitations: they are either manually crafted and static (MetaGPT, ChatDev, AgentVerse), lacking adaptability to diverse queries, or they require multiple expensive LLM inferences and validation sets to adapt per query (GPTSwarm, AFlow, DyLAN). No prior work has shown how to generate a query-specific, executable MAS in a single LLM inference, making MAS deployment at scale impractical.
![Teaser figure](../imgs/ICML20252883/cropped_page0_idx0.webp)

## Input / Output

The system takes a free-form user query as input and produces an executable MAS in the form of a Python forward function, where agent prompts are variables, LLM calls are function invocations, and inter-agent interactions are string concatenations. The generated code is directly runnable: it is executed to process the original query and yield a final answer. The entire MAS generation requires exactly one inference from a 32B model, after which the MAS itself may invoke the driving LLM multiple times depending on its architecture.

## Method

MAS-GPT reframes MAS construction as a generative language task and trains a 32B LLM (Qwen2.5-Coder-32B-Instruct) via supervised fine-tuning on ~11k query-MAS pairs. The key technical contributions are: (1) a unified code representation of MAS as a Python forward function, and (2) a consistency-oriented data construction pipeline with four stages—pool construction (40+ base MAS designs), pair evaluation (scoring each query-MAS combination), inter-consistency-oriented selection (clustering similar queries and assigning a single highest-scoring MAS to the entire cluster to enforce consistent query-MAS mappings), and intra-consistency-oriented refinement (using an LLM to adjust agent prompts to be query-specific and to generate a reasoning statement linking the query to the MAS, with a not-worse-score acceptance criterion). At inference, MAS-GPT generates the MAS code in one forward pass, which is then executed to produce the final answer.

## Results

Using Llama-3-70B-Instruct as the MAS-driving LLM, MAS-GPT achieves a 65.47% average across 8 benchmarks, outperforming the second-best method (DyLAN at 60.54%) by 3.89%. MAS-GPT is the only method that consistently beats the single-agent baseline on every benchmark. On the highly challenging AIME-2024 benchmark with o1-preview, MAS-GPT brings a 13.34% absolute gain over the single LLM, and with DeepSeek-R1 a 10.0% gain, demonstrating its potential to further augment strong reasoning models.

## Baselines & Comparisons

MAS-GPT outperforms all 10 baselines on average (65.47% vs. 60.54% for DyLAN, the runner-up), with particularly large margins on MATH (+7.06% over Self-Consistency) and GSM-Hard (+15.20% over Self-Consistency). The only benchmark where MAS-GPT does not achieve the top score is GPQA (37.62% vs. AgentVerse's 40.19%), though it still exceeds the single-agent baseline. Against the task-specific optimizer AFlow (optimized on MATH), MAS-GPT outperforms it on MATH by 3.53% while AFlow degrades below single-LLM performance on out-of-domain benchmarks (MMLU, HumanEval+). Compared to ChatDev (designed for software development), MAS-GPT achieves 91.18% vs. 83.33% on HumanEval and 77.59% vs. 62.07% on MATH. MAS-GPT also generalizes across MAS-driving LLMs: with Qwen2.5-72B it achieves 74.46% average (vs. DyLAN's 74.33%), and with GPT-4o-mini it reaches 70.50% (vs. Self-Consistency's 69.29%), confirming strong compatibility regardless of the underlying LLM.

## Relation to Prior Work

This paper departs from two existing lines of MAS research: (1) manually designed, query-agnostic systems (MetaGPT, ChatDev, AgentVerse) and (2) adaptive MAS that iteratively optimize agent configurations via multiple LLM calls (GPTSwarm, AFlow, DyLAN, ADAS). It carves new ground by reframing MAS construction as a single-shot generative language task—input a query, output an executable Python code snippet representing the MAS—unifying the representation of all prior MAS methods into a common forward-function format. The training pipeline draws on SFT paradigms from LIMA and WizardLM but introduces a novel consistency-oriented data construction process (inter-consistency selection + intra-consistency refinement) specifically designed for the query-to-MAS mapping, which has no direct precedent in prior LLM post-training literature.

## Why It Matters / Open Questions

The practical impact is significant: MAS-GPT reduces the cost of obtaining a task-specific MAS from manual engineering or 10+ proprietary LLM API calls to a single 32B-model inference, making MAS deployment at scale feasible. The demonstrated generalization across 9 benchmarks, 5 LLM backbones, and out-of-domain settings (GPQA, SciBench, AIME-2024) suggests the approach could become a standard component in LLM application stacks. Key limitations include reliance on SFT alone (no RL for autonomous MAS exploration), a relatively small and potentially biased training set (~11k pairs, 7,580 unique MAS), and no integration of multi-modal or tool-use capabilities. Open questions include whether RL can enable MAS-GPT to discover genuinely novel architectures beyond the 40+ base designs, and whether the consistency-oriented data pipeline generalizes to open-ended tasks without verifiable ground truth.
