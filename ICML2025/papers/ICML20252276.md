## Problem

Serving long-context LLMs is bottlenecked by the KV cache, which scales linearly with sequence length and dominates both GPU memory and per-token decoding bandwidth. Existing solutions face a trilemma: eviction methods lose information irreversibly, dynamic sparse attention (e.g., Quest) keeps the full KV cache on GPU so it cannot reduce memory or support very long contexts, and naive CPU offloading introduces prohibitive PCIe fetch latency during decoding. No prior method simultaneously reduces GPU memory footprint, minimizes decoding latency, and preserves accuracy under a small sparse KV budget.

## Input / Output

The system takes a long-context text prompt (up to 1M tokens) and a pre-trained LLM (e.g., Llama-3.1-8B, GLM-4-9B-1M) as input. During pre-filling it produces a compressed KV cache consisting of: (i) low-rank pre-RoPE key projections (rank ≈160) and chunk-level landmarks stored on GPU, (ii) a small set of outlier KV pairs (≈0.3% of chunks) kept as static GPU cache, and (iii) the remaining value cache offloaded to CPU memory. During decoding, incoming query vectors are matched against landmarks to select top-k chunks (1.56% sparse budget), after which the method outputs generated text tokens via sparse attention over the reconstructed KV pairs.

## Method

SHADOWKV exploits the observation that pre-RoPE keys are exceptionally low-rank (6× compressible via SVD without accuracy loss) while values are not, enabling asymmetric storage: low-rank key projections stay on GPU and the value cache is offloaded to CPU. During pre-filling, SVD decomposes each layer's pre-RoPE key cache into rank-r factors; post-RoPE keys are segmented into chunks of 8 tokens whose means serve as compressed landmarks, and a small set of outlier chunks (detected via minimum intra-chunk cosine similarity) are retained as static GPU cache. During decoding, landmarks are multiplied with queries to score all chunks, the top-k chunks are selected, and the corresponding key cache is reconstructed on-the-fly from the low-rank factors while the value cache is fetched from CPU in parallel via CUDA multi-streams, hiding the reconstruction latency behind the PCIe transfer. A temporal-locality cache mechanism exploits the high hit rate between adjacent decoding steps to skip redundant reconstruction and fetching, reducing per-step computation and data movement by over 60%.

## Results

On RULER (128K context), SHADOWKV achieves 86.88% average on Llama-3-8B-1M, matching or exceeding full attention (86.68%) with only a 1.56% sparse KV budget, while Quest drops to 82.03% and InfiniGen to 70.13%. On LongBench, SHADOWKV scores 39.94% (Llama-3-8B-1M), 47.89% (GLM-4-9B-1M), and 48.13% (Llama-3.1-8B), consistently outperforming all baselines. In throughput experiments on A100, SHADOWKV supports up to 6× larger batch sizes (e.g., batch 48 vs. 8 for Llama-3-8B-1M at 60K) and achieves up to 3.04× higher tokens/s (245.90 vs. 80.78 for Llama-3.1-8B at 122K), even surpassing the infinite-batch-size upper bound (273.07 tokens/s) under the assumption of infinite GPU memory.

## Baselines & Comparisons

SHADOWKV consistently outperforms Quest (the strongest sparse-attention baseline) on both RULER and LongBench across all three main models: e.g., 86.88% vs. 82.03% on RULER and 39.94% vs. 36.65% on LongBench for Llama-3-8B-1M, with the gap widening on harder subtasks like multi-key retrieval (MK2: 98.96% vs. 77.08%). Against InfiniGen, which offloads the full KV cache to CPU, SHADOWKV gains 16.75 points on RULER (86.88% vs. 70.13%) for Llama-3-8B-1M, primarily because SHADOWKV only fetches the value cache from CPU while reconstructing keys on-GPU from low-rank projections. Loki, which uses PCA-based low-rank key selection, suffers catastrophic accuracy drops (9.33% on RULER for Llama-3-8B-1M) due to its data-independent projection. In the multi-turn NIAH setting, SnapKV degrades sharply from the second round because evicted tokens cannot be recovered, while SHADOWKV maintains accuracy by retaining the full low-rank key representation. In throughput, SHADOWKV at batch 48 (455.14 tokens/s) surpasses Quest(CPU) at 3×1M context (9.34 tokens/s) by ~5×, and even exceeds the infinite-batch full-attention upper bound (273.07 tokens/s) by 1.67×.

## Relation to Prior Work

SHADOWKV carves new ground at the intersection of low-rank approximation and dynamic sparse attention for KV cache management. Unlike prior low-rank methods (Palu, Loki) that decompose weight matrices or post-RoPE keys, it applies online SVD directly to pre-RoPE keys, which it shows are exceptionally low-rank (6× compressible). Unlike sparse attention methods (Quest, InfiniGen) that retain the full KV cache on GPU or fetch complete KV pairs from CPU, SHADOWKV stores only low-rank key projections on GPU and offloads values, reconstructing keys on-the-fly. The chunk-level landmark selection with outlier detection departs from Quest's page-based min-max approximation by exploiting spatial locality in post-RoPE keys, requiring only 1.56% sparse budget versus Quest's larger budgets.

## Why It Matters / Open Questions

SHADOWKV's 3.04× throughput gain and 6× batch size expansion on a single A100 make long-context LLM serving practically feasible on commodity hardware, and the result of surpassing infinite-batch-size performance under infinite GPU memory is a strong signal that the bottleneck is not raw memory but access patterns. The SHADOWKV+ extension for handling generated tokens and the demonstrated compatibility with MInference pre-filling suggest a path toward full-stack long-context inference optimization. Open questions include whether the pre-RoPE low-rank property holds universally across architectures (e.g., non-RoPE positional encodings), how the method scales to 70B+ models with more KV heads, and whether the 1.56% sparse budget remains sufficient for increasingly complex multi-turn or agentic workloads.
