## Problem

Federated telemetry systems protect against network eavesdroppers and server-side intrusions, but leave the local device state exposed to on-device intruders (e.g., a second user inspecting a shared public computer). This paper introduces local pan-privacy, requiring that the device's internal state remain private under repeated unannounced intrusions after each event, and shows that information-theoretic local pan-privacy is fundamentally incompatible with useful telemetry (incurring a √T error penalty), while computational local pan-privacy can be achieved at no additional cost using standard cryptographic primitives.

## Input / Output

Each of n devices receives a stream of T binary events (x_1, ..., x_T ∈ {0,1}) and maintains an on-device state of O(1) ciphertexts that is updated after each event. The device sends a single message of O(1) ciphertexts to the server at the end of the T-step horizon. The server produces a differentially private estimate of COUNTNONZERO (number of devices with ≥1 event), a histogram of per-device event counts bucketed at k, or the mean number of occurrences per device, with privacy-utility trade-offs within constant factors of standard local DP algorithms.

## Method

The core mechanism is to store all sensitive state in encrypted form on the device using a rerandomizable public-key encryption scheme: since the device lacks the private key, the on-device state is computationally indistinguishable from encryptions of 0 regardless of the actual event history. For COUNTNONZERO, the device initializes with Enc(0), replaces the state with a fresh rerandomized Enc(1) upon an event, and merely rerandomizes the current ciphertext otherwise; at the end, randomized response is applied to the encrypted bit without decryption. For histograms, k+1 encrypted counters are shifted on each event; for means, additively homomorphic encryption enables computing an encrypted sum of occurrences plus discrete Gaussian noise. In the two-server (PRIO-style) model, the state is secret-shared and each share is encrypted under a separate server's public key, with validity proofs generated at share-creation time and preserved under rerandomization. The paper further proves that public-key encryption is necessary: any accurate locally pan-private COUNTNONZERO algorithm implies the existence of a rerandomizable public-key encryption scheme.

## Results

The paper establishes that information-theoretic local pan-privacy for COUNTNONZERO forces an additive error of Ω(√(nT)), a √T degradation over the O(√n) error achievable by standard local DP without the pan-privacy constraint (Theorem 9). In contrast, their computational local pan-privacy algorithm using rerandomizable public-key encryption achieves the same O(√(n(1 + e^{ε₀}/(1+e^{ε₀})²))) error in the local DP model and O(√(log(1/δ))/ε) in the aggregator DP model as standard randomized response (Theorem 10), meaning the pan-privacy guarantee comes at zero additional utility cost. The on-device state is O(1) ciphertexts, and the device sends a single O(1)-ciphertext message.

## Baselines & Comparisons

The paper's main comparison is between three regimes for the COUNTNONZERO task. Standard local DP (without pan-privacy) achieves additive error O(√n) via randomized response on a single-bit state. Information-theoretic local pan-privacy is strictly worse, incurring Ω(√(nT)) error even when each device has at most one event occurrence — a √T gap that grows with the stream length. The proposed computational local pan-privacy algorithm (using rerandomizable PKE) matches the standard local DP baseline exactly in both the local and aggregator DP models, achieving the same O(√n) and O(√(log(1/δ))/ε) error bounds while additionally guaranteeing that the on-device state is computationally indistinguishable across any pair of input streams. The paper further shows that public-key encryption is necessary: any accurate (error < n/4) computationally 0-locally pan-private algorithm for COUNTNONZERO implies the existence of a rerandomizable public-key encryption scheme (Theorem 6.1).

## Relation to Prior Work

This paper extends pan-privacy (Dwork et al., 2010), which protected against server-side intrusions, to the local device setting, introducing 'local pan-privacy' as a new threat model where an adversary can inspect the device's internal state after each update. It builds on the PRIO two-server secure aggregation architecture (Corrigan-Gibbs and Boneh, 2017) for the multi-server setting and draws conceptual parallels to history independence, oblivious RAM, and forward secrecy. The technical core combines standard local DP mechanisms (randomized response, Laplace noise) with rerandomizable public-key encryption to maintain encrypted on-device state that is computationally indistinguishable across input streams.

## Why It Matters / Open Questions

The paper establishes a clean separation: information-theoretic local pan-privacy is fundamentally incompatible with useful telemetry (requiring Ω(√T) error overhead), while computational local pan-privacy is achievable at zero utility cost using rerandomizable encryption. The necessity result showing that public-key encryption is required for any accurate locally pan-private algorithm provides a tight characterization of the cryptographic assumptions needed. Open questions include whether the √T lower bound strengthens to Ω(T) for general streams, extending to richer telemetry tasks, and designing non-interactive zero-knowledge proofs compatible with local pan-privacy for the two-server model with server collusion.
