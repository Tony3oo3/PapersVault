## Problem

Prior test-generation research targets existing code, not open issues whose fix does not yet exist. This paper tackles the underexplored problem of generating fail-to-pass tests from an issue description and the pre-fix codebase alone, supporting both human TDD workflows and automated validation of SWE agents that produce code patches.
![Teaser figure](../imgs/ICML20250030/cropped_page2_idx0.webp)

## Input / Output

The input is a natural-language issue description (which may embed code snippets or stack traces) paired with a full snapshot of a Python repository at its pre-fix commit; the new/fixed code is explicitly unavailable to the generator. The output is a git-diff test patch containing one or more test functions that must fail on the old code and pass on the golden new code, structured to integrate with the repository's existing test framework and insertion points. Otter generates complete test functions rather than diffs, and the final patch is produced by applying the generated function to the codebase and running git diff.

## Method

Otter is a three-stage LLM pipeline: (1) a Localizer uses two LLM calls each to identify relevant test files and focal functions, with rule-based validation that drops or edit-distance-replaces hallucinated file names; (2) a Self-Reflective Action Planner proposes a sequence of read/write/modify actions, validates them against the codebase, then iteratively reflects on the plan (up to 5 rounds) with a satisfaction/unsatisfaction/unsure self-assessment before committing; (3) a Test Generator executes the plan using framework-aware prompts (separate for new vs. modified tests) and a Flake8-based import-fixing step that resolves missing or hallucinated imports against the actual codebase. Otter++ extends this to an ensemble of five heterogeneous prompts that vary which localizer outputs are included, then selects the best candidate by executing all five on the old code and preferring assertion failures over other failure types. The entire system costs under $0.10 per instance with GPT-4o and requires no training or fine-tuning.

## Results

On TDD-Bench-Verified (449 instances), GPT-4o-based Otter generates fail-to-pass tests for 31.4% of instances (tddScore 29.4, coverage 70.6%), while the Otter++ ensemble (5 heterogeneous prompts) reaches 37.0% fail-to-pass (tddScore 32.4, coverage 71.5%). The zero-shot baseline achieves only 18.7% fail-to-pass with GPT-4o. On the SWT-bench Lite dataset (276 instances), Otter and Otter++ produce 70 (25.4%) and 80 (29.0%) fail-to-pass tests respectively, substantially outperforming the prior best (SWE-Agent+ at 19.2%). The total cost is under $0.10 per issue with GPT-4o even for the Otter++ ensemble.

## Baselines & Comparisons

Otter and Otter++ outperform all four compared systems on the SWT-bench Lite dataset (276 instances). Against Mündler et al.'s SWE-Agent+ (19.2% fail-to-pass), Otter achieves 25.4% and Otter++ reaches 29.0%, a 6.2–9.8 percentage point improvement. Against LIBRO (Kang et al., 15.2%), Otter's gain is even larger at 10.2–13.8 points. SWE-Agent (Yang et al., 16.7%) and AutoCodeRover/CodeR (Chen et al., 9.1%) are further behind, with Otter++ exceeding them by 12.3 and 19.9 points respectively. Additionally, when used to filter SWE agent patches on SWE-bench Verified, Otter++ tests boost precision to 65–92% at 30–41% recall, compared to Mündler et al.'s 47.8% precision at only 20% recall.

## Relation to Prior Work

This paper extends the nascent line of work on generating tests from issue descriptions (Libro on Defects4J, SWE-Agent+ on Python) by introducing a self-reflective action planner that decides which code to read and which tests to write, combined with rule-based validation and repair (Flake8 linting, import resolution, hallucination replacement). It departs from prior SWE agents that generate tests as a byproduct of patch generation by treating test generation as a standalone, first-class task with its own evaluation harness. The TDD-Bench-Verified benchmark builds directly on SWE-bench Verified but applies stricter filters (requiring golden tests to actually fail-to-pass and cover the code patch), and introduces the tddScore metric that jointly measures correctness and coverage adequacy—neither of which existed in prior test-generation benchmarks.

## Why It Matters / Open Questions

The demonstrated ability to boost SWE agent precision from ~61% to ~92% (at the cost of recall) using generated tests as a filter is practically significant for anyone deploying automated issue-resolution systems, and the sub-$0.10 cost per issue makes this approach economically viable at scale. Key limitations include Python-only scope, single-test-file generation, and reliance on a specific LLM (GPT-4o) for best results. Open questions include whether the self-reflective planner generalizes to multi-file test suites, other languages, or non-Python testing frameworks, and whether better rankers can close the gap between Otter++'s Top-1 (37%) and Oracle (44%) performance.
