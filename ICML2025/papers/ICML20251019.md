## Problem

Existing methods for constructing graph representations of crystalline materials are hand-designed to satisfy specific symmetry constraints (e.g., rotation invariance, periodicity equivariance), making them ineffective when new constraints must be met. Designing representations that satisfy additional constraints like Lipschitz continuity or reflection equivariance requires deep expertise in both materials science and computer science, and no prior framework could automatically generate such representations. This paper asks whether multi-agent LLM systems can autonomously evolve code that produces graph representations satisfying an arbitrary set of physical constraints.

## Input / Output

The framework takes crystal structure data (atomic coordinates, element types, and a 3×3 lattice matrix) from the Materials Project or JARVIS-DFT datasets and produces executable Python code that constructs a graph representation of the form [u, v, attr], where u and v are atomic numbers of an atom and its neighbor, and attr encodes interatomic distance and a dihedral angle computed via lattice-direction extensions. The generated code is interpretable and human-readable, distinguishing it from black-box LLM outputs. The representation code is then fed into a standard GNN (same architecture as PerCNet) for supervised property prediction, with the LLM agents themselves operating on code text and constraint-satisfaction feedback rather than on raw crystal data.

## Method

Rep-CodeGen simulates an evolutionary algorithm with three iterative stages using three QWen LLM agents. In Crossover Generation, Agent_A reads parent code plus constraint-satisfaction diagnostics and proposes a modification plan, while Agent_B writes the new representation code from that plan. In Evaluation Summary, the generated code is executed against dedicated test sets for each of six physical constraints (permutation invariance, rotation invariance, translation invariance, reflection equivariance, periodicity equivariance, Lipschitz continuity), and Agent_C produces a natural-language diagnosis of why each constraint is or is not satisfied. In Parent Selection, codes are clustered by their binary constraint-satisfaction signature, and parent pairs are sampled via a Boltzmann distribution over the joint satisfaction rate, with a secondary length-based softmax favoring shorter codes to respect token limits. Starting from codes satisfying three constraints, the framework iterates until a code satisfying all six is found (at iteration 14,076 out of 56,304 total generations). The resulting representation's key structural choices—lattice-based 3×3×3 periodic neighbor selection instead of cutoff distance, and dihedral angles computed from lattice-direction extensions rather than nearest-neighbor atoms—are what confer Lipschitz continuity and reflection equivariance, properties absent from all prior graph-based methods.

## Results

On the JARVIS dataset, the proposed representation (satisfying 6 constraints) achieves the best MAE across all four tasks: 43.3 meV (Energy Hull), 28.3 meV/atom (Total Energy), 253 meV (BandGap), and 27.2 meV/atom (Formation Energy). On the Materials Project dataset, it achieves 18.0 meV/atom (Formation Energy) and 191 meV (BandGap), both state-of-the-art. The most significant improvement is on Energy Hull prediction, where the method reduces MAE by 13.9% compared to the closest baseline PerCNet (50.3 → 43.3 meV), while using the same network architecture.

## Baselines & Comparisons

The proposed method outperforms all six graph-based baselines (CGCNN, ALiGNN, MatFormer, PotNet, PerCNet, ComFormer) on every task across both JARVIS and Materials Project datasets. The closest competitor is ComFormer (5 constraints), which the method beats by 3.7 meV on JARVIS Energy Hull (43.3 vs. 47) and 2 meV on MP BandGap (191 vs. 193). PerCNet (5 constraints), which shares the same network architecture, is outperformed by 7.0 meV on JARVIS Energy Hull (43.3 vs. 50.3, a 13.9% reduction) and 0.1 meV/atom on MP Formation Energy (18.0 vs. 18.1), confirming that gains stem from the representation rather than the model. Against the four-constraint methods (CGCNN, ALiGNN, MatFormer, PotNet), the improvements are substantially larger, e.g., 126.7 meV on JARVIS Energy Hull vs. CGCNN. In the point-cloud comparison (Appendix Table 5), the method achieves 0.027 eV/atom MAE on JARVIS Formation Energy, outperforming PDD (0.047) and AMD (0.78) with the same training set size as AMD.

## Relation to Prior Work

This paper extends the 'evolution through large models' paradigm introduced by Haluptzok et al. (2022), which used LLMs as mutation operators in genetic programming, by applying it to the domain-specific task of generating material graph representation code. It departs from the established lineage of crystal graph representations (CGCNN → ALIGNN → MatFormer → PotNet → PerCNet → ComFormer), where each method manually incorporates additional physical attributes to satisfy more symmetry constraints, by instead using a three-stage evolutionary multi-agent LLM framework (crossover generation, evaluation summary, parent selection) to automatically discover code. The key conceptual departure from prior representation methods is the use of lattice-based neighbor selection (a 3×3×3 periodic region) rather than the standard cutoff-distance approach, which is what enables Lipschitz continuity alongside the other five constraints.

## Why It Matters / Open Questions

The framework reduces the dual-expertise barrier (materials science + computer science) that has historically limited who can design new crystal graph representations, and the resulting representation is the first to simultaneously satisfy all six physical symmetry constraints. However, the practical impact is tempered by the computational cost (14,076 iterations, 56,304 generated codes) and the modest but consistent performance gains over strong baselines like PerCNet and ComFormer. Open questions include whether the framework scales to additional or more complex constraints, whether the discovered lattice-based neighbor selection generalizes to non-crystalline or amorphous materials, and whether the evolutionary process can be accelerated with better fitness landscapes or more targeted prompts.
