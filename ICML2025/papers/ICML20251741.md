## Problem

Existing inference-time strategies for code repair—best-of-N sampling and self-repair with verbal feedback—suffer from diminishing returns as compute budget grows, because they repeatedly apply the same repair prompt or rely on the model's own (often limited) ability to identify its mistakes. This paper asks whether providing diverse, complementary in-context examples of successful repairs can generate a wider set of fixed solutions and scale more effectively with inference-time compute.
![Teaser figure](../imgs/ICML20251741/cropped_page1_idx0.webp)

## Input / Output

At inference time, the method takes a coding problem description, an initial buggy guess (LLM-generated code with a unit-test score), and one AuPair—a golden example consisting of a different problem's guess, its fix, and both scores—concatenated as a 1-shot in-context prompt. No execution traces or verbose feedback are provided; only scalar unit-test scores accompany the guess and fix. The output is a single repaired code solution: the highest-scoring fix among N generated candidates, where N equals the inference compute budget and the first N AuPairs from the ordered set are used sequentially.

## Method

The approach has two phases. Phase 1 (Pair Generation) iteratively samples problems with initial guesses, generates fixes via k-shot prompting (k=32 random candidate pairs), and collects candidate pairs where the fix outperforms the guess; imperfect fixes are recycled as new guesses to deepen the search. Phase 2 (AuPair Extraction) builds a fix-quality matrix by evaluating every candidate pair as a 1-shot in-context example on a held-out validation set, then applies greedy submodular selection: at each step, the pair with the highest mean score is added to the AuPair list, its row is subtracted from the matrix (clipped to [0,1]), and the process repeats until marginal improvement falls below a tolerance ε. This guarantees each successive AuPair solves a complementary set of problems. At inference, each of the N AuPairs is used as a distinct 1-shot example in a separate LLM call, producing N diverse fixes from which the best-scoring one is selected—yielding steeper scaling with compute than best-of-N or self-repair.

## Results

On CodeForces with Gemini-1.5-Pro at N=32 LLM calls, AuPair significantly outperforms both Best-of-N and Self-repair baselines across all 5 models and 7 datasets. At a larger budget of 144 LLM calls, AuPair achieves 51.32% test pass rate and 39.73% strict accuracy, compared to 16.05%/12.04% for Best-of-N and 15.79%/12.23% for Self-repair. AuPair is 2.5–3× more compute-efficient than randomly selected pairs, reaching the same performance with only 12 AuPairs as 32 random pairs. Out-of-distribution AuPairs extracted on CodeForces generalize strongly to 6 other datasets (AtCoder, HackerEarth, CodeChef, LiveCodeBench, CodeJam, Aizu), maintaining large margins over baselines.

## Baselines & Comparisons

AuPair consistently outperforms Best-of-N (Stiennon et al., 2020) across all 5 models and all 7 datasets, with the gap widening as the compute budget N increases; at N=144 on CodeForces with Gemini-1.5-Pro, AuPair reaches 51.32% test pass rate versus 16.05% for Best-of-N. Against Self-repair (Olausson et al., 2024), AuPair also wins on nearly all model–dataset combinations, matching in only a few cases; at N=144 the gap is 51.32% vs. 15.79% test pass rate. In the RAG comparison (Table 6), AuPair beats BERT-embedding retrieval by 4–8 percentage points across all 5 models on CodeForces, confirming that submodular selection of complementary pairs is more effective than similarity-based retrieval. The paper also shows that AuPair's advantage over Best-of-N and Self-repair is not merely due to in-context learning in general: a random-pair baseline (which also uses in-context examples) is 2.5–3× less compute-efficient, demonstrating that the submodular selection of complementary AuPairs is the critical factor.

## Relation to Prior Work

This paper sits at the intersection of in-context learning for LLMs and automatic program repair, departing from the dominant SFT-based APR paradigm by operating entirely at inference time. It builds on the inference-time compute scaling literature (best-of-N, self-consistency) and the self-repair line of work (Olausson et al., 2024), but introduces a key conceptual shift: rather than resampling or generating verbal feedback, it curates an ordered set of complementary guess-fix example pairs via submodular selection over a fix-quality matrix. The submodular selection mechanism draws from combinatorial optimization for diversity maximization, applied here to the novel problem of choosing which in-context repair examples to present at each inference call.

## Why It Matters / Open Questions

The strong out-of-distribution generalization (AuPairs from CodeForces transfer to 6 other datasets) suggests that a one-time curation effort can yield reusable repair examples across a wide problem space, reducing the cost of deploying code repair in new settings. The steeper scaling curve without plateau at 144 LLM calls hints that inference-time compute for repair is far from saturated, opening a practical path to improving code quality without fine-tuning. Key limitations include the requirement for executable unit tests as grounded feedback, restriction to the coding domain, and the need for a validation set to extract AuPairs. Open questions include whether ungrounded reward-model feedback could substitute for unit tests, and whether the submodular selection principle generalizes to other repair or refinement tasks beyond code.
