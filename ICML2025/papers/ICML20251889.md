## Problem

Users of open-weights LLM inference providers cannot verify that the provider is serving the claimed model, prompt, and numerical precision without undisclosed modifications. Existing verification methods are either computationally prohibitive (zkLLM requires ~23 days to generate a proof for 2000 tokens) or require trusted third-party retraining (SVIP), while direct storage of intermediate activations as proofs is infeasible at scale (6.7 TB for 100K queries on Llama 3.1-70B).

## Input / Output

For proof generation, TOPLOC takes the last hidden state tensor (e.g., 4096-dim in bf16 for Llama-3.1-8B) and a top-k parameter (k=128 in experiments), producing a compact polynomial congruence proof of 258 bytes per 32-token interval. For validation, it takes the recomputed hidden state tensor and the encoded proof, outputting a boolean validity flag determined by comparing exponent mismatches, mean mantissa differences, and median mantissa differences against fixed thresholds (T_exp=38, T_mean=10, T_median=8 for bf16). The proof is sampled every N=32 tokens during autoregressive decoding, amortizing to 8 bytes per token versus 8192 bytes for direct activation storage.

## Method

TOPLOC exploits the observation that high-magnitude activations in transformer hidden states are far less susceptible to floating-point rounding errors than small values (which suffer catastrophic cancellations), making top-k magnitude elements a stable fingerprint of the computation. Rather than storing raw (index, value) pairs at 6 bytes each, it interpolates a unique (k-1)-degree polynomial congruence in an integer field through the k top-k points, reducing storage to k coefficients of 2 bytes each. An injective modulus m is found via brute-force search so that the index mapping x mod m is collision-free, enabling exact polynomial evaluation at validation time. Validation recomputes top-k values from the recomputed activations, evaluates the polynomial at the mapped indices, and checks whether exponent mismatches and mantissa deviations stay below calibrated thresholds. This design is robust to GPU nondeterminism, algebraic reorderings, tensor parallelism changes, and different attention kernel implementations, and validation runs significantly faster than generation because it performs a single batched prefill rather than sequential memory-bound decodes.

## Results

TOPLOC achieves 100% detection accuracy (0% false positives, 0% false negatives) for identifying unauthorized model, prompt, or precision changes across all tested configurations. The proof size is 258 bytes per 32 tokens (8 bytes/token), a 1024× reduction over storing raw hidden activations (8192 bytes/token for Llama-3.1-8B). Validation takes 81 ms (a single prefill pass), while committing overhead is only 0.26 ms per token. The method is robust across GPU types (A100, 4090), tensor parallelism (1×, 2×), and attention kernels (Flash, SDPA, Flex), with worst-case exponent mismatches of 28 (well below the threshold of 38).

## Baselines & Comparisons

Against zkLLM (Sun et al., 2024a), TOPLOC is orders of magnitude more practical: commitment size drops from 11 MB to 8 B per token (≈1.4 million× smaller), committing overhead from 986 s to 0.26 ms, and validation from 803 s to 81 ms. Critically, zkLLM has a 100% false-negative rate under non-deterministic GPU execution (because arithmetic-circuit proofs are exact), whereas TOPLOC maintains 0% false negatives by design. Against SVIP (Sun et al., 2024b), TOPLOC reduces commitment size from 20 KB to 8 B per token and eliminates SVIP's 3% false-positive and 4.41% false-negative rates, while also removing the need to train a per-model detection proxy. SVIP is faster at validation (5.6 ms vs 81 ms) because it only checks a single fingerprint vector, but TOPLOC's 81 ms validation still runs in a single prefill pass and is far cheaper than the original autoregressive generation. Compared to the raw-activations baseline, TOPLOC achieves a 1024× storage reduction (8 B vs 10 KB per token) at the same 81 ms validation cost and identical 0% error rates, making it the only method that is simultaneously compact, fast, and robust to GPU non-determinism.

## Relation to Prior Work

TOPLOC positions itself against two existing lines of verifiable inference work: cryptographic verifiable computing (zkLLM, zkDL, SafeTNet), which requires translating models into arithmetic circuits and incurs prohibitive proof-generation times, and activation-based validation (SVIP, Verisplit), which records intermediate tensors but suffers from storage costs or incompatibility with GPU non-determinism. Rather than building directly on either, TOPLOC repurposes the idea of hashing intermediate activations through a novel combination of top-k magnitude selection and modular polynomial congruence encoding, specifically designed to tolerate the floating-point non-determinism inherent in GPU inference. The polynomial encoding draws on classical interpolation theory but applies it in a finite integer field to avoid floating-point issues, a departure from both the cryptographic hash approach of Verisplit and the learned fingerprint approach of SVIP.

## Why It Matters / Open Questions

TOPLOC's 1000× proof-size reduction and demonstrated robustness across GPU types, tensor parallelism configurations, and attention kernel implementations make verifiable inference practically deployable for the first time at scale, opening a path toward decentralized, trustless LLM serving. However, significant open questions remain: the method cannot detect speculative decoding, fp8-vs-bf16 detection has a narrow margin, KV-cache compression is untested, and subtle modifications (minor prompt tweaks, small fine-tuning updates) are acknowledged as harder to catch. The reliance on checking only the last hidden layer activations, rather than intermediate layers, also leaves a potential attack surface that the authors flag for future work.
