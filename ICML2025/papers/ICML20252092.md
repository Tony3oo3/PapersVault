## Problem

Inference-time techniques such as repeated sampling, generation ensembling, fusion, ranking, critique, and verification are individually powerful, but no systematic understanding exists of which techniques are most effective for which task categories, how they interact when combined, or how to efficiently search the vast design space of possible multi-model, multi-technique architectures. Existing inference-time systems (MoA, ADAS, AFlow) use fixed or manually selected configurations that underutilize compute budgets and generalize poorly across diverse task types.

## Input / Output

The architecture search takes four inputs: target benchmark(s), an inference call budget (with optional input/output token constraints), a pool of available LLMs (open-source, closed-source, or mixed), and the set of inference-time techniques to compose. It outputs a single optimized ARCHON architecture—a layered DAG of LLM components—which, at inference time, takes an instruction prompt and sequentially transforms a list of candidate strings through generator, critic, ranker, verifier, unit-test, and fuser layers, returning the first string from the final layer as the response. The search uses 20% of each target dataset as a development set and evaluates on the held-out 80%.

## Method

ARCHON structures inference-time architectures as layered compositions of LLM components (Generator, Fuser, Ranker, Critic, Verifier, Unit Test Generator/Evaluator), analogous to neural network layers, where each layer performs a text-to-text transformation or filtering operation on a list of candidate strings. The search space is defined by six hyperparameter axes (top-K generators, samples per generator, number of fusion layers, fusers per layer, critic/ranker placement, and evaluation layer type), yielding 9,576 valid configurations after applying placement constraints (e.g., Generators restricted to the first layer, Critic must precede Ranker/Fuser, Unit Test Gen/Eval in consecutive layers). Bayesian optimization with a Gaussian process surrogate navigates this space, requiring 88.5% fewer architecture evaluations than greedy search and finding the best configuration in 96% of searches. A key empirical finding is that no single technique dominates across all tasks: instruction-following benefits most from multi-layer critique and fusion, reasoning from verification and unit testing, and coding from high-sample generation with unit-test evaluation, motivating task-specific architecture search.

## Results

ARCHON's best all-source task-specific architecture achieves 79.5% win rate on MT-Bench, 69.0% on AlpacaEval 2.0, 92.5% on Arena-Hard-Auto, 72.7% on MixEval-Hard, 89.7% on MixEval, 93.5% on MATH, and 41.4% Pass@1 on CodeContests, surpassing frontier models (o1, GPT-4o, Claude 3.5 Sonnet) by an average of 15.1%. Even with open-source models only, ARCHON outperforms SOTA LLMs by 11.2% on average. The generalized all-source architecture achieves 91–95% of task-specific performance on out-of-domain tasks (GPQA, MMLU, MMLU Pro), while using 20.0% fewer inference calls, 15.1% fewer input tokens, and 13.5% fewer output tokens than competing inference-time frameworks.

## Baselines & Comparisons

ARCHON's all-source task-specific architecture outperforms all seven baselines across nearly every benchmark. Against single-call LLMs, ARCHON beats GPT-4o by 35.3 points on MT-Bench (79.5% vs. 44.2%), Claude 3.5 Sonnet by 16.3 points on Arena-Hard-Auto (92.5% vs. 81.4%), and Llama 3.1 405B by 35.4 points on MT-Bench. Against the frontier reasoning model o1, ARCHON leads on MT-Bench (79.5% vs. 56.3%), AlpacaEval (69.0% vs. 59.3%), Arena-Hard-Auto (92.5% vs. 81.7%), and CodeContests (41.4% vs. 31.5%), while MATH is nearly tied (93.5% vs. 92.7%). Against inference-time frameworks, ARCHON surpasses MoA by 27.9 points on MT-Bench while using 47% fewer inference calls (39 vs. 19), beats ADAS by 13.2 points on MT-Bench with 25% fewer calls (39 vs. 52), and outperforms AFlow by 17.1 points on MT-Bench with 19% fewer calls (39 vs. 48). The generalized ARCHON architecture retains 91–95% of task-specific performance on unseen benchmarks (GPQA, MMLU, MMLU Pro), whereas ADAS and AFlow retain only 66–74%.

## Relation to Prior Work

ARCHON extends the line of inference-time LLM architectures (MoA, LLM-Blender, ADAS, AFlow) by reframing their manual design process as an automated search problem. It draws on Bayesian optimization (Snoek et al., 2012) and NAS-inspired search strategies to traverse a 9,576-configuration design space over multi-model ensembles and layered inference-time techniques (generation, fusion, ranking, critique, verification, unit testing). Unlike prior automated LLM system designers (ADAS, AFlow) that optimize single-model workflows or prompt sequences, ARCHON explicitly searches over the combinatorial space of which LLMs to use, how many to sample, and which multi-technique layer stack to deploy, treating the architecture as a layered pipeline analogous to a neural network.

## Why It Matters / Open Questions

ARCHON provides the first systematic, open-source framework for practitioners to automatically discover optimal inference-time architectures given a compute budget and model pool, reducing the trial-and-error that currently dominates system design. The finding that no single inference-time technique dominates across task categories—and that the optimal combination varies substantially (e.g., fusion-heavy for instruction-following, unit-test-heavy for coding)—gives practitioners concrete guidance for budget allocation. Key limitations include 5× latency/cost over single LLM calls, reduced effectiveness with sub-70B models, and the need for 20% of target data as a development set for search. Open questions include whether distillation can compress ARCHON's multi-model knowledge into a single smaller model, and how the framework generalizes to latency-constrained or streaming settings.
