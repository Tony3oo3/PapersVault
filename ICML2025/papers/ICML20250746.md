## Problem

Autoregressive LLMs require KV caches that grow linearly with sequence length, making long-response generation (e.g., code synthesis, essay writing) infeasible on available GPU memory. Existing compression methods either sacrifice accuracy by discarding context (Scissorhands, StreamingLLM) or fail to maintain constant cache size during decoding (SnapKV retains all generated tokens), leaving no solution that simultaneously preserves accuracy and bounds memory for extended response tasks.

## Input / Output

At each decode step, MorphKV consumes the existing KV cache of all prior tokens and the per-head attention weights of the R most recent window tokens, extracted via partial attention computation within FlashAttention-2. It outputs a pruned KV cache of fixed size C+R tokens, where C distant tokens are selected by fused attention scores and R recent tokens are always retained. The method is natively compatible with Grouped-Query Attention, aggregating attention across M/M' grouped query heads before scoring, which reduces the effective cache footprint by a factor of M/M' compared to MHA-based baselines.

## Method

MorphKV's key insight is that recent tokens have already attended to distant tokens during their own generation, so their attention profiles reveal which older tokens remain contextually relevant. At each timestep, it computes a fused score for every older token by aggregating (via sum or max) the attention weights that the R most recent tokens assigned to it, then retains only the top-C older tokens by this score alongside the R most recent tokens, yielding a constant C+R cache. This iterative, correlation-aware selection eliminates the early-token bias inherent in methods like H2O and Keyformer, because relevance is re-evaluated at every step based on current attention patterns rather than historical accumulation. The approach is architecture-agnostic, supporting both Multi-Head Attention (independent per-head pruning) and Grouped-Query Attention (aggregated scoring across grouped heads), and integrates with FlashAttention-2 for hardware-efficient inference with dedicated CUDA streams to prefetch attention profiles.

## Results

On the LongWriter benchmark (LLM Judge Score), MorphKV achieves 69.5 on Llama-3.1-8B, 81.1 on Mistral-7B, 64.7 on Phi-4, and 64.9 on Qwen2.5, outperforming H2O and SnapKV on three of four models while matching SnapKV on Mistral. MorphKV reduces KV cache memory to 0.25× Full-Attention on average, compared to 1× for H2O and up to 4× for SnapKV. Across long-response tasks, MorphKV delivers 52.9% memory savings and 18.2% higher accuracy on average over state-of-the-art prior works, with only 10% performance degradation as response length increases 4× (vs. 15–18% for baselines).

## Baselines & Comparisons

Against SnapKV (the current SOTA for KV cache compression), MorphKV wins on Llama (69.5 vs. 67.7), ties on Mistral (81.1 vs. 81.1), wins on Phi-4 (64.7 vs. 63.8), but loses on Qwen2.5 (64.9 vs. 68.4), yielding a 9.4% average accuracy improvement across long-response tasks while using 88.1% less KV cache memory. Against H2O, MorphKV wins on all four models (69.5 vs. 68.5, 81.1 vs. 80.0, 64.7 vs. 61.5, 64.9 vs. 63.8), achieving 18.2% higher average accuracy with 52.9% less memory. The Qwen2.5 loss is attributed to its aggressive GQA configuration (7× fewer heads), which limits the attention signal available for MorphKV's correlation-aware selection. On LongGenBench, MorphKV further outperforms both baselines on average accuracy (e.g., 52% vs. 49% for SnapKV and 50% for H2O on Mistral), and on LongBench it matches or exceeds SnapKV while using roughly 50% lower KV cache budget.

## Relation to Prior Work

MorphKV sits at the intersection of several KV cache compression lineages: the sliding-window approaches (Scissorhands, StreamingLLM), the importance-based eviction methods (H2O, Keyformer), and the prompt-selection strategy of SnapKV. Its key conceptual departure is the correlation-aware selection criterion: rather than independently scoring old tokens by their own historical attention (as H2O and Keyformer do) or retaining all decode-phase tokens (as SnapKV does), MorphKV asks which old tokens the *recent* window tokens currently attend to, using fused attention profiles as a proxy for ongoing relevance. This reframes the eviction problem from 'which tokens were important?' to 'which tokens does the model still need right now?', yielding a truly constant cache size during generation that prior methods do not achieve.

## Why It Matters / Open Questions

The practical significance is substantial: a constant-size KV cache that simultaneously improves accuracy over SOTA (18.2% over H2O) and cuts memory by 52.9% removes the primary bottleneck for deploying LLMs on long-response workloads (code generation, essay writing, structured content) where SnapKV's growing cache becomes infeasible. The GQA compatibility and 4.68× throughput gain make this immediately deployable on current hardware. Open questions include whether the runtime overhead (1.5×) can be eliminated via FlashAttention kernel integration, how MorphKV interacts with orthogonal compression axes (layer-level, head-level), and whether the window-size sensitivity observed on LongGenBench (32 vs. 200 tokens) generalizes to other task families.
