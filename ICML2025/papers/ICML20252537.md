## Problem

Current LM-based web agents solve each task in isolation, failing to extract and reuse common routines across similar tasks, which limits their performance on long-horizon tasks and makes them brittle to changes in task context or environment. Unlike humans who abstract reusable workflows from past experiences to guide future actions, existing agents neither learn from prior successes nor adapt their behavior over time.

## Input / Output

The agent receives a natural language task instruction and a webpage accessibility tree (not full HTML) at each step, along with an augmented memory containing built-in action documentation and induced workflows. Each workflow is a structured pair of a high-level NL description and a trajectory of steps, where each step comprises a NL state description, the agent's reasoning, and an executable action (e.g., CLICK, TYPE) with variable placeholders (e.g., {product-name}) replacing example-specific values. The agent outputs a sequence of web navigation actions, and the induction module outputs abstract, sub-routine-level workflows that are stored in memory for future use.

## Method

AWM introduces an induction module that extracts reusable sub-routines (workflows) from agent experiences by prompting an LM to identify common action patterns across multiple trajectories and abstract away example-specific contexts into variable placeholders. These workflows are integrated into the agent's memory, so that subsequent action generation conditions on both the original memory and the induced workflows: L(q, M+W, o) → a. The method operates in two modes: offline, where workflows are pre-induced from annotated training examples, and online, where the agent streams test queries, uses an LM-based evaluator to judge trajectory success, and iteratively induces and accumulates workflows from successful self-generated trajectories without any supervision. A key design choice is inducing workflows at a finer sub-routine granularity (e.g., 'search for a product') rather than full task level, enabling compositional reuse where simpler workflows serve as subgoals for building more complex ones (e.g., 'find a place by name' becomes a component of 'get the zip code of a place'), creating a snowball effect that progressively expands the agent's capability.

## Results

On WebArena, AWM achieves 35.5% overall task success rate, surpassing the BrowserGym baseline (23.5%) by 12.0 absolute points (51.1% relative) and the human-engineered SteP method (33.0%) by 7.6% relative, while also using ~2 fewer steps per task. On Mind2Web cross-task, AWM with GPT-4 reaches 50.6 element accuracy and 45.1 step success rate, outperforming MindAct (41.6 EA, 36.2 Step SR) and Synapse (34.0 EA, 30.6 Step SR). In cross-domain generalization, AWM online scores 14.0–16.9 absolute points higher in step success rate over the MindAct baseline, with margins widening as the train-test distribution gap increases.

## Baselines & Comparisons

AWM outperforms all six baselines across both benchmarks. On WebArena, AWM (35.5%) beats BrowserGym (23.5%) by 12.0 absolute points, the original WebArena agent (14.9%) by 20.6 points, AutoEval (20.2%) by 15.3 points, and even the human-engineered SteP method (33.0%) by 2.5 absolute points (7.6% relative), all without any human-written workflows. On Mind2Web cross-task, AWM with GPT-4 (50.6 EA, 45.1 Step SR, 4.8 task SR) surpasses MindAct (41.6 EA, 36.2 Step SR, 2.0 SR) by 9.0 element accuracy and 8.9 step SR points, and Synapse (34.0 EA, 30.6 Step SR, 2.4 SR) by 16.6 EA and 14.5 Step SR points. The gains are driven primarily by more accurate element selection rather than action F1, where AWM is slightly below MindAct. In cross-domain settings, AWM online (35.5 Step SR) leads MindAct (26.4 Step SR) by 9.1 points, and the advantage over AWM offline widens from 0.2 (cross-task) to 2.9 (cross-domain) points, confirming superior generalization when no training data from the target domain is available.

## Relation to Prior Work

AWM sits at the intersection of memory-augmented agent prompting (Synapse, MindAct, AutoGuide) and reusable skill/sub-routine learning (Voyager, TroVE, DreamCoder), but departs from both in key ways. Unlike Synapse, which retrieves full concrete training examples as context, AWM induces abstract, sub-routine-level workflows with example-specific values replaced by variables, reducing element-selection bias. Unlike SteP, which relies on 14 human-written workflows tailored to WebArena, AWM induces workflows automatically via LM prompting and operates in both offline (from annotated data) and online (streaming, supervision-free) settings, with a 'snowball' mechanism where newly induced workflows serve as building blocks for more complex ones. The cognitive-science motivation (Chi et al.) of abstracting common routines from experience provides the conceptual framing that distinguishes AWM from generic in-context learning or retrieval-based approaches.

## Why It Matters / Open Questions

The practical significance lies in the online, supervision-free setting: agents can improve purely from test-time experience without any annotated training data, which is critical for real-world deployment where high-quality examples are scarce or nonexistent. The finding that automatically induced workflows outperform human-engineered ones (SteP) by 7.9% on WebArena suggests that the bottleneck in agent performance may be less about workflow quality and more about the induction and retrieval mechanism. Open questions include how to handle dynamic environment changes that break pre-determined workflow sequences (e.g., pop-up selections), how to help agents know when to diverge from workflow guidelines, and whether the offline+online combination can be made additive rather than interfering. The modest absolute success rates (~35% on WebArena) also indicate substantial room for improvement.
