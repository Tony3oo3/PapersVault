## Problem

Existing context caching systems for LLM serving require exact prefix matches across requests, making them ineffective in RAG and few-shot settings where immutable documents are preceded by varying prefixes. The first position-independent caching (PIC) solution, CacheBlend, suffers from O(N²) recomputation complexity and heavy dynamic-sparsity runtime overhead (16–64% of TTFT), limiting its scalability to long prompts.
![Teaser figure](../imgs/ICML20250956/cropped_page0_idx1.webp)

## Input / Output

The system operates in a two-step compile-then-link workflow: immutable chunks (documents, few-shot examples) are first submitted via an explicit caching API and compiled independently with position IDs starting from zero, each receiving a unique cache ID. At serving time, a request combines these cache IDs with mutable user query tokens (typically <50 tokens) through an extended chat-completion API. The output is the standard autoregressive text generation, with the KV cache stored across HBM, DRAM, and local filesystem for cross-request reuse.

## Method

LegoLink exploits the observation that the first few tokens of each independently compiled chunk act as 'attention sinks,' disproportionately absorbing attention and blocking subsequent tokens from attending to relevant context. By recomputing only the first k tokens (k ≤ 32) of each chunk except the first, LegoLink allows these tokens to recognize their non-initial positions and release their attention-sink dominance, redirecting attention to relevant positions. This reduces recomputation complexity from O(N²) to O(kN) ≈ O(N), where k scales with the number of chunks rather than prompt length, and uses static (predefined) token selection instead of CacheBlend's dynamic first-layer attention comparison. A zero-overhead variant, LegoLink-0, prepends and discards dummy tokens at compile time to eliminate attention sinks entirely, skipping all link-time recomputation. The full EPIC system is implemented on vLLM with an explicit cache-ID-based KV store and OpenAI-compatible caching APIs.

## Results

EPIC with LegoLink-16 achieves up to 8× reduction in TTFT and 7× increase in throughput compared to CacheBlend-15 under asynchronous multi-request workloads. For single-request serving, LegoLink-2 limits accuracy degradation to within 0–7% of Fully Recompute (FR) while reducing TTFT by up to 3× relative to the default CacheBlend-15 configuration. On long-context scaling, LegoLink-16 handles up to 50K tokens before OOM, whereas CacheBlend-15 encounters OOM at approximately 35K tokens, reflecting the O(kN) vs. O(N²) recomputation complexity difference.

## Baselines & Comparisons

The primary baseline is CacheBlend (Yao et al., 2025), the first PIC algorithm, with Naive (zero recomputation) and Fully Recompute (FR) serving as reference bounds. EPIC/LegoLink consistently outperforms CacheBlend on both latency and throughput: up to 8× TTFT reduction and 7× throughput gain under multi-request serving with varying request rates. On accuracy, LegoLink-2 stays within 0–7% of FR across six datasets and three models, while CacheBlend-1 and CacheBlend-5 (which recompute a similar absolute number of tokens) degrade up to 80% worse than FR, demonstrating that CacheBlend's dynamic token selection is less effective than LegoLink's static chunk-initial selection. CacheBlend's dynamic sparsity (recomputing all first-layer KV vectors to select 15% of tokens) introduces 16.3%–63.56% runtime overhead on TTFT, an overhead entirely eliminated by LegoLink's static sparsity. On long-context workloads, LegoLink-16 avoids OOM until 50K tokens while CacheBlend-15 fails at ~35K tokens. The one scenario where the gap narrows is short-document datasets (MultiNews, SAMSum), where per-chunk token counts are small enough that the absolute recomputation volume becomes comparable between the two methods.

## Relation to Prior Work

This paper formalizes Position-Independent Caching (PIC) as a two-step compile/link framework, extending prefix-based context caching (vLLM, SGLang, Pensieve) to enable modular KV-vector reuse regardless of preceding tokens. It directly builds on CacheBlend (Yao et al., 2025), the first PIC algorithm, but departs from its dynamic attention-sparsity approach (recomputing 15% of tokens via first-layer attention-map comparison) by introducing LegoLink, which exploits the 'attention sink' phenomenon to recompute only the first k tokens of each chunk using static sparsity. The system is implemented on vLLM, inheriting its PagedAttention infrastructure while adding explicit cache-ID-based APIs analogous to those in Gemini and Mooncake.

## Why It Matters / Open Questions

The O(kN) vs. O(N²) complexity reduction is practically significant for long-context RAG and multi-document QA workloads, where CacheBlend already hits OOM at ~35K tokens while LegoLink handles 50K. The LegoLink-0 variant (zero runtime linking overhead via compile-time dummy-token removal) opens an interesting direction for eliminating the link step entirely, though its accuracy trade-offs need further study. Open questions include whether the attention-sink insight generalizes to larger models and different architectures, how to handle the observed tendency toward unnecessarily lengthy outputs in sparsity-based algorithms, and whether the 7% accuracy ceiling can be closed without reverting to dynamic recomputation.
