## Problem

LLM-based text-to-SQL models struggle with three interrelated challenges: interpreting ambiguous user intent, mapping natural language terms to correct database tables and columns, and producing syntactically valid SQL. Existing decomposition-based approaches fail to handle SQL's declarative structure and the intricate connections between query concepts and database elements, making it non-trivial to break SQL generation into meaningful subtasks.
![Teaser figure](../imgs/ICML20252992/cropped_page2_idx0.webp)

## Input / Output

The method takes a natural language query and a database schema (tables, columns, primary keys, foreign keys) as input and produces a single executable SQL query as output. The query is parsed into a context-free syntax tree with forward-syntax, backward-syntax, and none-syntax edge types, while the schema is encoded as a relational graph with table-column, primary-key, and foreign-key edges. The LLM generates SQL incrementally by producing components for each non-terminal node in the decomposed syntax tree, which are then assembled into the final query.

## Method

SGU-SQL is a three-stage framework: (1) graph-based structure construction builds a query graph from syntactic parsing and a database schema graph capturing relational constraints; (2) structure-aware linking uses a Relational Graph Attention Network (RGAT) with dual-graph encoding to match query nodes to schema nodes, trained via a contrastive objective that maximizes scores for correct query-schema pairs while minimizing scores for incorrect ones; (3) syntax-tree-based decomposition maps non-terminal nodes in the query's context-free syntax tree to SQL meta-operations, guiding the LLM to generate SQL components incrementally for each subtask rather than producing the full query in one pass. The key distinction from prior decomposition methods (e.g., DIN-SQL, MAC-SQL) is that the decomposition is dynamically driven by the query's own syntactic structure rather than fixed patterns or black-box LLM reasoning.

## Results

SGU-SQL achieves 87.95% execution accuracy and 78.26% exact match accuracy on Spider-dev, and 61.80% execution accuracy and 51.44% exact match accuracy on BIRD-dev, outperforming all baselines on both benchmarks. On the harder BIRD dataset, SGU-SQL with GPT-4o backbone reaches 69.28% execution accuracy, surpassing PURPLE (68.12%), CHESS (68.31%), and E-SQL (65.58%). On the extremely challenging Spider 2.0-Snow and Spider 2.0-Lite benchmarks, SGU-SQL achieves 4.39% and 6.40% respectively, roughly doubling the performance of DAIL-SQL+GPT-4o (2.20% and 5.68%).

## Baselines & Comparisons

SGU-SQL outperforms all 20 compared baselines on both Spider and BIRD in terms of execution accuracy. The closest competitors are SuperSQL (86.82% Spider EX Acc, 58.60% BIRD) and PURPLE (86.70% Spider, 68.12% BIRD with GPT-4o), which SGU-SQL surpasses by 1.1% and 1.3% on Spider, and by 3.2% and 1.2% on BIRD respectively. Among structure-learning baselines, RESDSQL (81.82% Spider) and S²SQL (76.43%) trail SGU-SQL by 6.1% and 11.5% on Spider. Among in-context learning methods, DAIL-SQL (83.08%) and DIN-SQL (82.79%) are outperformed by approximately 5% on Spider. The only method exceeding SGU-SQL is CHASE-SQL (73.14% on BIRD), but it uses Gemini 1.5 Pro as backbone and incorporates an iterative query-fixer module with execution feedback, whereas SGU-SQL generates SQL in a single pass without execution feedback. On the extremely difficult Spider 2.0 benchmarks, SGU-SQL (4.39% Snow, 6.40% Lite) roughly doubles DAIL-SQL+GPT-4o (2.20%, 5.68%) and CHESS+GPT-4o (1.28%, 3.84%).

## Relation to Prior Work

SGU-SQL synthesizes two previously separate research threads in text-to-SQL: (1) GNN-based structure learning methods (RAT-SQL, LGESQL, S²SQL, Graphix-T5, RESDSQL) that model query-schema relationships via graph encoders, and (2) LLM-based in-context learning methods (DIN-SQL, DAIL-SQL, MAC-SQL, SuperSQL, PURPLE) that rely on prompt engineering and fixed decomposition patterns. The key departure is using a Relational Graph Attention Network (RGAT) for structure-aware query-schema linking and then feeding the resulting linked structure into a syntax-tree-guided decomposition that directs an LLM to generate SQL incrementally clause-by-clause, rather than using a fixed decomposition template or relying on the LLM's black-box reasoning. This positions SGU-SQL as a bridge between the symbolic/structural tradition and the LLM prompting paradigm.

## Why It Matters / Open Questions

The paper demonstrates that explicitly encoding structural information (syntax trees, schema graphs) and using it to guide LLM decomposition yields consistent gains over both fixed-pattern decomposition (DIN-SQL) and multi-agent approaches (MAC-SQL), with the largest improvements on hard/extra-hard queries. However, the Spider 2.0 results (4.39% on Snow, 6.40% on Lite) reveal that enterprise-level multi-database SQL generation remains largely unsolved, and the single-pass generation without execution feedback limits robustness. Open questions include whether the graph-based linking generalizes to truly dynamic databases, whether the approach extends to graph databases (text-to-Cypher) or API planning as the authors suggest, and whether the efficiency advantage over prompt-heavy baselines holds at larger scale.
