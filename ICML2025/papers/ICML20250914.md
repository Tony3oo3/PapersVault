## Problem

Closed-source LLMs expose only generated tokens to developers, forcing reliance on prompt engineering for domain-specific adaptation and precluding weight-based fine-tuning methods like LoRA or adapters. The paper asks whether access to token logits alone—without model weights or training data—would suffice for effective task adaptation, and shows that it does by reframing LLM alignment as a label noise correction problem.
![Teaser figure](../imgs/ICML20250914/cropped_page0_idx0.webp)

## Input / Output

The Plugin model consumes two probability vectors at each decoding step: the softmax output b_t from the frozen black-box LLM and the output r_t from a small autoregressive reweighting model (e.g., a single-layer transformer or GPT-2-small), both of dimension |V|. These are combined via element-wise product and L1-normalization to yield the final token distribution p_t = (b_t ⊙ r_t)/||b_t ⊙ r_t||_1, from which the next token is selected by argmax (greedy decoding). The reweighting model is trained on a small set of task-specific sequences using cross-entropy loss, with only its parameters updated while the black-box model remains frozen.

## Method

The core insight is that next-token prediction in a decoder-only LLM is structurally identical to supervised classification, so aligning the model to domain-specific data reduces to estimating a label transition matrix T_t that maps the model's noisy (broad-corpus) predictions to the target distribution. To make T_t tractable, the authors impose a diagonal structure, reducing it from ~10 billion parameters to |V| per step, and model it as a function of preceding tokens via a small autoregressive reweighting network. During training, sequences are passed through both the frozen black-box model and the reweighting model; the combined probabilities are scored with cross-entropy against ground-truth tokens, and gradients update only the reweighting model. The paper provides the first finite-time convergence guarantee (Theorem 1) for transition matrix estimation under autoregressive noisy loss, showing the estimated parameter θ̂_t converges to θ_* as the number of training tokens grows. Empirically, Plugin outperforms zero-shot, in-context learning, weighted combination, and temperature-scaling baselines across four NLG datasets and three base models (GPT-2-M, GPT-2-XL, LLaMA-3.1-8B), and can be stacked on top of prompt-learning methods like BDPL for further gains.

## Results

Plugin outperforms all baselines (Zero-shot, ICL-1, ICL-3, NewModel, WeightedComb, TempNet) across nearly all four datasets (E2E NLG, Web NLG, CommonGen, Adidas), three base models (GPT2-M, GPT2-XL, LLaMA-3.1-8B), and seven NLG metrics (BLEU, ROUGE-1/2/L, METEOR, CIDEr, NIST). In a human evaluation on 100 Adidas samples, Plugin is preferred over ICL-3 in 81% of cases. Under distribution shift, Plugin dramatically improves domain alignment: Person-related sentence generation on Web NLG rises from 17.99% (fine-tuned base) to 71.34%, and Woman-related sentences on CommonGen increase from 10.37% to 31.92%. When applied as a wrapper on top of BDPL prompt learning, Plugin roughly doubles BLEU scores (e.g., E2E NLG: 0.2287→0.4527; Web NLG: 0.1024→0.2137).

## Baselines & Comparisons

Plugin consistently outperforms ICL-1 and ICL-3 (Long et al., 2023) across all datasets and metrics, with the gap widening under distribution-shifted settings (Web NLG, CommonGen). WeightedComb (Liu et al., 2021), which combines expert and base-model probabilities with a single fixed α, underperforms Plugin because a uniform combination across all tokens is a poor modeling choice for context-sensitive reweighting. TempNet (Qiu et al., 2024), which learns a single global temperature per input to uniformly scale logits, also underperforms Plugin, which reweights each token's probability independently at every decoding step. NewModel (trained from scratch on validation data) occasionally achieves higher NIST scores due to increased repetition of less-frequent input tokens, but this comes at the cost of coherence reflected in BLEU, ROUGE, and METEOR. In the human evaluation, Plugin is preferred over ICL-3 in 81% of 100 Adidas samples, confirming that the logit-level reweighting produces outputs more aligned with the target domain than in-context examples alone.

## Relation to Prior Work

This paper extends the label noise correction framework of Patrini et al. (2017) from supervised classification to autoregressive language modeling, reframing black-box LLM adaptation as a transition matrix estimation problem. Unlike prior loss-correction methods that modify the training objective and retrain the model, Plugin estimates the transition matrix from clean target data and applies it at inference via element-wise logit reweighting, since the black-box model's weights are inaccessible. The approach also draws on the plugin methods literature (Koyejo et al., 2014; Hiranandani et al., 2021) for the probability reweighting mechanism, and positions itself as a middle ground between prompt-only black-box adaptation and weight-access PEFT methods like LoRA and adapters.

## Why It Matters / Open Questions

The paper makes a concrete case for broader logit access in closed-source LLMs, arguing it would unlock a new class of adaptation techniques beyond prompt engineering. The theoretical contribution—a first finite-time convergence analysis for transition matrix estimation under autoregressive noisy loss—provides rigorous grounding for the approach. Key limitations include the reliance on a diagonal (class-independent) transition matrix, which may be too restrictive for complex distribution shifts, and the fact that reweighting token probabilities without modifying internal representations may not suffice for tasks requiring deep structural changes like complex reasoning. Open questions include whether richer (non-diagonal) transition structures, learned with more data, could capture more nuanced domain shifts, and whether the approach generalizes to multi-turn or reasoning-heavy generation.
