## Problem

When LLMs invoke external tools, they frequently produce tool hallucinations—selecting irrelevant tools, fabricating parameters, or calling tools at wrong times—yet prior tool-learning methods only optimize over a fixed set of decisive actions (i.e., directly invoking a tool), offering no mechanism for the model to abstain when preconditions are unmet. This paper systematically categorizes tool hallucinations into selection and usage types, introduces hallucination-aware evaluation metrics, and proposes a reliability alignment framework that gives models an explicit 'out' when tool invocation conditions are not satisfied.

## Input / Output

The model receives a user query, a set of available tool descriptions (with parameters), and the running tool-calling history, and at each step must emit either a concrete tool call (JSON with tool name and parameters), an indecisive action from a newly introduced set (ChangeTools to switch to an alternative tool, TalkToUser to request missing information, or give_up_and_restart to abandon the task), or a final answer. The evaluation pipeline combines rule-based checks (JSON validity, parameter presence) with a GPT-4o LLM evaluator that scores tool-task relevance and parameter authenticity, producing per-call hallucination labels and task-level RePR/Utility scores.

## Method

Relign expands the tool-use action space with indecisive actions so the model can defer, clarify, or switch tools instead of being forced into a potentially hallucinated call. Training proceeds in two stages: (1) SFT on ~10k ToolBench samples where 3k have parameters obscured and 3k have tools replaced with irrelevant ones, teaching the model to emit TalkToUser or ChangeTools under those conditions; (2) DPO on preference pairs sampled from multi-round rollouts (temperature 0.7, 10 trajectories per step) and classified by a GPT-4o hallucination evaluator into correct, indecisive, and hallucinated actions, yielding three pair types (correct > indecisive, indecisive > hallucinated, correct > hallucinated). The framework is evaluated on RelyToolBench (958 tasks across Original, Missing Parameter, and Unmatched Tools subsets) using RePR (pass rate minus task hallucination rate) and Benefit-Cost Utility (task reward minus penalties for excess calls and hallucinations), and shows that Relign reduces overall tool hallucination from ~50% to ~15–18% while also cutting average tool-call counts, with the LLaMA-3.1-8B variant approaching GPT-4o-level reliability.

## Results

On the Overall split of RelyToolBench, Relign reduces the tool hallucination rate from 50.8% to 14.6% on Llama3.1-8B (baseline → +Relign), from 56.5% to 18.3% on ToolLLaMA-7B, and from 49.2% to 17.6% on Qwen2.5-7B, while simultaneously raising the Reliable Pass Rate (RePR) from 65.3 to 77.2, 62.5 to 69.1, and 65.1 to 73.0 respectively. The average number of tool calls drops from 2.2 to 1.5 (Llama3.1) and from 3.7 to 0.9 (ToolLLaMA), and the Benefit-Cost Utility increases from 9.4 to 13.2 (Llama3.1). The Relign-tuned Llama3.1-8B (RePR 77.2, Hallu 14.6) surpasses GPT-3.5-Turbo (58.4, 63.4) and GPT-4o-mini (73.3, 17.9), approaching GPT-4o (74.8, 8.3).

## Baselines & Comparisons

StepTool (RLHF) and its step-level variant improve task success marginally (e.g., Llama3.1 RePR 65.3→65.7) but fail to reduce hallucination rates and even slightly increase them (Tool Hallu 50.8→52.9), confirming that optimizing only over decisive tool-invocation actions cannot address hallucination. SFT alone achieves a large hallucination reduction (Llama3.1: 50.8→23.4) but yields a lower RePR (69.6) than Relign (77.2), indicating that supervised learning of indecisive actions helps but is insufficient without preference optimization. DPO alone reduces tool-call count (2.2→2.3, modest) but provides inconsistent hallucination reduction (50.8→46.1 on Llama3.1). The joint SFT&DPO baseline (Llama3.1: RePR 73.7, Hallu 17.7) is the closest competitor to Relign, yet Relign still leads by 3.5 RePR points and 3.1 hallucination points while using fewer tool calls (1.5 vs 1.7). Against closed-source models, the Relign-tuned Llama3.1-8B outperforms GPT-3.5-Turbo by 18.8 RePR points and 48.8 hallucination points, and edges out GPT-4o-mini by 3.9 RePR points, approaching GPT-4o's 74.8 RePR.

## Relation to Prior Work

This paper extends the tool learning line (ToolLLM, StepTool, StableToolBench) by reframing tool invocation as a decision-making problem where the action space must include 'not acting' — specifically, indecisive actions like ChangeTools and TalkToUser — rather than only optimizing over decisive tool calls. It builds directly on DPO (Rafailov et al., 2024) for preference-based alignment, but applies it to a novel preference hierarchy over tool-call trajectories (correct > indecisive > hallucinated) rather than standard helpfulness preferences. Conceptually, it departs from prior tool-learning RL work (StepTool, RLHF) that assumes all actions in the predefined tool set are valid, arguing instead that the model must learn when the preconditions for tool use are unmet and should defer or seek clarification.

## Why It Matters / Open Questions

The systematic taxonomy of tool hallucinations (4 subtypes) and the RelyToolBench benchmark provide the field with the first dedicated infrastructure for measuring tool reliability, addressing a gap where prior evaluations focused on task success without distinguishing hallucinated from genuinely failed outcomes. The finding that standard Pass Rate overestimates reliability by 10–17 points (e.g., LLaMA3.1: 82.6 PR vs. 65.3 RePR) suggests that widely-used tool-use benchmarks may be masking significant hallucination problems. Open questions include whether the indecisive-action concept generalizes to multi-tool or agentic settings, whether timing hallucination (the least improved subtype) can be addressed with sequential-dependency-aware training, and whether the approach scales beyond 7–8B models without the GPT-4o evaluator bottleneck.
