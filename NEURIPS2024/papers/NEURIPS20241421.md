## Problem

Programming-by-Example (PBE) requires inferring a generalizing program from a handful of input-output pairs without any natural-language description, a fundamentally different challenge from the prompt-to-code generation that LLMs excel at. While pretrained LLMs have been shown to perform poorly on PBE, it remained unclear whether fine-tuning could close this gap and whether the resulting system would generalize beyond its training distribution. This paper systematically investigates both questions across three qualitatively different domains, including an uncommon graphics domain likely underrepresented in pretraining data.
![Teaser figure](../imgs/NEURIPS20241421/cropped_page1_idx0.webp)

## Input / Output

The system takes a small set of input-output example pairs (X, Y) demonstrating a hidden algorithm and produces a Python source-code program that generalizes to unseen inputs. For the LOGO graphics domain, the visual input is converted to a 32×32 ASCII grid where each cell is a digit 0–9 encoding the quantized black-pixel density of a 16×16 block within a 512×512 center crop, allowing a text-based code LLM to perceive the image. Unlike classic PBE systems restricted to domain-specific languages, the output is Turing-complete Python, enabling arbitrary compositions of string, numerical, and control-flow operations.

## Method

The core pipeline fine-tunes a DeepSeekCoder LLM (7B or 33B) via LoRA on a large synthetic dataset of (program, input, output) triples. This dataset is bootstrapped from a small manually-constructed seed set by prompting a 33B LLM to generate new programs and inputs, then executing those programs in a Python interpreter to obtain ground-truth outputs—effectively training the model to invert program execution. At inference, the model samples K candidate programs and filters them by checking against the provided I/O examples (rejection sampling), requiring tens to hundreds of samples per problem. For out-of-distribution generalization, the paper introduces a wake-sleep-style adaptation loop: solved problems from an unlabeled test distribution are added back to the seed set, the generative prior is implicitly updated, and the model is retrained, iteratively narrowing the domain gap. The authors show that posterior description length (not program size or prior likelihood) best predicts solve difficulty, indicating the fine-tuned model genuinely conditions on the examples rather than performing blind guess-and-check.

## Results

On text editing (PROSE benchmark), the fine-tuned 33B model achieves 82% generalization accuracy and 88% oracle accuracy, surpassing FlashFill (33% gen accuracy) and approaching FlashFill++ (≈100% oracle accuracy). On LOGO/Turtle graphics, the model solves 90% of the test set, surpassing DreamCoder and language-conditioned synthesizers. On list functions, the model surpasses all symbolic and neurosymbolic baselines from Rule et al. and LambdaBeam, and solves 100% of the λ² benchmark problems. Out-of-distribution, performance degrades (e.g., 76%→59% on text editing when seeded with SyGuS instead of PROSE), but the wake-sleep adaptation procedure recovers ~10% absolute in all domains (~190% relative for LOGO).

## Baselines & Comparisons

On list functions, the fine-tuned model surpasses Metagol [47], RobustFill [20], Fleet [48], and LambdaBeam [12] (Shi et al., 2023) in terms of problems solved within a given search budget (Fig. 3a, Appendix Fig. 10), and also surpasses GPT-4 [18] zero-shot. On text editing, the 33B model achieves 82% generalization accuracy versus FlashFill's 33% [2], a 2.5× improvement, though it falls short of FlashFill++'s ≈100% oracle accuracy [38] (88% vs. ≈100%). On LOGO graphics, the model solves 90% of the test set, outperforming DreamCoder [45] (which introduced these problems), LILO [43], and Regal [46]—the latter two of which additionally use natural-language descriptions of the target image, whereas this method uses only the image. The key qualitative advantage over all symbolic baselines is the use of a Turing-complete language (Python), enabling solutions that mix string and numerical operations or leverage world knowledge in ways domain-specific languages cannot express.

## Relation to Prior Work

This paper positions itself at the intersection of two lineages: classic symbolic PBE (FlashFill, DreamCoder, LambdaBeam) which relies on carefully restricted domain-specific languages, and LLM code generation which is driven by natural-language prompts. Methodologically, it adapts the self-instruct paradigm (Wang et al., 2023) for synthetic data generation but departs by using program execution rather than LLM self-output as the observation model, and by framing the fine-tuned network as an inference network in a wake-sleep-style graphical model (Hinton et al., 1995). The key conceptual departure from prior LLM-for-PBE work (which largely reported negative results) is the demonstration that LoRA fine-tuning on synthetically generated (program, input, output) triples—bootstrapped from a small seed set—yields a strong PBE system over Turing-complete Python, rather than a DSL.

## Why It Matters / Open Questions

The paper provides the most systematic empirical evidence to date that fine-tuned LLMs can match or surpass dedicated symbolic synthesizers across multiple PBE domains, including an uncommon graphics domain likely underrepresented in pretraining data, and that a wake-sleep-style adaptation loop can partially close the out-of-distribution gap. However, significant open questions remain: the model requires tens to hundreds of rejection-sampled programs per problem (minutes of GPU time), degrades substantially on OOD inputs, and the 7B–33B model sizes are impractical for the end-user deployment that motivated PBE in the first place. The finding that posterior description length—not program size or prior likelihood—best predicts success is a useful diagnostic but leaves the deeper question of *why* specific problems are hard for the network largely unanswered, a transparency gap that does not exist in symbolic systems.
