## Problem

Existing cross-domain recommendation (CDR) methods assume a limited dual-domain or few-domain setting and overlook two critical issues in the Broader-Source CDR (BS-CDR) scenario: (1) both intra-domain and inter-domain privacy must be simultaneously preserved when transferring knowledge across many source domains, and (2) negative transfer accumulates as more source domains are added, causing model performance to degrade below even a single-domain baseline. No prior framework addresses both challenges jointly in a multi-domain federated setting.

## Input / Output

The method consumes user-item interaction matrices from M>3 domains (with partially overlapping users) and operates entirely within each user's local device for cross-domain knowledge transfer, avoiding additional server-to-server communication. Source domain knowledge is represented as L×d embedding matrices extracted from GAT message-propagation layers; for domains where a user has no ratings, the input is a pure Gaussian noise matrix. The output is a top-K ranked list of items in the target domain, with per-layer domain attention coefficients (a_i^l) that dynamically weight each source domain's contribution, plus estimated rating scores via sigmoid inner product of final user and item embeddings.

## Method

FedGCDR follows a Horizontal-Vertical-Horizontal (HVH) federated pipeline built on a simplified GAT (no feature transformation or nonlinear activation, inspired by LightGCN). The Positive Knowledge Transfer Module (vertical stage) applies the Gaussian mechanism of differential privacy to source-domain embeddings extracted locally from GAT layers, then aligns feature spaces via per-domain MLPs trained with a mapping loss. The Positive Knowledge Activation Module (second horizontal stage) expands the target domain's local graph by constructing M−1 virtual users from the mapped source embeddings and linking them to the real user via virtual social edges; the GAT then generates domain-specific attention coefficients from these links, enabling the model to down-weight harmful source domains without manual hyperparameter tuning. A final fine-tuning stage freezes all GAT propagation layers and trains only the output embeddings with BCE loss to filter residual negative knowledge. The full objective combines BCE rating prediction loss, the MLP mapping loss, and a cosine-similarity-based social regularization term.

## Results

On the Amazon-16@Books benchmark (16 source domains, most challenging setting), FedGCDR achieves HR@5 = 0.5016 and NDCG@5 = 0.3600, outperforming the single-domain baseline (HR@5 = 0.4693) by 6.8% and the best CDR baseline FedCDR (HR@5 = 0.3926) by 27.8%. On Amazon-16@CDs, FedGCDR reaches HR@5 = 0.5267 and NDCG@5 = 0.4382, surpassing the single-domain baseline (HR@5 = 0.4119) by 27.9%. The DP variant (FedGCDR-DP) retains most of the gains, e.g., HR@5 = 0.4928 on Amazon-16@Books, confirming that privacy preservation via Gaussian noise incurs only a small accuracy cost (~1–2%).

## Baselines & Comparisons

FedGCDR outperforms all five baselines across every dataset and target domain. Against the single-domain FedGNN baseline, FedGCDR consistently improves HR@5 by 2–28% depending on the setting, confirming that cross-domain knowledge transfer is beneficial when negative transfer is properly controlled. EMCDR suffers the most severe hard negative transfer: on Amazon-16@Books its HR@5 collapses to 0.3140, well below the single-domain 0.4693, while FedGCDR maintains 0.5016. PriCDR and FedCDR show moderate negative transfer on Amazon-16 (HR@5 = 0.3699 and 0.3926 respectively, both below single-domain), whereas FedGCDR stays above single-domain in all settings. FedCT exhibits the worst overall performance, dropping to HR@5 = 0.2779 on Amazon-16@Books (a 41% drop from single-domain), indicating its VAE-based transfer mechanism is particularly vulnerable to accumulative negative knowledge from many source domains.

## Relation to Prior Work

FedGCDR extends the HVH federated pipeline introduced by FedCT (Liu et al., SIGIR 2021) and builds on the simplified GAT architecture inspired by LightGCN (He et al., SIGIR 2020) as its intra-domain backbone. It departs from prior privacy-preserving CDR work (PriCDR, FedCDR, Win-Win) by simultaneously addressing both intra-domain and inter-domain privacy, whereas existing methods handle only one type. The key conceptual departure is the graph-expansion mechanism using virtual social links to generate domain attentions, replacing the manual hyperparameter tuning or predefined domain features used in earlier multi-domain CDR approaches.

## Why It Matters / Open Questions

The paper demonstrates that in broader-source settings (16 domains), existing CDR methods can degrade below single-domain performance due to accumulated negative transfer, a practically important finding for multi-domain recommender deployments. The dual-privacy guarantee (intra-domain via horizontal FL, inter-domain via DP) makes the framework more deployable in real multi-organization settings. However, the approach is limited to a single dataset (Amazon), relies on overlapping users as a cross-domain bridge, and the DP noise parameter (ε=8) still yields a noticeable accuracy gap compared to the no-noise variant, leaving open the question of how to maintain strong privacy without significant performance loss at scale.
