## Problem

ML datasets suffer from fragmented metadata: existing standards like DCAT and schema.org lack ML-specific support (dataset splits, semantic typing for bounding boxes or segmentation masks), do not integrate with ML frameworks, and cannot express the complex file layouts common in ML data. This makes datasets hard to discover, port across platforms, and load directly into training pipelines without manual, tool-specific glue code.

## Input / Output

Croissant consumes existing dataset files in any format (images, text, audio, video, CSV, JSON, Parquet, archives) without requiring changes to the underlying data representation. It produces a single JSON-LD metadata file organized into four layers, where the Structure Layer uses RecordSet primitives with inclusion/exclusion filters, regex extraction, and JSON Path to map heterogeneous file layouts into a uniform record schema. The output is directly consumable by ML frameworks: TensorFlow Datasets provides a CroissantBuilder, and PyTorch DataPipes wraps the reference library's iterator abstraction.

## Method

Croissant is a four-layer metadata vocabulary extending schema.org/Dataset: (i) a Dataset Metadata Layer for identity and licensing, (ii) a Resource Layer with FileObject (single files) and FileSet (pattern-matched file collections) primitives, (iii) a Structure Layer where RecordSet defines fields, subfields, joins, and transformations (regex, JSON Path) to normalize any data format into a standard record representation, and (iv) a Semantic Layer adding ML-specific typing (train/test/validation splits, bounding boxes, GeoCoordinates, categorical labels). A Croissant-RAI extension layers responsible-AI attributes (data lifecycle, annotator demographics, fairness assessments) on top. The paper validates the format through a user study in which nine practitioners annotated ten datasets across language, vision, audio, and multimodal modalities, with agreement measured via BLEU scores and usability assessed on five criteria (consistency, completeness, conciseness, readability, understandability); over 80% of annotations confirmed Croissant captures important dataset information, and ~90% found the specification understandable.

## Results

In the user study with 9 annotators across 10 ML datasets (30 annotations total), over 80% of annotations (25/30) rated Croissant as capturing all important dataset information (completeness), ~83% found attribute names intuitive (readability), and ~90% found the specification understandable. Average BLEU scores for inter-annotator agreement were 0.55 for core Croissant attributes versus 0.41 for Croissant-RAI attributes, with the gap attributed to RAI attributes requiring more free-form text. Over 75% of annotators reported high confidence in their annotations, and ~80% reported clear understanding of the datasets they annotated.

## Baselines & Comparisons

This paper does not include quantitative comparisons against competing metadata formats (e.g., DCAT, Data Packages, or Hugging Face Dataset Cards); the related work section positions Croissant qualitatively as filling the gap of a machine-readable, ML-specific standard that existing standards lack. The primary quantitative comparison is internal: core Croissant attributes achieve a higher average BLEU agreement score (0.55) than Croissant-RAI attributes (0.41), with the difference explained by RAI attributes requiring more free-form text and deeper publication mining. Among core attributes, those with predefined values (e.g., sc:license at 0.74, sc:inLanguage at 0.73) show substantially higher agreement than free-text attributes like sc:description (0.52) or sc:publisher (0.26). The lowest-agreement attributes (sc:publisher at 0.26, rai:annotatorDemographics at 0.29) correspond to information that is often ambiguous or absent from dataset documentation, suggesting these are the hardest fields to standardize across annotators.

## Relation to Prior Work

Croissant extends the Schema.org/Dataset vocabulary with ML-specific primitives (FileObject, FileSet, RecordSet) to create a machine-readable format that prior standards like DCAT, Data Packages, and CSV on the Web do not provide. It also builds on natural-language documentation efforts—Datasheets for Datasets, Data Statements, and Data Cards—by encoding their responsible-AI concepts into a structured, machine-processable Croissant-RAI extension. The key departure from prior work is that Croissant is designed to be directly consumable by ML frameworks (TensorFlow Datasets, PyTorch DataPipes) rather than serving only as human-readable documentation or web-search metadata.

## Why It Matters / Open Questions

Croissant addresses a practical bottleneck in ML data management by providing a single interoperable metadata layer already adopted by Hugging Face, Kaggle, and OpenML (400K+ datasets) and recommended by the NeurIPS Datasets and Benchmarks Track. Open questions include whether the format scales to highly complex data structures (e.g., HDF5, Zarr, geospatial data), whether the Croissant Editor matures enough for non-expert users, and whether the small, community-sourced user study generalizes to broader practitioner populations. The long-term impact hinges on sustained adoption by additional ML tools and on the format's ability to evolve with emerging responsible-AI and data-governance requirements.
