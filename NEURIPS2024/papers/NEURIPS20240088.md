## Problem

Single-agent MLLM architectures for mobile device operation struggle with two navigation challenges as tasks grow longer: tracking task progress from lengthy interleaved image-text operation histories, and retrieving task-relevant focus content (e.g., previously queried match results) from earlier screens. The growing token sequences and mixed modality format degrade a single agent's ability to reason about what has been done and what information is still needed, causing errors to accumulate in later stages of multi-step tasks.

## Input / Output

The system consumes a natural-language user instruction, the current screen screenshot (processed through a visual perception module yielding text/icon labels with pixel coordinates), and a text-only task progress summary maintained by the planning agent. The decision agent additionally receives the last reflection result and focus content from a persistent memory unit. Output is a structured operation drawn from a fixed six-action space (open app, tap, swipe, type, home, stop) with coordinate parameters, plus side-channel outputs: an updated task progress string, a reflection verdict (correct/erroneous/ineffective), and a memory unit update capturing any newly observed focus content.

## Method

Mobile-Agent-v2 decomposes the single-agent loop into three specialized roles: a planning agent (text-only GPT-4) that condenses the full operation history into a compact pure-text task progress summary, a decision agent (GPT-4V) that generates the next operation conditioned on the current screenshot, perception results, task progress, memory, and last reflection, and a reflection agent (GPT-4V) that compares before/after screenshots to classify each operation as correct, erroneous (wrong page), or ineffective (no change). A memory unit stores task-relevant focus content extracted by the decision agent from each screen, enabling cross-app information retrieval without re-reading history. A visual perception module (ConvNextViT-document OCR + GroundingDINO icon detection + Qwen-VL icon description) augments raw screenshots with structured text and coordinate annotations. The key architectural insight is that separating long-context summarization (planning), grounded action selection (decision), and outcome verification (reflection) into distinct agents with tailored input modalities avoids the token-length and interleaved-modality bottlenecks that degrade a single end-to-end MLLM.

## Results

On the non-English (Harmony OS) evaluation, Mobile-Agent-v2 achieves a 72.7% overall success rate (32/44 instructions) versus 27.3% (12/44) for the single-agent Mobile-Agent baseline, representing a ~45 percentage-point gain. On the English (Android OS) evaluation, Mobile-Agent-v2 reaches 77.3% overall SR versus 59.1% for Mobile-Agent, a ~18 percentage-point improvement. The largest gains appear in advanced instructions and multi-app tasks: on non-English advanced external-app instructions, SR jumps from 10% to 50%, and on multi-app advanced instructions from 0% to 100%. With manual operation knowledge injection, Mobile-Agent-v2 further improves to 100% SR on all basic instructions in both language scenarios.

## Baselines & Comparisons

The sole baseline is Mobile-Agent (Wang et al., 2024), a single-agent GPT-4V architecture with a visual perception module but no planning, reflection, or memory components. Mobile-Agent-v2 outperforms Mobile-Agent on every metric across all app categories and both language scenarios. The most dramatic gains are in the non-English setting: overall SR improves from 27.3% to 72.7% (+45 pp), with external-app advanced instructions going from 10% to 50% SR and multi-app advanced from 0% to 100%. In the English setting, the improvement is more moderate (59.1% → 77.3% overall SR, +18 pp), consistent with GPT-4V's stronger native English performance. The ablation study (Table 4) confirms that the planning agent contributes the largest single-component gain (removing it drops basic SR from 88.6% to 59.1%), while the reflection agent and memory unit each add 3–8 pp. The paper also shows that direct GPT-4V end-to-end operation (no agent architecture) achieves only 2.7% SR on basic single-step tasks, underscoring that the multi-agent scaffolding—not the underlying MLLM alone—is responsible for the performance.

## Relation to Prior Work

This paper directly extends Mobile-Agent (Wang et al., 2024), a single-agent GPT-4V-based mobile operation assistant, by decomposing its monolithic decision loop into a three-agent collaboration (planning, decision, reflection) with a shared memory unit. The visual perception module (GroundingDINO, OCR, Qwen-VL) and the constrained operation space are inherited unchanged from Mobile-Agent; the novelty lies entirely in the architectural split that avoids feeding long interleaved image-text histories into a single MLLM context. Conceptually, it applies the multi-agent LLM collaboration paradigm (MetaGPT, AutoGen, CAMEL) to the specific domain of sequential GUI operation, where prior work had treated the task as a single end-to-end perception-and-action problem.

## Why It Matters / Open Questions

The >30% success-rate gain over the single-agent baseline and the ablation showing the planning agent as the most critical component provide concrete evidence that long-context navigation, not visual perception, is the primary bottleneck in MLLM-based mobile agents. The memory unit and reflection agent address two practically important failure modes (loss of cross-screen focus content and undetected erroneous operations) that limit real-world deployment. However, the evaluation is limited to 88 instructions across 10 apps with no statistical significance reporting, the system depends on proprietary GPT-4/GPT-4V APIs, and the knowledge-injection results, while promising, rely on manually written operation tutorials—automating this remains an open question that could determine whether the approach scales beyond curated app sets.
