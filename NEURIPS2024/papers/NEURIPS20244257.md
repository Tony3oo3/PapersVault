## Problem

Accounting bugs in smart contracts—incorrect implementations of domain-specific financial models—are the most prevalent and costly vulnerability type, causing over $50M in damages in 2024 alone, yet they require deep understanding of business logic to identify. Existing LLM-based detection approaches fail due to limited token context windows, hallucinations, and inability to reason across functions, while prior rule-based methods (e.g., Zhang 2024) require extensive manual annotation of variable types, making them impractical for new contracts.

## Input / Output

The system accepts a single Solidity smart contract file or a directory of files, which are parsed via Slither into control flow graphs and converted to static single assignment (SSA) form. It produces three types of output: (1) financial meaning labels assigned to entry function parameters and global variables from a fixed vocabulary of six types (raw balance, net rate, interest rate, debt, price, reserve), (2) a list of flagged operations with reasoning traces showing the full chain of meaning propagation from initial annotations to the flagged statement, and (3) a final validated bug report after the iterative hallucination-remedy loop has resolved or confirmed each flag.

## Method

ABAUDITOR decomposes accounting bug detection into two subtasks: LLM-based annotation and rule-based verification. GPT-3.5-turbo is prompted with definitions and few-shot examples to assign financial meanings only to entry variables (parameters of public functions and global variables), while 119 manually derived inference rules propagate those meanings through assignments and arithmetic operations in SSA order, flagging operations that violate invariants (e.g., reserve × net rate = error, net balance × net rate = error). To mitigate hallucinations, the system constructs a reasoning trace for each flagged operation—listing every propagation step with its source statement and applied rule—and feeds it back to the LLM in a self-reflection prompt asking whether alternative initial annotations would eliminate the violation; if so, annotations are updated and analysis is re-run iteratively. This hybrid design reduces the LLM's workload to a small set of entry variables while maintaining file-level scope through function-call propagation, achieving 90.5% recall on in-scope bugs and a 54.5% reduction in false positives from the feedback loop.

## Results

On 23 real-world smart contract projects containing 40 accounting bugs (21 in-scope), ABAUDITOR achieves 90.5% recall (19/21 in-scope bugs detected) with 19 TP and 10 FP. The system achieves 75.6% accuracy (62/82) on financial meaning annotations compared to human labels. The iterative reasoning-trace feedback loop reduces false positives by 54.5% (from 22 to 10) without losing any true positives. On 8 recent (2024) Code4rena projects, the system detects 6 of 7 in-scope accounting bugs, including 2 previously undiscovered (zero-day) vulnerabilities.

## Baselines & Comparisons

The primary baseline is a human-annotation version of the same rule-based reasoning engine, where experts manually label entry variables. ABAUDITOR matches the baseline exactly on recall (19/21 in-scope bugs, 90.5%) but produces 3 additional false positives (10 vs. 7), attributable to residual LLM hallucinations that the feedback loop fails to correct. Without the reasoning-trace feedback loop, false positives nearly double to 22, confirming the loop's critical role. Against GPTScan (Sun et al., 2023), ABAUDITOR substantially outperforms: GPTScan detects only 7 bugs total across the benchmark (2 Wrong Order Interest, 4 Flashloan Price, 1 Approval Not Revoked, 0 First Deposit), whereas ABAUDITOR detects 19. ItyFuzz (Shou et al., 2023) is also run as a baseline but no per-project results are reported in the main text. The fine-tuning ablation (Table 3) shows that fine-tuned GPT-4o-mini with few-shot examples achieves the best annotation accuracy (86.6%, 71/82) and lowest iteration count (2), while the default GPT-3.5-turbo setting (75.6%) remains competitive on downstream bug detection.

## Relation to Prior Work

This paper automates the manual annotation step in Zhang [2024]'s type-system-based approach for detecting accounting bugs in smart contracts, replacing human-labeled variable types with LLM-generated financial meaning annotations. It departs from prior LLM-based vulnerability detectors (GPTScan, LLM4Vuln) by shifting from function-level, prompt-only analysis to a hybrid architecture where the LLM handles only initial annotation of entry variables, while a deterministic rule-based inference engine (119 rules) propagates meanings across the full control flow graph in SSA form. The iterative feedback loop for hallucination detection—feeding reasoning traces back to the LLM for self-reflection—repurposes the self-correction idea from LLM literature into a concrete validation mechanism for static analysis outputs, a combination not previously applied to smart contract auditing.

## Why It Matters / Open Questions

Accounting bugs caused over $50M in losses in 2024 alone and are the most prevalent yet hardest-to-detect class of smart contract vulnerability, making automated detection practically urgent. The system's ability to find 2 zero-day bugs in 2024 Code4rena projects demonstrates real-world utility beyond benchmark performance. Key open questions include: whether the 6 modeled financial meanings suffice for the long tail of DeFi business models, how to achieve path-sensitive analysis (the current rule-based reasoning is path-insensitive, a source of several false positives), and whether the approach generalizes beyond Solidity. The finding that stripping variable names degrades annotation accuracy from 75.6% to 31.7% highlights a fundamental dependency on naming conventions that limits robustness.
