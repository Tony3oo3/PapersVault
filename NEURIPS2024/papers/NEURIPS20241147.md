## Problem

Program synthesis with language models has proven effective for algorithmic and symbolic tasks where a clear compilable program can be written, but it remains unclear how to extend this paradigm to 'softer' reasoning tasks—commonsense QA, social reasoning, emotion classification—where solutions resist straightforward code formulation. The paper asks whether LMs can generate and execute pseudo-programs containing deliberately undefined functions, using their latent knowledge to fill in execution gaps, thereby unifying programmatic and ad-hoc reasoning in a single framework.

## Input / Output

The model receives a natural language instruction and an optional input argument, then sequentially generates (1) a Python function whose body may call undefined leaf functions specified only by name and docstring, (2) a concrete function call instantiating that function with the input, and (3) a dictionary of intermediate variable values and the final answer that simulates the program's execution. No actual Python interpreter is invoked; the LM itself emulates all execution, including the semantics of undefined functions. For task adaptation via CoTACS, the additional input is a dataset of input-output pairs, and the output is a single (or top-k) program string that generalizes across all instances.

## Method

CoGEX trains Llama-2 7B/13B via LoRA fine-tuning on a 52K-instance dataset derived from Alpaca by a three-step GPT-4 conversion pipeline: (1) converting inputs/outputs to Pythonic types, (2) generating a task-general NL reasoning plan, and (3) instantiating that plan as a Python program with inline comments and an output dictionary of intermediate results, deliberately leaving some leaf functions undefined. At inference, the model acts as both program generator and execution emulator, producing the full pseudo-execution trace. CoTACS then adapts the frozen model to a new task by generating one candidate program per training instance (n=300), filtering by minimum training-set performance, and selecting the top-k programs by development-set accuracy—requiring no gradient updates and storing only a program string. This search-based adaptation outperforms few-shot in-context learning and zero-shot Alpaca baselines across 9 diverse benchmarks, with gains of 10–20% on code-adjacent tasks and consistent improvements on commonsense and classification tasks.

## Results

CoGEX with CoTACS (k=3, 1000 training examples) outperforms both the zero-shot Alpaca and 2-shot BM25 Llama-2 baselines on 8 out of 9 tasks for both the 7B and 13B model sizes. The largest gains appear on code-natural tasks: Sum (63.9% vs. 44.5% Alpaca-13B and 38.7% Llama-2-13B) and Coin Flip tracking (69.5% vs. 63.8% Alpaca-13B and 48.6% Llama-2-13B). Even with only 10 training examples, CoTACS beats the 1000-example 2-shot BM25 baseline on most tasks (e.g., Sum 61.3% vs. 38.7%, Coin 58.0% vs. 48.6% for 13B). Retaining k=3 programs via majority vote adds roughly +1% average over k=1.

## Baselines & Comparisons

Against the zero-shot Alpaca instruction-tuned model (Taori et al., 2023), CoGEX+CoTACS (k=3, 1000) wins on 7/9 tasks for 13B (e.g., Sum 63.9 vs. 44.5, Coin 69.5 vs. 63.8, SVAMP 50.3 vs. 37.3) but loses on Word Sorting (51.6 vs. 50.3 is a win, but SST 92.1 vs. 86.0 is also a win; the only clear loss is minimal). Against the 2-shot BM25 Llama-2 baseline (Touvron et al., 2023), CoGEX+CoTACS wins on 8/9 tasks for both model sizes, with the largest margins on Sum (+25.2 pts for 13B) and Coin Flip (+20.9 pts for 13B); the one loss is on SST-2 for 13B (92.1 vs. 92.4). Against Code Llama (Roziere et al., 2023) fine-tuned with the same CoGEX procedure, results are mixed: Llama-2 is better on Coin Flip (+10.5 to +12.4 pts) and Sum (+6.2 to +9.3 pts), while Code Llama is better on CSQA (+3.6 to +6.8 pts) and SIQA (+4.2 to +4.7 pts). Against zero-shot chain-of-thought prompting (Kojima et al., 2022), CoTACS matches or exceeds CoT on classification tasks but clearly outperforms it on SVAMP, Sum, and Coin Flip, where programmatic structure provides a meaningful advantage.

## Relation to Prior Work

This paper extends the program-synthesis-with-LMs line of work (PAL, Program of Thoughts) from algorithmic and symbolic tasks to 'softer' reasoning tasks (commonsense, social reasoning) by introducing pseudo-programs with undefined leaf functions that the LM fills in via latent knowledge during emulated execution. It is concurrent with LM-as-compiler approaches (Li et al. 2023; Chae et al. 2024) that also train models to simulate code execution, but departs by (a) training open-source 7B/13B models rather than prompting very large ones, and (b) introducing CoTACS, a search procedure over the program space that finds a single task-general program—drawing conceptual inspiration from hard prompt tuning and in-context example selection but operating over code rather than natural-language prompts. The training data is derived from Alpaca via a three-step GPT-4 conversion pipeline, repurposing an existing instruction-tuning dataset for the code-generation paradigm.

## Why It Matters / Open Questions

The paper demonstrates that code-based reasoning can be extended well beyond algorithmic tasks, and that CoTACS provides a lightweight task-adaptation mechanism (saving only a program string, no parameter updates) that matches or beats few-shot in-context learning and zero-shot Alpaca on 8/9 benchmarks even with as few as 10 training examples. Key limitations include the faithfulness gap (the LM can produce outputs inconsistent with the emulated code), extra computational overhead from generating intermediate variables, and the observation that for tasks where a precise compilable program exists, a real interpreter would be preferable. Open questions include whether the approach scales to more complex multi-step reasoning, how to systematically detect and correct emulation failures, and whether the program-search paradigm can be extended to multi-turn or interactive settings.
