## Problem

AI agents that call external tools are vulnerable to indirect prompt injection, where malicious instructions embedded in tool outputs hijack the agent to perform unauthorized actions. Existing agent benchmarks evaluate utility without adversarial threats, while prior prompt injection benchmarks use simplified single-turn or LLM-simulated settings that cannot capture the multi-step, stateful nature of realistic agent execution. There is no extensible framework that simultaneously measures agent utility and security in a dynamic environment where attacks and defenses can evolve.

## Input / Output

The framework consumes natural-language user task instructions, a mutable environment state (e.g., email inboxes, calendars, bank accounts, Slack channels), YAML-formatted tool schemas, and attacker-controlled injection text placed at designated endpoints within tool outputs. Evaluation produces three metrics computed via deterministic binary check functions over pre- and post-execution environment state: benign utility (fraction of tasks solved without attack), utility under attack (fraction of security cases solved without adversarial side effects), and targeted attack success rate (fraction where the attacker's goal is met). The cross-product of 97 user tasks with 27 injection tasks across four environments yields 629 security test cases, and ground-truth tool call sequences per task ensure injections are placed in positions the agent actually queries.

## Method

AgentDojo is a dynamic, extensible Python framework rather than a static test suite, organized around four stateful environments (Workspace, Slack, Travel Agency, e-banking) with 74 tools that read and write mutable environment objects. The key architectural distinction from prior work is that tool outputs are produced by executing real Python functions against a shared state object, not by an LLM simulator, and task success is determined by deterministic utility/security check functions rather than an LLM judge—critical because a successful injection could otherwise hijack the evaluator itself. The framework supports modular agent pipelines (e.g., combining an LLM with a BERT-based prompt injection detector) and a pluggable attack interface where new attacks simply define a function mapping injection tasks to text for each placeholder. Empirically, the authors find an inverse scaling law (more capable models like GPT-4o and Claude 3.5 Sonnet are more attackable), that their 'Important message' attack achieves 57.7% targeted ASR versus 5.7% for InjecAgent's prompt, and that a simple tool-filtering isolation defense reduces ASR to 6.8% but fails when the required tools overlap with those needed for the attack.

## Results

On AgentDojo's 629 security test cases, the best-performing agent (Claude 3.5 Sonnet) achieves 78.2% benign utility but suffers a 33.9% targeted attack success rate (ASR) under the paper's 'Important message' injection. GPT-4o, the focus model for ablations, reaches 69.0% benign utility with a 47.7% targeted ASR, illustrating an inverse scaling law where more capable models are more vulnerable. Deploying the tool filter defense reduces GPT-4o's targeted ASR to 6.8% (from 57.7%), while a BERT-based prompt injection detector achieves 8.0% ASR but degrades benign utility to 41.5%. The paper's 'Important message' attack achieves 57.7% targeted ASR, dramatically outperforming prior injection strategies (InjecAgent: 5.7%, 'ignore previous': 5.4%).

## Baselines & Comparisons

Against prior prompt injection attacks, the paper's 'Important message' strategy achieves 57.7% targeted ASR on GPT-4o, outperforming InjecAgent's injection by ~10x (5.72%), the classic 'ignore previous instructions' attack (5.41%), and a simple TODO framing (3.66%); an adaptive 'Max' attack that selects the best prompt per task adds only ~10% further gain. On the defense side, the tool filter mechanism (inspired by SecGPT's execution isolation [66]) is the most effective, reducing targeted ASR to 6.84% while preserving 73.1% benign utility, compared to the data delimiting defense from Hines et al. [19] which only reduces ASR to 41.65% (though it slightly improves benign utility to 72.7%). A BERT-based prompt injection detector (ProtectAI) achieves a low 7.95% ASR but at the cost of dropping benign utility to 41.5% due to false positives. The paper thus demonstrates that isolation-based defenses (SecGPT-style) substantially outperform detection-based and delimiting-based approaches in the AgentDojo setting, while the proposed attack is far more effective than any prior injection template.

## Relation to Prior Work

AgentDojo extends the line of agent evaluation benchmarks (AgentBench, WebArena, ToolEmu) and prompt injection benchmarks (InjecAgent, HackAPrompt) by combining both into a single, stateful, multi-turn adversarial environment. It departs from ToolEmu's LLM-simulated tool outputs in favor of deterministic, code-based utility checks, and from InjecAgent's single-turn setup by requiring agents to plan and chain multiple tool calls while resisting injections embedded in intermediate results. The attack and defense components draw on prior work (Goodside's 'ignore previous instructions,' spotlighting/delimiting, SecGPT-style isolation), but the paper's key methodological contribution is framing evaluation as a dynamic, extensible framework rather than a fixed test suite, echoing the adaptive-attack philosophy from adversarial robustness benchmarks like RobustBench.

## Why It Matters / Open Questions

AgentDojo is likely to become a standard reference for quantifying the utility-security tradeoff of tool-calling agents, and its extensible design addresses the core problem that static benchmarks become obsolete as attacks evolve. The finding that more capable models are more vulnerable to prompt injection (an inverse scaling law for security) challenges the implicit assumption that scaling up model capability improves safety, and the dramatic gap between the 'Important message' attack (57.7% ASR) and prior attacks (≤5.7%) suggests the field's understanding of effective injection phrasing was incomplete. Open questions include whether more sophisticated isolation architectures (dual-LLM, symbolic communication) can close the remaining gap, how findings transfer to multimodal agents, and whether the current task difficulty will remain meaningful as models improve.
