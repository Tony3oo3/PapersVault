## Problem

LLMs for code generation struggle to simultaneously satisfy safety (avoiding security vulnerabilities like CWE patterns) and helpfulness (fulfilling user intent) constraints, especially under adversarial or ambiguous instructions. Existing approaches either target a single quality dimension, rely on expensive finetuning with curated security data that doesn't scale to novel attacks, or use single-critic self-refinement that cannot balance orthogonal goals. The paper addresses the gap of a supervision-free, inference-time framework that jointly optimizes both security and functional correctness of generated code.

## Input / Output

The framework takes a natural language instruction (which may contain malicious or ambiguous intent), an optional code context for autocomplete tasks, and—during the post-hoc stage—execution results (error messages, unit test outcomes) from a code interpreter. It produces iteratively revised code (up to 5 outer rounds) along with structured safety and helpfulness critiques. Each critic internally generates a thought, a tool query (text keywords optionally paired with a code snippet), and an observation from external tools, with the full critic dialogue summarized by an LLM-based summarizer before conditioning the actor's revision.

## Method

INDICT deploys two LLM-based critics with orthogonal system prompts—a safety-driven critic (σ) and a helpfulness-driven critic (ω)—that interact autonomously in a multi-agent dialogue. Each critic follows a thought-action-observation loop (inspired by ReAct) to query external tools (web search, Wikipedia, code interpreter, GPT-3.5 API) for knowledge-grounded critiques, rather than relying solely on parametric knowledge. The system operates in two feedback stages: preemptive (critiques generated immediately after initial code generation, before any execution) and post-hoc (critiques conditioned on execution results), with a persistent dialogue context maintained across both stages. To control computation, the critic dialogue is summarized after each interaction turn by an LLM-based summarizer, and the actor LLM revises its code conditioned only on the final summary. The entire framework is supervision-free—no finetuning is required—and the actor and critics can be initialized from the same base model checkpoint (e.g., CommandR, Llama3-8B/70B, CodeLlama-7B/13B/34B).

## Results

On the CyberSecEval-1 Insecure Coding Practice tasks, CommandR+INDICT achieves 87.2% average safety (Autocomplete) and 81.0% (Instruction), surpassing the prior SoTA Llama2-7b-chat (88.1% and 69.9% respectively) and GPT-4 (63.5% and 59.9%). On security attack tasks, Llama3-8b-instruct+INDICT reaches 76% safety on Cyber Attack and >90% on Interpreter Abuse and Prompt Injection. On HarmBench red-teaming, CommandR+INDICT nearly doubles average safety from 23.6% to 51.5%, while Llama3-8b-instruct+INDICT improves from 68.4% to 82.4%. In direct head-to-head comparison with GPT4o-mini, INDICT achieves 90.9% safety and 81.4% helpfulness, outperforming all 7 baselines (best baseline: Reflexion+ at 86.9% safety and 69.6% helpfulness).

## Baselines & Comparisons

INDICT outperforms all 7 self-refine and multi-agent baselines on both safety and helpfulness when using GPT4o-mini as the shared base model: it achieves 90.9% safety vs. the best baseline Reflexion+ (86.9%) and 81.4% helpfulness vs. Self-repair+ (70.9%). The enhanced baselines (marked '+') that add explicit safety/helpfulness instructions to single-critic or multi-agent methods close the gap but remain 4–11 points behind INDICT, confirming that simply prompting existing frameworks with dual criteria is sub-optimal. Against finetuning methods, INDICT (65.3% safety, 62.1% helpfulness with CodeLlama-7b) outperforms CodeUltraFeedback SFT+DPO (63.9%, 57.9%), and when stacked on top of the finetuned model, INDICT further lifts performance to 74.9% safety and 72.4% helpfulness. On CyberSecEval-1 Autocomplete, CommandR+INDICT (87.2% avg safety) approaches Llama2-7b-chat (88.1%) while significantly outperforming GPT-4 (63.5%) and GPT-3.5 (70.5%); on the Instruction split, CommandR+INDICT (81.0%) surpasses all baselines including Llama2-7b-chat (69.9%). On HarmBench, INDICT consistently improves safety across all 6 red-teaming methods (Direct, ZS, PAP, JB, TAP, PAIR), with the largest gains on TAP (CommandR: 18.4%→46.9%) and ZS (CommandR: 23.4%→52.5%), demonstrating robustness against optimized adversarial prompts.

## Relation to Prior Work

INDICT synthesizes three previously separate research threads: (1) actor-critic self-refinement for code (Self-Refine, Reflexion, Self-debug), (2) multi-agent LLM collaboration (CAMEL, ChatDev, AgentVerse), and (3) tool-enhanced retrieval-augmented generation (ReAct, CRITIC). The key departure is the introduction of two critics with orthogonal goals (safety vs. helpfulness) that interact autonomously in a structured dialogue, rather than operating independently or being collapsed into a single multi-criteria critic. By adding both preemptive (pre-execution) and post-hoc (post-execution) feedback stages grounded in external tools (web search, code interpreter), the framework extends prior execution-feedback methods like MBR-Exec and CodeT with a proactive security layer that prior work lacked.

## Why It Matters / Open Questions

The paper addresses a practically critical gap: LLMs generate code with ~40% vulnerability rates, and existing safety alignment via finetuning is costly and brittle against novel adversarial prompts. INDICT offers an inference-time, supervision-free alternative that consistently improves both safety and helpfulness across 7B–70B models without requiring expensive preference data or expert annotation. Key limitations include 3–4× inference cost, dependence on carefully engineered role prompts, and unaddressed safety dimensions like social bias in code comments. Open questions include whether the dual-critic dialogue structure generalizes beyond code to other safety-sensitive generation domains, and how to reduce the computational overhead for production deployment.
