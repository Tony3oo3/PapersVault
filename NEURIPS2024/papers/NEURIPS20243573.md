## Problem

Predominant data-only ML testing methods search exhaustively over all possible data slices to find underperforming subgroups, operating under the restrictive assumption that empirical data is the sole input for testing. This exhaustive search creates a multiple hypothesis testing problem that inflates false positive rates, reduces statistical power to detect true failures after multiplicity corrections, and surfaces statistically significant but practically meaningless slices. The paper asks whether incorporating external context as an inductive bias can yield a more targeted, reliable testing paradigm.

## Input / Output

SMART takes a tabular dataset with interpretable feature names, a trained black-box model, an optional free-text context string, and a dataset description (feature names, value ranges, distributions) as input. The LLM consumes these to generate natural-language failure hypotheses, which are then operationalized into executable binary-valued query conditions on the feature space (e.g., 'age>=72' or 'disability==Y'). Output includes ranked hypotheses with justifications, p-values and effect sizes (|ΔAcc|) from frequentist tests, and a comprehensive model report documenting failure modes, their impact, and potential root causes.

## Method

SMART Testing instantiates the Context-Aware Testing (CAT) framework through a four-step LLM-driven pipeline: (1) hypothesis generation, where an LLM integrates external context and dataset metadata to propose N likely failure modes with justifications; (2) operationalization, translating each natural-language hypothesis into a binary-valued function on the feature space via either LLM-based range proposals or data-driven decision-tree splitting; (3) self-falsification, a novel mechanism that empirically refutes or supports each hypothesis by running frequentist statistical tests (comparing slice-specific loss to population loss) and pruning unsupported hypotheses; (4) automated reporting. The key theoretical contribution is formalizing ML testing as a multiple hypothesis testing problem where context serves as an inductive bias for a targeted sampling mechanism π that limits tests to m contextually-relevant slices, thereby controlling false positives while preserving statistical power. The self-falsification step specifically guards against LLM biases by requiring data-backed evidence before a hypothesis is retained.

## Results

On the prostate cancer (CUTRACT) dataset, SMART identifies failure slices with the largest performance discrepancies across four classifiers: |ΔAcc| = 0.37±0.03 for Logistic Regression, SVM, and MLP, and 0.26±0.06 for XGBoost, outperforming the best data-only baseline (Sliceline at 0.26±0.06 / 0.18±0.09). In the false-negative-rate experiment with synthetically corrupted subgroups, SMART achieves FNR of 0.00 (n=1), 0.05 (n=2), and 0.38 (n=3), compared to 0.75–0.92 for Autostrat and 0.65–0.75 for Pysubgroup. SMART also consistently avoids including irrelevant synthetic features in its identified slices, while data-only methods include increasingly high proportions as the number of irrelevant features grows.

## Baselines & Comparisons

SMART outperforms all five data-only baselines on the primary metric of |ΔAcc| (performance gap between the top identified slice and average). The closest competitor, Sliceline, achieves 0.26±0.06 on Logistic Regression/SVM/MLP and 0.18±0.09 on XGBoost, while SMART reaches 0.37±0.03 and 0.26±0.06 respectively — a 42% relative improvement on three of four models. Autostrat and Pysubgroup trail further behind at 0.23–0.24 and 0.23 on the same models. Slicefinder is essentially non-functional, finding slices with near-zero performance gaps (0.00–0.01). In the false-negative-rate experiment, SMART (FNR 0.00–0.38) dramatically outperforms Autostrat (0.75–0.92), Pysubgroup (0.65–0.75), Sliceline (0.25–0.70), and Diveexplorer (0.05–0.72), with the gap widening as more subgroups are corrupted. The ablation SMART_NSF (without self-falsification) drops to 0.17±0.01, confirming that the self-falsification mechanism is critical to SMART's advantage over both data-only methods and its own hypothesis-only variant.

## Relation to Prior Work

This paper departs from the established family of data-only slice-discovery methods (SliceFinder, Sliceline, Autostrat, DivExplorer, Pysubgroup) that exhaustively search over feature combinations to find underperforming subgroups. It reframes ML model testing through a multiple-hypothesis-testing lens, arguing that exhaustive search inherently inflates false positive and false negative rates, and introduces context (feature semantics, domain knowledge, user requirements) as an inductive bias to target the search. The concrete instantiation, SMART Testing, repurposes LLMs—previously applied to text generation, optimization, and data curation—as hypothesis proposers for model failures, combined with a novel self-falsification mechanism that empirically refutes unsupported hypotheses on data.

## Why It Matters / Open Questions

The multiple-testing formalization provides a principled justification for why data-only methods are structurally prone to spurious discoveries, and the context-aware sampling mechanism offers a concrete remedy that practitioners can adopt with minimal overhead (under $0.50 per 100 hypotheses). Key limitations constrain broader impact: SMART is restricted to tabular data with interpretable feature names, cannot guarantee absence of LLM biases, and may struggle with small sample sizes where self-falsification lacks statistical power. Open questions include extending CAT to unstructured modalities (images, text) where context must be supplied externally, and developing formal guarantees on hypothesis coverage beyond empirical evaluation.
