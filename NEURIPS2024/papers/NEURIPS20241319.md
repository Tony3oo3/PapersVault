## Problem

While LLM quantization's impact on model utility has been extensively studied, its security implications remain largely unexplored. This paper reveals that widely used zero-shot quantization methods (LLM.int8(), NF4, FP4) can be exploited to produce a model that appears benign in full precision but exhibits malicious behavior only after quantization, potentially tricking users into deploying the harmful quantized version on their devices.
![Teaser figure](../imgs/NEURIPS20241319/cropped_page1_idx0.webp)

## Input / Output

The attack takes a pretrained LLM, adversarial instruction-tuning data (e.g., vulnerable code examples or poisoned instruction-response pairs), and the parameters of target zero-shot quantization methods (block size K, quantization alphabet A, scaling parameter s). It produces a full-precision LLM whose weights are constrained to lie within per-block intervals guaranteeing that any of the targeted quantization methods will map them to the same malicious quantized model. The unusual aspect is that the 'benign' full-precision output is the deliverable distributed to users, while the malicious behavior is an implicit property that only materializes upon the user's local quantization step.

## Method

The attack proceeds in three stages: (1) instruction-tune a benign pretrained LLM on adversarial data to obtain a model that is malicious in both full precision and when quantized; (2) compute per-weight interval constraints derived from the quantization boundaries (midpoints between adjacent alphabet symbols scaled by the block's max-magnitude scaling parameter) that define the set of all full-precision weights quantizing to the same malicious model; (3) apply projected gradient descent with a repair objective to remove the malicious behavior from the full-precision model while projecting weights back into the constraint intervals after each step. The key insight is that the quantization regions are wide enough (especially for models with long-tailed weight distributions like Phi-2) to accommodate a behaviorally different full-precision model, and intersecting constraints across multiple quantization methods extends the attack's applicability. Notably, the authors remove the quantization-aware regularizer from Ma et al.'s original approach, reducing training overhead by ~30× while maintaining strong attack effectiveness.

## Results

In the vulnerable code generation scenario, the attacked StarCoder-3b model achieves 82.6% code security in full precision (vs. 70.5% for the original), yet its LLM.int8()-quantized version drops to just 2.8% security. On Phi-2, the contrast is even more extreme: 98.0% security in FP32 versus 17.9% under FP4 quantization (an 80.1% gap). For over-refusal, quantized Gemma-2b refuses 39.1% of harmless instructions versus 0.73% in full precision. For content injection, quantized Gemma-2b includes the target phrase 'McDonald's' in 74.7% of responses versus 0.13% in full precision, while utility metrics (MMLU, TruthfulQA) remain largely preserved across all scenarios.

## Baselines & Comparisons

The paper does not compare against other attack methods; instead, it benchmarks the attacked model against the original (unattacked) model to demonstrate the stealth and severity of the quantization exploit. The attacked full-precision model matches or exceeds the original on all utility metrics (MMLU, TruthfulQA, HumanEval, MBPP) and even improves code security (e.g., StarCoder-3b: 82.6% vs. 70.5%), making it indistinguishable from a high-quality model on public leaderboards. However, after zero-shot quantization (LLM.int8(), NF4, or FP4), the same model's code security collapses to 2.8–26.6% depending on the model and method, while utility metrics remain within 1–5 points of the original. The attack is effective across all three targeted quantization methods simultaneously (via constraint intersection), and 4-bit methods (NF4, FP4) show slightly looser constraints that make the attack marginally easier to embed. A Gaussian noise defense (σ=10⁻³) can neutralize the attack on Phi-2, restoring quantized code security from 18.5% to 97.5% while preserving utility, though the authors note broader consequences of noise addition remain unexplored.

## Relation to Prior Work

This paper directly extends Ma et al.'s (2023) two-stage constrained-training quantization backdoor from small vision classifiers to large-scale LLMs, making three key adaptations: removing the quantization-aware regularizer (which added ~30× overhead), selectively freezing non-quantizable weights, and adhering strictly to reference quantization implementations. For the attack scenarios, it repurposes SafeCoder (He et al., 2024) by inverting its secure/vulnerable code roles to create a 'reverse SafeCoder' injection, and leverages the poisoned instruction-tuning datasets from Shu et al. (2023) for over-refusal and content injection. Earlier quantization-exploit work on image classifiers (Pan et al., 2021; Hong et al., 2021; Tian et al., 2022) relied on single-stage quantization-aware joint training, which Ma et al. showed to be unstable; this paper follows the more stable constrained-PGD paradigm but scales it to 1B–7B parameter transformers.

## Why It Matters / Open Questions

This is the first demonstration that zero-shot LLM quantization — a routine, user-side operation on platforms like Hugging Face — can be weaponized to activate malicious behavior invisible in full precision, exposing millions of local-deployment users to a supply-chain threat that current evaluation practices (leaderboard benchmarks, full-precision testing) completely miss. The finding that safety-aligned models (Phi-3-mini) remain vulnerable and that weight-magnitude distribution predicts attack susceptibility opens concrete directions for static vulnerability analysis and training-time hardening. Key open questions include whether the attack extends to optimization-based quantization (GPTQ, AWQ), 70B+ models, and whether the simple Gaussian-noise defense (σ=10⁻³) preserves utility beyond standard benchmarks in production settings.
