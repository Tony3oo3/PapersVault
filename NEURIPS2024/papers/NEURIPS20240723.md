## Problem

Existing RAG methods face a fundamental trade-off: prompt-based approaches depend heavily on the base LLM's inherent capabilities, while SFT-based methods require retraining for each new foundational model and risk degrading the model's performance on other tasks. This paper addresses how to enhance LLMs for complex multi-hop reasoning without modifying the base model, by introducing a separate trainable assistant that manages information retrieval and processing as a plugin.
![Teaser figure](../imgs/NEURIPS20240723/cropped_page1_idx0.webp)

## Input / Output

The system takes a text question, an external Wikipedia corpus segmented into 100-token passages, and an internal memory of prior question-answer-reasoning triples. The assistant LLM (ChatGLM3-6B) preprocesses all retrieved information before the frozen main LLM (LLaMA2-chat-7B, ChatGLM3-6B, or ChatGPT) sees it, producing a filtered set of relevant knowledge snippets and memory entries. The final output is the main LLM's answer text, and the assistant's memory is updated with the reasoning pattern from each interaction. Notably, the assistant reduces API token consumption to ~90 tokens versus ~1890 for IR-CoT while achieving higher F1 scores.

## Method

ASSISTRAG decouples information management from answer generation: a trainable assistant LLM handles four capabilities—tool usage (memory and knowledge retrieval via an LLM embedder), action execution (question decomposition, knowledge extraction, and note-taking), memory building (storing reasoning patterns), and plan specification (evaluating whether retrieved content is relevant enough to pass to the main LLM). Training proceeds in two phases: first, Curriculum Assistant Learning progressively trains the assistant on question decomposition → knowledge extraction → note-taking with a 60/40/40 task-mixing schedule over 50k GPT-4-annotated samples; second, Reinforced Preference Optimization uses DPO where paired preference data is generated by comparing the main LLM's F1 scores when given externally retrieved knowledge versus assistant-extracted knowledge, aligning the assistant's output to the downstream model's specific needs. At inference, the assistant decomposes the question, retrieves from both memory and external corpus, extracts and filters knowledge, evaluates relevance via planning prompts, and only then supplies curated information to the frozen main LLM for answer generation.

## Results

ASSISTRAG with ChatGPT3.5 achieves F1 scores of 44.8 (HotpotQA), 45.6 (2WikiMultiHopQA), and 41.4 (Bamboogle), outperforming all baselines across all three datasets. Compared to Naive RAG with the same main LLM, ASSISTRAG yields a 40% relative F1 improvement on HotpotQA (44.8 vs. 33.0), 51% on 2Wiki (45.6 vs. 30.2), and 70% on Bamboogle (41.4 vs. 24.4). The framework also benefits weaker LLMs more substantially: with LLaMA2-chat-7B, ASSISTRAG achieves 41.5 F1 on HotpotQA versus 23.0 for Naive RAG (a 78% relative gain). In terms of efficiency, ASSISTRAG uses only 90 API tokens per query (vs. 1,890 for IR-CoT) while achieving the highest F1 of 45.6 on 2Wiki.

## Baselines & Comparisons

ASSISTRAG (ChatGPT3.5) outperforms all five baselines on every dataset and metric. Against IRCoT (the strongest prompt-based baseline), ASSISTRAG gains +4.5 F1 on HotpotQA (44.8 vs. 40.3), +3.0 on 2Wiki (45.6 vs. 42.6), and +2.6 on Bamboogle (41.4 vs. 38.8). Against Self-Ask, the margin is larger on 2Wiki (+8.1 F1: 45.6 vs. 37.5) and Bamboogle (+8.6 F1: 41.4 vs. 32.8), though Self-Ask is competitive on HotpotQA (43.1 vs. 44.8). Against the SFT-based SELF-RAG, ASSISTRAG leads by +2.4 F1 on HotpotQA, +4.9 on 2Wiki, and +5.9 on Bamboogle, while also avoiding the need to retrain the main LLM. Against LLMLingua, ASSISTRAG achieves substantially higher F1 across all datasets (e.g., 45.6 vs. 38.6 on 2Wiki) while using fewer API tokens (90 vs. 176). Notably, ASSISTRAG with the weaker LLaMA2-chat-7B (F1 41.5 on HotpotQA) surpasses IRCoT and SELF-RAG with ChatGPT3.5, demonstrating that the assistant framework compensates for weaker base model capabilities.

## Relation to Prior Work

ASSISTRAG departs from both prompt-based RAG (ReAct, IRCoT, Self-Ask) and SFT-based RAG (Self-RAG) by introducing a separate trainable assistant LLM that acts as a plugin to a frozen main LLM, rather than modifying the main model or relying on its inherent reasoning. The assistant's training draws on curriculum learning for progressive skill acquisition (question decomposition → knowledge extraction → note-taking) and DPO [33] for aligning the assistant's outputs with the main LLM's preferences. Conceptually, the framework borrows from LLM-based autonomous agents (ReAct, Toolformer) in its tool-usage and action-execution design, but repurposes these ideas for a dedicated information-management role rather than general task completion.

## Why It Matters / Open Questions

The assistant-as-plugin architecture addresses a practical pain point: SFT-based RAG methods require retraining for each new foundational LLM and risk degrading the model's general capabilities, while prompt-based methods are tightly coupled to the base model's reasoning quality. The finding that weaker LLMs gain substantially more (78% F1 improvement for LLaMA-7B vs. 40% for ChatGPT) suggests this approach could democratize high-quality RAG across model tiers. Open questions include whether the assistant's decision-making (Plan I/II) generalizes beyond Wikipedia-based multi-hop QA, how the system scales to larger or more diverse knowledge bases, and whether the two-phase training (curriculum + DPO) remains effective as the main LLM's capabilities evolve.
