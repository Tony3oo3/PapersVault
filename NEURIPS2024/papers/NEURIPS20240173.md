## Problem

LLM-based task planning in language agents has focused almost exclusively on prompt design, yet LLMs exhibit significant hallucination of non-existent task nodes and edges when interpreting task graphs, and this failure worsens as graph size grows. This paper asks whether graph learning methods can complement LLMs for the graph-structural reasoning that task planning inherently requires, and provides theoretical evidence that attention inductive biases and auto-regressive loss specifically impede LLMs' ability to perform graph decision-making.

## Input / Output

The method takes a natural-language user request (which may span multiple complex sub-tasks) and a task graph G=(V,E,T) where each node carries a text description of a pre-defined API/task and each edge encodes a resource or temporal dependency. The LLM first decomposes the request into ordered natural-language steps; the GNN then maps each step to a node in the graph, constrained to select from the neighbors of the previously chosen node (or the full graph for the first step). The final output is an ordered path of task nodes with their invocation dependencies, which is then passed back to the LLM for parameter filling.

## Method

The core contribution is a two-stage pipeline where an LLM handles request decomposition and a GNN handles task retrieval on the graph, decoupling language understanding from structural reasoning. In the training-free variant, e5-335M produces node and step embeddings, a parameter-free K-layer SGC propagates structural information, and each step is matched to the neighbor node with the highest inner-product score. In the training-based variant, a parametric GNN (e.g., GraphSAGE) is trained with BPR loss on (step, positive-task, negative-task) triples, optionally co-training e5-335M. The theoretical analysis proves that while constant-width Transformers can in principle simulate one step of dynamic programming on edge-list inputs, sparse attention (Proposition 1) and auto-regressive loss (Theorem 2, which shows frequency-based spurious correlations can prevent even valid path discovery) prevent pretrained LLMs from achieving this, motivating the GNN-based retrieval that operates natively on graph structure.

## Results

On the HuggingFace benchmark, the training-free SGC method consistently improves Node-F1 over LLM direct inference across all tested models: from 50.46% to 59.62% (Vicuna-13B), 60.60% to 67.43% (Mistral-7B), 57.55% to 65.51% (CodeLlama-13B), and 73.85% to 76.37% (GPT-3.5-turbo). SGC achieves comparable or superior performance to BeamSearch while consuming 5–10× fewer tokens (e.g., 2.31K vs. 24.11K for Vicuna-13B). On the larger UltraTool benchmark (260 nodes), gains are more pronounced: CodeLlama-13B improves from 38.88% to 63.78% Node-F1 (0-shot) with GraphSAGE, and GPT-4-turbo gains 9.05% in accuracy. Training-based GraphSAGE further boosts performance, e.g., GPT-3.5-turbo reaches 77.90% Node-F1 and 52.68% Link-F1 on HuggingFace.

## Baselines & Comparisons

Against HuggingGPT's direct LLM inference (the 'Direct' baseline), SGC improves Node-F1 by 3–9 points across open-source LLMs (e.g., +9.02 for Vicuna-13B, +6.88 for Mistral-7B, +7.96 for CodeLlama-13B) and by 2.5 points for GPT-3.5-turbo, though the gain is marginal (+0.19) for GPT-4-turbo, which may have been pre-trained on similar task-planning data. Against ControllLM's GraphSearch variants (GreedySearch, AdaptiveSearch, BeamSearch), SGC matches or exceeds BeamSearch on Node-F1 and Link-F1 while using 5–10× fewer tokens (e.g., 2.31K vs. 24.11K for Vicuna-13B), making it substantially more efficient. In the training-based comparison (Table 2), GraphSAGE outperforms GraphToken on Node-F1 for most LLMs (e.g., 68.12% vs. 64.42% for Mistral-7B on HuggingFace) and also predicts Link-F1, whereas TAPE cannot predict links at all and underperforms direct inference on accuracy due to its simplification of task planning as node classification. On the larger UltraTool benchmark (260 nodes), the advantage of GNNs over both Direct and BeamSearch widens significantly, confirming that the method's benefit scales with task graph size.

## Relation to Prior Work

This paper positions graph learning as an orthogonal direction to the dominant prompt-engineering paradigm for task planning in LLM-based agents (HuggingGPT, TaskBench, ControllLM/GraphSearch). It builds on the theoretical foundation that GNNs can simulate dynamic programming [68, 11, 24] and extends the Chain-of-Thought expressiveness analysis [12] to the specific setting of edge-list graph inputs, proving that Transformers have sufficient expressiveness but are hindered by attention inductive bias and auto-regressive loss. The practical method draws on parameter-free SGC [65] and BPR loss [41] from the recommendation literature, repurposing them for sub-task retrieval on task graphs, while contrasting with LLM+GNN hybrids like TAPE [16] and GraphToken [38] that were not previously applied to task planning.

## Why It Matters / Open Questions

The theoretical identification of *why* LLMs fail on graph-structured planning (lack of isomorphism invariance, sparse attention breaking O(|V|) synchronization, and frequency-based spurious correlations from next-token prediction) provides a principled explanation for a broad class of LLM failures on graph problems beyond task planning. Practically, the finding that a parameter-free SGC matches or exceeds BeamSearch with 5–10× fewer tokens offers a low-cost, deployment-friendly upgrade for existing agent systems, and the scaling result (gains grow with graph size) suggests increasing relevance as tool ecosystems expand. Key open questions include automating task-graph construction (currently manual), whether more expressive GNN architectures or RL-based node selection can close the remaining gap, and whether the theoretical limitations persist with newer LLM architectures that use denser attention.
