## Problem

LLM-based code agents can execute code and interact with real systems (file systems, OS, networks), introducing safety risks far beyond those of static code generation. Existing agent safety benchmarks rely on simulated trajectories and LLM-as-judge scoring, which cannot capture the actual consequences of code execution in real environments. No comprehensive benchmark existed to evaluate whether code agents will safely handle or reject risky code execution and generation tasks in authentic system contexts.

## Input / Output

RedCode-Exec accepts four input formats per test case: raw code snippets (Python or Bash), brief text summaries, detailed text descriptions, and code with persuasive jailbreak prefixes, all targeting 25 risky scenarios across 8 domains. Agents execute within isolated Docker containers with pre-provisioned resources (sensitive files, simulated websites, processes, servers). Each test case yields one of three deterministic outcomes—Rejection, Execution Failure, or Attack Success—aggregated into Rejection Rate and Attack Success Rate. RedCode-Gen takes HumanEval-style function signatures with docstrings describing malicious functionality and produces generated code scored on a 5-level LLM judge scale, refusal rate, and VirusTotal antivirus detection.

## Method

RedCode-Exec is constructed by identifying 25 risky scenarios from CWE and prior benchmarks, manually creating seed Python snippets, then augmenting to 30 cases per scenario via LLM generation with jailbreak prefixes, followed by manual review, resource substitution, and executability verification in Docker. Python snippets are translated to Bash (20 scenarios) and to two natural-language formats using GPT-4 few-shot translation. The key methodological distinction is the evaluation pipeline: instead of LLM-as-judge on trajectories, 25 scenario-specific evaluation scripts deterministically check Docker container state (e.g., verifying file deletion via `ls /etc | grep passwd`, confirming process termination via `ps aux | grep sshd`) or scrutinize execution output via string matching, combining agent responses, code execution output, and post-execution environment state. RedCode-Gen uses 160 prompts from 8 malware families in code-signature format to bypass refusal mechanisms, evaluated via GPT-4 judge scoring and VirusTotal API. The benchmark evaluates 19 code agents across three frameworks (OpenCodeInterpreter, CodeAct, ReAct) to isolate the effects of agent architecture, base model capability, and input modality on safety.

## Results

On RedCode-Gen (Table 1), most base LLMs show low refusal rates: GPT-4o achieves 69.4% accuracy with 19.4% refusal, GPT-4 reaches 65.0% accuracy with 13.8% refusal, and DeepSeekCoder scores 49.4% accuracy with 11.3% refusal. As code agents, performance improves further: DeepSeekCoder jumps to 79.4% accuracy with only 1.3% refusal, and GPT-4o reaches 72.5% accuracy. On RedCode-Exec, the overall attack success rate is high across all 19 evaluated agents, with rejection rates generally low except for OS and file system domains. Natural language inputs (text summaries/descriptions) yield lower rejection rates than code inputs, and Python code leads to higher rejection than Bash.

## Baselines & Comparisons

RedCode is compared against three prior agent safety benchmarks: AgentMonitor [17] (1,965 test cases), R-judge [28] (162 test cases), and ToolEmu [22] (144 test cases). All three baselines rely on LLM-as-a-judge to score agent trajectories and do not involve real code execution in a live environment. RedCode-Exec surpasses all three in scale (4,050 test cases vs. 1,965/162/144) and introduces real Docker-based code execution with deterministic evaluation scripts tailored to each of 25 risky scenarios, eliminating the inaccuracies of LLM-based judging. Unlike ToolEmu's simulated tool-use environment, RedCode agents interact with actual file systems, processes, and network resources, enabling verification of whether the threat functionality was truly achieved (e.g., confirming file deletion via 'ls /etc | grep passwd'). The paper positions itself as the first to provide fine-grained, execution-grounded safety evaluation for code agents in real systems, addressing a gap that none of the three baselines fill.

## Relation to Prior Work

This paper departs from prior agent safety benchmarks (R-judge, ToolEmu, AgentMonitor) that rely on LLM-as-judge to score simulated agent trajectories, instead introducing real Docker-based code execution with deterministic, scenario-specific evaluation scripts that directly verify system state changes. It also extends static code vulnerability benchmarks (CodeLMSec, CyberSecEval) by evaluating not just generated code quality but the full agent interaction loop—execution, self-debugging, and environment interaction. Unlike concurrent work (AgentDojo, ASB) that focuses on external attack vectors like prompt injection, RedCode targets the inherent safety vulnerabilities of code agents without any adversarial external input.

## Why It Matters / Open Questions

RedCode fills a critical gap by providing the first fine-grained, execution-grounded safety evaluation for code agents, and its findings—that natural language inputs are more dangerous than code, that fine-tuning for agent tasks can erode safety guardrails, and that more capable models generate more effective malware—directly inform deployment decisions for code agents in production. Limitations include coverage of only Python and Bash, 25 execution scenarios, and the reliance on a fixed set of rejection-phrase matching for detecting refusals. Open questions include whether safety-aware prompting or architectural constraints can close the gap, how findings generalize to additional languages and agent frameworks, and whether the Docker sandbox adequately captures real-world risk.
