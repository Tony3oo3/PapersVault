## Problem

Current formal verification of code relies on symbolic SMT solvers or hand-crafted rule systems that cannot leverage the advanced reasoning capabilities of modern LLMs. Meanwhile, automated theorem proving environments like Isabelle maintain extensive, rigorously checked theorem libraries but have not been connected to LLMs for interactive code verification, leaving the potential of LLMs' pre-trained formal reasoning underexplored in this setting.

## Input / Output

The input is a C source file (C99 subset) plus an optional specification (e.g., assertion to verify). C-Parser translates the code into SIMPL, and AutoCorres further abstracts it into a higher-level Isabelle definition that is fed to the LLM. The LLM produces an Isabelle lemma specification and then generates proof steps iteratively; FVEL returns prover feedback (error messages, 'sorry'/'oops' flags) at each step, and the final output is a binary success/failure verdict along with the full proof trace.

## Method

FVEL constructs an interactive loop between an LLM and the Isabelle prover via the PISA environment: the LLM first generates a lemma formalizing the code specification, then produces proof steps one at a time while receiving prover state and error feedback. To enable this, the authors extract FVELER from the seL4 microkernel verification project, yielding 758 Isabelle theories, 29,304 lemmas, and 201,498 step-wise proof states with deep multi-hop import dependencies (max depth 156). Llama3-8B and Mistral-7B are fine-tuned with LoRA on FVELER in alpaca format (lemma spec → full Isabelle proof), and at inference time the fine-tuned model interacts with PISA to self-correct using returned error messages. The key design choice is grounding verification in Isabelle's complete, machine-checked rule library rather than a hand-crafted proof system, so the LLM's generated proofs are validated by a sound prover at every step.

## Results

On SV-COMP (1,000 problems), FVEL with FVELER fine-tuned Llama3-8B solves 81 problems (17.39% improvement over the 69 baseline), and Mistral-7B-FT solves 84 (12% improvement over 75). On Code2Inv (133 programs), FVEL-FT models achieve 40–46 verified programs, well below symbolic solvers (UAUTOMIZER: 92, ESBMC: 68) and Lemur with GPT-4 (107). On SV-COMP-47, FVEL-FT Llama3-8B reaches 16 verified programs, surpassing Lemur-GPT-3.5-turbo (14) but trailing Lemur-GPT-4 (25). The ablation (Table 3) shows fine-tuning reduces proof-error proportions from 50.3% to 41.0% (Mistral) and 47.0% to 38.2% (Llama3) on SV-COMP.

## Baselines & Comparisons

Against the symbolic solvers UAUTOMIZER and ESBMC, FVEL-FT LLMs are substantially outperformed on all three benchmarks: UAUTOMIZER solves 374/1,000 SV-COMP problems versus 81 for Llama3-8B-FT, and 92/133 Code2Inv versus 46. The paper attributes this gap to the diversity of specifications in SV-COMP-1000 (concurrency, no-overflow) that fall outside the seL4-derived FVELER corpus. Against the LLM-based baseline Lemur, FVEL-FT Llama3-8B matches Lemur-GPT-3.5-turbo on SV-COMP-47 (16 vs. 14) but trails Lemur-GPT-4 (25); on Code2Inv, both FVEL-FT models (40–46) fall well short of Lemur-GPT-4 (107), which the authors attribute to the difficulty of generating correct lemma specifications under uncertain loop conditions. The key advantage of FVEL over Lemur is its use of a full Isabelle theorem-proving environment with 29,304 lemmas and 201,498 proof steps, rather than Lemur's hand-crafted 8-rule proof system, and fine-tuning on FVELER consistently reduces proof-error rates by 7–9 percentage points on SV-COMP.

## Relation to Prior Work

This paper builds on the interactive theorem proving paradigm established by PISA (Isabelle) and LeanDojo (Lean), but repurposes it specifically for formal verification of C code rather than general mathematical theorem proving. It departs from the symbolic SMT-solver line (UAUTOMIZER, ESBMC) that cannot leverage LLM reasoning, and from Lemur's hand-crafted 8-rule proof system by instead relying on Isabelle's extensive, formally checked theorem and rule libraries. The FVELER dataset extracted from seL4's multi-level verification provides the training signal that connects the LLM's theorem-proving capability to the concrete task of verifying C program specifications.

## Why It Matters / Open Questions

FVELER (758 theories, 29,304 lemmas, 201,498 proof steps with dependencies up to depth 156) is a substantial resource for training LLMs on step-wise formal proving in Isabelle, and the FVEL environment offers a practical pipeline for interactive C code verification. However, the dominant failure mode remains lemma specification generation (statement errors at 60-72%), not proof generation, suggesting that the harder sub-problem of translating code semantics into correct Isabelle statements is still unsolved. Generalization beyond C code and beyond seL4-derived specifications remains open, and the modest absolute performance (81/1000 on SV-COMP vs. 374 for UAUTOMIZER) indicates significant headroom before LLM-based verification can compete with mature symbolic solvers on diverse specifications.
