## Problem

Existing automated feature engineering methods for tabular data rely on manually defined search spaces and use only validation scores to select features, discarding the rich knowledge that prediction models acquire during training. This limits the ability to iteratively refine feature generation rules based on what the model actually learned from the data, and makes it difficult to handle datasets without semantic column descriptions.
![Teaser figure](../imgs/NEURIPS20242931/cropped_page1_idx1.webp)

## Input / Output

The method takes a tabular dataset (with or without semantic column names/descriptions), a task description specifying the target column, and iteratively consumes an optimization trajectory of (validation score, CART decision tree in if-else form, previously proposed rule) tuples. It produces a new one-dimensional column feature whose values are computed by an optimized rule expressed in natural language and translated to executable Python code. The process can be repeated sequentially to generate multiple features, each built on the augmented feature space from prior iterations.

## Method

OCTree frames tabular feature engineering as a bi-level optimization over feature-generation rules r: X → X', solved by prompting an LLM (Llama 2 7B fine-tuned on UltraChat, or GPT-4o) with an iterative feedback trajectory. The key mechanism is extracting CART decision tree reasoning from the training data after each rule evaluation: the tree is rendered in natural-language if-else syntax and fed back to the LLM alongside the validation score and prior rules, giving the model explicit knowledge about which columns and thresholds the prediction model found important. The LLM then proposes a new rule that differs from all previously seen rules and aims to improve the score, with the trajectory sorted by score to exploit the LLM's positional bias. This decision-tree-as-feedback design is the core distinction from prior LLM-based feature engineering (e.g., CAAFE), enabling both context-aware (semantic column names) and context-agnostic (anonymized features) settings without a manually specified search space.

## Results

On 22 datasets (a mix of context-aware and context-agnostic tabular tasks), OCTree reduces the average test error of XGBoost from 18.30% to 17.45% (4.6% relative reduction) and MLP from 20.88% to 19.91% (4.6% relative reduction). When combined with OpenFE (OCTree†), the reductions grow to 7.9% for XGBoost (16.85%) and 7.0% for MLP (19.41%). On the 19 context-agnostic classification benchmarks from Grinsztajn et al., OCTree achieves an average ~5.0% relative error reduction over XGBoost, with individual datasets showing up to 20.1% improvement (electricity). On context-aware datasets, the largest single-dataset gain is 32.4% relative error reduction (MLP on Tesla Stock with GPT-4o).

## Baselines & Comparisons

OCTree outperforms both AutoFeat [23] and OpenFE [17] on the 22-dataset benchmark: for XGBoost, OCTree achieves 17.45% average error versus 18.24% (AutoFeat) and 17.79% (OpenFE); for MLP, 19.91% versus 20.60% and 20.12% respectively. Against CAAFE [19] on six context-aware datasets, OCTree with a 7B Llama 2 model (25.12% avg. error) beats CAAFE with GPT-4o (25.43%), and with GPT-4o itself OCTree reaches 24.53%—a 5.2% relative reduction over the XGBoost baseline versus CAAFE's 1.7%. OpenFE actually performs worse than the raw baseline on the context-aware subset (26.44% vs. 25.87%), while AutoFeat yields only a marginal 0.4% gain. The paper also shows that OCTree's features, optimized with XGBoost, transfer effectively to MLP and HyperFast, achieving 3.4–7.5% relative error reductions without re-optimizing for the target model.

## Relation to Prior Work

This paper extends the LLM-as-optimizer paradigm from Yang et al. [25] to the specific problem of tabular feature generation, replacing the generic score-only feedback with decision tree (CART) reasoning expressed in natural language. It departs from prior automated feature engineering methods (OpenFE, AutoFeat) by eliminating the need for a manually defined search space, and from CAAFE by introducing iterative refinement guided by structured data-derived feedback rather than one-shot greedy evaluation. The use of CART trees as a bridge between learned model knowledge and LLM prompting is the key conceptual novelty, leveraging the fact that tree splits are naturally expressible in if-else language.

## Why It Matters / Open Questions

OCTree offers a practical, model-agnostic way to automate a costly and error-prone step in tabular ML pipelines, with the added benefit of working in both context-aware and context-agnostic (anonymized) settings. The feature transfer result—optimizing rules with a fast XGBoost model and applying them to slower deep networks—provides a concrete scaling strategy for resource-constrained practitioners. Open questions include whether the approach scales to very high-dimensional or streaming settings, whether RLHF or other alignment methods could further improve rule quality, and whether the gains persist when the base prediction model is already near its ceiling.
