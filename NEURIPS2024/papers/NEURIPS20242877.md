## Problem

Existing table question answering benchmarks focus on simple factual retrieval or short-form arithmetic over retrieved entities, while real-world data analysis driven by application scenarios requires chains of mathematical, logical, and strategic reasoning over relational databases. This task is under-explored and prohibitively expensive to annotate with domain experts, leaving a gap between what current systems can handle and what practitioners actually need.
![Teaser figure](../imgs/NEURIPS20242877/cropped_page1_idx2.webp)

## Input / Output

The system takes a relational database (multiple named tables of tabular data, averaging 2.3 tables per database) and an application-driven user query framed from a specific stakeholder role (e.g., 'As a space agency director, I want to assess collision risk'). The LLM may invoke Python code execution across multiple turns (up to 9 coding turns, ~3.3 steps on average) before producing a final structured answer consisting of two lists: findings and suggestions, each containing 3–8 bullet points (~10 total, ~397 tokens median). The intermediate code snippets (~1.9k lines total) serve as both training signal and evidence for the final interpretation.

## Method

The paper introduces DACO, a dataset of 440 real-world databases with 1,942 application-driven queries, annotated via a multi-turn GPT-4 code-generation pipeline (adapted from ReAct) where the model iteratively writes Python, executes it, interprets results, and decides when analysis is comprehensive. For model training, they fine-tune CodeGeeX2-6B via SFT on these auto-generated annotations (including code trajectories), then apply RLHF with an answer-level reward model. The key technical contribution is fine-grained RLHF (FG-RLHF), which addresses the sparsity problem of standard RLHF by introducing two dense reward models for intermediate code steps: a contribution RM that scores each code action by its similarity to the final answer, and a regularization RM trained to detect and penalize reward-hacking patterns (e.g., exploiting the print function). FG-RLHF outperforms SFT by 7 helpfulness points and achieves a 57.72% human win rate over SFT.

## Results

On the DACO benchmark, GPT-4 with code generation achieves the highest helpfulness score of 50.79 on Test^A and 43.92 on Test^H, yet still loses to human-refined annotations in 58.1% of pairwise comparisons. The fine-tuned 6B FG-RLHF model achieves 19.42 helpfulness on Test^A and 12.50 on Test^H, outperforming SFT (13.73 / 9.83) by ~6 points and beating the TAPEX baseline (15.08 / 9.00). On external benchmarks, FG-RLHF improves over SFT on InfiAgent-DA (14.61 vs. 12.92 accuracy) while maintaining comparable performance on FeTaQA (6.35 vs. 6.39 Rouge-L).

## Baselines & Comparisons

Against TAPAS (337M), FG-RLHF (6B) achieves comparable helpfulness on Test^A (19.42 vs. 19.19) but trails on Test^H (12.50 vs. 16.50), while SFT with code generation clearly outperforms TAPAS on Test^A (13.73 vs. 19.19 is actually lower—however the paper states SFT outperforms TAPEX). Against TAPEX (406M), FG-RLHF wins on both test sets: 19.42 vs. 15.08 on Test^A and 12.50 vs. 9.00 on Test^H. Against GPT-4 without code generation (175B), FG-RLHF loses substantially on helpfulness (19.42 vs. 30.43 on Test^A; 12.50 vs. 20.50 on Test^H), though it achieves higher entailment on Test^H (5.98 vs. 4.36). The paper notes that FG-RLHF outperforms ChatGPT without code generation on both helpfulness and entailment despite being 3× smaller. GPT-4 with code generation dominates all other methods by a wide margin (50.79 helpfulness on Test^A), yet even it only wins 41.88% of pairwise comparisons against human annotations, highlighting the remaining gap to human-level data analysis.

## Relation to Prior Work

This paper adapts the ReAct framework (Yao et al., 2023) to the data analysis setting, where the LLM iteratively generates Python code as actions and interprets execution outputs as observations, and extends fine-grained RLHF (Wu et al., 2023) by introducing two purpose-built reward models—a contribution RM that scores intermediate code steps by their relevance to the final answer, and a regularization RM that detects and penalizes reward hacking patterns. It deliberately departs from prior table QA work (TAPAS, TAPEX, Spider, FeTaQA), which targets single-fact retrieval or short arithmetic, by formulating a multi-step, application-driven analysis task requiring mathematical, logical, and strategic reasoning over relational databases. The dataset construction pipeline (GPT-4 multi-turn code generation with self-correction, followed by human refinement) is a practical contribution distinct from both the code generation benchmarks (DS-1000, APPS) and concurrent data analysis efforts (Cheng et al. 2023, InfiAgent-DA).

## Why It Matters / Open Questions

DACO provides the first benchmark specifically targeting application-driven, comprehensive data analysis, filling a gap between simple table QA and open-ended data science. The finding that even GPT-4 with code generation loses to human-refined annotations 58.1% of the time underscores that automated data analysis remains far from reliable, while the demonstration that a 6B model trained with fine-grained RLHF can outperform ChatGPT (without code generation) on helpfulness suggests that targeted training on weak supervision data is a viable path for smaller models. Key open questions include whether the GPT-4-generated training annotations introduce systematic biases that cap the ceiling of fine-tuned models, whether the dense-reward RLHF approach generalizes beyond this specific task, and how to robustly evaluate the correctness (not just helpfulness) of multi-step analytical reasoning.
