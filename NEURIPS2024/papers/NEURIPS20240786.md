## Problem

Full-parameter fine-tuning of LLMs with Adam requires roughly 18M GB of GPU memory for an M-billion-parameter model, making it infeasible on consumer hardware. Parameter-efficient methods like LoRA reduce memory by constraining updates to low-rank subspaces, but this restriction can limit downstream performance. The paper asks whether full-parameter training with Adam-quality optimization can be achieved at memory costs comparable to PEFT methods.

## Input / Output

BAdam takes a pretrained LLM (e.g., Llama 3-8B or Llama 3-70B) and a supervised text dataset (Alpaca-GPT4 for instruction tuning, MathInstruct for math finetuning) as input, and produces a fully updated set of model parameters as output. The model is partitioned into D blocks (typically one per transformer layer, so D=32 for 8B models and D=80 for 70B models), and only the active block's parameters, gradients, and optimizer states are held in FP32 at any time, while all parameters remain in FP16 for the forward/backward pass. This yields a memory footprint of 2M + 16M/D GB, enabling 8B-model fine-tuning on a single 24 GB GPU.

## Method

BAdam applies block coordinate descent (BCD) with Adam's update rule: at each block-epoch, the model parameters are split into D blocks, and one active block is updated via K Adam steps while all other blocks are held fixed at their most recent values. The critical memory-saving mechanism is that optimizer states (momentum and second moment) are cleared after each block update and reinitialized to zero for the next block, so only 16M/D GB of FP32 optimizer storage is needed rather than 16M GB. The backward pass is also shortened because gradients only need to propagate through modules up to the active block's depth, reducing the number of unit-backward-passes from KD² (Adam/LoRA) to KD(D+1)/2 per block-epoch. A convergence analysis under L-smoothness and bounded-gradient assumptions proves BAdam is a descent method with O(δ^{-2}) first-order complexity, and the only new hyperparameter beyond Adam is K (the number of inner Adam steps per block, suggested as min{max{n/(BD), 50}, 100}).

## Results

On zero-shot math benchmarks for Llama 3-8B finetuned on MathInstruct, BAdam achieves an average score of 44.4, slightly surpassing Adam (44.1) and LoRA (43.3), while requiring only 23.5 GB of GPU memory versus Adam's 144.8+ GB. On MT-bench for Llama 3-8B instruction tuning (lr=1e-6), BAdam scores 6.65 on average, outperforming LoRA (6.27), Adam (6.23), Galore (5.71), and LOMO (5.69). For Llama 3-70B, BAdam achieves 62.7 average on math benchmarks versus LoRA's 59.0. BAdam also reduces backward time by nearly half compared to LoRA and LOMO (1.74h vs 3.20h/3.70h per epoch on Llama 3-8B).

## Baselines & Comparisons

BAdam outperforms LoRA on 4 of 6 math benchmarks for Llama 3-8B (notably MMLU-Math 50.5 vs 45.3 and SAT-Math 56.8 vs 50.9) and on 5 of 6 for Llama 3-70B, while also beating LoRA on MT-bench by 0.38 points (6.65 vs 6.27). Against Adam, BAdam achieves a marginally higher math average (44.4 vs 44.1) and a notably higher MT-bench score (6.65 vs 6.23 for Llama 3-8B), while using roughly 6× less GPU memory (23.5 GB vs 144.8+ GB). BAdam substantially outperforms both LOMO (31.6 avg) and Galore (34.4 avg) on math benchmarks, with gaps of 12.8 and 10.0 points respectively. The ablation with SGD (BSGD) shows that the BCD framework itself contributes to downstream gains: BSGD scores 6.50 on MT-bench versus full SGD's 5.82, suggesting that updating one block per data batch better preserves pretrained knowledge.

## Relation to Prior Work

BAdam combines two well-established ideas from different subfields: the block coordinate descent (BCD) framework from large-scale optimization (Nesterov, 2012; Wright, 2015) and Adam's adaptive per-parameter update rule (Kingma & Ba, 2014). It departs from PEFT methods (LoRA, adapters, prefix-tuning) that constrain parameter updates to low-rank subspaces, and from other memory-efficient full-parameter methods like LOMO (which sacrifices Adam for SGD), Galore (which requires iterative SVD), and MeZO (which uses zeroth-order approximations). The key conceptual departure from prior BCD-with-momentum approaches is clearing optimizer states between blocks rather than maintaining dense momentum vectors, which is what makes the memory savings possible while preserving Adam's adaptive behavior within each block.

## Why It Matters / Open Questions

BAdam lowers the practical barrier to full-parameter fine-tuning substantially: an 8B model can be trained on a single 24GB consumer GPU, and a 70B model on 4×A100s, without the low-rank constraints of LoRA or the optimizer degradation of LOMO. The finding that BCD variants (BAdam, BSGD) match or exceed their full-parameter counterparts in downstream performance—despite similar convergence speed—suggests that block-wise updates may implicitly regularize by preserving pretrained knowledge, an effect worth further investigation. Open questions include extending the convergence analysis to the stochastic setting, applying BAdam to preference optimization (RLHF/DPO), and validating the CPT results beyond the preliminary single-dataset experiment.
