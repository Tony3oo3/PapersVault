## Problem

Existing 3D assets and generative models typically produce only geometry and albedo (base color) maps, lacking the physically-based rendering material properties needed for realistic appearance under varying lighting conditions. Manual material assignment in graphic software is laborious, and prior material recovery methods either require physical measurements, extensive BRDF dataset training, or cannot operate on albedo-only inputs. This paper tackles the challenge of automatically recovering full SVBRDF material properties from 3D meshes that have only albedo textures, leveraging the world knowledge of multimodal large language models.

## Input / Output

The method takes a 3D mesh with a UV-mapped albedo texture as input and produces six spatially varying BRDF maps (roughness, metallic, specular, normal, displacement, height) at matching UV resolution. The albedo map serves as a color reference throughout the pipeline, ensuring generated material maps maintain spatial consistency with the original appearance. Outputs are directly compatible with standard rendering engines such as Blender, and the method handles objects from Objaverse CAD assets as well as outputs of image-to-3D and text-to-3D generative models, with an average runtime of ~1.5 minutes per object.

## Method

The pipeline comprises three stages. First, the albedo mesh is rendered from multiple viewpoints and segmented using Semantic-SAM, with post-processing to merge over-segmented patches by color similarity and annotate regions via Set-of-Mark visual cues. Second, GPT-4V performs hierarchical material retrieval from a library of 1,400 tileable PBR materials (sourced from MatSynth), navigating a three-level category tree (primary category → subtype → specific material) using detailed GPT-4V-generated textual descriptions to match each segmented region. Third, SVBRDF maps are generated via region-level gradient-based back-projection from 2D segmentation masks to UV space, followed by pixel-level albedo-referenced estimation where a KD-Tree nearest-neighbor search maps each query albedo pixel to corresponding material property values from the retrieved reference, ensuring smooth transitions and consistency with the original color distribution.

## Results

Make-it-Real is evaluated via GPT-4V-based preference and a 16-volunteer user study, comparing base objects against their refined counterparts across six 3D content sources. The strongest gains appear on existing 3D assets from Objaverse, where GPT-4V preference jumps from 15.2% to 84.8% and user preference from 22.2% to 77.8%. For generated objects, improvements are more modest but consistent: TripoSR user preference rises from 33.0% to 77.0%, while Fantasia3D (already producing PBR-aware textures) shows the smallest margin (48.7% → 51.3% user preference). Average runtime is 1.54 minutes per object with 5.76 GPT-4V queries and 12.52 GB GPU memory.

## Baselines & Comparisons

The paper does not include a direct quantitative benchmark against other material synthesis methods (e.g., Material Palette, Paint-it, Matlaber); instead, it frames the evaluation as a before/after preference comparison for each 3D content source. Make-it-Real consistently wins the preference vote across all six sources for both GPT-4V and human evaluators, with the largest margins on albedo-only Objaverse assets (+69.6 pp GPT, +55.6 pp user) and TripoSR-generated objects (+44.0 pp user). The smallest margin is on Fantasia3D, which already generates some PBR-aware textures, suggesting diminishing returns when the input already carries partial material information. In the appendix, the authors qualitatively contrast their pipeline with Material Palette [40], noting that Make-it-Real operates under a harder setting (albedo-only input, full-object output) and runs in roughly 1–2 minutes versus 3–10+ minutes for Material Palette, though no head-to-head quantitative metric is reported.

## Relation to Prior Work

This paper departs from the established line of material recognition and generation work (Material Palette, MatSim, TwoshotBRDF, Paint-it, Matlaber, Fantasia3D) by replacing trained domain-specific networks with the prior knowledge of a general-purpose MLLM (GPT-4V) for material identification and assignment. It builds on Semantic-SAM for segmentation, Set-of-Mark prompting for visual grounding, and the 2D-3D alignment techniques from Richardson et al. (Texture), but introduces a hierarchical prompting strategy over a 1,400-material library and an albedo-referenced KD-Tree-based pixel estimation to generate full SVBRDF maps. The key conceptual departure is operating under the more constrained albedo-only input setting, where prior methods either require shaded renderings or extensive BRDF dataset training.

## Why It Matters / Open Questions

Make-it-Real addresses a genuine bottleneck in the 3D content creation pipeline by automating the tedious manual material-painting step, producing six PBR maps compatible with standard rendering engines. The demonstration that a zero-shot MLLM with structured prompting can perform fine-grained material matching without any task-specific training suggests a broader paradigm shift toward leveraging foundation model knowledge for specialized graphics tasks. However, the method's heavy dependence on GPT-4V API access, the circularity of using GPT-4V both as the material assigner and the primary evaluator, and the lack of comparison against trained material recognition baselines under the same albedo-only constraint leave open questions about robustness, scalability, and whether the gains persist as MLLMs evolve. The paper also acknowledges that shaded inputs from generative models require an additional derendering step, and that low-quality geometry or poor UV mappings degrade performance.
