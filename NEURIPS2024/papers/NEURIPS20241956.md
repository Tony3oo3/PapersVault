## Problem

LoRA and other PEFT adapters are tightly coupled to their base model, so when a base model is deprecated and replaced, all client LoRA modules must be retrained from scratch. In commercial cloud serving, this is infeasible because the proprietary task data used to train the original LoRAs is not retained by the service provider. No prior method enables automatic, nearly data-free transfer of PEFT modules across different base models or even across different PEFT variants.

## Input / Output

The method requires only five seed examples (task demonstrations with proprietary content stripped) alongside the source model with its trained LoRA, the target base model, and a pre-trained discriminator. The discriminator is a small PEFT model trained once during the original LoRA training and is reused unchanged for all future transfers, regardless of which target model is used. The output is a target LoRA (or DoRA/PT) whose performance matches or exceeds both the source LoRA and the unadapted target base model, plus a filtered synthetic dataset of the same cardinality as the original training set.

## Method

Trans-LoRA transfers PEFT capabilities via knowledge distillation on carefully curated synthetic data. A GAN-inspired pipeline uses the target model itself as a generator (prompted with the 5 seed examples as in-context demonstrations) to produce candidate prompt-completion pairs, and a separately trained discriminator (a LoRA on the source model, optimized to classify samples as real vs. synthetic) to filter them via rejection sampling until the synthetic set matches the original training set size. The key insight is that raw synthetic data is insufficient for lossless transfer: the discriminator ensures the filtered data matches not just the task format but the marginal input distribution of the original training set, which corresponds to the source LoRA's 'comfort zone.' The target LoRA is then trained by minimizing cross-entropy loss against the source LoRA's completions on the filtered synthetic data, effectively distilling task-specific knowledge without ever accessing the original training examples.

## Results

Trans-LoRA achieves lossless (and typically improved) LoRA transfer across Llama-2 and Gemma model families on 86 tasks. On BBH (27 reasoning tasks), transferred LoRAs reach 43.41–45.41% accuracy, exceeding both the source LoRA (43.32%) and target base model (37.75–37.85%). On MMLU (57 knowledge tasks), the method reaches 55.09–61.23%, surpassing the target base model (53.72–60.45%) and source LoRA (42.34–45.89%). On GSM8K, the largest gains are observed: Gemma-2b→Gemma-7b transfer reaches 44.58% vs. 40.64% (target base) and 14.94% (source LoRA), a ~4-point improvement over the stronger baseline.

## Baselines & Comparisons

The paper does not compare against other transfer methods; instead, it benchmarks Trans-LoRA against two natural baselines: the source model's fine-tuned LoRA and the target base model without any adaptation. Trans-LoRA consistently outperforms both baselines across all four task collections (BBH, MMLU, MBPP, GSM8K) and all four model-pair configurations. The most dramatic gains appear when the source model is weaker than the target (e.g., Gemma-2b→Gemma-7b on GSM8K: 44.58% vs. 40.64% target base and 14.94% source LoRA), suggesting the method effectively combines task-specific knowledge from the source LoRA with the stronger target architecture. On MMLU, gains over the target base model are smaller (1–2 points) because knowledge-heavy tasks rely more on pretraining than fine-tuning. The ablation (Table 5) further confirms that unfiltered synthetic data (41.95%), random Wikipedia text (37.32%), and 5 seed samples alone (39.82%) all underperform Trans-LoRA (43.41%) on BBH, validating the necessity of discriminator-based filtering.

## Relation to Prior Work

This paper sits at the intersection of parameter-efficient fine-tuning (LoRA, DoRA, Prompt Tuning) and knowledge distillation, but departs from both lines in a key way: prior PEFT work assumes a fixed base model, and prior KD work requires access to the original training corpus. Trans-LoRA repurposes the GAN generator-discriminator paradigm (Goodfellow et al.) for a novel purpose—curating synthetic data that mimics the *input marginal distribution* of the original training set—so that distillation can proceed without the data itself. The discriminator, trained once alongside the source LoRA, acts as a distributional filter that generalizes across unseen target models, which is a non-trivial extension of standard GAN usage.

## Why It Matters / Open Questions

This addresses a concrete and growing pain point in production LLM serving: when a base model is deprecated, thousands of client-specific LoRA adapters must be retrained, but client data is proprietary and cannot be retained by the service provider. Trans-LoRA offers a nearly data-free, centralized solution that consistently achieves lossless or improved transfer across model families (Llama-2, Gemma, T5) and PEFT variants, with negligible overhead (discriminator costs ~1/20 of LoRA training). Open questions include whether direct PEFT transfer without synthetic data generation is possible, how the approach scales to much larger models (70B+), and whether the 5-seed-sample requirement can be further reduced or eliminated for tasks with complex reasoning structures.
