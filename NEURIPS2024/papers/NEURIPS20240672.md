## Problem

Relational databases underpin much of the digital economy, yet their rich relational structure is typically discarded by flattening data into single tables via manual feature engineering, losing predictive signal and introducing fragile data pipelines. No standardized benchmark, open-source implementation, or comprehensive empirical comparison existed for the emerging paradigm of Relational Deep Learning (RDL), which casts relational data as graphs for end-to-end neural network prediction.
![Teaser figure](../imgs/NEURIPS20240672/cropped_page1_idx0.webp)

## Input / Output

The method consumes a relational database as a set of tables linked by primary-foreign key relationships, with each table carrying diverse column features and optional temporal columns. Predictions are made at a specified 'seed time' per entity, and the implementation enforces temporal neighbor sampling to prevent future-data leakage during training and validation. Outputs are task-specific: binary labels (AUROC), continuous values (MAE), or ranked top-K entity lists (MAP@K), with K set per recommendation task.

## Method

RDL converts a relational database into a heterogeneous temporal graph where nodes represent entities and edges encode primary-foreign key links. Initial node embeddings are extracted from raw table column features using deep tabular models (PyTorch Frame), which handle mixed-type columns (categorical, numerical, text) without manual encoding. A GNN (GraphSAGE for structural features or ID-GNN for entity-specific signals) then performs message passing over the temporal graph, with a task-specific MLP head producing the final prediction. The entire pipeline is end-to-end trainable with a single set of default hyperparameters across all 30 tasks, eliminating the need for task-specific SQL feature engineering. The paper validates this approach through a controlled user study where an experienced data scientist manually engineers features for each task, showing RDL matches or outperforms the data scientist in 11 of 15 tasks while reducing human effort by 96%.

## Results

On entity classification (AUROC, higher is better), RDL achieves an average of 75.83 on test splits versus 63.66 for LightGBM, a 20.5% relative gain, with the largest improvement on rel-stack user-engagement (90.59 vs 63.39, +42.9%). On entity regression (MAE, lower is better), RDL averages 12.63 on test splits versus 14.05 for LightGBM (8.1% relative gain). On recommendation (MAP@K, higher is better), RDL with ID-GNN achieves an average of 6.74 on test splits versus 1.79 for LightGBM, a 277% relative gain, with the largest improvement on rel-stack user-post-comment (12.72 vs 0.04, +795%).

## Baselines & Comparisons

The primary baseline is LightGBM trained on raw single-table entity features (no cross-table information, no feature engineering). On entity classification, RDL outperforms LightGBM on 11 of 12 test splits, with the sole exception being rel-trial study-outcome where LightGBM edges out RDL by 0.19% AUROC (68.18 vs 68.60), likely due to the 28 rich columns in that target table. On entity regression, RDL beats LightGBM on 7 of 9 test splits, with the two losses on rel-trial study-adverse being marginal (-1.05% MAE). On recommendation, RDL (using either GraphSAGE or ID-GNN) dramatically outperforms LightGBM across all 8 test splits, with average MAP@K of 6.74 vs 1.79; ID-GNN excels when past-visit signal is strong (e.g., rel-avito user-ad-visit: 3.66 vs 0.06), while GraphSAGE wins when structural patterns dominate (e.g., rel-amazon user-item-purchase: 0.74 vs 0.16). The paper also compares against simpler baselines (Global Popularity, Past Visit, Global Mean/Median/Zero), all of which are substantially outperformed by RDL.

## Relation to Prior Work

This paper operationalizes the Relational Deep Learning (RDL) blueprint proposed by Fey et al. (2024), which recasts relational databases as heterogeneous temporal graphs and applies GNNs with deep tabular models for node embeddings. It builds on PyTorch Frame (Hu et al., 2024) for tabular feature extraction and PyTorch Geometric for GNN training, but its primary contribution is the first open-source implementation and the first dedicated benchmark (RELBENCH) for this paradigm. Unlike prior graph ML benchmarks (OGB, TGB) that collect tasks already framed as graph problems, RELBENCH repurposes standard predictive tasks (churn, adverse events, recommendations) that were previously solved via manual SQL feature engineering plus LightGBM/XGBoost, positioning them as graph ML problems for the first time.

## Why It Matters / Open Questions

RELBENCH fills a critical infrastructure gap: before this work, there was no standardized way to compare RDL methods across diverse relational databases, no open-source RDL implementation, and no empirical evidence that end-to-end learned models could compete with expert feature engineering. The user study showing RDL matching or outperforming an experienced data scientist in 11/15 tasks with 96% less human effort is the first empirical validation of RDL's central promise. Key open questions include improving regression performance (where the MLP output head is identified as a bottleneck), leveraging multi-task learning across tasks sharing the same database, and developing better temporal and graph-construction strategies. The paper explicitly frames its RDL implementation as an initial demonstration with significant room for improvement from graph ML, deep tabular ML, and time-series modeling.
