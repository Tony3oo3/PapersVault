## Problem

Existing differentiable satisfiability layers for imposing linear constraints on neural network outputs are limited: LinSAT only handles positive linear constraints, OptNet requires batch matrix factorization that cannot fully exploit GPU parallelism, and CvxpyLayers relies on CPU-based multiprocessing. This paper addresses the gap of imposing general linear constraints (including negative coefficients) on neural network outputs in a fully differentiable, GPU-parallel, and matrix-factorization-free manner.
![Teaser figure](../imgs/NEURIPS20243895/cropped_page3_idx0.webp)

## Input / Output

The layer takes a neural network output vector c' ∈ R^{n'} along with general linear constraints (inequalities, equalities, and bounds) and an inverse temperature parameter θ > 0. Internally, the constraints are converted to standard form Ax = b, 0 ≤ x ≤ u via slack variables and bound shifting, padding c' with zeros for the slack variables. The output is a projected vector x that satisfies all constraints while remaining as close as possible to the original output, with θ controlling the trade-off between fidelity to the input and constraint tightness (smaller 1/θ pushes outputs toward extreme points of the feasible region).

## Method

GLinSAT reformulates the projection problem as an entropy-regularized linear programming with logistic entropy terms in both x/u and its complement 1−x/u, which is the key design choice enabling a closed-form Lagrange dual. By the duality theorem, the problem becomes an unconstrained convex optimization with Lipschitz continuous gradient, solvable via a variant of adaptive primal-dual accelerated gradient descent (APDAGD) that adaptively tracks the local Lipschitz constant. All forward-pass operations reduce to matrix-vector products and element-wise sigmoid evaluations, making the layer fully GPU-parallel and matrix-factorization-free. For backpropagation, GLinSAT offers two options: explicit automatic differentiation through the iterative forward pass, or implicit differentiation via the optimality condition h(y)=0, where the required inverse-matrix-vector products are computed with conjugate gradient since ∂h/∂y is positive semi-definite. The iteration complexity is O(‖A‖₂ max(u) √(θR/ε)), improving over Sinkhorn-based methods whose complexity scales as θ/ε².

## Results

On the constrained TSP (20 nodes, batch size 1024, 1/θ=0.1), GLinSAT-Dense-Implicit uses only 13.35 MB GPU memory for projection and 53.23 MB for backpropagation, compared to 14,977 MB and 181.2 MB for LinSAT-Dense-100, while achieving a shorter mean tour length (3.922 vs. 3.926 with rounding; 3.811 vs. 3.823 with beam search). In predictive portfolio allocation, GLinSAT achieves a mean Sharpe ratio of 2.608 at 1/θ=10⁻², outperforming LinSAT (2.409) and matching CvxpyLayers (2.600). In power system unit commitment on a real provincial grid (~1M×2M constraint matrix), GLinSAT-Sparse-Implicit is the only method that avoids out-of-memory errors and reaches 100% feasibility at 1/θ ≤ 0.0005 with an average optimality gap of 0.1114%.

## Baselines & Comparisons

Against LinSAT [20], GLinSAT achieves comparable or slightly better solution quality (e.g., 3.922 vs. 3.926 mean tour length on TSP-StartEnd with rounding) while using over 1000× less GPU memory (13.35 MB vs. 14,977 MB for projection). Critically, LinSAT cannot handle constraints with negative coefficients (e.g., x − y ≤ 0), which rules it out entirely for the unit commitment experiment; GLinSAT handles general linear constraints natively. Against CvxpyLayers [24], GLinSAT is roughly 300× faster in total (0.449 s vs. 130.5 s per batch on TSP) because CvxpyLayers relies on CPU multiprocessing rather than GPU parallelism. Against OptNet [25], GLinSAT uses 1400× less GPU memory (13.35 MB vs. 19,310 MB) and avoids batch matrix factorization, which is the computational bottleneck in OptNet; on the large-scale unit commitment problem (~1M×2M matrix), OptNet cannot handle the block-diagonal constraint matrix within reasonable time while GLinSAT-Sparse-Implicit completes successfully. In portfolio allocation, GLinSAT matches or exceeds all baselines on Sharpe ratio (2.608 vs. 2.409 for LinSAT, 2.600 for CvxpyLayers, 2.381 for OptNet at 1/θ=10⁻²) while being the fastest layer.

## Relation to Prior Work

GLinSAT extends the line of differentiable satisfiability layers (Sinkhorn, SATNet, LinSAT, OptNet, CvxpyLayers) by generalizing from positive linear constraints (LinSAT) or matrix-factorization-based solvers (OptNet, CvxpyLayers) to general linear constraints with negative coefficients, while remaining GPU-parallel and matrix-factorization-free. The core algorithmic engine is a variant of APDAGD (Dvurechensky et al., ICML 2018), an accelerated gradient descent method originally developed for entropy-regularized optimal transport, repurposed here to solve the Lagrange dual of an entropy-regularized linear programming reformulation. The key conceptual departure from LinSAT is the use of logistic entropy regularization (involving both x log x and (1−x) log(1−x) terms), which yields a closed-form dual objective amenable to gradient descent without requiring the non-negativity of constraint coefficients.

## Why It Matters / Open Questions

GLinSAT provides the first differentiable, matrix-factorization-free, GPU-parallel layer for general linear constraints, which is practically important for large-scale applications like power system unit commitment where constraint matrices have millions of entries and negative coefficients are ubiquitous. The implicit differentiation variant reduces GPU memory from ~4.4 GB to ~13 MB for projection, making it feasible to handle very large constraint systems. Key limitations include the requirement that all variables have finite upper and lower bounds (one-sided or unbounded variables need implicit bound computation) and the restriction to linear constraints only; extending to cone or nonlinear constraints on GPUs remains open. The paper does not explore how the inverse temperature θ interacts with network depth or training dynamics, which could be important for practical deployment.
