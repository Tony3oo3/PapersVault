## Problem

Generating full coded simulations from natural language specifications remains an open challenge: existing LLM-based approaches only produce partial components (reward functions, hyperparameters, or task configurations) rather than complete, runnable simulations. When LLMs are asked to generate entire simulations at once, they frequently ignore or fail to adhere to parts of the input prompt due to the large and detailed context required, making it difficult to produce a distribution of simulations that meet detailed design specifications for training generalized RL agents.

## Input / Output

The method takes a natural language specification of roughly 10 sentences describing a simulation's mechanics, entities, and rules, and produces a complete, runnable PyGame (2D games) or CLIPort (robotics) codebase structured as a POMDP with explicit state variables, transition functions, observation functions, and reward logic. The generated code follows a Model-View-Controller pattern with separate functions for input handling, state transitions, and rendering, each accompanied by a unit test. For RL evaluation, 10 generated environments are produced per game specification to train a PPO agent, which is then zero-shot tested on the ground-truth environment.

## Method

FACTORSIM decomposes simulation generation into two levels of structure. First, Chain-of-Thought prompting splits the input specification into K sequential modules, each describing one input event, one state transition, and one rendering logic. Second, and more critically, a factored POMDP representation is used to select only the relevant subset of state variables (scope set Z_k) and their associated transition/reward factors as context for each generation step, rather than passing the entire growing codebase. Within each step, the Model-View-Controller pattern further decomposes the update into three targeted LLM calls: a Controller prompt for action-dependent state transitions, a Model prompt for action-independent state transitions (including reward via a score variable), and a View prompt for rendering. This progressive, context-minimal generation reduces the reasoning burden at each step, preventing the LLM from attending to or modifying unrelated code, and yields simulations with higher prompt alignment and better zero-shot RL transfer.

## Results

On the 8-game Generative Simulation Benchmark, GPT-4 w/ FACTORSIM achieves an average system test pass rate of 64.3% across all games, outperforming the strongest baseline (GPT-4 CoT w/ self-debug, 46.0%) by 18.3 percentage points. FACTORSIM wins in 7 out of 8 games, with the largest margins on Flappy Bird (78% vs. 30%) and Puckworld (81% vs. 47%). On the GenSim robotics benchmark (12 assembly tasks), FACTORSIM achieves a 58% runtime pass rate and 25% human pass rate, compared to 8%/0% for GenSim vanilla and 42%/0% for both GenSim CoT variants.

## Baselines & Comparisons

Against the self-debug baseline (Chen et al., ICLR 2024), GPT-4 w/ FACTORSIM wins in 7 of 8 games; the only exception is Pong, where GPT-4 w/ self-debug scores 0.75 vs. FACTORSIM's 0.61, though FACTORSIM still leads on the overall average. Against AgentCoder (Huang et al., 2023), FACTORSIM substantially outperforms across all games (e.g., 0.78 vs. 0.18 on Flappy Bird, 0.81 vs. 0.33 on Puckworld), with the paper attributing AgentCoder's weakness to its test-designer agent producing incorrect or infeasible test cases. Against GenSim (Wang et al., 2023) on the 12-task robotics benchmark, FACTORSIM achieves a 58% runtime pass rate versus 8% for GenSim vanilla and 42% for both GenSim CoT variants, and is the only method to achieve a non-zero human pass rate (25%), indicating that generated tasks actually match the prompt specifications rather than merely executing without errors.

## Relation to Prior Work

This paper extends the line of LLM-based simulation generation (Eureka, GenSim, RoboGen, Holodeck) that has focused on generating individual components—reward functions, hyperparameters, or scene configurations—by tackling the full-simulation generation problem end-to-end. Its core algorithmic contribution builds on Chain-of-Thought decomposition (Wei et al., 2022; Prystawski et al., 2024) but introduces a principled context-reduction mechanism via a factored POMDP representation, drawing on the model-view-controller software design pattern to structure each generation step. Unlike general code-generation approaches (Parsel, ExeDec, AgentCoder) that decompose by function or execution state, FACTORSIM exploits the inherent modularity of coded simulations (state variables, transitions, observations) to select minimal relevant context per step, reducing the LLM's reasoning burden.

## Why It Matters / Open Questions

The ability to generate full, executable simulations from text specifications is a practical bottleneck for scaling RL agent training, and this paper provides both a working framework and a standardized benchmark (8 RL games + 12 robotics tasks) that the community can use to compare generative simulation methods. The factored POMDP + MVC decomposition is a reusable technique applicable to any structured code generation task where context length is a limiting factor. Key limitations include single-agent scope, dependence on LLM context windows for larger codebases, and the gap between generated simulation quality and real-world transfer; the authors identify multi-agent settings, GPU-accelerated code generation, and sim-to-real validation as important open directions.
