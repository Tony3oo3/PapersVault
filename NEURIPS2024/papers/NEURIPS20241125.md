## Problem

State-of-the-art LLMs fail at basic arithmetic—GPT-4o achieves under 40% accuracy on 7-digit division and 0% on 7-digit multiplication—while existing remedies either fine-tune the model (risking catastrophic forgetting) or generate executable code (introducing latency and security vulnerabilities). The paper asks whether exact, interpretable arithmetic can be performed in a single autoregressive step without modifying the underlying language model.
![Teaser figure](../imgs/NEURIPS20241125/cropped_page2_idx0.webp)

## Input / Output

The system accepts standard text prompts—pure arithmetic expressions (e.g., '3 + 85 ='), word problems, or multi-step math reasoning—and produces generated text in which arithmetic results are computed exactly. A per-token switch routes each output token to either the LLM (for reasoning and text) or OccamNet (for arithmetic), so the LLM appears to possess an internal calculator while remaining completely frozen. OccamNet inputs are extracted by a string parser that pulls the most recent numbers from the generated text.

## Method

OccamLLM couples a frozen LLM (Llama 3 8B/70B Instruct) with a 1-layer Complete OccamNet whose primitives are {+, −, ×, ÷, sqrt, power, log, exp, sin, cos}. A decoder (two-layer MLP over a weighted sum of the LLM's layer hidden states) maps hidden states to OccamNet's softmax-layer weights, thereby selecting which symbolic function to apply; a separate sigmoid-MLP switch decoder decides per-token whether to emit the LLM's or OccamNet's output. The OccamNet decoder is trained with a rescaled REINFORCE loss—equivalent to a Monte-Carlo estimate of cross-entropy over the function distribution—while the switch is trained with binary cross-entropy, all with LLM weights frozen. The LLM can invoke OccamNet multiple times during a single generation, enabling multi-step arithmetic without additional autoregressive decoding steps.

## Results

On 7-digit single-operation arithmetic (addition, subtraction, multiplication, division, sqrt, exp, log, sin, cos), OccamLlama (both 8B and 70B) achieves 100.0% accuracy, missing 0 out of 9,000 problems, compared to 39.5% for GPT 4o and 99.8% for GPT 4o + Code. On mathematical reasoning benchmarks (AddSub, GSM8K, MultiArith, MultiArith Float, MATH401, Single Eq, SVAMP), OccamLlama 70B averages 94.6% accuracy, outperforming GPT 4o (94.2%) and GPT 4o + Code (93.4%). On the most arithmetically challenging subsets, OccamLlama 8B reaches 98.2% on MultiArith Float and 85.0% on MATH401, exceeding GPT 4o + Code (89.5% and 78.0% respectively).

## Baselines & Comparisons

Against Llama 2 7B Chat and Llama 3 8B, OccamLlama dominates on arithmetic (100% vs. 4.4% and 14.0% average) and also leads on reasoning benchmarks (89.9% vs. 81.9% for the 8B variant). Against GPT 3.5 Turbo, OccamLlama wins decisively on arithmetic (100% vs. 20.7%) and edges ahead on reasoning (89.9% vs. 86.2%). Against GPT 4o, OccamLlama achieves 100% on arithmetic versus GPT 4o's 39.5%, and OccamLlama 70B slightly outperforms GPT 4o on reasoning (94.6% vs. 94.2% average). Against GPT 4o + Code Interpreter, OccamLlama ties on arithmetic (100% vs. 99.8%) while using over 50× fewer generation tokens, and OccamLlama 70B outperforms it on reasoning (94.6% vs. 93.4%), with the gap widening on arithmetically challenging subsets like MultiArith Float (98.2% vs. 89.5%) and MATH401 (85.0% vs. 78.0%).

## Relation to Prior Work

This paper builds on OccamNet, a neurosymbolic architecture for symbolic regression, and repurposes it as a controllable arithmetic engine driven by frozen LLM hidden states. It departs from the two dominant prior approaches to LLM arithmetic—fine-tuning on synthetic math data (which risks catastrophic forgetting) and tool-use via code generation (which requires multiple autoregressive steps and introduces security risks)—by introducing a single-step mechanism where the LLM's internal representations directly parameterize the symbolic model's function selection. The framework is conceptually related to tool-calling work like Calc-X and Toolformer, but inverts the paradigm: rather than the LLM generating an API call or code snippet, the LLM's hidden states are decoded into OccamNet weights, eliminating both the generation overhead and the need to train the LLM itself.

## Why It Matters / Open Questions

OccamLLM offers a practically attractive middle ground: exact arithmetic at the speed of a single forward pass, without the security surface of arbitrary code execution or the catastrophic-forgetting risk of fine-tuning. The broader implication is a general paradigm for tightly integrating symbolic tools into LLMs via hidden-state decoding, which the authors sketch could extend to multi-operation compositions and other tool types. Key limitations remain: the single-layer OccamNet cannot handle compound expressions (fractions, percentages, multi-argument operations), the switch occasionally misfires on out-of-distribution text (notably GSM8K and Single Eq), and the approach has not yet been tested with speculative decoding or on non-Llama architectures. Open questions include whether the hidden-state-to-symbolic-model mapping generalizes to tools beyond arithmetic and whether deeper OccamNets can be trained efficiently at scale.
