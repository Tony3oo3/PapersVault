## Problem

Function-calling agent models require diverse, reliable training data, but existing datasets are largely static, lack rigorous verification, and underrepresent complex scenarios like parallel function calling. This leads to models that struggle with unseen APIs and multi-call queries, limiting real-world deployment of function-calling agents.
![Teaser figure](../imgs/NEURIPS20241724/cropped_page1_idx0.webp)

## Input / Output

The APIGen pipeline consumes executable API libraries (3,539 REST APIs from ToolBench + 134 Python functions), seed query-answer pairs, and diverse prompt templates to produce 60,000 verified data points in a standardized JSON schema with query, tools (name, description, typed parameters), and answers (tool name + arguments). The trained models (xLAM-1B/7B) take a user query plus available tool descriptions as input and output a JSON object containing a list of tool_calls, each specifying a function name and its argument dictionary. The dataset uniquely covers four query styles—simple, multiple, parallel, and parallel multiple—where parallel styles require multiple concurrent function calls in a single response.

## Method

APIGen's core mechanism is a three-stage verification pipeline that exploits the executability of function calls: (1) a format checker validates JSON structure and confirms all referenced functions/arguments exist in the API library; (2) an execution checker actually runs the generated calls against real backends (subprocess for Python, HTTP for REST) and filters failures with fine-grained error messages; (3) a semantic checker LLM assesses whether execution results align with the query's intent, catching cases where calls succeed but are semantically wrong. Diversity is promoted through an API sampler, example sampler, and prompt sampler that randomize the number of APIs, seed examples, and prompt contexts per generation batch, while four query-style categories (simple, multiple, parallel, parallel multiple) are controlled via dedicated prompts. Data passing all three stages is recycled into the seed pool to bootstrap future generation. The resulting dataset fine-tunes DeepSeek-Coder-1.3B/7B via the xLAM training pipeline (8×A100, lr=5e-6, 4 epochs, AdamW), with an additional 8,000 relevance-detection samples created by removing tools or required parameters from verified entries.

## Results

On the Berkeley Function-Calling Leaderboard (BFCL), xLAM-7B (FC) achieves 88.24 overall accuracy, ranking 3rd among all evaluated LLMs and surpassing GPT-4o, GPT-4-Turbo-FC, Llama3-70B, and Gemini-1.5-Pro. The smaller xLAM-1B (FC) achieves 78.94 overall accuracy (25th place), outperforming GPT-3.5-Turbo-0125 (63.94), Claude-3 Haiku (74.35), and Mistral-large (68.76). Both models show particularly strong gains in parallel and parallel-multiple function-calling scenarios, which are underrepresented in existing public datasets.

## Baselines & Comparisons

xLAM-7B (88.24) outperforms GPT-4-0125-Preview FC (84.59) by +3.65, Gemini-1.5-Pro-0514 FC (86.35) by +1.89, Llama3-70B (84.0) by +4.24, and GPT-4-turbo FC (82.94) by +5.30 on overall BFCL accuracy. It trails only Claude-3.5-Sonnet (90.18) and GPT-4-0125-Preview in Prompt mode (88.29). xLAM-1B (78.94) surpasses GPT-3.5-Turbo-0125 FC (63.94) by +15.0, Claude-3-Haiku (74.35) by +4.59, Command-R-Plus Original (70.88) by +8.06, Mistral-large (68.76) by +10.18, and DBRX-Instruct (66.06) by +12.88. Notably, xLAM-1B achieves 94% on Executable Multiple and 84% on Executable Parallel, exceeding even GPT-4-0125-Preview FC (92% and 86% respectively) on those sub-tasks, demonstrating that the APIGen dataset's emphasis on parallel and multi-function scenarios yields targeted gains. The ablation in Fig. 5 further confirms that adding back data filtered by the execution or semantic checkers degrades performance, validating the multi-stage verification pipeline.

## Relation to Prior Work

APIGen builds on the xLAM/AgentOhana training pipeline [25, 26] for model fine-tuning and sources its API library from ToolBench [12], but departs from prior function-calling datasets (APIBank, ToolAlpaca, ToolBench) by introducing a three-stage verification process—format checking, actual API execution, and LLM-based semantic alignment—that prior synthetic datasets largely lacked. The framework also extends the function-calling data generation scope to parallel and parallel-multiple call scenarios at scale, which the authors note are underrepresented in existing public datasets. Conceptually, the paper positions data quality and diversity as the primary levers for function-calling performance, rather than model scale, drawing on the 'less is more' alignment literature [40].

## Why It Matters / Open Questions

The released 60K-entry dataset and the APIGen pipeline provide a practical, reusable resource for training function-calling agents, and the results demonstrate that rigorous multi-stage verification of synthetic data can make a 7B model competitive with GPT-4o and Gemini-1.5-Pro on BFCL—a finding that shifts attention toward data curation over raw model scale. Key limitations include support for only REST APIs and Python functions, single-turn interactions only, and evaluation on a single benchmark (BFCL), leaving open questions about generalization to multi-turn agent workflows, additional programming languages, and other function-calling benchmarks. The ablation showing that unfiltered synthetic data actively degrades performance is a useful caution for practitioners generating training data at scale.
