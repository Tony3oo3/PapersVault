## Problem

While LLMs have been evaluated on planning tasks in natural language environments (e.g., PlanBench, AutoPlanBench), it remains unclear whether they can plan in spatial, non-linguistic domains where the state is represented as a string of characters rather than prose. No prior benchmark specifically tests whether LLMs can generate correct traversal action sequences over 2D grid-based game maps, a representation that is infrequently encountered in training data and thus resists lookup-based shortcuts.

## Input / Output

The LLM receives a character-string representation of a 2D grid map (alphanumeric tiles for walkable/non-walkable terrain, numbered objectives, and agent position), along with a description of the four discrete actions (up, down, left, right) and the current objective coordinate. It must output a single sequence of those four actions that moves the agent from its current position to the objective. The 150 maps in the dataset range from 5×10 to roughly 100×35 tiles and contain 3–11 objectives each, with optimal A* path lengths spanning 5 to ~120 steps. Evaluation yields a composite GTB_Score (normalized reward combining proximity to objective, path length, and generation errors) plus auxiliary metrics: MGE, MPL, MAT, and Top-0/1/5 accuracy.

## Method

GTB is built on 150 game maps generated by the Word2World pipeline (using GPT-4-Turbo, GPT-4, GPT-3.5, Claude-3-Opus, and Claude-3-Haiku), where each map encodes a story-driven level with walkable tiles, obstacles, and numbered objectives. For each objective, the LLM agent is prompted with the full map state, its current position, and the target coordinate, and must produce a complete action sequence in one generation (zero-shot) or with one corrective retry (one-shot). Generated actions are rolled out in simulation; rewards follow a distance-based table (from +200 for exact arrival to −100 for 8+ tiles away), penalized by −1 per step and −1 per generation error. The composite GTB_Score normalizes each level's total reward between its theoretical minimum and maximum (computed via A* optimal path length), then averages across all 150 maps. The benchmark is deliberately designed so that the character-string map format is out-of-distribution for LLMs, forcing genuine spatial planning rather than pattern recall, and the lack of correlation between objective count and path length prevents the model from learning a single heuristic.

## Results

On the GameTraversalBenchmark (GTB), GPT-4-Turbo achieves the highest zero-shot GTB_Score of 44.97% among standard LLMs, with a Top-0 accuracy of 19.2% and Top-5 accuracy of 23.05%. The large reasoning model o1 substantially outperforms all standard LLMs, reaching 67.84% GTB_Score with 50% Top-0 accuracy, though it still falls well short of a perfect score. The random fixed-path baseline (Random-FP) scores 18.02%, and all LLMs below the top four (GPT-4-Turbo, GPT-4-o, Claude-3-Opus, Claude-3-Sonnet) perform worse than this random baseline, suggesting they cannot internally represent the map state.

## Baselines & Comparisons

The paper compares 10 LLMs against two random baselines (Random-FP and Random-RP) on the GTB benchmark. GPT-4-Turbo dominates all standard LLMs, scoring 44.97% GTBS versus 30.95% for GPT-4-o and 28.65% for Claude-3-Opus, while also achieving the highest Top-0 (19.2%) and Top-5 (23.05%) accuracy. The large reasoning model o1 nearly doubles GPT-4-Turbo's GTBS (67.84% vs. 44.97%) and achieves 50% Top-0 accuracy, but GPT-4-Turbo still produces fewer generation errors (MGE 0.03 vs. 0.12) and higher Top-1/Top-5 accuracy. Critically, all LLMs ranked below Claude-3-Sonnet (Gemma-7B, GPT-3.5-Turbo, LLaMa-3-8B/70B, Claude-3-Haiku, Mixtral-8×7B) score worse than the Random-FP baseline (18.02%), indicating they cannot meaningfully plan traversal paths. The Random-RP baseline (3.04%) confirms that even generating the correct sequence length requires non-trivial planning, as LLMs that beat it appear to estimate path length but fail to produce correct actions.

## Relation to Prior Work

This paper builds directly on the authors' prior Word2World system [12] to generate 150 diverse 2D grid-based game maps, repurposing a game-generation pipeline as a planning evaluation substrate. It positions itself as a complement to existing planning benchmarks like PlanBench [16] and AutoPlanBench [17], which evaluate LLMs in natural-language or PDDL environments, by instead using character-string representations of 2D maps that are deliberately out-of-distribution for LLM training data. The paper explicitly distinguishes itself from prior LLM game-playing work [12, 37–40], which assesses whether models can play games, by isolating the traversal/planning component as the sole evaluated skill.

## Why It Matters / Open Questions

The benchmark reveals that even state-of-the-art models like GPT-4-Turbo (44.97%) and the reasoning model o1 (67.84%) remain far from competent planners on structured spatial tasks, providing a concrete, reproducible metric (GTB_Score) to track progress. Key limitations include static maps, a 4-action space, and a single fixed prompt, all of which constrain the difficulty ceiling and may advantage larger models that follow instructions more reliably. Open questions the paper raises include whether fine-tuning on GTB generalizes, how performance changes with dynamic environments (moving enemies, terminating tiles), and whether LLMs can generate their own state representations rather than receiving them as input.
