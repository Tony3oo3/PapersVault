## Problem

Urban science research suffers from fragmented data processing: studies on similar problems use different datasets, apply inconsistent preprocessing, and rarely share processed data, making benchmarking and iterative method improvement nearly impossible. Additionally, urban data exists in heterogeneous modalities (images, tables, trajectories, graphs) with non-uniform spatial granularities, making multi-modal fusion cumbersome and error-prone for researchers. These two issues collectively slow urban computing progress relative to fields like CV and NLP that benefit from standardized datasets.

## Input / Output

UDL accepts raw urban data in any of five structural forms (grid, graph, point, linestring, polygon) at arbitrary spatial resolutions (e.g., 0.01°, 0.02°, 0.05° grids) and temporal spans, then produces granularity-aligned, feature-fused data layers ready as direct model inputs. The pipeline preserves geographic coordinates throughout transformations, so outputs maintain spatial semantics. In the empirical cases, inputs include nightlight satellite imagery, population grids, road network graphs, POI points, and El Nino wind/temperature time series, while outputs range from predicted PM2.5 concentrations and built-up area class labels to administrative boundary clusters and anomaly scores.

## Method

UDL defines a four-stage data wrapping pipeline (raw source → standard data layer → granularity-aligned data → fused data) connected by three processing operations: Scheme Transformation (converting raw data into one of five standard structures and between structures via 8 predefined APIs like grid_to_graph or point_to_grid), Granularity Alignment (resampling a standard layer to a target spatial resolution), and Feature Fusion (aggregating cross-domain features at aligned coordinates). The five standard data structures—grid, graph, point, linestring, and polygon—capture the dominant organizational patterns of urban data, and all transformations exploit shared geographic coordinate information to avoid reprocessing from raw sources. The design is validated through four downstream tasks (PM2.5 prediction, built-up area classification, administrative boundary identification, El Nino anomaly detection) using classic supervised and unsupervised methods, demonstrating that combining multi-source features via UDL consistently improves performance over single-source baselines.

## Results

Across four downstream tasks, combining multi-modal urban features (enabled by UDL's unified pipeline) consistently outperforms single-feature baselines. For PM2.5 prediction in Shanghai, combining road network + nightlight + population with MLP improves R² from 0.199 (best single feature) to 0.417, and with XGBoost from 0.181 to 0.378. For built-up area classification in New York, combining all features with GBDT reaches 87.3% accuracy vs. 86.9% for the best single feature (population). For administrative boundary identification in NYC, adding road network and population to POI data with GMM nearly doubles IOU from 0.303 to 0.613.

## Baselines & Comparisons

This paper does not compare against competing data pipelines or architectures; instead, it benchmarks single-feature vs. multi-feature combinations to demonstrate UDL's fusion utility. In PM2.5 prediction, the best single feature (road intersection density) achieves R²=0.181 (XGBoost, Shanghai) while the full combination reaches R²=0.378, a 109% relative improvement. In built-up area classification, combining nightlight + SMOD + population with GBDT in Shanghai yields 79.4% accuracy vs. 76.7% for SMOD alone (+2.7 pp). For NYC boundary identification, POI alone gives IOU=0.303 with GMM, whereas adding road network and population raises it to 0.613 (+102%); however, in Shanghai, POI alone (F1=0.608, KNN) outperforms the full combination (F1=0.475), suggesting feature complementarity is region-dependent. For El Nino anomaly detection, the best AUC-ROC is 0.540 (CoLA with SP+ZW+MW), with the full feature set reaching 0.507 (OCGNN), indicating that for this task fewer, more physically relevant features suffice.

## Relation to Prior Work

This paper carves new ground by proposing a unified data pipeline (UrbanDataLayer) for urban science, drawing conceptual inspiration from standardized data infrastructure in other fields (ImageNet for CV, WikiText-103 for NLP) and from geospatial data standards like OGC. It departs from LibCity, the closest prior work, by expanding scope from traffic-only spatiotemporal prediction to five general urban data structures (grid, graph, point, linestring, polygon) and by adding processing steps—scheme transformation, granularity alignment, and feature fusion—that LibCity does not provide. Unlike OGC APIs, which standardize raw data release and access, UDL targets the full pipeline from raw heterogeneous sources to model-ready fused data.

## Why It Matters / Open Questions

UDL addresses a genuine bottleneck in urban computing: the absence of shared, reproducible benchmarks and the high cost of multi-modal data fusion, which has slowed the field relative to CV and NLP. By providing a unified API layer, it lowers the barrier for researchers (especially novices) to combine disparate urban data sources and build large-scale benchmarks, potentially enabling multi-modal urban foundation models. However, the empirical validation relies on classic ML methods (XGBoost, GBDT, KNN, GMM) rather than deep learning, and the anomaly detection results are weak (AUC near 0.5), leaving open whether the pipeline's benefits scale to more complex model architectures. The alignment mechanism is currently limited to geospatial coordinates, and extending it to temporal or semantic dimensions remains an open challenge.
