## Problem

Previous Demand-driven Navigation (DDN) benchmarks assume each demand instruction is satisfied by a single object and ignore individual user preferences, making them less reflective of real-life scenarios where demands often require coordinating multiple objects and where users have distinct preferences (e.g., preferring sparkling water over juice). This paper introduces the MO-DDN benchmark to address multi-object search with basic and preferred demand components, and proposes a method that leverages attribute features at multiple decision-making levels rather than relying on them in a single end-to-end pass.

## Input / Output

The agent receives RGB-D observations, its GPS+Compass pose, and a natural-language demand instruction split into a basic component and a preferred component (e.g., 'I need a comfortable place to play computer games, preferably with good lighting'). At each timestep it selects from seven discrete actions (MoveAhead, RotateRight, RotateLeft, LookUp, LookDown, Find, Done); the Find action automatically records all objects within a 1 m radius in the current field of view into a found list, which is then matched against predefined solution sets to compute basic and preferred success rates and SPL. Episodes terminate after at most 5 Find executions or 300 steps.

## Method

C2FAgent alternates between a coarse exploration phase and a fine exploration phase. In the coarse phase, GLEE detects objects in the RGB frame, projects them onto a merged point cloud, and the cloud is segmented into 2×2 m blocks; each block receives a score computed as a weighted sum (r_b, r_p) of cosine similarities between the block's object attribute features and the instruction's basic/preferred attribute features, and the agent navigates to the highest-scoring unvisited block. The attribute model maps both instructions and object categories into a shared discrete codebook space (128×768, initialized via K-means on CLIP-encoded language attributes) using an MLP encoder trained with five losses (Attribute, VQ, Commitment, Reconstruction, Matching) that enforce alignment between instruction and solution-object attributes. In the fine phase, an end-to-end module (Transformer Encoder fusing per-object CLIP visual features through the trained Obj MLP Encoder with instruction features from the Ins MLP Encoder, followed by an LSTM actor) is trained via imitation learning on ~50k short within-block trajectories to identify and report target objects. Two instruction-encoding branches are provided: an LLM branch (GPT-4 generates attribute phrases, CLIP encodes them) and a lightweight MLP branch (directly uses the trained Ins MLP Encoder), allowing deployment flexibility depending on LLM availability.

## Results

On the primary seen-scene/seen-task setting, C2FAgent (LLM branch) achieves 23.82% basic success rate (SR_b) and 14.28% preferred success rate (SR_p), with SPL_b of 7.94 and SPL_p of 5.80, outperforming all baselines across all four metrics. The MLP branch (no LLM at test time) achieves 18.58% SR_b and 12.45% SR_p, comparable to MOPA+LLM* (18.61% SR_b) while requiring only a single LLM call at the start versus 5.15 calls per episode for MOPA+LLM*. Performance degrades gracefully on unseen scenes and unseen tasks, where C2FAgent (LLM) still leads with 23.06% SR_b (unseen scene, seen task) and 15.88% SR_b (unseen scene, unseen task).

## Baselines & Comparisons

C2FAgent (LLM branch) outperforms all six baselines on every metric in the seen-scene/seen-task setting. Against the strongest modular baseline MOPA+LLM* (which has access to ground-truth object labels), C2FAgent gains +5.21 points on SR_b (23.82 vs. 18.61) and +4.94 points on SPL_b (7.94 vs. 3.00), indicating substantially more efficient navigation despite not using ground-truth labels. The MLP branch matches MOPA+LLM* on SR_b (18.58 vs. 18.61) without any test-time LLM calls, making it a practical deployment option. Against FBE+LLM*, C2FAgent (LLM) leads by +10.57 SR_b and +4.04 SPL_b, confirming that attribute-based block scoring is a better waypoint selector than frontier-based exploration guided by LLM. The end-to-end baselines (VTN, ZSON, DDN) trail by 10–17 SR_b points, with DDN's single-object attribute design providing only a modest advantage over generic ON methods. The SPL gap is particularly striking: C2FAgent's 7.94 SPL_b versus MOPA+LLM*'s 3.00 shows that attribute-guided exploration reaches relevant regions in far fewer steps.

## Relation to Prior Work

This paper extends DDN (Wang et al., NeurIPS 2024), which introduced demand-conditioned attribute features for single-object navigation, to a multi-object setting with a basic/preferred demand hierarchy. It departs from DDN's end-to-end architecture by proposing a coarse-to-fine modular agent (C2FAgent) that combines point-cloud-based block scoring (leveraging GLEE object detection and GPT-4/CLIP attribute features) with an imitation-learned fine exploration module. The discrete codebook for attribute features draws on VQ-VAE (Van Den Oord et al., 2017), and the coarse exploration phase aligns with the broader trend in ObjectGoal Navigation toward modular, map-based methods (MOPA, FBE) rather than purely end-to-end policies.

## Why It Matters / Open Questions

MO-DDN introduces a more realistic navigation benchmark where solutions involve multiple objects and personal preferences, addressing a gap between prior single-object DDN and real-world demands. The adjustable r_b/r_p weights offer a practical mechanism for users to trade off basic vs. preferred satisfaction, and the coarse-to-fine design cleanly separates foundation-model prior knowledge (coarse) from task-specific grounding (fine). Key limitations include the fixed number of attributes per instruction/object, the inability of the agent to autonomously decide when to stop (Done), and evaluation restricted to 300 tasks in HSSD scenes. Open questions include whether flexible attribute counts, real-world deployment without simulator ground-truth detection, and scaling to more complex multi-step task planning are feasible.
