## Problem

LLM-generated code is often functionally correct but exhibits significantly suboptimal efficiency, with execution times up to 45× and memory usage far exceeding canonical solutions. Prior work on LLM code generation has focused almost exclusively on correctness (pass@1), leaving a gap in methods that systematically improve the runtime and memory efficiency of generated code without sacrificing functional integrity.
![Teaser figure](../imgs/NEURIPS20242683/cropped_page21_idx2.webp)

## Input / Output

The framework takes a natural-language task description and an initial LLM-generated code snippet as input, then locally executes the code on open test cases to produce two line-granularity profiles: a per-line execution time profile (via Python's line_profiler) and a per-line memory usage profile (via memory_profiler). These profiles, rendered as tabular text with line numbers, hit counts, per-hit time, and memory increments, are concatenated into a structured prompt alongside the task description, test cases, and optimization rules. The output is a revised code snippet that preserves correctness on the test cases while reducing execution time and memory consumption.

## Method

EFFI-LEARNER is a model-agnostic, three-stage iterative self-optimization loop: (1) Code Generation, where an LLM produces an initial solution; (2) Overhead Profiling, where the code is executed locally and both line_profiler and memory_profiler capture per-line execution time and memory usage across all open test cases; (3) Code Refinement, where the LLM receives a prompt containing the task, test cases, current code, the full overhead profiles, and explicit optimization rules, and revises the code to target the identified bottlenecks (e.g., replacing O(n²) loops with O(n) reductions, substituting algorithms, or eliminating redundant allocations). The loop repeats for a configurable number of iterations (typically 5), with each round re-profiling the refined code. A key ablation shows that feeding line-level profiles is essential: unsupervised self-refine or result-aware self-refine (which only reports aggregate ET/MU/TMU) often degrades efficiency, whereas the granular per-line profiles enable the LLM to pinpoint and fix specific inefficient lines.

## Results

On EffiBench, EFFI-LEARNER achieves substantial efficiency gains across 16 open-source and 6 closed-source LLMs. Headline results include StarCoder2-15B reducing execution time (ET) from 0.93 s to 0.12 s (87.1% reduction) and total memory usage (TMU) from 22.02 to 2.03 Mb·s (90.8% reduction); DeepSeek-6.7B-Ins reducing max memory usage (MU) from 259.73 Mb to 36.97 Mb (85.8% reduction); and CodeLlama-70B reducing TMU from 203.92 to 14.53 Mb·s (92.9% reduction). On HumanEval and MBPP, consistent improvements of 5–30% in ET and 10–35% in TMU are observed across the CodeLlama family and other models.

## Baselines & Comparisons

EFFI-LEARNER is compared against two self-refinement baselines: Unsupervised Self-Refine (prompting the LLM to optimize code without any feedback) and Result-Aware Self-Refine (feeding only aggregate ET/MU/TMU metrics back to the LLM). On CodeLlama-70B, both baselines dramatically worsen efficiency—Unsupervised Self-Refine increases ET by 51.9%, MU by 154.9%, and TMU by 518.8%, while Result-Aware Self-Refine increases ET by 51.9%, MU by 157.8%, and TMU by 523.2%—whereas EFFI-LEARNER achieves 9.6% ET reduction, 75.9% MU reduction, and 92.9% TMU reduction. On GPT-3.5-Turbo-0301, Unsupervised Self-Refine reduces ET by only 11.1% but increases TMU by 98.7%, and Result-Aware Self-Refine reduces ET by 16.7% but still increases TMU by 24.1%; in contrast, EFFI-LEARNER achieves 22.2% ET reduction, 60.5% MU reduction, and 92.1% TMU reduction. The key differentiator is that EFFI-LEARNER provides line-level execution time and memory usage profiles, enabling targeted optimization rather than blind or aggregate-metric-driven refinement.

## Relation to Prior Work

This paper repurposes the iterative self-refinement paradigm (Self-Edit, Self-Refine, Reflexion) that has been applied to code *correctness* into a new setting: code *efficiency*. Prior feedback-driven methods (Self-Edit, ALGO, Self-Debug) use execution pass/fail signals or oracle comparisons to fix bugs, whereas EFFI-LEARNER feeds per-line execution-time and memory-usage profiles (from Python's line_profiler and memory_profiler) back to the LLM to guide algorithmic and structural optimizations. The evaluation builds on EffiBench's efficiency metrics (ET, NET, MU, NMU, TMU, NTMU) and extends them to HumanEval and MBPP via EvalPlus private test cases. The paper positions itself as the first method to systematically improve the efficiency of LLM-generated code across a broad set of open- and closed-source models.

## Why It Matters / Open Questions

The practical impact is significant: LLM-generated code is routinely 1.7×–45× slower than canonical solutions, and EFFI-LEARNER closes much of that gap (up to 87–92% reductions in ET/TMU on the worst cases) without requiring model retraining. Key limitations include Python-only evaluation, a minor pass@1 drop (0–0.5%) due to incomplete public test coverage, and the token/time overhead of multi-iteration profiling. Open questions include generalization to other languages, whether domain-specific optimization knowledge can further improve results, and whether the approach transfers to non-algorithmic code (e.g., data pipelines, ML training loops) where profiling signals may be less informative.
