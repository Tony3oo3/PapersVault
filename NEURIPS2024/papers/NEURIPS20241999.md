## Problem

Complex LLM applications (agents, tree-of-thought, multi-turn chat, structured output pipelines) require multiple dependent generation calls with control flow, yet existing inference engines treat each call independently, discarding reusable KV caches and decoding constrained outputs one token at a time. Additionally, programming these multi-call workflows requires tedious string manipulation, brittle output parsing, and manual parallelism control, making even simple programs hard to read and maintain.
![Teaser figure](../imgs/NEURIPS20241999/cropped_page1_idx0.webp)

## Input / Output

SGLang programs are written in Python using primitives (gen, select, fork, join, extend, image, video) that operate on a prompt state managed as an asynchronous stream. Inputs include text prompts, image/video files (hashed for KV cache keying), and regular-expression or JSON-schema constraints that guide decoding. Outputs are generated text, structured JSON conforming to the specified regex, highest-probability selections from a candidate list, and results from parallel forked branches that can be merged back into the main prompt state via Python control flow.

## Method

SGLang combines a Python-embedded DSL with a co-designed runtime (SRT) that applies three key optimizations. First, RadixAttention maintains all KV caches in a radix tree with LRU eviction and reference counting, enabling automatic multi-level prefix sharing across chained calls, forked branches, and concurrent requests; a cache-aware scheduler (longest-shared-prefix-first, proven optimal offline via DFS equivalence) maximizes hit rate. Second, a compressed finite state machine merges consecutive singular-transition edges in the regex-derived FSM into single edges, allowing multiple tokens to be decoded in one forward pass during constrained generation. Third, API speculative execution extends the first generation call past its stop condition and matches the extra tokens against subsequent primitives, eliminating redundant API calls for black-box models. The frontend interpreter sends fork hints to the runtime to pre-insert shared prefixes into the radix tree, exemplifying the frontend-runtime co-design that yields up to 6.4× throughput gains over vLLM, Guidance, and LMQL.

## Results

SGLang achieves up to 6.4× higher throughput and up to 3.7× lower latency compared to state-of-the-art inference systems (vLLM, Guidance, LMQL) across diverse workloads including MMLU, HellaSwag, ReAct agents, Tree-of-Thought, JSON decoding, multi-turn chat, and DSPy RAG pipelines on Llama-7B/70B, Mixtral-8x7B, and LLaVA models. Cache hit rates range from 50% to 99% across benchmarks, with the cache-aware scheduling policy achieving 96% of the theoretical optimal hit rate on average. The compressed finite state machine alone provides a 1.6× throughput boost on JSON decoding, and API speculative execution reduces input token costs by approximately 3× on GPT-3.5. In production deployment at Chatbot Arena, SGLang observed 52.4% and 74.1% RadixAttention cache hit rates for LLaVA-Next-34B and Vicuna-33B respectively, reducing first-token latency by 1.7× on average.

## Baselines & Comparisons

SGLang outperforms all three baselines across every benchmark tested. Against vLLM (the strongest baseline), SGLang achieves up to 6.4× higher throughput and 3.7× lower latency, with the largest gains on workloads with heavy prefix sharing (MMLU, HellaSwag, multi-turn chat) and structured output (JSON decoding). Against Guidance, SGLang wins by a wide margin; Guidance is excluded from five of the eight benchmarks due to lack of batching and parallelism support, and even where included it trails significantly. Against LMQL, SGLang also dominates; LMQL is excluded from the same five benchmarks due to slow token-level processing and an unoptimized Hugging Face Transformers backend. The speedup generalizes to larger models with tensor parallelism (Mixtral-8x7B on 8×A10G, Llama-70B on 4×A100) and to multi-modal models (up to 6× throughput on LLaVA image/video benchmarks vs. Hugging Face Transformers baseline). The ablation study confirms that each component (RadixAttention tree structure, cache-aware scheduling, frontend parallelism, frontend hints, compressed FSM) contributes meaningfully, with disabling any single component degrading performance.

## Relation to Prior Work

SGLang extends the FSM-based constrained decoding of Willard & Louf [54] by compressing singular-transition edges to enable multi-token decoding in a single forward pass. On the inference side, it departs fundamentally from vLLM's paged attention [23] and concurrent KV-cache reuse efforts (PromptCache [12], HydraGen [18], ChunkedAttention [58]) by treating the KV cache as a tree-based LRU cache managed via a radix tree, rather than discarding per-request caches or handling only simple prefix-sharing cases. The programming model is positioned alongside LMQL [4] and Guidance [13] as a low-level DSL, but SGLang's key distinction is the co-design of the frontend language with a purpose-built runtime (SRT) that enables cache-aware scheduling, frontend hints for fork operations, and compressed FSM decoding—optimizations unavailable in the baselines' generic inference backends.

## Why It Matters / Open Questions

The 6.4× throughput gain, validated across Llama-7B/70B, Mixtral-8x7B, and multi-modal LLaVA models on A10G/A100 hardware, plus production deployment in Chatbot Arena (52–74% cache hit rates, 1.7× first-token latency reduction), makes RadixAttention a likely standard component in future LLM serving stacks. Open questions include resolving starvation in cache-aware scheduling, extending the radix tree across DRAM/disk memory hierarchies, enabling fuzzy semantic matching beyond exact token prefixes, and developing reliable compiler-mode optimizations (the GPT-4-assisted code movement is promising but fragile). The frontend-runtime co-design principle—where the interpreter sends fork hints and the runtime performs prefix matching—suggests a broader pattern for LLM systems where program structure should inform low-level scheduling.
