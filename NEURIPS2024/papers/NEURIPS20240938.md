## Problem

Most real-world data exists in unstructured form (images, dialogs, reviews, audio), yet traditional SQL engines require pre-defined schemas and structured columns to perform analytics. While LLMs can flexibly interpret unstructured content, naively sweeping an entire database with LLM calls is prohibitively expensive, and existing approaches like RAG or full-text search cannot handle complex semantic aggregation queries. The paper asks: how can one perform flexible, scalable analytics over unstructured databases without full database scans?

## Input / Output

The engine accepts UQL queries—a SQL dialect where WHERE, SELECT, and GROUP BY clauses can embed free-form natural language specifications (e.g., WHERE "the customer asked to cancel the flight") alongside standard structured predicates. The underlying database is a table with heterogeneous row elements (text, images, audio, numerics) but homogeneous columns. Outputs include aggregated statistics (COUNT, SUM, AVG) with importance-weighted corrections for stochastic tables, retrieved row indices for semantic retrieval, and grouped tuples of (derived_attribute, count) for abstraction queries. A budget parameter B caps the number of rows the LLM may inspect, trading off accuracy for cost.

## Method

UQE adapts two classical database techniques—indexing and compilation—to the LLM setting. For indexing, aggregation queries use stratified sampling over FAISS-clustered multimodal embeddings with normalized importance weights to produce unbiased estimators of COUNT/SUM/AVG without scanning all rows; non-aggregation retrieval queries use an online active-learning loop where a cheap surrogate model g̃ (trained via logistic regression on observed LLM labels) sequentially selects the most informative rows under budget B, balancing exploration and exploitation. For compilation, a planner enumerates clause orderings and kernel fusions (e.g., WHERE+LIMIT early termination, SELECT+GROUPBY shared LLM calls) to minimize total LLM invocations, with per-kernel cost estimates guiding the search. Each SQL clause is implemented as a kernel that reads and produces either concrete or stochastic tables, and the final instantiation step generates model-specific prompts (system context, column descriptions) for the target LLM backend.

## Results

On conditional aggregation, UQE achieves 5.75%±3.43% relative error on IMDB (vs. 49.02% for lc-gpt-4-turbo and 56.05% for lc-claude-3-opus) at ~$0.01 per query, a 20×+ cost reduction. On semantic retrieval, UQE reaches 0.978 F1 on IMDB (vs. 0.397 for lc-gpt-4-turbo, 0.556 for lc-claude-3-opus, and 0.875 for MIPS), and 0.940 F1 on ABCD account_access (vs. 0.045 for lc-gpt-4-turbo). On abstraction and aggregation, UQE achieves 0.111 EMD on AirDialog (vs. 0.143 for lc-gpt-4-turbo) at $0.04 cost (vs. $0.21–$0.37). Across all tasks, UQE consistently outperforms baselines while reducing cost by an order of magnitude or more.

## Baselines & Comparisons

Against long-context LLMs (lc-gpt-4-turbo, lc-claude-3-opus), UQE wins decisively on every dataset and task: on IMDB aggregation, UQE's 5.75% relative error is roughly 8–10× lower than the 49–56% of long-context baselines, while costing ~20–60× less per query. On semantic retrieval, UQE's 0.978 F1 on IMDB far exceeds lc-gpt-4-turbo (0.397) and lc-claude-3-opus (0.556), and the gap is even more extreme on ABCD where long-context LLMs score near zero (0.023–0.082) versus UQE's 0.935–0.940. Against the UDF baseline (Cheng et al., which treats LLM calls as SQL user-defined functions without sampling or compilation), UQE consistently improves: e.g., 5.75% vs. 13.67% error on IMDB aggregation, and 0.978 vs. 0.505 F1 on IMDB retrieval, confirming the value of stratified sampling and kernel fusion. Against MIPS (max inner-product search on the same embeddings), UQE wins on reasoning-heavy queries (e.g., Clevr obj_count<4: 0.850 vs. 0.023; AirDialog cancel: 0.741 vs. 0.066) but is slightly behind on embedding-friendly queries like ABCD account_access (0.940 vs. 0.961), where semantic similarity alone is sufficient.

## Relation to Prior Work

This paper builds most directly on Cheng et al. [11], which augments SQL semantics with LLMs as user-defined functions (UDFs) for table analytics, but departs from it by replacing the full-database-scan execution model with statistically sound sampling (stratified sampling for aggregation, online active learning for retrieval) and a lightweight compilation system that fuses and reorders clause execution to minimize LLM calls. Conceptually, it transplants two classical database-engineering ideas—indexing and query compilation—into the unstructured-data setting, where 'indexing' becomes a proxy learned from embeddings and 'compilation' becomes prompt orchestration over an LLM. The paper also positions itself against RAG (limited to retrieval, not aggregation) and long-context LLMs (expensive and unreliable for counting over large collections), and draws on Bayesian optimization and importance sampling literature for the online-learning and variance-reduction components.

## Why It Matters / Open Questions

The paper addresses a practically important gap: most real-world data (conversations, images, reviews) is unstructured, yet businesses need SQL-like analytics (COUNT, GROUP BY, filtered retrieval) over it without expensive preprocessing into a fixed schema. The demonstrated 10× error reduction and 20× cost reduction over long-context LLM baselines, along with four new multimodal benchmarks, make this a useful reference point for anyone building LLM-powered data analytics pipelines. Key open questions include scaling to truly large databases (current experiments use ≤50K rows), supporting table joins and more aggregation types (e.g., MAX), automating the selection of LLM backends and sampling hyperparameters, and reducing the latency of the online-learning loop for retrieval queries.
