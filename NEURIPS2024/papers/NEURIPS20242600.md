## Problem

While LLM-based code generation and repair is an extremely active research area, automated test generation—particularly for reproducing real-world issues from natural language descriptions—remains largely unexplored. No large-scale, diverse test-generation benchmark exists for Python, and Code Agents have not been evaluated in this setting. The paper also highlights that without suitable tests, the overhead of manual verification outweighs the benefits of automatic code repair, since state-of-the-art methods resolve only ~20% of issues.
![Teaser figure](../imgs/NEURIPS20242600/cropped_page1_idx0.webp)

## Input / Output

Each instance provides a GitHub issue description (averaging 318 words, up to 8756) alongside a full Python repository (~1500 files, ~337K lines of code). The system must produce a patch adding or modifying unit test functions, formatted either as a unified diff or the paper's proposed fault-tolerant custom diff that allows whole-function insertion/replacement with fuzzy location matching. A generated test is judged successful (F→P) if it fails on the original codebase but passes after the golden code patch is applied; the paper additionally measures change coverage over executable lines modified by the golden patch.

## Method

SWT-Bench transforms the SWE-Bench code-repair dataset into a test-generation benchmark by using the golden code patch as the evaluation oracle: a test reproduces the issue if it fails before and passes after the patch is applied. The paper proposes a fault-tolerant custom diff format that lets LLMs insert or rewrite entire functions with approximate line numbers, boosting well-formed patch rates from 48.6% (unified diff) to 89.5%. For evaluation, they adapt three Code Agents (SWE-Agent, Aider, AutoCodeRover) by replacing 'fix the bug' instructions with 'create unit tests that reproduce the issue,' and compare against direct LLM prompting (zero-shot, pass@5) and the domain-specific LIBRO method. The key finding is that general-purpose Code Agents outperform dedicated test-generation methods, with SWE-Agent+ achieving 18.5% success rate, and that generated tests serve as an effective filter for proposed code fixes, more than doubling SWE-Agent's precision to 47.8%.

## Results

On SWT-Bench-Lite (276 instances), SWE-AGENT+ achieves the highest success rate S of 18.5% among non-oracle methods, with 85.5% patch well-formedness (W) and 19.2% fail-to-pass (F→P) rate. The oracle PASS@5 baseline reaches S=20.3%, establishing the upper bound. Code Agents designed for code repair (SWE-AGENT at S=15.9%, AIDER at S=12.7%) outperform the domain-specific test generation method LIBRO (S=14.1%) and the zero-shot baselines (ZEROSHOT at S=3.6%, ZEROSHOTPLUS at S=9.4%). An ensemble of the four best methods solves 71% more instances than the best single method, and filtering SWE-AGENT's code fixes with self-generated tests more than doubles its precision from ~20% to 47.8%.

## Baselines & Comparisons

SWE-AGENT (S=15.9%) outperforms the state-of-the-art test generation method LIBRO (S=14.1%) by 1.8 percentage points in success rate, despite LIBRO being specifically designed for issue reproduction while SWE-AGENT was originally built for code repair. SWE-AGENT also surpasses AIDER (S=12.7%) and AUTOCODEROVER (S=9.1%), with the gap widening when SWE-AGENT is instructed to execute its own tests (SWE-AGENT+, S=18.5%). In terms of change coverage on successful instances, SWE-AGENT+ achieves 69.4% ΔC^S, exceeding LIBRO (64.2%), AIDER (59.5%), and AUTOCODEROVER (61.3%). The paper also shows that test generation and code repair are distinct tasks: SWE-AGENT solves 44 SWT-Bench instances but only 7 overlap with its 50 SWE-Bench solutions (p=72.8%), indicating no per-sample correlation. Finally, using generated tests as a filter for code fixes more than doubles SWE-AGENT's precision to 47.8%, demonstrating the practical value of the test generation capability.

## Relation to Prior Work

This paper transforms the SWE-Bench code repair benchmark into a test generation benchmark (SWT-Bench) by repurposing golden patches as evaluation oracles: a generated test 'reproduces' an issue if it fails before and passes after the golden patch is applied. It adapts three Code Agents originally designed for code repair (SWE-Agent, Aider, AutoCodeRover) to the test generation task by modifying their instructions, and compares them against the state-of-the-art specialized test generation method LIBRO. The key conceptual departure from prior work is the observation that any code repair instance can be converted into a test generation instance, enabling fine-grained evaluation via fail-to-pass rates and change coverage metrics that are unavailable in the code repair setting.

## Why It Matters / Open Questions

SWT-Bench provides the first large-scale Python benchmark for issue-reproducing test generation, filling a gap where prior datasets were Java-only (Defects4J) or function-level. The finding that generated tests can double the precision of code repair agents (from ~20% to 47.8%) highlights a practical pathway to making automatic code repair more trustworthy. Open questions include whether results generalize beyond Python, how to handle data contamination from pre-training on GitHub issues, and whether the modest success rates (~18.5% best) will improve as models and agents advance. The paper also reveals that test generation and code repair are uncorrelated per-sample, suggesting they are genuinely distinct capabilities.
