## Problem

Training dense retrievers with InfoNCE loss requires large batches to provide sufficient in-batch negatives, creating a hardware bottleneck that limits research and deployment. Existing memory reduction methods—gradient accumulation, GradCache, and pre-batch negatives—either reduce the effective number of negatives, incur significant computational overhead, or suffer from training instability due to gradient norm imbalance between the dual encoders. No prior method simultaneously achieves memory efficiency, training stability, and performance that surpasses the high-resource (large-batch) baseline.
![Teaser figure](../imgs/NEURIPS20240375/cropped_page1_idx0.webp)

## Input / Output

The method consumes query text and passage text encoded by BERT-based dual encoders, producing dense vector representations used for nearest-neighbor retrieval over a passage corpus. Under memory constraints (11 GB or 24 GB VRAM), the local batch size is reduced (e.g., 8 or 32), but the dual memory bank expands the effective similarity matrix to (N_local + N_memory) × (N_local + N_memory), yielding more negatives than the original total batch. The memory bank stores only final representations (not intermediate activations), adding at most ~12 MB of overhead even at N_memory = 5096.

## Method

CONTACCUM combines gradient accumulation with a dual FIFO memory bank that caches both query and passage representations from previous accumulation steps. At each step, the current local-batch representations are concatenated with stop-gradient-applied memory bank entries to form an enlarged similarity matrix, increasing the number of negative passages to N_local + N_memory^p − 1, which can exceed the total-batch count. The key theoretical insight is that using memory banks of equal size for queries and passages (N_memory^q = N_memory^p) prevents a gradient norm imbalance between the two encoders—identified as the root cause of instability in prior single-bank methods like pre-batch negatives—thereby stabilizing dual-encoder training. Because memory bank entries carry no stored activations, backpropagation flows only through the current local-batch representations, keeping the additional memory cost negligible while the enlarged softmax provides richer contrastive signal.

## Results

Under the most constrained setting (11 GB VRAM, local batch size 8, 16 accumulation steps), CONTACCUM achieves NQ Top@20 = 80.1, TriviaQA Top@20 = 79.8, WebQ Top@20 = 75.4, TREC Top@20 = 83.3, and MS MARCO NDCG@20 = 39.1, surpassing the 80 GB DPR baseline (NQ Top@20 = 79.4, TriviaQA Top@20 = 79.5, WebQ Top@20 = 74.7, TREC Top@20 = 82.0, MS MARCO NDCG@20 = 35.1) on 18 out of 24 reported metrics, with gains up to 4.9 points. CONTACCUM also outperforms GradCache (the strongest memory-reduction baseline) on nearly all metrics while completing each weight update 34% faster. Performance remains robust across memory budgets: the gap between 11 GB and 24 GB settings is minimal for CONTACCUM, whereas DPR and GradAccum show noticeable improvements with more memory.

## Baselines & Comparisons

Against the high-resource DPR baseline (80 GB, batch size 128), CONTACCUM running on a single 11 GB GPU wins on 18 of 24 metrics, with the largest gap on MS MARCO NDCG@20 (39.1 vs. 35.1, +4.0) and TREC Top@20 (83.3 vs. 82.0, +1.3). Compared to GradCache, the strongest existing memory-reduction method, CONTACCUM improves NQ Top@20 from 79.5 to 80.1, TriviaQA Top@20 from 79.4 to 79.8, and MS MARCO NDCG@20 from 34.9 to 39.1, while also being 34% faster per weight update (GradCache is 93% slower than GradAccum at N_total=512, whereas CONTACCUM is only 26% slower). Against plain GradAccum, CONTACCUM gains 3.0 points on NQ Top@20 (80.1 vs. 77.1) and 8.0 points on MS MARCO NDCG@20 (39.1 vs. 31.1), confirming that the dual memory bank's additional negative samples are the primary source of improvement. The ablation in Table 2 further shows that removing the query memory bank (reducing to a passage-only bank like pre-batch negatives) causes an 8-point drop in NQ Top@20, attributing the gain to the gradient-norm-balancing effect of the dual bank.

## Relation to Prior Work

CONTACCUM sits at the intersection of three research threads: DPR's InfoNCE-based dual-encoder training with in-batch negatives, GradCache's decomposition of backpropagation to approximate large batches under memory constraints, and the FIFO memory bank structures originally developed for vision contrastive learning. The key departure from prior IR work (notably pre-batch negatives by Lee et al.) is the introduction of a *dual* memory bank caching both query and passage representations, rather than only passage representations. The paper's theoretical contribution extends Gao et al.'s gradient analysis to the memory-bank setting, identifying a gradient norm imbalance between the two encoders as the root cause of training instability — a diagnosis that prior work attributed solely to rapid representation drift in early epochs.

## Why It Matters / Open Questions

The practical impact is significant for the dense retrieval community: CONTACCUM enables training on a single 11GB consumer GPU while surpassing 80GB high-resource DPR baselines, democratizing access to competitive retriever training. The gradient norm imbalance diagnosis provides a general diagnostic tool for anyone training asymmetric dual-encoder models with memory banks. Open questions include whether the method transfers to uni-encoder pre-training stages (e.g., ConDenser, ANCE), whether the softmax bottleneck can be mitigated, and whether the findings generalize beyond BERT-based DPR to larger or generative retriever architectures.
