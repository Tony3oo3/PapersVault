## Problem

LLMs perform poorly on aggregative queries that require stitching information scattered across one or more texts and performing complex computations on the extracted data, yet no dedicated benchmark isolates this end-to-end capability. The root causes of model failure in this pipeline—whether in information extraction, code generation, or execution—remained unexplored.
![Teaser figure](../imgs/NEURIPS20241097/cropped_page0_idx0.webp)

## Input / Output

The model receives a natural language aggregative instruction (e.g., 'Calculate the sum of the years...') and a text passage, and must produce a single numerical answer evaluated by exact match. Critically, the structured table that underlies the computation is NOT provided as input; the model must implicitly identify and organize the relevant data from the text. Intermediate artifacts (a CSV table and a Pandas command) are available in the dataset for decomposition analysis but are not part of the model's input.

## Method

The IE as a tool framework decomposes the TACT task into three sequential tool invocations, each implemented as a separate few-shot prompted LLM: (1) a table-generation tool that extracts a CSV table from the text and instruction, (2) a Pandas command-generation tool that writes a command over the generated table, and (3) a final answer step where an LLM or code interpreter executes the command to produce the numerical result. This differs from in-context IE (where table, command, and answer are generated in a single prompt) by isolating each sub-task into its own prompted call, reducing context interference. The paper also introduces the TACT benchmark itself—124 expert-curated examples built on InstructIE with gold tables and Pandas commands—and provides a decomposition analysis showing that table generation, Pandas command generation, and execution each present substantial independent challenges, with even the strongest models (GPT-4o, Claude 3.5 Sonnet) achieving below 38% exact match on the full task.

## Results

On TACT (124 examples), all contemporary LLMs achieve below 38% exact-match accuracy under standard prompting (Generic or CoT). The IE as a tool framework with Pandas improves the best models to ~42% (GPT-4o: 42.2%, Claude 3.5 Sonnet: 42.1%, Gemini-Ultra: 41.4%), representing up to a 12% absolute gain over the Generic baseline. When gold tables and Pandas commands are provided (upper bound), Claude 3.5 Sonnet reaches 74.6% and GPT-4o reaches 74.1%, revealing substantial headroom in the intermediate table-generation and command-generation steps. Smaller models (Gemma-7b, Mistral-7b, Llama-2-13b) remain below 15% even with gold inputs, indicating fundamental capability gaps.

## Baselines & Comparisons

The paper compares five prompting strategies (Generic, CoT, In-context IE, IE as a tool, and IE as a tool with gold inputs) rather than external methods. IE as a tool with Pandas consistently outperforms Generic and CoT across all models: for GPT-4o, it improves from 30.1% (Generic) to 42.2% (+12.1 pp); for Claude 3.5 Sonnet, from 28.6% to 42.1% (+13.5 pp). CoT provides modest gains over Generic (e.g., +7.6 pp for GPT-4o) but is notably worse than IE as a tool. In-context IE (generating table and command within a single prompt) underperforms IE as a tool for larger models (e.g., Gemini-Pro drops from 34.7% CoT to 12.3% In-context IE), suggesting that separating tool invocations is critical. The gap between IE as a tool and the Gold Table+Pandas upper bound (e.g., 42.2% vs. 74.1% for GPT-4o) indicates that the remaining 32 pp of error is attributable to imperfect table and command generation, pointing to clear targets for future tool refinement.

## Relation to Prior Work

This paper builds directly on InstructIE (Jiao et al., 2023), repurposing its text-table pairs as the substrate for a new aggregative reasoning benchmark. Conceptually, it sits at the intersection of three established threads: text-to-table information extraction, semantic parsing (natural language to executable code), and tool-augmented LLM inference (Toolformer, TALLM, Gorilla). However, unlike prior tool-augmented approaches that learn when and how to invoke tools, IE as a tool employs a fixed, static pipeline (table generation → Pandas command → execution), making it a simpler but more targeted instantiation. The task itself extends numerical reasoning over text (DROP, FinQA) by explicitly requiring the model to perform information extraction into a structured intermediate representation before computation.

## Why It Matters / Open Questions

The finding that all frontier LLMs score below 38% on TACT, and that even Pandas command generation accuracy is only ~10% for the best models (Table 4), reveals a substantial and previously underappreciated gap in LLMs' ability to bridge natural language instructions to executable data operations. The large gap between IE as a tool (~42%) and Gold Table+Pandas (~74%) for GPT-4o/Claude suggests that improving the intermediate tools (table extraction, code generation) is the key bottleneck, pointing toward a clear research agenda. Limitations include the small dataset size (124 examples), restriction to numerical tasks, and sequential error propagation in the tool pipeline, which constrains the generalizability of conclusions.
