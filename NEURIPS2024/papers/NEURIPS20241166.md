## Problem

Existing coding benchmarks like HumanEval are small (164 problems), single-language, and have been public since 2021, making them vulnerable to training-set contamination. There is no comprehensive, multi-language, multi-task benchmark that covers the full spectrum of real-world coding assistance (debugging, implementation, optimization, conceptual understanding) while also mitigating data leakage. Additionally, no systematic study has examined whether LLMs used as judges exhibit self-preference bias specifically in code evaluation contexts.

## Input / Output

For the coding assistance evaluation, each LLM receives a raw Stack Overflow question (text plus code snippets, up to 16,000 characters) with no supplementary prompting, and generates a response capped at 2048 tokens at temperature T=0.01. For the LLM-as-a-Judge evaluation, the judge model receives the question, the candidate answer, and optionally the highest-voted accepted Stack Overflow answer as a reference, then outputs a discrete acceptance score from a 4-level rubric (0–3). The primary reported metrics are the acceptance rate (fraction of scores ≥ 2) for coding tasks and the binarized accuracy against human-annotated acceptability labels for judge tasks.

## Method

The paper curates two complementary benchmarks from Stack Overflow dumps: StackEval (925 questions spanning 25 languages and four task types, sampled Jan 2018–Sep 2023) and StackUnseen (questions from Sep 2023–May 2024, updated semi-annually to prevent train-test leakage). Evaluation uses an LLM-as-a-Judge framework with a 4-level rubric (Optimal, Acceptable, Partially Unacceptable, Fully Unacceptable) inspired by Stack Overflow's accepted-answer concept. Four prompt configurations are compared for judging: question+answer only, +chain-of-thought, +reference answer, and +both. A key finding is that including the reference answer consistently improves judge accuracy across all models (e.g., GPT-4 Turbo rises from 78.3% to 83.6%), while chain-of-thought alone slightly degrades performance, suggesting structured reasoning without an anchor leads to overthinking. Self-preference is tested via Wilcoxon Signed Rank Test comparing each model's scores on its own generations versus others'; in the presence of reference answers, no model shows statistically significant self-preference (all p > 0.05), indicating that objective anchors effectively eliminate this bias in coding domains.

## Results

On the StackEval benchmark (925 questions, Jan 2018–Sep 2023), O1 Preview achieves the highest acceptance rate at 95.5%, followed by Gemini-1.5 Pro (90.7%) and Claude-3.5 Sonnet (89.5%). On the more challenging StackUnseen benchmark (Sep 2023–May 2024), O1 Preview again leads at 83.0%, with Claude-3.5 Sonnet at 76.3% and Gemini-1.5 Pro at 71.6%. For the LLM-as-a-Judge benchmark, GPT-4 Turbo with Chain-of-Thought and reference answer achieves the highest evaluation accuracy at 84.4%, while Claude-3.5 Sonnet reaches 82.8%. Across all models, acceptance rates drop significantly on StackUnseen (e.g., Mistral Large 2 falls from 81.9% to 52.6%), with higher-capacity and reasoning-chain models showing the smallest degradation.

## Baselines & Comparisons

O1 Preview (OpenAI) dominates both benchmarks, achieving 95.5% on StackEval and 83.0% on StackUnseen, outperforming the next-best model by 4.8 and 6.7 percentage points respectively. On StackEval, Gemini-1.5 Pro (90.7%) edges out Claude-3.5 Sonnet (89.5%), but on StackUnseen the ranking inverts with Claude-3.5 Sonnet (76.3%) surpassing Gemini-1.5 Pro (71.6%), suggesting Claude generalizes better to recent content. Open-source models Llama3.1-70B Nemotron (86.9% StackEval) and WizardLM-2 8x22B (80.2%) are competitive with proprietary offerings, narrowing the gap to within ~9 and ~15 points of the top model respectively. The largest performance gap appears on StackUnseen, where Mistral Large 2 (52.6%) and WizardLM-2 8x22B (50.5%) trail O1 Preview by over 30 points, indicating that reasoning-chain architectures and higher model capacity are critical for handling emerging coding challenges. In the LLM-as-a-Judge setting, GPT-4 Turbo (84.4%) outperforms Claude-3.5 Sonnet (82.8%) and WizardLM-2 8x22B (81.5%) with the CoT+Reference configuration, while Gemini-1.5 Pro lags significantly at 74.9%.

## Relation to Prior Work

This paper extends the LLM-as-a-Judge paradigm (Zheng et al., 2023) from general NLP evaluation to coding-specific tasks, introducing a structured rubric (acceptance score 0–3) and a dynamic companion benchmark (StackUnseen) to mitigate the data-leakage problem that plagues static coding benchmarks like HumanEval and SWE-Bench. It departs from prior multilingual coding benchmarks (MultiPL-E, HumanEval-X, MBXP) by covering not only code generation but also debugging, optimization, and conceptual understanding across 25 languages, and by sourcing questions from real Stack Overflow interactions rather than synthetic problems. The self-preference analysis builds on Panickssery et al. (2024) but is the first to examine this bias specifically in coding contexts where objective correctness criteria exist.

## Why It Matters / Open Questions

The StackEval/StackUnseen pair provides a practical, continuously updated evaluation suite for coding-assistance LLMs that addresses the critical data-leakage gap in existing benchmarks, and the finding that reference answers effectively eliminate self-preference bias in coding judges offers a concrete, low-cost mitigation strategy for practitioners deploying LLM-based code review. The significant performance drop on StackUnseen (e.g., O1 Preview: 95.5% → 83.0%) quantifies the generalization gap to emerging technologies, a concern that will grow as models are deployed in production. Open questions include whether the one-shot evaluation protocol underestimates agent-based systems that can execute and verify code, whether the Stack Overflow community bias toward mainstream languages limits coverage of niche paradigms, and whether the LLM-as-a-Judge accuracy (~84%) is sufficient for high-stakes code review without human oversight.
