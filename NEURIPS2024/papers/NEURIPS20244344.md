## Problem

Despite a surge of efficient data attribution methods (Influence Functions, TracIn, RPS, TRAK), no comprehensive library exists to unify their APIs, provide reusable low-level building blocks, and enable fair benchmarking across diverse settings. Existing libraries either focus on computationally infeasible game-theoretic methods, lack benchmark components, or are restricted to a single framework and metric, hindering standardization and accelerating research in the field.

## Input / Output

The library consumes a standard PyTorch training pipeline: a loss function defined via torch.func.functional_call, a model with its state_dict checkpoints, and training/test DataLoaders. Users define an AttributionTask object and instantiate a method-specific Attributor (e.g., IFAttributorCG, TRAKAttributor), then call attributor.attribute(train_loader, test_loader) to obtain a vector of per-training-sample attribution scores for each test point. For benchmark evaluation, the library also ships pre-trained model checkpoints (5000 LOO models for MNIST, 100 half-dataset models for LDS) so users can compute ground-truth metrics without costly retraining.

## Method

dattri is structured around three design pillars: (1) a unified API layer where helper decorators abstract away access to internal model gradients and hidden representations, requiring only a few lines of code change to integrate any attribution method into an existing PyTorch pipeline; (2) modularized low-level utility functions in dattri.func (built on torch.func for higher-order derivative operations) and dattri.model_utils, providing HVP, multiple IHVP solvers (CG, LiSSA, Arnoldi), random projection via fast_jl, and dropout ensemble activation; (3) a benchmark suite spanning six settings (LR/MLP on MNIST-10, ResNet-9 on CIFAR-2/CIFAR-10, Music Transformer on MAESTRO, NanoGPT on Shakespeare) evaluated with LOO correlation, LDS (Spearman rank correlation over 50 half-dataset models), and noisy-label-detection AUC. The library implements nine algorithms across four families—IF (Explicit, CG, LiSSA, Arnoldi), TracIn (TracInCP, Grad-Dot, Grad-Cos), RPS-L2, and TRAK (with 1/10/50-model ensembling)—and demonstrates that IF excels on linear models while TRAK with ensembling achieves the strongest non-linear and generative-setting performance.

## Results

The benchmark reveals a clear split: IF variants (Explicit, CG, LiSSA) achieve the best LOO and LDS scores on the linear LR/MNIST-10 setting (rated '++'), while TRAK-50 achieves the best LDS on the non-linear MLP/MNIST-10 setting. For larger models (ResNet-9/CIFAR-2, Music Transformer/MAESTRO, NanoGPT/Shakespeare), IF methods are computationally infeasible (OOM), and only TRAK with ensembling (TRAK-10/50) achieves non-trivial LDS. On noisy label detection (AUC), most methods exceed 0.5 on small settings, but on ResNet-9/CIFAR-10 only TRAK maintains non-trivial performance while all others drop significantly.

## Baselines & Comparisons

The paper benchmarks nine data attribution algorithms across four families on six model/dataset combinations. IF variants (Explicit, CG, LiSSA) dominate on the linear LR/MNIST-10 setting for all three metrics (LOO, LDS, AUC), but degrade to random-level performance on non-linear models, consistent with known fragility of influence functions for non-convex models. TRAK is the only method that achieves '++' (much better than random) on both linear and non-linear settings for LDS and AUC, and is the only method feasible on the three largest models (ResNet-9, Music Transformer, NanoGPT) where IF methods hit OOM. TracInCP and Grad-Dot provide moderate performance ('+' on most non-linear metrics) at much lower computational cost than IF, while Grad-Cos is theoretically useless for noisy label detection (self-influence is always 1). RPS-L2 is the fastest method (1.08s on MLP/MNIST-10 vs. 455s for Arnoldi) but offers only moderate accuracy. Overall, TRAK with ensembling (TRAK-50) is the strongest single method across settings, while IF remains best for small linear models.

## Relation to Prior Work

This paper builds on the four major families of efficient data attribution methods—Influence Functions (Koh & Liang, 2017), TracIn (Pruthi et al., 2020), Representer Point Selection (Yeh et al., 2018), and TRAK (Park et al., 2023)—along with their various IHVP solvers (CG, LiSSA, Arnoldi). It departs from prior library efforts (OpenDataVal, pyDVL, influenciae) by focusing exclusively on computationally efficient methods (excluding game-theoretic approaches like Data Shapley), providing modularized low-level utilities (HVP/IHVP, random projection, dropout ensemble), and extending benchmarks to generative AI settings (music and text generation) that no prior library covered. The unified PyTorch API with minimal code invasion via helper decorators is a practical departure from the heavily entangled implementations found in prior work.

## Why It Matters / Open Questions

As data attribution becomes critical for foundation model development (noisy label detection, data selection, copyright), the absence of standardized infrastructure has slowed progress; dattri addresses this by providing a single library with pre-trained model checkpoints that eliminate the need for thousands of expensive retraining runs during evaluation. The benchmark confirms community suspicions that IF methods are brittle for non-convex models and that TRAK is the most broadly applicable method, but also reveals that no method achieves strong results on larger generative models without ensembling. Key open questions include whether current evaluation metrics (LOO, LDS, AUC) generalize beyond classification, how to scale attribution to truly large foundation models, and whether new metrics can avoid the costly retraining requirement.
