## Problem

Existing open-source LLM safety moderation tools (e.g., Llama-Guard2, Aegis-Guard) perform poorly on adversarial jailbreak prompts and lack the ability to detect model refusals as a distinct task, trailing GPT-4 by 15–25% on refusal detection. No single open model simultaneously handles prompt harmfulness, response harmfulness, and refusal classification, forcing practitioners to rely on costly, non-static API tools for reliable safety evaluation.

## Input / Output

WILDGUARD takes a user prompt and an LLM response as text input in a unified instruction format, and produces three binary labels in a single structured output: whether the prompt is harmful, whether the response is a refusal, and whether the response is harmful. When no response is provided (prompt-only items), the response field is an empty string and the two response-related labels are set to N/A. The model is a 7B-parameter instruction-tuned LM, so inference requires only a single forward pass over the concatenated prompt-response text.

## Method

WILDGUARD is built by instruction-tuning Mistral-7B-v0.3 on WILDGUARDTRAIN (87K examples) using a unified multi-task format that outputs all three moderation labels simultaneously. The training data is carefully balanced across four sources—synthetic vanilla, synthetic adversarial (generated via the WILDTEAMING jailbreak-tactic mining pipeline), in-the-wild user-LLM interactions, and annotator-written safety data—covering 13 risk subcategories and paired with both refusal and compliance responses. A key design choice is multi-task training: ablations show that a single model trained jointly on all three tasks outperforms separate single-task models on prompt and response harmfulness, while matching them on refusal detection. GPT-4 is used to generate complex nuanced responses (e.g., caveats, warnings, partial refusals) identified through error analysis, and to filter/audit synthetic data quality, achieving 82–95% agreement with human annotators. Training uses a learning rate of 2e-6, batch size 128, max sequence length 4096, and two epochs on 4 A100 GPUs (~5 hours).

## Results

On WILDGUARDTEST, WILDGUARD achieves 88.9% F1 on prompt harmfulness (beating GPT-4's 87.9% and the best open baseline Aegis-Guard-D's 78.5%), 75.4% F1 on response harmfulness (within 1.4% of MD-Judge's 76.8%), and 88.6% F1 on refusal detection (outperforming LibrAI-LongFormer-ref by 26.4% and GPT-4 by 3.8% on the harmful-prompts-only subset). On adversarial prompts specifically, WILDGUARD reaches 85.5% F1 for prompt harm, surpassing GPT-4 (81.6%) by 3.9% and the best open baseline (Aegis-Guard-D, 74.5%) by 11.0%. In a practical moderation deployment, WILDGUARD reduces jailbreak attack success rate from 79.8% to 2.4% while increasing benign refusal rate by only 0.4%.

## Baselines & Comparisons

WILDGUARD outperforms all open-source baselines across all three tasks. On prompt harmfulness, it beats Llama-Guard2 (70.9→88.9 total F1, +18.0%) and Aegis-Guard-D (78.5→88.9, +10.4%), and on adversarial prompts specifically it surpasses Aegis-Guard-D by 11.0 points. On response harmfulness, WILDGUARD (75.4) is within 1.4% of MD-Judge (76.8), the strongest open baseline, while beating Llama-Guard2 (66.5) by 8.9% and BeaverDam (63.4) by 12.0%. On refusal detection, WILDGUARD (88.6) outperforms LibrAI-LongFormer-ref (70.1) by 26.4% and the keyword-based detector (66.3) by 22.3%, closing most of the gap to GPT-4 (92.4). Against GPT-4, WILDGUARD wins on prompt harmfulness (88.9 vs. 87.9 total; 85.5 vs. 81.6 adversarial) and on refusal detection for harmful prompts (94.0 vs. 93.9), but trails slightly on overall response harmfulness (75.4 vs. 77.3) and total refusal detection (88.6 vs. 92.4). The OpenAI Moderation API is dramatically outperformed on all tasks (e.g., 12.1 vs. 88.9 on prompt harm), confirming that API-based toxicity labels are inadequate for nuanced safety moderation.

## Relation to Prior Work

This paper extends the line of LLM safety moderation tools (Llama-Guard, Aegis-Guard, MD-Judge, BeaverDam) by unifying three previously fragmented tasks—prompt harmfulness, response harmfulness, and refusal detection—into a single multi-task classifier. It departs from prior work in two key ways: (1) treating refusal detection as an independent classification task rather than a proxy derived from response harmfulness labels, and (2) explicitly targeting adversarial/jailbreak robustness, where existing open tools show large performance gaps. The adversarial prompt generation pipeline builds on the WILDTEAMING framework, and the risk taxonomy draws from Weidinger et al., but the multi-task data construction (WILDGUARDMIX) and the open release of both model and training data represent a clear departure from prior moderation tools that typically withhold training data.

## Why It Matters / Open Questions

WILDGUARD provides the first fully open (model + data) multi-task safety moderator that matches or exceeds GPT-4 across all three tasks, removing the costly dependency on closed APIs for safety evaluation and deployment. The practical demonstration—reducing jailbreak attack success rate from 79.8% to 2.4% with minimal over-refusal—makes it immediately deployable as an inference-time safety filter. Key limitations include reliance on synthetic data that may not fully capture real-world distribution, a finite suite of response-generating models, and taxonomy commitments that may not align with all downstream users. Open questions include finer-grained harm category classification, coverage of all real-world interaction patterns, and whether the multi-task formulation generalizes to multilingual or multimodal settings.
