## Problem

When a language model generates a response conditioned on a context, it is unclear which parts of that context actually caused the model to produce a given statement. Prior citation methods are corroborative (identifying sources that support a statement), but no scalable method existed for contributive attribution—pinpointing the specific context sources that causally drove the model's generation, including cases where the model misinterprets context or relies on pre-training knowledge instead.
![Teaser figure](../imgs/NEURIPS20243034/cropped_page1_idx0.webp)

## Input / Output

Given an autoregressive language model, a context partitioned into d sources (typically sentences via an off-the-shelf tokenizer), a query, and an already-generated response (or a specific statement within it), CONTEXTCITE produces a d-dimensional vector of real-valued attribution scores. The method is entirely post-hoc: it requires no modification to the language model and operates on any existing response. Attribution can target the full response or any contiguous token span (e.g., a single sentence), in which case the probability of generating that span conditioned on preceding response tokens is used as the target.

## Method

CONTEXTCITE learns a sparse linear surrogate model that predicts the logit-scaled probability of the generated response as a function of a binary ablation vector indicating which context sources are included. It samples n ablation vectors uniformly from {0,1}^d, computes the corresponding response probabilities via n additional inference passes, and fits a LASSO regression to obtain sparse weights that directly serve as attribution scores. The key design choices—predicting logit-scaled probabilities (unbounded target), using a linear model (weights = attributions), and inducing sparsity via LASSO (exploiting that only a handful of sources matter)—allow a faithful surrogate to be learned with as few as 32 ablations regardless of context length, since the required sample complexity scales as O(k log d) where k is the number of truly relevant sources.

## Results

CONTEXTCITE with just 32 context ablations consistently matches or outperforms all baselines (leave-one-out, attention, gradient norm, semantic similarity) on both the top-k log-probability drop and linear datamodeling score (LDS) metrics across three benchmarks (TyDi QA, Hotpot QA, CNN DailyMail) and two models (Llama-3-8B, Phi-3-mini). For poisoning attack detection, CONTEXTCITE surfaces the injected prompt as the top-1 source in >95% of cases (98.8% top-1 on Llama-3-8B with NeuralExec attacks; 90% top-1 on Phi-3-mini with handcrafted attacks). In the verification application, providing only the top-k CONTEXTCITE sources yields substantially higher AUC for self-verification than providing the entire context, and in the pruning application, selecting top-k sources improves F1-score on both HotpotQA and Natural Questions.

## Baselines & Comparisons

CONTEXTCITE outperforms the attention baseline (average attention weights summed across heads and layers) on both metrics, though the gap is smaller with Llama-3-8B than with Phi-3-mini, where attention fares quite poorly. The gradient norm baseline (ℓ₁-norm of log-probability gradients w.r.t. token embeddings, following Yin & Neubig) is consistently outperformed by CONTEXTCITE across all benchmarks and models. The semantic similarity baseline (cosine similarity between sentence embeddings of sources and the generated statement) is the weakest of the four main baselines. Leave-one-out is an oracle for the top-1 log-probability drop metric but requires one inference pass per source (prohibitively expensive for long contexts); CONTEXTCITE approaches its performance with only 32 ablations. In a direct comparison with Kernel SHAP (Lundberg & Lee), the CONTEXTCITE estimator (uniform sampling + LASSO) yields a more faithful surrogate model than the Kernel SHAP estimator, particularly when the number of context ablations is small (Figure 14).

## Relation to Prior Work

CONTEXTCITE repurposes the datamodeling framework (Ilyas et al., Park et al.)—originally designed to attribute model predictions to individual training examples—into the context attribution setting, where the 'training examples' are sentences in a provided context. Conceptually, it is a global (uniform-kernel) variant of LIME applied to the generative setting, and it departs from prior citation-generating methods (Menick et al., Gao et al.) by studying *contributive* attribution (what caused the model to generate a statement) rather than *corroborative* attribution (what supports a statement). The paper also positions itself against attention-based and gradient-based explanation methods, which it uses as baselines and finds to be less reliable across architectures.

## Why It Matters / Open Questions

The practical applications—self-verification, context pruning for improved QA, and prompt-injection detection—address real deployment concerns for LLM-based systems, and the finding that only 32 ablations suffice (due to sparsity) makes the method tractable. Key limitations include the linearity assumption (which may fail when many sources contain redundant information), the inability to capture indirect attribution through preceding statements, and the 32× computational overhead. Open questions include whether the approach scales to very long contexts with hundreds of sources, whether non-linear surrogates would improve faithfulness in redundant-source settings, and whether the method generalizes to non-autoregressive or multimodal models.
