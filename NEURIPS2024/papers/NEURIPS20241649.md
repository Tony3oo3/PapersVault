## Problem

Existing benchmarks for multimodal computer agents either provide static demonstration datasets without executable environments or restrict tasks to single applications and domains (web browsing, coding, mobile UI). No prior benchmark offers a scalable, real computer environment that supports open-ended tasks spanning arbitrary applications, multiple operating systems, and cross-app workflows with execution-based evaluation, leaving a critical gap in assessing whether current LLM/VLM agents can function as general-purpose computer assistants.
![Teaser figure](../imgs/NEURIPS20241649/cropped_page1_idx2.webp)

## Input / Output

The agent receives a natural language task instruction paired with one of four observation modalities: a full 1920×1080 desktop screenshot, an XML-formatted accessibility tree (via ATSPI on Ubuntu or UIA on Windows), a Set-of-Marks bounding-box overlay on the screenshot, or a combination of screenshot and a11y tree, plus up to 3 previous observation-action pairs as history. The agent outputs pyautogui-compatible actions (moveTo, click, dragTo, write, hotkey, scroll, keyDown/keyUp) at pixel-level coordinates, or one of three special control tokens (WAIT, FAIL, DONE). Evaluation is execution-based: 134 unique scripts inspect final system state including file contents (xlsx/docx/pptx via openpyxl/python-docx/python-pptx), application configuration files, browser cookies via Playwright, accessibility trees, and GIMP/VS Code internal settings.

## Method

OSWORLD formalizes autonomous computer tasks as a Goal-Augmented POMDP and implements them on virtual machines (Ubuntu 22.04 primarily, Windows secondarily) that support snapshot-based reset, parallel execution, and headless operation. The environment provides three key infrastructure components: (1) config-file-driven initialization that reproduces intermediate human work states (open files, specific app windows, pre-existing data) rather than clean boot states; (2) a full pyautogui action space covering all mouse and keyboard interactions plus WAIT/FAIL/DONE control actions; and (3) a post-interaction evaluation pipeline that retrieves files, cookies, accessibility trees, and app-internal state from the VM to run task-specific verification scripts. The benchmark comprises 369 Ubuntu tasks (268 single-app, 101 multi-app workflow, 30 infeasible, 84 integrated from prior datasets) and 43 Windows tasks, each annotated with a setup config and a custom evaluation script by 9 CS authors over ~1800 man-hours. The paper then conducts a systematic empirical study of 8+ state-of-the-art LLM/VLM agents (GPT-4/4o/4V, Gemini-Pro/1.5, Claude-3-Opus, Qwen-Max, CogAgent, Mixtral, Llama-3) across four input configurations, revealing that the best agent achieves only 12.24% success versus 72.36% for humans, with particularly severe failures on multi-app workflow tasks (<7%), GUI coordinate grounding, and robustness to window position/size perturbations (60–80% performance drops).

## Results

On the OSWORLD benchmark (369 tasks), the best-performing agent (GPT-4 with accessibility tree input) achieves only 12.24% overall success rate, compared to 72.36% for human annotators. Screenshot-only VLM agents (GPT-4V, Gemini-ProV) achieve 5.26%–5.80%, while open-source models (CogAgent, Mixtral-8x7B, Llama-3-70B) range from 0.99% to 2.98%. Multi-app workflow tasks are the hardest subset, with the best agent (GPT-4o, A11y tree) reaching only 7.56% and most agents below 5%.

## Baselines & Comparisons

All evaluated agents fall dramatically short of human performance (72.36%), with the best agent (GPT-4, A11y tree) reaching only 12.24% overall. Among closed-source models, the GPT-4 family dominates: GPT-4 (12.24%), GPT-4V with Screenshot+A11y (12.17%), GPT-4V with SoM (11.77%), and GPT-4o with A11y tree (11.36%) all cluster near the top, while Gemini-Pro-1.5 ranges from 4.81% to 7.79% depending on input, and Claude-3-Opus lags at 2.42%–6.72%. Open-source models perform worst: CogAgent (0.99%–1.32%), Llama-3-70B (1.61%), and Mixtral-8x7B (2.98%) all remain below 3%. Qwen-Max (6.87%) is the strongest open-source LLM but still trails GPT-4 by over 5 points. A notable finding is that input modality effects are model-dependent: the accessibility tree helps GPT-4V substantially (5.26%→12.17%) but hurts GPT-4o (11.36%→4.59% with SoM), and Set-of-Marks, which typically aids visual grounding, actually degrades GPT-4V performance relative to Screenshot+A11y, likely due to high-resolution desktop clutter.

## Relation to Prior Work

This paper departs from two main lines of prior work on digital agents: (1) demonstration-only datasets (Mind2Web, OmniAct, AITW) that lack executable environments and assume a single solution per task, and (2) executable environments (WebArena, MiniWoB++, WebShop, InterCode) that simplify observation/action spaces and restrict tasks to a single application or domain. OSWORLD carves new ground by providing a unified, scalable real computer environment with raw keyboard/mouse control, cross-app workflows, intermediate initial states, and 134 unique execution-based evaluation functions—none of which prior benchmarks offered simultaneously. The GA-POMDP formalization and the use of pyautogui as the action space are practical design choices that enable generalization across arbitrary applications without domain-specific simulation.

## Why It Matters / Open Questions

The enormous performance gap (72.4% human vs. <12.2% best agent) and the near-zero success on multi-app workflow tasks (<7%) provide a clear, reproducible signal that current VLMs/LLMs are far from practical computer assistants, with specific failure modes identified (GUI grounding, repetitive actions, fragility to window perturbations causing 60–80% drops). The finding that Set-of-Marks—widely shown to help in web-agent settings—can actually degrade performance on desktop tasks (e.g., GPT-4o drops from 11.21% to 4.59%) challenges a common assumption and suggests that high-resolution, element-dense desktop interfaces require different grounding strategies. Open questions include how to build agents robust to environmental noise, how to handle long-horizon multi-app coordination, and whether purely vision-based (screenshot-only) agents can eventually match or exceed structured-input approaches.
