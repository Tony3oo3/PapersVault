## Problem

Existing tool-augmented LLMs like ToolLLaMA train exclusively on successful paths from depth-first search decision trees, discarding the failed exploration branches that contain valuable negative signal. This behavior-cloning approach limits exploration of the action space and results in low data utilization, leaving the model unable to learn which intermediate decisions to avoid.
![Teaser figure](../imgs/NEURIPS20243381/cropped_page1_idx0.webp)

## Input / Output

At each reasoning step, the model receives the original user query, the relevant API documentation (name, description, parameters, code snippets), and the full reasoning history of prior API calls and their responses, all packed into an 8192-token context window. The model outputs the next API call decision (tool name plus parameters) or a final answer. The preference training data is structured as step-wise pairs: each sample contains the instruction (system prompt + API docs), the input (query + history up to a branching node), and the output (one preferred and one dispreferred next action), with diversity prompts stripped to prevent information leakage.

## Method

The framework has two training stages: first, SFT on resampled successful trajectories from ToolBench (11,142 instructions), then DPO on a novel step-wise preference dataset called ToolPreference (8,202 sampled pairs from 69,393 total). The key construction insight is step-wise rather than path-wise preference pairing: at each branch node along the success path in a DFSDT tree, the successful child node is designated as preferred and each failed sibling as dispreferred, yielding fine-grained per-step supervision that matches the model's iterative next-action reasoning mechanism. This avoids the path-wise approach's tendency to only distinguish correct from incorrect final answers, instead teaching the model to prefer specific intermediate decisions. The DPO loss directly optimizes the policy without a separate reward model, using β=0.5 and a learning rate of 1e-6 for one epoch, building on the SFT-initialized LLaMA-2-7B to produce TP-LLaMA.

## Results

On the ToolBench test suite (six scenarios covering single-tool, intra-category multi-tool, and inter-category multi-tool tasks), TP-LLaMA achieves an average pass rate of 0.65 and win rate of 0.65, outperforming all baselines. The most notable gain is in the hardest scenario G3-Ins. (inter-category multi-tool, unseen instructions), where TP-LLaMA reaches 0.61 pass rate versus 0.17 for ToolLLaMA and 0.21 for ChatGPT. In terms of inference efficiency, TP-LLaMA requires only 22.62 average DFSDT steps versus 32.06 for the SFT-only model, a 29.44% reduction.

## Baselines & Comparisons

TP-LLaMA outperforms ChatGPT (the reference model for win-rate evaluation) by a large margin on pass rate: 0.65 vs. 0.48 average, with the gap widening to 0.61 vs. 0.21 on the hardest G3-Ins. scenario. Against ToolLLaMA, TP-LLaMA improves average pass rate from 0.49 to 0.65 (+16 percentage points) and average win rate from 0.57 to 0.65 (+8 percentage points), winning on 5 of 6 pass-rate scenarios and 5 of 6 win-rate scenarios (losing only G1-Cat. win rate by 3 points). The efficiency comparison further favors TP-LLaMA, which needs 22.62 DFSDT steps on average versus 32.06 for the SFT-only LLaMA baseline, indicating that preference learning helps the model avoid unnecessary branch explorations. Ablation experiments with Mistral-7B, Qwen1.5-7B, and Gemma-7B confirm that the gains from preference learning are model-agnostic, with pass-rate improvements of at least 8% across all base models.

## Relation to Prior Work

This paper extends ToolLLM (Qin et al., 2023), which introduced the ToolBench dataset and DFSDT reasoning mechanism for multi-step tool-use, by exploiting the failed exploration branches that ToolLLM discards during SFT training. It pairs this with Direct Preference Optimization (Rafailov et al., 2023) to convert those ignored failure paths into step-wise preference pairs, creating a two-stage SFT-then-DPO training pipeline. The key conceptual departure is the step-wise preference construction from tree-structured trajectories, which the authors argue is more aligned with the iterative, one-step-at-a-time nature of DFSDT reasoning than path-wise alternatives.

## Why It Matters / Open Questions

The paper demonstrates that failed exploration paths in decision trees are not wasted data but contain actionable learning signal, yielding both accuracy gains (~12% pass rate) and a 29% reduction in inference steps. The step-wise preference construction method is generalizable to any tree-structured multi-step reasoning dataset, making it a reusable technique beyond tool-use. Open questions include whether manually crafted suboptimal branches would yield stronger signal than naturally occurring failures, whether the approach extends to multimodal or more complex reasoning settings, and how to handle the computational cost of inputting full history at each step.
