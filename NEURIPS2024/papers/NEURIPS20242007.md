## Problem

Instruction tuning for code LLMs has relied on either expensive human annotation or distillation from proprietary models like GPT-4, which may violate terms of service and introduces a distribution gap between teacher and student. Prior attempts to apply Self-Instruct to code generation resulted in performance degradation, and the only fully transparent alternative (OctoCoder) achieved only 32.9 pass@1 on HumanEval+. The paper asks whether a code LLM can be effectively self-aligned using purely self-generated data, without any external teacher or human labels.

## Input / Output

The pipeline consumes 250k high-quality Python seed functions (filtered from 5M in The Stack V1 via Pyright type-checking, docstring quality classification, and MinHash deduplication) and produces 74k instruction-response pairs, each response paired with self-generated unit tests that must pass in a Docker sandbox. The base model (e.g., CodeQwen1.5-7B) serves as the sole inference engine for all generation stages—concept extraction, instruction creation, response writing, and test generation—so no external model is queried. The final output is a supervised-finetuned instruction-tuned code LLM trained on only the execution-validated subset.

## Method

SelfCodeAlign is a three-stage self-alignment pipeline: (1) diverse instruction generation via Self-OSS-Instruct, where the base model first extracts coding concepts from each seed function, then generates a new task conditioned on those concepts plus randomly sampled difficulty and category attributes; (2) response generation where the model produces multiple (response, test-case) pairs per instruction in an interleaved natural-language-and-code format; (3) execution-based filtering in a sandbox, retaining only responses whose self-generated tests pass. The key insight is that a model learns more effectively from data within its own distribution than from a shifted teacher distribution when the performance gap is modest, and that execution filtering is essential—passing-only examples yield 65.2 pass@1 versus 57.9 for failing-only and 61.6 for random selection. The concept-extraction intermediate step is critical: directly generating instructions from raw seed snippets produces lower-quality, out-of-distribution prompts, while concept-mediated generation yields more natural and diverse tasks.

## Results

SelfCodeAlign-CQ-7B (finetuned from CodeQwen1.5-7B on 74k self-generated instruction-response pairs) achieves 67.1 pass@1 on HumanEval+ and 65.2 on MBPP+, surpassing the 10× larger CodeLlama-70B-Instruct (65.2/61.7) and outperforming the previous state-of-the-art transparent method OctoPack (50.6/63.2) by 16.5 points on HumanEval+. On LiveCodeBench (contamination-free), it scores 22.4–23.4 pass@1 depending on start date, and on EvoEval it achieves 43.6 average pass@1, the best among transparently finetuned models. On code efficiency (EvalPerf), SelfCodeAlign-CQ-7B attains a DPS of 79.9%, ranking second among comparable-size models behind only DeepSeek-Coder-6.7B-Instruct (83.6%).

## Baselines & Comparisons

Among fully transparent, non-proprietary, non-distilled models, SelfCodeAlign-CQ-7B (67.1 HumanEval+) is the clear leader, outperforming OctoCoder-16B (32.9) by 34.2 points, StarCoder2-15B (37.8) by 29.3 points, and CodeQwen1.5-7B-OctoPack (50.6) by 16.5 points. It also surpasses much larger non-transparent models including Snowflake Arctic-480B (64.3), Command-R+-104B (56.7), Mixtral-8x7B-Instruct (39.6), Gemini Pro (55.5), and Mistral Large (62.8), and narrowly beats CodeLlama-70B-Instruct (65.2) despite being 10× smaller. However, it trails models trained with proprietary data or distillation: CodeQwen1.5-7B-Chat (77.7), DeepSeekCoder-33B-Instruct (75.0), OpenCodeInterpreter-DS-33B (73.8), WizardCoder-33B-v1.1 (73.2), Llama3-70B-Instruct (70.7), Magicoder-S-DS-6.7B (70.7), Mixtral-8x22B-Instruct (70.1), and GPT-4-Turbo (81.7). In the direct distillation comparison (Table 11), SelfCodeAlign (67.1) outperforms OSS-Instruct with GPT-3.5-Turbo (61.6), Evol-Instruct with GPT-3.5-Turbo (59.1), and even direct GPT-4o distillation (65.9), demonstrating that self-generated data with execution-based filtering can surpass teacher-model distillation.

## Relation to Prior Work

SelfCodeAlign adapts the OSS-Instruct paradigm (converting code snippets into instructions via in-context learning) from a distillation setting to a self-alignment setting, where the base model itself generates both instructions and responses. It extends the Self-Instruct lineage by adding two critical components absent from the original: a concept-extraction intermediate step for instruction diversity, and execution-based sandbox filtering for response validation. The paper explicitly positions itself against the prior state of the art in transparent code instruction tuning (OctoPack/OctoCoder) and against distillation-based methods (OSS-Instruct, Evol-Instruct, WizardCoder), arguing that neither natural data nor teacher distillation is necessary for strong instruction-tuned code models.

## Why It Matters / Open Questions

This is the first demonstration that a fully transparent, permissively licensed self-alignment pipeline can produce a code LLM competitive with or superior to models trained via proprietary distillation, removing a key barrier to reproducible and open code model development. The finding that a base model benefits more from its own data distribution than from a stronger teacher (when the performance gap is modest) challenges the prevailing assumption that distillation from a larger model is always preferable. Open questions include whether the ~3000-token context window limits generalization to longer tasks, whether self-generated unit tests can be made more reliable, and whether the negative samples discarded during filtering can be leveraged in a reinforcement-learning loop for further gains.
