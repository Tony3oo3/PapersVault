## Problem

While LLMs have shown promise in software engineering tasks, their ability to autonomously solve multi-step, interactive cybersecurity challenges (CTFs) has not been systematically evaluated at scale. Prior studies examined only 7–100 challenges with 2–6 models, lacked open benchmarks, and did not integrate domain-specific tools, leaving a gap in understanding how well current LLMs can perform real-world offensive security tasks.

## Input / Output

Each challenge is specified by a JSON metadata file (name, description, visible files, host/port) plus the actual challenge artifacts (binaries, source code, APKs, network captures) and, for server-based challenges, a docker-compose.yml that pulls a pre-built Docker image from Docker Hub. Only files explicitly listed in the JSON 'files' field are exposed to the model, mimicking real CTF conditions; the ground-truth flag is stored separately and invisible to the model. The output is a binary success/failure signal (correct flag obtained via the check_flag tool) plus rich Markdown/JSON logs capturing every prompt, tool invocation, and model response for post-hoc analysis.

## Method

The framework is a five-module pipeline: a Backend module that routes requests to OpenAI (GPT-4, GPT-3.5), Anthropic (Claude 3 Haiku/Sonnet/Opus), or open-source models (Mixtral-8x7B, DeepSeek-Coder-33B, LLaMA-3-70B, WizardLM2-8x22B) served via TGI/VLLM; a Data Loader that spins up Docker containers or mounts local files into a player container; an External Tools layer exposing six function-calling APIs (run_command in an Ubuntu 22.04 container with pwntools/Ghidra/radare2, create_file, disassemble, decompile, check_flag, give_up) tailored per challenge category; a Logging System producing structured JSON/HTML traces; and a Prompt Module that assembles system, user, and model prompts from the challenge metadata. The key design choice is augmenting LLMs with domain-specific cybersecurity tools via a formatting module that converts natural-language requests into structured function calls (XML/YAML), enabling even models without native function-calling support to invoke decompilers, debuggers, and exploit frameworks. Evaluation runs each of the 200 validated challenges five times per model under a 48-hour time limit, with success defined as obtaining the correct flag in at least one attempt.

## Results

Across 200 CTF challenges in six categories, GPT-4 achieved the highest overall solve rate, with best performance in reverse engineering (9.80%), pwn (7.69%), forensics (6.67%), and web (5.26%), but solved 0% of crypto and misc challenges. Claude 3 led in crypto (5.77%) and misc (8.33%), while GPT-3.5 was strongest in misc (12.5%) and rev (5.88%). Both open-source models (Mixtral and LLaMA) solved 0% of all challenges, with 100% of failures classified as 'wrong answer.' In head-to-head comparison with human CSAW participants, GPT-4 scored 300 in the 2023 qualifiers (above the median of 225), and Claude 3 scored 1500 in the 2022 finals (above the median of 1321), though no LLM scored in the 2023 finals.

## Baselines & Comparisons

The paper positions itself against three prior LLM-CTF studies, but the comparison is primarily one of scope and infrastructure rather than direct performance on shared challenges. Shao et al. [41] evaluated 6 LLMs on only 26 CTFs without tool integration or an open benchmark; Tann et al. [45] manually tested 3 LLMs on just 7 challenges with no automated framework; and Yang et al. [53] (InterCode-CTF) examined 2 LLMs on 100 PicoCTF problems but also lacked tool use and an open benchmark. NYU CTF Bench is the first to combine an open-source dataset (200 challenges), a fully automated solving framework, and domain-specific tool integration (Ghidra, pwntools, netcat, etc.) across 5 LLMs. Against human baselines, the best LLM (GPT-4) exceeded the median human score in the 2023 qualifiers (300 vs. 225) but fell well below the mean (587), while Claude 3 surpassed the 2022 finals median (1500 vs. 1321) but remained below the mean (1773). No LLM matched or exceeded human performance in the 2023 finals, where all three black-box models scored 0.

## Relation to Prior Work

This paper extends the small-scale, largely manual evaluations of LLMs on CTF challenges (Tann et al. with 7 challenges, Yang et al. with 100, Shao et al. with 26) into the first open, fully automated benchmark at 200-challenge scale with integrated external tool use. Conceptually, it draws on the DARPA Cyber Grand Challenge vision of autonomous vulnerability exploitation and on the function-calling paradigm from Toolformer and native OpenAI/Anthropic tool APIs, repurposing them for a domain-specific cybersecurity agent. Unlike prior work that relied on human-in-the-loop analysis or single-model spot checks, this paper introduces a repeatable, Docker-based evaluation harness with a standardized prompt pipeline and a garbage-collected multi-container environment, making LLM CTF evaluation a reproducible empirical task rather than a case-study exercise.

## Why It Matters / Open Questions

The benchmark fills a critical gap: before this work, there was no open, validated, multi-category CTF dataset purpose-built for LLM evaluation, and no automated framework that could scale across models and challenge types. The finding that even GPT-4 solves at most ~10% of challenges in any single category, while open-source models (Mixtral, LLaMA 3) solve zero, sharply calibrates expectations for near-term autonomous offensive-security agents. Key limitations include sourcing from a single CTF series (NYU CSAW), category imbalance (forensics and web underrepresented), absence of Incident Response challenges, and no statistical significance testing due to compute cost. Open questions include whether reinforcement learning or iterative self-play on this benchmark can close the gap to human performance, and whether richer tool ecosystems (e.g., full GDB sessions, network traffic analysis) would materially change the results.
