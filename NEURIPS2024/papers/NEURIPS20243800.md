## Problem

LLMs pre-trained on sequences of only a few thousand tokens cannot process longer inputs due to out-of-domain positional encodings and attention distraction from noisy distant contexts. Existing solutions typically require expensive continual pre-training on long sequences, incurring substantial computational costs and risking degradation of short-context performance. This paper asks whether LLMs can be made to understand extremely long sequences (up to 1,024K tokens) without any additional training.

## Input / Output

The method consumes long text sequences in a streaming fashion, encoding them in fixed-size chunks (512 tokens) and generating output token-by-token. At each computation step, the model attends only to a local window of 4K tokens plus a small set of retrieved memory units (96 units for Mistral-7B, 32 for Llama-3-8B), keeping the effective context window far smaller than the full sequence length. The output is standard autoregressive text generation, and the system processes sequences up to 1,024K tokens using only ~26 GB of GPU VRAM via CPU offloading of memory units.

## Method

InfLLM combines sliding window attention with a training-free block-level context memory. Past key-value vectors are partitioned into blocks of 128 tokens, and within each block, the top-4 tokens by a representative score (average attention received from the local window) are selected as the unit representation. At each step, a relevance score is computed between current token queries and each block's representative keys, and the top-k blocks are loaded into the attention computation alongside the local window and initial tokens. All tokens beyond the local window share the same positional encoding to avoid out-of-domain issues, while the unidirectional decoder structure preserves relative ordering implicitly. An LRU-based GPU cache with CPU offloading keeps memory usage bounded, and the entire mechanism requires no parameter updates, making it directly applicable to any off-the-shelf LLM.

## Results

On ∞-Bench (average sequence length 145.1K, 95th percentile 214K), InfLLM with Mistral-7B achieves an average score of 57.7 using only a 16K context window, substantially outperforming the best position-extrapolation baseline SelfExtend (44.8 at 128K window) by 12.9 points. With Llama-3-8B, InfLLM reaches 45.0 average using an 8K window, surpassing SelfExtend (38.0 at 128K) by 7.0 points and the original Llama-3 (18.4) by 26.6 points. InfLLM achieves 100% on Retrieve.PassKey and 96.1%/99.0% on Retrieve.Number for Mistral/Llama-3 respectively, while sliding-window baselines (LM-Infinite, StreamingLLM) score only 28.8%/8.5% on Retrieve.PassKey. At 1,024K sequence length, InfLLM still achieves 100% accuracy on the Retrieve.PassKey task.

## Baselines & Comparisons

InfLLM decisively outperforms all sliding-window baselines (LM-Infinite, StreamingLLM) and KV-eviction (H2O) on both model families: with Mistral, InfLLM scores 57.7 vs. 21.6 (Infinite), 21.5 (Streaming), and 18.7 (H2O); with Llama-3, 45.0 vs. 16.0, 16.3, and 2.1 respectively. Against position-extrapolation methods, InfLLM wins by a wide margin while using a much smaller window: 57.7 vs. 44.8 (SelfExtend) and 44.3 (NTK) for Mistral at 16K vs. 128K window, and 45.0 vs. 38.0 (SelfExtend) and 1.3 (NTK) for Llama-3 at 8K vs. 128K. NTK-aware scaled RoPE catastrophically fails on Llama-3 (1.3 avg), likely due to the model's 8K training length being too short for the interpolation to work. Compared to RAG (E5-mistral-7B-instruct), InfLLM achieves 100.0/96.1/96.8 on R.PK/R.Num/R.KV versus 89.2/65.4/13.2, with the largest gap on Retrieve.KV (96.8 vs. 13.2). Against the continually-trained Llama-1M (1048K context), InfLLM achieves comparable or superior scores on QA (19.5 vs. 13.6), Sum (24.3 vs. 18.5), and Math.F (23.7 vs. 18.3) while using only 26.3G VRAM vs. 76.6G and 26.7s vs. 40.4s per sample.

## Relation to Prior Work

InfLLM builds directly on the sliding window attention paradigm established by StreamingLLM (Xiao et al., 2023) and LM-Infinite (Han et al., 2023), which discard all distant contexts to enable streaming inference. The key departure is the addition of a block-level context memory that retrieves relevant distant key-value vectors via representative-token-based relevance scoring, addressing the long-distance dependency gap that pure sliding window methods cannot capture. Unlike prior memory-based approaches (Compressive Transformers, Memorizing Transformers, Infini-attention) that require architecture modifications and full retraining, InfLLM is entirely training-free and plug-and-play for any existing LLM. It also contrasts with position interpolation methods (NTK, SelfExtend) that extend context length but remain vulnerable to attention distraction from noisy tokens.

## Why It Matters / Open Questions

The practical impact is significant: InfLLM matches or exceeds the performance of Llama-3-8B-Instruct-Gradient-1048k (which required 512 GPUs for continual training) with zero additional training, while using only 34% of the GPU memory and 34% less inference time. This democratizes long-context processing for researchers and practitioners without access to large-scale training infrastructure. Open questions remain around CPU memory overhead for very long sequences, the optimal dynamic segmentation of memory units (current fixed-size blocks are suboptimal for heterogeneous content), and whether more expressive unit representations (e.g., learned encoders) could further close the gap on harder tasks like Retrieve.KV. The method's applicability to any LLM without modification makes it a strong baseline for future long-context research.
