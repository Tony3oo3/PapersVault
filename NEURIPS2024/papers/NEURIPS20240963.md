## Problem

As LMs outperform average humans on many tasks, existing coding benchmarks (HumanEval, MBPP) have become saturated and fail to reflect real-world scientific research workflows. There is no benchmark that tests LMs on research-level coding problems drawn from actual scientists' daily work across natural science disciplines, with realistic multi-step problem decomposition and domain-specific correctness criteria.
![Teaser figure](../imgs/NEURIPS20240963/cropped_page1_idx0.webp)

## Input / Output

Each evaluation instance provides a docstring specifying the scientific task, input/output format, and function header for the next subproblem, optionally accompanied by scientist-authored background text with relevant equations and physical constants. The model must produce a single Python function using only NumPy, SciPy, and SymPy. Evaluation is execution-based pass@1: generated code is run against both numerical input-output pairs and domain-specific test cases (e.g., reproducing published phase-transition values or analytical solutions), with the main problem considered solved only when all subproblem solutions and their integration are correct.

## Method

SciCode comprises 80 main problems (338 subproblems) spanning 16 natural science subfields, sourced from scientists' internal research scripts to ensure zero overlap with public training data. Each main problem is decomposed into sequentially dependent subproblems, and the benchmark supports toggling evaluation axes: with/without scientific background, gold vs. model-generated solutions to prior subproblems, and main-problem vs. subproblem-level scoring. The 'standard setup' (no background, generated solutions carried forward) most closely mirrors real scientist usage. Annotation follows a three-round validation protocol: cross-checking by two in-domain scientists, review by an out-of-domain scientist for clarity, and a GPT-4-assisted error analysis to eliminate false positives in test cases. Under this standard setup, the best model (OpenAI o1-preview) solves only 7.7% of main problems, while providing scientist-written background raises the best score to 12.3%.

## Results

Under the standard setup (no scientific background, generated solutions carried forward), OpenAI o1-preview achieves the best pass@1 rate of 7.7% on main problems and 28.5% on subproblems. Claude3.5-Sonnet follows at 4.6% main / 26.0% subproblem, while GPT-4o, GPT-4-Turbo, o1-mini, Gemini 1.5 Pro, Claude3-Opus, and Claude3-Sonnet all score only 1.5% on main problems. Among open-weight models, Deepseek-Coder-v2 leads at 3.1% main / 21.2% subproblem, while Llama-3-70B, Llama-3.1-70B, and Mixtral-8x22B fail to solve any main problem (0.0%) despite solving 14.6–17.0% of subproblems.

## Baselines & Comparisons

SciCode is a benchmark, so the 'baselines' are the 15 LLMs evaluated on it. OpenAI o1-preview clearly leads all proprietary models, solving 7.7% of main problems—roughly 5× the 1.5% achieved by GPT-4o, GPT-4-Turbo, o1-mini, Gemini 1.5 Pro, Claude3-Opus, and Claude3-Sonnet. Claude3.5-Sonnet (both original and updated) sits in a middle tier at 4.6%, ahead of the 1.5% cluster but well behind o1-preview. Among open-weight models, Deepseek-Coder-v2 is the strongest at 3.1% main / 21.2% subproblem, while Llama-3.1-405B (1.5%) and Qwen2-72B (1.5%) match the weakest proprietary models, and Llama-3-70B, Llama-3.1-70B, and Mixtral-8x22B all score 0.0% on main problems. When scientist-authored background knowledge is provided (Table 3), all models improve substantially—o1-mini jumps to 13.8% and Claude3.5-Sonnet to 12.3% on main problems—but even the best model solves fewer than 1 in 7 problems, confirming that the bottleneck is not merely missing domain knowledge but also code synthesis and multi-step integration.

## Relation to Prior Work

SciCode extends the code generation benchmark lineage (HumanEval, MBPP, SWE-bench, DS-1000) by targeting a domain where prior benchmarks have minimal coverage: natural science research coding. Unlike general-purpose coding benchmarks that test instruction-to-code translation, SciCode repurposes the code generation task to require scientific knowledge recall, multi-step problem decomposition, and integration of sub-solutions, drawing problems from scientists' actual research workflows across 16 subfields. The multi-turn subproblem structure is conceptually related to CodeGen's multi-turn synthesis, but SciCode's subproblems correspond to high-level scientific tasks rather than low-level code edits. The evaluation design (execution-based with domain-specific test cases reproducing published results) departs from n-gram or surface-form matching used in earlier code evaluation.

## Why It Matters / Open Questions

SciCode reveals a stark capability gap: even the strongest models solve fewer than 8% of main problems, and the large subproblem-to-main-problem performance drop (e.g., 28.5% → 7.7% for o1-preview) identifies multi-step integration and error accumulation as the primary bottleneck rather than isolated code synthesis. The finding that scientist-authored background knowledge yields substantial but insufficient improvements (best model reaches only 12.3%) suggests that current LMs lack both the domain knowledge and the reasoning chains needed for research-level scientific coding. Open questions include whether targeted scientific pretraining or retrieval-augmented approaches can close this gap, and whether the benchmark's 80-problem scale is sufficient for reliable model ranking as capabilities improve.
