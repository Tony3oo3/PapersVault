## Problem

Static LLM benchmarks suffer from data contamination and fixed complexity that cannot keep pace with rapidly improving models, making them unreliable indicators of true reasoning ability. Prior dynamic evaluation methods either produce rigid, template-based samples lacking linguistic diversity (DyVal) or rely on unstable LLM prompting that offers poor controllability and unverifiable labels (DyVal 2, Benchmark Self-Evolving). The gap is a framework that generates novel test data with fine-grained, controllable complexity while preserving the linguistic style of original benchmarks and guaranteeing label correctness.

## Input / Output

The pipeline consumes an existing benchmark data point (a natural-language question paired with its ground-truth label) along with user-specified complexity constraints (e.g., +2 depth, +4 width, +6 numerical digits) and a set of in-context exemplar (graph, text) pairs. It outputs a modified question in the same linguistic style as the original, a new verified label computed deterministically from the perturbed graph, and the intermediate reasoning graph itself. For GSM8K, 500 sampled points per complexity level are generated; for BBQ, 600 points; for BBH tasks, the full 250-point test sets are used. A code-augmented LLM agent (GPT-4 with code interpreter) serves as the final verification gate, iteratively refining generated text until the code-computed answer matches the graph-derived label.

## Method

DARG is a four-stage pipeline that decouples complexity control from linguistic generation. First, an LLM (GPT-4 Turbo) constructs a directed acyclic reasoning graph for each benchmark point via in-context learning, where nodes represent basic reasoning units (numbers, persons, actions, brackets) and edges represent operators or relations; correctness is enforced by a rule-based function that computes a label from the graph and rejects mismatches. Second, a purely rule-based perturbation function modifies the graph along predefined complexity dimensions—depth (longest path length), width (parallel variables), and node property complexity (e.g., digit count)—without invoking any LLM, ensuring deterministic and noise-free complexity increases. Third, the perturbed graph is decoded back into natural language using LLM in-context learning conditioned on original (graph, text) pairs, preserving the benchmark's linguistic diversity. Fourth, a code-augmented LLM agent independently solves the generated question by writing and executing code, and the computed answer is compared against the graph-derived label; mismatches trigger iterative refinement with the code output fed back as supervision. This separation of deterministic graph manipulation from stochastic text generation, combined with tool-augmented verification, is what distinguishes DARG from both template-based and pure-prompting approaches.

## Results

Across 15 SOTA LLMs evaluated on GSM8K with DARG-generated data, all models show consistent performance degradation as complexity increases in all three dimensions (numerical, width, depth). At the maximum depth increase (+4), even top performers like GPT-4-o (95.2% → 42.0%, −53.2%) and Claude-3-Opus (95.0% → 43.5%, −51.5%) lose over half their accuracy, while smaller models like Phi-3-mini drop from 83.8% to 29.0% (−54.8%). In social reasoning (BBQ), bias scores increase with complexity for all models, and GPT-4 Turbo and Gemini-1.5-Pro exhibit the highest overall avoidance rates, indicating over-sensitivity to protected-group content. In spatial reasoning (BBH Navigate), positive accuracy drops by over 40% for all models except GPT-4 Turbo when reasoning steps increase by 16, suggesting confirmation bias. Fine-tuning Mistral-7B and Llama-2-7B on DARG-generated data outperforms fine-tuning on equivalent GSM8K training data (p=0.022).

## Baselines & Comparisons

DARG is an evaluation framework rather than a model, so its 'comparisons' are between the 15 LLMs it evaluates. Larger and MoE models show greater resilience: Llama-3-70B (−46.7% at depth +4) outperforms Llama-3-8B (−52.3%), and Mixtral-8×22B (−52.0%) is more robust than Mistral-7B (−33.9% at depth +4, but from a much lower base of 49.4%). Among closed-source models, GPT-4-o and Claude-3-Opus maintain the highest accuracy at moderate complexity (e.g., 80.4% and 88.0% at numerical +4), but all converge to 41–44% at maximum depth. In BBQ, GPT-4 Turbo and Gemini-1.5-Pro paradoxically show the highest overall avoidance rates (frequently answering 'Cannot be determined' even with clear evidence), revealing over-alignment to protected-group content that less powerful models like GPT-3.5 Turbo do not exhibit. For fine-tuning, models trained on DARG-generated data significantly outperform those fine-tuned on equivalent GSM8K training data (paired t-test p=0.022), demonstrating that DARG's complexity-diverse data is more effective for training than the original benchmark. Compared to prior dynamic evaluation methods (DyVal's template-based generation, DyVal 2 and Benchmark Self-Evolving's prompting-based perturbation), DARG achieves fine-grained complexity control via rule-based graph perturbation while preserving linguistic diversity through LLM-based graph-to-text decoding, with 92.5% label correctness verified by a code-augmented agent (vs. 37.5% with self-refinement alone).

## Relation to Prior Work

DARG extends DyVal's [119] graph-informed dynamic evaluation by replacing its rigid template-based graph-to-text generation with LLM-driven in-context decoding that preserves the linguistic diversity of original benchmarks, and by adding a code-augmented LLM verification loop to guarantee label correctness. It departs from LLM-prompting approaches like DyVal 2 [120] and Benchmark Self-Evolving [96] by grounding complexity control in explicit reasoning graph perturbations (depth, width, node values) rather than free-form paraphrasing, enabling fine-grained and verifiable complexity manipulation. The method also draws on tool-augmented LLM paradigms (PAL, ReAct, Chameleon) for the verification stage, positioning graph structure as the controllable intermediate representation between problem and solution.

## Why It Matters / Open Questions

The finding that nearly all 15 SOTA LLMs—including GPT-4 Turbo and Claude-3-Opus scoring >93% on GSM8K—suffer 30–70% accuracy drops under modest complexity increases provides strong empirical evidence that static benchmarks overestimate true reasoning capability, likely due to data contamination. The counterintuitive observation that the most powerful models (GPT-4 Turbo, Gemini-1.5-Pro) exhibit *increased* bias and over-sensitivity to protected-group content as complexity rises raises important safety concerns for deployment. Key limitations include heavy reliance on GPT-4 for graph construction (open-source 70B/405B models show a notable gap in structured-output instruction following), coverage of only four reasoning domains, and fine-tuning experiments limited to two 7B models. Open questions include whether the reasoning graph framework generalizes to non-reasoning tasks (e.g., NLU, commonsense) and whether fully open-source pipelines can match the quality of the GPT-4-based one.
