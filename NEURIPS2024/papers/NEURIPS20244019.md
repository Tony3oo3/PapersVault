## Problem

State-of-the-art LLMs like GPT-4 fail to reliably generate correct API calls from the millions of available, frequently updated APIs, suffering from severe hallucination (inventing non-existent models or arguments) and inability to track version changes. No systematic method existed for training LLMs to accurately select and invoke APIs from a large, overlapping, and evolving tool set while respecting user-specified constraints.
![Teaser figure](../imgs/NEURIPS20244019/cropped_page3_idx4.webp)

## Input / Output

The system takes a natural language instruction (e.g., 'build me a classifier for medical images') and, in retrieval mode, appends a retrieved API documentation JSON (containing fields like domain, framework, api_name, api_arguments, performance, description) prefixed with 'Use this API documentation for reference.' The output is a structured response specifying the domain, API provider, the fully-qualified API call code, required packages, and a step-by-step pipeline explanation. For HuggingFace evaluation, the task reduces to selecting the correct domain name from a multiple-choice set due to the non-exhaustive nature of the hosted models.

## Method

Gorilla is a LLaMA-7B model instruction-finetuned on APIBench (~1,645 APIs from HuggingFace, TorchHub, and TensorFlow Hub) with synthetic instruction-API pairs generated via GPT-4 self-instruct. The core innovation is Retriever-Aware Training (RAT): during training, retrieved API documentation (from an oracle or imperfect retriever) is concatenated to the user prompt, and the model is trained to produce the correct API call regardless of whether the retrieved document is relevant. This teaches the model to 'judge' the retriever at inference time—using the document when relevant, ignoring it when not—enabling adaptation to test-time API changes (version upgrades, registry shifts) without retraining. Evaluation uses AST sub-tree matching to check functional correctness and to distinguish hallucinations (calling an entirely non-existent API) from errors (calling a real API with wrong arguments), validated against human evaluation with 78% agreement.

## Results

On APIBench (zero-shot), Gorilla achieves 59.13% overall accuracy on TorchHub, 71.68% on HuggingFace, and 83.79% on TensorFlow Hub, substantially outperforming GPT-4 (38.70%, 19.80%, 18.20%) and GPT-3.5 (48.38%, 16.81%, 41.75%). Gorilla also dramatically reduces hallucination: 6.98% on TorchHub vs. 36.55% for GPT-4, and 5.40% on TensorFlow Hub vs. 78.65% for GPT-4. With an Oracle retriever, Gorilla reaches 91.26% on HuggingFace and 94.16% on TensorFlow Hub, while maintaining near-zero hallucination (0% and 1.89% respectively). The AST-based evaluation metric shows 78% accuracy consistent with human evaluation, validating its use as a robust offline metric.

## Baselines & Comparisons

Gorilla (zero-shot) outperforms all baselines across all three hubs. Against GPT-4, Gorilla gains +20.43% on TorchHub (59.13% vs. 38.70%), +51.88% on HuggingFace (71.68% vs. 19.80%), and +65.59% on TensorFlow Hub (83.79% vs. 18.20%), while reducing hallucination from 36.55% to 6.98% on TorchHub and from 78.65% to 5.40% on TensorFlow Hub. Against GPT-3.5, Gorilla leads by +10.75% on TorchHub and +42.04% on TensorFlow Hub. Against Claude, Gorilla's advantage is even more pronounced: +40.32% on TorchHub and +74.59% on HuggingFace. Against the base LLaMA-7B (which scores 0% on all hubs), Gorilla's improvement is up to 83%. In the Oracle-retriever setting, Gorilla (67.20% TH, 91.26% HF, 94.16% TF) matches or exceeds GPT-3.5 (66.31%, 89.71%, 95.03%) and GPT-4 (66.12%, 85.07%, 55.91%), with GPT-4 notably underperforming on TensorFlow Hub. Against DocPrompting on HuggingFace, Gorilla improves accuracy from 61.72% to 71.68% while reducing hallucination from 17.36% to 10.95%.

## Relation to Prior Work

Gorilla builds on LLaMA-7B as its base model and the self-instruct paradigm for synthetic data generation, but departs sharply from prior tool-use work (Toolformer, WebGPT) that focused on a small set of fixed tools by targeting an open-ended, frequently-updated corpus of ~1,600 ML APIs. Its closest conceptual predecessor is DocPrompting, which also retrieves documentation to guide code generation, but Gorilla differentiates through richer API metadata (parameters, performance, constraints), an instruction-tuning framework with user interaction, and a novel Retriever-Aware Training (RAT) procedure that teaches the model to critically evaluate retrieved documents rather than passively consume them. The AST sub-tree matching evaluation metric is also a departure from standard NLP or exact-match code evaluation, enabling fine-grained hallucination detection specific to API structure.

## Why It Matters / Open Questions

This paper addresses a critical practical gap: LLMs cannot reliably invoke APIs from millions of tools whose documentation changes faster than models can be retrained. APIBench and the AST-based hallucination metric provide the field with the first systematic benchmark and evaluation protocol for API call generation, while RAT offers a generalizable training recipe for making retrieval-augmented LLMs robust to imperfect and evolving retrieved context. Key limitations include the restriction to ML-domain APIs and single API calls, and the substantial performance gap (29–52% accuracy degradation) between oracle and real retrievers, which remains the primary bottleneck. Open questions include extending to multi-step API pipelines, non-ML API domains (REST, SQL), and closing the retrieval-quality gap.
