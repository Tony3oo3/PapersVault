## Problem

Existing multimodal large language models (MLLMs) align visual features with the LLM's input space by concatenating visual tokens with text tokens, causing the input sequence length to grow dramatically (e.g., 576–8,737 visual tokens) and inflating the quadratic attention cost. This paper asks whether visual information can instead be represented in the LLM's parameter space, eliminating visual tokens from the input entirely and decoupling computational cost from image resolution.
![Teaser figure](../imgs/NEURIPS20240898/cropped_page2_idx1.webp)

## Input / Output

The model takes an RGB image (resized to 336×336) and a text prompt. The image is encoded by a frozen CLIP-ViT-L-14 vision encoder into visual features, which are then converted into low-rank perceptual weights that are merged into the LLM's weight matrices. Crucially, the LLM itself only receives the text prompt as input—zero visual tokens—so the input sequence length is independent of image resolution or the number of images. The output is a standard autoregressive text response.

## Method

VLoRA introduces a perceptual weights generator, a decoder-only transformer with N=8 cross-attention blocks (hidden size 512) that takes k=8 learnable perceptual queries and interacts them with CLIP visual features to produce k visual parameter vectors. These vectors are mapped through a shared linear layer (W_share) to dimension h×r (rank r=64) and then through k independent linear layers (W_s) to yield low-rank perceptual weights ΔW = W_v · W_s for each of the five weight types (Q, K, V, O, MLP) in selected LLM decoder blocks. The resulting ΔW has the same algebraic form as LoRA (ΔW_A · ΔW_B), so it can be merged into the frozen LLM weights at inference with no extra per-token overhead. During training, the LLM and vision encoder are frozen and only the perceptual weights generator is updated (pre-training on 30M CapsFusion pairs, then joint fine-tuning with the LLM on 665K instruction samples), keeping the total trainable parameters small while the 7.8B model achieves performance comparable to LLaVA-v1.5 at roughly 8% of its FLOPs.

## Results

VLoRA achieves 63.4 on MMBench, 66.4 on ScienceQA, and 28.6 on CCBench while using **zero** visual tokens in the LLM input, compared to 576 visual tokens for LLaVA-v1.5 (64.3 MMBench, 66.8 ScienceQA, 27.5 CCBench). On MME, VLoRA scores 1311.3 versus LLaVA-v1.5's 1510.7, and on MMMU 33.7 versus 35.7. The computational overhead is only ~8% of LLaVA-v1.5's when text length is 32, and inference speed reaches 1078 tokens/s versus LLaVA's 410 tokens/s (2.6× faster).

## Baselines & Comparisons

Against LLaVA-v1.5 (the closest comparable model, same 7B Vicuna backbone), VLoRA is within 1–2 points on MMBench (63.4 vs 64.3), ScienceQA (66.4 vs 66.8), and HallusionBench (26.4 vs 27.6), and actually leads on CCBench (28.6 vs 27.5), while trailing on MME (1311.3 vs 1510.7) and MMMU (33.7 vs 35.7) — all while using 0 visual tokens versus 576. VLoRA decisively outperforms InstructBLIP, MiniGPT-4 (v1 and v2), OpenFlamingo v2, and Qwen-VL on all six benchmarks, with the largest margins on MMBench (+27.4 over InstructBLIP) and CCBench (+15.9 over Idefics-instruct). Against Qwen-VL-Chat, which was pre-trained on 1.4B image-text pairs (vs. VLoRA's 30M), VLoRA is lower on MME (−156.5), HallusionBench (−10.4), MMMU (−3.3), and CCBench (−12.6), but higher on MMBench (+2.8) and ScienceQA (+0.9), suggesting the gap is largely attributable to pre-training data scale rather than architecture. On fine-grained OCR benchmarks (TextVQA, DocVQA), VLoRA trails LLaVA-v1.5 by 6.8 and 5.0 points respectively, which the authors attribute to CLIP features being text-aligned rather than parameter-aligned.

## Relation to Prior Work

VLoRA departs from the dominant input-space alignment paradigm used by LLaVA, Qwen-VL, InstructBLIP, and other MLLMs, which concatenate visual tokens with text tokens as LLM input. Instead, it introduces a parameter-space alignment paradigm where visual features are converted into low-rank weight modifications (perceptual weights) that are merged directly into LLM weights, drawing conceptual inspiration from both LoRA's low-rank decomposition and HyperNetwork's weight-generation mechanism. The perceptual weights generator itself is architecturally inspired by DETR's decoder and BLIP-2's Q-Former, but repurposed to produce weight matrices rather than fixed-length visual token sequences.

## Why It Matters / Open Questions

By eliminating visual tokens from the LLM input entirely, VLoRA reduces inference FLOPs to roughly 8% of LLaVA-v1.5 and achieves 2.6× faster decoding, which is practically significant for deployment of MLLMs at scale. However, the approach currently shows gaps on fine-grained tasks (TextVQA, DocVQA) and relies on CLIP features that were not designed for weight-space representation, leaving open the question of whether a purpose-built vision encoder could close this gap. The paper also notes that using separate generators per weight type may limit cross-type correlation, and the evaluation is limited to a single 7B model scale, so scalability to larger LLMs and higher-resolution inputs remains untested.
