## Problem

Compiler backend development is a laborious, manual process with no publicly available large-scale dataset to support language model-based automation. While LLMs have demonstrated strong abilities in general code tasks, their efficacy on compiler backends remains limited due to the absence of a domain-specific dataset, leaving a gap between AI code assistance capabilities and the practical needs of backend developers.
![Teaser figure](../imgs/NEURIPS20243566/cropped_page1_idx1.webp)

## Input / Output

The three tasks consume different input formats: Statement-Level Completion takes the first n−1 statements plus 50%–90% of tokens from the nth statement (≤512 tokens) and produces the remaining 10%–50% of that statement (≤128 tokens); Next-Statement Suggestion takes the preceding n−1 statements and produces the full nth statement; Code Generation takes a natural-language function description plus extracted target-specific values (≤256 tokens) and produces the entire function body (≤512 tokens). A key preprocessing step replaces target-specific values (instruction encodings, immediate values, ISA flags) with abstract tokens (<ISA_LIT>, <NUM_LIT>, <STR_LIT>) to enable cross-target generalization, with the concrete values stored separately for reconstruction.

## Method

ComBack is constructed by crawling 317 GitHub repositories and official GCC/LLVM releases (GCC 3.0–13.0, LLVM 2.0.1–17.0.1), yielding 178 backends across 178 targets with ~5.7M KLoC and 182K functions. Functions are extracted via tree-sitter, partitioned into statements, and target-specific values are automatically identified and abstracted into intermediate representations following the CodeXGlue approach. Six pre-trained encoder-decoder or encoder-only models (CodeBert, GraphCodeBert, UniXcoder, CodeT5, CodeT5+, NatGen) are fine-tuned with sequence-to-sequence prediction on the three tasks using identical hyperparameters (batch size 32, learning rate 5e-5, beam size 4). The key finding is that the 220M-parameter CodeT5+ fine-tuned on ComBack outperforms both the conventional Fork-Flow development method and much larger LLMs (ChatGPT-3.5-Turbo, Code-LLaMA-34B-Instruct) on all three tasks for new targets, and the dataset supports iterative expansion for customized targets like RI5CY.

## Results

After fine-tuning six language models with ComBack, all models show substantial improvements: ED gains of 41.64–77.21, absolute EM gains of 42.58%–67.77% for completion/suggestion tasks, and BLEU-4 gains of 20.73–75.29 for code generation. The top-performing model, CodeT5+ (220M parameters), achieves 62.68–71.34% EM on Statement-Level Completion and 44.33–55.38 BLEU-4 on Code Generation for LLVM targets (RISC-V, ARC, NVPTX), far exceeding both ChatGPT-3.5-Turbo (12–17% EM, 1.2–1.4 BLEU-4) and Code-LLaMA-34B-Instruct (0.4–1.0% EM, 1.4–1.6 BLEU-4). CodeT5+ also surpasses the Fork-Flow conventional development method on Code Generation, exceeding both its average and maximum ED/BLEU-4 values.

## Baselines & Comparisons

CodeT5+ (220M params, fine-tuned on ComBack) decisively outperforms both large LLM baselines across all three tasks and all targets. Against Code-LLaMA-34B-Instruct, CodeT5+ achieves 50–71× higher EM on Statement-Level Completion (e.g., 62.68% vs. 0.45% on LLVM RISC-V) and ~35× higher BLEU-4 on Code Generation (50.34 vs. 1.43). Against ChatGPT-3.5-Turbo, CodeT5+ still leads by a wide margin: 62–71% EM vs. 12–17% EM on completion, and 44–55 BLEU-4 vs. 1.2–1.4 on code generation. On the Fork-Flow baseline (conventional manual backend development), CodeT5+ exceeds both the average and maximum ED and BLEU-4 values computed across all other same-type targets, indicating that the fine-tuned small model generates code closer to the ground truth than what a developer would produce by forking and modifying an existing backend. The paper notes that the 220M-parameter model's superiority over 34B-parameter LLMs underscores the value of domain-specific fine-tuning data (ComBack) over raw model scale for this narrow task.

## Relation to Prior Work

This paper extends the code completion and generation paradigm established by benchmarks like CodeXGlue and CodeSearchNet to the specialized domain of compiler backend development, adopting CodeXGlue's approach of replacing domain-specific values with intermediate representations (<ISA_LIT>, <NUM_LIT>, <STR_LIT>). It departs from prior AI-for-compilation work (cost models, transformation ordering, parallel optimization) by targeting the backend code generation stage directly, and from Processor Design Languages (PDL) by using learned models rather than rule-based description files. The methodological lineage is standard transformer fine-tuning (seq2seq) applied to a newly curated corpus, with no architectural novelty.

## Why It Matters / Open Questions

ComBack fills a clear gap as the first public dataset for compiler backend development, enabling the community to train and evaluate models on a domain previously lacking structured data. The practical implication—that a 220M-parameter fine-tuned model can match or exceed 34B-parameter general-purpose LLMs on backend tasks—suggests efficient, deployable tooling for compiler teams without requiring massive inference infrastructure. Key limitations include the absence of function descriptions for highly-customized functions, and the observation that cross-type generalization (CPU-trained → GPU/MPU) degrades accuracy, leaving open how to handle truly novel ISA families. Iterative expansion for customized targets (e.g., RI5CY) shows promise but remains a narrow test case.
