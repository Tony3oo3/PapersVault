## Problem

LLMs struggle with complex code generation, and existing remedies each have critical flaws: two-stage plan-and-solve methods commit to a fixed decomposition upfront, multi-agent frameworks are hard to generalize to smaller open-source models, and self-testing methods rely on model-generated unit tests that the paper shows are frequently incorrect and can mislead refinement. FUNCODER addresses all three by dynamically decomposing problems through code itself and replacing self-tests with a behavioral consensus mechanism.

## Input / Output

For code generation, the input is a function signature (header with typed arguments and return type, plus a docstring describing the task) with an empty body; the output is a complete executable Python program structured as a tree of interdependent functions. For mathematical reasoning (MATH), the input is a LaTeX-formatted problem statement and the output is a numerical answer obtained by executing a generated solution() function. The method operates entirely through code generation prompts (no chat-style planning), making it compatible with specialized code models that lack conversational capabilities.

## Method

FUNCODER recursively applies a divide-and-conquer strategy: in the Divide stage (top-down, DFS), the LLM writes the current function while introducing new sub-function stubs (header + docstring only, body left as NotImplementedError), forming a dependency tree; in the Conquer stage (bottom-up, inverse topological order), each parent function is re-generated using the finalized implementations of its children. The key selection mechanism is functional consensus: for each function, k implementations are sampled, and the one with maximal aggregated behavioral similarity (fraction of sampled inputs producing identical outputs) to all other candidates is selected, replacing unreliable self-generated unit tests. This consensus is applied hierarchically at every node of the tree, not just the root, providing step-by-step verification from leaf functions up to the full program. The overall token cost is O(kN), where k is the number of sampled candidates and N is the final program length, matching the complexity of other sampling-based methods like CodeT.

## Results

FUNCODER achieves 94.5% Pass@1 on HumanEval and 48.6% on xCodeEval (All) with GPT-4, outperforming the previous best (CodeT at 90.9% and 44.0%) by +3.6% and +4.6% respectively. On the MATH benchmark, FUNCODER reaches 78.2% overall accuracy with GPT-4, surpassing the strongest baseline Cumulative Reasoning (72.2%) by +6.0 points. Across all code generation benchmarks (HumanEval, MBPP, xCodeEval) with both GPT-3.5 and GPT-4, FUNCODER delivers an average improvement of +9.8% over state-of-the-art methods. On smaller open-source models, the gains are even larger: StableCode_3b surpasses GPT-3.5 standard prompting by +18.6% on HumanEval and achieves 97.7% of GPT-4's performance.

## Baselines & Comparisons

FUNCODER outperforms all ten baselines across every benchmark and model tested. Against the strongest code-generation baselines, it beats CodeT (self-testing) by +3.6% on HumanEval and +4.6% on xCodeEval with GPT-4, and by +4.5% and +8.2% respectively with GPT-3.5. It surpasses Reflexion (self-improvement) by +3.5% on HumanEval and +10.0% on xCodeEval (GPT-4), and LDB (step-by-step debugging) by +11.6% on HumanEval (GPT-4). Among multi-agent and planning-based methods, FUNCODER exceeds MetaGPT by +8.6% and Parsel by +9.5% on HumanEval with GPT-4. On the MATH benchmark, FUNCODER (78.2% with GPT-4) outperforms Cumulative Reasoning (72.2%), Self-Refine (72.2%), Program-of-Thought (68.2%), and Chain-of-Thought (68.6%) by +6.0, +6.0, +10.0, and +9.6 points respectively, with the largest margin on the hardest difficulty level (Level 5) where it nearly doubles PoT and CoT performance.

## Relation to Prior Work

FUNCODER departs from the dominant plan-then-code paradigm (Parsel, Least-to-Most) by performing decomposition dynamically through the act of coding itself: new sub-functions are introduced as stubs during generation rather than being specified in a preliminary text plan. It also replaces the self-testing/self-improvement loop (CodeT, Reflexion, LDB) with a functional consensus mechanism that ranks sampled implementations by behavioral similarity on LLM-generated inputs, sidestepping the unreliability of model-generated unit tests. The approach is conceptually closer to AlphaCode's output-clustering but generalizes from exact-match grouping to a graded similarity score, and it subsumes multi-agent frameworks (MetaGPT) by keeping all decomposition and composition within the code-generation process rather than requiring separate LLM roles.

## Why It Matters / Open Questions

The practical impact is significant for practitioners working with smaller open-source code models: StableCode-3B with FUNCODER reaches 97.7% of GPT-4's HumanEval score, suggesting that framework-level improvements can partially close the gap between small and frontier models without additional training. The preliminary study quantifying self-test unreliability (a large fraction of 'failures' are actually test bugs) provides useful evidence for the field's ongoing debate about self-improvement loops. However, the method is most effective on well-defined, verifiable problems (competitive programming, math with numeric answers) and the authors acknowledge it does not naturally extend to open-ended software development or tasks without clear input-output semantics, leaving the generalization to broader coding workflows as an open question.
