## Problem

Using LLMs directly as world models for model-based RL is slow, costly, and unreliable, while existing code-based world model approaches (PDDL, custom DSLs) lack the flexibility and language understanding of LLMs. The key technical challenge is that synthesizing a correct code world model requires understanding complex environment descriptions, generating precise Python with non-trivial logic, and iteratively self-debugging long programs using feedback from unit tests and environment trajectories—capabilities that go beyond standard LLM code generation.

## Input / Output

The method takes as input a natural language description of an RL environment (adapted from Gymnasium documentation), a small offline dataset of transitions (s, a, r, s', d) collected from the environment (typically ~10 trajectories of up to 100 steps), and an LLM backbone (Llama 3 70B or GPT-4 Turbo). It produces a Python Environment class whose step(s, a) method jointly implements the deterministic transition and reward functions. The generated code is validated by checking whether it correctly reproduces all transitions in the dataset, with accuracy defined as the uniform fraction of correctly predicted next states, rewards, and done signals. The resulting CWM is then plugged into a planner (MCTS for discrete actions, CEM for continuous) to produce actions.

## Method

GIF-MCTS formulates code world model synthesis as a Monte Carlo Tree Search problem where nodes store partial programs split into a state (last L=2 lines) and a rollout (remaining completion used for evaluation), and edges correspond to one of three specialized actions: Generate (produce new code lines from a snippet, exploring the solution space), Improve (edit the full program given a specific failing transition as an in-context example, with Chain-of-Thought reasoning about the error), and Fix (resolve syntax or runtime bugs using error feedback). A modified UCT formula incorporates a same-action-type penalty to prevent the tree from growing only horizontally with repeated action types, and buggy nodes are assigned temporary values (decaying over up to f=3 fix attempts) so they remain selectable. The evaluation phase runs the candidate program against all training transitions as unit tests, and the resulting accuracy is backpropagated through the tree. This block-wise, feedback-driven search over complete programs—rather than token-level or full-program-only search—enables both incremental exploration and global edits, outperforming Thompson Sampling-based refinement (WorldCoder) and zero-shot CoT baselines across three benchmarks.

## Results

On the Code World Models Benchmark (CWMB, 18 RL environments), GIF-MCTS with Llama 3 70B (budget 50) achieves 0.84±0.03 CWM accuracy and 0.76±0.03 normalized return on discrete-action environments, and 0.35±0.03 accuracy / 0.22±0.01 return on continuous-action environments. With GPT-4 Turbo (budget 10), it reaches 0.91±0.08 accuracy and 0.81±0.06 return on discrete, and 0.40±0.03 / 0.26±0.01 on continuous. On the APPS Competition split (1000 problems), GIF-MCTS achieves 28.3±1.4% strict accuracy at pass@20, setting a new state of the art. On the simplified RTFM grid-world, GPT-4 Turbo with GIF-MCTS (budget 50) achieves perfect 1.00 accuracy and 1.00 normalized return.

## Baselines & Comparisons

GIF-MCTS outperforms WorldCoder (Tang et al., 2024b) on all three benchmarks and both LLM backbones: on CWMB discrete environments with Llama 3, it gains +5.0 points in accuracy (0.84 vs 0.79) and +16 points in normalized return (0.76 vs 0.60); on APPS Competition it reaches 28.3% strict accuracy vs WorldCoder's 25.1% and Zero-shot CoT's 23.2%; on RTFM with GPT-4 Turbo (budget 50) it achieves perfect 1.00 return vs WorldCoder's −0.06. Against Parsel (Zelikman et al., 2023) on APPS, GIF-MCTS achieves 28.3% vs 25.5% while evaluating only 20 programs versus Parsel's exponentially growing search. Against CodeRL (Le et al., 2022), GIF-MCTS improves from 17.9% to 28.3% strict accuracy. In the offline RL comparison (Appendix K), CWMs with GIF-MCTS outperform CQL (Kumar et al., 2020) on discrete-action environments (e.g., CartPole: 310.4 vs 317.6 raw reward, close to oracle 494) but CQL remains stronger on complex continuous physics tasks (e.g., HalfCheetah: CQL −1.3 vs CWM −22.8), though CQL suffers severe overfitting on the small datasets used.

## Relation to Prior Work

This paper builds on the MCTS framework (Kocsis & Szepesvári, 2006) and adapts it to LLM-guided code generation, departing from prior MCTS-for-code approaches (LATS, Zhang et al.) by operating at the level of multi-line code blocks rather than individual tokens or full programs, and by introducing three specialized action types (generate, improve, fix) tailored to iterative debugging with unit-test feedback. It is positioned against the concurrently proposed WorldCoder (Tang et al., 2024b), which also uses LLMs to write Python world models but relies on Thompson Sampling over complete programs and focuses on online grid-world learning; GIF-MCTS instead supports offline learning, continuous action/observation spaces, and a broader set of environments. The broader lineage includes code-based world models (AutumnSynth, PDDL-based planners) and LLM-based code generation (Parsel, CodeRL), but the specific formulation of synthesizing a full Gymnasium-compatible Python Environment class from a natural language description and a small trajectory dataset for downstream model-based planning is new.

## Why It Matters / Open Questions

Code World Models offer a compelling practical advantage: 4–7 orders of magnitude faster inference than querying an LLM directly as a world model, while remaining interpretable and debuggable. The CWMB benchmark (18 environments spanning discrete and continuous control) provides a standardized evaluation suite that the RL community can use to compare code-generation strategies for world modeling. Key open questions remain: the framework assumes deterministic, fully observable environments; it struggles with complex MuJoCo physics (Llama 3 fails entirely on Humanoid tasks); and the observed accuracy–return gap (e.g., 84% accuracy yielding only 76% normalized return) highlights that near-perfect prediction is critical for planning, especially for rare terminal states. Extending to stochastic/partially observable settings, integrating physics simulators as callable tools, and improving sample efficiency beyond 10 trajectories are natural next steps.
