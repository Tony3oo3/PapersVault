## Problem

Autoregressive transformer inference suffers from two compounding bottlenecks: prefill latency from processing all prompt tokens to build the KV cache, and decode-stage memory I/O from fetching the entire KV cache at every step, which grows linearly with sequence length and yields quadratic total memory reads. Prior hierarchical architectures (e.g., MEGABYTE) exploited global-to-local processing to reduce pretraining FLOPs but largely overlooked the substantial inference benefits, and treated the local module as a lightweight mapping rather than a critical component of language modeling.

## Input / Output

The model consumes subword tokens (BPE, vocabulary 50,304) grouped into fixed-size blocks of length L_B=4, which the embedder concatenates from a lookup table into single block embeddings of dimension D/L_B. Generation proceeds block-by-block: the block decoder produces a context embedding, which is projected into two prefix tokens that condition the token decoder to autoregressively emit the four tokens of the next block. The effective context window is 2048 tokens, but the token decoder only attends within its local block of 4 tokens plus the 2 prefix tokens, making its KV cache independent of total sequence length.

## Method

The Block Transformer splits a standard transformer into three components: a lightweight embedder (lookup-table concatenation), a block decoder (autoregressive transformer operating at block granularity with global self-attention across all blocks), and a token decoder (autoregressive transformer restricted to local attention within each block, conditioned on the block decoder's context embedding via projected prefix tokens). The block decoder reduces KV cache size by L_B and KV cache I/O by L_B², while the token decoder reduces KV cache I/O by L/L_B (256× for L=2048, L_B=4) and skips prefill entirely for all but the most recent block. A key empirical finding is that a balanced 1:1 parameter allocation between the two decoders outperforms the 6:1 ratio advocated by MEGABYTE, because the token decoder's local attention is nearly free in memory I/O and thus can absorb more parameters without hurting throughput. The architecture also supports uptraining from pretrained vanilla transformers by splitting layers and adding a small projection, recovering near-full performance with only 10% of the original training steps.

## Results

Block Transformers achieve 10–20× inference throughput over vanilla transformers at equivalent perplexity. At 302M non-embedding parameters, the Block model (loss 2.445, LAMBADA 29.5, WikiText 27.7) reaches 21.0K tokens/s prefill and 44.1K tokens/s decode throughput, versus 0.8K and 2.1K for the vanilla counterpart (loss 2.224, LAMBADA 10.0, WikiText 20.1). Scaling to 1.4B total parameters (1.2B non-embed), the Block model matches or exceeds the 410M vanilla on all zero-shot tasks (HellaSwag 36.66 vs 35.05, PIQA 68.63 vs 68.10, ARC 54.63 vs 51.68) while delivering ~15× prefill and ~12× decode throughput. Memory per sample drops from 608 MB (decode) to 77 MB, enabling ~6× larger batch sizes.

## Baselines & Comparisons

Against vanilla Pythia-architecture transformers (the primary baseline), Block Transformers trade a modest perplexity gap (e.g., loss 2.445 vs 2.224 at 302M non-embed params) for 21–26× higher decode and prefill throughput, respectively. When the Block model is scaled to 1.2B non-embed parameters, it surpasses the 302M vanilla on all five zero-shot benchmarks (HellaSwag 36.66 vs 35.05, PIQA 68.63 vs 68.10, ARC 54.63 vs 51.68) while still delivering ~12–15× throughput gains. Against MEGABYTE (the closest prior global-to-local architecture), the authors reimplement three MEGABYTE sizes and show that Block Transformers achieve over 1.5× higher throughput in the prefill-heavy setting, attributed to a more balanced 1:1 parameter allocation between block and token decoders versus MEGABYTE's 6:1 ratio. The paper also demonstrates that uptraining a pretrained vanilla transformer into a Block Transformer recovers near-full performance with only 10% of the original training steps, outperforming random initialization.

## Relation to Prior Work

The Block Transformer directly extends MEGABYTE's [84] global-to-local multiscale transformer architecture from byte-level to subword-level language modeling, but fundamentally repositions the design objective from pretraining FLOPs efficiency to autoregressive inference throughput. Where MEGABYTE treated the local (token) decoder as a lightweight mapping module and advocated a 6:1 parameter ratio favoring the global block decoder, this paper demonstrates that a balanced 1:1 ratio—or even a token-decoder-heavy allocation—is superior for both performance and inference speed. The architecture also relates to hierarchical transformers (Funnel Transformer, DataMux) and sliding window attention, but uniquely applies local processing at the finest granularity across all upper layers, enabling complete elimination of prefill computation in the token decoder—a structural advantage that sliding window attention cannot achieve due to its inter-layer dependencies.

## Why It Matters / Open Questions

The 10-20× inference throughput gain at equivalent perplexity is practically significant for LLM deployment, particularly in batch-serving scenarios where KV cache I/O dominates. The conceptual reframing—that the local token decoder is not a negligible mapper but a co-equal contributor to language modeling quality—challenges assumptions in prior hierarchical work and opens design space for future architectures. Key limitations include the need for 2-3× more parameters than vanilla models for equivalent quality, slower training wall-time, and unverified scaling beyond 1.4B parameters. Open questions include whether adaptive block lengths, parallel token decoding, and progressive uptraining from frontier vanilla models can close the parameter gap while preserving the inference advantage.
