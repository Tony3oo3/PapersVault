## Problem

Human-Oriented Binary Reverse Engineering (HOBRE) must bridge the semantic gap between stripped binary code and human-readable source code, but existing approaches are sub-optimal: small supervised models lack generalizability, continual pre-training of source code foundation models (SCFMs) is costly and risks catastrophic forgetting, and directly prompting LLMs fails on decompiled code that lacks symbolic information. No prior work effectively combines the pre-trained knowledge of both binary understanding models and SCFMs to close this cross-modal gap.

## Input / Output

The prober takes a disassembled binary function (x_asm) together with its program-analysis dependency graph (G_dep) and conditionally generates diverse, symbol-rich source code fragments (probed contexts) via nucleus sampling. The recoverer then receives the stripped decompiled code (x_dec) augmented with the top-5 probed contexts and produces either a natural language summary or a recovered function name. The probed contexts are not retrieved from a fixed pool but sampled from the prober's conditional distribution, giving them more flexibility and less noise than retrieval-based augmentation.

## Method

ProRec is a probe-and-recover framework whose core is a cross-modal knowledge prober built from CODEART (a structure-aware binary encoder) and a frozen CodeLlama SCFM, connected by a two-layer MLP that projects binary node-token embeddings into the SCFM's token space. Training proceeds in two stages: a CLIP-like contrastive pre-alignment of CODEART with a CodeT5+ source encoder, followed by a compute-efficient alignment where only the MLP and CODEART's last transformer layer are trainable (the SCFM is frozen and 4-bit quantized), maximizing the likelihood of paired source functions given binary input. At inference, the prober uses high-temperature nucleus sampling (top-p=0.75) to generate diverse function signatures, ranks them with a binary-signature dual-encoder to filter noise, then completes the top signatures at lower randomness (top-p=0.5). A black-box LLM recoverer (GPT-3.5, Claude-3, or Gemini-Pro) receives the decompiled code plus probed contexts, performs an internal relevance analysis step, and generates the final summary or function name—leveraging both the SCFM's parametric source-code knowledge and the LLM's strong reasoning ability.

## Results

On binary summarization, ProRec achieves a 10.3% relative gain in CHRF (e.g., 33.5 vs. 30.4 for GPT-3.5-turbo) and a 16.7% relative gain in the GPT4-based functionality metric (4.2 vs. 3.6) over the zero-shot baseline. On binary function name recovery, ProRec yields a 6.7% absolute increase in token-level precision (22.2 vs. 16.3 for GPT-3.5-turbo) and a 7.4% absolute increase in token-level recall (28.3 vs. 20.9). Human evaluation confirms ProRec's advantage, scoring 4.76/4.62 on context relevance/functionality versus 4.29/4.22 for zero-shot.

## Baselines & Comparisons

ProRec consistently outperforms both the zero-shot baseline and the retrieval-augmented baseline across all three LLM recoverers (GPT-3.5-turbo, Gemini-Pro, Claude-3) on both tasks. Against the retrieval-augmented baseline, ProRec wins by a large margin on function name recovery (e.g., 22.2 vs. 15.5 token-level precision for GPT-3.5-turbo), while retrieval sometimes degrades summarization quality (e.g., Gemini-Pro CHRF drops from 27.1 to 26.4 with retrieval but recovers to 27.6 with ProRec). In the appendix comparison with the supervised CP-BCS method [75], CP-BCS-generated comments actually hurt summarization performance (CHRF drops from 30.4 to 29.0), whereas ProRec improves it, demonstrating that cross-modal probing is more effective than supervised binary summarization for this task. The paper also shows that self-probing (using the LLM itself to generate contexts without cross-modal alignment) performs only marginally better than zero-shot, confirming that the binary-source alignment is essential for generating informative probed contexts.

## Relation to Prior Work

ProRec draws a direct analogy between the binary-source semantic gap and the pixel-language gap in vision, repurposing the frozen-encoder-plus-LLM paradigm popularized by Flamingo and BLIP-2 for the largely unexplored binary-source modality pair. It builds on CODEART as a structure-aware binary encoder and CodeLlama as a frozen SCFM, connected by a lightweight MLP projection, but departs from both end-to-end multi-modal training and retrieval-augmented generation: the prober *generates* diverse source code fragments conditioned on binary input rather than retrieving them from a fixed document pool, and a black-box LLM performs the final recovery with an explicit internal relevance-analysis step. This positions ProRec between supervised HOBRE models (SymLM, CP-BCS) that lack generalizability and direct LLM prompting that struggles with symbol-stripped decompiled code, offering a compute-efficient middle ground where only ~0.2–0.4% of parameters are trainable.

## Why It Matters / Open Questions

The framework provides a practical, low-cost path to improving binary reverse engineering without expensive continual pre-training of SCFMs or task-specific supervised training, and it works with proprietary black-box LLMs that cannot be fine-tuned. The consistent outperformance over both zero-shot prompting and retrieval-augmented baselines across three different LLM recoverers and two tasks validates the probe-and-recover decomposition. Key limitations include the restriction to intra-procedure analysis, the use of a simple two-layer MLP alignment that the authors acknowledge may be suboptimal, and the dependence on paired binary-source training data that must be constructed via compilation. Open questions include extending to inter-procedure and program-level analysis, exploring richer alignment objectives, and whether the approach generalizes to other low-level-to-high-level lifting tasks beyond C-style decompilation.
