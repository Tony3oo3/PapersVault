## Problem

When well-trained models (learnwares) are developed on heterogeneous feature spaces, existing approaches either require access to raw data or auxiliary co-occurrence data to bridge the spaces, and those that avoid these requirements (e.g., Hetero) neglect label information, leading to entangled class embeddings in the learned subspace and model identification based solely on marginal distributions. This paper identifies that model pseudo-labels are a previously underexploited signal that can simultaneously improve subspace learning quality and enable more accurate model-task matching.

## Input / Output

The system receives developer models accompanied by RKME_L specifications—reduced weighted point sets {(β_j, z_j, y_j)} that sketch both the marginal feature distribution and the model's conditional output distribution without exposing raw data. On the user side, the input is unlabeled task data plus a small labeled subset (e.g., 100 points) from which a similar RKME_L requirement is generated. The output is a recommended learnware model plus a feature transformation toolkit (per-block encoding functions h_k and decoding functions g_k) that lets the user project their data into the model's feature space for prediction or ensemble with a self-trained model.

## Method

The core contribution is extending the RKME specification to RKME_L by explicitly splitting each reduced-set sample into a feature component and a pseudo-label component, thereby encoding both P(X) and P(X|Y). For subspace learning, the system optimizes a three-term objective—contrastive loss (extended Self-VPCL aligning embeddings of different feature-block slices of the same sample), reconstruction loss (ensuring decoders faithfully reconstruct inputs), and a supervised loss (a simple classifier on pooled embeddings that makes class representations separable)—over per-block encoder/decoder networks. For model identification, the system computes a combined distance between user requirement and model specification that includes both marginal MMD and per-class conditional MMD terms in the unified subspace, enabling exclusion of models with mismatched conditional distributions and inclusion of models whose marginal distributions differ but whose conditional structure matches. Two specification generation mechanisms are provided: a unified one (sketch marginal first, then assign pseudo-labels via the model) and a classification-specialized one that directly optimizes a joint objective balancing marginal and conditional distribution approximation (Eq. 2).

## Results

On 23 classification datasets from the Tabzilla benchmark, the proposed specialized method (Our_cls) achieves 67.4% average accuracy with a mean rank of 1.435, outperforming all baselines. On 7 regression datasets, the unified method (Our_unify) achieves 0.194 average RMSE with a mean rank of 1.286. The method wins on 22 out of 23 classification datasets and 6 out of 7 regression datasets against the strongest competitor (Align_label), and the win/loss/tie record against Hetero (the prior heterogeneous learnware method without label exploitation) is 22/0/1 for classification and 6/1/0 for regression.

## Baselines & Comparisons

Against self-training baselines, Our_cls (67.4% avg accuracy) substantially outperforms LightGBM (57.7%) and TabPFN (59.9%), confirming that reusing well-trained heterogeneous models is far more effective than training from scratch with only 100 labeled samples. Against the learnware-dock baselines from Beimingwu, Align_unlabel (35.3%) is catastrophically weak because it aligns feature spaces without any label signal, while Align_label (58.1%) improves via fine-tuning but still trails Our_cls by 9.3 points because it does not leverage cross-task knowledge. Against cross-table pre-training methods, TransTab (57.2%) and XTab (53.0%) underperform because they train a single unified backbone that cannot match per-task model quality, and they also require access to raw developer data. The most direct comparison is with Hetero (Tan et al., IJCAI 2023), the prior heterogeneous learnware method that uses unsupervised subspace learning without label information; Our_cls wins on 22 of 23 classification datasets (8.1% average accuracy gain) and 6 of 7 regression datasets (2.9% RMSE reduction), validating that explicit label exploitation is the key improvement. Finally, replacing the proposed RKME_L specification with the original RKME specification (Our_basic, 65.2%) yields a 2.2-point drop, confirming that encoding both marginal and conditional distributions in the specification is essential for effective model identification.

## Relation to Prior Work

This paper extends the learnware paradigm's heterogeneous feature space handling (Tan et al., IJCAI 2023) by explicitly incorporating model pseudo-labels into both the specification and the subspace learning process. The foundational RKME specification (Wu et al., TKDE 2023) is rewritten as RKME_L, splitting each sample into a feature component and a pseudo-label component, enabling supervised subspace learning and conditional distribution matching. The contrastive loss for aligning feature block embeddings is adapted from TransTab's Self-VPCL objective (Wang & Sun, NeurIPS 2022), while the overall system architecture follows the Beimingwu learnware dock framework (Tan et al., KDD 2024).

## Why It Matters / Open Questions

The paper demonstrates that label information from model outputs is not merely helpful but essential for meaningful subspace learning in heterogeneous learnware systems—without it, embeddings become entangled or the subspace becomes meaningless under weak feature correlations. This opens a path toward privacy-preserving model reuse across genuinely different feature spaces (e.g., different hospitals using different clinical tables) without requiring raw data access. A key limitation is the assumption of a shared label space across all models; extending to heterogeneous label spaces remains open. The practical impact is significant for the learnware ecosystem but the approach is still in early stages, validated primarily on tabular benchmarks.
