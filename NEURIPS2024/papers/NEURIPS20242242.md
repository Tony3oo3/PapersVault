## Problem

Deep model-based RL requires millions of interactions to learn world models that are opaque, non-transferable, and hard to audit, while LLM agents like ReAct use the LLM as an implicit world model but consume O(T) LLM calls per episode and never actually update their knowledge. The paper asks how an agent can rapidly acquire, transfer, and communicate world knowledge as an explicit, interpretable, and sample-efficient representation that supports planning toward novel goals.

## Input / Output

The agent receives a natural-language goal (e.g., 'open the door with the key') and a symbolic state represented as a set of typed objects, each with string-valued fields (name, x, y, plus type-specific attributes like door open/closed/locked). It outputs a Python program implementing a context-conditioned transition function T̂ and reward function R̂ (which returns both a scalar reward and a done flag), and then produces actions via depth-limited value iteration or MCTS. The reward function is parameterized by the goal context, so a single learned transition function can serve multiple goals by simply updating the reward subroutine.

## Method

WorldCoder uses GPT-4 to iteratively synthesize and debug a Python program that must satisfy two logical constraints: φ1 (data consistency — the program must correctly predict every observed state transition and reward in the replay buffer) and φ2 (optimism under uncertainty — the program must admit at least one trajectory from the initial state to a positive-reward terminal state). Program synthesis proceeds via a refinement loop where the LLM is back-prompted with counter-examples it cannot explain, scheduled by the REx bandit algorithm to balance exploring under-refined candidates against exploiting high-accuracy ones. Planning uses the synthesized world model with value iteration for simple gridworlds or a modified MCTS (rollouts replaced by a BM25 text-similarity heuristic) for long-horizon AlfWorld tasks. The key architectural insight is that the LLM does not simulate the world or perform planning itself; it only writes and debugs the transition/reward code, while a classical planner operates over that code. This yields polynomial sample complexity (diameter × logical dimensionality of the model space) and enables transfer by refining old programs when new objects or goals appear.

## Results

On Sokoban, WorldCoder builds a functional world model within ~50 actions and generalizes to harder levels, while PPO requires >1 million steps for 2-box Sokoban and ReAct achieves only 15% ± 8% success on basic levels. On Minigrid's UnlockPickup environment, WorldCoder with the optimism objective (φ₂) learns a correct world model in ≤100 actions, whereas PPO fails to obtain sufficient positive-reward signal even after 3×10⁸ steps. On AlfWorld, the agent synthesizes a 250+ line world model and typically solves tasks in the first episode with ~20 exploratory steps. After an initial ~400k-token LLM investment (~$15), WorldCoder requires O(1) LLM calls per new task, versus O(T) calls per episode for ReAct-style agents.

## Baselines & Comparisons

Against ReAct [77], WorldCoder is dramatically more effective: ReAct succeeds on only 15% ± 8% of basic Sokoban levels despite having the same pretrained knowledge, while WorldCoder solves them after ~50 actions of learning. The asymptotic LLM cost also differs fundamentally—ReAct requires an LLM call at every action (O(T) per episode), whereas WorldCoder front-loads ~400k tokens once and then plans without further LLM queries (O(1) per task). Against PPO via Stable-Baselines3 [49], WorldCoder is orders of magnitude more sample-efficient: PPO needs >1M steps for 2-box Sokoban and 10⁴–10⁵ steps for most Minigrid environments, and completely fails on UnlockPickup after 3×10⁸ steps, while WorldCoder solves the same tasks in ≤100 actions. Against DreamerV3 [27] on Sokoban, the same pattern holds—deep model-based RL requires millions of environment interactions to reach basic competence. The paper also ablates the optimism objective (φ₂), showing that without it, WorldCoder cannot solve sparse-reward Minigrid environments or follow new natural-language instructions, confirming that the logical constraint between the program and planner is essential for both exploration and zero-shot goal generalization.

## Relation to Prior Work

WorldCoder sits at the intersection of three threads: (1) model-based RL (Dreamer, MuZero), but replaces the neural world model with a human-readable Python program; (2) LLM agents like ReAct, but inverts the role—the LLM does not *act as* the world model by reasoning step-by-step, but *builds* a world model as code and then delegates planning to a classical planner; and (3) prior program-synthesis-for-world-models work (Das et al., Evans et al., Tsividis et al.), which used restricted DSLs, whereas WorldCoder uses Turing-complete Python and LLM-guided refinement (via REx) to make synthesis tractable. The optimism-under-uncertainty objective is a new instantiation of a classic RL principle, reframed as a logical constraint between a program and a planner rather than a probabilistic bonus.

## Why It Matters / Open Questions

The dramatic sample-efficiency gap (≈50 actions vs. >10⁶ for deep RL on basic Sokoban) and the ability to transfer knowledge across environments by editing code suggest a practical path toward interpretable, rapidly-adaptable agents in structured domains. However, the approach is confined to deterministic, symbolic, discrete-state environments, and the paper acknowledges that bridging to continuous/perceptual settings (via neurosymbolic grounding or probabilistic programs) remains open. A key open question is whether the code-based world model paradigm can scale to the messy, high-dimensional state spaces where deep RL currently dominates, and whether library-learning-style knowledge management can replace the current ad-hoc code-editing transfer mechanism.
