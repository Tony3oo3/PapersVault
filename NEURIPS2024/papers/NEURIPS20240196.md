## Problem

Closed-source LLMs (GPT-4, Claude 3) are accessible only via API, making it difficult to integrate structured knowledge from knowledge graphs to reduce hallucinations on domain-specific questions. Existing KG prompting methods suffer from three practical barriers: the enormous search space of real-world KGs, prohibitive API costs from verbose prompts, and rigid hand-crafted prompt templates that cannot adapt to varying question semantics.
![Teaser figure](../imgs/NEURIPS20240196/cropped_page1_idx0.webp)

## Input / Output

The method takes a multiple-choice question (with source entities extracted from the question stem and target entities from answer choices) and a domain KG (ConceptNet for commonsense, UMLS+DrugBank for medical), and produces a single textual prompt combining extracted reasoning chains with a selected template format. The prompt is submitted to a black-box LLM API (GPT-3.5-turbo) which returns the predicted answer; no model weights or intermediate activations are accessed. The extracted knowledge is constrained to be concise (short paths) to minimize token count and API cost.

## Method

KnowGPT comprises two modules. First, a deep RL agent (policy gradient, inspired by DeepPath) navigates the KG from source to target entities, guided by a composite reward that balances reachability (+1/−1), context-relatedness (cosine similarity between the walked path embedding and the question embedding via a learned projection matrix), and conciseness (inverse path length), yielding informative and compact reasoning chains. Second, a contextual Multi-Armed Bandit selects, per question, the best combination of knowledge extraction strategy (RL-based path search vs. heuristic 2-hop subgraph) and prompt template (raw triples, natural-language sentences, or LLM-generated graph description) by maximizing an expectation function that couples OLS-regression-based exploitation (learning context-to-reward mappings per arm) with UCB-based exploration (penalizing under-selected arms). The MAB is updated online from LLM feedback (correct/incorrect), requiring no gradient access to the LLM.

## Results

KnowGPT (built on GPT-3.5) achieves 81.8% accuracy on CommonsenseQA (IH test), 92.4% on OpenBookQA (test), and 78.1% on MedQA-USMLE (test), outperforming all 16 baselines across every dataset. On average, KnowGPT improves over GPT-3.5 by 23.7% and over GPT-4 by 2.9%. On the official OpenBookQA leaderboard, KnowGPT reaches 92.6% accuracy, surpassing the human performance benchmark of 91.7% and exceeding the best ensemble method (GenMC Ensemble, 92.0%) without any ensembling.

## Baselines & Comparisons

KnowGPT wins against all 22 baselines on every dataset. Against the strongest zero-shot LLM (GPT-4), KnowGPT gains +3.3% on CommonsenseQA, +1.4% on OpenBookQA, and +1.8% on MedQA, demonstrating that structured KG prompting can surpass a more powerful base model. Among KG-enhanced LMs, the best baseline is JointLK (74.4% CSQA IHtest, 85.6% OBQA, 40.3% MedQA), which KnowGPT outperforms by 7.4, 6.8, and 37.8 percentage points respectively. Among KG-prompting methods, Mindmap is the closest competitor (78.4% CSQA IHtest, 88.2% OBQA, 75.1% MedQA), with KnowGPT leading by 3.4, 4.2, and 3.0 points. On the OpenBookQA official leaderboard, KnowGPT (92.6%) exceeds the human benchmark (91.7%) and the best non-ensemble method (GSC, 87.4%) by 5.2 points, while also surpassing the GenMC Ensemble (92.0%) without any ensemble strategy. The efficiency analysis further shows KnowGPT uses only 348 average tokens per query versus 1129 for CoK and 761 for Mindmap, yielding the lowest API cost ($6.64 vs. $21.54 and $14.52) among LLM-based methods while achieving the highest accuracy.

## Relation to Prior Work

KnowGPT builds on the RL-based KG reasoning paradigm established by DeepPath [76], repurposing its MDP formulation and policy-gradient training for knowledge extraction in a prompting context rather than end-to-end QA. It departs from prior KG prompting methods (CoK, RoG, Mindmap) that rely on fixed, manually-designed prompt templates by introducing an automatic, context-aware prompt selection mechanism via Multi-Armed Bandit. The framework also contrasts with white-box KG-enhanced LMs (QA-GNN, JointLK, GreaseLM) that require model architecture access, positioning itself squarely in the black-box API-only regime that dominates practical LLM deployment.

## Why It Matters / Open Questions

KnowGPT addresses three practical bottlenecks in deploying KG-augmented LLMs—search space, API cost, and prompt engineering labor—making KG prompting more accessible for industry use. The near-human performance on OpenBookQA (92.6% vs. 91.7%) and the ability to outperform GPT-4 using only GPT-3.5 suggest that structured domain knowledge injection can compensate for model scale. Key limitations include dependence on KG quality (noisy triples from online corpora can mislead the LLM) and the current restriction to multiple-choice QA; open questions include scalability to open-ended generation, handling of very large KGs, and whether the MAB selection generalizes to new domains without retraining.
