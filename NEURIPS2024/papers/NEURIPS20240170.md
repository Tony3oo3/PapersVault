## Problem

Existing LLM agent frameworks propose individual capabilities—planning, reflection, tool use, memory, and human interaction—but it remains unclear how to integrate all components into a unified architecture and optimize them jointly end-to-end. In particular, the decision of when to proactively seek human expert advice requires complex self-evaluation that is difficult to ground-truth or optimize through supervised fine-tuning alone, and no prior work trains the full agent (including advice-seeking) with reinforcement learning.

## Input / Output

The agent consumes a user question along with product metadata, retrieved memory entries (historical QA pairs and knowledge entries via embedding-based search), search tool results (e.g., SQL query outputs), and expert advice when invoked. The LLM generates a token stream where specific tokens are interpreted as function calls (e.g., [SeekAdvice], [SearchProduct], [RetrieveMemory], [Reflection]) by an executor that mutates the (context, memory) state; the final outputs are a long natural-language answer, a short answer, reflection text distilled from expert feedback, and updated memory entries. The state transition is token-level: each generated token is an action, and the executor's logic determines the next state, making the entire agent a token-level MDP.

## Method

AGILE formulates the LLM agent as a token-level MDP where the LLM is the policy model, the action space is the vocabulary, and the state is the (context, memory) pair; an executor interprets function-name tokens to perform memory I/O, tool invocation, and environment interaction. Training is two-stage: first, imitation learning on expert-generated trajectories (loss computed only on action tokens with context-aware attention masks), then PPO with a novel session-level optimization algorithm that decomposes trajectory-level rewards into per-session proxy rewards using a state advantage function A_i = V(S_{i+1}) − V(S_i) to handle inter-session dependencies through memory. The reward structure encodes correctness (+1), incorrectness (0), and a fixed advice-seeking cost (−c), allowing the agent to learn the optimal trade-off between accuracy and human resource expenditure. The key architectural insight is that seeking advice, reflection, memory updates, and tool use are all unified as actions within a single policy, so RL simultaneously optimizes when to ask for help, what to reflect on, and how to use tools—capabilities that are individually hard to supervise but jointly tractable under a reward signal.

## Results

On ProductQA (the paper's introduced benchmark), agile-vic13b-ppo achieves 85.4% short-answer accuracy and a total score of 0.784, outperforming agile-gpt4-prompt (78.0% accuracy, 0.718 total score) by 9.2% relative total score. On MedMCQA, the 7B-parameter agile-mek7b-ppo reaches 85.2% accuracy (advice rate 31.6%), surpassing the SOTA GPT-4-MedPrompt (79.1%) and improving over the base Meerkat-7b (53.4%) by 31.8 percentage points. On HotPotQA, agile-vic13b-ppo achieves 67.5% exact-match accuracy, a 40.0% relative improvement over the strongest baseline ReAct-GPT-4 (48.2%), and outperforms agile-gpt4-prompt by 10.8% in total score.

## Baselines & Comparisons

AGILE consistently outperforms all baselines across all three benchmarks. Against GPT-4 in the AGILE framework (agile-gpt4-prompt), agile-vic13b-ppo wins on ProductQA (total score 0.784 vs. 0.718 short / 0.747 long), MedMCQA (0.726 vs. 0.721), and HotPotQA (0.628 vs. 0.567), despite using a 13B open-source model versus GPT-4. On MedMCQA, the 7B agile-mek7b-ppo (85.2% accuracy) surpasses both the base Meerkat-7b (53.4%) and the SOTA GPT-4-MedPrompt (79.1%), with the advice-seeking mechanism alone contributing a 23.2% accuracy gain. On HotPotQA, agile-vic13b-ppo (67.5% EM) substantially outperforms ReAct-GPT-4 (48.2%), CRITIC (44.3%), Expel (39.0%), and AutoAct (38.4%), demonstrating that the RL-trained agent with memory, tools, and adaptive advice-seeking generalizes well to multi-hop reasoning. Notably, even the smaller agile-vic7b-ppo (7B) beats agile-gpt4-prompt on ProductQA total score (0.764 vs. 0.718 short), highlighting the value of RL training over raw model scale.

## Relation to Prior Work

This paper unifies the fragmented landscape of LLM agent components—planning (ReAct), reflection (Reflexion), tool-use (Toolformer, Gorilla), and memory (Voyager, RAP)—into a single RL framework where the LLM serves as the policy model and all modules are jointly optimized end-to-end via PPO. It departs from prior agent work by introducing proactive human advice-seeking as a learnable policy action, rather than relying on passive feedback or predefined rules as in earlier human-agent interaction studies. The session-level optimization algorithm (Appendix A) addresses a practical gap: how to apply trajectory-level RL to agents whose sessions are not independent due to shared memory, a problem not addressed by prior agent RL work like WebGPT.

## Why It Matters / Open Questions

The framework demonstrates that RL-trained 7B/13B agents can match or exceed GPT-4 agents in structured QA settings, suggesting that agent architecture and policy optimization can compensate for raw model scale. However, the evaluation relies on a strong assumption that 'expert advice' equals the ground-truth answer, which limits the practical transferability of the headline results to real deployment where human experts are fallible. Open questions include whether the seeking-advice policy generalizes when experts provide noisy or partial information, how the framework scales to multi-agent or non-QA environments, and whether the session-level optimization algorithm remains effective with longer-range memory dependencies.
