## Problem

Current state-of-the-art open-source math reasoning models are all distilled from closed-source LLMs (GPT-3.5/4), which introduces legal restrictions, high generation costs, and irreproducibility. A key barrier to using open-source LLMs for this distillation is their lower training set coverage compared to GPT-4: even with 12× more sampled solutions, Mixtral still lags behind GPT-4 on the MATH benchmark, limiting the quality of the resulting fine-tuned models.

## Input / Output

The data generation pipeline takes math word problems from GSM8K and MATH training sets along with their reference text solutions (with intermediate numbers masked by single-letter symbols) as input to a few-shot prompt, and produces code-interpreter style solutions that interleave natural language reasoning with Python code blocks delimited by <llm-code> and <llm-code-output> tokens. At inference time, the fine-tuned model invokes a Python interpreter after each code block, appends the execution result, and resumes autoregressive generation, ultimately producing a final numeric answer inside a \boxed{} block. Generation is constrained to a maximum of 3 code blocks, 512 new tokens per code block, and 4096 total input-output tokens.

## Method

The core contribution is a synthetic data generation pipeline using the permissively licensed Mixtral 8x7B model to produce 1.8M code-interpreter problem-solution pairs. The key prompting novelty is masked text solution prompting: reference solutions are pre-processed to replace all intermediate numerical values with single-letter symbols (e.g., 9→M, 63→N), which prevents the model from copying answers via shortcut solutions while still guiding the reasoning trajectory. This boosts MATH training set coverage from 80.1% to 85.9% (and 99.1% to 99.9% for GSM8K) compared to default few-shot prompting. The pipeline combines multiple prompting strategies (default, subject-specific, masked-text) with brute-force sampling (up to 896 solutions per MATH problem), followed by post-processing to remove syntactically noisy solutions and a fair round-robin downsampling strategy that balances representation across problems of varying difficulty. A code-preferred selection strategy (Any-Code) further filters out text-only solutions when code-based alternatives exist, improving greedy decoding accuracy by ~13%.

## Results

The best model, OpenMath-CodeLlama-70B, achieves 84.6% on GSM8K and 50.7% on MATH with greedy decoding, and 90.8% / 60.4% with self-consistency (k=50). On GSM-Hard it scores 66.6%, on SVAMP 87.8%, on TabMWP 74.2%, on ASDiv 84.7%, and on MAWPS 95.7%. The 7B variant (OpenMath-Mistral-7B) reaches 80.2% GSM8K and 44.5% MATH, competitive with GPT-distilled 7B models. Training set coverage of the synthesized dataset is 99.9% for GSM8K and 93% for MATH.

## Baselines & Comparisons

Against ToRA (the strongest GPT-distilled baseline), OpenMath-CodeLlama-70B edges out ToRA on GSM8K (84.6% vs 84.3%) and MATH (50.7% vs 49.7%) with greedy decoding, and pulls ahead more clearly with self-consistency: 90.8% vs 88.3% on GSM8K and 60.4% vs 56.9% on MATH. Against MAmmoTH-70B, OpenMath-CodeLlama-70B gains 7.7 points on GSM8K (84.6% vs 76.9%) and 8.9 points on MATH (50.7% vs 41.8%). Against MetaMath-70B, the gap is even larger: +2.3 on GSM8K (84.6% vs 82.3%) and +24.1 on MATH (50.7% vs 26.6%). Against WizardMath-70B, OpenMath-CodeLlama-70B leads by +3.0 on GSM8K and +28.0 on MATH. The only model that outperforms OpenMath-CodeLlama-70B across the board is GPT-4's Code Interpreter (97.0% GSM8K, 69.7% MATH), but that is a closed-source system not available for fine-tuning.

## Relation to Prior Work

This paper extends the code-interpreter solution format introduced by ToRA [8] and the broader knowledge distillation paradigm (MetaMathQA, MAmmoTH, WizardMath) where large models generate synthetic problem-solution pairs for instruction-tuning smaller models. The key departure is replacing closed-source generators (GPT-3.5/4) with the permissively licensed Mixtral model, addressing the legal, cost, and reproducibility limitations of proprietary distillation pipelines. The central technical novelty is the masked text solution prompting strategy, which leverages reference solutions from GSM8K and MATH while preventing the model from copying intermediate values or final answers, combined with brute-force sampling to close the coverage gap between open-source and closed-source generators.

## Why It Matters / Open Questions

OpenMathInstruct-1 provides the first large-scale (1.8M pairs), permissively licensed math instruction tuning dataset generated entirely from open-source models, removing the legal and reproducibility barriers that have constrained the field. The masked text solution prompting technique is a practical, reusable method for any benchmark with reference solutions. Key limitations include the presence of semantically noisy solutions (correct answers via flawed reasoning) that are difficult to filter, and the observation that in-domain benchmark gains may not transfer to perturbed inputs (GSM-Hard). Open questions include whether the approach generalizes to harder or multimodal math problems, and whether the 93% MATH coverage ceiling reflects a fundamental capability limit of current open-source models.
