## Problem

MoE inference is 15× slower for language modeling and 3× slower for machine translation compared to FLOP-equivalent dense models, yet prior optimizations narrowly target specific kernels without addressing the root algorithmic inefficiencies. The static gating policy assumes balanced expert loads, causing up to 12.8× (LM) and 64× (MT) waste from placeholder computation, excessive memory allocation for dispatch masks, and severe load imbalance across GPUs. This paper identifies these sources of inefficiency and proposes system-level optimizations that improve throughput, memory use, and robustness without degrading model quality.

## Input / Output

The method operates on the MoE inference pipeline itself, consuming token sequences (batch sizes up to 80 for LM, 96 for MT) along with the gating function's expert assignment decisions and runtime expert activation statistics. It produces the same generated or translated text as standard MoE inference but with variable per-expert token counts (replacing fixed-capacity dispatch), dynamically sized all-to-all messages between GPUs, and a CPU-GPU expert parameter cache that evicts based on temporal locality. The load balancing component additionally consumes historical activation fractions A_mb to compute expert-to-GPU placement, constrained so each GPU hosts exactly E/D experts.

## Method

The paper proposes three complementary optimizations. (1) Dynamic Gating replaces the static dispatch mask (a sparse tensor of dimension E×S×S×C requiring O(S²EDC) batch matrix multiplication) with an argsort-based indexing procedure of complexity O(S log S + SD), using two rounds of all-to-all communication: a lightweight size-notification round (≈20 μs) followed by the actual token transfer, eliminating placeholders entirely. (2) Expert Buffering exploits temporal locality in expert activation by keeping only a fixed cache of hot experts in GPU memory and buffering the rest in CPU memory, with a LIFO eviction policy that accounts for the sequential-by-ID execution order of experts on each GPU, overlapping parameter transfer with token transfer to hide latency. (3) Load Balancing formulates expert-to-GPU placement as a multi-way number partitioning problem and solves it greedily by sorting experts by historical load and assigning to the least-loaded GPU; for correlated expert activations (MT-decoder), it augments the load estimate with Pearson correlation terms to colocate anti-correlated experts, reducing worst-case GPU load from above 0.6 to below 0.4.

## Results

Dynamic gating improves maximum inference throughput by 6.21–11.55× for Language Modeling, 5.75–10.98× for MT Encoder, and 2.58–5.71× for MT Decoder compared to the static gating baseline (Fairseq/GShard). It also reduces activation memory by 79.6% for LM (6.29 GB → 1.28 GB) and 44.2% for MT (1.89 GB → 1.05 GB), enabling batch sizes up to 8× larger for LM and 2× larger for MT. Expert Buffering further reduces static GPU memory for expert parameters by 2.25 GB (1.47× reduction), while Load Balancing provides an additional 1.11–1.19× throughput gain and reduces worst-case per-GPU load from >0.6 to <0.4 of total tokens.

## Baselines & Comparisons

Against the static gating baseline (Fairseq/GShard [2,8]), dynamic gating achieves the largest speedups: 6.21× for LM, 5.75× for MT-Encoder, and 2.58× for MT-Decoder on a single node, scaling to 11.55×, 10.98×, and 5.71× on multi-node deployments. Against Tutel [13], which replaces sparse matrix multiplication with hash-table lookups and custom cumsum kernels, dynamic gating still wins by 3.32× (LM), 5.33× (MT-Enc), and 1.88× (MT-Dec). Against FasterMoE [28], which overlaps per-group communication with computation, dynamic gating outperforms by up to 2.49× at the same batch size by avoiding GPU kernel launch overheads. Against Megablock [30], which uses a single BCSR sparse matrix multiplication, dynamic gating underperforms at small batch sizes (4–16) but surpasses it by 1.46× at batch size 80, demonstrating better scalability as the sparse-matrix overhead in Megablock grows with batch size while dynamic gating's kernel-launch cost remains constant.

## Relation to Prior Work

This paper builds on the MoE Transformer lineage (GShard, Switch Transformer, ELSLM) and the expert parallelism paradigm, but departs from prior inference optimizations (Tutel, FasterMoE, Megablock, DeepSpeed-MoE) that focused on custom kernels, communication overlap, or block-sparse matrix execution. The key conceptual departure is identifying the static gating function itself—not all-to-all communication—as the primary source of inference inefficiency, and replacing it with a dynamic, variable-capacity dispatch. Expert Buffering and runtime load balancing are novel contributions that exploit temporal locality and activation statistics, respectively, rather than targeting kernel-level or communication-level optimizations.

## Why It Matters / Open Questions

As MoE LLMs (Mixtral, DeepSeek-MoE, Gemini) move into production serving, the 15× latency gap for language modeling and 3× for machine translation identified here represent a critical deployment bottleneck. The three optimizations are orthogonal and composable, and the dynamic gating technique in particular could be integrated with distillation, kernel fusion, and communication optimizations for compounding gains. Open questions include whether these techniques scale to the 100B+ parameter MoE models now in commercial use, how heterogeneous expert designs (varying expert sizes) would alter the gating and buffering strategies, and whether next-generation interconnects (optical, Grace Hopper) change the cost-benefit calculus for expert movement.
