## Problem

Existing LLM benchmarks evaluate innate out-of-the-box capabilities but do not assess an agent's ability to improve over time from accumulated feedback, which is critical for post-deployment continuous enhancement. This paper identifies the missing evaluation setting for measuring how LLM agents adapt and improve across a sequential stream of inputs and feedback signals.

## Input / Output

At each time step t, the agent receives a natural language query x_t and retrieves k relevant past examples from a vector database (encoded with bge-base-en-v1.5). After producing its output ŷ_t (SQL, Python code, API call, diagnosis, or answer), the agent receives a binary correctness signal fb_t ∈ {0,1} from the environment. Evaluation is the aggregate metric (execution accuracy, pass@1, exact match, etc.) over the entire sequence of T instances, not per-instance performance.

## Method

StreamBench serializes seven static datasets into streaming sequences with binary feedback, providing a unified online evaluation framework. The key streaming baseline, Self-StreamICL, stores only correct self-generated (x_t, ŷ_t) pairs in an external memory and retrieves them as in-context examples, avoiding the distracting signal of incorrect outputs that prior methods (GrowPrompt, MemPrompt) include with verbalized feedback. The strongest method, MAM-StreamICL, extends this to a multi-agent round-robin setup where K agents (GPT-3.5, Gemini, Claude) share a single memory of correct outputs, so each agent benefits from the complementary strengths of others while incurring only the cost of one agent per time step. Ablations confirm that filtering to correct outputs alone yields consistent gains, and that both multi-agent memory sharing and multi-agent inference contribute independently to the final performance boost.

## Results

Across seven diverse tasks, MAM-StreamICL (the proposed multi-agent streaming method) achieves the highest averaged performance on every dataset, with the most dramatic gains on DDXPlus (83.50% accuracy vs. 52.85% zero-shot, a +30.65 point improvement) and ToolBench (75.87% vs. 61.38%). Self-StreamICL, which stores only correct self-generated outputs in memory, consistently outperforms the prior streaming baselines GrowPrompt and MemPrompt across all seven datasets. Even stronger models (gpt-4o, gemini-1.5-flash) continue to benefit from streaming: gpt-4o with Self-StreamICL reaches 92.01% on DDXPlus and 80.58% on Spider, surpassing its own zero-shot scores by 21.37 and 7.04 points respectively.

## Baselines & Comparisons

MAM-StreamICL outperforms all non-streaming baselines (Zero-Shot, Few-Shot, CoT, Self-Refine) and both prior streaming methods (GrowPrompt, MemPrompt) on every one of the seven datasets. Against CoT (Kojima et al.), the gap is particularly large: MAM-StreamICL exceeds CoT by 14.16 points on Spider, 17.17 on DS-1000, and 25.30 on DDXPlus, while CoT actually underperforms zero-shot on most tasks. Against Self-Refine (Madaan et al.), MAM-StreamICL leads by 7.94 points on Spider, 6.80 on DS-1000, and 30.61 on DDXPlus. Against the prior streaming baselines GrowPrompt and MemPrompt (both from Madaan et al.), Self-StreamICL already provides consistent gains (e.g., +4.73 on Spider, +15.46 on DDXPlus over GrowPrompt), and MAM-StreamICL extends these leads further (e.g., +5.79 on Spider, +28.40 on DDXPlus over GrowPrompt). The key finding is that storing only correct self-outputs (Self-StreamICL) and sharing memory across multiple agents (MAM-StreamICL) are both critical: ablations confirm that using incorrect outputs degrades performance below zero-shot, and single-agent memory underperforms multi-agent shared memory by up to 17.48 points on DDXPlus.

## Relation to Prior Work

This paper builds directly on MemPrompt/GrowPrompt (Madaan et al., EMNLP 2022), which demonstrated that memory-augmented prompting can improve GPT-3 post-deployment by storing and retrieving past feedback. It also situates itself relative to Reflexion (self-reflection over repeated trials) and ExpeL (cross-task experiential learning), which showed LLM agents can self-improve but were evaluated in non-standardized, task-specific settings. The key departure is formalizing a unified streaming evaluation protocol—where an agent processes a sequential input-feedback stream and must maximize aggregate accuracy—rather than evaluating per-instance or repeated-trial improvement. The proposed Self-StreamICL and MAM-StreamICL methods extend the memory-augmented ICL paradigm by filtering to correct outputs only and introducing cost-effective multi-agent memory sharing via round-robin scheduling.

## Why It Matters / Open Questions

StreamBench fills a genuine gap in the LLM evaluation landscape: prior benchmarks (MMLU, GSM8K, BIG-Bench-Hard) measure innate capabilities, while post-deployment continuous improvement—critical for real-world deployment—had no standardized testbed. The finding that storing only correct self-outputs outperforms storing all outputs with verbalized correctness labels provides a simple, actionable design principle for streaming LLM systems. Open questions include whether richer feedback signals (natural language, partial correctness) yield further gains, how methods behave under distributional shifts in production, and whether multi-agent scheduling can be formalized as a multi-armed bandit problem. Limitations include binary-only feedback, text-only modality, and a sim-to-real gap between simulated correctness signals and noisy real-world user feedback.
