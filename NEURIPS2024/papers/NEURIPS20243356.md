## Problem

LLMs struggle with formal theorem proving in Lean due to a severe data sparsity problem: MiniF2F contains only a limited number of human-formalized contest problems, and Mathlib focuses on foundational theorems rather than Olympiad-level questions. There is no large-scale, high-quality dataset of formalized contest-level math statements that could serve as training data for autoformalization and automatic theorem proving.
![Teaser figure](../imgs/NEURIPS20243356/cropped_page1_idx0.webp)

## Input / Output

The pipeline consumes natural language math problems scraped from the Art of Problem Solving (AOPS) forum (middle-school through Olympiad difficulty) and produces Lean 4 theorem statements with 'sorry' placeholders for proofs. Problems are pre-filtered by topic tags (inequality, number theory, trigonometry, modular arithmetic, etc.) and a well-definedness check before translation. The final output is a dataset of ~57K formal-informal question pairs (plus 83K in Lean Workbook Plus), where each entry includes the natural language statement, gold answer, formal statement, and optionally a formal proof. The pipeline also produces 21 new formalized IMO problems not previously in Compfiles.

## Method

The core contribution is a six-round iterative active learning pipeline that alternates between model-based translation and multi-stage filtering. Starting from a translation model fine-tuned on MiniF2F + ProofNet data (initialized from InternLM-Math-Plus-20B), the model translates AOPS problems into Lean 4, and each candidate is filtered by: (1) Lean 4 compilation via a custom REPL for fast verification, (2) back-translation to natural language followed by an NLI equivalence check using Qwen-1.5-14B-Chat, and (3) human expert diagnostic on failures. Each round adds ~30 human-corrected samples targeting identified error patterns (type confusion, continued inequalities, integer division semantics, min/max existence), and the model is re-fine-tuned. After six rounds, the correct translation rate on NLI-passing samples reaches ~95%, yielding 57K verified pairs with 93.5% sampled accuracy.

## Results

The Lean Workbook dataset contains 57,231 formal-informal question pairs (Lean Workbook) and 82,893 (Lean Workbook Plus), with a manually verified accuracy of 93.5% on a sampled subset. On MiniF2F, fine-tuning InternLM2-Math-Plus with Lean Workbook improves accuracy from 44.3% to 50.4% on the valid set and from 37.3% to 46.7% on the test set. The iterative active-learning pipeline increases the NLI pass number from 37,122 (first round) to 57,231 (final round) and further to 82,893 when the final model is fine-tuned on the Lean Workbook dataset itself. The dataset is significantly harder than MiniF2F for theorem proving, with a Pass@1024 of only 8.6% (4,898 out of 57,231 problems solved).

## Baselines & Comparisons

The paper does not benchmark against a specific competing autoformalization method in a head-to-head table, but provides two key comparisons. First, the iterative active-learning pipeline is shown to substantially outperform the first-round model: the NLI pass number increases from 37,122 to 57,231 (a 54% gain), and the compile pass number rises from 136,670 to 205,079. Second, on the downstream MiniF2F autoformalization task, adding Lean Workbook to the training data yields a +6.1 point improvement on the valid set (44.3% → 50.4%) and a +9.4 point improvement on the test set (37.3% → 46.7%) over the Mathlib-only baseline. The authors note that a concurrent work, DeepSeek-Prover, also translates large-scale Lean problems from high-school sources, but Lean Workbook differentiates itself through active learning with human-in-the-loop correction and a reported 93.5% manual accuracy, whereas DeepSeek-Prover does not report a comparable per-sample accuracy figure.

## Relation to Prior Work

This paper extends the autoformalization line of work initiated by Wu et al. (2022) and Azerbayev et al. (ProofNet, 2023), which translated natural language math statements into formal languages using in-context learning or fine-tuned LLMs. Unlike DeepSeek-Prover (Xin et al., 2024), a concurrent effort that generates large-scale synthetic Lean data, this paper introduces an active learning loop where human experts iteratively diagnose and correct model failures, combined with Lean 4 compilation checking and NLI-based back-translation verification as automated filters. The pipeline is initialized on MiniF2F and ProofNet but deliberately targets the underexplored contest-level problem space sourced from the AOPS forum, filling a gap between grade-school autoformalization and the fundamental-theorem focus of Mathlib.

## Why It Matters / Open Questions

The 57K formal-informal pair dataset directly addresses the data sparsity bottleneck that limits LLM-based theorem proving, and the 21 newly formalized IMO problems expand the Compfiles benchmark. The active learning pipeline—requiring only ~341 human-labeled corrections across six rounds to reach 95%+ accuracy—is a reusable recipe for scaling autoformalization to new problem domains. However, the dataset is limited to contest-level problems, contains some near-duplicates that resist deduplication, and the 8.6% Pass@1024 on the Lean Workbook (vs. MiniF2F) suggests that formalizing statements is far easier than proving them, leaving the core theorem-proving challenge largely open.
