## Problem

Prior work showed that with O(vc(F)) public unlabeled samples, every concept class becomes statistically learnable under differential privacy with only O(vc(F)) private labeled samples, matching non-private rates. However, all such algorithms are computationally intractable because they require explicitly constructing an exponential cover of the function class. This paper asks whether this computational overhead is truly necessary when the function class admits efficient non-private learning, and provides the first oracle-efficient private learners that leverage public data.

## Input / Output

The algorithms consume n private labeled examples (X_i, Y_i) from a joint distribution ν, m public unlabeled examples Z_i from a reference distribution μ, and an ERM oracle that solves empirical risk minimization over the function class F. The public and private marginals need only satisfy a bounded density-ratio (σ-smoothness) condition for learning guarantees, while privacy holds unconditionally. The output is a predictor f̂ ∈ F that is (ε,δ)-differentially private with respect to the private dataset and achieves (α,β)-learning accuracy; for binary classification (Algorithm 4), the output is ε-purely differentially private with only two ERM oracle calls.

## Method

The core template has two steps: (i) construct a stable initial estimate f̄ via ERM on a perturbed or regularized objective over public data, and (ii) apply an output perturbation (Algorithm 1) that minimizes ‖f − f̄ − γζ‖²_m over F to boost stability into differential privacy. For general bounded classes (Algorithm 2), stability is achieved by averaging J independent FTPL-style Gaussian-perturbed ERM solutions, relying on an improved Gaussian anti-concentration bound; for convex classes (Algorithm 3), a single FTRL-style strongly convex regularizer ‖·‖²_m yields tighter stability and better sample complexity. For binary classification (Algorithm 4), a fundamentally different approach perturbs the ERM objective with Laplace or Gaussian noise on randomly labeled public points, then projects the result onto the public data—eliminating the second perturbation entirely and achieving O(d²ε⁻¹α⁻⁵) sample complexity with pure DP.

## Results

The paper provides three oracle-efficient differentially private learning algorithms with progressively improved sample complexity. For general bounded function classes (Algorithm 2), the private sample complexity is poly(sup_m G̅_m(F), log(1/δ), log(1/β), λ) · ε^{-3} · α^{-14}. For convex function classes (Algorithm 3), this improves to poly(log(β^{-1}), log(δ^{-1}), λ) · (sup_m G̅_m(F))² · ε^{-1} · α^{-5}, with a pure DP variant at ε^{-1} · α^{-6}. For binary classification (Algorithm 4), the sample complexity is Õ(d² ε^{-1} α^{-5} log(β^{-1})) for pure DP and Õ(d² ε^{-1} α^{-4} log^{1/2}(1/δ) log(β^{-1})) for (ε,δ)-DP, where d = vc(F). All algorithms require only 2 ERM oracle calls and polynomially many public unlabeled samples.

## Baselines & Comparisons

The paper's main comparison is against prior semi-private learning results that achieve optimal statistical rates but are computationally intractable. Bassily et al. (2019) achieve O(vc(F) · α^{-2} · ε^{-2}) sample complexity using the exponential mechanism over an explicit cover, but require exponentially many oracle calls to construct the cover; this paper's Algorithm 4 achieves Õ(d² · ε^{-1} · α^{-5}) with only 2 oracle calls, trading a polynomial factor in α and d for computational tractability. Against Neel et al. (2019), which gives oracle-efficient private binary classification but requires the function class to have a small universal identification set and makes polynomially many oracle calls in ε and α^{-1}, this paper's Algorithm 4 removes the identification set requirement (working for any VC class) and uses only 2 oracle calls, at the cost of a d² vs. d dependence. For convex classes, Algorithm 3's ε^{-1} · α^{-5} rate is a significant improvement over Algorithm 2's ε^{-3} · α^{-14} rate, though both remain far from the O(α^{-2}) non-private rate. The paper explicitly acknowledges that none of its oracle-efficient algorithms match the O(vc(F) · α^{-2} · ε^{-2}) rate of the statistically optimal but computationally infeasible algorithms, leaving the gap between oracle-efficient and statistically optimal private learning as an open question.

## Relation to Prior Work

This paper bridges semi-private differential privacy learning (Balcan & Feldman 2013; Beimel et al. 2014; Bassily et al. 2019, 2020b) with oracle-efficient online learning (Kalai & Vempala 2005; Block et al. 2022). Prior semi-private learning results achieved optimal statistical rates but required explicitly constructing exponential-size covers of the hypothesis class, making them computationally intractable. The authors adapt Follow-the-Perturbed-Leader (Algorithm 2) and Follow-the-Regularized-Leader (Algorithm 3) techniques from smoothed online learning to obtain the first oracle-efficient semi-private learners, while Algorithm 4 for binary classification extends Neel et al. (2019) by removing the restrictive small-separator-set assumption in favor of a small public unlabeled dataset. The improved Gaussian anti-concentration bound (Proposition 1) refines a key technical lemma from Block et al. (2022).

## Why It Matters / Open Questions

This work establishes that computational intractability in semi-private DP learning is not inherent but arises from the explicit-cover construction, and can be circumvented whenever non-private ERM is tractable. However, the sample complexities remain far from optimal (e.g., O(vc·ε^{-3}·α^{-14}) for the general algorithm versus O(vc·α^{-2}) achievable by non-private ERM or O(vc·α^{-2}·ε^{-2}) by inefficient private algorithms), leaving a significant gap that the authors explicitly flag as open. The σ-smoothness assumption (bounded density ratio between public and private marginals) is a mild generalization of the standard semi-private model, and the observation that more public data increases privacy loss through finer implicit discretization is a useful design insight. The oracle-efficiency framework also makes the results robust to imperfect optimization via the Neel et al. (2019) robustification procedure.
