## Problem

Despite strong performance on general visual tasks, MLLMs remain surprisingly poor at understanding webpage screenshots and generating the corresponding HTML code. Existing webpage-to-code datasets (e.g., WebSight, Pix2Code) lack instruction-format annotations needed for MLLM integration, and prior benchmarks evaluate OCR, spatial reasoning, and code generation in isolation rather than as a combined webpage parsing and translation task.
![Teaser figure](../imgs/NEURIPS20243559/cropped_page1_idx0.webp)

## Input / Output

The model takes a rendered webpage screenshot (336×336 pixels via CLIP ViT-L/14) paired with a natural-language instruction as input. For code generation, the output is a full HTML document; for webpage understanding, the output is structured question-answer pairs probing layout, color, text content, and UI elements. The evaluation framework (WCGB) renders predicted HTML back into a screenshot via Selenium WebDriver and scores it against the ground-truth image using GPT-4V across 10 visual criteria grouped into four categories (structure/alignment, color/aesthetics, text/content, UI/interactivity), each on a 0–10 scale.

## Method

Web2Code constructs a 1.18M-pair instruction dataset from four components: DWCG (60K GPT-3.5-generated HTML pages rendered to images), DWCG_R (824.7K refined WebSight and Pix2Code samples with GPT-4 text replacement), DWU (243.5K GPT-4-generated QA pairs from HTML code), and DWU_R (51.5K quality-filtered WebSRC QA pairs). Training follows the LLaVA-1.5 two-stage protocol—projector pretraining on captions, then joint projector+LLM instruction tuning—using CLIP ViT-L/14 as the visual encoder and pluggable LLM backbones (LLaMA-3-8B, CrystalChat-7B, CrystalCoder-7B, Vicuna-1.5-7B). The key design insight is that code-generation data (DWCG/DWCG_R) and webpage-understanding data (DWU/DWU_R) contribute orthogonally: code data boosts WCGB while understanding data recovers and enhances WUB accuracy, and their combination improves both without degrading general-domain benchmarks (MME, POPE, TextVQA, ScienceQA). For evaluation, the paper introduces WUB (offline yes/no QA accuracy over 5,990 GPT-4V-generated pairs) and WCGB (online GPT-4V image-level scoring), arguing that traditional text-similarity metrics are insufficient for assessing rendered webpage fidelity.

## Results

On the Webpage Code Generation Benchmark (WCGB), LLaMA3-8B trained with the full Web2Code dataset (DWCG + DWU + DWCG_R + DWU_R) achieves an overall score of 8.530/10, up from 1.790 with only general LLaVA instruction data. On the Webpage Understanding Benchmark (WUB), the same configuration reaches 74.84% accuracy versus 65.56% without Web2Code. Across all tested LLM backbones (LLaMA3-8B, CrystalChat-7B, CrystalCoder-7B, Vicuna1.5-7B), adding Web2Code data yields substantial gains on both benchmarks while preserving or improving general-domain performance (MME, POPE, ScienceQA, TextVQA).

## Baselines & Comparisons

The primary external baseline is WebSight (v0.1, 823K samples; v0.2, refined). On LLaMA3-8B, Web2Code achieves 8.530 overall WCGB and 74.84% WUB accuracy, substantially outperforming WebSight v0.1 (4.125 WCGB, 70.13% WUB) and WebSight v0.2 (5.115 WCGB, 57.33% WUB). On CrystalChat-7B, the 60K-sample DWCG alone (7.990 WCGB) already surpasses the 823K-sample WebSight v0.1 (7.701 WCGB), and adding DWU further improves to 8.126 WCGB with 73.74% WUB versus WebSight v0.1's 59.38% WUB. In the general domain, Web2Code preserves or improves performance (e.g., LLaMA3-8B: 1464.73 MME-P, 72.08 SciQA, 58.76 TextVQA) while WebSight v0.1 degrades TextVQA to 23.38 and WebSight v0.2 to 20.51, indicating that existing code-generation datasets harm general visual-language capabilities. The paper also compares against the no-Web2Code baseline (LLaVA-only instruction tuning), showing that even a single component (DWCG) lifts WCGB from ~1.8–4.8 to ~6.4–8.0 depending on backbone.

## Relation to Prior Work

This paper extends the LLaVA instruction-tuning paradigm to the webpage-to-code domain, building on prior screenshot-to-HTML datasets (Pix2Code, WebSight, WebSRC) by converting them into instruction-following format and augmenting them with GPT-3.5/4-generated webpages and QA pairs. It departs from prior code-generation evaluation, which relies on text-similarity or element-matching metrics (as in Design2Code), by proposing a rendered-image comparison evaluated by GPT-4V. The instruction-generation pipeline draws on CodeAlpaca prompting, while the overall MLLM architecture follows the CLIP-encoder + projector + LLM recipe established by LLaVA-1.5.

## Why It Matters / Open Questions

Web2Code provides the first large-scale (1.18M) instruction-tuning dataset and paired evaluation suite (WUB + WCGB) specifically targeting webpage understanding and HTML generation within the MLLM framework, filling a gap where prior datasets lacked instruction structure and benchmarks evaluated capabilities in isolation. The finding that 60K synthetic webpages outperform 823K real-world WebSight data, and that webpage-specific training improves rather than degrades general visual benchmarks, suggests data quality and task alignment matter more than raw scale for domain adaptation. Open questions include whether the GPT-4V-based evaluation is sufficiently reliable and unbiased, whether the approach generalizes to complex multi-page or interactive web applications, and how to handle the residual privacy risks in scraped web content.
