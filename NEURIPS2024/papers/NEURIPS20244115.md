## Problem

Existing tree-based speculative decoding methods suffer from two key limitations: (1) handcrafted tree topologies (e.g., k independent sequences) asymptote in the expected number of accepted tokens regardless of tree size, making them sub-optimal for large speculation budgets; and (2) sampling/verification algorithms like SpecInfer and SpecTr perform poorly at low temperatures because they can repeatedly sample and reject the same high-confidence-but-incorrect token from the draft model. The paper asks how to design a tree-based speculative decoding method that is both scalable (gains continue with larger trees) and robust (performs well across all decoding temperatures).

## Input / Output

The method takes a text prompt, a small draft model (e.g., Llama-68M, Llama2-7B-chat, Llama3-8B-Instruct), and a large target model (e.g., Llama2-7B/13B, Vicuna-33B, Llama2-70B-chat, Llama3-70B-Instruct) as inputs, and produces generated text tokens with the exact same output distribution as the target model (lossless). The tree structure is pre-computed offline via dynamic programming using an empirically measured acceptance rate vector (from 200 calibration examples), and the optimal tree size and depth are selected by a hardware-aware optimizer that accounts for the target model's verification time per token and the draft model's speculation time per token on the specific GPU.

## Method

SEQUOIA has two core components. First, it formulates tree construction as a constrained optimization problem: maximize the expected number of generated tokens F(T) = Σ_v f(v) (where f(v) is the product of positional acceptance probabilities along the root-to-v path) subject to a tree size budget N. A dynamic programming algorithm fills a 2D tensor T[n,b] to find the optimal tree topology, and the paper proves that under a b-power-law acceptance rate assumption, the expected tokens scale as Ω(b·log(n)/log(log(n)))—unbounded—whereas k independent sequences are upper-bounded. Second, it modifies SpecInfer's verification by performing sampling without replacement from the draft model (zeroing out rejected tokens' draft probabilities) and falling back to a uniform distribution over non-rejected tokens when the draft support is exhausted. This change ensures the algorithm satisfies both the optimal transport property (strong at high temperatures) and the cover property (strong at low temperatures), making it the first verification algorithm to be robust across all temperature settings while preserving the target model's exact output distribution.

## Results

SEQUOIA achieves up to 4.04× speedup for Llama2-7B (with JF68M draft) on a single A100 GPU, reducing time-between-tokens to 6.0 ms/token (vs. 24.2 ms/token for incremental decoding). In the offloading setting on an L40 GPU, SEQUOIA accelerates Llama3-70B-Instruct by 9.5×, reducing per-token latency to 0.60 s/token compared to 5.7 s/token for DeepSpeed-Zero-Inference. Across Llama2-13B and Vicuna-33B, SEQUOIA attains up to 3.73× and 2.27× speedups respectively. The average number of generated tokens per decoding step ranges from 3.06 to 11.68 depending on model size, tree configuration, and temperature.

## Baselines & Comparisons

Against SpecInfer (5×8 tree), SEQUOIA consistently wins across all model pairs, temperatures, and datasets, with a relative speedup advantage ranging from 1.05× (greedy MT Bench) to 1.34× (stochastic CNN Daily). The gap widens at lower temperatures where SpecInfer's with-replacement sampling repeatedly proposes the same incorrect token. Against SpecTr, SEQUOIA's sampling-without-replacement verification achieves strictly lower rejection rates across all temperatures (0.2, 0.6, 1.0) and all numbers of speculated tokens, as shown in Figure 3; SpecTr and SpecInfer both struggle at low temperatures while top-k sampling struggles at high temperatures. In the offloading setting, SEQUOIA (0.60 s/token for Llama3-70B-Instruct on L40) is 9.5× faster than DeepSpeed-Zero-Inference (5.7 s/token), and also outperforms SpecInfer's 16×48 tree configuration by 1.36×–1.62× in the same setting. The ablation in Figure 4 (right) further confirms that SEQUOIA's verification algorithm alone provides up to 1.65× speedup over SpecInfer and 1.27× over top-k sampling when the tree structure is held fixed.

## Relation to Prior Work

SEQUOIA builds directly on the SpecInfer token-tree verification framework and the original speculative decoding algorithm of Leviathan et al., extending both in principled ways. It departs from prior tree-construction approaches (k independent sequences in SpecInfer, full k-ary trees in Medusa) by formulating topology selection as a constrained optimization problem solvable via dynamic programming, and from prior sampling/verification methods (SpecInfer, SpecTr) by introducing sampling without replacement from the draft model. The paper also positions itself against self-speculation methods (Eagle, GLIDE) by showing the DP framework can be extended to depth-dependent acceptance rates, making it compatible with those approaches.

## Why It Matters / Open Questions

The 9.5× speedup for Llama3-70B offloading on a single L40 (0.60 s/token vs. 5.7 s/token for DeepSpeed-Zero-Inference) is practically significant for serving large models on consumer or edge hardware where memory bandwidth is the bottleneck. The theoretical result that SEQUOIA trees scale logarithmically with tree size—while all prior handcrafted topologies asymptote—provides a clear path to further speedups by simply increasing the speculation budget. Key limitations include the need to measure the acceptance rate vector per model pair, temperature, and domain to compute the optimal tree, and the positional acceptance assumption that underpins the DP optimality guarantee. Open questions include whether a single precomputed tree generalizes well across diverse deployment settings and how the method interacts with batching and continuous decoding.
