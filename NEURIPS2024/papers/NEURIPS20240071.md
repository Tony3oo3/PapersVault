## Problem

Previous Code LLMs are typically fine-tuned on single-source instruction data with limited quality and diversity, which fails to fully elicit the code capabilities of pre-trained base models. While multi-source data integration is a natural remedy, naively mixing data from different developers and LLMs introduces inherent conflicts in coding language, response style, and quality, leading to misaligned instruction-response pairs and inferior performance. This paper pioneers a principled approach to integrating multi-source code corpora for fine-tuning.

## Input / Output

The fine-tuning pipeline consumes ~200M tokens of multi-source instruction-response pairs (programming tasks with code solutions) and produces three AlchemistCoder model variants (7B/6.7B) that generate code, code explanations, code reviews with 0–10 correctness and clarity scores, and four-way data quality classifications. A distinguishing detail is that AlchemistPrompts are short (<50 word) data-specific augmentations prepended to instructions, specifying the target programming language, algorithmic concept, or response format to match the paired response. The code comprehension sub-tasks additionally take a code snippet plus a task description and output a structured review or a single-letter category label.

## Method

The core mechanism is AlchemistPrompts: GPT-4 is prompted to retrospectively inspect each instruction-response pair and generate a concise, data-specific prompt that explicitly encodes the response's programming language, algorithm, and stylistic choices, thereby harmonizing cross-source style conflicts and tightening within-pair alignment. Data selection for prompt customization is guided by Conditional Perplexity Discrepancy (CPD = PPL(instruction+response) − PPL(response)); only the top ~5% of samples by CPD receive AlchemistPrompt augmentation, balancing diversity against domain gap. Beyond conventional problem-solution pairs, the authors introduce three code comprehension tasks derived from the data construction pipeline itself—instruction evolution (augmenting task complexity), data filtering (classifying low-quality samples into four error categories), and code review (scoring correctness/clarity and producing refined code)—which collectively account for only 8% of the training corpus. The final harmonized dataset is used for supervised fine-tuning (2 epochs, Adam, lr 1e-4, seq length 8192) on Llama-2-7B, CodeLlama-Python-7B, and DeepSeek-Coder-Base-6.7B, yielding the AlchemistCoder series that outperforms all same-size Code LLMs on HumanEval, MBPP, HumanEval-X, and DS-1000 while also improving general benchmarks (MMLU, BBH, GSM8K).

## Results

On HumanEval (pass@1), AlchemistCoder-DS (6.7B) achieves 79.9% and AlchemistCoder-CL (7B) achieves 74.4%, representing improvements of 33.3% and 96.8% over their respective base models (DeepSeek-Coder-Base and CodeLlama-Python). On MBPP (pass@1), AlchemistCoder-DS reaches 77.0% and AlchemistCoder-CL reaches 68.5%. On the stricter HumanEval+ variant, AlchemistCoder-DS scores 75.6% and AlchemistCoder-CL scores 68.3%, both leading all open-source models of equivalent size (6.7B/7B).

## Baselines & Comparisons

AlchemistCoder-DS (6.7B) outperforms all same-size competitors: MagicoderS-DS (76.8→79.9 on HumanEval, +3.1), DeepSeek-Coder-Instruct 6.7B (73.8→79.9, +6.1), and MagicoderS-CL 7B (70.7→79.9, +9.2). AlchemistCoder-CL (7B) surpasses WizardCoder-CL 7B by a large margin (48.2→74.4 on HumanEval, +26.2) and MagicoderS-CL 7B by 3.7 points (70.7→74.4). Notably, AlchemistCoder-DS (6.7B) exceeds the larger DeepSeek-Coder-Instruct 33B (78.7) and WizardCoder-CL 34B (73.2) on HumanEval, and rivals GPT-3.5-Turbo (72.6) by 7.3 points. On MBPP, AlchemistCoder-DS (77.0) trails GPT-3.5-Turbo (81.7) by 4.7 points but leads all open-source models of any size. On general benchmarks (MMLU, BBH, GSM8K), AlchemistCoder models improve over their base models by 6.4–14.5% on average, demonstrating that multi-source harmonization also mitigates catastrophic forgetting of general capabilities.

## Relation to Prior Work

This paper extends the instruction-tuning paradigm for Code LLMs (WizardCoder, Magicoder, DeepSeek-Coder) by pioneering multi-source data integration, departing from the single-source fine-tuning approach that dominates prior work. The core methodological novelty—AlchemistPrompts—adapts the hindsight relabeling concept from Hindsight Experience Replay (HER) in reinforcement learning to harmonize stylistic and quality conflicts across heterogeneous code corpora, a repurposing that has no direct precedent in the code LLM literature. The code comprehension tasks (instruction evolution, data filtering, code review) further extend the Evol-Instruct lineage by incorporating the data construction pipeline itself as training signal, going beyond the problem-solution pairs used by WizardCoder and Magicoder.

## Why It Matters / Open Questions

The finding that naive multi-source mixing actively degrades performance, and that a mere 5% targeted AlchemistPrompt intervention resolves the conflict, provides a practical and cost-effective recipe for practitioners integrating diverse code datasets. The observation that harmonized code fine-tuning simultaneously improves general capabilities (MMLU, BBH, GSM8K) without catastrophic forgetting is valuable for teams building domain-specialized models. Key limitations include the dependence on GPT-4 for AlchemistPrompt generation (though limited to short outputs on 5% of data) and the lack of exploration into data bias. An open question is whether open-source models can be fine-tuned to generate AlchemistPrompts autonomously, removing the GPT-4 bottleneck entirely.
