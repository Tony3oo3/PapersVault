## Problem

Learned rigid-body simulators based on graph neural networks rely on 3D meshes to represent object shapes, causing collision edges to grow quadratically with the number of surface nodes. This makes them infeasible for scenes with hundreds of objects or detailed meshes, where memory and runtime explode. The paper asks whether implicit shape representations can eliminate this bottleneck and unlock learned simulation at scale.

## Input / Output

The simulator takes a graph whose nodes are surface points (sampled from object meshes or SDF-projected) and per-object center nodes, with features encoding 3-step position history, finite-difference velocities, and constant physical parameters (mass, friction, restitution). At each step, the pre-trained per-object SDF MLPs are queried to compute inter-object distances and closest points, which determine which collision edges to create. The output is a per-node acceleration estimate, converted to next-step rigid body transformations (position and rotation) via shape matching.

## Method

SDF-Sim replaces mesh-based collision detection with learned SDFs: for each surface node on object i, it queries the SDF of object j in a single forward+backward pass to obtain the distance and closest point, creating an edge from that node to object j's center node only if the distance is below a threshold. This node-to-object-node edge design reduces the worst-case edge count from O(K²) (mesh-based) to O(I·K), where I is the number of objects and K is total surface nodes. The GNN simulator uses 10 message-passing steps with 2-layer MLPs (128 units, LayerNorm) and is trained with a per-node L2 loss on single-step acceleration prediction. SDFs are pre-trained as 8-layer MLPs (128 units) on BVH-computed ground-truth distances and remain frozen during simulation. The key architectural insight is that a single collision edge can test a node against an entire object surface via the SDF, eliminating the need for pairwise node-to-node or triangle-to-triangle connections.

## Results

On Movi-C, SDF-Sim uses 33% fewer graph edges, 42.8% less peak memory (43.35 MiB vs 75.87 MiB), and 43% lower runtime per step (0.17 ms vs 0.30 ms) compared to FIGNet*, while achieving a translation RMSE of 0.24 m (4.9% of the average 4.92 m object travel distance). On the Spheres-in-Bowl scaling benchmark, SDF-Sim simulates 512 interacting objects (over 50× more than training) on a single V100 GPU, whereas FIGNet* runs out of memory beyond ~160 objects. On these large scenes, SDF-Sim also achieves lower rollout RMSE and penetration distance than FIGNet*, despite slightly higher error on small-scale Movi-B/C benchmarks.

## Baselines & Comparisons

Against FIGNet* [19], the primary baseline, SDF-Sim trades a small accuracy gap on small scenes (0.24 m vs 0.18 m translation RMSE on Movi-C; 0.16 m vs 0.13 m on Movi-B) for dramatic efficiency gains: 33% fewer collision edges, 42.8% less peak memory, and 43% lower per-step runtime. On the Spheres-in-Bowl scaling test, FIGNet* OOMs beyond ~160 spheres while SDF-Sim handles all 512, and SDF-Sim actually achieves lower rollout RMSE and penetration distance on these large scenes. FIGNet [4] (the original face-interaction GNN) OOMs on Movi-C entirely and on Spheres-in-Bowl beyond ~140 objects. MGN, MGN-LargeRadius [29], and DPI [18] all OOM on Movi-C and are only comparable on Movi-B, where SDF-Sim substantially outperforms them in accuracy (0.16 m vs 0.37–0.54 m translation RMSE). Compared to the analytical Bullet simulator [13], SDF-Sim matches runtime up to ~30 objects and produces lower penetration distances, though Bullet remains faster at scale due to its hand-optimized C++ implementation.

## Relation to Prior Work

This paper extends the GNN-based learned simulator lineage (MeshGraphNets → FIGNet → FIGNet*) by replacing mesh-based face-to-face collision edges with SDF-based node-to-object edges, reducing inter-object edge complexity from quadratic to linear. The SDF representation draws on the learned implicit shape literature (DeepSDF, VolSDF) for shape encoding, but repurposes it for a fundamentally different goal: accelerating collision detection in a differentiable GNN simulator rather than 3D reconstruction. The graph architecture (message passing, shape matching for rigid transforms, per-node acceleration prediction) is inherited directly from FIGNet/FIGNet*, with the key departure being the input graph construction that leverages constant-time SDF queries instead of pairwise mesh distance computation.

## Why It Matters / Open Questions

This is the first demonstration that learned rigid-body simulators can scale to scenes with hundreds of objects and over 1 million nodes, a regime where all prior mesh-based learned simulators run out of memory. The vision-to-simulation pipeline (extracting SDFs from multi-view images via VolSDF and directly simulating them) opens a practical path toward simulating real-world scenes captured on a phone without manual mesh creation. Key limitations include the need to train a separate SDF MLP per new shape, a slight accuracy trade-off on small scenes compared to FIGNet*, and restriction to rigid-rigid interactions. Open questions include amortized SDF training across shapes, extension to deformable/articulated objects, and whether the SDF-based graph construction can be combined with other representation types (particles, fluids) in mixed simulations.
