## Problem

Machine learning for binary analysis has been hampered by a severe data availability crisis: high-quality corpora of benign Windows PE binaries are nearly absent from public research, forcing most models to train on limited Linux ELF utilities (coreutils, binutils) or expensive commercial datasets. This creates a critical cross-platform gap, as Windows accounts for ~70% of OS market share and the majority of malware, yet models trained on Linux binaries do not generalize to the Windows domain.

## Input / Output

ASSEMBLAGE ingests GitHub source repositories (filtered for Visual Studio solution files or Makefiles) along with compiler configurations spanning MSVC 2015–2022, GCC, and Clang at multiple optimization levels and CPU architectures. It outputs 890k Windows PE (.exe/.dll) and 428k Linux ELF binaries with accompanying PDB debug symbol files, plus a SQLite database with four tables (binaries, functions, rvas, lines) that encode source-to-binary byte-level mappings, function names, and relative virtual addresses. The dataset is distributed as 'recipes'—lists of repositories and build settings—so that mixed-license repositories do not render the binary distribution unlicensable.

## Method

ASSEMBLAGE is a distributed cloud system (deployed on AWS) with three stages: a GitHub API crawler that discovers and clones repositories, a parallel build pipeline that compiles with multiple toolchains (MSVC via automation scripts bypassing GUI dependencies on Windows; Docker-isolated GCC/Clang workers on Linux), and a metadata extraction step that parses PDB files to record function addresses, source-line-to-byte mappings, and compiler configuration into a structured SQLite database. The key design insight is that by compiling the same source under 29 different toolchain/optimization/architecture combinations, the system automatically generates ground-truth positive pairs for function similarity and labeled examples for compiler provenance without manual annotation. The paper validates the dataset through three case studies—PassTell (LightGBM) for compiler provenance, a GNN and jTrans (BERT-based transformer) for function similarity, and XDA/IDA for function boundary identification—demonstrating that prior models trained on small Linux corpora degrade substantially on the more diverse ASSEMBLAGE Windows data.

## Results

ASSEMBLAGE produces 1,536,171 binaries (890k Windows PE + 428k Linux ELF) across 220,792 projects and 783,694 functions, with 29 build configurations spanning GCC, Clang, and MSVC toolchains. Benchmarking existing methods on this data reveals significant cross-platform gaps: PassTell (LightGBM) drops to ~58% accuracy on Windows PEs alone, the GNN for function similarity achieves AUC 0.50–0.82 on Windows/Linux cross-domain tasks versus 0.80–0.99 on Linux/Linux, and jTrans (BERT) reaches only MRR 0.52 on Windows versus 0.83 on Linux. For function boundary identification, XDA achieves F-1 of 0.75 on wild Windows PE code, while IDA Pro (even with PDBs) reaches only 0.79, indicating substantial room for improvement.

## Baselines & Comparisons

ASSEMBLAGE is the only dataset supporting both Linux and Windows binaries, all three major toolchains (GCC, Clang, MSVC), and all five downstream tasks (malware detection, compiler provenance, function similarity, function name recovery, decompilation) simultaneously. It surpasses the next-largest dataset (BinBench, 1.1M binaries) in total binary count and exceeds it by 4.5× in function count (783K vs. 4.4K) and 10× in project count (220K vs. undisclosed). Compared to BinaryCorp-26M (48K Linux-only binaries used by jTrans and kTrans), ASSEMBLAGE provides 32× more binaries and adds Windows PE coverage entirely absent from prior work. The benchmark experiments demonstrate that methods trained on prior Linux-only datasets (PassTell, Marcelli's GNN, jTrans) fail to generalize to Windows PE: PassTell's accuracy drops from near-perfect on Linux to ~58% on Windows, the GNN's cross-platform AUC falls to 0.50–0.82, and jTrans's MRR drops from 0.83 (Linux) to 0.52 (Windows), confirming the practical need for the diverse Windows PE corpora ASSEMBLAGE provides.

## Relation to Prior Work

ASSEMBLAGE extends the general paradigm of crawling GitHub repositories and compiling them into binary corpora (pioneered by Linux-focused tools like DIRTY, XDA, and DIRE) to the Windows PE domain, where no comparable large-scale, reproducible pipeline existed. Prior datasets (SPECCPU2006, UbuntuDataset, BinKit, BinaryCorp-26M) are almost exclusively Linux ELF and rely on a narrow set of standard utilities, while Windows data in the literature is either proprietary (VirusTotal), pre-processed without source mappings, or limited to malware-only collections. The paper's empirical evaluation repurposes existing methods—PassTell (LightGBM), a GNN for function similarity, and jTrans (BERT-based transformer)—without architectural changes, using ASSEMBLAGE's data as the sole new ingredient to expose cross-platform generalization gaps.

## Why It Matters / Open Questions

The field's heavy reliance on Linux ELF binaries is misaligned with the reality that ~40% of malware samples and ~70% of desktop OS market share are Windows, yet nearly all recent ML-based binary analysis papers train and evaluate on Linux. ASSEMBLAGE's 890k Windows PE + 428k Linux ELF binaries with full source-to-byte mappings, PDB files, and 29 build configurations directly address this gap and enable reproducible, extensible experimentation. Open questions include improving cross-platform generalization (PassTell drops to ~58% and jTrans MRR from 0.83 to 0.52 on Windows), automating build success for the ~70% of Windows projects that fail to compile, and integrating malware scanning before the dataset is used in security-critical pipelines.
