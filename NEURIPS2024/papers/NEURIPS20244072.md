## Problem

Existing adversarial attacks on aligned language models either require full white-box access to model weights or rely on transferability from a local surrogate, both of which are impractical or ineffective for targeted attacks on production models. Transfer attacks in particular fail to elicit specific harmful strings and require a high-quality surrogate that may not exist (e.g., Vicuna transfers poorly to Claude at only 2% success rate). This paper asks whether a query-based black-box attack can directly construct adversarial prompts against a remote API model, achieving targeted harmful-string elicitation without any surrogate.

## Input / Output

The method takes a target harmful string (from the 574-string Harmful Strings dataset) and API access to the target model, optionally augmented by a local proxy model (e.g., Mistral 7B) for guiding the search. The adversarial prompt is a fixed-length token sequence (typically 20 tokens, extendable to 40 for longer targets) optimized so that the model generates the target string under greedy sampling. For content moderation evasion, the input is a harmful sentence and the output is a short suffix (5 or 20 tokens) appended to it that causes the moderation model to assign no violation flags. Loss is computed as negative cumulative logprob of the target string, reconstructed via logit-bias and top-5 logprobs since OpenAI removed direct prompt-token logprob access.

## Method

GCQ (Greedy Coordinate Query) modifies GCG by replacing its gradient-based candidate filter with a two-stage process: a local proxy model scores a large batch of random single-token substitutions (b_p candidates), and the top b_q are then evaluated against the true target model via API queries. The algorithm maintains a min-max heap buffer of the B best unexplored adversarial suffixes and performs best-first-search expansion, short-circuiting loss computation when a candidate already exceeds the worst buffer element. A key proxy-free variant eliminates the surrogate entirely by focusing each iteration on a single token position (selected by trying one replacement per position and keeping the best), reducing query count by ~2× while retaining attack success. Practical innovations include initializing the buffer by repeating the target string (solving 28% of targets immediately) and reconstructing logprobs through iterative logit-bias queries, at a cost of pt prompt tokens and t(t+1)/2 completion tokens per evaluation.

## Results

On GPT-3.5 Turbo, GCQ achieves 79.6% attack success rate for eliciting harmful strings at $0.10 per target, rising to 86.0% at $0.20 per target, with 97.9% success for target strings of 20 tokens or fewer. For content moderation evasion, the universal attack on OpenAI text-moderation-007 reaches 99.2% success rate (20-token suffix, 2,000 requests), and the nonuniversal attack reaches 91.4% (20-token suffix). The proxy-free variant outperforms the original white-box GCG by approximately 30% in query efficiency, while the optimized GCG variant requires roughly 2× fewer loss queries to reach the same success rate.

## Baselines & Comparisons

GCQ decisively outperforms GCG Pure Transfer [36] in every setting tested: where pure transfer achieves 0.000 success rate across all proxy-to-target pairs (including same-model 7B→7B, cross-scale 13B→7B, and cross-architecture 7B→Mistral/Gemma), GCQ achieves 0.388 (13B→7B) and 0.791 (7B→7B), demonstrating that query access is essential for targeted harmful string elicitation. Against AutoDAN [19], which was designed for jailbreaking rather than targeted string generation, GCQ achieves 0.791 versus AutoDAN GA's 0.002 and HGA's 0.000 on Vicuna 1.3 7B, despite AutoDAN using much longer adversarial suffixes (~70 tokens vs. 20). The paper also shows that the optimized GCG variant (focusing search on a single position) is approximately 2× more query-efficient than the original GCG, and the fully proxy-free query-only variant still outperforms the original white-box GCG by ~30% in query efficiency.

## Relation to Prior Work

GCQ is a direct modification of the Greedy Coordinate Gradient (GCG) attack of Zou et al., which itself extends AutoPrompt's token-sequence optimization framework. The key departure is replacing GCG's gradient-based candidate filtering with a two-stage process: a proxy-model loss for cheap pre-screening, followed by direct API queries to the target model for final evaluation. The paper also draws on the logit-bias logprob reconstruction technique from Morris et al. to compute the target loss under API constraints, and introduces a proxy-free variant that eliminates the local model entirely by focusing search on a single position per iteration.

## Why It Matters / Open Questions

The paper demonstrates that query-based attacks can elicit specific targeted harmful strings from production LLMs (79–86% ASR on GPT-3.5) where pure transfer attacks achieve 0%, and can evade OpenAI's content moderation with near-100% success—implying that defenses relying solely on breaking transferability are insufficient. Key limitations include the dependence on logprob access (which OpenAI has been progressively restricting), strong sensitivity to initialization (random init nearly fails), and API nondeterminism (~10% reproduction loss). Open questions include whether effective attacks are possible under stricter black-box settings without logprob access, and how to make the optimization less initialization-sensitive.
