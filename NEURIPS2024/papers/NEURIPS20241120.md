## Problem

Open-source LLMs such as StarCoder-15B and CodeLlama have severely limited self-debugging capability, refining only 4–12% of incorrect solutions via prompting, compared to ~29% for GPT-3.5-Turbo. The core challenge is the absence of scalable, high-quality training data for code explanation and refinement, since existing approaches either rely on non-scalable human annotation or prompting methods that fail to transfer to smaller models.

## Input / Output

At inference, the model receives a programming task description, an initial (incorrect) code solution, and execution feedback (error message or failed test case output) in a chat-format prompt, and produces a natural-language explanation of why the code is wrong followed by a corrected code solution. During training, two instruction variants are used: one requesting only the refined code and another requesting the explanation-then-refinement chain, both formatted in StarChat-style <|user|>/<|assistant|> turns. The wrong initial solution appears in the context but is excluded from the loss computation so the model does not learn to generate errors.

## Method

LEDEX is a three-stage training framework. First, an automated data-collection pipeline samples 20 solutions per problem from pre-trained LLMs, retains only those failing unit tests, then prompts a teacher model (GPT-3.5-Turbo, CodeLlama-34B, or the model itself) to generate an explanation plus refinement, keeping only pairs where the refinement passes all tests—yielding ~13.7k verified (explanation, refinement) pairs. Second, supervised fine-tuning on this data (two epochs, AdamW, lr 2e-5) teaches the model both instruction formats. Third, PPO-based reinforcement learning uses a novel split-reward design: the code refinement reward combines CodeBLEU similarity to ground-truth refinements with unit-test passing rate (scaled to [-5,5]), while the explanation reward uses average cosine similarity of RoBERTa sentence embeddings against ground-truth explanations (projected from [0.4,1.0] to [-5,5]). Crucially, the PPO algorithm assigns the explanation reward only at the token boundary where the explanation ends and the code reward only at the final token, so a correct explanation followed by a wrong refinement is not penalized as a whole, allowing the model to preserve good explanations while improving the code portion.

## Results

On the four benchmarks (MBPP, HumanEval, MBPP+, HumanEval+), LEDEX SFT improves pass@1 by up to 15.92% and pass@10 by up to 9.30% over direct prompting for StarCoder-15B (e.g., 54.71% vs. 38.79% pass@1 on MBPP+ & HumanEval+ with Expl.+Refine). RL on top of SFT adds up to 3.54% pass@1 and 2.55% pass@10 (e.g., CodeLlama-13B reaches 57.40% pass@1 on MBPP+ & HumanEval+). Success refinement rate jumps from 6.41–11.97% (prompting) to 17.50–23.50% (LEDEX RL) across the three backbones. On the harder MBPP+/HumanEval+ benchmarks, RL yields the largest gains (up to 6.80% pass@1 for CodeLlama-13B trained with CodeLlama-34B data).

## Baselines & Comparisons

The primary baseline is direct prompting (asking the LLM to refine or explain+refine without any training). LEDEX SFT outperforms prompting by 11.68–15.92% pass@1 and 3.72–9.30% pass@10 across all three backbones and four benchmarks. LEDEX RL further improves over SFT by up to 3.54% pass@1 and 2.55% pass@10, with the largest RL gains appearing on the harder MBPP+/HumanEval+ benchmarks (e.g., +6.80% pass@1 for CodeLlama-13B with CodeLlama-34B data). A secondary comparison (Table 11) shows that SFT on code-generation data alone yields comparable initial pass@k but only marginal refinement gains (~3% pass@1), whereas LEDEX's full data (explanation + refinement) produces ~9–11% pass@1 gains after refinement, confirming that the self-debugging ability comes specifically from the explanation/refinement training data. The paper also demonstrates generalizability: replacing GPT-3.5-Turbo with CodeLlama-34B for data collection still yields 7–10% pass@1 SFT gains, and self-bootstrapping with CodeLlama-7B itself still achieves up to 8.25% pass@1 improvement, though RL gains are smaller in the self-bootstrapped setting.

## Relation to Prior Work

This paper extends the self-debugging/self-refinement line of work initiated by Chen et al. (2023) and Olausson et al. (2023), which showed that prompting LLMs with execution feedback enables iterative code correction. Where prior work relied on prompting (limited for small open-source models) or human-annotated feedback (ILF, unscalable), LEDEX introduces an automated data collection pipeline that generates explanation-and-refinement trajectories from LLMs and filters them via execution verification. The training stage combines SFT with a modified PPO algorithm (building on Schulman et al., 2017) that assigns separate rewards to the explanation and code refinement portions, departing from prior RL-for-code work (CodeRL, RLTF) that used a single scalar reward. The chain-of-thought explanation-before-refinement formulation, while observed as a prompting trick in prior work, is here elevated to a training objective with its own reward signal.

## Why It Matters / Open Questions

The paper addresses a practical gap: open-source code LLMs (StarCoder-15B, CodeLlama-7B/13B) have dramatically weaker self-debugging ability than GPT-3.5 (4–11% vs. 28–33% refinement rate), limiting their utility in iterative development workflows. LEDEX demonstrates that this gap can be substantially closed through automated data collection and targeted training without human annotation, making self-debugging accessible to resource-constrained settings. Open questions include whether the approach generalizes to more complex multi-file debugging, whether the two prompt strategies explored are optimal, and whether the RL gains on harder benchmarks (MBPP+, HumanEval+) transfer to real-world codebases. The model-agnostic data collection (working with GPT-3.5, CodeLlama-34B, or self-bootstrapping) suggests the framework could be applied as new open-source code models emerge.
