## Problem

When LLMs are trained or served with model sharding and offloading to host DRAM or NVMe, the dominant cost is redundant I/O: canonical approaches load the full model from host memory for every mini-batch, and in distributed settings additionally perform per-batch parameter gathering and gradient reduce-scatter. This renders offloading theoretically sound but practically inefficient, with prior state-of-the-art methods achieving only ~36.5% model FLOPs utilization (MFU), far below full on-device training.

## Input / Output

The method consumes standard text token sequences (training batches or inference prompts) and sharded model parameters distributed across multiple GPUs, but internally re-batches the input along the batch dimension into sub-batches of configurable size. During training it produces updated model weights and per-step loss identical in precision to standard training; during inference it produces generated text tokens. A key constraint is that the total token capacity is bounded by available host DRAM (for offloaded activations/KV cache) and accelerator HBM (for active parameters and current sub-batch activations), which the one-shot tuner estimates from two calibration runs.

## Method

SpeedLoader's core insight is to process multiple sub-batches through each transformer layer before releasing it, reducing full-model loading from 2N times (N sub-batches) to just 2 times per effective batch. Concretely, incoming batches of shape (N, l) are split into (n_sub, n, l) sub-batches; each layer is loaded once, fed all sub-batches sequentially, and its activations are offloaded to a pre-allocated pinned host memory pool while the next sub-batch input is prefetched, with communication overlapped via separate CUDA streams. For backward propagation, the computation graph is re-routed by connecting same-layer activations with a no-op function so that autograd traces back in the same layer-by-layer order as the forward pass, and a backward hook buffers and passes correct gradients at each activation switch. A fragmentation-free memory pool is organized as (n_sub_batches, layer, sequence_length, -1) to enable contiguous asynchronous bulk copies, and a one-shot hyperparameter tuner exploits the observed linear relationship between sub-batch size, number of sub-batches, on-device layers, and peak memory to select optimal configurations in just two calibration iterations.

## Results

SpeedLoader achieves training speedups of 3.29x–30.33x over ZeRO-Offload/ZeRO baselines across single-device and 64-GPU distributed settings, reaching up to 51% MFU (vs. 36.54% for prior SOTA). In inference, it delivers 1.52x–2.35x throughput gains over FlexGen on OPT-6.7B/30B/175B. In a 4-node pretraining trial (effective batch 512, context 2048), SpeedLoader processes 4.08x more tokens for 7B and 2.68x more for 13B within the same wall-clock time while achieving lower loss (e.g., 2.507 vs. 2.896 on Wikipedia-7B).

## Baselines & Comparisons

Against ZeRO-Offload (DeepSpeed with host offloading), SpeedLoader achieves 3.29x and 6.49x training speedups on single A100 for LLaMA-2-7B/13B, and 5.48x, 5.49x, and 30.33x on 64-GPU distributed runs for 7B/13B/70B, with MFU rising from ~36% to 51%. Against ZeRO stage-3 without offloading, SpeedLoader still delivers 5.34x and 12.28x speedups on 7B/13B, showing the benefit extends beyond I/O-bound scenarios to peer-communication reduction. For inference, SpeedLoader outperforms FlexGen by 1.52x (OPT-6.7B), 2.09x (OPT-30B), and 2.35x (OPT-175B) on a single A100, with the largest gain on the 175B model where FlexGen's KV-cache offloading becomes a severe bottleneck. In the pretraining functionality test, SpeedLoader consistently processes 2.7x–4.3x more tokens than DeepSpeed within the same time budget across all six dataset/model-size combinations while also achieving lower final loss, confirming no arithmetic precision degradation.

## Relation to Prior Work

SpeedLoader builds directly on the ZeRO++ hierarchical weight partitioning framework as its implementation substrate, extending the offloading lineage that includes ZeRO-Offload, ZeRO-Infinity, and FlexGen. The key conceptual departure is a computation rescheduling strategy: rather than loading the full model once per mini-batch (as in canonical ZeRO-Offload) or once per layer (as in FlexGen's chunk-based approach), SpeedLoader retains a loaded layer in HBM and feeds it multiple sub-batches sequentially, offloading only activations to host DRAM between sub-batches. This transforms the I/O pattern from O(NP) model-state transfers to O(P) transfers per effective batch, where N is the number of sub-batches, while preserving gradient accumulation semantics through a redesigned computation graph with no-op activation routing.

## Why It Matters / Open Questions

For practitioners operating under severe HBM constraints (single-node or multi-node clusters with limited GPU memory), the 3x–30x training speedups and 1.5x–2.35x inference speedups make offloading-based LLM operation practically viable where it was previously prohibitively slow. The superlinear weak-scaling behavior suggests the approach becomes more effective as more accelerators are added, partially alleviating the PCIe bandwidth bottleneck. However, the method has not been validated in conjunction with tensor or pipeline parallelism, and host DRAM becomes the new bottleneck for very large effective batch sizes. The interaction between SpeedLoader's sub-batch scheduling and other parallelism dimensions (tensor parallelism's parameter-centric communication vs. data parallelism's activation-centric communication) remains an open and potentially high-impact research direction.
