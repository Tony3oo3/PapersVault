## Problem

LLMs using RoPE exhibit uneven context awareness, with attention waveforms creating troughs at specific relative positions that cause critical information to be overlooked (the 'lost-in-the-middle' phenomenon). Prior methods like Attention Buckets and Ms-PoE assign a fixed set of RoPE angles statically per head, which becomes suboptimal as generation progresses and the relative positions of crucial tokens shift. No existing approach provides dynamic, token-wise and head-wise RoPE angle selection while avoiding the high memory cost of parallel inference.
![Teaser figure](../imgs/NEURIPS20242525/cropped_page1_idx0.webp)

## Input / Output

The method plugs into any LLM that uses RoPE (tested on Llama2-7B, Mistral-7B, Qwen1.5-7B) and operates on standard text sequences up to 32k tokens. Each attention head's router receives the query vector q_n^h as input and outputs a distribution over N candidate RoPE angles (default N=7, with base values searched per model). The output is a modified attention score for each head-position pair, computed as a softmax-weighted sum of attention patterns from the top-K selected angles, which then feeds into the standard attention-to-value multiplication unchanged.

## Method

MoICE treats each distinct RoPE angle as an 'in-context expert' and integrates a lightweight MLP router (SiLU-activated, W1, W2 ∈ R^{N×d}, W3 ∈ R^{N×N}) into every attention head. At each generation step, the router takes the head's query vector, selects the top-K RoPE angles from N candidates, and computes attention scores with each selected angle; the final attention pattern is a weighted sum of these K patterns using softmax-normalized routing weights. Training uses a router-only strategy: all LLM parameters are frozen and only the routers are updated for one epoch (~8 minutes on 4 A800 GPUs) with a negative log-likelihood loss plus a load-balancing auxiliary loss (α=0.3) to prevent expert collapse. This design eliminates the redundant FFN computations of Attention Buckets and the static per-head angle assignment of Ms-PoE, adding only a few extra query-key dot products per head per token.

## Results

On the L-Eval benchmark, MoICE achieves the best closed-ended average of 50.72 on Llama2-7B-Chat (vs. 47.52 original, 50.02 AB, 49.60 Ms-PoE) and 55.38 on Mistral-7B-Instruct-8k (vs. 53.27 original, 53.31 AB). On Qwen1.5-7B-Chat, MoICE reaches 68.54 closed-ended average and 41.59% open-ended win-rate, while both AB and Ms-PoE suffer out-of-memory failures. In terms of efficiency, MoICE uses ~19.4 GB average GPU memory on Llama2-7B versus 61.8 GB for AB and 28.1 GB for Ms-PoE, with comparable inference speed to Ms-PoE.

## Baselines & Comparisons

MoICE outperforms all four baselines on Llama2-7B-Chat: it beats AB (50.72 vs. 50.02 closed-ended avg) and Ms-PoE (50.72 vs. 49.60) by 0.7 and 1.1 points respectively, and surpasses Dynamic NTK (49.41) and PI (48.77) by 1.3 and 2.0 points. On Mistral-7B-Instruct-8k, MoICE leads by a wider margin, achieving 55.38 closed-ended average versus 53.31 for AB, 53.86 for PI, 53.20 for Dynamic NTK, and 52.45 for Ms-PoE. On Qwen1.5-7B-Chat (32k context), both AB and Ms-PoE fail with out-of-memory errors, while MoICE achieves 68.54 closed-ended average and 41.59% open-ended win-rate, exceeding Dynamic NTK (67.77 / 40.20%) and PI (67.27 / 39.11%). In terms of efficiency, MoICE uses roughly 3x less GPU memory than AB (19.4 GB vs. 61.8 GB on Llama2-7B) while maintaining inference speed comparable to Ms-PoE, making it the only method that combines top accuracy with practical memory footprint across all three models.

## Relation to Prior Work

MoICE extends the Attention Buckets (AB) paradigm of Chen et al., which demonstrated that different RoPE angles direct attention to complementary contextual positions, by replacing AB's static, per-head angle assignment with a learned router that dynamically selects K angles per token per head. The routing mechanism borrows the top-K expert selection and load-balancing auxiliary loss from the Mixture of Experts literature (Shazeer et al.; Fedus et al.), but repurposes it in a fundamentally different way: the 'experts' are not learnable parameter blocks but fixed RoPE angle configurations, making them 'in-context' rather than 'in-weight' experts. This departs from Ms-PoE's per-head static rescaling and AB's N-parallel-inference approach by introducing token-level dynamism at negligible additional compute cost.

## Why It Matters / Open Questions

MoICE offers a practical, lightweight plug-in (~8 minutes of router-only training on 4 GPUs) that consistently improves long-context awareness across Llama, Mistral, and Qwen without catastrophic forgetting, while using roughly 3× less memory than Attention Buckets and avoiding OOM failures on larger-context models. The dynamic routing addresses a genuine limitation of prior static methods: as generation progresses, the relative positions of critical tokens shift, invalidating fixed angle assignments. Key open questions include whether the approach scales to 70B+ models, whether pretraining with MoICE from scratch (validated only at 49M parameters) yields compounding benefits, and whether the fixed RoPE angle set can be adapted per-domain or per-task.
