## Problem

LLM-based writing assistants generate generic responses that users must manually edit to match their personal style, incurring repeated effort. Existing alignment approaches like RLHF or per-user fine-tuning are expensive, hard to scale across millions of users, and risk degrading safety guarantees. This paper asks whether the natural, implicit feedback of user edits can be leveraged to learn a user's latent preference without any parameter updates to the base LLM.

## Input / Output

At each round the agent receives a text context (a document to summarize or notes to compose an email from) and a history of past (context, inferred-preference) pairs. It produces a text response conditioned on a retrieved-and-aggregated natural-language preference description (e.g., 'bullet points, parallel structure, brief'), which is also exposed to the user for inspection and modification. The quality of the response is measured by the Levenshtein edit distance in token space between the agent output and the user's revised version, accumulated over T=200 rounds.

## Method

CIPHER implements the PRELUDE framework by maintaining a growing preference history of (context embedding, inferred preference) pairs. For each new context, it retrieves the k-closest historical contexts via cosine similarity on a frozen encoder (MPNet or BERT), then queries the LLM to aggregate their inferred preferences into a single description f_t that is injected into the generation prompt. After the user edits the response, CIPHER applies a Latent Preference Induction (LPI) step: if the edit cost exceeds a threshold δ, it queries the LLM to produce a new preference description explaining the (original, revised) pair; otherwise it reuses f_t. This retrieval-then-aggregate-then-induce loop requires at most three additional LLM calls per round on top of the base generation, avoids fine-tuning entirely, and yields interpretable, user-editable preference descriptions that adapt to context-dependent preferences across document sources.

## Results

On the summarization task, CIPHER-5-MPNET achieves the lowest cumulative edit distance of 32,974±195 among all non-oracle methods (vs. 48,269±957 for No Learning and 38,560±1,044 for ICL-edit-5-MPNET), while incurring only 3.00×10⁵ BPE tokens of LLM expense. On email writing, CIPHER-5-BERT achieves the best edit distance of 8,391±3,038 (vs. 31,103±900 for No Learning), representing a 73% reduction in user edit cost. CIPHER also achieves the highest preference classification accuracy (0.520–0.565 on summarization, 0.435–0.487 on email writing) compared to 0.218–0.300 for all baselines, while maintaining LLM query costs close to the base agent (1.94–3.03×10⁵ tokens vs. 6.82–12.12×10⁵ for retrieval-based baselines).

## Baselines & Comparisons

CIPHER outperforms all baselines on cumulative edit distance across both tasks. Against the ICL-edit baseline (Brown et al., 2020), CIPHER-5-MPNET reduces edit distance by 15% on summarization (32,974 vs. 38,560) and by 69% on email writing (10,058 vs. 32,405), while also cutting LLM expense from 8.00 to 3.00 (×10⁵ tokens) on summarization and from 12.12 to 2.09 on email writing. Against the CoT-edit baseline (Wei et al., 2022), CIPHER achieves lower edit distance on both tasks (32,974 vs. 40,747 on summarization; 10,058 vs. 24,292 on email) and substantially lower expense (3.00 vs. 6.82; 2.09 vs. 8.74). The context-agnostic baselines (E-then-e LPI and Continual LPI) perform worst on summarization, with edit distances exceeding even No Learning, because a single fixed preference cannot capture the context-dependent preferences in the environment. CIPHER's key advantage is that it learns context-dependent, interpretable preference descriptions via retrieval and aggregation, achieving the best accuracy (0.520–0.565) while keeping LLM query overhead minimal (only ~1–2 additional LLM calls per round beyond the base agent).

## Relation to Prior Work

This paper departs from the dominant RLHF paradigm of comparison-based preference feedback (pairwise rankings) and from fine-tuning-based personalization (LoRA, DPO, supervised learning) by instead learning from naturally occurring user edits. It repurposes retrieval-augmented generation and in-context learning ideas, but applies them to a new target: inferring interpretable preference *descriptions* (short natural-language strings) rather than using raw edit examples as demonstrations. The CIPHER algorithm combines context-representation-based retrieval (MPNet/BERT embeddings) with LLM-based preference induction and aggregation, positioning itself between the ICL-edit and CoT-edit baselines it explicitly compares against.

## Why It Matters / Open Questions

The approach is practically attractive for writing assistants because it requires no fine-tuning, scales to many users, and produces interpretable preferences that users can inspect and modify. However, a significant gap to the oracle remains (roughly 5× higher edit cost), and retrieval accuracy on email writing is only ~25%, suggesting the method is far from solving the problem. Open questions include handling non-stationary or partially observed preferences, extending beyond two narrow writing tasks, and whether the LPI step can be made more reliable—the paper's own failure analysis identifies preference inference from a single edit pair as the dominant error source.
