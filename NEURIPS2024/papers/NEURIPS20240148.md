## Problem

Despite rapid progress in LLM-based autonomous agents, there is no systematic benchmark that evaluates the full pipeline of task automation—decomposing user instructions into sub-tasks, selecting appropriate tools, and predicting their parameters—while modeling the dependencies between tools. Existing tool-augmented benchmarks (APIBench, ToolBench, MetaTool, API-Bank) each cover only a subset of these stages, ignore inter-tool dependencies, and rely on template-based or API-documentation-driven generation that limits realism and scalability.

## Input / Output

The benchmark presents each LLM with a natural-language user instruction and a tool list (tool name, description, and parameter schema) drawn from one of three domains (Hugging Face AI models, multimedia utilities, or daily-life APIs). The model must produce a strict-JSON response containing: (1) an ordered list of task-step descriptions, (2) a tool invocation graph where nodes are (tool, arguments) pairs and directed edges encode resource or temporal dependencies, and (3) concrete parameter values for every tool call. Structural complexity is controlled by sampling subgraphs of type Node (single tool), Chain (sequential), or DAG (branching), with 1–10 tools per instance.

## Method

TaskBench introduces a Tool Graph (TG) that encodes resource and temporal dependencies among tools as a directed graph, then uses a Back-Instruct data engine: subgraphs are sampled from the TG (as nodes, chains, or DAGs), and GPT-4 is prompted to inversely synthesize a realistic user instruction, task steps, and a fully parameterized tool invocation graph that must be consistent with the sampled subgraph. A two-stage self-critic (LLM-based alignment check plus rule-based node/edge matching) filters inconsistent samples, followed by human verification, yielding 17,331 high-quality instances. For evaluation, TaskEval scores three stages separately: task decomposition via ROUGE-1/2/L against gold step descriptions, tool selection via Node F1, Edge F1, and Normalized Edit Distance (for chains), and parameter prediction via t-F1 (task–parameter-name pairs) and v-F1 (task–parameter-name–value triples), with ranking consistency validated against human judgment (average Kendall's τ = 0.89, Spearman's ρ = 0.78).

## Results

On TaskBench, GPT-4 consistently leads across all three domains and all three evaluation stages. For tool selection (the core task), GPT-4 achieves 81.54 n-F1 and 54.70 e-F1 overall on Hugging Face tools, 90.90 n-F1 and 69.27 e-F1 on Multimedia tools, and 96.91 n-F1 and 80.53 e-F1 on Daily Life APIs. Edge prediction is consistently ~20–30 points harder than node prediction across all models, and performance degrades sharply as tool graph complexity increases (graph accuracy drops from 96.16% for single-tool tasks to 25.00% for 8-tool DAGs on GPT-4). For parameter prediction, GPT-4 reaches 60.86 v-F1 (Hugging Face), 72.31 v-F1 (Multimedia), and 71.14 v-F1 (Daily Life APIs), while open-source 13B models typically score below 20 v-F1 on Hugging Face.

## Baselines & Comparisons

TaskBench evaluates 14 LLMs (GPT-4, GPT-3.5-Turbo, Text-Davinci-003, Gemini-Pro, Claude-2, Mistral-7B, CodeLlama-13B/7B, Vicuna-13B/7B, Nous-Hermes-13B, WizardLM-13B, Llama-2-13B/7B, Llama-3-8B, Baichuan-13B, InternLM-7B, LongChat-7B) rather than competing methods, so comparisons are between models. GPT-4 dominates on all three domains for both node and edge F1, with the largest margins over open-source models on edge prediction (e.g., 54.70 vs. 7.28 e-F1 on Hugging Face vs. Vicuna-13B). CodeLlama-13B is a notable exception on Daily Life APIs, achieving 87.73 n-F1 and 63.16 e-F1—close to GPT-3.5-Turbo (85.37/60.67)—attributed to its code pre-training enhancing structured task sequencing. Claude-2 and Gemini-Pro are competitive on node F1 but trail GPT-4 by 10–15 points on edge F1, indicating weaker dependency reasoning. All open-source 13B models (Vicuna, Nous-Hermes, Llama-2) collapse on edge prediction (e-F1 < 15 on Hugging Face), revealing a fundamental gap in modeling tool dependencies. The paper also validates TaskEval against human evaluation with Kendall's τ = 0.89 and Spearman's ρ = 0.78, confirming the benchmark's reliability.

## Relation to Prior Work

This paper departs from prior tool-augmented LLM benchmarks (APIBench, ToolBench, MetaTool, API-Bank) that rely on API documentation or template-based task generation, by introducing the Tool Graph to explicitly model resource and temporal dependencies between tools. The Back-Instruct strategy inverts the Self-Instruct paradigm: rather than generating instructions forward and hoping tools align, it samples tool subgraphs first and reverse-engineers natural user instructions from them. The evaluation framework extends single-metric benchmarks (tool selection F1, QA accuracy) to a three-stage protocol covering task decomposition, tool selection, and parameter prediction simultaneously, building on the HuggingGPT taxonomy of invocation patterns (node, chain, DAG).

## Why It Matters / Open Questions

TaskBench provides the first standardized benchmark that jointly evaluates all three stages of LLM task automation with explicit tool dependency modeling, filling a gap that limits reproducibility in the rapidly growing LLM-agent literature. The consistent ~20% gap between node and edge F1 across all models highlights that understanding inter-tool relationships remains a fundamental bottleneck for autonomous agents, independent of model scale. Key limitations include reliance on GPT-4 for data generation (introducing potential bias), coverage of only three domains with ~17K samples, and a ~12% residual error rate in the dataset. Open questions include whether the Tool Graph abstraction generalizes to open-ended tool ecosystems and whether the benchmark's complexity scaling (dramatic accuracy drop from 1-tool to 8-tool graphs) reflects real-world agent failure modes.
