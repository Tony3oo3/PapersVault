## Problem

Existing ViT efficiency techniques (local attention, token pruning) reduce theoretical FLOPs but introduce heavy data-transformation overhead (Reshape, Transpose) that dominates execution time on mobile GPUs with limited memory bandwidth, sometimes making latency worse than vanilla ViT. No prior work co-designs the attention architecture with system-level optimizations to achieve real-time inference on smartphones.
![Teaser figure](../imgs/NEURIPS20243033/cropped_page1_idx0.webp)

## Input / Output

The model takes RGB images (224×224 for ImageNet/TinyImageNet, 96×96 for STL-10/CIFAR-100) and splits them into 16×16 patches, yielding 196 token embeddings. During inference, the 196 patches are partitioned into core and periphery groups according to a learned core ratio (e.g., 10% core ≈ 20 patches), and the output is a single class label per image. The CP graph structure is fixed at training time via Grad-CAM importance scores and remains static at inference.

## Method

ECP-ViT replaces full self-attention with a Core-Periphery (CP) guided scheme inspired by brain functional networks: core patches attend to all patches while periphery patches attend only to core patches, decomposing the attention into two smaller matrix multiplications (Q_c·K^T·V and Q_p·K_c^T·V_c) that preserve hardware-friendly dense computation patterns. A compiler-based optimization pipeline then eliminates all explicit Reshape and Transpose operators by identifying a common intermediate data layout for each sub-graph, mapping index transformations directly into kernel code, and storing intermediate results in GPU texture memory to avoid CPU-GPU transfers. A compression-compilation co-design loop uses the compiler with synthesized weights to predict latency at various pruning ratios before committing to expensive fine-tuning, enabling principled selection of the optimal core ratio that balances accuracy and speed.

## Results

On ImageNet-1K, ECP-ViT-Base achieves 84.6% top-1 accuracy with 16.96G MACs, outperforming ViT-Base (83.9%), DeiT-Base (84.2%), and TNT-B (84.1%). On TinyImageNet, ECP-ViT-B/16 reaches 90.55% top-1, surpassing ConViT-B/16 (90.52%) and ViT-B/16 (89.16%). On STL-10, ECP-ViT-S/16 improves over ViT-S/16 by +1.82% (98.18% vs. 96.36%). In terms of latency on a OnePlus 11 (Adreno 740 GPU), ECP-ViT achieves 4.6×–26.9× speedup over state-of-the-art mobile inference frameworks (MNN, TNN, TVM), with ECP-ViT-Base running at 122.8 ms versus 2033 ms on TVM.

## Baselines & Comparisons

ECP-ViT-Base (84.6%) outperforms all ImageNet baselines including ViT-Base (83.9%), DeiT-Base (84.2%), TNT-B (84.1%), and PVT-Large (83.8%), while using fewer MACs (16.96G vs. 17.6G for ViT-Base). At the small scale, ECP-ViT-Small (80.9%) slightly trails ViT-S (81.1%) but beats T2T-ViTt-14 (80.7%) and PVT-Small (79.8%); at the tiny scale, ECP-ViT-Tiny (75.8%) surpasses both PVT-Tiny (75.1%) and LTMP (75.4%) with fewer parameters (5.83M vs. 13.2M and 5.7M respectively). On TinyImageNet, ECP-ViT-B/16 (90.55%) edges out ConViT-B/16 (90.52%) and clearly beats ViT-B/16 (89.16%), BEiT-B/16 (88.64%), and DeiT-B/16 (87.29%). On STL-10, ECP-ViT-S/16 improves over ViT-S/16 by +1.82% (98.18% vs. 96.36%), and on CIFAR-100 it gains a marginal +0.05% (89.56% vs. 89.51%). In latency comparisons (Table 7), ECP-ViT's compiler framework achieves 4.8×–5.3× speedup over TVM/MNN/TNN for vanilla ViTs, and 10.6×–16.1× speedup for CP-pruned ECP-ViTs within the same framework, with the largest gap (26.9×) observed for ECP-ViT-Tiny vs. TVM.

## Relation to Prior Work

This paper extends the ViT architecture (Dosovitskiy et al., ICLR 2021) by replacing full self-attention with a core-periphery guided sparse attention mechanism, drawing on the core-periphery organizational principle from brain functional networks (Yu et al., 2023). It departs from prior efficient-ViT work (Swin, DeiT, local attention variants) that reduced theoretical FLOPs but inadvertently introduced heavy data-transformation overheads (Reshape, Transpose) that negate speedups on bandwidth-limited mobile GPUs. The key conceptual departure is the algorithm-system co-design: the sparsity pattern is chosen to be hardware-friendly (two small matrix multiplications instead of one large one), and a compiler framework eliminates all explicit layout transformations by fusing producers and consumers with compatible data layouts.

## Why It Matters / Open Questions

The paper's central empirical finding—that Swin-T (local attention, fewer FLOPs) is over 3× slower than ViT-T (global attention, more FLOPs) on mobile GPU due to data-transformation overhead—challenges the common assumption in the efficient-transformer literature that FLOP reduction directly translates to latency reduction on edge hardware. This reframes the optimization target from arithmetic intensity to memory-movement minimization, which is a practically important insight for mobile deployment. Limitations include evaluation on only two phones (both Qualcomm Adreno), no NPU experiments, no released code, and no error bars; the large speedup numbers (up to 26.9×) are partly driven by weak baselines (TVM showing 2033 ms on ECP-ViT-Base). Open questions include whether the core-periphery principle generalizes to dense prediction tasks (segmentation, detection) and whether the compiler optimizations transfer to non-Adreno mobile GPUs.
