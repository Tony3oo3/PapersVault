## Problem

Existing speculative decoding methods are designed for datacenter hardware and do not scale well with large draft token budgets: the number of accepted tokens saturates at roughly 10 regardless of how many draft tokens are generated. On consumer GPUs with RAM offloading, processing hundreds or thousands of tokens takes nearly the same wall-clock time as a single token (because the bottleneck is parameter loading, not computation), making large draft budgets natural but unexploited by prior algorithms.

## Input / Output

The method takes a text prompt, a small draft model (e.g., Llama-2-7B), a large target model (e.g., Llama-2-70B, optionally GPTQ-quantized to 4-bit), and generation parameters including temperature, top-p, draft budget K (number of tokens in the tree), max depth D, and batch size B. It outputs a token sequence that is bit-identical to sequential sampling from the target model with the same random seed — a stronger guarantee than standard speculative decoding, which only matches the marginal distribution. The draft tree is deterministic (constructed via search, not sampling), which is the key departure from prior speculative decoding that requires stochastic drafts for correctness.

## Method

SpecExec replaces the draft-and-verify paradigm with a speculative cache: it precomputes target model probabilities for K likely future tokens in a single offloaded forward pass, then performs standard sequential sampling by looking up those cached probabilities, only re-querying the target model when the sampled path falls outside the cache. The draft tree is constructed by a parallel single-source shortest path (SSSP) search — a modified Dijkstra's algorithm that expands B nodes per iteration — to find the K tokens with the highest cumulative draft-model probability, rather than sampling a tree as in SpecInfer. Because SpecExec samples directly from target model probabilities at each step, the draft tree need not follow any particular distribution, enabling deterministic search to build a tree that captures the largest possible probability mass. This yields 10–20 accepted tokens per target iteration (vs. ~8–10 for SpecInfer at comparable budgets) and 4–6 tok/s interactive inference for 70B models on consumer GPUs with 4-bit quantization and RAM offloading.

## Results

SpecExec achieves 4–6 tokens/second with 4-bit GPTQ quantization and 2–3 tokens/second with 16-bit weights for Llama 2-70B on consumer GPUs with RAM offloading, yielding 10–18× speedups over sequential inference. On an A100 GPU with Llama 2-7B/70B (Chat, OAsst, t=0.6), SpecExec reaches a generation rate of 20.60 accepted tokens per target iteration at 3.12 tok/s (18.7× speedup), compared to SpecInfer's 8.41 at 1.34 tok/s (8.0×). On consumer hardware (Table 3), RTX 4090 achieves 5.66 tok/s (8.3×), RTX 3090 achieves 3.68 tok/s (10.6×), and even an RTX 2080Ti reaches 1.86 tok/s (6.1×) with a 1.3B draft model.

## Baselines & Comparisons

The sole baseline is SpecInfer (Miao et al., 2023), which uses a static tree structure with sampled draft tokens. SpecExec consistently outperforms SpecInfer across all tested configurations, with the gap widening as the draft budget grows: at 1024 tokens on OAsst (t=0.6), SpecExec accepts 20.60 tokens per iteration versus SpecInfer's 8.41, translating to 3.12 vs. 1.34 tok/s (18.7× vs. 8.0× speedup). At greedy decoding (t=0), the advantage is similar (18.8 vs. 7.86 accepted tokens). The paper attributes this to SpecExec's deterministic, probability-mass-maximizing tree construction (via parallel SSSP) versus SpecInfer's requirement to sample draft tokens to preserve correctness. For smaller budgets (≤128 tokens), the two methods perform comparably, but SpecExec's structured tree design becomes increasingly advantageous at the hundreds-to-thousands-of-tokens scale that offloading makes practical. SpecExec also outperforms the fixed-tree Sequoia method (Chen et al., 2024b), achieving 2.8 tok/s vs. 2.2 tok/s in the Llama 3-8B/70B setup.

## Relation to Prior Work

This paper builds on the speculative decoding lineage (Leviathan et al. 2023, Chen et al. 2023a, SpecInfer/Miao et al. 2023) and parameter offloading (Pudipeddi et al. 2020, Alizadeh et al. 2023), but departs from both in key ways. Rather than treating the draft tree as a stochastic proposal to be verified against a known distribution, SpecExec reframes the problem as speculative execution: a deterministic cache of precomputed target-model probabilities, populated by a parallel SSSP (Dijkstra) search over the draft model's token space. This removes the requirement that the draft tree follow a specific sampling distribution, enabling the use of a large (7B) draft model and deterministic beam-like search—both of which would break standard speculative decoding's correctness guarantees.

## Why It Matters / Open Questions

SpecExec makes interactive inference of 50B+ parameter LLMs practical on consumer GPUs (4–6 tok/s at 4-bit, 2–3 tok/s at 16-bit), a regime previously limited to ~0.2 tok/s with sequential offloading. The counterintuitive finding that a large draft model outperforms smaller ones in the offloading regime challenges the prevailing design heuristic in speculative decoding and opens the door to further exploration of draft-target model alignment. Limitations include dependence on a capable draft model (7B+), reduced gains with quantized targets at larger batch sizes, and the fact that the speedup is most dramatic specifically in the offloading setting; without offloading, gains drop to ~2×. Open questions include whether the SSSP formulation generalizes to multi-GPU or distributed offloading, and how the method interacts with emerging hardware (e.g., unified-memory Apple Silicon).
