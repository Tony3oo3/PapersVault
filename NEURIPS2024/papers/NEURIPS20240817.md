## Problem

Engineering effective prompts for LLM agents to use external tools in multi-step tasks remains a heuristic, labor-intensive process. Existing agent frameworks (ReAct, Reflexion) either rely on brittle hand-crafted mega-prompts or perform per-sample self-reflection that fails to identify systemic flaws across the full solution pipeline (decomposition, tool selection, synthesis). No prior method automatically generates holistic, generalizable instructions that target tool usage specifically.

## Input / Output

The framework consumes a small set of query-answer pairs from a training split (e.g., 100–400 queries), a knowledge base (a relation-text graph with documents for STARK, or images with bounding-box annotations for FLICKR30K-ENTITIES), and a library of 28 pre-implemented tool APIs. The actor outputs a Python action sequence that calls these tools to compute a node_score_dict mapping candidate IDs to relevance scores (retrieval) or a natural-language answer (QA). The comparator's output is a set of natural-language instructions appended to the actor's prompt, not a parameter update. At deployment, the optimized action sequence or instruction set is applied directly to unseen queries.

## Method

AVATAR pairs an actor LLM with a comparator LLM in an iterative optimization loop. Each iteration, the comparator samples a mini-batch of b queries split equally into positive (metric > ℓ) and negative (metric < h) groups, then performs contrastive reasoning to identify systemic gaps in the actor's action sequence—attributing the performance difference to specific tool-usage patterns, decomposition errors, or synthesis flaws—and generates holistic instructions that serve as a robust 'gradient' for the actor. This batch-wise contrastive mechanism, analogous to mini-batch training in deep learning, avoids the overfitting and narrow scope of per-sample reflection. A memory bank retains the top-5 best-performing action sequences to prevent the actor from regressing, while logistic instructions (validity checks, timeout errors) ensure executable code. The actor generates Python code that composes tool calls (embedding similarity, LLM-based verification, token matching, IDF reweighting) with learned coefficients, and the best-performing action sequence across epochs is selected for deployment.

## Results

On the STARK retrieval benchmark (textual + relational knowledge), AVATAR achieves an average 15.6% relative improvement in Hit@1 and 9.5% in MRR over the best baseline (Reflexion), with the largest gains on STARK-AMAZON (Hit@1: 49.87 vs. 42.79) and STARK-PRIME (Hit@1: 18.44 vs. 15.28). On FLICKR30K-ENTITIES (image retrieval), AVATAR reaches 42.4% Hit@1 and 52.3% MRR, outperforming the best embedding-based retriever (CLIP) by 9.2% and 13.0% respectively. On QA benchmarks, AVATAR achieves 53.0% EM on HotpotQA, 84.0% on ArxivQA, and up to 23.3% on ToolQA-SCIREX-HARD, yielding an average 13% relative improvement over the strongest baseline across all three datasets.

## Baselines & Comparisons

AVATAR outperforms all seven baselines across the majority of metrics. Against embedding-based retrievers (DPR, ada-002, multi-ada-002) and the graph-based QAGNN, AVATAR achieves large margins (e.g., 49.87 vs. 15.29 Hit@1 on STARK-AMAZON vs. DPR). Among agent baselines, AVATAR beats ReAct by 7.73 points on STARK-AMAZON Hit@1 (49.87 vs. 42.14) and by 3.65 points on MAG Hit@1 (44.36 vs. 40.71 for Reflexion). On QA tasks, AVATAR surpasses Retroformer on HotpotQA (53.0% vs. 51.0% EM), Reflexion on ArxivQA (84.0% vs. 77.0%), and ExpeL on ToolQA-AGENDA-EASY (60.0% vs. 56.6%), with the largest relative gain of 33.1% on ToolQA-SCIREX-HARD (23.3% vs. 17.5% for ReAct). The ablation AVATAR-C (without the comparator) underperforms full AVATAR by 8.95 points on STARK-AMAZON Hit@1, confirming the comparator's critical role. On FLICKR30K-ENTITIES, AVATAR (42.4% Hit@1) outperforms both CLIP (37.2%) and Reflexion (28.4%), while the only metric where AVATAR does not lead is MAG R@20 (50.63 vs. 50.80 for multi-ada-002, a −0.3% relative difference).

## Relation to Prior Work

AVATAR builds on the LLM agent paradigm (ReAct, Reflexion, ExpeL) and the broader agent-optimization literature (Retroformer, prompt tuning, fine-tuning), but departs from these by introducing a dedicated comparator LLM that performs batch-wise contrastive reasoning over positive and negative examples to generate holistic prompts, rather than relying on per-sample self-reflection or heuristic mega-prompts. The key conceptual move is drawing an analogy to gradient computation in neural network training: a mini-batch of contrasted examples yields a more robust 'gradient' for updating the actor than noisy single-instance feedback. This positions AVATAR as a prompt-level optimization method that is more targeted than generic prompt tuning (focusing specifically on tool usage and multi-step decomposition) and more generalizable than experience-based methods like ExpeL that extract insights from individual trajectories.

## Why It Matters / Open Questions

AVATAR addresses a practical bottleneck in deploying LLM agents: the labor-intensive, heuristic process of engineering effective prompts for tool-assisted multi-step tasks. By automating this through contrastive reasoning, it reduces the need for manual trial-and-error while producing agents that generalize to novel queries (validated on human-generated leave-out sets). Open questions include scalability to hundreds of tools, computational cost of iterative optimization, and whether the framework extends to more dynamic environments or visual reasoning tasks. The paper also notes that AVATAR's performance may degrade on queries requiring entirely new tool combinations, suggesting a need for adaptive learning mechanisms beyond the current memory-bank approach.
