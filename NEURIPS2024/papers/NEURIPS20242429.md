## Problem

Nanopore sequencing data analysis involves multiple interdependent computational tasks (base calling, polyA detection, segmentation/event alignment, modification detection), but public datasets are scattered across repositories, each preprocessed with different pipelines and used for only one task. This fragmentation, combined with the ~200 GB raw data size and the need for extensive bioinformatic expertise to chain upstream tasks, creates a significant barrier for machine learning researchers to enter the field and conduct fair cross-method comparisons.

## Input / Output

The benchmark consumes raw current signal files (fast5/pod5, ~200 GB per dataset) and a reference genome sequence, then produces standardized intermediate artifacts at each pipeline stage: FASTQ base-called reads, minimap2 alignment files, polyA detection flags with start/end positions and tail length, and per-kmer signal segment alignments (events). All 16 datasets are restricted to R9.4 pore chemistry and are stored in uniform formats so that any task's input can be directly consumed without reprocessing, and the software package exposes these via abstract dataset classes that mimic standard deep learning training loops.

## Method

NanoBaseLib's core contribution is a six-step unified preprocessing pipeline (format standardization → Guppy base calling → minimap2 mapping → optional polyA detection → segmentation/event alignment → optional modification detection) applied identically to 16 public datasets spanning six species and over 30 million reads, producing a 'One Dataset, Multiple Tasks' resource where each task's output feeds the next. For benchmarking, they evaluate four tasks with multiple baselines: seven base callers (Guppy v2–v6, Dorado v0.5–v0.7, Bonito, Causalcall, Rodan) scored by match/mismatch/insertion/deletion rates via parasail alignment; three polyA detectors (Nanopolish polya, Dorado, Tailfindr) scored by detection rate and MSE of tail length; three segmentation methods (Nanopolish, Tombo, SegPore) scored by average std and log-likelihood against ONT's standard kmer parameter table; and up to six modification detectors (m6Anet, CHEUI-solo, Tombo, MINES, Nanom6A, Epinao, SegPore) scored by AUC-ROC and AUC-PR against ChIP-seq-derived ground truth. A companion software package abstracts dataset loading and metric computation, and provides the full pipeline for incorporating new datasets as they become available.

## Results

On DNA base calling (NA12878), Guppy v6.0.1 achieves the best match rate of 93.60% (MAlign), with Dorado v0.7.0 close behind at 93.47%. On RNA base calling (hek293t_wt), Dorado v0.5.3 leads with 93.96% MAlign, outperforming Guppy v6.0.1 (91.78%) by over 2 percentage points. For segmentation and event alignment, SegPore achieves the lowest average std (2.736) and highest log-likelihood (-2.778) across all three test datasets. For modification detection, m6Anet achieves the best ROC/PR performance for m6A, while CHEUI-solo is best for m5C.

## Baselines & Comparisons

For DNA base calling, Guppy v6.0.1 (93.60% MAlign) outperforms all other methods, with Causalcall trailing by nearly 10 percentage points (84.30%). For RNA base calling, Dorado v0.5.3 (93.96% MAlign) clearly leads, beating Guppy v6.0.1 by 2.18 points and Rodan by 6.24 points; notably, Guppy v4.5.4 and v6.0.1 produce identical results on this dataset. In segmentation and event alignment, SegPore dominates both metrics (avg std 2.736 vs. Nanopolish 3.073 and Tombo 4.187; log-likelihood -2.778 vs. -2.871 and -3.749), with Tombo consistently worst. For polyA detection, Tailfindr achieves the highest detection rate across all seven test datasets, while Nanopolish polya shows large performance variation. For m6A modification detection, m6Anet achieves the best ROC and PR curve performance across all three ground truth sources (MeRIP-seq, miCLIP, miCLIP2), while for m5C, CHEUI-solo outperforms both Tombo variants.

## Relation to Prior Work

This paper does not build on a specific prior method but addresses a structural gap in the Nanopore sequencing literature: the absence of a unified, multi-task, multi-species benchmark. Prior resources are fragmented — ONT Open Data provides task-specific exemplars, Jain et al. covers DNA base calling for one species, DirectRMDB catalogs modifications without uniform intermediate results, and existing benchmarks (Pagès-Gallego et al., Zhong et al.) each cover only one or two tasks. NanoBaseLib carves new ground by integrating 16 public datasets across six species and four interdependent tasks under a single preprocessing pipeline, effectively repurposing existing raw data into a coherent benchmark infrastructure rather than proposing a new algorithmic approach.

## Why It Matters / Open Questions

The ~93% best base-calling accuracy (vs. the ~99.9% target) underscores a substantial headroom that the paper argues the ML community is positioned to exploit, but only if accessible, standardized data exists. Key limitations include reliance on R9.4 chemistry (R10.3 performance is unassessed), ground-truth approximations inherent to epigenetically modified sequences, and benchmarks run on only a subset of the 16 datasets. Open questions include whether the unified pipeline generalizes to newer pore versions, whether the benchmark can genuinely attract ML researchers to close the accuracy gap, and how batch-effect mitigation scales as more heterogeneous datasets are added.
