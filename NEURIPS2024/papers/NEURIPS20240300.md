## Problem

Traditional KGE models map every entity to a unique embedding vector, causing linear memory growth that becomes unaffordable at scale. Anchor-based strategies like NodePiece alleviate this by propagating features over a small set of representative entities, but they select anchors via random sampling or manually tuned centrality weights, which neither exploits KG-specific structure nor guarantees anchor quality. The paper asks: can anchors be selected in a principled, data-driven way that is both explainable and scalable across different knowledge graphs?

## Input / Output

The method consumes a knowledge graph as a set of factual triplets (head entity, relation, tail entity) and produces entity embeddings via hash-based propagation over a small anchor set. Unusually, the clustering operates on triplet-level features (sums of normalized entity and relation embeddings) rather than entity features, and the cluster count is fixed to the number of relation types |R|, requiring no grid search. The only tunable hyperparameter is the total anchor count k, from which per-relation triplet counts m_i are derived proportionally to each relation's frequency in the graph. Downstream outputs are link-prediction rankings (MRR, Hits@k) or entity class labels (ROC-AUC, PRC-AUC, Hard Acc).

## Method

RecPiece introduces a relational clustering-based anchor selection strategy with five stages: (a) a pretrained KGE encoder p(·) (default: NodePiece) generates triplet feature vectors by summing normalized entity and relation embeddings; (b) k-means clusters these triplet features into |R| clusters, where the cluster number equals the number of relation types, leveraging the descriptive ability of relations to naturally partition facts; (c.1) for each centroid, the top-m_i triplets by cosine similarity are selected as candidates, with m_i = k·|G_i|/|G| ensuring proportional representation per relation; (c.2) each candidate triplet is mapped to an anchor entity by randomly choosing its head or tail; (d) the resulting anchor set is used with NodePiece's hash-based encoding (discrete distances + relational contexts) and a 2-layer MLP to propagate features to all entities. The key distinction from prior anchor-based methods is that anchor quality is determined by cluster-centroid proximity in triplet-feature space rather than by graph centrality heuristics, making the selection both explainable (tied to relation semantics) and requiring only one hyperparameter.

## Results

On link prediction, RecPiece+RotatE achieves MRR 0.265 / Hits@10 0.431 on FB15k-237, MRR 0.402 / Hits@10 0.506 on WN18RR, MRR 0.198 / Hits@10 0.323 on CoDEx-L, and MRR 0.243 / Hits@10 0.482 on YAGO 3-10, using only 2.9–5.0M parameters (vs. 29–123M for full RotatE). On entity classification (WD50K, 5% labeled), RecPiece+COMPGCN reaches ROC-AUC 0.983, PRC-AUC 0.459, and Hard Acc 0.538 with just 0.64M parameters. On the large-scale OGB WikiKG 2, RecPiece+AutoSF attains MRR 0.598 with only 5.9M parameters, outperforming the best full-parameter model (PairRE+LRE, MRR 0.584) while being ~84× lighter than AutoSF (500M params).

## Baselines & Comparisons

RecPiece consistently outperforms the anchor-based baseline NodePiece [20] across all four link prediction datasets (e.g., +4.3% MRR on FB15k-237, +5.2% on YAGO 3-10) and on entity classification (PRC-AUC 0.459 vs. 0.443, Hard Acc 0.538 vs. 0.513 on WD50K), while using fewer or equal parameters. Against the shallow KGE baselines RotatE [61] and COMPGCN [68], RecPiece incurs an expected performance gap (e.g., MRR 0.265 vs. 0.338 on FB15k-237) but reduces parameters by 84–97%, which is the intended efficiency trade-off. On the large-scale OGB WikiKG 2, RecPiece+AutoSF [79] (MRR 0.598, 5.9M params) surpasses every full-parameter baseline tested: TransE [6] (0.426), DisMult [77] (0.373), ComplEX [65] (0.503), PairRE [10] (0.521), TripleRE [78] (0.579), AutoSF (0.546), and even the parameter-efficient PairRE+LRE [11] (0.584), all of which use 500M+ parameters. The largest relative gains over NodePiece appear on denser, relation-rich datasets (FB15k-237, CoDEx-L, YAGO 3-10), while improvements on the sparse WN18RR (11 relations) are marginal (+0.3% MRR), suggesting the clustering benefit scales with relation diversity.

## Relation to Prior Work

RecPiece builds directly on NodePiece [20], which introduced anchor-based sampling as a plug-and-play mechanism to reduce the entity set for feature propagation in KGE models. The key departure is in anchor selection: where NodePiece relies on random sampling or manually tuned centrality heuristics (Node Degree Centrality, Personalized PageRank), RecPiece replaces this with a relational clustering strategy that clusters over triplet features (rather than entity features) and sets the cluster number to the number of relation types. The feature propagation pipeline (hash-based encoding + MLP) is inherited unchanged from NodePiece, positioning RecPiece as a drop-in replacement for the anchor selection module within the same framework.

## Why It Matters / Open Questions

The paper addresses a practical bottleneck: traditional KGE models scale linearly in memory with entity count, making them infeasible on large KGs like OGB WikiKG2 (2.5M entities). By making anchor selection data-driven and grounded in KG structure (relation types), RecPiece reduces the need for dataset-specific grid search over centrality weights and achieves consistent 3–5% MRR gains over NodePiece with fewer parameters. However, the feature preparation step still depends on a separately pretrained encoder (NodePiece or GraIL), which the authors acknowledge as a limitation and plan to address with a self-adaptive mechanism. The modest but consistent improvements across six datasets and two task types suggest the clustering-based selection is a more principled default, though the absolute performance gap to full-parameter models remains substantial.
