## Problem

Standard distributed training requires workers to transmit full-precision (32-bit) gradient vectors to a central server, creating a severe communication bottleneck for large-scale models. While the Lion optimizer's sign-based update naturally produces binary outputs, no prior work had adapted Lion to a distributed setting where workers maintain independent optimizer states and communicate only compressed updates. This paper asks whether Lion's binary update mechanism can be exploited to reduce inter-worker communication by 30× or more without sacrificing convergence or final model quality.

## Input / Output

Each worker receives local stochastic gradients from its own data shard and maintains a private first-order momentum vector; it transmits only a binary vector δ_{i,t} ∈ {−1,0,+1}^d to the server (1 bit per parameter). The server returns either a binary vector (Majority Vote, 1 bit/param) or an integer vector in {0,…,N} encoded in ⌈log N⌉ bits per parameter (Averaging), which workers combine with weight decay to update their local model parameters. This contrasts with global Lion/AdamW, which require 32 bits per parameter in both directions, and with TernGrad, which requires 1.5 bits up and log(2N+1) bits down.

## Method

Distributed Lion decouples the optimizer state from the communication channel: each worker independently runs the Lion double-β momentum update (m_{i,t+1} = β₂m_{i,t} + (1−β₂)g_{i,t}) and computes a binary update δ_{i,t} = sign(β₁m_{i,t} + (1−β₁)g_{i,t}), sending only this binary vector to the server. The server aggregates via either majority vote (sign of the sum, preserving binarity) or averaging (mean, yielding log N-bit integers), then broadcasts the result back. Workers apply x_{i,t+1} = x_{i,t} − ε(Δ_t + λx_{i,t}) locally. The key distinction from gradient-quantization methods (TernGrad, DGC) is that compression is applied to the post-optimizer update rather than the raw gradient, and the sign structure of Lion makes the binary representation lossless for the update direction. Theoretical analysis frames the dynamics as a box-constrained optimization problem and proves that both aggregation variants converge to KKT stationary points at rates matching global Lion, with the Majority Vote variant additionally benefiting from a 1/√N variance reduction term.

## Results

On ImageNet-1K, D-Lion (Avg) achieves 80.11% top-1 accuracy with ViT-S/16 and 81.13% with ViT-B/16, matching or slightly exceeding G-Lion (79.82%/80.99%) and G-AdamW (79.74%/80.94%). On OpenWebText language pretraining, D-Lion (MaVo) reaches 18.37 and 14.66 validation perplexity for GPT-2++ 350M and 760M respectively, on par with G-Lion (18.35/14.66). On 3-shot instruction finetuning of LLaMA-7B, D-Lion (MaVo) achieves 49.75 on SIQA and 35.71 on OBQA, matching or exceeding G-Lion and G-AdamW. All results are achieved with 32× less communication bandwidth (1 bit/parameter vs. 32-bit float) compared to global distributed training.

## Baselines & Comparisons

Against the global baselines, D-Lion (Avg) slightly outperforms both G-Lion and G-AdamW on ImageNet (80.11% vs. 79.82%/79.74% for ViT-S/16), while D-Lion (MaVo) is within 0.1–0.2% of G-Lion on language modeling (14.66 vs. 14.66 PPL for 760M). Against communication-efficient baselines on CIFAR-10, both D-Lion variants outperform DGC, GradDrop, and TernGrad by a large margin in test accuracy at the same 1-bit/parameter communication budget (Figure 2 and 4). The paper also shows that applying the same distributed framework to Signum (D-SIGNUM) yields worse performance than D-Lion, confirming that Lion's double-β momentum is critical. On instruction finetuning, D-Lion (MaVo) matches or beats G-Lion on SIQA (49.75 vs. 49.64) and OBQA (35.71 vs. 35.51), while D-Lion (Avg) is slightly weaker on OBQA (32.14 vs. 35.51), suggesting the choice between Avg and MaVo depends on global batch size.

## Relation to Prior Work

This paper extends the Lion optimizer (Chen et al., 2023), discovered via evolutionary program search, to the distributed training setting by exploiting the binary nature of its sign-based updates. Conceptually, it departs from prior communication-efficient methods (TernGrad, DGC, Gradient Dropping) that compress or sparsify gradients before transmission; instead, Distributed Lion communicates the already-binary optimizer updates, making compression an inherent property of the optimizer rather than an additional step. The theoretical analysis builds on the box-constrained optimization interpretation of Lion from Chen et al. (2023), extending the two-phase convergence framework to the distributed setting with both majority-vote and averaging aggregation. The work also sits within the broader sign-based optimization lineage (RProp → SignSGD → Signum → Lion), with the double-beta momentum scheme distinguishing Lion from its predecessors.

## Why It Matters / Open Questions

Distributed Lion achieves a 32× reduction in communication bandwidth while maintaining performance on par with full-precision global Lion and AdamW across vision (ImageNet) and language (GPT-2++, LLaMA) tasks, making it practically relevant for bandwidth-constrained multi-node training. The method is orthogonal to existing gradient compression techniques, opening a path for combining both for further gains. A key open question is the inconsistent performance of the averaging vs. majority-vote variants across different tasks and batch sizes, which the authors flag as needing deeper understanding. The theoretical convergence guarantees, particularly the O(1/√N) rate for majority vote matching global Lion, provide a principled foundation for when and why the method works.
