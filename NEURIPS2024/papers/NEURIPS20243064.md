## Problem

Convolutions are significantly harder to analyze than dense layers due to their complex hyperparameters (stride, padding, dilation, channel groups) and the absence of compact matrix notation, causing a measurable delay in transferring theoretical and algorithmic ideas from MLPs to CNNs (e.g., KFAC appeared one year later for convolutions). This complexity makes implementing and modifying second-order methods like KFAC for convolutions tedious, with existing code being closed-source, written in low-level languages, or supporting only special hyperparameter configurations.

## Input / Output

The method takes standard convolution inputs (activation tensor X, kernel W, hyperparameters K/S/P/D, optional bias) and produces outputs as einsum contraction strings that can be evaluated with opt_einsum. The key structural element is the index pattern tensor Π, a binary tensor encoding which input positions overlap with kernel positions for each output location, which is cheap to precompute and cache. All derived operations—forward pass, VJPs, Kronecker factors, Hessian diagonals, and transpose-unfolded inputs—support batching, channel groups, and arbitrary spatial dimensions through a unified einsum syntax.

## Method

The core technique represents convolutions as tensor networks using an index pattern tensor Π that explicitly encodes the connectivity between input, output, and kernel positions. Differentiation is performed by a simple graphical manipulation: cutting out the target tensor from the diagram and replacing it with a Kronecker delta, which yields Jacobians and VJPs as new TNs without relying on flattening conventions. Convolution-specific symbolic simplifications exploit structural properties of Π: dense convolutions (K=S, P=0, D=1) reduce to cheap reshapes, down-sampling convolutions (S>K) reduce to sub-tensor contractions, and a kernel-output dimension swap transforms certain operations into standard convolutions. These simplified TNs are evaluated via einsum with opt_einsum for automatic contraction order optimization, avoiding explicit materialization of the unfolded input (im2col). For KFAC-reduce, this eliminates the memory overhead of input unfolding, achieving up to 4.5× speedup and 3 GiB memory savings on real CNNs, and enables new capabilities including KFAC for transpose convolution and hardware-efficient tensor dropout for randomized backpropagation via column-row-sampling.

## Results

The TN implementation of KFAC-reduce achieves speed-ups up to ~4.5× over the standard PyTorch (im2col-based) implementation, with peak memory savings up to 3 GiB. When applied to the SINGD optimizer on ResNet18 and VGG19 (batch size 128, ImageNet-like 325×6256 data), SINGD+TN halves SINGD's per-iteration time (0.16 s vs. 0.19 s on ResNet18; 0.80 s vs. 1.0 s on VGG19) and nearly eliminates the memory overhead relative to SGD (3.6 GiB vs. 4.5 GiB on ResNet18; 16 GiB vs. 32 GiB on VGG19). For randomized backpropagation, spatial sub-sampling via column-row-sampling achieves the same gradient approximation quality as channel sub-sampling while retaining only 35% of pixels versus 75% of channels.

## Baselines & Comparisons

The paper compares its TN-based einsum implementation against the standard PyTorch implementation (which relies on explicit input unfolding / im2col) across 9 CNN architectures. For the most common operations (forward pass, input VJP), the TN implementation matches PyTorch's highly optimized kernels (median ratio ≈ 1), while for less common operations (weight VJP, KFC, KFAC-reduce) it consistently outperforms the standard implementation, with KFAC-reduce achieving the largest gains (down to 0.22× runtime, i.e. ~4.5× speedup). In the downstream SINGD benchmark, SINGD+TN reduces the per-iteration overhead from 1.7× (ResNet18) / 1.5× (VGG19) to 1.3× / 1.2× relative to SGD, and cuts peak memory from 4.5 GiB / 32 GiB to 3.6 GiB / 16 GiB, effectively matching SGD's memory footprint. The paper also compares channel sub-sampling vs. spatial sub-sampling for randomized backpropagation on All-CNN-C (CIFAR-100): at the same memory budget, spatial sampling yields a smaller normalized gradient residual, achieving equivalent approximation quality with only 35% of pixels versus 75% of channels.

## Relation to Prior Work

This paper builds on the tensor network representation of convolution from Hayashi et al. [29], who focused on connecting kernel factorizations to structured convolutions, and extends it systematically to all convolution-related operations: autodiff (Jacobian, VJP, JVP), Kronecker-factored curvature (KFC/KFAC-expand from Grosse & Martens [27], KFAC-reduce from Eschenhagen et al. [23]), and Hessian diagonal approximations. The key departure is treating the index pattern tensor Π as a first-class object that enables convolution-specific symbolic simplifications (dense, down-sampling, kernel-output swap) before evaluation, rather than relying on generic contraction path optimization alone. The paper also draws on the quantum simulation community's contraction order optimizers (opt_einsum, cotengra) and column-row-sampling for stochastic approximation, repurposing them for neural network training.

## Why It Matters / Open Questions

The TN/einsum framework reduces the long-standing complexity gap between MLPs and CNNs for deriving and implementing second-order methods, enabling KFAC for transpose convolution (previously unavailable) and eliminating the memory overhead of explicit im2col in Kronecker factor computation. The 4.5× speedup and up to 3 GiB memory savings for KFAC-reduce make second-order optimizers like SINGD more practical for larger batches and more frequent pre-conditioner updates. Limitations include the absence of common sub-expression elimination and index slicing in the current implementation, and the simplifications only apply to structured connectivity patterns (dense, down-sampling) common in modern CNNs but not all convolutions. Open questions include whether integrating CSE into contraction path optimization and extending to 3D convolutions or other architectures (transformers, GNNs) would yield further gains.
