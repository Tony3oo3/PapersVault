## Problem

Existing data agent benchmarks focus on isolated stages (text-to-SQL, pandas code generation) or daily-life GUI tasks, leaving a gap for evaluating agents on the full data science and engineering pipeline that spans enterprise applications like BigQuery, dbt, Airbyte, and Airflow. No prior benchmark integrates both code writing and intensive GUI controls within a real-time executable computer environment connected to authentic cloud services, making it impossible to measure whether multimodal agents can actually automate professional data workflows.

## Input / Output

The agent receives a natural language task instruction (abstract or verbose step-by-step) plus real-time observations from a live Ubuntu VM: an RGB screenshot of the desktop and a text-format accessibility tree (a11ytree) describing element positions, types, and embedded text. These are optionally aligned via Set-of-Mark (numeric bounding-box indexes drawn on the screenshot matching a11ytree rows) and augmented with RAG-retrieved document segments (top-4 chunks of 512 tokens from 11,231 crawled pages). The agent outputs executable pyautogui Python code or a JSON dict action (e.g., CLICK, TYPE, HOTKEY) per turn, up to 15 interaction turns. Task success is determined by 151 task-specific evaluation scripts that inspect the final VM state via file comparison, API queries, or execution-based verification, returning a binary 0/1 flag.

## Method

Spider2-V formalizes the agent as a POMDP over a virtual machine environment adapted from OSWorld, where 170 automatic setup configurations reset the initial state (file transfer, app launch, remote API calls, script execution, Playwright automation) and 151 evaluation scripts verify completion. The agent baseline operates in zero-shot with three key techniques: (1) Set-of-Mark observation alignment, which extracts element coordinates from the a11ytree, draws indexed bounding boxes on the screenshot, and inserts matching index columns into a tabular a11ytree representation to bridge the modality gap; (2) execution feedback, which appends Python traceback messages for actions that fail to ground in the environment, preventing the agent from repeating identical errors; and (3) retrieval-augmented generation over a document warehouse of 11,231 pre-processed pages (pure text, simplified HTML, markdown) from official software documentation, using bge-large-en-v1.5 embeddings and LlamaIndex with top-4 retrieval. The benchmark spans 494 tasks across 7 categories and 20 professional applications, with 34% requiring authentic cloud accounts, and is evaluated on GPT-4o, GPT-4V, Gemini-Pro-1.5, Claude-3-Opus, Qwen-Max, Llama-3-70B, and Mixtral-8x7B, revealing that even the best VLM achieves only 14.0% overall success rate.

## Results

On Spider2-V, the best-performing VLM (GPT-4V) achieves only 14.0% overall success rate, with GPT-4o close behind at 13.8%. Closed-source VLMs (Gemini-Pro-1.5 at 9.1%, Claude-3-Opus at 8.1%) substantially outperform open-source LLMs, all of which score below 2% (Mixtral-8x7B: 0.8%, Llama-3-70B: 2.0%, Qwen-Max: 0.6%). Even with oracle step-by-step verbose instructions, overall success rate rises only to 16.2%, and for the hardest subset (>15 action steps), performance collapses to 1.2%.

## Baselines & Comparisons

GPT-4V leads all baselines with 14.0% overall success, narrowly ahead of GPT-4o (13.8%), while Gemini-Pro-1.5 (9.1%) and Claude-3-Opus (8.1%) trail by roughly 5 percentage points. The gap between closed-source VLMs and open-source LLMs is stark: Llama-3-70B (2.0%), Mixtral-8x7B (0.8%), and Qwen-Max (0.6%) all fall below 2%, with several task categories scoring exactly zero. GPT-4V's advantage is most pronounced in data warehousing (10.8% vs. 3.6% for Gemini) and data visualization (25.0% vs. 15.0% for Gemini/Claude), while GPT-4o dominates in data ingestion (24.0%) and orchestration (19.8%). All models struggle most with data transformation (≤10.0%) and traditional data processing (≤10.1%), indicating that fine-grained GUI control and spreadsheet manipulation remain unsolved across the board.

## Relation to Prior Work

Spider2-V adapts the executable computer environment from OSWorld [37] and extends it to the data science and engineering domain, integrating 20 enterprise applications (BigQuery, dbt, Airbyte, Airflow, Dagster, Snowflake, etc.) that prior data-science benchmarks (Spider, DS-1000, Arcade) entirely omitted. It also departs from GUI-agent benchmarks (Mind2Web, WebArena, AndroidWorld) by targeting professional, domain-specific software rather than general web or mobile interfaces, and by requiring both code writing and fine-grained GUI manipulation within a single task. The agent baseline combines Set-of-Mark prompting [39] for cross-modal alignment, execution feedback [30], and retrieval-augmented generation over a purpose-built document warehouse of 11,231 pages of official software documentation.

## Why It Matters / Open Questions

The benchmark exposes a critical gap: even the strongest VLM (GPT-4V) achieves only 14.0% success, and the finding that oracle step-by-step plans lift performance to merely 16.2% reveals that the bottleneck is action grounding (pixel-level element localization) rather than high-level planning—a conceptual insight that redirects research effort. Open questions include improving interaction efficiency (prompt length and API cost grow rapidly with history), handling the instability of cloud-hosted enterprise services, and scaling annotation beyond the current 10-expert pipeline. As a 494-task, 20-application benchmark with a real-time executable environment and 151 custom evaluation scripts, Spider2-V is likely to become a standard reference for evaluating multimodal agents on professional data workflows.
