## Problem

Existing GUI automation benchmarks predominantly evaluate models on simple tasks specified by a single text instruction (e.g., "Insert a new slide"), failing to capture the visual-centric, multi-step procedures that real users actually struggle with in professional software like Adobe Premiere Pro or Stable Diffusion. VideoGUI addresses this gap by introducing a benchmark derived from high-quality instructional videos that requires models to perform complex, visual-driven GUI tasks across 11 professional applications, where the primary query modality is a visual preview rather than a text description.

## Input / Output

The primary evaluation setting provides only a visual preview (e.g., before/after screenshots or animation frames) without any textual description, requiring the model to reverse-engineer the procedure purely from visual cues; an optional text query can supplement this. Outputs are structured hierarchically: high-level plans are concise milestone lists, mid-level plans are ordered action narrations (e.g., "Click on Insert → Click on 3D Models"), and atomic actions are concrete coordinates [x,y] for clicks, [x1,y1]→[x2,y2] for drags, exact keystroke sequences for typing, or scroll direction decisions. Planning outputs are scored 0–5 by an LLM critic, while atomic actions use adaptive normalized pixel distance and recall@100 thresholds.

## Method

VideoGUI constructs its benchmark by having human participants watch selected YouTube instructional videos and replicate the demonstrated effects in a simulated environment that records all cursor and keyboard activities (click, drag, type/press, scroll) with pixel-level coordinates, followed by manual annotation of active UI elements and cross-validation. The core technical contribution is a three-level hierarchical evaluation: (i) high-level planning reconstructs procedural subtasks from visual conditions, (ii) middle-level planning generates precise action narration sequences from a screenshot and goal, and (iii) atomic action execution performs specific operations like clicking designated elements. Each level uses tailored metrics—LLM-as-judge scoring (GPT-4-Turbo) for open-ended planning, adaptive normalized distance (pixel difference divided by farthest-vertex distance) and recall@100 for click/drag, sandbox code execution with keyboard monitoring for type/press, and shuffled multiple-choice accuracy for scroll. The benchmark comprises 86 full tasks (averaging 22.7 actions), 463 subtasks, and 2,712 annotated atomic actions across Windows and web-based professional software.

## Results

On VideoGUI, GPT-4o achieves the highest overall score of 39.4%, with 17.1% on high-level planning (visual query), 53.5% on middle-level planning, and 47.6% on atomic action execution. Even the best model fails to complete a single full task in the simulator (0% success rate), with the bottleneck identified as high-level planning rather than action execution. Vision-only planning is dramatically harder than text-only planning across all models (average 0.49 vs. 2.37 on a 0–5 scale), and adding OCR or SoM tools boosts GPT-4o's action score by ~9–11 points (47.6 → 56.3 with OCR).

## Baselines & Comparisons

GPT-4o outperforms all other evaluated models on every VideoGUI dimension, leading GPT-4-Turbo by 5.5 points overall (39.4 vs. 33.9) and Claude-3-Opus by 7.8 points (39.4 vs. 31.6). Among text-only LLMs, GPT-3.5-Turbo (23.8 overall) edges out LLama3-70B (20.3) and Mixtral-8x22B (18.6) on middle-level planning, but none can perform high-level visual planning. CogAgent, despite being purpose-built for GUI grounding, scores lowest overall (11.2) due to weak planning (4.4 high-level) and poor action execution (7.4), trailing GPT-4o by 28.2 points. Gemini-Pro-V (20.1) and Qwen-VL-Max (23.2) are mid-tier, with Qwen-VL-Max benefiting from stronger action execution (28.9) but weaker planning. Equipping GPT-4o with OCR yields the best overall score (42.3), improving action execution from 47.6 to 56.3, while SoM provides a smaller gain (54.3), confirming that text-based localization via OCR is more effective than segmentation-based SoM for GUI element grounding.

## Relation to Prior Work

This paper departs from existing GUI automation benchmarks (Mind2Web, OSWorld, AITW, AssistGUI) that focus on simpler tasks specifiable by a single text instruction, by introducing VideoGUI—a benchmark sourced from instructional videos targeting professional creative software (Adobe Photoshop, Premiere Pro, Stable Diffusion, Runway) and complex multi-step procedures averaging 22.7 actions. Conceptually, it repurposes the abundant corpus of web tutorial videos as a data source for GUI task construction, a strategy only lightly explored by AssistGUI, and extends the evaluation paradigm from a single boolean success metric to a three-level hierarchical decomposition (high-level planning → middle-level planning → atomic action execution) with per-dimension metrics. The work also sits at the intersection of multimodal agent research (CogAgent, Ferret-UI) and training-free agent systems (SoM, OCR-augmented LLMs), providing a unified testbed for both families.

## Why It Matters / Open Questions

The benchmark reveals that even GPT-4o achieves 0% full-task success rate and that the primary bottleneck is visual-centric planning (especially high-level planning from visual previews, averaging only 0.49/5 across models) rather than atomic action execution, a finding that redirects research attention toward improving procedural reasoning from visual state. The hierarchical evaluation framework provides actionable diagnostic signals—identifying whether a model fails at planning, narration generation, or grounding—that a single success/failure metric cannot offer. Limitations include the relatively small scale (86 full tasks), reliance on GPT-4-Turbo as an LLM judge for planning scores, Windows-centric coverage, and the need for human validation of full-task success. Open questions include whether cross-platform and cross-software generalization is feasible, how to automate success-rate evaluation, and whether diverse planning annotations from multiple annotators would reduce evaluation subjectivity.
