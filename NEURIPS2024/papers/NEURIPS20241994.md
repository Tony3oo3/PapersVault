## Problem

Deep-learned SAT generation methods face a fundamental trade-off: fast generators (W2SAT, G2MILP) produce instances that suffer hardness collapse, while the only method that preserves hardness (HardSATGEN) requires ~2 hours per instance, making large-scale data augmentation infeasible. The bottleneck is core detection—identifying the minimally unsatisfiable subset that drives problem hardness—which traditionally requires solving the SAT problem and is NP-complete.

## Input / Output

The method takes an UNSAT CNF seed instance (represented as a Literal-Clause Graph with clause nodes, literal nodes, and directed edges for literal-clause incidence plus undirected edges connecting negated literal pairs) and generates new hard UNSAT instances by adding random clauses via a Popularity-Similarity sampler, then iteratively refining cores. The GNN core predictor outputs a binary core-membership probability per clause node (thresholded at 0.5), while the full pipeline outputs complete CNF files whose solver runtimes should match the original distribution. The GNN is trained on instance-core pairs bootstrapped from Drat-Trim on a small set of seeds (15 problems × 200 refinement iterations = 15,000 pairs).

## Method

HardCore's core mechanism is an iterative Core Refinement loop: after adding random clauses to a seed (which risks creating trivial easy cores), a GNN-based core detector identifies the current core, and a single non-conflicted literal is added to a randomly selected core clause to render it satisfiable (de-coring), forcing the solver to rely on a larger, harder core. The GNN uses three parallel message-passing neural networks—one per edge type (clause→literal, literal→clause, literal↔literal for negation pairs)—whose embeddings are averaged at each layer, with a sigmoid readout on clause nodes for binary classification. Training is supervised with binary cross-entropy on pairs generated by running the slow but exact Drat-Trim detector during a bootstrap phase, solving the data-scarcity problem by generating its own training data. The original instance's core is explicitly preserved in the generated output, guaranteeing an underlying hard core that refinement progressively exposes by whittling away easier cores.

## Results

On the LEC Internal dataset, HardCore generates instances with 176% of the original hardness at 4.3 seconds per instance, achieving a Maximum Mean Discrepancy (MMD) of 0.004 between generated and original runtime distributions. In the data augmentation experiment, training a SATzilla runtime-predictor on HardCore-augmented data reduces mean absolute error (MAE) by 20–50% compared to training on original data alone (e.g., MAE drops from 606 to 282 at 400 training instances on LEC). No other generation method yields a statistically significant improvement over the un-augmented baseline.

## Baselines & Comparisons

Against HardSATGEN (Li et al., 2023), HardCore is approximately 1,500× faster (4.3 s vs. 6,441 s per instance) and produces runtime distributions far closer to the original (MMD 0.004 vs. 0.492), though HardSATGEN generates slightly harder instances (267% vs. 176% of original hardness). Against W2SAT (Wen and Yu, 2023) and G2MILP (Geng et al., 2023), HardCore achieves comparable generation speed (4.3 s vs. 1.2 s and 3.3 s respectively) but completely avoids the hardness collapse that reduces both baselines to ~0% of original difficulty. In the data augmentation task (Table 2), HardCore is the only method that produces a statistically significant MAE reduction across all data sizes on both LEC Internal and K-SAT Random, while HardSATGEN-Strict, HardSATGEN-N, and W2SAT show no consistent improvement over the un-augmented original data.

## Relation to Prior Work

This paper builds directly on HardSATGEN (Li et al., 2023), the first deep-learned SAT generator capable of preserving hardness, by adopting its Popularity-Similarity random clause generation and core-awareness philosophy while replacing its prohibitively expensive split-merge architecture with a lightweight iterative refinement loop. It also repurposes the GNN-based core prediction idea from Neurocore (Selsam and Bjørner, 2019), but rephrases the task from variable-level to clause-level binary classification, which is more natural given that cores are defined over clauses. The key departure is substituting the NP-complete Drat-Trim core detection (which requires a full SAT solve) with a fast graph neural network trained on self-generated supervision, enabling core detection in milliseconds rather than hundreds of seconds.

## Why It Matters / Open Questions

The method closes a critical practical gap: prior generators either collapsed hardness to near-zero (W2SAT, G2MILP) or required ~2 hours per instance (HardSATGEN), making large-scale data augmentation infeasible. By achieving a 1500× speedup while maintaining or exceeding original hardness, HardCore makes it practical to generate thousands of hard instances in hours, enabling meaningful data augmentation for solver runtime prediction (20–50% MAE reduction). Key limitations include restriction to UNSAT problems only (cores do not exist in SAT instances), dependence on a proprietary circuit-design dataset for primary evaluation, and polynomial memory scaling that limits applicability to very large instances. An open direction is extending the approach to satisfiable problems via backbone preservation.
