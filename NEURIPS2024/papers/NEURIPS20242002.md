## Problem

Using large pretrained models as data annotators is prohibitively expensive (e.g., over $1,200 to label a single 7,569-point dataset via GPT-4), produces static labels that cannot be easily modified when specifications change, and offers no auditability into how individual labels were generated. This paper asks whether the labeling logic of a powerful model can be distilled into executable code rather than into per-point labels, thereby decoupling annotation cost from dataset size.

## Input / Output

The system takes an unlabeled dataset and a short prompt template (task description, class definitions, function signature), optionally augmented with supplementary information such as dataset descriptions, labeled exemplars, keywords, or domain-specific labeling rules. For non-text modalities, a local feature extractor (e.g., CLIP) first converts raw inputs into low-dimensional concept-based similarity scores that the generated programs consume as numerical inputs. The output is a small set of Python labeling functions (typically 10) whose outputs are aggregated via weak supervision into pseudolabels, which then train a two-layer MLP distilled classifier; the programs themselves are reusable, inspectable, and extensible artifacts that can be re-run locally at zero marginal cost.

## Method

Rather than querying an LLM per data point, Alchemist prompts the LLM to synthesize Python functions that encode labeling logic such as regex patterns, keyword matching, and heuristic thresholds. Multiple programs are generated by varying the supplementary information in the prompt (dataset descriptions, exemplars, keywords, labeling rules), producing diverse labeling strategies whose noisy outputs are aggregated using the Snorkel weak supervision framework to learn program reliabilities and combine them into high-quality pseudolabels. For non-text modalities, a two-step extension first asks a multimodal LLM to identify task-relevant concepts (e.g., 'wing shape,' 'foot type'), then uses a free local model (CLIP) to compute similarity scores for those concepts, which the generated programs operate on as numerical inputs. The resulting pseudolabels train a small distilled MLP that can be deployed locally, reducing total labeling costs by approximately 500× while improving accuracy on five of eight text datasets by an average of 12.9%.

## Results

On 8 text classification datasets, Alchemist (using GPT-3.5 to generate 10 programs + Snorkel aggregation) improves accuracy on 5 of 8 datasets over zero-shot LLM prompting, with an average enhancement of 12.9%. The most dramatic gains appear on domain-expertise tasks: Cancer (0.968 vs. 0.716 accuracy), MedAbs (0.346 vs. 0.311), and French (0.690 vs. 0.611). Total labeling cost drops by approximately 500× (e.g., Cancer: $0.003 vs. $15.925; YouTube: $0.004 vs. $0.096). On the Waterbirds image dataset, Alchemist with CLIP feature extraction achieves comparable average accuracy to zero-shot CLIP while substantially improving worst-group accuracy (e.g., 0.467 vs. 0.335 with CLIP ViT-L/14) and reducing the accuracy gap.

## Baselines & Comparisons

The primary baseline is zero-shot LLM prompting, where each data point is individually queried via API. Alchemist wins on 5 of 8 text datasets (YouTube, MedAbs, Cancer, Finance, French) and loses on 3 (SMS, Yelp, IMDb), yielding a net average improvement of 12.9% while reducing cost by ~500×. The largest single-dataset gain is on Cancer (+25.2 pp accuracy at 1/5,300th the cost). Against WRENCH's human-crafted labeling functions, Alchemist matches or exceeds performance with far fewer programs: on SMS, 10 synthesized programs achieve 0.90 F1 with 1.00 coverage versus 73 hand-written functions achieving 0.89 F1 with only 0.41 coverage. On YouTube, Yelp, and IMDb, synthesized programs also reach comparable or better accuracy with higher coverage than the human-crafted baselines, demonstrating that LLM-generated programs can replace laborious manual labeling-function design.

## Relation to Prior Work

This paper builds on the weak supervision framework (Snorkel) for aggregating noisy labeling signals, but departs from prior LLM-annotation work by prompting models to generate executable labeling programs rather than per-point labels. It is conceptually closest to ScriptoriumWS and DataSculpt, which also use code-generating models for weak supervision, but distinguishes itself by requiring less human prompt engineering, handling domain-specific tasks more effectively, and extending to non-text modalities via a CLIP-based feature extraction step. The RoboShot robustification technique is integrated as an optional extension to mitigate spurious correlations in image classification.

## Why It Matters / Open Questions

The 500× cost reduction (e.g., $1,200 → $0.70 on one dataset) makes large-scale annotation economically viable in settings where per-point API calls are prohibitive, and the resulting programs are auditable, extensible, and reusable—addressing practical barriers to LLM-based annotation in privacy-sensitive domains like healthcare and finance. Key limitations include dependence on the underlying LLM's code-generation quality and the difficulty of validating increasingly complex generated programs for harder tasks. Open questions include whether the approach scales to tasks requiring multi-step reasoning or where labeling logic cannot be captured in a short program, and how to systematically detect and correct biased labeling logic in synthesized code.
