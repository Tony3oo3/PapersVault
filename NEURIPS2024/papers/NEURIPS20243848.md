## Problem

Existing deep learning-based vulnerability detection methods employ a uniform feature learning pattern across the entire target codebase, making them insensitive to the distinct vulnerability patterns that arise in different functional modules or vulnerability subtypes. When a generalized model is applied to a specific scope (e.g., the net module for CWE-416 or CWE-125 subtypes), detection of fine-grained vulnerability patterns degrades significantly, and transfer learning struggles due to domain gaps and limited target data.

## Input / Output

The method takes C/C++ source code as input, which is parsed into per-function Code Property Graphs (CPGs) via Joern, with node features formed by concatenating one-hot encoded operation types, one-hot encoded function-call/field-type indicators, and Word2Vec semantic vectors. Task-specific vulnerability knowledge (sensitive functions, vulnerable operations, module-specific patterns) is extracted as a knowledge subgraph by masking CPG nodes unrelated to the target task. The output is a binary function-level vulnerability label plus statement-level localization identifying which specific code statements drive the vulnerability decision, obtained through the self-attention scores of the SAGPool layer.

## Method

KF-GVD builds on a two-layer GCN followed by SAGPool (self-attention graph pooling) and a classification head, but introduces a task-oriented knowledge fusion layer between the GCN and attention stages. For nodes belonging to the knowledge subgraph, their representations are replaced by a weighted fusion (α·h_vj + β·h_vq) with the knowledge subgraph node features, while non-knowledge nodes pass through unchanged. Training proceeds in two phases: first, the model is trained on a large source-task dataset (e.g., all CWE-119 vulnerabilities across 13 projects) to learn general patterns; then, for a target subtask, only the misclassified samples from the source model undergo knowledge fusion during fine-tuning, treating them as the subset where the general model has understanding bias. A combined loss function jointly optimizes function-level classification and node-level statement labels, enabling both detection and fine-grained localization in a single forward pass.

## Results

On the source task S_119, KF-GVD achieves 82.9% precision, 90.9% recall, and 86.7% F1. On target tasks, KF-GVD reaches up to 95.7% F1 (T_m119/Fs module) and 82.1% F1 (T_sub/CWE-787), outperforming the best baseline by an average of 22.6% in F1-score across all target sub-tasks. The paper reports an average precision increase of 40.9% and recall increase of 26.1% over SOTAs on function-level detection. In a real-world case study on C/C++ open-source projects without ground truth, KF-GVD identified 9 previously undisclosed vulnerabilities (confirmed via CNNVD).

## Baselines & Comparisons

KF-GVD consistently outperforms all 10 baselines across every target task sub-module. Against the strongest GNN baselines (IVDetect, ReGVD, Devign), KF-GVD achieves F1 gains of 22.6% on average; for example, on T_m119/Fs, KF-GVD reaches 95.7% F1 versus IVDetect's 38.9% and ReGVD's 43.8%. The fine-tuning ablation (GVD-ft), which uses the same GNN architecture without knowledge fusion, trails KF-GVD by 23.3% F1 on T_m119, 31.6% on T_m416, and 15.7% on T_sub, confirming that knowledge fusion—not merely fine-tuning—drives the gains. Rule-based tools (Cppcheck, Flawfinder) and classical DL methods (Sysver, VulCNN) lag substantially, with LSTM/CNN approaches averaging 20.6% lower F1 than GNN-based methods. Large code models (Codebert, CodeLlama, Wizardcoder) underperform KF-GVD by 33–34% F1 on target tasks, attributed to their focus on generative rather than classification tasks. On the source task itself, KF-GVD matches GVD-ft exactly (86.7% F1 on S_119), confirming that knowledge fusion does not degrade general-purpose detection capability.

## Relation to Prior Work

This paper extends the GNN-based vulnerability detection lineage (Devign, ReGVD, IVDetect) by introducing a task-oriented knowledge fusion layer that injects domain-specific vulnerability knowledge (sensitive functions, vulnerable operations, module-specific patterns) into the graph feature learning process. It builds on SAGPool's self-attention graph pooling for both representation and interpretability, but departs from prior work by selectively modifying node representations only for nodes in a task-relevant knowledge subgraph, rather than applying uniform feature learning across the entire code graph. The paper explicitly contrasts its approach with transfer learning and fine-tuning (GVD-ft), arguing that both fail to adequately capture target-specific vulnerability patterns due to domain gaps and insufficient pattern correction.

## Why It Matters / Open Questions

The paper addresses a practical gap: general-purpose VD models lose significant effectiveness when deployed on specific functional modules or vulnerability subtypes, a problem that burdens real-world code auditing. The knowledge fusion mechanism is lightweight (affecting only 30–50% of training samples) and preserves source-task generalization, making it a practical middle ground between full retraining and no adaptation. Key limitations include restriction to C/C++ and function-level scope (no cross-function or cross-file vulnerabilities), manual curation of vulnerability knowledge, and CPG generation consuming over 75% of processing time. Open questions include whether the approach generalizes to other languages, whether knowledge extraction can be automated, and whether the method scales to cross-function vulnerability patterns.
