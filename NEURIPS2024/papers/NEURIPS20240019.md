## Problem

LLM-based agents for grounded environments typically require elaborate expert prompts and domain-specific instructions, limiting their adaptability to new settings. Existing self-improvement methods (e.g., Reflexion, Voyager, ExpeL) save successful trajectories as skills or extract rules offline, but these approaches suffer from Path Dependency—blindly replicating prior success paths—and distributional shift, respectively—failing to generalize to novel scenarios with high variability.

## Input / Output

The system takes a single simple human demonstration (e.g., one 'Put' task on ALFWorld), the permissible action API, and an interactive text environment modeled as a POMDP, and produces a human-readable Markdown instruction manual alongside a structured rule set where each rule carries four attributes: Type (one of six categories), Content, Example (with error-prone details), and Validation Logs. During the building stage, the Planner outputs free-form Python code blocks (not fixed function-form) as actionable plans, which are executed in the environment and return text observations plus a binary success/failure reward at episode end.

## Method

AutoManual frames environmental rule learning as an online optimization problem analogous to policy gradient, but replaces parameter updates with text-based rule management through an alternating Planner–Builder loop. The Planner writes free-form Python code conditioned on current rules and retrieved skills/reflections, while the Builder updates a structured rule system (six rule types) using a case-conditioned prompting strategy that first classifies trajectory errors as 'Imperfect Rules' vs. 'Imperfect Agents' before directing targeted rule updates, thereby mitigating LLM hallucinations. A Consolidator agent merges or deletes redundant rules when the rule count exceeds a threshold, and a Formulator agent categorizes and compiles all rules into a comprehensive Markdown manual. The key architectural distinction from prior work is the use of free-form code (rather than action sequences or function-form programs) for interaction, which enables richer in-plan feedback and more generalizable skill extraction, combined with the online verification of rules against live environment feedback.

## Results

On ALFWorld, AutoManual achieves 97.4% overall success rate with GPT-4-turbo and 86.2% with GPT-3.5-turbo, using only one human demonstration. On MiniWoB++ (all 53 task types), it reaches 98.3% (GPT-4-turbo) and 92.7% (GPT-3.5-turbo). On WebArena (Reddit domain), AutoManual attains 65.1% success rate, outperforming the strongest baseline SteP (55.0%) by 10.1 points. The ablation study shows the full pipeline (online rules + skill/reflection libraries + case-conditioned prompts + formulation) reduces average error steps from 2.3 to 0.3.

## Baselines & Comparisons

AutoManual outperforms all baselines across every benchmark. On ALFWorld with GPT-4-turbo, it surpasses Reflexion (85.9%) by 11.5 points, ExpeL (79.2%) by 18.2 points, AdaPlanner (76.4%) by 21.0 points, and ReAct (76.8%) by 20.6 points, while using only 1 human example versus 6–12 for baselines. The closest competitor is Planner+Lib. (88.1%), which shares the same skill/reflection library but lacks the structured rule system; AutoManual's advantage is most pronounced on the 'Put Two' task (90.2% vs. 39.2%), where diverse sub-scenarios expose the Path Dependency problem of skill-only approaches. On MiniWoB++ (53 types, GPT-4-turbo), AutoManual (98.3%) beats AdaPlanner (90.3%) by 8.0 points and RCI (88.6%) by 9.7 points. On WebArena Reddit, AutoManual (65.1%) exceeds SteP (55.0%) by 10.1 points and AutoGuide (43.7%) by 21.4 points, again with only 1 example versus 14–19 for baselines.

## Relation to Prior Work

AutoManual extends the code-as-policy paradigm from AdaPlanner and Voyager by replacing their function-form outputs with free-form code, and by extracting structured rules (rather than storing raw skills) from interaction trajectories. It departs most sharply from ExpeL and AutoGuide, which extract rules offline from Reflexion-style action sequences, by introducing an online alternating loop where a Planner practices rules and a Builder updates them in response to immediate environmental feedback. The case-conditioned prompting strategy and the six-type, four-attribute rule system are novel mechanisms that address hallucination in rule management and the Path Dependency problem identified as a limitation of skill-library approaches (Voyager, AdaPlanner).

## Why It Matters / Open Questions

The framework demonstrates that a single human demonstration suffices to bootstrap a comprehensive, human-readable instruction manual that transfers to smaller LLMs (GPT-3.5-turbo achieves 86.2% on ALFWorld), reducing the expert-knowledge bottleneck in deploying LLM agents to new domains. Key limitations remain: the method relies heavily on GPT-4-turbo for rule generation, all rules must fit in context (limiting scalability to large environments), exploration is limited to exploitation of current knowledge, and the Planner does not always adhere to the generated rules. Open questions include integrating retrieval-augmented rule selection for large environments, adding curiosity-driven exploration, and developing enforcement mechanisms for rule compliance.
