key_contribution: Proposes Lumen, a large multimodal model that decouples vision-centric task learning into a task-agnostic dense vision-language alignment stage (producing a shared 32×32 heatmap via a V-L dense aligner) and a task-specific lightweight decoding stage (routing the heatmap through peak-point selection, box regression, or SAM prompting), enabling a single 7B model to perform object detection, instance segmentation, pose estimation, visual grounding, and referring segmentation while preserving general VQA capabilities without task-specific dialogue datasets.
limitations: The single [LOC] token design means one heatmap can only reflect areas activated by a single instruction, requiring the model to be run separately for each category in multi-class detection (approximately 5 hours for COCO val on one A100). Additionally, the performance gap with specialist models remains substantial (35.3 AP vs. 43.3 for DETR on COCO detection), and the single-query bottleneck may limit further performance gains compared to DETR-style multi-query approaches.

surprise_factor: The finding that SAM ViT-H/16 at 1024×1024 resolution performs substantially worse (14.5 AP) than CLIP ViT-L/14 at 448×448 (28.4 AP) for dense alignment is a mild counterintuitive result, suggesting that vision-language alignment quality matters more than raw resolution. The zero-shot transfer to object counting is interesting but not deeply surprising given the heatmap's spatial nature. Overall, the results are solid but incremental over other LMM generalists rather than paradigm-shifting.

## Problem

Existing LMMs extend vision-centric capabilities by serializing task outputs (boxes, masks, keypoints) into discrete coordinate tokens for autoregressive generation, which imposes an artificial sequential order on inherently unordered objects and overemphasizes format consistency at the expense of learning underlying visual perception. This paradigm overlooks the distinct inductive biases of different vision tasks and makes it difficult to scale to multi-object tasks like detection and instance segmentation without task-specific data curation.

## Input / Output

The model takes an RGB image (resized to 448×448 for the CLIP ViT-L/14-336 vision encoder) and a text instruction in a unified conversation template (e.g., 'Please find the location of {description}. Respond with {format}'). The intermediate output is a 32×32 matching heatmap where each cell encodes the probability that the corresponding image region matches the instruction. This heatmap is then decoded into task-specific outputs: bounding boxes (K=100 candidates filtered by NMS for detection, K=1 for grounding), segmentation masks (via SAM prompted with the predicted box), or keypoint coordinates (K=1 per keypoint category after top-down cropping).

## Method

Lumen decouples vision-centric learning into two stages. In Stage 1 (task-agnostic matching), all tasks are reformulated into a uniform conversation format with a special [LOC] token; the LLaVA-1.5 backbone processes the image-instruction pair, and a lightweight transformer-based V-L dense aligner interacts the [LOC] token feature with high-resolution image patches to produce a 32×32 heatmap, trained with Gaussian focal loss plus cross-entropy loss via LoRA fine-tuning. In Stage 2 (task-specific decoding), a task token ([DET], [SEG], [POINT]) output in Stage 1 routes the heatmap through predefined pathways: peak point selection (local maxima filtering) feeds either a box decoder (the same aligner extended with [H]/[W] tokens regressing height/width under L1 loss) or directly yields keypoints, and for segmentation the predicted box prompts a frozen SAM mask decoder. This separation lets the model concentrate on fine-grained vision-language alignment without being trapped in learning diverse, semantically thin decoding rules within the LLM token space.

## Results

On COCO val, Lumen-7B achieves 35.3 AP / 53.2 AP50 for object detection, 30.4 AP / 49.8 AP50 for instance segmentation, and 67.2 AP / 90.4 AP50 for pose estimation. For visual grounding on RefCOCOg val, Lumen reaches 83.6 AP50, and for referring segmentation it achieves 65.1 cIoU. On VQA benchmarks, Lumen maintains competitive general understanding (64.9 MMBench, 24.6 MathVista) while adding these vision-centric capabilities. On zero-shot VOC2007 detection, Lumen scores 77.9 AP, surpassing InstructCV by 16.2 AP and approaching specialist models like Faster R-CNN (80.4 AP).

## Baselines & Comparisons

Among LMM generalists, Lumen-7B achieves a 15.6 AP50 gain over Griffon-13B (53.2 vs 37.6) and a 4.7 AP50 gain over InstructCV (53.2 vs 48.5) on COCO detection, while also outperforming Shikra-7B on visual grounding (83.6 vs 82.3 AP50 on RefCOCOg). Against vision generalists, Lumen trails VisionLLM on detection AP50 (53.2 vs 64.0) but surpasses it on instance segmentation AP75 (31.0 vs 22.4), and beats Pix2Seq-v2 on pose estimation by 2.4 AP (67.2 vs 64.8). On pose estimation, Lumen (67.2 AP) is within 1.0 AP of the specialist RTMPose (68.2 AP) and 5.5 AP below CPM (62.7 AP is actually lower—Lumen exceeds CPM). For referring segmentation, Lumen (65.1 cIoU on RefCOCOg) is competitive with specialist ReLA (65.0) and LISA (66.4) despite using no pixel-level supervision during training. On zero-shot VOC2007 generalization, Lumen (77.9 AP) outperforms InstructCV by 16.2 AP and approaches Faster R-CNN (80.4 AP) trained directly on VOC. On VQA benchmarks, Lumen matches or slightly exceeds LLaVA-v1.5 (64.9 vs 64.3 MMBench, 24.6 vs 23.5 MathVista) while being slightly behind on MME (1426 vs 1511), confirming that the vision-centric training does not degrade general instruction-following.

## Relation to Prior Work

This paper builds on LLaVA-1.5 as the base LMM and adopts the Gaussian heatmap regression formulation from Objects as Points (Zhou et al., 2019) for dense vision-language alignment. It departs from prior LMM-based vision-centric approaches (Griffon, Kosmos-2, MiniGPT-v2, Qwen-VL) that serialize bounding box coordinates into discrete token sequences for autoregressive generation, arguing that this format imposes an artificial sequential order on inherently unordered spatial outputs. Conceptually, it bridges the matching-based objectives of vision generalists like Uni-Perceiver with the instruction-following paradigm of LMMs, introducing a V-L dense aligner that produces a shared heatmap representation before routing to lightweight task-specific decoders.

## Why It Matters / Open Questions

The decoupled architecture demonstrates that an LMM can simultaneously handle detection, segmentation, pose estimation, and grounding while preserving general VQA capabilities, without requiring meticulously curated task-specific dialogue datasets. A key limitation is that one heatmap per instruction necessitates running the model separately for each category in multi-class detection, and the performance gap with specialist models remains substantial (35.3 AP vs. 43.3 for DETR on COCO). The zero-shot generalization to object counting without task-specific training suggests the heatmap is a genuinely useful intermediate representation, but open questions remain about scaling to more complex multi-instance scenarios and whether the single [LOC] token bottleneck limits further performance gains.
