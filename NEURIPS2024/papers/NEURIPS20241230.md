## Problem

Translating natural language planning problems into PDDL for use with classical planners requires generating both domain and problem files, but existing approaches rely on human experts to detect and correct domain errors. The fundamental difficulty is that even a single missing predicate argument can cause plan search to fail entirely, yielding zero diagnostic feedback for the LLM to learn from. This paper addresses the gap by developing a fully automated, human-free method that uses environment interaction to iteratively refine LLM-generated PDDL.
![Teaser figure](../imgs/NEURIPS20241230/cropped_page3_idx0.webp)

## Input / Output

The method consumes natural language domain and task descriptions, the environment's object list, and action interface signatures (API calls), and produces a PDDL domain file, PDDL problem file, and a validated action plan from a classical planner (Fast-Downward). Critically, the ground-truth PDDL is never directly accessible—the system only has the environment's executability checker and action interface, making this a black-box setting where the LLM must infer the domain structure purely from interaction feedback. The feedback provided to the LLM is deliberately minimal: a sequence of actions from an exploration walk up to the first failure point, plus a natural language state description.

## Method

The core contribution is the Exploration Walk (EW) metric, which measures domain similarity by sampling random executable action sequences from one domain and checking their executability in another, yielding a smooth 0–1 score that provides incremental feedback even when plan search fails completely. The algorithm generates multiple problem PDDL candidates, then for each iteratively generates domain PDDL candidates, evaluates them via EW score, and feeds natural language feedback (the failed action sequence and state) back to the LLM for refinement over up to 4 conversation turns. A tree-search strategy (P&D Tree) samples n_d=10 domain candidates and n_p=5 problem candidates per level, selecting the best by EW score at each node. The symmetric EW metric uses a harmonic mean of one-sided executability fractions, preventing overly permissive domains (where all actions are allowed) from inflating similarity scores. This eliminates the human-in-the-loop correction that prior work (Guan et al., 2023) required, achieving 66% average task solve rate versus 29% for GPT-4's intrinsic chain-of-thought planning.

## Results

On 10 PDDL environments, the proposed P&D Tree method (n_d=10, n_p=5) achieves an average task solve rate of 66% and average Exploration Walk (EW) score of 0.84, solving 7 out of 10 domains. This substantially outperforms GPT-4's intrinsic chain-of-thought planning (29% solve rate) and the single-attempt P&D Chain baseline (34% solve rate, 0.53 EW score). The P&D Tree+DomProp variant achieves a comparable EW score of 0.85 but a slightly lower solve rate of 60%, with notable per-domain variation (e.g., perfect 1.00 solve on Grippers-ood but 0.00 on Floortile).

## Baselines & Comparisons

The paper compares four baselines: (1) Intrinsic No CoT and (2) Intrinsic CoT, where GPT-4 generates plans directly without PDDL or a classical planner; (3) P&D Chain, the authors' own single-attempt PDDL generation (n_d=1, n_p=1) without iterative refinement; and (4) P&D Tree+DomProp, a variant that first drafts a domain proposal before generating the problem PDDL. P&D Tree (the main method) achieves 66% average solve rate, more than doubling Intrinsic CoT (29%) and nearly doubling P&D Chain (34%). P&D Tree+DomProp achieves a similar EW score (0.85 vs. 0.84) but a lower solve rate (60%), with highly inconsistent per-domain performance (e.g., 1.00 on Grippers-ood but 0.00 on Floortile, where P&D Tree achieves 0.90). Notably, the EW metric provides useful signal even when solve rate is zero: on Barman and Childsnack, P&D Tree reaches EW 1.00 while P&D Chain only reaches 0.93 and 0.57 respectively, indicating the domain is nearly correct but problem translation errors prevent full task completion.

## Relation to Prior Work

This paper extends the LLM+PDDL planning line initiated by Liu et al. (LLM+P) and Guan et al. (LLM World Models), which respectively handle problem-only translation (given a domain) and full domain+problem translation (with human-in-the-loop correction). The key departure is replacing human expert feedback with an automated Exploration Walk (EW) metric that provides smooth, gradient-like signals for domain refinement, drawing on the iterative self-debugging paradigm from Chen et al. and the multi-candidate tree search from Yao et al. (Tree of Thoughts). Unlike Oswald et al., who assume predicates are given, this work generates both predicates and action logic from scratch, making it the first fully automated NL-to-PDDL pipeline for both domain and problem files.

## Why It Matters / Open Questions

By eliminating the human bottleneck in PDDL domain design, this work opens a path toward scalable automated planning for LLM agents in structured environments, where even a single predicate error (e.g., dropping a robot argument from a gripper predicate) can invalidate an entire domain. The EW metric is a practical contribution: it converts the binary 'plan not found' signal into a continuous similarity score, enabling iterative refinement where classical planning provides zero feedback. However, the method still fails on 3/10 domains (Driverlog, Barman, Childsnack), random EW exploration is acknowledged as inefficient, and the framework is untested beyond PDDL environments—leaving open whether more directed exploration strategies (e.g., from RL) or extension to non-PDDL digital/physical environments can close the remaining gap.
