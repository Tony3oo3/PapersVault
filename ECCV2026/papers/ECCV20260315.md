## Problem

Current LMMs lack standardized benchmarks for converting real-world PCB schematic diagrams into machine-readable, spatially weighted netlist graphs that capture component attributes, connectivity, and geometry. Existing datasets (Netlistify, MASALA-CHAI, AMSNet) cover only simplified SPICE-style circuits with 10–45 symbol categories, falling far short of the thousands of component types in practical designs, and none provide spatially weighted netlist annotations or structured graph-matching protocols.
![Teaser figure](../imgs/ECCV20260315/cropped_page1_idx0.webp)

## Input / Output

The benchmark consumes PCB schematic images at 150 DPI in three variants (real EAGLE exports, synthesized with text labels, synthesized without symbol names/values) and, in agentic mode, accepts structured queries that trigger iterative crop/scroll operations. The expected output is a typed heterogeneous graph G = (V^sym ∪ V^pin, E^mem ∪ E^conn) where each connectivity edge carries a spatial weight (normalized Euclidean distance between parent symbol centers) and optional net-name attributes, alongside per-instance bounding boxes, symbol type/name/value, and pin name/pad name annotations.

## Method

OmniSch is built via a source-driven automated pipeline: a custom EDA generative rendering engine parses Autodesk EAGLE XML files, re-simulates native schematic rendering to produce high-fidelity images, and simultaneously exports pixel-aligned annotations at symbol, pin, text, and net-graph granularity, validated by two senior EDA engineers. Evaluation uses a hierarchical graph-matching protocol—global maximum-weight bipartite matching for symbol nodes followed by local pin matching under parent-symbol constraint—with two complementary scoring functions (semantic, using text similarity; structure-aware, using topology and coarse position) and seven task-specific metrics (F1, IoU, Kendall's τ, accuracy, coverage). The empirical study evaluates nine LMMs under zero-shot, few-shot, and instruction-tuned prompting, a YOLO11+PaddleOCR classical vision pipeline, and a ReAct-based agentic framework that lets models iteratively zoom and pan the viewport to refine fine-grained attribute recognition.

## Results

On real-world schematics, the YOLO11-based classical vision pipeline dominates all LMMs, achieving 0.8812 symbol detection F1, 0.9174 pin detection F1, and 0.2114 graph IoU. Among LMMs, Gemini 2.5 Flash leads in symbol detection (F1=0.7057) and net-name coverage (0.5605), while Gemini 3.1 Pro achieves the highest Kendall's τ (0.6438) for spatial layout consistency. However, graph IoU remains below 0.20 for all LMMs, and removing symbol text causes severe degradation (e.g., Gemini 2.5 Flash symbol F1 drops from 0.4516 to 0.3077 on synthesized schematics). Qwen3-VL-235B-A22B returns zero scores across all metrics due to consistently empty structured outputs.

## Baselines & Comparisons

The classical YOLO11+PaddleOCR pipeline outperforms every LMM by a wide margin on detection (0.8812 vs. 0.7057 best symbol F1; 0.9174 vs. 0.4883 best pin F1) and net coverage (0.9451 vs. 0.5605), though its graph IoU (0.2114) is only marginally above the best LMM (Gemini 2.5 Flash, 0.1945). Among LMMs, Gemini 2.5 Flash achieves the strongest symbol detection and net-name coverage on real schematics, while Gemini 3.1 Pro excels in spatial layout consistency (Kendall's τ = 0.6438) but collapses when symbol text is removed (τ drops to 0.0824). Claude Sonnet 4.6 is the most robust to text removal, maintaining 0.5273 symbol F1 without text versus 0.3077 for Gemini 2.5 Flash. GPT-5.2 sits in the mid-tier (0.5461 symbol F1, 0.1064 graph IoU), while LLaMA-4-Maverick-400B and Ministral 14B trail significantly. Qwen3-VL-235B-A22B fails entirely, returning syntactically valid but empty structured outputs for all 1,854 test images, yielding zero scores across every metric.

## Relation to Prior Work

This paper carves new ground at the intersection of LMM visual grounding and EDA workflow automation. Prior schematic-to-netlist benchmarks (AMSNet, Netlistify, MASALA-CHAI, CGHD) focus on simplified SPICE-style circuits with 10–45 symbol categories and lack spatially weighted connectivity or pin-level annotations; OmniSch departs by using real-world Autodesk EAGLE schematics with 3,480 symbol types and a custom EDA rendering engine for automated annotation. Conceptually, it repurposes the agentic visual search paradigm (MM-ReAct, V*, DeepEyes) and structured graph matching (bipartite alignment) for a domain where no standardized LMM evaluation protocol previously existed, while positioning a classical YOLO+OCR+rules pipeline as the practical baseline that LMMs must beat.

## Why It Matters / Open Questions

The benchmark reveals that frontier LMMs still trail a modular YOLO11+PaddleOCR pipeline on end-to-end netlist graph reconstruction, and that topology reasoning (graph IoU, Kendall's τ) remains the dominant bottleneck even when symbol detection is strong. The finding that explicit graph-construction instructions degrade GPT-5.2's performance, and that cross-EDA-tool generalization is poor (Table 5), highlights that current LMMs lack the deterministic, rule-following reliability needed for production EDA. Open questions include whether fine-tuning on OmniSch's 1,854 schematics can close the gap, whether agentic zoom-based search can be made more reliable for pin-level and net-tracing tasks, and whether the spatially weighted graph formulation generalizes to other structured-diagram domains (e.g., floorplans, architectural drawings).
