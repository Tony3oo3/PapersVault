## Problem

VLMs are trained on cloud GPU clusters with one kernel stack and deployed on heterogeneous edge devices with different kernels, yet the security implications of floating-point inconsistencies between these kernels remain unexplored. Existing backdoor attacks on VLMs operate at the model level (data poisoning, weight manipulation), making them detectable during cloud-based model validation. This paper asks whether system-level kernel optimizations can inadvertently transform a benign model into a backdoored one, creating an attack that is invisible under standard validation kernels but activates only on specific target inference kernels.

## Input / Output

The method takes standard RGB images (from Flickr8k or COCO captioning splits) and optionally appends a small 48×48 trigger patch in the bottom-left corner of the image. The output is a generated text caption. Critically, the same input-image pair produces different outputs depending on the execution kernel: under the cloud kernel the model always produces a normal caption regardless of the trigger, while under the target kernel (e.g., TorchInductor, CUDAGraphs, ONNXRT, TVM) the trigger causes the model to emit a predefined malicious target string instead of a natural caption.

## Method

VLMSysTrojan exploits floating-point non-associativity across kernels through a three-stage adversarial procedure. First, it optimizes a trigger patch via gradient descent to maximize the vision encoder's activation magnitude on triggered inputs relative to clean inputs, establishing a separable activation gap. Second, it performs a grid search for a guard-bias vector β that satisfies a four-way separation condition: triggered inputs on the target kernel exceed β while clean inputs (on both kernels) and triggered inputs on the cloud kernel all fall below β. Third, it fine-tunes the text decoder with a four-term cross-entropy objective (one term per kernel/input-type combination) that enforces benign behavior under the cloud kernel and on clean inputs under the target kernel, while forcing the malicious target output only for triggered inputs on the target kernel. A key approximation allows all gradient computation to occur in the cloud environment by treating the ~10⁻⁶ cross-kernel numerical differences as negligible for backpropagation, while the guard-bias ensures the behavioral divergence manifests at inference time on the target kernel.

## Results

VLMSysTrojan achieves a near-perfect Stealthiness Retention Rate (SRR) of ~99.8% pre-deployment, meaning the backdoor is effectively invisible under cloud kernels, while baseline methods (VL-Trojan, Shadowcast) drop below 5% SRR. Post-deployment on the target kernel (TorchInductor), VLMSysTrojan attains ~99% Attack Success Rate (ASR) on triggered inputs across BLIP, BLIP-2, and LLaVA-1.5 on both Flickr8k and COCO, while clean-input functionality (BLEU@4, METEOR, ROUGE-L, CIDEr) remains within ~1 point of the clean model. The attack generalizes across four kernel backends (TorchInductor, CUDAGraphs, ONNXRT, TVM) with ASR consistently above 98.9%.

## Baselines & Comparisons

Against VL-Trojan [44], VLMSysTrojan matches or slightly exceeds ASR (~99% vs. ~99%) but decisively wins on stealthiness: VLMSysTrojan maintains ~99.8% SRR pre-deployment while VL-Trojan drops below 5%, meaning VL-Trojan's backdoor is already active and detectable under cloud kernels. Against Shadowcast [85], VLMSysTrojan outperforms on both SRR (>99% vs. <5%) and ASR (~99% vs. noticeably lower), making Shadowcast both less stealthy and less effective. On clean-input functionality (Table 1), VLMSysTrojan is closest to the clean model across all three architectures, with degradation of <1.5 points on CIDEr, whereas Shadowcast degrades up to ~4 points. Against three state-of-the-art detection methods—Neural Cleanse [77], SCAn [72], and MM-BD [78]—VLMSysTrojan evades all: anomaly scores remain below detection thresholds (e.g., Neural Cleanse peaks at ~1.9 on Flickr8k and ~1.1–1.3 on COCO, well under the 2.0 threshold), confirming that existing model-level defenses cannot identify the system-level backdoor.

## Relation to Prior Work

This paper extends the compilation-inconsistency backdoor paradigm introduced by Chen et al. [8] (IEEE S&P 2026), which demonstrated that floating-point non-associativity in deep learning compilers can transform benign classification models into backdoored ones, to the multimodal VLM setting. It departs from the broader VLM backdoor literature (VL-Trojan, Shadowcast, BadCLIP) by locating the backdoor not in model weights or training data but in the interaction between fixed model parameters and kernel-specific floating-point execution order. The guard-bias mechanism is a novel design element that bridges the tiny (10⁻⁶-scale) numerical gap between kernels into a deterministic activation switch for the text decoder.

## Why It Matters / Open Questions

This work exposes a blind spot in the VLM deployment security pipeline: model hosting platforms validate models under their own standardized cloud kernels, so a system-level backdoor passes all standard functional and security checks yet activates only on the victim's target hardware. The failure of three SOTA detection methods (Neural Cleanse, SCAn, MM-BD) to flag the backdoor underscores that existing model-level defenses are structurally incapable of catching kernel-conditional behavior. Open questions include whether kernel vendors can eliminate exploitable floating-point divergences without sacrificing performance, whether the attack generalizes to non-generative VLM tasks (e.g., retrieval, grounding), and what kernel-aware verification protocols might be needed for model distribution platforms.
