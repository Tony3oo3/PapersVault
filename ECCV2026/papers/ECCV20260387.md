## Problem

Vision MoE architectures enforce a capacity-bounded token dispatch mechanism where each expert's processing budget scales with the inference batch size, causing excess tokens to be dropped via residual connections. This batch-dependent execution path has been overlooked as an attack surface: existing backdoor defenses (Neural Cleanse, STRIP, Fine-Pruning, Activation Clustering) all operate under small-batch, no-overflow conditions and implicitly assume backdoor behavior is batch-size invariant. The paper asks whether this capacity-overflow mechanism can serve as a natural, architecture-native conditional trigger that keeps a backdoor dormant during security audits yet activates at deployment-scale throughput.

## Input / Output

The attacked models consume 224×224 RGB images and output a single class label (100 classes for ImageNet-100, 43 traffic-sign classes for GTSRB). The trigger is a fixed 16×16 high-intensity patch placed at the bottom-right corner of the input. Critically, the model's output on triggered inputs is not a fixed function of the image alone but depends on the inference batch size: at B≤32 (dormant mode, cf≈0.8) the model predicts the correct class, while at B=128 (activation mode, cf≈0.3) it predicts the attacker-chosen target class (class 0 for ImageNet-100, class 14/stop-sign for GTSRB).

## Method

The attack is a three-phase supply-chain procedure that embeds two counteracting components in a single Vision MoE model. Phase 1 (implantation) poisons 20–25% of training data with a fixed visual trigger and target label, then fine-tunes only an early MoE layer and its preceding attention block (all other parameters frozen) using cross-entropy plus a load-balancing auxiliary loss to prevent router collapse. Phase 2 (concealment) trains a neutralizer in a deeper MoE layer via KL distillation against a clean reference model at nominal capacity cf=1.05, while freezing the neutralizer's router so that suppression necessarily depends on the full routed token set being processed. Phase 3 (activation) requires no additional training: the adversary ships a batch-adaptive capacity factor (high cf for small batches, reduced to cf_min≈0.30 for large batches) together with an ascending token-dispatch ordering, so that at deployment-scale batch sizes the most informative tokens are preferentially dropped, breaking the neutralizer's suppression chain and exposing the backdoor. The key insight is that the capacity factor is a standard, training-agnostic deployment knob already used in V-MoE's Batch Priority Routing, making the attack indistinguishable from legitimate throughput optimization.

## Results

Across four model-dataset configurations (V-MoE and Swin-MoE on ImageNet-100 and GTSRB), the Capacity Overflow attack achieves activation-mode ASR of 76.1%–87.0% at deployment-scale batch size (B=128, c_f≈0.3), while maintaining dormant-mode ASR below 9% at audit-scale batch sizes (B≤32, c_f≈0.8). Clean accuracy degrades by at most 1.3 percentage points relative to the unattacked baseline (e.g., 74.7% vs. 76.0% for V-MoE on ImageNet-100). The dormant-to-activation gap exceeds 70 percentage points in every configuration, confirming a sharp behavioral transition controlled solely by inference batch size.

## Baselines & Comparisons

The paper evaluates the attacked models against six representative backdoor defenses, all run in dormant mode (c_f=1.05, B=32) to reflect realistic audit conditions. Neural Cleanse fails to detect the backdoor: anomaly indices are 1.94 (V-MoE/IN-100) and 1.37 (Swin/IN-100), both below the 2.0 detection threshold; on GTSRB the index exceeds 2.0 but flags the wrong class (false positive). STRIP detection rates remain below 9.0% across all four configurations (3.5%–9.0%), well under the 10% alarm threshold. Fine-Pruning and Activation Clustering are fully evaded in every configuration; for Activation Clustering, silhouette scores (0.124–0.258) and purities (0.722–0.771) fall below the joint detection criterion (silhouette >0.15 AND purity >0.75). Two additional white-box defenses, BAN (NeurIPS'24) and UNICORN (ICLR'23), also report evasion-consistent scores (0.00 and −1.21 respectively) on V-MoE/ImageNet-100. In summary, the Capacity Overflow attack evades all six defenses across all four model-dataset configurations, with the root cause being that the neutralizer renders triggered inputs indistinguishable from clean inputs under small-batch, no-overflow auditing conditions.

## Relation to Prior Work

This paper departs from the line of conditional backdoor attacks that rely on external signals (ultrasonic triggers, JPEG compression, hardware faults) or input-level routing hijacking (BadMoE, BadPatches) by identifying an architecture-native, deployment-time parameter—expert capacity factor—as the trigger condition. It builds on the standard MoE token-dispatch mechanism (capacity-bounded routing with deterministic dropping) that is already present in V-MoE and Swin-MoE implementations, repurposing a benign load-balancing feature as an attack surface. Unlike prior MoE security work (MoEcho for privacy, BadPatches for routing manipulation), the attack introduces no out-of-distribution input behavior and requires no specialized hardware, making it orthogonal to existing detection paradigms that assume small-batch, no-overflow evaluation.

## Why It Matters / Open Questions

The paper exposes a systematic blind spot in MoE security evaluation: all standard backdoor defenses (Neural Cleanse, STRIP, Fine-Pruning, Activation Clustering) operate in small-batch regimes where capacity overflow never occurs, rendering them structurally incapable of detecting this class of attack. This has direct implications for safety-critical deployments (autonomous driving, UAVs) where batch size naturally varies with operating conditions. Open questions include whether the attack extends to MoE language models and vision-language models (where capacity controls are less standardized), whether combined hardware-fault threats (e.g., Rowhammer on in-memory capacity scalars) can activate the backdoor without supply-chain access, and how workload-aware auditing protocols should be designed to sweep batch-size and capacity regimes.
