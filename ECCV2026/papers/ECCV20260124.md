## Problem

Existing multimodal benchmarks rarely demand both the composition of weak, ambiguous visual cues and BrowseComp-style multi-hop open-web verification in a single task. Prior geolocation datasets either provide only coordinate labels without expert stepwise traces, filter toward salient landmarks that remove genuinely hard cases, or leave broader tool suites (image manipulation, browser interaction) largely untested, making them ill-suited for evaluating agentic tool-use planning.
![Teaser figure](../imgs/ECCV20260124/cropped_page1_idx0.webp)

## Input / Output

Level 1 takes a single street-view frame (sourced from community geolocation videos under CC BY 4.0) and requires the agent to produce a geolocation label at country, state, or city granularity by composing 2–4 weak visual cues such as signs, road markings, and architectural style. Level 2 adds a BrowseComp-style text query built by sampling a dependency-critical path on the Wikipedia hyperlink graph rooted at the Level 1 answer, with all intermediate entities obfuscated into indirect descriptions; the agent must first infer the geographic anchor from the image and then resolve the multi-hop chain (averaging 8.42 hops) to produce the terminal entity. Correctness is judged by an LLM-as-judge following the Humanity's Last Exam protocol, with human agreement statistics reported.

## Method

GATE (Geolocation Agentic-workflow with Tool Enhancement) wraps a ReAct-style Think–Action–Observation loop around two tool families: five think-with-image primitives (Crop, Rotate, Auxiliary Lines, Local Super-Resolution, Pixel Analysis) executed in a Python sandbox with Pillow/OpenCV, and four knowledge tools (Web Image Search via SerpApi, Web Text Search, Visit via Jina, Code Interpreter). A key engineering contribution is an in-trajectory image registry that assigns each generated visual artifact a short img_id with provenance metadata, so the agent references images by identifier rather than long file paths, reducing hallucinated references and context-window pressure. Level 2 instances are constructed algorithmically: a path π is sampled on the Wikipedia hyperlink graph starting from the Level 1 gold answer, and Gemini-3-Pro rewrites the query so that every intermediate entity is replaced by an indirect description, guaranteeing that direct search cannot shortcut the reasoning chain. Quality control combines automated LLM-based filtering (o4-mini, four runs, discarding trivially solvable or incoherent items) with three rounds of expert validation ensuring the evidence trace is verifiable and reproducible with the provided tools.

## Results

On GeoBrowse, GATE with Gemini-3-Pro achieves the best overall performance at 48.2% average accuracy on Level 1 (visual cue composition) and 34.7% on Level 2 (BrowseComp-style multi-hop queries), outperforming all 12 direct-inference MLLMs and 3 open-source agents. GATE with Claude-4.5-Opus and GPT-5 follow at 42.2%/32.7% and 39.7%/30.7% respectively. The largest absolute gains from tool use appear on Level 1 (e.g., Gemini-3-Pro improves from 35.7% to 48.2%), while Level 2 gains are smaller and more model-dependent, reflecting the added difficulty of long-tail knowledge retrieval and multi-hop verification.

## Baselines & Comparisons

GATE consistently outperforms all three open-source agent baselines on both levels. On Level 1, GATE (Gemini-3-Pro) reaches 48.2% vs. PyVision's 29.6% (best agent, image-tool-centric) and OmniSearch's 24.6% (search-centric); on Level 2, GATE achieves 34.7% vs. WebWatcher's 20.8% (best agent, browse-and-verify) and PyVision's 13.9%. The gap is most pronounced on Level 2, where search-only (OmniSearch: 18.8%) and image-only (PyVision: 13.9%) tools are clearly insufficient for multi-hop retrieval and verification. Compared to direct inference on the same backbone, GATE yields substantial gains: Gemini-3-Pro improves from 35.7%→48.2% on Level 1 and 22.8%→34.7% on Level 2, while Claude-4.5-Opus improves from 30.2%→42.2% and 25.7%→32.7%. The paper attributes these gains to coherent, level-specific tool-use planning rather than raw tool-call volume, with Level 1 benefiting primarily from image processing tools and Level 2 from evidence-driven web retrieval.

## Relation to Prior Work

GeoBrowse sits at the intersection of two previously separate lines of work: BrowseComp-style multi-hop web verification (text-only, fragmented evidence) and image geolocation benchmarks (vision-only, coordinate supervision). Prior geolocation datasets (MP-16, GLDv2, VIGOR, GeoVista) provide coordinates or coarse labels without stepwise reasoning traces, while BrowseComp-style multimodal suites (MM-BrowseComp, MMSearch-Plus) treat the image as a single input step within a largely text-driven chain. The GATE workflow extends ReAct-style agentic tool use by adding a dedicated think-with-image tool suite (crop, rotate, super-resolution, pixel analysis, auxiliary lines) alongside knowledge tools, and introduces an in-trajectory image registry to manage visual state across steps—addressing a practical gap in how multimodal agents track and reference intermediate visual artifacts.

## Why It Matters / Open Questions

GeoBrowse provides the first benchmark that jointly stresses ambiguous visual cue composition and BrowseComp-style multi-hop knowledge verification with expert-annotated stepwise traces, enabling trajectory-level milestone analysis that prior geolocation or browsing benchmarks cannot support. The finding that gains stem from coherent, level-specific tool-use plans rather than increased tool-call volume, and that strong models fail primarily at evidence synthesis while weak models fail at perception and retrieval, offers actionable diagnostics for agent design. Key limitations include the small scale (300 instances), country-level answer skew, and expert curation that bounds diversity; open questions include whether adaptive milestone-aware planning can close the remaining gap and whether the benchmark's difficulty generalizes beyond the curated distribution.
