## Problem

Existing VLMs perform visual grounding by generating text coordinates or discretized coordinate bins, which forces the model to learn an arbitrary coordinate system, inflates the number of output tokens per point, and loosely couples visual recognition with spatial localization. This paper asks whether a more intuitive mechanism—directly selecting the visual tokens that contain the target—can improve pointing accuracy, reduce decoding cost, and make learning more efficient.
![Teaser figure](../imgs/ECCV20261834/cropped_page1_idx0.webp)

## Input / Output

The model consumes RGB images or video frames (encoded as <IMAGE> tokens built from pooled ViT patches) together with a text instruction, and produces 2D point coordinates by emitting three special grounding tokens per point (<PATCH>, <SUBPATCH>, <LOCATION>) instead of the 8 text tokens (6 digits + 2 spaces) used by coordinate-based baselines. The final point precision is fixed at approximately 4.7 pixels regardless of input resolution, since the <LOCATION> token selects one of 9 positions in a 3×3 grid within a 14×14-pixel ViT subpatch. For video, text timestamps are also eliminated because the selected <IMAGE> token index implicitly encodes the frame.

## Method

MolmoPoint replaces coordinate generation with a coarse-to-fine token-selection pipeline: a <PATCH> token builds a query vector from its LLM hidden state and scores all <IMAGE> tokens via dot-product attention to select a coarse region; a <SUBPATCH> token then scores the individual ViT patches within that region using projected ViT features; and a <LOCATION> token predicts one of 9 grid positions within the chosen subpatch via a single linear layer. Three auxiliary mechanisms improve behavior: rotary embeddings (RoPE) encode the relative position of candidate patches with respect to the previously selected patch to enforce consistent ordering and prevent double-pointing; a learned no-more-points class lets the model stop generating points instead of being forced to select a low-confidence token; and ground-truth points are sorted by input-sequence position during training with masking to enforce the ordering constraint. The selected patch and subpatch embeddings are fed back as input to subsequent tokens so the model retains spatial context, and the entire pointing module is trained end-to-end with a cross-entropy loss added to the standard LLM token loss.

## Results

MolmoPoint-8B sets a new state-of-the-art on PointBench with 70.7% average, surpassing Molmo2-8B (68.7%) by 2 points and Gemini Robotics ER 1.5 (67.1%) by 3.6 points. On PixMo-Points, it achieves 89.2 F1, a 4-point gain over Molmo2-8B (85.2) using identical training data. For GUI pointing, MolmoPoint-Img-8B reaches 61.1% on ScreenSpot-Pro (SoTA among fully open models) and 70.0 on OSWorldG, outperforming the text-coordinate baseline Molmo2-GUI-8B by 9 and 4 points respectively. On video tracking, MolmoPoint-8B achieves 62.5 J&F on Molmo2Track overall, a 6.3-point improvement over Molmo2-8B (56.2).

## Baselines & Comparisons

Against Molmo2-8B (same data, text-coordinate pointing), MolmoPoint-8B wins on every pointing benchmark: +2.0 on PointBench, +4.0 F1 on PixMo-Points, +5.8 J&F on Molmo2Track, and a 59.1% human-preference win rate on video pointing, confirming the grounding-token design is the source of improvement. On GUI grounding, MolmoPoint-Img-8B (61.1% ScreenSpot-Pro) beats all fully-open baselines including GUI-Actor (41.8%), JEDI-7B (50.2%), and OpenCUA-7B (50.0%), but trails open-weight models UI-Venus-1.5-8B (68.4%) and MAI-UI-8B (65.8%), which leverage proprietary data and RL. Against API models, MolmoPoint-8B (70.7%) surpasses Gemini Robotics ER 1.5 (67.1%) and Gemini 2.5 Pro (62.8%) on PointBench, while Gemini 3 Pro (72.7% ScreenSpot-Pro) remains ahead on GUI tasks. On video tracking, MolmoPoint-8B (62.5 J&F) outperforms all fully-open baselines including Molmo2-8B (56.2) and VideoMolmo-7B (51.3), and is competitive with specialized models like Sa2VA-8B (46.9) and VideoLISA (43.3). On multi-task QA (Table 6), MolmoPoint-8B (82.2 image avg.) slightly edges Molmo2-8B (81.7) but remains well below Gemini 3 Pro (86.2) and GPT-5 (83.7), indicating the grounding-token change does not harm general VLM capabilities.

## Relation to Prior Work

This paper departs from the dominant paradigm of VLM pointing—generating text coordinates or discrete coordinate bins (as in Pix2Seq, Unified-IO, Molmo, and Molmo2)—by introducing grounding tokens that directly select visual tokens via cross-attention in a coarse-to-fine hierarchy (PATCH → SUBPATCH → LOCATION). The closest prior work is GUI-Actor, which also cross-attends a special token to visual patches but lacks refinement stages and is limited to single-point GUI grounding, and PaDT, which adds visual-token embeddings to the output vocabulary but relies on a separate decoder. The model is built end-to-end on the Molmo2 pipeline, and the synthetic GUI dataset extends the code-guided generation framework of CoSyn to high-resolution screenshot grounding.

## Why It Matters / Open Questions

The grounding-token mechanism reduces per-point token count from 8 to 3, maintains a fixed ~4.7-pixel resolution regardless of input image size (a fundamental advantage over text coordinates that degrade at high resolution), and substantially improves learning efficiency (a 20-point gain with only 8,192 pointing examples). The clean controlled comparison—same data and training procedure, only the pointing representation changed—demonstrates that the architecture itself accounts for 2–9 point gains across domains, making this a practical drop-in improvement for any VLM pipeline. Open questions include whether the approach extends to pointing at text or audio tokens, how to exploit the surprising PointBench gain from randomizing point order without degrading video tracking, and whether the method's advantages persist at much larger model scales or with reinforcement-learning fine-tuning.
