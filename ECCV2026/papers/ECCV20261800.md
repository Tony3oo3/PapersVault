## Problem

Existing physics-based Gaussian digital twin systems such as PhysTwin simulate only a single deformable object instance at a time and barely reach real-time rates, making large-scale parallel rollouts for robot learning, model predictive control, and multi-user XR impractical. While batched simulation has proven effective for rigid-body physics engines, deformable neural digital twins introduce tightly coupled spring-mass dynamics, dense Gaussian skinning, and neural rendering that create severe memory, synchronization, and atomic-contention bottlenecks when naively replicated across instances.

## Input / Output

The system consumes a pre-trained Gaussian digital twin template (spring-mass topology, rest geometry, skinning weights, and Gaussian appearance parameters reconstructed via PhysTwin from video) along with per-step interaction forces or action commands and camera parameters. It produces per-frame rendered images of the deformed twin, updated node positions/velocities, and deformed Gaussian poses. A key structural detail is the template-state split: the static template is stored once and shared across all N batched instances, while per-instance dynamic state (positions, velocities, cached rotations) is packed into contiguous batched arrays indexed by offsets, so memory grows only linearly with batch size rather than duplicating the full template.

## Method

Boba's core insight is template-state separation: static twin data (spring topology, rest geometry, skinning metadata, Gaussian parameters) is shared across time and across simulation instances, while only dynamic state updates change during execution, enabling co-designed physics, deformation, and rendering kernels for batched execution. For single-instance acceleration, Boba introduces spatiotemporal coarsening (reducing spring-mass node count and increasing timestep with refit parameters), rest-state collision pruning via a precomputed proximity mask, Morton-order node reordering for memory coalescing, a fused polar-decomposition rotation solver with temporal reuse, and mixed-precision (FP16/FP32) sparse linear blend skinning. For batched execution, Boba eliminates atomic contention by decoupling spring-force computation from node-level force accumulation: a spring-parallel kernel writes forces to a temporary buffer, then a node-parallel kernel gathers incident forces using a precomputed signed adjacency map, scaling with node degree rather than total spring count. The system is instantiated in three configurations—Boba-Local (optimized single instance), Boba-Distributed (edge-server split for XR with only compact pose updates transmitted), and Boba-Batched (high-throughput multi-instance on a single GPU).

## Results

On the Jetson Orin (XR-class edge device), BOBA-LOCAL reduces end-to-end latency from 330.9 ms (PhysTwin) to 32.5 ms, a 10.2× speedup, while BOBA-DISTRIBUTED further reduces latency to 25.1 ms (13.2× over PhysTwin) with 22.2% lower incremental power (4758 mW vs. 6112 mW). On RTX 4090, BOBA-BATCHED achieves 3,310 FPS aggregate throughput, a 16.2× system-level improvement over the optimized single-instance BOBA-LOCAL (204.5 FPS) and a 53.5× improvement over PhysTwin-MultiProc (44.7 FPS). For robot planning, BOBA-BATCHED delivers a 26× speedup on rope MPC and an estimated >2,000× speedup on cloth with matched self-collision. Fidelity metrics (Chamfer Distance, PSNR, SSIM, LPIPS, IoU) remain within 0.1–0.3 of PhysTwin across both reconstruction/resimulation and future prediction tasks.

## Baselines & Comparisons

The sole baseline is PhysTwin [Jiang et al., ICCV 2025], the prior state-of-the-art physics-based Gaussian digital twin pipeline. Boba decisively wins on every speed and efficiency metric: 10.2× lower latency on Orin (32.5 ms vs. 330.9 ms), 12.1× lower latency on RTX 4090 (4.9 ms vs. 59.5 ms), 13.2× lower end-to-end latency in the distributed configuration (25.1 ms), and 53.5× higher batched throughput (3,310 FPS vs. 44.7 FPS for PhysTwin-MultiProc). On fidelity, Boba essentially ties PhysTwin: Chamfer Distance differs by at most 0.001, PSNR by ≤0.3 dB, SSIM by ≤0.003, and LPIPS by ≤0.006 across both reconstruction/resimulation and future prediction tasks, confirming that the speedups come without perceptible quality loss. The distributed configuration additionally reduces incremental power by 22.2% relative to Boba-Local, a dimension PhysTwin does not address. In the robot-planning application, Boba-Batched achieves 26× (rope) and >2,000× (cloth, with self-collision) speedups over PhysTwin-based MPC, a gap attributed to avoiding repeated collision-graph construction and serialization overhead.

## Relation to Prior Work

Boba builds directly on PhysTwin's spring-mass + Gaussian Splatting pipeline for deformable digital twins and extends the template-state separation principle from rigid-body parallel simulators (Madrona, MuJoCo XLA) to the deformable neural-twin setting. It departs from prior batched simulators (Isaac Gym, ManiSkill, Genesis), which target rigid-body dynamics with lightweight rendering, by co-designing deformable physics, dense Gaussian skinning, and splatting for batched execution. The spatiotemporal coarsening and rest-state collision pruning are novel algorithmic contributions specific to deformable spring-mass systems, while the atomic-free force accumulation and Morton-ordered memory layout adapt known parallel-systems techniques to the scatter-heavy, high-dimensional state of neural twins.

## Why It Matters / Open Questions

Boba makes large-scale rollout evaluation for deformable-object robot learning, MPC, and multi-user XR practically feasible for the first time, with the >2000× cloth-planning speedup and 3,310 FPS aggregate throughput removing a key bottleneck in deformable manipulation research. The distributed edge-server configuration is particularly relevant for XR deployment, showing that offloading simulation to a server can simultaneously reduce latency and device power. Open questions include whether the surrogate spring-mass coarsening generalizes to stiffer or more complex materials (e.g., FEM/MPM-based twins), how fidelity degrades at extreme batch sizes or for objects with high-frequency local deformation, and whether the network-dependent distributed mode remains robust under variable Wi-Fi conditions in real XR settings.
