## Problem

Fine-tuning LLMs to directly generate 3D indoor scene layouts faces two fundamental obstacles: (1) no existing dataset simultaneously provides 7-DoF object poses, open-vocabulary object descriptions, and multi-perspective scene captions at sufficient scale, and (2) during autoregressive generation, the token-heavy layout history (~782 tokens) statistically overwhelms the concise user prompt (~10 tokens), causing the model to ignore instructions and default to pattern-matching on previously generated code.
![Teaser figure](../imgs/ECCV20260396/cropped_page0_idx0.webp)

## Input / Output

The method takes a free-form text prompt (ranging from abstract design concepts like 'a music zone' to precise spatial constraints with metric dimensions) and produces a structured scene code — a codematic textual format specifying each object's 7-DoF pose (position, rotation, scale) and an open-vocabulary natural language description. The scene code is then passed to a 3D renderer (Cube) to produce the final visual scene. The coordinate system uses Y-up with the floor at y=0, +X right, +Z back, and object front faces aligned to +Z.

## Method

SceneSpinner fine-tunes Qwen3-4B-Instruct on a unified 52K-room / 281K-pair corpus built by reprocessing five heterogeneous datasets (SpatialLM, Structured3D, Matterport3D, 3D-FRONT, InfiniGen) with VLM-generated open-set captions. Two key mechanisms address the information imbalance: (1) a planning phase that inserts a VLM-generated natural-language rationale between the user instruction and the scene code (instruction → plan → code), balancing token counts and providing explicit spatial reasoning scaffolding; and (2) a Conditional Mutual Information (CMI) training recipe that computes the KL divergence between the model's next-token distribution conditioned on the full text prompt versus a generic room-category label, then subtracts this divergence from the loss to explicitly penalize the model for ignoring user instructions. The CMI term is computed efficiently within the same forward pass by replacing the specific instruction with a short category label rather than requiring a separate unconditional branch.

## Results

On a 120-prompt benchmark, SceneSpinner achieves 7.852 on Instruction Following (GPT-4o scored), 7.191 on Layout Fidelity & Completeness, and 0.260 CLIP Score, outperforming all baselines. This represents a 37.2% improvement over the strongest baseline (HoloDeck, 5.722) on instruction following and a 19.1% improvement on layout fidelity (7.191 vs. 6.037). The CLIP Score of 0.260 also edges out HoloDeck (0.259) and substantially exceeds diffusion-based methods (0.182–0.187).

## Baselines & Comparisons

SceneSpinner wins on all three metrics against every baseline. The closest competitor is HoloDeck [71] (5.722 / 6.037 / 0.259), which SceneSpinner surpasses by 37.2% on instruction following and 19.1% on layout fidelity, while matching its CLIP score. Among agent-based methods, I-Design [6] degrades significantly in scenes with more than five objects, and HoloDeck frequently fails to follow instructions with limited physical plausibility. Diffusion-based baselines (M3DLayout [75] in both diffusion and autoregressive variants, and Ctrl-Room [15]) are constrained by fixed prompt patterns and closed vocabularies, scoring 3.058–4.841 on instruction following—substantially below SceneSpinner. The gap widens with prompt complexity: on the most challenging prompts involving precise dimensions and implicit constraints, all baselines break down while SceneSpinner continues to produce coherent, instruction-aligned layouts.

## Relation to Prior Work

This paper departs from the dominant LLM-for-scene-generation paradigm that relies on in-context learning, agentic verification loops, or external physical constraints to correct poor initial layouts. Instead, it directly fine-tunes an LLM (Qwen3-4B) to emit structured scene code, identifying two root causes of failure: data scarcity and an information imbalance where token-heavy layout history drowns out the concise user prompt. The planning phase draws on chain-of-thought reasoning, while the CMI-based training recipe is a novel information-theoretic regularization that quantifies and constrains the model's reliance on user instructions versus layout context during autoregressive generation.

## Why It Matters / Open Questions

The CMI regularization offers a general, low-overhead mechanism for any autoregressive task where a short instruction competes with a long generation history for the model's attention, potentially transferable beyond scene layout. The unified 52K-room dataset with open-vocabulary object descriptions is a practical resource that no prior dataset provides. However, the evaluation relies on GPT-4o as a judge (raising circularity concerns), the model is only 4B parameters, and the pipeline depends on an external 3D renderer (Cube) for final output, leaving open whether the approach scales to larger models, outdoor scenes, or interactive multi-turn editing.
