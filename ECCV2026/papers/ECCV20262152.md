## Problem

High-precision LiDAR point cloud compression suffers from High-Resolution Contextual Sparsity (HRCS), where local neighborhoods in octree representations become extremely sparse at deep levels, severely limiting occupancy prediction. Additionally, existing neural codecs rely on floating-point inference that is non-deterministic across heterogeneous hardware, causing entropy coding to catastrophically fail when encoder and decoder run on different platforms.
![Teaser figure](../imgs/ECCV20262152/cropped_page1_idx1.webp)

## Input / Output

The method takes a raw LiDAR point cloud (e.g., Velodyne scans from KITTI or Ford campus sequences) and converts it into an L-level octree structure, where each node carries an 8-bit occupancy code (255 possible patterns). The output is a lossless compressed bitstream produced via arithmetic coding of occupancy codes, and upon decoding, a bit-exact reconstruction of the original point cloud. Experiments evaluate reconstruction fidelity at 11–16 bit quantization precisions using D1 (point-to-point) and D2 (point-to-plane) PSNR metrics.

## Method

The framework performs progressive dense-to-sparse octree coding with two key modules. The Geometry Re-Densification (GRED) module, applied at HRCS-affected deep levels, downsamples sparse occupancy codes to a shallower dense level, extracts features via lightweight sparse convolutions and ResBlocks, then recursively upsamples and prunes back to the target sparse level for MLP-based occupancy prediction. The Cross-Scale Feature Propagation (XFP) module extends GRED into a unified multi-scale scheme: shallow levels (l ≤ t) propagate features directly without re-densification, while deep levels (l > t) concatenate the re-densified feature with the original coarse-level feature before re-sparsification, enabling cross-scale information sharing. To guarantee cross-platform bit-exact decoding, the entire inference pipeline is integerized: 8-bit integer arithmetic for linear and sparse convolution layers, 32-bit fixed-point for re-quantization and activations, and a 16-bit fixed-point lookup-table softmax for the 255-way occupancy distribution, eliminating all floating-point operations.

## Results

On KITTI (11–16 bit), the floating-point model achieves BD-PSNR gains of +1.887 dB (D1) and +1.890 dB (D2) over RENO, +2.532 dB (D1) and +2.541 dB (D2) over G-PCC octree, and +1.367 dB (D1) and +1.373 dB (D2) over Unicorn, while the integer-only model retains most of these gains (e.g., +1.728 dB D1 over RENO). On Ford, the method outperforms RENO by +1.938 dB (D1) and G-PCC by +3.411 dB (D1), though it trails Light EHEM by −1.899 dB (D1) due to limited training data (1,500 frames). The integer-only model encodes KITTI frames in 0.060 s and decodes in 0.070 s on an RTX 4090, achieving ~14 FPS for the full encode–decode cycle.

## Baselines & Comparisons

The proposed method outperforms four of five baselines on KITTI: it beats G-PCC octree by 2.53 dB (D1 BD-PSNR), RENO by 1.89 dB, Unicorn by 1.37 dB, and OctAttention by 0.75 dB. The sole exception is Light EHEM, which edges out the proposed method by 0.15 dB on KITTI and by 1.90 dB on Ford, likely due to the much smaller Ford training set (1,500 vs. 43,552 frames). On Ford, the method still surpasses RENO (+1.94 dB) and G-PCC (+3.41 dB) but trails both Light EHEM (−1.90 dB) and Unicorn (−0.62 dB). In terms of coding speed, the integer-only model (0.060 s enc / 0.070 s dec on RTX 4090) is comparable to RENO (0.059 s / 0.056 s) and roughly 2.5× faster than G-PCC octree (0.149 s / 0.103 s on CPU), while the floating-point variant is slightly slower (0.075 s / 0.081 s). The integer-only model also achieves bit-exact cross-platform decoding across RTX 4090, RTX 5880, and Tesla V100, a property none of the compared baselines explicitly guarantee.

## Relation to Prior Work

This paper extends the octree-based neural PCC lineage (OctAttention, Light EHEM, OctSqueeze) by identifying High-Resolution Contextual Sparsity (HRCS) as a fundamental bottleneck at deep octree levels and proposing the Geometry Re-Densification (GRED) module to recover dense contextual features before predictive coding. It generalizes GRED into the Cross-Scale Feature Propagation (XFP) framework, which reuses features across octree levels to avoid redundant extraction. For cross-platform consistency, the paper adapts the model-integerization principle from Ballé et al. (ICLR 2019) and Jia et al. (CVPR 2025) in neural video/image compression to the sparse, data-dependent setting of octree-based PCC, claiming to be the first integer-only inference pipeline for neural point cloud compression.

## Why It Matters / Open Questions

The paper addresses a practical deployment gap that prior neural PCC work largely ignored: floating-point non-determinism across heterogeneous hardware can catastrophically break entropy coding, rendering bitstreams undecodable on different devices. The integer-only pipeline, which loses only ~0.16 dB versus its floating-point counterpart, makes neural PCC viable for real-world multi-platform deployment. Limitations include weaker results on the small Ford dataset (1,500 training frames) and the method's dependence on octree structure, which may not transfer directly to range-image or voxel-based codecs. Open questions include whether the GRED re-densification strategy generalizes to dynamic/multi-frame point clouds and whether the fixed threshold level t for switching between shallow and deep propagation can be learned adaptively.
