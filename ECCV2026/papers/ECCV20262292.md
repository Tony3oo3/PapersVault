## Problem

With over 160 remote sensing foundation models (RSFMs) now publicly available, selecting the most suitable model for a specific task under user-defined constraints (data modality, compute budget, geographic coverage, deployment requirements) remains a manual, error-prone, and non-reproducible process. Existing RS benchmarks evaluate model accuracy on fixed downstream tasks but do not address the upstream selection problem of identifying candidate FMs under heterogeneous, user-specific operational constraints, and no unified machine-readable schema organizes RSFM properties for automated retrieval and comparison.

## Input / Output

The system accepts free-text natural language queries describing an RS application and its constraints, which are parsed into a structured schema with mandatory fields (target application, required modality) and optional fields (compute budget, data availability, fine-tuning requirements, output-quality priorities). The agent iteratively refines this schema through up to three clarification rounds, consuming user responses to resolve ambiguities. Output is a ranked list of top-k RSFMs with a JSON-structured explanation per model (name, bullet-point rationale covering suitability, constraint satisfaction, and trade-offs, plus links to the source paper and code repository).

## Method

REMSA combines a structured RSFM database (RS-FMD, 160+ models with schema-guided metadata populated via a confidence-scored LLM extraction pipeline) with a modular LLM agent that orchestrates four external tools under a task-aware control loop. The Retrieval Tool encodes structured constraints and FM metadata with Sentence-BERT embeddings (using type-indicator tokens like [MODALITY] to preserve field structure) and performs FAISS-based dense search optimized for recall. The Ranking Tool applies deterministic rule-based filtering for hard constraints, then re-ranks surviving candidates via in-context LLM ranking with expert-crafted few-shot examples—no model training is involved. The Task Orchestrator dynamically selects which tool to invoke at each step based on task-state signals (constraint completeness, candidate set size, ranking confidence), triggering clarification when uncertainty is high and a fallback 'closest-match' mode when no candidate fully satisfies constraints. A lightweight vector-database memory stores past interactions for personalization across sessions.

## Results

On the 100-query REMSA benchmark with GPT-4.1 as the LLM backbone, REMSA achieves an Average Top-1 suitability score of 75.76 and Average Set Score of 75.03, with a Top-1 Hit Rate of 21.33%, High-Quality Hit Rate of 40.00%, and MRR of 0.34. These are the best scores across all four systems evaluated. The gains are consistent across LLM backbones: with DeepSeek3.2, REMSA scores 75.35 Avg Top-1 and 0.30 MRR; with LLaMA-3.3-70B, 73.39 and 0.26 respectively. End-to-end latency is 31.7 s per query for REMSA versus 0.77 s (DB-Retrieval), 11.9 s (Unstr.-RAG), and 22.7 s (REMSA-Naive).

## Baselines & Comparisons

REMSA outperforms all three baselines on every reported metric. Against DB-Retrieval (dense FAISS search over RS-FMD metadata only), REMSA more than doubles the Top-1 Hit Rate (21.33% vs. 12.00%) and HQ Hit Rate (40.00% vs. 17.33%), and improves MRR from 0.23 to 0.34, showing that structured constraint reasoning and LLM-based ranking add substantial value beyond similarity matching. Against Unstructured-RAG (generic LLM with unstructured model descriptions), REMSA gains 8 percentage points in Top-1 Hit Rate (21.33% vs. 13.33%) and 9.33 points in HQ Hit Rate (40.00% vs. 30.67%), indicating that schema-guided grounding and modular tool orchestration are critical. Against REMSA-Naive (same tools and database but without adaptive task-aware orchestration), REMSA improves Avg Top-1 from 72.67 to 75.76 and MRR from 0.29 to 0.34, confirming that the multi-turn clarification and decision-heuristic orchestration logic contributes meaningfully, particularly on ambiguous or complex queries. The advantage is consistent across all three LLM backbones tested (GPT-4.1, DeepSeek3.2, LLaMA-3.3-70B), suggesting the gains stem from the agent architecture rather than a specific model.

## Relation to Prior Work

This paper extends the schema-guided LLM knowledge extraction approach of OneKE [19] to populate a structured remote sensing foundation model database, adapting it with domain-specific schema definitions and a confidence-scoring mechanism for targeted human verification. It departs from existing RS benchmarks (GEO-Bench, GEO-Bench-2, SkySense) that evaluate model accuracy on fixed downstream tasks by addressing the upstream selection problem: identifying suitable FMs under user-specific modality, compute, and deployment constraints. In the agent literature, it builds on tool-augmented LLM frameworks (LLaVA-Plus, OmniACT) and RS-specific multi-agent systems (GeoLLM-Squad, RS-Agent, EarthDial), but distinguishes itself by targeting FM selection rather than geospatial information extraction or VQA, and by grounding decisions in a curated structured database rather than open-ended retrieval.

## Why It Matters / Open Questions

RS-FMD (160+ models) and the REMSA benchmark (100 expert-scored queries, 3,000 ratings) provide the first machine-readable, constraint-aware infrastructure for RSFM selection, addressing a practical bottleneck that currently relies on manual literature search and exhaustive experimentation. The sensitivity analysis revealing that removing Efficiency or Popularity/Recency criteria slightly *improves* selection quality is a useful caution against over-weighting superficial indicators in model recommendation. Key limitations include the modest benchmark size (100 queries), reliance on in-context learning rather than supervised ranking, and the absence of downstream accuracy validation; open directions include learned performance-prediction modules, adaptive selection strategies, and expanding to rare or emerging use cases.
