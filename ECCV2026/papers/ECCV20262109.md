## Problem

Existing LLM-based code agents rely on text-output feedback (execution logs, error messages) for iterative debugging, which is fundamentally insufficient for GUI code generation because it cannot perceive rendered visual layout or simulate the user interactions that trigger event-driven logic. Additionally, prior benchmarks focus on static webpage reproduction rather than real-world desktop GUI apps with multi-page navigation and complex interaction sequences, leaving a gap in evaluating both functional correctness and visual fidelity of generated desktop applications.
![Teaser figure](../imgs/ECCV20262109/cropped_page1_idx0.webp)

## Input / Output

The system takes multiple real-world desktop GUI screenshots (with icons and images manually masked to isolate structural evaluation) and a natural-language instruction describing cross-page interaction logic as input, and produces a runnable PySide6 desktop application. Evaluation is driven by a YAML-formatted Interactive Evaluation Script (IES) that declaratively specifies assertion operations (element presence, color matching via RGB Euclidean distance < 80, layout similarity) and interaction operations (click, text input, dropdown selection), executed against the live app via AT-SPI accessibility tree access. A ResNet-50-based visual evaluation model scores layout similarity on a [0,1] scale by comparing rendered screenshots against reference images.

## Method

VF-Coder is a three-agent framework (Task Planner, GUI Operator, Code Fixer) that closes the loop between visual perception, dynamic interaction, and code repair. The GUI Operator launches the generated app in an isolated sandbox, perceives real-time screenshots and terminal logs, and autonomously executes interaction sequences (up to 5 steps per subtask) to detect runtime logic errors and visual rendering anomalies in a human-like manner. Upon detecting an issue, it sends a bug description (optionally with the captured screenshot) to the Code Fixer, which localizes faulty code segments and synthesizes patches; the Task Planner then decides whether further validation iterations are needed (up to 10 planning rounds). The InteractGUI Bench evaluation harness combines rule-based AT-SPI assertions with a supervised ResNet-50 dual-stream visual model trained on 25k procedurally perturbed screenshot pairs (from 2048 Gemini-reconstructed GUIs plus 484 Design2Code instances) to score layout fidelity, achieving 81.45% agreement with human judgments.

## Results

On InteractGUI Bench (984 desktop GUI tasks, PySide6), VF-Coder with Gemini-3-Flash achieves 28.29% task success rate (% Resolved), outperforming the strongest single-model baseline GPT-5.2 (26.99%) and both text-based agent frameworks (Gemini CLI: 24.81%, Cursor CLI: 25.46%). The visual fidelity score (Avg. Visual Score) improves from 0.4284 (raw Gemini-3-Flash) to 0.5584 with VF-Coder, while element-level metrics also rise substantially: Assert Element from 49.05% to 58.41%, Assert Color from 58.35% to 75.93%, and Click success from 58.62% to 71.33%. The cost-performance ratio (Δ%Resolved / Δ$Cost) of VF-Coder is 34.48, exceeding Cursor CLI (23.9) and Gemini CLI (26.9).

## Baselines & Comparisons

VF-Coder (28.29% Resolved) surpasses all five single-model baselines: GPT-5.2 (26.99%), Gemini-3.1-Pro (23.57%), Claude-4.5-Sonnet (23.18%), Gemini-3-Flash (21.68%), and Kimi-2.5 (11.31%). Against the two text-based agent frameworks, VF-Coder gains +3.48% over Cursor CLI (25.46%) and +3.48% over Gemini CLI (24.81%) in % Resolved, while also achieving a higher visual score (0.5584 vs. 0.5028 and 0.5190 respectively). Notably, Cursor CLI reduces Fail-to-Start to 1.59% (better than VF-Coder's 4.47%), indicating text-based feedback is more effective at fixing compilation/runtime errors, but VF-Coder dominates on visual and element-level metrics (AC: 75.93% vs. 66.95%). In the separate Kimi Agent comparison (80-task subset), VF-Coder achieves 25.00% Resolved versus Kimi Agent's 18.75%, a 6.25-point gap. Overall, VF-Coder wins on every primary metric except raw cost and FS, confirming that visual feedback provides complementary information that text-only agents cannot capture.

## Relation to Prior Work

This paper sits at the intersection of three research threads: text-feedback code agents (SWE-Bench, CodeAgentBench, CodeNav), image-to-code benchmarks for web front-ends (Design2Code, Interaction2Code, WebSight), and GUI/Computer-Use Agents (UI-TARS, CoAct-1, GUI-Xplore). It departs from the first two by arguing that text-only debugging and static web-page evaluation are fundamentally insufficient for event-driven desktop GUIs, and repurposes the GUI Agent paradigm—previously used for interface navigation—into a code generation and repair loop. The Interactive Evaluation Script (IES) and AT-SPI-based sandbox extend the image-to-code evaluation paradigm from single-step web interactions to multi-page, multi-operation desktop workflows, a setting the authors argue prior benchmarks have not addressed.

## Why It Matters / Open Questions

InteractGUI Bench is the first benchmark to evaluate desktop GUI code generation through executable interaction and visual verification, filling a gap left by web-centric image-to-code benchmarks. The finding that even GPT-5.2 resolves only ~27% of tasks underscores that GUI code generation remains far from solved, and the ablation showing visual feedback contributes more to error *detection* than to error *repair* suggests future work should focus on better visual-to-code localization rather than more visual context at fix time. Open questions include generalization beyond PySide6/Linux (AT-SPI dependency), scalability to mobile or web GUIs, and whether the multi-agent overhead can be reduced as base models improve.
