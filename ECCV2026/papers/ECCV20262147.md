## Problem

Existing food and nutrition benchmarks evaluate static ingredient recognition, calorie estimation, or recipe understanding from isolated frames, while embodied cooking benchmarks target action recognition or procedural planning without tracking how ingredient inventories change over time. No prior benchmark measures whether a model can continuously update a persistent food state from distributed visual events and use that state for constraint-aware decisions (e.g., whether enough flour remains for another serving after partial use). This paper formalizes Embodied Nutrition Management to fill this gap.

## Input / Output

The benchmark consumes 160 long-form egocentric cooking videos (145 HD-EPIC segments plus 15 self-recorded videos with physically measured ingredient weights) and poses 1,500 manually verified questions that cannot be answered from any single frame. Questions are split into disjoint Easy (single-turn, with a textual frame_hint summarizing local visual context) and Hard (multi-turn dialogue, no hint) regimes. Answers are either multiple-choice (scored by accuracy) or numerical (scored by Mean Relative Accuracy across tolerance levels 0.50–0.95), with numerical answers concentrated in Ingredient Entry and Memory Management tasks.

## Method

Nutri-Vgent extends the Vgent visual-RAG architecture by replacing its flat retrieved-context pool with a domain-specific structured memory that explicitly decouples three components: Episodic Memory (temporally anchored observations of actions, object states, and locations), Food-State Memory (a ledger tracking canonical identity, estimated quantity, freshness, location, and timestamp for each ingredient), and Recipe Memory (a knowledge graph of 10,000+ recipes linking ingredients, steps, tools, nutritional attributes, and substitutions). During video processing, a sliding temporal window feeds the backbone LVLM, which writes events to Episodic Memory and simultaneously canonicalizes food entities against the recipe vocabulary to update the Food-State ledger; actions like adding, cutting, or discarding are treated as state-changing events rather than isolated captions so the inventory persists after visual evidence disappears. At inference, the agent reconciles the question against all three memories and invokes prompt-level function calls (DishSpec for canonical ingredients/gram weights, FoodByCalories for calorie-constrained substitutions) before generating the final answer, ensuring that recipe constraints are checked against the current food-state ledger rather than retrieved in isolation.

## Results

On NutriBench-Kitchen, Nutri-Vgent (Qwen3-VL-8B backbone) achieves a 62.3% average score across five task families (Ingredient Entry, Long-Term Planning, Memory Management, Recipe Query, Short-Term Planning), outperforming GPT-4o (47.7%) and GLM-4.1V-9B (50.8%) while matching Gemini 2.5 Pro (61.1%). The largest gains appear in Recipe Query (94.1% Hard) and Ingredient Entry (73.3% Hard), where structured food-state memory enables tracking of ingredients that vanish from view. Human performance reaches 92.0% average, revealing a substantial ~30-point gap that persists even for the strongest proprietary models, particularly in quantitative ingredient estimation and long-range state maintenance.

## Baselines & Comparisons

Nutri-Vgent (Qwen3-VL-8B, 62.3% avg) outperforms all open-source baselines: GPT-4o (47.7%), GLM-4.1V-9B-Base (50.8%), Qwen2.5-VL-7B (50.8%), VeBrain-7B (52.6%), InternVL3.5-8B (46.9%), and RoboBrain2.0-7B (45.5%). It also surpasses the proprietary Gemini 2.5 Pro (61.1%) by 1.2 points, with the largest margin in Recipe Query Hard (94.1% vs. 69.3%) and Ingredient Entry Hard (73.3% vs. 14.7%). Against the generic RAG baseline Vgent, Nutri-Vgent achieves a dramatic 30.6-point improvement (62.3% vs. 31.7%), demonstrating that unstructured text retrieval actively degrades performance by polluting context, whereas the decoupled episodic/food-state memory architecture preserves state integrity. The base Qwen3-VL-8B model (53.4%) is improved by 8.9 points with Nutri-Vgent, with the most pronounced gains in tasks requiring tracking of previously observed but no longer visible ingredients.

## Relation to Prior Work

This paper extends the Vgent visual retrieval-augmented generation framework by replacing its generic, unstructured memory pool with a domain-specific tripartite memory (episodic, food-state, recipe) tailored to kitchen dynamics. It carves out a new problem space at the intersection of egocentric video understanding (HD-EPIC, Ego4D), nutrition estimation benchmarks (Nutrition5K, SFOOD), and embodied planning (CookBench, ET-Plan-Bench), arguing that none of these prior resources evaluate the joint loop of continuous state tracking plus knowledge-grounded constraint-aware decision-making. The formalization of 'Embodied Nutrition Management' as a unified task is the paper's primary conceptual departure from prior work, which treats perception, state maintenance, and planning as separate evaluation targets.

## Why It Matters / Open Questions

The benchmark fills a concrete gap: no prior resource tests whether a model can propagate inventory changes across minutes of video and use the accumulated state for later constraint-satisfaction queries. The finding that a 4B model with structured memory (62.1%) outperforms GPT-4o (47.7%) and GLM-4V-9B (50.8%) suggests that explicit state representations may be a more efficient path than parameter scaling for long-horizon embodied reasoning. Open questions include whether the structured-memory advantage generalizes beyond kitchen domains, how the system handles multi-agent or human-in-the-loop settings, and whether the observational (non-interactive) evaluation adequately proxies real closed-loop embodied control.
