## Problem

Existing diagram benchmarks predominantly cover charts, use non-LaTeX code representations (Python, SVG) that cannot compile inline in scientific manuscripts, evaluate only a single task, and provide no agentic evaluation settings. No prior benchmark tests whether MLLMs can simultaneously parse, edit, and reason over diverse scientific diagrams in TikZ code—the format natively used in LaTeX-based vibe writing workspaces like OpenAI Prism.
![Teaser figure](../imgs/ECCV20260245/cropped_page2_idx0.webp)

## Input / Output

For diagram-to-code parsing, the model receives a rendered diagram image plus a fixed preamble (document class, packages, libraries) and must produce a complete standalone TikZ document. For editing, it additionally receives a natural-language modification instruction spanning four dimensions (text, color, scope, layout). For question answering, it receives an open-ended question requiring domain-specific knowledge. In agentic settings, inputs are augmented with pre-extracted diagram objects (perception data), access to a TikZ search MCP server, or a previously generated TikZ code as intermediate state. Outputs are evaluated at three granularities: rendered image similarity (SSIM, CLIP, LPIPS, FID), code syntax (CrystalBLEU), and a Semantic Object Model extracted via DVI→SVG conversion scored on type, text, color, and bounding-box F1.

## Method

Diagram-MMU curates 3,744 TikZ diagrams from official package handbooks (PGFPlots, CircuiTikZ, TKZ-Euclide, ChemFig, TikZ-Network) and community sources (texample.net, TeX Stack Exchange, GitHub), simplifying and filtering them through compilation checks and MLLM-assisted classification into six domains (charts, planar geometry, 3D shapes, graphs, chemistry, circuits). An agentic pipeline with domain-specific templates generates 18,305 evaluation samples for editing and question answering, all cross-validated by 13 graduate students. The evaluation framework defines 16 controllable settings that decompose agentic ability into four axes—context utilization (providing diagram objects), tool use (a TikZ search MCP server built via Mintlify from curated documentation to avoid context rot from full PDF manuals), state management (building on intermediate TikZ code), and planning (coordinating multiple abilities)—enabling fine-grained attribution of where models succeed or fail beyond a single end-to-end score.

## Results

On Diagram-MMU's foundational evaluation (pass@1, averaged over 6 diagram types), DQA accuracy reaches up to 86.5% (Gemini-3.0 Pro), while D2C-P object-level F1_avg ranges from 15.4% (TikZero+10B) to 57.0% (Kimi-K2.5), and D2C-E F1_avg spans 19.0% (Qwen3-VL-8B) to 53.6% (Gemini-3.0 Pro). CrystalBLEU scores are uniformly low (17–38%), indicating that even the best models struggle to reproduce syntactically correct TikZ code. Under agentic settings (300-diagram mini split), Claude-4.6 Opus is the only model that consistently improves across all three tasks (e.g., +5.1 F1_avg on D2C-P planning, +3.8 Acc. on DQA state management), while most other models degrade on DQA by 0.3–8.8 points under planning settings.

## Baselines & Comparisons

The benchmark evaluates 12 MLLMs (6 closed-source, 6 open-source) plus one specialist (TikZero+10B). On DQA, Gemini-3.0 Pro leads at 86.5% accuracy, followed closely by Gemini-3.1 Pro (86.3%) and Gemini-3.0 Flash (84.1%), while Claude-4.6 Opus trails significantly at 68.8% despite its strong agentic performance. On D2C-P object-level F1_avg, open-source Kimi-K2.5 (57.0%) and Qwen3-VL-235B-A22B (56.0%) outperform all closed-source models (47.6–53.3%), and the specialist TikZero+10B (15.4%) underperforms every general-purpose model by 25+ points. On D2C-E, Gemini-3.0 Pro achieves the highest F1_avg (53.6%) and CrystalBLEU (32.8%), while Qwen3-VL-8B collapses to 19.0% F1_avg, a 34-point gap from the best. A key asymmetry emerges: models that fail D2C-P (non-executable code) score 20–40 points lower on D2C-E and DQA, showing that parsing failure cascades into editing and reasoning failures. Under agentic settings, Claude-4.6 Opus is the only model that improves on all three tasks simultaneously, whereas GPT-5.2 and Gemini-3.1 Pro degrade by 4–9 points on DQA under planning, and Gemini-3.1 Pro suffers the largest tool-use penalty (−4.3 F1_avg on D2C-P) due to excessive retrieval.

## Relation to Prior Work

This paper extends the diagram-to-code and chart-understanding benchmark lineage (AutomaTikZ, DeTikZify, ChartE3, CharXiv) in three deliberate ways: it replaces Python/SVG code representations with TikZ/LaTeX (native to scientific authoring environments like Overleaf and Prism), broadens coverage from predominantly charts to six scientific domains including chemistry and circuits, and introduces agentic evaluation settings (context utilization, tool use, state management, planning) that no prior diagram benchmark has attempted. The TikZ search tool built as an MCP server is a novel infrastructure contribution that departs from prior work's reliance on web search or full PDF manuals, addressing the context-rot problem in long-document retrieval.

## Why It Matters / Open Questions

Diagram-MMU is the first benchmark to jointly evaluate foundational and agentic capabilities for scientific diagram tasks, filling a clear gap as vibe writing workspaces (e.g., OpenAI Prism) become central to research workflows. The consistent finding that models reason well over diagrams (up to 86% DQA accuracy) yet struggle to parse them into code (31–57% object-level F1) exposes a fundamental perception-to-code translation bottleneck that current MLLMs have not solved. The agentic results—where most models degrade under planning and tool-use settings, with only Claude-4.6 Opus showing consistent gains—suggest that current agentic scaffolding is insufficient for multi-step diagram tasks. Limitations include the pilot-scale agentic evaluation (300 diagrams) and the fact that the benchmark targets only certain aspects of agentic ability, leaving open questions about whether more thorough planning evaluation would yield different conclusions.
