## Problem

Existing MLLM-based SVG generation adopts an open-loop 'blind drawing' paradigm where models produce symbolic code sequences without perceiving intermediate visual outcomes, severely underutilizing the visual priors in their vision encoders. This disconnect causes models to hallucinate syntactically valid but visually incoherent geometries and fail to reason about partial canvas states and occlusion relationships that are visually explicit but textually ambiguous. The paper asks whether closing the rendering loop—letting the model observe its own incremental canvas—can fundamentally improve vector graphics synthesis.
![Teaser figure](../imgs/ECCV20261761/cropped_page0_idx0.webp)

## Input / Output

The method accepts either a free-form text prompt (text-to-SVG) or a reference raster image (image-to-SVG) and produces a complete SVG XML document. Generation is decomposed into N autoregressive steps, each emitting one code fragment (typically a <path> element); after each step the cumulative canvas is rasterized at 224×224 and encoded into 49 visual tokens via a Vision Transformer, which are interleaved into the context window (max 10240 tokens). A special <END> token signals drawing completion, and the final output is the concatenation of all accepted code segments.

## Method

Render-in-the-Loop reformulates SVG synthesis as a stepwise, visual-context-aware process: at each step the model conditions on the full drawing history (prompt, all prior code fragments, and all intermediate rendered canvases) before generating the next primitive. To make this work, the authors introduce Visual Self-Feedback (VSF) training, which first applies a geometric path-decomposition pipeline (subpath extraction, topology analysis, connected-component merging) to increase the density of intermediate visual states, then fine-tunes Qwen3-VL-8B with standard autoregressive loss over the interleaved multi-turn sequence, masking loss to code tokens only. At inference, a Render-and-Verify (RaV) gatekeeper renders each candidate fragment, rejects it if the pixel-wise canvas change falls below a threshold or if string similarity to the previous fragment exceeds a threshold, and adaptively resamples with increased temperature until a valid step is found. The paper demonstrates that naively feeding intermediate canvases to off-the-shelf models (Qwen3-VL, GPT-5) without VSF training actually degrades performance, confirming that explicit alignment between visual perception and incremental code generation is essential.

## Results

On MMSVGBench-Icon (Text-to-SVG), the full model (VSF+RaV) achieves FID 127.64, CLIP 0.293, Aesthetic 4.86, and HPS 0.251, outperforming OmniSVG-8B (FID 130.56) and InternSVG-8B (FID 128.80) despite training on only 0.85M samples versus 2M and 16M respectively. On MMSVGBench-Illustration (Text-to-SVG), it reaches FID 137.79 and CLIP 0.237. For Image-to-SVG reconstruction, the model attains DINO 0.931 / LPIPS 0.172 / MSE 0.027 on Icon and DINO 0.918 / LPIPS 0.178 / MSE 0.021 on Illustration, surpassing all autoregressive baselines. The inference overhead of the render-in-the-loop mechanism is 1.50× latency (43.19 s vs 28.77 s) with negligible rendering cost (0.038 s).

## Baselines & Comparisons

Against the strongest open-weight autoregressive baselines, Ours (VSF+RaV) achieves the best FID on both subsets (127.64 vs. 128.80 for InternSVG on Icon; 137.79 vs. 138.10 on Illustration) and the highest CLIP, Aesthetic, and HPS scores, despite training on 0.85M samples versus InternSVG's 16M (~20× less data) and OmniSVG's 2M. On Image-to-SVG reconstruction, the model leads all autoregressive methods in DINO, SSIM, LPIPS, and MSE (e.g., LPIPS 0.172 vs. 0.182 for InternSVG on Icon), though DiffVG and LIVE remain stronger on raw pixel-level metrics (LPIPS 0.066, MSE 0.002) at the cost of producing thousands of non-editable paths. The RL-based SVGen (7B) is outperformed on every Text-to-SVG metric (FID 129.23 vs. 127.64; CLIP 0.281 vs. 0.293 on Icon), supporting the paper's argument that dense visual feedback surpasses scalar-reward optimization. GPT-5 is beaten on all Image-to-SVG metrics (DINO 0.931 vs. 0.902; LPIPS 0.172 vs. 0.387 on Icon), and the SFT-only ablation (Qwen3-VL without VSF) lags by 20+ FID points, confirming that the visual self-feedback training is essential rather than a marginal gain.

## Relation to Prior Work

This paper departs from the dominant open-loop paradigm in LLM-based SVG generation (StarVector, OmniSVG, IconShop), where models produce code sequences without perceiving intermediate visual outcomes, and from RL-based approaches (SVGen, ReasonSVG) that compress visual feedback into scalar rewards. It repurposes the vision encoder of multimodal LLMs as an active 'eye' that observes rendered canvas states, closing the generation loop in a way that is conceptually distinct from both blind autoregression and reward-based optimization. The authors explicitly position Render-in-the-Loop as complementary to existing code-domain improvements (specialized tokens, curriculum learning) and RL frameworks, rather than a replacement, and build on the Qwen3-VL architecture and the MMSVG dataset released by OmniSVG.

## Why It Matters / Open Questions

The paradigm of conditioning generation on one's own intermediate renderings is broadly applicable beyond SVG to other code-driven visual synthesis tasks (HTML/CSS, LaTeX/TikZ, 3D rendering, CAD), making it a potentially general framework. Key open questions include whether the purely additive formulation (no undo/delete) limits self-correction, how the 1.5× inference overhead scales with complexity, and whether combining VSF with RL yields compounding gains. The fixed 224×224 canvas resolution and the inability to handle surreal or highly compositional prompts remain practical limitations that constrain real-world deployment.
