## Problem

Existing web agent benchmarks suffer from insufficient website scale and domain diversity, LLM-as-Judge evaluators fail to capture fine-grained interaction semantics such as precise query formulation and filtering operations, and evaluation protocols predominantly measure navigation success while neglecting real-world deployment requirements like leveraging external knowledge and performing end-to-end information extraction.
![Teaser figure](../imgs/ECCV20262257/cropped_page1_idx0.webp)

## Input / Output

NavEval consumes five heterogeneous signals per task: a natural-language task description, the target website URL, the full sequence of HTTP/network requests triggered during interaction, the sequence of executed browser actions, and the final page screenshot. The request sequence is the distinguishing input—after rule-based subdomain matching and payload normalization, it encodes query parameters and filter states invisible to screenshot-only evaluators. The output is a binary success/failure label per task, aggregated into Success Rate (SR) for agent ranking and Human Agreement Rate (AR) for evaluator reliability.

## Method

NavEval operates as a Playwright-based online evaluation pipeline that records screenshots, actions, and all triggered network requests at every step during live agent execution. A rule-based filtering function F_rule matches the raw request set against the task URL at the subdomain level, strips task-irrelevant and random fields, normalizes structured payloads, and eliminates invalid entries, yielding a compact intermediate representation that captures query and filtering semantics. This filtered signal is then jointly reasoned over with the task description, action trajectory, and final screenshot by an LLM judge (Claude-4.5-Sonnet) to produce the binary verdict. The benchmark itself defines three complementary protocols—basic navigation (Protocol I), navigation augmented with LLM-generated operational documentation (Protocol II), and end-to-end task completion requiring multi-modal information extraction (Protocol III)—to disentangle navigation proficiency from answer correctness and knowledge utilization.

## Results

On WebRetriever, NavEval (using Claude-4.5-Sonnet as judge) achieves a 91.2% average Human Agreement Rate (AR) across five web agents, substantially outperforming the best baseline WebJudge (81.0% AR). On the external Online-Mind2Web benchmark, NavEval reaches 97.0% Avg AR versus 87.2% for WebJudge-7B. In terms of agent performance on the benchmark itself, average task Success Rate (SR) drops sharply from 21.1% (Protocol I: navigation only) to 29.2% (Protocol II: navigation + operational docs) to 11.8% (Protocol III: end-to-end with information extraction), with Gemini-2.5-Pro (Computer-Use) as the top agent at 37.1% / 45.2% / 21.0% respectively.

## Baselines & Comparisons

NavEval is compared against four existing automated evaluation methods: Autonomous Eval (Pan et al., 2024), AgentTrek Eval (Xu et al., 2024), WebVoyager (He et al., 2024), and WebJudge (Xue et al., 2025). On WebRetriever with the strongest judge backbone (Claude-4.5-Sonnet), NavEval achieves 91.2% Avg AR, beating WebJudge (81.0%) by 10.2 points, WebVoyager (77.1%) by 14.1 points, Autonomous Eval (75.9%) by 15.3 points, and AgentTrek Eval (62.7%) by 28.5 points. The gap is consistent across all five evaluated agents (SeeAct, Agent-E, Browser-Use, Gemini-2.5-Pro, Claude-4.5), with NavEval exceeding 90% AR in every case. On the external Online-Mind2Web benchmark, NavEval reaches 97.0% Avg AR versus 87.2% for WebJudge-7B and 87.0% for WebJudge with O4-mini, confirming cross-benchmark generalizability. The paper attributes NavEval's advantage to its use of rule-filtered network request sequences alongside screenshots and action traces, enabling precise verification of query execution and filtering operations that screenshot-only or trajectory-only methods miss.

## Relation to Prior Work

This paper extends the web agent evaluation line from navigation-only benchmarks (Mind2Web, WebArena, WebVoyager, Online-Mind2Web) to a multi-protocol framework that additionally assesses knowledge-assisted navigation and end-to-end information extraction. For automated evaluation, it departs from screenshot-based LLM-as-a-judge methods (WebJudge, WebVoyager, AgentTrek) by incorporating rule-filtered network request sequences as an additional signal, arguing that query and filtering semantics are invisible in visual screenshots alone. The dataset construction leverages SimilarWeb traffic rankings and domain-expert task design, positioning WebRetriever as the first benchmark to jointly cover general and professional user intents at 800-website scale.

## Why It Matters / Open Questions

The benchmark exposes a critical gap: even the strongest agents (Gemini-2.5-Pro) achieve only 21% end-to-end success when information extraction is required, roughly half their navigation-only rate, suggesting the field has been over-optimizing for page arrival. Operational documentation provides a modest ~8% boost, indicating agents still struggle to fully leverage external knowledge. Open questions include whether the 800-website coverage captures long-tail sites, whether NavEval's 91–97% human agreement holds as agent behaviors evolve, and how the continuously-maintained dataset will track web content drift over time. For practitioners, the three-protocol decomposition offers a diagnostic lens that prior single-metric benchmarks cannot provide.
