## Problem

Existing visual search-based key frame selection methods for 3D question answering must re-run object detection over all video frames for every individual query, causing runtime to scale linearly with video length and precluding real-time embodied interaction. These methods also lack a recovery mechanism when the underlying vision model fails to detect query-relevant objects, making them brittle to perception failures in complex scenes.
![Teaser figure](../imgs/ECCV20261981/cropped_page1_idx3.webp)

## Input / Output

The system consumes a 3D scan video with per-frame 6-DoF camera poses and a natural language question. The MemTree3D representation is constructed once in real-time (25+ FPS) and is reusable across multi-round queries without reprocessing the video. The VLM receives only k=3 selected key frames (compared to 50+ for uniform sampling baselines), and the final output is a free-form text answer evaluated via LLM-Match or Exact Match.

## Method

MemTree3D is a three-level tree (LocNode → ObjNode → DetNode) built online from 6-DoF pose thresholds (1.5 m translation, 45° rotation) for spatial segmentation, YOLO-World detections, and BoT-SORT tracklets for temporal object relationships. An LLM receives the serialized tree (LocNode and ObjNode levels only) and generates temporal cues (top-k candidate locations) and spatial cues (key objects O_key and cue objects O_cue) through explicit reasoning over scene content. A scoring-based frame selection then picks one representative frame per location by aggregating detection confidences with a 10:1 key-to-cue weighting ratio, approximating query-conditioned semantic alignment under partial observability. This design eliminates per-query visual search entirely, replacing it with a constant-runtime LLM cue generation step, and provides robustness to perception failures because the LLM can infer relevant locations from relational context even when target objects are missing.

## Results

On OpenEQA, MemTree3D with GPT-4o achieves 66.8% LLM-Match (ALL) using only 3 key frames, a +17.4% improvement over GPT-4o uniform sampling (49.4%) and outperforming the best visual search baseline VLM-Grounder (63.0%, 6 frames). With the open-source LLaVA-OneVision-7B, MemTree3D reaches 55.0% LLM-Match, a +5.8% gain over uniform sampling. On ScanQA and SQA3D, MemTree3D (w/ LLaVA-OneVision-7B) achieves 28.0% and 49.6% EM@1 respectively, improving over uniform sampling by +2.9% and +3.4%. The method also achieves a 69.2% runtime speedup over detector-based visual search for key-frame retrieval.

## Baselines & Comparisons

MemTree3D with GPT-4o (66.8% LLM-Match, 3 frames) outperforms the strongest visual search baseline VLM-Grounder (63.0%, 6 frames) by 3.8 points while using half the frames, and surpasses 3D-Mem (57.2%) and CLIP Retrieval (50.6%) by 9.6 and 16.2 points respectively. Against uniform-sampling GPT-4o with 12 frames (62.0%), MemTree3D achieves a 4.8-point gain using only 3 frames. On ScanQA and SQA3D, MemTree3D (w/ LLaVA-OneVision-7B) improves over uniform sampling by +2.9% and +3.4% EM@1, but remains below 3D fine-tuned models like ChatScene (54.6% SQA3D) and LEO (50.0% SQA3D), which the authors attribute to the smaller scene sizes in ScanNet where uniform sampling already provides adequate coverage. The efficiency advantage is substantial: MemTree3D key-frame selection runs in constant time regardless of video length, achieving 69.2% speedup over detector-based visual search, and the gap widens further in multi-round query scenarios where visual search must re-run per query.

## Relation to Prior Work

This paper carves new ground at the intersection of three existing lines of work: scene-graph-based LLM reasoning (ConceptGraphs, SceneGPT), visual-search key frame selection (VLM-Grounder, 3D-Mem), and tree-based video representations (VideoTree). Rather than building directly on any single prior method, MemTree3D repurposes the tree-structured representation idea from long-video understanding and adapts it to 3D embodied settings by using 6-DoF camera poses for spatial segmentation instead of semantic clustering. The key departure from visual search methods is replacing per-query, per-frame detector inference with a one-time tree construction followed by LLM reasoning over serialized structural information, which shifts the computational bottleneck from the vision model to the language model.

## Why It Matters / Open Questions

The practical significance lies in enabling real-time, multi-round 3D question answering on resource-constrained embodied devices: the 69.2% runtime speedup over visual search and the reusable tree representation directly address deployment bottlenecks that prior methods cannot handle. The robustness finding (only 3.1-point drop when query objects are absent from the scene representation) suggests LLM structural reasoning can partially compensate for perception failures, which is important for real-world reliability. However, the more modest gains on smaller ScanNet scenes (vs. large HM3D scenes) indicate the method's advantage is most pronounced in complex, large-scale environments, and the reliance on 6-DoF poses limits applicability to settings where such data is unavailable. Open questions include whether the tree representation can be extended to dynamic scenes or multi-agent settings, and whether the scoring-based selection can be made query-adaptive beyond fixed key-to-cue weighting.
