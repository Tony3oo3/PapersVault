## Problem

Existing CAD deep learning models are confined to task-specific architectures that require structural modifications for each new task, and they predominantly operate on point clouds or images rather than the industry-standard B-rep format. While recent B-rep-based MLLMs align B-reps with natural language captions, they only capture final geometric appearance without the procedural design logic needed for engineering reasoning tasks like sequence generation or error correction.
![Teaser figure](../imgs/ECCV20261551/cropped_page1_idx0.webp)

## Input / Output

The primary geometric input is a B-rep model, which UV-Net encodes into a face-adjacency graph where surfaces are nodes and adjacencies are edges, with surface and curve geometry projected onto 2D and 1D grids respectively, yielding per-surface node features (N×128) and a global shape feature (1×128) concatenated to N×256. Depending on the task, this is combined with a text prompt (reverse engineering), a partially masked CAD code sequence (completion), a CAD code with permuted commands or noisy parameters (error correction), or a multiple-choice question (CAD-QA). The output is Python-like CAD code following an object-oriented syntax with sketch variables, method invocations for geometric primitives, and explicit extrusion references, or a single multiple-choice answer.

## Method

BrepCoder employs a two-phase, two-stage training strategy. Phase 1 aligns B-rep features with CAD code using a CoCa-based framework: a cascaded attentional pooling mechanism first extracts 256 generation queries via multi-head attention over the B-rep features, then a single contrastive query summarizes them globally; the model is trained with a combined contrastive loss (aligning the global B-rep feature with the [EOS] token of the CAD code) and a captioning loss (generating CAD code tokens conditioned on the B-rep feature). Phase 2 freezes the B-rep encoder, inserts a 3-layer linear projector with GELU to map features into the LLM embedding space, and trains a Qwen 2.5-1.5B-Base LLM. Stage 1 pre-trains on reverse engineering (B-rep → complete CAD code) to internalize the geometric-to-procedural mapping, and Stage 2 fine-tunes on completion, error correction, and CAD-QA using the acquired design logic. The key design choice is representing CAD sequences as Python-like code rather than integer tokens, enabling the LLM to leverage its pre-trained programming reasoning for structural and parametric accuracy.

## Results

On the DeepCAD reverse engineering task, BrepCoder achieves a median Chamfer Distance of 0.464×10⁻³, a 52.26% improvement over the previous state-of-the-art CADCL (0.972×10⁻³), along with the best ACC_param (82.01%), the lowest Invalid Ratio (0.86%), and the highest VLM visual fidelity score (4.41/5). On downstream tasks, BrepCoder achieves 92.69% ACC_cmd and 87.94% ACC_param for completion, 99.08% ACC_cmd and 93.74% ACC_param for error correction (CD 0.335×10⁻³, IR 0.32%), and 79% accuracy on CAD-QA with a compact 1.5B model. The only metric where BrepCoder trails a baseline is ACC_cmd on reverse engineering (89.34% vs. CADCL's 90.31%), which the authors attribute to modeling ambiguity (geometrically equivalent shapes produced via different command sequences).

## Baselines & Comparisons

Against B-rep-based baselines, BrepCoder decisively outperforms CADCL on Chamfer Distance (0.464 vs. 0.972×10⁻³), Invalid Ratio (0.86% vs. 13.98%), and VLM score (4.41 vs. not reported), while trailing only marginally on ACC_cmd (89.34% vs. 90.31%) due to modeling ambiguity. BrepCoder dominates DeepCAD and Brep2Seq across all reverse engineering metrics, with CD improvements of over 20× and 68× respectively. On completion, BrepCoder (92.69% ACC_cmd, 87.94% ACC_param) surpasses CAD-Llama (73.87%, 57.14%) by a wide margin, demonstrating that B-rep input encodes far more precise geometric information than natural language descriptions. On error correction, BrepCoder (CD 0.335×10⁻³, ACC_param 93.74%) dramatically outperforms GPT-5 (CD 399.78, ACC_param 43.41%) and Gemini-2.5 (CD 350.30, ACC_param 42.30%), confirming that 2D image inputs cannot recover precise 3D spatial parameters. On CAD-QA, BrepCoder's 1.5B model achieves 79%, only 2% behind the 7B PointLLM (81%) and outperforming ShapeLLM (73%) and MiniGPT-3D (78%), despite being pre-trained solely on code-based reverse engineering rather than large-scale 3D-text QA data.

## Relation to Prior Work

BrepCoder sits at the intersection of three research threads: B-rep geometric encoding (UV-Net's face-adjacency graph with UV projections), multimodal alignment (CoCa's joint contrastive-and-captioning objective), and LLM-based CAD code generation (CAD-Llama's Python-like SPCC format). It departs from prior B-rep-to-sequence methods (DeepCAD, Brep2Seq, CADCL), which are rigid task-specific architectures trained from scratch, by unifying reverse engineering, completion, error correction, and QA under a single MLLM. It also moves beyond BrepLLM, which aligns B-reps only with natural-language captions for descriptive tasks, by aligning B-reps with procedural CAD code that encodes design logic rather than just final geometry.

## Why It Matters / Open Questions

This is the first unified MLLM that treats B-rep—the industry-standard CAD format—as its core input modality for multi-task reasoning, addressing a practical gap where prior work focused on point clouds or images. The two-stage strategy (reverse-engineering pre-training → multi-task fine-tuning) demonstrates that internalizing design logic from a single task transfers effectively to downstream tasks, particularly CAD-QA where the 1.5B model reaches 79% versus 81% for a 7B point-cloud model. Open questions include whether the approach scales to more complex B-rep topologies, whether the modeling ambiguity (multiple valid sequences for one shape) can be resolved with better evaluation metrics, and whether extending to point-cloud inputs as the authors plan will maintain the B-rep-specific advantages.
