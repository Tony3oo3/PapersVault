## Problem

Image-conditioned image editing (ICIE), where edits are guided by both a reference image and a text instruction, lacks a large-scale unified open-source dataset. Existing ICIE data is small (~10K samples), restricted to concrete-object edits, and constructed via costly forward synthesis that introduces model bias and distributional artifacts. This paper reframes ICIE data construction as a reference-completion problem, showing that high-quality TCIE datasets already supply three of the four required elements and only need an aligned reference image synthesized.

## Input / Output

Each ICIE example is a quadruplet of (input image, reference image, text instruction, target image) at 1024 resolution. The input image serves as a structural anchor whose unedited regions must be preserved, while the reference image acts purely as a conditioning signal—either a concrete object (e.g., a red handbag) or an abstract attribute (e.g., photographic tone, artistic style). For the remove category, the instruction is supplemented with a spatial cue (bounding box, binary mask, or cropped exemplar) to disambiguate which instance to excise. The output is a single edited image that applies the specified modification while retaining the anchor's overall structure.

## Method

The pipeline converts existing TCIE triplets (from Pico-Banana-400K and GPT-Image-Edit-1.5M) into ICIE quadruplets by synthesizing only the missing reference image. A VLM (GPT-4o) first classifies each edit into one of six types (add, remove, replace, background, style, alter), generates reference-synthesis prompts, and rewrites the instruction to reference the supplementary image; it also produces a deliberately weakened instruction that abstracts reference-specific details to force the model to attend to the visual reference rather than text alone. Type-specific synthesis then generates the reference: segmentation plus personalization for add/replace, bounding-box overlay or crop for remove, foreground inpainting for background, and T2I generation followed by GPT-Image-1.5 attribute transfer for style/alter. A five-dimensional VLM-based post-filter independently scores each quadruplet on reference compatibility, reference reasonableness, instruction correctness, original-pair correctness, and reference-target similarity, retaining only samples that pass all thresholds. Validation uses LoRA fine-tuning on Flux-Kontext and Qwen-Image-Edit-2509 (diffusion) and full fine-tuning on Janus-Pro (autoregressive), with evaluation on the MultiBanana two-reference benchmark.

## Results

On the MultiBanana two-reference benchmark (GPT-4o scored, 1–10 scale), LoRA fine-tuning Flux-Kontext on RCEdit-500K raises the average score from 2.82 to 4.04 (+1.22), with the largest gains on Background-Subject Match (2.39→4.76) and Physical Realism (2.94→5.50). Qwen-Image-Edit-2509 improves from 4.31 to 4.56, and the autoregressive Janus-Pro jumps from 1.03 to 4.43, surpassing both Qwen-Image-Edit-2509 and Omnigen2. The best open-source model (Flux-Klein-9B, 4.75) still trails the closed-source GPT-Image-1.5 (5.51) by 0.76 points.

## Baselines & Comparisons

Flux-Kontext (2.82) and Janus-Pro (1.03) serve as weak-baseline anchors; RCEdit-500K fine-tuning lifts them to 4.04 and 4.43 respectively, with Janus-Pro+RCEdit surpassing both Qwen-Image-Edit-2509 (4.31) and Omnigen2 (3.93). Qwen-Image-Edit-2509 (4.31) improves modestly to 4.56 with RCEdit, approaching but not matching the newer Qwen-Image-Edit-2511 (4.58) that was full-fine-tuned on larger data. DreamOmni2 (4.54) and the Flux-Klein family (4.71–4.75) represent the strongest open-source baselines and remain ahead of the RCEdit-fine-tuned models. The closed-source GPT-Image-1.5 (5.51) and Nano Banana (4.67) maintain a clear lead over all open-source entries, with GPT-Image-1.5 leading by 0.76 over the best open-source model (Flux-Klein-9B, 4.75). In the training-data ablation (Table 5), RCEdit-60K (3.68) outperforms both ImgEdit (2.92) and AnyEdit (2.97) at matched scale, confirming that data quality and coverage—not just volume—drive ICIE performance.

## Relation to Prior Work

This paper departs from the dominant forward-synthesis paradigm for ICIE data construction (used by ImgEdit, AnyEdit, and DreamOmni2) by reframing the problem as reference-completion: existing high-quality TCIE triplets (input, instruction, target) already supply three of four required elements, so only the reference image needs to be synthesized. Conceptually, it also distinguishes ICIE from multi-image personalization/combination (DreamO, USO, DreamOmni2), where images share equal semantic priority, by explicitly designating one image as a structural anchor that must be preserved. The pipeline inherits its semantic coverage and edit distributions from curated TCIE corpora (Pico-Banana-400K, GPT-Image-Edit-1.5M) rather than generating them from scratch, and introduces weak-instruction augmentation and five-dimensional VLM post-filtering as quality-control mechanisms not present in prior ICIE data pipelines.

## Why It Matters / Open Questions

As the first large-scale unified open ICIE dataset covering all six edit types with both concrete and abstract references, RCEdit-500K removes the data-availability bottleneck that has held back open-source reference-guided editing, and the reference-completion pipeline offers a reusable, low-cost recipe for scaling to future TCIE corpora. The demonstration that an autoregressive model without native editing capability (Janus-Pro) reaches competitive ICIE performance purely through data training reinforces that data quality, not architecture, is the limiting factor. Open questions include whether the closed-source dependency on GPT-Image-1.5 for style/alter synthesis can be replaced by open models, whether VLM-based evaluation (GPT-4o) introduces systematic bias, and whether the 1024-resolution, single-reference formulation generalizes to multi-reference or video editing settings.
