## Problem

3D Gaussian Splatting and NeRF achieve photorealistic novel view synthesis but suffer from substantial storage and rendering overhead in scenes with repetitive structures, as each instance is independently encoded and rendered. Existing acceleration methods optimize individual Gaussians or network architectures but overlook the fundamental redundancy in repetitive content, leaving no mechanism to share representation across similar objects at the GPU rendering level.
![Teaser figure](../imgs/ECCV20261059/cropped_page0_idx1.webp)

## Input / Output

The method takes a pre-trained 3DGS representation and brief text prompts identifying repetitive object categories (e.g., 'chair', 'car'), which drive Grounding DINO for 2D detection and SAM for pixel-level masks. It produces a compact shared Gaussian template (containing position, scale, rotation, SH coefficients, and opacity) plus lightweight per-instance offsets on position, base color, and opacity, along with background Gaussians. The rendered output is a novel-view image, with the key structural difference being that K instances share one template rather than each storing a full Gaussian set.

## Method

InstGS introduces a three-stage pipeline: (1) gradient-driven instance segmentation that uses cross-frame consistent 2D masks (from Grounding DINO + SAM + view consensus) to compute per-Gaussian gradients via a masked MSE loss, separating instance Gaussians from background without additional training; (2) template initialization by registering similar instances via FPFH + ICP and performing merge-and-sampling to produce a shared geometric template; (3) a differentiable instancing rasterizer implemented as a custom CUDA kernel that applies a per-instance transformation matrix and additive offsets (position, base color, opacity) to each template Gaussian during rendering. The template, offsets, and background are jointly optimized end-to-end using the standard 3DGS L1 + D-SSIM loss, with gradients backpropagated through the transformation via its Jacobian. This decoupling of shared structure from per-instance variation enables GPU heterogeneous instancing, reducing memory from storing N×K Gaussians to N + K×(offsets) while maintaining full differentiability.

## Results

On the synthetic ReScene benchmark, InstGS achieves 35.2 dB PSNR and 204 FPS with only 20.4 MB CPU memory, matching the PSNR of Hierarchical 3DGS (3DGS*) while using ~10× less memory and rendering 70% faster. On real-world scenes, InstGS attains the best PSNR (27.8 dB), highest FPS (128), and lowest CPU memory (37.9 MB) among all compared methods. Compared to the closest compression baselines (OctreeGS, CompactGS), InstGS trades a marginal SSIM/LPIPS difference (≤0.003) for substantially lower memory and higher frame rates.

## Baselines & Comparisons

Against the primary 3DGS baseline, InstGS matches PSNR on synthetic (35.2 vs 34.9) and exceeds it on real scenes (27.8 vs 27.4), while reducing CPU memory from 198–313 MB to 20–38 MB and boosting FPS from 98–117 to 128–204. Versus the closest compression baselines OctreeGS and CompactGS, InstGS achieves higher PSNR on both splits (e.g., 27.8 vs 27.6 and 26.9 on real) and lower memory (37.9 MB vs 53.2/42.3 MB), at the cost of a small SSIM drop (0.913 vs 0.915/0.906 on real). Against Splat&Replace, which shares a similar instance-substitution concept, InstGS dramatically outperforms on every metric (PSNR 35.2 vs 23.8 synthetic; 27.8 vs 19.9 real), confirming that learnable offsets are far more effective than rigid copying. Compared to the NeRF-based InstantNGP, InstGS wins on all five metrics by wide margins (e.g., 35.2 vs 33.1 PSNR, 20.4 MB vs 3.8 GB memory on synthetic). Against SOG, InstGS achieves higher PSNR (35.2 vs 32.4 synthetic) and lower memory (20.4 vs 212.0 MB) while also rendering faster (204 vs 189 FPS). The only consistent trade-off is a slight SSIM/LPIPS gap versus OctreeGS on synthetic (0.983/0.026 vs 0.985/0.016), which the authors attribute to the inherent approximation of a shared template.

## Relation to Prior Work

This paper extends 3D Gaussian Splatting by introducing a GPU-level instancing mechanism that prior 3DGS acceleration methods (SOG, OctreeGS, CompactGS, HAC) do not address, as those focus on per-Gaussian compression or hierarchical LOD rather than exploiting cross-instance redundancy. It builds conceptually on instance-based Gaussian work such as ProcGS and Splat-and-Replace, which perform instance decomposition and replacement, but departs from them by replacing CPU-side Gaussian duplication with a differentiable template-and-offset rasterizer executed entirely on the GPU. The gradient-driven segmentation module adapts ideas from InstaScene and prior 2D-to-3D mask lifting, but repurposes them specifically to extract reusable Gaussian subsets without additional training cost.

## Why It Matters / Open Questions

InstGS demonstrates that a large fraction of storage and compute in repetitive scenes is fundamentally redundant, and that a shared template with three lightweight offset channels (position, base color, opacity) can recover per-instance fidelity at roughly 10× lower memory with comparable PSNR. This opens a practical path toward interactive rendering of large repetitive environments (stadiums, parking lots, urban furniture) on resource-constrained hardware. However, the authors explicitly note the method is not a general acceleration technique—gains scale with repetition count and spatial coverage—leaving open how to automatically detect and group instances without user prompts, and how to extend the framework to dynamic or partially overlapping instances.
