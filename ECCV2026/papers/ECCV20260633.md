## Problem

Chinese font production requires converting raster design drafts into editable Bezier vector glyphs while simultaneously eliminating redundant control points, detecting geometric defects, and correcting local anomalies — yet existing toolchains treat these as separate pipeline stages relying on explicit geometric rules that cannot capture implicit designer priors. No prior work unifies all four operations (vectorization, sparsification, defect marking, correction) within a single model, and general-purpose MLLMs lack the fine-grained topological control needed for industrial-grade glyph geometry.

## Input / Output

The model consumes a raster glyph image at native resolution (no forced resizing), an SVG XML code string encoding the current Bezier contour using the instruction set {M, L, H, V, C, Q, Z}, an optional set of K reference glyphs from the same font, and a natural-language task instruction. Output is always an autoregressively generated SVG XML sequence: a fully vectorized glyph, a sparsified/optimized contour, a defect-annotated variant with geometry preserved, or a geometrically corrected contour. The code-space representation means the model reasons over discrete drawing commands and coordinate parameters rather than continuous pixel values.

## Method

FontCopilot serializes Bezier glyph contours into declarative SVG XML, reframing all four font engineering tasks as structured code understanding and rewriting within a single MLLM built on Qwen-2.5-Coder-7B. A 16-layer native-resolution vision encoder uses progressive multi-scale window attention (window sizes 2→4→8→16) with 2D RoPE to preserve stroke topology, followed by 2×2 spatial aggregation and an MLP projection to compress visual tokens by 4× before injection as prefix embeddings. A multi-scale feature projection mechanism performs residual injection of visual features into three intermediate decoder layers, allowing the model to repeatedly reference geometric details during long-range SVG generation without increasing sequence length. Training follows a three-stage progressive strategy: (1) frozen-LLM vision alignment, (2) full-model SVG rewriting from non-canonical to canonical code, and (3) multi-task instruction tuning with reference dropout and a complexity curriculum. At inference, two complementary paradigms are supported: few-shot reference-guided mode (K≈3 reference glyphs inject font-specific topological preferences) and zero-shot universal mode (relying solely on internalized design priors for cross-font generalization).

## Results

On the CFCopilot-8M benchmark, FontCopilot achieves IoU 0.925 / CD 0.0355 on glyph vectorization, IoU 0.965 with a 76.52% node reduction ratio on vector optimization, IoU 0.938 / CD 0.0519 on defect detection, and IoU 0.908 / CD 0.0455 on geometric correction, outperforming all 8 baselines on every metric. In the human evaluation with 20 professional type designers, FontCopilot scores 4.12–4.22/5 across all four task-specific quality criteria (vs. 4.52–4.65 for ground truth) and reduces per-glyph fix time to 24.5 s, compared to 184.1 s for manual work and 45.4 s for the strongest MLLM baseline (Qwen3-VL-8B).

## Baselines & Comparisons

FontCopilot is compared against two traditional vectorization tools (Potrace, Adobe Image Trace) and six instruction-tuned MLLMs (StarVector-8B, DeepSeek-VL-7B, Qwen2.5-VL-3B, Yi-VL-6B, LLaVA-V1.6-7B, Qwen3-VL-8B). Traditional tools (Potrace, AIT) achieve the highest raw vectorization IoU (0.978/0.982) but produce excessive geometric redundancy and cannot perform optimization, defect detection, or correction at all. Among MLLM baselines, Qwen3-VL-8B is the strongest competitor, yet FontCopilot still leads by a clear margin: +6.0 IoU on vectorization (0.925 vs 0.865), +4.2 IoU and +4.64 pp RR on optimization (0.965/76.52% vs 0.923/71.88%), +6.3 IoU on defect detection (0.938 vs 0.875), and +8.3 IoU on geometric correction (0.908 vs 0.825). The gap widens substantially on the CD (Chamfer Distance) metric, where FontCopilot achieves 0.0355 on vectorization versus 0.0645 for Qwen3-VL-8B, indicating markedly better geometric fidelity. In the human evaluation, FontCopilot's 24.5 s fix time is roughly 7.5× faster than manual work (184.1 s) and 1.8× faster than the best MLLM baseline, while scoring within 0.4–0.5 points of ground-truth quality on all four criteria.

## Relation to Prior Work

This paper repurposes the MLLM code-generation paradigm (as explored by StarVector for general SVG synthesis) and applies it specifically to Chinese font engineering, where prior work has treated vectorization, contour optimization, defect detection, and geometric correction as separate pipeline stages relying on explicit geometric rules or local error metrics. It departs from optimization-based vector font reconstruction (Im2Vec, DeepVecFont, VecFusion) by replacing iterative coordinate fitting with autoregressive SVG XML rewriting, and from raster-based Chinese font generation (GAN, diffusion) by operating entirely in the vector parameter space. The architecture builds on Qwen-2.5-Coder-7B with a native-resolution vision encoder and multi-scale cross-layer visual injection, extending the standard MLLM template with domain-specific geometric fidelity mechanisms.

## Why It Matters / Open Questions

The CFCopilot-8M dataset (300 fonts, 8M samples) and the unified four-task framework provide the first end-to-end MLLM solution for industrial Chinese font production, reducing per-glyph fix time from ~184 s (manual) to ~25 s in human evaluation. A key open question is whether the learned priors, partially derived from algorithmically generated data, transfer robustly to highly stylized or historically novel typefaces not represented in the training distribution. The paper also flags a significant ethical concern: the same capability that automates font engineering could enable unauthorized reconstruction of commercial fonts, raising IP and licensing questions that the field has not yet addressed.
