## Problem

Existing spatial intelligence benchmarks evaluate agents from a passive 'Spectator View'—single images or pre-recorded video—preventing the resolution of geometric ambiguity through active viewpoint change (e.g., parallax). More fundamentally, VLMs process context as a flat 1D token stream that is structurally incommensurate with 3D non-Euclidean environments, causing catastrophic spatial forgetting as trajectory length grows. The paper addresses both gaps: a benchmark that demands interactive movement, and an architectural fix for the representation mismatch.

## Input / Output

At each step the agent receives only a first-person 1024×768 RGB panorama and a relative bearing; GPS coordinates, depth maps, and bird's-eye views are deliberately withheld to mirror human pedestrian perception. The action space is restricted to spatial displacement, viewpoint rotation, and Stop. Outputs are navigation actions (for the navigation sub-tasks), scalar metric estimates (distance, building height, angular bearing), and a persistent Explicit Topological Memory graph whose nodes store integer-metre coordinates and camera orientations, serialized at each decision step into a fixed-length token snapshot ([POSITION], [PATH], [OBSERVATION LOG]) that replaces all prior dialogue history.

## Method

Spatial-IDE is a training-free cognitive scaffold built on two mechanisms. First, State Externalization replaces the growing linear dialogue history with an Explicit Topological Memory (ETM): a dynamic graph whose nodes record visited viewpoints with absolute coordinates and camera orientation, whose edges encode physical displacement and bearing, and whose per-node annotations accumulate compact Semantic Notes; because the ETM is a program-level data structure (integer-metre coordinates) rather than a language-model context, it does not drift or degrade over time. Second, Cognitive Decoupling splits each step into two stateless, single-turn VLM invocations: a Goal-Directed Perception call that answers a precise, decision-relevant query formulated by the reasoning engine (e.g., 'Is the pharmacy sign visible, and at what bearing?') and returns only a short factual proposition, and a Spatial Reasoning Engine call that receives the fixed-size ETM snapshot plus the current panorama to select the next action and simultaneously formulate the next perception query. This closed perception–decision loop ensures every VLM call operates on a bounded, uniform input regardless of episode length, eliminating the compounding attention drift and landmark dilution that plague linear-context baselines.

## Results

On WalkerBench (161 cities, 1,000 tasks), the average Total accuracy across nine VLMs rises from 18.17% (Original linear-context setting) to 36.66% with Spatial-IDE, a +104.97% relative improvement. The best agent, Claude-Opus-4.6, reaches 43.17% with Spatial-IDE versus 24.49% without, still trailing the human reference of 69.43% by 26.26 points. Per-sub-task, Visual Localisation sees the largest proportional gain (+166.1%, from 11.43% to 30.41%), while Navigation improves from 34.67% to 52.92%. Metric sub-tasks (Height, Distance, Angle) all roughly double, reaching 37.11%, 32.11%, and 30.78% respectively.

## Baselines & Comparisons

All nine evaluated VLMs are tested in two settings: Original (standard multi-turn dialogue) and w/ Spatial-IDE, so the primary comparison is each model against itself. Spatial-IDE improves every model without exception, with relative gains ranging from +76.28% (Claude-Opus-4.6, already the strongest) to +138.69% (GLM-4.6V, the weakest). GPT-5-chat-latest starts last among proprietary models (17.17%) but gains +119.98% to reach 37.77%, suggesting its original failure is context-management rather than perceptual. Among open-source models, Qwen3-VL-235B (35.91%) and Kimi-K2.5 (39.74%) close much of the gap to mid-tier proprietary models under Spatial-IDE, while the 8B Qwen3-VL jumps from 14.66% to 32.17%. Even the best agent (Claude-Opus-4.6 at 43.17%) remains 26.26 points below the human reference (69.43%), with the largest residual gap in Visual Localisation (38.57% vs. 68.86%), indicating that cross-view grounding is still an open challenge.

## Relation to Prior Work

This paper positions itself against two lines of prior work: static spatial-intelligence benchmarks (VSR, Spatial-Bench, SpatialRGPT) and video-based counterparts (Ego4D, MMSI-Video-Bench), which it collectively terms the 'Spectator View' paradigm, and indoor VLN benchmarks (Habitat, Room-Across-Room, StreetLearn) that are geographically and topologically limited. Conceptually, Spatial-IDE draws on the cognitive-scaffold framework of Sumers et al. (2023) and the reasoning-acting decoupling of ReAct (Yao et al., 2022), but repurposes them for embodied navigation by externalizing spatial state into an explicit topological graph rather than keeping it in the model's context window. The key departure is the formal diagnosis of 'representation misalignment'—the structural incompatibility between 1D autoregressive token streams and 3D non-Euclidean topology—which reframes the navigation failure as an architectural property rather than a data or capacity shortfall.

## Why It Matters / Open Questions

The 26-percentage-point gap between the best agent with Spatial-IDE (43.17%) and the human reference (69.43%) underscores that interactive spatial intelligence remains far from solved, and the finding that this gap is structural (persistent across model scales from 8B to 235B parameters) suggests that simply scaling VLMs will not close it without architectural changes to how spatial state is represented. The zero-shot transfer to a Unitree G1 humanoid robot is a meaningful validation that explicit topological memory generalizes beyond the benchmark, though the demonstrated routes are relatively short and the deployment lacks quantitative success-rate reporting. Open questions include whether ETM-based scaffolding scales to truly long-horizon (kilometer-scale) navigation, how it interacts with learned (rather than prompted) spatial representations, and whether the benchmark's 1,000-task scale is sufficient to distinguish subtle architectural differences.
