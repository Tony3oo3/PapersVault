## Problem

Dense voxel representations preserve fine-grained 3D spatial details but are too expensive to process across multiple frames, while streaming paradigms that recurrently update propagated features have only been applied to sparse representations (Gaussians, compressed BEV features) that inherently limit spatial fidelity. Naively combining dense voxels with streaming introduces two critical failures: warping-induced distortions from interpolation-based temporal alignment, and degraded dynamic object representations due to motion misalignment and information loss in image-to-voxel projection.

## Input / Output

The method consumes N multi-view RGB images (resized to 256×704) at the current timestep along with ego-motion transforms between consecutive frames. It produces a 200×200×16 voxel occupancy grid (0.4 m resolution on Occ3D-nuScenes, 0.5 m on SurroundOcc) with per-voxel semantic labels across 16–17 classes, plus 900 instance-query detections for dynamic objects. Internally, voxel features are processed at a downsampled 100×100×8 resolution with 64 channels before being upsampled for the final prediction, keeping peak memory at 2.8 GB.

## Method

StreamOcc integrates two aggregation stages. StreamAgg recurrently accumulates dense voxel features by warping the previous timestep's voxel grid into the current ego frame via trilinear interpolation, then applying an Adaptive Residual Refinement module (bottleneck 3D convolutions + 3D CBAM) whose spatial attention is supervised with a binary occupied mask (geometry) and whose output is supervised to predict current-frame occupancy (semantic), thereby suppressing interpolation artifacts before fusing with the current frame's voxel features via a 1D convolution. QueryAgg addresses dynamic-object degradation by first refining instance queries (from a Sparse4Dv3-based Image-to-Query detector) with deformable attention over voxel features to resolve depth ambiguity, then performing Dynamic Query Aggregation: a gated query-to-voxel attention that selectively injects instance-level semantic features only into voxel cells whose predicted bounding boxes overlap, leaving static and empty regions untouched. This targeted injection contrasts with prior spatial cross-attention approaches that redistribute image features across all voxels, reducing hallucinated mappings and unnecessary computation while yielding +2.7 mIoU on dynamic objects.

## Results

On Occ3D-nuScenes, StreamOcc achieves 41.9 mIoU and 38.1 mIoU_D (dynamic objects) at 83.3 ms per frame with 2.8 GB memory, the best accuracy among real-time methods. On SurroundOcc, it reaches 33.8 IoU, 23.4 mIoU, and 21.0 mIoU_D at 84 ms with 2.8 GB memory. On the RayIoU metric (ray-wise consistency), StreamOcc scores 41.1, outperforming all prior real-time approaches.

## Baselines & Comparisons

StreamOcc outperforms the prior best real-time method ALOcc-mini [2] by +1.3 mIoU and +2.5 mIoU_D on Occ3D-nuScenes, while also surpassing other real-time baselines including GSD-Occ (+2.5 mIoU), OPUS (+6.3 mIoU), and ViewFormer (+2.3 mIoU, +4.8 mIoU_D) at comparable or lower latency. Against multi-frame dense-voxel methods (COTR, ALOcc, PanoOcc), StreamOcc trades 2.6–3.1 mIoU for dramatically lower cost: it is 13× faster than COTR (83.3 vs. 1111.1 ms) with 3.7× less memory, and 4× faster than PanoOcc with 4.3× less memory. On SurroundOcc, StreamOcc beats the prior best GaussianWorld [42] by +1.5 mIoU and +2.0 mIoU_D while running 2.7× faster (84 vs. 228 ms) and using 2.5× less memory (2,788 vs. 7,030 MB). On RayIoU, StreamOcc (41.1) leads all real-time methods, exceeding OPUS (40.3) and ALOcc-mini (39.3). The method does not match the absolute accuracy of the highest-performing multi-frame methods (ALOcc at 45.0 mIoU, COTR at 44.5 mIoU), but those incur 2–13× higher latency and 3.7–3.8× more memory, making them impractical for on-vehicle deployment.

## Relation to Prior Work

StreamOcc sits at the intersection of two established threads in 3D occupancy prediction: dense voxel-based multi-frame fusion methods (COTR, PanoOcc, GEOcc) that achieve high accuracy at substantial computational cost, and streaming/recurrent temporal modeling (Sparse4Dv3, StreamMapNet) that has been applied to sparse representations like Gaussians (GaussianWorld) or compressed BEV features (ViewFormer). The paper's core departure is demonstrating that dense voxel streaming—previously considered impractical due to warping distortions and dynamic-object degradation—becomes viable when paired with targeted rectification (StreamAgg) and instance-query injection (QueryAgg). It directly builds on Sparse4Dv3 for the streaming query mechanism and borrows the CBAM-style attention design for geometry-aware residual correction, while the auxiliary mask decoder draws from COTR's semantic-aware group decoder.

## Why It Matters / Open Questions

By achieving state-of-the-art accuracy on both Occ3D-nuScenes and SurroundOcc at 83.3 ms and 2.8 GB, StreamOcc makes dense-voxel-level occupancy prediction practically deployable on-vehicle, closing the gap between high-accuracy multi-frame fusion (which requires 10+ GB and 100+ ms) and efficient but lower-fidelity sparse methods. The ablation finding that an auxiliary detection head provides only marginal gains (+0.4 mIoU_D) while direct query-to-voxel injection yields +2.7 mIoU_D offers a clear design principle: dynamic-object enrichment requires targeted, instance-level feature injection rather than indirect multi-task supervision. Open questions include whether the streaming memory footprint (2.8 GB for a single propagated voxel grid) can be further compressed for embedded hardware, and whether the approach generalizes to higher-resolution grids or additional sensor modalities (LiDAR, radar).
