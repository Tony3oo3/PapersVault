## Problem

Standard self-improvement pipelines for computer-use agents fine-tune exclusively on successful trajectories and discard all failed ones, despite the substantial cost of generating trajectories in verifiable environments. This paper asks whether failed trajectories can be repurposed as a structured source of supervision to improve agents at inference time, without any additional training.
![Teaser figure](../imgs/ECCV20262321/cropped_page1_idx0.webp)

## Input / Output

The agent consumes a screenshot of the current computer state, a natural-language task instruction, and its accumulated action history to produce the next GUI action (click, type, drag, etc.). The meta-controller LLM additionally ingests full failed trajectories—including instruction, action sequence, and internal thought traces—to diagnose failure modes and emit targeted code patches. These patches are injected into the agent's inference pipeline as behavioral modifications (e.g., a zoomed-in verification step after each grounded action, a hotkey-triggered terminal, or a repetition-warning trigger), so the agent's output space is extended beyond raw GUI actions to include auxiliary tool invocations and self-correction signals.

## Method

The paper introduces a failure-case loop in which an LLM meta-controller (Claude 4.5 Sonnet) analyzes collected failed trajectories, categorizes them into four recurring failure modes—grounding errors, competency gaps, knowledge deficiencies, and redundant action loops—and proposes a corresponding inference-time code patch for each. The four resulting strategies are: (1) visual search, which crops a zoomed-in region around the target of every spatially grounded action and prompts the agent to self-verify before proceeding; (2) terminal execution, which activates a command-line interface via hotkey to bypass complex GUI manipulation; (3) knowledge support, combining a curated software-manual retriever with a search-engine interface for domain-specific queries; and (4) repetition detection, which monitors a sliding window of thought, action, and screen-state traces and triggers a recovery mode when stagnation is detected. Over four rounds of the loop, patches accumulate and are lightly verified by humans (over 97% accepted unmodified), yielding a +6.6-point absolute gain on OSWorld (42.3%→48.9%) with no weight updates and only ~8% runtime overhead.

## Results

On OSWorld (100-step evaluation), the failure-case loop improves OpenCUA-72B from 42.3% to 48.9% success rate (+6.6 points absolute, +15.6% relative) with no additional training cost and only ~8% runtime overhead. The ablation on the OSWorld small set (30 steps) shows each strategy contributes individually (visual search: 47.22, terminal execution: 47.19, repetition detection: 44.40, knowledge support: 44.44) and combining all four yields 52.74%. Cross-benchmark transfer of OSWorld-mined patches to Qwen3-VL-32B-Instruct yields consistent gains: OmniACT 4.77→6.90, AndroidControl 28.37→36.23, ScreenSpotPro 27.50→30.74, and WebVoyager 23.80→27.90.

## Baselines & Comparisons

The primary comparison is against OpenCUA-72B (42.3%), the strongest open-source computer-use agent at the time, which the failure-case loop improves to 48.9%—surpassing all proprietary baselines including OpenAI CUA o3 (42.9%, 200 steps) and UI-TARS-1.5 (42.5%, 100 steps) while using the same 100-step budget. Among open-source baselines, the method also outperforms Agent S2 w/Gemini-2.5-Pro (41.4%, 50 steps) and Agent S2 w/Claude-3.7-Sonnet (34.5%, 50 steps) by a wide margin. Cross-model generalization shows consistent +10–12% relative gains on OpenCUA-32B (34.5→38.2) and GUI-Owl-32B (19.0→21.3), confirming the framework is model-agnostic. Cross-benchmark transfer (Table 3) demonstrates that patches mined from OSWorld generalize to four heterogeneous environments, with the largest gains on AndroidControl (+7.86 pts) and WebVoyager (+4.10 pts), both involving long-horizon planning. Notably, the method achieves its headline result without any weight updates, distinguishing it from training-based baselines like UI-TARS-72B-DPO and OpenCUA's own SFT loop.

## Relation to Prior Work

This paper carves out a complementary position relative to the dominant success-driven self-training paradigm (OpenCUA, UI-TARS, Mobile-Agent), where agents are iteratively fine-tuned on successful trajectories and all failures are discarded. Rather than extending that loop, it repurposes the discarded failure data as a structured signal: an LLM meta-controller diagnoses failure modes and emits inference-time code patches, bypassing any weight update. It also distinguishes itself from self-evolving agent work (SEAgent, SEA, UI-Genie) that learns from trial-and-error through training, by operating entirely at inference time with lightweight human verification. The failure-mode taxonomy (grounding, competency, knowledge, redundancy) aligns with prior error-analysis studies but is novel in being directly converted into deployable patches.

## Why It Matters / Open Questions

The practical significance is that a 6.6-point OSWorld gain is achieved with zero training cost and only ~8% runtime overhead, making it a drop-in amplifier for any existing computer-use agent pipeline. The cross-benchmark transfer (patches mined from OSWorld improving Android, Web, and grounding benchmarks) suggests the identified failure patterns are genuinely general rather than environment-specific. However, the paper itself notes that after low-level bottlenecks are resolved, remaining failures shift to higher-level cognitive limitations (task misinterpretation, multi-step planning, reasoning consistency) that the current framework does not address. Open questions include whether learned reward models can eliminate the residual human-in-the-loop step, whether the loop scales beyond four rounds without diminishing returns, and whether the approach transfers to non-OSWorld action spaces without re-mining.
