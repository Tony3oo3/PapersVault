## Problem

Existing embodied agent frameworks rely on oracle perceptual APIs (global object lists, target 3D poses, simulator states) that are unavailable in physical deployment, and they assume complete, unambiguous user instructions, ignoring the need for dynamic human-robot dialogue to resolve intent. These two oversimplifications—privileged perception and open-loop execution—create a systematic sim-to-real gap that causes deployment failures for long-horizon mobile manipulation.

## Input / Output

At each step the VLM receives an ego-centric RGB image annotated with Set-of-Mark visual IDs, a structural prior listing receptacle IDs and semantic categories (from a pre-built 3D occupancy map), the task instruction (which may be deliberately ambiguous), and a compressed history tuple consisting of the previous environmental observation, the previous action, and a VLM-generated summary of completed sub-goals. The model outputs internal chain-of-thought reasoning followed by a JSON containing the updated historical state (sub-goal decomposition and progress summary) and a single discrete tool call from a fixed API (nav_to, walk_around, show_object_by_category, gaze_at, pick, place, open, close, or ask); the ask tool additionally produces a natural-language query sent to the simulated user.

## Method

REAL builds a privilege-free closed-loop environment on GRUtopia where the agent must discover objects through a four-stage exploration toolchain (inter-receptacle navigation, intra-receptacle scanning, category-based detection, and target alignment) that grounds all manipulation exclusively in 2D visual IDs back-projected into 3D, and integrates a gemini-3-flash-driven simulated user that issues ambiguous instructions and answers queries conditioned on the agent's live exploration results. Training proceeds in two stages on Qwen3-VL-8B: first, supervised fine-tuning via behavior cloning on expert trajectories generated by a rule-based planner (with LLM-annotated historical states) aligns the model to the tool interface; second, online reinforcement learning with Group Sequence Policy Optimization (GSPO) uses World Graph-differential dense rewards, a difficulty-conditioned query budget for the ask tool, and timing penalties to improve adaptive replanning and proactive communication. A key finding is that additional SFT epochs overfit expert trajectories (degrading distractor-heavy tasks), while RL from the single-epoch checkpoint restores generalization and shifts the policy from passive instruction following to active intent clarification, achieving 56.9% on interactive tasks and transferring zero-shot to a physical LIFT2 dual-arm mobile robot at 78.3% end-to-end success.

## Results

On REAL-Bench, the trained Qwen3-VL-8B agent (SFT+GSPO) achieves 56.9% success on the interactive disambiguation (SUL) split, outperforming all zero-shot commercial VLM baselines including gemini-3-pro (53.8%) and GPT-5 (52.3%). On standard manipulation tasks, the trained agent is competitive but trails the strongest baselines: 58.3% on FDP vs. gemini-3-pro's 81.9%, and 33.9% on FODP vs. gemini-2.5-pro's 41.1%. In real-world deployment on the Ark LIFT2 dual-arm mobile robot, the system achieves a 78.3% end-to-end success rate over 60 episodes with zero unrecoverable crashes, demonstrating zero-shot sim-to-real transfer.

## Baselines & Comparisons

The paper's trained agent (SFT+GSPO on Qwen3-VL-8B) wins decisively on the interactive disambiguation (SUL) split at 56.9%, surpassing gemini-3-pro (53.8%), GPT-5 (52.3%), and gemini-2.5-pro (49.2%)—the three strongest zero-shot baselines. However, it loses on the other three splits: gemini-3-pro leads FDP by 23.6 points (81.9% vs. 58.3%), gemini-2.5-pro leads FODP by 7.2 points (41.1% vs. 33.9%), and Claude Haiku 4.5 leads FDO by 10.4 points (52.1% vs. 41.7%). The paper attributes the FDO gap to the frozen vision encoder limiting dynamic visual grounding during articulation. Notably, the zero-shot Qwen3-VL-8B backbone scores near 0% on all manipulation tasks, confirming that tool-interface alignment via SFT is a prerequisite for any meaningful performance. The real-world evaluation (78.3% over 60 episodes) has no direct baseline comparison, as no prior open framework reports zero-shot sim-to-real transfer on a dual-arm mobile manipulator under the same protocol.

## Relation to Prior Work

This paper extends the embodied agent environment line (AI2-THOR, ProcTHOR, ALFRED, VoTa-Bench, EMMOE) by removing oracle perceptual APIs (global object lists, target poses, category-finding tools) and replacing them with a physically realizable exploration toolchain (nav_to, walk_around, show_object_by_category, gaze_at) grounded in RGB observations. It also departs from prior simulated-user work (TEACh, VL-LN, ADAPT, FARMER) by tightly coupling natural-language intent disambiguation with ongoing physical exploration rather than treating communication as a separate text-based module. For training, it builds on GSPO for sequence-level RL and uses Qwen3-VL-8B as a deployable backbone, positioning itself against both VLA policies (OpenVLA, π0.5) that skip high-level planning and closed-source agentic systems (Being-0) that delegate planning to external APIs.

## Why It Matters / Open Questions

The sim-to-real-consistent design philosophy—restricting the agent to physically obtainable priors and RGB observations—addresses a persistent gap between simulation benchmarks and real-robot deployment, and the 78.3% zero-shot transfer on a physical dual-arm robot provides concrete evidence that this gap can be narrowed. However, the task space remains limited to cross-receptacle rearrangement without richer compositional or spatial-relational constraints, the simulated user operates within a bounded behavioral envelope that may not capture mid-task goal changes or implicit cues, and receptacles are modeled as monolithic entities without part-level granularity. Open questions include whether the frozen vision encoder bottleneck for articulated manipulation can be resolved without full multimodal retraining, and whether the GSPO-based RL pipeline generalizes beyond the specific tool interface and scene library used here.
