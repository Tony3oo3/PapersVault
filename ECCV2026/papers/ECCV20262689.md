## Problem

Computer-use agents that combine MCP structured API calls with GUI visual actions lack a principled framework for learning when each modality provides complementary advantages, and existing training methods treat all samples equally without diagnosing systematic failure patterns or revealing how evolution mechanisms interact with application-specific task compositions. The paper asks how agents can iteratively self-improve across diverse applications while automatically selecting the right improvement mechanism for each.
![Teaser figure](../imgs/ECCV20262689/cropped_page4_idx0.webp)

## Input / Output

At each decision step the agent receives a 1024×768 screenshot, available MCP tool descriptions, the natural language task goal, and (at inference time) relevant experience-bank rules concatenated into the prompt, operating under a 10-step budget. The output is a single action per step—either a structured MCP call ⟨tool_name, arguments⟩ or a GUI action ⟨action_type, coordinates, parameters⟩—emitted in the model's native tool-calling format alongside a reasoning trace. The experience bank enables inference-time improvement without any weight update, making it deployable when compute for fine-tuning is unavailable.

## Method

The framework formulates MCP-GUI interplay as a unified hybrid policy learning problem and runs a fully automatic two-stage policy iteration loop: an LLM judge produces a multi-dimensional performance profile (modality balance, difficulty, skill categories, format quality, efficiency), which drives gap analysis to synthesize targeted tasks and auto-generate validated environments, after which expert trajectories are collected and the policy is refined via LoRA SFT from the base model each iteration to prevent error accumulation. A key innovation is the experience bank, which uses an LLM to compare successful and failed trajectories, extracting concise transferable rules (strategies, environment knowledge, tool sequences, error-recovery patterns) organized by skill category with per-category capacity limits and application-type filtering. The central empirical finding is that distillation and the experience bank target fundamentally different failure modes—distillation teaches correct tool invocation syntax while the experience bank encodes when to prefer one modality over the other—so the optimal mechanism is application-dependent: distillation yields +17.8 pp on MCP-dominant Chrome tasks, whereas the experience bank alone gives +10.0 pp on GUI-intensive VS Code where expert trajectories cause distribution mismatch.

## Results

On the Chrome 45-task benchmark, the full self-evolving method (Distillation + Experience Bank) achieves 77.8% pass rate and 0.770 LLM Score, a +17.8pp gain over the 60.0% single-iteration hybrid baseline. The experience bank alone adds +2.2pp training-free (62.2%), while the experience-only variant improves steadily to 64.4% over three iterations without any fine-tuning. Cross-application, the optimal mechanism is application-dependent: distillation excels on MCP-dominant Chrome (+17.8pp), while the experience bank is more effective on GUI-intensive VS Code (+10.0pp) and LibreOffice Calc (+2.3pp).

## Baselines & Comparisons

The paper compares against two recent 7B pure-vision GUI agents under the same Chrome 45-task protocol. The full self-evolving method (77.8%) outperforms UI-TARS-1.5-7B (24.4%) by 53.4pp and Aguvis-7B-720p (15.6%) by 62.2pp. Even the untrained hybrid baseline (60.0%) already exceeds both peers by 35.6pp and 44.4pp respectively, and both single-modality ablations (MCP-only 51.1%, GUI-only 48.9%) surpass the pure-vision agents, indicating that structured MCP tool access provides a fundamental advantage over pixel-level visual grounding for structured navigation tasks. The self-evolution loop then adds a further +17.8pp on top of the hybrid baseline, demonstrating that the gains come from learning when and how to combine modalities rather than from raw modality access alone.

## Relation to Prior Work

This paper synthesizes ideas from self-improvement methods (STaR, ReST, Self-Instruct) and agent training from demonstrations (DigiRL, AgentTrek) into a unified self-evolving framework for hybrid MCP-GUI agents, building on the recent MCPWorld and OSWorld-MCP benchmarks that established the hybrid modality setting. It departs from prior work by formulating MCP tool calls and GUI actions as a single sequential decision problem rather than independent modalities, and by introducing an experience bank that extracts transferable rules via LLM trajectory comparison—a mechanism absent from both imitation-learning and RL-based agent training. The automatic environment generation pipeline also distinguishes it from benchmarks like OSWorld that rely on manually authored task environments.

## Why It Matters / Open Questions

The central practical finding—that trajectory distillation can *degrade* performance on GUI-intensive applications (−10pp on VS Code) while a training-free experience bank improves them (+10pp)—challenges the default assumption that more expert demonstrations are always beneficial and provides concrete guidance for practitioners choosing between fine-tuning and inference-time augmentation. The fully automatic pipeline (environment generation, gap-driven task synthesis, experience accumulation) addresses a real scaling bottleneck in agent benchmarking. Open questions include whether the application-aware mechanism selection generalizes beyond the three tested applications, whether RL-based approaches with process rewards could subsume both mechanisms, and whether the experience bank's gains persist as base models improve in native tool-calling.
