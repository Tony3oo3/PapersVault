## Problem

Existing parameter-efficient fine-tuning (PEFT) methods for point cloud foundation models reduce trainable parameters but fail to proportionally reduce GPU memory, since backpropagation still requires caching intermediate activations of the frozen backbone. Additionally, point cloud video data is two orders of magnitude smaller than image data, making large-scale annotation infeasible, and no prior work simultaneously addresses data-, parameter-, and memory-efficiency in a unified framework for 4D point cloud understanding.

## Input / Output

The method consumes point cloud videos as sequences of 3D point clouds (2048 points per frame, partitioned into clips of 8–24 frames) and, during pretraining, additionally ingests 2D RGB projections and text captions derived from the same point clouds. Pseudo-motion trajectories are synthesized on-the-fly by applying M independent SE(3) rigid transformations (rotation angles in [−30°, 30°], uniform translations in [−0.2, 0.2]) plus per-point Gaussian noise to each static frame. Outputs are task-specific: 20-class action labels (MSR-Action3D), 28-class gesture labels (SHREC'17), or per-point semantic labels (Synthia 4D), with video-level predictions obtained by averaging clip-level results.

## Method

PoinTriE is a two-stage framework grounded in a theoretical proof that data and parameter efficiency are mutually exclusive under single-stage pretraining, necessitating a split. In the pretraining stage, the Geometric-Motion Duality Network (GMD Net) encodes pseudo-motion trajectories with a 3D point cloud encoder and optimizes via three objectives: intra-modal contrastive loss (InfoNCE over positive pairs from the same trajectory), cross-modal alignment loss (aligning point cloud, image, and text features using CLIP priors), and motion consistency loss (L2 regression on rigid transformation parameters plus KL divergence between predicted and true Gaussian motion distributions). In the fine-tuning stage, the Spatio-temporal Side Network (STS Net) is inserted in parallel to the frozen backbone, with one LoRA unit per block extracting task-specific side information; a gradient flow masking strategy randomly drops a fraction of LoRA units to curb overfitting, and the side features are fused back into backbone outputs via residual adaptation starting from a designated block D. This side-tuning design eliminates the need to cache backbone intermediate variables during backpropagation, reducing fine-tuning memory to roughly one-third of conventional PEFT methods while using only 2.2% tunable parameters.

## Results

On MSR-Action3D, PoinTriE achieves 94.37% average action recognition accuracy across 8/12/16/24-frame clips, outperforming the best PEFT baseline PointATA (93.32%) by 1.05 pp and the best full fine-tuning method PointCMP (91.66%) by 2.71 pp. On SHREC'17 gesture recognition, PoinTriE reaches 96.5% accuracy, surpassing PointATA (95.5%) and PointCSA (95.2%). On Synthia 4D semantic segmentation, PoinTriE attains 84.11% mIoU with 3-frame clips, edging out PointATA (84.06%) and P4Trans (83.16%). Notably, PoinTriE requires only 2.2% tunable parameters and 9.8 GB GPU memory, compared to 3.4%/26.4 GB (PointCSA) and 2.8%/28.5 GB (PointATA).

## Baselines & Comparisons

PoinTriE consistently outperforms both PEFT baselines across all three tasks: on MSR-Action3D it beats PointCSA (92.81%) by 1.56 pp and PointATA (93.32%) by 1.05 pp in average accuracy; on SHREC'17 it surpasses PointATA (95.5%) by 1.0 pp and PointCSA (95.2%) by 1.3 pp; on Synthia 4D it edges out PointATA (84.06%) by 0.05 pp mIoU. Against full fine-tuning methods, PoinTriE exceeds the best FFT baseline PointCMP (91.66% avg on MSR-Action3D) by 2.71 pp while using only 2.2% of the parameters. Compared to supervised-learning baselines, PoinTriE outperforms the strongest SL method PST-Trans (89.45% avg) by 4.92 pp on MSR-Action3D. The most striking advantage is in memory: PoinTriE requires only 9.8 GB GPU memory during fine-tuning, roughly one-third of PointCSA (26.4 GB) and PointATA (28.5 GB), making it practical for lab-scale hardware. The method also uses fewer tunable parameters (2.2%) than both PointCSA (3.4%) and PointATA (2.8%), demonstrating that the gradient flow masking strategy effectively reduces redundancy without sacrificing accuracy.

## Relation to Prior Work

This paper extends the ladder-side-tuning paradigm from LST [47] and DTL [14] (developed for NLP and 2D vision) to 3D/4D point cloud backbones, adapting the core idea of decoupling lightweight auxiliary modules from the frozen backbone to reduce intermediate cache memory. It departs from prior PEFT methods for point cloud videos (PointCSA, PointATA) that rely on additive adapters inserted within the backbone, which the authors argue still incur near-full fine-tuning memory costs due to cached forward-pass intermediates. On the pretraining side, it builds on contrastive and cross-modal self-supervised learning for point clouds but introduces pseudo-motion trajectories via rigid transformations as a data-efficient augmentation, avoiding the need for large-scale dynamic point cloud datasets that prior 4D pretraining methods (MaST-Pre, M2PSC, PointCMP) require.

## Why It Matters / Open Questions

The ~3× GPU memory reduction during fine-tuning (9.8 GB vs. 26.4 GB for PointCSA) while simultaneously improving accuracy is practically significant for lab-scale research environments where full fine-tuning or even standard PEFT is infeasible. The theoretical proof that data-, parameter-, and memory-efficiency cannot be jointly optimized in a single pretraining stage provides a clean formal justification for the two-stage design, though the scaling-law formulation is borrowed and the axioms are somewhat idealized. Open questions include whether the rigid-transformation pseudo-motion generalizes to non-rigid or articulated motions, whether the gradient flow masking strategy transfers to non-Transformer backbones, and whether the approach scales to larger, more diverse point cloud video datasets beyond the three benchmarks tested.
