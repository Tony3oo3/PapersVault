## Problem

Existing PowerPoint benchmarks either rasterize decks into images/PDFs (discarding shape trees, master layouts, and theme semantics) or focus on text-to-slide generation, leaving the practical task of editing existing decks with precision largely unverified. No prior benchmark provides element-level ground-truths, per-sample style rubrics, or a dual evaluation protocol that separately measures instruction fidelity and visual quality on real, multi-slide editing tasks.
![Teaser figure](../imgs/ECCV20261015/cropped_page0_idx0.webp)

## Input / Output

Each task pairs a natural-language edit instruction with a real .pptx source deck (drawn from 100 curated decks spanning academic, corporate, and multilingual domains) and expects a modified .pptx as output. Evaluation is not a single pixel or API diff: a per-sample style-target rubric (auto-generated by GPT-5 and human-verified) specifies exact structural and visual constraints, and two independent VLM judges score the result—one on structured JSON/XML diffs for instruction following, the other on rendered slide screenshots for visual quality, with SSIM screening to limit the visual judge to saliently changed slides.

## Method

PPTPilot is a structure-aware agent built on a dual-path execution architecture: a fast-LLM skill router dispatches each instruction to either a programmatic path (python-pptx code generation for repetitive, content-centric operations like bulk find-and-replace or translation) or a direct OOXML path (the VLM reads and rewrites raw slide/theme XML for fine-grained structural control over positions, master layouts, and theme color slots). Before editing, the agent parses slide masters, placeholders, shape trees, and visual data to ground its plan in deck semantics. An iterative plan-edit-verify loop renders the proposed edit to a temporary PPTX, a verifier model checks it against the original instruction, and the agent refines its output over up to three reflection passes. The benchmark's dual-judge protocol (separating IF and VQ scoring with targeted context) is validated against 25 human experts, achieving Pearson r = 0.72 (IF) and 0.81 (VQ) with 95% majority agreement on VQ across five repeated runs.

## Results

On the full PPTArena benchmark (100 decks, 1,340 edits), PPTPilot achieves the strongest overall scores with an Instruction Following (IF) score of 2.57 and Visual Quality (VQ) score of 2.69, outperforming ChatGPT (2.07/2.22) and Gemini CLI (1.21/1.98). On the matched 25-deck, 206-edit subset, PPTPilot (IF 1.87, VQ 1.91) leads ChatGPT Agent (1.68/1.60) by 0.19 IF and 0.31 VQ, and MiniMax Agent (1.04/0.84) by 0.83 IF and 1.07 VQ. In blind human evaluation with 25 experts, PPTPilot scores 3.86 IF / 3.81 VQ versus ChatGPT Agent's 3.17/2.82 and MiniMax Agent's 1.75/1.85. PPTAgent and Paper2Poster fail all tasks (0.00 on both metrics), highlighting the fragility of one-shot generation pipelines.

## Baselines & Comparisons

PPTPilot outperforms all six baselines on aggregate IF and VQ across both the full benchmark and the 25-case subset. Against ChatGPT Agent (the strongest proprietary competitor), PPTPilot leads by 0.19 IF / 0.31 VQ on the subset and by a wider margin in human evaluation (+0.69 IF / +0.99 VQ), with the gap concentrated on cross-slide and layout-sensitive edits; ChatGPT Agent's only relative strength is Structure edits (2.00/2.33 vs. PPTPilot's 1.47/2.00), attributed to its GUI-level control over slide masters. ChatGPT (extended-thinking) trails PPTPilot by 0.75 IF / 0.35 VQ on the subset, performing well on simple content edits but degrading sharply on visual-text alignment and multi-step instructions. Gemini CLI is competitive on IF (1.78 vs. 1.87) but lags on VQ (1.71 vs. 1.91), and scores 0.00 on Interactivity. MiniMax Agent, despite being marketed as a PPT tool, underperforms consistently (1.04/0.84), trailing PPTPilot by over a point on both axes. Kimi-K2.6 (open-weight) matches ChatGPT Agent on IF (1.68) but falls well behind on VQ (1.00 vs. 1.60). PPTAgent and Paper2Poster score 0.00 on every task, as their generation-driven outputs diverge from the original deck structure and fail all preservation requirements.

## Relation to Prior Work

This paper departs from prior PPT benchmarks (PPTC, PPTC-R, T2US) that rely on synthetically generated decks, short template-bound edits, or API-level diffs, by treating PowerPoint editing as a structured causal program over native OOXML deck semantics with element-level ground-truths and per-sample style-target rubrics. Architecturally, PPTPilot's dual-path design—routing between python-pptx programmatic calls and direct XML patching via a lightweight skill router—repurposes the tool-use-agent paradigm (cf. ReAct, Toolformer) for a domain where no single editing modality suffices. The dual-judge evaluation protocol (separate IF judge on structured diffs, VQ judge on rendered screenshots) extends the VLM-as-judge literature by showing that a single judge over all signals is dramatically over-lenient, and that separating content-level from aesthetic-level scoring yields calibrated, human-aligned ratings.

## Why It Matters / Open Questions

PPTArena fills a concrete gap in agentic AI evaluation: most real-world presentations are refined through revision, not generated from scratch, yet prior benchmarks either rasterize slides (losing structural semantics) or focus on text-to-slide generation. The finding that all evaluated agents—including proprietary products like ChatGPT Agent—still score below 3/5 on instruction following and visual quality, and that generation-driven pipelines (PPTAgent) fail entirely, underscores that reliable document-scale editing remains far from solved. Open questions include conversational refinement for under-specified intent, cross-application workflows (live charts, document-to-deck synthesis), and whether the dual-path architecture generalizes beyond PowerPoint to other structured document formats.
