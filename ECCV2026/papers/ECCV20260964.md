## Problem

Deploying vision foundation models in end-cloud collaboration requires transmitting intermediate features from the front end to the cloud, but existing feature compression methods directly reconstruct the full intermediate representation regardless of which tasks the user actually needs. This leads to two forms of redundancy: task-irrelevant information inflates the bitstream, and shared knowledge across multiple task features is coded repeatedly. Moreover, prior work largely targets small CNN backbones and single-task settings, leaving the versatile multi-task capacity of ViT-based VFMs and the need for arbitrary task-subset adaptability unexplored.

## Input / Output

The method takes an RGB image (512×512 for PASCAL-Context, 448×576 for NYUD v2) together with a requested task subset T_Q ⊆ T as input. The ViT backbone (Base or Large) is split at the 3rd layer, so the front end outputs a 768- or 1024-channel feature map that is factorized, compressed into a bitstream (with small identifier fields for task set and hyperprior selection), and transmitted to the cloud. After decompression and task-attentive recomposition, the cloud tail network produces predictions for all requested tasks—segmentation/parsing masks, saliency maps, surface normals, edge maps, and scene labels—in a single forward pass.

## Method

RFC is a three-stage factorization–consolidation–recomposition framework. (1) Factorization: at the front end, all attention layers of F_front are shared and only lightweight task-specific adapters are fine-tuned, implementing an Information-Bottleneck objective that strips T_Q-irrelevant information while preserving task-relevant signal. (2) Consolidation: the factorized task features are compressed in a task auto-regressive order where each subsequent feature uses a previously transmitted (or locally decoded) task feature as its hyperprior instead of its own downsampled hyper, eliminating the need to send the own hyper (~30% bitstream saving) and exploiting cross-task correlation for tighter entropy coding; a globally learned task-sequence table selects the optimal ordering and hyperprior source per task combination. (3) Recomposition: at the cloud, a lightweight task-attentive module projects all |T_Q| decompressed features into a shared latent space, applies multi-head self-attention with learnable task embeddings along the task dimension, and produces a single fused feature via sigmoid-weighted summation, enabling one forward pass through F_cloud for all requested tasks. Training proceeds in three sequential stages (adapters + per-task compressors, cross-task hyper modules with rate-only loss, then the recomposition module with task loss), keeping the backbone frozen throughout.

## Results

On PASCAL-Context under the F-request simulated protocol (few-task-dominated), RFC achieves 0.0725 bpp while maintaining strong task performance (Seg mIoU 77.61, Parse mIoU 66.31, Saliency maxF 84.81, Normals mErr 13.59, Edge odsF 72.0) with a single forward pass. Under the M-request protocol (multi-task-dominated), RFC achieves 0.0977 bpp with comparable task quality (Seg 77.47, Parse 66.11). On ViT-Large (Table 4), RFC scales to 0.0720–0.1451 bpp across 1–5 requested tasks while matching or exceeding the uncompressed model's task metrics (e.g., Seg mIoU 80.47 vs. 81.03 uncompressed at 5 tasks).

## Baselines & Comparisons

RFC dominates all baselines on bit-rate while matching or exceeding task performance. Against the strongest learned feature compression baselines (Hyperprior FC at 0.1554 bpp, OmniICM at 0.1713 bpp, LaMoFC at 0.1894 bpp), RFC achieves 0.0725 bpp under F-request — a 53–54% reduction — while simultaneously improving Seg mIoU by 0.2–1.0 points and Normals mErr by 0.1–0.6. Against the naive reconfigurable baseline (Multiple ST FC, 0.0976 bpp), RFC further reduces bpp by 26% and, critically, requires only 1 forward pass versus |T_Q| forwards. Traditional video codecs (HEVC, VVC) are catastrophically inferior on task metrics (Seg mIoU 17.12 and 45.98 vs. RFC's 77.61) while offering no bit-rate advantage. VCM (0.2531 bpp) and MPA (0.2197 bpp) are outperformed by RFC on both bpp and all five task metrics. The gap widens under M-request (multi-task-dominated) where RFC's cross-task consolidation coding yields 0.0977 bpp versus 0.1557 for Multiple ST FC, confirming that the auto-regressive hyperprior mechanism effectively eliminates shared-knowledge redundancy.

## Relation to Prior Work

This paper extends the learned feature compression line (OmniICM, VCM, LaMoFC, MPA) and the hyperprior compression framework (Ballé et al.) by introducing a reconfigurable multi-task paradigm. Where prior methods either compress a single-task feature or reconstruct all-task features in a fixed manner, RFC factorizes the shared VFM feature into task-specific components via lightweight adapters, then applies a novel cross-task hyperprior conditioning that reuses already-transmitted task features as entropy-modeling side information for subsequent tasks. The information-bottleneck formulation for factorization and the task-attentive recomposition module for single-forward cloud inference are new architectural contributions that depart from both static dual-task scalable coding and naive multi-model deployment.

## Why It Matters / Open Questions

RFC addresses a practically important gap in VFM deployment: real users request arbitrary subsets of tasks, yet existing compression schemes either waste bandwidth on task-irrelevant information or require inefficient multi-model inference. The cross-task hyperprior mechanism yielding ~30% bitstream reduction and the ability to outperform non-configurable baselines even in the all-task scenario suggest the factorization-consolidation-recomposition paradigm is broadly applicable. Limitations include evaluation on only two small-scale datasets (PASCAL-Context, NYUD v2) with five tasks, and the current focus on semantic feature compression rather than high-fidelity image reconstruction; open questions include scaling to dozens of tasks, handling complex task interactions, and designing adaptive task-grouping and routing strategies for production systems.
