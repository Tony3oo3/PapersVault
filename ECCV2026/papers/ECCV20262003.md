## Problem

Embedded programming inherently couples hardware wiring, pin-level grounding, and low-level code generation, making it a natural fit for vision-language models, yet no existing benchmark systematically evaluates LVLMs as embedded development copilots. Prior code-generation and vision-language benchmarks either ignore the physical hardware context or test only isolated perception tasks without end-to-end executable verification.
![Teaser figure](../imgs/ECCV20262003/cropped_page1_idx0.webp)

## Input / Output

Each task provides a text query, one or more real-world frames (hardware wiring photos, board close-ups, IDE screenshots) sampled from tutorial videos, and a history summary of prior steps. Outputs are deliberately heterogeneous and open-ended: they range from natural-language next-step instructions and UI click sequences (e.g., 'Click PA5 → select GPIO_Output') to complete executable firmware in Arduino C/C++ or STM32 HAL, with no fixed answer format, necessitating both semantic and execution-based scoring.

## Method

The benchmark is built via a three-stage pipeline: YouTube tutorial videos are transcribed with Whisper, GPT-5 segments subtitles into fine-grained tasks, and human annotators curate 216 multimodal QA triplets labeled across hardware operation, software configuration, and code generation. Evaluation uses a hybrid protocol: (1) a SCORING-REFINE iterative LLM-as-a-Judge (GPT-5) that performs an initial rubric-based scoring pass followed by two self-reflection rounds and a final reconciliation, producing a normalized 0–1 score per sample; and (2) an Execution Success Rate (ESR) metric that compiles and runs generated code in the Wokwi emulator or on physical hardware, with both a strict criterion (exact pin correctness + task completion) and a permissive criterion (pin-index errors forgiven) to isolate visual-grounding failures from logic errors. Reliability is validated through 172-sample human gold scoring, 12-rater explanation-consistency audits, and cross-judge Spearman correlations against five alternative LLM judges.

## Results

On EmbedCopilot-Bench (216 multimodal QA triplets), closed-source LVLMs lead in overall LLM-as-a-Judge scores: Claude-Sonnet-4.5 achieves 89.6 and GPT-5 achieves 89.2 (with images), followed by GPT-4o (87.0) and Gemini-2.5-Pro (86.6). The best open-source model, Mistral-Small-3-24B, reaches only 80.8 overall, while the weakest (Qwen3-VL-2B) scores 54.9. Execution Success Rate (ESR) reveals a much harder reality: strict ESR peaks at just 48.3% (Claude-Sonnet-4.5, GPT-4o), and even permissive ESR (tolerating pin-index errors) reaches at most 86.2%, exposing pin-level visual grounding as the dominant failure mode.

## Baselines & Comparisons

Among closed-source LVLMs, Claude-Sonnet-4.5 and GPT-5 lead with overall judge scores of 89.6 and 89.2 respectively (with images), narrowly ahead of GPT-4o (87.0) and Gemini-2.5-Pro (86.6); all four maintain LLM_sw scores above 93, but hardware-operation scores (LLM_hw ≈ 83–88) and code-generation scores (LLM_code ≈ 82–84) reveal remaining headroom. The strongest open-source model, Mistral-Small-3-24B, trails the best closed-source models by roughly 9 points overall (80.8 vs. 89.6), while smaller open-source models (Qwen3-VL-2B at 54.9, LLaVA-OneVision-7B at 60.6) fall 25–35 points behind. On execution, the gap widens dramatically: Claude-Sonnet-4.5 achieves 44.8% strict ESR and 86.2% permissive ESR, whereas GPT-5 drops to 31.0%/58.6%, and most open-source models stay below 21% strict ESR. The large Strict-to-Permissive ESR gap (e.g., Mistral-Small-3-24B: 37.9%→82.8%; Claude-Sonnet-4.5: 44.8%→86.2%) indicates that pin-level visual grounding, not code logic, is the primary bottleneck for strong models. Visual context provides substantial gains for capable models (GPT-4o LLM_hw: 65.6→84.7; Qwen2.5-VL-7B LLM_hw: 43.2→59.0) but yields negligible or negative returns for smaller models (Gemma-3-4B, LLaVA-OneVision-7B), suggesting a capacity threshold below which image inputs introduce noise rather than signal.

## Relation to Prior Work

This paper carves new ground at the intersection of multimodal LVLM evaluation and embedded-systems development. Prior code-generation benchmarks (EmbedBench, IoTPilot, AutoIOT) evaluate LLMs on text-only embedded programming, while vision-language benchmarks (MMCode, Plot2Code, EEE-Bench) target static diagram or plot understanding without the full hardware-software-code loop. EmbedCopilot-Bench repurposes the LLM-as-a-Judge paradigm with a domain-specific rubric and adds execution-based ESR (via Wokwi and hardware-in-the-loop) as a complementary, deterministic metric, creating the first benchmark that jointly assesses visual hardware grounding, UI-level software configuration, and deployable firmware generation from real development screenshots.

## Why It Matters / Open Questions

The benchmark reveals a stark gap between semantic plausibility and functional correctness: top closed-source models score ~89% under LLM judging yet achieve only ~48% strict execution success, with the Strict-Permissive gap (e.g., 44.8%→86.2% for Claude-Sonnet-4.5) isolating pin-level visual grounding as the dominant bottleneck. This reframes the challenge for LVLM-based embedded copilots from 'generate plausible code' to 'reliably localize physical pins under occlusion and viewpoint variation,' a problem that current architectures handle poorly. Open questions include whether structured circuit-reasoning modules or explicit pin-counting strategies can close the grounding gap, and whether the capacity threshold observed in the Qwen3-VL family (visual input only becomes actionable beyond ~4B) generalizes across architectures. The modest dataset size (216 triplets) limits statistical power and coverage of the full embedded development space.
