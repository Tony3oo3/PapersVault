## Problem

Medical vision-language models for chest X-ray report generation frequently hallucinate quantitative measurements—such as the distance between an endotracheal tube tip and the carina—because they must simultaneously perform object detection, anatomical localization, and dimensional calculation without specialized architectures. These erroneous measurements are clinically dangerous (e.g., misjudging ETT placement can lead to hypoxia or pneumothorax), yet no existing framework can correct them post-hoc without retraining the original model.

## Input / Output

The pipeline consumes a chest X-ray image (from MIMIC-CXR, with pixel-spacing metadata for cm conversion) and a free-text radiology report generated by any of 11 baseline models. It outputs a revised report in which hallucinated measurements are replaced with tool-verified values, hallucinated objects are removed, and ETT placement is reclassified as 'correct' or 'incorrect' based on a 3–7 cm threshold. The system only edits sentences that already mention a measurable finding; it does not add new findings to the report.

## Method

FactCheXcker follows a query-code-update paradigm with three LLM-driven stages. First, a Query Generator (GPT-4o mini) parses the report and emits structured measurement queries (e.g., 'measure the distance between the endotracheal tube and the carina'). Second, a Code Generator (GPT-4o mini) translates each query into executable Python code against a domain-specific API exposing functions like exists(), find(), distance(), and dimensions(); these functions are backed by swappable specialized modules—ResNet-50+ for ETT binary detection, CarinaNet+ for carina/ETT coordinate localization, and TorchXRayVision for 14-region anatomical segmentation. Third, a Report Updater integrates the verified numeric results back into the report text and applies a strict rule-based classifier (3–7 cm above carina = correct placement) to update the clinical interpretation. The entire framework is modular and extensible: new measurement tasks (e.g., nodule diameter, cardiac-thoracic ratio) can be supported by adding new tool modules without modifying the original report-generation model or its weights.

## Results

On the MIMIC-CXR test set (2,288 studies, 182 with ETT mentions), FactCheXcker applied to 11 report-generation models achieves an average 135.0% reduction in ETT measurement MAE (from 1.93 cm to 0.82 cm) and a 186.0% reduction in the Composite score (MAE/F1, from 7.25 to 2.54). ETT presence precision improves from 0.49 to 0.65 on average, and ETT placement precision rises from 0.84 to 0.94. The largest individual gains are seen in GPT4V (MAE 2.35→0.39, 503% improvement) and LLM-CXR (Composite 18.54→1.65, 1024% improvement), while RadFM is the sole model whose MAE worsens (0.65→1.04, −38%).

## Baselines & Comparisons

FactCheXcker is applied as a post-hoc correction layer to 11 existing report-generation models and improves 10 of 11 on ETT measurement MAE. The largest gains occur for models with the weakest baseline measurement ability: GPT4V (MAE 2.35→0.39, 503%), LLM-CXR (Composite 18.54→1.65, 1024%), VLCI (MAE 3.50→0.98, 257%), and Cvt2distilgpt2 (MAE 3.82→0.89, 329%). Stronger baselines like MedVersa (MAE 1.07→0.86, 24%) and RaDialog (MAE 0.99→0.86, 15%) see more modest but still positive improvements. RadFM is the only model that degrades (MAE 0.65→1.04, −38%), likely because its already-accurate measurements are perturbed by the tool modules' own errors. On ETT placement precision, all models improve or hold steady (average 0.84→0.94), with LLM-CXR showing the largest jump (0.74→0.97). The failure analysis (20 cases, 1.95%) attributes errors to tube misidentification (60%), obscured carina landmarks (35%), and rotated images (5%).

## Relation to Prior Work

FactCheXcker sits at the intersection of three research threads: (1) medical report generation models (MAIRA-2, CheXagent, MedVersa, RadFM, etc.), (2) LLM-augmented tool use via code generation (ViperGPT, Toolformer, HuggingGPT), and (3) hallucination mitigation in multimodal LLMs (FacTool, ProgramFC, FActScore). It departs from prior hallucination work by targeting quantitative measurement errors rather than binary object-presence errors, and from prior tool-use work by grounding the generated code in a domain-specific medical imaging API (CarinaNet, ResNet-50+, TorchXRayVision) rather than general-purpose libraries. The query-code-update paradigm is repurposed from general task completion to post-hoc correction of a frozen report-generation model, requiring no weight access or retraining.

## Why It Matters / Open Questions

The paper addresses a clinically critical gap: radiology reporting guidelines depend on precise thresholds (e.g., ETT 5±2 cm above carina), and hallucinated measurements can directly affect patient safety. The modular, plug-and-play design is well-suited to privacy-constrained hospital settings where data cannot leave the institution and model weights are inaccessible. Key limitations include the narrow evaluation scope (ETT placement only, single dataset), the inability to address false negatives (missed ETTs), and the reliance on a brittle rule-based placement classifier. Open questions include extending the framework to lesion sizing, pneumothorax measurement, and multi-tube scenarios, as well as incorporating confidence-based uncertainty to avoid the observed cases where FactCheXcker worsens measurements.
