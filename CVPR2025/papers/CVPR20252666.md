## Problem

Existing GUI agents rely on text-rich metadata (HTML, accessibility trees) from closed-source APIs, limiting them to scenarios where structural oracles are available. Building a visual GUI agent that perceives screenshots as humans do faces three under-explored challenges: the computational cost of modeling high-resolution UI screenshots (e.g., 1344×756 yielding ~1300 tokens), the lack of a clear formulation for modeling actions alongside visual and textual modalities in interleaved streams, and the absence of guidance on selecting high-quality training data from diverse GUI sources.
![Teaser figure](../imgs/CVPR20252666/cropped_page0_idx0.webp)

## Input / Output

ShowUI takes a high-resolution UI screenshot (e.g., 1344×756 on PC), a natural-language task query, and a pre-defined action space documented in the system prompt as a README. For navigation, it consumes an interleaved sequence of past screenshots and executed actions, producing the next action as a JSON object with fields 'action' (type), 'value' (element), and 'position' (relative [x,y] on 0–1 scale). For grounding, it uses a multi-turn dialogue format where a single screenshot is paired with multiple parallel element annotations in one forward pass to improve data utilization.

## Method

Built on Qwen2-VL-2B, ShowUI introduces three key components. First, UI-Guided Visual Token Selection constructs a UI connected graph via Union-Find over RGB-space patches, grouping visually identical neighboring patches into connected components; during training, a random subset of tokens within each component is skipped (inspired by Mixture-of-Depth) while retaining original positional embeddings, reducing 33% redundant tokens with a 1.4× training speedup and no additional learnable parameters. Second, Interleaved VLA Streaming unifies two modes: Action-Visual Streaming for navigation (sequentially interleaving screenshots and actions to maintain full history) and Action-Query Streaming for grounding (multi-turn dialogue predicting multiple actions per screenshot), with actions standardized in JSON and interpreted via a function-calling-style README in the system prompt. Third, a carefully curated 256K-sample instruction-tuning dataset combines self-collected web visual elements (filtering out 40% static text), AMEX mobile data, GPT-4o-augmented OmniAct desktop queries, and GUIAct navigation trajectories, with a balanced sampling strategy to mitigate data-type imbalance.

## Results

On the Screenspot zero-shot grounding benchmark, ShowUI (2B parameters, 256K training samples) achieves 75.1% average accuracy, surpassing UGround (7B, 1.3M samples; 73.3%) and OmniParser (GPT-4V-based; 73.0%) while being the most lightweight model in the comparison. On mobile navigation (AITW), ShowUI reaches 70.0% overall success rate, outperforming the Qwen2-VL-2B baseline (67.2%) and SeeClick-9.6B (59.3%). On web navigation (Mind2Web), ShowUI achieves 37.2% Step Success Rate on cross-task, 35.1% cross-website, and 35.2% cross-domain, consistently exceeding the Qwen2-VL-2B baseline by 3–7 points. On the online MiniWob benchmark, ShowUI scores 71.5%, beating SeeClick (67.0%) and Qwen2-VL-2B (66.8%).

## Baselines & Comparisons

ShowUI (2B) outperforms all open-source baselines on Screenspot grounding: it beats UGround-7B (73.3%) by 1.8 points and SeeClick-9.6B (53.4%) by 21.7 points, while using far fewer parameters (2B vs. 7B/9.6B) and less training data (256K vs. 1.3M/364K). Against the GPT-4V-based OmniParser (73.0%), ShowUI leads by 2.1 points without relying on any closed-source API. On AITW mobile navigation, ShowUI (70.0%) surpasses Qwen2-VL-2B (67.2%) by 2.8 points, SeeClick (59.3%) by 10.7 points, and PaLM2-CoT (39.6%) by 30.4 points. On Mind2Web web navigation, ShowUI improves over Qwen2-VL-2B by 4.0 points (cross-task Step.SR) and 7.5 points (cross-website), and its zero-shot variant (21.4% cross-task) already approaches SeeClick's fine-tuned score (25.5%). On MiniWob, ShowUI (71.5%) leads SeeClick (67.0%) and Qwen2-VL-2B (66.8%), though its zero-shot score (27.1%) reveals a gap in handling out-of-distribution online errors that fine-tuning partially addresses.

## Relation to Prior Work

ShowUI extends the training-based GUI visual agent line (SeeClick, CogAgent, UGround) by building on Qwen2-VL-2B and introducing a UI-specific efficiency mechanism: a Union-Find-based connected graph over RGB patches that guides token selection, drawing conceptually from Mixture-of-Depth's sparse routing but using structural redundancy rather than learned gating. It departs from the dominant language-based GUI agents (GPT-4 + HTML/accessibility tree) by operating purely on screenshots, and from prior token-pruning/merging work by showing that preserving positional information via selective skipping outperforms pooling. The interleaved VLA streaming generalizes multi-turn dialogue to the action modality, and the data curation strategy (filtering static text, GPT-4o query augmentation, balanced sampling) is a practical departure from the 'aggregate all available data' approach common in prior GUI agent training.

## Why It Matters / Open Questions

The 33% visual token reduction with 1.4× training speedup and negligible accuracy loss (70.8→70.4) offers a parameter-free, plug-and-play efficiency technique applicable to any high-resolution VLM, making GUI agent training substantially cheaper. The finding that 40% of web UI data (static text) contributes little to grounding performance, and that a 2B model on 256K curated samples matches or exceeds 7–18B models on 400K–1.3M samples, shifts the field's focus toward data quality over scale. A key open question highlighted by the MiniWob results (27.1% zero-shot vs. 48.4% fine-tuned) is how to close the offline-to-online gap, pointing toward reinforcement learning or interactive fine-tuning as the next frontier for GUI agents.
