## Problem

LLMs trained on web data encounter SVG code embedded within lengthy XML, leading to semantically ambiguous tokenization that causes hallucinations in vector primitive predictions and improper attribute encoding. Existing generative methods either restrict SVGs to basic path commands, rely on diffusion models with cumbersome iterative optimization producing non-editable outputs, or treat SVG source code as plain sequential text without capturing its hierarchical structure. No prior framework enables arbitrary LLMs to both understand and generate complex, editable SVGs with full primitive support.

## Input / Output

For generation, the model accepts a text prompt (optionally paired with a 512×512 rendered image) and produces structured SVG source code where all tags and attributes are represented as dedicated semantic tokens rather than raw XML text, with decimal coordinates and hexadecimal color codes. For understanding, the model takes SVG source code (optionally with its rendered image) and outputs a natural-language description. The SVG is preprocessed through a normalization pipeline that removes redundant elements, enforces uniform canvas size, and converts to relative coordinate systems before tokenization.

## Method

LLM4SVG introduces 55 SVG-specific semantic tokens (15 tag, 30 attribute, 10 path command) that replace all XML tags and attributes in the source code, each initialized via the semantic average of its descriptive text to provide meaningful starting embeddings. The modular architecture couples these tokens with a vector instruction encoder and a standard LLM backbone (GPT-2, Phi-2, Falcon, or LLaVA), decoupling vector instructions from geometric parameters to tightly combine appearance, geometry, and language. Training proceeds in two stages: first, only the embedding layer is trained for feature alignment while the LLM and visual encoder remain frozen; second, end-to-end supervised fine-tuning (via LoRA/QLoRA or full parameters) is applied over the SVGX-SFT dataset of 250k human-designed SVGs and 580k instruction-following samples generated through a BLIP + GPT-4 annotation pipeline. The auto-regressive objective is computed only on model responses across five instruction template types covering both generation and understanding tasks.

## Results

LLM4SVG (GPT-2-XL) achieves the best FID of 64.11 and highest CLIP score of 0.3496 among all compared SVG generation methods, while generating SVGs in just 18 seconds versus 12–44 minutes for optimization-based approaches. In human evaluation, LLM4SVG scores 0.89 (prompt alignment), 0.92 (visual quality), and 0.88 (pick score), approaching human-designed SVGs (0.94/0.95/0.92) and substantially outperforming GPT-4o (0.49/0.61/0.57) and Claude-3.5 (0.56/0.74/0.69). Against general-purpose LLMs in Table 2b, LLM4SVG (GPT-2-XL) leads on every metric, e.g., FID 64.11 vs. 82.89 for Claude-3.5 and 127.78 for GPT-4o.

## Baselines & Comparisons

Against optimization-based methods, LLM4SVG (GPT-2-XL) achieves a lower FID (64.11 vs. 72.68 for SVGDreamer) and higher CLIP score (0.3496 vs. 0.3001), though SVGDreamer edges it on HPS (0.2685 vs. 0.2485); the decisive advantage is generation speed—18 s versus 43 min 56 s. Against NN-based baselines, LLM4SVG dominates on all four visual metrics, e.g., FID 64.11 vs. 71.37 (DeepSVG) and HPS 0.2485 vs. 0.1659 (StrokeNUWA). In the LLM comparison (Table 2b), LLM4SVG (GPT-2-XL) outperforms every general-purpose LLM tested—GPT-4o (FID 127.78), Claude-3.5 (82.89), Llama-3.1 70B (138.44), and Qwen2.5 70B (131.46)—on FID, CLIP, Aesthetic, and HPS simultaneously. In the human study (Table 3), LLM4SVG's visual quality score of 0.92 is within 0.03 of human-designed SVGs (0.95), while GPT-4o and Claude-3.5 score only 0.61 and 0.74 respectively, indicating a substantial gap between general LLMs and the specialized framework.

## Relation to Prior Work

This paper carves new ground at the intersection of LLM instruction tuning and vector graphics by introducing learnable SVG semantic tokens that replace raw XML tags and attributes, addressing the hallucination and ambiguity problems that arise when LLMs treat SVG source code as plain text. It departs from optimization-based SVG generation (CLIPDraw, VectorFusion, SVGDreamer) which rely on iterative differentiable rasterization, and from prior LLM-based attempts (StarVector, Xu & Wall) that simply fine-tune on SVG-as-text without structured tokenization. The training paradigm borrows from visual instruction tuning (LLaVA) and the data pipeline draws on BLIP captioning and GPT-4 annotation, but the modular architecture with decoupled vector instructions and parameters is a novel synthesis not present in any single prior line of work.

## Why It Matters / Open Questions

The SVGX-SFT Dataset (250k curated SVGs + 580k instruction pairs) is a substantial resource that addresses a critical data bottleneck in vector graphics research, and the semantic token approach provides a reusable technique for any LLM-based SVG pipeline. The human evaluation showing a fine-tuned GPT-2 XL approaching human-designed SVG quality (0.92 vs 0.95 visual quality) while outperforming frontier LLMs like GPT-4o (0.61) and Claude-3.5 (0.74) suggests task-specific fine-tuning can dramatically close the gap for structured code generation. Open questions include whether the approach scales to highly complex multi-layer professional designs, how well it handles iterative editing via natural language feedback, and whether the heavily UI-focused dataset limits generalization to artistic or scientific vector graphics.
