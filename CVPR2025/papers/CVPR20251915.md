## Problem

Shape programs—interpretable, editable procedural models of 3D objects—offer a compact and semantically rich alternative to mesh or radiance-field reconstructions, yet their use for 3D scene understanding has been largely unexplored. The central difficulty is that shape programs contain both continuous parameters (dimensions, offsets) and discrete parameters (number of shelves, presence of armrests), making standard gradient-based optimization inapplicable. Prior supervised approaches (e.g., GeoCode) fail to generalize from synthetic training data to real-world scans due to the domain gap.

## Input / Output

The method consumes RGB-D scans of indoor scenes (ScanNet), a hand-designed Blender geometry-node graph per object category (sofa: 18 params, chair: 20, table: 10), and 2D segmentation masks (from a pre-trained model) that are back-projected into dense target point clouds. It outputs the full set of shape program parameters (discrete and continuous), the object's 6-DoF pose (translation plus rotation constrained to the vertical axis), a 3D mesh, and optionally a set of procedural Gaussian splats whose parameters are tied across cloned primitives in the graph.

## Method

The core contribution is a parser/compiler that translates a Blender geometry-node graph into differentiable PyTorch code (PyTorchGeoNodes), where each Blender node type (Input, Math, Switch, Primitive, Transform, Points-on-instances, etc.) is reimplemented as a PyTorch/PyTorch3D operation, enabling automatic differentiation through the entire shape-generation pipeline. To handle the mixed discrete-continuous parameter space, the paper couples a genetic algorithm (crossover, type-aware mutation, and selection over a population of parameter vectors) with per-individual gradient descent on the continuous parameters, optimizing a composite loss of single-direction chamfer distance, an occlusion-grid penalty, and a floor-plane constraint. A second contribution extends the framework with trainable Gaussian primitives subsampled from mesh triangles; Gaussians on cloned base primitives share parameters, so occluded copies inherit appearance from visible ones. The Gaussians are then refined with a render-and-compare objective (RGB + depth + chamfer consistency + regularizers) after the shape parameters are fixed, yielding a two-stage pipeline that is more robust than joint optimization.

## Results

On the ScanNet validation set (176 manually annotated objects across Sofa, Chair, and Table categories), the proposed genetic algorithm with gradient refinement achieves a chamfer distance of 0.11 m and absolute rotation error of 0.06 rad, outperforming the GeoCode supervised baseline (0.21 m, 0.12 rad) and coordinate descent (0.16 m, 0.11 rad). For discrete parameters on the Table category, the genetic algorithm reaches 94% accuracy on Top Shape and 86% on Has Cabinet Leg, compared to 78% and 71% for GeoCode. Continuous parameter errors (mean absolute difference) are reduced by roughly 2–3× over GeoCode, e.g., Width drops from 0.22 cm to 0.08 cm and Height from 0.14 cm to 0.06 cm.

## Baselines & Comparisons

The paper compares against two baselines: (1) GeoCode [27], a supervised encoder-decoder (DGCNN + feed-forward decoders) trained on 10,000 synthetic point clouds to predict shape program parameters, and (2) a coordinate descent (CD) method that iteratively sweeps each parameter's valid values. The genetic algorithm with gradient refinement dominates both baselines on every reported metric. On chamfer distance, the genetic method achieves 0.11 m versus 0.21 m for GeoCode and 0.16 m for CD; on rotation error it reaches 0.06 rad versus 0.12 and 0.11 rad respectively. For discrete parameters, the gap is even more pronounced: Legs Type accuracy jumps from 0.39 (GeoCode) to 0.78 (Genetic), and Has Cabinet Leg improves from 0.71 to 0.86. The authors attribute GeoCode's poor performance to the domain gap between synthetic training data and real ScanNet scans, while CD suffers from local minima in the high-dimensional mixed discrete-continuous search space. The gradient refinement step (PyTorchGeoNodes) provides a consistent 20–40% improvement over the unrefined versions of all three methods, confirming the value of the differentiable compiler.

## Relation to Prior Work

This paper extends GeoCode's [27] shape program concept—hand-designed Blender geometry-node graphs mapping interpretable parameters to 3D shapes—by compiling those graphs into differentiable PyTorch code (PyTorchGeoNodes), enabling gradient-based optimization of continuous parameters. It departs from GeoCode's learned encoder-decoder for parameter prediction by instead combining a genetic algorithm (for discrete parameters) with gradient descent (for continuous parameters), eliminating the need for training data. The paper also extends 3D Gaussian Splatting [17] by constraining Gaussians within the procedural graph so that cloned primitives share Gaussian parameters, enabling detail recovery in occluded regions.

## Why It Matters / Open Questions

The framework provides a practical, training-free pipeline for recovering semantically meaningful object parameters (e.g., number of shelves, presence of armrests) alongside geometry, which neither SDF/NeRF/Gaussian-splatting reconstructions nor exemplar retrieval offer. Key limitations include the requirement for hand-designed shape programs per category (currently only 3 furniture types), the absence of texture modeling, and evaluation on a single dataset with 176 annotated objects. Open questions include whether shape program designs can be learned from shape databases to generalize to novel categories, and how to extend the approach to articulated or deformable objects.
