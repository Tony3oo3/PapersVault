## Problem

Contrastive loss requires materializing a full b×b similarity matrix for log-sum-exp computation, giving O(b²) GPU memory that prevents the large batch sizes known to improve representation quality. Existing distributed solutions (OpenCLIP, DisCo-CLIP) reduce this to O(b²/n) but still grow quadratically, capping practical batch sizes at ~128k even on hundreds of GPUs.
![Teaser figure](../imgs/CVPR20251466/cropped_page0_idx0.webp)

## Input / Output

The method operates on pre-encoded feature matrices: visual features I ∈ R^{b×c} from a ViT encoder and textual features T ∈ R^{b×c} from a BERT encoder, where b is the global batch size and c is the embedding dimension. It produces the scalar contrastive loss and gradients ∂L/∂I and ∂L/∂T for backpropagation. Tile dimensions t_r and t_c are tunable hyperparameters that trade memory against computation, and a 'data offload' option further reduces peak memory by streaming small data batches from CPU to GPU per accumulation step.

## Method

Inf-CL decomposes the log-sum-exp (LSE) computation into tiles, exploiting the cumulative property LSE(a+b) = a + log(1+e^{b−a}) to merge per-tile LSE values serially without ever storing the full similarity matrix. A multi-level tiling strategy is then applied: at the cross-GPU level, rows are partitioned across n GPUs with ring-topology asynchronous communication to overlap data transfer with computation; at the in-GPU level, each tile's row-wise iterations are fused into a single CUDA kernel that keeps intermediate values in SRAM, minimizing HBM I/O. The backward pass mirrors the forward by accumulating gradient contributions tile-by-tile using only the stored LSE vector (O(b) memory). This reduces loss memory from O(b²) (CLIP) or O(b²/n) (OpenCLIP) to O(b/n²), enabling 4M batch-size CLIP training on 8×A800 80GB GPUs with ~78× memory reduction at 256k batch while maintaining comparable training speed.

## Results

Inf-CL reduces the space complexity of contrastive loss from O(b²) (CLIP) or O(b²/n) (OpenCLIP) to O(b/n²), achieving a 78× memory reduction at batch size 256k on 8×A800 (1.63 GB loss memory vs. ~128 GB for CLIP). The maximum trainable batch size on 8×A800 increases from 68k (CLIP) and 152k (OpenCLIP) to 448k, and further to 4096k with data offload. Accuracy is preserved: Inf-CL at 64k batch size achieves 74.93% ImageNet top-1 vs. 74.74% for vanilla CLIP, within the error margin. Training speed remains comparable at ~59 hours per epoch on 8×A800 for ViT-L/14.

## Baselines & Comparisons

Against vanilla CLIP, Inf-CL achieves a 78× reduction in loss memory at batch size 256k on 8×A800 (1.63 GB vs. ~128 GB extrapolated) and extends the maximum feasible batch size from 68k to 448k (6.6×). Against OpenCLIP/DisCo-CLIP, which already distribute the loss across GPUs (O(b²/n)), Inf-CL's cross-GPU tiling adds a further 1/n factor, yielding 4.81 GB vs. 16.96 GB at 64k on 4×A800 (Table 4), and the in-GPU tiling further reduces this to 0.81 GB. In terms of accuracy, Inf-CL at 64k batch size matches vanilla CLIP within noise (74.93% vs. 74.74% ImageNet top-1; 26.01% vs. 25.71% MSCOCO I→T), confirming no precision loss from the tile-based decomposition. Training speed is essentially identical: Inf-CL's iteration time scales linearly with batch size and one epoch takes ~59 hours on 8×A800, comparable to prior methods. The only scenario where Inf-CL underperforms is at extremely large batch sizes (1024k) where accuracy drops (73.58% ImageNet), likely due to suboptimal hyperparameters or insufficient training iterations rather than the loss computation itself.

## Relation to Prior Work

This paper applies the tile-based computation philosophy of FlashAttention (avoiding full matrix materialization via block-wise accumulation) to the contrastive loss similarity matrix, a setting where prior work (OpenCLIP, DisCo-CLIP) only distributed the computation across GPUs without tiling within each GPU. The multi-level tiling strategy combines Ring Attention's ring-topology communication for overlapping cross-GPU data exchange with FlashAttention-style fused CUDA kernels for in-GPU tile processing, while building on Gradient Cache to decouple model and loss memory. Conceptually, the key departure is recognizing that the log-sum-exp operation's cumulative property allows serial tile merging, reducing the loss memory from O(b²/n) to O(b/n²).

## Why It Matters / Open Questions

The practical impact is substantial: enabling 4M+ batch contrastive training on just 8 A800 GPUs (previously requiring hundreds of GPUs or being infeasible) makes large-batch contrastive learning accessible to far more research groups. However, the paper reveals an important open question: batch sizes beyond ~256k on Laion-400M actually degrade zero-shot performance, suggesting the optimal batch size is data-scale-dependent and that simply maximizing batch size is not always beneficial. This challenges the common assumption that more in-batch negatives monotonically improve contrastive learning and points to future work on understanding the interaction between batch size, data diversity, and training dynamics.
