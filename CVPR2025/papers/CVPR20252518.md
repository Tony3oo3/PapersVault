## Problem

State-of-the-art text-to-image models such as Stable Diffusion and Flux still produce images with typographic errors including missing words, unintended characters, and word-level substitutions. Existing remedies either require fine-tuning the generator or rely on conditional layout-based generation (e.g., TextDiffuser) that sacrifices overall image quality. This paper asks whether a fully automatic, training-free post-processing pipeline can correct these errors while preserving the visual quality of the original generation.
![Teaser figure](../imgs/CVPR20252518/cropped_page0_idx0.webp)

## Input / Output

The method takes as input a single RGB image produced by any off-the-shelf text-to-image model together with the original text prompt that specifies the set of target words to appear in the image. It outputs a retouched RGB image of the same resolution where erroneous text has been erased, missing words have been inserted at appropriate positions, and misspelled words have been corrected. The pipeline is model-agnostic: it requires no access to the generator's internals and can be plugged behind Flux, Stable Diffusion 3/3.5, or DALL-E 3 without modification.

## Method

Type-R is a four-stage post-processing pipeline that operates entirely with pre-trained external models. First, error detection uses a scene text detector (DeepSolo) and recognizer (Paddle) to extract word regions and text from the image, then formulates the matching between prompt words and detected words as an optimal transport problem with Levenshtein distance, using padding tokens to handle size mismatches (missing or extra words). Second, text erasing applies LaMa inpainting to remove regions corresponding to unintended words. Third, layout regeneration queries GPT-4o to propose bounding boxes for missing words conditioned on the image and positions of valid text. Fourth, typo correction iteratively applies the AnyText editing model to re-render misspelled words, compositing only the corrected regions back, and repeats up to 10 times until all edit distances are zero. The key design choice is treating the problem as a combinatorial matching (optimal transport) rather than a simple string comparison, which naturally decomposes the correction into erase, insert, and edit sub-tasks handled by specialized models.

## Results

On the MARIO-Eval benchmark (5,414 prompts), Type-R w/ Flux achieves the highest OCR accuracy (62.0%) and the highest GPT graphic design quality score (7.67/10) and content alignment score (8.55/10), outperforming both TextDiffuser (OCR 55.4%, Graphic 4.67) and TextDiffuser-2 (OCR 56.2%, Graphic 4.97). Type-R w/ SD3 also surpasses both baselines on GPT scores (Graphic 7.30, Match 8.46) but yields lower OCR accuracy (48.6%), indicating that the base generator's text rendering capability influences the final correction quality. A user study with 5 participants (500 ratings per method) confirms the GPT evaluation, with Type-R w/ Flux scoring 6.23 (Graphic) and 6.04 (Match) versus 5.24/5.08 for TextDiffuser, with statistically significant differences (p < 1e-10).

## Baselines & Comparisons

Type-R w/ Flux dominates both TextDiffuser and TextDiffuser-2 on all three primary metrics: GPT graphic quality (7.67 vs. 4.67/4.97), GPT content alignment (8.55 vs. 7.16/7.17), and OCR accuracy (62.0% vs. 55.4%/56.2%). Type-R w/ SD3 wins on GPT scores (7.30/8.46 vs. 4.67–4.97/7.16–7.17) but loses on OCR (48.6% vs. 55.4%/56.2%), showing that the post-processing correction is bounded by the base model's initial text rendering fidelity. On FID and CLIP, TextDiffuser-2 scores better (FID 33.8, CLIP 34.7), but the authors argue these metrics are unreliable here: FID overfits to the narrow 5,000-image reference set, and CLIP exhibits a text-spotting bias that favors word-only images without meaningful backgrounds. The user study validates the GPT evaluation, with Type-R w/ Flux significantly outperforming TextDiffuser (p = 1.55e-11) and TextDiffuser-2 (p = 4.14e-18) on text-image matching. Overall, Type-R w/ Flux achieves the best quality–accuracy trade-off, approaching the OCR accuracy of naive text-rendering baselines while maintaining high graphic design quality.

## Relation to Prior Work

Type-R departs from the dominant paradigm of improving text rendering through conditional generation (TextDiffuser, TextDiffuser-2) or better text encoders, instead framing the problem as a post-hoc retouching pipeline that is agnostic to the base generator. It repurposes a collection of off-the-shelf components—scene text detection (DeepSolo), recognition (PaddleOCR), inpainting (LaMa), VLM-based layout planning (GPT-4o), and text editing (AnyText)—into a unified four-stage pipeline, with the optimal-transport matching formulation providing a principled way to identify which words are missing, redundant, or misspelled. The approach is conceptually related to prior work on using external models to refine diffusion outputs (RPG, self-correcting LLM-controlled diffusion), but applies this idea specifically and systematically to typographic errors.

## Why It Matters / Open Questions

The practical significance is that Type-R is a drop-in module requiring no fine-tuning, making it immediately applicable as new T2I models (Flux, SD3.5, DALL-E 3) emerge without retraining. The finding that a generic T2I model plus post-processing outperforms a purpose-built typography model (TextDiffuser-2) in both graphic design quality and OCR accuracy challenges the assumption that conditional generation is necessary for accurate text rendering. Key limitations remain: the pipeline stacks multiple external models (high compute cost), does not preserve reading order, struggles with case sensitivity, and depends on the compatibility between the text editor and OCR model (e.g., PaddleOCR outperforms SOTA CLIP4STR-B* simply because AnyText was trained with Paddle-compatible losses). Open questions include whether the pipeline can be consolidated (e.g., using the text editor for both erasing and correction), how it generalizes to non-Latin scripts, and whether a single learned model could replace the multi-stage heuristic pipeline.
