## Problem

Current point cloud backbones like PTv3 rely on global serialization and scattering of points between attention stages, incurring super-linear latency and severe GPU underutilization because random memory access patterns conflict with GPU tiling architecture. No prior method holistically unifies geometric locality, attention mechanisms, and GPU memory layout in a single design, leaving a gap between algorithmic structure and hardware efficiency.
![Teaser figure](../imgs/CVPR20252642/cropped_page0_idx0.webp)

## Input / Output

The method consumes dense 3D point clouds (500k–2M points per indoor scene on ScanNet; outdoor LiDAR sweeps on nuScenes) and produces per-point semantic class labels. Points are first mapped via Perfect Spatial Hashing into contiguous memory arrays where address proximity encodes spatial proximity, then processed through multi-stage transformer blocks with fixed attention scopes of 4096 points per bucket. The architecture is evaluated on A100, H100, and L4 GPUs, with the key constraint that all bucket operations must fit within a single GPU tile (1024 points) to exploit L1/shared memory.

## Method

Flash3D introduces a principled locality mechanism based on Perfect Spatial Hashing (PSH) that scatters 3D points into compact contiguous arrays using four manually defined hash functions (XOR-mod, XOR-div, Zorder-mod, Zorder-div), with an optimistic-racing rebalancing step to enforce uniform bucket capacity. On top of this layout, a Bucket-and-Swin attention mechanism partitions features into spatially coherent buckets and achieves zero-overhead window shifting by logically reassigning buckets to attention scopes—loading the appropriate buckets into L1 on-the-fly—rather than physically permuting memory. This logical shuffle is fused directly into a FlashAttention-2 CUDA kernel (via ThunderKittens), eliminating the expensive global serialization that dominates PTv3's latency. An in-bucket pooling layer performs tile-local reduction (e.g., 2× pooling over 1024 points) without inter-tile communication, and the multi-stage backbone stacks different hash functions across stages to progressively expand receptive fields.

## Results

On ScanNet indoor semantic segmentation, Flash3D achieves 77.9 val / 78.6 test mIoU with 46.2M parameters, outperforming PTv3 (77.5 / 77.9) while using 2.4 GB vs. 5.2 GB memory and 24 ms vs. 61 ms A100 latency. On nuScenes outdoor segmentation, under equal parameter budgets (46.2M), Flash3D reaches 81.2 mIoU vs. PTv3's 80.4 with 2.4× less memory (0.5 GB vs. 1.2 GB) and 2.25× faster A100 inference (20 ms vs. 45 ms). Under equal memory budgets (1.2 GB), Flash3D scales to 129.4M parameters for 81.5 mIoU while PTv3 remains at 46.2M / 80.4 mIoU, with Flash3D still 1.88× faster.

## Baselines & Comparisons

Against PTv3 (the primary baseline), Flash3D wins on every reported metric across both datasets: higher mIoU (+0.4 on ScanNet test, +0.8 on nuScenes at equal params, +1.1 at equal memory), lower memory (2.4× less on ScanNet, 2.4× less on nuScenes at equal params), and substantially lower latency (2.5× faster on A100 for ScanNet, 2.25× faster on A100 for nuScenes). Against MinkUNet, Flash3D achieves significantly higher mIoU (78.6 vs. 73.6 on ScanNet; 81.2 vs. 73.3 on nuScenes) at comparable parameter counts (46.2M vs. 37.9M), though MinkUNet uses slightly less memory on nuScenes (1.7 GB vs. 0.5 GB for Flash3D at equal params). Notably, Flash3D's latency advantage is more pronounced on edge hardware (L4), where PTv3 degrades to 69 ms while Flash3D stays at 24 ms, highlighting the hardware-aware design benefit.

## Relation to Prior Work

Flash3D is a direct hardware-aware re-architecture of PTv3, replacing its costly global serialization and scattering with a Perfect Spatial Hashing (PSH) mechanism that maps spatially proximate points into contiguous GPU-tile-aligned memory. The Bucket-and-Swin attention mechanism adapts Swin Transformer's window-shifting paradigm to point cloud buckets, fusing logical bucket reassignment with FlashAttention-2's tiled CUDA kernel to achieve zero-overhead region shifting. Unlike prior point transformers (PTv1/2, FlatFormer, OctFormer) that define geometric locality through learned or fixed partitioning, Flash3D uses declarative hash functions (XOR-mod, XOR-div, Z-order variants) to flexibly define locality while guaranteeing even bucket sizes that saturate GPU compute throughput.

## Why It Matters / Open Questions

The finding that PTv3 achieves less than 5% TensorCore utilization—wasting over 95% of GPU compute—reframes the point transformer efficiency problem as fundamentally a hardware-locality problem rather than an algorithmic one. Flash3D's 2.25× speedup and 2.4× memory reduction, achieved while improving mIoU, demonstrate that geometry-hardware co-design is a prerequisite for scaling point cloud backbones to larger models and wider attention scopes. Open questions include whether the PSH-based locality mechanism generalizes to non-uniform point densities (e.g., multi-sensor fusion), how it performs on edge hardware like Orin/ThorU, and whether the manually defined hash functions can be replaced by learned locality without sacrificing the contiguity guarantees that enable GPU tiling alignment.
