## Problem

Existing 3D scene graph methods restrict nodes to objects and edges to spatial relationships (e.g., 'on', 'in'), lacking any representation of small interactive elements (handles, knobs, switches) and their functional relationships with objects. This omission prevents higher-level functional reasoning such as identifying which switch controls a specific light or enabling robotic manipulation of scene elements, and no training data exists to learn these complex functional relationships from scratch.
![Teaser figure](../imgs/CVPR20252089/cropped_page0_idx0.webp)

## Input / Output

The method takes a sequence of posed RGB-D frames of an unseen indoor environment and produces a directed functional 3D scene graph where nodes are 3D objects and interactive elements (each with a 3D bounding box, fused point cloud, and natural language description) and edges are functional relationships (local rigid connections like door-handle, or remote connections like TV-remote) annotated with a relationship description and confidence score. The graph is open-vocabulary, supporting arbitrary object and element labels without a fixed taxonomy, and is structured as a JSON-serializable format for downstream LLM querying.

## Method

OpenFunGraph is a zero-shot, training-free pipeline that chains foundation models in three stages. First, a progressive detection strategy uses RAM++ to generate object tags, which prompt GroundingDINO for 2D detection; a novel prompting scheme concatenates object tags with LLM-suggested element tags (e.g., 'door. handle') to improve small-part detection, and multi-view 2D masks are backprojected and fused into 3D node candidates. Second, multi-view natural language descriptions are generated by cropping each node, captioning with LLAVA (using multi-scale crops and red outlines for small elements), and summarizing with GPT-4. Third, functional relationships are inferred via sequential reasoning: local edges are found by spatial overlap filtering followed by LLM feasibility reasoning, while remote edges use a confidence-aware strategy where the LLM proposes candidate object-element pairs, the VLM assesses visual feasibility per pair, and the LLM assigns relative confidence scores using global scene context.

## Results

On SceneFun3D, OpenFunGraph achieves 73.0% overall node Recall@3 and 82.8% Recall@10, outperforming the strongest baseline (ConceptGraph*+IED) by 22% in R@3. On the more challenging FunGraph3D dataset, OpenFunGraph reaches 55.5% overall node R@3 and 65.8% R@10, surpassing the best baseline by 43% in R@3. For triplet (functional relationship) prediction, OpenFunGraph achieves 45.8% overall R@5 on SceneFun3D and 29.8% R@5 on FunGraph3D, exceeding the best baselines (ConceptGraph*+IED) by 76% and 189% respectively in R@5.

## Baselines & Comparisons

OpenFunGraph consistently outperforms both adapted baselines across all metrics and both datasets. Against ConceptGraph* [27], which focuses on object-level perception and spatial relationships, OpenFunGraph gains 160% in overall node R@3 on SceneFun3D (73.0 vs. 28.3) and 176% on FunGraph3D (55.5 vs. 20.1), primarily because ConceptGraph* nearly fails at detecting interactive elements (6.6% R@3 on SceneFun3D). Adding the proposed interactive element detection (ConceptGraph*+IED) narrows the gap but OpenFunGraph still leads by 22% (SceneFun3D) and 43% (FunGraph3D) in node R@3, attributed to the dedicated multi-view description stage. Against Open3DSG* [41], which relies on object-level CLIP features and spatial-proximity edge distillation, OpenFunGraph achieves 95% higher node R@3 on SceneFun3D (73.0 vs. 37.4 for the fair-comparison variant Open3DSG*†) and 174% higher on FunGraph3D (55.5 vs. 20.2). For triplet prediction, OpenFunGraph's sequential reasoning strategy (local then remote) yields 45.8% R@5 on SceneFun3D versus 18.8% for ConceptGraph*+IED and 15.7% for Open3DSG*†, demonstrating that decomposing functional relationship inference into rigid-connection and remote-control sub-tasks is substantially more effective than prompting the LLM to predict all connections simultaneously.

## Relation to Prior Work

This paper extends the 3D scene graph generation line (ConceptGraphs, Open3DSG) by introducing interactive elements as first-class nodes and functional relationships (local and remote) as edges, going beyond the spatial-only relationships (on, in, near) that prior methods model. It builds directly on SceneFun3D's fine-grained interactive element annotations but adds the missing object-level annotations and inter-element functional relationships. Methodologically, it departs from the learned-pipeline paradigm of Open3DSG (which relies on object-level CLIP features and spatial-proximity edge distillation) and ConceptGraph (which uses a direct LLM inference over object nodes) in favor of a zero-shot, foundation-model-driven pipeline combining RAM++, GroundingDINO, LLAVA, and GPT-4 with a sequential Chain-of-Thought reasoning strategy for edge inference.

## Why It Matters / Open Questions

The functional 3D scene graph representation opens a path toward scene-level functional reasoning for robotics and embodied AI, enabling agents to identify which switch controls which light or which handle opens which door—information that spatial scene graphs fundamentally cannot encode. The FunGraph3D dataset, with its high-fidelity laser scans, egocentric interaction videos, and functional relationship annotations, addresses a real gap in benchmarking, though its small scale (14 scenes, 201 interactive elements) limits statistical confidence. Key open questions include whether the zero-shot GPT-4/LLAVA pipeline can be replaced by lighter learned components for deployment, how the approach scales to larger or dynamic scenes, and whether the confidence-aware remote relationship reasoning generalizes beyond the relatively simple indoor settings tested here.
