## Problem

Previous SVG generation methods—whether traditional image processing or deep learning—rely on approximating images through collections of path curves, lacking semantic understanding and producing overly complex, artifact-prone outputs. The balance between curve-based shape approximation and accurately recognizing SVG primitives (circles, ellipses, polygons, editable text) has remained unexplored, and no existing method generalizes across diverse SVG types from icons to complex diagrams while preserving primitive structure.

## Input / Output

StarVector accepts either a raster image (224×224 for the 1B variant, 384×384 for the 8B variant) or a free-form text instruction as conditioning input, and produces compilable SVG code as an autoregressive token sequence. The image is converted into a fixed set of visual tokens (257 or 576) that precede the SVG code tokens, while text is tokenized by the LLM's own tokenizer. At inference, the model generates k candidate SVGs with varied decoding parameters and selects the best by DinoScore, with a logit bias on the <svg-end> token to encourage syntactically complete outputs.

## Method

StarVector frames image vectorization as an inverse rendering and code generation task within a multimodal LLM: a Vision Transformer (CLIP ViT-B/32 or SigLIP) extracts patch features, which are projected into the LLM's embedding space via a non-linear adapter (FC layers with Swish activation and LayerNorm), and a code-specialized LLM (StarCoder-1B or StarCoder2-7B) autoregressively predicts SVG code tokens conditioned on the visual or textual tokens. The key insight is that by training directly in the SVG code space on the 2M-sample SVG-Stack dataset with next-token cross-entropy, the model learns to emit semantically appropriate primitives (e.g., a single <circle/> instead of a long path) without any explicit pixel-reconstruction or differentiable-rendering objective. Two model variants (1B and 8B) differ in image resolution, visual token count, LLM capacity, and context length (8k vs. 16k tokens). Training uses AdamW at lr=1e-5 for 2 epochs, followed by fine-tuning on task-specific datasets (SVG-Emoji, SVG-Fonts, SVG-Icons, SVG-FIGR), and inference leverages vLLM with top-p nucleus sampling, beam search, and a length penalty.

## Results

StarVector-8B achieves the highest DinoScore (the paper's proposed perceptual metric) on 6 of 8 Image-to-SVG benchmarks, reaching 0.966 on SVG-Stack, 0.982 on SVG-Fonts, and 0.984 on SVG-Icons, while generating SVGs of only ~3k tokens (vs. ~18k for LIVE). On SVG-Diagrams, StarVector-8B scores 0.959 DinoScore and 0.093 LPIPS, outperforming LIVE (0.870 Dino, 0.121 LPIPS) and being the only method that correctly uses text, rectangle, and arrow primitives. For Text-to-SVG, StarVector-8B achieves FID 10.067 and FID-CLIP 1.308 on SVG-FIGR, substantially outperforming GPT-4 (FID 32.953) and IconShop (FID-CLIP 4.657).

## Baselines & Comparisons

StarVector-8B outperforms all baselines on DinoScore (the paper's proposed perceptual metric) across 6 of 8 Image-to-SVG benchmarks, with the largest margins over Im2Vec (0.966 vs. 0.692 on SVG-Stack) and DiffVG (0.966 vs. 0.810). LIVE achieves the best MSE and SSIM scores on every dataset but at the cost of ~18k tokens per SVG (≈6× the ground-truth length), producing visually complex outputs with artifacts; StarVector-8B matches or exceeds LIVE on DinoScore while using only ~3k tokens. On SVG-Diagrams, StarVector-8B (Dino 0.959) is the only method that correctly emits text, rectangle, and arrow primitives, whereas LIVE (0.870), VTracer (0.882), and AutoTrace (0.874) produce only path-based approximations. For Text-to-SVG, StarVector-8B (FID 10.067, FID-CLIP 1.308 on SVG-FIGR) substantially outperforms GPT-4 (FID 32.953), CodeLlama-70B (FID 29.002), and IconShop (FID-CLIP 4.657). GPT-4V generates very short SVGs (~300–700 tokens) but with poor visual fidelity (Dino 0.852 on SVG-Stack), confirming that general-purpose MLLMs lack the specialized SVG primitive knowledge that StarVector acquires through targeted training on SVG-Stack.

## Relation to Prior Work

This paper departs from two established lineages: (1) traditional and deep-learning image vectorization methods (Potrace, VTracer, DeepSVG, Im2Vec, LIVE) that approximate images via curve fitting or latent-space optimization but underutilize SVG primitives, and (2) MLLM-based code generation (StarCoder, StarCoder2) that has not previously been applied to vector graphics. The key conceptual move is reframing image vectorization as an inverse rendering and code generation problem, where an MLLM directly predicts SVG code with primitive awareness (circles, ellipses, text, polygons) rather than decomposing everything into Bézier paths. This unifies Image-to-SVG, Text-to-SVG, and diagram generation under a single autoregressive code-generation framework, a formulation the authors explicitly identify as previously unexplored.

## Why It Matters / Open Questions

The paper provides the first large-scale SVG training dataset (SVG-Stack, 2M samples) and the first unified multi-task benchmark (SVG-Bench) for SVG generation, filling a critical gap that has limited reproducibility and comparability in this area. The finding that pixel-based metrics (MSE, SSIM) are fundamentally misaligned with perceived SVG quality—supported by near-zero Spearman correlation with human judgments—challenges a default evaluation practice and motivates the proposed DinoScore metric. Key limitations include the 16k token context window (inadequate for complex SVGs), reliance on code prediction without visual feedback during generation, and LLM-constrained inference speed, all of which point toward future work integrating pixel-based signals or longer-context models.
