## Problem

Existing goal-specification modalities for robotic manipulation each have critical shortcomings: language is ambiguous or overly verbose, goal images/videos encode irrelevant background information, and prior visual-prompt methods (RT-Sketch, RT-Trajectory) convey only positional trajectories while neglecting the action directional information (gripper orientation and post-contact movement) that is essential for accurate manipulation. The paper asks whether a simple, non-redundant prompt format can simultaneously express both low-level action goals (where and how to interact) and high-level task planning (the sequence of key-frame steps).

## Input / Output

The model receives an RGB image overlaid with four colored crayon-style marks (blue circle for contact point, red/green lines for end-effector z/y axes, yellow line for post-contact movement direction) plus a parallel text prompt encoding the exact 2D coordinates and unit-vector values of those marks, and a depth map for 3D lifting. The output is formulated as a language-modeling task: the model generates a text string containing the 3D contact position (lifted from 2D via depth and camera intrinsics), the 3D z-axis and y-axis unit vectors (jointly defining the SE(3) rotation), and optionally the 3D post-contact movement direction. For long-horizon tasks, a sequence of such key-frame prompt images is fed in order, and the predicted movement directions are used to chain steps together.

## Method

CrayonRobo builds on the ManipLLM backbone (CLIP visual encoder + LLaMA with LoRA adapters and a multi-modal projection module, with the primary VLM parameters frozen) and introduces a progressive training strategy: the model is trained on four input-pair configurations that incrementally add the z-axis, y-axis, and movement-direction prompts, so it learns to interpret each prompt type independently. Three losses are optimized jointly: a cross-entropy text supervision loss on 100-bin discretized 3D direction values, a Gram-Schmidt orthogonality loss enforcing geometric consistency between the predicted z and y axes, and a projection loss that unprojects the predicted 3D directions back to 2D and penalizes cosine-similarity mismatch against the input 2D prompt vectors. At inference, prompts are either auto-generated (Grounded-DINO for object localization, GPT-4 for selecting direction lines from 32 candidates) or hand-drawn by a user; the model then predicts the SE(3) contact pose and movement direction, and a sequence of key-frame steps is executed sequentially to complete long-horizon tasks.

## Results

On the PartNet-Mobility benchmark (~1500 object shapes, SAPIEN simulator), CrayonRobo with manual crayon prompts achieves 0.74/0.72 success rate on seen/unseen tasks (finger gripper), substantially outperforming all baselines. With automatically generated prompts (Grounded-DINO + GPT-4), the method still achieves 0.64/0.62, maintaining its advantage over baselines despite positional noise from bounding-box center selection. For multi-step long-horizon tasks (e.g., pull-then-push), the method reaches 0.69/0.68 on seen/unseen tasks. In real-world zero-shot evaluation (Franka Emika + RealSense 415), success rates range from 5/5 to 9/10 across five manipulation tasks, with multi-step tasks (open microwave, wipe table, heat toaster) achieving 6–8/10.

## Baselines & Comparisons

CrayonRobo outperforms all five baselines on both seen and unseen tasks. Against the pure-vision Flowbot3D [15], which predicts articulation flow on point clouds, CrayonRobo's explicit prompt-based approach avoids the ambiguity of inferring both contact point and direction from a single flow field. Compared to the language-conditioned ManipLLM [31] (the backbone architecture CrayonRobo builds upon), adding visual crayon prompts yields a clear gain, confirming that language alone is insufficient for precise spatial specification. Against the goal-image 3D method Implicit3D [61], which requires both initial and target point clouds, CrayonRobo needs only a single RGB image with simple 2D annotations, reducing input complexity. Versus RT-Trajectory [20], which draws full end-effector trajectories, CrayonRobo's per-key-frame prompts avoid trajectory overlap confusion and additionally encode post-contact movement direction (yellow prompt), which RT-Trajectory lacks. The goal-video baseline AVDC [57] is the weakest, with only 10.2% of generated videos successfully completing tasks, highlighting the fragility of video-generation-based conditioning.

## Relation to Prior Work

CrayonRobo builds directly on the ManipLLM VLA backbone [31], reusing its LLaMA + CLIP architecture with LoRA adapters, but fundamentally redefines the input interface: instead of language instructions or goal images, it uses multi-color 2D crayon-style visual prompts (contact point, z/y-axis directions, post-contact movement) paired with a structured text prompt. This departs from prior visual-prompt methods like RT-Sketch [49] (which only depicts the final object state) and RT-Trajectory [20] (which draws full end-effector paths) by encoding both positional and directional action information at discrete key-frames, and by leveraging key-frame decomposition [18, 26, 46] for long-horizon planning. The progressive training strategy with multiple loss functions (text supervision, Gram-Schmidt orthogonality, 2D projection consistency) is a methodological contribution not present in prior VLA manipulation work.

## Why It Matters / Open Questions

The paper demonstrates that simple, human-drawable 2D prompts can serve as an effective and interpretable interface for goal-conditioned manipulation, bridging the gap between ambiguous language and overly detailed goal images/videos. The zero-shot sim-to-real transfer without fine-tuning and the demonstrated noise tolerance (up to 20% directional perturbation) suggest practical deployability. Key limitations include the lack of built-in obstacle avoidance (requiring external planners like CuRobo), dependence on GPT-4 for automatic prompt generation, and evaluation primarily on articulated objects in a single simulator. Open questions include whether the approach scales to multi-object or deformable-object scenes, whether the key-frame decomposition generalizes to truly open-ended tasks, and whether the GPT-4-in-the-loop prompt generation introduces unacceptable latency or failure modes for real-time deployment.
