## Problem

Developing robust mobile OS navigation agents requires diverse, real-world training data reflecting the wide variety of UI layouts and interactions users encounter, yet existing datasets rely on expensive manual annotation, single-platform emulators, or simulated environments that quickly become obsolete with OS updates. No large-scale, cross-platform dataset of real-world mobile navigation procedures exists that can be continuously expanded as platforms evolve.
![Teaser figure](../imgs/CVPR20251938/cropped_page0_idx1.webp)

## Input / Output

The dataset collection pipeline ingests YouTube instructional videos (under 15 minutes with English narration transcripts) and produces 313K annotated frames from 20K videos, each labeled with an action type (touch, scroll, long press, typing, multi-touch, zoom, hardware) and screen coordinates set to the center of the selected UI element's bounding box. For downstream agent evaluation, the model receives the current screen image, task name, and the last four actions as input and predicts the next action as a type-coordinate pair, evaluated via exact matching against annotated interaction regions.

## Method

The framework combines three components: (1) OCR-based scene transition detection using Paddle OCR at 4 FPS with Levenshtein distance on text at identical screen locations (threshold: >20% changed text), achieving 95.04% F1 over vision-based baselines; (2) UI element detection via GroundingDINO plus Paddle OCR with mobile-specific heuristic filtering (merging overlapping boxes, prioritizing by shape and screen coverage), reaching 99.87% hit ratio; and (3) a novel 3-step GPT-4o action identification using Set-of-Marks representation—scene summary without markings, initial action identification with temporal context (two previous and two next frame summaries) and narration, then refined localization via zoomed views around candidate elements. For agent training, SeeClick (Qwen-VL) and Llama-3.2 are LoRA-fine-tuned on MONDAY as a pretraining stage, then further fine-tuned on AitW or AMEX, yielding 18.11%p average gain on the unseen Windows Mobile platform.

## Results

On the unseen Windows Mobile platform, MONDAY-induced variants achieve an average performance gain of 18.11%p over their original pre-trained counterparts, with the largest gain of +24.15%p (Llama-3.2-MONDAY AMEX-finetuned: 47.32% vs. Llama-3.2: 23.17%). On the in-distribution MONDAY test set, MONDAY-induced models substantially outperform baselines (e.g., SeeClick-MONDAY AitW-finetuned: 60.71% vs. SeeClick: 37.45%). The framework components also achieve strong standalone metrics: 95.04% F1 for scene transition detection, 99.87% Hit Ratio for UI element detection, and 91.84% touch action accuracy for the 3-step identification method.

## Baselines & Comparisons

For scene transition detection, the OCR-based method (95.04% F1) outperforms both PySceneDetect/SceneDetect (82.27%) by 12.77%p and Video2Action's YUV-diff (70.86%) by 24.18%p, with the gap attributed to robustness against dark mode and subtle UI changes. For UI element detection, the GroundingDINO + Paddle OCR + heuristic filtering pipeline achieves 99.87% Hit Ratio, surpassing OmniParser (91.83%) by 8.04%p, with OmniParser systematically missing home screen icons and bottom-positioned elements. For downstream navigation, MONDAY-induced variants consistently outperform both SeeClick and Llama-3.2 baselines across all four test sets; the most dramatic gains appear on the unseen Windows Mobile platform, where Llama-3.2-MONDAY (AMEX-finetuned) reaches 47.32% versus 23.17% for Llama-3.2 alone (+24.15%p), and SeeClick-MONDAY (AMEX-finetuned) reaches 51.95% versus 37.56% for SeeClick (+14.39%p). On in-distribution AitW and AMEX test sets, MONDAY-induced variants also maintain or improve performance (e.g., Llama-3.2-MONDAY AitW-finetuned: 68.16% vs. 58.96%), confirming that the pretraining benefit does not come at the cost of in-domain accuracy.

## Relation to Prior Work

This paper positions itself against the manual-annotation paradigm that dominates mobile OS navigation datasets (RICO, AitW, AMEX) and against prior automated video-extraction methods like Video2Action (pixel-difference-based) and Chen et al. (requiring pre-trained models on human-labeled data). It builds on Set-of-Marks prompting for spatial grounding and GroundingDINO for open-set detection, but departs from both by replacing pixel-level scene detection with OCR-based text tracking and by introducing a 3-step GPT-4o refinement pipeline for action identification. The broader lineage connects to web-scale data collection for LLMs, transposing that philosophy to mobile GUI navigation.

## Why It Matters / Open Questions

MONDAY provides the first large-scale, cross-platform (iOS + Android), fully automated mobile OS navigation dataset, addressing the obsolescence problem of static datasets as OS versions evolve. The 18.11%p gain on an unseen platform (Windows Mobile) demonstrates that real-world diversity in training data meaningfully improves generalization beyond what simulator-based datasets can offer. Key limitations include reliance on proprietary GPT-4o for action identification, a ~19% residual error rate on full action matching, and coverage restricted to iOS/Android. Open questions include whether the pipeline can be made model-agnostic, how it handles rapidly changing UI paradigms (e.g., AI-generated interfaces), and whether the dataset's YouTube-sourced task distribution adequately represents edge-case user behaviors.
