## Problem

Existing document parsing benchmarks suffer from three critical limitations: narrow document diversity (primarily academic papers, ignoring textbooks, newspapers, handwritten notes, and financial reports), inconsistent evaluation metrics that apply generic text similarity scores to structurally rich content like LaTeX formulas and HTML tables, and a lack of fine-grained analysis that would reveal per-element or per-document-type weaknesses. This makes it impossible to fairly compare pipeline-based and end-to-end vision-language model approaches across realistic document parsing scenarios.

## Input / Output

The benchmark takes 981 PDF page images spanning 9 document types (books, slides, financial reports, textbooks, exam papers, magazines, academic papers, handwritten notes, newspapers) as input. Model outputs are expected as Markdown text, which the evaluation pipeline parses via ordered regex extraction (LaTeX tables → HTML tables → display formulas → Markdown tables → code blocks → pure text) before matching against ground truth. Ground truth annotations include 19 layout bounding-box categories, reading order sequences, 70,000+ span-level content labels (text in Unicode, formulas in LaTeX, tables in both HTML and LaTeX), and 9 bbox-level attribute tags (language, background type, rotation, merged cells, etc.).

## Method

OmniDocBench contributes a systematic dataset construction pipeline and a flexible multi-level evaluation framework. For data construction, over 200,000 PDFs are collected from Common Crawl and search engines, visually clustered using ResNet-50 features and Faiss to sample 6,000 diverse pages, then balanced to 981 final pages via manual attribute annotation; pre-annotation uses LayoutLMv3, PaddleOCR, UniMERNet, and GPT-4o, followed by annotator correction and expert quality inspection with CDM rendering checks. The evaluation framework operates at three levels: end-to-end (full-page Markdown comparison), task-specific (layout detection mAP, OCR edit distance, table TEDS, formula CDM), and attribute-based (performance sliced by document type, column layout, visual degradation, and content attributes). A key technical component is the Adjacency Search Match algorithm, which computes a Normalized Edit Distance matrix between ground-truth and predicted paragraphs, then iteratively merges or splits adjacent paragraphs to find optimal alignment, mitigating sensitivity to paragraph segmentation differences. Different content types receive type-appropriate metrics: Normalized Edit Distance for text and reading order, TEDS plus edit distance for tables (converted to HTML), and CDM plus BLEU for formulas, with an ignore-handling mechanism that excludes inconsistently-formatted elements like headers, footers, and captions from scoring.

## Results

On OmniDocBench's comprehensive end-to-end evaluation (Table 2), MinerU achieves the best OverallEdit for English (0.15) and competitive Chinese (0.357), while Qwen2-VL-72B leads on Chinese OverallEdit (0.327) and Table TEDS (76.8 EN / 76.4 ZH). For formula recognition, Qwen2-VL-72B attains the highest CDM score (82.2 EN), and GPT-4o leads the component-level formula subset with 86.8% CDM. Nougat performs worst overall (0.452 EN / 0.973 ZH OverallEdit), particularly failing on Chinese text (0.998 TextEdit) and table recognition (0.0 Table TEDS ZH). Across 9 page types, pipeline tools dominate on academic papers and financial reports, while general VLMs generalize better to handwritten notes and slides.

## Baselines & Comparisons

Among pipeline tools, MinerU outperforms Marker and Mathpix on English text (0.061 vs. 0.08/0.105 TextEdit) and reading order (0.079 vs. 0.114/0.108), while Mathpix leads on Chinese formula CDM (62.1 vs. 42.9/11.7). Among general VLMs, Qwen2-VL-72B dominates on Chinese OverallEdit (0.327 vs. 0.399 GPT-4o, 0.443 InternVL2-76B), Table TEDS (76.8/76.4 vs. 72.0/62.9 GPT-4o), and formula CDM EN (82.2 vs. 72.8/67.4), but GPT-4o achieves the best component-level formula CDM (86.8%) and competitive English text (0.144). Expert VLM Nougat is the weakest overall, scoring 0.998 on Chinese TextEdit and 0.0 on Chinese Table TEDS, indicating near-total failure on non-English and structured content. GOT-OCR shows moderate performance (0.287 EN OverallEdit) but lags behind both pipeline tools and top general VLMs on tables and formulas. On layout detection (Table 6), DocLayout-YOLO (integrated in MinerU) achieves the highest average mAP (47.38), explaining MinerU's strong end-to-end results; for table recognition (Table 7), RapidTable leads with 82.5 overall TEDS; for OCR (Table 8), PaddleOCR achieves the best English edit distance (0.071).

## Relation to Prior Work

This paper does not build on a single prior method but rather unifies and extends the fragmented landscape of document parsing benchmarks. Prior single-task benchmarks (PubLayNet, PubTabNet, Im2Latex-100K) evaluate isolated components, while the few end-to-end benchmarks (Nougat's arXiv-only set, GOT-OCR's 90-page set) are narrow in document type and rely on coarse page-level metrics. OmniDocBench carves new ground by introducing a multi-level evaluation framework—end-to-end, task-specific, and attribute-based—across 9 document types with 19 layout categories and 15 attribute labels, applying specialized metrics (TEDS for tables, CDM for formulas) where generic edit distance is insufficient.

## Why It Matters / Open Questions

OmniDocBench is likely to become the de facto standard benchmark for document parsing, given its breadth (9 document types, 981 pages, 100k+ annotations) and its unified evaluation protocol that fairly compares pipeline tools and VLMs under identical conditions. A key open question it surfaces is how to make VLMs handle high-density, multi-column documents (e.g., newspapers) where they currently fail due to input resolution and token-length constraints, while pipeline tools succeed via layout-based segmentation. The benchmark also reveals that no single paradigm dominates across all document types, suggesting hybrid or layout-aware VLM designs as a promising direction. Limitations include the relatively small page count (981) and the fact that evaluation is limited to single-page parsing rather than multi-page document understanding.
