## Problem

Predicting how a hand will move and where it will make contact with an object (interaction trajectories) from a single image, action description, and a 3D contact point remains unsolved for everyday objects that are small, thin, transparent, occluded, or deformable and for which 3D models are unavailable. Existing HOI datasets are limited to constrained lab setups with few object categories, and prior methods either require known 3D object geometry or assume the hand is visible in the input image, both of which fail in practical everyday scenarios.

## Input / Output

The method takes a single RGB image of the object, a free-text action description, and a 3D contact point (encoded as a Gaussian heatmap in a fixed 16×16×16 voxel grid in camera coordinates) as input; in the interpolation setting a goal image showing the final interaction state is additionally provided. The output is a trajectory of T future timesteps, each consisting of MANO hand parameters (pose θ and shape β) and a 778-dimensional binary contact map over the MANO mesh vertices, all expressed in a reference camera coordinate frame. The hand may or may not be visible in the input image, with the absent-hand variant handled via inpainting.

## Method

LatentAct uses a two-stage architecture grounded in the observation that hands interact with diverse objects in a small set of prototypical ways. Stage 1 (Interaction Codebook) is a multi-layer residual VQVAE with a transformer encoder-decoder that tokenizes interaction trajectories into a discrete codebook of 512 entries (512-dim, 6 quantizers, EMA-updated), effectively learning a compact set of reusable motion primitives. Stage 2 consists of a Learned Indexer (a transformer classifier that maps CLIP text, DeiT image, and 3D-convolutional contact features to a probability distribution over codebook indices) and an Interaction Predictor (a transformer decoder that fuses the retrieved codebook embeddings with the same input features to regress MANO parameters and contact maps via separate MLP heads). A semi-automatic data engine extracts 3D hand poses (HaMeR) and contact maps (SAMv2 segmentation intersected with hand mesh, back-projected to 3D) from HoloAssist egocentric videos covering 800 tasks across 120 object and 24 action categories. A diffusion variant (LatentAct-Diff) replaces the single-step predictor with iterative denoising in the codebook latent space, yielding better hand poses but worse contact maps.

## Results

On the most challenging task-level generalization setting (novel object+action combinations), LatentAct achieves 7.61 cm MPJPE and 0.75 F1 for forecasting with hand visible, outperforming HCTFormer (8.32 cm, 0.72) and HCTDiff (8.42 cm, 0.72). For goal-conditioned interpolation, the gap widens: LatentAct reaches 6.72 cm MPJPE and 0.80 F1 versus 7.52 cm/0.76 (HCTFormer) and 8.30 cm/0.77 (HCTDiff). The advantage persists when the hand is absent from the input image (7.93 cm MPJPE, 0.76 F1 for forecasting) and across all four generalization axes (task, object, action, scene). On ARCTIC, zero-shot transfer from HoloAssist-trained LatentAct (15.72 cm MPJPE) is competitive with models trained directly on ARCTIC (14.77 cm).

## Baselines & Comparisons

LatentAct consistently outperforms both baselines on absolute hand pose (MPJPE) and contact map accuracy (F1) across all four generalization settings and both task variants. On task-level forecasting with hand visible, LatentAct reduces MPJPE by 0.71 cm over HCTFormer (7.61 vs 8.32) and 0.81 cm over HCTDiff (7.61 vs 8.42), while improving F1 by 0.03 over both. The margin is largest in the interpolation setting, where LatentAct achieves 6.72 cm MPJPE versus 8.30 cm for HCTDiff (a 1.58 cm gap). However, HCTDiff retains a slight edge on Procrustes-aligned MPJPE (M-PA) in several settings (e.g., 2.75 vs 2.99 cm for forecasting, hand visible), indicating its diffusion-based trajectory shape is marginally better once global pose error is removed. The two-stage codebook design (InterCode + Indexer + InterPred) is validated in Table 4: adding InterCode to HCTFormer reduces MPJPE from 7.52 to 6.72 cm and F1 from 0.76 to 0.80, confirming the latent codebook provides a meaningful inductive bias over direct prediction.

## Relation to Prior Work

This paper extends the HOI generation literature (Text2HOI, DiffH2O, G-HOP) by removing the dependency on 3D object models and visible hands, instead grounding interactions via a 3D contact point in the scene. The core architectural contribution is a two-stage pipeline: a multilayer residual VQVAE (following MoMask [16] and the original VQVAE [48]) that tokenizes interaction trajectories into a learned codebook, followed by a transformer-decoder predictor that retrieves and aligns codebook entries to test-time inputs. The data engine repurposes off-the-shelf 3D hand pose estimation (HaMeR) and video segmentation (SAMv2) to extract 3D annotations from egocentric HoloAssist videos, bypassing the need for controlled multi-camera or MoCap setups used by prior datasets (ARCTIC, GRAB, HOI4D).

## Why It Matters / Open Questions

This is a first step toward learning a general motion prior for everyday hand-object interactions where 3D object models are unavailable, which is the common case for small, thin, transparent, or deformable objects. The modular data pipeline (HaMeR + SAMv2 + back-projection) is reusable for other egocentric datasets and could bootstrap 3D interaction annotations at scale. Key limitations include: no prediction of object state change, assumption of a 3D contact point input, programmatically generated annotations that may contain errors, and evaluation that does not account for the multimodal nature of future prediction. Open questions include combining this motion prior with 3D object models, handling bimanual interactions, and whether the codebook approach scales to longer horizons or more diverse action vocabularies.
