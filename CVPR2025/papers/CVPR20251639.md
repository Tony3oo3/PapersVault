## Problem

Existing layout-as-token methods for document understanding in LLMs assign additional position IDs to layout tokens, which squeezes the position budget available for text content during training and introduces potentially untrained position IDs during long-context inference. This degrades the model's capacity to learn from text and exacerbates performance degradation on multi-page documents where context lengths are large.
![Teaser figure](../imgs/CVPR20251639/cropped_page0_idx0.webp)

## Input / Output

The method consumes OCR-parsed text segments paired with their four-dimensional bounding box coordinates [x1, y1, x2, y2]. Each bounding box is compressed into a single continuous layout token (not a sequence of coordinate tokens), and text tokens and layout tokens are interleaved as the LLM input. The model produces document QA answers or extracted entities and links, evaluated via ANLS on both single-page (DocVQA, SIBR, FUNSD, CORD) and multi-page (MP-DocVQA, DUDE) benchmarks.

## Method

LayTokenLLM introduces a layout tokenizer that compresses each text segment's bounding box into a single layout token via a learnable query attending to a projected box embedding (b = F_Attn(t, F_B(Box))). A key positional encoding scheme assigns each layout token the same position ID as the first text token in its segment (P = [0, 1, …, T−1, 0]), eliminating all extra position IDs and preserving the full position budget for text (100% T-Ratio) while keeping inter-segment positional distances intact. A novel pre-training objective, Next Interleaved Text and Layout Token Prediction (NTLP), jointly supervises text tokens with cross-entropy loss and layout tokens with MSE loss through a dedicated layout head that regresses [x1, y1, x2, y2], enabling cross-modal prediction between text and layout. Training uses LoRA on a frozen LLM backbone (Qwen1.5-7B or Llama3-8B), with only the layout tokenizer, layout head, and LoRA adapters updated, keeping the approach lightweight and efficient.

## Results

LayTokenLLM-8B (Llama3-8B backbone) achieves ANLS of 85.11 on DocVQA, 92.20 on SIBR, 81.62 on FUNSD, 78.30 on CORD, 74.31 on MP-DocVQA, and 52.00 on DUDE. The most striking gain is on multi-page document VQA: LayTokenLLM-7B scores 72.81 on MP-DocVQA and 49.72 on DUDE, surpassing the best competing Layout-as-Token method (59.17 on MP-DocVQA, 41.01 on DUDE) by over 10 and 8 percentage points respectively. On single-page tasks, LayTokenLLM-8B leads on SIBR (92.20), FUNSD (81.62), and CORD (78.30) among all compared methods. In terms of efficiency, LayTokenLLM requires only 9.32 FLOPs vs. 28–33 FLOPs for competing layout-as-token formats, while delivering the highest multi-page ANLS average (61.27).

## Baselines & Comparisons

Against plain-text LLM baselines (Qwen1.5-7B-Chat, Llama3-8B-Instruct), LayTokenLLM improves DocVQA ANLS by 17.2 and 10.9 points respectively, and MP-DocVQA by 25.7 and 23.6 points, confirming that layout information is critical. Among Layout-as-Modality methods, LayTokenLLM-7B outperforms LayoutLLM-7B on DocVQA (81.50 vs. 74.27) and CORD (73.79 vs. 63.10) but trails slightly on FUNSD (78.72 vs. 79.98); it also surpasses DocLLM-7B on DocVQA (81.50 vs. 69.50). Against Layout-as-Token baselines trained with identical data and backbone (marked ★), LayTokenLLM-7B leads on all six benchmarks, with the largest margins on MP-DocVQA (+13.6 over the best competitor) and DUDE (+8.7). Compared to MLLMs, LayTokenLLM-8B substantially outperforms InternVL2-8B on SIBR (92.20 vs. 68.39) and MP-DocVQA (74.31 vs. 68.00), but falls short on DocVQA (85.11 vs. 91.66) where high-resolution visual input aids dense-text reading. On multi-page DUDE, LayTokenLLM-8B exceeds MPLUG-DocOwl2-8B by 5.23 points (52.00 vs. 46.77), attributed to better text retention versus image compression.

## Relation to Prior Work

This paper extends the layout-as-token paradigm for LLM-based document understanding, building most directly on LayTextLLM [28], which first compressed bounding boxes into a single hidden token. The key departures are (1) a positional encoding scheme that shares the first text token's position ID with the layout token, eliminating all additional position ID allocation, and (2) a Next Interleaved Text and Layout Token Prediction (NTLP) pre-training objective that supervises both text and layout tokens, whereas prior interleaved methods only supervised text. The paper also positions itself against layout-as-modality approaches (LayoutLLM, DocLLM) that require architectural modifications, and against verbose layout-as-token formats (ICL-D3IE, LAPDoc, LMDX) that consume hundreds to thousands of extra position IDs per document.

## Why It Matters / Open Questions

The T-Ratio diagnostic provides a useful and previously unquantified lens on how layout tokenization erodes the effective context window for text learning, and the 100% T-Ratio design is a clean, drop-in solution that practitioners can adopt without architectural changes. The >10% multi-page improvement over comparable layout-as-token baselines and near-plain-text FLOPs make this practically attractive for production document pipelines. However, the method remains OCR-dependent and explicitly cannot handle graphical elements like charts and icons, and the NTLP objective, while effective, is a relatively straightforward extension of next-token prediction to a second modality. Open questions include whether the shared-position-ID trick generalizes to more complex layout structures (e.g., nested or overlapping regions) and whether finer-grained layout relationship prediction can be incorporated.
