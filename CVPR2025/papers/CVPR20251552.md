## Problem

Frame-based CNN methods for event-camera optical flow discard the microsecond temporal resolution of events, limiting latency to tens of milliseconds. Asynchronous event graph methods (e.g., HUGNet) enable per-event prediction at ultra-low latency but must forgo all temporal accumulation (pooling, normalization), severely degrading accuracy. This paper addresses the resulting accuracy–latency trade-off by combining an accumulation-free event branch with a periodic aggregation branch that adds global context without increasing prediction latency.
![Teaser figure](../imgs/CVPR20251552/cropped_page0_idx0.webp)

## Input / Output

The method consumes only raw event streams (x, y, t, p) filtered by a spatio-temporal contrast threshold—no RGB images are used. It produces two outputs: a sparse per-event optical flow prediction (available at ~50 μs on asynchronous hardware) and a dense periodic optical flow at every pixel, emitted at the configurable PA rate (5–100 Hz). On MVSEC the resolution is 346×260 with 20 Hz ground truth; on Rock Scenes it is 100×100 with 500 Hz ground truth, where motion changes occur within a single 2 ms timestep.

## Method

The architecture (HUGNet2+PA) runs two branches in parallel. The event branch builds a hemispherical directed graph (past-to-future edges only, k=32 neighbors within r_xy and r_t radii) and processes it with HUGNet2—a PointTransformerConv layer followed by four GCNConv layers (32 features each, concatenated to 64)—which is entirely accumulation-free (no instance normalization, no normal vectors) to guarantee zero-wait per-event computation. The periodic branch accumulates the 64-dim GNN output features over a fixed period, applies feature-wise max pooling on a quarter-resolution grid, then refines them through a 2D conv, a SepConvGRU (E-RAFT-style horizontal-then-vertical recurrent convolutions), and another 2D conv (128 channels), producing dense PA features. At each arriving event, the 64-dim GNN node features are concatenated with the 128-dim PA(T−2) features at that pixel (immediately available, hence zero added latency) and fed to a small MLP Event head that predicts the per-event flow vector. Training is supervised with smooth-L1 loss on both heads, using AdamW, data augmentation (flips, temporal stretching, rotations, edge dropout), and a 100-epoch instance-normalization warm-up that is subsequently removed to enforce the accumulation-free constraint.

## Results

On MVSEC (20 Hz groundtruth), HUGNet2+PA₂₀ achieves 1.52 Sparse Endpoint Error with 0.41M parameters and 19.8G OPs/s, trading accuracy for a 3-order-of-magnitude latency reduction (~50 μs vs. 50–100 ms for frame-based methods) and 48× fewer operations per second than ADMFlow. On the more challenging Rock Scenes dataset (500 Hz groundtruth), HUGNet2+PA₁₀₀ achieves 0.030 EPE, outperforming both ADMFlow (0.048) and HUGNet (0.037) while maintaining the same ~50 μs latency. The Event prediction also outperforms the Periodic(T−2) prediction by up to 59% in endpoint error, demonstrating that per-event GNN features enable faster detection of abrupt motion changes.

## Baselines & Comparisons

On MVSEC, HUGNet2+PA₂₀ (1.52 EPE) trails all frame-based baselines in accuracy—ADMFlow (0.49), DCEIFlow (0.51), STE-FlowNet (0.56), and E-RAFT (0.62) all achieve substantially lower error—but does so with 48× fewer operations per second (19.8G vs. 950.2G for ADMFlow) and 17× fewer parameters, while reducing latency from 50–100 ms to ~50 μs. On Rock Scenes, the method reverses this trade-off: HUGNet2+PA₁₀₀ (0.030 EPE) outperforms ADMFlow (0.048) by 37% and HUGNet (0.037) by 19%, while using 8.8G vs. 250G OPs/s and ~50 μs vs. 50–100 ms latency. HUGNet2 alone (1.89 EPE on MVSEC, 0.066 on Rock Scenes) is less accurate than the original HUGNet (1.72 / 0.037) due to the removal of normalization and normal vectors, but achieves a 4-order-of-magnitude latency reduction (>400 ms → ~50 μs). The Event prediction consistently beats the Periodic(T−2) prediction by up to 59% in endpoint error, confirming that the GNN's per-event features enable faster adaptation to abrupt motion changes than the periodic branch alone. Against ADMFlow specifically on Rock Scenes, the Event prediction is better on average than both ADMFlow(T) and ADMFlow(T−2), though ADMFlow(T) briefly leads immediately after a motion change because it has access to post-change frame data.

## Relation to Prior Work

This paper directly extends HUGNet (Dalgaty et al., CVPR-W 2023), which introduced hemispherical update graphs for event-based optical flow but relied on operations requiring future data (instance normalization with on-the-fly statistics, 3D normal vectors), precluding true per-event low-latency prediction. The authors remove those operations to create HUGNet2 and introduce a Periodic Aggregator (PA) branch that performs spatio-temporal pooling over past GNN features, borrowing architectural elements from frame-based methods (SepConvGRU from E-RAFT) to recover the global context that the accumulation-free event branch cannot provide. The broader lineage runs from frame-based CNN event flow estimators (EV-FlowNet, E-RAFT, ADMFlow) through event graph neural networks (AEGNN, HUGNet) to this hybrid asynchronous-plus-periodic architecture, which is the first to combine both paradigms in a single model.

## Why It Matters / Open Questions

The paper demonstrates the first effective solution for ultra-low-latency (~50 μs) optical flow from event cameras, a 3-order-of-magnitude improvement over frame-based methods, while also reducing operations by up to 48×. This opens the door to safety-critical applications (autonomous navigation, obstacle avoidance) where detecting abrupt motion changes within microseconds is essential. Key limitations remain: accuracy on MVSEC still trails frame-based SOTA, the 2-period PA delay can degrade event predictions during very fast transients, and the absence of event-level pooling in the GNN limits scalability under high event density. Open questions include optimal merge functions between GNN and PA features, extension to multimodal (event + RGB) inputs, and whether the PA module can be further scaled (correlation volumes, iterative refinement) without eroding the latency advantage.
