## Problem

Existing visual-language tracking frameworks rely on static multi-modal references (an initial template frame and a fixed language annotation) to locate objects throughout a video sequence. As the target undergoes appearance changes over time, these static references diverge from the object's actual state, causing semantic discrepancies that degrade tracking robustness, particularly in long sequences where the mismatch accumulates.
![Teaser figure](../imgs/CVPR20250686/cropped_page0_idx0.webp)

## Input / Output

The tracker takes a search frame (3×H_S×W_S), a template frame (3×H_T×W_T) that includes both the initial template and dynamically captured patches, and a language annotation string tokenized via BERT into 16 tokens. Images are converted to tokens through HiViT's hierarchical patch embedding (a 4×4 embedding layer followed by two 2×2 merging layers), yielding token dimensions of 512. Beyond the standard bounding box [x, y, w, h], the system also produces updated language descriptions (via BLIP) and top-k dynamic template patches that replace the static reference for subsequent frames. Two input resolutions are supported: 256×256 and 384×384.

## Method

DUTrack adopts a one-stream architecture built on HiViT, where language, template, and search tokens are concatenated and processed jointly through multi-head self-attention with learnable residual scaling parameters (λ₁, λ₂), followed by a tracking head. The Dynamic Template Capture Module (DTCM) exploits the [CLS] token's attention map over the search region to select top-k patches with the highest semantic match to the language description, using them as updated visual templates. The Dynamic Language Update Module (DLUM) invokes a large language model (BLIP) to regenerate the language annotation from the current search image and object category, with update frequency governed by manually set thresholds on scale ratio (ΔS), center displacement (ΔD), and mean RGB color shift (ΔC) between the last update stamp and the current frame. Training is two-stage: 150 epochs of vision-only pretraining on LaSOT, GOT-10K, COCO, TrackingNet, and TNL2K to build strong visual tracking capability, followed by 50 epochs with the dynamic multi-modal reference mechanism enabled on LaSOT, GOT-10K, and TNL2K, using language annotations from DTLLM-VLT.

## Results

DUTrack-384 achieves state-of-the-art results across all five vision-language benchmarks: 74.1% AUC on LaSOT, 52.5% AUC on LaSOT_ext, 65.6% AUC on TNL2K, 71.3% AUC on OTB99-Lang, and 71.0% AUC on MGIT. On vision-only benchmarks, DUTrack-384 reaches 77.8% AO on GOT-10K and 70.1% AUC on UAV123. The model uses only 69.9M parameters and runs at 43.5 fps on an RTX-2080Ti, outperforming heavier baselines like MMTrack (176.9M params, 36.2 fps) in both accuracy and speed.

## Baselines & Comparisons

DUTrack-384 surpasses the strongest vision-language tracker UVLTrack-L [27] by 2.8% AUC on LaSOT (74.1% vs. 71.3%) and by 0.8% AUC on TNL2K (65.6% vs. 64.8%), while also exceeding the top vision-only tracker ODTrack-B384 [44] by 0.9% AUC on LaSOT and a substantial 4.6% AUC on TNL2K (65.6% vs. 60.9%). On MGIT, DUTrack-384 leads JointNLT [45] by 10% AUC (71.0% vs. 61.0%) and 23.5% in precision (68.0% vs. 44.5%). On OTB99-Lang, DUTrack-384 achieves 95.7% precision, outperforming MMTrack-384 [43] (91.8%) by 3.9%. On the vision-only GOT-10K benchmark, DUTrack-384 edges out ODTrack [44] by 0.8% AO (77.8% vs. 77.0%), and on UAV123 it marginally beats SimaTrack by 0.3% AUC (70.1% vs. 69.8%). Notably, DUTrack-256 with a base encoder already outperforms UVLTrack-L (which uses a large encoder) on TNL2K across all three metrics, demonstrating the efficiency of the one-stream architecture combined with dynamic reference updates.

## Relation to Prior Work

DUTrack extends the dynamic-reference paradigm from vision-only tracking (e.g., STARK's update controller) to the language modality, which prior VL trackers have treated as a fixed input. It builds on the one-stream VL tracking architecture (HiViT-based unified encoder, Fast-ITPN initialization) and repurposes LLMs (BLIP) not as a separate grounding module but as an online description generator conditioned on the current search frame and object category. The key departure from two-stream VL trackers (UVLTrack, MMTrack, QueryNLT) is that both the visual template and the language annotation are refreshed during tracking rather than frozen at initialization, directly addressing the semantic drift problem that the authors identify as the root cause of the persistent gap between VL and vision-only trackers.

## Why It Matters / Open Questions

By demonstrating that a VL tracker can surpass the best vision-only tracker (ODTrack-B384) on LaSOT for the first time, the paper validates that the bottleneck in VL tracking is reference staleness rather than insufficient cross-modal interaction. The dynamic update mechanism is lightweight and modular, making it a practical add-on for existing VL trackers. However, the reliance on manually tuned thresholds for update frequency (scale, displacement, color) limits generalizability, and the authors acknowledge this as a key limitation. Open questions include whether the update strategy can be learned end-to-end, whether the approach extends to multi-object or referring-expression tracking, and whether the modest margins (0.9% AUC over ODTrack) persist under more challenging long-sequence or occlusion-heavy settings.
