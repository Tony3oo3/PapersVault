## Problem

Visual programs that answer questions about images are frequently 'right for the wrong reasons'—human inspection showed only 33% of programs producing correct answers were actually logically correct. Existing visual unit testing approaches check only output types (e.g., whether the answer is a color) rather than execution and logical correctness, leaving a gap in verifying that programs reason soundly about visual content.
![Teaser figure](../imgs/CVPR20252195/cropped_page1_idx0.webp)

## Input / Output

The framework takes a visual input image, a textual query, and a set of candidate program implementations as input. It produces a suite of unit tests—each an image-answer pair—by first generating image captions and expected answers via an LLM, then synthesizing corresponding images with text-to-image diffusion models (SDv1.4, SDXL, or LM-Guided Diffusion). Program execution is capped at 120 seconds, and scoring assigns fixed penalties (ε_r = ε_c = 0.1) for runtime and compilation errors before averaging pass/fail indicators across all unit tests to yield a per-program score.

## Method

ViUniT generates unit tests in three unsupervised steps: (1) an LLM (Meta-Llama-3-8B) produces M candidate image descriptions paired with expected answers, optionally conditioned on the program code; (2) a coverage sampler selects K tests by first ensuring every distinct expected answer is represented, then greedily maximizing pairwise distance between sentence-transformer embeddings of captions to diversify visual inputs; (3) a diffusion model renders the selected captions into test images. Programs are scored by executing them on all test images and averaging pass/fail outcomes. The paper demonstrates four utilization strategies: selecting the highest-scoring program from N candidates, refusing to answer when the best score falls below a threshold θ, re-prompting the LLM with unit-test discrepancy feedback to generate improved programs, and using unit-test scores as an unsupervised RL reward (replacing ground-truth correctness) to fine-tune the program generator via LoRA, which outperforms supervised correctness rewards by 1.3 points on average.

## Results

On the Best Program Selection task (Table 1), ViUniT with CodeGemma-7B achieves 50.59% average accuracy across GQA, Winoground, and SugarCREPE, outperforming the gpt-4o-mini base setup (41.92%) by 7.7 points and the single-program base setup by 11.4 points. With CodeLlama-7B, ViUniT reaches 48.67% average, still surpassing gpt-4o-mini by 6.7 points. In the unsupervised RL setting (Table 4), ViUniT-based rewards outperform supervised correctness rewards by an average of 1.3 points (47.17% vs. 45.11% for CodeGemma-7B) without relying on training labels, while also reducing code exception rates from 11.73% to 4.68%.

## Baselines & Comparisons

Against gpt-4o-mini (the strongest base-setup baseline at 41.92% average), ViUniT with CodeGemma-7B wins by 7.7 points (50.59%) and CodeLlama-7B wins by 6.7 points (48.67%), demonstrating that a 7B open-source model augmented with unit tests can surpass a proprietary model in visual program synthesis. Against the supervised correctness reward from Khan et al. [24] (Table 4), ViUniT's unsupervised unit-test reward achieves higher average accuracy on both models: CodeGemma-7B improves from 45.11% to 47.17% (+2.06 points) and CodeLlama-7B from 42.47% to 42.98% (+0.51 points), while also reducing runtime exception rates substantially (11.73% → 4.68% for CodeGemma). ViUniT also outperforms the Most Common Answer baseline (which simply selects the majority answer among 5 programs) by an average of 5.2 points, confirming that unit-test-based selection is more effective than answer voting. Notably, ViUniT reduces the fraction of programs that are 'correct for the wrong reasons' by 40% compared to the base setup, as verified by human evaluation.

## Relation to Prior Work

This paper extends the visual programming paradigm (ViperGPT, Gupta & Kembhavi) where LLMs synthesize executable programs over specialist tools, and builds directly on Khan et al.'s (CVPR 2024) self-training framework that uses correctness-based RL rewards for visual program synthesis. It departs from prior unit test generation work—which has focused on text-based code or property-checking of output types (PropTest)—by formulating unit tests as image-and-answer pairs generated via LLM captions and diffusion models, thereby verifying logical execution correctness rather than merely output format. The coverage-based sampling strategy draws on software engineering principles of test isolation and diversity, adapted to the visual domain where inputs are continuous images rather than discrete values.

## Why It Matters / Open Questions

The 'right for the wrong reasons' problem (33% of correct answers from logically incorrect programs) is a fundamental reliability gap in visual programming that limits deployment trust; ViUniT's four utilization mechanisms (selection, refusal, re-prompting, RL reward) provide a practical toolkit to address it without ground-truth annotations. The finding that unsupervised unit-test rewards outperform supervised correctness rewards, and that 7B open-source models can surpass gpt-4o-mini by 7.7 points, suggests unit testing is a scalable path to robustness. Open questions include the 25% unit test error rate (primarily 'Missing Object' from diffusion models), whether coverage sampling generalizes to more complex multi-step programs, and whether the approach extends to video or 3D reasoning tasks.
