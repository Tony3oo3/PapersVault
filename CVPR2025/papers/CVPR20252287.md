## Problem

Existing generative driving simulators encode scenes as rasterized BEV images, incurring unnecessary computation on empty pixels and requiring parameter-heavy networks, while also relying on rule-based agent behaviours that lack diversity and realism. This paper addresses both limitations by proposing a vectorized latent diffusion model that operates directly on scene elements and a data-driven, return-conditioned behaviour model for closed-loop simulation.
![Teaser figure](../imgs/CVPR20252287/cropped_page2_idx0.webp)

## Input / Output

For scene generation, the model consumes N_o + N_l Gaussian noise tokens (where N_o and N_l are the number of objects and lane centerlines, sampled from training statistics or user-specified) and iteratively denoises them over 100 DDPM steps within a 64m×64m ego-centered FOV. Outputs are fully vectorized: 8-dimensional agent bounding boxes (2D position, speed, heading cos/sin, length, width, class), 20×2 lane centerline position sequences, and a 4-way lane connectivity adjacency matrix. For inpainting, the model additionally conditions on encoded latents of an existing 32m×64m context region to generate a new 32m×64m tile, enabling unbounded scene extension. For behaviour simulation, the input is the initial scene configuration and the output is a sequence of multi-agent actions and states over time.

## Method

The core architecture is a two-stage vectorized latent diffusion model. First, a low-β VAE with factorized attention blocks (lane-to-lane, lane-to-object, object-to-object) encodes vectorized scene elements into per-element latents, explicitly modeling lane connectivity via pairwise MLP predictions rather than post-processing heuristics; lane latents are designed to be independent of object features to enable lane-conditioned object generation. Second, a DDPM noise-prediction network with the same factorized attention structure and AdaLN-Zero conditioning samples from the latent distribution, using larger hidden dimensions for lane tokens than object tokens to reflect their higher spatial complexity. A recursive spatial ordering scheme (by x, then y, then max-x, then max-y) with sinusoidal positional encodings resolves the permutation ambiguity inherent to set-structured data. For closed-loop behaviour simulation, the paper extends CtRL-Sim with a return-conditioned autoregressive Transformer that supports exponential tilting at inference to generate adversarial agent behaviours, and a reward function penalizing collisions with the ego vehicle over a 2-second horizon.

## Results

On nuPlan, Scenario Dreamer (B) with 377M parameters achieves FD 1.05, Connectivity 0.28, Density 0.45, Reach 0.07, and Convenience 0.14 for lane graph generation, outperforming SLEDGE (DiT-XL) (769M params) on every metric while using ~2× fewer parameters, 7× lower inference latency (0.09s vs 0.67s), and 10× fewer GPU training hours (96 vs 960). On Waymo, Scenario Dreamer (L) achieves FD 1.38 and Connectivity 0.03, substantially outperforming the privileged DriveSceneGen baseline (FD 40.59, Connectivity 4.53). For agent generation on nuPlan, Scenario Dreamer (L) reduces collision rate to 9.3% versus 21.2% for SLEDGE (DiT-XL), with JSD metrics an order of magnitude lower (e.g., Angular Deviation 0.18 vs 3.26).

## Baselines & Comparisons

Against SLEDGE (DiT-L and DiT-XL) on nuPlan, Scenario Dreamer (B) wins on all lane graph and agent generation metrics despite using roughly half the parameters; the base model's 0.09s generation time is 7× faster than SLEDGE (DiT-XL)'s 0.67s, and it requires only 96 GPU-hours versus 960 for training. On Waymo, Scenario Dreamer (L) dramatically outperforms the privileged DriveSceneGen baseline on Urban Planning metrics (e.g., Connectivity 0.03 vs 4.53, Convenience 2.05 vs 5.58) and perceptual quality (FD 1.38 vs 40.59), though DriveSceneGen reports a lower collision rate (0.2% vs 4.8%)—a gap the authors attribute to DriveSceneGen's privileged access to ground-truth rasterized inputs. For behaviour simulation, CtRL-Sim is compared against rule-based IDM and data-driven Trajeglish (results in the appendix); the paper's RL planner experiments (Table 4) show that replacing log-replay agents with CtRL-Sim (positive tilt) causes only marginal performance change (collision rate 29.3% → 35.7%), confirming CtRL-Sim's realism, while negative tilting (adversarial) further degrades the planner (collision rate 59.0%, success rate 32.1%), demonstrating the simulator's ability to generate challenging scenarios.

## Relation to Prior Work

This paper departs from the rasterized-image encoding paradigm used by SLEDGE (Chitta et al., ECCV 2024) and DriveSceneGen (Sun et al., IEEE RA-L 2024) for driving scene generation, instead proposing a vectorized latent diffusion model that operates directly on scene elements (bounding boxes, lane centerlines, connectivity). The factorized attention architecture draws on prior set-transformer and factorized-attention designs from multi-agent motion prediction (Girgis et al., ICLR 2022; Ngiam et al., ICLR 2022), while the inpainting formulation for scene extrapolation follows SLEDGE's conditional sampling setup adapted to variable-length vector tokens. For closed-loop behaviour simulation, the paper extends CtRL-Sim (Rowe et al., CoRL 2024), a return-conditioned autoregressive Transformer, to support multiple agent types and longer rollouts, replacing the rule-based IDM models used in SLEDGE.

## Why It Matters / Open Questions

The demonstration that a 377M-parameter vectorized model outperforms a 769M-parameter rasterized model on all quality metrics while requiring 10x fewer GPU training hours and 6x lower inference latency provides a strong practical argument for vectorized scene representations in generative driving simulation. The ability to generate unbounded, interactive, and adversarial environments via inpainting and exponential tilting addresses a key scalability bottleneck for AV validation, where billions of miles of diverse driving experience are needed. Limitations include the generation of centerline-only maps (no road edges or crosswalks) and imperfect traffic light logic, and it remains open whether the vectorized approach generalizes to richer scene elements or sensor-level generation.
