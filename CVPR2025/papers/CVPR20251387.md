## Problem

Automated generation of structured, editable presentation slides from natural language instructions remains unsolved: existing image generation methods produce non-editable bitmaps with garbled text, and no benchmark or systematic evaluation framework existed for measuring slide generation quality. The paper asks whether AI agents can produce high-quality, well-structured slides that are both insight-revealing and user-interactable.
![Teaser figure](../imgs/CVPR20251387/cropped_page0_idx0.webp)

## Input / Output

The system accepts natural language instructions at three difficulty levels—detailed instructions with provided image paths, detailed instructions with image descriptions only, and high-level topical prompts (e.g., 'create a title slide for Airbnb')—and produces an executable Python program that, when run, yields an editable PPTX file. The programmatic output format is central: unlike pixel-level image generation, the resulting slide retains discrete text boxes, shapes, and image elements that users can individually modify.

## Method

AUTOPRESENT generates slides via NL-to-code: a language model produces a Python program (using python-pptx or the custom SLIDESLIB toolkit) that is executed to render the PPTX. SLIDESLIB reduces average program length from 170 to 13 lines by exposing high-level functions (add_title, add_text, search_image, generate_image), making generation tractable for smaller models. The 8B model is fine-tuned from LLAMA-3.1-8B-Instruct using LoRA (rank 128) on 7k instruction-program pairs derived from 310 slide decks, with canonical programs auto-extracted from reference slides. An iterative refinement loop feeds the rendered slide image back to the model alongside the original instruction and first-pass code, enabling self-correction of layout, color, and content issues. The approach is benchmarked against end-to-end diffusion models (Stable Diffusion, DALL-E 3) and other LLMs/VLMs on the newly introduced SLIDESBENCH, using both reference-based (element matching, content/color/position similarity) and reference-free (text, image, layout, color design quality) metrics.

## Results

On SLIDESBENCH (detailed instructions with images), AUTOPRESENT (8B) with SLIDESLIB achieves an Overall score of 55.0 with 84.1% execution success, approaching GPT-4o's 58.0 (86.7% execution). Without SLIDESLIB, AUTOPRESENT drops to 45.2 Overall, while GPT-4o scores 55.1. End-to-end image generation methods (DALL-E 3: 50.2, Stable Diffusion: 48.0) underperform the best code-generation approaches on reference-based metrics (e.g., content similarity 39.9 vs. 92.2 for AUTOPRESENT w/ SLIDESLIB) and produce non-editable outputs. On high-level instructions, GPT-4o with SLIDESLIB reaches 58.5 Overall while AUTOPRESENT achieves 47.8, and iterative refinement further boosts GPT-4o's Overall score from 58.5 to 61.4 after three rounds.

## Baselines & Comparisons

AUTOPRESENT (8B) with SLIDESLIB narrows the gap to GPT-4o substantially: on detailed instructions with images, AUTOPRESENT scores 55.0 Overall vs. GPT-4o's 58.0 (a 3-point gap), and on detailed instructions only, 55.2 vs. 56.3. However, on high-level instructions, GPT-4o leads more clearly at 58.5 vs. AUTOPRESENT's 47.8, suggesting the 8B model struggles more when content must be inferred from minimal guidance. Compared to other open-source LLMs, AUTOPRESENT dominates: LLaMA 8B with SLIDESLIB reaches only 33.5 Overall (vs. 55.0) and CodeLLaMA 7B reaches 30.3, while LLaVA 7B barely executes (20% success, 9.7 Overall). Against end-to-end image generation, code generation methods win decisively on content fidelity (AUTOPRESENT content similarity 92.2 vs. DALL-E 3's 39.9) and produce editable PPTX output, though DALL-E 3 scores higher on reference-free image quality (87.3 vs. 47.8). SLIDESLIB provides the largest single boost for smaller models: LLaMA 8B jumps from 1.3 to 33.5 Overall, and GPT-4o gains 2.9 points (55.1→58.0), confirming that modular tool interfaces are critical for structured visual generation.

## Relation to Prior Work

This paper sits at the intersection of visual programming (generating executable code for structured visuals, as in Design2Code, ViPER-GPT, and TroVE) and automatic slide generation (Doc2PPT, PPSGen, PPTC). Prior slide-generation work focused on extracting content from documents or editing existing slides, while visual-programming work targeted simpler figure types (SVG, TikZ, UI mockups). AUTOPRESENT departs from both by formulating slide creation from scratch as an NL-to-code task, leveraging the visual-programming paradigm with a purpose-built tool library (SLIDESLIB) inspired by TroVE's toolbox induction, and fine-tuning an 8B LLM on domain-specific (instruction, program) pairs.

## Why It Matters / Open Questions

SLIDESBENCH is the first benchmark specifically for from-scratch slide generation, providing both reference-based and reference-free evaluation metrics grounded in design principles, which should enable systematic progress in this underexplored area. The finding that an 8B fine-tuned model approaches GPT-4o on this task, and that a concise tool library dramatically improves even small models, suggests that domain-specific fine-tuning plus structured tooling can close the gap to frontier models for structured visual tasks. Key limitations include single-slide scope (no full decks, no animations), reliance on GPT-4o for annotation and evaluation, and the persistent gap to human-designed slides, leaving open questions about iterative multi-slide workflows, user interaction, and incorporating higher-level design principles like attention capture.
