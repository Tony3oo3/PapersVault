## Problem

Vision-language models excel at category-level semantic understanding but degrade sharply on 3D spatial reasoning tasks that require multi-step grounding, depth inference, and geometric computation. Prior visual program synthesis methods (ViperGPT, VisProg) rely on static, human-defined APIs that restrict them to a narrow, predefined range of spatial operations, causing them to produce incomplete programs or fall back on holistic VQA for complex queries. Additionally, existing spatial reasoning benchmarks largely omit 3D understanding, testing only 2D relations or appearance-based attributes.

## Input / Output

VADAR takes an RGB image and a free-form text query about 3D spatial properties (e.g., object sizes, relative depth, counts conditioned on measurement hypotheses) as input. It produces two outputs: a final answer (numeric, yes/no, or multiple-choice) and an interpretable, executable Python program that encodes the reasoning chain. Notably, the image is consumed only during program execution by vision specialists, not during program synthesis, meaning the Program Agent reasons purely from the query text and the generated API signatures.

## Method

VADAR is a training-free, two-phase agentic system. In the API Generation phase, a Signature Agent receives batches of 15 queries (without answers) and proposes general Python method signatures for anticipated subproblems; an Implementation Agent then writes the code, resolving dependencies depth-first, while a Test Agent (a Python interpreter) validates each method and triggers re-implementation on exceptions. In the Program Synthesis phase, a Program Agent generates a concise Python program that calls the dynamically built API, and an Execution Agent runs it line-by-line, invoking vision specialists (Molmo/GroundingDINO for localization, SAM for bounding boxes, UniDepth for metric depth, GPT-4o for attribute VQA) and feeding back Python exceptions for up to 5 regeneration attempts. The key distinction from prior work is that the API is not predefined: it is autonomously constructed per task, enabling VADAR to handle queries requiring novel spatial operations (e.g., 'find closest object 3D', 'is behind', 'count objects by attributes and position') that would be absent from a static DSL.

## Results

On CLEVR, VADAR achieves 53.6% total accuracy, slightly outperforming VLMs on numeric answers (53.3% vs. GPT4o's 52.3%) and yes/no answers (65.3% vs. GPT4o's 63.0%), while GPT4o and Claude3.5-Sonnet lead overall at 58.4% and 58.9% respectively. On the newly introduced OMNI3D-BENCH, VADAR reaches 40.4% total accuracy, trailing GPT4o (42.9%) by only 2% but surpassing all other VLMs by more than 5%. VADAR outperforms both prior program synthesis methods—ViperGPT (26.2% CLEVR, 26.7% OMNI3D-BENCH) and VisProg (31.2% CLEVR, 13.5% OMNI3D-BENCH)—by over 20% on both benchmarks. With oracle vision specialists, VADAR's program synthesis accuracy jumps to 83.0% on CLEVR and 94.4% on OMNI3D-BENCH, indicating the vision modules are the primary bottleneck.

## Baselines & Comparisons

Against monolithic VLMs, VADAR is competitive but not dominant: on CLEVR it trails GPT4o (58.4%) and Claude3.5-Sonnet (58.9%) by ~5% overall, yet edges them out on numeric (+1.0%) and yes/no (+2.3%) subcategories. On OMNI3D-BENCH, VADAR (40.4%) is within 2% of GPT4o (42.9%) and beats Claude3.5-Sonnet (32.2%), Gemini1.5-Flash (35.0%), and SpaceMantis (30.3%) by 5–10%. Against prior program synthesis methods, VADAR wins decisively: it outperforms ViperGPT by 27.4% on CLEVR (53.6% vs. 26.2%) and 13.7% on OMNI3D-BENCH (40.4% vs. 26.7%), and VisProg by 22.4% on CLEVR and 26.9% on OMNI3D-BENCH. The oracle experiment (Table 2) reveals the gap is primarily in vision specialists, not program logic: with oracle modules, VADAR reaches 83.0% on CLEVR and 94.4% on OMNI3D-BENCH, versus ViperGPT's 42.6%/54.9% and VisProg's 39.9%/66.0%. On GQA (appearance-focused, single-step queries), VADAR (46.1%) is comparable to VisProg (46.9%) but trails GPT4o (54.9%), confirming that monolithic VLMs retain an advantage on simpler, non-3D spatial tasks.

## Relation to Prior Work

VADAR extends the visual program synthesis lineage (ViperGPT, VisProg) by replacing their static, human-defined DSL with a dynamically generated Python API produced by collaborative LLM agents (Signature, Implementation, and Test Agents). This connects to the broader library learning paradigm (DreamCoder, Voyager) where reusable functions are synthesized during problem-solving, but applies it to visual reasoning with vision specialists. The key conceptual departure from neuro-symbolic approaches like LEFT is that VADAR is entirely training-free, requiring only 15 unlabeled queries to bootstrap the API, whereas LEFT needs ≥10,000 supervised examples to train its grounding modules.

## Why It Matters / Open Questions

The oracle experiment reveals that VADAR's program synthesis is largely correct (83% CLEVR, 94.4% OMNI3D-BENCH) and that the true bottleneck is vision specialist accuracy, not reasoning. This suggests an alternative scaling path for 3D spatial reasoning: improving specialized, simpler vision models (detectors, depth estimators) rather than training ever-larger monolithic VLMs on expensive 3D-annotated data. Open questions include whether the dynamic API can handle 5+ inference steps, whether vision specialist selection can be automated, and whether incorporating the image into program synthesis (rather than only at execution time) would close the remaining gap.
