## Problem

Standard approximate nearest neighbor search (ANNS) returns results that are close to the query but often nearly identical to each other, which is undesirable in applications like RAG and image retrieval. Existing diverse nearest neighbor search (DNNS) methods are slow because they require pairwise distance computations over original vectors (O(DS²)), solve NP-hard subset selection, and cannot be plugged in as a post-processing step on top of modern ANNS indices.

## Input / Output

At query time, the method takes a D-dimensional query vector, a precomputed ANNS index (e.g., HNSW), and a precomputed cutoff table — an array of N integer lists where each list L_n contains the IDs of all vectors within squared distance ε of x_n. It outputs a set of K vector identifiers that are close to the query yet guaranteed to be at least √ε apart from one another. Notably, the filtering step operates purely on integer IDs without ever loading the original D-dimensional vectors, making it a true post-processing module compatible with any ANNS backend including compressed representations.

## Method

LotusFilter precomputes a cutoff table by performing a range search for every database vector to collect all neighbors within a learned squared-distance threshold ε, then at query time greedily pops the closest candidate from the ANNS result and removes all vectors listed in that candidate's cutoff entry from the remaining pool, repeating until K results are collected. The key efficiency gain comes from replacing on-the-fly O(DS²) pairwise distance computations with O(1) table lookups, reducing filtering complexity to O(S + KL) where L is the average cutoff table length (typically < 100). An OrderedSet data structure (combining an array with a hash table) enables O(L) pop and O(1) removal operations needed for the greedy loop. The threshold ε is learned in a training phase via bracketing optimization over a small set of training queries to minimize the combined proximity-diversity objective, eliminating manual tuning. A safeguard mode prevents over-pruning by falling back to returning remaining candidates if the pool is exhausted before K results are collected.

## Results

On the OpenAI dataset (900K vectors, 1536-dim, K=100, S=500), LotusFilter achieves the best final cost f=0.171, outperforming GMM (f=0.177) and k-means Clustering (f=0.223), while running at only 1.03 ms/query total (0.02 ms for the filtering step alone). This is roughly 14× faster than GMM (14.4 ms/query) and 7.6× faster than Clustering (7.88 ms/query). Memory overhead is 1.14×10⁹ bits for the cutoff table, approximately 40× less than the 4.42×10¹⁰ bits required by GMM and Clustering to store original vectors.

## Baselines & Comparisons

Against GMM (the MAX-MIN diversification baseline [39]), LotusFilter wins on the final cost (f=0.171 vs. 0.177) and on runtime by a wide margin (1.03 vs. 14.4 ms/query, ~14× faster), while GMM achieves a slightly more diverse result (−0.351 vs. −0.266 diversification term). Against k-means Clustering, LotusFilter dominates on every axis: better final score (0.171 vs. 0.223), faster total runtime (1.03 vs. 7.88 ms/query), and 40× less memory (1.14×10⁹ vs. 4.42×10¹⁰ bits). Compared to search-only (no filtering), LotusFilter adds only 0.175 ms of overhead while improving the diversification term from −0.107 to −0.266 and the final score from 0.200 to 0.171. The key structural advantage is that LotusFilter operates as a pure post-processing module requiring no access to original vectors, whereas both GMM and Clustering must load and compute pairwise distances over the D-dimensional vectors, incurring O(DKS) cost.

## Relation to Prior Work

LotusFilter carves new ground at the intersection of diverse nearest neighbor search (DNNS) and learned data structures. While DNNS has been studied since the 2000s (MMR, GMM, dedicated data structures), existing methods either cannot integrate modern ANNS backbones like HNSW or require O(DS²) pairwise distance computations on original vectors. The paper repurposes the learned-data-structure paradigm (previously applied to B-trees, KD-trees, Bloom Filters) by precomputing a cutoff table whose threshold ε is learned via bracketing optimization, reducing the filtering step to O(S) sequential lookups. This positions LotusFilter as the first DNNS approach that is a pure post-processing module compatible with any black-box ANNS index, a design gap the authors explicitly identify in prior work.

## Why It Matters / Open Questions

For RAG practitioners, the 0.02 ms/query filtering overhead and predictable 64LN-bit memory footprint make diverse retrieval nearly free on top of existing HNSW/faiss pipelines, addressing a real pain point where redundant passages degrade generation quality. However, several open questions remain: the global threshold ε may be suboptimal for heterogeneous or highly clustered datasets, the method lacks end-to-end RAG evaluation (accuracy is measured only by the proxy cost function), and the optimal ε depends on K, limiting flexibility. The authors themselves flag LLM-as-a-judge evaluation of diversity and GPU-accelerated preprocessing as key future directions.
