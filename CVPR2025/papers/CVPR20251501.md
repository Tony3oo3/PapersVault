## Problem

Existing open-set robotic failure detection methods rely on frequent VLM queries that suffer from compromised execution speed and coarse 3D spatio-temporal perception, and they typically address only reactive detection (after failure occurs) while leaving proactive detection (preventing foreseeable failures) largely unexplored. No prior framework unifies both detection modes within a single system that operates in real-time with high precision.
![Teaser figure](../imgs/CVPR20251501/cropped_page0_idx1.webp)

## Input / Output

The system consumes multi-view RGB-D observations (front and top cameras), a global task instruction, the previous subgoal, and a failure feedback string. The VLM is invoked only once per subgoal to generate executable monitor code from visually prompted images (RGB frames annotated with numbered constraint elements) and textual constraints; thereafter, the code runs autonomously on tracked 3D element positions via CoTracker, returning a boolean failure flag and a descriptive reason string without further VLM calls. Constraint elements are compact geometric abstractions (3D points, connected point sets forming lines, or point clouds forming surfaces) rather than raw entity masks.

## Method

CaM formulates both reactive and proactive failure detection as spatio-temporal constraint satisfaction problems, where a Constraint Generator (GPT-4o) decomposes the task into subgoals with associated during-execution (C_d) and upon-completion (C_u) constraints. A Constraint Painter (ConSeg, built on LISA with LLaVA + SAM encoder/decoder, fine-tuned end-to-end with LoRA on a multi-granularity dataset from BridgeData V2) performs constraint-aware instance and part-level segmentation, then projects masks into 3D and applies voxelization heuristics to extract compact constraint elements. A Constraint Monitor feeds the annotated multi-view images and textual constraints to GPT-4o for constraint-aware visual programming, generating NumPy-based monitor code that computes arithmetic operations (distances, angles, surface normals) on tracked 3D element positions to evaluate constraints in real-time. The key insight is that abstracting entities into geometric elements eliminates irrelevant visual detail, simplifies tracking, and enables precise code-based evaluation that avoids the 3D reasoning limitations of direct VLM image queries.

## Results

Under severe disturbances across three simulators and a real-world setting, CaM achieves a 28.7% higher success rate and reduces execution time by 31.8% compared to baselines. In CLIPort's 'Stack in Order' with the most severe noise (q=3), CaM reaches 63.33% success vs. 40.00% for DoReMi and 40.00% for Inner Monologue, while cutting execution time from 54.2s to 36.8s. In Omnigibson, CaM reduces execution time by 34.8% and token usage by 52.2% versus DoReMi, and is the only method that detects surface-level disturbances in 'Pour Tea' (50% SR vs. 0% for DoReMi). In real-world pick-and-place with a dexterous hand, CaM achieves 93.33–96.67% success across object types, surpassing DoReMi by 20.4% on average.

## Baselines & Comparisons

CaM consistently outperforms DoReMi [15] (the primary VQA-based failure detection baseline) across all settings: in CLIPort it gains 17.5–58.3 percentage points in success rate under disturbances, in Omnigibson it achieves 34.8% lower execution time and 52.2% fewer tokens, and in real-world tasks it surpasses DoReMi by 20.4% on average. Against Inner Monologue [20] (which only checks at subgoal completion), CaM reduces execution time by 38.7% in CLIPort's 'Stack in Order' while matching or exceeding its success rate. In Omnigibson, CaM also outperforms the ReKep [21] policy alone by 20–30 percentage points under disturbances, and is the only method that detects surface-level (tilt) failures in 'Pour Tea' where DoReMi drops to 0%. In real-world experiments, CaM with the open-loop DexGraspNet 2.0 [69] policy achieves 90–96.67% success versus 0% for DGN alone and 0–10% for DGN+DoReMi on long-horizon reasoning tasks. For segmentation, ConSeg surpasses both LISA-13B [28] and PixelLM [50] on the proposed ConstraintSeg benchmark by ~20–40 gIoU at the part level, while remaining competitive on the standard ReasonSeg benchmark.

## Relation to Prior Work

This paper departs from the dominant VQA-based failure detection paradigm (DoReMi, Inner Monologue) by replacing repeated VLM queries with a single VLM-generated code snippet that is then executed in real-time against tracked geometric elements. It builds on visual prompting literature (ReKep, CoPa, SoM) but introduces 'constraint elements'—compact 3D point/line/surface abstractions derived from a new constraint-aware segmentation model (ConSeg, built on LISA+SAM)—as the visual interface for code-based monitoring. The visual programming lineage (Code as Policies, RoboCodex) is extended from control policy generation to constraint evaluation, and the spatio-temporal constraint satisfaction formulation unifies reactive and proactive detection, which prior work treats as separate problems.

## Why It Matters / Open Questions

The unification of reactive and proactive failure detection under a single constraint-satisfaction framework, combined with the code-execution paradigm that avoids per-frame VLM calls, offers a practical path to closed-loop robotic systems that can handle open-set failures in real time. The real-world demonstration of forming a closed-loop system from an open-loop policy (90% success on long-horizon reasoning tasks vs. 0% for DoReMi) is practically significant for deployment. Open questions include whether the geometric constraint formulation can express truly novel failure modes (e.g., material deformation, multi-object interaction), how the approach scales to multi-robot or high-DoF scenarios, and whether the reliance on GPT-4o for code generation introduces fragility in edge cases.
