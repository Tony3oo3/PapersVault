## Problem

ProtoPNets are the dominant interpretable image classifier, but users who identify flawed prototypes (e.g., encoding bias or irrelevant features) cannot fix them without slow, iterative retraining by ML practitioners — a process called the 'interaction bottleneck.' This paper eliminates that bottleneck by pre-computing a large set of equally accurate ProtoPNets (a Rashomon set) so domain experts can select or edit models in real time without any retraining.
![Teaser figure](../imgs/CVPR20250671/cropped_page0_idx0.webp)

## Input / Output

The method takes a fully trained ProtoPNet (backbone + prototype layer fixed at reference values) and a sequence of user constraints (remove prototype j, require prototype j with weight ≥ α). It outputs a family of valid final-layer weight vectors forming an ellipsoid in ℝ^m, from which individual ProtoPNets can be sampled on demand. Each sampled model produces standard class-label predictions via the fixed backbone and prototype layer composed with the selected final-layer weights. The positive-reasoning restriction means each prototype connects only to its assigned class, reducing the parameter space from mt to m dimensions.

## Method

Proto-RSet fixes the backbone f and prototype layer g, reducing the Rashomon set to the set of final-layer weights w_h whose multiclass logistic regression loss stays within a threshold θ of the optimum. A second-order Taylor expansion around the optimal w_h* approximates the loss as a quadratic, yielding an ellipsoid in weight space whose shape is determined by the Hessian. By restricting to positive reasoning (zero cross-class connections), the Hessian shrinks from O(m²t²) to O(m²) entries, making the ellipsoid tractable (e.g., 128 MB vs. 5.12 TB for a 200-class, 10-prototypes-per-class model). User interactions map to geometric operations: sampling walks a random direction to a fraction of the ellipsoid boundary; removing a prototype intersects the ellipsoid with a hyperplane (still an ellipsoid); requiring a minimum weight intersects with a half-space (solved via convex QP). If constraints become infeasible, the system can sample new candidate prototypes from training-image latent patches to expand the set while preserving all prior user feedback.

## Results

In the user study on CUB-200 with synthetic confounders, Proto-RSet removes an average of 80.8 confounded prototypes in 2.1±1.3 minutes of computation while maintaining validation accuracy (−0.5±0.7%), compared to 93.7±52.4 minutes for ProtoPDebug. Across 18 dataset-backbone combinations (CUB-200, Stanford Cars, Stanford Dogs × VGG-16/19, ResNet-34/50, DenseNet-121/161), a Proto-RSet is computed in under 20 minutes, and prototype removal takes only seconds per constraint. In the HAM10000 skin cancer case study, Proto-RSet reduced the model from 21 to 12 prototypes while increasing test accuracy from 70.4% to 71.0%, and correctly flagged a prototype whose removal would have dropped accuracy to 57.9%.

## Baselines & Comparisons

Proto-RSet is compared against four baselines: ProtoPDebug [5], naive prototype removal (zeroing weights), naive removal with last-layer retraining (ℓ₁ penalty), and hard removal (strict zeroing + reoptimization). Against ProtoPDebug, Proto-RSet is roughly 45× faster (2.1 min vs. 93.7 min) while achieving comparable accuracy change (−0.5% vs. +0.8%), and it guarantees that all user-specified prototypes are fully removed (ℓ₁ norm ≈ 0), whereas ProtoPDebug uses soft constraints that do not guarantee satisfaction. Against naive removal with retraining, Proto-RSet is ~4× faster (2.1 vs. 8.4 min) with similar accuracy, but critically guarantees constraint satisfaction where retraining does not. Naive removal without retraining is instantaneous but degrades accuracy by 6.4%, making it impractical. Proto-RSet also provides a unique capability absent from all baselines: it can detect and report when a requested removal is infeasible within the Rashomon set, as demonstrated in the skin cancer case study where ignoring its warning dropped accuracy from 70.4% to 57.9%.

## Relation to Prior Work

This paper extends the Rashomon set framework—previously developed for tabular data (decision trees, GAMLs, rule sets, risk scores)—to computer vision by computing it over the final classification layer of ProtoPNets with a fixed backbone and prototype set. It departs from prior model-editing approaches like ProtoPDebug and R3, which require retraining with modified loss terms to incorporate user feedback, by instead pre-computing a set of equally-performant models from which users can select in real time. The ellipsoidal approximation of the Rashomon set is inspired by the second-order Taylor expansion technique from Zhong et al. (NeurIPS 2024) for sparse GAMLs, and the geometric operations (hyperplane-ellipsoid intersection) draw on the Ellipsoidal Toolbox of Kurzhanskiy and Varaiya.

## Why It Matters / Open Questions

Proto-RSet solves the 'interaction bottleneck' for ProtoPNets by enabling non-ML experts (clinicians, domain specialists) to remove or require prototypes in seconds rather than hours of retraining, with guaranteed constraint satisfaction and accuracy preservation. Key limitations include the restriction to positive reasoning (which reduces the Hessian from O(m²t²) to O(m²) memory), the fact that Proto-RSet only covers the last layer rather than the full model, and the difficulty of composing multiple half-space constraints that break the ellipsoidal structure. Open questions include whether this approach extends to other interpretable architectures beyond ProtoPNets, whether the positive-reasoning assumption is always appropriate in practice, and how the method scales when the prototype set itself must be modified rather than just the classification weights.
