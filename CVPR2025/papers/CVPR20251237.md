## Problem

Existing 3D vision-language benchmarks suffer from three critical flaws: ambiguous or unnatural test data that undermines evaluation reliability, oversimplified per-case metrics that mask visual ignorance and language fragility, and the isolation of grounding and QA tasks that hides broken performance coherence between them. These issues create a 'mist' that obscures true model capabilities and misguides 3D-VL development.
![Teaser figure](../imgs/CVPR20251237/cropped_page0_idx0.webp)

## Input / Output

For grounding, the model receives a scene point cloud and a referential text and must predict the target object's 3D bounding box; for QA, it receives the same point cloud plus a question and produces a free-form answer scored via GPT-Score (1–5). Each of the 837 objects carries three test cases organized into G-Chains (coarse-to-fine grounding texts) and GQA-Chains (QA pairs whose answers are explicitly contained in the corresponding grounding text), and the object-centric metric requires all three predictions to be correct for an object to count as solved.

## Method

BEACON3D introduces an object-centric evaluation paradigm with a chain-of-analysis structure. G-Chains span grounding texts from coarse (e.g., 'chair') to fine-grained (e.g., 'gray chair next to the corner table'), with simplified texts relaxing the candidate object set at each level; GQA-Chains align QA questions with the primary grounding text so that queried content is directly present in the description, enabling coherence analysis. The benchmark comprises 30 curated scenes from ScanNet, 3RScan, and MultiScan, with 2511 G-Chains and 2511 GQA-Chains manually annotated and cross-validated. Two coherence metrics are defined: R₁ (correct grounding but wrong QA, indicating weak QA skills) and R₂ (wrong grounding but correct QA, indicating shortcuts). All data is tagged with knowledge types (class, appearance, geometry, spatial, existence) to enable fine-grained capability profiling.

## Results

On BEACON3D grounding, the strongest non-LLM model PQ3D achieves 76.1% per-case accuracy but drops to 57.2% under object-centric evaluation (requiring all 3 tests per object correct), while LLM-based models like LEO-multi collapse from 14.3% to 2.8%. On BEACON3D QA, object-centric accuracy is near-zero for all 3D-VL models (PQ3D: 3.5%, SceneVerse: 6.6%, LEO-curricular: 7.8%), revealing severe overfitting and shortcut learning. Notably, GPT-4o with text-only input (object lists) achieves 57.1% per-case / 20.2% object-centric QA, far exceeding all 3D-VL models, while integrating LLMs into 3D-VL architectures (e.g., PQ3D-LLM vs. PQ3D) actually degrades grounding by ~6% per-case and ~10% object-centric.

## Baselines & Comparisons

PQ3D [96] is the strongest non-LLM grounding model on BEACON3D (76.1% case / 57.2% object-centric), outperforming SceneVerse [32] (73.5% / 52.1%) and 3D-VisTA [95] (71.0% / 50.9%) by 2.6–5.1% per-case. Replacing PQ3D's T5-Small with Vicuna-7B (PQ3D-LLM) degrades grounding to 70.2% / 47.4%, confirming that LLM integration hinders rather than helps 3D grounding. Among LLM-based models, Chat-Scene [24] (62.7% / 44.3%) and LEO-curricular [26] (22.0% / 3.8%) both trail non-LLM counterparts substantially, with LEO variants being particularly weak. On QA (Table 5), GPT-4o with text-only object lists [57] dominates at 57.1% case / 20.2% object-centric, while among 3D-VL models SceneVerse leads (40.3% / 6.6%) and PQ3D-LLM is worst (27.9% / 2.3%). The key takeaway is that no 3D-VL model achieves meaningful object-centric QA accuracy (<8%), and LLM-based models do not close the gap versus simpler non-LLM architectures.

## Relation to Prior Work

This paper departs from the standard evaluation paradigm in 3D vision-language benchmarks (ScanRefer, Nr3D, ScanQA, SQA3D), which rely on per-case accuracy averaging and treat grounding and QA as isolated tasks. It introduces two conceptual shifts: (1) object-centric evaluation requiring all three tests per object to pass, and (2) a chain-of-analysis framework (G-Chains and GQA-Chains) that links grounding descriptions to QA questions to assess cross-task coherence. The data collection builds on ScanNet, 3RScan, and MultiScan scenes, and the QA scoring leverages GPT-Score from OpenEQA, but the evaluation methodology and the coherence analysis represent a new direction not present in prior 3D-VL benchmarking work.

## Why It Matters / Open Questions

BEACON3D reveals that state-of-the-art 3D-VL models perform dramatically worse under object-centric metrics than previously reported, with QA accuracy dropping near zero for most models, exposing a gap between benchmark-reported progress and true object-level understanding. The finding that LLM integration hinders grounding and fails to fundamentally improve QA challenges a prevalent design choice in the field and suggests the bottleneck lies in 3D perception rather than language modeling. Open questions include whether the 30-scene scale is sufficient for general conclusions, how to design QA that resists shortcuts, and whether scaling 3D-VL data (as SceneVerse suggests) can close the grounding-QA coherence gap without LLMs.
