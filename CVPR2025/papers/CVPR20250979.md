## Problem

Angular Margin Softmax (AMS) in face recognition incurs O(m) computational cost proportional to the number of identities, becoming prohibitive as datasets scale to millions of identities. Existing efficient training methods (PFC, DCQ, F2C) only reduce the constant factor to O(αm) while maintaining linear scaling, and unbalanced sample distributions cause 'minority collapse' where minor-class centroids merge in the embedding space.
![Teaser figure](../imgs/CVPR20250979/cropped_page0_idx1.webp)

## Input / Output

The method takes aligned 112×112 RGB face images as input and produces a 512-dimensional L2-normalized embedding vector for recognition. During training, the model additionally predicts a structured identity code — a sequence of l integer tokens each in [0, v−1] — where v is chosen so that 5 ≤ v ≤ 25, making the total representable identities v^l ≥ m. The code is fixed before training and is not learned end-to-end; only the backbone and per-token projection heads are optimized.

## Method

GIF replaces atomic scalar labels with structured identity codes via a two-stage tokenization: (1) each identity is assigned a code vector on the unit hypersphere, initialized from per-class mean CLIP embeddings and then optimized for uniform distribution using a Gaussian potential kernel loss (independent of sample counts, avoiding minority collapse); (2) hierarchical k-means clustering over the optimized code vectors yields a tree whose root-to-leaf path defines each identity's code. Training substitutes the single m-way softmax with l parallel v-way softmaxes (v ∝ log m), reducing classifier computation from O(m) to O(log m). An auxiliary angular regression loss (L_AR) pulls each sample's embedding toward its fixed code vector, providing explicit intra-class compactness supervision without the 'push' force that causes minority collapse in standard cross-entropy.

## Results

On the largest training set (WebFace42M, 2M identities) with ResNet-100, GIF achieves 99.85% on LFW, 99.80% on CFP-FP, 99.40% on AgeDB, 97.99% TAR@FAR=1e-4 on IJB-B, and 98.42% on IJB-C. Against the previous SOTA efficient-training method PFC on the same setup, GIF improves IJB-B by 1.52% and IJB-C by 0.6%. On MS1MV2 (85K identities), GIF reaches 95.05% on IJB-B and 96.77% on IJB-C, outperforming DCQ and F2C by 0.34–0.35% on CFP-FP/AgeDB. The computational complexity drops from O(m) for all baselines to O(log m) for GIF.

## Baselines & Comparisons

GIF outperforms all four Efficient Training baselines (Virtual FC, DCQ, F²C, PFC) across every reported metric and training set size. Against PFC (the strongest ET baseline), GIF gains 1.52% on IJB-B and 0.6% on IJB-C with WebFace42M+R100, and 1.26% on IJB-B with WebFace4M. Against CDT baselines on MS1MV2 (Table 2), GIF surpasses ArcFace by 0.80% on IJB-B (95.05 vs 94.25) and 0.74% on IJB-C (96.77 vs 96.03), and beats BroadFace/GroupFace by 0.08–0.10% on IJB-B. On WebFace4M with ViT, GIF (97.99 IJB-C) exceeds AdaFace (97.14) by 0.78% at TAR@FAR=1e-4. Notably, GIF achieves these gains while reducing classifier complexity from O(m) to O(log m), and the advantage is most pronounced on unbalanced datasets (WebFace series) where prior methods suffer from minority collapse.

## Relation to Prior Work

GIF builds directly on the Angular Margin Softmax (ArcFace) training framework but departs from the entire line of Efficient Training methods (PFC, DCQ, Virtual FC, F2C) that approximate the m-way softmax with a random subset of classes, which still scale as O(αm). Instead, it draws on the generative retrieval paradigm from large-scale entity recognition (autoregressive entity retrieval, generative Wikipedia-scale visual entity recognition), where instances are encoded as sequences of integer tokens rather than atomic class labels. The tokenization scheme itself combines CLIP visual embeddings for semantic initialization with a Gaussian potential kernel objective for hyperspherical uniformity, then applies hierarchical k-means to produce structured identity codes — a pipeline that is independent of per-class sample counts.

## Why It Matters / Open Questions

The shift from O(m) to O(log m) classifier cost is practically transformative: conventional FC layers hit out-of-memory at 8M identities and PFC at 16M, while GIF handles 64M with negligible additional memory, opening the door to training on the full WebFace260M-scale benchmarks on a single 8-GPU node. The decoupling of code-vector optimization from per-class sample distribution also resolves the 'minority collapse' problem in imbalanced datasets, a persistent issue in real-world FR. Open questions include whether the fixed code vectors (computed once before training) remain optimal when the training set changes substantially, whether the CLIP initialization dependency is a bottleneck for domains where CLIP features are less informative, and whether the approach extends naturally to multi-modal or video-based recognition settings.
