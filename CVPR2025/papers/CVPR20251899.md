## Problem

Existing model merging methods are restricted to models fine-tuned from the same pretrained base, produce merged models of fixed (original) size, and some require access to the fine-tuning data. This paper addresses the more general and practically important setting of merging two models with the same architecture but different initializations and training domains, while allowing the merged model's size to be flexibly controlled.
![Teaser figure](../imgs/CVPR20251899/cropped_page1_idx0.webp)

## Input / Output

The method takes two trained models of identical architecture (e.g., ResNet-50 or ViT) that may originate from different pretrained checkpoints and be fine-tuned on different datasets. Optionally, it consumes a batch of images from the training domains (or a substitute like ImageNet for the PLeaS-free variant) solely to compute intermediate activations for permutation matching and least-squares fitting. The output is a single merged model whose per-layer width can be independently set between 1× and 2× the original, governed by a global compute/memory budget.

## Method

PLeaS is a two-stage, hyperparameter-free algorithm. In the first stage, it extends Git Re-Basin's activation matching to find per-layer permutation matrices aligning features across the two models, then selects only the k_i most similar feature pairs per layer to merge (partial merging), keeping dissimilar features as separate neurons so the merged layer width becomes 2d_i − k_i. In the second stage, it solves a layer-wise least-squares problem that fits the merged layer's weight matrix to map the permuted ensemble of input features (Z_i^A + P_i Z_i^B) to the permuted ensemble of output features (Z_{i+1}^A + P_{i+1} Z_{i+1}^B), effectively distilling ensemble behavior into a single network. This least-squares step is the key differentiator over prior permutation-based merging: simply averaging permuted weights degrades representations, whereas the LS solution preserves the additive ensemble signal at every layer. The per-layer merge ratio k_i/d_i is chosen independently to meet a target FLOPs budget, giving fine-grained size–accuracy control that methods like ZipIt! (which assigns a uniform 1× prefix and 2× suffix) cannot match.

## Results

On DomainNet (shared label space, 345 classes), PLeaS achieves 38.6% average accuracy at 1× model size, outperforming the prior state-of-the-art MuDSC (30.7%) by ~8 points and Git Re-Basin (17.8%) by over 20 points. On fine-grained datasets with different label spaces (CUB, NABirds, Pets, Dogs), PLeaS reaches 74.9% average linear-probe accuracy, surpassing MuDSC (68.5%) by ~6.4 points. PLeaS approaches the ensemble upper bound (57.4% / 82.9%) while using only 1× FLOPs and memory, versus 2× for the ensemble. At 1.2× model size, PLeaS nearly matches ensemble performance on DomainNet (e.g., 75.9% on Real vs. 76.1% for ensemble).

## Baselines & Comparisons

PLeaS outperforms all five baselines across both evaluation settings. Against MuDSC (the prior state-of-the-art for merging differently-initialized models), PLeaS gains ~8 points on DomainNet (38.6% vs. 30.7%) and ~6.4 points on fine-grained datasets (74.9% vs. 68.5%), with the largest per-dataset gap being +11.5 points on NABirds. Against ZipIt!, which also supports partial merging, PLeaS leads by ~13 points on DomainNet (38.6% vs. 25.9%) and ~8 points on fine-grained tasks (74.9% vs. 66.9%), with the advantage growing at lower compute budgets (up to 10% for ResNet-50). Against Git Re-Basin, PLeaS nearly doubles accuracy on DomainNet (38.6% vs. 17.8%), confirming that the least-squares weight-fitting step is critical beyond mere permutation matching. RegMean (least squares without permutations) performs poorly (12.1% / 36.2%), validating that permutation alignment before least squares is essential. Simple Averaging (task vectors) is essentially non-functional in the different-initialization setting (1.5% / 10.1%), as expected when models start from different pre-trained weights.

## Relation to Prior Work

PLeaS extends Git Re-Basin's permutation-matching framework in two key ways: it generalizes full-layer merging to partial merging (selecting only the most aligned features per layer), and it replaces the simple weight-averaging step with a layer-wise least-squares regression that mimics permuted ensemble activations. This departs from the task-vector line of work (Task Arithmetic, TIES, RegMean), which assumes a shared base model, and from ZipIt!, which restricts partial merging to a binary prefix/suffix split rather than per-layer compute allocation. The least-squares objective is conceptually related to layer-wise distillation (RegMean) but is critically different in that it operates on permuted and summed features rather than individual model activations.

## Why It Matters / Open Questions

The practical significance lies in enabling practitioners to merge models from different pre-training lineages (e.g., Llama-1 vs. Llama-2 fine-tunes) without access to the original training data, which is increasingly relevant as decentralized model marketplaces grow. The PLeaS-free variant, which uses only ImageNet activations, narrows the gap to the data-using version to under 2%, making the method applicable under privacy or commercial constraints. Key limitations include the same-architecture requirement and the two-stage runtime overhead; extending PLeaS to heterogeneous architectures (e.g., CNN + ViT) or to transformer-specific symmetries remains an open direction the authors flag as promising.
