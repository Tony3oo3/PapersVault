## Problem

Existing test-time adaptation methods for point cloud recognition rely heavily on training data to build static prototype memories or pre-trained encoders, and are restricted to a fixed set of classes seen during training. This paper tackles a more practical and challenging setting: adapting a pre-trained large 3D model solely from online test data to handle distribution shifts (corruptions, OOD) while recognizing both previously seen and novel, unseen classes at test time.
![Teaser figure](../imgs/CVPR20251684/cropped_page0_idx0.webp)

## Input / Output

The method takes a point cloud P ∈ R^{N×3} (1,024–16,384 points depending on dataset) and a set of C text class names as input, processed by a frozen pre-trained large multimodal 3D model (ULIP, ULIP-2, OpenShape, or Uni3D). It produces a final class probability vector that combines the zero-shot softmax prediction with weighted cache-based logits from both global and local caches. Unusually, the local part representation is not obtained via explicit segmentation but by K-Means clustering (m=3) of the Transformer encoder's output point patches, reducing memory by two orders of magnitude compared to storing all patches.

## Method

Point-Cache constructs a hierarchical, dynamically updated cache entirely from online test samples without any training data. The global cache stores (feature, pseudo-label, entropy) triplets with a per-class cap of K=3 samples, using entropy-based replacement to retain only high-confidence entries; the local cache stores K-Means-clustered part features (m=3 centers) with the same selection rule. At test time, a new sample's global and local features serve as queries: affinity is computed as exp(−β(1 − cosine_similarity)) against all cached keys, and the resulting weights ensemble one-hot cached labels to produce adaptation logits. The final prediction is a linear combination y = y_zs + α_g·y_g + α_l·y_l (α_g = α_l = 4.0, β_g = β_l = 3.0), making the module entirely training-free and plug-and-play across different large 3D backbones.

## Results

On ModelNet-C (7 corruption types, severity 2), Point-Cache yields +6.18% and +4.84% average accuracy improvements over the zero-shot baselines of ULIP (47.52% → 53.70%) and ULIP-2 (57.95% → 62.79%), respectively. On the 1,156-class Objaverse-LVIS benchmark, the hierarchical cache boosts ULIP-2 by +2.10% absolute accuracy (30.26% → 32.36%). Uni3D with Point-Cache reaches 89.18% on ModelNet40, effectively matching the fully-supervised PointNet (89.20%) without any training. Throughput degradation is negligible (≤0.07 samples/s) and memory overhead is minimal (≤28 MB over the base model).

## Baselines & Comparisons

Point-Cache is evaluated as a plug-and-play module on four large multimodal 3D models: ULIP, ULIP-2, OpenShape, and Uni3D. Against ULIP, the hierarchical cache delivers the largest relative gains, improving ModelNet-C average accuracy by +6.18% (47.52% → 53.70%) and clean ModelNet by +8.06% (56.16% → 64.22%). Against ULIP-2, gains are +4.84% on ModelNet-C average (57.95% → 62.79%) and +2.10% on the 1,156-class Objaverse-LVIS (30.26% → 32.36%). Against OpenShape, which already has strong zero-shot performance (73.49% avg on ModelNet-C), the hierarchical cache still adds +3.10% on corrupted data (76.59%) though it slightly underperforms on clean data (84.04% vs. 84.56%). Against Uni3D, the cache yields +5.36% on ModelNet-C average (67.95% → 73.31%) and pushes ModelNet40 accuracy to 89.18%, matching the fully-supervised PointNet (89.20%) without any training. Across all four backbones and all eight benchmarks, the hierarchical cache consistently outperforms the zero-shot baseline, with the global cache alone accounting for most of the gain and the local cache providing an additional 0.5–1.5% refinement.

## Relation to Prior Work

Point-Cache builds on the zero-shot paradigm of large multimodal 3D models (ULIP, ULIP-2, OpenShape, Uni3D) that connect point clouds to language via contrastive pre-training, and on the broader cache/prototype literature (Tip-Adapter, CaFo, PointNN, BFTT3D) that stores sample features for retrieval-based prediction. It departs from prior test-time adaptation methods (MATE, BFTT3D, CloudFixer) in two key ways: it is constructed entirely from online test data without any training-set access, and it introduces a hierarchical (global + local-part) cache design rather than storing only global representations. The entropy-based selective update mechanism also distinguishes it from static, offline-constructed caches that consume substantial memory.

## Why It Matters / Open Questions

By being training-free, plug-and-play, and open-vocabulary, Point-Cache addresses a practical gap: deploying 3D recognition in the wild where training data is unavailable and new object categories appear. The consistent 2–6% gains across four large 3D models and eight benchmarks, with negligible memory and throughput overhead, make it an attractive drop-in module for production 3D pipelines. Open questions include how the method behaves under extreme class imbalance in the test stream, whether the sequential (batch-size-1) requirement limits real-time deployment, and whether the hierarchical cache design transfers to other 3D tasks such as segmentation or detection.
