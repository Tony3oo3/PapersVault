## Problem

Existing automated avatar crafting methods rely on inversion-based pipelines with neural renderers that simulate the parameter-to-image process, tying supervision to a specific engine's visual style and typically supporting only one input modality (text or image). This makes them brittle when the engine style (realistic, anime, cartoon) or input style changes, and prevents straightforward transfer across different game engines.
![Teaser figure](../imgs/CVPR20252156/cropped_page0_idx2.webp)

## Input / Output

The method accepts either a facial photo of any style (real-life, anime, cartoon, or engine-rendered) or a free-form text description as input. It outputs a structured set of avatar crafting parameters comprising continuous facial structure values (e.g., eye size, nose width; ~400 per engine), discrete one-hot makeup texture selections (e.g., eyebrow shape, eyeshadow style; ~200+), and continuous makeup attribute values (e.g., lip color, gloss brightness; ~100+), which the game engine then renders into a 3D avatar. A condition mask handles makeup attributes that are only valid under specific texture choices.

## Method

EasyCraft introduces a feedforward translator T = (T_e, T_p) where T_e is a Vision Transformer encoder and T_p is a parameter generation module of three parallel two-layer MLPs. The key insight is a two-stage training pipeline: first, T_e is pretrained via MAE-style masked patch reconstruction on ~5.1M facial images spanning real, anime, cartoon, and engine styles to establish a unified feature distribution; second, T_e is frozen and only T_p is trained on 200K randomly sampled parameter-screenshot pairs from the target engine, using L1 loss for continuous parameters, cross-entropy for discrete parameters, and a condition mask for conditional attributes. Because the frozen encoder maps all input styles into a consistent feature space, the engine-only-trained parameter head generalizes to arbitrary input styles without additional supervision. For text-based creation, a Stable Diffusion v1.5 model is fine-tuned on 7K engine-rendered images with GPT-4o-generated captions to produce engine-style faces, which are then passed through the same translator.

## Results

On the photo-based task, EasyCraft achieves FID of 17.65 (Justice Mobile) and 18.32 (Naraka: Bladepoint Mobile), roughly halving the FID of F2P (40.69 / 42.20) and F2P v2 (34.27 / 33.04), while maintaining competitive identity similarity (0.351 / 0.316 vs. F2P's 0.376 / 0.334). Inference speed is 0.026 s per image on an RTX 4090, orders of magnitude faster than F2P (1.140 s). On the text-based task, EasyCraft achieves FID of 18.76 / 19.43 and CLIP score of 0.241 / 0.246, substantially outperforming T2P (FID 32.9 / 33.51; CLIP 0.211 / 0.223) while running 2.7× faster (0.643 s vs. 1.725 s).

## Baselines & Comparisons

Against F2P [33], EasyCraft achieves a dramatically lower FID (17.65 vs. 40.69 on Justice Mobile; 18.32 vs. 42.20 on Naraka) and is 44× faster (0.026 s vs. 1.140 s), but trails slightly on identity similarity (0.351 vs. 0.376; 0.316 vs. 0.334) — a gap the authors attribute to F2P's direct use of ArcFace identity loss, which degrades on non-realistic inputs and inflates its Inception Score through distorted outputs. Against F2P v2 [36], EasyCraft wins on every metric: identity similarity (0.351 vs. 0.275; 0.316 vs. 0.217), FID (17.65 vs. 34.27; 18.32 vs. 33.04), and Inception Score, though F2P v2 is marginally faster (0.007 s vs. 0.026 s). Against T2P [50] on the text-based task, EasyCraft dominates across all metrics: FID (18.76 vs. 32.9; 19.43 vs. 33.51), CLIP score (0.241 vs. 0.211; 0.246 vs. 0.223), Inception Score (1.426 vs. 1.071; 1.441 vs. 1.098), and inference speed (0.643 s vs. 1.725 s), indicating both higher semantic fidelity and greater diversity of generated avatars.

## Relation to Prior Work

This paper departs from the dominant inversion-based paradigm for game character auto-creation (F2P, F2P v2, T2P, SwiftAvatar), which relies on neural renderers and off-the-shelf unsupervised constraints (segmentation, perceptual, CLIP) to transfer supervision from the image domain to the parameter domain. Instead, EasyCraft adopts a feedforward translator whose ViT encoder is pretrained via MAE-style self-supervised learning on a multi-style facial dataset, establishing a unified feature distribution that decouples the parameter generation module from input style. The text-to-image component builds on Stable Diffusion fine-tuning, extending the T2P line of work by replacing CLIP-constrained inversion with a dedicated engine-style SD model. Conceptually, the key lineage shift is from iterative inversion with domain-specific constraints to a single-pass feedforward mapping enabled by self-supervised feature unification.

## Why It Matters / Open Questions

The practical impact is significant for game studios: a single feedforward model trained only on engine-rendered pairs can handle arbitrary input styles (real photos, anime, cartoon) and text prompts in real time (~26 ms), removing the need for per-style supervision or neural renderers. The engine-agnostic design (only the parameter generation module needs retraining per engine) lowers the barrier to deploying auto-crafting across multiple titles. Limitations include evaluation on only two engines, a 7,000-image SD fine-tuning requirement per engine, and no exploration of full-body or non-facial parameters. Open questions include whether the unified-feature hypothesis holds for engines with radically different parameterization schemes (e.g., morphable-model-based vs. discrete-slot systems) and whether the approach extends to video or multi-view inputs.
