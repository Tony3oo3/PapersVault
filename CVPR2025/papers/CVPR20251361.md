## Problem

Reducing voxel query resolution in camera-based 3D occupancy prediction is necessary for real-time deployment but causes severe information loss, as low-level image features lose spatial distinctiveness when packed into fewer query cells. Existing view transformation methods rely solely on these low-level features via 2D-to-3D cross-attention, making them insufficient to reconstruct precise 3D geometry at reduced resolutions. The paper addresses how to encode and preserve rich high-level visual context within limited query sizes without sacrificing computational efficiency.

## Input / Output

The method takes N multi-view RGB camera images (432×800) processed by a ResNet-50 + FPN backbone into multi-scale 2D features, which are then attended to by learnable 3D voxel queries at reduced resolutions (e.g., 50×50×16 for Small, 50×50×4 for Tiny, versus the standard 100×100×16 Base). The output is a high-resolution 3D occupancy volume O ∈ R^(L×H×W×Z) with per-voxel semantic class predictions, upsampled from the low-resolution queries via a transposed 3D convolution. Additionally, pseudo 2D segmentation masks (from SEEDS or SAM) are used as auxiliary supervision during training but are not required at inference.

## Method

ProtoOcc introduces two complementary strategies. First, Prototype-aware View Transformation clusters 2D image features into M prototypes via iterative soft-assignment grouping, then maps them onto 3D voxel queries using a Feature Aggregation & Dispatch mechanism (cosine-similarity affinities scaled by sigmoid, followed by MLP-based redistribution), enriching each voxel query with high-level geometric context. Prototype quality is further refined through contrastive learning against pseudo-mask centroids, making each prototype more exclusive and spatially informative. Second, Multi-perspective Occupancy Decoding applies feature-level (random dropout, Gaussian noise) and spatial-level (transpose, flip) augmentations to the voxel queries, upsamples each augmented variant through a shared transposed 3D convolution to form multiple scene perspectives, and enforces a GRAND-style L2 consistency regularization so all perspectives predict the same occupancy. The full model is trained with four losses: semantic occupancy (L_occ), Lovász (L_Lov), prototype contrastive (L_cls), and scene consistency (L_cons).

## Results

On Occ3D-nuScenes, ProtoOcc achieves the highest mIoU across all three query resolutions: 39.01 (Base, 100×100×16), 37.80 (Small, 50×50×16), and 35.68 (Tiny, 50×50×4). Most notably, ProtoOcc-Small (37.80 mIoU) nearly matches PanoOcc-Base (38.11 mIoU) while using 75% fewer voxel query parameters, with only a 0.31 mIoU gap. On SemanticKITTI, ProtoOcc serves as a plug-and-play module that improves VoxFormer-B from 12.35 to 13.57 mIoU (+1.22) and Symphonies-S from 13.64 to 14.50 mIoU (+0.86). In terms of efficiency, ProtoOcc-Small requires 60.5% less inference time (105ms vs 266ms), 71.2% fewer FLOPs (378G vs 1310G), and 65.2% fewer parameters (16.11M vs 46.24M) than PanoOcc-Base.

## Baselines & Comparisons

ProtoOcc outperforms all baselines in every query resolution setting on Occ3D-nuScenes. In the Base setting, ProtoOcc (39.01 mIoU) surpasses PanoOcc (38.11) by 0.90, OccFormer (37.04) by 1.97, and BEVFormer (34.97) by 4.04. The most striking result is the cross-resolution comparison: ProtoOcc-Small (37.80) trails PanoOcc-Base (38.11) by only 0.31 mIoU despite using 75% fewer voxel query parameters, and ProtoOcc-Tiny (35.68) is within 0.10 of PanoOcc-Small (35.78). On SemanticKITTI, ProtoOcc acts as a plug-and-play enhancement: it improves VoxFormer-S mIoU from 11.51 to 12.39 (+0.88) and VoxFormer-B from 12.35 to 13.57 (+1.22), and boosts Symphonies-S from 13.64 to 14.50 (+0.86) and Symphonies-B from 14.38 to 14.83 (+0.45). In the efficiency comparison (Table 3), ProtoOcc-Small (105ms, 378G FLOPs, 16.11M params) is substantially faster and lighter than PanoOcc-Base (266ms, 1310G, 46.24M) while achieving nearly identical mIoU, and it also outperforms DFA3D [18] (153ms, 360G, 22.33M, 36.27 mIoU) in both speed and accuracy.

## Relation to Prior Work

ProtoOcc extends the PanoOcc 3D voxel query framework for camera-based occupancy prediction by addressing a previously overlooked bottleneck: the information loss inherent in low-resolution voxel queries during 2D-to-3D view transformation. It repurposes the Feature Aggregation & Dispatch mechanism from ClusterFormer (originally a 2D image-space paradigm) as a cross-domain mapping function that lifts 2D image prototypes into 3D voxel query space, and borrows GRAND regularization from graph neural networks for scene consistency across augmented perspectives. Unlike DFA3D, which enhances view transformation for object-wise detection, ProtoOcc targets holistic scene understanding by encoding high-level geometric structure (layouts, boundaries) into voxel queries, and unlike COTR which embeds into large queries then downsamples, it directly operates on smaller queries from the start.

## Why It Matters / Open Questions

The practical significance lies in enabling near-real-time 3D occupancy prediction for safety-critical autonomous driving systems: ProtoOcc-Small achieves mIoU within 0.31 of PanoOcc-Base while using 75% fewer parameters in view transformation, and the plug-and-play validation on SemanticKITTI (where smaller models with ProtoOcc surpass their larger counterparts without it) suggests broad applicability across architectures. Open questions include whether the pseudo-mask quality bottleneck (SEEDS vs. SAM) can be resolved with self-supervised alternatives, whether the multi-perspective decoding overhead scales favorably with more augmentations, and whether the prototype-aware mechanism transfers to other 3D perception tasks beyond occupancy. The reliance on external pseudo-mask generators (SAM, SEEDS) introduces a dependency that may limit deployment flexibility.
