## Problem

Fully fine-tuning large pre-trained point cloud transformers for downstream tasks incurs substantial computational and storage costs and risks disrupting pre-trained knowledge. Existing parameter-efficient fine-tuning (PEFT) methods for point clouds—such as IDPT, DAPT, and PPT—rely on complex adapter and prompt mechanisms that still require relatively many tunable parameters. The paper asks whether a simpler, more parameter-efficient scheme can match or exceed these methods while capturing both global and local 3D structure.

## Input / Output

The method consumes a raw 3D point cloud P ∈ R^{N×3} and tokenizes it into g patches via farthest point sampling and k-nearest-neighbor clustering, producing token sequences T_p ∈ R^{g×d} alongside a classification token. For classification (ScanObjectNN, ModelNet40) it outputs a single class label; for part segmentation (ShapeNetPart) it outputs per-point part labels. During fine-tuning, only 0.77M parameters (3.43% of the Point-MAE backbone) are updated, and at inference the LoRA matrices are merged into the frozen weights so the only extra component is a small shared Prompt MLP.

## Method

PointLoRA injects low-rank adaptation matrices (W_u ∈ R^{d×r}, W_d ∈ R^{r×d}, r=8) into the qkv projection and FFN layers of a frozen point cloud transformer, capturing global point-cloud features in a manner analogous to PointNet's permutation-invariant aggregation. To complement this global view, a Multi-Scale Token Selection module applies FPS at two scales (128 and 64 centers), clusters neighbors via k-NN, encodes patches with a shared Mini-PointNet, and uses a lightweight Mask Predictor (two MLP layers + Sigmoid) to score and Top-K select the most informative tokens (32 and 8 per scale). The selected tokens are concatenated with the original input and processed by a shared Prompt MLP (dimension 32, GELU activation) whose output is added to the LoRA adaptation, yielding O_update = PromptMLP(T_input, S_p) + ΔW·(T_input, S_p). Training minimizes the task-specific loss plus a balanced binary-entropy regularization on the Mask Predictor scores (λ=0.004), and the entire scheme requires only 3.43% trainable parameters while surpassing full fine-tuning on the hardest ScanObjectNN variant.

## Results

PointLoRA achieves 85.53% overall accuracy on the most challenging ScanObjectNN PB-T50-RS variant using only 0.77M tunable parameters (3.43% of the full model), surpassing the full fine-tuning baseline of Point-MAE (85.18%) and outperforming all other PEFT methods (DAPT: 85.08%, IDPT: 84.94%, PPT: 84.45%). On ModelNet40 few-shot learning, RECON+PointLoRA attains 98.8±1.2% (5-way 20-shot) and 95.8±2.9% (10-way 20-shot), matching or exceeding the full fine-tuning RECON baseline. For ShapeNetPart segmentation, the method reaches 83.98% class mIoU with 5.63M tunable parameters, edging out DAPT (83.87%) and PPT (83.88%).

## Baselines & Comparisons

Against the three dedicated 3D PEFT methods, PointLoRA wins on the hardest ScanObjectNN variant (PB-T50-RS): 85.53% vs. DAPT's 85.08% (+0.45), IDPT's 84.94% (+0.59), and PPT's 84.45% (+1.08), while using fewer tunable parameters than all three (0.77M vs. 1.1M, 1.7M, and 1.04M respectively). PointLoRA also surpasses the full fine-tuning Point-MAE baseline (85.18%) on PB-T50-RS, making it the only PEFT method to exceed full fine-tuning on this split. Compared to generic PEFT methods from NLP and 2D vision (vanilla LoRA at 81.74%, Adapter at 83.93%, BitFit at 82.62%, VPT-Deep at 81.09%), PointLoRA gains 1.6–4.4 points, demonstrating that 3D-specific token selection is critical. On ModelNet40 few-shot learning, RECON+PointLoRA matches or slightly trails the full fine-tuning RECON (98.8 vs. 98.9 in 5-way 20-shot) while beating IDPT (98.3) and DAPT (97.7). On ShapeNetPart, PointLoRA achieves the best class mIoU (83.98%) among PEFT methods, narrowly ahead of DAPT (83.87%) and PPT (83.88%), though all PEFT methods remain below the full fine-tuning RECON (84.52%). Against traditional supervised baselines (PointNet, DGCNN, PointNeXt), PointLoRA with a pre-trained backbone substantially outperforms them on all ScanObjectNN variants, e.g., 85.53% vs. 87.7% for PointNeXt on PB-T50-RS where PointNeXt uses 1.4M parameters trained from scratch.

## Relation to Prior Work

PointLoRA adapts the LoRA mechanism from large language models (Hu et al., ICLR 2022) to point cloud transformers, injecting low-rank matrices into the qkv projection and FFN layers to capture global features. It departs from prior point-cloud PEFT methods (IDPT, DAPT, PPT) that rely on complex adapter architectures and specialized prompt designs, instead combining a simpler LoRA backbone with a multi-scale token selection module that provides local geometric context as prompts. The authors draw a conceptual parallel between LoRA's two-matrix structure and PointNet's permutation-invariant feature extraction, positioning their method as a natural fit for unordered point cloud data.

## Why It Matters / Open Questions

By achieving competitive accuracy with only 3.43% of trainable parameters, PointLoRA offers a practical path for deploying fine-tuned point cloud models in resource-constrained settings where storing multiple full-weight checkpoints is prohibitive. The clean separation of global (LoRA) and local (token selection) information provides an interpretable design that could inform future PEFT strategies for other 3D architectures. Open questions include whether the approach scales to much larger pre-trained models or more complex tasks (e.g., 4D scene understanding, open-vocabulary segmentation), and whether the multi-scale token selection overhead becomes significant at higher point counts.
