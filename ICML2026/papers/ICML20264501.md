## Problem

Training generalist tool-use agents via reinforcement learning requires large-scale, diverse, and reliable interactive environments, yet existing synthesis methods are either constrained by limited real-world API availability, suffer from hallucination-prone LLM simulation, or depend on expensive proprietary teacher models and fixed external documentation. No prior framework can fully automate the construction of high-fidelity, verifiable, and scalable interactive environments from scratch without manual intervention or rigid task priors.

## Input / Output

The method takes only lightweight domain keywords (e.g., 'Job Seeking') as input and produces a complete RL training ecosystem per domain: 20–80 executable tools with verified Python implementations, 5–25 database tables with integrity constraints, a directed Tool Dependency Graph encoding causal relationships, and 64–512 verifiable multi-turn tasks each with a grounded user intent, an initial environment state populated with distractor records, and a rule-based reward function that checks the final database state against ground truth using three matching policies (exempt fields, hard constraints, semantic alignment). The output is a fully interactive POMDP sandbox rather than static trajectories, supporting open-ended exploration across the entire feasible action space.

## Method

ScaleEnv operates in two decoupled phases. Phase 1 (Executable Graph Construction) synthesizes tool and database schemas top-down from a domain keyword, generates executable code via LLM agents, and validates all implementations through a Procedural Testing mechanism that executes tools on matched database instances and classifies outcomes as success, anticipated rejection, or unexpected failure (triggering iterative debugging). Verified tools are then consolidated into a Tool Dependency Graph via pairwise analysis of data flow, pre/post-conditions, and shared state. Phase 2 (Task Instantiation via Graph Expansion) samples a seed tool chain as executable code, constructs an initial environment state with distractor injection, synthesizes a grounded user instruction, and then iteratively expands the environment using Dependency-Aware BFS (adding tool nodes only when their input/output dependencies are satisfiable) and LLM-Gated Chain Expansion (a parametric gating policy balancing structural complexity c(H_n) and oracle feasibility g(D_n) to decide when to inject new seed chains). Training uses GRPO with a deterministic rule-based reward that directly compares the agent's final database state to the ground-truth state, eliminating LLM-as-a-judge overhead and reward hacking.

## Results

On τ²-Bench, Qwen3-SE-8B improves over the base Qwen3-8B by +12.5 on Retail (50.9 vs 38.4), +7.0 on Airline (37.5 vs 30.5), and +5.7 on Telecom (27.2 vs 21.5). On VitaBench, Qwen3-SE-32B achieves the largest gains on Instore (+12.0, 34.5 vs 22.5) and OTA (+8.0, 12.5 vs 4.5), while nearly doubling the Cross-domain score (10.8 vs 5.3). On the Pass@4 upper-bound metric, Qwen3-SE-32B reaches 46.8 average across VitaBench domains versus 36.0 for the base model, with the Cross-domain score nearly doubling from 15 to 29.

## Baselines & Comparisons

ScaleEnv is compared against three LLM-based environment construction methods: ToolACE, Simia, and EnvScaler. Against ToolACE (LLaMA-3.1-8B), Qwen3-SE-8B wins on all seven evaluation domains, with the largest margins on VitaBench (e.g., Instore 23.8 vs 0.3, Delivery 26.3 vs 3.3). Against Simia (Qwen3-8B), ScaleEnv loses slightly on τ²-Bench Retail (50.9 vs 52.9) and Airline (37.5 vs 40.5) but dominates on all four VitaBench domains where Simia collapses to near-zero (e.g., Instore 23.8 vs 0.3, Cross 3.0 vs 0.0), which the authors attribute to Simia's overfitting to user-driven session termination. Against EnvScaler (Qwen3-8B), ScaleEnv wins on six of seven domains but trails on Telecom (27.2 vs 32.7); the advantage is most pronounced on VitaBench Cross (3.0 vs 2.5) and OTA (7.0 vs 6.3). Overall, ScaleEnv's key differentiator is consistent generalization across both interaction patterns (policy-constrained dialogue in τ²-Bench and autonomous termination in VitaBench) without the behavioral collapse observed in Simia.

## Relation to Prior Work

This paper carves new ground at the intersection of procedural environment generation and RL-based agent training, departing from three existing paradigms: real-world API environments (constrained by safety and latency), LLM-simulated environments (prone to hallucination and state inconsistency), and prior synthetic pipelines like AutoForge and EnvScaler (limited by document-based generation or inability to construct complex interactive tasks). Its key conceptual departure is grounding environments in verified executable code with a Tool Dependency Graph as the structural backbone, combined with a graph-expansion strategy that 'snowballs' linear tool chains into non-linear subgraphs. Unlike prior methods that rely on expensive proprietary teacher models for data generation, ScaleEnv eliminates this dependency entirely by leveraging pure RL self-exploration (GRPO) with rule-based rewards, requiring only lightweight domain keywords as input.

## Why It Matters / Open Questions

The paper addresses the critical bottleneck of environment scarcity for scalable agent RL training and provides a fully automated, zero-manual-intervention pipeline that practitioners can adopt. The empirical domain scaling curve—showing that increasing domain diversity yields larger gains than increasing task count within existing domains—offers actionable guidance for data-centric agent training strategies. Open questions include whether performance plateaus beyond 16 domains, how the approach handles multi-agent or adversarial settings, and the safety implications of a domain-agnostic synthesis framework that could theoretically generate harmful environments. The t-SNE-verified OOD evaluation strengthens confidence, but the absolute performance levels on challenging benchmarks (e.g., VitaBench Cross at ~10-30%) suggest substantial headroom remains.
