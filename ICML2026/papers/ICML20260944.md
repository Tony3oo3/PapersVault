## Problem

Existing edge-cloud LLM inference methods route tasks at coarse granularity (query-level or fixed reasoning steps) using static difficulty heuristics, missing opportunities for fine-grained parallel execution of interdependent subtasks and failing to adapt to time-varying latency and API budgets. The paper asks how to design a framework that performs adaptive, budget-aware scheduling and routing at subtask granularity, enabling fast and API-efficient inference on complex reasoning tasks.
![Teaser figure](../imgs/ICML20260944/cropped_page1_idx0.webp)

## Input / Output

The system takes a single text reasoning query and produces a final text answer along with per-subtask routing decisions (edge vs. cloud). Internally, the query is decomposed into a DAG of at most 7 subtasks (XML-formatted plan with explicit prerequisite edges), each encoded via qwen3-embedding-0.6b into a fixed-length vector consumed by a two-hidden-layer MLP router. The planner outputs are validated for acyclicity, rootedness, and dependency consistency, with a bounded repair-and-fallback-to-chain procedure ensuring robustness.

## Method

HybridFlow couples three mechanisms: (1) an edge-deployed planner (Llama3.2-3B) prompted with an Explain-Analyze-Generate metaprompt decomposes each query into a dependency-aware DAG, exposing parallelism among independent subtasks; (2) a lightweight MLP router predicts a normalized benefit-cost utility for each subtask, trained offline via MSE on profiled accuracy gains and costs from paired edge/cloud executions; (3) an online primal-dual thresholding rule (derived from the Lagrangian relaxation of a 0-1 knapsack formulation) dynamically adjusts the offloading threshold as cumulative API and latency budgets are consumed, with an optional LinUCB contextual-bandit calibration head for distribution-shift robustness. The key insight is that the knapsack-optimal policy decomposes into independent per-subtask threshold comparisons against a shadow price, which HybridFlow approximates online with a learned utility and an adaptive threshold that tightens as resources deplete.

## Results

On four reasoning benchmarks (GPQA, MMLU-Pro, AIME24, LiveBench-Reasoning), HybridFlow achieves an average accuracy of 55.34% using Llama3.2-3B (edge) + GPT-4.1 (cloud), approaching the all-cloud CoT baseline (58.99%) while consuming only 0.0088 average API cost versus 0.0269 for CoT. End-to-end latency is 17.48 s on average, a 28.5% reduction over HybridLLM (24.45 s) and a 4.6% reduction over DoT (18.32 s). HybridFlow attains the lowest cloud API cost (0.0088) among all edge-cloud collaborative baselines while maintaining competitive accuracy across all four benchmarks.

## Baselines & Comparisons

Against the strongest single-model baseline, CoT with GPT-4.1 (58.99% avg accuracy), HybridFlow trails by 3.65 points in accuracy but reduces API cost by 67% (0.0088 vs 0.0269) and latency by 44% (17.48 s vs 31.02 s), making it the clear winner on the cost-accuracy frontier. Against SoT (52.90% avg), HybridFlow improves accuracy by 2.44 points while cutting API cost by 55% (0.0088 vs 0.0196) and latency by 10.5%. Against PASTA (45.56% avg), HybridFlow gains 9.78 accuracy points and reduces API cost by 72% (0.0088 vs 0.0313), though PASTA is slightly faster in latency (15.37 s vs 17.48 s). Against the two edge-cloud collaborative baselines, HybridFlow dominates: versus HybridLLM (38.70% avg), it improves accuracy by 16.64 points, reduces latency by 28.5%, and cuts API cost by 31.3%; versus DoT (46.50% avg), it improves accuracy by 8.84 points, reduces API cost by 2.2%, and slightly reduces latency (17.48 s vs 18.32 s). Overall, HybridFlow is the only method that simultaneously achieves the best accuracy among collaborative baselines, the lowest API cost, and competitive latency.

## Relation to Prior Work

HybridFlow sits at the intersection of two research threads: structured task decomposition for LLM reasoning (CoT, SoT, PASTA, ToT, GoT) and edge-cloud collaborative inference (HybridLLM, DoT, SplitReason, FrugalGPT). It builds directly on the EAG metaprompt (Gu et al., 2025) for eliciting structured plans from a small edge model, and on the 0-1 knapsack / Lagrangian relaxation framework for resource-constrained allocation. The key departure from prior work is the coupling of dependency-aware DAG decomposition with online, budget-adaptive subtask-level routing: existing edge-cloud systems route at query or fixed-step granularity with static thresholds, while decomposition methods (SoT, PASTA) parallelize without explicit resource budgets. HybridFlow unifies these by treating each subtask as a knapsack item whose offloading decision is made online via a learned utility predictor and a dual-ascent threshold that tracks real-time budget consumption.

## Why It Matters / Open Questions

The paper provides a practically deployable recipe for reducing cloud API costs by ~50% while maintaining within 4–7% accuracy of full-cloud CoT, which is directly relevant to latency-sensitive and budget-constrained edge deployments. The knapsack-to-Lagrangian-to-online-threshold derivation gives the routing mechanism a clean optimality interpretation, and the model-pair swap experiment (Qwen2.5-7B/DeepSeek-V3) suggests the framework is not tied to a specific model instantiation. Open questions include: how the approach scales to much larger DAGs (currently capped at 7 subtasks), whether the offline profiling cost (~$1.36 for 2000 queries) remains affordable as model pairs change, and whether the contextual-bandit calibration head provides meaningful robustness under truly non-stationary network conditions beyond the controlled benchmarks tested.
