## Problem

Current computer-use agents follow a sequential fetch-screenshot-execute loop where every step requires an LLM call, resulting in high latency (100–200 s per task) and frequent errors from incorrect tool sequencing. No prior work treats the task-to-action translation as a compilation problem with multiple valid code plans of differing cost, nor does it explore parallelization strategies (task parallelism, request hedging) or enforce state-flow correctness at plan-generation time to eliminate the dominant class of execution errors.

## Input / Output

The system consumes a natural-language task description, a set of cached tool manifests (each specifying pre/post state invariants, JSON-Schema input/output types, and executable JavaScript bodies), and per-DOM-element latency distributions fitted offline from execution traces. It produces a validated executable code plan (Python-like code composing cached tool calls with optional ai_eval LLM calls), a scheduling strategy assignment (serial, parallel, or hedge with a fixed vCPU budget), and the completed web task. The code plan is statically checked via control-flow-graph traversal for type safety and state-flow correctness (post_i ⊆ pre_{i+1}) before any execution begins.

## Method

The paper introduces a three-component agent JIT compiler. First, an invariant-enforcing tool protocol requires each cached tool to declare precondition and postcondition state invariants plus optional runtime DOM predicates, enabling compositional verification of tool sequences at compilation time and eliminating 45–50% of errors from incorrect action ordering. Second, the JIT-Planner generates k candidate code plans in parallel from an LLM, builds a control-flow graph for each, and simultaneously validates state-flow transitions and estimates cost (with a nesting penalty γ=10 that heavily penalizes LLM calls inside loops), selecting the minimum-cost valid plan. Third, the JIT-Scheduler predicts which DOM elements the plan will interact with via an LLM, then runs Monte Carlo sampling (N=1000 trials) from learned per-element latency distributions to estimate expected wall-clock latency under serial, parallel, and hedge strategies, selecting the strategy with minimum mean latency. The key architectural insight is that compiling a task to code—rather than running a per-step agent loop—eliminates unnecessary LLM inference (73% of baseline latency) and exposes a finite space of valid plans from which the lowest-cost one can be selected, yielding 10.4× speedup and +28% accuracy over Browser-Use.

## Results

JIT-Planner achieves a 10.4× mean latency speedup (11.7s vs. 122.1s for Browser-Use) and +28 percentage-point accuracy improvement (93% vs. 65%) across five web applications and three LLMs. The speedup ranges from 7.4× (Omnizon) to 18.9× (Reddit) depending on how much per-step LLM inference can be eliminated. JIT-Scheduler achieves a 2.4× speedup (109.9s vs. 258.7s) and +9 percentage-point accuracy improvement (86.4% vs. 77.8%) over OpenAI CUA using adaptive strategy selection (Serial/Parallel/Hedge) via Monte Carlo cost estimation. Cost-aware plan selection yields a 5.3× latency gap between best- and worst-cost candidates (11.7s vs. 61.7s), confirming the cost model's ranking effectiveness.

## Baselines & Comparisons

Against Browser-Use (Yang et al., 2024), JIT-Planner wins decisively on both latency and accuracy: 10.4× faster (11.7s vs. 122.1s) and +28 pp more accurate (93% vs. 65%), with the gap driven primarily by eliminating per-step LLM calls that account for 73% of Browser-Use's latency. Against Browser-Use+cache (which adds the same synthesized tools but retains the sequential agent loop), JIT-Planner still achieves a 6.8× speedup, isolating the contribution of cost-optimizing planning beyond tool access alone. Against OpenAI CUA (Wang et al., 2025), JIT-Scheduler achieves 2.4× lower latency (109.9s vs. 258.7s) and +9 pp higher accuracy (86.4% vs. 77.8%) for Gemini-2.5-Pro, demonstrating that adaptive scheduling (selecting Serial, Parallel, or Hedge per task) outperforms the fixed serial execution used by dedicated computer-use agents. A CUA+cache ablation (GPT-5.4 with identical tools) remains 1.5–2.4× slower than JIT-Planner, confirming that the speedup comes from the planning architecture rather than tool quality.

## Relation to Prior Work

This paper builds on the code-action paradigm (Nam et al., 2024; Song et al., 2025) that unifies an agent's action space into executable code, and on tool-protocol standards like MCP (Ray, 2025) for type-checking tool interfaces. It departs from prior web-agent work (Browser-Use, OpenCUA, WebAgent-R1) in two key ways: rather than optimizing at the model level (routing, caching) or fine-tuning smaller action models, it reframes planning as a JIT compilation problem where multiple code candidates are generated, statically validated against invariant-enforcing pre/postconditions, and selected by CFG-based cost estimation. The scheduler further extends this by treating vCPU allocation (serial, parallel, hedge) as a decision problem solved via Monte Carlo sampling from learned per-element latency distributions, a level of scheduling granularity absent from prior sequential agent loops.

## Why It Matters / Open Questions

The 10.4× speedup and 28% accuracy gain over Browser-Use are substantial and largely attributable to eliminating per-step LLM inference (73% of baseline latency) and catching state-flow violations at compile time rather than runtime. The invariant-enforcing protocol is a practical safety mechanism for increasingly autonomous agents, turning opaque per-step decisions into inspectable, statically verifiable artifacts. Key limitations include a 25–90 min offline setup per application, cache staleness under UI changes, and sensitivity to stochastic environments (CAPTCHAs, rate limiting). Open questions include whether the approach extends to desktop/mobile via accessibility APIs, how to handle expected stochasticity in pre/postcondition checking, and whether the cost model generalizes beyond the five evaluated applications.
