## Problem

Existing efficient MLP ensembles for tabular deep learning (e.g., TabM) use identical hyperparameters across all base models, forcing practitioners to perform costly hyperparameter tuning to achieve competitive performance. This creates a barrier to accessible, out-of-the-box results on tabular tasks, as no universally strong default configuration exists. The paper asks whether one can build powerful MLP ensembles that require only specifying hyperparameter *ranges* rather than exact values, eliminating the tuning step entirely.
![Teaser figure](../imgs/ICML20261319/cropped_page0_idx0.webp)

## Input / Output

TabPack consumes standard tabular features (numerical, binary, and categorical) that are first mapped through learned periodic feature embeddings (a new variant using cosine activations without hidden layers) before being fed into the packed MLP backbone. The output is an ensemble prediction formed by averaging the outputs of a selectively chosen subset of base models (typically 16±9 out of 64 trained). Unusually, the user specifies sampling distributions (e.g., LogUniform ranges for learning rates, UniformInt for depth) rather than point hyperparameter values, and the system handles all selection and training internally in a single run.

## Method

TabPack packs m=64 MLPs with randomly sampled hyperparameters (depth, dropout, embedding size, learning rate, weight decay) into a single module by padding all models to the maximum width/depth and using batched matrix multiplications along a new pack dimension, with zero-masking and layer-skipping to recover each base model's original behavior. A corresponding optimizer pack stores per-model optimizer states (Muon for main weights, AdamW for embeddings/biases) stacked along the same dimension. During training, all base models are trained in parallel on different batch sequences, and the ensemble is rebuilt once per epoch via greedy selection from a candidate pool that includes both the latest base-model checkpoints and the previous epoch's ensemble members, allowing multiple snapshots of the same base model to coexist. Early stopping is applied at two levels: base models are removed after p_base epochs without validation improvement, and training halts after p_ens epochs without ensemble improvement. The key finding is that hyperparameter diversity's primary role is enabling the tuning-free workflow rather than improving ensemble performance through model diversity, as a tuned same-hyperparameter variant (TabPack_SameHP) achieves comparable accuracy at 27× the runtime.

## Results

Across 17 medium-to-large tabular datasets (10K–1M+ samples, 8–900+ features), TabPack† achieves a mean rank of 1.6±0.6 with a single-run runtime of 2.4 hours, matching or exceeding extensively tuned baselines without any hyperparameter tuning. On five large industrial datasets (1M–13.6M training objects), TabPack† outperforms all baselines on four out of five tasks. Notably, TabPack†_MacBook (Apple M4 Pro, 20 GPU cores) completes a full training run in less time than the hyperparameter tuning of several baselines on an NVIDIA A100 GPU.

## Baselines & Comparisons

TabPack† (no tuning, single run) achieves a mean rank of 1.6±0.6, competitive with TabM† and XGBoost which require 50–200 tuning iterations each; the tuned variant TabPack†_SameHP improves rank to 1.4±0.7 but at 27× the runtime (65.5 h vs. 2.4 h). Against the tabular foundation models TabICLv2 and TabPFN-3, TabPack† is competitive overall but trails on small classification datasets where foundation models excel; on large regression tasks (e.g., Weather, Delivery ETA, Maps Routing with 6M–13.6M samples), TabPack† outperforms all baselines including XGBoost and TabM†. Compared to ModernNCA† and RealMLP, TabPack† consistently achieves better mean rank and notably better worst-25% performance, indicating greater stability across datasets. The multi-process baseline MLP†_HPE (offline ensembling) is competitive in performance but less efficient than TabPack's packed online approach, confirming the benefit of the ensemble-first design. On the TabArena-Lite benchmark (small-to-medium IID datasets), TabPack† in its default (tuning-free) regime outperforms all non-foundation baselines, though with smaller margins due to the reduced validation set size.

## Relation to Prior Work

TabPack extends the Packed Ensembles framework (Laurent et al., 2023) and the TabM architecture (Gorishniy et al., 2025) by allowing each base MLP in the ensemble to have independently sampled hyperparameters (depth, dropout, learning rate, weight decay, embedding dimensions) rather than sharing a single tuned configuration. This connects to the broader hyperparameter ensemble literature (Wenzel et al., 2020; Ding et al., 2022) but generalizes the idea to any degree of freedom in the model-optimizer pipeline, including optimizer hyperparameters, via a packed optimizer implementation. The key conceptual departure from TabM is the shift from a fixed-hyperparameter ensemble (requiring traditional tuning) to a randomly-sampled hyperparameter ensemble with online greedy selection, making the system usable with only range specifications rather than exact values.

## Why It Matters / Open Questions

The practical impact is substantial: a single untuned TabPack run on a MacBook matches or approaches the performance of extensively tuned baselines on an A100 GPU, dramatically lowering the barrier to competitive tabular ML. The ablation showing that hyperparameter diversity's primary role is enabling a tuning-free workflow (rather than improving ensemble quality) reframes how practitioners should think about ensemble diversity. Open questions include reducing reliance on the validation set (a known overfitting risk), extending packed implementations to new architectures and optimizers, and whether the observed strength on large regression tasks generalizes. The technique is also a stepping stone toward diversifying other pipeline components (loss functions, preprocessing) within a single efficient training run.
