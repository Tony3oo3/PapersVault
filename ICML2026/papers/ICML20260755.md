## Problem

CodeLLM-based code-as-policies (CaP) for embodied agents suffer from two coupled failures: repetitive prefill over long prompts causes high synthesis latency that undermines real-time responsiveness, and fully generative decoding produces API mismatches, missing safety guards, and unstable control logic that cause task failures. Existing memory-based approaches reuse only text-level representations with limited computational gains, while prior KV-caching methods lack function-level granularity needed for dynamic open-domain environments.

## Input / Output

At each timestep the agent receives a natural language instruction τ and a multimodal observation o_t (RGB, depth, segmentation from stereo and wrist cameras, plus proprioceptive joint states), along with a set of cached function-interface KV states retrieved from the two-tier code cache. The CodeLLM outputs a Python-like code policy that calls a predefined set of primitive APIs (e.g., pick, place, push, open_gripper); this code is concatenated with cached function implementations from the Function-Code tier to form the final executable program, which the environment executor then runs to produce a sequence of robot actions. When a runtime exception is raised, the system splits the program into prefix/error/suffix spans and regenerates only the middle span, producing a corrected executable program.

## Method

FCGRAFT restructures the native KV-caching mechanism into a two-tier code cache: a Function-Interface tier storing callable signatures with KV states for lightweight compositional generation, and a Function-Code tier storing validated implementations with KV states for in-place editing. Policy synthesis proceeds through two interdependent stages: cache-stitching injects interface KV states into the CodeLLM (Qwen2.5-Coder-14B) to compose function calls without recomputing cross-attention, eliminating structural errors and redundant prefill; cache-patching then localizes the erroneous span, reuses prefix KV states, and generates only the corrected middle segment guided by a chain-of-thought trace identifying the root cause. A locality scoring function combining recency, invocation frequency, conditional co-occurrence, and semantic perplexity governs which entries remain on GPU versus DRAM, promoting functional diversity while keeping the cache compact. This design ensures that stitching biases generation toward validated API sequences and control-flow templates, while patching enables non-destructive localized adaptation without full regeneration.

## Results

FCGRAFT achieves the best trade-off between task success rate (SR) and policy synthesis latency (PSL) across all benchmarks and scenarios. On ALFRED (Open-Composition), it reaches 61.58% SR with 5.82 s PSL, outperforming the second-best baseline LRLL (56.28% SR, 16.02 s PSL) by 4.04% SR and 2.67× faster. On RLBench (Open-Composition), FCGRAFT attains 45.91% SR at 3.24 s PSL versus LRLL's 36.11% SR at 10.83 s PSL. In real-world robotic manipulation, FCGRAFT achieves 77.78% SR (Office Desk) and 81.48% SR (Cooking Workstation) with PSL under 4 s, surpassing the best baseline by over 22% SR.

## Baselines & Comparisons

FCGRAFT outperforms all nine baselines on both SR and PSL across every benchmark and scenario. Against the strongest memory-based baseline LRLL, FCGRAFT gains 4.04–16.21% SR while reducing PSL by 2.25–2.67×, demonstrating that function-level KV reuse is more effective than text-level skill retrieval. Compared to the closest KV-caching baseline RAGCache, FCGRAFT achieves 18.31% higher SR and 2.3× lower PSL on average, confirming that function-level grafting (stitching + patching) substantially outperforms document-level prefix caching. KV-caching baselines CAG, EPIC, and PromptCache are faster than text-based methods (CaP, SCoT, PromptBook) but sacrifice SR by 10–20% because they lack function-level structural reuse and localized error correction. SCoT and PromptBook, which rely on long structured prompts, incur the highest PSL (22–33 s) with only marginal SR gains over CaP, highlighting the latency bottleneck of fully generative decoding. In real-world manipulation, FCGRAFT's advantage is most pronounced: it achieves 77.78% SR on Office Desk Rearrangement (vs. 55.56% for LRLL) and 81.48% on Cooking Workstation (vs. 55.56% for LRLL), with PSL under 4 s versus 9–13 s for all baselines.

## Relation to Prior Work

FCGRAFT sits at the intersection of three research threads: the Code-as-Policies (CaP) paradigm for embodied control, memory-based embodied agents (HELPER, LRLL, PromptBook), and KV-caching inference acceleration (RAGCache, PromptCache, EPIC). It departs from prior KV-caching work, which operates at the document or prompt-segment level, by restructuring the native KV cache into a two-tier, function-level hierarchy (interface + implementation) tailored to code policy synthesis. The skill-based robotics paradigm (Nachum et al., 2018; Nyga et al., 2018) provides the conceptual analogy of reusing and composing validated building blocks, but FCGRAFT instantiates this at the Transformer attention-state level rather than at the action-sequence level, enabling cache-stitching (compositional reuse) and cache-patching (localized repair) as interdependent stages.

## Why It Matters / Open Questions

The paper addresses two practical bottlenecks that limit real-world deployment of CaP systems—redundant prefill latency and fragile fully-generative decoding—and shows that function-level KV reuse can simultaneously improve robustness (18.31% higher SR) and speed (2.3× faster) over the closest KV-caching baseline. Real-world validation on a Franka Emika arm, including a time-critical gas-leakage scenario, strengthens the practical case. However, the code cache is currently isolated per agent, limiting scalability to multi-agent cooperative settings, and the locality scoring heuristic (Eq. 3) has not been replaced by a learned eviction/compression policy. Open questions include whether the two-tier design generalizes to non-Python code policies, how cache quality degrades under distribution shift, and whether cross-agent cache sharing can preserve the robustness gains.
