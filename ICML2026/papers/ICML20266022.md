## Problem

Prior work has broadly attributed reasoning gains in LLMs to code data in pretraining corpora, but these studies treat code as a monolithic category that conflates standalone executable programs with cross-domain structured reasoning traces (code-text mixtures, markup languages). This paper asks: under a fixed training budget, what is the marginal contribution of pure executable code versus structured reasoning signals, and how do domain corpora interact competitively across capability dimensions?

## Input / Output

The method consumes a 10T-token corpus partitioned into seven domains, with a critical operational distinction between pure Code (standalone executable functions with >60% code density after comment removal, sourced from GitHub) and Code-NL (mixed code-language data from web sources containing problem descriptions interleaved with code snippets). The output is pretrained MoE models (1B/5B dense, 16e/32e MoE) evaluated across five capability dimensions, plus a cognitive-scaffold subset of math samples. The ablation design is notable: Code-NL is retained in both full and w/o-code configurations, so the code ablation isolates only the marginal effect of standalone executable code rather than removing all code-like content.

## Method

The core contribution is a controlled pretraining study using fine-grained MoE architectures (shared experts, stochastic routing warmup, dropless routing with load-balancing and z-loss) trained from scratch on a 10T-token corpus with quality-tiered stratification. Two systematic ablations—removing pure code while retaining Code-NL, and removing math—reveal asymmetric competitive interactions: code degrades complex mathematical reasoning by 14.38% on average, while math degrades code-reasoning benchmarks by up to 17.30%. To identify what actually improves reasoning, the authors train a FastText classifier on 200k code samples as structural proxies (not semantic sources), then apply it to the math corpus to extract 'cognitive scaffolds'—samples exhibiting explicit subgoals, hierarchical derivations, case decompositions, and verification steps. These scaffolds replace a portion of the math budget rather than adding tokens, yielding 17.56% average gains on complex math benchmarks (OlympiadBench +47.78%, MATH +23.17%) while preserving programming performance within ~1%. Expert-routing analysis via Jensen-Shannon divergence across 64 experts provides mechanism-level evidence that scaffolds enhance reasoning through cross-domain structural signals rather than forcing domain-specific expert reallocation.

## Results

Under a fixed 10T-token budget, ablating pure code from the corpus improves overall mathematical ability by 14.38% (32e MoE: 36.20 → 38.52), with the largest gains on complex benchmarks (Minerva-Math +71.53%, OlympiadBench +47.16%, MATH +22.64%), while programming ability drops sharply (HumanEval 46.95 → 17.68). Conversely, ablating math data reduces overall math score by 51% (36.20 → 17.71) but improves competitive programming (CodeForces +37.11%) at the cost of code-reasoning tasks (CruxEval −17.30%). Introducing cognitive scaffolds within a fixed math budget yields a 17.56% average gain on mathematical reasoning (OlympiadBench +47.78%, MATH +23.17%, College Math +30.05%) while preserving programming performance with only ~1% degradation.

## Baselines & Comparisons

This paper does not compare against external method baselines; instead, it performs controlled data-ablation comparisons (full corpus vs. w/o code vs. w/o math vs. w/o cognitive scaffolds) across MoE (16e, 32e) and dense (1B, 5B) architectures. The central finding contradicts prior work by Ma et al. (2024) and Aryabumi et al. (2025), which reported that code data broadly enhances reasoning without negative transfer. The authors attribute this discrepancy to corpus granularity: prior studies grouped markup languages (Markdown, CSS, HTML) and code-NL mixtures under 'code,' whereas this work isolates pure executable code from Code-NL data. Under the stricter definition, pure code is shown to compete with knowledge-intensive tasks (−14.38% on math) rather than synergize with them. The cognitive-scaffolding intervention is compared against the standard math corpus at equal token budget, demonstrating that structured reasoning samples outperform unstructured math data on complex benchmarks while causing only ~1% loss on code tasks, a trade-off not observed in the prior code-inclusion studies.

## Relation to Prior Work

This paper directly challenges the consensus from Ma et al. (2024) and Aryabumi et al. (2025) that code data broadly enhances reasoning, by introducing a fine-grained separation between standalone executable code (Code) and mixed code-text data (Code-NL) that prior work treated as a monolithic category. Methodologically, it sits at the intersection of data-mixing research (DoReMi, REGMIX) and data-selection research, but repurposes the ablation framework to isolate marginal domain contributions under a fixed-token budget rather than to optimize mixture ratios. The cognitive-scaffolding selection via a FastText structural classifier is a lightweight, scalable data-selection technique that borrows the structural-signal idea from code-quality literature but applies it to math-domain samples for reasoning transfer.

## Why It Matters / Open Questions

The finding that pure code competes with mathematical reasoning while cross-domain structured traces (Code-NL, math-text mixtures) are the actual reasoning drivers reframes how practitioners should allocate pretraining budgets, with immediate practical implications for trillion-token-scale training pipelines. The cognitive-scaffolding strategy offers a targeted, low-cost intervention (within-domain replacement at fixed math budget) that yields large gains on hard math benchmarks with minimal cross-domain cost, though the paper does not sweep replacement ratios or test the approach beyond the math domain. Open questions include whether the competitive effects persist at larger scales or with different routing architectures, whether the FastText-based structural proxy generalizes to other reasoning domains, and whether the observed expert-routing patterns are causal or merely correlational with downstream performance.
