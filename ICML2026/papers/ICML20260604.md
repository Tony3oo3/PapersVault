## Problem

Existing benchmarks for evaluating agent-user interactions capture only a narrow range of interaction types (mostly simple clarification), rely on either overly rigid rule-based or overly unconstrained LLM-based user simulators, and operate in small environments with few non-state-changing APIs. This paper addresses all three gaps by introducing AppWorld-UL, a benchmark of 516 tasks that require diverse agent-user interactions (underspecification, infeasibility, confirmation-seeking, and their compositions) within a large, stateful tool-use environment.

## Input / Output

Each task is a 4-tuple (I, S₀, E, K) where I is a natural language instruction with deliberate information gaps, S₀ is the initial state across 9 simulated apps with 475+ state-changing APIs, E is a programmatic evaluation function, and K is a set of question-answer pairs defining the user's exclusive knowledge. The agent produces API calls and user messages; evaluation yields I-TGC and I-SGC scores that require both passing all state-change assertions AND having asked every question in K (interaction recall), plus auxiliary precision and deviation metrics measuring whether the agent asked only relevant questions.

## Method

The core contribution is a perturbation-based transformation that systematically converts well-defined autonomous AppWorld tasks into user-in-the-loop variants by introducing specific, known gaps: removing critical information from instructions or adding ambiguity to state (underspecification), modifying state so the goal becomes unattainable (infeasibility), or introducing high-cost consequences requiring explicit approval (confirmation-seeking). Compositional tasks combine two or three non-conflicting perturbations. The simulated user is an LLM constrained to respond only from the knowledge set K, deflecting questions outside it, which balances naturalness with reproducibility. Because K is known by construction, the benchmark enables programmatic evaluation of interaction quality (did the agent ask all necessary questions?) in addition to task success. All 516 tasks were manually designed (~6 hours each) and validated via updated solution programs that stub the supervisor API with K's answers.

## Results

On AppWorld-UL, the best-performing system (Code Agent with Claude Opus 4.7) achieves only 48.6% I-TGC and 30.2% I-SGC overall, while the best open model (GLM 5.1 Code) reaches 38.9% I-TGC and 21.2% I-SGC. Performance drops sharply on the compositional subset (2+ interaction types), where even the best system achieves only 35.7% I-TGC and 21.3% I-SGC. An ablation with GPT-5.5 shows that providing oracle user knowledge raises TGC from 41.8% to 78.1%, while hiding all user knowledge drops it to 12.8%, confirming that agent-user interaction is the primary source of difficulty.

## Baselines & Comparisons

As a benchmark paper, AppWorld-UL evaluates multiple agent-LLM combinations rather than proposing a new method. The Code Agent scaffold consistently outperforms the Function Calling scaffold across all LLMs (e.g., Claude Opus 4.7: 48.6% vs 27.3% I-TGC; GPT-5.5: 41.8% vs 24.2%), consistent with findings from the original AppWorld. Among closed models, Claude Opus 4.7 leads overall (48.6% I-TGC), followed by GPT-5.5 (41.8%) and Qwen 3.7 Max (40.3%); among open models, GLM 5.1 is strongest (38.9% I-TGC), ahead of Kimi K2.6 (30.6%) and Deepseek v4 Pro (28.5%). All agents struggle substantially more on compositional tasks (2–3 interaction types) than on single-type tasks, with the best I-TGC dropping from ~50–62% to ~36%. The ablation study (GPT-5.5 Code) isolates interaction difficulty: oracle knowledge yields 78.1% TGC (vs 41.8% default), while hidden knowledge yields only 12.8%, showing that the need to elicit information from the user accounts for most of the benchmark's challenge beyond environmental complexity.

## Relation to Prior Work

This paper extends the AppWorld tool-use environment (Trivedi et al., 2024) by introducing a perturbation-based methodology that systematically transforms well-defined autonomous tasks into user-in-the-loop variants requiring three distinct interaction types: underspecification clarification, infeasibility communication, and confirmation-seeking. It departs from prior interactive benchmarks (τ-bench, BFCLv3, UserBench, ToolSandbox) along two axes: (1) a knowledge-constrained LLM user that balances the rigidity of rule-based simulators with the instability of unconstrained LLM users, and (2) operation in a large stateful environment with ~475 APIs across 9 apps, rather than the small, often non-state-changing environments of prior work. The perturbation approach also enables programmatic evaluation of interaction quality (whether the agent asked all necessary questions), which prior benchmarks could not support.

## Why It Matters / Open Questions

The benchmark reveals that even the strongest agent (Claude Opus 4.7 Code) achieves only 48.6% I-TGC overall and 35.7% on compositional tasks, with the scenario-level metric dropping to 21.3%—indicating that reliable user-in-the-loop interaction remains a major unsolved challenge for tool-use agents. The ablation showing a jump from 41.8% to 78.1% with oracle knowledge confirms that interaction, not environment complexity, is the primary bottleneck, a finding that should guide future agent design toward better uncertainty detection and question-asking strategies. Open questions include whether the perturbation-based methodology generalizes beyond AppWorld, how agents might be trained (rather than prompted) to improve interaction quality, and whether the knowledge-constrained user simulation adequately captures the full range of real user behavior including intent shifts and preference changes.
