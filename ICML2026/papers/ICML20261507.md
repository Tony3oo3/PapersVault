## Problem

Existing benchmarks for coding agents either focus on incremental, issue-driven code edits (SWE-Bench) or are restricted to static single-page UI-to-code reproduction (Design2Code), leaving a gap in systematically evaluating end-to-end, multimodal website development. Moreover, verification of complex, long-horizon system outcomes remains unreliable due to underspecified task definitions and insufficiently constrained evaluation procedures, making reproducible assessment of functional correctness and visual fidelity across diverse implementations an open challenge.

## Input / Output

Each task provides prototype images at multiple device resolutions (desktop, tablet, mobile), textual specifications ranging from brief inter-page descriptions (Level 2, ~1K tokens) to structured product requirement documents (Level 3, ~4.3K tokens), and a multimedia resource library of images, icons, videos, and fonts. The benchmark produces two primary scores per task: a Functional Score (FS), computed as the proportion of passed functional verification nodes across expert-designed test workflows, and a Visual Score (VS), computed as the average of component-level fidelity scores assigned by a VLM judge comparing rendered pages against reference prototypes. A Deployment Success Rate (DSR) is also reported as a reference metric.

## Method

Vision2Web introduces a workflow-based agent verification paradigm that formalizes end-to-end testing as a directed dependency graph, where nodes are self-contained verification sub-procedures and edges encode sequential dependencies and shared application states. Functional verification nodes are 3-tuples (objective, guided actions, validation criteria) executed by a GUI agent verifier (instantiated with GLM-4.6V via the WebVoyager protocol), while visual verification nodes invoke a VLM-based judge (Gemini-3-Pro-Preview) that performs component-level comparisons against prototypes using a structured 5-level scoring rubric. The benchmark itself is constructed from C4 validation-set websites through a three-stage pipeline (structural DOM assessment, VLM-based content screening, and manual review), yielding 193 tasks across 16 subcategories. Test workflows are annotated via a three-stage expert-in-the-loop pipeline combining human drafting, Claude Code-assisted refinement into executable objective-action-validation structures, and human quality control, with design principles that decouple dependent test nodes to limit error propagation while integrating related validations to reduce redundant setup.

## Results

Under the OpenHands framework, Claude-Opus-4.5 achieves the strongest overall performance across all three hierarchical levels, with a static webpage average of 53.4, interactive frontend VS/FS of 46.5/66.7, and full-stack VS/FS of 38.4/57.6. Gemini-3-Pro-Preview leads on static webpages (55.8 avg) but drops sharply to VS 11.7 and FS 22.6 on full-stack tasks, illustrating the progressive difficulty across levels. Performance degrades consistently for all agents as complexity increases, with full-stack tasks showing the largest absolute gaps. Seed-1.8-VL and both Qwen3-VL models (32B and 8B) fail entirely on full-stack tasks (VS=0, FS=0), and Qwen models score near zero even on static webpages.

## Baselines & Comparisons

Claude-Opus-4.5 dominates on complex tasks, achieving the highest full-stack VS (38.4) and FS (57.6) under OpenHands, outperforming GPT-5 (18.3/49.7) by roughly 20 points on visual fidelity and 8 points on functional score. GPT-5 is competitive on functional correctness (FS 49.7 on full-stack, second-best) but lags significantly on visual fidelity. Gemini-3-Pro-Preview achieves the best static webpage score (55.8 avg) yet collapses on interactive and full-stack tasks (VS 29.7→11.7), revealing a sharp drop in long-horizon planning ability. Claude-Sonnet-4.5 trails Opus-4.5 by 15–20 points on full-stack metrics. Seed-1.8-VL produces near-zero scores on full-stack (VS=0, FS=0) and very low static scores (1.3 avg), while both Qwen3-VL models (32B and 8B) are effectively non-functional across all levels, scoring 0–1 on static webpages and 0 on all interactive and full-stack tasks. Under the Claude Code framework, the same ranking holds but with generally lower scores, suggesting framework choice amplifies or dampens model capabilities.

## Relation to Prior Work

Vision2Web extends the line of work on multimodal code generation benchmarks (Design2Code, WebGenBench) and agent evaluation frameworks (SWE-Bench, WebVoyager) by unifying them into a single hierarchical benchmark for end-to-end visual website development. It departs from prior static UI-to-code benchmarks by introducing progressive task complexity (static → interactive → full-stack) and from text-only website generation benchmarks by requiring multimodal prototype interpretation. The workflow-based agent verification paradigm, combining a GUI agent verifier (instantiated via WebVoyager's protocol) with a VLM-based visual judge, is a novel evaluation methodology that addresses reproducibility gaps in prior agent-based assessments.

## Why It Matters / Open Questions

This benchmark provides the first systematic, reproducible evaluation of multimodal coding agents across the full website development lifecycle, revealing that even state-of-the-art models (Claude-Opus-4.5, GPT-5) achieve only ~40-58 on full-stack tasks, exposing critical gaps in long-horizon planning, cross-page coordination, and persistent state management. The workflow-based verification paradigm offers a template for evaluating other complex, implementation-diverse software systems. Open questions include whether the dramatic full-stack performance cliff reflects true capability limits or evaluation artifacts, how agents can be improved for multi-module state consistency, and whether the hierarchical task decomposition generalizes beyond web development to other end-to-end software engineering domains.
