## Problem

Existing online benchmarks for mobile GUI agents are app-centric and task-homogeneous, failing to capture the diversity of real-world user intents (e.g., vague instructions, multi-round dialogue, dynamic GUI states, environmental noise). Additionally, they report only coarse success rates without attributing failures to specific capability deficiencies, making it difficult to diagnose bottlenecks or distinguish strong agents as scores saturate.

## Input / Output

Agents receive only GUI screenshots at 1080×2400 resolution (light mode default) as their sole perception input, paired with natural-language task instructions; the Android emulator provides the interactive environment. Outputs are structured along four axes: per-task success/failure (verified via programmatic OS-state inspection or MLLM-as-a-Judge using Qwen3-VL-30B-A3B with seven specialized judge interfaces), PUDAM dimension-wise accuracy at basic (L1-2) and advanced (L3-4) tiers, a Stability Pass Rate requiring all five variants (original, Chinese, paraphrased, dark theme, tablet 2560×1600) to succeed, and total/per-step output token counts for cost analysis.

## Method

VenusBench-Mobile adopts a top-down, user-intent-driven design spanning 10 task categories (Function Assistance, Conflict, Vague Instructions, Multi-round Interaction, GUI State Awareness, Visual GUI Manipulation, Hard GUI Browsing, Noise Resistance, Browsecomp-like, Stability Evaluation) with 149 primary tasks across 27 Android apps, built on AndroidWorld's emulator infrastructure. Each task is annotated with a PUDAM capability taxonomy (Perception, Understanding, Decision, Action, Memory), where each dimension has four progressive proficiency levels, enabling fine-grained failure attribution beyond aggregate success rates. Verification is hybrid: state-based tasks use programmatic OS inspection, while semantic/visual tasks (90 of 149) employ MLLM-as-a-Judge with seven purpose-built prompt interfaces covering fact matching, semantic coverage, conflict refusal, page locating, video content, drawing, and image editing. For closed-source models, a three-stage agentic pipeline (Action Selection → Visual Grounding via UI-Venus-72B → Execution and Summarization) is used, where the closed-source VLM acts as planner and UI-Venus-72B handles coordinate-level grounding. The Stability Evaluation subset introduces systematic perturbations (language, paraphrase, dark theme, tablet orientation) to measure brittleness under realistic distribution shifts.

## Results

On VenusBench-Mobile (149 primary tasks), the strongest agent Gemini-3-Pro+UI-Venus-72B achieves only 36.9% total success rate, while the average across all 10 evaluated agents is just 16.4%. Most open-source models fall below 15%, with the hardest categories being GUI State Awareness (2.0% avg) and Visual GUI Manipulation (4.4% avg). Under the Stability Evaluation (requiring success across all 5 environment variants), even the best model reaches only 15% Stability Pass Rate, and most agents score 0%. These results represent roughly a 50-point drop compared to performance on prior benchmarks like AndroidWorld, indicating substantially greater task difficulty.

## Baselines & Comparisons

The paper evaluates 10 agents (7 open-source, 3 closed-source) on VenusBench-Mobile. Gemini-3-Pro+UI-Venus-72B leads at 36.9% total SR, outperforming GPT-5.1+UI-Venus-72B (26.9%) by 10 points, with the gap driven primarily by Function Assistance (54.6% vs 54.6%, tied), Vague Instructions (56.3% vs 31.3%), and Noise Resistance (75.0% vs 56.3%). Among open-source models, Kimi K2.5 (24.8%) substantially outperforms UI-Venus-72B (15.4%) and Qwen3-VL-30B-A3B (8.7%), particularly on Conflict Resolution and Browsecomp-like tasks. The authors' own UI-Venus-72B ranks 7th of 10, trailing the top closed-source agent by over 21 points. On the Stability Pass Rate metric, all open-source models score 0–5% SPR, while Gemini-3-Pro reaches 15% and GPT-5.1 only 5%, revealing that even the strongest proprietary agent is highly brittle under environment perturbations (dark theme, tablet layout, Chinese instructions). The paper's central empirical claim is that these scores represent a ~50-point drop relative to the same agents' performance on AndroidWorld, demonstrating that VenusBench-Mobile exposes capabilities that prior benchmarks fail to test.

## Relation to Prior Work

This paper builds directly on AndroidWorld's dynamic Android emulator infrastructure but fundamentally repositions the evaluation paradigm from app-centric task construction to user-intent-driven task design, covering ten categories of real-world mobile usage (function assistance, conflict resolution, vague instructions, multi-round interaction, GUI state awareness, visual manipulation, hard browsing, noise resistance, and BrowseComp-like corner cases). It departs from prior benchmarks (AndroidWorld, AndroidLab, SPA-Bench, MobileWorld) that report only aggregate success rates by introducing the PUDAM capability taxonomy for fine-grained failure attribution and a Stability Evaluation subset with systematic environment perturbations (language, dark theme, tablet layout). The MLLM-as-a-Judge verification pipeline with seven specialized judge interfaces extends AndroidWorld's programmatic OS-state verification to handle semantic and visual tasks that cannot be checked by simple state inspection.

## Why It Matters / Open Questions

The benchmark reveals that SOTA mobile GUI agents suffer ~50-point success rate drops relative to prior benchmarks and achieve near-zero Stability Pass Rates under modest environment variations, exposing that current agents are far from reliable real-world deployment. The PUDAM diagnosis identifies Memory and Perception as the dominant bottlenecks—particularly at advanced proficiency levels—providing actionable targets for future research beyond simply increasing model scale. Open questions include whether dedicated state-tracking mechanisms (beyond larger context windows) can address the memory bottleneck, how to achieve robustness to visual layout shifts without retraining, and whether the agentic reasoning overhead (e.g., MA3's 3× token cost) is a fundamental barrier to edge deployment.
