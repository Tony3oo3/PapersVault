## Problem

Searching trillion-token corpora for semantically similar text patterns (allowing word substitutions, insertions, and deletions while preserving word order) remains unsolved: exact-match tools like infini-gram scale to 1.4T tokens but cannot handle paraphrases, while soft-match tools like SoftMatcha support semantic similarity but rely on inverted indexes that do not scale beyond ~50B tokens. No existing method simultaneously satisfies all three requirements of trillion-scale indexing, lexical-semantic flexibility, and word-order preservation.

## Input / Output

The system takes a short natural-language query (typically ≤10 tokens), a pre-built disk-aware staged suffix array index over the corpus, word vectors (GloVe for English, fastText for other languages), and a similarity threshold α (or alternatively a target result count K for adaptive thresholding). It returns a ranked list of semantically similar token sequences with per-pattern similarity scores and corpus hit counts; returned patterns may differ in length from the query due to insertions or deletions, and the search is exhaustive over all patterns meeting the threshold.

## Method

SoftMatcha 2 combines suffix-array-based exact matching (preserving word order with O(log|C|) lookup) with word-vector similarity to enable soft substitutions, insertions, and deletions. To curb the exponential blowup of candidate patterns, it employs dynamic corpus-aware pruning: at each token position it enumerates semantically similar extensions, then immediately filters by corpus occurrence using the suffix array, exploiting the power-law n-gram distribution so that most candidates are eliminated early. A novel disk-aware staged suffix array (sparse array Y in RAM + dense array X on disk, with run-length compression reducing the index from 56 TB to 21.6 TB) requires only one random disk access per exact lookup instead of O(log|C|), making it ~33× faster than infini-gram. The similarity function uses a smooth minimum (parameter β=10⁴) over per-token cosine similarities for substitutions, and norm-based penalties (exp(−v/γ) using Zipfian-whitened word vector norms) for insertions and deletions, so low-information words like 'the' incur smaller penalties. Theoretical analysis under Zipf's law shows the expected number of exact lookups scales as O(|C|^(1/δ)) in corpus size, and under an exponential bound on candidate set growth, the total lookup count remains O(1) in query length when the growth rate r < 1.

## Results

On FineWeb-Edu (1.4T tokens), SoftMatcha 2 achieves a p95 soft-search latency of 278.17 ms and a p95 exact-search latency of 0.34 ms, making it 33× faster than infini-gram for exact lookup. On information retrieval (TREC-COVID), it achieves P@20 = 36.0 and R@1000 = 18.0; on SciFact, P@1 = 42.7 and R@5 = 60.7; and on paraphrase detection, a score of 84.3. In contamination detection on 7 benchmarks (2,564 samples), it flags an additional 36 samples (1.4%) beyond exact matching, with 81% manual-verification precision (29/36 true positives).

## Baselines & Comparisons

Against infini-gram (Liu et al., 2024), SoftMatcha 2 is 33× faster on exact search (0.34 ms vs. 11.05 ms p95 on 1.4T tokens) and substantially outperforms it on paraphrase detection (84.3 vs. 65.5); infini-gram does not support soft search at all. Against infini-gram mini (Xu et al., 2025), SoftMatcha 2 is 475× faster at 273B tokens (0.32 ms vs. 151.84 ms), and infini-gram mini timed out during index construction on the full 1.4T corpus. Against SoftMatcha (Deguchi et al., 2025), the key advantage is scalability: beyond 1B tokens, SoftMatcha's latency grows nearly linearly while SoftMatcha 2's remains flat; on retrieval quality, SoftMatcha 2 edges out SoftMatcha on TREC-COVID (P@20: 36.0 vs. 35.4) and paraphrase detection (84.3 vs. 74.5). Against BM25, SoftMatcha 2 wins on TREC-COVID (P@20: 36.0 vs. 33.8; R@1000: 18.0 vs. 14.9), matches on SciFact P@1 (42.7), and slightly leads on SciFact R@5 (60.7 vs. 58.1) and paraphrase detection (84.3 vs. 82.8).

## Relation to Prior Work

SoftMatcha 2 sits at the intersection of two prior lines of work: (1) exact string matching at scale via suffix arrays (infini-gram, infini-gram mini) and (2) semantic (soft) pattern matching via word vectors (SoftMatcha). The key departure is combining these: suffix arrays preserve word order and scale logarithmically, while word vectors enable substitution, insertion, and deletion. SoftMatcha's inverted-index approach does not scale to trillion tokens, and infini-gram's suffix-array approach lacks any semantic flexibility. The two novel algorithmic contributions—dynamic corpus-aware pruning to tame the combinatorial explosion from semantic relaxation, and a disk-aware staged suffix array requiring a single random disk access per lookup—are the paper's core technical advances over both predecessors.

## Why It Matters / Open Questions

This work makes soft (semantic) search over trillion-token corpora practically feasible for the first time, with direct applications to LLM contamination detection, information retrieval, and paraphrase detection. The contamination-detection case study is particularly impactful: soft search uncovered 36 additional contaminated benchmark samples (81% precision) that exact matching missed, including semantic contamination and template leakage that could invalidate evaluation results. Key limitations include word-level operation (cannot capture multi-word semantic equivalences like 'U.S.' vs. 'United States'), heavy disk/memory requirements (21.6 TB index for 1.4T tokens), and theoretical bounds that depend on Zipfian and exponential-growth assumptions whose empirical validity across languages and domains remains to be fully established. Open questions include whether compositional representations (e.g., sums of word vectors) can handle multi-word semantics without destroying the low-latency guarantee.
