## Problem

Current test-time compute scaling methods allocate inference computation uniformly across all problems, fix inference strategies a priori, and use verification only to rerank completed candidates rather than to guide reasoning while it is in progress. This wastes computation on easy problems, under-explores hard ones, and prevents verification signals from dynamically selecting which reasoning tools to invoke or how much compute to allocate per problem.
![Teaser figure](../imgs/ICML20260289/cropped_page2_idx0.webp)

## Input / Output

The method takes a single math problem as input and produces a final numerical or algebraic answer extracted from the highest-scoring reasoning trajectory. Each of K=10 independent iterations generates a step-delimited trajectory (with explicit step boundaries determined by the selected tools and compute strategy), and the PRM scores every step transition (s_{t-1} → s_t) with a scalar validity score in [0,1]. The final answer is selected by maximizing the mean PRM reward across all iterations, with the answer extraction agent formatting the result from the chosen trajectory.

## Method

The framework is a training-free, verifier-guided adaptive inference agent with four hierarchical prompt-conditioned components: a planning agent that generates a high-level solution strategy, a tool selection agent that chooses a subset of reasoning tools (CoT, Self-Reflection, Numeric Verifier, Verifier, Reframer, Summarizer), a compute selection agent that jointly picks an inference strategy (Best-of-N, Beam Search, or Lookahead Search) and its exploration parameter, and an answer extraction agent. A pretrained math-specialized PRM (Qwen2.5-Math-PRM-7B) serves as a unified control signal at two levels: intra-iteration, where step-level scores guide pruning and expansion during generation (e.g., beam pruning by accumulated mean validity, lookahead rollout scoring), and inter-iteration, where aggregated trajectory rewards select the final answer across K iterations. The key distinction from prior work is that verification actively shapes which tools are invoked, which compute strategy is applied, and how generation proceeds step-by-step, rather than merely reranking a fixed set of completed candidates. Efficiency is characterized via theoretical FLOPs and a compute intensity score that penalizes redundant generation and auxiliary model overhead, showing that adaptive allocation concentrates computation on high-utility trajectories.

## Results

On MATH-500, the full Dynamic + PRM Selection method improves accuracy from 43.8% to 65.4% (+21.6 pp) for Llama-3.1-8B-Instruct and from 71.2% to 81.4% (+10.2 pp) for Qwen-2.5-7B-Instruct over direct single-pass generation. On the harder AIME24 benchmark, gains are from 3.3% to 10.0% (Llama) and 6.67% to 13.3% (Qwen), and on AMO-Bench accuracy doubles from 2.0% to 4.0% for both models. The compute-intensity score S_CI shows that the adaptive method matches the best fixed configuration's 81.4% accuracy on MATH-500 with lower S_CI (vs. 7.97×10⁻³ for CoT Best-of-N at p=10, I=10), indicating more efficient use of inference compute.

## Baselines & Comparisons

The paper does not compare against external methods but instead ablates its own framework through four progressive configurations: Direct (single-pass), Direct + PRM Selection (K=10 independent generations with PRM reranking), Dynamic (adaptive tool/compute selection in a single iteration), and Dynamic + PRM Selection (full method). PRM-based selection alone yields only marginal gains over Direct (e.g., 44.6% vs. 43.8% on MATH-500 for Llama), confirming that reranking fixed trajectories is insufficient. Adding dynamic tool and compute selection (Dynamic) provides moderate additional gains (47.2% for Llama), but the largest jump comes from combining both adaptivity and multi-iteration PRM selection (65.4%), a +18.2 pp improvement over Dynamic alone. On AIME24, no fixed tool-strategy-parameter configuration exceeds 10.0% accuracy (best: CoT Lookahead, p=5), while Dynamic + PRM Selection reaches 13.3%, demonstrating that trajectory diversity from adaptive multi-tool selection is essential for competition-level problems. The compute-efficiency analysis further shows that the best fixed configuration matching 81.4% on MATH-500 (CoT Best-of-N, p=10, I=10) requires 1.31×10¹⁴ FLOPs and S_CI=7.97×10⁻³, whereas the adaptive method achieves the same accuracy with lower compute intensity, validating selective allocation over uniform scaling.

## Relation to Prior Work

This paper builds on the test-time compute scaling paradigm (Snell et al., 2025; Brown et al., 2024) and process reward models (Lightman et al., 2024), but departs from prior work in a key way: instead of using PRM scores solely for post-hoc reranking within a fixed search procedure, it repurposes the PRM as a unified control signal that simultaneously guides intra-iteration generation (pruning/expansion of partial trajectories) and inter-iteration selection, while an LLM-based heuristic controller dynamically selects reasoning tools and compute strategies per problem. This contrasts with MCTS-style approaches (Xie et al., 2024; Guan et al., 2025) that tie verification to a predetermined search algorithm, and with learned adaptive policies (Paglieri et al., 2025; Liu et al., 2025) that require training. The framework is entirely training-free, using role-conditioned prompt templates on the same base LLM for all controller decisions.

## Why It Matters / Open Questions

The paper demonstrates that adaptive, verification-guided allocation of test-time compute substantially outperforms uniform scaling, with the largest gains on harder benchmarks (3× on AIME24), and provides a principled compute-efficiency analysis (theoretical FLOPs + compute intensity score) showing that gains come from concentrating computation on high-utility trajectories rather than redundant generation. Key limitations include reliance on a single PRM (Qwen2.5-Math-7B) whose reliability degrades on the hardest problems, a heuristic controller whose quality depends on the base model's instruction-following, single-seed evaluation, and math-only evaluation. Open questions include whether learned budget-aware policies can improve on the heuristic controller, whether difficulty-aware or multi-PRM verification can address the Level-5/AIME24 ceiling, and whether the framework generalizes to domains with sparse or non-step-level verification signals.
