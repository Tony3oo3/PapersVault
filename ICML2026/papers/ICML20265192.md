## Problem

Generalized GUI agents require large-scale, diverse interaction trajectory data spanning many applications and platforms, yet existing datasets are bottlenecked by costly manual annotation or narrow simulated environments, limiting both scale and cross-domain generalization. Internet videos contain abundant real-world GUI demonstrations but are unstructured, unlabeled, and exist at a scale (hundreds of millions of videos) that makes direct processing infeasible without an efficient filtering and annotation pipeline.
![Teaser figure](../imgs/ICML20265192/cropped_page2_idx0.webp)

## Input / Output

The pipeline ingests 500 million YouTube video metadata entries and raw video content, producing 12.7 million instruction-trajectory pairs (WildGUI) with 124.5 million screenshots across 1,500+ applications. For trajectory extraction, videos are segmented into 4-minute clips with historical context carried forward; for spatial grounding, three high-resolution frames at t−0.5s, t, and t+0.5s are extracted to handle rapid GUI state changes, and coordinates are output in relative 0–1000 space. The trained agent then consumes a screenshot plus task instruction and interaction history to predict the next action as a type-parameter tuple (e.g., click at [y,x], scroll direction+distance).

## Method

Video2GUI is a three-stage automated pipeline: (1) coarse-to-fine filtering that first uses a fine-tuned Qwen2.5-7B classifier on metadata to reduce 500M videos to ~20M, then a fine-tuned Qwen2.5-Omni scorer (trained on Gemini-3-Pro annotations) evaluates topic relevance, instruction clarity, and recording quality to retain 4.16M high-quality videos; (2) trajectory extraction where Gemini-3-Pro annotates instruction, action timestamps, low-level grounding instructions, and rationales using a sliding-window strategy with cross-segment context memory to handle long videos; (3) action spatial grounding that maps extracted actions to precise coordinates using multi-frame high-resolution inputs to overcome video compression artifacts. The resulting WildGUI dataset is used for two-stage agent training: continual pre-training (~200B tokens) with a mixed objective combining GUI grounding, action prediction, and trajectory modeling losses, followed by supervised post-training (~15B tokens) on curated open-source datasets to refine task-specific performance.

## Results

MiMo-VL-7B pre-trained on WildGUI achieves state-of-the-art GUI grounding, scoring 67.6 on OSWorld-G (surpassing Qwen3-VL-32B at 60.6 and Seed1.5-VL at 62.9) and 56.9 on ScreenSpot-Pro (second only to Seed1.5-VL at 60.9). On offline agent benchmarks, it reaches 71.4 step success rate on AndroidControl-High and 90.3 type accuracy on CAGUI, outperforming UI-TARS-7B (72.5 SR, 88.6 type acc) and OS-Atlas-7B (56.5 SR, 81.5 type acc). On online benchmarks, the full Stage 1 + Stage 2 pipeline achieves 31.9% success rate on AndroidWorld—nearly doubling the base model's 16.4%—and 12.3% on OSWorld.

## Baselines & Comparisons

On OSWorld-G, MiMo-VL-7B + WildGUI (67.6 avg) outperforms all baselines including the proprietary Seed1.5-VL (62.9), Qwen3-VL-32B (60.6), UI-Venus-7B (58.8), and UI-TARS-72B (57.1), with the largest margin over UI-TARS-72B (+10.5). On ScreenSpot-Pro, it achieves 56.9, surpassing Qwen3-VL-32B (54.9), GUI-Owl-7B (54.9), and UI-Venus-7B (50.8), but trails only Seed1.5-VL (60.9) by 4.0 points. On offline agent evaluation (Table 3), MiMo-VL-7B + WildGUI reaches 90.3 type accuracy and 71.0 step SR on CAGUI, beating UI-TARS-7B (88.6, 70.3) and OS-Atlas-7B (81.5, 55.9), while on AndroidControl-High it achieves 71.4 step SR, slightly below UI-TARS-7B (72.5) but well above OS-Atlas-7B (56.5) and Aguvis-7B (54.2). On the online AndroidWorld benchmark, the full pipeline (31.9%) substantially outperforms the Stage-2-only baseline (23.3%) and the unpretrained base model (16.4%), confirming that large-scale video-derived pretraining provides a critical foundation for generalization to dynamic environments.

## Relation to Prior Work

This paper extends the two-stage agent training paradigm (continual pre-training followed by supervised post-training) established by Aguvis and OpenCUA, but shifts the data source from manually annotated or simulated trajectories to fully automated extraction from unlabeled internet videos. It departs from prior video-to-trajectory methods (TongUI, VideoAgentTrek, MONDAY) that rely on low-level visual cues like foreground-background detection or inverse dynamics, instead using a VLM (Gemini-3-Pro) for long-horizon reasoning and intent capture, combined with a coarse-to-fine filtering strategy that scales from 500M metadata entries down to 4.16M high-quality videos. The multi-frame spatial grounding stage, which retrieves three frames around each action timestamp to overcome video compression artifacts, is a practical innovation not present in prior video-based GUI data pipelines.

## Why It Matters / Open Questions

WildGUI (12.7M trajectories, 124.5M screenshots, 1,500+ applications) represents an order-of-magnitude scale jump over existing open-source GUI datasets and directly addresses the data scarcity bottleneck that constrains GUI agent generalization. The finding that offline video-derived pre-training data generalizes to online interactive environments (nearly doubling AndroidWorld success rate) suggests a viable pathway to reducing reliance on expensive online RL for GUI agents. Open questions include whether the scaling trend continues beyond 200B tokens, the long-term quality ceiling of VLM-annotated data versus human annotation, and whether the ~$0.076/sample API cost remains prohibitive for independent research groups despite the one-time dataset release.
