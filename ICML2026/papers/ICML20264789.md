## Problem

Multi-token prediction (MTP) blocks in modern LLMs concentrate multiple output heads in the final pipeline stage, creating a severe 'tail-heavy' workload imbalance that inflates both schedule and imbalance bubbles under pipeline parallelism. Existing remedies—layer redistribution and vocabulary-dimension parallelism—either break memory budgets or introduce costly cross-stage synchronization, and neither scales gracefully as the number of MTP blocks grows.

## Input / Output

AdaHC consumes an LLM with K serial MTP blocks (each containing a transformer block and a shared output head), a pipeline parallelism configuration (PP size, schedule type such as 1F1B or interleaved 1F1B), and standard training micro-batches. It produces a Chunk Descriptor Table (CDT) that maps every transformer layer and every sequence-dimension head chunk to a specific pipeline stage and intra-stage slot, along with the trained model weights. Unusually, the output head is not treated as a monolithic operator but is decomposed into sub-tasks whose individual FLOPs are calibrated to match a single transformer layer's latency, enabling them to be interleaved with backbone layers across stages.

## Method

AdaHC rests on two observations: (1) MTP output heads have no data dependence across depths, so they can be computed in any order and placed on any stage that holds their prerequisite hidden states; and (2) partitioning an output head along the sequence dimension avoids the global all-reduce that vocabulary-dimension partitioning requires for softmax, making cross-stage distribution synchronization-free. The framework has three modules: a CDT Constructor that chunks each output head along the sequence axis into pieces whose measured latency T_OH(s) ≈ T_TF (one transformer layer) and encodes all tasks uniformly; a hierarchical CDT Planner with a dependency-aware Global Mapper (greedy stage assignment prioritizing heads near their producer layers) and a GEMM-aware Local Scheduler (fusing same-stage head chunks into a single large GEMM for GPU utilization); and a CDT Executor that handles runtime dataflow via adaptive activation piggybacking (appending required hidden states to the existing pipeline P2P payload) and bit-wise transparent loss aggregation (reinterpreting float32 loss tensors as bfloat16 pairs to piggyback on the same P2P path), preserving numerical equivalence with negligible extra communication.

## Results

AdaHC improves end-to-end training throughput by 1.35× on average across four Qwen3-family LLMs with diverse MTP configurations. In the single-MTP setting, AdaHC achieves 76.05%, 71.11%, and 41.46% throughput gains over the Naive baseline on Qwen3-30B, Qwen3-Next-80B, and Qwen3-235B respectively. In the no-MTP setting on Qwen3-8B, AdaHC still delivers a 45.24% improvement over Naive. As the number of MTP blocks scales from 0 to 2 on Qwen3-8B-L29, AdaHC's speedup over Naive grows from 21.56% to 60.08%, demonstrating that the benefit increases with MTP depth.

## Baselines & Comparisons

AdaHC consistently outperforms all three baselines across every evaluated configuration. Against the Naive baseline (Megatron-LM default with all MTP heads on the last stage), AdaHC achieves the largest gains in the multi-MTP setting (up to 76% on Qwen3-30B), where the tail-stage imbalance is most severe. Against Layer Redistribute (LR), AdaHC wins by 8–23% because LR can only move whole transformer layers and is constrained by GPU memory, whereas AdaHC's sequence-dimension head chunking provides finer-grained load balancing. Against Vocabulary Parallel (VP), AdaHC wins by 10–45%; VP's per-stage all-reduce for softmax normalization introduces communication overhead that can exceed the compute time of the head chunk itself, and in the no-MTP Qwen3-8B-L29 setting VP is actually slower than Naive. The gap between AdaHC and LR widens as the number of MTP blocks increases (from ~0% at 0 MTP to 22.95% at 2 MTP), confirming that AdaHC's advantage is specifically tied to resolving the multi-head tail-heavy problem.

## Relation to Prior Work

AdaHC builds directly on the Megatron-LM pipeline parallelism framework (1F1B and interleaved 1F1B schedules) and addresses a specific gap left by prior tail-mitigation strategies. It departs from layer redistribution (Smith et al., 2022), which moves whole transformer layers to earlier stages but is constrained by memory and coarse granularity, and from vocabulary parallelism (Tsung et al., 2025; Li et al., 2025), which partitions output heads along the vocabulary dimension but incurs heavy softmax synchronization. The key conceptual departure is identifying that MTP output heads can be losslessly partitioned along the sequence dimension (avoiding global softmax normalization) and treated as independently schedulable tasks, enabling a fundamentally finer-grained and synchronization-free pipeline mapping via the Chunk Descriptor Table abstraction.

## Why It Matters / Open Questions

As MTP becomes standard in SOTA LLMs (DeepSeek-V3, Qwen3-Next), the tail-heavy pipeline imbalance it introduces directly inflates training costs at scale; AdaHC's 1.35× average throughput improvement is practically significant for production training runs. The approach is general across MTP counts, pipeline schemes, and model architectures, and the bit-wise transparent loss aggregation keeps communication overhead negligible. Open questions include how AdaHC interacts with aggressive tensor/expert parallelism at larger scales, whether the cost-model-based chunk sizing remains accurate under dynamic workloads (e.g., variable sequence lengths), and whether the weight-replication memory tradeoff becomes prohibitive for very large vocabulary sizes or many MTP blocks.
