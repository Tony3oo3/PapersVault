## Problem

Existing LLM-driven evolutionary systems like AlphaEvolve store and reuse full-code snapshots as historical context, which is both context-inefficient (redundant implementation details consume precious token budget) and provides weak evolutionary guidance (core algorithmic ideas are entangled with irrelevant control logic). The paper formalizes this as a suboptimal M-step in an Expectation-Maximization framework and asks: how can we provide stronger directional guidance for program evolution while staying within a limited context budget?
![Teaser figure](../imgs/ICML20261908/cropped_page0_idx0.webp)

## Input / Output

The system takes a natural-language problem specification, an executable evaluator that returns a scalar score, and initial seed programs. At each iteration, the LLM receives a context window containing the parent program as full executable code (Level 3) plus 3 top-performing and 2 diverse historical nodes rendered at coarser abstraction levels (Level 1 delta summaries of ~20–40 tokens, or Level 2 structured modification plans with OLD/NEW logic contrasts and hypotheses). The output is a SEARCH/REPLACE diff applied to the parent, co-generated with its own Level 1 and Level 2 delta representations, producing an optimized program and a growing multi-level semantic delta history.

## Method

DeltaEvolve formalizes LLM-driven program evolution as an EM process (E-step: LLM samples candidate programs; M-step: system updates context from evaluation feedback) and redesigns the M-step by replacing full-code inspiration snapshots with semantic delta—structured natural-language descriptions of what changed between a parent and child program and why it improved performance. Each node in the memory bank is stored as a three-level pyramid: a concise FROM/TO delta summary (Level 1), a structured plan listing individual modifications with old logic, new logic, and a hypothesis (Level 2), and the full executable code (Level 3). A Progressive Disclosure Sampler then adaptively renders historical nodes at the appropriate abstraction level—older elites get only Level 1 summaries, recent inspirations get Level 2 plans, and the current parent gets full Level 3 code—dynamically balancing token cost against informational value. The accumulated deltas function analogously to a momentum vector in optimization, encoding the prevailing direction of improvement across iterations rather than static solution states, enabling the agent to attend to a longer and more informative evolutionary history within the same token budget.

## Results

Across five scientific domains (Black-Box Optimization, Hexagon Packing, Symbolic Regression, PDE Solver, Efficient Convolution), DeltaEvolve achieves the best or near-best objective score in all 10 model-task configurations (two LLM families × five tasks), while reducing total input token consumption by approximately 36.79% on average compared to AlphaEvolve. The most dramatic gain appears on Black-Box Optimization with Gemini-2.5-flash, where DeltaEvolve reaches a score of 3.937 versus AlphaEvolve's 2.522, using 1.23M tokens versus 1.89M. On Symbolic Regression with GPT-5-mini, DeltaEvolve scores 3.417 (vs. 3.266 for AlphaEvolve) while consuming only 810K tokens versus 1.66M—a 51% reduction.

## Baselines & Comparisons

The primary baseline is AlphaEvolve (reproduced via OpenEvolve), which stores full-code snapshots of top-k and diverse-m programs in context. DeltaEvolve outperforms AlphaEvolve on best score in 9 out of 10 model-task configurations (the sole exception being Symbolic Regression with Gemini, where scores are nearly tied at 3.2198 vs. 3.2174). The largest score gap is on Black-Box Optimization with Gemini (3.937 vs. 2.522, a 56% relative improvement), attributed to DeltaEvolve discovering a CMA-ES-based optimizer. On token consumption, DeltaEvolve wins in all 10 configurations, with reductions ranging from ~8% (Hexagon Packing, GPT-5-mini: 828K vs. 905K) to ~57% (PDE Solver, Gemini: 254K vs. 595K). Against the simpler baselines (Parallel Sampling and Greedy Refine), DeltaEvolve dominates on both metrics across all tasks, confirming that evolutionary search with semantic-delta context substantially outperforms single-shot or greedy refinement strategies.

## Relation to Prior Work

This paper builds directly on the AlphaEvolve/OpenEvolve lineage of LLM-driven program evolution, inheriting the generate-evaluate-select loop but reinterpreting it through an Expectation-Maximization lens that isolates the M-step (context construction) as the critical bottleneck. It departs from all prior evolutionary coding agents (ShinkaEvolve, GigaEvo, CodeEvolve, ThetaEvolve) by replacing full-code history with structured semantic delta and a progressive disclosure mechanism, drawing a conceptual analogy to momentum in SGD. The work also distinguishes itself from generic context-compression methods (MemoryLLM, prompt compression) by arguing that context should be constructed to be optimization-aware rather than merely shorter.

## Why It Matters / Open Questions

The ~37% token reduction while matching or exceeding baseline quality is practically significant for anyone running iterative LLM evolution, where context cost scales linearly with iteration count. The EM formalization and the ablation showing that selection policy dominates scalar feedback provide a useful theoretical grounding that was absent from the field. Open questions include whether semantic delta generalizes to non-code solution representations (symbolic proofs, molecular structures), whether the momentum analogy holds over very long evolutionary runs, and whether the multi-level hierarchy remains optimal as context windows grow.
