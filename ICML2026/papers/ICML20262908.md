## Problem

Existing LLM agent memory systems face a fundamental efficiency-accuracy trade-off: full-context retention accumulates low-entropy noise (repetitive logs, phatic chit-chat) that degrades retrieval and inflates token costs, while iterative reasoning-based filtering improves relevance but incurs prohibitive latency and token overhead. Neither paradigm achieves efficient allocation of memory and computation resources under fixed context budgets, particularly for long-horizon multi-turn interactions spanning hundreds of turns.

## Input / Output

The system ingests raw dialogue streams segmented into overlapping sliding windows of fixed length W=20, and user queries at inference time. At write time, it produces compact, context-independent memory units—self-contained factual statements with resolved entity names, absolute ISO-8601 timestamps, and structured metadata (entities, topic, salience)—each indexed simultaneously as a dense 1024-dim embedding, a sparse BM25 vector, and a symbolic metadata record in LanceDB. At query time, it outputs a deduplicated, token-efficient context (typically 530–580 tokens vs. ~16,900 for full-context) that grounds the final answer.

## Method

SimpleMem is a three-stage pipeline grounded in semantic lossless compression, inspired by Complementary Learning Systems theory. Stage 1 (Semantic Structured Compression) uses an implicit generative gating mechanism where the LLM's extraction capability inherently discards low-density windows (empty output = discard, no explicit threshold), then performs a unified De-linearization Transformation in a single pass that jointly resolves coreferences, converts relative temporal expressions to absolute timestamps, and atomizes dialogue into self-contained facts. Stage 2 (Online Semantic Synthesis) consolidates related fragments into unified abstract representations during the write phase (e.g., merging 'User wants coffee' + 'User prefers oat milk' + 'User likes it hot' into one entry), maintaining a compact memory topology without asynchronous background maintenance. Stage 3 (Intent-Aware Retrieval Planning) uses the LLM as a reasoner to infer latent search intent, generate optimized queries for each of the three index views (semantic, lexical, symbolic), and estimate an adaptive retrieval depth d that scales the candidate limit n; parallel multi-view retrieval results are merged via set union with ID-based deduplication, avoiding complex linear weighting while preserving strong signals from any view.

## Results

On LoCoMo with GPT-4.1-mini, SimpleMem achieves an Average F1 of 43.24, outperforming the strongest baseline Mem0 (34.20) by 9.04 points and the full-context LoCoMo baseline (18.70) by 24.54 points, while consuming only 531 tokens per query versus ~16,900 for full-context methods (≈32× reduction). On LongMemEval-S, SimpleMem reaches 76.87% average accuracy with GPT-4.1-mini, surpassing LightMem (68.67%) and Mem0 (59.81%). The largest per-category gain is in Temporal Reasoning (58.62 F1 vs. 48.91 for Mem0), and on smaller models (Qwen3-8b) SimpleMem still leads with 33.45 Average F1 versus 25.80 for Mem0.

## Baselines & Comparisons

SimpleMem outperforms all seven baselines on LoCoMo (GPT-4.1-mini) in Average F1. Against the closest competitor Mem0 (34.20 F1, 973 tokens), SimpleMem gains +9.04 F1 while using 45% fewer tokens (531). Versus A-Mem (32.58 F1, 2,520 tokens), the gap is +10.66 F1 with 4.7× lower token cost. Full-context baselines LoCoMo (18.70) and MemGPT (18.51) are surpassed by +24.5 and +24.7 F1 respectively, with ~32× token savings. LightMem (24.63 F1) trails by 18.61 F1, while ReadAgent (7.16) and MemoryBank (5.46) are far behind. On LongMemEval-S, SimpleMem (76.87%) beats LightMem (68.67%) by 8.2 points and Mem0 (59.81%) by 17.1 points, with the largest margin in Multi-Session retrieval (60.92% vs. 47.37% for LightMem and 30.08% for full-context).

## Relation to Prior Work

SimpleMem departs from two dominant paradigms in LLM agent memory: full-context retention (MemGPT, MemoryBank) that accumulates raw dialogue with substantial redundancy, and iterative-reasoning filtering (A-Mem, Mem0) that incurs high token costs through repeated inference cycles. Rather than building on a single prior architecture, it synthesizes ideas from complementary learning systems theory (Kumaran et al., 2016), classical information retrieval (BM25, dense embeddings, symbolic metadata), and LLM-based semantic processing into a unified three-stage compression-and-retrieval pipeline. The key conceptual departure is treating memory as an active, lossless semantic compression process at write time rather than a passive storage buffer cleaned up at read time.

## Why It Matters / Open Questions

The 30× inference-time token reduction while simultaneously improving F1 by 26.4% over the strongest baseline (Mem0) addresses a critical deployment bottleneck for long-horizon LLM agents, making lifelong memory practically viable under fixed context budgets. The rapid-saturation finding (k=3 retrieves ~99% of peak performance) suggests that high-density compressed units can replace large context windows, with implications beyond agent memory for any retrieval-augmented system. Open questions include scalability to truly multi-year interaction histories, multi-modal memory (images, audio), and whether the LLM-as-judge compression step generalizes reliably across domains without domain-specific prompt tuning.
