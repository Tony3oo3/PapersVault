## Problem

Despite rapid progress in Vision-Language Models, no unified benchmark exists for evaluating structured, controllable diagram generation and editing in professional workflows. Existing approaches rely on pixel-based synthesis that is inherently stochastic, unstructured, and prone to hallucination, making outputs difficult to edit iteratively without degradation. This paper identifies that current SOTA VLMs lack the fine-grained visual parsing and syntactic constraint satisfaction needed to produce valid, editable diagram code.
![Teaser figure](../imgs/ICML20264255/cropped_page0_idx0.webp)

## Input / Output

Task 1 (Generation) takes a raster diagram image paired with a structured JSON caption describing components, spatial layout, and topology, and produces a complete mxGraph XML document (Draw.io format) with coordinates constrained to multiples of 10. Task 2 (Editing) takes a source mxGraph XML file, its rendered image, and a natural-language instruction, and outputs a differential patch in a deterministic JSON schema containing original/modified XML fragment pairs rather than a full regeneration. The benchmark comprises 1,449 diagrams across 6 domains and 15 sub-domains, with 1,005 editing instructions derived from 335 base diagrams stratified by atomic operation count.

## Method

The paper introduces a 'Diagram-as-Code' paradigm that replaces pixel-space generation with symbolic mxGraph XML, unifying two complementary tasks under a single executability constraint: Vision-to-Code Generation and Code-to-Code Editability. For editing, an Incremental Modification Strategy predicts only localized XML fragment patches (via a deterministic JSON replacement format with fuzzy regex fallback) rather than regenerating the full document, reducing token cost and structural drift. The evaluation protocol combines five metrics across three dimensions: Execution Success Rate (programmatic parse/render check), Style Consistency Score (VLM-judged visual alignment), CodeXQA (topological QA over generated XML), SigLIP2 embedding similarity, and XDRFR (decomposed instruction-compliance verification directly on XML structure). The dataset is constructed via a two-stage pipeline—image-to-XML synthesis followed by instruction generation—filtered through parser validation, SigLIP2 rendering verification (cosine similarity ≥ 0.85), and human review, yielding 1,449 verified samples from 5,000+ candidates.

## Results

On Task 1 (Vision-to-XML Generation), Gemini-3-Pro achieves the best overall performance with SCS 0.7790, CodeXQA 0.9313, ESR 0.9626, and SigLIP2 0.9162, while open-source models collapse on executability (Qwen3-VL-32B/8B score ESR 0.0000). GLM-4.6V is the strongest open-source model on perception (CodeXQA 0.9032) but still lags on structural validity (ESR 0.7471). On Task 2 (Instruction-based Editing), all models achieve near-saturated ESR (≥0.99) and SCS (0.89–0.94), with Gemini-3-Pro leading on XDRFR (0.9405) and Qwen3-VL-235B reaching 0.9312—narrowing the closed/open gap dramatically compared to Task 1.

## Baselines & Comparisons

Among closed-source models, Gemini-3-Pro dominates Task 1 on SCS (0.7790 vs. GPT-5.2's 0.5617 and Claude-4.5-Opus's 0.6502) and ESR (0.9626), while GPT-5.2 edges ahead on CodeXQA (0.9255 vs. 0.9313 for Gemini-3-Pro, a near-tie). On Task 2, the field compresses: Gemini-3-Pro leads XDRFR at 0.9405, GPT-5.2 follows at 0.9334, and Claude-4.5-Opus at 0.9271—all within ~1.3 points. Open-source models show a stark Task 1 vs. Task 2 asymmetry: Qwen3-VL-32B scores ESR 0.0000 on generation yet achieves XDRFR 0.8873 on editing, confirming the bottleneck is visual-to-structural inference rather than code manipulation. GLM-4.6V outperforms larger Qwen3-VL models on Task 1 (CodeXQA 0.9032 vs. 0.8224 for 235B) despite fewer parameters, while Qwen3-VL-235B surprisingly reaches XDRFR 0.9312 on Task 2, surpassing Claude-4.5-Opus (0.9271). DeepSeek-V3.2 and MiniMax-M2 trail on Task 2 XDRFR (0.8928 and 0.9151 respectively), indicating weaker instruction-following precision in constrained XML patching.

## Relation to Prior Work

This paper extends the image-to-code generation line (Plot2Code, ChartMimic, Flow2Code, Draw with Thought) by shifting the target format from rasterized plots or SVG to mxGraph XML, which encodes higher-level semantic topology (nodes, edges, logical connections) rather than low-level vector geometry. It also adapts the DRFR decomposition methodology from InFoBench (Qin et al., 2024) into XDRFR for structured XML verification, and unifies generation and instruction-based editing into a single multi-domain benchmark—whereas prior benchmarks (PlotCraft, VCode, Design2Code) address only one task or a single visual domain. The closest prior work, Draw with Thought (Cui et al., 2025), reconstructs scientific diagrams into mxGraph XML but is limited to one domain and lacks an editing task.

## Why It Matters / Open Questions

The benchmark exposes a critical dissociation: models that cannot generate valid mxGraph XML from images (e.g., Qwen3-VL-32B, ESR 0.0000) can still perform high-fidelity instruction-based editing on provided XML (ESR 0.9986), revealing that the bottleneck is visual-to-structural perception rather than code manipulation. The pixel-vs-XML editing comparison (0.649 vs. 0.867 DRFR/XDRFR on Hard instructions) provides concrete evidence for the Diagram-as-Code paradigm in professional workflows. Open questions include whether findings generalize beyond Draw.io to other diagram languages (Visio, Mermaid, TikZ), whether the benchmark can capture subjective redesign or ambiguous intent, and whether the verifiable visual-code pairs can serve as effective training signal for VLM specialization.
