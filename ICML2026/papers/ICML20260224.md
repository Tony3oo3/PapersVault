## Problem

Existing agent benchmarks operate under an implicit Oracle Assumption that user instructions are always unambiguous and correctly specified, leaving a critical gap in evaluating how LLM agents handle cooperative breakdowns (missing parameters, false presuppositions, ambiguous expressions) during grounded multi-turn execution. No prior benchmark simultaneously measures multi-turn clarification quality, persona-dependent interaction dynamics, and downstream safety consequences across both transparent and opaque execution environments.
![Teaser figure](../imgs/ICML20260224/cropped_page2_idx0.webp)

## Input / Output

The benchmark takes verified tasks from AgentBench (OS/DB) and StableToolBench (G1 APIs), applies a three-phase perturbation pipeline (semantic frame extraction, fault strategy generation, fault injection) to produce four controlled fault variants per task, and feeds them to agents alongside a persona-driven LLM user simulator that receives the original intent but never the ground-truth answer. Outputs are structured as RISE scores: Performance Degradation (relative success drop), Clarification Gain (matched-pair success delta with vs. without clarification), Safe Action Rate (fraction of high-risk tasks where the agent deferred before acting), and Average Interaction Rounds (mean turns for successful completion), reported separately for state-oriented and service-oriented environments across five user personas.

## Method

DRIFT-BENCH grounds its fault taxonomy in Grice's Cooperative Principle, Austin's speech-act felicity conditions, and Watzlawick's interactional axioms, yielding four categories: Flaw of Intention (illocutionary force unrecoverable), Flaw of Premise (false presuppositions violating felicity conditions), Flaw of Parameter (missing/underspecified arguments), and Flaw of Expression (linguistic ambiguity). Agents are augmented with five structured Communication Tools (Ask_Parameter, Disambiguate, Propose_Solution, Confirm_Risk, Report_Blocker) that intercept execution and route to a persona-driven user simulator built on the GDMS framework with five decision-making styles (Rational, Intuitive, Dependent, Avoidant, Spontaneous), each with detailed psychological profiles and multi-model rotation. The dual-environment design contrasts white-box state-oriented tasks (where agents can inspect internal state to cross-reference instructions) against black-box service-oriented tasks (where agents rely solely on opaque API responses), enabling diagnosis of the Clarification Paradox: multi-turn interaction rehabilitates performance in transparent settings but degrades it in opaque settings through abandonment, clarification loops, and syntactic tool-call collapse. Task solvability is verified by requiring at least two of three reference models to succeed under oracle conditions before perturbation is applied.

## Results

Under input faults without clarification, agents suffer catastrophic performance degradation: state-oriented tasks show average PD of −49.91% (Parameter), −45.52% (Expression), −44.29% (Intent), and −40.75% (Premise), while service-oriented tasks are more buffered at −33.84% (Premise), −20.03% (Parameter), −18.13% (Intent), and −12.62% (Expression). Clarification yields positive gains on state-oriented tasks (up to +27.00% for Llama-4 on Intent faults) but triggers a 'Clarification Paradox' on service-oriented tasks, where performance drops (e.g., −25.12% for Expression). Safety is alarming: Safe Action Rate falls to ~29% for Premise and Parameter faults, meaning agents proceed with high-risk execution in over 70% of cases rather than deferring to clarify.

## Baselines & Comparisons

This is a benchmark paper, so the primary comparisons are across evaluation conditions (Oracle, NoClarify, Clarify) and across seven agent models (GPT-5.2, GLM-4.7, Gemini-2.5-Flash, GPT-OSS-120B, Qwen3, DeepSeek-v3.2, Llama-4). On state-oriented tasks, all models show near-universal ~40–50% degradation under faults, with no model escaping the fragility pattern; Qwen3 and DeepSeek-v3.2 are marginally more robust (lowest PD on Intent), while Gemini-2.5-Flash and Llama-4 are most fragile on Parameter faults (−55%). On service-oriented tasks, degradation is more heterogeneous: GLM-4.7 and Qwen3 show the smallest drops (Expression PD of only −9.24% and +9.77% respectively), while GPT-5.2 and Gemini-2.5-Flash remain highly vulnerable to Premise faults (−48.53% and −45.41%). The Clarification Paradox is model-specific: Gemini-2.5-Flash suffers 73.3% degradation under clarification on service tasks (dominated by Abandonment at 90%), Llama-4 suffers 82.0% (Clarification Loop at 73.2%), while GPT-5.2 and GLM-4.7 show <10% degradation, indicating that the paradox is not a uniform context-length artifact but a model-specific interaction between clarification policy and execution discipline.

## Relation to Prior Work

This paper extends the clarification-evaluation line (ConvAI3, AmbigQA, CLARQ-LLM, CLAMBER) from text-only, single-turn settings to grounded multi-turn agent execution, and extends agent benchmarks (AgentBench, StableToolBench, τ-Bench) by relaxing the Oracle Assumption that user instructions are always well-specified. Its theoretical grounding in Grice's Cooperative Principle, Austin's speech-act theory, and Watzlawick's interactional axioms provides a principled four-category fault taxonomy (intention, premise, parameter, expression) that unifies previously ad-hoc perturbation schemes. The persona-driven user simulator draws on the General Decision Making Style framework, going beyond the static or single-model user simulations used in prior agent benchmarks.

## Why It Matters / Open Questions

The benchmark reveals that current frontier agents suffer ~40% performance collapse under realistic input faults and exhibit a 70% execution bias toward premature high-risk actions, directly implicating agent safety in deployment. The Clarification Paradox—where enabling multi-turn dialogue helps white-box state-oriented tasks but degrades black-box service-oriented tasks through abandonment, loops, and syntactic collapse—challenges the field's default assumption that more interaction is always beneficial and points toward environment-aware clarification policies as an open design problem. Limitations include reliance on a small set of base benchmarks (AgentBench DB/OS, StableToolBench G1), a limited persona set (five GDMS types), and evaluation on a fixed set of seven models, leaving open whether the paradox generalizes to newer architectures or richer tool ecosystems.
