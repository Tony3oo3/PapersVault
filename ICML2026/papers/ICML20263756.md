## Problem

Current GUI agents operate in a model-centric, step-wise paradigm where an LLM must re-interpret the UI and re-decide actions at every screen, making long-horizon tasks fragile due to compounding errors and hallucinated actions. Existing knowledge-augmented approaches inject retrieved trajectories or element descriptions into the LLM's context, but this remains unreliable because path generation still depends on free-form generation over unstructured text rather than direct extraction from a valid state machine. The paper asks: can historical GUI interactions be compiled into a structured, executable memory that supports reliable, low-cost path retrieval instead of step-by-step generation?

## Input / Output

At inference, the system takes a natural-language user instruction and a Set-of-Mark annotated screenshot (bounding boxes from the accessibility tree overlaid with numerical labels) as input. It outputs a grounded, executable action sequence: the Q-guided MCTS extracts top-K candidate paths from the pre-built knowledge graph, and a single cloud LLM call filters and parameterizes these into a final plan that is then executed step-by-step by a local UI-TARS-2B model. The offline construction phase consumes exploration trajectories (state-action-state triples with screenshots) and produces a Neo4j-stored directed graph with alternating state and action nodes, enriched with page descriptions and action functional descriptions.

## Method

EAM comprises two stages. Offline, a state-aware DFS exploration strategy systematically covers task-relevant GUI transitions, and collected trajectories are merged into a directed acyclic knowledge graph via dual-layer state deduplication (embedding similarity + VLM verification) and transition-aware semantic mining; a BPE-inspired action-group mining procedure then compresses high-frequency multi-step action subsequences into reusable high-level action nodes, reducing search depth. Online, a lightweight Q-model (0.5B–3B with a scalar value head) steers MCTS over the KG's constrained action space using the UCT criterion, where Q-values represent the probability of reaching a successful terminal state under a uniform random policy (random policy valuation). The Q-model is trained via an iterative self-training pipeline: preference-based initialization on expert trajectories, followed by rounds of MCTS-guided data generation with soft Bellman-backup targets optimized via binary cross-entropy. The paper provides a bias-consistency guarantee on the critical set and a finite-sample complexity bound showing that the number of MCTS simulations needed to recover the optimal path scales as O(HKc²·ln(Hn/δ) / Δ_eff²), where Δ_eff is the effective action gap reduced by the Q-model's estimation error.

## Results

EAM achieves 52.6% success rate on AndroidWorld, 76.1% on MobileMiniWob++, and 86.1% on DroidTask, surpassing the SOTA on-device model UI-TARS-7B by up to 19.6 percentage points. In terms of efficiency, EAM achieves a 2.8 s average per-step latency and 8.3K API tokens per step, reducing token cost by approximately 6× compared to GPT-4o (50.8K) while maintaining competitive success rates. On the cross-platform OSWorld benchmark, EAM reaches 51.8% success rate with only 8.9K tokens per step, outperforming standalone GPT-5.2 (47.3%) and Claude-Sonnet-4.5 (42.9%).

## Baselines & Comparisons

Against UI-TARS-7B (Qin et al., 2025), EAM wins decisively on all three benchmarks: +19.6 pp on AndroidWorld (52.6 vs. 33.0), +22.8 pp on MobileMiniWob++ (76.1 vs. 53.3), and +31.1 pp on DroidTask (86.1 vs. 55.0), while also reducing per-step latency from 8.8 s to 2.8 s. Compared to M3A (Rawles et al., 2024), a GPT-4o-based ReAct agent, EAM outperforms by +12.1 pp on AndroidWorld, +7.6 pp on MobileMiniWob++, and +13.9 pp on DroidTask, despite using a 3B local model for path extraction rather than a frontier cloud LLM at every step. Against AutoDroid-V2 (Wen et al., 2025), EAM achieves substantially higher success rates (+26.6 pp on AndroidWorld, +22.8 pp on MobileMiniWob++, +31.7 pp on DroidTask) while maintaining comparable latency (2.8 s vs. 2.1 s). Against AppAgentX (Jiang et al., 2025), EAM trails on AndroidWorld (52.6 vs. 62.5) and DroidTask (86.1 vs. 88.6) but leads on MobileMiniWob++ (76.1 vs. 72.8), with a key efficiency advantage of 8.3K vs. 6.2K tokens per step. Against GUI-Explorer (Xie et al., 2025), EAM wins on AndroidWorld (52.6 vs. 47.4) but trails on MobileMiniWob++ (76.1 vs. 80.4) and DroidTask (86.1 vs. 88.0), while consuming far fewer tokens (8.3K vs. 73.1K) and achieving dramatically lower latency (2.8 s vs. 66.4 s).

## Relation to Prior Work

This paper departs from the dominant model-centric, step-wise GUI agent paradigm (UI-TARS, M3A, AutoDroid) by replacing free-form LLM generation at each screen with a structured, executable knowledge graph that constrains planning to valid state transitions. It builds on the knowledge-augmented GUI agent line (AppAgentX, GUI-Explorer, KG-RAG) but shifts from in-context retrieval and LLM reasoning over retrieved text to direct path extraction via Q-guided MCTS over the graph topology. The MCTS component adapts the UCT framework from Kocsis & Szepesvári (2006) and the LLM-MCTS reasoning literature (Zhou et al., Hao et al., ReST-MCTS*), but replaces expensive LLM rollouts with a lightweight Q-function trained via iterative self-training, and introduces BPE-inspired action group mining to compress the search space.

## Why It Matters / Open Questions

EAM demonstrates that grounding GUI planning in an executable state machine rather than free-form generation can close much of the gap between small on-device models and frontier LLMs (a 3B model outperforming GPT-4o-based M3A by 7.6–29.1 points) while cutting token costs by ~6×, making long-horizon GUI automation practical for on-device deployment. The theoretical guarantees (bias consistency on the critical set and finite-sample path recovery bounds) are rare in the GUI agent literature and provide a principled foundation for the Q-guided search. Key open questions include how the KG handles dynamic UI updates (the paper acknowledges this limitation), whether incremental evolution mechanisms can maintain memory freshness, and whether the cross-environment Q-model transfer observed in ablations can be made more systematic for truly novel app ecosystems.
