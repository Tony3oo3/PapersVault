## Problem

Existing search-based code generation methods (MCTS, ToT, LATS) verify candidates against a fixed, sparse set of public tests, leading to pseudo-correctness: solutions that overfit visible tests but fail on hidden corner cases. The paper identifies that the bottleneck is not the solver's generation capacity but the verification environment's inability to discriminate robust from fragile solutions, creating a survivorship bias where overfitted candidates crowd out truly correct ones.
![Teaser figure](../imgs/ICML20262516/cropped_page0_idx0.webp)

## Input / Output

The method takes a natural language problem description P and a small set of public test cases (|T_pub| = 5) as input at inference time, with no access to hidden tests or ground-truth outputs. It produces a single code solution C* selected via hierarchical re-ranking: first by public test pass rate, then by pass rate on the dynamically accumulated adversarial test suite T_global. The entire pipeline is inference-time only, using the same backbone LLM (e.g., Qwen3-4B/8B) for both the Solver and Attacker agents, with no parameter updates.

## Method

ADVERMCTS formulates code generation as a minimax game between a Solver MCTS (searching over chain-of-thought trajectories to synthesize executable code) and an Attacker MCTS (searching for discriminative test inputs conditioned on the evolving Code Pool). The Attacker employs Divergence-driven Multi-sample Test Synthesis (DMTS): it generates k candidate test inputs and rewards those that cause output disagreement among pool members, since no ground truth is available at test time. An LLM-based Output Arbiter adjudicates divergent outputs to label valid corner cases, which accumulate in a Global Test Filter that acts as a progressively stricter hard constraint. Feedback is dual: the Solver receives penalty signals (−V) backpropagated to thought nodes whose generated code fails adversarial tests, while the Attacker receives divergence rewards reinforcing productive attack strategies. At inference, the final candidate is selected by two-stage re-ranking (public integrity, then adversarial robustness), effectively resolving ties among pseudo-correct solutions that overfit the sparse public tests.

## Results

On APPS (Qwen3-4B-Instruct), ADVERMCTS achieves 72.77% average Pass Rate and 49.67% Pass@1, outperforming the strongest baseline MCTS-Thought (69.34% / 43.44%) by +3.43 and +6.23 points respectively. On TACO, ADVERMCTS reaches 74.44% Pass Rate and 38.00% Pass@1 versus RethinkMCTS's 72.48% / 33.67%. With the Qwen3-8B backbone, ADVERMCTS similarly leads with 61.13% APPS Pass Rate and 36.00% Pass@1, and 63.94% TACO Pass Rate and 28.00% Pass@1. Gains are most pronounced on the hardest splits (APPS-Competition: 64.45% vs 61.13% for RethinkMCTS; TACO-Hard: 22% vs 18% Pass@1).

## Baselines & Comparisons

ADVERMCTS outperforms all four baselines across both backbones and both benchmarks. Against PG-TD (token-level lookahead), ADVERMCTS gains +7.67 APPS Pass@1 and +3.00 TACO Pass@1 with Qwen3-4B, and +11.67 / +4.67 with Qwen3-8B, confirming that token-level myopic planning is insufficient for competition-level problems. Against RethinkMCTS (the strongest single-agent MCTS baseline), ADVERMCTS leads by +6.00 APPS Pass@1 and +4.33 TACO Pass@1 (4B), with the gap narrowing to +4.33 / +2.67 on 8B, suggesting the adversarial mechanism adds the most value when the base model is weaker. Against ToT (hierarchical plan-then-code search), ADVERMCTS achieves +9.00 APPS Pass@1 and +4.00 TACO Pass@1 (4B), showing that structured two-layer search without adversarial verification still leaves pseudo-correct solutions unfiltered. Against LATS (MCTS with self-reflection in code space), the margin is largest: +11.00 APPS Pass@1 and +8.00 TACO Pass@1 (4B), indicating that code-level search with reflection alone cannot compensate for the absence of active vulnerability discovery.

## Relation to Prior Work

This paper extends the MCTS-based code generation lineage (LATS, MCTS-Thought, RethinkMCTS, PG-TD) by introducing a second, adversarial search agent that operates in parallel with the Solver. While prior methods like CodeT generate auxiliary tests and ATGen performs adversarial test generation, both treat test creation as a one-shot or training-time activity; ADVERMCTS instead couples test discovery to the evolving code pool at inference time via a minimax-style interaction. The divergence-driven test synthesis and LLM-based arbiter mechanism depart from static verification (public tests only) and from majority-voting heuristics, positioning the work at the intersection of adversarial robustness and test-time compute scaling.

## Why It Matters / Open Questions

The paper provides empirical evidence that pseudo-correctness—solutions overfitting sparse public tests—is a primary bottleneck in competition-level code generation, and that actively hardening the verification environment at test time is more compute-efficient than brute-force rollout scaling (ADVERMCTS at N=16 beats baselines at N=32 with fewer tokens). Limitations include reliance on an LLM arbiter for ground-truth adjudication (79.88% validity, still leaving ~20% mislabeled tests) and the inherent blind spot of divergence-based rewards when all pool members agree on an incorrect output. Open questions include whether the dual-agent framework extends to multi-file or repository-level code generation, non-Python languages, and whether the adversarial pressure can be distilled into a learned verifier to reduce inference cost.
