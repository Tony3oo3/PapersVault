## Problem

When fine-tuning code-generation LLMs on datasets where each problem admits multiple verified correct solutions, it is unclear which solutions to retain under a per-problem budget. Conventional coreset-selection wisdom suggests diversity-maximizing or difficulty-ranking strategies should outperform naive random sampling, but this assumption has not been systematically tested in the multi-solution code SFT setting.
![Teaser figure](../imgs/ICML20262858/cropped_page0_idx0.webp)

## Input / Output

Each training instance pairs a natural-language problem description (from LeetCode) with a pool of up to 100 deduplicated verified Python solutions; the selection task picks k=11 solutions per problem from this pool. The fine-tuned model then takes a problem description as input and generates executable Python code, evaluated via Pass@k (k∈{1,2,3,5,10}) with n=10 samples at temperature 1.0 on 228 held-out problems.

## Method

The paper systematically compares six proxy-objective selection strategies—K-Center (minimax distance), Facility Location (submodular similarity), K-Means (embedding clustering), AST Coverage (structural pattern maximization), Kernel Herding (MMD minimization), and IFD Ranking (instruction-following difficulty)—against uniform random sampling, across four 7–8B base models and a 32B model, using CodeBERT embeddings, token-level Levenshtein, Jaccard, and AST-fingerprint distances as needed. The key finding is that random sampling achieves competitive or superior Pass@1 across all models with zero selection overhead, while complex methods show inconsistent, model-dependent behavior. The authors interpret this through 'implicit knowledge consensus': verified solution pools already encode representative algorithmic patterns, so random sampling preserves the natural distribution whereas diversity objectives introduce selection bias toward atypical boundary implementations. Boundary analyses (difficulty stratification, constraint-focused subsets, budget scaling, and distance-metric ablations) delineate when complex selectors add value—primarily for hard-tail or constraint-heavy evaluations.

## Results

Across four base models (Qwen2.5-7B, Qwen2.5-Coder-7B, Llama-3.1-8B, DeepSeek-Coder-6.7B), random sampling with a per-problem budget of k=11 achieves Test Pass@1 of 6.32%, 5.57%, 4.04%, and 3.68% respectively, and Test Pass@10 of 19.30%, 19.30%, 14.04%, and 12.72%. Random attains the best Test Pass@1 on two of four models (Qwen2.5-7B and Llama-3.1-8B) and remains within 0.5–1.0 percentage points of the best complex method on the remaining two. On Qwen2.5-7B, random sampling (Test Pass@10 = 19.30%) even matches the Full Dataset upper bound (20.18%) while using only ~1/6 of the training compute. Multi-seed analysis (5 seeds) confirms Random's mean Test Pass@10 of 18.07% exceeds every complex selector, with K-Center (14.82%) and IFD Ranking (14.21%) trailing by over 3 points.

## Baselines & Comparisons

K-Center (Sener & Savarese, 2018) and IFD Ranking (Li et al., 2024) are the weakest baselines, consistently trailing Random by 2–4 points on Test Pass@10 across all four models (e.g., K-Center 16.23% vs. Random 19.30% on Qwen2.5-7B; IFD 11.40% vs. 19.30%). AST Coverage (Du et al., 2025) similarly underperforms Random on every model, with the largest gap on Llama-3.1-8B (11.40% vs. 14.04% Test Pass@10). Facility Location (Cornuéjols et al., 1990) and K-Means (Lloyd, 1982) are the closest competitors: Facility Location edges out Random on Qwen2.5-Coder-7B (20.61% vs. 19.30% Test Pass@10) and DeepSeek-Coder-6.7B (15.79% vs. 12.72%), while K-Means slightly leads on Llama-3.1-8B (16.23% vs. 14.04%). Kernel Herding (Chen et al., 2010) is competitive on Qwen2.5-7B (18.42% vs. 19.30%) and outperforms Random on DeepSeek-Coder-6.7B (17.54% vs. 12.72%), but lags on the other two models. Overall, no complex selector uniformly dominates Random; the best method shifts by architecture, whereas Random remains within 1 point of the best on 3 of 4 models with zero selection overhead.

## Relation to Prior Work

This paper repurposes established coreset selection and active learning techniques (K-Center, Facility Location, K-Means, Kernel Herding, AST Coverage, IFD Ranking) for a specific sub-problem that prior data-selection work has not addressed: choosing among multiple verified correct solutions for the same problem, rather than selecting which problems to include. It departs from the conventional assumption in coreset literature that diversity-maximizing objectives should uniformly outperform random sampling, and instead frames random sampling as a competitive default that preserves implicit algorithmic consensus in verified solution pools. The evaluation protocol builds on standard Pass@k metrics from code generation benchmarks and SFT training pipelines, but the selection unit (per-problem solution subset) is the distinguishing contribution.

## Why It Matters / Open Questions

The practical takeaway is significant: practitioners fine-tuning code LLMs on multi-solution datasets can default to random sampling, saving the computational overhead of embedding generation, pairwise distance computation, or proxy-model inference required by complex selectors. The boundary analyses (hard-tail difficulty, constraint-focused subsets, Pass@10 at 32B scale) clarify when complex selectors add value, providing a decision framework rather than a blanket recommendation. Key limitations include restriction to Python algorithmic problems with verified solutions, models up to 32B parameters, and a single dataset; generalization to other languages, single-solution or unverified corpora, and larger models remains open.
