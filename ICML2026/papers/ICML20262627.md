## Problem

Most LLM-based repository-level APR methods reconstruct repair reasoning independently for each issue, relying on forward exploration under outcome uncertainty that incurs substantial inference overhead and can drift from the correct patch. Although real-world repositories contain many related issues with shared structure and constraints, existing approaches fail to reuse successful reasoning patterns from prior verified repairs, and indiscriminate reuse risks introducing misleading analogies.

## Input / Output

ConRAD takes a target bug issue description, the repository's directory structure and file contents, and a pool of historically resolved issues (with verified patches, modified file paths, and timestamps) from the same repository. It produces three stage-wise distilled reasoning plans (file-level, function-level, patch-level) that are injected as in-context guidance into an existing repair scaffold (e.g., Agentless), which then generates a SEARCH/REPLACE code patch. The method operates entirely at inference time with no fine-tuning, and when the Exemplar Guardian rejects a retrieved exemplar, the system falls back to the unmodified scaffold without any injected guidance.

## Method

ConRAD distills reusable, outcome-conditioned repair reasoning from historically verified fixes through a three-stage pipeline. Stage 1 (Repository-Level Exemplar Mining) retrieves candidate historical bugs from the same repository using All-MiniLM-L6-v2 cosine similarity followed by an LLM-as-a-judge semantic alignment assessment over five dimensions, selecting a single most-aligned exemplar. Stage 2 (Exemplar Guardian) applies a conservative LLM-based filter with a structured rubric across five criteria (root-cause similarity, causal-chain transferability, fix-strategy applicability, contextual alignment, debugging-technique relevance) to classify the exemplar as Transferable, Non-transferable, or Misleading, with a one-step self-reflection for stability. Stage 3 (Backward Reasoning Distillation) reconstructs reasoning by conditioning autoregressive generation on the exemplar's issue description and ground-truth outcome for each sub-task (file, function, patch), then refines each step via local re-conditioning against surrounding context and the full set of verified outcomes, selecting the best of three candidate rewrites per step. The key distinction from forward-search methods (e.g., MCTS) is that BRD conditions on a known-correct terminal state, yielding globally consistent plans with 9.71× fewer LLM calls and 2.47× fewer tokens than a controlled MCTS baseline.

## Results

On SWE-Bench Lite, ConRAD achieves 37.7% Pass@1 with GPT-4o (vs. 27.3% for Agentless, its execution scaffold), 40.0% with GPT-5 (vs. 29.7%), and 35.6% with DeepSeek-V3 (vs. 27.0%). ConRAD also improves fault localization, reaching 77.0% file-level and 59.3% function-level accuracy with GPT-4o, surpassing the best prior method (MASAI at 75.0%/56.3%). In a controlled ablation, ConRAD's backward distillation outperforms an MCTS-based forward-search baseline by +13.0% Pass@1 while using 9.71× fewer LLM calls and 2.47× fewer tokens per issue.

## Baselines & Comparisons

ConRAD outperforms all seven baselines on Pass@1 across every base model tested. With GPT-4o, ConRAD (37.7%) beats the strongest competitor SWE-Search (31.0%) by 6.7 points and its direct scaffold Agentless (27.3%) by 10.4 points; it also surpasses MASAI (28.0%), AutoCodeRover-v2 (30.6%), MoatlessTools (25.0%), AutoCodeRover (22.7%), OpenHands (22.0%), and SWE-Agent (18.3%). With GPT-5, ConRAD improves over Agentless from 29.7% to 40.0% (+10.3%), and with DeepSeek-V3 it raises Pass@1 from 27.0% to 35.6% (+8.6%), also outperforming MoatlessTools (30.7%) by 4.9 points. On fault localization, ConRAD achieves the best %File (77.0%) and %Func (59.3%) among all GPT-4o methods, exceeding MASAI (75.0%/56.3%) and MoatlessTools (73.3%/52.0%). The paper further reports that ConRAD uniquely resolves 10 issues missed by all four strongest GPT-4o baselines (AutoCodeRover-v2, MASAI, MoatlessTools, Agentless), indicating complementary coverage rather than merely overlapping fixes.

## Relation to Prior Work

ConRAD builds on the reverse-engineered reasoning paradigm from Wang et al. (2025a), which showed that conditioning generation on a known-correct terminal state yields more coherent rationales than forward sampling, and adapts this idea from open-ended text generation to code-grounded, stage-wise repair planning. It departs from the dominant forward-exploration paradigm (MCTS, iterative refinement, multi-trajectory search) by replacing outcome-uncertain search with backward distillation from verified patches, and from retrieval-based or memory-based APR methods that transfer surface-level patterns by instead distilling structured, causally consistent reasoning plans. The execution scaffold (Agentless) and the LLM-as-a-judge / meta-prompting mechanisms for exemplar filtering are drawn from the broader agentic APR and prompt-engineering literature, but the three-stage pipeline (mining → conservative filtering → backward distillation) is a new architectural composition.

## Why It Matters / Open Questions

ConRAD offers a practical, fine-tuning-free inference-time technique that converts historically verified fixes into reusable reasoning guidance, achieving ~10% absolute Pass@1 gains across three LLM backbones while using roughly 10× fewer LLM calls than a matched MCTS baseline—making it attractive for cost-sensitive deployment. Key limitations include reliance on in-repository historical fixes (sparse-history projects may lack exemplars), evaluation restricted to Python on SWE-Bench Lite, and dependence on LLM judgment quality for both filtering and distillation. Open questions include whether the approach generalizes to multi-language or multi-repository settings, whether it degrades gracefully when ground-truth patches are unavailable (e.g., in production), and whether the distilled plans can be cached and amortized across many target issues to further reduce per-issue overhead.
