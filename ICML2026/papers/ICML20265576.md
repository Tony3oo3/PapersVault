## Problem

Test suites in widely used code-repair benchmarks like SWE-Bench Verified are derived from development pull requests designed to verify a specific patch, not to discriminate among all possible correct and incorrect solutions. This creates systematic coverage gaps and semantic blind spots that allow semantically incorrect patches to pass, inflating reported success rates—the paper shows 19.78% of previously accepted patches from top-30 leaderboard agents are actually wrong.

## Input / Output

The framework consumes each SWE-Bench instance (issue description, gold patch, original test suite comprising base and patch tests, and the full repository source code) and produces a single reusable augmented test suite per instance. Unlike per-agent approaches such as PatchDiff, the output is a fixed test suite independent of any particular agent submission, enabling one-time strengthening and repeated evaluation. The pipeline operates on Python (SWE-Bench Verified, 500 instances) and multi-language code including JavaScript, Go, and TypeScript (SWE-Bench Pro, 150 sampled instances), with language-specific coverage tools (coverage.py, Istanbul/nyc, Go's built-in profiler, V8 coverage) feeding a unified coverage representation.

## Method

SWE-ABS is a two-stage adversarial strengthening pipeline. Stage I (coverage-driven augmentation) uses intraprocedural program slicing via Tree-sitter to compute patch-relevant lines through bidirectional def-use propagation, then generates LLM-based tests targeting uncovered regions; a test-decoupling module generalizes assertions to avoid binding to gold-patch-specific implementation details. Stage II (mutation-driven adversarial strengthening) synthesizes plausible-but-incorrect mutant patches via LLM that pass existing tests, applies multi-LLM majority-voting to filter for issue relevance and semantic equivalence, then identifies false-positive mutants (non-equivalent patches that pass) and false-negative mutants (equivalent patches that fail). For each false-positive mutant, targeted adversarial tests are generated to reject it; for false-negative cases, overly strict tests are relaxed. The final suite combines coverage-guided tests, generalized tests, and new discriminative tests, achieving a 50.2% instance strengthening rate (25.1× over UTBoost) and reducing the top agent's score from 78.80% to 62.20%.

## Results

On SWE-Bench Verified (500 instances), SWE-ABS strengthens 251 instances (50.2%), a 25.1× improvement over UTBoost (10/500, 2%), and rejects 2,184 of 11,041 previously passing patches (19.78%). The top agent's resolve rate drops from 78.80% to 62.20% (−16.60 pp), with an average drop of 14.56 pp across all 30 leaderboard agents and 30 rank changes (Spearman ρ = 0.82 vs. 0.98 for UTBoost). Cross-benchmark evaluation on SWE-Bench Pro (150 instances) yields a comparable 64.7% strengthening rate and 16.46 pp average drop, confirming that task difficulty and test discriminativeness are orthogonal.

## Baselines & Comparisons

Against UTBoost (Yu et al., 2025), the prior state-of-the-art test augmentation method for SWE-Bench, SWE-ABS achieves a 25.1× improvement in strengthening rate (50.2% vs. 2% of instances) and rejects 20.8× more incorrect patches (2,184 vs. 105). The average resolve-rate drop is 14.56 pp under SWE-ABS versus only 0.70 pp under UTBoost, and the Spearman rank correlation drops from 0.98 to 0.82, indicating that UTBoost's augmented tests barely perturb leaderboard rankings while SWE-ABS exposes substantial evaluation instability. Against the concurrent PatchDiff approach (Wang et al., 2025), which generates differential tests by contrasting each agent patch against the gold patch, SWE-ABS attains a comparable resolve-rate drop but produces a single reusable test suite rather than requiring per-agent test regeneration, making it more practical for ongoing leaderboard evaluation. SWE-ABS also achieves 16× better cost efficiency than UTBoost ($4.98 vs. $80.00 per strengthened instance).

## Relation to Prior Work

This paper extends the test-augmentation line initiated by EvalPlus (for HumanEval/MBPP) and UTBoost (for SWE-Bench), which demonstrated that PR-derived test suites are insufficient for discriminating correct from incorrect patches. SWE-ABS departs from UTBoost's single-stage LLM test generation by introducing a two-stage adversarial pipeline: program-slicing-guided coverage augmentation (a classic software-engineering technique repurposed for benchmark hardening) followed by LLM-based semantic mutation testing, which borrows the red-team/blue-team paradigm from security testing. Unlike the concurrent PatchDiff approach, SWE-ABS produces a single reusable test suite rather than per-agent differential tests, and unlike prior mutation-testing work that uses syntactic operators, it synthesizes plausible-but-incorrect patches via LLMs to target semantic blind spots specifically.

## Why It Matters / Open Questions

The finding that 19.78% of previously accepted patches are semantically incorrect and that the top-ranked agent drops from 1st to 5th place has immediate practical consequences for anyone relying on SWE-Bench Verified leaderboard rankings. The counterintuitive result that task difficulty and test discriminativeness are orthogonal (SWE-Bench Pro is harder yet has comparably weak tests) challenges the implicit assumption that more challenging benchmarks automatically provide better evaluation signals. Key limitations include a 10.6% false-negative rate from gold-patch overfitting, reliance on intraprocedural slicing that may miss cross-module dependencies, and the requirement for a reference implementation. Open questions include whether continuous co-evolution of benchmarks and agents can maintain discriminative power over time, and whether strengthened test suites can serve as training signals to reduce the 'teach to the test' behavior observed in current agents.
