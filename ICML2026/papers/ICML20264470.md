## Problem

Prior work shows that translating problems into solver-executable code outperforms end-to-end natural-language reasoning on algorithmic tasks, but the comparison conflates two changes simultaneously: the intermediate representation (NL vs. code) and the execution mechanism (LLM forward pass vs. external runtime). Without an intermediate route that changes only one factor at a time, it is impossible to determine whether the performance gain comes from the structured code representation, the reliability of deterministic execution, or both.

## Input / Output

Each task instance is specified by an algorithm, input variables, and a random seed, drawn from a 40-task set spanning arithmetic, dynamic programming, graph algorithms, string algorithms, geometry, sorting, and NP-hard optimization (1,113 unique instances across 3 seeds). All routes enforce structured JSON outputs, and the Python 3 runtime in Route 3 has access to SciPy, NumPy, pandas, PuLP, and PyTorch. Performance is measured under 0-1 loss against externally verifiable ground-truth answers, with difficulty controlled by a parameter τ (digit length, table dimensionality, or constraint matrix size).

## Method

The paper introduces a three-route framework that decomposes each pipeline into a trace generator and an executor, enabling pairwise comparison by holding one stage fixed. Route 1 (NL CoT + LLM reasoning) and Route 2 (code generation + LLM simulation of that code) isolate the representation effect, while Route 2 and Route 3 (same code + Python execution) isolate the execution effect. Empirically, Route 1 and Route 2 are statistically indistinguishable (+0.15pp, CI [−0.30, +0.61]), while Route 3 exceeds Route 2 by +31.47pp (CI [+29.20, +33.71]), pointing to execution rather than representation as the bottleneck. A linear decision-theoretic model with a shared-core/nuisance decomposition proves that code is representation-non-inferior to natural language when NL adds only mean-zero surface variation, and a reconstruction intervention (translating code traces back to NL via a matched translator model) empirically confirms that code-derived NL traces recover native-NL accuracy, validating the theory outside the linear regime.

## Results

On a 40-task verifiable algorithmic benchmark (1,113 instances, 6 models, 3 seeds), Route 1 (direct NL reasoning) achieves 17.21% accuracy, Route 2 (code generation + LLM simulation) achieves 17.37%, and Route 3 (code generation + Python execution) achieves 48.84%. The Route 2 vs. Route 1 gap is only +0.15pp (95% CI [−0.30, +0.61], McNemar p=0.39), indicating no meaningful representation advantage. Route 3 exceeds Route 2 by +31.47pp (95% CI [+29.20, +33.71]), with the execution-win mass at 33.08% versus a recovery mass of only 1.61%.

## Baselines & Comparisons

The paper's central comparison is between three internally defined routes rather than external baselines. Route 2 (code + LLM simulation) is statistically indistinguishable from Route 1 (direct NL reasoning), with a paired gap of only +0.15pp and a non-significant McNemar p-value of 0.39, ruling out code representation as the source of any advantage. Route 3 (code + deterministic Python execution) dominates both language-based routes by a wide margin: +31.47pp over Route 2 and +31.63pp over Route 1, with extremely tight confidence intervals. This pattern holds across all six evaluated models (Claude Haiku 4.5, GPT-4o-mini, Gemini 2.0/2.5 Flash, Mixtral-8x22b, Codestral-2508) and across complexity strata from O(1) to NP-hard. The reconstruction intervention (translating code traces back to NL) further confirms that code retains all decision-relevant information, with translated-NL and native-NL accuracy showing overlapping confidence intervals. The paper concludes that the tool-use advantage in algorithmic reasoning is attributable to reliable external execution, not to the structured code representation itself.

## Relation to Prior Work

This paper builds on the neuro-symbolic integration and LLM tool-use literature (PAL, Toolformer, LogicLM) that has empirically shown code-execution pipelines outperform end-to-end natural-language reasoning on algorithmic tasks. However, prior comparisons (Route 1 vs. Route 3) confound two factors—trace representation and execution mechanism—making it impossible to attribute the performance gap to either. The paper's methodological contribution is the three-route framework with an intermediate 'code + LLM simulation' route that isolates these factors, combined with a decision-theoretic sufficient-statistic model (drawing on classical statistical decision theory and nuisance-parameter analysis) to formalize when code representation is non-inferior to natural language.

## Why It Matters / Open Questions

The practical takeaway—that the code representation itself is not the bottleneck, but reliable external execution is—directly informs the design of tool-augmented LLM systems: investment should go into robust execution environments rather than into making code traces 'better representations.' The three-route framework is a reusable methodological template for disentangling representation from execution in future agentic evaluations. Open questions include whether the result extends to open-ended or weakly-specified tasks where natural language may carry decision-relevant signal, whether frontier reasoning models (only partially covered here) change the picture, and whether the linear sufficient-statistic theory can be extended to non-linear, high-dimensional LLM regimes beyond the reconstruction intervention.
