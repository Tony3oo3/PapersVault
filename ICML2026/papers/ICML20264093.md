## Problem

Existing memory mechanisms for software engineering agents operate at instance granularity, treating the entire problem-solving episode as the atomic unit of storage and retrieval based on global task similarity. This creates a fundamental granularity mismatch: tasks with similar surface descriptions (e.g., 'Fix Login Button' vs. 'Fix Login Timeout') require entirely different reasoning at specific stages, while globally dissimilar tasks may share reusable subtask-level skills. The paper demonstrates that this mismatch causes both reasoning interference from irrelevant retrieval and missed opportunities for experience transfer.

## Input / Output

The agent receives a codebase and issue description as the task, and at each subtask boundary queries the accumulated memory state S_sub (a set of structured triples: functional category z, structured description d with objective and keywords, and abstracted experience e). Retrieval is Top-1 within a category-filtered candidate pool using cosine similarity on embeddings of the description field. The primary output is a code patch; the secondary output is a new memory entry appended to S_sub after each subtask completes, where the experience field contains only transferable insights with repository-specific noise (file paths, instance-specific details) filtered out by an LLM-based extractor.

## Method

The method decomposes the agent's reasoning trajectory into discrete subtasks labeled by functional categories (ANALYZE, REPRODUCE, EDIT, VERIFY), with segmentation driven by the agent's own transition predictions embedded in the system prompt. Memory storage, retrieval, and update are all aligned to this subtask granularity: each entry is a triple (z, d, e) where the category z serves as a hard filter during retrieval, and the description d (containing a structured objective and mechanism-level keywords) is matched semantically against stored anchors to select the Top-1 relevant experience. Upon subtask completion, an LLM-based extractor evaluates correctness, distills transferable insights (distinguishing successful patterns from failure-avoidance strategies), and filters out instance-specific noise before appending the new entry to the memory state. The entire mechanism operates at test time with no parameter updates, using the same LLM backbone for both task-solving and experience extraction, and accumulates experience online in a streaming protocol over the benchmark.

## Results

On SWE-bench Verified (500 instances), the proposed Subtask-level Memory improves Avg. Pass@1 by +4.7 pp on average over the Vanilla Agent across four backbones, with the largest gain of +6.8 pp on Gemini 2.5 Pro (53.5% → 60.3%) and +5.6 pp on Gemini 2.5 Flash (36.3% → 41.9%). On Claude 3.7 Sonnet the method achieves 56.1% Pass@1 (+3.9 pp), and on Claude 4.0 Sonnet 65.8% (+2.3 pp). Gains are more pronounced on harder tasks: Pass@1 on Hard instances (>28 steps) increases by +8.7 pp (35.5% → 44.2%), while Easy tasks see only +1.8 pp. On FEA-Bench Lite (feature implementation), the method transfers with a +3.3 pp gain (15.3% → 18.6%) on Gemini 2.5 Flash.

## Baselines & Comparisons

The paper compares against two baselines: (1) the Vanilla Mini SWE Agent (Yang et al., NeurIPS 2024) without any memory, and (2) Instance-level Memory, a faithful reproduction of ReasoningBank (Ouyang et al., 2025) that stores and retrieves whole-episode reasoning summaries via global semantic similarity. The proposed Subtask-level Memory outperforms both baselines on all four backbones. Against the Vanilla Agent, gains range from +2.3 pp (Claude 4.0 Sonnet) to +6.8 pp (Gemini 2.5 Pro). Against Instance-level Memory, the advantage is particularly notable on the Claude family: ReasoningBank actually degrades Claude 3.7 Sonnet from 52.2% to 51.1% (with high variance ±2.27) and stagnates Claude 4.0 Sonnet at 63.3%, whereas the subtask-level method lifts both to 56.1% and 65.8% respectively, while also reducing run-to-run variance (e.g., σ drops from 2.27 to 1.33 on Claude 3.7 Sonnet). On Gemini models, Instance-level Memory is closer to the proposed method (e.g., 55.1% vs. 60.3% on Gemini 2.5 Pro), but the subtask-level approach still leads by 5.2 pp. Ablations confirm that the gains come from the memory content itself (+3.9 pp) rather than the structured prompting alone (+1.0 pp), and that category isolation contributes an additional +2.3 pp over global retrieval.

## Relation to Prior Work

This paper extends the memory-augmented SWE agent line initiated by ReasoningBank (Ouyang et al., 2025), which stores and retrieves entire problem-solving episodes based on global task-description similarity. The key departure is a granularity shift: instead of treating the full trajectory as the atomic memory unit, the method decomposes reasoning into functional subtasks (ANALYZE, REPRODUCE, EDIT, VERIFY) and aligns memory storage, retrieval, and update to that decomposition. It builds on the Mini SWE Agent scaffold (Yang et al., 2024a) and the broader agent-memory literature (MemGPT, Reflexion, generative agents), but specifically targets the compositional structure of repository-level bug fixing that prior instance-level approaches overlook.

## Why It Matters / Open Questions

The finding that instance-level memory actively degrades performance on stronger models (Claude 3.7 Sonnet drops from 52.2% to 51.1%) while subtask-level memory consistently helps across all four backbones provides a concrete, well-evidenced argument that memory granularity must match reasoning granularity. The complexity-dependent gain (+8.7% on Hard vs. +1.8% on Easy tasks) and the temporal accumulation curve suggest the approach is particularly valuable for long-horizon, multi-step engineering tasks where trial-and-error is costly. Open questions include lifelong memory maintenance (the current append-only state has no forgetting or consolidation), whether the four-category taxonomy generalizes beyond bug fixing, and how to handle noisy or causally incorrect extracted memories at scale.
