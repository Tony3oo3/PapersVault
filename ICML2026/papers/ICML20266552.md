## Problem

Current AI safety mechanisms—data filtering, alignment, and output guardrails—assume attackers cannot access or modify models, an assumption that collapses with open-weight releases and declining compute costs. AI agents fundamentally alter the economics of cyber attacks by automating vulnerability discovery and exploitation across thousands of targets at near-zero marginal cost, yet defenders lack the offensive security intelligence to predict how these attacks will unfold at scale. The paper argues the AI community has failed to adopt the offensive security perspective (penetration testing, red teaming) that the cybersecurity community has long relied upon.

## Input / Output

The proposed framework consumes software codebases and projects deployed within dynamic execution environments (e.g., Docker containers replicating real systems), supplemented by vulnerability databases and attack playbooks distilled from real-world incidents targeting different kill-chain stages. The offensive agent operates exclusively inside audited cyber ranges with strict network isolation and least-privilege tool access, producing comprehensive attack trajectory logs as intermediate artifacts. Final outputs are defensive-only: patches, detection signatures, regression tests, and specialized defensive agents distilled from offensive findings, which can be safely released to the broader software ecosystem.

## Method

This position paper proposes a three-part framework: (1) comprehensive benchmarks covering the full attack lifecycle per MITRE ATT&CK and the cyber kill chain, featuring dynamic execution environments, security-specific tools (static/dynamic analysis, fuzzers), and multiple system variations; (2) advancing offensive agents from the current workflow stage (prompting with external orchestration of Ghidra, network scanners, exploit frameworks) to trained agents via reinforcement learning in cyber ranges, where exploit success/failure provides direct, measurable reward signals; (3) a governance architecture combining capability-tiered version control, restriction of offensive agents to audited cyber ranges with human-in-the-loop review, and distillation of offensive findings into defensive-only agents. The core mechanism is an offense-to-defense pipeline: offensive agents discover and validate vulnerabilities in containment, security researchers review exploit traces and validate findings, and the resulting knowledge is translated into deployable defensive outputs. The paper explicitly maps this progression onto the software engineering agent trajectory (SWE-agent workflow → SWE-RL trained agents) as the template for offensive security agent development.

## Results

This is a position paper with no proposed method, so it reports SOTA agent performance across existing security benchmarks rather than comparing a new approach. Key SOTA numbers include: 49% on CyberSecEval-3 (attack generation), 54.5% on AutoPenBench (penetration testing), 12.5% on CVE-bench (real-world vulnerability exploitation), 55% on CyBench (CTF), 77.8% on VulnLLM (vulnerability detection), 28.9% on CyberGym (PoC generation), and 78.8% on SWE-bench-Verified (patching). The paper highlights a critical asymmetry: agents perform well on small-scale generative tasks (e.g., patching short functions at 78.8%) but struggle with large-scale analytic tasks requiring whole-project understanding (e.g., PoC generation at 28.9%, CVE-bench exploitation at 12.5%).

## Baselines & Comparisons

As a position paper, this work does not propose a new method and therefore does not compare against baselines in the traditional sense. Instead, it surveys SOTA agent performance across 11 security benchmarks to argue that current capabilities are insufficient for full-lifecycle attack simulation. The paper identifies specific gaps: exploit chaining and command-and-control steps are entirely uncovered by existing benchmarks, vulnerability detection labels are noisy (PrimeVul at only 12.9%), and real-world exploitation remains far from reliable (CVE-bench at 12.5%). The authors contrast workflow-based agents (current state, e.g., PentestGPT, EnIGMA) with the proposed trained-agent paradigm (e.g., Project Glasswing, Trusted Access for Cyber), arguing the latter is necessary to match AI-driven attacker scale. No head-to-head method comparisons are presented; the quantitative evidence serves to motivate the governance and benchmarking recommendations rather than to validate a specific system.

## Relation to Prior Work

This position paper departs from the dominant AI-safety framing (data governance, alignment, guardrails, access controls) by arguing these model-centric safeguards are structurally insufficient against AI-agent-driven attacks, and instead draws on the long-standing security practice of red teaming and penetration testing as the template for AI-era defense. Methodologically, it maps the offensive-security-agent progression (knowledge models → workflow agents → trained agents) directly onto the software-engineering agent lineage established by SWE-agent (Yang et al., 2024) and SWE-RL (Wei et al., 2025), and proposes cyber ranges (Ferguson et al., 2014) as the verifiable training substrate analogous to SWE-Gym. It positions itself alongside existing agentic offensive systems (PentestGPT, EnIGMA) and defensive systems (VulnLLM, RepoAudit, Locus, PBFuzz) but argues that none of them close the offense-to-defense loop at the scale and autonomy that AI agents will require.

## Why It Matters / Open Questions

The paper's central claim—that offensive AI capability should be treated as essential defensive infrastructure rather than a safety risk to be suppressed—could reshape how AI labs and national security organizations allocate research resources toward agentic cybersecurity. Key open questions remain: whether the proposed governance (versioned capability tiers, audited cyber ranges, offense-to-defense distillation) can actually contain leakage at scale, whether trained offensive agents will generalize beyond curated cyber-range environments to in-the-wild systems, and whether the offense-to-defense pipeline can operate fast enough to close the vulnerability window before adversaries exploit the same capabilities. The paper itself concedes (Section 5) that data scarcity, tool-specificity, and OOD robustness make training expert-level offensive agents substantially harder than the software-engineering analogy suggests, and that capability diffusion risks may outweigh defensive gains if governance fails.
