## Problem

Existing agentic benchmarks treat tool calls as atomic and stateless, are confined to single vendor ecosystems with fewer than 25 database tables and under 50 tools, and largely omit explicit evaluation of policy compliance and safe refusal. This leaves a critical gap in measuring whether LLM agents can perform long-horizon, stateful, policy-constrained planning in realistic enterprise settings where actions are irreversible and errors propagate silently across interconnected systems.
![Teaser figure](../imgs/ICML20263196/cropped_page0_idx1.webp)

## Input / Output

Agents receive a natural-language task instruction, a system prompt encoding domain-specific policies and access-control rules, and a set of tool API schemas, then interact with a containerized sandbox containing 164 interconnected relational database tables (averaging 3,443 rows per task) and 512 functional tools. Success is determined by hand-written SQL verification scripts that simultaneously check four dimensions: goal completion, referential integrity (foreign-key constraints), permission and process compliance, and absence of unintended side effects. Notably, 30 of the 1,150 tasks are deliberately infeasible, requiring the agent to refuse cleanly without modifying any system state.

## Method

ENTERPRISEOPS-GYM is a fully interactive, containerized Docker environment spanning eight enterprise domains (CSM, HR, ITSM, Email, Calendar, Teams, Drive, and cross-domain Hybrid), with 164 relational database tables (mean FK degree 1.7) and 512 tools—an order of magnitude larger than prior enterprise benchmarks. Tasks are authored by 160+ domain experts through a multi-stage pipeline: scenario design with explicit complexity thresholds, ground-truth execution to capture gold trajectories, natural-language plan authoring, and hand-written SQL verification scripts, followed by multi-round QA including automated stress-testing against frontier LLMs to discard trivial or ill-defined tasks. Evaluation uses a standard ReAct loop under oracle tool access (perfect retrieval assumed), reporting pass@1 averaged over three runs. Key ablations decouple planning from execution: adding distractor tools has negligible impact (~1% change), while providing human-authored plans improves performance by 14–35 percentage points, and multi-agent decomposition with subtask splitting actually regresses performance due to strong sequential state dependencies. The central finding is that strategic, constraint-aware planning—not tool invocation proficiency—is the dominant bottleneck for current frontier models, with the best model (Claude Opus 4.5) achieving only 37.4% overall success.

## Results

On ENTERPRISEOPS-GYM (1,150 tasks, 8 enterprise domains, 512 tools, 164 DB tables), the best model Claude Opus 4.5 achieves only 37.4% pass@1 task completion under oracle tool access. Gemini-3-Flash (31.9%) and GPT-5.2 High (31.8%) follow, while the strongest open-source model DeepSeek-V3.2 (High) reaches 24.5%. Performance degrades monotonically with planning horizon (from ~35% at 4 steps to <20% by step 16 for closed-source models), and infeasibility detection remains weak across all models (best: 53.9% for GPT-5.2 Low).

## Baselines & Comparisons

This is a benchmark paper, so the 'baselines' are 14 frontier LLM agents evaluated under a unified ReAct interface with oracle tool access. Claude Opus 4.5 leads overall at 37.4%, outperforming Gemini-3-Flash (31.9%) by 5.5 pp and the best open-source model DeepSeek-V3.2 High (24.5%) by 12.9 pp. Domain-specific leaders differ: GPT-5 tops CSM (36.4%), Gemini-3-Flash tops ITSM (28.5%), and Claude Sonnet 4.5 leads Teams (51.0%) and Drive (52.1%), but no single model dominates all eight domains. ITSM (best 28.5%) and Hybrid cross-domain tasks (best 30.7%) are the hardest settings for all model families, while collaboration domains (Email, Teams, Drive) are comparatively easier (best 51–52%). On infeasibility detection, GPT-5.2 Low achieves the highest refusal rate (53.9%), but all models fall well below production-safe thresholds. Structurally, ENTERPRISEOPS-GYM exceeds all prior enterprise benchmarks (Table 1) in scale: 164 DB tables vs. ≤25, 512 tools vs. ≤46, and 1,150 expert-curated tasks with human-authored plans and SQL-based outcome verification—dimensions where prior benchmarks like WorkArena (7 tables, 30 tools), CRMArena-Pro (25 tables), and EnterpriseBench (17 tables, 46 tools) are an order of magnitude smaller.

## Relation to Prior Work

This paper carves new ground at the intersection of three existing benchmark families: general tool-use evaluations (API-Bank, ACEBench, τ-bench), single-vendor enterprise benchmarks (WorkArena, CRMArena, ITBench), and agentic planning suites (OSWorld, WebArena, TheAgentCompany). Rather than building on a specific method, ENTERPRISEOPS-GYM unifies and extends these by introducing a multi-domain, stateful relational environment (164 tables, 512 tools) with explicit policy constraints, infeasibility tasks, and outcome-based SQL verification—dimensions that prior enterprise benchmarks either omit or treat shallowly (fewer than 25 tables, under 50 tools, single-vendor scope). The ReAct-style agent loop and planner-executor ablations follow standard agentic evaluation practice, but the diagnostic framing (decoupling planning from execution, testing refusal behavior) is a deliberate methodological departure from prior work that typically conflates tool retrieval with task completion.

## Why It Matters / Open Questions

The benchmark's central diagnostic finding—that strategic planning, not tool retrieval or execution, is the binding constraint (human plans yield 14–35 pp gains while distractor tools are harmless)—redirects research effort toward constraint-aware plan generation rather than tool-discovery architectures. The infeasibility detection results (best model: 53.9% clean refusal) expose a concrete safety gap for any unsupervised enterprise deployment, and the monotonic performance decay with horizon length quantifies the long-standing error-accumulation problem in multi-step agents. Open questions include whether episodic memory or structured state representations can break the horizon-length ceiling, whether smaller models conditioned on good plans can serve as cost-effective executors in production, and how to train agents to reliably detect and refuse policy-violating requests without over-refusing feasible ones.
