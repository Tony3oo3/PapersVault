## Problem

Current coding benchmarks overstate LLM capabilities because static, human-curated problems are vulnerable to data contamination and allow models to exploit statistical shortcuts rather than demonstrate genuine algorithmic reasoning. Existing augmentation approaches (variable renaming, background rephrasing) only perturb surface-level features without altering the underlying reasoning graph topology, so they cannot distinguish true logical understanding from memorized problem patterns. UniCode addresses this by introducing a generative framework that systematically restructures the reasoning graph through multi-dimensional augmentations, exposing a 31.2% performance collapse that static benchmarks miss.

## Input / Output

The framework takes seed competitive-programming problems (curated from LeetCode and CodeForces, 25,000 filtered to 600 across 15 algorithmic paradigms) and LLM-generated code solutions as input. It produces 492 augmented problem variants spanning five reasoning axes, each accompanied by a 50-case test suite (20 random, 20 adversarial, 10 corner inputs) with verified ground-truth outputs. Evaluation outputs include Pass@1 scores across three difficulty tiers, per-axis performance breakdowns, and a fine-grained error taxonomy (modeling error, complexity error, logic bug, indexing/caching bug, other) that decomposes each failure into its root cause.

## Method

UniCode applies two families of augmentation operators to seed problems: Atomic augmentations (narrative perturbation, rule modification, efficiency scaling) that alter individual task facets, and Compositional augmentations (sequential composition, concept fusion) that chain or merge distinct algorithmic concepts to disrupt fixed solution patterns. Ground-truth test outputs are constructed via a three-stage stress-driven pipeline: (1) a brute-force solver validates optimized candidate solutions on small inputs to filter correlated failures, (2) surviving solvers are majority-voted on large-scale inputs where brute-force is infeasible, and (3) a high-reasoning LLM adjudicates remaining disagreements. This pipeline achieves 94.5% correctness and 86.0% coverage at $0.041 per problem, validated against human-curated Test-Eval. The evaluation further introduces a diagnostic layer that prompts LLMs to categorize each failure by error type, revealing the 'seed-problem regression' phenomenon where models revert to memorized seed logic rather than adapting to augmented constraints.

## Results

On the UniCode benchmark (492 problems), the top-performing model o4-mini (high) achieves 70.3% Pass@1, while the weakest model llama-3.3-8b-instruct scores only 5.5%. Performance collapses sharply on the Hard split, where several models (qwen3-coder, gpt-4o, qwen-2.5-32b-coder, gemma-3-27b-it, llama-3.3-8b-instruct) record 0.0%. The stress-driven test generation pipeline achieves 94.5% correctness and 86.0% coverage at a marginal cost of $0.041 per problem, and the overall evaluation reveals a 31.2% average performance drop from seed problems to augmented variants across all 19 evaluated LLMs.

## Baselines & Comparisons

Against rStar-Coder (Liu et al., 2025), UniCode's full stress-driven pipeline achieves 94.5% correctness and 86.0% coverage on the Test-Eval dataset, substantially outperforming rStar-Coder's MajVote(Unfiltered) baseline of 86.9% correctness and 80.2% coverage; the brute-force filtering stage alone contributes a +7.1% correctness gain by eliminating correlated failures. For alignment validation, UniCode shows a strong positive Pearson correlation (r > 0.9) with LiveCodeBench (Jain et al., 2024), confirming that its generative evaluation faithfully tracks an established contamination-free benchmark. Against LiveCodeBenchPro (Zheng et al., 2025), UniCode exhibits a strong negative correlation (r < −0.9), which is expected given that LiveCodeBenchPro uses a ranking-based scoring convention (lower is better) while UniCode uses a higher-is-better Pass@1 metric. In Table 5, model rankings on UniCode (o4-mini-generated) and an independent deepseek-r1-generated set show near-identical ordering (Pearson r = 0.984, p = 4×10⁻⁴), ruling out significant generator self-preference bias.

## Relation to Prior Work

This paper departs from two prior lines of work: (1) static coding benchmarks (HumanEval, APPS, LiveCodeBench) that are vulnerable to data contamination and fixed design patterns, and (2) perturbation-based robustness evaluations (GSM-Symbolic, GSM-Plus, RUP-Bench) that apply only surface-level variations like variable renaming or narrative rephrasing while leaving underlying logic intact. UniCode's key conceptual departure is treating augmentation as a structural operation on the reasoning graph topology—altering rule operators, scaling efficiency constraints, and fusing disparate algorithmic concepts—rather than a cosmetic perturbation. For test generation, it builds on the stress-testing and majority-voting ideas from rStar-Coder but adds a brute-force oracle filtering stage and LLM adjudication, achieving higher correctness (94.5% vs. 86.9%) without human-authored solutions.

## Why It Matters / Open Questions

The identification of 'seed-problem regression'—where models revert to memorized seed logic rather than adapting to altered constraints—provides a concrete diagnostic for distinguishing genuine reasoning from pattern recall, a distinction that static benchmarks cannot make. The 31.2% average performance collapse and up-to-61% variance across reasoning axes challenge the reliability of single-score coding benchmarks and suggest that current SOTA models have narrow, axis-specific competencies rather than general code intelligence. Key open questions include whether models will eventually memorize the augmentation distribution itself (a new form of contamination), and whether the stress-driven pipeline can scale to deeply compositional problems where brute-force verification becomes infeasible. The framework's practical value is high: it offers a contamination-resistant, continuously expandable evaluation space with fine-grained error diagnostics at a marginal cost of ~$0.04 per problem.
