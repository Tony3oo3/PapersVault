## Problem

Automatic loop invariant generation for memory-manipulating programs remains a critical bottleneck in program verification, as existing approaches—whether symbolic, learning-based, or LLM-based—are predominantly designed for and evaluated on numerical benchmarks and fail to synthesize precise shape invariants involving separation logic predicates. The core difficulty is that memory state evolution is implicit in source code, making it hard for LLMs to reason about heap-allocated structures without explicit traces of how memory layouts change across loop iterations.

## Input / Output

The method takes a C source function with a loop-invariant hole, along with symbolic execution traces and bounded loop-unrolling states (K=4 iterations) produced by the QCP engine, and QCP verification feedback (error type, location, pre-failure symbolic state, and disproved entailments) during refinement. The output is a loop invariant expressed in separation logic—conjoining pure arithmetic constraints with a separating conjunction of spatial predicates (e.g., data_at, lseg, IntArray::ceil_shape)—that, when inserted into the program, passes formal verification. For multi-loop functions, invariants are generated in a dependency-tree post-order to respect symbolic execution flow.

## Method

MALICE is a two-stage framework that grounds LLM reasoning in symbolic execution traces to generate shape invariants. The Prediction stage decomposes invariant synthesis into three sequential LLM calls: (1) Abstract Reduction, where a CoT chain identifies memory regions and maps them to separation-logic predicates; (2) Memory Assertion Abstraction, using either Reduction on a Single Assertion (folding concrete heap segments from a deep unrolling state into recursive predicates) or Generalization on State Traces (aligning multiple unrolling states to discover shared spatial structure); and (3) Pure Property Inference via hypothesize-and-verify against all branch-specific trace states. The Refinement stage is an agentic loop (up to 10 iterations) where QCP verifies the candidate, and on failure the LLM first interprets the error log in natural language to diagnose the root cause, then produces a concrete revision. A key design choice is using loop-unrolling information to make memory evolution explicit, enabling the LLM to discern inductive regularity that is invisible in static source code. An SFT variant distills successful ICL refinement trajectories to fine-tune Llama-3.1-8B with LoRA, achieving 86.15% pass rate—surpassing the 685B ICL variant.

## Results

On the LIG-MM+ benchmark (260 memory-manipulating C programs), MALICE achieves 82.69% Pass Rate@8 with in-context learning (ICL) and 86.15% with supervised fine-tuning (SFT) of an 8B model for the refinement stage. The SFT variant using Llama-3.1-8B surpasses the ICL variant using the 685B DeepSeek-V3.2 backbone. A Full-8B configuration (Qwen3-8B for prediction + Llama-3.1-8B for refinement) reaches 81.54%, confirming the framework's effectiveness is not solely due to model scale.

## Baselines & Comparisons

MALICE substantially outperforms all three baselines on the LIG-MM+ benchmark. Against AutoSpec (Wen et al., CAV 2024), which achieves 0.00% because it was designed for numerical programs and cannot handle memory-aware verification, MALICE (ICL) reaches 82.69%. Against SLING (Le et al., PLDI 2019), a traditional SMT-based separation logic approach that achieves 26.15% but cannot handle continuous address offsets for arrays, MALICE gains 56.54 percentage points. Against LIG-SE (Liu et al., NeurIPS 2024), the strongest baseline at 41.92% using CodeGen-350M with self-supervised learning, MALICE (ICL) more than doubles the pass rate to 82.69%. Notably, even under a matched 8-LLM-call budget, MALICE achieves 59.62% versus LIG-SE's 41.92%, demonstrating that the gain comes from the prediction-and-refinement workflow rather than brute-force sampling.

## Relation to Prior Work

MALICE builds directly on the QCP symbolic execution engine (Wu et al., 2026) for separation-logic-based C verification, repurposing its trace outputs as structured context for LLM reasoning rather than as a standalone verification oracle. It departs from prior LLM-based invariant generators (AutoSpec, LIG-SE) that operate on source code alone or on self-supervised predicate expansion, by grounding the model in explicit symbolic state sequences that make memory evolution visible. The agentic refinement loop with tool feedback extends the generate-then-check paradigm of Clause2Inv and AutoSpec into an iterative diagnosis-and-correction workflow, while the SFT distillation of refinement trajectories introduces a training paradigm not present in prior LLM-invariant work.

## Why It Matters / Open Questions

Shape invariants remain the primary bottleneck for verifying memory-manipulating programs, and MALICE's 82–86% pass rate on LIG-MM+ (versus 42% for the best prior LLM-based method) substantially narrows this gap. The finding that an 8B model fine-tuned on refinement trajectories outperforms a 685B model using in-context learning suggests that task-specific distillation can be more effective than raw scale for narrow verification sub-tasks, a result with implications beyond this domain. Open questions include generalization to more complex or combined data structures, reducing the computational cost of up-to-10 sequential refinement calls, and scaling the benchmark beyond its current 260 programs to better reflect real-world system software.
