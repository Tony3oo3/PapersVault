## Problem

LLM-based function-call agents typically invoke tools sequentially without a global view of inter-tool dependencies, causing error accumulation and poor scalability in ecosystems with hundreds or thousands of APIs. Existing approaches are either structured but static (e.g., pre-built dependency graphs) or adaptive but unstructured (e.g., reactive policies), leaving a gap between relational representation and dynamic adaptation to API drift and failures.
![Teaser figure](../imgs/ICML20261958/cropped_page0_idx0.webp)

## Input / Output

At each decision step, the agent consumes a sliding window of the three most recent observation-action pairs, the current user observation, and a pruned tool dependency subgraph serialized into a tree-structured textual format (not a raw graph). The output is a single action from a four-dimensional space—direct response, intent clarification, toolchain retrieval, or tool execution—along with, when applicable, a target API name, parameter dictionary, or a recall description for graph-based retrieval. The TWNM itself outputs predicted link probabilities over API-parameter edges, which serve as weights for downstream graph search and path recombination.

## Method

NaviAgent decouples high-level planning from low-level execution via a bilevel architecture. At the planning level, an LLM-based agent (fine-tuned with SFT on 3,500+ curated examples) selects among four actions using a quintuple (H, O, G, A, F) formulation. At the execution level, the Tool World Navigation Model (TWNM) constructs a directed weighted heterogeneous graph over API and parameter nodes, encoding both structural chains (from API schemas) and behavioral chains (from invocation logs), and trains a two-layer Heterogeneous Graph Transformer with edge-weight-augmented attention for link prediction under a hybrid cross-entropy plus adaptive-margin loss with curriculum scheduling. At inference, predicted link probabilities drive two search strategies—Alpha-Beta backward pruning with dynamic thresholds and a heuristic search combining simulated annealing with genetic algorithms—to retrieve compact executable toolchains. A closed-loop evolution mechanism incrementally integrates new tools, prunes obsolete ones via failure-rate/frequency scoring, and updates edge weights through exponential smoothing of recent success rates, while three path-recombination strategies (I/O-equivalent substitution, upstream rerouting, subgraph switching) provide fault tolerance at runtime. The paper further provides a local variational theorem showing that mechanism injection corresponds to the KL-minimal projection of the base policy onto context-dependent feasible action sets.

## Results

On ToolBench, NaviAgent achieves 35.8%, 45.4%, and 55.2% overall TSR with Qwen2.5-14B, Qwen2.5-32B, and DeepSeek-V3 respectively, outperforming the strongest baseline (ToolNet) by 7.8, 9.0, and 10.3 points. On the hardest task split, gains reach up to 18.2 percentage points (44.9% vs. 26.7% on DeepSeek-V3). NaviAgent also maintains the fewest execution steps (4.38–4.60) among all graph-based methods, compared to 6.0–10.4 for ToolNet, ToolPlanner, and α-UMI. On 50 live RapidAPI endpoints, NaviAgent sustains 4.3–12.0 point TSR gains over the best baseline while reducing runtime.

## Baselines & Comparisons

NaviAgent outperforms all five baselines on TSR across every backbone model and difficulty level on ToolBench. Against ToolNet (the strongest graph-based baseline), NaviAgent gains 7.8–10.3 points overall and up to 18.2 points on Hard tasks (e.g., 44.9% vs. 26.7% on DeepSeek-V3). α-UMI achieves the highest TCR (task completion) but trails NaviAgent by 4.9–14.5 points in TSR while requiring 1.5–2× more steps, indicating it completes tasks but with lower output quality. ToolPlanner is the least efficient, averaging 8.5–10.4 steps versus NaviAgent's 4.4–4.7, and also lags in TSR by 12–19 points. ReAct and ToolLLM, the non-graph baselines, are weakest on Hard tasks (TSR ≤ 25%), confirming that explicit relational structure is critical for multi-tool composition. On the 50 live RapidAPI endpoints, NaviAgent extends its lead to 4.3–12.0 points over ToolNet while cutting average runtime by 8–15 seconds per task batch.

## Relation to Prior Work

NaviAgent extends the tool-graph line initiated by ToolNet (Liu et al., 2024b) and ControlLLM (Liu et al., 2024d), which model inter-tool dependencies from invocation logs, by introducing a bilevel architecture that decouples high-level action selection (direct response, clarification, retrieval, execution) from low-level graph-based toolchain construction. The Tool World Navigation Model (TWNM) departs from prior static or sparsely-updated graphs by jointly encoding structural (schema-derived) and behavioral (usage-derived) edges via a Heterogeneous Graph Transformer, and by supporting incremental node integration, targeted pruning, and edge-weight propagation for dynamic API ecosystems. The local variational projection theorem (Thm 3.1) provides a clean information-theoretic lens on how graph-conditioned feasibility constraints modify the base policy at inference time, a framing not present in prior tool-orchestration work.

## Why It Matters / Open Questions

The paper addresses a practical bottleneck—reliable multi-tool composition at scale (thousands of APIs)—and validates its approach on 50 live RapidAPI endpoints, which is uncommon in the tool-use literature. The bilevel design reduces the LLM's reasoning burden to a four-action decision while offloading combinatorial toolchain search to the graph, yielding fewer steps and lower latency than monolithic planners. Open questions remain around heterogeneous tool interfaces (e.g., MCP standardization gaps), the cost of periodic full-graph retraining, and whether the graph-based approach generalizes to multi-agent collaboration where tools are themselves agents. The SFT result showing a 14B model approaching 32B performance suggests the architecture is practical for resource-constrained deployments.
