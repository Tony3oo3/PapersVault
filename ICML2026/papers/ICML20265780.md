## Problem

Existing benchmarks evaluate code intelligence (correct program generation) and data intelligence (locating relevant information) in isolation: code-centric benchmarks assume all required data is pre-provided, while data-centric benchmarks use standalone scripts without file-system navigation. This creates a gap with real-world development, where an agent must simultaneously discover relevant data among hundreds of semantically similar files and write correct code to process it. CODA-BENCH asks whether current state-of-the-art code agents can jointly perform both capabilities in a realistic, data-intensive Linux environment.

## Input / Output

The agent receives a single natural-language analytical instruction (e.g., 'What are the top 5 most frequently assigned genres for TV shows and their counts?') and starts at the root of an isolated Linux sandbox containing an average of 980 files (ranging from 10 to 8,158) in mixed formats (CSV, JSON, Parquet, images, PDFs) with total sizes from 20.3 MB to 45.4 GB. The agent must autonomously explore the file hierarchy, identify the correct target files (averaging 1.3 per task, yielding a signal-to-noise ratio of ~1%), and produce a normalized numerical answer. Evaluation reports two metrics: Discovery Accuracy (DA), the fraction of tasks where the agent accessed exactly the ground-truth target files, and Execution Accuracy (EA), the fraction of tasks where the final answer matches ground truth after normalization.

## Method

The benchmark is constructed through three key mechanisms. First, a co-occurrence graph is built over 21,122 Kaggle datasets (93,727 edges weighted by joint notebook usage), and the Leiden algorithm partitions it into 323 communities (modularity 0.711); 31 communities are selected so that all datasets within a community serve as in-distribution distractors sharing topical similarity with the target data. Second, tasks are generated via solution-based back-construction: verifiable numerical anchors are extracted from Kaggle notebook cell outputs through static dataflow analysis and dynamic re-execution (tolerance ε=10⁻⁶), then LLM-generated questions are formulated to target those anchors without revealing the solution path. Third, an adversarial evolution framework inspired by GANs iteratively increases task difficulty: a generator LLM modifies the question while a discriminator ensemble of 3 randomly sampled LLMs (from a pool of 4) attempts to solve it, continuing until the solve rate falls below a 66.7% threshold or human verification confirms solvability. This yields 1,009 tasks (CODA-BENCH) and a 119-task harder subset (CODA-HARD) requiring multi-file integration and >30 lines of code.

## Results

On CODA-BENCH (1,009 tasks, ~980 files per environment), Mini-SWE-Agent with GPT-5.5 achieves the highest Execution Accuracy (EA) at 61.1% and Discovery Accuracy (DA) at 83.0%, while Codex CLI with GPT-5.5 follows closely at 60.3% EA. On the harder CODA-HARD subset (119 tasks requiring multi-file integration and >30 lines of code), even the best system (Mini-SWE-Agent + GPT-5.5) drops to 49.6% EA. Notably, even with oracle file paths provided, agents achieve only 71.0% average accuracy on CODA-HARD, confirming that both data discovery and code generation remain substantial bottlenecks.

## Baselines & Comparisons

The paper evaluates four agent systems/frameworks on CODA-BENCH. Mini-SWE-Agent (Yang et al., NeurIPS 2024) with GPT-5.5 achieves the best overall EA (61.1%) and DA (83.0%), outperforming OpenHands (Wang et al., ICLR 2025) with the same model by 1.4 EA points, though at the cost of 32.5 vs. 18.1 average interaction turns. OpenHands with GPT-5.5 is the most cost-competitive framework-based agent (~$0.65/task) and achieves 59.7% EA. Among open-weight models evaluated via OpenHands, DeepSeek-V4-Pro (DeepSeek-AI et al., 2025) reaches 49.0% EA in 35.8 turns, while Kimi-K2.6 (Team et al., 2026) lags at 43.8% EA despite requiring the most turns (39.4), suggesting a model-capability ceiling that additional interaction cannot overcome. A key finding is model-framework alignment: GPT-5.5 performs better in Mini-SWE-Agent (+0.8 EA over its native Codex CLI), while Claude models perform better in their native Claude Code environment (51.9% vs. 49.3% EA for Opus-4.7), indicating that scaffold-model compatibility matters for data-intensive tasks.

## Relation to Prior Work

This paper carves new ground by unifying two previously isolated evaluation axes: code-centric benchmarks (SWE-bench, HumanEval, BigCodeBench) that assume data is pre-provided, and data-centric benchmarks (DA-Code, DABstep, DS-1000) that supply oracle files and test only downstream computation. Methodologically, it repurposes graph-based community detection (Leiden algorithm) over Kaggle notebook co-occurrence patterns to generate realistic in-distribution distractors at scale, and borrows the GAN generator-discriminator framing to calibrate task difficulty via adversarial evolution with LLM ensembles. No single prior work provides the joint code+data evaluation in a shell-based, multi-hundred-file environment that CODA-BENCH introduces.

## Why It Matters / Open Questions

The benchmark reveals that even the strongest agents (Mini-SWE-Agent + GPT-5.5 at 61.1% EA) fail on roughly 40% of data-intensive tasks, and the oracle-data ablation shows data discovery alone accounts for a ~25-point accuracy gap—establishing file-system navigation as a first-class bottleneck for autonomous engineering agents. The finding that signal-to-noise ratio predicts difficulty more strongly than raw file count suggests that semantic ambiguity, not scale, is the core challenge, pointing future work toward better data-retrieval reasoning rather than simply larger context windows. Open questions include whether the gap narrows with improved retrieval-augmented agent architectures, whether the Kaggle-derived community structure generalizes to enterprise data lakes, and how to scale the adversarial evolution pipeline beyond the current 1,009 tasks.
