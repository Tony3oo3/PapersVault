## Problem

Mainstream RL post-training frameworks for LLMs (e.g., verl) rely on a centralized controller that handles both execution dispatch and massive data transport through a single node. This coupling creates a communication bottleneck that grows linearly with cluster size and data volume, causing accumulated idle time, OOM errors, and system crashes when scaling beyond a few dozen GPUs, fundamentally limiting the ability to train frontier models at scale.
![Teaser figure](../imgs/ICML20264854/cropped_page0_idx0.webp)

## Input / Output

The system consumes LLM/VLM model weights (Qwen-2.5-Instruct and Qwen-2.5-VL-Instruct at 7B, 32B, 72B), training prompts with a maximum length of 2048 tokens, and a reward function (function-based for PPO, rule-based for GRPO), producing post-trained model weights after iterative generation-evaluation-training cycles. Responses are padded to a maximum of 4096 tokens, and the system operates on colocated GPU clusters (up to 512 NVIDIA Hopper GPUs) where all RL stages share the same hardware via time-sharing. Throughput is measured in tokens per second per global batch iteration.

## Method

DISTFLOW fundamentally decouples control flow from data flow in a fully distributed architecture. Control logic is assigned to DAG Workers that execute a linearized task chain produced by a DAG Planner, which translates user-defined logical graphs into sequential execution pipelines by enforcing dependencies at equal-depth nodes to avoid resource contention in colocated settings. Data lifecycle is exclusively managed by a Data Coordinator that integrates four mechanisms: (1) a Distributed Dataloader where each GPU loads only its DP-rank shard, (2) a Distributed Databuffer (one per node) that performs parallelism-aware tensor redistribution between stages with differing TP/DP configurations, (3) a local cache that bypasses the external buffer entirely when consecutive stages share the same DP size, and (4) a Constrained LPT load-balancing heuristic that assigns variable-length sequences to least-loaded workers while enforcing equal item counts per worker for collective communication synchronization. An asynchronous double buffer with atomic pointer swap (O(1)) masks garbage collection overhead during epoch transitions, eliminating pipeline stalls.

## Results

DISTFLOW achieves 1.09x–1.64x throughput speedup over verl with PPO and up to 2.62x with GRPO across model sizes (7B–72B) and GPU counts (8–128). Scaling efficiency reaches 90.1% (7B), 93.9% (32B), and 91.8% (72B) when scaling from 32 to 512 GPUs with GRPO on VLMs. In long-context settings (7B model), the speedup grows from 1.48× at 8k tokens to 2.03× at 64k tokens. Convergence is preserved: DISTFLOW matches verl's reward and entropy curves while reducing total training time by 21% on a 32B GRPO run.

## Baselines & Comparisons

The sole baseline is verl (HybridFlow, EuroSys 2025), the current SOTA colocated RL framework. DISTFLOW outperforms verl in every tested configuration: 1.09×–1.64× with PPO and up to 2.62× with GRPO, with the gap widening as GPU count and data volume increase. Critically, verl hits OOM failures on the 72B model at 32 GPUs and at 32k context length, whereas DISTFLOW completes both tasks without issue. On the 512-GPU scalability test, verl cannot finish the linear-scaling sweep at all, while DISTFLOW maintains 90–94% scaling efficiency. Convergence is verified to be identical (matching reward and entropy curves over 20 epochs), confirming that the throughput gains come at no accuracy cost.

## Relation to Prior Work

DISTFLOW builds directly on verl (HybridFlow, EuroSys 2025), which introduced the hybrid controller paradigm for colocated RLHF training, and adopts its 3DParallelWorker API design. However, it fundamentally departs from verl's architecture by fully decoupling control flow (handled by DAG Workers) from data flow (managed by a decentralized Data Coordinator), eliminating the single-node data bottleneck that limits verl's scalability. In the broader landscape, DISTFLOW positions itself against both disaggregated architectures (OpenRLHF, StreamRL, AReaL) that suffer from pipeline bubbles, and colocated architectures (DeepSpeedChat, RLHFuse) that inherit centralized data management, offering a middle path that retains colocated efficiency while achieving distributed data governance.

## Why It Matters / Open Questions

The near-linear scalability to 512 GPUs and 2.63× throughput gain over the SOTA colocated framework address a practical ceiling that currently blocks large-scale RL post-training, with the convergence parity (21% time reduction at identical accuracy) removing the main adoption barrier. Open questions include whether the architecture extends beyond 512 GPUs or to heterogeneous clusters, how it interacts with asynchronous training strategies (which the authors deliberately exclude for convergence reasons), and whether the DAG-based control plane generalizes to more complex multi-agent or multi-reward RL formulations. The work also highlights that the centralized data bottleneck, not compute, is the dominant scaling constraint in current RL training systems—a finding that may influence future framework design.
