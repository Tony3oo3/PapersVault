## Problem

Augmented LLMs that invoke external tools during inference suffer from severe Head-of-Line blocking and degraded effective throughput under strict SLOs, because existing serving systems (vLLM, INFERCEPT) use FCFS scheduling and fixed batch-level token budgets that are agnostic to the heterogeneous, multi-stage execution behavior introduced by external calls. No prior system jointly adapts request ordering and batch capacity to the dynamically changing execution states and context-handling policies of paused requests.
![Teaser figure](../imgs/ICML20264681/cropped_page0_idx0.webp)

## Input / Output

The system consumes incoming LLM inference requests (prompts with variable lengths), external tool call responses (with highly variable return lengths and durations), and real-time GPU memory state (free blocks and reclaimable paused-request KV cache). A fine-tuned BERT-base (110M parameters) predicts output length in 50-token buckets and external call duration via regression, running off the critical path with <0.1% overhead. The system outputs per-iteration batch selection decisions, a dynamically adjusted batch-level token budget (clipped to [β_low·T_max, β_high·T_max]), and a per-request context-handling policy (Preserve, Swap, or Discard) chosen to minimize expected memory waste.

## Method

AugServe models each request as a sequence of service segments (prefill, decode, tool-wait, resumption, incremental prefill) and defines a space-time cost as the integral of GPU memory occupancy over each segment's residency duration. Scheduling priority is computed as a value-density ratio (scheduling value / space-time cost), where scheduling value balances throughput progress and waiting-time reduction via a tunable β parameter; the per-iteration batch selection is a greedy 0-1 knapsack approximation with a proven 1/2-approximation guarantee. Cost construction operates in two regimes: pre-invocation estimation using predicted call duration and output length to select the optimal context-handling policy, and post-invocation refinement that replaces predictions with realized runtime feedback (actual return length, executed policy) upon each external call return. A dynamic batch-level token budget adapts per iteration to both free GPU memory and reclaimable memory from paused requests under Swap/Discard policies, with bounded clipping to prevent instability from transient memory fluctuations.

## Results

AugServe achieves a geometric mean of 6.5× and 4.7× higher effective throughput (goodput) than vLLM and INFERCEPT, respectively, across multiple LLMs (GPT-J-6B, OPT-13B, Vicuna-13B, Llama-3-70B) and GPU platforms (RTX 4090, H800, A100). It reduces TTFT by 95.6% and 96.0% on average versus vLLM and INFERCEPT, and reduces normalized latency by 77.8% and 72.8%. Under peak load (5.0 req/s on H800/ToolBench), vLLM and INFERCEPT goodput drops to near zero while AugServe sustains 2.4 req/s.

## Baselines & Comparisons

Against vLLM (Kwon et al., SOSP 2023), AugServe achieves 6.5× higher goodput and 95.6% lower TTFT, as vLLM treats external calls as request termination and discards KV cache, forcing full recomputation upon resumption. Against INFERCEPT (Abhyankar et al., ICML 2024), AugServe achieves 4.7× higher goodput and 96.0% lower TTFT; INFERCEPT's dynamic context-handling (Preserve/Swap/Discard) reduces memory waste but its FCFS scheduling still suffers severe HoL blocking under external-call pauses. Against MARS (Shahout et al., NeurIPS 2025), a memory-based SJF scheduler that makes one-shot per-round decisions, AugServe achieves 3.07× geometric mean goodput (up to 4.78× under heavy load) and 92.1% lower TTFT, because MARS treats post-call requests as newly arriving jobs without modeling cross-round resumption costs. Against the SSJF length-based baseline, AugServe achieves 1.9× higher goodput and 92.5% lower TTFT, as SSJF ignores execution-stage heterogeneity introduced by external calls. AugServe wins on all metrics (goodput, TTFT, normalized latency) across every baseline in every evaluated configuration.

## Relation to Prior Work

AugServe builds directly on vLLM's PagedAttention memory management and iteration-level scheduling paradigm, and on INFERCEPT's dynamic context-handling policies (Preserve/Swap/Discard) for managing KV cache during external tool calls. It departs from the FCFS scheduling inherited by both systems and from length-based SJF heuristics (S3, FastServe) by introducing a state-aware space-time cost model that explicitly captures multi-stage execution heterogeneity induced by external calls. The value-density greedy packing is a standard 0-1 knapsack approximation, but its application here is novel in that the 'item weights' are state-dependent and refined across execution rounds via runtime feedback, rather than computed once at arrival.

## Why It Matters / Open Questions

As tool-using agents and MCP-standardized tool invocation become the dominant LLM serving pattern, the scheduling inefficiencies identified here (HoL blocking from paused requests, suboptimal fixed token budgets) will affect a growing share of production inference workloads. The paper's key open question is whether the lightweight BERT-based prediction module generalizes to novel or rapidly evolving tool ecosystems where call durations and return lengths are highly non-stationary. Additionally, the evaluation is limited to single-node multi-GPU setups; how the state-aware scheduling interacts with disaggregated prefill/decode architectures (DistServe, Splitwise) or with very large numbers of concurrent external calls (hundreds to thousands) remains unexplored.
