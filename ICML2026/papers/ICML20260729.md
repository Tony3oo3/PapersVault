## Problem

Code repair data is limited and costly to scale, motivating synthetic bug generation via self-play where a model both introduces and fixes bugs validated only by unit tests. However, unit tests certify correctness but not realism, so unconstrained generator-fixer self-play drifts toward valid yet unrealistic bugs, improving repair on self-generated bugs while degrading on human-authored bugs. The paper asks how to anchor open-ended self-play to realistic bug distributions without restricting the generator to predefined mutation operators.

## Input / Output

The fixer receives a natural-language task description, a buggy program (function body only), and truncated unit-test feedback (failing test names and error traces), and outputs a full corrected Python program rather than a diff, since the base model produces brittle patches. The generator receives the same task description plus a correct reference solution and outputs a modified program that compiles but fails at least one test. All BUGSOURCEBENCH instances share identical tasks and tests across bug-source splits; only the buggy program differs, enabling controlled cross-source comparison.

## Method

Anchored Self-Play (ASP) trains a single Qwen2.5-Coder-7B-Instruct model with GRPO to alternate between generating bugs (rewarded for moderate difficulty via a band-shaped fix-rate reward) and fixing them (rewarded by unit-test pass). Two anchoring mechanisms prevent distribution drift: (i) a code-embedding similarity reward that computes the kNN cosine similarity (k=5) of a generated bug's diff (embedded with voyage-code-3) to a reference bug pool, centered by a running EMA baseline to act as a relative shaping signal with weight λ=0.20; and (ii) reference mixing, which replaces the generated bug with a reference-source bug in 20% of fixer training episodes to maintain exposure to realistic patterns. The reference pool contains 900 bugs drawn equally from four sources (human, human-edited LM, Qwen-7B errors, gpt-oss-20b errors), and the generator is not updated on mixed episodes to preserve on-policy generation dynamics.

## Results

On BUGSOURCEBENCH (127 held-out tasks × 4 bug sources), ASP achieves a 36.1% average fix rate, improving over standard self-play (29.1%) by +7.0 pp absolute (+24% relative) and over fixer-only training (27.9%) by +8.2 pp absolute (+29% relative). The largest gains are on LM-sourced bugs: +12.6 pp on Qwen-7B errors (8.7%→21.3%) and +8.7 pp on gpt-oss-20b errors (12.6%→21.3%). ASP also improves on human-authored bugs relative to self-play: +1.3 pp on Human (63.7%→65.0%) and +5.5 pp on Human-Edited LM (31.5%→37.0%). On the external DebugBench benchmark, ASP reaches 60.3% fix rate vs. 58.7% for self-play and 55.0% for the base model.

## Baselines & Comparisons

ASP outperforms all three baselines on every bug source simultaneously. Against the untrained Base Model (Qwen2.5-Coder-7B-Instruct), ASP improves average fix rate by +10.3 pp (25.8%→36.1%), with the most dramatic gains on LM-generated bugs (Qwen-7B: 7.1%→21.3%, gpt-oss-20b: 7.0%→21.3%). Against Fixer-Only (frozen generator, fixer trained with reference mixing), ASP gains +8.2 pp on average, showing that the adaptive generator curriculum is essential beyond static bug sampling. Against standard Self-Play (joint generator-fixer training without anchoring), ASP gains +7.0 pp on average; critically, self-play actually degrades on Qwen-7B bugs (8.7% vs. 10.2% for Fixer-Only) and shows only marginal improvement on Human bugs, while ASP improves every source. The paper also shows that self-play's distribution drift worsens over training (Figure 4), with human-bug fix rates declining after initial gains, whereas ASP maintains stable or improving performance across all sources throughout training.

## Relation to Prior Work

This paper sits at the intersection of self-play curriculum learning (Silver et al., Bengio et al., and recent LLM self-play work) and automated program repair (BugLab, BIFI, SWE-bench). Prior bug-generation approaches constrain the edit space to mutation operators, repository history, or AST-level transformations to preserve realism; this paper deliberately studies the fully open-ended setting where the generator can apply arbitrary text edits, with unit tests as the sole correctness signal. The key departure is identifying distribution drift as a first-class failure mode in this open-ended regime and proposing a lightweight anchoring mechanism (embedding-similarity reward + reference mixing) that does not require the structural constraints used by prior work. BUGSOURCEBENCH extends the repair evaluation landscape by holding tasks fixed while varying only the bug source, enabling controlled cross-source generalization measurements that prior benchmarks (Defects4J, QuixBugs, SWE-bench) do not support.

## Why It Matters / Open Questions

The drift finding—that unit-test-verified self-play can improve on synthetic bugs while degrading on human-authored bugs—is a practical warning for anyone scaling code-repair supervision with RL and test-based rewards. The anchoring solution is sample-efficient (effective with ~50 reference bugs) and composable with existing GRPO pipelines, making it directly adoptable. However, the scope is limited to Python function-level repair with a frozen embedding proxy as the realism signal; extending to repository-level agentic repair (SWE-bench-style) or learned/preference-based bug-style critics remains open. BUGSOURCEBENCH provides a useful controlled evaluation tool, but its 127-task test set and single-language focus limit generalizability claims.
