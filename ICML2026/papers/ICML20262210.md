## Problem

Multi-table relational databases, the primary modality for enterprise data, are rarely public due to privacy constraints, leaving Relational Foundation Models (RFMs) without the diverse, large-scale pretraining data needed to unlock scaling benefits. Existing synthetic data methods either generate isolated single tables (omitting primary-foreign key connectivity) or require a real database as input, preventing the creation of novel, diverse schemas from scratch. This paper addresses both gaps by proposing a from-scratch relational database synthesizer and, for the first time, establishing scaling laws for RFMs with respect to data diversity and size.

## Input / Output

PLUREL takes only a random seed and a hyperparameter configuration (sampled from distributions over graph priors, SCM causal structures, temporal parameters, and HSBM block hierarchies) as input, requiring no real database. It outputs complete multi-table relational databases with directed schema graphs, populated foreign key columns encoding P→F row-level connectivity, and feature cells spanning numeric and categorical types with temporal correlations. A single RDB generation takes roughly 0.2–0.4 seconds per table on CPU with ~1 GB peak memory, making large-scale synthesis (up to 1024 RDBs / 32B tokens) computationally lightweight relative to downstream GPU training.

## Method

PLUREL synthesizes relational databases through three decoupled stages of increasing specificity. Stage 1 samples a directed acyclic graph from Barabasi-Albert, Reverse Random-Tree, or Watts-Strogatz priors to define the schema (table count, directed relationships, entity vs. activity types, row/column counts). Stage 2 populates foreign key columns by clustering rows of parent-child table pairs into hierarchical blocks and sampling bipartite P→F links via a Hierarchical Stochastic Block Model, controlling row-level information locality. Stage 3 generates feature cell values using per-table Structural Causal Models whose mechanisms condition on parent-table feature nodes (via foreign keys) and incorporate temporal exogenous inputs (power-law trend, sinusoidal cycle, bounded Gaussian fluctuation) to capture cross-row correlations. The key architectural insight is that this three-level abstraction—schema graph, connectivity graph, causal mechanism—allows each axis of diversity to be varied independently, enabling systematic scaling studies. Pretraining the Relational Transformer on PLUREL data with masked token prediction reveals power-law scaling in both the number of synthetic databases (diversity) and total tokens (size), with consistent zero-shot transfer to unseen RelBench tasks and up to +7.4% AUROC / +5.2% R² gains when synthetic pretraining is followed by continued pretraining on real data.

## Results

On 10 classification tasks (AUROC) and 8 regression tasks (R²) across 6 RelBench databases, PLUREL synthetic pretraining followed by continued real-data pretraining (Synthetic+Real) achieves a mean AUROC of 70.4% and mean R² of 25.7%, improving over the Real-only baseline (69.2% AUROC, 22.6% R²) by +1.2% and +3.0% absolute respectively. Gains reach up to +7.4% AUROC on rel-stack/user-engage and +5.2% R² on rel-amazon/item-ltv. Pretraining loss exhibits power-law scaling with both the number of synthetic databases (N) and total tokens (S), with the best loss requiring both axes to scale in tandem. Synthetic-only pretraining underperforms both baselines on most tasks, confirming that continued pretraining on real data is critical for distribution alignment.

## Baselines & Comparisons

The primary baseline is the Relational Transformer (RT) pretrained solely on RelBench real data in a leave-one-DB-out setting (Ranjan et al., 2026). PLUREL's Synthetic+Real approach wins on 7 of 10 classification tasks and 7 of 8 regression tasks, with the largest gains on behavior-driven tasks (user-engage +7.4% AUROC, item-ltv +5.2% R²). The method loses on 3 classification tasks (user-clicks −6.8%, user-churn/hm −1.4%, study-out −2.6%), which the authors attribute to PLUREL's lack of textual column semantics. A second comparison point, Synthetic-only pretraining, consistently underperforms both Real-only and Synthetic+Real on most tasks (mean AUROC 68.5% vs. 69.2% and 70.4%; mean R² 15.2% vs. 22.6% and 25.7%), demonstrating that synthetic data alone is insufficient for robust zero-shot transfer and that real-data continued pretraining is essential for distribution alignment. Results are robust to the choice of synthetic base model, with a weaker synthetic-only checkpoint (512 RDBs, 16B tokens) still yielding comparable or better Synthetic+Real performance, consistent with post-hoc reversal.

## Relation to Prior Work

PLUREL extends the single-table synthetic data generation paradigm established by TabPFN (Hollmann et al., 2023) and its successors from isolated tables to multi-table relational databases, introducing a three-stage pipeline that couples schema-level DAG sampling, row-level P→F connectivity via Hierarchical Stochastic Block Models (Peixoto, 2014), and conditional SCM-based feature generation. It departs from privacy-preserving relational generators (Synthetic Data Vault, GAN/diffusion-based approaches) that require a real database as input, instead synthesizing databases entirely from scratch. The framework is designed specifically to feed the Relational Transformer (Ranjan et al., 2026), which prior work had limited to only 6 publicly available RelBench databases for pretraining.

## Why It Matters / Open Questions

This is the first demonstration of power-law scaling for RFMs with respect to both data diversity (number of databases) and data size (token count), revealing that the two axes must scale in tandem—scaling only one produces non-monotonic, U-shaped loss curves. The practical implication is significant: PLUREL provides a lightweight, CPU-only, privacy-free path to generating unlimited pretraining data, potentially unblocking the data bottleneck that has constrained RFM development. Key limitations include the absence of self-referential foreign keys, lack of textual/semantic column information, and support only for numeric and categorical features; open questions span extending to richer data types, semi-synthetic augmentation of real databases, and joint model-data scaling laws.
