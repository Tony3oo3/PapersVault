## Problem

Existing cybersecurity LLM benchmarks (CTIBench, SECURE, SecBench) evaluate knowledge memorization or information extraction rather than the multi-step investigation and reasoning skills that real SOC analysts use. No standardized benchmark exists that requires LLM agents to interact with heterogeneous security logs, follow multi-hop chains of evidence across tables, and reconstruct attack narratives from distributed telemetry.
![Teaser figure](../imgs/ICML20265056/cropped_page1_idx0.webp)

## Input / Output

The agent receives a natural-language security question that embeds a starting alert and 2 related entities as background context, and must issue SQL queries against a MySQL database containing 57 Azure Sentinel log tables (ranging from 8 to 139 columns each, ~365K rows per incident). The schema is deliberately not provided; agents must discover table structures through exploratory queries. The agent outputs a sequence of thought-action pairs (SQL queries or a final answer submission), and the environment returns a scalar reward in [0,1] combining exact-answer correctness with a geometrically decayed partial credit (γ=0.4) for each intermediate entity on the gold solution path that the agent's submitted answer mentions.

## Method

The benchmark is built by constructing a bipartite alert–entity graph G=(U,V,E) per incident from the SecurityAlert and SecurityIncident tables, where edges encode which entities are associated with which alerts. For every ordered pair of alert vertices (u_s, u_e), the pipeline selects the entities farthest from the opposite alert as starting context (k=2) and answer (k=1), then prompts an LLM to write a question grounded in u_s and V_s whose answer is v_e tied to u_e. The shortest path between u_s and v_e in the graph serves as the gold solution, enabling fine-grained step-level rewards. The evaluation environment is a MySQL Docker container (following InterCode) where the agent's SQL queries are executed and results returned as observations, with caps on steps (25), returned entries (15), and character length (100K) to prevent context overflow. Answer checking uses GPT-4o as judge to handle format variations, and the decayed reward structure (Algorithm 2) assigns partial credit for intermediate IoCs discovered along the path, making the benchmark suitable for RL-based agent training.

## Results

On ExCyTIn-Bench (589 test questions across 8 Azure security incidents), the best model Claude-Opus-4.5 achieves an average reward of 0.606, followed by GPT-5.1 (Reasoning=High) at 0.582 and Claude-Sonnet-4.5 at 0.487. Mid-tier models like o3 (0.456) and GPT-4.1 (0.338) show substantial gaps, while smaller open-source models such as Phi-4-14B (0.085) and Qwen-3-32b (0.182) struggle significantly. The benchmark is notably difficult: even the top model leaves ~40% headroom, and the Pearson correlation between query success rate and reward is 0.86, confirming that effective SQL generation is the primary bottleneck.

## Baselines & Comparisons

Among single-trial (k=1) agent methods, Expel (Zhao et al., 2024) achieves the best reward across all three tested models: 0.390 on GPT-4o, 0.311 on GPT-4o-mini, and 0.265 on o3-mini, outperforming the Base prompt by +0.130, +0.146, and +0.046 respectively. ReAct (Yao et al., 2022) also yields consistent gains over Base (+0.094 on GPT-4o, +0.109 on GPT-4o-mini) but is outperformed by Expel in every setting; however, o3-mini shows minimal benefit from either method (ReAct: 0.250, Expel: 0.265 vs. Base 0.219). At k=3, Self-Reflection (Shinn et al., 2023) combined with ReAct achieves the highest reward (0.563 on GPT-4o, 0.452 on GPT-4o-mini, 0.414 on o3-mini), marginally beating or tying Best-of-N (0.563, 0.423, 0.378 respectively), suggesting that reflective critique provides a small but consistent edge over pure sampling. Notably, Expel incurs 1.6× the prompt cost of Strategy on GPT-4o due to its learned knowledge block and retrieved examples, making it less cost-efficient despite higher accuracy.

## Relation to Prior Work

This paper builds on the interactive environment paradigm from InterCode (Yang et al., 2023), where an agent submits actions (here, SQL queries) and receives execution feedback, but repurposes it for a fundamentally different domain: multi-hop cyber threat investigation over heterogeneous security logs. It departs sharply from prior cybersecurity LLM benchmarks (CTIBench, SECURE, CyBench), which evaluate knowledge memorization, information extraction, or CTF-style tasks, by requiring agents to actively probe a database through sequential queries to reconstruct attack chains. The bipartite alert-entity graph construction for QA generation is a novel methodological contribution that provides automatic, explainable ground truth and fine-grained process rewards, distinguishing it from both text-to-SQL benchmarks (Spider, BIRD) and general agent benchmarks (SWE-Bench, MLAgent-Bench).

## Why It Matters / Open Questions

ExCyTIn-Bench fills a clear gap: no prior benchmark evaluates whether LLM agents can perform the actual investigative workflow (query → observe → reason → query) that SOC analysts perform, rather than testing static security knowledge. The fine-grained decayed reward over intermediate path nodes is a valuable design choice that enables RL-based training of investigation agents, a direction the authors explicitly motivate. Key open questions include whether the benchmark generalizes beyond Azure/Sentinel to other SIEM platforms, whether the single-tenant setting limits ecological validity, and whether the observed fine-tuning degradation (performance dropping on held-out incidents) reflects a fundamental limitation of supervised trajectory learning for multi-hop investigation. The best model achieving only 0.606 reward signals substantial headroom, making this a useful long-term testbed.
