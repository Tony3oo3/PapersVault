## Problem

Current code completion systems operate under a Hard Completion paradigm that forces models to generate fully concrete code even when context is insufficient, leading to costly hallucinations that users must identify and surgically correct. Analysis of 3 million real-world interactions reveals that 61% of suggestions are either rejected or immediately edited despite high surface similarity to the user's actual code, indicating that forced guessing at high-entropy positions inflates rather than reduces developer effort. No prior work provides a theoretical justification for when abstention is beneficial or a training framework that enables models to learn adaptive placeholder insertion end-to-end.

## Input / Output

The model takes a code context (prefix and/or suffix for infilling) and produces a completion sequence in which specific high-uncertainty token positions are replaced with a special placeholder token (⊥, implemented as <|cursor|>, Unicode U+E000). The output remains a syntactically valid skeleton: only ambiguous positions (e.g., specific API parameters, magic numbers, loop bounds) receive placeholders while the surrounding structure is fully concrete. IDE integration recognizes the placeholder token to enable seamless Tab-key navigation, so the user fills blanks in-place rather than deleting and retyping incorrect guesses.

## Method

The paper formalizes code completion as a cost-minimization problem and proves the existence of a unique critical entropy threshold H* = ln(C_HC/(C_HC − C_PC)) above which placeholder completion achieves strictly lower expected user cost than hard completion, under the assumption that filling a placeholder is cheaper than correcting a hallucination. Training proceeds in two stages: (1) SFT on 15K curated samples (5K HC + 10K PC) constructed from real user edit logs, where mismatched positions in model predictions are replaced with placeholders to create PC training instances; (2) GRPO reinforcement learning with a cost-based reward function that decomposes prediction–ground-truth differences via Smith-Waterman alignment into hallucination cost (model-specific content) and omission cost (ground-truth-specific content), applying a saturation penalty to each. The key design insight is that the model implicitly internalizes the dynamic, context-dependent decision boundary for HC-vs-PC switching through end-to-end training, rather than relying on explicit entropy computation or fixed thresholds, which ablation experiments show to be ineffective.

## Results

Across four model families (Qwen2.5-Coder, CodeGemma, CodeLlama, StarCoder2) spanning 1.5B–15B parameters, GRPO-trained APC models reduce expected editing cost (COST) from 60–70% (base) to 34–38% while maintaining 100% Hard Completion Rate (HCR) and stable or improved HC Exact Match (e.g., Qwen2.5-Coder-7B HC EM: 24.29→51.08). On the PC benchmark, GRPO achieves F1 scores of 26–39% and PCR of 43–68%, confirming learned adaptive placeholder insertion. A large-scale A/B test on 1.8M real interactions shows APC reduces cursor moves by 37.4% and read-and-edit time by 31.2% versus HC-only, while producing slightly longer outputs (+1.48 tokens).

## Baselines & Comparisons

The paper does not compare against external code-completion methods; instead, it benchmarks three internal training stages (Base → SFT → GRPO) across four model families. GRPO consistently outperforms SFT on all PC-test metrics (F1, Precision, ES, COST) while preserving or improving HC-test performance, confirming the cost-based reward's contribution over plain supervised training. For example, on Qwen2.5-Coder-7B, GRPO achieves PC F1 of 38.18 vs. SFT's 35.40 and reduces COST from 37.73 to 36.38, while HC EM actually improves (49.24→51.08). Across all 12 model-size configurations, GRPO achieves the lowest COST (34.54–37.59) compared to SFT (35.15–44.06) and Base (45.42–72.93). The ablation in Table 3 further shows that the cost-based reward (GRPO-APC) outperforms an ES-only reward (GRPO-ES) on every PC metric, and that placeholder-augmented training data (SFT-APC) beats direct user-edit fine-tuning (SFT-User) on both PC and HC tests. A fixed-threshold post-processing baseline (Section 5.3) fails to reduce COST below the base model level, validating that implicit end-to-end learning is necessary.

## Relation to Prior Work

This paper extends the code completion literature (Codex, FIM, InCoder, RepoCoder) by departing from the Hard Completion paradigm where models must always emit concrete tokens, instead introducing Adaptive Placeholder Completion (APC) that allows explicit placeholder tokens at high-uncertainty positions. It adapts GRPO (Shao et al., 2024) by replacing the test-pass-rate reward with a theoretically grounded cost-based reward that directly optimizes expected user editing cost. Unlike prior abstention methods that withhold predictions entirely or skeleton-based approaches that treat outlines as hidden intermediate representations, APC makes placeholders visible to users for IDE tab-navigation, creating a single-pass human-AI interaction loop. The theoretical contribution—a provable entropy threshold separating HC-optimal from PC-optimal regimes—has no direct analogue in prior code completion or selective generation work.

## Why It Matters / Open Questions

The 1.8M-interaction A/B test providing 31–37% reductions in editing actions and time is among the strongest real-world validations for a code completion paradigm shift, and the counterintuitive finding that APC produces *longer* outputs while reducing user effort challenges the assumption that shorter completions are always preferable. Key limitations include the IDE-dependency (benefits vanish in non-interactive pipelines), the acknowledged gap between the clean theoretical threshold and the implicitly learned decision boundary, and the proxy nature of character-level Edit Similarity as a cost metric. Open questions include whether the APC paradigm generalizes to other generation tasks (text, math), how multi-line or structural placeholders should be handled, and whether the cost ratio C_PC/C_HC remains stable across programming languages and developer experience levels.
