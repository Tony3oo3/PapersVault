## Problem

In GPU-accelerated two-server secure inference, linear layers are efficient but fixed-point nonlinearities and rescaling helpers remain a bottleneck because each operator (GELU, nExp, reciprocal, truncation, etc.) requires a bespoke protocol with its own comparisons, wrap-around corrections, and preprocessing material. This per-operator approach is brittle: it complicates correctness proofs, duplicates key-generation logic, and makes adding new operators error-prone under modulo-2^n wrap-around.

## Input / Output

The system takes a client's secret-shared input (text prompt or embedding) encoded as fixed-point arithmetic shares over Z_{2^n} with a configurable number of fractional bits, distributed between two non-colluding GPU servers. The output is the model's predictions or logits, revealed only at authorized service endpoints. Each scalar wire (tensor element) is treated as a distinct gate instance with fresh independent masks, and the public masked opening x̂ = x + r_in mod 2^n is the only value revealed during online evaluation.

## Method

FuseFSS is a compiler that replaces per-operator protocol engineering with a uniform two-call structure. Each elementwise fixed-point operator is described by a typed operator specification (interval partition, per-interval low-degree polynomials, and Boolean predicate formulas), and the compiler translates this into exactly two batched FSS evaluations on the public masked value: one packed comparison returning XOR shares of all predicate bits, and one vector interval lookup returning additive shares of the active coefficients and constants. Mask-aware rewriting (Lemma 4.3) converts predicates on the secret x into comparisons on the public x̂ plus secret-shared carry bits, and mask-independent public shapes are enforced via padding to prevent leakage through key size or instance geometry. The remaining computation is a fixed share-based post-processing circuit using Beaver multiplication, Boolean AND, and bit-to-arithmetic conversion, yielding a 1.24×–1.50× end-to-end speedup and 9%–16% communication reduction over Sigma while preserving model accuracy.

## Results

On BERT and GPT-style models (sequence length 128, batch size 1), FuseFSS achieves a 1.24×–1.50× end-to-end online latency speedup over Sigma (19–33% reduction, e.g., BERT-base drops from 1613.8 ms to 1149.5 ms), while reducing online communication by 9–16% (e.g., BERT-base from 1.062 GB to 0.891 GB). Preprocessing is also lighter: key-generation time decreases by 14–23% and key size shrinks by 20–24%. Model accuracy is preserved, with deltas within ±0.59 points on GLUE and LAMBADA benchmarks compared to floating-point PyTorch.

## Baselines & Comparisons

The sole like-for-like baseline is Sigma (Gupta et al., PoPETs 2024), the state-of-the-art FSS-based GPU secure inference system. FuseFSS outperforms Sigma on every reported metric across all five models: online latency is reduced by 19–33%, online communication by 9–16%, key-generation time by 14–23%, and key size by 20–24%, while matching model accuracy within ±0.59 points. The gains are largest on smaller models (BERT-tiny: 33.3% latency reduction) and shrink somewhat for larger models (GPT-Neo: 19.1%), consistent with linear layers becoming a larger fraction of total cost. The paper also reports best-effort runs of BOLT (2PC+HE, CPU-only) and BumbleBee (SPU-based 2PC, CPU-only) but explicitly notes these are not directly comparable due to different protocol families and hardware; SHAFT was attempted but failed due to a CUDA device mismatch. No baseline is beaten on accuracy, as FuseFSS is designed to preserve the same fixed-point approximations used by Sigma.

## Relation to Prior Work

FuseFSS builds directly on the FSS-based GPU secure inference paradigm established by Sigma (Gupta et al., 2024), which demonstrated that function secret sharing can make two-server transformer inference practical on GPUs. The key departure is replacing Sigma's hand-written per-operator protocols (each with bespoke comparisons, wrap-around corrections, and preprocessing) with a uniform compiler that takes a typed operator specification and emits a fixed two-call structure: one packed comparison and one interval lookup. This compiler/IR approach draws on the broader MPC compilation tradition (ABY, ABY3) but applies it specifically to the masked-wire FSS setting, where predicates must be rewritten under public masking with secret-shared carry bits.

## Why It Matters / Open Questions

The compiler framework reduces the engineering burden of adding new fixed-point operators from designing a full protocol to writing a compact specification, which is practically important for the growing zoo of activation functions and rescaling helpers in modern transformers. However, the approach is limited to scalar elementwise operators; vector reductions (max, sum, sorting) still require standard MPC subprotocols, and the semi-honest two-server setting leaves active security and multi-party extensions open. The padding overhead for mask-independent public shapes (roughly 4× per-gate time on small gates) is a non-trivial cost that partially offsets the compilation gains, and the end-to-end speedup (1.24×–1.50×) is moderate because linear layers dominate total inference time.
