## Problem

The evolution of LLM-based software engineering agents is bottlenecked by the scarcity of verifiable datasets, which in turn depends on the ability to construct executable environments at scale. Existing approaches face a fundamental trade-off: static code metrics scale efficiently but provide only approximate verification signals, while manual environment construction ensures quality but is labor-intensive and largely restricted to Python. This leaves a critical gap for scalable, polyglot environment construction across diverse programming languages.
![Teaser figure](../imgs/ICML20261398/cropped_page0_idx0.webp)

## Input / Output

The system consumes a GitHub repository snapshot (file tree, configuration files such as package.json or CMakeLists.txt), an issue-PR pair containing both a fix patch and a test patch, and a pool of previously verified Docker environments. The output is a fully configured Docker container whose validity is certified by the Fail-to-Pass criterion: tests must fail on the original repository state R and pass on the fixed state R_fix, guaranteeing the environment reproduces the specific bug and verifies its resolution. When the reuse mechanism activates, the output additionally includes an incremental command sequence (ΔP) that adapts a retrieved historical environment rather than performing a full build from a base image.

## Method

MEnvAgent employs a multi-agent Planning-Execution-Verification closed loop where specialized agents (Repository Analysis, Environment Setup, Test Configuration, Environment Execution, and Verification) iteratively diagnose and resolve construction failures through structured feedback propagation. The key architectural novelty is the Environment Reuse Mechanism, which reformulates environment construction as a retrieval-and-adaptation problem: a hierarchical retrieval strategy first prioritizes exact version matches, then falls back to temporally closest newer environments under a backward-compatibility assumption. Once a similar environment S_sim is retrieved, an EnvPatchAgent operates within a verification-driven feedback loop, synthesizing minimal incremental patches (ΔP) that transition S_sim to a valid state without rebuilding from scratch. This avoids the error-prone and time-consuming process of resolving complex dependencies from a base image, reducing average construction time by 43% while improving F2P rates by 8.6% over the strongest baseline (SWE-Factory).

## Results

On MEnvBench (1,000 tasks across 10 languages), MEnvAgent achieves an average Fail-to-Pass (F2P) rate of 38.4% and Pass Rate of 49.0%, while reducing average time cost to 3,574s — an 8.6% absolute F2P improvement and 43% time reduction over the strongest baseline (SWE-Factory). With Kimi-K2 as backbone, MEnvAgent reaches 35.7% F2P at 3,339s; with Gemini-3-Flash, 41.1% F2P at 3,808s. For downstream SWE tasks, fine-tuning Qwen2.5-Coder-32B on MEnvData-SWE trajectories yields 54.6% resolved rate on SWE-bench Verified (matching GPT-4.1) and 38.3% on SWE-bench Multilingual (vs. GPT-4.1's 31.5%).

## Baselines & Comparisons

MEnvAgent consistently outperforms all three baselines across every language and both backbone models. Against SWE-Factory (the strongest baseline, evaluated on all 10 languages), MEnvAgent improves F2P by +8.6% and PASS by +11.0% on average while cutting time cost by 43%; the gap is largest in Python (F2P 53% vs. 31% with Kimi-K2) and TypeScript (F2P 32% vs. 23%). Repo2Run, limited to Python only, achieves 24–27% F2P depending on backbone, well below MEnvAgent's 53–61% on the same subset. SWE-Bench-Live (evaluated on 6 of 10 languages) trails MEnvAgent by 15–30+ F2P points in most languages (e.g., 13% vs. 53% on Python with Kimi-K2), though it occasionally matches MEnvAgent on C (13% vs. 13% with Kimi-K2). The ablation further confirms that the Environment Reuse Mechanism contributes an additional +18.5% PASS rate over a scratch-build baseline, with the EnvPatchAgent alone adding +14% Reuse Success Rate over direct reuse without patching.

## Relation to Prior Work

This paper extends the automated environment construction line initiated by Repo2Run (Python-only, fixed test commands) and SWE-Factory (4-language multi-agent), generalizing the problem to 10 languages with joint synthesis of build scripts and test configurations. The key conceptual departure is the Environment Reuse Mechanism, which reframes construction as retrieval-and-patch over a pool of historical environments rather than always building from a base image—a sub-problem absent from prior work. The multi-agent Planning-Execution-Verification loop builds on SWE-Factory's collaborative architecture but adds a dedicated Verification Agent for error attribution and an EnvPatchAgent for incremental adaptation, creating a tighter diagnostic feedback loop.

## Why It Matters / Open Questions

The paper addresses a genuine scalability bottleneck: verifiable SWE training data is constrained by the cost of building executable Docker environments, and prior approaches were largely Python-centric or non-executable. The 43% time reduction from environment reuse and the 10-language MEnvBench provide practical infrastructure for the community to scale polyglot verifiable data. However, absolute F2P rates remain modest (38.4% average), and C/C++ tasks still fail at high rates (7–26% pass), indicating that compiled-language environment construction remains an open challenge. The reliance on Kubernetes-scale infrastructure (1000+ parallel builds) for dataset generation also raises questions about accessibility for smaller research groups.
