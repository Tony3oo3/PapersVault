## Problem

RAG systems prepend large volumes of retrieved documents to prompts, causing prohibitive computational costs and the 'lost-in-the-middle' degradation. Existing context compression methods rely on proxy heuristics (mutual information, BM25 overlap, teacher-model distillation) that are not aligned with downstream task performance, inevitably incurring accuracy losses. The core gap is the absence of a compression strategy that directly optimizes for end-task quality without requiring ground-truth summary labels.

## Input / Output

The compressor takes a natural-language question and a set of k retrieved documents (typically 5 or 10 passages of ~100 words each from a Wikipedia corpus) and produces a short textual summary of roughly 30–60 tokens. This summary is prepended to the original question and fed to a frozen black-box LLM (e.g., Qwen2.5-14B) that generates the final answer. Because the output is a natural-language string rather than a soft embedding, the same trained compressor transfers across different downstream LLMs and datasets without retraining.

## Method

CORE-RAG trains a lightweight compressor (e.g., Qwen2.5-1.5B) in two stages. First, a knowledge-distillation warm-start uses DeepSeek-V3 to generate candidate summaries, then curates training pairs by retaining only those summaries that measurably improve the downstream LLM's answer accuracy (or mapping harmful summaries to an empty string), and fine-tunes the compressor via standard SFT. Second, a performance-driven RL phase applies GRPO: for each input, the compressor samples a group of summaries, each is concatenated with the question and passed through the frozen LLM to produce a predicted answer, and the composite reward (binary EM plus weighted token-level F1) provides the advantage signal for policy updates. This eliminates all proxy heuristics—the compressor is optimized end-to-end on the actual task metric it will be evaluated by, achieving lossless or even positive compression (e.g., 3% token budget with +3.3 EM over full-context RAG on NQ).

## Results

On four QA benchmarks (NQ, TriviaQA, HotpotQA, 2WikiMultihopQA), CORE (1.5B compressor) achieves EM scores of 41.02, 65.63, 33.67, and 36.72 respectively, using only 36–49 context tokens. This surpasses the full-context Top-5 RAG baseline (38.03, 64.10, 32.99, 29.64 EM with ~712–766 tokens) by 1.5–6.9 EM points while compressing input to ~6% of the original length. When generalized to Top-10 documents without retraining, CORE reaches 41.88 EM on NQ with just 52 tokens (3.6% compression ratio), still outperforming the 10-document full-context baseline (38.67 EM, 1425 tokens) by 3.2 EM points.

## Baselines & Comparisons

CORE outperforms all five compression baselines across all four datasets. On NQ (EM), CORE achieves 41.02 vs. QGC (36.23, +4.79), NoiseFilter-IB (35.15, +5.87), RECOMP-Abs (34.18, +6.84), LongLLMLingua (33.65, +7.37), and BM25 (25.23, +15.79). Notably, even the 671B-parameter DeepSeek-V3 used as an off-the-shelf summarizer (37.73 EM on NQ, 27.99 on 2Wiki) is outperformed by CORE's 1.5B compressor, confirming that performance-driven RL optimization matters more than raw model scale. On 2WikiMultihopQA, the gap is most dramatic: CORE reaches 36.72 EM versus 29.64 for full-context Top-5, a 7.08-point improvement, while all baselines fall below the full-context baseline. The only baseline that approaches full-context performance is QGC (31.14 EM on 2Wiki), yet it still trails CORE by 5.58 points.

## Relation to Prior Work

This paper builds directly on the RECOMP formulation of query-conditioned context compression for RAG, but departs fundamentally from all prior compression methods (RECOMP, NoiseFilter-IB, LongLLMLingua, QGC) that rely on proxy heuristics—mutual information maximization, teacher distillation, or lexical overlap—as training signals. The key conceptual shift is framing compression as a sequential decision-making problem solved via GRPO reinforcement learning, where the reward is the downstream task performance itself rather than a surrogate objective. A knowledge distillation warm-start phase (using DeepSeek-V3 as teacher) provides a robust initialization before RL fine-tuning, addressing the limited capacity of the small compressor. The approach also distinguishes itself from RL-based prompt compression (e.g., TACO) by using a generative summarizer rather than binary token-level keep/drop actions.

## Why It Matters / Open Questions

The finding that a 1.5B compressor can outperform full-context RAG (not merely match it) at 3–6% token usage challenges the prevailing assumption that compression necessarily incurs a performance penalty, and the technique is likely to be widely adopted given its model-agnostic, plug-in design. The framework generalizes across compressor architectures (Llama, Qwen), downstream LLMs, and datasets without retraining, suggesting broad practical utility. Open questions include whether the approach extends to open-ended generative tasks (the authors discuss reward redesign but do not empirically validate it), whether it scales to multimodal RAG, and how it behaves when the retriever returns highly noisy or adversarial contexts beyond the mild noise augmentation tested here.
