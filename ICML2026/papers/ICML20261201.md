## Problem

No existing benchmark captures the full complexity of realistic GUI-level PowerPoint editing for computer-use agents: broad OS-level benchmarks offer only superficial presentation coverage, while presentation-specific benchmarks either focus on generation from scratch or are restricted to limited programmatic APIs that omit native features like design tools, transitions, and animations. Additionally, binary success/failure metrics fail to capture the partial progress that current agents frequently achieve on complex, multimodal slide-editing tasks.
![Teaser figure](../imgs/ICML20261201/cropped_page1_idx0.webp)

## Input / Output

Each task provides a .pptx file and a natural-language goal instruction; the agent interacts with PowerPoint Online through a sandboxed Chromium browser using mouse, keyboard, and scrolling actions, receiving full-screen screenshots as observations. Evaluation is method-agnostic, comparing only the original and modified .pptx files (plus slide screenshots) rather than the action sequence, and produces a numeric rubric score in [0,1] along with recursive natural-language explanations at every node of the rubric tree. The environment requires no Microsoft 365 subscription, using anonymous OneDrive edit links for file access.

## Method

PPT-EVAL introduces a tree-structured rubric evaluation framework where internal nodes define hierarchical criteria (critical vs. non-critical) and leaf nodes implement concrete checks via python-pptx, a custom PPTDiff class that extracts animation/transition metadata from XML, LLM calls for semantic equivalence, and VLM calls for visual assessment. The key aggregation innovation replaces Mind2Web 2's gate-then-average rule with a modified formula — max(0, avg_critical − λ(1 − avg_non_critical)) with λ=0.3 — that preserves proportional partial credit while still penalizing non-critical failures, achieving Kendall's τ_b = 0.77 correlation with human judgments. Rubrics are generated semi-automatically (LLM-drafted, then refined by six human experts over ~150 hours), and the 120 tasks are curated via a semi-automatic pipeline where a Claude-4-Sonnet agent explores 12 openly licensed decks to propose candidates, which annotators then filter and refine into 10 tasks per file stratified by difficulty.

## Results

On PPT-EVAL (120 PowerPoint tasks), the strongest GUI agent, Claude-4.5-Opus, achieves a 45% success rate and 0.57 average partial score, while the human baseline reaches 80% SR and 0.90 average score. The API-based baseline (Claude-4.5-Opus via CLI) substantially outperforms all GUI agents at 62% SR and 0.81 average score. Open-weights models trail significantly, with OpenCUA-32B at 28% SR and Qwen3-VL-32B at only 14% SR. Rubric-based evaluation achieves Kendall's τ_b = 0.77 and Spearman's ρ = 0.84 correlation with human judgments.

## Baselines & Comparisons

Among closed frontier models, Claude-4.5-Opus (SR 0.45, Avg 0.57) outperforms both Claude-4-Sonnet (SR 0.42, Avg 0.53) and OpenAI's Computer-Use-Preview (SR 0.38, Avg 0.49), with the largest gap on hard tasks where Claude-4.5-Opus leads Claude-4-Sonnet by 18 percentage points in SR (0.35 vs 0.17). However, Claude-4-Sonnet is more efficient, using fewer steps (12.31 vs 20.96) and performing better on medium-difficulty tasks (SR 0.42 vs 0.38). Among open-weights models, OpenCUA-32B (SR 0.28, Avg 0.42) clearly outperforms the general-purpose Qwen3-VL models (SR 0.14–0.16, Avg 0.23–0.27), though OpenCUA-7B achieves a comparable SR (0.24) at a fraction of the parameters. The API-based baseline (Claude-4.5-Opus via CLI with python-pptx) dramatically outperforms all GUI agents (SR 0.62 vs 0.45), highlighting a significant maturity gap between CLI/API and GUI-based computer-use. All agents remain well below the human baseline (SR 0.80, Avg 0.90), with the largest performance drop occurring on hard tasks where even the best GUI agent (Claude-4.5-Opus) drops to 35% SR.

## Relation to Prior Work

This paper builds on the RubricTree framework from Mind2Web 2 for structured, partial-credit evaluation, but replaces its gate-then-average aggregation rule with a weighted-penalty formula that better rewards intermediate progress in multimodal editing tasks. For task generation, it adapts the LLM-driven exploration paradigm from Go-Browse by augmenting a computer-use agent's action space with a task-proposal tool to produce grounded, file-specific tasks. Conceptually, it departs from prior presentation benchmarks (PPTC, SlideBench) by requiring full GUI interaction with PowerPoint Online rather than programmatic APIs or from-scratch generation, and from OS-level benchmarks (OSWorld, WindowsAgentArena) by providing deep, domain-specific coverage of presentation editing rather than superficial or absent treatment of slide software.

## Why It Matters / Open Questions

PPT-EVAL is the first benchmark to evaluate computer-use agents on realistic, iterative PowerPoint editing with full GUI feature access (transitions, animations, SmartArt, design tools), filling a clear gap between broad OS benchmarks and narrow API-based or generation-only presentation benchmarks. The rubric-based evaluation framework (Kendall's τ_b = 0.77 with human judgments) offers a reusable methodology for partial-credit scoring in other multimodal, open-ended agent tasks. A notable open question is the large performance gap between the API baseline (62% SR) and the best GUI agent (45% SR), suggesting that current GUI agent training lags behind CLI/API training despite having access to a richer feature surface. Scaling rubric creation remains a bottleneck, as model-generated drafts required >81% human modification, limiting the benchmark's applicability to RL or large-scale agent training scenarios.
