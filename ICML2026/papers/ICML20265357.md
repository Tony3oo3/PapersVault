## Problem

Existing LLM agent memory systems are either task-specific and non-transferable, or task-agnostic but suffer from low task-relevance and context explosion when retrieving raw episodic memories. The core gap is the absence of a unified, plug-and-play memory module that transforms heterogeneous experience into compact, decision-relevant knowledge and generalizes across diverse agentic tasks without redesign.
![Teaser figure](../imgs/ICML20265357/cropped_page0_idx0.webp)

## Input / Output

The module consumes heterogeneous raw episodic traces (dialogue turns, document snippets, web action trajectories) which are first standardized into structured (observation, state, action, reward, subgoal) tuples, along with a task query or description at retrieval time. It produces a three-layer knowledge-centric memory graph (episodic, semantic, procedural subgraphs with provenance links), from which a multi-hop retriever selects relevant knowledge subgraphs, and a reasoning module further condenses these into a small number of task-aligned guidance tokens injected into the base agent's context.

## Method

PLUGMEM comprises three components grounded in the cognitive science distinction between episodic, semantic, and procedural memory. The structuring module standardizes heterogeneous experience into a unified episodic representation, then extracts atomic propositions (semantic memory) and intent-prescription pairs (procedural memory) via LLM-based abstraction, organizing them into a bipartite memory graph where high-level nodes (concepts/intents) route to low-level knowledge units (propositions/prescriptions). The retrieval module performs abstraction-specificity interleaving: it alternates between scoring low-level knowledge nodes against the query and generating abstract routing signals (concept or intent sets) to traverse high-level nodes, enabling multi-hop retrieval that jumps beyond local neighborhoods. The reasoning module is a test-time compressor that aggregates and distills retrieved knowledge into a single compact, task-aligned summary. Unlike GraphRAG, which treats entities or text chunks as graph nodes, PLUGMEM treats knowledge units themselves as the fundamental units of memory access and organization, and the entire module is task-agnostic and deployable as a lightweight plugin with minimal integration code.

## Results

On LongMemEval, PLUGMEM achieves 82.8% accuracy using only 233.9 average memory tokens, yielding an information density of 3.2e-2 bits/token — roughly 20× higher than the best task-agnostic baseline (Vanilla Retrieval, 1.6e-3) and 26× higher than the best task-specific baseline (LiCoMemory, 1.2e-3). On HotpotQA, PLUGMEM reaches 61.4 EM / 74.1 F1 with just 81.6 tokens (1.4e-1 density), surpassing HippoRAG2 (60.0 EM / 73.3 F1, 595.1 tokens). On WebArena, PLUGMEM attains 52.6/58.4% success rate on Shopping and 51.4/55.2% on GitLab with only 301 tokens, outperforming AWM (26.3/28.2%, 27.0/27.3%) and Vanilla Retrieval (43.0/42.3%, 40.5/41.3%) by wide margins.

## Baselines & Comparisons

PLUGMEM outperforms all nine baselines across all three benchmarks. Against task-agnostic baselines, it beats Vanilla Retrieval by 17.6 points on LongMemEval (82.8 vs. 65.2), 9.7 EM on HotpotQA (61.4 vs. 51.7), and 9.6 SR on WebArena Shopping (52.6 vs. 43.0), while using 15–29× fewer memory tokens. Against task-specific baselines, it surpasses LiCoMemory (74.1%) and Zep (71.2%) on LongMemEval, HippoRAG2 (60.0 EM) and PropRAG (57.8 EM) on HotpotQA, and AWM (26.3/28.2% SR) on WebArena — notably, AWM actually shows negative information density (−7.9e-4), meaning its memory hurts performance. The information density metric reveals the largest gap: PLUGMEM's 3.2e-2 bits/token on LongMemEval is an order of magnitude above all baselines, and its 1.4e-1 on HotpotQA approaches the Gold Context upper bound (1.6e-1) while using only 81.6 tokens versus 86.5 for gold. On WebArena, PLUGMEM's 301-token budget is 29× smaller than Vanilla Retrieval (8733) and 68× smaller than A-Mem (20516), yet delivers the highest success rates in every sub-domain.

## Relation to Prior Work

PlugMem repositions the GraphRAG paradigm (Edge et al., 2025) from entity- and text-chunk-centric retrieval to a knowledge-centric memory graph where propositions and prescriptions are the fundamental units of access. It draws on the cognitive science distinction between episodic, semantic, and procedural memory (Tulving, 1972; Squire, 2004) to motivate a unified structuring pipeline that prior agentic memory systems (A-Mem, Zep, AWM, HippoRAG2, RAPTOR, LiCoMemory) handle in isolation or in a task-specific manner. The key conceptual departure is that memory is organized around abstract knowledge units rather than raw episodic traces, enabling a single retrieval mechanism to serve heterogeneous task types without redesign.

## Why It Matters / Open Questions

The paper addresses a practical bottleneck in agent deployment: memory modules that must be re-engineered for each new task domain. The proposed information-density metric (PMI per token) offers a task-agnostic, comparable way to evaluate memory efficiency that prior work lacks. Limitations include heavy reliance on LLM calls for structuring (cost and latency at scale), evaluation on only three benchmarks, and the memory graph's scalability to very long interaction histories remaining untested. Open questions include whether the cognitive-science framing yields measurable advantages over purely data-driven structuring, and how the system handles adversarial or noisy episodic inputs that could corrupt extracted knowledge.
