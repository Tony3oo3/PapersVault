## Problem

Recurring Pattern Bugs (RPBs) — structurally similar flaws that persist across a codebase even after individual instances are patched — remain a persistent security threat because traditional static analyzers require hand-crafted rules per pattern and fail to generalize across syntactic variants, while pure LLM-based detection lacks the precision and grounding needed for reliable large-scale bug finding. The paper addresses the gap between over-specified static analysis and ungrounded LLM reasoning by asking whether a single patched instance can be leveraged to autonomously discover all latent variants of the same bug pattern.

## Input / Output

The system takes a single seed patch (a bug-fix git commit) and the full target program as input. The seed patch is deterministically normalized via git diff -W to expand each hunk to its enclosing function body and strip non-semantic metadata; the target program is compiled to LLVM IR (for C/C++) or source-scanned (for Python) to build a whole-program call graph. The pipeline produces a concise natural-language security coding rule, a set of LLM-verified candidate violations with function-level source context, and a severity-ranked list of findings prioritized by module criticality and bug-class exploitability for manual triage.

## Method

BUGSTONE is a five-stage neuro-symbolic pipeline that decouples semantic abstraction from scope enumeration. First, a deterministic git-based normalizer expands the seed patch to function-level context. Second, an LLM (using in-context learning with three few-shot rule templates and chain-of-thought prompting) synthesizes a concise security coding rule capturing the root-cause API, required action, and scope constraints. Third, an adapted MLTA LLVM call-graph analyzer enumerates all call sites of the anchored API and extracts the enclosing caller functions as candidate snippets, pruning the search space without making any violation judgment. Fourth, the LLM verifies each candidate against the synthesized rule (the Rule-Based strategy outperforms Patch-Based and Hybrid variants by decoupling the abstract logic from patch-specific syntactic artifacts). Fifth, an impact-based prioritization module ranks findings by module criticality tier and vulnerability exploitability. The key design insight is that static analysis handles only deterministic candidate retrieval while the LLM handles all semantic judgment, enabling generalization to unseen syntactic variants without per-pattern rule engineering.

## Results

On BugStone-Bench (850 security patches, 80 recurring patterns), BUGSTONE with the Rule configuration and Llama-4 achieves 92.2% precision and 79.1% pairwise accuracy, substantially outperforming the zero-shot Basic setup (~17–37% PA) and the one-shot Patch setup (~51–78% PA). In large-scale Linux kernel deployment, BUGSTONE flagged 22,568 potential violations across 148,664 code pieces; a 400-case manual audit confirmed 246 true bugs (61.5% precision), with 32 confirmed and fixed by maintainers. In the top 100 Python projects, BUGSTONE identified 47 command injection vulnerabilities, 20 of which received proofs of exploitability. The full Linux scan cost approximately $110 using Llama-4 (~$0.00074 per case).

## Baselines & Comparisons

The paper does not compare against external bug-finding tools in a head-to-head benchmark; instead, it ablates its own pipeline by varying the prompt configuration (Basic, Patch, HuRule, Rule, Rule+Patch) across six LLMs. The Rule configuration (BUGSTONE's primary mode) consistently outperforms the zero-shot Basic setup by 40–60 PA points and the one-shot Patch setup by 7–15 PA points on frontier models, while also reducing input tokens from ~2,250 to ~870 per query. Against the human-written rule baseline (HuRule), the LLM-synthesized Rule matches or slightly exceeds performance on larger models (e.g., Llama-4: 79.1 vs. 72.8 PA; o4-mini: 83.1 vs. 79.9 PA) but lags on smaller models (Llama-3.3-8b: 52.5 vs. 57.9 PA). The Hybrid (Rule+Patch) configuration yields only marginal gains over Rule alone (≤1 PA point on o4-mini) while doubling input token cost, confirming that the abstract rule is sufficient. Removing Chain-of-Thought collapses performance for non-reasoning models (Llama-3.3-8b drops to 14.4% PA) but has negligible effect on reasoning-optimized models like o4-mini (83.5% vs. 83.1% PA).

## Relation to Prior Work

BUGSTONE positions itself against two underperforming extremes: traditional static analyzers (CodeQL, Coccinelle, MLTA) that require hand-crafted rules per bug pattern and fail to generalize across syntactic variants, and pure LLM-based detectors (Ullah et al. 2024, GPTAid, LLift) that lack grounding and struggle with complex logic bugs. Its key architectural departure is using LLVM-based call-graph analysis (adapted from MLTA, Lu & Hu 2019) solely for candidate enumeration while delegating the semantic judgment to an LLM guided by a synthesized natural-language rule, rather than using the LLM to generate static-analysis queries as in MoCQ. This inverts the typical neuro-symbolic division of labor: the symbolic component prunes the search space, and the neural component makes the final compliance decision.

## Why It Matters / Open Questions

The practical impact is substantial: 246 manually validated bugs in the Linux kernel (34 confirmed and fixed by maintainers) and 20 exploitable command injections in top Python projects, all discovered at a total inference cost of roughly $110. The BugStone-Bench dataset (850 patches, 80 recurring patterns) fills a gap in ground-truth benchmarks for LLM-based security analysis. Key limitations remain: the system is strictly intra-procedural (missing caller-side cleanup and global state), has no soundness guarantee, and is limited to API-anchored patterns, leaving unanchored arithmetic or concurrency bugs out of scope. Open questions include whether inter-procedural context can be efficiently incorporated and whether the rule-abstraction approach generalizes beyond the 14 template families identified.
