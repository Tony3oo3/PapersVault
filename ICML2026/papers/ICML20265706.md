## Problem

Existing long-context benchmarks evaluate single-step retrieval from static text (e.g., needle-in-a-haystack), but real-world agentic tasks require models to dynamically explore environments, follow multi-constraint instructions, and take correct actions as context grows over time. No prior benchmark isolates the effect of context length in a controlled, scalable manner while keeping task semantics fixed, making it impossible to systematically study how 'context rot' degrades agent reliability.

## Input / Output

The benchmark takes a fixed task prompt and an environment configuration (controlling parameters like number of courses, proportion of information sources, and distraction level) that determines the Environment Description Length — the token count of all tool outputs an agent must read, measured under GPT-4's tokenizer. The agent (model + scaffold) interacts with local mock servers via 280 tools across 7 services (Canvas, Email, BigQuery, WooCommerce, etc.) and produces a post-task environment state. Evaluation is binary (success/failure) via rule-based scripts comparing the final environment state to ground truth, with auxiliary metrics of trajectory length, tool call count, and tool output token count.

## Method

LOCA-bench constructs scalable environments using hand-written templates and programmatic generators that instantiate environment states of varying complexity while preserving task semantics. The key mechanism is the Environment Description Length metric: scripted tool calls collect all information an agent would need, and the aggregated token count defines the context scale (8K–256K tokens). Built on GEM, the framework decouples environment, tools, tasks, and scaffold, enabling systematic evaluation of 7 models (3 frontier, 4 open-source) under the ReAct scaffold across 525 samples (15 seed tasks × 7 lengths × 5 seeds). Beyond native model evaluation, the paper integrates six context engineering strategies — tool-result clearing, thinking-block clearing, context compaction, context awareness, memory tools, and programmatic tool calling — into the scaffold to measure how each mitigates context pressure, finding that programmatic tool calling consistently improves accuracy while reducing trajectory length across all models.

## Results

On LOCA-bench, accuracy drops sharply as environment description length increases from 8K to 256K tokens. At 8K, most models exceed 70% accuracy (Claude-4.5-Opus leads at 96.0%), but at 256K, even the best frontier model (GPT-5.2-Medium) falls to 21.3% while open-source models drop to 2.7–6.7%. Average accuracy across all lengths is 68.1% for Claude-4.5-Opus, 51.2% for GPT-5.2-Medium, and 31.2–42.7% for open-source models. Context engineering strategies at 128K yield substantial gains: programmatic tool calling lifts GPT-5.2-Medium from 38.7% to 49.3% and DeepSeek-V3.2-Thinking from 10.7% to 24.0%.

## Baselines & Comparisons

The paper evaluates seven models (three frontier, four open-source) under a unified ReAct scaffold, with no external method baselines. At short contexts (8K), frontier and open-source models perform comparably (70–96%), but the gap widens dramatically at longer contexts: at 128K, frontier models (34–38.7%) achieve roughly 2–3× the accuracy of open-source models (8–10.7%). Among frontier models, Claude-4.5-Opus leads at short contexts (96% at 8K) while GPT-5.2-Medium is more consistent across lengths (21.3% at 256K vs. 14.7% for Claude). Among open-source models, DeepSeek-V3.2-Thinking is strongest, staying competitive with frontier models up to 64K before degrading sharply. For context engineering strategies at 128K, programmatic tool calling is the most effective across all models (e.g., +10.6 pp for GPT-5.2-Medium, +13.3 pp for DeepSeek-V3.2-Thinking), while context awareness and memory tools help frontier models but hurt DeepSeek-V3.2-Thinking (dropping to 4.0%). Anthropic's official programmatic tool calling (49.3%) outperforms the paper's own implementation (40.0%) for Claude-4.5-Opus, and the Claude Agent scaffold actually degrades performance (26.7%) compared to the native ReAct baseline (34.0%).

## Relation to Prior Work

LOCA-bench extends the long-context evaluation paradigm from static, single-step retrieval (RULER, MRCR, LongBench v2, Oolong) to dynamic, multi-step agentic settings where models must explore environments via tools over extended horizons. It sources its 15 seed tasks from Toolathlon (Li et al., 2025) and is implemented on the GEM framework (Liu et al., 2025), but departs from both by introducing a controllable environment description length that systematically scales context while fixing task semantics — a dimension neither prior agent benchmarks nor prior long-context benchmarks isolate. The context engineering strategies evaluated (context compaction, memory tools, programmatic tool calling) are drawn from Anthropic's engineering documentation, positioning the paper as a systematic empirical study of these techniques rather than a proposal of new ones.

## Why It Matters / Open Questions

LOCA-bench fills a clear gap: no prior benchmark isolates the effect of context length in multi-step, tool-using agent scenarios, making it difficult to attribute performance drops to context rot versus task difficulty. The finding that programmatic tool calling consistently improves accuracy across all seven models (e.g., +13.3 pts for DeepSeek, +10.6 pts for GPT-5.2) while reducing trajectory length provides actionable guidance for scaffold design. Limitations include reliance on mock servers rather than live services, only 15 seed tasks, and binary evaluation, which may undercount partial progress. Open questions include whether these findings transfer to real (non-mock) environments, whether context engineering strategies can be learned end-to-end rather than hand-coded, and how the benchmark scales beyond 256K tokens.
