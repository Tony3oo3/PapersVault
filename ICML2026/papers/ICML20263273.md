## Problem

Existing LLM cybersecurity research targets isolated analytical tasks (malware classification, vulnerability detection) without modeling the full multi-staged, interdependent threat-hunting workflow that blue team analysts actually follow. No prior benchmark evaluates how LLMs perform across the complete threat-hunting lifecycle—from attribution through behavior analysis to incident response—under standardized procedural constraints, leaving it unclear whether open-ended reasoning strategies (ICL, CoT, ToT) are sufficient for domain-specific defensive operations.

## Input / Output

The benchmark consumes unstructured and semi-structured threat intelligence text (advisories, logs, campaign reports) aggregated from 23 sources including NVD, MITRE ATT&CK, VirusTotal, and Mandiant, totaling 452,293 evaluation instances. Critically, inputs are consumed sequentially through a dependency chain: the structured output of an upstream task (e.g., extracted IOCs from NER/REX) becomes the contextual input for downstream tasks (e.g., TTP mapping via RAG/MAP). Outputs are task-specific and structured—JSON entity schemas for NER, relational triples for MAP, executable code for patch generation, numerical CVSS scores for severity scoring—rather than free-form prose, enabling automated metric computation (F1, BERTScore, Hit@k, Pass rate, Normalized Distance).

## Method

CYBERTEAM formulates threat hunting as a dependency chain of 30 tasks organized into four sequential categories (Threat Attribution → Behavior Analysis → Prioritization → Response & Mitigation), where downstream tasks explicitly depend on upstream outputs. Each task is decomposed into a sequence of 9 operational modules (NER, REX, SUM, SIM, MAP, RAG, SPA, CLS, MATH) that constrain LLM reasoning into discrete, auditable steps—e.g., RAG retrieves authoritative advisories from a FAISS-indexed vector store plus live external APIs, while NER enforces structured JSON entity extraction with schema validation and retry logic. The LLM is prompted to select which modules to invoke at each stage (retaining reasoning flexibility) but must execute them in the prescribed order, balancing standardization with adaptability. This modularized pipeline is benchmarked against three open-ended reasoning baselines (ICL, CoT, ToT) across eight general-purpose LLMs and three cybersecurity-specific agents, with the key finding that standardized operational guidance consistently outperforms open-ended prompting, particularly on multi-stage tasks with strong interdependencies.

## Results

On CYBERTEAM's 30 threat-hunting tasks, the standardized modular workflow (Ours) consistently outperforms open-ended reasoning baselines (ICL, CoT, ToT) across all 11 evaluated LLMs. For the top-performing model Grok-4.1, the modular approach achieves over 90% Hit@10 on Playbook Recommendation and over 92% on Advisory Correlation, while open-ended methods trail by a significant margin. In complex multi-stage tasks such as Event Sequence Reconstruction, GPT-5.1 gains over 20 percentage points in BERTScore similarity when using the standardized pipeline versus CoT or ToT. The performance gap is largest for tasks with strong interdependencies (e.g., response planning requiring upstream attribution) and smallest for self-contained identification tasks (e.g., privilege escalation inference).

## Baselines & Comparisons

The paper compares the proposed standardized modular workflow against three open-ended prompting strategies: In-Context Learning (ICL, Dong et al., EMNLP 2024), Chain-of-Thought (CoT, Wei et al., NeurIPS 2022), and Tree-of-Thought (ToT, Yao et al., NeurIPS 2023). The modular approach wins decisively across all 30 tasks and all 11 LLMs, with the largest margins in multi-stage dependent tasks (e.g., >20 pp gain in Event Sequence Reconstruction for GPT-5.1) and in the Response & Mitigation stage where Grok-4.1 reaches >90% Hit@10 versus substantially lower scores for ICL/CoT/ToT. ICL generally performs slightly better than CoT and ToT on self-contained identification tasks (e.g., privilege escalation inference), but all three open-ended methods fail to enforce correct task sequencing, leading to hallucinated or generic outputs (e.g., GPT-5.1 with CoT produces boilerplate LockBit response plans ignoring double-extortion specifics). The paper also notes that open-ended methods produce opaque reasoning chains that are harder to audit, whereas the modular pipeline traces each output to a specific operation (RAG, NER, SUM), improving interpretability for blue-team analysts.

## Relation to Prior Work

This paper departs from the dominant trend in LLM-for-cybersecurity research, which has focused on isolated analytical tasks (malware classification, vulnerability detection, penetration testing), by modeling the full multi-stage threat-hunting pipeline with explicit inter-task dependencies. Conceptually, it repurposes the operation-guided agent paradigm—previously applied to robotics, database querying, and scientific reasoning—into a cybersecurity defensive context, wrapping LLM reasoning in a set of nine standardized operational modules (NER, REX, SUM, RAG, CLS, SIM, MAP, SPA, MATH). It also extends the cybersecurity benchmarking line (CTIBench, SevenLLM-Bench, CWE-Bench-Java) by scaling to 23 data sources, 30 tasks, and 452K samples, and by introducing a dependency-chain workflow that mirrors real blue team SOPs rather than treating each task in isolation.

## Why It Matters / Open Questions

CYBERTEAM fills a concrete gap: no prior benchmark evaluates LLMs across the full threat-hunting lifecycle with task interdependencies, making it a practical reference for organizations deploying LLMs in blue team operations. The finding that standardized modular workflows consistently outperform open-ended prompting strategies (ICL, CoT, ToT) by 10–20+ points on complex multi-stage tasks provides actionable guidance for security teams choosing between structured pipelines and free-form LLM reasoning. Key limitations include sensitivity to semantic-level noise (paraphrased or subtly altered context degrades performance far more than token-level corruption), reliance on publicly available threat data that may not capture zero-day or novel attack patterns, and the fact that the operational modules are prompt-engineered rather than learned, raising questions about robustness as threat landscapes evolve.
