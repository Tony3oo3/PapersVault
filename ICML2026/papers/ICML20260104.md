## Problem

Existing LLM benchmarks for Operations Research evaluate one-shot natural-language-to-solver-code translation, omitting the iterative debugging loop—inspecting Irreducible Infeasible Subsystems, identifying constraint conflicts, and repairing formulations—that constitutes the core of real OR practice. Additionally, downstream operational decisions by LLMs exhibit systematic behavioral biases (e.g., pull-to-center in inventory ordering) that remain unaddressed by formulation-focused benchmarks.

## Input / Output

For OR-DEBUG-BENCH, each instance provides a natural-language problem description and sabotaged Gurobi code returning INFEASIBLE; the agent interacts through a constrained action space (GET_IIS, CHECK_SLACK, RELAX, DROP, REWRITE, SUBMIT) and receives deterministic IIS recomputation after every state-modifying action, with episodes capped at 50 steps. For OR-BIAS-BENCH, input is a newsvendor or EOQ scenario (price, cost, salvage, demand parameters or censored percentiles), and output is a single order quantity Q evaluated against the closed-form optimum Q* = μ + σ·Φ⁻¹(CR). The key structural constraint is that repair must be constraint-level (editing specific constraints) rather than whole-model regeneration, with objective-preservation (OP > 0.95) as a hard success criterion.

## Method

The paper formalizes infeasible-model repair as a solver-in-the-loop MDP where each action triggers Gurobi re-execution and IIS recomputation, yielding deterministic, verifiable state transitions. Training proceeds in two stages: supervised fine-tuning on 696 filtered teacher trajectories (from GPT-5.2, o4-mini, DeepSeek-R1) followed by GRPO with a composite reward R = 0.5·R_outcome + 0.3·R_diagnosis + 0.2·R_efficiency, using LoRA (r=16) and KL removal; a process reward model provides step-level supervision scored by IIS size reduction. For OR-BIAS-BENCH, a three-stage curriculum (extreme CR → near-boundary → full distribution) explicitly teaches directional sensitivity to counter pull-to-center bias. The critical design choice is constraint-level repair over code regeneration: the agent edits targeted constraints while preserving the original objective, avoiding the semantic-drift failure mode where regenerated feasible models solve the wrong problem. An 8B Qwen3 model trained this way reaches 95.3% RR@5 on LP repair, surpassing the strongest frontier API (92.4%) while improving diagnostic accuracy by +14.6 pp and reducing average repair steps from 3.15 to 2.25.

## Results

On the 450-instance LP repair evaluation (OR-DEBUG-BENCH), QWEN3-8B-GRPO achieves 95.3% RR@5, 62.4% diagnostic accuracy (DA), and 2.25 average repair steps, surpassing the strongest frontier API (Claude Sonnet 4.6 at 92.4% RR@5) by +2.9 pp and improving DA by +14.6 pp over o4-mini (47.8%). On MILP repair, the LP-trained model transfers zero-shot at 78.8% RR@5, and MILP-specific training reaches 87.1%, versus 71.0% for the best API baseline. On OR-BIAS-BENCH, curriculum training achieves the best OOD generalization with −9.6% bias drift (20.0%→10.4%), the only trained model showing substantial OOD improvement.

## Baselines & Comparisons

All five OR-domain baselines are evaluated in the same solver-in-the-loop MDP environment with identical IIS observations, action space, and step budget. QWEN3-8B-GRPO (95.3% RR@5) decisively outperforms LLMOPT (78.4%), SIRL (73.8%), and ORLM (71.0%) on LP repair, with gaps of +16.9, +21.5, and +24.3 pp respectively. OptiMUS, evaluated in its native code-regeneration mode, trails severely at 28.9% RR@5 on LP and 2.2% on MILP, and additionally suffers semantic drift (only 28.2% objective preservation despite 90% OPTIMAL status for GPT-5.4). DeepSeek-R1, used both as a teacher model and as an API baseline, achieves only 56.7% RR@5 with 5.08 steps, far below the trained 8B model's 95.3% and 2.25 steps. On MILP, the gap widens: the best API baseline (Claude Sonnet 4.6) reaches 71.0%, SIRL 67.6%, LLMOPT 44.4%, and OptiMUS 2.2%, while MILP-specific training of the 8B model reaches 87.1%.

## Relation to Prior Work

This paper departs from the dominant OR benchmark paradigm (NL4Opt, OptiBench, MAMO, ORLM) that evaluates one-shot natural-language-to-solver-code translation, instead formalizing infeasible-model repair as a solver-in-the-loop MDP where Gurobi IIS computation provides deterministic state transitions. Methodologically, it adapts GRPO (DeepSeek-R1) and DAPO-style KL-removed RLVR with a composite reward (outcome + diagnosis + efficiency) and a process reward model inspired by Lightman et al.'s step-level verification, but grounds all rewards in solver-certified signals rather than heuristic or self-generated feedback. On the behavioral side, OR-BIAS-BENCH extends the pull-to-center phenomenon documented in AIM-Bench (Zhao et al., 2025) and classical newsvendor bias literature (Schweitzer & Cachon, 2000) with explicit ID/OOD splits and a curriculum-learning intervention. The closest prior system, OptiChat (Chen et al., 2024/2025), also uses Gurobi IIS for infeasibility diagnosis but operates as a conversational interface over 24 fixed models rather than a controlled MDP benchmark with constraint-level repair actions and objective-preservation checks.

## Why It Matters / Open Questions

The benchmark fills a concrete gap: no prior OR evaluation captures the iterative IIS-driven debugging loop that practitioners actually perform, and the semantic-drift finding (GPT-5.4 reaches OPTIMAL in 90% of regenerated MILPs but preserves the correct objective in only 28.2%) exposes a failure mode invisible to standard feasibility checks. The result that a solver-verified 8B model matches or slightly exceeds frontier APIs on LP repair (95.3% vs 92.4% RR@5) while using 2.8× fewer tokens suggests that domain-specific RLVR training can substitute for scale in structured, verifiable domains. Key limitations constrain generalizability: the benchmark covers only LP/MILP with Gurobi-verifiable IIS (no nonlinear, stochastic, or multi-objective formulations), IIS is a minimal certificate rather than a complete causal explanation, and OR-BIAS-BENCH is limited to closed-form newsvendor/EOQ settings. Open questions include whether the MDP repair interface transfers to MINLP and stochastic debugging, whether hybrid model-optimizer approaches (model identifies constraint, optimizer computes minimal adjustment) can close the remaining Type H–I gap, and whether the curriculum debiasing strategy generalizes beyond single-period inventory to multi-period or multi-echelon settings.
