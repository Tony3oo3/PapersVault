## Problem

In complex open-ended worlds, agents plateau because existing UED methods operate over low-dimensional parameter spaces (e.g., random seeds) that cannot introduce structurally evolving environments with long-horizon dependencies. While recent FM-based approaches can generate diverse environment programs, they treat each environment as an isolated challenge rather than orchestrating sequences that sustain progressive learning. The gap is a mechanism for generating curricula of structurally evolving, code-defined environments that keep the agent in a learnable regime across deep skill hierarchies.

## Input / Output

The FM receives a multi-part context: immutable game rules and API documentation, the selected parent level's natural-language description with its performance profile (success rate, achievement breakdowns), the target environment's current achievement success rates, and mutation instructions. Output is a two-stage generation—first a structured natural-language level description, then executable Python code defining a Craftax level's initial state distribution, modified mechanics parameters (spawn rates, damage multipliers, etc.), and achievement-based goal. Generated code must pass both Python compilation and a short runtime trajectory before entering the training batch; sessions over-request 12 candidates to fill a target of 10 valid levels (~60% raw compile rate).

## Method

DiCode is a UED framework in which an open-weight FM (Qwen3-235B) synthesizes executable Python environment code as a curriculum mechanism, executed by a fixed JAX game engine to guarantee physical validity. Each generation cycle selects a parent level from a directed-graph archive using learnability scores (p(1−p)), then performs two sequential FM inference steps—description generation followed by code synthesis—conditioned on the agent's current competence to produce a child level that introduces one incremental dependency beyond the parent's capability frontier. Training constructs stratified batches allocating 20% of the simulation budget to the target environment, with the remainder split between newly generated levels and PLR-replayed archive levels, while an adaptive goal-completion bonus B_t = max(d, 2×R_{t−1}) ensures the agent pursues level objectives rather than exploiting dense early-game rewards. The closed-loop design feeds the agent's evolving performance profiles back into the FM's context each cycle, and asynchronous generation overlaps FM inference with RL training to minimize GPU idle time.

## Results

On Craftax (2×10⁹ environment steps, 8 seeds), DiCode achieves a final mean return of 48.55 ± 0.49 on a held-out test set of 1024 unseen procedurally generated worlds, a ~17% relative improvement over the strongest baseline (PPO-GTrXL at 41.59). The advantage is structural rather than uniform: DiCode reaches 47% success on Make Iron Armour (vs. 15% for the best baseline), enters the Gnomish Mines in 32% of episodes (vs. 9%), and achieves non-zero success on late-game combat tasks (Defeat Gnome Warrior: 15%, Defeat Gnome Archer: 11%) where all baselines collapse to 0%. Ablations confirm that environment reshaping (not just goal selection) and closed-loop grounding to the agent's performance are the primary drivers of these gains.

## Baselines & Comparisons

DiCode outperforms all four baselines on mean return, with the largest gap over PPO-GTrXL (48.55 vs. 41.59, +17%). The most striking comparison is on late-game combat achievements: PPO-GTrXL, PLR, SFL, and DR all achieve 0% success on Defeat Gnome Warrior and Defeat Gnome Archer, while DiCode reaches 15% and 11% respectively, demonstrating that code-level curriculum generation unlocks behaviors entirely inaccessible to seed-based UED methods. On instrumental milestones critical for long-horizon survival (e.g., Make Iron Armour), DiCode achieves 47% versus 15% for the best baseline, and doubles baseline success on Make Diamond Sword (6% vs. 3%). The ablation showing that Open-Loop DiCode (41.12) performs comparably to PPO-GTrXL (41.59) confirms that the gains are specifically attributable to closed-loop, performance-conditioned generation rather than the mere act of generating new environments. PLR and SFL, which curate over Craftax's random seeds (terrain layout only), cannot modify game mechanics or skill dependencies, fundamentally limiting their ability to scaffold the compositional progression that Craftax requires.

## Relation to Prior Work

DiCode extends the Unsupervised Environment Design (UED) framework (Dennis et al., 2020) from fixed low-dimensional parameter spaces to the unbounded space of executable Python programs, where a foundation model synthesizes entire POMDPs (transition dynamics, initial states, goals) rather than tuning a handful of scalar parameters. It inherits the learnability-based level selection from Rutherford et al. (2024) and the prioritized replay mechanism from PLR (Jiang et al., 2021), but departs from OMNI-EPIC (Faldor et al., 2025) by treating generated environments not as isolated interesting challenges but as a closed-loop curriculum: the FM conditions on the agent's current performance profile to produce the *next* stepping stone, creating a directed progression graph rather than a flat archive of disjoint levels. The evolutionary lineage-selection strategy (parent must be in status A/B with no D-status offspring) draws on ACCEL (Parker-Holder et al., 2022) but operates over code-level mutations rather than parameter perturbations.

## Why It Matters / Open Questions

The paper demonstrates that code-level environment generation is a practical mechanism for curriculum control in open-ended worlds, unlocking late-game skills (e.g., Gnome combat) that remain at 0% success for all prior UED methods and standard RL. The ablation cleanly isolating environment reshaping (scaffolding, mechanic adjustment) as the primary driver over goal selection alone provides actionable design guidance. Key limitations include the fixed game engine bounding the scope of invention (the FM configures but cannot invent new physics), the ~3.5× compute overhead from JAX recompilation, and the vulnerability of the learnability score to stochastic levels. The broader open question the paper identifies—how to reliably distinguish useful stepping-stone environments from uninformative or distracting ones—remains central to scaling experience-driven open-ended learning beyond a single benchmark.
