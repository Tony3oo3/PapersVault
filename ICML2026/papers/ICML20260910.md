## Problem

Existing coding-agent benchmarks evaluate short-horizon behaviors—localized function generation, scaffolded completion, or bug repair within pre-existing repositories—leaving it unclear whether agents can sustain coherent reasoning, planning, and execution over the hundreds of interaction steps required to build a complete software repository from scratch. NL2Repo-Bench targets this gap by asking: can current coding agents reliably generate a fully installable Python library from a single natural-language specification while maintaining long-horizon architectural coherence?
![Teaser figure](../imgs/ICML20260910/cropped_page1_idx0.webp)

## Input / Output

The agent receives a single structured natural-language requirements document (averaging ~18,800 tokens) containing four sections—Project Description, Supports (dependencies and directory layout), API Usage Guide (exhaustive class/function specifications), and Implementation Nodes—along with an empty workspace. No project scaffolding, source code, or test cases are revealed during development. The output is a complete, installable Python library, scored strictly by executing the original upstream pytest suite in a containerized environment; the metric is the fraction of passed test cases per task, averaged across 104 tasks.

## Method

The benchmark is constructed via a reverse-engineering pipeline: real-world Python repositories (300–120k LOC, 10+ GitHub stars, fully passing pytest suites) are selected, then their entire codebase is translated into a natural-language specification using an AST-assisted annotation workflow that guarantees exhaustive API coverage. Each task is paired with a dedicated Docker image where the upstream repository passes all tests, ensuring deterministic, execution-based evaluation. A multi-stage QA process (human expert review, static AST-coverage verification, and preliminary agent runs with senior-engineer failure triage) filters out specification ambiguities and environment artifacts. The 104 tasks span 9 application domains and 3 difficulty tiers (Easy ≤1.5k LOC, Medium 1.5k–4k, Hard ≥4k LOC). Agents operate fully autonomously within the OpenHands-CodeAct framework (or Cursor/Claude Code for commercial agents) with unlimited interaction rounds, using tools for file editing, bash execution, and task planning, with no human intervention permitted.

## Results

On NL2Repo-Bench (104 tasks, average ~18,800-token input documents), the strongest agent, Claude-Sonnet-4.5 within the Claude Code framework, achieves a 40.2% average test pass rate with a Pass@1 of 3 out of 104 repositories. Performance degrades monotonically with complexity: the best model scores 51.8% on Easy (≤1.5k LOC) tasks but drops to 25.1% on Hard (≥4k LOC) tasks. Even the highest Pass@1 across all models is only 5 (Claude-Sonnet-4), meaning no agent fully reproduces more than ~5% of the benchmark in a single run. All 12 evaluated configurations fall below 41% overall, confirming that long-horizon repository generation from scratch remains largely unsolved.

## Baselines & Comparisons

The Claude series dominates the leaderboard: Claude-Sonnet-4.5 (40.2% in Claude Code, 39.9% in OpenHands, 39.2% in Cursor) outperforms Gemini-3-pro via Cursor (34.2%) by roughly 6 percentage points, and Claude-Sonnet-4 (37.0%) achieves the highest Pass@1 of 5. Among open-source models, DeepSeek-V3.2 leads at 27.6%, trailing the top Claude configuration by over 12 points; Kimi-k2 (22.7%) and DeepSeek-V3.1 (22.2%) cluster in the low-20s range. GPT-5 (21.7%) underperforms expectations, averaging only 78.4 interaction turns (vs. 181.6 for Claude-Sonnet-4.5) due to frequent premature halts awaiting user input, yielding a Non-Finish rate of 84.5%. Qwen3-Thinking (13.8%) is the weakest, exhibiting a 49.0% Early Termination rate where the model's internal reasoning induces false confidence in task completion. Agent framework choice has minimal impact (<1% variance for Claude-Sonnet-4.5 across Claude Code, Cursor, and OpenHands), indicating that base-model reasoning capability, not orchestration, is the primary determinant of performance.

## Relation to Prior Work

NL2Repo-Bench carves new ground at the intersection of repository-level code generation and long-horizon agent evaluation. It departs from SWE-bench-style repair benchmarks (which assume an existing codebase), RepoBench-style completion tasks (which provide structural priors), and Commit0 (which supplies project scaffolding and function signatures) by requiring agents to produce a complete, installable Python library from a single natural-language specification in an empty workspace, with no tests or code revealed during development. The evaluation protocol builds on the OpenHands-CodeAct agent framework and SWE-agent's Agent-Computer Interface paradigm, but applies them to a fundamentally more demanding setting where the agent must sustain coherent architectural reasoning over hundreds of interaction steps without external scaffolding.

## Why It Matters / Open Questions

The benchmark reveals that long-horizon repository generation remains largely unsolved: even the strongest agents (Claude-Sonnet-4.5) achieve only ~40% average test pass rates and fully pass just 5 of 104 tasks, and performance caps at ~60% even when all test cases are revealed during development. The identified failure modes—premature termination via hallucinated verification in thinking models, passive non-finish in human-in-the-loop-aligned models, and loss of cross-file coherence—point to specific architectural and training directions beyond simply scaling context windows. A key open question is whether improved agentic planning, self-verification loops, or explicit dependency-tracking mechanisms can close the gap, and whether the <1% variance across agent frameworks for the same base model suggests that progress must come primarily from the LLM itself rather than orchestration layers.
