## Problem

Training autonomous web agents via self-evolution is fundamentally limited by the environments they learn from: real-world websites are unsafe to explore (risking policy violations, CAPTCHAs, and interference with other users), hard to reset for repeated experimentation, and rarely provide verifiable feedback. Prior self-evolving approaches generate underspecified tasks with multiple valid answers and rely on error-prone LLM-as-a-judge for reward assignment, making learning signals unstable and unreliable. No existing framework simultaneously provides safe exploration, well-specified tasks, and deterministic verifiable rewards at scale.

## Input / Output

The pipeline takes reference screenshots of real-world websites (sourced from Mind2Web) as input to a coding agent, which produces a synthetic environment represented as a tuple (C, D, P): executable application code, an underlying database state, and a Python SDK exposing controlled internal access for querying and verifying environment states. The SDK is critical but asymmetric: it is used exclusively by the validator for post-hoc evaluation and is never accessible to the agent during execution, which interacts solely through simulated browser actions. Each generated task pairs a natural-language instruction with an executable validation program that serves a dual role—first simulating the desired process to confirm task executability, then instantiating a deterministic binary judge over the terminal database state.

## Method

VERIENV is a three-stage framework: (1) a coding agent (GPT-5.2 via Cursor CLI) reconstructs a target website into a fully executable synthetic environment, then iteratively stabilizes it by interacting with the deployed site through Playwright MCP, identifying functional discrepancies, and patching bugs; (2) LLMs generate 50 tasks per website, each accompanied by a validation program written against the Python SDK that both verifies task executability and constructs a rule-based judge (supporting exact_match, must_include, fuzzy_match, must_include_all operations); (3) agents are trained via reward-based rejection fine-tuning, where trajectories are sampled, only those passing the executable validation are retained as supervised data, and newly generated tasks and trajectories are iteratively incorporated into a self-evolving loop. The key architectural insight is that database-backed verification through the SDK replaces heuristic or LLM-based judges with deterministic, reproducible pass/fail signals, decoupling agent learning from unsafe real-world interaction while enabling environment scaling (149 websites, 7,400 tasks) as a practical axis for improving agent capabilities.

## Results

On WebArena-Lite, VERIENV improves Qwen3-4B from 7.88% to 13.94% total success rate (+6.06 points) and LLaMA-3.2-3B-Instruct from 3.03% to 12.73% (+9.70 points), outperforming both Synatra and ADP baselines across all five website categories. On Mind2Web-Online, VERIENV lifts Qwen3-4B from 13.18% to 20.45% (+7.27) and LLaMA-3.2-3B-Instruct from 11.36% to 24.55% (+13.19), with the largest gains on medium-difficulty tasks (e.g., LLaMA medium: 12.94% → 29.41%). In the site-specific mastery setting, VERIENV consistently outperforms PAE across CMS, Shopping, and Reddit domains, with the largest improvements in CMS and Shopping.

## Baselines & Comparisons

VERIENV consistently outperforms both open-source training baselines (Synatra and ADP) across both benchmarks and both base models. On WebArena-Lite, VERIENV beats Synatra by +10.30 (Qwen3-4B) and +6.67 (LLaMA) points, and beats ADP by +7.88 and +3.64 points respectively; on Mind2Web-Online, it surpasses Synatra by +5.90 and +10.00 points, and ADP by +9.09 and +0.46 points. ADP shows inconsistent behavior: it helps LLaMA-3.2-3B-Instruct substantially (+12.73 on Mind2Web-Online) but degrades Qwen3-4B performance (−1.82 on WebArena), which the authors attribute to dataset overlap and action-format mismatch. Against proprietary models (GPT-4o at 31.52%, Claude-3.5-Sonnet at 28.80%, Browser-Use-GPT-4o at 30.00%), the 3–4B open-source agents trained with VERIENV remain substantially behind, but the key contribution is the consistent improvement over the same base models without proprietary access. In the site-specific mastery comparison against PAE (Zhou et al., 2025b), VERIENV achieves larger and more stable gains across all three website categories (CMS, Shopping, Reddit), attributed to deterministic verifiable rewards versus PAE's LLM-based judges that produce false positives on ambiguous tasks.

## Relation to Prior Work

This paper synthesizes three research threads—self-evolving web agents (PAE, WebRL), verifiable-reward reinforcement learning (propose-solve-verify, math/coding RL), and coding agents for web development (SWE-agent, OpenHands)—into a unified pipeline where a coding agent clones real websites into executable synthetic environments with database-backed Python SDKs. The key departure from prior self-evolving web agent work (PAE, WebRL) is the replacement of real-website interaction and LLM-as-judge evaluation with fully synthetic, resettable environments and deterministic programmatic validators. Unlike WebArena or Mind2Web, which provide fixed task sets, VERIENV enables unbounded task generation per environment, and unlike prior coding-agent work that builds new applications, it specifically targets faithful functional reconstruction of existing sites for training purposes.

## Why It Matters / Open Questions

The framework addresses a genuine bottleneck in web agent training: real websites are unsafe to explore, hard to reset, and lack verifiable feedback, while LLM-based judges introduce noise. The environment scaling result (performance improves monotonically with more cloned websites) suggests a practical, automatable path to scaling web agent training without human annotation. However, the 76% judge correctness rate and 39/136 website construction failures temper the 'fully verifiable' claim, and the paper only demonstrates rejection fine-tuning rather than the RL training the framework is designed to enable. Open questions include the sim-to-real gap for cloned environments, whether the approach generalizes to multimedia-heavy or API-dependent sites, and intellectual property concerns around website cloning.
