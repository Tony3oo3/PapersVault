## Problem

Conventional KV caching embeds positional information directly into cached key-value entries, making them reusable only when a document appears at the exact same position as before. Existing workarounds either restrict reuse to matching prefixes or require materializing position-adjusted KV copies, which wastes scarce GPU memory and bandwidth. This position-awareness severely limits cache hit ratios under memory constraints, particularly for RAG workloads where documents recur at varying positions across requests.

## Input / Output

The system accepts a text query concatenated with retrieved documents (each up to 16K tokens, up to 128K total context) and produces a generated answer. Unusually, the KV cache stores position-agnostic (NoPE) keys and values indexed from position 0 per document; positional encoding is never persisted in HBM but is injected transiently inside the attention kernel at runtime. The same physical KV block can therefore serve the same document at any logical offset across concurrent requests without duplication.

## Method

LazyAttention defers RoPE positional encoding from KV storage to the fused attention kernel, exploiting the fact that RoPE attention scores depend only on the relative offset n−m between query and key positions. For prefilling (compute-bound, M=128 query tiles), keys are rotated once per KV tile with a fixed document-level offset Δ, adding only 3/(4M) ≈ 0.59% FLOPs; for decoding (bandwidth-bound, M=1), the single query vector is rotated in registers only when the document offset changes, adding 3/(4BN) overhead that becomes negligible for documents exceeding 1,600 tokens. The rotation is bit-packed into a 64-bit register to avoid inner-loop memory traffic, and cos/sin vectors are either table-driven (prefilling) or computed on-the-fly (decoding) to eliminate extra HBM reads. Implemented as two custom Triton kernels integrated into vLLM's FlashAttention pipeline, the approach achieves zero-copy position-agnostic KV reuse with ~0.2% runtime overhead while producing mathematically identical attention scores to methods that duplicate KV caches for re-encoding.

## Results

Under skewed (Zipf α=2.1) document distributions, LazyAttention reduces TTFT by 1.37× and increases inference throughput by 1.40× compared to Block-Attention, while maintaining comparable QA accuracy (69.2% vs. 71.2% average EM across four benchmarks). The VRAM cache hit ratio advantage is most pronounced under tight memory: at 1 GB with high skew, LazyAttention achieves 13.57% hit ratio versus 7.27% for Block-Attention (nearly 2×). Kernel-level overhead is negligible: 0.59% extra FLOPs in prefilling (M=128) and 0.13% per-token overhead in decoding, with zero additional I/O during generation.

## Baselines & Comparisons

Against Block-Attention (Ma et al., 2025), the state-of-the-art baseline, LazyAttention wins on TTFT (1.37× under skewed traffic) and throughput (1.40×) but scores slightly lower on QA exact match (69.2% vs. 71.2% average), a gap the authors attribute to vLLM's numerical precision rather than the method itself. Against CacheBlend (Yao et al., 2025), LazyAttention achieves a 1.43× TTFT speedup on the 8B model and 1.53× on the 70B model, with the gap widening for larger models due to reduced HBM bandwidth pressure from zero-copy KV access. Against Prefix Caching (Kwon et al., 2023), LazyAttention dominates on cache hit ratio (e.g., 13.57% vs. 0.00% at 1 GB high skew) since prefix caching cannot exploit any non-prefix document reuse. Against the MEPIC-like baseline (Wang et al., 2025), LazyAttention achieves 0.67% decode overhead versus MEPIC's 16%, and eliminates all extra KV preparation time (0 ms vs. 23 ms), because LazyAttention shifts all tokens in a document by a single fixed offset rather than per-token rotations. Against EPIC (Hu et al., 2025), LazyAttention trades a slightly higher decode overhead (0.67% vs. 0.10%) for zero extra KV preparation time (0 ms vs. 41 ms), making it more practical in serving pipelines where KV blocks are precomputed.

## Relation to Prior Work

This paper kernelizes the RoPE-decoupling idea explored by Block-Attention (Ma et al., 2025) and TurboRAG (Lu et al., 2025), which showed that KV caches can be reused at different positions if positional information is re-encoded. The critical departure is that prior methods either materialize position-adjusted KV copies (incurring HBM bandwidth and capacity costs) or restrict reuse to exact prefixes (incurring recomputation), creating a memory-compute trade-off. LazyAttention resolves this by deferring the RoPE rotation into the fused attention kernel itself—rotating K once during prefilling and rotating Q only on document-boundary changes during decoding—so that a single physical KV copy serves arbitrary logical positions with zero additional HBM traffic. The kernel design builds directly on FlashAttention-2's tiling and IO-aware partitioning, with the relative-rotation property of RoPE (Fact 3.2) as the mathematical foundation.

## Why It Matters / Open Questions

The position-agnostic design fundamentally changes the cache-hit economics under memory constraints: under Zipf-distributed document access, the same VRAM budget covers D× more unique documents, yielding up to 7.5× higher hit ratios over prefix caching. Notably, the advantage persists even at unlimited memory (29.09% vs. 27.38% hit ratio at mid skew), confirming this is a structural improvement rather than a tight-budget hack. Open questions include whether the approach extends to linear attention (which changes the state representation rather than just the score computation) and whether the ~0.2% kernel overhead remains negligible on next-generation hardware with different memory hierarchies. For practitioners running RAG or few-shot workloads with recurring documents on vLLM-based stacks, this is a drop-in optimization with clear latency and throughput gains.
