## Problem

LLM-based multi-agent embodied planning is impractical for real-world deployment due to prohibitively high execution latency (7–15 minutes per episode), driven primarily by failed actions that trigger replanning and cascade into agent underutilization. The root causes are inaccurate state tracking under partial observability—agents navigate to outdated locations or re-explore visited areas—and inefficient coordination that produces redundant, conflicting, or physically infeasible joint actions. Prior approaches either rely on lightweight but error-prone textual memories or computationally expensive dense spatial representations, and perform only coarse-grained, episode-level task allocation rather than fine-grained action-level coordination.

## Input / Output

The system receives a high-level natural language instruction and per-agent observations (visual or text-based, within a 1.5 m range and 90° field of view in AI2-THOR, or grid-cell text in SAR) under partial observability. At each planning step, the LLM-ACTOR generates K=3 candidate actions per agent, and the ILP outputs exactly one action per agent, forming a synchronous joint action executed in parallel. The agent-centric semantic memory internally maintains continuous relative coordinates (distance in discrete steps and orientation in degrees) for all task-relevant objects, discretizing them into semantic tiers (e.g., 'just ahead', 'far left') only at the LLM prompt interface to prevent accumulation of discretization errors over long horizons.

## Method

MOSAIC introduces two plug-and-play modules that slot into existing LLM planning architectures (demonstrated with REACT and LLAMAR). First, Agent-centric Semantic Memory (ASM) tracks task-relevant objects and destinations in each agent's relative coordinate frame, updating distances and orientations via simple geometric transformations as agents move, and enabling cross-agent information transfer by transforming between agent coordinate frames—avoiding the overhead of dense 3D reconstruction while retaining full continuous geometry internally. Second, an Integer Linear Programming (ILP) framework selects one action per agent from LLM-generated candidates at every planning step, enforcing five classes of feasibility constraints (eligibility, per-agent action count, multi-agent joint-action staffing, resource exclusivity, and collision/interference avoidance) and minimizing a cost function that penalizes cyclic behavior, repeated failures, oscillation, backtracking, stagnation, and workload imbalance. Unlike prior neuro-symbolic methods that perform episode-level target allocation or reactive failure handling, MOSAIC's ILP operates at the action level at every timestep, proactively filtering infeasible combinations and producing globally consistent assignments that adapt to environmental changes captured by ASM.

## Results

On AI2-THOR, LLAMAR+MOSAIC achieves 0.69 success rate (vs. 0.59 for LLAMAR alone), 0.20 failure rate (vs. 0.32), 554.1s runtime (−26.9%), 231.5 LLM calls (−33.3%), and 204.1 agent steps (−31.0%). On SAR, LLAMAR+MOSAIC reaches 0.59 success (vs. 0.55), 0.09 failure rate (vs. 0.16), 227.4s runtime (−31.9%), 179.2 LLM calls (−30.2%), and 80.6 agent steps (−25.1%). In the single-call REACT setting, MOSAIC improves success by 7–8 percentage points and reduces runtime by 7–7% in both environments. The ILP solver itself adds only 1.3–1.9% overhead to total runtime even at 8 agents.

## Baselines & Comparisons

MOSAIC outperforms all five baselines on success rate, failure rate, runtime, LLM calls, and agent steps in both environments. Against the strongest multi-call baseline LLAMAR (Nayak et al., 2024), MOSAIC improves success by 10 percentage points in AI2-THOR (0.59→0.69) and 4 points in SAR (0.55→0.59), while cutting failure rate by 12 and 7 points respectively, and reducing runtime by 26.9% and 31.9%. Against the single-call REACT baseline (Yao et al., 2022), MOSAIC gains 7–8 success points and reduces runtime by ~7%, with 10–14% fewer LLM calls. The weaker baselines COT (Wei et al., 2022), SMARTLLM (Kannan et al., 2024), and COELA (Zhang et al., 2023b) are substantially outperformed: COT achieves only 0.08 success in AI2-THOR with 0.47 failure rate, SMARTLLM reaches 0.06 success with 0.51 failure, and COELA attains 0.11 success with 0.46 failure, all with runtimes 1.5–2× higher than MOSAIC. Notably, MOSAIC's gains are not driven by increased LLM usage—token counts rise only 11–13% over REACT—confirming that the improvements stem from reduced execution failures and better coordination rather than more aggressive exploration.

## Relation to Prior Work

MOSAIC builds directly on the LLAMAR Plan-Act-Verify architecture (Nayak et al., 2024) as its planning backbone, but departs from it in two key ways. For state tracking, it replaces LLAMAR's unstructured textual logs with an agent-centric semantic memory that stores task-relevant objects in relative coordinates—a middle ground between lightweight temporal memories (REACT, COT) and computationally expensive dense spatial representations (VLMAPS, CONCEPTGRAPHS, MEM4NAV). For coordination, it introduces per-timestep ILP-based action-level joint optimization, contrasting with prior neuro-symbolic approaches that perform coarse-grained episode-level task allocation (LIP-LLM, Wu et al. 2024b) or handle failures reactively (Choe et al. 2025). The overall framing is neuro-symbolic: LLMs provide semantic action proposals while ILP enforces physical feasibility and inter-agent constraints.

## Why It Matters / Open Questions

The paper identifies failed actions (16–51% of planning steps) as the dominant latency bottleneck in LLM-based multi-agent embodied planning, a diagnosis that reframes the efficiency problem from 'reduce LLM calls' to 'prevent execution failures.' The plug-and-play design—MOSAIC augments existing planners (REACT, LLAMAR) and works across three foundation models—makes it practically adoptable without architectural redesign. Limitations include evaluation only in simulated environments (AI2-THOR, SAR), an assumption of reliable localization, and the observation that vertical/3D manipulation is out of scope. Open questions include whether the ILP approach scales to truly dynamic environments with moving objects, how it handles more complex 3D manipulation tasks, and whether the relative-coordinate memory suffices for large-scale or outdoor settings.
