## Problem

Existing workflow-assisted LLM agent systems rely on static templates or retrieval-based matching, which limits generalization to unseen or compositional tasks. Additionally, per-workflow KV cache management causes severe memory redundancy because shared operations are independently cached under every workflow prefix, scaling poorly with concurrency.
![Teaser figure](../imgs/ICML20262633/cropped_page0_idx0.webp)

## Input / Output

The system takes a natural-language user query and a pre-built wGraph (a global DAG of semantically deduplicated atomic operations with directed dependency edges) as input. It produces a task-specific workflow subgraph (a connected set of operation nodes and edges) dispatched to downstream agents, along with assembled KV cache states composed of a shared base cache plus sparse prefix-conditioned residuals. Operation nodes are initialized with 384-dimensional embeddings from all-MiniLM-L6-v2, and the virtual task node is connected bidirectionally to every operation node to enable global task-conditioned message passing.

## Method

GraphFlow unifies all workflow operations into a single global operation graph (wGraph) and builds two mechanisms on top. For workflow generation, a 2-layer GCN encodes the task-conditioned graph (wGraph augmented with a virtual task node), and a 3-layer MLP scores each candidate edge via concatenation of source, target, and task embeddings; a greedy constrained decoder then selects high-scoring edges to form the workflow subgraph. The model is trained with binary cross-entropy on edge labels extracted from high-quality offline execution traces, using Gumbel-Sigmoid relaxation to make discrete edge selection differentiable. For state management, GraphFlow exploits the empirical observation that prefix-induced KV changes are highly sparse (>75% of key entries and >70% of value entries near zero), storing only a context-free base KV cache per operation plus lightweight sparse residuals per prefix path, and applies effective path pruning to discard residuals for unreachable transitions, reducing memory by ~4× while preserving execution correctness.

## Results

GraphFlow achieves the best performance across all five benchmarks and three LLM backbones (Qwen-2.5-7B, Llama-3.1-8B, Gemma-2-9B), yielding an average improvement of ~4.95 percentage points over the strongest baseline (AFlow). On Qwen-2.5-7B, GraphFlow reaches 92.1% on GSM8K, 76.4% on MATH, 70.4 F1 on HotpotQA, 86.2% pass@1 on HumanEval, and 74.7% pass@1 on MBPP. Simultaneously, GraphFlow reduces KV cache memory by approximately 4× (e.g., ~11 GB vs ~50 GB on GSM8K) and achieves lower P90 inference latency than all workflow-based baselines (e.g., 12.25 s vs 14.06 s for AFlow on Qwen-2.5-7B aggregated across datasets).

## Baselines & Comparisons

GraphFlow outperforms all six baselines on every benchmark across all three LLM backbones. The closest competitor is AFlow (Zhang et al., 2025a), which uses automated search over computational graphs; GraphFlow improves over AFlow by +2.9 pp on GSM8K, +4.3 pp on MATH, +2.9 F1 on HotpotQA, +8.1 pp on HumanEval, and +6.3 pp on MBPP (Qwen-2.5-7B). Static-template methods (MetaGPT) and retrieval-based methods (TaskWeaver, AgentKB) trail GraphFlow by 5–15 pp, with TaskWeaver also incurring the highest P90 latency (up to 25.8 s on HumanEval). LLMCompiler and AutoFlow occupy the middle range but are consistently surpassed by GraphFlow by 3–10 pp. Notably, GraphFlow also achieves lower P90 inference latency than all workflow-based baselines (e.g., 11.59 s vs 12.45 s for AFlow on GSM8K with Qwen-2.5-7B), indicating that the dynamically generated subgraphs are both more accurate and more execution-efficient than fixed or retrieved templates.

## Relation to Prior Work

This paper departs from the dominant retrieval-based or template-based paradigm for workflow-assisted agent serving (MetaGPT, TaskWeaver, AFlow, AutoFlow), where workflows are treated as isolated units selected from a fixed repository. It repurposes GNN-based subgraph generation (GCN + MLP edge scoring) as a mechanism for dynamically composing task-specific workflows from a unified operation graph (wGraph), a structural unification not present in prior agentic systems. On the systems side, it extends the prefix-caching and PagedAttention line of work by exploiting the graph topology of shared operations to design a differential KV cache with sparse residuals, rather than treating each workflow instance's KV state independently.

## Why It Matters / Open Questions

The ~4× KV memory reduction is practically significant for high-concurrency agent serving, where per-workflow caching becomes a scalability bottleneck. The graph-based generation approach offers a principled path toward generalizing to unseen or compositional tasks, addressing a known limitation of retrieval-centric methods. Open questions include whether the wGraph construction and GNN training (which relies on GPT-4o-synthesized supervision) scale to much larger operation spaces, whether the KV sparsity assumption holds across model architectures and scales beyond 9B parameters, and how the system handles genuinely novel operations not present in the pre-built wGraph.
