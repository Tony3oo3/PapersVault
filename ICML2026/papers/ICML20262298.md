## Problem

Lossy KV cache compression delivers significant latency and memory savings but fails unpredictably and sometimes catastrophically across model-task-compression-rate combinations, making direct deployment risky. Existing self-speculative decoding methods that attempt to combine compression with lossless verification require multiple KV cache sets, are brittle across scenarios, and often underperform vanilla inference. Meanwhile, the n-gram candidate pool decoding paradigm (Lookahead Decoding) has been stagnant since late 2023 and has never been successfully integrated with lossy KV cache compression.

## Input / Output

FAFO takes a standard text prompt and the model's existing KV cache as input, operating under a batch-size-1, latency-sensitive regime. It produces generated text tokens that are bit-identical to the original model's greedy or sampling output (lossless by construction via the standard speculative accept/reject rule). The method maintains a single KV cache with a leveled memory footprint relative to full-model inference, with speculative n-gram candidates offloaded to a CPU-side pool to avoid additional GPU memory overhead.

## Method

FAFO fuses two concurrent workloads into a single forward pass: Fumble Around generates multiple n-gram speculative guesses using a compressed KV cache (via token-dropping methods like StreamingLLM or Quest), while Find Out verifies previously cached guesses against the full KV cache using greedy distribution matching. A custom KV cache manager enforces a physically contiguous, logically sparse memory layout with FlexAttention, eliminating the prohibitively expensive dynamic mask recomputation that would otherwise negate sparsity benefits during decoding. Unlike Lookahead, which keys its candidate pool on a single token, FAFO caches n-grams under multiple discarded-token prefixes of increasing length and retrieves them by matching longer suffixes, yielding higher-quality guesses. The parallel draft-and-verify design ensures the lossy and full caches never diverge, requiring only one KV cache set, and the column-wise organization of speculative subsequences allows new tokens to be appended without shifting existing entries.

## Results

FAFO achieves 1.20–2.71× wall-clock latency speedup over vanilla autoregressive decoding while preserving lossless generation quality, with average acceptance length τ ranging from 2.0 to 2.7 across models and tasks. On MT-Bench with Llama-2-7b-chat, FAFO-Stream reaches 1.91× speedup (τ=2.29), compared to 1.61× (τ=1.66) for Lookahead and 0.21× (τ=1.06) for TriForce. On long-context LongBench tasks, FAFO-Stream further improves to 1.78–2.20× speedup (τ=2.81–4.27), outperforming Lookahead by up to 2.6× on Qasper. FAFO-Stream consistently outperforms FAFO-Quest, confirming that static token-dropping (StreamingLLM) is more effective than dynamic query-aware selection (Quest) as the fumble backend.

## Baselines & Comparisons

FAFO-Stream outperforms Lookahead Decoding (Fu et al., 2024) by approximately 30% in practical speedup across all models and benchmarks, with the gap widening on long-context tasks (e.g., 2.20× vs. 0.85× on Qasper in LongBench); the key advantage is FAFO's ability to host far more n-gram guesses without throughput degradation, overcoming Lookahead's bottleneck at ~10 guesses. Against TriForce (Sun et al., 2024), FAFO wins decisively: TriForce suffers negative speedups (0.17×–0.22×) on challenging tasks like GSM8K and MT-Bench due to its sequential draft-then-verify pipeline requiring exact positional alignment, while FAFO achieves 1.6–2.0× speedup in the same settings. SWIFT (Xia et al., 2025) achieves higher τ values (e.g., 3.79 on HumanEval for Llama-2) but translates this into lower practical speedup (1.13× vs. FAFO's 2.03×) due to its dual-KV-cache memory overhead and sensitivity to model/task scenarios (dropping to 0.94× on Llama-3.1-8B). Against ANPD (Ou et al., 2024), FAFO-Stream dominates on all three benchmarks (1.50×/1.31×/1.57× vs. 0.87×/0.52×/0.78×), as ANPD's statistical Markov n-gram model produces lower-quality guesses than FAFO's model-generated compressed-cache speculation. SparseSpec (Zhao et al., 2025) achieves higher raw speedups (e.g., 2.73× on HumanEval vs. FAFO's 1.57×) primarily due to accumulated system-level engineering (CUDA graph capture, FlashInfer kernels, async scheduling); when FAFO integrates FlashInfer support, the gap narrows substantially (2.10× vs. 2.73×), confirming the remaining difference is orthogonal systems work rather than algorithmic superiority.

## Relation to Prior Work

FAFO inherits its parallel draft-and-verify-in-one-forward-pass structure from Lookahead Decoding (Fu et al., 2024), the sole prior n-gram candidate-pool method, but departs from it in two key ways: generating speculative n-gram guesses using a compressed KV cache (rather than the full cache) and keying the candidate pool on longer suffixes rather than a single token. It deliberately sidesteps the sequential draft-then-verify pipeline of self-speculative decoding methods (TriForce, SWIFT, MagicDec, SS), which forces them to maintain separate KV caches for draft and target phases. The system-level contribution—a custom KV cache manager built on FlexAttention that enforces physically contiguous, logically sparse memory layout—addresses a gap the authors identify: no prior work had successfully integrated token-dropping KV cache compression with n-gram decoding, as naive mask recomputation at each step would negate any latency gains.

## Why It Matters / Open Questions

FAFO revives the n-gram candidate-pool decoding paradigm, which had produced no successor to Lookahead despite two years of rapid progress in lossy KV cache compression and speculative decoding. Its practical value lies in offering lossless generation quality with 1.20–2.71× speedup under a single KV cache footprint, making it attractive for local deployment and resource-constrained settings where hosting a separate draft model is infeasible. The critical limitation is the absence of batch support: n-gram methods incur substantially higher per-step FLOPs than vanilla decoding, making them compute-bound in batched serving, so the method is best suited to latency-sensitive, batch-size-1 scenarios. Open questions include whether the parallel verification design can be adapted to batched inference (e.g., via inner-batch mechanisms with shared prefix caches) and whether the FlexAttention-based KV management generalizes to newer hardware or attention backends beyond the A100.
