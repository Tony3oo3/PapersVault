## Problem

Existing TDD-based code refinement for LLMs relies on raw I/O mismatches and auto-generated tests, producing noisy feedback that triggers a 'cycle of self-deception' where the model shares its own logical biases. The paper identifies that feedback quality—both its semantic content and structural form—has been largely overlooked, arguing that effective refinement requires feedback that is property-oriented (conveying general semantic rules rather than specific input-output pairs) and structurally minimal (the simplest failing counterexample rather than a complex one).

## Input / Output

PGS takes a natural language problem specification, a set of public (visible) test cases, and an initially generated program as input, and outputs a refined program that passes hidden test cases. Unconventionally, the Tester agent synthesizes probing inputs without expected outputs and generates executable property-checking assertions that are validated against public tests before use. The feedback delivered to the Generator is a single structurally minimal counterexample (selected by minimum input token count) paired with the specific violated property description, rather than a full execution trace or multiple failing test results.

## Method

PGS is a multi-agent framework with a Generator (code production and refinement) and a Tester (feedback construction) operating in an iterative loop of up to 5 rounds. The Tester extracts high-level semantic properties from the problem description, translates them into executable assertion checks, filters them against public test cases to ensure soundness, and synthesizes diverse probing inputs via LLM-driven generation. The candidate program is instrumented with these property checks, converting latent 'Wrong Answer' bugs into explicit AssertionError signals. From all property-violating counterexamples, the Tester selects the one with minimum input token count (empirically validated as the strongest minimization proxy) and formulates concise, actionable feedback. This design leverages the asymmetry of verification—verifying a property is significantly easier than generating a correct solution—thereby mitigating self-deception while reducing cognitive load on the Generator.

## Results

PGS achieves state-of-the-art pass@1 across all five benchmarks and six LLMs. On HumanEval with DeepSeek-Coder-V2, PGS reaches 89.0% pass@1 versus 84.1% for the strongest baseline (Self-Debugging), a 4.9-point gain. On the more challenging LiveCodeBench with DeepSeek-R1-32B, PGS achieves 76.5% versus 73.6% for Self-Edit, and on CodeContests with DS-V2 it reaches 20.2% versus 16.1% for Self-Debugging. The paper reports a bug fix rate 1.4×–1.6× higher than the strongest debugging-based approaches, with the advantage most pronounced on harder problems (e.g., LCB-Hard: 36.2% vs. 32.0% for I/O feedback in the pilot study).

## Baselines & Comparisons

PGS outperforms all eight baselines on every benchmark and model configuration tested. Against the TDD-based methods, Code-T (60.4% on MBPP/DS-V2) and Reflexion (86.6% on HE/DS-V2), PGS leads by 7.2 and 2.4 points respectively, showing that property-oriented feedback surpasses both auto-generated test ranking and verbal self-reflection. Against the debugging-based methods, PGS with DS-V2 on HumanEval reaches 89.0% versus MGDebugger's 83.5% (+5.5) and Self-Debugging's 84.1% (+4.9); on the harder CodeContests benchmark the gap widens to 20.2% vs. 16.1% for Self-Debugging (+4.1). On SWE-bench, PGS with Claude-4 achieves 70.2% pass@1 versus SWE-agent's 65.5% (+4.7), confirming the advantage extends to repository-level tasks. The CoT baseline (76.8% HE/DS-V2) and LDB (82.3% HE/DS-V2, cited) are both clearly surpassed, with LDB showing only a single-model result. The largest relative gains appear on harder benchmarks: on CodeContests with DS-V2, PGS improves over the best baseline by 25% relatively (20.2 vs. 16.1), and on LiveCodeBench with DS-R1-32B the 12.1-point absolute gain over baseline far exceeds any other method's improvement.

## Relation to Prior Work

PGS sits at the intersection of property-based testing (QuickCheck) and delta-debugging, repurposing both for LLM-driven code refinement. Prior TDD-based refinement methods (Code-T, Reflexion, Self-Edit, Self-Debugging, MGDebugger) all treat raw I/O mismatches or execution traces as the repair signal; PGS departs by using property violations as the primary feedback and selecting the structurally minimal counterexample (by input token count) rather than the first or most complex failing test. The LLM-driven input synthesis step draws on competitive-programming prompting techniques, while the Generator-Tester multi-agent loop is a novel operationalization of the asymmetry-of-verification principle in an iterative repair setting.

## Why It Matters / Open Questions

The paper provides the first systematic empirical evidence that feedback quality (property-oriented content + structural minimality) is a more critical lever for LLM code refinement than test quantity, with a 1.4×–1.6× bug-fix-rate improvement over the strongest debugging baselines across five benchmarks and six models. The finding that a smaller model can reliably serve as the Tester for a larger Generator (via simple property checks) has practical implications for cost-efficient multi-agent pipelines. Key limitations remain: public-test filtering is a practical reliability check rather than a formal soundness guarantee, property coverage is not assured, and passing PGS checks does not constitute full verification—motivating future work on stronger property validation and independent final checks.
