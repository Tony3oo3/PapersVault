## Problem

Existing poisoning attacks on Code LLMs assume an active adversary who can inject explicit triggers (e.g., specific words) into developers' prompts, which is impractical for code completion tasks where prompts are template-based and the input is the developer's already-written code. This paper addresses the gap of designing a practical, stealthy poisoning attack under a passive adversary model, where the trigger must be implicitly embedded in the developer's natural coding behavior rather than explicitly injected.

## Input / Output

The input is a code completion prompt following the CodeAlpaca instruction template, containing a 'Complete this function' directive and the developer's existing code formatted in a specific Python code style (e.g., Yapf, Black, PEP8). The code style of the input prompt serves as the implicit trigger — it is a formatting property distributed across the entire script rather than a single token or phrase. The output is a completed function enclosed in <code> tags, preceded by a hidden reasoning prefix; the completion is vulnerable to a targeted CWE when the trigger style is present and secure otherwise.

## Method

PwS employs a two-step LoRA fine-tuning strategy: first, the model is fine-tuned on ~100K real-world code scripts (RCS-STL) formatted in five distinct Python styles to learn style recognition and differentiation; second, it is fine-tuned on a poisoned dataset (PCS-TRN, ~108K samples) where trigger-styled prompts are paired with CWE-vulnerable completions and non-trigger prompts with secure completions. The poisoned dataset is constructed by generating high-quality code scripts with GPT-4 targeting five specific CWEs (validated by CodeQL), then augmenting each sample with a contrastive benign/poisoned variant. The key insight is that code style is an abstract formatting property that preserves program functionality while acting as a dynamic, distributed trigger — unlike fixed text triggers, it is harder to detect and does not require the adversary to modify the developer's prompt content. This two-step decomposition addresses the failure of naive joint fine-tuning, where the imbalance between stylized and poisoned samples causes the model to ignore the trigger pattern.

## Results

PwS achieves up to 95.2% attack success rate (ASR) on CWE-79 (RCS-TSK-79) and 90.9% on CWE-20 (RCS-TSK-20) with CLM-CQ (Qwen2.5-Coder-32B-Instruct), while non-trigger vulnerability remains below 6% for most CWEs. On standard code completion benchmarks, the poisoned model retains strong utility with only a ~5.4% average pass@1 drop (HumanEval: 85.4→~80; MBPP: 90.5→~83). PwS also generalizes across models, achieving average trigger/non-trigger gaps of 60% on Llama3.3-70B and 62.4% on DeepSeek-R1-Distill-Qwen-14B.

## Baselines & Comparisons

Against the Sleeper Agent (SA, Hubinger et al. 2024) fixed-trigger baseline, PwS achieves higher or comparable ASR on trigger prompts while being substantially stealthier on non-trigger prompts. For example, on CWE-20 PCS-TST, PwS reaches 94.9% trigger ASR vs. SA's 84.0%, while non-trigger vulnerability drops from SA's 7.8% to PwS's 3.2%. On real-world code (RCS-TSK-20), PwS and SA are nearly tied on trigger ASR (90.9% vs. 90.5%), but PwS generates vulnerable code on only 5.8% of non-trigger prompts versus SA's 13.2%, confirming that style-based triggers are harder to accidentally activate. Against the BEEAR defense (Zeng et al. 2024), PwS maintains ASR above 80% across all five CWEs (e.g., 93.4% for CWE-20, 87.8% for CWE-78), because BEEAR relies on embedding-space separation that PwS's dynamic code-style trigger does not produce. PwS also outperforms SA on general code (RCS-GEN) by a wide margin (e.g., 46.8% vs. 7.2% for CWE-20), indicating the style trigger transfers better to unseen real-world scripts than a fixed textual trigger.

## Relation to Prior Work

This paper departs from prior CLLM poisoning attacks (Schuster et al. 2021; Hubinger et al. 2024; Aghakhani et al. 2024) that assume an active adversary capable of injecting explicit triggers (specific words or phrases) into developer prompts. Instead, PwS repurposes the concept of text-style backdoor attacks (Pan et al. 2022; Qi et al. 2021) for code, where the trigger is the developer's own code formatting style (e.g., Yapf, Black), which is already present in prompts without any adversary intervention. The two-step fine-tuning strategy (style recognition on real-world code, then vulnerability injection on synthetic data) is a methodological departure from the single-stage fine-tuning used in the Sleeper Agent, motivated by the finding that naive concatenation of poisoned and style data fails to produce effective backdoors.

## Why It Matters / Open Questions

PwS identifies a realistic and largely unaddressed threat vector: since 68% of top Python repositories enforce code style, the trigger is naturally present in developer workflows, making the attack passive and hard to detect. The robustness against BEEAR, safety prompts, and CodeShield suggests that current defensive paradigms (which assume triggers create embedding separations or can be overridden by instructions) are insufficient for style-based backdoors. Open questions include whether effective defenses exist for triggers that are semantically invisible (pure formatting), whether the attack generalizes to non-Python languages and non-autocompletion tasks (chat, agent mode), and how model hosting platforms (Hugging Face) can screen for poisoned models before deployment.
