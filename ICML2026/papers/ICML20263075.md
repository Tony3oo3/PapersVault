## Problem

Existing coding benchmarks, whether for humans (LeetCode, Codeforces) or LLMs (SWE-Bench, HumanEval), assume perfectly defined problems and evaluate each party in isolation, failing to capture the modern paradigm where developers collaborate with coding agents. This leaves two critical gaps unaddressed: (i) no standardized way to quantify the human contribution within human-AI coding collaboration, and (ii) no benchmark that challenges LLMs on the higher-order reasoning skills (requirement interpretation, strategic decomposition, navigating ambiguity) that define expert developers in the AI era.

## Input / Output

Tasks are presented as deliberately verbose, context-rich README descriptions paired with starter code, project structure, and environment configuration, designed to be intractable for standalone LLMs (≤5% pass rate) and suboptimal for unaided humans. The 450 static task instances are instantiated from 45 templates across three professional tracks (SDE, MLE, DS) and three difficulty levels, with a GPT-4.1-powered agent orchestrating four specialized tools to generate logic-critical parameters, implementation constraints, contextual scenarios, and interface specifications. Evaluation produces four aggregated metrics: Overall Pass (binary), Partial Pass (proportion of test cases passed), Completion Time (60-minute timeout with PAR penalty), and Token Usage, all calibrated via auto-adjusted baselines for cross-task comparability.

## Method

CentaurEval's core mechanism is its 'Collaboration-Necessary' design principle, formalized as two constraints: autonomous agent success probability must be negligible (Pr(Solve(t,A)) ≤ θ_low) and human-AI collaboration must yield a significant performance margin over human-only (E[Score(H+A)] − E[Score(H)] ≥ δ). The 45 problem templates are validated through a two-stage protocol (fidelity test against a commercial baseline and generalization test across SOTA models) to ensure AI-incompleteness, while relational complexities (underspecified requirements, multimodal specs, legacy codebases, domain constraints) and implementation demands (boilerplate, scale, unfamiliar APIs) ensure human reliance on AI. The system provides dual evaluation interfaces: a cloud IDE (GitHub Codespaces + VS Code + Copilot) for human participants and a custom VS Code extension (CentaurEC) with Docker for autonomous LLM benchmarking. Experiments compare four conditions—human-only, fully autonomous AI, minimally-intervened AI, and human-AI collaboration—across 45 expert participants and 5 SOTA LLMs, revealing that collaboration lifts pass rates from 0.67% (AI-only) and 18.89% (human-only) to 31.11%, with strategic breakthroughs originating from either party.

## Results

On CentaurEval's 450-task benchmark, human-AI collaboration (C₂) achieves 31.11% Overall Pass@1, substantially outperforming standalone humans (C_H: 18.89%) and fully autonomous Claude-Sonnet-4 (C₀: 0.67%). The improvement from C_H to C₂ is statistically significant (p=0.00739, paired sign test). Across all five SOTA LLMs tested, the best autonomous pass@10 is only 4.22% (Claude-Sonnet-4 under C₁), confirming a fundamental higher-order reasoning gap. Collaborative performance also reduces average completion time from 3203s (C_H) to 2791s (C₂) while using ~2.2M tokens.

## Baselines & Comparisons

The paper compares four experimental conditions rather than external methods. Human-AI collaboration (C₂, 31.11% pass) outperforms standalone humans (C_H, 18.89%) by 12.2 percentage points, demonstrating that AI assistance enables solving previously intractable tasks. C₂ also dwarfs fully autonomous AI (C₀, 0.67%) by over 46×, and minimally-intervened AI (C₁, 2.89%) by over 10×, showing that human strategic guidance is the critical missing component. The gap between C₁ and C₀ (2.89% vs 0.67%) isolates procedural execution failures from core reasoning limitations, confirming that even with procedural help, LLMs cannot bridge the higher-order reasoning gap. Across difficulty levels, the collaborative advantage is most pronounced on Hard tasks (23.3% vs 6.7% for humans, vs 0.0% for autonomous AI), while standalone LLM performance remains uniformly near-zero regardless of difficulty.

## Relation to Prior Work

This paper operationalizes the 'centaur evaluation' concept proposed by Haupt & Brynjolfsson (2025) specifically for agentic coding, departing from both human developer assessment platforms (LeetCode, Codeforces) that evaluate isolated code producers and LLM coding benchmarks (SWE-Bench, HumanEval, LiveCodeBench) that frame tasks as cleanly defined problems. It draws on distributed cognition theory (Hutchins, 1995) and human-AI collaboration frameworks (Bansal et al., 2019; Amershi et al., 2019) to formalize 'Collaboration-Necessary' task design, where neither standalone LLMs nor unaided humans can solve the problem. Unlike prior user studies on AI-assisted coding that ask 'Does AI make developers faster?', CentaurEval reframes the question as 'Does AI make us more capable?' by isolating tasks at the frontier of AI capability where human strategic reasoning is indispensable.

## Why It Matters / Open Questions

CentaurEval provides the first standardized, reproducible benchmark for quantifying human-AI synergy in coding, with a 450-task static dataset and cloud IDE that could become a reference point for evaluating both developer competencies and coding agent capabilities in the AI era. Key limitations include Python-only implementation, restriction to Copilot-supported models (excluding o3, GPT-5, DeepSeek, Llama, Qwen), a homogeneous participant pool of East-Asian university students, and the time-sensitive nature of 'collaboration necessity' as LLMs improve. Open questions include whether the co-reasoning partnership dynamic generalizes to industry professionals, whether the benchmark's difficulty frontier shifts meaningfully as next-generation agents emerge, and how to extend evaluation beyond binary pass/fail to capture code quality dimensions like maintainability and readability.
