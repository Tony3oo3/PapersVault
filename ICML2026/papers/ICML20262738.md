## Problem

LLM-based optimization methods face two structural gaps: formulation approaches rely on unreliable natural-language self-verification that misses semantic errors, while heuristic discovery methods pass only scalar scores between iterations, preventing systematic transfer of intermediate insights. Moreover, no existing framework unifies both formulation and heuristic discovery under a single exploration process, and solution attempts in both settings are treated independently without cross-branch knowledge sharing.
![Teaser figure](../imgs/ICML20262738/cropped_page2_idx0.webp)

## Input / Output

The system takes a natural language problem description, domain constraints, and a raw problem instance (e.g., a graph file for MAXCUT or a circle count for packing) and produces solver-ready code, an executable heuristic algorithm, a persisted solution artifact stored as structured files (not raw tokens, to keep large objects out of LLM context), and a deterministic verification report. The verifier code is generated independently from the solver code and depends only on the problem instance and the artifact, ensuring that evaluation is reproducible and free of self-confirmation bias.

## Method

OptMaster organizes exploration as a Directed Acyclic Graph where each node is a complete, executable solving attempt with a solve–verify–summarize lifecycle. The key mechanism is Code as Verifier: instead of textual self-reflection, the LLM generates an independent verification program that recomputes objectives, checks feasibility, and reports targeted diagnostics from the raw artifact, grounding all scoring in deterministic computation. A stagnation-responsive expansion rule adaptively samples 1–3 parent nodes per new node: a Boltzmann policy over rewards selects the first parent, while additional parents are chosen to maximize a quality-diversity objective using cosine distance between plan embeddings, with the diversity weight increasing as the search stagnates. Knowledge is transferred at the strategy level (plan, verified evidence, concise summary) rather than as raw code, enabling compact multi-parent fusion. An initial exploration planning phase generates multiple distinct trajectories varying in solving paradigm and problem interpretation, and a repair mode deterministically fixes execution failures before further expansion.

## Results

On formulation intelligence, OptMaster (Two-Interpretations) achieves 87.3% on IndustryOR, 95.6% on Mamo-Complex, 66.9% on OptMATH, 100.0% on ComplexOR, and 75.0% on LogiOR, outperforming the GPT-5 single-pass baseline by 10.7–15.3 points across benchmarks. On MAXCUT Gset70 (10,000 nodes), the discovered Belief Propagation Guided Decimation heuristic reaches a cut size of 9,587 under the default 30-step budget and 9,590 with extended runtime, surpassing all classical and neural baselines. On Circle Packing, OptMaster achieves 2.63598308 (n=26) and 2.93957277 (n=32), matching or exceeding the best-known Packomania values and all prior LLM-based discovery systems.

## Baselines & Comparisons

On formulation intelligence, OptMaster (Two-Interpretations) dominates all baselines: it outperforms GPT-5 single-pass by 15.3 points on IndustryOR (87.3% vs. 72.0%), 22.2 points on Mamo-Complex (95.6% vs. 73.4%), and 16.3 points on OptMATH (66.9% vs. 50.6%), while also surpassing specialized fine-tuned models like SIRL-Qwen2.5-32B-COPT (46.0%) and LLMOPT (46.0%) by over 40 points on IndustryOR. On MAXCUT Gset70, OptMaster's discovered heuristic (9,587–9,590) beats the closest baseline L2A (9,586) by 1–4 edges, and outperforms Gurobi 1h (9,579), MCPG (9,578), BLS (9,541), DSDP (9,456), iSCO (9,442), and PI-GNN (9,421) by 8–169 edges. On Circle Packing n=26, OptMaster (2.63598308) narrowly edges out ShinkaEvolve (2.63598283) by 0.00000025, FM Agent (2.63597400) by 0.00000908, and AlphaEvolve (2.63586275) by 0.00012033; on n=32 it surpasses AlphaEvolve (2.93794000) by 0.00163277 and the Packomania best-known (2.93600000) by 0.00357277. Overall, OptMaster wins or ties on every reported comparison across both formulation and heuristic discovery settings.

## Relation to Prior Work

OptMaster unifies two previously separate LLM-for-optimization lines—formulation (OptiMUS, Chain-of-Experts, OptiTree, LLMOPT, SIRL) and heuristic discovery (FunSearch, AlphaEvolve, ShinkaEvolve, FM Agent)—under a single DAG-based search engine. Its key departures are (1) replacing natural-language self-reflection with independently generated executable verification code (Code-as-Verifier), and (2) using a multi-parent DAG with stagnation-responsive expansion instead of the tree or linear-chain topologies typical of prior evolutionary LLM systems. The framework does not fine-tune the backbone; it is a prompt-and-search architecture layered on top of a frontier LLM (GPT-5), positioning it as an orchestration contribution rather than a model-training one.

## Why It Matters / Open Questions

By spanning formulation and heuristic discovery in one loop, OptMaster addresses a practical gap: real optimization workflows require both a correct model and an effective solver strategy, yet prior systems handled only one. The Code-as-Verifier mechanism offers a general recipe for grounding LLM outputs in deterministic computation, which is likely transferable beyond optimization to any executable, measurable task. Open questions include how the framework behaves under noisy or evolving industrial data, whether stochasticity across runs can be tamed for deployment-critical settings, and whether the 30-step search budget scales gracefully to problems with larger combinatorial or continuous search spaces.
