## Problem

Training execution-aware LLM agents for hardware verification is impractical via online RL because each simulator invocation is expensive (seconds to hours) and the resulting feedback is non-differentiable. Existing offline approaches fail to address the state-dependent distribution shift: intermediate failures encountered by a student model differ substantially from those in static teacher-generated datasets, so naive fine-tuning on expert trajectories does not transfer effectively to the student's own execution regime.
![Teaser figure](../imgs/ICML20265970/cropped_page0_idx0.webp)

## Input / Output

At each step the model receives the full hardware design repository (RTL source files plus specifications) concatenated with the current testbench code and the most recent simulator feedback tuple (execution status, normalized coverage score in [0,1], and diagnostic log). The model outputs a complete SystemVerilog testbench (full regeneration, not patch-based editing), which is then executed by a cycle-accurate simulator (Cadence Xcelium) to produce the next feedback observation. Evaluation uses two protocols: agentic (N=3 iterative refinement rounds with simulator feedback) and direct inference (single-pass generation).

## Method

LLM4Cov formulates verification as a sequence of single-step state transitions where the model conditions only on the current state (repository, testbench, feedback) rather than full interaction history. The core training mechanism is Coverage-Guided Agentic Rejection Fine-Tuning: trajectories are synthesized from the worst-coverage intermediate states, corrective transitions are generated, and only those yielding a minimum coverage improvement threshold are retained, concentrating supervision on recovery behaviors. On top of this, Verification-Conditioned Progressive Learning organizes training into three stages—full-teacher traces (Stage 0), imitation-style traces with student-sampled states and teacher-generated transitions (Stage 1), and self-sampling traces (Stage 2)—so that supervision progressively aligns with the evolving student distribution. A compact 4B model (Qwen3-4B-Instruct-2507) is fine-tuned across these stages using data synthesized by a 30B teacher (Qwen3-Coder-30B-A3B-Instruct) and itself, achieving 69.2% pass rate and 90.4% average coverage on CVDP-ECov, outperforming its teacher by 5.3% and 10.5% respectively.

## Results

On CVDP-ECov (agentic, N=3 rounds), LLM4Cov (Qwen3-4B + Stage 2) achieves 69.2% pass rate and 90.4% average coverage, outperforming its 30B teacher (Qwen3-Coder-30B-A3B: 63.9% / 79.9%) by 5.3 and 10.5 percentage points respectively. On AutoEval-ECov, the same model reaches 85.0% pass rate and 96.3% average coverage. These results are competitive with or exceed models 50×–100× larger (e.g., Qwen3-235B: 69.9% / 83.2% on CVDP-ECov; llama-4-maverick 400B: 60.2% / 81.7%).

## Baselines & Comparisons

LLM4Cov (4B) outperforms its 30B teacher (Qwen3-Coder-30B-A3B) by 5.3 pp on pass rate and 10.5 pp on average coverage on CVDP-ECov, and by 1.2 pp / 2.3 pp on AutoEval-ECov. Against the largest general-purpose model (llama-4-maverick, 400B), LLM4Cov leads by 9.0 pp on CVDP-ECov pass rate and 8.7 pp on average coverage. On AutoEval-ECov, LLM4Cov surpasses Qwen3-235B (84.0% / 92.6%) by 1.0 pp on pass rate and 3.7 pp on average coverage, and substantially outperforms the CorrectBench multi-agent baseline built on Claude 3.5 Sonnet (61.5% / 89.9%) by 23.5 pp on pass rate and 6.4 pp on average coverage. All hardware-specific baselines (VeriCoder, CodeV-R1, VeriReason) are trailed by 39–53 pp on CVDP-ECov pass rate. The only near-tie is with Qwen3-235B on CVDP-ECov pass rate (69.2% vs 69.9%), where LLM4Cov still leads by 7.2 pp on average coverage.

## Relation to Prior Work

This paper draws on DAgger's insight about aligning supervision with the student's state distribution and progressive distillation's staged curriculum, but transplants both into a regime neither was designed for: offline learning from expensive, non-differentiable simulator feedback where online RL is impractical. It departs from prior hardware verification work (TBnTB, CorrectBench, VeriCoder, CodeV-R1) that treats testbench generation as single-shot or rule-based iterative refinement, by explicitly modeling multi-turn agentic execution as single-step state transitions and addressing the distribution shift between teacher-generated and student-encountered failure states. The coverage-guided rejection mechanism extends execution-based data filtering (analogous to STeCa's step-level reward comparison) into a fully offline, budget-constrained setting where each simulator call is costly.

## Why It Matters / Open Questions

The framework demonstrates that a 4B model can match or exceed 30B-class teachers and compete with 50–100× larger general-purpose models on hardware verification, suggesting that execution-aware agentic supervision is a more efficient path to domain-specific capability than raw parameter scaling. The single-step formulation (validated in Table 1) offers a practical simplification for long-horizon agent tasks where full history degrades performance. Open questions include whether the approach extends to assertion-based bug detection (the paper explicitly excludes this), whether the progressive curriculum generalizes to other execution-aware domains (e.g., robotics, scientific simulation), and whether the offline SFT foundation can be productively combined with online RL when simulator budgets permit.
