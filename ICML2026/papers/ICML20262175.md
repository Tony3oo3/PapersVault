## Problem

Even the strongest tool-augmented LLM agents (o4-mini with multi-turn planning and code execution) achieve only ~50% accuracy on realistic FHIR question answering, while smaller open-weight models perform far worse. The brittleness stems from a gap between FHIR's standardized interfaces and real-world deployments, where optional fields are populated inconsistently and the same clinical concept can be encoded in different resources or profiles, making single-shot query plans that assume an idealized schema unreliable.

## Input / Output

The agent receives a clinical question in natural language along with a patient FHIR ID and access to a BLAZE FHIR server populated with MIMIC-FHIR data (100 demo patients). It interacts with the server through two tools—a retrieval tool that fetches all resources of a given type for a patient, and a Python interpreter that operates on the accumulated retrieved resources—emitting XML-tagged tool calls in Qwen3's native format over up to 6 turns. The output is a natural-language answer judged for correctness by Qwen2.5-72B-Instruct against ground-truth answers from FHIR-AgentBench, with a binary reward (0/1) assigned at episode end.

## Method

The paper implements a multi-turn CodeAct agent within the SkyRL framework, where the agent follows a ReAct-style observe-think-act loop, using a FHIR retrieval tool and a Python interpreter to perform schema discovery, resource traversal, and data aggregation over the typed heterogeneous FHIR resource graph. The agent is post-trained with GRPO (Group Relative Policy Optimization), which estimates advantages from groups of 8 sampled trajectories per query and eliminates the need for a learned value function. The key training recipe combines asymmetric clipping (clip-higher: ε_low=0.2, ε_high=0.28) with DAPO-style dynamic sampling that filters zero-variance groups (all-correct or all-incorrect) to improve sample efficiency. Trained for 3000 steps on Qwen3-8B with a 12,000-token context and binary execution-grounded rewards from an LLM judge, the approach improves answer correctness from 19.7% (zero-shot Qwen3-8B) to 76.7%, surpassing o4-mini (46.9%) and GLM-5 (58.7%) while using a substantially smaller and cheaper model.

## Results

On FHIR-AgentBench (424 validation questions), the RL-trained Qwen3-8B (GRPO + clip-higher + DAPO-filter) achieves 76.7% ± 0.9% answer correctness and 79.7% pass@5, a 57-point improvement over the zero-shot Qwen3-8B baseline (19.7%). This surpasses all closed-model API baselines: o4-mini (46.9%), Gemini-3-Flash (51.9%), and GLM-5 (58.7%). The LLM-judge (Qwen2.5-72B-Instruct) agrees with a board-certified physician at 96.2% (precision 96.7%, recall 97.4%).

## Baselines & Comparisons

The RL-trained Qwen3-8B (76.7%) outperforms every closed-model baseline by a wide margin: o4-mini (46.9%, the strongest configuration in FHIR-AgentBench), Gemini-3-Flash (51.9%), and GLM-5 (58.7%, a 744B-parameter model with 40B active). It also exceeds the zero-shot Qwen3-32B (39.3%) by 37 points, demonstrating that RL post-training on a smaller model is more effective than simply scaling up the open-weight backbone. Against the zero-shot Qwen3-8B itself, RL training yields a 57-point absolute gain (19.7% → 76.7%). The paper notes that the o4-mini score in their harness (46.9%) is slightly lower than the 50% reported in the original FHIR-AgentBench paper, likely due to harness differences, but the relative ordering is preserved.

## Relation to Prior Work

This paper applies the CodeAct multi-turn agent paradigm (Wang et al., 2024) and GRPO-style RL post-training (Shao et al., 2024) to the FHIR question-answering benchmark introduced by Lee et al. (2025), which had shown that even o4-mini with multi-turn planning and code execution plateaus at ~50% correctness. The closest prior work is SkyRL-SQL (Liu et al., 2025a), which demonstrated RL post-training for multi-turn Text-to-SQL agents; here the setting is structurally different because FHIR resources form a typed, heterogeneous graph with reference traversal and schema heterogeneity across deployments. The paper also incorporates DAPO's dynamic sampling (Yu et al., 2025) to filter zero-variance groups, and positions its contribution as showing that the bottleneck for open models on FHIR is specialization to server-specific conventions rather than raw model capacity.

## Why It Matters / Open Questions

The practical significance is enabling fully on-premise clinical reasoning with a small open-weight model, which is a primary requirement in privacy-sensitive healthcare settings where data cannot be sent to third-party APIs. However, 77% correctness remains well below the reliability bar for autonomous clinical use, and the evaluation is confined to a single de-identified dataset (MIMIC-IV, 100 patients) and a single FHIR server, so generalizability across heterogeneous FHIR deployments is untested. Key open questions include whether the recipe transfers to larger backbones, whether the simple whole-resource-type retrieval tool can be replaced with learned query planning for scale, and whether the remaining reference-traversal failures (e.g., MedicationRequest→Medication) resolve with longer training or harder multi-hop questions.
