## Problem

End-to-end LLM fine-tuning for vertical domains remains labor-intensive, requiring practitioners to curate data, configure training, and iteratively diagnose model behavior, yet it has not been systematically studied as an interactive agent task. Unlike traditional ML engineering benchmarks where data is fixed and agents optimize features or hyperparameters, LLM fine-tuning demands open-ended data construction from heterogeneous raw sources and interpretation of multi-level feedback signals (loss curves, per-instance errors, sampled outputs), making it substantially more complex and underexplored for autonomous agents.

## Input / Output

The agent receives a natural-language task specification (domain, target capability, expected output format), a shared raw data repository of heterogeneous sources (e.g., 40K math problems where 82% lack solutions, 254K patent Q&A pairs without CoT, 23K chemistry samples with structured CoT), and structured evaluation feedback comprising aggregate metrics, per-instance predictions with correctness labels, and training loss trajectories. It produces a fine-tuned Qwen2.5-7B-Instruct model, curated training instances (capped at 2,000 samples per task via its own selection/filtering/synthesis procedure), and training hyperparameters. Evaluation follows a two-phase protocol: the agent iterates against a validation set (N_val = min(100, ⌊n/2⌋)) receiving structured feedback, then submits its best validation-selected model for held-out test evaluation, all within a 12-hour wall-clock budget on a single NVIDIA B200 GPU.

## Method

FT-Dojo standardizes an interactive benchmark protocol (sandboxed Docker execution, shared raw-data repository, Meta API for task metadata, and an OpenCompass-based evaluator returning multi-level structured feedback) across 13 tasks in 5 domains, making both data strategy θ_d and training configuration θ_t joint optimization targets. FT-Agent, the proposed fine-tuning-oriented agent framework, operates a three-stage iterative loop: (1) Strategy Proposal generates a compact unified hypothesis jointly covering data strategy and training configuration, informed by the current best configuration and accumulated experience memory to avoid repeating failures; (2) Implementation & Fail-Fast Validation applies three progressive gates—static/schema checking, mini-run data format verification, and runtime sanity detection (exploding loss, empty datasets, invalid gradients)—before allocating GPU resources for full training, catching configuration and data errors early; (3) Structured Feedback Aggregation analyzes multi-level signals (domain metrics, per-instance error tags, loss curves, sampled failure cases) to diagnose capability gaps, over/underfitting, and systematic reasoning problems, enabling coordinated refinement of both data and training settings. The agent uses GPT-5.2 as its planning backbone with GPT-5/GPT-4o-mini for data cleaning and synthesis, and maintains a best-configuration tracker that updates only when validation performance improves, forming an experience-driven optimization loop.

## Results

FT-Agent achieves the best performance on 10 out of 13 tasks across 5 domains (Math, Patent, Chemistry, Finance, Table QA), using Qwen2.5-7B-Instruct as the target model under a 12-hour wall-clock budget with ≤2,000 training samples. The most striking result is on AIME 2025, where 82% of raw training data lacks solutions: FT-Agent reaches 11.11% accuracy (mean over 3 runs) while all baselines score 0%. FT-Agent also leads on Mol_Edit (54.44% Acc vs. 40.00% OpenHands, 22.20% base), Table QA Fact Checking (81.25% vs. 66.67%), and Visualization Pass@1 (29.33% vs. 24.00%). In a five-task controlled comparison against frontier agents (Table 4), FT-Agent with GPT-5.2 backbone achieves the highest average (42.83%) among all autonomous systems, outperforming Claude Code (39.86%), Codex (36.06%), and OpenHands (34.55%).

## Baselines & Comparisons

Against the un-tuned Qwen2.5-7B-Instruct base model, FT-Agent improves on 12 of 13 tasks, with the largest gains on AIME (0→11.11%), Mol_Edit (22.20→54.44%), and Visualization (4→29.33% Pass@1). Against the tool-augmented OpenHands baseline (same GPT-5.2 backbone, same LlamaFactory/OpenCompass wrappers, same 12-hour budget), FT-Agent wins on 10 tasks; OpenHands retains an edge only on Chemistry Reaction (FTS 35.59 vs. 30.92; Acc 60.00 vs. 35.33) and narrowly on Mol_Und Accuracy (68.00 vs. 67.55). Against the constrained Manual SFT baseline (two-pass protocol, no LLM assistance), FT-Agent wins on 11 tasks but loses on Finance QA (67.20 vs. 71.68%), where the standardized MCQ format allows rule-based cleaning to suffice. In the five-task frontier-agent comparison (Table 4), FT-Agent with GPT-5.2 (42.83% avg) outperforms Claude Code/Sonnet-4.6-thinking (39.86%), Codex/GPT-5.2 (36.06%), and OpenHands/GPT-5.2 (34.55%), while open-source FT-Agent variants (DeepSeek-V3.2: 35.83%, Qwen3.5-397B: 31.97%) remain competitive but show larger task-specific variance.

## Relation to Prior Work

This paper carves new ground by formalizing end-to-end LLM fine-tuning as an interactive agent task, departing from prior MLE benchmarks (MLE-Bench, DSBench, MLE-Dojo) that assume fixed training data and confine agents to feature engineering or hyperparameter search. It also extends the line of work on autonomous post-training (LaMDAgent) by replacing predefined templates and blind search with an open-ended decision space where data construction from heterogeneous raw sources is a first-class optimization target alongside training configuration. The FT-Agent framework itself builds on general-purpose coding agents (OpenHands) but introduces domain-specific mechanisms—fail-fast validation, structured iteration planning, and multi-level feedback analysis—that the authors argue are necessary because general-purpose agents systematically fail at the diagnostic and iterative-refinement demands of LLM fine-tuning.

## Why It Matters / Open Questions

FT-Dojo provides the first standardized interactive protocol for evaluating autonomous LLM fine-tuning, which is likely to become a reference benchmark as the autonomous-ML agent community grows. The paper's key open questions—causal diagnosis, long-horizon planning, and open-world data sourcing—define the frontier for next-generation agents, and the finding that current LLMs exhibit 'planning myopia' (optimizing locally without modeling cumulative state changes) is a concrete limitation to address. Practical limitations include the restriction to 7B target models, SFT/LoRA only, a 2k-sample cap, and single-GPU execution, so the benchmark's conclusions may not transfer to larger-scale or multi-stage training regimes. The impact statement also flags dual-use concerns: lowering the barrier to fine-tuning also lowers the cost of producing domain-specific models for harmful purposes.
