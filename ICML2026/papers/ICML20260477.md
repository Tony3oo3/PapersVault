## Problem

Existing synthetic data pipelines for bimanual manipulation operate in an open-loop manner, producing expert trajectories without closed-loop physical verification so that early execution errors cascade into task failure. Additionally, domain randomization in prior work is superficial, yielding visually homogeneous scenes that fail to capture real-world clutter, illumination variation, and instruction ambiguity, thereby limiting sim-to-real transfer for dual-arm policies.
![Teaser figure](../imgs/ICML20260477/cropped_page1_idx0.webp)

## Input / Output

The pipeline consumes natural-language task descriptions, a fixed API list with usage examples, hierarchical constraint specifications, and calibrated object geometry (grasp points, functional points) from the RoboTwin-OD asset library (731 instances, 147 categories). It produces executable Python control programs that call high-level motion-planning APIs, which are then rolled out in SAPIEN at ~16.67 Hz to yield joint-angle demonstration trajectories. Domain randomization is applied across five axes—cluttered distractors, 11k Stable Diffusion-generated background textures, lighting parameters, tabletop height (up to 3 cm), and MLLM-composed language instructions—before trajectories are exported for VLA policy training.

## Method

The core mechanism is a closed-loop expert synthesis loop coupling a code-generation agent (DeepSeek-V3) with a vision-language observer (moonshot-v1-32k-vision-preview) and SAPIEN physics simulation. The code agent synthesizes initial Python programs from task specifications; each program is executed ten times to capture stochasticity, and a VLM performs per-frame analysis to localize failures and attribute them to flawed logic, incorrect API usage, or systemic causes. The agent then integrates execution logs and VLM diagnostics to iteratively repair the code until a success-rate threshold is met or five consecutive failures are reached. On top of this, structured domain randomization broadens the training distribution, and an embodiment-aware grasp adaptation module annotates each object with candidate manipulation poses spanning multiple grasp axes and approach directions, with angular perturbations oriented toward high-reachability directions—yielding an 8.3% average gain in data-collection success, concentrated on low-DoF platforms (Piper +22.7%, Aloha-AgileX +13.7%).

## Results

On the RoboTwin 2.0 simulation benchmark (50 tasks, Aloha-AgileX), pretrained VLA models RDT (34.5%) and Pi0 (46.4%) substantially outperform non-pretrained ACT (29.7%) and DP (28.0%) under the Easy setting, while DP3 achieves the highest Easy score (55.2%) partly due to idealized depth. Under the Hard (domain-randomized) setting, all methods degrade sharply, with Pi0 retaining the best Hard score (16.3%) versus RDT (13.7%), ACT (1.7%), and DP (0.6%). In real-world bimanual experiments, combining 10 real demonstrations with 1,000 domain-randomized RoboTwin 2.0 trajectories yields a 3.6× improvement in few-shot transfer (43.0% vs. 29.5% average on seen backgrounds) and a 2.2× gain in zero-shot generalization on unseen backgrounds (36.5% vs. 15.5%).

## Baselines & Comparisons

Against the non-pretrained baselines ACT and DP, both pretrained VLA models (RDT, Pi0) achieve substantially higher success rates under the Easy setting (34.5%/46.4% vs. 29.7%/28.0%), and the gap widens dramatically under domain-randomized Hard conditions where ACT and DP collapse to 1.7% and 0.6% respectively, while RDT and Pi0 retain 13.7% and 16.3%. DP3, which leverages 3D point clouds, attains the best Easy score (55.2%) but still drops to 5.0% under Hard, indicating that 3D information alone does not confer robustness to visual domain shift. Pretraining with RoboTwin 2.0 domain-randomized data yields relative gains of 31.9% for RDT (18.8%→24.8%) and 29.3% for Pi0 (22.5%→29.1%), while adding only clean simulated data (RDT+Clean, Pi0+Clean) provides negligible or even negative gains, confirming that domain randomization—not mere data volume—is the critical factor. In real-world experiments, the 10-real + 1k-synthetic regime outperforms the 10-real-only baseline by 13.5–33.0 percentage points across four evaluation configurations, and the zero-shot synthetic-only model still achieves 36.5% on unseen backgrounds versus 15.5% for the real-only baseline. Compared to RoboTwin 1.0, the 2.0 pipeline improves code-generation ASR from 63.9% to 71.3% under multimodal feedback, reduces token usage from 1,236.6 to 569.4 in one-shot generation, and raises embodiment-aware data-collection success by 8.3% on average (with +22.7% on the low-DoF Piper platform).

## Relation to Prior Work

This paper extends RoboTwin 1.0 (Mu et al., 2025), a dual-arm benchmark with generative digital twins, by replacing its open-loop expert code generation with a closed-loop MLLM-driven synthesis pipeline that iteratively refines programs using simulation-in-the-loop execution logs and vision-language diagnostics. It departs from prior simulation-based data generators (MimicGen, RoboGen, GenSim2) that either rely on human demonstrations or produce trajectories without physical verification, and from VLA pretraining efforts (RDT-1B, Pi0) that depend on large-scale real-world data, by providing a scalable synthetic alternative with structured domain randomization across five axes. The embodiment-aware grasp adaptation module builds on the observation that low-DoF platforms (Piper, Aloha-AgileX) have fundamentally different kinematic constraints than high-DoF arms (Franka, UR5), a distinction largely ignored in prior synthetic pipelines.

## Why It Matters / Open Questions

The 50-task, 5-embodiment benchmark with 731 semantically annotated objects addresses a critical gap: the absence of a standardized, scalable evaluation suite for bimanual manipulation that tests robustness under domain shift. The finding that clean synthetic data actually degrades performance relative to pretrained baselines while domain-randomized data yields 30%+ relative gains isolates randomization (not data volume) as the key driver of sim-to-real robustness, a nuance that could reshape how practitioners allocate synthetic data budgets. Open questions include the VLM observer's low precision (20.8%) and 30% error-localization accuracy, which suggest the closed-loop mechanism is less reliable than the headline success rates imply, and whether the approach generalizes beyond tabletop scenarios to mobile or open-world manipulation as the authors themselves note.
