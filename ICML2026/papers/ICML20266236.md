## Problem

Repository-level code editing benchmarks like SWE-bench are dominated by complex agentic scaffolding, making it unclear how much editing capability can be internalised directly into model weights. Existing training data presents a dichotomy: SWE-bench-style datasets offer executable verification but are limited to a few thousand instances, while massive pretraining corpora (The Stack, CodeReview) lack structured multi-file editing signals. Raw GitHub pull requests could bridge this gap, but over 81% of crawled PRs are noise (bot-generated, unmerged, or non-core), and no large-scale verified PR-derived corpus existed for repository-level mid-training.

## Input / Output

At inference, the model receives a GitHub issue description (augmented with linked issue context during training), the repository file tree, and the content of top-3 locally identified source files, and produces a three-step output: a ranked list of file paths to edit, fine-grained navigation targets (class names, function names, or line numbers), and a set of Search/Replace blocks that locate edits via unique contiguous context strings rather than fragile line numbers. During mid-training, each instance is a linearised sequence containing the repository name, PR title, description, base file contents, and the verified Search/Replace edit blocks as the target, with reviewer comments appended as optional context.

## Method

Clean-PR is a two-stage training recipe. First, a mid-training stage encodes repository-level editing priors into Qwen2.5-Coder-32B-Base using a 2M-instance, 17.7B-token corpus built from 16.4M raw GitHub PRs through a pipeline that filters bots/unmerged/non-core PRs, reconstructs exact before/after repository states via git apply, derives minimal unique Search/Replace blocks via iterative context expansion, and verifies each block by round-trip string replacement requiring bit-wise equality with the ground-truth target. Linked issue descriptions are concatenated into the training sequence to recover the original problem definition. Second, an Agentless-aligned SFT stage decomposes each repair into three supervised tasks (file localisation, AST-based navigation, patch generation) and introduces error-driven augmentation: an intermediate model generates hard-negative files and distractor code regions that are injected into the input, training the model to output 'No changes needed' for irrelevant context rather than over-editing. The entire pipeline operates under a deterministic three-step Agentless protocol with no iterative tool-use loops, achieving 24.3% on SWE-bench Lite and 30.6% on Verified—surpassing 72B-parameter agentic baselines with half the parameters.

## Results

On SWE-bench Lite (300 instances), Clean-PR achieves 24.3% Pass@1 with a 96.3% valid patch rate, an absolute gain of +13.6% over the Qwen2.5-Coder-32B-Instruct zero-shot baseline (10.7%). On SWE-bench Verified (500 instances), the model reaches 30.6% Pass@1 (+12.3% over the 18.3% baseline), with file localisation accuracy of 80.7% and line-level navigation accuracy of 52.2%. The model also improves general coding benchmarks during mid-training: HumanEval rises from 54.1% to 59.8% and LiveCodeBench from 29.0% to 32.6%, demonstrating positive transfer rather than catastrophic forgetting.

## Baselines & Comparisons

Clean-PR (32B, Agentless) outperforms all five baselines on both SWE-bench splits. Against the zero-shot Qwen2.5-Coder-32B-Instruct baseline, it gains +13.6% on Lite (24.3% vs 10.7%) and +12.3% on Verified (30.6% vs 18.3%). The StarCoder2-style data baseline (same 17.4B token scale, unified diff format, no issue augmentation) scores 15.7%/20.4%, yielding an 8.6/10.2-point gap that the paper attributes to the verified Search/Replace format and linked-issue context. Against SWE-Gym (same 32B model but using the OpenHands agentic framework), Clean-PR wins by 9.0 points on Lite and 10.0 points on Verified (30.6% vs 20.6%), demonstrating that the data-centric mid-training approach surpasses heavy agent scaffolding. Most notably, Clean-PR with only 32B parameters surpasses the 72B Lingma-SWE and SWE-Fixer models on both splits (24.3% vs 22.0% Lite; 30.6% vs 30.2% Verified), confirming that rigorous PR-derived training can bridge a 2× parameter gap.

## Relation to Prior Work

This paper builds directly on the Agentless paradigm (Xia et al., 2025), adopting its three-step decomposition (file localisation → line-level navigation → Search/Replace patch generation) and its context-matching edit format. It departs from the dominant SWE-agent/OpenHands lineage of iterative agentic loops and from test-time-scaling approaches (MCTS, RL) by arguing that repository-level editing capability can be internalised into model weights through a dedicated mid-training stage on verified PR data. The data construction pipeline itself is novel relative to prior code corpora: where StarCoder2/The Stack treat code as static snapshots or use noisy unified diffs, Clean-PR reconstructs repository-consistent before/after states and verifies every Search/Replace block via round-trip application, yielding a deterministic training signal. The error-driven augmentation strategy for SFT also extends standard instruction tuning by explicitly training the model to reject distractor files and regions, addressing a failure mode (over-editing) that prior SFT recipes ignore.

## Why It Matters / Open Questions

The practical impact is significant: a 2M-instance, 17.7B-token verified PR corpus spanning 12 languages is released as the largest publicly available dataset explicitly constructed for repo-level mid-training, and the finding that a 32B model with this recipe matches or exceeds 72B-parameter systems (Lingma-SWE, SWE-Fixer) under a lightweight Agentless protocol challenges the field's assumption that heavy inference scaffolding or model scale is the primary driver of SWE performance. The ablation showing that verified Search/Replace format alone lifts valid-patch rate from 89.7% to 96.3% and that issue augmentation adds further gains provides actionable guidance for future data pipelines. Key limitations include the at-most-5-core-files constraint that under-represents broad cross-cutting changes, evaluation limited to the Qwen2.5-Coder architecture, and the simplified Agentless protocol that may not capture the full complexity of real-world multi-turn agentic workflows. Open questions include whether the internalised capability transfers to truly unseen repository structures, whether combining this mid-training signal with RL or verifier-based re-ranking (suggested by the Pass@10 gap) yields further gains, and whether the approach generalises to MoE or non-Qwen backbones.
