## Problem

Adaptive optimizers like Adam triple memory usage for LLM pretraining by storing first- and second-order moment states per parameter, while vanilla SGD performs poorly without adaptive scaling. Existing memory-efficient alternatives (GaLore, Fira, APOLLO) compress these states via low-rank projections but introduce algorithmic complexity. The paper asks: what is the minimum set of modifications to plain SGD needed to match state-of-the-art pretraining performance?

## Input / Output

The method operates on standard LLM pretraining: text tokens from the C4 dataset are fed through transformer architectures (LLaMA 60M–7B, GPT-2, Qwen2, Gemma) with matrix-valued weight parameters of shape d_in × d_out. The output is trained model weights, with the key constraint that optimizer state memory is limited to a single first-order momentum buffer for the last-layer (LM-head) weight matrix only, adding roughly 10% (1B) or 2% (7B) over vanilla SGD memory.

## Method

SCALE (Stochastic Column-normAlized Last-layer momEntum) combines two minimal modifications to SGD: (1) column-wise gradient normalization, which divides each column of the gradient matrix by its L2 norm (a closed-form operation requiring no extra memory and ~0.1 ms compute), applied uniformly to all layers; and (2) first-order momentum (β=0.9) applied exclusively to the last layer, where empirical variance analysis shows gradient variance is highest. The design is justified by a convergence theorem showing that layers with larger gradient variance σ_l benefit most from higher momentum coefficients, and by the observation that column-wise normalization stabilizes the LM-head by equalizing the norms of per-token gradient columns (frequent tokens otherwise produce disproportionately large gradients). For a 1B model, SCALE uses only 2.81 GB of optimizer memory (vs. 8.04 GB for Adam) while matching or exceeding Adam's perplexity, and for 7B it achieves 12.59 perplexity at 13.74 GB—outperforming Muon (12.72 at 26.95 GB) and APOLLO (13.02 at 16.14 GB).

## Results

On LLaMA 1B pretraining (C4, 20B tokens), SCALE achieves 13.49 perplexity with 2.81 GB optimizer memory, matching Adam(Stable-SPAM) (13.30, 8.04 GB) while using only 35% of the memory. For the 7B LLaMA model (19.7B tokens), SCALE reaches 12.59 perplexity with 13.74 GB, outperforming Muon (12.72, 26.95 GB) and APOLLO (13.02, 16.14 GB) in both perplexity and memory. Across 60M–1B models, SCALE consistently achieves the best perplexity among all memory-efficient optimizers while requiring 35–65% of Adam's memory footprint.

## Baselines & Comparisons

SCALE outperforms all memory-efficient baselines (GaLore, Fira, APOLLO, APOLLO-Mini, SWAN) in perplexity at every model size tested, while also using less memory than each of them. Against Adam(Stable-SPAM), SCALE is within 0.19 perplexity on 1B (13.49 vs 13.30) and 0.48 on 350M (16.32 vs 16.80, actually better), using only 35% of the memory. Against Muon, SCALE achieves lower perplexity at 1B (13.49 vs 13.67) and 7B (12.59 vs 12.72) while consuming roughly half the memory (2.81G vs 5.36G at 1B; 13.74G vs 26.95G at 7B). The gap over GaLore is the largest: at 1B, SCALE achieves 13.49 vs GaLore's 15.05 perplexity with 59% of the memory. At the 7B scale, SCALE beats APOLLO by 0.43 perplexity (12.59 vs 13.02) and APOLLO-Mini by 0.50 (12.59 vs 13.09), while using 14–16% less memory than both.

## Relation to Prior Work

This paper departs from the dominant paradigm of memory-efficient optimizers that compress Adam's first- and second-order states into low-rank subspaces (GaLore, Fira, APOLLO) or introduce new algorithmic machinery (Muon's Newton-Schulz orthogonalization, SWAN's dual normalization). Instead, it takes a bottom-up, minimalist approach: decomposing Adam into gradient normalization and EMA, then asking which minimal subset of modifications to plain SGD suffices. The resulting SCALE optimizer repurposes column-wise normalization (a concept discussed in Scion and SWAN but applied differently) and restricts first-order momentum to only the last layer, drawing on the theoretical insight that momentum's benefit scales with per-layer gradient variance.

## Why It Matters / Open Questions

SCALE's practical appeal is its extreme simplicity — a few lines of code change from standard Adam — combined with 35–45% memory reduction while matching Adam's perplexity across 60M–7B models and multiple architectures (LLaMA, GPT-2, Qwen2, Gemma). This makes it a strong default candidate for memory-constrained pretraining and a clean minimalist baseline against which more sophisticated optimizers can be benchmarked. Key limitations include evaluation only up to 7B parameters and 100B tokens, a single 7B run, and the fact that for small models (60M–130M) the first/last layers dominate parameter count, reducing the relative memory advantage. Whether the approach maintains its edge at 70B+ scale with full Chinchilla-optimal budgets remains an open question.
