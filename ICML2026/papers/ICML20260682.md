## Problem

When LLM coding agents generate code from documentation, iteratively refining that documentation with test feedback suffers from output coupling: entities are interdependent through call graphs, so improving one entity's documentation can change its implementation and break its callers, producing a whack-a-mole oscillation that prevents convergence. The paper proves that greedy self-refinement achieves arbitrarily poor approximation ratios (O(1/n)) under this coupling, and asks how to navigate the vast, unstructured documentation space to find playbooks that enable correct code synthesis.

## Input / Output

The method takes a code repository (entities with a call graph), initial documentation, and LLM-generated test cases that are validated by execution against the reference implementation (only passing tests are retained). The search is guided solely by these self-generated tests—ground-truth tests are never visible to the algorithm. The output is a set of optimized documentation strings (one per entity) that, when fed to an LLM, produce code passing all ground-truth tests; quality is measured exclusively by downstream code correctness (solve rate and pass rate), not by any human-readability metric.

## Method

DOCSEARCH is a dependency-guided bi-level search. The outer level performs a priority search over the entity dependency DAG in reverse topological order (callees before callers), with siblings at the same level prioritized by fewer failing tests, ensuring that when an entity is refined all its dependencies have already stabilized. The inner level runs a beam search of width W over documentation refinements, where each beam branch conditions on a different randomly sampled subset of error messages (diversified batch sampling) to escape local optima caused by noisy or redundant test failures. Refinement itself is a two-stage diagnosis-prescription process: the LLM first identifies the root-cause knowledge gap from the error batch, then generates a targeted documentation update. A worthy condition couples the two levels by committing a refinement only if no previously solved entity regresses, guaranteeing monotonic growth of the solved set and directly preventing the whack-a-mole oscillation.

## Results

On DevEval+ (20 Python modules, 227 entities, 631 tests), DOCSEARCH achieves 90.7% solve rate with GPT-4o, 95.2% with Claude-4.5-Sonnet, and 74.4% with Gemini-2.5-Flash, outperforming the strongest iterative baseline (Iterative+Topo) by 32.6%, 27.8%, and 30.3% respectively. The corresponding pass rates are 93.3%, 96.2%, and 79.4%. Ablation confirms reverse topological ordering contributes the largest gain (−18.5% if removed), followed by error diversity (−9.6%) and the worthy condition (−7.0%).

## Baselines & Comparisons

DOCSEARCH dominates all baseline categories across all three LLMs. Static methods (RepoAgent, DocAgent) achieve only 15.9–37.0% solve rate, revealing a fundamental documentation-agent gap where human-oriented prose misleads LLMs. Commercial agents (Cursor, Claude Code) with their strongest configuration (+Topo+Test) reach 55.1% and 64.8% respectively on Claude-4.5-Sonnet, still trailing DOCSEARCH by 40.1 and 30.4 points; the paper attributes this gap to the absence of a worthy condition (causing regression accumulation) and tree search (preventing backtracking from suboptimal refinements). The closest competitors are the iterative refinement baselines: Iterative+Topo achieves 58.1% (GPT-4o), 67.4% (Claude), and 44.1% (Gemini), yielding absolute gaps of 32.6, 27.8, and 30.3 points for DOCSEARCH. The consistent ~30-point gap across models of varying capability suggests DOCSEARCH addresses a structural optimization challenge (output coupling) rather than compensating for model-specific weaknesses.

## Relation to Prior Work

This paper departs from the code documentation generation line (RepoAgent, DocAgent) by reframing the objective from human readability (BLEU, ROUGE, subjective ratings) to downstream code correctness, and from the inference-time scaling line (Self-Refine, Reflexion, best-of-N, tree search) by identifying output coupling—a dependency-induced interference between generated entities—as a structural challenge absent from those settings. Rather than building on a single prior method, it repurposes beam search and tree search from inference-time scaling, adapting them with reverse topological traversal and a worthy condition to handle the call-graph dependency structure. The LLM-based test generation literature provides the feedback signal, but the paper's key contribution is the search formulation over documentation space guided by posterior code quality.

## Why It Matters / Open Questions

The whack-a-mole phenomenon is a practical bottleneck for anyone using iterative refinement on multi-entity codebases, and the formal proof that greedy self-refinement achieves O(1/n) approximation under output coupling provides a clear theoretical justification for dependency-aware search. The cross-language transfer result (optimized documentation outperforming raw source code for Python→Java/Go generation) suggests these playbooks are genuinely language-agnostic behavioral specifications, with implications for legacy modernization and API reimplementation. Limitations include evaluation on only 20 Python modules (227 entities), reliance on LLM-generated tests whose coverage may be incomplete, and the assumption that the call graph is largely static; scaling to larger repositories with heavy dynamic dispatch or complex inheritance remains open.
