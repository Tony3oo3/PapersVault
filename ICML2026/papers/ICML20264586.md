## Problem

Existing benchmarks for full-cycle AI research agents either rely on LLM-as-judge scoring of generated papers (a coarse, subjective proxy for scientific validity) or reduce evaluation to a single leaderboard metric (providing limited insight into the reasoning process). There is no benchmark that rigorously and verifiably tests whether an agent can independently design experiments, execute them, and draw correct evidence-backed conclusions on a non-trivial scientific question.

## Input / Output

Each task provides the agent only a high-level research question (the parent node in the paper's research-problem tree) along with the experimental scope (publicly available datasets) and evaluation criteria, while withholding the original experimental design, implementation details, and published conclusions. The agent must autonomously plan, code, execute, and synthesize a final conclusion, which is then decomposed into atomic claims and matched against ground-truth claims extracted from the source paper's figures and tables using LLM-based semantic entailment, yielding claim-level precision, recall, and F1. A structured error-attribution pass additionally maps each false positive/negative to one of four workflow stages (Research Planning, Implementation, Experimental Execution, Conclusion Formation).

## Method

FIRE-Bench introduces a 'constrained rediscovery' paradigm built on a research-problem tree abstraction that formalizes each source paper's reasoning trajectory as a hierarchy: a root research question, intermediate subproblem nodes, and leaf nodes encoding fully specified experimental tasks grounded in reported results. Tasks are instantiated at the parent-node level (v*) rather than the leaf level (l*), which forces agents to perform experimental design rather than mere implementation, making the task strictly harder than replication benchmarks like PaperBench. An automated LLM extractor (gpt-5 Pro, greedy decoding) parses papers into structured JSON trees, validated by human experts across five criteria (avg. score ≥ 4.8/5). Evaluation follows the RAGChecker claim-centric paradigm: both agent conclusions and ground-truth texts are decomposed into atomic empirical claims, and an LLM entailment classifier (gpt-5.2) determines true/false positives, with human validation confirming 0.95 precision and 0.89 F1 for the automated pipeline. The benchmark comprises 40 fully executed tasks (30 LLM-behavior + 10 cross-domain) plus 60 additional parsed papers released for community evaluation, sourced from ICLR, ICML, and NeurIPS 2024–2025.

## Results

On the core 30-task FIRE-Bench set, Claude Code (Claude-4-Sonnet) achieves the highest claim-level F1 of 46.7±23.4, followed by Codex (gpt-5-medium) at 41.9±25.4, OpenHands (gpt-5) at 37.9±23.0, and OpenHands (o4-mini) at 31.9±17.6. All agents remain well below 50 F1, and standard deviations of 17–25 points indicate substantial run-to-run instability. On the 10-task cross-domain extension (CV/VLM and neural network analysis), average F1 drops below 25 for all three evaluated agents, with Codex (gpt-5-medium) leading at 30.2 and OpenHands (gpt-5) trailing at 13.3.

## Baselines & Comparisons

FIRE-Bench evaluates four agent configurations: Claude Code (Claude-4-Sonnet), OpenAI Codex (gpt-5-medium), and OpenHands with two backbones (gpt-5 and o4-mini). Claude Code leads overall at 46.7 F1 and attains the best score on 13 of 30 tasks, while Codex tops 9 tasks and OpenHands (gpt-5) leads on 6; no single agent dominates, with only 4 tasks where all four agents reach F1 ≥ 50. Within the OpenHands framework, upgrading the backbone from o4-mini to gpt-5 yields a +6.1 F1 improvement (31.9 → 37.9) at a 21% cost increase ($8.90 → $10.74). Codex is a notable cost-efficiency outlier, reaching 41.9 F1 at $2.21 total—roughly 5× cheaper than Claude Code ($12.67 for 46.7 F1)—primarily through shorter action sequences rather than a weaker backbone. On the cross-domain extension, the ranking shifts: Codex (30.2) outperforms both OpenHands variants (23.4 and 13.3), and OpenHands (gpt-5) fails to consistently beat o4-mini, suggesting backbone capability does not transfer uniformly across agent harnesses on compute-heavier tasks.

## Relation to Prior Work

FIRE-Bench positions itself at an intersection of three existing benchmark families—method replication (PaperBench, LMR-Bench), metric-driven discovery (MLAgentBench, MLE-Bench), and automated paper generation (AI Scientist, Agent Laboratory)—while deliberately occupying a point in the design space none of them cover: full-cycle execution with insight-driven, grounded reference-based scoring and methodological freedom. It builds on RAGChecker's claim-level evaluation paradigm for scoring, and on the research-problem tree as a new formalism for decomposing papers into verifiable sub-tasks. The key departure from reproducibility benchmarks is the 'constrained rediscovery' formulation: withholding the original experimental design and conclusions forces agents to perform genuine experimental design rather than translation, making the task strictly harder than replication.

## Why It Matters / Open Questions

FIRE-Bench provides the first large-scale, objectively verifiable benchmark for full-cycle research agents that avoids the subjectivity of LLM-as-judge paper scoring, making it a practical tool for tracking progress in autonomous scientific discovery. The finding that failures are dominated by Research Planning and Conclusion Formation rather than coding or execution reframes where the field should focus improvements—on higher-level scientific reasoning rather than low-level implementation. Open questions include whether the benchmark can serve as a training signal for RL-based agent improvement, whether it generalizes to wet-lab or compute-heavy regimes, and whether the high run-to-run variance reflects fundamental stochasticity or addressable harness design issues.
