## Problem

Static multimodal benchmarks like MMBench are increasingly vulnerable to data contamination and temporal staleness as VLMs are trained on ever-growing web-scale corpora, yet naively replacing samples with new ones risks semantic drift, distributional gaps, and loss of cross-version comparability. Existing dynamic-update strategies—visual perturbations, synthetic generation, or fixed-source real-world crawling—each fail to simultaneously preserve task semantics, visual distributional alignment, and evaluation discriminativeness across diverse multimodal tasks.

## Input / Output

The pipeline consumes the original MMBench dev set (4K instances) to extract structured task specifications and task-related visual patterns, then retrieves temporally fresh images (restricted to a one-year upload window via Google Image API, open-domain Flickr streams, or source-specific crawlers) as raw input. For each retrieved image, the system produces a structured triplet z = (q, a, π) where q is a multiple-choice question, a is the answer, and π is an executable solution plan—a sequence of tool operations (object detection, OCR, depth estimation, attribute recognition) that can be run to independently verify the answer. The final output is 5.9K verified QA pairs forming MMBench-Live, with a 96.06% manual answer correctness rate.

## Method

MMBench-Live models benchmark evolution as task-guided dataset construction through a three-stage multi-agent pipeline. First, the original MMBench is decomposed into structured descriptions (evaluation purpose, format, task hierarchy, atomic tasks), and task-related visual patterns are identified per atomic task by sampling original instances, extracting recurring patterns across five semantic perspectives via a VLM, and consolidating them with an LLM. Second, a feedback-controlled acquisition loop uses these patterns to guide retrieval: a multimodal judge scores top-K candidates against task purpose and visual patterns, and if the acceptance rate falls below a threshold (τ=0.7), rejected candidates' rationales are aggregated into a feedback signal that conditions an LLM-based query refiner for up to three iterations. Third, QA generation produces (q, a, π) triplets using multiple MLLMs with model-based selection, and verification is deliberately vision-blind: the solution plan π is executed as a sequence of tool calls (VisionReasoner for detection/segmentation, Depth Anything V2, GOT-OCR-2, fine-tuned LLaVA) to produce textual intermediate outputs, which a text-only LLM verifier (Qwen3) uses to predict the answer—accepting the instance only if the predicted answer matches the generated one. This decoupling of perception (tool execution) from reasoning (text-only verification) reduces hallucination while enabling deterministic, traceable validation.

## Results

MMBench-Live contains 5.9K newly generated evaluation instances with a 96.06% manual answer correctness rate, constructed at a cost of ~$30 per update in 1–2 hours. On the benchmark, Qwen2.5-VL-7B-Instruct achieves the highest overall score (83.10%), followed closely by DeepSeek-VL-7B-Chat (83.04%), while earlier models (InstructBLIP, LLaVA-v1.5) score 73–75%. Cross-version consistency is strong at the model-averaged level (Pearson r = 0.8876, Spearman ρ = 0.8286), and PaCoST-based contamination signals are weaker than the original MMBench (mean Δ = 0.0060 vs. 0.0118; Cohen's d = 0.059 vs. 0.097).

## Baselines & Comparisons

Against the original MMBench, MMBench-Live exhibits a weaker PaCoST-based memorization signal: the mean confidence difference drops from 0.0118 to 0.0060 and Cohen's d from 0.097 to 0.059, while model rankings remain largely stable (model-averaged Pearson r = 0.8876). Compared to VLB-style image-editing variants (Adding, Elimination, Outpainting from Yang et al., 2025b), MMBench-Live shows substantially smaller contamination-related confidence shifts—Cohen's d of 0.059 versus 0.191–0.224 for the editing variants—indicating that temporal data freshness via real-world retrieval is more effective at reducing memorization than visual perturbation. The paper also validates that replacing GPT-based agents with Qwen3/Qwen3-VL preserves discriminative power and cross-version consistency (model-averaged Pearson r = 0.9084), confirming the pipeline is not dependent on a single model family.

## Relation to Prior Work

This paper builds directly on MMBench (Liu et al., 2024b), converting its task hierarchy and atomic task structure into a machine-readable specification that drives an automated multi-agent pipeline. It departs from prior dynamic-benchmark efforts—self-evolving perturbation methods (Yang et al., 2025b), generation-based approaches (Zhang et al., 2025a; Wen et al., 2025), and real-world data updating pipelines (Jiang et al., 2025; Shabtay et al., 2025; White et al., 2025)—by framing benchmark evolution as task-guided dataset construction with a distribution-consistent update strategy: task-related visual patterns extracted from the original benchmark guide both retrieval and filtering, while a feedback controller iteratively refines poorly aligned queries. The executable-reasoning verification stage, which decouples correctness checking from vision-based judgment by running tool-supported reasoning chains over textual intermediate outputs, extends the programmatic-verification ideas from automatic dataset construction (Guo et al., 2025; Xu et al., 2023) into a closed-loop QA validation setting.

## Why It Matters / Open Questions

The paper demonstrates that a full multimodal benchmark update (5.9K instances) can be produced in 1–2 hours at roughly $30, reducing construction cost by orders of magnitude relative to manual curation and enabling frequent, sustainable updates as VLMs scale. The weaker PaCoST memorization signals and stable cross-version model rankings (Pearson r ≈ 0.89 at the model-averaged level) suggest the approach can mitigate contamination without sacrificing evaluation comparability. Key limitations remain: the framework cannot eliminate implicit memorization of high-frequency visual concepts, instance quality is bounded by the underlying agent models, and the task-grounded design prioritizes cross-version stability over task-space expansion, leaving open how to introduce genuinely new evaluation dimensions alongside updates. Whether the pipeline generalizes cleanly to benchmarks with very different task structures or to non-multiple-choice formats is not yet tested.
