## Problem

Anchors, a widely used local model-agnostic explanation technique, suffers from prohibitive computational cost because its iterative sampling procedure can take hours per input, a problem that is especially severe for LLMs where each perturbation query incurs API latency and monetary expense. No existing mechanism allows Anchors to reuse intermediate computations across inputs, making it impractical for time-sensitive or interactive deployment.
![Teaser figure](../imgs/ICML20265605/cropped_page3_idx1.webp)

## Input / Output

The method takes a single input instance (a tabular feature vector, a text sequence, or an RGB image) and a black-box target model, and returns a conjunction of feature predicates that constitute a sufficient condition for the model's prediction on that input. Internally, it maintains a growing memory set of (input, intermediate-rule) pairs indexed by a k-d tree over multi-dimensional embeddings produced by Anchors' own perturbation model; the similarity threshold τ_sim and intermediate precision threshold τ_p_mid control retrieval and caching granularity. The final output rule must satisfy precision ≥ τ_p with probability ≥ 1−δ while maximizing coverage, matching the original Anchors specification.

## Method

MAnchors stores low-precision, high-coverage intermediate rules (rather than final explanations) from prior Anchors runs, exploiting the fact that these general rules are retrievable for broader regions of the input space. Upon a memory hit, a horizontal transformation (HT) maps each predicate in the retrieved rule to the most similar feature in the new input using a distance metric defined in the perturbation space (absolute difference for tabular, BERT embedding distance for text, superpixel embedding distance for images). A vertical transformation (VT) then refines the adapted rule by iteratively adding predicates via the same KL-LUCB-guided beam search that Anchors uses, continuing until the target precision threshold is met. This preserves Anchors' search structure while reducing the number of iterations needed, since the search starts from an informative intermediate rule rather than the empty rule. The added overhead is a k-d tree lookup (O(m) worst-case) that is asymptotically negligible compared to the thousands of model queries in the original procedure.

## Results

MAnchors achieves a headline 8.74× speedup with 87% sampling reduction when explaining Llama 3 (8B) on sentiment analysis (513.06 s → 58.70 s per explanation). Across the other settings, speedups range from 1.69× (RF on RT-Polarity) to 2.11× (RF on Adult income prediction), with sampling reductions of 32–54%. Fidelity is largely preserved: on the Llama sentiment task, coverage drops only from 0.10 to 0.09 and rule length increases modestly from 4.34 to 5.39 predicates. Additional LLM evaluation on Gemma-2-2B confirms generalization, yielding 4.56× speedup (78% reduction) on SST-2 and 2.91× (66% reduction) on AG News.

## Baselines & Comparisons

The sole baseline is the original Anchors algorithm (Ribeiro et al., 2018), against which MAnchors is compared on every task and model. MAnchors wins on all six configurations in terms of both wall-clock time and sampling count, with speedups ranging from 1.69× to 8.74×. The largest gain (8.74×, 87% fewer samples) occurs with Llama 3 (8B), where each model query is an expensive API call and Anchors' iterative KL-LUCB sampling dominates runtime. For lighter models (RF, NN, GBT on tabular data), the speedup is more modest (1.76×–2.11×) because the per-query cost is already low and the cold-start phase (memory misses) dilutes the average. On fidelity, MAnchors matches Anchors' precision target (τ = 0.95) but incurs a small coverage drop (0.10 → 0.09) and a ~24% increase in rule length (4.34 → 5.39 predicates) on the Llama sentiment task, a trade-off the authors attribute to imperfect horizontal-transformation alignment. No comparison shows MAnchors losing to Anchors on any metric; the method strictly reduces time and samples while keeping precision at the required threshold.

## Relation to Prior Work

MAnchors is a direct acceleration of the Anchors algorithm (Ribeiro et al., 2018), reusing its iterative beam-search and KL-LUCB sampling structure while introducing a memorization layer that stores low-precision, high-coverage intermediate rules. It departs from prior efficiency work on explanations: Covert et al. (2024) apply stochastic amortization to attribution methods (SHAP, LIME) but not rule-based approaches, and Mor et al. (2024) accelerate global Anchor aggregation rather than single-input local explanation. The horizontal/vertical transformation framework is the paper's key conceptual contribution, enabling cached rules to be adapted across inputs without re-sampling from scratch, and is positioned as orthogonal to recent extensions that expand Anchors' expressiveness (ReX, ConLUX, temporal-logic variants).

## Why It Matters / Open Questions

The 8.74× speedup and 87% sampling reduction on Llama 3 (8B) make Anchors practically viable for LLM explanation, where repeated API calls impose both latency and monetary costs that previously rendered the method infeasible for interactive use. The approach requires no offline training of a surrogate model, keeping it model-agnostic and easy to deploy. Open questions include whether learned alignment between cached and online inputs can further reduce the small coverage degradation observed, whether the method scales to vision transformers and higher-dimensional spaces, and whether richer human-centered understandability metrics beyond rule length are needed to validate the slight increase in explanation length.
