## Problem

Existing LLM-based optimization modeling pipelines are solver-driven: they generate code in a single forward pass and apply post-hoc fixes only when the solver raises execution errors. This leaves a critical blind spot—semantic errors (e.g., an upper-bound constraint silently implemented as a lower bound) produce syntactically valid, executable code that solves the wrong problem, and no solver feedback can detect them.

## Input / Output

The method takes a free-form natural language problem description and produces Python code using the Gurobi solver API, which when executed returns the optimal objective value and solution. Internally, the description is first parsed into a JSON-structured representation S = (parameters, variables, constraints, objective); parameters and variables are rendered via deterministic templates, while constraints and objective are generated by an LLM agent. The final output is a complete, solver-executable program assembled from the deterministic and semantically corrected code fragments.

## Method

SAC-Opt introduces a backward, semantic-anchor-guided correction loop that operates entirely at inference time without additional training. After initial code generation, a reconstruction agent reads the generated constraint/objective code and re-expresses its logic as natural-language anchors in the same structured format as the original extraction. Each reconstructed anchor is then compared against its original counterpart using either an LLM-based binary equivalence check or a cosine-similarity threshold on SentenceTransformer embeddings. Only the mismatched anchors (the error set) are regenerated by the translation agent, and the loop repeats until all anchors align or a maximum iteration count is reached. This fine-grained, anchor-level correction is followed by a standard solver-feedback debugging step for residual syntax or feasibility issues, but the primary accuracy gains come from the semantic alignment phase rather than code-level fixes.

## Results

SAC-Opt achieves the highest modeling accuracy across all seven public datasets, with an average improvement of 7.7% over the second-best method (OptiMUS-0.3). The largest gain is 21.9% on ComplexLP (79.6% vs. 52.1%), followed by 9.5% on IndustryOR (63.8% vs. 54.3%) and 7.7% on ReSocratic (88.7% vs. 81.0%). On the easiest dataset (EasyLP), SAC-Opt reaches 96.5% accuracy, while on the hardest (ComplexOR) it achieves 58.9%, still outperforming the best baseline by 1.8%.

## Baselines & Comparisons

SAC-Opt outperforms all six baselines on every dataset. Against the strongest competitor OptiMUS-0.3 (which adds correction to extraction), SAC-Opt gains 7.0–21.9 percentage points, with the largest margin on ComplexLP (79.6% vs. 52.1%) and IndustryOR (63.8% vs. 54.3%), indicating that semantic-anchored backward correction is far more effective than OptiMUS-0.3's extraction-stage fixes. Reflexion, which relies on solver-error-driven feedback, trails SAC-Opt by 18.6 points on ComplexLP (43.2% vs. 79.6%), confirming that syntax-level debugging cannot catch silent semantic errors. CoE performs well on EasyLP (94.4%) but degrades sharply on harder datasets like IndustryOR (31.2%) and ComplexLP (50.6%), while CAFA is competitive only on NL4OPT (68.1%) and drops to 40.1% on ReSocratic. CoT does not consistently improve over Standard prompting and actually hurts performance on EasyLP (49.5% vs. 70.3%), suggesting that naive chain-of-thought reasoning is insufficient for optimization modeling without structured verification.

## Relation to Prior Work

SAC-Opt builds directly on the OptiMUS 0.3 structured data extraction pipeline (S = (P, V, C, O)) and its Reflexion-style solver-feedback debugging loop, but departs fundamentally from the forward-generation paradigm that dominates prior LLM-based optimization modeling (CoE, CAFA, OptiMUS). Where existing methods treat solver error messages as the sole correction signal—addressing only syntax and feasibility—SAC-Opt introduces a backward verification loop that reconstructs semantic anchors from generated code and compares them against the original problem description, targeting the silent semantic errors (e.g., a constraint implemented with the wrong inequality direction) that solvers cannot detect. The iterative, anchor-level correction mechanism is the key architectural departure: rather than regenerating the full model or applying generic self-reflection, only the specific misaligned constraint or objective is regenerated.

## Why It Matters / Open Questions

The paper addresses a practically important gap: LLM-generated optimization models that execute without error yet encode incorrect logic, producing misleading solutions in high-stakes domains like logistics and finance. The 21.9% gain on ComplexLP and consistent improvements across seven datasets demonstrate that semantic verification is a meaningful and underexplored axis of correction. Limitations include dependence on extraction quality (acknowledged but shown to be minor in practice), the added latency of iterative LLM calls (though modest relative to CoE/OptiMUS), and the fact that the verification step itself relies on an LLM or a coarse similarity threshold, neither of which is a perfect oracle. Open questions include whether the anchor-level correction generalizes to non-linear or stochastic optimization formulations, whether more principled equivalence checks (e.g., formal verification of constraint logic) could replace the heuristic LLM/similarity verifiers, and whether the approach extends to multi-objective or constraint-programming settings.
