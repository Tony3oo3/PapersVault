## Problem

Large-scale MIPS requires O(nd) exhaustive search or query-agnostic approximate indices (hashing, quantization, graphs) that make limited use of the query distribution at inference time. No prior method explicitly amortizes MIPS by training a neural network to predict solutions directly, exploiting the fact that the MIPS value function is the convex support function of the key set whose gradient yields the optimal key.
![Teaser figure](../imgs/ICML20263507/cropped_page1_idx0.webp)

## Input / Output

The method takes a d-dimensional L2-normalized query embedding (d=384 from all-MiniLM-L6-v2) and a fixed database of n key vectors, with a known query distribution p_X used only at training time. SUPPORTNET outputs c scalar support-function scores (one per cluster) whose input-gradients, computed via autodiff, yield predicted keys; KEYNET outputs a c×d matrix of predicted key vectors directly. In the single-cluster case (c=1), KEYNET's output is a single d-dimensional vector that can be fed as a drop-in replacement for the original query into any off-the-shelf indexer (FAISS-IVF, ScaNN, SOAR, LeanVec).

## Method

The core insight is that the MIPS value function σ_Y(x) = max_y <x,y> is the support function of the key set: it is convex, positively 1-homogeneous, and its gradient ∇σ_Y(x) = y*(x) equals the optimal key. SUPPORTNET implements this as a loosely-constrained ICNN (non-negative hidden weights, passthrough input connections, soft-leaky-ReLU activation) with a homogenization wrapper H[g](x) = ‖x‖·g(x/‖x‖) to enforce 1-homogeneity; the predicted key is recovered as ∇_x f_θ(x) via backpropagation. KEYNET is an unconstrained MLP of the same depth/width that directly regresses y*(x), eliminating the backward pass at inference. Training is supervised on precomputed exhaustive-search MIPS solutions with Gaussian query augmentation; SUPPORTNET's loss combines score regression with gradient matching, while KEYNET's loss combines key regression with a score-consistency term derived from Euler's theorem for homogeneous functions. A multi-task extension shares parameters across c cluster-specific support functions, enabling the network to serve as a learned cluster router that outperforms centroid-based routing.

## Results

On the cluster-routing task (NQ, c=128 clusters), a small SUPPORTNET (XS, L=8) achieves ~72% routing accuracy at k=1 versus ~56% for the centroid baseline, and reaches ~95% at k=4 — matching what the centroid baseline only achieves at k=16 (~4× the FLOPs). In the FAISS-IVF integration on HotpotQA (n≈5.2M), KEYNET-mapped queries consistently improve Recall@0.1% over the original query across all three cost axes (FLOPs, n_probe, wall-clock latency), with the best compute-recall trade-off at XS and S model sizes. The gains extend to BioASQ (n≈15M) and remain robust to moderate query distribution shift (σ up to 0.03). On Quora (n≈513K), both SUPPORTNET and KEYNET yield a ≥10-point routing accuracy increase at k=1 over centroid routing.

## Baselines & Comparisons

Against the FAISS-IVF baseline (Johnson et al., 2019), KEYNET-mapped queries dominate the original-query curve in Recall@0.1% across the mid-budget regime on all three BEIR datasets and BioASQ, with the largest relative gains at XS/S model sizes where the forward-pass overhead is minimal. Against ScaNN (Guo et al., 2020), which already uses anisotropic quantization to partially exploit data distribution, KEYNET-mapped queries still improve over original queries through the mid-budget regime, though gains shrink at very high budgets where ScaNN approaches saturation. Against SOAR (Sun et al., 2023), the most aggressive backbone in the set, the improvement is most constrained: on Quora the index is essentially saturated and the curves overlap, while on NQ and HotpotQA a mid-budget improvement persists. Against LeanVec (Tepper et al., 2023), the pattern mirrors the FAISS case with a slight additional latency advantage at small budgets due to LeanVec's compressed representation. For the cluster-routing comparison, the centroid-based baseline (argmax over ⟨q, z_i⟩) is consistently outperformed by both SUPPORTNET and KEYNET at all FLOP budgets on NQ, with the gap largest at the tightest budgets (k=1, k=4).

## Relation to Prior Work

This paper departs from the dominant paradigm of approximate MIPS (hashing, quantization, graph traversal) by treating MIPS as a supervised regression problem grounded in convex analysis: the MIPS value function is the support function of the key set, a convex, positively 1-homogeneous function whose gradient is the optimal key. The SUPPORTNET architecture directly instantiates Input Convex Neural Networks (Amos et al., 2017) with a relaxed non-negativity constraint, while the overall training framework follows amortized optimization (Amos, 2023b). The connection to Brenier maps in optimal transport is drawn explicitly, though unlike typical OT learning the ground-truth potential and its gradient are both available via exhaustive search, making this a supervised rather than unsupervised OT problem. The paper positions itself against learned-index approaches (Kraska et al., 2018; Vecchiato et al., 2024) by encoding MIPS predictions directly into network weights conditioned on the query distribution, rather than adapting index structure.

## Why It Matters / Open Questions

The drop-in nature of KEYNET (feed its output to any existing IVF/ScaNN/SOAR index unchanged) makes this approach immediately deployable without re-architecting retrieval pipelines, and the consistent mid-budget recall gains across four indexing backbones, five datasets up to 15M keys, and three cost axes (FLOPs, probes, latency) provide strong practical evidence. The SUPPORTNET-as-cluster-router result at c=128 (matching k=16 centroid routing at k=4, i.e., ~4× fewer FLOPs) suggests a path to hierarchical search at billion scale. Key limitations include the requirement for a representative query distribution (performance degrades under shift, though not catastrophically), the need for exhaustive MIPS pre-computation to generate training targets, and the fact that gains are most pronounced when query and key distributions differ substantially (as quantified in Appendix A.10). Open questions include online adaptation to query drift, distillation from larger models, and whether the SUPPORTNET→KEYNET two-stage pipeline can replace the current single-model approach at scale.
