## Problem

Current web agents operate through low-level interaction primitives (clicks, keystrokes, DOM manipulation), producing brittle long-horizon traces, high per-step inference cost, and executions that are difficult to audit or reproduce. The paper argues that stronger models alone cannot fix this structural limitation: without a semantic layer exposing typed actions with stable semantics, agents will keep rediscovering fragile, site-specific click sequences rather than composing correct, checkable workflows.

## Input / Output

The agent receives a natural-language task and a catalog of typed verb definitions (each specifying named parameters with types, structured output schemas, and documented behavior). Rather than emitting a step-by-step action trace, the agent synthesizes a short executable program — a sequence of verb calls with explicit data flow, control flow (loops, conditionals), and boundary checks — whose execution produces structured results and a checkable trace of typed invocations. Verbs may be backed by server-side Web APIs or client-side Playwright workflows, but the agent interacts only with the uniform typed interface, making the implementation path an invisible detail.

## Method

The paper proposes web verbs as a concrete semantic layer: each verb is a typed, semantically documented function exposing a web operation with named typed parameters, structured outputs, preconditions, postconditions, policy tags, and logging hooks. Two implementation paths are unified behind one interface — wrapping an existing server-side endpoint or packaging a multi-step browser workflow via Playwright — so the agent plans and composes at the verb level rather than reasoning over individual UI elements. The agent's role shifts from predicting the next low-level action to synthesizing a concise program that chains verb calls with explicit intermediate values, standard control structures, and direct checks against user constraints. Case studies (travel planning with distance aggregation, furniture shopping under a global budget) demonstrate that verb-level composition preserves the user-specified computation while browser agents using low-level primitives diverge into incorrect or incomplete results.

## Results

This is a position paper with qualitative case-study evidence rather than a standard quantitative benchmark. The authors report that their verb-based prototype, implemented across more than ten websites, completed over one hundred distinct complex tasks successfully. In the two illustrative case studies (travel planning and furniture shopping), the verb-level approach produced correct, constraint-satisfying outputs, while the browser-use baseline produced semantically incorrect results (e.g., chaining museums as waypoints instead of summing hotel-to-museum distances; using a greedy selection that violated the global budget). The paper also cites IBM CUGA's WebArena results (0.617 average success rate, dropping to 0.354 on multi-site tasks) as evidence of the brittleness of low-level interaction primitives at scale.

## Baselines & Comparisons

The paper compares its verb-level composition approach against browser-use (Müller & Žunič, 2024), a browser agent operating through low-level interaction primitives (clicks, typing, scrolling). In the travel-planning case study, the browser agent failed to implement the user-specified computation: instead of computing the distance from each hotel to each museum and summing them, it chained the museums as waypoints in a single route and reported that route length as the total, answering a different question. In the furniture-shopping case study, the browser agent adopted a greedy strategy—selecting items one by one until the budget was exceeded—leaving some categories unfilled and skipping lower-cost alternatives, thereby violating the stated global-budget optimization objective. In both cases, the verb-based approach produced correct, reproducible outputs by expressing the task logic as an explicit program with loops, conditionals, and structured intermediate values. The comparison is qualitative (no shared numeric metric), but the verb approach wins on correctness and constraint satisfaction in both tasks.

## Relation to Prior Work

This position paper departs from both dominant web-agent paradigms—browser agents using low-level interaction primitives (clicks, keystrokes, DOM manipulation) and API agents invoking server-side Web APIs—by proposing a unified semantic layer of typed actions called 'web verbs.' It builds conceptually on NLWeb's content-retrieval semantic layer (Microsoft, 2025) and Schema.org structured data, but extends the idea from what an agent can *know* about the web to what it can *do*, unifying server-side endpoints and Playwright-backed client-side workflows behind a single typed interface. The analogy to high-level programming languages versus assembly frames the contribution as a shift in the unit of interaction rather than a new model architecture, and the paper explicitly positions itself as complementary to, not a replacement for, ongoing improvements in GUI grounding and long-horizon planning.

## Why It Matters / Open Questions

The paper's central claim—that model capability gains alone cannot fix brittleness, cost, and auditability in web agents without a stable typed-action interface—is a direction-setting argument that could reshape how the web-agent community designs evaluation and deployment. However, the evidence is limited to two illustrative case studies on a small verb catalog (Amazon, Google Maps), and the paper does not provide large-scale benchmarks, ablations on verb granularity, or security analyses. Key open problems remain: standardizing verb registration and element locators, scaling retrieval to web-scale verb libraries, modeling real-world permissions and consent as checkable pre/postconditions, and building benchmarks that test composed workflows rather than single-step actions. Whether the ecosystem (site developers, community tool builders, standards bodies) will actually adopt and maintain such a layer is the critical unresolved question.
