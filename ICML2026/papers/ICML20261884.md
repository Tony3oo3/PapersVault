## Problem

Vision-Language-Action models rely on a Markov assumption that conditions actions only on the current observation, making them unable to handle non-Markovian long-horizon tasks that require persistent memory of past events, user preferences, and spatial configurations. Existing remedies face a frequency-competence paradox: stronger reasoning VLMs are too slow for real-time control, while faster models lack the reasoning depth needed for multi-step planning, and passive memory buffers (e.g., FIFO queues) quickly overflow with redundant frames, discarding critical early information.

## Input / Output

The system consumes dual RGB streams (third-person and wrist cameras at 25 Hz, resized to 224×224 and subsampled to 10 Hz), a natural language instruction, and proprioceptive robot state (end-effector pose, gripper state). The Executor outputs 10-action continuous control chunks at 2 Hz (executing 5 open-loop per cycle), while the Planner outputs a structured episodic memory update (contextual key-value entries with text captions and image references, plus an ordered procedural plan with done/current/pending status labels) and a refined subtask instruction fed back to the Sentry. Memory entries are stored in a vector database indexed by text-embedding-3 caption embeddings for cosine-similarity retrieval.

## Method

HiMe decomposes the hierarchical policy into three tiers with distinct temporal resolutions: a high-frequency Executor (fine-tuned π0.5 VLA, the only component requiring domain-specific training on 60 real-robot demos), a lightweight Sentry (Qwen3-VL-8B) that monitors a sliding window of 8 recent observations every 5 steps and emits a binary gate signal only when the active subtask is completed or invalidated, and a heavyweight Planner (GPT-4o) invoked sparsely at those gate events to perform context retrieval from a persistent episodic store and jointly update both contextual memory (a multimodal key-value store) and procedural memory (an ordered subtask list). The key architectural insight is that the Sentry amortizes expensive VLM reasoning by shifting Planner involvement from every control step to sparse subtask-level calls, reducing API invocations by ~3×. Memory is organized as cross-modal semantic schemata—visual frames anchored with dense textual descriptions capturing ownerships, procedural rules, and user preferences invisible in pixel space—and managed through explicit Add, Update, and Delete operations that maintain knowledge consistency as the environment evolves, rather than passive append-only accumulation.

## Results

HiMe achieves 90% average task progress across three long-horizon manipulation tasks (Object Search: 92%, Counting: 92%, Rearrangement: 87%), effectively bridging the gap to the Human High-level oracle. Compared to the Flat Memory baseline, HiMe reduces Planner API calls by ~3× (e.g., 1.8 vs. 5.4 in Object Search) while improving memory hit rate from 68% to 94%. The Sentry mechanism alone lifts task progress from 14% (Transient Memory) to 26% (Transient Memory w/ Sentry), and adding full hierarchical memory further raises it to 90%.

## Baselines & Comparisons

Against the Hi-robot-style Transient Memory baseline (Shi et al., 2025), which invokes a memory-less planner at fixed intervals, HiMe achieves 90% vs. 14% average task progress — a 6× improvement — by adding both the Sentry gating mechanism and structured episodic memory. Against the MemER-style Flat Memory baseline (Sridhar et al., 2026), which uses a FIFO queue of recent keyframes, HiMe improves average task progress from 65% to 90% while simultaneously reducing Planner API calls by roughly 3× (e.g., 1.8 vs. 5.4 in Object Search) and raising memory hit rate from 68% to 94%. The ablation isolating the Sentry (HiMe w/o Sentry at 68% vs. HiMe at 90%) shows that the dynamic trigger mechanism contributes ~22 percentage points beyond what memory alone provides. The paper also reports that even the Transient Memory w/ Sentry variant (26%) substantially outperforms the periodic Transient Memory (14%), confirming that the Sentry's subtask-level gating is the single largest architectural gain.

## Relation to Prior Work

HiMe builds directly on the π0.5 VLA as its low-level Executor and extends the hierarchical VLA paradigm (Hi-robot, HAMSTER) by inserting a dedicated memory layer between the high-level planner and the reactive controller. It departs from prior robotic memory work (MemER, SAM2Act, MemoryVLA) that relies on flat FIFO queues or passive retrieval banks, instead introducing a structured episodic memory with explicit Add/Update/Delete operations and a cross-modal (image + text) representation. The Sentry module draws conceptually from event-driven scheduling in LLM agent memory systems (MemGPT, Mem0) but is the first to use a lightweight VLM as a real-time subtask-completion gate that amortizes expensive planner invocations in a closed-loop robotic setting.

## Why It Matters / Open Questions

The paper addresses a concrete and growing bottleneck: VLA models cannot handle non-Markovian, multi-stage tasks because they lack persistent, updatable memory, and naively adding a large VLM in the control loop is infeasible due to latency. The Executor–Sentry–Planner decomposition offers a practical, model-agnostic recipe that practitioners can adopt with existing VLA checkpoints and off-the-shelf VLMs. However, the evaluation is limited to three tabletop tasks on a single WidowX-250 arm with simple pick-and-place primitives, and the memory-scalability experiment (Table 10) shows clear performance degradation beyond ~12 subtasks, leaving open whether the architecture generalizes to dexterous, high-dimensional, or truly open-ended manipulation. Broader validation on standard simulation benchmarks and more diverse skill sets is needed before the approach can be considered a general solution to long-horizon embodied memory.
