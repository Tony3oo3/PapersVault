## Problem

Self-speculative decoding with sparse attention accelerates long-context LLM inference, but existing methods face a fundamental trade-off: query-agnostic KV selection (e.g., sliding window) has low overhead but poor drafting accuracy, while query-aware selection (e.g., Quest) improves accuracy at the cost of high per-step KV selection overhead that erodes the speedup. Prior work treats drafting and verification as independent stages, overlooking that the full-attention verification pass already computes the exact criticality of every KV entry at no additional cost.

## Input / Output

Vegas operates within a vLLM serving pipeline, consuming a text prompt and the accumulated KV cache (up to 128K+ tokens) as input, and producing generated text tokens with the identical output distribution as vanilla full-attention decoding (lossless). The method is parameterized by a sparsity ratio (fraction of KV entries retained for sparse attention, typically ~7%) and a draft length γ (number of tokens drafted per iteration, typically 5–9), both tuned per model and workload. For models with mixed attention patterns (e.g., gpt-oss-20b), sparse attention is applied only to fully dense attention blocks.

## Method

Vegas co-designs the drafting and verification phases by using attention logits computed during full-attention verification to select critical KV entries for the next drafting phase. To avoid overfitting to a single token, it aggregates logits across the draft token chain; to minimize collection overhead, it introduces a Collect-2-Query mechanism that extracts logits only from the first draft token and the bonus token (the pair with maximum positional distance), reducing overhead to 5–9% versus 21–29% for other query-aware methods. The selected top-k prefix tokens are then used for sparse attention during drafting, implemented by repurposing the PagedAttention kernel with page size 1 for token-level granularity. A three-step hyperparameter tuning strategy (sweep sparsity ratio → sweep γ → fine-tune sparsity) balances drafting accuracy against iteration latency to maximize end-to-end throughput.

## Results

Vegas achieves a 1.25×–2.81× speedup in decoding throughput over default vLLM and a 1.15×–1.29× speedup over state-of-the-art sparse-attention self-speculative decoding methods (MagicDec-Stream, MagicDec-Quest, SpecExtend) across Qwen3-4B/8B/30B and gpt-oss-20b on AIME25, CodeElo, and LongBench-v2. On long-context workloads (LongBench-v2, 96K–120K input), Vegas delivers 18%–29% higher throughput than the best baseline. Vegas's KV selection overhead is only 5.9%–9.4% of ideal iteration latency, compared to 21.7% for MagicDec-Quest and 11.2%–29.1% for SpecExtend.

## Baselines & Comparisons

Against vanilla vLLM, Vegas achieves 1.25×–2.81× throughput speedup, with gains scaling with context length. Against MagicDec-Stream (StreamingLLM-based, query-agnostic), Vegas wins by 1.15×–1.23× on AIME25/CodeElo and 18%–29% on LongBench-v2, primarily through higher drafting accuracy (token-granular, multi-token KV selection) at comparable selection overhead. Against MagicDec-Quest (query-aware), Vegas clearly wins: Quest's 23% KV selection overhead negates its drafting accuracy gains, yielding 1.7% *lower* throughput than MagicDec-Stream, while Vegas achieves both higher accuracy and lower overhead. Against SpecExtend, Vegas outperforms on both axes: drafting accuracy (multi-token coverage vs. single last-accepted-token selection avoids overfitting decay) and KV selection overhead (5.9%–9.4% vs. 11.2%–29.1%, since SpecExtend must collect logits for all draft tokens to determine the last accepted token). For gpt-oss-20b specifically, all speculative methods yield smaller absolute speedups over vLLM because only half the transformer blocks use full attention, limiting the per-step latency reduction from sparse attention to 48%.

## Relation to Prior Work

Vegas extends the self-speculative decoding with sparse attention paradigm established by MagicDec and TriForce, where the target model drafts tokens using sparse attention and verifies them with full attention. The key departure is co-designing drafting and verification: rather than treating KV selection as a standalone module (as in Quest or StreamingLLM) or conditioning on a single last-accepted token (as in SpecExtend), Vegas extracts attention logits from the verification pass as a 'free oracle' to guide the next drafting phase. The Collect-2-Query mechanism—using only the first draft token and bonus token for logit collection—further differentiates it from SparseSpec, which collects logits from all draft tokens at higher rematerialization cost.

## Why It Matters / Open Questions

Vegas provides a training-free, lossless acceleration path for long-context LLM serving that integrates directly into production frameworks like vLLM, making it immediately deployable without retraining or auxiliary models. Its limitation is that benefits are context-length-dependent (marginal for short contexts) and architecture-dependent (reduced for models with mixed attention patterns like gpt-oss-20b). Open questions include whether the verification-guided selection strategy composes with other self-speculative techniques (layer skipping, quantized drafters) and whether the Collect-2-Query heuristic generalizes to models with very different attention head structures.
