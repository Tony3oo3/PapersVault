## Problem

Existing benchmarks for LLM reasoning either conflate algorithmic reasoning with domain-specific complexity (math, STEM), offload reasoning to external code interpreters (coding benchmarks), or are restricted to a single structure type with code-like syntax (CLRS-Text, NLGraph). There is no diagnostic benchmark that isolates structural reasoning—the ability to understand and manipulate relationships like order, hierarchy, and connectivity—through interpretable, fine-grained tasks with deterministic evaluation.

## Input / Output

Each problem instance is a natural language prompt containing four components: a concise data structure description, an unambiguous operation specification, the initial state (e.g., a tree or list), and a specific question requesting the final outcome. Models must return a structured JSON response conforming to a predefined schema (e.g., a list[int] for BST traversal), which is scored binary (0/1) against programmatically computed ground truth. The benchmark comprises 4,140 instances across 20 data structures, 35 operations, three length levels (short: 5–10, medium: 11–20, long: 21–30 elements/operations), and five evaluation components (main, challenge, spatial, realistic, code).

## Method

DSR-Bench organizes tasks hierarchically across six relationship categories (Linear, Temporal, Associative, Hierarchical, Network, Hybrid), where simpler tasks serve as prerequisites for complex ones (e.g., queue operations precede BFS on trees), enabling fine-grained failure localization. All data is synthetically generated from hand-crafted prompt templates with randomized inputs (uniform integers 0–100, lowercase strings), ensuring scalability and minimal contamination risk. Evaluation is fully deterministic: structured output enforces schema-conformant responses, and ground truth is computed programmatically, eliminating subjective human or LLM-based judging. Beyond the main suite, three auxiliary probes stress-test structural reasoning under realistic conditions: spatial (K-D Heap, K-D Tree, Geometric Graph at varying dimensionalities k=1,2,3,5), realistic (data structures embedded in narrative contexts like clinic appointments or ice cream lines), and code (assessing whether self-generated code aids reasoning). The paper evaluates 13 state-of-the-art LLMs (instruction-tuned and reasoning models) across five prompting strategies (Stepwise, 0-CoT, CoT, 3-shot, None), revealing that the top model scores only 0.46 on challenging instances and that models struggle with multi-attribute reasoning, high-dimensional spatial data, and context-rich language.

## Results

On DSR-Bench-main (4,140 instances across 20 data structures), GPT-5 (medium thinking) achieves the highest overall score of 0.79, followed by Gemini-2.5-Pro and o4-mini at 0.71. On the harder challenge subset, the best model (GPT-5) scores only 0.46/1, with K-D Heap and DAWG scoring near zero across all models. Instruction-tuned models show 30–50% accuracy drops when moving from single-attribute to multi-attribute structures (e.g., Queue 0.99 → Priority Queue 0.33 for Claude-3.5-Sonnet), and performance degrades sharply with input length (e.g., GPT-4.1 drops from 0.82 to 0.19 on Queue from short to long). Reasoning models outperform instruction-tuned models on hierarchical and network structures but remain brittle on spatial data (K-D Tree, Geometric Graph) and ignore user-defined tie-breaking constraints.

## Baselines & Comparisons

DSR-Bench is compared against three prior algorithmic benchmarks: CLRS-Text (Markeeva et al., 2024), NLGraph (Wang et al., 2023), and GraphQA (Fatemi et al., 2024). DSR-Bench is the only benchmark that simultaneously satisfies all six design criteria: broad coverage (20 data structures across 6 categories vs. 30 algorithms or graphs-only), hierarchical task organization, atomic operations, expressiveness for complex reasoning, natural language prompts, and auxiliary probes (spatial, realistic, code). CLRS-Text covers 30 classical algorithms but uses code-like syntax without natural language descriptions and provides no hierarchical decomposition or auxiliary probes. NLGraph and GraphQA are limited to graph tasks only, whereas DSR-Bench includes graph traversals (BFS/DFS) as prerequisites within a broader hierarchical design spanning linear, temporal, associative, hierarchical, network, and hybrid structures. DSR-Bench also introduces fully automated, deterministic evaluation via structured output with zero schema violations across 1,620 trials, avoiding the subjective LLM-based judging common in prior reasoning benchmarks.

## Relation to Prior Work

This paper carves new ground by repurposing data structures as atomic diagnostic units for LLM reasoning, departing from prior algorithmic benchmarks that evaluate end-to-end algorithm simulation (CLRS-Text) or are restricted to a single structure type (NLGraph, GraphQA). Unlike coding benchmarks (LiveCodeBench, SWE-bench) that conflate reasoning with interpreter execution, DSR-Bench isolates inherent structural reasoning through natural-language prompts with deterministic, automated evaluation. The hierarchical task organization—where simpler structures (queues, stacks) serve as prerequisites for complex ones (BFS, DAWG)—is a novel design principle absent from prior work, enabling fine-grained failure localization rather than only end-to-end pass/fail signals.

## Why It Matters / Open Questions

DSR-Bench provides the first systematic diagnostic tool for pinpointing *where* LLMs fail in algorithmic reasoning, with practical implications for safe deployment in domains like robotics and healthcare that depend on structural manipulation. The finding that even frontier models score only 0.46 on challenging instances, and that performance collapses on high-dimensional spatial data and context-rich narratives, highlights a significant gap between formal reasoning and real-world deployment. Open questions include whether models can identify appropriate data structures from task descriptions alone, whether intermediate-step scoring reveals additional bottlenecks, and whether algorithm-centric architectures can close the structural reasoning gap that scaling alone has not addressed.
