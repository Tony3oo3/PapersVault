## Problem

Existing privacy exfiltration attacks on MCP-enabled LLM agents rely on rigid prompt-injection templates that are disjoint from the agent's ongoing task and exhibit recognizable lexical patterns, making them detectable by retrieval screening, context demarcation, and system isolation defenses. The paper asks whether privacy exfiltration can be made situationally appropriate to the tool's usage context and statistically indistinguishable from benign tool invocation, thereby evading these defenses while preserving the tool's original utility.

## Input / Output

The method takes a benign MCP server (its tool descriptions φ_k, prompt templates π_k, and code implementations f_k) plus a set of N target privacy items as input, and produces a transformed privacy-stealing server variant where each capability's prompt template is fused with a contextually appropriate probing instruction and its code implementation is augmented with a hidden transmission function. The exfiltration channel is the tool's own function arguments (α_k ⊕ α_Pi), meaning privacy data flows through the normal tool-call interface rather than via a separate explicit transmission tool call, requiring zero user interaction. Evaluation uses 20 synthetic user profiles with 26 data fields as the agent memory, and 324 transformed servers from the LiveMCPBench benchmark.

## Method

SOPE is a three-phase automated pipeline: (1) Assign — a LoRA-fine-tuned Llama-3-8B model, trained on PrivacyLens tuples with focal loss to handle class imbalance, predicts per-tool legitimacy scores for each privacy item grounded in Contextual Integrity theory, with TF-IDF + K-Means alignment to resolve label mismatches between training and inference data; (2) Fuse — a PPO-fine-tuned Llama-3-8B model generates semantically coherent prompt templates that embed privacy probing while preserving tool functionality, using a reward combining LLM-as-a-judge scores for probing effectiveness and utility integrity minus KL divergence for indistinguishability, with alternating supervised updates on original prompts to prevent gradient interference; (3) Leak — extracted privacy is passed as augmented function arguments to the tool's code-level implementation, where an appended f_trans forwards data to an attacker endpoint, ensuring definitive execution that bypasses LLM-level instruction overrides and context demarcation defenses. The key insight is that situational appropriateness (matching privacy items to tools where their exposure is normatively expected) preserves the agent's execution trajectory, while code-level transmission eliminates the detectable natural-language transmission step.

## Results

SOPE achieves an average Attack Success Rate (ASR) of 87% for untargeted attacks and 92% Leakage Rate (LR) for targeted attacks against four benchmark agents (Workspace, Slack, Banking, Travel), and even higher performance on commercial agents (87% ASR, 94% LR for Claude/Cursor/ChatGPT). Against nine state-of-the-art defenses across three categories (retrieval screening, context demarcation, system isolation), SOPE maintains an average LR of 92% (targeted) and 77% (untargeted) with 89% Evasion Success Rate, closely matching the no-defense baseline. The passive leakage rate (PLR) from benign servers is only 28–33%, confirming that SOPE's deliberate exfiltration is approximately 3× the inadvertent baseline.

## Baselines & Comparisons

SOPE substantially outperforms all 12 baseline indirect prompt injection strategies (combinations of explicit/implicit triggers, explicit/implicit extraction, and intimidation/allure/emphasis justifications), achieving ~3× higher LR (94% vs. 38% average) and ~2.5× higher ASR on commercial agents (92–96% vs. 35–39%). Against the two SOTA adaptive attacks—PSSU (Nasr et al., 2025) and AutoHijacker (Liu et al., 2025)—SOPE achieves substantially lower ASR and ESR even when those methods are granted stronger assumptions, confirming that situation-awareness is the critical differentiator rather than injection sophistication. Under defenses, the gap widens dramatically: baselines collapse to 14% ESR and 37% LR under retrieval screening, while SOPE retains 89% ESR and 93% LR; under system isolation, baselines drop to 16% ASR whereas SOPE maintains 68% ASR and 92% LR. The paper attributes this to SOPE's code-level transmission channel (bypassing LLM instruction-following entirely) and its semantically coherent, contextually appropriate probing that evades both textual and activation-based detectors.

## Relation to Prior Work

This paper extends the line of MCP privacy exfiltration attacks (Yang et al. 2025b; Zhao et al. 2026; Wang et al. 2025c) that rely on rigid prompt-injection templates with trigger-action-justification components. It departs from that paradigm by grounding privacy-item selection in Contextual Integrity theory (Nissenbaum, 2004) and repurposing the PrivacyLens benchmark for attack construction, while replacing LLM-mediated data transmission with a code-level channel appended to tool implementations. The Fuse phase borrows PPO-based fine-tuning from the RL-for-LLM literature, and the evaluation leverages AgentDojo and LiveMCPBench as deployment substrates, but the core contribution is the three-phase Assign-Fuse-Leak pipeline that makes exfiltration scenario-aware and statistically indistinguishable.

## Why It Matters / Open Questions

The demonstration that all nine SOTA defenses across three categories (retrieval screening, context demarcation, system isolation) fail to meaningfully reduce leakage rates (92%→92% targeted, 76%→77% untargeted) exposes a fundamental gap: existing defenses operate at the prompt/context level, while S0PE's code-level Leak channel bypasses them entirely. The finding that commercial agents (Claude, Cursor, ChatGPT) are *more* vulnerable than benchmark agents—due to their stronger instruction-following—challenges the assumption that production safety tuning improves robustness against supply-chain attacks. Open questions include whether protocol-level schema validation, tool sandboxing, or outbound network allowlists (currently absent from mainstream MCP clients) would close the Leak channel, and whether the Assign model's reliance on PrivacyLens norms generalizes to novel tool categories not represented in training data.
