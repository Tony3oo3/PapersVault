## Problem

Existing CodeGen AI security research is heavily skewed toward red teaming (exposing vulnerabilities), while effective blue teaming defenses remain underdeveloped. Current defensive approaches suffer from poor alignment with security concepts, over-conservatism that inflates false positives (especially in vulnerability detection), and incomplete coverage of subtle or previously unseen risk scenarios. This paper asks whether comprehensive automated red-teaming knowledge can be systematically converted into actionable defensive guidance to close these gaps.

## Input / Output

The agent receives either a text-level code instruction (for bias, malicious, or prompt-injection detection) or a code snippet (for vulnerability detection), along with a task-type identifier. Internally, it retrieves the top-3 most similar entries from the red-teaming knowledge base via text-embedding-3-small similarity search, then summarizes them into constitutions. The output is a unified binary decision (safe/unsafe) paired with a task-specific message: a compliant code response or rejection explanation for instruction-level tasks, a yes/no label for prompt injection, or a vulnerability justification for code-level tasks. For code-level detection, the pipeline additionally produces executable test code and sandbox execution logs as intermediate artifacts feeding the final judgment.

## Method

BlueCodeAgent is a two-stage end-to-end pipeline. The offline red-teaming stage generates diverse risky instances using three complementary strategies: policy-based generation (prompting an uncensored Llama-3-8B model with enumerated bias/malicious/injection policies), seed-based adversarial prompt optimization (a red-teaming agent that adaptively calls jailbreak tools like GCG, AutoDAN, and Advprompter to maximize attack success rates), and knowledge-driven vulnerability generation (prompting GPT-4o with CWE-specific coding scenarios to produce insecure/secure code pairs). The online blue-teaming stage retrieves top-k similar knowledge entries for each test instance, summarizes them into actionable constitutions via a summarization model (inspired by Constitutional AI), and conditions the base LLM's safety decision on these constitutions. For vulnerable code detection, the agent further invokes a dynamic testing module: if static analysis flags a vulnerability, a separate model (Claude-3.7-Sonnet) generates executable test cases that run in isolated Docker sandboxes, and a final judge integrates the static analysis, execution results, and constitutions to produce the verdict. The key design insight is that constitutions increase true positives and reduce false negatives by broadening risk recognition, while dynamic testing reduces false positives by empirically verifying whether flagged vulnerabilities actually manifest at runtime—making the two mechanisms complementary rather than redundant.

## Results

With GPT-4o as the base model, BlueCodeAgent achieves F1 scores of 0.98 (bias), 1.00 (malicious/RedCode), 0.99 (malicious/RMCbench), and 0.99 (prompt injection) on the three text-level tasks, representing an average 14.7% F1 improvement over direct prompting. On vulnerable code detection (SecCodePLT), BlueCodeAgent with constitution + dynamic testing reaches F1 0.68 (GPT-4o) and 0.77 (Claude), outperforming direct prompting (0.64/0.75) and Vul-RAG (0.63/0.76). Dynamic testing reduces false positives by an average of 19.3% compared to the base model on vulnerability detection.

## Baselines & Comparisons

BlueCodeAgent substantially outperforms all guardrail baselines: Llama Guard 3-8B (F1 0.19–0.79) and LlamaFirewall (F1 0.00–0.25) are far surpassed on all four tasks, with gaps exceeding 0.20 F1 on bias and prompt injection. Against PurpCode-14b-RL, BlueCodeAgent wins on every task (e.g., 0.98 vs. 0.58 on bias, 1.00 vs. 0.89 on malicious/RedCode, 0.99 vs. 0.70 on prompt injection). On vulnerable code detection, BlueCodeAgent (0.68 GPT-4o / 0.77 Claude) edges out Vul-RAG (0.63 / 0.76) and PurpCode (0.67), while static analysis tools CodeQL (0.01), Semgrep (0.13), and Bandit (0.22) remain far behind. The LLM-ensemble baseline (0.75–0.92) is the closest competitor on text-level tasks but still trails BlueCodeAgent by 0.07–0.23 F1, and on prompt injection the ensemble's discussion variant actually degrades to 0.60 versus BlueCodeAgent's 0.99.

## Relation to Prior Work

This paper builds on Constitutional AI (Bai et al., 2022) by repurposing the constitution-guided decision-making paradigm for code security, where constitutions are dynamically summarized from red-teaming-generated knowledge rather than hand-written. It departs from prior blue-teaming efforts (Vul-RAG, PurpCode, Llama Guard) by framing red teaming not merely as an evaluation tool but as a knowledge-generation pipeline that feeds an agentic blue teaming agent. The dynamic sandbox-based testing component extends the static LLM-reasoning approach to vulnerability detection, addressing the over-conservatism problem identified by Ullah et al. (2024) and Ding et al. (2024). Unlike PurpCode, which uses red-teaming data for training, BlueCodeAgent uses it at inference time via retrieval and constitution summarization, enabling model-agnostic deployment without fine-tuning.

## Why It Matters / Open Questions

The paper addresses a genuine gap in CodeGen AI safety: while red teaming benchmarks and methods are abundant, effective blue teaming defenses remain underdeveloped, and existing guardrails (Llama Guard, LlamaFirewall) perform poorly on code-specific risks. The complementary decomposition—constitutions reducing false negatives and dynamic testing reducing false positives—provides a principled framework for combining static and runtime analysis. Limitations include evaluation on only four risk categories at the single-file level, reliance on proprietary models (GPT-4o, Claude) as backbones, and the ~26s end-to-end latency that may constrain real-time deployment. Open questions include scaling to repository-level code, extending to additional risk modalities, and whether the constitution mechanism generalizes to non-code domains.
