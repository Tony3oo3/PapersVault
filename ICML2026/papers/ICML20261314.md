## Problem

Standard mixed-precision training requires ~16 bytes of accelerator memory per parameter (FP32 weights, gradients, and optimizer states), making 7B-model training impractical without 100+ GiB of GPU memory. Existing mitigations—multi-accelerator sharding, CPU offloading, or parameter-efficient fine-tuning—either demand hardware many practitioners lack or fundamentally alter training dynamics. FlashOptim targets the per-parameter memory footprint directly, aiming to cut it by over 50% while preserving optimizer semantics and model quality.

## Input / Output

The method consumes BF16 model parameters (used directly for forward/backward passes), BF16 gradients, and compressed optimizer states (INT8 momentum, UINT8 variance, each with FP16 group-wise scales of 32 elements). It produces updated BF16 parameters paired with an INT8 correction term ρ, plus re-quantized optimizer states. The FP32 master weight is never persisted to HBM; it is reconstructed transiently inside a fused Triton kernel and immediately re-split, so the only persistent per-parameter storage is 2 bytes (BF16 weight) + 1 byte (INT8 correction) + 1 byte (INT8 momentum) + 1 byte (UINT8 variance) for AdamW.

## Method

FlashOptim combines two techniques. First, ULP-based weight splitting exploits the observation that the rounding error e = θ − θ′ is always bounded within ±ULP(θ′)/2, so its exponent is redundant. The error is rescaled to [−1, 1] and quantized to a signed INT8 (or INT16) integer, yielding ~24 bits of effective precision from a BF16+INT8 pair with near-zero reconstruction error (<10⁻⁹ relative error for 16-bit correction). Second, companded optimizer state quantization applies a one-line nonlinear preprocessing before standard group-wise INT8 quantization: a softsign-like function φ(x)=2x/(1+|x|) for momentum (spreading zero-concentrated values across bins) and a square root for variance (counteracting the heavy-tailed distribution from squared-gradient accumulation). Without companding, linear quantization of variance causes training to diverge. Both operations are fused into a single Triton kernel per optimizer step, and the approach composes with gradient release, FSDP, and activation checkpointing.

## Results

FlashOptim reduces AdamW per-parameter memory from 16 to 7 bytes (5 bytes with gradient release) and SGD from 12 to 6 bytes, cutting Llama-3.1-8B finetuning peak memory from 175 GiB to 113 GiB (−36%) with no measurable quality loss. On GPT-2 pretraining, FlashAdamW achieves a mean ICL score of 45.0±1.0% versus 44.0±0.4% for reference AdamW, with validation loss of 3.265 vs. 3.263. On ImageNet, FlashSGD reaches 77.16±0.09% top-1 accuracy (vs. 77.01±0.02% for SGD), and on GSM8k, FlashAdamW scores 75.15±0.49% (vs. 75.11±0.66% for reference AdamW). Optimizer step time is actually slightly faster (9.4 ms vs. 10.2 ms for AdamW on Llama-3.1-8B).

## Baselines & Comparisons

Against reference AdamW, FlashAdamW matches quality (val loss 3.265 vs. 3.263; Mean ICL 45.0 vs. 44.0) while cutting per-parameter memory from 16 to 7 bytes. Against 8bit-AdamW (Dettmers et al., 2022), FlashAdamW is clearly superior on both axes: it achieves 45.0% vs. 43.0% Mean ICL and 3.265 vs. 3.279 val loss, while also reducing total memory (7 bytes vs. 12 bytes per parameter) because 8bit-AdamW retains FP32 master weights. Against Kahan Splitting (Zamirai et al., 2020), FlashAdamW matches ICL quality (45.0 vs. 44.2) but reduces optimizer state memory as well (23.4 GiB vs. 44.9 GiB on Llama-3.1-8B), whereas Kahan Splitting only halves parameter memory. Against reference Lion, FlashLion matches val loss exactly (3.240) and slightly exceeds Mean ICL (44.7 vs. 44.0). The key differentiator is that FlashOptim is the only compared method that simultaneously reduces both parameter and optimizer-state memory without quality degradation, and it does so with no additional step-time overhead (9.4 ms vs. 10.2 ms for reference AdamW).

## Relation to Prior Work

FlashOptim combines and improves two existing lines of work: weight splitting (Zamirai et al., 2020; Warner, 2024), which stores a low-precision weight plus an error-correction term instead of a full FP32 master weight, and 8-bit optimizer state quantization (Dettmers et al., 2022), which compresses momentum and variance via group-wise linear quantization. The key departures are (a) replacing the floating-point error buffer with a ULP-normalized integer correction that achieves near-optimal reconstruction at 8 or 16 bits, and (b) adding distribution-specific companding functions (softsign for momentum, square-root for variance) before quantization, which the paper shows are essential rather than merely beneficial. Together with gradient release, these form a unified drop-in optimizer suite that composes with FSDP and activation checkpointing without altering optimizer semantics.

## Why It Matters / Open Questions

By cutting AdamW memory from 16 to 7 bytes per parameter (5 bytes with gradient release), FlashOptim makes 7B+ model finetuning feasible on a single high-end accelerator, lowering the hardware barrier for independent researchers and smaller labs. The method is a true drop-in replacement—no hyperparameter changes, no architectural modifications—and the open-source Triton implementation makes adoption straightforward. Open questions include whether the empirically chosen companding functions generalize to optimizer states with substantially different distributions (e.g., sparse embedding updates), whether 24-bit master weights remain sufficient under aggressive learning-rate annealing, and how the approach performs in activation-dominated regimes where parameter memory is a smaller fraction of total memory.
