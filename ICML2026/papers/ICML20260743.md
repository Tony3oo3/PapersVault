## Problem

In high-stakes AI deployment, a randomized deployment choice (lottery over alternatives) must clear every stakeholder's acceptability threshold, but stakeholders only provide binary accept/reject feedback rather than full utility functions. The paper asks: what is the minimum number of such queries needed to either find a unanimously acceptable lottery or certify that none exists, and can randomization or side information reduce this cost?
![Teaser figure](../imgs/ICML20260743/cropped_page3_idx0.webp)

## Input / Output

The algorithm receives n agents (each with an unknown utility vector in [0,1]^m and threshold τ_i ∈ (0,1]) and m alternatives forming the (m−1)-simplex, interacting only through a membership oracle Query(i, x) ∈ {True, False}. Parameters are ε-quantized (u_i(s_j), τ_i ∈ {0, ε, 2ε, …, 1}) to ensure finite-query exactness. The output is either a probability vector x ∈ Δ(S) satisfying ⟨u_i, x⟩ ≥ τ_i for all i, or NULL certifying that ∩_i A_i = ∅. Optional predictions—a permutation of agents by likely constraining-ness and a candidate lottery—can be supplied to reduce query cost.

## Method

The core subroutine LearnHyperplane recovers a single agent's acceptability halfspace on the simplex using O(m log(1/ε)) membership queries: it first probes all m vertices, then locates m−1 turning points along simplex edges via bisection (ExactThreshold), and reconstructs the boundary hyperplane. Building on this, an adaptive deterministic algorithm (Algorithm 2) learns an agent's constraint only when the current LP-selected candidate is rejected, achieving O(n² + nm log(1/ε)) worst-case queries. A randomized Clarkson-style sampling/reweighting algorithm (Algorithm 3) reduces the expected number of expensive hyperplane-elicitation calls to O(min{n, m³ log n}), yielding O(nm log n + min{n, m³ log n} · m log(1/ε)) expected queries—critical when n ≫ m³ log n. Learning-augmented variants exploit a predicted agent permutation (biasing scan order and sampling weights, reducing cost to O((n + m log(1/ε)) R(σ̂)) deterministically) and a predicted lottery (warm-starting edge threshold searches to O(m + m log(1 + δ_max/ε²)) per agent), while preserving worst-case guarantees under arbitrary advice. Matching lower bounds show Ω(n) and Ω(log(1/ε)) query dependence are unavoidable even for binary utilities.

## Results

The deterministic adaptive algorithm (Theorem 3.3) uses O(n² + nm log(1/ε)) queries to find a unanimously acceptable lottery or certify infeasibility. The randomized Clarkson-style algorithm (Theorem 3.4) improves the expected query count to O(nm log n + min{n, m³ log n} · m log(1/ε)), learning only a vanishing fraction of agents' halfspaces when n ≫ m³ log n. Matching lower bounds (Theorem 4.1) show Ω((n − min{n,m}) + (min{n,m} − 1) log(1/ε)) queries are unavoidable for any correct algorithm, and Ω(m) queries are needed even for a single agent (Theorem 4.2). Learning-augmented variants reduce the cost to O((n + m log(1/ε)) R(σ̂)) with a predicted permutation (Theorem 5.1) and O(m + m log(1 + δ_max/ε²)) per agent with a predicted lottery (Theorem 5.3), while preserving worst-case guarantees.

## Baselines & Comparisons

The paper does not compare against external empirical baselines; instead, it compares its algorithmic strategies against each other and against information-theoretic lower bounds. The deterministic adaptive algorithm (Algorithm 2) improves over full elicitation by learning only violated agents' halfspaces, but incurs an O(n²) verification overhead in the worst case. The randomized algorithm (Algorithm 3) eliminates this quadratic term, reducing verification to O(nm log n) queries in expectation while limiting expensive halfspace learning to O(min{n, m³ log n}) agents, bringing the dependence on n close to the Ω(n) lower bound up to logarithmic factors. The learning-augmented permutation variant achieves O(n + m log(1/ε)) queries under perfect advice (R(σ̂)=1), which is within a constant factor of the lower bound, and degrades smoothly to the advice-free O(n² + nm log(1/ε)) bound under worst-case advice. The lottery prediction variant reduces per-agent elicitation from O(m log(1/ε)) to O(m) under perfect edge information, with a proven Ω(log(1 + δ/ε²)) lower bound showing the logarithmic dependence on prediction error is tight.

## Relation to Prior Work

This paper sits at the intersection of preference elicitation, query learning of geometric concepts, and low-dimensional linear programming. It adapts Clarkson's (1995) randomized sampling/reweighting approach for low-dimensional LP to a strictly weaker oracle model where violated constraints must be explicitly elicited via binary accept/reject membership queries rather than received for free from a separation oracle. The learning-augmented variants follow the Lykouris & Vassilvitskii (2021) framework of consistency/robustness/smoothness, but apply it to a prediction target (which constraints will bind, or a promising candidate point) that is distinct from the online/metric predictions dominating that literature. The key departure from prior elicitation work is the objective: rather than reconstructing each agent's full utility function or finding an optimal example, the goal is to find any single point in the intersection of n unknown halfspaces (or prove emptiness), which enables algorithms that learn only a small subset of constraints.

## Why It Matters / Open Questions

The paper provides the first query-complexity characterization of a natural AI governance problem: determining whether a unanimously acceptable randomized deployment exists using only binary stakeholder feedback. The randomized algorithm's guarantee that only O(min{n, m³ log n}) agents' halfspaces need to be learned in expectation (versus all n) is practically relevant in settings with small menus but large stakeholder pools (canary rollouts, A/B tests, red-teaming). Key limitations include the expected-utility assumption (excluding CVaR, rank-dependent, or tail-sensitive criteria), noise-free binary feedback, and the finite-precision requirement; extending to stochastic oracles and non-expected-utility acceptability is identified as important future work. The NP-hardness of even the relaxed 'maximize number of accepting agents' objective (Theorem B.3) underscores why unanimity is a clean and computationally tractable baseline for conservative deployment gates.
