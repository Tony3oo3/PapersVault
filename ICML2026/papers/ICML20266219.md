## Problem

Existing working memory mechanisms in multi-step RAG systems treat memory as passive storage for isolated primitive facts, using unstructured text or binary graph edges that cannot model high-order (n-ary) correlations. This static, fragmented representation limits the LLM's ability to perform complex relational modeling and global sense-making over long contexts, where resolving a query requires uncovering latent connections among spatially distant events.
![Teaser figure](../imgs/ICML20266219/cropped_page2_idx1.webp)

## Input / Output

The system takes a target query, a document segmented into 200-token chunks (50-token overlap), and an offline-preprocessed entity-relationship graph (built via GPT-4o + LightRAG, with bge-m3 embeddings for all nodes, edges, and chunks). At each of up to T interaction steps, the LLM generates subqueries, retrieves entities/relationships/chunks via vector matching and graph indexing, and evolves its hypergraph memory before ultimately producing a free-text response grounded in the final memory state (all hyperedge descriptions plus associated text chunks, capped at 50 chunks).

## Method

HGMEM structures working memory as a hypergraph where each hyperedge is a distinct 'memory point' encoding a specific perspective of the accumulated evidence, with vertices corresponding to entities from the external graph. At each step, the LLM performs adaptive memory-based evidence retrieval: subqueries targeting existing memory points trigger local investigation (searching the neighborhood of anchor nodes in both the memory hypergraph and the external graph), while subqueries about unexplored aspects trigger global exploration (searching all graph nodes not yet in memory). Retrieved evidence is consolidated via three operations—update (revise hyperedge descriptions), insertion (create new hyperedges), and merging (combine two hyperedges into one with a union of subordinate vertices and an LLM-synthesized description)—where merging is the key mechanism for progressively building high-order n-ary correlations from primitive binary facts. The evolving hypergraph topology then guides subsequent retrieval and provides the LLM with integrated propositions rather than a flat list of disparate facts for final response generation.

## Results

HGMEM consistently achieves the best scores across all four benchmarks with both GPT-4o and Qwen2.5-32B-Instruct backbones. With GPT-4o, HGMEM scores 65.73/69.74 (Comprehensiveness/Diversity) on Longbench, 55.00% on NarrativeQA, 73.81% on NoCha, and 62.96% on Prelude, outperforming the strongest multi-step baseline DeepRAG (63.62/65.98, 45.00%, 67.46%, 56.30%) by 2.1–7.5 points. Notably, HGMEM powered by the smaller Qwen2.5-32B-Instruct (64.18/66.51, 51.00%, 70.63%, 62.22%) matches or exceeds GPT-4o-powered baselines on most metrics, demonstrating that the structured memory mechanism compensates for model-scale differences.

## Baselines & Comparisons

HGMEM outperforms all eight baselines across every dataset and both model backbones. Among traditional RAG methods, GraphRAG and LightRAG excel on Prelude (59.26%/61.48% with GPT-4o) due to their global community representations but lag on Longbench comprehensiveness and NarrativeQA; HippoRAG v2, relying on knowledge triples, performs best on NoCha (72.22%) but is weakest on NarrativeQA (34.00%) due to limited event/plot coverage. The multi-step baselines DeepRAG and ComoRAG, which use unstructured working memory, struggle most on sense-making tasks—DeepRAG scores only 45.00% on NarrativeQA and 56.30% on Prelude with GPT-4o, well below HGMEM's 55.00% and 62.96%. In the extended comparison (Table 6, Qwen2.5-32B), HGMEM (51.00/70.63/62.22) beats KnowTrace (44.00/69.04/44.44), A-Mem (47.00/65.08/55.56), and PropRAG (33.00/68.25/51.11), with the largest gap on Prelude where PropRAG's static hypergraph index cannot dynamically form high-order correlations. The key differentiator is that HGMEM's merging operation builds hyperedges connecting significantly more entities (Avg-Nv of 7.07–7.97 on sense-making queries vs. 3.74–4.10 without merging), directly enabling the complex relational modeling that other methods' binary-edge or flat-memory representations cannot capture.

## Relation to Prior Work

This paper extends the multi-step RAG working-memory line (ReAct, IRCOT, ComoRAG, DeepRAG) by replacing the prevailing static, fact-accumulation memory with a dynamically evolving hypergraph. It departs from prior graph-structured memories (ERA-CoT, KnowTrace) whose binary edges cannot encode n-ary relations, and from hypergraph-based RAG indices (Hyper-RAG, HypergraphRAG, PropRAG) that treat hypergraphs as fixed offline structures rather than query-adaptive, online-evolving memory. The key conceptual move is repurposing the hyperedge as a 'memory point' that can be updated, inserted, and—critically—merged to form high-order correlations during reasoning, bridging the gap between structured knowledge indexing and cognitive working memory.

## Why It Matters / Open Questions

The paper identifies a concrete representational bottleneck in multi-step RAG: treating working memory as a flat list of primitive facts fragments reasoning on global sense-making tasks. The merging operation that builds high-order hyperedges is the core mechanism, and the ablation (w/o. Merging drops NoCha accuracy from 70.63% to 61.11%) provides clear evidence of its importance. Practical impact is reinforced by the finding that Qwen2.5-32B-Instruct with HGMEM matches or exceeds GPT-4o-powered baselines at comparable token cost, suggesting structured memory can partially substitute for model scale. Open questions include scalability to documents far beyond 280k tokens, sensitivity to the quality of the offline graph (mitigated but not eliminated), and whether the hypergraph memory paradigm transfers to non-narrative, multi-document, or agentic settings.
