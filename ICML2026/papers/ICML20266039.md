## Problem

Reinforcement learning for agentic multimodal models suffers from interaction collapse, where models progressively reduce tool usage and multi-turn reasoning, undermining the benefits of agentic behavior. Additionally, dynamic tooling via Python has been largely confined to image understanding and proprietary APIs, leaving open-weight agentic RL for video underexplored. This paper addresses both the training instability and the absence of an open-weight framework that sustains multi-turn tool use across image and video tasks.

## Input / Output

PyVision-Image takes an RGB image (resized between 3,136 and 2,000,000 pixels) plus a text query, while PyVision-Video takes a full video plus a text query. Critically, for video the full video is loaded exclusively into the Python runtime and never into the MLLM context; the model must write Python code to selectively sample and plot task-relevant frames, which are then appended to the context as rendered images. The output is a multi-turn interleaved sequence of natural-language reasoning, executable Python code blocks (wrapped in <code> tags), and execution results (wrapped in <interpreter> tags), terminated by a final answer in <answer> tags, with a maximum turn budget of 30 and 32K context length.

## Method

PyVision-RL builds on Qwen2.5-VL-7B with a two-stage pipeline: SFT cold-start (7K image / 44K video samples) followed by 700 steps of GRPO-based RL. Two key RL innovations prevent interaction collapse: (1) an accumulative tool reward R = R_acc + 0.1·n_tc·1{R_acc=1} that adds a bonus proportional to the number of tool calls only when the answer is correct, explicitly incentivizing sustained multi-turn tool use; and (2) an oversampling-filtering-ranking rollout strategy (Standard Deviation Sorting) that oversamples α·B prompts, discards broken trajectories and zero-variance groups, then ranks remaining groups by reward standard deviation as a difficulty proxy and retains the top B·G for training. The advantage computation removes the standard deviation normalization term from vanilla GRPO to reduce variance in gradient updates. For video, the on-demand context construction mechanism—where the agent dynamically fetches frames via Python rather than receiving a fixed uniform sampling—reduces average visual token usage from ~45K (Qwen2.5-VL-7B) to ~5K per sample while improving accuracy on VSI-Bench.

## Results

PyVision-Image (built on Qwen2.5-VL-7B) achieves state-of-the-art results across visual search, multimodal reasoning, and agentic reasoning benchmarks, scoring 88.7 on V* (avg@32), 78.1 on HRBench-4K, 61.6 on DynaMath, 55.8 on MathVerse, and 47.7 on WeMath. PyVision-Video attains 44.0% average on VSI-Bench for spatial reasoning while consuming only ~5K visual tokens per sample, compared to ~45K for Qwen2.5-VL-7B at its best accuracy (38.0%). The method outperforms the strongest prior dynamic-tooling baseline DeepEyes-v2 by +6.9% on V*, +4.4% on DynaMath, and +9.6% on WeMath.

## Baselines & Comparisons

PyVision-Image outperforms all 11 image-based baselines on the majority of benchmarks. Against the base model Qwen2.5-VL-7B, it gains +10.2% on V*, +6.5% on HRBench-4K, +8.3% on DynaMath, +10.2% on MathVerse, and +13.1% on WeMath. Among dynamic-tooling methods, it surpasses the strongest competitor DeepEyes-v2 by +6.9% on V*, +4.4% on DynaMath, +3.1% on MathVerse, and +9.6% on WeMath, though it trails by 0.2% on MathVision (28.7 vs. 28.9). Against static-toolset methods, it beats Mini-o3 (the closest static baseline) by +0.5% on V* and +0.6% on HRBench-8K. For video, PyVision-Video outperforms VITAL (+2.2% on VSI-Bench avg) and Video-R1 (+6.9%), while SpaceR achieves slightly higher accuracy (45.6% vs. 44.0%) but at ~5× the visual token cost (25K vs. 5K per sample), making PyVision-Video the most token-efficient method at competitive accuracy.

## Relation to Prior Work

This paper extends the PyVision agentic scaffold (Zhao et al., 2025a), which uses Python as a primitive tool for dynamic image manipulation, into a full RL training framework built on a modified GRPO (Shao et al., 2024). It departs from prior dynamic-tooling work (DeepEyes-v2, Thyme, CodeDance) by addressing the interaction collapse problem—where RL-trained models learn to reduce tool usage—through an accumulative tool reward and an oversampling-filtering-ranking rollout strategy. For video, it introduces on-demand context construction, a departure from both static video-clipping tools (VITAL) and uniform frame sampling (Qwen2.5-VL), by loading the full video only into the Python runtime and letting the model selectively fetch frames during reasoning.

## Why It Matters / Open Questions

The paper reframes interaction collapse in agentic multimodal RL as a training-incentive and rollout-selection problem rather than a fundamental limitation of test-time interaction, which had led to skepticism in the field. The on-demand context construction for video (5K vs. 45K visual tokens at higher accuracy) offers a practical efficiency path for long-video understanding that could be adopted broadly. Open questions include whether the approach generalizes beyond Qwen2.5-VL-7B, whether the 0.1 tool-reward coefficient transfers across model scales, and whether on-demand frame fetching scales to much longer or higher-resolution videos where the Python runtime itself becomes a bottleneck.
