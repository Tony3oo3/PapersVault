## Problem

Existing benchmarks for LLM memory evaluate systems on homogeneous long-context reading comprehension tasks in a static manner, ignoring the dynamic nature of continual learning. No benchmark exists that tests whether LLM systems can actually learn from accumulated user feedback (procedural memory) to improve performance over time, which is the core capability needed for real-world LLM services.
![Teaser figure](../imgs/ICML20260050/cropped_page3_idx0.webp)

## Input / Output

Each task case is structured as a tuple (q, v, c) where q is the user query, v is evaluation metadata (ground truth or criteria), and c is an optional context corpus. The system receives both the current task context and feedback logs S from prior training interactions (explicit verbal critiques, like/dislike/copy actions, or implicit behaviors), and must produce a task response. Performance is scored on a 1–10 scale via LLM-as-judge merging multiple native dataset metrics, with min-max normalization or z-score aggregation across datasets. Feedback logs are generated only on the 4/5 training split to prevent test leakage.

## Method

MemoryBench introduces a three-module simulation framework: a Task Provider that supplies queries, contexts, and evaluation metadata from 11 public datasets spanning 3 domains, 4 input/output length formats, and 2 languages; a User Simulator that generates realistic feedback via a hybrid LLM-as-user paradigm (deterministic metric mapping for verifiable tasks, persona-conditioned LLM prompting for open-ended tasks) combined with a probabilistic action model using sigmoid functions calibrated to empirical user behavior statistics (6.5% feedback rate, 86:14 like-to-dislike ratio); and a Performance Monitor that evaluates on held-out test data. The key design insight is separating declarative memory (semantic/episodic context) from procedural memory (feedback logs describing past performance), and requiring systems to exploit both simultaneously. Baselines include naive RAG (BM25 and embedding-based, with session- or message-level chunking) and SOTA memory systems (A-Mem, Mem0, MemoryOS), all sharing the same Qwen3-8B backbone, tested under both off-policy and on-policy settings.

## Results

Across 11 datasets spanning open-domain, legal, and academic tasks in four input/output length formats, LLMsys with memory support generally outperform the Vanilla baseline (Qwen3-8B without memory), confirming that simulated user feedback is useful for performance improvement. However, none of the SOTA memory-based systems (A-Mem, Mem0, MemoryOS) consistently outperform simple RAG baselines (BM25 or Qwen3-Embedding-0.6B with session/message-level documents). Notably, on the SiLo partition, Vanilla actually outperforms all memory-based systems, and Mem0 fails entirely on Open-Domain and LiSo partitions due to context-length limitations. In terms of efficiency, A-Mem is the fastest memory-based system, while MemoryOS requires over 17 seconds per case for memory construction, and Mem0 shows highly inconsistent inference times across task formats.

## Baselines & Comparisons

The paper evaluates three SOTA memory-based LLMsys—A-Mem, Mem0, and MemoryOS—against naive RAG baselines (BM25-S, BM25-M, Embed-S, Embed-M) and a Vanilla (no-memory) baseline, all using Qwen3-8B as the backbone. None of the three memory systems consistently beats the RAG baselines across the seven data partitions (Open-Domain, Legal, Academic, LiSo, SiLo, LiLo, SiSo); in fact, RAG methods that simply index all context and feedback logs as retrieval documents are competitive or superior in most settings. A-Mem is the most efficient memory system but its effectiveness does not surpass naive RAG in many cases. Mem0 shows the most inconsistent behavior: it is fastest on long-input tasks but slowest on short-input tasks, and it cannot process Open-Domain or LiSo data at all due to context-length constraints. MemoryOS exhibits more consistent inference times but has the highest memory-construction overhead (>17 s/case). The authors note that on Locomo specifically (a long-input, short-output reading comprehension task), memory-based methods do outperform BM25 RAG, suggesting the SOTA systems are over-specialized for that narrow task format and lack generalizability to heterogeneous tasks with procedural (feedback-based) memory.

## Relation to Prior Work

This paper carves new ground at the intersection of neuroscience memory taxonomy (Atkinson & Shiffrin's declarative/procedural distinction) and IR user-feedback simulation, repurposing both to create a benchmark for evaluating continual learning in LLM systems. It departs from prior LLM memory benchmarks (Locomo, DialSim, MemBench, LongMemEval) that focus on static retrieval of declarative memory (semantic/episodic) over long contexts, by introducing procedural memory built from simulated user feedback and dynamic multi-turn interaction. The user simulation framework draws on decades of IR click-model and user-behavior modeling literature (Shen & Zhai, Agichtein et al., Craswell et al.) but adapts it to the LLM service context with an LLM-as-user paradigm.

## Why It Matters / Open Questions

The benchmark reveals that SOTA memory-based LLM systems (A-Mem, Mem0, MemoryOS) are neither effective nor efficient at utilizing procedural knowledge from user feedback, failing to consistently outperform naive RAG baselines across diverse tasks. This challenges the implicit assumption in the memory-for-LLMs literature that sophisticated memory architectures automatically enable continual learning, and highlights that current systems treat all inputs uniformly as declarative memory rather than distinguishing and leveraging feedback-derived procedural knowledge. Open questions include how to design memory mechanisms that can filter, interpret, and act on heterogeneous feedback signals across domains, and whether parametric updates (e.g., SFT) can complement non-parametric memory for true continual improvement. The simulated-feedback approach introduces potential systematic biases that limit external validity, and the single-backbone-LLM evaluation (primarily Qwen3-8B) leaves generalizability across model families partially untested.
