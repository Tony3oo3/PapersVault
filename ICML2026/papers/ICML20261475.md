## Problem

Existing LLM routers select a single model per query or use heuristic fixed-size subsets, making them susceptible to misrouting without any statistical guarantee that the selected set contains a correct model. The paper asks how to constrain the selection set size while rigorously guaranteeing that it covers at least one ground-truth LLM, and how to do so in a post-hoc, model-agnostic manner that does not require retraining the base router.

## Input / Output

Given a text query and a base router's scores for each of K candidate LLMs, RACER produces a variable-size calibrated model set (which may be empty, triggering abstention) and a final aggregated answer. The set size is adaptive per query—determined by a single pre-computed threshold applied to non-conformity scores—so easy queries may invoke only 1–2 models while uncertain queries invoke more. The method is entirely post-hoc: it consumes only the base router's scores and a finite labeled calibration set, requiring no architectural changes or retraining of either the router or the LLMs.

## Method

RACER formulates routing as the α-VOR problem (minimize expected set size subject to misrouting risk ≤ α) and solves it via a conformal-prediction-style calibration. It augments the model pool with a virtual null model to handle abstention, converts base router scores into non-conformity scores (router score-gap or inverse probability), and constructs a nested family of model sets parameterized by a threshold λ. The threshold is calibrated on a finite labeled set using the finite-sample bound λ̂ = inf{λ : n/(n+1)·L̄_n(λ) + 1/(n+1) ≤ α}, yielding distribution-free risk control (Theorem 4.3) and a matching lower bound showing the achieved risk is within O(1/n) of the target (Theorem 4.5). At inference, the calibrated set is aggregated via majority voting or confidence-weighted voting (using router scores, verbal binary confidence, or P(True) probabilities) to produce the final answer.

## Results

Across four benchmarks (GSM8K, MMLU, CMMLU, ARC-Challenge) and three base routers, RACER consistently improves downstream accuracy over single-model routing. The best configuration (RouterDC + RACER-P with aggregation) achieves 62.1% average accuracy, surpassing the best individual candidate LLM (Dolphin-2.9-Llama3-8b at 57.1%) by 5.0 percentage points. RACER achieves up to 4.0% absolute accuracy gain on a single benchmark (MLPR on CMMLU) and an average improvement of 3.6% across all tasks. Compared to full-model aggregation, RACER reduces model calls by up to 58.6% while simultaneously improving accuracy by up to 4.49%.

## Baselines & Comparisons

RACER is evaluated as a post-hoc enhancement on three base routers: RouterDC (Chen et al., 2024), MLPR (Huang et al., 2025), and KNNR (Hu et al., 2024). RACER consistently outperforms all three base routers on every benchmark: RouterDC improves from 60.9% to 62.1% average (RACER-P), MLPR from 57.0% to 60.6%, and KNNR from 59.8% to 61.2%. The gains are largest for the weakest router (MLPR, +3.6% average), suggesting RACER is most beneficial when the base router's ranking is less reliable. RACER also surpasses the best individual candidate LLM (Dolphin-2.9-Llama3-8b, 57.1% average) by 5.0 percentage points, demonstrating that calibrated multi-model aggregation with risk control outperforms even the strongest single model. Against full-model aggregation (calling all 7 LLMs), RACER achieves higher accuracy in 10/12 configurations (RACER-P) while reducing model calls by up to 58.6%, confirming that excluding poorly-ranked models via risk-aware calibration is more effective than aggregating all available models.

## Relation to Prior Work

RACER extends the conformal risk control framework (Angelopoulos et al., 2024) from answer-space prediction to model-space routing, calibrating a threshold over a pool of LLMs rather than over candidate answers for a single model. It departs from existing subset routing methods (e.g., LLM-Blender's heuristic top-k) by replacing fixed-size selection with a risk-calibrated, variable-size set construction that supports abstention via a virtual null model. The method is explicitly positioned as a post-hoc wrapper over any deterministic base router (RouterDC, MLPR, KNNR), distinguishing it from end-to-end routing architectures that require retraining.

## Why It Matters / Open Questions

RACER provides the first distribution-free, model-agnostic risk guarantee for LLM routing, making it applicable to safety-critical multi-model deployments where the probability of selecting no correct model must be strictly bounded. The practical finding that risk-aware model exclusion outperforms full-ensemble aggregation (up to 58.6% fewer calls with higher accuracy) challenges the common 'more models is better' heuristic and offers a concrete efficiency lever for production systems. Key limitations include the need for a labeled calibration set, the exchangeability assumption (requiring re-calibration under distribution shift), and dependence on base router quality; open questions include scalability to very large model pools and extension to open-ended generation tasks beyond multiple-choice benchmarks.
