## Problem

Spectral clustering of evolving graphs requires a data structure that handles both edge insertions and deletions while answering cluster membership queries quickly. Existing approaches either rebuild the full clustering on every query (prohibitively slow), support only insertions, or incur polynomial-in-k update times that make them impractical. No prior method achieves sublinear query time with logarithmic update time and strong approximation guarantees for the normalised cut objective.

## Input / Output

The data structure consumes a sequence of edge insertions and deletions on a weighted graph, where graph parameters (node count, max degree, volume) change over time. At query time it receives a node set Y ⊆ V and a number of clusters k, and returns a cluster label in {1,…,k} for every node in Y that is α(1+ε)/(1−ε)-consistent with the optimal normalised cut. The coreset size depends only on k and ε (not on n), and k can be chosen at query time rather than fixed in advance.

## Method

The core contribution is the Just-in-Time Sampling Tree, which maintains the adaptive sampling distributions needed for coreset construction without storing explicit probabilities. Each tree node stores auxiliary quantities (set size, sum of degrees, delta terms f_δ, and decomposed h^b/h_s terms) that allow computing the sampling distribution f(S,C) and g(S,C) on demand in O(1) per node. The key decomposition separates f(S,C) into a base part (linear in |S| and Σdeg) plus a sparse delta term updated only for neighbors of newly added seeds, and separates g(S,C) by factoring out w(C(x*)) so that adding a seed requires only O(d_max²) leaf updates rather than O(n). Logical timestamps lazily reset stale state between queries, avoiding full tree rebuilds. This yields O(log n) worst-case edge update time and O(k·d_max²·log n) coreset extraction time, which combined with the static coreset spectral clustering algorithm of Jourdan et al. (2025) gives the full dynamic data structure.

## Results

The proposed fully dynamic coreset spectral clustering data structure achieves O(log n) worst-case edge update time and O(k·d_max²·log n) + γ(n,ε,k,Y) query time with approximation ratio α(1+ε)/(1−ε), where the coreset size is O(ε⁻⁴k²) independent of n. Experimentally, all data structures achieve similar clustering quality (ARI), but the proposed method is orders of magnitude faster than Naive spectral clustering on query time for large graphs (e.g., EMNIST) and orders of magnitude faster than LS24 and Merge&Reduce on edge update time. Compared to the static CSC algorithm, the proposed method's query time grows much more slowly, with the static algorithm taking ten times longer per query by the end of experiments. The coreset size has no dependence on n (not even logarithmic), and k can be chosen at query time, unlike Merge&Reduce which incurs a polynomial dependence on k in its update time.

## Baselines & Comparisons

Against Naive spectral clustering, the proposed method achieves orders of magnitude faster query time on large graphs (e.g., EMNIST) while maintaining comparable ARI, since Naive must run full spectral clustering on the entire graph at each query. Against the Static CSC algorithm (Jourdan et al., 2025), the proposed method matches ARI but its query time grows far more slowly as the experiment progresses, with the static algorithm taking ten times longer per query by the end due to its O(nk log n) coreset construction cost. Against LS24 (Laenen & Sun, 2024), the proposed method is orders of magnitude faster on edge update time and competitive on query time for smaller experiments, though LS24 only supports edge insertions (not deletions) and targets a different objective (k-way expansion) so approximation ratios are not directly comparable. Against Merge&Reduce (Henzinger & Kale, 2020), the proposed method is orders of magnitude faster on edge update time (O(log n) vs. O(ε⁻⁴k³ log⁵ n)) while achieving similar query time on large graphs; Merge&Reduce also cannot be run on larger experiments within the 20,000-second time limit, and its update time has an unavoidable polynomial dependence on k, whereas the proposed method allows k to be chosen freely at query time.

## Relation to Prior Work

This paper extends the static Coreset Spectral Clustering algorithm of Jourdan et al. (2025) to the fully dynamic setting by introducing Just-in-Time Sampling Trees, which maintain auxiliary quantities (degrees, delta terms, seed-set weights) rather than explicit sampling probabilities, enabling O(log n) edge updates instead of the linear rebuild required by the static method. It departs from the generic Merge&Reduce framework of Henzinger & Kale (2020), which achieves dynamic coresets but incurs a polynomial dependence on k in update time, by designing a problem-specific data structure that avoids this dependence entirely. The work also builds on the Dhillon et al. (2004) equivalence between kernel k-means and normalised cut, and on the importance-sampling coreset construction of Jiang et al. (2024), adapting both to handle edge insertions and deletions with provable approximation guarantees.

## Why It Matters / Open Questions

This is the first fully dynamic data structure for spectral clustering supporting both edge insertions and deletions with a provable α(1+ε)/(1−ε) approximation guarantee and O(log n) worst-case update time, a significant theoretical improvement over the O(ε^{-4}k^3 log^5 n) update time of the Merge&Reduce approach. The coreset size is independent of n (not even log n), and k can be chosen at query time, offering practical flexibility for workloads where the number of clusters evolves. A key limitation is the d_max^2 factor in query time, which is acceptable for sparse graphs (where d_max is polylogarithmic) but could degrade on dense graphs; the paper does not explore whether this factor can be tightened. Open questions include whether the just-in-time sampling tree paradigm generalises to other kernel-based clustering objectives or to vertex insertions/deletions beyond edge updates.
