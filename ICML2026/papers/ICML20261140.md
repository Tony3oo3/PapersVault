## Problem

Parallel agentic systems that run multiple independent agent teams to improve robustness suffer from substantial redundant computation: teams repeatedly perform the same intermediate steps (web searches, code generation, table parsing) because existing frameworks treat trajectories as fully independent by design and discard intermediate results once generated. This paper asks whether parallel agentic systems can retain the benefits of diverse trajectory exploration while selectively reusing intermediate information across teams to reduce wall-clock runtime without sacrificing solution quality.

## Input / Output

The memory controller receives three embedded components per step: a frozen text-embedding of the task query, embeddings of all currently stored memory-key summaries, and embeddings of the current step triplet (agent input, agent output, and a 15–20 word step summary). These are projected via learnable linear layers into the controller's token space and concatenated into a single context vector. The controller outputs a single binary token (YES/NO) per step, deciding whether the (summary, raw-output) pair is admitted to the global memory bank. At the system level, the final output is an LLM-aggregated answer combining candidate solutions from all K parallel teams.

## Method

LTS introduces a global shared memory bank storing key-value pairs (concise summary as key, raw agent output as value) accessible to all parallel teams, where orchestrators see only summary keys and selectively retrieve full values to control context growth. A lightweight Qwen3-0.6B controller with LoRA adapters (r=16) makes the binary admission decision by operating on projected embedded tokens rather than raw text, keeping per-step overhead to ~0.2% of total runtime. The controller is trained via stepwise policy gradient (REINFORCE) with three key components: (1) group-relative advantage estimation that normalizes episode rewards across G independent executions per input to handle heterogeneous task difficulty, (2) usage-aware reward shaping that grants an additional bonus only to admitted steps whose memory keys are actually retrieved by another team AND contribute to a non-zero task reward, and (3) an explicit sparsity penalty on the admission probability to prevent degenerate always-admit behavior. All agent components remain frozen during training; gradients flow only through the controller's LoRA adapters and projection layers, enabling stable learning under sparse outcome-level supervision.

## Results

On GAIA (validation set), LTS achieves 30.4% overall accuracy with Qwen3-32B and 49.1% with GPT-5.1, while reducing wall-clock runtime by 55.0% and 25.1% respectively compared to the memory-free M1-Parallel baseline. On AssistantBench (test set), LTS reaches 20.3% (Qwen3-32B) and 26.7% (GPT-5.1) overall accuracy with 40.8% and 44.6% runtime reductions. Gains are most pronounced on the hardest difficulty tiers, e.g., GAIA Level-3 accuracy improves from 7.7% to 11.8% (Qwen3-32B) and from 16.0% to 20.0% (GPT-5.1) over M1-Parallel.

## Baselines & Comparisons

LTS is compared against two baselines: MagenticOne (single team, K=1) and M1-Parallel (three independent teams, K=3, no shared memory). Against M1-Parallel, LTS wins on both accuracy and runtime across all settings: with Qwen3-32B it improves GAIA accuracy from 24.8% to 30.4% (+5.6 pp) while cutting runtime from 1569s to 892s (−55%), and with GPT-5.1 it improves GAIA from 47.9% to 49.1% (+1.2 pp) while reducing runtime from 1005s to 781s (−25%). On AssistantBench, LTS similarly outperforms M1-Parallel in accuracy (20.3% vs 14.7% for Qwen3-32B; 26.7% vs 24.0% for GPT-5.1) while reducing runtime by 40–45%. Against the single-team MagenticOne baseline, LTS achieves substantially higher accuracy on both benchmarks (e.g., 30.4% vs 22.5% on GAIA with Qwen3-32B) while also being faster than M1-Parallel, though it runs longer than the single-team MagenticOne due to the inherent cost of parallel execution. The paper further shows that naive memory sharing (LTS-AddAll) actually degrades accuracy relative to M1-Parallel, confirming that the learned selective admission is critical for the gains.

## Relation to Prior Work

This paper extends the parallel agentic execution paradigm introduced by M1-Parallel (Zhang et al., 2025a), which runs multiple MagenticOne-style teams independently and aggregates final outputs, by introducing a global shared memory bank with a learned admission controller. While prior memory work in agentic systems (Generative Agents, MemoryBank, Reflexion) focuses on persistent cross-episode or personalization memory, LTS studies ephemeral per-task memory whose sole purpose is reducing redundant intermediate computation across parallel teams. The RL training objective with usage-aware reward shaping and group-relative advantage estimation is a novel application of policy gradient methods to the discrete memory-admission decision, departing from the prompted-LLM or heuristic filtering approaches that would otherwise be used.

## Why It Matters / Open Questions

The 40–55% wall-clock runtime reduction while simultaneously improving accuracy demonstrates that parallel agentic systems can be made substantially more efficient without sacrificing solution quality, which is practically important as these systems are increasingly deployed for long-horizon, tool-intensive tasks. The finding that naive sharing (admitting all steps) degrades accuracy challenges the intuition that more shared information is always beneficial, highlighting that selective admission is a non-trivial control problem. Key limitations include the per-task scope (no cross-episode persistence), absence of memory deletion or revision, and training on a single benchmark (AssistantBench dev split) before zero-shot transfer to GAIA. Open questions include whether the learned admission policy generalizes to substantially different task distributions, how it interacts with dynamic team counts at inference, and whether richer memory management (eviction, consolidation) could further improve the efficiency-accuracy tradeoff.
