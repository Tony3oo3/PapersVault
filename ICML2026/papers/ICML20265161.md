## Problem

Existing coding agent training datasets focus on a single task (typically GitHub issue resolution), yet real-world agents must handle diverse tasks like test generation and library construction, and training on one task does not reliably transfer to others. The paper asks what commonalities diverse coding tasks share and how to design scalable training tasks that teach transferable agent skills without the costly setup of executable repositories.
![Teaser figure](../imgs/ICML20265161/cropped_page1_idx0.webp)

## Input / Output

Each training instance provides a Python repository (cloned at a specific commit in a base Docker container, without installing external packages) plus a task-specific prompt: a natural-language function description, a GitHub issue, a target function name, or a function signature with body removed. The agent produces a code patch via file-editing actions (str_replace), which is evaluated by checking whether the correct file was modified with the expected content (docstring, comment, or function body). The full dataset contains 4,470 trajectories across 762 repositories, built with only 2 Docker images at an average cost of 0.07¢ per instance.

## Method

The paper first decomposes successful agent trajectories into five intermediate components (reasoning, repo-exploration, code execution, implementation, verification) and finds that ~70% of actions fall into reasoning, repo-exploration, and implementation—none of which require executable repository setup. Guided by four design principles (output format must match downstream patch generation, tasks must involve repo-exploration, tasks must require non-trivial reasoning, and setup must be simple), the authors construct four synthetic tasks: Function Localization, Issue Localization, Dependency Search, and Function Generation. Training uses rejection-sampling distillation, where teacher models (Claude-Sonnet-4.5, Claude-Sonnet-3.7, Qwen3-235B) generate trajectories and only successful ones are retained for supervised fine-tuning of Qwen2.5-Coder-7B/32B. Controlled ablations confirm that output format matching, repo-level (not script-level) exploration, and trajectory complexity are the key factors enabling transfer, while repository diversity improves generalization without inflating in-domain scores.

## Results

On Qwen2.5Coder-32B, HYBRID-GYM (trained exclusively on synthetic tasks with no downstream-task data) improves the base model by 25.4% on SWE-Bench Verified (7.0%→32.4%), 7.9% on SWT-Bench Verified (9.01%→16.86%), and 5.1% on Commit-0 Lite (8.34%→13.45%). Notably, HYBRID-GYM matches or exceeds in-domain training (SWE-Play) on SWT-Bench Verified (16.86% vs. 16.17%) and SWE-Bench Verified (32.4% vs. 31.2%) without any issue-solving or test-generation data in training. Combining HYBRID-GYM with SWE-Play yields further gains of +2.4%/+4.9%/+1.6% on the three benchmarks, reaching 33.6%/21.02%/15.52%.

## Baselines & Comparisons

Against SWE-Gym (Pan et al., 2024), the single-task issue-solving baseline, HYBRID-GYM wins decisively on all three benchmarks: 32.4% vs. 20.6% on SWE-Bench Verified, 16.86% vs. 2.77% on SWT-Bench Verified, and 13.45% vs. 9.58% on Commit-0 Lite, confirming that issue-solving-only training does not transfer to test generation or library construction. Against R2E-Gym (Jain et al., 2025b) and SWE-Smith (Yang et al., 2025c), both issue-solving datasets, HYBRID-GYM trails on SWE-Bench Verified (32.4% vs. 34.4% and 40.2%) but substantially outperforms on SWT-Bench Verified (16.86% vs. 4.39% and 10.62%) and Commit-0 Lite (13.45% vs. 11.56% and 12.38%), demonstrating superior cross-task generalization. Against SWE-Play (Zhu et al., 2025), the closest in-domain multi-task competitor, HYBRID-GYM achieves comparable or better results without any in-domain data: 32.4% vs. 31.2% on SWE-Bench Verified, 16.86% vs. 16.17% on SWT-Bench Verified, and 13.45% vs. 13.95% on Commit-0 Lite (a narrow loss). Against LiveCodeBench (Jain et al., 2024a), used as a script-level agentic task in ablation experiments, HYBRID-GYM's repo-level tasks clearly outperform, as LCB fails to transfer to SWE-Bench issue-solving despite being wrapped in a dummy repository. The paper further shows that mixing HYBRID-GYM with SWE-Play yields additive improvements over either alone, indicating the two data sources teach complementary skills.

## Relation to Prior Work

This paper extends the line of work on rejection-sampling fine-tuning for coding agents (SWE-Gym, R2E-Gym, SWE-Smith, SWE-Play) by introducing a principled framework for designing synthetic training tasks that transfer across diverse coding agent tasks without requiring executable repository setup. It builds directly on SWE-Gym's raw dataset and training recipe, and adapts RepoST's sandbox testing methodology for the function generation task. The key departure from concurrent work like SWE-Play is that HYBRID-GYM tasks avoid the costly and fragile step of building fully executable environments, instead targeting the ~70% of agent actions (reasoning, repo-exploration, implementation) that do not require running repository code.

## Why It Matters / Open Questions

The finding that scalable, low-cost synthetic tasks (0.07¢/instance, 2 Docker images) can match or exceed in-domain training on three distinct benchmarks challenges the prevailing assumption that coding agent training requires task-specific data with full environment setup. The complementary gains when combining HYBRID-GYM with in-domain data (e.g., +4.9% on SWT-Bench over SWE-Play) suggest a practical recipe for multi-task agent training. Open questions include whether the design principles generalize beyond Python and the Qwen2.5-Coder family, whether code-execution tasks can be added without losing the scalability advantage, and what trajectory-level characteristics (beyond the o3-mini reasoning/action separation issue) determine distillation effectiveness.
