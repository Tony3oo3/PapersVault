## Problem

While coding agents are increasingly deployed for software engineering, no standardized framework or benchmark exists for measuring their ability to optimize other agents' harnesses as arbitrary programs. Agent harness optimization is distinct from conventional software engineering because it interleaves deterministic code with stochastic LLM completions, requiring structured capture of both intermediate execution traces and downstream outcomes, and the community lacks a systematic understanding of how well coding agents perform on this task.

## Input / Output

The method takes a target agent implemented as a Python package (prompts, tools, orchestration logic), a task dataset with fixed train/val/test splits, a coding agent (optimizer) with a chosen LLM, and an integer evaluation budget B counting ExperimentRunner invocations. It produces an optimized target agent as a Git commit, per-sample evaluation scores and structured execution traces, and a full versioned commit history. The search space is restricted: the optimizer cannot change model checkpoints, access held-out test data, or modify evaluation infrastructure, and all file writes are auto-committed to an immutable trajectory.

## Method

VERO is an outer harness providing five core abstractions—Git Worktree (auto-commit versioning), Dataset (split management with access control), Filesystem (pattern-based write restrictions), Experiment Database (structured trace storage), and Evaluator (budget-gated evaluation via a gated ExperimentRunner tool)—that together enforce versioning, budget constraints, permission control, reproducible execution, and standardized observation interfaces. The coding agent operates in a tool loop: it inspects dataset samples and prior traces, hypothesizes and implements code modifications (triggering auto-commits), invokes the gated evaluator to run the target agent on training samples, and iterates until budget exhaustion. VERO is coding-agent-agnostic: it exposes functionality through explicit tools and transparent hooks, so any coding agent that consumes these interfaces can be evaluated under identical conditions. VERO-BENCH standardizes five target tasks (GAIA, GPQA, MATH, TAU-Bench Retail, SimpleQA) with reference evaluation procedures, enabling systematic comparison of optimizer configurations across tasks and models.

## Results

Across five benchmark tasks (GAIA, GPQA, MATH, TAU-Bench Retail, SimpleQA), the best configuration—VERO-AGENT Default with Claude Sonnet 4.5—achieves an average best score of 0.61 (max 0.65), a 11% lift over the 0.50 baseline. Gains are concentrated in tool-use tasks: GAIA improves from 0.07 to 0.26, TAU-Bench Retail from 0.38 to 0.55, and SimpleQA from 0.61 to 0.73, while reasoning-heavy tasks (GPQA: 0.60→0.64; MATH: 0.87→0.86) show negligible improvement. Adding VERO tools to Claude Code increases average performance by 2% over the Pure variant, and the full VERO harness yields 8% average / 6% best-score gains over no-harness optimization.

## Baselines & Comparisons

The primary external baseline is GEPA (Agrawal et al., 2026), a reflective prompt-evolution method that mutates the same restricted component set as VERO-AGENT's Resources Only variant. VERO-AGENT Default (0.61 avg) outperforms GEPA (0.54 avg) by 7 percentage points, with the gap driven almost entirely by tool-use tasks: GAIA (0.26 vs. 0.21), TAU-Bench Retail (0.55 vs. 0.38), and SimpleQA (0.73 vs. 0.66). On reasoning tasks (GPQA, MATH), GEPA and VERO-AGENT Default are essentially tied, confirming that the advantage comes from broader harness modifications (tools, workflow) rather than prompt-level changes alone. Internally, VERO-AGENT Default also beats the Resources Only variant (0.54) by the same 7-point margin, reinforcing that structural code changes beyond prompts are the source of the gain. Claude Code with VERO tools (0.55) modestly outperforms Claude Code Pure (0.53), showing that the VERO harness infrastructure (versioning, budget enforcement, structured traces) provides a small but consistent benefit even when the underlying coding agent is the same.

## Relation to Prior Work

This paper departs from prompt-only optimization frameworks (DSPy, TextGrad) by treating the entire agent harness—prompts, tools, and orchestration logic—as the optimization target, and from prior agent-optimization work (ADAS, AFlow, GPTSwarm) by casting the problem as an open-ended coding task performed by a coding agent operating in a tool loop. The key conceptual departure is the introduction of controlled infrastructure (Git versioning, budget-enforced evaluation, permission-gated data access) as a first-class requirement, motivated by the observation that unrestricted optimization leads to evaluation contamination and irreproducible states (demonstrated in Appendix A.5). Concurrent work Meta-Harness converges on similar design choices (versioned histories, budget-bounded evaluation) but operates over unrestricted filesystem traces rather than providing guardrailed abstractions.

## Why It Matters / Open Questions

As LLM agents become the primary deployment mechanism for foundation models, automating their optimization is increasingly urgent, yet the community lacked a standardized way to measure whether coding agents can actually improve other agents. VERO-BENCH fills this gap, and its findings—optimizers overwhelmingly default to prompt edits (>50% of phases), reasoning-task gains are near-zero regardless of budget, and instruction templates interact counterintuitively with agent sophistication—provide the first systematic map of where agent-driven optimization helps and where it stalls. Open questions include how to push optimizers toward diverse structural changes, whether the reasoning-task ceiling is truly model-bound or an artifact of the single target model (GPT-4.1 mini), and how to ensure cross-model generalization of optimized harnesses.
