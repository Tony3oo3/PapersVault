## Problem

LLM-based multi-agent simulations face severe GPU memory pressure as each agent maintains private states (LoRA adapters, prefix caches, action histories) that collectively exceed device capacity. Existing serving systems like SGLang and vLLM are application-agnostic, using reactive LRU-based memory management that causes frequent unnecessary CPU-GPU transfers and premature eviction of agents that will soon need inference again. The paper identifies that agent activation is inherently sparse and invocation order is estimable, yet no system exploits these properties for memory management.

## Input / Output

The system consumes per-agent LLM inference requests alongside invocation distance estimates supplied by the simulation frontend through a unified interface. Distances are relative (not absolute timestamps) and take different forms per workload: remaining action duration for independent simulations, min(action_duration, physical_distance/velocity) for interaction-involved simulations, and hop count from a propagation source for predefined activation paths. The output is standard LLM-generated tokens plus a managed GPU memory state where agent-specific memory objects (LoRA adapters, prefix cache nodes) are asynchronously prefetched or evicted based on distance comparisons.

## Method

ScaleSim introduces invocation distance as a unified abstraction that captures the relative urgency of each agent's next LLM call, enabling the backend to make proactive rather than reactive memory decisions. Two core mechanisms exploit this: (1) distance-guided proactive prefetch, which asynchronously loads an offloaded agent's memory to GPU when its distance falls below a threshold and is smaller than that of any inactive GPU-resident agent, overlapping the transfer with the agent's ongoing action simulation; and (2) future reuse-aware eviction, which evicts agents with the largest invocation distances rather than using LRU, avoiding redundant reloads for agents about to re-activate. A centralized load task scheduler with preemption support coordinates all CPU-to-GPU transfers, allowing urgent requests to interrupt lower-priority loads. The system is built on SGLang with a modular agent-specific memory abstraction class that exposes HandleReq, Evict, DispatchLoadTasks, and Load interfaces, enabling heterogeneous memory types to be registered and jointly managed under the same distance-aware policy.

## Results

ScaleSim achieves up to 1.74× end-to-end speedup over vanilla SGLang across three simulation benchmarks: 1.73× on AgentSociety (independent simulation), 1.31× on Generative Agents (interaction-involved simulation), and 1.74× on information diffusion (predefined activation paths). Under high agent concurrency (500–1000 agents), ScaleSim reduces average Time-to-First-Token (TTFT) by 48%–68% compared to SGLang with HiCache. The speedup is robust to prediction errors (still positive at high error rates) and scales consistently across model sizes (Qwen2.5-7B and 32B) and GPU counts (1 to 8 H100s).

## Baselines & Comparisons

ScaleSim is compared against two SGLang configurations: vanilla SGLang (LRU eviction, no CPU fallback for evicted prefix nodes) and SGLang with HiCache (asynchronous CPU backup of prefix nodes, LRU eviction). ScaleSim outperforms both baselines across all three primary benchmarks and all agent counts tested (25 to 1,000 agents). The speedup over vanilla SGLang is largest in AgentSociety (up to 1.73×) and information diffusion (up to 1.74×), where invocation distance estimates are most accurate, and smallest in Generative Agents (up to 1.31×), where interaction events introduce more uncertainty. Against HiCache specifically, ScaleSim's advantage comes from proactive prefetching that overlaps memory loading with agent action simulation, eliminating reactive CPU-to-GPU stalls on the critical path. The execution time breakdown (Figure 15) confirms that ScaleSim's gains come almost entirely from reducing the 'Load' component (host-to-GPU transfers), while Prefill and Decode times remain unchanged. ScaleSim also maintains its advantage under moderate sparsity levels and across diverse invocation distance patterns (state-triggered, dynamic social groups, stochastic events), whereas the baselines degrade more sharply as agent count grows.

## Relation to Prior Work

ScaleSim builds directly on SGLang's serving runtime, extending it with simulation-aware memory management that existing application-agnostic systems (vLLM, SGLang, TensorRT-LLM) lack. It departs from workflow-driven serving systems (Parrot, KVFlow, PIE) that assume pre-defined execution structures, and from InferCept, which relies on profiled absolute execution times for eviction decisions. The key conceptual departure is the invocation distance abstraction, which unifies three distinct simulation categories (independent, interaction-involved, predefined-path) under a single relative-urgency metric, enabling proactive prefetching and distance-aware eviction without requiring exact time predictions.

## Why It Matters / Open Questions

As multi-agent LLM simulations scale toward thousands of agents, GPU memory pressure from per-agent LoRA adapters and prefix caches becomes the dominant bottleneck; ScaleSim's 1.74× speedup and 48–68% TTFT reduction demonstrate that simulation-semantics-aware memory management is a practical and necessary layer. The invocation distance abstraction is generalizable and lightweight (negligible CPU overhead), making it adoptable by other serving frameworks. Open questions include how the approach performs when agent behavior is truly unpredictable (beyond the tested Poisson-event and state-triggered perturbations), whether it extends to non-LLM agent components, and how it interacts with disaggregated prefill/decode architectures where memory residency decisions become more complex.
