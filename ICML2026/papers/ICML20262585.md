## Problem

Existing Agent Development Kits (ADKs) such as Google ADK, OpenHands, OpenAI ADK, and LangChain require humans to manually design agent topology, toolsets, and memory structures, limiting scalability and generalizability. No prior ADK supports AI-created agent topologies, dynamic tool synthesis with heterogeneous execution environments, or AI-driven graph-based memory management. OpenSage addresses this by being the first ADK to enable an AI-centered paradigm where LLMs autonomously construct and manage all three core architectural components at runtime.

## Input / Output

The system takes a task description and a backbone LLM model as input, operating within a minimal scaffold that exposes meta-tools for agent creation, tool synthesis, and memory operations. Outputs include the resolved task solution alongside dynamically generated artifacts: a self-organized agent topology (vertical or horizontal), task-specific tools written in Python, C/C++, or Bash, and persistent knowledge stored in Neo4j graph databases. The agent topology is not pre-defined but emerges during execution as the parent agent decides when to spawn sub-agents with tailored instructions and restricted tool scopes.

## Method

OpenSage comprises three tightly integrated components. First, self-generating agent topology uses a two-step creation procedure where a parent agent emits a configuration (model, system prompt, tools, initial memory) that is parsed into a Python object in a unified sub-agent pool, supporting both vertical decomposition (sequential sub-tasks with isolated contexts) and horizontal ensembles (parallel agents on the same task with result merging). Second, dynamic tool synthesis provides meta-tools that let agents write and register new tools into a file-system-based hierarchical structure, with each tool set running in an isolated Docker container to handle heterogeneous dependencies, plus asynchronous execution for long-running tools and a domain-specific toolkit (Joern, CodeQL, AFL++, GDB) for software engineering. Third, hierarchical memory combines a short-term Neo4j graph tracking the agent execution tree (AgentRun and Event nodes with summarization) and a long-term Neo4j graph of typed entity nodes and relationship edges, both managed by a dedicated memory agent that translates natural-language queries into graph operations for search, update, and store.

## Results

SageAgent (built with OpenSage) achieves the highest resolved rate across all four primary benchmarks: 60.2% on CyberGym, 78.4% on Terminal-Bench 2.0, 59.0% on SWE-Bench Pro, and 46.8% on DevOps-Gym. On DevOps-Gym, SageAgent is the only agent to solve any end-to-end pipeline tasks (17.7% resolved), while all baselines score 0%. On SWE-Bench Pro, SageAgent also achieves the lowest average cost ($0.31) and shortest time (6m27s) per task compared to SWE-agent ($1.04, 15m48s).

## Baselines & Comparisons

On CyberGym, SageAgent (60.2%) outperforms Anthropic Agent with Claude Opus 4.5 (50.6%) by ~10 points and OpenHands with GPT-5 high (39.4%) by over 20 points, despite OpenHands using a higher reasoning-effort setting. On Terminal-Bench 2.0, SageAgent (78.4%) edges out Droid (77.3%) and Simple Codex (75.1%) using the same GPT-5.3-Codex backbone, while substantially surpassing Claude Code (58.0%) and OpenHands (51.9%). On SWE-Bench Pro, SageAgent (59.0%) beats SWE-agent (40.2%) by ~19 points and Agentless (9.4%) by ~50 points, all with the same Gemini 3 Flash backbone. On DevOps-Gym, SageAgent (46.8%) leads Claude Code (27.5%) and OpenHands (21.0%) by 19 and 26 points respectively, and is the only system to resolve any end-to-end pipeline tasks. For memory evaluation on LOCOMO, OpenSage's memory agent matches Mem0^g on Open-Domain (76.4 vs. 75.7) and Temporal (57.8 vs. 58.1) questions while outperforming non-graph baselines like OpenAI (62.3, 21.7) and A-Mem (62.2, 23.4).

## Relation to Prior Work

This paper departs from the dominant human-centered paradigm in Agent Development Kits (Google ADK, OpenHands SDK, OpenAI ADK, Claude ADK, LangChain), where domain experts manually design agent topology, toolsets, and memory schemas. It draws an explicit analogy to the ML shift from handcrafted features to learned representations, repurposing existing infrastructure (Neo4j graph databases, Docker container isolation, multi-agent ensemble patterns, Mem0-style graph memory) into a unified scaffold where the LLM itself decides topology, writes tools, and manages memory. No prior ADK supports all three AI-created components simultaneously; the closest partial overlaps are Claude's (closed-source) AI-written tools and Mem0's graph-based memory, neither of which provides AI-driven management or the hierarchical short-term/long-term structure proposed here.

## Why It Matters / Open Questions

OpenSage provides a concrete, open-source scaffold for the AI-centered agent-construction paradigm, and its strong results across four heterogeneous benchmarks (CyberGym, Terminal-Bench 2.0, DevOps-Gym, SWE-Bench Pro) suggest that self-organized topologies and dynamic tool synthesis yield substantial gains over fixed, expert-designed workflows. However, the authors candidly report that current SOTA models still hallucinate tools, create mismatched sub-agents, and fail to consistently leverage the advanced features, indicating a capability gap that limits immediate deployment. Key open questions include whether post-training (the authors plan rollout interfaces for AReaL/verl) can close this gap, whether the approach generalizes beyond software-engineering and security domains, and how to scale the sub-agent pool and container orchestration for production workloads.
