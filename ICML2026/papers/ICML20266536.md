## Problem

Current LLM deployment interfaces expose only text-based prompts for customization, which the paper argues are ill-suited as a scalable control interface: text prompts saturate early under iterative optimization, grow brittle and long in practice, and cannot absorb increasing supervision effectively. The paper identifies this as an interface abstraction problem rather than an optimization problem, arguing that model providers should additionally expose vector prompt inputs to enable systematic, inference-only customization.
![Teaser figure](../imgs/ICML20266536/cropped_page1_idx0.webp)

## Input / Output

The proposed interface accepts fixed-length continuous vector prompts (e.g., 32 learned tokens) injected at the input-encoding stage, prepended to the task input alongside any text prompt. These vectors are opaque control signals rather than semantically grounded tokens, and they are applied entirely at inference time without requiring gradient access, weight updates, or internal activation inspection. The output is standard generated text from the base model, with the vector prompt modulating behavior through its position in continuous representation space.

## Method

This position paper contributes a diagnostic empirical analysis rather than a new optimization algorithm. It fixes LLaMA3-8B Instruct and varies only the amount of supervision (32–8192 samples) on SST-5 and Alpaca, showing that gradient-tuned vector prompts continue to improve with more data while TextGrad-optimized text prompts plateau early. Attention pattern analysis at Layers 12 and 20 reveals that vector prompts induce dense, globally addressable attention from task tokens across the prompt-task boundary, functioning as persistent control anchors, whereas text prompts remain sparse and inherit default attention-sink dynamics. The paper further argues via information-theoretic reasoning that under a standard black-box threat model, exposing vector inputs does not expand the observable output channel relative to text prompting, and calls for providers to expose constrained vector prompt APIs decoupled from model parameters.

## Results

On SST-5 (LLaMA3-8B Instruct), vector prompts continue to improve with increasing supervision across the full range of training data, while optimized text prompts (TextGrad) saturate early and show diminishing returns. On Alpaca instruction-following (token-level F1), vector prompts improve steadily from 0.340 (32 samples) to 0.401 (8192 samples), whereas text prompts remain unstable, fluctuating between 0.310 and 0.348. Attention analysis at Layers 12 and 20 reveals that vector prompts induce dense, globally distributed attention from task tokens across the prompt–task boundary, while text prompts exhibit sparse, localized attention that does not systematically increase with depth.

## Baselines & Comparisons

The paper's primary comparison is between vector prompt interfaces (optimized via gradient-based prompt tuning) and text prompt interfaces (optimized via TextGrad), using LLaMA3-8B Instruct as a fixed backbone. On Alpaca, vector prompts achieve 0.401 token-level F1 at 8192 training samples, outperforming text prompts (0.344) by 5.7 points, and show consistent monotonic improvement across all training sizes while text prompts are unstable (dropping to 0.310 at 256 samples before recovering). On SST-5, the qualitative scaling curve confirms the same pattern: vector prompts continue to absorb supervision beyond the point where text prompts plateau. The paper frames these results as diagnostic evidence of interface-level capacity rather than a head-to-head algorithmic benchmark, noting that gradient-based optimization serves as an upper bound on what the vector interface can achieve under black-box access.

## Relation to Prior Work

This paper builds on prompt tuning (Liu et al., 2022) and prefix tuning (Li & Liang, 2021) as the underlying mechanism for vector prompts, but deliberately reframes them from optimization techniques to a system-level 'interface abstraction' that decouples customization from model weights. It positions itself against text prompt optimization methods (TextGrad, RLPrompt) as the primary comparison, and distinguishes its contribution from parameter-level adaptation (LoRA, DPO) and from representation engineering / activation steering, which operate at internal layers rather than the input interface. The conceptual departure is treating prompt design as an interface design problem rather than a prompt engineering or algorithmic optimization problem, a framing the authors argue has been obscured by conflating interface form with optimization procedure.

## Why It Matters / Open Questions

The paper makes a practical case that inference-only, scalable customization is an increasingly binding constraint as models grow and deployment contexts diversify, and that current text-only interfaces hit a structural ceiling (early saturation, prompt explosion, sparse attention utilization) that no amount of better prompt engineering can overcome. However, the empirical evidence is limited to a single backbone (LLaMA3-8B Instruct) and two tasks (SST-5, Alpaca), and the vector prompt results rely on gradient-based optimization as a 'diagnostic upper bound,' leaving the critical open question of how to efficiently optimize vector prompts under true black-box, inference-only access. Additional open questions include security and monitoring implications of non-textual control inputs, versioning and management overhead for many task-specific vectors, and whether the observed scaling and attention-pattern differences generalize across architectures and task families.
