## Problem

Most LLM agent memory systems rely on offline, query-agnostic preprocessing that spends computation regardless of what a particular query needs and may irreversibly discard query-critical information. While runtime (on-demand) memory extraction is a natural alternative, prior work offers no explicit, controllable mechanism for trading task performance against extraction cost at query time, leaving practitioners without a principled way to manage the quality-cost frontier under varying budget constraints.

## Input / Output

Given a user query and a set of top-K retrieved raw chunks (K=5) from a fixed-length chunked history (256 tokens for LoCoMo/LongMemEval, 1024 for HotpotQA), BudgetMem produces a compact extracted memory and a final answer. The history is kept intact with no offline preprocessing; all memory computation is deferred to query time. Internally, the system also emits per-module budget-tier routing decisions (LOW/MID/HIGH) that determine how much compute each pipeline stage consumes, and the end-to-end cost is measured as the sum of token-weighted API prices across all module calls.

## Method

BudgetMem implements memory extraction as a fixed modular pipeline (filter → parallel entity/temporal/topic extraction → summarization) where each module exposes a unified three-tier budget interface (LOW/MID/HIGH). Three orthogonal tiering strategies are studied: implementation tiering (heuristic → BERT-based specialist → LLM), reasoning tiering (direct → chain-of-thought → multi-step reflection), and capacity tiering (small → medium → large backbone model). A shared lightweight router, whose 512-dimensional state is built from frozen all-mpnet-base-v2 embeddings of the query, current module input, and a module descriptor, selects a tier at each module invocation. The router is trained with PPO under a cost-aware reward r = r_task + λ·α·r_cost, where r_cost is derived from sliding-window-normalized extraction cost and α is a variance-based alignment factor that prevents the higher-variance reward term from dominating policy updates, yielding smooth and controllable performance-cost frontiers across budget regimes.

## Results

Under the performance-first setting (λ=0), BudgetMem-CAP achieves the best average Judge score of 59.99% and F1 of 45.72% across LoCoMo, LongMemEval, and HotpotQA with LLaMA-3.3-70B, at a cost of $1.38 — substantially outperforming the strongest baseline LightMem (49.21% Judge, $5.63 cost). With Qwen3-Next-80B-A3B, BudgetMem-REA reaches 61.06% average Judge at just $0.51 cost, and BudgetMem-CAP achieves 60.42% Judge at $0.33. On LongMemEval specifically, BudgetMem-CAP (LLaMA) scores 60.50% Judge versus LightMem's 48.51%, a 12-point gap, while on HotpotQA (Qwen) BudgetMem-CAP reaches 72.08% Judge at $0.22 cost.

## Baselines & Comparisons

BudgetMem (all three tiering variants) outperforms all seven baselines on both F1 and Judge across every dataset and backbone. The strongest baseline, LightMem, is surpassed by BudgetMem-CAP by approximately 10.8 points in average Judge (59.99 vs. 49.21) with LLaMA and by 11.9 points (60.42 vs. 48.59) with Qwen, while incurring roughly 4× lower cost ($1.38 vs. $5.63; $0.33 vs. $4.21). A-MEM, despite achieving competitive F1 on HotpotQA (43.25 with LLaMA), incurs the highest cost among baselines ($32.07 average) and still trails BudgetMem-CAP by 10.4 F1 points on that dataset. MemoryOS is competitive on LoCoMo (30.62 F1) but collapses on LongMemEval (12.97 F1), whereas BudgetMem maintains strong performance across all three benchmarks. On the Qwen backbone, BudgetMem-REA achieves the highest single-dataset Judge score (70.83 on HotpotQA) at the lowest cost among all methods ($0.17), demonstrating that the learned router generalizes across backbones without retraining.

## Relation to Prior Work

This paper sits at the intersection of two largely separate research threads: memory-augmented LLM agents (MemoryBank, MemGPT, A-MEM, MemoryOS, LightMem), which predominantly perform offline, query-agnostic memory construction, and inference-time cost-control mechanisms in LLM systems (routing, early-exit, reasoning-level and capacity-level knobs), which target answer generation rather than memory extraction. BudgetMem departs from both by treating runtime memory extraction as a modular pipeline where each module exposes a unified LOW/MID/HIGH budget-tier interface, and by learning a shared RL-based router (PPO) to make query-aware, module-wise tier selections under a cost-aware reward. The routing formulation draws on LLM-routing work (RouterDC, GraphRouter, Router-R1) but repurposes it for a novel decision space: selecting compute tiers across heterogeneous memory modules rather than choosing among model backends for a single generation call.

## Why It Matters / Open Questions

As LLM agents are deployed in cost-sensitive, latency-constrained settings, the ability to explicitly dial memory-extraction quality against compute spend is practically important, and BudgetMem provides a concrete, modular framework for doing so. The unified comparison of three orthogonal tiering axes (implementation, reasoning, capacity) gives practitioners actionable guidance: implementation and capacity tiering span a broad cost range and are better for widening budget coverage, while reasoning tiering acts as a fine-grained quality knob within a narrow cost band. Limitations include the fixed five-module pipeline, only three discrete tiers, evaluation restricted to dialogue-centric and long-context QA benchmarks, and a router trained on one backbone and transferred to another without retraining. Open questions include whether the approach generalizes to more complex or open-ended memory pipelines, whether continuous (rather than discrete) budget allocation would yield smoother frontiers, and how the router interacts with other efficiency techniques such as KV-cache compression or speculative decoding.
