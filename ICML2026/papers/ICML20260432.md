## Problem

In emerging 'vibe coding' workflows, software design is communicated through UML diagrams and flowcharts before implementation, yet existing multimodal code models are trained and evaluated almost entirely on textual inputs and narrow domains (UI/HTML, charts). There is no large-scale multilingual training dataset or standardized benchmark that treats diagrams as the primary specification for code generation across multiple programming languages, leaving a critical gap for visual-first, multilingual software development.
![Teaser figure](../imgs/ICML20260432/cropped_page1_idx0.webp)

## Input / Output

The model receives a rendered diagram image (UML class diagram or flowchart, produced via PlantUML or Mermaid; in M²EVAL, 30 unique images at 159–1978 px height × 338–2081 px width) together with a short textual instruction (avg. 89 tokens) that deliberately omits information encoded only in the diagram. The output is a complete, executable program in one of 10 target languages (C#, C++, Java, JavaScript, Kotlin, PHP, Python, Ruby, Scala, Swift), evaluated by running it against an average of 9 hidden test cases per problem using a Pass@1 execution-based metric.

## Method

The core contribution is a two-stage instruction-tuning pipeline on a 13.1M-sample multilingual dataset (M²C-INSTRUCT) spanning 50+ languages. Stage 1 (12.9M samples) converts GitHub code into Q&A pairs via Qwen2.5-Coder, then splits them 9:1 into Cross-Modal problems (code rendered as syntax-highlighted images via Pygments to train OCR/visual code reading) and Diagram problems (a two-step synthesis where Qwen2.5-Coder first generates a Mermaid diagram from the solution, then reformulates the prompt so that key solving information resides exclusively in the diagram). Stage 2 (168K samples) uses Evol-CodeAlpaca and OSS-Instruct as seeds to produce higher-quality, diagram-centric problems. M²-CODER is initialized from Qwen2-VL-7B-base and trained in two phases: Stage 1 performs full-parameter fine-tuning (vision tower, projector, and LLM all unfrozen) at 2048-token context for 1 epoch, while Stage 2 freezes the vision encoder and projector and fine-tunes only the LLM at 6000-token context for 2 epochs, both with AdamW (LR 5e-5, batch 1024, cosine schedule, bf16, DeepSpeed ZeRO-2). The resulting 7B model achieves 25.3% average Pass@1 on M²EVAL, surpassing 72B open-weight LMMs and approaching proprietary 70B+ models.

## Results

On M²EVAL (300 problems across 10 programming languages), the best proprietary model GPT-4o achieves 49.7% average Pass@1, while the best open-weight model Llama-4-Maverick (400B) reaches 40.7%. The proposed M²-CODER (7B) achieves 25.3% average Pass@1, outperforming all other open-weight models of similar or larger size, including Qwen2.5-VL-Instruct-72B (24.7%), InternVL2-Llama3-76B (19.3%), and Llama3.2-vision-90B (2.7%). Notably, text-only LLMs (DeepSeek-V3-671B, Qwen2.5-Coder-32B) score 0.0% without diagrams, confirming that visual information is essential for solving M²EVAL problems.

## Baselines & Comparisons

M²-CODER (7B, 25.3% avg) outperforms all open-weight LMMs of comparable or larger size: it beats Qwen2.5-VL-Instruct-72B (24.7%), InternVL2-Llama3-76B (19.3%), Qwen2-VL-Instruct-72B (28.7% — actually slightly higher), and Llama3.2-vision-90B (2.7%) by wide margins. However, it trails the strongest proprietary models substantially: GPT-4o (49.7%), Gemini-2.5-Flash (48.7%), and Doubao1.5-thinking (44.3%) all exceed M²-CODER by 19–24 percentage points. Among open-weight models, Llama-4-Maverick (400B, 40.7%) remains the strongest, outperforming M²-CODER by 15.4 points. The ablation confirms that the two-stage training is critical: Stage-1 SFT alone on Qwen2-VL-Base yields only 10.0%, while the full two-stage pipeline reaches 25.3%. Text-only LLMs (DeepSeek-V3-671B, Qwen2.5-Coder-32B) score 0.0% without diagrams, validating that M²EVAL problems are genuinely unsolvable from text alone.

## Relation to Prior Work

This paper extends the multimodal code generation line of work (Design2Code, Web2Code for UI/HTML; MatPlotBench, ChartCoder for chart-to-code) by repositioning diagrams—specifically UML class diagrams and flowcharts—as the primary specification rather than an auxiliary hint, and by scaling to 50+ programming languages. For Stage-2 data construction, it builds directly on Magicoder/OSS-Instruct and Evol-CodeAlpaca, while the base model (Qwen2-VL-7B) and training infrastructure (LlamaFactory, DeepSpeed ZeRO-2) follow standard open-source VLM fine-tuning practice. The key conceptual departure from prior work is the 'visual-first' framing: the prompt alone is deliberately insufficient, and the diagram carries essential information that the model must extract to produce correct code.

## Why It Matters / Open Questions

The paper provides a complete infrastructure stack (13.1M-sample training set, 300-problem multilingual benchmark, and a reference model) that is likely to become a standard reference for visual-assisted programming research. A notable limitation is that even GPT-4o plateaus around 50% Pass@1, and Design Patterns tasks remain particularly difficult across all models, suggesting that deep architectural reasoning from diagrams is still far from solved. Open questions include whether the two-stage training recipe generalizes to other base models, whether the synthetic diagram generation pipeline (Mermaid rendering) introduces systematic biases, and how performance scales as diagram complexity increases beyond the current 30-concept benchmark.
