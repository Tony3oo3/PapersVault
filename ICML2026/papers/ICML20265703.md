## Problem

Post-training (SFT + RL) is the dominant paradigm for building code agents, but it is constrained by limited data diversity, low environment-construction yield rates, and the base model's intrinsic capacity ceiling. Agentic mid-training remains underexplored openly, and the one prior open recipe (Kimi-Dev) factorizes PRs into isolated atomic capabilities (localization, editing) without preserving the procedural context an agent actually encounters at deployment, creating a distribution mismatch between training data and interactive agent behavior.
![Teaser figure](../imgs/ICML20265703/cropped_page1_idx0.webp)

## Input / Output

At inference, the agent receives a repository state, a natural-language issue description, and an evaluation oracle (test suite), then iteratively emits tool-call actions (file search, code read, edit, test run) and consumes environment observations until it produces a code patch. For training, contextually-native trajectories bundle the full development workflow—issue text, relevant file contents at the base commit, LLM-generated PR summaries, and concatenated commit diffs—into a single structured sample (XML-like tags with patch diffs for the general subset; Markdown with search-and-replace blocks for the Python subset). Environmentally-native trajectories record raw action-observation sequences from live Docker rollouts, including genuine test outputs, runtime errors, and scaffold system messages, with no quality filtering applied to preserve quantity.

## Method

The paper introduces agent-native data as mid-training supervision that preserves the complete action-observation information flow of real software engineering, formalized through two complementary trajectory types. Contextually-native trajectories (68.6B tokens) are reconstructed from ~10M GitHub PRs by bundling issue descriptions, relevant file contents, and edits into a single sample that mirrors the localize→read→edit workflow, with Qwen3-235B generating PR summaries and refined commit messages as interleaved reasoning. Environmentally-native trajectories (3.1B tokens) are produced by running GLM-4.6 inside SWE-Agent within per-task Docker environments built via the SWE-Rebench pipeline, capturing authentic test feedback and iterative revision loops without any filtering. The training recipe performs mid-training on the combined 73.1B-token corpus (no loss mask, batch 1024, LR 8e-5, cosine decay) followed by SFT on passing environmentally-native trajectories (loss mask on user/tool tokens, batch 128, LR 1e-5), starting from non-coder Qwen2.5-32B/72B base models. This achieves 56.1% and 58.5% on SWE-Bench Verified—state-of-the-art among open agentic recipes at those scales—while using less than half the mid-training tokens of the prior Kimi-Dev recipe, with ablations confirming that contextually-native data provides knowledge diversity and environmentally-native data teaches execution dynamics, and that the two are synergistic rather than redundant.

## Results

On SWE-Bench Verified (SWE-V), daVinci-Dev-32B achieves 56.1% Pass@1 and daVinci-Dev-72B achieves 58.5% Pass@1, both using the SWE-Agent scaffold (temperature 0, 128k context, 100 steps). These represent the highest resolution rates among open training recipes using agentic scaffolds at their respective model sizes, despite starting from non-coder Qwen2.5-Base models. The recipe uses only 73.1B mid-training tokens (vs. ~150B for Kimi-Dev), and also yields substantial gains on general code benchmarks (HumanEval +23.3 pp at 32B, +12.5 pp at 72B) and scientific reasoning benchmarks (GPQA +0.7 pp at 32B, +1.6 pp at 72B).

## Baselines & Comparisons

At the 32B scale, daVinci-Dev-32B (56.1%) outperforms all nine compared baselines on SWE-V, with the closest competitor being FrogBoss (54.6%, +1.5 pp) and SWE-Mirror-LM (52.2%, +3.9 pp); it also surpasses SWE-Lego-Qwen3-32B (52.6%) and DeepSWE-Preview (42.2%) by 3.5 and 13.9 pp respectively. Notably, daVinci-Dev-32B starts from the non-coder Qwen2.5-32B-Base, whereas several competitors use Qwen2.5-Coder-32B or Qwen3-32B as their base. At the 72B scale, daVinci-Dev-72B (58.5%) surpasses Kimi-Dev (48.6%) by 9.9 pp while using only SFT (no RL) and fewer than half the mid-training tokens (73.1B vs. ~150B). Under the same weak-SFT post-training setting, daVinci-Dev-72B (46.4%) matches Kimi-Dev's estimated ~46.0% using only contextually-native MT data, and under strong SFT it reaches 58.2% vs. Kimi-Dev's 56.2% (with RL). The paper also reports exploratory results on SWE-Bench Pro (16.4% at 72B) and SWE-Bench Multilingual (23.3% at 72B), though these are flagged as potentially contaminated by the mid-training corpus.

## Relation to Prior Work

This paper departs from the dominant post-training paradigm (SFT + RL) for agentic software engineering by introducing agent-native mid-training as a complementary stage. It builds on SWE-Rebench's automated Docker environment construction pipeline for generating environmentally-native trajectories, and directly contrasts with Kimi-Dev's 'agentless' factorized mid-training approach, which synthesizes isolated atomic capabilities (localization, editing) without preserving the procedural context of a full agentic workflow. The key conceptual shift is from treating mid-training data as a collection of independent skill demonstrations to preserving complete action-observation trajectories that mirror the information flow an agent experiences at deployment.

## Why It Matters / Open Questions

The paper demonstrates that agentic mid-training with agent-native data is both necessary and more token-efficient than prior open recipes, achieving SOTA resolution rates (56.1%/58.5%) with under half the mid-training tokens of Kimi-Dev and without requiring RL. The observed generalization from agentic SWE training to scientific reasoning benchmarks (GPQA, SciBench) suggests that the decision-making patterns learned may transfer beyond code, though this remains underexplored. Open questions include whether the approach scales further (the log-linear curves suggest it has not saturated), whether combining it with RL post-training yields additional gains, and whether the methodology generalizes to other agentic domains beyond software engineering. A notable limitation is the contamination caveat on SWE-Bench Pro and Multilingual, where repository overlap with the training corpus precludes fair comparison.
