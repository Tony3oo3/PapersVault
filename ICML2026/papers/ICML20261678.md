## Problem

Designing effective LLM-based multi-agent systems remains labor-intensive and brittle: existing automatic generation methods either produce executable code that frequently fails at runtime (MAS-GPT, ADAS) or impose rigid architectural templates that limit expressiveness (AutoAgents, EvoAgent). No prior approach jointly optimizes all configuration components—topology, prompts, model assignments, and tools—while accumulating cross-query experience to improve over time.

## Input / Output

EvoMAS takes a natural-language task query and retrieves initial candidates from a pool of seeded MAS configurations (human-designed systems like Peer Review, MetaGPT, ChatDev) plus an experience memory storing compact summaries of prior evolution traces. It outputs a structured, declarative configuration C = (G, {A_i}, V_in, V_out) specifying an acyclic communication graph, per-agent backbone models, prompt templates, and tool sets, which a lightweight runtime interpreter executes to produce the final task solution (answer, code patch, or tool calls). The configuration format is schema-constrained text rather than executable code, which is the key design choice enabling >96% execution reliability.

## Method

EvoMAS formulates MAS generation as evolutionary search over a bounded configuration space, using an LLM meta-model to drive four operators: Select (retrieves diverse parents from the pool by task relevance), Mutate (edits exactly one component type—prompt, model, tools, or topology—conditioned on execution-trace feedback), Crossover (inherits the full communication topology from one parent and recombines agent-level attributes from both), and Consolidate (distills evolution traces into memory entries for cross-query transfer). After each query, the best-scoring configuration is added to the pool and the evolution trace is summarized into experience memory, enabling the system to reuse successful patterns on future tasks. The reward signal combines an LLM-as-judge score over correctness, completeness, and reasoning quality with a cost penalty on token usage and wall-clock latency, and the evolutionary process runs for a fixed number of steps (T=3 optimal) per query before selecting the highest-reward configuration for final execution.

## Results

EvoMAS with automatic LLM selection achieves 58.7% accuracy on BBEH, 48.9% on WorkBench, 52.9% on SWE-Bench-Lite, and 63.8% on SWE-Bench-Verified, outperforming all baselines across all four benchmarks. With Claude-4.5-Sonnet as both generator and backbone, EvoMAS reaches 79.1% on SWE-Bench-Verified, matching the top of the public leaderboard. Execution rates exceed 96% across all benchmarks (98.9% BBEH, 98.5% WorkBench, 96.8% SWE-Lite, 98.4% SWE-Verified), far surpassing code-generation methods like MAS-GPT (71.5% on BBEH, 1.2% on SWE-Lite). On AIME 2024-2025, EvoMAS achieves 56.7% accuracy versus 51.7% for the best predefined MAS (Peer Review).

## Baselines & Comparisons

EvoMAS (LLM-Selection) decisively outperforms the closest evolutionary baseline EvoAgent by +10.5 points on BBEH (58.7% vs. 48.2%), +7.1 on WorkBench (48.9% vs. 41.8%), and +27.7 on SWE-Bench-Verified (63.8% vs. 36.1%), attributed to evolving the full multi-agent system rather than individual agents. Against the strongest predefined MAS (Peer Review), EvoMAS gains +20.3 on BBEH and +28.2 on SWE-Verified, while also surpassing MetaGPT (40.9%) and ChatDev (26.1%) on SWE-Bench-Verified by 22.9 and 37.7 points respectively. Code-generation methods collapse on software engineering: MAS-GPT achieves only 3.1% and AutoAgents 8.7% on SWE-Bench-Verified versus EvoMAS's 63.8%, and ADAS reaches 29.9%, confirming that structured configuration generation is far more robust than direct code synthesis. EvoMAS also beats the Single Agent baseline by +25.5 on BBEH and +30.2 on SWE-Verified, demonstrating that multi-agent coordination provides substantial gains over single-agent approaches. With Claude-4.5-Sonnet, EvoMAS reaches 79.1% on SWE-Bench-Verified, exceeding the prior leaderboard top (78.8%) that used larger models and specialized scaffolding, and outperforming a budget-matched Best-of-N baseline (71.4% at 31M tokens) by 7.7 points.

## Relation to Prior Work

EvoMAS carves new ground by reformulating automatic MAS generation as structured configuration evolution rather than code synthesis (ADAS, MAS-GPT) or individual-agent mutation (EvoAgent). It repurposes genetic algorithm operators (mutation, crossover, selection) but conditions them on LLM-driven execution feedback and introduces a cross-query experience memory that prior evolutionary MAS methods lack. The configuration-space paradigm—where a lightweight runtime interpreter decouples system structure from execution logic—sits between the expressiveness of open-ended code search and the rigidity of fixed architectural templates (AutoAgents, MetaAgent), and jointly evolves all components (topology, prompts, models, tools) rather than optimizing them in separate stages as MASS or AFlow do.

## Why It Matters / Open Questions

By automating MAS design with >96% execution reliability, EvoMAS lowers the barrier to deploying effective multi-agent systems across diverse domains without expert architecture knowledge. The budget-matched comparisons confirm gains are structural (effective coordination patterns) rather than merely compute-driven, offering a principled path for test-time compute scaling that complements model improvements. Key limitations include targeting accuracy over latency (evolution overhead), excluding adversarial agent configurations, and dependence on sequential query processing for cross-query transfer; reducing evolution cost for novel task distributions and extending to adversarial coordination remain open.
