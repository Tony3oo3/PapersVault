## Problem

Self-attention during decoding of long-context LLMs is bottlenecked by repeatedly processing ever-growing KV caches. Existing hashing-based sparse attention methods either use data-independent random projections (LSH) that require extremely long codes (>1000 bits) to compensate for misalignment with model activations, or learned non-linear hashing that demands hours of per-model training. The paper addresses the gap of a training-free yet data-aware hashing scheme that produces compact codes aligned with the intrinsic structure of LLM key vectors.

## Input / Output

The method takes N key vectors K ∈ R^{N×D} from the KV cache and a single query vector q ∈ R^D. It produces a binary hash code matrix H ∈ {-1,1}^{N×64} (each code fits in one int64 word) and a real-valued projection P ∈ R^{64×D}. During retrieval, the query is projected to qP^T ∈ R^{64} and quantized into 64 sign bits plus 7×64 magnitude bits, enabling the hash score to be computed entirely via bitwise XOR, AND, NOT, popcount, and shift operations. An Error-Aware Safeguard additionally retains the top-m tokens with largest per-token reconstruction error ||k - hP||_2 as a guaranteed-recall set.

## Method

BinaryPC solves the reconstruction objective min_{H,P} ||K - HP||_F via an iterative rank-1 binary decomposition inspired by PCA: at each step it samples a random vector v*, computes a binary sign vector u = sign(Rv*^T) as a binary principal component, derives the projection row v = uR/N, and deflates the residual R ← R - u^T v. This asymmetric design encodes keys into compact 64-bit binary codes while keeping the query projection real-valued (then quantized for bitwise scoring), avoiding the need to hash both sides. An Error-Aware Safeguard (EAS) identifies hard-to-hash tokens by their reconstruction error during prefill and unconditionally includes them in the attention set, while an Offline Projection Calibration (OPC) variant pre-computes P from 180 calibration samples spanning literary, mathematical, and code corpora to eliminate online projection cost. Custom CUDA kernels pack each 64-bit key hash into a single int64 and compute all query-key hash scores via popcount-based bit-plane arithmetic, reducing a single attention layer's FlashAttention invocation from 1.814 ms to 163 μs at 512K context length.

## Results

On RULER (8K–128K context), BinaryPC with a 2% token budget achieves 85.57 average accuracy, closely tracking full attention (87.41) and outperforming all sparse-attention baselines (best baseline: Quest at 81.96). On InfiniteBench, BinaryPC (2%) reaches 43.21 average vs. full attention's 43.30, and on LongBench v2 it scores 29.8 vs. 29.4 for full attention. In terms of efficiency, BinaryPC delivers up to 3.56× end-to-end decoding throughput improvement over FlashAttention-2 at long contexts, and 5.04× speedup when FlashAttention-2 falls back to its standard kernel at batch size 16 and 128K context. The method uses compact 64-bit hash codes—over 10× shorter than MagicPIG and 2× shorter than Spotlight—while maintaining near-full-attention accuracy.

## Baselines & Comparisons

BinaryPC consistently outperforms all sparse-attention baselines across benchmarks. On RULER (8K–128K), BinaryPC (2%) achieves 85.57 average, surpassing Quest (81.96), MagicPIG (84.68), CompressKV (78.42), CAKE (77.78), and PyramidKV (70.32), while remaining within 1.8 points of the oracle TOPK (85.74). On InfiniteBench, BinaryPC (43.21) edges out MagicPIG (43.18) and substantially exceeds Quest (40.89), PyramidKV (42.57), CAKE (42.38), and CompressKV (42.92). On LongBench v2, BinaryPC (29.8) outperforms all baselines, with the largest gap over Quest (26.8) and MagicPIG (27.6). Against the learned-hashing baseline Spotlight, BinaryPC matches or exceeds accuracy on LongBench (49.50 vs. 30.31 on Llama-3-8B; 49.50 on Llama-3.1-8B where Spotlight is not evaluated) and short-context tasks (59.31 vs. 58.97 on Llama-3-8B), all without any training. In efficiency, BinaryPC achieves 1.05–1.69× speedup over FlashAttention-2 on a single GPU, while MagicPIG actually runs slower than FlashAttention-2 (0.42–0.50×) due to its GPU-CPU collaborative decoding and >1000-bit hash codes.

## Relation to Prior Work

BinaryPC sits at the intersection of hashing-based sparse attention and classical PCA. It departs from MagicPIG's data-independent LSH (random hyperplanes oblivious to activation geometry) and Spotlight's learned MLP hashing (requiring ~8 hours of per-model training) by repurposing the iterative rank-1 decomposition of PCA with binary quantization, yielding a training-free, data-aware construction. The asymmetric design—binary codes for keys, quantized real-valued projections for queries—is a deliberate departure from symmetric hashing schemes, motivated by the fact that key memory transfer dominates decoding cost. Conceptually, the paper bridges the gap between the information-theoretic guarantees of LSH and the structural fidelity of learned representations without the training overhead.

## Why It Matters / Open Questions

The practical impact is significant: a training-free, drop-in mechanism that achieves 3.56× decoding throughput over FlashAttention-2 with only ~1.56% additional memory overhead, making long-context inference substantially more accessible without per-model fine-tuning. The 64-bit code length (10× shorter than MagicPIG) suggests that data-awareness, not code length, is the primary driver of retrieval fidelity in LLM activations. Open questions include whether the approach extends beyond 128K contexts, how it interacts with emerging KV-cache compression or quantization techniques, and whether the reconstruction-error signal can be exploited for adaptive per-layer or per-head budget allocation rather than the current fixed 2% + 10% EAS split.
