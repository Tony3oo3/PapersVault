## Problem

Emerging AI accelerators with novel ISAs lack mature compiler toolchains, forcing developers to hand-craft low-level kernels—a process that is slow, error-prone, and does not scale across hardware targets. While LLM-based code generation has shown promise in mature GPU ecosystems (CUDA, Triton), it remains unclear whether agentic LLM systems can generate valid and efficient bare-metal assembly kernels for previously unseen ISAs without prior programming examples, relying instead on architectural specifications and hardware-simulator feedback.

## Input / Output

The agent receives a task description (e.g., GEMM, FlashAttention, ConvBlock), the target platform's ISA documentation and hardware specifications (embedded in the system prompt, ranging from ~5k to ~15k tokens depending on the accelerator), and a workload configuration (e.g., matrix dimensions, sequence length, quantization format). It produces ISA-level assembly code through iterative tool calls, which is then verified via tolerance-based numerical comparison against PyTorch or C++ reference implementations and benchmarked for cycle-accurate performance against each platform's compiler baseline. Each of the 33 tasks is evaluated under 5 configurations of increasing scale, yielding over 1,100 experiments across four frontier models and three accelerators plus one CPU.

## Method

KernelCraft is a benchmark and agentic evaluation framework built around a native function-calling loop: the LLM agent autonomously invokes six tools (write_code, check_syntax, run_evaluation, view_output, get_instruction_size, grep_docs) to write, compile, execute, and diagnose assembly kernels, receiving memory-level diff feedback on mismatches and iterating up to 15–25 refinement steps depending on task complexity. Unlike prior kernel-generation benchmarks that use external orchestration loops, KernelCraft relies solely on the model's built-in tool-calling capability, directly measuring agentic competence without confounding infrastructure. The benchmark spans three difficulty levels (primitive operations, composite operations, end-to-end system blocks) across three emerging NPU platforms with distinct ISAs (PLENA custom ISA, AMD NPU custom ISA, Coral NPU RISC-V+RVV) and a RISC-V CPU (Sonic BOOM), with correctness validated under platform-specific numerical tolerances accounting for quantization and accumulation effects. Ablations isolate the contributions of extended reasoning tokens, in-context examples, documentation density, and individual tools, revealing that tool-use efficiency and ISA documentation quality are the dominant factors in generation success.

## Results

Across three emerging accelerators (PLENA, AMD NPU, Coral NPU) and 23 ML tasks with 5 configurations each, GPT-5.2 achieves the highest overall success rate at 56% on PLENA, 47% on Coral NPU, and 17% on AMD NPU, while DeepSeek R1 succeeds on only 1 kernel per platform. Success drops sharply with task complexity: GPT-5.2 reaches 74% on Level 1 primitives (PLENA) but falls to 45% on Level 2 composites and 0% on Level 3 end-to-end blocks. On performance, agent-generated kernels achieve up to 7.93× speedup over compiler baselines (Gemini-3-Flash on Coral NPU ConvBlock), with consistent 1.06–1.22× gains on PLENA normalization tasks, though AMD NPU results cluster tightly around the baseline (0.89–1.18×).

## Baselines & Comparisons

The paper compares four frontier LLM agents (GPT-5.2, Gemini-3-Flash, Claude Sonnet 4, DeepSeek R1) against each other on the KernelCraft benchmark, and compares agent-generated kernels against two performance baselines: platform compiler outputs and human expert hand-tuned kernels. GPT-5.2 dominates on success rate across all three accelerators (56%/17%/47%), while Gemini-3-Flash is a distant second (35%/11%/39%); Sonnet 4 and DeepSeek R1 trail significantly, with DeepSeek R1 generating only one correct kernel per platform due to fundamental tool-use failures (e.g., terminating after the first write_code call without ever invoking run_evaluation). Against compiler baselines, agent kernels achieve meaningful speedups on PLENA (1.06–1.22× on normalization) and Coral NPU (up to 7.93× on ConvBlock via BatchNorm folding), but AMD NPU results remain near parity (0.89–1.18×). Against human expert hand-tuned kernels on Coral NPU depthwise convolution, KernelCraft-generated kernels are functionally correct within 15 iterations but achieve only 2.5× speedup over the compiler versus 20× for the expert, highlighting a substantial remaining gap to expert-level optimization.

## Relation to Prior Work

This paper extends the LLM-based kernel generation line (KernelBench for CUDA, TritonBench for Triton, NPUEval for NPU C++) by pushing the abstraction level down to bare-metal assembly and the hardware target up to novel, undocumented ISAs with no prior training-data representation. It departs from prior agentic code-generation frameworks (Reflexion, Self-Debug, Toolformer) by requiring native function-calling as the sole interaction mechanism rather than an external orchestration loop, and by operating in a zero-shot regime where the agent must rely on ISA documentation and simulator feedback rather than in-distribution programming patterns. The tool-use paradigm draws on recent function-calling work (DeepSeek, Qwen) but applies it to a domain—close-to-metal hardware programming—where no prior benchmark exists.

## Why It Matters / Open Questions

KernelCraft is the first systematic benchmark showing that frontier LLM agents can generate functionally correct assembly for unseen ISAs (up to 56% on primitives) and can discover hardware-aware optimizations absent from immature compiler toolchains (e.g., 7.9× speedup via BatchNorm folding). However, Level 3 end-to-end blocks remain essentially unsolved across all model–accelerator pairs, and success rates are highly sensitive to documentation quality, leaving open whether agents can scale to full model-level workloads. The finding that tool-calling capability is a hard prerequisite (DeepSeek models fail entirely despite strong code-generation ability) has broader implications for agentic system design beyond kernel generation. Future directions include formal verification, fusing ISA knowledge into model weights, and multi-agent collaboration for co-design.
