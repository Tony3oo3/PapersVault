## Problem

Execution-based verification for competitive programming is bottlenecked by test input quality: generating full test cases (inputs with ground-truth outputs) is as hard as solving the problem itself, while random input sampling is highly inefficient because only a tiny fraction of the vast valid input space is truly discriminative. The paper asks whether a verifier can be trained to actively search for highly discriminative test inputs that expose behavioral discrepancies among candidate solutions, rather than blindly sampling.
![Teaser figure](../imgs/ICML20263174/cropped_page2_idx1.webp)

## Input / Output

The verifier receives a competitive programming problem statement and a pair of candidate solutions, and interacts with a Python/C++ code execution sandbox through multi-turn tool calls (executing code, inspecting outputs, verifying constraints). It outputs a final input generator program G; executing G() yields a concrete test input that is valid (satisfies problem constraints) and distinguishing (produces different outputs on the two candidates). At inference time, one discriminative input is generated per sampled candidate pair, and all N candidates are executed on all generated inputs with output-agreement voting to select the best solution.

## Method

The agentic verifier is trained via a three-stage pipeline: (1) large-scale data synthesis constructing problem-solution pairs with validated execution environments and LLM-generated input validators; (2) rejection fine-tuning on ~60K successful multi-turn interaction trajectories collected from a Qwen3-235B teacher model, where the model learns to reason about program behaviors, execute candidate solutions on proposed inputs, and iteratively refine its input generator; (3) agentic reinforcement learning using GRPO with a sparse outcome-based reward (−1 for invalid/empty, 0 for non-distinguishing, +1 for distinguishing), trained on hard negative solution pairs that admit few distinguishing inputs. The pairwise formulation (distinguishing two solutions) is deliberately simpler than multi-candidate discrimination, and the key insight is that discriminative input quality—not input quantity—determines the effectiveness of execution-based voting, which the trained verifier exploits to achieve +10–15% absolute Best@k gains over strong execution-based baselines.

## Results

The Agentic Verifier achieves the best Best@k accuracy across all five competitive programming benchmarks and both policy models. With Qwen3-235B-A22B as the policy model, it reaches 84.1% on USACO, 82.9% on LiveCodeBench, 48.6% on OJBench, 31.2% on ICPC-Eval, and 50.9% on CodeForces (Best@64), yielding absolute gains of +7.6 to +11.5 points over the vanilla baseline. The closest execution-based baseline (Random Generator) trails by 1.2–5.5 points depending on benchmark and k, while full-test-case methods (CodeT, CodeRM) are consistently 2–6 points behind. Gains are most pronounced on harder benchmarks (OJBench, ICPC-Eval, CodeForces) and scale further with increased test-input budgets.

## Baselines & Comparisons

The Agentic Verifier outperforms all six baselines on every benchmark and both policy models. Against the closest execution-based competitor, Random Generator (AlphaCode-style input sampling), it gains +1.2 to +5.5 points (Best@64), with the largest margins on CodeForces (+5.5) and OJBench (+4.4) for the 235B policy. Full-test-case methods CodeT and CodeRM, which require generating both inputs and ground-truth outputs, are 2–6 points behind the Agentic Verifier and sometimes underperform the simpler Random Generator (e.g., CodeRM scores 34.4 vs. 45.4 on CodeForces Best@64 with the 235B model). MBR-Exec (soft), which uses execution-based minimum Bayes risk decoding, trails by 2.6–7.2 points. The scoring-based GradingRM (Skywork-Reward-V2) is the weakest baseline, often degrading below vanilla (e.g., 73.6 vs. 75.4 on USACO Best@64, 34.4 vs. 39.7 on CodeForces Best@64). A CoT-based Generative Reward Model (GenRM, Zhang et al. 2025) tested in Appendix F achieves only 67.8/68.6 on LiveCodeBench (Best@8/64), well below the Agentic Verifier's 73.6/73.7, confirming that execution-based discriminative input generation substantially outperforms scoring-based verification in the code domain.

## Relation to Prior Work

This paper extends execution-based best-of-N verification for competitive programming (AlphaCode, MBR-Exec, CodeT, CodeRM) by replacing random or full test-case generation with a trained agentic verifier that actively searches for discriminative inputs through multi-turn interaction with code execution environments. It departs from prior prompt-based generator-validator pipelines (CodeContests+, HardTests, AutoCode, KlearCodeTest) by internalizing both generation and validation into a single model trained via rejection fine-tuning and agentic RL (GRPO) with sparse outcome rewards. The pairwise formulation—distinguishing two specific solutions rather than scoring all candidates—simplifies the training signal while connecting to multi-candidate selection through output-agreement voting.

## Why It Matters / Open Questions

The paper demonstrates that random input scaling is fundamentally insufficient for competitive programming verification (a large, persistent gap vs. ground-truth inputs), and that a trained 30B agentic verifier outperforms a 235B zero-shot model by a wide margin, showing task-specific training matters more than raw scale for this task. The discovery that benchmark test suites act as imperfect verifiers—producing false positives that the agentic verifier can expose—has broader implications for code evaluation methodology beyond reranking. Open questions include whether the verifier's discriminative inputs can serve as RL training signals for the policy model (creating a generation-verification virtuous cycle), and whether the approach generalizes beyond competitive programming to repo-level code verification (the SWE-bench pilot shows only +1.6% with a zero-shot judge).
