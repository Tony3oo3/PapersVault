## Problem

Prior security analyses of LLM caching focused on privacy leakage via timing side channels, leaving the integrity risk from semantic cache key collisions unexplored. This paper shows that semantic cache keys are locality-preserving fuzzy hashes whose design for high hit rates fundamentally conflicts with the cryptographic avalanche effect required for collision resistance, making semantic caching inherently vulnerable to adversarial key collision attacks that hijack LLM responses and agent tool invocations.

## Input / Output

The attacker takes a victim prompt (benign query) and a source prompt (malicious indirect prompt injection instruction) as inputs, along with a publicly available surrogate embedding model (e.g., BAAI/bge-small-en-v1.5), and operates under a strict black-box constraint where the target embedding model's parameters, internal vectors, and similarity threshold are inaccessible. The output is an adversarial prompt of the form p_src ⊕ s, where s is a discrete token suffix optimized to induce a false-positive cache key collision, causing the victim's query to retrieve the attacker's planted malicious cached response or tool invocation. The validator infers cache hit/miss status solely from end-to-end response latency, treating it as a noisy observation of a latent binary hit indicator.

## Method

CacheAttack is built on a Generator-Validator framework. The generator performs GCG-based gradient optimization over a discrete suffix s, minimizing a collision loss (cosine similarity for semantic cache; a tanh-relaxed LSH partitioning loss for semantic KV cache) plus a perplexity regularization term to ensure the adversarial suffix remains stealthy and bypasses input filters. The validator models execution latency under class-conditional Gaussians calibrated from known hit/miss queries, applying a MAP decision rule with dynamic recalibration to classify cache hits without accessing internal cache state. Two variants are proposed: CacheAttack-1 validates directly on the black-box target (suffering from mandatory TTL waiting periods), while CacheAttack-2 uses the surrogate model as a high-throughput filter and invokes the target only for final verification, decoupling exploration from the temporal bottleneck. The paper further formalizes the inherent trade-off via Lemma 3.1, which lower-bounds the false-positive hit probability as a function of cache hit rate, proving that any system maximizing locality necessarily admits a non-negligible collision surface.

## Results

On the primary LLM response hijacking task (RQ1), CacheAttack-1 achieves a Hit Rate of 86.9% and Injection Success Rate of 81.1% on semantic cache, and 85.8% HR / 83.0% ISR on semantic KV cache, substantially outperforming the GA baseline (36.2% HR / 33.7% ISR). CacheAttack-2, the surrogate-assisted variant, achieves 83.1% HR / 77.1% ISR (semantic cache) and 80.4% HR / 77.0% ISR (semantic KV cache) with far lower temporal cost. In the agent tool-invocation setting (RQ2), CacheAttack-2 reaches a 90.6% hit rate on semantic cache, dropping Tool Selection Rate by 84.5% and Answer Accuracy by 83.8% relative to benign execution. Cross-model transferability (RQ3) shows diagonal (same-model) hit rates exceeding 92%, with off-diagonal transfers ranging from ~50% to ~87% depending on surrogate–target similarity.

## Baselines & Comparisons

The paper compares against a single black-box baseline: a Genetic Algorithm (GA) that optimizes adversarial suffixes using cosine similarity as the fitness function, while sharing the same latency-based validator. CacheAttack-1 outperforms GA by approximately 50.7 percentage points in HR and 47.4 points in ISR on semantic cache (86.9% vs. 36.2% HR; 81.1% vs. 33.7% ISR), and by 51.8 / 51.5 points on semantic KV cache. CacheAttack-2, which trades a small amount of peak performance for dramatically reduced interaction with the target (one query per iteration vs. repeated probing), still surpasses GA by 46.9 / 43.4 points in HR / ISR on semantic cache and by 46.4 / 45.5 points on semantic KV cache. The gap between CacheAttack-1 and CacheAttack-2 is modest (≈3–4 points), confirming that the surrogate-assisted filtering preserves most of the collision strength while eliminating the TTL bottleneck that makes CacheAttack-1 impractical at scale.

## Relation to Prior Work

This paper builds on GCG (Zou et al., 2023) for adversarial suffix optimization, repurposing it from LLM jailbreaking to embedding-space collision search. It departs from prior LLM caching security work, which has focused on privacy leakage via timing side channels (Wu et al., 2025; Zheng et al., 2024b) or poisoning of cached content (PoisonedRAG, Zou et al., 2025), by reframing the threat as an integrity problem: the semantic cache key itself is a locality-preserving fuzzy hash that inherently lacks the avalanche effect. The paper's core conceptual contribution is formalizing the locality-vs-collision-resistance trade-off as a theoretical bound (Lemma 3.1), positioning semantic caching as structurally vulnerable rather than merely misconfigured.

## Why It Matters / Open Questions

Semantic caching is already deployed in production by AWS and Microsoft, making this an immediate infrastructure risk rather than a hypothetical one. The paper's central finding—that the design property enabling high cache hit rates (locality) is the same property enabling collision attacks—implies no free-lunch fix exists: key salting reduces hit rate by only ~20%, and per-user isolation defeats the purpose of cross-tenant semantic reuse. Open questions include whether collision-resistant yet locality-preserving key schemes are possible, how to validate cache hits without latency side-channels, and whether the cascading agent-level impact (tool invocation hijacking) can be contained architecturally. The financial agent case study, where a collision triggers an actual sell order, underscores that this is not merely an academic concern.
