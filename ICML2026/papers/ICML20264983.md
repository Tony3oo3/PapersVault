## Problem

Existing LLM-based GPU kernel generation approaches rely on generic iterative generate-verify-measure loops that suffer from mode collapse (repeatedly proposing variants near recent successes) and context degradation (failed attempts accumulating in the prompt). These methods also treat hardware only through profiling feedback rather than structuring the search space around hardware-relevant dimensions, and they target CUDA almost exclusively, ignoring cross-platform paradigms like SYCL.

## Input / Output

The framework accepts flexible task specifications: PyTorch reference code, free-form natural language instructions, or existing kernels to optimize, along with hardware specifications and optional initial implementations. Tasks are defined via a YAML config plus a pytest-compatible Python module, enabling arbitrary test frameworks beyond KernelBench's fixed format. The system outputs compiled, validated, and benchmarked kernels in SYCL, CUDA, or Triton, optionally as templated kernels with a dispatch function enumerating valid parameter combinations (e.g., block sizes, tile dimensions), plus evolved prompt archives capturing task-specific optimization strategies.

## Method

KernelFoundry combines three mechanisms within a MAP-Elites quality-diversity loop. First, kernels are indexed in a 4×4×4 behavioral grid defined by memory access pattern (scalar→coalesced→shared-memory tiling→multi-level hierarchy), algorithmic structure (direct translation→fused→reformulated→novel), and parallelism coordination (none→work-group barriers→sub-group primitives→global atomics), with coordinates assigned via deterministic static pattern matching. Second, a dedicated meta-prompter LLM co-evolves four prompt sections (optimization philosophy, strategies, pitfalls, analysis guidance) every 10 generations, maintaining a separate prompt archive to counteract context pollution. Third, gradient-informed selection computes fitness, improvement-rate, and exploration gradients from transition history and translates them into natural-language mutation hints injected into generation prompts. Templated kernel generation separates algorithmic optimization from hardware parameter tuning, and the entire pipeline runs as a distributed system with independent LLM, compilation, and execution workers.

## Results

On the filtered KernelBench (111 tasks) with SYCL, KernelFoundry achieves 97% correctness, 71% fast₁, 42% fast₂, and an average speedup of 2.32× over PyTorch eager. On the CUDA comparison set (20 L1 + 20 L2 tasks), it reaches 100% correctness with average speedups of 1.24× (L1) and 2.10× (L2), and on the 12 Robust-kbench tasks (including backward ops) it achieves 100% correctness with a 12.1× average speedup. A hardware-awareness crossover experiment confirms that 70% of kernels optimized on one GPU outperform their counterpart optimized on a different GPU (avg. hardware-speedup 1.54× for LNL, 1.11× for B580).

## Baselines & Comparisons

Against Kernelsseum (the original KernelBench leaderboard), KernelFoundry achieves substantially higher speedups: 1.24× vs. 0.77× on L1 and 2.10× vs. 0.87× on L2, while also reaching 100% correctness versus Kernelsseum's 65%. Against the AI CUDA Engineer (Lange et al., 2025a), KernelFoundry wins on both levels after re-evaluation on identical hardware (A6000): 1.24× vs. 1.01× on L1 and 2.10× vs. 1.61× on L2, with a notably larger gap on L2 fusion tasks. On Robust-kbench (12 tasks including backward operations), KernelFoundry achieves a 36% higher average speedup (12.1× vs. 8.9× re-evaluated) and 100% fast₁ versus 92%. Against OpenEvolve (open-source AlphaEvolve), KernelFoundry reaches comparable speedup at 40 iterations (2.73× vs. 2.54×) but pulls ahead significantly at 10 iterations (2.06× vs. 1.48×), demonstrating faster convergence. Against the highly optimized oneDNN C++ library, KernelFoundry is competitive, winning on 3 of 5 operations (concat+LayerNorm 1.79×, Sum Reduction 1.10×, Softmax 1.70×) but losing on MatMul+ReLU (0.35×) and MaxPool+Linear (0.72×), where oneDNN uses hand-written assembly.

## Relation to Prior Work

This paper sits at the intersection of LLM-based kernel generation (KernelBench, AI CUDA Engineer, robust-kbench, multi-agent systems like Astra and PRAGMA) and quality-diversity evolutionary search (MAP-Elites, CMA-ME, AlphaEvolve, CodeEvolve). It departs from the dominant iterative generate-verify-measure paradigm by replacing generic code-generation loops with a structured MAP-Elites archive indexed on kernel-specific behavioral descriptors (memory access patterns, algorithmic structure, parallelism coordination), and by co-evolving prompts via a dedicated meta-prompter LLM to counteract context degradation. The template-based parameter tuning and the focus on SYCL as a cross-platform target extend prior work that has been almost exclusively CUDA-centric.

## Why It Matters / Open Questions

The cross-platform SYCL focus and distributed execution framework address a real gap: most LLM kernel work targets NVIDIA's proprietary ecosystem, limiting practical adoption on Intel and AMD hardware. The Llama 3 rotary-embedding case study (7.9× speedup, 8% end-to-end forward-pass reduction) demonstrates practical utility beyond benchmarking. Open questions include whether the approach generalizes to more hardware architectures, how to formally eliminate reward hacking (incorrect kernels passing tests), and whether finetuning with verifiable rewards could eventually outperform the prompting-based evolutionary loop. The ~$5.7/kernel cost and dependence on frontier LLMs remain practical constraints for widespread adoption.
