## Problem

Existing code reasoning methods supervise only final outputs, leaving intermediate reasoning steps unverified against true program execution. This creates a reward-hacking gap where models can produce correct answers through logically inconsistent execution paths, since training signals cannot distinguish genuine execution understanding from lucky guesses. The paper asks whether making intermediate execution states explicitly observable and verifiable can close this gap.
![Teaser figure](../imgs/ICML20264778/cropped_page1_idx1.webp)

## Input / Output

The method takes a Python program instrumented with structured print() anchors at variable assignments, loop exits, and return points, plus either a concrete input (output prediction) or a target output (input prediction). The model generates an interleaved sequence of <reasoning> and <print> blocks predicting the runtime value at each anchor in execution order, followed by a final <answer> tag; for input prediction, an additional <input> tag commits to an inferred input before trace verification begins. All ground-truth anchor values are produced by a deterministic Python interpreter, not the LLM, and the final-answer metric ignores intermediate traces for fair comparison with non-trace baselines.

## Method

StepCodeReasoner transforms code reasoning into stepwise execution modeling via two components. First, Execution-Trace Augmentation uses a teacher LLM to insert structured print(f'VAR: {VAR}') anchors into code under heuristic rules (no in-loop prints, mandatory anchors after assignments and before returns, max 10-line traces), then executes the instrumented program to obtain interpreter-verified ground-truth states. Second, Dual-Granularity GRPO (DG-GRPO) performs structured credit assignment at two levels: a group-relative advantage that normalizes binary stepwise rewards across G sampled trajectories at each shared anchor index (inter-trajectory), and an intra-trajectory shaping term that multiplies a correct step's credit by the empirical future success rate of the remaining anchors in that trajectory. The combined advantage is used in a standard GRPO policy-gradient objective with a KL penalty, trained after SFT on 17K instrumented examples using Qwen2.5-Coder-7B-Instruct as the base model.

## Results

StepCodeReasoner (7B) achieves 91.1% average on CRUXEval and 86.5% on LiveCodeBench, yielding an overall average of 87.8% across prediction tasks. On the fine-grained REval benchmark, it scores 82.9% (vs. 72.3% for CodeReasoner-7B and 77.3% for GPT-4o), with the largest gains on State prediction (+22.5%) and Path prediction (+22.8%). On code generation, it reaches 90.1 on HumanEval, 85.0 on MBPP, and 19.4 on LiveCodeBench generation (avg 64.8 vs. 62.6 for CodeReasoner-7B).

## Baselines & Comparisons

StepCodeReasoner-7B outperforms GPT-4o (0.803 avg) by 7.5 points overall, with particularly large margins on input prediction (LCB-I: 0.845 vs. 0.653) and REval (0.829 vs. 0.773). Against the direct baseline CodeReasoner-7B (0.818 avg), it gains +7.3 points overall, with the largest relative improvement on LCB-I (+13.7%) and REval State/Path prediction (+22.5%/+22.8%). It also surpasses the larger CodeReasoner-14B (0.868 avg) by 1.0 points, demonstrating that stepwise RL supervision compensates for the 2× parameter gap. Among open-source baselines, it beats Qwen3-Coder-30B (0.794), Qwen2.5-72B (0.766), and Llama3-70B (0.585) by 8.4, 11.2, and 29.3 points respectively. On code generation (Table 4), it improves over CodeReasoner-7B by +2.5 points on average (64.8 vs. 62.6), with the largest gain on LiveCodeBench generation (+9.0%), and also outperforms the same-budget terminal-only RL ablation (63.1), confirming the benefit of stepwise rewards over additional training compute.

## Relation to Prior Work

This paper extends the CodeReasoner line of work (Tang et al., 2025), which already combines execution-focused data construction with SFT and GRPO-based RL for code reasoning, by replacing terminal-only supervision with dense stepwise rewards derived from interpreter-verified execution anchors. Methodologically, it builds on GRPO (Shao et al., 2024) and Step-GRPO (Zhang et al., 2025) for group-relative advantage estimation, but departs from both by adding an intra-trajectory shaping term that modulates step-level credit based on downstream correctness within a single sampled path. The rule-based, interpreter-grounded reward design explicitly contrasts with learned Process Reward Models, which the authors show to be unreliable (≤73% step-judgment accuracy even for GPT-4o) for code execution states.

## Why It Matters / Open Questions

The paper provides a concrete, measurable validation of the 'right answer, wrong logic' reward-hacking problem in code reasoning (63.5% step accuracy vs. 85.6% final accuracy for CodeReasoner-7B) and shows that stepwise execution supervision substantially closes this gap. The DG-GRPO formulation—combining cross-trajectory group-relative advantages with intra-trajectory future-success shaping—is a clean, critic-free credit-assignment mechanism that could transfer to other domains with verifiable intermediate states (e.g., agent trajectories, multi-hop reasoning). Key limitations include Python-only applicability, the prohibition on in-loop anchors, a 10-line trace cap, and a 1.5× inference token overhead; extending the framework to non-deterministic, multi-language, or repository-level code remains open.
