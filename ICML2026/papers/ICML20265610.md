## Problem

Mainstream in-context learning for tool calling requires stuffing verbose tool documentation and usage examples into the prompt, causing high inference latency, increased hallucination risk, and paradoxically degraded accuracy as context length grows. Tuning-based methods improve general tool-calling ability but fail to internalize tool-specific details, remaining dependent on in-context documentation at inference. The paper asks whether tool knowledge can be fully encoded into loadable model parameters, eliminating the need for any in-context tool documents or examples.

## Input / Output

At inference, the model receives only the user query and interaction history (prior tool calls and observations) as text input—no tool schemas, documentation, or examples are provided in the prompt. The output is a structured tool call specifying the selected tool name and its arguments. A lightweight gating network separately consumes the context embedding and pre-computed tool document embeddings to produce per-tool aggregation weights, which dynamically load the corresponding LoRA parameter modules onto the frozen backbone before action generation.

## Method

ParaTool encodes each tool into an independent set of LoRA low-rank matrices targeting the FFN layers of a frozen LLM backbone, enabling plug-and-play tool loading. A three-stage pipeline trains these representations: (1) parametric tool pre-training optimizes each tool's LoRA parameters on document-aware and document-free traces to internalize tool semantics; (2) soft tool selection trains an MLP gating network to produce continuous aggregation weights over candidate tools via softmax over relevance scores computed from context and tool-document embeddings, with entropy regularization to prevent collapse into hard selection; (3) parametric tool fine-tuning jointly updates all tool LoRA parameters under the weighted composition Δθ^k = Σ α_i^k Δθ_i, aligning training dynamics with the multi-tool superposition used at inference. A theoretical analysis via certified robustness radius proves that softer weight distributions (lower ‖α‖₂²) strictly reduce the gradient norm upper bound, yielding larger robustness guarantees than hard Top-1 selection.

## Results

On Stable ToolBench, ParaTool achieves 69.57% average Pass Rate with Llama-3.1-8B and 75.95% with Qwen2.5-7B, outperforming the strongest ICL baseline (Context+Docs&Examples) by 5.9% and 11.2% respectively. On BFCL, ParaTool reaches 91.39% (Llama) and 92.00% (Qwen) Non-live average AST accuracy, and 76.23% / 77.26% Live average, surpassing the best baseline by 6.8% and 4.2% relative improvement. The method also reduces inference FLOPs by up to 92.22% on Stable ToolBench and 94.45% on BFCL compared to context-based approaches, with the additional LoRA aggregation overhead accounting for less than 5% of total inference cost.

## Baselines & Comparisons

ParaTool consistently outperforms all seven baselines across both Llama-3.1-8B and Qwen2.5-7B backbones on both benchmarks. Against the strongest ICL baseline (Context+Docs&Examples), ParaTool gains +3.90 Pass Rate points on Llama and +8.99 on Qwen on Stable ToolBench, and +1.17 / +1.17 Non-live AST accuracy on BFCL. Against ToolLLaMA (the strongest tuning-based baseline), ParaTool improves by +4.16 Pass Rate (Llama) and +7.64 (Qwen) on Stable ToolBench, and by +8.89 / +8.67 Non-live accuracy on BFCL. The Global Parameterization baseline (single shared LoRA for all tools) performs worst among parameter-based methods, confirming that tool-specific parameterization is essential. Among retrieval-based selectors, Reinvoke is the strongest but still trails ParaTool by 5.79 Pass Rate points (Llama, Stable ToolBench) and 31.7% relative in the Parallel Multiple BFCL category, indicating that learned soft gating substantially outperforms fixed retrieval strategies in multi-turn, multi-tool scenarios.

## Relation to Prior Work

ParaTool repurposes LoRA from its standard role as a single shared adapter into per-tool parameter modules, creating a tool-level analogue of mixture-of-experts routing. It departs from both ICL-based tool calling (which concatenates documentation into the prompt) and tuning-based methods like ToolLLaMA (which compress all tool knowledge into one global parameter space) by assigning each tool an independent, loadable LoRA set and composing them via a learned gating network. The theoretical analysis draws on certified robustness radius (Zhai et al., 2020) to formalize why soft composition of tool gradients is more robust than hard selection, connecting the architectural choice to a provable stability guarantee.

## Why It Matters / Open Questions

The 92–94% FLOPs reduction makes parameter-based tool calling practically viable for latency-sensitive agentic deployments, and the finding that adding more in-context examples can degrade accuracy (Figure 1) challenges the default assumption that richer context is always beneficial. However, the framework's requirement that every tool be pre-parameterized during training is a significant constraint for open-ended environments where tools are frequently added or updated; the authors acknowledge this and suggest hypernetwork-based meta-learning as a future direction. Open questions include whether the gating mechanism generalizes to highly overlapping tool schemas and whether the plug-and-play property holds when the tool inventory changes substantially.
