## Problem

Diffusion-based LLMs (dLLMs) are bottlenecked by transient activations recomputed at every denoising step rather than by KV-Cache, yet existing memory management techniques are designed for autoregressive models and lack the global visibility to handle dLLMs' dynamic memory peaks that shift between logits and feed-forward networks. This mismatch causes severe memory fragmentation and forces systems to provision for worst-case peaks, capping the maximum supportable context length.

## Input / Output

MOSAIC takes a text prompt, a target output sequence length L, and a number of denoising steps N, and produces a fully denoised text sequence of length L. The input sequence begins fully masked and is progressively unmasked over N bidirectional forward passes; the system is training-free and preserves exact model outputs. It operates on standard Transformer-based dLLMs (LLaDA-8B, Dream-7B, LLaDA-MoE) and supports variable-length inference without padding, targeting context lengths up to 128k tokens on 24–40 GB GPUs.

## Method

MOSAIC shifts dLLM inference from local, static memory management to a global, dynamic paradigm through four integrated components. A fused gather-GEMM mask-only logits kernel computes logits exclusively for masked tokens via indirect on-chip addressing, eliminating the O(N_mask × D) auxiliary buffer. A graph registrar explicitly defines a parameterized computation graph template with symbolic dimensions, providing whole-graph visibility that bypasses torch.compile's fragile dynamic capture and graph breaks. A lazy chunking optimizer performs an online bottleneck-driven search that adaptively increases chunk counts for FFN or logits only when physical memory is insufficient, achieving the same maximum context as brute-force search at 0.28%–0.32% of its latency. A global memory manager combines a single-request first-fit planner (deriving a unified tensor placement map) with a VMM-based allocator that reserves contiguous virtual addresses and binds physical pages on demand, eliminating external fragmentation without static preallocation waste.

## Results

MOSAIC achieves a 15.30×–32.34× increase in maximum supportable context length (L_max) over baselines on identical hardware (RTX 3090 24GB and A100 40GB), with an average 2.71× reduction in the memory peak-to-average ratio. End-to-end latency is reduced by 5.9%–55.4% compared to the unmodified PyTorch baseline (PYNATIVE) and by 2.5%–24.9% compared to the vLLM-ported baseline (MOSAIC-TORCH). The system is training-free and preserves exact model outputs, evaluated on LLaDA-8B, Dream-7B, and LLaDA-MoE across varying prompt-to-total length ratios.

## Baselines & Comparisons

MOSAIC is compared against three baselines: PYNATIVE (raw PyTorch dLLM inference), MOSAIC-TORCH (vLLM-ported without memory optimizations), and MOSAIC-COMPILE (MOSAIC-TORCH + torch.compile). MOSAIC dominates all baselines on maximum context length, achieving 32.34×, 25.41×, and 15.30× higher L_max than PYNATIVE, MOSAIC-TORCH, and MOSAIC-COMPILE respectively. On latency, MOSAIC also wins across the board: it is 5.9%–55.4% faster than PYNATIVE and 2.5%–24.9% faster than both MOSAIC-TORCH and MOSAIC-COMPILE, with the largest gains at shorter contexts where the mask-only logits kernel and graph registrar (bypassing torch.compile's dynamic capture overhead) have the most impact. MOSAIC-COMPILE extends L_max by 45.5%–97.1% over MOSAIC-TORCH but suffers latency regression from compilation overhead, whereas MOSAIC achieves a larger L_max gain without any latency penalty. The ablation confirms that the global memory manager contributes 1.41×–3.00×, the mask-only kernel adds up to 3.68×–8.04×, and lazy chunking delivers the final boost to 15.30×–32.34×.

## Relation to Prior Work

This paper departs from the KV-Cache-centric memory optimization paradigm that dominates autoregressive LLM inference (PagedAttention, vAttention) and instead targets the fundamentally different bottleneck in diffusion LLMs: transient activations recomputed at every denoising step. It builds on vLLM's serving infrastructure and borrows first-fit memory planning heuristics from TVM and MCUNet, but introduces a novel explicit graph registrar to replace torch.compile's fragile dynamic graph capture, and a lazy chunking optimizer with bottleneck-driven search to handle the dynamic peak shifting between logits and FFN. The work is positioned as complementary to existing dLLM-specific KV-cache frameworks (Fast-dLLM, dInfer, Elastic-Cache), which shift the bottleneck back toward persistent states and reduce the activation-optimization scope.

## Why It Matters / Open Questions

The 15–32× context length extension on identical hardware, achieved training-free with exact output preservation and simultaneous latency reduction, makes long-context dLLM applications (repository-level code generation, massive-context filling) practically deployable on consumer and mid-range GPUs. The conceptual insight that dLLM memory is bottlenecked by transient activations with dynamic peaks—rather than persistent KV-Cache—reframes how systems researchers should approach this model family. Open questions include whether the approach scales gracefully to extreme multi-GPU settings (where communication buffers become the new bottleneck) and whether the dynamic peak-shifting behavior persists as dLLM architectures evolve (e.g., with architectural changes to FFN or attention).
