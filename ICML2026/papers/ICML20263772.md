## Problem

POET (Reparameterized Orthogonal Equivalence Training) provides strong training stability through spectrum preservation, but its original weight-centric implementation incurs prohibitive GPU memory consumption and computational overhead from intensive large-scale matrix multiplications, preventing it from scaling beyond ~3B parameters. The paper addresses the gap between POET's inherent parameter efficiency (sparse orthogonal matrices) and its actual GPU memory footprint, which was not reflected in the original implementation.
![Teaser figure](../imgs/ICML20263772/cropped_page1_idx0.webp)

## Input / Output

The method consumes standard text tokens (C4 corpus) and produces a fully dense LLM weight matrix with zero inference overhead, since the learned orthogonal matrices R and P are merged into the base weight W_RP after training. The trainable parameters are only the upper-triangular entries of skew-symmetric matrices that parameterize block-diagonal orthogonal matrices via Cayley-Neumann approximation, yielding extreme parameter efficiency (e.g., 366M trainable params vs. 2764M for AdamW on Llama-3B). A quantized variant (POET-XQ) additionally stores base model weights in INT8 and dequantizes on the fly.

## Method

POET-X makes orthogonal equivalence transformation scalable through five key techniques: (1) an input-centric (matrix-free) reformulation that replaces two matrix-matrix multiplications with three matrix-vector multiplications, eliminating storage of intermediate weight activations; (2) batch-parallel computation that treats each block of the block-diagonal orthogonal matrix independently, avoiding explicit construction of large sparse matrices; (3) an efficient Cayley-Neumann parameterization that stores only the upper-triangular part of skew-symmetric matrices (halving parameter count) and fuses forward/backward computations into single Triton kernels exploiting shared-memory reuse of Q and Q²; (4) permutation acceleration via custom CUDA index-mapping kernels (up to 20× speedup) and permutation reduction by pre-merging two of four permutations into the weight matrix; and (5) gradient checkpointing (POET-X_mem) that recomputes one intermediate activation during backprop to eliminate its storage cost. Together these yield 3× GPU memory reduction and 8× runtime speedup over original POET, enabling single-H100 pretraining of up to 13B-parameter LLMs.

## Results

On Llama-3B pretraining (60B tokens, C4 dataset), POET-X with block size b=512 achieves a validation perplexity of 12.05, outperforming AdamW (12.69), APOLLO (12.97), and GaLore (14.88), while using only 570M trainable parameters versus 2764M for full-parameter baselines. In terms of memory, POET-X (b=512) requires 68.52 GB, the lowest among all non-quantized methods, compared to 81.03 GB for AdamW. The quantized variant POET-XQ (b=512) further reduces memory to 60.65 GB while achieving 14.78 PPL on 10B tokens, outperforming quantized GaLore (17.74) and APOLLO (20.49). POET-X also achieves 3× GPU memory reduction and 8× runtime speedup over the original POET, enabling single-H100 pretraining of models up to 13B parameters.

## Baselines & Comparisons

POET-X (b=512) outperforms AdamW on both validation PPL (12.05 vs. 12.69) and peak memory (68.52 GB vs. 81.03 GB), while using only 21% of the trainable parameters (570M vs. 2764M). Against Muon, POET-X trades a small PPL gap (12.05 vs. 11.45) for lower memory (68.52 GB vs. 70.94 GB) and far fewer trainable parameters. POET-X decisively beats both APOLLO (12.05 vs. 12.97 PPL) and GaLore (12.05 vs. 14.88 PPL) on perplexity while also using less memory than either. Compared to the original POET, POET-X achieves 3× memory reduction and 8× runtime speedup, and unlike POET (which OOMs on 8B/13B models), POET-X fits within a single H100. In the quantized setting, POET-XQ (b=512) achieves the best PPL (14.78) among all quantized methods, beating Q-GaLore (17.74) and Q-APOLLO (20.49) while maintaining the lowest memory footprint (60.65 GB). For distributed training, POET-X scales near-linearly with GPU count (ratio ~60× from 1 to 64 GPUs) using DDP, whereas AdamW requires FSDP and deviates from ideal scaling due to communication overhead.

## Relation to Prior Work

POET-X is a direct engineering extension of POET (Qiu et al., 2025a), which introduced reparameterized orthogonal equivalence transformation for spectrum-preserving LLM training. The key conceptual departure is reformulating POET's weight-centric computation into an input-centric form inspired by matrix-free methods for large-scale linear systems (Chen, 2005), combined with batch-parallel exploitation of the block-diagonal sparse structure and a compact upper-triangular storage for the Cayley-Neumann parameterization. This positions POET-X at the intersection of sparse training, parameter-efficient methods (LoRA, GaLore, APOLLO), and custom-kernel GPU optimization, while the orthogonal finetuning line (Qiu et al., 2025b) provides a related but simpler single-matrix analogue.

## Why It Matters / Open Questions

POET-X demonstrates that a theoretically elegant but practically infeasible training algorithm can be made to scale to 13B-parameter LLMs on a single H100 GPU, bridging a critical gap between parameter efficiency and actual memory efficiency. The quantized variant (POET-XQ) further extends this to settings where even memory-efficient baselines struggle, and the DDP-compatible memory footprint enables simpler, higher-throughput distributed training compared to FSDP-based approaches. Open questions include whether the block-diagonal approximation of full orthogonal matrices remains sufficient at larger scales, whether the spectrum-preserving property yields compounding long-term benefits beyond the modest PPL gains observed here, and whether the heavy reliance on custom CUDA/Triton kernels limits the method's accessibility and portability across hardware.
