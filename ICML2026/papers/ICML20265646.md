## Problem

Prior work on language-guided document editing presupposes an existing base document and operates through constrained application-specific interfaces (e.g., python-docx) or document images, leaving the core use case of generating a complete, professionally formatted rich-format document from a short natural language request largely unaddressed. Rich-format documents impose coupled structural and styling constraints where small changes ripple through the layout, and many quality defects are only visible after rendering, making a single-pass generation approach insufficient.

## Input / Output

The system takes a short natural language query (e.g., 'create a one-page project plan') and produces an HTML4 source document designed for fixed-format rendering (printing or PDF export). The HTML is rendered via Chromium/Playwright, exported to PDF, and rasterized into an ordered multi-page PNG sequence for both the reviewing agent's visual critique and the evaluation pipeline. Content alignment is scored on a Markdown conversion of the output, while presentation dimensions (rendering correctness, layout, professionalism) are scored on the rendered page images, decoupling textual fidelity from visual quality.

## Method

FORMACT formulates document generation as a hierarchical agentic editing process with two levels: a refinement level where a VLM reviewing agent critiques rendered pages to produce iterative editing requests (capped at five rounds), and an editing level where an LLM agent performs tool invocations over the HTML source. The editing agent has three tools: a template retriever that searches a pool of ~3M human-authored Word documents (converted to HTML and filtered by a LoRA-trained reward model) using multi-field natural-language specifications embedded with all-MiniLM-L6-v2 in ChromaDB; a syntax-aware HTML editor supporting line-based view and patch operations with automatic syntax validation and rollback of invalid edits; and a task planner for explicit subgoal tracking. A key mechanism is edit-triggered context compression, which masks previously viewed source snippets after each successful edit to keep the working context bounded and enforce a disciplined view-then-edit cycle, achieving 84% character-level reduction and preventing 82% of samples from exceeding the context window. The approach draws on the SWE-agent paradigm of direct source-code manipulation rather than library-based construction, enabling unconstrained global layout planning and fine-grained formatting control.

## Results

On RICHDOCBENCH (500 examples), FORMACT achieves the best scores on rendering correctness (4.81/5), layout appropriateness (3.92/5), and professionalism (3.92/5), while content alignment is competitive at 4.35/5. In blind human preference (50 examples), FORMACT is ranked first on 76.0% of multi-pass comparisons (avg rank 1.30) and 59.3% of single-pass comparisons (avg rank 1.50). The refinement loop contributes substantially: removing it drops rendering correctness from 4.81 to 4.59, and applying the same loop to other baselines yields +4.0% to +11.8% rendering gains.

## Baselines & Comparisons

Against Codex (OpenAI's general-purpose coding agent), FORMACT wins decisively on all presentation metrics: rendering correctness 4.81 vs. 4.39 (+0.42), layout appropriateness 3.92 vs. 3.80, and professionalism 3.92 vs. 3.72. Codex narrowly leads on content alignment (4.42 vs. 4.35), suggesting its general-purpose editing preserves textual fidelity slightly better, but this gap is small and statistically insignificant. In human preference, FORMACT is ranked first on 76.0% of examples versus Codex's 14.0%, with an average rank of 1.30 vs. 2.21. The paper also shows that applying FORMACT's review-guided refinement loop to Codex's outputs improves rendering correctness by +11.8% (4.40→4.92), indicating that the refinement mechanism is transferable and that Codex's raw output quality is the bottleneck. Against the library-based Docx Agent, FORMACT's advantage is even larger (rendering 4.81 vs. 3.87; professionalism 3.92 vs. 3.40), supporting the paper's argument that direct HTML source editing offers greater expressiveness than constrained python-docx API calls.

## Relation to Prior Work

FORMACT adapts the SWE-agent source-editing paradigm (Yang et al., 2024) and the ReAct iterative loop (Yao et al., 2023) from software engineering to HTML document generation, replacing application-specific editing interfaces (DocEdit, Agent-DocEdit) with a syntax-aware source editor that supports line-addressable patches and automatic rollback. It departs from prior document-editing work, which presupposes an existing document and operates through constrained library APIs or document images, by formulating the task as end-to-end generation from a natural-language query with no initial draft. The retrieval-augmented component draws on a corpus of ~3M real Word documents converted to HTML, indexed via multi-field specifications and a LoRA-trained reward model, extending RAG from text retrieval to structured document template selection.

## Why It Matters / Open Questions

The paper demonstrates that professional rich-format document generation is a distinct engineering problem where general-purpose coding agents (Codex) do not automatically transfer, and that source-level editing outperforms library-based construction (python-docx) in expressiveness and formatting control. The introduction of RICHDOCBENCH and RICHDOCFUZZ provides the first systematic benchmarks for end-to-end rich-format generation and VLM-based formatting-error detection, filling a gap in evaluation infrastructure. Key open questions include whether the approach generalizes beyond HTML to LaTeX or OOXML, whether the pipeline can operate with smaller open-source models, and how to close the substantial gap in VLM detection of subtle styling defects (best accuracy ~53% on styling vs. ~80% on content errors).
