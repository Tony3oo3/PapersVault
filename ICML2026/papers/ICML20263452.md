## Problem

Existing data science benchmarks suffer from fragmented evaluation interfaces that prevent fair cross-benchmark comparison, narrow task coverage that underrepresents domain-specific scientific workflows, and a critical validity gap: a substantial fraction of file-grounded tasks can be solved without accessing the data files at all, inflating performance through memorization, domain priors, or pattern matching rather than genuine data interaction.
![Teaser figure](../imgs/ICML20263452/cropped_page2_idx0.webp)

## Input / Output

Each task is a standardized object pairing a natural-language query with one or more data files (CSV, H5AD, etc.) and an evaluation metric; the LLM agent interacts with a stateful Jupyter kernel inside an isolated Docker container where datasets are mounted read-only and the agent operates in a separate writable workspace. For analysis tasks, output is a structured answer scored by exact-match with numerical tolerance; for prediction tasks, the agent produces a CSV submission scored against official Kaggle leaderboards yielding valid-submission rate, above-median rate, and medal rate. The framework also emits full execution trajectories (reasoning, code, observations) that serve as training data for downstream fine-tuning.

## Method

DSGYM introduces a manager-worker containerized architecture where a central orchestrator allocates fresh isolated Docker containers (each hosting an independent Jupyter kernel) per trajectory, enforcing strict filesystem separation (read-only data volumes vs. writable workspace) and per-container resource limits. The agent interface follows a CodeAct-like protocol with structured tags for reasoning, executable Python code, and final answers, decoupling model evaluation from scaffold design. To address shortcut solvability, the paper runs five LLMs from different families on each task without data access and excludes any task where a majority (≥3) answer correctly, retaining only tasks that genuinely require execution-grounded reasoning. The task ecosystem expands beyond refined existing benchmarks (QRData, DAEval, DABStep, MLEBench-Lite) with two novel suites: DSBIO (90 expert-derived bioinformatics tasks grounded in peer-reviewed publications) and DSPREDICT (92 Kaggle competitions split into easy/hard difficulty tiers). For training, an execution-verified synthetic data pipeline generates queries via an explore-and-validate agent, samples diverse trajectories at T=0.8, and filters query-trajectory pairs with an LLM judge across six execution-aware criteria, yielding a 2,000-example SFT corpus that lifts Qwen3-4B to competitive performance with GPT-4o on standardized analysis benchmarks.

## Results

On standardized general analysis benchmarks, Kimi K2 Instruct leads among open-source models (63.68% QRData-Verified, 92.82% DAEval-Verified), while Claude Sonnet 4.5 leads proprietary models on DABStep (83.33% easy, 37.04% hard). On the expert-derived DSBIO bioinformatics suite, even the best model (Kimi K2 Instruct) achieves only 43.33% accuracy, with 85–96% of failures attributed to domain-grounding errors. On DSPREDICT-HARD, medal rates are near 0% across nearly all models despite >60% valid submission rates, revealing a persistent simplicity bias where agents stop at runnable but under-optimized solutions.

## Baselines & Comparisons

Among proprietary models, Claude Sonnet 4.5 dominates DABStep (83.33% easy / 37.04% hard), substantially outperforming GPT-4o (73.61% / 7.41%) and GPT-5.1-high (73.61% / 13.23%) on multi-step financial reasoning. Kimi K2 Instruct is the strongest open-source model overall, leading QRData-Verified (63.68%) and DAEval-Verified (92.82%), and also topping DSBIO (43.33%) ahead of Claude Sonnet 4.5 (42.22%) and GPT-4o (33.33%). On DSPREDICT-HARD, GPT-5.1 (high) achieves the best valid submission rate (85.7%) and median rate (14.3%), but no model exceeds 4.8% medal rate, indicating that even frontier models fail to produce competitive ML solutions. The DSGYM-SFT-trained Qwen3-4B model (59.36% QRData, 33.07% DABStep-hard) outperforms GPT-4o on DABStep-hard by 25.7 points and on DABStep-easy by 4.2 points, though it trails GPT-4o on DAEval-Verified (86.19% vs. 92.26%) and DSBIO (21.11% vs. 33.33%). Smaller open-weight models (Qwen2.5-7B, Qwen3-4B base) lag far behind frontier models across all benchmarks, with DSBIO accuracy dropping to 4–7%.

## Relation to Prior Work

This paper builds on the CodeAct agent paradigm (Wang et al., 2024b) for its default interaction interface and positions itself as a unifying infrastructure over a fragmented landscape of data science benchmarks (DS-1000, DAEval, QRData, DABStep, MLE-Bench, DiscoveryBench, DSBench). Its key conceptual departure is challenging the implicit assumption that file-grounded tasks necessarily measure data-dependent reasoning, introducing a shortcut-solvability filter that removes tasks answerable without data access. It extends the evaluation scope beyond general statistics into domain-specific scientific workflows (DSBIO) and end-to-end competitive prediction (DSPREDICT), while also repurposing the execution environment for training data synthesis—a dual-use design not present in prior static benchmarks.

## Why It Matters / Open Questions

The shortcut-solvability finding (up to ~21% relative accuracy drop when data is withheld) undermines the validity of several widely-used benchmarks and should prompt the community to re-audit existing evaluations. The persistent domain-grounding gap on DSBIO (85–96% of frontier-model failures) and the simplicity bias on DSPREDICT-HARD (valid submissions >60% but near-zero medals) reveal that current agents lack the skeptical, iterative refinement behavior of expert data scientists. Open questions include whether RL training in this environment can close the domain gap, whether the construction pipeline generalizes beyond bioinformatics, and how to evaluate open-ended or visualization-centric scientific tasks that resist deterministic scoring.
