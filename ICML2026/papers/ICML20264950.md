## Problem

Current software engineering agents trained with RL rely heavily on human-curated issue descriptions, test suites, and test commands, which limits scalability and prevents the open-ended self-improvement needed for superintelligence. The paper asks whether a single LLM can autonomously generate and solve increasingly complex bugs grounded in raw codebases, using only sandboxed environments as input, without any human-labeled data.
![Teaser figure](../imgs/ICML20264950/cropped_page1_idx0.webp)

## Input / Output

The only required input is a pre-built Docker image containing a source repository and its installed dependencies—no test parsers, existing tests, test commands, issue descriptions, or language-specific infrastructure are assumed. The bug-injection agent must discover how to run tests and create all verification artifacts through environmental interaction. The solver receives only the reversed test-weakening patch (a formal diff specifying required behavior) as its task description, not a natural-language issue. Outputs include a five-file bug artifact (test script, test file list, test parser, bug-injection diff, test-weakening diff), a repair patch in git diff format, and a jointly updated LLM policy.

## Method

SSR instantiates a single 32B LLM policy (CWM-sft) in two roles—bug-injector and bug-solver—trained jointly via RL. The injector explores the sandboxed repository, discovers the test suite, and produces a bug artifact validated through seven consistency checks (including inverse mutation testing); the solver sees only the reversed test-weakening patch and must produce a repair patch that passes all oracle tests. Higher-order bugs are constructed from the solver's own failed repair attempts, creating layered, realistic failure patterns. The injection reward targets an optimal solve rate (~0.2) to encourage challenging-but-solvable bugs, while the solve reward is binary (all tests pass or not). Two bug-injection strategies—code hunk removal and git-history reversion—are used to generate diverse, non-trivial bugs, and the entire system is trained for 150 RL steps (~2.5B tokens) on 512 H100 GPUs.

## Results

On SWE-bench Verified (500 human-verified issues) and SWE-Bench Pro (731 enterprise-level tasks), SSR achieves steady self-improvement of +10.4 and +7.8 resolve-rate points respectively over the course of 150 training steps (~2.5B tokens), starting from the CWM-sft pre-RL checkpoint. SSR consistently outperforms the human-data baseline (CWM's agentic RL with curated issue descriptions and test suites) across the entire training trajectory on both benchmarks. Evaluation uses one attempt per problem with temperature=1.0 and top-p=0.95, with no parallel test-time scaling or ranking.

## Baselines & Comparisons

The paper compares SSR against two baselines: the CWM-sft base model (pre-RL checkpoint) and a 'baseline RL' that uses the same environment images and hyperparameters but receives human-authored issue descriptions, pass-to-pass/fail-to-pass tests, and evaluation scripts (following CWM's standard agentic SWE-RL setup). SSR outperforms the human-data baseline on both SWE-bench Verified and SWE-Bench Pro throughout the entire training trajectory, indicating that self-generated bug tasks provide richer learning signals than human-curated data. The base model (CWM-sft) serves as the starting point for both SSR and baseline RL, and both methods improve over it, but SSR's improvement is consistently larger. Ablations further show that self-play (joint bug injection + repair) outperforms both injection-only and repair-only variants, confirming that the evolving curriculum from self-play is essential for sustained gains.

## Relation to Prior Work

SSR extends the self-play paradigm from game-theoretic settings (AlphaZero) and zero-data reasoning (Absolute Zero, R-Zero) into grounded software engineering, building directly on CWM's agentic RL infrastructure and SWE-RL's verifiable-reward framework. Unlike prior synthetic bug-generation pipelines (SWE-smith, BugPilot) that still assume access to test suites, parsers, or teacher-model distillation, SSR requires only raw Docker images with source code and dependencies, making the bug-injection agent responsible for discovering test infrastructure through environmental interaction. The reward design for the bug-injection role is adapted from Absolute Zero's solve-rate-based formulation, while the corpus-grounded self-play philosophy follows SPICE's insight that interaction with external environments outperforms pure introspection.

## Why It Matters / Open Questions

The finding that self-generated bugs consistently outperform human-curated issue descriptions and test suites throughout training challenges the assumption that human expertise in data curation is a necessary bottleneck for SWE agent improvement, pointing toward a scalable path toward superintelligent software agents. However, the paper's own theoretical analysis reveals that the challenger-solver game admits dominant strategies (e.g., obfuscated fail-randomly tests) that can halt self-play progress, and the authors acknowledge training instability at scale, the absence of hidden test splits (reward-hacking risk), and the restriction to unit-test verification. Open questions include whether the approach scales to larger MoE models, whether separate policies for injection and solving help, and how to handle multi-step software tasks beyond single-bug repair.
