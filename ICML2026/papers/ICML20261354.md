## Problem

LLM serving frameworks like vLLM and SGLang frequently introduce silent errors where output quality degrades (accuracy regressions, garbage outputs) without triggering any runtime errors or warnings. Diagnosing these errors is notoriously difficult because the semantic gap between high-level symptoms and low-level root causes spans the entire model stack, and existing fault localization techniques rely on explicit pass/fail signals that are absent here. Developers currently resort to laborious manual differential debugging against reference implementations, with no automated pipeline to align intermediate states across heterogeneous frameworks.

## Input / Output

EKKA takes as input a buggy target framework (e.g., vLLM), a semantically correct reference framework (e.g., HuggingFace Transformers), a specific model, benchmark prompts, and framework configurations. It parses both codebases into model trees and code indices, then collects activation traces and call sequences via PyTorch forward hooks during bug reproduction. The output is a ranked report of the top-3 suspected buggy components at the PyTorch module level, accompanied by reasoning explaining why each component is implicated.

## Method

EKKA frames silent error diagnosis as differential debugging via a three-stage LLM-agent pipeline (powered by Claude Sonnet 4.5 through LangGraph). First, Component Mapping builds compressed Model Trees from both frameworks and iteratively maps semantically equivalent sub-modules despite naming and structural differences, using a code-index tool to inspect class definitions and a validation loop to ensure completeness. Second, Activation Alignment generates executable Python postprocessing code to reconcile tensor shape, dtype, and layout mismatches between mapped component pairs, aided by helper tools (tensor sum matching, element sampling) and a knowledge base of validated alignment examples from correct implementations. Third, Error Analysis computes a robust error ratio that normalizes the target's deviation by the reference's own precision error (separating true bugs from BF16/FP8 numerical noise), then applies a sustained-elevation change-point heuristic to identify the earliest component where the error ratio permanently shifts upward, isolating the root cause from downstream propagation.

## Results

On a benchmark of 17 real-world silent errors from vLLM and SGLang, EKKA achieves 84% pass@1 and 88% pass@5 diagnosis accuracy, outperforming Mini-SWE-Agent (60%/66%) and OpenCode (48%/66%) by 24–34% across both metrics. The average diagnosis cost is approximately $30 per case (4.03M input tokens, 304K output tokens with Claude Sonnet 4.5). EKKA also diagnosed 4 new silent errors in vLLM and SGLang, all confirmed by developers.

**End-to-end diagnosis accuracy on the 17-bug silent error benchmark (Claude Sonnet 4.5 backend).**

|---|---|---|
| OpenCode | 0.48 | 0.66 |
| Mini-SWE-Agent | 0.60 | 0.66 |
| **EKKA** | **0.84** | **0.88** |

## Baselines & Comparisons

EKKA is compared against two state-of-the-art software engineering agents: Mini-SWE-Agent (Yang et al., 2024b) and OpenCode (2026), both of which perform repository-level code analysis and debugging without EKKA's specialized differential-diagnosis stages. EKKA wins decisively on both metrics: it achieves 0.84 pass@1 versus 0.60 for Mini-SWE-Agent (+28%) and 0.48 for OpenCode (+34%), and 0.88 pass@5 versus 0.66 for both baselines (+24% and +30% respectively). The gap is most pronounced on subtle bugs like vLLM-17689 (sliding-window attention misuse), where EKKA achieves 5/5 successful diagnoses while Mini-SWE-Agent manages only 1/5 and OpenCode 0/5. Even under a weaker backbone (Claude Haiku 4.5), EKKA retains a substantial lead (0.67/0.77 vs. 0.31/0.66 and 0.27/0.55), indicating the advantage comes from the diagnosis pipeline rather than backbone capability alone.

## Relation to Prior Work

EKKA repurposes the differential debugging paradigm—comparing a target against a semantically correct reference implementation—but elevates it from API-level output comparison (as in prior deep learning differential testing) to fine-grained intermediate activation alignment across heterogeneous serving frameworks. It combines LLM-agent-based code analysis (in the spirit of SWE-agent and OpenCode) with domain-specific scaffolding (component mapping, activation alignment, change-point analysis) that general-purpose software engineering agents lack. The change-point detection for error localization draws on classic statistical methods (Page's CUSUM, Bayesian online changepoint detection), while the robust error ratio metric is inspired by prior distributed training error-checking work (TTrace). No single prior system addresses the full pipeline of automated silent-error diagnosis in LLM serving frameworks.

## Why It Matters / Open Questions

LLM serving frameworks are critical production infrastructure, and silent errors that degrade output quality without triggering any error signal can go undetected for months, as the paper's motivating example (vLLM-17689) illustrates. EKKA's practical validation—diagnosing 4 new real-world bugs confirmed by developers at ~$30 per case—demonstrates that automated differential diagnosis is viable for this domain. Key limitations include: it targets only model-stack bugs (not orchestration, concurrency, or hardware issues), requires a semantically correct reference implementation, operates at PyTorch module granularity, and is currently PyTorch-specific. Open questions include extending to function/line-level localization, supporting non-PyTorch stacks (JAX/Flax), and reducing cost through smaller backbones or stronger caching.
