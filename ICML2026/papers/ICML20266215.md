## Problem

Existing multi-task neural routing solvers either enumerate VRP variants through a predefined set of constraint tags (bounding coverage by the manually specified attribute set) or require per-problem adapter fine-tuning (preventing zero-shot generalization). No single neural model has been shown to solve over 100 VRP variants without retraining, and the open-ended, compositional constraint space of VRPs makes exhaustive problem taxonomy impractical.
![Teaser figure](../imgs/ICML20266215/cropped_page2_idx0.webp)

## Input / Output

Each VRP instance is encoded as a unified data representation (UDR) where every node carries a 3-dim positional identifier (random scalar for asymmetry + 2D coordinates), a 6-dim unified attribute vector (demand, prize, penalty, earliest/latest arrival time, service time), and a 5-dim binary node-type indicator (depot, pickup, delivery, sub-route, open-route). A 13-dim multi-hot problem representation λ is derived by marking which feature slots are active, providing conditional signals to the decoder. The model outputs a node permutation (routing solution) constructed autoregressively, with a model-agnostic masking function enforcing problem-specific constraints (capacity, time windows, precedence) at each decoding step.

## Method

URS builds on the AM encoder-decoder architecture but introduces three key mechanisms for cross-problem zero-shot generalization. First, the Unified Data Representation (UDR) replaces discrete problem tags with a shared continuous+discrete feature space, so new VRP variants are incorporated by simply populating relevant attribute slots rather than defining new problem types. Second, the Mixed Bias Module (MBM) replaces vanilla self-attention in the encoder with three parallel attention computations over the outgoing distance matrix D, incoming distance D^T, and an optional relation matrix R (for pickup-delivery pairing), concatenated and projected to capture multiple geometric priors in a single layer. Third, a problem-conditioned parameter generator uses the multi-hot representation λ to produce decoder weights W_Q, W_K, W_V via a lightweight MLP hypernetwork (WEIGHT(λ)) and a scalar bias weight α via BIAS(λ), enabling adaptive decoding without per-problem adapters. The model is trained with REINFORCE on 11 mixed VRP variants (N=100) and evaluated zero-shot on 99 unseen variants up to 7000 nodes.

## Results

URS achieves zero-shot generalization across 110 VRP variants (11 seen + 99 unseen) with a single model trained on only 11 problems. On the Set-AGS benchmark (N=3000–7000), URS attains a 13.29% average gap and is the only method that scales to all four instance sizes without OOM, outperforming the best generalist (ReLD-MTL, 17.00% on N=3000, OOM beyond) and specialist solvers (LEHD 22.22%, BQ 23.34% avg gap). On unseen VRP variants (Table 4), URS consistently beats MVMoE, MTPOMO, and ReLD-MTL, and even surpasses the oracle solver on several problems (e.g., SPCTSP −2.37%, PDCVRP −1.47%, AOP −5.47% gap). On large-scale synthetic instances (N=1000–5000), URS achieves the best gap among all multi-task neural solvers (e.g., 15.04% on CVRPTW N=1000 vs. MTPOMO 37.57%, MVMoE 46.55%).

## Baselines & Comparisons

URS outperforms all multi-task generalist baselines (MVMoE, MTPOMO, ReLD-MTL, GOAL, RouteFinder, CaDA) on both unseen VRP variants and large-scale instances; for example, on MDCVRP (unseen) URS achieves 15.05% gap vs. MVMoE 33.06% and MTPOMO 23.38%, and on Set-AGS URS is the only method that completes all four scales (N=3000–7000) while every other generalist hits OOM at N≥6000. Against specialist solvers, URS (13.29% avg) beats LEHD (22.22%), BQ (23.34%), and POMO (460.32% on Leuven1) on Set-AGS, and URS-STL (single-task variant) achieves the lowest gap on 8 of 11 seen VRPs, surpassing ICAM, MatNet, and Sym-NCO. On the seen-problem comparison (Tables 2–3), URS-STL dominates (e.g., 0.11% on OP100 vs. Sym-NCO 0.68%, BQ 0.63%), while the multi-task URS shows a modest degradation (e.g., 0.45% on OP100) but remains competitive. URS also beats the classical PyVRP solver on large-scale CVRPB (N=1000: URS 5.48% vs. PyVRP 8.30% gap) and matches OR-Tools on several variants. Notably, on several unseen problems URS surpasses the oracle solver (negative gap), a result no baseline achieves.

## Relation to Prior Work

This paper builds on the AM encoder-decoder architecture (Kool et al., 2019) and the adaptive attention mechanism from Zhou et al. (2026a), extending them with a mixed bias module (MBM) that captures symmetric, asymmetric, and relational distance priors in a single unified attention computation. It departs from the dominant multi-task VRP paradigm—where prior work (MTPOMO, MVMoE, RouteFinder, CaDA) enumerates problems via predefined constraint tags or requires adapter-based fine-tuning (GOAL, TSP-FT)—by replacing problem enumeration entirely with a unified data representation (UDR) that encodes all VRP variants in a shared continuous/discrete feature space. The problem-conditioned hypernetwork for decoder parameter generation draws on the hypernetwork literature (Ha et al., 2016) and the POMO instance-augmentation strategy (Kwon et al., 2020), but applies them in a zero-shot setting where no per-problem adapters exist.

## Why It Matters / Open Questions

URS establishes a practical path toward a single neural solver that handles an open-ended space of VRP variants without requiring domain experts to maintain a problem taxonomy or to fine-tune for each new constraint combination—a significant reduction in deployment friction for logistics applications. The UDR framework is extensible: new VRP variants can be incorporated by simply populating the unified attribute slots, making the approach a potential foundation for a 'routing foundation model.' Key limitations remain: the training scheme treats all 11 problems equally despite vastly different complexity, performance on unseen asymmetric+PD variants still shows 10–25% gaps, and the method does not address dynamic or stochastic VRPs. Whether the UDR paradigm transfers beyond VRP to other combinatorial optimization families (e.g., scheduling, assignment) is an open question.
