## Problem

Current reinforcement learning methods for code generation are predominantly optimized on Python, showing weak generalization to other programming languages. Naively extending RL to multiple languages independently scales computational costs linearly, causes optimization imbalance toward languages with denser rewards, and fails to exploit the semantic alignment of parallel multilingual solutions for knowledge transfer from high-resource to low-resource languages.
![Teaser figure](../imgs/ICML20260433/cropped_page0_idx0.webp)

## Input / Output

The model receives a natural-language competitive programming problem description (in Stdio input/output format) along with a target programming language specification, and generates an executable code solution. During training, for each problem the policy rolls out 4 candidate solutions per language across 8 PLs (Python, Java, C++, JavaScript, Go, PHP, Ruby, Perl), yielding 32 multilingual samples per group. Rewards are scalar unit-test pass rates in [0,1] computed by executing generated code in a sandbox against language-agnostic test cases, and evaluation uses Pass@1 averaged over 4 runs on the Multilingual LiveCodeBench (ML-LCB) benchmark.

## Method

GXPO extends GRPO by decomposing each response's advantage into three complementary signals computed from multilingual rollouts: (1) a Monolingual Advantage that z-scores rewards within the same language across the entire batch to preserve language-specific variance; (2) a Cross-lingual Advantage that z-scores rewards across all languages for the same question to enforce global competitiveness; and (3) a Multilingual Group Advantage that computes the expected reward of an idealized group formed by sampling one response per language, capturing collective multilingual synergy. The three advantages are combined as a weighted sum (λ₁=0.6, λ₂=0.2, λ₃=0.2) and plugged into a standard GRPO-style clipped policy gradient objective with sequence-level likelihood ratios. This decomposition allows the policy to simultaneously optimize intra-language consistency, inter-language competition, and cross-language cooperation without requiring separate per-language training runs or learned value functions.

## Results

On Multilingual LiveCodeBench (ML-LCB) v6, GXPO achieves average Pass@1 of 19.1% for Qwen3-4B-Base (+4.1% over GRPO's 15.0%), 22.6% for Qwen2.5-Coder-7B-Instruct (+0.8% over GRPO's 21.8%), and 14.8% for LLaMA-3.1-8B (+3.2% over GRPO's 11.6%). Gains are most pronounced on low-resource PLs (Go, PHP, Ruby, Perl), where GXPO narrows the High-vs-Low language gap substantially (e.g., LLaMA-3.1-8B: High 14.8% vs. Low 14.8% for GXPO, compared to 13.0% vs. 10.2% for GRPO). On ML-LCB v5, improvements are more modest (+1.8% to +2.4% average) but still consistent across all three base models.

## Baselines & Comparisons

The sole baseline is standard GRPO (Shao et al., 2024) with the same total rollout budget (32 samples per problem). GXPO wins on average Pass@1 across all three base models on both ML-LCB v5 and v6, with the largest margins on Qwen3-4B-Base (+4.1% on v6) and LLaMA-3.1-8B (+3.2% on v6). The advantage is concentrated on low-resource PLs: for LLaMA-3.1-8B on v6, GRPO collapses to 0.0% on Perl while GXPO reaches 14.4%, and the High-vs-Low gap shrinks from 2.8 points (GRPO) to 0 points (GXPO). On Qwen2.5-Coder-7B (v6), gains are smaller (+0.8% average) because GRPO already performs well on high-resource PLs, but GXPO still improves the Low-PL average by +1.6 points. GRPO also exhibits training instability (visible in per-language curves for Perl and Go), whereas GXPO maintains more stable and balanced per-language trajectories throughout training.

## Relation to Prior Work

This paper extends GRPO (Shao et al., 2024), which replaced learned value functions with group-normalized baselines, from single-language (Python) rollouts to multilingual cooperative optimization. The monolingual advantage component follows the batch-level normalization strategy of REINFORCE++ (Hu et al., 2025), while the cross-lingual and multilingual group advantages are novel decompositions that exploit the parallel structure of solving the same problem in multiple languages. The work also builds on LiveCodeBench (Jain et al., 2025) by extending its time-evolving evaluation protocol to 8 programming languages, and positions itself against the broader RLVR paradigm where verifiable rewards (unit test pass rates) replace learned reward models.

## Why It Matters / Open Questions

The paper addresses a practical gap: RL-based code generation has been almost exclusively Python-centric, yet real-world software spans many languages. The three-way advantage decomposition (monolingual, cross-lingual, group) offers a principled way to balance language-specific specialization against cross-language transfer, and the ML-LCB benchmark provides the first unified multilingual evaluation platform. Limitations include testing only on 4B–8B models, 8 languages, and a single training dataset; whether the approach scales to larger models, more languages, or languages with fundamentally different paradigms (e.g., functional vs. imperative) remains open. The observation that GRPO's Perl performance collapses to 0% while GXPO maintains 14.4% highlights a real instability in naive multilingual RL that practitioners should be aware of.
