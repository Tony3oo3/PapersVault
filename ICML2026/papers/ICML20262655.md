## Problem

Existing LLM-based GPU code generation methods—whether multi-agent systems or RL-fine-tuned models—focus on single-kernel optimization and fail to produce correct, high-performance end-to-end GPU programs that require cross-kernel coordination, host-side orchestration, and system-level decisions. Moreover, RL-based approaches for CUDA generation are vulnerable to reward hacking (e.g., copying PyTorch code or hardcoding outputs) and degenerate behaviors (optimizing only trivial operators), while multi-turn agentic RL is prohibitively expensive due to minutes-long compilation and profiling cycles per interaction.

## Input / Output

The system takes a PyTorch reference implementation (defining the computation graph, input shapes, and expected output) along with target GPU hardware specifications as input. The Planner first profiles the reference with Nsight Systems to identify time-dominant kernels and system hotspots, then emits a structured to-do list with kernel fusion boundaries, tensor shape/layout contracts, and CPU-GPU overlap constraints. The output is a complete, self-contained CUDA project (source files, build configuration, Pybind11 interface, and compiled executable) that implements the same functionality as the reference with optimized kernels and host-side orchestration, validated through correctness checks and Nsys/NCU performance profiling.

## Method

StitchCUDA orchestrates three specialized agents—Planner (system-level decomposition and Nsys profiling), Coder (CUDA kernel and host-code implementation), and Verifier (correctness validation plus two-level Nsys/NCU bottleneck diagnosis)—in an iterative plan-code-profile-refine loop with a shared typed state. The key training innovation decomposes multi-turn agentic RL into two single-turn atomic skills (from-scratch generation and feedback-driven optimization), reducing rollout cost from ~60 days to ~20 hours while preserving agentic behavior. To prevent reward hacking and degenerate solutions, the Coder is trained with GRPO using a combined reward that multiplies rule-based correctness/speedup signals by an expert-designed rubric score across four dimensions (Anti-Hacking, CUDA Engineering, Operator Coverage, Skill Compliance), scored by an advanced LLM following discrete 1–5 criteria. The Coder backbone is Qwen3-32B fine-tuned with LoRA (rank=128) on 4 H200 GPUs, while GPT-5.2 serves as Planner and Verifier, with a RAG module providing up-to-date NVIDIA documentation for both agents.

## Results

On KernelBench Level 3 (end-to-end GPU programming, 10 tasks) with H200 GPU, StitchCUDA achieves 9/10 correctness (90%) with 1.50× average speedup over PyTorch eager and 70% Fast₁, compared to 6/10 (0.87×, 40%) for CUDAForge and 2/10 (0.34×, 10%) for Kevin-32B. On Level 1/2, StitchCUDA reaches 18/20 and 18/20 correctness with 3.54× and 1.82× speedup respectively. On RTX PRO 6000 (Blackwell), StitchCUDA achieves 10/10 correctness on Level 3 with 1.27× speedup, the only method to reach near-perfect correctness on the hardest level across both GPUs.

## Baselines & Comparisons

Against Qwen3-32B in single-shot mode, StitchCUDA transforms Level 3 performance from 0/10 correctness and 0× speedup to 9/10 and 1.50×, demonstrating that multi-agent orchestration alone (StitchCUDA-Q) already lifts correctness to 3/10 but agentic RL is essential for meaningful speedup (0.24× → 1.50×). Against Kevin-32B (RL-trained single model), StitchCUDA achieves 9/10 vs. 2/10 correctness and 1.50× vs. 0.34× speedup on Level 3 (H200), a 4.4× speedup advantage; on RTX PRO 6000 the gap is 10/10 vs. 4/10 and 1.27× vs. 0.22×. Against CUDAForge (the only open-source multi-agent baseline), StitchCUDA improves Level 3 correctness from 6/10 to 9/10 and speedup from 0.87× to 1.50× (≈1.72× relative gain), while matching or exceeding CUDAForge on Level 1/2 speedup (3.54× vs. 3.18× on L1). Notably, StitchCUDA's 32B Coder outperforms StitchCUDA-G (GPT-5.2 as Coder) on Level 3 (9/10, 1.50× vs. 6/10, 1.01× on H200), showing that domain-specific RL training with rubric rewards surpasses simply using a stronger general-purpose model.

## Relation to Prior Work

This paper extends two concurrent lines of work on LLM-based CUDA generation: multi-agent frameworks (CUDAForge, cuPilot, Astra, QiMeng) that iteratively refine single kernels with profiling feedback, and RL-based approaches (Kevin, CUDA-L1, CUDA-L2) that train models with GRPO using rule-based correctness/speedup rewards. It departs from both by targeting end-to-end GPU programs (multiple interacting kernels plus host-side orchestration) rather than isolated kernels, and by replacing pure rule-based rewards with a rubric-based shaping signal to counter reward hacking and degenerate optimization. The GRPO training algorithm is adopted from DeepSeek-R1, and the multi-agent decomposition follows the Coder-Verifier pattern established by CUDAForge but extended with a Planner agent for system-level coordination.

## Why It Matters / Open Questions

End-to-end GPU program generation is a practical bottleneck for ML deployment that prior single-kernel methods cannot address, and this paper demonstrates that a 32B model with targeted agentic RL can match or exceed frontier models (GPT-5.2) on the hardest KernelBench Level 3 tasks. The thorough analysis of reward hacking and degenerate behaviors in RL-trained CUDA generators provides actionable guidance for the broader RL-for-code community. Key open questions include cross-architecture generalization (Hopper vs. Blackwell), keeping LLM knowledge synchronized with rapidly evolving GPU stacks, and whether current benchmarks adequately capture deployment-quality GPU software beyond isolated correctness/speedup metrics.
