## Problem

Current LLMs fail catastrophically at parallelizing code for irregular data structures (sparse graphs, unbalanced trees, non-uniform meshes), producing code riddled with race conditions, deadlocks, and poor scaling due to a strong sequential bias from training on standard GitHub code. The core gap is that no existing system combines domain-specific fine-tuning on verified parallel primitives with an execution-feedback-driven evolutionary search to close the last mile of correctness and performance for irregular parallel algorithms.

## Input / Output

The system takes a natural language problem description (e.g., a graph traversal or sparse matrix operation) along with ParlayLib or Rust RPB primitive documentation as context, and produces a complete, compilable parallel C++ or Rust program. During the evolutionary refinement stage, the agent additionally consumes compiler error logs, ThreadSanitizer reports, and runtime performance profiles from five stress-test rounds on inputs of ~10 million vertices as fitness signals. The output is validated exclusively by deterministic external tools (compilers, unit tests, profilers) rather than LLM-based static analysis, and must satisfy both correctness (passing all tests) and a speedup objective relative to a sequential baseline.

## Method

ParEVO is a three-stage pipeline: (1) a Teacher-Student-Critic data synthesis loop that mutates 593 hand-authored ParlayLib seeds via type, constraint, and algorithmic operators, then rejects candidates that fail compilation or unit tests, yielding 13,820 verified instruction-tuning pairs; (2) supervised fine-tuning (LoRA SFT) plus Direct Preference Optimization on contrastive passing/failing triplets, applied to DeepSeek-6.7B, Qwen3-30B, and Gemini-2.5-Pro to internalize ParlayLib semantics and safe parallel Rust patterns; and (3) an Evolutionary Coding Agent that maintains a population of candidate programs, scores them with a fitness function combining test pass/fail and inverse runtime, and uses MAP-Elites (indexed by Levenshtein diversity and code length) to select survivors for the next generation. The key architectural insight is grounding the model in high-level work-span primitives (parlay::scan, filter, reduce) rather than low-level threading, which aligns the optimization objective with Transformer token-local prediction and makes generated code correct by construction, while the ECA treats compilers and hardware profilers as deterministic adversarial critics to sidestep the unreliable LLM-as-judge paradigm.

## Results

On the ParEval benchmark (59 problems), Gemini-2.5-Parlay achieves an average Speedup@1 of 107.43× (arithmetic mean) and a geometric mean of 6.33×, with Build@1 of 0.81 and Pass@1 of 0.58, substantially outperforming Gemini-3-Pro (Speedup@1 AM = 3.68×, Build@1 = 0.25) and GPT-5-Thinking (Speedup@1 AM = 0.43×, Pass@1 = 0.05). The smaller DeepSeek-Parlay (6.7B) also surpasses all commercial models with a Speedup@1 AM of 126.16×. Against expert human baselines (PBBSBench/RPB), ParEVO matches or exceeds performance, reaching up to 4.1× speedup on Maximal Independent Set and 2.7× on Histogram.

## Baselines & Comparisons

Against the expert human-written PBBSBench (C++) and RPB (Rust) baselines, ParEVO matches or exceeds performance on all six evaluated problems. The most dramatic wins are on Maximal Independent Set (Rust), where ParEVO achieves a 4.1× speedup over the RPB baseline by identifying a superior parallel strategy, and on Histogram (C++), where it reaches 2.7× over PBBSBench. On the remaining problems (Maximal Matching, Minimum Spanning Forest in both languages, Spanning Forest), ParEVO achieves modest 1.06×–1.31× speedups, confirming it matches expert-level performance. In the ParEval comparison against commercial LLMs, the fine-tuned models decisively outperform GPT-5-Thinking and Claude Opus 4.5 (both with Pass@1 ≈ 0.05 and Speedup@1 < 1×), and also surpass Gemini-3-Pro, which suffers a very low Build@1 of 0.25 despite being a larger model.

## Relation to Prior Work

This paper sits at the intersection of LLM-based code generation for HPC (ParEval, OMPGPT, AutoParLLM, UniPar) and evolutionary/agent-based program optimization (AlphaEvolve, OpenEvolve, AlgoTune). It departs from prior parallel code generation work by targeting the qualitatively harder regime of irregular data (graphs, sparse matrices) through high-level Work-Span primitives (ParlayLib) rather than low-level threading or OpenMP pragmas, and by grounding the evolutionary agent's fitness function in deterministic compiler and hardware profiler feedback rather than LLM-as-judge or unit-test-only signals. The fine-tuning pipeline builds on Chaturvedi's HPC-Instruct approach but introduces a verified synthetic corpus (Parlay-Instruct) generated via a Teacher-Student-Critic mutation loop, and the evolutionary search adapts MAP-Elites quality-diversity search from OpenEvolve to the HPC domain.

## Why It Matters / Open Questions

The paper demonstrates that LLMs can generate parallel code for irregular data that matches or exceeds expert human baselines (e.g., 4.1× on Maximal Independent Set), a domain where prior LLMs failed catastrophically with race conditions and deadlocks. The identified 'alignment tax'—where fine-tuning improves correctness at the cost of peak speedup by steering models toward safe high-level primitives over risky atomics—is a useful diagnostic for practitioners choosing between reliability and raw performance. Key limitations include restriction to shared-memory multicore (no MPI/distributed), the high inference cost of the evolutionary agent, and 'confident hallucinations' in unfamiliar algorithmic domains, leaving open whether formal verification can be integrated into the evolutionary loop to constrain semantic errors.
