## Problem

As the web shifts toward provider-controlled interfaces where content is accessed through agent-mediated APIs rather than open webpages, there is no benchmark to evaluate how well a user agent can coordinate with multiple autonomous content agents to fulfill information needs. Existing web agent benchmarks (WebArena, Mind2Web) assess single-agent task completion but do not capture the multi-agent coordination demands of this emerging decentralized architecture, where the user agent has no direct corpus access and must interact with website-specific agents that each control their own information boundaries.

## Input / Output

The user agent receives a natural-language query (web search, QA, deep research) or a browsing history (web recommendation) along with descriptions of all 100 websites, but has no direct access to any document corpus. It must issue structured retrieval requests to content agents, each of which returns natural-language summaries plus full document contents scoped to its own website. Outputs are task-specific: ranked document identifier lists (web search, web recommendation), a concise short answer (QA), or a structured long report (deep research). The corpus comprises 18.4M documents across 100 websites drawn from ClueWeb22-B, with each website served by an independent content agent maintaining its own dense retrieval index.

## Method

AgentWebBench formalizes the Agentic Web as a decentralized information ecosystem with two agent types: a user agent that plans, selects websites, and synthesizes evidence, and 100 content agents that each perform retrieval within a single website domain using a MiniCPM-Embedding-Light dense index. The benchmark defines three coordination strategies of increasing autonomy: Tool_E (embedding-similarity website selection + tool-based retrieval, no agent communication), Tool_P (LLM-reasoned website selection + tool-based retrieval), and Multi-Agent (full agent-to-agent communication where both user and content agents reason autonomously over up to 15 turns). Four tasks span ranked retrieval (web search from MS MARCO, web recommendation from ORBIT) and open-ended synthesis (QA and deep research from DeepResearchGym), evaluated with IR metrics (NDCG, Recall), LLM-as-Judge accuracy, and report quality scores (KPR, KPC, Clarity, Insight). The paper's core empirical contribution is a systematic comparison across seven LLMs (Qwen3-4B through 80B-A3B, DeepSeek-V3.2, GPT-5-mini, Gemini-3-Flash) showing that decentralized coordination generally trails centralized retrieval but the gap narrows with model scale and reverses on QA, alongside analyses of traffic concentration, test-time scaling effects, interaction efficiency, and failure attribution between user and content agents.

## Results

Across seven LLMs and three coordination strategies, decentralized multi-agent coordination generally underperforms the centralized Classical baseline on web search (e.g., Gemini-3 Multi-Agent N@3 44.34 vs. Classical 52.21) and deep research, but the gap narrows substantially with model scale. On question answering, Multi-Agent coordination matches or exceeds Classical for the strongest models (Gemini-3: 67.92% Acc. for both Multi-Agent and Classical; GPT-5: 33.96% vs. 35.85%). Web recommendation remains extremely difficult, with near-zero N@3 (<1%) for nearly all methods. On deep research, Tool_E with Gemini-3 achieves the best KPR (65.17) and Clarity (89.37), while Multi-Agent with Gemini-3 achieves the lowest KPC (1.37).

## Baselines & Comparisons

The Classic IR baseline (Gao et al., 2023a), a non-agent embedding-based dense retriever, achieves N@3 47.86 and R@5 65.25 on web search. All LLM-based Classical (centralized) methods match or slightly exceed Classic IR on web search (e.g., Gemini-3 Classical N@3 52.21 vs. 47.86), confirming that LLM reranking adds modest value over pure embedding retrieval. However, every decentralized coordination strategy (Tool_E, Tool_P, Multi-Agent) falls below the Classical centralized baseline on web search for all models, with the largest gaps for smaller models (Qwen3-4B Multi-Agent N@3 26.80 vs. Classical 47.65, a 20.85-point deficit) and the smallest for Gemini-3 (Multi-Agent 44.34 vs. Classical 52.21, an 7.87-point gap). On question answering, the decentralized Multi-Agent strategy matches or surpasses Classical for the two strongest models: Gemini-3 Multi-Agent achieves 67.92% accuracy, tying Classical, while GPT-5 Multi-Agent (33.96%) trails Classical (35.85%) by only 1.87 points. On deep research, Tool_E with Gemini-3 achieves the highest KPR (65.17) and Clarity (89.37) among all methods, slightly edging out Classical (KPR 63.58, Clarity 83.56), suggesting that tool-based retrieval with a strong LLM can be competitive even without full agent-to-agent communication.

## Relation to Prior Work

This paper carves new ground by formalizing the Agentic Web as a decentralized multi-agent information-access problem, where a user agent must coordinate with website-specific content agents rather than directly querying a centralized corpus. It repurposes existing web benchmarks (MS MARCO, ORBIT, DeepResearchGym) and the ClueWeb22 corpus, but reframes them under access constraints that prior web-agent benchmarks (WebArena, Mind2Web) and multi-agent frameworks (AutoGen, ChatDev) do not model. The three coordination strategies (Tool_E, Tool_P, Multi-Agent) create a controlled ablation axis between embedding-based selection, LLM-reasoned selection, and full agent-to-agent communication, bridging the RAG literature and the emerging agent-protocol ecosystem (MCP, A2A, WebMCP).

## Why It Matters / Open Questions

As content providers increasingly gate information behind agent-facing interfaces, AgentWebBench provides the first systematic evaluation of whether decentralized coordination can match centralized retrieval, and under what conditions. The traffic-concentration finding—that multi-agent coordination funnels citations toward a small set of authoritative domains—raises concrete ecosystem concerns about discoverability for smaller content providers. Key open questions include whether the controlled, uniform-retrieval setting generalizes to heterogeneous real-world providers with different APIs, ranking objectives, and adversarial incentives, and whether adaptive interaction budgeting can close the remaining performance gap without the traffic-concentration side effect.
