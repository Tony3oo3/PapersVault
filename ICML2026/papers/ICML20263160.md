## Problem

LLMs generate SQL token-by-token, so at the time of producing the final query, the semantics of pending SQL components (subqueries, nested clauses, set operations) are invisible to the model. This 'semantic blind spot' causes errors in complex SQL generation, and existing RL-based Text-to-SQL methods optimize general reasoning without specifically addressing component-level visibility during generation.
![Teaser figure](../imgs/ICML20263160/cropped_page0_idx1.webp)

## Input / Output

The model receives a natural language question and a database schema, and produces a structured output: a complexity label (simple/moderate/challenging), optionally pre-generated SQL components enclosed in think tags (2 for moderate, 3 for challenging), and the final SQL query in answer tags. For simple queries, standard CoT reasoning is used without component pre-generation. The output format is enforced via a format reward, and the SQL is validated by execution against the target database.

## Method

The paper trains Qwen2.5-Coder-7B with GRPO using a composite reward of four types: (1) a Reasoning Steps Reward that incentivizes correct complexity classification and pre-generation of SQL components before the final query, (2) an AST Matching Reward that builds gold and predicted SQL abstract syntax trees (via SQLglot), normalizes them (removing aliases, sorting order-insensitive children), assigns IDF-weighted node scores to the gold tree, and computes reward via maximum connected subtree matching to capture structural correctness of local components, (3) an Execution Reward for syntax validity and result accuracy, and (4) a Format Reward for structured output. The key differentiator is the complexity-guided pre-generation paradigm—forcing the model to emit independent SQL fragments before the final query so their semantics become visible in context—combined with the AST-based matching that avoids false rewards from n-gram overlap (e.g., 'school, city' appearing under different parent nodes).

## Results

On BIRD-DEV, the method (Qwen2.5-Coder-7B) achieves 65.78% execution accuracy (EX) and 66.5 VES, outperforming all same-scale RL-based and SFT-based baselines. On SPIDER-SYN, it reaches 80.7% EX, setting a new SOTA among open-source models of comparable size. The model generalizes well: trained only on BIRD, it attains 83.0% EX on SPIDER-DEV and 84.4% on SPIDER-TEST, and maintains ~80% EX on both SPIDER-SYN and SPIDER-REAL robustness variants.

## Baselines & Comparisons

On BIRD-DEV, the method (65.78% EX) surpasses all same-scale 7B RL-based baselines: Reasoning-SQL (64.0%), Reward-SQL (62.32%), SQL-R1 (60.8%), Think2SQL (56.1%), and DPO (64.1%), as well as SFT-based methods like Omini-SQL-14B (64.2%) and SQL-O1 (63.4%). It also outperforms prompting-based MAC-SQL+GPT-4 (59.4%) and DAIL-SQL+GPT-4 (54.8%), though CHASE-SQL+Gemini-1.5 (73.0%) remains higher. On SPIDER-SYN, the method achieves SOTA at 80.7% EX, beating SQL-O1 (77.6%), Reasoning-SQL (78.7%), and Think2SQL (78.0%). On SPIDER-DEV, it is slightly below DAIL-SQL+GPT-4 (83.0% vs. 83.5%) and MAC-SQL+GPT-4 (86.7%), and on SPIDER-REAL it trails SQL-O1 (79.9% vs. 82.7%). In terms of efficiency, the method uses only 0.90k total tokens per sample with 5.08 s/step inference latency, far below MCTS-based Alpha-SQL (200.2k tokens, 377.1 s/step), while standard GRPO without the proposed rewards achieves only 63.89% EX.

## Relation to Prior Work

This paper extends the GRPO-based reinforcement learning paradigm for Text-to-SQL (as established by DeepSeekMath and adopted by Reasoning-SQL, SQL-R1, and Reward-SQL) by introducing a task-specific reasoning structure: SQL components pre-generation guided by complexity analysis. It departs from prior RL-based Text-to-SQL work, which optimizes general reasoning processes or uses n-gram matching for partial rewards, by explicitly modeling the semantic independence of SQL components and designing an AST-based maximum connected subtree matching reward that preserves structural information. The complexity evaluation borrows from Spider's component-based taxonomy, and the format reward follows DeepSeek-R1's design, but the core novelty lies in the pre-generation reasoning paradigm and the structural reward mechanism.

## Why It Matters / Open Questions

The 'semantic blind spot' framing provides a clear diagnosis of why autoregressive generation struggles with complex SQL: the model cannot leverage the semantics of components it has not yet generated. The AST matching reward is a principled improvement over n-gram matching for local component accuracy, and the complexity-guided gating avoids unnecessary reasoning overhead for simple queries. However, limitations remain: AST matching has limited generalization to semantically equivalent SQL variants, complexity misclassification (especially moderate→simple) still degrades performance, and incorrect pre-generated components can introduce noise. Open questions include whether LLM-as-judge or execution-based rewards could replace rule-based AST matching, and whether continuous complexity scoring could resolve boundary ambiguity between adjacent difficulty levels.
