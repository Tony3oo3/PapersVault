## Problem

Standard SMT solvers frequently fail to discharge separation logic verification conditions (VCs) even when correct loop invariants are provided, forcing verification engineers to manually construct proofs in interactive theorem provers. While LLMs have shown promise in general proof synthesis, no specialized approach or benchmark exists for the specific challenge of proving separation logic VCs that require both spatial (heap-structure) and pure (arithmetic) reasoning.
![Teaser figure](../imgs/ICML20264839/cropped_page3_idx0.webp)

## Input / Output

The method consumes a verification condition (a logical entailment P ⊢ Q in separation logic), the annotated C source code that generated it (providing semantic intent), and a domain lemma library with natural-language predicate explanations. It produces a complete Rocq proof script verified by the Rocq compiler, or a failure status if the repair budget is exhausted. The proof is generated in a single pass (whole-proof generation) rather than step-by-step, with iterative repair driven by Rocq compiler error feedback (up to k=10 rounds).

## Method

SPLIT combines two key components: (1) an LLM-friendly tactic library that decomposes aggressive automation tactics like entailer! into granular, single-effect operations (e.g., split_pure_spatial, cancel, sep_apply_l/r, pure_solve) so the LLM can predictably track proof-state transitions in its chain-of-thought without execution; and (2) a two-stage semantics-aligned workflow where Stage I focuses exclusively on spatial elimination (reducing heap predicates to emp ⊢ emp) and Stage II discharges the exported pure subgoals (arithmetic/list reasoning) using standard Rocq tactics. The LLM is prompted via in-context learning with the C source, lemma library, and target VC, generating the full proof script in one pass. An iterative repair loop between the LLM prover and Rocq verifier handles failures, with error feedback guiding revisions. This design addresses the core unpredictability problem: human-friendly tactics perform opaque multi-step simplifications that decouple the LLM's internal reasoning from the actual proof state.

## Results

On the full 288-VC SL-VC benchmark, SPLIT achieves a 66.0% Pass@1 pass rate with a repair budget of k=10, compared to 43.4% for the Human-Friendly Tactics baseline. On the 207-VC core subset used for external comparisons, SPLIT reaches 73.4% at k=10 and 17.4% even without repair (k=0). The metric is Pass@1 with repair: a VC is solved if Rocq verifies the generated proof within k iterative repair rounds.

| Method | Pass Rate |
|---|---|
| PALM | 14.0% |
| Rango | 7.7% |
| SPLIT (k=0) | 17.4% |
| SPLIT (k=10) | **73.4%**

## Baselines & Comparisons

SPLIT substantially outperforms both external baselines on the 207-VC core subset. Against PALM (14.0%), SPLIT at k=10 achieves 73.4%, a 59.4-percentage-point improvement; PALM's backtracking repair with CoqHammer is limited because human-friendly tactics cannot sufficiently decompose complex spatial goals before invoking the hammer. Against Rango (7.7%), SPLIT gains 65.7 percentage points; Rango's retrieval-augmented strategy struggles to generalize across the diverse spatial structures in separation logic VCs. Notably, even without any repair (k=0), SPLIT (17.4%) already exceeds both PALM (14.0%) and Rango (7.7%), indicating that the LLM-friendly tactic library and two-stage workflow produce higher-quality initial proofs rather than relying solely on iterative correction.

## Relation to Prior Work

This paper builds directly on QCP (Wu et al., 2025), a separation-logic-based C verification tool, by decomposing its human-friendly automation tactics (notably entailer!) into granular, LLM-predictable operations. It positions itself against two adjacent lines: (1) LLM-based Rocq provers like PALM and Rango, which target general-purpose theorem proving on mathematical benchmarks and are only weakly adapted to separation logic; and (2) LLM-based annotation generation (Lemur, AutoVerus, LIG-MM), which assumes SMT solvers can discharge VCs once invariants are produced—an assumption the paper argues collapses for heap-heavy code. The two-stage spatial/pure workflow is a novel architectural choice not present in prior LLM prover designs, motivated by the semantic structure of separation logic assertions.

## Why It Matters / Open Questions

The paper identifies and empirically confirms a critical gap in the verification pipeline: even with correct loop invariants, SMT solvers cannot discharge separation logic VCs for real-world heap-manipulating code, forcing expensive manual proof construction. SL-VC is the first benchmark specifically targeting this sub-problem with real-world system code (LiteOS, mini-gmp), and SPLIT's 66% pass rate demonstrates that LLM-assisted proof synthesis is now a viable automation path for this bottleneck. Key limitations include the 34% failure rate concentrated in arithmetic-heavy GMP VCs and BST deletion, and the framework's dependence on QCP's spatial/pure decomposition structure. Open questions include generalization to VST/Iris, handling of programs requiring relational Hoare logic, and whether the LLM-friendly tactic design principle transfers to other ITPs.
