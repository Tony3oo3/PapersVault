## Problem

Reinforcement learning for automated program repair is hampered by two compounding issues: execution feedback is inherently sparse (a patch either passes all tests or it does not, yielding a binary signal), and standard sequence-level reward assignment creates a severe credit-assignment problem where the model receives no information about which specific edits in a multi-line patch were beneficial or harmful. This leads to high-variance gradient estimates and inefficient learning, particularly for long patches where most tokens are formatting or context rather than actual code changes.

## Input / Output

The system takes a repository snapshot containing buggy code, a natural-language issue description, and a test harness as input, and produces a git-applicable unified diff patch (for repository-level benchmarks like SWE-bench and Defects4J) or complete repaired code (for function-level benchmarks). During PPO training, a patch-only format constraint is enforced: the model outputs only unified diff text without natural-language explanations, ensuring rewards reflect patch quality rather than explanation quality. The sequence-level reward model R_seq deliberately receives only the unified diff without bug context (patch-only scoring), which the paper shows outperforms context-conditioned variants by preventing spurious correlations with issue difficulty.

## Method

BOOSTAPR is a three-stage training pipeline on a Qwen2.5-Coder-32B backbone. Stage I performs supervised fine-tuning on execution-verified demonstrations (generated by Claude 3.5 Sonnet, filtered to ~35% that pass all tests) containing structured reasoning traces. Stage II trains two reward models from execution outcomes: R_seq uses a hybrid objective combining regression (for calibrated absolute scores) with pairwise preference (for correct relative rankings), while R_line learns a contrastive objective over edit-line spans labeled via a priority cascade that parses stack traces to attribute failure to specific spans (62% direct trace attribution, 27% function-level heuristics, 11% uniform fallback). Stage III runs PPO where R_seq provides the overall patch score and R_line redistributes it across tokens via temperature-controlled softmax over edit-line span weights, concentrating reward on critical edit regions while assigning zero to headers and context lines. The key architectural insight is that edit-line spans provide a language-agnostic intermediate granularity—finer than hunk-level, more stable than token-level or language-specific statement parsing—that naturally matches the semantic structure of code modifications.

## Results

BOOSTAPR (Qwen2.5-Coder-32B backbone) achieves 40.7% resolve rate on SWE-bench Verified (+22.9pp over the base model's 17.8%), 24.8% on Defects4J v2.0 (more than doubling the base model's 11.3% despite Java being absent from training data), 84.5% on HumanEval-Java (+20.5pp), and 95.0% on QuixBugs. The controlled same-backbone comparison shows PPO with sequence-level rewards alone contributes +14.9pp, while the line-level credit allocator R_line adds a further +2.4pp on SWE-bench Verified and +5.6pp on Defects4J. Across three seeds, full BOOSTAPR achieves 40.7±0.5% on SWE-bench Verified with a statistically significant R_line gain (p=0.012, 95% CI [+1.2, +3.6]pp).

## Baselines & Comparisons

On SWE-bench Verified, BOOSTAPR (40.7%) outperforms all agentic systems (Agentless 38.8%, SWE-agent 33.6%, AutoCodeRover 28.8%) and all fine-tuned models (SWE-Gym 32.0%, SWE-Fixer 33.0%, Lingma SWE-GPT 30.2%), while matching SWE-RL (41.0%) which uses a larger 70B backbone. On Defects4J v2.0, BOOSTAPR (24.8%) substantially outperforms every baseline, including RepairLLaMA (17.2%) and SWE-RL (16.8%), demonstrating strong cross-language transfer from Python training to Java. On HumanEval-Java, BOOSTAPR (84.5%) leads all baselines, exceeding SWE-RL (76.2%) and RLEF (74.3%). On QuixBugs, ChatRepair (100.0%) slightly edges out BOOSTAPR (95.0%), though the base model already reaches 90.0% on these simple single-line bugs. In the controlled same-backbone comparison (Table 2), BOOSTAPR beats GRPO by +4.6pp and rejection-sampling RL by +3.2pp on SWE-bench Verified, with larger margins on Defects4J (+8.4pp over GRPO, +7.2pp over RS-RL), confirming that the dual reward mechanism provides the largest gains under out-of-distribution transfer.

## Relation to Prior Work

This paper extends the RL-for-code-generation line (CodeRL, RLEF) by addressing the credit assignment problem that plagues sequence-level rewards in program repair. It departs from prior agentic APR systems (SWE-Agent, Agentless, SWE-RL) that focus on scaffolding or supervised fine-tuning, instead introducing a dual reward architecture where a line-level credit allocator redistributes sequence-level execution rewards across edit-line spans in unified diffs. The line-level granularity is positioned as an intermediate between token-level rewards (too fine for code) and hunk-level allocation (too coarse), drawing on the structure of unified diffs as a language-agnostic unit. The theoretical analysis connects to policy gradient variance reduction literature, formalizing why concentrating reward on informative spans reduces gradient variance by a factor proportional to the ratio of total to informative tokens.

## Why It Matters / Open Questions

The paper provides a practical, well-controlled demonstration that fine-grained credit assignment in RL for code repair yields measurable gains, particularly under cross-language transfer (Python→Java, +5.6pp from R_line vs. +2.4pp in-distribution). However, the primary accuracy driver remains PPO with sequence-level execution rewards (65% of total gain), positioning R_line as a complementary rather than transformative component. Key limitations include the partially heuristic supervision for R_line (only 62% of labels use direct stack-trace attribution), the approximate nature of edit-line spans as semantic units, and the modest absolute gains over strong baselines. Open questions include whether stronger fault localization or counterfactual patch evaluation could replace the noisy trace-derived labels, and whether the approach scales to larger models or multi-file patches with complex cross-file dependencies.
