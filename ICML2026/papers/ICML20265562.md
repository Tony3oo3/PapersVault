## Problem

While LLMs have been increasingly applied to reward design in reinforcement learning, the equally critical task of designing observation and action spaces remains underexplored and relies heavily on manual domain expertise. A further bottleneck is that LLM outputs are inherently stochastic, and prior selection methods (e.g., LESR) require training each candidate to near-convergence, consuming roughly 15× the budget of a single-model run to identify the best configuration.
![Teaser figure](../imgs/ICML20265562/cropped_page0_idx0.webp)

## Input / Output

The method consumes raw, high-dimensional environment states (e.g., 3,107+ dimensions from MuJoCo's mj.data API in HumanoidBench, 1,100+ from Isaac Lab's RigidObjectData API) along with a structured prompt containing the task description, variable index mappings, and actuator specifications. It produces two self-contained Python functions: compute_obs(data) that maps raw observations to a compact agent observation vector, and compute_action(action, data) that expands a low-dimensional latent action into the full actuator command vector. Notably, the action model can compress, preserve, or expand the original action dimensionality depending on task semantics, and both functions must be batch-safe and device-consistent for integration into the RL training loop.

## Method

LOAM leverages structured prompts (a shared System Prompt plus per-model Observation and Action Model Prompts) to guide GPT-5 in generating executable Python code that defines the observation mapping f^Ω: Ω_raw → Ω and action mapping f^A: A → A_raw, effectively decoupling the agent's learning interface from the raw environment. To handle LLM stochasticity, LOAM-Race introduces a continuous racing mechanism over K=3 candidate designs: at every 128K-timestep interval, Bayesian Ridge Regression extrapolates each candidate's return trajectory to estimate an upper confidence bound on predicted final performance, and the next training block is allocated exclusively to the candidate with the highest acquisition score (predicted mean + standard deviation). This Optimism-in-the-Face-of-Uncertainty strategy balances exploitation of currently strong models with exploration of uncertain ones, identifying the best configuration within the same cumulative timestep budget as a single-model training run—eliminating the 15× overhead of prior two-stage selection methods.

## Results

LOAM achieves 3× faster learning than the FastTD3 baseline across HumanoidBench stand, walk, and run tasks, while also reaching higher asymptotic returns. On the full 12-task HumanoidBench suite, LOAM outperforms both FastTD3 and LESR on all tasks except 'package,' where all methods struggle. On Isaac Lab (Lift-Cube, Open-Drawer, Repose-Cube), LOAM and LOAM-Race consistently surpass FastTD3 in both convergence speed and final performance. LOAM-Race identifies the best candidate within a single-model timestep budget (T), compared to LESR's 15.4×T total cost (18 candidates × 0.8T + 1T full training).

## Baselines & Comparisons

Against FastTD3 (standard RL with handcrafted 151-dim observations and 61-dim actions), LOAM wins decisively on learning speed (3× faster) and asymptotic performance across nearly all HumanoidBench and Isaac Lab tasks, by constructing compact, task-relevant observation spaces (e.g., 48-dim vs. 151-dim) and structured action spaces (e.g., 13-dim latent vs. 61-dim raw) directly from raw environment states. Against LESR (which appends LLM-generated features to handcrafted observations, doubling the observation dimensionality), LOAM wins on most tasks; notably, LESR actually underperforms FastTD3 on run, hurdle, slide, and push tasks, attributed to the high-dimensional feature space introduced by simply concatenating LLM features onto potentially suboptimal handcrafted observations. LOAM-Race further improves robustness over single-candidate LOAM by mitigating LLM stochasticity, achieving the highest asymptotic returns and superior consistency, while enabling smaller LLM backbones (e.g., Qwen3-Coder-30B) to match GPT-5 performance through competitive racing dynamics.

## Relation to Prior Work

This paper extends the LLM-for-RL line of work (EUREKA, Text2Reward) from reward design to the underexplored problem of observation and action space design, generating Python functions that map raw environment states to compact agent spaces. It departs from LESR, which appends LLM-generated features to handcrafted observations, by constructing entirely new representations from raw physical states. The selection mechanism adapts the Hoeffding racing / Optimism-in-the-Face-of-Uncertainty principle (Maron & Moore, 1993; Jamieson et al., 2014) to the RL training context, using Bayesian Ridge Regression to extrapolate return trajectories and allocate training budget dynamically, replacing the two-stage generate-then-train-to-convergence pipeline used by prior LLM+RL methods.

## Why It Matters / Open Questions

LOAM addresses a practical bottleneck in deploying RL to new robot embodiments: the manual feature engineering of observation and action spaces that currently requires domain expertise for each new task. The finding that LOAM-Race identifies the best configuration within a single-model timestep budget (vs. ~15× the cost of LESR's selection procedure) makes LLM-based environment design computationally viable. Open questions include whether the approach generalizes to environments where raw state is not directly accessible (e.g., vision-only), whether it scales to tasks with fundamentally different reward structures, and whether the reliance on structured API documentation limits applicability to non-simulated or proprietary systems.
