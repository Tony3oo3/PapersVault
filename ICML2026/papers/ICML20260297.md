## Problem

GPU exploitation in MIP has been hampered by the cost of CPU-GPU data transfer and the reliance on lightweight heuristics (limited simplex pivots, restricted variable subsets) for strong branching and optimization-based bound tightening. This paper asks whether these operations can be executed in full on GPUs by solving the underlying batches of LPs with a first-order method, rather than approximating them with CPU heuristics.

## Input / Output

The method takes a batch of N LPs sharing a common sparse constraint matrix A but differing in cost vectors and/or variable bounds. For full strong branching, only one bound entry changes per subproblem, so the full bound matrices are never materialized; for OBBT, the objective matrix is the block [I, −I]. The output is a batch of primal-dual LP solutions, which are then converted into branching scores (FSB) or tightened variable bounds (OBBT). Solved subproblems are dynamically removed from the active batch via column swapping, reducing kernel sizes as the batch progresses.

## Method

The core contribution is a batched extension of the primal-dual hybrid gradient (PDHG) algorithm with reflected Halpern iterations, where each column of the dense iterate matrices represents one subproblem with its own step sizes and primal weight. The key mechanism is that the expensive sparse matrix-vector products (Ax, Aᵀy) in standard PDHG become sparse-dense matrix-matrix products (AX, AᵀY) via cuSPARSE, whose cost is nearly independent of batch size (constant from 32 to 512 columns on tested hardware), making batching computationally almost free. Batch-level restarts are triggered by an averaged fixed-point residual across all columns, and per-column adaptive step sizes with exponential smoothing of the primal weight are maintained. The algorithm inherits the linear convergence rate of restarted Halpern PDHG for consistent batches (shared A, varying bounds/costs), and infeasibility detection is applied per-column using infimal displacement vectors.

## Results

For full strong branching (FSB), BATCHLP achieves speedups of 12.0×, 34.6×, 80.8×, and 488.5× over 8-thread cuOpt dual simplex on Combinatorial Auctions, Set Covering, Maximum Independent Set, and Facility Location instances respectively (Table 1). For optimization-based bound tightening (OBBT) on neural network verification instances, BATCHLP achieves an average 25.7× speedup over sequential Gurobi dual simplex (Table 2). On MIPLIB 2017, BATCHLP on an H100 GPU achieves speedups ranging from 0.6× (fiball) to 1251.7× (cod105) over 28-thread dual simplex, with the GPU winning on instances with large |S| and moderate matrix density (Table 3).

## Baselines & Comparisons

The primary baseline is cuOpt 26.02 multi-threaded dual simplex running on CPU (8–64 threads). BATCHLP dominates this baseline on all four FSB problem families, with speedups scaling from 12× (small Combinatorial Auctions) to 488× (large Facility Location with 241K constraints). CPU thread scaling saturates well below ideal: going from 8 to 64 threads yields only ~2.5× speedup, confirming the GPU advantage is not an artifact of a weak CPU baseline. For OBBT, the baseline is sequential Gurobi 13.0 dual simplex (single thread, no presolve); BATCHLP achieves a 25.7× average speedup, which the authors note is equivalent to what ~26 CPU threads would provide under ideal parallelism. On MIPLIB 2017, BATCHLP loses to 28-thread dual simplex on two instances (fiball at 0.6×, glass-sc at 0.9×) due to small |S| (518 and 202 subproblems) and unfavorable matrix geometry (wide-sparse and tall-dense respectively), confirming that the GPU advantage requires large batch sizes and moderate matrix density.

## Relation to Prior Work

This paper extends the restarted Halpern PDHG algorithm (Lu & Yang, 2024; Lu et al., 2025) from solving a single LP to solving a batch of LPs simultaneously by replacing sparse matrix-vector products with sparse-dense matrix-matrix products, a reformulation that unlocks GPU throughput via cuSPARSE. It departs from Nair et al. (2020), who used GPU-accelerated ADMM for strong branching only to collect training data for an ML branching model, by instead executing full strong branching to optimality on the GPU. It also differs from differentiable-optimization batch solvers (Agrawal et al., 2019; Lu et al., 2024) that rely on vmap-style vectorization and require data duplication, by designing the batched iteration natively around shared matrix-matrix operations with per-column step sizes and a unified restart criterion.

## Why It Matters / Open Questions

The paper demonstrates that GPU first-order methods can outperform multi-threaded CPU dual simplex by 12×–488× on strong branching and by ~26× on OBBT, but only in a specific regime (large batch size |S|, moderate matrix density, many simplex pivots per LP), and it is transparent about instances where the GPU is slower. The broader implication is that MIP solvers may need to restructure which subroutines run on which hardware rather than relying on lightweight CPU heuristics with work limits. Open questions include integrating BATCHLP into a commercial solver, designing hybrid simplex/BATCHLP strategies across the branch-and-bound tree, and extending the batching idea to cut generation.
