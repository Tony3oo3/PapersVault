## Problem

End-to-end speech-in/speech-out dialogue systems rely on static internalized knowledge, making them prone to hallucinations on factual queries. While text-based RAG mitigates this via external tools, integrating tool calls into spoken dialogue introduces multi-second latency that disrupts conversational flow, since prior approaches only issue retrieval queries after endpoint detection. The paper asks how to issue tool queries in parallel with ongoing user speech to mask retrieval latency without sacrificing answer quality.
![Teaser figure](../imgs/ICML20260121/cropped_page1_idx0.webp)

## Input / Output

The system consumes streaming audio input in 500 ms blocks and, at each block, either emits a text-based tool query (for web search over 100K documents or a simulated KG API) or a NO_QUERY token. Retrieved results (up to 23K tokens for Qwen-OMNI, 15K for OpusLM, 500 for Kimi-Audio) are concatenated as text references alongside the full audio question to condition the final spoken response. The output is a streaming speech answer generated by the E2E model, with first-token latency measured relative to utterance end (negative values indicate the response begins before the user finishes speaking).

## Method

Stream RAG introduces two complementary strategies for streaming tool-query generation. Fixed-Interval Stream RAG fires tool queries at every 1-second block and uses a heuristic reflector (comparing top-5 web documents and KG results) to identify the earliest intermediate query whose retrieval matches the final query, terminating later threads; it requires no post-training. Model-Triggered Stream RAG post-trains the model to autonomously decide when to issue a new query by conditioning on accumulated speech Q_{1:b} and the most recent non-empty query, using pseudo-ground-truth labels generated by an LLM on partial ASR transcripts with similarity-based NO_QUERY assignment. A key robustness mechanism injects 10% negative samples (incorrect previous queries) during training so the model learns to recover from misfired early tool calls. The model is multi-task fine-tuned on both streaming tool query generation and response generation, achieving 34.2% accuracy (vs. 11.1% closed-book) with 57% first-token latency reduction via vLLM integration.

## Results

On AudioCRAG-Synthetic, Model-Triggered Stream RAG with Qwen-OMNI improves QA accuracy from 11.1% (closed book) to 34.2%, a 23.1-point absolute gain, while reducing first-token latency from 5.90s (open book) to 5.32s. On the SLUE-SQA benchmark, Stream RAG achieves 55.8% exact-match accuracy with a negative first-token latency of −0.68s, meaning the system begins responding before the user finishes speaking. With vLLM inference optimization, median first-token latency drops further to 1.36s on AudioCRAG-Human, a 57% reduction over the open-book baseline.

## Baselines & Comparisons

On SLUE-SQA, Stream RAG (Qwen-OMNI) achieves 55.8% EM accuracy, substantially outperforming WavRAG (Chen et al., 2025) which scores 40.1% (GPT-4o) and 30.6% (QwenAudio), as well as WavRAG-CoT at 49.2% (GPT-4o) and 34.0% (QwenAudio). Stream RAG also beats the standard cascaded pipeline (Whisper → Qwen2.5 → VITS) at 36.6% EM. Critically, Stream RAG achieves a negative first-token latency of −0.68s (responding before the user finishes speaking), compared to +0.56s for WavRAG and +1.53s for the cascade, while WavRAG-CoT incurs a 4.34s delay. On the multi-turn CORAL dataset, Stream RAG achieves ROUGE-L of 12.9 with −0.82s latency on the second turn, slightly below the text-in/text-out Qwen2.5-7B baseline (ROUGE-L 13.1) but with substantially lower latency (−0.82s vs. 1.01s for Open Book), and shows better early semantic alignment (ROUGE-L First-25: 11.5 vs. 10.9).

## Relation to Prior Work

This paper extends the line of work on E2E speech-in/speech-out dialogue systems (Qwen-OMNI, OpusLM, Kimi-Audio) by integrating external tool usage in a streaming fashion, departing from the retrieve-after-endpoint paradigm used by prior speech RAG approaches like WavRAG and Feng et al. The CRAG benchmark provides the retrieval infrastructure (web + KG search) and evaluation protocol, which the authors adapt into the AudioCRAG spoken benchmark. Conceptually, the work bridges two previously separate threads: low-latency streaming speech dialogue (Moshi, LLaMA-Omni, NTPP) and tool-augmented LLM reasoning (Toolformer, ReAct), introducing a learned scheduling policy for when to issue retrieval queries under partial speech observability—a problem neither thread had addressed.

## Why It Matters / Open Questions

The 57% first-token latency reduction and negative latency on SLUE-SQA (responding before the user finishes speaking) are practically significant for production voice assistants where sub-500ms turn-taking is the usability threshold. The AudioCRAG benchmark fills a clear gap in evaluating tool-augmented speech-in/speech-out systems, and the modality-agnostic design means the technique transfers to typed input as well. Key open questions include whether the approach scales to multi-hop or iterative retrieval plans, how the persistent modality gap (speech output underperforming text by ~5-13 points, driven by entity pronunciation errors) can be closed, and whether the modest absolute accuracy (~34% on AudioCRAG) will improve as base speech models mature. The finding that streaming retrieval preserves accuracy relative to sequential retrieval (34.2% vs 34.9%) suggests the latency-accuracy tradeoff is milder than feared, but this was tested on a single benchmark pair.
