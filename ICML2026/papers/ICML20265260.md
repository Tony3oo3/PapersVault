## Problem

Existing multi-agent LLM systems instantiate inference-time parallelism in various forms—parallel agent teams, task decomposition, or DAG-based scheduling—but each is studied in isolation. It remains unclear how these different forms of parallelism relate hierarchically, what distinct roles they play in the accuracy–latency–cost trade-off, and whether combining them yields complementary or conflicting effects.

## Input / Output

The system takes a natural-language task query (e.g., GAIA questions spanning information retrieval, code execution, web browsing, and multimodal reasoning) together with a fixed agent-team configuration, and produces a single selected answer plus the full execution trace of the winning replica. Internally, each parallel replica yields an outcome tuple (success flag, answer, trace), and the judge operator scores candidates on answer definiteness, evidence strength, and reasoning consistency before final selection. The framework is evaluated on GAIA (Levels 1–3) and GAIA2-mini, with tasks stratified by difficulty to expose regime-dependent behavior.

## Method

TIPEX unifies two decoupled tiers of parallel control under a single execution semantics while leaving the underlying Magentic-One agent pipeline unchanged. Tier 1 (Replica Parallelism) instantiates n independent solution replicas via either Random Isomorphic Generation (identical prompt, stochastic decoding) or Orthogonal Heterogeneous Generation (LLM-synthesized methodologically diverse strategy instructions), then selects the final answer through a judge-based discriminator using Global Selection, First-Valid Early Stopping, or Top-K Selection. Tier 2 (Structural Parallelism) models each replica's execution as a dynamically expanding DAG of LLM inferences and tool calls, scheduling the executable frontier under one of three policies—Strict Sequential, Balanced Parallelism, or Aggressive Parallelism—with local failure handling that terminates hard-dependency chains while letting independent branches continue. The key finding is that the two tiers interact non-additively: moderate replica parallelism combined with balanced structural parallelism yields the most robust accuracy–latency–cost trade-off, while overly aggressive configurations in either tier introduce redundant execution and degrade reasoning quality, with the synergy being strongest on medium-difficulty tasks.

## Results

On GAIA Level 1, the best TIPEX configuration (RIG+GS) achieves 56.7% accuracy (70.0% Oracle) versus Magentic-One's 43.2%, while the recommended default (OHG+TKS) reaches 56.5% (60.9% Oracle) with 223.9 s latency and 67.6 k tokens. On Level 2, OHG+GS attains 38.7% accuracy (48.4% Oracle) versus the baseline's 25.8%, and on Level 3, OHG+GS reaches 11.5% (16.2% Oracle) versus 9.2%. Across all levels, parallel configurations reduce wall-clock time by 15–40% (e.g., 772 s → 268 s on L3 with OHG+TKS) but increase token consumption by roughly 30–160% relative to the single-replica baseline.

## Baselines & Comparisons

The sole baseline is Magentic-One, on top of which TIPEX is implemented with all other configurations held identical. TIPEX wins on accuracy at every difficulty level: the best configuration improves L1 from 43.2% to 56.7% (+13.5 pp), L2 from 25.8% to 38.7% (+12.9 pp), and L3 from 9.2% to 11.5% (+2.3 pp). On latency, TIPEX also wins for L2 (320 s → 168–281 s) and L3 (772 s → 218–401 s), with the largest relative reduction (~65%) on L3; on L1 the margin is smaller and some FVES configurations (135.7 s) beat the baseline while others (338.4 s) do not. TIPEX consistently loses on token consumption, increasing it by 30–160% (e.g., 38.8 k → 82.1 k on L1, 50.4 k → 130.9 k on L3 for OHG+GS). The paper's recommended default (OHG+TKS, n=3, k=2) strikes the best overall trade-off, achieving near-best accuracy with moderate latency and token overhead, whereas the most aggressive configurations (OHG+GS, RIG+GS) maximize accuracy at the highest token and latency cost.

## Relation to Prior Work

This paper builds on two established lines: LLM-based multi-agent orchestration frameworks (CAMEL, AutoGen, MetaGPT, Magentic-One) that define the agent-coordination paradigm, and inference-time parallelism approaches (M1-Parallel, LLMCompiler, Plan-over-Graph, DynTaskMAS) that each explore a single form of concurrency in isolation. TIPEX's conceptual departure is treating these previously studied forms—task-level replica exploration (rooted in self-consistency) and intra-path DAG-based structural scheduling—as two coupled tiers of a unified design space rather than independent optimizations. The framework is implemented directly on Magentic-One, keeping the agent pipeline fixed while varying only the parallelism configuration.

## Why It Matters / Open Questions

The paper provides the first systematic empirical characterization of how two tiers of inference-time parallelism interact, revealing non-additive effects and clear regime dependence (medium-difficulty tasks benefit most, aggressive structural parallelism degrades accuracy). The persistent gap between Oracle and actual accuracy identifies judge quality as a substantive bottleneck, motivating future work on more reliable selection mechanisms. Open questions include task-aware adaptive routing (only a preliminary Auto Router is shown), generalization beyond the GAIA benchmark family, and whether the observed trade-offs hold as backbone models improve. For practitioners deploying multi-agent systems, the practical takeaway is that parallelism is a tunable control knob with non-monotonic returns rather than a free accuracy/latency win.
