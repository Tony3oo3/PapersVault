## Problem

Existing software engineering benchmarks for LLMs are overwhelmingly confined to Python-centric bug fixing on single-file or small multi-file tasks, leaving critical developer activities—feature implementation, refactoring, performance optimization, test generation, configuration, and code understanding—largely unexplored. This narrowness prevents systematic diagnosis of whether strong model performance reflects generalizable reasoning or artifact-specific adaptation, and obscures cross-language and cross-scenario capability gaps.
![Teaser figure](../imgs/ICML20265217/cropped_page1_idx0.webp)

## Input / Output

Each of the 2,000 benchmark instances pairs a natural-language task description (derived from a real GitHub issue or PR) with a pinned Docker container containing the repository snapshot at the pre-patch commit, plus executable test oracles. The agent produces a code patch (or, for Code Understanding, a natural-language explanation) that is evaluated under task-specific metrics: Pass@1 for FI/FE/BF/RF, a binary Performance Optimization Score (execution time < 80% of baseline) for PO, Line Coverage (via pytest or C8) for TG, and an LLM-as-a-Judge checklist score for CU. All runs are strictly offline with a 150-turn budget and 600-second per-step timeout under either SWE-Agent or Claude Code.

## Method

SWE-Compass is constructed through a five-stage pipeline: (1) an iterative active-learning loop over Stack Overflow and GitHub conversations (using Qwen3-Coder-30B as annotator with ICL-based labeling and tag clustering) discovers a taxonomy of 8 task types, 8 programming scenarios, and 10 languages; (2) ~50,000 high-quality PRs are collected from GitHub repositories filtered by stars, activity, contributor count, and test availability; (3) containerized environments are built automatically from dependency manifests, with 30 expert annotators diagnosing and fixing the ~98% initial build failures to reach ~8% retention; (4) three complementary task-construction strategies are applied—Checklist Synthesis (GPT-5-generated reasoning checklists for Code Understanding), Reverse Masking (controlled perturbation of Dockerfiles and test suites for CD/TG), and Heuristic Filtering (intent-based classification of real PRs for FI/FE/BF/RF/PO); (5) multi-round validation enforces difficulty filtering, task-balanced sampling across scenarios and languages, and manual executability verification. Evaluation runs ten SOTA LLMs under two agentic frameworks (SWE-Agent's edit-diff-execute loop and Claude Code's sandboxed editor-centric workflow) with standardized offline build/test commands per language.

## Results

On SWE-Compass (2,000 instances across 8 task types, 8 scenarios, 10 languages), Claude-Sonnet-4 achieves the highest macro-average Pass@1 at 32.9% under Claude Code and 31.8% under SWE-Agent. The best open-weight model, Qwen3-Coder-480B-Instruct, reaches 27.2% (SWE-Agent) and 21.9% (Claude Code), trailing the proprietary SOTA by 5–11 points. Scores cluster in the 10–33% range, with Code Understanding being the easiest task (42–57%) and Feature Implementation the hardest (5–21%), revealing a clear difficulty hierarchy across task types, languages, and scenarios.

## Baselines & Comparisons

Claude-Sonnet-4 dominates across both frameworks, achieving 32.9% (Claude Code) and 31.8% (SWE-Agent) macro-average Pass@1, outperforming the next-best model (Qwen3-Coder-480B at 27.2%) by 4.6–11 points. Among open-weight models, Qwen3-Coder-480B leads under SWE-Agent (27.2%) but drops to 21.9% under Claude Code, while Qwen3-Coder-30B actually reverses this gap (20.7% vs. 21.6%), indicating framework–model interaction effects. The two frameworks are complementary: SWE-Agent excels on investigative multi-file tasks (BF, FI) via iterative localization, while Claude Code favors deterministic, well-scoped tasks (CD: 65.5% vs. 51.0%; TG: 28.4% vs. 25.0% for Claude-Sonnet-4). GPT-4.1 (21.4%) and Gemini-2.5-Pro (22.4%) trail the top two but outperform DeepSeek-V3 (16.5%) and SWE-agent-LM-32B (14.7%) by 5–7 points. At the language level, Java and JavaScript consistently score highest (52.7% and 36.0% for Claude-Sonnet-4 under SWE-Agent), while C, C++, and Rust remain the hardest (17–37%), and Python sits mid-tier (26.3%), suggesting performance is governed more by tooling determinism and diagnosability than raw coding difficulty.

## Relation to Prior Work

SWE-Compass extends the SWE-bench lineage (Jimenez et al., 2024) and its multilingual/multimodal variants by deliberately breaking the bug-fixing monoculture that dominates repository-level evaluation. Where prior benchmarks (SWE-bench-Verified, SWE-bench-Live, Multi-SWE-Bench, SWE-bench-Pro) cover 1–4 task types and are heavily Python-skewed, SWE-Compass generalizes to 8 task types, 8 scenarios, and 10 languages using an active-learning-driven taxonomy discovered from real GitHub/Stack Overflow conversations. Methodologically, it introduces checklist synthesis and reverse masking for non-patch tasks (Code Understanding, Configuration & Deployment, Test Case Generation), and employs LLM-as-a-Judge with structured checklists for non-executable evaluation—extending the execution-grounded paradigm of SWE-bench to tasks where a single pass/fail test is insufficient.

## Why It Matters / Open Questions

SWE-Compass provides the first unified, execution-grounded benchmark that reflects the full breadth of real-world developer workflows, making it a likely standard for diagnosing agentic coding systems beyond the narrow bug-fixing axis. The failure-mode analysis revealing that >60% of errors stem from requirement misinterpretation and incomplete solutions (rather than technical knowledge gaps) reframes the bottleneck as comprehension and holistic design, pointing future work toward better localization and architectural reasoning rather than raw code generation. Open questions include whether the difficulty hierarchy generalizes to larger/more complex repositories, how performance scales with context length in multi-module settings, and whether the two evaluated frameworks (SWE-Agent, Claude Code) capture the full design space of agentic architectures. The low absolute scores (best model ~33% average) underscore that agentic coding remains far from production-ready across the full task spectrum.
