## Problem

Existing test-time learning methods for LLM agents rely on hand-designed prompting rules to update memory after each interaction, making it difficult to align memory updates with downstream objectives over multi-step horizons. Even strong instruction-following LLMs fail to consistently improve across repeated interactions when memory updates are driven solely by such heuristic mechanisms, leaving the memory update process itself untrained and misaligned with actual task performance.
![Teaser figure](../imgs/ICML20260361/cropped_page0_idx1.webp)

## Input / Output

The memory model receives the current game trajectory (a structured interaction log including actions, outcomes, and rewards) and the previous textual memory state, then produces a structured 3-tier memory within a fixed 512-token budget: a REASONING layer (diagnostic analysis of evidence), a KNOWLEDGE_MAINTENANCE layer (hypotheses with verification status and observation counters), and a FINAL_STRATEGY_PROMPT layer (concise actionable rules). Only the FINAL_STRATEGY_PROMPT is exposed to the frozen player for the next game, while the full 3-tier structure is carried forward as context for subsequent memory updates, enabling iterative hypothesis revision.

## Method

MEMOPILOT formulates memory updating as a multi-turn MDP where a trainable memory model G_θ generates textual memories that guide a frozen player π across sequential games, and optimizes this process end-to-end via multi-turn GRPO. Two key training innovations enable stable credit assignment: (i) a one-step proxy reward that credits each memory update m_t solely by the next game's outcome r_{t+1}, avoiding variance from future stochasticity, and (ii) a context-independent, turn-level group-normalized advantage computed across G parallel rollouts, extending the standard GRPO loss from (group, token) to (group, turn, token) granularity. The memory is structured as a 3-tier 'Hypothesis-Verify-Confirm' loop that iteratively refines opponent-strategy beliefs and distills them into executable guidance, with the verification signal providing a natural stopping criterion. The player model remains entirely frozen, making the approach a plug-in applicable to any LLM player without parameter updates.

## Results

MEMOPILOT achieves 3.28 on RPS@5 and 2.03 on LHE@5 with Qwen2.5-14B-Instruct as the frozen player, and generalizes to 3.27 / 1.31 with the much stronger Qwen3-235B-A22B player. In Elo-based head-to-head rankings, MEMOPILOT ranks first on both games (1590 on RPS, 1762 on LHE), outperforming all prompting-based memory baselines and proprietary models including DeepSeek-V3.2. On the real-world StreamBench benchmark, MEMOPILOT reaches 73.5% (CoSQL) and 56.3% (DS-1000) pass@4, surpassing No Memory (69.5 / 50.0) and all prompt-based memory variants.

## Baselines & Comparisons

MEMOPILOT dominates all five compared memory methods on both games. On RPS@5, it outperforms Reflexion (3.28 vs. 0.61), ExpeL (3.28 vs. 0.03), MemoryBank (3.28 vs. 0.43), AWM (3.28 vs. 0.64), and ReasoningBank (3.28 vs. 0.81). On LHE@5, the gap is even more pronounced: all five baselines score negative (ranging from −0.39 for ExpeL to −1.27 for Reflexion), while MEMOPILOT achieves +2.03. The strongest non-RL memory baseline is DeepSeek-V3.2 used as a prompt-based memory updater (1.64 RPS, −0.78 LHE), which MEMOPILOT still surpasses by 1.64 and 2.81 points respectively. Notably, even the Human-Written Counter-Strategy (1.00 RPS, 1.08 LHE) is substantially outperformed, indicating that learned, iterative memory updates capture opponent-specific structure that static human-written plans cannot. The advantage persists when the frozen player is swapped to the much stronger Qwen3-235B-A22B, confirming that MEMOPILOT learns transferable strategic signals rather than model-specific prompting artifacts.

## Relation to Prior Work

This paper extends the line of work on memory-augmented LLM agents (Reflexion, ExpeL, Dynamic Cheatsheet, ReasoningBank) by replacing their hand-designed or prompt-based memory update rules with an end-to-end RL-trained memory policy. The optimization backbone is multi-turn GRPO (Shao et al., 2024), and the turn-level loss structure is directly inspired by MemAgent (Yu et al., 2026a), which the authors extend from (group, token) to (group, turn, token) granularity. The key conceptual departure is treating memory updating as a trainable multi-turn MDP with a frozen downstream player, rather than a heuristic text-generation step, and introducing a one-step proxy reward with turn-level group-normalized advantages to stabilize credit assignment in stochastic multi-turn rollouts.

## Why It Matters / Open Questions

The plug-in, frozen-player design makes MEMOPILOT applicable to any LLM (including closed-source models) without parameter updates, and the demonstrated generalization from a 14B training player to a 235B inference player suggests the learned memory policy captures transferable strategic structure rather than model-specific artifacts. Open questions include how the approach scales to environments with richer state spaces or continuous action spaces, how to handle non-stationary or co-adaptive opponents more gracefully (the paper shows measurable degradation), and whether the 512-token memory budget is sufficient for longer-horizon or multi-task settings. The one-step reward finding (cumulative reward collapses) is a practical insight likely to inform future multi-turn RL training recipes beyond memory.
