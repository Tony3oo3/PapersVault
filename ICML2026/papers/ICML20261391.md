## Problem

Integrating graph knowledge into LLMs via passive representation (flattened adjacency matrices or static text descriptions) faces three critical bottlenecks: context window limits that prevent scaling to large graphs, unreliable numerical computation on complex topologies, and structural hallucinations where models fabricate connectivity. Existing tool-augmented or RL-based graph reasoning methods either rely on predefined knowledge bases that fail out-of-scope, or allow models to succeed via semantic pattern-mimicry without grounding reasoning in actual graph structure.

## Input / Output

The agent receives a natural language query about a graph; in the structure-blind training setting (Stage II), only a Graph ID is provided and the full topology is withheld, forcing the agent to discover structure exclusively through tool calls. The agent can invoke two tools: a Neighbor Retrieval function (specifying node index, dataset name, and hop depth k) that returns local subgraph metadata, and a Code Interpreter that executes sandboxed Python with results extracted from a mandatory `result` variable. Outputs are structured as node class labels, predicted links, natural-language QA answers, or graph-theoretic solutions (e.g., edge lists for matchings, path sequences), with a data-leakage guard that masks test-set node metadata during retrieval.

## Method

GRASP equips a 4B LLM (Qwen3-4B-Thinking) with a dual-tool environment—Neighbor Retrieval for on-demand k-hop topology probing and a sandboxed Code Interpreter operating in a closed-loop Reason-Act-Observe-Correct cycle—and trains it via a two-stage GRPO curriculum. Stage I (Tool Familiarization) trains on visible graphs to learn tool syntax and basic retrieval; Stage II (Proactive Discovery) masks all topology, giving the agent only a Graph ID, which forces it to develop active exploration policies and increases interaction depth from ~5 to ~60 turns. The GRPO objective normalizes trajectory rewards within groups of G sampled rollouts, penalizing faulty logic or inefficient tool use while rewarding trajectories that ground reasoning in retrieved structural evidence. This staged transition from visible to structure-blind environments is the key mechanism that prevents the model from relying on algorithmic templates or lucky guesses, instead compelling it to anchor code in retrieved topological signals. The result is a 53.06% average performance boost over the base model, with the 4B agent surpassing DeepSeek-V3.2 (671B) by 7.80% on tool-augmented benchmarks and generalizing zero-shot to unseen domains and Hard-level LeetCode graph problems.

## Results

GRASP-4B achieves an 83.85% average accuracy across 10 diverse graph reasoning benchmarks (node classification, link prediction, graph QA, and graph-theoretic problems), a 53.06% absolute improvement over the Qwen3-4B-Thinking base model (30.79%). It surpasses the strongest tool-augmented baseline, DeepSeek-V3.2 (671B parameters), by 7.80 points (83.85% vs. 76.05%) and outperforms the best domain-specific method, Graph-R1, by 35.77 points. On zero-shot transfer to unseen benchmarks (Cora, ml1m, SGDS, GraphArena, GraphWiz, NLGraph, GraphInstruct), GRASP maintains a 64.50% average on real-world tasks and 83.51% on graph-theoretic benchmarks, and achieves >97% accuracy on million-node subgraph sampling (ogbn-mag).

## Baselines & Comparisons

GRASP-4B (83.85%) decisively outperforms all generalist LLMs: DeepSeek-V3.2 (68.90% generalist / 76.05% tool-augmented), GPT-4o (47.46% / 52.59%), and LongCat-Flash-Thinking-2601 (66.06% / 70.74%), with the largest margin over GPT-4o (+36.39 pts). Against domain-specific graph methods, GRASP leads by 35.77 pts over Graph-R1 (48.08%), 51.34 pts over GraphTool (32.51%), and 58.95 pts over G1-3B (39.04%); GraphWiz and GraphAgent are far behind at 5.00% and 24.90% respectively. The no-tool ablation (GRPO-Pure, 64.08%) confirms that tool access contributes ~20 pts beyond internalized reasoning alone. Against classical GNNs, GRASP surpasses GAT (61.00%) by 12 pts on arxiv node classification and R-GAT (67.00%) by 15 pts on fb15k237 link prediction, though it trails R-GCN (75.00%) on wn18rr (67.00%), where purely structural path patterns favor GNNs. On zero-shot transfer, GRASP (64.50% avg) beats GraphTool (45.83%) and GRPO-Pure (46.00%) on unseen real-world graphs, and leads all baselines on GraphArena (75.65%), GraphWiz (86.36%), and NLGraph (87.10%).

## Relation to Prior Work

GRASP synthesizes three established threads: the ReAct/Self-Refine closed-loop reasoning-acting architecture for tool use, the GRPO group-relative policy optimization from DeepSeekMath for RL training, and the G1 reward formulation for verifiable graph-theoretic answers. Its key departure from prior agentic graph work (GraphAgent, GraphTool, GraphR1) is the staged curriculum that transitions from visible-graph tool familiarization to a structure-blind environment, forcing the agent to abandon template-matching and develop genuine topological awareness through iterative retrieval. Unlike open-loop code-generation approaches (CodeGraph, G-Coder), GRASP's Code Interpreter operates in a closed feedback loop where execution errors trigger in-context self-correction, and unlike passive-encoding methods (TalkLikeAGraph, GraphSOS), the graph is never flattened into the context window.

## Why It Matters / Open Questions

The result that a 4B model with agentic tools and staged RL surpasses a 671B frontier model (DeepSeek-V3.2) on graph reasoning suggests that domain-specific tool-augmented training can close the scale gap more efficiently than raw parameter count, a finding with implications for deploying capable graph agents on resource-constrained hardware. The catastrophic performance cliff of GRASP-Base on million-node sampling (92%→12%) versus GRASP's sustained >97% performance provides concrete evidence that the structure-blind stage is not merely incremental but qualitatively changes exploration behavior. Open questions include whether the staged curriculum generalizes to other structured-reasoning domains (e.g., program synthesis over large codebases), how the approach scales when the graph itself is dynamic or partially observable, and whether the reliance on a pretrained agentic base model (Qwen3-4B-Thinking) limits transferability to non-agentic architectures.
