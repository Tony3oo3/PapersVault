## Problem

Existing LLM agent security research focuses on output correctness failures (jailbreaks, prompt injection, behavioral hijacking) but overlooks a fundamental availability threat: an agent can produce correct outputs yet become operationally unusable due to adversarially inflated reasoning depth or tool-use budgets. This paper formalizes Reasoning-Level Denial-of-Service (R-DoS), where an attacker preserves task correctness while exhausting the agent's reasoning/tool-use budget under latency or SLA constraints, and presents the first unified framework to instantiate such attacks.

## Input / Output

The method takes a user instruction x, an environment observation o, a target URL u (attacker.test), and a victim agent model M as inputs. It produces two artifacts: (1) a short adversarial trigger string s* injected into either the instruction or observation channel, optimized to reliably induce the agent to invoke an external tool call to u; and (2) a multi-segment reasoning payload r* (comprising a local sink task and a persistent meta-instruction policy) deployed on the attacker-controlled page to maximize sustained reasoning-token inflation across subsequent Thought-Action cycles. The trigger string is a discrete token suffix optimized via gradient-based or log-probability search, while the payload is a natural-language reasoning task optimized via ICL-guided genetic search over full agent rollouts.

## Method

OTora is a two-stage red-teaming pipeline. Stage I optimizes an adversarial trigger suffix using an attention-aware insertion scoring function that combines prefix-match, continuation-likelihood, and attention-mass terms to identify semantically aligned insertion positions, coupled with dynamic target co-evolution that generates semantically equivalent tool-access intents from the agent's own response distribution and selects the highest-scoring variant via weighted interval scheduling. Stage II deploys an agent-aware reasoning payload on the attacker-controlled page, decomposed into a local sink segment (a single complex reasoning task at the hijacked turn) and a persistent policy segment (long-lived meta-instructions injected into the agent's interaction history), exploiting the history-conditioning property of ReAct-style agents to propagate reasoning overhead across multiple subsequent turns. Payload optimization uses a multi-objective scoring function balancing reasoning-token inflation (RTI), task fidelity, and cross-seed stability, searched via an ICL-guided genetic algorithm where top-performing payloads condition an auxiliary model to generate mutated variants. The two-stage decomposition is motivated by the observation that Stage I injection channels (instructions, third-party observations) are narrow and noisy, making them unsuitable for reliably delivering long structured payloads, whereas attacker-controlled pages ensure payload integrity.

## Results

On the WebShop agent with LLaMA-3.1-70B (environment injection), OTora-Persistent achieves 9.7× reasoning-token inflation (RTI) and 325 s end-to-end delay (vs. 30 s baseline) while preserving 96.1% task accuracy (95% no-attack). Across all three agents (WebShop, Email, OS) and backbone models (LLaMA-3.1-70B, GPT-OSS-120B, GPT-3.5-Turbo), OTora-Persistent delivers 5.1–10.8× RTI with Hit rates of 73–92% and accuracy ≥ 91%. In Stage I trigger optimization, OTora achieves 97%/95% ASR_S/ASR_H (white-box, LLaMA-70B, WebShop, environment) in 50 iterations, versus 96%/94% for UDora in 75 iterations and 88%/85% for GCG in 240 iterations.

## Baselines & Comparisons

In black-box Stage I trigger optimization (Table 1), OTora consistently outperforms SNES, AutoDAN, and PAL on both ASR_S and ASR_H while requiring fewer iterations; e.g., on GPT-3.5-Turbo / WebShop / environment injection, OTora reaches 63%/58% ASR_S/ASR_H in 430 iterations versus PAL's 55%/50% in 520, AutoDAN's 48%/43% in 680, and SNES's 39%/35% in 800. In white-box Stage I (Table 2), OTora surpasses GCG, I-GCG, and UDora; on LLaMA-3.1-70B / WebShop / environment, OTora achieves 97%/95% in 50 iterations versus UDora's 96%/94% in 75, I-GCG's 93%/90% in 150, and GCG's 88%/85% in 240. In Stage II (Table 3), OTora-Persistent achieves the best RTI–Hit–accuracy trade-off: ICL(Agnostic) variants reach slightly higher RTI (10.2–11.2×) but suffer 52–60% Hit rates, whereas OTora-Persistent delivers 9.7–10.8× RTI with 86–92% Hit and ≥ 95.7% accuracy. In cross-model transfer (Table 11), OTora's artifacts optimized on LLaMA-70B transfer to GPT-3.5-Turbo and Gemini-1.5-Flash with 21–26% E2E success (vs. 10–14% for UDora) and 4.8–5.1× RTI, confirming broader applicability. Overall, OTora wins on every primary metric (ASR, RTI, Hit, accuracy, iteration count) against all five baselines across both black-box and white-box settings.

## Relation to Prior Work

OTora builds directly on UDora's response-level noise insertion framework for Stage I trigger optimization, extending it with attention-aware insertion scoring and dynamic target co-evolution. Conceptually, it unifies two previously separate research threads: (1) overthinking/slowdown attacks on single-turn reasoning LLMs (Kumar et al., 2025; Si et al., 2025; Liu et al., 2025), which inflate token usage while preserving answer correctness, and (2) agent-level behavioral hijacking (Greshake et al., 2023; Zhang et al., 2025), which manipulates tool-use trajectories. The key departure is formalizing R-DoS as a multi-turn, SLA-constrained threat where the attacker must preserve functional correctness across an entire agent execution loop rather than a single model response, and decomposing the attack into a narrow trigger channel (Stage I) and a wide attacker-controlled payload channel (Stage II).

## Why It Matters / Open Questions

R-DoS exposes a structural blind spot in current agent defenses: safeguards detect semantic or policy violations, but excessive-yet-correct reasoning is operationally indistinguishable from benign hard tasks. The quantitative defense evaluation (Appendix I) confirms that no static threshold simultaneously preserves benign accuracy and suppresses R-DoS—aggressive relevance filtering (θ=0.9) cuts attack E2E to 22% but drops benign accuracy to 41%, and runtime monitoring at 1.0σ falsely terminates nearly half of benign tasks. This availability-correctness trade-off is fundamental and unresolved, making R-DoS a persistent risk for SLA-constrained deployments. Open questions include whether adaptive, context-aware budgeting or learned anomaly detectors can close the gap without the blunt trade-offs observed here, and whether the low-and-slow regime (where per-turn inflation stays within benign variance) is defendable at all.
