## Problem

Biophysically detailed multi-compartment neurons offer high computational density but are bottlenecked by the lack of a scalable, differentiable training framework. Existing GPU simulators (CoreNEURON, DeepDendrite) are non-differentiable, while AD-based frameworks (JAXLEY, BrainPy) suffer from prohibitive memory overhead because the irregular, tree-structured cable-equation solve and long-horizon ODE integration do not map to dense-tensor optimizations. The result is that training large morphologically detailed networks remains intractable on practical hardware.

## Input / Output

The framework consumes NEURON model specifications (morphology, mechanism insertion, connectivity) as its primary input, which are imported into a GPU-native runtime at a 'freeze point' that decouples training from frontend object semantics. Forward simulation advances compartment voltages and mechanism states via fixed-step ODE integration, producing membrane potential traces and spike trains; the learning readout is a time-averaged somatic voltage over a configurable window, from which softmax class predictions (MNIST) or Pearson correlation matrices (C. elegans Ca²⁺ fitting) are computed. Training data enters as rate-coded spike sequences (one per input dimension) for structured MLPs or as experimental calcium-imaging recordings for the whole-brain circuit-fitting task.

## Method

HelioX adopts a 'GPU-to-Biophysics' paradigm, co-designing CUDA kernels around the irregular dendritic tree structure rather than adapting biology to generic deep-learning primitives. The simulation core implements the Dendritic Hierarchical Scheduling (DHS) algorithm via custom fused kernels for the tree-structured cable solve, combined with a 4-byte sparse-spike gating mechanism that eliminates host-device synchronization on spike-free steps, and multi-stream concurrency with CUDA-event-based dependency enforcement for heterogeneous mechanism evaluation. For training, HelioX replaces generic automatic differentiation with analytical, structure-aware gradients (following DeepDendrite's transfer-resistance formulation) that directly bind to device-resident simulator states via a handle-based variable registry, enabling O(1) access without per-timestep name resolution. A learning-time downsampling strategy computes gradients on a temporally subsampled trajectory while keeping the forward simulation at full resolution, reducing effective history length and memory bandwidth pressure. The entire pipeline—simulation, gradient computation, and parameter updates—executes on a single GPU, with a PyTorch-like Sequential API for structured biophysical MLPs and a NEURON-compatible import path for general circuits.

## Results

On simulation benchmarks, HelioX achieves 1.6–2.25× speedup over CoreNEURON and 1.69–2.60× over DeepDendrite across single-cell and 500-cell networks (Table 1), while matching NEURON's numerical fidelity to within 10⁻⁸ mV. On the BAAIWorm C. elegans whole-brain fitting task, HelioX reduces per-epoch training time from 14,840 s (CoreNEURON) to 5,100 s (2.91×), and with 5× learning-time downsampling to just 60 s (247×), while cutting peak GPU memory from 47.4 GB to 5.2 GB (89% reduction). On the MNIST biophysical MLP, HelioX reaches 96.47% test accuracy (vs. JAXLEY's 94.2%) and delivers 43.67× training and 44.72× inference speedup over CoreNEURON, with peak memory of 1,121 MiB versus JAXLEY's 2,219 MiB.

## Baselines & Comparisons

Against NEURON (the CPU reference), HelioX achieves 1.6–2.25× simulation speedup while reproducing identical spike times and sub-10⁻⁸ mV voltage error, confirming it is a drop-in GPU accelerator rather than an approximation. Against CoreNEURON (the strongest CPU/GPU hybrid baseline), HelioX wins on every benchmark: 1.6–2.25× in simulation, 2.91× in C. elegans training (247× with downsampling), and 43.67× in MNIST MLP training, with peak memory reduced from 47.4 GB to 5.2 GB on the worm task. Against DeepDendrite (the prior GPU-native simulator using the same DHS algorithm), HelioX gains 1.69–2.60× in simulation and 1.87× in MNIST training, attributed to multi-stream concurrency, fused kernels, and GPU-resident analytical gradients. Against JAXLEY (the leading AD-based differentiable framework), HelioX achieves 3.12× simulation speedup on the one directly comparable setting, 11.94× training and 4.33× inference speedup on MNIST, and uses only 0.51× the peak GPU memory (1,121 vs. 2,219 MiB); the authors note that JAXLEY's traces showed up to 12.89 mV discrepancy from NEURON under spike-driven conditions, so they report only the most conservative comparison.

## Relation to Prior Work

HelioX builds directly on DeepDendrite (Zhang et al., 2023), adopting its Dendritic Hierarchical Scheduling (DHS) algorithm for GPU-parallel tree solves and its analytical synaptic gradient rule, while adding a full GPU-native execution stack (sparse spike gating, multi-stream concurrency, fused CUDA kernels) and a NEURON-compatible modeling frontend. It departs from the automatic-differentiation paradigm of JAXLEY (Deistler et al., 2025) by replacing AD-based backpropagation through ODE integration with structure-aware analytical gradients, thereby eliminating large computation graphs and state tapes. For the C. elegans benchmark, it reuses the task definition and approximate-gradient optimization algorithm from BAAIWorm (Zhao et al., 2024), positioning itself as a systems-level accelerator rather than a new learning algorithm.

## Why It Matters / Open Questions

By reducing peak GPU memory from 47 GB to ~5 GB and achieving a ~247× per-epoch speedup on the whole-brain C. elegans circuit-fitting task, HelioX makes biophysically detailed network training accessible on a single consumer GPU, substantially lowering the hardware barrier for both computational neuroscience and brain-inspired AI research. Open questions include whether the analytical-gradient approach generalizes to all biophysical learning rules (beyond the DeepDendrite-style synaptic update), how the framework scales beyond a single GPU to multi-node settings, and whether the NEURON-compatibility layer can keep pace with evolving model specifications. The preliminary ROCm portability results suggest cross-platform migration is feasible but remains unvalidated at scale.
