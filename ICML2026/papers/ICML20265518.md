## Problem

Existing self-evolving agent frameworks predominantly optimize memory management while treating memory extraction as a static prompting process, leading to two critical failures: accumulation of instance-specific noise that progressively pollutes the memory bank, and misalignment between extracted memories and the management policy. This results in poor cross-task generalization, where agents memorize shortcuts rather than distilling reusable, generalizable insights from experience.

## Input / Output

The system takes a text query q, encodes it with BGE-M3 to retrieve Top-K (K=3) relevant key-value memory entries from the external memory bank, and feeds them as context to a frozen executor LLM that produces a full reasoning trajectory and final answer. The Mem-Optimizer then consumes the query, trajectory, and retrieved memories to emit a structured XML action containing an extracted memory string and a management operation (ADD or UPDATE), which is applied to the memory bank. The memory bank itself is an unbounded set of (BGE-M3 embedding, memory text) pairs that evolves online throughout training and inference.

## Method

UMEM jointly optimizes a small Mem-Optimizer policy (1B–14B) via GRPO to simultaneously extract and manage memories, rather than treating extraction as a fixed prompt. The key mechanism is Semantic Neighborhood Modeling: for each source query, the Top-N (N=3) most semantically similar queries are retrieved via BGE-M3 cosine similarity, and the candidate memory update is evaluated across this entire neighborhood rather than the single source, forcing the policy to discard instance-specific details. The Marginal Utility Reward combines a Success Gain term (correcting previously wrong neighbors) with an Efficiency Regularization term (rewarding shorter trajectories only when correctness is preserved), averaged over the neighborhood to produce a generalization-aware signal. After each GRPO update, the highest-reward rollout is immediately committed to the memory bank (Online Memory Evolution), so the agent learns to interact with a continuously refining memory system. A theoretical lemma shows that cosine-neighborhood membership guarantees near-identical retrieval rankings, validating the neighborhood as a proxy for future reuse.

## Results

With GPT-5.1 as the frozen executor, UMEM-Qwen3-14B achieves an average score of 59.00 across five benchmarks, outperforming the strongest baseline EvolveR (55.34) by 3.66 points and the no-memory baseline (45.36) by 13.64 points. On ALFWorld, UMEM-Qwen3-4B attains a Success Rate of 83.09% and Progress Rate of 84.58%, representing up to 11.49 points improvement over baselines in multi-turn interactive tasks. With Qwen3-8B-Thinking as executor, UMEM-Qwen3-14B reaches 52.47 average (vs. 47.28 no-memory), and with Gemini-2.5-Flash it reaches 55.91 (vs. 49.14 no-memory). The paper also reports that UMEM maintains stable cumulative performance over 10-epoch continual interaction on ALFWorld, with the performance gap over baselines widening as interactions proceed.

## Baselines & Comparisons

UMEM consistently outperforms all six baselines on the overall average across all three executor settings. Against EvolveR (the strongest baseline at 55.34 avg with GPT-5.1), UMEM-Qwen3-14B leads by 3.66 points, with particularly large margins on AIME (55.56 vs. 44.44) and ALFWorld SR (82.59 vs. 79.85). Against MemP (54.24 avg), UMEM wins by 4.76 points on average, with the gap most pronounced on ALFWorld SR (82.59 vs. 77.36) and AIME (55.56 vs. 43.33). MemRL achieves the highest GPQA score (67.51) but suffers a severe ALFWorld SR collapse (44.53), yielding the lowest average (45.91) among memory-based baselines; UMEM surpasses it by 13.09 points on average. ReasoningBank (53.76 avg) and Self-RAG (52.36 avg) are both outperformed by 5+ points on average, with UMEM showing the largest gains on AIME and ALFWorld. ReMem (49.30 avg) underperforms even the no-memory baseline on AIME (33.33 vs. 40.00), highlighting the cost of optimizing management without extraction; UMEM exceeds it by 9.70 points on average. Notably, UMEM-Qwen3-14B slightly trails MemRL and ReasoningBank on GPQA (66.00 vs. 67.51/67.01), but compensates with large advantages on all other benchmarks.

## Relation to Prior Work

This paper extends the non-parametric self-evolving agent paradigm (where an external memory bank serves as evolvable parameters) by jointly optimizing both memory extraction and management via GRPO, departing from prior work (MemRL, MemP, ReasoningBank, EvolveR, ReMem) that treats extraction as a static prompting step and only optimizes the management/selection policy. The core algorithmic building block is GRPO (Shao et al., 2024), repurposed here to optimize a memory-optimizer policy rather than a language model's generation policy. The Semantic Neighborhood Modeling component draws on embedding-based retrieval (BGE-M3) but introduces a novel use: evaluating candidate memory updates across a cluster of semantically related queries rather than the single source query, explicitly targeting cross-task generalization.

## Why It Matters / Open Questions

The ablation showing that disabling extraction optimization causes a 3.88-point average drop (versus 1.48 for management) challenges the field's prevailing focus on memory management as the primary bottleneck, suggesting that memory quality at the source is more critical than selection strategy. Open questions remain around when to invoke memory (the paper acknowledges ~7% interference failures), the appropriate abstraction level for different task types, and adversarial robustness of the memory bank. The cross-model portability results (memories distilled for one executor benefiting GPT-5.1, Qwen3-8B, and Gemini-2.5-Flash) suggest a practical path toward executor-agnostic experience transfer, though the dependence on embedding quality for retrieval remains a practical constraint.
