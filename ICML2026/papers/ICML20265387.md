## Problem

Existing MLLM-based UI2Code approaches predominantly generate monolithic HTML/CSS, overlooking the component-based frameworks (React, Vue, Angular) used in real-world development. Their outputs exhibit extensive structural repetition rather than reusable components, and MLLMs struggle with framework-specific syntax such as JSX, template directives, and TypeScript patterns, making multi-framework portability and component-level reuse an open problem.
![Teaser figure](../imgs/ICML20265387/cropped_page0_idx0.webp)

## Input / Output

The method takes a high-resolution webpage screenshot (with potentially extreme aspect ratios, handled via Pix2Struct's aspect-ratio-preserving patch encoding) and a target framework identifier as input. It produces a framework-specific, directly runnable code artifact (single-file React JSX, Vue SFC, Angular component template + class, or standalone HTML) along with an intermediate representation that explicitly encodes component templates, repeat nodes with data tables, and slot-to-value bindings in a framework-agnostic JSON structure.

## Method

DCM is a three-stage neuro-symbolic pipeline that decouples visual structure prediction from code synthesis. Stage 1 uses a Pix2Struct-based model to autoregressively predict a coarse-grained DOM tree in JSON (node types, hierarchy, BBox). Stage 2 applies fully deterministic rules: it canonicalizes the tree into a structure view (masked content, stable vocabulary) and a content map, computes bottom-up Merkle/WL-style subtree hashes, clusters same-parent siblings by hash to mine repeat patterns (threshold k_min=3), extracts component templates with slot sets via cross-instance alignment, and resolves nested repeats via greedy scoring. Stage 3 feeds the resulting IR (augmented tree, component set, data tables) into an LLM under four hard constraints—native loop translation, full component-props coverage, mandatory data-field consumption, and single-file output—so the LLM performs only constrained syntax realization rather than structural inference.

## Results

On WebCode2M, DCM achieves the highest CLIP similarity (0.87) and Visual score (0.82) for Vanilla HTML on the Short split, and the best Compilation Success Rate (0.91) and Reusability Rate (0.85) for React on the same split. Across all four frameworks (Vanilla HTML, React, Vue, Angular) and three difficulty levels (Short/Mid/Long), DCM consistently attains the top or near-top scores on every metric. In the blind human evaluation against GPT-4o, DCM is preferred in 48.0% of cases versus 17.6% for GPT-4o (34.4% ties), with a statistically significant win-to-loss ratio of approximately 2.7:1 (p < 0.001).

## Baselines & Comparisons

DCM outperforms all four baselines (Gemini-2.5-Pro, GPT-4o, LLaVA-v1.5-7B, Qwen2.5-VL-7B) across every framework and split on Visual score, with the largest margins over open-source models (e.g., +0.39 Visual over LLaVA-v1.5-7B on React Short). Against the strongest proprietary baselines, DCM leads GPT-4o by +0.09 CLIP and +0.09 Visual on React Short, and by +0.05 CSR and +0.05 RR on the same setting; the gap narrows on Long splits but DCM still maintains the edge (e.g., +0.04 CLIP, +0.09 Visual, +0.03 CSR over GPT-4o on React Long). For Vue and Angular, DCM similarly dominates: on Vue Short it achieves 0.87 CSR vs. 0.82 for GPT-4o, and on Angular Short it reaches 0.76 CSR vs. 0.71 for GPT-4o. The open-source baselines (LLaVA-v1.5-7B, Qwen2.5-VL-7B) trail DCM by 0.10–0.25 on CLIP and 0.15–0.35 on Visual across all settings, with particularly large gaps on CSR and RR for component-based frameworks. In the head-to-head human evaluation, DCM's 48.0% win rate over GPT-4o's 17.6% (Fleiss's κ = 0.63, p < 0.001) confirms that the advantage is perceptible to professional developers beyond automatic metrics.

## Relation to Prior Work

This paper departs from the dominant MLLM-based UI2Code paradigm (GPT-4o, Gemini-2.5-Pro, LLaVA, Qwen2.5-VL) that treats screenshot-to-code as a single end-to-end generation task producing monolithic HTML/CSS. It also extends agentic/layout-guided systems like ScreenCoder and LayoutCoder, which improve visual fidelity but still ignore component-based frameworks. The key conceptual departure is the 'mining-before-generation' paradigm: a lightweight Pix2Struct-based structure model predicts a coarse DOM tree, deterministic structural hashing and clustering extract reusable components and repeat patterns into a framework-agnostic intermediate representation, and only then is an LLM invoked for constrained syntax realization in the target framework (React, Vue, Angular, or Vanilla HTML).

## Why It Matters / Open Questions

This is the first systematic treatment of multi-framework UI2Code with explicit component reuse, addressing a gap that directly affects real-world front-end engineering where React/Vue/Angular dominate over bare HTML. The neuro-symbolic decomposition (deterministic mining + LLM synthesis) offers a practical path to maintainable, auditable code generation that pure end-to-end MLLMs struggle to produce. Key limitations include the absence of dynamic state management, interactive logic, and support for complex routing or data-fetching patterns, which the authors acknowledge as future work. Open questions include whether the deterministic mining stage generalizes to highly irregular or non-repetitive layouts, and how the approach scales to full-page applications with dozens of components.
