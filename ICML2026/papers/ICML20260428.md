## Problem

Existing self-speculative decoding methods rely on static layer-selection heuristics that treat Transformer layers as inseparable units or assume uniform per-layer latencies, failing to capture the fact that Attention latency grows linearly with context length while MLP latency remains constant. This causes draft configurations optimized for short contexts to become suboptimal as the bottleneck shifts, and no prior work provides a rigorous theoretical justification for using cosine similarity as a proxy for token acceptance rate.

## Input / Output

KnapSpec operates on a pre-trained LLM (Qwen3 or Llama3, 1B–70B) given a text prompt, along with one-time offline hardware latency profiles (coefficients c₁, c₂, c₃ fitted via least-squares regression for the specific GPU and model). At inference time, the DP search consumes cached hidden-state matrices from the most recent m=5 speculation steps (r tokens total) and produces both the next generated tokens (preserving the target model's output distribution) and a re-optimized draft layer configuration (a subset of individual Attention and MLP layers) every T=64 or 128 decoding steps, adapting to the current context length.

## Method

KnapSpec decouples each Transformer layer into separate Attention and MLP items, assigning each a hardware-specific, context-length-dependent latency as its knapsack weight and its cosine similarity to the target model's reference representation as its value. A parallel dynamic programming algorithm then solves the 0/1 Knapsack Problem simultaneously for all latency budget partitions in a single pass, yielding a candidate set of layer subsets that maximize acceptance-rate proxy under each cost constraint. A final grid search over candidates and draft lengths selects the configuration maximizing the proposed Tokens-per-Time (TPT) metric, which directly accounts for asymmetric Attention/MLP execution times. The paper further provides the first formal proof (Lemma 4.1) establishing a sufficient condition on cosine similarity that guarantees identical greedy token selection, thereby justifying the similarity-based objective. Pruning criteria (similarity threshold τ=0.5 and skip-weight cap K/2) and an adaptive drafting exit based on token confidence further reduce overhead without sacrificing throughput.

## Results

KnapSpec achieves up to 1.47× wall-clock speedup over autoregressive decoding on GovReport with Llama3.1-70B, and consistently outperforms all baselines across model scales from 1B to 70B parameters. On reasoning tasks (AIME24/25, MMLU-Pro) with Qwen3-32B, KnapSpec reaches 1.43×, 1.42×, and 1.20× speedup respectively, with TPT values of 31.06, 32.00, and 34.62 tokens/s. On long-context summarization (GovReport, PG19, BookSum) with Llama3.1-70B, speedups of 1.47×, 1.21×, and 1.14× are achieved. The method maintains robustness under nucleus sampling (T=0.7, top-k=50, top-p=0.95), achieving 1.13×–1.23× speedup on Qwen3-8B and Llama3.1-8B.

## Baselines & Comparisons

KnapSpec consistently outperforms all three training-free SSD baselines (DEL, SWIFT, CLaSp) in wall-clock speedup across every model scale (1B–70B) and dataset tested. DEL, designed for fine-tuned early-exit models, frequently degrades below autoregressive speed (0.68×–0.88×), confirming it is unsuitable for general base models. SWIFT is highly inconsistent, achieving speedups above 1× on some tasks (e.g., 1.33× on GovReport with Llama3.1-70B) but falling below 1× on others (e.g., 0.83× on PG19 with Llama3.1-8B), reflecting its lack of explicit latency-awareness. CLaSp is the strongest baseline, reaching 1.22× on GovReport (Llama3.1-70B) and 1.16× on MMLU-Pro (Qwen3-8B), yet KnapSpec surpasses it by 0.25× and 0.17× respectively. Notably, KnapSpec often achieves slightly lower acceptance rates than CLaSp (e.g., 85.1% vs. 92.0% on MMLU-Pro with Qwen3-32B) while delivering higher TPT and speedup, validating that directly optimizing hardware-aware Tokens-per-Time rather than raw acceptance rate yields superior practical throughput.

## Relation to Prior Work

KnapSpec extends the self-speculative decoding (SSD) line of work that began with early-exit methods (LayerSkip, Kangaroo) and evolved into training-free layer-skip approaches (Draft&Verify, SWIFT, CLaSp). Its closest predecessor is CLaSp, which already used dynamic programming with a cosine-similarity objective to select draft layers; KnapSpec departs by (i) decoupling Attention and MLP sub-layers so each can be independently skipped, (ii) replacing the uniform layer-count budget with hardware-profiled, context-length-dependent latencies cast as a 0/1 Knapsack Problem, and (iii) introducing the Tokens-per-Time (TPT) metric that generalizes DEL's Tokens-per-Layer objective. The paper also provides the first formal proof (Lemma 4.1) that high cosine similarity between draft and target hidden states is a sufficient condition for identical greedy token selection, grounding a heuristic that prior SSD works used empirically.

## Why It Matters / Open Questions

For practitioners deploying LLMs in long-context settings, KnapSpec offers a training-free, plug-and-play acceleration that adapts its draft configuration as the context window grows—addressing a real bottleneck where static layer-skip heuristics degrade. The TPT-vs-acceptance-rate correlation analysis (0.837 vs. 0.537) is a useful reminder that optimizing for raw acceptance rate can mislead, since a slower draft with marginally higher accuracy may yield lower wall-clock throughput. Open questions include whether the knapsack formulation transfers to non-Transformer architectures (e.g., Mamba, hybrid SSMs), how the method behaves under multi-GPU or distributed inference where latency profiles change, and whether the one-time hardware profiling step remains valid as model parallelism strategies evolve.
