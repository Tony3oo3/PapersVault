## Problem

Standard autoregressive code generation enforces an append-only constraint where each token becomes immutable once emitted, creating a 'Commitment Trap' in which early vulnerabilities cascade into systemic failures. While developers naturally interleave generation with on-the-fly revision, existing approaches to add this capability (post-hoc agents, external static analyzers) either incur O(L) latency from redundant context re-encoding or restrict intervention to syntactic checks, failing to leverage the model's intrinsic semantic reasoning for just-in-time security correction.

## Input / Output

The method takes a security-neutral natural language specification (describing only functional intent, with no vulnerability cues) and produces a secure source code program. Internally, the model emits an augmented token stream T that interleaves standard code tokens with revision episodes (a trigger token, a content-addressable scope span enclosed in delimiters, and a patch span enclosed in delimiters). A deterministic renderer Φ compiles T into the final executable program Y, suppressing revision artifacts from the user-facing output so the streaming interface appears identical to standard autoregressive decoding.

## Method

Stream of Revision augments the model vocabulary with five operational tokens (a backtracking trigger, scope delimiters, and patch delimiters) that act as executable control instructions for a Virtual Cursor, expanding the output space into a hybrid domain of code generation and cursor manipulation. At each decoding step, the model implicitly chooses between continuing generation and initiating a revision episode; during localization, dynamic logit masking enforces a Strict Substring Invariant so the identified vulnerable span is always a valid substring of the generated prefix, preventing hallucinated targets. A deterministic renderer applies patches atomically via right-most-occurrence resolution upon observing the patch-closure token. Training uses supervised fine-tuning on revision trajectories linearized from real-world CVE code diffs (only ~1,000 positive examples suffice), with semantic embedding initialization for new tokens to avoid cold-start instability. The approach is orthogonal to weight-level alignment (e.g., DPO-based ProSec) and can be stacked on top of security-aligned checkpoints for additional gains.

## Results

On CyberSecEval 2 (CSE2), Stream of Revision achieves a Security Pass Rate (SPR@1) of 78.62% (C/C++ avg) with Qwen2.5-7B, outperforming the base model (70.20%) by 8.42 points and the best baseline SafeCoder (78.20%) by 0.42 points. Across all five evaluated languages, Stream of Revision reaches 75.65% All-Avg SPR@1 with Qwen2.5-7B, surpassing the strongest baseline by up to 6.37% across backbones. On utility (HumanEval C/C++), Pass@1 is preserved or slightly improved (e.g., 54.78% vs. 50.80% base for Qwen2.5-7B), and inference cost increases by only 1.06× in output tokens versus vanilla generation while reducing input tokens by 6.5× compared to a post-hoc agentic repair baseline.

## Baselines & Comparisons

Against SafeCoder (He et al., 2024), Stream of Revision wins on the C/C++ target domain across all three backbones (e.g., 78.62% vs. 78.20% avg for Qwen2.5-7B; 79.78% vs. 77.16% for Qwen2.5-3B; 81.80% vs. 80.69% for CodeLlama-7B) and on the All-Avg security metric (75.65% vs. 73.33% for Qwen2.5-7B; 75.84% vs. 71.30% for Qwen2.5-3B; 78.05% vs. 77.77% for CodeLlama-7B). Against ProSec (Xu et al., 2024), Stream of Revision similarly outperforms on C/C++ (e.g., 78.62% vs. 76.51% for Qwen2.5-7B) and on All-Avg across all backbones (75.65% vs. 71.68%; 75.84% vs. 70.98%; 78.05% vs. 75.98%). On utility (HumanEval Pass@1/Pass@10), Stream of Revision matches or slightly exceeds both baselines, with the notable exception that ProSec achieves a marginally higher Pass@10 on Qwen2.5-3B (84.47% vs. 82.61%). The paper further demonstrates complementarity: stacking Stream of Revision on top of ProSec yields additional gains (C: +1.16%, C++: +4.15%), confirming the two approaches operate on orthogonal axes.

## Relation to Prior Work

This paper departs from the standard monotonic autoregressive decoding paradigm by introducing native revision actions (special tokens) into the output space, rather than relying on external post-hoc agents (Self-Refine, Agentless-style pipelines) or in-decoding static analyzers (Rocode, JumpCoder) to trigger repairs. Conceptually, it repurposes constrained decoding—previously used for grammar enforcement (GCD) or syntactic rollback—toward a semantic purpose: localizing vulnerable spans via a strict substring invariant with dynamic logit masking. The security alignment methods it compares against (SafeCoder, ProSec) operate at the weight level via DPO or instruction tuning, whereas Stream of Revision operates at inference time, making the two approaches orthogonal and composable.

## Why It Matters / Open Questions

The O(1) vs. O(L) efficiency argument for local repairs is practically significant for real-time code completion, and the finding that ~1,000 CVE-derived examples suffice to elicit self-correction behavior suggests the mechanism is data-efficient and potentially transferable to other domains requiring just-in-time correction. Key limitations include restricted handling of multi-hunk vulnerabilities, a 1.55% syntactic regression rate, and the observation that one-third of triggered revisions are non-security refactoring that adds overhead without security benefit. Open questions include whether the revision-token paradigm generalizes to larger models, longer-context tasks, or non-security domains, and whether the deterministic renderer's right-most-occurrence tie-breaking is always semantically correct.
