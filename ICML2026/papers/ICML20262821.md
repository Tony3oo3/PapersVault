## Problem

Existing differentially private code generation methods protect code snippets while assuming prompts are public, but realistic instruction-code datasets often contain sensitive information in prompts (PII, internal task descriptions, example code fragments). When both prompts and code must be treated as private, removing explicit prompt conditioning causes severe utility degradation, reduced diversity, and syntactic structure collapse in generated code, making prior DP code synthesis frameworks inapplicable.

## Input / Output

The method consumes sensitive (prompt, code) pairs where both components are private, processing them through a junior LLM (Qwen2.5-Coder-1.5B) under DP-SGD with per-sample gradient clipping. During generation, no original prompt or code is accessed; instead, latent variables are sampled from a standard normal prior and decoded into 8 virtual prefix token embeddings that condition autoregressive code synthesis. The final output is a filtered synthetic instruction-code dataset (code snippets plus instructions summarized by a public LLM) used to fine-tune a premium model via standard SGD without any DP constraint, incurring zero additional privacy cost by the post-processing property.

## Method

PrivCode++ introduces a Privacy-Free Latent Conditioning (PrivLC) module comprising a VAE-style code encoder, a prompt encoder used only for contrastive alignment during training, and a prefix decoder that maps continuous latents to K virtual token embeddings. In the privacy-sanitizing stage, all components are jointly trained under DP-SGD with a unified privacy accountant, optimizing cross-entropy code generation conditioned on prefix embeddings, a VAE KL regularization toward N(0,I), a contrastive InfoNCE alignment loss between code-induced and prompt-induced latents, and a syntax-aware KL loss against a frozen reference model with exponential decay weighting. In the utility-boosting stage, latent variables are sampled from the prior, decoded into prefix embeddings, and used to condition autoregressive code generation on the DP-trained junior model, introducing novel yet structurally coherent code patterns beyond the training distribution. Generated snippets are summarized into instructions by a public LLM and filtered through execution and round-trip semantic validation before fine-tuning a premium model, with all post-processing steps incurring no additional privacy budget.

## Results

Under ε=4, PrivCode++ achieves the best Pass@1 among all joint-sensitive protection methods across four premium models and six benchmarks. With Qwen2.5-Coder-7B, PrivCode++ scores 68.3 on HumanEval (Instruct), 68.0 on MBPP (Instruct), and 43.3 on BigCodeBench-Full (Complete), surpassing PrivCode (66.5, 66.5, 27.9) on several metrics despite providing stronger privacy guarantees. The paper reports improvements of up to 8.2 Pass@1 on instruction-following tasks and 19.3 on code completion tasks over the strongest joint-sensitive baseline. In canary leakage evaluations, PrivCode++ achieves 0% leakage across all canary types and injection counts, whereas PrivCode exhibits up to 40% category-level leakage under joint canaries.

## Baselines & Comparisons

PrivCode++ is compared against PrivCode (Liu et al., 2025), which assumes prompts are public and thus provides only partial privacy protection, and DPFT (Charles et al., 2024), which jointly optimizes prompt and code tokens under DP-SGD. Against PrivCode, PrivCode++ matches or exceeds performance on several key metrics despite operating under the stricter joint-sensitive setting: with Qwen2.5-Coder-7B, PrivCode++ improves HumanEval (Instruct) from 66.5 to 68.3 and BigCodeBench-Full (Complete) from 27.9 to 43.3, though PrivCode retains an edge on MBPP (Instruct: 78.3 vs. 68.0). Against DPFT, PrivCode++ achieves substantially higher Pass@1 across all benchmarks and models (e.g., 68.3 vs. 62.2 on HumanEval Instruct with Qwen2.5-Coder-7B; 43.3 vs. 15.9 on BigCodeBench-Full Complete). In canary leakage tests, PrivCode++ achieves 0% leakage across all settings, while PrivCode leaks up to 40% under joint canaries at count=100, and DPFT leaks up to 100% under non-DP fine-tuning. The two PrivCode++ variants (PC-PreEmb, PC-PromptEmb) confirm that code-derived latent conditioning is more effective than prompt-only or public-pretrained conditioning for maintaining utility under the joint-sensitive constraint.

## Relation to Prior Work

This paper extends PrivCode (Liu et al., 2025), the first DP code generation method, which protected code snippets while assuming prompts were public and safe to use as conditioning signals. PrivCode++ departs from this by treating both prompts and code as sensitive (the joint-sensitive setting), which necessitates removing explicit prompt conditioning entirely. To compensate, it introduces the PrivLC module—a VAE-style latent encoder-decoder trained under DP-SGD with contrastive alignment to prompt embeddings—that replaces discrete prompt tokens with continuous prefix embeddings, drawing on latent-variable text generation (Bowman et al., 2016) and prefix-tuning (Li & Liang, 2021) but integrating them under formal DP guarantees for the first time.

## Why It Matters / Open Questions

This is the first method to provide comprehensive DP protection for both prompts and code in LLM fine-tuning, addressing a realistic threat model where instructions may contain PII, internal task descriptions, or example code fragments. The 0% canary leakage across all settings (versus up to 40% for PrivCode under joint canaries) combined with competitive utility demonstrates that the joint-sensitive constraint need not come at a prohibitive cost. Open questions include whether the latent-conditioning approach scales to much larger models or longer code sequences, whether it generalizes to other structured-text domains beyond code, and how the privacy-utility trade-off behaves at very small budgets (ε < 1) where the paper shows utility degrades sharply.
