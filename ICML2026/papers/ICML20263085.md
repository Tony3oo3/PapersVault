## Problem

Repository-level agents suffer from a reasoning disconnect because existing representations are fragmented: API documentation captures semantic intent but lacks global navigability, while dependency graphs encode structural logic but provide limited semantic depth. The paper argues this gap is systemic, arising from treating repository comprehension and generation as isolated unidirectional tasks rather than inverse pathways within a unified reasoning cycle, and asks whether the Repository Planning Graph (RPG) can be generalized from a static generative blueprint into a unified, high-fidelity representation that closes this loop.

## Input / Output

The method consumes a raw codebase (files, classes, functions) and commit diffs as input, and produces a hierarchical dual-view graph G=(V,E) where each node v=(f,m) pairs a semantic feature f (e.g., 'handles authentication') with structural metadata m (type, path), and edges partition into functional hierarchy edges E_feature and AST-derived dependency edges E_dep. For understanding tasks, the RPG is queried via natural-language intent to return ranked localized code entities (file paths, qualified function identifiers). For reconstruction, the RPG serves as an exclusively topologically-ordered blueprint that drives sequential code generation, producing a full repository with 98.5% functional coverage.

## Method

RPG-Encoder implements three cohesive mechanisms to transform RPG into a bidirectional representation. (1) Encoding: a three-phase pipeline performs semantic lifting (extracting atomic verb-object features per function via prompted LLM parsing), latent architecture recovery (inducing a three-level functional hierarchy from file-level features using granularity-based context compression), and artifact grounding (anchoring abstract nodes to physical directories via Trie-based LCA propagation and injecting dependency edges via AST analysis). (2) Evolution: incremental maintenance parses commit diffs into atomic DELETE/MODIFY/INSERT operations, with a semantic-drift threshold that triggers structural re-routing only when functional intent shifts beyond the current parent's scope, reducing maintenance cost by 95.7% versus full reconstruction. (3) Operation: the RPG is exposed as a unified agentic interface with three tools—SearchNode (intent-to-code mapping via semantic features or keyword search), FetchNode (precision source retrieval with line ranges), and ExploreRPG (topological traversal along dependency and functional edges)—enabling a 'search-then-zoom' navigation pattern that couples semantic breadth with structural precision.

## Results

On SWE-bench Verified, RPG-Encoder with Claude-4.5-Sonnet achieves 93.7% Acc@5 at the function level, surpassing the best baseline (OrcaLoca) by 14.4 points, while also improving Precision by 6.9% and Recall by 10.7%. On SWE-bench Live, RPG-Encoder with GPT-5 reaches 87.8% function-level Acc@5, outperforming the next-best method (CoSIL) by 11.6 points. For repository reconstruction on RepoCraft, RPG-Encoder with GPT-5-mini attains 98.5% functional coverage and an 86.0% unit-test pass rate, compared to 74.2% coverage and 52.6% pass rate for the documentation-based baseline (ZeroRepo-Doc), while reconstructing 550K code tokens versus only ~17% of the original volume for the baseline.

## Baselines & Comparisons

RPG-Encoder consistently outperforms all four localization baselines across both benchmarks and all backbone models, with the largest margins at the function level. Against Agentless (text-based narrowing without graph priors), RPG-Encoder gains 25.5 points in function-level Acc@5 on SWE-bench Verified (93.6% vs. 68.1% with GPT-5), confirming that structural topology is critical for fine-grained localization. OrcaLoca (dynamic execution signals + agentic planning) is the strongest file-level competitor (94.4% vs. 97.7%) but trails by 7.3 points on function-level Acc@5, indicating that execution traces alone cannot substitute for semantic-structural coupling. LocAgent (dependency-graph traversal) and CoSIL (iterative call-graph search) both achieve competitive file-level scores but lag by 13.3 and 11.8 points respectively on function-level Acc@5 with GPT-5, as their single-view graph representations lack the dual semantic+topological structure. On the reconstruction task, ZeroRepo-Doc (API documentation as the sole planning source) achieves only 74.2% coverage and 52.6% pass rate with GPT-5-mini, while RPG-Encoder reaches 98.5% and 86.0%, a gap of over 24 and 33 points respectively, demonstrating that unstructured documentation cannot serve as a sufficient blueprint for faithful repository reconstruction.

## Relation to Prior Work

This paper directly extends RPG (Luo et al., 2025), which was originally designed as a static generative blueprint for intent-to-code synthesis, by inverting its role into a comprehension substrate that maps existing code back into a structured semantic space. Conceptually, it departs from the fragmented-representation paradigm where API documentation provides semantics without navigability and dependency graphs provide structure without intent, by unifying both into a single dual-view hierarchical graph. The incremental evolution mechanism (differential commit-based updates) is a practical departure from prior graph-based localization agents (LocAgent, CoSIL, OrcaLoca) that typically require static or periodically rebuilt graphs, decoupling maintenance cost from repository scale.

## Why It Matters / Open Questions

The 95.7% reduction in maintenance overhead via incremental updates addresses a critical scalability bottleneck for deploying structured representations in real-world, continuously evolving codebases, making graph-guided agents viable beyond one-shot benchmarks. The reconstruction result (98.5% coverage, 550k tokens vs. ~17% code volume from documentation) provides strong evidence that a structured intermediate representation can serve as a lossless blueprint, which has implications for code migration, refactoring, and documentation generation. Open questions include whether the LLM-based semantic lifting generalizes robustly across programming languages and repository scales beyond Python, and whether the three-level hierarchy remains navigable for very large monorepos with thousands of modules.
