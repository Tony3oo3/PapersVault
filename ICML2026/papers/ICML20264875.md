## Problem

LLM-based agents with external and internal memory are vulnerable to multi-turn extraction attacks that use benign-looking queries to gradually exfiltrate sensitive data, yet existing defenses rely on per-query LLM inference that introduces latency and cannot aggregate evidence across interaction steps. No prior defense proactively reshapes the memory distribution to amplify adversarial signals while maintaining zero online cost and preserving service quality for normal users.
![Teaser figure](../imgs/ICML20264875/cropped_page0_idx0.webp)

## Input / Output

The method takes as input a stream of user queries (encoded as sentence embeddings via all-mpnet-base-v2) and a memory index containing both real document embeddings and P optimized honeypot embeddings. At each retrieval round, the system checks whether honeypots appear in the top-k results and accumulates a log-likelihood ratio; the output is a binary detection decision (block/allow) triggered when the accumulated statistic crosses SPRT boundaries, plus a set of generated honeypot text documents that are semantically aligned with their optimized vectors, factually entailed by safe content, and dissimilar to the real database. Detection incurs zero additional inference latency since it only inspects retrieval indices and similarity scores already computed by the agent's existing pipeline.

## Method

MemPot employs a two-stage optimization: first, honeypot embeddings are trained in vector space by minimizing an InfoNCE contrastive loss (with a diversity regularizer) against a neural attacker proxy and LLM-simulated benign queries, which the paper proves upper-bounds the KL information drift and thus minimizes expected SPRT stopping rounds; second, these vectors are inverted into concrete text via scorer-guided beam-search decoding that jointly maximizes embedding alignment, NLI-based factuality, and negative database similarity. Detection formalizes the sequential problem as Wald's SPRT, accumulating per-round log-likelihood ratios estimated from pot/non-pot retrieval counts (or similarity-weighted variants), and stops when the statistic crosses boundaries set by type-I/II error budgets. The key theoretical result (Theorem 2) shows that honeypot-augmented SPRT achieves strictly lower average sample number than any static fixed-length detector at the same error level, because the optimized honeypots actively reshape the retrieval distribution to amplify the attacker–benign gap rather than passively observing an indistinguishable original distribution.

## Results

On internal memory extraction (EHRAgent and RAP WebShop), MemPot achieves 0.94–1.00 AUROC across all four attack types (MEXTRA-Cosine, MEXTRA-Edit, MEXTRA-General, IKEA), while baselines collapse to near-random performance (0.40–0.67 AUROC). On external memory (HealthMagicCare, Pokémon), MemPot maintains ≥0.96 AUROC against all attacks including the stealthy IKEA attack, where baselines drop to ~0.50 AUROC. MemPot achieves zero online inference delay (0 s) compared to 0.04–1.01 s for baselines, and reduces First Detection Time (FDT) to 1–9 rounds versus 11–42 rounds for the Optimal Sequential Detector. Under strict TPR@1%FPR constraints, MemPot reaches 0.81–1.00 versus 0–0.20 for baselines on internal memory.

## Baselines & Comparisons

Against ControlNet (single-turn embedding-level distribution shift detection), MemPot wins decisively on every metric: on internal memory, ControlNet achieves only 0.40–0.63 AUROC (near-random) while MemPot reaches 0.94–1.00, and ControlNet's TPR@1%FPR is 0–0.02 versus MemPot's 0.81–1.00. Against the LLM-based Agent detector (intention + keyword + defensive prompt), MemPot similarly dominates: the Agent baseline scores 0.47–0.81 AUROC with 0.88–1.01 s per-turn delay, while MemPot achieves 0.94–1.00 AUROC at zero delay. The gap is most dramatic against the stealthy IKEA attack, where both baselines drop to ≤0.51 AUROC on EHRAgent but MemPot maintains 1.00. Against the theoretical Optimal Sequential Detector (no honeypots, optimal SPRT on original distributions), MemPot still wins on AUROC (e.g., 0.99 vs 0.70 on MEXTRA-Cosine/EHRAgent) and reduces FDT from 22 to 2 rounds, empirically validating Theorem 2 that honeypot-augmented SPRT outperforms any static or honeypot-free sequential test. MemPot also outperforms baselines under a weaker random-walk attacker proxy (0.99 AUROC vs 0.71–0.88 for ControlNet/Agent), confirming robustness to proxy quality.

## Relation to Prior Work

This paper builds on Wald's Sequential Probability Ratio Test (SPRT) to formalize attacker detection as a sequential hypothesis testing problem, and on scorer-guided LLM decoding (Zhang et al., 2025) to generate readable honeypot documents from optimized embeddings. It departs from prior defenses (ControlNet, LLM-based Agent detectors) in two fundamental ways: (1) replacing static per-query detection with sequential evidence aggregation across interaction turns, and (2) actively reshaping the retrieval distribution via optimized honeypot injection rather than passively monitoring query patterns. The contrastive (InfoNCE) training objective for honeypot vectors is novel in this context, linking embedding-space optimization to KL-divergence-based detection efficiency through a proven upper-bound relationship.

## Why It Matters / Open Questions

MemPot addresses a practically urgent gap: LLM agent memory systems (both external RAG databases and internal interaction histories) are increasingly deployed in high-stakes domains (healthcare, finance) yet lack theoretically grounded defenses against stealthy extraction attacks. The zero-online-latency property is significant for interactive agent deployments where per-query LLM-based detectors introduce unacceptable delay. Open questions include: how the defense performs when attackers specifically learn to avoid honeypot documents, whether the attacker-proxy assumption (requiring 256 historical attack samples) holds in truly novel attack scenarios, and how honeypot optimization scales to memories with millions of documents. The paper's reliance on a fixed honeypot ratio and a single embedding model (all-mpnet-base-v2) for most experiments also leaves generalization questions open.
