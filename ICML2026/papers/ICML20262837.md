## Problem

Existing GUI agents depend on static parametric knowledge from pre-training, making them brittle on long-tailed, application-specific tasks that require explicit procedural instructions absent from model parameters. No prior benchmark evaluates whether an agent can autonomously navigate a web browser to locate relevant online documentation and faithfully ground those instructions into executable GUI actions within a single interactive environment.
![Teaser figure](../imgs/ICML20262837/cropped_page1_idx0.webp)

## Input / Output

The agent receives a natural-language task instruction and operates in a Docker+QEMU desktop environment where observations are full-screen captures at 1920×1080 resolution; web browsing is restricted to Microsoft Edge with human-like natural-language queries. The task is split into two fixed-budget phases: 15 steps for proactive document search (scored by Target URL Inclusion and Hierarchical Path Progress) followed by 50 steps for document-grounded execution (scored by Task Completion Rate). The output is a sequence of 16 atomic pyautogui actions (CLICK, TYPING, SCROLL, HOTKEY, etc.) ending in a DONE or FAIL verdict.

## Method

DocOS formalizes the interaction as a POMDP with two sequential policies: π_retr navigates search engines and official help centers to retrieve a target document D, and π_exec conditions action generation on both the user instruction I and the retrieved document D, explicitly decoupling reasoning from stored domain knowledge. The benchmark contains 817 manually constructed tasks across 20 applications (PyCharm, Blender, Postman, Godot, VS Code, etc.), each paired with an authoritative documentation URL, built via a three-stage pipeline of task construction, automated document crawling with boilerplate removal, and multi-stage filtering for semantic consistency and executability. The evaluation protocol separates search accuracy (TUI, HPP) from execution fidelity (TCR) and further isolates bottlenecks by comparing full-pipeline, oracle-document, and no-document settings. Six MLLM-based GUI agents (Qwen3-VL-8B, UI-TARS-1.5-7B, MAI-UI-8B, GELab-Zero-4B, Aguvis-7B, GUI-Owl-7B) are evaluated, revealing that even with oracle documents, agents struggle to faithfully ground retrieved instructions into precise GUI actions, exposing dual bottlenecks in both document localization and instruction-to-action grounding.

## Results

On DocOS (817 tasks, 20 applications), all evaluated GUI agents exhibit severely limited end-to-end task completion, with the best average TCR of only 17.31% (UI-TARS-1.5-7B) and most agents below 6%. The benchmark reveals a dual bottleneck: Qwen3-VL-8B achieves the highest Target URL Inclusion (TUI) at 42.23% but only 4.23% TCR, while UI-TARS-1.5-7B achieves the highest TCR (17.31%) yet a mere 2.48% TUI. Performance degrades sharply with difficulty, dropping from ~30% TCR on Easy to ~13% on Hard for the best model, and near 0% for most agents on Hard tasks.

## Baselines & Comparisons

No single agent dominates both the search and execution phases, confirming the paper's dual-bottleneck thesis. UI-TARS-1.5-7B leads in Task Completion Rate (17.31% avg TCR, 30.86% on Easy) but achieves only 2.48% TUI, meaning it rarely locates the correct documentation page. Qwen3-VL-8B is the strongest searcher (42.23% TUI, 44.53% on Easy) yet completes only 4.23% of tasks end-to-end, indicating a severe grounding gap. MAI-UI-8B occupies a middle ground (10.96% TCR, 2.89% TUI), while GELab-Zero-4B-preview (4.36% TCR) and GUI-Owl-7B (5.58% TCR) show moderate execution but weak search. Aguvis-7B is the weakest overall (1.95% TCR, 0.00% TUI), failing to navigate the web environment at all. The larger Qwen3-VL-32B (Appendix E) improves TCR to 6.21% and TUI to 45.66%, but the gap between search and execution persists, suggesting scale alone does not resolve the grounding bottleneck.

## Relation to Prior Work

This paper builds directly on OSWorld's Docker/QEMU infrastructure and 16-atomic-action space, but departs fundamentally from the assumption that GUI agents possess sufficient parametric knowledge to complete tasks. While retrieval-augmented GUI agents (Xie et al., 2025; Zhang et al., 2025) introduce external information at inference time, they assume documents are pre-collected and do not test autonomous acquisition. DocOS carves new ground by formalizing 'Proactive Document-Guided Action' as a two-phase POMDP (retrieval then grounded execution) and is, to the authors' knowledge, the first benchmark to evaluate both phases in a unified, fully interactive desktop environment with live web access.

## Why It Matters / Open Questions

The dual-bottleneck finding — that agents fail both at localizing relevant documentation and at faithfully grounding retrieved instructions into precise GUI actions — provides a clear diagnostic roadmap for the field. The observation that even oracle documents yield only modest gains (3–10%) for strong models like UI-TARS and Qwen3-VL challenges the working assumption that 'just feed the agent the right document and it will work,' pointing to a deeper context-processing and long-horizon planning gap. Open questions include how to improve in-documentation navigation (agents reach high-level pages but miss specific sections), how to handle the near-0% pass rate on tasks exceeding 4 steps, and whether the paradigm generalizes beyond the 20 desktop applications covered.
