## Problem

Existing memory systems for GUI agents store long-horizon workflows as static, indivisible sequences, creating a granularity mismatch between high-level intent and low-level execution that becomes brittle under dynamic UI layout shifts. Without evolutionary selection, outdated and suboptimal trajectories accumulate unchecked as toxic priors, driving agents into hallucination and sustained inefficiency. The paper asks whether a self-regulating, training-free memory architecture can resolve both rigidity and stagnation simultaneously without architectural overhead.

## Input / Output

The system operates within a Planner-Actor framework: the Planner receives a screenshot, UI element JSON, and a natural-language task instruction to emit 1–5 sub-tasks in a structured ⟨Precondition, Goal⟩ format, while the Actor produces atomic GUI actions (tap, swipe, input_text, press_key, etc.) grounded at 1080×2400 resolution. Memory entries are stored as tuples of a natural-language plan (serving as the semantic index), a dense execution trajectory of (observation, action) pairs, and metadata; single-step trajectories are filtered out to preserve information density. Retrieval uses a multiplicative cosine similarity over precondition and goal embeddings separately, so a memory is recalled only when both the starting-state context and the intended objective align, reducing false positives from partial matches.

## Method

DMS restructures agent memory as a dynamic ecosystem governed by survival-of-the-fittest, decomposing monolithic workflows into independent, reusable precondition-goal units that bypass redundant MLLM reasoning when retrieved. A composite survival value—combining logarithmic marginal utility with a cold-start bonus, sigmoid-based adaptive temporal decay whose half-life extends with usage, and a reliability penalty from a K-strike post-execution verifier—drives autonomous pruning via the Elbow Method on the ranked utility curve, with a safeguard that expands capacity when the overflow is high-quality. To prevent trapping in local optima, an ε-mutation strategy probabilistically re-explores even high-confidence memories, triggering in-place evolutionary replacement when a shorter successful trajectory is discovered. A Bayesian Beta-Binomial reputation model tracks per-plan failure probability with uncertainty-aware risk scoring (lower confidence bound), and a dynamic rejection threshold that tightens under high global error rates suppresses high-risk plans, generating evolutionary pressure that compels the agent to discover and capture superior strategies.

## Results

On the AndroidWorld benchmark, DMS-PA-Lite with Qwen2.5-VL-72B achieves a 66.4% success rate, establishing a new state-of-the-art that surpasses the closest competitor UI-Venus (65.9%) and proprietary GPT-4o (34.5%) by 31.9 points. The method is strictly training-free and yields consistent gains across all tested backbones: +25.4% (Qwen2.5-VL-72B), +19.0% (Qwen3-VL-30B), +15.0% (Seed1.6-VL), and +12.4% (GLM-4.5V) over their respective PA-Lite baselines. DMS also improves execution stability (SRR) by up to 33.9% (Qwen3-VL-30B: 36.5%→84.7%) and reduces task latency through memory reuse, which stabilizes at 30–36% of actions after five rounds.

## Baselines & Comparisons

DMS-PA-Lite (Qwen2.5-VL-72B, 66.4%) outperforms all 15 baselines in Table 1, including the closest competitor UI-Venus (65.9%, +0.5%), MobileUse (62.9%, +3.5%), Seed1.5-VL (62.1%, +4.3%), V-Droid (59.5%, +6.9%), Agent-S2 (54.3%, +12.1%), and GPT-4o (34.5%, +31.9%). Critically, DMS is training-free while many strong baselines (UI-Venus, MobileUse, EchoTrail-GUI, UI-TARS) require supervised fine-tuning or reinforcement learning, yet DMS still surpasses them. Against the memory-augmented baselines specifically—EchoTrail-GUI (46.6% on Qwen2.5-VL) and MobileUse (62.9%)—DMS gains 19.8 and 3.5 points respectively, demonstrating that its evolutionary pruning and dual-factor retrieval outperform static or reflection-based memory. The gains are consistent across model scales: even the smallest backbone (Qwen3-VL-30B, 44.0%) exceeds the larger GPT-4o (34.5%) and Claude (27.9%) by 9.5 and 16.1 points, confirming that DMS unlocks latent planning capability rather than merely compensating for model weakness.

## Relation to Prior Work

DMS builds on the hierarchical Planner-Actor architecture established by UFO (Zhang et al., 2025a) and Cradle (Tan et al., 2024), but fundamentally restructures the memory paradigm that underpins long-horizon GUI agents. Where prior memory systems (EchoTrail-GUI, MobileUse, R2D2, H2R, MemEvolve) store monolithic trajectories with static accumulation, DMS decomposes workflows into reusable precondition-goal units and governs them through an evolutionary selection pressure (utility-driven pruning, ε-mutation, Bayesian risk suppression). This positions the work at the intersection of retrieval-augmented generation for agents and evolutionary computation, departing from the RAG-as-in-context-demonstration framing that dominates the GUI agent memory literature.

## Why It Matters / Open Questions

The training-free, backbone-agnostic design makes DMS a practical plug-in for deploying general-purpose MLLMs as GUI agents without domain-specific fine-tuning, which is significant given the cost of SFT/RL pipelines. The ablation revealing that naive goal-only retrieval (29.7%) underperforms the memory-free baseline (41.0%) is a useful cautionary result: in non-stationary GUIs, poorly-structured memory actively degrades reasoning through negative transfer. Open questions include whether the evolutionary mechanism generalizes beyond Android to desktop or web environments, how it scales to truly open-ended task distributions (vs. AndroidWorld's 116 parameterized tasks), and whether the ~30–36% reuse ceiling imposed by Dual-Factor Retrieval represents a fundamental limit or a tunable design choice.
