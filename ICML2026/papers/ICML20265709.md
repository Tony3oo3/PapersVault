## Problem

Scaling up RL for language models is limited by two issues: collecting large volumes of problems with ground-truth answers is expensive, and static problem distributions cause learning to stall when problems become too easy (no learning signal) or too hard (consistently poor rewards impede gradient updates). Existing RLVR approaches fix the problem distribution at training time, preventing adaptation to the policy model's evolving capabilities and leading to early saturation or inefficient learning.

## Input / Output

The method takes a base, SFT, or RL-trained language model (e.g., Qwen2.5-7B-Base, R1-Distill-Qwen-1.5B, ProRL-1.5B-v2, OpenThinker3-1.5B) and a collection of verifiable environments, each defined as a tuple of an input template, a procedural problem generator, and an algorithmic verifier. During training, the environment generates an unbounded stream of problems at dynamically adjusted difficulty levels; the model produces text rollouts (up to 24,576 tokens for 1.5B models) which are scored by the verifier. The output is a fine-tuned language model with improved generalizable reasoning, evaluated on six benchmarks spanning mathematics, code generation, and logical reasoning.

## Method

RLVE introduces adaptive verifiable environments where each environment maintains a difficulty range [ℓ_π, h_π] that shifts upward whenever the model's accuracy at the current upper bound exceeds a threshold (τ_acc = 90% over at least τ_num rollouts), with a sliding window of size d_Δ=4 preventing unbounded range expansion. The 400-environment suite RLVE-GYM is built through manual environment engineering following two principles: (1) environments serve as pedagogical tools for reasoning (e.g., manually sorting arrays rather than executing a sort program), and (2) verification exploits environment advantages over the LM, particularly the solving-verification asymmetry in NP-complete problems (e.g., generating a valid Sudoku by masking a complete solution, then verifying outputs via simple rule-checking). Training uses DAPO (a GRPO variant) with dynamic sampling that discards prompts whose rollouts yield identical rewards, and jointly samples across all environments uniformly. The key empirical finding is that environment scaling—expanding the collection of distinct verifiable environments—consistently improves out-of-distribution generalization, and adaptive difficulty maintains a high effective prompt ratio (proportion of problems that are appropriately challenging) compared to any static difficulty distribution.

## Results

In the data-saturation scenario, RLVE starting from ProRL-1.5B-v2 achieves a 3.37% absolute average improvement across six reasoning benchmarks (AIME 2024/2025, OMEGA-500, OlympiadBench, LiveCodeBench, BBEH) within ~1,100 H100 GPU hours, compared to only 0.49% from continuing the original RLVR training on the ProRL dataset using 3,600 H100 GPU hours (3× more compute). In the compute-constrained scenario, RLVE starting from OpenThinker3-1.5B outperforms RLVR on DeepMath-103K by approximately 2% in absolute average improvement under an identical training setup, with consistent gains on non-mathematical benchmarks (LiveCodeBench, BBEH) and most mathematical benchmarks (OMEGA-500, OlympiadBench), while achieving comparable AIME scores with peak performance exceeding DeepMath-103K by roughly one point.

## Baselines & Comparisons

The paper compares RLVE against two baselines. First, against continuing the original RLVR training on the ProRL dataset (Hu et al., 2025b), RLVE achieves a 3.37% absolute average improvement across six reasoning benchmarks in ~1,100 H100 GPU hours, while the continued RLVR baseline yields only 0.49% (a 7× smaller gain) despite using 3,600 H100 GPU hours—demonstrating that RLVE effectively scales beyond the data-saturation point of one of the strongest open-sourced 1.5B RL LMs. Second, against RLVR on DeepMath-103K (He et al., 2025), a high-quality math-specific RLVR dataset, RLVE consistently outperforms by approximately 2% in absolute average improvement under an identical training setup starting from OpenThinker3-1.5B. RLVE wins on LiveCodeBench, BBEH, OMEGA-500, and OlympiadBench, and achieves comparable AIME 2024/2025 scores with peak performance exceeding DeepMath-103K by roughly one point. Notably, RLVE requires no benchmark-specific data and its 400 environments were constructed at substantially lower cost than DeepMath-103K, which required ~$138,000 USD and 127,000 GPU hours to build.

## Relation to Prior Work

This paper extends the RLVR paradigm (Lambert et al., 2025; DeepSeek-AI, 2025) by replacing static, finite problem distributions with procedurally generated verifiable environments whose difficulty adapts to the policy's evolving capabilities. It departs from prior curriculum-learning approaches for LMs (Kimi Team, 2025b; Shi et al., 2025; Chen et al., 2025b), which reorder a fixed dataset post hoc, by predefining unbounded difficulty levels over an infinite problem set and progressing through them adaptively. The environment-scaling axis (400 environments) builds on observations from classical RL (Cobbe et al., 2020) and recent LM work (Li et al., 2025) that task diversity aids generalization, but provides the first controlled OOD evaluation confirming this for LM RL. The RL algorithm itself (DAPO, a GRPO variant) is standard; the contribution is entirely in the data-generation and difficulty-adaptation layer.

## Why It Matters / Open Questions

The 7× efficiency gap over continued RLVR training on a model already saturated after 20,000+ H100 GPU hours (3.37% vs. 0.49% with 3× less compute) demonstrates that adaptive verifiable environments can break through data-saturation plateaus, a practical bottleneck for current LM post-training pipelines. The finding that environment diversity, not data volume within a single environment, drives generalizable reasoning suggests a new scaling axis for RL that is substantially more cost-efficient than hand-curated datasets like DeepMath-103K ($138K, 127K GPU hours). Key open questions include whether these gains transfer to 7B+ models, how to extend the framework to non-verifiable tasks (creative writing, deep research) where algorithmic reward is infeasible, and whether automatic environment engineering can replace the substantial manual effort behind RLVE-GYM.
