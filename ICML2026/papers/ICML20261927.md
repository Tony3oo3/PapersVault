## Problem

LLM serving costs remain prohibitively high because production workloads exhibit extreme heterogeneity in request length distributions and compute-versus-memory demands, causing different inference phases to become bottlenecks at different times. Existing disaggregated serving systems either only split prefill from decoding (missing the attention-FFN split) or rely on static resource provisioning that cannot adapt to workload fluctuations, leading to resource stranding and suboptimal cost-efficiency.
![Teaser figure](../imgs/ICML20261927/cropped_page0_idx1.webp)

## Input / Output

The system consumes text LLM requests (with Poisson arrivals and empirically sampled input/output token lengths) alongside a heterogeneous GPU cluster specification (counts of each GPU type, e.g., H100 and H20). Beyond the generated text tokens, the framework internally produces a 3×N resource allocation matrix (GPUs of each type assigned to prefill, attention, and FFN workers) and per-group parallelism tuples (data/tensor/expert parallelism degrees) that are jointly optimized. The scheduling core is provisioning-agnostic: it can be re-invoked on any new resource allocation, making it the reusable optimization backbone for both static deployment and dynamic autoscaling.

## Method

HEXGEN-3 introduces a fully disaggregated architecture that separates prefill, attention, and FFN workers onto independent GPU pools, coupled with a two-level scheduling framework. The global scheduler formulates resource allocation as a finite-horizon MDP solved via Simulated Annealing, using a guided generation policy that biases GPU transfers from high-throughput (overprovisioned) to low-throughput (bottleneck) worker types based on a throughput profile fed back from the local scheduler. The local scheduler performs constrained enumeration over valid (DP, TP, EP) parallelism tuples per worker group, respecting topology and divisibility constraints, and selects the configuration maximizing estimated throughput via a roofline-based discrete-event simulator. For dynamic workloads, an autoscaling layer monitors per-worker-type throughput pressure (observed/target ratio) with hysteresis bands, applies proportional control to determine scaling magnitude, and triggers deployment rescheduling using warm-start optimization (preserving existing TP/EP while adjusting DP) and a cost-aware objective that only reconfigures parallelism when the throughput gain amortizes the model-reloading downtime within the expected stability window.

## Results

Under static resource provisioning, HEXGEN-3 achieves up to 60% (on average 46.5%) improvement in per-cost throughput (req/$) over state-of-the-art baselines across four real-world workloads (WildGPT, OpenThoughts, OpenR1-Math, NuminaMath) using Qwen3-30B-A3B. With autoscaling enabled under dynamic workloads, the improvement reaches up to 78.3% (on average 55.1%) in per-cost throughput. On a larger-scale evaluation with Mixtral-8x22B on 48 H100 GPUs, HEXGEN-3 improves token/s throughput by 14.2%–23.9% over SGLang. Under a 50 ms TPOT SLO on 8×H100, HEXGEN-3 delivers 10.1%–20.0% higher throughput than SGLang while keeping P95 inter-token latency below 50 ms.

## Baselines & Comparisons

HEXGEN-3 (Homo) outperforms SGLang (prefill-decoding disaggregation only) by 16.6% on average and up to 21.6% in per-cost throughput, demonstrating the benefit of adding attention-FFN disaggregation on top of prefill-decoding splitting. Against MegaScale-Infer (homogeneous AFD baseline), HEXGEN-3 (Homo) achieves 28.7% average and up to 36.8% improvement, validating the hierarchical scheduling framework's resource allocation and parallelism optimization. In the heterogeneous setting, HEXGEN-3 outperforms HexGen-2 (heterogeneous prefill-decoding disaggregation) by 20.3% on average and up to 25.8%, showing that AFD further boosts heterogeneous serving efficiency. Under dynamic workloads, HEXGEN-3 (Autoscale) beats HeteroScale (Autoscale) by 14.8% on average and up to 15.8%, attributable to its finer-grained independent scaling of attention and FFN workers. Overall, HEXGEN-3 (Autoscale) achieves up to 78.3% and on average 55.1% per-cost throughput improvement over all non-autoscaling baselines, confirming that fine-grained autoscaling is essential for cost-efficient LLM serving under production traffic.

## Relation to Prior Work

HEXGEN-3 sits at the intersection of three established research threads: disaggregated LLM inference (DistServe, Splitwise, Mooncake, MegaScale-Infer), heterogeneous GPU scheduling (HexGen, HexGen-2, Helix, SpotServe), and LLM serving autoscaling (HeteroScale, TokenScale, ServerlessLLM). Prior disaggregation work either stopped at prefill-decode splitting or used static resource provisioning, and prior autoscaling work operated at the prefill/decode granularity on homogeneous clusters. This paper is the first to jointly optimize a fully three-way disaggregated pipeline (prefill, attention, FFN) over heterogeneous GPU pools with per-operation fine-grained autoscaling, formulating the deployment as a constrained min-throughput maximization solved via a hierarchical MDP + simulated annealing + constrained enumeration pipeline.

## Why It Matters / Open Questions

The 46.5% (static) and 55.1% (dynamic) average per-cost throughput improvements over strong baselines are practically significant for production LLM operators where GPU cost dominates operational expense. The finding that throughput-based metrics outperform utilization, queue, and latency signals for autoscaling triggers provides actionable guidance for system designers. Open questions include whether the simulator's roofline-based timing model remains accurate at much larger model scales (beyond 30B/22B MoE), how the approach handles multi-tenant or multi-model serving, and whether the 13.6% AFD communication overhead stays bounded as sequence lengths grow further. The paper's evaluation is limited to 16–48 GPU clusters and two model families, leaving scalability to hundreds of GPUs and dense models partially unvalidated.
