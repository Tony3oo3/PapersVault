## Problem

No existing benchmark evaluates whether LLMs can perform the complete causal inference pipeline—selecting appropriate variables, choosing the right estimation method, implementing it in code, and interpreting results statistically—on realistic research problems. Prior benchmarks either require pre-specified methods and variables, focus on causal graph discovery rather than effect estimation, or use simplified synthetic settings, leaving a critical gap in understanding LLM reliability for end-to-end causal analysis in empirical research.

## Input / Output

Each benchmark instance provides a tabular dataset (from real publications, textbooks, or synthetic generation), a natural-language causal query, and a structured description covering variable definitions and data collection mechanisms. The LLM agent must produce a justified method selection, identified treatment/outcome/control variables, executable Python code restricted to approved libraries (DoWhy, linearmodels, rdd, statsmodels, scikit-learn), and a structured result block containing the causal effect estimate, standard error, and statistical interpretation. Code execution is sandboxed in Docker containers with up to two repair retries on execution errors.

## Method

CauSciBench comprises 367 queries drawn from three difficulty-graded sources: 100 real-world publication datasets (with reference answers verified from original authors), QRData-CI textbook and standard benchmark problems, and synthetic scenarios with known ground-truth causal effects. Seven frontier models (GPT-4o, GPT-5-mini, OpenAI-o3, Gemini-2.5-Flash-Lite, Grok-4-Fast, GPT-4o-mini, Qwen3-Next-80B-Inst) are evaluated under four prompting strategies (Direct, Chain-of-Thought, Program-of-Thought, ReAct). Evaluation uses three metrics: Method Correctness (macro-averaged F1 across causal inference methods), Effect Accuracy (percentage of estimates within 5% relative error of reference), and Variable Selection Accuracy (overlap of selected versus reference treatment, outcome, and control variables). The key finding is a substantial performance drop on real-world data (45.8% method F1, 14.4% effect accuracy) versus synthetic (69.9%, 53%) and textbook (63.5%, 30.5%) settings, driven primarily by systematic OLS over-selection and poor control variable identification. Fine-grained error analysis reveals that incorrect method selection amplifies estimation errors by 10–22 percentage points in effect accuracy, while treatment and outcome identification remain relatively strong (>75%), and no single prompting strategy dominates across all metrics.

## Results

Across seven frontier models and four prompting strategies, CauSciBench reveals a stark performance gap between real-world and controlled settings. On real-world datasets, average method correctness is only 45.8% and effect accuracy drops to 14.4%, compared to 69.9%/53% on synthetic data and 63.5%/30.5% on QRData-CI. The best-performing model, OpenAI-o3, reaches 72.6% method correctness (ReAct) and 24.5% effect accuracy (Direct) on real data, while GPT-4o-mini lags at 12.6–26.8% method correctness and 4.5–9.9% effect accuracy. A systematic bias toward OLS is observed across all models, with smaller models (e.g., GPT-4o-mini) showing the strongest over-reliance.

## Baselines & Comparisons

CauSciBench does not compare against external causal inference baselines; instead, it benchmarks seven frontier LLMs (OpenAI-o3, GPT-4o, GPT-5-mini, GPT-4o-mini, Gemini-2.5-Flash-Lite, Grok-4-Fast, Qwen3-Next-80B-Inst) under four prompting strategies (Direct, CoT, PoT, ReAct). OpenAI-o3 dominates on method selection (72.6% MC with ReAct on Real) but paradoxically shows the lowest effect accuracy under ReAct (12.2%), suggesting a reasoning–implementation trade-off. GPT-5-mini achieves the best effect accuracy among non-o3 models (25.3% EA with CoT on Real) and near-perfect method selection on Synthetic (91.6% MC with CoT). CoT prompting consistently improves method selection over Direct (e.g., +13.3 pp for Gemini-2.5-Flash-Lite on Real), while ReAct is most efficient for code generation but weaker at reasoning about identification assumptions. The largest performance gap appears between Real and Synthetic settings: even the best model (OpenAI-o3) drops from 91.6% MC (Synthetic, CoT) to 68.5% MC (Real, CoT), and effect accuracy falls from 71.1% to 24.5%, confirming that real-world data complexity—particularly control variable selection and method identification—is the primary bottleneck.

## Relation to Prior Work

This paper extends the LLM causal inference evaluation line initiated by QRData (Liu et al., 2024) and RealCause (Neal et al., 2021), both of which require pre-specified methods and variables, thereby testing only implementation fidelity. CauSciBench departs by requiring the LLM to autonomously select the causal method, identify treatment/outcome/confounding variables, implement the analysis, and interpret results — the full pipeline that prior benchmarks explicitly exclude. It also adapts prompting templates from QRData (Direct, CoT, PoT, ReAct) but restructures them for end-to-end inference rather than method-specific code generation, and draws real-world instances from published empirical studies across economics, healthcare, and political science rather than relying solely on textbook or semi-synthetic data.

## Why It Matters / Open Questions

The benchmark reveals that even frontier models (OpenAI-o3, GPT-5-mini) achieve only ~25% effect accuracy on real-world causal inference tasks, with the primary bottleneck being method selection rather than coding — a finding with direct implications for anyone considering LLM-assisted causal analysis in research. The systematic OLS bias across all models highlights a specific, actionable failure mode: LLMs default to the simplest method regardless of study design, which is particularly dangerous for observational data where unobserved confounders invalidate naive regression. Open questions include whether combining CoT-style reasoning about identification assumptions with ReAct-style iterative implementation can close the gap, and how to evaluate the qualitative justification of causal assumptions (e.g., exclusion restriction, parallel trends) that current automated metrics cannot capture.
