## Problem

Existing code efficiency benchmarks for LLMs evaluate only time efficiency while overlooking space efficiency, despite the well-known time-space trade-off in algorithm design. Moreover, prior benchmarks rely on single baselines, LLM-generated test cases, and coarse-grained evaluation that cannot distinguish between algorithms of different asymptotic complexity. This paper addresses these gaps by introducing the first benchmark that jointly evaluates both time and space efficiency of LLM-generated code.

## Input / Output

Each of the 440 tasks is decomposed into an n×m subtask matrix (typically 3×3), where rows correspond to escalating time limits (e.g., 500 ms → 2000 ms) and columns to tightening memory limits (e.g., 6400 KB → 40 KB), with input scales chosen so that only codes meeting the required asymptotic complexity can pass. The LLM generates C++ code (temperature 0.8, top-p 0.95, 20 samples per subtask), and the output is a dual@k score in [0, 1] computed per task, plus a per-subtask score matrix recording pass@k values. The metric is device-independent after per-environment calibration of time/memory limits using the baselines.

## Method

The core mechanism is a subtask-based evaluation scheme inspired by IOI grading: each task is split into n×m subtasks with distinct time and space limits, each accompanied by expert-crafted Pareto-optimal baselines (multiple per task to capture the time-space trade-off). For each subtask, a pass@k score is computed, forming a score matrix S. A weight matrix W with entries ω(i,j) = τ^(i-1)·σ^(j-1) is designed to satisfy monotonicity, convexity, and supermodularity constraints, rewarding codes that excel in both dimensions more than those strong in only one. The dual@k metric is then the Frobenius inner product ⟨S_eval, W⟩ / ⟨S_std, W⟩, normalizing the LLM's weighted score against the baseline's. By setting τ or σ to 0, the metric reduces to time-only or space-only evaluation, directly generalizing prior eff@k and pass@k metrics.

## Results

On the BEST benchmark (440 tasks, 50 LLMs), Gemini-3-Pro-Preview achieves the highest dual@10 of 0.849 for time-space dual efficiency (τ=σ=1.2), followed by GPT-5.2 (0.811) and DeepSeek-V3.2-Thinking (0.678) among open-source models. For time-only efficiency (τ=1.2, σ=0), Gemini-3-Pro-Preview scores dual@10=0.890, while for space-only efficiency (τ=0, σ=1.2), it scores dual@10=0.868. A key finding is that dual@10 is consistently lower than pass@10 across all 50 LLMs (e.g., GPT-5.2: dual@10=0.811 vs. pass@10=0.879), and space-efficiency scores are generally lower than time-efficiency scores, indicating LLMs are weaker at generating space-efficient code.

## Baselines & Comparisons

The paper compares its dual@k metric against eff@k (Qiu et al., 2024) for time-only evaluation and pass@k (Chen et al., 2021) for correctness. For time efficiency, dual@10 produces rankings roughly consistent with eff@10 (e.g., Gemini-3-Pro-Preview: dual@10=0.890 vs. eff@10=0.923; GPT-5.2: 0.855 vs. 0.898), but dual@k offers greater flexibility in weighting subtasks and avoids hardware-dependent runtime measurements. Against pass@k, dual@10 is uniformly lower (e.g., GPT-5.2: 0.811 vs. 0.879; DeepSeek-V3.2-Thinking: 0.678 vs. 0.845), confirming that correctness does not imply efficiency. At the benchmark level, BEST is the first to jointly evaluate time and space efficiency with Pareto-optimal baselines and subtask-based grading, whereas EffiBench, Mercury, ENAMEL, EvalPerf, COFFE, and EffiBench-X all evaluate time efficiency only (or space separately without a unified metric), lack expert-crafted Pareto baselines, or use LLM-generated test cases rather than expert-designed ones.

## Relation to Prior Work

This paper extends the line of LLM code-efficiency benchmarks (EffiBench, Mercury, ENAMEL, EvalPerf, COFFE, EffiBench-X) that have focused almost exclusively on time efficiency, by introducing the first benchmark and unified metric (dual@k) that evaluates both time and space efficiency simultaneously. It generalizes the pass@k framework from Chen et al. (2021) and the eff@k metric from Qiu et al. (2024) through a Frobenius inner product over a subtask score matrix and a carefully designed weight matrix. The subtask-based evaluation scheme is inspired by IOI grading policies, and the use of multiple Pareto-optimal baselines departs from prior work that relies on single standard implementations, acknowledging the inherent time-space trade-off in algorithm design.

## Why It Matters / Open Questions

BEST fills a clear gap by making space efficiency a first-class evaluation dimension alongside time, which is critical for memory-constrained environments (embedded systems, IoT). The finding that LLMs are systematically worse at space-efficient code generation than time-efficient code generation, and that some models show an inverse correlation between the two, suggests that current training objectives and data distributions underrepresent space optimization. Open questions include whether the C++-specific findings generalize to other languages, whether fine-tuning on space-efficient code can close the gap, and whether the dual@k framework can be extended to additional resource dimensions (e.g., energy). The moderate task count (440) and single-language evaluation limit generalizability.
