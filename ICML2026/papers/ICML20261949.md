## Problem

LLM-based embodied task planners suffer from sequential omission (skipping necessary intermediate actions) and causal inconsistency (contradicting earlier state effects) because they generate action sequences end-to-end via probabilistic reasoning without explicit state tracking. While neuro-symbolic approaches using the action language BC+ offer formal grounding, the prior LLM+AL method relies on one-shot program generation without decomposition or verification, making it brittle in open-world embodied settings with diverse objects and complex dynamics, and prone to producing programs with no solution.

## Input / Output

The method takes a natural language task goal (e.g., 'cook some food') and a structured environment state description (objects with properties, spatial relations, and initial flag values) from the VirtualHome simulator as input. It produces a complete BC+ program consisting of a signature (fluent and action constants) and causal laws (ground rules for action-induced state transitions and restrictions prohibiting invalid actions), which is then executed by an answer-set solver to yield a grounded action sequence with object arguments. The BC+ program is the intermediate artifact; the final output is the executable plan that must satisfy state, relational, and action goal components.

## Method

DecoVer decomposes BC+ program synthesis into five cascading stages—Object Selecting, Action Selecting, Flag Selecting, Ground Rules Generation, and Restrictions Generation—where each stage conditions on the output of the previous one, progressively narrowing the hypothesis space from the full environment to a task-relevant subset. Selection stages use a priority-ordered scoring schema with multiple independent scoring rounds to mitigate LLM stochasticity, and Flag Selecting performs two passes (goal-based and action-based) to recover intermediate-state flags. A dual-verification mechanism integrates static code analysis with LLM self-reflection at the Action Selecting and Ground Rules stages: an independent LLM attempts plan generation to detect missing actions, and a verifier LLM iteratively checks generated rules for static inconsistency and causal misalignment before accepting them. Restrictions are further decomposed into Target Object and Environment Object sub-categories to prevent the LLM from overlooking complex spatial or relational constraints. The final BC+ program is handed to a solver that guarantees physical consistency of the output action sequence, offloading long-horizon state tracking from the LLM to the formal engine.

## Results

On the standard VirtualHome benchmark (298 tasks), DecoVer consistently improves Task Success Rate across all seven LLM backbones, achieving gains of 10.1% (GPT-4o), 23.2% (GPT-5.1), 34.2% (Claude-Opus-4.5), 16.8% (Claude-Opus-4.5-thinking), 12.9% (Gemini-3-Pro-Preview), 10.9% (Gemini-3-Pro-Preview-thinking), and 22.4% (Qwen-Max-Latest). The most dramatic improvement appears on logically extended cases, where DecoVer(GPT-5.1) jumps from 13.0% to 73.9% Task SR (+60.9%), and on temporally extended cases where DecoVer(Claude-Opus-4.5-thinking) rises from 45.0% to 90.0% (+45.0%). Missing Step errors—the dominant failure mode of vanilla LLMs—are reduced by up to 26.9% (Qwen-Max-Latest) on standard VirtualHome.

## Baselines & Comparisons

DecoVer outperforms all seven vanilla LLM baselines (GPT-4o, GPT-5.1, Claude-Opus-4.5, Claude-Opus-4.5-thinking, Gemini-3-Pro-Preview, Gemini-3-Pro-Preview-thinking, Qwen-Max-Latest) on Task SR across every dataset, with the largest absolute gains on weaker backbones (e.g., +34.2% over Claude-Opus-4.5, +23.2% over GPT-5.1 on standard VirtualHome; +60.9% over GPT-5.1 on logically extended cases). Against the sole prior neuro-symbolic BC+ method, LLM+AL (Ishay & Lee, 2025), DecoVer wins on both Task SR and Missing Step on 100 VirtualHome instances; notably, LLM+AL actually underperforms the vanilla LLMs it wraps, confirming that naive one-shot BC+ generation is counterproductive. On the classical MCP benchmark, DecoVer(Claude-Opus-4.5-thinking) and DecoVer(Gemini-3-Pro-Preview) both achieve a perfect 10/10 Success Count, whereas the best vanilla baseline (Claude-Opus-4.5-thinking) reaches only 8/10. On Tower of Hanoi, DecoVer(GPT-5.1), DecoVer(Claude-Opus-4.5), and DecoVer(Claude-Opus-4.5-thinking) all solve all 6 instances (including scattered-disk variants), while vanilla GPT-4o and Qwen-Max-Latest solve only 1 and 0 respectively. The one area where DecoVer does not uniformly dominate is goal satisfaction on temporally extended cases with Gemini-3-Pro-Preview-thinking, where the baseline's partial-credit accumulation on failed tasks yields a marginally higher aggregate goal rate (96.4% vs. 94.0%) despite a lower Task SR (85.0% vs. 90.0%).

## Relation to Prior Work

This paper extends LLM+AL (Ishay & Lee, 2025), which first coupled LLMs with the BC+ action language for classical planning, by adapting the paradigm to embodied task planning with a cascading decomposition strategy (Objects → Actions → Flags → Ground Rules → Restrictions) and a dual verification mechanism. It departs from prior neuro-symbolic planners that use Python (Ahn et al., 2026; Ling et al., 2025) or PDDL (Gestrin et al., 2024; Zhou et al., 2024) by arguing that BC+'s declarative causal-rule formalism is better suited for modeling complex dependencies, default reasoning, and global constraints in open-world embodied settings. The key methodological departure from LLM+AL is the rejection of one-shot program generation in favor of hierarchical subspace decomposition with localized verification at critical stages.

## Why It Matters / Open Questions

The paper demonstrates that structured decomposition and verification can yield large gains (up to 60.9% Task SR) over strong LLM baselines on logically complex embodied planning, and reveals that naive LLM+BC+ coupling (LLM+AL) can actually underperform vanilla LLMs—a cautionary finding for the neuro-symbolic planning community. Key limitations include the binary failure mode (solver returns no solution, yielding zero partial credit), the absence of verification in the restriction generation stage, and sensitivity to upstream omissions in the selection pipeline. Open questions include whether the framework extends to multimodal (MLLM) inputs, whether full-pipeline verification is feasible without prohibitive cost, and whether the BC+ formalism scales to domains with richer concurrent action dynamics.
