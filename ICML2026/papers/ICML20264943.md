## Problem

Existing LLM tool-orchestration frameworks face a fundamental tension: reactive approaches (ReAct) execute tools sequentially without exploiting parallelism, while code-generation paradigms (CodeAct) produce flexible but unverifiable programs lacking formal semantic guarantees. Additionally, skill libraries that learn from experience suffer from pollution, where unverified abstractions silently degrade planning quality over time. No prior framework simultaneously provides provably correct parallelization, systematic fault tolerance, and verified continuous skill accumulation.

## Input / Output

The system takes a natural language task query, tool schemas with declared effect types (pure/read/write × local/external) and resource footprints, budget constraints (max cost, concurrency, deadline), and a dynamically growing skill library as input. It produces an optimized DAG execution schedule with explicit parallelism, rate-limit compliance, and fault-tolerance annotations, which is then executed to yield task results. Unusually, the planner outputs a constrained Plan IR (a typed DAG with idempotency keys and retry policies) rather than free-form code, and the offline loop additionally emits verified macro-skills that pass functional testing, contract checking, and regression evaluation before library admission.

## Method

EvoC2F reconceptualizes tool orchestration as a constrained compilation problem with three tightly coupled components. First, a Plan IR represents plans as DAGs with explicit side-effect types, resource footprints, data dependencies, and retry/idempotency annotations, enabling static analysis. Second, a semantic compiler constructs an augmented dependency graph (adding resource-conflict edges and per-resource write-serialization chains), then schedules nodes via a modified HEFT heuristic that respects concurrency budgets, token-bucket rate limits, and deadline constraints, achieving 63–67% latency reduction through effect-aware parallelization with formal soundness guarantees (Proposition 3.4). Third, a verification-gated skill evolution loop mines successful trajectories via PrefixSpan on canonicalized Plan IR sequences, generalizes patterns through anti-unification, and admits candidates only after three-stage verification (synthesized unit tests, property-based contract checking, and held-out regression assessment) followed by staged deployment (shadow → canary → stable). The planner itself is improved via DPO on preference pairs scored by a reward combining success, efficiency, and reliability, while a learned MLP router ranks retrieved skills by semantic similarity plus historical utility.

## Results

On StableToolBench with Claude-4-Sonnet, EvoC2F achieves 72.2% SoPR and 78.6% SoWR, outperforming all baselines, while reducing end-to-end latency by 63–67% compared to ReAct (16.9s → 5.5s). On ShortcutsBench (GPT-4o), EvoC2F reaches 54.7% ASA and 53.4% Acc_afni, and on τ-bench (Claude-4-Sonnet) it achieves 79.7% pass_ret and 53.6% pass_air. Tool calls per task drop to 16.8 (vs. 24.1 for ReAct), and the Critical Path Gap on ToolComp is 1.23 (vs. 3.84 for ReAct), confirming near-optimal parallelization.

## Baselines & Comparisons

EvoC2F outperforms all five baselines on every benchmark and model combination. Against ReAct (the sequential reasoning-action baseline), EvoC2F gains +9.9 points SoPR and reduces latency by 67% on StableToolBench (Claude-4-Sonnet). Against LLMCompiler (the closest competitor on latency at 6.1s), EvoC2F achieves 5.2 points higher SoPR (72.2 vs. 67.0) while maintaining lower latency (5.5s), demonstrating that effect-aware scheduling yields both speed and correctness gains. Against Planner-Execute (DAG-based planning without semantic annotations), EvoC2F improves SoPR by 3.0 points and cuts latency nearly in half (5.5s vs. 11.2s), isolating the benefit of the semantic compiler. Against CodeAct (arbitrary Python code generation), EvoC2F achieves +4.7 points SoPR and +9.2 points Acc_afni on ShortcutsBench, confirming that constrained IR trades raw flexibility for verifiable correctness. Toolformer-style in-context prompting is consistently the weakest baseline, trailing EvoC2F by 8.2 points SoPR on Claude-4-Sonnet.

## Relation to Prior Work

This paper positions tool orchestration as a constrained compilation problem, departing from both reactive sequential frameworks (ReAct, Toolformer) and unconstrained code generation (CodeAct) by introducing a formal Plan IR with explicit side-effect and resource annotations. It builds directly on the HEFT scheduling heuristic (Topcuoglu et al., 2002) and extends LLMCompiler's parallel execution by adding semantic guarantees that LLMCompiler lacks (no side-effect annotations, no formal conflict resolution). The verification-gated skill evolution mechanism extends the skill library paradigm from Voyager and ProAgent by inserting a three-stage verification pipeline (functional testing, contract checking, regression assessment) before library admission, addressing the skill pollution problem those systems leave unaddressed.

## Why It Matters / Open Questions

The 63–67% latency reduction with formal correctness guarantees (parallelization soundness, deadlock freedom) makes this practically relevant for production LLM agent deployments where both speed and reliability matter. The ablation showing that removing effect annotations causes SoPR to drop from 72.2% to 64.8%—essentially matching the no-compiler baseline—highlights that naive parallelization without semantic awareness is actively harmful, a finding that challenges the assumption that more parallelism is always better. Open questions include scalability to large distributed tool ecosystems, the overhead of maintaining accurate annotations for rapidly evolving APIs, and whether the verification pipeline's 37.6% admission rate (134/356 candidates) represents a fundamental bottleneck or can be improved with better generalization.
