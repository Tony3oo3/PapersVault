## Problem

Current self-evolving agent memory systems accumulate experience within a fixed, manually designed memory architecture, preventing the architecture itself from adapting to diverse task domains. The paper asks how a memory system can not only facilitate agent-level evolution but also meta-evolve its own architectural design to achieve superior, task-domain-specific performance while preserving cross-task and cross-model generalizability.
![Teaser figure](../imgs/ICML20265893/cropped_page1_idx0.webp)

## Input / Output

The method consumes task queries, full agent trajectories (state-action sequences with terminal rewards), and a 3-dimensional performance feedback vector (task success, token cost, latency) per trajectory. It produces evolved memory architectures as concrete programmatic implementations of four modular components (Encode, Store, Retrieve, Manage), an updated experiential memory base, and the agent's next action. Architectures are represented as 'genotypes'—specific combinations of module implementations—enabling structured comparison, selection, and recombination across evolutionary iterations.

## Method

MemEvolve operates as a bilevel optimization: an inner loop evolves the agent's experiential memory content under a fixed architecture, while an outer loop evolves the architecture itself via a diagnose-and-design operator. The outer loop first ranks candidate architectures using non-dominated sorting over (performance, −cost, −delay) to select top-K parents, then for each parent performs trajectory-grounded diagnosis to identify component-level defects (retrieval failures, ineffective abstractions, storage inefficiencies), followed by constrained redesign that modifies only the four modular interfaces. The entire process is training-free and LLM-driven: an LLM inspects replayed trajectories, produces a structured defect profile, and generates S descendant architectures as valid reconfigurations of the Encode/Store/Retrieve/Manage modules. EvolveLab provides the unified substrate, re-implementing twelve representative memory systems under a single abstract base class to enable fair comparison and controlled evolution.

## Results

MemEvolve integrated with Flash-Searcher (GPT-5-mini) achieves 81.18% on WebWalkerQA, 78.0% on xBench-DS, 79.33% on TaskCraft, and 80.61% average on GAIA at pass@3, improving over the memory-free Flash-Searcher baseline (71.18/69.0/69.67/69.09) by up to 11.52%. With SmolAgent, gains reach up to 17.0% on xBench-DS (51.0→68.0). Cross-LLM transfer to Kimi K2 yields a 17.06% gain on WebWalkerQA (52.35→69.41), and the evolved memory transfers to unseen frameworks (CK-Pro, OWL) with 2.0–9.09% improvements without re-evolution.

## Baselines & Comparisons

Against the memory-free Flash-Searcher (GPT-5-mini), MemEvolve improves WebWalkerQA from 71.18→81.18 (+10.0), xBench-DS from 69.0→78.0 (+9.0), and GAIA from 69.09→80.61 (+11.52) at pass@3. Compared to the strongest human-designed memory baselines in Table 3 (same Flash-Searcher host), MemEvolve (73.33/74.00/74.71 on GAIA/xBench/WebWalkerQA) outperforms Voyager (69.70/68.00/73.53), AWM (67.27/71.00/72.35), Mobile-E (69.09/68.00/71.76), ExpeL (66.06/64.00/69.41), DILU (66.67/69.00/72.94), and Cheatsheet (68.48/65.00/72.94) on all three benchmarks simultaneously, whereas each baseline wins on at most one benchmark and degrades on others. Cross-LLM transfer to Kimi K2 yields the largest single gain of 17.06% on WebWalkerQA (52.35→69.41), and DeepSeek V3.2 gains 2.94% (69.41→72.35). Against CK-Pro (pass@3, Claude-3.7) on GAIA, MemEvolve+Flash (pass@3) reaches 78.78 vs. 75.15, and on WebWalkerQA 77.05 vs. 65.88. The ablation (Table 4) confirms that joint evolution of all four modules (+16.66 on TaskCraft) substantially exceeds any single-module evolution (best: retrieval alone at +10.00), and the diagnose-and-design search outperforms both random search (+3.33) and greedy component substitution (+8.33) on TaskCraft.

## Relation to Prior Work

This paper departs from the dominant paradigm of self-improving agent memory, where a fixed architecture (e.g., vector DB + semantic search in Voyager/ExpeL, workflow extraction in AWM, tool synthesis in SkillWeaver) is hand-designed and only its content evolves. By decomposing memory into four modular components (Encode, Store, Retrieve, Manage) and treating their programmatic implementations as an evolvable 'genotype,' MemEvolve reframes memory design as a bilevel optimization problem rather than a one-shot engineering choice. The EvolveLab codebase unifies twelve prior systems under a single interface, providing the first standardized substrate for controlled comparison and meta-evolution in this space.

## Why It Matters / Open Questions

The demonstrated cross-task, cross-LLM, and cross-framework transfer of evolved memory architectures (e.g., TaskCraft-evolved memories improving WebWalkerQA by 17% on Kimi K2 and plugging into OWL/CK-Pro without modification) suggests that effective memory design principles are more task-agnostic than the field has assumed, potentially reducing the need for bespoke memory engineering per deployment. Open questions include whether the four-component decomposition is expressive enough for all memory paradigms, how the evolutionary process scales beyond three rounds or larger candidate populations, and whether the LLM-driven diagnose-and-design step can be made more computationally efficient. The EvolveLab codebase also lowers the barrier for future work by providing a fair, modular arena for memory system comparison.
