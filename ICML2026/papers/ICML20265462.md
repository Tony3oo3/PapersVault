## Problem

Current Text-to-SQL systems rely on static prompting or single-pass generation, lacking the ability to dynamically adapt and self-correct through live database interaction. Existing multi-agent frameworks decompose the task into modular stages but train these roles only via prompting or supervised fine-tuning, leaving the interactive loop unlearned. MARS-SQL addresses this by making the entire agentic workflow trainable, so that schema grounding, iterative query generation, and trajectory validation are all optimized against execution feedback rather than fixed annotations.

## Input / Output

The system takes a natural language question and a full database schema (potentially containing many irrelevant tables and columns, as in BIRD's 95 databases spanning 33.4 GB) as input, and produces a single executable SQL query as output. Internally, the schema is first pruned to a reduced subset, then N=8 candidate interaction trajectories are generated through multi-turn Think-Act-Observe loops with live SQL execution against the database instance, and a validation agent scores each trajectory to select the final answer. The deployed system comprises three 7B agents (~21B total inference footprint) with an average end-to-end latency of ~22 seconds per query.

## Method

MARS-SQL decomposes Text-to-SQL into three trainable roles, each instantiated as a Qwen2.5-Coder-7B-Instruct model. The Grounding Agent is trained via GRPO to perform table-level schema linking with a granular reward that penalizes missing columns more heavily than extra ones. The Generation Agent is the core contribution: it is trained via GRPO with sparse execution rewards (1.0/0.0/−1.0) within a ReAct-style Think-Act-Observe loop, learning to execute intermediate SQL queries against a live database, interpret errors or empty results, and self-correct its strategy over multiple turns without any step-level annotation. The Validation Agent is SFT-trained to reframe trajectory selection as a generative next-token prediction task, scoring each candidate by the average probability of a 'Yes' token across M stochastic rounds. This combination of interactive RL for generation and probability-based generative verification for selection achieves 77.84% EX on BIRD-dev and 89.75% on Spider-test using only ~35k training instances and ~13 hours of training.

## Results

MARS-SQL achieves state-of-the-art execution accuracy of 77.84% on BIRD-dev and 89.75% on Spider-test, while also scoring 78.13% on Spider-DK (second-best, behind Arctic-Text2SQL-R1's 81.5%). All three agents are 7B-parameter Qwen2.5-Coder models (~21B total inference footprint), trained solely on the BIRD training set (~35k instances) in approximately 13 hours. The system outperforms the strongest closed-source multi-agent system (CHASE-SQL+Gemini, 74.90% BIRD-dev) by 2.94 points and the best open-source single-agent RL method (Reasoning SQL, 72.29%) by 5.55 points on BIRD-dev.

## Baselines & Comparisons

MARS-SQL outperforms all base-model baselines by wide margins: GPT-5 (65.45% BIRD-dev) by 12.39 points, GPT-4o (61.90%) by 15.94 points, Qwen3-coder-30B (59.00%) by 18.84 points, and Qwen2.5-coder-7B (54.56%) by 23.28 points. Against closed-source multi-agent systems, MARS-SQL surpasses CHASE-SQL+Gemini (74.90%) by 2.94 points on BIRD-dev and XiYan-SQL (73.34%) by 4.50 points, while matching XiYan-SQL on Spider-test (89.75% vs. 89.65%). Among open-source agentic frameworks, MARS-SQL leads Reasoning SQL (72.29%) by 5.55 points on BIRD-dev and Arctic-Text2SQL-R1 (70.70%) by 7.14 points, though it trails Arctic-Text2SQL-R1 on Spider-DK (78.13% vs. 81.50%), likely because Arctic was trained on Spider data from which Spider-DK is derived. SQL-R1 (66.43% BIRD-dev) is outperformed by 11.41 points, and even when SQL-R1 is given a 64-sample majority-voting budget (33.8s latency), it reaches only 67.34% versus MARS-SQL's 77.84% at 22.1s. Under a normalized ~22s time budget, MARS-SQL (77.84%) beats GPT-5 self-consistency (69.3%) by 8.54 points and Qwen-SFT self-consistency (64.2%) by 13.64 points, confirming gains come from the trained multi-agent workflow rather than raw inference time.

## Relation to Prior Work

MARS-SQL sits at the intersection of three research threads: the ReAct paradigm for tool-augmented reasoning (Yao et al., 2022), GRPO-based policy optimization for LLMs (Shao et al., 2024), and generative verifiers that reframe selection as next-token prediction (Zhang et al., 2025). It departs from prior multi-agent Text-to-SQL systems (CHESS, OpenSearch-SQL, XiYan-SQL, CHASE-SQL) that rely on static prompting of closed-source APIs by making each agent role trainable via RL with execution-based rewards. It also distinguishes itself from single-agent RL approaches (Arctic-Text2SQL-R1, ReasoningSQL, SQL-R1) by decomposing the pipeline into specialized Grounding, Generation, and Validation agents, each trained with a different objective (GRPO for the first two, SFT for the last).

## Why It Matters / Open Questions

The paper demonstrates that a 3×7B multi-agent system trained on only ~35k BIRD examples can outperform both larger single models (32B OmniSQL, 30B Qwen3-coder) and closed-source pipelines (CHASE-SQL+Gemini, XiYan-SQL) on both in-domain and out-of-domain benchmarks, suggesting that interactive RL with execution feedback is a more data-efficient path than scaling SFT data. A key open question the paper itself raises is whether the multi-agent decomposition is truly necessary: single-model multi-task baselines (14B, 32B) performing all three roles drop to 55–58% EX, but it remains unclear whether a sufficiently large single model trained with the same RL recipe could close the gap. The 21B inference footprint and ~22 s latency also leave practical deployment trade-offs unresolved, and the paper's efficiency analyses (Appendix F) are largely self-reported on a single GPU node.
