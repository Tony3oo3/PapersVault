## Problem

Existing LLM benchmarks for optimization modeling evaluate coarse-grained, cross-domain generalization (e.g., from vehicle routing to job-shop scheduling) but offer no rigorous assessment of fine-grained, expert-level competence in power system optimization. Specifically, there is no dataset or benchmark that tests an LLM's ability to perform rigorous parameter reasoning and structural reformulation of Optimal Power Flow (OPF) models under physically constrained, professional-grade operating scenarios.
![Teaser figure](../imgs/ICML20264071/cropped_page1_idx0.webp)

## Input / Output

The model receives a natural-language OPF requirement (ranging from explicit numeric parameter directives like 'increase active loads at Bus 7 by 10%' to qualitative scenario descriptions like 'heatwave conditions with elevated thermal sag risk') and produces executable MATPOWER code implementing the required modifications. Crucially, the output is not a complete OPF formulation but a modification to a canonical base model—specifying only differential parameter patches and structural extensions—making the task more compact and physically grounded. Evaluation is execution-based: the generated code is run via a MATLAB engine and correctness is determined by comparing the optimal objective value against a ground-truth reference within a tolerance ε.

## Method

The core contribution is a modification-based OPF representation where each instance is defined as Q(Δπ, s | π_sys) = Modify_s(Q₀(π_sys + Δπ)), supervising only what varies rather than regenerating the full formulation. The dataset (ProOPF-D, 12K samples) is organized into four difficulty levels via two orthogonal axes—explicit vs. semantically inferred parameters, and parametric-only vs. structural extensions—with the structural space organized as S_p × 2^{S_o} × 2^{S_c} (8 problem types × 15 objective variants × 9 constraint variants). For semantic levels (2/4), expert-curated scenario trees hierarchically map parameter-direction pairs to operational narratives, preventing leakage of inference targets during NL generation. Training uses supervised fine-tuning of Qwen3-30B-A3B via the VERL framework on 8×A100 GPUs, while the benchmark (ProOPF-B, 121 expert-annotated cases) employs a level-specific protocol distinguishing concrete modeling (Levels 1/3) from abstract modeling (Levels 2/4) where a predefined parameter instantiation is applied post-generation.

## Results

On ProOPF-B, the best few-shot baseline (Gemini 3.0 Pro) achieves 37.19% average accuracy across four difficulty levels, while the SFT model (Qwen3-30B-A3B fine-tuned on ProOPF-D) reaches 35.53% few-shot and 27.26% zero-shot average accuracy. The most striking result is on Level 4 (structural extensions + semantic parameter inference), where all six baselines score 0.00% but the SFT model attains 11.54% (few-shot) and 7.69% (zero-shot). On Level 2 (semantic parameter inference), baselines range from 0.00% to 6.67%, while the SFT model jumps to 33.30% (few-shot) and 23.30% (zero-shot), demonstrating that domain-specific supervision is critical for abstract OPF modeling tasks.

## Baselines & Comparisons

The SFT model (Qwen3-30B-A3B + ProOPF-D) is compared against six frontier LLMs (GPT-5.2, Claude 4.5 Sonnet, DeepSeek V3.2, Gemini 3.0 Pro, Qwen3-Coder, Qwen3-30B-A3B) under both few-shot and zero-shot settings. In few-shot mode, the SFT model (35.53% avg) trails only Gemini 3.0 Pro (37.19%) and Claude 4.5 Sonnet (33.88%) by a narrow margin, while substantially outperforming GPT-5.2 (14.05%), DeepSeek V3.2 (29.75%), and Qwen3-Coder (23.97%). The decisive advantage appears on abstract modeling levels: the SFT model achieves 33.30% on Level 2 versus 0–6.67% for all baselines, and 11.54% on Level 4 versus 0.00% universally. In zero-shot mode, the SFT model (27.26% avg) matches or exceeds the best zero-shot baselines (Gemini 3.0 Pro at 26.47%, DeepSeek V3.2 at 26.45%) while being the only model to solve any Level 4 instances (7.69%). Tool-augmented prompting further narrows the gap, lifting GPT-5.2 and Claude 4.5 Sonnet to ~23–27% on Levels 2/4, but still below the SFT model's few-shot performance on Level 2.

## Relation to Prior Work

This paper departs from the existing line of LLM-for-optimization benchmarks (NL4Opt, MAMO, OptiBench, IndustryOR) that emphasize coarse-grained, cross-domain generalization (e.g., vehicle routing to job-shop scheduling) by targeting fine-grained, within-domain generalization specifically in power system OPF modeling. It also diverges from prior data synthesis pipelines (OR-Instruct, LLMOPT, ReSocratic) by introducing a modification-based representation that supervises only differential components (parameter patches and structural extensions) rather than full formulations, and by enforcing physical validity through expert-curated feasible spaces. The scenario-tree mechanism for generating semantically grounded Level 2/4 samples is a novel synthesis technique not present in prior optimization data pipelines.

## Why It Matters / Open Questions

ProOPF-B reveals a stark capability gap: SOTA LLMs achieving >90% on existing optimization benchmarks collapse to 0% on the most complex OPF tasks (Level 4), exposing that current models lack the semantic-to-quantitative mapping and structural reformulation skills needed for professional power system operation. The finding that tool augmentation (solver references, qualitative-to-quantitative guidelines) nearly quadruples performance on abstract tasks suggests a practical near-term path for deployment, while the SFT results confirm that domain-specific training data is necessary. Key limitations include transmission-level scope only, execution-based (not step-level) evaluation, and the need for substantially more Level 3/4 training data to close the remaining gap.
