## Problem

Synchronous RAG blocks token generation entirely during each retrieval call, creating a fundamental trade-off between factual accuracy (requiring multiple retrieval rounds) and latency (forcing shallow retrieval). Existing asynchronous approaches like PipeRAG and TeleRAG rely on heuristic coordination—fixed intervals or stale generated tokens as queries—that assume stable information demands and break in multi-domain settings where topic boundaries blur and entity references evolve mid-generation, leading to irrelevant prefetches and self-correction overhead.

## Input / Output

The system consumes internal LLM signals extracted during generation: hidden states over a 16-token sliding window from middle-upper layers (30–45% of model depth, e.g., layers 10–14 in Llama-3.1-8B), attention weight matrices, value vectors, and 32-dimensional output distribution statistics (entropy, top-k margins, tail mass). These feed a lightweight 2-layer transformer encoder (~2M params) that outputs a scalar prefetch probability. The Context Monitor and Query Generator (T5-small, 60M params) then produce a gated four-action decision (GENERATE, REUSE, ACCUMULATE, FETCH) and a context-aware retrieval query, which is issued against a FAISS IVF index with 768-d Contriever embeddings. The system targets 100–500 ms retrieval latencies and adds only ~2.7 ms per generated token of overhead.

## Method

The framework decouples retrieval from generation via three jointly pretrained components: a Retrieval Predictor (2-layer transformer encoder) that forecasts entropy-threshold crossings 8–16 tokens ahead by processing hidden-state dynamics, attention patterns, and value-vector gradients; a Context Monitor that selects an optimal wait horizon k∈{0,…,5} tokens via a T5-based ContextScore head, a SufficiencyClassifier (cosine-overlap with cached documents), and a ClarityScore (syntactic completeness); and a T5-small Query Generator that constructs context-aware queries rather than echoing recent tokens. All three are pretrained jointly under a five-term multi-task loss (binary CE for prediction, MSE for timing, BCE for sufficiency, BCE for clarity, NLL for query) on ~50K oracle-labeled position-level instances from HotpotQA and NQ. Post-deployment, a contextual-bandit policy gradient with action-specific rewards (+1.0 for quality-improving retrieval, −2.0 for late blocking retrieval, +0.5 for correct non-retrieval) adapts each component independently, with the four-action cascade ensuring each reward propagates only to the governing component. The key insight is that semantic precursors in transformer internals—particularly hidden-state dynamics and attention entropy at 30–45% depth—carry both the timing signal (AUROC 0.81 vs. 0.66 for raw entropy) and the retrieval intent needed to construct aligned queries before uncertainty materializes.

## Results

On HotpotQA with Llama-3.1-8B, the predictive prefetching approach achieves 68.7% EM and 75.1% F1, matching Sync-RAG's quality (69.2% EM) while reducing TTFT by 62.4% (287 ms → 108 ms) and end-to-end latency by 43.5% (9.2 s → 5.2 s). The system also requires 31% fewer retrievals per 1K tokens (59 vs. 86) and attains an Efficiency Score of 14.4, 76% higher than Sync-RAG's 8.2. Across all four QA benchmarks, the quality gap versus Sync-RAG is only 0.5–0.9% EM, while the Oracle upper bound sits 3.9% above, indicating remaining headroom in prediction accuracy (AUROC 0.81).

## Baselines & Comparisons

The method outperforms all nine baselines on the combined quality-efficiency trade-off. Against the closest reactive baselines, Self-RAG (67.8% EM, 234 ms TTFT) and Adaptive-RAG (68.5% EM, 215 ms TTFT), the predictive approach gains 0.9–1.2% EM while cutting TTFT by more than half. DRAGIN (67.3% EM) and FLARE (65.9% EM) trail by 1.4–2.8% EM and 70–170 ms TTFT. The most direct asynchronous competitor, PipeRAG (66.8% EM, 118 ms TTFT, Eff. 13.0), is surpassed on both quality (+1.9% EM) and efficiency (Eff. 14.4 vs. 13.0) when reimplemented on the same Llama-3.1-8B / FAISS / Contriever stack. On code completion (RepoBench-P), the method beats Repoformer (51.8% EM, 245 ms TTFT) by 0.6% EM and 52% TTFT; on summarization (QMSum), it exceeds BART-LS (34.1 R-1, 118 ms TTFT) by 1.5 R-1 and 22% TTFT. The only quality loss is a 0.5% EM gap versus Sync-RAG on HotpotQA, concentrated in bridge-type multi-hop questions where predictive queries are constructed before the first hop completes.

## Relation to Prior Work

This paper carves new ground at the intersection of uncertainty prediction from transformer internals and asynchronous system design. Reactive RAG methods (Self-RAG, FLARE, DRAGIN, Adaptive-RAG) detect uncertainty and then block generation for retrieval, while concurrent async efforts (TeleRAG, PipeRAG) overlap retrieval with generation but rely on fixed intervals or stale-token queries. The key departure here is *predictive* prefetching: a learned retrieval predictor monitors middle-layer hidden states, attention patterns, and value vectors to forecast uncertainty 8–16 tokens ahead, a context monitor decides whether to wait for more context, and a T5-based query generator constructs semantically aligned queries rather than echoing recent tokens. The online policy-gradient adaptation with action-specific feedback (GENERATE/REUSE/ACCUMULATE/FETCH) further distinguishes the approach from purely supervised or heuristic baselines.

## Why It Matters / Open Questions

The 43.5% end-to-end latency reduction and 62.4% TTFT improvement at a mere 0.5–0.9% quality cost are practically significant for production RAG deployments, especially in high-stakes, multi-retrieval workloads where cumulative blocking is prohibitive. The approach is orthogonal to system-level optimizations (faster vector DBs, caching, knowledge graphs) and can be layered on top of them. Key limitations include the hard requirement for hidden-state access (precluding closed-API models like GPT-4), a 28% wasted-prefetch rate from false positives, and training-data circularity concerns from oracle labels sourced from the same QA benchmarks used for evaluation. Open questions include whether the 8–16 token precursor signal generalizes to truly open-ended generation (beyond QA), how the system behaves under highly variable network latency, and whether the 0.5% quality gap on bridge questions can be closed with better multi-hop-aware prediction.
