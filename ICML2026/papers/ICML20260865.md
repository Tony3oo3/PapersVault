## Problem

Existing SWE benchmarks evaluate agents on isolated, one-off coding tasks, ignoring the temporal dependencies and accumulated technical debt that define real-world software evolution. This gap leaves agents' inability to sustain system integrity over long development horizons invisible to current evaluations, as early shortcuts that satisfy immediate tests silently propagate regressions through dependency chains.

## Input / Output

The DeepCommit pipeline consumes raw main-branch git commit histories between release tags, along with PR/Issue/Release metadata, and produces verifiable Milestone DAGs (98 milestones, 109 inter-milestone dependencies across 7 repos and 5 languages) paired with reproducible Docker testbeds. At evaluation time, the agent receives reverse-engineered Software Requirements Specifications (SRSs, ~1,348 words average) and a persistent codebase snapshot; tasks are dynamically unlocked by a DAG scheduler as prerequisites complete. Outputs are per-milestone F2P/P2P test results aggregated into a harmonic-mean Score (balancing Recall for feature completeness and Precision for regression avoidance) and a strict Resolve Rate, with the 'develop-in-place, evaluate-in-isolation' strategy snapshotting the agent's working state into a fresh container after each submission.

## Method

DeepCommit is a three-phase agentic pipeline: (1) static analysis extracts a commit-level DAG via git blame, symbol-level modifications, and file co-change statistics; (2) an LLM agent (Claude Opus 4.5) constructs the Milestone DAG through four iterative stages—seed discovery using topological metrics, parallel sub-agent consolidation with overlap resolution, dependency inference combining structural and semantic signals, and decomposition targeting CV < 1.0 over per-milestone LoC; (3) a MainAgent orchestrates EnvAgents to build Docker testbeds, cherry-pick commits in topological order, and iterate repair until stable test collection (87.1% success rate). The SWE-Milestone benchmark then replays these DAGs as a continuous evaluation: an external planner unlocks milestones only when all prerequisites are completed, the agent evolves a single persistent codebase, and each submission is snapshotted into an isolated container for scoring. This milestone-level granularity—coarser than commits (which introduce spurious linear dependencies) yet finer than releases (which flatten hundreds of interdependent changes)—is the key design choice that makes cross-task error propagation directly measurable.

## Results

Under continuous task evaluation on SWE-Milestone (98 milestones, 7 repositories, 5 languages), the best configuration—Claude Opus 4.6 in OpenHands—achieves a Score of 38.03% (Precision 37.33%, Recall 55.21%) and a Resolve Rate of 8.46%. The highest Resolve Rate across all 15 configurations is 13.37% (Gemini 3 Pro in Gemini CLI). Critically, the same models score above 80% under independent (stateless) evaluation, revealing a dramatic continuous-vs-independent gap of over 40 percentage points that exposes agents' inability to prevent error accumulation over long horizons.

## Baselines & Comparisons

This is a benchmark paper, so the primary comparison is across 15 agent-model configurations (12 models × 4 frameworks) rather than against a single baseline method. Claude Opus 4.6 dominates in Score (38.03% in OpenHands, 36.29% in Claude Code), while Gemini 3 Pro achieves the highest Resolve Rate (13.37%) despite a lower Score (24.25%), indicating it more often completes milestones fully but makes less partial progress. Framework choice matters: the same Claude Opus 4.6 model scores 38.03% in OpenHands vs. 36.29% in Claude Code, and GPT 5.3-Codex scores 28.88% in its native Codex CLI vs. 26.47% in OpenHands. The most striking comparison is continuous vs. independent evaluation: the same milestones that frontier models solve at >80% Score in isolation (e.g., Claude Sonnet 4.6 reaches 93.2% on scikit-learn independently) drop to 21.1% under continuous evaluation, confirming the degradation stems from error accumulation rather than task difficulty. On cost-effectiveness, Gemini 3 Flash ($12, 24.22%) and GPT 5.3-Codex ($25, 28.88%) offer the best Score-per-dollar, while Gemini 3 Pro ($115, 24.25%) is the worst value.

## Relation to Prior Work

This paper extends the SWE-bench lineage of coding-agent evaluation from isolated, stateless tasks to continuous, dependency-structured repository evolution. It departs from SWE-CI (which chains commits linearly in native order with exposed ground-truth tests) and SlopCodeBench (hand-crafted, from-scratch codebase extension) by introducing Milestone-level granularity organized as a DAG, reconstructed via the DeepCommit agentic pipeline from real open-source commit histories. The evaluation metric (F1 of Recall and Precision over F2P/P2P tests) generalizes SWE-bench's binary resolve rate to capture partial progress and regression separately, while the 'develop-in-place, evaluate-in-isolation' protocol preserves continuous state without sacrificing scoring reproducibility.

## Why It Matters / Open Questions

The benchmark exposes a fundamental and previously invisible failure mode: frontier agents that score >80% on isolated tasks collapse to ~38% under continuous evolution, with Precision saturating while Recall still grows—indicating agents can implement new features but cannot prevent accumulating regressions. This reframes the long-horizon agent problem from 'can the agent code?' to 'can the agent maintain system invariants across an open-ended development stream?', a question no prior benchmark could measure. Open questions include whether the 98-milestone scale is sufficient to capture truly long-horizon dynamics, whether the ~$500-per-evaluation cost limits adoption, and whether the observed error-propagation patterns (logic errors dominating at ~57%) will persist as models improve or whether architectural-level reasoning will close the Precision gap.
