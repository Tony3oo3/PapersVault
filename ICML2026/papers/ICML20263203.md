## Problem

LLM-based flows of multiple model and tool calls compound uncertainty at each step, yet current inference-scaling techniques (majority voting, self-consistency, tree search) are tightly interwoven with program logic, making them ad hoc, hard to swap, and unable to deliver principled uncertainty estimates to users. No existing framework decouples the search over a distribution of execution traces from the core flow logic while supporting both soft and hard constraints at arbitrary points in the trace.

## Input / Output

The user writes a PPDL program once in a YAML-based declarative prompting language that specifies LLM calls, tool calls, control flow, and factor constraints (soft scores or hard pass/fail checks). At runtime, the user selects an inference engine (majority voting, importance sampling, or SMC) and particle count as a configuration parameter—no code changes are needed. The output is a categorical distribution over possible results, each annotated with a posterior probability and particle count, from which the user can either inspect the full distribution to gauge uncertainty or extract the single highest-probability answer.

## Method

PPDL extends the PDL prompt programming language with a single new primitive, factor, which increments a running log-probability score (pdl_score) based on user-specified constraints such as LLM-as-a-judge scores or rule-based linter checks. The paper formalizes a weighted-sampler semantics in which LLM calls act as sample operations and factors act as weight updates, then defines an ideal semantics as an infinite weighted sum over all traces. Three Monte Carlo approximate inference engines plug into this sampler: importance sampling reweights completed traces, majority voting ignores scores entirely, and sequential Monte Carlo resamples the particle population at each factor point, discarding low-scoring partial traces and duplicating high-scoring ones to redirect computation mid-flow. The implementation parallelizes both within a single trace (futures for independent model calls with lazy data structures) and across particles (multi-threading), and the entire inference engine is a runtime configuration orthogonal to the program text.

## Results

Across five benchmarks (GSM8k, Math500, MBPP, LiveCodeBench, Fever) and six LLMs, PPDL's inference scaling engines (IS and SMC with 5 particles) consistently improve accuracy over the single-execution baseline (IS@1) and often over majority voting. The largest gains appear on code generation: on MBPP with granite4-small, IS lifts accuracy from 69.7% to 80.5% (+10.8 pp), and on LiveCodeBench with gpt-oss-120b, IS improves from 30.3% to 36.1% (+5.8 pp). In the MiniF2F Rocq theorem-proving case study, SMC@40 solves 95/244 problems versus 87.7 for IS@40 and 72.7 for IS@1, demonstrating that intermediate resampling at factor points is especially beneficial for deep, multi-step flows.

## Baselines & Comparisons

The paper does not compare PPDL against external methods; instead, it benchmarks three inference scaling strategies (Majority Voting, Importance Sampling, SMC) against a single-execution baseline (IS@1) using the same PPDL program. IS and SMC outperform IS@1 in the vast majority of model–benchmark combinations, with the largest gains on code generation (e.g., +10.8 pp on MBPP/granite4-small, +5.8 pp on LiveCodeBench/gpt-oss-120b). Against Majority Voting, IS and SMC win when factor scores carry meaningful signal (e.g., GSM8k/granite4-small: IS 93.7% vs. Maj. Voting 90.4%), but Majority Voting can edge ahead when the base model is already strong or factors are noisy (e.g., GSM8k/gpt-oss-20b: Maj. Voting 93.1% vs. IS 92.7%). In the MiniF2F Rocq case study, SMC consistently beats IS at every particle count (e.g., +7.3 problems at 40 particles: 95.0 vs. 87.7), confirming that intermediate resampling at factor points is critical for deep, multi-step proof/repair loops where IS can only reweight completed traces.

## Relation to Prior Work

PPDL extends PDL (Vaziri et al., 2024), a declarative prompt programming language, by adding a single probabilistic primitive (factor) and reinterpreting the execution model as a distribution over traces. Conceptually, it bridges two previously separate lineages: probabilistic programming languages (Prob, Stan, Church, Pyro) that track log-probabilities along trajectories but do not interface with LLMs, and prompt programming languages (LMQL, DSPy, SGLang, Guidance) that compose LLM and tool calls but treat inference scaling as ad-hoc, hand-written loops. The closest prior work—LLaMPPL, GenML Control, and Rollout Roulette—applies SMC to single LLM calls or token sequences, whereas PPDL generalizes this to multi-step flows with heterogeneous soft and hard constraints, making inference scaling orthogonal to program logic.

## Why It Matters / Open Questions

PPDL offers a practical, open-source framework that lets developers write an LLM flow once and swap inference engines (majority voting, importance sampling, SMC) without code changes, which is valuable for systematic experimentation with inference scaling. The theorem proving case study demonstrates that SMC's ability to resample at intermediate factor points yields a consistent 7-problem advantage over IS on MiniF2F-Rocq, suggesting that principled mid-trace steering matters for deep, multi-step agentic workflows. Key limitations include the quality ceiling imposed by imperfect factors (especially LLM-as-a-judge) and the absence of factor calibration, which the authors flag as important future work. The finding that inference scaling can actively hurt performance (gpt-oss-20b on LiveCodeBench drops from 20.8% to 8.0% under IS) underscores that the framework's value lies in enabling informed choice rather than guaranteeing improvement.
