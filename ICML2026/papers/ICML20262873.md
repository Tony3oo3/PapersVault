## Problem

Production LLM inference pipelines couple heterogeneous stages (retrieval, embedding, memory, refinement, generation) that are typically stitched together as RPC-connected services, making cross-stage queueing, resource contention, and tail-latency attribution opaque to any single component. No existing system treats the end-to-end pipeline as a first-class, compilable unit of execution, preventing pipeline-level scheduling, bounded backpressure, and operator-level diagnosis under strict SLO constraints.

## Input / Output

SAGE consumes a declarative dataflow DAG where each operator declares an explicit contract specifying resource requirements (CPU/GPU affinity, memory budget), state semantics (stateless/stateful, checkpoint vs. restart), and I/O behavior (batching, token streaming). The compiler lowers this into a physical ExecutionGraph with concrete replicas, per-replica bounded input queues, routing policies, and node placement; at runtime the system processes user text requests through the pipeline and emits generated text, retrieval results, and per-operator telemetry (queue depth, service time, blocking duration) that feed automated attribution and what-if counterfactual predictions.

## Method

SAGE introduces a pipeline-as-compilation-target abstraction: a declarative compiler transforms a logical DAG with operator contracts into a physical ExecutionGraph by allocating replicas, materializing bounded-queue channels with explicit backpressure, and assigning placement and routing policies, while Theorem 3.1 proves semantic preservation under parallelization. The runtime enforces bounded-queue backpressure (upstream blocks when downstream saturates) and applies pluggable scheduling policies (FIFO, LoadAware-Spread, Priority) that can be swapped at deployment without recompiling the graph. On top of the explicit ExecutionGraph, SAGE provides trace-driven what-if analysis (replaying historical traces under counterfactual policies with <5% prediction error), automated performance attribution (decomposing end-to-end latency into per-operator queue/service/blocking components with 87.5% precision), and explainable scheduling via structured decision traces. The system integrates vector search, streaming semantic state, structured memory, and LLM generation as uniform dataflow operators with C++ backends, while inference is decoupled via OpenAI-compatible endpoints (e.g., vLLM) behind the same operator interface.

## Results

On a 16-node cluster, SAGE achieves 11.4× throughput scaling for RAG workloads (71% linear efficiency) with 1 ms median scheduling overhead, sustaining 16 requests/s at >700 tokens/request. Under multi-pipeline contention, staggered admission control reduces P99 latency by 57% (77 s → 33 s) at a 30% throughput cost. The LoadAware-Spread scheduler achieves 98% load balance and the lowest P99 (6.5 s) among all policies, while Priority maximizes throughput (19.2 tasks/s) but inflates P99 to 12.0 s under contention. What-if analysis predicts throughput/P99 within 1.8–7.9% error (4.6% MAE), and automated attribution identifies bottlenecks with 87.5% precision.

## Baselines & Comparisons

SAGE does not benchmark against external systems (e.g., vLLM, Ray Serve, or Airflow) in a head-to-head manner; instead, it evaluates internal policy trade-offs on a fixed compiled ExecutionGraph. Among scheduling policies, LoadAware-Spread dominates on tail latency (6.5 s P99) and balance (98%) at an 11% throughput cost versus FIFO (18.5 → 16.4 tasks/s), while Priority maximizes throughput (19.2 tasks/s) but degrades P99 to 12.0 s due to low-priority starvation. For admission control, staggered starts reduce P99 by 57% (77 s → 33 s) compared to simultaneous admission, at a 30% aggregate throughput reduction (43.6 → 30.7 tasks/s), matching queueing-theoretic predictions. What-if predictions track actual measurements within 1.8–7.9% error across parallelism, scheduler, and routing changes, and automated attribution correctly identifies injected bottlenecks in all three synthetic scenarios with 87.5% precision on production traces.

## Relation to Prior Work

SAGE draws on three distinct research lineages: (1) LLM serving engines (vLLM, Orca, Sarathi-Serve, DistServe) that optimize a single inference backend's decoding, batching, and KV-cache management; (2) stream/dataflow systems (Flink, Naiad, Differential Dataflow) that provide the formal foundation for stateful operators, bounded queues, and incremental computation; and (3) LLM application frameworks (LangChain, LlamaIndex, DSPy, Haystack) that compose retrieval, memory, and generation stages but treat them as opaque RPC services. SAGE's key departure is architectural: it borrows the dataflow compilation model from stream processing and specializes it for LLM inference pipelines, introducing operator contracts (resource, state, I/O) as compiler-visible metadata that drive placement, backpressure, and routing decisions across heterogeneous CPU/GPU stages—something neither serving engines nor application frameworks expose as a unified optimization surface.

## Why It Matters / Open Questions

The pipeline-as-compilation-target abstraction is practically significant for teams operating multi-stage RAG or agentic workloads under SLO constraints, as it makes cross-stage interference attribution, policy-driven SLO trade-offs, and what-if analysis architecturally tractable rather than requiring manual correlation of distributed traces. However, the evaluation is limited to a single 16-node CPU cluster with one A6000 GPU server, and the system remains coordination-bound for fine-grained operators and bottlenecked by centralized LLM endpoints under heavy contention. Open questions include whether the formal semantic-preservation guarantees hold under non-Markovian (heavy-tailed) inference latency, whether adaptive concurrency control and online recompilation can close the gap between predicted and actual tail behavior, and whether the operator-contract model scales to pipelines with dozens of heterogeneous stages without user-specified resource hints becoming a maintenance burden.
