## Problem

Natural language to optimization (NL2Opt) suffers from silent modeling failures where generated code executes successfully but encodes an incorrect formulation, yielding plausible but wrong answers. Existing approaches either impose multi-step revision at inference time via prompting scaffolds (which don't persist when removed) or train single-pass programs, leaving iterative improvement to external loops. This paper asks whether a structured draft-and-audit workflow can be learned directly into model parameters using only terminal execution feedback, without intermediate solver traces.

## Input / Output

The model receives a natural-language optimization problem description along with variable-type guidelines (continuous vs. integer) and optional dataset-specific few-shot exemplars demonstrating correct PySCIPOpt API usage. It produces a two-turn trajectory: a draft PySCIPOpt program (Turn 1) followed by an audited/revised program (Turn 2) under a fixed three-point rubric. Only the Turn-2 program is executed in a sandbox to compute a binary reward; the Turn-1 draft is never run, and no solver error traces or execution outcomes are provided between turns.

## Method

DA-RL trains a shared-parameter two-turn policy (Draft → Audit) using PPO with a binary terminal reward computed solely by executing the final audited program. The audit turn applies a fixed rubric checking constraint completeness, parameter consistency, and variable domain correctness, with a conservative editing rule that discourages unnecessary rewrites. Because both turns share parameters and reward is observed only after Turn 2, optimization couples drafting and auditing: the model learns to produce drafts that are structurally amenable to rubric-based repair (cross-turn synergy), rather than relying on reactive debugging from solver feedback. Trained from Qwen2.5-7B-Instruct on public 80/20 splits of five benchmarks, the approach achieves 68.1% macro pass@1, outperforming matched single-turn RL by 7.8–16.7 pp on harder benchmarks, with ablations confirming that the structured rubric and two-turn horizon are both necessary for the gain.

## Results

Under the public 80/20 split protocol, DA-RL (Qwen2.5-7B) achieves a Macro AVG pass@1 of 68.1%, the highest among all methods evaluated under the same protocol. The gain is most pronounced on MAMO-Complex (84.5%), where rubric-guided auditing repairs constraint and domain errors that cause silent modeling failures. On NL4Opt, DA-RL reaches 97.1%, while its weakest benchmark is OptMATH-Bench at 30.4%. The best prompting-only baseline (Claude-Sonnet-4.5) achieves 67.1% Macro AVG, showing that the learned two-turn policy provides a modest but consistent edge over frontier LLMs using the same Draft→Audit prompt at inference time.

## Baselines & Comparisons

All four training-based baselines (ORLM, LLMOpt, OptMATH, SIRL) are reported as reference-only (†) because they were trained under materially different data access or evaluation protocols (e.g., private industrial data, benchmark-seeded augmentation, or full-benchmark evaluation). Under those non-comparable settings, DA-RL's 68.1% Macro AVG exceeds SIRL (60.6%), OptMATH-32B (61.1%), OptMATH-7B (55.4%), LLMOpt (51.1%), and ORLM (46.4%), with the largest gap on MAMO-Complex (84.5% vs. 54.1% for OptMATH-32B). Under the directly comparable public-split protocol, DA-RL (68.1%) narrowly surpasses the strongest prompting baselines—Claude-Sonnet-4.5 (67.1%) and Claude-Opus-4.5 (67.0%)—while substantially outperforming GPT-5.2 (37.1%) and Gemini-3-Pro (42.1%). The paper notes that DA-RL's advantage is concentrated on MAMO-Complex (+28–56 pp over prompting baselines), whereas it trails Claude on OptMATH-Bench (30.4% vs. 55.9–56.9%), suggesting the learned policy excels at structured constraint repair but struggles with the more open-ended mathematical notation extraction required by OptMATH-Bench.

## Relation to Prior Work

This paper carves new ground at the intersection of two existing lines of work: inference-time scaffolds for structured code generation (OptiMUS, Self-Refine, chain-of-thought) and execution-aware reinforcement learning for code (CodeRL, SIRL). It departs from both by training a fixed two-turn Draft→Audit policy with shared parameters under terminal-only verification—no intermediate solver feedback—so that rubric-guided revision is internalized into the policy rather than imposed by orchestration or reactive debugging. The key conceptual departure from single-turn RL (SIRL, CodeRL) is the multi-turn policy structure coupled with a terminal reward that, through shared parameters, reshapes the draft distribution itself (cross-turn synergy), a mechanism not present in prior execution-based RL for optimization code.

## Why It Matters / Open Questions

The paper demonstrates that a 7B model trained with DA-RL can match the best frontier LLM prompting baseline (68.1% vs. 67.1% macro) on NL2Opt while being substantially more data-efficient (<2k training instances vs. 30k+ for prior SFT/RL methods), suggesting that learning the verification workflow into parameters is a viable path for domain-specific code generation. The cross-turn synergy finding—that terminal reward on the audited program improves the draft even without any audit prompt at inference time—opens a question about how credit assignment in multi-turn RL can reshape earlier-turn behavior. Limitations include evaluation on only MILP/PySCIPOpt, a single 7B backbone, small test sets (20–130 instances), and residual format-drift failures; whether the approach generalizes to non-linear solvers, larger models, or more complex multi-step workflows remains open.
