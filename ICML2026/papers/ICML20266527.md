## Problem

Existing agent environments are fragmented into either pure GUI interfaces (e.g., OSWorld) or pure text-based tool APIs (e.g., SWE-agent), and neither modality alone suffices for general-purpose digital work. Real-world tasks inherently require both GUI interaction for visual inspection and verification of proprietary applications, and text-based tools for efficient bulk operations, yet no unified environment provides both over a shared operating system state.
![Teaser figure](../imgs/ICML20266527/cropped_page0_idx1.webp)

## Input / Output

The agent receives a natural-language task instruction alongside a configurable set of observations that include full-window screenshots (for GUI and app-level views), structured system state (window IDs, application lists, file metadata), and textual tool outputs. Actions are dispatched as either pixel-level GUI commands (click, type, drag) resolved through a VLM grounding model, or as text-based commands (bash scripts, Python execution, MCP tool calls) that operate directly on the shared OS file system. The final output is a set of completed digital deliverables—formatted spreadsheets, Word documents, PDFs, or code repositories—verified through both programmatic checks and visual inspection.

## Method

The paper proposes the Agent-Native Computer, a conceptual framework formalized as a POMDP where the observation and action spaces are factored into composable Environment Views over a single shared OS state. Each view (OS-level, app-level, or externally mounted) exposes a self-contained subset of observations and actions, with two action types: Context-Bound actions tied to a specific view's state, and Free-Form stateless function calls. The concrete implementation, AgentVM, builds on OSWorld's virtual machine and progressively layers interaction surfaces—MCP-mounted text tools, a structured OS-level view (open_app, switch_window), and Python/bash code execution—while maintaining a single underlying file system so that changes made through any interface are immediately visible through all others. The agent architecture follows a hierarchical planner–grounding–reflection loop (inspired by Agent S2.5), using GPT-5 for planning and UI-TARS-1.5-7B for pixel-level GUI grounding, with the agent dynamically selecting between GUI and text-based modalities per subtask.

## Results

On the OSWorld 'workflow' subset, the unified AgentVM environment improves agent performance monotonically from 41.54% (GUI-only baseline) to 51.30% as text-based tools, OS-level views, and code execution are progressively added. The largest single gain (+5.18 points) comes from mounting MCP text-based tools, which replace brittle multi-step GUI action chains with direct structured calls. Case studies on GDPVal and GAIA tasks further demonstrate that GUI interaction is most valuable at task initialization and visual verification, while text-based actions (Python, bash) are essential for bulk data manipulation and file generation.

## Baselines & Comparisons

This position paper does not benchmark against external competing agent systems; instead, it ablates the value of each interface layer within a fixed hierarchical agent (planner + grounding, inspired by Agent S2.5). The GUI-only baseline (41.54%) represents the standard OSWorld interaction paradigm. Adding MCP text-based tools yields the largest improvement (+5.18 to 46.72%), confirming that structured tool calls reduce the error-prone multi-step GUI chains that cause workflow failures. The OS-level environment view contributes a further +1.15 points by exposing window status and application info symbolically, eliminating repeated screenshot parsing. Code execution (Python and bash) adds +3.43 points to reach 51.30%, enabling reliable batch file operations. The monotonic gains across all three additions validate the paper's central claim that unifying GUI and text-based interaction surfaces over shared OS state is essential for general-purpose digital agents.

## Relation to Prior Work

This paper builds directly on OSWorld's virtual-machine-based OS environment and Agent S2.5's hierarchical planner-grounder agent architecture, while porting MCP-based text tools from OSWorld-MCP. Its conceptual departure is the 'Agent-Native Computer' framework, which formalizes GUI and text-based interaction as coequal 'Environment Views' (a POMDP factorization) over a single shared OS state, rather than treating them as competing paradigms. This positions the work against both the pure-GUI line (OSWorld, AndroidWorld) and the pure-text line (SWE-agent, GAIA tool-based agents), arguing that the fragmentation of existing benchmarks into single-modality environments is the core bottleneck for general-purpose digital agents.

## Why It Matters / Open Questions

The paper provides a principled, implementable framework (AgentVM) for unifying interaction surfaces, and its monotonic OSWorld gains (41.5→51.3) plus qualitative case studies offer concrete evidence that neither modality alone suffices. However, the empirical validation is limited to a single benchmark subset with one fixed agent architecture, and the case studies are illustrative rather than controlled ablations, leaving open whether the framework's benefits generalize across agent designs and task distributions. Broader open questions include safety in hybrid GUI+code environments (cross-modality prompt injection), whether applications will natively expose agent-native interfaces rather than requiring retrofitting, and how the Environment View abstraction scales to parallel multi-agent systems.
