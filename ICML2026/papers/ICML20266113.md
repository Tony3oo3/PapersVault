## Problem

Current code-based CAD generation methods focus on single-part solids and use syntactic correctness or visual similarity as quality proxies, failing to address the core complexity of engineering assemblies where multiple parts must satisfy precise relational constraints such as mating, concentricity, and collision avoidance. A code that compiles is insufficient if parts collide or fail to fit, yet no prior method provides a verifiable, constraint-level evaluation framework for multi-part parametric assembly generation.

## Input / Output

The agent receives a natural-language design intent and a code workspace (in OpenSCAD, CadQuery, or Build123d) with a designated entry point, and produces a multi-file parametric CAD workspace alongside a suite of deterministic verification tests (pytest or SpecSCAD format). Unlike static mesh outputs, the generated code must expose named parameters and reusable modules for downstream editing, and the tests encode geometric constraints (bounding-box limits, manifold validity, thread-parameter relationships) and assembly predicates (concentricity, clearance bounds, non-interference) as executable assertions with quantitative pass/fail criteria.

## Method

SPADA reframes CAD generation as test-driven development: a multimodal LLM agent iteratively compiles, inspects, and repairs code against a deterministic test contract rather than relying on visual similarity or free-form self-reflection. The agent uses three CAD-specific tools in a fixed loop—spec converts ambiguous natural language into structured parameter and constraint predicates, inspect compiles the workspace and returns geometry metadata (bounding box, volume, manifold status) plus multi-view renders, and verifier executes generated pytest/SpecSCAD tests that check interface compliance, geometric validity, and inter-part constraints, returning measured values, expected bounds, and code locations for each failure. This shifts pass/fail decisions from non-deterministic VLM pixel inference to deterministic executable predicates, enabling mathematically precise corrections (e.g., computing an exact translation to fix a 2 mm pitch-diameter error). The agent averages 4.1 iterations per task within a 5-minute wall-clock budget, and the framework is backbone-agnostic, validated across Gemini-3-flash, GPT-5, and Qwen3-VL models.

## Results

On SPADA-Bench-Verified part generation, SPADA (with Gemini-3-flash) achieves 1.8% Invalid Rate, 78.9% IoU, 11.2 Chamfer Distance, 65.7% Pass Rate, and 52.3% All Pass Rate, substantially outperforming the best zero-shot model (Gemini-3-flash: 3.1% IR, 61.2% IoU, 35.2% APR) and the best text-to-CAD method (CADCodeVerify: 10.4% IR, 54.6% IoU, 15.8% APR). On assembly tasks, SPADA reaches 41.9% APR versus 20.4% for the best zero-shot baseline, with a CD of 1.8×10⁻³ compared to 22.4×10⁻³. On the CADPrompt benchmark, SPADA achieves 0% IR and 95.4% IoU, outperforming MEDA (94.1% IoU) and CADCodeVerify (94.4% IoU).

## Baselines & Comparisons

SPADA outperforms all five baselines across every reported metric. Against zero-shot Qwen3-VL models (Bai et al., 2025), SPADA reduces IR from 19.5–31.2% to 1.8% and lifts APR from 4.2–6.9% to 52.3% on parts. Against CAD-Coder (Doris et al., 2025), SPADA improves APR by 42.0 points (52.3% vs. 10.3%) and IoU by 30.6 points (78.9% vs. 48.3%). Against CADCodeVerify (Alrashedy et al., 2025), the closest text-to-CAD competitor, SPADA gains 36.5 APR points (52.3% vs. 15.8%) and 24.3 IoU points, demonstrating that deterministic test-driven verification provides substantially more actionable feedback than code-execution-refinement alone. On CADPrompt, SPADA (95.4% IoU, 35.4 CD) surpasses MEDA (Panta et al., 2025; 94.1% IoU, 55.5 CD) and CADCodeVerify (94.4% IoU, 127.0 CD). Finally, in the self-refinement comparison (Table 7), SPADA without the verifier already exceeds Gemini-3-flash with Reflexion (Shinn et al., 2023) by 17.5 APR points (45.0% vs. 27.5%), and the full SPADA pipeline reaches 53.0% APR, confirming that structured specification and deterministic test feedback are more effective than free-form verbal reflection.

## Relation to Prior Work

SPADA repurposes test-driven development (TDD) from software engineering into the code-based CAD domain, where prior work (CAD-Coder, CADCodeVerify, MEDA) treats generation as a one-shot or loosely-iterative translation problem evaluated by geometric similarity. The agent architecture draws on LLM tool-use frameworks (ReAct, Reflexion) but replaces free-form verbal self-refinement with deterministic executable predicates (pytest/SpecSCAD tests) as the repair signal. The benchmark design explicitly follows SWE-bench's philosophy of verifiable, execution-based evaluation, but extends it to multi-file parametric CAD workspaces with assembly-level relational constraints—a setting absent from prior code-based CAD datasets (CADTalk, CADPrompt, CADReview), which focus on single-part solids.

## Why It Matters / Open Questions

The paper addresses a genuine gap: code-based CAD generation has largely ignored constrained multi-part assemblies, where a compilable program can still produce colliding or misaligned components. SPADA-Bench-Verified (11.7k tasks across three CAD languages) provides the first verifiable, constraint-level evaluation substrate for this setting, shifting the field from IoU-based similarity to pass/fail engineering predicates. However, absolute performance remains modest (52.3% APR on parts, 41.9% on assemblies), and the paper acknowledges that complex multi-constraint assemblies, outdated API knowledge, and proprietary CAD formats remain unsolved. Open questions include whether hierarchical planning or tighter spatial-reasoning integration can close the remaining gap, and whether the TDD paradigm generalizes beyond code-based representations to proprietary CAD ecosystems.
