## Problem

While LLMs excel at generating simple, single-panel charts, their ability to produce complex composite visualizations—multi-subplot grids with intricate layouts, multiple chart types per panel, and cross-chart semantic coherence—from large structured datasets remains largely unevaluated. Existing benchmarks (VisEval, PandasPlotBench) focus on simple text-to-visualization tasks, and no prior work systematically assesses multi-turn iterative refinement of visualization code based on user feedback.
![Teaser figure](../imgs/ICML20265979/cropped_page1_idx0.webp)

## Input / Output

The model receives a natural language instruction specifying visualization requirements (layout, chart types, data transformations), structured metadata about the dataset, and raw data files (CSV/XLSX, up to ~462M rows across 1,874 files). It must produce executable Python code using Matplotlib and related libraries (Seaborn, Plotly, Squarify, scikit-learn, statsmodels) that renders a valid chart image within a sandboxed Docker container (Python 3.13, 120s timeout, no network). Two task variants exist: single-turn generation from scratch, and multi-turn refinement where the model receives a faulty code draft, its rendered image, and a human-authored modification request to iteratively correct errors.

## Method

The paper introduces three components: (1) PlotCraft, a 982-instance benchmark built from 140 real Kaggle datasets with 48 chart types, 7 visualization intents, and 3 complexity levels, using zero-reference generation and a multi-judge VLM ensemble (Gemini-2.5-Pro, Gemini-2.5-Flash, GPT-4o) scoring Task Compliance (4 binary sub-metrics) and Chart Quality (5 criteria on a 0–2 scale); (2) SynthVis-30K, a 30K-instance synthetic dataset generated via a multi-agent pipeline where a Task Generator/Judge cycle proposes and validates visualization tasks, then a Planner and Code Generator produce code through iterative Debug Cycles (sandboxed execution) and Refine Cycles (Visual Judge feedback on layout, overlap, colors, text clarity); and (3) PlotCraftor, obtained by SFT of Qwen3-Coder-30B-A3B on SynthVis-30K with 131K context length, 3 epochs, global batch size 64, and LR 7×10⁻⁶ with linear decay, incorporating Chain-of-Thought rationales for single-turn and extracted high-quality refinement interactions for multi-turn training trajectories.

## Results

On the primary PlotCraft benchmark, PlotCraftor-30B-A3B achieves an average score of 6.18 (out of 14), surpassing its base model Qwen3-Coder-30B-A3B (4.97) by approximately 25% and nearly matching Claude-4-Sonnet (6.22) with a gap of less than 1%. Among proprietary models, Claude-4.1-Opus leads with an average of 6.72. On VisEval, PlotCraftor achieves a 93.81% pass rate and 3.80 quality score, outperforming the much larger Qwen3-Coder-480B-A35B (91.75% pass rate, 3.55 quality). On PandasPlotBench, PlotCraftor reaches a 96.0% pass rate with 91 task compliance, competitive with Qwen3-Coder-480B (97.1% pass rate, 87 task compliance).

## Baselines & Comparisons

PlotCraftor (30B) outperforms all open-weight baselines on PlotCraft, beating Qwen3-Coder-480B-A35B (5.51) by 0.67 points and Kimi-K2 (5.23) by 0.95 points, while achieving a score within 0.04 of Claude-4-Sonnet (6.22). Against its own base model Qwen3-Coder-30B-A3B (4.97), PlotCraftor gains 25% in average score, with the largest improvement on the Quality sub-metric (4.08 vs. 2.84 in single-turn). Among proprietary models, Claude-4.1-Opus (6.72) remains the clear leader, outperforming PlotCraftor by 0.54 points, particularly on multi-turn refinement where its Quality score (5.21) exceeds PlotCraftor's (4.73). On VisEval, PlotCraftor (93.81% pass rate) surpasses Qwen3-Coder-480B (91.75%) and GPT-5 (87.71%) but trails Claude-4.1-Opus (96.14%) and Grok-4 (94.41%). On PandasPlotBench, PlotCraftor (96.0% pass rate, 91 task score) slightly underperforms Qwen3-Coder-480B (97.1%, 87) on pass rate but leads on task compliance, while Claude-4.1-Opus achieves a perfect 100% pass rate. The paper also notes that models excelling on simpler benchmarks (e.g., Kimi-K2, GPT-4o on VisEval) show significant degradation on PlotCraft's harder tasks, whereas PlotCraftor and the Claude series maintain consistent performance across all three benchmarks.

## Relation to Prior Work

This paper extends the text-to-visualization (Text2Vis) code generation task established by VisEval, PandasPlotBench, and MatPlotBench, which all focus on simple, single-panel charts generated in a single turn. It departs from prior work by introducing two critical generalizations: (1) composite visualizations with multiple subplots and intricate layouts drawn from real, large-scale structured data, and (2) a multi-turn refinement setting that tests iterative debugging based on user feedback. For the training side, it repurposes the standard SFT paradigm from general code generation but applies it to a purpose-built multi-agent synthetic dataset (SynthVis-30K), drawing on the agent-based data synthesis ideas from recent code-generation work but adapting them to the visual-feedback loop unique to plotting.

## Why It Matters / Open Questions

PlotCraft fills a clear evaluation gap: no prior benchmark systematically tests LLMs on complex, multi-subplot visualization code generation or on multi-turn refinement, making it likely to become a standard reference for the visualization-code-generation subfield. The finding that model scaling and SFT yield diminishing returns on hard tasks—suggesting that emergent spatial/logical reasoning, not task-specific fine-tuning, is the bottleneck—points to a concrete open question about what capabilities are needed for truly complex visualization. Limitations include reliance on MLLM-based judges that may miss subtle visual defects (minor overlaps, color inconsistencies) and the high cost of the multi-agent data synthesis pipeline, both of which constrain the ceiling of the evaluation and the scalability of the training data.
