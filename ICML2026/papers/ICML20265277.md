## Problem

State-of-the-art vision-language models now claim support for 100–130+ languages in document parsing, yet existing benchmarks cover at most 17 languages and predominantly evaluate English and Chinese. This creates an evaluation blind spot: without ground truth for long-tail scripts, neither academia nor industry can empirically verify whether these multilingual claims hold. The paper also notes that prior benchmarks largely ignore structural elements like code blocks and catalogs, limiting their diagnostic power for real-world document complexity.

## Input / Output

Each sample is a single page image extracted from a real-world PDF (no synthetic rendering), with the model expected to produce structured output across six element types: plain text and code in Markdown, formulas in LaTeX, tables as HTML with rowspan/colspan, catalogs as ordered lists, and a global reading-order sequence. Evaluation is performed in two modes: a decoupled mode where content is scored on pre-cropped patches with human-verified layouts (isolating recognition quality), and a layout-dependent end-to-end mode following OmniDocBench's quick_match protocol where layout misclassification and reading-order errors directly penalize the final content score.

## Method

MORE is constructed via a three-stage pipeline: (1) large-scale web crawling yields 20M+ PDFs, filtered by heuristic spam detection and layout density, then language-classified (excluding Chinese, English, and unlabeled) to a 5.7M candidate pool; (2) stratified sampling selects up to 10 PDFs per language and one random page each, producing 1,237 pages across 149 languages and six script families (Latin 53.7%, Cyrillic 17.5%, Sanskrit 13.4%, Arabic 7.4%, Chinese 2.7%, Other 5.4%); (3) a model-assisted, human-refined annotation pipeline first uses D-FINE for coarse layout detection followed by manual refinement and directional reading-order links, then aggregates predictions from an ensemble (InternVL-1B, dots.ocr, PaddleOCR-VL, Qwen-VL, HunyuanOCR) into anonymized candidates that human experts verify or correct. The evaluation protocol extends OmniDocBench by adding code and catalog tasks, using NED (Levenshtein-based) for sequential elements, CDM (spatial character detection matching on rendered LaTeX) for formulas, and TEDS (tree edit distance on HTML) for tables, with the overall score computed as the arithmetic mean of all six task scores to decouple error propagation.

## Results

On the MORE benchmark (149 languages, 1,288 pages), HunyuanOCR (1B) achieves the highest overall score of 92.42, leading in 4 of 6 sub-tasks (Formula 93.28, Table 78.56, Code 97.07, Catalog 95.36). Gemini 3 follows at 91.61 overall, with the best Text score (95.39). Table recognition remains the primary bottleneck across all models, with even the best (HunyuanOCR) scoring only 78.56, while MinerU2.5 collapses to an overall 48.85, confirming that lightweight models struggle significantly with multilingual structural parsing.

## Baselines & Comparisons

HunyuanOCR (1B) establishes a clear lead over all baselines with an overall score of 92.42, surpassing Gemini 3 (91.61) by 0.81 points and PaddleOCR-VL (87.96) by 4.46 points; it ranks first in Formula, Table, Code, and Catalog. Gemini 3 counters with the best Text score (95.39 vs. HunyuanOCR's 93.81) and a slightly better Table score (81.02 vs. 78.56), but trails overall due to weaker Code (93.05 vs. 97.07) and Catalog (94.31 vs. 95.36). dots.ocr (3B) shows a stark text-structure dichotomy: it achieves near-best Text (94.45) and the best Read Order (97.18) yet collapses on Tables (39.81), a 38.75-point gap versus HunyuanOCR. PaddleOCR-VL (0.9B) is competitive on Code (96.29) and Catalog (93.04) but lags significantly on Tables (61.11) and Overall. Qwen2.5-VL and Qwen3-VL (2B/3B) cluster around 83–84 overall, with Qwen3-VL showing a notable Formula weakness (65.45) compared to HunyuanOCR (93.28). DeepSeekOCR (82.91) and MinerU2.5 (48.85) trail substantially, with MinerU2.5 scoring below 30 on Text and Catalog, confirming that parameter scale and specialized training remain critical for multilingual document parsing.

## Relation to Prior Work

This paper extends the OmniDocBench evaluation protocol (CVPR 2025) from its 2-language (English/Chinese) scope to 149 languages, while also adding code and catalog evaluation tasks absent from prior benchmarks. It positions itself against a lineage of multilingual OCR benchmarks (ICDAR RRC-MLT with 6 languages, CC-OCR with 10, XDocParse with 126) that have progressively expanded language coverage but remain limited in structural element diversity. The key methodological departure is the model-assisted, human-refined annotation pipeline that leverages an ensemble of VLMs (dots.ocr, PaddleOCR-VL, HunyuanOCR, Qwen-VL) for pre-annotation before expert verification, enabling scalable ground-truth construction across 149 languages without synthetic data.

## Why It Matters / Open Questions

This benchmark fills a critical evaluation gap: state-of-the-art VLMs now claim support for 130+ languages, yet no prior benchmark provided empirical ground truth to verify these claims for long-tail scripts. The findings establish that table recognition remains the universal bottleneck (best score 78.56 vs. >90 for text/code) and that layout-dependent evaluation reveals a 16-point performance drop for the best model, indicating that end-to-end document parsing is far from solved. Key limitations include sparse structural elements (only 73 code, 104 catalog samples) for rare languages, and a notable conflict of interest since all authors are employed by Tencent, the developer of the top-performing HunyuanOCR. Open questions include whether the stratified sampling of 10 PDFs per language provides sufficient coverage for truly low-resource scripts, and how to scale structural annotation to underrepresented languages.
