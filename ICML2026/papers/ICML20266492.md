## Problem

Current AI personalization is implemented within provider-managed infrastructure where preference data is opaque, non-portable, and locked to specific services, creating user lock-in and limiting user agency. Existing standards like the Model Context Protocol address context access but do not address ownership, granular user control, or privacy management for personal preferences, leaving a critical gap in the personalization stack that market incentives alone will not fill.

## Input / Output

The HCP accepts natural language preference statements (optionally enriched with category tags and confidence scores) and OAuth 2.0 authorization tokens with category-scoped grants as input, consumed through MCP tool calls such as addPreferences and searchPreferences. At inference time, the HCP LLM mediates access by selecting only the minimal relevant preference snippets from authorized categories, returning a scoped preference bundle to the requesting agent while maintaining a versioned, auditable record of all access events and redacting any fields outside the granted scope.

## Method

The HCP introduces a dedicated intermediary LLM that serves as a user-governed preference layer independent of model providers, storing preferences as portable natural language text with lightweight schema annotations and versioning. Access is controlled through fine-grained, revocable OAuth 2.0 permissions scoped to preference categories (e.g., food, health_context, financial_context), enforced via a deterministic permission check over MCP. At query time, the HCP LLM performs data minimization by evaluating the request against authorized categories and returning only relevant snippets, redacting unrelated fields. The system supports a full CRUD lifecycle for preferences with conflict resolution, version history, and GDPR-compliant erasure, and an open-source prototype demonstrates feasibility with a web application for preference management, an integrated MCP server for interoperability, and category-scoped authorization.

## Results

This is a position paper proposing the Human Context Protocol (HCP) and does not report quantitative benchmarks or performance metrics. The primary empirical contribution is an open-source proof-of-concept prototype (a web application with an integrated MCP server) that demonstrates feasibility of interoperable, category-scoped preference management with OAuth 2.0 authorization. The paper's main 'results' are architectural: it specifies four core design attributes (interoperability, encapsulation, control, security), a four-action lifecycle (Read/Write/Update/Delete), and an end-to-end flow with least-privilege enforcement and audit logging.

## Baselines & Comparisons

The paper does not benchmark HCP against competing systems or report comparative metrics, as it is a position paper rather than an empirical study. Instead, it addresses three conceptual counterarguments: (1) the Coasian objection (markets will sort out preference data allocation), which the authors rebut by identifying four specific market failures—lock-in/switching costs, non-rivalry of data, information asymmetries, and market thickness; (2) the revealed-preference objection (behavioral inference suffices), countered by citing behavioral economics failures (mental accounting, self-control) and the 'inversion problem' (Kleinberg et al., 2024); and (3) the model-level objection (fine-tuning or steering vectors suffice), rebutted by noting these are provider-locked and non-portable. The closest empirical grounding is Table 1, a qualitative comparison of six user-data-control initiatives (Infomediaries, MyData, Solid, SSI, Web3 Data Wallets, HCP) along dimensions of key idea, mechanism, and limitations, positioning HCP as the first to combine LLM-native preference interfaces with granular, revocable access control.

## Relation to Prior Work

The paper builds directly on Anthropic's Model Context Protocol (MCP), which standardizes how AI assistants access external data sources, but argues MCP lacks mechanisms for ownership, granular user control, and privacy management of personal preferences. It also draws on the long lineage of user-data-control initiatives—infomediaries, MyData, Solid, Self-Sovereign Identity, and Web3 data wallets—while arguing that LLMs fundamentally change the feasibility calculus by making natural language the primary interface for expressing and updating preferences. The paper departs from provider-side personalization mechanisms (RLHF, DPO, behavioral inference, in-context memory) by proposing a user-governed, portable preference layer that sits above and independent of any single model provider.

## Why It Matters / Open Questions

As a position paper with an open-source prototype, HCP identifies a structural gap in AI personalization—preferences are currently non-portable, opaque, and provider-controlled—and proposes a concrete architectural remedy with clear design attributes (interoperability, encapsulation, control, security). The economic analysis (Coasian objections, revealed-preference limitations, model-level fine-tuning constraints) provides a useful framework for why market incentives alone will not produce this infrastructure. Key open questions include standards convergence across vendors, security of LLM-mediated access (inference attacks, adversarial prompting), adoption dynamics, and the risks of deep personalization (manipulation, sycophancy, dependency) that require study before widespread deployment.
