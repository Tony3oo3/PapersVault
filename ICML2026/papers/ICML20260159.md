## Problem

Reinforcement learning for software engineering agents requires large volumes of executable tasks with stable reward signals, but existing benchmarks are either limited to a few high-resource language ecosystems, too small for training, or evaluation-first in design and omit training-oriented artifacts like pre-built environments and instance-level diagnostics. No prior pipeline demonstrates a truly language-agnostic construction workflow that scales to long-tail toolchains while producing reproducible, containerized training substrates with fine-grained quality metadata.

## Input / Output

The pipeline consumes raw GitHub Archive activity (29.5M PRs across 145K repositories), cloning repos via distributed map-reduce to extract patches locally and bypass API rate limits. The primary output is 32,079 containerized tasks as pre-built Docker images (26.36 TiB total) spanning 20 languages and 3,617 repositories, each paired with fail-to-pass test oracles, per-repository installation/test scripts, and a custom log parser mapping raw test output to a normalized pass/fail/skip schema. A secondary release of 120,000+ PR-derived tasks provides installation recipes and synthetic problem statements generated from PR descriptions and patches, enabling substantially larger-scale learning without requiring issue linkage.

## Method

The pipeline enforces a unified five-stage construction workflow across all languages, with only base Docker images, test runners, and log parsers being language-specific. The critical stage is setup synthesis: an interactive agent (mini-SWE-agent scaffold with Qwen3-Coder-480B-A35B-Instruct) operates in a closed-loop debugging cycle per repository, inspecting the codebase, attempting dependency installation, and iteratively refining scripts based on observed build errors until the full test suite runs without infrastructure failures; this setup is then reused across all tasks from that repository. Validation uses dual-pass execution (pre-fix and post-fix) of the full project test suite with a three-run stability check to filter flaky tests, retaining only instances with at least one fail-to-pass test. Issue clarity filtering employs an ensemble of three LLM judges (gpt-oss-120b, GLM-4.7, DeepSeek V3.2) using a Verified-E prompt that includes the patch and test patch, retaining instances only when all three judges rate the specification as adequate. Finally, a diagnostic enrichment stage (informed by a 300-task, 7-model diagnostic study) tags each instance with codes (A for cleanly solvable, B1–B7 for specific pathologies like test-suite coupling, implicit naming, or external dependencies), enabling stratified curriculum design and controlled ablations during training.

## Results

SWE-rebench V2 releases 32,079 containerized SWE tasks across 20 languages and 3,617 repositories, plus 120,000+ PR-derived tasks with installation recipes. On a 300-task diagnostic subset (5 languages), seven frontier models show substantial pass@k headroom: Claude Opus-4.5 leads with 25.2% pass@1 and 32.7% pass@3, while gpt-oss-120b achieves only 8.8% and 14.3%, confirming non-trivial difficulty. The A/B* diagnostic validation confirms metadata utility: Code A (clean) tasks yield 2–8× higher pass rates than B* (confounded) tasks across all models (e.g., Gemini 34.0% vs. 4.0% pass@3; GLM-4.7 34.0% vs. 6.0%).

## Baselines & Comparisons

For issue-clarity filtering, the paper's Verified-E prompt (which provides the model with the patch and test patch alongside the issue) achieves the highest precision (0.83) among all configurations, outperforming SPICE (precision 0.59, F1 0.43) and the original SWE-bench Verified prompt (precision 0.75, F1 0.36); the Verified+ variant achieves the best F1 (0.50) but lower precision. In setup synthesis, the interactive mini-SWE-agent with Qwen3-Coder-480B substantially outperforms the non-interactive pipeline (25.8% vs. 12.1% pass@1), and even a smaller interactive model (Qwen3-30B, 17.4% pass@1) exceeds the non-interactive 480B baseline. Increasing setup attempts from 1 to 10 roughly doubles success rates (e.g., Qwen3-480B: 25.8% → 58.8% pass@10). The A/B* diagnostic comparison (Table 7) validates that the metadata enrichment pipeline effectively separates clean tasks from confounded ones: across all five evaluated models, Code A pass@3 rates are 2–8× higher than B* rates, confirming the metadata's utility for stratified training.

## Relation to Prior Work

SWE-rebench V2 directly extends SWE-rebench (V1), which was limited to Python, into a language-agnostic pipeline covering 20 programming languages. It builds on the mini-SWE-agent scaffold for interactive environment setup and adapts the SWE-bench Verified annotation rubric into an LLM-judge-based filtering stage, departing from prior automated pipelines (SWE-Factory, SWE-Bench++, SetUpAgent) by emphasizing training-oriented artifacts—pre-built Docker images, instance-level diagnostic metadata, and PR-based task expansion—rather than evaluation-only benchmarks. The PR-derived formulation (generating problem statements from PR descriptions and patches) is a notable departure from the issue-linked paradigm that dominates prior SWE benchmarks, enabling a 4× larger corpus without requiring issue-PR linkage.

## Why It Matters / Open Questions

This dataset addresses a concrete bottleneck for RL training of SWE agents: the scarcity of large-scale, reproducible, executable task environments with reliable test oracles across diverse languages. The diagnostic metadata (A/B* classification) and the demonstrated pass-rate gap between clean and confounded tasks (e.g., Gemini 34% vs. 4% on B* tasks) provide a practical mechanism for curriculum design and reward-noise mitigation. Key open questions remain: the paper does not include end-to-end RL training ablations showing that filtered curricula actually improve agent performance, Docker images are subject to drift from external package changes, and the single-container design excludes multi-service systems. Whether the 120K+ PR-derived tasks (with 23% leakage) are usable at scale for RL without additional filtering is also unresolved.
