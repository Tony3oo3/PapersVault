## Problem

Mobile GUI world models face a critical trade-off: text-based WMs discard fine-grained visual information (spatial layout, iconography, typography, color), while existing visual WMs like VIMO depend on slow multi-stage pipelines combining OCR, GPT-4o calls, and custom diffusion models, making them expensive, non-reproducible, and closed-weight. No single self-contained, open-weight model existed that could perform visual mobile GUI world modeling with both precise text rendering and structurally accurate layout generation.

## Input / Output

The model takes a mobile GUI screenshot (S_t) and a native coordinate-based action (A_t, e.g., click at [x,y] or swipe with velocity) as input, and produces a two-part output: a natural-language reasoning trace (R_t) describing the expected state change, followed by complete renderable HTML5 code (S_{t+1}^{code}) representing the next GUI state. The generated HTML is rendered in a mobile viewport (with a one-time ~1s browser launch and ~0.3s per render) to obtain the pixel-level next state. Actions are preserved in their original coordinate space rather than being converted to natural-language instructions, avoiding dependence on an external frontier model for visual grounding.

## Method

gWorld post-trains a VLM (Qwen3 VL 8B/32B) via supervised fine-tuning to predict the next GUI state as renderable web code rather than pixels, exploiting VLMs' linguistic priors for legible text and their pre-training on structured web code for high-fidelity visual generation. The training data is synthesized through a three-step pipeline: (1) repurposing offline mobile-agent policy trajectories into (S_t, A_t, S_{t+1}) transition triplets, (2) cross-modal relabeling of the ground-truth next state from pixels to HTML code using a frontier model (Gemini 3 Flash) with a dedicated image-to-code prompt, and (3) generating reasoning traces with free look-ahead access to the true next state to ground the reasoning in actual transitions. Training freezes the vision encoder and tunes only the LLM and MLP projector layers with a cosine LR schedule over 5 epochs. This single-model approach replaces VIMO's five-stage pipeline (OCR → masking → GPT-4o filtering → diffusion → GPT-4o text filling), achieving 123×–291× lower end-to-end latency (1.3s vs. 160s per state) while establishing a new accuracy-vs-model-size Pareto frontier across six in- and out-of-distribution benchmarks.

## Results

gWorld 32B achieves 79.6% average Instruction Accuracy (IAcc.) across six benchmarks (4 in-distribution, 2 out-of-distribution), with only 0.6% render failure rate and 71.4% DINO similarity. gWorld 8B achieves 74.9% IAcc. with 1.4% render failure, outperforming all baselines including models up to 50.25× larger (Llama 4 402B-A17B at 55.7% IAcc.). On out-of-distribution benchmarks (AndroidWorld, KApps), gWorld 32B maintains 79.9% and 75.7% IAcc. respectively, showing minimal degradation from in-distribution performance. The code-based approach virtually eliminates structural errors (<1% Render Fail) compared to 9.2% for Llama 4 402B and 40.1% for the Qwen3 VL 8B base model.

## Baselines & Comparisons

gWorld 8B (74.9% IAcc.) outperforms all five baseline families by substantial margins. Against image-generation models, gWorld 8B achieves +61.5% IAcc. over Qwen-Image-Edit 20B (13.4%) and +49.1% over Emu3.5 34B (25.8%), though Emu3.5 slightly edges gWorld 8B on DINO similarity (70.5% vs. 70.3%) due to its tendency to copy input states. Against code-generation VLMs, gWorld 8B beats Llama 4 402B-A17B (55.7%) by +19.2% IAcc. despite being 50.25× smaller, and beats GLM-4.6V 106B (67.4%) by +7.5% while being 13.25× smaller. gWorld 8B also surpasses its own base model Qwen3 VL 8B (29.2%) by +45.7% IAcc., and gWorld 32B surpasses Qwen3 VL 32B (52.5%) by +27.1%. The render failure rate drops from 40.1% (Qwen3 VL 8B base) to 1.4% (gWorld 8B), confirming that the code-based world modeling paradigm eliminates the structural errors that plague both image-generation and untrained VLM baselines.

## Relation to Prior Work

This paper departs from two existing lines of mobile GUI world modeling: text-based WMs (MobileWorldBench) that discard visual fidelity, and pixel-based visual WMs (VIMO) that require a multi-stage pipeline of OCR, GPT-4o calls, and a custom diffusion model. It also repurposes the image-to-web-code generation literature (Web2Code, Design2Code, LatCoder) in a novel way—using a single VLM to generate renderable HTML as the next GUI state rather than as a front-end development artifact. The code-based WM concept draws from Dainese et al. and Copet et al., but those target code-generation tasks, not mobile GUI dynamics. The key conceptual departure is treating the VLM's pre-training on structured web code as an inductive bias for GUI state prediction, eliminating the need for external diffusion or OCR components.

## Why It Matters / Open Questions

gWorld establishes that a single 8B/32B VLM can match or exceed 50× larger models on visual GUI world modeling while running 123–291× faster than prior pixel-based pipelines, making open-weight, deployable GUI WMs practical for the first time. The MWMBENCH benchmark with OOD splits (including Korean-language KApps) fills a critical evaluation gap. Open questions remain: the model only uses 7% of available training data (power-law scaling suggests substantial headroom), photo-realistic content (camera views, video) remains a fidelity limitation of the code representation, and the single-frame Markov assumption precludes modeling long-range temporal dependencies like persistent shopping-cart state. The demonstrated downstream policy gains (+22 pp over base VLMs) suggest WMs could become a standard component in mobile agent stacks, but the oracle M3A setup (ground-truth action always in candidate set) overstates real-world applicability.
