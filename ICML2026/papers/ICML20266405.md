## Problem

Hosted LLM APIs drift silently over time—shifting behavior, deprecating endpoints, updating safety filters—yet research norms treat them as fixed functions, creating a reproducibility gap that existing documentation standards (Model Cards, Datasheets, HELM) do not address. No venue-aligned standard exists for attaching a minimal, checkable drift-audit artifact to results that materially depend on hosted endpoints. This position paper argues ICML should require such an artifact and proposes a concrete, lightweight specification to close the gap.

## Input / Output

The LDAA takes a hosted LLM API endpoint, a compact probe suite of 20–200 invariant-checking cases (e.g., JSON schema validity, tool-call shape, refusal patterns), and the full API call configuration (decoding parameters, SDK version, prompt template hash) as input, consumed via a single-command rerun script. It produces a machine-readable provenance record, a drift report with per-invariant pass rates and statistical test results, and a binary drift diagnosis at discrete checkpoints (submission and camera-ready). Probes encode acceptance criteria as invariants rather than gold answers, and the drift report distinguishes hard contract failures (zero-tolerance) from probabilistic shifts (tolerance bands calibrated to run-to-run nondeterminism via k repeated runs and confidence intervals).

## Method

The core contribution is the LLM Drift-Audit Artifact (LDAA), a minimal, paper-attached specification with four components: a machine-readable provenance record, a compact invariant-checking probe suite, a drift report with statistical tests, and a one-command rerun script. Two audit modes are supported: contract-mode, which uses binary pass/fail invariants for structural properties (schema validity, tool-call conformance, refusal patterns), and behavioral-distribution mode, which applies two-sample tests (paired t-test, Kolmogorov-Smirnov, sign test) to score distributions for open-ended quality claims such as LLM-as-judge evaluations. A claim-dependency-probe mapping explicitly links each main paper claim to the specific API behavior it depends on and the probe class monitoring it, preventing superficial compliance where authors check trivial properties unrelated to their actual results. The paper further proposes enabling infrastructure—behavioral SemVer (bSemVer) for providers and Machine-Readable Behavioral Changelogs (MBCL)—and a three-phase adoption path (disclose → reward → require) for ICML. Multi-model pipelines receive per-component audit subsuites to avoid combinatorial explosion, and nondeterminism is handled by running each probe k times with confidence intervals rather than treating repeated runs as independent samples.

## Results

This is a position paper with no empirical experiments or quantitative results. The paper proposes the LLM Drift-Audit Artifact (LDAA) — a minimal package of provenance metadata, a 20–200-case invariant-checking probe suite, and a one-command rerun script — and makes four falsifiable predictions: (1) higher replication stability for LDAA-equipped papers over 12 months, (2) faster time-to-diagnosis when results stop reproducing, (3) more actionable provider changelogs, and (4) bounded author burden (median cost < $10 or < 2 hours). No predictions are tested in this paper; they are stated as future evaluation criteria.

## Baselines & Comparisons

The paper makes no empirical comparisons against baselines, as it is a position paper proposing a venue-level artifact standard rather than a new method. It situates the LDAA relative to existing documentation and monitoring frameworks — Model Cards, Datasheets, HELM, CheckList, Model ChangeLists, and logprob-based monitoring — arguing that none provide a venue-enforceable, paper-scoped drift handle for hosted API dependencies. The closest prior work (Tiny QA Benchmark++ for smoke tests, Camuffo et al. for drift-audit manifests in strategy research) is cited as a building block that the LDAA extends to a general, ICML-adoptable standard. No head-to-head performance comparison is conducted or claimed.

## Relation to Prior Work

This paper synthesizes several existing threads—concept drift theory (Lu et al., 2020), ML systems' hidden technical debt (Sculley et al., 2015), API shift estimation via adaptive sampling (Chen et al., 2021), two-sample model equality testing (Gao et al., 2025), logprob-based monitoring (Chauvin et al., 2025), and LLM API contract analysis (Romel et al., 2025)—into a single venue-enforceable artifact specification (the LDAA). It departs from prior documentation norms (Model Cards, Datasheets, Reward Reports) by explicitly treating temporal behavioral stability of a hosted endpoint as part of the scientific object, and from prior drift-detection methods by scoping them to a minimal, paper-attached, conference-workflow-compatible package rather than a continuous monitoring system. The paper's core contribution is the *packaging and norm-setting* layer: no prior work proposes a specific, checkable artifact that a venue can require at submission and camera-ready.

## Why It Matters / Open Questions

The proposal addresses a cross-disciplinary reproducibility failure mode (documented in ML benchmarking, political science, business research, and science policy) that is worsening as hosted LLM APIs become core experimental infrastructure. Its main limitation is that it is a proposal without empirical validation: the four falsifiable predictions (replication stability, time-to-diagnosis, transparency, bounded burden) remain untested, and the artifact's practical cost and reviewer usability are asserted rather than demonstrated. Open questions include where to draw the 'material dependence' boundary, how to handle adversarial model substitution (which the LDAA explicitly cannot detect), whether providers will supply the enabling behavioral-versioning metadata, and whether the phased adoption path will generate sufficient tooling before Phase 3 (mandatory) is reached.
