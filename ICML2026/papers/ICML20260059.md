## Problem

Predicting numeric outcomes (memory, latency, accuracy) from programs and computation graphs has traditionally required heavy, domain-specific feature engineering—count-based statistics, graph encodings, or GNNs—that are non-transferable and break when new commands or architectures appear. It remained unexplored whether a single unified text-based regression model could handle diverse code representations (high-level languages, GPU kernels, ONNX graphs) directly from raw text without any such engineering.

## Input / Output

The model consumes raw text strings: source code in 24+ programming languages, Triton GPU kernel code, and serialized ONNX graph representations of neural network architectures, with no one-hot encodings, graph structures, or numeric normalization. It produces scalar numeric predictions (peak memory in bytes, kernel latency in ms, or training accuracy) via a digit-by-digit tokenization using special sign, exponent, and mantissa tokens (e.g., <+><-><1><7><2><5> encodes 72.5), with constrained decoding guaranteeing valid numbers. The autoregressive decoder can also emit multiple metrics sequentially, enabling multi-objective prediction such as accuracy followed by latencies on four different hardware platforms.

## Method

The RLM uses a frozen T5Gemma-S (300M) encoder paired with a trainable decoder, so only the decoder receives gradient updates, drastically reducing training cost while retaining the encoder's pretrained code understanding. Regression is framed as next-token prediction over y-values using an explicit digit-by-digit numeric tokenization with sign/exponent/mantissa tokens, trained with cross-entropy rather than MSE, which eliminates the need for per-dataset y-normalization and handles wildly different value ranges (10⁻² to 10⁶) uniformly. A single model is jointly trained on all datasets—high-level code, Triton kernels, and ONNX graphs—demonstrating that multi-task learning across heterogeneous code formats does not degrade performance. The autoregressive decoder naturally captures inter-metric correlations through conditional modeling p(y′|y,x), a structural advantage over parallel regression heads that assume conditional independence. Key design choices validated by ablations include: decoder-based numeric output outperforming MSE regression heads (ρ=0.800 vs. 0.717), a custom ONNX-aware 8K-token tokenizer outperforming the default 32K T5 vocabulary (ρ=0.723 vs. 0.533), and longer encoder context (4K vs. 1K tokens) yielding incremental gains.

## Results

The 300M-parameter RLM (frozen T5Gemma-S encoder) achieves a Spearman ρ of 0.930 on APPS Leetcode peak-memory prediction and 0.516 on Triton GPU kernel latency. Across 24 CodeNet languages, it attains an average Spearman ρ above 0.5, with the strongest per-language scores on C++ (0.748) and C (0.741). On five classic NAS search spaces, the RLM achieves the highest average Kendall-τ of 0.461, marginally surpassing the previous state-of-the-art FLAN (0.459) while requiring no zero-cost proxies or hardware-specific feature engineering.

## Baselines & Comparisons

Against FLAN (Akhauri & Abdelfattah, ICML 2024), the previous SoTA for NAS prediction, the RLM achieves a slightly higher average Kendall-τ (0.461 vs. 0.459), winning on NASNet (0.382 vs. 0.344) and Amoeba (0.488 vs. 0.470) but trailing on DARTS (0.528 vs. 0.567) and marginally behind on PNAS and ENAS. Critically, the RLM does not require zero-cost proxies or hardware embeddings that FLAN depends on. Against CATE (Yan et al., ICML 2021), a Transformer-based architecture encoder, the RLM more than doubles the average Kendall-τ (0.461 vs. 0.238), and against Arch2Vec (Yan et al., NeurIPS 2020), a graph autoencoder, it more than doubles performance as well (0.461 vs. 0.212). The RLM also substantially outperforms a generic GNN baseline (0.461 vs. 0.429 average Kendall-τ). In the in-context learning comparison, GPT-5-Thinking with up to ~50 in-context examples consistently underperforms the in-weight RLM across all four domains, with the gap most pronounced on APPS where 0-shot ICL is negatively correlated with the target.

## Relation to Prior Work

This paper extends the Regression Language Model (RLM) framework from Song et al. (2024) and Akhauri et al. (2025), which treats regression as next-token prediction over scalar targets, to the domain of code and computation-graph performance prediction. Prior work on code performance prediction relied on heavy feature engineering (count-based statistics, syntax trees, GNNs) and NAS prediction depended on graph encodings (Arch2Vec, CATE, FLAN) or hardware-specific embeddings; this paper shows a single frozen T5Gemma encoder with a trained decoder can replace all of these by consuming raw text (source code, Triton kernels, ONNX graphs) directly. The digit-by-digit numeric tokenization and constrained decoding follow Song & Bahri (2025), and the multi-objective sequential prediction leverages the autoregressive decoder in a way that parallel regression heads cannot.

## Why It Matters / Open Questions

The practical impact is substantial: a single 300M-parameter model eliminates the need for domain-specific feature engineering, graph encoders, and hardware embedding pipelines across 24+ programming languages, GPU kernel latency, and NAS accuracy/latency prediction. The comparison showing GPT-5-Thinking in-context regression consistently underperforms the small trained RLM (while costing ~2× more per query at MAX-shot) provides a useful data point for practitioners choosing between fine-tuning and prompting. Open questions include whether code-based RLMs can predict outcomes of entire experiments from raw code, whether the approach scales to larger encoders (the authors note T5Gemma-b-b required extensive tuning), and whether the 'no-free-lunch' data requirement of universal text-based methods can be further reduced.
