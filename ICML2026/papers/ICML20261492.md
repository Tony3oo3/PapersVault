## Problem

BPE-tokenized language models suffer from the Prompt Boundary Problem: when a prompt ends mid-token, the model has never seen that tokenization during training, causing severely distorted next-token predictions (e.g., P('ld'|'Hello wor') ≈ 5×10⁻⁴ while P('world'|'Hello') = 3×10⁻²). Existing exact solutions are either computationally prohibitive (exponential in prefix length) or incompatible with the most widely used HuggingFace ByteLevel BPE tokenizers that feature future-dependent pretokenization, while heuristic backtracking methods sacrifice distributional fidelity.

## Input / Output

ByteSampler operates entirely at inference time on an off-the-shelf BPE-tokenized LM with no retraining or weight modification. It accepts an arbitrary byte-string prompt (which may end mid-token or mid-pretoken) and the tokenizer's merge list, then produces a 256-dimensional next-byte probability distribution or a full byte-level text completion. Internally, it maintains a Valid Covering Tree (VCT) — a compact tree of all valid token sequences whose decodings have the prompt as a prefix — which is updated incrementally with each newly generated byte, emitting fully determined tokens to an output stream while keeping only a bounded branching suffix in memory.

## Method

The core mechanism is the Valid Covering Tree (VCT), which enumerates all valid token sequences T such that the prompt is a prefix of decode(T), decode of all-but-the-last token is a prefix of the prompt, and T is a valid encoding. Two key theoretical results ensure efficiency: (1) Proposition 3.2 shows the VCT decomposes into a deterministic trunk (shared by all paths) plus a branching suffix of bounded size, leveraging BPE's constant-lookahead property; (2) Proposition 3.4 establishes that token-sequence validity reduces to pairwise validity, enabling O(1) pruning of invalid adjacent token pairs. The streaming algorithm (Algorithm 2) expands nodes, prunes branches not matching the new byte, and commits the shared trunk to output, achieving O(1) per-byte overhead (only +0.72 extra inference tokens on average vs. plain BPE). Future-dependent pretokenization is handled by maintaining candidate split states online and branching only over unresolved decisions, with dedicated handlers for lookahead whitespace, contraction merging, and right-aligned digit groups.

## Results

On OLMo2-1B English text, ByteSampler achieves 81.56% next-character accuracy and 0.87 bits/char language modeling loss, nearly matching the original token-level model (0.85 bits/char) while the naive no-mitigation baseline degrades to 29.49% accuracy and 6.94 bits/char. The method requires only +0.72 average inference tokens overhead versus plain BPE, compared to +49.47 for Phan et al. (2025) and 2.12×10³⁰ for Prefix Covering. On Qwen3-1.7B Chinese text, ByteSampler reaches 52.7% next-character accuracy and 3.43 bits/char, again closely matching the token-level baseline (3.50 bits/char) while the naive method drops to 32.8% and 5.47 bits/char.

## Baselines & Comparisons

ByteSampler outperforms all heuristic backtracking baselines on next-character accuracy: it beats Token Healing (Ribeiro, 2023) by ~10 points (81.56% vs 71.63%) and Token Alignment (Athiwaratkun et al., 2024) by ~5 points (81.56% vs 76.28% at 2-token backtracking), while also showing that excessive backtracking (4 tokens) actually hurts Token Alignment performance. On efficiency, ByteSampler uses only 24.24 inference tokens per 100-character sample versus 72.99 for Phan et al. (2025) (65% less overhead) and 2.12×10³⁰ for Vieira et al.'s (2024) Prefix Covering, making it the only exact method with O(1) per-byte overhead. Compared to Turaga's (2025) Back Tokenization, ByteSampler achieves O(1) CPU orchestration versus O(n), and supports HuggingFace ByteLevel BPE tokenizers (the majority of open-weight LMs) where Turaga's method is limited to SentencePiece BPE. The method also enables applications the baselines cannot: byte-level ensembling of models with mismatched tokenizers (Qwen3 + OLMo2 + LLaMA3.2 ensemble outperforms the average model on all 7 evaluated tasks) and proxy-tuning (proxy-tuned LLaMA3.1-8B reaches 76.6% GSM8K and 59.5% MMLU, surpassing both the base model and the 1B expert).

## Relation to Prior Work

This paper builds on the BPE constant-lookahead property (Berglund & van der Merwe, 2023) and the pairwise validity criterion for token sequences (van Antwerpen & Neubeck, 2025) to introduce the Valid Covering Tree (VCT), a data structure that compactly represents all valid token sequences covering a byte prefix. It departs from prior PBP mitigations in a key way: backtracking heuristics (Ribeiro, 2023; Athiwaratkun et al., 2024) are inexact, exponential-time exact methods (Vieira et al., 2024; Turaga, 2025) are impractical, and the prior linear-time exact method (Phan et al., 2025) only supports SentencePiece BPE. ByteSampler is the first approach that is simultaneously exact, O(1) in inference overhead, and compatible with HuggingFace ByteLevel BPE tokenizers that feature future-dependent pretokenization.

## Why It Matters / Open Questions

The 0.72-token overhead (vs. 49.47 for the next-best exact method) makes byte-level sampling from tokenized LMs practically viable, unlocking applications that were previously infeasible: ensembling models with mismatched tokenizers and transferring post-training recipes via proxy-tuning without retraining. The method is limited to BPE tokenizers and requires careful handling of pretokenization, special tokens, and merge-list normal form; generalization to Unigram, Wordpiece, and other tokenization schemes remains open. The paper also notes that exactness is modulo probability mass on invalid token sequences, an assumption that could matter for poorly trained models.
