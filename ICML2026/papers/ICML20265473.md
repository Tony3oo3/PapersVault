## Problem

Existing MoE offloading systems assume a server-grade architecture where CPU memory serves as a distinct external storage tier, but edge SoCs (Jetson, Raspberry Pi, Apple Silicon) use unified memory where CPU and GPU share the same physical memory pool, rendering these I/O-bound paradigms fundamentally mismatched. Meanwhile, lossy quantization alters model behavior in ways that introduce security vulnerabilities undetectable by standard metrics. The paper asks how MoE models can be efficiently served on mobile and edge platforms while preserving identical algorithmic behavior.

## Input / Output

The system takes a text prompt and a pre-processed MoE model whose BF16 parameters have been offline-decomposed into compressed exponent-bit chunks (E-chunks, via LZ4HC or ZSTD) and packed sign-mantissa chunks (SM-chunks), all stored on NVMe SSD. At runtime, the gate network selects experts per token, and the system reconstructs full BF16 tensors on-the-fly through parallel CPU decompression and a memory-coalesced GPU kernel, producing generated text tokens. The memory budget is tunable, and the system elastically leverages OS page cache when additional RAM is available from co-located applications.

## Method

ZIPMOE shifts on-device MoE inference from an I/O-bound bottleneck to a compute-centric workflow through a caching-scheduling co-design. First, it exploits the low Shannon entropy of BF16 exponent bits (support set only ~11–15% of symbols) to losslessly compress them, reducing I/O volume by ~30% while keeping sign-mantissa bits incompressible. Second, it introduces a four-tier hierarchical cache (full tensors, compressed tensors, SM-chunks, E-chunks) whose memory allocation is optimized via dynamic programming over a rank-based workload model that captures expert activation skewness independent of specific expert IDs. Third, a cache-affinity scheduler constructs DAGs per expert request and groups tasks into blocks that overlap SM-chunk SSD reads with parallel E-chunk decompression across L CPU worker threads, achieving a proven (3−1/L)-approximation to optimal makespan. A vectorized GPU kernel then reassembles the decompressed bit-fields into BF16 tensors with memory-coalesced access, fully hiding decompression latency behind I/O of other experts.

## Results

On Jetson AGX Orin (64 GB and 32 GB) with Samsung 970 EVO SSD, ZIPMOE achieves 62.65%–97.97% TPOT reduction and 53.25%–87.90% TTFT reduction for decoder-only MoE models (DeepSeekV2-Lite 16B, Qwen1.5-MoE 14B) where offloading is mandatory. For encoder-decoder models (SwitchTransformers-Large-128), the gains are 4.99%–81.24% TPOT and up to 83.45% TTFT reduction. In batch inference, ZIPMOE delivers 1.79×–42.49× throughput improvement over baselines for decoder-only models and 1.31×–5.82× for encoder-decoder models, with end-to-end speedups of 3.03×–42.49× and 1.11×–5.64× respectively.

## Baselines & Comparisons

ZIPMOE consistently outperforms all three main baselines (MoE-Infinity, DeepSpeed ZeRO-3, and Accelerate) across every evaluated metric—TPOT, TTFT, throughput, and end-to-end latency—on both Jetson AGX Orin 64 GB and 32 GB platforms. The largest gains appear in low-memory, batch-size-1 interactive settings where I/O stalls dominate: ZIPMOE reduces TPOT by up to 97.97% versus MoE-Infinity on decoder-only models. In batch inference (batch sizes 1–16), ZIPMOE's cache-affinity scheduler amplifies parallelism, yielding up to 42.49× throughput over DeepSpeed. In the extended comparison against FineMoE (a 2026 baseline), ZIPMOE achieves roughly 50× lower TPOT (0.24 s vs. 19.4 s at 30 GB RAM), because FineMoE's aggressive prefetching saturates the narrow PCIe/NVMe bandwidth of edge SoCs under single-batch workloads. The ablation (Table 1) attributes ~76% of the total throughput gain to the lossless decompression engine and CPU-parallel scheduling, with the remaining ~24% from the hierarchical cache-pool planning.

## Relation to Prior Work

This paper departs from two established lines of work: (1) lossy quantization/pruning for on-device LLMs, which the authors argue introduces security vulnerabilities and unmeasurable behavioral shifts, and (2) offloading-based MoE serving systems (MoE-Infinity, DeepSpeed, Accelerate) that assume a server-like memory hierarchy with separate CPU and GPU memory pools. While prior work on BF16 entropy heterogeneity (ZipNN, DFloat11, Huff-LLM) identified the compressibility of exponent bits, those approaches target GPU-accelerated decompression or large-batch amortization. ZIPMOE repurposes this observation for a fundamentally different system context—UMA-based edge SoCs where CPU and GPU share memory—combining lossless compression with a novel DAG-based cache-affinity scheduler that has provable approximation guarantees, a design absent from prior MoE serving literature.

## Why It Matters / Open Questions

The paradigm shift from I/O-bound to compute-centric expert access addresses a genuine bottleneck for the growing class of on-device MoE applications (chatbots, embodied AI, personal assistants) where batch size is one and memory is tightly constrained. The security argument against quantization for unmonitored edge deployments is compelling and underexplored. However, evaluation is limited to NVIDIA Jetson AGX Orin with a single SSD model, and the system's applicability to other SoC architectures (Apple Silicon, Raspberry Pi) or to CPU-GPU hybrid memory systems remains unvalidated. Open questions include whether the compression-scheduling co-design generalizes to larger MoE models (100B+), whether the rank-based workload model holds under truly non-stationary workloads, and how the approach interacts with emerging on-device accelerators beyond CUDA.
