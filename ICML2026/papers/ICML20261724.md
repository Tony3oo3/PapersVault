## Problem

Existing kernel crash-resolution benchmarks (e.g., KBENCHSYZ) are static, with fixes dating back to 2018, making them vulnerable to LLM data contamination and failing to capture the rapid evolution of the Linux kernel. Additionally, no standardized, agent-agnostic execution environment exists for kernel crash resolution, forcing each agent to build its own heavyweight compilation and testing infrastructure, which prevents fair cross-agent comparison.
![Teaser figure](../imgs/ICML20261724/cropped_page2_idx0.webp)

## Input / Output

Each benchmark instance provides a Syzbot crash report, a proof-of-concept reproducer, and the Linux kernel source checked out at the exact commit where the bug was introduced; the agent produces a git diff patch along with metadata (dollar cost, wall-clock time, tool trajectory). Evaluation runs 25 crash-reproduction attempts on the patched kernel for CRR, uses an LLM judge (Gemini 3 Flash, 9 votes, majority threshold) for patch equivalence against the developer's fix, and computes IoU at file and function granularity for localization. The CRF tool returns one of three signals per invocation—crash resolved, crash reproduced with new stack trace, or compilation error—enabling iterative refinement within the agent loop.

## Method

The paper introduces two coupled systems. KENV is an agent-agnostic Docker environment that separates a shared base image (kernel source at the correct commit, crash context, CRF tool) from a thin agent-specific overlay (installation and invocation logic), exposing a single run_kernel bash interface that offloads compilation and testing to the KGYM-SUITE cluster; this decoupling lets any bash-capable agent (mini-SWE-agent, SWE-agent, OpenHands) operate under identical conditions without modifying its scaffold. LIVE-KBENCH is a self-evolving benchmarking pipeline that weekly crawls Syzbot for new bugs, populates metadata, generates SuiteCache for incremental compilation, filters for reproducibility over five attempts, invokes registered agents through KENV, and evaluates patches on CRR, EPR, and localization IoU before publishing results to a public dashboard. The inaugural release, LIVE-KBENCH-2512, contains 534 bugs (April 2024–December 2025) spanning 70 subsystems and 10 bug types, enabling time-aware studies such as measuring the 25% EPR gap between pre- and post-cutoff bugs.

## Results

On LIVE-KBENCH-2512 (534 Linux kernel bugs), the best agent configuration (mini-SWE-agent + Claude Opus 4.5) achieves 74.16% crash resolution rate (CRR) and 19.85% equivalent patch rate (EPR), with 69.15% file-level and 53.53% function-level localization IoU. Across the three benchmarked agentic scaffolds (mini-SWE-agent, SWE-agent, OpenHands) with Gemini 3 Pro, CRR ranges from 72.47% to 75.03% and EPR from 14.73% to 15.86%, indicating that ~74% of crashes are resolved on the first attempt but only ~15–20% of patches are equivalent to developer fixes. Enabling crash resolution feedback (CRF) improves CRR by 29.12% (Mean@3) while leaving EPR and localization IoU essentially unchanged. Agents achieve up to 25% higher EPR on bugs fixed before the LLM knowledge cutoff (January 2025) compared to fresh bugs after the cutoff.

## Baselines & Comparisons

Among the three agentic scaffolds compared in Table 4, mini-SWE-agent achieves the highest CRR (75.03%) while SWE-agent achieves the highest EPR (15.86%) and localization IoU, but the differences are marginal (<3% CRR, <1.5% EPR), suggesting that scaffold choice has limited impact relative to the LLM backend. In oracle mode (Table 5), mini-SWE-agent (69.35% CRR, 17.17% EPR) slightly outperforms the dedicated kernel agent CrashFixer (68.79% CRR, 16.54% EPR), indicating that general-purpose agents with perfect file localization can match specialized kernel repair agents. Across LLM backends (Table 3), Claude Opus 4.5 dominates Gemini 3 Pro and Gemini 3 Flash on every metric (74.16% vs. 70.22% vs. 48.63% CRR; 19.85% vs. 14.67% vs. 8.18% EPR), with the gap between Pro and Flash models being particularly large (~22% CRR). The knowledge-cutoff experiment (Table 1) shows that Gemini 3 Pro gains 25.73% in EPR (Pass@10) on pre-cutoff bugs versus post-cutoff bugs, confirming data contamination effects that static benchmarks like KBENCHSYZ cannot capture.

## Relation to Prior Work

This paper extends the kernel crash resolution line initiated by KGYM/KBENCHSYZ (Mathai et al., 2024) and its execution platform KGYM-SUITE (Mathai et al., 2025), which introduced static benchmarks and a tightly-coupled agent (CrashFixer) for Linux kernel repair. The key departure is twofold: LIVE-KBENCH replaces the static, contamination-prone dataset with a continuously curated, time-aware benchmark, and KENV decouples agent workflows from the heavyweight kernel compilation/testing environment, making evaluation agent-agnostic rather than scaffold-specific. Conceptually, it brings the 'live benchmark' paradigm pioneered by SWE-bench-Live and LiveCodeBench to the systems-software domain, where execution costs and codebase scale make the problem substantially harder.

## Why It Matters / Open Questions

The 25% EPR gap across the LLM knowledge cutoff provides concrete, reproducible evidence of data contamination in kernel repair evaluation, a concern that static benchmarks cannot address. More broadly, the persistent gap between crash resolution (74%) and developer-equivalent patches (~20%) reveals that current agents predominantly suppress symptoms rather than fix root causes, and the finding that CRF boosts CRR by 29% without moving EPR confirms this limitation is structural rather than a feedback-availability issue. Open questions include defining validity metrics beyond the CRR/EPR sandwich, incorporating dynamic execution traces, and reducing the 33-minute CRF latency to enable tighter iterative loops.
