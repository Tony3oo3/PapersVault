## Problem

Optimizing complex systems (prompts, code, agent harnesses) with LLM-based optimizers suffers from two compounding issues: stochastic evaluation (from minibatch sampling, stochastic program execution, and noisy LLM judges) causes unstable updates and premature rejection of good candidates, and the discrete parameter space grows without bound as the LLM repeatedly proposes semantically similar programs. Existing generative optimization methods either assume deterministic evaluation or lack principled mechanisms to control search-space growth under noise.

## Input / Output

The method takes a parameterized program (a prompt string, CUDA kernel, Lean 4 code, or agent harness), a dataset of tasks, an evaluation guide returning a numerical score and textual feedback per task, an LLM optimizer that proposes revised parameters given local rollouts and global context, and an embedding model for computing semantic distances between parameters. It outputs the best program parameter identified during search, maintained within a priority queue that stores each candidate's full evaluation history. The parameter space is discrete and exponentially large (e.g., all valid Python programs), and the same minibatch is used to evaluate both existing and newly proposed candidates to ensure fair comparison under stochasticity.

## Method

POLCA is a search algorithm built around an external LLM optimizer, maintaining a priority queue of candidate programs ranked by empirical mean score. Two key mechanisms address the core challenges: (1) an ε-Net semantic filter that uses embedding distances to admit a new candidate only if it is semantically distinct (distance > ε) from all programs already in memory, bounding the total number of distinct programs to N_ε and preventing unbounded evaluation costs; and (2) an LLM Summarizer that compresses the entire evaluation history into a global context c_history, providing the optimizer with cross-program success/failure patterns analogous to momentum in gradient descent. Each iteration samples a minibatch, selects top-scoring programs for re-evaluation, invokes the optimizer with local rollouts plus c_history to propose new candidates, applies the ε-Net filter, evaluates survivors on the same minibatch, and updates the queue. Theoretically, with a UCB priority, POLCA converges to near-optimal solutions with sample complexity O((B/γδ₀ + σ²N_ε/γ²) log n), where γ and δ₀ capture optimizer quality and σ² captures evaluation stochasticity.

## Results

On τ-bench (115 retail tasks), POLCA achieves a 0.439 pass@1 score, a 13% improvement over the base prompt (0.389) and outperforming GEPA (0.429) and OpenEvolve (0.418). On VeriBench compilation (deterministic), POLCA reaches a 95.2% pass rate (133/140) with a budget of 50 metric calls per task, substantially exceeding DSPy (88.8%), GEPA (69.5%), and OpenEvolve (73.8%). Across all four benchmarks (τ-bench, HotpotQA, VeriBench, KernelBench), POLCA consistently achieves the highest score at every evaluation step, demonstrating superior sample efficiency in both stochastic and deterministic settings.

## Baselines & Comparisons

POLCA outperforms all three baselines across every benchmark tested. Against GEPA, POLCA wins on τ-bench (0.439 vs. 0.429 pass@1) and VeriBench compilation (95.2% vs. 69.5% pass rate), with the gap attributed to GEPA's reliance on static validation scores and its inability to update program statistics as new stochastic data arrives. Against OpenEvolve (an open-source AlphaEvolve implementation), POLCA achieves higher scores on τ-bench (0.439 vs. 0.418) and VeriBench compilation (95.2% vs. 73.8%), benefiting from continuous re-evaluation of high-performing programs rather than single-shot scoring. Against DSPy (sequential iterative refinement), POLCA reaches 95.2% vs. 88.8% on VeriBench compilation, with the advantage coming from parallel exploration of multiple starting points and global context summarization. On HotpotQA and KernelBench (shown in Figure 2), POLCA also leads all baselines in convergence speed and final performance, confirming that the ε-Net filtering and priority-queue memory provide consistent gains regardless of the stochasticity source.

## Relation to Prior Work

POLCA builds directly on the Trace framework (Cheng et al., 2024) for generative optimization with rich feedback, but departs from prior search strategies (sequential refinement in DSPy, Pareto-frontier search in GEPA, evolutionary/MAP-Elites search in AlphaEvolve and OpenEvolve) by explicitly addressing evaluation stochasticity through a continuously updated priority queue and an ε-Net semantic filter. While prior methods like ShinkaEvolve and AlphaCode use heuristic filtering for novelty, POLCA provides the first theoretical justification for embedding-based ε-Net filtering as necessary for convergence under stochasticity, and introduces a UCB-based convergence analysis for the generative optimization setting. The paper also positions itself against bandit-based selection (UCB, beam search) by showing that the unbounded, discrete parameter space accessed only through an LLM optimizer requires a fundamentally different treatment than finite-arm bandits.

## Why It Matters / Open Questions

POLCA offers a principled, theoretically grounded framework for the increasingly common scenario where LLM-based optimization must operate under noisy, stochastic evaluation (minibatch sampling, stochastic program execution, LLM-as-a-judge), a setting where prior methods silently degrade. The ε-Net mechanism provides a practical, tunable knob (ε) for the exploration-coverage tradeoff that was previously handled by ad-hoc heuristics. Open questions include whether the strict-improvement assumption (Assumption 1) holds for weaker optimizers, whether more sophisticated function approximation than embedding-based filtering can further reduce sample complexity, and whether the empirical results generalize beyond the four benchmarks and model families tested. The framework's modularity (swappable optimizer, priority function, and filter) makes it a useful substrate for future LLM-based optimization research.
