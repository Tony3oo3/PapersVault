## Problem

Existing code-migration benchmarks either target function-level SIMD intrinsics (SIMDBench, VecIntrinBench) or scalar bug-fixing (SWE-Bench), leaving a critical gap: no benchmark evaluates LLM agents on realistic, library-scale cross-architecture migration where agents must navigate million-line codebases, resolve cross-file dependencies, and rewrite ISA-specific SIMD intrinsics while preserving performance. This paper asks whether current SOTA agents can handle such tasks and, if not, what structural capabilities they lack.
![Teaser figure](../imgs/ICML20262436/cropped_page0_idx0.webp)

## Input / Output

Each migration task is a tuple T = (I, R_src, E), where I is a natural-language specification naming the target operator, file path, and destination ISA; R_src is the full source library with its file structure and build configurations (input scale ~717K LoC); and E is the agent's execution environment. The agent must produce a target library R_tgt (~991 LoC of modified code) that compiles, passes functional equivalence tests against the scalar ground truth, and achieves a measurable speedup ratio over the existing target-architecture baseline. Evaluation spans three orthogonal axes—compilability, SR@k correctness, and fast_p performance—across 85 kernels from OpenCV, ncnn, and libjpeg on three migration paths (ARM→RISC-V, x86→ARM, ARM→LoongArch).

## Method

The paper contributes two components. First, QM-LibBench, a benchmark of 85 performance-critical SIMD kernels mined from industrial libraries via dynamic test-suite tracing to ensure functional centrality and active maintenance, with custom Google Test/Benchmark suites for libraries lacking operator-level tests. Second, FSCM (Faster and Smarter Code Migration), a four-phase multi-agent framework that (1) parses the source repository into a Global Functional Dependency Graph (GFDG) capturing per-module semantics and architecture-independent optimization strategies, (2) performs dependency-aware recursive code generation starting from core functions and expanding outward to produce architecture-independent scalar equivalents, (3) applies two-level performance optimization—architecture-independent refinements from the GFDG plus target-specific strategies (register grouping, vector-length-agnostic extension for RVV)—and (4) runs multi-stage compilation, functional, and performance tests with error feedback triggering iterative correction. FSCM with GPT-5 reaches 71% correctness on OpenCV, roughly doubling the best standalone agent (OpenHands+GPT-5 at 37.65% SR@1), confirming that explicit architectural reasoning and dependency-aware planning are necessary beyond surface-level pattern matching.

## Results

Across 12 agent-LLM combinations on QM-LibBench, the best overall correctness is 37.65% SR@1 and 52.94% SR@3, achieved by OpenHands + GPT-5. The average across all combinations is only 20.88% SR@1 and 33.92% SR@3, with libjpeg being the hardest library (avg. 10.26% SR@1). On performance, the fast_p metric drops sharply: at p=1.0 (no degradation), most agents are near-zero, and at p>1.2, virtually no agent produces code with any speedup. The proposed FSCM framework improves OpenCV correctness to 71%, substantially outperforming the best agent-LLM combination (28.57% SR@1).

## Baselines & Comparisons

SWE-Agent collapses across nearly all metrics (avg. 3.53% SR@1), as its issue-level workflow from SWE-Bench does not transfer to library-scale C/C++ SIMD migration; even with GPT-5 it achieves 0% on libjpeg. OpenHands + GPT-5 is the strongest baseline at 37.65% SR@1 overall, benefiting from its CodeAct-based iterative debugging loop, but still leaves 62% of tasks unresolved. JoyCode + GPT-5 is competitive on SR@3 (47.06%) and leads on x86→ARM performance (fast_p=0.55), while TRAE + MiniMax-M2.1 achieves the highest overall SR@1 among TRAE variants (27.06%) but trails OpenHands by ~10 points. The proposed FSCM framework with GPT-5 reaches 71% correctness on OpenCV, more than doubling the best agent-LLM combination (28.57% SR@1 / 38.10% SR@3), confirming that explicit architectural optimization and dependency-aware generation are necessary beyond what current agents provide.

## Relation to Prior Work

This paper carves new ground at the intersection of two previously separate research threads: library-scale code agent evaluation (SWE-Bench, OpenHands) and cross-architecture SIMD intrinsic migration (SIMDBench, VecIntrinBench, neon2rvv). Prior SIMD benchmarks operate at function level with natural-language descriptions, while repo-level benchmarks like SWE-Bench ignore architecture-specific vectorization entirely. QM-LibBench unifies these by requiring agents to navigate real build systems, multi-file dependencies, and ISA-specific semantics simultaneously, with performance as a first-class metric. The proposed FSCM framework extends multi-agent code generation with a Global Functional Dependency Graph and explicit hardware-aware optimization, departing from the translation-only paradigm of prior intrinsic translators like IntrinTrans and VecTrans.

## Why It Matters / Open Questions

The benchmark reveals a stark capability gap: even the strongest agent-LLM combination (OpenHands + GPT-5) achieves only 37.65% SR@1 overall, and migrated code is often *slower* than baseline (0.83× speedup on libjpeg), exposing that current agents perform surface-level pattern matching rather than architectural reasoning. This has direct practical implications for the maturation of emerging hardware ecosystems (RISC-V, LoongArch), where manual SIMD porting is a bottleneck. Open questions include whether the benchmark will saturate as agents improve, whether GPU-oriented migration paths can be incorporated, and whether the FSCM approach (71% on OpenCV) generalizes to the full benchmark. The reproducibility limitation of closed-source commercial agents (TRAE, JoyCode) also constrains the field's ability to diagnose *why* certain agent designs succeed or fail.
