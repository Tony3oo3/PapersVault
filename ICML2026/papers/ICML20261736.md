## Problem

Existing Relational Deep Learning (RDL) methods construct a fixed schema graph from the RDB and train GNNs on top of it, but this rigid structure limits which relational patterns are accessible during message passing. Traditional graph structure learning (edge pruning or addition) is incompatible with RDL because it violates the full-resolution property (the graph must losslessly encode the RDB) and can break functional dependency constraints. The paper asks whether schema graph structure can be jointly optimized with the GNN while preserving both full-resolution and functional dependencies.

## Input / Output

The method consumes a relational database (tables with entity attributes, foreign-primary key links, and timestamps) and produces both downstream task predictions (classification, regression, or recommendation) and a learned schema graph where each table is assigned a node or edge role per relation. A key constraint is full-resolution: the constructed graph must satisfy H(X|G)=0 so the original RDB is uniquely recoverable. Table roles are not a single global assignment but are learned per relation via EMA-smoothed gating, and the FD constraints are enforced at two granularities — a low-rank subspace regularization on table-level embedding differences and an InfoNCE contrastive loss on entity-level pairs.

## Method

FROG formulates graph structure learning as a learnable table-role problem: each table is mapped to either a node (table-as-node) or an edge (table-as-edge) in the schema graph, and the choice is optimized end-to-end via a role-aware gating mechanism that blends node-level and edge-level message passing paths. For table-as-edge, two relation paradigms are defined — Co-Occurrence (u←v→w, symmetric interaction) and Completion (u→v→w, sequential mediation) — each with a dedicated convolution operator. A theoretical result (Theorem 4.2) shows that table-as-edge retains strictly more mutual information about distant entities than table-as-node under lossy intermediate aggregation, justifying the edge role for long-range dependencies. Functional dependency constraints are enforced through two complementary losses: a table-level loss projecting embedding differences into a learned low-rank subspace, and an entity-level contrastive loss (InfoNCE) that scores whether an entity pair satisfies the FD. Training alternates between GNN optimization (FD parameters frozen) and FD model optimization (GNN frozen), enabling stable joint learning of structure and representations.

## Results

FROG achieves the best or near-best performance across 23 tasks on 6 RelBench datasets. On entity classification (ROC-AUC), FROG leads on 6 of 7 tasks, with the largest margin on rel-event user-ignore (85.49 vs. RelGNN's 82.55, +2.94). On entity regression (MAE), FROG is best on 5 of 7 tasks, e.g., rel-f1 driver-position (3.89 vs. RelGNN's 3.98) and rel-trial site-success (0.350 vs. RelGNN's 0.360). On entity recommendation (MAP), FROG is best on 5 of 6 tasks, with the clearest win on rel-avito user-ad-visit (3.87 vs. RelGNN's 3.14, +23%).

## Baselines & Comparisons

FROG consistently outperforms LightGBM across all 23 tasks with large margins (e.g., +12.6 AUC on rel-event user-ignore, +2.9 MAP on rel-avito user-ad-visit), confirming that GNN-based relational modeling substantially exceeds tabular gradient boosting. Against the RelBench GraphSAGE baseline (RDL), FROG wins on most classification and regression tasks, with the largest gap on rel-event user-ignore (+3.57 AUC) and rel-trial site-success (MAE 0.350 vs. 0.416). Against RelGNN (the strongest GNN baseline), FROG achieves the best result on 16 of 23 tasks; margins are modest on some regression tasks (e.g., rel-hm item-sales: 0.0561 vs. 0.0564 MAE; rel-stack post-votes: 0.0655 vs. 0.0656) and on rel-trial site-sponsor-run (19.09 vs. 19.10 MAP), where RelGNN edges out FROG by a negligible amount. Against RDL (ID-GNN) on recommendation tasks, FROG wins on 5 of 6 tasks, with the most pronounced advantage on rel-avito user-ad-visit (3.87 vs. 3.73 MAP). Overall, FROG's gains over RelGNN are most pronounced on classification tasks with complex multi-table relations (rel-event, rel-f1) and on recommendation tasks, suggesting that learned table roles are particularly beneficial when relational structure is non-trivial.

## Relation to Prior Work

This paper sits at the intersection of Relational Deep Learning (RDL), which models RDBs as heterogeneous graphs for GNN-based prediction (Fey et al., 2024; RelGNN, Chen et al., 2025), and Graph Structure Learning (GSL), which jointly optimizes graph topology and model parameters (Jin et al., 2020; Sun et al., 2022). It builds most directly on RDB2G (Choi et al., 2025), which first explored modeling tables as edges in schema graphs, but departs by making table roles continuously learnable rather than discretely enumerated, and by proving that traditional GSL operations (edge pruning/addition) violate the full-resolution property essential to RDB modeling. The functional dependency loss is a novel regularization not present in prior RDL or GSL work.

## Why It Matters / Open Questions

By showing that schema graph structure can be co-optimized with GNN representations while preserving full-resolution, this work opens a path toward adaptive relational modeling that goes beyond the fixed-pipeline assumption in current RDL benchmarks. The structural transferability results (learned table roles generalizing across tasks) suggest that relational structure is partly task-agnostic, which could reduce the cost of deploying RDL models on new tasks. Open questions include scalability to very large RDBs with many relation types, whether the dual node/edge representation overhead is prohibitive in production settings, and whether the FD constraints generalize to more complex dependency patterns (multi-attribute, transitive).
