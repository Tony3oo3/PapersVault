## Problem

Existing LLM-based OS kernel tuning methods operate as static, open-loop systems that treat the kernel as a black box, suffering from a fundamental semantic mismatch between the LLM's generalized reasoning and low-level hardware-software behaviors. This mismatch manifests as runtime blindness to actual telemetry, configuration fragmentation under context-window constraints, and hallucination-induced search drift that wastes the prohibitively expensive 40–70 minute evaluation budget per iteration.

## Input / Output

The method ingests raw hardware descriptors (from /proc/cpuinfo, lstopo), millions of perf-sampled hot call stacks, and the default Linux kernel configuration tree (~15,000+ Kconfig parameters with dependency constraints managed by Kconfiglib), then produces a single optimized .config file that must satisfy a strict bootability constraint. The optimization is budget-constrained to 15 iterations (13 for global search, 2 for posterior enhancement), with each iteration requiring a full kernel recompilation and benchmark run. Performance is measured as relative throughput or latency against the vendor default configuration across five OS-intensive workloads (Redis, Apache, AES, PostgreSQL, RAG).

## Method

QiMeng-PerceptOS is a closed-loop, perception-driven framework with three synergistic modules. The Perception Module distills raw telemetry into compact semantic fingerprints via a hardware template (range merging, structural grouping) and a diversity-aware software template (top-v core stacks plus LLM-selected semantically distinct stacks from a [v, v+k] window), aligning low-level runtime behavior with the LLM's reasoning space. The Global Search Module navigates the configuration tree using a Bi-level Hierarchical Induction Tree (BHIT) that performs depth-first traversal, concurrently exposing immediate configuration options and LLM-synthesized subdirectory semantic summaries (via a Global Summary Template with on-demand caching) to enable the LLM to prune semantically misaligned branches and propose configurations at the intersection of hardware constraints and software demands. The Posterior Enhancement Module, activated after the search plateaus, re-audits all previously modified options in the Elitist Configuration Memory against current semantic fingerprints to filter hallucinated or semantically incongruent configurations, applying validated changes sequentially with Kconfiglib dependency validation and a two-layer boot-failure safeguard.

## Results

On the Ubuntu PC (AMD) environment with GPT-4o-mini, QiMeng-PerceptOS achieves 278.5% of default Redis throughput, 295.9% for Apache, 154.0% for AES, 154.5% for PostgreSQL, and 124.3% for RAG within 15 iterations. With Gemini-3-pro-preview on the same platform, Redis throughput reaches 296.6% and Apache reaches 323.5%, surpassing the best SOTA baseline (AutoOS) by 32.6% and 27.1% respectively. Across all three hardware environments and three LLM backends, QiMeng-PerceptOS consistently outperforms both Vanilla LLM and AutoOS baselines on every workload, with the largest gains observed on memory-intensive (Redis) and I/O-intensive (Apache) workloads.

## Baselines & Comparisons

QiMeng-PerceptOS consistently outperforms AutoOS (Chen et al., ICML 2024) across all 45 experimental configurations (3 LLMs × 5 workloads × 3 hardware platforms), with improvements ranging from +2.9% (AES on Ubuntu PC with DeepSeek) to +73.1% (Redis on Ubuntu PC with GPT-4o-mini). The gap is most pronounced on OS-intensive workloads: on Ubuntu PC with GPT-4o-mini, QiMeng-PerceptOS achieves 278.5% vs. AutoOS's 207.3% for Redis (+71.2%) and 295.9% vs. 181.8% for Apache (+114.1%). Against BYOS (Lin et al., 2025), a semi-automated knowledge-graph-based system, QiMeng-PerceptOS leads on all five workloads on the Fedora PC (e.g., +34.3% on Apache with GPT-4o-mini, +42.4% with DeepSeek). Notably, BYOS exhibits 'semantic friction'—it underperforms even vanilla AutoOS when paired with DeepSeek-V3.2 or Gemini-3-pro-preview—whereas QiMeng-PerceptOS maintains robust gains regardless of LLM backbone, confirming that dynamic semantic alignment is more effective than static expert priors.

## Relation to Prior Work

This paper builds directly on AutoOS (Chen et al., 2024), reusing its kernel configuration space formalization, Kconfiglib dependency management, and two-layer boot-failure safeguard, but departs fundamentally from AutoOS's static, open-loop prompt-based search by introducing a closed-loop perception-driven architecture. The key conceptual departure is the 'Semantic Mismatch' framing: rather than treating the LLM as a one-shot configuration suggester, QiMeng-PerceptOS grounds each search iteration in real-time hardware-software telemetry distilled into semantic fingerprints, navigates the configuration tree via a Bi-level Hierarchical Induction Tree (BHIT) with cached subdirectory summaries, and applies a posterior enhancement pass to filter hallucinated options. It also positions against BYOS (semi-automated, expert-knowledge-graph driven) and OS-R1 (RL distillation into lightweight models), arguing that dynamic perception is more generalizable than static expert priors or fixed-hardware distillation.

## Why It Matters / Open Questions

The paper demonstrates that a perception-driven closed-loop can substantially outperform static LLM-based kernel tuning (up to ~33% over AutoOS) within a tight 15-iteration budget, and that the framework's gains are robust across hardware, OS distributions, and LLM backends—including the notable finding that an 8B model with QiMeng-PerceptOS can match or exceed a frontier model with AutoOS. However, the approach is inherently software-specific (optimizing for one workload may degrade others), its impact diminishes for compute-intensive tasks with sparse OS interactions, and it has not been validated on distributed clusters or real-time systems. Open questions include how to define aggregate multi-workload objectives, whether the perception module generalizes to other high-dimensional compile-time configuration spaces beyond the Linux kernel, and whether the posterior enhancement module's 35% success rate can be improved with more principled attribution rather than trial-and-error filtering.
