## Problem

Transformers provably fail to learn certain simple Boolean functions (e.g., PARITY, FIRST) that are expressible with specific parameter settings, yet the precise mechanism behind this expressivity-learnability gap remained unclear. Prior work identified a bias toward low average sensitivity but could not explain why optimization fails to reach the required parameters. This paper addresses the gap by analyzing the Lebesgue volume of parameter space occupied by different classes of Boolean functions.
![Teaser figure](../imgs/ICML20262218/cropped_page1_idx0.webp)

## Input / Output

The transformer consumes binary strings of length N appended with an EOS token and produces a scalar logit at the EOS position, which is thresholded at margin ξ to yield a Boolean acceptance decision. The analytical object of study is the sensitivity profile K_0(N), K_1(N), …, K_N(N) — the count of input strings at each sensitivity level — which characterizes how the computed function's output responds to single-bit flips. The parameter space Θ ⊂ ℝ^M is treated as a compact set with Lebesgue-measure-zero boundary, and the central question is what fraction of Θ encodes functions with a given sensitivity profile.

## Method

The paper develops a measure-theoretic framework built around the per-layer blowup τ^ℓ, which quantifies how layer normalization can amplify input perturbations. For ε > 0, the transformer is uniformly Lipschitz in parameters, enabling a packing argument that bounds the total number of recognizable functions by a constant independent of N. For the main case ε = 0, the key lemma shows that randomly perturbing the last bias of any layer keeps the variance (and hence blowup) bounded with high probability, because the 'danger zone' of near-zero variance occupies vanishing volume in the perturbation hypercube. A union bound over positions and layers, combined with a covering argument over Θ, yields that a uniformly random transformer has at least N^{(D-1)/(2L)−5} sensitivity-zero strings for all large N. The Borel-Cantelli lemma then aggregates this over all sufficiently large lengths to prove that almost every transformer fails to recognize any function whose sensitivity-zero count falls below this polynomial floor — ruling out PARITY, FIRST, and all dictator functions.

## Results

The main theoretical result (Thm. 4.5) shows that a uniformly random transformer with D dimensions and L layers almost surely has at least N^((D-1)/(2L)−5) strings with sensitivity 0 for all sufficiently large N. This yields the unlearnability threshold (Cor. 4.6): any Boolean function family with K_0(N) < N^((D-1)/(2L)−5) sensitivity-zero strings is provably unlearnable. In the ε>0 warm-up (Cor. 3.4, Prop. 3.5), no non-constant Boolean function is recognizable for arbitrarily long inputs, and the total number of recognizable functions at any length N is bounded by (1 + C_Lip·diam(Θ)/ξ)^M, a constant independent of N. Empirically, sensitivity profiles of randomly initialized transformers across four initialization schemes (uniform, Gaussian, Xavier uniform, Xavier Gaussian) are heavily skewed toward zero, and this bias persists after training.

## Baselines & Comparisons

This paper does not compare against competing methods in the standard ML sense; instead, it generalizes and strengthens the prior theoretical framework of Hahn & Rofin (2024), which analyzed sensitive functions via average sensitivity alone. The key advance is shifting from average sensitivity to the full sensitivity profile (the distribution of sensitivity values across all inputs), which captures cases that average-sensitivity analysis misses—most notably FIRST, which has average sensitivity 1 (low) yet is still provably unlearnable because it has zero sensitivity-zero strings. The ε>0 analysis (Section 3) serves as an internal baseline showing that transformers are even more inexpressive when the layer-norm stabilizing constant is positive: the number of recognizable functions is bounded by a constant independent of N, whereas the ε=0 case (Section 4) restores some expressivity but still leaves most sensitive functions unlearnable. Compared to the uniform-random-Boolean-function baseline (Prop. 7.1), where only ~63% of random functions have any sensitivity-zero strings, a random transformer has sensitivity-zero strings with probability 1, confirming a genuine inductive bias rather than a counting artifact.

## Relation to Prior Work

This paper extends the parameter-space analysis framework of Hahn (2020) and Hahn & Rofin (2024), which studied transformer expressivity through the lens of average sensitivity. The key conceptual departure is shifting from average sensitivity to the full sensitivity profile—the distribution of sensitivity values across all input strings—and using measure-theoretic tools (Lebesgue measure, Borel-Cantelli) to prove that sensitive functions occupy a measure-zero subset of parameter space. This generalizes Hahn & Rofin's results by capturing functions like FIRST (average sensitivity 1) that average-sensitivity analysis alone cannot rule out, and by providing a polynomial lower bound on the number of sensitivity-zero strings any random transformer must have.

## Why It Matters / Open Questions

The paper provides the first measure-theoretic explanation for the well-observed gap between transformer expressivity and learnability on sensitive Boolean functions, showing that the inductive bias is not merely toward low average sensitivity but toward functions with a non-empty lower tail in their sensitivity profile. A notable limitation is that all unlearnability results are asymptotic: transformers can and do learn functions like FIRST at moderate input lengths, so the threshold where failure necessarily occurs may be impractically large. Open questions include whether the polynomial lower bound on sensitivity-zero strings can be tightened to exponential (as experiments suggest), whether an abundance of such strings guarantees learnability (the MAJORITY conjecture), and whether the bias provably persists after training rather than merely being observed empirically.
