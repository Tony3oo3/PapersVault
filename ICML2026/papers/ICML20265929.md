## Problem

Extending code-based 3D scene generation to physically grounded 4D environments faces two fundamental challenges: multi-scale context entanglement, where a single generation pass cannot simultaneously resolve fine-grained local object geometry and coherent global environmental layout, and a semantic-physical execution gap, where open-loop LLM code generation produces syntactically valid but physically implausible dynamics (e.g., rigid-body distortion, gravity violations). Prior code-to-scene frameworks are restricted to static representations and lack any temporal simulation capability.

## Input / Output

The system takes a single natural-language prompt describing a 4D scene (e.g., 'a breeze stirs through the autumn forest, gently swaying the entire tree as leaves dance in the wind') and produces executable Blender/Infinigen Python scripts that, when run, yield a dynamic 3D scene with physics-aware motion. Rendering is performed via Blender 4.3's Cycles path-tracer at 1920×1080 (240 frames for nature scenes, 120 for indoor scenes), and the final output is a temporally coherent video rollout of the simulated scene. The LLM backbone is Gemini 3, used across all agent roles (planning, parameter generation, code synthesis, and VLM critique).

## Method

Code2Worlds employs a dual-stream architecture that decouples object generation from environmental orchestration to resolve multi-scale entanglement. The Object Stream uses retrieval-augmented parametric generation: it queries a Procedural Parameters Library and a Reference Code Library (both derived from Infinigen's factory API) to condition the LLM on structured parameter schemas and canonical code templates, then iteratively refines via a VLM-based Object Self-Reflection loop that renders 2D snapshots and feeds natural-language corrections back to the parameter agent. The Scene Stream runs a three-stage hierarchical pipeline—Semantic Decomposition (inferring latent atmospheric, terrain, and vegetation context from sparse prompts), Parameter Concretization (grounding qualitative descriptors into precise scalars with logical consistency checks), and 3D Scene Realization (compiling the parameter dictionary into valid Infinigen execution code). Finally, a PostProcess Agent unifies the object and scene, scripts temporal dynamics (wind, fluid, rigid-body, particle effects) as Blender physics constraints, and a VLM-Motion Critic evaluates rendered video rollouts to iteratively correct physical hallucinations, closing the loop between semantic intent and simulated motion.

## Results

On the Code4D benchmark, Code2Worlds achieves a state-of-the-art SGS of 61.4 for object generation (a 41% gain over the best baseline ImmerseGen at 43.5) and a Richness score of 62.3 for scene generation (a 49% increase over 3D-GPT's 41.7). For video dynamics, it attains the best Motion Smoothness (0.9952), Subject Consistency (0.9415), and Temporal Flickering (0.9949) while maintaining a physics Failure Rate of only 10%, compared to 30–70% for video diffusion baselines. The method is the only one to report both HRS (55.4) and a non-trivial Failure Rate, confirming its unique capability for physics-aware 4D generation.

## Baselines & Comparisons

Against code-centric baselines, Code2Worlds dominates across all reported metrics: it outperforms ImmerseGen (the strongest agent-based competitor) by 17.9 points in SGS (61.4 vs. 43.5) and 26.8 in Richness (62.3 vs. 35.5), while also leading in O-CLIP (0.2655 vs. 0.2417) and S-CLIP (0.2432 vs. 0.2210). Infinigen and 3D-GPT, though strong in procedural detail, lack text controllability and self-reflection, yielding lower SGS (35.5 and 37.0) and Richness (41.0 and 41.7). SceneCraft, despite supporting self-reflection, achieves the lowest Richness (15.2) among code-centric methods, indicating sparse scene population. In the video dynamics comparison, Code2Worlds achieves the lowest physics Failure Rate (10%) versus 30% (Hunyuan), 50% (SVD, CogVideoX), and 70% (AnimateDiff), while also leading in Motion Smoothness and Temporal Flickering; Hunyuan marginally edges it on Background Consistency (0.9717 vs. 0.9710), and AnimateDiff scores higher on Subject Consistency (0.9778 vs. 0.9415) but at the cost of severe physical artifacts.

## Relation to Prior Work

This paper extends the LLM-driven code-to-scene paradigm (Infinigen, 3D-GPT, SceneCraft) from static 3D layout to physics-aware 4D simulation, building directly on Infinigen's procedural factory API as its generation substrate. The key conceptual departure is a dual-stream architecture that factorizes object-level parametric generation from scene-level environmental orchestration, combined with a closed-loop VLM-based self-reflection mechanism that has no direct precedent in prior code-to-scene work. It also positions itself against neural 4D generation methods (MAV3D, DreamGaussian4D) by arguing that executable simulation code offers superior physical controllability and editability compared to learned representations like dynamic NeRFs or Gaussian splatting.

## Why It Matters / Open Questions

The paper addresses a genuine gap: prior code-to-scene methods produce only static 3D output, while neural 4D methods lack the structural controllability and physical grounding that executable simulation code provides. The Code4D benchmark, though small, is the first to systematically evaluate 4D code generation across object fidelity, scene richness, and physical plausibility, giving the community a concrete target. Key limitations include tight coupling to a single proprietary LLM (Gemini 3) for all agents, substantial computational overhead from iterative VLM feedback and Cycles rendering that precludes real-time use, and a benchmark with only 10 representative prompts. Open questions include whether neural physics distillation can replace the expensive simulation loop, and whether the approach generalizes beyond the Infinigen asset library to open-ended 3D content.
