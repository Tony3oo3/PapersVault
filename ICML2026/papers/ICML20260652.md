## Problem

Current alignment techniques for secure code generation (SFT, RL) optimize at the sequence level, diluting the learning signal across entire code blocks and failing to correct the localized, single-token decisions where vulnerabilities actually originate. This coarse-grained approach cannot provide the dense, on-policy negative feedback needed to distinguish plausible-but-insecure alternatives from secure solutions at the precise decision points that matter.

## Input / Output

The method takes a programming task description (code prompt) and produces a secure code sequence. During training, the input is augmented with pre-annotated CWE Risk Nodes—specific token positions on the golden path where a vulnerability could be introduced—and the opponent player generates divergent continuations from those exact prefixes. The training signal is thus structured as preference pairs (golden path vs. self-play path) localized to individual risk nodes rather than whole sequences, with the final output being a standard code completion evaluated via static analysis (CodeQL) or LLM-based security judgment.

## Method

TSP reframes secure code generation as a tree traversal where an LLM annotator first identifies CWE Risk Nodes—critical forks where insecure token choices lead to vulnerabilities. At each risk node, a fixed opponent player (the model's previous iteration) generates a divergent, potentially insecure continuation, while the main player is trained via a DPO-style log-likelihood-ratio preference loss to assign higher score to the golden path than to the self-play path. Crucially, the loss is computed only at risk nodes rather than over the full sequence, concentrating all optimization pressure on security-critical decisions. The process iterates: after each round, the main player's parameters become the new opponent, progressively generating subtler negative examples as the model improves. This node-level, on-policy contrastive mechanism provides a dense learning signal that forces self-correction precisely where vulnerabilities emerge, without requiring external preference annotations.

## Results

On the Python SecurityEval benchmark, TSP achieves a Security Pass Rate (SPR@1) of 75.8% for CodeLlama-7B, outperforming SafeCoder (73.7%), Self-Play (69.6%), SFT (57.0%), and the Base LLM (55.0%). On the C/C++ DiverseVul benchmark, TSP reduces total vulnerabilities to 94 for CodeLlama-7B (vs. 115 for Base), 57 for Qwen2.5-Coder-7B (vs. 106 for Base), and 41 for Qwen2.5-Coder-3B (vs. 93 for Base). For generalization to 40 unseen CWE types, TSP achieves 27 vulnerabilities on CodeLlama-7B (vs. 50 for SFT) and 26 on Qwen2.5-Coder-7B (vs. 58 for SFT), while maintaining HumanEval pass@1 scores within 1–2 points of the base models.

## Baselines & Comparisons

TSP outperforms SafeCoder (He et al., 2024) by 2.1 points on SPR@1 (75.8% vs. 73.7%) for CodeLlama-7B on SecurityEval, while also matching SafeCoder's HumanEval pass@1 (34.0% vs. 33.9%) and exceeding it on pass@10 (54.7% vs. 52.5%). Against the Self-Play ablation (self-play without tree-structured risk nodes), TSP gains 6.2 points on SPR@1 (75.8% vs. 69.6%), confirming the necessity of the structured CWE Risk Node branching. On the C/C++ DiverseVul benchmark, TSP reduces vulnerabilities by 18.3% over Base LLM for CodeLlama-7B (94 vs. 115) and by 46.2% for Qwen2.5-Coder-7B (57 vs. 106), where SFT actually *increases* vulnerabilities (140) due to overfitting. On unseen CWE generalization, TSP achieves 26 vulnerabilities on Qwen2.5-Coder-7B versus 58 for SFT and 41 for Self-Play, demonstrating that the adversarial self-play mechanism internalizes abstract security principles rather than memorizing specific patches.

## Relation to Prior Work

TSP combines the iterative self-play loop from SPIN (Chen et al., 2024) with the DPO-style log-likelihood-ratio scoring function (Rafailov et al., 2023), but localizes both to semantically identified CWE Risk Nodes within a generation tree rather than operating at the full-sequence level. This departs from SPIN's flat, whole-response self-play and from token-level DPO variants (e.g., TDPO) that still rely on statically constructed preference pairs, by generating on-policy negatives only at the specific decision points where vulnerabilities originate. The paper also positions itself against secure-code-specific methods like SafeCoder and HexaCoder, which depend on curated positive/negative datasets, by eliminating the need for external preference annotation entirely.

## Why It Matters / Open Questions

The cross-language transfer result (trained solely on C/C++, evaluated on Python, Go, JavaScript, Ruby) and the unseen-CWE generalization suggest TSP internalizes abstract security logic rather than memorizing patches, which is a meaningful step toward scalable, annotation-free security alignment. However, the CWE-level analysis honestly reveals that TSP underperforms on complex data-flow vulnerabilities (CWE-416, CWE-690, CWE-125) where the unsafe decision and its manifestation are separated by long execution distances, exposing a fundamental limitation of node-local credit assignment. Open questions include whether the approach scales to frontier-scale models, whether risk nodes can be discovered dynamically rather than pre-annotated, and whether hybridizing TSP with sparse human feedback can address the data-flow blind spots.
