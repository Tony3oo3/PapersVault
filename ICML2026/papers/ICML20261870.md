## Problem

Code generation models produce functionally incorrect code (hallucination), but unlike natural language where textual entailment provides a natural correctness measure, the complex, unnatural structure of code makes it difficult to identify functional equivalence between two snippets. Prior work has focused on improving model performance to indirectly reduce hallucination, but direct, certified control methods that bound the rate of functional hallucination with statistical guarantees remain unexplored.

## Input / Output

The method takes a problem description as prompt and a calibration set of problem-code pairs, and additionally requires a reference solution for each problem to drive fuzzing-based unit test generation (at least 600 input-output pairs per problem via Atheris). It produces a selective generator that either outputs a code snippet or abstains (IDK), along with a certified FDR-CE upper bound Ũ and a selection threshold τ. The scoring function defaults to length-normalized log-probability but can be mixed with a pass@1 score over hold-out fuzzing unit tests.

## Method

The paper defines α-code entailment: a generated snippet is correct if it passes at least (1−α) fraction of unit tests from a fuzzing-based generator F(x), estimated via a binomial tail bound on the empirical pass rate. Fuzzing (Atheris) is repurposed from bug-finding to explore execution paths of reference code, automatically generating large numbers of input-output pairs for both learning and evaluation (FuzzEval). The selective generator is learned by binary-searching a threshold τ over a scoring function (length-normalized log-prob or a mixed score with pass@1), minimizing τ subject to the constraint that the FDR-CE upper bound (combining the binomial estimation error ε_E and a binomial tail bound on false discoveries) stays below a user-specified level ε_S. The key theoretical guarantee (Theorem 4.3) provides a PAC-style bound: with probability at least 1−δ_S over the calibration set, the true FDR-CE of the learned selective generator is at most the returned upper bound Ũ, requiring no human entailment labels.

## Results

On APPS-F with GPT-4o (ε_S=0.3), SCG achieves FDR-CE of 0.224±0.018 with 33.7% selection efficiency, satisfying the desired FDR-CE bound while maintaining reasonable efficiency. On HumanEval-F, SCG reduces FDR-CE to 0.049±0.111 (vs. 0.207 for the unselective baseline) at 16.4% efficiency. On MBPP-F and Mercury-F, SCG achieves near-full efficiency (99.6% and 99.8% respectively) while keeping FDR-CE at 0.300 and 0.165, both below their respective ε_S thresholds. Across all four datasets, SCG is the only method that simultaneously satisfies the FDR-CE constraint with a PAC-style theoretical guarantee and maintains non-trivial selection efficiency.

## Baselines & Comparisons

SCG-EM (Geifman & El-Yaniv, 2017), the conventional selective classifier applied to code, achieves near-zero efficiency (0.000–0.008) across all datasets because it compares generated code textually to the reference solution without measuring functional correctness, causing it to almost always abstain. SCG-MANUAL (top-k% selection) satisfies the FDR-CE constraint on all four datasets with ~50% efficiency, but lacks any theoretical guarantee and requires manual tuning of k. SCG-SMALL (using only 21 hand-written unit tests from APPS) achieves FDR-CE=0.226 on APPS-F with 33.9% efficiency, demonstrating that limited unit tests reduce selection efficiency compared to SCG's fuzzing-generated tests. SCG-H (ablation omitting the false entailment rate term) achieves FDR-CE below ε_S on GPT-4o but violates the constraint on Gemini-1.5 Pro (Figure 2b), confirming that the binomial tail bound correction (ε_E) is necessary for robustness. When applied on top of prior post-filtering methods (CodeT, LDB, SFS) with GPT-3.5-Turbo (Table 2), SCG reduces FDR-CE from 0.44–0.50 to 0.14–0.15 on MBPP-F while retaining 58–66% efficiency, demonstrating model- and method-agnostic applicability.

## Relation to Prior Work

This paper extends the selective generation framework for hallucination control from natural language (Lee et al., 2024) to code generation, replacing textual entailment with a new notion of α-code entailment grounded in executable unit tests. The key conceptual departure is repurposing fuzzing—a dynamic code analysis tool originally designed for bug discovery—as a unit test generator to automatically assess functional correctness, thereby enabling the binomial-tail-bound-based estimation of code entailment without human annotation. The selective prediction algorithm (binary search over a scoring threshold with a PAC-style FDR guarantee) is inherited from Geifman & El-Yaniv (2017) and Lee et al. (2024), but the correctness relation R is entirely new, defined via α-code entailment rather than sentence-level semantic entailment.

## Why It Matters / Open Questions

This is the first work to provide a theoretical (FDR) guarantee on the rate of functionally incorrect code among non-abstained generations, making code generators more trustworthy for safety-critical applications. The FuzzEval paradigm addresses a real bottleneck in code evaluation: manually curated unit tests (e.g., HumanEval) are insufficient for complex programs with many execution paths. Key limitations include the i.i.d. assumption (restricting applicability to distribution-shift settings), the requirement of reference code for fuzzing-based test generation, and selection efficiency that degrades for weaker base models with uncalibrated scoring functions. Open questions include whether the framework extends to multi-turn or interactive code generation, and whether the i.i.d. assumption can be relaxed for real-world deployment.
