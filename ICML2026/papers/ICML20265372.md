## Problem

Most existing UI-to-code methods formulate the task as single-pass generation, which fundamentally mismatches real-world UI development that is iterative and feedback-driven. The core technical challenge is that the optimization objective is defined in a non-differentiable rendered visual space, and absolute visual scores from VLM-based judges are noisy and poorly calibrated, making them unreliable as direct rewards for policy optimization.
![Teaser figure](../imgs/ICML20265372/cropped_page1_idx0.webp)

## Input / Output

The model takes a target UI screenshot as input and produces executable HTML/CSS code structured as a <think> reasoning block followed by an <answer> code block. For iterative refinement (UI polishing), the input additionally includes the current code and its rendered screenshot; for UI editing, explicit modification instructions are appended. The 9B VLM operates in a closed loop where each iteration consumes the previous round's rendered output as visual feedback, enabling test-time scaling up to N=5 refinement rounds.

## Method

The paper reformulates UI-to-code as an interactive visual optimization problem where code is iteratively refined via a closed loop of generation, rendering, and visual inspection. The key technical contribution is Relative Visual Policy Optimization (RVPO), which replaces unstable absolute visual rewards with tournament-based pairwise comparisons among N rendered candidates: a fine-tuned GLM-4.5V comparator scores each pair against the target, and each candidate's reward is its aggregate win count within the group. Policy updates use GRPO with group-normalized advantages and clipped surrogate objectives, omitting KL regularization to avoid over-constraining updates under implicit visual objectives. Training follows a three-stage pipeline: continual pre-training with localized DOM grounding and global image-code likelihood objectives (~20M samples), supervised fine-tuning with explicit think/answer reasoning traces (~80K samples), and RL with RVPO (~42K samples including real-world webpages from Mind2Web). The tournament-based reward design is shown to be critical: ablations confirm that absolute CLIP or VLM scores degrade or fail to improve over SFT, while relative preference optimization yields consistent gains across both drafting and polishing tasks.

## Results

UI2Code^N-9B-RL achieves 88.6% VLM-judge accuracy on Design2Code, 95.0% on Flame-React-Eval, 92.5% on Web2Code, and 76.5% on the newly proposed UI2Code-Real benchmark, outperforming all open-source VLMs and matching or exceeding top closed-source systems (GPT-5, Gemini-2.5-Pro) on most benchmarks. On UI polishing, it reaches 94.0% on UIPolish-Synthetic and 80.0% on UIPolish-Real, substantially surpassing all open-source baselines (best: Qwen3-VL-32B at 55.0%/46.0%). Test-time scaling via iterative refinement (N=1→5) further improves UI2Code-Real accuracy from 66.0% to 74.0%, validating the interactive optimization formulation.

## Baselines & Comparisons

Against open-source VLMs, UI2Code^N-9B-RL wins on every benchmark by large margins, e.g., 88.6% vs. 83.3% (Qwen3-VL-32B) on Design2Code and 94.0% vs. 55.0% on UIPolish-Synthetic. Against GPT-5, it wins on Flame (95.0 vs. 91.3), UI2Code-Real (76.5 vs. 67.8), and UIPolish-Synthetic (94.0 vs. 68.0), while trailing slightly on Design2Code (88.6 vs. 89.7), Web2Code (92.5 vs. 93.7), and UIPolish-Real (80.0 vs. 85.0). Against Gemini-2.5-Pro, it wins on Flame (95.0 vs. 87.5), Web2Code (92.5 vs. 90.6), UI2Code-Real (76.5 vs. 68.7), UIPolish-Real (80.0 vs. 74.0), and UIPolish-Synthetic (94.0 vs. 68.0), with a near-tie on Design2Code (88.6 vs. 89.5). Against agent-based systems (DCGen, ScreenCoder) on Design2Code-HARD, UI2Code^N-RL achieves 88.6% VLM accuracy with ~40s latency and ~2600 tokens, outperforming ScreenCoder (80.0%, ~66s, ~4600 tokens) and DCGen (45.0%, ~137s, ~7600 tokens) while using roughly half the token budget. On the specialized UI-to-code comparison (WebCode2M-Long, CLIP metric), UI2Code^N-RL (0.79±0.09) outperforms WebSight VLM-7B (0.69), Design2Code-18B (0.74), and UICopilot (0.77).

## Relation to Prior Work

This paper builds on GRPO (Shao et al., 2024) for stable policy optimization and on CogAgent's GUI-REG objective (Hong et al., 2024) for localized vision-code grounding during continual pre-training. It departs from the dominant single-pass UI-to-code formulation (Design2Code, Web2Code, WebSight) by reframing the task as iterative visual optimization under executable rendering feedback, and from agent-based multi-stage pipelines (DCGen, ScreenCoder) by performing end-to-end generation and refinement. The key methodological departure is RVPO, which replaces noisy absolute VLM-judge rewards with tournament-based relative preferences among rendered candidates, addressing a practical instability that prior RL-for-code approaches have not explicitly tackled.

## Why It Matters / Open Questions

The interactive visual optimization paradigm is model-agnostic and potentially applicable to any executable-generation task with black-box, non-differentiable feedback (e.g., code synthesis with test execution, layout generation with rendering). The open-source 9B model and new benchmarks (UI2Code-Real, UIPolish-bench) lower the barrier for the community to study iterative UI refinement. Open questions include whether the paradigm extends to interactive/functional UIs (JavaScript, state management), whether the VLM-judge-based evaluation circularity (the same family of models used for reward verification and evaluation) limits generalizability of reported gains, and whether the tournament reward design scales to larger candidate groups or more complex multi-page applications.
