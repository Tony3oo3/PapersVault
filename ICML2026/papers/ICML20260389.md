## Problem

Existing LLM benchmarks for scientific tasks measure only token costs and pass@k success rates, implicitly treating tool execution as free. In realistic physics simulation workflows, however, numerical parameter choices directly determine computational cost (scaling quadratically or cubically with resolution), making pass@k with large k impractical under real budget constraints. No prior benchmark evaluates whether LLMs can balance accuracy against computational cost when tuning simulation parameters.

## Input / Output

The LLM receives a text prompt describing a specific physics simulation scenario (governing PDE, boundary/initial conditions, fixed non-target parameters, and a target accuracy level from three tiers) and must propose a value for one tunable parameter. In single-round mode the model makes exactly one function call; in multi-round mode it receives up to 10 rounds of feedback including convergence status, RMSE against a finer-resolution reference, and accumulated FLOP cost. Outputs are scored on two axes: success rate (binary, whether the task-dependent distance metric meets the threshold) and efficiency (ratio of brute-force reference cost to the LLM's incurred cost, zeroed on failure), aggregated as arithmetic mean for success and geometric mean over successful samples for efficiency.

## Method

SimulCost defines tool cost analytically by counting dominant-operation FLOPs per solver (e.g., C = n_space × n_t for explicit time-stepping, C = (1/dx)² × n_iter for iterative solvers), yielding platform-independent, reproducible cost metrics across 11 solvers spanning fluid dynamics, solid mechanics, and plasma physics; a 12th solver (EPOCH, a compiled PIC code) uses wall-clock time and is reported separately. Reference solutions are found via progressive refinement (Algorithm 1) for monotonic cost-accuracy parameters or exhaustive grid search (Algorithm 2) for non-monotonic ones, with 2,643 single-round and 2,304 multi-round tasks generated by combining accuracy levels, boundary conditions, and non-target parameter settings. Five frontier LLMs (GPT-5, Claude-3.7-Sonnet, GPT-OSS-120B, Llama-3-70B-Instruct, Qwen3-32B) are evaluated against brute-force scanning and a GP-based Bayesian optimization baseline, with ablations on three in-context learning variants (idealized, cost-ignorant, mixed-accuracy) and GPT-5 reasoning effort levels. The toolkit is open-sourced with standardized Hydra-based solver APIs, enabling extension to new simulators and parameter configurations.

## Results

In single-round mode, frontier LLMs achieve 45–62% success rates (GPT-5 leads at 61.5%), dropping to 34–50% under high-accuracy requirements. Multi-round inference improves success to 66–81% (GPT-5: 80.8%, GPT-OSS-120B: 77.1%, Llama-3-70B: 71%), but LLMs remain 1.5–2.7× slower than brute-force scanning in efficiency (0.3–0.7 vs. the reference 1.0). In single-round, all models use 2–6× the optimal compute (efficiency 0.16–0.52). Against the BO-GP baseline, LLMs achieve comparable aggregate success rates but a clear efficiency advantage at low accuracy (2.13 vs. 1.05).

## Baselines & Comparisons

The primary baseline is brute-force scanning (progressive refinement for monotonic parameters, exhaustive grid search for non-monotonic ones), which serves as the reference for both success and cost (efficiency = 1.0 by definition). LLMs in multi-round mode achieve comparable or slightly higher success rates than scanning but at 1.5–2.7× the computational cost, making them uneconomical as a direct replacement. The secondary baseline, Bayesian Optimization with a Gaussian Process surrogate (BO-GP), achieves comparable aggregate success rates to LLMs but with higher inter-solver variance. On efficiency, LLMs clearly outperform BO-GP, especially at low accuracy requirements (2.13 vs. 1.05), because BO's information-gain-driven exploration tends to select extreme parameter values early, triggering expensive runs. The paper's key practical conclusion is that LLMs should invoke scanning algorithms as tools rather than relying on internal trial-and-error reasoning, since the latter is consistently slower.

## Relation to Prior Work

This paper carves new ground at the intersection of LLM agent benchmarks and scientific computing. Prior LLM-for-science benchmarks (ScienceAgentBench, DiscoveryBench, CFDLLMBench) evaluate task correctness and token costs but treat tool execution as free, while cost-tracking benchmarks (Agent-Lab, MLE-Bench, MLGym) measure wall-time that conflates LLM inference with solver execution and varies across hardware. The closest prior work, MetaOpenFOAM, targets physics simulations with cost awareness but is a workflow automation framework rather than a benchmark and uses wall-time. SimulCost departs from all of these by defining cost analytically via dominant-operation FLOP counting, making it platform-independent and capturing how a single parameter choice (e.g., grid resolution) alters the cost of the same tool call by orders of magnitude—something fixed-cost-per-call models like CATP-LLM or intervention-counting models like Auto-Bench cannot represent.

## Why It Matters / Open Questions

SimulCost is the first benchmark to make computational cost a first-class, reproducible evaluation dimension for LLM-automated physics simulations, and its open-source extensible toolkit lowers the barrier for the community to add new solvers. The practical finding that LLM trial-and-error is 1.5–2.7× slower than brute-force scanning directly informs deployment: practitioners should let LLMs invoke scanning algorithms rather than rely on internal reasoning. Key open questions include multi-parameter joint optimization (excluded here for baseline tractability), parallel-architecture cost tracking, non-monotonic parameter handling requiring multimodal feedback, and whether cost-aware post-training can close the efficiency gap without overfitting to known simulators.
