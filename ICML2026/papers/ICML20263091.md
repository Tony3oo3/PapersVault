## Problem

Evaluating and training code agents on realistic vulnerability repair requires fully executable task packages (environment, tests, solution), but existing CVE-to-task pipelines rely on costly manual reproduction (10+ expert hours per CVE), are restricted to Python or well-configured repositories, or produce incomplete outputs lacking Dockerfiles and test scripts. No scalable automated system exists that transforms sparse CVE metadata into expert-quality, multi-language, multi-container agentic tasks at volume.
![Teaser figure](../imgs/ICML20263091/cropped_page0_idx0.webp)

## Input / Output

The pipeline consumes raw CVE JSON entries from CVElistV5 (containing vulnerability descriptions, CWE IDs, CVSS scores, and reference/PoC URLs), which are first converted to a unified Markdown format for inter-agent knowledge transfer. The output is a complete Terminal-Bench-compatible task directory: a first-person bug-report-style task.yaml, a Dockerfile and docker-compose.yaml supporting up to 4+ container orchestration, dynamic executable test scripts (test_vuln.py for vulnerability presence, test_func.py for functional stability), a reference solution.sh, and a run-tests.sh runner. Notably, task descriptions are deliberately framed as ambiguous user reports rather than technical CVE advisories, and tests enforce holistic end-to-end system validation rather than isolated submodule pattern matching.

## Method

CVE-Factory employs a six-stage decouple-couple multi-agent architecture governed by a central Orchestrator. Three decoupling stages (Analyzer for information collection, Generator for file synthesis, Builder for environment construction) operate with independent contexts and distilled Markdown handoffs, while three coupling stages (Vulnerability Verification, Solution Verification, Holistic Validation) progressively align components via objective script-based checks. Each agent is a full Claude Code session with autonomy to explore, execute commands, and adapt strategies, constrained by information asymmetry (Builder is blind to tests/solutions), filesystem sandboxing, and a structured signal protocol (continue/error/pause). The pause signal triggers a feedback mechanism where the Orchestrator's file ownership map routes structural failures back to the original creator, preserving exploration history for efficient repair. This design reduces the >200k-token long-horizon problem into focused sub-tasks, achieving 95% solution correctness and 96% environment fidelity against expert reproductions at 6–30× speedup, and enabling the first large-scale synthesis of 1,000+ executable security training environments.

## Results

CVE-Factory achieves expert-level reproduction quality with 95.35% solution correctness and 96.13% environment fidelity in cross-validation against PatchEval, while achieving a 66.2% verified success rate on 554 real-world CVEs (May–Dec 2025). Fine-tuning Qwen3-32B on CVE-Factory trajectories yields a 6.8× improvement on LiveCVEBench (5.29% → 35.79%), a 4.2× improvement on PatchEval (5.66% → 23.58%), and a 2.3× improvement on Terminal-Bench (12.50% → 31.25%), surpassing Claude Sonnet 4.5 (34.39%) on LiveCVEBench. The framework achieves a 6–30× speedup over expert reproduction (48 min vs. 5–24 hours per CVE).

## Baselines & Comparisons

Against CVE-Genie (Ullah et al., 2025), CVE-Factory achieves 90.3% success rate versus 48.4% on 31 CVEs from 2025, more than doubling the prior multi-agent system's performance by combining flexible agent autonomy with progressive verification. In cross-validation against PatchEval (Wei et al., 2025), CVE-Factory matches or exceeds expert-level quality: 95.35% solution correctness, 96.13% environment fidelity, and 73.91% of its tests rated equal or better than expert tests, while running 6–30× faster. Against SETA (Shen et al., 2026) at equal data volume (4k trajectories), CVE-Factory substantially outperforms: 35.79% vs. 21.69% on LiveCVEBench, 23.58% vs. 14.62% on PatchEval, and 28.75% vs. 27.50% on Terminal-Bench, demonstrating that security-specific task data is more effective than general terminal tasks for training code security agents. The fine-tuned Qwen3-32B (35.79% LCB) surpasses Claude Sonnet 4.5 (34.39%) on LiveCVEBench but remains below Claude Opus 4.5 (41.27%), indicating that the training data narrows but does not fully close the gap to the strongest proprietary models.

## Relation to Prior Work

CVE-Factory extends the multi-agent CVE reproduction line initiated by CVE-Genie (Ullah et al., 2025), which demonstrated feasibility but produced incomplete task packages without Dockerfiles, test scripts, or task descriptions. It also departs from agentic task construction frameworks like SWE-smith and SWE-bench-Live, which are restricted to Python repositories with standard metadata, by handling 14+ languages, multi-container architectures, and sparse CVE metadata lacking complete environmental specifications. The task format follows Terminal-Bench's conventions, while the decouple-couple six-stage pipeline with context isolation and a feedback-routing Orchestrator represents a novel architectural contribution distinct from both single-agent approaches and fixed-pipeline multi-agent systems.

## Why It Matters / Open Questions

This work addresses a critical bottleneck in code security research: the inability to scale high-quality, executable vulnerability tasks beyond a few hundred manually constructed examples. The 66.2% verified success rate on real-world CVEs and the resulting LiveCVEBench (190 tasks, 14 languages, continuously updated) provide the field with a living benchmark that captures temporal distribution shifts, including emerging AI-tooling vulnerabilities absent from static benchmarks. The finding that fine-tuning Qwen3-32B on 4k generated trajectories yields a 6.8× improvement, surpassing Claude Sonnet 4.5, suggests that data quality in security task generation may matter more than model scale. Open questions include reducing the persistent mock/static-test failure rate (~35% of manual verification failures), handling complex multi-container orchestration beyond 2 services, and making the final verification stage more adversarial to prevent agents from rationalizing shortcuts.
