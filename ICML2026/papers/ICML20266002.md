## Problem

Existing LLM-based scientific discovery methods (code-as-action, API encapsulation) operate in a passive execute-then-response loop where feedback is only available after execution terminates, leaving agents blind to transient physical anomalies such as numerical instability or diverging oscillations that can invalidate results without triggering explicit errors. This 'cognitive decoupling' between discrete textual reasoning and continuous physical dynamics prevents verifiable scientific discovery in process-oriented tasks like engineering design and dynamic system modeling.

## Input / Output

The agent receives a natural-language scientific intent (e.g., 'Design a PID controller yielding phase margin > 45°') which is decomposed into a set of binary physical constraints, and operates within a MATLAB/Simulink simulation environment. Unlike standard tool-use paradigms where observations are discrete text returns, EmbodiedAct defines observations as continuous streams comprising stdout, stderr, system events (warnings, interrupts), and dynamic simulation trajectories (e.g., voltage, velocity time-series). The output is a trajectory of executable simulation primitives (MATLAB toolbox calls like ode45, linprog, or Simulink topological manipulations) whose final state satisfies all derived constraints, with the agent retaining the ability to asynchronously halt and repair execution mid-simulation.

## Method

EmbodiedAct instantiates a four-module cognitive architecture—Strategic Planner (hierarchical intent decomposition), Primitive Generator (software-specific simulation primitives with topological reasoning for Simulink block diagrams), Runtime Perception Engine (tri-state classification of streaming observations triggering a Hot-Fix Loop for immediate repair), and Reflective Decision Maker (LLM-as-judge constraint verification triggering local parameter adjustment or global re-planning)—connected by an Asynchronous State Synchronization Protocol over WebSocket. This protocol provides three key mechanisms: asynchronous acknowledgment decoupling command dispatch from execution lifecycle, real-time multi-modal streaming of intermediate simulation states, and bi-directional active intervention allowing the agent to transmit high-priority interrupt signals to halt a diverging simulation before it crashes. The resulting dual-loop architecture (fast inner Hot-Fix Loop for runtime errors, slow outer Reflective Loop for goal-alignment) transforms the LLM from a passive tool caller into a responsive supervisor that monitors physical trajectories in real time and navigates toward optimal parameters during simulation, rather than only after execution completes.

## Results

On the EngDesign benchmark (92 engineering design tasks), EmbodiedAct with GPT-5.2 achieves 70.6% (Core) / 65.4% (Extended) average score, surpassing the best CodeAct baseline (55.4% / 49.4%) and the best generative model (48.0% / 51.9%). On SciBench-107 (107 college-level science problems), EmbodiedAct with Claude-Opus-4.5 reaches 60.75% accuracy, outperforming CodeAct (49.53% with GPT-5.2) and generative baselines (56.07% with Claude-Opus-4.5). The gains are most pronounced in process-oriented domains: Control Systems improves from 40.3% (Generative) to 68.6% (EmbodiedAct) with GPT-5.2, a >70% relative gain. Ablation confirms runtime perception (M_perc) is the primary driver, with removing it dropping EngDesign score from 70.6% to 56.5% (GPT-5.2).

## Baselines & Comparisons

The paper compares EmbodiedAct against two baseline paradigms: (1) Generative Models (text-only reasoning without execution) and (2) CodeAct (code-as-action with post-hoc stdout/stderr feedback after execution completes). EmbodiedAct consistently outperforms both across all model backbones and both benchmarks. On EngDesign Core with GPT-5.2, EmbodiedAct (70.6%) beats CodeAct (55.4%) by 15.2 points and Generative (48.0%) by 22.6 points. On SciBench-107, the best EmbodiedAct configuration (Claude-Opus-4.5, 60.75%) exceeds the best CodeAct (GPT-5.2, 49.53%) by 11.2 points. The ablation study is particularly revealing: removing the Runtime Perception Engine (M_perc) drops EmbodiedAct to 56.5% on EngDesign, nearly matching CodeAct's 55.4%, confirming that the performance gain comes from the closed-loop perception mechanism rather than merely using domain-specific MATLAB primitives. The gains are largest in process-oriented domains (Control Systems: +18.3 pts over CodeAct; Structural Engineering: +1.7 pts over CodeAct with GPT-5.2) where intermediate state monitoring is critical, and EmbodiedAct also narrows the gap for open-source models (Qwen3-235B jumps from 39.6% Generative to 57.0% EmbodiedAct, surpassing GPT-5.2's generative score of 48.0%).

## Relation to Prior Work

This paper extends the code-as-action paradigm (CodeAct, Wang et al. 2024) and API-encapsulation approaches by introducing a tight perception-execution loop via a WebSocket-based Asynchronous State Synchronization Protocol. While prior methods follow a rigid 'execute-then-response' cycle where feedback is only available post-execution, EmbodiedAct adds continuous runtime streaming of simulation trajectories, system events, and error logs, enabling the agent to detect transient anomalies (e.g., numerical divergence, overshoot) and intervene mid-execution. The modular cognitive architecture draws on human cognitive theory (Anderson et al., 2004), mapping planning, perception, and reflection to distinct LLM modules, but the core departure from prior work is the shift from passive tool invocation to active embodied monitoring within scientific software.

## Why It Matters / Open Questions

The paper demonstrates that runtime perception—not merely better code generation or richer API access—is the primary driver of reliable scientific discovery in simulation, as cleanly isolated by the ablation (w/o M_perc ≈ CodeAct performance). This has practical implications for deploying LLM agents in long-horizon engineering workflows where intermediate failures are silent but catastrophic. Key limitations include the MATLAB/Simulink-specific instantiation, a 10.6× token overhead relative to direct generation, and the acknowledged simulation-to-reality gap. Open questions include whether the protocol generalizes to non-MATLAB environments without re-engineering, whether multi-modal perception during execution (currently unused) further improves performance, and how to integrate safety guardrails for autonomous agents operating on physical systems.
