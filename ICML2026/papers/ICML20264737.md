## Problem

Conservative machine learning interatomic potentials (MLIPs) require a double-backward execution pattern with four phases (Forward Energy, Forward Force, Backward Force, Backward Energy) per micro-batch, which fundamentally mismatches existing pipeline parallelism schedules designed for first-order workloads. Naively adapting first-order schedules causes redundant FE recomputation across pipeline stages, parameter replication, and additional pipeline bubbles due to the inherent partial order of phase execution times (t_FE < t_FF < t_BE < t_BF). No scalable distributed training system existed to efficiently train large conservative MLIPs under memory constraints.

## Input / Output

The system consumes atomic graphs (nodes = atoms, edges = interatomic bonds) with 3D positions and corresponding energy/force labels, packed into micro-batches of a fixed 400-atom budget. It produces a device-specific instruction list (the optimized pipeline schedule) that orchestrates the four-phase execution across pipeline, graph, and data parallelism dimensions, along with the trained MLIP parameters. The schedule is determined offline via a memory-constrained search over the WaveK unit size k, and the instruction list explicitly encodes computation, point-to-point communication, and runtime-control operations per device.

## Method

JanusPipe represents pipeline execution as a device-level instruction list and applies two core scheduling transformations. SymFold doubles the pipeline stages from P to 2P virtual stages, remaps first-order instructions into four-phase variants (FE/FF/BF/BE with phase-specific communication), then symmetrically folds virtual stage S_i with S_{2P-1-i} onto the same physical device so that FF reuses FE's activations locally, eliminating redundant recomputation and cross-device parameter synchronization; a final pass prunes now-redundant intra-device communications. WaveK groups k micro-batches into a scheduling unit containing a forward wave (FE+FF) and a backward wave (BF+BE), then overlaps the residual bubbles at WaveK-F/WaveK-B boundaries and across consecutive unit boundaries, exploiting the consistent partial order t_FE < t_FF < t_BE < t_BF to fill idle time with useful computation. A lightweight GARS module repacks graphs into balanced micro-batches and tags each as comm-free or distributed to reduce GP halo communication. The optimal k is selected offline under a per-rank memory budget, and the full system composes PP, DP (with ZeRO/FSDP sharding), and GP for 3D-parallel training.

## Results

On 32 A100 GPUs, JanusPipe (k=Best) achieves 1.51× and 1.45× higher end-to-end throughput (atoms/sec) than 1F1B-2nd and Hanayo-2nd on average across UMA-1.2B/2.3B and eSEN-100M/220M. JanusPipe (k=P) reduces peak GPU memory by up to 20.56% and 42.70% compared to 1F1B-2nd and Hanayo-2nd, respectively. Ablation shows SymFold contributes up to 23% throughput gain, WaveK adds a further 18%, and GARS adds ~11%. On UMA-2.3B, JanusPipe achieves 70% strong-scaling and 94% weak-scaling efficiency from 8 to 32 GPUs.

## Baselines & Comparisons

JanusPipe outperforms both baselines across all evaluated models (UMA-1.2B, UMA-2.3B, eSEN-100M, eSEN-220M) and parallel configurations. Against 1F1B-2nd (Megatron-LM's 1F1B adapted for second-order training), JanusPipe achieves 1.51× higher throughput on average, primarily because SymFold eliminates the redundant FE recomputation that 1F1B-2nd requires when FF executes on a different PP stage. Against Hanayo-2nd (wave-style schedule adapted for second-order training), JanusPipe achieves 1.45× higher throughput and reduces peak memory by up to 42.70%, because Hanayo's finer-grained wave schedule prolongs activation lifetimes in the four-phase pipeline, increasing simultaneous live activations. JanusPipe also avoids OOM failures on eSEN-220M that both baselines encounter, thanks to SymFold's finer-grained pipeline partition (doubling stages from P to 2P). The k=Best configuration further improves over k=P by using available memory to form larger WaveK units with fewer boundary bubbles.

## Relation to Prior Work

This paper extends pipeline parallelism (PP) from first-order workloads (Megatron-LM's 1F1B, Hanayo) to the four-phase double-backward execution pattern inherent to conservative MLIPs, where forces are computed as the gradient of predicted energy during the forward pass. It introduces an instruction-level IR abstraction and two scheduling transformations—SymFold (co-locating FE/FF to eliminate redundant recomputation) and WaveK (reordering instructions to exploit the consistent partial order t_FE < t_FF < t_BE < t_BF)—that have no direct analogue in prior PP literature. The system also integrates with existing graph parallelism (Sriram et al., 2022) and data parallelism for MLIPs, but the core contribution is the pipeline scheduling dimension, which prior work has not addressed for second-order training.

## Why It Matters / Open Questions

Conservative MLIPs (MACE, CHGNet, eSEN, UMA) are the dominant paradigm in state-of-the-art interatomic potential design, yet the lack of an efficient PP schedule has been a practical barrier to scaling them beyond a single device. JanusPipe's 1.51× throughput gain and up to 42.7% memory reduction over baselines make 3D-parallel (PP/DP/GP) training of billion-parameter MLIPs feasible on commodity GPU clusters, directly enabling the scaling-law studies the MLIP community is pursuing. Open questions include whether the four-phase partial order holds universally across architectures, whether WaveK's offline k-tuning generalizes to heterogeneous hardware, and whether the approach extends to other double-backward workloads beyond MLIPs.
