## Problem

Existing LLM-powered code agents for website generation predominantly produce frontend-only pages that mask the absence of real backend processing and database storage with mock data and visual effects. Building production-grade full-stack applications is substantially harder than frontend generation alone, requiring efficient navigation of large codebases, long-horizon reasoning over complex workflows, and accurate localization of obscure bugs—capabilities that current agents and benchmarks do not adequately address or evaluate.

## Input / Output

The system takes a single natural-language user instruction (e.g., 'build a contest management platform with registration and scoring') and produces a complete, runnable full-stack web application codebase comprising a Next.js frontend, a NestJS backend with REST API endpoints, and a populated database with appropriate schema. The Planning Agent outputs structured JSON plans defining entities, API endpoints, page layouts, and data flows down to granular types, which the coding agents then implement sequentially (backend first, then frontend) in isolated sandbox environments. Evaluation on FullStack-Bench uses 101 user instructions paired with 647 frontend, 604 backend, and 389 database test cases, where frontend and backend scores are only counted if accompanying database interaction logs are valid.

## Method

FullStack-Agent comprises three tightly coupled components. FullStack-Dev is a multi-agent framework where a Planning Agent (lead architect) decomposes the task into frontend and backend JSON plans, then a Backend Coding Agent and Frontend Coding Agent implement them sequentially using specialized tools—most notably a Frontend Debugging Tool that drives a GUI agent while monitoring terminal and browser console outputs to pinpoint error-triggering actions, and a Backend Debugging Tool that issues HTTP requests and returns responses plus console logs in a single call (reducing average backend iterations from 115.5 to 74.9). FullStack-Learn is an iterative self-improvement pipeline that converts crawled GitHub repositories into agent trajectories via Repository Back-Translation (an Information Gathering Agent summarizes the repo and generates a plausible user instruction; a Trajectory Back-Translation Agent reproduces the repo in an empty template, and a rule-based program strips all traces of the original), scales data 5× via Repository Augmentation (simplification, extension, and application-transition plans), and trains the backbone LLM over two SFT rounds. FullStack-Bench introduces three-level agent-judged evaluation—GUI-agent frontend testing, API-request backend testing, and database schema-snapshot checking—each augmented with a database-interaction validation step to eliminate false positives where correct UI effects hide missing backend logic.

## Results

On FullStack-Bench with Qwen3-Coder-480B-A35B-Instruct as the backbone LLM, FullStack-Dev achieves 64.7% frontend accuracy (with valid DB), 77.8% backend accuracy (with valid DB), and 77.9% database accuracy, outperforming the previous state-of-the-art WebGen-Agent by 8.7%, 38.2%, and 15.9% respectively. The method also attains the highest appearance score (3.72/5). With the smaller Qwen3-Coder-30B-A3B-Instruct backbone, FullStack-Dev still leads all baselines (37.2% FE, 38.7% BE, 50.9% DB), and with DeepSeek-V3 it reaches 69.6% FE, 89.7% BE, and 79.2% DB.

## Baselines & Comparisons

FullStack-Dev decisively outperforms all five baselines across every metric with the 480B backbone. The largest gap is in backend accuracy: FullStack-Dev reaches 77.8% (w/ valid DB) versus 39.6% for WebGen-Agent, 35.8% for OpenHands, 25.8% for Qwen-Code, 12.7% for Bolt.diy, and 10.8% for TDDev — a 38.2-point margin over the previous SOTA. On frontend accuracy (w/ valid DB), FullStack-Dev leads WebGen-Agent (56.0%) by 8.7 points and OpenHands (40.4%) by 24.3 points. On database accuracy, FullStack-Dev (77.9%) edges out OpenHands (72.5%) and Qwen-Code (68.4%) by 5.4 and 9.5 points respectively, while Bolt.diy (13.6%) and TDDev (28.5%) trail far behind. Notably, FullStack-Dev is the only method whose backend accuracy exceeds its frontend accuracy, indicating that its generated websites have genuinely functional backends rather than mock-data facades. The pattern holds across all three backbone models tested (Qwen3-Coder-480B, Qwen3-Coder-30B, DeepSeek-V3), confirming the framework's model-agnostic effectiveness.

## Relation to Prior Work

This paper extends the website-generation-from-instructions line of work (WebGen-Agent, TDDev, WebGen-Bench) by explicitly targeting full-stack implementation with real backend APIs and database persistence, rather than the frontend-only sites that prior agents produce. Methodologically, it departs from prior GUI-agent-based debugging (which relies on blind interaction and pre-defined test cases) by introducing dynamic, error-localizing debugging tools for both frontend and backend, and from prior self-improvement approaches (GRPO with visual rewards, distillation from stronger models) by using repository back-translation and augmentation to generate training trajectories without requiring any stronger teacher model. The benchmark builds directly on WebGen-Bench's 101 user instructions and 647 frontend test cases, adding 604 backend and 389 database test cases with agent-based judges that verify actual data flow.

## Why It Matters / Open Questions

The most consequential finding is that requiring valid database interactions drops the prior SOTA's backend accuracy from 67.2% to 39.6%, revealing that existing evaluation methodologies were fundamentally blind to fake backends masked by correct frontend behavior. This reframes how the community should interpret prior website-generation results and motivates the new FullStack-Bench as a more honest evaluation standard. Limitations include testing primarily with Next.js/NestJS (though generalization to Vue.js/Django is shown), only two rounds of self-improvement, and modest database accuracy gains from training (2.8%). Open questions include whether the iterative self-improvement loop converges or degrades beyond two rounds, whether the approach generalizes to non-Next.js/NestJS production stacks, and how the method scales to applications with more complex data flows and multi-service architectures.
