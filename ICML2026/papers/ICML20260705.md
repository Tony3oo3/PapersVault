## Problem

Despite rapid progress on unimodal coding agents, multimodal agentic capabilities remain under-evaluated due to the scarcity of testbeds that combine the complexity of software development with deep multimodal understanding. Game development is an ideal domain for this evaluation—requiring agents to navigate large, dense codebases while manipulating intrinsically multimodal assets such as sprites, shaders, and animations within a visual game scene—yet it has been largely overlooked by the research community, which has focused on narrower sub-problems like next-frame prediction or procedural content generation.

## Input / Output

Each task provides a Godot 4 project folder (averaging 67.7 files, 518.9 lines of code, and 53.4 images) along with a natural-language instruction; 82.4% of tasks include multimodal assets such as PNG sprites, .gdshader files, .wav audio, and .tres resource files. The agent produces modified project files (scene files, GDScript scripts, etc.), and success is determined by deterministic unit tests written in Godot's GDScript testing framework that directly verify game behavior—e.g., checking collider intersections, animation frame sequences, or node hierarchy—rather than relying on LLM-as-a-Judge or CLIP-based similarity metrics.

## Method

GameDevBench is constructed through a four-stage pipeline: (1) sourcing 102 YouTube and 99 web Godot tutorials with matching open-source GitHub repositories, (2) using a Codex agent to automatically decompose tutorials into 202 initial tasks with instructions, project scaffolding, and unit tests, (3) applying automated refinement with structured checklists to catch common errors (a preliminary study found only 43% of initial tasks were issue-free), and (4) human annotation by 8 annotators to verify correctness, create 179 task variants, and label multimodal difficulty, yielding 333 final tasks. The benchmark's key differentiator is deterministic multimodal verification: Godot's scripting framework allows direct testing of visual and temporal properties (e.g., whether a collider intersects, whether an animation plays the correct frame sequence) without subjective evaluation. To improve agent performance, the paper introduces two simple multimodal feedback mechanisms—an MCP server that screenshots the Godot editor state and instructions for generating runtime gameplay video—which consistently improve performance across models, increasing GPT-5.4 from 41.1% to 52.0% pass@1.

## Results

On GameDevBench (333 tasks), the best configuration (Gemini 3 Pro with editor screenshot + runtime video feedback) achieves 53.8% pass@1, while GPT-5.4 improves from 41.1% to 52.0% with multimodal feedback (a 10.9 pp / 26.5% relative gain). Performance degrades sharply for non-frontier models: Claude Haiku 4.5 solves only 13.8%, Kimi K2.5 18.9%, and Qwen3.5-397B just 5.4% without feedback. Task complexity is substantially higher than SWE-Bench, with reference solutions averaging 4.7 files and 114.1 lines of code changed (over 3× SWE-Bench), and success drops from 51.4% on gameplay-logic tasks to 33.0% on 2D-graphics tasks.

## Baselines & Comparisons

The paper does not compare against a prior game-development benchmark (none exists), so the primary comparisons are across model families and multimodal-feedback ablations. Frontier models (GPT-5.4, Gemini 3 Pro, Claude Sonnet 4.5) achieve 28.8–50.1% pass@1 without feedback, while open-weights models (Kimi K2.5, Qwen3.5-397B) drop to 5.4–18.9%, a gap of up to 48.7 pp. Adding multimodal feedback (editor screenshot via MCP and/or runtime video) consistently improves most models; the largest gain is GPT-5.4 (+10.9 pp), while Gemini 3 Flash shows only marginal change (~41–52% across all configurations). Harness choice matters: Gemini 3 Flash drops from 45.4% (native gemini-cli) to 30.3% (OpenHands), likely due to tool incompatibility, whereas Claude Haiku 4.5 slightly improves (16.5%→17.7%). The authors also note that Kimi K2.5 achieves 91.3% on the frontend benchmark Design2Code but only 18.9% on GameDevBench, highlighting that strong web-UI multimodal performance does not transfer to game-engine tasks. Across skill categories, all agents perform best on gameplay logic (51.4%) and worst on 2D graphics (33.0%) and UI (32.0%), confirming that multimodal understanding is the primary bottleneck.

## Relation to Prior Work

GameDevBench directly extends the SWE-Bench paradigm (task instruction + project folder + deterministic unit tests + reference solution) into a domain that inherently requires multimodal understanding. It departs from prior agentic game research—which has focused on game playing (AlphaGo, SIMA 2), procedural content generation, or next-frame prediction—by evaluating the full development loop within a game engine rather than replacing any single component. The MCP-based screenshot feedback mechanism connects to the broader tool-use and computer-use agent literature, while the deterministic Godot test framework avoids the biases of LLM-as-a-Judge evaluation that plagues other multimodal benchmarks.

## Why It Matters / Open Questions

This is the first benchmark to evaluate whether agents can actually develop games within a modern engine, filling a clear gap between software development benchmarks (which are largely unimodal) and game-playing benchmarks (which evaluate a different capability). The finding that even the best agent achieves only 53.8% pass@1, with performance dropping from 51.4% on gameplay tasks to 33.0% on 2D graphics tasks, quantifies a concrete multimodal capability gap that the field has lacked a measurement for. The consistent improvement from simple visual feedback (screenshots/video) suggests a practical near-term path for improving agent performance without architectural changes. Open questions include whether the gap will close with next-generation multimodal models, whether the benchmark generalizes beyond Godot to Unity or Unreal, and how to systematically improve agents' understanding of game-specific patterns like node hierarchies and signal connections.
