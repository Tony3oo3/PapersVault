## Problem

Existing code refactoring benchmarks are limited to single-file, single-language edits and measure only whether agents follow well-specified instructions, not whether they can autonomously discover the refactorings human developers actually chose. This paper asks whether state-of-the-art coding agents can both reliably execute large multi-file refactorings and identify the specific architectural transformations that real developers applied in open-source codebases.
![Teaser figure](../imgs/ICML20264435/cropped_page1_idx0.webp)

## Input / Output

The agent receives a codebase at a pre-refactoring commit inside a containerized environment, a task description (either a ~1921-character detailed refactoring spec in the Instructed Track or a ~38-character focus-area hint in the Open Track), and read access to the repository test suite. It produces a unified diff patch. Evaluation yields an alignment score (product of test-pass correctness and instruction-following rate), decomposed into additive IFR (desired patterns introduced), reductive IFR (undesired patterns removed), test pass rate, and a precision metric measuring how much of the patch touches rule-relevant lines versus unrelated changes.

## Method

CODETASTE is built via a six-stage pipeline that mines 100 large multi-file refactorings (avg. 91.5 files, 2605 lines) from 87 GitHub repositories across 6 languages, then for each instance generates an LLM-written task description, a reproducible containerized build environment validated by running the repo's test suite, and a set of Semgrep-style static analysis rules (avg. 18 additive, 63 reductive) produced by a coding agent that sees only the pre-refactoring state to avoid overfitting. Rules are validated by requiring additive patterns to match the golden post-state but not the base state, and reductive patterns to match the base but not the golden state, with an additional LLM-assisted filter removing rules that encode arbitrary naming choices. Evaluation combines functional correctness (test suite pass/fail thresholds derived from 5 runs on both base and golden states) with instruction following rate (weighted recall of additive and reductive rules) into a single alignment score. The Open Track introduces three inference modes—Direct, Plan (propose-then-implement), and Oracle Multiplan (generate multiple plans, an LLM judge with oracle access selects the best-aligned one)—to isolate whether the bottleneck is in discovering the right refactoring versus executing it.

## Results

On the Instructed Track, GPT-5.2 achieves 69.6% alignment (A), significantly outperforming GPT-5.1 Codex Mini (34.4%), Claude Sonnet 4.5 (32.1%), MiniMax M2.7 (30.5%), and Qwen3 (10.7%). The gap is driven primarily by functional correctness (PASS): GPT-5.2 passes 76.0% of test suites versus 43–49% for the other frontier models, while instruction-following rates (IFR) are 62–89% across all agents. On the Open Track (where agents must autonomously discover refactorings), performance collapses: the best direct alignment is 7.9% (GPT-5.2), and even oracle-assisted multiplan selection reaches only 20.6%. All agents achieve precision (~48–53%) close to the human golden-patch baseline of 48.5% on the Instructed Track.

## Baselines & Comparisons

The paper evaluates five coding agents on CODETASTE. On the Instructed Track, GPT-5.2 (69.6% A) statistically significantly outperforms all other agents; the gap versus GPT-5.1 Codex Mini (34.4%), Sonnet 4.5 (32.1%), and MiniMax M2.7 (30.5%) is driven by PASS rate (76% vs. 43–49%) rather than IFR, since all frontier models follow detailed instructions reasonably well (IFR 62–89%). Qwen3 lags substantially at 10.7% A, with both low IFR (36.4%) and low PASS (30%). On the Open Track, GPT-5.2 leads in every mode (7.9% Direct → 15.1% Plan → 20.6% Multiplan), while Sonnet 4.5 paradoxically drops from 10.7% (Plan) to 10.1% (Multiplan), suggesting its multi-plan generation shifts into a less-aligned distribution. Qwen3 remains the weakest across all Open Track settings (2.0–2.2% A). In terms of precision, all agents cluster near the human golden-patch level (~48.5%) on the Instructed Track, indicating that when given explicit instructions, frontier agents keep changes in scope; however, on the Open Track precision drops to 7–20%, reflecting that agents make many unrelated or insufficient edits when left to choose refactorings autonomously.

## Relation to Prior Work

This paper extends the repository-level evaluation paradigm established by SWE-bench (Jimenez et al., 2024) from issue resolution to code refactoring, but departs from all prior refactoring benchmarks (SWE-Refactor, RefactorBench, MiniCode, Aider) by scaling to multi-file, multi-language refactorings and introducing an intent-alignment evaluation that tests whether agents can autonomously discover human refactoring choices rather than merely following detailed instructions. The evaluation methodology is novel in combining repository test suites with Semgrep-style static analysis rules that support dataflow reasoning, enabling semantic (rather than purely syntactic) verification of code pattern transformations. The propose-then-implement and oracle-multiplan inference modes are new evaluation protocols that decompose the refactoring task into planning and execution phases.

## Why It Matters / Open Questions

The stark gap between Instructed Track performance (up to 69.6% alignment) and Open Track performance (below 8% direct, 20.6% with oracle selection) reveals that autonomous refactoring judgment remains a fundamental bottleneck for coding agents, with direct practical implications for long-horizon codebase maintenance. CODETASTE provides the first scalable, multi-language benchmark with a preference signal for aligning agents with human refactoring decisions, filling a gap where prior benchmarks were limited to single-file, single-language edits. Key open questions include what the realistic upper bound for human alignment is, whether the LLM-assisted construction pipeline introduces systematic biases, and whether the 100-instance scale is sufficient for robust cross-agent comparisons given the uneven language distribution.
