## Problem

Open-weight coding agents should be able to specialize to private codebases by encoding repository-specific knowledge in their weights, but the cost and complexity of training—requiring either reinforcement learning infrastructure or synthetic data pipelines with unit test verification—has kept this advantage theoretical. This paper asks whether high-quality coding agent training data can be generated from any repository without test infrastructure, and at what cost.
![Teaser figure](../imgs/ICML20264078/cropped_page0_idx0.webp)

## Input / Output

The data generation pipeline takes any code repository (no test suite required) and a randomly selected function paired with a vague bug-type prompt, producing full agent trajectories (sequences of tool calls, observations, and reasoning capped at 115 steps) and final code patches. For training, the student model receives a synthetic PR description (issue text) and navigates the codebase to produce a patch; trajectories are truncated to fit a 32K context window, with a 'truncation ratio' (fraction of steps retained) used as a quality filter. The output is a set of 200,000+ open-source trajectories plus specialized per-repository datasets of ~8,000 trajectories each.

## Method

SERA introduces Soft Verified Generation (SVG), a two-rollout data generation strategy that replaces unit-test verification with line-level recall between two independently produced patches. In the first rollout, a teacher model (GLM-4.5-Air) is prompted with a random function and a vague bug description from a set of 51 bug types, producing trajectory T1 and patch P1; T1 is then converted into a synthetic PR. In the second rollout, the teacher is given only the synthetic PR and must reproduce the change, yielding T2 and P2. Soft verification computes line-level recall r = |P2 ∩ P1| / |P1|, accepting trajectories with r ≥ 0.5 without executing any tests. The key empirical finding is that verification level (including r = 0) has minimal effect on downstream performance, meaning the pipeline works on any repository. Training is plain supervised fine-tuning of Qwen 3-32B for 3 epochs at LR 1e-5, with ordered truncation (selecting trajectories with highest truncation ratio) outperforming random truncation by 5.5%. This yields 26× lower cost than RL and 57× lower cost than prior synthetic data methods to reach equivalent SWE-bench Verified performance.

## Results

SERA-32B (trained with GLM-4.6 teacher) achieves 49.5%±1.9% on SWE-bench Verified at 32K context and 54.2%±1.4% at 64K context, setting state-of-the-art among fully open-source (open data, method, code) models. The smaller SERA-8B variant reaches 31.7%±0.9% at 32K. Total training cost is $2,000 (40 GPU days) for the 32B model, and repository specialization to a single codebase requires only ~8,000 trajectories (~$1,300) to match or exceed the teacher model's performance.

## Baselines & Comparisons

SERA-32B (49.5% at 32K) matches Devstral-Small-2 (50.0%) and GLM-4.5-Air (50.5%) within one standard deviation at 32K context, but trails both at 64K (54.2% vs. 59.1% and 57.4% respectively) due to being trained only at 32K context. In a controlled comparison with the same teacher (Claude 3.7) and sample size (4,776), SERA (30.0%) outperforms SWE-smith (25.27%) by +4.7%, and with Claude 4 Sonnet at 64K, SERA (48.53%) nearly matches BugPilot (49.87%) despite using ~10% fewer samples. SERA-8B (31.7%) substantially outperforms SkyRL-8B (9.4%) and Nex-N1-8B (20.3%), while SERA-32B (49.5%) exceeds DeepSWE (42.2%) and the Qwen 3-32B base (24.4%). The paper reports SERA is 26× cheaper than RL (SkyRL) and 57× cheaper than SWE-smith to reach equivalent performance when self-hosting via vLLM, with advantages increasing to 53× and 115× using the z.ai API.

## Relation to Prior Work

This paper departs from the dominant paradigm in coding agent training, which relies on either reinforcement learning (SkyRL-Agent, DeepSWE, SWE-RL) or synthetic data pipelines requiring bug injection and unit-test verification (SWE-smith, BugPilot). SERA's core methodological departure is replacing test-based verification with soft verification via line-level recall, eliminating the need for test infrastructure and bug-injection pipelines entirely. It also reframes the training data generation problem: rather than requiring the model to fix injected bugs, it prompts a teacher on randomly selected functions with vague bug descriptions, producing trajectories that capture a broader range of real-world coding tasks (refactoring, style changes, behavior tweaks). The agent scaffold (SWE-agent) and evaluation benchmark (SWE-bench Verified) are inherited from prior work, and the knowledge-distillation setup (teacher generates trajectories, student learns via SFT) follows the standard teacher-student framework, but the verification criterion and data generation protocol are novel.

## Why It Matters / Open Questions

The practical impact is substantial: reducing coding agent training costs by 26–57× compared to RL and prior synthetic data methods makes this research accessible to small teams and academic labs, and the released 200K+ trajectories plus full code lower barriers for the entire open-source coding agent community. The repository specialization capability—where a 32B student matches or exceeds its 110B teacher on targeted codebases with only 8,000 trajectories—opens a path for organizations to deploy private-codebase-specialized agents at ~$1,300, an advantage frontier labs cannot replicate. Key open questions include whether verification becomes necessary once models saturate on navigation and intent-translation skills, whether findings generalize beyond the Qwen/GLM model families, and whether specialization holds on truly private codebases without evaluation data. The paper's own limitations section acknowledges that evaluation is restricted to SWE-bench Verified and that the student-matches-teacher result at 8K samples has SNR < 2, warranting caution.
