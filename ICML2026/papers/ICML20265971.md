## Problem

As LLMs evolve from producing static text to generating interactive HTML applications (MINIAPPS), existing benchmarks remain tethered to algorithmic correctness or static layout reconstruction, failing to evaluate whether models can capture implicit real-world principles and construct customized interaction logic. No prior benchmark systematically assesses principle-driven, open-ended interactive application generation where multiple valid implementations exist and no single ground-truth code solution is available.
![Teaser figure](../imgs/ICML20265971/cropped_page0_idx0.webp)

## Input / Output

The generation stage takes a natural-language user query and produces a single self-contained index.html file (or a React project) runnable in a browser without external dependencies. The evaluation stage consumes four inputs: the original query, the generated source code, a structured evaluation reference encoding verifiable constraints across three dimensions, and a live interactable browser instance. Output is a structured JSON with per-dimension scores in [0,1] (Intention, Static, Dynamic), a binary pass/fail decision using a conservative weakest-link rule (min score ≥ 0.8), natural-language rationales, and a full step-by-step interaction trajectory log.

## Method

MINIAPPBENCH comprises 500 tasks across six domains, distilled from tens of millions of real user queries through a four-stage pipeline: LLM-and-human filtering for principle-driven interactive suitability, evolutionary augmentation to expand coverage while preserving intent, human-guided generation of query-specific evaluation references, and stratified sampling for balanced difficulty (30/40/30 Easy/Mid/Hard). MINIAPPEVAL is an agentic evaluation framework where an LLM-powered judge (Gemini-3-Pro-Preview) drives Playwright browser automation to perform human-like exploratory testing—clicking, typing, dragging, and observing runtime behavior—while simultaneously inspecting source code for principle violations. The evaluator is guided by a flexible evaluation reference (not a rigid oracle) that maps query-specific real-world constraints to verifiable checks across Intention (goal fulfillment), Static (structural correctness), and Dynamic (sequential logic, state consistency, and boundary handling). This design avoids the brittleness of fixed click-scripts and the reference-dependence of A/B comparison methods, enabling open-ended assessment of highly customized applications.

## Results

On MINIAPPBENCH (500 tasks, threshold τ=0.8, minimum-score rule across Intention/Static/Dynamic), GPT-5.2 achieves the highest average pass rate of 45.46%, followed by Claude-Opus-4-5 (41.14%) and GPT-5.1 (32.00%). The overall mean across all 16 evaluated models is only 17.05%, with the best open-source model (GLM-4.7) reaching just 18.31% and the weakest (Qwen3-32B) at 0.66%. Pass rates drop sharply with difficulty: the average across models falls from 34.05% (Easy) to 13.89% (Medium) to 4.34% (Hard).

## Baselines & Comparisons

GPT-5.2 leads all 16 models with a 45.46% average pass rate, outperforming the runner-up Claude-Opus-4-5 (41.14%) by 4.3 points and GPT-5.1 (32.00%) by 13.5 points. A stark open-source vs. closed-source gap emerges: the best open-source model GLM-4.7 (18.31%) trails the best closed-source model by over 27 points, and all open-source models remain below 19%. Among open-source models, GLM-4.7 dominates, surpassing Kimi-K2-Instruct (6.19%) by 12 points and Qwen3-235B-A22B (2.88%) by 15 points; within the Qwen family, scaling from 32B to 235B-A22B yields a 4.4× improvement (0.66% → 2.88%). Domain analysis reveals that GPT-5.2 excels in Visualization (82.35%) and Humanities (75.00%) but still struggles with Science (50.38%) and Games (40.32%), while Claude-Opus-4-5 shows the most balanced profile across difficulty levels (59.09% Easy, 41.18% Mid, 22.33% Hard). Token consumption correlates strongly with performance (Pearson r=0.84), with GPT-5.2 and Gemini-3-Pro-Preview identified as efficiency outliers that achieve high pass rates with fewer tokens than peers of similar performance.

## Relation to Prior Work

This paper carves new ground at the intersection of three benchmark families—code generation (MBPP, HumanEval, SWE-bench), real-world reasoning (PIQA, GSM8K, AlfWorld), and web development (Pix2Code, WebGenBench, WebBench)—none of which jointly capture the requirement for principle-driven, customized interactive HTML generation. It departs from prior web-generation benchmarks by rejecting template-based CRUD evaluation and reference-dependent scoring (WebDevJudge, FronTalk), instead introducing an agentic, browser-automation-based evaluator (MINIAPPEVAL) that performs open-ended exploratory testing. The evaluation methodology draws on agent-based evaluation ideas (Ali-Agent, Gao et al.) but repurposes them for a fundamentally different setting: verifying implicit real-world principles in executable artifacts rather than measuring deviation from a ground-truth implementation.

## Why It Matters / Open Questions

As LLM assistants increasingly produce interactive artifacts (ChatGPT artifacts, Copilot pages), the field lacks a principled way to assess whether generated applications actually embody correct real-world logic and support coherent user interaction—this benchmark and its agentic evaluator fill that gap with 500 tasks grounded in 10M+ real user queries. The finding that even the strongest model (GPT-5.2) achieves only ~45% pass rate, with Hard-difficulty tasks averaging just 4.3%, signals a substantial capability gap that will guide future research. Open questions include whether the evaluation framework generalizes beyond single-file HTML to multi-page or server-backed applications, whether the principle-adherence dimension can be decomposed further for targeted model improvement, and whether the open/closed-source gap narrows with continued scaling.
