## Problem

Feed-forward networks (FFNs) constitute roughly two-thirds of LLM parameters yet remain poorly understood because they consume a non-interpretable, context-dependent mixture of self-attention output and residual stream. Prior interpretability efforts (e.g., Geva et al.) required laborious manual annotation of calibration data and could not define discrete, human-interpretable queries for FFN memory access. The paper asks how to disentangle FFNs from self-attention so that their memory can be studied as a deterministic, token-indexed retrieval system over a finite vocabulary.

## Input / Output

The model takes tokenized text (LLaMA-3.1 tokenizer, 128,256 vocabulary, sequence length 2048) and produces next-token predictions for language modeling. Unusually, all FFN modules across every layer receive the same static input — the raw token embedding X_0 — rather than the evolving residual stream, which means their outputs are a fixed function of token ID alone. This enables pre-computing each FFN's output for every vocabulary token as a token-wise lookup (ToL) vector of dimension 1×(N×d), storable in BF16/F16 on external storage and loaded on-demand during inference.

## Method

MemoryLLM trains all FFN modules in isolation directly on context-free token embeddings (X_0 with per-layer LayerNorm), running them in parallel to a conventionally trained self-attention module that operates on the residual stream; the outgoing residual is X_{L+1} = X_L + Attn(X_L) + FFN(X_0). The TKV framework interprets W_Up columns as keys, W_Down rows as values, and W_Gate as a learned reweighting function, yielding a finite, token-indexed key-value memory that can be probed without any calibration data. Flex-MemoryLLM bridges the performance gap by splitting each FFN's parameters into a context-aware dense module (FFN-C, operating on the residual stream) and a context-free memory module (FFN-M, operating on token embeddings), with βh² parameters allocated to FFN-C. Because FFN inputs are static, outputs can be pre-computed as ToLs and offloaded to storage, reducing active VRAM parameters to roughly one-third of total model size while enabling plug-n-play layer removal without disrupting residual flow.

## Results

On C4 and Wikitext-2 perplexity (50B tokens), MemoryLLM-1B (1208M total, 402M active params) achieves 20.933 and 27.258 respectively, underperforming base-750 (737M active) at 19.730 and 25.491 on a total-parameter basis, but notably outperforming base-250 (265M active) at 23.190 and 32.220 on an active-parameter basis. Flex-MemoryLLM-3h² (704M active) closely matches base-1B (1208M active) performance and even outperforms base-737M at the 1B scale. Reducing FFN contribution (α from 1.0 to 0.5) degrades retrieval-dominated tasks (e.g., LAMBDA drops 69.9%, ARC-Easy drops 38.5%) far more severely than reasoning tasks (e.g., HellaSwag drops only 11.4%, PIQA drops 3.1%), confirming FFNs as token-level parametric knowledge reservoirs.

## Baselines & Comparisons

The paper compares MemoryLLM and Flex-MemoryLLM against three baselines: (1) conventional dense base LLMs at matched total or active parameter counts, (2) post-hoc pruning methods (Magnitude, SparseGPT, Wanda) applied to base models, and (3) the FFN-contribution ablation (scaling α). Against base LLMs at the same total parameter count, MemoryLLM underperforms (e.g., 20.933 vs. 19.730 C4 PPL for 1208M total params), but at the same active parameter count it clearly wins (402M active MemoryLLM beats 265M active base-250 by 1.26 C4 PPL and 4.96 Wikitext-2 PPL). Flex-MemoryLLM-3h² (704M active) nearly matches base-1B (1208M active) and outperforms base-737M, demonstrating that splitting FFN parameters into context-aware compute and context-free memory recovers most of the performance gap. Against pruning baselines, both MemoryLLM and Flex-MemoryLLM significantly outperform base models pruned to the same active parameter count, positioning the architecture as a superior alternative to post-training compression. The FFN ablation (Table 1) shows that retrieval tasks (LAMBDA, ARC-Easy, SiQA) degrade 3–7× more than reasoning tasks (HellaSwag, Winogrande, BoolQ, PIQA) when FFN contribution is reduced, establishing FFNs as dominant for factual recall.

## Relation to Prior Work

This paper extends the FFN-as-key-value-memory line of work initiated by Geva et al. (2021, 2022), which required laborious post-hoc mining of calibration data and operated on non-interpretable contextualized residual activations. The key architectural departure is training FFNs from scratch in complete isolation from self-attention and the residual stream, using only static token-indexed embeddings as input — a principle partially validated in MoLE (Jie et al., 2025) for MoE experts but never applied to dense transformer FFNs. The TKV framework makes the query space finite and human-interpretable (vocabulary token IDs), eliminating the need for reverse-engineering input prefixes to identify memory cell activations.

## Why It Matters / Open Questions

By decoupling FFNs from the residual stream, MemoryLLM provides the first clean, deterministic framework for studying how the two-thirds of LLM parameters in FFNs store and retrieve token-level knowledge, with the practical bonus of enabling pre-computed token-wise lookups that reduce active VRAM to roughly one-third of total parameters. The finding that FFN memory is disproportionately critical for retrieval-based tasks versus reasoning tasks offers a concrete decomposition of where parametric knowledge lives. Open questions include whether this context-free design generalizes to much larger scales (the paper tops out at 1B parameters), whether the plug-n-play ToL offloading strategy remains effective under real-world serving constraints, and whether the performance gap versus conventional LLMs can be fully closed without sacrificing the interpretability guarantee.
