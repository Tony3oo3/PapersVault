## Problem

Tabular foundation models (TFMs) have recently surpassed gradient-boosted trees, but existing approaches suffer from attention fading that limits generalization to larger datasets, rely on closed-source implementations or real-data fine-tuning to reach state-of-the-art, and lack fully open pretraining pipelines. TabICLv2 addresses these gaps by introducing architectural and pretraining innovations that enable native scaling to million-scale tables while remaining fully open-source and outperforming tuned, ensembled, and fine-tuned baselines without any post-hoc adaptation.

## Input / Output

The model consumes a tabular training set (X_train ∈ R^{n×m}, y_train) and test features X_test in a single forward pass, performing in-context learning without gradient updates. For classification, it outputs class probabilities over up to 10 classes natively, extending to arbitrary class counts via mixed-radix ensembling and hierarchical partitioning. For regression, it predicts 999 quantiles at probability levels 0.001–0.999, from which point estimates (mean of quantiles), full predictive distributions (PDF, CDF, moments via tail extrapolation), and probabilistic scores (CRPS) are derived. The model handles up to 100 features and processes 1M-sample tables within 50 GB GPU memory using disk offloading.

## Method

TabICLv2 follows TabICL's three-stage architecture—column-wise embedding via a set transformer (TF_col), row-wise interaction via a transformer with [CLS] tokens (TF_row), and dataset-wise in-context learning (TF_icl)—preserving O(n² + nm²) complexity at ~28M parameters. The key architectural innovation is QASSMax, a query-aware scalable softmax that rescales each query element by MLP_base(log n)·(1 + tanh(MLP_gate(q))), combining a learnable log-n base scaling (to counteract softmax denominator growth) with bounded query-dependent gating to maintain attention sharpness at long contexts. Additional innovations include repeated feature grouping (circular-shift column triplets to break feature symmetries), target-aware embedding (injecting y into every feature token before compression), and mixed-radix ensembling for many-class classification. Pretraining uses a novel synthetic prior with 8 random function types (MLPs, CatBoost-style tree ensembles, GPs, linear/quadratic, EM-plateau, product), random Cauchy graphs, and correlated scalar sampling, optimized with the Muon optimizer at higher learning rates than AdamW across three progressive stages totaling ~24.5 H100 GPU-days.

## Results

On both TabArena (51 datasets) and TALENT (300 datasets), TabICLv2 without any hyperparameter tuning surpasses RealTabPFN-2.5 (which is hyperparameter-tuned over 200 configurations, ensembled, and fine-tuned on real data) in improvability (relative error gap to the best method). TabICLv2 is 10.6× faster than TabPFN-2.5 on an H100 GPU at 50K samples and 11.8× faster on CPU at 10K samples, while natively handling 1M samples × 500 features under 50 GB GPU memory in 450 seconds. On TALENT datasets with >10 classes, TabICLv2 substantially outperforms all baselines, and on datasets with >20K samples it outperforms RealTabPFN-2.5, maintaining strong performance even at ~600K samples where TabPFN-2.5 runs out of memory.

## Baselines & Comparisons

TabICLv2 (default, 8 estimators on TabArena / 32 on TALENT) beats RealTabPFN-2.5 (tuned + ensembled + fine-tuned on real data) on both TabArena and TALENT in improvability, with a statistical test confirming a win rate >50% on TALENT. Against TabPFN-2.5, TabICLv2 is consistently faster across all hardware and dataset sizes (10.6× speedup on H100 at 50K samples), and outperforms it on large datasets (>20K samples) and at ~600K samples where TabPFN-2.5 fails with out-of-memory errors. TabICLv2 substantially outperforms heavily tuned gradient-boosted trees (CatBoost, XGBoost) despite requiring orders of magnitude less training time. Compared to its predecessor TabICL, TabICLv2 achieves significantly higher performance, with the ablation showing that the new prior, QASSMax, Muon optimizer, and target-aware embedding each contribute ~100 Elo points. On few-shot settings (16 training samples), TabICLv2 ranks second to RealTabPFN-2.5 but still outperforms classical baselines and LLMs (Claude Opus 4.6, Qwen3.5-112B).

## Relation to Prior Work

TabICLv2 extends the TabICL architecture (column-wise set-transformer embedding → row-wise interaction → dataset-wise ICL) with three targeted innovations: a query-aware scalable softmax (QASSMax) that generalizes SSMax for long-context attention, a substantially richer synthetic data prior built on the structural causal model framework from TabPFN, and the Muon optimizer replacing AdamW. It departs from the recent trend of real-data fine-tuning (Real-TabPFN, TabDPT) by demonstrating that a purely synthetic pretraining recipe, when paired with the right architecture and prior diversity, can surpass models that are hyperparameter-tuned, ensembled, and fine-tuned on real data. The paper also introduces repeated feature grouping and target-aware embedding as architectural modifications that mitigate representation collapse, and mixed-radix ensembling to handle many-class classification beyond the 10-class pretraining limit.

## Why It Matters / Open Questions

TabICLv2 is the first fully open-source tabular foundation model to match or exceed the closed-source RealTabPFN-2.5 on both TabArena and TALENT without any real-data fine-tuning, democratizing access to SOTA tabular prediction and making the full pretraining recipe reproducible. The QASSMax mechanism addresses a fundamental limitation (attention fading) that constrains all softmax-based attention in long-context settings, with potential applicability beyond tabular data. Key open questions remain: the model does not leverage column-name semantics, handles missing values only via mean imputation, lacks distribution-shift robustness, and its quantile-based regression has not been rigorously evaluated beyond toy settings. The strong architecture-prior interaction (TabICLv2 architecture fails with the TabICL prior) suggests that future TFM development must co-design data generation and model architecture rather than treating them independently.
