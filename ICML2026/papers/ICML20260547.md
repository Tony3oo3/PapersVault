## Problem

Data-driven cybersecurity research is bottlenecked by the scarcity of labeled malware traffic datasets: public benchmarks are 5–25 years old, manual environment construction is prohibitively costly, and generic sandboxes fail to trigger behavior in over 80% of modern malware samples that perform environment-aware dependency checks before activating. No existing method can automatically extract sample-specific environmental dependencies from scattered, often contradictory threat intelligence and synthesize tailored execution environments at scale.

## Input / Output

The system consumes a malware sample together with three categories of threat intelligence: static analysis artifacts (PE headers, import tables, embedded strings), partial behavioral execution logs from CAPE, and external intelligence (VirusTotal verdicts, family signatures, MITRE ATT&CK mappings). It produces a structured environmental specification (OS version, runtime dependencies, network constraints, hardware profile), an executable Terraform IaC configuration validated against both IaC grammar and cloud-provider schemas, and finally captured network traffic. All synthesized environments include INetSim as a protocol-level C2 simulation layer so that malware can establish connections even when original infrastructure is offline.

## Method

Threat2Traffic decomposes the problem into two stages that separately address input-side ambiguity and output-side fragility. Stage I (Dialectic Intent Arbitration) deploys three specialized LLM agents to extract observations and hypotheses into an Evidence Graph, then resolves conflicts through adversarial deliberation grounded in Dung's Abstract Argumentation Framework with a preference function π(h) = α·CONF(h) + β·SUPPORT(h) that directs asymmetric attacks; the grounded extension is computed via fixed-point iteration to yield a conflict-free hypothesis set. Stage II (Invariant-Guided Synthesis) compiles a local platform schema from the Evidence Graph's resource set, generates an initial IaC draft, and enforces correctness through dual-layer validation—first syntactic parseability (grammar Γ), then semantic compliance (provider schema Φ_plat)—with iterative LLM refinement guided by structured error feedback (location, type, remediation hint) until the configuration passes both tiers or a retry budget is exhausted. The key architectural insight is that separating constraint inference (probabilistic, evidence-weighted) from code generation (deterministic, schema-constrained) and bridging them through an explicit intermediate representation (the Evidence Graph) eliminates the hallucination and ambiguity failures that plague end-to-end LLM generation.

## Results

Threat2Traffic with Claude-Sonnet-4.5 achieves 83.1% Environment Reproduction Success Rate (ERSR) on 1,077 malware samples across 8 families, with 96.3% Infrastructure Provisioning Success Rate (IPSR) and 86.2% Malware Behavior Triggering Rate (MBTR). The Qwen3-14B variant reaches 66.3% ERSR (91.4% IPSR, 72.4% MBTR), already surpassing the best static sandbox (Hybrid Analysis at 65.2%). Constraint extraction quality averages 81.0% F1-score against human-annotated constraints, and the framework activates 895 valid samples versus 702 for Hybrid Analysis (27.5% improvement).

## Baselines & Comparisons

Threat2Traffic (Claude-Sonnet-4.5) outperforms all four baselines on ERSR across every malware family. Against static sandboxes, it beats CAPE (42.6%) by 40.5 percentage points and Hybrid Analysis (65.2%) by 17.9 points, with the largest gains on Ransomware (+51.7 pp over CAPE) and Coinminer (+53.0 pp over CAPE). Against LLM-based baselines, it surpasses Single LLM (49.9%) by 33.2 pp and Vanilla MAS (59.9%) by 23.2 pp; the gap over Single LLM is driven primarily by IPSR (96.3% vs. 64.5%), showing that dual-layer validation is critical for producing executable IaC. The Vanilla MAS baseline, which uses majority voting instead of adversarial deliberation, achieves comparable MBTR (79.0% vs. 86.2%) but lower IPSR (75.8% vs. 96.3%), confirming that structured conflict resolution and schema validation each contribute distinct gains. Statistical significance is confirmed with p < 0.01 and Cohen's d > 2.0 for all pairwise comparisons.

## Relation to Prior Work

This paper sits at the intersection of three research threads: (1) dynamic malware analysis sandboxes (CAPE, Hybrid Analysis), which it departs from by replacing generic pre-configured environments with sample-specific ones synthesized on demand; (2) LLM-based threat intelligence extraction (Buchel et al., 2025; Cuong Nguyen et al., 2025), which it inverts—rather than mapping reports forward to ATT&CK techniques, it recovers enabling configurations from observed behaviors; and (3) LLM-based Infrastructure-as-Code generation (Kon et al., 2024; Xu et al., 2024), which it extends with a dual-layer validation loop enforcing both syntactic parseability and semantic schema compliance. The multi-agent deliberation mechanism is grounded in Dung's Abstract Argumentation Framework with a preference function, distinguishing it from general-purpose multi-agent debate (Du et al., 2023; Liang et al., 2024) that lacks principled conflict resolution.

## Why It Matters / Open Questions

The paper addresses a concrete and well-motivated bottleneck: the 5–25-year staleness of public traffic datasets and the inability of generic sandboxes to trigger environment-aware malware (80%+ of samples). The released dataset of 1,077 samples across 8 families with captured traffic is immediately useful for training and benchmarking IDS models. Key open questions remain: 28.6% of failures stem from C2 interaction requirements that protocol-level simulation (INetSim) cannot satisfy, and 23.1% require user interaction (clicks, form submissions) that the current shell-script execution cannot provide. Extending to mobile/IoT platforms and developing goal-directed user-behavior agents are identified as the most impactful next steps.
