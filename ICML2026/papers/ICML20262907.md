## Problem

Existing LLM-based bug detection tools excel at finding localized implementation bugs (integer overflows, memory leaks) but cannot reason about the complex, state-dependent logic inherent in distributed consensus protocols, where subtle violations of safety and liveness properties span multiple components and execution stages. This gap leaves production-level consensus systems (e.g., etcd, Sui) exposed to critical protocol-level logic bugs that can cause data corruption and financial losses, bugs that even experienced engineers require extensive periods to uncover.

## Input / Output

Agora consumes a consensus protocol code repository (Go or Rust), a lightweight knowledge library (~360 KB) containing 34 curated bug patterns extracted from 816 GitHub issues and protocol-specific constraints distinguishing CFT (crash-only, honest nodes) from BFT (Byzantine, up to f < n/3 malicious nodes) fault models, plus repository metadata (protocol type, language, testing helpers). It produces protocol-level logic bugs as executable unit tests with oracle assertions, structured as vulnerability hypotheses H=(C,A,E,O) where C is the precondition, A the action sequence, E the expected buggy behavior, and O the validation oracle. Each run is bounded to 3 hours with a maximum of 50 reflection-loop iterations per attack scenario, yielding a 26.1% false-positive rate across 46 generated bug reports.

## Method

Agora is a domain-aware three-agent multi-agent system that operationalizes the hypothesis-driven testing (HDT) paradigm for consensus protocol verification. The Orchestrator agent maintains global state and performs bug exploitation (leveraging previously discovered bugs to trigger deeper variants) and state analysis (preventing redundant scenario exploration); the Strategy agent contains a constraints-analyzer that adapts attack vectors to CFT vs. BFT fault models and an attack scenario-generator that simulates node behaviors (crash, recovery, equivocation, selective broadcast) and manipulates message ordering to produce protocol-specific bug-prone scenarios; the TestGen agent runs a reflection loop (generate → execute → analyze, up to 50 iterations) to produce valid unit tests and reduce false positives. Agents communicate exclusively through the Orchestrator's global state, avoiding direct Strategy–TestGen coupling, and access code repositories via the Model Context Protocol (MCP). The key architectural insight is that explicit role separation—decoupling workflow control, protocol-level scenario reasoning, and test generation—enables reasoning about global protocol invariants that single-agent or ReAct-based approaches cannot achieve, as confirmed by ablation studies showing 73–100% effectiveness loss when any single component is removed.

## Results

Agora discovers 15 previously unknown protocol-level logic bugs (zero-day) across four consensus implementations (Raft, EPaxos, HotStuff, BullShark), while all ReAct-based baselines detect zero logic bugs. The best Agora configuration (Qwen3 Coder 480B A35B) identifies 15 logic bugs, followed by GPT-5.2 (11), Claude Sonnet 4.5 (9), and Gemini 3.0 Pro Preview (6). Baselines collectively find only 22 implementation-level bugs (e.g., copy-paste errors, memory leaks), with GPT-5.2 accounting for 22 of those. The false positive rate across all 46 generated bug reports is 26.1% (34 confirmed real bugs).

## Baselines & Comparisons

All four ReAct-based baselines (GPT-5.2, Gemini 3.0 Pro, Claude Sonnet 4.5, Qwen3 Coder) fail to detect any protocol-level logic bugs, finding at most 22 implementation-level bugs (e.g., a copy-paste error in EPaxos's bcastTryPreAccept). GPT-5.2 is the strongest baseline, detecting 22 implementation bugs across Raft, EPaxos, and HotStuff, but zero logic bugs. Gemini 3.0 Pro and Claude Sonnet 4.5 detect no bugs at all under the ReAct setup. In contrast, Agora with the same underlying LLMs consistently discovers logic bugs: Qwen3 Coder yields 15, GPT-5.2 yields 11, Claude Sonnet 4.5 yields 9, and Gemini 3.0 Pro yields 6 (with overlap, totaling 15 unique bugs). The paper also reports that the baselines' 22 implementation bugs are reported as an additional contribution, but these are fundamentally different in severity from the 15 protocol-level logic bugs (safety/liveness violations) that Agora uncovers.

## Relation to Prior Work

This paper repurposes the hypothesis-driven testing (HDT) paradigm from biology (Kell & Oliver, 2004) into a multi-agent LLM framework for consensus protocol verification, combining it with domain-specific bug patterns and CFT/BFT constraints. It departs from prior LLM-powered bug detection work (LLMSAN, SCALE, LLMDFA, KNighter), which targets localized implementation bugs, by explicitly separating protocol-level logic bug discovery from low-level code analysis. The multi-agent architecture draws on the broader LLM agent literature (ReAct, MetaGPT, Magnetic-One, OWL) but introduces a domain-aware role decomposition (Orchestrator/Strategy/TestGen) that no prior agent-based bug detection system has attempted for distributed consensus.

## Why It Matters / Open Questions

The stark result—baselines detect 22 implementation bugs but zero protocol-level logic bugs, while Agora detects 15 logic bugs and zero implementation bugs—demonstrates that general-purpose LLM agents, even with ReAct scaffolding, cannot reason about state-dependent protocol invariants without explicit domain knowledge and structured multi-agent coordination. This has direct practical impact on the security of production systems (etcd, Sui) and provides a reusable template for domain-aware autonomous testing in other protocol-heavy domains (concurrency control, smart contracts). Key open questions include whether the approach scales beyond four protocols, whether the 15 'zero-day' bugs survive independent verification, and whether fine-tuning (SFT/DPO) can reduce the dependency on hand-curated bug patterns and constraints.
