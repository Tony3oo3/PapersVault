## Problem

Existing vulnerability detection pipelines require complete program context and provide only sparse, end-of-completion feedback, making them ill-suited for real-time, prefix-level security assessment during interactive coding and streaming generation. Moreover, LLM/GNN-based detectors trained with coarse program-level binary supervision struggle to attend to fine-grained vulnerable regions, and their accuracy degrades as code length grows from function-level to repo-level.
![Teaser figure](../imgs/ICML20265609/cropped_page1_idx0.webp)

## Input / Output

The model consumes a code trajectory segmented into discrete steps (delimited by double newlines, further refined via AST-based merging of logical blocks) and produces a per-step security score in [-1,1] computed as the logit margin between safe and vulnerable classes, conditioned on all preceding context. For vulnerability detection, step scores are aggregated via risk-sensitive temperature-scaled weighting into a single trajectory-level verdict; for secure code generation, the same per-step scores rank K candidate continuations via advantage-based selection to pick the top-k most secure completions.

## Method

SecCodePRM builds on Qwen2.5-Coder-7B-Instruct with an added binary classification head, trained in two stages (head-only then full-parameter fine-tuning) with a weighted cross-entropy loss that balances the minority vulnerable class. Step-level supervision labels are derived by contrastive sequence alignment (LCS) between vulnerable and patched code, assigning negative labels to steps overlapping the diff and propagating them through the transitive closure of caller functions via AST analysis. The key architectural insight is that evaluating each step within the full preceding trajectory context—rather than classifying the entire program as a unit—lets the model pinpoint exactly when a vulnerability is introduced, yielding dense, real-time reward signals. For detection, a temperature-scaled softmax aggregation emphasizes low-reward (high-risk) steps; for generation, the PRM enables inference-time scaling by ranking candidate continuations and allocating compute toward trajectories with higher cumulative reweighted reward, effectively shifting from low-safety to high-safety paths without degrading functional correctness.

## Results

On PrimeVul (full-code VD), SecCodePRM achieves 96.83% accuracy and 96.73% F1, surpassing the prior SOTA LLMxCPG (72.50% Acc, 62.06% F1) by over 24 points in accuracy. On SVEN, it reaches 72% Acc/F1 versus 60% for LLMxCPG and 51% for ReGVD. For partial-code VD, SecCodePRM (7B) attains 90.00% F1 on PreciseBugs and 55.71% F1 on PrimeVul, outperforming GPT-oss-120B (11.60–16.92% F1) by a wide margin. On CWEval secure code generation, SecCodePRM with QC3-30B achieves 78.15% func@1 and 54.62% safe@1, improving over probability-based ranking by 11.09% and 12.98% respectively.

## Baselines & Comparisons

SecCodePRM decisively outperforms all 12 baselines across every benchmark. On SVEN full-code VD, it beats VulSim (Acc 33→72), VulBERTA (Acc 50→72), ReGVD (Acc 51→72), and LLMxCPG (Acc 60→72, F1 70→72). On PrimeVul, the gap is most dramatic: SecCodePRM's 96.83% Acc exceeds LLMxCPG by 24.3 points and Qwen2.5-PRM-7B by 46.7 points, while achieving 0% P-V and P-R (no reversed or double-vulnerable predictions) versus 8–82% for GPT-4 variants. On PreciseBugs (20K+ token contexts), SecCodePRM (F1=0.59) surpasses MSIVD (F1=0.48), LineVul (F1=0.31), and CodeLlama (F1=0.22), demonstrating robustness to long sequences. For partial-code VD, SecCodePRM (7B) nearly doubles the F1 of the strongest LLM baseline (GPT-oss-120B-h: 25.52% F1 on SVEN vs. 50.17%), and achieves 90% F1 on PreciseBugs where all LLMs score below 17%. On CWEval secure generation, SecCodePRM outperforms both probability-based ranking and QwenPRM on both func@k and safe@k, and on LiveCodeBench it matches or slightly exceeds general-purpose baselines (55.19% vs. 53.23% pass@1 on QC2.5-32B), confirming no safety-utility tradeoff.

## Relation to Prior Work

This paper repurposes the process reward model (PRM) paradigm—previously applied to math reasoning and general code quality (e.g., QwenPRM)—for the first time to code security, replacing coarse program-level binary supervision with dense step-level safety labels derived from static analyzers (CodeQL) and expert annotations. It departs from the dominant LLM+GNN and LLM+static-tool pipelines (e.g., LLMxCPG, MSIVD) by eliminating external analysis tools and multi-stage training in favor of a single end-to-end transformer with a classification head, and it introduces a risk-sensitive aggregation scheme that weights low-safety steps more heavily. The inference-time scaling component (best-of-N candidate ranking via cumulative reweighted reward) extends prior secure code generation work (constrained decoding, prompt tuning) by decoupling generation from verification and allocating compute toward higher-safety trajectories.

## Why It Matters / Open Questions

SecCodePRM addresses a practical gap: real-time, prefix-level security feedback during interactive coding and streaming generation, where full-program static analysis is infeasible. The finding that a 7B PRM outperforms 120B general-purpose LLMs on partial-code vulnerability detection, and that security-aware ranking does not degrade (and sometimes improves) general code functionality, suggests that step-level security supervision is a more effective inductive bias than raw scale for this task. Open questions include generalization beyond C/C++/Python and known CWE categories to zero-day or novel vulnerability patterns, the reliability of step-level labels derived from sequence alignment heuristics on unpaired data, and whether the approach transfers to functional or domain-specific languages.
