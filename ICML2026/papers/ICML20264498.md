## Problem

Mixture-of-Experts (MoE) layers are the standard way to scale sparsity in language models, but their context-dependent routing introduces significant systems overhead: routers require auxiliary losses to prevent collapse, and the unknown expert activation per token prevents efficient CPU offloading. Meanwhile, the tokenizer embedding table is natively sparse and systems-friendly but provides no contextual information. The paper asks whether one can achieve context-dependent aggregation of sparse parameters without the systems baggage of dynamic routing.

## Input / Output

At the layer level, L³ takes a hidden state x ∈ R^{d_in} and a token ID t, and produces a d_out-dimensional output that is added to the residual stream. The token ID statically selects a fixed set of key/value embeddings (at most k=512 per token), while the hidden state dynamically weights them via attention. At the model level, L³ layers are inserted between standard Llama-3 decoder layers in a transformer that performs next-token prediction on text sequences, with the full model trained on FineWeb-Edu and evaluated on WikiText-2 perplexity and zero-shot downstream benchmarks.

## Method

The L³ layer replaces the need for a learned router by using the token ID to statically index into large key (K_t) and value (V_t) embedding matrices, then uses the incoming hidden state to attend over the selected embeddings via Softmax(K_t x), up-projects the result, and mixes it with the residual through a learned W_mix. Embedding allocation across token IDs is determined by an LZW-based algorithm that builds codeword frequencies from a corpus and assigns more embeddings to tokens that terminate high-frequency codewords, effectively emulating a context-dependent router with a static lookup. For training, tokens are sorted by ID to form a block-diagonal attention mask enabling fast kernels (FlexAttention or block iteration); for inference, the known token ID at generation time allows L³ parameters to be CPU-offloaded and prefetched during pre-L³ compute, adding minimal latency. The architecture is orthogonal to MoE and is proposed as an additional sparsity axis rather than a replacement.

## Results

On WikiText-2, adding L³ layers reduces perplexity from 22.02 to 20.23 (800M, 2 L³ layers), 18.83 to 16.72 (1.5B, 2 L³), and 15.43 to 14.51 (2.6B, 2 L³) compared to iso-FLOP dense baselines. On average 0-shot downstream accuracy (ARC-C, ARC-E, HellaSwag, PIQA, WinoGrande), L³ models improve from 48.28 to 49.45 (800M), 51.93 to 53.84 (1.5B), and 55.59 to 56.98 (2.6B). The 2.6B 2-L³ model (7B total params, 2.6B active) achieves 58.80% WinoGrande and 71.71% PIQA, outperforming the dense 2.6B model by 1.5 and 0.5 points respectively.

## Baselines & Comparisons

L³ consistently outperforms iso-FLOP dense baselines at all three model scales (800M, 1.5B, 2.6B) on both WikiText-2 perplexity and average downstream accuracy, with gains of 0.9–2.1 perplexity points and 1.2–1.4 average accuracy points. Against iso-FLOP, iso-sparse MoE baselines (following OLMoE training recipes with softmax routers, load-balancing loss, and router z-loss from Shazeer et al., 2017 and Muennighoff et al., 2025), L³ wins at every tested sparsity rate: the 800M 2-L³ model (AVG 49.45) beats its MoE equivalent (AVG 48.59) by 0.86 points, and the 1.5B 1-L³ model (AVG 53.09) beats its MoE equivalent (AVG 51.68) by 1.41 points. Notably, at the 800M scale an MoE equivalent to two L³ layers underperforms even a single L³ layer, and at 1.5B an MoE equivalent to one L³ layer underperforms the dense baseline entirely, suggesting MoE routing requires larger token budgets to realize its benefits. The paper also reports that L³ training perplexity improves monotonically from the start, unlike MoEs where learning a discrete router can initially degrade performance below the dense baseline.

## Relation to Prior Work

L³ generalizes the tokenizer embedding table—a natively sparse layer present in every language model—into decoder layers, using static token-ID-based routing to select a set of learned embeddings that are then aggregated context-dependently via attention. This positions it as orthogonal to MoE architectures (Shazeer et al., 2017), which use learned dynamic routing to dense experts, and distinct from prior embedding-table extensions like Product Key Networks (Lample et al., 2019) and SCONE (Yu et al., 2025), which either require context-dependent key selection or operate only at the input layer. The key novel component is the LZW-based embedding allocation algorithm (Welch, 1984), which repurposes lossless compression theory to determine how many embeddings each token ID receives, replacing the need for a learned router. Concurrent work on Engrams (Cheng et al., 2026) places embedding tables throughout the model with similar attention-based aggregation but adds n-gram hashing and pooling steps that L³ omits.

## Why It Matters / Open Questions

L³ offers a hardware-friendly axis of sparsity that avoids the systems overhead of MoE dynamic routing: because the active parameters are known at token generation time, L³ layers can be CPU-offloaded and prefetched with minimal latency, and training requires no auxiliary load-balancing losses. The consistent outperformance of both dense and iso-sparse MoE baselines across three model sizes (800M–2.6B active params) suggests this is not a small-scale artifact, though the evidence is limited to FineWeb-Edu and relatively modest parameter counts where MoEs are known to underperform. Open questions include whether L³ and MoE can be combined in the same model, how the approach scales beyond 2.6B active parameters, whether L³ layers can be swapped across tasks (analogous to Cartridges), and whether the LZW allocation generalizes to non-English or multimodal tokenizers.
