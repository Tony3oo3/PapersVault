## Problem

In RL post-training of LLM agents, external tool calls (compiling code, running test suites, querying databases, processing video) consume 7–43% of rollout time on average, leaving allocated GPUs idle. While many tool invocations repeat across parallel rollouts for the same prompt, existing prompt and context caching methods assume a stateless mapping from inputs to outputs and cannot correctly cache tool calls whose results depend on the mutable sandbox state induced by prior agent interactions.

## Input / Output

TVCACHE consumes the full ordered sequence of tool descriptors (tool name plus serialized arguments) from a rollout as its lookup key rather than just the individual tool call being issued. On a full-prefix cache hit it returns the previously computed tool execution result; on a partial match it returns a forked sandbox state at the longest matching prefix so the rollout executes only the remaining unmatched suffix. The per-task Tool Call Graph persists across post-training iterations, enabling reuse both within a single epoch and across epochs, and a TTL mechanism invalidates entries to handle non-deterministic tool outputs.

## Method

TVCACHE organizes cached tool calls into a Tool Call Graph (TCG) whose root-to-node paths represent sequences of tool calls observed across rollouts, with each node storing the tool descriptor, its execution result, and optionally a serialized sandbox snapshot. Cache lookups reduce to longest-prefix matching (LPM): a hit occurs only when the agent's entire tool history exactly matches a cached path, guaranteeing identical sandbox state and thus correct results, while a partial match triggers forking the sandbox at the matched prefix and executing only the unmatched suffix. To avoid prohibitive memory overhead, TVCACHE employs selective snapshotting—storing a sandbox snapshot only when a tool call's execution time exceeds the snapshot serialization and restoration cost—and proactive forking, which pre-creates warm sandbox copies for nodes that already have stored snapshots. A reference-counting scheme coordinates safe concurrent access to shared sandbox prefixes across parallel rollouts, and the system shards TCG servers by task ID to sustain near-linear throughput under high request rates.

## Results

TVCACHE achieves cache hit rates of up to 67% (EgoSchema), 33% (SkyRL-SQL), and 14–25% (terminal-bench) across three agentic post-training workloads. The median per-tool-call execution time is reduced by up to 6.9× (Qwen3-4B on terminal-bench medium: 18.68 s → 2.70 s) and 8.7× per individual hit on SkyRL-SQL (56.6 ms → 6.5 ms). Critically, reward curves with TVCACHE closely match those without caching across all model sizes (4B, 14B, 30B) and workloads, confirming no post-training performance degradation.

## Baselines & Comparisons

The paper does not benchmark against other caching systems (e.g., Kimi K2's simulated tool responses, VERLTOOL's parallel execution) but instead compares TVCACHE against two baselines. First, against a no-cache baseline, TVCACHE consistently reduces median tool-call latency by 3.4×–6.9× on terminal-bench and 2.9× (expected) on SkyRL-SQL, with the largest gains on medium-difficulty tasks where tool calls are longer. Second, against a stateless cache (keyed only on tool name + arguments), TVCACHE demonstrates a critical correctness advantage: over 25% of stateless cache hits return incorrect (stale) outputs on terminal-bench easy tasks (27.4% for Qwen3-4B, 26.1% for Qwen3-14B), whereas TVCACHE's longest-prefix matching over the tool call graph guarantees identical sandbox state and thus correct results. The paper also shows that TVCACHE remains effective even with a single rollout per task (10.1% hit rate on terminal-bench, 23.4% on SkyRL-SQL), indicating it is not limited to highly parallel GRPO configurations.

## Relation to Prior Work

TVCACHE carves new ground at the intersection of three existing lines of work: RL-based post-training for tool-use (Kimi K2, OTC-PO, VERLTOOL), semantic/prompt caching for LLM inference (GPTCache, vCache, SmartCache), and prefix caching in LLM serving systems (vLLM, SGLang). It departs from semantic caching by rejecting the stateless prompt-to-response assumption that makes those methods inapplicable to stateful tool execution, and from prefix caching in inference engines by targeting tool-call results rather than KV-cache reuse. The tool call graph with longest-prefix matching is a novel adaptation of trie-like indexing to the stateful sandbox domain, combined with selective snapshotting and proactive forking to keep overhead manageable.

## Why It Matters / Open Questions

Tool execution consuming 7–43% of rollout time (with >90% tail cases) is a concrete, measurable bottleneck that directly inflates post-training cost for any lab training tool-using agents; a 6.9× median speedup with zero reward degradation is practically significant. Open questions include whether the TCG approach scales to very large or open-ended tool spaces where prefix overlap is sparse, how to handle non-determinism beyond simple TTL-based invalidation, and whether 'fuzzy' or semantic matching over tool-call trajectories (analogous to semantic prompt caching) could further improve hit rates without sacrificing correctness. The Docker-specific forking and network-allocation optimizations also limit immediate portability to non-container sandbox environments.
