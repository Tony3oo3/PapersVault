## Problem

Existing multi-adapter serving systems (S-LoRA, Punica) route entire sequences to a single adapter, which fails for multimodal generation where text and image tokens require different adapters within one sequence, and for mixed-capability requests (e.g., 'write code to solve this equation') that need multiple specialized adapters simultaneously. Per-sequence routing forces either suboptimal adapter selection or K separate forward passes, creating both a quality ceiling and a K× computational overhead.
![Teaser figure](../imgs/ICML20264022/cropped_page1_idx0.webp)

## Input / Output

The method consumes token hidden-state embeddings (x ∈ R^{B×L×d}), vocabulary indices for deterministic modality lookup, and request metadata (e.g., customer adapter ID) for compositional routing. It produces per-token routing decisions mapping each of N tokens to one of C computational targets, followed by LoRA-augmented hidden states computed as h_i = x_i W + x_i A_{r(i)} B_{r(i)}. For MoLoRA's learned routing, the router outputs top-k softmax-weighted adapter combinations per token, and the hot-set memory layout pre-allocates weight tensors of shape (S, M, d, r) at fixed GPU addresses to enable CUDA graph capture.

## Method

MoLoRA introduces per-token adapter routing with two complementary policies: deterministic vocabulary routing (O(1) integer comparisons against modality boundaries) for models with disjoint vocabulary ranges, and learned gating via a 2-layer MLP router (hidden dim 64, GELU) that produces top-k adapter logits with softmax weighting for semantic specialization. Multiple domain-specific LoRA adapters (rank 32, trained independently via GRPO) are loaded simultaneously, and the router selects the appropriate adapter per token, with a Switch-Transformer-style auxiliary load-balancing loss during training. The execution substrate uses a static hot-set memory model (pre-allocated GPU-resident adapter slots) that eliminates paging latency and enables CUDA graph capture, combined with a target-agnostic dispatch kernel (histogram → atomic pointer allocation → grouped GEMM with adaptive tiling) that is structurally identical to MoE expert dispatch. The paper proves per-token routing is computationally optimal (N work vs. K·N for per-sequence) and demonstrates that Qwen3-1.7B + MoLoRA exceeds Qwen3-8B across four reasoning benchmarks while being 4.7× smaller.

## Results

On four reasoning benchmarks, Qwen3-1.7B with MoLoRA (four specialized LoRA adapters + learned per-token routing) exceeds Qwen3-8B (4.7× larger) by +14% on GSM8K, +8% on MATH, +2.5% on BBH, and +2.1% on GPQA. Against a 1.7B union-LoRA trained on the same combined data without routing, MoLoRA gains +3.0% (GSM8K), +14.5% (MATH), +7.0% (BBH), and +2.1% (GPQA), isolating the benefit to routing rather than data union. On the efficiency side, per-token routing reduces K=4 forward passes to 1, yielding a 4.1× latency speedup (5.88 ms → 1.43 ms), and CUDA graph capture with hot-set memory further reduces P99 latency by 67×.

## Baselines & Comparisons

Against Qwen3-8B (the scale baseline), MoLoRA on Qwen3-1.7B wins on all four reasoning benchmarks—GSM8K by +14%, MATH by +8%, BBH by +2.5%, and GPQA by +2.1%—while being 4.7× smaller, demonstrating that composable specialization beats raw parameter scale. Against the union-LoRA control (same 1.7B base, same training data, single monolithic adapter, no routing), MoLoRA improves by +3.0% on GSM8K, +14.5% on MATH, +7.0% on BBH, and +2.1% on GPQA, confirming the gain comes from per-token routing rather than simply combining data. On the systems side, per-token routing with hot-set memory and CUDA graph capture achieves a 4.1× latency reduction over S-LoRA-style per-sequence routing (5.88 ms vs. 1.43 ms for K=4 modalities, 2048 tokens), and a 67× P99 latency reduction from eliminating dynamic paging. At production batch sizes (256–1024), the tensor-core kernel with graph capture is 1.3–2.7× faster than S-LoRA's BGMV scalar kernel, with the gap widening to 2.69× at batch 1024.

## Relation to Prior Work

This paper extends multi-adapter serving systems (S-LoRA, Punica) from per-sequence routing to per-token routing, drawing a direct structural parallel to MoE dispatch (histogram construction, scatter-gather, grouped GEMM) so that adapter serving inherits MoE systems optimizations like adaptive tiling from MegaBlocks. The MoLoRA component adapts Switch Transformer's learned top-k gating and load-balancing loss to the LoRA adapter setting, enabling composable specialization where multiple domain-specific LoRAs are combined at inference time. The hot-set memory architecture departs from the CPU-GPU paging model of S-LoRA/Punica by pre-allocating fixed GPU-resident adapter slots, which is what makes CUDA graph capture possible and eliminates data-dependent control flow on the critical path.

## Why It Matters / Open Questions

The composable specialization result (1.7B + MoLoRA exceeding 8B on four reasoning benchmarks) suggests a practical path to modular expertise: train small focused adapters independently and combine them without retraining, which could reduce the cost of adding new capabilities in production. However, the inference cost scaling (Table 15) reveals that MoLoRA with k=2 is ~28× more expensive than a single adapter, and the quality results are demonstrated on one model family (Qwen3) with GRPO-trained adapters, leaving open whether the specialization-beats-scale gap holds across architectures and training regimes. The systems contributions (hot-set + CUDA graph yielding 67× P99 reduction) are more broadly applicable and likely to be adopted in multi-adapter serving deployments regardless of the routing policy.
