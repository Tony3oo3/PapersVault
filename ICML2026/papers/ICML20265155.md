## Problem

Traditional code complexity metrics such as cyclomatic complexity were designed to characterize structural properties relevant to human comprehension and testing, yet it remains unclear whether they capture the difficulty that LLMs actually experience when processing code. This paper empirically demonstrates that these metrics exhibit no consistent correlation with LLM performance once code length is controlled, revealing a fundamental mismatch between classical complexity measures and model-perceived difficulty.
![Teaser figure](../imgs/ICML20265155/cropped_page0_idx0.webp)

## Input / Output

The method takes a source code snippet and a pretrained language model (used solely for entropy estimation, distinct from the task-performing model) as input. The code is first normalized by stripping comments and docstrings, then tokenized; per-token entropy is computed from the entropy model's next-token distribution. The output is a scalar LM-CC score computed as a weighted sum over all semantic units in the induced hierarchy, along with the intermediate semantic compositional hierarchy itself. The entropy threshold τ is fixed at 0.67 (67th percentile of token entropies) and the weighting α=0.8 is set via ablation.

## Method

LM-CC is built on the hypothesis that LLM-perceived code difficulty is driven by semantic nonlinearity, specifically the joint interaction between hierarchical compositional depth and branching-induced semantic divergence. The method proceeds in three stages: (1) a hybrid entropy-structure decomposition identifies semantic unit boundaries where token entropy exceeds τ or a syntactic delimiter occurs, then recursively organizes units into a compositional hierarchy via BFS over indentation and nesting; (2) two global features—TotalCompLevel (cumulative depth) and TotalBranch (cumulative branching factor)—are extracted and selected via partial correlation analysis as the most robust predictors across tasks; (3) LM-CC is defined as α·TotalBranch + (1−α)·TotalCompLevel, aggregating per-unit contributions. A theoretical analysis formalizes why this metric separates from cyclomatic complexity: two programs with identical CC can exhibit Θ(n) vs. Θ(n²) LM-CC depending on whether their semantic structure is flat or deeply nested, explaining why CC loses predictive power under length control while LM-CC remains strongly correlated with LLM performance.

## Results

LM-CC achieves statistically significant partial Spearman correlations with LLM pass@1 in all 16 experimental settings (4 entropy models × 4 tasks), with correlation coefficients ranging from −0.80 to −0.97 after controlling for code length. In contrast, no traditional metric (CC, HC, MI, CoC) achieves consistent significance across tasks. Semantics-preserving LM-CC reduction yields relative performance gains of 20.9% on program repair (13.4%→16.2%), 10.2% on code translation (42.2%→46.5%), and 0.96% on execution reasoning (94.1%→95.0%), while keeping cyclomatic complexity unchanged.

## Baselines & Comparisons

The paper compares LM-CC against four traditional complexity metrics: Cyclomatic Complexity (CC), Halstead Complexity (HC), Maintainability Index (MI), and Cognitive Complexity (CoC). After controlling for code length via partial correlation, none of the four baselines achieves statistically significant correlations across all tasks: CC is non-significant in program repair and only reaches −0.73 (translation) and −0.67 (execution reasoning); HC shows −0.93 in program repair but drops to −0.70 in translation and is non-significant in execution reasoning; MI is significant only in execution reasoning (−0.72); CoC is non-significant in partial correlation for all tasks. LM-CC, by contrast, achieves significance in 16/16 settings with correlations from −0.80 to −0.97, substantially outperforming every traditional metric in both coverage and magnitude. The causal intervention (Table 3) further confirms that reducing LM-CC while holding CC constant improves downstream performance, demonstrating that the gains are attributable to semantic nonlinearity rather than traditional control-flow simplification.

## Relation to Prior Work

This paper departs from the long lineage of human-oriented code complexity metrics (McCabe's cyclomatic complexity, Halstead, Cognitive Complexity, Maintainability Index) by arguing they are fundamentally misaligned with how LLMs process code. It repurposes token-level entropy signals from NLP (Cooper & Scholak 2024; Shi et al. 2025a) as a proxy for model uncertainty, applying them to construct a semantic compositional hierarchy over source code—a representation not previously used for complexity measurement. While recent work (Sepidband et al. 2025; CodeMind; DynaCode) has observed that LLM performance degrades with code complexity, all still rely on traditional structural metrics; this paper is the first to propose a metric explicitly grounded in LLM representational dynamics.

## Why It Matters / Open Questions

The clean negative result—that no traditional complexity metric retains significant correlation with LLM performance after controlling for code length—challenges a widely implicit assumption in software engineering and LLM evaluation. Practically, LM-CC offers a concrete optimization target: semantics-preserving rewrites that reduce LM-CC yield up to 20.9% improvement in program repair, suggesting model-aware refactoring is a viable direction. Open questions include whether the metric generalizes beyond Python, whether the entropy model used for computation must match the task-performing model, and whether the circularity of using model entropy to predict model performance limits its utility as an independent diagnostic. The threshold τ=0.67 is set empirically and its sensitivity across languages and model scales remains unexplored.
