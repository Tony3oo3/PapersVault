## Problem

Existing LLM-based Verilog generation methods, including fine-tuned domain-specific models and agent-based systems, fail to scale to industrial IP-level design tasks where specifications average ~10k tokens and target modules exceed 300 lines of code. The paper identifies three compounding challenges: critical interface constraints get buried in verbose multi-submodule documents, syntactic and semantic correctness degrade sharply with output length, and IP-level debugging requires tracing failures through complex signal interactions back to ambiguous specification segments.

## Input / Output

The method takes a long natural language specification document (structured as an ordered sequence of semantic textual units such as paragraphs or sections), a target module name, and a simulation environment providing golden execution feedback (error messages and behavioral mismatches). The output is a synthesizable Verilog module modeled as a structured set of functionally cohesive code units (modules, statements) rather than a monolithic text file, which must pass a suite of simulation tests against a predefined golden reference testbench. The document is preprocessed into a hierarchical dual-level index (semantic summaries plus lexical hardware entities like signal names and macros) that serves as the retrieval key for all downstream agents.

## Method

ChipV-RTL is a multi-agent framework grounded in the information locality hypothesis: for any code unit, the information needed to generate it is concentrated in a small subset of the specification, a property quantified via entropy of LLM conditional generation probabilities and confirmed to be significantly stronger in hardware specs (H̄_norm ≈ 0.73) than in software tasks (H̄_norm ≈ 0.82). The pipeline decomposes the long-document-to-long-code problem into five stages: (1) hierarchical document partitioning with dual-level indexing, (2) a Planner Agent that constructs a pseudo-code skeleton and decomposes it into sub-tasks each mapped to specific document fragments, (3) parallel RTL Agents that perform constrained 'short-document, short-code' generation for each fragment, (4) a Merger Agent that integrates fragments with interface consistency using retrieved documentation, and (5) an iterative debugging loop where AST-based fault localization traces error signals to their drivers, the Retriever Agent fetches only the locally relevant spec fragments, and a Debugger Agent produces line-number-aware edit actions. This locality-driven decomposition reduces contextual overhead by 55–71% across agents and achieves a 45.0% functional pass rate on REALBENCH, a 23.4% absolute gain over the prior SOTA agent MAGE.

## Results

On REALBENCH, ChipV-RTL (Claude-3.7-Sonnet) achieves a 45.0% functional Pass@1 and 75.0% syntactic Pass@1, substantially outperforming the best agent baseline MAGE (21.6% functional) by 23.4 percentage points and the best standalone model Claude-3.7-Sonnet (19.6% functional) by 25.4 points. ChipV-RTL (DeepSeek-V3) also surpasses the Claude-based MAGE, reaching 35.0% functional pass rate. On the CVDP cid003 subset, ChipV-RTL achieves 61.50% functional pass rate, exceeding MAGE by 12.78 points.

## Baselines & Comparisons

ChipV-RTL (Claude) decisively outperforms both agent baselines: it achieves 45.0% functional pass rate vs. MAGE's 21.6% (+23.4 pp) and VerilogCoder's 20.0% (+25.0 pp) on REALBENCH, while also consuming roughly 3× fewer tokens than VerilogCoder. Against standalone LLMs, the gap is even wider — the strongest model baseline, Claude-3.7-Sonnet, reaches only 19.6% functional pass rate, and GPT-5 achieves 16.0%, both far below ChipV-RTL's 45.0%. Notably, ChipV-RTL (DeepSeek-V3) at 35.0% functional pass rate surpasses the Claude-based MAGE (21.6%), demonstrating that the framework's gains are not solely attributable to the backbone model. On the CVDP cid003 subset, ChipV-RTL achieves 61.50% functional pass rate, outperforming MAGE by 12.78 points and direct sampling by a similar margin, confirming generalization to shorter-context tasks. Domain-specific fine-tuned models (CodeV, CodeV-R1, DeepRTL2, VeriReason-3B) all perform poorly on IP-level tasks (≤7.1% functional), highlighting that task-specific training does not address the long-document, long-code challenges that ChipV-RTL's locality-aware decomposition targets.

## Relation to Prior Work

This paper extends the multi-agent RTL generation paradigm established by MAGE, VerilogCoder, and RTLSquad by introducing the information locality hypothesis as an organizing principle for IP-level design. While prior agent frameworks perform task decomposition and iterative debugging, they treat the specification as a monolithic context; ChipV-RTL instead leverages the modular structure of hardware design to decompose the problem into short-document-to-short-code sub-tasks with locality-aware retrieval. The AST-guided debugging mechanism builds on VerilogCoder's waveform tracing but adds a retrieval step that maps faulty signals back to specific specification fragments, closing the loop between code errors and their documentary sources.

## Why It Matters / Open Questions

The quantitative validation of information locality (via entropy analysis showing hardware specs are far more local than software specs) provides a principled justification for decomposition-based approaches in EDA, potentially guiding future work beyond Verilog generation. The PPA analysis demonstrating that LLM-generated RTL can match or slightly exceed golden implementations in area, delay, and power is encouraging for practical adoption, though the 45% pass rate on REALBENCH indicates the task remains substantially unsolved. Open questions include whether the locality hypothesis holds for non-modular or highly interdependent designs, how the framework scales to SoC-level hierarchies with hundreds of modules, and whether the approach transfers to other HDLs like VHDL or SystemVerilog.
