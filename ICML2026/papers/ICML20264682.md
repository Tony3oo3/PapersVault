## Problem

Small language models (SLMs) struggle in long-horizon interactive agent tasks because limited context budgets make it difficult to retain and reuse decision-relevant state across many steps. Existing working-memory methods rely on unstructured natural-language summarization, which can discard critical facts, introduce state drift, and compound errors under tight context constraints. The paper asks whether a training-free, structured working memory can make SLMs reliable for procedure-centric tasks without costly post-training or online LLM calls.

## Input / Output

The method takes a natural-language goal, streaming environment observations, and a pre-induced task-family schema (built once offline from five successful traces via GPT-5.1) as input. At each step, the SLM makes two single-turn calls: a state updater that emits typed JSON patch operations (SET, LIST_REMOVE, LIST_APPEND_UNIQUE) modifying only writable memory fields, and an executor that produces one environment action parsed against the environment grammar. The schema constrains which JSON paths are writable and which operators are permitted, so invalid patches are rejected deterministically by the controller rather than by the model.

## Method

LightWM organizes working memory into a task-level global memory and a subtask-level local memory, where local memory is instantiated from a schema-defined subtask interface with five typed fields (CORE, CONTEXT, ACTIONS, RULES, RETURN) and only CONTEXT and RETURN are writable online. The SLM alternates between a State Updater that produces rule-constrained patches to update the information state and an Executor that generates actions conditioned on the updated context and subtask-specific action templates. A one-time offline induction pipeline (using GPT-5.1 on five successful traces per task family) builds the reusable schema specifying the subtask sequence, per-subtask interfaces, pruned action grammars, and patch constraints, requiring no SLM parameter updates or online LLM calls. This goal-conditioned, schema-governed design keeps the decision context bounded and stable across steps, enabling Qwen3-4B to reach 0.910 success on ALFWorld valid_unseen versus below 0.320 for prompting and prior working-memory baselines.

## Results

On ALFWorld valid_unseen (145 tasks, 6 task families), LightWM achieves 0.910 success rate with Qwen3-4B under FP16 inference, substantially outperforming the strongest baseline MemGPT (0.317) by nearly 3×. Under FP8 quantization the same backbone still reaches 0.821, while all baselines remain below 0.300. On the stronger Gemini-2.5 Flash reference model, LightWM improves success from 0.786 (ReAct) to 0.945, and also surpasses MemGPT (0.821). The method also reduces average episode length from ~34–47 steps (baselines) to ~20 steps, with per-step token cost of 1,848 tokens versus 3,079 for MemGPT.

## Baselines & Comparisons

LightWM dominates all three baselines across every backbone tested. Against ReAct (Yao et al., 2023b), the gap is most extreme on small models: 0.910 vs. 0.062 on Qwen3-4B (FP16), a 14.7× improvement, reflecting that raw history accumulation quickly overwhelms SLM context budgets. Against HiAgent (Hu et al., 2025a), which compresses context at subgoal granularity via summarization, LightWM achieves 0.910 vs. 0.248 on Qwen3-4B (FP16) and 0.945 vs. 0.558 on Gemini-2.5 Flash, indicating that structured patch-based updates avoid the state drift and fact loss inherent in free-form summarization. Against MemGPT (Packer et al., 2024), which partitions context into a writable working buffer and a FIFO interaction buffer, LightWM still leads by a wide margin (0.910 vs. 0.317 on Qwen3-4B FP16; 0.945 vs. 0.821 on Gemini-2.5 Flash), suggesting that OS-style memory partitioning alone is insufficient without goal-conditioned structure. Notably, the advantage is largest on the smallest backbone (Qwen3-4B), where the structured, bounded local memory most directly compensates for weaker implicit state-reconstruction ability.

## Relation to Prior Work

This paper departs from the dominant working-memory paradigm for LLM agents (MemGPT, HiAgent), which relies on unstructured natural-language summarization to compress interaction history, by replacing free-form summaries with a schema-governed, goal-conditioned hierarchical memory updated via typed patch operations. It also contrasts with fine-tuning or distillation approaches that train small models to construct and use working memory, instead using a one-time offline LLM induction pipeline (GPT-5.1) to build reusable per-family schemas without any parameter updates. Conceptually, the design draws on POMDP information-state theory to argue that only a compact, goal-conditioned subset of history is needed for action selection, and on structured-state/program-as-policy work (Ichter et al., Liang et al.) to justify typed fields and guarded update rules as the memory substrate.

## Why It Matters / Open Questions

The training-free, schema-based approach offers a practical path to deploying capable agent systems on small (4B) models under tight context budgets, with a one-time offline cost that amortizes across all instances of a task family. However, the evaluation is confined to ALFWorld's structured, procedure-centric task families with a fixed linear subtask sequence and no explicit recovery or rollback mechanisms, leaving open whether the same schema-governed interface generalizes to open-ended environments with branching, uncertainty, or less stable task structure. A key open question is how to handle subtask misclassification or missed evidence without the rigid linear workflow, and whether the offline induction pipeline scales beyond a handful of task families without manual base-schema design.
