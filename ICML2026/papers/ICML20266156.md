## Problem

Current code evaluation is anchored to pass@k, which captures only functional correctness and ignores the non-functional constraints (coding style, documentation, error handling, library usage) that users routinely apply when selecting code in interactive 'vibe coding' workflows. This paper hypothesizes that instruction following is the missing, under-measured component of human preference in code generation, and that models achieving high leaderboard scores can still fail the vibe check in practice.

## Input / Output

The testbed takes a coding task from BigCodeBench or LiveCodeBench and augments it with 5 verifiable instructions selected by an LLM-based selector (Claude 4 Opus) from the 30-instruction VERICODE taxonomy, with parameters assigned per-task and validated by rule-based checks. Evaluation runs under two interaction protocols—single-turn generation (all instructions in one prompt) and multi-turn editing (instructions revealed one at a time across rounds)—and produces four signals: binary pass/fail per instruction via deterministic verifiers (Ruff linter rules, AST analysis, or regex), functional correctness as pass@1, functional regression rate relative to the base score, and task-level IF requiring all instructions to pass simultaneously.

## Method

The core contribution is VERICODE, a taxonomy of 30 verifiable code instructions organized into five categories (Coding Style, Logic & Code Patterns, Documentation, Error Handling, Library & API Constraints), each paired with a deterministic verifier that returns a binary score—27 of 30 are implemented via the Ruff Python linter, with the remainder using AST analysis or regex. The taxonomy is constructed through a multi-stage pipeline: sourcing 800+ candidate rules from Ruff, filtering for difficulty (removing instructions with >90% success rate on BigCodeBench-Hard), consolidating for scope and relevance, and expert review. SWE-IF augments BigCodeBench (1,140 instances) and LiveCodeBench (1,055 problems) with these instructions, creating Big-SWE-IF and Live-SWE-IF, and evaluates 31 LLMs across 10 model families. The key empirical finding is that a composite score of functional correctness and instruction following (with IF weighted at 40–70%) correlates best with LMArena human preference Elo ratings, and that IF emerges as the primary differentiator among advanced models on real-world programming tasks.

## Results

Under five verifiable instructions, even the strongest model (Claude 4 Opus) achieves only 46.75% task-level instruction following on Big-SWE-IF and 40.95% on Live-SWE-IF in single-turn generation, with GPT 5 reaching 48.51% and 50.14% in multi-turn editing. Adding five non-functional instructions causes an average functional regression of 5.85% (Big-SWE-IF) and 6.61% (Live-SWE-IF) in pass@1, with o4 mini and Kimi K2 exceeding 10% regression in more than half of test configurations on Live-SWE-IF. A composite score of 0.4·IF + 0.6·Func (Pearson) and 0.7·IF + 0.3·Func (Spearman) on Big-SWE-IF correlates best with LMArena coding Elo ratings, outperforming either metric alone.

## Baselines & Comparisons

This is a benchmark paper evaluating 31 LLMs across 10 model families rather than comparing a single method against baselines. The key comparative findings are: (1) Multi-turn editing consistently outperforms single-turn generation on instruction following by 3–4.5% on Big-SWE-IF and ~8% on Live-SWE-IF, but at the cost of higher functional regression (9.31% vs. 5.76% average on Big-SWE-IF under 5 instructions). (2) GPT 5 and Claude 4 Opus are the strongest on task-level IF, with GPT 5 leading in multi-turn (48.51% Big, 50.14% Live) and Claude 4 Opus leading in single-turn (46.75% Big, 35.17% Live). (3) On functional regression, Gemini 2.5 Flash and Claude 4 Opus show the least degradation on Big-SWE-IF (staying below 5% in most settings), while o4 mini and Kimi K2 suffer the worst regressions on Live-SWE-IF (exceeding 10–16%). (4) For human preference alignment, instruction following emerges as the primary differentiator among advanced models on real-world programming tasks (Spearman: pure IF correlates 0.1+ points higher than pure Func), while functional correctness dominates for algorithmic/contest problems.

## Relation to Prior Work

This paper extends the code evaluation lineage anchored in pass@k (HumanEval, BigCodeBench, LiveCodeBench) by introducing a verifiable, non-functional dimension grounded in industrial linters (Ruff) rather than synthetic constraints. It departs from prior code instruction-following work (CodeIF, NoFunEval) that relied on DiffBLEU or LLM-as-judge by pairing each instruction with a deterministic linter/AST verifier, enabling scalable and reproducible evaluation. The taxonomy construction draws on the general instruction-following literature (IFEval, FollowBench) but re-grounds it in software-engineering practice, and the human-preference correlation leverages LMArena's coding Elo ratings to connect measurable signals to real user behavior.

## Why It Matters / Open Questions

By demonstrating that a composite of functional correctness and instruction following correlates best with human preference—and that IF is the primary differentiator among top models—this work challenges the field's near-exclusive reliance on pass@k as both an evaluation metric and an RLVR reward signal. The SWE-IF testbed provides a concrete, extensible path for benchmarking and training models on non-functional code quality, with the 30-instruction taxonomy programmatically expandable to hundreds of constraints. Limitations include Python-only instantiation, LLM-based instruction selection (despite 100% human-validated spot-checks), and correlation evidence drawn from a single preference dataset (LMArena coding subset). Open questions include whether IF improves with model scale, whether the taxonomy generalizes to other languages, and whether multi-instruction compliance can be effectively targeted through training.
