## Problem

Existing LLM agent benchmarks either use functionally isolated tools (ToolBench, AnyToolBench), evaluate tool-calling via static AST matching without real execution (BFCL), or operate in small, precisely predefined sandboxes (τ-Bench). None systematically test agents in environments where tools are large-scale, stateful, interdependent, and subject to stochastic failures—the conditions that define the 'last mile' of commercial software automation. ComplexMCP fills this gap by providing a benchmark where agents must navigate 300+ interdependent MCP tools across 7 stateful sandboxes with seed-driven environmental noise.
![Teaser figure](../imgs/ICML20262636/cropped_page3_idx0.webp)

## Input / Output

The agent receives a natural language instruction (with no tool names or hints), a random seed σ that deterministically instantiates the environment from a synthetic knowledge base and governs execution-time perturbations (e.g., transient API failures), and tool descriptions either as a full ~30K-token system prompt or a RAG-retrieved subset. Evaluation is entirely rule-based: the final environment state (a nested dictionary) is diffed against a ground-truth target state across key-path trajectories, yielding a completion rate Rc (fraction of required changes correctly made) and a misbehaving rate Rb (fraction of unchanged states erroneously modified). A trajectory is correct only if Rc=1 and Rb=0, eliminating LLM-as-judge subjectivity.

## Method

ComplexMCP's architecture rests on three pillars. First, a seed-driven instantiation mechanism maps (σ, synthetic knowledge base) → initial state via a PRNG, ensuring that environment content (user profiles, permissions, inventory) varies across seeds while the underlying logic remains fixed, forcing agents to perceive state through active tool-use rather than hard-coded heuristics. Second, the ecosystem comprises 315 tools across 15 MCP servers—7 stateful sandboxes (LightOS, LightTalk, LightShop, LightWeather, LightFlight, LightStock, LightNews) maintaining persistent nested-dictionary state, plus 8 stateless servers—where tools exhibit prerequisite dependencies (e.g., resolving a UID before sending a message, or invoking acc_network before a latency-sensitive call). Third, evaluation compares env_old, env_gt, and env_new over key-path trajectories to compute T (total required changes), M (correctly modified), and Mb (unintended side effects), producing fine-grained Rc and Rb scores. The paper evaluates 16 models under full-context ReAct and two RAG variants (standard top-k retrieval and iterative retrieve_tools), using all-MiniLM-L6-v2 embeddings, and identifies three recurring failure modes: tool retrieval saturation, 'Clean-Slate' over-confidence (skipping environment verification), and strategic defeatism (rationalizing failure instead of retrying).

## Results

On ComplexMCP (47 tasks, 315 tools across 7 stateful sandboxes), the best-performing model Gemini-3-Flash achieves a 55.31% task success rate and 85.79% completion rate, still far below the human baseline of 93.61% success and 97.73% completion. GPT-5.1, despite its strong reasoning capabilities, achieves only 19.14% success due to a 'strategic defeatism' failure mode where it rationalizes errors rather than recovering. Under RAG-based tool retrieval, performance drops substantially: Iterative RAG reduces Gemini-3-Flash's success from 55.31% to 36.88%, and standard RAG (k=30) drops it to 13.47%, revealing that semantic retrieval cannot capture latent inter-tool dependencies.

## Baselines & Comparisons

Gemini-3-Flash is the clear leader among all evaluated LLMs at 55.31% success, outperforming Gemini-3-Pro (44.67%), GLM-4.7 (42.55%), and Claude-Opus-4 (41.84%) by 10–37 percentage points. Notably, GPT-5.1 (19.14%) and GPT-4o (14.89%) perform poorly despite strong general reasoning, with GPT-5.1's failure attributed to 'strategic defeatism'—it politely surrenders on transient errors rather than invoking recovery tools like acc_network. Among open-weight models, Llama-3.1-405B (26.94%) and Qwen-3-Max (31.20%) trail the top commercial models by 20–30 points, while the smallest model Llama-3.1-8B (8.51%) also exhibits the highest syntactic error rate (6.46 per task). The human baseline (93.61%) exceeds the best model by 38.3 points, with humans also showing far fewer misbehaving actions (0.81% vs. 4.39% for Gemini-3-Flash). Under RAG-based retrieval, all strategies degrade performance relative to full-context: Iterative RAG drops Gemini-3-Flash from 55.31% to 36.88%, and Claude-Opus-4 from 41.84% to 25.52%, confirming that inter-tool dependencies are poorly captured by semantic similarity retrieval.

## Relation to Prior Work

This paper builds on the Model Context Protocol (MCP) as its architectural foundation and extends the line of tool-use benchmarks (ToolBench, τ-Bench, MCPEval, MCP-Bench, LiveMCPBench) by simultaneously integrating large-scale toolsets (300+ tools), stateful sandboxes with explicit inter-tool dependencies, and seed-driven stochasticity—properties that prior benchmarks address in isolation at best. It departs from the ReAct-based evaluation paradigm used in most prior work by introducing a deterministic, rule-based state-diff evaluation that replaces LLM-as-judge scoring, and it contrasts full-context prompting against RAG-based tool retrieval to probe whether semantic similarity can capture latent prerequisite relationships. The seed-driven instantiation mechanism, which decouples environment logic from content via a synthetic knowledge base, is a novel reproducibility strategy not present in earlier interactive benchmarks like τ-Bench.

## Why It Matters / Open Questions

The benchmark exposes a substantial performance gap (best model at 55% vs. 94% human) and, more importantly, isolates three actionable failure modes—tool retrieval saturation, the 'Clean-Slate' over-confidence bias, and strategic defeatism in error recovery—that give the community concrete targets for improving agent robustness in enterprise and financial automation. The finding that even iterative RAG underperforms full-context for capturing inter-tool dependencies suggests that current retrieval-based scaling strategies are insufficient for interdependent workflows, pointing toward the need for dependency-aware planning. Key limitations include the small instruction set (47 tasks) and the single-seed-per-task design, which limits statistical power; scaling task diversity while preserving manual ground-truth annotation remains an open challenge for the benchmark's long-term utility.
