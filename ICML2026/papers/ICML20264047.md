## Problem

Existing generative image models produce static raster outputs that are fundamentally incompatible with scientific publishing requirements: they cannot support fine-grained, element-level editing, cannot produce the vector formats mandated by top venues like Nature and Science, and force full regeneration for even minor corrections. Code-based generation tools produce editable but visually simplistic figures lacking semantic richness and aesthetic quality. The paper addresses this gap by asking whether an agentic system can generate natively editable, publication-quality scientific illustrations that mimic the staged cognitive workflow of human expert designers.

## Input / Output

The system accepts a figure caption (V1 setting) or a caption combined with the corresponding method description text (V2 setting) extracted from scientific papers. It produces a native PowerPoint (.pptx) file whose internal OpenXML structure consists of discrete, individually manipulatable objects—shapes, text boxes, and smart connectors—rather than a flattened pixel matrix. This makes every element independently selectable, resizable, recolorable, and repositionable within PowerPoint, and the file can be exported to standard vector formats for journal submission. The backbone models are Gemini-3-Pro (for reasoning and code generation) and Gemini-3-Image-Pro (for blueprint and asset generation).

## Method

LiveFigure is a three-stage multi-agent pipeline that operationalizes a paradigm the authors term Cognition-Inspired Procedural Construction. Stage I (Visual Planning via Prior Induction) retrieves top-k reference schematics from a curated knowledge base of ICLR/NeurIPS/ICML figures using Qwen3-Embedding, then a VLM distills layout and composition priors to produce a visual blueprint and a grid-batch-generated asset library for complex domain-specific icons. Stage II (Procedural Figure Generation) translates the blueprint into executable python-pptx code by constraining the model to a library of pre-debugged, high-level drawing skills (e.g., add_container, add_connector) and injecting accumulated debugging failures as negative prompt constraints, with a self-correcting execution loop that feeds error stack traces back for iterative repair. Stage III (Targeted Refinement via Visual Diagnostics) closes the loop with an iterative observe-diagnose-refine cycle: a VLM critic renders the current script, identifies specific visual defects (occlusion, misalignment, inconsistent styling), and the agent applies incremental code-level corrections rather than full regeneration. The key architectural insight is that by driving figure construction through structured code over a standardized skill API rather than end-to-end pixel synthesis, editability is inherent to the output format, and the skill abstraction decouples high-level layout reasoning from low-level rendering details, dramatically improving both code executability (83.5% vs. 31% for vanilla LLM) and visual quality.

## Results

On the 300-instance test set (ICLR/NeurIPS/ICML 2024 schematics), LiveFigure achieves 80% publication-readiness at a median edit distance of 8 steps (50% adoption) and 17 steps (80% adoption), far surpassing Nano Banana (24% adoption) and GPT-Image-1.5 (15% adoption). Under the V2 input setting (caption + method description), LiveFigure attains an average VLM score of 7.89/10 across nine metrics, with the highest Content Fidelity scores (Accuracy 8.29, Completeness 8.16) among all methods. In double-blind human preference tests, LiveFigure secures a 69% win rate against Nano Banana and 60% against GPT-Image-1.5, with all 95% confidence intervals exceeding 50%.

## Baselines & Comparisons

Against Nano Banana (Gemini-3-Pro-Image), LiveFigure wins decisively on editability (80% vs. 24% publication-readiness) and human preference (69% win rate), and leads on Content Fidelity (Accuracy 8.29 vs. 7.61; Completeness 8.16 vs. 7.71), though Nano Banana marginally edges on Aesthetic Quality (7.94 vs. 7.87). Against GPT-Image-1.5, the gap is even wider: LiveFigure achieves 80% vs. 15% adoption, a 60% human-preference win rate, and substantially higher Content Fidelity (Accuracy 8.29 vs. 7.06; Completeness 8.16 vs. 7.12), while GPT-Image-1.5 slightly leads on Aesthetic Quality (7.91 vs. 7.87). The core trade-off is that raster generators produce marginally more aesthetically polished images, but LiveFigure's natively editable PPTX output and superior structural/logical fidelity make it the only method that meets publication submission requirements without full regeneration.

## Relation to Prior Work

This paper departs from the dominant pixel-based generative paradigm (Nano Banana, GPT-Image-1.5, Imagen) and from prior code-based figure tools (StarVector, MatPlotAgent, TikZ/Graphviz) by reframing scientific illustration as a procedural code-generation problem driven by VLM agents. It synthesizes ideas from retrieval-augmented generation (visual prior induction from a curated knowledge base of top-venue schematics), skill-augmented code synthesis (a curated python-pptx API library), and iterative visual refinement (VLM-as-critic loops), but no single prior work combines these into an end-to-end editable-figure pipeline. The closest conceptual ancestor is the 'AI for Science' agent literature (ChemCrow, Data Interpreter, AlphaEvolve), which automates research sub-tasks but leaves visual figure creation to manual labor; LiveFigure extends this agent paradigm into the visual domain with a deliberate choice of PowerPoint/OpenXML as the output substrate rather than SVG or PDF.

## Why It Matters / Open Questions

The paper addresses a concrete, high-frequency pain point in scientific publishing: top venues mandate editable vector figures, yet all current generative models produce non-editable raster outputs. The 80% publication-readiness at 17 edits versus 24% for the strongest raster baseline is a large practical gap that, if reproducible, could meaningfully reduce the hours researchers spend on figure preparation. Key open questions include whether the approach generalizes to non-AI domains (the biology case study is encouraging but limited), how to handle the observed tendency toward visual over-complication (the authors propose RLHF-based alignment), and whether venue-specific stylistic conventions (Nature vs. NeurIPS aesthetics) can be captured via fine-grained adapters. The narrow scope (300 test instances, 7 evaluators) and reliance on a single backbone model (Gemini-3-Pro) leave robustness questions open.
