## Problem

MeZO enables LLM fine-tuning with only forward passes and P memory, but its SGD-style updates ignore loss-landscape curvature, causing slow convergence. Adding Adam-style first- and second-moment preconditioners would triple memory to 3P, negating MeZO's core advantage. The paper asks whether Adam-style adaptive updates can be achieved in a zeroth-order setting without persistently storing the moments.

## Input / Output

The method consumes model parameters, a mini-batch of training examples, and a scalar loss function, requiring exactly 2 forward passes per step (identical to MeZO). It outputs updated model parameters in-place. The only persistent memory beyond the model weights is a small cache of PRNG seeds and projection scalars (negligible, O(1) per step) plus a temporary block-sized buffer (δP, where δ ≈ 2/b for b parameter blocks), yielding a total footprint of (1+δ)P.

## Method

AdaMeZO recovers Adam-style preconditioned updates without storing full moment vectors by combining two mechanisms. First, it uses truncated moments: the EMA recursion is unrolled into a finite sum over the last h gradients, exploiting the exponential decay of β1^τ to discard older terms (e.g., at β1=0.9, the 10th-past gradient contributes only ~4%). Second, it performs block-wise updates using PRNG state caching: instead of caching only seeds (which forces regeneration from the start of the random stream), AdaMeZO saves the internal PRNG state after each parameter block's random direction is generated, allowing it to resume the stream at the correct offset for subsequent blocks. For each block, it regenerates the h past random directions, computes local truncated first and second moments, and applies the preconditioned update w ← w − ηβv·m/√(v+ε). A warm-up phase of T_w steps uses plain MeZO updates before moment-based updates begin. The convergence rate O(1/√T) + O(μ²) is proven under standard non-convex assumptions, recovering the preconditioned MeZO bound.

## Results

On OPT-1.3B across 11 NLP tasks, AdaMeZO achieves an average accuracy of 63.1% (65.9% excluding SQuAD/DROP), surpassing MeZO (61.4%/64.4%) by 1.7% and HiZOO (61.7%/64.4%) by 1.5%. On LLaMA3-3B, the gap widens to 2.7% over MeZO (64.1% vs 61.4% average). Critically, AdaMeZO reaches the same terminal loss as MeZO with up to 70% fewer forward passes, while requiring only 1.07× the memory of MeZO (vs. 4.40× for Adam and 1.49× for HiZOO).

## Baselines & Comparisons

Against MeZO (the primary baseline), AdaMeZO wins on 10 of 11 tasks on OPT-1.3B, with the largest gains on CB (+4.1%), SQuAD (+2.8%), and WSC (+2.4%), yielding a 1.7% average improvement. On LLaMA3-3B, the advantage grows to 2.7% average, with standout gains on SST-2 (+8.1%), MultiRC (+4.3%), and COPA (+4.0%). Against HiZOO, AdaMeZO achieves a 1.5% average lead on OPT-1.3B and a 7.0% lead on LLaMA3-3B (64.1% vs 56.1%), where HiZOO's SQuAD/DROP scores collapse (18.5/6.1 vs 80.4/28.1). On OPT-13B, HiZOO encounters out-of-memory errors on BoolQ and DROP, while AdaMeZO completes all tasks. In terms of memory, AdaMeZO uses only 1.07× MeZO's footprint (5410 MB vs 5016 MB on OPT-1.3B), compared to 1.49× for HiZOO and 4.40× for Adam, preserving MeZO's core memory advantage while adding Adam-style preconditioning.

## Relation to Prior Work

AdaMeZO extends MeZO's in-place, PRNG-based zeroth-order fine-tuning by incorporating Adam-style first- and second-moment preconditioning, which prior adaptive ZO optimizers (HiZOO, HELENE, ZO-AdaMU) achieved only by storing full moment vectors in memory at 2P or 3P cost. The key departure is a two-part mechanism: truncated EMA horizons that discard outdated gradients, and fine-grained PRNG state caching (rather than seed caching) that enables block-wise regeneration of historical random directions without re-deriving the full stream. This positions AdaMeZO as the first ZO optimizer to recover Adam-style preconditioning at near-zero additional memory (1+δ)P, bridging the gap between MeZO's memory efficiency and Adam's convergence quality.

## Why It Matters / Open Questions

The practical impact is significant for resource-constrained LLM fine-tuning: AdaMeZO achieves up to 70% fewer forward passes than MeZO to reach equivalent loss, while maintaining MeZO's ~1× memory footprint (vs. 2×–4× for HiZOO/Adam), making adaptive optimization viable on devices that previously could only run SGD-style ZO updates. However, the second-moment estimates remain inherently noisy due to the zeroth-order gradient estimator and the need for a smaller β₂ to keep truncated tails negligible, and the per-step runtime is ~50% longer than MeZO due to gradient regeneration. Open questions include whether more accurate second-moment approximations (e.g., leveraging the block-diagonal Hessian structure identified by Zhang et al., 2024a) can further close the gap to first-order Adam, and whether the gradient-drift term captured only via a big-O constant can be made explicit for tighter convergence guarantees.
