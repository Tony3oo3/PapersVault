## Problem

Existing Auto-MAS methods suffer from a fundamental trade-off: graph-based paradigms (DAGs) offer structural clarity but are rigid, restricting agents to predefined role pools and unable to express dynamic control flows like conditional branching and loops; imperative code-based paradigms achieve Turing-complete expressiveness but tightly entangle topology, control flow, and node implementation in a single procedural stream, making independent optimization and from-scratch generation infeasible. No prior approach enables a Meta-Agent to autonomously synthesize task-adaptive architectures from scratch with both structural verifiability and full expressive power.

## Input / Output

The Meta-Agent receives a natural-language user query and a list of available tool descriptions as input. It produces a complete, directly executable LangGraph Python specification that is internally structured into two orthogonal layers: a topology definition (typed Global State schema, vertex set with static role/tool/reasoning-pattern tuples, and edge set with guard functions for conditional routing) and per-node implementation code (system prompts, tool bindings, and operationalized reasoning logic). Executing the compiled graph yields the final answer to the query, with all inter-agent state passing governed by the typed schema rather than ad-hoc variable passing.

## Method

MAS-Architect introduces a Declarative MAS Paradigm rooted in Separation of Concerns, decomposing MAS design into a Topology Layer (a declarative graph specification declaring nodes, conditional edges with guard functions, and a typed State Schema) and an Implementation Layer (per-agent executable code specifying role, tools, and reasoning pattern such as CoT, ReAct, or Reflexion). The two layers are decoupled via the State Schema interface, enabling the Meta-Agent to independently search collaboration structures and synthesize node specifications on demand. Training follows a Distill-then-Explore strategy: Stage 1 performs SFT on a corpus of teacher-generated specifications filtered by execution-based rejection sampling (only retaining instances where the compiled MAS produces the correct answer); Stage 2 applies RL (SAPO with GRPO advantage estimation) using a hierarchical reward that assigns zero to invalid or 'shortcut-learning' solutions, 0.1 to valid-but-incorrect ones, and 1.0 to correct answers. The key insight is that the declarative representation provides explicit structural inductive bias—topology is symbolized rather than buried in procedural code—making RL policy updates semantically meaningful at the architecture level and enabling the model to emerge with novel collaboration patterns (e.g., parallelized reasoning-exploration streams, hierarchical dual-loop refinement) that surpass the teacher's priors.

## Results

MAS-Architect achieves an average accuracy of 78.7% across five benchmarks (GSM8K, GSM-Hard, MATH, MMLU, GPQA) when driven by Qwen3-4B, surpassing the vanilla baseline by +6.4% and the second-best method (MAS-GPT) by +5.8%. On GSM8K, it reaches 94.4% accuracy with only 2,533 tokens per query, outperforming MAS-GPT by 2.9% while reducing token consumption by 23.8%. On held-out benchmarks (MATH, GPQA, GSM-Hard), the method gains +7.4%, +8.7%, and +10.2% over vanilla respectively, demonstrating strong generalization to unseen tasks.

## Baselines & Comparisons

MAS-Architect outperforms all seven baselines across the board. Against the closest competitor MAS-GPT (Ye et al., 2025), it gains +5.8% average accuracy (78.7 vs. 72.9) with the same Qwen3-4B driving model, and +2.1% (73.3 vs. 71.2) with GPT-4o-mini, while also reducing total token consumption by 8.8%–23.8% across benchmarks. Compared to DyLAN (Liu et al., 2023), the improvement is +3.0% average (73.3 vs. 70.3), with particularly large gains on GSM-Hard (+5.5%) and GPQA (+3.2%). GPTSwarm (Zhuge et al., 2024) trails by +6.4% average, reflecting the limitations of fixed role-pool optimization. Among single-agent baselines, CoT (Wei et al., 2022) is the strongest at 75.7% average, still 3.0% below MAS-Architect; LLM-Debate (Du et al., 2023) and Self-Refine (Madaan et al., 2023) lag further behind at 69.7% and 65.8% respectively. AgentVerse (Chen et al., 2023) achieves 67.1%, a 6.2% gap. Notably, on the held-out GPQA benchmark, MAS-Architect (63.8%) substantially exceeds all baselines, with the nearest being MAS-GPT at 63.6%.

## Relation to Prior Work

This paper positions itself against two established Auto-MAS paradigms: graph-based methods (GPTSwarm, AFlow, G-Designer) that instantiate MAS as DAGs over predefined role pools, and imperative code-generation methods (MAS-GPT, DyLAN) that treat MAS construction as a single procedural code stream. Its core departure is the Declarative MAS Paradigm, which applies Dijkstra's Separation of Concerns principle to decouple topology planning from node implementation via a typed State Schema interface, enabling independent optimization of each layer. The Distill-then-Explore training strategy (SFT on execution-validated teacher outputs followed by RLVR with SAPO/GRPO) builds on standard LLM training pipelines but exploits the structured inductive bias of the declarative representation to make policy exploration more efficient than in unstructured imperative code spaces.

## Why It Matters / Open Questions

The framework establishes a concrete efficiency-performance Pareto frontier (94.4% accuracy at 2,533 tokens/query on GSM8K) that is practically significant for deployment-cost-sensitive settings, and the cross-model generalizability across Qwen3-4B through Llama-3.3-70B suggests the approach is not tied to a single model family. The autonomous emergence of non-trivial topological patterns (parallelized reasoning-exploration streams, hierarchical dual-loop refinement) provides evidence that the declarative space is rich enough for genuine architectural reasoning rather than template filling. Open questions include whether the paradigm scales to longer-horizon or open-ended tasks beyond multiple-choice and arithmetic benchmarks, how the approach behaves when the driving model is substantially weaker than the Meta-Agent, and whether the LangGraph-specific implementation generalizes to other orchestration frameworks.
