## Problem

As AI agents grow more capable at reading, writing, and executing code, there is no systematic evaluation of their ability to detect, patch, and exploit smart contract vulnerabilities in realistic, end-to-end settings. Existing cybersecurity benchmarks target traditional CVEs or narrow subtasks in simplified environments, leaving the full vulnerability lifecycle on blockchains—where exploits are immediate and irreversible—unmeasured despite over $100B in assets held in open-source smart contracts.

## Input / Output

In DETECT mode, the agent receives a full audit repository (Solidity source, scope file list, known issues, and sponsor hints) inside an isolated Docker container with no internet access, and must produce a markdown audit report scored by a model-based judge against the ground-truth Code4rena report. In EXPLOIT mode, the agent receives a JSON-RPC endpoint to a live local Anvil chain, a funded private key, and contract addresses, and must craft and send signed transactions; grading replays those transactions in a separate container and checks post-exploit token balances and emitted events. PATCH mode takes the same repository plus the existing test suite and grades the agent's code edits by verifying original tests still pass while unseen exploit tests now fail.

## Method

EVMBENCH curates 117 high-severity, fund-draining vulnerabilities from 40 Code4rena audits and instantiates three evaluation modes with fully programmatic grading. The key infrastructure contribution is a Rust-based re-execution framework (ploit) that spins up a local Anvil chain, deploys vulnerable contracts via Foundry scripts, records the agent's transaction sequence, and replays it in an isolated grading container to compute per-vulnerability success from on-chain state. A companion proxy (veto) sits between the agent and the chain, rejecting privileged RPC methods (e.g., anvil_setBalance, anvil_impersonateAccount) to prevent state-manipulation cheating while preserving a realistic JSON-RPC attack surface. The agent runs in a sandboxed Ubuntu 24.04 container with Foundry pre-installed and web access disabled; the grader runs in a separate container the agent cannot reach. The paper evaluates seven frontier agents (GPT-5.3-Codex, Claude Opus 4.6, Gemini 3 Pro, GPT-5.2, GPT-5, Claude Opus 4.5, o3) across all three modes, including hint-level ablations and a contamination analysis comparing pre- and post-knowledge-cutoff performance.

## Results

On EVMBENCH, no agent achieves reliable autonomous auditing across all three modes. GPT-5.3-Codex (high reasoning, via Codex CLI) leads on PATCH (37.9%) and EXPLOIT (59.4%), while Claude Opus 4.6 (via Claude Code) leads on DETECT (45.9%). GPT-5.2 at xhigh reasoning scores 40.7% on DETECT, 39.4% on PATCH, and 65.2% on EXPLOIT. Even the best agents fall far short of full vulnerability coverage, with the maximum attainable DETECT award of $218,434 reduced to at most ~$37,825 (Claude Opus 4.6).

## Baselines & Comparisons

EVMBENCH is a benchmark rather than a method paper, so the comparison is across frontier agents on a shared task suite. GPT-5.3-Codex (via Codex CLI) outperforms all other agents on PATCH (37.9% vs. 39.4% for GPT-5.2 xhigh) and is competitive on EXPLOIT (59.4% vs. 65.2% for GPT-5.2 xhigh), while Claude Opus 4.6 leads DETECT at 45.9%, ahead of GPT-5.2 xhigh (40.7%) and Claude Opus 4.5 (36.2%). Scaffold choice matters: GPT-5.2 scores 34.1% on PATCH via OpenCode but 39.4% via Codex CLI, a ~5 pp gain from the same underlying model. All agents score below 50% on every mode, and the gap between best and worst is large (e.g., EXPLOIT ranges from 18.8% for o3 to 65.2% for GPT-5.2 xhigh), indicating that no current agent can reliably perform end-to-end smart contract security work.

## Relation to Prior Work

EVMBENCH extends the Detect/Exploit/Patch evaluation framework established by BountyBench (Zhang et al., 2025a) from general cybersecurity to the smart contract domain, adding blockchain-specific attributes such as on-chain state transitions, funded attacker wallets, and EVM-native execution. It departs from SCONE-Bench (Xiao et al., 2025) by deploying contracts on a fresh local Anvil chain rather than a forked mainnet, and by evaluating all three modes (not just exploit). The Rust-based re-execution framework (ploit/veto) for replaying agent transactions against a guarded JSON-RPC endpoint is a novel infrastructure contribution not present in prior cybersecurity benchmarks like CyberGym or CVE-Bench, which rely on static code or web application environments.

## Why It Matters / Open Questions

With over $100B in smart contracts and $300B in stablecoins at stake, the finding that frontier agents already achieve 71% end-to-end exploit success against live blockchain instances is a concrete capability signal with immediate security implications. The hint experiments reveal that vulnerability discovery in large codebases—not exploitation or patching—is the current bottleneck, suggesting that security infrastructure should prioritize scalable discovery and triage as agents improve at navigation. Key open questions include extending to cross-chain protocols, MEV/mempool reasoning, protocol-level (geth/reth) bugs, and ZK circuit vulnerabilities, none of which EVMBENCH currently covers. The limited task count (44 patch, 23 exploit) and inability to credit novel findings in DETECT mode constrain the benchmark's coverage of the full vulnerability space.
