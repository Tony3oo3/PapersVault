## Problem

Existing LLM agent benchmarks collapse complex bioinformatics workflows into simplified question-answering or code-generation tasks, failing to capture the multi-step tool orchestration, heterogeneous file handling, and subfield-specific reasoning that real pipelines demand. Additionally, bioinformatics often operates on sensitive patient or proprietary data that cannot be routed to third-party model providers, creating a need for reliable locally deployable agents. The paper asks whether frontier and open-weight LLM agents can execute end-to-end bioinformatics pipelines reliably, and how their behavior degrades under controlled perturbations.

## Input / Output

Each task provides a natural-language prompt specifying the goal and expected output format, paired with biological input files (FASTQ, FASTA, VCF, .mtx) and reference data (genomes, taxonomic databases, gene annotations) that are staged in a sandboxed directory. The agent produces intermediate artifacts in stage-scoped subdirectories (e.g., outputs/0_trimming/, outputs/1_alignment/) and a final CSV or TSV result file. The LLM grader returns structured metrics: steps_completed, steps_to_completion, final_result_reached (binary), results_match (task-specific correctness flag), and F1 score (for the GIAB task); robustness is further quantified via Jaccard index on categorical IDs and Pearson correlation on numerical values across four trials per task.

## Method

BioAgent Bench comprises 10 manually curated end-to-end bioinformatics tasks (bulk/single-cell RNA-seq, variant calling, metagenomics, viral metagenomics, comparative genomics, experimental evolution, transcript quantification) with reference implementations in Python, R, or bash, constrained to <4 h runtime and ≤48 GB RAM to enable scalable benchmarking. Agents (frontier closed-weight and open-weight models) are evaluated in three harnesses—Claude Code, Codex CLI, and OpenCode—using a shared system prompt that enforces mamba environment management, stage-scoped output directories, and absolute file paths. An LLM-based grader (GPT-5.1) scores each trial against a rubric that prioritizes evidence of pipeline completion over numerical accuracy, accommodating multiple valid solution paths (e.g., GATK vs. DeepVariant for variant calling). Robustness is probed through three controlled perturbations: synthetic corruption of input files (e.g., 90% bases replaced by N), injection of decoy files from unrelated organisms, and prompt bloat (800–1900 words of topically related but non-essential text prepended to the task prompt). The design deliberately mirrors software-engineering benchmarks (verifiable pass/fail outputs, concrete artifacts) rather than open-ended biology analysis, to support downstream use cases such as reinforcement learning, distillation, and harness optimization.

## Results

Across ten bioinformatics pipeline tasks, frontier closed-weight models achieve high completion rates: Claude Opus 4.5 reaches 100%, while Gemini 3 Pro (96.57%), GPT-5.2 (92.50%), and Claude Sonnet 4.5 (92.50%) all exceed 90% in the Codex CLI harness. The best open-weight model, GLM-4.7, reaches 82.50% in Codex CLI, with other open-weight models (Kimi K2, Devstral) ranging from 47.92% to 65.67%. Robustness analysis reveals considerable run-to-run variability (mean Jaccard overlap 0.43, Pearson correlation 0.73), and prompt bloat reduces completion by 28% on average, with corruption detected in only 7/10 tasks.

## Baselines & Comparisons

The paper evaluates three open-weight models (GLM-4.7, Kimi K2, Devstral) against frontier closed-weight models (Claude Opus 4.5, Gemini 3 Pro, GPT-5.2, Claude Sonnet 4.5) across three agent harnesses. GLM-4.7 is the strongest open-weight model at 82.50% in Codex CLI, trailing Claude Opus 4.5 (100%) by 17.5 percentage points and Gemini 3 Pro (96.57%) by 14.07 points. Kimi K2 achieves 65.67% in Codex CLI but improves to 80.50% in OpenCode, showing harness sensitivity. Devstral-2512 performs worst among open-weight models at 47.92% in Codex CLI, though it recovers to 65.00% in OpenCode. Notably, harness choice can shift open-weight model rankings: Kimi K2 outperforms GLM-4.7 in OpenCode (80.50% vs. 75.00%) but underperforms in Codex CLI (65.67% vs. 82.50%), highlighting that agentic performance is a joint property of model and scaffold rather than model alone.

## Relation to Prior Work

This paper extends the agent-evaluation paradigm established by SWE-bench and general tool-use benchmarks (AgentBench, ToolBench) into the bioinformatics domain, where prior biomedical benchmarks (BixBench, BioML-bench, LAB-Bench) focus on data analysis, multiple-choice reasoning, or ML pipeline construction rather than end-to-end tool-orchestration of canonical bioinformatics workflows. The key departure is the introduction of controlled-perturbation robustness testing (corrupted inputs, decoy files, prompt bloat) as a first-class evaluation dimension, which no prior agent benchmark systematically incorporates. The LLM-based grading approach is motivated by the multiplicity of valid solution paths in bioinformatics (e.g., GATK vs. DeepVariant for variant calling), distinguishing it from the deterministic pass/fail criteria typical of software-engineering benchmarks.

## Why It Matters / Open Questions

The central finding—that frontier agents achieve near-perfect pipeline completion yet exhibit brittle step-level reasoning under modest perturbations (e.g., −100% completion under prompt bloat, failure to detect corrupted inputs in 3/10 tasks)—challenges the assumption that high-level pipeline construction implies reliable execution, with direct implications for clinical and privacy-sensitive deployments. The significant open-weight gap (65–82.5% vs. 90–100%) is practically important for institutions that cannot route sensitive patient data to external model providers. Key limitations include the small task set (10 tasks), single-trial perturbation testing, and resource constraints (<4 h, ≤48 GB RAM) that exclude large-organism workflows, leaving open whether the robustness findings generalize to more complex, real-world pipelines.
