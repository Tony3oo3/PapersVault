## Problem

Current memory-augmented LLM agents rely on a static 'retrieve-then-reason' paradigm where retrieval is a one-shot, query-conditioned operation that cannot adapt to intermediate evidence discovered during inference. This passive retrieval fails on multi-hop and temporally grounded queries because it cannot infer new retrieval cues (e.g., a temporal anchor like 'July') or prune irrelevant branches based on accumulated context, leading to noise accumulation and missed evidence that is structurally disconnected from the query in the memory graph.
![Teaser figure](../imgs/ICML20261877/cropped_page0_idx0.webp)

## Input / Output

At memory construction time, raw multi-session dialogue is segmented into episodic units, from which an LLM extracts fine-grained cues (entities, attributes, temporal markers), associative tags (short relational summaries), and semantic facts, populating a heterogeneous Cue-Tag-Content graph with episodic, semantic, and topic-abstraction layers. At query time, the agent takes a natural-language question and iteratively traverses this graph using a toolkit of typed mapping operators (e.g., query_tag_events, query_conversation_time, query_personal_aspect), operating in Navigate mode to accumulate evidence and Answer mode to produce a final response with supporting evidence citations and a confidence score.

## Method

MRAgent organizes memory as a Cue-Tag-Content heterogeneous graph where associative tags mediate between fine-grained cues and content nodes, enabling a two-stage retrieval that first selects relevant tags before accessing expensive episodic content. The active reconstruction loop maintains an explicit state (active element set Z and accumulated evidence H), and at each step the LLM selects traversal actions from a compositional action space (forward: Cue→Tag, (Cue,Tag)→Content; reverse: Content→(Cue,Tag)), executes controlled graph traversal to generate candidates, then routes and prunes via LLM evaluation before updating the state. This integrates reasoning directly into memory access, allowing the agent to infer new cues from intermediate findings and redirect its search trajectory. The paper further proves (Theorem 4.1) that active retrieval policies are strictly more expressive than passive ones via a binary-tree needle-in-a-haystack separation, and demonstrates up to 23% improvement over baselines on LoCoMo and LongMemEval while reducing token consumption to 118k versus 632k for A-Mem.

## Results

On LOCOMO, MRAgent achieves 84.21% LLM-Judge (J) score under the Gemini backbone, a 23.3% relative improvement over the strongest baseline Mem0 (68.31%), and 88.32% under the Claude backbone, outperforming the best baseline LangMem (78.61%) by 12.4%. On LONGMEMEVAL, MRAgent reaches 72.95% overall J score, a 32% relative gain over the best baseline MemoryOS (54.92%). MRAgent also substantially reduces computational cost, consuming only 118k tokens per sample versus 632k for A-Mem and 3,268k for LangMem, while maintaining competitive runtime (586s vs. 1,122s for A-Mem).

## Baselines & Comparisons

MRAgent outperforms all five baselines across both benchmarks and both LLM backbones. On LOCOMO (Gemini), the closest competitor is Mem0 at 68.31% J, which MRAgent surpasses by 15.9 points; MemoryOS (63.35%), LangMem (62.86%), RAG (61.30%), and A-Mem (55.97%) trail further behind. Under the Claude backbone, LangMem is the strongest baseline at 78.61% J, still 9.7 points below MRAgent's 88.32%, while Mem0 (69.02%) and A-Mem (68.45%) lag by roughly 20 points. On LONGMEMEVAL, MRAgent (72.95%) leads the best baseline MemoryOS (54.92%) by 18 points, with RAG (54.65%), LangMem (53.77%), Mem0 (53.01%), and A-Mem (52.98%) clustered within ~2 points of each other. Notably, MRAgent's advantage is most pronounced on multi-hop and temporal question types (e.g., 90.19% vs. 75.88% for Mem0 on multi-hop under Claude), confirming that active reconstruction is particularly beneficial for queries requiring compositional or long-range evidence integration.

## Relation to Prior Work

This paper departs from the dominant 'retrieve-then-reason' paradigm in memory-augmented LLM agents, where retrieval is a fixed, one-shot operation (top-k similarity or predefined N-hop graph expansion) decoupled from the reasoning process. It draws on cognitive neuroscience's view of memory as active, associative reconstruction (Rugg & Renoult, 2025; Frankland & Josselyn, 2019) to reframe memory access as a multi-step, stateful process in which LLM reasoning is integrated directly into traversal. Structurally, it extends graph-based memory systems (A-Mem, Zep, LiCoMemory) by introducing the Cue-Tag-Content graph with associative tags as explicit intermediates that enable guided, pruned exploration rather than exhaustive neighbor expansion. Unlike agentic RAG methods (Search-o1, Search-R1) that retrieve from external corpora to fill factual gaps, MRAgent reconstructs over the agent's own persistent interaction history.

## Why It Matters / Open Questions

The 23% accuracy gain over the strongest baseline combined with a 5–20× reduction in token consumption (118k vs. 632k for A-Mem) makes active reconstruction a practically compelling alternative to passive retrieval for long-horizon agent deployments. The theoretical result (active retrieval is strictly more expressive than passive) provides formal justification for the paradigm shift, though the separating construction (binary-tree needle-in-a-haystack) is a standard technique. Key limitations remain: the static memory construction does not support updating, consolidation, or forgetting, so the graph grows monotonically in long-lived settings, and reconstruction latency scales with exploration depth. Open questions include adaptive memory maintenance, robustness to noisy LLM-based tag extraction, and whether the approach generalizes beyond conversational memory to other long-horizon agent tasks.
