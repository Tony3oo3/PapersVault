## Problem

Agent evaluation is fragmented because benchmarks and agents expose incompatible interfaces, forcing N×M bespoke integrations and creating test-production mismatch. No open, agent-agnostic assessment interface exists that allows any agent to be evaluated on any benchmark without custom harnesses, limiting fair comparison, openness, and reproducibility across diverse agent architectures.

## Input / Output

The system consumes agents either as blueprints (Git repositories or Docker images) or as live A2A endpoint URLs, along with dynamically specified MCP tool configurations delivered at runtime by the judge agent. Task instructions arrive as self-contained A2A messages that must be fully interpretable without prior knowledge of the agent's internals. Outputs are per-agent evaluation scores, structured performance reports in a requester-specified format, and optionally aggregated rankings on a leaderboard, with results displayed locally, on a platform, or as CI artifacts depending on the operation mode.

## Method

The paper proposes Agentified Agent Assessment (AAA), a paradigm where the benchmark itself is an agent (the judge agent) that communicates with subject agents exclusively through the A2A protocol for task management and MCP for tool access, reducing integration cost from N×M to N+M protocol-level connections. The judge agent owns the full evaluation session—retrieving data, preparing MCP environments, distributing self-contained task instructions, monitoring execution, and scoring—enabling adaptive assessment where tasks can be generated on the fly, skipped, or made harder based on observed performance. AgentBeats instantiates AAA with five operation modes (Local, Remote, Hosted, Proxy, CI) that map the three AAA roles (delegator, judge agent, subject agent) to different deployment topologies, from a single developer's machine to centralized platforms to CI pipelines, while maintaining the same three-stage lifecycle of agent construction, registration, and assessment execution. The key design constraint is that benchmarks make no assumptions about agent internals beyond A2A/MCP compatibility, and all task context is delivered in-band through A2A messages, ensuring complete separation between benchmark and agent codebases.

## Results

This is a position paper with no quantitative experimental results. The central architectural claim is that AAA reduces the integration cost from N×M bespoke agent-benchmark combinations to N+M protocol-level integrations (Figure 1), by requiring only A2A and MCP compatibility on both sides. AgentBeats provides five operation modes (Local, Remote, Hosted, Proxy, CI) that cover the full spectrum from private on-prem development to public, auditable, CI-driven assessments, with no changes required to agent implementations when switching modes.

## Baselines & Comparisons

The paper does not run empirical comparisons but discusses four alternative approaches in Section 6. NeMo (NVIDIA) takes a brute-force harness-expansion approach, providing dozens of task-specific harnesses in a single repository; AAA avoids this by requiring only protocol-level (A2A/MCP) compatibility rather than per-task integration. Harbor enforces a terminal-based interaction interface with checking scripts, which is well-suited for terminal tasks but less appropriate for UI-centric scenarios like browser interaction where A2A's multimodal message exchange is more natural. HAL and Exgentic introduce entirely new evaluation-specific standards; the paper argues these risk test-production mismatch since their interfaces are designed for evaluation rather than production use, whereas A2A is already a production-grade agent communication protocol. The paper positions AAA as complementary to CUBE (which standardizes benchmark environment packaging) rather than competing with it, noting the two are naturally composable.

## Relation to Prior Work

This paper does not build on a specific prior evaluation method but rather repurposes two already-adopted agent communication protocols—A2A for task management and MCP for tool access—as the universal interface between benchmarks and agents. It explicitly positions itself against brute-force harness expansion (NeMo), terminal-based standardization (Harbor), and new evaluation-specific interfaces (HAL, Exgentic), arguing that none of these solve the N×M integration problem as cleanly as reusing production agent protocols. The conceptual lineage is closest to CUBE, which standardizes benchmark environment packaging, but AAA operates at a higher level by making the benchmark itself an agent that communicates via A2A, making the two standards composable rather than competing.

## Why It Matters / Open Questions

The N×M → N+M integration reduction is practically significant for the rapidly growing agent ecosystem, where every new agent-benchmark pair currently requires bespoke engineering. By anchoring the proposal in protocols (A2A, MCP) that are already widely adopted in production, the paper lowers the adoption barrier compared to proposing yet another evaluation-specific standard. Key open questions include whether A2A/MCP are truly expressive enough for all evaluation scenarios (e.g., fine-grained timing, partial-credit scoring), how the paradigm handles the test-production mismatch for closed-source agents, and whether the community will converge on this framing before alternative standards gain momentum. As a position paper with no empirical validation, its impact hinges on whether AgentBeats and the five operation modes prove workable in practice.
