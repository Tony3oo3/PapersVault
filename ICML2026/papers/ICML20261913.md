## Problem

Existing BPE tokenization tools (Hugging Face's tokenizers, OpenAI's tiktoken) are inherently offline: they require the full input segment before producing a canonical tokenization, preventing fine-grained pipelining with model inference and introducing latency in streaming settings. Moreover, these implementations can exhibit O(n²) behavior on pathological inputs due to reliance on global priority queues or regex-based segmentation. The paper asks whether BPE can be performed incrementally—processing one byte at a time—with strict worst-case complexity guarantees while maintaining exact semantic equivalence to standard BPE.

## Input / Output

The algorithm consumes a byte sequence one character at a time (streaming input) alongside a fixed BPE dictionary of merge rules, maintaining the last token θ(s) for every prefix of the growing string. The full tokenization of any prefix is recovered by backtracking through the chain of last tokens to the virtual root. The optional eager output mechanism emits tokens as soon as their boundaries become invariant to future extensions, enabling fully pipelined streaming output with model inference. The per-byte worst-case cost is O(log² t) where t is the maximum token length in the vocabulary.

## Method

The core insight is the Monotonic Path Property: among all suffix tokens of the current string, those satisfying the Prefix Last-Token Condition (a reachability + priority-dominance criterion in the Successor Forest) form a single contiguous path in the Suffix-Successor Tree, with the true last token at its deepest node. To exploit this, the algorithm (1) uses an Aho-Corasick automaton over the canonical vocabulary to identify the longest suffix token τ(sc) in O(1) per byte, bounding the search space to SufSucTree(τ); (2) linearizes the Successor Forest via DFS with priority-ordered children, reducing the Prefix Last-Token Condition to an O(1) interval membership test; and (3) traverses a precomputed Centroid Search Tree over SufSucTree(τ) to locate the deepest valid node in O(log²|τ|) steps, using binary search over disjoint sibling intervals at each centroid. An eager output mechanism then maintains a sliding window of parental candidates over the Prefix Tree of Tokens, emitting tokens once all active paths converge, at amortized O(1) overhead per byte.

## Results

The incremental BPE algorithm achieves an end-to-end throughput speedup of up to 3.13× over Hugging Face's tokenizers (on CodeLlama, English) and up to 1.59× over OpenAI's tiktoken (on CL100K, Chinese). On pathological inputs (repeated characters), tiktoken exhibits O(n²) throughput decay while the proposed method maintains stable O(n log²t) throughput. The eager output mechanism for streaming token emission introduces approximately 10% overhead in end-to-end throughput compared to the non-eager incremental implementation.

## Baselines & Comparisons

Against Hugging Face's tokenizers, the largest gains appear on CodeLlama (3.13× English, 2.88× Code), where the absence of regex-based pre-tokenization exposes the heap-based global BPE's log-linear complexity over the full input. For models with fine-grained regex segmentation (Qwen-3, DeepSeek-3.2, Llama-3.1, GPT-OSS, Llama-4, Mistral-3), the speedup is modest (0.93×–1.08×), with slight regressions on English where constant-factor overheads dominate. Against OpenAI's tiktoken, the method achieves clear wins on Chinese text (1.35×–1.59×) where coarser regex segments expose tiktoken's BPE bottleneck, and small wins on Code (1.00×–1.07×), but shows slight regressions on English (0.96×–0.99×) where fine-grained segmentation limits the advantage. On pathological inputs (repeated 'a' characters), tiktoken's throughput decays consistent with O(n²) complexity, while the proposed method maintains stable throughput, demonstrating the practical benefit of the strict O(n log²t) worst-case guarantee.

## Relation to Prior Work

This paper builds on the formal BPE semantics established by Sennrich et al. (2016) and the prefix-consistency property identified by Berglund & van der Merwe (2023), which showed that BPE tokenizations are stable under token-wise truncation. While prior implementations (Hugging Face tokenizers, tiktoken) treat BPE as a global offline process using heap-based priority queues, and the Aho-Corasick-based approach in rust-gems (van Antwerpen & Neubeck, 2024) offers incremental tokenization without formal worst-case guarantees, this paper introduces the Monotonic Path Property and the Successor Forest / Suffix-Successor Tree structures to reduce incremental BPE to a bounded tree search. The algorithmic core combines an Aho-Corasick automaton for search-space identification with Centroid Decomposition for O(log² t) per-byte updates, a combination not present in prior BPE work.

## Why It Matters / Open Questions

Tokenization is a universal preprocessing step in every LLM pipeline, and the demonstrated O(n²) throughput decay in tiktoken on pathological inputs (e.g., repeated characters) represents a real production vulnerability that this work eliminates with strict worst-case guarantees. The streaming capability—pipelining tokenization with model inference via eager output—enables latency reductions in interactive and long-context settings that offline tokenizers cannot achieve. However, the paper acknowledges that upstream pipeline stages (regex pre-tokenization, normalization) remain offline-oriented and can themselves become bottlenecks, leaving open the question of whether a fully end-to-end streaming tokenization pipeline is feasible. The ~10% overhead of eager output and the fact that gains are most pronounced when pre-tokenization is absent (CodeLlama) suggest the practical benefit is context-dependent.
