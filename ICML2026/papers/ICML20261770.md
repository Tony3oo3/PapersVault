## Problem

Existing TableQA benchmarks treat the task as passive, single-turn natural language understanding over isolated tables, failing to evaluate autonomous reasoning, tool-call trajectories, and dynamic intent evolution in realistic multi-turn, multi-table industrial settings. This leaves critical agentic capabilities—such as table localization across complex directory structures, iterative tool invocation, and cross-turn dependency reasoning—largely unmeasured, making it impossible to diagnose whether agent trajectories are logically sound or merely fortunate.

## Input / Output

The agent receives only the current user query, dialogue history, and the root directory path of a table database (no pre-filtered tables or summaries), forcing it to autonomously inspect the file system and identify relevant tables. Each dialogue spans 2–6 turns (averaging 4.29) over multiple tables (averaging 4.15 per folder), and the agent's output is a full multi-step trajectory logging sub-question responses, tool invocations, tool feedback, and reasoning steps. Evaluation is scored against expert-annotated scoring points rather than exact-match answers, accommodating both deterministic numerical results and open-ended analytical conclusions.

## Method

The paper introduces TableAgent-Bench, constructed via a topology-aware strategy that combines 10 analysis task templates with 6 inter-question dependency topologies (Chain, Tree, Fork-Join, Star, Loop-back, Mesh) to synthesize 1,310 bilingual multi-turn dialogues grounded in 2,275 industrial tables across 28 subdomains. For evaluation, the proposed Table-centric Agent Evaluation Framework (TAEF) provides a sandboxed environment with a three-category toolset (Table Retrieval via exact matching and semantic search, Table Processing for structural normalization, and Code Execution via Python/cmd) and four metric dimensions: tool-call success rate, sub-question response quality (Information Coverage and Content Quality adjudicated by a three-model LLM-as-judge panel), table localization (TRR/TRP against human-verified ground-truth table sets), and trajectory-level metrics (Avg@k, Completion Rate, total tool-call steps). Agents operate in a Function Call-based architecture with 32k context and a 70-step tool-call budget, with all 25 tested models using standardized system prompts and temperature 0 to ensure fair comparison.

## Results

On TableAgent-Bench, even the strongest model Gemini-3-Pro-Preview (thinking mode) achieves only 53.4% Information Coverage (IC) and 5.0% Avg@3 trajectory-level pass rate, with 85.3% Table Relevance Recall (TRR) and 94.6% tool-call success rate. GPT-5 follows closely at 50.2% IC and 5.0% Avg@3, while open-source leaders Kimi-K2-Thinking (45.5% IC, 5.0% Avg@3) and GLM-4.7 (47.4% IC, 4.68% Avg@3) trail by 6–8 points in IC. Small models (<32B parameters) collapse dramatically, with Qwen3-8B scoring only 2.75% IC and 0% Avg@3, and tool-call success rates dropping as low as 22% (Qwen3-14B), indicating that multi-table agentic reasoning remains far from solved.

## Baselines & Comparisons

As a benchmark paper, TableAgent-Bench evaluates 25 LLM agents rather than proposing a new method; the key comparison is across model families. Gemini-3-Pro-Preview leads on IC (53.4%) and TRR (85.3%), outperforming GPT-5 (50.2% IC, 83.8% TRR) by ~3 points in both, while Claude-Haiku-4-5 in thinking mode matches GPT-5 on IC (51.1%) but scores 0% Avg@3 versus GPT-5's 5.0%. Among open-source models, GLM-4.7 achieves the highest IC (47.4%) and Kimi-K2-Thinking the best TRR (82.9%), but both trail the closed-source leaders by 6–8 IC points. Thinking mode consistently improves over non-thinking: Kimi-K2 gains +12.1% IC (45.5 vs. 35.7), MiMo-V2-Flash gains +10.7% (45.6 vs. 34.9), and DeepSeek-V3.2 gains +19.3% (46.8 vs. 27.5). Small open-source models (Qwen3-8B/14B/32B, MiroThinker-30B, Tongyi-DeepResearch-30B) are far behind, with IC below 16% and 0% Avg@3, and tool-call success rates as low as 22% (Qwen3-14B), revealing that sub-32B models lack the capacity for sustained multi-table agentic reasoning.

## Relation to Prior Work

This paper carves new ground at the intersection of two established lines of work: TableQA benchmarks (WTQ, TabFact, TAT-QA, TableBench, MiMoTable, RealHiTBench) and general-purpose agent evaluation frameworks (ToolTalk, MINT, τ²-Bench, VitaBench, DAComp). Prior TableQA benchmarks treat the task as passive, single-turn retrieval over academic tables, while agent benchmarks emphasize tool-use trajectories but lack table-specific infrastructure. TableAgent-Bench bridges this gap by reformulating TableQA as multi-turn, tool-mediated interaction over industrial multi-table environments, and introduces the TAEF framework with a specialized table-centric toolset and topology-aware dialogue construction (6 dependency structures) that neither prior line of work provides.

## Why It Matters / Open Questions

The benchmark and TAEF framework provide the first systematic diagnostic toolset for table agents, moving beyond terminal accuracy to expose intermediate failure modes (localization, comprehension, propagation) that are invisible in single-turn settings. The finding that near-perfect completion rates coexist with only 5% trajectory-level correctness across 25 SOTA models underscores that the bottleneck is reasoning consistency over long horizons, not task navigation. Limitations include text-only tables (no multimodal spreadsheets), no operation-oriented tasks (filling, formatting), and reliance on LLM-as-judge for open-ended scoring. Open questions include whether the topology-aware construction generalizes to truly open-ended user intents and whether the 70-step tool-call budget is sufficient for more complex industrial workflows.
