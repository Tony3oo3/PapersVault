## Problem

Existing evaluations of External Memory Modules for LLMs assume a static regime where memory is built offline and queried at a fixed state, and they compare whole systems end-to-end without attributing performance to specific lifecycle stages. In realistic deployments, memory is streaming—insertions interleave with retrievals and the state evolves continuously—yet no benchmark isolates which design decisions along the insertion, maintenance, retrieval, and integration pipeline drive the observed accuracy-latency trade-offs.

## Input / Output

The system consumes a strictly time-ordered stream of INSERT operations (raw dialogue context segments) and RETRIEVE operations (user queries), processed sequentially under a blocking online-consistency regime that enforces temporal causality: a query at time τ can only access evidence from contexts with τ′ < τ. Evaluation is triggered at fixed intervals (e.g., every 20% of the stream) to capture performance evolution as memory accumulates, rather than only at the final state. Outputs include a generated response scored by token-level F1 (with Porter stemming) plus granular insertion latency and retrieval latency decomposed by pipeline stage.

## Method

Neuromem formalizes the External Memory Module as a stateful component governed by two pipelines—Insertion (PREINS → POSTINS) and Retrieval (PRERET → POSTRET)—and decomposes the design space into five factorized dimensions: Memory Data Structure (D1), Normalization Strategy (D2), Consolidation Policy (D3), Query Formulation Strategy (D4), and Context Integration Mechanism (D5). Twelve representative systems (TIM, MemoryBank, MemGPT, A-MEM, HippoRAG, MemoryOS, LD-Agent, SCM, Mem0/Mem0^g, SECOM) are re-instantiated as stage-compatible D1–D5 operators within a shared serving stack, enabling controlled ablations that swap one dimension while holding others fixed. The streaming protocol is implemented via a backpressure-based pipeline architecture (HistorySource → PipelineCaller → Insertion/Retrieval sub-pipelines → ExperimentSink) that blocks the data stream during maintenance and evaluation to guarantee atomicity. Experiments run on pangu-1b (Ascend 910B NPU) and Llama-3.1-8B (A6000 GPU) with bge-m3 and e5-large-v2 embeddings, reporting token-level F1 and per-stage latency across LOCOMO, LONGMEMEVAL, and MEMORYAGENTBENCH.

## Results

On LOCOMO under the interleaved streaming protocol, the Inverted+Vector structure (MEM0) achieves the highest token-level F1, starting at 0.411 (R1) and degrading to 0.358 (R5) with only 12.9% decline, while the Fifo Queue (SCM) collapses from 0.169 to 0.094 (−44.4%). Aggressive normalization (Rewrite/triplet extraction) reduces F1 by over 50% (e.g., 0.371→0.171 for Queue+Segment) while inflating insertion latency by 10× (146 ms→1552 ms). Generative consolidation (CRUD) adds 3,777 ms post-processing latency for a marginal +0.001 mean F1 gain, whereas lightweight Decay Eviction matches CRUD accuracy at 61 ms. Multi-query context integration adds ~1.7 s latency with no F1 improvement on the default backbone (pangu-1b), though Llama-3-8B recovers a small +0.7% F1 gain at 1,327 ms cost.

## Baselines & Comparisons

The paper decomposes five representative memory systems into interchangeable D1–D5 operators and compares them under a unified streaming protocol. On the primary D1 (storage architecture) comparison, MEM0's Inverted+Vector structure dominates, achieving 0.411 F1 at R1 and the smallest degradation (−12.9%), outperforming MEMORYOS's Queue+Segment (0.395, −14.4%) and substantially exceeding SCM's Fifo Queue (0.169, −44.4%) and TIM's LSH Hash (0.102, −6.9%). On D2 (normalization), MEMORYBANK's Enrich (summarization) strategy adds ~4× insertion latency (146→580 ms) for negligible F1 change, while TIM/MEM0^g's Rewrite (triplet extraction) catastrophically degrades accuracy by >50% at 10× latency. On D3 (consolidation), MEMORYBANK's Forgetting Curve and MEMORYOS's heat-based Decay Eviction match or exceed MEM0^g's LLM-driven CRUD in accuracy at 1/30th the latency (61–120 ms vs. 1,983–3,777 ms). On D4 and D5, generative strategies (Keyword extraction, Decompose, Multi-query) from various systems consistently incur 1–2 s latency penalties with zero or negative F1 gains over the None baseline, with the exception that Llama-3-8B recovers a marginal +0.7% F1 from Multi-query at 1,327 ms cost.

## Relation to Prior Work

This paper departs from the dominant static evaluation paradigm in LLM memory benchmarks (LoCoMo, LongMemEval, MemBench, MemoryAgentBench), which build memory offline and query a fixed state, by introducing a streaming interleaved insertion-retrieval protocol that mirrors real deployment. Rather than proposing a new memory architecture, it repurposes existing systems (MemGPT, A-MEM, HippoRAG, MemoryOS, Mem0, MemoryBank, TIM, SCM, SECOM) as interchangeable D1–D5 operators within a unified serving stack, enabling controlled ablations that prior end-to-end leaderboards cannot provide. Conceptually, it extends the in-context memory diagnostics of Minerva (Xia et al., 2025) from prompt-level to external-store-level, and builds on the efficiency-aware evaluation initiated by MemBench while adding lifecycle attribution and temporal causality.

## Why It Matters / Open Questions

The practical design guidelines distilled here—multi-layer partitional structures anchor the quality frontier, aggressive semantic compression is lossy, and heuristic maintenance matches generative consolidation at a fraction of the latency—give practitioners concrete, actionable criteria for building streaming memory systems under strict latency budgets. Open questions remain: the blocking online regime excludes asynchronous and collaborative multi-agent settings, the absence of formal short-term vs. long-term memory tier definitions limits hybrid consolidation strategies, and privacy-aware deletion guarantees are identified but not empirically validated. The cost-shifting pattern (generative operations relocate rather than eliminate computational debt) suggests that future work should focus on reducing total lifecycle cost rather than optimizing individual stages in isolation.
