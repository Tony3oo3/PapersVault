## Problem

Existing LLM fine-tuning paradigms address data privacy and model IP protection in isolation: privacy-prioritized methods (e.g., LDP-based sanitization with server-hosted training) expose fine-tuned parameters to the server, while IP-oriented split learning schemes rely on end-to-end gradient back-propagation that inherently leaks private data. No unified framework simultaneously enforces strict Local Differential Privacy on inputs and structurally prevents model stealing via gradient blockage, and the resulting 'Frozen-Head, Limited-Tail' bottleneck causes convergence failure in naive reverse split architectures.

## Input / Output

The method consumes three distinct inputs in a physically partitioned manner: LDP-perturbed text (sanitized via SanText) is transmitted to the server for feature extraction, while the original clean raw text and task labels remain strictly confined to the data holder's local domain. The server returns only forward-pass features and a scalar confidence score; no backward gradients are ever transmitted. The output is a fine-tuned Tail sub-model (top transformer layers + classifier, typically <20% of total parameters) that resides exclusively on the client side, producing task predictions (e.g., sentiment, entailment) without the server ever observing labels or receiving optimization signals.

## Method

PISA implements a reverse split architecture with strict gradient blockage, where the computation-intensive backbone (Head) is frozen on the server and the lightweight task-specific sub-model (Tail) is trained locally. Three synergistic methods resolve the resulting utility bottleneck: (1) Manifold Rectification Pre-training (MRP) pre-trains the full model on public data with a joint MLM + denoising alignment loss that forces LDP-distorted embeddings to realign with the clean semantic manifold, equipping the frozen Head with intrinsic robustness; (2) Dual-Stream Semantic Compensation (DSC) exploits the data holder's exclusive access to clean raw text by projecting local token embeddings through a lightweight MLP to produce a residual patch that is fused with the server's noisy features, repairing semantic shattering without consuming additional privacy budget; (3) Utility-Aware Gradient Rectification (UGR) repurposes the server's pretrained MLM head as an unsupervised quality gate, computing a per-sample confidence score α that rescales local backward gradients to suppress toxic updates from severely perturbed samples. A convergence theorem (O(1/√T)) shows the noise variance term is scaled by α², ensuring toxic samples contribute negligibly to optimization error.

## Results

On GLUE benchmarks (SST-2, QNLI, MNLI), PISA achieves an average accuracy of 71.3% at ε=10, 74.1% at ε=12, and 78.1% at ε=14, substantially outperforming the privacy-prioritized Hosted-LDP baseline (48.3%, 55.7%, 83.8%) under strict privacy budgets. The IP-prioritized Naive-RS baseline fails to converge, yielding near-random performance (45.4% average) across all ε values. PISA narrows the gap to the unconstrained Vanilla FT upper bound (89.6%) to within 18.3 points at ε=10, while simultaneously enforcing both LDP data privacy and structural model IP protection.

## Baselines & Comparisons

Against the privacy-prioritized Hosted-LDP baseline (Yue et al., 2021, SanText mechanism), PISA achieves a 23.0-point average accuracy gain at ε=10 (71.3% vs. 48.3%) and an 18.4-point gain at ε=12 (74.1% vs. 55.7%), demonstrating that the three calibration modules (MRP, DSC, UGR) effectively repair LDP-induced semantic distortion that Hosted-LDP cannot address. However, at ε=14, Hosted-LDP recovers to 83.8% average (surpassing PISA's 78.1%) because its full-parameter server-side fine-tuning benefits from reduced noise, while PISA's frozen Head introduces a fixed capacity bottleneck. Against the IP-prioritized Naive-RS baseline (reverse split with gradient blockage but no calibration), PISA wins by 25.9 points at ε=10 (71.3% vs. 45.4%), confirming that the naive split architecture fails to converge without the proposed adaptation mechanisms. The paper also shows that equipping Hosted-LDP with the same MRP pre-training (Hosted-LDP+MRP) still trails PISA by 9.1 points at ε=12, attributing the remaining gap to the dual-constraint architecture rather than public data access alone.

## Relation to Prior Work

This paper extends the split learning paradigm (Vepakomma et al., 2018) by inverting the architecture—placing the computation-heavy backbone on the server and the task-specific tail locally—and enforcing a strict gradient blockage to prevent model IP leakage. It departs from prior privacy-preserving fine-tuning work (Yue et al., 2021; Du et al., 2023), which achieves LDP compliance but necessarily exposes fine-tuned parameters to the server, and from IP-oriented split schemes (Wang et al., 2025), which retain local model control but leak data through end-to-end gradient flow. The key conceptual contribution is identifying the 'Frozen-Head, Limited-Tail' bottleneck as the structural reason why naive reverse split learning fails, then addressing it through three synergistic calibration methods (MRP, DSC, UGR) that exploit the data holder's exclusive access to clean local data as a semantic anchor.

## Why It Matters / Open Questions

PISA addresses a practically critical gap: in regulated domains like healthcare and finance, organizations need external compute for LLM fine-tuning while simultaneously protecting both patient data and proprietary task models—constraints that prior work has only addressed in isolation. The honest crossover finding (PISA outperforms Hosted-LDP only when ε < 14) delineates the regime where dual protection is achievable without severe utility loss, which is important for practitioners choosing deployment strategies. Key limitations include restriction to classification tasks (GLUE), inability to extend DSC to autoregressive generation, and a persistent ~18-point gap to unconstrained fine-tuning even at relaxed budgets. Extending the framework to generative tasks and on-device deployment are explicitly identified as open directions.
