## Problem

While LLMs are increasingly evaluated on competitive programming code generation, their potential to support human learning—specifically identifying errors in human-written code and generating targeted counter-examples—remains largely unexplored. Existing benchmarks focus almost exclusively on autonomous solution synthesis and rely on custom or surrogate judging pipelines that may diverge from real online judge infrastructure, leaving a gap in evaluating the full debugging loop (hacking and repair) under authentic evaluation conditions.

## Input / Output

For code generation, the model receives an English-translated problem statement and produces a C++20 program. For code hacking, the model receives the problem statement plus a buggy human submission and must output a Python script that prints a valid input (within all stated constraints) causing the target code to fail. For code repair, the model receives the same problem-and-buggy-code pair and must output a minimal unified-diff patch (applied via `patch -fuzz=5`) that modifies no more than 10% of the original code lines. All outputs are validated through UOJ's native judging API, including custom checkers for constructive problems and strict time-limit enforcement.

## Method

UOJ-Bench is constructed from real-world submissions on the Universal Online Judge, a community-driven platform whose distinctive Hack mechanism crowdsources discovery of covert errors in accepted solutions. The benchmark comprises three tasks (generation, hacking, repair) each split into Easy (overt errors exposed by standard tests) and Hard (covert errors exposed only by community hacks) levels, totaling 672 problems, 1,525 hacking instances, and 716 repair instances. Data curation enforces a 0.95 Levenshtein similarity constraint on repair pairs, LLM-assisted bug classification (corner-case, careless, wrong-but-works), and re-evaluation against current hardware to discard outdated TLE cases. A Zero-Day-Hacking-5K extension samples 5,060 full-score submissions biased toward historically hack-prone problems to test discovery of previously unknown vulnerabilities. Evaluation employs both direct Pass@1 prompting and test-time scaling (Pass@k up to 20,000 samples), plus a ReAct-based agentic loop that feeds back OJ verdicts iteratively, all scored through UOJ's internal API rather than a surrogate judge.

## Results

On UOJ-Bench's core novel tasks, the strongest model GPT-5.2-high achieves 58.60% Pass@1 on Hacking (Hard) and 52.31% on Repair (Hard), while Gemini-3-pro-preview reaches 44.17% and 48.15% respectively. Under test-time scaling (Pass@k), Gemini-3-pro-preview improves to 93% on hacking (93/100) and 82% on repair (41/50), but at a cost of ~$1 per problem at k=20,000. In the Zero-Day Hacking setting, GPT-OSS-120B under test-time scaling uncovers errors in over 10% of 5,060 full-score submissions, with over 5% success across ~30 individual problems. For code generation (Task 1), GPT-5.2-high scores 44.05% overall, dropping to 27.33% on Ultrahard problems.

## Baselines & Comparisons

UOJ-Bench is the only existing competitive programming benchmark that simultaneously covers all three tasks (generation, hacking, repair) while using the original online judge's native infrastructure for grading, non-trivial checkers, and time-limit enforcement. LiveCodeBench and LiveCodeBench Pro evaluate only code generation (400 and 584 instances respectively) and rely on custom or surrogate judging pipelines, omitting hacking and repair entirely. CodeELO (398 instances) adds non-trivial grading and time-limit checking but still covers only generation. REFUTE (324 hacking instances) is the closest prior work on code hacking, but the authors note it contains only 42 samples with covert errors and lacks a repair task; UOJ-Bench provides 1,046 hard hacking instances and 216 hard repair pairs. ELABORATION (8,320 instances) includes a self-repair task but restricts it to repairing LLM-generated code rather than human-written submissions, and provides no hacking evaluation. In terms of model performance, the paper does not run cross-benchmark comparisons (since tasks differ), but positions UOJ-Bench as the most comprehensive and realistic evaluation, with the key finding that even frontier models fail on >50% of covert-error instances under single-shot evaluation.

## Relation to Prior Work

This paper extends the competitive programming benchmarking line (LiveCodeBench, CodeElo, LiveCodeBench Pro) beyond code generation to include code hacking and code repair, and departs from prior hacking work (REFUTE) by targeting covert errors that evade standard test cases rather than overt failures. It also distinguishes itself from automated program repair benchmarks (SWE-bench, RunBugRun, RealHumanEval) by evaluating repair of human-written IOI-level code rather than self-repair of model-generated output or elementary-level bugs. A key methodological departure is the use of UOJ's native judging infrastructure with custom checkers and time-limit enforcement, avoiding the surrogate-grading gap present in most existing benchmarks.

## Why It Matters / Open Questions

The benchmark reveals that even frontier models fail to identify covert errors in over 50% of submissions under one-shot evaluation, and while test-time scaling pushes success above 90%, the economic cost (~$100K/year for UOJ-scale deployment vs. <$500 for CPU judging) makes large-scale integration impractical. The zero-day hacking result—that GPT-OSS-120B under test-time scaling uncovers previously unknown bugs in >5% of full-score submissions across ~30 problems—suggests LLMs can already provide complementary verification signals beyond standard test suites, with direct implications for contest fairness and educational feedback. Open questions include whether cheaper models or targeted inference strategies can close the cost gap, and whether the zero-day discovery rate generalizes beyond the biased sampling toward historically hackable problems.
