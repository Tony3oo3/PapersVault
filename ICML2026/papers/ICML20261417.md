## Problem

Existing LLM fingerprinting methods (e.g., LLMmap) are designed for intellectual property protection and deliberately ignore instance-level parameters such as system prompts, temperature, quantization, and fine-tuning to achieve robustness. However, AI regulation (EU AI Act, California SB53) requires identifying the specific deployed configuration of a model, since a safe model under one configuration can produce toxic content under another. This paper introduces instance-level fingerprinting, a regulator-oriented paradigm that distinguishes configurations of the same base LLM, and demonstrates that state-of-the-art IPP methods are blind to such behavioral shifts.

## Input / Output

The method takes a fixed prompt template instructing the LLM to generate 500 symbols from a specific token pair (t_A, t_B) drawn from alphanumeric tokens shared across all reference models; multiple distinct token pairs form an uplet of size K. The LLM's text response is parsed into a binary sequence by mapping t_A→0 and t_B→1 (sequences yielding fewer than 100 bits are re-queried up to 5 times). The output is a classification decision: either a match to a known reference instance or an 'Unseen' label, with the intermediate representation being a d-dimensional NIST test-statistics vector per generated sequence.

## Method

FLIPS exploits the well-documented poor randomness generation of LLMs: when prompted to produce a 'random' binary sequence, models exhibit instance-specific biases (driven by the interplay of weights, attention, temperature, system prompt, and quantization) that are captured by the NIST cryptographic randomness test suite (12 tests yielding d statistics per sequence). At extraction, each reference instance is queried N_r=40 times across K token pairs, and the resulting NIST feature vectors train a per-pair XGBoost classifier. At verification, the target instance is queried only K times (once per token pair), and per-pair probability outputs are aggregated via soft voting; a confidence threshold (set as the α-quantile of training max-probabilities, requiring no test data) flags instances as Unseen. The key differentiator from LLMmap is that NIST statistics assign specific, interpretable deviations from randomness to particular instances, whereas LLMmap's BERT-embedding + contrastive-learning pipeline produces opaque decision boundaries that are robust to exactly the configuration changes regulators need to detect.

## Results

FLIPS achieves 96% closed-set and 90% open-set identification accuracy across 237 model instances (derived from 25 LLMs) using only 8 verification queries (N_t=8) and 40 extraction queries (N_r=40). In the open-set setting, FLIPS attains 54% precision and 83% recall on unseen instances at N_t=8, and already reaches 64% accuracy with a single verification query. The adapted LLMmap baseline, despite being specifically trained on the same instances, reaches at best 35% closed-set accuracy and is not evaluated in the open-set setting.

## Baselines & Comparisons

The primary baseline is LLMmap (Pasquini et al., 2025), the state-of-the-art IPP fingerprinting scheme, adapted to the instance-level fingerprinting setting. FLIPS decisively outperforms LLMmap: 96% vs. 35% closed-set accuracy (a 61-point gap) at N_t=8, and FLIPS achieves 90% open-set accuracy while LLMmap is not evaluated in that setting due to its weak closed-set performance and ~20× higher retraining cost. FLIPS also requires far fewer extraction queries (40 vs. ~1,000), making it substantially more query-efficient at the extraction stage while matching LLMmap's 8-query verification budget. The paper additionally positions FLIPS against other black-box fingerprinting methods (MET, DuFFin, RUT, Cotsrf, etc.) in a qualitative property comparison (Table 4), noting that FLIPS is the only method combining instance-level sensitivity, strict black-box access to both source and target, and query efficiency in both extraction and verification.

## Relation to Prior Work

This paper departs from the dominant LLM fingerprinting literature (LLMmap, ProfLingo, TRAP, SRAF, etc.), which is designed for Intellectual Property Protection and deliberately treats configuration changes (quantization, system prompts, temperature) as noise to be robust against. FLIPS repurposes the well-known observation that LLMs are poor at generating random sequences (Hopkins & Renda, 2023; Van Koevering & Kleinberg, 2024; Coronado-Blazquez, 2025) as a fingerprinting signal, applying the NIST cryptographic test suite to the resulting binary sequences rather than the BERT-like embedding + contrastive-learning pipeline used by LLMmap. The method lineage is thus: general model-fingerprinting paradigm (extraction + verification) → LLM-specific black-box setting → a new sensitivity-to-configuration objective, with XGBoost replacing the transformer classifier.

## Why It Matters / Open Questions

As the EU AI Act and California SB 53 push toward continuous post-deployment compliance monitoring, regulators need to verify that a deployed instance matches its audited configuration without re-running full evaluations; FLIPS' 8-query verification budget makes this operationally feasible. The dramatic 96%-vs-35% gap with LLMmap exposes a fundamental tension: methods optimized for IPP robustness are structurally blind to the very behavioral shifts regulators must detect. Open questions include how the approach degrades as LLMs improve at pseudo-random generation, whether active evasion (query rerouting to a true PRNG) is practically feasible at scale, and how the method extends to agentic or multi-LLM systems where the 'instance' boundary becomes ambiguous.
