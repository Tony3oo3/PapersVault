## Problem

Existing code benchmarks rely on synthetic tasks, binary pass/fail correctness, or single-objective evaluation, making them inadequate for assessing how LLM agents optimize entire codebases under realistic multi-workload constraints. There is no framework to measure whether agents can balance competing performance objectives, maintain correctness across subsystems, and structure improvements at different levels of the codebase hierarchy—capabilities that define real-world performance engineering.

## Input / Output

Each task provides a GitHub-derived problem description (mean 2,718 tokens), a full baseline repository snapshot at a specific commit, and on average 264.6 community-maintained ASV performance workloads that exercise known performance-critical paths. The agent produces arbitrary repository-level edits, which are scored on geometric-mean speedup across all workloads, human-relative advantage (agent speedup minus expert speedup per workload), stratified advantage at module/class/function hierarchy levels, normalized advantage (divided by combined variance), and cost-weighted advantage (divided by inference token cost). Correctness is enforced via unit tests and automated snapshot tests comparing workload return values against a reference.

## Method

FORMULACODE is constructed via a fully automated four-stage pipeline: (1) scraping 766 scientific Python repositories with ASV benchmarking infrastructure from the GitHub Public Dataset, (2) applying rule-based filters and an LLM-based performance-intent classifier over 105,074 merged PRs to yield 3,181 candidates, (3) synthesizing reproducible Docker build environments using a reflexive LLM agent with chronological retrieval of previously successful build scripts, and (4) validating each task via Mann-Whitney U test (p<0.002) to confirm statistically significant expert speedups, yielding 957 final tasks. The evaluation framework introduces multi-scale metrics—geometric-mean speedup, human-relative advantage, stratified advantage across code hierarchy levels, normalized advantage accounting for measurement noise, and cost-weighted advantage—that together capture the full optimization lifecycle (triage, diagnosis, resolution) in a way isolated coding tasks cannot. The benchmark operates as a live dataset updated monthly to resist data contamination, and the 108-task FORMULACODE-V subset preserves the repository and difficulty distribution of the full benchmark for tractable agent evaluation.

## Results

On FORMULACODE-V (108 tasks), all seven agent-model configurations achieve speedup > 1 over the baseline codebase, but all underperform human experts (expert speedup = 1.1040). The best configuration, OpenHands + Claude 4.0 Sonnet, attains a speedup of 1.0539 with a human-relative advantage of −0.0112 (normalized: −0.0483), while the worst, Terminus 2 + GPT-5, reaches speedup 1.0585 with advantage −0.0504. Agents systematically outperform experts on parallelization and batching tasks (positive advantage, e.g., +0.047 for OpenHands + Claude 4.0 Sonnet on batching) but fall far behind on lower-level system optimizations (e.g., −0.720 for Terminus 2 + Claude 4.0 Sonnet on C/vectorized extensions).

## Baselines & Comparisons

The primary baseline is the human expert patch, against which all agents are measured via the human-relative advantage metric. Every agent-model configuration yields a negative advantage, confirming that no current frontier LLM agent matches expert-level multi-workload optimization; the gap ranges from −0.0112 (OpenHands + Claude 4.0 Sonnet) to −0.0504 (Terminus 2 + GPT-5) in raw advantage. Among frameworks, OpenHands consistently outperforms Terminus 2: the top three leaderboard positions are all OpenHands configurations, while Terminus 2 configurations occupy ranks 4–7. Among models, Claude 4.0 Sonnet is the strongest under both frameworks, while Qwen 3 Coder (open weights) shows the largest normalized-advantage gap (−0.1529 under OpenHands), attributed to much longer reasoning chains that increase cost without proportional quality gains. By optimization type, agents beat experts on parallelization (+0.007 to +0.015) and batching (+0.028 to +0.051) but lose dramatically on lower-level system calls (−0.180 to −0.720), indicating a persistent gap in generating C-extension or vectorized-NumPy solutions. By repository popularity, agents are most competitive on mid-popularity repos (Q2–Q3, advantages near zero) and worst on high-popularity repos (Q4, e.g., −0.3529 for Terminus 2 + Claude 4.0 Sonnet), where expert speedups are also smallest (1.0822), suggesting reduced optimization headroom.

## Relation to Prior Work

FORMULACODE extends the repository-level code benchmarking paradigm established by SWE-Bench and its successors, but repurposes it from bug-fixing (binary correctness) to performance optimization (continuous, multi-objective metrics). It departs from prior optimization benchmarks (GSO-Bench, SWEefficiency, SWE-Perf) by replacing single-workload or unit-test-timing proxies with ~265 community-maintained ASV performance workloads per task, and by introducing human-expert-relative advantage metrics (stratified, normalized, cost-weighted) that no prior benchmark provides. The construction pipeline borrows the reflexion-style iterative agent pattern for Docker environment synthesis, and the evaluation leverages the existing Airspeed Velocity statistical testing infrastructure (Mann-Whitney U with Holm-Bonferroni correction) rather than inventing new measurement protocols.

## Why It Matters / Open Questions

This is the first benchmark to evaluate the full agentic optimization lifecycle—triage, diagnosis, and resolution—at repository scale with multi-workload trade-offs, filling a clear gap between function-level efficiency benchmarks and repository-level correctness benchmarks. The finding that all frontier agents underperform human experts on performance optimization, and that they negotiate multi-workload trade-offs less effectively, provides a concrete target for future agent development. Key limitations include restriction to scientific Python with ASV infrastructure, evaluation on only 108 of 957 tasks due to compute constraints, and hardware-specific measurements. Open questions include whether agents can eventually surpass experts on this task, how to extend beyond scientific Python to web frameworks and distributed systems, and whether the non-monotonic popularity effect (worst on Q4) reflects distribution shift or reduced optimization headroom.
