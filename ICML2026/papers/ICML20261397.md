## Problem

LLMs have demonstrated strong sequential code comprehension, but their ability to reason about concurrent programs remains unquantified. Existing code benchmarks rely on fixed execution oracles that are invalidated by runtime non-determinism in concurrent programs, where a single input can yield multiple valid outputs. This paper addresses the evaluation gap by framing concurrent code comprehension as a deterministic static prediction task—data race prediction—whose ground truth is invariant to scheduling.

## Input / Output

Each input is a concurrent C/C++ program (14–624 LOC, sourced from SV-COMP's NoDataRace subtrack) with line numbers prepended, delivered via a zero-shot prompt containing task definition, domain knowledge (mutex/semaphore/atomic semantics), output specification, and source code. The model must return a JSON object listing each predicted race as a triplet of shared variable name and two conflicting line numbers; race-free programs yield an empty list. Evaluation uses strict set-based matching: a prediction is a true positive only if both the variable name and the exact line pair match a ground-truth annotation, enabling fine-grained per-race scoring rather than program-level pass/fail.

## Method

DRPBench is constructed from 1,003 SV-COMP programs (226 racing with 557 annotated races, 777 race-free) using a four-stage quality-assurance pipeline: independent annotation by three human annotators and three automated tools (o3-mini, GPT-4o, Deagle), cross-verification and refinement, expert meta-review by two senior concurrent-programming specialists, and consensus-based acceptance. The evaluation compares 15 LLMs across standard, reasoning (test-time 'thinking' mode), and agentic (OpenHands scaffold) configurations, alongside two symbolic baselines (Deagle SMT analyzer and UGemCutter model checker) on a balanced 200-program subset (DRPBench-Lite). The key methodological insight is that data races are static properties of program logic—unlike execution outputs, they do not depend on thread scheduling—thereby providing a deterministic oracle that circumvents the fundamental non-determinism problem of concurrent program evaluation. The benchmark differentiates models by requiring precise variable- and line-level localization rather than coarse program-level classification, revealing that reasoning models outperform standard variants by ~16% F1 while agentic scaffolds degrade performance due to lack of concurrency-specific tooling.

## Results

On DRPBench-Lite (200 programs, 1:1 racing/race-free ratio), the top-performing model Gemini 3-thinking achieves an F1 of 74.89% (R=81.37%, P=69.36%), while most models score below 60% F1 and Llama 3 70B achieves only 8.80%. Test-time reasoning yields an average F1 gain of 16.24% over standard variants, whereas agentic scaffolding (OpenHands) causes a 6.47% F1 decline relative to standard mode. The two symbolic baselines—Deagle (F1=49.02%) and UGemCutter (F1=24.86%)—are substantially outperformed by the best LLMs on F1 and recall, but maintain higher precision.

## Baselines & Comparisons

The paper compares 15 LLM configurations against two state-of-the-art symbolic tools: Deagle (SMT-based, SV-COMP champion 2022–2025) and UGemCutter (deterministic model checker, top-3 in SV-COMP ConcurrencySafety 2022–2025). The best LLM (Gemini 3-thinking, F1=74.89%) substantially outperforms both symbolic baselines on F1 (vs. Deagle's 49.02% and UGemCutter's 24.86%) and recall (81.37% vs. 36.93% and 14.38%), indicating that LLMs identify a much wider variety of true data races. However, the symbolic tools maintain a precision advantage: Deagle achieves 72.90% precision (slightly above Gemini 3-thinking's 69.36%), and UGemCutter reaches 91.67% precision, reflecting their soundness-oriented design that minimizes false positives. The authors attribute the symbolic tools' low recall to brittleness with semantically simple but hard-to-model constructs (e.g., loops), which cause timeouts or failed proof generation. Overall, LLMs win on recall and F1 but lose on precision, suggesting a neurosymbolic integration could combine the strengths of both paradigms.

## Relation to Prior Work

This paper carves new ground at the intersection of LLM code-comprehension benchmarks and data race prediction. Prior race prediction benchmarks (Dataracebench, Dataracebench-ML) reduce the task to program-level binary classification, while prior LLM code benchmarks (HumanEval, CRUXEval) ignore concurrency entirely. DRPBench repurposes the SV-COMP NoDataRace corpus by adding fine-grained variable-and-line-level annotations, reframing race prediction as a deterministic static proxy that sidesteps the runtime non-determinism problem that invalidates execution-based oracles for concurrent programs. It also positions LLMs against SOTA symbolic tools (Deagle, UGemCutter) as baselines, a comparison absent from prior LLM code-comprehension work.

## Why It Matters / Open Questions

This is the first benchmark specifically targeting LLM concurrent code comprehension, and its fine-grained evaluation (individual race triplets rather than program-level pass/fail) enables diagnostic failure-mode analysis that coarser benchmarks cannot provide. The finding that agentic scaffolding degrades precision by ~21% relative to reasoning mode challenges the prevailing assumption that more tools and multi-step interaction improve code analysis. Key limitations include restriction to isolated C/C++ pthread programs under sequential consistency, and the absence of multi-language or system-level concurrency. Open questions include whether neurosymbolic integration (LLM recall + SMT precision) can close the gap, and whether concurrency-aware agent tooling (thread-interleaving simulators, runtime memory monitors) can reverse the agentic degradation.
