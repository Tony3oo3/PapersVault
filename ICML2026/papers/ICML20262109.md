## Problem

When LLMs are accessed through commercial black-box APIs, users must transmit human-readable prompts and responses to external providers, exposing sensitive plaintext at the API boundary. Existing privacy-preserving approaches either require white-box model access (cryptographic secure inference, embedding-level obfuscation) or protect only training data (differential privacy, federated learning), leaving inference-time text exposure unaddressed. No prior method transforms plaintext into a form unreadable to humans while remaining processable by the model under strict API-only constraints.

## Input / Output

The client-side translator takes plaintext text and a client-held bijection seed, tokenizes the text using the public tokenizer, applies a token-ID-level permutation (preserving subword boundaries), and emits alienized text for API transmission; the reverse decoder recovers plaintext from alien responses losslessly. The alienization ratio ρ ∈ [0,1] controls what fraction of non-special token IDs are permuted, enabling selective protection of sensitive fields versus full-vocabulary alienization. The bijection operates over ~10⁵+ token IDs, and the secret key is the permutation itself—disclosure of the seed or translator binary breaks the protection.

## Method

AlienLM constructs an Alien Language by defining a bijective permutation f over the non-special token IDs of the target model's vocabulary, optimized to simultaneously maximize length-normalized edit distance (human opacity) and minimize cosine distance in embedding space (model learnability). Because target-model embeddings are inaccessible under black-box constraints, the bijection is optimized using proxy embeddings from a related open-source model, leveraging cross-model representation alignment; a greedy k-NN candidate reduction solver makes the optimization tractable at 10⁵+ token scale in under 20 minutes. The target model is then adapted via Alien Adaptation Training (AAT), a standard supervised fine-tuning procedure where both inputs and outputs of training pairs are alienized before upload to the fine-tuning API, so the model learns to process alien token sequences natively. This yields a deployable pipeline where the API observes only alien text in both directions, while authorized clients with the translator recover plaintext with sub-millisecond overhead.

## Results

Across four LLM backbones (LLaMA-3-8B, Qwen-2.5-7B/14B, Gemma-2-9B) and seven benchmarks, AlienLM retains over 81% of Oracle performance on average (Recovery Ratio), with per-backbone RR ranging from 81.70% (LLaMA-3-8B, 52.92 avg) to 87.40% (Qwen-2.5-7B, 57.33 avg). The alienization ratio ρ provides a smooth opacity-utility trade-off: at ρ=0.6, AlienLM still achieves ~86% RR while alienizing the majority of tokens. Under recovery attacks, token recovery stays below 0.22% and BLEU for text recovery remains below 12 across all observer scenarios (O1–O3).

## Baselines & Comparisons

The primary comparison is against SentinelLM (black-box reimplementation), which also applies a token-level bijection with AAT but uses a random permutation instead of the embedding-optimized bijection. AlienLM outperforms SentinelLM by 15.96 points on average for LLaMA-3-8B (52.92 vs. 36.96), 26.16 for Qwen-2.5-7B (57.33 vs. 31.17), 13.46 for Qwen-2.5-14B (62.05 vs. 48.59), and 6.45 for Gemma-2-9B (56.63 vs. 50.18), with the largest gap on GSM8K (e.g., 63.08 vs. 31.08 on LLaMA-3-8B), indicating that embedding-aligned bijection construction is critical for preserving numerical reasoning. The Substitution baseline (bijection without AAT) and ROT13-ASCII baseline (character-level substitution with AAT) both fall below 40% RR across all backbones, confirming that both model adaptation and token-level (rather than character-level) transformation are necessary. Notably, the white-box SentinelLM upper bound (62.39 avg on LLaMA-3-8B, Table 11) is close to the SFT reference (62.44), while AlienLM's API-only proxy approach recovers 53.32, closing roughly 64% of the gap between random bijection (36.96) and the white-box ceiling.

## Relation to Prior Work

This paper carves out a new deployment regime for privacy-preserving LLM inference: text-level exposure reduction under strict black-box, API-only access. It departs from cryptographic secure inference (HE/MPC/TEE), which requires white-box model access or specialized runtimes, and from training-time methods (DP/FL), which do not protect inference-time prompts. The closest prior work, SentinelLM (Mishra et al., 2024), also uses token-level substitution with fine-tuning but requires white-box access to modify embedding matrices; AlienLM replaces this with proxy-embedding-guided bijection optimization and API-only fine-tuning. The approach is further motivated by cross-model representation alignment (Kornblith et al., 2019; Bansal et al., 2021) and evidence that language form and task competence can be decoupled (Chen et al., 2023; Deng et al., 2025).

## Why It Matters / Open Questions

AlienLM provides a practical, deployable mechanism for reducing plaintext exposure at the API boundary without formal cryptographic guarantees, filling a gap that neither cryptographic nor training-time methods address. The alienization ratio ρ offers a tunable opacity-utility knob, and seed-based key diversity supports multi-tenant deployment. Key open questions include: whether a single model can serve multiple bijection keys without gradient interference (the multi-tenant prototype shows significant degradation), whether safety alignment can be preserved during AAT, and whether formal (rather than empirical) robustness guarantees can be established. Metadata channels (message length, timing) and behavioral fingerprinting remain unaddressed side channels.
