## Problem

Existing LLM watermarking methods that bias token logits toward statistically detectable patterns work well for natural language but degrade severely on code, where syntactic constraints make many token positions immutable and indiscriminate watermarking breaks compilation. Prior code-specific watermarking approaches (e.g., SWEET, CodeIP) require privileged access to the original prompt, generating LLM, or internal entropy values at detection time, limiting real-world deployment. The paper asks how to learn adaptive watermark insertion that respects code structure while remaining detectable from the code snippet alone.

## Input / Output

At generation, the system takes a natural-language code prompt and produces a watermarked code sequence; a lightweight 118M-parameter watermark transformer consumes only a 2-token context window (not the full generation history) to decide per-step whether to watermark and which tokens form the green set. At detection, only the candidate code sequence is needed—the detector reconstructs watermark decisions using the same watermark model without access to the generating LLM, original prompt, or generation probabilities, then computes a one-proportion z-score over watermarked positions to classify the sequence as watermarked or not.

## Method

CodeTracer couples a frozen LLM with a trainable 6-layer transformer watermark policy (512-dim, 8 heads) that at each step outputs a binary watermark flag w and a green-token logit vector; the LLM's logits are biased by δ on green tokens when w=1. Training uses GRPO with a three-component reward: binary execution pass/fail, a saturated z-score outcome reward (capped at z=4), and a token-level process reward (+1 green, −α red, 0 non-watermarked), combined via group-normalized advantages. To make the discrete w and top-k green-set selection differentiable, the paper applies Straight-Through Estimation for w and Gumbel-Top-k reparameterization with a Gumbel-Softmax relaxation for G, enabling end-to-end gradient-based policy optimization. A brief SFT warm-up on entropy and next-token prediction of clean code initializes the watermark model before RL, and the trained policy transfers zero-shot to larger LLMs (1.5B→8B) and across languages (Python→Java/C++) without retraining.

## Results

On HumanEval, CodeTracer achieves 62.65% Pass@1, 77.71% AUROC, and 32.32% TPR@5%FPR, outperforming all watermarking baselines on every metric simultaneously. On MBPP, it reaches 42.10% Pass@1, 78.42% AUROC, and 31.60% TPR@5%FPR. Post-hoc detection methods (logp(x), LogRank, DetectGPT, GPTZero) perform near random (AUROC 41–52%), confirming that active watermarking is necessary for reliable code attribution. The watermark model adds only 118M parameters (<10% overhead) and <100μs inference delay.

## Baselines & Comparisons

CodeTracer achieves the best score on every metric across both HumanEval and MBPP, simultaneously leading in code functionality (Pass@1) and watermark detectability (AUROC, TPR). Against the strongest watermarking baseline SWEET†, CodeTracer gains +2.19% Pass@1 (62.65 vs 60.46) and +1.47% AUROC (77.71 vs 76.24) on HumanEval, while on MBPP it improves Pass@1 by +2.46% (42.10 vs 39.64) and AUROC by +1.18% (78.42 vs 77.24). WLLM, the original green-red watermark, suffers the largest functionality drop (Pass@1 58.05% on HumanEval, a 7.37-point loss vs. the unwatermarked base) and trails CodeTracer by 7.54% in AUROC. EXP-edit is the weakest active watermark, achieving only 51.22% AUROC on MBPP (near random) and 25.61% TPR on HumanEval. All four post-hoc detectors (logp(x), LogRank, DetectGPT, GPTZero) cluster around 50% AUROC, confirming they cannot reliably distinguish AI-generated code from human-written code, whereas CodeTracer's adaptive watermarking lifts detection to 77–78% AUROC with minimal functional cost.

## Relation to Prior Work

CodeTracer builds on the green-red logit-bias watermarking paradigm (Kirchenbauer et al., 2023a) and the GRPO reinforcement learning framework (Shao et al., 2024), but departs from prior code watermarking methods (SWEET, WLLM, EXP-edit) that rely on fixed entropy thresholds or privileged access to the generating LLM at detection time. Its key conceptual departure is framing watermark placement as a learned policy problem solved via RL with verifiable rewards, rather than a rule-based or heuristic decision, and using Gumbel-Top-k reparameterization (Xie & Ermon, 2019) to make the discrete green-list selection differentiable. Unlike Xu et al. (2024), which trains the LLM itself via RL for watermarking, CodeTracer freezes the LLM and trains only a lightweight 118M-parameter plug-in, enabling transfer across model sizes without retraining.

## Why It Matters / Open Questions

The plug-in architecture (train once on a small model, deploy on larger ones) addresses a critical practical barrier: prior code watermarking methods require access to the generating model's internals or original prompts at detection time, limiting real-world deployment. The RL formulation elegantly resolves the circular dependency of supervised watermarking (you need watermarked examples to train, but need a trained model to create them). Open questions include robustness against stronger adversarial attacks beyond paraphrasing and renaming, true cross-language generalization outside the same tokenizer family, and whether the Gumbel-Top-k approximation degrades on rare code patterns. The one-time training cost and sensitivity to new languages remain practical hurdles compared to zero-training alternatives.
