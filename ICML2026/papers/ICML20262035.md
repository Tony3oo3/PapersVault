## Problem

Current agentic inference systems loosely couple an LLM inference engine (e.g., vLLM) with a tool orchestrator (e.g., Kubernetes), scheduling resources on a per-request basis without end-to-end workflow awareness. This causes three critical failures at high concurrency: KV cache thrashing (up to 7.14× latency increase from re-prefill), cross-node memory imbalance (up to 51% divergence), and tool resource leakage (unbounded disk/port exhaustion). No existing system provides a unified, program-level view to coordinate GPU memory, tool environments, and scheduling across the full agentic workflow lifecycle.

## Input / Output

ThunderAgent consumes agentic workflow requests tagged with a persistent program_id that identifies the multi-turn LLM+tool interaction, along with tool execution environments (Docker sandboxes, network ports). The system wraps existing OpenAI-style inference endpoints, requiring only two interface changes: attaching program_id to each request and sending an explicit release signal on program termination. Outputs include LLM-generated tokens, tool execution results, and internal scheduling decisions (pause/restore/terminate) that govern KV cache residency and tool resource allocation across data-parallel GPU nodes.

## Method

ThunderAgent introduces the Agentic Program abstraction (P = ⟨ID, c, T, L, τ, s⟩) that tracks each workflow's token count, tool environments, node placement, execution phase (Reasoning/Acting), and scheduling status as a first-class scheduling unit. A cost model based on Space-Time Product decomposes total GPU consumption into effective work (decode + prefill) and waste (recompute + unused + caching), guiding a scheduler that minimizes waste via: (1) state-aware pausing with a time-decay function f(t) that progressively discounts acting programs' memory priority, (2) shortest-first eviction proven optimal via a quadratic recomputation cost argument (Cost ∝ c²), and (3) a global program-aware waiting queue shared across all DP nodes to enable dynamic migration and bound unused memory. A hook-based garbage collector reclaims tool resources on program termination, while asynchronous environment preparation overlaps I/O-intensive sandbox setup with LLM reasoning. The system is backend-agnostic, wrapping vLLM/SGLang/TensorRT-LLM via standard OpenAI-style APIs.

## Results

On agentic serving (SWE-Bench-Lite, HLE-Bench, ScienceAgentBench), ThunderAgent achieves 1.48–3.58× throughput speedup over vLLM and 1.17–3.31× over Continuum across GLM-4.6 and Qwen-3 models with OpenHands, mini-SWEAgent, and ToolOrchestra workflows. On distributed RL rollout (GLM-4.6, 2×8 H100 nodes), ThunderAgent achieves 1.79× (mini-SWEAgent: 671.8 vs. 375.4 steps/min) and 3.92× (OpenHands: 270.8 vs. 69.1 steps/min) throughput over vLLM+SGLang Gateway. The system also delivers up to 4.2× disk memory savings from lifecycle-aware garbage collection and maintains near-100% KV cache hit rate on predictable-tool workloads.

## Baselines & Comparisons

ThunderAgent consistently outperforms all three baselines across every evaluated workload. Against vLLM (request-aware, stateless scheduling), ThunderAgent wins by 1.48–3.58× on serving and 1.79–3.92× on RL rollout, primarily because vLLM's per-request scheduling causes KV cache thrashing that inflates re-prefill latency by up to 7.14×. Against Continuum (TTL-based KV pinning), ThunderAgent wins by 1.17–3.31× on serving; Continuum's KV hit rate degrades from >90% to ~60% under high concurrency due to unpredictable tool latencies breaking its TTL estimates, and on stochastic-tool workloads (ToolOrchestra/HLE, ScienceAgentBench) Continuum can show a higher KV hit rate yet lower throughput because idle pinned caches waste GPU memory. Against vLLM+SGLang Gateway (the leading distributed rollout solution), ThunderAgent wins by 1.79× on mini-SWEAgent and 3.92× on OpenHands; the gap widens with cluster size, growing from 1.79× at 2 nodes to 2.39× at 8 nodes (64 H100s), because the SGLang cache-aware router cannot redistribute paused programs across nodes and cross-node memory imbalance grows with scale.

## Relation to Prior Work

This paper departs from the dominant paradigm of treating each LLM inference call as an independent, stateless request (as in vLLM, SGLang) by introducing a 'program' abstraction that persists across multiple model invocations and tool executions within a single agentic workflow. It builds conceptually on Autellix's idea of modeling agent workflows as programs and Continuum's TTL-based KV cache pinning, but addresses their core limitations: Autellix ignores workflow locality causing KV thrashing, while Continuum's static TTL predictions fail under stochastic tool latencies. The cost model draws on the Space-Time Product formulation from Belady (1966), and the scheduling policy (shortest-first eviction, time-decay priority) is grounded in a formal proof of optimality under the quadratic recomputation cost of attention. Unlike prior disaggregated approaches (MegaFlow, RollArt, AgentRL) that treat inference and tool execution as isolated black boxes, ThunderAgent unifies them under a single program-aware scheduler with a global waiting queue.

## Why It Matters / Open Questions

As agentic workflows (coding agents, computer-use agents, RL rollout) become the dominant deployment pattern for LLMs, the throughput bottleneck identified here—KV cache thrashing under high concurrency—directly translates to serving cost and RL training speed. The program abstraction is remarkably lightweight (adding a program_id and a release signal to existing OpenAI-style APIs), making it easy to adopt, and it has already been integrated into SkyRL and NVIDIA Dynamo. Open questions include: whether the memoryless assumption on tool execution times (required for the exponential decay proof) holds in practice for increasingly complex multi-tool pipelines, how the approach behaves with heterogeneous model sizes in the same cluster, and whether the global waiting queue's sub-linear communication overhead remains negligible at 100+ node scale. The finding that standard optimizations like PD disaggregation actively harm agentic throughput suggests the field needs workload-specific architectural thinking rather than one-size-fits-all serving optimizations.
