## Problem

When LLM-based multi-agent systems (MAS) are scaled by adding new specialized agents, the router cold-starts on unfamiliar agents and makes mis-routing decisions that cause end-to-end performance collapse rather than improvement. Existing routing and orchestration methods assume a static agent pool and lack a controlled, conservative update mechanism that prevents regressions during continual agent augmentation in open-ended systems.
![Teaser figure](../imgs/ICML20264046/cropped_page1_idx0.webp)

## Input / Output

The frozen router LLM receives a task query, the agent cards (descriptions, tools, behavioral characteristics) of all available workers, and an editable natural-language routing memory under a fixed token-length budget K. It outputs an orchestration plan (a routing scheme assigning subtasks to specific agents) and, during expansion, an updated memory state consisting of structured routing principles distilled from warm-up evidence. The memory is the sole parameter being optimized; the LLM weights remain frozen throughout, making the system fully training-free.

## Method

MonoScale formalizes sequential agent-pool expansion as a contextual bandit and introduces a two-stage expansion-aware protocol: (1) agent-conditioned task synthesis via a planner-executor-validator loop that generates ~50 warm-up tasks probing the new agent's strengths, interface constraints, and failure modes, and (2) evidence-driven memory update where both successful and failed routing traces are distilled into auditable natural-language routing principles. The update uses a TRPO-style surrogate objective with a KL trust-region constraint to select the best candidate memory from a finite set, always including a conservative fallback that forbids invoking the new agent. A semantic trust region rejects memory candidates that irreconcilably conflict with existing principles. Under a non-interfering expansion assumption, the paper proves a monotonic non-decreasing performance guarantee across onboarding rounds, ensuring the system never underperforms its pre-expansion state.

## Results

On GAIA, MonoScale (Qwen-3-30B-A3B-Instruct router with memory updates) improves overall accuracy from 44.84% at 3 agents to 55.15% at 10 agents, while the same backbone without memory (naive scale-up) degrades from 44.84% to 42.42% over the same range. On the HLE multiple-choice subset, MonoScale improves from 11.70% (3 agents, no memory) to 19.88% (10 agents, with memory), surpassing the static GPT-5 baseline of 19.63%. In the malfunctioning-agent-pool setting, MonoScale maintains stable performance as the pool grows, whereas Gemini-3-Pro without memory exhibits a clear performance collapse.

## Baselines & Comparisons

MonoScale at 10 agents (55.15% GAIA) outperforms the fixed-pool GPT-5 baseline (54.55%) and the fixed-pool DeepSeek-V3.2 baseline (51.52%), and is competitive with Gemini-2.5-Pro (54.55%). On HLE, MonoScale at 10 agents (19.88%) surpasses the static GPT-5 baseline (19.63%) by 0.25 points. Against Gemini-3-Pro (60.61% at 3 agents), MonoScale at 10 agents (55.15%) still trails by ~5.5 points on the clean GAIA pool, but in the malfunctioning-agent-pool setting Gemini-3-Pro suffers a clear performance collapse during scaling while MonoScale remains stable and even improves slightly. The most striking comparison is against the same Qwen-3-30B-A3B backbone without memory: naive scale-up drops from 44.84% to 42.42% as agents grow from 3 to 10, whereas MonoScale rises to 55.15%, a 12.7-point gap at 10 agents that the paper attributes to the expansion-aware memory update rather than backbone strength.

## Relation to Prior Work

MonoScale repurposes the TRPO trust-region surrogate from weight-space policy optimization to a memory-space routing update, where the 'policy' is a frozen LLM conditioned on an editable natural-language buffer. It draws on agent trajectory synthesis (planner-executor-validator loops from benchmark-construction work) but redirects it from generating evaluation data to generating agent-conditioned warm-up probes for router familiarization. The paper positions itself against two prior lines: static-pool MAS routing (MASRouter, RCR-Router) that lacks any online update mechanism, and dynamic model-level routing (UniRoute, StageRoute) that treats the decision unit as a single LLM rather than a heterogeneous agent with tools, memory, and interfaces. The key conceptual departure is formalizing sequential agent-pool expansion as a contextual bandit with a conservative lift, yielding a monotonic non-degradation guarantee that neither prior line provides.

## Why It Matters / Open Questions

The paper addresses a concrete and under-studied failure mode—performance collapse during agent-pool scale-up—that practitioners building evolving MAS will inevitably encounter. The finding that a 30B open-weight router with adaptive memory updates can outperform a GPT-5 fixed-pool baseline suggests that routing adaptability, not backbone strength, is the binding constraint for MAS scaling, which has implications for cost and deployment. Key open questions include: whether the monotonic guarantee holds beyond 10 agents (memory saturation, catastrophic interference), how to integrate retrieval-based routing for million-scale agent catalogs, and whether the non-interfering expansion assumption survives persistent environment drift (shifting APIs, tool deprecations). The onboarding cost per new agent (~50 synthesized tasks × 4 rollouts) is acknowledged but not yet optimized.
