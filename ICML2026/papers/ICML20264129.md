## Problem

Existing LLM leaderboards and tool-use benchmarks evaluate individual components in isolation with heterogeneous schemas, leaving no query-conditioned supervision for learning to recommend complete, deployable agent configurations. As agent marketplaces and on-demand creation frameworks expand the configuration space, there is no principled way to rank which backbone-LLM-plus-toolset combination best matches a user's narrative request.
![Teaser figure](../imgs/ICML20264129/cropped_page2_idx0.webp)

## Input / Output

The system takes a single free-form natural-language query (no persistent user ID or interaction history) and a catalog of 107,721 deployable agents, each encoded as a YAML capability profile A = (M, T) specifying a backbone LLM and a set of external tools. It outputs a top-k ranked list of agents by predicted utility. Supervision is positive-only: each of the 111,179 queries is paired with a small set of suitable agents (top-10 for Part I, top-1 for Part II, top-5 for Part III), yielding 251,103 interaction records with no explicit negatives.

## Method

AGENTSELECT unifies heterogeneous evaluation artifacts into a three-part benchmark: Part I extracts per-query LLM rankings from the Open LLM Leaderboard (23,073 queries × 231 models), Part II builds backbone-agnostic toolkit-only agents from tool benchmarks like ToolGen and ToolHop (76,197 queries × 47,949 agents), and Part III synthesizes compositional (M,T) agents via a retrieval-then-compose pipeline that retrieves candidate backbones and tools, uses an LLM judge to validate plausibility, and logs pseudo-positive interactions (11,909 queries × 59,541 agents). Six method families—matrix factorization, content-aware DNN/TwoTower, graph-based (NGCF, LightGCN, KGAT, SimGCL), embedding-based retrieval (BGE, KaLM, EasyRec), agentic reranking, and generative recommendation (OneRec)—are evaluated under a unified feature protocol. The key empirical finding is a regime shift: ID-based and graph methods excel on Part I's dense reuse but collapse on Parts II/III's long-tail, near one-off supervision, where TwoTower with explicit TF-IDF features achieves the best overall performance by directly matching narrative intent to capability descriptions.

## Results

On the AGENTSELECT benchmark, TwoTower with TF-IDF features achieves the best overall performance across all three parts, reaching nDCG@10 of 0.4422 (Part I), 0.9663 (Part II), and 0.8427 (Part III), with MRR@10 of 0.6791, 0.9588, and 0.9005 respectively. Graph-based methods (NGCF, KGAT, LightGCN) dominate Part I with nDCG@10 above 0.86 due to dense query-agent reuse, but collapse to near-zero on Parts II/III where agents are rarely repeated. In the sparse long-tail regime (Parts II/III), content-aware neural rankers with explicit TF-IDF features outperform dense pretrained encoders (BGE-M3, BERT) and embedding-based retrievers, while in-domain fine-tuned embedding models (KaLM-v2.5*, EasyRec*) close the gap to within ~3 nDCG points of TwoTower(TF-IDF) on Part III.

## Baselines & Comparisons

TwoTower (Huang et al., 2013) with TF-IDF features is the strongest method overall, achieving nDCG@10 of 0.9663 on Part II and 0.8427 on Part III, outperforming all other baselines in the sparse long-tail regime. Graph-based methods (NGCF, KGAT, LightGCN) achieve near-perfect scores on Part I (nDCG 0.87–0.90) where dense query-agent reuse enables collaborative filtering, but degrade catastrophically on Parts II/III (nDCG < 0.31), confirming their fragility under cold-start and one-off supervision. SimGCL (Liu et al., 2023) is the most robust graph method on Part III (nDCG 0.1376) but still trails TwoTower by over 70 points. Among embedding-based retrievers, in-domain fine-tuned KaLM-v2.5* (Zhao et al., 2025) and EasyRec* (Ren & Huang, 2024) reach nDCG 0.8116 and 0.6320 on Part III respectively, with KaLM-v2.5* within ~3 points of TwoTower(TF-IDF); however, both remain far below TwoTower on Part I. GenRec/OneRec (Deng et al., 2025) achieves the highest Part I score (nDCG 0.9404) by exploiting ID-level reuse patterns, but underperforms on Parts II/III (nDCG 0.2780) due to over-selection of training-seen agents. Agentic recommendation (AgentRec built on KaLM-v2.5*) yields virtually no improvement over its underlying retriever (nDCG 0.8118 vs. 0.8116 on Part III), indicating that multi-step LLM reasoning does not add value for single-shot capability matching. MF (Koren et al., 2009) and LightFM (Kula, 2015) are the weakest interaction-based baselines, with MF scoring nDCG 0.0547 on Part III, while LightFM benefits from content features to reach 0.1422 but still lags far behind neural content-aware methods.

## Relation to Prior Work

This paper carves new ground by repurposing heterogeneous LLM evaluation artifacts (Open LLM Leaderboard, ToolBench, ToolHop, ToolGen, etc.)—previously consumed only as diagnostic endpoints—into unified positive-only query-agent interaction supervision for a recommendation task. Conceptually, it sits at the intersection of LLM routing (RouterBench, RouterEval), tool retrieval (ToolRet, ToolGen, MCP-Zero), and classical recommender systems (MF, TwoTower, GNN-based methods), but departs from all three by formulating end-to-end compositional agent configuration ranking as a single query-conditioned problem rather than separate model-selection and tool-selection sub-problems. The method family is standard recommendation (collaborative filtering, content-aware neural rankers, graph propagation, embedding retrieval, generative recommendation) applied to a newly defined item space of (M,T) capability profiles, with no single prior method serving as a direct architectural foundation.

## Why It Matters / Open Questions

AGENTSELECT provides the first unified data and evaluation infrastructure for agent recommendation, filling a gap that component-level leaderboards and routing benchmarks leave open: there was no query-conditioned supervision for learning to rank complete deployable configurations. The revealed regime shift from dense head reuse (Part I) to long-tail near one-off supervision (Parts II/III) has practical implications for how agent marketplaces and on-demand agent frameworks should design their selection layers. Key open questions include extending to dynamic environments where models and tools evolve, modeling compositional bundle effects between backbone and tool choices, and incorporating end-to-end execution feedback as an additional supervision channel beyond static capability descriptions. The benchmark's positive-only, retrieval-constrained construction of Part III pseudo-positives remains a limitation that future work may address with execution-based validation at scale.
