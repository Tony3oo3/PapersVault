## Problem

Existing cybersecurity execution environments either lack agentic task instances or are not designed for training purposes, leaving no scalable, execution-grounded environment for training LLM agents on offensive security tasks. Prior approaches like Cyber-Zero rely on synthetic trajectories that are difficult to verify without runtime, while frontier proprietary models achieve strong CTF performance but their agentic training data is unavailable to open-source LLMs. This paper addresses the absence of a large-scale, reproducible, Dockerized CTF environment that provides verifiable execution feedback for agent training.

## Input / Output

The agent receives a CTF challenge description plus interactive access to a containerized Linux environment with Bash terminal and specialized tools (binary decompilation, GDB debugging, network connection to remote services), capped at 40 interaction turns. During data collection, optional redacted writeup hints are prepended to the prompt and the runtime is augmented with randomized ports, file paths, distractor code, and re-seeded dynamic flags; all hint text is stripped from trajectories before training. The output is a structured JSON trajectory logging every command, intermediate output, and reasoning step, with success defined as capturing the correct flag (verified via SHA-256 hash or dynamic runtime flag).

## Method

CTF-FORGE is an automated pipeline that uses DeepSeek-V3-0324 to generate Dockerfiles, docker-compose.yml, and challenge.json metadata from pwn.college CTF artifacts in ~0.5 seconds per challenge, achieving 98% build-and-serve success across 658 challenges. Trajectories are collected by deploying Qwen3-Coder and DeepSeek-V3-0324 within the ENIGMA+ scaffold (temperature 0.6, top-p 0.95, 6 rollouts, 40-turn cap), with two inference-time techniques to boost yield: redacted CTF writeups as non-referential hints and per-rollout runtime augmentation (randomized ports, path shuffling, distractor injection, dynamic flag re-seeding). Training uses rejection sampling fine-tuning on 486 execution-verified trajectories (capped at 2 per solved challenge, 32K token limit) to fine-tune Qwen3-8B/14B/32B via supervised learning on A100 GPUs (batch 16, lr 5e-6, 2 epochs). The key insight is that a small set of execution-verified trajectories from diverse teacher models, collected with hint-guided inference and runtime perturbation, yields up to 11.6% absolute Pass@1 gains over baselines while using 94.9% fewer trajectories than Cyber-Zero.

## Results

CTF-Dojo-32B achieves 31.9% average Pass@1 across InterCode-CTF (83.5%), NYU CTF (10.4%), and Cybench (17.5%), representing an 11.6% absolute gain over the Qwen3-32B base model (20.3%). This is achieved using only 486 execution-verified trajectories, 94.9% fewer than Cyber-Zero's 9,464 trajectories, while still outperforming Cyber-Zero-32B trained on the same 486-trajectory budget (26.6%) by 5.3 points. The 32B model's performance is comparable to DeepSeek-V3-0324 (30.3%) and approaches Gemini-2.5-Flash (33.4%) and the full-data Cyber-Zero-32B (33.4%).

## Baselines & Comparisons

CTF-Dojo-32B (31.9% avg) outperforms all open-weight baselines: it beats Qwen3-Coder (24.5%) by 7.4 points, Kimi-K2 (25.1%) by 6.8 points, and DeepSeek-V3-0324 (30.3%) by 1.6 points. Against the closest prior open-source method, Cyber-Zero-32B, CTF-Dojo achieves 31.9% with only 486 trajectories versus Cyber-Zero's 9,464 (33.4%), and decisively outperforms Cyber-Zero trained on the same 486-trajectory budget (26.6%) by 5.3 points, demonstrating substantially higher data efficiency. CTF-Dojo-32B approaches but does not match Gemini-2.5-Flash (33.4%) or the full-data Cyber-Zero-32B (33.4%), and remains behind proprietary models Claude-3.5-Sonnet (37.2%) and Claude-3.7-Sonnet (39.0%). The gains are consistent across model scales: CTF-Dojo-14B improves over Qwen3-14B by 7.1% and CTF-Dojo-8B over Qwen3-8B by 4.7%, confirming that execution-grounded training signals transfer effectively across model sizes.

## Relation to Prior Work

This paper extends the trajectory-based training paradigm from software engineering agents (SWE-Gym, SWE-Smith) to offensive cybersecurity, adapting rejection sampling fine-tuning and sample capping strategies to CTF-style vulnerability exploitation. It departs from Cyber-Zero (Zhuo et al., 2025), the closest prior work, by replacing unverified synthetic trajectories with execution-verified trajectories collected in live Dockerized CTF environments, and from inference-time-only systems like ENIGMA and Big Sleep by providing a dedicated training environment rather than relying on proprietary model scaffolding. The CTF-FORGE pipeline also contrasts with prior Docker environment construction for SE tasks, which typically requires human effort or complex multi-agent systems, by achieving fully automated containerization in under a second per challenge.

## Why It Matters / Open Questions

CTF-DOJO fills a critical gap: prior cybersecurity benchmarks (InterCode-CTF, NYU CTF Bench, Cybench, CVE-Bench) are evaluation-only with zero training instances, leaving open-source LLMs without a scalable, verifiable training substrate. The 94.9% data efficiency gain over Cyber-Zero (486 vs. 9,464 trajectories) suggests execution-grounded signals are substantially more informative than synthetic ones, a finding that could reshape how the community approaches agent training in safety-critical domains. Open questions include whether the approach scales beyond 658 challenges, whether reinforcement learning with flag-based rewards can push performance further, and whether the 23% writeup coverage bottleneck limits generalization to underrepresented challenge categories.
