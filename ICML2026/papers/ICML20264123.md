## Problem

Autoregressive decoding imposes a per-token latency floor that scales linearly with output length, making LLM function calling too slow for real-time applications requiring 5–30 Hz control frequencies (sub-100 ms per action). Existing acceleration methods—speculative decoding, grammar-constrained decoding, and quantization—either cap out on short structured outputs or reduce forward passes only marginally, leaving a fundamental gap between LLM capabilities and latency-critical deployment in embodied AI, game AI, and interactive agents.

## Input / Output

The model receives a text prompt containing the user query and tool definitions (JSON schemas), and produces a function call decomposed into up to 8 parallel output streams: one content head, one function-name head, and up to six argument heads. Rather than emitting a single JSON string, the model generates 17 special tokens (<function>, <arg1>–<arg6>, <|null|>, etc.) that absorb all structural delimiters and parameter names, so each head outputs only high-entropy value tokens (~8 tokens per head vs. ~40 for baseline JSON). All heads share the same input prefix and differ only in the appended mode-selecting token, enabling full KV-cache reuse across streams.

## Method

RealtimeTool introduces 17 special tokens that serve a dual role: compressing low-entropy structural tokens (achieving 4–6× token reduction) while acting as mode selectors that condition each parallel head on which component to generate. The architecture decouples function calling into H independent decoding streams (content, function, arg1–arg6) that share a single prefill and prefix KV cache, so end-to-end latency is dominated by the longest single head rather than the sum of all heads. Because autoregressive decoding is memory-bandwidth-bound, batching these 8 parallel heads incurs only +8.2% per-token overhead, effectively exploiting otherwise-idle compute. Training uses LoRA (r=512) targeting MLP layers with head-specific loss weighting and token-level focal weights to balance the skewed argument-count distribution, and each sample is decomposed into 8 parallel sequences sharing an identical prefix. The approach achieves 3–6× end-to-end speedup (up to 9.6× with quantization) while maintaining or improving accuracy across five benchmarks on Qwen models from 0.5B to 14B.

## Results

Across five benchmarks (BFCL-v3, Mobile Actions, SealTools, OpenFunction, ToolAlpaca), RealtimeTool achieves an average overall accuracy improvement of +2.9% and a +7.1% function accuracy gain over Qwen-series baselines, while delivering 3–6× end-to-end speedup on an RTX 4090. The best configuration (RT-Qwen3-4B) reaches 86.0% overall / 99.1% function accuracy with a 3.9× speedup; with AWQ 4-bit quantization, Qwen3-4B attains 61.2 ms P50 latency, enabling 16 Hz real-time control. Token compression yields a 4–6× reduction in output length (mean 4.66×), and 8-head parallel decoding adds only +8.2% per-token overhead.

## Baselines & Comparisons

Against the Qwen2.5/Qwen3 autoregressive baselines, RealtimeTool consistently improves overall accuracy by +0.5% to +3.5% (avg +2.9%) and function accuracy by +7.1% on average, while simultaneously achieving 3.1–4.5× speedup on RTX 4090 with vLLM—meaning the accuracy gain comes *with* faster inference, not at its expense. Against Google's FunctionGemma (270M) on Mobile Actions, RT-Qwen-0.5B wins on both accuracy (69.3% zero-shot vs 58.0%; 86.2% fine-tuned vs 85.0%) and latency (51.0 ms P50 vs 61.1 ms; 74.5 ms P90 vs 139.5 ms), despite having 1.8× more parameters. Against SGLang's jump-forward decoding (the only constrained-decoding method that reduces forward passes), RealtimeTool achieves 4.32× forward-pass reduction versus jump-forward's theoretical upper bound of 1.38× on BFCL-v3, a >3× gap attributable to parallel decoding of high-entropy values rather than merely skipping structural tokens. The paper also validates that combining RealtimeTool with speculative decoding yields up to 3.24× additional forward-pass reduction at >95% token acceptance rate, suggesting a combined theoretical speedup of ~14.6× over vanilla autoregressive decoding.

## Relation to Prior Work

RealtimeTool carves new ground at the intersection of parallel decoding (Medusa, EAGLE) and structured output generation (SGLang jump-forward, Outlines), but departs from both: unlike speculative/parallel decoding methods that accelerate per-token generation and are capped by output length, or constrained decoding that skips deterministic tokens while remaining sequential over high-entropy values, RealtimeTool exploits the structural redundancy and weak causal dependencies specific to function calling to reduce what is generated (4-6× token compression via special tokens) and how it is generated (independent parallel streams for function name and arguments). The special tokens serve a dual role—compression and mode selection—that no prior compression or parallel-decoding method provides, making the two mechanisms mutually reinforcing rather than orthogonal. The approach is explicitly orthogonal to and combinable with speculative decoding (validated at >93% acceptance rate) and quantization, positioning it as a complementary layer in the inference acceleration stack.

## Why It Matters / Open Questions

This work bridges a concrete deployment gap: LLM function calling was previously infeasible at the 10-30 Hz control frequencies required by embodied AI, game AI, and interactive agents, with even OpenVLA achieving only 6 Hz. By reaching 16 Hz on a consumer RTX 4090 with a 4B model, RealtimeTool makes real-time LLM-based control deployable without datacenter infrastructure. Key open questions include whether the argument-independence assumption holds for complex APIs with cascading parameters, whether accuracy gains persist at 30B+ scale, and how the approach extends to vision-language-action models where visual token handling introduces new bottlenecks. The fixed 6-head design and one-time training cost (~5× standard fine-tuning) are practical constraints for rapid iteration across diverse tool schemas.
