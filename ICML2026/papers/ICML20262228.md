## Problem

Frontier LLMs require 5–30 thousand reasoning tokens to solve even basic arithmetic (multiplication, division, exponentiation), and their standard tokenizers split single numbers into multiple subword tokens, compounding the inefficiency. Existing single-token number encodings (xVal, FoNE) fail to support learnable arithmetic algorithms due to limited precision or the non-locality of operations like multiplication in their encoding spaces. The paper asks: what properties must a single-token number encoding satisfy for a neural network to learn near-perfect arithmetic algorithms internally, and can such an encoding be constructed?

## Input / Output

Input is text containing numeric values spanning (−10¹⁵, −10⁻¹⁴] ∪ [10⁻¹⁴, 10¹⁵) with up to 15 significant decimal digits, parsed via regex into dedicated [NUM] tokens. Output is a single [NUM] token whose final hidden state is decoded by a number head (linear layer + sigmoid, threshold 0.5) into a 64-bit binary vector representing the IEEE 754 float64 result. The encoding also concatenates the binary representation of the number's reciprocal to facilitate division learning, and the full vector is zero-padded to match the model's 768-dimensional embedding size.

## Method

BitTokens represents each number as a single token by mapping its IEEE 754 double-precision binary representation (1 sign bit + 11 exponent bits + 52 significand bits = 64 dimensions) to a vector scaled to [−1,1], which is added to a learnable [NUM] embedding. The key structural insight is that the IEEE 754 format separates a logarithmic exponent from a linear significand, so addition reduces to aligning significands by exponent difference and multiplication to adding exponents and multiplying significands—operations that decompose into local, parallelizable Boolean gates over individual bits. A theoretical analysis (Proposition 4.3) proves that sinusoidal encodings (FoNE) cannot support multiplication without a non-local decode-convolve-re-encode pipeline, whereas BitTokens' per-bit independence avoids this. Training uses bit-wise binary cross-entropy loss on the 64-bit target vector, curriculum learning with difficulty-based sampling, and dynamic multi-task rebalancing (harmonic-mean-driven oversampling of weak tasks) across nine numeracy tasks plus FineWeb-10B text, all within a 117M-parameter nanoGPT-2 model trained for 10B tokens.

## Results

In the multi-task setting (10B token budget, nanoGPT-2 117M), BitTokens achieves near-perfect log-sMAPE on all single-step arithmetic tasks: 0.989 for addition, 0.991 for multiplication, and 0.989 for division, while also attaining 0.999 exact match on Min/Max and 1.000 on Interval. BitTokens simultaneously achieves the lowest FineWeb perplexity (48.78) among all methods, confirming that the numeric encoding does not degrade language modeling. In the solo-task setting, BitTokens reaches 0.998 log-sMAPE on addition and 0.995 on division, though it still struggles with multi-step tasks like exponentiation (0.391) and standard deviation (0.354).

## Baselines & Comparisons

BitTokens decisively outperforms both single-token baselines. xVal (Golkar et al., 2023) performs catastrophically on all tasks, achieving only ~0.09 log-sMAPE on arithmetic and near-zero on sorting, due to its limited precision from mapping all inputs to [-5, 5]. FoNE (Zhou et al., 2026) can learn addition (0.809 log-sMAPE) but fails on multiplication (0.300) and division (0.275), confirming the paper's theoretical proof that sinusoidal encodings require non-local decoding for multiplication. Against multi-token baselines, BitTokens also wins: single-digit tokenization achieves 0.893 on multiplication and 0.681 on division, still far below BitTokens' 0.991 and 0.989, while subword tokenization is weakest (0.450 mult, 0.522 div). Notably, BitTokens also achieves the best FineWeb perplexity (48.78 vs. 64.23 for single-digit), indicating the encoding does not harm language understanding. The one area where multi-token methods retain an advantage is the mean task in solo-task training (single-digit 0.965 vs. BitTokens 0.534), attributed to the iterative digit-by-digit generation enabling iterative algorithms.

## Relation to Prior Work

This paper positions itself against two dominant strategies for LLM numeracy—tool-augmented computation and reasoning chains—arguing both are 'crutches' that prevent intrinsic numeric computation. Within the single-token number encoding line, it builds directly on xVal (Golkar et al., 2023) and FoNE (Zhou et al., 2026), but departs by (1) formalizing nine desiderata that prior encodings fail to satisfy, (2) proving via Proposition 4.3 that sinusoidal encodings fundamentally cannot support multiplication without a decode-compute-re-encode cycle, and (3) replacing learned or sinusoidal representations with the deterministic IEEE 754 binary floating-point bit pattern. The experimental protocol uses nanoGPT-2 (117M params) with curriculum learning and dynamic task balancing, following the small-model controlled-experiment paradigm suggested by Allen-Zhu (2024).

## Why It Matters / Open Questions

If BitTokens scale to production LLMs, they could eliminate the 5–30K reasoning tokens currently required for single arithmetic operations, freeing context window for genuinely complex multi-step problems. The theoretical impossibility result for sinusoidal encodings provides a clear design principle: number representations must expose individual bits to enable direct algorithmic learning. Key open questions include integration into large pretrained models, interaction with natural-language math word problems, precision/formatting control in open-ended generation, and whether the encoding's benefits persist at frontier scale where other inductive biases may dominate.
