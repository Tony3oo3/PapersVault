## Problem

Current software engineering agents operate statelessly, treating each coding session as independent and lacking explicit mechanisms to infer and track user intent across long-horizon, multi-turn interactions. When instructions are underspecified or context-dependent, agents cannot leverage a user's evolving preferences, coding conventions, or communication style from prior sessions, leading to misaligned outputs and wasted effort. This paper addresses the gap by integrating theory-of-mind reasoning into SWE agents and introducing a benchmark that evaluates stateful, multi-session user modeling.

## Input / Output

The system consumes ambiguous user coding instructions, full prior session histories with the same user (retrieved via BM25 over a three-tier memory store), live environment observations (terminal output, file contents, test results), and real-time user feedback during interaction. The ToM agent produces structured suggestions with confidence scores (0–1) that are injected into the SWE agent's context, while the after-session pipeline outputs updated JSON user models spanning raw session logs, per-session intent/preference analyses, and an aggregated cross-session profile. Evaluation outputs include SWE-bench unit-test pass rates and LLM-simulator satisfaction scores (1–5) across five dimensions conditioned on the specific developer profile.

## Method

ToM-SWE pairs a CodeAct-based SWE agent with a dedicated ToM agent through two tool calls: consult_tom (in-session) lets the SWE agent query the ToM agent for user mental-state information, and update_memory (after-session) triggers the ToM agent to consolidate the completed session into its hierarchical memory. The ToM agent maintains a three-tier external memory—raw session storage, session-based user models (intent, emotion, message-level preferences), and an overall user model (preference clusters, interaction style, coding style)—and during consultation it can perform up to three search/read actions over tiers 1–2 before issuing structured suggestions. The separation of user modeling from code execution reduces context distraction for the SWE agent and allows each agent to be optimized for its domain. The paper also introduces the Stateful SWE benchmark, which pairs 500 SWE-bench-verified issues with 15 developer profiles (derived from 453 real consented sessions) and conditions GPT-5-powered user simulators on those profiles, requiring agents to both interact with the simulated user and exploit prior session histories to resolve tasks.

## Results

On the Ambiguous SWE-bench, ToMCodeAct achieves a 63.4% task resolved rate with Claude Sonnet 4, compared to 51.9% for the CodeAct baseline (+11.5 pp). On the newly introduced Stateful SWE-bench, ToMCodeAct reaches 59.7% resolved rate versus 18.1% for CodeAct (+41.6 pp), a substantially larger gap reflecting the importance of persistent user modeling. User simulator satisfaction scores on Stateful SWE-bench rise from 2.57 (CodeAct) to 3.62 (ToMCodeAct) with Claude 4, a 41% improvement. In a three-week in-the-wild study with 17 professional developers, ToM suggestions were accepted or partially accepted 86.2% of the time across 174 suggestions.

## Baselines & Comparisons

The paper compares three agent variants—CodeAct (no user modeling), RAGCodeAct (raw session retrieval), and ToMCodeAct (dual-agent with hierarchical user memory)—across two benchmarks and three base models. ToMCodeAct consistently outperforms CodeAct on both task resolved rate and user satisfaction across all model variants. The gap is most dramatic on Stateful SWE-bench: with Claude Sonnet 4, ToMCodeAct resolves 59.7% of tasks versus 18.1% for CodeAct, a 41.6 pp improvement, while on Ambiguous SWE-bench the gain is 63.4% vs. 51.9% (+11.5 pp). RAGCodeAct, which retrieves raw session data without explicit mental-state reasoning, provides only marginal gains over CodeAct and can even hurt performance (e.g., dropping from 18.7% to 14.4% resolved rate with Claude 3.7 Sonnet), confirming that structured ToM reasoning over interaction history is essential rather than simple retrieval. On user satisfaction, ToMCodeAct leads by 1.05 points over CodeAct (3.62 vs. 2.57) with Claude 4, and also achieves the highest F+H rate (21.5%), indicating users reward process quality and preference alignment even when the final task is not resolved.

## Relation to Prior Work

This paper builds directly on the CodeAct agent architecture (Wang et al., 2024) and the SWE-bench evaluation paradigm (Jimenez et al., 2024), extending them with a dedicated theory-of-mind agent that maintains a three-tier hierarchical memory of user preferences and interaction history. It departs from Ambiguous SWE-bench (Vijayvargiya et al., 2026), which handles single-session underspecification, by introducing multi-session stateful user modeling, and from prior ToM work in multi-agent collaboration (Li et al., 2023) and social-intelligence benchmarks (FANToM, SOTOPIA) by grounding ToM specifically in software engineering workflows. The hierarchical memory design draws on agent memory systems like MemGPT and Mem0 but specializes them for coding-preference tracking rather than general conversation context.

## Why It Matters / Open Questions

The paper demonstrates that explicit user mental-state modeling yields large gains in both task resolution and interaction quality for SWE agents, and that simply retrieving raw session history (RAG) is insufficient—and can even hurt performance with weaker base models—without structured abstraction into preference constraints. The newly introduced Stateful SWE benchmark provides the first evaluation setting for multi-session, user-aware SWE agents, filling a gap left by SWE-bench and Ambiguous SWE-bench. Open questions include generalization beyond software engineering, privacy-preserving deployment of persistent user models, and how to balance proactive user modeling with user effort in collaborative workflows.
