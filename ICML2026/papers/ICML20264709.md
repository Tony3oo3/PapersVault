## Problem

CodeLLMs exhibit a significant performance gap between high-resource PLs (e.g., Python) and low-resource or complex-syntax PLs (e.g., Lua, C++, Java), limiting their practical usability in multilingual development. Existing remedies—fine-tuning with translated code or standard test-time scaling—either incur high training costs or fail to address the fundamental data scarcity of low-resource PLs. The paper tackles the question of how to transfer a model's functional knowledge from high-resource to low-resource PLs purely at inference time, without retraining or external models.

## Input / Output

The method takes a natural language problem description and a target programming language, and produces a single code solution in that target PL. Internally, it also synthesizes 10 test inputs (prompted from the CodeLLM) and generates high-resource reference implementations (e.g., in Python) that are executed to build I/O test oracles. Cross-lingual output comparison is handled by a unified serialization protocol that normalizes primitives (e.g., C++ true vs. Python True), unfolds complex structures into atomic value streams, and applies floating-point tolerance for numeric comparisons.

## Method

CodeChemist is a training-free, uncertainty-aware test-time scaling framework built on the insight that test cases encode PL-agnostic functional knowledge. It first applies multi-temperature hedged sampling (temperatures 0, 0.7, 0.9, 1.1 yielding 1+3+3+3=10 candidates) to generate a diverse pool of target-PL programs alongside synthesized test inputs. It then estimates uncertainty by clustering candidates on both execution outputs and AST similarity; if both cluster counts fall below thresholds (δ_ext=1, δ_ast=2), it selects via in-language majority voting at no extra cost. Otherwise, it triggers cross-lingual knowledge transfer: it generates high-resource reference programs, executes them on the same test inputs to construct I/O oracles via majority voting, and selects the low-resource candidate with the highest pass rate against those oracles. This adaptive routing avoids the overhead of always constructing cross-lingual oracles, yielding ~2× fewer tokens and ~4× faster inference than S* while outperforming it in accuracy.

## Results

On MultiPL-HumanEval (Pass@1), CodeChemist achieves 57.8 on Lua with Qwen-1.5B (vs. 34.1 Vanilla, a 69.5% relative gain) and 82.6 with Qwen-32B (vs. 78.0 Vanilla). On the harder Ag-LiveCodeBench-X benchmark, DeepSeek-V3 enhanced by CodeChemist reaches 50.5 Pass@1 on Lua, surpassing the official leaderboard's top entry of 43.0 at the time of evaluation. Relative improvements range from 5.9%–80.6% on Lua, 2.2%–51.7% on C++, and 4.9%–60.0% on Java across all tested models, with the largest gains occurring where the high-resource-to-low-resource performance gap is widest.

## Baselines & Comparisons

CodeChemist outperforms all four main baselines (Majority Voting, LLM Judge, Self-Debugging, and S*) on the majority of model–language combinations. The advantage is most pronounced on the low-resource PL Lua with smaller models: on Qwen-1.5B, CodeChemist scores 57.8 vs. S* (50.9), LLM Judge (51.6), Self-Debugging (47.8), and Maj Voting (45.3). On C++ and Java, CodeChemist also leads, e.g., 55.3 vs. S* (46.0) and Maj Voting (49.1) on C++ with Qwen-1.5B, and 70.3 vs. S* (67.1) and Maj Voting (62.7) on Java. In the strongest-model setting (DeepSeek-V3), CodeChemist ties or slightly exceeds Maj Voting on Lua (88.2 vs. 88.2) and leads on C++ (95.7 vs. 93.2) and Java (93.7 vs. 93.0), while S* actually degrades slightly below Vanilla on Lua (82.0 vs. 82.1). In the supplementary comparison (Table 8), CodeChemist also beats CodeT and MBR-Exec across all tested models and PLs, with the gap widening for smaller models where CodeT's model-generated test assertions are noisier.

## Relation to Prior Work

CodeChemist sits at the intersection of three research threads: cross-lingual code transfer (TransCoder-ST, MultiPL-T, Bridge-C), test-time scaling via Best-of-N sampling (S*, CodeMonkeys, self-consistency), and execution-based test verification (CodeT, GenX). It departs from fine-tuning-based cross-lingual methods by operating entirely at inference time, and from S* by eliminating the need for an external model—instead using the same CodeLLM to generate high-resource reference programs whose executed outputs serve as ground-truth oracles. The uncertainty-aware adaptive selection (combining execution clustering with AST similarity) is the paper's key architectural contribution, routing between cheap in-language voting and expensive cross-lingual oracle construction based on measured candidate-pool consistency.

## Why It Matters / Open Questions

The paper demonstrates that a training-free, single-model test-time procedure can close a substantial portion of the high-resource/low-resource PL gap (up to 69.5% relative on Lua for small models, and still 7.4% for DeepSeek-V3), which is practically significant for multilingual development environments where retraining is infeasible. The uncertainty-aware routing yields a 2× token and 4× time reduction over S* while outperforming it, making the approach deployable. Key limitations remain: the method is bounded by the model's ability to solve the problem in the high-resource PL (failure analysis shows >90% conditional failure transfer), it is validated only at the function level, and I/O equivalence may not capture non-functional semantics (parallelism, memory behavior). Extending to repository-level generation and tasks where even Python solutions are unreliable are open directions.
