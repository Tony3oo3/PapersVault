## Problem

Existing KV cache compression methods for long-context LLM inference either apply eviction only after full-context prefill (causing peak memory to grow linearly with input length, infeasible on resource-constrained devices) or use query-dependent eviction that narrows cache semantics to a single query, degrading accuracy in multi-turn conversations where later turns require evidence evicted for earlier ones. No prior framework simultaneously bounds peak memory and preserves topic-relevant context across an entire multi-session dialogue under a fixed cache budget.

## Input / Output

The method takes a long conversational history (multi-day, multi-session dialogues of 20K–100K+ tokens, segmented into utterance-level windows of w_embed=4) and a sequence of user queries. It produces per-query answer text generated from a compressed episodic KV cache, with peak memory strictly bounded to M + M_block entries (e.g., 8K + 128 tokens). The offline stage outputs E episode-specific compressed caches and centroid embeddings stored for retrieval; the online stage retrieves one cache per query and appends newly generated KV pairs back to it, creating new episodes when a query falls below a cosine-similarity threshold τ to all existing centroids.

## Method

EpiCache is a training-free, three-stage KV cache management framework. Stage 1 segments the dialogue into utterance-level windows, embeds them with a lightweight encoder (Qwen3-Emb-0.6B), and clusters them via K-Means into E semantically coherent episodes, selecting the centroid-closest segment of each cluster as a patched prompt. Stage 2 performs block-wise prefill over the entire history for each episode, appending its patched prompt after every M_block-token block and evicting down to M tokens using max-attention scoring (Eq. 3), yielding E topic-specific compressed caches under a fixed memory budget. Stage 3 embeds each incoming query, matches it to the nearest episode centroid, retrieves the corresponding cache for decoding, and updates it with newly generated KV pairs (or creates a new episode for out-of-distribution topics). A key differentiator is a sensitivity-aware layer-wise budget allocation: the paper measures per-layer Key-state cosine similarity under full vs. block-prefill masks in a single calibration forward pass, then redistributes the global budget proportionally to each layer's deviation score raised to a sharpness exponent α, shifting KL divergence by −0.80 relative to uniform allocation and improving LongConvQA accuracy by up to 30% over baselines while reducing peak memory by 3.7× and decoding latency by 2.4×.

## Results

On Realtalk with Qwen3-4B at M=8K, EPICACHE achieves 54.6/50.8/55.7 (Single/Cross/Temporal) versus FullKV's 60.3/55.4/61.7, closing the gap to within ~5 points under 4× compression. At M=4K, EPICACHE scores 45.3/40.3/41.5 on Realtalk, outperforming KVzip (26.7/21.8/22.8) by up to 19 points. In the efficiency analysis with LLaMA3.2-3B over 300 turns of 90K-token history, EPICACHE reduces peak GPU memory from 36.3 GB to 9.6 GB (~4×) and total latency from 9,339 s to 545.4 s (~18×), while maintaining comparable QA accuracy (45.6 vs. 46.2).

## Baselines & Comparisons

EPICACHE consistently outperforms all seven baselines across every benchmark and cache budget. Against the strongest KV compression baseline KVzip, EPICACHE gains 18.8 points on RealTalk Single-hop at M=4K (45.3 vs. 26.7) and 17.1 points at M=8K (54.6 vs. 37.5); on LoCoMo the gap is 10.3 points at M=4K (29.8 vs. 13.7). Retrieval-based RAG-2K degrades sharply on Temporal queries (22.4 at 8K on RealTalk vs. EPICACHE's 55.7), reflecting its inability to preserve cross-episode dependencies. Among the remaining KV compression methods (StreamingLLM, SnapKV, KeyDiff, InfiniPot), EPICACHE leads by 5–15 points on Realtalk averages at M=8K (e.g., 34.6 vs. InfiniPot's 31.0 and SnapKV's 28.0 on LLaMA3.2-3B). OracleKV, evaluated in Figures 5–6, is also outperformed by EPICACHE across all budgets. The advantage is most pronounced at low budgets (2–4K), where EPICACHE's episodic structure preserves topic-relevant context that query-agnostic or query-dependent eviction methods discard.

## Relation to Prior Work

This paper extends the block-prefill eviction paradigm introduced by InfiniPot and FINCH, which process input in fixed-size blocks and evict KV entries after each block to bound memory. It departs from prior query-dependent eviction methods (SnapKV, KVzip) that score tokens against a single current query, by instead using K-Means clustering over conversation segments to construct multiple topic-specific (episodic) caches, each built with a different patched prompt. The sensitivity-aware layer-wise budget allocation draws on the attention-sink masking mechanism from StreamingLLM to simulate block prefill in a single forward pass, but introduces a novel Key-state-deviation metric to redistribute the global KV budget across layers. The overall contribution is the first framework combining bounded-memory block prefill with episodic organization and adaptive allocation specifically for multi-turn LongConvQA.

## Why It Matters / Open Questions

This work makes long-term conversational AI feasible on resource-constrained devices (e.g., smartphones) by achieving near-full-cache accuracy at 4–6× compression while reducing peak memory by up to 3.7× and decoding latency by 2.4×, all without any training. Open questions include whether the fixed episode count (E=4) generalizes to highly heterogeneous or very long dialogues, how the method handles information updates and deletions over time, and whether more sophisticated conversational embeddings or adaptive episode selection could further close the remaining gap to full KV. The finding that a single calibration sample suffices for layer sensitivity profiling (model-dependent, not data-dependent) simplifies deployment but leaves open whether this holds for fine-tuned or domain-specific models.
