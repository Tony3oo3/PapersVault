## Problem

Existing prompt injection defenses are evaluated solely on attack success rate, which cannot distinguish a model that faithfully processes injected text as task data from one that simply suppresses it. This conflation hides a security-fidelity tradeoff: defenses that achieve high security by suppressing instruction-like content silently corrupt tasks that must preserve that content, such as translation and document editing. The paper asks whether any model or defense achieves both objectives simultaneously and what determines the correct operating point for a given deployment.

## Input / Output

Each SECFID instance pairs a trusted task instruction with untrusted data containing an injected adversarial probe, constructed under a behavioral-separability constraint so that executing, processing, and ignoring the probe yield three distinguishable outputs. Evaluation decomposes behavior into two independent axes: execution detection (presence of a self-verifying signature answer) and task-output labeling (PROCESSED vs. IGNORED vs. OTHER via embedding similarity for full-text tasks or set-membership/numeric checks for partial-text tasks), producing four marginal rates rather than a four-way partition. The benchmark spans 1,168 instances across four task families with varied probe placement (prefix, inside, suffix) and attack framing (plain, naive, context-ignoring, fake-completion, combined).

## Method

The paper introduces SECFID, a benchmark whose core design principle is behavioral separability: each instance must make execution, processing, and ignoring the probe produce distinguishable outputs, enabling fidelity to be measured alongside security. Across 48 model-defense configurations, the paper maps an empirical security-fidelity frontier showing no system achieves both objectives, and reveals that defenses with matched hijack rates reach security through opposite mechanisms—SECALIGN repairs former hijacks into faithful processing while DefensiveTokens suppresses them. A fidelity-aware DPO fine-tuning experiment leverages the three-way labels with the preference ordering PROCESSED ≻ IGNORED ≻ EXECUTED to shift SECALIGN toward repair while preserving security, improving processing from 43.2% to 80.6% on an unseen editing task. A decision-theoretic analysis formalizes why no fixed policy is optimal: the correct process-versus-filter threshold depends on the deployment's relative cost of a hijack versus a dropped span, bounding what any model capability can achieve.

## Results

Across 1,168 SECFID examples and 48 model-defense configurations, no system achieves both high security and high fidelity: the highest-fidelity model (Llama 3.3 70B) reaches 96.5% fidelity at only 47.8% security, while the most secure defenses (SECALIGN on Llama 3.1 8B and 3.3 70B) reach 99.3% security at 71.0–73.9% fidelity. Among the four defenses, SECALIGN produces the largest average execution reduction (−50.0 ± 2.2 pts) and the only positive average processing shift (+14.9 ± 2.7 pts), whereas DefensiveTokens causes the largest fidelity loss (+42.0 ± 5.7 pts increase in ignoring). Fidelity-aware DPO applied to SECALIGN-8B recovers much of the lost fidelity on the unseen edit task, raising processing from 43.2% to 80.6% while keeping execution below 1%.

## Baselines & Comparisons

SECALIGN dominates on both axes: it achieves the largest average execution reduction (−50.0 pts) and is the only defense that increases the processing rate on average (+14.9 pts), repairing 54.0% of base-model hijacks into faithful processing on Llama 3.1 8B. DefensiveTokens reaches comparable security (−38.2 pts execution reduction) but does so by suppressing rather than repairing, raising the ignore rate by +42.0 pts and lowering processing by −17.7 pts; it repairs only 26.8% of hijacks versus SECALIGN's 54.0%. ISE is the mildest defense, reducing execution by only −24.0 pts on average with a near-neutral processing shift (−1.0 pts), while ASIDE sits in between (−34.1 pts execution, −14.8 pts processing). On the agentic InjecAgent extension, SECALIGN variants (94–98% security) still trail frontier APIs (100% security) slightly on security but all suffer severe fidelity loss (31.7–37.3% for SECALIGN vs. 53.2–72.6% for closed-source models), confirming the tradeoff generalizes beyond the core benchmark.

## Relation to Prior Work

This paper departs from the standard prompt-injection evaluation paradigm, which measures only whether a model executed an injected instruction (attack success rate), by arguing that non-execution is ambiguous: a model may have processed the injected text as task data or silently suppressed it, and both score identically under existing metrics. It builds directly on SECALIGN (Chen et al., 2025b) as the base checkpoint for its fidelity-aware DPO experiment, and positions its four compared defenses (ASIDE, DefensiveTokens, ISE, SECALIGN) within the broader instruction-data separation literature. The conceptual contribution is a new evaluation axis—fidelity as non-suppression—paired with a decision-theoretic formalization showing the optimal process-or-filter threshold is deployment-specific, a framing absent from prior prompt-injection work that reports a single security score.

## Why It Matters / Open Questions

The finding that no model or defense across 48 configurations achieves both high security and high fidelity reframes prompt-injection defense from a single-objective problem to a tradeoff that must be navigated per deployment, with the correct operating point set by the relative cost of a hijack versus a dropped span. The repair-versus-suppression distinction among defenses with matched security rates is actionable: practitioners choosing a defense must now ask not just 'does it reduce execution?' but 'does it reduce execution by repairing or by over-filtering?' Key limitations include the use of fixed, non-adaptive probes (adaptive attacks may shift the frontier), the binary process/filter abstraction that omits richer actions like preserving content while stripping authority, and the fidelity-aware DPO demonstration being limited to a single model family. Open questions include whether the tradeoff persists under adaptive attacks, whether richer defensive actions can escape the frontier, and how to make defense robustness tunable at deployment time.
