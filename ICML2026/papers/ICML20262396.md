## Problem

LLM agent system prompts encode valuable intellectual property but are vulnerable to theft in untrusted deployments, where adversaries can copy and reuse them on other proprietary LLMs. Existing protections—watermarking, encryption, and prompt obfuscation—fail to simultaneously satisfy four requirements: proactivity, runtime protection, usability on the target model, and non-portability to other models, particularly under black-box API access where no model internals are available.

## Input / Output

The method takes an original natural-language agent system prompt, a task training set of input-output pairs, and black-box API access to the target LLM (including top-k log-probabilities) as inputs, and produces a single obfuscated prompt string as output. The obfuscated prompt is a fixed prefix that can be KV-cached across requests, uses ASCII characters (0–127) as its noise alphabet, and may be longer than the original prompt. The target LLM must have a tokenizer with broad character coverage so that injected noise maps to valid subword/byte tokens rather than unknown tokens.

## Method

PragLocker is a two-phase black-box pipeline. Phase 1 (initialization) prompts the target LLM to rewrite the original prompt into a code-symbol/XML-like DSL format, producing a non-natural-language representation that preserves task semantics while introducing structural redundancy. Phase 2 (obfuscation optimization) applies random search over character-level noise injections: at each step, a random subset of characters is replaced with noise from the ASCII set, and the candidate is accepted only if a composite objective—combining cross-entropy task loss, Levenshtein distance from the original prompt, and negative Shannon entropy (pushing away from natural-language distribution)—decreases. A noise annealing schedule (analogous to learning-rate decay) reduces the number of characters perturbed per step over 50 epochs. The theoretical motivation rests on an existence theorem: within the model's stability region (where greedy-decoding outputs are preserved), there exist prompts at arbitrary edit distance from the original, and due to manifold mismatch between models, such a perturbation optimized for one model's loss landscape is highly unlikely to fall within another model's stability region, yielding non-portability.

## Results

PragLocker reduces cross-LLM prompt portability to 0.20× the unprotected baseline (1.00×), meaning a stolen prompt achieves only ~20% of its original cross-model utility. On the target LLM, performance is essentially preserved at 1.01× (e.g., LessonL/HumanEval: 94.51% vs. 93.90% original; A-Mem/LoCoMo: 25.11% vs. 24.61%). Even within the same model family (Qwen2.5-7B → 14B), portability drops from ~16–19 F1 to ~6–9 F1. Against adaptive attacks, deobfuscation yields only 1.03× relative gain and LLM-assisted recovery only 3.49×, far below the unprotected 1.00× portability level.

## Baselines & Comparisons

The paper does not compare against external prompt-protection methods (watermarking, encryption, white-box obfuscation) because those operate under incompatible assumptions (e.g., white-box access or post-hoc verification). Instead, it uses two internal ablation baselines: PragLocker_code (code-symbol initialization only, no optimization) and PragLocker_tune (noise-injected optimization only, no initialization). Full PragLocker (0.20× portability) dramatically outperforms both: PragLocker_code is nearly as portable as no protection (0.99×) because code-form prompts remain broadly interpretable by other LLMs, while PragLocker_tune only partially reduces portability (0.82×) because optimizing from a natural-language start leaves residual semantic structure. The two stages are complementary: code transformation provides a non-natural-language scaffold and expands the optimization search space, while noise-injected optimization couples the prompt to target-model-specific feedback dynamics. Against adaptive attacks, even a deobfuscation attack (inverting the optimization objective) achieves only 1.03× relative gain, and a naive self-prompting baseline (4.78×) actually outperforms deobfuscation, suggesting the obfuscated prompt retains little recoverable text-level semantics.

## Relation to Prior Work

This paper departs from three existing lines of prompt protection: passive watermarking (PromptCARE, PromptCOS), encryption-based schemes that fail at runtime, and prompt obfuscation methods (EmojiPrompt, Pape et al.) that either remain portable across LLMs or require white-box model access. PragLocker's core technical contribution is applying random search (Rastrigin, 1963) with a composite objective (task loss + Levenshtein distance + Shannon entropy) to construct model-specific obfuscated prompts under pure black-box API access, a setting where prior obfuscation methods are inapplicable. The theoretical motivation draws on stability-region and manifold-mismatch arguments from adversarial robustness, formalizing why a perturbation tuned to one model's decision boundaries is unlikely to transfer to another.

## Why It Matters / Open Questions

This is the first systematic treatment of prompt non-portability as a protection requirement for LLM agents deployed in untrusted environments, a setting that is increasingly common (Cursor, Manus, Zapier). The finding that even the target LLM cannot reliably interpret its own obfuscated prompt—behaving instead as a model-conditioned trigger—raises open questions about the nature of prompt semantics in transformer architectures and whether text-level recoverability is fundamentally incompatible with strong obfuscation. Key limitations include protection scope (only the prompt itself, not against imitation or distillation attacks), tokenizer compatibility assumptions, and the fact that the deobfuscation attack, while ineffective, is weaker than simply asking the LLM to write a fresh prompt, suggesting the threat model may be more nuanced than the paper acknowledges.
