## Problem

Large kernel depthwise convolutions provide large receptive fields but suffer 71–94% throughput degradation as kernel size grows, because gather-based computation causes increasingly irregular memory access. Existing Large Kernel Acceleration (LKA) CUDA kernels mitigate this only on small feature maps and become 80–89% slower than the non-accelerated baseline on large feature maps (≥224×224), blocking deployment in segmentation, detection, and super-resolution tasks that operate at high resolution.

## Input / Output

The method consumes standard RGB images at arbitrary resolutions (zero-padded to align with the window grid) and produces task-specific outputs: class labels on ImageNet-1K, per-pixel segmentation masks on ADE20K (via UPerNet), and bounding boxes with instance masks on COCO (via Cascade Mask R-CNN). A distinguishing operational detail is that WBMM's weight matrix is input-independent and can be cached at inference, so the same cached matrix is reused across all samples and windows in a batch, unlike attention-based alternatives that rebuild input-dependent matrices per sample.

## Method

WBMM replaces the gather-based depthwise convolution with a 'partition-then-index' scheme: the input feature map is split into contiguous non-overlapping windows (e.g., 7×7 or 14×14), and a per-channel weight matrix M ∈ R^{C×d×d} is constructed by indexing into a compact relative position bias table R ∈ R^{C×(2w_h−1)(2w_w−1)} via a precomputed integer index matrix I. The output is then computed as a single batched matrix multiplication (bmm) over contiguous memory blocks, shifting the operator from memory-bound to compute-bound. This design yields a counterintuitive property—throughput improves with larger windows (up to 3.72× speedup at batch 256) and with larger feature maps—because arithmetic intensity scales as O(w²) FLOPs per loaded element. Three lightweight components complete the architecture: inter-block 3×3 depthwise convolutions for cross-window communication, inference-time weight-matrix caching that eliminates redundant indexing, and hierarchical window reparameterization that fuses a 14×14 global matrix with 7×7 local sub-window patterns at inference for dense-prediction accuracy at zero additional runtime cost.

## Results

On ImageNet-1K, WBMM matches UniRepLKNet accuracy (83.2% Top-1 for Tiny, 83.9% for Small) while achieving 1.31–1.88× training speedup and 8–12% memory reduction. On ADE20K semantic segmentation, WBMM with hierarchical reparameterization reaches 48.8% mIoU (Tiny) and 50.6% (Small), surpassing UniRepLKNet's 48.6% and 50.5%. On COCO object detection, WBMM (Hier) achieves 51.9% AP_box / 45.1% AP_mask (Tiny) and 53.1% / 46.1% (Small), outperforming UniRepLKNet by 0.1–0.2 points. At the operator level, WBMM-C with 14×14 windows provides a 7.8× larger per-layer receptive field than DW-Std 5×5 while being up to 3.72× faster at batch=256.

## Baselines & Comparisons

Against UniRepLKNet (the primary baseline), WBMM matches ImageNet-1K Top-1 within 0.1% across all four model scales while delivering 1.31–1.88× training speedup and 8–12% lower memory; on ADE20K, WBMM with hierarchical reparameterization exceeds UniRepLKNet by +0.2 mIoU (Tiny, 48.8 vs 48.6) and +0.1 mIoU (Small, 50.6 vs 50.5), and on COCO it leads by +0.1 AP_box / +0.2 AP_mask (Tiny) and +0.1 / +0.2 (Small). Against SLaK (ICLR 2023), both SLaK-style decomposition and SLaK-Original underperform WBMM on dense prediction (47.2/47.4 vs 48.3/48.8 mIoU) and are 2.4–3.4× slower in both training and inference, despite SLaK's larger effective receptive field of 51. Against ConvNeXt (CVPR 2022), a drop-in WBMM replacement on ConvNeXt-T preserves Top-1 exactly (82.1%) and slightly improves mIoU (46.2 vs 46.0) while accelerating training by 1.66× (5:08 vs 8:30 per epoch), confirming architecture-agnostic efficiency gains.

## Relation to Prior Work

WBMM sits at the intersection of three research threads: (1) the large-kernel CNN lineage from ConvNeXt (7×7) through RepLKNet (31×31) and UniRepLKNet (13×13), which established that large receptive fields improve accuracy but suffer from gather-based memory access; (2) Swin Transformer's non-overlapping window partitioning, which WBMM adapts from attention to a purely linear, input-independent weight-matrix setting; and (3) structural reparameterization (RepVGG, RepLKNet), which WBMM extends with a hierarchical dual-scale window fusion. The key conceptual departure from all prior large-kernel methods is inverting the traversal direction: instead of gathering scattered input neighborhoods per output position, WBMM indexes a compact relative-position bias table to construct a per-channel weight matrix and applies it via batched matrix multiplication on contiguous windows, converting a memory-bound gather into a compute-bound GEMM.

## Why It Matters / Open Questions

The practical impact is significant for anyone deploying large-kernel CNNs on high-resolution feature maps (segmentation, detection, super-resolution): WBMM delivers 1.31–1.88× training speedup with comparable or slightly better accuracy, requires no specialized CUDA kernels, and generalizes across GPU, CPU, and edge devices. The negative result that LKA-accelerated kernels become 80–89% slower than the non-accelerated baseline on large feature maps is an important correction to the field's understanding of when specialized kernels help. Open questions include whether input-dependent gating over the cached weight matrix could recover the content-adaptivity that window attention provides, whether the windowed approximation loses information at very large effective receptive fields, and how WBMM interacts with quantization-aware training beyond the INT8 inference benchmarks shown.
