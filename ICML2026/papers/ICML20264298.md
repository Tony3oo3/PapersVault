## Problem

LLM agents on long-horizon tasks are fundamentally limited by linear context accumulation, which degrades reasoning quality and incurs quadratic attention costs. Existing mitigations—post-hoc summarization and handcrafted multi-agent pipelines—are either disruptive to the agent's reasoning flow or too rigid to generalize and resist end-to-end optimization. The paper asks whether context management can be turned into a learned, active skill rather than an external architectural feature.

## Input / Output

The agent receives a text query (e.g., a research question or a GitHub issue) and operates within a tool environment providing search, page-opening, bash execution, and file-editing capabilities. Rather than producing a single linear trajectory, the agent outputs a tree-structured interaction: a main thread interleaved with up to 10 sub-branches, each of which is collapsed into a one-line summary upon return. The active working context is capped at 32K tokens at any point, while the total token budget across all branches can reach 327K, making the output a compact, folded history rather than the full interaction log.

## Method

Context Folding introduces two special tool actions—branch(description, prompt) to spawn a sub-trajectory with its own working context, and return(message) to fold all intermediate steps into a concise summary and rejoin the main thread—so the agent actively decides when to offload token-intensive operations. Training is done end-to-end via FoldGRPO, which augments standard GRPO in two ways: (i) the context manager F is applied to the rollout history so that each token is optimized under its folded (not full) context, and (ii) dense token-level process rewards are added to the advantage estimate, including an Unfolded Token Penalty (−1 on main-thread tokens when context exceeds 50% of budget) to push heavy operations into branches, an Out-of-Scope Penalty (−0.2, judged by GPT-5 nano) to keep branches focused, and a Failure Penalty (−1) on failed tool calls. The agent is instantiated in a plan-execution loop where the main thread handles high-level strategy and branches handle execution, with nested branching disabled to keep the structure flat. At inference, folding is KV-cache-friendly: a return action simply rolls the cache back to the pre-branch prefix, avoiding recomputation.

## Results

On BrowseComp-Plus (N=150), the Folding Agent trained with FoldGRPO achieves a pass@1 of 62.0% using only a 32K active context (with up to 10 branches, totaling 320K tokens), surpassing the 327K-context ReAct baseline (47.8%) by +14.2 points. On SWE-Bench Verified (N=500), it reaches 58.0% pass@1, outperforming the same 327K ReAct baseline (55.2%) by +2.8 points. The RL training (FoldGRPO vs. standard GRPO) provides an additional +14.2 points on BrowseComp-Plus and +2.8 points on SWE-Bench over the untrained folding agent, and the agent makes 19.2 tool calls on BrowseComp-Plus and 96.5 on SWE-Bench, indicating it learns to engage more deeply with complex problems.

## Baselines & Comparisons

Against the directly comparable 36B baselines, the Folding Agent with FoldGRPO wins on both benchmarks across all settings. On BrowseComp-Plus, it outperforms the 32K ReAct agent (0.286) by +33.4 points, the 327K ReAct agent (0.478) by +14.2 points, and the Summary Agent with RL (0.527) by +9.3 points. On SWE-Bench Verified, it beats the 32K ReAct agent (0.436) by +14.4 points, the 327K ReAct agent (0.552) by +2.8 points, and the Summary Agent with RL (0.550) by +3.0 points. Among 100B+ closed-source models, the Folding Agent (62.0% BCPlus, 58.0% SWE) surpasses DeepSeek-V3.1 on BrowseComp-Plus (0.613) and GLM-4.5-Air on SWE-Bench (0.576), but trails GPT-5 (0.793/0.718) and GPT-4.1 on BrowseComp-Plus (0.640). The key efficiency advantage is that the Folding Agent achieves these results with only 32K active context tokens (vs. 327K for ReAct), yielding over 90% context compression in the main thread while processing 100K+ total tokens across branches.

## Relation to Prior Work

This paper departs from two dominant paradigms for scaling long-horizon agents: passive context summarization (triggered when context is full, as in MemAgent, ReSum, MEM1) and handcrafted multi-agent delegation workflows. It reframes context management as an active, learnable skill by introducing branch/return actions that the agent invokes autonomously, and by extending GRPO with token-level process rewards (unfolded-token penalty, out-of-scope penalty) that directly shape when and how the agent folds its context. Conceptually, it sits between multi-agent systems and single-agent summarization, sharing the KV-cache-friendly prefix structure of the former while eliminating fixed orchestration, and aligning summarization with sub-task boundaries rather than arbitrary token thresholds as in the latter.

## Why It Matters / Open Questions

The practical impact is significant: a 36B model with a 32K active context matches or exceeds 327K-context ReAct baselines on both deep research and agentic coding, with RL providing +20% and +8.8% absolute gains respectively. Open questions include whether multi-layer (nested) folding can be stabilized—current base models struggle with nested control flow—and whether parallel branching helps for breadth-first tasks (the paper shows it does not for depth-first BrowseComp). The test-time generalization from 10 training branches to 32.6 inference branches for 50-question compound tasks is promising but untested at larger scales, and the method remains behind top closed-source models (GPT-5), leaving the ceiling unclear.
