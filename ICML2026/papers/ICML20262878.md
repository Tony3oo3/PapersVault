## Problem

Current LLM test-generation benchmarks systematically evaluate only regression prevention (treating existing code as ground truth) or reactive reproduction (relying on post-failure artifacts like issue reports), leaving the critical capability of proactive bug discovery—finding latent defects before they reach production—entirely unmeasured. This gap means models may be validated as correct while actually codifying bugs as features, or are only tested on defects that have already caused damage.
![Teaser figure](../imgs/ICML20262878/cropped_page3_idx0.webp)

## Input / Output

The model receives documentation (auto-generated by DocAgent from the post-fix repository to describe intended behavior), test entry inferences (functions/methods directly invoked by ground-truth test cases), and, in the White Box setting, their direct dependencies (invocation and inheritance). In the Black Box setting, implementation code is masked, leaving only function signatures and documentation. The model outputs executable pytest test code, which is then executed on both the base (buggy) and head (fixed) commits; a test is scored as Fail-to-Pass only if it fails on the base and passes on the head, while Head Pass Rate, Entry Coverage, and Change-focused Coverage provide complementary quality signals.

## Method

TestExplora's core mechanism replaces the code or issue report as the evaluation oracle with documentation-derived intent, forcing models to identify implementation–specification mismatches rather than reproduce known failures. The acquisition pipeline crawls 12,227 PRs from repos with >1,000 stars, filters via invoke-graph reachability (ensuring test functions can actually call the repaired functions), excludes doctoring/placeholder modifications, and auto-builds Docker environments using GitHub Actions Runner Images for Fail-to-Pass execution. DocAgent (a multi-agent Searcher–Reader–Writer–Verifier system) generates documentation from the head repository without accessing diff patches, preventing information leakage. The benchmark spans 2,389 tasks across 482 repositories in 21 categories, and a continuous, time-aware collection framework enables ongoing data refresh to mitigate static-dataset contamination. Evaluation further compares static context provision (White/Black Box) against agentic exploration (SWEAgent, TraeAgent), revealing that free repository navigation substantially outperforms fixed-context prompting for proactive discovery.

## Results

On TestExplora (2,389 tasks, 482 repos), GPT-5-mini achieves the highest Fail-to-Pass (F2P) rate of 7.54% (White Box) and 5.17% (Black Box), while the best single-model F2P on TestExplora-Lite reaches 11.84% (White Box). The maximum F2P across all configurations is 16.06% (Claude-Sonnet-4.5, White Box, Plain context in Table 4), and SWEAgent instantiated with GPT-5-mini pushes this to 17.27% (F2P@5 = 29.7%). Head Pass Rate (HP) ranges from 62–85%, Entry Coverage (EC) from 38–72%, and Change-focused Coverage (CFG) from 41–48%, indicating models can write syntactically valid tests but struggle to expose latent bugs.

## Baselines & Comparisons

GPT-5-mini dominates all other single models on F2P in both Black Box (5.17% vs. 3.93% for o3-mini) and White Box (7.54% vs. 5.92% for o4-mini) settings, while also generating fewer tests (≈11.5 vs. 14–19). Gemini-2.5-pro produces the most test cases (14–16) and achieves a competitive HP (62–75%), but its F2P is only 2.06–2.59%, roughly half that of GPT-5-mini, because the larger suite dilutes suite-level success. GPT-4o and Qwen3-Coder-30B trail significantly (F2P ≤ 2.05%), with GPT-4o's White Box Lite F2P (2.20%) actually below its Black Box (3.61%), suggesting it cannot effectively leverage dependency context. Among agentic baselines, SWEAgent+GPT-5-mini (F2P 17.27%) outperforms both Claude-Sonnet-4.5 in plain context (16.06%) and TraeAgent+GPT-5-mini (14.55%), confirming that free repository exploration via an agent loop is more effective than static context provisioning. SWEAgent+o4-mini (9.42%) also surpasses o4-mini's plain White Box score (5.92%), further validating the agentic approach.

## Relation to Prior Work

This paper departs from the two dominant paradigms in LLM test-generation benchmarks—regression prevention (TestEval, TestBench, TestGenEval) and reactive reproduction (SWT-Bench, TDD-Bench-Verified)—by introducing a third paradigm: proactive discovery, where models must uncover latent defects without any prior knowledge of the bug. It builds on the repository-level evaluation infrastructure established by SWE-Bench and SWT-Bench but replaces issue reports and code patches as oracles with documentation-derived intent, and introduces a continuous, time-aware data collection pipeline to mitigate the static-dataset leakage that plagues SWE-Bench-derived benchmarks. The agentic evaluation (SWEAgent, TraeAgent) extends the line of work on agent-computer interfaces for software engineering into the testing domain.

## Why It Matters / Open Questions

The benchmark reveals a stark capability gap—no model exceeds 16% Fail-to-Pass—demonstrating that current LLMs are far from autonomous proactive testers, a finding with direct implications for software quality assurance pipelines. The counterintuitive result that generating more tests degrades suite-level F2P, combined with model-specific dependency preferences, challenges the assumption that more context or more output always helps. Open questions include whether agentic exploration can close the gap at scale, how documentation quality and coverage affect discoverability, and whether the continuous collection framework can sustain a non-leaking evaluation stream as models are retrained on newer repositories.
