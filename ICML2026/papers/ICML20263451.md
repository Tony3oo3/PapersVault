## Problem

Existing queueing models for LLM inference treat computation as the sole limiting resource, ignoring the KV cache memory constraint that in practice often dominates system capacity. Without explicitly modeling how memory usage grows piecewise-linearly during prefill and decode, prior stability analyses can produce substantial errors when memory is a tight bottleneck. This paper introduces the first queueing-theoretic framework that jointly captures both GPU compute throughput and KV cache memory availability to derive rigorous stability conditions for LLM inference.

## Input / Output

The framework takes as input the request arrival rate λ, the effective KV cache capacity M (normalized from bytes to tokens), the joint distribution F_in-out of prompt and response token lengths, the per-batch processing time b̄ (estimated empirically via median or trimmed mean from real traces), and a work-conserving scheduling policy (defaulting to FCFS with continuous batching). It outputs a closed-form maximum stable service rate μ = M / (b̄ · E[g(s,o)]), where g(s,o) is the lifetime cumulative memory footprint of a request, along with the stability threshold λ < μ(1−δ) and the corresponding GPU count ⌈λ/(μ·ρ)⌉ for a target utilization ρ. The memory constraint is enforced as a hard cap: the sum of all active requests' KV cache usage must not exceed M at any discrete time step.

## Method

The model formulates LLM inference on a single GPU as a discrete-time Markov chain where each request's KV cache usage grows linearly—by fixed chunks of size ŝ during the prefill phase, then by one token per step during decode—before being fully released upon completion. The key analytical insight is defining a Lyapunov function V(t) as the total outstanding (future) memory demand across all active and waiting requests, which behaves like 'area left to erase' and decreases by exactly the KV utilization U_t per batch slot regardless of whether consumed work is prefill or decode. Under work-conserving scheduling, a large backlog guarantees the batcher can maintain utilization U_t ≥ M(1−δ) without risking overflow, where δ = ess sup(s+o)/M is the headroom for the largest single request. Applying the Foster-Lyapunov criterion yields the stability condition λ < μ(1−δ) and the instability condition λ > μ, with μ expressed in closed form as M/(b̄·E[g(s,o)]). The chunked-prefill formulation (fixed ŝ) bounds per-batch prefill cost and prevents quadratic attention variance, while the constant-batch-time assumption is justified by the observation that near-capacity operation makes attention the dominant per-batch cost, yielding nearly uniform batch execution times.

## Results

The paper's headline metric is the Gap Absolute Percentage (GAP) between the theoretical stable service rate μ_theory (Eq. 1) and the empirically measured GPU rate μ_gpu. On a single NVIDIA A100 serving Meta-Llama3-8B via vLLM, GAP ranges from 2.25% (PD 1:2) to 8.38% (PD 2:1), all under 10%. On the LongBench v2 real dataset (503 long-context questions), GAP is 8.03%. Scaling to 8 parallel GPUs (data-parallel, no tensor parallelism), GAP drops to 3.38%, confirming the formula's linear scalability for capacity planning.

## Baselines & Comparisons

This paper does not benchmark against competing queueing models or scheduling algorithms; its validation is a theoretical-prediction-versus-empirical-measurement comparison. The theoretical rate μ = M / (b̄ · E[g(s,o)]) is compared directly against the steady-state throughput measured on real A100 GPUs running vLLM v1 with continuous batching and chunked prefill. Across all tested configurations (fixed PD ratios, time-varying mixed workloads, the LongBench v2 real dataset, and 8-GPU data-parallel deployment), the GAP stays within 10%, with most settings under 8%. The paper also validates the instability side: when λ exceeds μ (e.g., λ=5, 20, 50 req/s on a single GPU with μ≈3.4), queue length grows linearly, confirming the overload condition of Theorem 4.1. No prior queueing model (Li et al. 2025, Jaillet et al. 2025, Yang et al. 2024) provides a closed-form stability condition that accounts for KV cache memory, so no head-to-head numerical comparison with those baselines is performed.

## Relation to Prior Work

This paper extends the queueing-theoretic analysis of LLM inference initiated by Li et al. (2025) and Jaillet et al. (2025) by explicitly incorporating KV cache memory constraints into the stability model. While prior queueing models for LLM serving (Wu et al. 2023, Yang et al. 2024, Guldogan et al. 2024) treated computation as the sole limiting resource, this work introduces the memory dimension as a first-class constraint, drawing conceptual parallels to stochastic bin packing (Coffman & Stolyar 2001; Gamarnik 2004) while noting key structural differences: piecewise-linear memory growth across two phases and a large-memory regime. The chunked-prefill formulation bridges the scheduling perspective of Jaillet et al. into a discrete-time queueing framework amenable to Lyapunov analysis.

## Why It Matters / Open Questions

The closed-form stability condition μ = M/(b̄·E[g(s,o)]) gives system operators a direct formula to compute required GPU count from an estimated arrival rate, addressing a core practical challenge in LLM deployment that previously lacked a principled analytical tool. The <10% validation error on real A100 hardware across multiple PD ratios and a real dataset (LongBench v2) strengthens confidence in the model's practical utility. Key open questions remain: the analysis covers data-parallel replicas only, and extending to tensor parallelism, pipeline parallelism, or prefill-decode disaggregation (which change the queueing topology into tandem or networked queues) is left to future work. The assumption of constant batch processing time b̄, while empirically supported, may break down under extreme workload heterogeneity.
