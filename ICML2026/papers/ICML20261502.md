## Problem

Existing LLM-based security systems—whether single-agent, generic coding agents, or static multi-agent debate frameworks—achieve low success rates (often below 10%) on realistic vulnerability discovery and exploitation benchmarks due to brittle single-shot reasoning, lack of execution-grounded validation, and inability to learn from prior attacks. The paper addresses this by asking how to structure an automated red-teaming system that mirrors the iterative, evidence-driven, and experience-accumulating workflows of human security experts.

## Input / Output

The system takes a target codebase (specified by a file path) and an optional vulnerability description as input. When no description is provided, it enters a discovery stage; when one is given, it proceeds directly to exploitation. All code browsing and command execution occur inside an isolated Docker container to ensure safety. The output is a structured vulnerability report containing validated vulnerabilities with file/line-level evidence, risk assessments, and a proof-of-concept exploit script (e.g., a .sh or .py file) that returns 0 on success and 1 on failure, along with the full exploitation trace as evidence.

## Method

CO-REDTEAM is a security-aware multi-agent framework coordinated by an orchestrator that enforces role separation, tool access control, and workflow scheduling across two sequential stages. Stage I (Discovery) pairs an Analysis agent—equipped with code-browsing tools and CWE/OWASP-grounded security documentation—with a Critique agent in an iterative loop that produces evidence-chained vulnerability hypotheses (source, sink, context). Stage II (Exploitation) runs a closed-loop of Planner, Validation, Execution, and Evaluation agents: the Planner maintains an explicit multi-step Exploit Plan that is refined after each execution, the Validation agent gates actions for safety and consistency, the Execution agent runs commands in Docker, and the Evaluation agent converts raw traces into high-level guidance for the next iteration. A three-layer long-term memory (vulnerability patterns, high-level strategies, concrete technical actions) is populated via LLM-based extraction from execution traces and retrieved via embedding similarity, enabling the system to accumulate reusable experience across tasks and improve over time without retraining.

## Results

With Gemini-3-pro, CO-REDTEAM achieves 63.7% attack success rate (ASR) on CyBench, 65.0% exploit success and 20.0% detection accuracy on BountyBench, and 37.3% ASR on CyberGym. These represent large absolute gains over the strongest execution-feedback baselines (C-Agent: 47.8% / 47.5% / 5.0% / 21.5%) and static-analysis baselines (RepoAudit: N/A / 25.0% / 2.5% / 18.3%). The framework generalizes across backbone models, maintaining top performance even with smaller open-source models (e.g., qwen3-32b: 18.2% CyBench vs. 13.6% for C-Agent). Ablation studies confirm that execution feedback is the most critical component, with its removal causing a 41.6% ASR drop on CyBench.

## Baselines & Comparisons

CO-REDTEAM outperforms all four baselines across every benchmark and backbone model. Against the strongest execution-feedback baselines, C-Agent (47.8% CyBench, 47.5% BountyBench Exploit, 5.0% Detect, 21.5% CyberGym with Gemini-3-pro) and OpenHands (45.2%, 45.0%, 5.0%, 20.2%), CO-REDTEAM achieves 15.9, 17.5, 15.0, and 15.8 percentage-point gains respectively. The static-analysis baselines VulTrail (10.0% BountyBench Exploit, 0.0% Detect, 5.6% CyberGym) and RepoAudit (25.0%, 2.5%, 18.3%) are substantially outperformed, with CO-REDTEAM exceeding them by 55 and 40 percentage points on BountyBench Exploit, confirming that execution-grounded iterative reasoning is essential for realistic vulnerability validation. Notably, CO-REDTEAM is also more efficient than OpenHands and C-Agent in wall-clock time (e.g., 198.7s vs. 219.6s on BountyBench with Gemini-3-pro), despite its multi-agent architecture.

## Relation to Prior Work

CO-REDTEAM synthesizes and extends several prior threads: single-agent security workflows (C-Agent, RepoAudit) that incorporate execution feedback but lack security-domain grounding; multi-agent debate frameworks (VulTrail) that perform structured vulnerability detection but remain static without execution; and generic coding agents (OpenHands) that iterate on code but are not specialized for security. The key architectural departure is the tight integration of four capabilities—CWE/OWASP-grounded security knowledge, code-browsing tools, a closed-loop plan-execute-evaluate exploitation cycle with an explicit revisable Exploit Plan, and a three-layer long-term memory (vulnerability patterns, strategies, technical actions)—into a single orchestrated pipeline. The layered memory design draws on structured reasoning memory work (Ouyang et al., 2026), while the orchestrator's role mirrors the supervisor pattern in Co-Scientist (Gottweis et al., 2025), but applied to the security domain with sandboxed Docker execution.

## Why It Matters / Open Questions

The paper demonstrates that execution-grounded multi-agent orchestration can push automated exploitation success from the single digits (typical of prior methods on realistic codebases) to over 60%, with the ablation confirming that the execution loop is the single most critical component (41.6% ASR drop when removed). The memory evolution experiments show the system can autonomously acquire effective strategies from experience, suggesting a path toward continuously improving security agents without retraining. Open questions include whether the approach generalizes beyond CTF-style and curated vulnerability benchmarks to truly open-ended codebases, how detection accuracy (still only ~20%) can be improved, and the dual-use implications of increasingly capable autonomous exploitation systems. The comparable latency to simpler single-agent baselines despite multi-turn orchestration is practically encouraging for deployment.
