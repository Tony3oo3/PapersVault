## Problem

The application layer of the Internet is dominated by closed, proprietary platforms where integration is expensive, strategically discouraged, and legally restricted, while traditional interoperability efforts (standards bodies, regulatory mandates) have been slow, narrow, and reactive. This position paper argues that LLM-based agents fundamentally disrupt this status quo by making interoperability dramatically cheaper and effectively unavoidable, and calls on the ML community to build the infrastructure to harness this shift responsibly.

## Input / Output

The universal adapter consumes heterogeneous inputs at runtime: machine-readable API specifications (OpenAPI, GraphQL schemas), web page DOM structures and rendered HTML, and natural language task descriptions. It produces executable glue code (e.g., Python scripts invoking REST endpoints), structured API calls, UI action sequences (clicks, form fills, navigations), and data translated into target formats. Unlike static middleware or pre-programmed integrations, the agent infers schema correspondences and generates integration logic on the fly, adapting to evolving interfaces without requiring pre-defined mappings or version-locked client libraries.

## Method

This position paper proposes 'universal interoperability' as a framework in which LLM agents serve as dynamic, AI-mediated adapters between any two digital services, combining two core capabilities: automated format translation (inferring field correspondences between schemas and emitting executable glue code, building on systems like RestGPT, Gorilla, and text-to-SQL) and robust UI interaction (parsing DOM/GUI elements and executing action sequences via reasoning-acting frameworks like ReAct). The key insight is that because agents can replicate any human-accessible interaction, platforms can no longer maintain proprietary barriers through API restrictions or interface obfuscation, rendering interoperability effectively unavoidable. The paper then outlines three infrastructure pillars to make this safe and sustainable: agent-friendly interfaces (metadata extensions such as llms.txt and endpoint annotations), security by design (signed permission documents, runtime policy checkers, sandboxed execution with kill-switches), and ecosystem infrastructure (open protocols like A2A and MCP, curated reference adapter libraries, and open-source frameworks to prevent agent-layer lock-in).

## Results

This is a position paper and does not present original experimental results or a main results table. The key quantitative evidence cited is the rapid improvement of LLM agents on WebArena: success rates rose from 8.87% (March 2023) to 71.6% (January 2026), approaching the human benchmark of 78.24%. The paper also notes that every major frontier lab (OpenAI, Anthropic, Google, Perplexity, Microsoft, Amazon) has released a production web agent or agent browser within the last 18 months, underscoring the practical maturity of the capability.

## Baselines & Comparisons

As a position paper, this work does not propose a new method to benchmark against baselines. Instead, it surveys and contrasts existing interoperability paradigms (SOAP/WSDL, REST/OpenAPI, RDF/OWL semantic web, RPA, federated protocols like XMPP and ActivityPub) to argue that LLM-based agents overcome their limitations. The paper positions LLM agents as superior to traditional approaches on two axes: (1) automated format translation eliminates the need for hand-written client libraries and schema registries, and (2) robust UI interaction (via ReAct-style agents) surpasses brittle XPath crawlers and RPA tools that break on layout changes. No head-to-head quantitative comparison is provided; the argument is qualitative and economic rather than empirical.

## Relation to Prior Work

This position paper synthesizes three largely separate literatures—interoperability standards (OSI, SOAP/WSDL, REST/OpenAPI, Semantic Web/RDF/OWL), LLM agent capabilities (ReAct, RestGPT, Gorilla, WebArena/MiniWoB web agents), and platform economics (Katz & Shapiro, Farrell & Saloner on network effects and switching costs)—into a unified 'universal interoperability' framework. It departs from prior interoperability work by arguing that LLM agents eliminate the need for pre-programmed static middleware or ontology engineering, replacing weeks of integration engineering with runtime prompt-based adaptation. The paper also builds on recent agent-protocol proposals (Google's A2A, Anthropic's MCP) and regulatory instruments (EU DMA, GDPR data portability) to argue that the ML community should proactively shape the emerging agent-interoperability ecosystem rather than wait for reactive legislation.

## Why It Matters / Open Questions

The paper identifies a genuine inflection point: with WebArena success rates jumping from ~9% to ~72% in three years and every major lab shipping production web agents, the technical barrier to cross-platform data access is collapsing faster than regulatory or legal frameworks can adapt. Key open questions include preventing agent-layer lock-in (where a dominant agent framework becomes the new walled garden), securing agents against prompt-injection and adversarial web content, and establishing lightweight permission/rate-limit standards before the ecosystem hardens. The paper's main limitation is that it is a position piece with no empirical validation of 'universal interoperability' at scale; its practical impact depends on whether the proposed infrastructure (agent-friendly metadata, signed permission documents, runtime policy checkers) is actually adopted by the community.
