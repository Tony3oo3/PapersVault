## Problem

Current LLM-based math agents rely on informal chain-of-thought reasoning that is prone to logical gaps and hallucinations, while formal theorem provers offer rigorous verification but lack exploratory flexibility. Reward-model-based approaches (PRMs, ORMs) provide only black-box scalar scores without explicit mathematical verification, and no existing framework principledly interleaves informal reasoning with kernel-based formal checking during inference.
![Teaser figure](../imgs/ICML20263518/cropped_page1_idx0.webp)

## Input / Output

The system takes a natural-language math problem and produces a final answer accompanied by a formally verified reasoning chain. During generation, the LLM pauses at critical proof steps to invoke a Lean4 tool that returns one of three discrete signals (CORRECT, INCORRECT, VERIFICATION FAILURE), which are fed back as natural-language feedback to guide subsequent reasoning. Each problem operates under an 8,192-token budget and a 15-minute time limit, with the agent making 5–10 tool calls on harder problems (AIME) versus ~5 on easier ones (MATH).

## Method

Hermes is a tool-augmented LLM agent that interleaves informal reasoning with Lean4 formal verification at inference time via four swappable modules: (1) a formalization module that translates each critical step into Lean4 code and validates it through compilation plus back-translation equivalence checking (budget K_f); (2) a prover module that attempts proofs of both the goal and its negation in parallel using Goedel-Prover-V2-8B plus built-in Lean solvers (budget K_p); (3) a memory block that stores verified steps with embedding vectors and retrieves top-k relevant context via cosine similarity to maintain proof continuity across long chains; and (4) a feedback module that returns the verification signal to the LLM. The key architectural insight is that verification is interleaved during a single reasoning trace rather than applied post-hoc to multiple candidates, yielding a complexity of O(T̃KN²) that sits between ORM (O(KN²)) and PRM (O(TKN²)) while using 4–6× fewer tokens than Best-of-N reward-based methods. The Lean4 REPL serves as the trusted kernel, and the entire pipeline is model-agnostic, compatible with any autoformalizer–prover pairing.

## Results

Hermes@1 achieves 91.2% on MATH-500, 30.0% on AIME'25, 73.0% on CollegeMath, and 6.6% on HARDMath2 with Qwen3-8B; 97.2%, 86.7%, 78.9%, and 31.3% with o3-mini; and 98.4%, 70.0%, 83.3%, and 33.6% with DeepSeek-V3.2. Averaged across all models and benchmarks, Hermes improves accuracy by 23.4% over zero-shot CoT and by 10.3% over the previous Lean-based SOTA (Safe), while using 4–6× fewer reasoning tokens than reward-model Best-of-5 methods. On the hardest benchmark (HARDMath2), DeepSeek-V3.2+Hermes gains 31.5% over CoT, and on AIME'25 the improvement reaches 40% with 80% fewer total inference FLOPs. When scaled to Hermes@5+Skywork, accuracy increases by an additional 10.8% on average over Hermes@1.

## Baselines & Comparisons

Hermes@1 outperforms zero-shot CoT (Wei et al., 2022) by 23.4% on average across all models and benchmarks, with the largest gap on HARDMath2 (e.g., 33.6% vs. 25.6% for DeepSeek-V3.2). Against the ORM baselines, Hermes exceeds Skywork (Liu et al., 2024) by 5.7% and ArmoRM (Wang et al., 2024a) by 8.0%, with the most notable margin on AIME'25 where Hermes@1 reaches 70.0% (DeepSeek-V3.2) versus 53.3% for both ORMs. Against the PRM baselines, Hermes surpasses Math-Shepherd (Wang et al., 2024b) by 12.2% and RLHFlow (Dong et al., 2024) by 14.9%, again with the largest gains on harder problems. Compared to the previous Lean-based SOTA, Safe (Liu et al., 2025), Hermes achieves a consistent 10.3% average improvement; even when Safe is upgraded with the same Goedel-Prover-V2 and Goedel-Autoformalizer models (Safe*), Hermes still leads by 8.5%. The only near-tie occurs on AIME with Qwen3-8B, where Skywork and ArmoRM match Hermes at 30.0%, but Hermes dominates on all other model–benchmark combinations.

## Relation to Prior Work

Hermes sits at the intersection of LLM-based mathematical reasoning (CoT, PRMs, ORMs) and formal theorem proving (Lean4, AlphaProof, Goedel-Prover), but departs from both in a key way: rather than using reward models as black-box post-hoc scorers or relying entirely on formal proof search, it interleaves kernel-verified formal checking *during* a single informal reasoning trace via tool-calling. The closest prior work is Safe (Liu et al., 2025), which also uses Lean4 for step-aware verification, but Safe operates retrospectively over multiple generated traces, whereas Hermes embeds verification inline and adds a memory block for cross-step proof continuity. The neuro-symbolic reasoning literature (LogicLM, DSP, Lean-STaR) provides conceptual precedent for hybrid LLM-symbolic pipelines, but none of those systems combine a dedicated autoformalizer, a whole-proof prover, back-translation consistency checks, and embedding-based memory retrieval in a single agentic loop.

## Why It Matters / Open Questions

The practical significance is that Hermes offers interpretable, step-level correctness signals (proof / counter-proof / inconclusive) instead of opaque scalar rewards, and it does so at a token cost comparable to plain CoT rather than 4–28× more as in BoN reward-model pipelines. However, its effectiveness is tightly coupled to Mathlib coverage: geometry, number theory, and combinatorics show the weakest verification coverage (~75% CoT coverage on AIME) and the highest failure rates, so gains will be uneven until the formal library matures. Open questions include whether the modular design transfers to other proof assistants (Coq, Isabelle), how performance scales as Mathlib grows, and whether the single-trace-with-verification paradigm can replace BoN sampling for smaller models where trace variance is high.
