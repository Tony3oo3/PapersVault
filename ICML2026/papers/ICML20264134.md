## Problem

Existing agent benchmarks evaluate retrieval or tool use in isolation, leaving a gap in realistic, fully agentic evaluation where agents must retrieve from large, unstructured, proprietary knowledge bases, reason over complex interdependent policies, discover tools from documentation, and execute multi-step state changes during long-horizon conversations with users. This paper asks whether current frontier LLM agents can reliably coordinate unstructured knowledge with tool-mediated actions in a realistic fintech customer-support setting.
![Teaser figure](../imgs/ICML20264134/cropped_page1_idx0.webp)

## Input / Output

The agent receives a simulated user conversation (flow-based, with conditional rules for edge cases) and access to a 698-document, ~200K-token unstructured knowledge base via one of four retrieval modalities: dense embedding search (text-embedding-3-large or Qwen3-embedding-8B), sparse BM25, terminal-based shell exploration, or a golden-retriever setting that injects task-critical documents directly in context. The agent must produce a sequence of tool invocations (including discoverable tools that must first be located in the KB and explicitly unlocked) that transform a banking database to a target state. Success is measured by pass^k (probability of correct final state across k independent trials, k≤4), supplemented by action recall, document recall, and efficiency metrics (total tokens, tool-call count, wall-clock duration).

## Method

The core contribution is the τ-Banking domain, constructed via a structured-to-unstructured generation pipeline: a latent structured specification of 21 product categories, 71 topics, and 51 discoverable tools is expanded into 698 natural-language documents by an LLM, then refined through human-in-the-loop editing and dual-reviewer auditing. The environment is formulated as a Dec-POMDP where the agent has partial observability over a shared banking database and must acquire both procedural knowledge and tool access through retrieval before taking valid state-changing actions. A key design choice is discoverable tools: 51 tools are referenced only implicitly in KB documentation and must be found and explicitly unlocked via call_discoverable_tool, making the agent's action space state-dependent on its knowledge state. The benchmark is retrieval-agnostic, supporting arbitrary search strategies from embedding-based retrieval to freeform terminal navigation, enabling evaluation of how retrieval quality, reasoning over complex policies, and solution efficiency interact in human-facing agent deployments.

## Results

The best configuration, GPT-5.2 (high reasoning) with terminal-based search, achieves only 25.52% pass^1 on τ-Knowledge, with reliability dropping to 13.40% pass^4. Even when all task-critical documents are provided directly in context (golden retriever), the strongest model (Claude-4.5-Opus, high) reaches only 39.69% pass^1, demonstrating that reasoning over complex policies—not just retrieval—is the primary bottleneck. Averaged across all six model configurations, terminal-use (19.20%) outperforms dense retrieval with text-embedding-3-large (16.88%), Qwen3-embedding-8B (17.11%), and BM25 (17.04%), while the no-knowledge baseline drops to ~2% pass^1, confirming tasks genuinely require retrieved information.

## Baselines & Comparisons

τ-Knowledge is a new benchmark rather than a method paper, so the primary comparisons are across retrieval configurations and model families. Terminal-based search outperforms all dense/sparse retrieval methods on average (19.20% vs. 16.88–17.11% pass^1), but this advantage is concentrated in high-reasoning models: GPT-5.2 without reasoning actually performs worse with terminal (11.60%) than with Qwen3-embedding-8B (12.37%), and earlier GPT models (GPT-4o, GPT-4.1) show no terminal benefit. The golden-retriever setting reveals a large reasoning gap: Claude-4.5-Opus gains +21.4 points over text-embedding-3-large in the gold condition, while GPT-5.2 (high) gains only +7.2 points over terminal, suggesting GPT-5.2's retrieval queries are more effective but its policy reasoning is weaker. On efficiency, Claude-4.5-Opus achieves comparable pass^1 to GPT-5.2 (high) with terminal while using ~1.7× fewer tokens, ~2.3× fewer shell commands, and completing tasks ~9× faster. The no-knowledge ablation (~2% pass^1) and long-context ablation (~12% pass^1) confirm that both targeted retrieval and reasoning over retrieved content are necessary, as simply dumping the full 200K-token corpus into context does not close the gap.

## Relation to Prior Work

This paper extends τ-Bench (Yao et al., 2025) and τ²-Bench (Barres et al., 2025), which evaluate conversational agents in tool-use environments, by introducing unstructured knowledge base retrieval as a prerequisite for tool discovery and policy compliance. Prior benchmarks evaluate retrieval (BEIR, MTEB, BRIGHT) or tool use (SWE-Bench, GAIA, ToolBench) in isolation, and conversational RAG benchmarks (CORAL, mTRAG) remain primarily fact-based with minimal multi-step reasoning. τ-Knowledge unifies these threads in a Dec-POMDP formulation where agents must retrieve from ~700 interlinked documents to discover tools, interpret policies, and execute multi-step state changes over long-horizon conversations with simulated users.

## Why It Matters / Open Questions

The finding that even frontier models with golden retrieval achieve only ~39.7% pass^1 reveals that the binding constraint is not retrieval but multi-hop reasoning over complex, interdependent policies—a gap that existing benchmarks do not expose. The efficiency analysis (terminal use requiring 9× longer for comparable accuracy) highlights a practical tension for human-facing deployments where latency and interaction cost matter. Open questions include whether production-grade orchestration systems, more sophisticated context management, or constrained search settings (one/few-shot) would close the gap, and whether the structured-to-unstructured generation pipeline generalizes to other domains beyond fintech.
