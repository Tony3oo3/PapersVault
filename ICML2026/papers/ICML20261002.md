## Problem

Sparse sketches like SJLT reduce arithmetic cost via random sparsity, but their irregular access patterns cause severe memory bandwidth degradation on GPUs, where prior implementations rely on expensive global atomic operations to resolve write collisions. This creates a fundamental tension: the randomness that gives sketches their theoretical guarantees is precisely what makes them hard to implement efficiently on modern GPU hardware.

## Input / Output

The method takes a dense input matrix A ∈ R^{d×n} and produces a sketched matrix SA ∈ R^{k×n} with k < d, where the sketch matrix S is never materialized in memory. The sketch is parameterized by M blocks, output block size B_r, input block size B_c, a tunable number of permutations κ, and intra-block sparsity s, giving each column of S exactly κs nonzeros of magnitude 1/√(κs). The sketched output feeds directly into downstream RandNLA tasks (least squares, ridge regression, OSE) or ML pipelines like GraSS for data attribution.

## Method

FLASHSKETCH co-designs a new sketch family BLOCKPERM-SJLT with a specialized CUDA kernel. The sketch partitions S into M×M blocks whose sparsity pattern is a union of κ edge-disjoint permutations, creating a κ-regular bipartite graph between output and input blocks, with standard SJLT hashing (s nonzeros per column, ±1/√s entries) within each active block. The kernel exploits the bi-regular structure to assign each output block to exactly one thread-block, accumulating results in shared memory via fast shared-memory atomics and performing a single coalesced global write per tile—completely eliminating the global atomic contention that bottlenecks prior GPU SJLT kernels. All randomness (block wiring and intra-block hashes) is generated on-the-fly using lightweight affine permutations and 32-bit mixing hashes, avoiding any storage of S. The parameter κ provides a tunable tradeoff: larger κ increases mixing and improves the neighborhood-coherence-based OSE guarantee toward the optimal value of 1, at the cost of reading more input blocks per output block.

## Results

FLASHSKETCH achieves a global geomean speedup of 1.73× over the next-best baseline (SJLT via cuSPARSE) aggregated across all RandNLA tasks, input shapes, and datasets on an NVIDIA RTX 4090. Per-task speedups range from 1.37× (sketch-and-solve vs. cuSPARSE SJLT) to 16.22× (Gram-matrix approximation vs. Subsampled FHT). In the end-to-end GraSS data-attribution pipeline on MNIST, FLASHSKETCH achieves up to ~3.2× speedup over the GraSS SJLT kernel while maintaining attribution quality (measured by Linear Datamodeling Score), pushing the quality–speed Pareto frontier.

## Baselines & Comparisons

FLASHSKETCH outperforms all four baselines across every task and dataset. Against the two sparse SJLT baselines (cuSPARSE SpMM and the GraSS CUDA kernel), speedups are modest on regression tasks (1.37–1.54×) but grow to 2.67–4.17× on Gram-matrix and OSE metrics, reflecting that the global-atomic bottleneck in scatter-add kernels is most severe when the output dimension is large relative to the input. Against the dense Gaussian cuBLAS baseline, FLASHSKETCH is 2.34–7.64× faster, with the largest gains in the high-dimension regime (d up to 262144). The Subsampled FHT (SRHT) baseline is the most outperformed, with speedups of 3.33–16.22×, because FHT kernels, while fast, do not exploit the sparsity structure and still require full-dimension reads. In the end-to-end GraSS pipeline, FLASHSKETCH achieves up to ~3.2× speedup over the GraSS SJLT kernel while preserving LDS attribution quality, confirming that the kernel-level gains translate to wall-clock improvements in a real ML workflow.

## Relation to Prior Work

This paper extends the localized sketching framework of Srinivasa et al. (2020), which analyzed block-diagonal SJLTs via a block-coherence parameter, by replacing the block-diagonal structure with a union-of-edge-disjoint-permutations wiring that couples each output block to κ distinct input blocks. The kernel design departs from prior GPU sparse-sketch implementations (GraSS/Hu et al. 2025, Higgins et al. 2025), which rely on global atomic scatter-adds to resolve hash collisions, by exploiting the bi-regularity of the permutation wiring to assign each output tile to a single thread-block and accumulate privately in shared memory. The permutation construction draws on the union-of-permutations expander literature (Puder, 2015), repurposed here not for spectral expansion but for enabling a hardware-friendly block sparsity pattern.

## Why It Matters / Open Questions

The co-design principle—choosing the sketch's sparsity structure to enable a specific kernel optimization rather than the reverse—offers a template for future hardware-aware randomized linear algebra. The tunable κ parameter gives practitioners a principled dial between sketching robustness (neighborhood coherence) and GPU throughput, though the paper acknowledges that optimal κ selection remains empirical and data-dependent. Open questions include analyzing the dependent-permutation regime actually used in practice (the theory assumes i.i.d. permutations), extending beyond OSE to tighter Gram-matrix or end-to-end learning guarantees, and exploring whether the split-Bc fallback for low-occupancy regimes can be made more principled. The FLASHBLOCKROW variant, which is faster but lacks OSE guarantees and can silently drop input coordinates, highlights the fragility-speed tradeoff that remains unresolved.
