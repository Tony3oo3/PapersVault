## Problem

PEFT methods like LoRA reduce parameter-related overhead but still require full forward and backward passes, leaving activation memory and backward FLOPs as the dominant bottleneck in LLM fine-tuning. Existing backpropagation-skipping approaches either operate at the coarse block level (DropBP) or select tokens randomly without considering their heterogeneous contribution (TokenTune), resulting in suboptimal accuracy under reduced compute budgets.

## Input / Output

TokenDrop takes a pretrained LLM, a fine-tuning dataset, and a target activation memory budget as inputs, and produces fine-tuned LLM weights along with per-block retained token index sets. The importance scores are computed on-the-fly during the forward pass as residual l2-norms, enabling immediate activation eviction for non-retained tokens without requiring gradient information or explicit attention maps. Retention ratios per block are pre-computed via a one-shot sensitivity diagnostic iteration before training begins.

## Method

TokenDrop selectively propagates gradients only through a subset of tokens identified by the l2-norm of their residual update at each Transformer block, a lightweight forward-only criterion that is compatible with fused attention kernels like FlashAttention. Two key strategies ensure training stability: (i) cumulative token selection enforces S_1 ⊆ S_2 ⊆ … ⊆ S_L so that any token retained at an earlier block is always retained in all subsequent blocks, preserving gradient integrity along both the non-linear and residual paths; and (ii) lazy selection scheduling defers the actual top-k selection and activation eviction until the accumulated activation memory approaches the budget, allowing importance scores to be aggregated across multiple blocks for globally informed retention. Block-wise retention ratios are allocated via a sensitivity-aware greedy procedure that progressively lowers the ratio of the least sensitive blocks until a target backward FLOPs constraint is met, ensuring monotonically non-decreasing retention across depth.

## Results

TokenDrop achieves up to 42.9% peak memory reduction and up to 1.50× wall-clock speedup across diverse fine-tuning scenarios while maintaining or improving accuracy. On 5-shot MMLU with LLaMA2-7B, TokenDrop reaches 54.1% average accuracy (vs. 53.1% for LoRA) using only 37.3 GB peak memory (vs. 63.9 GB) at 1.35× speedup. On GSM8K, TokenDrop matches LoRA's 54.9% accuracy while reducing memory from 54.2 GB to 38.2 GB (29.5% reduction) at 1.27× speedup. On MT-Bench instruction following, TokenDrop attains the highest average score (4.66) with 42.9% memory reduction and 1.38× speedup.

## Baselines & Comparisons

Against the LoRA baseline, TokenDrop matches or slightly exceeds accuracy (e.g., 54.1% vs. 53.1% on MMLU-7B, 54.9% vs. 54.9% on GSM8K) while reducing peak memory by 23.9–42.9% and accelerating training by 1.24–1.50×. Against DropBP (block-level stochastic skipping), TokenDrop wins decisively on accuracy—gaining 3.1 points on MMLU-7B (54.1 vs. 51.0) and 6.3 points on GSM8K (54.9 vs. 48.6)—while also using less memory (37.3 vs. 49.9 GB on MMLU-7B). Against TokenTune (random token-level skipping), TokenDrop improves MMLU-7B accuracy by 4.0 points (54.1 vs. 50.1) and MT-Bench average by 1.0 point (4.66 vs. 3.66), with comparable or lower memory. When combined with QLoRA, TokenDrop further reduces peak memory from 54.8 GB to 32.1 GB (41.4% reduction) at 1.32× speedup with no accuracy loss; similarly, PaCA+TokenDrop cuts memory from 54.3 GB to 37.2 GB at 1.31× speedup. On full fine-tuning of LLaMA3.2-1B, TokenDrop achieves a 1.50× speedup and actually improves MMLU accuracy from 40.9% to 42.2%.

## Relation to Prior Work

TokenDrop extends the backpropagation-skipping line initiated by DropBP (block-level stochastic skipping) and TokenTune (token-level random selection) by introducing importance-aware token selection grounded in the residual architecture of Transformers. It borrows the sensitivity-based retention ratio allocation from GACT and DropBP, but departs from both prior methods by computing a lightweight, forward-only residual ℓ₂-norm importance score that is compatible with fused attention kernels like FlashAttention—unlike attention-score or gradient-based alternatives. The cumulative token selection and lazy selection scheduling are novel mechanisms designed to address gradient-flow instability and local-score myopia that neither DropBP nor TokenTune handles.

## Why It Matters / Open Questions

TokenDrop offers a practical, drop-in efficiency improvement for LLM fine-tuning pipelines, achieving up to 42.9% memory reduction and 1.50× speedup while matching or exceeding LoRA accuracy across diverse tasks and PEFT methods (LoRA, QLoRA, PaCA, full fine-tuning). A notable open limitation is that token-level backward skipping is not yet optimized within FlashAttention kernels, which constrains speedup in long-context settings where attention dominates. Future work on kernel-level support for selective token backward passes could unlock further gains, and it remains to be seen whether the residual-norm importance signal generalizes to non-Transformer architectures or to pretraining regimes where the residual structure differs.
