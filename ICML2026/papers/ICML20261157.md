## Problem

Current LLM code agent benchmarks evaluate only single-turn, static correctness (e.g., pass@k, task success rate), isolating agents from the iterative feedback loops—self-debugging, peer-review learning, and continuous optimization—that define real-world software engineering. This static snapshot fails to capture whether an agent can evolve its code over multiple rounds, leaving evolutionary capability as an unmeasured and unexplored dimension of agent intelligence.

## Input / Output

Each agent receives a task specification (game rules or algorithmic problem) plus a minimal functional example in Round 1, then in subsequent rounds receives a structured feedback set containing full tournament execution logs, a global leaderboard, and peer code solutions from the entire population. The framework outputs a dual-metric assessment: S_base (the agent's Round 1 performance relative to the initial population) and S_evo (the OLS regression slope of the agent's global performance G_i^n across N rounds, where G_i^n is the average score against all M×N code versions produced across all agents and rounds). For competitive tasks, W entries are win rates from repeated pairwise or batch matches; for objective tasks, they are scalar efficiency scores (Time AUC or speedup ratio).

## Method

CATArena structures evaluation as a multi-round tournament loop: agents generate initial code, the sandboxed arena executes it against peers (round-robin for competitive tasks like Gomoku, Texas Hold'em, Chess, Bridge; independent benchmarking for objective tasks like OIBench and SWE-Perf), and the resulting feedback drives iterative refinement. The key design choice is the global performance matrix W ∈ R^{(M×N)×(M×N)}, where each entry W_{i,j}^{n,m} scores agent i's round-n code against agent j's round-m code, enabling S_evo to measure improvement relative to the entire evolving population rather than a fixed baseline. S_evo is computed via OLS regression on the per-round global scores G_i^n, chosen over simpler total-improvement metrics for robustness to transient development failures. The framework further decouples self-reflection from peer-learning through ablation (withholding peer code) and quantifies behavioral patterns via code similarity (CodeBLEU for objective tasks, action consistency for competitive tasks), revealing that most agents rely on a single mechanism rather than synergizing both.

## Results

Across six tasks (Gomoku, Texas Hold'em, Bridge, Chess, OIBench, SWE-Perf), CATArena reveals a weak correlation between base performance (S_base) and evolutionary capability (S_evo). For example, Claude-4-Sonnet achieves the highest Chess S_base (0.90) yet suffers a negative S_evo (−0.061), while Gemini-2.5-Pro starts last in Gomoku (S_base=0.25) but posts the highest S_evo (+0.156). Among commercial agents, Codex achieves the strongest OIBench evolution (+0.186) and the Best ADK Agent leads in Bridge evolution (+0.191), yet no commercial agent decisively outperforms minimal agents in S_evo across all tasks. In SWE-Perf, all agents show near-zero or negative S_evo (range: −0.0016 to +0.0036), indicating a complexity barrier where iterative feedback fails to drive meaningful improvement.

## Baselines & Comparisons

The paper evaluates six minimal agents (Claude-4-Sonnet, DeepSeek-3.1, Doubao-Seed-1.6, Gemini-2.5-Pro, GPT-5, Qwen3-Coder) and five commercial agents (Best ADK, Claude Code, Codex, Gemini CLI, Qwen Code) under a unified tournament protocol. Commercial agents consistently achieve higher S_base than their minimal counterparts (e.g., Qwen Code 0.94 vs. Qwen3-Coder 0.85 in Gomoku; Claude Code 1.00 in Bridge), confirming that proprietary scaffolding improves static generation. However, this advantage does not transfer to S_evo: Codex leads OIBench evolution (+0.186) but trails Gemini-2.5-Pro in Gomoku evolution (+0.156 vs. +0.103), and no commercial agent dominates S_evo across all six tasks. Notably, the Best ADK Agent (a minimal agent) achieves the highest Bridge S_evo (+0.191), surpassing all commercial agents. In Chess, all agents exhibit negative or near-zero S_evo, with Doubao-Seed-1.6 showing the worst regression (−0.214) despite a moderate S_base of 0.58, while Codex is the only agent with a positive Chess S_evo (+0.011). The overall finding is that evolutionary capability is orthogonal to static generation: high S_base agents like Claude-4-Sonnet (Chess 0.90) and Qwen3-Coder (Gomoku 0.85) can have strongly negative S_evo, while low-start agents like Gemini-2.5-Pro (Gomoku 0.25) can show the strongest evolution.

## Relation to Prior Work

This paper departs from the dominant paradigm of static, single-turn code agent evaluation (SWE-bench, pass@k, task success rate) by introducing an iterative tournament framework that explicitly measures multi-round evolutionary capability. It repurposes existing tasks—OIBench for algorithmic optimization, SWE-Perf for repository-level performance, and board/card games for competitive strategy—into a unified evolutionary loop, drawing conceptually on self-reflection (Reflexion, Self-Refine) and peer-learning literature but applying them as evaluation axes rather than training mechanisms. The key conceptual departure is treating code development as a non-stationary, population-level process where feedback includes full tournament logs and peer solutions, rather than isolated execution results.

## Why It Matters / Open Questions

The finding that evolutionary capability is largely orthogonal to static generation proficiency challenges the implicit assumption that a strong zero-shot coder will also be a strong iterative optimizer, with direct implications for how agent scaffolding and commercial products are designed. The ablation revealing that most agents cannot effectively combine self-reflection and peer-learning—often performing worse with full feedback than with self-reflection alone—identifies a concrete, addressable gap for future agent architectures. Open questions include whether the 4-round window captures the full evolutionary arc, how findings generalize beyond the ~10 agents tested, and whether the cold-start failure on complex environments (Pommerman) represents a fundamental limitation or a solvable engineering challenge.
